# Bevezetés az idézőjelek használatába

Van egy tanács, amit a kezdő bash-programozók újra és újra hallani fognak:

> Tedd idézőjelbe a változóidat!

Miért is?

Amikor kiterjesztesz egy változót (például `$name`), szinte mindig a változó _értékét_ szeretnéd egyetlen stringként (vagy számként) használni.
Nem szeretnéd, hogy az értéket a rendszer véletlenül két vagy több különálló stringként kezelje.

## Idézőjelek

Az idézőjelek használata az elsődleges módja annak, hogy egy szövegrész egyetlen szóként legyen kezelve.
Két fő idézőjeltípus van.

### Kettős idézőjelek

A kettős idézőjelek engedélyezik a paraméterkiterjesztést, az aritmetikai kiterjesztést és a parancsbehelyettesítést.

```bash
echo "This is bash version $BASH_VERSION"
```

Egy literál kettős idézőjelet úgy tehetsz egy kettős idézőjelbe zárt stringbe, hogy egy fordított perjelet teszel elé.

```bash
echo "She said \"Let me teach you about bash.\""
```

### Egyszeres idézőjelek

Az egyszeres idézőjelek _nem engedélyeznek_ semmilyen kiterjesztést.

```bash
echo 'This is bash version $BASH_VERSION'
# ...^..................................^
# prints exactly: This is bash version $BASH_VERSION
```

Egyszeres idézőjelbe zárt stringbe _nem lehet_ egyszeres idézőjelet beágyazni.

## Az idézőjelek fontossága

Mi is pontosan a baj a `echo $name` utasítással?

Amikor a shell feldolgoz egy kódsort, [többféle kiterjesztést][expansions] végez el, meghatározott sorrendben.
Az utolsó kiterjesztések közül kettő a _szófelbontás_ és a _fájlnévkiterjesztés_.

### Szófelbontás

A paraméterkiterjesztés, a parancsbehelyettesítés vagy az aritmetikai kiterjesztés minden olyan eredménye, _amely nem kettős idézőjelek között jött létre_, részt vehet a szófelbontásban.
A shell fogja a kiterjesztett eredményt, és minden olyan karaktersorozat mentén feldarabolja, amely szerepel a `$IFS` értékében.
Alapértelmezés szerint ez a szóköz, a tabulátor és az újsor.

Mindez működés közben is megfigyelhető egy shell-ciklussal:

```bash
sentence="The quick brown fox jumps."
i=0
for word in "$sentence"; do echo "$((++i)) $word"; done
# ..........^.........^
```
kimenete
```none
1 The quick brown fox jumps.
```

De idézőjel nélkül:

```bash
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
kimenete
```none
1 The
2 quick
3 brown
4 fox
5 jumps.
```

Nézzük meg ugyanezt a `$IFS` egy másik értékével:

```bash
csv="first,second,third"
IFS=","
for word in $csv; do echo "$word"; done
```
kimenete
```none
first
second
third
```

#### A szófelbontás kikapcsolása

A szófelbontást úgy kapcsolhatod ki, hogy a `$IFS` értékét üres stringre állítod

```bash
sentence="The quick brown fox jumps."
IFS=    # or explicitly, IFS=""
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
kimenete
```none
1 The quick brown fox jumps.
```

A változók idézőjel nélkül hagyása azonban nem ajánlott, hacsak nem kapcsolod ki a fájlnévkiterjesztést is.
Az alábbiakban megnézzük, hogyan teheted meg.

### Fájlnévkiterjesztés

A glob mintákkal tömören megadhatsz egy fájlhalmazra illeszkedő mintát.
Például egy könyvtár összes Markdown-fájlját a `*.md` mintával illesztheted.
A [glob minták][glob] a Unix megszületése óta léteznek.

A glob helyettesítő karakterei a következők:

* `*` nulla vagy több tetszőleges karakterre illeszkedik,
* `?` pontosan egy tetszőleges karakterre illeszkedik,
* `[...]` pontosan egy karakterre illeszkedik a zárójelek között felsorolt karakterek közül.

   ~~~~exercism/advanced
   <details><summary>
   Rengeteg részlet van a karakterkészletekről.
   Kattints ide a megjelenítésükhöz.
   </summary>

    * `[abc]` pontosan egy olyan karakterre illeszkedik, amely `a`, `b` vagy `c`.
        * hogy egy literál csukó zárójelet is szerepeltess a kifejezésben, tedd azt a nyitó zárójel utáni első karakterré (egy opcionális `^` után)
            * a `[][]` egy karakterkészlet, amely csukó vagy nyitó zárójelre illeszkedik.
            * vagy menekítsd fordított perjellel: `[[\]]`
    * `[x-y]` pontosan egy olyan karakterre illeszkedik, amely az `x` és `y` közötti _tartományba_ esik
        * hogy egy literál kötőjelet is szerepeltess egy karakterkészletben, annak vagy a nyitó zárójel utáni első karakternek (egy opcionális `^` után), vagy a csukó zárójel előtti utolsó karakternek kell lennie.
            * a `[-xy]` és a `[xy-]` is pontosan egy olyan karakterre illeszkedik, amely `-`, `x` vagy `y`
            * vagy menekítsd fordított perjellel: `[x\-y]`
        * több tartomány is megadható, például a `[0-9A-Fa-f]` egy hexadecimális számjegyre illeszkedik
    * `[^abc]` pontosan egy olyan karakterre illeszkedik, amely **NEM** `a`, `b` vagy `c`,
    * `[^x-y]` pontosan egy olyan karakterre illeszkedik, amely **NEM** esik az `x` és `y` közötti tartományba
    * `[[:character_class:]]` egy olyan karakterre illeszkedik, amely a megnevezett »character_class« kategóriába tartozik
        * az elérhető karakterosztályok a következők:
            * `lower` -- kisbetűk
            * `upper` -- nagybetűk
            * `alpha` -- betűk
            * `digit` -- számjegyek
            * `alnum` -- betűk és számjegyek
            * `space` -- whitespace
            * `blank` -- vízszintes whitespace (szóköz és tabulátor)
            * `xdigit` -- hexadecimális számjegyek
            * `word` -- azonosítóban engedélyezett karakterek (betűk, számok, alulvonás)
            * `punct` -- írásjelek
            * `cntrl` -- vezérlőkarakterek
            * `graph` -- »látható« karakterek
            * `print` -- látható karakterek és a szóköz
        * ezek kombinálhatók:
            * az `[[:alpha:]]` osztály a `[[:lower:][:upper:]]` osztályokból áll
            * az `[[:alnum:]]` osztály a `[[:alpha:][:digit:]]` osztályokból áll
            * a `[[:word:]]` osztály a `[[:alnum:]_]` osztályból áll
            * az alulvonás (oktális 137) egyszerre `[[:word:]]` és `[[:punct:]]`
            * a `[[:graph:]]` osztály a `[[:alnum:][:punct:]]` osztályokból áll
            * a `[[:print:]]` osztály a `[[:graph:] ]` osztályból áll -- csak a szóközt (oktális 040) tartalmazza, nem más whitespace-t.
   </details>   
   ~~~~

#### Végighaladás egy fájllistán

Egy fájllistán `for` ciklussal haladhatsz végig

```bash
for file in *.csv; do
    do_something_with "$file"
done
```

Figyeld meg, hogy a `"$file"` változó idézőjelben van.
A glob minta olyan fájlokat is visszaadhat, amelyek nevében szóköz van.
Idézőjelbe kell tennünk a változót, hogy a `do_something_with` parancs pontosan egy argumentumot kapjon: a fájl nevét.

#### A glob minták nem reguláris kifejezések

A glob minták **nem** reguláris kifejezések.

* pontosan egy karakterre illeszkedik
   * regex `.`
   * glob `?`
* nulla vagy több karakterre illeszkedik
   * regex `.*`
   * glob `*`
        * a `.*` glob minta jelentése: »olyan fájlnévre illeszkedik, amelynek első karaktere egy literál pont, amit nulla vagy több tetszőleges karakter követ«.
* egy vagy több karakterre illeszkedik
   * regex `.+`
   * glob `?*`
* a regex és a glob karakterkészletei ugyanúgy viselkednek.

#### Idézőjelek és fájlnévkiterjesztés

Vannak esetek, amikor a fájlnévkiterjesztést szeretnéd letiltani.
A felhasználói bemenet kezelése pont ilyen eset.
Vegyük ezt a kódrészletet

```bash
read -p "Enter something: " user_input
echo $user_input
```

Ha a felhasználó egy csillagot (`*`) ír be, mi lesz a kimenet?
Az aktuális könyvtár fájljainak listája.
Ez valószínűleg nem az, amit szeretnél.

Egy másik példa: mintákat adunk át argumentumként olyan programoknak, amelyek mintákat várnak.
A `tr` programot gyakran használják szövegszerkesztésre. Egy változó értékének kisbetűsítéséhez ezt teheted

```bash
var="My Puppet"
echo "$var" | tr '[:upper:]' '[:lower:]'
```
kimenete
```none
my puppet
```

Gyakori hiba, hogy elfelejtjük idézőjelbe tenni a `tr` argumentumait: `tr [:upper:] [:lower:]`

~~~~exercism/caution
Miért jelent ez problémát?
Az idézőjel nélküli glob minták arra a fájllistára bővülnek ki, amelyek illeszkednek.
Tegyük fel, hogy a szkripted felhasználójának vannak `p`, `u` és `w` nevű fájljai az aktuális könyvtárban:

```bash
touch p u w
var="My Puppet"
echo "$var" | tr [:upper:] [:lower:]
```

Ez hibát eredményez!

Az idézőjel nélküli `[:upper:]` minta a `:`, `u`, `p`, `e` vagy `r` karakterek bármelyikére illeszkedik.
Az idézőjel nélküli `[:lower:]` minta a `:`, `l`, `o`, `w`, `e` vagy `r` karakterek bármelyikére illeszkedik.
A bash az első mintához a `p` és `u` fájlt illeszti, a másodikhoz a `w` fájlt, és a `tr` így hívódik meg:

```bash
echo "$var" | tr p u w
```

Ez pedig rossz számú argumentum a `tr` számára.
~~~~

#### A fájlnévkiterjesztés kikapcsolása

A fájlnévkiterjesztést a [`set`][set] paranccsal kapcsolhatod ki.

```bash
echo *      # prints a list of files
set -f      # disable filename expansion
echo *      # prints a literal asterisk
set +f      # enable filename expansion
```

#### A fájlnévkiterjesztés szabályozása

A beépített [`shopt`][shopt] parancsnak több beállítása is szabályozza, hogyan működik a fájlnévkiterjesztés.
Néhány érdekesebb közülük:

* `shopt -s nocaseglob` -- kis- és nagybetűt nem megkülönböztető illesztés
* `shopt -s extglob` -- kiterjesztett minták engedélyezése
* `shopt -s nullglob` -- ha egyetlen fájl sem illeszkedik, a minta helyére semmi sem kerül.
   Az alapértelmezett viselkedés az, hogy a minta literál stringként a helyén marad.
