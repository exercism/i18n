# Bevezetés

A `channel-chatter` feladatban már *használtál* streameket, a `boatswains-bilge`-ben pedig meg is szabadultál tőlük. Ez a feladat az első saját streamod: egy osztály, amely megvalósítja a [protokollt][stream-protocol], így ugyanaz a `with-input-stream` / `read1` / `stream-read1` kód, amely egy `<string-reader>`-en működött, a te streameden is működni fog.

## Mixinek: az osztályhierarchia másik fele

A `TUPLE: child < parent …` szerkezetet már ismered a `dragons-descendants` feladatból: ez egy egyetlen szülős hierarchia, ahol a slotok lefelé öröklődnek. A Factorban van egy *második* mód is az osztálygráf bővítésére: **a nyílt mixinek**. A `MIXIN: m` egy olyan osztályt deklarál, amelynek nincsenek slotjai, és amelyhez más osztályok utólag csatlakozhatnak az `INSTANCE: c m` segítségével. A tagság több-a-többhöz jellegű: egy osztály annyi mixin példánya lehet, amennyi csak tetszik.

A streamek protokollja két mixinnel jelöli, hogy az interfész melyik felét valósítja meg egy osztály:

```factor
INSTANCE: my-stream input-stream    ! readable
INSTANCE: my-stream output-stream   ! writable
```

Egy stream lehet az egyik, a másik, vagy mindkettő. Az `input-stream` (vagy `output-stream`) generikus metódusai ezután minden olyan osztályra elirányítanak, amely csatlakozott a mixinhez. Így találnak el a környezeti `read1`, `stream-contents`, `with-input-stream` stb. a te osztályodig.

A mixinek *nyíltak*: a mixin deklarálása után is hozzáadhatsz új tagot, akár egy másik szótárban is. Ez a különbség a `TUPLE: < parent`-hez képest, ahol a kapcsolat már a gyermekosztály deklarálásakor rögzül.

## A protokoll generikusai

A protokoll generikusai az `io` szótárban találhatók:

```
stream-read1         ( stream -- elt/f )
stream-read          ( n stream -- seq/f )
stream-read-unsafe   ( n buf stream -- count )
stream-write1        ( elt stream -- )
stream-write         ( seq stream -- )
stream-flush         ( stream -- )
stream-element-type  ( stream -- type )
```

A `stream-read1` visszaadja a következő bájtot (vagy `f`-et a stream végén); a `stream-write1` pedig egyet ír. A `stream-read-unsafe` az alacsonyabb szintű kötegelt olvasás, amelyet a legtöbb bemeneti stream biztosít; a `stream-read` erre épül, és kezeli a memóriafoglalást. A `stream-element-type` megmondja, hogy a stream bájtokkal (`+byte+`) vagy karakterekkel (`+character+`) dolgozik-e; amikor egy másik streamet csomagolsz be, a legegyszerűbb megvalósítás egyszerűen továbbadja a hívást a mögöttesnek.

## A takarítás a `destructors`-ból jön

A streamek disposable objektumok: egy saját stream kiterjeszti a `disposable`-t, és megvalósítja a `dispose*`-ot. Ez a `boatswains-bilge`-ből ismert keretrendszer, most egy streamosztályra alkalmazva:

```factor
TUPLE: my-stream < disposable underlying ;

: <my-stream> ( underlying -- s )
    my-stream new-disposable swap >>underlying ;

M: my-stream dispose* underlying>> dispose ;
```

Ha ez megvan, a `channel-chatter`-ből ismert összes `with-…` kombinátor automatikusan működik a te streameden.
