# Névjegy

A dinamikus memóriát olyan könyvtári függvények valósítják meg, amelyeket a programozó a futásidőben történő memóriafoglaláshoz és -felszabadításhoz használ.
Mivel a programozó szabályozza a memória foglalását és felszabadítását, a dinamikus memória annyira biztonságos, amennyire a programozó mentes az emberi hibáktól.
Ezért a dinamikus memória a programozási hibák egyik fő forrása, és a hackertámadások egyik fő célpontja.

A dinamikus memóriát olyan változókhoz használjuk, amelyek mérete csak futásidőben derül ki.
Ez általában hasznos az olyan tömböknél, amelyek elemszáma futásról futásra változhat.
A változó hosszúságú tömbök (VLA) egy másik módja az olyan tömbök kezelésének, amelyek elemmérete csak futásidőben ismert.
A VLA automatikus tárolást használ, ami azt jelenti, hogy a memóriája a definiáló blokk elhagyásakor megsemmisül.
(A tárolással kapcsolatos további információkért lásd a [tárolási osztály meghatározók](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers) fogalmat.)
A VLA-kat a C99 hozta be a C nyelvbe, de a C11 óta a VLA-k opcionálisak, így a C11-et és az újabb szabványokat támogató fordítóknak nem kell támogatniuk a VLA-kat.
A változó hosszúságú tömbök részletes elemzése meghaladja e cikk kereteit.

## malloc

A `malloc` a `stdlib.h` fejlécfájlban deklarált függvény, amelyet dinamikus memória foglalására használunk.
Ha a foglalás sikeres, egy mutatót kapunk vissza, amely a lefoglalt memória első bájtjának címére mutat.
Ha a foglalás sikertelen, `NULL`-t ad vissza.
Érdemes ellenőrizni a `malloc` eredményét, hogy nem `NULL`-e, és ha sikertelen, szépen kezelni.
A visszaadott mutató `pointer-to-void` típusú, amely nagyjából „generikus” mutatónak tekinthető, és átalakítható arra a konkrét típusra, amelyet a memória használ.
A `malloc` egyetlen paramétert vár, amely a kívánt memória mérete bájtban.
A tömb lefoglalásához szükséges teljes méret az egyes elemek adattípusának mérete szorozva az elemek számával.
A `sizeof` operátort szokás arra használni, hogy megkapjuk az egyes elemek adattípusának méretét.
Az alábbi példa ezt szemlélteti

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

Fontos megjegyezni, hogy a `malloc` által újonnan lefoglalt memória nincs inicializálva, hanem szemét értékeket tartalmazhat.
Vedd észre, hogy a `numbers` mutató `sizeof` értéke nem a tömb elemeinek száma, és nem is a lefoglalt memória teljes mennyisége.
A `malloc` által visszaadott mutató mérete megegyezik bármely mutató méretével az adott rendszeren.
A példakód 64 bites rendszeren futott, így a mutató mérete 8 bájt volt (bájtonként 8 bittel szorozva = 64 bit).
A mutató típusa implicit módon `pointer-to-void`-ból `pointer-to-int`-té alakult.
Az, hogy a `pointer-to-int` egyetlen `int`-re vagy `ints` tömbjére mutat, olyan, amivel a programozó úgy bánik, ahogy jónak látja.
Például

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

Ha az érték(ek)et bizonyosan írjuk, mielőtt olvasnánk, akkor a `malloc` használata hatékony módja lehet a memóriafoglalásnak.
De ha fennáll a lehetősége, hogy az érték(ek)et inicializálás előtt olvassuk, akkor a `malloc` használata kockázatos.
A memóriafoglalás biztonságosabb módja a `calloc` használata, amely az újonnan lefoglalt memóriát nullára inicializálja.

Vedd észre a fenti példákban, hogy `free(numbers)` szerepelt.

## free

A `free` a `stdlib.h` fejlécfájlban deklarált függvény, amelyet a dinamikusan lefoglalt memória felszabadítására használunk.
A dinamikusan lefoglalt memória addig marad lefoglalva, amíg a `free` fel nem szabadítja.
Egyes operációs rendszerek automatikusan felszabadíthatják a dinamikusan lefoglalt memóriát, amikor a program befejeződik, de a legjobb gyakorlat, ha nem támaszkodunk erre.
A `free` egyetlen paramétert vár: egy mutatót a dinamikusan lefoglalt memóriára.
A `free` használata vagy hiánya több memóriaproblémával jár együtt.

#### memóriaszivárgás

Ha a dinamikusan lefoglalt memóriát nem szabadítjuk fel, miután a rá mutató hivatkozás eléri élettartama végét, vagy más módon megszűnik, azt memóriaszivárgásnak nevezzük.
A szivárgó memória olyan memória, amelyet a rendszer lefoglalva tart, de a program már nem fér hozzá.
Ez különösen akkor lehet probléma, ha a memóriát ciklusban foglaljuk le, a ciklus végén nem szabadítjuk fel, majd a ciklus elején újra lefoglaljuk.
Ha elég sok memóriát foglalunk le anélkül, hogy felszabadítanánk, a memóriafoglalási hívás meghiúsul, mert nem marad elegendő memória a foglaláshoz.
Fontos megjegyezni, hogy bár a dinamikusan lefoglalt memóriát a rendszer a felszabadításig lefoglalva tartja, a hozzá rendelt mutató `scope`-ja csak a blokkra korlátozódhat.
Például a `malloc`-os példákban a memória a `my_function`-ben van lefoglalva.
Ez a memória szivárogna, ha a rá mutató mutatót nem adnánk vissza, és nem használnánk a `main`-ben a `numbers` mutató beállítására.
Így a `numbers` mutató átadása a `free`-nek felszabadítja a `my_function`-ben lefoglalt memóriát.

#### felszabadítás utáni használat (**UAF**)

Ha a memóriát a felszabadítása után érjük el, az érték(ek) bármi lehet(nek).
A következő példában a `numbers` által mutatott memória felszabadul, majd a `printf` olvas belőle.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

A `numbers` mutatót a felszabadítása után lógó mutatónak nevezzük.
Egy lógó mutató a szándékolt memóriától eltérő memóriára mutathat.
Így a lógó mutató adatsérüléshez, valamint tetszőleges kód behelyettesítéséhez és végrehajtásához vezethet.
Egy olyan mutató, amely lefoglalt memóriára mutat, és amelyet nem töröltünk `NULL`-ra állítással, felhasználható a program feltörésére.
A fenti példában, ha a `numbers` a felszabadítás után így lett beállítva: `numbers = NULL;`, akkor a következő `printf` a program leállását eredményezné, és a `numbers[0]` olvasásakor talán szegmentálási hibát jelezne.

#### kétszeres felszabadítás

Ha a `free`-t kétszer hívjuk meg egy dinamikusan lefoglalt memóriára mutató mutatón, az nem definiált viselkedést (**UB**) eredményez.
Ez azt jelenti, hogy a fordító tetszőlegesen kezelheti, ahogy akarja.
A következő példa két különböző fordítóval lefordítva két különböző eredményt adhat

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

Az első és a második fordító nem jelzett futásidejű hibát, amikor a `numbers` a `free` minden hívása között `NULL`-ra volt állítva, de ez egy harmadik fordítóval nem lenne garantáltan működőképes.
A kétszeres felszabadítás gyakori forrása, ha két mutató ugyanarra a dinamikusan lefoglalt memóriára mutat.
Az egyik mutató a program egyik pontján egy tömb elejére mutathat, a másik mutatót pedig a program egy másik pontján a tömb bejárására használhatjuk.
A program különböző pontjain mindkét mutatót felszabadítjuk, ezzel kétszeres felszabadítást okozva.

## calloc

A `calloc` a `stdlib.h` fejlécfájlban deklarált függvény, amelyet dinamikus memória foglalására és az újonnan lefoglalt memória nullára inicializálására egyaránt használunk.
Ha a foglalás sikeres, egy mutatót kapunk vissza, amely a lefoglalt memória első bájtjának címére mutat.
Ha a foglalás sikertelen, `NULL`-t ad vissza.
Érdemes ellenőrizni a `calloc` eredményét, hogy nem `NULL`-e, és ha sikertelen, szépen kezelni.
A visszaadott mutató `pointer-to-void` típusú, amely nagyjából „generikus” mutatónak tekinthető, és átalakítható arra a konkrét típusra, amelyet a memória használ.
A `calloc` két paramétert vár.
Az első paraméter megadja, hogy hány darabot szeretnénk lefoglalni a megadott adattípusból.
A második paraméter a lefoglalni kívánt adattípus mérete.

A következő példában minden `printf` utasításnak mindig `0`-t kell mutatnia, mert a `calloc` garantáltan nullázza az újonnan lefoglalt értékeket.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

A `realloc` a `stdlib.h` fejlécfájlban deklarált függvény, amelyet a meglévő lefoglalt memória bővítésére vagy zsugorítására használunk.
Ha az újrafoglalás sikeres, egy mutatót kapunk vissza, amely az újrafoglalt memória első bájtjának címére mutat.
Ha az újrafoglalás sikertelen, `NULL`-t ad vissza.
Érdemes ellenőrizni a `realloc` eredményét, hogy nem `NULL`-e, és ha sikertelen, szépen kezelni.
A `realloc` két paramétert vár.
Az első paraméter egy mutató a meglévő, újrafoglalandó memóriára.
A második paraméter az újrafoglalt memória mérete bájtban.
A memória bővítése előtt beállított értékek megmaradnak.
Fontos megjegyezni, hogy a memória bővítésekor hozzáadott memória nincs nullára inicializálva, és az érték(ek) bármi lehet(nek).
Ráadásul a memória zsugorításakor eltávolított memória sincs inicializálva, és megőrizheti az érték(ek)et.
A következő példa egy tömb bővítését és zsugorítását mutatja be

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## Amikor az átadott méret 0

Ha a `malloc`, `calloc` vagy `relloac` függvénynek átadott méret `0`, akkor az történik, amit a fordító implementációja meghatároz.
A fordító vagy `NULL` mutatót ad vissza, vagy nem null mutatót.
Például ha egy `char`-ra mutató mutató számára foglalunk memóriát, a fordító vagy `NULL`-t ad vissza, vagy egy nem null mutatót egy üres stringre.
A különböző fordítóknál tapasztalható eltérő eredmények elkerüléséhez a legjobb, ha nem foglalunk 0 mérettel.
