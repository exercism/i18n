# Bevezetés

A literálok olyan rögzített értékek, amelyeket közvetlenül a kódban használunk.
Futásidőben nincs szükségük semmilyen számításra.
Többféle formában fordulnak elő, hogy hatékonyan ábrázolják a különböző adattípusokat.
A leggyakoribb literálok numerikus jellegűek, de léteznek literáloperátorok dátum-, idő- és string-típusokhoz is.
Egy későbbi fogalom bemutatja, hogyan használhatók a felhasználó által definiált literáloperátorok.

## Numerikus literálok

A numerikus literálok közé tartozik a decimális, az oktális, a hexadecimális és a bináris ábrázolás.
Ezekkel az alapokkal már találkoztál a [számok fogalomban][numbers-concept].

A fordító az olyan ábrázolásokat, mint a `23`, a `0x50f7ba11` és a `0xba5eba11`, `int`-ként értelmezi.
Az általános `int` típus előjeles, és ([a fordítótól és a rendszertől függően][in-depth-integers]) gyakran a `-2'147'483'648` és `2'147'483'647` közötti tartományt fedi le.
Ez a legtöbb esetben elegendő, és nem kell aggódnod a konkrét típus miatt.

Egyes felhasználási esetek nagyobb tartományt vagy nagyon kis memórialábnyomot igényelnek.
Hogy egyértelmű legyél, a numerikus literállal közvetlenül megadhatod a konkrét egész típust.

Ha nincs szükség negatív számokra, de a nagyobb tartományra igen, akkor az `u` vagy `U` utótagot használjuk az _előjel nélküli_ egészekhez.
Még nagyobb tartományokhoz `L`, sőt `LL` is használható a long és long long típusokhoz.

~~~~exercism/caution
A kisbetűs `l` használata megengedett, de könnyen összetéveszthető az `1` számmal, ezért nem ajánlott.
~~~~

```cpp
auto net_worth_christian_grey{2'500'000'000U}; // out of range for 32-bit integers
auto net_worth_carlisle_cullen{46'000'000'000LL}; // int and uint are not enough
```

A lebegőpontos számok a fordítás során általában `double` típusként értelmeződnek.
Ez jó alapértelmezés, és ritkább, hogy szűkebb `float` típusra van szükség, mint a fenti előjel nélküli példa.

~~~~exercism/advanced
A [C++23 szabvány][cpp23-literals] finomabb szabályozást vezet be az olyan literálokkal, mint az `f128` vagy az `F16`.
Néhány fordító engedélyezi a saját literáljait.
A GCC megengedi a `d` literálként való használatát, de ezt a szabvány nem írja elő, és akadályozhatja a platformok közötti kompatibilitást.

[cpp23-literals]: https://en.cppreference.com/w/cpp/language/floating_literal

~~~~

```cpp
auto light_year_in_m{9.46073e+15f}; // well in the range of float
auto earth_to_edge_comoving_distance_in_nm{4.32355e+32}; // needs double type for magnitude
auto eulers_number{2.718281828459045}; // needs double type for precision
```

## Karakter- és stringliterálok

Más fogalmak már használtak karakterliterálokat szimpla idézőjelekkel, például `'}'` vagy `'@'`.

A C++-ban a `char` csak az első 128 [ASCII-karakterkódra][ascii-code] korlátozódik.
Ha több ASCII-karaktert vagy kiterjesztett ASCII-karaktert, például a `‰` jelet, vagy akár Unicode-karaktereket, például a `麗` és `ẞ` jeleket akarsz használni, más típusokra van szükség.
Egy korábbi fogalomban a stringliterálokat _kettős idézőjelekkel_ vezettük be: `"一体どういう意味ですか。C++です"`.
Ennek a japán mondatnak a tényleges típusa `const char (&)[46]`, azaz egy C-stílusú string.

A stringliterálok használata alapértelmezés szerint nincs engedélyezve.
Ahhoz, hogy a _string_ literált (`""s`) vagy a _string-view_ literált (`""sv`) használd, a megfelelő névtér használatával kell ezt jelezned:

```cpp
#include <string>
#include <string_view>

using namespace std::literals;

auto green_light{"무궁화 꽃 이 피었 습니다"};
// green_light type is const char (&)[36]
auto umbrella{"달고나"s};
// umbrella type is std::basic_string<char>, the same as std::string
auto il_nam{"보는 것이 하는 것보다 더 재미있을 수가 없지"sv};
// il_nam type is std::basic_string_view<char>
```

A _string_view_ egy konstans stringre mutató referenciaként fogható fel.
