# Névjegy

## Összett típusok

Gyakran hasznos egyedi típusokat definiálni a programjainkban.

Új primitív típusokat létrehozni lehetséges, de ritkán teszünk ilyet.
A beépített [primitív típusok][primitive] nem önkényes választás eredményei: szorosan megegyeznek az LLVM-fordító szabványos típusaival, amelyet a Julia a JIT-fordításhoz használ.

Sokkal hasznosabb viszont, hogy névvel ellátott mezőkkel rendelkező [összetett típusokat][composite-types] definiálhatunk.

Más nyelvekben is található valami hasonló, ezeket `structs` vagy `records` néven ismerik.
A Julia dokumentációja `composite types` néven említi őket, bár (némi ellentmondással) a nyelv szintaxisa a `struct` kulcsszóval definiálja őket.

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

Néhány pontot érdemes megjegyezni a fenti példában:

- Az `id` számára nincs megadva típus, így a fordító ezt `id::Any`-ként értelmezi.
  - **Megjegyzés:** a gyakorlatban a legjobb segíteni a fordítónak azzal, hogy egy mező típusát konkrét típussal adjuk meg.
  - Egy [későbbi fogalomban][parametric] látni fogjuk, hogy a paraméterek használata egy másik lehetőség.
- A típus nevét konstruktorként használjuk, mint a `Person(id, name, age)` esetében, hogy egy `Person` típusú példányt kapjunk.
- Az egyes mezők pontjelöléssel érhetők el, ugyanúgy, mint a [nevesített tuple-ök][named-tuple] esetében.

A `Person` típusú elemek módosíthatatlanok, ezért a frissítés nem megengedett.

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

Ha módosíthatóságra van szükség, tedd hozzá a `mutable` kulcsszót a definícióhoz.

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

A konstruktor alapértelmezés szerint megköveteli, hogy a mezők ugyanabban a sorrendben jelenjenek meg, mint a definícióban, ami bonyolultabb típusoknál kényelmetlenné válik.

A `@kwdef` makró használata két új lehetőséget kínál:

- A konstruktor kulcsszavakat használ, nem pozíciót.
- A mezőknek lehet alapértelmezett értékük, és opcionálisan el is hagyhatók a konstruktorból.

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## Összetett típusok hierarchiája

Eddig csak konkrét összetett típusokat hoztunk létre.
Ha ellenőrzöd, mindegyik az `Any` altípusa.

Amikor több egymással összefüggő típust hozunk létre, valószínűleg ésszerűbb hierarchiát definiálni számukra.
Ez nagyon egyszerűen megtehető.

Először hozzunk létre egy absztrakt típust:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

Ezután tegyünk egy `<:` operátort a típusdefinícióba, hogy jelezzük a kapcsolatot.

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

Ismételd meg, ahányszor szükséges, de ne feledd, hogy a konkrét típusok altípusosítása nem megengedett.

Egy bonyolultabb hierarchiához hozz létre absztrakt altípusokat, ahogy szükséges.

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

Egy ilyen hierarchia értéke akkor válik világosabbá, amikor eljutunk a `Multiple Dispatch` fogalomhoz, és meglátjuk, hogyan kezelik a függvények az argumentumok típusait.


## Belső konstruktorok

A fogalom elején láttuk, hogy a típus nevét konstruktorként használjuk az adott típusú elemek létrehozásához:

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)
```

Itt a `Person()` az úgynevezett `outer constructor`.
A mezők típusait ellenőrzi a rendszer a típusdefinícióval való kompatibilitás szempontjából, és szükség esetén hibát jelez.

Tegyük fel, hogy a bevitt _értékekre_ szeretnénk megkötéseket, nem csak a _típusokra_?

Ekkor a típusdefiníción belül elhelyezhetünk egy `inner constructor`-t, amely elvégzi a megfelelő ellenőrzéseket.

Például van egy `AbstractPoint` absztrakt típusunk, amely `(x, y)` koordinátákat vesz fel, de szeretnénk egy olyan altípust, amelyre a `y > x` megkötés érvényes.

```julia-repl
julia> abstract type AbstractPoint end;

julia> struct Point <: AbstractPoint
           x::Integer
           y::Integer
       end;

julia> struct ConstrainedPoint <: AbstractPoint
           x::Integer
           y::Integer
           
           ConstrainedPoint(x, y) =
               y > x ? new(x, y) : @error("require y > x")
       end;
       
julia> Point(3, 2)
Point(3, 2)

julia> ConstrainedPoint(3, 2)
Error: require y > x

julia> ConstrainedPoint(3, 5)
ConstrainedPoint(3, 5)
```

A `new()` függvény _kizárólag_ belső konstruktorokban használható, és visszaadja a kívánt elemet, ha a bemenetek érvényesnek bizonyulnak.

Érvénytelen bemenet esetén leállhatunk egy hibaüzenettel, mint a példában.
Másik lehetőség, hogy egy helyőrzőt, például a `nothing` vagy `missing` értéket használod.
További részletekért lásd a [`Nothingness`][nothingness] fogalmat.
