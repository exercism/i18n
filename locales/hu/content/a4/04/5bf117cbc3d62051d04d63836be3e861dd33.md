# Bemutató

Az Elm egy élvezetes nyelv megbízható webalkalmazások építéséhez.
Barátságos hibaüzenetei vannak, remek a teljesítménye, kicsi a mérete, és nincsenek futásidejű kivételei.

Az Elm talán leghíresebb és legszélesebb körben másolt része az Elm Architecture: egy egyszerű minta a webalkalmazások felépítésére, és minden Elm webalkalmazás így íródik.

A lényeg az, hogy a kódod az alkalmazásod állapotát leíró `Model`, a modelledet frissítő `update` és a modelledet megjelenítő `view` köré épül.

A `Model` tartalmazza az alkalmazás állapotát, vagyis minden adatot, amire az alkalmazásnak szüksége van.
Bármilyen típus lehet, de egy igazán hasznos alkalmazásban általában egy [rekord][record].
Ha elképzelsz egy egyszerű alkalmazást egy szövegmezővel és egy szöveggel, ami a beírt szöveg fordítottját mutatja, a modell így nézne ki.
Ezt a példát az [Elm Guide][elm-guide-text-fields] oldalon is megnézheted.

```elm
type alias Model =
  { text : String
  }
```

Az `update` egy függvény, amit egy `Msg`-gel hívnak meg, amikor valami változik (például a felhasználó rákattint egy gombra).
Megkapja a `Msg`-et és a jelenlegi `Model`-t, és visszaad egy új `Model`-t.
A `Msg` bármilyen típus lehet, de általában egy [egyéni típus][custom-type].

```elm
type Msg
  = TextChanged String

update : Msg -> Model -> Model
update msg model =
  case msg of
    TextChanged newText ->
      { model | text = newText }
```

Ahogy minden egyéni típusnál, a `Msg` változatai annyi tetszőleges információt tartalmazhatnak, amennyire szükségük van.
A fenti példában a `TextChanged` változat egy `String`-et tartalmaz.

A `view` egy függvény, ami olyan HTML-t ad vissza, amit a böngésző megjelenít a felhasználónak.
Megkapja a jelenlegi `Model`-t, és egy `Html Msg`-t ad vissza (ez az a típus, amivel az Elm a HTML-t reprezentálja).
Minden HTML-elemhez (például `<div>`) tartozik egy megfelelő Elm-függvény (`Html.div`) a `Html` csomagban.
Ezek a függvények két paramétert kapnak: az első az attribútumok listája (a `Html.Attributes` és `Html.Events` csomagból), a második pedig a gyermekelemek listája (a `Html` csomag függvényei).
Van egy `text` függvény is, ami HTML szöveges tartalmat reprezentál; ez csak egy string paramétert kap, de egyébként ugyanúgy használjuk, mint a `Html` csomag összes többi függvényét vagy elemét.

A `view` függvény megadhatja, hogy bizonyos események, például egy gombra kattintás vagy egy szövegmezőben a szöveg szerkesztése, egy `Msg` létrejöttét eredményezzék; ezt az Elm Runtime arra használja, hogy meghívja az `update` függvényt, módosítsa a `Model`-t, és előállítsa a frissített HTML-t.
Az alábbi kódban ez a `Html.Events.onInput TextChanged` segítségével történik.

```elm
view : Model -> Html Msg
view model =
  Html.div []
    [ Html.input
      [ Html.Attributes.placeholder "Text to reverse"
      , Html.Attributes.value model.text
      , Html.Events.onInput TextChanged
      ]
      []
    , Html.div [] [ Html.text (String.reverse model.text) ]
    ]
```

A `Html.Events.onInput` egy függvényt (`String -> Msg`) vár, amivel létrehozza a `Msg`-et.
A különböző események attól függően várnak különböző függvényeket, hogy milyen információt tudnak szolgáltatni; így például a `Html.Events.onCheck` (jelölőnégyzetekhez) `Bool -> Msg`-et vár, a `Html.Events.onClick` pedig csak egy `Msg`-et.

Az Elm nyelv tiszta és funkcionális, mutációra nincs lehetőség, ezért mindent, ami változik, az Elm Runtime kezel.
Az Elm csomagjegyzékében megnézheted a különféle [HTML-elemeket][html-elements], [elematribútumokat][element-attributes] és [HTML-eseményeket][html-events].

Az Elmben négy „szinten” írhatsz webalkalmazást, amelyek egyre nagyobb tudásúak és egyre bonyolultabbak (bár az Elm továbbra is élvezetesen egyszerű nyelv és ökoszisztéma marad).
Ezeket mind a [Browser csomag][browser-package] definiálja:

- [sandbox][browser-sandbox]: reagál a felhasználói bemenetre, például gombokra és jelölőnégyzetekre
- [element][browser-element]: HTTP és JavaScript-interop segítségével kommunikál a külvilággal
- [document][browser-document]: vezérli egy weboldal `<title>` és `<body>` elemét
- [application][browser-application]: teljes egyoldalas alkalmazásokat hoz létre, amelyek kezelik az útvonalkezelést / az URL-változásokat

Ez a fogalom a [sandbox][browser-sandbox] szintet használja, mert ez a legegyszerűbb (és mivel sandbox, viszonylag könnyű az Exercism online szerkesztőjével dolgozni).
Egy Elm program belépési moduljának a neve `Main`, az alkalmazást létrehozó függvény neve pedig `main`, ahogy az alábbi példa mutatja.

```elm
import Browser
import Html exposing (Html, Attribute, div, input, text)
import Html.Attributes exposing (placeholder, value)
import Html.Events exposing (onInput)

main =
  Browser.sandbox { init = init, update = update, view = view }

init : Model
init =
  { text = "" }

-- Add Model, Msg, update and view here
```

Az `update` és `view` függvényeket már láttuk, a [sandbox][browser-sandbox] azonban emellett megkövetel egy `init` függvényt is, amely a `Model` kezdeti állapotát adja vissza.
