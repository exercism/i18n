# Bevezetés

A JavaScript beépített `Date` objektummal rendelkezik, amely dátumot és időt tárol, valamint metódusokat biztosít ezek kezelésére.

<!-- prettier-ignore -->
~~~exercism/caution
Ez a Java `java.util.Date` osztályán alapult, amelyet a 2010-es évek elején lecseréltek, de a visszafelé kompatibilitás érdekében a JavaScript `Date` továbbra is megmaradt.

Mivel a dátumokkal való munka általában nehéz, és mivel az időzónakezelés rossz vagy nem is létezik, számos könyvtár létezik, mint például a `moment.js`, `day.js`, `date-fns` és `luxon`.
Ezek egyike sem érhető el az Exercism-ön.

A saját projektjeidben ne használj elavult / nem karbantartott csomagot, mint a `moment.js`, hanem támaszkodj modernebb alternatívákra, például a `luxon`-ra, vagy a még nem széles körben elérhető [Temporal][mdn-temporal]ra.
Ez a feladat a `Date`-re összpontosít, amely a JavaScript végéig releváns marad.

[mdn-temporal]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal

## Létrehozás

A `Date` objektum a `Date` osztály egy példánya.
Létrehozható anélkül, hogy bármilyen argumentumot adnánk át a konstruktorfüggvénynek.
Ennek eredménye egy `Date` objektum, amely az aktuális dátumot és időt reprezentálja:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### Unix időbélyeg (szám)

Ha egy számot adunk át, azt `timestamp`-ként értelmezi.
Az időbélyeg egy egész szám, amely az **1970. január 1. [UTC][defn-utc]+0** óta eltelt **milliszekundumok** számát reprezentálja.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

Az ember azt várná, hogy a `new Date(0)` a "legkorábbi" dátum objektumot hozza létre, de a JavaScript a dátumot a helyi időzónádra konvertálja, ami azt jelenti, hogy valójában csak azok kapják meg a [Unix epoch][defn-unix-epoch] értéket, akik a [GMT / UTC+0][defn-gmt] időzóna környékén vannak.

### ISO 8601 időbélyeg (string)

Átadhatsz egy dátumot reprezentáló string értéket a `Date` konstruktornak.
Az **egyetlen** formátum, amely implementációk között konzisztens, a nemzetközileg elismert és szabványosított úgynevezett [ISO 8601 időbélyeg stringek][defn-iso8601] [egyszerűsített változata][mdn-date-string-format].

Egy pillanat az időben [UTC][defn-gmt] szerint így néz ki:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

Ahol a következő helyettesítések történnek:

| Kulcs | Leírás                                      | Alapértelmezett |
| ----- | ------------------------------------------- | --------------- |
| YYYY  | A naptári év, 4 számjeggyel ábrázolva       |                 |
| MM    | A naptári hónap, 2 számjeggyel ábrázolva    | 01              |
| DD    | A naptári nap, 2 számjeggyel ábrázolva      | 01              |
| T     | Egy literál T betű, elválasztja a dátumot és az időt | T      |
| HH    | Az órák 24 órás formátumban, 2 számjegy     | 00              |
| mm    | A percek, 2 számjegy                        | 00              |
| ss    | A másodpercek, 2 számjegy                   | 00              |
| mss   | A milliszekundumok, 3 számjegy              | 000             |
| Z     | Egy literál Z betű, vagy egy eltolás `+/-HH:mm` |             |

A literál `Z` betű az UTC-t jelzi (nincs időzóna, nincs nyári időszámítás).

Mivel a legtöbb komponensnek vannak alapértelmezett értékei, érvényes a végét elhagyni:

```text
YYYY-MM-DD
```

Alapértelmezésben az idő 00:00:00.000

Ha az időbélyeg nem `Z`-vel végződik, és nem végződik `+HH:mm`-mel vagy `-HH:mm`-mel (ami időzóna-eltolást jelez), történelmi okokból a következő érvényes:

> Ha az időzóna-eltolás hiányzik, a csak dátumot tartalmazó formák UTC időként, a dátum-idő formák helyi időként értelmeződnek.
> Az UTC időként való értelmezés egy történelmi specifikációs hiba miatt van, amely nem volt összhangban az ISO 8601-gyel, de a webes kompatibilitás miatt nem lehetett megváltoztatni.
> Lásd: [Broken Parser – A Web Reality Issue][ref-broken-parser].

### Date objektum

Egy meglévő dátum objektum is használható konstruktor argumentumként.
Ez másolatot készít a meglévő `Date` objektumról, ugyanazzal a dátummal és idővel.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### Egyedi dátum- és időkomponens-értékek megadása

Egy dátumot reprezentáló dátum létrehozható három szám átadásával.
Egy dátumot és időt reprezentáló dátum létrehozható 6 szám átadásával.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

A második érték a `month`, amely januártól `0`-tól indul, decemberig `11`-ig tart.

## `Date.parse()`

Találkozhatsz egy dátumértelmező függvény, a `Date.parse` említésével vagy hivatkozásával.
Mivel ennek a függvénynek csak néhány invariánsa (igazsága) van, és mivel az implementáció többi része nem specifikált (és így nem szabványos), nem szabad használni.

## `Date` komponensek elérése

Különböző metódusok vannak a dátum objektumokon, amelyek a dátum komponenseit adják vissza:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

Mindegyiknek van egy megfelelő `set` változata (például `setFullYear`) az érték frissítéséhez.
Minden túlcsorduló érték átgördül a következő komponensbe:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

Minden metódusnak van UTC változata, amelyek figyelmen kívül hagyják a helyi időzónát.

## Konvertálás dátumból

A dátum objektumoknak van egy `getTime()` metódusuk, amely az UNIX időbélyeget adja vissza milliszekundumban, azaz az 1970. január 1-jei UTC éjfél óta eltelt milliszekundumok számát.
Ezenkívül elérhető a `toISOString()` metódus, amely egy dátum objektumot ISO 8601 időbélyeg stringgé konvertál.

## Dátumok összehasonlítása

A nagyobb mint (`>`) és a nagyobb vagy egyenlő (`>=`), valamint a kisebb mint (`<`) és a kisebb vagy egyenlő (`<=`) közvetlenül használható két dátum között vagy egy dátum és egy szám között.
Ez azért működik, mert a JavaScript megpróbálja a dátumot primitívvé alakítani.

<!-- prettier-ignore -->
~~~exercism/advanced
Amikor két dátum vagy egy dátum és egy szám között végez összehasonlítást, a JavaScript meghívja a [`[Symbol.toPrimitive]("number")`][mdn-to-primitive] metódust, amely belsőleg meghívja a [`date.valueOf()`][mdn-date-value-of] metódust.
Ez utóbbi ugyanaz, mint a [`date.getTime()`][mdn-date-get-time] meghívása.

Ha nem szeretnél erre a viselkedésre támaszkodni, először konvertálj számmá a `getTime()` használatával.

[mdn-to-primitive]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/Symbol.toPrimitive
[mdn-date-value-of]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/valueOf
[mdn-date-get-time]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/getTime
~~~

A dátumok nem hasonlíthatók össze egyenlőséggel (`==` és `===`), de a `.getTime()` eredménye igen.
