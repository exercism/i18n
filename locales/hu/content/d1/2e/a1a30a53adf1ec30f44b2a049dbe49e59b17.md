# Bevezetés

Sok nyelvben létezik valami, például a `null` vagy a `none`, amivel a nem létező értéket lehet jelölni. Mivel a Julia nyelvet nagy mennyiségű (gyakran rendezetlen) adat kezelésére tervezték, többféle formában is kifejezhető benne a semmi.

A cél összességében az, hogy a hiányzó vagy gyanús értékeket rögtön megjelöljük, amikor találkozunk velük, majd pedig kivétel dobása nélkül folytassuk a munkát.

## `nothing`

Ha egy érték valóban nem létezik, azt a `nothing` képviseli. Ez valószínűleg a legközelebbi ahhoz, amit a C (`NULL`) vagy a Python (`None`) tenne.

```julia-repl
julia> n = nothing

julia> isnothing(n)
true

julia> typeof(n)
Nothing
```

A `nothing` tehát a `Nothing` típus egyetlen értéke, és tesztelni is tudjuk.

A `nothing` egy gyakori felhasználása, hogy visszatérési (nem-)értékként szolgál azoknak a függvényeknek, amelyeket csak a mellékhatásaik miatt használunk (nyomtatás, hálózati beállítások, vagy bármi más).

## `missing`

Azokban az esetekben, amikor egy érték elméletben létezik, de nem tudjuk, mi az, a `missing` használatos. Például amikor egy úton haladó járműveket számolunk, a megfigyelőknek szünetre lehet szükségük, vagy az automatikus érzékelők elromlanak, a forgalom viszont tovább folyik.

A `missing` tehát egy helyőrző, amely figyelmezteti az embereket, hogy dönteniük kell, mit kezdjenek az adatokban lévő ezzel a hiányossággal.

```julia-repl
julia> mv = [1, 2, missing]
3-element Vector{Union{Missing, Int64}}:
 1
 2
  missing

julia> typeof(mv)
Vector{Union{Missing, Int64}} (alias for Array{Union{Missing, Int64}, 1})

julia> ismissing.(mv)  # broadcast function, displays as 1 for true, 0 for false
3-element BitVector:
 0
 0
 1
```

Kevés más nyelvben van ez a funkció beépítve, de közeli megfelelői az `NA` az R-ben vagy a `NULL` az SQL-ben.

A kifejezések alapértelmezésben általában `missing` értéket adnak vissza, ha `missing` értékek vannak bennük.
Ha azt szeretnéd, hogy ezeket az értékeket figyelmen kívül hagyják, használd a `skipmissing()` függvényt, hogy ezt egyértelművé tedd:

```julia-repl
julia> mv = [1, 2, missing]
3-element Vector{Union{Missing, Int64}}:
 1
 2
  missing

julia> sum(mv)  # missing in, missing out
missing

julia> skipmissing(mv)
skipmissing(Union{Missing, Int64}[1, 2, missing])

julia> collect(skipmissing(mv))
2-element Vector{Int64}:
 1
 2

julia> sum(skipmissing(mv))  # functions like sum() can work with iterators
3
```

Mivel a `skipmissing` egy iterátort hoz létre, burkold `collect()`-ba, ha vektorra van szükséged.

Néha hasznos a `missing` értékeket valamilyen alapértelmezett értékkel helyettesíteni.
Erre a `@coalesce()` makró hasznos, mert az első nem `missing` értéket adja vissza (vagy `missing`-t, ha nincs más).

```julia-repl
julia> str = ["I", "exist", missing]
3-element Vector{Union{Missing, String}}:
 "I"
 "exist"
 missing

julia> [@coalesce(s, "-") for  s in str]
3-element Vector{String}:
 "I"
 "exist"
 "-"
```

## `NaN`

A „Not a Number” rövidítéseként a NaN egy számítási problémát jelez olyan helyzetekben, ahol számot vártunk volna.

```julia-repl
julia> v = [0, 1, -1]
3-element Vector{Int64}:
  0
  1
 -1

julia> v / 0
3-element Vector{Float64}:
 NaN
  Inf
 -Inf
 
julia> sum(v / 0)
NaN
```

Bármilyen számítás olyan adatokon, amelyek NaN-t tartalmaznak, `NaN` eredményt ad.

Jelenleg nincs külön függvény a `NaN` értékek eltávolítására, de a szabványos `filter()` függvény ezt egészen egyszerűen meg tudja tenni.
Csak azok az értékek másolódnak be az eredménytömbbe, amelyekre valamilyen megadott feltétel `true`:

```julia-repl
julia> filter(!isnan, [1, 2, NaN])
2-element Vector{Float64}:
 1.0
 2.0
```
