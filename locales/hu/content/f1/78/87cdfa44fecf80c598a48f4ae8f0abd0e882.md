# Az Unison alapjai

## Termek és függvények

A termek és a függvények a Unison-program írásának alapegységei.

A „term" az, amit statikus értéknek nevezünk. A `name = expression` formával definiáljuk, amelyet opcionálisan megelőzhet egy `name : MyType` alakú típusszignatúra. A Unison támogatja a típuskövetkeztetést, ezért egyszerű definícióknál előfordulhat, hogy elhagyják a típusszignatúrát.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

A Unison függvényei így néznek ki: `myFunctionName argument1 argument2 = myImplementation`; a függvény nevével kezdődnek, amelyet szóközzel elválasztott argumentumok követnek.

```
getMax a b = Nat.max a b
```

A függvények opcionálisan tartalmazhatnak típusszignatúrát. A jobb oldalon álló utolsó típus mindig a függvény végső visszatérési típusa, az egyes argumentumokat pedig a függvénynyíl `->` választja el.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Egy függvény meghívásához írd le a nevét, majd az argumentumokat, amelyeket csak szóköz választ el.

```
maximum = getMax 1 10
```

Amikor meghívsz egy függvényt, a Unison mindazt, ami közvetlenül tőle jobbra áll, argumentumként próbálja kezelni, ami nem feltétlenül eredményezi a függvénykiértékelés kívánt sorrendjét.

Tegyük fel, hogy az `1` értéket szeretnénk megkapni a következő kifejezésből

```
shouldBe1 = getMax 1 10 - 10
```

Ahogy le van írva, a `shouldBe1` értéke `0` lesz, mert az implicit függvényalkalmazási sorrend a `getMax 1 10`, ami `10`, majd a `10 - 10`, ami `0`.

Zárójelekkel átcsoportosíthatod a kifejezést a kívánt műveleti sorrend szerint.

```
shouldBe1 = getMax 1 (10 - 10)
```

## Többsoros függvények

A Unison többsoros függvényei behúzással vagy `let` blokkokkal jelölik a kódrészek határait, más néven a „lexikai scope"-ot.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Minden, ami ugyanazon a behúzási szinten van, ugyanahhoz a scope-hoz tartozik, ezért hivatkozhatunk a `newBeginning` változóra az utolsó sorban.

## Névterek és `use` utasítások

A névterekkel csoportosítjuk és szervezzük a Unison függvényeit. Gondolhatsz rájuk úgy, mint a „könyvtárakra". Struktúrát és logikai csoportosítást adnak.

Egy `use` utasítással beemelheted a scope-ba egy névtér függvényeit.

Tegyük fel, hogy olyan függvényt írsz, amely Unison `List` értékeket használ. Tudod, hogy szükséged lesz olyan függvényekre, mint a `List.map` és a `List.flatMap`, ahol a `List` a névtér, a `map` és a `flatMap` pedig függvények. Hogy ne ismételd magadat, dönthetsz úgy, hogy a `List` névtér minden elemét a függvényed lexikai scope-jába emeled, így:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

A `use List` sor egyértelművé teszi a `map` és a `flatMap` hivatkozásait. A [`use` utasításokról itt olvashatsz bővebben][use-statements].

## A Unison szabványos könyvtára

A Unison szabványos könyvtárát `base`-nek hívják. Ha követted a gyorsindító útmutatót, és van egy helyben létrehozott codebase-ed, akkor a szabványos könyvtár valószínűleg automatikusan letöltődött. A szabványos könyvtár dokumentációját online böngészheted a [Unison Share][unison-share-base] oldalon.

## Megjegyzések és dokumentációs literálok

A megjegyzések a Unisonban kissé szokatlan funkciót jelentenek. Amikor Unison-kódot írsz, a `.u` kiterjesztésű fájlodban létrehozhatsz olyan szöveget, amelyet nem értelmez a program, a következő szintaxissal:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Azonban_ mivel a Unison-kód az absztrakt szintaxisfájának hash-eként tárolódik, nem szövegalapú fájlként a fájlrendszeren, azok a megjegyzések, amelyek egy adott Unison-függvény vagy term szövegalapú „díszítései" a fájlban, valójában nem menthetők el és jeleníthetők meg újra megosztáshoz. Ha szeretnél információt hozzáadni a Unison termjeidhez úgy, hogy az tárolva legyen, és mások is elolvashassák és megérthessék, használhatsz dokumentációs literált.

A dokumentáció első osztályú érték a Unison programozási nyelvben. Ez azt jelenti, hogy egy `Doc` elem hozzárendelhető értékhez, argumentumként átadható egy függvénynek, vagy visszaadható egy függvény értékeként. A dokumentációs literál elemeket dupla kapcsos zárójelek nyitják és zárják. Így használhatjuk a `Doc` elemet megjegyzésként.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
