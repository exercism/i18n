# A nullázhatóságról

Egy ideális világban számíthatnánk arra, hogy minden szépen definiált, konkrét értékekkel és hézagok nélkül.

Ez ellentmond a mindennapi tapasztalatunknak, ezért sok programozási nyelvben van mód az érték hiányának ábrázolására: null vagy NULL, nil, None, nothing...

Ezt könnyű volt bevezetni (1965-ben), de hamar megbánták.
A feltalálója később „Egymilliárd dolláros hiba” néven emlegette.

Az utóbbi évtizedekben a nyelvtervezők sokféle módszert fedeztek fel, hogy a nullértékek elérhetők, de (többnyire) biztonságosak legyenek.

A Kotlinban néhány [általános elv][ref-null-safety] érvényesül, amelyek [jelentősen eltérnek a Java-tól][ref-java2kotlin].
_A különbségek miatt a Kotlin speciális funkciókkal rendelkezik a Java-interoperabilitás kezelésére, bár a részletek meghaladják e fogalom kereteit._

- A Kotlinban van egy speciális `null` érték.
- Minden típus _alapértelmezés szerint_ nem nullázható (azaz nem lehet `null`).
- Minden típus lehet _nullázható_, de ezt kifejezetten meg kell tenni.
- Azoknak a függvényeknek, amelyek kivétellel meghiúsulhatnak, valószínűleg van egy nullázható visszatérési értékű változatuk.
- A speciális, rendkívül tömör szintaxis igyekszik a nullértékek tesztelését és kezelését a lehető legegyszerűbbé tenni.

## Nullázható változók létrehozása

Egy típus [nullázhatóvá][ref-nullable-type] tehető a `?` utótag hozzáadásával (pl. `String?` a `String` helyett).

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## Hasznos operátorok és függvények

### A [biztonságos hívás operátor][ref-safe-call] `?.`

Egy nem nullázható `String` esetén lekérhetjük a `.length` tulajdonságot.

Egy nullázható `String?` esetében ugyanaz a szintaxis hibát okoz, de a `?.length` használatával számolhatunk a `null` lehetőségével.
A visszatérési típus `Int?`.

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

Ahogy a fenti utolsó sorban láttuk, a `?.` nem nullázható típusokkal is működik.

### Az [Elvis-operátor][ref-elvis] `?:`

Kiterjesztve a biztonságos hívás operátor ötletét, az [Elvis-operátor][wiki-elvis] lehetővé teszi, hogy egy alapértelmezett értéket adjunk meg a `null` helyére.

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### [Nem-null állítás operátor][ref-not-null] `!!`

Ezzel az operátorral egy nullázható típust nem null típusként kényszerítünk kezelni, amikor a programozó biztos ebben.
Talán néha jobban értjük a program logikáját, mint egy túlzottan óvatos fordító?

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

A felelősség most rajtunk van: ha `b` továbbra is `null`, `NullPointerException`-t kapunk.

### [let függvény][ref-let] `?.let`

Ha egy nullázható elemet adunk át egy kódblokknak, végezhetünk konkrét null-ellenőrzéseket: `if (item != null) { do something }`.

Egyszerűbb és idiomatikusabb az `item?.let { do something }` használata.
A `do something` csak akkor fut le, ha az `item` nem null.

### `somethingOrNone()` típusú függvények

Egyes függvények meghiúsulhatnak, például amikor egy string vagy lista érvénytelen indexét kérjük.

Ahelyett, hogy kivételt dobnánk, használhatjuk a függvény [`...OrNull` változatát][ref-elem-at-or-null], hogy (ebben az esetben) `Int?` visszatérési értéket kapjunk.

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
