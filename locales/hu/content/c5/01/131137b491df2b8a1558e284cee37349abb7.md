# Bevezetés

A Java programozási nyelv _kivételeket_ használ a hibák és más rendkívüli események kezelésére.

## Mi a kivétel?

A kivétel olyan esemény, amely egy program végrehajtása során következik be, és megzavarja az utasítások normál menetét.
A kivételeket Javában explicit módon dobjuk, és ezt a műveletet _kivételdobásnak_ nevezzük.
A kivétel kezelésének műveletét _kivétel elkapásának_ nevezzük.

Javában minden kivétel az `Exception` osztály leszármazottja, amely maga a `Throwable` leszármazottja.

A Java kétféle kivételt különböztet meg:

1. Ellenőrzött kivételek
2. Nem ellenőrzött kivételek

### Ellenőrzött kivételek

Az _ellenőrzött kivételek_ olyan rendkívüli állapotok, amelyekre az alkalmazásnak számítania kell, és amelyekből helyre kell tudnia állni.
Az ellenőrzött kivétel egy példája a `FileNotFoundException`, amely akkor fordul elő, amikor egy metódus olyan fájlt próbál beolvasni, amely nem létezik.

Ezt a kivételtípust fordítási időben ellenőrzi a fordító: azoknak a metódusoknak, amelyek ellenőrzött kivételt dobnak, ezt a metódus szignatúrájában is jelezniük kell, és az olyan kódnak, amely esetleg ellenőrzött kivételt dobó metódust hív, kezelnie kell a kivételt, különben nem fordul le.

Minden ellenőrzött kivétel az `Exception` olyan leszármazottja, amely nem terjeszti ki a `RuntimeException`-t.

### Nem ellenőrzött kivételek

A _nem ellenőrzött kivételek_ olyan rendkívüli állapotok, amelyekre az alkalmazás általában nem tud számítani, és amelyekből nem is tud helyreállni.
A nem ellenőrzött kivétel egy példája a `NullPointerException`, amely akkor fordul elő, amikor egy metódus nem `null` értéket vár, de `null`-t kap.

Ezt a kivételtípust nem ellenőrzi a fordító fordítási időben: azoknak a metódusoknak, amelyek nem ellenőrzött kivételt dobnak, nem kell ezt a metódus szignatúrájában jelezniük, és az olyan kódnak, amely esetleg nem ellenőrzött kivételt dobó metódust hív, nem kell kezelnie a kivételt.

Minden nem ellenőrzött kivétel a `RuntimeException`-ból származik, amely maga az `Exception` kiterjesztése.

## Kivételek dobása

Egy metódus Javában a `throw` utasítással dobhat kivételt.

### Ellenőrzött kivétel dobása

Amikor egy metódus ellenőrzött kivételt dob, ezt a metódus szignatúrájában a `throws` kulcsszóval kell jelezni, ahogy az alábbi példa mutatja.
Ez arra kényszeríti a hívó kódot, hogy számítson a kivétel dobására, és ennek megfelelően kezelje azt.

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### Nem ellenőrzött kivétel dobása

Amikor egy metódus nem ellenőrzött kivételt dob, ezt nem kötelező jelezni a metódus szignatúrájában, bár megtehető.

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## Kivételek kezelése

A kivételek kezelése Javában a `try`, `catch` és `finally` kulcsszavakkal történik.

- Azokat az utasításokat, amelyek kivételt dobhatnak, érdemes egy `try` blokkba foglalni.
- A `try` blokkot egy vagy több `catch` blokk követi, amelyek elkapják a `try` blokkban dobott kivételeket.
- A `catch` blokkokat opcionálisan egy `finally` blokk követi, amely a `try` blokk után mindig lefut, függetlenül attól, hogy történt-e kivétel vagy sem.

Az alábbi példa bemutatja, hogyan működnek ezek a kulcsszavak:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

Ebben a példában, amikor nem dobódik kivétel, a következő jelenik meg:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

Ha azonban a `bankAccount.withdraw(amount)` utasítás `InsufficientBalanceException`-t dob, a következő jelenik meg:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

Vagy, ha a `bankAccount.withdraw(amount)` nem ellenőrzött kivételt dob, a következő jelenik meg:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## Hibák

A Javában van egy külön kategória is, a _Errors_, amelybe az alkalmazáson kívül eső súlyos problémák tartoznak.
A hiba egy példája az `OutOfMemoryError`, amely akkor fordul elő, amikor egy alkalmazás több memóriát próbál használni, mint amennyi a rendszeren elérhető.

A nem ellenőrzött kivételekhez hasonlóan a hibákat sem ellenőrzi a fordító fordítási időben.
A különbség az, hogy rendszerszintű problémákat jelölnek, és általában nem az alkalmazás, hanem a Java virtuális gép vagy a környezet dobja őket.
Az alkalmazásoknak általában nem szabad megpróbálniuk elkapni vagy kezelni őket.

Javában minden hiba az `Error` osztályból származik.
