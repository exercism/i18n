# Bevezetés

Gyakran hasznos saját típusokat definiálni a programjainkban.

Új primitív típusokat is létrehozhatunk, de ezt ritkán tesszük.
A beépített primitív típusok nem önkényes választás eredményei: szorosan egyeznek azokkal a szabványos típusokkal, amelyeket a Julia a JIT-fordításhoz használt LLVM-fordítóban megtalál.

Sokkal hasznosabb viszont az a lehetőség, hogy összetett típusokat definiáljunk nevesített mezőkkel.

Más nyelvekben is van valami hasonló, ott `structs` vagy `records` a nevük.
A Julia dokumentációja `composite types` néven emlegeti őket, bár (némi ellentmondással) a nyelv szintaxisa a `struct` kulcsszóval definiálja őket.

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

A fenti példában érdemes megjegyezni néhány dolgot:

- Az `id`-hez nincs megadva típus, ezért a fordító ezt `id::Any`-ként értelmezi.
- A típusnév konstruktorként használható, mint a `Person(id, name, age)` esetében, hogy megkapjuk a `Person` típus egy példányát.
- Az egyes mezők pont jelöléssel érhetők el, ugyanúgy, mint a nevesített tuple-öknél.

A `Person` típusú elemek módosíthatatlanok, ezért nem lehet őket frissíteni.

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

Ha mégis módosíthatóságra van szükség, egészítsd ki a definíciót a `mutable` kulcsszóval.

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

A konstruktor alapértelmezés szerint megköveteli, hogy a mezők ugyanabban a sorrendben szerepeljenek, mint a definícióban, ami bonyolultabb típusoknál kényelmetlenné válik.

A `@kwdef` makró használatával két új lehetőség nyílik:

- A konstruktor kulcsargumentumokat használ a pozicionálisak helyett.
- A mezőknek lehet alapértelmezett értékük, és a konstruktorból akár el is hagyhatók.

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## Összetett típusok hierarchiája

Eddig csak konkrét összetett típusokat hoztunk létre.
Ha utánanézel, mindegyik a `Any` altípusa.

Ha több, egymással kapcsolatban álló típust hozunk létre, valószínűleg ésszerűbb hierarchiát definiálni hozzájuk.
Ez nagyon egyszerűen megtehető.

Először hozzunk létre egy absztrakt típust:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

Ezután a típusdefinícióba írjunk egy `<:` operátort, amivel kifejezzük a kapcsolatot.

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

Ismételd meg annyiszor, amennyiszer szükséges, de ne feledd, hogy konkrét típusokat nem lehet alárendelni.

Egy összetettebb hierarchiához szükség szerint hozzunk létre absztrakt altípusokat.

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

Hogy mennyit ér egy ilyen hierarchia, az akkor válik világosabbá, amikor eljutunk a `Multiple Dispatch` fogalomhoz, és meglátjuk, hogyan kezelik a függvények az argumentumok típusait.
