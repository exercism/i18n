# Bevezetés

A **lebegőpontos szám** egy olyan szám, amelynek lehet tört része, például `-1.23` vagy `3.1415`.

Ahhoz, hogy egy ilyen számot bájtok sorozataként ábrázoljunk, az x86-64 az **IEEE-754** szabványt használja.
Ebben a szabványban a két leggyakoribb formátum az egyszeres pontosságú és a kétszeres pontosságú lebegőpontos szám.
Az x86-64 mindkettőt támogatja.

Az egyszeres pontosságú lebegőpontos szám 32 bites, míg a kétszeres pontosságú 64 bites.

## XMM regiszterek

Az x86-64-ben 16 dedikált regiszter szolgál a lebegőpontos aritmetikához, ezek neve `xmm0`-tól `xmm15`-ig terjed.

Ezek a regiszterek legalább 128 bitesek, de az újabb processzorok ezt 256 vagy 512 bitre növelik.
A gyakorlatban azonban a legtöbb lebegőpontos szám csak a legalsó 32 vagy 64 bitet használja, a kívánt pontosságtól függően.

## Számok közötti átalakítás

Létezik egy utasításcsalád a számformátumok közötti átalakításra: `cvtxx2yy`.

A `xx` és a `yy` nem literálok, hanem helyőrzők:

- `xx` a forrásoperandus típusának helyőrzője.
- `yy` a céloperandus típusának helyőrzője.

Ez a helyőrző sok formát ölthet, többek között:

| helyőrző | jelentés              |
| ----------- | --------------------- |
| `si`        | előjeles egész szám   |
| `ss`        | 32 bites lebegőpontos |
| `sd`        | 64 bites lebegőpontos |

Például:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

Vedd észre, hogy lehetséges egy 32 bites egész számot 64 bites lebegőpontos számmá alakítani, vagy egy 64 bites egész számot 32 bites lebegőpontossá.
Hasonlóképpen az is lehetséges, hogy egy 32 bites lebegőpontos számot 64 bites egész számmá alakítsunk, vagy egy 64 bites lebegőpontos számot 32 bites egésszé.
Más szóval, a `cvtxx2yy` mindkét operandusának mérete _nem kell, hogy megegyezzen_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

Amikor a lebegőpontos szám nem fejezhető ki pontosan egész számként, a `cvtxx2si` a `mxcsr` nevű speciális regiszterben lévő kerekítési vezérlésnek megfelelően kerekíti a számot.
Ez lehet kerekítés a legközelebbire, lefelé kerekítés, felfelé kerekítés vagy csonkítás.
A függvénybe való belépéskor nincs garantált alapértelmezés.

Vedd észre, hogy egy pontos eredményt nem kerekítünk, így azt a kerekítési vezérlés sem befolyásolja.
Például a `42.0` _mindig_ `42`-vé konvertálódik.

Létezik egy hasonló utasításcsalád `cvttxx2si` formátummal (egy plusz `t` betűvel), amely mindig csonkítja az eredményt.

## Kerekítés

A `roundxx` utasításcsalád a forrásoperandusban lévő lebegőpontos számot a céloperandusban tárolt kerekített lebegőpontos számmá alakítja.

Itt a `xx` a szokásos módon az operandusok típusának helyőrzője: `ss` az egyszeres pontosságú, `sd` a kétszeres pontosságú lebegőpontos számokhoz.

Ezek az utasítások egy állandó számot vesznek fel harmadik operandusként.
Ez a szám a kerekítési módot jelöli:

| Szám | Mód          |
| :----- | :----------- |
| 0      | Legközelebbi |
| 1      | Lefelé       |
| 2      | Felfelé      |
| 3      | Csonkítás    |

Például:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

Mivel ezek az utasítások pontos eredményt adnak, egy `cvtxx2si` előkészítéseként használhatók.

## Aritmetikai utasítások

A lebegőpontos számokkal végzett műveletek közül sok ugyanolyan nevű utasítást használ, mint az egész számok megfelelője, de a végére odakerül a szükséges helyőrző (`ss` vagy `sd`).
Ezek az utasítások kétoperandusúak, a szokásos szemantikával, még azok is, amelyek szorzást vagy osztást végeznek:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## Mozgatás

Az egyik XMM regiszterből a másikba mozgató utasítások a `movss` és a `movsd`:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

**Nem** lehetséges egy immediate-et (egy állandó előjeles egész számot) közvetlenül xmm regiszterbe mozgatni.
Ezt a számot először egy általános célú regiszterbe kell mozgatni, majd a `cvtsi2xx` segítségével átalakítani:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## Összehasonlítások

Két utasításcsoport létezik két lebegőpontos szám összehasonlítására.
Formájuk `comixx` és `ucomixx`, ahol a `xx` vagy `ss`, vagy `sd`.
Mindkettő a szokásos módon állítja be a jelzőbiteket a `rflags` regiszterben, ugyanazt a szemantikát követve, mint a `cmp`.

A különbség köztük az, hogy a `ucomixx` beállítja a `parity flag (PF)`-et, ha a két lebegőpontos szám egyike `NaN` értékkel rendelkezik, míg a `comixx` ebben az esetben kivételt vált ki.

A lebegőpontos értékek közötti összehasonlítás _előjel nélküli_:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## Hívási konvenció

A System V ABI esetén a függvények az első nyolc lebegőpontos argumentumot sorrendben kapják, `xmm0`-tól `xmm7`-ig.
A függvények a lebegőpontos értékeket `xmm0`-ban, szükség esetén `xmm1`-ben adják vissza.

Az összes `xmm` regiszter szabadon használható, egyik sem van fenntartva a hívó számára.

## Memória

A lebegőpontos értékek ugyanolyan szemantikával definiálhatók a memóriában, mint az azonos méretű egész számok.
A NASM (The Netwide Assembler, a kurzus által használt assembler) a lebegőpontos értékek tudományos jelöléssel történő deklarálását is lehetővé teszi.

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```
