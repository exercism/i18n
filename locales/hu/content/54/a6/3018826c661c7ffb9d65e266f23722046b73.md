# Bevezetés a Bash shell aritmetikájába

A Bash tud aritmetikát végezni, de _csak egész számokkal_.
Ha lebegőpontos számításokat kell végezned, külső programot kell hívnod (például [awk][awk] vagy [bc][bc]).

Az aritmetikai operátorok (precedenciasorrendben) a kézikönyvben vannak felsorolva: [Shell Arithmetic][arithmetic].

Ráadásul a Bash csak bizonyos helyeken végez aritmetikát (ezeket aritmetikai „kontextusoknak” nevezzük).

## Aritmetikai kiterjesztés

Az aritmetikai kiterjesztés a [parancsbehelyettesítéshez][cmd-sub] hasonlít, csak dupla zárójelekkel.

```bash
$(( expression ))
```

Ez a szintaxis a kifejezés kiértékelésének eredményét adja.
Gyakran arra használjuk, hogy az eredményt egy változóban eltároljuk:

```bash
x=$(( 3 + 4 ))
```

~~~~exercism/note
Hogy mennyi szóközt hagysz a zárójelek között, rajtad áll.
Ez stílus és olvashatóság kérdése.

```bash
x=$(( 3 + 4 ))
y=$((5+6))
```

A barátságos szerződ szeret szóközöket hozzáadni, hogy az aritmetikai kifejezés jobban látható legyen a zárójelek között.
~~~~

## Aritmetikai feltétel

Az aritmetikai feltételt dupla zárójelek között hajtjuk végre, a kezdő `$` _nélkül_:

```bash
(( expression ))
```

Ez nem az eredményt adja vissza.
Viszont előállít egy _kilépési állapotot_.

* A kilépési állapot 0 (siker), ha a kifejezés eredménye **nem nulla**.
* A kilépési állapot 1 (hiba), ha a kifejezés eredménye **nulla**.

~~~~exercism/note
A `((` belsejében a Bash ugyanúgy értelmezi az igaz/hamist, mint a C nyelv: a nulla hamis, a nem nulla igaz.
**Ez pont az ellenkezője annak, ahogy a Bash a kilépési állapotokat értékeli!**
~~~~

Ez a szintaxis jellemzően két helyen fordul elő:

1. egy [`if` utasítás][conditional-if] vagy egy [`while` ciklus][looping-while] COMMAND részeként.

   ```bash
   if (( x == y - 1 )); then ...
   while (( y > 0 )); do ...
   ```

1. önálló utasításként, hogy egy változó értékét módosítsuk.

   ```bash
   (( x = x + 1 ))
   echo "new value for x is $x"
   ```

   ~~~~exercism/caution
   Vigyázz, ha az aritmetikát így használod `set -e` mellett.
   Ha a kifejezés nullára értékelődik ki, a kilépési állapot nem nulla lesz, és a Bash leáll.

   ```bash
   x=0
   (( x++ ))
   echo "you will see this"

   set -e
   x=0
   (( x++ ))
   echo "shell exits on the previous line; you won't see this"
   ```

   A `++` operátorról szóló részletesebb fejtegetésért lásd ezt a cikket: [Postincrement vs Preincrement][incr]

   [incr]: https://thisvsthat.io/postincrement-vs-preincrement
   ~~~~


## Egyéb helyek, ahol aritmetikai kontextus van

Néhány további hely is aritmetikai kontextus:

* Az [aritmetikai for-ciklus][looping-for].

  ```bash
  for (( i = 0; i < 10; i++ )); do
      echo "$i"
  done
  ```

* Egy numerikusan indexelt tömb indexrésze.

  ```bash
  echo "The next element is ${array[x + 1]}"
  # ................................^^^^^
  ```

  A tömbökről bővebben a [Tömbök][arrays] fogalmi leírásban olvashatsz.

* A `${var:offset:length}` kiterjesztés offset és length részei.
* A [`let` beépített utasítás][let].
  * Jegyezd meg, hogy a `(( expression ))` előnyben részesítendő a `let "expresson"` helyett.
    Az aritmetikai feltétel konstrukcióval ellentétben a `let` kifejezés ki van téve a fájlnévkiterjesztésnek és a szófelbontásnak, ráadásul idézőjelek közé kell tenni.
* Változóértékadás, amikor a változónak „integer” attribútuma van.

  ```bash
  # variable x does not have the integer attribute
  x="3 + 4"
  declare -p x      # => declare -- x="3 + 4"

  # variable y has the integer attribute
  declare -i y
  y="4 + 5"
  declare -p y      # => declare -i y="9"
  ```

  ~~~~exercism/note
  A szerző véleménye szerint a `declare -i` felhasználása korlátozott.
  Legfőbb előnye, hogy lehetővé teszi a „csupasz” aritmetikát (az aritmetikai kifejezés szintaxisa nélkül).
  Ez zavart okozhat a kódod olvasóinak, mert az aritmetikai kifejezések váratlan helyeken értékelődnek ki.
  ~~~~

## Változók használata aritmetikai kifejezésekben

Íme az aritmetikai kontextusok egyik jellemzője, amely javítja az olvashatóságot.

```bash
height=10
width=20
area=$(( height * width ))
```

Észrevetted, hogy az aritmetikai kifejezésben szereplő változóknál hiányoznak a `$` dollárjelek?
A Bash ezt megengedi.
Ez sokkal könnyebben olvashatóvá teszi a kifejezéseket.

A kézikönyv így fogalmaz:

> Egy kifejezésen belül a shell-változókra név szerint is hivatkozhatsz a paraméterkiterjesztés szintaxisa nélkül.

Még a tömbök elemeinél is működik:

```bash
point1=(10 15)  # these are (x, y) coordinates
point2=(20 7)
distance_squared=$(( (point1[0] - point2[0])**2 + (point1[1] - point2[1])**2 ))
```

Más paraméterkifejezéseknek viszont a saját speciális szintaxisukat kell használniuk.
Például egy string hosszának megduplázása:

```bash
s="hello world"
len=$(( ${#s} * 2 ))
```

A pozicionális paramétereknek pedig szintén.
Ha az első két pozicionális paraméter a szélességet és a magasságot jelöli:

```bash
area=$(( $1 * $2 ))
```
