# Bevezetés

## Custom Types

Az Elm Custom Type-jai rögzített számú, elnevezett esetet jelölnek. Minden érték pontosan az egyik elnevezett esetnek felel meg.

Egy Custom Type-ot a `type` kulcsszóval definiálsz, és nagyon kevés szintaxist igényel. Ez az Elm programozás egyik legfontosabb technikája, amely arra szolgál, hogy a kódban lehetséges értékek pontosan megfeleljenek a valós életben érvényes értékeknek. Így nem marad hely az érvénytelen adatoknak, és [a lehetetlen állapotokat lehetetlenné teszi a kódban][impossible-states].

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

Egy custom type minden esetéhez tartozhat opcionálisan adat, és a különböző esetekhez különböző típusú adat tartozhat. Ha egyik esethez sem tartozik adat, a diszkriminált unió hasonló ahhoz, amit más nyelvek általában _felsorolásnak_ (vagy _enumnak_) neveznek.

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Egy adott eset értékét úgy hozhatod létre, hogy a nevére hivatkozol (`Spring`), ha az ugyanabban a modulban van definiálva, vagy az `import SeasonModule exposing (Season(..))` formájú szintaxissal van importálva, illetve a teljesen minősített nevére hivatkozol (`Season.Spring`), ha az `import SeasonModule exposing (Season)` formájú szintaxissal van importálva.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

A custom type-ok az Elm minden más eleméhez hasonlóan _strukturális egyenlőséggel_ rendelkeznek, ami azt jelenti, hogy két érték, amely ugyanahhoz az esethez tartozik és ugyanazzal az (opcionális) adattal rendelkezik, egyenértékű.

A custom type-okkal való munka előnyben részesített módja a [mintailesztés][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
