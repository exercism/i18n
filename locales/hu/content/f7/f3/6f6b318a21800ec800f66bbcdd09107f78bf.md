# Névjegy

Egy függvény akkor [farokrekurzív][recursion-tc], ha az _utolsó_ dolog, amit végrehajt, önmagának a meghívása.

Valahányszor meghívnak egy függvényt, a helyi változóit és argumentumait tartalmazó _veremkeret_ rákerül [a függvényhívási verem][call-stack] tetejére. Amikor egy függvény visszatér, a veremkeret lekerül a veremről.

A farokrekurzív függvények lehetővé teszik a [farokhívás-optimalizálást][tail-call-optimization] (vagy farokhívás-kiküszöbölést). Ez egy optimalizálás, amely lehetővé teszi, hogy a következő függvényhívás újrahasználja az utolsó veremkeretet, amikor biztos, hogy az előző függvénynek már nincs rá szüksége. Ez mérsékli a függvényhívási verem túlcsordulásának kockázatát, ami olyan helyzet, amikor olyan sok keret van a függvényhívási vermen, hogy nincs több memória egy újabb létrehozására.

## Farokhívás-optimalizálás Elmben

Bizonyos feltételek mellett az Elm-fordító képes automatikusan elvégezni a farokhívás-optimalizálást, amikor JavaScriptre fordít.

Az optimalizálás rekurzív függvényeknél akkor történhet meg, amikor egy ágban az _utolsó_ művelet az, hogy a függvény önmagát hívja meg egy egyszerű függvényalkalmazásban. Nézzünk néhány példát:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

A fenti implementáció nem farokrekurzív, mert az `else` ág utolsó művelete egy szorzás, `n *`.

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

A fenti implementáció farokrekurzív, és optimalizálva lesz, mert az `else` ág utolsó művelete az, hogy a `factorialHelper` önmagát hívja. Ez nem lenne lehetséges egy `Int -> Int` típusszignatúrájú függvény esetében, és a gyakorlatban a farokhívás-optimalizálást gyakran segédfüggvények definiálásával érik el.

## Határesetek

Bizonyos esetekben a fordító nem tudja optimalizálni a rekurzív függvényeket. Nézzünk néhány példát.

Míg az `f x = f (x - 1)` farokrekurzív, addig az `f x = (x - 1) |> f` nem, mert a `|>` függvényalkalmazás az utolsó művelet, és különállónak számít az `f`-től. Hasonlóképpen az `f x = x > 0 || f (x - 1)` logikai feltétellel végződő függvények sem farokrekurzívak.

Az `f x = if f (x - 1) then 1 else 0` függvény nem farokrekurzív, mert az `if`-ben lévő kifejezés nem számít ágnak. Hasonlóképpen egy rekurzív hívás egy `case` utasításban szintén nem lenne optimalizálva.

Az `f x = let y = f (x - 1) in y` függvény nem farokrekurzív, mert egy `let` utasításban hívja meg önmagát, ami nem számít ágnak. Ugyanakkor az `f x = let g x = g (x - 1) in g x` esetében a `g` függvény farokrekurzív, és optimalizálva lesz, még akkor is, ha egy `let` utasításban van definiálva.

Az `f x = if x > 0 then f (x + 1) else 1 + f x` függvény _részben_ lesz optimalizálva: a `then` ág optimalizálható, az `else` ág viszont nem. A részleges optimalizálás néha a legjobb, amit el lehet érni, például fa jellegű struktúrák bejárásakor vagy ko-rekurzív függvények definiálásakor.
