# Részletesen

A `Result` típus lehetővé teszi, hogy egy függvény egyetlen értékkel visszaadja az alábbiak mindegyikét:
- Azt, hogy a művelet sikeres volt-e vagy sem
- Siker esetén a művelet eredményértékét
- Hiba esetén a hiba okát

Más, a `Result` típushoz hasonlót nem támogató programozási nyelvekben gyakran találkozni a következő mintákkal, amelyek a fenti célokat szolgálják:
- Egy függvény numerikus kódot ad vissza, ami a sikert vagy a hiba okát jelzi, emellett pedig egy kimeneti paramétert vár, amely siker esetén átveszi az értéket.
- Egy függvény siker esetén az értéket adja vissza, hiba esetén pedig NULL-t, majd egy másik függvény hívásával kérdezhető le a hiba okát jelző hibakód.

Egy másik gyakori hibakezelési mechanizmus a kivétel, amely hiba esetén hirtelen kilép az aktuális függvényből, és átadja a vezérlést a hívási veremben található első kezelőnek.  
Ha egyetlen kezelő sem „kapja el” a kivételt, a program megszakad.

## A `Result` típus használatának előnyei

* __Fordítási idejű biztonság__: Azzal, hogy egy függvényhívás sikerét vagy kudarcát explicit módon kifejezzük a típusrendszerben, a fordító gondoskodhat róla, hogy a hívó kód minden hibaesetet kezeljen, ezzel megelőzve a nullértékek miatt előforduló hibák nagy csoportját.

* __Futásidejű biztonság__: A `null` használata helyett a `Result` típus a `Error` értékkel jelzi a kudarcot, így lehetetlenné válik, hogy `NullReferenceException` forduljon elő.

* __Explicit hibakezelés__: Az a kód, amely egy `Result`-ot visszaadó függvényt hív, kénytelen tudomásul venni, hogy a hívás meghiúsulhat; a hívó kódnak szándékosan kell kezelnie az ilyen hibákat.  Nincsenek csendes hibák és nincsenek váratlan kivételek.

* __Kiszámítható vezérlésfolyam__: A `Result` ugyanúgy visszatérési értékként jön vissza, mint bármely más érték; nem ugrik ki a hívási veremből, mint egy kivétel.  Mindig tudod, honnan erednek a hibák, és hogyan terjednek tovább.

* __Jobb olvashatóság és karbantarthatóság__: Azzal, hogy egy függvény `Result`-ot ad vissza, a szignatúrája világosan jelzi a siker és a hiba esetén elvárt viselkedést.

## Használat

A `Result` típus egy generikus típus, amely két mögöttes típust tartalmaz:
- a sikeres művelet eredményének a típusát
- a hiba okát reprezentáló típust

A `Result` típus egyben egy [megkülönböztetett unió][discriminated-union] is, a következő lehetséges esetekkel:
* `Ok <value>`, amely egy sikeres eredményt reprezentál
* `Error <reason>`, amely egy kudarcot reprezentál

A következő függvény bemutatja, hogyan hozhatunk létre `Result` értéket:

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

Ebben a példában az `Ok` érték egy string (a megadott név), az `Error` érték pedig szintén egy string (a hiba oka, ember által olvasható formában).

## A `Result` érték tartalmának kiolvasása

Tekintsd a következő típusdefiníciót és függvényszignatúrát:

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

Az `openFile` függvényt hívó kód mintaillesztéssel kezelheti a siker és a kudarc eseteit, ahogy a következő példában is látható:

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
