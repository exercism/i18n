# Megjegyzések a zárójelekről

A Tcl egy [nagyon egyszerű nyelv](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm), de abban, ahogy az értelmező a kódot feldolgozza, van néhány kellemetlen határeset.

## Kapcsos zárójelek

A kapcsos zárójelek a Tcl-ben egyszerűen egy szövegblokk idézésére szolgálnak. Az ilyen szöveg kódként vagy adatként is értelmezhető. A kapcsos zárójelek között egymásba ágyazott zárójelek is megjelenhetnek, de ezeknek kiegyensúlyozottnak kell lenniük. A Tcl man oldala ezt írja:

> A kapcsos zárójelek egymásba ágyazódnak a szón belül: minden további nyitó kapcsos zárójelhez kell egy további csukó kapcsos zárójel (ha azonban a szón belüli nyitó vagy csukó kapcsos zárójel _backslash karakterrel van idézve_, akkor nem számít bele a hozzá tartozó csukó zárójel megkeresésébe).

A megfogalmazás ott meglehetősen pontos: ha nem párosított nyitó vagy csukó kapcsos zárójel karaktert szeretnél, akkor azt backslash karakterrel kell idézned. Tehát ne ezt csináld:
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "{"}]
    # ......................^ will not work
}
```
Ezt viszont igen:
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "\{"}]
    # ......................^^ will work
}
```

Ez problémát okozhat amiatt, hogy a Tcl másképp dolgozza fel a megjegyzéseket, mint a legtöbb nyelv. Erről bővebben a [Tcl wikin](https://wiki.tcl-lang.org/page/Why+can+I+not+place+unmatched+braces+in+Tcl+comments) olvashatsz.

## Szögletes zárójelek

Hasonlóképpen, mivel a Tcl a szögletes zárójeleket a [parancsbehelyettesítéshez.](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M11) használja, még a dupla idézőjelbe tett szövegekben is figyelned kell a nyitó szögletes zárójelek escape-elésére.
