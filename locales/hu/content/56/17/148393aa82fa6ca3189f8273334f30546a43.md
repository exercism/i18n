# Bevezetés

## Opaque típusok

### Bevezetés

Az opaque típusok egy enkapszulációs technika az Elmben.
Egyesek információelrejtésnek vagy az implementációs részletek elrejtésének is nevezik.
Gyakran használják az érvényesítés kikényszerítésére is, a [Parse, dont validate][parse-dont-validate] mintát követve.
Például lehet egy `EmailAddress` opaque típusod, amely csak érvényes e-mail-címeket tartalmazhat (ellentétben a `String`-gel, amely bármit tartalmazhat).

### Opaque típus létrehozása

A [custom type-oknak][custom-types] egy vagy több *változatuk* van, és a fordító automatikusan létrehoz egy-egy függvényt minden *változat* létrehozásához, a *változat* nevének felhasználásával.
Ez az egyetlen módja annak, hogy custom type-okat létrehozzunk.
A fordító ezen változatok destrukturálását is lehetővé teszi.

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

Alapértelmezés szerint mindez a fájlon / modulon belül marad, és az `exposing` kulcsszóval választjuk ki, mit exportálunk.
Opaque típus létrehozásához egyszerűen csak nem exportálod a *változatokat*.

Amikor ezt teszed, szinte mindig szükség van egy másik módra a *változatok* létrehozásához és eléréséhez, méghozzá saját függvények exportálásával.
Ezek a saját függvények lehetővé teszik, hogy valamilyen logikát alkalmazz a *változatok* létrehozásakor és elérésekor.
Ez elrejti a modul belső implementációs részleteit, és azt jelenti, hogy az implementációs részleteket tetszés szerint módosíthatod, amíg az exportált függvények ugyanazok maradnak.

### Parse, don't validate

Az opaque típusok talán leggyakoribb felhasználása az érvényesítés kikényszerítése a [Parse, dont validate][parse-dont-validate] mintával.
Ebben a mintában exportálsz egy függvényt, amely egy nálad kevésbé strukturált / típusbiztos bemenetet kap, például egy `String`-et, majd ezt egy strukturáltabb típussá alakítja, például `EmailAddress`-dé, és vagy visszaadja a típust, vagy hibát ad vissza (általában `Maybe`-t vagy `Result`-ot).

Például az alábbi kódban a külső modulok csak a `parseEmailAddress` függvénnyel hozhatnak létre `EmailAddress` típust, így amikor az `EmailAddress` típussal dolgozol, biztos lehetsz benne, hogy érvényes.

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
