# A fogalomról

A tanterv ezen pontjára már sok függvénydefiníciót láttál. Ezeket általában anélkül mutattuk be, hogy sokat foglalkoztunk volna a REPL-ben látható kimenettel:

```julia-repl
julia> f(x) = x^2
f (generic function with 1 method)
```

Miért is _„generic function with 1 method”_?

Tegyük fel, hogy pontosabban szeretnénk megadni az argumentumok típusait.

```julia-repl
julia> f(x::Integer) = x^2
f (generic function with 2 methods)

julia> f(x::Real) = x^2
f (generic function with 3 methods)
```

Vagy megváltoztathatjuk az argumentumok számát:

```julia-repl
julia> f(x, y) = x * y
f (generic function with 4 methods)
```

Úgy tűnik, hogy ugyanazon függvény új definícióit „metódusoknak” nevezzük.
A metódusok egy listába kerülnek, ahelyett hogy felülírnák a régi definíciót.

A metódusokat könnyedén kilistázhatjuk:

```julia-repl
julia> methods(f)  # output edited for brevity
# 4 methods for generic function "f" from Main:
 [1] f(x, y)
 [2] f(x::Integer)
 [3] f(x::Real)
 [4] f(x)
 ```

Ha meghívjuk az `f` függvényt, Julia valahogy tudja, melyik metódust kell használnia:

```julia-repl
julia> f(2.5)  # Float64
6.25

julia> f(2)  # Int64
4

julia> f(2, 3)  # Int64, Int64
6
```

## Mi az a függvény?

A [kézikönyv][function] szerint a függvény egy objektum, amely argumentumok egy tuple-jét egy visszatérési értékre képezi le.
Ez közel áll ahhoz a definícióhoz, amelyet a matematikusok használnak.

Az `f(2, 3)` függvényargumentumaira általában két különálló dologként gondolunk, a fordító viszont egyetlen [tuple][tuple] formájában látja őket.
Ez még egyetlen argumentum esetén is igaz (bár hogy ez világosabb legyen, vesszőt kell hozzátennünk):

```julia-repl
julia> typeof( (2, 3) )
Tuple{Int64, Int64}

julia> typeof( (2,) )
Tuple{Int64}
```

Ha a függvényt fekete dobozként tekintjük, azt mondhatjuk, hogy egy tuple megy be, és egy visszatérési érték jön ki.
Formálisabban: a tuple-t egy visszatérési értékre _képezzük_ le.

## Hogyan kezelik a függvények az argumentumok eltérő számát és típusát?

Ezt általában [polimorfizmusnak][polymorphism] nevezik.

Ez már évtizedek óta nagy téma a számítástudományban, és többféle megközelítést dolgoztak ki.

A Julia megközelítése szokatlan, bár nem egyedülálló.

- A függvények [generikusak][generic], ami azt jelenti, hogy több metódus is kapcsolódhat hozzájuk.
- A függvények csupán nevek, amíg metódusok nem kapcsolódnak hozzájuk.
- A metódusok igény szerint adhatók hozzá, akár nagy számban is (a `+` operátor jelenleg 161 metódussal rendelkező függvény).
- Amikor egy függvényt meghívunk, a Julia megvizsgálja a hívási szignatúrát: az argumentumok számát és mindegyik aktuális típusát.
- A hívási szignatúrához legjobban illeszkedő metódus kerül kiválasztásra.
  - Általában az argumentumok számának pontosan egyeznie kell (bár a [splat/slurp][splat] operátor `...` részben megkerülheti ezt).
  - Azokat a metódusokat részesítjük előnyben, amelyek típusai pontosan megegyeznek a hívási szignatúrával.
  - Ha szükséges, a Julia megvizsgálja a hívási szignatúrában szereplő egyes argumentumok fölérendelt típusait, hogy megtalálja a legjobban illeszkedő, legspecifikusabb metódust.
- A kiválasztott metódus a megadott argumentumokkal [`dispatched`][dispatch] hívásra kerül, és visszaad egy eredményt.
- Ha nem található megfelelő metódus, [`MethodError`][methoderror] hibát kapunk.

Vegyük észre, hogy a Julia dinamikusan típusos, ezért a metódus-diszpécselés _futásidőben_ történik.

## Többszörös diszpécselés: egy példa

Az előző szakaszban sok szó volt, úgyhogy fordítsuk le ezeket az ötleteket kódra.
Az egyszerűség kedvéért az alábbi függvényeknek csak egyetlen argumentumuk van, de az sem ritka, hogy egy függvénynek több tucat argumentuma van (például ábrázoló csomagokban vagy a gépi tanulásban).

Kezdjük néhány saját típus definiálásával, amelyek geometriai alakzatokat képviselnek.

```julia-repl
julia> abstract type Shape end

julia> struct Circle <: Shape
           radius::Float64
       end

julia> struct Square <: Shape
           side::Float64
       end

julia> struct Rectangle <: Shape
           length::Float64
           width::Float64
       end
```

Ezután definiálhatunk metódusokat az egyes alakzatok területének kiszámítására.
Mindegyik egy argumentumot vár, mégpedig minden esetben más-más konkrét, felhasználó által definiált típussal.

```julia-repl
julia> area(c::Circle) = π * c.radius^2
area (generic function with 1 method)

julia> area(s::Square) = s.side^2
area (generic function with 2 methods)

julia> area(r::Rectangle) = r.length * r.width
area (generic function with 3 methods)
```

Most létrehozhatunk néhány alakzatot, és kiszámíthatjuk a területüket, bízva abban, hogy a Julia diszpécselési mechanizmusa mindegyikhez a helyes képletet választja.

```julia-repl
julia> circle = Circle(2.3)
Circle(2.3)

julia> area(circle)  # call signature Tuple{Circle}
16.619025137490002

julia> square = Square(1.6)
Square(1.6)

julia> area(square)  # call signature Tuple{Square}
2.5600000000000005

julia> rectangle = Rectangle(1.4, 2.1)
Rectangle(1.4, 2.1)

julia> area(rectangle)  # call signature Tuple{Rectangle}
2.94
```

## [Parametrikus metódusok][parametric]

A metódus-szignatúrák dummy típusértékeket vehetnek fel, nagyjából ugyanúgy, ahogy a parametrikus típusok.

A szintaxis jellegzetes, `where` feltételt igényel:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T} = true
same_type (generic function with 1 method)

julia> same_type([1, 2], 3)
true

julia> same_type([1, 2], "three")
ERROR: MethodError: no method matching same_type(::Vector{Int64}, ::String)
```

A fenti példában mindkét argumentumnak ugyanazt a `T` típust kell használnia, bármi is legyen az.

Pontosabbak lehetünk, ha megkötést teszünk a `T`-re:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T<:Number} = true
same_type (generic function with 2 methods)
```

Ezzel a metódussal csak az azonos numerikus típusok adnak vissza `true`-t.

Több dummy változó is lehetséges, amelyeket a `where` feltételben vesszővel választunk el.
A következő két metódus hasonlónak tűnik:

```julia-repl
julia> func(v::Vector{Number}, x::Number) = true
func (generic function with 1 method)

julia> func(v::Vector{S}, x::T) where {S<:Number, T<:Number} = true
func (generic function with 2 methods)
```

Egy különbség, hogy az `S` és `T` típusértékek a második metódus függvénytörzsén belül is használhatók.
Ez olyan trükk, amelyet talán nem használsz gyakran, bizonyos helyzetekben viszont sok bajtól megkímélhet.

Például a következő parametrikus típusdefinícióban a mezőknek ugyanolyan `T` típusúnak kell lenniük, amelyre az a megkötés, hogy a `Real` altípusa legyen:
```julia
struct Point{T<:Real}
    x::T
    y::T
end
```
Ez a `Point` definíció elfogad egy azonos típusú `x`-et és `y`-t, vagy elfogadhat különböző típusú `x`-et és `y`-t is, de ilyenkor meg kell adni egy explicit konverziós típust.
```julia-repl
julia> Point(4, 5)
 Point{Int64}(4, 5)

julia> Point(3.5, 2)
 MethodError: no method matching Point(::Float64, ::Int64)    # Output truncated for brevity

julia> Point{Float32}(3.5, 2)
 Point{Float32}(3.5f0, 2.0f0)

julia> Point{Int64}(3.5, 2) 
 InexactError: Int64(3.5)      # Output truncated for brevity
```
Bár a típusok fölötti ilyen szintű kontroll kívánatos lehet, némi absztrakció is hasznos lehet.
```julia
Point(x::T, y::S) where {T<:Real, S<:Real} = Point{promote_type(T,  S)}(x, y)
```
Ez a külső konstruktor ezt azzal valósítja meg, hogy a `Point` elfogadhat inhomogén típusokat az `x` és az `y` számára anélkül, hogy explicit módon meg kellene adni a konverziós típust.
A `T` és `S` típusértékek a függvénytörzsben, a `promote_type(T, S)` hívásban szolgáltatják az explicit konverziós típust az eredeti definícióhoz.
```julia-repl
julia> Point(3.5, 2)
 Point{Float64}(3.5, 2.0)
```

## Összehasonlítás más nyelvekkel

Mivel a Julia a metódus kiválasztásakor az összes argumentumot megvizsgálja, ezt [`multiple dispatch`][multiple-dispatch] néven ismerjük.

Néhány más nyelv is támogatja a többszörös diszpécselést, például a Common Lisp, bár ez ritkán olyan központi eleme a nyelv felépítésének, mint a Juliában.

Ezzel szemben egy objektumorientált (OO) nyelvben (például Rubyban) a metódusokat általában egy [példányon][instance] hívjuk meg.
A definíció most az első argumentumot részesíti előnyben (amely a definícióban olyan nevet kap, mint a `self` vagy a `this`), a metódusnevet pedig ponttal fűzzük a példányhoz, hogy meghívjuk vele:

```ruby
irb(main):004:0> "abc".sub("b", "*")
=> "a*c"
```

Ezt [`single dispatch`][single-dispatch] néven ismerjük, mivel csak a példány osztálya (a fenti példában a „abc” stringé) alapján választjuk ki a metódust.

Néhány statikusan típusos OO nyelv támogatja a metódusok polimorfizmusát, ami némileg hasonlít a többszörös diszpécseléshez.
A nagy különbség, hogy a metódus kiválasztása csak _fordítási időben_ történik.

A funkcionális nyelvekben általában csak egyetlen függvénydefiníció van, és valamilyen Select/Case/Match kifejezés kezeli a különböző lehetőségeket.
A saját logikádat írod meg, amelyet általában egy tömör mintaillesztési szintaxis segít, ami a Juliából hiányzik.
Persze a Julia is alkalmaz egyfajta mintaillesztést, de az a diszpécselésnél történik, nem a függvénytörzsön belül.

## Összegzés

A többszörös diszpécselés nagyon rugalmas és rendkívül gyors a Juliában, ezért széles körben használják.

Ahogy a `+` 161 metódusára vonatkozó példa is mutatja, a Julia programozói igyekeznek szűken meghatározott típusú metódusokat definiálni.
Két egész szám összeadása bájtkód szinten nagyon más, mint két tizedes tört összeadása, ráadásul ha egy egész számhoz tizedes törtet adunk, az a típuspromóció további bonyodalmát hozza magával.

Minél specifikusabb a típus, annál több optimalizálást végezhet a fordító: az Exercismen egy apró feladatnál alig számít, de létfontosságú a teljesítmény szempontjából azokban a nagy numerikus szimulációkban, amelyekre a Juliát tervezték.

_Ha tudod, milyen bemeneteket fog kapni egy metódus, mondd meg a fordítónak!_
