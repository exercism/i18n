# Bevezetés

## Null-referenciák

Ha valaha használtál már más programozási nyelvet (C/C++, Python, Java, Ruby, Lisp stb.), valószínűleg találkoztál már a `null` vagy a `nil` fogalmával.
A `null` vagy a `nil` használatával jelzik ezek a nyelvek, hogy egy adott változónak nincs értéke.
Ez azonban könnyűvé (és gyakorivá) teszi azt a hibát, hogy véletlenül `null` értékű változót használunk.
Ahogy sejtheted, abból, hogy olyan függvényt próbálunk meghívni, ami nincs, vagy olyan értéket próbálunk elérni, ami nem létezik, mindenféle hiba és összeomlás származhat.
A `null` megalkotója odáig ment, hogy a saját „egymilliárd dolláros tévedésének” nevezte.

[billion-dollar-mistake]: https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/

## Az `Option` típus

Hogy elkerüljük ezeket a problémákat, a Cairo változói az `Option` enum használatával biztonságosan ábrázolhatják az érték hiányát.
Ennek az enumnak két változata van: a `None`, ami a Cairo megfelelője a nullnak, és a `Some(T)`, ahol a `T` bármilyen típusú érték lehet.

Így néz ki:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

Gondolhatsz úgy az `Option`-ra, mint egy biztonsági rétegre közted és a null-referenciák okozta problémák között, amely megőrzi azok fogalmi hasznosságát.

## Az `Option` használata

Egy változó `None`-ra állítása meglehetősen egyszerű:

```rust
let nothing: Option<u32> = Option::None;  // Variable nothing is set to None
```

Ha viszont azt szeretnéd, hogy az `Option` típus értéket hordozzon, ezt az értéket nem rendelheted hozzá közvetlenül.
Egy `Option` típusú változó és mondjuk egy `i32` típusú változó nem egyenértékű.
A `Some`-ot kell használnod:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Option::Some(-4); // This will work
let another_right_way = Option::Some(-4); // Compiler infers that this is Option<i32>
```

Ugyanezen okból a következő sem működik:

```rust
let number = 47;
let option_number = Option::Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

Ahhoz, hogy hozzájuss a `Some` által tartalmazott értékhez, először ellenőrizned kell, hogy létezik-e:

```rust
let mut some_words = Option::Some("choose something to say"); // some_words set to something

match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "Here, we will choose something to say"

some_words = Option::None; // some_words now set to None

// Exactly the same match block as above
match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "I've got nothing to say"
```

A Cairoban a `match`-en kívül más eszközök is rendelkezésre állnak az `Option`-ban tárolt értékek ellenőrzésére és elérésére, de a `match` számodra mostanra ismerős lehet.

Tekintsd ezt annak bemutatásának, hogy miért használ a Cairo `Option`-t a null-referencia helyett.
A lényeg az, hogy **mindenképpen ellenőrizned _kell_**, hogy az `Option` típusú változó `Some`-e (ilyenkor nyugodtan kinyerheted és felhasználhatod a benne tárolt értéket), vagy `None`.
Ellenkező esetben a programod nem fog lefordulni; a fordító megvéd a `null`-tól.
