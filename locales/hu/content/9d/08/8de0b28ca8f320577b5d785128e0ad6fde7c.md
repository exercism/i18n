# Bevezetés

A korábbi fogalmakban láttuk, hogy a Julia típusai hierarchiát alkotnak, amelynek csúcsán az `Any` áll.

Az olyan absztrakt típusoknak, mint a `Number`, vannak altípusaik, de maguk nem példányosíthatók.
Ha egy változó típusát absztrakt típusra állítod, az _korlátozza_ a változó értékeit arra, hogy az absztrakt típus valamelyik altípusába tartozzanak.
Például:

```julia-repl
julia> x::Number = 3
3
julia> typeof(x)  # one subtype of Number
Int64
julia> x = 4.2
4.2
julia> typeof(x) # another subtype of Number
Float64
julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

Ez egyfajta rugalmasságot ad abban, hogy mely bemenetek lehetnek érvényesek.

De mi van akkor, ha azt szeretnénk, hogy egy változó egyszerre fogadjon el egész szám és string értékeket is?
Ez a két típus nem a hierarchia ugyanazon ágán van.

A típust beállíthatnánk `Any` típusra, vagy rábízhatnánk, hogy ez legyen az alapértelmezett, de akkor teljesen elveszítjük az irányítást a megengedett típusok felett.

Egy jobb megoldás a `Union{ }` szintaxis, amelyben kettő vagy több típust sorolunk fel a kapcsos zárójelek között.

```julia-repl
julia> y::Union{Integer, String} = 4
4
julia> typeof(y)
Int64
julia> y = "works"
"works"
julia> typeof(y)
String
julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

Egy másik példa ugyanezt a típusuniót használja egy függvényszignatúrában:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}
julia> f(z::IntOrString) = z^3
f (generic function with 1 method)
julia> f(2) # integers are cubed
8
julia> f("ab") # strings are repeated 3 times
"ababab"
```

Itt nevet adtunk a típusnak, ami kényelmes rövidítést nyújthat, de nem feltétlenül szükséges.
A `g(z::Union{Integer, String}) = z^3` függvény ugyanígy viselkedik.

A függvényszignatúrákról sokkal többet mondunk majd a Multiple Dispatch fogalomban.

## Uniók a semmivel

Több más nyelvben is léteznek olyan típusok, amelyek tartalmazhatnak értéket, de nem is, ilyen például az `Option`, a `Nullable` vagy a `Maybe`.

A Juliának nincs külön szintaxisa erre, de a típusuniók ugyanennek az ötletnek az általánosításai.

A `Nothingness` fogalomban láttuk, hogy a Juliában többféleképpen is ábrázolhatók a nem-értékek, például a `nothing` és a `missing`.
Bármelyikük szerepelhet egy típusunióban.

Ha például valamilyen láncolt listát definiálunk, szükségünk van egy módra, amivel lezárhatjuk a listát, ha nincs több csomópont.
A `Nothing` az a típus, amelynek egyetlen értéke a `nothing`, és ez a Node-definíció lehetővé teszi a lánc végének jelzését:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

Hasonlóképp a `missing` is használható helyőrzőként a hiányzó értékek jelölésére, különösen a vektorokhoz hasonló gyűjteményekben.
Az alábbi példa nagyon erőltetett, de a hiányzó értékek gyakoriak a valós adathalmazokban.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)
julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
