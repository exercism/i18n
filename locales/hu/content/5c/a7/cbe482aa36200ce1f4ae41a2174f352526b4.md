# Nil

A Crystalben van egy `Nil` nevű típus, amelynek csak egyetlen értéke lehet: `nil`.
Arra szolgál, hogy egy érték hiányát fejezze ki, és hasonló a `null`-hoz vagy a `None`-hoz más nyelvekben.

A `nil` értéket több metódus is visszaadhatja, például a [`String#[]?`][string-index], amely `nil`-t ad vissza, ha az index kívül esik a megengedett tartományon.

```crystal
"foo"[10]? # => nil
```

A Crystalben léteznek az úgynevezett **NULLREFERENCIA-ELLENŐRZÉSEK**, ami azt jelenti, hogy alapértelmezésben egyetlen típus sem vehet fel `nil` értéket.
Ez azt jelenti, hogy nem rendelhetsz `nil`-t egy változóhoz, hacsak nem deklarálod kifejezetten `Nil` típusként.
Ez pedig azt jelenti, hogy a fordító automatikusan ellenőrzi a nullreferenciákat.

## Hamis érték

Többféleképpen is kezelheted a `nil` értékeket.
A `nil` [hamis][truthy-falsey] érték, és a `false` is az.
Ez azt jelenti, hogy az elágazásokban és más helyeken, ahol hamis vagy igaz értéket várunk, ugyanúgy kezelik, mint a `false`-t.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Ez azt jelenti, hogy ha egy nilable változó értéke `nil`, akkor az igaz ág nem fut le.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## A nil ellenőrzése

A Crystalben van egy metódus, amellyel ellenőrizheted, hogy egy érték `nil`-e.
Ez a [`nil?`][nil?], és minden objektumon elérhető.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Ez kicsit más, mint amikor az értéket közvetlenül egy elágazásban használod, mert az előző példákban a `false` és a `nil` is hamisnak számított.
Itt viszont csak a `nil` hamis, hiszen ha `false` lenne, akkor nem `nil` lenne, így igaz értéknek számítana.

## A vagy operátor

A `nil` értékek kezelésének legegyszerűbb módja, ha eleve megakadályozod, hogy `nil`-lé váljanak.
A vagy operátort ([`||`][or]) gyakran `Bools` értékekkel való munkához használják, de ha jól megérted, `nil` értékek kezelésére is alkalmas.
A vagy operátor megnézi, hogy az első érték igaz-e; ha nem, akkor a második értéket használja.
Így ha az érték `nil`, az hamisnak számít, és ezért a második érték lesz az eredmény.

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
Ezt a megoldást csak végső esetben alkalmazd, és csak akkor, ha **biztos** vagy benne, hogy az érték nem `nil`.
Ha lehet, inkább a többi megoldást válaszd.
~~~~

A [`not_nil!`][not_nil] egy olyan metódus, amellyel tudathatod a fordítóval, hogy egy érték nem `nil`, és ettől kezdve a típusa már nem lehet `nil`.
Ezt úgy éri el, hogy kivételt dob, ha az érték `nil`.

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
