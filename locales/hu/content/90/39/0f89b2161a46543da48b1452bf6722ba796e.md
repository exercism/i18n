# Unison alapjai

## „Term” és függvények

A „term” és a függvények a Unison-program írásának alapvető egységei.

A „term” a mi szóhasználatunkban statikus értéket jelent. A `name = expression` formával definiáljuk, amelyet opcionálisan megelőzhet egy `name : MyType` alakú típusaláírás. A Unison támogatja a típuskövetkeztetést, ezért egyszerű definíciók esetén előfordulhat, hogy elhagyják a típusaláírást.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

A Unison-függvények így néznek ki: `myFunctionName argument1 argument2 = myImplementation`; a függvény nevével kezdődnek, amelyet szóközzel elválasztott argumentumok követnek.

```
getMax a b = Nat.max a b
```

A függvényekhez opcionálisan tartozhat típusaláírás. A jobb oldalon álló utolsó típus mindig a függvény végső visszatérési típusa, az egyes argumentumokat pedig a `->` függvénynyíl választja el.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Egy függvény meghívásához írd le a nevét, majd az argumentumait, amelyeket csak szóköz választ el.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Amikor meghívsz egy függvényt, a Unison megpróbálja a közvetlenül jobbra álló dolgot argumentumként kezelni, ami nem feltétlenül eredményezi a kívánt kiértékelési sorrendet.

Tegyük fel, hogy az `1` értéket szeretnénk megkapni a következő kifejezésből

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

Ahogy le van írva, a `shouldBe1` értéke `0` lesz, mert az implicit függvényalkalmazási sorrend a `getMax 1 10`, ami `10`, majd a `10 - 10`, ami `0`.

Zárójelekkel átcsoportosíthatod a kifejezést a kívánt műveleti sorrendbe.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Watch kifejezések

A Unison biztosít egy módszert a kód gyors kiértékelésére, ezt hívják „watch expression”-nek. A „watch expression” egy `>` szimbólummal kezdődik, amelyet a kiértékelendő kifejezés követ. A „watch expression”-ök bármely `.u` kiterjesztésű fájlban leírhatók. A fájl mentése után látni fogod, hogy mire értékelődik ki a kifejezés a Unison Codebase Manager (UCM) konzoljában. Ahol ebben a dokumentációban lehetséges, igyekszünk megmutatni a kifejezést a „watch expression”-ben való kiértékelés után kapott várható kimenettel együtt.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Többsoros függvények

A Unison többsoros függvényei behúzással vagy `let` blokkokkal jelölik a kódhatárokat, más néven „lexical scope”-ot.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Minden, ami ugyanazon a behúzási szinten van, ugyanahhoz a scope-hoz tartozik, ezért hivatkozhatunk a `newBeginning` változóra az utolsó sorban.

## Névterek és `use` utasítások

A névterek segítségével csoportosítjuk és rendezzük a Unison-függvényeket. Gondolhatsz rájuk úgy, mint a „könyvtárak” megfelelőire. Struktúrát és logikai csoportosítást biztosítanak.

Egy `use` utasítással behozhatod egy névtér függvényeit a scope-ba.

Tegyük fel, hogy olyan függvényt írsz, amely Unison `List` értékeket használ. Tudod, hogy szükséged lesz olyan függvényekre, mint a `List.map` és a `List.flatMap`, ahol a `List` a névtér, a `map` és a `flatMap` pedig függvények. Hogy ne ismételd magad, dönthetsz úgy, hogy a `List` névtér minden elemét behozod a függvényed scope-jába, így:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

A `use List` sor egyértelművé teszi a `map` és a `flatMap` hivatkozásait. A [`use` utasításokról itt olvashatsz bővebben][use-statements].

## A Unison szabványos könyvtára

A Unison szabványos könyvtárát `base`-nek hívják. Ha követted a gyorsindító útmutatót, és létrehoztál egy kódbázist helyben, a szabványos könyvtárnak automatikusan le kellett töltődnie. A szabványos könyvtár dokumentációját online böngészheted a [Unison Share][unison-share-base] oldalon.

## Megjegyzések és dokumentációs literálok

A megjegyzések a Unisonban kicsit szokatlan dolog. Amikor Unison-kódot írsz, a következő szintaxissal olyan szöveget hozhatsz létre a `.u` kiterjesztésű fájlodban, amelyet a rendszer nem értelmez:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Azonban_, mivel a Unison a kódját az absztrakt szintaxisfája hash-eként menti, nem pedig szöveges fájlként a fájlrendszeren, azok a megjegyzések, amelyek egy adott Unison-függvény vagy „term” szöveges „díszítései” a fájlban, valójában nem menthetők és jeleníthetők meg újra a megosztáshoz. Ha úgy szeretnél információt hozzáadni a Unison „term”-edhez, hogy az mások számára is tárolva legyen olvasásra és megértésre, használhatsz dokumentációs literált.

A dokumentáció első osztályú érték a Unison programozási nyelvben. Ez azt jelenti, hogy egy `Doc` elem hozzárendelhető értékhez, átadható értékként egy függvénynek, vagy visszaadható egy függvény értékeként. A dokumentációs literál elemeket dupla kapcsos zárójel nyitja és zárja. Így használhatjuk a `Doc` elemet megjegyzésként.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
