# Részletesen

A Factor két rétegre bontja a stream I/O-t. Az alsó réteg az *explicit-stream* API: minden szó argumentumként kapja meg a streamet. A felső réteg az *ambient-stream* API: rövid, egysoros szavak, amelyek arra a streamre hatnak, amelyik éppen be van kötve. Mindkét réteg ugyanarra a [protokollra][stream-protocol] épül; a felső réteg szavai csupán kikeresik az ambiens streamet, és továbbadják a hívást.

## Az explicit-stream szavai

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

A `stream-contents` az egészet kiolvassa; a `stream-lines` szintén kiolvassa, de sorhatároknál fel is bontja; a `stream-readln` egyszerre egy sort ad vissza (vagy `f`-et a stream végén).

## Az ambiens stream szavai

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

Ezek a mindennapi I/O szavak. A dinamikus `input-stream` / `output-stream` változókból kikeresik az aktuális bemeneti vagy kimeneti streamet, és továbbadják a hívást. Ezért van az, hogy a `print` átirányítása egy stringbe csupán annyi, hogy egy quotation időtartamára bekötjük az `output-stream`-et.

## Beépített stream-konstruktorok

| szó               | vocab                | mit hoz létre                   |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | egy literál stringet olvas      |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | az írásokat egy stringbe gyűjti |
| `<file-reader>`   | [`io.files`][io.files]           | egy fájlt olvas adott kódolással |
| `<file-writer>`   | [`io.files`][io.files]           | egy fájlt ír adott kódolással   |

Mind a négy disposable objektumot hoz létre: a `destructors` `disposable` szavát terjesztik ki, így az alábbi `with-…` kombinatorok kilépéskor felszabadítják őket.

## Hatókörre szóló bekötés

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

Mindegyik megnyit egy streamet, beköti a belső quotation ambiens bemeneteként vagy kimeneteként, majd kilépéskor felszabadítja, akkor is, ha a quotation hibát dob. Ezek a `boatswains-bilge` destruktor-kombinatorai, streamre specializálva.

A `with-string-writer` különösen letisztult változat: magától létrehoz egy friss `<string-writer>`-t, a quotationt azzal a writerrel futtatja ambiens kimenetként, és visszaadja az összegyűlt stringet. A „quotation kimenetének elkapása” minta az egész egyetlen szó.

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## Miért egyáltalán ambiens?

A dinamikus változóhoz kötés miatt működik a `print` olyan programban is, amely nem tudja, hogy interaktívan fut-e, naplófájlba ír-e, vagy egy rögzített teszpufferbe. Elég egyszer kicserélni a bekötést, és minden szó, amely a `print`-et hívja, a helyes dolgot teszi, átkötés nélkül. Ez az az inverzió, amit a felső réteg ad neked.

Ha saját streamet szeretnél *implementálni*, vagyis olyan saját osztályt definiálni, amely csatlakozik a protokollhoz, lásd a `streams` fogalmat (amelyet a `telegraphers-tape` tanít).
