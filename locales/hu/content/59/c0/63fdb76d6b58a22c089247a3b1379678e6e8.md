# Részletesen

A Factor szálai *kooperatív korutinok*, amelyek egyetlen operációs rendszerbeli száron futnak. Egy szál addig fut, amíg kifejezetten át nem adja a vezérlést, vagy blokkoló I/O-t nem végez; ekkor az ütemező kiválaszt egy másik futtatható szálat. Ebből két dolog következik:

- A két vezérlésátadás között végrehajtott műveletek gyakorlatilag atomiak.
- Az igazi többmagos párhuzamossághoz ki kell lépni a szabványos `threads` szókincsből (például `concurrency.distributed` többfolyamatos megoldásokhoz).

A szabványos párhuzamossági primitívek rétegekbe rendeződnek:

| Szókincs                    | Mit nyújt                              |
|-----------------------------|----------------------------------------|
| [`threads`][threads]                   | `spawn`, `yield`, a szál azonosítója   |
| [`concurrency.promises`][concurrency.promises]      | `<promise>`, `fulfill`, `?promise`     |
| [`concurrency.locks`][concurrency.locks]         | `<lock>`, `with-lock`                  |
| [`concurrency.combinators`][concurrency.combinators]   | `parallel-map`, `parallel-each`        |
| [`concurrency.semaphores`][concurrency.semaphores]    | `<semaphore>`, `acquire`, `release`    |
| [`concurrency.mailboxes`][concurrency.mailboxes]     | szálankénti postaládák, `send`, `receive`  |
| [`concurrency.channels`][concurrency.channels]      | találkozási pont kezelői, `to`, `from`     |

```factor
USING: concurrency.combinators concurrency.locks
concurrency.promises kernel sequences threads ;

! parallel-map: fork-join, in order
{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }

! spawn + promise: hand-rolled fork-join
<promise> [
    [ "hello, world" swap fulfill ] curry "greeter" spawn drop
] keep ?promise .   ! => "hello, world"

! <lock> + with-lock: protect a shared mutable slot
<lock> :> guard
guard [ "do thing under lock" drop ] with-lock
```

A `parallel-map` a magas szintű API, és az idiomás Factor ehhez nyúl először. A `spawn` / `<promise>` / `?promise` hármas az, amiből a `parallel-map` felépül; ez akkor jön jól, ha az iteráció formája nem illik a map-hez (például olyan munkaszálakat indítunk, amelyek más csatornákon keresztül válaszolnak).

A zárak a *megosztott módosítható állapotot* védik, többnyire egy tuple egy mezőjét vagy egy hash táblát, amelyet egynél több szál olvas vagy ír. Ha bármilyen nem atomi, összetett módosítás van, akkor az olvasást is és az írást is úgy kezeld, hogy zár kell hozzá; ha bármelyik oldalon elmarad a zár, az a klasszikus recept a szétszakadt olvasáshoz.
