# Névjegy

A korábbi fogalmakban láttuk, hogy a Julia típusai hierarchiát alkotnak, amelynek a csúcsán az `Any` áll.

Az olyan absztrakt típusoknak, mint a `Number`, vannak altípusaik, de magukat nem lehet példányosítani. Ha egy változó típusát absztrakt típusra állítod, az _arra korlátozza_ a változó értékét, hogy az absztrakt típus valamelyik altípusa legyen. Például:

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

Ez egyfajta rugalmasságot ad abban, hogy mely bemenetek érvényesek.

Tegyük fel azonban, hogy egy változó egyszerre fogadjon el egész számokat és stringeket is. Ez a két típus nem ugyanazon az ágon van a hierarchiában.

Beállíthatnánk a típust [`Any`][any]-ra, vagy hagyhatnánk, hogy ez legyen az alapértelmezett, de akkor teljesen elveszítenénk az irányítást a megengedett típusok felett.

A jobb megoldás a [`Union{ }`][union] szintaxis, amelyben kettő vagy több típust sorolunk fel a kapcsos zárójelek között.

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

Egy másik példa ugyanezt a típusuniót használja egy függvényszignatúrában:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

Itt nevet adtunk a típusnak, ami kényelmes rövidítést kínál, de nem feltétlenül szükséges. A `g(z::Union{Integer, String}) = z^3` függvény ugyanígy viselkedik.

A függvényszignatúrákról sokkal többet mondunk majd a többszörös diszpécselés fogalmában.

## Uniók a semmivel

Több más nyelvben vannak olyan típusok, amelyek vagy tartalmaznak értéket, vagy nem, és olyan nevük van, mint az `Option`, a `Nullable` vagy a `Maybe`.

A Juliában nincs erre külön szintaxis, a típusuniók viszont ugyanennek az ötletnek az általánosításai.

A [`Nothingness`][nothingness] fogalomban láttuk, hogy a Juliában többféleképpen ábrázolhatók a nem-értékek, köztük a [`nothing`][nothing] és a [`missing`][missing]. Bármelyikük bekerülhet egy típusunióba.

Ha például egyfajta [láncolt listát][linked] definiálunk, kell valami, amivel lezárjuk a listát, ha nincs több csomópont. A `Nothing` az a típus, amelynek egyetlen értéke a `nothing`, és ez a `Node`-definíció lehetővé teszi a lánc végének jelzését:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

Hasonlóképpen a `missing` is használható a hiányzó értékek helyőrzőjeként, különösen olyan kollekciókban, mint a vektorok. Az alábbi példa nagyon mesterkélt, de a hiányzó értékek gyakoriak a valós adathalmazokban.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
