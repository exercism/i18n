# Bevezetés

## Stringek

### Karakterek

A **karakterkódolás** egy konkrét megállapodás arra, hogy egy természetes nyelv szövegelemét byte-ok sorozataként ábrázoljuk.
A „szövegelem” itt bármilyen egység lehet, amelynek jelentése van egy természetes nyelvben, például betűk, szóközök, írásjelek, emojik, ideogrammák stb.

A NASM (The Netwide Assembler, az ezen a kurzuson használt assembler) támogatja az adatok **ASCII** szerinti definiálását.

A NASM karakterkonstansai legfeljebb 8 byte hosszúak lehetnek, és definiálhatók aposztróffal (`'`), idézőjellel (`"`) vagy backtickkel (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

A speciális karaktereket backtickek között kell definiálni, és `\` karakterrel escape-elni:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Ne feledd, hogy az x86-64-ben nincs beépített támogatás egyetlen karakterkódolásra sem külön típusként.
Az assemblyben az adat byte-ok sorozata, és hogy ezeket a byte-okat karakterként, számként vagy bármi másként értelmezzük, az a programozóra van bízva.

Például az ASCII '0' karakter egyetlen byte, értéke 48.
Tehát ha egy byte-ba 48-at tárolunk, az pontosan ugyanaz, mintha az ASCII '0' karaktert tárolnánk:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Ugyanezért a karakterek manipulálása úgy történik, hogy közvetlenül átalakítjuk a byte-okban lévő értékeket:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

### Stringek

A **string** karakterek sorozata.
Assemblyben általában tömbként valósítják meg.

Lehetőség van string deklarálására a NASM-ben ugyanúgy, ahogy bármely tömböt deklarálnál:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

A stringek és más tömbök között az egyik különbség, hogy a NASM támogatja a stringek deklarációját vessző (`,`) nélkül is, amely elválasztaná az értékeket.
Az is lehetséges, hogy az értékeket vesszőkkel váltogatva adjuk meg:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Ne feledd, ahogy már említettük, a karakterek valójában csak byte-ok (vagy byte-ok sorozata Unicode-kódolásban):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Mivel minden ASCII-karakter egyetlen byte-ot foglal el, egy nagyobb méretben minden további byte `0`.
Például ha az `'a'` karaktert qwordként (8 byte) deklarálod, az első byte `'a'` (`97`), a többi hét byte pedig `0`.

Ezért ezek mind egyenértékűek:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
Assemblyben a stringeket nem zárja le automatikusan egy ASCII NUL karakter (értéke `0`).

Amikor magasabb szintű nyelvekkel, például C-vel kommunikálsz, a programozó felelőssége, hogy a megfelelő lezárót, ha van ilyen, a string végéhez fűzze.
~~~~

### String utasítások

Mivel a stringek tömbök, ugyanúgy dolgozhatsz velük, mint bármely tömbbel, a memória explicit dereferálásával:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Ezen kívül vannak utasítások, amelyek értékek betöltésére, mozgatására és tárolására szolgálnak a memóriában lévő byte-sorozatokban.
Bár _string utasításoknak_ nevezik őket, a memóriában lévő bármely byte-sorozattal, azaz bármely tömbbel használhatók.

A három legfontosabb string utasítás a `lods`, a `stos` és a `movs`:

| instruction | what it does                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | loads a value from a memory location indicated by `rsi` into `rax`                                                |
| `stos`      | stores a value from `rax` into a memory location indicated by `rdi`                                               |
| `movs`      | copies a value from a memory location indicated by `rsi` and stores it in a memory location indicated by `rdi`    |

Ne feledd, hogy ezek az utasítások _nem_ vesznek fel explicit operandust.
Az operandusaik implicit módon adottak.

Ökölszabályként:

1. Ha a forrásoperandusuk egy memóriacím, akkor annak címét a `rsi`-ben kell tárolni (`s` a forrás rövidítése).
2. Ha a céloperandusuk egy memóriacím, akkor annak címét helyette a `rdi`-ben kell tárolni (`d` a cél rövidítése).
3. Ha valamelyik operandus nem memóriacím, akkor az a `rax` regiszter.

Ne feledd, hogy ezek az utasítások automatikusan dereferálják a memóriacímeket az általuk végzett konkrét műveletnek megfelelően.

Mindegyikük különböző méretekben működhet.
A méret jelzésére utótagot fűzünk a nevekhez:

| suffix | meaning | size    |
| :----: | ------- | :------ |
|  `b`   | byte    | 1 byte  |
|  `w`   | word    | 2 byte |
|  `d`   | dword   | 4 byte |
|  `q`   | qword   | 8 byte |

Például:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

A használt címeket is frissítik a művelet méretével.
Ez a frissítés a **irányjelző flag (DF)** értékétől függ:

- Ha a `DF` törölve van, a címek a művelet méretével _nőnek_.
- Ha a `DF` be van állítva, a címek helyette ugyanennyivel _csökkennek_.

A System V ABI előírja, hogy a függvény belépésekor az irányjelző flaget törölni kell.
Így _az alapértelmezett viselkedés az, hogy a memóriát növekvő címsorrendben olvassuk/írjuk_.

A `cld` utasítással törölhető az irányjelző flag, a `std` utasítással pedig beállítható:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
A hívó fél elvárja, hogy a `DF` törölve legyen, miután bármely meghívott függvény visszatér, a System V ABI szerint.
Ha valaha beállítod a `DF`-et, ügyelj rá, hogy `ret` előtt töröld.
~~~~

#### Rep

Ezeken kívül a **rep** utasítás nem érintkezik közvetlenül a memóriával.
Ehelyett előtagként hozzáadható a többi említett utasításhoz, _megismételve_ azokat.

Amikor `rep` előtaggal látjuk el őket, a string utasítások annyiszor ismétlődnek, ahányszor a `rcx` értéke.
Mindegyik alkalommal a `rcx` értéke `1`-gyel csökken.
Ne feledd, hogy a `rcx` értékét az utasítás használata előtt be kell állítani:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
A modern CPU-kon a `rep movs` és a `rep stos` általában gyors megoldás, amikor nagy blokkokban mozgatunk adatot.
A többi string utasítás, sőt a `movs` és a `stos` is, amikor `rep` nélkül működnek, azonban általában lassabbak egy egyszerű ciklusnál.

A témáról részletesebb betekintést nyújt [A 16.9. fejezet, „String instructions”, ebből a referenciakönyvből][agner-optimization-guide].
