# Bevezetés az átirányításba

A parancssori felület világában a programok gyakran három szabványos adatfolyammal dolgoznak:

1. **Szabványos bemenet** (`stdin`): itt kapja meg a program a bemenetét (többnyire a billentyűzetről).
1. **Szabványos kimenet** (`stdout`): ide küldi a program a szokásos kimenetét (többnyire a terminál képernyőjére).
1. **Szabványos hiba** (`stderr`): ide küldi a program a hibaüzeneteket (többnyire a terminál képernyőjére).

Emlékezz rá, hogy ezeket a [csővezetékek és parancslisták][pipelines] fejezetben vezettük be.

~~~~exercism/note
A csővezetékek az átirányítás egy formájának tekinthetők: az egyik program szabványos kimenete közvetlenül egy másik program szabványos bemenetére kerül.
A csővezetékeket már tárgyaltuk.
Ez a fogalom arról szól, hogyan irányíthatunk át fájlokba és fájlokból.
~~~~

A shell-átirányítás hatékony mechanizmus, amellyel megváltoztathatod ezeknek az adatfolyamoknak a célját.
Ahelyett, hogy a program a billentyűzetről olvasna vagy a képernyőre írna, átirányíthatod a bemenetet egy fájlból, vagy a kimenetet egy fájlba küldheted.
Ez jelentős rugalmasságot és kontrollt ad afölött, hogyan dolgoznak a programok az adatokkal.

## A legfontosabb átirányítási operátorok

Íme a leggyakoribb átirányítási operátorok, és hogy mit tesznek:

### `>` (kimenet átirányítása)

* Cél: egy parancs szabványos kimenetének (`stdout`) átirányítása egy fájlba.
* Viselkedés:
  * Ha a fájl nem létezik, létrejön.
  * Ha a fájl létezik, a tartalma felülíródik.
* Példa:

  ```bash
  # Sends the output of 'ls -l' to 'file_listing.txt'
  ls -l > file_listing.txt
  ```

~~~~exercism/caution
Az átirányítás **a parancs végrehajtása előtt** történik.
Ez azt jelenti, hogy nem irányíthatsz át ugyanabba a fájlba, amelyből olvasnod kell.

```bash
date > date.txt         # populate the file with the current date
cat date.txt > date.txt # 'date.txt' is now empty!
```

A fenti példa második parancsában

1. A Bash először levágja az átirányításban megnevezett fájlt.
   Ezzel megsemmisíti a korábbi tartalmat, és egy üres fájl marad.
2. Ezután a bash beolvassa az immár üres fájlt.
3. Végül a bash visszaírja a fájlba a tartalmát (azaz semmit).
~~~~

### `>>` (kimenet hozzáfűzése)

* Cél: egy parancs szabványos kimenetének (`stdout`) hozzáfűzése egy fájlhoz.
* Viselkedés:
  * Ha a fájl nem létezik, létrejön.
  * Ha a fájl létezik, a kimenet a fájl végére kerül.
* Példa:

  ```bash
  # Adds "Another line" to the end of the file
  echo "Another line" >> file_listing.txt
  ```

### `<` (bemenet átirányítása)

* Cél: egy parancs szabványos bemenetének (`stdin`) átirányítása egy fájlból.
* Viselkedés: a parancs a megadott fájlból olvassa a bemenetét a billentyűzet helyett.
* Példa:

  ```bash
  # 'tr' reads from 'lowercase.txt' and
  # output is redirected to 'uppercase.txt'
  tr 'a-z' 'A-Z' < lowercase.txt > uppercase.txt
  ```

### `2>` (hiba átirányítása):

* Cél: egy parancs szabványos hibájának (`stderr`) átirányítása egy fájlba.
* Viselkedés: a hibaüzenetek a megadott fájlba kerülnek a terminál helyett.
* Példa:
  ```bash
  # Error message from 'rm' is sent to 'error_log.txt'
  rm non_existent_file 2> error_log.txt
  ```

A szabványos hibát a `2>>` segítségével _hozzáfűzheted_ egy fájlhoz.

### További átirányítások

Vannak olyan átirányítások is, amelyek egyszerre vonhatják össze a `stdin`-t és a `stderr`-t.
A részleteket lásd a [kézikönyvben][manual].

## `/dev/null`

A `/dev/null` egy különleges fájl, amely

* üres fájl, amikor olvasol belőle, és
* eldobja az összes beleírt adatot.

Néha „a bitbucket” néven emlegetik.
Arra jó, hogy elnyomd vele a kimenetet vagy a hibákat.

```bash
some_command > /dev/null  # Discards stdout
some_command 2> /dev/null # Discards stderr

# Using /dev/null as input will prevent the command
# from reading data from the keyboard
some_command < /dev/null
```

## Átirányítások kombinálása

Egyszerre több átirányítás is megadható.

```bash
some_command < input.txt > output.txt 2> error.txt
```

Egy átirányítás átmásolható.

```bash
# send stderr to the same destination as stdout
some_command > output.txt 2>&1
```

Amikor `2>&1`-et látsz, olvasd úgy, hogy „irányítsd át a stderr-t _oda, ahová a stdout **éppen** mutat_”.
A Bash szigorúan balról jobbra dolgozza fel az átirányítási utasításokat, ami azt jelenti, hogy ezt is megteheted:

```bash
# redirect stdout to 'output1.txt'
# redirect stderr to the same place
# then change stdout to 'output2.txt'
some_command > output1.txt 2>&1 > output2.txt
```

## Fájlleírók

A shell-programozás és az olyan operációs rendszerek világában, mint a Linux/Unix, a fájlleíró (FD) egy nemnegatív egész szám, amely egy nyitott fájl vagy egy I/O (bemeneti/kimeneti) erőforrás azonosítójaként vagy hivatkozásaként szolgál.
Gondolj rá úgy, mint egy címkére vagy hivatkozási számra, amelyet az operációs rendszer a nyitott fájlok és adatfolyamok nyilvántartására használ.

Az átirányítások bal oldalán látható számok a fájlleírók.

A szabványos I/O adatfolyamok kapják az első 3 fájlleírót:

* a szabványos bemenet a 0-s FD
* a szabványos kimenet az 1-es FD
* a szabványos hiba a 2-es FD

Új fájlleírókat az `exec` paranccsal és átirányítási operátorokkal állíthatsz be vagy hozhatsz létre.

```bash
# create FD 3 as a copy of stdout
exec 3>&1
# send stdout to a log file
exec > log.txt

# then redirect both stdout and file descriptor 3
echo "some debug message" >&3  # displayed in the terminal
some_command  2>&1 # stdout and stderr send to 'log.txt'
```

Ez a technika meglehetősen bonyolultnak tűnik, de nagyon hasznos lehet olyankor, amikor a szkriptedet valamilyen más szoftvercsomag futtatja, és a szabványos kimenetet a szoftver automatikusan elkapja.
A `bats` parancs, amellyel ezen a kurzuson az egységteszteket futtatják, így működik: a `bats` elkapja egy teszt stdoutját és stderr-jét, de a 3-as FD-re küldött hibakeresési üzenetek megjelennek a terminálon.
~~~~

## Összefoglalva

Miért hasznos az átirányítás?

* Kimenet mentése: elmented egy parancs eredményét későbbi áttekintéshez vagy feldolgozáshoz.
* Naplózás: elkapod a hibaüzeneteket a hibakereséshez.
* Automatizálás: parancsokat fűzöl össze úgy, hogy az egyik kimenete a másik bemenete lesz.
* Szűrés: eldobod a nem kívánt kimenetet.
* Kötegelt feldolgozás: fájlokból dolgozol fel adatokat ahelyett, hogy kézzel gépelnéd be őket.
* Szkriptírás: az átirányítások elengedhetetlenek a robusztus shell-szkriptek megírásához.

A shell-átirányítások finomhangolt kontrollt adnak afölött, hogyan dolgoznak a programok az adatokkal, így összetett munkafolyamatokat építhetsz, és hatékonyan kezelheted az információkat.
