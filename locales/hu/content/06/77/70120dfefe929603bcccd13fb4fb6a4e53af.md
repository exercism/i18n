A regex számos képessége beépül a Base R-be, és régebbi kódokban is találkozhatsz példákkal.

Új kód esetén _erősen_ ajánlott a [`stringr`][web-stringr] könyvtár használata.

Ahogy a [Strings fogalomnál][concept-strings] megjegyeztük, a `stringr` jó dokumentációval rendelkezik, amelyet jellemzően a csomag szerzője (szerzői) írt.

A [`Strings`][concept-strings] fogalomnál már tárgyalt függvények közül sok eleve regexes keresésre készült.

A Strings fogalmat viszonylag egyszerűen tartottuk, csak stringliterálokra illesztettünk, de helyette bármilyen regexminta használható.

Formálisan egy regexet R-ben a [`regex()`][ref-regex] meghívásával hozunk létre.
A kényelem kedvéért a `stringr` függvényei bármelyik mintastringet regexként kezelik.
Az alábbi példában az első `str_replace_all()` szintaktikai cukor a második változathoz:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

A [puskalap][cheat-stringr] hasznos útmutató: minden `pattern` argumentummal rendelkező függvény (pirossal szedve) elfogad regexet, a 2. oldal pedig összefoglalja a regex szintaxisát.

Vedd figyelembe, hogy a [`regex()`][ref-regex] függvény továbbra is fontos lehet, ha felül kell bírálnod az alapértelmezéseket, például a kis- és nagybetűk megkülönböztetését vagy a locale-t.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

Sok regexkód tartalmaz backslasht, mint a fentebb használt `\s`.
A normál R stringekben a `\` karaktert duplázással kell escape-elni, ezért `"\\s"`.

A backslash-ek elszaporodhatnak és zavaróvá válhatnak, ezért bonyolult esetekben segíthet a [raw stringek][book-raw] használata.

Alapértelmezés szerint a raw string definiálásának szintaxisa `r"( )"`, de más határolójelek is megengedettek.
Mivel a kerek zárójelek `( )` és a szögletes zárójelek `[ ]` egyaránt gyakoriak a regex szintaxisában (elfogó csoportokhoz és opcióscsoportokhoz), a kapcsos zárójelek `{ }` jó választás lehet.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## Egyezések felismerése

Íme néhány kérdés, és függvények, amelyek segíthetnek megválaszolni őket.

Néhány példa a `fruit` vektort használja, amely 80 gyümölcsnevet tartalmaz, és a `stringr`-rel együtt érkezik gyakorláshoz.

_Tartalmaz egy string egyezést?_
`str_detect()`, vagy `str_starts()`, `str_ends()`, hogy elkerüld a `^` vagy `$` horgonyok használatát.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_Csak az egyezést tartalmazó stringeket add vissza?_
Használd a `str_subset()`-et a stringekhez, a `str_which()`-et az indexekhez.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_Hány egyezés van az egyes stringekben?_
Használd a `str_count()`-et.

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_Hol van az egyezés?_
`str_view()` interaktív használathoz, `str_locate()` vagy `str_locate_all()` általánosabban.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## Elfogások

Gyakran szeretnénk tudni, hogy _mi_ illeszkedik.
Ezt úgy érjük el, hogy elfogó csoportokat teszünk zárójelbe a regexen belül.

Lehetőség van arra, hogy ugyanazon a regexen belül visszahivatkozz az elfogásokra a `\1`, `\2` stb. segítségével.
Például ismétlődő betűpárok keresése:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

Hasonló szintaxissal az elfogások a csere-stringekben is használhatók:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

Gyűjtsd össze az egyezéseket későbbi feldolgozásra a `str_match()` függvénnyel, ha csak az első egyezés kell, vagy az `str_match_all()` függvénnyel az összes egyezéshez.

Az elfogó csoportok hajlamosak bonyolult kimenetet adni bármelyik nyelvben.
Az R megközelítése (_amely ráadásul vektorizált, hogy még nagyobb kihívás legyen_) az, hogy mátrixot készít a `str_match()`-ból, soronként egy bemeneti stringgel, az 1. oszlopban a teljes illeszkedő stringgel, a többi oszlopban pedig a különféle elfogó csoportokkal.

Az elnevezett csoportok használata előny lehet, mivel az eredménymátrix oszlopneveivé válnak.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

~~~~exercism/note
Ebben a tantervben nem sokat beszéltünk a mátrixokról, bár van egy [fogalmi dokumentum][concept-matrices-arrays], amelyet megnyithatsz.
A mátrixok nem illeszkednek jól a Tidyverse ökoszisztémához, pedig régóta a Base R részei.

Rövid összefoglaló: kezeld a mátrixokat úgy, mint a vektorokat 2 indexszel, a `[rows, cols]` sorrendben.
Hagyd üresen bármelyik indexet, hogy megkapd a teljes sort vagy oszlopot.

Amikor egyetlen `r` sort kérsz le `m[r,]` alakban, vagy egyetlen `c` oszlopot `m[,c]` alakban, a visszaadott érték alapértelmezés szerint vektorrá lapul.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```
~~~~

A `str_match_all()` elkerülhetetlenül még bonyolultabb szerkezetű kimenetet ad:

- Az eredmény egy lista, soronként egy bemeneti stringgel.
- Ha csak egy bemeneti string van, bontsd ki a kimenetet `[[1]]` indexeléssel, ahogy a [Lists fogalom][concept-lists] leírja.
- Minden elem egy mátrix, ugyanazokkal az oszlopokkal, mint a `match()` esetén.
- A mátrix minden sora egy sikeres elfogás.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

Természetesen az egyezések meghiúsulhatnak.
Ilyenkor az eredmény a különleges `NA` érték lesz.
Készülj fel ennek tesztelésére, ahogy a [Nothingness fogalom][concept-nothingness] leírja.

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
