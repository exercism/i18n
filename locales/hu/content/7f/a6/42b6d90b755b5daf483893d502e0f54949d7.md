# Bevezetés a shell alapjaiba

## A shellek

A _shell_ egy olyan program, amellyel parancsokat beírva tudsz az operációs rendszerrel kommunikálni.
A shellek lehetnek grafikusak is: az asztali környezet, amelyet egérrel vagy trackpaddel használsz, szintén egy shell.
Mi most a parancssori felületekre összpontosítunk, ahol parancsokat gépelsz be, és az eredmény (általában) a terminálban jelenik meg.

Sokféle parancssori shell létezik.
Windowson **cmd** és **powershell** érhető el.
A Mac és a Linux „Unix shelleket” kínál, amelyekből rengeteg van.
A Mac alapértelmezett shellje a **zsh**.
A **csh** egy régi shell C-szerű szintaxissal.
A **bash** az egyik legnépszerűbb shell, különösen Linuxon.

A legkorábbi shellek egyike a Bourne shell, a **sh**.
Idővel ezt a shellt [szabványosították][posix], hogy minden Unix-szerű rendszeren elérhető legyen.
Sok shell a Bourne shellen alapul, és gyakran további interaktív vagy programozási funkciókkal egészíti ki azt.

A **Bash** a Bourne shellen alapul.
Ezért is hívják „**B**ourne-**a**gain **sh**ellnek”.
Sok Linux-rendszeren ez az alapértelmezett shell.
A bash sok olyan szolgáltatást nyújt, amely élvezetessé teszi interaktív shellként való használatát, többek között:

* teljesen testreszabható prompt,
* a korábbi parancsok felidézésének és módosításának lehetősége,
* a futó folyamatok kezelésének lehetősége,
* aliasok, amelyekkel kevesebbet kell gépelni,
* és még sok minden más.

Ez a kurzus nem arról szól, hogyan használd a bash-t interaktív shellként.
Arról szól, hogy megtanulj programokat írni bashben.
A hangsúly azon lesz, hogy _csak_ bash-t használj a problémák megoldásához, bár semmi sem tiltja a külső eszközök hívását.

## A bash alapjai: parancsok és argumentumok

A bash a bemenetéről olvassa a parancsokat (ami általában vagy egy terminál, vagy egy fájl).
Az általa beolvasott minden egyes sor _parancsnak_ számít, azaz egy végrehajtandó utasításnak.
(Néhány haladó eset, például a több soron átívelő parancsok, később kerül szóba.)

A bash minden sort **szavakra** bont, amelyeket valamilyen whitespace-karakter (szóköz vagy tabulátor) határol.
A sor első szava a végrehajtandó _parancs_ neve.
Az összes többi szó a parancs _argumentumaivá_ válik (opciók, fájlnevek stb.).

~~~~exercism/note
Az alábbi példákban néhány interaktív parancsot mutatunk, amelyeket futtathatsz.

* A `#` karakter _kommentet_ kezd.
  A komment utáni szavakat a shell figyelmen kívül hagyja; a komment csak olvasásra szolgál.
* A `$` karakter a shell promptját jelöli. 
  Ha bemásolod a parancsot, a promptot ne vedd bele.
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

Az `rm` egy alkalmazás, amely törli a neki átadott fájlokat.
A `*` egy [glob][glob] karakter, egy „wildcard” minta, amely az aktuális könyvtár összes fájljára illeszkedik.
A globokról később részletesebben is szót ejtünk.

Feltűnt, hogy `a` és `b` között több szóköz van, `b` és `c` között pedig csak egy?
Nem számít, mennyi whitespace van az argumentumok között!
Például:

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

Az `echo` egy parancs, amely kiírja az argumentumait a szabványos kimenetre (esetünkben ez a terminál).
A bash a parancsot öt szóra bontja, és az `echo` parancsot négy argumentummal hívja meg.
A második példában szereplő plusz szóközök semmit sem változtatnak.
Az `echo` nem tudja, hogyan helyezkedtek el eredetileg a szóközök a szavak között.

Ha meg akarjuk őrizni a plusz whitespace-t, egyetlen argumentumként kell átadnunk a mondatot.
Ezt [idézőjelek][Quotes] használatával tehetjük meg:

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

Az idézőjelek mindent egyetlen _argumentumba_ fognak össze.
Az argumentum a `This    is    a    test.`, beleértve azokat a konkrét szóközkaraktereket.
Vedd észre, hogy az idézőjelek nem részei az argumentumnak: a bash eltávolítja őket, mielőtt átadná az argumentumot az `echo`-nak.

Az argumentumokat a parancs nevétől és egymástól is whitespace választja el.
Ezt fontos megjegyezni.
Például a következő hibás:

```bash
$ [-f file]
bash: [-f: command not found
```

Ez azt hivatott vizsgálni, hogy létezik-e `file` nevű fájl.
Kézenfekvő azt feltételezni, hogy a `[` és `]` körüli whitespace nem számít, de a `[` valójában egy parancs, és megköveteli, hogy az utolsó argumentuma `]` legyen.
(A `[` parancsra később részletesebben is kitérünk.)
Ezért a `[`-t el kell választanunk a `-f`-től, a `]`-t pedig a `file`-tól.
Ellenkező esetben a bash azt hiszi, hogy egy `[-f` nevű parancsot próbálunk futtatni egyetlen `file]` argumentummal.
A helyes parancs minden argumentumot whitespace-szel választ el:

```bash
$ [ -f file ]
```

(Sokakat látunk, akiket összezavar ez a viselkedés; azt hiszik, hogy a `[...]` „csak szintaxis”, és elhagyhatják a szóközöket; pedig a `[` egy parancs, és a whitespace kötelező.)

Ha a fájlnevünk whitespace-t vagy más speciális karaktereket tartalmaz, azt is idézőjelbe kell tenni:

```bash
$ [ -f "my file" ]
```

## A parancsok típusai

A bash többféle parancstípust ismer: aliasok, függvények, beépített parancsok, kulcsszavak és futtatható fájlok.
Ezek mind _parancsok_, és mind nagyon hasonló módon viselkednek.

Alapértelmezés szerint az aliasok csak interaktív shellekben érhetők el, shell-szkriptekben nem.
Ezekkel itt nem foglalkozunk.

### Függvények

A függvény shellparancsokat tartalmaz, és nagyon hasonlóan viselkedik egy kis szkripthez; még argumentumokat is kaphat, és létrehozhat helyi változókat.
Amikor egy függvényt meghívunk, a benne lévő parancsok végrehajtódnak.
A függvényekre később részletesen is kitérünk.

### Beépített parancsok

A bashbe néhány alapvető parancs van beépítve, például: `cd` (könyvtárváltás), `echo` (kimenet írása) és így tovább.
Úgy tekinthetünk rájuk, mint eleve biztosított függvényekre.

### Kulcsszavak

A kulcsszavak hasonlítanak a beépített parancsokhoz, a fő különbség az, hogy a kulcsszavak valójában bash-szintaxist alkotnak, és speciális szabályok szerint értelmeződhetnek.
Például a `[` egy bash-beépített parancs, míg a `[[` egy bash-kulcsszó; mindkettőt különféle feltételek vizsgálatára használjuk.
A `[[` kulcsszó azonban néhány extra funkcióval is rendelkezik.
Például biztosítja a `=~` operátort, amely reguláris kifejezésekkel való illesztést végez.

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

A `<` és `>` szöveg-összehasonlító operátorok egy másik példa arra, hogy a kulcsszavak másképp értelmezik a kódot.
A `[[...]]` belsejében ezek az operátorok nem igényelnek különleges kezelést.

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

A `[...]` esetében viszont idézőjelbe kell tenned vagy escape-elned őket, hogy a shell ne értelmezze őket átirányítási operátorként.

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### Futtatható fájlok

Az utolsó parancstípus, amelyet a bash végre tud hajtani, a _futtatható fájl_.
Ezek a számítógéped fájlrendszerén található futtatható fájlok (programok), amelyeket elindíthatsz.
(A futtatható fájlokat _külső parancsoknak_ vagy _alkalmazásoknak_ is nevezik.)
A futtatható fájlokat általában elég csak a nevük beírásával meghívni; a fájl teljes elérési útjára jellemzően nincs szükség.
Ez azért lehetséges, mert a bash egy előre definiált változót használ, amely segít megtalálni a gyakori futtatható fájlok helyét.
Ezt a változót `PATH`-nak hívják.
Könyvtárnevek halmaza, amelyeket kettőspont választ el egymástól (pl. `/usr/bin:/bin`). 
Amikor egy parancsot elérési út nélkül adunk meg (pl. `myprogram` vagy `ls`), és az nem alias, függvény, beépített parancs vagy kulcsszó, a bash végigkeresi a `PATH`-ban szereplő könyvtárakat.
A könyvtárakat balról jobbra, sorrendben vizsgálja meg, hogy tartalmaznak-e futtatható fájlt a megadott névvel.

Ha a futtatható fájl egy ismert útvonalon kívül van, meg kell adni a fájl elérési útját.
Az aktuális könyvtárban lévő `myprogram` futtatható fájlhoz használd a `./myprogram` útvonalat; ha a `/opt/somedirectory` könyvtárban van, akkor a `/opt/somedirectory/myprogram` útvonalat.

Tipp: A `type` paranccsal részleteket tudhatsz meg a parancsról:

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## Szkriptek

A _szkript_ egy fájlban tárolt parancssorozat.
A bash beolvassa a fájlt, és sorrendben feldolgozza a parancsokat.
Csak akkor lép tovább a következő parancsra, amikor az aktuális befejeződött.
Kivétel ez alól, ha egy parancsot aszinkron módon (a háttérben) való futtatásra jelöltünk meg.
Ezzel az esettel még ne foglalkozz túl sokat; később megtanuljuk, hogyan is működik.

Az ebben az útmutatóban szereplő bármelyik parancssori példát használhatod szkriptben is.

Szkriptet készíteni egyszerű.
Kezdd azzal, hogy létrehozol egy új fájlt, és írd be az első sorába ezt:

```bash
#!/bin/bash
```

Ezt a sort _értelmeződirektívának_ nevezik (más néven _hashbang_ vagy **_shebang_**).
Ez határozza meg, hogy a `/bin/bash` legyen az értelmező, amikor a fájlt végrehajthatóként használjuk egy parancsban.
Amikor az operációs rendszer kernelje végrehajt egy _nem bináris fájlt_, beolvassa a fájl első sorát.
Ha a sor `#!`-tal kezdődik, a kernel e sor alapján határozza meg, melyik értelmezőnek adja tovább a fájlt.
(Erre más érvényes módok is léteznek, lásd alább.)
A `#!`-nak a fájl legeslegeljén kell állnia, előtte nem lehet szóköz vagy üres sor.
A szkriptünk parancsai ez alatt, külön sorokban következnek.

Tipp: A `#!/bin/bash` helyett használhatod ezt is:

```bash
#!/usr/bin/env bash
```

Az `env` a `$PATH`-ban keresi azt a futtatható fájlt, amelyet az első argumentuma megnevez (ebben az esetben a „bash”-t).
Ha részletesebben szeretnéd megérteni ezt a technikát, és azt, hogy miben tér el a jó öreg `#!/bin/bash`-tól, nézd meg [ezt a StackOverflow-kérdést][env bash].

Ne hagyd, hogy megtévesszenek az interneten található olyan szkriptek vagy példák, amelyek `/bin/sh`-t használnak értelmezőként.
**A `sh` nem `bash`!**
Maga a bash egy „sh-kompatibilis” shell, ami azt jelenti, hogy a legtöbb `sh` szkriptet le tudja futtatni, és sok azonos szintaxist hordoz.
Ez azonban fordítva nem igaz; a bash bizonyos funkciói elromlanak vagy váratlan viselkedést okoznak `sh`-ban.
Valójában nincs egyetlen `sh` shell sem.
Sok olyan shell-implementáció létezik, amely támogatja a POSIX-sh szintaxist.
Attól függően, hogy milyen operációs rendszert használsz, a `sh` futtatásakor valójában lehet, hogy bash-t, ash-t, dash-t vagy valamilyen más shellt futtatsz.

Miután a szkriptfájl elkészült, így futtathatod:

```bash
$ bash myscript
```

Ebben a példában a `bash` _parancsot_ futtatjuk, és megkérjük, hogy olvassa be a _argumentumként_ megadott szkriptet.
Amikor így teszünk, a `#!` sor csupán egy _komment_.

Másik lehetőség, hogy futtatási jogosultságot adunk a szkriptünknek.
Ezzel a módszerrel úgy futtathatjuk a szkriptet, mint bármely más futtatható fájlt, ahelyett hogy kézzel hívnánk meg a bash-t:

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

Amikor így futtatjuk a parancsot, az operációs rendszer a `#!` sor alapján határozza meg, melyik értelmezőt használja a szkript futtatásához.
