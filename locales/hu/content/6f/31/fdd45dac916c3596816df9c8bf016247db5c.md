# Gyakorlófeladat hozzáadása

Ez a dokumentum elmagyarázza, hogyan adhatsz hozzá új [gyakorlófeladatot](/docs/building/tracks/practice-exercises).

## A feladat kiválasztása

A legegyszerűbb módja annak, hogy megnézd, mely gyakorlófeladatok nincsenek még megvalósítva, ha felmész a kurzus build oldalára (pl. https://exercism.org/tracks/csharp/build), és megnézed a „Gyakorlófeladatok” szakaszt.

```exercism/caution
A build oldalon lévő adatok naponta egyszer frissülnek.
```

## A feladat vázának létrehozása

Gyorsan létrehozhatod egy új gyakorlófeladat vázát, ha a kurzus gyökérkönyvtárából futtatod a `bin/add-practice-exercise` szkriptet ([forrás](https://github.com/exercism/generic-track/blob/main/bin/add-practice-exercise)):

```shell
bin/add-practice-exercise <exercise-slug>
```

Opcionálisan megadhatod a feladat nehézségét (a `-d` kapcsolóval) és/vagy a szerző GitHub-felhasználónevét (az `-a` kapcsolóval) is:

```shell
bin/add-practice-exercise -d 3 -a foobar <exercise-slug>
```

```exercism/note
Ha olyan kurzustárházon dolgozol, amelyben nincs meg ez a fájl, nyugodtan másold be a tárházadba a fenti forráshivatkozás segítségével.
```

## A feladat implementálása

Miután elkészültek a vázfájlok, a következőket kell tenned:

- Teszteket adsz a tesztfájlhoz
- Hozzáadsz egy példaimplementációt
- Meghatározod a stub fájl tartalmát
- A feladat `.meta/config.json` fájljában:
  - Hozzáadod a feladat szerzőinek GitHub-felhasználónevét az `authors` kulcshoz
- A kurzus `config.json` fájljában:
  - Ellenőrzöd és frissíted a feladat nehézségét
  - Fogalmakat adsz a `practices` kulcshoz (csak akkor szükséges, ha a kurzusnak vannak tanulófeladatai)
  - Fogalmakat adsz a `prerequisites` kulcshoz (csak akkor szükséges, ha a kurzusnak vannak tanulófeladatai)

### Tesztek hozzáadása

A feladat hozzáadásának egyik legfontosabb része a tesztek megírása.
Nagyjából két lehetőség van, amikor egy gyakorlófeladathoz teszteket írsz:

1. A teszteket a nulláról írod meg, a feladat `canonical-data.json` fájljában lévő teszteseteket használva, amelyek a [problem-specifications repóban](https://github.com/exercism/problem-specifications) találhatók.
2. Átülteted a teszteket egy másik kurzus implementációjából (tipp: menj a `https://exercism.org/exercises/<slug>` címre, hogy áttekintést kapj arról, mely kurzusok valósítottak meg egy adott feladatot).

A második lehetőség különösen vonzó lehet, mert gyorsan eredményt adhat.
Tartsd azonban észben, hogy az implementációt hozzá kell igazítanod a kurzusodhoz.
Például van, amelyik kurzus nem használ osztályokat, csak függvényekkel dolgozik.
Ha viszont a kurzusod jellemzően objektumokkal dolgozik, akkor az implementációt ahhoz igazítsd, ami a legjobban illik a kurzusodhoz.

```exercism/note
Egyes kurzusok [tesztgenerátort](/docs/building/tooling/test-generators) használnak a feladat tesztfájljainak automatikus (újra)generálására.
Nézd meg a kurzus dokumentációját, hogy van-e tesztgenerátor, és ha igen, hogyan kell használni.
```

### Példaimplementáció hozzáadása

Ahhoz, hogy biztos legyen, írható olyan kód, amely átmegy a teszteken, hozzá kell adnod egy példaimplementációt.

```exercism/note
A kódnak _nem_ kell idiomatikusnak lennie, csak át kell mennie a teszteken.
```

Ellenőrizheted, hogy a példaimplementáció átmegy-e az összes teszten, ha a kurzus gyökérkönyvtárából futtatod a `bin/verify-exercises` szkriptet ([forrás](https://github.com/exercism/generic-track/blob/main/bin/verify-exercises)):

```shell
bin/verify-exercises <exercise-slug>
```

A kimenet alapján ellenőrizd, hogy a példaimplementáció átmegy az összes teszten.

```exercism/note
Ha olyan kurzustárházon dolgozol, amelyben nincs meg ez a fájl, nyugodtan másold be a tárházadba a fenti forráshivatkozás segítségével.
```

```exercism/advanced
A színfalak mögött a `bin/verify-exercises` szkript több dolgot is csinál:

- A feladatot egy ideiglenes könyvtárba másolja
- Felülírja a stub fájl(oka)t a példaimplementációs fájllal/-okkal
- Ha a tesztfájlban vannak kihagyott tesztek, azokat »kihagyatlanná« teszi
- Lefuttatja a teszteket
```

### Stub fájl(ok) hozzáadása

A stub implementációs fájl(ok) kiindulópontot adnak a tanulóknak.

Azt javasoljuk, hogy a stub fájlok a lehető legkevesebb kódot tartalmazzák, hogy:

- a tanuló azonnal elkezdhesse megvalósítani a tesztek átmenéséhez szükséges logikát
- a tanuló ne szembesüljön „furcsa” szintaktikai hibákkal

A gyakorlatban ez azt jelenti, hogy definiálod azokat a függvényeket/metódusokat, amelyeket a teszthalmaz tesztel.
A kurzusok szabadon dönthetik el, hogyan állítják össze ezt a kódot, amíg biztosítják, hogy a stub kód kezdetben minden teszten elbukik.

#### Példák

Python:

```python
def two_fer(name):
    pass
```

Kotlin:

```kotlin
fun twofer(name: String): String {
    TODO("Implement the function to complete the task")
}
```

## A feladat lintelése

Az utolsó lépés, hogy futtatod [a lintert](/docs/building/configlet/lint), amely ellenőrzi, hogy a kurzus (konfigurációs) fájljai megfelelően strukturáltak-e, szintaktikailag és szemantikailag is.

Először győződj meg róla, hogy a [`configlet`](/docs/building/configlet/) legújabb verziójával rendelkezel, ehhez futtasd:

```shell
bin/fetch-configlet
```

Ezután futtasd [a lintert](/docs/building/configlet/lint):

```shell
bin/configlet lint
```

A kimenet alapján ellenőrizd, hogy minden rendben van.

## Pull request beküldése

Miután minden rendben van, [beküldhetsz egy pull requestet](/docs/building/github/contributors-pull-request-guide) a kurzus repójába.

Beküldés előtt olvasd el a [közreműködői pull request útmutatót](/docs/building/github/contributors-pull-request-guide) és a [pull request útmutatót](/docs/community/being-a-good-community-member/pull-requests).

Ügyelj rá, hogy a PR leírása felsorolja a hozzáadott feladatot.
