# Bemutatás

Ahogy a [`Nothingness`][concept-nothingness] fogalomban láttuk, az R-nek többféle módja van arra, hogy olyan adatot ábrázoljon, amely hiányzik ([`NULL`][ref-null]), ismeretlen ([`NA`][ref-na]) vagy matematikailag érvénytelen ([`NaN`][ref-finite], [`Inf`][ref-finite]).
Az R általában arra használja ezeket az értékeket, hogy helyben jelezze a problémákat, és kivétel dobása nélkül folytatja a futást.

## `stop()`

Némely probléma túl alapvető ahhoz, hogy a program folytatódhasson. 
Ebben az esetben használd a [`stop(msg)`][ref-stop] függvényt, hogy azonnal leállítsd a programot egy `Error`-ral, és kiírd a `msg`-t.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

A más nyelvekben megszokott [`assert`][wiki-assert]-hez hasonlóan a [`stopifnot()`][ref-stopifnot] a `stop()` kényelmes burkolója.
Az argumentumok tetszőleges számú, vesszővel elválasztott boolean feltétel, és a program csak akkor folytatódik, ha mindegyik `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

Az R-nek többféle módja van a hibák kezelésére.
Ezek a Common Lisp-en alapulnak, és jelentősen eltérnek számos népszerű nyelvtől.

A legegyszerűbb, ha a potenciálisan problémás kódot [`try()`][ref-try] hívásba csomagolod.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning] és [`message()`][ref-message]

Ezek nem végzetes feltételekre adott reakciók, például:

- Figyelmeztetnek egy olyan problémára, amelyből a program legalább részben helyre tud állni.
- Tájékoztatják a felhasználót egy hosszú ideig futó program előrehaladásáról.

Az egyik különbség köztük az, hogy a figyelmeztetések gyorsítótárazódnak, és (alapértelmezés szerint) akkor íródnak ki, amikor a függvény visszatért, az üzenetek viszont azonnal megjelennek.
Számos módja van az alapértelmezett viselkedés megváltoztatásának, de ezek túlmutatnak a mostani kereteinken.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

A [`suppressWarnings()`][ref-warning] függvény időnként hasznos lehet az Exercism-ön belül, hogy a nem kívánt kimenet ne zavarja össze a tesztfuttatót.
