# Ismertetés

A `String` és a `&str` a szöveges adatokkal való munka két alapvető módja Rustban.
Nagyon jól jön, ha ismered a tulajdonságaikat, és azt, hogyan működnek együtt.
Ez a dokumentum azt járja körül, hogy hol fedik egymást, és néhány alapvető tanáccsal szolgál.
A `String` egy saját tulajdonú, `u8` bájtokból álló vektor.
A `String` módosítható.
A `&str` pedig egy kölcsönzött hivatkozás egy string szeletre.
A `&str` nem módosítható.

A `&str` helyes kiejtése „ref string”.
A `String` Unicode kódpontok sorozatának potenciálisan módosítható, UTF-8-kódolású reprezentációja.

A `&str` egy jól formált UTF-8 sorozat csak olvasható nézete.
Mivel hivatkozás, `Copy`, és megosztható.

A Rustban a `String` és a `&str` nem indexelhető úgy, ahogy más nyelvekben megszokhattad.
Ez például nem fog működni:

```rust,invalid
let hello = "Hello";
println!("First letter = {}", hello[0]);
```

Ez a következő tulajdonságokból fakad:

- A stringek UTF-8-asak, amelynek alapegysége nem egy bájt, hanem egy Unicode kódpont: `char`.
- A Unicode kódpontok legfeljebb 4 bájt szélesek, de változó szélességgel kódolódnak.
- Ezért lehetetlen kiszámítani az `n`-edik kódpont helyét anélkül, hogy végig ne iterálnánk a ténylegesen kódolt karaktereken, mert az első karakter után a következő karakter helye attól függ, milyen szélesek voltak az előzőek.
- A Rust standard könyvtárának szerzői ezért úgy döntöttek, hogy nem implementálják a `Index` traitet a stringekhez: míg egy bájttömb indexelése állandó ideig tart, egy string indexelése meglehetősen sokáig is eltarthat. Ez megsérti a legkisebb meglepetés elvét.

```rust
let example = "I'm not entirely ASCII! ❤";

let n_chars = example.chars().count();
let final_byte = example.as_bytes()[example.len()-1];

println!("n_chars = {}", n_chars);             // 25
println!("example.len() = {}", example.len()); // 27

println!("final char: {}", example.chars().nth(n_chars-1).unwrap()); // ❤
println!("final byte: {final_byte}");                                // 164
println!("char of final byte: {}", final_byte as char);              // ¤
```

## `String` átalakítása `&str`-ré

A `String` implementálja a `Deref<Target=str>` traitet.
Ennek a traitnek van némi fordítóspecifikus különleges kezelése: azt jelenti, hogy a `String`-re mutató bármely hivatkozás automatikusan, átlátszóan `&str`-ré alakítható.
Ebből a következők következnek:

- Bármely kód, amely például `&str` argumentumot vár, elfogadhat helyette `&String`-et.
- A `&str`-hez implementált bármely metódus meghívható `String`-en is.

(Ha valaki általánosan bármilyen formájú, `str`-re mutató hivatkozást szeretne elfogadni, akkor `impl AsRef<str>` típusú argumentumot adhat meg, de jellemzően az argumentumok `&str`-ként való tipizálása a szokásos.)

## `&str` átalakítása `String`-gé

Többféleképpen is létrehozhatsz `String`-et egy `&str`-ből:

- `String::from("my str")`
- `"my str".to_string()`
- `"my str".to_owned()`
- `let s: String = "my str".into();`

A fenti módok mindegyike memóriafoglalást igényel a `String` számára (a heapen).
Ezért elérhető a `&str` a no_std-ban, a `String` viszont nem.

(A [heapless](https://crates.io/crates/heapless) crate-et gyakran használják, amikor no_std-ban stringeket manipulálsz.)

## A String és a `&str` használata structokban

Ez a szakasz arról szól, mikor használj `String`-et vagy `&str`-t a struct mezőihez.
Gyakran láthatsz olyan structokat, amelyeknek a mezőértékei `String`-ként vannak definiálva `&str` helyett.

```rust
struct Record {
    latitude: f64,
    longitude: f64,
    population: Option<u64>,
    city: String,
    state: String,
}
```

A `String` használatával a struct birtokolja az adatokat.
Ez könnyebben olvashatóvá és taníthatóvá teszi a kódot kezdők számára.
De azt is jelenti, hogy minden mezőhöz heapfoglalás történik.
A `&str` kölcsönzi a szöveges adatokat, így jobban teljesít, cserébe a structnak élettartam-paramétereket kell definiálnia.
A [csv crate oktatóanyaga][csv-tutorial] gyakorlatiasan, egészen szépen bemutatja és elmagyarázza ezeket az ötleteket.

## Teljesítménnyel kapcsolatos megjegyzések

A `String`-ek a heapen foglalódnak le, így használatuk költségesebb lehet.
A `&str`-ek megosztott hivatkozások, így nem igényelnek gyakori újrafoglalást.
