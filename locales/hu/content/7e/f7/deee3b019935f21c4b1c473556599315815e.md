# Függvények a `jq`-ban

A `jq`-ban definiálhatsz saját **egyéni függvényeket**, hogy egy helyre gyűjtsd a logikát, amire szükséged van.
A _függvények_ pontosan úgy viselkednek, mint a beépített függvények: kapnak egy bemenetet, és nulla, egy vagy több kimenetet adnak.

## Függvény definiálása

A következő szintaxissal definiálhatsz egy `jq` _függvényt_:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- a `def` kulcsszóval kezdődik,
- a függvény törzse előtt egy kettőspont áll,
- a törzs egyetlen kifejezésből áll,
- pontosvesszővel végződik,
- ahogy a `jq` szintaxisának többi részénél, itt is tetszőlegesen tagolhatod a kódot az olvashatóság érdekében.

## Hová kerüljenek a függvények

A _függvényeket_ használat előtt kell definiálni: ez hibát okoz:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Ez azt jelenti, hogy a _függvényeket_ a `jq`-kódod elejére kell tenned, a „fő” kifejezés elé.

### Egymásba ágyazott függvények

A _függvények_ egymásba ágyazhatók:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Itt a `B` _függvény_ csak az `A` törzsében látható.

## Scope

Egy _függvény_ új **scope**-ot vezet be a változók és az egymásba ágyazott függvények számára.

## Argumentumok

A _függvény_ **argumentumait** _pontosvesszők_ választják el, nem vesszők.
Például egy _függvény_, amely kap egy számot, majd hozzáad egy számot és megszoroz egy számmal:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
A pontosvesszőkre azért van szükség, mert a vesszőnek már van egy funkciója a `jq`-ban: ez egy operátor, amely folyamokat fűz össze.

Ha vesszőt használsz pontosvessző helyett, az két hívást próbál indítani egy _egyargumentumos_ `add_mul` függvényre, amely nem létezik, ezért már az első megkísérelt hívásnál hiba lesz:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```
~~~~

<!-- prettier-ignore-end -->

### Az argumentumok _kifejezések_

A függvény _argumentumai_ szűrők, nem értékek.
Ebben az értelemben úgy viselkednek, mint amit más nyelvek callbacknek neveznek:

Példaként használva az `add_mul` függvényt:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

Mi történik itt?

- az `adder` argumentum a `. + 5` _kifejezést_ kapja
  - amikor a függvény a `. + adder` műveletet végzi, az `. + . + 5` lesz
  - ennek az eredménye 25, mivel `. == 10`
- hasonlóképpen a `multiplier` argumentum a `. - 2` kifejezés
  - ennek az eredménye 8
  - így a végeredmény `25 * 8 == 200`

### Argumentumok értékként

Néha szeretnél egy _argumentumot_ változóvá „materializálni”:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Erre van egy rövidítés:

```jq
def my_func($arg):
    other stuff ...
;
```

Jegyezd meg, hogy ez csupán „szintaktikai cukor”: az `arg` név `$` nélkül is a _függvény_ scope-jában van.

## Aritás

A _függvények_ **aritása** az általuk átvett _argumentumok_ száma.

A _függvények_ ugyanazt a nevet használhatják különböző _aritásokkal_.
A beépített [`range`][man-range] függvény jól mutatja ezt: a `range/1`, `range/2` és `range/3` mind létezhet egymás mellett.

Ez hasznos lehet olyan rekurzív függvények definiálásához, amelyek argumentumokon keresztül hordozzák az állapotot.
A `map`-et például _meg lehetne_ így valósítani:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## Rekurzió

A `jq` végez farokhívás-optimalizálást, de csak nulla aritású függvényeknél.

## Modulok

A `jq` modul olyan fájl, amely csak függvényeket tartalmaz.
A modulokat az [`include`][man-include] vagy az [`import`][man-import] utasítással illeszted be egy jq programba.
