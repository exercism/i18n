# Részletesen

## Részleges alkalmazás

Az Elmben minden függvény [curryzett][currying], ami azt jelenti, hogy ha úgy hívsz meg egy függvényt, hogy nem adod át az összes argumentumot, akkor az egy új függvényt ad vissza.

Ennek az eredményét [részleges alkalmazásnak][partial-application] nevezzük (ilyenkor nem adod át az összes argumentumot a függvénynek, hanem csak részlegesen alkalmazod néhányat közülük).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

A részleges alkalmazás mindig sorrendben alkalmazza az argumentumokat.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## Pipe operátor (`|>`)

Az `x |> f` pontosan ugyanaz, mint az `f x`. Konkrét példa erre, hogy a `"5" |> String.toInt` ugyanaz, mint a `String.toInt "5"`.

Ez elsőre nem hangzik túl hasznosnak, de azért nevezik [pipe operátornak][pipe-operator], mert lehetővé teszi, hogy „csővezetékbe” fűzött kódot írj.

Tegyük fel például, hogy van egy sanitize függvényünk, amely a felhasználói bemenetet egész számokká alakítja:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Átírhatjuk így:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Így elkerüljük a zárójelek használatát, és a függvények abban a sorrendben jelennek meg, ahogy alkalmazzuk őket (először a `String.trim`, aztán a `String.toInt`), ami segíti az olvashatóságot.

Van egy [fordított pipe operátor `(<|)`][reverse-pipe-operator] is.
Az `x <| f` pontosan ugyanaz, mint az `f x`.
Ez első pillantásra szintén nem tűnik túl hasznosnak, és határozottan nem használják annyit, mint a pipe operátort, de bizonyos helyzetekben segít elkerülni a zárójeleket.

## Függvénykompozíció / point-free stílus

A [`(>>)`][forward-composition] operátor típusa `(a -> b) -> (b -> c) -> (a -> c)`, és két kompatibilis, `a -> b `, illetve `b -> c` típusú függvény összefűzésével egy `a -> c` típusú függvényt hoz létre.
Ezt úgy éri el, hogy az első függvény kimenetét (amely `b` típusú) a második függvény első argumentumaként használja (amelynek ugyanilyen `b` típusúnak kell lennie).
A létrehozott függvény ugyanazt a bemenetet veszi át (amely `a` típusú), mint az első függvény, és azt a `c`-t adja vissza, amit a második függvény visszaad.

Konkrét példa a `String.trim >> String.toInt`.
A `String.trim` egyetlen paramétere egy string, tehát a létrehozott függvény is ezt veszi át.
A `String.toInt` egy `Maybe Int` értéket ad vissza, tehát a létrehozott függvény is ezt adja vissza.
A `String.trim` egy `String` értéket ad vissza, amelyet a `String.toInt` paraméterként elfogad, így a példa lefordul.

Most már így írhatjuk át a `sanitize` függvényünket:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Figyeld meg, hogy már nem használjuk az `input` paramétert, amelyet az eredeti példában láthatsz, pedig a működés ugyanaz.
Az így, a paramétereikre nem hivatkozó függvények létrehozásának módját „point-free stílusnak” nevezik.
Ennek a stílusnak az előnye, hogy a kód tömörebb, a hátránya, hogy nehezebben érthető, különösen kezdők számára.

Érdemes megjegyezni, hogy az Elmben minden függvény curryzett, ezért a `String.length >> max` lefordul, és a következőt eredményezi:

- Egy függvény (1), amelynek egy string paramétere van (a `String.length` bemenete)
- A `max` egy két `Int` paraméterrel rendelkező függvény, de az 1. függvény egyetlen `Int`-et ad át neki (a `String.length` visszatérési értékét), így a `max` részlegesen alkalmazott lesz.
- A részlegesen alkalmazott `max` függvény visszatérési értéke egy másik függvény (2), amely egy `Int`-et vesz át, és visszaadja az átvett `Int` és a `String.length`-ből részlegesen alkalmazott `Int` közül a nagyobbat.
- Ezért az 1. függvény (`String -> Int`) a 2. függvényt (`Int -> Int`) adja vissza.
- Tehát a `((String.length >> max) "123") 2` értéke `3`, mert a `"123"` hossza 3, ami nagyobb, mint az `Int` argumentumból származó 2.

## Függvénytervezés

Ahhoz, hogy könnyen tudj elegáns kódot írni Elmben, a fő adatszerkezetet tedd a függvények utolsó paraméterévé.
A standard könyvtár összes gyakori függvénye ezt teszi, például a `List.map` is (típus aláírása lent).

```elm
map : (a -> b) -> List a -> List b
```

Itt láthatjuk, hogy a `map` függvény utolsó paramétere a `List a`, és `List b`-t ad vissza, tehát a fő adatszerkezet (a `List`) az utolsó paraméter.

Ez teszi lehetővé, hogy elegáns, csővezetékbe fűzött kódot írj, például így:

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Az is kényelmesebbé válik tőle, hogy függvénykompozíciót és point-free stílust használj a csővezetékbe fűzés alternatívájaként.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

A függvénykompozícióval ezt a példát le is egyszerűsítheted egyetlen `List.map` hívásra.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
