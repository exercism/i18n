# Névjegy

A Ruby dinamikus és erősen típusos nyelv.
A dinamikus nyelvekben egy változó vagy objektum típusa futásidőben dől el, ami azt jelenti, hogy az értéke vagy a típusa egészen az utolsó pillanatig megváltozhat (amikor az értelmező feldolgozza).
És mit értünk azon, hogy erősen típusos?
Amint ismerjük egy változó vagy objektum típusát, a Ruby szigorúan megszabja, hogy mit tehetsz vele, például:

```ruby
x = '2'
y = x + 'n'
# => '2n'
```

**De**

```ruby
x = '2'
y = x + 2
# => TypeError (no implicit conversion of Integer into String)
```

Ne feledd, a Rubyban minden objektum.
Még az osztályok is a `Class` osztály példányai.

Például:

```ruby
1.class
# => Integer

Integer.is_a?(Object)
# => true

Class.is_a?(Object)
# => true
```

Ez azt jelenti, hogy így is definiálhatunk osztályokat:

```ruby
Car = Class.new do
  def run
    'running'
  end
end

Car.new.run
# => 'running'
```

Végül tartsd észben, hogy az `Integer` objektum olyan értékeket tárol, amelyek egy vagy több (egymást követő) számjegyből állnak, és a metódusai a [matematikai operátorok][integers-docs] közül sokat támogatnak.

[integers-docs]: https://docs.ruby-lang.org/en/master/Integer.html

~~~~exercism/note
A dokumentációkban gyakran előfordul, hogy a példánymetódusokra olyan szintaxissal hivatkoznak, mint a `Class#method_name`, az osztály- vagy modulszintű metódusokra pedig `Class::method_name` formában.
A `::` neve _Scope Resolution Operator_, és arra az osztály- vagy modulszintű állandóra vagy metódusra utal, amelyre a hivatkozás irányul.
Ezzel a Ruby dokumentációjában, a levelezőlistákon és más támogatási felületeken találkozhatsz.
Azt viszont látni fogod, hogy az írásainkban mi inkább `ClassName.method_name` vagy `ModuleName.method_name` formában hivatkozunk az osztály- és modulszintű metódusokra.
~~~~
