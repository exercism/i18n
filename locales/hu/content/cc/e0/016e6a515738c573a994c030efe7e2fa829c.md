# Részletek

A C# `struct`-ok szorosan kapcsolódnak a `class`-okhoz.
Van állapotuk és viselkedésük.
Ugyanolyan típusú tagjaik lehetnek: konstruktorok, metódusok, mezők, tulajdonságok stb.

A mezők és tulajdonságok lehetnek egyszerű típusok, `struct`-ok vagy referenciatípusok.
A `struct`-ok ugyanazokat a szabályokat követik a scope, az olvasási/írási szabályok és a hozzáférési szintek tekintetében, mint a `class`-ok.

```csharp
enum Unit
{
    Kg,
    Lb
}

struct Weight
{
    private double count;
    private Unit unit;

    public Weight(double count, Unit unit)
    {
        this.count = count;
        this.unit = unit;
    }

    public override string ToString()
    {
        return count.ToString() + unit.ToString();
    }
}

new Weight(77.5, Unit.Kg).ToString();
// => "77.6Kg"
```

Az egyik legfontosabb dolog, amit érdemes megjegyezni, hogy amikor egy `struct`-ot értékül adunk egy változónak, vagy paraméterként adunk át, az értékek átmásolódnak, így az eredeti változó módosításai nem befolyásolják a másolatot, és fordítva.
Összefoglalva, a `struct`-ok **értéktípusok**.

Ez a [cikk][class-or-struct] a `struct`-ok és a `class`-ok közötti különbségeket tárgyalja.
A cikkből láthatod, hogy a `struct`-ok általában könnyűsúlyúak és [változtathatatlanok][structs-immutable], bár ezt az útmutatást a fordító vagy a futtatókörnyezet (alapértelmezés szerint) nem kényszeríti ki.

Van néhány dolog, amivel szembesülni fogsz (és amire a fordító is emlékeztetni fog):

1. A `struct`-ok tagjait nem lehet a deklaráció helyén inicializálni.
2. A `struct` nem örökölhető.
3. A `struct` mindig rendelkezik alapértelmezett konstruktorral, még akkor is, ha meg van adva nem alapértelmezett konstruktor, és nem adhatsz meg explicit paraméter nélküli konstruktort.

Az 1. és 3. pont következményeként a `struct` fejlesztője semmilyen módon nem tudja megakadályozni, hogy érvénytelen példányok jöjjenek létre.

## Gyakori structok

A dokumentációból láthatod, hogy szoros kapcsolat van a primitívek és a structok között.
Erre példa a [`Int32/int`][int32].
A `struct`-ra egy hagyományosabb példa a [`TimeSpan`][time-span] típus.

A `TimeSpan` példányai nagyon hasonlítanak a számokhoz: rendelkeznek összehasonlító operátorokkal, például `>` és `<`, valamint aritmetikai operátorokkal.
Ezeket az operátorokat a saját `struct`-jaidhoz is implementálhatod, amikor szükséged van rájuk.

A `TimeSpan` kapcsán érdemes megjegyezni, hogy számos interfészt implementál, például az `IComparable<TimeSpan>` interfészt.
Bár a `struct`-ok nem származtathatók más `struct`-okból, interfészeket implementálhatnak.

## Egyenlőség

A `struct`-ok egyenlőségvizsgálata gyakran sokkal egyszerűbb lehet, mint a `class`-oké, mert alapértelmezés szerint egyszerűen csak a mezőket hasonlítja össze egyenlőség szempontjából.
Nem kell felülírni az `object.Equals()` metódust (vagy a `GetHashCode()` metódust).
Ne feledd, hogy ha a `Object.GetHashCode()` metódusra támaszkodsz, akkor is biztosítanod kell, hogy a hashkód előállításában részt vevő mezők (azaz az összes mező) ne változzanak meg, amíg egy hash-alapú gyűjteményt használsz.
Ez gyakorlatilag azt jelenti, hogy az így használt structoknak változtathatatlannak kell lenniük.

Az `Equals()` metódussal ellentétben az egyenlőségoperátoroknak, a `==` és `!=` operátoroknak nincs alapértelmezett implementációja.
Ha a `struct`-odnak szüksége van rájuk, akkor neked kell implementálnod őket.

Másrészt ez a [cikk][equality] leírja, hogyan optimalizálható a teljesítmény saját egyedi `Equals()` és `GetHashCode()` metódusok létrehozásával, ahogy azt a `class`-oknál is gyakran teszik.
Ennek a feladatnak az esetében a különbség körülbelül 20% volt egy nem túl szigorú összehasonlításban, de ez alulbecsülheti a valóságot, mert az összes mező azonos típusú (lásd alább).

A [web][equality-performance]en vannak beszélgetések a sebességnövelésről, amikor az `Equals()` metódust nem írják felül, ha minden mező azonos típusú.
Ebben a feladatban a különböző típusú mezők bevonásával a különbség körülbelül 60% volt.
Ez nem szerepel a Microsoft dokumentációjában, így ez egy nem dokumentált implementációs részlet, és csak megfontoltan érdemes kihasználni.

```csharp
public bool Equals(Weight other)
{
    return count.Equals(other.count) && unit.Equals(other.unit);
}

public override bool Equals(object obj)
{
    return obj is Weight other && Equals(other);
}

public override int GetHashCode()
{
    return HashCode.Combine(count, unit);
}
```
