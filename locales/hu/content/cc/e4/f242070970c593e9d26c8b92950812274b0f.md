# Bemutatás

A programozási feladat a paraméterek számos tulajdonságát szemlélteti:

- A módosító (például `out` vagy `ref`) nélkül [átadott][passing-parameters] paraméterek érték szerint adódnak át. Ez azt jelenti, hogy a paraméter a hívott metódusban használható és értéket adhatsz neki, de a módosításoknak nem lesz hatásuk a hívóra.
- Ha egy tömb vagy egy osztálypéldány referenciája paraméter, akkor a hívott metódus módosíthatja az adott példány elemeit/mezőit, és a változásokat a hívó is látni fogja. Ez függetlenül attól érvényes, hogy jelen van-e a `ref` módosító.
- A `out` módosítóval ellátott paraméter a hívott metódusból a hívó felé közvetít vissza egy értéket. A paraméter kezdőérték nélkül is átadható a hívott metódusnak, és a hívott metódus belépéskor mindenképpen úgy kezeli, mintha nem kapott volna kezdőértéket. A paramétermódosítók viselkedését és szabályait a legkönnyebben példákon (lásd lent) és a fordító üzenetein keresztül értheted meg.

```csharp
void Foo(out int val)
{
    val = 42;
}
void Bar(int val)
{
    val = 42;
}

int importantValue = 1729;
Foo(out importantValue);
var result = importantValue == 42;
// => true

importantValue = 1729;
Bar(importantValue);
result = importantValue == 1729;
// => true
```

- Az `out` paramétereknek a hívott metóduson belül értéket kell kapniuk.

- A `ref` módosítóval ellátott paraméter értéket ad át a hívott metódusnak. Amikor a metódus visszatér, a hívó a hívott metódus minden módosítását megtalálja ebben a paraméterben.

```csharp
void Foo(ref int val)
{
    val *= 7;
}

int importantValue = 6;
Foo(ref importantValue);
return importantValue;
// => 42
```

- A `ref` paramétereknek változóknak kell lenniük, mivel a hívott metódus közvetlenül azon a paraméteren fog dolgozni, ahogyan a hívó látja.

- Az `out` és a `ref` módosítóra egyaránt szükség van a hívott metódus szignatúrájában és a hívás helyén is.
- Az `out` paraméterek a hívás helyén is deklarálhatók, így: `Foo(out int importantValue);`
- Ha olyan metódust hívsz, amelynek `out` paraméterei vannak, de nem érdekel az egyik vagy több ilyen paraméternek adott érték, akkor használhatod az [eldobó][discard] álváltozót, a `_`-t, például így: `Foo(out int _);`

A `ref` és `out` paraméterekre vonatkozó összes szabályt a fordító kényszeríti ki.

Léteznek `in` paraméterek is, de ezek elsősorban teljesítményoptimalizálást szolgálnak, és a `structs` feladatban tárgyaljuk őket, ahol a leginkább relevánsak.

A fent hivatkozott dokumentáció összefoglalása:

- [paraméterátadás][passing-parameters]: elmagyarázza, hogyan adhatók át az értékek argumentumként. Vedd figyelembe, hogy a structok és a paraméterek témáját a `structs` feladat tárgyalja.
- [ref-paraméter][ref-parameter]: leírja, hogyan működnek a `ref` paraméterek.
- [out-paraméter][out-parameter]: leírja, hogyan működnek az `out` paraméterek.

A dokumentáció tanulmányozása során vedd figyelembe, hogy a következő kifejezéseket használja:

- paraméter / formális paraméter: arra a paraméterre utal, ahogyan a hívott metódus látja.
- argumentum: arra a paraméterre utal, ahogyan a hívó látja.

[Vitathatóan][so-tuples-vs-out] az `out` paraméterek értékének nagy része elveszett a C# 7-ben megjelent `tuples` bevezetésével. A `tuples` feladat bemutatja, hogyan használhatók a `tuples`-ek több érték visszaadására.

Bár a `ref` könnyen használható és nincs teljesítménybeli hátránya, érdemes megnézni, hogyan kezelik egy adott kódbázisban azokat a problémákat, amelyeket megold, mielőtt széles körben alkalmaznád. Vannak alternatívák, például érték szerint átadni, majd a hívott metódus visszatérési értékét felhasználni. Itt is szerepet kaphatnak a `tuples`-ek.

A [dokumentációból][ref-parameter] látni fogod, hogy az `out` és a `ref` bizonyos helyzetekben nem használható, de ezeket egyelőre figyelmen kívül hagyhatod. A fordító jelezni fogja, amikor ilyen helyzet adódik.

Vedd figyelembe, hogy az `optional parameters` és a `named arguments` a `method-overloading` feladatban kerül szóba.

A kapcsolódó [`ref local`][ref-local] és [`ref return`][ref-return] témákat máshol tárgyaljuk.

## Veremfoglalások

A paraméterekre és módosítóikra vonatkozó szabályok elég egyszerűek ahhoz, hogy készpénznek vedd őket, és az absztrakció szintjén megértsd őket. Ha azonban érdekelnek a mögöttes mechanizmusok, és hogy ezek a kulcsszavak miért okozhatnak teljesítménykülönbséget, legalábbis `struct`-ok esetében, akkor kezdheted ezzel a [_Wikipédia-szócikkel_][calling-conventions], megjegyezve, hogy a C# a `stdcall`-t használja x86/64-en.

A lényeg az, hogy módosító nélküli paraméterek esetében a változó **értéke** másolódik a program veremtárába, hogy elérhető legyen a hívott rutin számára, míg a `ref`, `out` és `in` paraméterek esetében egy, az értéket tartalmazó memóriára mutató pointer (**referencia**) kerül a program veremtárába, és az értékek a referencia által mutatott memóriába íródnak.
