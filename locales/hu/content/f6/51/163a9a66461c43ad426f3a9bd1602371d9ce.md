# A Unison alapjai

## Terminusok és függvények

A terminusok és a függvények egy Unison-program írásának alapegységei.

A terminus az, amit statikus értéknek nevezünk. A definíciója `name = expression`, amit opcionálisan megelőzhet egy `name : MyType` alakú típusszignatúra. A Unison támogatja a típuskövetkeztetést, így egyszerű definíciók esetén elmaradhat a típusszignatúra.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

A Unison-függvények így néznek ki: `myFunctionName argument1 argument2 = myImplementation`; a függvény nevével kezdődnek, amelyet szóközzel elválasztott argumentumok követnek.

```
getMax a b = Nat.max a b
```

A függvényeknél opcionálisan megadhatsz típusszignatúrát is. A jobb oldalon álló utolsó típus mindig a függvény végső visszatérési típusa, az egyes argumentumokat pedig a függvénynyíl `->` választja el.

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Egy függvény meghívásához írd le a nevét, majd utána az argumentumait, amelyeket csak szóközök választanak el.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Amikor meghívsz egy függvényt, a Unison mindent megpróbál argumentumként kezelni, ami közvetlenül jobbra következik, ez pedig nem mindig adja a függvénykiértékelés kívánt sorrendjét.

Tegyük fel, hogy az `1` értéket szeretnénk megkapni a következő kifejezésből

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

Ahogy le van írva, a `shouldBe1` értéke `0` lesz, mert a hallgatólagos függvényalkalmazási sorrend a `getMax 1 10`, ami `10`, majd a `10 - 10`, ami `0`.

Zárójelekkel újracsoportosíthatod a kifejezést a kívánt műveleti sorrend szerint.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Figyelő kifejezések

A Unison egy „figyelő kifejezés” nevű lehetőséget kínál a kód gyors kiértékelésére. A figyelő kifejezés egy `>` szimbólummal kezdődik, amit a kiértékelendő kifejezés követ. Figyelő kifejezést bármely `.u` kiterjesztésű fájlba írhatsz. A fájl mentése után a Unison Codebase Manager (UCM) konzoljában látni fogod, hogy mire értékelődik ki a kifejezés. Ahol ebben a dokumentációban lehet, igyekszünk a kifejezést a figyelő kifejezésben való kiértékelés utáni várható kimenetével együtt megmutatni.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Többsoros függvények

A Unison többsoros függvényei behúzással vagy `let` blokkokkal jelölik ki a kódhatárokat, más néven a „lexical scope”-ot.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Minden, ami ugyanazon a behúzási szinten van, ugyanahhoz a scope-hoz tartozik, ezért hivatkozhatunk az utolsó sorban a `newBeginning` változóra.

## Névterek és `use` utasítások

A névterek segítségével csoportosítjuk és rendszerezzük a Unison-függvényeket. Gondolhatsz rájuk úgy, mint a „könyvtárakra”. Struktúrát és logikai csoportosítást adnak.

A `use` utasítással egy névtér függvényeit hozhatod be a scope-ba.

Tegyük fel, hogy olyan függvényt írsz, amely Unison `List` értékeket használ. Tudod, hogy szükséged lesz olyan függvényekre, mint a `List.map` és a `List.flatMap`, ahol a `List` a névtér, a `map` és a `flatMap` pedig függvények. Hogy ne ismételd magadat, behozhatod a `List` névtér minden elemét a függvényed lexikai scope-jába, így:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

A `use List` sor teszi egyértelművé a `map` és a `flatMap` hivatkozásait. A [`use` utasításokról itt olvashatsz bővebben][use-statements].

## A Unison szabványos könyvtára

A Unison szabványos könyvtárát `base`-nek hívják. Ha követted a quickstart útmutatót, és van egy helyben létrehozott kódbázisod, akkor a szabványos könyvtár valószínűleg automatikusan letöltődött. A szabványos könyvtár dokumentációját online böngészheted a [Unison Share][unison-share-base] oldalon.

## Megjegyzések és dokumentációs literálok

A megjegyzések a Unisonban kicsit szokatlan jelenségnek számítanak. Amikor Unison-kódot írsz, a `.u` kiterjesztésű fájlodban olyan szöveget hozhatsz létre, amelyet nem értelmez a rendszer, a következő szintaxissal:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Azonban_ mivel a Unison-kód az absztrakt szintaxisfájának hash-eként kerül mentésre, nem pedig szövegalapú fájlként a fájlrendszerben, azokat a megjegyzéseket, amelyek egy adott Unison-függvény vagy terminus szövegalapú „díszítései” a fájlban, valójában nem lehet elmenteni és újra megjeleníteni megosztás céljából. Ha szeretnél információt hozzáadni a Unison-terminusodhoz úgy, hogy az eltárolódjon, és mások elolvashassák és megérthessék, használhatsz dokumentációs literált.

A dokumentáció első osztályú érték a Unison programozási nyelvben. Ez azt jelenti, hogy egy `Doc` elem hozzárendelhető egy értékhez, átadható értékként egy függvénynek, vagy visszaadható a függvény értékeként. A dokumentációs literál elemeket dupla kapcsos zárójel nyitja és zárja. Így használhatnánk a `Doc` elemet megjegyzésként.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
