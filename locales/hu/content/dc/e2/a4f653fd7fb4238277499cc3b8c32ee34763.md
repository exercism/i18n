# Kiegészítés az utasításokhoz

## A feladat

Két eljárást kell megvalósítanod.

- A `custom_error_message message` hibát vált ki, és a `message` lesz a hibaüzenet.
- A `handle_error script` lefuttatja a kapott szkriptet, és egy stringet ad vissza arról, hogy mi történt:

  | Amikor a szkript…                  | visszatérési érték   |
  | --------------------------------- | -------------------- |
  | nullával oszt                     | `"division by zero"`    |
  | nem létező fájlt nyit meg         | `"file does not exist"` |
  | nem létező procot hív meg         | `"proc does not exist"` |
  | bármilyen más hibát vált ki       | `"unknown error"`       |
  | sikeresen lefut                   | `"success"`             |

## Hibák kiváltása

A Tcl két parancsot kínál hiba kiváltására.

```tcl
error "something went wrong"
throw {MYAPP BADTHING} "something went wrong"
```

A `throw` első argumentumaként egy _hibakódot_ vár.
A hibakód egy lista, ami megmondja a kezelőnek, milyen fajta hiba történt, így az az üzenet szövegének elemzése nélkül is tud reagálni.
A tartalma rajtad áll: a `{MYAPP BADTHING}` csak egy példa, bármilyen nem üres lista megteszi.
A szokás szerint az általánostól halad a konkrét felé.
Egy kezelő egy illeszkedő `try ... trap` mintával kapja el (erről alább lesz szó), például `trap {MYAPP BADTHING}`, vagy `trap {MYAPP}`, ha minden `MYAPP` hibát el akarsz kapni.
Az `error` opcionális hibakódot is kaphat harmadik argumentumaként: `error message ?info? ?code?`.

## Hibák kezelése `catch`-csel

A [`catch`][catch] lefuttat egy szkriptet, és a hiba kiváltása helyett egy egész _befejezési kódot_ ad vissza:

| kód | jelentés    |
| ---- | ---------- |
| 0    | `ok`       |
| 1    | `error`    |
| 2    | `return`   |
| 3    | `break`    |
| 4    | `continue` |

```tcl
if {[catch {expr {1 / 0}} result options] == 1} {
    puts "error message: $result"
    puts "error code:    [dict get $options -errorcode]"
}
```
```none
error message: divide by zero
error code:    ARITH DIVZERO {divide by zero}
```

Az opcionális második argumentum kapja meg az eredményt (vagy a hibaüzenetet).
Az opcionális harmadik argumentum egy _opciószótárt_ kap, amelyben ott van a `-errorcode` és a `-errorinfo` (a veremkiírás).

Előnyök:

- Kicsi és rugalmas.
- Egyszerű esetekben rövid, például `if {[catch {open $f} fh]} {...}`.

Hátrányok:

- Neked kell ellenőrizned a befejezési kódot.
  Egy figyelmetlen `if {[catch ...] != 0} { handle error }` a `return`, a `break` és a `continue` befejezési kódot is hibaként kezeli.
- A nem kezelt hibák eltűnnek, hacsak magad újra ki nem váltod őket.
- Nincs beépített mód arra, hogy akár hibázott a szkript, akár nem, lefuttass egy takarító kódot.

## Hibák kezelése `try`-jal

A [`try`][try] lefuttat egy szkriptet, és az eredményt az első illeszkedő kezelőhöz küldi.
Egy opcionális `finally` ág mindig lefut, így jó hely az olyan erőforrások felszabadítására, mint a fájlcsatornák.

```tcl
set fh [open $filename r]
try {
    set data [read $fh]
} on error {msg options} {
    puts "could not read $filename: $msg"
} finally {
    close $fh
}
```

Előnyök:

- Áttekinthető a szerkezet: minden kimenetfajtához egy kezelő.
- A `finally` mindig lefut.
- A kezelő nélkül maradt kimenetek változatlanul továbbkerülnek a hívóhoz.

Hátrányok:

- Egyszerű esetekben kicsit bőbeszédűbb a `catch`-nél.

### `try ... on` kontra `try ... trap`

Kétféle kezelő létezik.

Az `on code {msgVar optionsVar}` a _befejezési kódra_ illeszkedik: `ok`, `error`, `return`, `break` vagy `continue`.
Minden hiba befejezési kódja `error`, így az `on error` nem tud különbséget tenni a nullával osztás és egy hiányzó fájl között.
Az üzenet szövegét kellene vizsgálnod, ami törékeny megoldás: az üzenetek az embereknek szólnak, és Tcl-verziók között változhatnak.

```tcl
try {
    expr {$a / $b}
} on error {msg} {
    if {[string match "*divide by zero*" $msg]} { ... }
}
```

A `trap pattern {msgVar optionsVar}` a _hibakódra_ illeszkedik.
A kezelő akkor illeszkedik, ha a minta a `-errorcode` lista előtagja.
Így megbízhatóan kiszűrhető a hiba fajtája.

```tcl
try {
    expr {$a / $b}
} trap {ARITH DIVZERO} {} {
    puts "division by zero"
} trap {} {msg} {
    puts "some other error: $msg"
}
```

Az üres minta, a `trap {}`, minden hibára illeszkedik.
A kezelőket sorrendben ellenőrzi a rendszer, ezért a mindent elkapó kezelőt tedd a végére.

## A hibakód megkeresése

Hol van dokumentálva az `ARITH DIVZERO`?
Többnyire csak a forráskódban, de a Tcl megmutatja neked.
Hiba után a globális `errorCode` változóban van a legutóbbi hiba hibakódja:

```none
$ tclsh
% set a 1; set b 0
% expr {$a / $b}
divide by zero
% set errorInfo     ;# this is the stack trace
divide by zero
    while executing
"expr {$a / $b}"
% set errorCode     ;# this is what we're after
ARITH DIVZERO {divide by zero}
```

Programon belül az opciószótárból kérdezheted le:

```tcl
try {
    expr {$a / $b}
} on error {msg options} {
    puts [dict get $options -errorcode]
}
```

A hibakód utolsó eleme gyakran egy ember által olvasható üzenet, vagy a hibát okozó dolog neve.
Hagyd ki a `trap` mintádból: a `{ARITH DIVZERO}` mintát használd, ne a `{ARITH DIVZERO {divide by zero}}` mintát.

### Néhány gyakori hibakód

A táblázat nem teljes.
A fenti módszerrel keresd meg bármely más hiba kódját.

| Helyzet               | Példa                    | Hibakód                       |
| --------------------- | ------------------------ | ----------------------------- |
| Nullával osztás       | `expr {1 / 0}`           | `ARITH DIVZERO ...`           |
| Matematikai értelmezési tartomány hiba | `expr {sqrt(-1)}` | `ARITH DOMAIN ...`            |
| Fájl nem található    | `open nosuchfile r`      | `POSIX ENOENT ...`            |
| Hozzáférés megtagadva | `open /root/x w`         | `POSIX EACCES ...`            |
| Ismeretlen parancs    | `no::such::proc`         | `TCL LOOKUP COMMAND name`     |
| Ismeretlen változó    | `set nosuchvar`          | `TCL LOOKUP VARNAME name`     |
| Rossz számú argumentum | `string length a b`     | `TCL WRONGARGS`               |
| Érvénytelen szótár    | `dict size {1 2 3}`      | `TCL VALUE DICTIONARY`        |
| Érvénytelen lista     | `llength "a \{b"`        | `TCL VALUE LIST ...`          |

A `POSIX` hibakódok az operációs rendszer `errno` neveit használják, például `ENOENT`, `EACCES` és `EEXIST`.

## Tipp: hol fut a szkript

A `handle_error` a hívójától kap egy szkriptet.
Ha `try $script` formában futtatod, akkor a `handle_error` scope-jában értékelődik ki, nem a hívóéban.
Ahhoz, hogy ott értékelődjön ki, ahol megírták, használd az [`uplevel`][uplevel] parancsot: `try {uplevel 1 $script} ...`.
