# Bevezetés

A Go 1.18-ban jelent meg a **generikusok** támogatása.
A generikusok segítségével olyan függvényeket és adatszerkezeteket írhatsz, amelyek különböző típusokkal működnek, anélkül hogy duplikálnád a kódot.

## Miért használjunk generikusokat?

A Go-ban a függvények és a típusok általában konkrét típusokkal dolgoznak, például `int`-tel vagy `string`-gel.
A generikusok megjelenése előtt két lehetőséged volt arra, hogy több típust támogass.
Először is írhattál több függvényt különböző névvel, például `SumInts` és `SumFloats` néven.
Ez a megközelítés duplikált kódot eredményez, amit nehéz karbantartani.
Másodszor használhattad az üres interfészt, az `any`-t (`interface{}`).
Az üres interfész viszont megszünteti a fordítás idejű típusellenőrzéseket, és futásidőben típusállításokat tesz szükségessé.
A generikusok úgy oldják meg ezt a problémát, hogy típusbiztonságot nyújtanak, miközben elkerülik a duplikált kódot.

## Generikus függvények

Egy generikus függvényt úgy hozol létre, hogy a függvény neve után szögletes zárójelben `[...]` **típusparamétereket** adsz meg.
Íme egy példa egy generikus függvényre, amely egy megfordított szeletet ad vissza:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

Ebben a példában `T` egy típusparaméter.
A `T`-re gondolhatsz úgy, mint egy valódi típus helyőrzőjére.
A szögletes zárójelben lévő `any` kulcsszó egy **típusmegkötés**.
A megkötés megmondja a fordítónak, milyen típusok engedélyezettek a `T` számára.
Itt az `any` azt jelenti, hogy `T` bármilyen típus lehet.

### Generikus függvények meghívása

Egy generikus függvényt úgy hívhatsz meg, hogy szögletes zárójelben átadod a konkrét típust.
Ezt a konkrét típust **típusargumentumnak** nevezzük.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

A legtöbb esetben a Go fordítója automatikusan felismeri a típust a függvény argumentumaiból.
Ezt a funkciót **típuskikövetkeztetésnek** nevezzük.
A típuskikövetkeztetésnek köszönhetően nem kell kiírnod a típusargumentumot szögletes zárójelben.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

Ebben a példában a fordító látja, hogy a `words` stringek szelete, így kikövetkezteti, hogy `T` a `string`.

## Típusmegkötések

Minden típusparaméterhez kell tartoznia megkötésnek.
A megkötés meghatározza, mely típusokat használhatod típusargumentumként.
A megkötés azt is meghatározza, milyen műveleteket végezhetsz el az adott típusú értékeken.

### Az `any` megkötés

Az `any` megkötés bármilyen típust engedélyez.
A Go-ban az `any` az üres interfész, az `interface{}` álneve.
Mivel az `any` minden típust engedélyez, a függvény csak olyan műveleteket végezhet, amelyek minden Go-típuson működnek.
Ha például két `any` értéked van, amelyek szeletet tartalmaznak, azokat nem hasonlíthatod össze `==`-val, mert a szeleteket nem lehet `==`-val összehasonlítani.

### A `comparable` megkötés

A Go beépített megkötést kínál `comparable` néven.
A `comparable` megkötés minden olyan típust engedélyez, amely támogatja az `==` és a `!=` operátort.
Összehasonlítható típusok például a Boolean-ok, a számok, a stringek, a pointerek, a csatornák, valamint az összehasonlítható típusokból álló struktúrák és tömbök.

Íme egy példa egy olyan függvényre, amely ellenőrzi, hogy egy szelet tartalmaz-e egy adott elemet:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

Mivel `T` a `comparable` megkötést használja, az `elem == target` összehasonlítás érvényes.
Ha a `comparable`-t `any`-re cseréled, a fordító hibát jelez.

### Egyedi megkötések interfész típushalmazokkal

A Go 1.18-tól kezdve az interfészek a metódusok mellett típushalmazokat is definiálhatnak.
Az engedélyezett típusokat egy interfészben a függőleges vonal (`|`) karakterrel sorolhatod fel.

```go
type Number interface {
    int | int64 | float64
}
```

Most már használhatod a `Number`-t megkötésként egy függvényhez:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

Mivel a `Number`-ben szereplő összes típus támogatja a `*` operátort, a Go engedélyezi a `value * 2` kifejezést a függvényen belül.

### A mögöttes típus közelítése `~`

Néha egy primitív típusra épülő egyedi típusdefiníciót hozol létre:

```go
type MyInt int
```

A fent definiált `Number` megkötés csak a pontos `int`, `int64` és `float64` típusokat engedélyezi.
Ha egy `MyInt` értéket adsz át a `Double`-nak, a fordító hibát jelez, mert a `MyInt` nem egyezik az `int`-tel.
Ha minden olyan típust engedélyezni szeretnél, amelynek a mögöttes típusa `int`, írj egy hullámjelet (`~`) a típus elé:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

Most már használhatod a `Double`-t `MyInt` típusú értékekkel.

### A `cmp.Ordered` megkötés

A standard könyvtár a `cmp.Ordered` megkötést a [`cmp` csomagban][doc-cmp] biztosítja.
A `cmp.Ordered` megkötés minden olyan típust engedélyez, amely támogatja a `<`, `<=`, `>` és `>=` összehasonlító operátorokat.

## Generikus típusok

Típusparaméterekkel generikus típusokat is definiálhatsz, például struktúrákat.
Íme egy példa egy generikus `Stack` adatszerkezetre:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

Amikor egy generikus típusú változót deklarálsz, meg kell adnod a típusargumentumot szögletes zárójelben:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

A típuskikövetkeztetés csak generikus függvényeknél működik.
Generikus típusú értékek létrehozásakor mindig meg kell adnod a típusargumentumot.

## Mikor használjunk generikusokat

A generikusok hatékony eszköz, de nem kell minden problémánál használnod őket.

Ezekben a helyzetekben használj generikusokat:
- Olyan adatszerkezeteket építesz, mint a fák, a láncolt listák vagy a gyorsítótárak, amelyek bármilyen elemtípussal működnek.
- Olyan segédfüggvényeket írsz, amelyek bármilyen típusú szeleten vagy mapen működnek, például szűrés, rendezés vagy keresés.
- Több típushoz pontosan ugyanarra a megvalósításra van szükséged, és fordítás idejű típusbiztonságot szeretnél.

Ezekben a helyzetekben inkább interfészeket használj:
- A viselkedés és a metódusok fontosak számodra, nem a mögöttes adattípus.
  Ha például különböző típusú forrásokból (fájlokból, hálózatról, TTY-ról) szeretnél adatot olvasni és feldolgozni, a `func Process(src io.Reader)` megoldást választanád a `func Process[T](src T)` helyett.
- A különböző típusoknak különböző metódusmegvalósításokra van szükségük a feladatuk elvégzéséhez.
