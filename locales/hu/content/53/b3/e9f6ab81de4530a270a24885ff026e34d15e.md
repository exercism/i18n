# Bevezetés

## Null-referenciák

Ha valaha használtál más programozási nyelvet (C/C++, Python, Java, Ruby, Lisp stb.), valószínűleg már találkoztál a `null` vagy a `nil` értékkel.
Ezekben a nyelvekben a `null` vagy a `nil` jelzi, hogy egy adott változónak nincs értéke.
Ez viszont könnyűvé (és gyakorivá) teszi azt a hibát, hogy véletlenül olyan változót használunk, amely `null`-ra mutat.
Ahogy sejtheted, ha megpróbálunk meghívni egy nem létező függvényt, vagy hozzáférni egy nem létező értékhez, abból mindenféle bug és összeomlás származhat.
A `null` megalkotója odáig ment, hogy [„egymilliárd dolláros tévedésének”.](https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/) nevezte.

## Az `Option` típus

Ezen problémák elkerülésére a Rust nem használ null-referenciákat.
Mégis szüksége van egy biztonságos módra annak jelzésére, hogy egy adott változónak nincs értéke.
Itt jön képbe az `Option`.
Ahelyett, hogy olyan változónk lenne, amelynek nincs értéke, a Rust változói használhatják az `Option` enumot.
Ennek az enumnak két változata van: a `None`, a Rust null-megfelelője; és a `Some(T)`, ahol a T bármilyen típusú érték.

Így néz ki:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

Az `Option`-ra úgy gondolhatsz, mint egy biztonsági rétegre közted és a null-referenciák okozta problémák között, miközben megőrzi azok fogalmi hasznosságát.

## Az `Option` használata

Egy változót `None`-ra állítani meglehetősen egyszerű:

```rust
let nothing: Option<u32> = None;  // Variable nothing is set to None
```

Ha viszont szeretnéd, hogy az `Option` típus értéket hordozzon, nem rendelhetsz hozzá értéket közvetlenül.
Egy `Option` típusú változó és mondjuk egy `i32` típusú változó nem egyenértékű.
A `Some`-ot kell használnod:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Some(-4); // This will work
let another_right_way = Some(-4); // Compiler infers that this is Option<i32>
```

Ugyanezen okból a következő sem fog működni:

```rust
let number = 47;
let option_number = Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

Ha szeretnéd megkapni a Some által tartalmazott értéket, először ellenőrizned kell, hogy létezik-e:

```rust
let mut some_words = Some("choose something to say"); // some_words set to something

match some_words {
    Some(str) => println!("Here, we will {}", str),
    None => println!("I've got nothing to say"),
} // Prints "Here, we will choose something to say"

some_words = None; // some_words now set to None

// exactly the same match block as above
match some_words {
    Some(str) => println!("Here, we will {}", str),
    None => println!("I've got nothing to say"),
} // Prints "I've got nothing to say"
```

A `match` mellett a Rust más eszközöket is kínál az `Option`-ban tárolt értékek ellenőrzésére és elérésére, de a `match`-et addigra már ismerned kell.

Mellékesen ezt tekintsd annak bemutatásaként, hogy a Rust miért használ `Option`-t null-referencia helyett.
A lényeg, hogy **ellenőrizned _kell_**, hogy az `Option` változó `Some`-e (amely esetben nyugodtan kinyerheted és felhasználhatod a benne tárolt értéket), vagy `None`.
Minden más esetben a programod nem fog lefordulni; a fordító megvéd a `null`-tól.
