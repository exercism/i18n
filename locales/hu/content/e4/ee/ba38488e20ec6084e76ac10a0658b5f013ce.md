# Bevezetés

## Karakterek

A **karakterkódolás** egy adott konvenció, amellyel egy természetes nyelv szövegelemeit bájtok sorozataként ábrázoljuk.
A „szövegelem” itt bármilyen olyan egység lehet, amelynek jelentősége van egy természetes nyelvben, például betűk, szóközök, írásjelek, emojik, ideogrammák stb.

A NASM (The Netwide Assembler, az ezen a kurzuson használt assembler) támogatja az adatok **ASCII** szerinti definiálását.

A NASM karakterkonstansai legfeljebb 8 bájt hosszúak lehetnek, és definiálhatók egyszeres idézőjelekkel (`'`), kettős idézőjelekkel (`"`) vagy backtickekkel (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

A speciális karaktereket backtickekben kell definiálni, és `\` jellel kell escape-elni:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Ne feledd, hogy az x86-64-ben nincs beépített támogatás egyetlen karakterkódolásra sem külön típusként.
Az assemblyben az adat bájtok sorozata, és az, hogy ezeket a bájtokat karakterként, számként vagy bármi másként értelmezzük, a programozóra van bízva.

Például az ASCII '0' karakter egyetlen bájt, amelynek értéke 48.
Tehát ha 48-at tárolsz egy bájtban, az pontosan ugyanaz, mint az ASCII '0' karakter tárolása:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Ugyanezért a karakterek manipulálása úgy történik, hogy közvetlenül átalakítjuk az értékeket ezekben a bájtokban:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## Stringek

A **string** karakterek sorozata.
Assemblyben általában tömbként valósítják meg.

A NASM-ben ugyanúgy deklarálhatsz stringet, ahogy bármelyik tömböt deklarálnád:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

A stringek és más tömbök között az egyik különbség, hogy a NASM támogatja a stringek olyan deklarálását is, ahol nincs vessző (`,`) az értékek között.
Az értékek közé vesszőket is be lehet iktatni:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Ne feledd, ahogy már említettük: a karakterek csak bájtok (vagy Unicode-kódolás esetén bájtok sorozata):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Mivel minden ASCII-karakter egyetlen bájtot foglal el, egy nagyobb méretnél a további bájtok mind `0` értékűek.
Például ha a `'a'` karaktert qwordként (8 bájt) deklarálod, az első bájt `'a'` (`97`), a másik hét bájt pedig mind `0`.

Ezért ezek mind egyenértékűek:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
Assemblyben a stringeket nem zárja le automatikusan egy ASCII NUL-karakter (`0` érték).

Amikor magasabb szintű nyelvekkel, például C-vel lépsz kapcsolatba, a programozó felelőssége, hogy a string végére a megfelelő lezárót (ha van ilyen) odaírja.
~~~~

## Stringutasítások

Mivel a stringek tömbök, ugyanúgy dolgozhatsz velük, mint bármelyik tömbbel, ha közvetlenül dereferálod a memóriát:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Ezen kívül vannak utasítások értékek betöltésére, mozgatására és tárolására memóriabeli bájtsorozatokban.
Bár _stringutasításoknak_ nevezik őket, a memória bármely bájtsorozatával használhatók, azaz bármely tömbbel.

A három legfontosabb stringutasítás a `lods`, a `stos` és a `movs`:

| utasítás | mit csinál |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | betölt egy értéket az `rsi` által jelzett memóriacímről az `rax` regiszterbe |
| `stos`      | eltárol egy értéket az `rax` regiszterből az `rdi` által jelzett memóriacímre |
| `movs`      | átmásol egy értéket az `rsi` által jelzett memóriacímről, és eltárolja az `rdi` által jelzett memóriacímre |

Ne feledd, hogy ezek az utasítások _nem_ vesznek fel semmilyen explicit operandust.
Az operandusaik implicit módon adottak.

Ökölszabályként:

1. Amikor a forrásoperandusuk egy memóriacím, annak címét az `rsi` regiszterben kell tárolni (`s`, mint source).
2. Amikor a céloperandusuk egy memóriacím, annak címét ehelyett az `rdi` regiszterben kell tárolni (`d`, mint destination).
3. Ha az egyik operandus nem memóriacím, akkor az az `rax` regiszter.

Ne feledd, hogy ezek az utasítások automatikusan dereferálják a memóriacímeket aszerint, hogy milyen konkrét műveletet végeznek.

Mindegyikük különböző méretekben működhet.
A méret jelzésére egy utótagot fűznek hozzá:

| utótag | jelentés | méret    |
| :----: | ------- | :------ |
|  `b`   | byte    | 1 bájt  |
|  `w`   | word    | 2 bájt |
|  `d`   | dword   | 4 bájt |
|  `q`   | qword   | 8 bájt |

Például:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

A művelet méretével frissítik az érintett címeket is.
Ez a frissítés a **direction flag (DF)** értékétől függ:

- Ha a `DF` törölve van, a címek a művelet méretével _növekednek_.
- Ha a `DF` be van állítva, a címek ehelyett ugyanennyivel _csökkennek_.

A System V ABI szerint a direction flaget a függvény belépési pontján törölni kell.
Tehát _az alapértelmezett viselkedés az, hogy a memória növekvő címek szerint olvasódik/íródik_.

A `cld` utasítással törölheted a direction flaget, a `std` utasítással pedig beállíthatod:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
A hívó fél a System V ABI szerint azt várja, hogy a `DF` törölve legyen, miután bármely meghívott függvény visszatér.
Ha valaha beállítod a `DF`-et, mindenképpen töröld vissza `ret` előtt.
~~~~

### Rep

Ezeken kívül a **rep** utasítás nem érintkezik közvetlenül a memóriával.
Ehelyett előtagként hozzáadható a többi említett utasításhoz, és _ismétli_ azokat az utasításokat.

Amikor a `rep` előtagot kapják, a stringutasítások a `rcx` értékének megfelelő számú alkalommal ismétlődnek.
Minden alkalommal a `rcx` értéke `1`-gyel csökken.
Ne feledd, hogy a `rcx` értékét az utasítás használata előtt be kell állítani:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
A modern CPU-kon a `rep movs` és a `rep stos` általában gyors megoldás nagy adatblokkok mozgatásakor.
A többi stringutasítás, sőt a `movs` és a `stos` is, amikor `rep` nélkül működnek, azonban általában lassabbak egy egyszerű ciklusnál.

A témáról részletesebb áttekintést találsz [a referenciakönyv 16.9. fejezetében, „String instructions”][agner-optimization-guide].
