# Részletesen

Bár a Swiftben sokféle típus létezik, mindegyikük két nagy kategória valamelyikébe tartozik: _értéktípusokba_ és _referenciatípusokba_. A Swiftben a [struktúrák értéktípusok][structs-are-value-types], az [osztályok pedig referenciatípusok][classes-are-reference-types].

Az értéktípusok és a referenciatípusok közötti legfőbb különbség az, hogy amikor egy értéktípust hozzárendelünk egy változóhoz vagy konstanshoz, illetve átadunk egy függvénynek, valójában az érték egy másolata lesz hozzárendelve vagy átadva, nem maga az az érték. Ha egy struktúra egyik másolatát módosítod, az nem hat a többi másolatra. A referenciatípusoknál viszont az értékre mutató referencia lesz hozzárendelve vagy átadva, így két különböző név ugyanarra az osztálypéldányra hivatkozhat. Ez ahhoz vezethet, hogy az eredeti példány is módosul, amikor egy másik néven féred el.

Nézzük tehát, mi történik, ha lemásoljuk és megváltoztatjuk az alábbi struktúrát és osztályt, amelyek egy játékbeli karaktert és annak játékstatisztikáit írják le.

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

Figyeld meg, hogy `charB` tulajdonságainak módosítása `charA`-ra is hatott, hiszen mindkét név ugyanarra a példányra hivatkozik. Az is látszik, hogy a két karakter statisztikáinál a referenciatípuson belüli értéktípusok a referenciatípuson belül változnak. Ez azonban nem sérti az értéktípusok viselkedését, mert `charA.stats` ugyanaz a `CharacterStats`-példány, mint `charB.stats`, hiszen `charA` és `charB` ugyanarra a `GameCharacter` osztálypéldányra hivatkozik. Amint látjuk, ezeknek az értéktípusoknak a másolatai például nem hatnak egymásra.

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

Ez az oka annak, hogy a struktúráknál a `mutating` kulcsszót kell olyan metódusok elé írni, amelyek a struktúra tulajdonságainak állapotát megváltoztatják. Egy struktúra tulajdonságának megváltoztatása valójában létrehozza a struktúra egy új másolatát, amelyben az adott tulajdonság az új értéket kapja, és az új másolat lép a régi helyébe. Ez vizuális jelzés arra, hogy ennél a típusnál sor kerülhet erre a másolásra és cserére.

Ennek az a mellékhatása, hogy azokat a struktúrapéldányokat, amelyeknél változó tulajdonságok változnak, akár mutating függvények hívásával, akár közvetlen értékadással, _változókhoz_ kell rendelni, nem konstansokhoz. Különben a fordító hibát jelez:

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

A kezdőértékeket így is létre lehet hozni és el lehet érni, de megváltoztatni nem lehet őket. Ez a megkötés az osztályokra nem vonatkozik. Ha egy osztálypéldányt `let`-tel rendelsz egy névhez, akkor a konstans a példányra mutató referenciát tárolja, és éppen ez az, ami nem változhat, nem maga a példány. A példány tehát változhat, de a referencia nem állítható át egy másik példányra.

Íme egy összefoglaló arról, mi változtatható meg a `let`-tel vagy `var`-ral definiált struktúráknál és osztályoknál:

|         | **struct**                                                                                  | **class**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | _Nem_ rendelhetsz hozzá új struktúrát a névhez.</br>_Nem_ módosíthatod a struktúra egyetlen tulajdonságát sem. | _Nem_ rendelhetsz hozzá új osztályt a névhez.</br>_Módosíthatod_ az osztály változtatható tulajdonságait. |
| **var** | _Hozzárendelhetsz_ új struktúrát a névhez.</br>_Módosíthatod_ a struktúra változtatható tulajdonságait.   | _Hozzárendelhetsz_ új osztályt a névhez.</br>_Módosíthatod_ az osztály változtatható tulajdonságait.    |

## Azonosság

Mivel két különböző név is tarthat referenciát ugyanarra az osztálypéldányra, néha hasznos ellenőrizni, hogy valóban erről van-e szó. A Swift erre a `===` _azonos_ operátort használja (és annak tagadását, a `!==`-t).

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

Mivel két név nem hivatkozhat ugyanarra a struktúrapéldányra, ezek az azonosságoperátorok struktúrákra nincsenek definiálva.

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

Fontos, hogy az azonosság nem ugyanaz, mint az egyenlőség. Sokféle meghatározás szerint `char1` és `char3` egyenlőnek számítana, hiszen minden tulajdonságuk ugyanazokat az értékeket tartalmazza, mégsem azonosak. Az azonosságot a Swift automatikusan biztosítja minden osztály számára, de az egyenlőségoperátorokat általában a fejlesztőnek magának kell megírnia ahhoz, hogy eldönthesse, egy struktúra vagy osztály két példánya _egyenlő_-e. Ennek a részletei túlmutatnak e feladat keretein.
