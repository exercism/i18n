# Részletesen

Sok objektumorientált nyelvben megszokott, hogy a viselkedést úgy bővítjük, hogy [alosztályt készítünk][wiki-subclass] egy szülőosztályból: örököljük a szülő metódusait, és újakat is hozzáveszünk.
Így jön létre az objekthierarchia.

A Juliában _nincsenek osztályok_, így _alosztályok sincsenek_.
Hogyan örökölhetünk és bővíthetünk mégis meglévő viselkedéseket?

A korábbi fogalmakban láttuk, hogyan hozhatunk létre típushierarchiát, és azt is megtanultuk, hogyan használja a Julia a [többszörös diszpécselést][concept-multiple-dispatch] arra, hogy az argumentumok típusa alapján válasszon metódust.

A Juliának emellett számos informális [interfésze][ref-interfaces] van, amelyek segítségével a saját típusaid bekapcsolódhatnak a szabványos típusokhoz már definiált viselkedésekbe.

Ezt az Iterator interfésszel lehet a legkönnyebben szemléltetni.

## [Iterátorok][ref-iterators]

A tantervben korábban már több módot is láttunk arra, ahogyan a Julia egy gyűjtemény minden elemén műveletet végezhet.

- [Ciklusok][concept-loops], például `for item in items...`
- [Broadcasting][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Magasabb rendű függvények][concept-hof]: `map(√, [1, 4, 9])`
- [Komprehenziók][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Generátorok][concept-comprehensions]: `(x^2 for x in 1:1e6)`, amely lustán, csak igény szerint értékelődik ki.

A Julia nyilvánvalóan tudja, hogyan lépkedjen végig a szabványos gyűjteményeken elemenként: a fenti példákban vektorokon és tartományokon, de a Set és Dict típusokon is.

Hogyan adjuk hozzá ezt a képességet a saját egyéni gyűjteményeinkhez, különösen, ha azokat egy generátorhoz hasonlóan lustán lehet bejárni?

### Minimális követelmények

Ahhoz, hogy egy bejárható sorozatot létrehozzunk, (legalább) két dologra van szükség:

1. Egy mód, amivel megkapjuk az _első_ elemet.
2. Egy mód, amivel az aktuális állapotból megkapjuk a _következő_ elemet.

A Julia ezeket a feladatokat a `Base.iterate()` függvény metódusaival oldja meg, a következő lépések szerint:

1. Először automatikusan a `Base.iterate(iter)` hívódik meg.
    - Ha nincs mit bejárni, `nothing`-ot ad vissza.
    - Egyébként az első visszaadott elem és az első állapot `Tuple`-jét adja vissza: `(firstitem, firststate)`.
2. A `Base.iterate(iter, state)` akkor hívódik meg automatikusan, ha az előző iteráció visszaadott egy elemet; ilyenkor a `firststate` lesz a `state` argumentuma.
    - Ha az iteráció véget ér, `nothing`-ot ad vissza.
    - Egyébként a következő elem és a következő állapot `Tuple`-jét adja vissza: `(nextitem, nextstate)`.
3. Ismétli a 2. lépést, amíg az iteráció véget nem ér.

Ezek a lépések mind a „motorháztető alatt” zajlanak: a metódushívásokat és az állapotot maga az iterációs protokoll kezeli (az állapot rejtve marad), a magas szintű szerkezetek, például a ciklusok pedig csak az elemet látják.
Más szóval csak az `item`-et látjuk, minden más a fekete dobozban marad.

Ebben központi szerepe van a [többszörös diszpécselésnek][concept-multiple-dispatch].
Az `iter` típusa dönti el, hogy mely metódusok hívódnak meg, az argumentumok száma pedig azt, hogy az első vagy a következő elemet kapjuk-e vissza.

A szabványos típusokhoz már definiálva vannak a metódusok: `Vector`, `Range`, `Set` stb. ([jelenleg][ref-iterations-collections] összesen 14 típus).

Ahhoz, hogy egy egyéni `MyType` ugyanezeket a viselkedéseket tudja, először definiálnunk kell:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Mindez elvontan valószínűleg zavarosan hangzik, de a gyakorlatban egészen egyszerű lehet.
Szemléltetésképpen képzeljük el, hogy olyan típust szeretnénk, amely egy adott `n` egész szám hatványait adja, egy maximális darabszámig.

Először definiáljunk egy egyéni típust:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Most már definiálhatjuk ehhez a típushoz az `iterate` metódusokat, de mi az első elem és az első állapot?

Az első elem megadásához néhány iterátornál bonyolult előkészítés kell, de ebben a játéktípusban észrevehetjük, hogy az első visszaadott elem maga az alapszám, így csak azt kell ellenőriznünk, hogy a `count` értéke legalább egy.

Most nézzük az első állapotot, amely olyan információt hordoz, amit a következő iteráció felhasznál.
Rajtad múlik, hogy milyen adatot tartasz nyilván ehhez, és az bármilyen típus lehet.

Ebben az esetben egyszerűen nyilván tarthatjuk azt az „indexet”, amelyre `n`-t emeljük, de találhatunk hatékonyabb megoldást is, ha a legutóbbi hatványt (vagyis a visszaadott elemet) és a sorozat következő „indexét” használjuk.
Ez a két szám egy `Tuple`-be csomagolva adható vissza `state`-ként.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

Ebben a példában az első elem (`p.n`) kerül vissza a ciklusba, az első állapotot `(p.n, 2)` pedig az `iterate(P::Powers, state)` metódus kapja meg.
Ott feldolgozhatjuk az állapotot, és úgy állíthatjuk elő a következő elemet, hogy az aktuális elemet megszorozzuk az alapszámmal, ezzel `1`-gyel növelve a kitevőt.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Ha az index értéke még `count`-on belül van, akkor a `Tuple` a `next` elemmel és a megnövelt `(next, index + 1)` állapottal tér vissza.
Amikor az `index` értéke meghaladja `count`-ot, akkor helyette `nothing` a visszatérési érték, jelezve, hogy az iteráció véget ért.

Talán észrevetted, hogy az `iterate(p::Powers)` és az `iterate(p::Powers, state)` metódus törzse meglehetősen hasonló.
Ha ügyesek vagyunk, ez a hasonlóság lehetővé teszi egy letisztultabb megvalósítást: elég csak a kétargumentumos változatot használni, az állapotnak pedig alapértelmezett értéket adni: `Base.iterate(p::Powers, state=(1, 1))`
Ezzel nem lenne szükség külön az egyargumentumos `iterate(p::Powers)` metódusra.
A gyakorlatban ezt gyakran megteszik, amikor csak lehet.

~~~~exercism/advanced
Amikor a [Függvények][concept-functions] fogalomban bemutattuk az opcionális argumentumokat, a megvalósításról nem esett szó.

Azóta megismerkedtünk a többszörös diszpécseléssel, így most már érthetőbb, hogy a Julia az _opcionális argumentumokkal_ rendelkező függvényt automatikusan több olyan metódussá alakítja, amelyek _nem_ tartalmaznak opcionális argumentumot.

A `Base.iterate(P::Powers, state=(1, 1))` definiálása pontosan egyenértékű azzal, mintha a `Base.iterate(P::Powers, state)` és a `Base.iterate(P::Powers)` metódust külön-külön definiálnád.

Eddig már hasznos funkciókkal is rendelkezünk: a 3 első 4 hatványánál végigmehetünk ciklussal az eredményeken, ellenőrizhetjük, hogy egy adott szám szerepel-e az eredmények között, és alkalmazhatunk összesítő függvényeket, például a `sum()`-ot.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### További metódusok

A jó kezdés ellenére még nem működik minden.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers)
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Valóban, a `length(Powers(3, 4))` pontosan ugyanezt a hibaüzenetet adja.

Ez könnyen orvosolható, hiszen a hossz része a típus konstruktorának: ebben az esetben a 4.
Csak definiálnunk kell ehhez a típushoz a `Base.length()` metódust, és máris használhatunk komprehenziókat és `collect()`-et a sorozaton.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

A hatékonyság érdekében érdemes a `Base.eltype()` metódust is definiálni: ez az eredmény elemtípusa.
Ennek köszönhetően az olyan függvények, mint a `collect()`, előre kioszthatják a helyet a kimeneti `Vector{Int}` számára, ahelyett hogy ismételten `push!()`-t hajtanának végre egy `Vector{Any}`-n.

Figyeld meg a szintaxist, amit eddig talán még nem láttál: ez a metódus a _típuson_ van definiálva, nem a típus egy _példányán_.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Az iterátoroknak nem _kötelező_ véges hosszúságúnak lenniük.
A „végtelen” sorozatok használata korlátozottabb, de a rajtuk való végigciklusolás hasznos lehet, amíg van valamilyen mód arra, hogy `break`-kel kilépjünk a ciklusból.
Definiálhatnánk például a `Powers` egy olyan változatát, amely egy bizonyos határnál kisebb értékeket állít elő (talán `typemax(Int)`-ig, hogy elkerüljük az egész számok túlcsordulását).

## Egyéb interfészek

### [Indexelés][ref-indexing]

Az Iterators interfész segítségével egy tetszőleges egyéni típus is viselkedhet sorozatként, pusztán néhány egyszerű metódus definiálásával.

Tegyük fel, hogy indexelni is szeretnénk tudni a sorozatba:

```julia-repl
julia> P = Powers(3, 4)
Powers(3, 4)

julia> P[2]
ERROR: MethodError: no method matching getindex(::Powers, ::Int64)
The function `getindex` exists, but no method is defined for this combination of argument types.
```

Ezt a viselkedést is hozzáadhatjuk, és a [kézikönyv][ref-indexing] elmagyarázza, hogyan.

Minimálisan a `getindex()` metódust kell definiálnunk.

```julia-repl
julia> function Base.getindex(P::Powers, i::Int)
          1 ≤ i ≤ P.count || throw(BoundsError(P, i))
          return p.n ^ i
       end

julia> p = Powers(3, 4)
Powers(3, 4)

julia> p[3]
27
```

Emellett definiálnunk kell még:

- a `firstindex()` és a `lastindex()` metódust a `P[begin]` és a `P[end]` támogatásához.
- a `getindex()` változatait, hogy vektorokkal és tartományokkal is lehessen indexelni.
- Elméletben a `setindex!()` metódust is, bár nehéz elképzelni, hogy ebben a példában mit is jelentene ez.

Ezen a ponton azonban már sok munkát végzünk csak azért, hogy az iterátorunk jobban hasonlítson egy vektorhoz.

### [AbstractArray][ref-abstractarray]

Érdemes lehet alternatív interfészeken gondolkodni, amelyek jobb kiindulópontot kínálnak.

Ebben az esetben megfontolhatjuk, hogy a `Powers` a [`AbstractArray`][ref-abstractarray] altípusa legyen, ami sok tömbhöz hasonló viselkedést ad ingyen.

A `Powers` sorozat esetében a megfelelő tömb egész számokból áll, egyetlen dimenzióval.
Ezt néha `AbstractArray{Int, 1}` alakban láthatod, de az egydimenziós `AbstractVector{Int}` és a kétdimenziós `AbstractMatrix{Int}` aliasok gyakoribbak az újabb Julia-kódban.

```julia-repl
julia> struct PowersArray <: AbstractVector{Int}
           n::Int
           count::Int
       end
```

A `length()` helyett most a `size()` metódust kell definiálnunk, egy tuple-lel, amely az egyes dimenziók menti hosszakat tartalmazza: ebben az esetben csak egy dimenzióét.

```julia-repl
julia> Base.size(PA::PowersArray) = (PA.count,)
```

Hogyan szeretnénk indexelni az elemeket?
A [többdimenziós tömbök fogalmában][concept-multi-dimensional-arrays] két fő megközelítést mutattunk be:

- Dimenzióként egy index, tehát `M[row, col]` egy `M` mátrix esetén.
- Egyetlen index, amely megfelel az elemek memóriabeli elrendezésének

Ezeket nevezik `Cartesian`, illetve `Linear` indexelésnek.

A példában csak egy dimenzió van, így a lineáris indexelés a megfelelő.

```julia-repl
julia> Base.IndexStyle(::Type{PowersArray}) = IndexLinear()

julia> Base.getindex(PA::PowersArray, i::Int) = PA.n ^ i

julia> p = PowersArray(3, 4)
4-element PowersArray:
  3
  9
 27
 81

julia> p[3]
27
```

Figyeld meg, hogy ebben az esetben nem definiáltuk az `iterate()` metódust.
A Julia automatikusan ad egy alapértelmezett megvalósítást, a `getindex()` definíciónk alapján.

Az `iterate()` saját változatát persze továbbra is definiálhatjuk, és néha ez hatékonyabb lehet.

Az `AbstractArray` interfész használata különösen akkor értékes, ha magasabb dimenziós iterációt szeretnénk.
Kockáztatva, hogy a játéktípust a szakadásáig feszítjük, ez jelenthetné például az `1:n` számok első `m` hatványát, amivel iteratív módon egy `(m, n)` méretű tömböt definiálunk.

```julia-repl
struct PowersMatrix{Int} <: AbstractMatrix{Int}
    ns::AbstractVector{Int}
    count::Int
end

Base.size(PM::PowersMatrix) = (PM.count, length(PM.ns))
Base.IndexStyle(::Type{PowersMatrix}) = IndexCartesian()
Base.getindex(PM::PowersMatrix, i::Int, j::Int) = PM.ns[j] ^ i

julia> PM = PowersMatrix(2:6, 4)
4×5 PowersMatrix{Int64}:
  2   3    4    5     6
  4   9   16   25    36
  8  27   64  125   216
 16  81  256  625  1296

julia> PM[3, 2]
27

julia> PM[7] # column major linear indexing
27

julia> PM[21]
BoundsError: attempt to access 4×5 PowersMatrix{Int64} at index [21]
[...]
```

### [Kerekítés][ref-rounding]

A korábbi fogalmak már említettek különféle kerekítési módokat a numerikus típusokhoz.

```julia-repl
julia> round(1.7)
2.0

julia> floor(1.7)
1.0

julia> ceil(1.7)
2.0

# specify output type
julia> round(Int, 1.7)
2

julia> round(2.4 + 7.3im)
2.0 + 7.0im
```

A [`round()`][ref-round] függvény ennél rugalmasabb: megadhatod neki a [`RoundingMode`][ref-roundingmode] módot (a jelenleg támogatott 7 közül), a kimenet tizedesjegyeinek számát és a számrendszert.

Szeretnénk, ha ugyanezek a függvények kezelnék a saját típusainkat is.
Ez általában összetett típusokat jelent, például koordinátákat.

```julia-repl
julia> struct Point3D
           x::Float64
           y::Float64
           z::Float64
       end

julia> p = Point3D(7.63, 9.24, 4.50)
Point3D(7.63, 9.24, 4.5)

julia> round(p)
ERROR: MethodError: no method matching round(::Point3D, ::RoundingMode{:Nearest})
The function `round` exists, but no method is defined for this combination of argument types.
```

Nem meglepő módon létezik egy `Rounding` interfész, amely minimálisan annyit kíván, hogy definiáljuk a `round()` metódust a saját típusunkhoz.

```julia-repl
julia> Base.round(P3D::Point3D, r::RoundingMode) = Point3D(round(P3D.x, r), round(P3D.y, r),round(P3D.z, r))

julia> round(p)
Point3D(8.0, 9.0, 4.0)

julia> ceil(p)
Point3D(8.0, 10.0, 5.0)
```

Mivel a definícióban szerepel a `RoundingMode`, a `floor()` és a `ceil()` automatikusan működik.

Természetesen szabadon definiálhatunk bonyolultabb kerekítési módokat is.

- Kerekíthetnénk a `Point3D`-t úgy, hogy egész távolságra kerüljön az origótól, ugyanabban az irányban.
- Szögek esetében kerekíthetnénk a meteorológusok által használt 16 irányra („SSW szél 15 csomóval”), ami a π/8 radián többszöröseit jelenti.
- Hozzáadhatnánk annak lehetőségét is, hogy megadjuk a `digits`, a `sigdigits` vagy a `base` értékét.
- Az időtartamokhoz [különleges beállítások][ref-round-periods] vannak

## Összefoglalás

Az interfészeket meglehetősen zavaros elmagyarázni, mert a Julia megközelítése nagyon eltér a legtöbb más nyelvétől.
Az implementációban például az interfész neve soha nem is szerepel: ez nagyon más, mint az [alosztálykészítés][wiki-subclass] vagy a [mixin][wiki-mixins] esetében.

A gyakorlatban mégis meglepően egyszerűek:

1. Definiálj egy megfelelő típust, és döntsd el, hogy hasznos-e altípust készíteni vagy sem.
2. Nézd meg, mely metódusok szükségesek (a [dokumentációból][ref-interfaces]).
3. Valósítsd meg ezeket a metódusokat az egyéni típusodhoz; általában csak néhány metódusról van szó, ráadásul rövid és egyszerű.
4. A többiről [a többszörös diszpécselés][concept-multiple-dispatch] gondoskodik, automatikusan.
