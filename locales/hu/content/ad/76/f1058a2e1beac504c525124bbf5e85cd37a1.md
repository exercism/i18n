# Bevezetés

Az assembly-ben minden adat bájtok sorozata.
Ez azt jelenti, hogy bármely adat felfogható a mögöttes bájtok **tömbjeként**.

## Elemek elérése egy tömbben

Ahhoz, hogy a memóriában bármely értéket elérjünk, ki kell számítanunk az **effektív címét**.
Az effektív cím egy kifejezés, amely a következőkből állhat:

- egy _báziscím_, például amit egy változó címkéje jelöl ki.
- egy _indexregiszter_, amelyet esetleg `1`, `2`, `4` vagy `8` értékkel skálázunk.
- egy előjeles 32 bites _eltolás_, amely egy szám, amit a báziscímhez hozzáadunk (vagy kivonunk belőle).

Vedd figyelembe, hogy ez a cím _0-tól indexelt_, így egy báziscím eltolás nélkül a változó első bájtjára mutat.
Ezért amikor a memóriát csak egy címkével érjük el, eltolás nélkül, ahogyan a korábbi fogalmakban tettük, az eredmény egy olyan érték, amely az első bájtjánál kezdődik:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
Az x86-64 [little endian][endianness].
Ez azt jelenti, hogy egy többbájtos érték legkisebb helyiértékű bájtja a legkisebb memóriacímen tárolódik.

Következésképpen, amikor egy többbájtos érték egyes bájtjait érjük el, pozitív eltolást kell hozzáadni a báziscímhez, hogy a nagyobb helyiértékű bájtokhoz jussunk.

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

Egy inicializált változó, amelyet értékek listájával deklarálunk, ezen értékek tömbje, ahol minden elem a megadott méretű.
Az eltolások azonban mindig **_bájtban_** értendők, még akkor is, ha a tömb minden eleme nagyobb méretű:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

Vedd figyelembe, hogy mivel a címek bájtokra vonatkoznak, egy tömb bármely elemének egyes bájtjait közvetlenül is elérhetjük:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

Ugyanezen okból egyetlen utasításban egy elem méreténél többet is elérhetünk:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
Az assembly semmilyen határellenőrzést nem végez a tömbeléréseknél.
A tömb végén túli index a tömbön kívüli memóriát olvassa vagy írja.
Ez csendben helytelen eredményekhez, más adatok megsérüléséhez vezethet, és ha az elért memória nincs leképezve, futásidejű hibát okozhat.
A programozó felelőssége, hogy minden effektív cím a tömbön belül maradjon.
~~~~

## Egy inicializált tömb méretének kiszámítása

A NASM (The Netwide Assembler, a kurzus által használt assembler) rendelkezik egy speciális szimbólummal (`$`), amely a memória aktuális helyét jelöli.
Ez a szimbólum kényelmes módot kínál egy tömb által elfoglalt teljes memóriaméret kiszámítására:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

Amikor közvetlenül az `example` után használjuk, a `$` a tömb végének memóriacímét adja.
Ez azt jelenti, hogy a `$ - example` a különbség ezen cím és az `example` címke által mutatott cím között.
Ez pontosan az `example` által mutatott tömb által elfoglalt teljes méret, bájtban.

Így amikor az `example_length` értékét ezzel a számmal definiáljuk, létrehoztunk egy 8 bájtos változót, amely a tömb méretét, azaz hosszát tárolja bájtban.

## A .bss szekció

A nem inicializált adatokat a **.bss szekcióban** deklaráljuk.
A legtöbb platformon ezt az adatot az operációs rendszer nullákkal tölti fel a program indításakor.

A NASM-ben egy nem inicializált változónak van egy neve, egy direktívája, amely az adat méretét jelzi, és a lefoglalandó elemek száma.
Ezeket szóköz választja el egymástól.

A főbb direktívák és a hozzájuk tartozó adatméret:

| direktíva | méret   |
| :-------: | :------ |
|   resb    | 1 bájt  |
|   resw    | 2 bájt  |
|   resd    | 4 bájt  |
|   resq    | 8 bájt  |

Például ez nem inicializált helyet foglal le `3` bájt számára az `example` nevű változóban:

```x86asm
section .bss
    example resb 3
```

Ez pedig nem inicializált helyet foglal le `10`-szer `8` bájt (azaz `80` bájt) számára az `arr` nevű változóban:

```x86asm
section .bss
    arr resq 10
```

A `section .bss`-ben lévő változók módosíthatók, azaz olvashatók és írhatók.

A nem inicializált adat ugyanúgy elérhető, mint az inicializált, az effektív címének használatával.
Hasonlóképpen statikus tárolási időtartamúak, és ugyanazon forrásfájl bármely függvényéből elérhetők (és ha `global`-ként deklaráljuk őket, más forrásfájlokból is).

## Tömbcímek elérése a Lea utasítással

Ahogyan azt egy korábbi fogalomban megvizsgáltuk, a `lea` utasítás kiszámít egy effektív memóriacímet.
Ugyanazokat a szemantikai szabályokat követve bármely tömb elem címének kiszámítására használható.

Vedd figyelembe, hogy relatív címzésnél gyakran szükséges a változó címét egy regiszterbe betölteni, mielőtt összetettebb címet képezünk:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
A `lea` egyik előnye, hogy címzési aritmetikát használ egy érték kiszámításához anélkül, hogy ténylegesen hozzáférne az adott címen lévő memóriához.
Ez hasznossá teszi aritmetikai számítások elvégzésére akkor is, amikor egyetlen regiszter sem tartalmaz memóriacímet:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
