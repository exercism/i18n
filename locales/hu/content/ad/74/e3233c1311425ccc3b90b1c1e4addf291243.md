# Bevezetés

## Ciklusok

A **ciklus** olyan utasítássorozat, amelyet lehet, hogy többször is végrehajtunk, amíg egy befejezési feltétel nem teljesül.

Az x86-64-en a ciklust általában egy korábbi címkére való ugrással hozzuk létre:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Figyeld meg, hogy egy feltétel nélküli ugrás egy korábbi címkére mindig erre a címkére irányítja a végrehajtást.
Ez azt jelenti, hogy a ciklus a végtelenségig ismétlődni fog, hacsak nincs egy másik ugrás az ismételt sorozaton kívülre.

Például ez a ciklus nem fejeződik be:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

Ez a ciklus pedig attól függően érhet véget, hogy teljesül-e a feltétel:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

### Számlálóciklusok

A számlálóciklus majdnem mindig ugyanúgy ér véget: egy utasítás, amely frissíti a számlálót vagy összehasonlít két értéket, közvetlenül utána pedig egy feltételes ugrás, amely eldönti, hogy újra végigmenjen-e a cikluson.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
A fenti kódban a `cmp rsi, 0` nem szükséges, mert a `sub rsi, 1` már beállítja a `zero flag (ZF)` jelzőt, amikor az eredmény `0`.

Bár assemblyben a feltételek vizsgálatának fő módja a `cmp`, sok utasítás frissíti a jelzőbiteket.
Például sok egész aritmetikai vagy bitenkénti utasítás beállítja a `ZF`-t, ha az eredmény `0`, és az `SF`-et, ha az eredmény negatív (azaz a legfelső bit be van állítva).

Megnézhetsz egy [referenciát][reference], hogy lásd, mely jelzőbiteket érinti az egyes utasítások.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Figyeld meg, hogy a fenti példában az `rsi` értékéről feltételezzük, hogy nagyobb, mint `0`.
Ha `0` lenne, akkor a `sub rsi, 1` `-1`-re csökkentené az `rsi`-t, ami előjel nélküli számként nagyon nagy érték.
Még `18,446,744,073,709,551,615` iterációra lenne szükség, mire a ciklus végre befejeződne.
Ráadásul, mivel a tömb hossza `0`, minden memóriahozzáférés a megengedett tartományon kívül esne.

Ha nincs garancia a tömb hosszára, két gyakori megközelítés létezik.

Az első megközelítés, hogy a befejezési feltételt a ciklus elejére helyezzük, a végére pedig egy feltétel nélküli ugrást teszünk:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

A második, hogy a ciklus kezdete előtt egyszer ellenőrizzük a nulla hosszúságú tömböt:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Ez a második megközelítés általában hatékonyabb az elsőnél, mert kevesebb elágazás van a ciklus törzsében.
Erről egy későbbi fogalomban tanulsz majd többet.

~~~~exercism/advanced
Bizonyos helyzetekben a modern CPU-k képesek két különböző utasítást egyetlen műveletté összevonni.
Ezt az optimalizálást **makrofúziónak** nevezik.

Sok aritmetikai utasítás, például a `sub` és az `add`, valamint a `cmp` és a `test`, gyakran összeolvad a közvetlenül utána következő feltételes ugrással.
Ez azt jelenti, hogy egy olyan utasítást, mint a `cmp rax, rdx`, amelyet közvetlenül egy feltételes ugrás követ, a CPU általában egyetlen műveletként kezelheti.

A makrofúzió a CPU-tól függ, és változó, hogy mely utasítások melyik feltételes ugrással olvadnak össze.

A [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch] hasznos referencia.
Az [Intel optimization reference manual][intel-opt] 3.4.2.2. szakasza (Optimizing for Macrofusion) szintén felsorolja az Intel CPU-khoz összeolvasztható párokat.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
