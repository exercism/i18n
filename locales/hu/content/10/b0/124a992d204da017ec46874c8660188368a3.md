# Bevezetés

A Go-ban a stringek megváltoztathatatlanok.
Ha ciklusban a `+` operátorral fűzöd össze a stringeket, gyakori memóriafoglalások történnek, és az adatok többször másolódnak.
A [`strings` csomag](https://pkg.go.dev/strings) [`Builder`](https://pkg.go.dev/strings#Builder) típust kínál, amellyel hatékonyan építheted fel a stringeket, a memóriahasználatot minimálisra csökkentve.

## Stringek építése

A `strings.Builder` nullaértéke azonnal használatra kész, explicit inicializálás vagy memóriafoglalás nélkül.
A builderbe az erre szolgáló író metódusokkal juttathatsz új adatot.
Minden író metódus hibát ad vissza, hogy megfeleljen a szabványos Go-interfészeknek, de garantáltan mindig `nil` az értéke, ezért a mindennapi kódban általában figyelmen kívül hagyjuk.

A leggyakrabban használt metódusok:

- `WriteString(s string) (int, error)`: Egy stringet fűz a puffer végéhez.
- `WriteRune(r rune) (int, error)`: Egy rune UTF-8 kódolását fűzi a puffer végéhez.
- `WriteByte(c byte) error`: Egyetlen bájtot fűz a puffer végéhez.

```go
var sb strings.Builder

sb.WriteString("Hello")
var r rune = ' '
sb.WriteRune(r)
var b byte = '.'
sb.WriteByte(b)
```

## Lekérés és alaphelyzetbe állítás

Ha elkészült a szöveg, a felhalmozott tartalmat a `String()` metódus meghívásával szabványos Go-stringként kérheted le.
A `String()` hívása nagyon olcsó művelet, mert a mögötte lévő bájtszeletet közvetlenül stringként adja vissza, anélkül hogy lemásolná a felhalmozott adatot.

Ha ugyanazt a builderpéldányt szeretnéd újra felhasználni egy új string összeállításához (például egy cikluson belül), hívd meg a `Reset()` metódust.
Ez kiüríti a belső puffert, így tiszta lappal indulsz, és felépítheted a következő stringet, miközben a már lefoglalt memóriakapacitás a háttérben megmarad.

```go
var sb strings.Builder

sb.WriteString("Task One")
fmt.Println(sb.String()) // Output: Task One

// Clear the buffer for resource reuse
sb.Reset()

sb.WriteString("Task Two")
fmt.Println(sb.String()) // Output: Task Two
```
