# Bevezetés

Az Elixirben minden hiba megvalósítja az _Exception Behaviour_-t. Csakúgy, mint az _Access Behaviour_, az _Exception Behaviour_ is visszahívó függvényeket definiál, amelyeket egy modulnak meg kell valósítania ahhoz, hogy teljesítse a behaviour szoftveres szerződését. Amint definiáltunk egy hibát, annak a következő tulajdonságai vannak:

- A modul neve adja a hiba nevét.
- A modul definiál egy hibastruktúrát.
- A struktúrának lesz egy `:message` mezője.
- A modul a `raise/1` és a `raise/2` függvénnyel használható a szándékolt hiba kiváltására

Az _Exception Behaviour_ emellett két visszahívó függvényt is meghatároz: a `message/1`-et és az `exception/1`-et. Ha ezeket nem valósítjuk meg, az alapértelmezett implementációk lépnek a helyükbe. A `message/1` a hibastruktúrát olvasható üzenetté alakítja, amikor a `raise` meghívja. Az `exception/1` lehetővé teszi, hogy további kontextust adjunk az üzenethez, amikor a `raise/2` hívja meg.

## Kivétel definiálása

Ahhoz, hogy egy hibamodulból kivételt definiáljunk, a `defexception` makrót használjuk:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

## Kivételek használata

A definiált hibák ugyanúgy használhatók, mint a beépített hibák, akár a `raise/1`, akár a `raise/2` segítségével.

- A `raise/1` a modul neve alapján vált ki egy adott hibát, vagy ha az argumentum egy string, akkor egy `RuntimeError`-t vált ki, amelynek az üzenete maga a string.
- A `raise/2` a modul neve alapján vált ki egy adott hibát, és elfogad egy attribútumargumentumot, amelynek a segítségével a megfelelő üzenetű hibát kapjuk meg.
