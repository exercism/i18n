# Bővebben

A Factor egyetlen adatátadási konvenciója az *adatverem*: a szavak leveszik a bemeneteiket, és felteszik a kimeneteiket. Minden szódefiníció deklarál egy *veremhatást*, amely ezt a szerződést dokumentálja.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

A `( … -- … )` zárójelek közötti nevek csak az olvasót segítik; a fordító a bemenetek és a kimenetek *számát* ellenőrzi. Az eltérés fordítási idejű hiba, ami a hibák egy olyan csoportját kapja el, amelyek egy ilyen deklaráció nélküli, dinamikusan típusos nyelvben futási idejű hibák lennének.

Mivel a verem pozicionális, folyton át kell rendezned a tetejét, mielőtt lefuthatna a következő szó. A `kernel` **átrendező szavai** pontosan ezt teszik:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

A teljes átrendező család tovább bővíti ezeket a `-rot` szóval (a másik irányba forgat), a `d` végződésű rokonaival, amelyek egy elemmel mélyebben hatnak (`dupd`, `swapd`), a `2` előtagú rokonaival, amelyek párokra hatnak (`2dup`, `2drop`, `2nip`), és másokkal, például a `pick` és a `tuck` szóval. Ezeket majd akkor vezetjük be, amikor a későbbi feladatoknak szükségük lesz rájuk; ha egyszerre túl sok átrendező szóhoz nyúlsz, az általában annak a jele, hogy egy *local* (nevesített érték) olvashatóbb lenne.

Konvenció szerint a szavak `lowercase-kebab-case` stílusban íródnak, a predikátumok `?`-re végződnek és Boolean-t adnak vissza (`even?`, `empty?`), a beállítók `>>name`, a lekérdezők `name>>` formában íródnak, és egy szó meg a módosító változata gyakran ugyanazt a nevet viseli, csak a kontextus különbözteti meg őket.
