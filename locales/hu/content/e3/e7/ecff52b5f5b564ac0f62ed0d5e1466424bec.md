# Bevezetés

Gyakran hasznos saját típusokat definiálni a programjainkban.

Új primitív típusokat is létre lehet hozni, de ezt ritkán tesszük.
A beépített primitív típusok nem önkényes választás eredményei: szorosan illeszkednek a Julia által JIT-fordításhoz használt LLVM-fordító szabványos típusaihoz.

Sokkal hasznosabb viszont az a lehetőség, hogy összetett adattípusokat definiáljunk elnevezett mezőkkel.

Más nyelvekben is található valami hasonló, ott `structs` vagy `records` a nevük.
A Julia dokumentációja `composite types` néven említi őket, bár (kis ellentmondásként) a nyelv szintaxisa a `struct` kulcsszóval definiálja őket.

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

Néhány dolgot érdemes megjegyezni a fenti példában:

- Az `id` számára nincs megadva típus, ezért a fordító ezt úgy értelmezi, hogy `id::Any`.
  - A gyakorlatban érdemes segíteni a fordítónak, és egy mező típusát konkrét típusként megadni
- A típusnév konstruktorként használható, ahogy a `Person(id, name, age)` esetében is, így kapunk egy `Person` típusú példányt.
- Az egyes mezőket ugyanúgy pontjelöléssel érhetjük el, mint a named tuple-öknél.

A `Person` típusú értékek megváltoztathatatlanok, ezért nem frissíthetők.

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

Ha szükség van a módosíthatóságra, add hozzá a `mutable` kulcsszót a definícióhoz.

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

A konstruktor alapértelmezés szerint megköveteli, hogy a mezők ugyanabban a sorrendben szerepeljenek, mint a definícióban, ami bonyolultabb típusoknál kényelmetlenné válik.

A `@kwdef` makró használata két új lehetőséget kínál:

- A konstruktor kulcsszavakat használ, nem pozíciót.
- A mezőknek lehet alapértelmezett értékük, és a konstruktorból akár el is hagyhatók.

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## Összetett típusok hierarchiája

Eddig csak konkrét összetett típusokat hoztunk létre.
Ha utánanézel, mindegyik az `Any` altípusa.

Amikor több, egymással rokon típust hozunk létre, valószínűleg ésszerűbb hierarchiát definiálni számukra.
Ez nagyon egyszerűen megtehető.

Először hozz létre egy absztrakt típust:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

Ezután tedd bele a `<:` operátort a típusdefinícióba, hogy kifejezd a kapcsolatot.

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

Ismételd meg, ahányszor csak kell, de ne feledd, hogy konkrét típusok alárendelése nem megengedett.

Összetettebb hierarchia esetén hozz létre absztrakt altípusokat, ahogy szükséges.

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

Az ilyen hierarchia értéke akkor válik világosabbá, amikor eljutunk a `Multiple Dispatch` fogalomhoz, és meglátjuk, hogyan kezelik a függvények az argumentumok típusait.
