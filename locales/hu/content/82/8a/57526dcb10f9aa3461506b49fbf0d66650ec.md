# Névjegy

A kézzel írt assembly tele van ismétlődéssel.
Ugyanaz a rövid utasítássor jelenik meg újra és újra, alig eltérő formában, és kevés absztrakció segít csökkenteni a sablonkódot.
Ráadásul az assemblyben a programozónak olyan értékeket kell kezelnie, amelyeknek nincs nyilvánvaló jelentésük.
Nincsenek nevesített paraméterek, és a háttérben működő gépezet részleteit nagyrészt a programozónak kell kézzel kezelnie.

A NASM, a kurzus által használt assembler, néhány olyan eszközt kínál, amely mindkét problémában segíthet a programozónak.
Ezek az eszközök _fordítási időben_ futnak le, még mielőtt bármelyik utasítás eljutna a processzorhoz.
Arra utasítják az assemblert, hogyan írja át a forrásszöveget, még mielőtt az gépi kóddá alakulna.

Ezek közül a legfontosabbak a **makrók**, amelyekre úgy gondolhatsz, mint az assembler receptjére.
A használat helyén fejtődnek ki, mintha a kódot oda kézzel írták volna.

A [makrók][macro] több literál tokent is fogadhatnak paraméterként, így különböző helyzetekben újra felhasználhatók.
Ugyanakkor nem függvények: nincs `call`, nincs `ret`, és nincs vezérlésátadás a kód egy másik pontjára.

## Egysoros makrók

A legegyszerűbb definíció egy értéknek vagy egy rövid kifejezésnek ad nevet a `%define` segítségével:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

A `WIDTH` minden későbbi előfordulását a fordítás előtt `8`-ra cseréli.
A helyettesítés szöveges, ezért a nevet mindenhol behelyettesíti, ahol megjelenik, akár operandusban, akár egy másik definícióban.

~~~~exercism/note
Numerikus _konstansokhoz_ inkább az `equ`-t válaszd a `%define` helyett.

A `%define`-nal deklarált egysoros makró csak használatkor fejtődik ki, és újraértékadható vagy törölhető.
Az `equ` konstans viszont a definíció helyén értékelődik ki, és soha nem módosul.
~~~~

A `%define` _nevesített_ paramétereket is fogadhat, és úgy viselkedik, mint egy kicsi, beágyazott függvény:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Tedd zárójelbe a teljes törzset és minden paramétert is.
A `%define square(x) x*x` esetén a `square(1+1)` hívás `1+1*1+1`-re fejtődik ki, ami `3`.
`%define square(x) ((x)*(x))` formában ugyanez a hívás `((1+1)*(1+1))`-re fejtődik ki, ami `4`.
~~~~

A `%define`-nal definiált neveknél számít a kis- és nagybetű.
A `%idefine` változat viszont nem tesz különbséget kis- és nagybetű között a névben, ha éppen erre van szükség.

Az egysoros makrókkal jelentést adhatunk a kód különböző részeinek.
Ha körültekintően használod őket, javítják az olvashatóságot és csökkentik az elgépelések esélyét.
Egy függvényen belül különleges szerepet betöltő regisztert például a szerepe szerint is elnevezhetsz:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Többsoros makrók

Egy teljes kódsorozatot, akárhány sorral, a `%macro` rögzít, és a `%endmacro` zár le.
A név utáni szám mutatja, hogy a makró hány argumentumot vár, ami nulla is lehet.
Az argumentumokat vessző (`,`) választja el egymástól:

```x86asm
%macro example_macro 0
...
%endmacro
```

A többsoros makrók argumentumai nem nevesítettek.
Rájuk `%1`, `%2` és így tovább néven hivatkozunk, abban a sorrendben, ahogy átadjuk őket:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Figyeld meg, hogy az argumentumoknak érvényes szintaxist kell alkotniuk a makró törzsében végzett műveletekhez.
Itt a `mult_two eax, ecx` és a `mult_two r8, r9` is lefordul, a `mult_two eax, cl` viszont nem, mert az `imul eax, cl` nincs definiálva.

A makrók tetszőleges számú argumentumot is fogadhatnak.
Ezt az `n-*` jelöléssel lehet megtenni, ahol az `n` az argumentumok minimális száma:

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

Egy többsoros makróban a `%0` az argumentumok _számát_ jelöli.
Ez különösen hasznos azokban a makrókban, amelyek tetszőleges számú argumentumot fogadhatnak.

### Címkék a makrón belül

Egy olyan makró, amely közönséges címkét definiál, abban a pillanatban elromlik, amint kétszer használod, mert a címke akkor kétszer is definiálódna.
Ahhoz, hogy egy többször is meghívható makróban címkét használj, az ilyen címkét `%%` előtaggal kell ellátnod.
Ez arra utasítja az assemblert, hogy minden kifejtéskor más, egyedi nevet adjon a címkének:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Ismétlés fordítási időben

Egy egysoros kódblokkot a [`times`][times] segítségével ismételhetsz.
Ez különösen hasznos, amikor ismétlődő értékeket deklarálsz a memóriában:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Többsoros kód ismétléséhez ehelyett a `%rep`-et használhatod:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Figyeld meg, hogy az ismétlések számát közvetlenül a `%rep` után adod meg, és az ismételt blokkot egy `%endrep` zárja le.

Gyakori, hogy egy `%rep` blokkon belül fordítási idejű számlálót használunk, hasonlóan ahhoz, ahogy egy futásidejű ciklus számlálót használ.
Bár egy fordítási idejű egész konstans az `equ`-val deklarálható, ahogy azt már láttuk, a fordítási idejű egész _változókhoz_ ehelyett a `%assign`-et használjuk.
A `%define`-tól eltérően a `%assign` azonnal számmá értékelődik ki, és újraértékadható:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Miután a preprocesszor lefut, a ciklus eltűnik, és négy `add` utasítás marad, a `0`, `1`, `2` és `3` immediate értékkel beégetve.
Ez a ciklus kigöngyölítése, amit az assembler végez: nincs számlálóregiszter és nincs elágazás, csak lineáris kód.

A `%rep` másik gyakori felhasználása, hogy egy tetszőleges számú argumentumot fogadó makró argumentumait kezeljük vele.
Ilyenkor a `%rep` általában a `%rotate`-tel párosul, amely elforgatja a makró argumentumait, így a második argumentumból lesz az első.
A `%rotate` ismételt alkalmazásával a harmadik, majd a negyedik, és így további argumentum lesz az első, így minden argumentum sorra kerülhet:

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## Feltételes fordítás

A [preprocesszor][preprocessor] számos feltételes szerkezetet kínál.
Több különböző útvonal közül választanak, és a helyükön fejtik ki a törzsüket, de csak akkor, ha a feltételük igaz.

A `%if` ... `%elif` ... `%else` ... `%endif` egy numerikus vizsgálat alapján választ ágat:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

A `%ifdef` és a `%ifndef` hasonló, de azt vizsgálják, hogy egy név definiálva van-e.
Például arra használhatók, hogy egy fájl tartalma csak egyszer legyen beillesztve, akkor is, ha több forrás húzza be a fájlt:

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

Talán észrevetted, hogy ebben a kurzusban minden `.asm` fájl végén ott van ez a kódrészlet:

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

A `%ifidn` két szöveget hasonlít össze pontos egyezésre.
A beépített `__OUTPUT_FORMAT__` az aktuális kimeneti formátumra fejtődik ki, így ez a kód azt ellenőrzi, hogy a kimeneti formátum `elf64`-e, ami a Linux rendszerek által használt formátum.
Ha igen, egy megjegyzés kerül az objektumfájlba, amely kinyilvánítja a verem számára engedélyezett jogosultságokat, ami egy gyakori biztonsági intézkedés.
Ha nem, semmi sem változik.

## Struktúrák

Egy memóriabeli rekord mezőjének eléréséhez a mező bájtban mért eltolását kell hozzáadni egy báziscímhez.
Ha ezeket az eltolásokat nyers számokként írjuk le, az hibalehetőséget rejt magában, és elrejti a jelentésüket.
A [`struc`][struc] és az `endstruc` ehelyett elnevezi az elrendezést, és minden mezőt egy fordításkor kiszámított szimbolikus eltolássá alakít.

A blokkon belül a `resb`, `resw`, `resd` és `resq` foglalási direktívák egy vagy több bájtot, szót, duplaszót vagy négyszeres szót foglalnak le.
Ha minden mező elé egy kezdő `.`-ot teszel, a neve a struktúrához kötve marad:

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

Most minden mezőnév az eltolását jelöli, így a `thread.color` értéke `0`, a `thread.tension` értéke `4`, a `thread.name` értéke pedig `12`.
A NASM emellett definiálja a `<struc>_size` értéket a teljes méretként, ahol a `<struc>` a `struc` neve.
Például itt a `thread_size` értéke `4 + 8 + 16 = 28` lenne.

Egy mezőt úgy érünk el, hogy az eltolását hozzáadjuk egy bázisregiszterhez, a `thread_size` pedig az egyik rekordtól a következőig tartó lépésköz:

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

A `struc` csak egy formát ír le, önmagában nem foglal memóriát.
Egy inicializált példány létrehozásához egy címke után `istruc ... iend`-et használhatsz.
Egy példányon belül az `at` egy értéket helyez el egy nevesített mezőben:

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

Figyeld meg, hogy a `thread.name` a `"warp", 0` értékkel inicializálódik, ami csak 5 bájtot foglal el.
A `struc`-ban számára lefoglalt további 11 bájtot az `iend` automatikusan `0` értékkel tölti fel, így a példányt `thread_size` méretűre egészíti ki.

A `struc` csupán szintaktikai cukorka olyan memóriához, amit kézzel is deklarálhatunk.
A fenti kód például egyenértékű a következővel, ahol a `times 11 db 0` gondoskodik arról, hogy a végén 16 bájt legyen lefoglalva:

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## Felosztás fájlokra

A makrókat gyakran külön fájlban tartjuk, és minden forrásba, amelynek szüksége van rájuk, a `%include`-dal húzzuk be:

```x86asm
%include "patterns.mac"
```

A megnevezett fájl szó szerint beillesztődik az adott helyre, a fordítás előtt, pontosan úgy, mintha a tartalmát oda írták volna be.
Így a definíciók egy helyen maradnak, és több forrásfájl is megoszthatja őket.

Ha a makrófájlt önállóan is le lehet fordítani, akkor `.asm` fájlkiterjesztéssel kell rendelkeznie.
Figyeld meg, hogy a makróknak nincs külső kapcsolatuk.
Még ha a makrófájl le is fordul, a makrói csak annak a fájlnak a számára láthatók, amely a `%include` segítségével behúzza.

Egyébként egy csak `%include`-nal behúzott fájlnak bármilyen fájlkiterjesztése lehet.
Az `.asm` vagy a `.mac` használata egyaránt bevett szokás.
