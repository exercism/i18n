# Bevezetés

A Factor szálai *kooperatív korutinok*: egyetlen operációsrendszer-szálon osztoznak, az I/O műveleteknél és a kifejezett átadási pontokon adják át egymásnak a vezérlést, és soha nem futnak valóban egyszerre. Minden, amit az átadási pontok *között* teszel, egyetlen megszakítás nélküli lépésként zajlik le. Ha viszont egy összetett művelet (olvasás-módosítás-írás) félúton átadja a vezérlést, egy másik szál közbeékelődhet, és megváltoztathatja a világot, mielőtt befejeznéd, ez pedig versenyhelyzet.

Ez a feladat négy primitívet mutat be, amelyek újra és újra előkerülnek:

## `parallel-map`, fork/join egy sorozaton

```
parallel-map ( seq quot: ( elt -- newelt ) -- newseq )
```

A [`concurrency.combinators`][combinators] szótárban található. Minden elemhez létrehoz egy szálat, lefuttatja a quotationt, majd az eredményeket ugyanabban a sorrendben egy új sorozatba gyűjti:

```factor
USING: concurrency.combinators sequences ;

{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }
```

## `spawn`, szál indítása

```
spawn ( quot name -- thread )
```

A [`threads`][threads] szótárban. A quotation párhuzamosan fut; a `name` egy címke a hibakereséshez. A visszaadott szálkezelő ezen a szinten többnyire érdektelen, egyszerűen dobd el a `drop` szóval.

## Promise-ok, egyszeri értékátadás

```
<promise>           ( -- promise )
fulfill             ( value promise -- )
?promise            ( promise -- value )
```

A [`concurrency.promises`][promises] szótárban. A promise egy egyszeri postafiók: az egyik szál teljesíti, a többiek olvassák. A `?promise` blokkol, amíg a promise teljesül, majd visszaadja az értéket.

```factor
USING: concurrency.promises kernel threads ;

<promise> [
    [ 42 swap fulfill ] curry "answer" spawn drop
] keep ?promise .
! => 42
```

A `parallel-map` valójában a `spawn` és a `<promise>` együtteséből épül fel; kézzel összeállítani őket akkor hasznos, ha az egyes részfeladatok nem pusztán „kiszámolnak egy elemet”.

A sorozaton alkalmazott tipikus fan-out/join minta így néz ki: minden bemenethez készíts egy új promise-t, indíts egy szálat, amely elvégzi a munkát és meghívja a promise-on a `fulfill`-t, gyűjtsd az összes promise-t egy sorozatba, majd mindegyiken hívd meg a `?promise`-t, hogy megvárd a befejezést. A lokális változók olvashatóbbá teszik mindezt: kösd a promise-t egy névhez a `:>` használatával egy `[| | ]` lambda belsejében, hogy az indított quotation lezárhasson fölötte:

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
inputs [| x |
    <promise> :> p
    [ x do-work t p fulfill ] "worker" spawn drop
    p
] map [ ?promise drop ] each
```

## Zárak, kölcsönös kizárás

```
<lock>     ( -- lock )
with-lock  ( lock quot -- )
```

A [`concurrency.locks`][locks] szótárban. Egy adott zárat egyszerre csak egy szál tarthat. A `with-lock` megszerzi, lefuttatja a quotationt, majd elengedi, akkor is, ha a quotation kivételt dob.

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
USING: concurrency.locks kernel locals ;

[let <lock> :> guard
    guard [ ! exclusive section ! ] with-lock
]
```

Használj zárat mindig, amikor egy értéket *több szál is olvas vagy ír*, és a rajta végzett műveletek nem eleve atomiak. Az olvasáshoz és az íráshoz egyaránt szükség van a zárra: egy olvasás, amely félúton átadja a vezérlést, szétszakadt állapotot láthat.
