# Bevezetés

## Részleges alkalmazás és függvénykompozíció

### Részleges alkalmazás

Az Elmben minden függvény [curry-zott][currying], ami azt jelenti, hogy ha úgy hívsz meg egy függvényt, hogy nem adod meg az összes argumentumot, akkor egy új függvényt ad vissza.

Az így kapott eredményt [részleges alkalmazásnak][partial-application] nevezzük (ilyenkor nem adod meg az összes argumentumot a függvénynek, hanem csak néhányat alkalmazol részlegesen).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

A részleges alkalmazás mindig sorrendben alkalmazza az argumentumokat.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

### Pipe operátor (`|>`)

Az `x |> f` pontosan ugyanaz, mint az `f x`. Egy konkrét példa: a `"5" |> String.toInt` ugyanaz, mint a `String.toInt "5"`.

Ez elsőre nem hangzik túl hasznosnak, de azért hívják [pipe operátornak][pipe-operator], mert lehetővé teszi, hogy „csővezeték-szerű” kódot írj.

Tegyük fel például, hogy van egy sanitize függvényünk, amely a felhasználói bemenetet egész számokká alakítja:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Így is átírhatjuk:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Ezzel elkerüljük a zárójelek használatát, és abban a sorrendben mutatja a függvényeket, ahogy alkalmazzuk őket (először a `String.trim`, aztán a `String.toInt`), ami segíti az olvashatóságot.

Létezik egy [fordított pipe operátor `(<|)`][reverse-pipe-operator] is.
Az `f <| x` pontosan ugyanaz, mint az `f x`.
Ez első pillantásra szintén nem tűnik túl hasznosnak, és határozottan nem használják annyit, mint a pipe operátort, de bizonyos helyzetekben segít elkerülni a zárójeleket.

### Függvénykompozíció / point free stílus

A [`(>>)`][forward-composition] operátor típusa `(a -> b) -> (b -> c) -> (a -> c)`, és egy `a -> c` típusú függvényt hoz létre két kompatibilis, `a -> b `és `b -> c` típusú függvény komponálásával.
Ezt úgy éri el, hogy az első függvény kimenetét (amely `b` típusú) veszi, és a második függvény első argumentumaként használja (amelynek szintén `b` típusúnak kell lennie).
A létrehozott függvény ugyanazt a bemenetet veszi (amely `a` típusú), mint az első függvény, és azt a `c` értéket adja vissza, amit a második függvény visszaad.

Egy konkrét példa a `String.trim >> String.toInt`.
A `String.trim` egy stringet vesz az egyetlen paramétereként, tehát a létrehozott függvény is ezt veszi.
A `String.toInt` egy `Maybe Int` értéket ad vissza, tehát a létrehozott függvény is ezt adja vissza.
A `String.trim` egy `String` értéket ad vissza, amelyet a `String.toInt` paraméterként elfogad, így a példa lefordul.

Most már így írhatjuk át a `sanitize` függvényünket:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Figyeld meg, hogy már nem használjuk az `input` paramétert, amelyet az eredeti példában láthatsz, pedig a működés ugyanaz.
Az ilyen, a paramétereikre nem hivatkozó függvények létrehozásának módját „point free stílusnak” nevezik.
Ennek a stílusnak az előnye, hogy a kód tömörebb, a hátránya, hogy nehezebb megérteni, különösen kezdőknek.

Érdemes észben tartani, hogy az Elmben minden függvény curry-zott, így a `String.length >> max` lefordul.

- A [`(>>)`][forward-composition] operátor típusa `(a -> b) -> (b -> c) -> (a -> c)`.
- A `String.length` típusa `String -> Int`, ami az `(a -> b)` rész, tehát `a` a `String`, `b` pedig az `Int`.
- A `max` típusa `Int -> Int -> Int`, ami a `b -> c` rész.
- `b` az `Int`, tehát a `max` részlegesen alkalmazott, így `c` ennek a részleges alkalmazásnak az eredménye (`Int -> Int`).
- Tehát a `String.length >> max` típusa `String -> (Int -> Int)`.
- Így a `((String.length >> max) "123") 2` visszaadja a `3`-at, mert a `"123"` hossza 3, ami nagyobb, mint az `Int` argumentumból származó 2.

### Függvénytervezés

Hogy könnyen tudj elegáns kódot írni Elmben, a fő adatszerkezetet érdemes a függvények utolsó paraméterévé tenni.
A standard könyvtár összes gyakori függvénye így működik, például a `List.map` (típusjelzése lent).

```elm
map : (a -> b) -> List a -> List b
```

Itt láthatjuk, hogy a `map` függvény utolsó paramétere `List a`, és `List b`-t ad vissza, tehát a fő adatszerkezet (`List`) az utolsó paraméter.

Ez teszi lehetővé, hogy elegáns, csővezeték-szerű kódot írj, mint például az alábbi.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Emellett kényelmessé teszi a függvénykompozíció és a point free stílus használatát is, a csővezeték-szerű írásmód alternatívájaként.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

A függvénykompozícióval ezt a példát egyetlen `List.map` hívásra is le tudod egyszerűsíteni.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
