# Bevezetés

A C++-ban a deklarációk gyakran el vannak választva a definícióktól.
A deklarációkat úgynevezett headerfájlokba csoportosítják, a hozzájuk tartozó implementációk pedig forrásfájlokba kerülnek.
A headerfájlokra gondolhatsz úgy, mint egy API-ra.
A headerfájlból megtudod, _mit_ kínál egy kódbázis, anélkül hogy a _hogyan_ részleteibe mennél.

## Header és forrás

A headerfájlok leggyakoribb kiterjesztése a `.h`.
Egyes projektek `.hpp`-t használnak, vagy teljesen elhagyják a kiterjesztést.

A definíciók egy külön `.cpp` fájlban találhatók.
A részek újraegyesítéséhez a forrásfájl azzal kezdődik, hogy _behúzza_ a megfelelő headerfájlt.

Ha írni szeretnél egy „quick_math” nevű könyvtárat, amely egy „super_root” nevű függvényt kínál, amit gyakran szeretnél használni, akkor a fájlok így néznének ki:

```cpp
// A file named quick_math.h
#pragma once

namespace quick_math {

double super_root(double x, int n);

}  // namespace quick_math
```

```cpp
// A file named quick_math.cpp
#include <cmath>

#include "quick_math.h"

double quick_math::super_root(double x, int n) {
    while (n) {
        x = std::sqrt(x), --n;
    }
    return x;
}
```

Ha olyan headert kell behúznod, amelyre csak az implementációnak van szüksége, akkor a megfelelő `#include` sorra csak a forrásfájlban van szükség.
Minden, ami a headerben be van húzva, a `.cpp` fájlban is elérhető, például az alábbi példában a `string` könyvtár.
**Figyelem**: a deklaráció után kell a `;` a headerfájlban, a definíció után viszont már nem a forrásfájlban.

## Osztályok és headerek

Az osztályok nagyon összetettekké válhatnak, és zavaró lehet, hogyan viszonyulnak a header és a forrás közötti felosztáshoz.
Az egyik lehetséges felosztás, hogy minden implementációs részletet a forrásfájlban tartasz, a deklarációkat és a tagváltozókat pedig a headerben:

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0);
    void give_water();
    std::string get_name();
    int get_size();
    void start_next_day();
};

}  // namespace robots

#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"

robots::Flower::Flower(std::string name, int size) {
    this->name = "Robotica " + name;
    this->size = size;
}

void robots::Flower::start_next_day() {
    if (!needs_water) {
        ++size;
    }
    needs_water = true;
}

std::string robots::Flower::get_name() { return name; }

int robots::Flower::get_size() { return size; }
```

Amikor a headert API-áttekintésként használják, az ember az ilyen információkat, például az alapértelmezett értékeket ott keresi.
A konstruktor `size` paraméterének alapértéke ezért a headerben van kezelve, nem az implementációban.
A forrásfájlban a definíciók elé a `robots` névtér és a `Flower` osztálytípus kerül előtagként.

Egy másik felosztási lehetőség a _header only_ könyvtár, amelynek egyáltalán nincs `.cpp` fájlja:

```cpp
// A file named robot_flower.h
#pragma once

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0) {
        this->name = "Robotica " + name;
        this->size = size;
    }
    void give_water() { needs_water = false; }
    std::string get_name() { return name; }
    int get_size() { return size; }
    void start_next_day() {
        if (!needs_water) {
            ++size;
        }
        needs_water = true;
    }
};

}  // namespace robots
```

A projektek ezeknek a felosztásoknak a kombinációit is használhatják, és sok vita folyik arról, melyik illik legjobban az egyes esetekhez.

## Include guardok

Talán észrevetted a fenti példa headerfájljában a `#pragma once` sort.
Ezt include guardnak nevezik, és biztosítja, hogy a fájl tartalma a fordítás során csak egyszer legyen behúzva, elkerülve ezzel a hibákat.
Létezik az include guardnak egy másik, összetettebb változata is, amely egy `#ifndef` sorral kezdődik és egy `#endif` sorral végződik.
Ugyanazt a célt szolgálja, és a használatát a fenti `Flower` osztály példája mutatja.
