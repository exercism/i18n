# Bevezetés

A `Complex numbers` nem bonyolult.
Csupán egy kevésbé ijesztő névre lenne szükségük.

Olyannyira hasznosak, különösen a mérnöki munkában és a tudományokban, hogy az R a komplex számokat is szabványos atomi típusként kezeli, az integer, double, logical, character és raw típusok mellett.

## Alapok

Az R-ben a `complex` szám egyetlen érték.
A gyakorlatban viszont felfoghatjuk két szám párjaként.
Ezeket sajnálatos történelmi okokból „valós” és „képzetes” résznek nevezik.
Ismét csak a lényegi egyszerűségre érdemes összpontosítani, nem a furcsa nevekre.

Ahhoz, hogy két valós számból komplex számot hozzunk létre, egyszerűen csak fűzzük az `i` utótagot a képzetes részhez.

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

Ha valós változókból szeretnénk komplex számot létrehozni, a fenti szintaxis nem működik.
Ha `r + imi`-t írunk, az összezavarja a parsert: azt hiszi, hogy az `imi` egy (nem létező) változónév.

Vagy szorozzuk meg a képzetes részt `1i`-vel, vagy használjuk a [`complex()`][ref-complex] függvényt:

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

Felmerülhet benned a kérdés, miért `i` és nem `j`?

A legtöbb mérnök a `j`-t részesíti előnyben.
A legtöbb tudós és matematikus az `i` matematikai jelölést kedveli a _képzetes_ jelentésben, ez a jelölés azonban ütközik azzal, hogy az elektrotechnikában az `i` az _áramot_ jelöli.

Az R az `i`-t választotta, a Python a `j`-t, a Julia pedig kikerülte a vitát azzal, hogy az `im`-et választotta.
Légy óvatos, amikor a [STEM][wiki-STEM] programozási nyelvek között váltasz.

A komplex szám részeihez külön-külön így férhetsz hozzá:

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

Bármelyik rész lehet nulla, és a matematikusok ilyenkor „teljesen valós” vagy „teljesen képzetes” számról beszélnek.
Az R-ben azonban ez továbbra is komplex szám.

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

Talán hallottad már, hogy „az `i` (vagy `j`) a -1 négyzetgyöke”.

Egyelőre ez csak annyit jelent, hogy a képzetes rész _definíció szerint_ kielégíti a következő egyenlőséget:

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

Ez egyszerű gondolat, de érdekes következményekhez vezet.

## Aritmetika

A lebegőpontos és egész számokkal használt operátorok többsége komplex számokkal is működik:

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

## Függvények

A matematikai függvények többsége komplex bemenettel is működik.

A `Re()` és `Im()` mellett több olyan függvény is van, amely különösen fontos a komplex számok szempontjából.

- A `Conj()` egyszerűen megfordítja egy komplex szám képzetes részének előjelét (_pluszból mínusz lesz, vagy fordítva_).
  - A komplex szorzás működése miatt ez hasznosabb, mint gondolnád.
- Az `abs(<complex number>)` garantáltan olyan valós számot ad vissza, amelynek nincs képzetes része (ez a szám „nagysága”), a `Mod(<complex number>)` pedig a szinonimája.
- Az `Arg(<complex number>)` radiánban adja vissza a fázisszöget.

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```
