# Névjegy

Elérkezett az idő, hogy rátérjünk a C++ egyik központi paradigmájára: az objektumorientált programozásra (OOP).
Az OOP középpontjában a `classes`, vagyis a felhasználó által definiált adattípusok állnak, amelyeknek saját, hozzájuk tartozó függvényeik vannak.
Kezdjük az alapokkal, a fejlettebb témákra pedig a tantervfa mélyebb szintjein térünk rá.

## Tagok

Az osztályoknak lehetnek **tagváltozóik** és **tagfüggvényeik**.
Ezeket a **tagkiválasztó** operátorral (`.`) érheted el.
Ahogy a `classes`-en kívüli változóknál is, érdemes a tagváltozókat már a deklarációkor értékkel inicializálni.
Ez az érték lesz az ebből az osztályból újonnan létrehozott objektumok alapértéke.

## Egységbezárás és információelrejtés

Az osztályok lehetőséget adnak arra, hogy korlátozzák a tagjaikhoz való hozzáférést.
A két alapvető eset a `private` és a `public`.
A `private` tagok az osztályon kívülről nem érhetők el.
A `public` tagokat szabadon meghívhatod.
Alapértelmezés szerint minden tag `private`, és ahhoz, hogy az osztályon kívülről is használhatók legyenek, kifejezetten meg kell jelölni őket.

## Egy egyszerű példa

Egy új `class` definícióját mutatja a következő példa.
Figyeld meg a definíció után álló `;` jelet.

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

Az osztályon belülről minden változóhoz hozzáférhetsz.
Nézd meg a `cast_spell` függvényben a `damage` változót.
A `private` tagokat az osztályon kívülről nem olvashatod és nem módosíthatod:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## Konstruktorok

A konstruktorok lehetővé teszik, hogy az objektum létrehozásakor értéket adj a tagváltozóknak.
A nevük megegyezik a `class` nevével, és nincs visszatérési típusuk.
Egy osztálynak több konstruktora is lehet.
Ez akkor hasznos, ha nem mindig van szükséged az összes változó beállítására.

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

A konstruktorok nagy téma, sok apró részlettel.
Ha nem definiálsz kifejezetten `constructor`-t az `class`-odhoz, akkor, és csak akkor, a fordító elvégzi helyetted a munkát.
Ez történt a fenti első példában is.
A _silverhand_ objektum az alapértelmezett konstruktor meghívásával jön létre, argumentumot nem adtunk át.
Minden változó a class definíciójában megadott értéket kapja.
Ha nem adtál volna meg értékeket abban a definícióban, a változók inicializálatlanok maradhatnak, aminek nem várt következményei lehetnek.

## Struktúrák

A struktúrák a nyelv eredeti C-s gyökereiből származnak, és olyan régiak, mint maga a C++.
Lényegében ugyanazok, mint a `classes`, egy fontos kivétellel.
Alapértelmezés szerint egy `class`-ban minden `private`.
A struktúrákban viszont minden `public`, hacsak másképp nem definiálod.
A `struct` kulcsszót a hagyomány szerint gyakran **csak adatot tartalmazó struktúrákra** használják.
A `class` kulcsszót előnyben részesítjük azoknál az objektumoknál, amelyeknek bizonyos tulajdonságokat garantálniuk kell.
Ilyen invariáns lehet például az, hogy a `Wizzard` `class`-od `damage` értéke nem válhat negatívvá.
A `damage` változó privát, és minden függvény, amely megváltoztatja a damage értékét, gondoskodik az invariáns megőrzéséről.
