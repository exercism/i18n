# Bevezetés

Vannak olyan ciklusok, amelyeket nem lehet úgy megírni, hogy »csináld ezt egy sorozat minden elemére«, hanem addig kell menni, amíg valamilyen feltétel át nem billen. A Factor `while` kombinátora épp erre való: egy predikátum quotation azt mondja, hogy »tovább?«, egy body quotation elvégzi egy lépés munkáját, a `while` pedig addig ismétel, amíg a predikátum `f`-et nem ad.

## `while` és `until`

```
while ( pred body -- )
until ( pred body -- )
```

A `pred` és a `body` is quotation, és mindkettő az adatvermen dolgozik. A `while` addig ismétel, amíg a `pred` igaz értéket hagy maga után; az `until` ennek az ellenkezője: addig ismétel, *amíg* a `pred` igazzá nem válik (vagyis amíg a `pred` `f`-et hagy).

Egyetlen állapotérték is áramolhat a vermen a predikátum és a body között:

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

Nyomkövetés: a `dup 0 >` predikátum ránéz a futó számlálóra, a `dup . 1 -` body kiírja és eggyel csökkenti, a ciklus pedig leáll, amint a számláló eléri a `0`-t. A záró `drop` eldobja ezt a végső `0`-t a veremből.

## `while*`: megőrzi a predikátum értékét

```
while* ( pred body -- )
```

A `while` számára csak az számít, hogy a predikátuma igaz értéket hagyott-e, magát az értéket eldobja, mielőtt lefuttatná a bodyt. A `while*` ezzel szemben *átadja ezt az értéket a bodynak*. Akkor nyúlj hozzá, amikor a feltétel és a body ugyanazt a frissen kiszámított dolgot akarja használni: egy keresést, egy egyezést, egy beolvasott tokent.

Itt minden név a lánc következő elemére mutat. A predikátum kikeresi az aktuális nevet, és amíg van következő név, a `while*` átadja azt a bodynak, amely kiírja, majd onnan folytatja:

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

A `links at` visszaadja a következő nevet, vagy `f`-et, ha egy névhez már nem tartozik bejegyzés. Amíg nevet ad vissza, a `while*` átadja azt a `dup .`-nak, amely kiírja, és a következő keresés kulcsaként hagyja a vermen. Az első `f` leállítja a ciklust, a `while*` eldobja, így nem marad semmi a vermen.

## Több állapotérték lokális változókkal

Amikor a ciklus egynél több értéket hordoz magával, mondjuk egy hátralévő listát és egy futó összeget, a veremmel való zsonglőrködés zajossá válik. A legtisztább minta, ha *lokálisokat* deklarálunk `::`-tal:

```
:: word ( inputs -- outputs ) ... ;
```

A bodyban a `:> name!` egy módosítható lokálist ad hozzá; olvasáshoz a `name`-et, íráshoz a `name!`-ot használjuk (ez utóbbi leveszi az új értéket a veremről, és hozzárendeli).

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

Ez a két lokális (`rest` és `running`) lefedi a teljes ciklus állapotát: a predikátum megnézi őket, a body frissíti őket, a végső érték pedig a végén adódik vissza.

Az `unclip ( seq -- rest first )` lehántja egy sorozat első elemét, ami kényelmes, amikor a ciklus iterációnként egy elemet akar elfogyasztani a listából. A `[ rest! ] dip` alak a `rest`-et a hátralévő végére frissíti, miközben az imént kivett elemet a vermen hagyja, hogy a body használhassa.
