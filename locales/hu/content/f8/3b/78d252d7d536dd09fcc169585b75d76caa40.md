# Bevezetés

A program memóriáját általában az operációs rendszer (OS) egy általános elrendezés szerint képezi le:

| cím | memóriaterület          |
| :-----: | :--------------------- |
|  magas   | verem                  |
|         | ...                    |
|         | kupac                   |
|         | olvasható-írható szegmens |
|         | kód/csak olvasható szegmens |
|   alacsony   | fenntartott               |

A szegmensekre osztott memória különböző jogosultságú szakaszokra tagolódik.

A függvények, amelyeket eddig definiáltunk, mind a **section .text** szakaszban voltak.
Ez a szakasz csak olvasható, végrehajtható adatokat tartalmaz.
Más szakaszok adatváltozók deklarálására szolgálnak; ezek lehetnek csak olvashatók vagy olvashatók és írhatók, de nem végrehajthatók.

## A .data szakasz

Az inicializált adatokat a **section .data** szakaszban deklaráljuk.

A NASM-ben (The Netwide Assembler, az ezen a kurzuson használt assembler) egy inicializált változónak van neve, egy direktívája, amely megadja az adat méretét, és egy vesszővel elválasztott értéklistája.
Ezeket szóköz választja el egymástól, a címkét pedig opcionálisan követheti egy `:`.

A legfontosabb direktívák és a hozzájuk tartozó adatméretek:

| direktíva | méret    |
| :-------: | :------ |
|    db     | 1 bájt  |
|    dw     | 2 bájt |
|    dd     | 4 bájt |
|    dq     | 8 bájt |

Például ez egy `space` nevű bájtváltozót deklarál `10` értékkel:

```x86asm
section .data
    space db 10
```

A `section .data`-ban deklarált változók módosíthatók, azaz olvashatók és írhatók.
Emellett _statikus_ tárolási időtartamúak, ami azt jelenti, hogy a program teljes futása alatt léteznek.

## A .rodata szakasz

A **section .rodata** hasonló a `section .data` szakaszhoz.
Mindkét szakasz inicializált adatokat tartalmaz, amelyeket ugyanúgy deklarálunk, és amelyeknek ugyanannyi a tárolási időtartama.

A fő különbség köztük az, hogy a `section .rodata`-ban lévő adatok megváltoztathatatlanok, azaz csak olvashatók.

~~~~exercism/note
A `equ`-val definiált konstansok különböznek a `section .rodata`-ban definiáltaktól.

Az `equ`-val definiált konstans nem foglal helyet a memóriában, és az assembler közvetlenül az értékével helyettesíti.
Valójában csak egy helyőrző az adott érték számára.

Ezzel szemben a `section .rodata`-ban definiált konstansok valóban a memóriában tárolódnak, és van címük.
~~~~

## Az adatok elérése

### Címkék és indirekció

A deklarált adathoz névnek kell tartoznia.
Ezt a nevet **címkének** nevezzük.

A címke egy szimbólum, amely az adat memóriabeli konkrét címét kódolja.
**Az x86-64-ben a címek 64 bites értékek**.

A NASM-ben, ha az adatot közvetlenül a címkéjével próbálod elérni, nem a lefoglalt memóriát kapod meg, hanem annak a címét:

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

Ahhoz, hogy egy memóriacím tartalmát elérd, _dereferálni_ kell azt.
Ezt **indirekciónak** nevezzük.

A NASM-ben erre a `[]` szolgál:

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

Vannak azonban olyan helyzetek, amikor kétértelmű lehet a dereferált memória mérete.
Ilyenkor egy előtaggal kell megadni ezt a méretet.

Ezek a legfontosabb előtagok és a méreteik egy tipikus x86-64 programban:

| előtag | méret    |
| :----- | :------ |
| byte   | 1 bájt  |
| word   | 2 bájt |
| dword  | 4 bájt |
| qword  | 8 bájt |

Ugyanez a betöltés írható úgy is, hogy a méretet kifejezetten megadjuk:

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

Jó gyakorlat, ha a memória dereferálásakor mindig használsz előtagot.

### Írás a memóriába

A memóriába írás ugyanígy történik, egy cím dereferálásával:

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

Figyeld meg, hogy a legtöbb utasításban használhatsz memóriaoperandusokat anélkül, hogy előbb betöltenéd a tartalmukat egy regiszterbe.
Általában azonban nem lehet őket egyszerre a forrás- és a céloperandusban használni, csak az egyikben:

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### Az LEA utasítás

Bár a `mov` is használható arra, hogy egy változó címét egy regiszterbe tároljuk, erre a célra van egy külön utasítás: **lea**.

Ez az utasítás memóriaformájú operandust használ, de _nem_ olvassa a memóriát.
Ehelyett kiértékeli az effektív cím kifejezését, és az eredményt a céloperandusba írja:

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

Idiomatikusabb a `lea`-t használni memóriacímek kiszámítására és regiszterekbe tárolására.

### Relatív címzés

A memóriahelyek elérésekor a NASM alapértelmezett viselkedése, hogy **abszolút címeket**, azaz rögzített memóriacímeket generál.

Biztonsági okokból a futtatható fájlokat gyakran **PIE (Position Independent Executable)** formátumban készítik el, ahol a memóriaterületek véletlenszerű helyekre kerülnek.
Egy `PIE`-ban a változó végleges címe nem ismert a linkelés idején.
Ezért a kód a címeket egy `rip` nevű speciális regiszter értékéhez viszonyított eltolásként számítja ki, amely a következő végrehajtandó utasításra mutat.

Ezt szokás **RIP-relatív címzésnek** nevezni.

A NASM-ben a `rel` operátorral kérhetsz RIP-relatív elérést:

```x86asm
mov rax, qword [rel variable]
```

A relatív címzés egy forrásfájl alapértelmezett beállításává is tehető, ha a fájl elejére beírod a `default rel` sort.

Ezen a kurzuson minden feladat `PIE`-ként van lefordítva és linkelve, ezért a relatív címek generálásához a `rel`-t érdemes használni.

### Láthatóság

Bármely szakaszban (például `.text`, `.data`, `.rodata`) definiált címke (függvények és adatok) látható ugyanazon forrásfájlon belül.
Ha `global`-ként deklaráljuk őket, más forrásfájlokból is láthatók.

Fordítva, a más forrásfájlokban definiált címkék akkor láthatók az aktuális forrásfájlból, ha `extern`-ként vannak deklarálva.
Ebben az esetben az assemblyben nincs utalás az adat méretére, azt előre ismerni kell.

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
