# Leírás

## Boolean értékek a Juliában

Az igaz és hamis értékeket a `Bool` típus ábrázolja.
Csak két értéket tartalmaz: `true` és `false`.

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

Számos más nyelvvel ellentétben a Juliában szándékosan nincs „truthiness” fogalom, és csak azok a kifejezések minősülnek `Bool`-nak, amelyek `true` vagy `false` értékre értékelődnek ki.

Konkrétan: az üres tömbök vagy stringek *nem* értelmeződnek `false`-ként.
Ha külön szeretnéd kezelni az üres értékeket, megfelelő vizsgálatra lesz szükség, például az `isempty()` használatára.

## Boolean operátorok

A Juliában három [Boolean operátor][boolean-operators] van.

A `&&` a Boolean „és”.
`true`-ra értékelődik ki, ha a `&&` *mindkét* oldalán szereplő kifejezés `true`.

```julia-repl
julia> true && true
true

julia> true && false
false
```

A `||` a Boolean „vagy”.
`true`-ra értékelődik ki, ha a `||` *valamelyik* oldalán szereplő kifejezés `true`.

```julia-repl
julia> true || true
true

julia> false || true
true
```

A `!` a Boolean „nem”.
Felcseréli (megfordítja) a `true` és `false` értékeket.

```julia-repl
julia> !true
false

julia> !false
true
```

A hasonló operátorok fogalmilag ismerősek lehetnek sok más nyelv használói számára, bár a pontos szintaxis nyelvenként eltérhet.

## Az operátorok precedenciája

Bonyolultabb kifejezésekben hasznos lehet tudni, hogy a `&&` [precedenciája][operator-precedence] kicsit nagyobb, mint a `||`-é *(ugyanúgy, ahogy az aritmetikai kifejezésekben a `*` előbb érkezik, mint a `+`)*.

Ha erre alapozol, könnyen zavaros és hibalehetőségekkel teli kód születik.
Az áttekinthetőség kedvéért zárójelekkel tedd egyértelművé a szándékodat.

## Rövidzárási kiértékelés

Függ-e a `true || x` kifejezés `x` értékétől, vagy a fordító figyelmen kívül hagyhatja `x`-et?

A Julia a Boolean kifejezéseket balról jobbra értékeli ki, és megáll, amint egyértelmű eredményhez jut.

Például a `true || x` mindenképpen `true` kell legyen `x`-től függetlenül, így `x` ki sem értékelődik.
Hasonlóképpen a `false && y` `false`, és nem szükséges kiértékelni `y`-t.

Fordított esetben a `true && x` *csak akkor* `true`, ha `x` is `true`, így `x`-et ki kell értékelni.

Hasonlóképpen, ha több operátort fűzünk egymás után:

```julia-repl
julia> true && false && something_else
false
```

Mivel a `true && false` mindenképpen `false`, a `something_else` lényegtelen, és a fordító figyelmen kívül hagyja.

Ebben az esetben a `something_else` nem létezett változóként, de ebben a kontextusban nem okozott hibát *(próbáld ki a REPL-ben, ha kételkedsz benne)*.

A Julia-programozók gyakran használják a rövidzárási kiértékelést arra, hogy elkapják a futásidejű problémákat és a szélsőséges eseteket:

```julia
all_ok || do_something()

is_problem && do_something_else()
```

A `do_something` például egy korai `return` lehet a függvényből, ha `all_ok` `false`, vagy egy változó alapértelmezett értékének beállítása a folytatás előtt.

Ez némileg visszaélés a Boolean szintaxissal, de nagyon kényelmes lehet.

## Hogyan működnek a `Bool`-ok a háttérben

Ha egy `Bool` *aritmetikai* kifejezésbe kerül, a `true` `1`-ként, a `false` pedig `0`-ként értelmeződik, ami azt tükrözi, hogyan tárolódnak.

Ha alacsonyabb szintű nyelvekhez (C és hasonlókhoz) vagy szokva, *kérlek*, kerüld ennek gyakori használatát.
Rontja a kód olvashatóságát, és megnehezíti a hibakeresést.

Néha láthatod, hogy a számértékeket arra használják, hogy gyorsan megszámolják, hány dolog `true`.

```julia-repl
julia> true + false + true
2
```
