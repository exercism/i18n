# Tesztek

Minden feladathoz tartoznak az egységtesztek, és minden, amire a lefordításukhoz és a futtatásukhoz szükség van.
A megvalósítást neked kell elkészítened.

## A tesztek futtatása

Nyiss egy terminált a feladat mappájában, és futtasd:

```
make
```

Ez lefordítja a megoldásodat és a teszteket, majd lefuttatja a teszteket.
Futtasd újra minden alkalommal, amikor módosítasz a megoldásodon.

Ha az [Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally) a rendelkezésedre áll, helyette ezt a parancsot is használhatod, amely szintén lefuttatja a `make`-et:

```
exercism test
```

A build során létrehozott fájlok eltávolításához futtasd a `make clean` parancsot.

### `make` nélkül

Ha nincs `make` (például Windowson), közvetlenül is lefordíthatod és lefuttathatod a teszteket.
A „Bob” feladat esetében:

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

Ezután futtasd a teszteket Linuxon vagy macOS-en:

```
./run_tests
```

Windowson pedig:

```
.\run_tests
```

## Egy feladat végigvitele

A feladatok fájljai a feladat nevét viselik.
A „Bob” feladat esetében:

| Fájl             | Tartalom                                                          |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90`        | a megoldás váza, amelyet neked kell kiegészítened                 |
| `bob_test.f90`   | a tesztek                                                         |
| `TesterMain.f90` | a tesztkönyvtár                                                   |
| `Makefile`       | utasítások a `make` számára                                       |
| `CMakeLists.txt` | utasítások a [CMake](#using-cmake-instead) számára, amely nem kötelező |

Csak a megoldás fájlját kell szerkesztened.

Az egyes feladatok végigvitele azt jelenti, hogy ismétled a következő lépéseket, amíg minden teszt sikeres nem lesz:

- Javítsd ki a fordítási hibákat, majd futtasd a teszteket, hogy lásd, melyek buknak el.
- Valósíts meg éppen annyit, hogy a következő elbukó teszt sikeres legyen.
- Alakítsd át a megvalósítást az olvashatóság javítása, a kódismétlés csökkentése stb. érdekében.
- Futtasd újra a teszteket, és lépj tovább a következő elbukó tesztre.

Minden elbukó tesztnél kiíródik egy üzenet, majd egy összegzés következik.
Ha bármelyik teszt elbukik, a `make` hibával ér véget.

Minden tesztnél egy komment írja le a tesztet, majd maga a teszt következik, amely `call assert_equal`-lel kezdődik, például.

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Egy teszt letiltásához egyszerűen kommenteld ki egy `'!'`-lel, például.

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## CMake használata helyette

Nincs szükséged CMake-re, de hasznos lehet, ha olyan IDE-ben dolgozol, mint a Visual Studio vagy az Xcode, vagy ha nem GFortrannal fordítasz.

A feladat mappájának meg kell tartania az eredeti nevét, mert a CMake ebből keresi meg a forrásfájlokat.
Indulj ki a feladat mappájából:

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

Miután módosítottál a megoldásodon, már csak az utolsó két parancsra van szükség.

**Megjegyzés:** a `cmake`-et mindig külön mappából futtasd, például a `build` mappából.
Ha a feladat mappájában futtatod a `cmake .` parancsot, felülírja a feladathoz tartozó `Makefile`-t.

A CMake egy, a rendszeredhez illő generátort választ.
Ha másikat szeretnél, használd a `-G` kapcsolót, például: `cmake -G Xcode ..`.
A használható generátorokat a `cmake --help` futtatásával listázhatod.
Visual Studióval vagy Xcode-dal a `ctest -V -C Debug` paranccsal futtathatod a teszteket.

Ha a feladat mappájában nincs `Makefile`, akkor a mappa még azelőtt lett letöltve, hogy ezek a fájlok bekerültek volna a feladatokba.
A CMake-et ettől még használhatod.
