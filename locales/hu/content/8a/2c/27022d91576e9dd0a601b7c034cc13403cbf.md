# Bevezetés

## Kivételek

Az Elixirben minden hiba az _Exception viselkedést_ valósítja meg. Ahogy az _Access viselkedés_, úgy az _Exception viselkedés_ is visszahívó függvényeket definiál, amelyeket egy modulnak meg kell valósítania, hogy teljesítse a viselkedés szoftverszerződését. Miután egy hiba definiálva van, a következő tulajdonságokkal rendelkezik:

- A modul neve határozza meg a hiba nevét.
- A modul definiál egy hibastruktúrát.
- A struktúrának lesz egy `:message` mezője.
- A modul a `raise/1` és `raise/2` segítségével használható a kívánt hiba dobására

Az _Exception viselkedés_ emellett két visszahívó függvényt is meghatároz: a `message/1`-et és az `exception/1`-et. Ha nem valósítod meg őket, a rendszer az alapértelmezett megvalósításokat használja. A `message/1` a `raise` hívásakor a hibastruktúrát olvasható üzenetté alakítja. Az `exception/1` lehetővé teszi, hogy a `raise/2` hívásakor további kontextust adj az üzenethez

### Kivétel definiálása

Ahhoz, hogy egy hibamodulból kivételt definiáljunk, a `defexception` makrót használjuk:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

### Kivételek használata

A definiált hibák ugyanúgy használhatók, mint a beépített hibák, akár a `raise/1`, akár a `raise/2` segítségével.

- A `raise/1` a modul nevével dob egy adott hibát, vagy ha az argumentum egy string, akkor egy `RuntimeError`-t dob, amelynek az üzenete maga a string.
- A `raise/2` a modul nevével dob egy adott hibát, és elfogad egy attribútumokat tartalmazó argumentumot, amelynek segítségével a megfelelő üzenetű hiba áll elő.
