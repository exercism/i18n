# Névjegy

## Hibák a `jq`-ban

A `jq` két nagy hibakategóriát különböztet meg:

1. **Fordítási idejű hibák**: maga a program érvénytelen, például szintaktikai hiba, nem definiált függvényre vagy változóra való hivatkozás és hasonlók.
   A `jq` ilyenkor egyáltalán nem hajlandó lefuttatni a programot.

   ```sh
   $ jq -n '1 + $foo + 2'
   jq: error: $foo is not defined at <top-level>, line 1, column 5:
       1 + $foo + 2
           ^^^^
   jq: 1 compile error
   ```

2. **Futásidejű hibák**: a program érvényes, de valami hiba történik egy érték feldolgozása közben. Ilyen például, ha egy számot stringgel indexelsz, ha érvénytelen JSON szöveget adsz át a `fromjson`-nak, vagy ha egy függvényt rossz típusú argumentumokkal hívsz meg.

   ```sh
   $ echo '42' | jq '.foo'
   jq: error (at <stdin>:1): Cannot index number with "foo"
   ```

Ez a fogalom a **futásidejű hibákról** szól: hogyan kelts hibát, hogyan kapd el, és hogyan állítsd le a programot.

Ha egy futásidejű hibát nem kap el senki, a `jq` üzenetet ír a _standard error_ kimenetre, és az `5` státusszal lép ki.

## Hibák keltése: `error` és `error(message)`

Az [`error`][man-error] szűrő hibát kelt.

- Az `error` olyan hibát kelt, amelynek értéke a **bemeneti** érték.
- Az `error(message)` olyan hibát kelt, amelynek értéke a `message` eredménye.

```jq
"bad input" | try error catch .
# => "bad input"

42 | try error("invalid value: \(.)") catch .
# => "invalid value: 42"
```

~~~~exercism/note
A hiba értéke _bármilyen_ JSON érték lehet, nem csak string.
A strukturált hibák keltésével a `catch` kezelő döntéseket hozhat a hiba tartalma alapján.

```jq
try error({kind: "range", msg: "age must be non-negative"})
catch (if type == "object" then "\(.kind) error: \(.msg)" else "unexpected: \(.)" end)
# => "range error: age must be non-negative"
```
~~~~

Ha egy nem string típusú hibaértéket nem kap el senki, a `jq` JSON-ként írja ki, `(not a string)` jelzéssel.

```sh
$ jq -n 'error({code: 42, msg: "boom"})'
jq: error (at <unknown>) (not a string): {"code":42,"msg":"boom"}
```

## Hibák elkapása: `try` és `catch`

A hibákat a [`try EXP catch HANDLER`][man-try-catch] szerkezettel kaphatod el.
Először az első kifejezés fut le; ha az hibát kelt, akkor a `HANDLER` kifejezés fut le, **bemenetként a hibaértéket kapva**.
A kezelő kimenete úgy jelenik meg, mintha a védett kifejezés kimenete lett volna.

```jq
true | try .a catch "cannot index a \(type)"
# => "cannot index a boolean"

[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]

true | try error("some exception") catch .
# => "some exception"
```

A rövidebb `try EXP` forma ugyanazt jelenti, mint a `try EXP catch empty`: a hiba elvész, és nem lesz kimenet.

```jq
[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]
```

~~~~exercism/note
A hiba **megszakítja az adatfolyam hátralévő részét** a `try`-n belül.
A már kiadott értékek megmaradnak, de a hiba utáni részt már semmi nem értékeli ki.

```jq
jq -n 'try (1, error("x"), 3) catch "caught: \(.)"'
# outputs:
# 1
# "caught: x"
# (3 is never produced)
```
~~~~

A kezelő új hibát is kelthet, vagy egy sima `error` hívással továbbadhatja az eredetit: mivel a hibaérték a kezelő bemenete, így változatlanul továbbterjed.

```jq
try repeat(f) catch
  if . == "break" then empty else error end
```

## Hibák elnyomása: a `?` operátor

A [`?` operátor][man-question-mark] `EXP?` alakban a `try EXP` szerkezet rövidítése.
A hibát okozó kifejezést olyanná alakítja, amely egyszerűen nem ad kimenetet.

```jq
["1", "invalid", "3", 4] | [.[] | tonumber?]
# => [1, 3, 4]

true | [.a?]
# => []
```

Gyakran indexelő operátorokhoz kapcsolva találkozhatsz vele:

- A `.foo?` ugyanaz, mint a `.["foo"]?`
- A `.[]?` csak akkor iterál, ha a bemenet tömb vagy objektum, egyébként üres

~~~~exercism/caution
A `?` **minden** hibát elnyom, még azokat is, amelyekre nem számítottál.
A `user.name?` csendben semmilyen kimenetet nem ad, ha a `user` nem objektum, és ez elrejtheti a programod adatproblémáit vagy elgépeléseit.
Ha tudni akarod, hogy _valami_ elszállt-e, inkább a `try ... catch` szerkezetet használd, vagy ellenőrizd kifejezetten a bemenetet.
~~~~

## Az alternatív operátor `//`

A programozók néha azt várják, hogy az `a // b` `b`-t ad, ha az `a` elszáll.
Ez igaz volt a `jq` régi verzióiban, de a `jq` 1.6 óta már nem.
A `//` operátor nem nyomja el a hibákat.
Csak akkor lép `b` a helyére, ha az `a` nem ad semmilyen értéket, vagy `false`-t, illetve `null`-t ad; az `a`-ban keletkező hibák viszont továbbterjednek.

```sh
$ jq -n '(error("x")) // 42'
jq: error (at <unknown>): x
```

Ha tartalékértéket szeretnél hiba esetére, használd a `try a catch b` szerkezetet.

## A destrukturáló alternatív operátor `?//`

A [`?//` operátor][man-question-mark-slash-slash] a destrukturálást kombinálja a hibakezeléssel.
Sorban kipróbálja az egyes kötési mintákat, amíg az egyik sikerül, a sikertelen alternatívák által kötött változók értéke pedig `null` lesz.

```jq
# input:
#   [
#     {"a": 1, "b": 2, "c": {"d": 3, "e": 4}},
#     {"a": 5, "b": 6, "c": [{"d": 7, "e": 8}]}
#   ]

.[] as {$a, $b, c: {$d, $e}} ?// {$a, $b, c: [{$d, $e}]}
| {$a, $b, $d, $e}

# outputs:
# {"a": 1, "b": 2, "d": 3, "e": 4}    # first element: c is an object, first pattern matched
# {"a": 5, "b": 6, "d": 7, "e": 8}    # second element: c is an array, second pattern matched
```

Itt az első minta azt várja, hogy a `c` egy _objektum_ legyen `d` és `e` kulccsal, a második pedig azt, hogy a `c` egy ilyen objektumot tartalmazó _tömb_ legyen.
Az első bemeneti elem az első mintával kötődik; a második elem nem illeszkedik erre a mintára, ezért a második mintával próbálkozik.

Így egyetlen program is destrukturálhat olyan bemeneteket, amelyek többféle alakot ölthetnek, anélkül hogy kifejezett `if type == ...` láncokat kellene írnod.

## A program leállítása: `halt` és `halt_error`

Néha a helyes válasz egy hibára az, hogy teljesen leállítod a feldolgozást.

- A [`halt`][man-halt] azonnal leállítja a `jq` programot, további kimenet nélkül; a kilépési státusz `0`.
- A [`halt_error`][man-halt-error] leállítja a programot, a **bemenetét** nyers szövegként kiírja a _standard error_ kimenetre (semmi díszítés, még egy sortörés sem), és a megadott státusszal lép ki, amely alapértelmezés szerint `5`.

```sh
$ echo '"Error: something went wrong"' | jq 'halt_error(1)'
Error: something went wrong    # printed on stderr, exit status 1
```

Vedd figyelembe, hogy ezek a szűrők azonnal leállítják a programot, akkor is, ha még több bemenet olvasásra vár.

### Kilépési státuszok

Referenciaként íme a `jq` által használt kilépési státuszok:

| Státusz | Jelentés                                         |
| :----: | ------------------------------------------------ |
| `0`    | siker                                            |
| `2`    | használati hiba (rossz parancssori kapcsolók)    |
| `3`    | fordítási hiba                                   |
| `5`    | futásidejű hiba (vagy `halt_error` argumentum nélkül) |

A `--exit-status` / `-e` kapcsolóval a státusz helyette az utolsó kimeneti értéket tükrözi: `0` a `true` vagy számok esetén, `1` a `false` vagy `null` esetén, `4` pedig kimenet nélkül.

## Hibakeresési segédeszközök

Amikor azt keresed, honnan jön egy hiba, ezek a szűrők segítenek:

- A [`debug`][man-debug] változatlanul átengedi a bemenetét, de kiírja a `["DEBUG:", <input>]` értéket a standard error kimenetre.
  A `debug(msgs)` a `msgs`-et is debug üzenetként írja ki.
- A [`stderr`][man-stderr] a bemenetét nyersen és tömören kiírja a standard error kimenetre.
- Az [`input_line_number`][man-input-line-number] annak a bemenetnek a sorszámát adja ki, amelyet éppen szűr, ami felbecsülhetetlen értékű, ha egy fájl sok JSON szöveget tartalmaz, és az egyik hibás.
- A [`$__loc__`][man-loc] egy `file` és `line` kulcsú objektumot ad ki, amely megmondja, hol található a programban; ezt beépítheted a hibaüzeneteidbe.

```jq
def checked_div($d):
  if $d == 0
  then error("\($__loc__): division by zero")
  else . / $d end;

try (10 | checked_div(0)) catch .
# => "{\"file\":\"<top-level>\",\"line\":3}: division by zero"
```
