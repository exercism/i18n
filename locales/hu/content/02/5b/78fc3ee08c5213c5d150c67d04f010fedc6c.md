# Tippek

Az `Option` olyan számítást jelöl, amelynek esetleg nincs hasznos eredménye
(például hiba vagy érvénytelen bemenet miatt).
Ha még nem ismered az `Option` típust, elolvashatod [ezt az útmutatót](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html).
Az `Option` egy úgynevezett [monád](https://en.wikipedia.org/wiki/Monad_(functional_programming)), amely egy „számítási szempontot” fed le, jelen esetben azt, hogy egy érték hiányozhat.
A monádok helyes használata nagyon tömör, mégis elegáns
és olvasható kódot eredményezhet. A helytelen használat könnyen az ellenkezőjét hozhatja.
Nézd meg [ezt a videót](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA), hogy többet megtudj.

## Gyakori buktatók, amelyeket érdemes elkerülnöd

Néhány ökölszabály segít az `Option` használatában:
1. Ha nem kell, ne használd. Ahelyett, hogy
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
jobb, ha ezt írod:
```scala
def add1(x: Int): Int = x + 1
```
(erre való az `Option.map`, amivel az ilyen egyszerű függvényeket alkalmazhatod,
így nem kell őket `Option` értékekkel teletűzdelned).
2. Ne „csomagold ki” az értéket, ha valójában nincs rá szükséged.
Az esetedre gyakran vannak beépített függvények. A korai
kicsomagolás jele lehet az `isDefined/isEmpty` vagy a mintaillesztés. Ahelyett, hogy
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
jobb, ha ezt írod:
```scala
x map (_ + 1) getOrElse 0
```
3. A monádokat akár for-comprehension belsejében is használhatod. Ez a nyerő megoldás.
Ez akkor ajánlott, amikor több `Option` példányt szeretnél „összefűzni”. Ahelyett, hogy
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
jobb, ha ezt írod:
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
