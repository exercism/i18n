# Tulajdonjog

Cairoban a tulajdonjog fogalma a _változókhoz_ kapcsolódik, nem pedig az általuk tárolt _értékekhez_.

A Cairoban az értékek változtathatatlanok, ez a változtathatatlanság biztosítja, hogy még ha sok változó is ugyanarra az értékre hivatkozik, maga az érték állandó és változatlan marad.
A fordítónak tehát biztosítania kell, hogy a programozó helyesen használja őket.
Ez a jelentése a változó _tulajdonjogának_: a tulajdonos az a kód, amely olvashatja (és írhatja is, ha módosítható) a változót.

## A változók tulajdonjogának szabályai

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## A változó scope-ja

A scope egy program azon tartománya, amelyben egy változó érvényes.
Nézzük meg a következő példát, amely egy `x` változót deklarál előjel nélküli egész típusúként, és a megjegyzések jelzik, hogy hol érvényes a változó:

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

Megjegyzések:

- Amikor `x` bekerül a scope-ba, érvényes.
- Érvényes marad, amíg ki nem kerül a scope-ból, ebben az esetben a `main()` függvény végéig.

## Értékek mozgatása

Mozgatás akkor következik be, amikor egy értéket átadunk egy másik függvénynek, megsemmisítve az eredeti változót, amely az értékre hivatkozott (ezáltal a változó használhatatlanná válik), és létrehozva egy új változót ugyanazon érték tárolására.

A tömbök példa egy olyan összetett típusra, amely mozgatásra kerül, amikor átadjuk egy másik függvénynek.
Íme egy rövid emlékeztető, hogyan néz ki egy tömb:

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

Hogyan biztosítja a típusrendszer, hogy a Cairo program soha ne próbáljon kétszer ugyanabba a memóriacellába írni?
Tekintsük a következő kódot, ahol kétszer próbáljuk eltávolítani a tömb elejét:

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

Ebben az esetben ugyanazt az értéket (a `arr` változóban lévő tömböt) próbáljuk átadni mindkét függvényhívásnak.
Ez azt jelenti, hogy a kódunk kétszer próbálja eltávolítani az első elemet, ez pedig kétszer próbál ugyanabba a memóriacellába írni, amit a Cairo VM tilt, és ez futásidejű hibát okoz.
Szerencsére ez a kód valójában nem fordul le.
Miután átadtuk a tömböt a `foo` függvénynek, az `arr` változó már nem használható.
Ezt a fordítási idejű hibát kapjuk, amely azt mondja, hogy az `Array` típusnak implementálnia kellene a `Copy` traitet:

## A Copy trait

Ha egy típus implementálja a `Copy` traitet, akkor a függvénynek való átadás nem mozgatja az értéket, hanem létrehoz egy új változót, amely ugyanarra az értékre hivatkozik.
Ez ingyenes művelet, mert a változók a Cairo absztrakcióját képezik, az értékek pedig mindig változtathatatlanok.

Ahhoz, hogy a `Copy` traitet implementáld a típusodon, add hozzá a `#[derive(Copy)]` annotációt a típusdefinícióhoz.
A Cairo azonban nem engedi ezt, ha a típus vagy annak bármely összetevője nem implementálja a `Copy` traitet.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## Értékek megsemmisítése

A lineáris típusok úgy is felhasználhatók, hogy megsemmisítjük őket, ami biztosítja, hogy a kapcsolódó erőforrás megfelelően felszabaduljon.
Ezt a `Drop` trait implementálásával vagy származtatásával érjük el, amely jelzi a fordítónak, hogy a típus biztonságosan megsemmisíthető, amint már nem hasznos.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

Jelenleg a `Drop` implementáció minden típusra származtatható, kivéve a szótárakat (`Felt252Dict`) és a szótárakat tartalmazó típusokat.
Ez azért van, mert a szótárakat a megsemmisítésükkor „össze kell squasholni”.
Ehhez a `Destruct` traitet származtatjuk:

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## Visszatérési értékek és scope

Az értékek visszaadása egyenértékű a mozgatásukkal.
Az alábbi példa egy olyan függvényt mutat be, amely visszaad egy értéket:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
