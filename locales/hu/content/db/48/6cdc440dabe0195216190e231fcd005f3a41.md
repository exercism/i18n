# Részletesen

Az olyan osztályok, mint a `LocalDate` és a `LocalDateTime`, az idő egy _pontját_ írják le.
A `java.time` csomagban van két olyan osztály is, amely az idő egy _mennyiségét_ írja le:

- A [`Period`][period-docs] dátumalapú időmennyiség években, hónapokban és napokban kifejezve, például „2 hónap és 5 nap”.
- A [`Duration`][duration-docs] időalapú időmennyiség órákban, percekben, másodpercekben, ezredmásodpercekben és nanoszekundumokban, például „1 óra és 30 perc”.

A különbség azért számít, mert a naptári egységek hossza nem rögzített.
Egy hónap 28, 29, 30 vagy 31 napos is lehet, tehát az „egy hónap” nem rögzített számú másodperc.
A `Period` a naptárt követi, a `Duration` viszont pontos időt mér.

| | `Period` | `Duration` |
| --- | --- | --- |
| Mit tárol | éveket, hónapokat és napokat | másodperceket és nanoszekundumokat |
| Mivel használható | `LocalDate`, `LocalDateTime` | `LocalTime`, `LocalDateTime`, `Instant` |

Mindkét osztály módosíthatatlan.
Az olyan metódusok, mint a `plusDays()` vagy a `multipliedBy()`, egy _új_ példányt adnak vissza, az eredetit pedig változatlanul hagyják.

## `Period`

### Periódus létrehozása

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

A `toString()` eredménye az [ISO 8601-es időtartamformátumot][iso-8601-durations] használja: egy `P` betűt, majd az évek (`Y`), a hónapok (`M`) és a napok (`D`) számát.
A `Period` nem ismeri a heteket: a `Period.ofWeeks(2)` 14 napként tárolódik.
Ugyanez a jelölés a `Period.parse()` metódussal olvasható vissza:

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### Periódus hozzáadása egy dátumhoz

Egy dátumhoz a `plus()` és a `minus()` metódussal adhatsz hozzá vagy vonhatsz ki periódust:

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

Ugyanígy adhatsz hozzá periódust egy `LocalDateTime`-hoz is, és a napszak változatlan marad:

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

Az `Instant`-nek nincs naptára, ezért csak napokban megadott periódust adhatsz hozzá.
Az éveket vagy hónapokat tartalmazó periódus kivételt dob:

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

Először az éveket adja hozzá, aztán a hónapokat, végül a napokat.
Ha az évek vagy hónapok hozzáadása olyan napra esik, amely nem létezik, az eredmény visszakerül az adott hónap utolsó érvényes napjára:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

Ez azt is jelenti, hogy ha hozzáadsz egy periódust, majd újra kivonod, nem mindig az eredeti dátumot kapod vissza:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### A két dátum közötti periódus

A `Period.between()` az egyik dátumtól (beleértve) a másikig (nem beleértve) tartó periódust adja vissza.
Ugyanezt az eredményt a `LocalDate.until()` is megadja:

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

A periódus részeit a `getYears()`, a `getMonths()` és a `getDays()` metódussal kérdezheted le.
Ezek a részek függetlenek egymástól: a `getDays()` csak a napok részét adja vissza, nem a napok összes számát.
A `toTotalMonths()` az éveket és a hónapokat együtt, hónapok számaként adja vissza, a napok összes számára viszont nincs metódus, mert az attól függ, mely hónapokról van szó.

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### Periódus normalizálása

A gyártó metódussal létrehozott periódus pontosan úgy tartja meg az egységeit, ahogy megadtad, az `equals()` pedig az egységeket egyenként hasonlítja össze.
A `normalized()` a hónapokat átváltja évekké, a napokhoz viszont nem nyúl:

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## Egységek számlálása a `ChronoUnit` segítségével

Ha két időpont között egyetlen egység összes számát szeretnéd megkapni, használd a [`ChronoUnit`][chronounit-docs] valamelyik konstansának `between()` metódusát:

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

Csak a teljes egységeket számolja, és az eredmény negatív, ha a második argumentum korábbi, mint az első:

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

A `ChronoUnit` időalapú egységekkel és dátum-időkkel is működik:

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### Időtartam létrehozása

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

Az ISO 8601-es jelölésben a `T` választja el a dátum részt az idő résztől.
A `Duration`-nek nincs dátum része, ezért a `toString()` mindig `PT`-vel kezdődik.
A `Duration.ofDays()` egy napot pontosan 24 órának tekint.

Egy időtartamot a `Duration.parse()` metódussal is beolvashatsz:

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### Időtartam hozzáadása egy időponthoz

Egy `LocalTime`-hoz, `LocalDateTime`-hoz vagy `Instant`-hez a `plus()` és a `minus()` metódussal adhatsz hozzá vagy vonhatsz ki időtartamot:

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

A `LocalTime` átfordul éjfélkor, ahogy az utolsó példa is mutatja.

A `LocalDate`-nek nincs idő része, ezért nem kombinálható `Duration`-nel:

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### A két időpont közötti időtartam

A `Duration.between()` a két időpont vagy dátum-idő között eltelt pontos időt adja vissza:

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

A `Duration.between()` nem fogad el két `LocalDate` értéket, mert egy dátumnak nincsenek mérhető másodpercei:

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

Dátumokhoz használd inkább a `Period.between()` vagy a `ChronoUnit.DAYS.between()` metódust.

### Időtartam átváltása

A `toXxx()` metódusok egy időtartamot egyetlen egység _összes_ mennyiségévé váltanak át, lefelé kerekítve:

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

A `toXxxPart()` metódusok egy időtartamot részekre bontanak, ahogy az órán is látod:

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

A `toHoursPart()` 23-nál megáll, mert az efeletti órákat a `toDaysPart()` számolja.

### Összehasonlítás és számítás időtartamokkal

Az időtartamokat a `compareTo()` metódussal hasonlíthatod össze, az `isZero()` és az `isNegative()` metódussal pedig ellenőrizheted:

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

Aritmetikai műveleteket is támogatnak, például a `plus()`, a `minus()`, a `multipliedBy()` és a `dividedBy()` metódust:

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## `Period` vagy `Duration`?

`LocalDate` vagy `LocalTime` esetén nem is kell választanod: a dátumnak nincs mérhető ideje, az időnek pedig nincs naptára.
A `LocalDateTime`-ban mindkettő megvan, de időzóna nélkül, ezért ha `Period.ofDays(1)`-et vagy `Duration.ofDays(1)`-et adsz hozzá, ugyanazt az eredményt kapod.
A különbség időzónákkal válik láthatóvá.
Amikor a nyári időszámítás miatt előreállítják az órákat, egy naptári nap csak 23 óra hosszú:

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

Egy napnyi `Period` hozzáadása megtartja a napszakot, egy napnyi `Duration` hozzáadása viszont pontosan 24 órát ad hozzá.
Használj `Period`-et, ha az emberek naptári értelemben gondolkodnak az időmennyiségről („jövő hónapban ugyanekkor”), és `Duration`-t az eltelt időre („a parkolójegy 2 óráig érvényes”).
