# Névjegy

Nem valószínű, hogy sok olyan éles kóddal találkozol, amely nem használ névtereket.

A szintaxisra egy példa:

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

A névterek segítségével összetartozó kódot csoportosíthatunk, és elkerülhetjük a névütközéseket.

A [hivatalos dokumentáció][namespaces] szerint a névtereknek két fő szerepe van:

- Először is, a .NET a névterekkel rendszerezi a számos osztályát.
- Másodszor, a saját névterek deklarálása segíthet kézben tartani az osztály- és metódusnevek scope-ját nagyobb programozási projektekben.

A base class library (BCL) széles körben használ névtereket a funkciói rendszerezésére.

## Hivatkozás névtérbe zárt típusokra

A névterekbe zárt típusokra a névtéren kívülről úgy hivatkozunk, hogy a névtér nevét ponttal elválasztva a típusnév elé írjuk. Másik lehetőség, és ez a gyakoribb, hogy a fájl elejére (vagy egy névtéren belülre) teszel egy `using` utasítást; ekkor az importált névtér bármely típusát használhatod előtag nélkül. Ugyanazon a névtéren belül nincs szükség a típusnevek minősítésére.

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

Ez a [cikk][using] világosan elmagyarázza, hogyan használható a `using` utasítás:

- `using`: nem kell a típusokat névtérrel minősíteni
- `using static`: nem kell a tagokat típussal minősíteni (jó példa erre a `Math.Max()`).
- `using MyAlias = YourNamespace;`: egy olvashatóbb nevet írhatsz a névtér neve helyére.

## Névterek ütközése

A .NET kezeli azt a helyzetet, amikor két azonos nevű névtér különböző assembly-kben található, és emiatt ütköznének a teljesen minősített azonosítók nevei (például amikor egy assembly több verziója van betöltve). Ezt a problémát a [névtéralias-minősítő][namespace-alias-qualifier] és az [extern alias][extern-alias] kezeli.

Az egyik ok, amiért ezt a meglehetősen szűk témát szóba hozzuk, a [`::` operátor][dot-dot-operator] használata. Gyakran látni majd, hogy a `global::` minősítő névterek előtt áll, különösen generált kódban. A szándék az, hogy elkerüljük az esetleges ütközést valamely egymásba ágyazott névtérrel vagy osztálynévvel. Ha egy névtér elé odaírod a `global::` minősítőt, biztosítod, hogy egy legfelső szintű névtér legyen kiválasztva.

## Megjegyzés Java-fejlesztőknek

Ha a Java `packages` `import`-jával hasonlítjuk össze, néhány különbséget és hasonlóságot is érdemes megjegyezni:

- A C#-ban nincs megfelelője a konkrét típusok importálásának.
- A `using static` és az `import static` egyenértékű.
- Javában a csomagnevek befolyásolják a jarok közötti hozzáférhetőséget. C#-ban az assembly-k a meghatározók, és az, hogy valami ugyanabba a névtérbe tartozik, nincs hatással a hozzáférési szintre.
- A fájlrendszerbeli útvonalak és a teljesen minősített osztálynevek közötti kapcsolat a Javában nem tükröződik a C# névtereiben, bár jó gyakorlat, hogy ahol lehet, a fájl ugyanazt a nevet kapja, mint a benne lévő fő osztály.
