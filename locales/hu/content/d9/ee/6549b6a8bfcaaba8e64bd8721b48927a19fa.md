# Bevezetés az elágazásokba

## Az igazságértékek a Bashben

A Bash nem ismeri a Boolean-értékek fogalmát.
Vannak stringek, számok, valamint stringekből vagy számokból álló tömbök.
Szóval hogyan bánnak a feltételes parancsok az igazzal és a hamissal?

## A kilépési állapot

Amikor egy parancs befejeződik, egy _kilépési állapotot_ ad vissza.
A kilépési állapot egy 0 és 255 közötti egész szám, a határértékeket is beleértve.
A Bash a **nulla** kilépési állapotot tekinti _sikernek_.
Minden más kilépési állapot _kudarcot_ jelent.

Ez minden parancsra érvényes, beleértve a bash beépített parancsait, a kulcsszavakat és a függvényeket.

## Az „if” parancs

Az `if` parancs alapvető szintaxisa:

```bash
if CONDITIONAL_COMMANDS; then TRUE_COMMANDS; else FALSE_COMMANDS; fi
```

`if`-fel kezdődik; a feltételt vizsgáló parancsokat a `then` választja el a „sikeres” parancsoktól; és `fi`-vel zárul.
Az `else` ág elhagyható.

A CONDITIONAL_COMMANDS lehet egyetlen parancs, vagy lehet [parancsok listája][command-list].

A CONDITIONAL_COMMANDS végrehajtódik, és

* ha a kilépési állapot nulla (siker), akkor a TRUE_COMMANDS hajtódik végre.
* ha a kilépési állapot nem nulla (kudarc), akkor a FALSE_COMMANDS hajtódik végre, feltéve hogy az jelen van.

Lépcsőzetes elágazások adhatók meg az `elif` segítségével
```bash
if CONDITIONAL_COMMANDS
then TRUE_COMMANDS
elif CONDITIONAL_COMMANDS_2
then TRUE_COMMANDS_2
# more elif branches ...
else FALSE_COMMANDS
fi
```

A `then`, `elif`, `else` és `fi` szavak előtt pontosvesszőnek vagy sortörésnek kell állnia.

Hangsúlyozzuk: a folyamat vezérlését a feltételes parancsok **kilépési állapota** irányítja.
Például a `grep` 0-t ad vissza, ha talál egyezést, és 1-et, ha nem talál.
A `-q` kapcsoló elnyomja a kimenetet, és csak a kilépési állapotot állítja elő.

```bash
if grep -q "my pattern" my_file; then echo "the pattern is found in the file"; fi
```

## A „[” és a „test” parancsok

A CONDITIONAL_COMMANDS körül nincs különleges szintaxis.
Lehet, hogy hozzászoktál az ilyen elágazásokhoz:

```if
if [ "$password" = "secure" ]; then
    echo "Welcome!"
fi
```

A `[` nem különleges szintaxis.
Ez egy _parancs_, amely kiértékeli a feltételes kifejezést, és siker vagy kudarc állapottal lép ki.
Mint minden parancsnál, **kötelező** a whitespace közte és az argumentumai között.

A `[` valójában a `test` parancs szinonimája.
Teljesen megegyeznek, azzal az egyetlen kivétellel, hogy a `[` utolsó argumentumának `]`-nek _kell_ lennie.

### Feltételes kifejezések

A `[` és a `]` között egy feltételes kifejezést írsz.
Néhány tipikus feltételes kifejezés:

```bash
[ -f "$filename" ]             # file operations
[ "$string1" = "$string2" ]    # string comparisons
[ "$num1" -eq "$num2" ]        # arithmetic comparisons
```

Sok más művelet is elérhető; ezeket a kézikönyv [Bash feltételes kifejezései][cond-expr] szakasza sorolja fel.

~~~~exercism/note
A fenti példákban figyeld meg, hogy minden változó idézőjelben van.
A `test` és a `[` parancsok egyszerű parancsok, amelyeknél az argumentumok ugyanúgy ki vannak téve a szófelbontásnak és a fájlnévkiterjesztésnek, mint bármely más parancsnál.

Ezt azért fontos kiemelni, mert a feltételes kifejezések kiértékelése attól függően változik, hogy _hány argumentumot_ adsz meg:

* 0 argumentum: a kilépési állapot nem nulla (kudarc)
* 1 argumentum: a kilépési állapot nulla (siker), ha az argumentum nem üres, és nem nulla, ha üres.
* 2 argumentum: az első argumentumnak egy unáris operátornak kell lennie (például `[ -z "$name" ]`), vagy egy `!`-nak (amely az 1 argumentumos teszt állapotát tagadja)
* és még [több][test].

Váratlan eredményeket kaphatsz, ha elfelejtesz idézőjelet használni:

```bash
str=""

# this prints "empty"
if [ -n "$str" ]; then echo "not empty"; else echo "empty"; fi

# leaving the variable unquoted results in incorrect "not empty" output
if [ -n $str ]; then echo "not empty"; else echo "empty"; fi
```

[test]: https://www.gnu.org/software/bash/manual/bash.html#index-test
~~~~

## A „[[” kulcsszó

A [`[[...]]` feltételes szerkezet][cond-construct] nem _parancs_, hanem **kulcsszó**.
Ez azt jelenti, hogy bár ugyanúgy kezelik, mint bármely más parancsot, különleges szabályok vonatkoznak az értelmezésére.
A `[[` különlegessége, hogy a benne kifejtett változók **nincsenek** kitéve szófelbontásnak vagy fájlnévkiterjesztésnek.
Ez azt jelenti, hogy ez a parancs idézőjelek nélkül is úgy viselkedik, ahogy elvárod.

```bash
if [[ -n $str ]]; then echo "not empty"; else echo "empty"; fi
```

A `[[` támogatja az összes olyan feltételes kifejezést, amit a `test` és a `[` kezelni tud.
Ezen kívül a `[[` a következőket kínálja:

* a `=~` reguláris kifejezésre illesztő operátort,
* a `==` és a `!=` glob-mintára illesztő operátorként működik,
* a `&&` és a `||` logikai operátorként (különleges értelmezési szabály),
* a `<` és a `>` „csupasz” string-összehasonlító operátorként (különleges értelmezési szabály: mivel ezek átirányítási szimbólumok, a `[`-ban escape-elni kell őket).

Széles körben elfogadott, hogy ezek a különleges szolgáltatások annyi előnnyel járnak, hogy a `[[`-t érdemes kizárólagosan használni.
(Például a [Google Shell Style Guide][goog-test].)

## A „case” parancs

A [`case`][case] egy másik vezérlési szerkezet.
Olyan, mint más nyelvekben a „switch” utasítás.

```bash
case WORD in [PATTERN [| PATTERN]...) COMMANDS ;;]... esac
```

A WORD-et a rendszer minden PATTERN-nel összeveti.
Amikor valamelyik illeszkedik, végrehajtódnak a COMMANDS.

```bash
read -p "Guess the secret word: " word
case "$word" in
    secret) echo "Yes, you guessed it!" ;;
    ??????) echo "That's the right number of letters." ;;
    s*)     echo "You guessed the first letter." ;;
    *)      echo "Not even close! Try again." ;;
esac
```

Minden COMMANDS ágnak **két** pontosvesszővel, `;;`-vel kell végződnie.
