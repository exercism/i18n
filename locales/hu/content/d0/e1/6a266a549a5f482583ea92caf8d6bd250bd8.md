# Bevezetés

A **ciklus** olyan utasítások sorozata, amelyet a program akár többször is végrehajt, egészen addig, amíg egy lezáró feltétel nem teljesül.

Az x86-64-en a ciklusokat általában egy korábbi címkére mutató ugrással hozzuk létre:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Vedd észre, hogy egy korábbi címkére irányuló feltétel nélküli ugrás mindig erre a címkére adja át a vezérlést.
Ez azt jelenti, hogy a ciklus a végtelenségig ismétlődik, hacsak nincs egy másik ugrás, amely kivezet az ismételt sorozatból.

Például ez a ciklus nem fejeződik be:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

Ez a ciklus pedig véget érhet, attól függően, hogy teljesül-e a feltétel:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## Számlálóciklusok

A számlálóciklus szinte mindig ugyanúgy ér véget: egy utasítás frissíti a számlálót vagy összehasonlít két értéket, és közvetlenül utána egy feltételes ugrás dönti el, hogy újra körbe megy-e a vezérlés.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
A fenti kódban nincs szükség a `cmp rsi, 0` utasításra, mert a `sub rsi, 1` már beállítja a `zero flag (ZF)` jelzőt, amikor az eredmény `0`.

Bár assemblyben a feltételek vizsgálatának fő módja a `cmp` utasítás, sok más utasítás is frissíti a jelzőket.
Például sok egész aritmetikai vagy bitenkénti utasítás frissíti a `ZF` jelzőt, ha az eredmény `0`, és az `SF` jelzőt, ha az eredmény negatív (azaz a legfelső bit be van állítva).

Ha kíváncsi vagy rá, mely jelzőket befolyásolja az egyes utasítások, nézz meg egy [referenciát][reference].

[reference]: https://www.felixcloutier.com/x86/
~~~~

Vedd észre, hogy a fenti példában `rsi`-ről feltételezzük, hogy nagyobb, mint `0`.
Ha viszont `0` lenne, akkor a `sub rsi, 1` `-1`-re csökkentené `rsi` értékét, ami előjel nélküli számként rendkívül nagy.
A ciklus végleges lezárulása előtt még `18,446,744,073,709,551,615` iterációra lenne szükség.
Ráadásul, mivel a tömb hossza `0`, bármilyen memóriahozzáférés a tartományon kívülre esne.

Ha nincs garancia a tömb hosszára, két gyakori megoldás kínálkozik.

Az első, hogy a lezáró feltételt a ciklus elejére tesszük, majd a végére egy feltétel nélküli ugrást:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

A második, hogy a ciklus eleje előtt egyszer ellenőrizzük, hogy a tömb hossza nem nulla-e:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Ez a második megoldás általában hatékonyabb az elsőnél, mert kevesebb elágazás van a ciklus törzsében.
Erről egy későbbi fogalomnál tanulsz majd többet.

~~~~exercism/advanced
Bizonyos helyzetekben a modern processzorok képesek két különböző utasítást egyetlen műveletté összevonni.
Ez az optimalizálás a **macrofusion** nevet kapta.

Sok aritmetikai utasítás, például a `sub` és az `add`, valamint a `cmp` és a `test`, gyakran összeolvad a közvetlenül utána következő feltételes ugrással.
Ez azt jelenti, hogy egy olyan utasítást, mint a `cmp rax, rdx`, amelyet közvetlenül egy feltételes ugrás követ, a processzor általában egyetlen műveletként kezelhet.

A macrofusion processzorfüggő, és némileg változik, hogy mely utasítások olvadnak össze melyik feltételes ugrással.

Hasznos forrás [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch].
Az [Intel optimization reference manual][intel-opt] 3.4.2.2. szakasza (Optimizing for Macrofusion) szintén felsorolja az összeolvasztható párokat az Intel processzoraihoz.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
