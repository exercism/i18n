# Bevezetés

## A let assert állítások

Amikor Gleamben egy értékre illesztünk mintát, biztosítanunk kell, hogy a minták a típus minden lehetséges értékét lefedjék, különben a kód nem fordul le.

Ezt a függvényt el kell utasítani, mert nem kezeli azt az esetet, amikor a lista üres:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

A Gleam-programokban a legtöbbször minden lehetséges esetet kezelni akarunk, de néhány programban, például prototípusokban és gyors szkriptekben, előfordulhat, hogy csak a happy pathra akarunk összpontosítani, és nem írunk kódot a többi esetre. Itt jön képbe a Gleam `let assert` konstrukciója.

A let assert állításokkal egy minta a típusnak csak néhány lehetséges értékére illeszkedhet, és ha a minta nem illeszkedik egy értékre, a program összeomlik. A `let assert` használatával a fenti függvényt így írhatjuk meg:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

A Gleam-könyvtáraknak soha nem szabad let assert állításokat használniuk, mert azok összeomlaszthatják a programot. Ehelyett a `Result` típust kell használniuk, és hagyniuk kell, hogy az alkalmazás fejlesztője döntse el, hogyan kezelje a hibákat.
