# Bevezetés a here documentokba

A Bash-szkriptelésben a „here document” (vagy „heredoc”) több sor bemenetet irányít át egy parancshoz vagy programhoz, mintha azokat közvetlenül a terminálba gépelnéd be.
Hatékony eszköz arra, hogy több soros szöveget ágyazz a szkriptjeidbe anélkül, hogy külső fájlokra vagy bonyolult stringmanipulációra lenne szükség.

## Fő jellemzők és szintaxis

1. Elválasztó: a here document a `<<` operátorral kezdődik, amelyet egy elválasztó szó követ (ezt szokás „jelölőnek” vagy „lezárónak” is nevezni).
   Ez az elválasztó bármilyen szó lehet, amelyet választasz, de az áttekinthetőség kedvéért gyakran használunk valami olyasmit, mint az `EOF`, az `END` vagy a `TEXT`.
   Olvashatóbb kódhoz választhatsz leíró elválasztót is, például `END_INSTALLATION_INSTRUCTIONS`.

1. Tartalom: a kezdő `<< DELIMITER` után írod le azt a tartalmat, amelyet át szeretnél irányítani.
   Ez lehet több sor szöveg, kód vagy bármi más.

1. Lezárás: a here document akkor ér véget, amikor az elválasztó szó ismét megjelenik egy önálló sorban, minden kezdő vagy záró szóköz nélkül.

## Alapszintaxis

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## Hogyan működik

* A Bash beolvassa az összes sort a kezdő `<< DELIMITER` és a záró `DELIMITER` között.
* A Bash ezt a tartalmat a parancs szabványos bemenetéhez csatlakoztatja.
* A parancs úgy dolgozza fel ezt a bemenetet, mintha az a billentyűzetről érkezne.

### 1. példa: egyszerű szövegkiírás

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

Kimenet:

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

Ebben a példában:

* A `cat` a parancs.
* A `<< EOF` indítja a here documentot, ahol az elválasztó az `EOF`.
* A három szövegsor a tartalom.
* Az önálló sorban álló `EOF` zárja le a here documentot.
* A `cat` ezután kiírja a kapott tartalmat.

### 2. példa: használat a wc-vel (szavak számlálása)

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

Kimenet:

```plaintext
3
```

Itt a `wc -l` megszámolja a sorok számát.
A here document biztosítja bemenetként a három sort.

### 3. példa: adatok átadása egy szkriptnek

A szkript:

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

Hívd meg a szkriptet egy interaktív bash-parancssorból egy here documenttel:

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

Kimenet:

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## Változatok és haladó lehetőségek

### Szó szerinti tartalom

A Bash a here documenton belül végrehajtja a változóhelyettesítést, a parancsbehelyettesítést és az aritmetikai kiértékelést.
Ebben az értelemben a here documentok úgy viselkednek, mint a kettős idézőjelbe zárt stringek.

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

Kimenet:

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

Ha az elválasztót idézőjelbe teszed (egyszeres vagy kettős idézőjellel), ezek a helyettesítések elmaradnak.
A tartalom szó szerint értendő.
Ez olyan, mint az egyszeres idézőjelbe zárt stringek.

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

Kimenet:

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### A kezdő tabulátorok eltávolítása

Ha a `<<` helyett a `<<-` jelet használod (a záró kötőjellel), a Bash minden sor elejéről eltávolítja a _tabulátorkaraktereket_.
Ez akkor hasznos, ha behúzva szeretnéd elhelyezni a here document tartalmát a szkriptben anélkül, hogy ez hatással lenne a kimenetre.

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

A kimenet az összes kezdő tabulátor eltávolításával jelenik meg:

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
A szerző nem javasolja ezt a használatot.
Bár javíthatja a szkript olvashatóságát,

1. könnyű véletlenül szóközökre cserélni a tabulátorkaraktereket (a szerkesztőd ezt automatikusan is megteheti), és
1. nehéz észrevenni a különbséget a szóközök és a tabulátorok között.
~~~~

## Mikor használjunk here documentot?

* Több soros bemenet: amikor több sor szöveget kell átadnod egy parancsnak.
* Konfigurációs fájlok: kisebb konfigurációs részletek beágyazása egy szkriptbe.
* Kódgenerálás: kód létrehozása menet közben egy szkriptben.
* Interakciók szkriptelése: felhasználói bemenet szimulálása interaktív programokhoz.
* Külső fájlok elkerülése: amikor nem szeretnél ideiglenes fájlokat létrehozni.

Egy tipikus felhasználás a súgószöveg biztosítása:

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## Lehetséges hátrányok

* A nagy beágyazott dokumentumok nehezebben olvashatóvá tehetik a kódodat.
  Jobb lehet, ha a szkriptet külön fájlokban lévő dokumentációval együtt élesíted.
* A here documentok megtörhetik a kód folyását.
  Lehet, hogy éppen a kód mélyen egymásba ágyazott részében vagy, amikor szöveget szeretnél átadni egy programnak.
  A here document behúzása rikítón hathat a környező kódhoz képest.

## Here stringek

A here documentokhoz hasonlóan a _here stringek_ (vagy „herestringek”) is bemenetet adnak egy parancsnak.
Míg azonban a here documentok egy szövegblokkot adnak át, addig a here stringek egyetlen szövegstringet.
A here stringek a `<<< "text"` szintaxist használják.

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

Kimenet:

```plaintext
UPPER CASE THIS STRING
```

A here documentokkal ellentétben itt nincs szükség záró elválasztóra.

### Miért használjunk here stringeket?

Egy here string helyett csővezetéket is használhatsz:

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

Akkor miért érdemes here stringet használni?

Vegyük azt az esetet, amikor egy hosszan futó számítás kimeneteként kapod meg a stringet, és az eredményt két külön parancsnak szeretnéd átadni.
Csővezetékek használatával kétszer kell lefuttatnod a számítást:

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

Hatékonyabb megközelítés, ha elkapod a számítás kimenetét (parancsbehelyettesítéssel), és here stringekkel adod meg a bemenetet a két következő parancsnak:

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

Íme a példa egy valós felhasználása:

* elkapod egy REST API-lekérdezés (amely lapozott) JSON-válaszát,
* átadod a JSON-adatokat egy jq programnak, amely feldolgozza az eredményeket, és kiírja azokat egy fájlba, majd
* átadod a JSON-adatokat egy másik jq programnak, hogy meghatározza a következő lekérdezés URL-jét.

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

Figyeld meg a kimenetátirányítás helyét!
A while ciklus teljes kimenete a `data.csv` fájl végére fűződik.

## A here documentek és a here stringek mint átirányítás

Mivel ezek csupán az átirányítás formái, más átirányítási műveletekkel is kombinálhatók:

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## Összefoglalás

A here documentek (vagy „heredocok”) rugalmas és kényelmes módját adják a több soros bemenet kezelésének a Bash-szkriptekben.
Leegyszerűsítik a szöveg és az adatok közvetlen beágyazását a szkriptjeidbe, így azok önállóbbak és könnyebben olvashatók lesznek.

A here stringek (vagy „herestringek”) hasonlítanak a here documentokhoz, de egyszerűbb, dinamikusabb szintaxist kínálnak.
