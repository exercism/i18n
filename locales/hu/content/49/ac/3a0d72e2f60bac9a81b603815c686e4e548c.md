# Bevezetés

## Függvények

Saját **egyéni függvényeket** definiálhatsz a `jq`-ban, hogy bármilyen logikát egységbe zárj vele.
A _függvények_ pontosan úgy viselkednek, mint a beépített függvények: kapnak egy bemenetet, és nullát, egyet vagy több kimenetet adnak.

### Függvény definiálása

A `jq`-ban a következő szintaxissal definiálhatsz egy _függvényt_:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- a `def` kulcsszóval kezdődik,
- a függvény törzse előtt kettőspont áll,
- a törzs egyetlen kifejezésből áll,
- pontosvesszővel zárul,
- a `jq` szintaxisának többi részéhez hasonlóan tetszőleges whitespace-t használhatsz az olvashatóság kedvéért.

### Hová kerüljenek a függvények

A _függvényeket_ a használatuk előtt kell definiálni: ez hiba:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Ez azt jelenti, hogy a _függvényeket_ a `jq`-kódod elejére kell tenned, a „fő” kifejezés elé.

#### Egymásba ágyazott függvények

A _függvényeket_ egymásba ágyazhatod:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Itt a `B` _függvény_ csak az `A` törzsében látható.

### Scope

Egy _függvény_ új **scope**-ot vezet be a változók és a beágyazott függvények számára.

### Argumentumok

A _függvény_ **argumentumait** _pontosvesszők_ választják el egymástól, nem vesszők.
Például egy olyan _függvény_, amely kap egy számot, majd hozzáad egy számot és megszoroz egy számmal:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
A pontosvesszőre azért van szükség, mert a vesszőnek már van egy funkciója a `jq`-ban: olyan operátor, amely stream-eket kapcsol össze.

Ha vesszőt használsz pontosvessző helyett, azzal két hívást próbálsz indítani egy _1 argumentumos_ `add_mul` függvény felé, amely nem létezik, ezért már az első próbált hívásnál hibára fut:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```
~~~~

<!-- prettier-ignore-end -->

#### Az argumentumok _kifejezések_

A függvények _argumentumai_ filterek, nem értékek.
Ebben az értelemben úgy viselkednek, mint amit más nyelvek callbacknek neveznek:

Az `add_mul` függvényt példaként használva:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

Mi történik itt?

- az `adder` argumentum a `. + 5` _kifejezést_ kapja
  - amikor a függvény a `. + adder` műveletet végzi, az `. + . + 5` lesz
  - ennek az értéke 25 lesz, mivel `. == 10`
- hasonlóképpen a `multiplier` argumentum a `. - 2` kifejezés
  - ennek az értéke 8
  - így az eredmény `25 * 8 == 200`

#### Argumentumok értékként

Néha szeretnéd egy _argumentumból_ változót „materializálni”:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Erre van egy rövidített írásmód:

```jq
def my_func($arg):
    other stuff ...
;
```

Vedd figyelembe, hogy ez csupán „szintaktikai cukor”: az `arg` név `$` nélkül is a _függvény_ scope-jában marad.

### Aritás

A _függvényeknek_ van egy **aritásuk**, vagyis az általuk felvett _argumentumok_ száma.

A _függvények_ ugyanazt a nevet használhatják különböző _aritásokkal_.
A beépített [`range`][man-range] függvény jól mutatja ezt: a `range/1`, `range/2` és `range/3` mind létezhet egymás mellett.

Ez hasznos lehet olyan rekurzív függvények definiálásához, amelyek argumentumokon keresztül hordozzák az állapotot.
Például a `map` _így_ is megvalósítható lenne:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

### Rekurzió

A `jq` elvégzi a farokhívás-optimalizálást, de csak 0 aritású függvények esetében.

### Modulok

A `jq` modul egy olyan fájl, amely csak függvényeket tartalmaz.
A modulokat az [`include`][man-include] vagy az [`import`][man-import] paranccsal illeszted be egy jq programba.
