# Bevezetés

## Kivételek

A Java programozási nyelv _kivételeket_ használ a hibák és más kivételes események kezelésére.

### Mi a kivétel?

A kivétel egy olyan esemény, amely a program végrehajtása során történik, és megzavarja az utasítások normál menetét.
A kivételeket a Java-ban explicit módon dobják, és a kivétel dobásának műveletét _kivételdobásnak_ nevezik.
A kivétel kezelésének műveletét _kivétel elkapásának_ nevezik.

A Java-ban minden kivétel az `Exception` osztály alosztálya, amely maga a `Throwable` alosztálya.

A Java kétféle kivételt különböztet meg:

1. Ellenőrzött kivételek
2. Nem ellenőrzött kivételek

#### Ellenőrzött kivételek

_Az ellenőrzött kivételek_ olyan kivételes állapotok, amelyekre az alkalmazásnak számítania kell, és amelyekből helyre kell állnia.
Példa ellenőrzött kivételre a `FileNotFoundException`, amely akkor fordul elő, amikor egy metódus egy nem létező fájlt próbál beolvasni.

Ez a típusú kivétel fordítási időben ellenőrzésre kerül: azoknak a metódusoknak, amelyek ellenőrzött kivételt dobnak, ezt a metódusuk szignatúrájában meg kell adniuk, és az olyan kódnak, amely olyan metódust hív meg, amely ellenőrzött kivételt dobhat, kezelnie kell azt, különben a kód nem fordul le.

Minden ellenőrzött kivétel az `Exception` olyan alosztálya, amely nem származik a `RuntimeException`-ból.

#### Nem ellenőrzött kivételek

_A nem ellenőrzött kivételek_ olyan kivételes állapotok, amelyekre az alkalmazás általában nem tud számítani, és amelyekből nem tud helyreállni.
Példa nem ellenőrzött kivételre a `NullPointerException`, amely akkor fordul elő, amikor egy metódus nem `null` értéket vár, de `null`-t kap.

Ez a típusú kivétel nincs ellenőrizve fordítási időben: azoknak a metódusoknak, amelyek nem ellenőrzött kivételt dobnak, nem kell ezt a metódusuk szignatúrájában megadniuk, és az olyan kódnak, amely olyan metódust hív meg, amely nem ellenőrzött kivételt dobhat, nem kell kezelnie azt.

Minden nem ellenőrzött kivétel a `RuntimeException`-ból származik, amely maga az `Exception` kiterjesztése.

### Kivételek dobása

Egy metódus a Java-ban a `throw` utasítás használatával dobhat kivételt.

#### Ellenőrzött kivétel dobása

Amikor egy metódusból ellenőrzött kivételt dobunk, ezt a metódus szignatúrájában a `throws` kulcsszó használatával meg kell adni, ahogy az alábbi példa mutatja.
Ez arra kényszeríti a hívó kódot, hogy számítson arra, hogy kivétel dobható, és ennek megfelelően kezelje azt.

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

#### Nem ellenőrzött kivétel dobása

Amikor egy metódusból nem ellenőrzött kivételt dobunk, nem kötelező ezt a metódus szignatúrájában megadni, bár támogatott.

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

### Kivételek kezelése

A kivételek kezelése a Java-ban a `try`, `catch` és `finally` kulcsszavakkal történik.

- Azokat a kód utasításokat, amelyek kivételt dobhatnak, `try` blokkba kell csomagolni.
- A `try` blokkot egy vagy több `catch` blokk követi, amelyek elkapják a `try` blokkban dobott kivételeket.
- A `catch` blokkokat opcionálisan egy `finally` blokk követi, amely mindig végrehajtódik a `try` blokk után, függetlenül attól, hogy történt-e kivétel vagy sem.

A következő példa bemutatja, hogyan működnek ezek a kulcsszavak:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

Ebben a példában, amikor nem dobódik kivétel, a következő kerül kiírásra:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

Ha azonban a `bankAccount.withdraw(amount)` utasítás `InsufficientBalanceException`-t dob, a következő kerül kiírásra:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

Vagy abban az esetben, ha a `bankAccount.withdraw(amount)` nem ellenőrzött kivételt dob, a következő kerül kiírásra:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

### Hibák

A Java-nak van egy külön kategóriája is, amelyet _hibáknak_ neveznek; ezek olyan súlyos problémák, amelyek az alkalmazáson kívül vannak.
Példa hibára a `OutOfMemoryError`, amely akkor fordul elő, amikor egy alkalmazás több memóriát próbál használni, mint amennyi a rendszerben elérhető.

A nem ellenőrzött kivételekhez hasonlóan a hibák sincsenek ellenőrizve fordítási időben.
A különbség az, hogy rendszerszintű problémákat képviselnek, és általában a Java virtuális gép vagy a környezet dobja őket, nem az alkalmazás.
Az alkalmazásoknak általában nem kell megpróbálniuk elkapni vagy kezelni őket.

A Java-ban minden hiba az `Error` osztályból származik.
