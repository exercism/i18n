# Bevezetés

Eljött az idő, hogy eljussunk a C++ egyik alapparadigmájához: az objektumorientált programozáshoz (OOP).
Az OOP középpontjában a `classes` állnak: felhasználó által definiált adattípusok, amelyeknek saját, hozzájuk kapcsolódó függvénykészletük van.
Az alapokkal kezdjük, és a tantervben lejjebb haladva foglalkozunk majd a haladóbb témákkal.

## Tagok

Az osztályoknak lehetnek **tagváltozóik** és **tagfüggvényeik**.
A **tagkiválasztó** operátorral (`.`) érhetők el.
Ahogy a `classes`-en kívüli változóknál is, érdemes a tagváltozókat deklarációkor értékkel inicializálni.
Ez az érték lesz az alapértelmezett az ebből az osztályból újonnan létrehozott objektumok számára.

## Egységbezárás és információrejtés

Az osztályok lehetőséget kínálnak a tagjaikhoz való hozzáférés korlátozására.
A két alapvető eset a `private` és a `public`.
A `private` tagok nem érhetők el az osztályon kívülről.
A `public` tagok szabadon hívhatók.
Alapértelmezés szerint minden tag `private`, és ahhoz, hogy az osztályon kívülről is használhatók legyenek, kifejezetten meg kell jelölni őket.

## Egyszerű példa

Egy új `class` definíciója a következő példában látható.
Figyeld meg a definíció utáni `;`-t.

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

Az osztályon belülről minden változó elérhető.
Nézd meg a `damage`-t a `cast_spell` függvényben.
Az osztályon kívülről nem olvashatod és nem változtathatod meg a `private` tagokat:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## Konstruktorok

A konstruktorok lehetőséget kínálnak arra, hogy objektum létrehozásakor értéket adjunk a tagváltozóknak.
Ugyanaz a nevük, mint a `class`-nak, és nincs visszatérési típusuk.
Egy osztálynak több konstruktora is lehet.
Ez akkor hasznos, ha nem mindig kell az összes változót beállítanod.

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

A konstruktorok nagy téma, és sok árnyalatuk van.
Ha nem definiálsz kifejezetten `constructor`-t a `class`-odhoz, akkor, és csak akkor, a fordító elvégzi helyetted a munkát.
Ez történt a fenti első példában.
A _silverhand_ objektum az alapértelmezett konstruktor hívásával jön létre, argumentumok átadása nélkül.
Minden változó arra az értékre van beállítva, amelyet az osztály definíciójában megadtunk.
Ha nem adtál volna meg értékeket abban a definícióban, a változók inicializálatlanok lehetnének, aminek nem szándékolt következményei lehetnek.

## Struktúrák

A struktúrák a nyelv eredeti C-s gyökereiből származnak, és olyan régiak, mint maga a C++.
Gyakorlatilag ugyanazok, mint a `classes`, egy fontos kivétellel.
Alapértelmezés szerint egy `class` minden tagja `private`.
A struktúrák viszont `public`-ok, amíg másként nem definiáljuk.
A hagyomány szerint a `struct` kulcsszót gyakran **csak adatokat tartalmazó struktúrákra** használják.
A `class` kulcsszót inkább olyan objektumokra használják, amelyeknek bizonyos tulajdonságokat biztosítaniuk kell.
Ilyen invariáns lehet például az, hogy a `Wizzard` `class` `damage` értéke nem válhat negatívvá.
A `damage` változó privát, és bármely függvény, amely megváltoztatja a damage értékét, biztosítaná az invariáns megmaradását.
