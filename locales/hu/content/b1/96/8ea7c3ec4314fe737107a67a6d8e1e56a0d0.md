# Bevezetés

Ez a feladat arra épül, amit a [Kerti madárfigyelő][backyard-birdwatcher] feladatban láttál, és bemutatja azokat a magasabb rendű szavakat, amelyek egy *quotation*t, azaz `[ ]` zárójelbe írt kódrészletet kapnak, és ezzel vezérlik a műveletet.

## A quotation mint érték

A quotation nem más, mint egy szó szerinti kódrészlet. Adatként átadhatod egy másik szónak:

```factor
{ 1 2 3 4 5 } [ 2 > ] count .   ! => 3
```

Itt a `[ 2 > ]` egy olyan quotation, amely kap egy számot, és egy Boolean értéket hagy maga után. A `count` minden elemre lefuttatja, és összeszámolja az igaz értékű eredményeket.

## Szűrés és kizárás

```
find      ( seq quot    -- i/f elt/f ) ! first match: index and element, or f f
find-last ( seq quot    -- i/f elt/f ) ! same, but searches from the end
filter    ( seq quot    -- newseq )    ! keep elements where quot is truthy
reject    ( seq quot    -- newseq )    ! drop them instead
without   ( seq exclude -- newseq )    ! drop every element that's in `exclude`
sift      ( seq         -- newseq )    ! drop every `f`, keep the rest
```

```factor
{ 1 2 3 4 5 } [ 3 > ] find .s
! => 3            (index)
! => 4            (element)
{ 1 2 3 4 5 } [ 3 > ] find-last .s
! => 4            (index)
! => 5            (element)
{ 1 2 3 4 5 } [ even? ] filter .    ! => { 2 4 }
{ 1 2 3 4 5 } [ even? ] reject .    ! => { 1 3 5 }
"hello world" " ld" without .       ! => "heowor"
{ 1 f 2 f 3 } sift .                ! => { 1 2 3 }
```

A `without` a második argumentumát halmazként kezeli: a `seq` minden olyan elemét eldobja, amely `=` valamelyik `exclude`-beli elemmel. A `sift` a `reject` azon különleges esete, amikor nincs quotation: minden elemet megtart, kivéve az `f`-et, ami kényelmes, ha ki akarod takarítani azokat a hézagokat, amelyeket egy korábbi `map` hagyott maga után.

### A teszt eredményének megtartása

A `find` a megtalált *elemet* adja vissza. Ha a teszt már *kiszámítja* azt az értéket, amire valójában szükséged van, a `map-find` megspórol neked egy második bejárást: lefuttatja a quotationt minden elemen, és visszaadja az első nem `f` eredményt **és** azt az elemet, amely létrehozta.

```
map-find ( seq quot: ( elt -- result/f ) -- result elt )
```

```factor
USING: kernel math sequences ;

! First multiple of 3, paired with that multiple divided by 3.
{ 11 13 15 17 } [ dup 3 mod 0 = [ 3 /i ] [ drop f ] if ] map-find .s
! => 5            (result: 15/3)
! => 15           (element)
```

A quotation `f`-et ad vissza azokra az elemekre, amelyek nem felelnek meg, és a megtartani kívánt eredményt arra az egyre, amelyik igen. Ha egy sem felel meg, a `map-find` az `f f`-et hagyja maga után, csakúgy, mint a `find`.

### Rekordok szűrése slot szerint

Amikor az elemek *tuple*-ok, a predikátum általában egy slotot vetít ki az automatikusan generált `slot>>` olvasóján keresztül, és azon végez vizsgálatot:

```factor
USING: accessors sequences ;

TUPLE: customer name vip? ;

{
    T{ customer { name "Alice" } { vip? t } }
    T{ customer { name "Bob"   } { vip? f } }
    T{ customer { name "Carol" } { vip? t } }
}
[ vip?>> ] filter [ name>> ] map .
! => { "Alice" "Carol" }
```

## Fix érték átvezetése a `with` szóval

Néha a predikátumnak minden hívásnál ugyanarra az értékre van szüksége: egy küszöbre, egy osztóra, egy cél stringre. A `with` (a [`kernel`][kernel] szótárban) beleégeti ezt a fix értéket a quotationbe, és a kétargumentumos `( value elt -- ? )` quotationből olyan egyargumentumos quotationt csinál, amilyet a `filter`, a `count`, a `map` és az `each` vár:

```
with ( value seq quot -- seq curry )
```

Minden elemenkénti hívás a `( value elt )` párost látja a stacken: elöl a fix érték, másodikként az aktuális elem:

```factor
USING: kernel sequences ;

! Count elements greater than 5 — value=5 is threaded in
5 { 2 7 4 9 1 8 } [ < ] with count .   ! => 3
```

## Leképezés és bejárás

A `map` (a [`sequences`][sequences] szótárban) minden elemre alkalmaz egy quotationt, és visszaadja az eredmények tömbjét. Az `each` ugyanezt a bejárást végzi, de eldobja az eredményeket, ami akkor hasznos, ha a quotationt kizárólag a mellékhatásai miatt futtatod. A `2map` *két* sorozaton halad egyszerre, lépést tartva, és összekapcsolja az egymásnak megfelelő elemeket; a `2each` és a `2reduce` ennek a csak mellékhatásokra építő, illetve összegző unokatestvérei; a `zip` pedig rövidítés arra, hogy „párokba rendezd őket, összekapcsolás nélkül”:

```
map     ( seq       quot           -- newseq )
map-as  ( seq       quot exemplar  -- newseq )
each    ( seq       quot           -- )
2map    ( seq1 seq2 quot           -- newseq )
2each   ( seq1 seq2 quot           -- )
2reduce ( seq1 seq2 identity quot  -- result )
zip     ( seq1 seq2                -- pairs )
```

A `2reduce` egyszerre vezet át egy akkumulátort mindkét sorozaton: a quotationje `( accumulator elt1 elt2 -- accumulator' )` alakú. Itt egy skaláris szorzatot állít elő: minden pár összeszorzódik, a szorzatok pedig összeadódnak (`1*10 + 2*20 + 3*30`):

```factor
{ 1 2 3 } { 10 20 30 } 0 [ * + ] 2reduce .   ! => 140
```

A `map-as` a `map` azon unokatestvére, amely rákényszeríti a kimeneti sorozat típusát: adj át egy üres `{ }` vagy `V{ }` exemplart, hogy felülírd a bemeneti típusból adódó alapértéket (különben, ha egy stringet nem karakterekké képezünk le, hibát kapunk, amikor a Factor megpróbálja az eredményeket visszapakolni egy stringbe).

```factor
USING: formatting math sequences ;

{ 1 2 3 } [ sq ] map .                         ! => { 1 4 9 }
{ 1 2 3 } [ . ] each                           ! prints 1, then 2, then 3
{ 1 2 3 } { 10 20 30 } [ + ] 2map .            ! => { 11 22 33 }
{ "x" "y" } { 1 2 } [ "%s%d" sprintf ] 2map .  ! => { "x1" "y2" }
{ 1 2 3 } { 10 20 30 } [ + . ] 2each           ! prints 11, then 22, then 33
{ "a" "b" "c" } { 1 2 3 } zip .                ! => { { "a" 1 } { "b" 2 } { "c" 3 } }
```

Mindkét két sorozatos forma a rövidebb bemenet hosszánál áll meg. A `zip` ugyanaz, mint a `[ 2array ] 2map`: megtartja a párokat, ahelyett hogy összevonná őket.

## Rendezés

A `sort` egy rendezett másolatot ad vissza természetes sorrendben; a `sort-by` (a [`sorting`][sorting] szótárban) pedig egy-egy elemből kinyert kulcs alapján rendez:

```
sort    ( seq      -- sortedseq )
sort-by ( seq quot -- sortedseq )
```

```factor
{ 3 1 4 1 5 9 2 6 } sort .
! => { 1 1 2 3 4 5 6 9 }

{ -3 5 -1 4 } [ abs ] sort-by .
! => { -1 -3 4 5 }
```

## Összesítés

A `map-sum` (a [`sequences`][sequences] szótárban) egyetlen bejárással leképezi a quotationt a sorozatra, és összeadja az eredményeket:

```
map-sum ( seq quot -- n )
```

```factor
{ 1 2 3 4 } [ sq ] map-sum .   ! => 30
```

## Minimum és maximum

A `minimum` és a `maximum` közvetlenül a sorozat legkisebb, illetve legnagyobb elemét adja vissza. A `minimum-by` és a `maximum-by` (mindkettő a [`sequences`][sequences] szótárban) pedig azt az elemet adja vissza, amelynek a kinyert kulcsa a legkisebb vagy a legnagyobb:

```
minimum     ( seq      -- elt )
maximum     ( seq      -- elt )
minimum-by  ( seq quot -- elt )
maximum-by  ( seq quot -- elt )
```

```factor
{ 3 1 4 1 5 9 2 6 } minimum .       ! => 1
{ 3 1 4 1 5 9 2 6 } maximum .       ! => 9

{ -3 5 -1 4 } [ abs ] minimum-by .
! => -1
```

## Írj saját magasabb rendű szót

Amikor *a te* szavad egy quotationt kap futásidejű argumentumként, és továbbadja a `map`, a `filter`, az `each` és társaik számára, akkor `; inline` módon deklaráld a szavadat. Ez megmondja a fordítónak, hogy minden hívási helyen inline-olja a szavadat, ahol a quotation ismert literál: enélkül a fordító semmilyen módon nem tudhatja a quotation stackhatását.

```factor
USING: math sequences ;

: tax-on ( inventory quot -- total )
    map-sum ; inline

{ { "shirt" 20 } { "hat" 15 } } [ second 1/10 * ] tax-on .
! => 3+1/2
```

Azok a szavak, amelyek csak literál quotationökből épülnek fel, nem igényelnek `inline`-t, csak azok, amelyek egy *bejövő* quotationt adnak tovább.

Ha egy ilyen `inline` szó valaha *önmagát* hívja, azaz rekurzív kombinator, akkor helyette `; inline recursive` módon deklaráld. A külön szó nélkül a fordító azzal áll le, hogy *„The inline recursive word ... must be declared recursive”*, ami pontosan megmondja, mit kell hozzáadnod.

## A második elem kinyerése

Egy kételemű tömb esetén a `second` a második elemét adja vissza. A `first` az elsőt. Mindkettő a [`sequences`][sequences] szótárban található.

## Számokból stringek

A `number>string ( n -- str )` (a [`math.parser`][math.parser] szótárban) egy számot a tizedes string alakjára fordítja:

```factor
42 number>string .     ! => "42"
3.5 number>string .    ! => "3.5"
```
