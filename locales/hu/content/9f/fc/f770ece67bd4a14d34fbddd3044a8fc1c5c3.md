# A karakterekről

Ez potenciálisan egy _nagy_ téma!
Lehetne róla egy vaskos könyvet írni, és többen meg is tették (keress rá az Amazonon a „unicode book” kifejezésre, ha látni szeretnél néhány példát).

## Egy nagyon rövid történelem

A karakterek kezelése a számítógépeken sokkal egyszerűbb volt a korábbi évtizedekben, amikor a programozók azt feltételezték, hogy az angol az egyetlen fontos nyelv.
Tehát: 26 betű kis- és nagybetűvel, 10 számjegy, néhány írásjel, plusz egy kód (0x07) a csengő megszólaltatásához, és mindez belefért 7 bitbe: az [ASCII][wiki-ascii] karakterkészletbe.

Természetesen az emberek elkezdték kérdezni, mi van az à, ä és Ł karakterekkel, aztán mások azt firtatták, mi van az ऄ, ஹ és ญ jelekkel, a fiatalok pedig emojikat akartak 😱.
Mit lehet ilyenkor tenni?

Hogy rövidre fogjuk: sok okos és türelmes embernek évekig kellett bizottságokban ülnie, hogy kidolgozza a [Unicode][web-unicode] karakterkészlet és az olyan kódolások részleteit, mint a [UTF-8][wiki-utf-8], ráadásul rengeteg szoftvert kellett _nagyon_ bonyolult módon újraírni.
Ráadásul rengeteg új hiba is keletkezett.

Hogy ne _minden_ törjön el, a Unicode/UTF-8 kialakítása gondoskodik róla, hogy az első 127 kód megegyezzen az ASCII-val _(még a csengő is)_.

## Karakterek Kotlinban

A nagyjából 2005 után tervezett nyelveknek hatalmas előnyük, hogy már létezett egy viszonylag stabil Unicode-szabvány.

A Kotlin (amely 2011-ben jelent meg először) abból indulhatott ki, hogy a felhasználók sokféle (emberi) nyelvet használnak majd, és szükségük lesz a Unicode-ra, hogy kifejezhessék őket.

~~~~exercism/advanced
A Kotlinban a [karakterek][ref-char] 16 bites (UTF-16) [`codepoints`][wiki-codepoint] értékek, ugyanazok, mint egy JVM `char`.
Ez elég a legtöbb írott ábécé kifejezéséhez, de nem terjed ki az emojik teljes skálájára.

A teljes Unicode-szabvány akár hat bájtot (48 bitet) is használhat karakterenként (ezt nevezik [`grapheme`][wiki-grapheme]-nek).

A Kotlin `Strings` támogatja ezt a teljes szabványt azzal, hogy szükség esetén több kódpontot használ karakterenként.
Például a 😱 a `\uD83D` és a `\uDE31` kódpontokból áll.

Sajnos a Java-nak nincs beépített grapheme-támogatása, és a kompatibilitás miatt a Kotlinnak sem.

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


A karakterliterálokat aposztrófok közé írjuk, és különböznek a dupla idézőjelbe zárt stringektől.
Ez valószínűleg magától értetődő a C/C++ világából érkezőknek, de a Python- és JavaScript-programozóknak zavaró lehet.

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

A `Char` és az `Int` közötti átalakítás egyszerű:

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

A fordító a `Char`-okon _néhány_ egészszám-aritmetikai műveletet engedélyez:

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## Néhány függvény a `Char` típushoz

Ahogy mindig, most is túl [sok függvény][ref-char-lib] van ahhoz, hogy itt mindet tárgyaljuk, szóval ez csak egy válogatás.

- A megfelelő ábécéknél válts kis- és nagybetűk között az [`uppercase()`][ref-uppercase] és a [`lowercase()`][ref-lowercase] függvénnyel.
- Vizsgáld a kis- és nagybetűsséget az [`isUpperCase()`][ref-isuppercase] és az [`isLowerCase()`][ref-islowercase] függvénnyel.
- Vizsgáld a karakter típusát ezekkel:
  - [`isLetter()`][ref-isletter], sok ábécét lefed (a Unicode Lu, Ll, Lt, Lm és Lo kategóriáit)
  - [`isDigit()`][ref-isdigit], a 0..9 tartományban (a Unicode Nd kategóriája)
  - `isLetterOrDigit()`, az előző kettőt ötvözi
  - [`isWhitespace()`][ref-iswhitespace], bármilyen whitespace karakter (a Unicode Cc, Zp, Zl és Zs kategóriái)

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

Emellett a [reguláris kifejezések][ref-regex] (amelyekről egy későbbi fogalom szól majd) hatékony keresést és manipulációt tesznek lehetővé.

## `Char`-lista és string közötti átalakítások

Ahhoz, hogy egy `String`-et `Char`-ok `List`-jévé alakítsunk, használhatjuk a `toList()` függvényt.

Ahhoz, hogy egy `Char`-okból álló `List`-et `String`-gé alakítsunk, ott van a [`joinToString()`][ref-jointostring] függvény, amely egy elválasztót (gyakran az üres stringet) vesz argumentumként.

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

Figyeld meg, hogy a `joinToString()` egy List-en vagy Array-n működik.
Ha egyetlen `Char`-t egyetlen karakterből álló stringgé szeretnél _átalakítani_, használd a `toString()` függvényt.

```kotlin
'a'.toString() // => "a"
```

Ha ellenőrizni szeretnéd, hogy egy karakter szerepel-e egy `String`-ben, illetve egy `Char`-okból álló listában vagy tömbben, használhatod az `in` operátort, amely a [`contains()`][ref-contains] függvényre képeződik le.

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
