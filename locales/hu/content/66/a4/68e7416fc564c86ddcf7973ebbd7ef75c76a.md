# Bemutatás

## Bevezetés

Az opaque típusok egy egységbezárási technika az Elmben.
Egyesek ezt információelrejtésnek vagy az implementációs részletek elrejtésének is nevezik.
Gyakran használják arra is, hogy kikényszerítsék az érvényesítést, a [Parse, dont validate][parse-dont-validate] minta segítségével.
Például lehet egy `EmailAddress` opaque típusod, amely csak érvényes e-mail-címeket tartalmazhat (ellentétben a `String` típussal, amely bármit tartalmazhat).

## Opaque típus létrehozása

A [Custom types][custom-types] egy vagy több *változattal* rendelkeznek, és a fordító automatikusan generál egy függvényt minden *változat* létrehozásához, a *változat* nevével.
Ezek az egyetlen módjai annak, hogy egyedi típusokat létrehozzunk.
A fordító ezen változatok destrukturálását is lehetővé teszi.

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

Alapértelmezés szerint mindez a fájlon / modulon belül marad, és az `exposing` kulcsszóval választjuk ki, mit exportálunk.
Opaque típus létrehozásához egyszerűen csak nem exportálod a *változatokat*.
Amikor ezt teszed, szinte mindig biztosítanod kell egy másik módot a *változatok* létrehozására és lekérésére, egyedi függvények exportálásával.
Ezek az egyedi függvények lehetővé teszik, hogy valamilyen logikát alkalmazz a *változatok* létrehozásakor és lekérésekor.
Ez elrejti a modul belső implementációs részleteit, és azt jelenti, hogy annyit változtathatsz az implementációs részleteken, amennyit csak szeretnél, mindaddig, amíg az exportált függvények ugyanazok maradnak.

## Parse, don't validate

Az opaque típusok talán leggyakoribb felhasználása az érvényesítés kikényszerítése, a [Parse, dont validate][parse-dont-validate] minta segítségével.
Ebben a mintában olyan függvényt exportálsz, amely egy olyan bemenetet vesz át, amely kevesebb struktúrával / típusbiztonsággal rendelkezik, mint amit szeretnél, például egy `String`-et, majd ezt egy strukturáltabb típussá értelmezed, amilyen például az `EmailAddress`, és vagy visszaadja a típust, vagy hibát ad vissza (általában `Maybe` vagy `Result`).

Például az alábbi kódban csak külső modulok hozhatnak létre `EmailAddress` típust a `parseEmailAddress` függvénnyel, így amikor az `EmailAddress` típussal dolgozol, biztos lehetsz benne, hogy érvényes.

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
