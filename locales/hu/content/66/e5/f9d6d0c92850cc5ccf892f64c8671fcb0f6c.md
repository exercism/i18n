# Bevezetés

Valahányszor meghívunk egy függvényt, a memóriában létrejön egy új veremkeret, amely a függvény argumentumait és lokális változóit tárolja, és ez a veremkeret felszabadul, amikor a függvény visszatér. Mivel a Gleam ciklusszintaxis helyett rekurzív függvényhívásokat használ, előfordulhat, hogy ezek a veremkeretek nagy mennyiségű memóriát foglalnak el.

Hogy elkerüljük ezt a problémát, a Gleam támogatja a farokhívás-optimalizálást, amelynek köszönhetően a fordító újrahasznosíthatja az aktuális függvény veremkeretét, ha a függvény legutolsó művelete egy függvényhívás. Ez azt jelenti, hogy egy függvény akár végtelen sokszor is meghívhatja önmagát anélkül, hogy további memóriát használna.

A nem optimalizált rekurzív függvények gyakran átírhatók farokhívás-optimalizált függvényekké egy _akkumulátor_ segítségével.

Az akkumulátor egy olyan változó, amelyet az adatok mellett adunk át. A függvény végrehajtásának aktuális állapotát adjuk vele tovább egészen az alapeset eléréséig.

Az akkumulátort a függvény írójának kell inicializálnia, nem a függvény felhasználójának. Ehhez két függvényt kell deklarálni: egy nyilvános függvényt, amely csak a szükséges adatokat veszi át argumentumként, és inicializálja az akkumulátort, valamint egy privát függvényt, amely már az akkumulátort is átveszi.

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
