# Bevezetés

A `Complex numbers` nem bonyolult.
Csak egy kevésbé ijesztő névre van szükségük.


Annyira hasznosak, különösen a mérnöki munkában és a tudományban, hogy a Python a [`complex`][complex] típust is beépítette szabványos numerikus típusként, az egész számok ([`int`][ints]) és a lebegőpontos számok ([`float`][floats]) mellett.


A `complex` érték a Pythonban lényegében két lebegőpontos szám párosa:

```python
>>> my_complex = 5.443+6.77j
(5.443+6.77j)
```

Ezeket „valós” és „képzetes” résznek nevezik.
Talán hallottad már, hogy „az `i` (vagy `j`) a -1 négyzetgyöke”.
Egyelőre ez annyit jelent, hogy a képzetes rész _definíció szerint_ kielégíti az `1j * 1j == -1` egyenlőséget.
Ez egyszerű gondolat, de érdekes matematikai következményekhez vezet.

A Pythonban a „képzetes” részt `j` jelöli (_nem `i`, ahogy a matematikakönyvekben láthatod_), és
a `j`-nek közvetlenül egy szám után kell állnia, hogy a Python ne értelmezze változónévként:


```python
>>> j
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
NameError: name 'j' is not defined

>>> 1j
1j

>>> type(1j)
<class 'complex'>
```


Két gyakori módja van a komplex számok létrehozásának.

1) A [`complex(real, imag)`][complex] konstruktor két `float` paramétert vár:

    ```python
    >>> z1 = complex(1.5, 2.0)
    >>> z1
    (1.5+2j)
    ```

    A konstruktor stringbemenetet is fel tud dolgozni.
    Ennek az a furcsa korlátja, hogy hibát ad, ha a string szóközt tartalmaz.

    ```python
    >>> complex('4+2j')
    (4+2j)
    
    >>> complex('4 + 2j')
    Traceback (most recent call last):
      File "<stdin>", line 1, in <module>
    ValueError: complex() arg is a malformed string
    ```


2) A komplex szám megadható `<real part> + <complex part>j` literálként, vagy csak `<complex part>j` alakban, ha a valós rész nulla:


    ```python
    >>> z2 = 2.0 + 1.5j
    >>> z2
    (2+1.5j)
    ```
    A végeredmény ugyanaz, mint a `complex()` konstruktor használatakor.


## Aritmetika

A floatokkal és intekkel használt [`operators`][operators] többsége komplex számokkal is működik.

Komplex számokon egész osztás _**nem**_ lehetséges, ezért a `//` és `%` operátorok, valamint a `divmod()` függvény hibára futnak a komplex típus esetén.

A komplex számok szorzási és osztási szabályainak magyarázata túlmutat ezen a fogalmon (_és valószínűleg nem is kell ezeket a műveleteket túl gyakran „kézzel” elvégezned_).

Ha szeretnél mélyebben beleásni a témába, bármely [matematikai][math-complex] vagy [villamosmérnöki][engineering-complex] bevezető a komplex számokról kitér ezekre az esetekre.

A Python szabványos könyvtárában van egy [`math`][math-module] modul, tele hasznos funkcióval a valós számok kezeléséhez, és a [`cmath`][cmath] modul ennek megfelelője a komplex számok kezeléséhez.
