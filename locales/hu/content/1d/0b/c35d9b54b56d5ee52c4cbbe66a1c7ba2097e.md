# Részletesen

C#-ban egy _osztály_hierarchia _örökléssel_ definiálható, ami lehetővé teszi, hogy egy származtatott osztály (`Car`) örökölje a szülőosztálya (`Vehicle`) viselkedését és adatait. Ha nincs megadva szülő, az osztály az `object` osztályból örököl.

A szülőosztályok háromféleképpen biztosíthatnak funkciókat a származtatott osztályoknak:

- Egy sima metódus definiálásával.
- Egy [`virtual` metódus][virtual-keyword] definiálásával, amely hasonló a sima metódushoz, de a származtatott osztályok _megváltoztathatják_.
- Egy [`abstract` metódus][abstract-keyword] definiálásával, amely implementáció nélküli metódus, és amelyet a származtatott osztályoknak _implementálniuk kell_. Az `abstract` metódusokat tartalmazó osztályt magát is [`abstract`][abstract-classes] jelöléssel kell ellátni. Az absztrakt osztályokat nem lehet példányosítani.

A [`protected` hozzáférés-módosító][protected-keyword] lehetővé teszi, hogy egy szülőosztály-tag elérhető legyen egy származtatott osztályban, de blokkolja a hozzáférést más osztályokból. A származtatott osztályok így hozzáférhetnek a szülőosztály `public` és `protected` tagjaihoz, de a `private` tagjaihoz nem.

A származtatott osztályok a [`base` kulcsszó][base-keyword] segítségével érhetik el a szülőosztály tagjait.

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

// Cannot be inherited from
sealed class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

Egy származtatott osztály konstruktora [automatikusan meghívja a szülője konstruktorát][constructors] _mielőtt_ végrehajtaná a saját konstruktorának logikáját. A szülőosztály konstruktorának argumentumokat adhatunk át a [`base` kulcsszó][base-keyword-constructor] segítségével. Mivel az absztrakt osztályokat nem lehet példányosítani, a konstruktoraik `protected`-té tehetők.

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

Amikor egynél több osztály származik egy alaposztályból, a két (vagy több) alosztály gyakran egy alaposztály-metódus különböző változatait valósítja meg. Ez egy nagyon fontos elv, amelyet [polimorfizmusnak][polymorphism] nevezünk. Például a fenti példa egy változatában megmutatjuk, hogyan változtathatja meg a viselkedését a `Vehicle`-t használó kód attól függően, hogy milyen típusú járművet példányosítottunk.

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```

Hogy megakadályozzuk egy osztály öröklését, használd a [`sealed` módosítót][sealed-classes].
Egyes gyakorlók igyekeznek elkerülni a konkrét osztályokból való öröklést (ahogy az [erről a Stack Overflow-kérdésről][pro-sealed] szóló vita is mutatja), és a _sealed_ módosító támogatja ezt a megközelítést. Másrészt sok C#-fejlesztő a karbantartás akadályának tartja őket, ahogy az [erre a kérdésre][anti-sealed] érkezett hozzászólások némelyikében is olvasható. A tanács az, hogy mértékkel használd a sealed módosítót, amíg kellő magabiztosságot nem szerzel abban, hogy a használatuk megfelel az igényeidnek.

A következő [cikk][new-vs-override] a `new`-ot mutatja be az `override` módosító alternatívájaként. Ez alkalmanként hasznos lehet, talán bonyolult osztályhierarchiák és/vagy valamilyen könyvtárütközés esetén.
