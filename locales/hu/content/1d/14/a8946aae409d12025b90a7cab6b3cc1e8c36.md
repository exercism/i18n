# Bevezetés

## Farokhívás-optimalizálás

Valahányszor meghívunk egy függvényt, a memóriában létrejön egy új veremkeret, amely a függvény argumentumait és lokális változóit tárolja, és ez a veremkeret felszabadul, amikor a függvény visszatér. Mivel a Gleam ciklusszintaxis helyett rekurzív függvényhívásokat használ, ezek a veremkeretek könnyen rengeteg memóriát foglalhatnak le.

Hogy ezt a problémát elkerülje, a Gleam támogatja a farokhívás-optimalizálást: ilyenkor a fordító újrahasznosíthatja az aktuális függvény veremkeretét, ha a függvényhívás a függvény utolsó művelete. Ez azt jelenti, hogy egy függvény végtelen sokszor hívhatja meg önmagát anélkül, hogy további memóriát használna.

Az optimalizálatlan rekurzív függvényeket gyakran átírhatjuk farokhívás-optimalizált függvényekké egy _akkumulátor_ segítségével.

Az akkumulátor egy olyan változó, amelyet az adatok mellett adunk át. Arra szolgál, hogy továbbadja a függvény végrehajtásának aktuális állapotát egészen az alapeset eléréséig.

Az akkumulátor kezdőértékét a függvény szerzőjének kell beállítania, nem a függvény felhasználójának. Ehhez két függvényt kell deklarálni: egy nyilvános függvényt, amely csak a szükséges adatokat veszi át argumentumként, és beállítja az akkumulátor kezdőértékét, valamint egy privát függvényt, amely az akkumulátort is átveszi.

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
