# Részletek

A [ciklus][control] egy utasítássorozat, amelyet potenciálisan többször is végrehajtunk, amíg egy befejező feltétel nem teljesül.

Az x86-64-ben a ciklust általában egy korábbi címkére való ugrással hozzuk létre:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Vedd észre, hogy egy feltétel nélküli ugrás egy korábbi címkére mindig erre a címkére adja át a vezérlést.
Ez azt jelenti, hogy a ciklus a végtelenségig ismétlődik, hacsak nincs egy másik ugrás az ismételt sorozaton kívülre.

Például ez a ciklus nem ér véget:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

Ez a ciklus pedig véget érhet, attól függően, hogy a feltétel teljesül-e:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## Számlálóciklusok

A számlálóciklus majdnem mindig ugyanúgy végződik: egy utasítás, amely frissít egy számlálót vagy összehasonlít két értéket, közvetlenül utána pedig egy feltételes ugrás következik, amely eldönti, hogy újra végigmenjen-e.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
A fenti kódban nem szükséges a `cmp rsi, 0`, mert a `sub rsi, 1` már beállítja a `zero flag (ZF)` jelzőt, amikor az eredmény `0`.

Bár a `cmp` az elsődleges módja a feltételek tesztelésének assemblyben, sok utasítás frissíti a jelzőket.
Például sok egész aritmetikai vagy bitenkénti utasítás frissíti a `ZF` jelzőt, amikor az eredmény `0`, és az `SF` jelzőt, amikor az eredmény negatív (azaz a legfelső bit be van állítva).

Megnézheted a [referenciát][reference] is, hogy lásd, melyik utasítás mely jelzőket érinti.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Vedd észre, hogy a fenti példában az `rsi` értékéről feltételezzük, hogy nagyobb, mint `0`.
Ha `0` lenne, akkor a `sub rsi, 1` `-1`-re csökkentené az `rsi`-t, ami előjel nélküli számként rendkívül nagy érték.
Még `18,446,744,073,709,551,615` iteráció kellene, mire a ciklus végleg befejeződne.
Ráadásul, mivel a tömb hossza `0`, bármilyen memóriahozzáférés a tartományon kívülre esne.

Ha nincs garancia a tömb hosszára, két gyakori megközelítés van.

Az első, hogy a befejező feltételt a ciklus elejére helyezzük, majd a végére egy feltétel nélküli ugrást teszünk:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

A második, hogy a ciklus kezdete előtt egyszer ellenőrizzük a nulla hosszúságú tömböt:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Ez a második megközelítés általában hatékonyabb az elsőnél, mert kevesebb elágazás van a ciklus törzsében.
Erről egy későbbi fogalomban tanulsz majd többet.

## Mikro-opok

A processzor nem hajt végre közvetlenül egy olyan utasítást, mint az `add` vagy a `jnz`.
A CPU front-endje először _dekódolja_ az egyes utasításokat egy vagy több kisebb belső lépésre, amelyeket **mikrooperációknak** (vagy **mikro-opoknak**) nevezünk.
A processzor ezután ütemezi és végrehajtja ezeket a mikro-opokat, gyakran többet is ciklusonként, és az eredeti sorrendjüktől eltérve.

A legtöbb egyszerű utasítás egyetlen mikro-oppá dekódolódik, míg egy összetettebb utasítás többé is dekódolódhat.
Mivel a processzor valódi munkaterhelése a mikro-opok folyama, ugyanazon feladat kevesebb mikro-oppal való megoldása az egyik módja annak, hogy a kód gyorsabb legyen.

## Makrófúzió

Ahogy korábban említettük, a ciklus általában valamilyen feltételes ugrással végződik.
Ez annyira gyakori, hogy a modern processzorok a dekódolás során erre a mintára vannak optimalizálva.

Egy jelzőt beállító utasítás, amelyet közvetlenül egy olyan feltételes ugrás követ, amely ezeket a jelzőket olvassa, együtt **egyetlen** mikro-oppá dekódolható, nem pedig külön-külön eggyé.
Ezt **makrófúziónak** nevezzük.

Az összeolvadt pár egyetlen műveletként viselkedik: a számláló frissítése és az elágazási döntés együtt, egyetlen mikro-opban történik.
A ciklus vezérlési folyamata így szinte semmibe sem kerül a ciklus tényleges munkáján felül.

Ökölszabályként kétféle pár olvad össze általában így:

- Aritmetikai utasítások, mint az `add` vagy a `sub`, amelyeket közvetlenül feltételes ugrás követ.
- Egy `cmp`, `test` vagy `and`, amelyet közvetlenül feltételes ugrás követ.

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

Az összeolvadás csak akkor történik meg, ha a feltételes ugrás **közvetlenül** a jelzőt beállító utasítás után következik, és nincs közöttük semmi.

~~~~exercism/note
A makrófúzió a CPU-tól függ, és van némi eltérés abban, hogy mely utasítások mely feltételes ugrással olvadnak össze.

Egy hasznos referencia a [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch].
Az [Intel optimization reference manual][intel-opt] 3.4.2.2. szakasza (Optimizing for Macrofusion) szintén felsorolja az Intel CPU-khoz összeolvasztható párokat.

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## A `loop` utasítás

Van néhány utasítás, amellyel ciklusszerű viselkedést lehet létrehozni.
Ezek egyike a [loop][loop].

Egyetlen operandusa egy címke, amely a ciklus kezdetének címét tartalmazza.

A `loop` utasítás az `rcx` értékét használja számlálóként, és minden alkalommal 1-gyel csökkenti.
Amint az `rcx` értéke eléri a nullát, a ciklus véget ér, és a végrehajtás sorban folytatódik:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

A `loop` utasításnak két változata van, amelyek minden iterációban ellenőrzik a nulla jelzőt (`ZF`).
Amellett, hogy leállítják a ciklust, amint az `rcx` eléri a nullát, akkor is leállnak, ha a feltétel _nem_ teljesül.

| utasítás          | feltétel  |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == 1 |
| `loopne`/`loopnz` | `ZF` == 0 |

A `ZF`-et **nem** ezek az utasítások állítják be.
Előttük kell lennie egy `cmp`, `test` vagy más utasításnak, amely megváltoztatja a `ZF`-et:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
Kényelmük ellenére a `loop`, `loope` és `loopne` általában sokkal lassabbak a modern processzorokon, mint a megfelelő `sub`/`jnz` vagy `cmp`/`jnz` sorozat.

Az utasítások teljesítményéről sok különböző CPU-n az [Agner's tables][agner-tables] jó referencia.

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
~~~~
