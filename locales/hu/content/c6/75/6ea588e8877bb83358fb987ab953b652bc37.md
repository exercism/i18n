# Bevezetés

A Factor hibarendszere három részből áll: a `throw` a hiba jelzésére, a `recover` egy hiba kezelésére, az `ERROR:` pedig saját hibatípus definiálására.

## `throw`

A `throw` (a [`kernel`][kernel] szótárban) hibát vált ki. Az argumentum *bármilyen* érték lehet (string, szám vagy tuple), és ez lesz a hiba, amit később megvizsgálhatsz:

```factor
! DOCTEST: SKIP
"file not found" throw
```

A `throw` nem tér vissza; az aktuális szó többi része kimarad.

## `recover`

A `recover` (a [`continuations`][continuations] szótárban) a Factor try/catch mechanizmusa. Egy *try* és egy *recovery* quotationt vár:

```
recover ( try recovery -- )
```

Ha a `try` dobás nélkül befejeződik, a `recovery` figyelmen kívül marad. Ha a `try` dob, a hiba a verembe kerül, és a `recovery` lefut:

```factor
[ "boom" throw ] [ drop "caught" ] recover .
! => "caught"

[ "ok" ] [ drop "never runs" ] recover .
! => "ok"
```

A `when` (a [`kernel`][kernel] szótárból) a természetes társa: csak akkor futtat egy quotationt, ha a verem tetején lévő érték igaz értékű:

```factor
: check-positive ( n -- )
    0 < [ "negative!" throw ] when ;
```

## `ERROR:`

Az `ERROR:` egy tuple osztályt *és* egy szót definiál, amely létrehoz egy friss példányt, és dobja azt:

```factor
! DOCTEST: SKIP
ERROR: not-found path ;

"/missing" not-found
! throws T{ not-found { path "/missing" } }
```

A slot nélküli hiba egyszerűen `ERROR: name ;`; a `name` meghívása egy üres példányt dob. Az `ERROR:` kulcsszóval definiált tuple-ok rendelkeznek egy `name?` osztálypredikátummal, amellyel tesztelheted, hogy egy elkapott hiba ilyen típusú volt-e.

## A slotok visszaolvasása

Az elkapott hiba csupán egy tuple, így minden `ERROR:` slot ugyanazzal az automatikusan generált `slot>>` olvasóval rendelkezik, mint bármely más tuple.

```factor
! DOCTEST: SKIP
{
    T{ not-found { path "/a" } }
    T{ not-found { path "/b" } }
}
[ path>> ] map .   ! => { "/a" "/b" }
```
