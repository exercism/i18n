# Nil

A Crystalben létezik egy [`Nil`][nil] nevű típus, amelynek csak egyetlen értéke lehet: `nil`.
Arra való, hogy egy érték hiányát jelezze, és hasonló a más nyelvekbeli `null`-hoz vagy `None`-hoz.

A `nil` értéket több metódus is visszaadhatja, például a [`String#[]?`][string-index], amely `nil`-t ad vissza, ha az index kívül esik a tartományon.

```crystal
"foo"[10]? # => nil
```

A Crystalben léteznek az úgynevezett **null referencia ellenőrzések**, ami azt jelenti, hogy alapértelmezés szerint egyetlen típus sem fogadhat el `nil` értéket.
Ez azt jelenti, hogy nem rendelhetsz `nil`-t egy változóhoz, hacsak kifejezetten nem `Nil` típusúként deklarálod.
Ez pedig azt jelenti, hogy a fordító automatikusan ellenőrzi a null referenciákat.

## Hamis érték

A `nil` értékek kezelésére többféle megközelítés kínálkozik.
A `nil` [hamis értékű][truthy-falsey] érték, akárcsak a `false`.
Ez azt jelenti, hogy az utasításokban és minden más helyen, ahol hamis vagy igaz értéket várunk, ugyanúgy kezelik, mint a `false`-t.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Ez azt jelenti, hogy ha egy nil-képes változó értéke `nil`, akkor nem az igaz ág fut le.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## A nil ellenőrzése

A Crystalben van egy metódus, amellyel ellenőrizheted, hogy egy érték `nil`-e.
A neve [`nil?`][nil?], és minden objektumon elérhető.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Ez kicsit másképp működik, ha csupán egy elágazásban használod az értéket, mivel az előző példákban a hamis és a nil is hamisként viselkedne.
Itt viszont csak a `nil` számít hamisnak, ugyanis ha az érték hamis lett volna, akkor nem nil lett volna, és így igaz értékű lett volna.

## A vagy operátor

A `nil` értékek kezelésének legegyszerűbb módja, ha eleve megakadályozod, hogy egyáltalán `nil` legyen belőlük.
A vagy operátort ([`||`][or]) gyakran `Bools` értékeknél használjuk, de ha jól értjük, a `nil` értékek kezelésére is beválik.
A vagy operátor megnézi, hogy az első érték igaz-e; ha nem, akkor a második értéket használja.
Ez arra használható, hogy ha egy érték `nil`, akkor hamisnak számítson, és így a második értéket kapjuk.

```crystal
"foo"[10]? || "bar" # => "bar"
```
