# A bitekről

A bináris számjegyek végső soron közvetlenül megfelelnek a processzorod vagy a memóriád tranzisztorainak, illetve annak, hogy mindegyik „be” vagy „ki” állapotban van-e.

Az alacsony szintű manipuláció, amit informálisan „bit-twiddling-nek” neveznek, különösen fontos a rendszerprogramozási nyelvekben.

A Kotlinhoz hasonló magasabb szintű nyelvek általában elrejtik ezeknek a részleteknek a nagy részét.
A bit szintű műveletek egy alapvető köre azonban [elérhető][ref-bitwise].

~~~~exercism/note
Ahhoz, hogy ember által olvasható bináris kimenetet láss, az alábbi példák szinte mindegyikét be kell csomagolni egy [`Integer.toBinaryString()`][web-binstring] függvénybe, vagy `toString(radix = 2)` hívással kell átalakítani.
 
Ez vizuálisan zavaró lenne, ezért a legtöbb helyen elhagytuk ezt a függvényt, és az eredményeket `0b` jelöléssel adjuk meg.

## Biteltolási műveletek

Az `Int` vagy `Long` típusok, mind előjeles, mind előjel nélküli változatban, ábrázolhatók 1-esekből és 0-kból álló stringként, és bitenkénti sorozatként manipulálhatók.

Talán meglepő, de a `Byte` és `Short` típusok nem kompatibilisek a Kotlin legtöbb bitenkénti műveletével.
Az alábbi példák mind 32 bites egészeket (`Int` vagy `UInt`) használnak.

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

A biteltolások mindent balra vagy jobbra mozgatnak egy megadott számú pozícióval.
Az egyik végén néhány bit kiesik, a másikat pedig nullákkal vagy egyesekkel töltjük fel.

- Balra tolás a `shl` operátorral: nullákkal való feltöltés.
- Jobbra tolás a `shr` vagy `ushr` operátorral: pozitív számoknál nullákkal való feltöltés (a negatív számokat lásd egy későbbi szakaszban).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Minden balra tolás megduplázza az értéket, minden jobbra tolás pedig felezi (az esetleges csonkolást figyelembe véve).
Ez tízes számrendszerben még nyilvánvalóbb:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Az ilyen biteltolás sokkal gyorsabb, mint a „rendes” aritmetika, ezért ez a technika nagyon népszerű az alacsony szintű programozásban.

### Negatív egészek biteltolása

A _negatív egészeknél_ egy kicsit óvatosabban kell eljárnunk.

A negatív értékek [kettes komplemens][wiki-2complement] formában tárolódnak, ami azt jelenti, hogy a legbaloldalibb bit 1.
Balra tolásnál ez nem jelent problémát, de jobbra tolásnál hogyan töltjük fel a legbaloldalibb biteket?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

A [`shr`][ref-shr] operátor [aritmetikai eltolást][wiki-arithmetic] végez, megőrizve az előjelbitet.

Az [`ushr`][ref-ushr] operátor [logikai eltolást][wiki-logical] végez, nullákkal töltve fel, mintha a szám előjel nélküli lenne.

## Bitenkénti logika

A [Booleanok][concept-booleans] fogalomban láttuk, hogy a `&&` (and), `||` (or) és `!` (not) operátorokat boolean értékekkel használjuk.

Vannak ezzel egyenértékű operátorok, az `and`, `or`, `xor` ([kizáró vagy][wiki-xor]), amelyek két egész szám bitjeit hasonlítják össze, valamint egy `inv` (inverzió) függvény, amely az összes bitet megfordítja.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
