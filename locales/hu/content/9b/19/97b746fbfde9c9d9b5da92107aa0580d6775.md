# Részletesen

A memóriát a program számára általában az operációs rendszer (OS) képezi le egy általános elrendezés szerint:

| cím     | memóriaterület         |
| :-----: | :--------------------- |
|  magas  | verem                  |
|         | ...                    |
|         | halom                  |
|         | olvasható és írható szegmens |
|         | kód / csak olvasható szegmens |
|   alacsony   | fenntartott        |

A szegmensekre tagolt memória szakaszokba rendeződik, amelyek különböző jogosultságokkal rendelkeznek.

Az eddig definiált függvények mind a **.text szakaszban** voltak.
Ez a szakasz csak olvasható, végrehajtható adatot tartalmaz.
Más szakaszok adatváltozók deklarálására szolgálnak, amelyek lehetnek csak olvashatók vagy írhatók, de nem végrehajthatók.

## A .data szakasz

Az inicializált adatokat a **[.data szakasz][data]** deklarálja.

A NASM-ben (The Netwide Assembler, a kurzus által használt assembler) egy inicializált változónak van egy neve, egy direktívája, amely megadja az adat méretét, és egy vesszővel elválasztott értéklistája.
Ezeket szóköz választja el egymástól, a címkét pedig opcionálisan `:` követheti.

A legfontosabb direktívák és a hozzájuk tartozó adatméret:

| direktíva | méret   |
| :-------: | :------ |
|    db     | 1 bájt  |
|    dw     | 2 bájt  |
|    dd     | 4 bájt  |
|    dq     | 8 bájt  |

Ez például egy `space` nevű, 1 bájt méretű változót deklarál `10` értékkel:

```x86asm
section .data
    space db 10
```

A `section .data` szakaszban deklarált változók módosíthatók, azaz olvashatók és írhatók.
Emellett _statikus_ tárolási időtartammal rendelkeznek, ami azt jelenti, hogy a program teljes futása alatt léteznek.

## A .rodata szakasz

A **.rodata szakasz** hasonló a `section .data` szakaszhoz.
Mindkét szakasz inicializált adatot tartalmaz, amelyet ugyanúgy deklarálunk, és a tárolási időtartamuk is megegyezik.

A fő különbség köztük az, hogy a `section .rodata` szakaszban lévő adat megváltoztathatatlan, azaz csak olvasható.

~~~~exercism/note
A `equ` kulcsszóval definiált konstansok mások, mint a `section .rodata` szakaszban definiáltak.

A `equ` kulcsszóval definiált konstans nem foglal helyet a memóriában, és az assembler közvetlenül a helyére írja az értékét.
Valójában csak egy helyőrző az adott érték számára.

Ezzel szemben a `section .rodata` szakaszban definiált konstansok ténylegesen a memóriában tárolódnak, és rendelkeznek címmel.
~~~~

## Az adatok elérése

### Címkék és indirekció

A deklarált adatokhoz névnek kell kapcsolódnia.
Ezt a nevet **címkének** nevezzük.

A címke egy szimbólum, amely a memóriában lévő adat pontos címét jelöli.
**Az x86-64 architektúrán a címek 64 bites értékek**.
Az ilyen címet tartalmazó értéket, akár regiszterben van, akár a memóriában tárolódik, a magasabb szintű nyelvek **[mutató][pointer]** néven emlegetik.

A NASM-ben, ha egy adatot közvetlenül a címkéjével próbálunk elérni, nem a lefoglalt memóriát kapjuk meg, hanem annak a címét:

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

Ahhoz, hogy hozzáférjünk egy memóriacím tartalmához, _dereferálni_ kell azt.
Ezt nevezzük **indirekciónak**.

A NASM-ben erre a `[]` szolgál:

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

Vannak azonban olyan helyzetek, amikor nem egyértelmű, hogy mekkora memóriát dereferálunk.
Ilyenkor egy, a méretet megadó előtagot kell használni.

Ezek a legfontosabb előtagok és a méretük egy tipikus x86-64 programban:

| előtag | méret   |
| :----- | :------ |
| byte   | 1 bájt  |
| word   | 2 bájt  |
| dword  | 4 bájt  |
| qword  | 8 bájt  |

Ugyanez a betöltés kiírható a méret egyértelmű megadásával is:

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

Jó gyakorlat, ha memória dereferálásakor mindig használunk előtagot.

### Írás a memóriába

A memóriába írás ugyanígy történik, egy cím dereferálásával:

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

Vedd észre, hogy a legtöbb utasításban használhatsz memóriaoperandust anélkül, hogy előbb betöltenéd a tartalmát egy regiszterbe.
Általában azonban nem lehet egyszerre a forrás- és a céloperandusban használni őket, csak az egyikben a kettő közül:

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### Az LEA utasítás

Bár egy `mov` is használható arra, hogy egy változó címét regiszterbe tegyük, van egy utasítás kifejezetten erre a célra: **[lea][lea]**.

Ez az utasítás memóriaalakú operandust használ, de _nem_ olvassa a memóriát.
Ehelyett kiszámítja az effektív cím kifejezését, és az eredményt a céloperandusba írja:

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

Idiomatikusabb a `lea` utasítást használni a memóriacímek kiszámítására és regiszterbe töltésére.

### Relatív címzés

Amikor memóriahelyeket érünk el, a NASM alapértelmezett viselkedése, hogy **abszolút címeket**, azaz rögzített memóriacímeket állít elő.

Biztonsági okokból a futtatható fájlokat gyakran **PIE (Position Independent Executable)** formában építik fel, ahol a memóriarészek véletlenszerű helyekre kerülnek.
Egy `PIE` esetében egy változó végleges címe a linkelés idején nem ismert.
Ezért a kód a címeket inkább egy `rip` nevű speciális regiszter értékéhez viszonyított eltolásként számítja ki, amely a következő végrehajtandó utasításra mutat.

Ezt általában **RIP-relatív címzésnek** nevezik.

A NASM-ben a **[rel operátorral][rel]** kérhetsz RIP-relatív elérést:

```x86asm
mov rax, qword [rel variable]
```

A relatív címzést egy forrásfájl alapértelmezésévé is teheted úgy, hogy a fájl elejére a `default rel` utasítást írod.

Ebben a kurzusban minden feladatot `PIE` formában fordítunk és linkelünk, ezért a relatív címek előállításához a `rel` utasítást kell használni.

A fent említett véletlenszerű elrendezés egy védekező technika, amelynek neve address space layout randomization.
Azzal, hogy az egyes memóriarégiók bázisát kiszámíthatatlanná teszi, megvonja a támadótól azokat a rögzített címeket, amelyekre sok kihasználási technika támaszkodik, a `PIE` pedig épp azt teszi lehetővé, hogy a betöltő ezeket a régiókat bárhová elhelyezze.

Emiatt ebben a kurzusban az abszolút címzés nem csupán nem ajánlott, hanem egyenesen használhatatlan.
Egy abszolút hivatkozás, például a `[abs variable]`, arra kéri az assemblert, hogy egy rögzített 32 bites címet ágyazzon be az utasításba.
Linuxon a `PIE` linkelő elutasítja az így keletkező relokációt, macOS-en pedig a `macho64` formátum egyáltalán nem támogatja a 32 bites abszolút címeket, így a fájlt nem sikerül lefordítani.

A RIP-relatív címzés mindkét problémát elkerüli, mivel az utasítás csak a `rip`-hez viszonyított eltolást kódol, soha nem rögzített címet.
`PIE` esetén ezért a cím regiszterbe töltésének idiomatikus módja a `lea` egy `rel` operandussal:

```x86asm
default rel

section .data
    variable dq 7

section .text
fn:
    lea rax, [rel variable]       ; materialize the address (PIE-safe)
    mov rcx, qword [rel variable] ; load the value through a RIP-relative access
    ...
```

### Láthatóság

Bármelyik szakaszban (például `.text`, `.data`, `.rodata`) definiált címke (függvények és adatok) látható ugyanazon forrásfájlon belül.
Ha `global`-ként deklaráljuk őket, más forrásfájlokból is láthatók.

Fordítva, a más forrásfájlokban definiált címkék akkor láthatók az aktuális forrásfájlból, ha `extern`-ként vannak deklarálva.
Ebben az esetben az assemblyben nincs semmilyen jelölés az adat méretére, ezért annak előre ismertnek kell lennie.

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
