# Bevezetés

A Go, akárcsak sok más nyelv, rendelkezik pointerekkel.
Ha most ismerkedsz velük, elsőre kicsit rejtélyesnek tűnhetnek, de ha egyszer megszoktad őket, egészen egyszerűek.
A Go kulcsfontosságú részét képezik, szóval szánj rájuk időt, hogy igazán megértsd őket.

Mielőtt belemennénk a részletekbe, érdemes megérteni, mire is használjuk a pointereket.
A pointerek segítségével memóriát oszthatunk meg a programunk más részeivel, aminek két fő ok miatt is hasznát vesszük:

1. Ha nagy mennyiségű adatunk van, a függvények közötti másolgatás nagyon nem hatékony.
   Ha ehelyett annak a memóriacímét adjuk át, ahol az adat tárolódik, drasztikusan csökkenthetjük a programjaink erőforrásigényét.
2. Ha pointereket adunk át a függvények között, közvetlenül férhetünk hozzá az adat egyetlen példányához, és módosíthatjuk is azt, ami azt jelenti, hogy az egyik függvény által végzett változtatások a függvény befejeződése után azonnal láthatók a program többi része számára.

## Változók és memória

Tegyük fel, hogy van egy közönséges egész típusú változónk, `a`:

```go
var a int
```

Amikor deklarálunk egy változót, a Go-nak helyet kell keresnie a memóriában, ahol eltárolhatja az értékét.
Ez nagyrészt el van rejtve előlünk: amikor ki kell olvasnunk az adott memóriadarabban tárolt értéket, egyszerűen a változó nevével hivatkozhatunk rá.

Amikor például `a + 2`-t írunk, valójában az `a` változóhoz tartozó memóriában tárolt értéket olvassuk ki, és adunk hozzá 2-t.

Hasonlóképpen, ha az `a` memóriadarabjában lévő értéket akarjuk megváltoztatni, a változó nevével értéket adhatunk neki:

```go
a = 3
```

Az `a`-hoz tartozó memóriadarab mostantól a `3` értéket tárolja.

## Pointerek

A változók segítségével a memóriában lévő értékekre hivatkozhatunk, de néha hasznos tudni azt is, hogy melyik **memóriacímre** mutat a változó.
A **pointerek** épp ezeket a memóriacímeket tárolják.
Egy pointer típusú változót úgy deklarálsz, hogy az alapul szolgáló típus elé csillagot teszel:

```go
var p *int // 'p' contains the memory address of an integer
```

Itt egy `p` változót deklarálunk, amelynek a típusa „intre mutató pointer” (`*int`).
Ez azt jelenti, hogy `p` egy egész szám memóriacímét fogja tárolni.
A pointerek nullaértéke a `nil`, mert egy `nil` pointer nem tárol memóriacímet.

### Pointer létrehozása egy változóhoz

Egy változó értékének memóriacímét a `&` operátorral kereshetjük meg.
Ha például meg akarjuk keresni az `a` változó memóriacímét, és el akarjuk tárolni a `p` pointerben, ezt így tehetjük:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### Az érték elérése pointeren keresztül (dereferálás)

Ha van egy pointerünk, néha szeretnénk tudni, milyen érték tárolódik azon a memóriacímen, amit a pointer képvisel.
Erre a `*` operátort használhatjuk:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

A `*p` művelet kiolvassa a `p`-ben tárolt memóriacímen lévő értéket.
Ezt a műveletet gyakran „dereferálásnak” nevezik.

A dereferáló operátorral új értéket is adhatunk a pointer által hivatkozott memóriacímnek:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

Ha a `*pa`-nak adunk értéket, az megváltoztatja a `pa` által tárolt memóriacímen lévő értéket.
Mivel `pa` az `a` memóriacímét tárolja, a `*pa`-nak adott értékkel valójában az `a` értékét változtatjuk meg!

Egy figyelmeztetés azonban: dereferálás előtt mindig ellenőrizd, hogy a pointer nem `nil`.
Ha egy `nil` pointert dereferálsz, a program futásidőben összeomlik!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### Pointerek struktúrákra

Eddig csak primitív értékekre mutató pointerekkel találkoztunk.
Struktúrákhoz is készíthetünk pointereket:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

Úgy is eljárhattunk volna, hogy létrehozunk egy új `Person` értéket, és rögtön eltároljuk rá a pointert:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

Ha egy struktúrára mutató pointerünk van, nem kell dereferálnunk a pointert ahhoz, hogy hozzáférjünk az egyik mezőjéhez:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## A szeletek és a map-ek már eleve pointerek

A szeletek és a map-ek különleges típusok, mert a megvalósításukban már eleve pointerek vannak.
Ez azt jelenti, hogy ezeknél a típusoknál a legtöbbször nem kell pointert létrehoznunk ahhoz, hogy megosszuk az értékeik memóriacímét.
Képzeljük el, hogy van egy függvényünk, amely megnöveli egy map egyik kulcsához tartozó értéket:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

Ha létrehozunk egy map-et, és meghívjuk ezt a függvényt, a függvény map-en végzett módosításai a függvény befejeződése után is megmaradnak.
Ez hasonló ahhoz, mintha pointert használtunk volna, de figyeld meg, hogy ebben a példában semmilyen referálást/dereferálást vagy más pointeres szintaxist nem használunk:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

Ugyanez érvényes, amikor egy szeletben lévő meglévő elemet módosítunk.

Az olyan műveletek azonban, amelyek új szeletet adnak vissza, például az `append`, különleges esetet jelentenek, és előfordulhat, hogy **nem** módosítják a szeletet a függvényen kívül.
Ez a szeletek belső működése miatt van így, de ezt nem részletezzük, mert ez már haladóbb téma.
Ha igazán kíváncsi vagy, erről többet olvashatsz a [Go Blog: Mechanics of 'append'][mechanics-of-append] bejegyzésben.
