# Bevezetés

## Részleges alkalmazás

Az Elmben minden függvény [curryzett][currying], ami azt jelenti, hogy ha úgy hívsz meg egy függvényt, hogy nem adod át az összes argumentumot, akkor egy új függvényt ad vissza.

Ennek az eredményét [részleges alkalmazásnak][partial-application] nevezzük (nem az összes argumentumot adod át a függvénynek, hanem csak néhányat alkalmazol részlegesen).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

A részleges alkalmazás mindig sorrendben alkalmazza az argumentumokat.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## Pipe operátor (`|>`)

Az `x |> f` pontosan ugyanazt jelenti, mint az `f x`. Konkrét példa: a `"5" |> String.toInt` ugyanaz, mint a `String.toInt "5"`.

Ez elsőre nem tűnik túl hasznosnak, de azért hívják [pipe operátornak][pipe-operator], mert lehetővé teszi „csővezetékbe fűzött” kód írását.

Tegyük fel például, hogy van egy sanitize függvényünk, amely a felhasználói bemenetet egész számokká alakítja:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Átírhatjuk így:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Ez elkerüli a zárójelek használatát, és abban a sorrendben mutatja a függvényeket, ahogy alkalmazásra kerülnek (először a `String.trim`, aztán a `String.toInt`), ami segíti az olvashatóságot.

Létezik egy [fordított pipe operátor `(<|)`][reverse-pipe-operator] is.
Az `f <| x` pontosan ugyanazt jelenti, mint az `f x`.
Ez első pillantásra szintén nem tűnik túl hasznosnak, és határozottan nem használják annyit, mint a pipe operátort, de bizonyos helyzetekben segít elkerülni a zárójeleket.

## Függvénykompozíció / point-free stílus

A [`(>>)`][forward-composition] operátor típusa `(a -> b) -> (b -> c) -> (a -> c)`, és két kompatibilis, `a -> b `és `b -> c` típusú függvény összefűzésével egy `a -> c` típusú függvényt hoz létre.
Ehhez az első függvény kimenetét (amely `b` típusú) veszi, és a második függvény első argumentumaként használja (amelynek szintén `b` típusúnak kell lennie).
A létrejött függvény ugyanazt a bemenetet veszi, mint az első függvény (amely `a` típusú), és azt a `c`-t adja vissza, amit a második függvény visszaad.

Konkrét példa a `String.trim >> String.toInt`.
A `String.trim` egyetlen paraméterként egy stringet vár, tehát a létrejött függvény is ezt veszi.
A `String.toInt` egy `Maybe Int`-et ad vissza, tehát a létrejött függvény is ezt adja vissza.
A `String.trim` egy `String`-et ad vissza, amit a `String.toInt` paraméterként elfogad, így a példa lefordul.

Most átírhatjuk a `sanitize` függvényünket a következőképpen:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Figyeld meg, hogy már nem használjuk az `input` paramétert, amely az eredeti példában látható, pedig a működés ugyanaz.
Az ilyen módon létrehozott, paramétereikre nem hivatkozó függvényeket „point-free stílusnak” nevezzük.
Ennek a stílusnak az előnye, hogy a kód tömörebb, a hátránya pedig az, hogy nehezebb megérteni, különösen kezdőknek.

Érdemes megjegyezni, hogy az Elmben minden függvény curryzett, így a `String.length >> max` lefordul.

- A [`(>>)`][forward-composition] operátor típusa `(a -> b) -> (b -> c) -> (a -> c)`.
- A `String.length` típusa `String -> Int`, ez az `(a -> b)` rész, tehát `a` a `String`, `b` pedig az `Int`.
- A `max` típusa `Int -> Int -> Int`, ez a `b -> c` rész.
- A `b` az `Int`, ezért a `max` részlegesen alkalmazott, így a `c` ennek a részleges alkalmazásnak az eredménye (`Int -> Int`).
- Tehát a `String.length >> max` típusa `String -> (Int -> Int)`.
- Így a `((String.length >> max) "123") 2` eredménye `3`, mert a `"123"` hossza 3, ami nagyobb, mint a 2 az `Int` argumentumból.

## Függvénytervezés

Ahhoz, hogy könnyen lehessen elegáns kódot írni Elmben, a fő adatszerkezetet a függvények utolsó paraméterévé kell tenned.
A standard könyvtár összes gyakori függvénye így tesz, például a `List.map` is (a típusa lent látható).

```elm
map : (a -> b) -> List a -> List b
```

Itt láthatjuk, hogy a `map` függvény utolsó paramétere `List a`, és `List b`-t ad vissza, tehát a fő adatszerkezet (`List`) az utolsó paraméter.

Ez teszi lehetővé, hogy elegáns, csővezetékbe fűzött kódot írjunk, mint például az alábbi.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Kényelmessé teszi a függvénykompozíció és a point-free stílus használatát is, a csővezetékbe fűzés alternatívájaként.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

A függvénykompozícióval ezt a példát egyetlen `List.map` hívásra is leegyszerűsítheted.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
