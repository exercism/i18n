# Névjegy

A parse-olás során szöveget alakítunk át jelentéssel bíró adatokká.
A `String` csomag függvényei ebből a szempontból korlátozottak, a reguláris kifejezéseket pedig nehéz használni, ezért az Elmben a szokásos módja a parse-olásnak az `elm/parser` csomag használata.

Nézzünk egy példát arra, hogyan írjunk parsert a [LOLCODE][lolcode] programozási nyelv (egy részhalmazának) feldolgozására.
Vegyük a következő megjegyzésekkel ellátott programot:

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

Először írjunk egy Elm-típust, amely a lehetséges parancsokat reprezentálja:

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

A LOLCODE programunk ekkor `List Command`-ként modellezhető.
Kezdjük a `HAI 1` sor parserével:

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

A `versionP` egy _parser-folyamat_ felhasználásával épül fel.
A `(|.)` operátor jelentése: „parse-old a szöveget, de dobd el az eredményt”, a `(|=)` pedig: „parse-old a szöveget, és tartsd meg az eredményt”.
Ebben a példában a `Parser.keyword "HAI"` elfogyaszt egy „HAI”-t, de az eredményt figyelmen kívül hagyja.
A `Parser.spaces` tetszőleges számú ' ', '\n' és '\r' karaktert fogyaszt, de ez is figyelmen kívül marad.
A `Parser.int` egy egész számot parse-ol, és annak az értéke (mondjuk 1) átadódik a legfelső `Parser.succeed Version` számára, így a parser sikeresen visszaadja a `Version 1` értéket.

Ha a folyamatban bármelyik parser elbukik, az egy `Parser.DeadEnd`-et ad vissza, és az egész parser elbukik.
Egy parsert a `Parser.run` segítségével futtathatunk:

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

Nézzük meg a „CAN HAS STDIO?” sort ezzel:

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

Az `importP` szintén egy parser-folyamat, de ezúttal egy `Parser.symbol`-lal végződik, amely az olyan szimbólumok parse-olására alkalmas, mint a „?”.
A megtartani kívánt értéket (az importálandó csomag nevét) ez parse-olja:

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

Mivel nem tudjuk, mi lesz a csomag neve, nem használhatjuk a `Parser.keyword`-öt, helyette a `Parser.chompWhile`-t használjuk, amely addig fogyaszt egyes karaktereket, amíg azok megfelelnek egy feltételnek (itt annak, hogy alfanumerikus karakterek).
Ezeket a lefogyasztott karaktereket aztán a `Parser.getChompedString` gyűjti össze, amely egy `Parser String`-et ad vissza.
Ebben az esetben normalizálni szeretnénk a csomagneveket, ezért a `Parser.map`-et használjuk, hogy módosítsuk a parserben lévő stringet, és csupa kisbetűssé tegyük.

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

Most a `VISIBLE "HAI WORLD!"` következik, amelyet ez parse-ol:

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

Most már minden parancshoz van parserünk.
Persze egy általános programban a parancsok sorrendje nem jelezhető előre, ezért készítünk egy általános parsert a parancsokhoz

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

A `Parser.oneOf` a megadott sorrendben egyszerre egy parsert próbál ki.
Ha egy parser elbukik, a következőt próbálja ki, ha viszont sikerül, az eredményét adja vissza anélkül, hogy kipróbálná a többit.
Ha minden parser elbukik, a `Parser.oneOf` is elbukik.

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

Figyeld meg, hogy minden sikertelen kísérlet egy `Parser.DeadEnd`-et hoz létre, amelyet a `Parser.oneOf` összegyűjt.

Egy teljes program parse-olásához több parancsot kell egymás után parse-olnunk ezzel:

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

A `Parser.sequence` egy nagyon testreszabható parser számos beállítással.
A `start`, `separator` és `end` olyan stringeket vesznek, amelyek elválasztják a sorozat elemeit; egy Elm-lista parse-olásához a „[”, „,” és „]” jeleket használnánk.
A `spaces` rugalmasságot ad azzal, hogy egy parsert vár, amely kezeli az elemek és elválasztók közötti lehetséges szóközöket; egy Elm-lista parse-olásához a `Parser.spaces`-t használnánk, de ebben az esetben nem fogadunk el szóközöket, ezért a `Parser.succeed ()`-t használjuk, amely azonnal sikerül, anélkül hogy bármit is fogyasztana.
Az `item` az elem parserét várja, végül a `trailing` segítségével eldönthetjük, hogy a záró elválasztók `Parser.Forbidden`, `Parser.Mandatory` vagy `Parser.Optional` típusúak legyenek.

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

Amikor a parserek sikeresen lefutnak, abbahagyják a string fogyasztását

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

Tehát ha biztosak akarunk lenni abban, hogy a stringben mindent parse-oltunk, használhatjuk a `Parser.end`-et

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

Végül néha a parser tartalmától függően kell döntenünk arról, hogy megbuktatunk-e egy parsert.
Például ha olyan parserre lenne szükségünk, amely megbuktatja azokat a programokat, amelyek két egymást követő „HAI” paranccsal kezdődnek, ezt használhatnánk:

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

A `Parser.andThen` megvizsgálhatja egy parser tartalmát, és az értékétől függően egy új parsert ad vissza.
Itt az egyik esetben a `Parser.problem` segítségével egyéni üzenettel buktattuk meg a parsert, a másikban pedig az eredeti értéket adtuk vissza.

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
