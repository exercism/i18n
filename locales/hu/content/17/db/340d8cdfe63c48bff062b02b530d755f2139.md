# Névjegy

A Common Lisp több különböző elágazást kínál a programozónak, amelyek aszerint kategorizálhatók, hogy hány „ágat” támogatnak.

Ráadásul, sok más programozási nyelvtől eltérően, a Common Lispben minden elágazás _kifejezés_, nem utasítás. Ez azt jelenti, hogy minden Lisp-elágazás kiértékelődik valamilyen értékre, és behelyettesíthető konkrét paraméterek helyére.

Például:

```lisp
;; Doubles x when it's even
(* x (if (evenp x) 2 1))
```

## Egyágú elágazások

A `when` és `unless` elágazások csak akkor értékelnek ki kódot, ha a megadott feltétel igaz, illetve hamis, egyébként `nil`-re értékelődnek.

A feltételkifejezés utáni rész több kifejezésből is állhat.

```lisp
(when (= 2 2) "All is well")      ; => "All is well"
(unless (= 2 2) "Time to panic!") ; => NIL
```

## A kétágú elágazás

Az `if` elágazás a törzs első kifejezését értékeli ki, ha a feltétel igaz, egyébként pedig a másodikat.

```lisp
(if (= 2 2) 'how-honest 'you-liar) ; => HOW-HONEST
```

Vedd észre, hogy mind a „then”, mind az „else” ág csak egyetlen kifejezés lehet.

## Többágú elágazások

A Lisp „szuper-elágazása” a `cond`, amelynek végtelen sok ága lehet. Minden ág egy feltételt és egy törzskifejezést tartalmaz, amelyeket egy plusz zárójelpár vesz körül. Ha minden feltétel hamisra értékelődik, akkor `nil`-t ad vissza.

```lisp
(cond ((= 0 2) 'nope)
      ((= 1 2) 'try-again)
      ((= 2 2) 'quite-true)
      ((= 3 2) 'too-far)
      (t 'something-else))
; => QUITE-TRUE
```

Vedd észre, hogy a feltételkifejezés utáni kifejezések számának nincs felső határa.

Ha csak egy értéket szeretnél több ággal összevetni, használhatod a letisztultabb `case` kifejezést. Ha egyik eset sem illeszkedik, `nil`-t ad vissza. A `t` és az `otherwise` is használható gyűjtőesetként:

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark")
  (otherwise "???"))
; => "???"
```

Vedd észre, hogy a `cond`-hoz hasonlóan itt sincs felső határa a feltételkifejezés utáni kifejezések számának.

## A lopakodó elágazások

A Common Lispben a `and` és `or` Boolean-műveletei rövidzárlati makrók, amelyekkel bizonyos feltételes kifejezések duplikációja csökkenthető.

Az `and` makró azonnal `nil`-t ad vissza, ha egyetlen hamis értékkel találkozik, egyébként pedig az `and` utolsó igaz értékét adja vissza:

```lisp
(and 42 "Magic" :cool) ; => :COOL
(and () "Magic" :cool) ; => NIL
```

Az `or` makró az első igaz értéket adja vissza, amellyel találkozik, vagy `nil`-t, ha nem volt igaz érték:

```lisp
(or () 42 nil)  ; => 42
(or () NIL nil) ; => NIL
```

## Kimerültem...

Ahogy korábban említettük, amikor a `case` utasítás egyetlen ága sem illeszkedik, és nincs `otherwise` ág, `nil`-t ad vissza. Néha azonban előfordul, hogy az illeszkedés hiányát hibaként kell kezelni, ekkor jön képbe az `ecase` (a **kimerítő** illesztéshez).

Pontosan ugyanúgy használjuk, mint a `case`-et, de amikor nincs illeszkedés, hibát jelez ahelyett, hogy `nil`-t adna vissza.

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => NIL

(ecase 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => ERROR: ELDER-BEAST fell through ECASE expression. Wanted one of (CAT BIRD DOG).
```
