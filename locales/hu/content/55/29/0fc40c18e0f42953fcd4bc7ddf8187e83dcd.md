# Részletesen

## Reprezentáció, karakterek és egész számok

A többi egyszerű típushoz (`int`-ek, `bool`-ok stb.) hasonlóan a `char`-nak is van társtípusa vagy aliastípusa, jelen esetben a `System.Char`.

Ez valójában egy `struct`, amely egy 16 bites mezőt tartalmaz, és alapértelmezés szerint nem módosítható.

A `char`-nak vannak példánymetódusai, például az `Equals`, a `ToString` és a [`CompareTo`][compare-to].

A `char` ugyanolyan széles, mint a [`ushort`][uint16], de a kettőt általában nem használják felcserélhetően, ahogy néhány nyelvben szokás. A `ushort`-ot explicit módon kell `char`-rá alakítani.

Mellesleg a `char`-okon aritmetikai műveleteket is el lehet végezni. Ezeknek a műveleteknek az eredménye egész szám.

Természetesen nincs megfelelés a 8 bites `byte` és a 16 bites `char` között.

## Használat

A `char`-okat általában könnyű használni.

Egyszeres idézőjelekkel literálként definiálhatók:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

Egy adott `char`-t elő is hívhatsz egy stringből (nullától induló) indexeléssel:

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

Ha végigiterálsz egy stringen, minden lépésben egy `char`-t kapsz:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

Ahogy fentebb látható, egy `char` átalakítható az `int` értékévé.
Ez (*legalábbis néha*) más írásrendszereknél is működik:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

A karakterek összehasonlításakor a mögöttes Int16-ot használja:

```fsharp
'A' < 'D'
// => val it: bool = true
```

Ezenkívül egy `int` is átalakítható `char`-rá:

```fsharp
char 77
// => val it: char = 'M'
```

A `System.Char` könyvtár tartalmazza a .NET-nyelvektől elvárt [metódusok][Char-methods] teljes készletét, például a kis- és nagybetűre alakítást (de lásd a következő szakasz fenntartásait):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

A .NET-könyvtárak segítenek a `char`-ok stringből való kinyerésében, ebben az esetben a `Seq` metódusok:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

Többféleképpen is átalakítható egy karakterlista (vagy tömb) stringgé, például így:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

A `char`-okról általános információkat itt találsz:

- [A `char` dokumentációja][chars-docs]: a `char` referenciadokumentációja.

A `char`-oknak azonban számos döccenője van, ahogy azt alább részletezzük. Ezek a döccenők leginkább a teljes Unicode-szabvány, valamint a szöveg történelmi ábrázolása, illetve a teljesítmény és a memóriahasználat közötti ellentétből fakadnak.

## Unicode-problémák

Amikor stringekkel dolgozol, ha rendelkezésre állnak a [`System.String`][System-string] könyvtár metódusai, keresd meg és használd azokat ahelyett, hogy karakterekre bontanád a stringet.

Egyes szöveges „karakterek” egynél több `char`-ból állnak, mert a Unicode-szabványban több mint 65536 kódpont van. Például a néhány tesztben felbukkanó emojik 2 `char`-ból állnak, mert [helyettesítő][surrogates] karakterekből tevődnek össze.

Ezenkívül léteznek kombináló sorozatok is, amikor például egy ékezetes karakter állhat az alapkaraktert jelölő egyik `char`-ból és az ékezetet jelölő másik `char`-ból.

Ha egyenként kell foglalkoznod a karakterekkel, próbálj könyvtári metódusokat használni, például a [`System.Char.IsControl`][is-control] vagy a [`System.Char.IsDigit`][is-digit] metódust, ahelyett hogy naiv összehasonlításokat végeznél, például azt ellenőriznéd, hogy egy karakter a '0' és a '9' közé esik-e.

Figyeld meg például, hogy a '٢' az arab 2-es számjegy. Az `IsDigit` igazat ad vissza az arab változatra, ezért amikor érvényesítesz, tisztázd, hogy mely bemeneti tartomány elfogadható.

Még a `System.Char` könyvtár metódusai sem viselkednek feltétlenül úgy, ahogy várnád, amikor ritkább nyelvekkel van dolgod.

A string biztonságos felbontására megjelenítendő „karakterekre” az egyik mód a [`StringInfo`][string-info] és az olyan metódusok használata, mint a [`GetNexttextElement`][get-next-text-element].
Erre szükség lehet, ha globalizációval/lokalizációval foglalkozol.

Egy másik lehetőség, amikor a Unicode-karakterek skalárértékei fontosak (mondjuk saját kódolási rendszert építesz), a [rune-ok][runes] használata. Ha azonban tudod, hogy a kezelt karakterek köre nem tartalmaz helyettesítőket vagy kombináló karaktersorozatokat (pl. latin ASCII), és a bemeneted jól érvényesített, akkor elkerülheted ezt.

A legjobb helyzet természetesen az, ha a `String` könyvtári metódusait használhatod.

Ha mégis abba a kellemetlen helyzetbe kerülsz, hogy a Unicode apró részleteivel kell bajlódnod, akkor [ez][char-encoding-net] jó kiindulópont.

## Globalizáció

Ha olyan környezetben dolgozol, ahol több kultúrával van dolgod, vagy a kultúra a kód egyes részein fontos, másokon nem, akkor légy tisztában a [`ToUpper`][to-upper] és a [`ToLower`][to-lower] azon túlterheléseivel, amelyek kultúrát fogadnak, valamint a [`ToUpperInvariant`][to-upper-invariant] és a [`ToLowerInvariant`][to-lower-invariant] metódusokkal, amelyek az aktuális [kultúrától][culture-info] függetlenül egységes eredményt adnak.
