# Bevezetés

## RFLAGs

Van egy speciális regiszter, amelyet `rflags`-nek hívnak.
A bitjei különféle feltételek flagjeként működnek.

Ezek közül néhányat az alábbi táblázat sorol fel:

| név         | szimbólum | bit |
| :---------- | :-------: | :-: |
| átvitel     |    CF     |  0  |
| nulla       |    ZF     |  6  |
| előjel      |    SF     |  7  |
| túlcsordulás|    OF     | 11  |

## Összehasonlító utasítások

Az `rflags` flagjeit _nem_ közvetlenül módosítjuk.
Ehelyett sok különböző utasítás állítja be őket.

Például a `ZF`-et sok aritmetikai vagy bitenkénti művelet beállítja, amikor az eredmény nulla.

A feltételek vizsgálatára használt egyik leggyakoribb utasítás a `cmp`.
Két operandust vesz át, és frissíti a flageket, de **nem módosítja az operandusait**.

### A `cmp` utasítás

A `cmp` utasítás kivonja a második operandust az elsőből, és az eredmény alapján állítja be a flageket.

Ha A az első operandus, B pedig a második:

| flag | beáll, ha                          |
| :--: | :--------------------------------- |
|  CF  | A < B (előjel nélküli)             |
|  ZF  | A == B                             |
|  SF  | A < B (előjeles, túlcsordulás nélkül) |
|  OF  | túlcsordulás előjeles kivonáskor   |

## Elágaztatás

Alapértelmezés szerint az x86-64-es kód fentről lefelé sorban hajtódik végre.

De sok helyzetben szükség van ennek a viselkedésnek a megváltoztatására.
Például hogy egy feltétel hatására más utasításokat hajtsunk végre.

A magasabb szintű nyelvekben ezt általában absztrakciókkal, például `if...else` elágazásokkal oldják meg.
Az x86-64-ben viszont ilyenek nincsenek.

Ehelyett az x86-64 olyan utasításokat kínál, amelyek a végrehajtást gyakorlatilag a kód egy másik helyére viszik át.
Ezt nevezik `branching`-nek.

~~~~exercism/note
Már láttunk két ilyen utasítást: a `call` és a `ret`.

Amikor meghívunk egy függvényt, a végrehajtás a hívótól a meghívott függvényhez kerül.
Visszatéréskor pedig a végrehajtás visszakerül a hívóhoz.

Ha nincs `ret`, a végrehajtás átcsúszik az egyik függvényből a másikba.
Ezt néha a kódfolyam optimalizálására lehet használni.
~~~~

### Feltétel nélküli ugrás

A **jmp** utasítás feltétel nélkül a kód egy másik pontjára viszi át a program végrehajtását.
Egyetlen operandusa egy címke, amely annak a pontnak a címét tartalmazza, ahol a végrehajtás folytatódik.

Nézzük például a következő függvényt:

```x86asm
fn:
    mov rax, 5
    jmp end

    add rax, 10
end:
    ret
```

Amikor meghívjuk az `fn`-t, a végrehajtás a `mov rax, 5`-nél kezdődik.
Ekkor a `rax` értéke 5 lesz.

A következő utasítás a `jmp end`, amely a végrehajtást az `end` címkére viszi át.

Az `end` után a következő utasítás a `ret`, amely visszaviszi a végrehajtást a hívó függvényhez.

Figyeld meg, hogy mivel az `add rax, 10` a `jmp end` után és az `end` előtt van, soha nem hajtódik végre.
Amikor az `fn` visszatér, a `rax` értéke 5.

### Feltételes ugrás

A **jcc** utasítások családja csak akkor viszi át a program végrehajtását egy másik pontra, ha egy adott feltétel teljesül.
Ellenkező esetben a végrehajtás sorban folytatódik.

Minden feltétel az `rflags` egy vagy több flagjéhez kapcsolódik.
A `jcc` egyes változatai azt vizsgálják, hogy egy flag be van állítva, mások azt, hogy nincs.

A `jcc`-ben a `cc` nem szó szerint értendő, hanem a vizsgált flaghez tartozó konkrét utótagot jelöli.

Sok utótag létezik, és közülük több ugyanazt a feltételt vizsgálja, mint egy másik.
Néhányuk közvetlenül egy flagre utal, így az utasítás egy címkére ugrik, ha az adott flag be van állítva:

| utótag | ugrik, ha |
| :----: | :-------: |
|   z    | ZF == 1   |
|   c    | CF == 1   |
|   s    | SF == 1   |
|   o    | OF == 1   |

Sok másikat pedig azért választottak, hogy a `cmp` utasításban betöltött jelentésükre utaljanak.
Például:

| utasítás | utótag | ugrik, ha        |
| -------- | :----: | :--------------- |
| cmp A, B |   e    | A == B           |
| cmp A, B |   l    | A < B (előjeles) |
| cmp A, B |   b    | A < B (előjel nélküli) |
| cmp A, B |   g    | A > B (előjeles) |
| cmp A, B |   a    | A > B (előjel nélküli) |

Az `l`, `b`, `g` vagy `a` után `e`-t írva az egyenlőséget is belefoglalhatod a feltételbe:

```x86asm
cmp rcx, r8
jge two      ; this jumps to 'two' if rcx is greater than, or equal to, r8 in a signed comparison
jbe two      ; this jumps to 'two' if rcx is lesser than, or equal to, r8 in an unsigned comparison
```

Minden utótaghoz léteznek olyan változatok, amelyek az ellenkező esetet vizsgálják.
Ugyanaz a szintaxisuk, csak az utótag előtt egy `n` áll.

Például a `jnz` akkor ugrik, amikor a `ZF` **nincs** beállítva.
Hasonlóképpen a `jnae` akkor ugrik, amikor A **nem** >= B (A-t és B-t előjel nélküli egészként értelmezve).

~~~~exercism/note
Egyes utótagok ugyanazoknak a feltételeknek az álnevei.
Például a `jz` (utótag: `z`, a `ZF`-re) és a `je` (utótag: `e`, az egyenlőségre) is akkor ugrik, amikor a `ZF` be van állítva.
Ez azért van, mert a `cmp` esetében a `ZF` akkor áll be, amikor a kivonás eredménye nulla, ami azt jelenti, hogy a két operandus egyenlő.

Más utótagok viszont flagek kombinációját vizsgálják, és nem helyettesíthetők közvetlenül egyetlen flagre utaló utótaggal.

Válaszd azt az utótagot, amely jobban leírja az összehasonlításod szemantikáját.
~~~~

## Helyi címkék

A címkék az egész forrásfájlban láthatók, nem korlátozódnak egy függvényre.
Ezért egy címkenevet nem lehet újra felhasználni.

Hogy utánozza egy helyi címke viselkedését, a NASM külön jelölést vezetett be az olyan címkékre, amelyek elé pontot (`.`) írnak.
Ez a jelölés olyan címkét definiál, amely implicit módon magában foglalja az előző, pont nélküli címke nevét:

```x86asm
section .text
fn1:
    ...
.example: ; this is fn1.example
    ...
    ret

fn2:
    ...
.example: ; this is fn2.example
    ...
    ret
```

A kód bármely pontjáról továbbra is lehet erre a címkére ugrani a teljes címenév használatával, például így: `jmp fn1.example`.

Ha viszont az ugrás a címkének a ponttól kezdődő részét használja, az a felső függvényen _belüli_ címkére irányul.
Például a `.example` úgy viselkedik, mintha a függvényen belül lenne helyi:

```x86asm
section .text
fn1:
    ...
.example:
    ...
    jmp .example ; this jumps to fn1.example

fn2:
    ...
.example:
    ...
    jmp .example ; this jumps to fn2.example
```
