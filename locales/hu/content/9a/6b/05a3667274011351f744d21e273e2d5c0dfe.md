# Bevezetés

A bináris számjegyek végső soron közvetlenül leképeződnek a CPU-d vagy a RAM-od tranzisztoraira, és arra, hogy mindegyik »be« vagy »ki« állapotban van-e.

A mély szintű manipuláció, amit köznapi nevén „bit-twiddling”-nek hívnak, különösen fontos a rendszerprogramozási nyelvekben.

A magasabb szintű nyelvek, például a Kotlin, általában elfedik ezeknek a részleteknek a nagy részét. Egy alapvető bitszintű műveletkészlet [azonban elérhető][ref-bitwise].

## Biteltolási műveletek

Az `Int` és `Long` típusok, előjelesen vagy előjel nélkül, ábrázolhatók 1-esek és 0-sok stringjeként, és bitenkénti sorozatként manipulálhatók.

Talán meglepő, de a `Byte` és `Short` típusok a Kotlinban nem kompatibilisek a legtöbb bitenkénti művelettel. Az alábbi példák mind 32 bites egészeket (`Int` vagy `UInt`) használnak.

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

A biteltolások egyszerűen elmozgatnak mindent balra vagy jobbra egy megadott számú pozícióval. Néhány bit leesik az egyik végén, a másik végét pedig nullákkal vagy egyesekkel töltjük fel.

- Balra tolás a `shl` operátorral: nullákkal való feltöltés.
- Jobbra tolás a `shr` vagy `ushr` operátorral: pozitív számoknál nullákkal való feltöltés (a negatív számokról később lesz szó).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Minden balra tolás megduplázza az értéket, minden jobbra tolás pedig megfelezi (a csonkítástól függően). Ez tizedes ábrázolásban még nyilvánvalóbb:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Az ilyen biteltolás sokkal gyorsabb a »rendes« aritmetikánál, ami miatt ez a technika nagyon népszerű a mély szintű programozásban.

A _negatív egészeknél_ egy kicsit óvatosabbnak kell lennünk.

A negatív értékek [kettes komplemens][wiki-2complement] formájában tárolódnak, ami azt jelenti, hogy a legbaloldalibb bit 1. Balra tolásnál ez nem gond, de jobbra tolásnál hogyan töltjük fel a legbaloldalibb biteket?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

A `shr` operátor [aritmetikai eltolást][wiki-arithmetic] végez, megőrizve az előjelbitet.

Az `ushr` operátor [logikai eltolást][wiki-logical] végez, nullákkal töltve fel, mintha a szám előjel nélküli lenne.

## Bitenkénti logika

Láttuk a [Booleans fogalomnál][concept-booleans], hogy a `&&` (és), `||` (vagy) és `!` (nem) operátorokat logikai értékekkel használjuk.

Vannak ezzel egyenértékű operátorok, az `and`, `or` és `xor` ([kizáró vagy][wiki-xor]), amelyek két egész bitjeit hasonlítják össze, valamint egy `inv` (inverzió) függvény, amely az összes bitet megfordítja.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
