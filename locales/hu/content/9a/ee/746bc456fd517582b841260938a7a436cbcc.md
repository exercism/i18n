# Az aritmetikáról a Bash shellben

A Bash tud aritmetikát végezni, de _csak egész számokkal_.
Ha lebegőpontos számításra van szükséged, külső programot kell hívnod (például [awk][awk] vagy [bc][bc]).

Az aritmetikai operátorok (precedencia szerinti sorrendben) a kézikönyvben vannak felsorolva: [Shell Arithmetic][arithmetic].

Emellett a Bash csak bizonyos helyeken végez aritmetikát (ezeket aritmetikai „kontextusoknak” nevezzük).

## Aritmetikai kifejtés

Az aritmetikai kifejtés a [parancsbehelyettesítéshez][cmd-sub] hasonlít, csak dupla zárójelekkel.

```bash
$(( expression ))
```

Ez a szintaxis a kifejezés kiértékelésének eredményét állítja elő.
Gyakran használjuk arra, hogy az eredményt egy változóban rögzítsük:

```bash
x=$(( 3 + 4 ))
```

~~~~exercism/note
A zárójeleken belüli szóközök mennyisége rajtad múlik.
Ez a stílus és az olvashatóság kérdése.

```bash
x=$(( 3 + 4 ))
y=$((5+6))
```

A kedves szerző szívesen tesz be szóközöket, hogy az aritmetikai kifejezés jobban látható legyen a zárójeleken belül.
~~~~

## Aritmetikai feltétel

Az aritmetikai feltételt dupla zárójelek között hajtjuk végre, a kezdő `$` _nélkül_:

```bash
(( expression ))
```

Ez nem az eredményt állítja elő.
Ehelyett egy _kilépési állapotot_ állít elő.

* A kilépési állapot 0 (siker), ha a kifejezés eredménye **nem nulla**.
* A kilépési állapot 1 (hiba), ha a kifejezés eredménye **nulla**.

~~~~exercism/note
A `((` belsejében a Bash ugyanazt az igaz/hamis értelmezést használja, mint a C nyelv: a nulla hamis, a nem nulla igaz.
**Ez pont az ellenkezője annak, ahogy a Bash a kilépési állapotokat értékeli!**
~~~~

Ezt a szintaxist általában két helyen használjuk:

1. egy [`if` utasítás][conditional-if] vagy egy [`while` ciklus][looping-while] COMMAND részeként.

   ```bash
   if (( x == y - 1 )); then ...
   while (( y > 0 )); do ...
   ```

1. önálló parancsként egy változó értékének módosítására.

   ```bash
   (( x = x + 1 ))
   echo "new value for x is $x"
   ```

   ~~~~exercism/caution
   Légy óvatos, ha így használod az aritmetikát `set -e` mellett.
   Ha a kifejezés nullára értékelődik ki, a kilépési állapot nem nulla lesz, és a Bash leáll.

   ```bash
   x=0
   (( x++ ))
   echo "you will see this"

   set -e
   x=0
   (( x++ ))
   echo "shell exits on the previous line; you won't see this"
   ```

   A `++` operátorról szóló részletesebb fejtegetésért lásd ezt a cikket: [Postincrement vs Preincrement][incr]

   [incr]: https://thisvsthat.io/postincrement-vs-preincrement
   ~~~~


## További helyek aritmetikai kontextussal

Van még néhány más hely, ami aritmetikai kontextus:

* Az [aritmetikai for-ciklus][looping-for].

  ```bash
  for (( i = 0; i < 10; i++ )); do
      echo "$i"
  done
  ```

* Egy számokkal indexelt tömb indexrésze.

  ```bash
  echo "The next element is ${array[x + 1]}"
  # ................................^^^^^
  ```

  A tömbökről bővebben a [Tömbök][arrays] fogalomdokumentumban olvashatsz.

* A `${var:offset:length}` kifejtés eltolás és hossz részei.
* A [`let` beépített parancs][let].
  * Vedd figyelembe, hogy a `(( expression ))` előnyben részesítendő a `let "expresson"` helyett.
    Az aritmetikai feltétel szerkezettel ellentétben a `let` kifejezés ki van téve a fájlnév-kifejtésnek és a szófelbontásnak, és idézőjeleket igényel.
* Változóértékadás, amikor a változónak „egész attribútuma” van.

  ```bash
  # variable x does not have the integer attribute
  x="3 + 4"
  declare -p x      # => declare -- x="3 + 4"

  # variable y has the integer attribute
  declare -i y
  y="4 + 5"
  declare -p y      # => declare -i y="9"
  ```

  ~~~~exercism/note
  A szerző véleménye szerint a `declare -i` használata korlátozott.
  Legfőbb előnye, hogy lehetővé teszi a „csupasz” aritmetikát (az aritmetikai kifejezés szintaxisa nélkül).
  Ez zavart okozhat a kódod olvasóinak, mert az aritmetikai kifejezések váratlan helyeken értékelődnek ki.
  ~~~~

## Változók használata aritmetikai kifejezésekben

Íme az aritmetikai kontextusok egyik szempontja, amely javítja az olvashatóságot.

```bash
height=10
width=20
area=$(( height * width ))
```

Észrevetted, hogy a `$` dollárjelek hiányoznak a változók elől az aritmetikai kifejezésben?
A Bash megengedi ezt.
Ez sokkal könnyebben olvashatóvá teszi a kifejezéseket.

A kézikönyv ezt írja,

> Egy kifejezésen belül a shell-változókra név szerint is hivatkozhatsz anélkül, hogy a paraméter-kifejtés szintaxist használnád.

Még a tömb elemeknél is működik:

```bash
point1=(10 15)  # these are (x, y) coordinates
point2=(20 7)
distance_squared=$(( (point1[0] - point2[0])**2 + (point1[1] - point2[1])**2 ))
```

De más paraméterkifejezéseknek a saját speciális szintaxisukat kell használniuk.
Például egy string hosszának megkétszerezése:

```bash
s="hello world"
len=$(( ${#s} * 2 ))
```

Ugyanez vonatkozik a pozíciós paraméterekre is.
Ha az első két pozíciós paraméter a szélességet és a magasságot jelöli:

```bash
area=$(( $1 * $2 ))
```
