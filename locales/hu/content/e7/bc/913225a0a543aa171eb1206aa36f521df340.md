# Tesztgenerátorok

A tesztgenerátorok segítségével a kurzusok automatikusan tudnak teszteket generálni, anélkül hogy nekünk kellene megírni őket. Minden tesztgenerátor a feladat `canonical data` állományából olvas, amely meghatározza a teszt nevét, a bemeneteit és a kimeneteit. Az Exercism tesztcsomagokkal kapcsolatos megközelítéséről [itt](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md) olvashatsz többet.

A tesztek automatikus generálása kiküszöböli a felhasználói hibákat a tesztek létrehozásakor. Szeretnénk, ha a tesztek pontosan illeszkednének a hozzájuk tartozó canonical data-hoz. A tesztgenerálás ráadásul sokkal könnyebbé teszi a tesztek naprakészen tartását. Ahogy a canonical data változik, a tesztek automatikusan frissülnek, amikor az adott teszthez tartozó generátort lefuttatjuk.

Egy példa a canonical data állományra [itt](https://github.com/exercism/problem-specifications/blob/master/exercises/bob/canonical-data.json) található.

## Gyakori kifejezések

Amikor a canonical data-t és a generátor kódbázisát böngésszük, rengeteg gyakori kifejezést használunk. Ez a lista remélhetőleg tisztázza, mit jelentenek.

* Canonical Data – A teljes tesztcsomagot jelöli.
* Canonical Data Case – Egyetlen teszteset reprezentációja.
* Description – A teszt neve.
* Property – A teszt futtatásakor meghívandó metódus.
* Input – A teszteset bemenete.
* Expected – A teszteset futtatásakor elvárt érték.

## Egy egyszerű generátor hozzáadása

Egy tesztgenerátor hozzáadása egyszerű. Egyszerűen adj hozzá egy osztályt a `generators` mappában lévő `Generators.fs` állományhoz a feladat nevével (PascalCase írásmóddal), és származtathatod a `GeneratorExercise` absztrakt osztályból.

Egy egyszerű generátor példája a Bob feladat. A forráskód alább található, de a tárolóban is megnézheted [itt](https://github.com/exercism/fsharp/blob/master/generators/Generators.fs#L174).

```fsharp
type Bob() =
    inherit GeneratorExercise()
```

Ez egy teljesen működő generátor, más kódot nem kell írni. Az egyszerűsége azonban onnan ered, hogy a tesztcsomag és maga a program viszonylag triviális.

## Egy összetett generátor hozzáadása

Sok generátornál elég a `GeneratorExercise` osztály alapértelmezett viselkedése. A _bonyolultabb_ generátoroknál viszont felülírhatod egy vagy több virtuális metódusát:

### Metódus: RenderInput

A tesztmetódus bemenetének renderelése.

#### Példa

A `Gigasecond` generátor a bemeneti értéket (zárójelek közé zárt) `DateTime` értékként rendereli:

```fsharp
override __.RenderInput (_, _, value) =
    DateTime.Parse(string value, CultureInfo.InvariantCulture)
    |> DateTime.renderParenthesized
```

Ne feledd, hogy a `key` mezővel csak bizonyos bemeneti mezők kimenetét szabhatod testre. A `Yacht` generátor ezt teszi:

```fsharp
override __.RenderInput (canonicalDataCase, key, value) =
    match key with
    | "category" -> Obj.renderEnum "Category" value
    | _ -> base.RenderInput (canonicalDataCase, key, value)
```

### Metódus: RenderExpected

A tesztmetódus elvárt értékének renderelése.

#### Példa

A `Connect` generátor az elvárt értéket `Option<T>` értékként rendereli:

```fsharp
override __.RenderExpected (canonicalDataCase, key, value) =
    match string value with
    | "O" -> "(Some White)"
    | "X" -> "(Some Black)"
    | _   -> "None"
```

### Metódus: RenderSut

A tesztelt rendszer (System Under Test, SUT) renderelése. Ez az a tényleges érték, amelyet az elvárt értékkel vetünk össze.

#### Példa

A `RunLengthEncoding` generátornak van egy tesztesete, amelyben ellenőrzi, hogy a bemenet belekódolása, majd visszafejtése ugyanazt az értéket adja-e. A `RenderSut` metódust felülírja, hogy a nem létező `consistency` függvény egyetlen hívását `encode |> decode` hívások láncává alakítsa:

```fsharp
override this.RenderSut canonicalDataCase =
    match canonicalDataCase.Property with
    | "consistency" ->
        let parameters = this.RenderSutParameters canonicalDataCase |> String.concat " "
        sprintf "%s |> encode |> decode" parameters
    | _ ->
        base.RenderSut canonicalDataCase
```

### Metódus: RenderArrange

A tesztmetódus előkészítő részének renderelése. Ebben a részben jön létre a SUT.

Az alapértelmezett viselkedés általában pontosan megfelel. Csak nagyon különleges esetekben érdemes ezen változtatni.

Megjegyzés: ez a metódus egy `string list` értéket ad vissza, amelyben minden `string` a tesztfájl egyetlen renderelt sorának felel meg.

### Metódus: RenderAssert

A tesztmetódus ellenőrző részének renderelése. Ebben a részben történik az állítás, amellyel a SUT-ot az elvárt értékkel vetjük össze.

Az alapértelmezett viselkedés általában pontosan megfelel. Csak nagyon különleges esetekben érdemes ezen változtatni.

Megjegyzés: ez a metódus egy `string list` értéket ad vissza, amelyben minden `string` a tesztfájl egyetlen renderelt sorának felel meg.

### Metódus: RenderSetup

További segéd- és előkészítő metódusok renderelése. Ezzel olyan segédmetódusokat definiálhatsz, amelyeket a tesztmetódusokban használhatsz.

Az előkészítő kód a tesztmetódusok _előtt_ kerül a fájlba, hogy a segédmetódusok használhatók legyenek a tesztmetódusokban.

Megjegyzés: ez a metódus egy `string list` értéket ad vissza, amelyben minden `string` a tesztfájl egyetlen renderelt sorának felel meg.

#### Példa

A `Zipper` generátor két segédmetódust ad hozzá, amelyeket a tesztmetódusok használnak, hogy megszabaduljanak néhány fárasztó, ismétlődő kódrészlettől:

```fsharp
override __.RenderSetup _ =
    [ "let subTree value left right = Some (tree value left right)"
      "let leaf value = subTree value None None" ]
    |> String.concat "\n"
```

### Metódus: RenderValue

Egyetlen érték renderelése (amelyet a bemeneti paraméterek, az elvárt érték és a SUT rendereléséhez használunk).

### Példa

A `ComplexNumbers` generátor az érték típusa alapján renderel különböző értékeket:

```fsharp
override __.PropertiesWithIdentifier canonicalDataCase =
    match canonicalDataCase.Expected.Type with
    | JTokenType.Array -> ["sut"]
    | _ -> base.PropertiesWithIdentifier canonicalDataCase
```

### Metódus: MapCanonicalDataCase

A canonical data case leképezése. Ez akkor lehet hasznos, ha tulajdonságokat szeretnél hozzáadni vagy eltávolítani.

Az alapértelmezett viselkedés általában pontosan megfelel. Csak nagyon különleges esetekben érdemes ezen változtatni.

#### Példa

A `ScaleGenerator` generátor a canonical data case leképezését arra használja, hogy egy hiányzó tulajdonságot `null` értékként adjon hozzá (ami megkönnyíti a későbbi feldolgozást):

```fsharp
override __.MapCanonicalDataCase canonicalDataCase =
    let input = canonicalDataCase.Input
    match Map.tryFind "intervals" input with
    | Some _ -> canonicalDataCase
    | None   -> { canonicalDataCase with Input = Map.add "intervals" null input }
```

### Metódus: PropertiesUsedAsSutParameter

Megadja, hogy mely tulajdonságokat használjuk a SUT paramétereként.

Az alapértelmezett viselkedés általában pontosan megfelel. Csak nagyon különleges esetekben érdemes ezen változtatni.

#### Példa

A `RailFenceCipher` kifejezetten meghatározza a SUT paramétereként használt tulajdonságokat, hogy megváltoztassa az átadásuk sorrendjét:

```fsharp
override __.PropertiesUsedAsSutParameter _ = ["rails"; "msg"]
```

### Metódus: PropertiesWithIdentifier

Megadja, hogy mely tulajdonságokhoz rendeljünk azonosítót. Ha egy tulajdonság szerepel ebben a listában, akkor az értékét egy külön sorban, saját azonosítóhoz rendeljük hozzá.

#### Példa

A `Transpose` generátor úgy döntött, hogy minden tulajdonsághoz azonosítót használ:

```fsharp
override this.PropertiesWithIdentifier canonicalDataCase = this.Properties canonicalDataCase
```

### Metódus: IdentifierTypeAnnotation

Bizonyos esetekben szeretnéd, ha egy azonosítónak explicit típusa lenne. Gyakori eset, amikor az érték egy üres lista. Ilyenkor az FsUnit-nak típusannotációra van szüksége ahhoz, hogy sikeresen végrehajtsa az állítást.

#### Példa

A `Minesweeper` generátor `string list` típusannotációt ad az üres értékekhez:

```fsharp
override __.IdentifierTypeAnnotation (_, _, value) =
    match Seq.isEmpty value with
    | true  -> Some "string list"
    | false -> None
```

### Metódus: AdditionalNamespaces

A tesztfájlban megnyitandó további névterek listáját adja vissza.

#### Példa

A `Gigasecond` generátor `DateTime` példányokkal dolgozik, ezért hozzáadja a névterét a további névterek listájához:

```fsharp
override __.AdditionalNamespaces = [typeof<DateTime>.Namespace]
```

### Metódus: AssertTemplate

A használandó állítássablon. Az állítássablonok teljes listját a `generators/Templates/_Assert*.liquid` fájlban találod.

#### Példa

A `RationalNumbers` generátor az `"AssertEqualWithin"` sablont használja, hogy a double értékeket adott tűréssel lehessen egyenlőségre ellenőrizni:

```fsharp
override __.AssertTemplate canonicalDataCase =
    match canonicalDataCase.Expected.Type with
    | JTokenType.Float -> "AssertEqualWithin"
    | _ -> base.AssertTemplate(canonicalDataCase)
```

### Metódus: TestFileFormat

A tesztfájl formátuma: vagy modul, vagy osztály.

Az alapértelmezett viselkedés szinte mindig pontosan megfelel. Csak rendkívül ritka esetekben érdemes ezen változtatni.

#### Példa

A `Grep` generátor tesztosztályként definiálja magát, hogy előkészítő és lezáró metódusokat használhasson:

```fsharp
override __.TestFileFormat = TestFileFormat.Class
```

### Metódus: TestMethodName

Megadja a tesztmetódus nevét.

Az alapértelmezett viselkedés általában pontosan megfelel. Csak nagyon különleges esetekben érdemes ezen változtatni.

#### Példa

A `Zipper` generátor kicsit rendbe teszi a tesztmetódusok nevét:

```fsharp
override __.RenderTestMethodName canonicalDataCase =
    let testMethodName = base.RenderTestMethodName canonicalDataCase
    testMethodName.Replace("Set_", "Set ")
```

### Metódus: UseFullMethodName

Jelzi, hogy a használt tesztmetódusnév a teljes útvonalat használja-e, ami azt jelenti, hogy egymásba ágyazott teszteseteknél a szülő(k) leírását fűzi a tesztmetódus neve elé.

Az alapértelmezett viselkedés általában pontosan megfelel. Csak akkor érdemes ezen változtatni, ha egyébként több azonos nevű tesztmetódus lenne.

#### Metódus: Signature

A `KindergartenGarden` generátor teljes metódusneveket használ, hogy elkerülje a tesztmetódusnevek ütközését:

```fsharp
override __.UseFullMethodName _ = true
```

### Metódus: SkipTestMethod

Jelzi, hogy a tesztmetódust meg kell-e jelölni a `Skip = true` tulajdonsággal.

Az alapértelmezett viselkedés szinte mindig pontosan megfelel. Csak rendkívül ritka esetekben érdemes ezen változtatni.

#### Metódus: Signature

A `Markdown` feladat egy refaktorálási feladat, ezért minden tesztjének már érvényes állapotban kell lennie. Ennek megfelelően egyetlen tesztmetódusához sem adja hozzá a `Skip` tulajdonságot:

```fsharp
override __.SkipTestMethod (_, _) = false
```

## Meglévő fájlok frissítése

Előfordulhat, hogy egy meglévő feladat nem illeszkedik a canonical data-hoz. Nyugodtan frissítheted a feladat vázát és/vagy a feladat példáját, hogy kövessék a canonical data-t!

Ha pedig problémát találsz valamelyik meglévő generátorban vagy tesztcsomagban, egyszerűen nyisd meg a frissíteni kívánt generátort, végezd el a módosításokat, majd futtasd a generátorokat.

## A generátorok futtatása

Ez a tároló a [.NET Core 2.x](https://www.microsoft.com/net/core) verzióra készült. A generátorok futtatásához mindössze a következő parancsot kell futtatnod a generators könyvtárban:

`dotnet run`

Ez a parancs az összes definiált feladatgenerátort felveszi, és minden feladathoz legenerálja az összes tesztesetet. Reflectiont használunk az összes feladat felkutatásához, így ha új tesztet adsz hozzá, az automatikusan bekerül a generátor futtatásakor.

Ha csak egyetlen generátort kell futtatnod, azt a következő paranccsal teheted meg:

`dotnet run -e <exercise>`

Miután lefuttattad a generátort, a generálás eredményét úgy nézheted meg, hogy megnyitod az adott feladat tesztfájlját. Például a Bob feladat tesztcsomagja itt található:

`exercises/bob/BobTests.fs`

## Generátor beküldése

Ha elégedett vagy a generátorod kimenetével, örülnénk, ha beküldenél egy pull requestet! Kérjük, mellékeld a generátort, a frissített tesztcsomagot és minden más kapcsolódó fájlt, amelyet esetleg módosítottál.
