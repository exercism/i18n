# Függvények a `jq`-ban

A `jq`-ban saját **egyéni függvényeket** definiálhatsz, hogy egységbe zárd a szükséges logikát.
A _függvények_ pont úgy viselkednek, mint a beépített függvények: bemenetet kapnak, és nulla, egy vagy több kimenetet adnak.

## Függvény definiálása

A következő szintaxissal definiálhatsz egy `jq` _függvényt_:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- a `def` kulcsszóval kezdődik,
- a függvény törzse előtt kettőspont áll,
- a törzs egyetlen kifejezésből áll,
- pontosvesszővel végződik,
- a `jq` szintaxis többi részéhez hasonlóan tetszőleges szóközöket használhatsz az olvashatóság érdekében.

## Hova tegyük a függvényeket

A _függvényeket_ használat előtt kell definiálni: ez hiba:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Ez azt jelenti, hogy a _függvényeket_ a `jq` kódod elejére kell tenned, a „fő” kifejezés elé.

### Egymásba ágyazott függvények

A _függvények_ egymásba ágyazhatók:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Itt a `B` _függvény_ csak az `A` törzsében látható.

## Scope

A _függvény_ új **scope**-ot vezet be a változók és az egymásba ágyazott függvények számára.

## Argumentumok

A _függvény_ **argumentumait** _pontosvesszők_ választják el, nem vesszők.
Például egy _függvény_, amely kap egy számot, majd hozzáad egy számot és megszoroz egy számmal:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
A pontosvesszőkre azért van szükség, mert a vesszőnek már van célja a `jq`-ban: olyan operátor, amely folyamokat fűz össze.

Ha vesszőt használsz pontosvessző helyett, az két hívást próbál intézni egy _1 argumentumos_ `add_mul` függvényhez, amely nem létezik, ezért az első megkísérelt hívásnál hibát kapunk:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

Az `5, 4`-ben a vessző az 5 és 4 számokat egy folyammá fűzi össze. 
Amikor egy függvényt folyammal hívunk meg argumentumként, a `jq` többször meghívja azt a függvényt, egyszer a folyam minden egyes értékére. 
Ez példa a `jq` folyamaiban rejlő „implicit iterációra”.
A `10 | add_mul(5, 4)` ekvivalens a következővel.

```jq
(10 | add_mul(5)), (10 | add_mul(4))
```
Most már láthatjuk, hogyan bukkan fel az `add_mul/1 is not defined` hiba.
~~~~

<!-- prettier-ignore-end -->

### Az argumentumok _kifejezések_

A függvény _argumentumai_ szűrők, nem értékek.
Ebben az értelemben úgy viselkednek, mint amit más nyelvek callbackeknek neveznek:

Az `add_mul` függvényt példaként használva:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

Mi történik itt?

- az `adder` argumentum a `. + 5` _kifejezést_ kapja
  - amikor a függvény végrehajtja a `. + adder` kifejezést, az `. + . + 5` lesz
  - ami 25-re értékelődik ki, mivel `. == 10`
- hasonlóképpen a `multiplier` argumentum a `. - 2` kifejezés
  - ami 8-ra értékelődik ki
  - ekkor az eredmény `25 * 8 == 200`

### Az argumentumok mint értékek

Néha szeretnél egy _argumentumot_ változóvá „materializálni”:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Van erre egy rövidítés:

```jq
def my_func($arg):
    other stuff ...
;
```

Vedd figyelembe, hogy ez csak „szintaktikai cukor”: az `arg` név `$` nélkül is látható marad a _függvényben_.

<!-- prettier-ignore -->
~~~~exercism/caution
Például valami ilyesmit írtam egy feladat megoldásához:

```jq
# function that encodes the input value
def code:
    # expression here
    ;

def equals($code):
    (. | code) as $this_code
    | $code == $this_code
    ;

("some key value" | code) as $key
| ["array", "of", "values"]
| map(select(equals($key)))
```

és meglepődtem, hogy a tömb minden értéke egyenlő volt a kulccsal.

Ez azért történt, mert a jq így látta az `equals` függvényt:

```jq
def equals(code):
    code as $code
    | (. | code) as $this_code
    | $code == $this_code
    ;
```

Az **argumentum** `code` _felülírta_ a korábban definiált **függvényt**, a `code`-ot.
Ez azt jelentette, hogy a `(. | code)` egyszerűen az **argumentumot** adja ki, ahelyett hogy a bemeneti érték alapján új kódot számítana ki.
Így a `$this_code` és a `$code` mindig ugyanaz volt.
~~~~

<!-- prettier-ignore-end -->

## Aritás

A _függvényeknek_ **aritásuk** van: ennyi _argumentumot_ vesznek fel.

A _függvények_ ugyanazt a nevet különböző _aritásokkal_ használhatják.
A beépített [`range`][man-range] függvény ezt szemlélteti: a `range/1`, `range/2` és `range/3` mind létezhet egymás mellett.

Ez hasznos lehet olyan rekurzív függvények definiálásához, amelyek argumentumokon keresztül visznek állapotot.
Például a `map` _megvalósítható_ így:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## Rekurzió

A `jq` végez farokhívás-optimalizálást, de csak 0 aritású függvényeknél.

## Modulok

A `jq` modul egy olyan fájl, amely csak függvényeket tartalmaz.
A modulokat a [`include`][man-include] vagy [`import`][man-import] parancsokkal illesztjük be egy jq programba.
