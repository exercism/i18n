# Bevezetés

A `GENERIC:` deklaráció egy olyan szót hoz létre, amelynek a viselkedése az egyik argumentuma *osztályától* függ. A konkrét viselkedést a *metódusok* adják, amelyeket `M:`-mel definiálunk.

```factor
GENERIC: area ( shape -- n )

TUPLE: square side ;
TUPLE: circle radius ;

M: square area
    side>> dup * ;
M: circle area
    radius>> dup * pi * ;
```

Amikor az `area` meghívásra kerül, a Factor megvizsgálja a verem tetejét, megkeresi a legspecifikusabb metódust, amelynek az osztálya illeszkedik, és lefuttatja. Lokális változók esetén az `M::`-t is használhatod:

```factor
TUPLE: rectangle width height ;

M:: rectangle area ( r -- n )
    r width>> r height>> * ;

T{ rectangle { width 3 } { height 4 } } area .   ! => 12
```

A generikusokkal később új reprezentációkat adhatsz hozzá anélkül, hogy a hívó kódot módosítanád: az `area` már működött a `square` és a `circle` esetében, a `rectangle` metódust pedig automatikusan felveszi mindenhol, ahol az `area`-t meghívják.

## Mikor jó választás egy generikus?

Akkor válaszd a `GENERIC:`-et, ha:

- Egyetlen műveletnek *valóban különböző* megvalósításai vannak a különböző bemenetekre.
- Számítasz rá, hogy a jövőbeli kód új típusokat ad hozzá.
- Szeretnéd, hogy a típusrendszer kikényszerítse az osztályonkénti definíciókat.

Ha a változatosság csupán címkék kis felsorolása, akkor egy `case` egyszerűbb.

## Csatlakozás egy mixinhez az `INSTANCE:` segítségével

A *mixin* egy *nyitott* generikus osztály: bárki regisztrálhat új osztályt tagként. A Factor számos beépített protokollja (szekvenciák, halmazok, streamek, …) mixinként érhető el, így egy egyedi tuple azzal tud csatlakozni a protokoll alapértelmezett metódusaihoz, hogy példányként deklarálja magát:

```factor
MIXIN: shape
M: shape area                   ! a default area for any shape
    drop 0 ;

TUPLE: my-shape ;
INSTANCE: my-shape shape         ! my-shape is now a `shape`

T{ my-shape } area .   ! => 0
```

Az `INSTANCE:` után minden `M: shape …` alapértelmezett metódus automatikusan a `my-shape`-re illeszkedik, és bármely kód, amely `shape`-et kér, elfogad egy `my-shape`-et. Az `M:` metódusok hozzáadására szolgál egy generikushoz; az `INSTANCE:` egy osztály csatlakoztatására egy mixinhez.

## `TYPED::`: ellenőrzött bemenetek egy egyszerű szóhoz

A `GENERIC:`/`M:` az argumentum osztálya alapján választ metódust. Néha nem akarsz diszpécselést, csak *egyetlen* szót, amely megköveteli, hogy a bemenetei egy adott osztályba tartozzanak. A `TYPED::` (a `typed` szótárban) a `::` változata, ahol minden bemeneti név után egy osztály szerepel:

```factor
TYPED:: triple ( n: integer -- m )
    n 3 * ;

14 triple .   ! => 42
```

Az `n: integer` úgy olvasható, mint a már ismert lokálisok, csak a kettőspont után ki van írva az osztály. Itt nincs diszpécselés, egy definíció, egy viselkedés, de most minden argumentumot ellenőriz a rendszer az osztálya ellen: egy `"x" triple` típusú eltérés elutasításra kerül (*expected input value of type integer but got string*), ahelyett hogy csendben átcsúszna.

A kimenet is ugyanígy annotálható. A `yes?` mind a bemenetét, mind az eredményét típusozza:

```factor
TYPED:: yes? ( word: string -- answer: boolean )
    word "yes" = ;

"yes" yes? .   ! => t
"no" yes? .    ! => f
```

## Matematikai függvények és állandók

Ez a feladat néhány olyan szóra is támaszkodik a `math.constants` és a `math.functions` szótárból, amelyekkel itt találkozol először:

- `pi`: a π állandó a `math.constants` szótárból.
- `sin ( x -- y )`, `cos ( x -- y )`: egy radiánban mért szög szinusza és koszinusza.
- `e^ ( x -- y )`: `e` az `x`-edik hatványon. (Tetszőleges alap esetén használd a `^`-t.)

```factor
pi 2 / sin   ! → 1.0
0 cos        ! → 1.0
1 e^         ! → 2.718281828459045
```
