# Bevezetés

A korábbi fogalmakból már tudjuk, hogy a Julia típusai hierarchiát alkotnak, amelynek csúcsán az `Any` áll.

Az olyan absztrakt típusoknak, mint a `Number`, vannak altípusaik, magukat azonban nem lehet példányosítani.
Ha egy változót absztrakt típussal látunk el, az _korlátozza_ a változó lehetséges értékeit: csak az absztrakt típus valamely altípusa lehet.
Például:

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

Ez egyfajta rugalmasságot ad abban, hogy mely bemenetek érvényesek.

De tegyük fel, hogy egy változó egyszerre egész és string értékeket is elfogadjon?
Ez a két típus nem ugyanazon az ágon van a hierarchiában.

Beállíthatnánk a típust `Any`-ra, vagy hagyhatnánk, hogy ez legyen az alapértelmezett, de akkor elveszítjük az irányítást a megengedett típusok felett.

Jobb megoldást kínál a `Union{ }` szintaxis, amelyben két vagy több típust sorolunk fel a kapcsos zárójelek között.

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

Egy másik példa ugyanezt a típusuniót használja egy függvényszignatúrában:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

Itt nevet adtunk a típusnak, ami kényelmes rövidítést nyújthat, de szigorúan véve nem szükséges.
A `g(z::Union{Integer, String}) = z^3` függvény ugyanígy viselkedik.

A függvényszignatúrákról sokkal több szó esik majd a Többszörös diszpécselés fogalomban.

## Uniók a semmivel

Több más nyelvben is vannak olyan típusok, amelyek tartalmazhatnak értéket, de nem is, ilyen például az `Option`, a `Nullable` vagy a `Maybe`.

A Juliában erre nincs külön szintaxis, de a típusuniók ennek az ötletnek az általánosításai.

A `Nothingness` fogalomban láttuk, hogy a Juliában többféleképpen is ábrázolhatók a nem-értékek, például a `nothing` és a `missing`.
Bármelyikük szerepelhet egy típusunióban.

Ha például egy láncolt listát definiálunk, kell valami, amivel lezárhatjuk a listát, ha nincs több csomópont.
A `Nothing` az a típus, amelynek egyetlen értéke a `nothing`, és ez a Node-definíció lehetővé teszi a lánc végének jelzését:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

Hasonlóképpen a `missing` helyőrzőként szolgálhat hiányzó értékekhez, főleg olyan gyűjteményekben, mint a vektorok.
Az alábbi példa nagyon erőltetett, a hiányzó értékek viszont gyakoriak a valós adathalmazokban.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
