# Kiegészítés az utasításokhoz

## A `from_quote` előnyei és hátrányai
Ez a feladat definiál egy `from_quote` függvényt a `DateOfBirth` típusban. Ettől lehetővé válik, hogy ilyen kódot írj:

```roc
birthdate : DateOfBirth
birthdate = "2019-01-20"
```

Ez a kód implicit módon meghívja a `DateOfBirth.from_quote("2019-01-20")`-t fordítási időben. Ez potenciálisan felgyorsíthatja a programot, mivel futásidőben nem kell foglalkoznia a szöveg feldolgozásával, és biztosítja, hogy a `from_quote` által elutasított dátumok már fordítási időben kiszűrődjenek, nem futásidőben. Ráadásul így a kód szép és olvasható lesz. Például íme a feladat egyik tesztje:

```roc
# multiple birthdates with one shared birthday
expect {
	shared_birthday(["1966-07-29", "1977-02-12", "2001-07-29", "1980-11-10"])
}
```

Előfordulhat azonban, hogy aki ezt a kódot olvassa, azt feltételezi, hogy a `shared_birthday` függvény `List(Str)`-et vár, pedig valójában `List(DateOfBirth)`-et. Ez zavarhoz és hibákhoz vezethet. Ezért talán a kicsit hosszabb, de egyértelműbb formátumot részesíted előnyben: a `"2019-01-20".DateOfBirth` alakot, amely szintén meghívja a `from_quote`-ot fordítási időben.

A saját programjaidban érdemes lehet egy kényelmes konstruktort adnod, például ezt:

```roc
DateOfBirth := { year : I64, month : U8, day : U8 }.{
    from_ymd : I64, U8, U8 -> Try(DateOfBirth, [InvalidMonth, InvalidDay])
    from_ymd = |year, month, day| ...
}
```

Ezt a konstruktort fordítási időben is meghívhatod, így:

```roc
Ok(birthdate) = DateOfBirth.from_ymd(2019, 1, 20)
```

Megjegyzés: Ha ezt a definíciót a legfelső szinten helyezed el, az fordítási időben fut le (mivel a függvény tiszta, és a bemenetek fordítási időben ismertek). Egy függvényen belül ugyanezt a konstruktort futásidőben is használhatod.
