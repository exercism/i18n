## A szkript használata

A tesztek generálásához a [problem-specifications][problem-specifications] tároló helyi másolatára van szükség.
A szkriptet a gyökér `python` könyvtárból érdemes futtatni, hogy helyesen férjen hozzá a feladatokhoz.

A használattal kapcsolatos információkért futtasd a `bin/generate_tests.py --help` parancsot.


## Tesztsablonok

A tesztsablonok támogatják a [Jinja2] szintaxist, és a kanonikus adatokból a következő kontextusváltozók érhetők el bennük:
- `exercise`: A feladat kötőjelezett neve (pl. `two-fer`)
- `version`: A kanonikus adat verziója (pl. `1.2.0`)
- `cases`: Esetobjektumok listája vagy `cases` listák listája. A pontos szerkezetért
ahhoz a feladathoz, amelyen éppen dolgozol, nézd meg a `canonical-data.json` fájlt.
- `has_error_case`: Azt jelzi, hogy vár-e valamelyik teszteset hibadobást
(pl. `False`)
- `additional_cases`: a `cases` listához hasonló szerkezetű, de a feladat `.meta/additional_tests.json` fájljából töltődik fel, ha van ilyen (példát lásd: `exercises/word-count/.meta/additional_tests.json`)

Ezenkívül a kényelem kedvéért a következő sablonszűrők is elérhetők:
- `to_snake`: stringet snake_case formára alakít (pl. `{{ "CamelCaseString" | to_snake }}` -> `camel_case_string`)
- `camel_case`: stringet CamelCase formára alakít (pl. `{{ "snake_case_string" | camel_case }}` -> `SnakeCaseString` )
- `error_case`: ellenőrzi, hogy egy teszteset hibadobást vár-e (pl. `{% for case in cases%}{% if case is error_case}`)
- `regex_replace`: regex alapú stringcsere (pl. `{{ "abc123" | regex_replace("\\d", "D") }}` -> `abcDDD`)


### Konvenciók

- A gyakran ismétlődő sablonszerkezetekhez használható általános célú makrók a `config/generator_macros.j2` fájlban vannak definiálva.
  - Ezeket a következőképpen importálhatod:
  `{%- import "generator_macros.j2" as macros with context -%}`
- Minden tesztsablon `{{ macros.footer() }}` hívással záruljon.
- Minden Python-osztálynév CamelCase formában legyen (pl. `TwoFer`).
  - Átalakítás: `{{ "two-fer" | camel_case }}`
- Minden Python-modul- és függvénynév snake_case formában legyen
(pl. `high_scores`, `personal_best`).
  - Átalakítás: `{{ "personalBest" | to_snake }}`
- A kurzusspecifikus tesztek az opcionális `.meta/additional_tests.json` fájlban vannak definiálva. Az ebben a fájlban definiált JSON-objektumnak
egyetlen kulcsa legyen, a `cases`, amelynek szerkezete megegyezik a
`canonical-data.json`-ban lévő `cases` szerkezetével.
- A kurzusspecifikus teszteket a tesztfájlokban a kanonikus tesztek után kell
elhelyezni.
- A kurzusspecifikus teszteket a tesztfájlban a következő megjegyzéssel kell megjelölni:
```
# Additional tests for this track
```


### Elrendezés

A legtöbb sablon valahogy így néz ki:

```Jinja2
{%- import "generator_macros.j2" as macros with context -%}
{{ macros.header() }}

class {{ exercise | camel_case }}Test(unittest.TestCase):
    {% for case in cases -%}
    def test_{{ case["description"] | to_snake }}(self):
        value = {{ case["input"]["value"] }}
        expected = {{ case["expected"] }}
        self.assertEqual({{ case["property"] }}(value), expected)

    {% endfor %}

{{ macros.footer() }}
```


### Importok felülírása

A `macros.header()` által importált nevek felülírhatók, ha megadod
az importálandó alternatív nevek listáját (pl. `clock`):

```Jinja2
{{ macros.header(["Clock"])}}
```


### Tulajdonságok kihagyása

Ritkán szükség lehet arra, hogy kiszűrjük azokat a tulajdonságokat, amelyeket
ezen a kurzuson nem tesztelünk. A `header` makró egy
`ignore` argumentumot is elfogad (pl. `high-scores`):

```Jinja2
{{ macros.header(ignore=["scores"]) }}
```

## Sablon készítése

1. Hozd létre a `.meta/template.j2` fájlt ahhoz a feladathoz, amelyet éppen megvalósítasz,
  és nyisd meg a szerkesztődben.
2. Másold be a [példa elrendezést](#Layout) a sablonfájlba,
  és mentsd el.
3. Addig módosítsd a sablonfájlt, amíg érvényes tesztkódot nem ad,
  a bemeneti nevekhez és az esetszerkezethez a feladat `canonical-data.json` fájlját
  használva.
    - Használd a [rendelkezésre álló makrókat](../config/generator_macros.j2), hogy ne kelljen újra megírnod a szabványos részeket.
    - Ha meglévő feladathoz készítesz sablont,
    nem követelmény, hogy pontosan a meglévő tesztfájl szerkezetét kövesd,
    de ha minimalizálod az eltéréseket, az mindenki számára sokkal gördülékenyebbé teszi a PR-áttekintést.
