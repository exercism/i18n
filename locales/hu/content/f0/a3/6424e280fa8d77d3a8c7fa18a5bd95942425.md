# A fogalomról

## Opcionálisok

A Swift az [_opcionálisokat_][optionals] használja arra, hogy a programozók kifejezhessék egy érték esetleges hiányát.
Az opcionális egy olyan típus, amely vagy tárol egy értéket, vagy [`nil`][nil], ami az érték hiányát jelöli.
Ahhoz, hogy egy opcionálist használhassunk, a programnak ellenőriznie kell, hogy létezik-e érték, mielőtt kicsomagolás után használná.

Bármely típusból készíthető opcionális úgy, hogy a típusnév végére egy `?` jelet teszünk.
Így egy opcionális egész szám típusa `Int?` lesz, egy opcionális string típusa pedig `String?`.
Az opcionális típusú konstansok és változók definiálása, valamint az értékadás nekik ugyanúgy történik, mint a nem opcionális típusú értékek esetében.

```swift
let x: Int? = 42
var y: String? = "Hello"
y = "Goodbye"
```

Egy opcionális típusú változónak az érték hiányát úgy adhatod meg, hogy a speciális `nil` értéket rendeled hozzá.
A `nil` minden opcionális típussal használható, de a két különböző opcionális típushoz rendelt `nil`-eknek nem ugyanaz a típusuk, és nem cserélhetők fel egymással, sőt össze sem hasonlíthatók.

```swift
let intOpt: Int? = nil
let stringOpt: String? = nil

intOpt = stringOpt
// Compiler error: Cannot assign value of type 'String?' to type 'Int?'

intOpt == stringOpt
// Compiler error: Binary operator '==' cannot be applied to operands of type 'Int?' and 'String?'
```

Azt is jegyezd meg, hogy bár a `nil` bármely opcionális típushoz hozzárendelhető, nem opcionális típushoz nem rendelhető hozzá (még akkor sem, ha az valójában nem tartalmaz `nil`-t).
És azoknak a metódusoknak, amelyek nem opcionális típust várnak, nem adhatunk át opcionális típust anélkül, hogy előbb kicsomagolnánk.

```swift
var x: Int = 42
var y: Int? = 42

y = x
// Works fine
x = y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
x + y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

## Opcionálisok használata

Mivel az opcionális típusok nem ugyanazok a típusok, mint az alaptípusaik, a két típus nem használható ugyanúgy.
Például: az `Int("123") + 1` fordítási hibát eredményez: „Value of optional type 'Int?' must be unwrapped to a value of type 'Int'”.
Ez azért van, mert az `Int("123")` egy opcionális `Int?` típust ad vissza, nem `Int` típust, hiszen ha a string nem alakítható át egésszé, az eredmény `nil` lesz.
Ahhoz, hogy az átalakításból megkapd az `Int`-et, először ki kell csomagolnod.

Erre a Swiftben leggyakrabban az `if-let` és a `guard-let` szerkezetet használjuk, amelyek az [_opcionális kötést_][optional-binding] valósítják meg: ellenőrzik a `nil`-t, és ha létezik érték, az egyik ágon a kicsomagolt értéket a megadott névhez kötik, ha pedig `nil`-t találnak, egy másik ágra lépnek.

```swift
if let safeNum = Int("123") {
	let sum = safeNum + 1
	…
} else {
  // code for the case where nil was found -- may be left out
}
```

Érdemes megjegyezni, hogy a `safeNum` változó típusa `Int`, nem pedig `Int?`.
Az alábbi példában a `num` típusa `Int?`, a `safeNum` típusa pedig `Int`.

```swift
let num = Int("123")
if let safeNum = num {
  // num is of type Int
}
```

Ez az _opcionális kötés_ azért fontos, mert kicsomagolja (vagy „eltávolítja”) az értékből az opcionális típust, így az nem opcionális értékként használható.
Ha csak feltételben ellenőriznéd, hogy az érték `nil`-e, az érték továbbra is opcionális típusú maradna:

```swift
let num = Int("123")
if num != nil {
  // num is of type Int?
}
```

A `guard-let` lehetőség is használható azokban az esetekben, amikor korai visszatérést szeretnénk:

```swift
guard let num = Int("123") else { return nil }
let sum = num + 1
…
```

## Opcionálisok összehasonlítása

Vedd figyelembe, hogy még ha egy opcionálispár alaptípusa össze is hasonlítható a szokásos összehasonlító operátorokkal, maguk az opcionálisok nem hasonlíthatók össze.
Rajtuk csak egyenlőségvizsgálatot végezhetsz.
Két opcionális akkor egyenlő, ha mindkettő `nil`, vagy ha a bennük tárolt értékek az alaptípusukon belül egyenlők.

Írhatunk azonban olyan kódot, amely két opcionális értéket egyéni módon hasonlít össze.
Az alábbi példa egy `switch` utasításra mutat, amely csak akkor ad vissza `true`-t, ha mindkét opcionális érték nem `nil`, és az első érték kisebb a másodiknál. 
Ehhez a `varName?` _opcionális mintát_ használja, amely csak a nem `nil` opcionálisokra illeszkedik, és az opcionálison belüli értéket a `varName` névhez köti.

```swift
switch (optionalA, optionalB) {
case let (valA?, valB?): return valA < valB
default: return false
}
```

## Nil-összevonás

A kicsomagolásnak létezik egy másik módja is: ha `nil`-t találunk, használhatunk [tartalékértéket][fallback].
Ezt a _nil-összevonó operátorral_, azaz a `??` segítségével teheted meg. Feltéve, hogy `x` egy `Int?`, ha valaki azt írja, hogy `let y = x ?? 0`, akkor a Swift ellenőrzi, hogy x `nil`-e.
Ha nem az, akkor kicsomagolja `x`-et, és a kicsomagolt értéket `y`-hoz rendeli; ha viszont `x` _valóban_ `nil`, akkor 0-t rendel `y`-hoz.

Mivel az `x ?? y` egyszerűen csak rövidítése az `x != nil ? x! : y` kifejezésnek, ha `x` nem `nil`, akkor az `y` kifejezés egyáltalán nem értékelődik ki.

Végül érdemes megjegyezni, hogy a nil-összevonó operátor jobbra asszociatív, ami meglepő eredményekhez vezethet annak, aki nem számít rá.

```swift
let k = 42 ?? 0 + 1    // returns 42
let j = nil ?? 0 + 1   // returns 1
```

A nil-összevonó operátorról bővebben a [A Tour of Swift: Nil-Coalescing Operator][nil-coalescing] című fejezetben olvashatsz.
