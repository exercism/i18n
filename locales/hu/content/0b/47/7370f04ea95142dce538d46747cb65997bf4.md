# Bevezetés

A feltételes elágazások fogalom bemutatja a `jcc`-t, a feltétel alapján történő elágazáshoz tartozó utasítások családját.
A `jcc` csak akkor adja át a végrehajtást a program egy másik pontjának, ha a feltétele teljesül.

A modern CPU-k viszont gyorsak, és sok utasítást képesek párhuzamosan végrehajtani.
Túl sokba kerülne, ha minden munkát le kellene állítani, amíg a CPU egy feltétel futásidejű ellenőrzésére vár.

Ezért a CPU belül nem vár.
Egy **elágazás-előrejelző** segítségével megtippeli egy feltétel kimenetelét, és _spekulatívan_ elkezdi végrehajtani a megjósolt útvonalat.

Ha a jóslat helyes, a végrehajtás úgy folytatódik, mintha nem is lenne elágazás.
Ha viszont a jóslat téves, a CPU-nak _el kell vetnie a megjósolt útvonalon végzett munkát_, és a helyes útvonalon kell újrakezdenie.

Ezt **téves elágazásjóslásnak** nevezik, és költséges, mert késleltetést okoz.

Ha egy elágazást nehéz megjósolni, ezek a téves jóslások felhalmozódnak.
Ilyenkor néha jobb teljesen elkerülni az elágazást, hogy ugyanazok az utasítások fussanak le, függetlenül a feltételtől.
Az olyan kódot, amely `jcc` nélkül választ az értékek között, **elágazásmentesnek** nevezik.

Többféleképpen is felépíthető a kód úgy, hogy ritkábban ágazzon el, vagy hogy a megmaradó elágazásai kiszámíthatóbbak legyenek.
Az x86-64 különösen két olyan utasításcsaládot kínál, amelyeket gyakran használnak elágazásmentes kód írásához.

## Feltételes mozgatások

A `cmovcc` utasításcsalád csak akkor másolja a forrásoperandust a célba, ha egy adott feltétel teljesül.
Egyébként a cél változatlan marad.

A `cc` utótag ugyanazt az elnevezést követi, mint a `jcc` esetében, ugyanazzal a jelentéssel:

| utasítás | mozgatás, ha                        |
|----------|-------------------------------------|
| `cmove`  | A == B a `cmp A, B` után            |
| `cmovne` | A != B a `cmp A, B` után            |
| `cmovl`  | A < B (előjeles) a `cmp A, B` után  |
| `cmovb`  | A < B (előjel nélküli) a `cmp A, B` után |
| `cmovg`  | A > B (előjeles) a `cmp A, B` után  |
| `cmova`  | A > B (előjel nélküli) a `cmp A, B` után |

A szabályok hasonlók a `jcc`-hez:

1. Az `l` és a `g` az előjeles összehasonlításokhoz használatos, a `b` és az `a` pedig az előjel nélküliekhez.
2. Ha egy utótaghoz hozzáadjuk az `e`-t, az magában foglalja az egyenlőséget is.
3. Az `n` hozzáadása tagadja a feltételt.
4. Vannak olyan változatok is, amelyek arra utalnak, hogy egy jelző be van állítva.
   Például a `cmovz` és a `cmovc`.

Vegyük egy `rdi`-ben lévő előjeles egész abszolút értékét, amelyet `rax`-ben adunk vissza.
`jcc`-vel megírva a függvény két útvonal közül választ:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

`cmovcc`-vel megírva mindkét lehetséges érték feltétel nélkül kiszámításra kerül, és a feltételes mozgatás választ közülük egyet:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

Az elágazásmentes változat mindig ugyanazokat az utasításokat hajtja végre.
Nincs `jcc`, amit az előrejelzőnek meg kellene tippelnie.

A `cmovcc` célja csak regiszter lehet.
A forrás lehet regiszter vagy memóriabeli hely, de immediate nem.

~~~~exercism/note
A fenti kódban a `neg` utasítás az eredmény alapján több jelzőt is beállít, köztük az előjeljelzőt (SF).
Ez azt jelenti, hogy a `cmp rdi, 0` teljesen elhagyható:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Pozitív `rdi` esetén a `neg` negatív eredményt ad, és SF == 1, így a `cmovs` visszaállítja `rdi`-t.
Nulla vagy negatív `rdi` esetén a `neg` nemnegatív eredményt ad, és SF == 0, így `rax` megtartja a negált értéket (ami a helyes abszolút érték).

Bár assemblyben az értékek összehasonlítására leginkább a `cmp` szolgál, sok utasítás szintén beállít jelzőket az eredménye alapján.
Az, hogy egy utasítás pontosan mely jelzőket befolyásolja, általában a [referenciájában][reference] szerepel.
A `neg` esetében ezek konkrétan: SF, ZF, CF, OF és PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

## Feltételes beállítás

A `setcc` utasításcsalád `1`-re állítja a céloperandust, ha egy adott feltétel teljesül, egyébként pedig `0`-ra.
A cél mindig _8 bites operandus_.

A `cc` utótag ugyanazt az elnevezést követi, mint a `jcc` és a `cmovcc` esetében.
Például a `setz` `1`-re állítja a célt, ha `ZF == 1`, egyébként pedig `0`-ra.

Mivel a cél 8 bites, gyakori, hogy a `setcc`-t egy `movzx` követi, amikor szélesebb értékre van szükség:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Ez egy gyakori idióma arra, hogy egy összehasonlítás eredményét `0` vagy `1` egész számmá alakítsuk.
