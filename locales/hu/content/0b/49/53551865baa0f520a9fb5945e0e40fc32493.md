# Bevezetés

A parti őrhajó *jeladója* vezeti az üzenetnaplót. A nyers
jelzőzászlók jelölőkarakterekkel keretezve érkeznek, a
leolvasásokat a vezetékre kell formázni, a megfigyelések párosait
és hármasait pedig menet közben összegzik. A munka nagy részét a
Factor szabványos könyvtárából származó néhány idióma végzi el.

## `unparse` - értékből forráskód

A [`unparse`][unparse] (a `prettyprint`-ben) bármilyen érték
forrásformájú szövegét adja vissza:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

Az `unparse` a parser inverze: a `dup unparse parse` oda-vissza út
újraépíti az értéket. Ez a megfelelő eszköz, ha olyan
vezetékformátumba szerializálsz, amelyet a fogadó fél vissza fog
parsolni, és a rossz eszköz az ember által olvasható kimenethez (a
stringek megőrzik az idézőjeleiket, a vektorok a `V{ ... }`
jelölésüket, és így tovább).

## Szeletváltozatok - nézetek, nem másolatok

A `head` és a `tail` (a `sequences`-ből) *lemásolja* a megtartott
részt egy új sorozatba. A `-slice` változataik viszont egy `slice`
objektumot adnak vissza: egy tuple-t, amely a kezdőindexet, a
záróindexet és a mögöttes sorozatot tartalmazza, és amely másolás
nélkül valósítja meg a [sorozatprotokollt][sequence-protocol]:

| szó           | hatás                                            |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )` - az első n másolata          |
| `head-slice`  | `( seq n -- slice )` - nézet az első n elemre        |
| `tail`        | `( seq n -- newseq )` - az n. indextől másol  |
| `tail-slice`  | `( seq n -- slice )` - nézet az n. indextől     |
| `head*`       | `( seq n -- newseq )` - az utolsó n kivételével másol mindent   |
| `head-slice*` | `( seq n -- slice )` - nézet az utolsó n kivételével mindenre   |
| `tail*`       | `( seq n -- newseq )` - az utolsó n másolata         |
| `tail-slice*` | `( seq n -- slice )` - nézet az utolsó n elemre         |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

A `slice` maga is egy sorozat, így minden, ami sorozatot fogad el,
elfogad egy slice-t is: a `length`, a `first`, az `each` és a
többi mind másolás nélkül működik. Azok a tesztek, amelyeknek egy
literál stringhez kell hasonlítaniuk, a `>string` segítségével
konvertálhatnak.

## `?head` és `?tail` - jelölő eltávolítása, ha jelen van

A keretezett leolvasások jelölőszöveget hordoznak, amely lehet,
hogy ott van, és lehet, hogy nem. A `?head` és a `?tail` (a
`splitting`-ből) megpróbál eltávolítani egy előtagot vagy utótagot,
és visszaadja a (lehetséges, hogy lerövidült) sorozatot *és* egy
Boolean értéket, amely megmondja, hogy megtalálta-e a jelölőt:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

A végén visszaadott Boolean érték természetes módon alkalmassá
teszi őket őrfeltételként való használatra: párosítsd a `?head`-et
az `if`-fel, hogy aszerint ágazz el, hogy jelen volt-e a keret,
vagy az `unless`-szel, hogy elutasítsd a várt jelölőt nélkülözlő
bemenetet.

## `<repetition>` - N másolat, virtuálisan

A [`<repetition>`][repetition] (a `sequences`-ben) egy másik,
másolás nélküli virtuális sorozat: a `( len elt -- repetition )`
olyan sorozatot épít, amelynek mind a `len` eleme `elt`, anélkül
hogy ennyi helyet lefoglalna:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

Az `elt` maga is lehet sorozat: minden másolat ugyanaz a sorozat.
A `concat` ezután végponttól végpontig összefűzi a másolatokat:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

A `slice`-hoz hasonlóan az eredmény maga is sorozat: a `length`,
az `each` és a társaik közvetlenül működnek rajta. Akkor nyúlj
hozzá, ha egy jelkódot fix szélességre szeretnél feltölteni, vagy
ha ismétlődő jelölők sorozatát akarod lefektetni; a `>string` (vagy
`>array`) konverziót csak akkor használd, ha valóban konkrét
sorozatra van szükség.

## `<clumps>` - átfedő ablakok, virtuálisan

A [`<clumps>`][clumps] (a `grouping`-ban) egy harmadik, másolás
nélküli virtuális sorozat: a `( seq n -- clumps )` a `seq`-et
*átfedő*, `n` hosszúságú ablakok sorozataként nézi, amelyek rajta
helyezkednek el, és minden ablak egy slice:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

Egy `length` hosszúságú sorozat `length - n + 1` ablakot ad. Mivel
minden ablak egy slice, az egymást követő leolvasások párosítása
nem jár másolással: ha minden `2`-es clumpra a `[ first2 ]`-t
alkalmazod, megkapod az összes egymást követő párt, amelyből
dolgozhatsz. (A nem átfedő rokona, a `<groups>`, ehelyett diszjunkt
blokkokra vágja a sorozatot.)

## Több bemenetes cleave - `2bi`, `3bi`, `2tri`, `3tri`

A sima cleave szavak, a `bi` és a `tri` két vagy három quotációt
alkalmaznak *egy* bemenetre. A `2`-es és `3`-as előtagú változatok
minden quotációt *két* vagy *három* bemenetre alkalmaznak:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

Minden quotáció *az összes* bemenetet megkapja. Akkor használd
őket, ha egynél több kivetítés függ ugyanattól az értékpártól
(vagy -hármastól), és nem akkor, ha *ugyanazt* a műveletet
szeretnéd külön-külön minden bemenetre alkalmazni (arra a `bi@`
vagy a `tri@` való).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
