# Bevezetés

A kézzel írt assembly tele van ismétlődéssel.
Ugyanaz a rövid utasítássor jelenik meg újra meg újra, alig változva, és kevés absztrakció van, ami csökkentené a sablonkódot.
Ráadásul az assemblyben való programozás során olyan értékeket kell kezelni, amelyeknek nincs nyilvánvaló jelentésük.
Nincsenek elnevezett paraméterek, és a háttérben működő gépezet részleteinek nagy részét a programozónak kézzel kell kezelnie.

A NASM, a kurzus által használt assembler, néhány olyan eszközt kínál, amelyek segíthetnek a programozónak mindkét problémában.
Ezek az eszközök _assembly időben_ futnak, mielőtt bármely utasítás eljutna a processzorhoz.
Segítenek az assemblert abban, hogyan írja át a forrásszöveget, mielőtt az egyáltalán gépi kódra fordulna.

Ezek közül a legfontosabbak a **makrók**, amelyekre úgy gondolhatunk, mint egy receptre az assembler számára.
A használat helyén fejtődnek ki, mintha a kódot kézzel oda írták volna.

A makrók számos literál tokent vehetnek fel paraméterként, így különböző kontextusokban újra felhasználhatók.
Nem függvények azonban: nincs `call`, nincs `ret`, nincs vezérlésátadás a kód egy másik pontjára.

## Egysoros makrók

A legegyszerűbb definíció egy értéknek vagy egy rövid kifejezésnek ad nevet a `%define` segítségével:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

A `WIDTH` minden későbbi előfordulása `8`-ra cserélődik az assembly előtt.
A csere szöveges, így a név mindenhol behelyettesítődik, ahol megjelenik, akár egy operandusban, akár egy másik definíción belül.

~~~~exercism/note
Numerikus _konstansokhoz_ inkább az `equ`-t válaszd a `%define` helyett.

A `%define`-nal deklarált egysoros makró csak használatkor fejtődik ki, és újraértékelve vagy definiálatlanná tehető.
Az `equ` konstans ezzel szemben a definíció pontján értékelődik ki, és soha nem módosul.
~~~~

A `%define` _elnevezett_ paramétereket is fogadhat, és úgy viselkedik, mint egy kis inline függvény:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Tegyél zárójelet mind a teljes törzs, mind az egyes paraméterek köré.
A `%define square(x) x*x` esetén a `square(1+1)` hívás `1+1*1+1`-re fejtődik ki, ami `3`.
Ha `%define square(x) ((x)*(x))`-ként írod le, ugyanez a hívás `((1+1)*(1+1))`-re fejtődik ki, ami `4`.
~~~~

A `%define`-nal definiált nevek kis- és nagybetűre érzékenyek.
A `%idefine` változat kis- és nagybetűtől függetlenné teszi a nevet, ha erre van szükség.

Az egysoros makrók hasznosak, hogy jelentést adjanak a kód különböző részeinek.
Ha körültekintően használod őket, javítják az olvashatóságot és csökkentik az elgépelések esélyét.
Például egy regiszter, amelynek egy függvényen belül kijelölt szerepe van, a szerepe szerint definiálható:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Többsoros makrók

Egy teljes kódsorozat, akármennyi sorral, a `%macro` segítségével rögzíthető, és a `%endmacro` zárja le.
A név utáni szám jelzi, hogy a makró hány argumentumot vesz fel, ami nulla is lehet.
Az átadott argumentumokat vessző (`,`) választja el:

```x86asm
%macro example_macro 0
...
%endmacro
```

A többsoros makrók argumentumai nem rendelkeznek névvel.
`%1`, `%2` és így tovább formában hivatkozunk rájuk, az átadás sorrendjében:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Vedd figyelembe, hogy az argumentumoknak érvényes szintaxissal kell rendelkezniük a makró törzsében végrehajtott műveletekhez.
Itt a `mult_two eax, ecx` és a `mult_two r8, r9` is lefordul, de a `mult_two eax, cl` nem, mivel az `imul eax, cl` nincs definiálva.

### Címkék egy makrón belül

Egy makró, amely közönséges címkét definiál, abban a pillanatban elromlik, amikor kétszer használják, mert ilyenkor a címke is kétszer definiálódna.
Ahhoz, hogy egy olyan makrón belül használj címkéket, amelyet többször is meghívhatnak, az ilyen címkét `%%` előtaggal kell ellátni.
Ez utasítja az assemblert, hogy minden kifejtéskor más, egyedi nevet adjon ennek a címkének:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Ismétlés assembly időben

Egy egysoros kódblokk ismételhető a `times` használatával.
Ez különösen hasznos, amikor ismétlődő értékeket deklarálunk a memóriában:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Többsoros kód ismétléséhez használhatjuk a `%rep`-et ehelyett:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Vedd figyelembe, hogy az ismétlések számát közvetlenül a `%rep` után adod meg, és egy `%endrep` zárja le az ismételt blokkot.

Gyakori, hogy egy assembly idejű számlálót használunk a `%rep` blokkon belül, ahogy a futásidejű ciklusok is számlálót használnak.
Míg egy assembly idejű egész konstans az `equ`-val deklarálható, az assembly idejű egész _változókhoz_ a `%assign`-et használjuk.
A `%define`-tól eltérően a `%assign` azonnal egy számmá értékelődik ki, és újraértékelhető:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Miután a preprocesszor lefut, a ciklus eltűnik, és négy `add` utasítás marad, a `0`, `1`, `2` és `3` azonnali értékekkel beépítve.
Ez az assembler által végzett cikluskibontás: nincs számlálóregiszter és nincs elágazás, csak egyenes vonalú kód.

## Feltételes assembly

A preprocesszor számos feltételes utasítást kínál.
Számos különböző útvonal közül választanak, és a helyükön fejtik ki a törzsüket, de csak akkor, ha a feltételük igaznak bizonyul.

A `%if` ... `%elif` ... `%else` ... `%endif` egy numerikus vizsgálat alapján választ ágat:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## Felosztás fájlokra

A makrókat gyakran külön fájlban tartják, és a `%include` segítségével húzzák be minden forrásba, amelyiknek szüksége van rájuk:

```x86asm
%include "patterns.mac"
```

A megnevezett fájl szó szerint beillesztődik az adott pontra, az assembly előtt, pontosan úgy, mintha a tartalmát oda gépelték volna.
Ez egy helyen tartja a definíciókat, és lehetővé teszi, hogy több forrásfájl is megossza őket.

Ha a makrófájl önállóan is lefordítható, akkor `.asm` fájlkiterjesztéssel kell rendelkeznie.
Vedd figyelembe, hogy a makróknak nincs kapcsolódásuk.
Még ha a makrófájlt le is fordítják, a makrói csak egy másik fájl számára láthatók, amely `%include`-olja.

Ellenkező esetben egy csak `%include`-ra használt fájl bármilyen fájlkiterjesztéssel rendelkezhet.
A `.asm` vagy a `.mac` használata gyakori konvenció.
