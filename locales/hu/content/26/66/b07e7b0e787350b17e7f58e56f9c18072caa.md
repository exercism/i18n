# Bemutatás

## Karakterek

A [karakterkódolás][char-encoding] egy konkrét konvenció, amellyel egy természetes nyelv szövegelemeit bájtok sorozataként ábrázoljuk.
Egy „szövegelem” itt bármilyen egység lehet, amelynek jelentősége van egy természetes nyelvben; például betűk, szóközök, írásjelek, emojik, ideogrammák stb.

A NASM (The Netwide Assembler, az ezen a kurzuson használt assembler) támogatja az adatok definiálását [ASCII][ascii] használatával.

A NASM karakterkonstansai legfeljebb 8 bájt hosszúak lehetnek, és definiálhatók aposztróffal (`'`), idézőjellel (`"`) vagy backtickkel (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

A speciális karaktereket backtickek között kell definiálni, és `\` jellel kell escape-elni:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

A NASM támogatja a [Unicode-karaktereket][unicode] [UTF-8][utf8] kódolásban is, amelyeket `\u` vagy `\U` előtaggal, backtickek között adunk meg:

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

Vedd figyelembe, hogy az x86-64-ben egyetlen karakterkódoláshoz sincs beépített támogatás külön típusként.
Az assemblyben az adat bájtok sorozata, és hogy ezeket a bájtokat karakterként, számként vagy bármi másként értelmezed, az a programozóra van bízva.

Például az ASCII '0' karakter egyetlen bájt, amelynek értéke 48.
Tehát ha egy bájtba 48-at tárolsz, az pontosan ugyanaz, mint az ASCII '0' karaktert tárolni:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Ugyanezért a karakterekkel végzett műveletek is úgy történnek, hogy közvetlenül a bájtokban lévő értékeket alakítod át:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## Stringek

A [string][string] karakterek sorozata.
Az assemblyben általában tömbként valósítják meg.

A NASM-ben deklarálhatsz stringet ugyanúgy, ahogy bármely tömböt deklarálnál:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

A stringek és a többi tömb között az egyik különbség, hogy a NASM támogatja a stringek deklarálását úgy is, hogy nem teszünk vesszőt (`,`) az értékek közé.
Az értékeket vesszőkkel is elválaszthatod:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Vedd figyelembe, hogy amint már említettük, a karakterek valójában csak bájtok (vagy Unicode-kódolás esetén bájtok sorozata):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Mivel minden ASCII-karakter egyetlen bájtot foglal el, egy nagyobb méretnél az összes utána következő bájt `0` lesz.
Például ha az `'a'` karaktert qwordként (8 bájt) deklarálod, az első bájt `'a'` (`97`) lesz, a többi hét bájt pedig mind `0`.

Ezért a következők mind egyenértékűek:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
Az assemblyben a stringeket nem zárja le automatikusan egy ASCII NUL karakter (`0` érték).

Amikor magasabb szintű nyelvekkel, például C-vel lépsz kapcsolatba, a programozó felelőssége gondoskodni arról, hogy a megfelelő lezáró karakter, ha egyáltalán kell ilyen, a string végére kerüljön.
~~~~

## String utasítások

Mivel a stringek tömbök, ugyanúgy dolgozhatsz velük, mint bármely tömbbel, a memória explicit dereferálásával:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Ezen kívül néhány utasítás kifejezetten arra szolgál, hogy értékeket töltsön be, mozgasson és tároljon a memóriában lévő bájtok sorozataiban.
Bár _stringutasításoknak_ nevezik őket, bármilyen memóriabeli bájtsorozattal használhatók, azaz bármilyen tömbbel:

| utasítás     | mit csinál                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | betölt egy értéket az `rsi` által mutatott memóriacímről az `rax`-be                                              |
| [stos][stos] | elmenti az `rax` értékét az `rdi` által mutatott memóriacímre                                                     |
| [movs][movs] | átmásol egy értéket az `rsi` által mutatott memóriacímről, és elmenti az `rdi` által mutatott memóriacímre        |
| [cmps][cmps] | összehasonlítja az `rsi` által mutatott memóriacím értékét az `rdi` által mutatott memóriacím értékével           |
| [scas][scas] | összehasonlítja az `rax` értékét az `rdi` által mutatott memóriacím értékével                                     |

Vedd figyelembe, hogy ezek az utasítások _nem_ fogadnak explicit operandust.
Az operandusaik implicit módon adottak.

Ökölszabályként:

1. Ha a forrásoperandus memóriacím, annak címét az `rsi` regiszterben kell tárolni (`s` = source).
2. Ha a céloperandus memóriacím, akkor annak címét az `rdi` regiszterben kell tárolni (`d` = destination).
3. Ha az egyik operandus nem memóriacím, akkor az az `rax` regiszter.

Vedd figyelembe, hogy ezek az utasítások automatikusan dereferálják a memóriacímeket annak megfelelően, hogy milyen műveletet végeznek.

Mindegyikük különböző méretekben működhet.
A méretet egy utótag jelzi:

| utótag | jelentés | méret   |
| :----: | -------- | :------ |
|  `b`   | bájt     | 1 bájt  |
|  `w`   | word     | 2 bájt  |
|  `d`   | dword    | 4 bájt  |
|  `q`   | qword    | 8 bájt  |

Például:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

Ezenkívül az általuk használt címeket is frissítik a művelet méretével.
Ez a frissítés a **direction flag (DF)** értékének megfelelően történik:

- Ha a `DF` törölve van, a címek a művelet méretével _növekednek_.
- Ha a `DF` be van állítva, a címek ugyanennyivel _csökkennek_.

A System V ABI előírja, hogy a direction flaget a függvény belépésekor törölni kell.
Tehát _alapértelmezés szerint a memóriát növekvő címek szerint olvassuk és írjuk_.

A [cld][cld] utasítással törölheted a direction flaget, a [std][std] utasítással pedig beállíthatod:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
A hívó fél a System V ABI szerint elvárja, hogy a `DF` törölve legyen, miután bármely meghívott függvény visszatér.
Ha valaha beállítod a `DF`-et, mindenképp töröld visszatérés (`ret`) előtt.
~~~~

### Lods

Ez az utasítás _olvas_ egy memóriacímről, amelynek címe az `rsi`-ben van, és átmásolja az értéket az `rax`-be.

Az `rsi`-ben lévő értéket a beolvasott bájtok számával frissítjük:

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

Ez az utasítás átmásolja az `rax`-ben lévő értéket, és _beírja_ egy memóriacímre, amelynek címe az `rdi`-ben van.

Az `rdi`-ben lévő értéket a beírt bájtok számával frissítjük:

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

Ez az utasítás _olvas_ egy memóriacímről, amelynek címe az `rsi`-ben van, és az értéket _beírja_ egy memóriacímre, amelynek címe az `rdi`-ben van.
Az `rax`-ben lévő értéket ez az utasítás nem érinti.

Az `rsi` és az `rdi` is frissül az egyik memóriacímről a másikra másolt bájtok számával:

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

Ez az utasítás _olvas_ egy memóriacímről, amelynek címe az `rsi`-ben van, és szintén _olvas_ egy memóriacímről, amelynek címe az `rdi`-ben van.
Ezután összehasonlítja az értékeket, és a `cmp` utasításnak megfelelően frissíti a jelzőbiteket.

Az `rsi` és az `rdi` is frissül a két címről beolvasott bájtok számával:

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

Ez az utasítás összehasonlítja az `rax`-ben lévő értéket azzal az értékkel, amelyet egy memóriacímről _olvas_ be, amelynek címe az `rdi`-ben van.
Ezután a `cmp` utasításnak megfelelően frissíti a jelzőbiteket.

Az `rdi`-ben lévő értéket a beolvasott bájtok számával frissítjük:

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

Ezeken kívül a [rep][rep] utasítás nem érintkezik közvetlenül a memóriával.
Ehelyett előtagként hozzáadható a többi említett utasításhoz, és _megismétli_ azokat.

Ha a `rep` előtagot kapják, a stringutasítások annyiszor ismétlődnek, ahányszor a `rcx`-ben lévő érték mutatja.
Minden ismétlésnél a `rcx`-ben lévő érték `1`-gyel csökken.
Vedd figyelembe, hogy a `rcx`-ben lévő értéket az utasítás használata előtt be kell állítani:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

A `rcx` számlálóként való használatán kívül a `repe` (vagy `repz`) és a `repne` (vagy `repnz`) leállítja a végrehajtást, ha a `zero flag (ZF)` törölve, illetve beállítva van:

| utasítás         | hol használható        | leállhat korábban       |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`, `lods`, `stos` | nem                     |
| `repe`,`repz`    | `cmps`, `scas`         | igen, leáll, ha ZF = 0  |
| `repne`, `repnz` | `cmps`, `scas`         | igen, leáll, ha ZF = 1  |

~~~~exercism/advanced
A modern CPU-kon a `rep movs` és a `rep stos` általában gyors megoldás, amikor nagy blokkokban mozgatunk adatot.
A többi stringutasítás viszont, sőt még a `movs` és a `stos` is `rep` nélkül, általában lassabb egy egyszerű ciklusnál.
