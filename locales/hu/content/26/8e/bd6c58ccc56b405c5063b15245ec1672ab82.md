# A generikusokról

A Go 1.18-ban bevezette a **generikusok** támogatását.
A generikusok lehetővé teszik, hogy olyan függvényeket és adatszerkezeteket írj, amelyek különböző típusokkal működnek, anélkül hogy duplikálnád a kódot.

## Miért hasznosak a generikusok?

A Go-ban a függvények és a típusok általában meghatározott típusokkal működnek, például `int` vagy `string`.
A generikusok előtt két lehetőséged volt több típus támogatására.
Először is írhattál több különböző nevű függvényt, például `SumInts` és `SumFloats`.
Ez a megközelítés duplikált kódot eredményez, amelyet nehéz karbantartani.
Másodszor használhattad az üres `any` interfészt (`interface{}`).
Az üres interfész azonban megszünteti a fordítás idejű típusellenőrzést, és futásidőben típus-állításokat igényel.
A generikusok ezt a problémát a típusbiztonság megteremtésével oldják meg, miközben elkerülik a duplikált kódot.

## Generikus függvények

Úgy definiálhatsz generikus függvényt, hogy a függvénynév után szögletes zárójelben `[...]` **típusparamétereket** adsz.
Íme egy példa egy olyan generikus függvényre, amely megfordított szeletet ad vissza:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

Ebben a példában `T` egy típusparaméter.
A `T`-t felfoghatod egy valódi típus helyőrzőjeként.
A szögletes zárójelek között álló `any` kulcsszó egy **típusmegkötés**.
A megkötés megmondja a fordítónak, milyen típusok engedélyezettek `T` számára.
Itt az `any` azt jelenti, hogy `T` bármilyen típus lehet.

### Generikus függvények hívása

Úgy hívhatsz meg egy generikus függvényt, hogy szögletes zárójelben átadod a tényleges típust.
Ezt a tényleges típust **típusargumentumnak** nevezzük.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

A legtöbb esetben a Go fordító automatikusan felismeri a típust a függvény argumentumaiból.
Ezt a tulajdonságot **típuskövetkeztetésnek** nevezzük.
Típuskövetkeztetéssel nem kell kiírnod a típusargumentumot szögletes zárójelben.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

Ebben a példában a fordító látja, hogy `words` stringekből álló szelet, ezért arra következtet, hogy `T` típusa `string`.

## Típusmegkötések

Minden típusparaméternek megkötéssel kell rendelkeznie.
A megkötés meghatározza, mely típusokat használhatod típusargumentumként.
A megkötés azt is eldönti, milyen műveleteket végezhetsz az adott típus értékein.

### Az `any` megkötés

Az `any` megkötés bármilyen típust engedélyez.
A Go-ban az `any` az üres `interface{}` interfész aliasa.
Mivel az `any` minden típust engedélyez, a függvény csak olyan műveleteket hajthat végre, amelyek minden Go-típuson működnek.
Például ha két `any` értéked van, amelyek szeleteket tárolnak, azokat nem lehet `==` operátorral összehasonlítani, mert a szeleteket sem lehet `==` operátorral összehasonlítani.

### A `comparable` megkötés

A Go biztosít egy beépített `comparable` nevű megkötést.
A `comparable` megkötés minden olyan típust engedélyez, amely támogatja a `==` és `!=` operátorokat.
Az összehasonlítható típusok közé tartoznak a Boolean értékek, a számok, a stringek, a mutatók, a csatornák, valamint az összehasonlítható típusokból álló struktúrák vagy tömbök.

Íme egy példa egy olyan függvényre, amely ellenőrzi, hogy egy szelet tartalmaz-e egy adott elemet:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

Mivel `T` a `comparable` megkötést használja, az `elem == target` kifejezés érvényes.
Ha a `comparable` megkötést `any` megkötésre cseréled, a fordító hibát jelez.

### Egyedi megkötések interfésztípus-halmazokkal

A Go 1.18-tól kezdve az interfészek a metódusok mellett típusok halmazait is definiálhatják.
A függőleges vonal (`|`) karakterrel felsorolhatod az interfészben engedélyezett típusokat.

```go
type Number interface {
    int | int64 | float64
}
```

Most már használhatod a `Number`-t egy függvény megkötéseként:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

Mivel a `Number` összes típusa támogatja a `*` operátort, a Go engedélyezi a `value * 2` kifejezést a függvényen belül.

### A mögöttes típus közelítése `~`

Néha egy primitív típusra épülő egyedi típusdefiníciót hozol létre:

```go
type MyInt int
```

A fent definiált `Number` megkötés csak a pontos `int`, `int64` és `float64` típusokat engedélyezi.
Ha egy `MyInt` értéket adsz át a `Double` függvénynek, a fordító hibát jelez, mert a `MyInt` nem egyezik az `int` típussal.
Ha engedélyezni szeretnéd bármely olyan típust, amelynek a mögöttes típusa `int`, tegyél egy tilde (`~`) jelet a típus elé:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

Most már használhatod a `Double`-t `MyInt` típusú értékekkel.

### A `cmp.Ordered` megkötés

A szabványos könyvtár a `cmp.Ordered` megkötést a [`cmp` csomagban][doc-cmp] biztosítja.
A `cmp.Ordered` megkötés minden olyan típust engedélyez, amely támogatja a `<`, `<=`, `>` és `>=` összehasonlító operátorokat.

## Generikus típusok

Típusparamétereket generikus típusok, például struktúrák definiálására is használhatsz.
Íme egy példa egy generikus `Stack` adatszerkezetre:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

Amikor egy generikus típusú változót deklarálsz, meg kell adnod a típusargumentumot szögletes zárójelben:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

A típuskövetkeztetés csak generikus függvényeknél működik.
Generikus típusú értékek létrehozásakor mindig meg kell adnod a típusargumentumot.

## Mikor használjunk generikusokat?

A generikusok hatékony lehetőséget kínálnak, de nem kell minden problémánál használnod őket.

Generikusokat használj az alábbi helyzetekben:
- Olyan adatszerkezeteket építesz, mint például fák, láncolt listák vagy gyorsítótárak, amelyek bármilyen elemtípussal működnek.
- Olyan segédfüggvényeket írsz, amelyek bármilyen típusú szeleteken vagy mapeken működnek, például szűrés, rendezés vagy keresés céljából.
- Pontosan ugyanarra a megvalósításra van szükséged több típus esetén, és fordítás idejű típusbiztonságot szeretnél.

Ehelyett interfészeket használj az alábbi helyzetekben:
- A viselkedés és a metódusok fontosabbak számodra, mint a mögöttes adattípus.
  Például ha különböző típusú forrásokból (fájlokból, hálózatból, TTY-terminálból) szeretnél adatokat olvasni és feldolgozni, a `func Process[T](src T)` helyett a `func Process(src io.Reader)` függvényt használnád.
- A különböző típusok eltérő metódusmegvalósításokat igényelnek a feladatuk elvégzéséhez.
