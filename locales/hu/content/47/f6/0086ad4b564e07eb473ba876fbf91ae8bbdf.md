# Bevezetés

A függvényekkel már a [Basics][concept-basics] fogalomban találkoztunk, ilyen példákkal:

```R
squareit <- function(x) {
    x * x
}

squareit(3)
#> [1] 9

# shorter form
squareit_short <- function(x) x ^ 2
```

Ha közelebbről megnézzük a `squareit` definícióját, több részt is megkülönböztethetünk benne:

- A függvény egy formális argumentumot fogad: `x`-et.
- Van egy függvénytörzs, rendszerint kapcsos zárójelben `{ }`.
- A létrehozott függvényobjektumot egy `squareit` nevű változóhoz rendeljük hozzá.

Az R-ben a függvény első osztályú objektum, akárcsak a számok és a stringek.
Így a `squareit <- function...` hozzárendelés szintaktikailag pont olyan, mint az `x <- 42`.

## Argumentumok

Az R nem tesz éles különbséget a pozicionális és a kulcsszavas argumentumok között, ellentétben más szkriptnyelvekkel, például a Pythonnal vagy a Juliával.

A függvényhívásokban az értékeket pozicionálisan vagy név szerint is átadhatjuk.
Utóbbi hasznos lehet az összetett, sok argumentumot váró függvényeknél, ahol nehéz megjegyezni az argumentumok sorrendjét.

```R
f <- function(x, y) x / y

# call positionally
f(4, 2)
#> [1] 2

# call by name
f(y = 2, x = 4)
#> [1] 2
```

### Opcionális argumentumok

A függvény definíciójában megadhatunk alapértelmezett argumentumértékeket, de ezeknek az összes alapértelmezés nélküli argumentum után kell szerepelniük.

Ezután eldönthetjük, hogy elfogadjuk-e az alapértelmezést, vagy felülírjuk.

```R
g <- function(x, y = 2) x / y

# default y value
g(6)
#> [1] 3

# explicit y value
g(6, 3)
#> [1] 2
```

### Extra argumentumok

Ha tetszőleges számú további argumentumot szeretnénk fogadni, használjunk `...` (három pontot) a definícióban.
A függvényhívásban átadott extra értékeket vektorrá alakíthatjuk, de olvass tovább, mert mutatunk egy másik módot is ezeknek a „pont argumentumoknak” a használatára (*amelyeket több más nyelvben „varargs” néven ismernek*).

```R
var_f <- function(x, y, ...) {
  print(c(...))
}

var_f(2, 3, "opt1", "opt2")
#> [1] "opt1" "opt2"
```

## A függvény környezete

Korábban azt mondtuk, hogy a formális argumentumok és a függvénytörzs is a függvény komponensei.

Valójában van egy harmadik komponens is: a *környezet*, amelyben a függvény definiálva van.

Ezt az egymásba ágyazott függvények példáján szemléltethetjük:

```R
outer_func <- function(x) {
  inner_func <- function(y) {
    x * y
  }
  
  inner_func(3)
}

outer_func(5)
#> [1] 15
```

A függvényhívás átadja az `x = 5` értéket a külső függvénynek, és ez az érték elérhető annak a függvénytörzsén belül.

A belső függvény a külső függvénytörzs *része*, és hozzáfér az `x` értékéhez.
Másképp fogalmazva, az `x = 5` a belső függvény *környezetében* van.

Technikailag ez [closure][wiki-closure] néven ismert.

A környezet különösen fontos a pont argumentumoknál, mert az így átadott értékek továbbadhatók a függvénytörzsben lévő függvényhívásoknak.
A külső függvénynek nem kell tudnia és nem is kell érdekelnie, mit jelentenek a pont argumentumok.

```R
f_var <- function(x, ...) {
  sum(x, ...)
}

x <- c(1, 2, NA, 6)

# for sum(), na.rm defaults to FALSE
f_var(x)
#> [1] NA

# pass through the na.rm value
f_var(x, na.rm = TRUE)
#> [1] 9
```

Ezt a technikát széles körben használják a Tidyverse könyvtárai, például a [`stringr`][ref-stringr].
A `stringr` számos függvénye felhasználóbarát burkoló az `stringi` és a base R alacsony szintű függvényei körül.

A `str_*()` függvényeknek átadott extra argumentumok egyszerűen továbbkerülnek ezekhez az alacsonyabb szintű függvényekhez.

## Függvények visszatérési értékként

Egy külső függvény definiálhat egy belső függvényt (nevesítettet vagy névtelent, ahogy azt alább leírjuk), és visszatérési értékként használhatja azt.

A visszaadott függvény magában hordozza azt a környezetet, amelyben definiálták.

```R
times_y <- function(x) {
  # anonymous function - see next section
  \(y) x * y
}

f <- times_y(3)
class(f)
#> [1] "function"

f(4)
#> [1] 12
```

## Névtelen függvények

Amikor függvényt definiálunk, a létrejövő függvényobjektumot általában egy változóhoz kötjük:

```R
x <- 2

# function definition captures x from the environment
doubleit_short <- function(y) x * y
```

Így később könnyen használhatjuk a függvényt a szkriptben, de ez a hozzákötés nem szükséges.
Egy rövid, csak egyszer használt függvény hasznos lehet az adott helyzetben.
Névhez kötés nélkül *névtelen függvénynek* nevezzük.

A névtelen függvények használata annyira gyakori, hogy (*az R 4.1.0-s verziója óta*) létezik egy rövidített szintaxis a definiálásukra: a `function` szót cseréljük le egy visszaperjelre `\`.

Erre láttunk példát az előző szakaszban, a visszatérési értékeknél.

## Másolat módosításkor

Az R-ben hozzárendelhetünk értéket egy vektor egyes elemeihez.
Ha vektort adunk át függvényargumentumként, és a visszaadás előtt módosítjuk a függvénytörzsben, akkor egy módosított vektort kapunk.

De mi történt az eredeti vektorral?

```R
f <- function(vec) {
  vec[1] <- 42
  vec
}

vals <- c(1, 3, 4)

# f() returns a modified vector
f(vals)
#> [1] 42  3  4  

# the original vector is unchanged.
vals
#> [1] 1 3 4
```

Az R egy adattudományra tervezett nyelv.
Az adatok összegyűjtése sok időbe és fáradságba kerülhet, és akár elképesztő mennyiségű pénzbe is: *ezért fontos, hogy ne rontsuk el őket!*

Az általános szabály (néhány kivétellel) a *másolat módosításkor*.
Ha egy objektumot (például egy vektort) olyan módon változtatunk meg, ami később problémát okozhatna, az R egy *módosított másolatot* ad vissza, és az eredetit érintetlenül hagyja.

A nagy adatszerkezetek másolása számításigényes lehet, de ez általában a kisebbik rossz, ha az alternatíva az adatok sérülése.
