# Bevezetés

A C nyelvben a **struct** egy összetett típus, amely különböző mezőkből áll.
Minden mezőnek saját típusa és mérete van.

Például ez egy három egész számból álló típust definiál, kettő 4 bájtos és egy 8 bájtos:

```c
struct example {
    int32_t first_four_byte_integer;
    uint32_t second_four_byte_integer;
    uint64_t eight_byte_integer;
};
```

Egy struct tartalmazhat más structokat is:

```c
struct example_2 {
    struct example first;
    struct example second;
};
```

Ha a struct egyik mezője egy tömb, akkor a tömb számára lefoglalt összes bájt a struct része.
Ha azonban a mező csak egy mutató a tömbre, akkor a tömböt máshol kell tárolni:

```c
struct with_array {
    char string[20];
};
// all 20 bytes of string are inside struct with_array

struct with_pointer {
    const char *string;
};
// only the 8-byte pointer to the string is inside struct with_pointer
```

## Igazítás

Egy típus **igazítása** egy nem negatív kettőhatvány (1, 2, 4, 8, ...), amely követelményt ír elő a címére nézve.
Az adott típus minden objektumának olyan címen kell elhelyezkednie, amely az igazításának többszöröse.

Egy primitív típus esetében az igazítás általában megegyezik a méretével, így például egy `int32_t` általában 4 bájtos igazítású.
Ez azt jelenti, hogy az `int32_t`-t 4 bájtos határokra kell elhelyezni.

Egy struct igazítása azonban a mezői közül a legnagyobb igazítás.
Így például a fent definiált `struct example` igazítása 8 bájt lenne, mivel ez a `uint64_t` igazítása.

Ha egy struct mezőjének igazítása kisebb, mint a structé, akkor a mező után kitöltő bájtok szúrhatók be.
Ez biztosítja, hogy a következő mezők és a struct egésze megfeleljen az igazítási követelményeknek.
A gyakorlatban ez azt jelenti, hogy bár ezek a kitöltő bájtok hozzájárulnak a struct méretéhez, a struct értékében nem játszanak szerepet:

```c
struct example_3 {
    char one_byte; // alignment of 1
    int four_byte; // alignment of 4
};
// example_3 has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one_byte'
// 3 padding bytes (with undefined value)
// 4 bytes for field 'four_byte'
```

Vegyük észre, hogy a fent definiált structban a 'one_byte' mező igazítása 1, és bármilyen címre elhelyezhető.
Mivel a 'four_byte' mező igazítása 4, a structban a mezőknek is tiszteletben kell tartaniuk a 4 bájtos határokat.
Ez azt jelenti, hogy a struct bármely két mezője között a bájtok számának 4 többszörösének kell lennie.
Mivel a 'one_byte' csak 1 bájtot foglal el, ezért 3 kitöltő bájtot szúrunk be utána, hogy megfeleljen ennek a határnak.

A szomszédos mezőket lehetőség szerint csoportosítjuk, hogy minimalizáljuk a szükséges kitöltő bájtok számát:

```c
struct two_padding {
    char one; // alignment of 1
    char two; // alignment of 1
    int three; // alignment of 4
};
// struct two_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 byte for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
```

Ennek a csoportosításnak is tiszteletben kell tartania az egyes mezők igazítását:

```c
struct one_padding {
    char one; // alignment of 1
    int16_t two; // alignment of 2
    int three; // alignment of 4
};
// struct one_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 padding byte
// 2 bytes for field 'two'
// 4 bytes for field 'three'
// Since 'two' has alignment of 2, it must be placed in a 2-byte boundary
// So, there must be 1 padding byte between 'one' and 'two'
```

Ez azt jelenti, hogy a mezők sorrendjének megváltoztatása egy structban néha a méretének különbségéhez vezethet:

```c
struct example_4 {
    int64_t one;
    short two;
    int32_t three;
};
// example_4 has one 8-byte field, one 4-byte field and one 2-byte field
// it has an alignment of 8 and occupies 16 bytes in space:
// 8 bytes for field 'one'
// 2 bytes for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
// two' and 'three' are adjacent and can be grouped to sum up 8 bytes with only 2 bytes of padding

struct example_5 {
    short one;
    int64_t two;
    int32_t three;
};
// example_5 also has one 8-byte field, one 4-byte field and one 2-byte field, in different positions
// it also has an alignment of 8, however, it occupies 24 bytes in space:
// 2 bytes for field 'one'
// 6 bytes for padding
// 8 bytes for field 'two'
// 4 bytes for field 'three'
// 4 bytes for padding
// 'one' can't be grouped with 'two' because their sum would be higher than the struct's alignment
// 'two' and 'three' also can't be grouped, for the same reason
// so padding bytes must be inserted in full after each field with less than 8 bytes in alignment
```

Vegyük észre, hogy egy tömb igazítása megegyezik a mögöttes típusának igazításával:

```c
struct array_example {
    char string[10]; // alignment of 1
};
// array_example has alignment of 1 (it can be placed at any address)
// it occupies 10 bytes in space, one for each char in 'string'
```

Egy tömb elemei ugyanúgy csoportosíthatók, mintha nem lennének egy tömb részei:

```c
struct group_array {
    int16_t arr[3];
    int8_t one_byte;
    int32_t four_byte;
};
// group_array has alignment of 4 because this is the alignment of 'four_byte'
// it occupies 12 bytes in space:
// 4 bytes for arr[0] and arr[1]
// 2 bytes for arr[2]
// 1 byte for 'one_byte'
// 1 padding byte (arr[2] is grouped with 'one_byte')
// 4 bytes for 'four_byte'
```

Fontos számításba venni az esetleges kitöltő bájtokat, amikor assemblyben érünk el egy structot.

## Hívási konvenció

Általában az értékeket a függvényeknek a várakozásoknak megfelelően adjuk át, és a függvények ugyanígy adják vissza:

- Az egész szám értékek, beleértve a memóriacímeket és az enumokat, általános célú regiszterekben (GPR) adódnak át.
- A lebegőpontos értékek `xmm` regiszterekben adódnak át.

A structok azonban különleges esetet jelentenek.
Ökölszabályként a struct összes mezője szomszédos helyet foglal el a memóriában, és lehetőség szerint egyetlen regiszterbe kell őket helyezni:

```c
struct single_type {
    int16_t first;
    int16_t second;
    int16_t third;
    int16_t fourth;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'first' is passed on the lowest 2 bytes
// each subsequent field is passed in the following 2 bytes
```

Ha egy structnak vannak egész értékű mezői és lebegőpontos értékű mezői is, akkor a structban minden egymást követő 8 bájtot külön kell osztályozni:

```c
struct mixed_types {
    double first;
    int second;
    int third;
};
// this struct occupies 16 bytes
// the field 'first' is passed in the first 8 bytes of a xmm register
// the fields 'second' and 'third' are passed in the same GPR register:
// the field 'second' is passed on the lowest 4 bytes
// the field 'third' is passed in the next 4 bytes
```

Ha egészek és lebegőpontos értékek ugyanabban a 8 bájtban vannak, a típus egész, és a teljes 8 bájt (beleértve a lebegőpontos értéket is) egy GPR-be kerül:

```c
struct mixed_types {
    int32_t integer;
    float floating_point;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'integer' is passed on the lowest 4 bytes
// the field 'floating_point' is passed on the next 4 bytes
```

~~~~exercism/caution
Amikor lebegőpontosból egésszé alakítasz `cvtss2si` vagy `cvtsd2si` használatával, az megváltoztatja a mögöttes bájtok elrendezését.

A `movd` (32 bites értékekhez) és a `movq` (64 bites értékekhez) használatával nyers bájtokat mozgathatsz egy `xmm` regiszterből egy GPR-be anélkül, hogy megváltoztatnád a bitreprezentációt.
~~~~

A 16 bájtnál nagyobb méretű structokat azonban általában a memóriában helyezik el, függetlenül az egyes 8 bájtok típusától:

```c
struct big_struct {
    uint8_t first;
    double second;
    int64_t third;
};
// this struct occupies 24 bytes, including 7 padding bytes between 'first' and 'second'
// it is entirely passed in memory
```

Amikor egy structot argumentumként adunk át egy függvénynek, annyi regisztert használ, amennyi szükséges.
Ha a memóriában helyezkedik el, akkor helyette a vermet használjuk.

Hasonló szabályok érvényesek a függvényből visszaadott structokra.
Általában először a `rax` és `rdx` regiszterekben adják vissza (ha egész értékű), vagy az `xmm0` és `xmm1` regiszterekben (ha lebegőpontos értékű).
Ha azonban a memóriában helyezkedik el, a hívónak helyet kell fenntartania számára, és a memóriahely címét implicit első argumentumként kell átadnia a függvénynek (a `rdi` regiszterben).
A függvény ezután eltárolja a structot ezen a helyen, és visszaadja annak címét a `rax` regiszterben.
