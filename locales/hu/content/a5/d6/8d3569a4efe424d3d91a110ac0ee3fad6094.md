# Bevezetés

A legtöbb szekvenciaszó, amellyel eddig találkoztál, *új* szekvenciát ad
vissza, és nem nyúl a bemenetéhez: `suffix`, `reverse`, `map` és így
tovább. A tömbök és a vektorok azonban támogatják a **helyben történő
módosítást** is, és mindkettőre szükség lehet, amikor időben változó
állapotot szeretnél rögzíteni.

## A módosítható szekvenciák két fajtája

- A **tömbök** (`{ … }`) hossza rögzített. A `<array> ( n elt --
  array )` (in [`arrays`n`n` hosszúságú
  tömböt épít, amelyet `elt` másolataival tölt fel.
- A **vektorok** (`V{ … }`) nőnek és zsugorodnak. Friss, üres vektorhoz
  használd a `V{ } clone` szót; a `<vector> ( n -- vector )` (a
  [`vectors`][vectors] szótárban) előre lefoglalja `n` elem
  kapacitását.

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## Egy pozíció módosítása

Ez a kettő mindkét fajta szekvencián működik: mindkettő az index után
várja a szekvenciát:

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

A `set-nth` hozzárendel, a `change-nth` pedig egy quotation
segítségével módosítja az `n` pozícióban lévő elemet. Ez a két
[`sequences`][sequences] szó semmit nem hagy a vermen: a módosítás maga
a hatás.

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## Növekedés és zsugorodás

Ez a három csak vektorokon értelmezhető, hiszen a tömbök hossza nem
változtatható:

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## Vektorból tömb

Amikor felépítettél egy vektort, és egy rögzített hosszúságú tömböt
szeretnél visszaadni, a `>array ( seq -- array )` (az
[`arrays`][arrays] szótárban) egy új tömböt ad vissza ugyanazokkal az
elemekkel:

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`: készíts pillanatképet

A módosítás helyben változtatja meg a szekvenciát. Ha egy hívó átad
neked egy szekvenciát, és te épp meg akarod változtatni, a `clone` (a
[`kernel`][kernel] szótárban) egy friss, független másolatot ad, így a
hívó által látott szekvencia nem változik meg alatta:

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

Ugyanez az óvatosság érvényes a `V{ }` és más üres literálok esetében
is. Egyes nyelvekben a `[]` vagy a `vec![]` minden kiértékeléskor egy
friss tárolót hoz létre. Factorban a forráskódban leírt `V{ }` literál
*egyetlen* objektum, amelyet minden őt megemlítő hívási hely megoszt.
Ha közvetlenül `push`-olsz a `V{ }`-ra, a következő hívás a maradékot
látja. A `V{ } clone` hozza létre azt a friss másolatot, amit szinte
mindig szeretnél.
