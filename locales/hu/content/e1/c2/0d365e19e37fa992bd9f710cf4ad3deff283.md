# Bevezetés

A TypeScript a JavaScript, kiegészítve a típusok szintaxisával, ami erősen típusos programozási nyelvvé teszi. Támogatja az objektumorientált, imperatív és deklaratív (például funkcionális programozási) stílust, és minden méretben jobb toolingot nyújt.

Mivel [nem tanulhatsz meg TypeScriptet anélkül, hogy JavaScriptet is megtanulnál][handbook-js-or-ts], ebben a kurzusban néhány tartalom a JavaScript-fogalmak tanítására összpontosít, más fogalmak pedig kizárólag a TypeScript saját funkcióira.

## (Újra)értékadás

Néhány alapvető módon rendelhetsz értéket nevekhez a TypeScriptben: változókkal vagy konstansokkal.
Az Exercismen a változókat mindig [camelCase][wiki-camel-case] írásmóddal írjuk, a konstansokat pedig [SCREAMING_SNAKE_CASE][wiki-snake-case] írásmóddal.
Nincs hivatalos útmutató, amit követni kellene, és a különböző cégeknek és szervezeteknek más-más stílusútmutatójuk van.
_A változókat nyugodtan írhatod úgy, ahogy neked tetszik_.
Ha viszont úgy írod őket, ahogy a feladatok elő vannak készítve, az az előnye, hogy a webes felületen és a legtöbb IDE-ben másképp lesznek kiemelve.

A TypeScriptben a változókat a [`const`][mdn-const], a [`let`][mdn-let] vagy a [`var`][mdn-var] kulcsszóval definiálhatod.

A `let` vagy `var` használatakor egy változó az élettartama során különböző értékekre hivatkozhat.
Például a `myFirstVariable` sokszor definiálható és újradefiniálható az `=` értékadó operátorral:

```typescript
let myFirstVariable = 1
myFirstVariable = 0
myFirstVariable = 42
```

A `let`-tel és a `var`-ral ellentétben a `const`-tal definiált változóknak csak egyszer adhatsz értéket.
Így definiálhatsz konstansokat a TypeScriptben.

```typescript
const MY_FIRST_CONSTANT = 10

// Can not be re-assigned.
MY_FIRST_CONSTANT = 20
// => TypeError: Assignment to constant variable.
```

Mivel a TypeScript ezt statikusan felismeri, a TypeScript-fordító is hibát jelez:

```typescript
// ^? Cannot assign to 'MY_FIRST_CONSTANT' because it is a constant.(2588)
```

Ez azt jelenti, hogy nem kell futtatnod a kódot ahhoz, hogy felismerd a `TypeError`-t.

## Típuskövetkeztetés

Anélkül, hogy túl mélyen beleásnánk magunkat a [típuskövetkeztetés][handbook-type-inference] témájába, tudnod kell, hogy egy értéket kapott változónak általában van következtetett típusa, még típusannotáció nélkül is.

```typescript
const MY_FIRST_CONSTANT = 10
// ^? const MY_FIRST_CONSTANT: number
```

Ezt a típust aztán a kód egészében érvényesíti a fordító.
Ez azt is jelenti, hogy míg a következő kód érvényes JavaScript:

```javascript
let myFirstVariable = 1
myFirstVariable = 'Some string'
```

TypeScriptben viszont hibát jelez:

```typescript
let myFirstVariable = 1
myFirstVariable = 'Some string'
// ^? Type 'string' is not assignable to type 'number'.(2322)
```

Ez a funkció típusbiztonságot garantál akkor is, ha nem használsz típusannotációkat.

## Függvénydeklarációk

A TypeScriptben a funkcióegységeket _függvényekbe_ zárjuk, és ha összetartoznak, általában ugyanabban a fájlban csoportosítjuk őket.
Ezek a függvények paramétereket (argumentumokat) fogadhatnak, és a `return` kulcsszóval _adhatnak vissza_ értéket.
A függvényeket a `()` szintaxissal hívod meg.

```typescript
function add(num1: number, num2: number): number {
  return num1 + num2
}

add(1, 3)
// => 4
```

A függvényparamétereket általában típussal érdemes annotálni: először egy kettőspont (`:`), majd a típus következik.
A függvény visszatérési értékét a paraméterlista bezárása után annotálhatod, a kettőspont (`:`) és utána a típus megadásával.

<!--prettier-ignore -->
~~~~exercism/note
💡 A TypeScriptben _sokféleképpen_ deklarálhatsz függvényt.
Ezek a módok máshogy néznek ki, mint a `function` kulcsszó használata.
A kurzus igyekszik fokozatosan bevezetni őket, de ha már ismered őket, nyugodtan használhatod bármelyiket.
A legtöbb esetben az egyik vagy a másik használata nem jobb vagy rosszabb.
~~~~

## Típusannotációk

Ahogy az `add` függvénydeklarációjában is látszik, a paramétereknek explicit típusannotációja van: `: number`.
A változódeklarációk, az osztálytulajdonságok, a függvénydeklarációk és még sok más mind támogatja a típusannotációkat.

Mind az explicit típusannotációt, mind a következtetett típusokat számon kéri a típusellenőrző.

```typescript
add('foo', 3)
// ^? Argument of type 'string' is not assignable to parameter of type 'number'.(2345)
```

## Elérhetővé tétel más fájlok számára

Ahhoz, hogy egy `function`, egy konstans vagy egy változó _más fájlokban_ is elérhető legyen, [exportálni][mdn-export] kell a `export` kulcsszóval.
Egy másik fájl ezeket aztán az `import` kulcsszóval [importálhatja][mdn-import].
Ezt modulrendszernek is nevezik.
Remek példa erre, hogyan működik az összes teszt.
Minden feladathoz tartozik legalább egy fájl, például `lasagna.ts`, amely az _implementációt_ tartalmazza.
Ezen kívül van legalább egy másik fájl is, például `lasagna.test.ts`, amely a _teszteket_ tartalmazza.
Ez a fájl _importálja_ a nyilvános (azaz exportált) entitásokat, hogy tesztelje az implementációt:

```typescript
// file.ts
export const MY_VALUE = 10

export function add(num1, num2) {
  return num1 + num2
}

// file.test.ts
import { MY_VALUE, add } from './file.js'

add(MY_VALUE, 5)
// => 15
```
