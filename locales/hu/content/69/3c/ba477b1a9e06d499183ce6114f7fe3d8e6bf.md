# Névjegy

A `String` egyedi karakterei ugyanazzal az indexeléssel érhetők el, amit a tömböknél is használunk.
A stringeknél használt [indexek][string-indices] azonban _nem_ egész számok, és nem lehet velük közvetlenül dolgozni.
Ehelyett valamilyen más ismert index alapján kell kiszámítani őket, például a `startIndex`-ből, amely egy nem üres string első karakterének helyére mutat, a [`String`][string-docs] és [`NSString`][nsstring-docs] könyvtárakban elérhető metódusokkal (ha a `Foundation` modul be van importálva, a Swift stringjei hozzáférnek az NSString összes tulajdonságához és metódusához).

Például adott a következő string:

```swift
let csv = "apple,pear,peach,orange,cherry,lime,goosberry"
```

Nem írhatjuk azt, hogy `csv[21]`, hogy megkapjuk az „orange” szó „g” betűjét; ehelyett egy `String.Index` típusú értéket kell kiszámítanunk, és azt az indexet kell megadnunk.
Jegyezd meg, hogy ezeket az indexeket nem arra szánták, hogy önmagukban ember számára értelmezhetők legyenek.
Ezek az úgynevezett _opaque indexek_, hiszen az embernek nem kell tudnia, mi van bennük.

```swift
let index = csv.index(csv.startIndex, offsetBy: 21)
csv[index]
// "g"
print(index)
// prints Index(_rawBits: 1376513)
```

Jegyezd meg azonban, hogy ha az eltolás nem érvényes indexre mutat, azaz ha a `startIndex` előtti vagy az `endIndex` utáni indexet adná vissza, a művelet hibát vált ki, és a program összeomlik.
Ennek elkerülésére megadhatunk egy korlátozó indexet.
Ez egy opcionális indexet ad vissza, és egyébként érvénytelen indexek esetén nil-t ad vissza.

```swift
let tooFar = csv.index(csv.startIndex, offsetBy: 200)
// error: Execution was interrupted, reason: EXC_BAD_INSTRUCTION (code=EXC_I386_INVOP, subcode=0x0).
let tooFarButSafe = csv.index(csv.startIndex, offsetBy: 200, limitedBy: csv.endIndex)
// nil
```

Ráadásul az indexek nem oszthatók meg a stringek között.
Ha például a fent kiszámított, az „orange” „g” betűjére mutató `index`-et használjuk a `fam = "This is my family: 👨‍👩‍👦‍👦, this is our dog: 🐶, this is our cat: 🐱!"` string indexelésére, azaz `fam[index]`, a program összeomlik.

Mindennek sok oka van, de lényegében mindegyik arra vezethető vissza, hogy „a Unicode bonyolult”.

Általánosságban, ha az egyes karakterekhez véletlenszerű hozzáférést szeretnél, valószínűleg más adatszerkezetet érdemes használnod, például az `Array<Character>`-t.

## Néhány hasznos metódus

A Swiftben a `first` és a `last` metódussal kérheted le egy string első és utolsó karakterét.
Ezek a metódusok opcionális karaktert adnak vissza, tehát ha a string üres, nil-t adnak vissza.

```swift
let str = "Hello, world!"
print(str.first) // Prints Optional("H")
print(str.last)  // Prints Optional("!")
```

A `prefix` és a `suffix` metódussal egy string részstringjét is megkaphatod.
Ezek a metódusok egy egész számot várnak argumentumként, és a string első vagy utolsó n karakterét tartalmazó részstringet adnak vissza.

```swift
let str = "Hello, world!"
print(str.prefix(5)) // Prints "Hello"
print(str.suffix(6)) // Prints "world!"
```

## Mélyelemzés: Unicode indexelés

~~~~exercism/advanced

A [Unicode][unicode] egy szabvány a szöveg kódolására; rengeteg karaktert tartalmaz sok különböző nyelvből és írásrendszerből.
Az ASCII szuperhalmaza, ami azt jelenti, hogy minden ASCII-karakter egyben Unicode-karakter is.
A Unicode változó hosszúságú kódolás, ami azt jelenti, hogy egyes karakterek több bájtot foglalnak el, mint mások.
Hogy ez miért fontos, azt a következő szakaszban fejtjük ki.

Ahhoz, hogy a problémát egyáltalán lássuk, más nyelvekhez kell fordulnunk (nem az angolhoz). Vegyük például a német „ü” karaktert (figyeld meg, hogy itt a kétbájtos változatot használjuk; létezik egybájtos verzió is).
Első pillantásra egyetlen karakternek tűnhet, valójában viszont két karakter: „u” és „¨”. Ha tehát kiírnád az „ü” string hosszát, az olyan nyelvekben, mint a Python, 2 lenne.
Mi azonban felhasználóként vagy programozóként egyetlen karakternek mondanánk, és a Swift valóban egyetért velünk.
De miért teszi ezt a Swift, míg a Python nem?
A válasz az, hogy a Swift más módon reprezentálja a stringeket, mint a Python.
A Pythonban a stringek bájtok sorozataként vannak reprezentálva, ami azt jelenti, hogy egy string hossza a memóriában elfoglalt bájtok száma.
A Swiftben a stringek karakterek sorozataként vannak reprezentálva, ami azt jelenti, hogy egy string hossza a benne lévő karakterek száma.
Ez nagyon fontos különbség, mert azt jelenti, hogy a Swiftben egy string hossza nem feltétlenül egyezik meg a memóriában elfoglalt bájtok számával.
Ez pedig az oka annak, hogy nem indexelhetünk egész számokkal a stringekbe.
