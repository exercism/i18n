# Utasítások

Egy autóipari alkatrészgyár gyártócsarnokának adatrendszeréhez írsz kódot.
Motor- és alvázalkatrészek haladnak át egy sor megmunkáló állomáson.
Minden állomás mérési adatokat állít elő, amelyeket össze kell vonni, össze kell hasonlítani, kalibrálni vagy normalizálni kell, mielőtt a következő szakasz elindul.
Az itt megvalósított függvények közül egy-egy tartozik minden állomáshoz.

~~~~exercism/note
Ebben a feladatban a számításokat SIMD utasításokkal kell elvégezni, nem skaláris műveletekkel.
~~~~

## 1. Két sor hozamának összevonása

A gyártócsarnokban két párhuzamos szerelősor működik.
Minden műszak végén mindkét sor jelenti a hozamát 4 alkatrészrekeszre, egyszeres pontosságú számokként.
A művezető irányítópultja rekeszenként mutatja az összevont hozamot, ezért a két jelentést rekeszenként összeadjuk.
Mindhárom puffert a jelentési rendszer kezeli, és mindig 16 bájtos határra igazítottak.

Definiálj egy `sum_yields` függvényt, amely a `line_a` és `line_b` rekeszenkénti hozamait kapva a rekeszenkénti összeget a `result`-ba írja.
Az argumentumok sorrendben:

1. `line_a`: 16 bájtos határra igazított memóriacím, amely 4 darab 32 bites lebegőpontos számot tartalmaz
2. `line_b`: 16 bájtos határra igazított memóriacím, amely 4 darab 32 bites lebegőpontos számot tartalmaz
3. `result`: 16 bájtos határra igazított memóriacím, ahová a függvény 4 darab 32 bites lebegőpontos számot ír

A függvénynek nincs visszatérési értéke, helyette az eredmény a kapott pufferben (`result`) tárolódik:

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. Skálázott eltérés kiszámítása

A műveletek között egy mintavevő állomás megméri a megmunkált alkatrészeket, és összehasonlítja őket a célméretekkel.
A mért értékek egy precíziós mérőműszerből érkeznek egy mindig 16 bájtos határra igazított pufferbe.
A célértékek a munkalapcsomagból származnak, amelynél nincs igazítási garancia.
Az eltérést megszorozzuk egy tengelyenkénti érzékenységi tényezővel, mielőtt eljut a következő szakasz tűrésellenőrzőjéhez.
Ebben a szakaszban a következő ellenőrző közvetlenül egy SIMD regiszterből olvassa az eltérést, nem a memóriából.

Definiálj egy `scaled_deviation` függvényt, amely a `measured`, a `target` és egy `sensitivity` alapján a skálázott eltérést a `result`-ba írja.
Az argumentumok sorrendben:

1. `measured`: 16 bájtos határra igazított memóriacím, amely 2 darab 64 bites lebegőpontos számot tartalmaz
2. `target`: memóriacím, amely 2 darab 64 bites lebegőpontos számot tartalmaz (az igazítás nem garantált)
3. `sensitivity`: memóriacím, amely 2 darab 64 bites lebegőpontos számot tartalmaz (az igazítás nem garantált)
4. `result`: memóriacím egy pufferhez, ahová a függvény 2 darab 64 bites lebegőpontos számot ír (az igazítás nem garantált)

A skálázott eltérés sávonként `(measured - target) * sensitivity`.

A függvénynek nincs visszatérési értéke, helyette az eredmény a kapott pufferben (`result`) tárolódik két 64 bites lebegőpontos számként.

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. Egy köteg kalibrálása

Mielőtt az alkatrészek bekerülnek a végső ellenőrző állomásra, egy 4 alkatrészből álló köteg méretadatait kétszeres pontosságúra skálázzuk át, és korrigáljuk az ismert hőmérsékleti eltolódásra.

A 4 nyers mérési érték egyszeres pontosságú számként érkezik.
Minden 2 mérési értékből álló sorra a kalibrálás kiszámítja a `reference / (raw - offset)` értéket, majd megszorozza ezt az eredményt egy állandó `0.5`-ös átváltási tényezővel.

Figyeld meg, hogy a reference és az offset ugyanaz a köteg mindkét sorában.
Az átváltási tényező minden kalibrálásnál ugyanaz, ezért ahelyett, hogy argumentumként kapnád meg, egy 16 bájtos tömörített konstansként kell deklarálnod a memóriában.

Definiálj egy `calibrate_batch` függvényt, amely egy `raw` köteget, egy `reference`-et, egy `offset`-et és egy `result` puffert kapva a kalibrált értékeket a `result`-ba írja.
Az argumentumok sorrendben:

1. `raw`: memóriacím, amely 4 darab 32 bites lebegőpontos számot tartalmaz (az igazítás nem garantált)
2. `reference`: 16 bájtos határra igazított memóriacím, amely 2 darab 64 bites lebegőpontos számot tartalmaz
3. `offset`: 16 bájtos határra igazított memóriacím, amely 2 darab 64 bites lebegőpontos számot tartalmaz
4. `result`: 16 bájtos határra igazított memóriacím, ahová a függvény 4 darab 64 bites lebegőpontos számot ír (összesen 32 bájt)

A függvénynek a köteg két sorára a következő lépéseket kell elvégeznie:

1. A sor 2 egyszeres pontosságú nyers értékét kétszeres pontosságúra alakítja.
2. Az átalakított párból kivonja az `offset`-et.
3. A `reference`-et elosztja az eredménnyel.
4. Sávonként megszorozza mindegyik 64 bites lebegőpontos számot a rögzített `0.5`-ös átváltási tényezővel.
5. A 2 darab 64 bites lebegőpontos számot a `result` megfelelő 16 bájtjára menti.

A függvénynek nincs visszatérési értéke, helyette az eredmény a kapott pufferben (`result`) tárolódik:

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. Pontszámok normalizálása a sor mentén

A sor végén minden alkatrésznek van egy minőségi pontszáma, amelyet normalizálni kell, mielőtt jelentik.
Minden pontszámot megszorzunk a saját, alkatrészenkénti erősítésével, majd elosztunk egy tengelyenkénti gyártási léptékkel.
A gains puffer alkatrészenként egy-egy erősítést tartalmaz.

A gyártási lépték az egész futásra ugyanaz, és egy olyan memóriacímben adjuk át, amely két 64 bites lebegőpontos számot tartalmaz.
A pontszámok **helyben** frissülnek: ugyanaz a puffer, amely a nyers pontszámokat tartalmazta, most a normalizált pontszámokat tartalmazza.

Definiálj egy `normalize_scores` függvényt, amely egy `scores` tömb, egy `gains` tömb, egy `scale` és egy `n` darabszám alapján helyben normalizálja a pontszámokat.
Az argumentumok sorrendben:

1. `scores`: 16 bájtos határra igazított memóriacím, amely `n` darab 64 bites lebegőpontos számot tartalmaz (helyben módosul)
2. `gains`: 16 bájtos határra igazított memóriacím, amely `n` darab 64 bites lebegőpontos számot tartalmaz
3. `scale`: 16 bájtos határra igazított memóriacím, amely 2 darab 64 bites lebegőpontos számot tartalmaz
4. `n`: egy 64 bites pozitív páros egész szám (minimum `2`), a normalizálandó pontszámok száma

A scale két sávja minden pár két elemére vonatkozik.
Az első sáv minden pár első elemét skálázza (a páros pozíciójú sávokat), a második sáv pedig a másodikat (a páratlan pozíciójú sávokat).
Minden pontszámot megszorzunk a hozzá tartozó erősítéssel, majd elosztunk a megfelelő scale-sávval: `score * gain / scale_lane`.

A függvénynek nincs visszatérési értéke, helyette az eredmény a bemeneti pufferben (`scores`) tárolódik, a normalizált `score` megfelelő pozíciójában:

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
