# Bevezetés

## Rekordok

A [rekordok][records] olyan adatszerkezetek, amelyek címkékkel csoportosítják az összetartozó információkat.
Hasonlítanak a JavaScript vagy Java objektumaihoz, illetve a C vagy Rust structjaihoz, de néhány lényeges különbség van köztük.

### Rekordok létrehozása

A rekordokat kapcsos zárójelekkel [hozzuk létre][create], az elemeiket pedig vessző választja el.

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

A rekord típusát is hasonló szintaxissal definiáljuk, azzal a különbséggel, hogy az egyenlőségjeleket (`=`) kettőspontok (`:`) helyettesítik.

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

Ezeket a típusdefiníciókat ismételgetni körülményes, ezért gyakori megoldás, hogy egy [típusalias][record-types] segítségével megosztjuk a definíciót.

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

A típusalias emellett automatikusan biztosít egy konstruktorfüggvényt is a rekordhoz.
Ez néha meglepő, hiszen az Elmben a függvényeknek kisbetűvel kell kezdődniük, a típuskonstruktorok viszont ez alól kivételt képeznek.

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

### A rekordok mezőinek elérése

A legfőbb módja annak, hogy [hozzáférjünk egy rekordpéldány egyik mezőértékéhez][access], a pontjelölés használata, például így: `firefly.creator`.
Az Elm fordító emellett támogat olyan speciális elérési függvényeket is, amelyek ponttal (`.`) kezdődnek, például a `.creator`, és minden olyan rekordon működnek, amelyben van ilyen nevű mező.
Ez a második kivétel az alól a szabály alól, hogy a függvényeknek kisbetűvel kell kezdődniük.
Valójában a felhasználó által definiált függvényeknek kisbetűvel kell kezdeniük, de az imént megismert két példát a fordító generálja, nem a programozó.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

A rekordokat kötéseken belül _destrukturálhatjuk_ is a [rekordok mintaillesztésével][pattern-matching].
A destrukturálás bármely olyan rekordon működik, amelyben megvannak a szóban forgó nevű mezők.

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

### Rekordok frissítése

A rekordok változtathatatlanok, ahogy az Elmben minden, így ha egyszer definiáltunk egy rekordot, a mezőértékei soha nem változhatnak meg.
Létezik egy [speciális szintaxis, amellyel egy meglévő rekord másolatát hozhatjuk létre úgy, hogy egy vagy több mezőjét megváltoztatjuk][update].
Ez a szintaxis a pipe (`|`) szimbólumot használja, hogy megkülönböztesse az eredeti rekordot a megváltozó mezőktől, például így: `{ oldRecord | field1 = newValue }`.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

### Rekordok összehasonlítása

Az Elm [szerkezeti egyenlőséget][equality] használ, ami azt jelenti, hogy ugyanazon rekord két példánya azonos értékekkel egyenlő.

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

### Bővíthető rekordok

Az Elm a [szerkezeti típusozást][structural-typing] is támogatja, ami azt jelenti, hogy ha egy függvény olyan rekordot vár, amelyben van x és y mező, akkor bármely olyan rekordon működik, amelyben megvannak ezek a mezők, például kétdimenziós pontokon, háromdimenziós pontokon, űrhajókon stb.
Ezeknek a rekordtípusoknak a definíciójában szerepel egy pipe (`|`), például `{ a | x : Float, y : Float }`, és az Elm terminológiájában „bővíthető rekordoknak” nevezzük őket.
Ügyelj a különbségre egy típusdefinícióban szereplő pipe (`|`) között, amely egy bővíthető rekord definíciója (`{ a | x : Int }`), és egy tényleges rekordpéldányban szereplő pipe (`|`) között, amely azt jelenti, hogy a rekord néhány mezőjét frissítjük.

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
