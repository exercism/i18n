# Bevezetés

Gleamben a `case` kifejezéssel feltételesen hajthatsz végre kódot. A `case` kifejezéssel egy értéket egy vagy több _mintával_ vethetsz össze. Ilyen minta például a _literálminta_, amely egy értéket egy literál értékkel vet össze (például `1` vagy `"hello"`).

A `case` kifejezéseket a `case` kulcsszóval írod le:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    1 -> "One"
  }
}
```

Bár ez más nyelvek `switch` utasításaira hasonlíthat, a mintaillesztés akkor mutatja meg igazán az erejét, amikor más mintákat is használsz. Ilyen minta a _változóminta_ is, amellyel egy értéket rendelhetsz egy változóhoz. Ebben a példában az `i` változó a `number` értékét kapja, ha az nem `0`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i -> "Non zero"
  }
}
```

Bizonyos esetekben további feltételt szeretnél adni egy mintához. Ezt _őr_-nek (vagyis _őrfeltétel_-nek) nevezik, amelyet az `if` kulcsszóval adhatsz meg:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
  }
}
```

Teljesítményi okokból az őrökben csak alapvető matematikai és Boolean-operátorok engedélyezettek, más függvényeket nem használhatsz bennük.

A fenti példában nem minden lehetséges bemenethez tartozik illeszkedő minta. A fordító ezt észleli, és hibát jelez. Ezt _kimerítő ellenőrzésnek_ nevezik. A figyelmeztetés elkerüléséhez minden esetet kezelned kell. Erre az _eldobóminta_ használható, amely bármely értékre illeszkedik:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
    _ -> "Positive number"
  }
}

// No compiler error
```

A `case` kifejezések felülről lefelé haladva minden mintával összevetik az értéket, amíg nem találnak egy illeszkedő mintát, és végre nem hajtják a hozzá tartozó logikát. A minták sorrendje számít!
