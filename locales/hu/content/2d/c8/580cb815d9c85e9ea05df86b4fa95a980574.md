# Az alapokról

A Kotlin statikusan típusos nyelv, amelyet úgy terveztek, hogy teljesen együttműködjön a Javával.

A Kotlin a következőkben tér el a Javától:

- letisztultabb, tömörebb szintaxissal rendelkezik;
- magában foglalja a funkcionális nyelvek számos jellemzőjét;
- kiterjedten támogatja a nullázható értékeket.

## Változók

Mivel a Kotlin statikusan típusos, fordítási időben _ismerni_ kell minden érték típusát.

A Kotlin [típuskövetkeztetése][inference] viszont nagyon erős, ezért a típus _megadása_ gyakran elhagyható.

Egy változót kétféleképpen deklarálhatsz.

1. A `val` megváltoztathatatlan változót hoz létre, és ha megpróbálod megváltoztatni, az fordítási hibát okoz.

```kotlin
val x = 42  // => 42
x = 43      // => 'val' cannot be reasssigned
```

2. A `var` módosítható változót hoz létre.

```Kotlin
var x = 42  // => 42
x = 43      // => 43
```

Mivel a megváltoztathatatlan változók a hibák egy gyakori fajtáját küszöbölik ki, érdemes minél gyakrabban a `val`-t használni.

Ráadásul a `var` sem változtathatja meg a típusát:

```kotlin
var x = 42
x = "foobar" // => Type mismatch: inferred type is String but Int was expected
```

Hogy kevesebb vizuális zavaró tényező legyen, ebben a tantervben többnyire elhagyjuk az explicit típusokat.
Ennek ellenére érdemes legalább a következőknél megadni a típust:

- nyilvános API-k
- függvényszignatúrák
- ahol dokumentációra van szükség

Egyes cégek és szervezetek szigorú típusbiztonságot írnak elő, és nem engedik meg a típuskövetkeztetést, míg mások csak az „egyszerű” típusokra korlátozzák, megint mások pedig teljesen elfogadják.

```kotlin
val x: Int = 42  // => 42
```

Általában a változók és a függvények nevét `camelCase` stílusban érdemes írni, nem `snake_case` stílusban

## Függvények

A függvényt a `fun` kulcsszóval deklarálod.
A Java-val ellentétben a függvényeknek nem kell egy osztály részének lenniük.

```Kotlin
fun hello(): String {
    return "Hello, World!"
}

fun add(x: Int, y: Int): Int {
    return x + y
}
```

Néhány dolog, amire érdemes figyelni:

- A függvénynév után akkor is kellenek zárójelek `()`, ha a függvény egyetlen argumentumot sem fogad.
- A függvény argumentumainál meg kell adni a típust: itt nincs típuskövetkeztetés (ellentétben a változókkal).
- A függvény törzsét kapcsos zárójelek `{ }` közé írjuk (de erről mindjárt lentebb).
- Ha értéket adsz vissza, a `return` kulcsszó kötelező.
- A sorok végén a pontosvessző `;` elhagyható, és általában el is hagyjuk.
- A `+`, `-`, `*`, `/` aritmetikai operátorok a legtöbb elterjedt nyelvhez hasonlóak.

Az ilyen nagyon egyszerű, „egykifejezéses” függvényekhez azonban van egy rövidített szintaxis:

```Kotlin
// return type is usually omitted for single-expression functions
fun add(x: Int, y: Int) = x + y  
```
A függvényeknek lehetnek alapértelmezett értékkel rendelkező paramétereik. 
Ezeket az értékeket akkor használja, ha a függvény hívásakor elhagyod őket:

```kotlin
fun ping(host: String = "localhost") {
    println("PING --> $host")
}

ping("exercism.io")  // PING --> exercism.io
ping()               // PING --> localhost
```

Az Exercism-ben a függvények általában visszaadnak egy értéket (mert a tesztfuttató így épül fel).
Ha a Kotlint szélesebb körben szeretnéd használni, hasznos lehet tudni, hogy az a függvény, amely nem ad vissza értéket, elhagyhatja a visszatérési típust és a return kulcsszót.

Ilyenkor azt mondjuk róla, hogy a visszatérési típusa `Unit`: ez a Java-ban és több más nyelvben a `void` megfelelője.

## Megjegyzések

Az egysoros megjegyzések `//` jellel kezdődnek, és a sor többi részét a rendszer figyelmen kívül hagyja.

A többsoros megjegyzések `/*` jellel kezdődnek és `*/` jellel végződnek

```Kotlin
fun hello(): String {
    /*
     * Failing to run this program on a new installation 
     * is considered bad luck
    */
    return "Hello, World!" // the compiler pixies are now happy
}
```

Ez ugyanaz, mint a Java-ban.
