# Tesztek

Minden feladat tartalmaz egy tesztfájlt.
A teszteket a `bats` programmal futtathatod.
```bash
bats test-hello-world.bats
```

A `bats`-t telepítened kell.
A `bats` rendszeredre való telepítésének lépéseit a [Tesztelés a Bash-kurzuson][bash] oldalon találod.

### A bats bashben íródott

A bats fájl egy bash-szkript, benne néhány speciális függvénnyel, amelyeket a `bats` parancs felismer.
Találkozni fogsz olyan tesztekkel, amelyek így néznek ki:
```sh
gawk -f some-exercise.awk <<< "some,input,here"
```
Ez a `<<<` szintaxis egy bash [Here String][here-string].
A jobb oldali sztringet küldi a bal oldali program standard bemenetére.
Ez ([nagyjából][so]) ugyanaz, mint
```sh
echo "some,input,here" | gawk -f some-exercise.awk
```

## Segítség az assert függvényekhez

A tesztek a [bats-assert][bats-assert] könyvtár függvényeit használják.
A különféle `assert*` függvényekhez ott találsz segítséget.

## Kihagyott tesztek

Egy feladat megoldása azt jelenti, hogy az összes tesztje sikeres lesz.
Alapértelmezés szerint csak egy teszt fut le (az első), amikor a teszteket futtatod.
Ez szándékos, mert így arra összpontosíthatsz, hogy az az egy teszt sikeres legyen.
Ha ez sikeres, a következő tesztet úgy engedélyezheted, hogy kikommenteled vagy eltávolítod a

    [[ $BATS_RUN_SKIPPED == true ]] || skip

annotációkat, amelyek a többi teszt elé vannak szúrva.

## A kihagyások felülírása

Az összes teszt futtatásához, beleértve a `skip` annotációval ellátottakat is, ezt futtathatod:
```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

Kényelmes lehet egy burkolófüggvény használata, hogy kevesebbet kelljen gépelni: `bash`-ben ezt teheted:
```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```
Ezután a teszteket csak ennyivel futtathatod:
```bash
bats
```

## Hibakeresési kimenet

```exercism/caution
Ez helyben működik a `bats`-szel, de **nem** az Exercism online szerkesztőjében.
```

Amikor teszteket futtatsz, a `bats` a stdoutot és a stderr-t is elkapja, hogy összehasonlítsa a várt kimenettel.
Ha hibakeresési üzeneteket írsz a stdoutra vagy a stderrre, azok belekerülnek az elkapott kimenetbe, és a teszt sikertelenségét okozhatják.

Hogy a hibakeresési információkat a teszteredmények befolyásolása nélkül írd ki, a `bats` erre a célra a **3**-as fájlleírót biztosítja.
Minden, ami a `/dev/fd/3` fájlba íródik, megjelenik a tesztfuttatás során, de nem kerül bele abba az elkapott kimenetbe, amelyet az állításokhoz használ.

Példa:

```awk
BEGIN {
    # This debug message will not interfere with test output comparison
    print "a debug message" > "/dev/fd/3"

    # Normal program output (this is what your tests will see and compare)
    print "Hello, World!"
}
```

Példa futtatás:

```none
$ bats test-hello-world.bats
test-hello-world.bats
 ✓ Say Hi!
a debug message

1 test, 0 failures
```

Így hasznos hibakeresési kimenetet láthatsz anélkül, hogy ez befolyásolná a teszteket.

Ha a kódod több helyén is használod, az áttekinthetőséget javíthatja, ha egy függvénybe rejted a részleteket:

```awk
BEGIN {
    debug("starting ...")
}

# do stuff here ...

END {
    debug("... finished")
}

function debug(msg) {print msg > "/dev/fd/3"}
```
