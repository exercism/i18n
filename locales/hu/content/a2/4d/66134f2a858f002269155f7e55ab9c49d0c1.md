# Bevezetés

A parse-olás során szöveget alakítunk át jelentéssel bíró adatokká.
A `String` csomag függvényei ebből a szempontból korlátozottak, a reguláris kifejezéseket pedig nehéz használni, ezért Elmben a parse-olás megszokott módja az `elm/parser` csomag használata.

Nézzük meg egy példán, hogyan írhatunk parsert a [LOLCODE][lolcode] programozási nyelvhez (annak egy részhalmazához).
Vegyük a következő, megjegyzésekkel ellátott programot:

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

Először írjunk egy Elm-típust, amely a lehetséges parancsokat írja le:

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

A LOLCODE-programunkat ekkor egy `List Command`-ként modellezhetjük.
Kezdjük a `HAI 1` sor parserével:

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

A `versionP` egy _parser pipeline_ felhasználásával épül fel.
A `(|.)` operátor jelentése: „feldolgozza a szöveget, de eldobja az eredményt”, a `(|=)` pedig: „feldolgozza a szöveget, és megtartja az eredményt”.
Ebben a példában a `Parser.keyword "HAI"` elfogyaszt egy „HAI”-t, de az eredményét figyelmen kívül hagyja.
A `Parser.spaces` tetszőleges számú ' ', '\n' és '\r' karaktert fogyaszt el, de az is figyelmen kívül marad.
A `Parser.int` egy egész számot dolgoz fel, és ennek az egész számnak az értéke (mondjuk 1) átadódik a legfelső `Parser.succeed Version`-nek, és a parser sikeresen visszaadja a `Version 1` értéket.

Ha a pipeline-ban bármelyik parser elbukik, az egy `Parser.DeadEnd`-et ad vissza, és az egész parser elbukik.
Egy parsert a `Parser.run` segítségével futtathatunk:

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

Nézzük meg a „CAN HAS STDIO?” sort ezzel:

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

Az `importP` szintén egy parser pipeline, de ezúttal a `Parser.symbol`-lal végződik, amely alkalmas az olyan szimbólumok feldolgozására, mint a „?”.
Azt az értéket, amelyet meg akarunk tartani (az importálandó csomag nevét), a következő dolgozza fel:

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

Mivel nem tudjuk, mi lesz a csomag neve, a `Parser.keyword` szóba sem jön, helyette a `Parser.chompWhile`-t használjuk, amely addig fogyaszt egyes karaktereket, amíg azok megfelelnek egy feltételnek (itt annak, hogy alfanumerikus karakterek).
Az így elfogyasztott karaktereket ezután a `Parser.getChompedString` gyűjti össze, amely egy `Parser String`-et ad vissza.
Ebben az esetben szeretnénk normalizálni a csomagneveket, ezért a `Parser.map` segítségével módosítjuk a parserben lévő szöveget, és csupa kisbetűssé alakítjuk.

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

Következik a `VISIBLE "HAI WORLD!"`, amelyet a következő dolgoz fel:

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

Most már minden parancshoz van parserünk.
Egy általános programban persze nem lehet előre megjósolni ezeknek a parancsoknak a sorrendjét, ezért készítünk egy általános parancsparsert:

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

A `Parser.oneOf` a megadott sorrendben próbálja ki a parsereket.
Ha egy parser elbukik, a következőre kerül sor, ha viszont sikerül, az eredményét adja vissza anélkül, hogy kipróbálná a többi parsert.
Ha minden parser elbukik, a `Parser.oneOf` is elbukik.

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

Figyeld meg, hogy minden sikertelen próbálkozás egy-egy `Parser.DeadEnd`-et eredményez, amelyeket a `Parser.oneOf` gyűjt össze.

Egy teljes program feldolgozásához több parancsot kell egymás után feldolgoznunk a következővel:

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

A `Parser.sequence` egy nagyon testreszabható parser, számos beállítással.
A `start`, a `separator` és az `end` olyan szövegeket vár, amelyek elválasztják a sorozat elemeit; egy Elm lista feldolgozásához a „[”, a „,” és a „]” jelet használnánk.
A `spaces` rugalmasságot ad azzal, hogy egy parsert vár, amely kezeli az elemek és elválasztók között esetlegesen megjelenő szóközöket; egy Elm lista feldolgozásához a `Parser.spaces`-t használnánk, itt viszont nem engedünk meg szóközöket, ezért a `Parser.succeed ()`-t használjuk, amely azonnal sikerül anélkül, hogy bármit is elfogyasztana.
Az `item` az elemek parserét várja, a `trailing` pedig arról dönt, hogy a záró elválasztók `Parser.Forbidden`, `Parser.Mandatory` vagy `Parser.Optional` típusúak-e.

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

Ha egy parser sikerrel jár, abbahagyja a szöveg feldolgozását:

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

Ezért ha meg akarunk bizonyosodni arról, hogy mindent feldolgoztunk a szövegben, használhatjuk a `Parser.end`-et:

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

Végül néha arról kell döntenünk, hogy egy parsert a feldolgozott tartalma alapján elbuktassunk-e.
Ha például olyan parsert szeretnénk, amely elbukik azokra a programokra, amelyek két egymást követő „HAI” paranccsal kezdődnek, ezt írhatnánk:

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

A `Parser.andThen` megvizsgálhatja egy parser tartalmát, és annak értékétől függően új parsert ad vissza.
Itt az egyik ágban egyéni hibaüzenettel buktattuk el a parsert a `Parser.problem` segítségével, a másikban pedig az eredeti értéket adtuk vissza.

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
