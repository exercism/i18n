# Névjegy

## const

A `const` módosító bármely olyan mezőre alkalmazható (és általában alkalmazni is érdemes), amelynek értéke fordítási időben ismert, és a program élettartama alatt nem változik.

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

A fordító eligazít abban, hogy mely kifejezések értékelhetők ki fordítási időben. Egyszerű aritmetikai műveletek és a string-összefűzés is megengedett. Ez kizárja azokat a kiértékeléseket, amelyekhez a halom vagy a verem használatára lenne szükség, így minden metódushívás és nem primitív típusra való hivatkozás elérhetetlen.

A weben több helyen is vita folyik arról, milyen teljesítményelőnyt jelent a `const` a változókkal szemben. Ha példányszintű, nem `const` mezőkkel hasonlítjuk össze, észrevehető memóriamegtakarítás adódhat, statikus változókhoz képest viszont ez határozottan elhanyagolható. A CPU-teljesítményre vonatkozó bármilyen megfontolást a kollégáid valószínűleg [korai optimalizálásnak][premature-optimization] fognak tartani.

Nyomósabb érv a `const` használata mellett, hogy megkönnyíti a karbantartó számára a kód feletti gondolkodást. Ha a karbantartó egy pillantásra látja, hogy egy mező `const` vagy `readonly` jelöléssel szerepel, vagy hogy egy tulajdonságnak nincs `set` hozzáférője, az elemzéséből nagyrészt kihagyhatja azt. Valószínűtlen, hogy a hibák fészke lenne. Az sem valószínű, hogy nehézséget okozna egy refaktorálás során. Ezzel foglalkozik ez a [Stack Overflow-hozzászólás][so-consts].

A `const` módosító metódusokon belüli értékekre is alkalmazható:

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

Ha egy értéket így `const`-tal jelölünk meg, az hasznos lehet, ha a metódusban többször is használjuk, vagy szeretnénk felhívni a figyelmet a jelentésére. A beágyazott literálok használatához képest nincs teljesítménybeli nyereség.

## readonly

A `readonly` módosító minden olyan mezőre alkalmazható (és általában alkalmazni is érdemes), amely nem tehető `const`-tá, ha az értéke a program élettartama alatt nem változik, és vagy beágyazott kezdőértékkel, vagy példányosításkor (a konstruktorral vagy egy általa meghívott metódussal) kapja meg az értékét.

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

A `readonly` módosító használata ugyanazok miatt az okok miatt javasolt, amelyek a `const` esetében is érvényesek. A mezők ilyen módon való megkötése segíti a karbantartókat a kód feletti gondolkodásban.

Vedd figyelembe, hogy a `readonly` módosító hozzáadása egy mezőhöz csak magának a mezőnek az értékét védi a megváltoztatástól. Összetett típusok esetén nem védi az adott típus mezőit vagy tulajdonságait. Különösen igaz ez a tömbök tartalmára, amelyeket nem véd.

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

Ahhoz, hogy egy referenciatípus minden tagja védve legyen, a mezőket `readonly`-vá tehetjük, és az automatikus tulajdonságok `set` hozzáférő nélkül definiálhatók.

Érdemes megnézned a [csak olvasható gyűjteményeket][readonly-collections] a Base Class Libraryban.

Tömbök esetén a csak olvasható változathoz legközelebb a [`Array.AsReadOnly<T>()`][as-read-only] metódus áll.
