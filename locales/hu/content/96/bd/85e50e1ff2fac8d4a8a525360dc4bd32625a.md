# Bevezetés

Egy ideális világban számíthatnánk arra, hogy minden szépen definiálva van, konkrét értékekkel és hézagok nélkül.

Ez viszont ellentmond a mindennapi tapasztalatunknak, ezért sok programozási nyelvben van mód arra, hogy kifejezzük egy érték hiányát: null vagy NULL, nil, None, nothing...

Bevezetni könnyű volt (még 1965-ben), de hamar megbánták.
A feltalálója később „egymilliárd dolláros hibának” nevezte.

Az utóbbi évtizedekben a nyelvtervezők sok módot kerestek arra, hogy a null értékek elérhetők, de (többnyire) biztonságosak legyenek.

A Kotlinnak van néhány [általános alapelve][ref-null-safety], amelyek jelentősen eltérnek a Javáétól.


- A Kotlinban van egy speciális `null` érték.
- Minden típus _alapértelmezés szerint_ nem nullázható.
- A legtöbb típus _tehető_ nullázhatóvá, de ezt a programozónak kifejezetten kérnie kell.
- Azoknak a függvényeknek, amelyek kivétellel elhasalhatnak, gyakran van egy nullázható visszatérési értéket adó változatuk.
- Egy különleges, nagyon tömör szintaxis igyekszik a lehető legegyszerűbbé tenni a null értékek vizsgálatát és kezelését.

## Nullázható változók létrehozása

A szabványos típusoknak általában van nullázható megfelelőjük, `?` utótaggal: például `String?` a `String` helyett.

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## Hasznos operátorok és függvények

### A biztonságos hívás operátora `?.`

Egy nem nullázható `String` esetén lekérhetjük a `.length` tulajdonságot.

Egy nullázható `String?` ugyanezzel a szintaxissal hibát ad, de a `?.length` használata megengedi a `null` lehetőségét.
A visszatérési típus `Int?`.

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

Ahogy a fenti utolsó sorban láttuk, a `?.` nem nullázható típusokkal is működik.

### Az Elvis-operátor `?:`

A biztonságos hívás operátorának ötletét továbbgondolva az [Elvis-operátor][wiki-elvis] lehetővé teszi, hogy egy alapértelmezett értékkel helyettesítsük a `null`-t.

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### A nem null értéket kikényszerítő operátor `!!`

Ezzel az operátorral egy nullázható típust nem null értékűként kezelünk, amikor a programozó biztos ebben.
Talán néha jobban értjük a program logikáját, mint egy túlzottan óvatos fordító?

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

A felelősség most rajtunk van: ha `b` még mindig `null`, akkor `NullPointerException`-t kapunk.

### A let függvény `?.let`

Ha egy nullázható elemet adunk át egy kódrésznek, elvégezhetünk külön null-ellenőrzéseket: `if (item != null) { do something }`.

Egyszerűbb és idiomatikusabb az `item?.let { do something }` használata.
A `do something` csak akkor fut le, ha `item` nem null.

### A `somethingOrNone()` típusú függvények

Egyes függvények elhasalhatnak, például amikor egy stringben vagy listában érvénytelen indexet kérünk.

Ahelyett, hogy kivételt dobnánk, használhatjuk a függvény `...OrNull` változatát, hogy (ebben az esetben) `Int?` visszatérési értéket kapjunk.

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
