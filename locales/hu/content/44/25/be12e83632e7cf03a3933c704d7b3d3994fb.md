# A hash-halmazokról

A hash-halmazok a [`sets`][sets] [protokollt][set-protocol] valósítják meg a háttérben hash-eléssel, ami átlagosan O(1) beszúrást, keresést és törlést tesz lehetővé. Helyben módosíthatók, ami ideálissá teszi őket a gráfbejárások *látogatott halmaz* mintájához.

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| szó           | hatás                                     |
|---------------|-------------------------------------------|
| `HS{ }`       | üres hash-halmaz literál (megosztott, `clone`-ozd!) |
| `>hash-set`   | `( seq -- set )` - friss halmazt épít egy sorozatból (kiszűri a duplikátumokat) |
| `adjoin`      | `( elt set -- )` - destruktív beszúrás    |
| `in?`         | `( elt set -- ? )` - tagsági vizsgálat    |
| `delete`      | `( elt set -- )` - destruktív törlés      |
| `cardinality` | `( set -- n )` - elemek száma             |
| `null?`       | `( set -- ? )` - igaz, ha a halmaz üres   |
| `members`     | `( set -- seq )` - sorozatként sorolja fel |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )` - a `set`-et az `exemplar` osztályává alakítja |

Ha már meglévő adatokból szeretnél halmazt építeni, a `>hash-set` egy lépésben bármilyen sorozatot átalakít, elhagyva a duplikátumokat: a `{ 2 3 2 5 }
>hash-set`adjoin`HS{ 2 3 5 }` gives `adjoin`-nal növesztünk egy halmazt.

Egy finom pont az `in?` és a `member?` (a `sequences`-ből) kapcsán: mindkettő tagságot vizsgál, de a `member?` lineárisan végigfut a sorozaton, míg az `in?` a halmaztípus protokollmetódusához irányít. `HS{ }` esetén ez hash-keresés. Az `in?`-t akkor használd, ha a „látogatott” tárolódban már több mint egy maroknyi bejegyzés van.

A `null?` arra válaszol, hogy „üres-e ez a halmaz?”, anélkül hogy kiszámolná a teljes `cardinality`-t. Ez a természetes őr arra, hogy „maradt-e még feldolgoznivaló?”. Ha egy munkalistát halmazként tartasz nyilván, a `[ set null? ]
[ … ] until` kiüríti.

## Szépen párosul a hash-táblákkal

A `HS{ }` arra a kérdésre, hogy „látogatott-e X?”, természetesen párosul a `H{ }`-vel arra, hogy „kik X szomszédai?”. Egy tankönyvi DFS mindössze ennyi:

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

A látogatott halmaz kiszűri az ismétlődő munkát; a verem a frontvonal csomópontjait fűzi (LIFO a `push`/`pop` segítségével); a szomszédsági térkép (egy hash-tábla) adja a gráfot. A bejárás sorrendje nem számít egy elérhetőségi kérdésnél, ezért elég egy vektor mint verem. Egy valódi BFS ugyanilyen felállásban a vektort egy [`<dlist>`][dlist]-re cseréli, és inkább az elejéről vesz ki elemeket.
