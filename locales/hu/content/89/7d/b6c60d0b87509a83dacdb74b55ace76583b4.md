# Névjegy

Az assemblyben minden adat bájtok sorozata.
Ez azt jelenti, hogy bármely adat tekinthető a mögötte lévő bájtok **[tömbjének][array]**.

## Egy tömb elemeinek elérése

Ahhoz, hogy a memóriában bármely értéket elérj, ki kell számítanod annak **effektív címét**.
Az effektív cím egy olyan kifejezés, amely a következőkből állhat:

- egy _báziscím_, például az, amelyet egy változó címkéje jelöl.
- egy _indexregiszter_, amelyet adott esetben `1`-gyel, `2`-vel, `4`-gyel vagy `8`-cal szorzunk.
- egy előjeles 32 bites _eltolás_, azaz egy szám, amelyet a báziscímhez hozzáadunk (vagy abból kivonunk).

Figyeld meg, hogy ez a címzés _0-tól indexelt_, így egy báziscím minden eltolás nélkül a változó első bájtjára mutat.
Ezért ha a memóriát csupán egy címkével éred el, minden eltolás nélkül, ahogy a korábbi fogalmaknál tettük, az így kapott érték az első bájttól kezdődik:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
Az x86-64 [little endian][endianness] architektúrájú.
Ez azt jelenti, hogy egy többbájtos érték legkisebb helyiértékű bájtja a legkisebb memóriacímen tárolódik.

Következésképpen, amikor egy többbájtos érték egyes bájtjait éred el, pozitív eltolást kell hozzáadnod a báziscímhez, hogy a nagyobb helyiértékű bájtokhoz juss.

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

Ha egy inicializált változót értékek listájával deklarálsz, az ezen értékek tömbje lesz, és minden elem a megadott mérettel rendelkezik.
Az eltolások azonban mindig _bájtban_ értendők, még akkor is, ha a tömb minden eleme nagyobb méretű:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

Mivel a címek bájtokra vonatkoznak, egy tömb bármely elemének egyes bájtjait közvetlenül is elérheted:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

Ugyanezért egyetlen utasításban egy elem méreténél több bájtot is elérhetsz:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
Az assembly nem végez határellenőrzést a tömbeléréseknél.
A tömb végén túlmutató index a tömbön kívüli memóriát olvassa vagy írja.
Ez csendben hibás eredményekhez, más adatok megsérüléséhez, és ha az elért memória nincs leképezve, futásidejű hibához vezethet.
A programozó felelőssége, hogy minden effektív cím a tömbön belül maradjon.
~~~~

## Egy inicializált tömb méretének kiszámítása

A NASM (Netwide Assembler, a kurzus által használt assembler) rendelkezik egy speciális szimbólummal (`$`), amely a memória aktuális helyét jelöli.
Ez a szimbólum kényelmes módot kínál egy tömb által a memóriában elfoglalt teljes méret kiszámítására:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

Ha közvetlenül `example` után használod, a `$` a tömb végének memóriacímét adja.
Ez azt jelenti, hogy a `$ - example` a különbség e cím és az `example` címke által mutatott cím között.
Ez pontosan az `example` által mutatott tömb által elfoglalt teljes méret bájtban.

Így az `example_length` ilyen értékkel való definiálásával létrehoztunk egy 8 bájtos változót, amely a tömb méretét, azaz hosszát tárolja bájtban.

## A .bss szakasz

A nem inicializált adatokat a **[.bss szakaszban][bss]** deklarálod.
A legtöbb platformon ezt az adatot az operációs rendszer nullákkal tölti fel a program indulásakor.

A NASM-ban egy nem inicializált változónak van neve, egy adatméretet jelző direktívája, valamint a lefoglalandó elemek száma.
Ezeket szóköz választja el egymástól.

A legfontosabb direktívák és a hozzájuk tartozó adatméret:

| direktíva | méret   |
| :-------: | :------ |
|   resb    | 1 bájt  |
|   resw    | 2 bájt  |
|   resd    | 4 bájt  |
|   resq    | 8 bájt  |

Például ez `3` bájt nem inicializált helyet foglal le egy `example` nevű változóban:

```x86asm
section .bss
    example resb 3
```

Ez pedig `10`-szer `8` bájt (`80` bájt) nem inicializált helyet foglal le egy `arr` nevű változóban:

```x86asm
section .bss
    arr resq 10
```

A `section .bss`-ben lévő változók módosíthatók, azaz olvashatók és írhatók.

A nem inicializált adat ugyanúgy elérhető, mint az inicializált, az effektív címének használatával.
Hasonlóképpen ezek is statikus tárolási időtartamúak, és a forrásfájl bármely függvényéből elérhetők (illetve, ha `global`-ként deklarálod őket, más forrásfájlokból is).

## Tömbcímek elérése a Lea utasítással

Ahogy egy korábbi fogalomban megnéztük, a `lea` utasítás egy effektív memóriacímet számít ki.
Ugyanazokat a szemantikai szabályokat követve bármely tömb elem címének kiszámítására használható.

Figyeld meg, hogy relatív címzésnél gyakran be kell töltened a változó címét egy regiszterbe, mielőtt összetettebb címet alkotnál:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
A `lea` egyik előnye, hogy címkiszámítási aritmetikát használ egy érték kiszámításához anélkül, hogy ténylegesen elérné a memóriát azon a címen.
Ez teszi hasznossá aritmetikai számításokhoz akkor is, ha egyetlen regiszter sem tartalmaz memóriacímet:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
