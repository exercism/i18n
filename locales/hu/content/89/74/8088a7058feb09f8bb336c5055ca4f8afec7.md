# Részletek

## Terminológia

Néhány fogalomban már használtál és írtál is C++ függvényeket.
Most térjünk rá a technikai részletekre.
Az alábbi kódrészlet a leggyakoribb kifejezéseket mutatja be, hogy könnyen visszakereshesd őket.
Mivel a C++ figyelmen kívül hagyja a whitespace-t, a formázást úgy alakítottuk át, hogy minden elem a saját sorába kerüljön.

```cpp
// Function declaration:
bool                                              // Return type
admin_detected(string user, string password)      // Type signature
;                                                 // Don't forget the ';' for the declaration

// Function definition:
bool                                              // Return type
admin_detected                                    // Function name
(string user, string password)                    // Parameter list
{ return user == "admin" && password == "1234"; } // Function body
```
~~~~exercism/advanced
A deklaráció olyan, mint egy üzenet a fordítónak: létezik egy ilyen nevű, visszatérési típusú és paraméterlistájú függvény.
A kód nem fog működni, ha hiányzik a definíció.
A deklarációk nem kötelezőek, akkor van rájuk szükség, ha a függvényt a definíciója előtt használod.
A deklarációk megoldhatnak olyan problémákat, mint a körkörös hivatkozások, és arra is használhatók, hogy az interfészt elválasszák a megvalósítástól.
~~~~

## A const minősítő

Néha biztos szeretnél lenni benne, hogy egy érték az inicializálása után nem változtatható meg.
A C++ a `const` kulcsszót használja a konstansok minősítőjeként.

```cpp
const int number_of_dragon_balls{7};
number_of_dragon_balls--; // compilation error
```

~~~~exercism/note
A konstansokat gyakran _UPPER_SNAKE_CASE_ írásmóddal látod majd.
Ajánlott ezt az írásmódot a makrók számára fenntartani, ha nincs más konvenció.
~~~~

Ha megpróbálsz megváltoztatni egy konstans változót a beállítása után, a kódod nem fog lefordulni.
Ez segít elkerülni a nem szándékolt változtatásokat, de optimalizálási lehetőségeket is nyit a fordító számára.
Emberként is könnyebb átgondolni a kódot, ha tudod, hogy bizonyos részek nem változnak meg.

A `const` a függvényparaméterek minősítőjeként is szerepelhet.

```cpp
string guess_number(const int& secret, const int& guess) {
    if (secret < guess) return "lower.";
    if (secret > guess) return "higher.";
    return "exact!";
}
```

Amikor egy `const` referenciát adsz át a függvénynek, biztos lehetsz benne, hogy az változatlan marad.
A `const` referenciákkal gyakran olyan objektumoknál találkozol, amelyek másolása költséges lehet, például hosszabb stringeknél.
A `const` minősítő harmadik felhasználási módja azok a tagfüggvények, amelyek nem változtatják meg az osztály egy példányát.

```cpp
class Stubborn {
    public:
    Stubborn(string reply) {
        response = reply;
    }
    string answer(const string& question) const {
        if (question.length() == 0) { return "";}
        return response;
    }
    private:
    string response{};
};
```

A `Stubborn` `answer` tagfüggvénye `const string&` referenciát használ paraméterként.
Ez elkerüli annak az eredeti objektumnak a másolását, amelyet átadtak a függvénynek.

## Függvénytúlterhelés

Több függvénynek is lehet ugyanaz a neve, ha a paraméterlistájuk eltér.
Ezt függvénytúlterhelésnek nevezik, és általában akkor alkalmazzák, ha ezek a függvények nagyon hasonló feladatokat látnak el.

A függvény visszatérési típus nélküli fejléce a függvény __típusszignatúrája__.
A típusszignatúra megváltozása új függvényt eredményez.

A `play_sound` példának hat különböző túlterhelése van, hogy különböző eseteket lehessen lefedni:

```cpp
// different argument types:
void play_sound(char note);         // C, D, E, ..., B
void play_sound(string solfege);    // do, re, mi, ..., ti
void play_sound(int jianpu);        // 1, 2, 3, ..., 7

// different number of arguments:
void play_sound(string solfege, double duration);

// different qualifiers:
void play_sound(vector<string>& solfege);
void play_sound(const vector<string>& solfege);
```

~~~~exercism/advanced
A típusszignatúrát a függvény neve, a paraméterek száma, azok típusai és minősítői határozzák meg (de nem a nevük).
A visszatérési típus kifejezetten nem része a típusszignatúrának, és fordítási hibát kapsz, ha két függvényed csak a visszatérési típusában tér el.
A fordító hibát jelez, mert nem egyértelmű, hogy a kettő közül melyiket kell használni.
~~~~

## Alapértelmezett argumentumok

Egyes függvények nagyon hosszúvá válhatnak, és a hívásaik közül sok ugyanazokat az értékeket használhatja a legtöbb paraméterhez.
Az ismétlődés az ilyen hívásokban alapértelmezett argumentumokkal kerülhető el.

```cpp
void record_new_horse_birth(string name, int weight, string color="brown-ish", string dam="Alruccaba", string sire="Poseidon");

record_new_horse_birth("Urban Sea", 130); // color will be brown, dam "Alruccabam", sire "Poseidon"
record_new_horse_birth("Highclere", 175, "off-white", "Fall Aspen");   // sire will be "Poseidon"
```

Mivel a függvény deklarációját gyakran a definíció előtt olvassák, ez a jobb hely az alapértelmezett argumentumok megadására.
Ha az egyik paraméterhez alapértelmezett értéket adsz meg, akkor a tőle jobbra lévő összes paraméterhez is meg kell adnod egyet.
Néha a bonyolult függvénytúlterhelések kevesebb, alapértelmezett argumentumokkal rendelkező függvényre alakíthatók át a karbantarthatóság javítása érdekében.
