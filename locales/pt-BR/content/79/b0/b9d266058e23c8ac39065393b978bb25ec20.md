# Sobre

A memória dinâmica é implementada por funções de biblioteca que o programador usa para alocar e desalocar memória em tempo de execução.
Como o programador controla a alocação e a desalocação de memória, a memória dinâmica é tão segura quanto o programador for livre de erro humano.
Por isso, a memória dinâmica é uma das principais fontes de bugs de programação e um dos principais alvos de ataques de hackers.

A memória dinâmica é usada para variáveis cujo tamanho só é conhecido em tempo de execução.
Isso costuma ser útil para arrays cujo número de elementos pode variar de uma execução para outra.
Arrays de comprimento variável (VLA) são outra forma de lidar com arrays cujo tamanho dos elementos só é conhecido em tempo de execução.
Uma VLA usa armazenamento automático, o que significa que sua memória é destruída ao sair do bloco em que foi definida.
(Para saber mais sobre armazenamento, consulte o conceito [especificadores de classe de armazenamento](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers).)
As VLAs foram introduzidas na linguagem C pelo C99, mas a partir do C11 elas são opcionais, então compiladores que suportam C11 em diante não precisam suportar VLAs.
Uma análise detalhada de arrays de comprimento variável está fora do escopo deste artigo.

## malloc

`malloc` é uma função declarada em `stdlib.h` que serve para alocar memória dinâmica.
Se a alocação for bem-sucedida, é retornado um ponteiro que aponta para o endereço do primeiro byte da memória alocada.
Se a alocação não for bem-sucedida, `NULL` é retornado.
É prudente verificar se o resultado de `malloc` é `NULL` e lidar com isso de forma adequada caso falhe.
O ponteiro retornado é do tipo `pointer-to-void`, que pode ser considerado, grosso modo, um ponteiro "genérico" que pode ser convertido para o tipo específico usado pela memória.
`malloc` tem um parâmetro, que é o tamanho da memória desejada em bytes.
O tamanho total para alocar um array é o tamanho do tipo de dados de cada elemento multiplicado pelo número de elementos.
O operador `sizeof` é comumente usado para obter o tamanho do tipo de dados de cada elemento.
O exemplo a seguir demonstra isso

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

É importante lembrar que a memória recém-alocada por `malloc` não é inicializada, mas pode conter valores de lixo.
Repare que o `sizeof` do ponteiro `numbers` não é o número de elementos do array, nem a quantidade total de memória alocada.
O tamanho do ponteiro retornado por `malloc` é o tamanho de qualquer ponteiro naquele sistema específico.
O código de exemplo foi rodado em um sistema de 64 bits, então o tamanho do ponteiro era 8 bytes (multiplicado por 8 bits por byte = 64 bits).
O tipo do ponteiro foi convertido implicitamente de ponteiro para void em ponteiro para int.
Se o ponteiro para int aponta para um único `int` ou para um array de `ints` é algo com que o programador pode lidar como achar melhor.
Por exemplo

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

Se os valores com certeza forem escritos antes de serem lidos, usar `malloc` pode ser uma forma eficiente de alocar memória.
Mas, se houver a chance de os valores serem lidos antes de serem inicializados, usar `malloc` é arriscado.
Uma forma mais segura de alocar memória é usar `calloc`, que inicializa a memória recém-alocada com zero.

Repare nos exemplos acima que `free(numbers)` foi usado.

## free

`free` é uma função declarada em `stdlib.h` que serve para desalocar memória que foi alocada dinamicamente.
A memória alocada dinamicamente permanece reservada até ser liberada por `free`.
Alguns sistemas operacionais podem liberar automaticamente a memória alocada dinamicamente quando o programa termina, mas a boa prática é não depender disso.
`free` tem um parâmetro, que é um ponteiro para a memória que foi alocada dinamicamente.
O uso ou a ausência de uso de `free` está associado a vários problemas de memória.

#### vazamento de memória

Não liberar a memória alocada dinamicamente depois que a referência a essa memória chega ao fim do seu tempo de vida, ou é destruída de outra forma, é chamado de vazamento de memória.
Memória vazada é a memória que está reservada pelo sistema, mas não é mais acessível pelo programa.
Isso pode ser um problema em particular se a memória for alocada dentro de um laço, não for liberada no fim do laço e for alocada de novo no início do laço.
Se memória suficiente for alocada sem ser liberada, a chamada para alocar memória vai falhar por não restar memória suficiente para alocar.
É importante lembrar que, embora a memória alocada dinamicamente fique reservada pelo sistema até ser liberada, o ponteiro ao qual ela é atribuída pode ter apenas escopo de bloco.
Por exemplo, nos exemplos de `malloc`, a memória é alocada em `my_function`.
Essa memória vazaria se o ponteiro para ela não fosse retornado e usado para definir o ponteiro `numbers` em `main`.
Assim, passar esse ponteiro `numbers` para `free` libera a memória alocada em `my_function`.

#### uso após liberação (**UAF**)

Se a memória for acessada depois de liberada, os valores podem ser qualquer coisa.
No exemplo a seguir, a memória apontada por `numbers` é liberada e depois lida em `printf`.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

O ponteiro `numbers`, depois de liberado, é chamado de ponteiro pendente.
Um ponteiro pendente pode se referir a outra memória além daquela para a qual foi destinado.
Assim, um ponteiro pendente pode levar à corrupção de dados e à substituição e execução arbitrária de código.
Um ponteiro para memória alocada que não foi limpo com a atribuição de `NULL` pode ser usado para hackear o programa.
No exemplo acima, se `numbers` fosse definido como `NULL` assim: `numbers = NULL;` depois de ser liberado, o `printf` seguinte resultaria no encerramento do programa, talvez relatando um segmentation fault ao tentar ler `numbers[0]`.

#### liberação dupla

Se `free` for chamada duas vezes em um ponteiro para memória alocada dinamicamente, isso resulta em comportamento indefinido (**UB**).
Isso significa que o compilador pode lidar com isso de qualquer maneira que quiser.
O exemplo a seguir, compilado com dois compiladores diferentes, pode ter dois resultados diferentes

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

O primeiro e o segundo compilador não geraram erro em tempo de execução quando `numbers` foi definido como `NULL` entre cada chamada a `free`, mas isso não é garantido de funcionar com um terceiro compilador.
Uma fonte comum de liberação dupla é ter dois ponteiros que apontam para a mesma memória alocada dinamicamente.
Um ponteiro pode apontar para o início de um array em um ponto do programa, e o outro ponteiro pode ser usado para percorrer o array em outro ponto do programa.
Em pontos diferentes do programa, cada ponteiro é liberado, causando assim uma liberação dupla.

## calloc

`calloc` é uma função declarada em `stdlib.h` que serve tanto para alocar memória dinâmica quanto para inicializar a memória recém-alocada com zero.
Se a alocação for bem-sucedida, é retornado um ponteiro que aponta para o endereço do primeiro byte da memória alocada.
Se a alocação não for bem-sucedida, `NULL` é retornado.
É prudente verificar se o resultado de `calloc` é `NULL` e lidar com isso de forma adequada caso falhe.
O ponteiro retornado é do tipo `pointer-to-void`, que pode ser considerado, grosso modo, um ponteiro "genérico" que pode ser convertido para o tipo específico usado pela memória.
`calloc` tem dois parâmetros.
O primeiro parâmetro indica quantos elementos do tipo de dados especificado devem ser alocados.
O segundo parâmetro indica o tamanho do tipo de dados especificado a ser alocado.

No exemplo a seguir, todas as instruções `printf` devem sempre mostrar `0`, já que `calloc` garante que os valores recém-alocados sejam zerados.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc` é uma função declarada em `stdlib.h` que serve tanto para expandir quanto para reduzir memória já alocada.
Se a realocação for bem-sucedida, é retornado um ponteiro que aponta para o endereço do primeiro byte da memória realocada.
Se a realocação não for bem-sucedida, `NULL` é retornado.
É prudente verificar se o resultado de `realloc` é `NULL` e lidar com isso de forma adequada caso falhe.
`realloc` tem dois parâmetros.
O primeiro parâmetro é um ponteiro para a memória existente a ser realocada.
O segundo parâmetro é o tamanho em bytes da memória realocada.
Os valores definidos antes de a memória ser expandida são mantidos.
É importante lembrar que a memória adicionada ao expandir a memória não é inicializada com zero e seus valores podem ser qualquer coisa.
Além disso, a memória removida ao reduzir o tamanho também não é inicializada e pode reter os valores.
O exemplo a seguir demonstra como expandir e reduzir um array

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## Quando o tamanho informado é 0

Se o tamanho passado para `malloc`, `calloc` ou `relloac` for `0`, o que acontece depende de como o compilador o implementa.
Um compilador pode retornar tanto um ponteiro `NULL` quanto um ponteiro não nulo.
Por exemplo, ao alocar memória para um ponteiro para `char`, o compilador pode retornar `NULL` ou um ponteiro não nulo para uma string vazia.
Para evitar resultados diferentes com compiladores diferentes, é melhor não alocar com tamanho 0.
