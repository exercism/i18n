# Instruções

É a noite de estreia no Grand Marquee, e toda a equipe trabalha ao mesmo tempo.
A multidão entra em peso por todas as portas, várias bilheterias vendem a partir do mesmo rolo de ingressos, a estreia está quase esgotada e, lá em cima, na cabine de projeção, os rolos precisam continuar rodando.

Tudo o que a equipe compartilha fica em um endereço de memória, e os testes chamam suas funções a partir de várias threads ao mesmo tempo.
Um valor lido, alterado e gravado de volta em etapas separadas vai perder atualizações sob essa carga, então cada função precisa tornar sua atualização atômica.

Todos os valores compartilhados neste exercício são inteiros de 64 bits com sinal.

Você tem cinco tarefas.

~~~~exercism/note
As atualizações neste exercício devem ser feitas com instruções _atômicas_.
Os testes executam suas funções de forma concorrente e verificam que nenhuma atualização se perde, então uma leitura-modificação-gravação não atômica tem grande chance de não passar.
~~~~

## 1. Conte as entradas

As portas estão abertas, e em cada uma delas um lanterninha está rasgando os ingressos.
Cada grupo que passa é contado em uma única contagem de entradas compartilhada e, mesmo com todas as portas contando ao mesmo tempo, o total da casa precisa sair correto.

Implemente a função `admit_group`, que adiciona atomicamente o tamanho de um grupo à contagem.

Esta função recebe como argumentos, nesta ordem:

- `admissions`: endereço de memória da contagem de entradas compartilhada, um inteiro de 64 bits com sinal.
- `group_size`: o número de pessoas no grupo, um inteiro de 64 bits com sinal, sempre maior que `0`.

```c
admissions = 120, group_size = 4
// admissions is now 124
```

Os testes admitem grupos por várias portas ao mesmo tempo.
A contagem final precisa ser igual à soma de todos os grupos que passaram.

Esta função não tem valor de retorno.
A contagem deve ser atualizada no mesmo local.

## 2. Troque o rolo

O projetor carrega exatamente um rolo.
Montar o próximo rolo e retirar o atual precisa ser um único movimento: com dois projecionistas na máquina, duas etapas separadas poderiam entregar o mesmo rolo para os dois, ou derrubar um no chão.

Implemente a função `change_reel`, que monta atomicamente o próximo rolo e retorna o que estava montado.

Esta função recebe como argumentos, nesta ordem:

- `mounted`: endereço de memória do identificador do rolo montado, um inteiro de 64 bits com sinal.
- `next_reel`: o identificador do rolo a montar, um inteiro de 64 bits com sinal.

```c
mounted = 7, next_reel = 9
// => 7, and mounted is now 9
```

Esta função retorna o identificador do rolo montado anteriormente como um inteiro de 64 bits com sinal.
Os testes fazem várias threads trocarem rolos pelo mesmo encaixe ao mesmo tempo, e verificam que todo rolo entregue volta a sair exatamente uma vez.

## 3. Venda um ingresso

Cada bilheteria vende a partir de uma contagem compartilhada de ingressos vendidos.
Somar a uma contagem, como as portas fazem, não basta aqui: cada venda também precisa saber qual número foi atribuído a ela.
Duas vendas não podem compartilhar um número, e depois da correria a contagem precisa ser exatamente igual ao número de ingressos vendidos.

Implemente a função `sell_ticket`, que adiciona um à contagem atomicamente e retorna o número do ingresso recém-vendido.
O número do ingresso é a contagem _depois_ desta venda: quando a contagem era `41`, esta venda é o ingresso `42`.

Esta função recebe como argumento:

- `tickets_sold`: endereço de memória da contagem compartilhada de ingressos vendidos, um inteiro de 64 bits com sinal.

```c
tickets_sold = 0
// => 1, and tickets_sold is now 1

tickets_sold = 41
// => 42, and tickets_sold is now 42
```

Esta função retorna o número do ingresso como um inteiro de 64 bits com sinal.
Os testes vendem a partir de várias bilheterias ao mesmo tempo: cada número retornado precisa ser distinto, e a contagem final precisa ser igual ao número de vendas.

## 4. Encha a estreia

A estreia tem um número fixo de lugares, e todas as bilheterias estão vendendo ingressos para ela.
Uma venda só pode ser concluída enquanto houver um lugar livre, e a sessão nunca pode ser vendida além da capacidade, nem mesmo quando todas as bilheterias disputam o último lugar no mesmo instante.
Verificar a contagem e depois somar a ela em duas etapas separadas abre uma brecha no meio, então a verificação e a atualização precisam ter sucesso ou falhar juntas.

Implemente a função `claim_seat`, que ocupa atomicamente o próximo lugar quando ainda há um livre.
Quando um lugar é ocupado, a função retorna o número do lugar, que é a contagem de lugares ocupados após esta ocupação.
Quando a sessão estiver esgotada, ela retorna `0` e deixa a contagem inalterada.

Esta função recebe como argumentos, nesta ordem:

- `seats_taken`: endereço de memória da contagem de lugares já ocupados, um inteiro de 64 bits com sinal, nunca acima de `capacity`.
- `capacity`: o número de lugares da sessão, um inteiro de 64 bits com sinal, sempre maior que `0`.

```c
seats_taken = 0, capacity = 150
// => 1, and seats_taken is now 1

seats_taken = 82, capacity = 150
// => 83, and seats_taken is now 83

seats_taken = 149, capacity = 150
// => 150, and seats_taken is now 150

seats_taken = 150, capacity = 150
// => 0, and seats_taken stays 150
```

Esta função retorna o número do lugar, ou `0` quando a sessão estiver esgotada, como um inteiro de 64 bits com sinal.

## 5. Fique de olho na cabine

A cabine de projeção comporta uma pessoa.
Uma palavra na memória diz se ela está ocupada: `0` para livre, `1` para ocupada.
Funcionários passam a noite inteira por ali, cada um com uma tarefa a fazer lá dentro: assinar o livro de registro, passar o filme no projetor, arquivar um rolo.
Seja qual for a tarefa, a regra da cabine é a mesma, e fazer valer essa regra é seu trabalho: uma pessoa lá dentro por vez, do início ao fim da tarefa dela.

Implemente a função `visit_booth`, que:

1. espera até que a cabine esteja livre;
2. ocupa a cabine;
3. executa a tarefa do visitante;
4. reabre a cabine depois da tarefa e antes de retornar.

Enquanto a cabine estiver ocupada por outra pessoa, deve esperar educadamente usando `pause`.

Esta função recebe como argumentos, nesta ordem:

- `booth`: endereço de memória da palavra de ocupação, um inteiro de 64 bits com sinal que é `0` ou `1`.
- `task`: a tarefa do visitante, uma função que não recebe parâmetros e não tem valor de retorno.

Repare que os testes executam tarefas que olham para a cabine e para um livro de registro compartilhado.
Isso significa que a cabine precisa ficar ocupada durante toda a tarefa, que cada visita precisa executar sua tarefa exatamente uma vez e que, com vários visitantes ao mesmo tempo, o livro de registro precisa sair exato.

~~~~exercism/caution
A tarefa do visitante é uma função comum que segue a convenção de chamada:

- ela pode sobrescrever qualquer registrador salvo pelo chamador, então você deve guardar tudo o que ainda precisar depois da tarefa em algum lugar onde a chamada não possa tocar;
- ela também espera que a pilha esteja alinhada em 16 bytes no ponto da chamada.

Uma violação de qualquer uma das regras pode se manifestar como um travamento em vez de uma verificação que falha.
~~~~
