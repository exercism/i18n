# Combinação de iteradores

Um laço pode chamar mais de um iterador. Pedimos a cada um o seu próximo valor uma vez a cada volta, e eles avançam juntos.

```sather
   loop
      first ::= violin_one.elt!;
      second ::= violin_two.elt!;
      #OUT + first + " against " + second + "\n";
   end;
```

Isso percorre os dois arrays lado a lado: o primeiro elemento com o primeiro, o segundo com o segundo.

## A regra que surpreende todo mundo

**O laço termina assim que o *primeiro* dos seus iteradores acaba.**

Não quando o último acaba. Nem quando todos acabam. O primeiro.

Então, se o `violin_one` tem quatro compassos e o `violin_two` tem dois, o laço acima roda **duas vezes**. Os terceiro e quarto compassos da primeira parte nunca são olhados, porque a essa altura a segunda parte já não tem nada a oferecer.

Isso geralmente é exatamente o que se quer, já que emparelhar coisas só faz sentido enquanto existem pares, mas é algo que você precisa saber, e não descobrir por conta própria.

## Contar em paralelo

Um iterador que nunca acaba é útil justamente por causa dessa regra. O `up!` conta para sempre:

```sather
1.up!        -- 1, 2, 3, 4, ... and never ends
```

Sozinho, ele faria um laço infinito. Emparelhado com um que acaba, ele numera os valores sem nunca precisar decidir até onde contar:

```sather
   loop
      number ::= 1.up!;
      bar ::= part.elt!;
      #OUT + "Bar " + number + ": " + bar + "\n";
   end;
```

O `part.elt!` termina o laço; o `1.up!` fornece a numeração. Nenhum dos dois precisa saber quantos compassos a parte tem.

## A ordem não importa

Todos os iteradores são consultados uma vez a cada volta, então não faz diferença qual deles é escrito primeiro. O que importa é que cada um seja consultado exatamente uma vez: escrever `part.elt!` duas vezes na mesma volta consome dois valores em vez de um.
