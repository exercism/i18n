# Sobre

Preparar um valor para transmissão significa três coisas ao mesmo tempo: serializá-lo, escolher a parte certa dele e não copiar quando não precisar. Três expressões idiomáticas do Factor dão conta disso.

## `unparse`: valor para código-fonte

[`unparse`][unparse] (no `prettyprint`) retorna o texto na forma de código-fonte de qualquer valor. É o inverso do parser: o ciclo de ida e volta `dup unparse parse` reconstrói o valor.

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

Compare com `>string` (que só funciona com sequências de caracteres) e `number>string` (só números). O `unparse` é o universal, mas ao custo de produzir sintaxe do Factor (strings entre aspas mantêm as aspas). Por isso, é a ferramenta certa quando quem recebe vai fazer o parse do texto de volta, e a ferramenta errada para uma saída legível para humanos.

## Slices: visões, não cópias

| palavra       | efeito                                         |
|---------------|------------------------------------------------|
| `head`        | `( seq n -- newseq )`: copia os primeiros n    |
| `head-slice`  | `( seq n -- slice )`: visão dos primeiros n    |
| `tail`        | `( seq n -- newseq )`: copia a partir do índice n |
| `tail-slice`  | `( seq n -- slice )`: visão a partir do índice n |
| `head*`       | `( seq n -- newseq )`: copia todos, exceto os últimos n |
| `head-slice*` | `( seq n -- slice )`: visão de todos, exceto os últimos n |
| `tail*`       | `( seq n -- newseq )`: copia os últimos n      |
| `tail-slice*` | `( seq n -- slice )`: visão dos últimos n      |

Uma `slice` é uma tupla que guarda um índice inicial, um índice final e a sequência subjacente. Ela implementa o [protocolo de sequência][sequence-protocol], então qualquer operação de sequência funciona nela. Recorra às variantes de slice quando, de outro modo, você alocaria memória só para ler; recorra às que copiam quando precisar manter os dados depois que a sequência subjacente puder mudar.

## Cleave com múltiplas entradas: `2bi`, `3bi`, `2tri`, `3tri`

As palavras cleave simples `bi` e `tri` aplicam duas ou três citações a *uma* entrada na pilha. As variantes com prefixo `2` e `3` aplicam cada citação a *duas* ou *três* entradas:

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

Cada citação recebe *todas* as entradas, então use `2bi` quando as duas projeções dependerem do par, não quando você quiser a mesma projeção aplicada a cada entrada separadamente (isso é `bi@`).

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

Para *uma* citação aplicada a cada entrada separadamente, recorra a `bi@` (duas entradas) ou `tri@` (três entradas). É a mesma família, com formato diferente.
