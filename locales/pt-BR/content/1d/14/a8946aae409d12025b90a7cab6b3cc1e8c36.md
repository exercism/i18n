# Introdução

## Otimização de chamada em cauda

Cada vez que uma função é chamada, um novo quadro de pilha é criado na memória para armazenar os argumentos e as variáveis locais da função, e esse quadro de pilha é desalocado quando a função retorna. Como Gleam usa chamadas de função recursivas em vez de uma sintaxe de laço, isso pode fazer com que esses quadros de pilha usem uma grande quantidade de memória.

Para evitar esse problema, Gleam oferece suporte à otimização de chamada em cauda, que permite ao compilador reutilizar o quadro de pilha da função atual se uma chamada de função for a última coisa que a função faz. Isso significa que uma função pode chamar a si mesma infinitas vezes sem usar memória adicional.

Funções recursivas não otimizadas muitas vezes podem ser reescritas como funções com otimização de chamada em cauda usando um _acumulador_.

Um acumulador é uma variável passada junto com os dados. Ele é usado para passar o estado atual da execução da função até que o caso base seja alcançado.

Os acumuladores devem ser inicializados por quem escreve a função, não por quem a usa. Para isso, declare duas funções: uma função pública que recebe apenas os dados necessários como argumentos e inicializa o acumulador, e uma função privada que também recebe um acumulador.

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
