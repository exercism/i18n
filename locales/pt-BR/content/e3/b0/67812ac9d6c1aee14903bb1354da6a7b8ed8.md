# Sobre

A única convenção de passagem de dados do Factor é a *pilha de dados*: as palavras retiram suas entradas da pilha e empilham suas saídas. Toda definição de palavra declara um *efeito de pilha*, que documenta esse contrato.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

Os nomes dentro de `( … -- … )` existem para ajudar quem lê; o que o compilador verifica é o *número* de entradas e saídas. Uma divergência é um erro em tempo de compilação, o que pega uma classe de bugs que, numa linguagem de tipagem dinâmica sem esse tipo de declaração, seriam erros em tempo de execução.

Como a pilha é posicional, você precisa reorganizar seu topo o tempo todo antes que a próxima palavra possa rodar. As **palavras de embaralhamento** do `kernel` fazem exatamente isso:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

A família completa de embaralhamento estende essas palavras com `-rot` (rolar para o outro lado), as variações com sufixo `d` que agem um item mais fundo na pilha (`dupd`, `swapd`), as variações com prefixo `2` que agem sobre pares (`2dup`, `2drop`, `2nip`) e outras como `pick` e `tuck`. Elas são apresentadas conforme os exercícios seguintes precisam delas; recorrer a muitas palavras de embaralhamento de uma vez costuma ser sinal de que um *local* (valor nomeado) seria mais legível.

Por convenção, as palavras usam `lowercase-kebab-case`, os predicados terminam em `?` e produzem um Boolean (`even?`, `empty?`), os setters são escritos `>>name` e os getters `name>>`, e uma palavra e sua variante mutável muitas vezes compartilham o mesmo nome, diferenciadas apenas pelo contexto.
