# Dicas

Um uso comum de `Either` é indicar uma computação que pode resultar em erro
(se o erro em si não interessa, o tipo mais simples `Option` pode ser uma escolha melhor).
Quando não há erro, o resultado costuma ser um `Right` (mnemônico: o valor "certo"),
enquanto um erro é um `Left`, por exemplo um `Left[String]` contendo uma mensagem de erro.
Repare que no Scala 2.12 o `Either` é enviesado para a direita por padrão, então ele funciona como esperado em operações como `filter`, `map`, `flatMap` ou em uma for-comprehension.
Se você não conhece `Either`, pode ler [este tutorial](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html). Mas atenção: esse tutorial é sobre versões do Scala anteriores à 2.12. No Scala 2.12, você pode ignorar `RightProjection` sem problemas e omitir o `.right`.
`Either` é uma chamada [mônada](https://en.wikipedia.org/wiki/Monad_(functional_programming)) que cobre um "aspecto computacional",
neste caso o tratamento de erros.
O uso adequado de mônadas pode resultar em um código bem conciso, mas ainda assim elegante
e legível. O uso inadequado pode facilmente resultar no contrário.
Assista a [este vídeo](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) para saber mais.

## Armadilhas comuns que você deve evitar

Há algumas regras práticas para `Either`:

1. Se você não precisa, não use. Em vez de
```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```
prefira
```scala
def add1(x: Int): Int = x + 1
```
(existe `Either.map` para aplicar funções simples assim,
então você não precisa sobrecarregá-las com `Either`).

2. Não faça "unwrap" se você realmente não precisar.
Muitas vezes já existem funções prontas para o seu propósito. Indicadores de
unwrap prematuro são `isLeft/isRight` ou pattern matching. Por exemplo, em vez de
```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```
prefira
```scala
x fold (identity, _ + 1)
```

3. Mônadas podem ser usadas dentro de uma for-comprehension FTW.
Isso é recomendável quando você quer "compor" várias instâncias de `Either`. Em vez de
```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```
prefira
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
