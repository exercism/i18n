# Sobre

O [Elixir](https://elixir-lang.org/), lançado inicialmente em 2012, amplia os recursos já robustos do Erlang e, ao mesmo tempo, é mais fácil para quem está começando a acessar, ler, testar e escrever.

José Valim, o criador do Elixir, explica [em sua palestra de 2012](https://vimeo.com/53221562) como ele construiu a linguagem para que as aplicações fossem:

  1. Distribuídas
  2. Tolerantes a falhas
  3. De tempo quase real (soft real-time)
  4. De troca de código a quente (é possível introduzir código novo sem parar o servidor)

Na verdade, o Elixir é compilado para [bytecode](https://en.wikipedia.org/wiki/Bytecode) e depois roda na [máquina virtual Erlang BEAM](https://codesync.global/media/robert-virding-co-creator-of-erlang-explains-the-beam/).

Não existe "custo de conversão" para chamar Erlang, ou seja, você pode rodar código Erlang lado a lado com código Elixir.

Por ser uma linguagem funcional, tudo no Elixir é uma expressão.

O Elixir tem "documentação de primeira classe", o que significa que comentários podem ser anexados a uma função, o que facilita encontrá-la depois.

As expressões regulares também recebem tratamento de primeira classe, o que elimina o escape desajeitado dentro das strings.

A implementação de comunicação assíncrona do Elixir permite que o código seja leve e, ainda assim, lide com um grande volume de concorrência.

Programadores usam o Elixir para lidar com milhares de requisições e respostas *concorrentemente* em um único nó de servidor.

Ele tem sido usado com sucesso para microsserviços que precisam consumir e servir uma infinidade de APIs rapidamente.

O [framework Phoenix](https://www.phoenixframework.org/) ajuda a estruturar aplicações Elixir para a web.
