# Fluxos de trabalho

O GitHub Actions usa o conceito de _fluxos de trabalho_, que são scripts executados automaticamente sempre que um evento específico acontece (por exemplo, ao fazer push de um commit).

Cada fluxo de trabalho do GitHub Actions é definido em um arquivo `.yml` no diretório `.github/workflows`.
Para saber mais sobre fluxos de trabalho, consulte a documentação a seguir:

- [Sintaxe de fluxos de trabalho](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions)
- [Escolher quando o fluxo de trabalho é executado](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/triggering-a-workflow)
- [Escolher onde o fluxo de trabalho é executado](https://docs.github.com/en/actions/writing-workflows/choosing-where-your-workflow-runs)
- [Escolher o que o fluxo de trabalho faz](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does)
- [Escrever fluxos de trabalho](https://docs.github.com/en/actions/writing-workflows)
- [Boas práticas](/docs/building/github/gha-best-practices)

## Fluxos de trabalho compartilhados

Alguns fluxos de trabalho são compartilhados entre repositórios.

```exercism/caution
Os fluxos de trabalho compartilhados são sincronizados automaticamente (a partir do [repositório org-wide-files](https://github.com/exercism/org-wide-files/)).
Por isso, você não deve alterar o conteúdo deles manualmente.
```

### Fluxos de trabalho gerais

- [Sincronizar rótulos](/docs/building/tracks/ci/workflows/sync-labels): sincroniza os rótulos do repositório a partir de um arquivo

### Fluxos de trabalho específicos da trilha

- [configlet](/docs/building/tracks/ci/workflows/configlet): verifica se os arquivos (de configuração) da trilha estão estruturados corretamente, tanto sintática quanto semanticamente
- [Nenhum arquivo importante alterado](/docs/building/tracks/ci/workflows/no-important-files-changed): comenta em pull requests que fariam com que soluções existentes fossem testadas de novo
- [Testes](/docs/building/tracks/new/setup-continuous-integration#h-test-workflow): verifica os exercícios da trilha

### Fluxos de trabalho específicos de ferramentas

- [Publicar](/docs/building/tracks/ci/workflows/deploy): faz o deploy da imagem Docker das ferramentas da trilha no Docker Hub e no ECR

### Fluxos de trabalho opcionais

Há também alguns fluxos de trabalho que as trilhas podem adotar opcionalmente:

- [Pausar contribuições da comunidade](/docs/building/tracks/ci/workflows/pause-community-contributions): comenta automaticamente em issues e PRs recém-criadas por pessoas que não são membros da organização do Exercism no GitHub
