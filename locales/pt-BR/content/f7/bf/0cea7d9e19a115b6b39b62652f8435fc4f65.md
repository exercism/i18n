# Introdução

## Tipos personalizados

[Tipos personalizados][custom-types] em Elm representam um número fixo de casos nomeados. Cada valor corresponde exatamente a um dos casos nomeados.

Um tipo personalizado é definido com a palavra-chave `type` e exige muito pouca sintaxe. Eles são uma das técnicas mais importantes da programação em Elm, e são usados para fazer com que os valores possíveis no código correspondam exatamente aos valores válidos da vida real, o que não deixa espaço para dados inválidos e faz com que [estados impossíveis não possam ser representados no código][impossible-states].

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

Cada caso de um tipo personalizado pode, opcionalmente, ter dados associados a ele, e casos diferentes podem ter tipos diferentes de dados. Se nenhum dos casos tiver dados associados, a união discriminada é parecida com o que outras linguagens costumam chamar de _enumeração_ (ou _enum_).

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Criar um valor para um caso específico pode ser feito referindo-se ao seu nome (`Spring`), quando ele é definido no mesmo módulo, ou é importado com a sintaxe de estilo `import SeasonModule exposing (Season(..))`, ou referindo-se ao seu nome totalmente qualificado (`Season.Spring`) quando importado com a sintaxe de estilo `import SeasonModule exposing (Season)`.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

Os tipos personalizados, assim como tudo em Elm, têm _igualdade estrutural_, o que significa que dois valores para o mesmo caso e com os mesmos dados (opcionais) são equivalentes.

A forma preferida de trabalhar com tipos personalizados é com [correspondência de padrões][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
