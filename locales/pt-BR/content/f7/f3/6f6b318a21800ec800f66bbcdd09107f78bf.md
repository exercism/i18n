# Sobre

Uma função é [recursiva em cauda][recursion-tc] se a _última_ coisa executada pela função for uma chamada a si mesma.

Cada vez que uma função qualquer é chamada, um _quadro de pilha_ com suas variáveis locais e seus argumentos é colocado no topo da [pilha de chamadas de funções][call-stack].
Quando uma função retorna, o quadro de pilha é removido da pilha.

Funções recursivas em cauda permitem a [otimização de chamada em cauda][tail-call-optimization] (ou eliminação de chamada em cauda).
É uma otimização que permite reutilizar o último quadro de pilha na próxima chamada de função, quando é garantido que a função anterior não vai mais precisar dele.
Isso reduz a preocupação com o estouro da pilha de chamadas de funções, uma situação em que há tantos quadros na pilha de chamadas que não sobra memória para criar mais um.

## Otimização de chamada em cauda no Elm

Sob certas condições, o compilador do Elm consegue realizar automaticamente uma otimização de chamada em cauda ao compilar para JavaScript.

A otimização pode acontecer em uma função recursiva quando a _última_ operação em um bloco é feita chamando a própria função em uma aplicação simples de função.
Vamos ver alguns exemplos:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

A implementação acima não é recursiva em cauda, porque a última operação no bloco `else` é uma multiplicação `n *`.

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

A implementação acima é recursiva em cauda e será otimizada, porque a última operação no bloco `else` é `factorialHelper` chamando a si mesma.
Isso não seria possível para uma função com assinatura de tipo `Int -> Int` e, na prática, a otimização de chamada em cauda costuma ser obtida definindo funções auxiliares.

## Casos limite

Em alguns casos, o compilador não consegue otimizar funções recursivas. Vamos ver alguns exemplos.

Enquanto `f x = f (x - 1)` é recursiva em cauda, `f x = (x - 1) |> f` não é, porque a aplicação de função `|>` é a última operação e é considerada separada de `f`.
De forma semelhante, funções que terminam com condições Boolean `f x = x > 0 || f (x - 1)` não são recursivas em cauda.

A função `f x = if f (x - 1) then 1 else 0` não é recursiva em cauda, porque a expressão dentro do `if` não é considerada um bloco.
De forma semelhante, uma chamada recursiva em uma instrução `case` também não seria otimizada.

A função `f x = let y = f (x - 1) in y` não é recursiva em cauda porque chama a si mesma em uma instrução `let`, que não é considerada um bloco.
Porém, em `f x = let g x = g (x - 1) in g x` a função `g` é recursiva em cauda e será otimizada, mesmo que esteja definida em uma instrução `let`.

A função `f x = if x > 0 then f (x + 1) else 1 + f x` será _parcialmente_ otimizada: o bloco `then` pode ser otimizado, mas o bloco `else` não.
A otimização parcial é o melhor que se consegue em algumas situações, como percorrer estruturas em forma de árvore ou definir funções co-recursivas.
