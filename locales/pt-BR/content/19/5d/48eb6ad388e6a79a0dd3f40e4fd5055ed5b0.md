# Introdução

## Referências nulas

Se você já usou outra linguagem de programação (C/C++, Python, Java, Ruby, Lisp etc.), é provável que já tenha encontrado `null` ou `nil`.
É com `null` ou `nil` que essas linguagens indicam que uma determinada variável não tem valor.
No entanto, isso faz com que usar uma variável `null` por acidente seja um erro fácil (e frequente) de cometer.
Como você pode imaginar, tentar chamar uma função que não existe ou acessar um valor que não existe pode levar a todo tipo de bug e travamento.
O criador do `null` chegou ao ponto de chamá-lo de seu ['erro de um bilhão de dólares'][billion-dollar-mistake].

[billion-dollar-mistake]: https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/

## O tipo `Option`

Para evitar esses problemas, as variáveis de Cairo podem usar o enum `Option` para representar com segurança a ausência de um valor.
Esse enum tem duas variantes: `None`, o equivalente a null em Cairo; e `Some(T)`, em que `T` é um valor de qualquer tipo.

Ele se parece com isto:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

Você pode pensar no `Option` como uma camada de segurança entre você e os problemas que as referências nulas podem causar, sem deixar de lado a utilidade conceitual delas.

## Usando `Option`

Definir uma variável como `None` é bem simples:

```rust
let nothing: Option<u32> = Option::None;  // Variable nothing is set to None
```

No entanto, se você quiser que o tipo `Option` carregue um valor, não pode atribuir esse valor diretamente.
Uma variável do tipo `Option` e, digamos, uma variável do tipo `i32` não são equivalentes.
Você precisa usar `Some`:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Option::Some(-4); // This will work
let another_right_way = Option::Some(-4); // Compiler infers that this is Option<i32>
```

Pelo mesmo motivo, o seguinte não vai funcionar:

```rust
let number = 47;
let option_number = Option::Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

Para obter o valor contido em `Some`, você precisa primeiro verificar se ele existe:

```rust
let mut some_words = Option::Some("choose something to say"); // some_words set to something

match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "Here, we will choose something to say"

some_words = Option::None; // some_words now set to None

// Exactly the same match block as above
match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "I've got nothing to say"
```

Cairo tem outras ferramentas além do `match` para verificar e acessar valores contidos em um `Option`, mas o `match` já deve ser familiar para você agora.

Considere isto uma demonstração de por que Cairo usa `Option` em vez de uma referência nula.
A ideia é que **você _precisa_ verificar** se a variável `Option` é `Some` (caso em que você pode extrair e usar o valor contido nela) ou `None`.
Caso contrário, seu programa não vai compilar; o compilador mantém você a salvo do `null`.
