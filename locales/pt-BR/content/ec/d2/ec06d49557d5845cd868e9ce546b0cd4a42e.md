# Sobre

O I/O do Factor é construído sobre um único [protocolo][stream-protocol] que qualquer fonte ou destino de dados pode implementar. Os streams incluídos, `<file-reader>`, `<file-writer>`, `<string-reader>`, `<string-writer>`, sockets de rede, arrays de bytes, ttys, são todas classes que implementam as mesmas poucas generics de [`io`][io] e estendem `disposable` de [`destructors`][destructors].

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe` é a leitura em lote de baixo nível: preenche um buffer fornecido pelo chamador e retorna quantos elementos foram escritos. Os `stream-read` e `stream-read-partial` públicos são construídos sobre ela e cuidam da alocação. A maioria dos streams definidos pelo usuário implementa `stream-read1` (quando as leituras acontecem um elemento por vez) ou `stream-read-unsafe` (quando as leituras podem ser agrupadas em lote).

`stream-element-type` retorna um de dois tokens singleton: `+byte+` para streams de bytes (leitores de arquivo, sockets) e `+character+` para streams de caracteres (leitores de string, ttys). Um stream wrapper geralmente apenas delega para o stream subjacente.

## Entrando nos mixins

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

Uma classe pode ser um, o outro, ou os dois. Entrar no mixin faz com que os métodos padrão de `input-stream` / `output-stream` sejam despachados para a sua classe, o mesmo padrão de mixin aberto que `set`, do vocab `sets`.

## O framework disposable

`new-disposable ( class -- disposable )` registra uma instância nova no escopo de destrutor atual, para que uma exceção no meio da configuração de recursos seja desfeita de forma limpa:

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose` é a palavra pública; `dispose*` é a generic que a classe implementa. Uma sobrescrita de `dispose*` numa subclasse deve limpar o próprio estado e depois descartar os recursos que ela possui:

```factor
M: my-stream dispose* underlying>> dispose ;
```

O framework garante que `dispose*` roda no máximo uma vez por objeto: chamadas repetidas a `dispose` não fazem nada.

## Acessadores com escopo

Três combinadores configuram o "stream de entrada/saída atual" global usado por `print`, `read1` etc.:

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

Cada um descarta o recurso na saída, mesmo que a quotation lance uma exceção. É assim que a maior parte do código usa um stream personalizado, em vez de passá-lo por cada chamada.
