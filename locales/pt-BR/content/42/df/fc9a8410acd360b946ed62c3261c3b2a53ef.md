# Dicas

## Geral

- `movapd` e `movaps` só devem ser usados quando se sabe que um operando de memória está alinhado.
  O uso deles é seguro quando os dois operandos são registradores `xmm`.
- Endereços de memória são passados como valores inteiros.
  Os primeiros seis argumentos inteiros são passados para uma função em `rdi`, `rsi`, `rdx`, `rcx`, `r8` e `r9`, respectivamente.

## 1. Combine os rendimentos de duas linhas

- A adição empacotada de números de ponto flutuante de 32 bits é `addps`.
- Os três argumentos de ponteiro têm garantia de estar alinhados em 16 bytes, então a variante de movimentação alinhada, `movaps`, é a adequada.

## 2. Calcule o desvio escalado

- A subtração empacotada de números de ponto flutuante de 64 bits é `subpd`.
- A multiplicação empacotada de números de ponto flutuante de 64 bits é `mulpd`.
- `measured` está alinhado e `target` não, então eles precisam de variantes de carregamento diferentes.

## 3. Calibre um lote

- `reference` e `offset` estão alinhados, mas `raw` não, então eles precisam de variantes de carregamento diferentes.
- `reference` e `offset` são necessários para as duas linhas.
- Instruções de dois operandos geralmente sobrescrevem o operando de destino.
- Para converter os 2 números de ponto flutuante superiores de `raw` em números de ponto flutuante de 64 bits, use `cvtps2pd` com um operando de memória deslocado 8 bytes em relação ao ponteiro `raw`.
- O fator de conversão deve ser armazenado na memória como 2 números de ponto flutuante de 64 bits (os dois iguais a `0.5`).
- O resultado ocupa 32 bytes (4 números de ponto flutuante de 64 bits): os primeiros 16 bytes em `[result]`, os 16 seguintes em `[result + 16]`.

## 4. Normalize as pontuações ao longo de uma linha

- Instruções de dois operandos geralmente sobrescrevem o operando de destino.
- A memória não pode ser o operando de destino de instruções aritméticas empacotadas.
- Para cada `score` de ponto flutuante de 64 bits no array `scores` (primeiro argumento), há um `gain` equivalente no array `gains` (segundo argumento).
  Cada `score` vai operar com o `gain` na mesma posição.
- O terceiro argumento é um `scale` fixo com 2 números de ponto flutuante de 64 bits empacotados.
- Para cada par `score` e `gain`, a função calcula `score * gain / scale_lane`.
  A primeira lane de `scale` escala o primeiro elemento de cada par (as lanes de posições pares); a segunda lane escala o segundo (as lanes de posições ímpares).
- A pontuação normalizada é armazenada no próprio array `scores`, na mesma posição do `score` que a originou.
- O número de elementos em `scores` e `gains` é o mesmo e igual ao valor de `n` (o quarto argumento).
- Você deve usar um laço para processar todos os pares de elementos, avançando 16 bytes (2 elementos) a cada iteração.
