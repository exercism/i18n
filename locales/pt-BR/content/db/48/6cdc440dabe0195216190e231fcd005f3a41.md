# Sobre

Classes como `LocalDate` e `LocalDateTime` descrevem um _ponto_ no tempo.
O pacote `java.time` também tem duas classes que descrevem uma _quantidade_ de tempo:

- [`Period`][period-docs] é uma quantidade de tempo baseada em data, em anos, meses e dias, como "2 meses e 5 dias".
- [`Duration`][duration-docs] é uma quantidade de tempo baseada em horas, minutos, segundos, milissegundos e nanossegundos, como "1 hora e 30 minutos".

A diferença importa porque as unidades de calendário não têm um tamanho fixo.
Um mês pode ter 28, 29, 30 ou 31 dias, então "um mês" não é um número fixo de segundos.
Um `Period` segue o calendário, enquanto uma `Duration` mede tempo exato.

| | `Period` | `Duration` |
| --- | --- | --- |
| Armazena | anos, meses e dias | segundos e nanossegundos |
| Usado com | `LocalDate`, `LocalDateTime` | `LocalTime`, `LocalDateTime`, `Instant` |

As duas classes são imutáveis.
Métodos como `plusDays()` ou `multipliedBy()` retornam uma _nova_ instância e deixam a original inalterada.

## `Period`

### Criando um período

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

O resultado de `toString()` usa o [formato de duração ISO-8601][iso-8601-durations]: `P` seguido do número de anos (`Y`), meses (`M`) e dias (`D`).
Não existem semanas em um `Period`: `Period.ofWeeks(2)` é armazenado como 14 dias.
A mesma notação pode ser interpretada de volta com `Period.parse()`:

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### Somando um período a uma data

Um período é somado ou subtraído de uma data com `plus()` e `minus()`:

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

Um período pode ser somado a um `LocalDateTime` da mesma forma, e o horário do dia continua o mesmo:

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

Um `Instant` não tem calendário, então só é possível somar a ele um período de dias.
Um período com anos ou meses lança uma exceção:

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

Os anos são somados primeiro, depois os meses e depois os dias.
Quando a soma de anos ou meses cai em um dia que não existe, o resultado é recuado para o último dia válido daquele mês:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

Isso também significa que somar um período e depois subtraí-lo de novo nem sempre devolve a data original:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### O período entre duas datas

`Period.between()` retorna o período de uma data (inclusive) até outra (exclusive).
O mesmo resultado está disponível em `LocalDate.until()`:

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

As partes de um período estão disponíveis por meio de `getYears()`, `getMonths()` e `getDays()`.
Essas partes são independentes entre si: `getDays()` retorna só a parte de dias, não o número total de dias.
`toTotalMonths()` retorna os anos e meses combinados como um número de meses, mas não existe um método para o número total de dias, porque isso depende de quais meses estão envolvidos.

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### Normalizando um período

Um período criado com um método de fábrica mantém suas unidades exatamente como foram informadas, e `equals()` compara as unidades uma a uma.
`normalized()` transforma meses em anos quando eles completam doze, mas deixa os dias como estão:

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## Contando unidades com `ChronoUnit`

Para obter o número total de uma única unidade entre dois pontos no tempo, use o método `between()` em uma das constantes de [`ChronoUnit`][chronounit-docs]:

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

Só unidades completas são contadas, e o resultado é negativo quando o segundo argumento é anterior ao primeiro:

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

`ChronoUnit` também funciona com unidades baseadas em tempo e com data-horas:

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### Criando uma duração

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

Na notação ISO-8601, o `T` separa a parte de data da parte de tempo.
Uma `Duration` não tem parte de data, então seu `toString()` sempre começa com `PT`.
`Duration.ofDays()` trata um dia como exatamente 24 horas.

Uma duração também pode ser interpretada com `Duration.parse()`:

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### Somando uma duração a um horário

Uma duração é somada ou subtraída de um `LocalTime`, um `LocalDateTime` ou um `Instant` com `plus()` e `minus()`:

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

Um `LocalTime` dá a volta na meia-noite, como o último exemplo mostra.

Um `LocalDate` não tem horário, então não pode ser combinado com uma `Duration`:

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### A duração entre dois horários

`Duration.between()` retorna a quantidade exata de tempo entre dois horários ou data-horas:

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

`Duration.between()` não aceita dois valores `LocalDate`, porque uma data não tem segundos para medir:

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

Para datas, use `Period.between()` ou `ChronoUnit.DAYS.between()`.

### Convertendo uma duração

Os métodos `toXxx()` convertem uma duração em uma quantidade _total_ de uma única unidade, arredondada para baixo:

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

Os métodos `toXxxPart()` dividem uma duração em suas partes, como em um relógio:

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

`toHoursPart()` para em 23, porque as horas acima disso são contadas por `toDaysPart()`.

### Comparando e calculando com durações

Durações podem ser comparadas com `compareTo()` e verificadas com `isZero()` e `isNegative()`:

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

Elas também suportam aritmética, como `plus()`, `minus()`, `multipliedBy()` e `dividedBy()`:

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## `Period` ou `Duration`?

Para um `LocalDate` ou um `LocalTime`, a escolha já está feita: uma data não tem horário para medir, e um horário não tem calendário.
Um `LocalDateTime` tem os dois, mas não tem fuso horário, então somar `Period.ofDays(1)` ou `Duration.ofDays(1)` a ele dá o mesmo resultado.
A diferença fica visível com fusos horários.
Quando os relógios avançam no horário de verão, um dia de calendário tem só 23 horas:

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

Somar um `Period` de um dia mantém o horário do dia, enquanto somar uma `Duration` de um dia acrescenta exatamente 24 horas.
Use um `Period` para quantidades que as pessoas pensam em termos de calendário ("o mesmo horário no mês que vem") e uma `Duration` para tempo decorrido ("o ticket do estacionamento vale por 2 horas").
