# Apêndice das instruções

## Dicas

Um dos principais aspectos da programação funcional é ter funções sem efeitos colaterais, sem precisar se perguntar quais objetos ocultos uma função alterou.  

Com a programação reativa, em vez de um component procurar trabalho ativamente, esse trabalho é enviado para ele. Isso é parecido com callbacks, mas em um nível muito mais alto, com abstrações mais poderosas. Muitas vezes, a programação reativa é usada junto com a programação funcional.

No exercício, vamos usar o [RxJava](https://github.com/ReactiveX/RxJava), uma biblioteca conhecida de programação reativa com uma API Java.

O contexto simulado deste exercício é uma aplicação que recebe duas entradas:

- as novas palavras a adivinhar, vindas de algum motor de jogo,
- as letras escolhidas pelo jogador.

Essas duas entradas são implementadas com [Observables](http://reactivex.io/documentation/observable.html), usando a classe [io.reactivex.Observable](http://reactivex.io/RxJava/2.x/javadoc/io/reactivex/Observable.html).
Basicamente, você pode se inscrever em um `Observable` para "reagir" aos valores que são produzidos em algum lugar. Por exemplo, o motor de jogo envia novas palavras quando detecta que um novo jogo começou, ou eventos de teclado geram entradas de letras.  
Mas muitos frameworks reativos oferecem abstrações poderosas, como [`map`](http://reactivex.io/documentation/operators/map.html), que permite mudar a entrada recebida, ou [`combine`](http://reactivex.io/documentation/operators/combinelatest.html), que permite combinar um ou mais `Observable`s.

A classe `Output` é o resultado esperado do processamento do exercício, permitindo que um front-end
exiba o estado completo do jogo sem exigir dele nenhuma forma de armazenamento, o que a torna
funcional também.  
Neste exercício, você precisa encontrar uma maneira de usar as duas entradas para gerar essa saída na forma de um `Observable`.
