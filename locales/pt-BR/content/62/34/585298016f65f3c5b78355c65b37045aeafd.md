# Testes

## Arquivos do exercício

Um exercício baixado inclui estes arquivos para compilar e testar sua solução:

```text
hello-world/
├── HelloWorld.vb       # Your solution
├── HelloWorldTests.vb  # The test suite
├── HelloWorld.vbproj   # Project and build configuration
└── packages.lock.json  # Resolved project dependencies
```

Os nomes dos arquivos variam de exercício para exercício.
Escreva sua solução no arquivo `.vb` cujo nome não termina em `Tests`.
O arquivo que termina em `Tests.vb` é a suíte de testes do xUnit; normalmente, você só deve editá-lo para remover os argumentos `Skip`.
Normalmente, você não precisa editar o arquivo de projeto nem o arquivo de lock.

## Rodar os testes

Abra um terminal no diretório do exercício e rode:

```bash
dotnet test
```

O comando restaura as dependências do projeto, compila o projeto e roda os testes.
Você também pode usar `dotnet watch test` para rodar os testes de novo sempre que um arquivo-fonte mudar.

## Testes ignorados

Os exercícios habilitam inicialmente apenas o primeiro teste, o que permite resolver o resto um passo de cada vez.
Abra o arquivo que termina em `Tests.vb` para encontrar os testes.
Cada teste é uma sub-rotina `Sub` marcada com um atributo `<Fact>` do xUnit.
Um teste ficará ignorado enquanto seu atributo `<Fact>` tiver um argumento `Skip`:

```vb
<Fact(Skip:="Remove this Skip property to run this test")>
Public Sub Lowercase_words()
    Assert.Equal("ROR", Abbreviate("Ruby on Rails"))
End Sub
```

Para habilitar o teste, basta remover o argumento `Skip`:

```vb
<Fact>
Public Sub Lowercase_words()
    Assert.Equal("ROR", Abbreviate("Ruby on Rails"))
End Sub
```

Depois que o teste recém-habilitado passar, repita esse processo com o próximo teste ignorado.
Quando todos os testes estiverem habilitados e passando, você terminou.
