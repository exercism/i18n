# Introdução

A maioria das palavras de sequência que você já viu retorna sequências *novas* e deixa as entradas intactas: `suffix`, `reverse`, `map` e assim por diante. Mas arrays e vetores também aceitam **mutação no lugar**, e os dois aparecem quando você quer registrar um estado que muda com o tempo.

## Dois tipos de sequência mutável

- **Arrays** (`{ … }`) têm comprimento fixo. `<array> ( n elt --
  array )` (em [`arrays`][arrays]) constrói um array novo de comprimento
  `n`, preenchido com cópias de `elt`.
- **Vetores** (`V{ … }`) crescem e diminuem. Use `V{ } clone` para criar um vetor vazio novo; `<vector> ( n -- vector )` (em
  [`vectors`][vectors]) pré-aloca capacidade para `n` elementos.

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## Alterando uma posição

Essas duas funcionam com qualquer um dos dois tipos de sequência: as duas esperam a sequência depois do índice:

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

`set-nth` atribui; `change-nth` aplica uma quotation ao elemento na posição `n`.
Essas duas palavras de [`sequences`][sequences] não retornam nada na pilha: o efeito é a mutação.

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## Crescendo e diminuindo

Essas três só fazem sentido em vetores, já que arrays não podem
mudar de comprimento:

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## Vetor → array

Quando você já montou um vetor e quer devolver um array de comprimento
fixo, `>array ( seq -- array )` (em [`arrays`][arrays]) retorna um
array novo com os mesmos elementos:

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`: mantenha um instantâneo

A mutação modifica a sequência no lugar. Se quem chamou te entrega uma
sequência e você está prestes a alterá-la, `clone` (em
[`kernel`][kernel]) te dá uma cópia nova e independente, para que quem
chamou não veja a sequência mudar sob os próprios pés:

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

A mesma precaução vale para `V{ }` e outros literais vazios. Em
algumas linguagens, `[]` ou `vec![]` aloca um contêiner novo a cada vez
que a expressão é avaliada. Em Factor, o literal `V{ }` escrito no seu
código é *um* único objeto, compartilhado por todo ponto de chamada
que o menciona. Se você der `push` direto em `V{ }`, a próxima chamada
vê as sobras. `V{ } clone` cria a cópia nova que você quase sempre
quer.
