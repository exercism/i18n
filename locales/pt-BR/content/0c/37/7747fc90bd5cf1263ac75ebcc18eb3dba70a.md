# Docker

Nossos Representers são publicados como imagens Docker.

Leia as [informações gerais de Docker do Tooling](/docs/building/tooling/docker) para se familiarizar com o funcionamento delas.

## Integração

Quando executamos um Representer para criar a representação de uma solução, usamos um comando Docker parecido com este:

```shell
docker run \
        --rm \
        --network none \
        --mount type=bind,src="${solution_dir}",dst=/solution \
        --mount type=bind,src="${output_dir}",dst=/output \
        --tmpfs /tmp:rw \
        "exercism/${track_slug}-representer" \
        "${exercise_slug}" "/solution" "/output"
```

Como você pode ver, passamos três argumentos para a imagem Docker:

1. O slug do exercício
2. O caminho para o diretório da solução
3. O caminho para o diretório de saída

## Convenções

Todos os nossos Representers seguem as convenções a seguir na sua implementação:

- O `Dockerfile` fica no diretório raiz do repositório.
- O diretório de trabalho deve ser `/opt/representer`.
- O entrypoint é `/opt/representer/bin/run.sh`
- O script `/opt/representer/bin/run.sh` recebe 3 argumentos:
  1. O slug do exercício
  2. O caminho para o diretório da solução
  3. O caminho para o diretório de saída

Para mais informações, veja [A Interface](/docs/building/tooling/test-runners/interface).

```exercism/note
Os novos repositórios de representer vão usar essas convenções por padrão.
```
