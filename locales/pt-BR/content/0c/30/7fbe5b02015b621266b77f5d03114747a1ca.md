# Introdução

O JavaScript tem um objeto embutido, `Date`, que armazena data e hora e fornece métodos para gerenciá-las.

## Criação

Um objeto `Date` é uma instância da classe `Date`.
Ele pode ser criado sem passar nenhum argumento para a função construtora.
Isso resulta em um objeto `Date` que representa a data e a hora atuais:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### Timestamp Unix (número)

Se um número for passado, ele será interpretado como um `timestamp`.
Um timestamp é um número inteiro que representa a quantidade de **milissegundos** que passaram desde **1º de janeiro de 1970 [UTC][defn-utc]+0**.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

Talvez você espere que `new Date(0)` gere o objeto de data "mais antigo", mas o JavaScript converte a data para o seu fuso horário local, o que significa que só quem está em um fuso [GMT / UTC+0][defn-gmt] vai realmente obter o valor da [época Unix][defn-unix-epoch].

### String de timestamp ISO 8601

Você pode passar para o construtor `Date` uma string que representa uma data.
O **único** formato consistente entre as implementações é a [versão simplificada][mdn-date-string-format] das chamadas [strings de timestamp ISO 8601][defn-iso8601], reconhecidas e padronizadas internacionalmente.

Um momento no tempo em [UTC][defn-gmt] se parece com isto:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

Em que as seguintes substituições acontecem:

| Chave | Descrição                                           | Padrão |
| ----- | --------------------------------------------------- | ------ |
| YYYY  | O ano civil, representado com 4 dígitos             |        |
| MM    | O mês civil, representado com 2 dígitos             | 01     |
| DD    | O dia do mês, representado com 2 dígitos            | 01     |
| T     | Uma letra T literal, que separa a data e a hora     | T      |
| HH    | As horas em um relógio de 24 horas, com 2 dígitos   | 00     |
| mm    | Os minutos, com 2 dígitos                           | 00     |
| ss    | Os segundos, com 2 dígitos                           | 00     |
| mss   | Os milissegundos, com 3 dígitos                     | 000    |
| Z     | Uma letra Z literal, ou um deslocamento `+/-HH:mm`  |        |

A letra literal `Z` indica UTC (sem fuso horário, sem horário de verão).

Como a maioria dos componentes tem valores padrão, é válido omitir partes no final:

```text
YYYY-MM-DD
```

O padrão é o horário 00:00:00.000

Se o timestamp não termina em `Z` e não termina com `+HH:mm` ou `-HH:mm` (que indicam um deslocamento de fuso horário), por motivos históricos vale o seguinte:

> Quando o deslocamento de fuso horário está ausente, formas apenas com data são interpretadas como horário UTC, e formas com data e hora são interpretadas como horário local.
> A interpretação como horário UTC se deve a um erro histórico na especificação, que não era consistente com a ISO 8601, mas não pôde ser corrigido por causa da compatibilidade com a web.
> Veja [Broken Parser – A Web Reality Issue][ref-broken-parser].

### Objeto Date

Um objeto de data existente também pode ser usado como argumento do construtor.
Isso cria uma cópia do objeto `Date` existente, com a mesma data e hora.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### Fornecendo valores individuais de componentes de data e hora

Um objeto de data que representa só uma data pode ser criado passando três números.
Um objeto de data que representa data e hora pode ser criado passando seis números.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

O segundo valor é o `month`, que começa em `0` para janeiro e vai até `11` para dezembro.

## `Date.parse()`

Você pode encontrar menções ou referências a uma função de parse de data, a `Date.parse`.
Como essa função tem poucas invariantes (verdades) e o restante da implementação não é especificado (e, portanto, não é padronizado), não se deve usá-la.

## Acessando os componentes de `Date`

Existem vários métodos em objetos de data que retornam os componentes da data:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

Cada um deles tem uma variante `set` correspondente (por exemplo, `setFullYear`) para atualizar o valor.
Qualquer valor que ultrapasse o limite passa para o próximo componente:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

Há variantes UTC de todos os métodos que ignoram o fuso horário local.

## Convertendo a partir de uma data

Os objetos de data têm um método `getTime()` que retorna o timestamp UNIX em milissegundos, ou seja, a quantidade de milissegundos desde a meia-noite do início de 1º de janeiro de 1970, UTC.
Além disso, há o método `toISOString()` para converter um objeto de data em uma string de timestamp ISO 8601.

## Comparando datas

Os operadores maior que (`>`), maior ou igual a (`>=`), menor que (`<`) e menor ou igual a (`<=`) podem ser usados diretamente entre duas datas, ou entre uma data e um número.
Isso funciona porque o JavaScript tenta converter a data em um primitivo.

<!-- prettier-ignore -->
~~~exercism/advanced
Quando você faz uma comparação entre duas datas, ou entre uma data e um número, o JavaScript chama [`[Symbol.toPrimitive]("number")`][mdn-to-primitive], que internamente chama [`date.valueOf()`][mdn-date-value-of].
Este último é o mesmo que chamar [`date.getTime()`][mdn-date-get-time].

Se você não quiser depender desse comportamento, converta para número primeiro usando `getTime()`.

[mdn-to-primitive]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/Symbol.toPrimitive
[mdn-date-value-of]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/valueOf
[mdn-date-get-time]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/getTime
~~~

Datas não podem ser comparadas com operadores de igualdade (`==` e `===`), mas o resultado de `.getTime()` pode.
