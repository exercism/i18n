# Noções básicas de match

A expressão `match` permite comparar um valor com uma série de padrões de forma simples e, depois, executar o código com base no padrão correspondente. Valores literais, nomes de variáveis, curingas e muitas outras coisas compõem um padrão.

```rust
#[derive(Drop)]
enum Color {
    Red,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red => println!("The color is Red"),
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Yellow;
    print_color_type(color); // prints "The color is Yellow"
}
```

Para lidar com várias linhas de código, o braço de código do `match` deve ser envolvido por chaves `{}`:

```rust
fn specified_color(color: Color) -> felt252 {
    let mut response: felt252 = '';

    match color {
        Color::Red => {
            response = 'You passed in Red';
        },
        Color::Yellow => {
            response = 'You passed in Yellow';
        },
        Color::Green => {
            response = 'You passed in Green';
        },
    }

    response
}
```

A expressão `match` também tem o recurso de se vincular a valores que correspondem ao padrão. Isso torna possível extrair o valor associado de uma variante de enum.

```rust
#[derive(Drop, Debug)]
enum ColorType {
    Light,
    Dark,
}

#[derive(Drop)]
enum Color {
    Red: ColorType,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red(state) => {
            println!("The color is Red");
            println!("The Color Type is {:?}", state);
        },
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Red(ColorType::Dark);
    print_color_type(color);
}
```

Aqui estendemos a variante `Red` do enum `Color` para ter um enum associado. Com a ajuda da expressão `match`, podemos extrair o valor associado: `state`. Esse é simplesmente um nome de variável que pode ser usado depois no braço de código.

## Correspondência com o tipo de enum `Option`

O enum `Option`, que já vem embutido na linguagem, também pode ser tratado com a expressão `match`.

Vamos criar uma função que recebe um parâmetro `Option<u8>`.
Se houver um valor no parâmetro fornecido, some um a esse valor; caso contrário, a função deve retornar o valor `None` sem realizar nenhuma operação.

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
        Option::None => Option::None,
    }
}

fn main() {
    let three: Option<u8> = Option::Some(3);
    let four: Option<u8> = add_one(three);
    let none = add_one(Option::None);

    println!("{three:?}"); // prints "Option::Some(3)"
    println!("{four:?}"); // prints "Option::Some(4)"
    println!("{none:?}"); // prints "Option::None(())"
}
```

> Observação: `{:?}` é uma sintaxe de formatação especial que permite imprimir uma forma de depuração do parâmetro passado para a macro `println!`.
> Você pode encontrar mais informações sobre isso em [The Cairo Book][debugging].

Um benefício de usar o fluxo de controle `match` é sua natureza exaustiva: os padrões dos braços precisam cobrir _todas_ as possibilidades.
Veja a versão do exemplo anterior que não trata o caso `None`:

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
    }
     // this code does not compile, as we forgot to handle the `None` case
}
```

## Padrão que captura tudo com o curinga `_`

Com enums, também podemos executar ações especiais para alguns valores específicos, mas, para todos os outros valores, executar uma ação padrão adicionando um novo braço com `_` como padrão do último braço da expressão `match`.
O padrão `_` é um padrão especial que corresponde a qualquer valor e não se vincula a esse valor.

A função `is_red` recebe um parâmetro e retorna `true` se a cor for `Red` e `false` para qualquer outra cor:

```rust
fn is_red(color: Color) -> bool {
    match color {
        Color::Red => true,
        _ => false,
    }
}
```

## Correspondência de padrões com o operador `|`

A construção de fluxo de controle `match` do Cairo permite comparar um valor com vários padrões usando o operador `|` (_ou_).
Isso ajuda a simplificar o código.

Por exemplo, usando o enum `Color`, queremos escrever uma função que retorna `true` para as cores `Red` ou `Green` e `false` para as outras cores:

```rust
fn is_red_or_green(color: Color) -> bool {
    match color {
        Color::Red | Color::Green => true,
        _ => false,
    }
}
```

## Correspondência de padrões com `felt252` e variáveis inteiras

É possível comparar variáveis `felt252` e inteiras com um conjunto de valores.
No entanto, há algumas restrições:

- Só há suporte a inteiros que cabem em um único `felt252` (ou seja, `u256` não é suportado).
- O 0 precisa ser o primeiro braço.
- Cada braço precisa seguir um segmento sequencial, contíguo aos outros braços.

Vamos implementar um jogo de lançamento de dado de seis lados.
Quando o dado é lançado, obtemos um número entre 0 e 5.
Se o lançamento der 0, 1 ou 2, você ganha.
Se der 3, você pode rolar de novo.
Para os outros valores, você perde:

```rust
fn toss(value: u8) {
    match value {
        0 | 1 | 2 => println!("you won!"),
        3 => println!("you can roll again!"),
        _ => println!("you lost...")
    }
}

fn main() {
    toss(2); // prints "you won!".
    toss(3); // prints "you can roll again!".
    toss(5); // prints "you lost...".
}
```

## Correspondência com tuplas

Tuplas também podem ser comparadas com um conjunto de padrões.
Esses padrões são escritos de forma semelhante a uma tupla.

```rust
#[derive(Drop)]
enum DayType {
    Week,
    Weekend,
    Holiday
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn vending_machine_accept(c: (DayType, Coin)) -> bool {
    match c {
        (DayType::Week, _) => true, // accepts all coins during week day
        (_, Coin::Dime) | (_, Coin::Quarter) => true, // accepts only Dime or Quarter coin for all specified days
        (_, _) => false, // returns false for other instances
    }
}
```

No último braço do `match`, não importa se usamos `(_, _)` ou apenas o curinga `_` para corresponder a qualquer combinação de dia e cor, porque são funcionalmente iguais.
