# Sobre

Quando fazemos pattern matching em um valor em Gleam, precisamos garantir que os padrões cubram todos os valores possíveis do tipo, caso contrário o código não compila.

Esta função deveria ser rejeitada, pois não tratou o caso em que a lista está vazia:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Na maior parte do tempo, em programas Gleam, queremos tratar todos os casos possíveis, mas em alguns programas, como protótipos e scripts rápidos, podemos querer focar apenas no caminho feliz e não escrever código para os outros casos. É aqui que entra o `let assert` do Gleam.

Com let assertions, um padrão pode cobrir apenas alguns dos valores possíveis de um tipo, e se o padrão não corresponder a um valor o programa vai quebrar. Usando `let assert`, podemos escrever a função acima assim:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

As bibliotecas de Gleam nunca devem usar let assertions, pois podem quebrar o programa; em vez disso, devem usar o tipo `Result` e deixar quem desenvolve a aplicação decidir como tratar os erros.
