# Sobre

Para entender [`Box`][box], é útil entender o que são a [pilha e o heap][stack and heap].

A pilha é uma área de memória que funciona como um buffer em que o último a entrar é o primeiro a sair (LIFO). É muito rápido empilhar dados e também é rápido desempilhá-los.
Os dados podem incluir variáveis ou endereços de função, mas precisam ter um tamanho fixo conhecido em tempo de compilação.

Se os dados tiverem um tamanho desconhecido em tempo de compilação ou um tamanho que pode mudar, eles precisam ser alocados no heap. O processo de alocação precisa encontrar
no heap um espaço grande o suficiente para armazenar os dados, escrever os dados no heap e empilhar o endereço de memória desses dados na pilha. Tudo isso leva
bem mais tempo do que simplesmente colocar dados na pilha. Recuperar dados do heap é um pouco mais lento, porque precisamos passar pelo endereço na
pilha e segui-lo até o local dos dados no heap.

`Box` é um ponteiro inteligente que aloca dados no heap. O endereço fica na pilha, apontando para os dados no heap. Um dos [motivos][reasons] para usar `Box`
é colocar dados no heap quando você tem um tipo cujo tamanho não pode ser conhecido em tempo de compilação e quer usar um valor desse tipo em um contexto que exige
um tamanho exato. Um uso prático disso é quando você tem várias structs que quer tratar da mesma forma por meio de uma trait que todas elas implementam, como
no exemplo abaixo.

Digamos que temos duas structs. Cada struct representa algo que pode ser irritante. Podemos fazer cada struct implementar uma trait Annoyance, assim

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

Agora digamos que queremos uma função que nos retorne uma Annoyance com base na hora do dia que passamos para ela. Podemos tentar primeiro isto, que descobrimos que não compila

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

O compilador, com toda a sua boa vontade, nos diz exatamente o que fazer: retornar um objeto de trait em uma `Box`. Se você não sabe o que é um objeto de trait,
uma forma simples de descrevê-lo é como uma maneira de retornar um objeto específico por meio de [despacho dinâmico][dynamic dispatch] a partir de uma função que poderia retornar qualquer objeto
que implemente uma trait especificada. Como precisamos de despacho dinâmico, podemos tentar simplesmente colocar um `dyn` na frente do nome da trait e ver se dá certo.

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

Um dos erros é que o tamanho de `dyn Annoyance` não pode ser conhecido em tempo de compilação. Isso acontece porque `annoy_me` não sabe qual objeto de trait específico
vai retornar antes de ser chamada. Structs que implementam Annoyance podem ter campos diferentes e tamanhos diferentes. E isso nos lembra que
um dos usos de `Box` é para um tipo cujo tamanho não pode ser conhecido em tempo de compilação. Então agora tentamos usar um valor de retorno em uma `Box`, e colocamos em uma `Box` os valores retornados
pela expressão match, assim

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

A assinatura de `Box` é `Box<T>`, em que `T` representa o tipo específico que será colocado em uma `Box`, dentro dos sinais de maior e menor, como em `Box<dyn Annoyance>` acima.

Podemos consumir o objeto de trait em uma `Box` assim

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

que imprime

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

Como `my_annoyance` é do tipo `Box<dyn Annoyance>`, é preciso desreferenciá-lo da `Box` com o operador de desreferência `*`. Depois, ele é referenciado como um
`dyn Annoyance` para que a função `be_annoying` possa tomá-lo emprestado.

Outra forma de implementar isso seria remover a exigência de que o parâmetro tenha tamanho definido. Nesse caso, a compilação criaria uma função separada
para cada variante de Annoyance, para que ela pudesse ser despachada estaticamente (um processo chamado [monomorfização][monomorphization]), assim

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

Ainda outra forma de implementar isso seria a função `be_annoying` aceitar uma `Box<dyn Annoyance>` e usar [coerção de desreferência][deref coercion] para evitar
ter que desreferenciar a `Box` manualmente. Isso transferiria a posse do objeto de trait Annoyance para a função `be_annoying`. Ele sairia de
escopo no fim da função e não estaria mais disponível.

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
