# Introdução

Um **laço** é uma sequência de instruções que pode ser executada mais de uma vez, até que uma condição de término seja satisfeita.

Em x86-64, um laço geralmente é criado com um salto para um rótulo anterior:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Repare que um salto incondicional para um rótulo anterior sempre transfere a execução para esse rótulo.
Isso significa que o laço vai continuar se repetindo para sempre, a menos que haja outro salto para fora da sequência repetida.

Por exemplo, este laço não termina:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

E este laço pode terminar, dependendo de a condição ser satisfeita:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## Laços de contagem

Um laço de contagem quase sempre termina do mesmo jeito: uma instrução que atualiza um contador ou compara dois valores, seguida imediatamente por um salto condicional que decide se deve dar mais uma volta.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
`cmp rsi, 0` não é necessário no código acima porque `sub rsi, 1` já define a `zero flag (ZF)` quando o resultado é `0`.

Embora `cmp` seja a principal forma de testar condições em assembly, muitas instruções atualizam as flags.
Por exemplo, muitas instruções aritméticas com inteiros ou bit a bit atualizam `ZF` quando o resultado é `0`, e `SF` quando o resultado é negativo (ou seja, o bit mais alto está definido).

Você pode consultar uma [referência][reference] para ver quais flags são afetadas por cada instrução.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Repare que, no exemplo acima, presume-se que `rsi` seja maior que `0`.
Se fosse `0`, então `sub rsi, 1` reduziria `rsi` a `-1`, que é um número sem sinal muito grande.
Seria necessário mais `18,446,744,073,709,551,615` iterações antes que o laço finalmente terminasse.
Além disso, como o comprimento do array é `0`, qualquer acesso à memória estaria fora dos limites.

Se não houver garantias sobre o comprimento de um array, existem duas abordagens comuns.

A primeira é mover a condição de término para o início do laço e depois ter um salto incondicional no final:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

A segunda é testar uma vez se o array tem comprimento zero antes do início do laço:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Essa segunda abordagem costuma ser mais eficiente que a primeira, porque há menos desvios no corpo do laço.
Você vai aprender mais sobre isso em um conceito futuro.

~~~~exercism/advanced
Em algumas situações, CPUs modernas conseguem mesclar duas instruções diferentes em uma única operação.
Essa otimização é chamada de **macrofusion**.

Muitas instruções aritméticas, como `sub` e `add`, além de `cmp` e `test`, costumam se fundir com um salto condicional que vem logo depois.
Isso significa que uma instrução como `cmp rax, rdx` seguida imediatamente por um salto condicional geralmente pode ser tratada pela CPU como uma única operação.

A macrofusion depende da CPU, e há alguma variação quanto a quais instruções se fundem com qual salto condicional.

Uma referência útil é [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch].
A seção 3.4.2.2 (Optimizing for Macrofusion) do [Intel optimization reference manual][intel-opt] também lista pares que podem se fundir para CPUs Intel.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
