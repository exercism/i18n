# Tipos de dados genéricos

Genéricos no Cairo permitem escrever código reutilizável que funciona com vários tipos, evitando duplicação e facilitando a manutenção.

Você pode usar genéricos com funções, structs, enums, traits e métodos.

## Funções genéricas

Uma função genérica opera sobre tipos diferentes sem precisar de implementações separadas.

Por exemplo:

```rust
fn largest_list<T>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

Aqui, `T` é um espaço reservado para qualquer tipo.

No entanto, o Cairo exige limites de trait para garantir que o tipo genérico atenda a requisitos específicos.

Se `T` precisa poder ser descartado, podemos atualizar a assinatura:

```rust
fn largest_list<T, impl TDrop: Drop<T>>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

Limites de trait, como `Drop` ou `PartialOrd`, adicionam restrições aos genéricos para operações específicas.

## Restrições anônimas

Se uma implementação de trait não for usada diretamente em uma função, você pode escrever restrições anônimas usando `+`:

```rust
fn smallest_element<T, +PartialOrd<T>, +Drop<T>, +Copy<T>>(list: @Array<T>) -> T {
    let mut smallest = *list[0];
    let mut index = 1;

    while index < list.len() {
        if *list[index] < smallest {
            smallest = *list[index];
        }
        index += 1;
    };

    smallest
}
```

Isso evita nomear traits como `TPartialOrd`, o que reduz a verbosidade.

## Structs com genéricos

Genéricos em structs deixam os campos flexíveis.

Por exemplo:

```rust
#[derive(Drop)]
struct Wallet<T> {
    balance: T,
}

let w = Wallet { balance: 42 };
```

Se uma struct precisa de vários tipos genéricos, basta adicionar mais espaços reservados:

```rust
#[derive(Drop)]
struct Wallet<T, U> {
    balance: T,
    address: U,
}

let w = Wallet { balance: 42, address: '0xabc' };
```

## Enums com genéricos

Enums também podem guardar tipos de dados genéricos.

Por exemplo:

```rust
enum Option<T> {
    Some: T,
    None,
}
```

O enum `Option<T>` pode representar um valor opcional de qualquer tipo.

De forma semelhante, `Result<T, E>` permite definir os tipos de sucesso e de falha:

```rust
enum Result<T, E> {
    Ok: T,
    Err: E,
}
```

## Métodos genéricos

Métodos também podem usar genéricos.

Por exemplo:

```rust
#[derive(Copy, Drop)]
struct Wallet<T> {
    balance: T,
}

trait WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T;
}

impl WalletImpl<T, +Copy<T>> of WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T {
        *self.balance
    }
}

let w = Wallet { balance: 50 };
assert!(w.balance() == 50);
```

Você também pode definir métodos para tipos genéricos específicos, como `Wallet<u128>`:

```rust
trait WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128);
}

impl WalletReceiveImpl of WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128) {
        self.balance += value;
    }
}

let mut w = Wallet { balance: 50 };
w.receive(100);
assert!(w.balance() == 150);
```

## Misturando tipos genéricos

Genéricos dão conta de combinações complexas.

Por exemplo, combinando duas instâncias de `Wallet` de tipos diferentes:

```rust
trait WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2>;
}

impl WalletMixImpl<T1, +Drop<T1>, U1, +Drop<U1>> of WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2> {
        Wallet { balance: self.balance, address: other.address }
    }
}

let w1 = Wallet { balance: true, address: 10 };
let w2 = Wallet { balance: 32, address: 100 };
let w3 = w1.mixup(w2);

assert!(w3.balance);
assert!(w3.address == 100);
```

Ao adicionar as restrições `+Drop`, o compilador garante o tratamento adequado dos recursos.

Genéricos são poderosos, mas exigem um gerenciamento cuidadoso das restrições.

Use-os para escrever código reutilizável, independente de tipo e conciso.
