# Construtores de string

`STR` é imutável; `FSTR` não é. Use `STR` para texto que já está pronto e
`FSTR` para texto que ainda está sendo montado.

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## Sempre atribua o resultado de volta

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

O `FSTR` cresce por **duplicação amortizada**: quando o espaço acaba, ele pega um
array novo e maior, o dobro do tamanho, e copia tudo para lá. Então o resultado
costuma ser o mesmo objeto e, de vez em quando, um objeto diferente. Escrever
`b := b + x` sempre está correto nos dois casos, e é a única forma que vale a
pena aprender.

É a duplicação que faz o trabalho total ser proporcional ao comprimento, e não
ao seu quadrado: as cópias ficam mais raras na mesma medida em que ficam mais
caras.

## Por que não usar `+` em STR?

Juntar um número fixo e pequeno de partes com `+` é claro e funciona bem:

```sather
   return piece + " by " + composer;
```

O problema é só o laço, em que o número de junções não é conhecido quando o
código é escrito. Uma regra geral: se o `+` está dentro de um `loop`, recorra ao
`FSTR`.

## Rotinas úteis

| Chamada | O que faz |
| --- | --- |
| `b + x` | adiciona ao final; `x` pode ser `STR`, `CHAR`, `INT`, `BOOL` … |
| `b.size` | quantos caracteres até agora |
| `b.str` | um `STR` pronto |
| `b.clear` | esvazia, mantendo o espaço |

## Sequências de escape

| Escrito | Significa |
| --- | --- |
| `"\n"` | uma nova linha |
| `"\t"` | uma tabulação |
| `"\""` | aspas duplas |
| `"\\"` | uma barra invertida |
