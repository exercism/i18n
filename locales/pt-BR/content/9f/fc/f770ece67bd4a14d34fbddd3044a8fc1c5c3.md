# Sobre caracteres

Este é potencialmente um assunto _enorme_!
É possível escrever um livro longo sobre ele, e várias pessoas já o fizeram (pesquise "unicode book" na Amazon para ver alguns exemplos).

## Uma breve história

Lidar com caracteres em computadores era muito mais simples em décadas anteriores, quando os programadores assumiam que o inglês era a única língua importante.
Então: 26 letras, maiúsculas e minúsculas, 10 dígitos, vários sinais de pontuação, além de um código (0x07) para tocar um sino, e tudo isso cabia em 7 bits: o conjunto de caracteres [ASCII][wiki-ascii].

Naturalmente, as pessoas começaram a perguntar sobre à, ä e Ł, depois outras pessoas começaram a perguntar sobre ऄ, ஹ e ญ, e os jovens queriam emojis 😱.
O que fazer?

Para encurtar a história, muitas pessoas inteligentes e pacientes tiveram que servir em comitês por anos, definindo os detalhes do conjunto de caracteres [Unicode][web-unicode] e de codificações como [UTF-8][wiki-utf-8], e muito software precisou de uma reescrita _muito_ complicada.
Além disso, muitos bugs novos foram introduzidos.

Para evitar que _tudo_ quebrasse, o projeto do Unicode/UTF-8 garante que os primeiros 127 códigos sejam idênticos ao ASCII _(até o sino)_.

## Caracteres em Kotlin

Linguagens criadas depois de mais ou menos 2005 têm a enorme vantagem de que já existia um padrão Unicode razoavelmente estável.

Kotlin (lançada em 2011) pôde assumir que os usuários usariam uma variedade de línguas (humanas) e precisariam do Unicode para expressá-las.

~~~~exercism/advanced
[Caracteres][ref-char] em Kotlin são [`codepoints`][wiki-codepoint] de 16 bits (UTF-16), o mesmo que um `char` da JVM.
Isso basta para expressar a maioria dos alfabetos escritos, mas não toda a variedade de emojis.

O padrão Unicode completo usa até seis bytes (48 bits) por caractere (chamado de [`grapheme`][wiki-grapheme]).

As `Strings` do Kotlin suportam esse padrão completo usando vários codepoints por caractere, quando necessário.
Por exemplo, 😱 seria `\uD83D` e `\uDE31`.

Infelizmente, o Java não tem suporte nativo a graphemes e, por compatibilidade, o Kotlin também não.

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


Literais de caractere são escritos entre aspas simples e são distintos de strings escritas entre aspas duplas.
Isso provavelmente é óbvio para quem vem do mundo C/C++, mas pode confundir programadores de Python e JavaScript.

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

Converter entre `Char` e `Int` é simples:

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

O compilador permite _algumas_ formas de aritmética de inteiros com `Char`s:

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## Algumas funções para `Char`

Como sempre, há [funções demais][ref-char-lib] para discutir aqui, então esta é apenas uma seleção.

- Para alfabetos apropriados, mude entre maiúsculas e minúsculas com [`uppercase()`][ref-uppercase] e [`lowercase()`][ref-lowercase].
- Teste a caixa com [`isUpperCase()`][ref-isuppercase] e [`isLowerCase()`][ref-islowercase].
- Teste o tipo de caractere com:
  - [`isLetter()`][ref-isletter], cobre muitos alfabetos (as categorias Lu, Ll, Lt, Lm e Lo no unicode)
  - [`isDigit()`][ref-isdigit], no intervalo 0..9 (a categoria Nd no unicode)
  - `isLetterOrDigit()`, combina as duas anteriores
  - [`isWhitespace()`][ref-iswhitespace], qualquer caractere de espaço em branco (as categorias Cc, Zp, Zl e Zs no unicode)

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

Além disso, [expressões regulares][ref-regex] (que serão o assunto de um Conceito posterior) permitem busca e manipulação poderosas.

## Conversões entre listas de `Char` e `String`

Para converter uma `String` em uma `List` de `Char`s, podemos usar `toList()`.

Para converter uma `List` de `Char`s em uma `String`, existe a função [`joinToString()`][ref-jointostring], que recebe um separador (muitas vezes a string vazia) como argumento.

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

Repare que `joinToString()` opera sobre uma List ou um Array.
Para _converter_ um único `Char` em uma string de 1 caractere, use `toString()`.

```kotlin
'a'.toString() // => "a"
```

Para verificar se um caractere está presente em uma `String`, ou em uma lista ou array de `Char`, temos `in`, que corresponde à função [`contains()`][ref-contains].

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
