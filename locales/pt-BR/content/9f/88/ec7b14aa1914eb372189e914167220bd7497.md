# Iteradores personalizados

Você vem usando iteradores desde `bird-survey`. Agora é a sua vez de escrever um.

## yield

Um iterador é como uma rotina, com duas diferenças: o nome termina em `!` e ele entrega valores com `yield` em vez de `return`.

```sather
   markers!(count : INT) : INT is
      loop
         yield 100 * 1.upto!(count);
      end;
   end;
```

`yield` dá um valor ao laço que chamou o iterador e então **espera**. Quando esse laço volta a rodar, o iterador continua logo depois do `yield`, com tudo exatamente como estava: suas variáveis, seu próprio laço, seu lugar.

É isso que um iterador é: uma rotina que pode pausar no meio e ser retomada.

```sather
   loop
      #OUT + TRAIL::markers!(3) + " ";      -- 100 200 300
   end;
```

## Como termina

Um iterador termina de duas maneiras.

**Acabar.** Quando o próprio laço do iterador termina, ou a rotina chega ao fim, acabou: o laço que o chamou termina imediatamente.

**quit.** `quit` termina ali mesmo, sem entregar nenhum valor.

```sather
   named!(names : ARRAY{STR}) : STR is
      loop
         name ::= names.elt!;
         if name = "" then quit; end;
         yield name;
      end;
   end;
```

Isso entrega nomes até encontrar um vazio e para. `quit` é para um iterador o que `return` é para uma rotina, só que não carrega nenhum valor: não há mais nada para entregar.

## once

Um argumento marcado como `once` é calculado uma única vez, quando o laço começa, em vez de a cada volta:

```sather
   markers!(once count : INT) : INT is
```

Use isso para tudo que não muda entre uma volta e outra, o que inclui a maioria dos argumentos. Os próprios iteradores da biblioteca fazem isso: `upto!(once i : SAME)`.

## Iteradores sem valor

Um iterador não precisa entregar nada. `times!` é um exemplo:

```sather
   steps!(once count : INT) is
      loop
         ignored ::= 1.upto!(count);
         yield;
      end;
   end;
```

Um `yield` sozinho não entrega nada e simplesmente deixa o laço seguir.

## Onde fica a posição

Cada *lugar no programa* que chama um iterador mantém a própria posição. É por isso que chamar o mesmo iterador duas vezes no corpo de um mesmo laço o percorre duas vezes. Agora dá para entender por quê: as duas chamadas são duas rotinas pausadas separadas.
