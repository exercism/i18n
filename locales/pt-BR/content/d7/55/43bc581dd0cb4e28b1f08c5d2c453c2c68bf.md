# Tags de analisador

As tags de analisador servem para identificar _como_ uma solução foi resolvida.

Essas tags podem então ser usadas para:

- Ligar uma solução a abordagens
- Ligar uma solução a conceitos
- Buscar soluções com determinadas tags

## Formato

Uma tag é uma string formatada assim: `<category>:<thing>`.

Oferecemos suporte a quatro categorias diferentes, do mais alto nível ao mais baixo:

| Categoria   | Descrição                                       | Especificidade                            | Exemplos                              |
| ----------- | ----------------------------------------------- | ----------------------------------------- | ------------------------------------- |
| `paradigm`  | Um [paradigma de programação][programming-paradigms] | Altíssimo nível, não específico de trilha | `imperative`, `functional`            |
| `technique` | Uma técnica sendo usada                         | Alto nível, a maioria não será específica de trilha | `recursion`, `immutability`           |
| `construct` | Um construto da linguagem                       | Muitos não serão específicos de trilha    | `bitwise-and`, `for-loop`             |
| `uses`      | Uso específico de uma linguagem, como tipos ou métodos | Baixo nível, específico de trilha    | `DateTime.add_seconds`, `IEnumerable` |

Alguns exemplos de tags:

- `paradigm:functional`
- `technique:recursion`
- `construct:bitwise-and`
- `uses:DateTime.add_seconds`

## Tags usadas com frequência

As trilhas são livres para marcar as soluções como quiserem, mas recomendamos tentar usar a lista de tags usadas com frequência abaixo sempre que possível.
Usar um conjunto comum de tags nos permite fazer coisas bem legais, como ligar soluções entre trilhas.
