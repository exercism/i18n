# Docker

Nossos Test Runners são implantados como imagens Docker.

Leia as [informações gerais sobre Docker do Tooling](/docs/building/tooling/docker) para se familiarizar com o funcionamento deles.

## Integração

Quando rodamos um Test Runner para testar uma solução, executamos um comando Docker parecido com este:

```shell
docker run \
        --rm \
        --network none \
        --mount type=bind,src="${solution_dir}",dst=/solution \
        --mount type=bind,src="${output_dir}",dst=/output \
        --tmpfs /tmp:rw \
        "exercism/${track_slug}-test-runner" \
        "${exercise_slug}" "/solution" "/output"
```

Como você pode ver, passamos três argumentos para a imagem Docker:

1. O slug do exercício
2. O caminho para o diretório da solução
3. O caminho para o diretório de saída

## Convenções

Todos os nossos test runners seguem as seguintes convenções na implementação:

- O `Dockerfile` fica no diretório raiz do repositório.
- O diretório de trabalho deve ser `/opt/test-runner`.
- O entrypoint é `/opt/test-runner/bin/run.sh`
- O script `/opt/test-runner/bin/run.sh` recebe 3 argumentos:
  1. O slug do exercício
  2. O caminho para o diretório da solução
  3. O caminho para o diretório de saída

Para mais informações, veja [A Interface](/docs/building/tooling/test-runners/interface).

```exercism/note
Novos repositórios de test runner usarão estas convenções por padrão.
```
