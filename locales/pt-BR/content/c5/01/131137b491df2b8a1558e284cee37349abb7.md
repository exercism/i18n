# Introdução

A linguagem de programação Java usa _exceções_ para lidar com erros e outros eventos excepcionais.

## O que é uma exceção

Uma exceção é um evento que ocorre durante a execução de um programa e que interrompe o fluxo normal das instruções.
As exceções são lançadas explicitamente em Java, e o ato de lançar uma exceção é chamado de _lançar uma exceção_.
O ato de tratar uma exceção é chamado de _capturar uma exceção_.

Em Java, todas as exceções são subclasses da classe `Exception`, que por sua vez é uma subclasse de `Throwable`.

Java distingue dois tipos de exceções:

1. Exceções verificadas
2. Exceções não verificadas

### Exceções verificadas

_Exceções verificadas_ são condições excepcionais que uma aplicação deve prever e das quais deve se recuperar.
Um exemplo de exceção verificada é a `FileNotFoundException`, que ocorre quando um método tenta ler um arquivo que não existe.

Esse tipo de exceção é verificado em tempo de compilação: os métodos que lançam exceções verificadas devem indicar isso na assinatura do método, e o código que chama um método que pode lançar uma exceção verificada precisa tratá-la, ou o código não vai compilar.

Todas as exceções verificadas são subclasses de `Exception` que não estendem `RuntimeException`.

### Exceções não verificadas

_Exceções não verificadas_ são condições excepcionais que uma aplicação geralmente não consegue prever nem das quais consegue se recuperar.
Um exemplo de exceção não verificada é a `NullPointerException`, que ocorre quando um método espera um valor não nulo, mas recebe `null`.

Esse tipo de exceção não é verificado em tempo de compilação: os métodos que lançam exceções não verificadas não precisam indicar isso na assinatura do método, e o código que chama um método que pode lançar uma exceção não verificada não precisa tratá-la.

Todas as exceções não verificadas herdam de `RuntimeException`, que por sua vez é uma extensão de `Exception`.

## Lançando exceções

Um método em Java pode lançar uma exceção usando a instrução `throw`.

### Lançando uma exceção verificada

Ao lançar uma exceção verificada de um método, é preciso indicar isso na assinatura do método usando a palavra-chave `throws`, como mostra o exemplo abaixo.
Isso obriga o código que faz a chamada a prever que uma exceção pode ser lançada e a tratá-la de acordo.

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### Lançando uma exceção não verificada

Ao lançar uma exceção não verificada de um método, não é preciso indicar isso na assinatura do método, embora isso seja permitido.

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## Tratando exceções

O tratamento de exceções em Java é feito com as palavras-chave `try`, `catch` e `finally`.

- As instruções de código que podem lançar uma exceção devem ser envolvidas em um bloco `try`.
- O bloco `try` é seguido por um ou mais blocos `catch`, que capturam as exceções lançadas no bloco `try`.
- Os blocos `catch` são opcionalmente seguidos por um bloco `finally`, que sempre é executado depois do bloco `try`, independentemente de uma exceção ter sido lançada ou não.

O exemplo a seguir mostra como essas palavras-chave funcionam:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

Neste exemplo, quando nenhuma exceção é lançada, o seguinte é impresso:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

No entanto, se a instrução `bankAccount.withdraw(amount)` lançar uma `InsufficientBalanceException`, o seguinte é impresso:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

Ou, caso `bankAccount.withdraw(amount)` lance uma exceção não verificada, o seguinte é impresso:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## Erros

Java também tem uma categoria separada chamada de _Erros_, que são problemas graves e externos a uma aplicação.
Um exemplo de erro é o `OutOfMemoryError`, que ocorre quando uma aplicação tenta usar mais memória do que está disponível no sistema.

Assim como as exceções não verificadas, os erros não são verificados em tempo de compilação.
A diferença é que eles representam problemas de nível de sistema e geralmente são lançados pela máquina virtual Java ou pelo ambiente, em vez da aplicação.
Em geral, as aplicações não devem tentar capturá-los nem tratá-los.

Todos os erros em Java herdam da classe `Error`.
