# Complemento das instruções

## Mensagens de exceção

Às vezes é necessário [levantar uma exceção][raise-an-exception]. Quando você fizer isso, sempre inclua uma **mensagem de erro significativa** que indique qual é a origem do erro. Isso deixa o seu código mais legível e ajuda muito na hora de depurar. Nas situações em que você sabe que a origem do erro é de um tipo específico, você pode optar por levantar um dos [tipos de erro internos][built-in-errors], mas ainda assim deve incluir uma mensagem significativa.

Este exercício em particular exige que você use a [instrução raise][raise-statement] para "lançar" um `ValueError` se a pergunta passada para `answer()` estiver malformada ou for inválida, ou se contiver uma operação desconhecida. Os testes só vão passar se você fizer o `raise` da `exception` e incluir uma mensagem junto com ela.
**Atenção**: a mensagem necessária é diferente para cada cenário, mesmo que o mesmo _tipo de erro_ esteja sendo lançado.
Confira os testes com atenção.

Para lançar um [`ValueError`][value-error] com uma mensagem, escreva a mensagem como argumento do tipo `exception`:


```python
# if the question contains an unknown operation.
raise ValueError("unknown operation")

# if the question is malformed or invalid.
raise ValueError("syntax error")
```

Para _tratar_ um erro lançado dentro de um bloco de código específico, você pode usar um [try-except][handling-exceptions].
Os blocos `try-except` "envolvem" o código que poderia causar um erro, mapeando todas as exceções para um erro, vários erros, ou outros trechos de código que lidem com o problema:


```python
while len(equation) > 1:
        try:
           # The questionable/error-prone code goes here,in an indented block
           # It can contain statements, loops, if-else blocks, or other executable code.
           x_value, operation, y_value, *rest = equation
           ...
           ...

        except:
            # Code for what to do when an error gets thrown in the code above.
            # This could be one error, or more complicated logging, error checking and messaging.
            raise ValueError("syntax error")
```
