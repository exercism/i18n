# Introdução

## Asserções let

Ao fazer correspondência de padrões com um valor em Gleam, precisamos garantir que os padrões cubram todos os valores possíveis do tipo; caso contrário, o código não compila.

Esta função deveria ser rejeitada, pois não trata o caso em que a lista está vazia:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Na maior parte do tempo, em programas Gleam queremos tratar todos os casos possíveis, mas em alguns programas, como protótipos e scripts rápidos, talvez queiramos focar apenas no caminho feliz e não escrever código para os outros casos. É aí que entra o `let assert` do Gleam.

Com as asserções let, um padrão pode corresponder apenas a alguns dos valores possíveis de um tipo e, se o padrão não corresponder a um valor, o programa quebra. Usando `let assert`, podemos escrever a função acima assim:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Bibliotecas Gleam nunca devem usar asserções let, pois elas podem quebrar o programa. Em vez disso, devem usar o tipo `Result` e deixar que quem desenvolve a aplicação decida como tratar os erros.
