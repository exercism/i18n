# Introdução

A maior parte dos dados no Factor fica em *sequências*. Arrays, vetores e strings são todos sequências e compartilham um conjunto comum de palavras do vocabulário [`sequences`][sequences].

## Literais de array

Um array literal usa `{ }` com espaço em branco entre os elementos:

```factor
{ 1 2 3 } .          ! => { 1 2 3 }
{ "a" "b" "c" } .    ! => { "a" "b" "c" }
```

Arrays têm comprimento fixo, então palavras como `suffix` e `remove-nth`, que mudam quantos elementos existem, retornam uma sequência *nova* em vez de aumentar a original.

## Comprimento e indexação

```
length   ( seq -- n   )
first    ( seq -- elt )
rest     ( seq -- tailseq )    ! everything but the first element
last     ( seq -- elt )
but-last ( seq -- headseq )    ! everything but the last element
nth      ( n seq -- elt )      ! 0-based
?nth     ( n seq -- elt/f )    ! 0-based; f when out of bounds
```

```factor
{ 10 20 30 } length .       ! => 3
{ 10 20 30 } first .        ! => 10
{ 10 20 30 } rest .         ! => { 20 30 }
{ 10 20 30 } last .         ! => 30
{ 10 20 30 } but-last .     ! => { 10 20 }
1 { 10 20 30 } nth .        ! => 20
```

`?nth` é a versão segura quanto aos limites: você pode sondar uma posição sem verificar o comprimento antes.

```factor
1 { 10 20 30 } ?nth .       ! => 20
9 { 10 20 30 } ?nth .       ! => f  (out of bounds, no error)
```

## Fatiamento

```
head ( seq n -- headseq )    ! first n elements
tail ( seq n -- tailseq )    ! drop first n
```

```factor
{ 1 2 3 4 5 } 3 head .   ! => { 1 2 3 }
{ 1 2 3 4 5 } 3 tail .   ! => { 4 5 }
```

Os dois lançam um erro se `n` for maior que a sequência. Se `n` for grande demais, `index-or-length` o reduz até o comprimento da sequência, então o corte que vem depois não ultrapassa o fim:

```
index-or-length ( seq n -- seq n' )
```

```factor
{ 10 20 30 40 50 } 3 index-or-length head .   ! => { 10 20 30 }
{ 10 20 } 3 index-or-length head .            ! => { 10 20 }
```

As variantes com asterisco `head*` e `tail*` contam a partir do fim. `head*` descarta os últimos `n` e `tail*` mantém os últimos `n`:

```
head* ( seq n -- headseq )   ! everything except the last n
tail* ( seq n -- tailseq )   ! the last n elements
```

```factor
{ 1 2 3 4 5 } 2 head* .   ! => { 1 2 3 }
{ 1 2 3 4 5 } 2 tail* .   ! => { 4 5 }
```

Para um corte qualquer entre dois índices, `subseq` recebe o *início* (inclusivo) e o *fim* (exclusivo):

```
subseq ( from to seq -- subseq )
```

```factor
1 4 { 10 20 30 40 50 } subseq .   ! => { 20 30 40 }
1 4 "hello" subseq .              ! => "ell"
```

Quando você tem um *início e um comprimento*, some os dois para obter o fim:

```factor
2 dup 3 + "hello world" subseq .  ! => "llo"
```

(Esse é o intervalo de índices `[2, 5)`: três caracteres a partir da posição 2.)

A pergunta inversa, *onde* uma subsequência ocorre, é respondida por `subseq-index`, que retorna o índice inicial da primeira correspondência, ou `f` quando não há nenhuma:

```
subseq-index ( seq subseq -- i/f )
```

```factor
"hello world" "o w" subseq-index .   ! => 4
"hello world" "xyz" subseq-index .   ! => f
```

## Preenchimento

```
pad-head ( seq n elt -- padded )    ! prepend copies of elt
pad-tail ( seq n elt -- padded )    ! append copies of elt
```

Os dois estendem `seq` até que seu comprimento seja pelo menos `n`. Se `seq` já tiver esse comprimento, ele é retornado sem alterações.

```factor
{ 2 5 0 } 6 0 pad-tail .   ! => { 2 5 0 0 0 0 }
{ 4 1 } 5 9 pad-head .     ! => { 9 9 9 4 1 }
```

## As mesmas palavras funcionam em strings

Uma string é uma sequência de caracteres, então tudo acima também funciona em strings: o resultado é apenas outra string em vez de um array:

```factor
"hello" length .            ! => 5
"hello" 3 head .             ! => "hel"
"abc" 6 CHAR: . pad-tail .   ! => "abc..."
```

## Agregação

`sum` e `product` (em [`sequences`][sequences]) somam ou multiplicam os elementos de uma sequência numérica:

```factor
{ 2 5 0 7 } sum .        ! => 14
{ 2 5 3 7 } product .    ! => 210
```

`count` executa um predicado sobre a sequência e retorna quantos elementos o tornaram verdadeiro:

```
count ( seq quot -- n )
```

```factor
{ 2 5 0 7 4 1 } [ even? ] count .    ! => 3
```

## Predicados sobre a sequência inteira

```
any?   ( seq quot -- ? )
all?   ( seq quot -- ? )
empty? ( seq -- ? )
```

```factor
{ 2 5 0 7 } [ 4 > ] any? .      ! => t
{ 2 5 0 7 } [ 0 > ] all? .      ! => f
```

## Construindo uma nova sequência

`suffix` adiciona um elemento ao fim de uma sequência; `prefix` adiciona um ao começo. `unclip` remove o primeiro elemento e `unclip-last` remove o último:

```
prefix      ( seq elt -- newseq )
suffix      ( seq elt -- newseq )
unclip      ( seq -- rest first )
unclip-last ( seq -- butlast last )
```

```factor
{ 7 9 } 3 prefix .             ! => { 3 7 9 }
{ 7 9 } 3 suffix .             ! => { 7 9 3 }
{ 4 0 9 } unclip .s
! => { 0 9 }
! => 4
```

Combinar `unclip-last` e `suffix` dá uma atualização não destrutiva do último elemento (e `unclip` + `prefix` faz o mesmo para o primeiro):

```factor
{ 10 20 30 } unclip-last 2 * suffix .
! => { 10 20 60 }
```

## Convertendo entre tipos de sequência

`>array`, `>vector` e `>string` (em [`arrays`][arrays] e nos vocabulários correspondentes) forçam uma sequência a um tipo concreto específico. Útil quando uma operação retornou um corte ou uma sequência genérica e você precisa de um array (ou de uma string) de volta.

```factor
{ 1 2 3 } 1 tail >array .   ! => { 2 3 }
"hello" >array .            ! => { 104 101 108 108 111 }
{ 65 66 67 } >string .      ! => "ABC"
```
