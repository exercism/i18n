# Instruções

Sua amiga Helma fez um pequeno jogo online que rapidamente ganhou popularidade.
Ele se chama _HellMath_.
A pequena comunidade atraiu alguns trolls que deixam o jogo e os fóruns bem desagradáveis.
Helma pediu para você trabalhar em um novo sistema de permissões para separar os encrenqueiros.

O fórum oferece três ações diferentes:

- Ler
- Escrever
- Remover

Existem quatro tipos de conta, cada um com permissões padrão diferentes:

- Convidados: podem ler posts.
- Usuários e trolls: podem ler e escrever posts.
- Moderadores: podem ler, escrever e remover posts, eles têm todas as permissões.

Helma percebeu que não adianta banir contas de troll.
A estratégia dela é dar a eles a ilusão de que seu tempo é "bem investido", mas os posts deles só são mostrados para outros trolls.
Em qualquer coisa que exija ordenação de prioridade, os trolls ficam por último em qualquer sequência.
Quando entram em um jogo, o grupo de jogadores disponíveis também fica limitado a outros trolls.

Essa prática se chama [banimento oculto][shadow-ban].

## 1. Configure os tipos de usuário e as permissões.

Primeiro, defina uma enumeração `AccountStatus` para representar os quatro tipos de conta: `troll`, `guest`, `user` e `mod`.

Em seguida, defina uma enumeração `Action` para representar os três tipos de permissão: `read`, `write` e `remove`.


## 2. Promova trolls apenas para outros trolls.

Cada post nos fóruns salva o `AccountStatus` de quem postou nos seus metadados.
Certifique-se de que posts de trolls sejam exibidos apenas para outros trolls.

Helma precisa de uma função `display_post`, que recebe dois argumentos do tipo `AccountStatus` e retorna um `bool`.
O primeiro argumento é o status de quem postou, o segundo é o status de quem visualiza.

```cpp
using namespace hellmath;
display_post(AccountStatus::troll, AccountStatus::user);
// => false
display_post(AccountStatus::mod, AccountStatus::guest);
// => true
```

## 3. Verifique as permissões de diferentes usuários.

Helma precisa de uma forma de verificar se uma determinada ação é permitida para um usuário.

Implemente uma função `permission_check`, que recebe uma `Action` como primeiro argumento e um `AccountStatus` para verificar.
Ela deve retornar um `bool` de acordo com as permissões listadas na introdução.

```cpp
permission_check(Action::remove, AccountStatus::guest);
// => false
permission_check(Action::write, AccountStatus::mod);
// => true
```

## 4. Conceda acesso ao jogo e emparelhe jogadores.

Para manter os jogadores de verdade responsáveis por suas ações no jogo, _Hellmath_ nega o acesso aos convidados.
Como mencionado acima, Helma quer que os trolls atormentem outros trolls.
As conexões de jogo entre os outros usuários não têm restrições.

Implemente a função `valid_player_combination`, que verifica se dois jogadores podem entrar no mesmo jogo.
A função tem dois parâmetros do tipo `AccountStatus` e retorna um `bool`.

```cpp
valid_player_combination(AccountStatus::guest, AccountStatus::mod);
// => false
valid_player_combination(AccountStatus::troll, AccountStatus::troll);
// => true
```

## 5. Monte a fila de prioridades.

Com o crescimento enorme do jogo e dos fóruns, Helma agora precisa distribuir poder de processamento e largura de banda entre os usuários.
Para lidar com emergências, os moderadores recebem a prioridade mais alta.
Os convidados ficam na fila atrás dos usuários normais, e os trolls ficam atrás de todo mundo.

Implemente a função `has_priority`, que recebe dois argumentos `AccountStatus` e retorna `true` se, e somente se, a primeira conta tiver uma prioridade estritamente maior que a segunda.

```cpp
has_priority(AccountStatus::guest, AccountStatus::mod);
// => false
has_priority(AccountStatus::user, AccountStatus::troll);
// => true
```
