# Introdução

O [casamento de padrões][pattern-matching] permite escrever código com ramificações expressivas, e a [desestruturação][destructuring] traz uma forma elegante de vincular valores a variáveis.
Dominar as duas é extremamente útil para quem programa em Elm e, quando usadas juntas, elas melhoram muito a legibilidade do código.

## Casamento de padrões simples

O casamento de padrões designa código com ramificações que dependem do formato dos dados manipulados.
Por isso, ele combina naturalmente com o conceito de tipos personalizados, que expressam os vários formatos que um dado pode assumir.
Dado um tipo personalizado `Color` definido como sendo `Blue` ou `Red`, por exemplo, podemos escrever uma função `toString` que faz casamento de padrões sobre a cor para retornar a string correta.

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

O casamento de padrões também funciona para tipos personalizados que não são simples enumerações.
Vamos considerar uma função `hello`, que recebe como parâmetro um `Maybe String`, contendo o nome de uma pessoa ou nada.
Ao fazer casamento de padrões, podemos dar nomes em minúsculas aos dados para vinculá-los a essa variável e depois usá-la no lado direito do casamento.

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

O casamento de padrões precisa ser exaustivo, caso contrário o compilador se recusa a compilar.
Mas, às vezes, não nos importamos com alguns dados nem com alguns ramos de uma expressão case.
Nesses casos, em vez de termos que encontrar um nome de variável para vincular e ter ramos para todos os casos, podemos usar o curinga de sublinhado `_`.

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## Casamento de padrões avançado

Além dos tipos personalizados, também podemos fazer casamento de padrões em tipos que têm literais, como `Char`, `String`, `Int` e `Floats`.

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

Para casar mais de um valor sem aninhamento, um truque comum em Elm é combinar os valores a casar em [_tuplas ad hoc_][ad-hoc-tuples], assim:

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

E, como listas são caras aos programadores funcionais, [também dá para fazer casamento de padrões nelas][pattern-match-lists], com a mesma sintaxe usada para construí-las, usando o operador `::`.

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

Por fim, o casamento de padrões funciona até de forma recursiva, permitindo mergulhar fundo em tipos complexos e recursivos.

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## Desestruturação

A desestruturação é muito parecida com o casamento de padrões, no sentido de que permite vincular variáveis a dados dentro de tipos.
A principal diferença é que chamamos esse mecanismo de "desestruturação" quando só existe um formato possível, e de casamento de padrões quando existem vários formatos.
A desestruturação aparece com frequência em vinculações `let`, em argumentos de função e, claro, em expressões case, misturada com casamento de padrões.

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

A desestruturação pode ser usada em tipos personalizados de variante única, em tuplas e também em registros, onde é muito conveniente.
Para [desestruturar um registro][records-pattern-matching], pode-se usar qualquer número de seus campos: um, dois, ... ou todos os campos.

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

Infelizmente, a sintaxe do Elm não permite desestruturação recursiva de registros.
No exemplo anterior de `Circle`, não há como acessar as posições `x`` and `y`center`center`x`x`y`y`.

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

E uma última dica!
Às vezes queremos acesso fácil tanto a uma coisa como um todo quanto a uma parte dela.
É aí que a [palavra-chave `as`][as-keyword] pode ser útil.
Ela permite dar um nome alternativo a uma coisa como um todo, sem deixar de poder desestruturar seu conteúdo.

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
