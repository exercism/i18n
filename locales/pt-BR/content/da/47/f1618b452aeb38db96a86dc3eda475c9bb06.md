# Instalação

## Preâmbulo

Embora o Regina Rexx tenha sido portado para muitas plataformas, as instruções de instalação vão se concentrar em plataformas desktop de 64 bits com Windows, Linux ou MacOS.

## Etapas de instalação

Vale notar que esta trilha espera que a versão mais recente do [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) esteja instalada (a 3.9.5, na data em que este texto foi escrito). O link acima leva você direto para a seção Files, de onde você escolhe o arquivo para baixar.

### Windows

Uma instalação para rodar nativamente no Windows (em uma janela do CMD ou do Powershell) é feita facilmente pelo navegador, com o botão [`Download Latest Version`](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/Regina395w64.exe/download). Basta clicar, baixar e instalar.

Se você tem, ou quer usar, ambientes de emulação de Linux como:

* [Git for Windows](https://gitforwindows.org/)
* [Cygwin](https://cygwin.com/)
* [MinGW](http://mingw.org/)

os binários nativos do Regina para Windows devem continuar acessíveis, então você pode simplesmente executá-los nesses ambientes e, para a maioria dos casos, isso funciona bem.

Uma ressalva, porém, é que a instrução ADDRESS não funciona corretamente (porque ela faz interface com o sistema operacional hospedeiro). Para obter os melhores resultados nesses ambientes, obtenha o pacote específico do ambiente e instale-o. O site do Regina, por exemplo, hospeda uma [versão específica para Cygwin](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-pc-cygwin.tgz/download) que pode ser instalada.

Como alternativa, se você tem ou quer usar uma distribuição Linux _de verdade_ no Windows, como o [WSL](https://docs.microsoft.com/en-us/windows/wsl/about) ou o [Virtual Box](https://www.virtualbox.org/), basta seguir as instruções da seção sobre Linux para a distribuição correspondente.

### Linux

As instalações no Linux costumam ser bem diretas quando se usa o gerenciador de pacotes do sistema. O problema aparece, porém, quando os pacotes disponíveis _não_ são os mais recentes. Infelizmente, é o caso do Regina.

Ainda é possível fazer uma instalação a partir de pacotes, obtendo manualmente o pacote mais recente. O site do [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) hospeda pacotes para distribuições da família Debian (inclui Ubuntu) e da família RHEL (inclui Fedora, CentOS, Rocky e Alma), entre outras.

Para a distribuição escolhida, você precisa baixar dois pacotes: um pacote de biblioteca e um pacote de binários. Por exemplo, para instalar no Debian ou no Ubuntu, faça o seguinte:

```plain
sudo apt update && sudo apt -y install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx_3.9.5-2_amd64-Debian-11.deb > regina-rexx_3.9.5-2_amd64-Debian-11.deb
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3_3.9.5-2_amd64-Debian-11.deb > libregina3_3.9.5-2_amd64-Debian-11.deb
sudo apt -y install libregina3_3.9.5-2_amd64-Debian-11.deb regina-rexx_3.9.5-2_amd64-Debian-11.deb
```

E no CentOS e no RHEL 7, tente:
```plain
sudo yum update && sudo yum install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
sudo yum localinstall libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
```

E no Fedora, Rocky e Alma, tente:
```plain
sudo dnf update && sudo dnf install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
sudo dnf localinstall libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
```

Quando uma instalação a partir de pacotes não é possível, ou se mostrou problemática, sempre dá para compilar a partir do código-fonte, com o arquivo disponível em:

```plain
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5.tar.gz > regina-rexx-3.9.5.tar.gz
```

Supondo que as ferramentas de compilação padrão (gcc, make) estejam instaladas (se não estiverem, siga as instruções aqui: [Install Development Tools](https://ostechnix.com/install-development-tools-linux/)), execute os seguintes passos:

```plain
tar -xzvf regina-rexx-3.9.5.tar.gz && cd regina-rexx-3.9.5
./configure
sudo make
sudo make install
```

A biblioteca (`libregina.so`) e dois conjuntos de binários (`rexx` e `regina`) são instalados (o local padrão é `/usr/local/bin`).

O binário `rexx` é vinculado estaticamente, portanto é autossuficiente e está pronto para usar.

O binário `regina` é vinculado dinamicamente e por isso exige alguma configuração para conseguir localizar a biblioteca compartilhada `libregina.so` em tempo de execução. Para isso, siga estes passos:

```plain
# Configure shared library location
sudo su
echo /usr/local/lib64/ > /etc/ld.so.conf.d/regina-rexx-3.9.5-x86_64.conf
echo /usr/local/lib64/regina-rexx/addons > /etc/ld.so.conf.d/regina-rexx-addons-x86_64.conf
cd /usr/local/lib64
rm -f libregina.so libregina.so.3
ln -s libregina.so.3.9 libregina.so
ln -s libregina.so.3.9 libregina.so.3
ldconfig
exit

# Check symbolic link creation
ls -l /usr/local/lib64/

# Output should be similar. Note symbolic links.
-rw-r--r--. 1 root root 3887554 Dec  1 18:22 libregina.a
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so -> libregina.so.3.9
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so.3 -> libregina.so.3.9
-rwxr-xr-x. 1 root root  574104 Dec  1 18:22 libregina.so.3.9
drwxr-xr-x. 2 root root      26 Dec  1 18:22 pkgconfig
drwxr-xr-x. 4 root root      33 Dec  1 18:22 regina-rexx

# Check library path, and executable using that path
ldconfig -p | grep regina
ldd /usr/local/bin/regina

# Alternate for local user
export LD_LIBRARY_PATH=${LD_LIBRARY_PATH}:/usr/local/lib64:/usr/local/lib64/regina-rexx/addons
```

Lembre-se de que compilar a partir do código-fonte, com a configuração de sistema que isso exige, é uma tarefa mais indicada para usuários experientes.

### MacOS

A instalação tem três etapas:

* Instale o gerenciador de pacotes [Homebrew](https://brew.sh)
* Localize e abra o aplicativo `Terminal`
* Na linha de comando do `Terminal`, digite o seguinte:

   `brew install regina-rexx`

Isso _deve_ instalar a versão mais recente.

Se isso não acontecer, você pode baixar o pacote [Regina for MacOS](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-apple-darwin21.6.0.tgz/download) e instalá-lo manualmente.

## Após a instalação

### Verificação da instalação

Depois de concluir a instalação, você pode verificar se o [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) foi instalado com sucesso rodando este comando em um terminal:

```plain
rexx --version=v
```

Tanto no Windows quanto no Linux, a seguinte saída aparecerá no terminal:

```plain
3.9.5
```

que é o número da versão do interpretador.

Um segundo binário, `regina`, também é instalado. Ele é idêntico ao `rexx` em todos os aspectos, exceto por se vincular a uma biblioteca compartilhada, e é o interpretador a usar quando você quiser acessar funções utilitárias externas. Veja a seção [Acesso a rotinas externas](###accessing-external-routines).

Nenhum outro componente de software precisa ser instalado para começar a usar a trilha (supondo que a CLI do Exercism já esteja instalada).

As notas de uso abaixo dão uma base inicial para usar o interpretador pela linha de comando.

### Uso

Um script Rexx normalmente tem a extensão _`.rexx`_, embora isso não seja obrigatório, pois o interpretador tenta executar qualquer nome de arquivo passado como argumento e, se ele contiver código Rexx válido, roda com sucesso.

O comando a seguir tenta executar um arquivo chamado `hello.rexx`:

```plain
rexx hello.rexx
```

Supondo que o arquivo contenha o seguinte código:

```rexx
say "Hello, world!"
exit 0
```

a saída no terminal seria:

```plain
Hello, world!
```

A mesma saída apareceria se o arquivo fosse renomeado para `hello.txt` e executado assim:

```plain
rexx hello.txt
```

Também vale muito saber que dá para enviar o código do script por pipe para o interpretador, em vez de mantê-lo em um arquivo. O código anterior pode ser executado por pipe assim:

```plain
echo "say 'Hello, world' ; exit 0" | rexx
```

e funciona igualmente bem em um terminal Linux ou em um terminal do Powershell do Windows.

### Uso avançado

É possível passar um ou mais argumentos de linha de comando para arquivos de script, e eles podem retornar códigos de retorno numéricos inteiros arbitrários. No entanto, o interpretador precisa saber que vários argumentos serão passados ao script, o que se faz com a opção `-a`.

Por exemplo, suponha que o arquivo `multiarg.rexx` contenha o seguinte código:

```rexx
say "My name is" ARG(1) || ", your name is" ARG(2) || ", and the script return code will be" ARG(3) || "."
exit ABS(ARG(3))
```

Para garantir que os vários argumentos do script sejam interpretados corretamente, o script é executado assim:

```plain
rexx -a multiarg.rexx "John" "Jill" 5
```

o que produz a seguinte saída no terminal:

```plain
My name is John, your name is Jill, and the script return code will be 5.
```

e o código de retorno do programa (acessível via `$?` no Linux ou `%errorlevel%` no Windows) definido com o valor 5.

### Acesso a rotinas externas

O Regina dá suporte ao uso de rotinas residentes em bibliotecas compartilhadas externas. Várias delas estão disponíveis no site do Regina. A instalação dessas bibliotecas, porém, não é tratada aqui.

O Regina vem, sim, com uma dessas bibliotecas incluída, a _regutil_. Ela contém várias rotinas de uso geral, inclusive para matemática, manipulação de arquivos e do sistema de arquivos, e tarefas de acesso ao sistema.

Nenhuma etapa adicional de instalação é necessária. Porém, para usar essas rotinas em um script, é preciso registrá-las quando o interpretador é carregado. Isso exige apenas duas chamadas de função, e o processo é ilustrado aqui.

Um arquivo, `access-external.rexx`, contém o seguinte código:

```rexx
/* Register external library and functions */
call RxFuncAdd 'SysLoadFuncs', 'regutil', 'SysLoadFuncs'
call SysLoadFuncs

say "Value of pi is" SysPi()
say "Square root of 25 is" SysSqrt(25)
say "Square root of 2 is" SysSqrt(2)

/* Deregister */
call SysDropFuncs

exit 0
```

Para carregar e usar essas rotinas, é preciso usar o binário `regina`, então o script seria executado assim:

```plain
regina access-external.rexx
```

e a seguinte saída aparece no terminal:

```plain
Value of pi is 3.141592654
Square root of 25 is 5.000000000
Square root of 2 is 1.414213562
```

Se, em vez disso, o binário `rexx` tivesse sido usado, a saída no terminal em uma plataforma Windows seria:

```plain
'SYSLOADFUNCS' is not recognized as an internal or external command,
operable program or batch file.
'SYSPI' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSDROPFUNCS' is not recognized as an internal or external command,
operable program or batch file.
```

enquanto em uma plataforma Linux a saída no terminal seria:

```plain
sh: SYSLOADFUNCS: command not found
sh: SYSPI: command not found
sh: SYSSQRT: command not found
sh: SYSSQRT: command not found
sh: SYSDROPFUNCS: command not found
```
