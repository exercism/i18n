# Sobre

Como explorado no conceito [`Nothingness`][concept-nothingness], o R tem várias formas de representar dados que estão ausentes ([`NULL`][ref-null]), desconhecidos ([`NA`][ref-na]) ou matematicamente inválidos ([`NaN`][ref-finite], [`Inf`][ref-finite]).
Em geral, o R vai tentar usar esses valores para sinalizar problemas ali mesmo e continuar sem lançar uma exceção.

## `stop()`

Alguns problemas são fundamentais demais para deixar o programa continuar. 
Nesse caso, use [`stop(msg)`][ref-stop] para interromper o programa imediatamente com um `Error` e imprimir `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Semelhante a um [`assert`][wiki-assert] em outras linguagens, [`stopifnot()`][ref-stopifnot] é um wrapper conveniente para `stop()`.
Os argumentos são um número arbitrário de condições booleanas, separadas por vírgulas, e o programa só continuará se todas forem `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

O R tem uma variedade de formas de lidar com erros.
Elas são baseadas em Common Lisp e diferem significativamente de muitas linguagens populares.

A mais simples é envolver o código potencialmente problemático em [`try()`][ref-try].

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning] e [`message()`][ref-message]

Essas são respostas a condições não fatais, por exemplo:

- Para avisar sobre um problema do qual o programa poderia ao menos se recuperar em parte.
- Para informar ao usuário sobre o progresso de um programa de longa duração.

Uma diferença entre elas é que os avisos são armazenados em cache e (por padrão) exibidos quando a função retorna, mas as mensagens são exibidas imediatamente.
Existem muitas formas de alterar o comportamento padrão, além do escopo aqui.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

A função [`suppressWarnings()`][ref-warning] pode, ocasionalmente, ser útil no Exercism, para evitar confundir o test runner com saída indesejada.

## Tratadores de condições

O R tem uma forma alternativa de lidar com estados de erro, mais próxima em espírito da abordagem de Java e linguagens relacionadas.

Os detalhes estão além do escopo neste conceito, mas quem tiver interesse deve dar uma olhada em [`tryCatch`][ref-conditions] e [`withCallingHandlers`][ref-conditions].
