# Números de ponto flutuante

`FLTD` guarda um número que pode ter uma parte fracionária. Um literal precisa de um ponto decimal e de um `d`:

```sather
   440.0d
   0.5d
   -2.25d
```

`FLT` é a mesma ideia com metade da precisão. Esta trilha usa `FLTD` do começo ao fim; não há motivo para recorrer a `FLT`, a menos que a memória esteja apertada.

## Aritmética

| Operador | Significado |
| --- | --- |
| `+` `-` `*` | como no `INT` |
| `/` | divisão, mantendo a parte fracionária |

Não existe `%` para `FLTD`.

Os dois operandos precisam ser `FLTD`. Misturar um `INT` é um erro de compilação, não uma conversão silenciosa, e isso é proposital: o único lugar em que isso incomoda é exatamente onde as pessoas erram.

## Conversão

```sather
   7.fltd            -- 7.0, an INT made into an FLTD
   7.5d.int          -- 7, the fraction thrown away
   7.5d.round        -- 8, to the nearest whole number
   7.5d.floor        -- 7.0, down to a whole number
   7.5d.ceiling      -- 8.0, up to a whole number
```

Converta antes de dividir, nunca depois: `n.fltd / 2.0d` mantém a metade, mas `(n / 2).fltd` já a perdeu.

## Rotinas úteis

```sather
   (-2.5d).abs       -- 2.5
   2.0d.sqrt         -- 1.41421
   (2.0d).max(3.0d)  -- 3.0
```

## Ponto flutuante é aproximado

Um `FLTD` guarda uma aproximação muito próxima, não o valor exato. A maioria das frações decimais não pode ser armazenada com exatidão, do mesmo jeito que um terço não pode ser escrito exatamente em decimal. Então:

```sather
0.1d + 0.2d          -- very nearly 0.3, but not exactly
```

Duas consequências que vale a pena lembrar:

**Não compare com `=`.** Dois cálculos que deveriam dar a mesma resposta muitas vezes diferem nos últimos dígitos. Em vez disso, verifique se eles estão próximos:

```sather
   (a - b).abs < 0.0001d
```

**Somar muitos valores pequenos perde precisão.** Cada soma arredonda um pouco, e os erros se acumulam.

Quando os valores precisam ser exatos, em especial dinheiro, conte em unidades inteiras com `INT` (centavos em vez de dólares).

## Impressão

`.str` mostra cerca de seis dígitos significativos, o que é menos que a precisão realmente armazenada:

```sather
   #OUT + (1.0d / 3.0d).str;      -- 0.333333
```
