## <a name="virtual-environments"></a>Ambientes virtuais

Os ambientes virtuais do Python oferecem isolamento leve de runtime e de pacotes.
 Eles ajudam a organizar seus projetos ao manter os pacotes Python que você instala agrupados dentro do diretório de um ambiente específico.
Ambientes diferentes podem conter versões diferentes do runtime do Python, junto com as dependências de qualquer projeto ou biblioteca.
Isso ajuda a evitar bugs e incompatibilidades causados por atualizar uma biblioteca de um projeto e "quebrar" uma dependência de outro.

Existem muitas ferramentas de *ambiente virtual* e *similares a ambientes virtuais* em uso hoje, e um movimento crescente para usar [metadados de script inline][PEP723], [dev containers][dev containers] ou [docker][docker] em vez de ambientes virtuais.
É importante experimentar estratégias diferentes e encontrar a que combine com seu estilo de desenvolvimento e as necessidades do seu projeto.
Não presuma que as estratégias aqui servem para todo mundo ou que são suas únicas opções.
Para uma visão mais geral de ferramentas que não são abordadas aqui, confira [este post do blog do Bas Nijholt][bas nihholt] e não perca a curiosidade.


Vamos abordar aqui três ferramentas principais de *ambiente virtual*: a [`venv`][venv] da biblioteca padrão do Python; o [`conda env`][condaenv] de terceiros, que usa o gerenciador de pacotes [`conda`][conda] e (_geralmente_) a distribuição Anaconda do Python; e o [`uv`][uv], um substituto de terceiros para `pip` + `venv`.
As três são bem simples de usar e/ou instalar.

Além disso, [`PyEnv`][pyenv], [`Poetry`][poetry] e [virtualenvwrapper][virtualenvwrapper] são ferramentas que ajudam a gerenciar várias versões do Python e vários ambientes Python na mesma máquina.

### <a name="creating-a-virtual-environment-with-venv"></a>Criando um ambiente virtual com `venv`

Para criar um ambiente virtual com `venv`, use `cd` para ir até o diretório onde você quer guardar seus ambientes.
Esse diretório deve ser **separado** do código do seu projeto e **não** deve ser incluído no controle de versão.
Em seguida, execute o comando `venv` com o nome de uma pasta onde você quer guardar esse **ambiente** específico.
A convenção comum é chamar essa pasta de `<project-name-here>_venv`:

**Windows**

```powershell
PS C:\Users\foobar> py -m venv {name_of_virtualenv}
```
Para ativar o ambiente virtual, execute o seguinte comando:

```powershell
PS> .\{name_of_virtual_env}\Scripts\activate.bat
(venv) PS> _
```

<br>

**Linux/MacOS**

```bash
$ python3 -m venv {name_of_virtualenv}
created virtual environment ... in 8568ms
```

Para ativar o ambiente virtual, execute o seguinte comando:

```bash
$ source {name_of_virtual_env}/bin/activate
(venv) $ _
```

Depois que uma `venv` está ativada, você pode executar comandos `pip` para instalar pacotes "dentro" do ambiente.
Os pacotes instalados ficam associados à versão do Python da `venv` e são guardados dentro de `{name_of_virtual_env}/Lib`.

*Desativar* um ambiente virtual é feito chamando o script `deactivate`, que fica no mesmo diretório que o `activate`.

### <a name="creating-a-virtual-environment-using-conda"></a>Criando um ambiente virtual com `conda`

*A versão mais recente do `conda` pode ser instalada via [miniconda][miniconda].*
Este [cheat sheet do `conda`][conda-cheatsheet] é muito útil, assim como a [documentação do `conda`][conda-docs].

Criado originalmente como um gerenciador de pacotes Python para a popular [`Anaconda distribution`][anaconda] de "Python científico", o `conda` depois foi generalizado e ampliado.
Os ambientes do Conda são parecidos com as `venv`s, com a diferença principal de que o conda pode criar ambientes virtuais e instalar pacotes para muitas outras linguagens de programação além do Python.

As linguagens compatíveis com o Conda incluem `R`, `JavaScript`, `Ruby`, `Fortran`, `C/C++`, `Scala`, `Java` e outras.
Para uma comparação entre comandos do conda e do venv, veja a [referência de comandos][conda command ref] do conda.

### <a name="uv">UV

Trabalhando em projetos com uv: [uv][uv-docs]

O `uv` é uma ferramenta de gerenciamento de pacotes e projetos Python da [Astral][astral], escrita em [Rust][rust programming language].
Ele foi criado para substituir o `pip`, o `venv`, o `poetry` e outras ferramentas de empacotamento e gerenciamento de dependências do Python.
Diferente do `Conda` ou do `Mamba`, o uv é especializado apenas em Python.
 Porém, o uv dá suporte à compilação de módulos de extensão do Python escritos em outras linguagens, como Fortran.
A Astral também é a desenvolvedora do popular linter [Ruff][ruff] e do [TY][ty], um verificador de tipos estático para type hints do Python, ambos escritos em Rust.


Em vez de entrar em detalhes aqui, a [documentação do UV][uv documentation] é sua melhor fonte para instalação e configuração.

### <a name="virtual-environment-wrapper">Wrapper de ambiente virtual

Documentação e contexto: [virtualenvwrapper][virtualenvwrapper].

O pacote `virtualenvwrapper` funciona sobre o `venv` para gerenciar todos os seus ambientes virtuais em um só lugar.
 Você pode criar, copiar, excluir e alternar entre ambientes com comandos no estilo Linux, como `lsvirtualenv` (_para listar ambientes_) e `mkvirtualenv` (_para criar um ambiente_).
  Ele também permite adicionar ferramentas de gerenciamento extras por meio de extensões.
  Você pode até criar suas próprias extensões para a ferramenta usando [este tutorial][venv wrapper tutorial].

<br>

### <a name="pyenv"></a>PyEnv

`pyenv` é o fork para Python das populares ferramentas `rbenv`/`ruby-build`, adaptadas para o Python.
Ele é essencialmente um conjunto de scripts e shims que permitem definir versões do Python tanto globalmente quanto por usuário.
Ele procura seguir a tradição Unix de uma ferramenta discreta, de propósito único, que faz uma coisa bem feita.

O `pyenv` e sua documentação estão no [GitHub][pyenv on github].

### <a name="visual-studio-code"></a>Visual Studio Code

[O Visual Studio Code (VS Code)][vscode] é um editor de código gratuito criado pela Microsoft.
Ele tem ótimo suporte tanto para [ambientes virtuais/conda][virtual environments in vscode] quanto para o [`docker`][docker in vscode] (_por meio do [plugin do docker][vs code docker plugin]_) e pode ser estendido com muitos plugins diferentes para [testes][python testing in vscode], [linting][linting python in vscode], [formatação][formatting python in vscode] e [desenvolvimento web][python web dev in vscode].

#### <a name="python-for-vs-code"></a>Python para o VS Code

_Id da extensão: ms-python.python_

![Cabeçalho da extensão Python no VS Code](https://raw.githubusercontent.com/exercism/python/main/docs/img/VSCode-EXT-Python-Header.png)

A partir da [versão mais recente][vs code python latest release], instalar a extensão Python da Microsoft também baixa o [pylance][vs code pylance] (_um pacote popular para fazer linting e validar código Python_) e o [jupyter][vs code jupyter] (_para trabalhar com Jupyter Notebooks_).

### <a name="spyder-ide">Spyder IDE

[O Spyder][spyder-ide] é uma IDE Python gratuita, de código aberto e multiplataforma, feita sob medida para a comunidade científica.
Ele normalmente vem incluído com a distribuição Anaconda do Python, mas pode ser [instalado por conta própria][spyder standalone installers] e usado com qualquer versão do Python.
Recomendamos uma instalação independente para garantir a máxima flexibilidade e evitar conflitos entre pacotes.

O Spyder tem suporte total a ambientes `venv` e `conda`.
Ele inclui um terminal interativo [IPython][ipython] integrado, um depurador interativo e amplo suporte a gráficos e exploração de dados dentro do editor.
Recursos adicionais de autocompletar código e linting são fornecidos pelo [kite][kite].
As integrações com [Jupyter Notebooks][spyder notebook plugin] e [ferramentas de teste][spyder unittest plugin] são fornecidas por plugins desenvolvidos pela comunidade.
Você também pode escrever [seus próprios plugins][writing spyder plugins] usando a API do Spyder.

### <a name="vim"></a>Vim

[O Vim][vimdotorg] é uma versão gratuita e "melhorada" do editor de texto `vi`, padrão do Unix.
Ele está disponível em uma grande variedade de sistemas operacionais e distribuições Linux/Unix.
Um ótimo [guia de instalação e configuração][vim setup at real python] está disponível no Real Python, e cheat sheets bem práticos estão em [vimsheet][vim cheat sheet], [glump][glump vim cheatsheet] e [rtorr][rtorr vim cheat sheet].


Mesmo que você decida que editar código Python no `vim` não é para você, é recomendável se familiarizar com um conjunto básico de comandos.
O `vim` ou o `vi` costuma ser um editor de texto "básico" ou "padrão" em distribuições Linux e Unix, e é o editor padrão para mensagens de commit do `git` (_entre outras coisas_) nesses sistemas.
É bem provável que você se veja em um sistema *nix precisando editar um arquivo de configuração com apenas o `vi` disponível, então saber como [sair do vim][how do I quit vim] é (_no mínimo_) uma boa autodefesa.
