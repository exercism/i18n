# Introdução

Julia, como a maioria das linguagens de programação, oferece uma grande variedade de tipos de coleção.

Alguns são ordenados por natureza (incluindo `Vectors` e `Arrays` de dimensões maiores), então podemos acessar os elementos pela posição.
Outras coleções não têm ordem (`Sets`, `Dicts`), e os elementos precisam ser acessados pela chave ou pelo valor.

No caso mais simples, suponha que temos um `Vector` de `Ints` e queremos ordená-lo em ordem crescente.

```julia-repl
julia> v = [3, 2, 4, 1]
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v)
4-element Vector{Int64}:
 1
 2
 3
 4

# sort descending
julia> sort(v, rev=true)
4-element Vector{Int64}:
 4
 3
 2
 1
```

Simples!
A função `sort()` tem um nome óbvio e, aparentemente, retorna o `Vector` ordenado.

_Só brincadeira!_
A essa altura do curso, você talvez suspeite (com razão) que existem nuances que precisamos discutir.

## Funções que modificam vs. funções que não modificam

Depois de rodar `sort(v)`, o que é `v`?

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> issorted(v)
false
```

O vetor original não mudou.
`sort()` é uma função ***que não modifica*** a entrada: ela retorna uma _cópia_ dela.

Isso é um bom design em muitos contextos: temos uma função pura cujo comportamento é fácil de entender, até mesmo em código paralelo e distribuído.

Por outro lado, suponha que tivéssemos um array de um bilhão de strings e quiséssemos ordená-lo.

A ordenação provavelmente é lenta.
Além disso, precisamos copiar tudo (_lento!_) e alocar memória suficiente (_vários GigaBytes!_) para guardar a cópia.

Compare com este código bem parecido:

```julia-repl
# v is as previously

julia> issorted(v)
false

julia> sort!(v)
4-element Vector{Int64}:
 1
 2
 3
 4

julia> v
4-element Vector{Int64}:
 1
 2
 3
 4

julia> issorted(v)
true
```

Agora o `Vector` de entrada é ordenado no lugar, sem cópia, e a ordem original é perdida para sempre.

Isso pode ser eficiente, pode ter bugs e causar efeitos colaterais inesperados, e pode confundir outras pessoas que usam o seu código.
_Escolha com cuidado!_

`sort!()` é uma "função que modifica", e por convenção (_muito forte_), toda função que modifica suas entradas tem um `!` acrescentado ao nome, como aviso para quem programa.

## Ordenar por array de índices

Se os elementos que estão sendo ordenados forem objetos grandes, pode ser mais fácil trabalhar com o índice de posição deles.

```julia-repl
julia> langs = ["Julia", "C++", "Python", "Elixir"]
4-element Vector{String}:
 "Julia"
 "C++"
 "Python"
 "Elixir"

julia> inxs = sortperm(langs)  # => Integers
4-element Vector{Int64}:
 2
 4
 1
 3

julia> langs[inxs]  # sort the entire vector
4-element Vector{String}:
 "C++"
 "Elixir"
 "Julia"
 "Python"

julia> langs[inxs[1:2]]  # slice the indices
2-element Vector{String}:
 "C++"
 "Elixir"
```

Como `langs` é um Vector, cada índice é um número inteiro no intervalo `1:length(langs)`.
A saída de `sortperm()` é uma permutação desses inteiros, correspondendo a uma ordenação do vetor de entrada.
