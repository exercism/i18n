# Sobre

As charlists são criadas usando o sigil `~c`.

```elixir
~c"hello"
```

~~~~exercism/note
Observe que, em versões mais antigas do Elixir, as charlists são representadas como `'hello'` com aspas simples.
~~~~

Uma charlist é uma lista de inteiros. Os inteiros representam os valores Unicode de um determinado caractere, também conhecidos como pontos de código.

```elixir
[65, 66, 67]
# => ~c"ABC"
```

## Charlists _são_ listas

```elixir
~c"" === []
# => true

is_list(~c"hello")
# => true
```

Como charlists são listas, você pode trabalhar com elas como faria com qualquer outra lista: usando recursão e pattern matching, ou usando o módulo [`List`][list].

```elixir
[first_letter | _] = ~c"cat"
first_letter
# => 99

List.first(~c"hello")
# => 104
List.pop_at(~c"hello", 0)
# => {104, ~c"ello"}

```

Você pode concatenar duas listas usando [`++`][kernel-concat-list].

```elixir
~c"hi" ++ ~c"!"
# => ~c"hi!"
```

Quanto maior for a primeira lista, mais lenta será a concatenação, então evite acrescentar repetidamente a listas de tamanho arbitrário.

## Imprimibilidade

Se uma lista de inteiros contiver apenas inteiros que são pontos de código de caracteres imprimíveis, ela será exibida como uma charlist. Mesmo que tenha sido definida usando a sintaxe `[]`.

```elixir
~c"ABC"
# => ~c"ABC"

[65, 66, 67]
# => ~c"ABC"
```

Se uma lista de inteiros contiver até mesmo um único ponto de código de um caractere não imprimível (por exemplo, `0-6`, `14-26`, `28-31`), ela será exibida como uma lista. Mesmo que tenha sido definida usando a sintaxe `~c""`.

```elixir
~c"ABC\0"
# => [65, 66, 67, 0]

[65, 66, 67, 0]
# => [65, 66, 67, 0]
```

A imprimibilidade pode ser verificada com [`List.ascii_printable?`][list-ascii-printable].

```elixir
List.ascii_printable?([65, 66, 67])
# => true
List.ascii_printable?([65, 66, 67, 0])
# => false
```

Lembre-se de que essas são duas formas diferentes de _exibir_ os mesmos dados. Os valores são estritamente iguais.

```elixir
~c"ABC" === [65, 66, 67]
# => true
```

Ao imprimir uma lista com [`IO.inspect`][io-inspect], você pode usar a opção [`:charlists`][inspect-opts] para controlar como as listas são impressas.

```elixir
IO.inspect(~c"ABC", charlists: :as_charlists)
# => prints ~c"ABC"

IO.inspect(~c"ABC", charlists: :as_lists)
# => prints [65, 66, 67]
```

## Pontos de código

Você pode colocar um `?` antes de um caractere para obter seu ponto de código.

```elixir
?A
# => 65

[?:, ?)]
# => ~c":)"
```

## Charlists vs strings

Charlists e strings compostas pelos mesmos caracteres não são consideradas iguais.

```elixir
~c"hello" == "hello"
false
```

Cada valor em uma charlist é o [ponto de código Unicode de um caractere][unicode-table], enquanto em uma string os pontos de código são codificados como [UTF-8][utf8].

```elixir
IO.inspect(~c"tschüss", charlists: :as_lists)
# => prints [116, 115, 99, 104, 252, 115, 115]

IO.inspect("tschüss", binaries: :as_binaries)
# => prints <<116, 115, 99, 104, 195, 188, 115, 115>>
```

Observe como `ü`, ponto de código `252`, é codificado em UTF-8 como `195` e `188`.

**Na prática, charlists raramente são usadas**. Seu principal caso de uso é interagir com Erlang, em particular ao usar bibliotecas mais antigas que não aceitam binários como argumentos.

Ao trabalhar com Elixir, **use strings para armazenar texto**. O módulo `String` oferece uma ampla variedade de funções para processar texto, funções que não estão disponíveis para charlists.

Charlists podem ser convertidas em strings com [`to_string`][kernel-to-string].

```elixir
to_string(~c"hello")
# => "hello"
```
