# Introdução

Em muitas linguagens orientadas a objetos, é comum estender comportamentos [criando subclasses][wiki-subclass] de uma classe pai, herdando métodos dela e também adicionando novos.
Assim, obtemos uma hierarquia de objetos.

Julia _não tem classes_, então, por extensão, _não tem subclasses_.
Como herdamos e estendemos comportamentos existentes?

Vimos em conceitos anteriores como criar uma hierarquia de tipos, além de aprender como Julia usa [multiple dispatch][concept-multiple-dispatch] para escolher métodos com base nos tipos dos argumentos.

Julia também tem várias interfaces informais, que permitem que seus tipos personalizados se conectem a comportamentos já definidos para os tipos padrão.

Isso fica mais fácil de ilustrar com a interface Iterator.

## Iteradores

Anteriormente, no decorrer do conteúdo, vimos várias formas de Julia operar sobre cada elemento de uma coleção.

- [Laços][concept-loops], como `for item in items...`
- [Broadcasting][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Funções de ordem superior][concept-hof]: `map(√, [1, 4, 9])`
- [Compreensões][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Geradores][concept-comprehensions]: `(x^2 for x in 1:1e6)`, que é avaliado sob demanda.

Claramente, Julia sabe percorrer coleções padrão item por item: vetores e intervalos nos exemplos acima, além de Sets, Dicts, etc.

Como adicionamos essa capacidade às nossas próprias coleções personalizadas, especialmente se elas puderem ser iteradas sob demanda, como um gerador?

### Requisitos mínimos

Para criar uma sequência para iteração, precisamos de (pelo menos) duas coisas:

1. Uma forma de obter o _primeiro_ item.
2. Uma forma de obter o _próximo_ item a partir do estado atual.

Julia realiza essas tarefas com métodos da função `Base.iterate()`, seguindo estes passos:

1. `Base.iterate(iter)` é chamado automaticamente primeiro.
    - Se não houver nada para iterar, retorna `nothing`.
    - Caso contrário, retorna a `Tuple` do primeiro item retornado e do primeiro estado: `(firstitem, firststate)`.
2. `Base.iterate(iter, state)` é chamado automaticamente se um item tiver sido retornado na iteração anterior, recebendo `firststate` como seu argumento `state`.
    - Se a iteração terminar, retorna `nothing`.
    - Caso contrário, retorna a `Tuple` do próximo item e do próximo estado: `(nextitem, nextstate)`.
3. Repete o passo 2 até a terminação.

Todos esses passos acontecem nos bastidores, o que significa que as chamadas de método e o estado são gerenciados internamente pelo protocolo de iteração (com o estado permanecendo opaco), e apenas o item fica exposto a construções de alto nível, como laços.
Em outras palavras, só vemos o `item`, enquanto todo o resto permanece numa caixa-preta.

O [Multiple dispatch][concept-multiple-dispatch] é central para isso.
O tipo de `iter` determina quais métodos são chamados, e o número de argumentos determina se o primeiro ou o próximo item é retornado.

Os métodos para tipos padrão já estão definidos: `Vector`, `Range`, `Set`, etc ([atualmente][ref-iterations-collections] 14 tipos no total).

Para que um `MyType` personalizado compartilhe os mesmos comportamentos, primeiro precisamos definir:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Tudo isso provavelmente soa confuso no abstrato, mas pode ser bem simples.
Para ilustrar, imagine que queremos um tipo que forneça as potências de um inteiro `n` qualquer, até uma contagem máxima.

Primeiro, defina um tipo personalizado:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Agora podemos definir os métodos `iterate` para esse tipo, mas quais são o primeiro item e o primeiro estado?

Para obter o primeiro item, alguns iteradores precisam de uma preparação complicada, mas neste caso de brinquedo, dá para notar que o primeiro item retornado é apenas o número base, então só precisamos verificar se o valor de `count` é maior ou igual a um.

Agora podemos considerar o primeiro estado, que carrega informações usadas para a próxima iteração.
Cabe a você decidir quais informações precisa acompanhar para fazer isso, e elas podem ser de qualquer tipo.

Neste caso, poderíamos simplesmente acompanhar o "index" ao qual elevar `n`, ou podemos encontrar uma opção mais eficiente usando a potência mais recente de `n` (ou seja, o item retornado) e o próximo "index" na sequência.
Esses dois números podem ser empacotados numa `Tuple` e retornados como o `state`.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

Neste exemplo, o primeiro item (`p.n`) é retornado para o laço e o primeiro estado `(p.n, 2)` é passado para o método `iterate(P::Powers, state)`.
Ali podemos processar o estado para produzir o próximo item, multiplicando o item atual pelo número base e, assim, aumentando sua potência em `1`.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Se o valor do index ainda estiver dentro de `count`, a `Tuple` é retornada com o item `next` e a `Tuple` de estado incrementado.
Quando o valor de `index` ultrapassa `count`, então `nothing` é retornado, indicando que a iteração terminou.

Talvez você tenha notado que os métodos `iterate(p::Powers)` e `iterate(p::Powers, state)` têm corpos de função bastante parecidos.
Na verdade, com um pouco de esperteza, essa semelhança permite uma implementação mais enxuta usando apenas a versão de dois argumentos, com um argumento padrão para o estado: `Base.iterate(p::Powers, state=(1, 1))`
Com isso, não precisaríamos do método separado de um único argumento `iterate(p::Powers)`.
Isso costuma ser feito na prática quando possível.

Até aqui, já temos uma funcionalidade útil: para as 4 primeiras potências de 3, podemos percorrer os resultados com um laço, verificar se um determinado número está entre os resultados e aplicar funções de agregação como `sum()`.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Métodos adicionais

Apesar desse bom começo, nem tudo funciona ainda.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Como esperado, `length(Powers(3, 4))` dá exatamente a mesma mensagem de erro.

Isso é fácil de corrigir, já que o comprimento faz parte do construtor do tipo: 4, neste caso.
Só precisamos definir `Base.length()` para esse tipo e aí podemos usar compreensões e `collect()` na sequência.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Por eficiência, é melhor também definir `Base.eltype()`: o tipo de elemento do resultado.
Isso permite que funções como `collect()` reservem espaço de antemão para o `Vector{Int}` de saída, em vez de fazer `push!()` repetidamente num `Vector{Any}`.

Repare na sintaxe, que talvez você ainda não tenha visto: esse método é definido no _tipo_, e não numa _instância_ do tipo.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Não é _obrigatório_ que iteradores tenham comprimento finito.
O uso de sequências "infinitas" é mais limitado, mas percorrê-las com um laço pode ser útil, desde que haja alguma forma de `break` para sair do laço.
Por exemplo, poderíamos definir uma variante de `Powers` que gerasse valores menores que um certo limite (talvez `typemax(Int)`, para evitar estouro de inteiros).

## Resumo

Interfaces são bem confusas de explicar, porque a abordagem de Julia é muito diferente da maioria das outras linguagens.
Em particular, o nome da interface pode nunca ser mencionado na implementação: bem diferente de [criar subclasses][wiki-subclass] ou [mixins][wiki-mixins].

No entanto, elas são surpreendentemente simples na prática:

1. Defina um tipo adequado.
2. Descubra quais métodos são necessários.
3. Implemente esses métodos para o seu tipo personalizado; normalmente são apenas alguns métodos, bem curtos e simples.
4. Deixe que o [Multiple Dispatch][concept-multiple-dispatch] cuide do resto, automaticamente.
