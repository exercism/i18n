# Introdução

Um *signaler* a bordo de uma embarcação de patrulha costeira mantém o
registro de mensagens. Bandeiras de sinal brutas chegam emolduradas
com caracteres marcadores; as leituras precisam ser renderizadas para a
transmissão; pares e trios de observações são resumidos na hora. Alguns
idiomas da biblioteca padrão do Factor fazem a maior parte do trabalho.

## `unparse`: do valor ao código-fonte

[`unparse`][unparse] (em `prettyprint`) retorna o
texto na forma de código-fonte de qualquer valor:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse` é o inverso do parser: a ida e volta
`dup unparse parse` reconstrói o valor. É a ferramenta certa
para serializar em um formato de transmissão que o receptor vai analisar
de volta, e a ferramenta errada para saída legível por humanos (as strings
mantêm suas aspas, os vetores mantêm seu `V{ ... }`, etc.).

## Variantes de slice: visões, não cópias

`head` e `tail` de `sequences` *copiam* a parte que você mantém para
uma sequência nova. Suas contrapartes `-slice` retornam um objeto `slice`
(uma tupla que guarda o índice inicial, o índice final e a sequência
subjacente) que implementa o [protocolo de sequência][sequence-protocol]
sem copiar:

| palavra       | efeito                                          |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )`: copia os primeiros n     |
| `head-slice`  | `( seq n -- slice )`: visão dos primeiros n     |
| `tail`        | `( seq n -- newseq )`: copia a partir do índice n |
| `tail-slice`  | `( seq n -- slice )`: visão a partir do índice n |
| `head*`       | `( seq n -- newseq )`: copia tudo menos os últimos n |
| `head-slice*` | `( seq n -- slice )`: visão de tudo menos os últimos n |
| `tail*`       | `( seq n -- newseq )`: copia os últimos n       |
| `tail-slice*` | `( seq n -- slice )`: visão dos últimos n       |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

Um `slice` *é* uma sequência, então tudo que aceita uma sequência
aceita um slice: `length`, `first`, `each` e assim por diante funcionam
todos sem copiar. Testes que precisam comparar com uma string literal
podem converter com `>string`.

## `?head` e `?tail`: remova um marcador, se estiver presente

Leituras emolduradas carregam texto marcador que pode ou não estar lá.
`?head` e `?tail` (em `splitting`) tentam remover um prefixo ou
sufixo, retornando a sequência (possivelmente encurtada) *e* um
Boolean que informa se o marcador foi encontrado:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

O Boolean no final as torna uma combinação natural para uma guarda:
combine `?head` com `if` para ramificar conforme a moldura estava
presente ou não, ou com `unless` para rejeitar uma entrada que não tem
o marcador esperado.

## `<repetition>`: N cópias, de forma virtual

[`<repetition>`][repetition] (em `sequences`) é outra
sequência virtual que não copia: `( len elt -- repetition )`
constrói uma sequência de `len` elementos que são todos `elt`, sem
alocar essa quantidade de posições:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

O próprio `elt` pode ser uma sequência: cada cópia é essa mesma
sequência. Aí o `concat` junta as cópias uma após a outra:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

Assim como um `slice`, o resultado *é* uma sequência: `length`, `each`
e companhia funcionam nele diretamente. Use-a para preencher um código
de sinal até uma largura fixa ou para gerar uma sequência de marcadores
repetidos; converta com `>string` (ou `>array`) só quando uma sequência
concreta for realmente necessária.

## `<clumps>`: janelas sobrepostas, de forma virtual

[`<clumps>`][clumps] (em `grouping`) é uma terceira sequência
virtual que não copia: `( seq n -- clumps )` encara `seq` como a
série de janelas de comprimento `n` *sobrepostas* sobre ela, cada
janela um slice:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

Uma sequência de `length` n produz `length - n + 1` janelas.
Como cada janela é um slice, emparelhar leituras sucessivas não custa
nenhuma cópia: `[ first2 ]` em cada clump de `2` dá a você todos os
pares consecutivos para projetar. (A prima não sobreposta,
`<groups>`, em vez disso corta a sequência em blocos disjuntos.)

## Cleave com múltiplas entradas: `2bi`, `3bi`, `2tri`, `3tri`

As palavras cleave simples `bi` e `tri` aplicam duas ou três
quotations a *uma* entrada. As variantes com prefixo `2` e
`3` aplicam cada quotation a *duas* ou *três* entradas:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

Cada quotation recebe *todas* as entradas. Use essas palavras quando
mais de uma projeção depende do mesmo par (ou trio) de valores, e não
quando você quer a *mesma* operação aplicada a cada entrada
separadamente (para isso existem `bi@` ou `tri@`).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
