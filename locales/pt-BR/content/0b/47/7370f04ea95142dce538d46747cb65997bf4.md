# Introdução

O conceito de condicionais apresenta o `jcc`, a família de instruções para desviar com base em uma condição.
Um `jcc` transfere a execução para outro ponto do programa somente se a sua condição for satisfeita.

Porém, as CPUs modernas são rápidas e capazes de executar muitas instruções em paralelo.
Seria custoso demais parar todo o trabalho enquanto a CPU espera por uma verificação da condição em tempo de execução.

Por isso, internamente, a CPU não espera.
Usa um **preditor de desvios** para adivinhar o resultado de uma condição e começa a executar _especulativamente_ o caminho previsto.

Se a predição estiver correta, a execução prossegue como se não houvesse desvio.
Porém, se a predição estiver errada, a CPU precisa _descartar o trabalho feito_ no caminho previsto e recomeçar no caminho correto.

Isso é chamado de **predição incorreta de desvio** e é custoso, provocando um atraso.

Quando um desvio é difícil de prever, essas predições incorretas se acumulam.
Nesses casos, às vezes é preferível evitar o desvio por completo, de modo que as mesmas instruções sejam executadas independentemente da condição.
O código que escolhe entre valores sem um `jcc` é chamado de **sem desvios**.

Há várias formas de estruturar o código para que ele desvie com menos frequência, ou para que os desvios que ele faz sejam mais previsíveis.
Em especial, o x86-64 oferece duas famílias de instruções comumente usadas para escrever código sem desvios.

## Movimentos condicionais

A família de instruções `cmovcc` copia o operando de origem para o destino somente se uma condição específica for satisfeita.
Caso contrário, o destino fica inalterado.

O sufixo `cc` segue a mesma nomenclatura do `jcc`, com o mesmo significado:

| instrução | move se                              |
|-----------|--------------------------------------|
| `cmove`   | A == B depois de `cmp A, B`          |
| `cmovne`  | A != B depois de `cmp A, B`          |
| `cmovl`   | A < B (com sinal) depois de `cmp A, B` |
| `cmovb`   | A < B (sem sinal) depois de `cmp A, B` |
| `cmovg`   | A > B (com sinal) depois de `cmp A, B` |
| `cmova`   | A > B (sem sinal) depois de `cmp A, B` |

As regras são semelhantes às do `jcc`:

1. `l` e `g` são usados para comparações com sinal, e `b` e `a`, para comparações sem sinal.
2. Acrescentar `e` a um sufixo inclui a igualdade.
3. Acrescentar `n` nega a condição.
4. Também há variantes que se referem ao flag estar definido.
   Por exemplo, `cmovz` e `cmovc`.

Considere o valor absoluto de um inteiro com sinal em `rdi`, retornado em `rax`.
Escrita com `jcc`, a função escolhe um de dois caminhos:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Escrita com `cmovcc`, os dois valores candidatos são calculados incondicionalmente e o movimento condicional escolhe um:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

A versão sem desvios sempre executa as mesmas instruções.
Não há nenhum `jcc` para o preditor adivinhar.

O destino de um `cmovcc` precisa ser um registrador.
A origem pode ser um registrador ou um local na memória, mas não um imediato.

~~~~exercism/note
No código acima, a instrução `neg` define vários flags de acordo com o resultado, incluindo o flag de sinal (SF).
Isso significa que o `cmp rdi, 0` pode ser removido por completo:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Para `rdi` positivo, `neg` produz um resultado negativo e SF == 1, então `cmovs` restaura o `rdi`.
Para `rdi` igual a zero ou negativo, `neg` produz um resultado não negativo e SF == 0, então `rax` mantém o valor negado (que é o valor absoluto correto).

Embora `cmp` seja a principal forma de comparar valores em código assembly, muitas instruções também definem flags de acordo com o resultado.
A lista completa de flags que uma instrução afeta costuma estar na sua [referência][reference].
No caso específico do `neg`, são SF, ZF, CF, OF e PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

## Definição condicional

A família de instruções `setcc` define o operando de destino como `1` se uma condição específica for satisfeita, e como `0` caso contrário.
O destino é sempre um _operando de 8 bits_.

O sufixo `cc` segue a mesma nomenclatura do `jcc` e do `cmovcc`.
Por exemplo, `setz` define o destino como `1` se `ZF == 1` e como `0` caso contrário.

Como o destino tem 8 bits, é comum seguir o `setcc` com um `movzx` quando um valor mais largo é necessário:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Esse é um idioma comum para transformar o resultado de uma comparação em um inteiro `0` ou `1`.
