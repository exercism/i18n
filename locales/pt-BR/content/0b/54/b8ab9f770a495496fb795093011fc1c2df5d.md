## Opções extras de linha de comando do `jq`

Você vai notar opções extras para o `jq` nos testes.

```sh
run jq -s -R -c -f flower-field.jq << 'END_INPUT'
```

O que elas fazem?

- `-s`

  Esse é o modo "slurp".
  Em vez de tratar a entrada como um fluxo de objetos JSON,
  toda a entrada é juntada em um array.

  ```sh
  $ seq 5 | jq -c '.'
  1
  2
  3
  4
  5
  $ seq 5 | jq -s -c '.'
  [1,2,3,4,5]
  ```

- `-R`

  Você talvez já tenha visto o `-r`, para imprimir strings "brutas" (sem aspas).
  Esse é o oposto.
  Cada linha da entrada é tratada como uma string.

  Dois exemplos:

  ```sh
  $ seq 5 | jq -R -c .
  "1"
  "2"
  "3"
  "4"
  "5"

  $ echo 42 | jq '. * 2'      # input is a JSON number
  84
  $ echo 42 | jq -R '. * 2'   # input is a JSON string
  "4242"
  ```

Quando você junta essas duas opções, você _não_ recebe um array de strings:
você recebe toda a entrada como uma única string, incluindo as quebras de linha ao final de cada linha.

```sh
$ seq 5 | jq -s -R -c .
"1\n2\n3\n4\n5\n"
```

Lidar com isso faz parte do desafio deste exercício.
