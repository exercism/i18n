# Introdução

Alguns laços não podem ser escritos como "faça isto para cada elemento de uma
sequência": você precisa continuar até que alguma condição mude.
O combinador `while` do Factor é a ferramenta para isso: uma quotation de
predicado diz "continuar?", uma quotation de corpo faz o trabalho de um passo,
e o `while` repete até que o predicado retorne `f`.

## `while` e `until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred` e `body` são ambas quotations que operam na pilha de dados. O `while`
continua repetindo enquanto `pred` deixa um valor verdadeiro; o `until` é o
oposto: continua repetindo *até* que `pred` se torne verdadeiro (ou seja,
enquanto `pred` deixa `f`).

Um único valor de estado pode fluir na pilha entre o predicado e o corpo:

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

Rastreando: o predicado `dup 0 >` espia o contador atual; o corpo
`dup . 1 -` o imprime e o decrementa; o laço para quando o contador chega a
`0`. O `drop` no final descarta esse `0` final da pilha.

## `while*`: manter o valor do predicado

```
while* ( pred body -- )
```

O `while` só se importa se o predicado deixou um valor verdadeiro: ele
descarta o valor em si antes de rodar o corpo. O `while*`, em vez disso,
*entrega esse valor ao corpo*. Recorra a ele sempre que o teste e o corpo
quiserem a mesma coisa recém-calculada: uma consulta, uma correspondência,
um token analisado.

Aqui, cada nome aponta para o próximo em uma cadeia. O predicado consulta o
nome atual; enquanto houver um próximo nome, o `while*` o entrega ao corpo,
que o imprime e segue a partir daí:

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

`links at` retorna o próximo nome, ou `f` quando um nome não tem entrada.
Enquanto ele retorna um nome, o `while*` passa esse nome para `dup .`, que o
imprime e o deixa como chave para a próxima consulta. O primeiro `f` para o
laço: o `while*` o descarta, então não sobra nada.

## Vários valores de estado com variáveis locais

Quando o laço carrega mais de um valor, por exemplo uma lista restante e um
total acumulado, o malabarismo com a pilha fica confuso. O padrão mais limpo
é declarar *variáveis locais* com `::`:

```
:: word ( inputs -- outputs ) ... ;
```

Dentro do corpo, `:> name!` adiciona uma variável local mutável; leituras usam
`name`, escritas usam `name!` (que consome o novo valor da pilha e o atribui).

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

Duas variáveis locais aqui (`rest` e `running`) cobrem o estado do laço
inteiro: o predicado as inspeciona, o corpo as atualiza, e o valor final é
retornado no fim.

`unclip ( seq -- rest first )` retira o primeiro elemento de uma sequência,
o que é prático quando o laço quer consumir uma lista um elemento por
iteração. A forma `[ rest! ] dip` atualiza `rest` para a cauda restante,
deixando o elemento recém-removido na pilha para o corpo usar.
