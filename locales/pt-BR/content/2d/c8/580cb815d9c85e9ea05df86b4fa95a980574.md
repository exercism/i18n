# Sobre o básico

Kotlin é uma linguagem de tipagem estática, projetada para ser totalmente interoperável com Java.

Diferentemente do Java, Kotlin:

- tem uma sintaxe mais limpa e mais concisa;
- incorpora muitos recursos das linguagens funcionais;
- tem amplo suporte a valores anuláveis.

## Variáveis

Como Kotlin tem tipagem estática, é necessário _saber_ o tipo de cada valor em tempo de compilação.

No entanto, a [inferência de tipos][inference] do Kotlin é muito poderosa, então _especificar_ o tipo geralmente é opcional.

Há duas formas de declarar uma variável.

1. `val` cria uma variável imutável, e tentar alterá-la é um erro de compilação.

```kotlin
val x = 42  // => 42
x = 43      // => 'val' cannot be reasssigned
```

2. `var` cria uma variável mutável.

```Kotlin
var x = 42  // => 42
x = 43      // => 43
```

Como variáveis imutáveis eliminam uma classe comum de bugs, o uso de `val` é incentivado sempre que possível.

Além disso, nem mesmo uma `var` pode mudar de tipo:

```kotlin
var x = 42
x = "foobar" // => Type mismatch: inferred type is String but Int was expected
```

Para reduzir a distração visual, os tipos explícitos serão omitidos na maior parte deste programa de estudos.
Ainda assim, recomenda-se especificar os tipos ao menos para:

- APIs públicas
- assinaturas de funções
- onde for necessário documentar

Algumas empresas e organizações exigem segurança de tipos estrita e não permitem inferência de tipos, enquanto outras a restringem a tipos "simples" ou adotam a inferência de tipos por completo.

```kotlin
val x: Int = 42  // => 42
```

Em geral, os nomes de variáveis e funções devem estar em `camelCase`, e não em `snake_case`.

## Funções

Declare uma função com a palavra-chave `fun`.
Diferentemente do Java, as funções não precisam fazer parte de uma classe.

```Kotlin
fun hello(): String {
    return "Hello, World!"
}

fun add(x: Int, y: Int): Int {
    return x + y
}
```

Alguns pontos a observar:

- Os parênteses `()` são necessários depois do nome da função, mesmo que ela não receba argumentos.
- Os argumentos da função precisam especificar o tipo: não há inferência de tipos (ao contrário das variáveis).
- O corpo da função fica entre chaves `{ }` (mas veja abaixo).
- A palavra-chave `return` é obrigatória, se a função retornar um valor.
- Os pontos e vírgulas `;` no fim das linhas são opcionais, e geralmente omitidos.
- Os operadores aritméticos `+`, `-`, `*`, `/` são parecidos com os da maioria das linguagens mais usadas.

No entanto, para essas funções bem simples, de "expressão única", existe uma sintaxe abreviada:

```Kotlin
// return type is usually omitted for single-expression functions
fun add(x: Int, y: Int) = x + y  
```
Funções podem ter parâmetros com valores padrão.
Esses valores serão usados se forem omitidos na chamada da função:

```kotlin
fun ping(host: String = "localhost") {
    println("PING --> $host")
}

ping("exercism.io")  // PING --> exercism.io
ping()               // PING --> localhost
```

As funções no Exercism geralmente retornam um valor (por causa de como o test runner é estruturado).
Para usar Kotlin de forma mais ampla, pode ser útil saber que uma função que não retorna valor pode omitir o tipo de retorno e a palavra-chave `return`.

Diz-se então que ela tem tipo de retorno `Unit`: equivalente a `void` no Java e em várias outras linguagens.

## Comentários

Comentários de uma linha começam com `//`, e o resto da linha é ignorado.

Comentários de várias linhas começam com `/*` e terminam com `*/`

```Kotlin
fun hello(): String {
    /*
     * Failing to run this program on a new installation 
     * is considered bad luck
    */
    return "Hello, World!" // the compiler pixies are now happy
}
```

Isso é igual ao Java.
