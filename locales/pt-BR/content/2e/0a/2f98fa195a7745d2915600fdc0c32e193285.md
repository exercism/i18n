# Sobre

Em Rust, um iterador é qualquer valor que implementa a trait [`Iterator`](https://doc.rust-lang.org/stable/std/iter/trait.Iterator.html).
Os valores de um iterador podem ser avançados manualmente chamando o método `next` no iterador.

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // many built-in methods implemented
}
```

Muitas das [`collections`](https://doc.rust-lang.org/std/collections/index.html) do Rust implementam
[`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html),
que consegue produzir um `Iterator` a partir dos valores da coleção.

```rust
trait IntoIterator where Self::IntoIter: Iterator<Item=Self::Item> {
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}
```

Repare que, embora `IntoIterator::into_iter` consuma seu tipo `self`, esse tipo não precisa necessariamente ser um valor com posse.
Assim, existem implementações de `IntoIterator` para [`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-2),
para [`&'a Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator)
e para [`&'a mut Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-1).
Essas implementações para graus variados de posse oferecem uma flexibilidade útil.

Não é preciso entender de `traits` para este conceito, e teremos um exercício inteiro para você dominar `traits`.
Por enquanto, basta lembrar que:

- Qualquer tipo que implementa `IntoIterator` é chamado de _iterável_, porque pode ser transformado em um iterador.
- Qualquer tipo que implementa `Iterator` é um iterador, que _produz_ valores e pode ser _iterado_.
- Você consegue obter um iterador de qualquer tipo que implementa `IntoIterator` chamando seu método `into_iter`.
- Todo iterador [implementa `IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html#impl-IntoIterator-25) e produz a si mesmo.
- Os laços `for` sempre operam sobre iteradores e chamam `IntoIterator` implicitamente no seu argumento de intervalo.

## `into_iter` e laços `for`

Você provavelmente já conhece laços `for` sobre um vetor:

```rust
// lor is a `Vec`, which implements `IntoIterator`
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
for people in &lor {
    println!("{people}");
}
```

Essencialmente, um laço `for` é apenas uma forma abreviada de chamar o método `into_iter` do seu argumento
e depois chamar `next()` até que ele pare de produzir itens. Em outras palavras, o laço anterior equivale a:

```rust
{
    let mut iterator = (&lor).into_iter();
    while let Some(people) = iterator.next() {
        println!("{people}");
    }
}
```

## Os métodos `iter` e `iter_mut`

A maioria dos tipos de coleção do Rust fornece os métodos `iter` e `iter_mut`.
Para uma coleção do tipo `T`, esses dois métodos fazem o seguinte, por convenção:

- O iterador retornado por `iter` produz `&T` emprestado de forma imutável.
- O iterador retornado por `iter_mut` produz `&mut T` emprestado de forma mutável.

```rust
let mut v = vec![1, 2, 3];

// Using `iter` method
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&1));
assert_eq!(iterator.next(), Some(&2));
assert_eq!(iterator.next(), Some(&3));
assert_eq!(iterator.next(), None);

// Using `iter_mut` method
for value in v.iter_mut() {
     *value *= *value;
}
println!("{v:?}");
// => [1, 4, 9]
```

## Diferença entre `iter`, `iter_mut` e `into_iter`

Se `iter`, `iter_mut` e `into_iter` todos produzem iteradores, quais são as diferenças?

- O iterador retornado por `iter` produz, por convenção, `&T` emprestado de forma imutável.
- O iterador retornado por `iter_mut` produz, por convenção, `&mut T` emprestado de forma mutável.
- O iterador retornado por `into_iter` pode produzir `T`, `&T` ou `&mut T`, dependendo do seu contexto.

Qual é o contexto de uma chamada a `into_iter`?
O seu tipo `self`.
Lembre-se de que existem implementações de `IntoIterator` para `Vec`, `&'a Vec` e `&'a mut Vec`.
Portanto:

- `(&v).into_iter()` é igual a `v.iter()` => retorna `&T`
- `(&mut v).into_iter()` é igual a `v.iter_mut()` => retorna `&mut T`
- `v.into_iter()` => retorna `T` e move os valores

Isso fica mais claro em laços `for`:

- `for num in &v {...}` => vincula `&T`
- `for num in &mut v {...}` => vincula `&mut T`
- `for num in v {...}` => vincula `T` e move os valores

Muitas vezes é mais claro escrever `v.iter()` em vez de `(&v).into_iter()`.
Por isso, existem motivos ergonômicos para preferir `iter` e `iter_mut` a `into_iter`.

## Usando métodos embutidos dos iteradores

Os iteradores fornecem inúmeros métodos embutidos, como `map`, `filter` e `collect`.
Esses métodos às vezes são usados com closures.

`map` usa uma closure para transformar os valores de um iterador.
`take` trunca um iterador (potencialmente infinito) em um que termina após no máximo a quantidade especificada de itens.

```rust
for even_number in (0..).into_iter().map(|x| x * 2).take(4) {
    let odd_number = even_number + 1;
    println!("{even_number} => {odd_number}");
}
// 0 => 1
// 2 => 3
// 4 => 5
// 6 => 7
```

`filter` transforma o iterador em um que só retorna os valores para os quais a closure é avaliada como `true`.
`count` consome o iterador, retornando a quantidade de itens produzidos.

```rust
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
let short_people = ["Dwarves", "Hobbits"];
let num_tall_people = lor.iter().filter(|people| !short_people.contains(people)).count();
assert_eq!(num_tall_people, 5);
```

`flat_map` transforma um iterador transformando cada item em um novo iterador pela closure fornecida
e depois achatando todos os novos iteradores produzidos ao encadeá-los.
`collect` produz uma nova coleção,
desde que o tipo da coleção implemente [`FromIterator`](https://doc.rust-lang.org/std/iter/trait.FromIterator.html).

```rust
let words = ["alpha", "beta", "gamma"];
// chars() returns an iterator
let merged: String = words.iter()
                          .flat_map(|s| s.chars())
                          .collect();
assert_eq!(merged, "alphabetagamma");
```

A [trait `Iterator`](https://doc.rust-lang.org/std/iter/trait.Iterator.html) oferece _muitas_ transformações de iterador úteis como essas;
vale a pena ler a documentação e se familiarizar com elas.

## Preguiça

É importante saber que os iteradores do Rust são preguiçosos:
eles não produzem nenhum valor até consumirmos o iterador.
Se você escrever e rodar o seguinte código:

```rust
(0..5).map(|x| x * x);
```

Você vai receber o seguinte erro do compilador:

```rust
 --> src/main.rs:2:5
  |
2 |     (0..5).map(|x| x * x);
  |     ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

Isso acontece porque `map` é um método adaptador que retorna outro iterador.

Para consumir um iterador, use um laço `for` ou um método de iterador que produza algum valor que não seja ele próprio um iterador.

Por exemplo, `collect` é um método consumidor (sua assinatura de função não retorna um iterador, mas um tipo genérico):

```rust
//         Iterator   Adaptor        Consumer
//                |      |               |
let v: Vec<_> = (0..5).map(|x| x * x).collect();
```
