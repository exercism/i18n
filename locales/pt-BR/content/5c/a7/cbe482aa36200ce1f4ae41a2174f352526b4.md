# Nil

O Crystal tem um tipo chamado [`Nil`][nil], que só pode ter um valor: `nil`.
Ele é usado para representar a ausência de um valor e é parecido com `null` ou `None` em outras linguagens.

Valores nil podem ser retornados por vários métodos, como o [`String#[]?`][string-index], que retorna `nil` se o índice estiver fora dos limites.

```crystal
"foo"[10]? # => nil
```

O Crystal tem o que se chama de **verificações de referência nula**, o que significa que, por padrão, nenhum tipo pode ser `nil`.
Isso quer dizer que você não pode atribuir `nil` a uma variável, a menos que a declare explicitamente como do tipo `Nil`.
Por sua vez, isso significa que o compilador verifica automaticamente referências nulas.

## Valor falso

Existem algumas abordagens para lidar com valores `nil`.
`nil` é um valor [falso][truthy-falsey], assim como `false`.
Isso significa que, em condicionais e em outros lugares onde se espera um valor falso ou verdadeiro, ele será tratado da mesma forma que `false`.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Isso significa que o ramo verdadeiro não será executado se uma variável que pode ser `nil` tiver o valor `nil`.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## Verificar se é nil

O Crystal tem um método que pode ser usado para verificar se um valor é `nil`.
Ele se chama [`nil?`][nil?] e está disponível em todos os objetos.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Isso é um pouco diferente de apenas usar o valor em uma condicional, já que nos exemplos anteriores tanto false quanto nil seriam tratados como false.
Aqui, só `nil` é tratado como falso; se o valor fosse false, ele não seria nil e, portanto, seria verdadeiro.

## Operador or

A maneira mais fácil de lidar com valores `nil` é garantir que eles nunca se tornem `nil` desde o início.
O operador or ([`||`][or]) costuma ser usado quando se lida com `Bools`, mas, se bem compreendido, também pode ser usado para lidar com valores `nil`.
O operador or verifica se o primeiro valor é verdadeiro; caso não seja, o segundo valor é usado.
Isso pode ser usado para que, se o valor for `nil`, ele seja considerado falso e, assim, o segundo valor seja usado.

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
Essa abordagem deve ser vista como último recurso e só deve ser usada se você tiver **certeza** de que o valor não é nil.
Se possível, use as outras abordagens.
~~~~

[`not_nil!`][not_nil] é um método que permite dizer ao compilador que um valor não é nil e, com isso, fazer com que o tipo que ele contém não possa ser nil.
Ele faz isso lançando uma exceção se o valor for nil.

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
