# Introdução

## Noções básicas

[Lua](https://lua.org) é uma linguagem de script simples, mas poderosa, eficiente, leve e embutível. Ela é projetada, implementada e mantida na [PUC-RIO](https://www.puc-rio.br/) no Brasil desde 1993 pela equipe de Roberto Ierusalimschy, Waldemar Celes e Luiz Henrique de Figueiredo.

### Comentários

Comentários de uma linha em Lua começam com `--` e comentários multilinha começam com `--[[` e terminam com `]]`.
```lua
-- This is a single line comment.

--[[This is
a multiline
comment
]]
```

### Variáveis

Há três tipos de variáveis em Lua: variáveis globais, variáveis locais e campos de tabela. Para simplificar, apenas variáveis locais são explicadas aqui. Por padrão, todas as variáveis são globais, então precisamos declará-las como locais com a palavra-chave `local`.
```lua
local x
```

Um valor pode ser atribuído a uma variável usando o operador `=`.
```lua
local x = 1
```

O escopo de uma variável `local` é limitado ao bloco onde ela é declarada. Um bloco pode ser o corpo de uma estrutura de controle, o corpo de uma função ou um arquivo ou string onde a variável é declarada.
```lua
local x = 1

if x == 1 then
  local x = 2
  print(x) -- prints 2
end

print(x) -- prints 1
```

### Funções

Uma função é declarada com a palavra-chave `function` e, assim como as variáveis, é global por padrão. Uma definição de função tem um nome, uma lista de parâmetros e um corpo. A função termina quando a palavra-chave `return` é alcançada e retorna todos os valores listados depois dela. Sem um `return` especificado, a função retornará `nil`.

```lua
-- Defining a local function which returns "Hello " followed by 
-- the name which was given as parameter
local function say_hello(name)
  return 'Hello ' .. name
end
```

### Tabelas

Tabelas são o único mecanismo de estruturação de dados em Lua e são muito poderosas. Elas são usadas para representar arrays, conjuntos, objetos, módulos e muito mais. Essencialmente, uma tabela em Lua é um array associativo.
```lua
-- create a table and assign its reference to tbl
local tbl = {}

-- new entry with key 'x' and value 1
tbl['x'] = 1

-- printing the value
print(tbl['x'])  --> 1

-- uninitialized table fields evaluate to nil
print(tbl['y'])  --> nil

-- there is also syntactic sugar - the following is the same as above
tbl.y = 1
print(tbl.y)    --> 1
```

Isto é apenas uma pequena noção necessária para a próxima seção. Voltaremos a este tópico em detalhes mais adiante.

### Módulos

Um módulo é uma coleção de código armazenada em um arquivo-fonte `.lua`. Tudo o que o módulo exporta é armazenado em uma tabela e essa tabela é retornada no final do arquivo. Então a tabela basicamente funciona como uma espécie de namespace.
```lua
-- say-hello.lua

-- defining the table 'say' which is exported at the end
local say = {}

-- defining the function 'hello' as a table field
-- this is syntax sugar for: say.hello = function() print('Hello!') end
function say.hello()
  print('Hello!')
end

-- returning (exporting) the table 'say'
return say
```

Esse módulo pode então ser carregado em outro arquivo através da função `require`, que retorna a tabela.
```lua
-- lets_say_hello.lua
local say = require('say-hello')
say.hello() -- prints "Hello!"
```

Quando vemos `say.hello`, pensamos em "a função `hello` do módulo `say`". Mas sabendo que nosso `say-hello.lua` retorna uma tabela e voltando à seção sobre tabelas, percebemos que em Lua a expressão significa "indexar a tabela `say` usando a string `hello` como chave".

Embora seja uma boa prática um módulo retornar uma tabela, é igualmente possível retornar qualquer outro tipo, como uma função.

```lua
--- say-bye.lua
local function bye()
  print('Bye!')
end

return bye
```
