# Booleans

`BOOL` holds one of two values, `true` and `false`.

```sather
   ready : BOOL is
      return true;
   end;
```

## Comparação

| Operador | Pergunta | Exemplo |
| --- | --- | --- |
| `=` | igual? | `age = 13` |
| `/=` | diferente? | `age /= 13` |
| `<` | menor que | `age < 13` |
| `<=` | menor ou igual | `age <= 13` |
| `>` | maior que | `age > 13` |
| `>=` | maior ou igual | `age >= 13` |

Eles funcionam com números, e `=` e `/=` também funcionam com strings.

## Os três operadores

| Operador | Escrito | Verdadeiro quando |
| --- | --- | --- |
| and | `a and b` | ambos são verdadeiros |
| or | `a or b` | pelo menos um é verdadeiro |
| not | `~a` | `a` é falso |

`and` e `or` fazem **curto-circuito**: `a and b` não se dá ao trabalho de olhar
para `b` assim que `a` se revela falso, porque a resposta já está decidida.
Da mesma forma, `a or b` para se `a` for verdadeiro. Isso faz diferença quando
o lado direito é custoso, ou daria problema se fosse executado.

## Retornar uma comparação diretamente

Uma rotina cujo trabalho é apenas fazer uma pergunta deve retornar a pergunta,
não escolher uma resposta com um condicional:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

Escrever `if age >= 13 then return true else return false end` ocupa três
linhas para dizer o que a comparação já dizia, e todo leitor experiente vai
perceber.

## Precedência

`~` tem a precedência mais alta, depois `and`, depois `or`. Então

```sather
~a and b or c
```

significa `((~a) and b) or c`. Parênteses não custam nada para escrever, e
valem a pena sempre que, sem eles, o leitor tivesse que se lembrar dessa ordem
para acompanhar a linha.
