# Inclusão de código

```sather
   include WARM_UP;
   include WARM_UP count -> warm_up_count;
   include WARM_UP describe -> ;
   include WARM_UP count -> beats, describe -> ;
```

Um `include` copia o código de outra classe para dentro desta. É uma operação de tempo de compilação, sem custo nem relação em tempo de execução: as duas classes não ficam conectadas depois.

## A cláusula

```
   include CLASS  old_name -> new_name , old_name -> ;
```

Cada entrada renomeia um membro. `-> ;` sem um novo nome o deixa de fora. Tudo o que não for mencionado entra sem alterações.

A renomeação se aplica ao que o *exterior* vê. Chamadas entre as rotinas incluídas continuam funcionando: se `describe` chama `count` e `count` é renomeado para `beats`, `describe` chama `beats`.

## Incluindo várias classes

```sather
   include WARM_UP;
   include COOL_DOWN;
```

é permitido, e é assim que Sather obtém o que outras linguagens chamam de herança múltipla, sem os problemas habituais, porque um conflito é um erro de compilação e a correção é renomear ou deixar um de fora. Nada é resolvido por uma ordem de precedência que você precise memorizar.

## private include

```sather
   private include WARM_UP;
```

traz o código para uso próprio desta classe sem expô-lo. Útil quando você quer a implementação e não a interface.

## Os dois juntos

A forma usual para uma família de classes:

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class ACT_BASICS is
   minutes : INT is return 5; end;
end;

class JUGGLING < $ACT is
   include ACT_BASICS;
   name : STR is return "Juggling"; end;
end;
```

`< $ACT` diz o que ela pode fazer; `include ACT_BASICS` fornece parte de como fazer. Mude de ideia sobre como fazer e o `<` não se move.

## Por que é feito assim

Uma classe abstrata não tem código, então não pode ser herdada por acidente, e não existe algo como uma superclasse cujo comportamento muda debaixo de você. O reúso é uma cópia feita em tempo de compilação, de uma classe que você nomeou, com cada renomeação registrada.

O custo é que o reúso precisa ser solicitado explicitamente em cada classe. Essa é a troca: mais para digitar, nada implícito.
