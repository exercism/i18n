# Sobre

## Aplicação parcial

Todas as funções em Elm são [currificadas][currying], o que significa que, se você chamar uma função sem passar todos os argumentos, ela retorna uma nova função.

O resultado disso é chamado de [aplicação parcial][partial-application] (você não está passando todos os argumentos para a função, mas aplicando alguns deles parcialmente).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

A aplicação parcial sempre aplica os argumentos na ordem.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## Operador pipe (`|>`)

Dizer `x |> f` é exatamente o mesmo que `f x`. Um exemplo concreto: `"5" |> String.toInt` é o mesmo que `String.toInt "5"`.

À primeira vista isso não parece muito útil, mas ele é chamado de [operador pipe][pipe-operator] porque permite escrever código “em pipeline”.

Por exemplo, digamos que temos uma função sanitize que transforma a entrada do usuário em números inteiros:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Podemos reescrevê-la assim:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Isso evita o uso de parênteses e mostra as funções na ordem em que são aplicadas (primeiro `String.trim`, depois `String.toInt`), o que ajuda na legibilidade.

Existe também um [operador pipe reverso `(<|)`][reverse-pipe-operator].
Dizer `x <| f` é exatamente o mesmo que `f x`.
À primeira vista isso também não parece muito útil, e com certeza não é usado tanto quanto o operador pipe, mas ajuda a evitar parênteses em algumas situações.

## Composição de funções / estilo point-free

O operador [`(>>)`][forward-composition] tem o tipo `(a -> b) -> (b -> c) -> (a -> c)` e cria uma função do tipo `a -> c` ao compor duas funções compatíveis do tipo `a -> b `e `b -> c`.
Ele faz isso pegando a saída (do tipo `b`) da primeira função e usando-a como o primeiro argumento da segunda função (que deve ser do mesmo tipo `b`).
A função criada recebe a mesma entrada (do tipo `a`) da primeira função e retorna o `c` que a segunda função retornar.

Um exemplo concreto é `String.trim >> String.toInt`.
`String.trim` recebe uma string como único parâmetro, então é isso que a função criada recebe.
`String.toInt` retorna um `Maybe Int`, então é isso que a função criada retorna.
`String.trim` retorna uma `String`, que `String.toInt` aceita como parâmetro, então o exemplo compila.

Agora podemos reescrever nossa função `sanitize` da seguinte forma:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Repare que não usamos mais o parâmetro `input` que aparece no exemplo original, mesmo que a funcionalidade seja idêntica.
Essa forma de criar funções que não fazem referência aos seus parâmetros é chamada de "estilo point-free".
A vantagem desse estilo é que o código fica mais conciso; a desvantagem é que pode ser mais difícil de entender, especialmente para iniciantes.

Vale lembrar que todas as funções em Elm são currificadas, então `String.length >> max` compila e resulta no seguinte:

- Uma função (1) que tem um parâmetro string (o valor de entrada de `String.length`)
- `max` é uma função que tem dois parâmetros `Int`, mas a função 1 passa um único `Int` para ela (o valor de retorno de `String.length`), então `max` é parcialmente aplicada.
- O valor de retorno da função `max` parcialmente aplicada é outra função (2) que recebe um `Int` e retorna o maior entre esse `Int` e o `Int` parcialmente aplicado vindo de `String.length`
- Portanto, a função 1 (`String -> Int`) retorna a função 2 (`Int -> Int`)
- Assim, `((String.length >> max) "123") 2` retorna `3`, porque `"123"` tem comprimento 3, que é maior que o 2 do argumento `Int`.

## Design de funções

Para facilitar a escrita de código elegante em Elm, faça com que a estrutura de dados principal seja o último parâmetro das funções.
Todas as funções comuns da biblioteca padrão fazem isso, como `List.map` (assinatura de tipo abaixo).

```elm
map : (a -> b) -> List a -> List b
```

Aqui podemos ver que o último parâmetro da função `map` é `List a` e ela retorna `List b`, então a estrutura de dados principal (`List`) é o último parâmetro.

Isso torna possível escrever código elegante em pipeline, como abaixo.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Também torna conveniente usar composição de funções e estilo point-free, como alternativa ao pipeline.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

A composição de funções também permite reduzir esse exemplo a uma única chamada de `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
