# Introdução

Julia, como a maioria das linguagens de programação, oferece uma grande variedade de tipos de coleção.

Alguns são inerentemente ordenados (incluindo `Vectors` e `Arrays` de dimensões maiores), então podemos acessar os elementos por posição.
Outras coleções não têm ordem (`Sets`, `Dicts`), e os elementos precisam ser acessados por chave ou valor.

No caso mais simples, suponha que temos um `Vector` de `Ints` e queremos ordená-lo em ordem crescente.

```julia-repl
julia> v = [3, 2, 4, 1]
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v)
4-element Vector{Int64}:
 1
 2
 3
 4

# sort descending
julia> sort(v, rev=true)
4-element Vector{Int64}:
 4
 3
 2
 1
```

Simples!
A função `sort()` tem um nome óbvio e, aparentemente, retorna o `Vector` ordenado.

_Só brincadeira!_
Nesta altura do programa de estudos, você talvez suspeite (corretamente) que há nuances que precisamos discutir.

## Funções que modificam vs. que não modificam

Depois de rodar `sort(v)`, o que é `v`?

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> issorted(v)
false
```

O vetor original permanece inalterado.
`sort()` é uma função ***que não modifica*** sua entrada, e retorna uma _cópia_ dela.

Isso é um bom design em muitos contextos: temos uma [função pura][wiki-pure-func] cujo comportamento é fácil de analisar, mesmo em código paralelo e distribuído.

Por outro lado, suponha que tivéssemos um array de um bilhão de strings e quiséssemos ordená-lo.

A ordenação provavelmente é lenta.
Além disso, precisamos copiar tudo (_lento!_) e alocar memória suficiente (_vários gigabytes!_) para guardar a cópia.

Compare com este código bastante parecido:

```julia-repl
# v is as previously

julia> issorted(v)
false

julia> sort!(v)
4-element Vector{Int64}:
 1
 2
 3
 4

julia> v
4-element Vector{Int64}:
 1
 2
 3
 4

julia> issorted(v)
true
```

Agora o `Vector` de entrada é ordenado no próprio lugar, sem cópia, e a ordem original é perdida de forma permanente.

Isso pode ser eficiente, pode ter bugs e causar efeitos colaterais inesperados, e pode confundir outras pessoas que usam seu código.
_Escolha com cuidado!_

`sort!()` é uma "função que modifica" e, por convenção (_muito forte_), toda função que modifica suas entradas tem um `!` acrescentado ao nome, como um aviso para quem programa.

## Ordenar por quê?

Ordenar valores `Int64` é relativamente simples: até crianças pequenas entendem que 2 é maior que 1 e menor que 3.

Outros tipos podem ser mais complicados, mas, em geral, `x < y` se `isless(x, y) == true`.
Julia fornece implementações de `isless()` para a maioria dos tipos padrão.

Por exemplo, caracteres Unicode (para letras europeias, maiúsculas vêm antes de minúsculas):

```julia-repl
julia> j = collect("Julia")
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)

julia> sort(j)
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0false069 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
```

Também podemos aplicar qualquer função arbitrária às entradas antes de ordenar, como `abs` para ignorar o sinal ou `uppercase` para uma ordenação que não diferencia maiúsculas de minúsculas:

```julia-repl
julia> nums = [3, -2, -4, 1]
4-element Vector{Int64}:
  3
 -2
 -4
  1

julia> sort(nums)
4-element Vector{Int64}:
 -4
 -2
  1
  3

julia> sort(nums, by=abs)
4-element Vector{Int64}:
  1
 -2
  3
 -4

# j is from "Julia", as previously

julia> sort(j, by=uppercase)
5-element Vector{Char}:
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)

julia> vecs = [[1, 3], [4, 2], [3, 4], [2, 1]];

julia> sort(vecs)  # by default sorts by the first element of the (2-element) vectors
4-element Vector{Vector{Int64}}:
 [1, 3]
 [2, 1]
 [3, 4]
 [4, 2]

julia> sort(vecs, by=last)
4-element Vector{Vector{Int64}}:
 [2, 1]
 [4, 2]
 [1, 3]
 [3, 4]
```

## Ordenar pelo array de índices

Se os elementos que estão sendo ordenados forem objetos grandes, pode ser mais fácil trabalhar com o índice da sua posição.

```julia-repl
julia> langs = ["Julia", "C++", "Python", "Elixir"]
4-element Vector{String}:
 "Julia"
 "C++"
 "Python"
 "Elixir"

julia> inxs = sortperm(langs)  # => Integers
4-element Vector{Int64}:
 2
 4
 1
 3

julia> langs[inxs]  # sort the entire vector
4-element Vector{String}:
 "C++"
 "Elixir"
 "Julia"
 "Python"

julia> langs[inxs[1:2]]  # slice the indices
2-element Vector{String}:
 "C++"
 "Elixir"
```

Como `langs` é um Vector, cada índice é um número inteiro no [intervalo][concept-range] `1:length(langs)`.
A saída de `sortperm()` é uma [permutação][wiki-permutation] desses números inteiros, correspondendo à ordenação do vetor de entrada.

## Ordenação parcial

Seu programa precisa que toda a entrada seja ordenada?
Nos casos em que apenas as primeiras ou as últimas entradas interessam, pode ser bem mais rápido fazer uma [ordenação parcial][wiki-partial-sort].

Julia fornece as funções `partialsort()` e `partialsort!()`, que garantem que a entrada especificada, ou o intervalo de entradas, está correta, mas não dão nenhuma garantia sobre o restante da entrada.

O segundo argumento pode ser um número inteiro ou um intervalo, representando o índice ou os índices da entrada ordenada:

```julia-repl
julia> vsq = [9, 4, 16, 1];  # would be [1, 4, 9, 16] after a full sort

julia> partialsort(vsq, 4)
16

julia> partialsort(vsq, 2:3)
2-element view(::Vector{Int64}, 2:3) with eltype Int64:
 4
 9
```
