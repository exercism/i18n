# Introdução

O JavaScript tem um objeto embutido, `Date`, que armazena data e hora e fornece métodos para gerenciá-las.

<!-- prettier-ignore -->
~~~exercism/caution
Ele foi baseado na classe `java.util.Date` do Java, que foi substituída no início da década de 2010, mas, por compatibilidade retroativa, o `Date` do JavaScript continua por aí.

Como é difícil lidar com datas em geral e como o tratamento de fuso horário é ruim ou simplesmente inexistente, existem muitas bibliotecas, como `moment.js`, `day.js`, `date-fns` e `luxon`.
Nenhuma delas está disponível no Exercism.

Nos seus próprios projetos, não use um pacote obsoleto ou sem manutenção como o `moment.js`; prefira alternativas mais modernas, como o `luxon`, ou o [Temporal][mdn-temporal], que ainda não está amplamente disponível.
Este exercício foca no `Date`, que continuará relevante até o fim do JavaScript.

## Criação

Um objeto `Date` é uma instância da classe `Date`.
Ele pode ser criado sem passar nenhum argumento à função construtora.
Isso resulta em um objeto `Date` que representa a data e a hora atuais:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### **Timestamp Unix (número)**

Se um número for passado, ele será interpretado como um `timestamp`.
Um timestamp é um número inteiro que representa a quantidade de **milissegundos** decorridos desde **1º de janeiro de 1970 [UTC][defn-utc]+0**.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

É de se esperar que `new Date(0)` gere o objeto de data "mais antigo", mas o JavaScript converte a data para o seu fuso horário local, o que significa que só quem está em um fuso [GMT / UTC+0][defn-gmt] é que vai obter de fato o valor da [época Unix][defn-unix-epoch].

### **Timestamp ISO 8601 (string)**

Você pode passar ao construtor `Date` um valor de string que representa uma data.
O **único** formato consistente entre implementações é a [versão simplificada][mdn-date-string-format] das chamadas [strings de timestamp ISO 8601][defn-iso8601], reconhecidas e padronizadas internacionalmente.

Um instante no tempo em [UTC][defn-gmt] se parece com isto:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

Onde ocorrem as seguintes substituições:

| Chave | Descrição                                              | Padrão |
| ----- | ------------------------------------------------------ | ------ |
| YYYY  | O ano civil, representado com 4 dígitos                |        |
| MM    | O mês civil, representado com 2 dígitos                | 01     |
| DD    | O dia civil, representado com 2 dígitos                | 01     |
| T     | Uma letra T literal, que separa a data da hora         |        |
| HH    | As horas em relógio de 24 horas, 2 dígitos             | 00     |
| mm    | Os minutos, 2 dígitos                                  | 00     |
| ss    | Os segundos, 2 dígitos                                 | 00     |
| mss   | Os milissegundos, 3 dígitos                            | 000    |
| Z     | Uma letra Z literal, ou um deslocamento `+/-HH:mm`     |        |

A letra `Z` literal indica UTC (sem fuso horário, sem horário de verão).

Como a maioria dos componentes tem valores padrão, é válido omitir partes no final:

```text
YYYY-MM-DD
```

O padrão é o horário 00:00:00.000

Se o timestamp não terminar em `Z` e não terminar em `+HH:mm` ou `-HH:mm` (que indicam um deslocamento de fuso horário), por razões históricas aplica-se o seguinte:

> Quando o deslocamento de fuso horário está ausente, formas apenas com data são interpretadas como horário UTC, e formas com data e hora são interpretadas como horário local.
> A interpretação como horário UTC se deve a um erro histórico na especificação, que não era compatível com a ISO 8601, mas que não pôde ser corrigido por causa da compatibilidade com a web.
> Veja [Broken Parser – A Web Reality Issue][ref-broken-parser].

### **Objeto Date**

Um objeto de data existente também pode ser usado como argumento do construtor.
Isso cria uma cópia do objeto `Date` existente, com a mesma data e a mesma hora.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### **Fornecendo valores individuais de componentes de data e hora**

Uma data que representa apenas uma data pode ser criada passando três números.
Uma data que representa data e hora pode ser criada passando 6 números.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

O segundo valor é o `month`, que começa em `0` para janeiro e vai até `11` para dezembro.

## `Date.parse()`

Você pode encontrar menções ou referências a uma função de análise de datas, `Date.parse`.
Como essa função tem poucas invariantes (verdades) e o restante da implementação não é especificado (e, portanto, não é padrão), não convém usá-la.

## Acessando os componentes de `Date`

Há vários métodos em objetos de data que retornam os componentes da data:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

Cada um deles tem uma variante `set` correspondente (por exemplo, `setFullYear`) para atualizar o valor.
Qualquer valor que ultrapasse o limite passa para o componente seguinte:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

Existem variantes UTC de todos os métodos, que desconsideram o fuso horário local.

## Convertendo a partir de uma data

Objetos de data têm um método `getTime()` que retorna o timestamp UNIX em milissegundos, ou seja, a quantidade de milissegundos desde a meia-noite do início de 1º de janeiro de 1970, UTC.
Além disso, o método `toISOString()` está disponível para converter um objeto de data em uma string de timestamp ISO 8601.

## Comparando datas

Os operadores maior que (`>`) e maior ou igual (`>=`), assim como menor que (`<`) e menor ou igual (`<=`), podem ser usados diretamente entre duas datas ou entre uma data e um número.
Isso funciona porque o JavaScript tenta converter a data em um primitivo.

<!-- prettier-ignore -->
~~~exercism/advanced
Ao fazer uma comparação entre duas datas, ou entre uma data e um número, o JavaScript chama [`[Symbol.toPrimitive]("number")`][mdn-to-primitive], que internamente chama [`date.valueOf()`][mdn-date-value-of].
Esta última é a mesma coisa que chamar [`date.getTime()`][mdn-date-get-time].

Se você não quiser depender desse comportamento, converta para número usando `getTime()` primeiro.

[mdn-to-primitive]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/Symbol.toPrimitive
[mdn-date-value-of]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/valueOf
[mdn-date-get-time]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/getTime
~~~

Datas não podem ser comparadas com igualdade (`==` e `===`), mas o resultado de `.getTime()` pode.
