# Introdução a pipelines e listas de comandos

Vimos como escrever comandos simples, em que um comando é seguido de argumentos.
Agora veremos como criar comandos mais complexos compondo comandos simples.

## Entrada e saída

Antes de começarmos, uma rápida introdução à entrada/saída.

Os processos têm "canais de entrada/saída padrão".

* Um processo pode consumir _entrada_ em "stdin".
* Um processo pode emitir _saída_ em "stdout".
* Um processo pode emitir _saída de erro_ em "stderr".

O comando `tr` é um exemplo muito puro disso.
Tudo o que ele faz é ler texto de sua entrada, realizar transliterações de caracteres e imprimir o texto resultante em sua saída.

Veremos mais sobre como manipular canais "stdio" mais adiante no programa.

## Pipelines

Este é um dos "grandes trunfos" da programação em shell.
Pipelines permitem criar transformações sofisticadas em um fluxo de texto.

Para produzir uma lista ordenada de usuários:

```bash
cat /etc/passwd | cut -d : -f 1 | sort
```

O símbolo de pipe (`|`) conecta a saída de um comando à entrada de outro.
`cut` lê a saída de `cat`, e `sort` lê a saída de `cut`.

~~~~exercism/advanced
* Por padrão, cada comando em um pipeline roda em um subshell separado.
  (Um subshell é um processo filho que é uma cópia do shell em execução no momento.)

* Há um custo de desempenho ao rodar pipelines.
  Se você se deparar com pipelines longos de comandos semelhantes, considere combiná-los em um único comando.
  Por exemplo, pipelines que usam várias instâncias de `grep`, `cut`, `sed`, `awk` e `tr` geralmente podem ser combinados em um único comando `awk` para maior eficiência.

* O status de saída de um pipeline é o status de saída do último comando do pipeline.
  Isso significa que, se algum comando anterior falhou mas o último comando teve sucesso, o status de saída de todo o pipeline é zero.

  Há uma configuração do shell que pode mudar isso;
  se a configuração "pipefail" estiver habilitada (com `set -o pipefail`), o status de saída do pipeline será:
  * zero se todos os comandos tiverem sucesso; caso contrário,
  * o _**último** status de saída diferente de zero_ dos comandos no pipeline.
~~~~

## Listas de comandos

Uma lista de comandos é uma sequência de pipelines separados por `;` (ou nova linha), `&&` ou `||`.

* `A; B` é uma lista de comandos em que `B` é executado depois que `A` termina.
* `A && B`, em que `B` é executado somente se `A` tiver sucesso (termina com status zero).
* `A || B`, em que `B` é executado somente se `A` falhar (termina com status diferente de zero).

O status de saída de uma lista de comandos é o status de saída do último comando executado.

Os operadores `&&` e `||` podem ser encadeados para que o próximo comando seja executado condicionalmente com base no status dos comandos anteriores.
Por exemplo

```bash
A && B && C && D || E
```

* B é executado se A tiver sucesso,
* C é executado se A e B tiverem sucesso,
* D é executado se A, B e C tiverem sucesso,
* E é executado se **qualquer um** de A, B, C ou D falhar.

~~~~exercism/caution
Use esses operadores lógicos com moderação.
Eles podem rapidamente levar a código ilegível ou a uma lógica difícil de compreender.

Por exemplo, você pode achar que estes são iguais:

```bash
if A; then B; else C; fi
```

```bash
A && B || C
```

A diferença é: quando C é executado?

* No primeiro trecho (a condicional), C será executado somente se A falhar.
* No segundo trecho, C será executado se A falhar _ou se A tiver sucesso mas B falhar_!
~~~~

### Usos de listas de comandos

Aqui estão alguns exemplos em que listas de comandos podem simplificar o código.

#### Lendo blocos de linhas de um arquivo

Suponha que você tenha um arquivo de dados contendo dados sobre triângulos,
e um triângulo é representado por três linhas separadas que contêm os lados do triângulo.

```bash
$ cat triangle.dat
3
4
5
9
12
14
```

Você pode usar um laço `while` em que a condição são três comandos `read` separados:

```bash
while read a && read b && read c; do
    if is_pythagorean "$a" "$b" "$c"; then
        echo "$a:$b:$c is pythagorean"
    else
        echo "$a:$b:$c is not pythagorean"
    fi
done < triangle.dat
```

Supondo que `is_pythagorean` seja um comando que determina se os três lados satisfazem a equação pitagórica, a saída seria:

```none
3:4:5 is pythagorean
9:12:14 is not pythagorean
```

#### Asserções

Muitas linguagens de programação têm uma forma de asserção em que uma exceção é lançada se alguma condição falhar

```
assert(user == "Administrator", "wrong user");
```

Podemos usar um operador OR no Bash para simular essa função:

```bash
die () { # a little convenience function
    echo "$*" >&2
    exit 1
}

[[ $user == "Administrator" ]] || die "wrong user"
[[ $password == "secret!" ]]   || die "incorrect password"
```

## Considerações de estilo

Listas de comandos longas ficam difíceis de ler muito rápido.
O uso generoso de quebras de linha pode ajudar bastante.

Considere este exemplo em que uma palavra é adicionada a um array se duas condições forem atendidas.

```bash
[[ "$word" != "$topic" ]] && [[ "$key" == "$(sorted "$topic")" ]] && anagrams+=("$candidate")
```

O Bash permite adicionar uma quebra de linha após um pipe ou um operador lógico.

```bash
[[ "$word" != "$topic" ]] &&
[[ "$key" == "$(sorted "$topic")" ]] &&
anagrams+=("$candidate")
```

No entanto, o operador pode ser fácil de passar despercebido no final da linha.
Usar uma _continuação de linha_ significa que você pode colocar o operador primeiro, o que deixa mais óbvio que a lista está sendo continuada:

```bash
[[ "$word" != "$topic" ]] \
&& [[ "$key" == "$(sorted "$topic")" ]] \
&& anagrams+=("$candidate")
```

~~~~exercism/note
Uma _continuação de linha_ é a sequência de dois caracteres "barra invertida" e "nova linha" (`\` + `\n`).
Quando o Bash vê essa sequência, ela é simplesmente removida do código, _continuando_ assim a linha atual com a próxima linha.
Tenha cuidado para não permitir espaços entre a barra invertida e a nova linha.
~~~~

Aqui está outro exemplo

```bash
printf "%s\n" "${numbers[@]}" | bc --mathlib | sort --general-numeric-sort
```

ou

```bash
printf "%s\n" "${numbers[@]}" \
| bc --mathlib \
| sort --general-numeric-sort
```
