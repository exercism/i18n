# Sobre

Exceções são uma forma de tratamento de erros.
Elas são chamadas de exceções porque normalmente surgem quando lidamos com algum evento inesperado.

Em qualquer ponto do nosso código, podemos dar um "raise" em uma exceção.
Fazemos isso usando o método `raise`, passando um objeto, normalmente um objeto `Exception`, embora também possamos usar strings básicas.
Por exemplo, você vai ver nos stubs dos exercícios que usamos `RuntimeError`, que já vem embutido, para dizer ao Ruby que um método não foi implementado.
Você também pode usar a sintaxe abreviada de `raise(ExceptionObject, params)`.
Se a classe da exceção for omitida, `RuntimeError` é usado por padrão.

Por exemplo:

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

Quando o Ruby vê isso, ele faz o erro subir até o topo do programa e então encerra a execução.

Por exemplo, se você tentar dividir algo por zero, vai ver algo assim:

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

É importante notar que as exceções devem ser usadas em casos em que algo excepcional acontece, um erro que precisa de um tratamento especial.
Exceções não devem ser usadas para o fluxo de controle de um programa, pois isso é considerado um design ruim, que costuma levar a problemas de desempenho e de manutenção.

## Hierarquia de classes

No Ruby, as exceções seguem uma hierarquia de classes em que `Exception` é a classe base.
Estas são as exceções embutidas mais comuns do Ruby:

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

Resgatar erros de uma classe específica também resgata os erros das suas classes filhas.
É por isso que resgatar a partir de `Exception` pode ser perigoso.
O Ruby também usa exceções para tratar mensagens de "Signals" do sistema operacional, por exemplo `ctrl-c`.
Isso significa que resgatar a partir de `Exception` também vai capturar esses "Signals" do sistema.
Então, para evitar comportamentos inesperados, a prática comum para capturar "todos os erros" é resgatar a partir de `StandardError`.

## Sintaxe do rescue

O Ruby também oferece cláusulas rescue estendidas para situações que exigem um tratamento especial:

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

Isso pode ser útil, por exemplo, ao trabalhar com IO de rede, quando sempre precisamos lembrar de fechar uma conexão.

Os blocos rescue do Ruby também podem usar a palavra-chave `retry`, que executa de novo tudo o que está entre begin e rescue:

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
