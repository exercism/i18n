# Apêndice das instruções

## Observações sobre a implementação de `smallest` e `largest`:

As duas funções devem receber dois argumentos nomeados:
- `max_factor`: int
- `min_factor`: int, padrão 0

O valor de retorno delas deve ser uma `tuple -- (value, factors)`, em que `value` é o
próprio palíndromo e `factors` é um `iterable` que contém os dois fatores do
palíndromo em ordem arbitrária.


## Mensagens de exceção

Às vezes é necessário [levantar uma exceção](https://docs.python.org/3/tutorial/errors.html#raising-exceptions). Quando você faz isso, deve sempre incluir uma **mensagem de erro significativa** para indicar qual é a origem do erro. Isso deixa seu código mais legível e ajuda bastante com o debug. Em situações em que você sabe que a origem do erro é de um tipo específico, pode optar por levantar um dos [tipos de erro embutidos](https://docs.python.org/3/library/exceptions.html#base-classes), mas ainda deve incluir uma mensagem significativa.

Este exercício em particular exige que você use a [instrução raise](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement) para “lançar” um `ValueError` quando a função `largest()` ou `smallest()` receber um par de fatores que não estão na faixa correta. Os testes só vão passar se você usar o `raise` na `exception` e incluir uma mensagem com ela.

Para levantar um `ValueError` com uma mensagem, escreva a mensagem como um argumento do tipo `exception`:

```python
# if the max_factor is less than the min_factor
raise ValueError("min must be <= max")
```
