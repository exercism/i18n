# Introdução

Tipos simples (strings e tipos primitivos) costumam ser testados quanto à igualdade com os operadores `==` e `!=`.

Tipos de referência (instâncias de classes) são comparados usando o método `Equals()` herdado de `Object`. Se o seu objetivo com o teste de igualdade é garantir que dois objetos sejam exatamente a mesma instância, a implementação de `Object` já basta. Caso contrário, você precisa sobrescrever `object.Equals()`.

Se você sabe que todas as instâncias da sua classe são criadas em um único lugar, como os personagens de um jogo ou de uma simulação, a igualdade de referência é suficiente. No entanto, é provável que várias instâncias da mesma entidade do mundo real sejam criadas (a partir de um banco de dados, pela entrada do usuário, por meio de uma requisição web). Nesse caso, os valores que identificam a entidade de forma única precisam ser testados quanto à igualdade. Por isso, `Equals()` deve ser sobrescrito e os membros de dados apropriados da sua classe são testados quanto à igualdade.

Um método `Equals()` sobrescrito vai conter testes de igualdade nos membros de tipos simples usando `==` e em tipos de referência com chamadas recursivas a `Equals()`.

A classe `Object` oferece os métodos apropriados para comparar dois objetos e detectar se são uma e a mesma instância.

## `Object.GetHashCode()`

O método `Object.GetHashCode()` retorna um código hash na forma de um número inteiro de 32 bits. O código hash é usado por classes de _dicionário_ e de _conjunto_, como `Dictionary<T>` e `HashSet<T>`, para armazenar e recuperar objetos de forma performática.

A relação entre código hash e igualdade é a seguinte: se dois objetos são iguais (`Equal()` retorna true), então `GetHashCode()` dos dois objetos deve retornar o mesmo valor. Isso não vale na direção contrária. A relação não é simétrica. Só porque dois objetos têm o mesmo código hash, eles não precisam ser iguais. Imagine uma função de busca que primeiro vai até um "bucket" com base no código hash e depois seleciona o item específico usando o teste de igualdade.

A documentação da API da biblioteca HashCode discute a melhor forma de gerar um código hash

Os valores usados no teste de igualdade devem ser estáveis enquanto a coleção com hash estiver em uso. Se você adicionar um objeto à coleção com um conjunto de valores e depois alterar esses valores, o código hash não apontará mais para o "bucket" correto. Na prática, isso significa que o objeto deve ser imutável. Outras abordagens correm o risco de criar armadilhas para quem for dar manutenção no código.
