# Como contribuir com um conceito + exercício de conceito

Um [exercício de conceito][product-concept] tem como objetivo ensinar um único conceito em uma determinada linguagem.
Ele deve ter um objetivo de aprendizagem claro e fornecer código de base suficiente para evitar que o estudante precise aprender código desnecessário.
O conceito associado tem sua própria documentação, independente do exercício de conceito.
Os conceitos podem ter outros conceitos como pré-requisitos e ficar bloqueados até que os exercícios de conceito dos conceitos pré-requisitos sejam concluídos.
A dificuldade dos exercícios de conceito não deve aumentar conforme a trilha avança.
Um exercício de conceito deve ser resolvido em 5 a 10 minutos por qualquer desenvolvedor familiarizado com os conceitos pré-requisitos.

Agora que sabemos o que é um exercício de conceito, vamos detalhar como implementar um, junto com o conceito associado.
Para referência, a [especificação detalhada de um exercício de conceito][concept-exercise-spec] e de um [conceito][concept-spec] estão disponíveis no [repositório de docs][docs-repo] do exercism.
Este documento reúne informações de diversas fontes para servir como um guia conveniente, passo a passo, de como contribuir com um exercício de conceito.

Os conceitos já implementados devem aparecer com um fundo verde e um contorno mais forte.

## 2. Defina os objetivos de aprendizagem

É importante saber o que um exercício de conceito pretende ensinar e o que está fora do escopo, então vamos criar nosso primeiro arquivo: `exercises/concept/<story-name>/.meta/design.md`.
Como os exercícios de conceito recebem o nome da história que usam e ainda não a conhecemos, vamos manter `story-name` por enquanto e substituí-lo depois.
A [especificação do `design.md`][design-spec] diz que este documento deve definir o objetivo geral do exercício, seus diversos objetivos de aprendizagem, as coisas que estão fora do escopo, o conceito associado que ele desbloqueia e os pré-requisitos de conceitos para conseguir concluir o exercício.
Você pode usar o [`design.md` do exercício de conceito de boolean][design-bool] como ponto de partida de modelo.

## 3. Escreva uma introdução de conceito para o exercício

Assim que os objetivos de aprendizagem estiverem claros, é hora de escrever uma introdução que explique o suficiente do conceito para que o estudante consiga resolver o exercício.
Crie um arquivo `exercises/concept/<story-name>/.docs/introduction.md`.
O conteúdo detalhado deste arquivo é explicado na [sua especificação][exercise-intro-spec].
Você pode usar o [`introduction.md` do exercício de conceito de boolean][intro-bool] como ponto de partida de modelo.

As informações fornecidas devem introduzir o conceito o suficiente para o estudante descobrir sozinho a solução do exercício.
Use termos técnicos adequados para facilitar a busca do estudante na internet.
Tente evitar links e, em vez disso, explique as coisas de forma concisa no próprio texto.
Apresente a sintaxe do código com blocos de código.

## 4. Encontre uma história para o exercício

Cada exercício de conceito deve ser baseado em uma história ou um tema.
Tentamos torná-los o mais inclusivos possível, sabendo que o Exercism é usado no mundo todo.
A primeira opção é reutilizar uma história existente da [lista de histórias registradas nos docs][stories].
Se você quiser criar uma nova história, não hesite em marcar @exercism/leadership no seu PR.
Agora você pode renomear o diretório `exercises/concept/<story-name>/` para corresponder à sua história.

## 5. Escreva as instruções do exercício

Depois de encontrar a história, precisamos escrever instruções precisas enumerando as tarefas que o estudante terá que realizar.
Tanto a história quanto as instruções são escritas no documento `exercises/concept/<story-name>/.docs/instructions.md`.
Como explicado na [especificação desse documento][instructions-spec], cada tarefa tem seu próprio título markdown de nível 2 (`## 1. Do X`) seguido de uma descrição e um exemplo de uso do código.
Você pode usar o [`instructions.md` do exercício de conceito de boolean][instructions-bool] como ponto de partida de modelo.

Além do `instructions.md`, também precisamos de um arquivo `hints.md`.
Ele deve conter os mesmos títulos de nível 2 (`## 1. Do X`) do arquivo de instruções, para que as dicas certas sejam dadas dependendo da tarefa em andamento.
Também pode haver uma seção `## General` para dicas que se aplicam a todas as tarefas.
As dicas não devem revelar a solução diretamente.
Além disso, lembre-se de que quem clica nas dicas pode já estar confuso/sobrecarregado/frustrado com o exercício.
Há mais informações sobre este documento na [sua especificação][hints-spec], e você pode usar o [`hints.md` do exercício de conceito de boolean][hints-bool] como ponto de partida de modelo.

## 6. Abra um pull request em rascunho para validar o design

Agora é um bom momento para abrir um pull request em rascunho do seu exercício de conceito!
Temos material suficiente para avaliar o exercício e reformulá-lo se necessário antes de fixá-lo no estado atual para os demais arquivos necessários.
Não se preocupe se as verificações automáticas da CI falharem por causa de documentos ausentes, vamos criá-los depois!

## 7. Escreva o código

Vamos escrever o código como se estivéssemos resolvendo o exercício e, depois, moveremos os arquivos para cumprir as especificações.
Vamos começar copiando o conteúdo do diretório [`template/`][template] para dentro do nosso diretório `exercises/concept/<story-name>/`.
Isso significa que temos os seguintes arquivos:

```txt
elm.json           # elm project configuration file
src/Exercise.elm   # code for the exercise
tests/Tests.elm    # tests for the exercise
```

Depois, renomeie `Exercise.elm` para usar o PascalCase do nome da história.
Por exemplo, `annalyns-infiltration` vira `AnnalynsInfiltration.elm`.
Dentro desse arquivo-fonte, agora você pode escrever todas as funções descritas no `instructions.md` que acabamos de escrever.

Depois que o exercício estiver implementado, atualize o conteúdo do arquivo `tests/Tests.elm` para incluir testes relevantes que sigam naturalmente a ordem das tarefas no `instructions.md`.
**Evite usar `Fuzz`** nos testes dos exercícios de conceito, pois ele não se dá bem com a capacidade de depurar o código com `Debug.log`.
Em vez disso, inclua alguns testes unitários de casos extremos e de casos gerais.
**Evite usar expressões `let` diretamente sob chamadas das funções `test` ou `describe`** nos testes dos exercícios de conceito, pois o [test runner do elm ainda não dá suporte a isso](https://github.com/exercism/elm-test-runner/issues/30).

Depois que tanto o exercício quanto os testes estiverem prontos e funcionando bem, faça o seguinte:

- Copie `src/<ExerciseSlug>.elm` para `.meta/Exemplar.elm`. Sua implementação serve como referência, uma implementação "exemplar" para o exercício, que é usada ao rodar os testes da trilha.
- Remova todas as implementações de dentro de `src/<ExerciseSlug>.elm` para deixar um arquivo inicial pronto para o estudante começar o exercício.

## 8. Escreva a documentação do conceito

Crie um diretório `concepts/<concept>/` para o conceito associado ao nosso exercício `exercises/concept/<story-name>`.
Dentro dessa nova pasta, criamos dois documentos markdown, [`introduction.md`][concept-intro-spec] e [`about.md`][concept-about-spec], e um arquivo [`links.json`][concept-links-spec] (os links levam às suas especificações).

O arquivo de conceito `introduction.md` contém a apresentação que os estudantes verão na página do conceito enquanto não tiverem concluído o exercício de conceito associado.
Ele deve dar uma boa visão geral do que eles vão aprender se começarem o exercício associado.
Em contraste, o arquivo de conceito `about.md` contém o resumo do conceito que um estudante verá na página do conceito apenas depois de ter concluído o exercício de conceito associado.
Sendo assim, eles têm conteúdo semelhante ao do arquivo `exercises/concept/<story-name>/.docs/introduction.md` que já escrevemos, mas não são iguais.
Sugiro começar pelo documento de introdução do exercício e simplificá-lo à sua essência para o arquivo de conceito `introduction.md`.
E, para o documento `about.md`, comece pela introdução do exercício e complete-a de modo que todas as informações relevantes sobre o conceito estejam presentes nessa página.
O `links.json` fornece links úteis com informações adicionais sobre um conceito.
Podem ser documentações oficiais, um ótimo tutorial, etc.
Esses links não substituem os links mais contextuais dentro do arquivo about.md de um conceito, mas fornecem um conjunto rápido de referências abrangentes para o estudante.
Os links também podem ter, opcionalmente, um campo icon_url, que pode ser usado para personalizar o ícone exibido quando o link é mostrado. Se não for especificado, o ícone padrão é o favicon.
Você pode encontrar ícones disponíveis em [github.com/exercism/website-icons/tree/main/exercises][icons].

## 9. Complete os diferentes arquivos de configuração

Agora que o código e a documentação estão prontos, restam alguns arquivos de configuração para deixar este PR completo:

- [`concepts/<concept>/.meta/config.json`][concept-config-json]: coloque você mesmo como autor, possíveis revisores como contribuidores e adicione uma "blurb" (descrição curta).
- [`exercises/concept/<story-name>/.meta/config.json`][exercise-config-json]: contém autores (você), contribuidores, blurb e outras coisas. Consulte a especificação linkada.
- `config.json`: adicione uma [entrada de conceito][track-config-json-concept] e uma [entrada de exercício de conceito][track-config-json-concept-exercise] no arquivo `config.json` da trilha. Use "wip" ou "beta" para a chave status do exercício de conceito. Os UUIDs podem ser gerados com o [executável configlet][configlet] fornecido pelo exercism.
