# Introdução a comandos e argumentos

Esta trilha não é sobre como usar o bash como um shell interativo.
É sobre aprender a escrever programas usando bash, a linguagem de programação.

Um programa bash, ou _script_, é uma sequência de comandos armazenada em um arquivo.
O bash (o executável) lê o arquivo e executa os comandos em ordem.

## O shebang

A primeira linha de um script geralmente é uma _diretiva de intérprete_, também chamada de _hashbang_ ou _shebang_:

```bash
#!/usr/bin/env bash
```

Quando o sistema operacional executa um _arquivo não binário_, ele lê a primeira linha.
Se a linha começar com `#!`, o kernel a usa para determinar qual intérprete deve executar o arquivo.
O `#!` precisa estar bem no início do arquivo, sem espaços nem linhas em branco antes dele.

Aqui, o `env` procura no `PATH` o executável `bash`.
Você também pode encontrar o mais simples `#!/bin/bash`, que fixa o local do intérprete; a forma com `env` é mais portátil.

~~~~exercism/note
Não se deixe enganar por scripts ou exemplos na internet que usam `/bin/sh` como intérprete.
**`sh` não é `bash`!**
O bash é "compatível com sh" e consegue rodar a maioria dos scripts `sh`, mas alguns recursos do bash quebram ou se comportam de forma inesperada no `sh`.
~~~~

## Comentários

Uma linha que começa com `#` é um _comentário_, e o bash a ignora.
Um comentário também pode vir depois de um comando na mesma linha: tudo, do `#` até o fim da linha, é ignorado.
Comentários existem para as pessoas que leem o script.

## Palavras e argumentos

O bash lê comandos da sua entrada (que geralmente é um terminal ou um arquivo).
Cada linha de entrada que ele lê é tratada como um _comando_, uma instrução a ser executada.
(Existem alguns casos avançados, como comandos que ocupam várias linhas, que veremos mais adiante.)

O bash divide cada comando em **palavras** delimitadas por caracteres de espaço em branco (espaços e tabulações).
A primeira palavra é o nome do _comando_ a ser executado.
Todas as palavras restantes se tornam _argumentos_ desse comando (opções, nomes de arquivos etc.).

Um comando pode ser um _builtin_ do bash, como o `echo`, ou um programa _executável_, como `head`, `awk` ou `sed`.

## O comando `echo`

O `echo` imprime seus argumentos separados por um único espaço e termina com uma quebra de linha:

```bash
echo flour sugar eggs
```

produz:

```text
flour sugar eggs
```

A quantidade de espaço em branco entre os argumentos não importa:

```bash
echo flour       sugar        eggs
```

```text
flour sugar eggs
```

Chamar o `echo` sem nenhum argumento imprime uma linha em branco.

## Opções são apenas argumentos

Muitos comandos aceitam _opções_ que mudam como eles se comportam.
Para o bash, uma opção não tem nada de especial: é uma palavra como qualquer outra, separada das vizinhas por espaço em branco.
O próprio comando decide como interpretar seus argumentos.
Por convenção, as opções começam com um `-`.

O comando `head` imprime as primeiras linhas de um arquivo.
Dado um arquivo `list.txt`:

```bash
head -n 2 list.txt
```

O bash divide essa linha em quatro palavras:

| Palavra    | Papel                                             |
| ---------- | ------------------------------------------------- |
| `head`     | o comando a ser executado                         |
| `-n`       | uma opção, que diz ao `head` para contar _linhas_ |
| `2`        | o valor da opção `-n`                             |
| `list.txt` | o arquivo a ser lido                              |

O bash passa as três últimas palavras ao `head` sem alterá-las.
É o `head` que entende que `-n` vem seguido de um número e que a palavra restante é um arquivo.

Como é o espaço em branco que separa as palavras, importa onde você o coloca.
`head -n 2` dá ao `head` dois argumentos (`-n` e `2`), enquanto `head -n2` dá apenas um (`-n2`).
Muitos comandos aceitam as duas formas, mas isso depende do comando.
O bash não se importa; ele só divide a linha em palavras.

## Argumentos entre aspas

[Aspas][Quotes] agrupam palavras em um _único argumento_.
O espaço em branco dentro das aspas é preservado, e os próprios caracteres de aspas não fazem parte do argumento:

```bash
echo "flour       sugar        eggs"
```

```text
flour       sugar        eggs
```

Se um argumento, como um nome de arquivo, contém espaço em branco, coloque-o entre aspas:

```bash
head -n 1 my shopping list.txt     # three files: "my", "shopping", "list.txt"
head -n 1 "my shopping list.txt"   # one file
```

## Executando um script

Para executar um script, passe-o como argumento ao comando `bash`:

```bash
bash myscript
```

Usada desse jeito, a linha `#!` é apenas um comentário.
Você está dizendo ao sistema operacional como executar o arquivo.

Como alternativa, marque o arquivo do script como executável e rode-o como qualquer outro programa:

```bash
chmod +x myscript
./myscript
```

Agora o sistema operacional usa a linha `#!` para determinar qual intérprete usar.
