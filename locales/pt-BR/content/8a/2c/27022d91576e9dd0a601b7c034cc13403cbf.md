# Introdução

## Exceções

Todos os erros em Elixir implementam o _Comportamento de Exceção_. Assim como o _Comportamento de Acesso_, o _Comportamento de Exceção_ define funções de callback que um módulo precisa implementar para cumprir o contrato de software do comportamento. Depois que um erro é definido, ele tem as seguintes propriedades:

- O nome do módulo define o nome do erro.
- O módulo define uma struct de erro.
- A struct terá um campo `:message`.
- O módulo pode ser usado com `raise/1` e `raise/2` para lançar o erro pretendido

O _Comportamento de Exceção_ também especifica dois callbacks: `message/1` e `exception/1`. Se não forem implementados, serão usadas implementações padrão. `message/1` transforma a struct de erro em uma mensagem legível quando chamada com `raise`. `exception/1` permite que contexto adicional seja adicionado à mensagem quando ela é chamada com `raise/2`

### Definindo uma exceção

Para definir uma exceção a partir de um módulo de erro, usamos a macro `defexception`:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

### Usando exceções

Erros definidos podem ser usados como um erro embutido, com `raise/1` ou `raise/2`.

- `raise/1` lança um erro específico pelo nome do seu módulo ou, se o argumento for uma string, lança um `RuntimeError` com a string como mensagem.
- `raise/2` lança um erro específico pelo nome do seu módulo e aceita um argumento de atributos, que é usado para obter o erro com a mensagem apropriada.
