# Testes

Cada exercício fornece os testes de unidade.
Você escreve a implementação.
Cada arquivo gera um executável de console que roda os testes.
Ao rodar o executável de testes, ele imprime mensagens para cada teste que falha e retorna um status de saída diferente de zero quando os testes falham.

*Observação* Seu código é testado com a suíte de testes toda vez que você compila o projeto.
Se o seu código não passar em um ou mais testes, mas for código D válido, ele ainda será compilado.

Resolver cada exercício é um processo de:

* Rodar os testes com `dub test`
  * Se você optou por não instalar o DUB, use `dmd source/*.d -de -w -main -unittest` e depois rode o binário gerado.
* Para cada teste de unidade:
  * Resolva os erros de compilação para fazer o teste falhar.
  * Implemente o suficiente para fazer o teste passar.
  * Refatore a sua implementação para melhorar a legibilidade, reduzir duplicação etc.
  * Habilite o próximo teste

*Observação:* o D tem suporte a testes de unidade direto na linguagem, então normalmente os testes de unidade ficam no mesmo arquivo que a implementação.
Os testes de unidade rodam antes do corpo da main e são habilitados no executável final com a opção **-unittest** do compilador.

## Como interpretar a saída dos testes de unidade

Se todos os testes passarem, a saída pode ser mais ou menos assim

```none
$ dub test
             Generating test runner configuration 'dnd-character-test-library' for 'library' (library).
    Starting Performing "unittest" build using dmd for x86_64.
    Building dnd-character ~master: building configuration [dnd-character-test-library]
     Linking dnd-character-test-library
     Running dnd-character-test-library
1 modules passed unittests
```
