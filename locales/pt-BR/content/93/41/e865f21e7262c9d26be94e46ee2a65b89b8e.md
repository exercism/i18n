# Testes

Você pode rodar os exercícios de Odin dentro do diretório do seu projeto do Exercism entrando no diretório do exercício e executando `odin test .`.

```sh
cd "$(exercism workspace)"/odin/leap
odin test .
```

## Ativando as verificações da linguagem

Enquanto você testa, o Odin pode fazer um "vet" no seu código: ele procura coisas como imports e variáveis não usadas.

Rode seus testes com

```sh
odin test . -vet
```

Para ainda mais verificações, adicione a opção `-strict-style`.

## Desenvolvimento Orientado a Testes (TDD)

O `odin test` roda cada procedimento que tem o atributo `@(test)`.

No conjunto de testes, você vai reparar que cada procedimento de teste tem esse atributo.
Isso significa que, quando você rodar os testes, cada procedimento de teste vai ser executado.

O Exercism em geral incentiva o [Desenvolvimento Orientado a Testes][tdd], em que:

- no começo, todos os testes, exceto o primeiro, são configurados para serem ignorados;
- você escreve só o código suficiente para passar no primeiro teste;
- depois você ativa o próximo teste e escreve só o código suficiente para fazê-lo passar;
- repita até seu código passar em todos os testes.

Nós (os mantenedores) não encontramos uma forma programática elegante de executar apenas um subconjunto dos testes.
O arquivo de testes simplesmente ficou complicado demais de lidar.
Para desenvolver com TDD, você pode editar o arquivo de testes e simplesmente comentar os testes que ainda não é hora de executar, e descomentá-los um a um conforme escreve sua solução.
