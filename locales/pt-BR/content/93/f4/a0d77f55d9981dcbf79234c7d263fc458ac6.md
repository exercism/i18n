- Leia sobre o comportamento `GenServer` [na documentação][genserver].

## 1. Inicie a máquina

- Lembre-se de [usar][use] o [comportamento `GenServer`][genserver].
- Existe [uma função nativa][start-link] que inicia um processo `GenServer` vinculado. A única coisa que `TakeANumberDeluxe.start_link/2` precisa fazer é chamar essa função com os argumentos certos.
- `__MODULE__` é uma variável especial que contém o nome do módulo atual.
- Implemente o [callback do `GenServer` usado ao iniciar o processo][init].
- O callback deve retornar `{:ok, state}` ou `{:stop, reason}`.
- Leia as opções da lista de palavras-chave `init_arg`.
- Existe [uma função nativa][keyword-get] para obter um valor de uma lista de palavras-chave.
- Use `TakeANumberDeluxe.State.new/2` para obter o estado inicial.
- Use `@impl` acima da implementação do seu callback para indicar de qual comportamento esse callback vem.

## 2. Reporte o estado da máquina

- Existe [uma função nativa][call] que envia uma mensagem para um processo `GenServer` e recebe uma resposta. A única coisa que `TakeANumberDeluxe.report_state/1` precisa fazer é chamar essa função com os argumentos certos.
- As mensagens enviadas a um servidor podem ser qualquer coisa, mas átomos são melhores.
- Implemente o [callback do `GenServer` usado ao tratar mensagens que precisam de uma resposta][handle-call].
- O callback deve retornar `{:reply, reply, state}`.
- Passe o estado como resposta.
- Use `@impl` acima da implementação do seu callback para indicar de qual comportamento esse callback vem.

## 3. Enfileire novos números

- Existe [uma função nativa][call] que envia uma mensagem para um processo `GenServer` e recebe uma resposta. A única coisa que `TakeANumberDeluxe.queue_new_number/1` precisa fazer é chamar essa função com os argumentos certos.
- As mensagens enviadas a um servidor podem ser qualquer coisa, mas átomos são melhores.
- Implemente o [callback do `GenServer` usado ao tratar mensagens que precisam de uma resposta][handle-call].
- O callback deve retornar `{:reply, reply, state}`.
- Obtenha a resposta e o novo estado chamando `TakeANumberDeluxe.State.queue_new_number/1`. Use uma expressão [`case`][case] para fazer pattern matching do valor de retorno.
- A resposta deve ser `{:ok, new_number}` ou `{:error, error}`.
- Use `@impl` acima da implementação do seu callback para indicar de qual comportamento esse callback vem.

## 4. Atenda o próximo número da fila

- Existe [uma função nativa][call] que envia uma mensagem para um processo `GenServer` e recebe uma resposta. A única coisa que `TakeANumberDeluxe.serve_next_queued_number/2` precisa fazer é chamar essa função com os argumentos certos.
- As mensagens enviadas a um servidor podem ser qualquer coisa, mas tuplas são melhores se for preciso enviar um argumento na mensagem. Use uma mensagem como esta: `{:my_message_name, some_argument}`.
- Implemente o [callback do `GenServer` usado ao tratar mensagens que precisam de uma resposta][handle-call].
- O callback deve retornar `{:reply, reply, state}`.
- Obtenha a resposta e o novo estado chamando `TakeANumberDeluxe.State.serve_next_queued_number/2`. Use uma expressão [`case`][case] para fazer pattern matching do valor de retorno.
- A resposta deve ser `{:ok, next_number}` ou `{:error, error}`.
- Use `@impl` acima da implementação do seu callback para indicar de qual comportamento esse callback vem.

## 5. Redefina o estado

- Existe [uma função nativa][cast] que envia uma mensagem para um processo `GenServer` e não espera por uma resposta. A única coisa que `TakeANumberDeluxe.reset_state/1` precisa fazer é chamar essa função com os argumentos certos.
- As mensagens enviadas a um servidor podem ser qualquer coisa, mas átomos são melhores.
- Implemente o [callback do `GenServer` usado ao tratar mensagens que não precisam de uma resposta][handle-cast].
- O callback deve retornar `{:noreply, state}`.
- Use `TakeANumberDeluxe.State.new/2` para obter o novo estado, assim como em `init/1`.
- Use `@impl` acima da implementação do seu callback para indicar de qual comportamento esse callback vem.

## 6. Implemente o desligamento automático

- Faça com que todos os callbacks `init/1` e `handle_*` retornem um elemento a mais nas tuplas. O valor dele deve ser `state.auto_shutdown_timeout`.
- O valor de retorno `{:stop, reason}` de `init/1` não precisa de timeout.
- Implemente o [callback do `GenServer` usado ao tratar mensagens que não foram enviadas da forma habitual do `GenServer`][handle-info].
- Esse callback precisa tratar as mensagens `:timeout` e encerrar o processo, mas também capturar e ignorar quaisquer outras mensagens.
- Para encerrar um processo GenServer, retorne `{:stop, reason, state}` do callback.
- O motivo do encerramento deve ser `:normal`.
