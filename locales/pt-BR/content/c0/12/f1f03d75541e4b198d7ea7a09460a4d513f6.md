# About

`<dlist>` (em [`dlists`][dlists]) constrói uma lista duplamente encadeada nova. As operações ficam em [`deques`][deques] e são despachadas pelo [protocolo de deque][deque-protocol], então outros contêineres, principalmente o `<dlist>`, podem implementá-las.

| palavra        | efeito                              |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )`: deque vazio e novo  |
| `push-front`    | `( elt deque -- )`: adiciona ao início |
| `push-back`     | `( elt deque -- )`: adiciona ao final  |
| `pop-front`     | `( deque -- elt )`: remove do início |
| `pop-back`      | `( deque -- elt )`: remove do final  |
| `peek-front`    | `( deque -- elt )`: lê o início sem remover |
| `peek-back`     | `( deque -- elt )`: lê o final sem remover  |
| `deque-empty?`  | `( deque -- ? )`: o deque está vazio? |
| `dlist-length`  | `( dlist -- n )`: número de elementos |

Todas as operações de push/pop modificam o deque no local: passar um deque para uma rotina e depois lê-lo de novo é o padrão normal.

## Pilha vs. fila

Dois padrões de despacho convencionais:

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

Um vetor com `push` e `pop` (de `mutation`) é a escolha certa quando a ordem LIFO é tudo o que você precisa: o `<dlist>` carrega a sobrecarga de uma lista encadeada. Recorra ao `<dlist>` quando precisar de O(1) nas *duas* pontas, quase sempre para uma fila FIFO.

## Padrão de BFS

A busca em largura é o uso canônico de uma fila FIFO:

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

O deque carrega a fronteira da busca; o hash-set carrega a desduplicação. Troque `pop-front` por `pop-back` e a mesma estrutura vira uma busca em profundidade.

## `MEMO:`: cache automático

Às vezes, a consulta por nó que a BFS faz é cara. O Factor fornece [`MEMO:`][memo-decl], um substituto para `:` que coloca automaticamente em cache o resultado da palavra, usando as entradas como chave:

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

Uma palavra `MEMO:` executa o corpo na primeira vez que cada entrada aparece e, a partir daí, devolve o resultado em cache. O cache dura toda a vida da imagem; não há descarte por tempo nem por tamanho. Use isso para funções puras cujas entradas vêm de um conjunto finito e administrável.
