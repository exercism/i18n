# Introdução

## Referências

### Cópias e referências

Com o que sabemos até agora, é um pouco complicado atualizar uma variável com a ajuda de uma função.
Todo argumento de função é tratado como uma cópia e não altera o valor original.
Dependendo do tamanho do seu tipo, isso pode ter consequências sérias para o desempenho do seu código.

```cpp
int adjust_salary(int base, int kids) {
    return base + kids * 500;
}
int now_a_mother_of_twins{2500};
adjust_salary(now_a_mother_of_twins, 2);

// now_a_mother_of_twins is still 2500
now_a_mother_of_twins = adjust_salary(now_a_mother_of_twins, 2);
// now_a_mother_of_twins is now 3500
```

Dá para pensar em `References` como apelidos: mudanças nelas têm efeito sobre a variável original.
`References` usam um **e comercial** (`&`) na declaração de tipo.

```cpp
int balance{1000};
int& budget{balance};
int pro_computer_wheels{699};
budget -= pro_computer_wheels;
// budget is now 301;
// balance is also 301;
```

Não é possível reassentar (mudar a ligação de uma `reference`).
Você não pode ter uma `reference` não inicializada.
É preciso inicializar `References` com uma variável existente.

```cpp
int main_acc{1'000'000};
int side_acc{-20};
int& savings{main_acc};
// => main_acc and savings are 1'000'000

// try to reseat savings to use main account
savings = side_acc;
// savings and main_acc are now -20
// as this uses the **value** of side_acc
savings += 20;
// savings and main_acc are now 0, side_acc is still -20

int& future_budget;
// => compiler error, reference must be bound!
```

### `void`

Com o poder das `references`, você pode nem precisar retornar um valor de uma função.
`void` é usado como tipo de retorno nesse cenário.

```cpp
void increase_power(int& level) {
    level += 500;
}
int goku{8700};
increase_power(goku);
// goku's power level?
// It's over 9000!
```
