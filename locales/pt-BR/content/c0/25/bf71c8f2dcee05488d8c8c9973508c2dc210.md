# Introdução

Como vimos no conceito [`Nothingness`][concept-nothingness], o R tem várias formas de representar dados ausentes (`NULL`), desconhecidos (`NA`) ou matematicamente inválidos (`NaN`, `Inf`).
Em geral, o R tenta usá-los para sinalizar problemas ali mesmo e continuar sem lançar uma exceção.

## `stop()`

Alguns problemas são fundamentais demais para deixar o programa continuar.
Nesse caso, use `stop(msg)` para interromper o programa imediatamente com um `Error` e imprimir `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Semelhante a um `assert` de outras linguagens, é um wrapper conveniente para `stop()`.
Os parâmetros são um número arbitrário de condições booleanas separadas por vírgulas, e o programa só continua se todas forem `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

O R tem várias formas de tratar erros.
Elas se baseiam em Common Lisp e são bem diferentes das de muitas linguagens populares.

A mais simples é envolver o código que pode dar problema em `try()`.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
#> Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## `warning()` e `message()`

São respostas a condições que não são fatais, por exemplo:

- Para avisar sobre um problema do qual o programa poderia se recuperar, ao menos em parte.
- Para informar ao usuário o progresso de um programa de longa duração.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

A função `suppressWarnings()` pode ser útil de vez em quando no Exercism, para não confundir o test runner com saídas indesejadas.
