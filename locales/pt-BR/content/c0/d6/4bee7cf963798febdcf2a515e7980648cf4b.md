# Introdução

O código assembly escrito à mão está cheio de repetição.
A mesma sequência curta de instruções aparece de novo e de novo, com pouca variação, e há poucas abstrações para reduzir o código repetitivo.
Além disso, programar em assembly exige gerenciar valores sem semântica óbvia.
Não há parâmetros nomeados, e a maior parte dos detalhes da máquina por trás disso precisa ser tratada manualmente por quem programa.

O NASM, o montador usado pela trilha, oferece algumas ferramentas que podem ajudar nesses dois pontos.
Essas ferramentas rodam em _tempo de montagem_, antes de qualquer instrução chegar ao processador.
Elas orientam o montador sobre como reescrever o texto-fonte antes mesmo de ele ser traduzido para código de máquina.

A mais importante dessas ferramentas são as **macros**, que podem ser vistas como uma receita para o montador.
Elas são expandidas no local onde são usadas, como se o código tivesse sido escrito ali à mão.

Macros podem receber uma série de tokens literais como parâmetros, o que as torna reutilizáveis em contextos diferentes.
No entanto, elas não são funções: não há `call`, nem `ret`, nem transferência de controle para outro ponto do código.

## Macros de uma linha

A definição mais simples dá um nome a um valor ou a uma expressão curta com `%define`:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Toda ocorrência posterior de `WIDTH` é substituída por `8` antes da montagem.
A substituição é textual, então o nome é substituído em qualquer lugar onde apareça, seja em um operando, seja dentro de outra definição.

~~~~exercism/note
Para _constantes_ numéricas, prefira `equ` em vez de `%define`.

Uma macro de uma linha declarada com `%define` só é expandida quando usada, e pode ser reatribuída ou ter sua definição removida.
Já uma constante `equ` é avaliada no ponto da definição e nunca é modificada.
~~~~

Um `%define` também pode receber parâmetros _nomeados_, comportando-se como uma pequena função inline:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Coloque entre parênteses tanto o corpo inteiro quanto cada parâmetro.
Com `%define square(x) x*x`, a chamada `square(1+1)` expande para `1+1*1+1`, que é `3`.
Escrito como `%define square(x) ((x)*(x))`, a mesma chamada expande para `((1+1)*(1+1))`, que é `4`.
~~~~

Nomes definidos com `%define` são sensíveis a maiúsculas e minúsculas.
A variante `%idefine` torna o nome insensível a maiúsculas e minúsculas, caso isso seja desejado.

Macros de uma linha são úteis para dar significado a várias partes do código.
Se usadas com cuidado, elas melhoram a legibilidade e reduzem a chance de erros de digitação.
Por exemplo, um registrador com uma finalidade específica dentro de uma função pode ser definido pelo seu propósito:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Macros de várias linhas

Uma sequência inteira de código, com qualquer número de linhas, é capturada com `%macro` e encerrada por `%endmacro`.
Um número depois do nome indica quantos argumentos a macro recebe, o que pode ser zero.
Quando argumentos são passados, eles são separados por vírgula (`,`):

```x86asm
%macro example_macro 0
...
%endmacro
```

Os argumentos em macros de várias linhas não têm nome.
Eles são referenciados como `%1`, `%2` e assim por diante, na ordem em que são passados:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Observe que os argumentos precisam ser sintaxe válida para as operações realizadas no corpo da macro.
Aqui `mult_two eax, ecx` e `mult_two r8, r9` montam sem problemas, mas `mult_two eax, cl` não, já que `imul eax, cl` não está definido.

### Rótulos dentro de uma macro

Uma macro que define um rótulo comum quebra no momento em que é usada duas vezes, porque o rótulo também seria definido duas vezes.
Para usar rótulos dentro de uma macro que pode ser chamada mais de uma vez, é preciso prefixar esse rótulo com `%%`.
Isso instrui o montador a dar a esse rótulo um nome diferente e único a cada expansão:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Repetição em tempo de montagem

É possível repetir um bloco de código de uma linha usando `times`.
Isso é especialmente útil ao declarar valores repetidos na memória:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Para repetir código de várias linhas, podemos usar `%rep`:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Observe que o número de repetições é especificado logo depois de `%rep`, e há um `%endrep` para encerrar o bloco repetido.

É comum usar um contador em tempo de montagem dentro de um bloco `%rep`, assim como um laço em tempo de execução usa um contador.
Embora uma constante inteira em tempo de montagem possa ser declarada com `equ`, para _variáveis_ inteiras em tempo de montagem usamos `%assign`.
Diferente de `%define`, `%assign` é avaliado imediatamente para um número e pode ser reatribuído:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Depois que o pré-processador roda, o laço desaparece e restam quatro instruções `add`, com os valores imediatos `0`, `1`, `2` e `3` já embutidos.
Isso é desenrolamento de laço feito pelo montador: sem registrador de contador e sem desvio, apenas código linear.

## Montagem condicional

O pré-processador tem várias condicionais à disposição.
Elas escolhem entre vários caminhos diferentes, expandindo seu corpo no próprio local, mas apenas quando a condição é verdadeira.

`%if` ... `%elif` ... `%else` ... `%endif` selecionam uma bifurcação a partir de um teste numérico:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## Dividindo em arquivos

As macros costumam ficar em um arquivo próprio e são trazidas para cada fonte que precisa delas com `%include`:

```x86asm
%include "patterns.mac"
```

O arquivo nomeado é inserido literalmente nesse ponto, antes da montagem, exatamente como se seu conteúdo tivesse sido digitado ali.
Isso mantém as definições em um único lugar e permite que vários arquivos-fonte as compartilhem.

Se o arquivo de macros puder ser montado sozinho, ele deve ter a extensão `.asm`.
Observe que as macros não têm ligação.
Mesmo que o arquivo de macros seja montado, suas macros só são visíveis para outro arquivo que o inclua com `%include`.

Fora isso, um arquivo destinado apenas a ser incluído com `%include` pode ter qualquer extensão.
O uso de `.asm` ou `.mac` é uma convenção comum.
