# Funções em `jq`

Você pode definir suas próprias **funções personalizadas** em `jq` para encapsular a lógica que precisar.
As _funções_ se comportam igual às funções internas: recebem uma entrada e emitem zero, uma ou mais saídas.

## Definindo uma função

Você pode definir uma _função_ `jq` usando a sintaxe a seguir:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- começa com a palavra-chave `def`,
- dois-pontos antes do corpo da função,
- o corpo consiste em uma única expressão,
- termina com um ponto e vírgula,
- assim como no resto da sintaxe do `jq`, você pode usar espaços em branco à vontade para facilitar a leitura.

## Onde colocar as funções

As _funções_ precisam ser definidas antes de serem usadas: isto é um erro:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Isso significa que você precisa colocar as _funções_ no topo do seu código `jq`, antes da expressão "principal".

### Funções aninhadas

As _funções_ podem ser aninhadas:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Aqui, a _função_ `B` só é visível no corpo de `A`.

## Escopo

Uma _função_ introduz um novo **escopo** para variáveis e funções aninhadas.

## Argumentos

Os **argumentos** de uma _função_ são separados por _pontos e vírgula_, e não por vírgulas.
Por exemplo, uma _função_ que recebe um número, soma um número e multiplica por um número:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
Os pontos e vírgula são necessários porque a vírgula já tem uma função no `jq`: é um operador que une streams.

Usar uma vírgula em vez de um ponto e vírgula vai tentar fazer duas chamadas a uma função `add_mul` _de 1 argumento_, que não existe e, portanto, vai falhar na primeira chamada:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

A vírgula em `5, 4` concatena os números 5 e 4 em um stream. 
Quando chamamos uma função com um stream como argumento, o `jq` chama essa função várias vezes, uma para cada valor do stream. 
Este é um exemplo da "iteração implícita" inerente aos streams do `jq`. 
`10 | add_mul(5, 4)` é equivalente ao seguinte.

```jq
(10 | add_mul(5)), (10 | add_mul(4))
```
Agora dá para ver como o erro `add_mul/1 is not defined` aparece.
~~~~

<!-- prettier-ignore-end -->

### Argumentos são _expressões_

Os _argumentos_ de uma função são filtros, não valores.
Nesse sentido, eles funcionam como o que outras linguagens chamam de callbacks:

Usando a função `add_mul` como exemplo:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

O que está acontecendo aqui?

- o argumento `adder` recebe a _expressão_ `. + 5`
  - quando a função faz `. + adder`, isso vira `. + . + 5`
  - isso resulta em 25, já que `. == 10`
- do mesmo jeito, o argumento `multiplier` é a expressão `. - 2`
  - isso resulta em 8
  - e então o resultado é `25 * 8 == 200`

### Argumentos como valores

Às vezes você vai querer "materializar" um _argumento_ em uma variável:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Existe uma forma abreviada para isso:

```jq
def my_func($arg):
    other stuff ...
;
```

Repare que isso é só "açúcar sintático": o nome `arg` sem o `$` continua no escopo dentro da _função_.

<!-- prettier-ignore -->
~~~~exercism/caution
Por exemplo, eu escrevi algo assim para resolver um exercício:

```jq
# function that encodes the input value
def code:
    # expression here
    ;

def equals($code):
    (. | code) as $this_code
    | $code == $this_code
    ;

("some key value" | code) as $key
| ["array", "of", "values"]
| map(select(equals($key)))
```

e fiquei surpreso que todos os valores do array fossem iguais à chave.

Isso aconteceu porque o jq enxergou a função `equals` assim

```jq
def equals(code):
    code as $code
    | (. | code) as $this_code
    | $code == $this_code
    ;
```

O **argumento** `code` _sobrescreveu_ a **função** `code` definida antes.
Isso significa que `(. | code)` simplesmente emite o **argumento** em vez de calcular um novo código com base no valor de entrada.
Assim, `$this_code` e `$code` eram sempre iguais.
~~~~

## Aridade

As _funções_ têm uma **aridade**: o número de _argumentos_ que recebem.

As _funções_ podem usar o mesmo nome com _aridades_ diferentes.
A função interna [`range`][man-range] demonstra isso: `range/1`, `range/2` e `range/3` coexistem.

Isso pode ser útil para definir funções recursivas que carregam estado por meio de argumentos.
Por exemplo, `map` _poderia_ ser implementado assim:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## Recursão

O `jq` faz otimização de chamada de cauda, mas apenas para funções de aridade 0.

## Módulos

Um módulo `jq` é um arquivo que contém apenas funções.
Os módulos são incluídos em um programa jq com os comandos [`include`][man-include] ou [`import`][man-import].

[man-import]: https://jqlang.org/manual/#import-relativepathstring-as-name
