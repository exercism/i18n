# Dicas

## Geral

Este exercício tem muitas soluções possíveis e muitos caminhos que você pode seguir pelo caminho.
Nenhum caminho é manifestamente "melhor" que outro, embora um caminho específico possa ser mais interessante ou mais adequado ao que você quer aprender ou explorar agora.
Alguns caminhos podem trocar velocidade por clareza, outros podem ocupar mais memória, mas ser mais escaláveis ou fáceis de manter.
Nós incentivamos você a experimentar mais de uma estratégia para ver o que acontece.

_______
-  O Python tem um conjunto robusto de ferramentas para trabalhar com strings. [`str.split`][str.split], [`str.replace`][str.replace], [`str.lower`][str.lower] e [`str.strip`][str.strip] podem ser especialmente úteis neste desafio.
-  Os métodos de string podem ser encadeados (_desde que o método retorne uma `str`_))
-  Enquanto `str.split()` é muito _específico_, `str.strip()` se comporta de forma diferente e permite várias combinações.
-  O módulo [`string`][string] (em oposição a `str`) tem algumas constantes que podem ser úteis para filtrar e comparar ao processar strings.
________

-  [Dicionários][dict] podem ajudar a tabular quando itens (chaves) aparecem mais de uma vez em uma string.
-  [`dict.setdefault()`][dict.setdefault] pode ajudar no processamento quando uma chave pode estar faltando em um dicionário.
-  O módulo [Collections][collections] implementa alguns subtipos realmente úteis do `dict` (dicionário) básico, feitos sob medida para coisas como [contagem][collections.counter].
________
-  Explorar o módulo [`re`][re] e as expressões regulares pode ser divertido, mas de forma alguma é necessário para resolver este desafio.
-  O [Regex101][regex101] é muito útil para experimentar com lógica de expressões regulares.
-  Tanto [`re.sub`][re.sub] quanto [`re.findall`][re.findall] podem ser estratégias interessantes de usar.
________
-  [Comprehensions][comprehensions] muitas vezes conseguem "achatar" laços em que itens estão sendo adicionados a uma lista ou inseridos em um dicionário.
-  [Generator expressions][generator expressions] muitas vezes podem "substituir" uma list comprehension quando um iterável é necessário.
  As generator expressions são avaliadas de forma "preguiçosa" e ocupam menos espaço na memória do que uma list comprehension equivalente.
