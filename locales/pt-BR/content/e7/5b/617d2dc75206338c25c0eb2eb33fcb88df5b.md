# Introdução

## Processos

No Elixir, todo código roda dentro de processos.

Por padrão, uma função roda no mesmo processo de onde foi chamada. Quando você precisa rodar explicitamente uma determinada função em um novo processo, use `spawn/1`:

```elixir
spawn(fn -> 2 + 2 end)
# => #PID<0.125.0>
```

`spawn/1` cria um novo processo que executa a função de aridade 0 fornecida e retorna um _identificador de processo_ (PID). O novo processo permanece vivo enquanto a função estiver em execução e depois termina silenciosamente.

Os processos do Elixir não devem ser confundidos com processos do sistema operacional. Os processos do Elixir usam muito menos memória e CPU. Não há problema nenhum em ter aplicações Elixir que rodam centenas de processos Elixir.

### Mensagens

Os processos não compartilham informações diretamente uns com os outros. Os processos _enviam e recebem mensagens_ para compartilhar dados.

Você pode enviar uma mensagem para qualquer processo com `send/2`. O primeiro argumento de `send/2` é o PID do destinatário, o segundo argumento é a mensagem.

Uma mensagem pode ser de qualquer tipo. Muitas vezes ela é composta de átomos e tuplas. Se você quiser receber uma resposta, deve incluir o PID do remetente em algum lugar da mensagem. Você pode obter o PID do processo atual com `self()`.

`send/2` não verifica se a mensagem foi recebida pelo destinatário, nem se o destinatário ainda está vivo. A mensagem vai parar na _caixa de mensagens_ do destinatário e só será lida se e quando o destinatário pedir explicitamente para _receber mensagens_.

Uma mensagem pode ser lida de uma caixa de mensagens usando a macro `receive/1`. Ela aceita um bloco `do` que pode fazer [correspondência de padrões][exercism-pattern-matching] nas mensagens.

```elixir
receive do
  {:ping, sender_pid} -> send(sender_pid, :pong)
  :do_nothing -> nil
end
```

`receive/1` vai pegar _uma mensagem_ da caixa de mensagens que corresponda a qualquer um dos padrões dados e executar a expressão dada para aquele padrão. Se não houver mensagens na caixa de mensagens, ou se nenhuma das mensagens corresponder a nenhum dos padrões, `receive/1` vai esperar por uma.

### Laço de recebimento

Se você quiser receber mais de uma mensagem, precisa chamar `receive/1` recursivamente. É um padrão comum implementar uma função recursiva, por exemplo chamada `loop`, que chama `receive/1`, faz algo com a mensagem e depois chama a si mesma para esperar por mais mensagens. Se você precisar carregar algum estado de uma chamada de `receive/1` para outra, pode fazer isso passando um argumento para essa função `loop`.

## PIDs

Os identificadores de processo são um tipo de dados próprio. Eles funcionam como _endereços de caixa de mensagens_: se você tem o PID de um processo, pode enviar uma mensagem para esse processo. Os PIDs geralmente são criados indiretamente, como valor de retorno de funções que criam novos processos, como `spawn`.
