# Reputação

A reputação é o sistema que permite que as pessoas adquiram "confiança" dentro do ecossistema do Exercism.

A reputação é uma medida de quanto uma pessoa contribuiu para o Exercism, tanto por meio da contribuição para a plataforma (por exemplo, criando software, exercícios e documentação) quanto da contribuição para a comunidade (por exemplo, mentoria).

A reputação não pode ser "gasta" nem "usada". No entanto, alcançar certos limites de reputação dá acesso a novos privilégios e formas de contribuir. Simplificando: quanto mais reputação uma pessoa tem, mais confiamos nela e, portanto, mais poder ela recebe. A reputação também é uma medida visível publicamente de quanto você já deu ao Exercism.

## Objetivo

O objetivo do sistema de reputação é:

1. Maximizar as interações centradas no crescimento entre estudantes e mentores
2. Maximizar a vontade dos mentores de contribuir

## Como adquirir reputação

A reputação pode ser adquirida de várias formas:

| Ação                              | Reputação |
| --------------------------------- | --------- |
| Mentorar uma solução com sucesso  | 5         |
| Publicar uma solução              | 1-3       |
| Escrever um exercício             | 20        |
| Atualizar um exercício            | 10        |
| Escrever um conceito              | 10        |
| Atualizar um conceito             | 5         |
| Criar um pull request             | 3-100     |
| Revisar um pull request           | 1-20      |
| Mesclar um pull request           | 1-5       |

### Mentorar uma solução com sucesso

Para cada solução mentorada com sucesso (a discussão foi concluída), são concedidos `5` de reputação.

### Publicar uma solução

Para cada solução publicada, a reputação concedida depende da dificuldade do exercício:

| Rótulo   | Reputação |
| -------- | --------- |
| `easy`   | 1         |
| `medium` | 2         |
| `hard`   | 3         |

### Escrever um exercício

Para cada exercício em que o usuário está listado como autor, são concedidos `20` de reputação.

### Atualizar um exercício

Para cada exercício em que o usuário está listado como colaborador, são concedidos `10` de reputação.

### Escrever um conceito

Para cada conceito em que o usuário está listado como autor, são concedidos `10` de reputação.

### Atualizar um conceito

Para cada conceito em que o usuário está listado como colaborador, são concedidos `5` de reputação.

### Criar um pull request

Por padrão, são concedidos `12` de reputação quando um pull request aberto pelo usuário é mesclado.

Dependendo do conteúdo do pull request, um mantenedor pode conceder mais (ou menos) reputação adicionando um dos seguintes rótulos ao pull request:

| Rótulo          | Reputação | Exemplos                                                                                                                                                                                                                                                                                                                                                            |
| --------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x:rep/tiny`    | 3          | <ul><li>Corrigir um único erro de digitação ou um link</li><li>Remover uma linha em branco ou adicionar uma quebra de linha</li><li>Alterar/adicionar um único comentário de código</li></ul>                                                                                                                                                                        |
| `x:rep/small`   | 5          | <ul><li>Corrigir um único caso de teste, tarefa ou exemplo</li><li>Corrigir vários erros de digitação ou links em um único arquivo</li><li>Esclarecer o conteúdo adicionando algumas linhas a um arquivo</li></ul>                                                                                                                                                     |
| `x:rep/medium`  | 12         | <ul><li>Sincronizar um exercício com as problem-specifications (incluindo edições)</li><li>Adicionar um ou mais casos de teste do zero</li><li>Melhorar vários arquivos de um exercício</li><li>Adicionar notas de mentoria de um exercício do zero</li><li>Corrigir um pequeno bug em um executor de testes/analisador/representador</li><li>Adicionar comentários do analisador para um único exercício</li></ul> |
| `x:rep/large`   | 30         | <ul><li>Adicionar um novo exercício de conceito ou de prática</li><li>Adicionar nova documentação de conceito</li><li>Reescrever substancialmente um conceito ou exercício existente</li><li>Adicionar novos scripts de CI ou outra automação</li></ul>                                                                                                              |
| `x:rep/massive` | 100        | <ul><li>Criar do zero um executor de testes, analisador, representador ou gerador</li><li>Grandes refatorações nessas ferramentas</li><li>Criar documentação importante do zero (por exemplo, guias de contribuição ou de testes)</li></ul>                                                                                                                          |

Os exemplos acima podem servir como orientação aproximada para decidir qual rótulo aplicar, mas os mantenedores são livres para usar seu próprio julgamento.

- A quantidade estimada de tempo gasto deve ser interpretada como o tempo médio que um _mantenedor_ gastaria para fazer o PR.
- Se mais de um rótulo for especificado, o rótulo com o maior valor de reputação determina a reputação concedida.
- Se um pull request ainda estiver aberto, nenhuma reputação é concedida (ainda).
- Se um pull request for fechado _sem_ ser mesclado, nenhuma reputação é concedida.

_Para fins de compatibilidade retroativa, também oferecemos suporte ao uso dos rótulos `x:size` para determinar a reputação concedida._

### Revisar um pull request

Para cada pull request mesclado ou fechado revisado pelo usuário, são concedidos `5` de reputação.

- Se um pull request ainda estiver aberto, nenhuma reputação é concedida (ainda).
- A reputação de revisão só é concedida uma vez por usuário por pull request.
- O usuário que abriu o pull request _não_ recebe reputação por revisar o próprio pull request.

- A reputação concedida pela revisão de um pull request muda se um dos seguintes rótulos for adicionado ao pull request:

  | Rótulo          | Reputação |
  | --------------- | ---------- |
  | `x:rep/tiny`    | 1          |
  | `x:rep/small`   | 2          |
  | `x:rep/medium`  | 5          |
  | `x:rep/large`   | 10         |
  | `x:rep/massive` | 20         |

  _Não_ é possível usar "tamanhos" de reputação diferentes para o autor e o revisor de um pull request.
  Ambos se baseiam no mesmo rótulo `x:rep`.

  Se mais de um rótulo for especificado, o rótulo com o maior valor de reputação determina a reputação concedida.

  _Para fins de compatibilidade retroativa, também oferecemos suporte ao uso dos rótulos `x:size` para determinar a reputação concedida._

### Mesclar um pull request

Para cada pull request mesclado pelo usuário, é concedido `1` de reputação.

- Se um pull request ainda estiver aberto, nenhuma reputação é concedida (ainda).
- Se um pull request for fechado _sem_ ser mesclado, nenhuma reputação é concedida.
- O usuário que abriu o pull request _não_ recebe reputação por mesclar o próprio pull request.
- Se o pull request não tiver nenhuma revisão, `5` de reputação são concedidos em vez disso.

### Abrir uma issue

Assim como os pull requests, por padrão, **nenhuma reputação é concedida** quando uma issue é aberta.
Diferente dos pull requests, a reputação só é concedida para issues grandes ou enormes.

Dependendo do conteúdo da issue, um mantenedor pode escolher conceder reputação adicionando um dos seguintes rótulos à issue:

| Rótulo          | Reputação | Exemplos                                             |
| --------------- | ---------- | ---------------------------------------------------- |
| `x:rep/large`   | 30         | <ul><li>Exercício de conceito totalmente detalhado</li></ul> |
| `x:rep/massive` | 100        | <ul><li>Projetar o currículo de uma trilha</li></ul>       |

Os exemplos acima podem servir como orientação aproximada para decidir qual rótulo aplicar, mas os mantenedores são livres para usar seu próprio julgamento.

- A reputação deve refletir a quantidade de esforço que o _mantenedor_ gastaria para criar a issue.

- Se mais de um rótulo for especificado, o rótulo com o maior valor de reputação determina a reputação concedida.
