# Sobre

Em C#, uma tupla é uma estrutura de dados que organiza dados e contém dois ou mais campos de qualquer tipo.

Uma tupla normalmente é criada colocando 2 ou mais expressões separadas por vírgulas dentro de um par de parênteses.

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

Por ser uma expressão como qualquer outra, uma tupla pode ser usada de várias maneiras: em [atribuições][tuple-assignment], para inicializar um campo ou uma variável, como [valor de retorno][tuple-return-values] de um método ou passada como parâmetro. A [igualdade][tuple-equality] delas pode ser testada. A igualdade de tuplas é ilustrada por completo no exercício `pattern-matching-tuples`, mas um exemplo é fornecido no código abaixo para fins de completude.

Os campos são extraídos usando a sintaxe de ponto. Por padrão, o primeiro campo é `Item1`, o segundo é `Item2`, etc. Nomes diferentes do padrão são discutidos abaixo, em _Nomenclatura_.

Uma tupla pode ser usada como parâmetro genérico, por exemplo `IList<(bool, string)>`

Além disso, as tuplas dão suporte à "desconstrução", discutida abaixo, e podem ser usadas em correspondência de padrões, que é abordada em um exercício posterior.

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

Esta [introdução][tuples] mostra como definir e usar tuplas.

## Nomenclatura

Nomes de campo como `Item1` etc. não deixam o código legível. Há 3 formas de dar nomes aos campos: a) na declaração do tipo, b) na expressão que cria a tupla ou c) por meio de [inicializadores de projeção de tupla][tuple-projection-initializers] (não ilustrado aqui).

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

Não tente ser esperto demais com o mecanismo de nomes. Ele é, na verdade, apenas açúcar sintático. Por exemplo, você não pode mudar os nomes de uma tupla quando atribui a ela a partir de outra tupla.

## Desconstrução

Às vezes é conveniente pegar uma tupla e atribuir os campos a várias variáveis, inicializando-as quando for o caso. Esse mecanismo é chamado de [desconstrução][tuple-deconstruction]. (Ele também pode ser aplicado aos seus próprios objetos. Veja [aqui][udt-deconstruction]).

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## Atribuição de campos

Os campos das tuplas podem receber atribuições individuais. No entanto, dada a tendência do C# à imutabilidade, esse tipo de uso não é difundido. As tuplas são muitas vezes usadas como se fossem imutáveis, o que, é claro, não são.

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## Contexto

As tuplas que estamos discutindo não devem ser confundidas com [`System.Tuple`][system-tuple], que provavelmente só será encontrada em bases de código legadas.

A situação é um pouco mais confusa quando se trata de `System.ValueTuple`. A [documentação][system-value-tuple] da sobrecarga final de [`System.ValueTuple`][system-value-tuple] afirma que "os tipos de tupla de valor fornecem a implementação de runtime que dá suporte a tuplas em C#". Com "tipos de tupla de valor", aqui, eles se referem às sobrecargas genéricas de `System.ValueTuple`. Com "tuplas", eles querem dizer as coisas que nos ocuparam neste exercício. Na prática, eles estão dizendo que `System.ValueTuple` é um detalhe de implementação das tuplas. É pouco provável que isso interesse muito à maioria das pessoas na maior parte do tempo. Infelizmente, boa parte da documentação sobre "tuplas", incluindo a da própria Microsoft, está repleta de referências a `System.ValueTuple`. Provavelmente não há problema em passar por cima dessas referências.

## Outros usos e limitações

A correspondência de padrões é um uso especialmente produtivo para tuplas. Isso é abordado em um exercício posterior.

As tuplas permitem alguns outros pequenos floreios de estilo:

- Atribuição múltipla (especialmente em construtores), por exemplo `(this.field1, this.field2) = (arg1, arg2);`
- Trocar ou reciclar valores, por exemplo `(a, b) = (b, a);`
- Usar no lugar de um `struct` em uma lista
- Usar como chave de dicionário ou como conteúdo de um conjunto.
- Usar em LINQ. (LINQ é abordado em exercícios posteriores).

A documentação descreve as tuplas como um mecanismo leve, e isso é a chave para usá-las com sucesso. Usar uma tupla no lugar de uma classe ou struct pode levar a uma repetição tediosa dos tipos de seus campos e, possivelmente, dos nomes. Isso vale especialmente para o uso como argumento de método ou como argumento genérico em coleções.

É melhor usar com bom senso truques como atribuição múltipla e troca de valores.

Operações relacionais que não sejam de igualdade e desigualdade não são suportadas.

Repare que as tuplas foram introduzidas na linguagem relativamente recente (C# 7), então, se você quiser usá-las, certifique-se de que sua base de código esteja usando a [versão][language-version] 7 ou posterior da linguagem.
