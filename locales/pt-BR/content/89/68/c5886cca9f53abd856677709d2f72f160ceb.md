# Introdução

Como vimos no conceito [`Nothingness`][concept-nothingness], o R tem várias formas de representar dados que estão ausentes (`NULL`), desconhecidos (`NA`) ou são matematicamente inválidos (`NaN`, `Inf`).
Em geral, o R tenta usar essas formas para sinalizar problemas ali mesmo e seguir adiante sem lançar uma exceção.

## `stop()`

Alguns problemas são fundamentais demais para deixar o programa continuar.
Nesse caso, use `stop(msg)` para interromper o programa imediatamente com um `Error` e imprimir `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Semelhante a um `assert` de outras linguagens, é uma forma prática de chamar `stop()`.
Os parâmetros são um número qualquer de condições Boolean separadas por vírgula, e o programa só continua se todas forem `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `warning()` e `message()`

Essas funções respondem a condições não fatais, por exemplo:

- Para avisar sobre um problema do qual o programa consegue se recuperar, ao menos em parte.
- Para informar o usuário sobre o progresso de um programa que roda por bastante tempo.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

A função `suppressWarnings()` pode ser útil de vez em quando no Exercism, para evitar confundir o test runner com saída indesejada.
