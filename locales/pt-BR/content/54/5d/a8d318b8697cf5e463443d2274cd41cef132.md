# Introdução

Um **número de ponto flutuante** é um número que pode ter uma parte fracionária, como `-1.23` ou `3.1415`.

Para representar esse tipo de número como uma sequência de bytes, o x86-64 usa o padrão **IEEE-754**.
Os dois formatos mais comuns desse padrão são os números de ponto flutuante de precisão simples e de precisão dupla.
O x86-64 dá suporte aos dois.

Um número de ponto flutuante de precisão simples tem 32 bits, enquanto um de precisão dupla tem 64 bits.

## Registradores XMM

No x86-64, existem 16 registradores dedicados à aritmética de ponto flutuante, chamados de `xmm0` a `xmm15`.

Esses registradores têm pelo menos 128 bits, mas processadores recentes aumentam isso para 256 ou 512 bits.
Na prática, porém, a maioria dos números de ponto flutuante usa apenas os 32 ou 64 bits mais baixos, dependendo da precisão desejada.

## Conversão entre números

Existe uma família de instruções para converter entre formatos de número: `cvtxx2yy`.

Nem `xx` nem `yy` são literais: são marcadores.

- `xx` é um marcador para o tipo do operando de origem.
- `yy` é um marcador para o tipo do operando de destino.

Esse marcador pode assumir várias formas, entre elas:

| marcador | significado              |
| ----------- | --------------------- |
| `si`        | inteiro com sinal        |
| `ss`        | ponto flutuante de 32 bits |
| `sd`        | ponto flutuante de 64 bits |

Por exemplo:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

Repare que é possível converter um inteiro de 32 bits em um ponto flutuante de 64 bits, ou um inteiro de 64 bits em um ponto flutuante de 32 bits.
Da mesma forma, também é possível converter um ponto flutuante de 32 bits em um inteiro de 64 bits, ou um ponto flutuante de 64 bits em um inteiro de 32 bits.
Em outras palavras, o tamanho dos dois operandos em uma `cvtxx2yy` _não precisa ser o mesmo_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

Quando o número de ponto flutuante não pode ser expresso exatamente como um inteiro, a `cvtxx2si` arredonda o número de acordo com o controle de arredondamento em um registrador especial chamado `mxcsr`.
Isso pode ser um arredondamento para o mais próximo, para baixo, para cima ou um truncamento.
Não há um padrão garantido na entrada da função.

Repare que um resultado exato não é arredondado e, portanto, não é afetado pelo controle de arredondamento.
Por exemplo, `42.0` seria _sempre_ convertido para `42`.

Há uma família parecida de instruções com o formato `cvttxx2si` (com um `t` a mais) que sempre trunca o resultado.

## Arredondamento

A família de instruções `roundxx` converte um ponto flutuante no operando de origem em um ponto flutuante arredondado, armazenado no operando de destino.

Aqui, `xx` é um marcador para o tipo dos operandos, como de costume: `ss` para precisão simples e `sd` para precisão dupla.

Essas instruções recebem um número constante como terceiro operando.
Esse número indica o modo de arredondamento:

| Número | Modo         |
| :----- | :----------- |
| 0      | Mais próximo |
| 1      | Piso (para baixo) |
| 2      | Teto (para cima)    |
| 3      | Truncar     |

Por exemplo:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

Como essas instruções produzem um resultado exato, elas podem ser usadas na preparação para uma `cvtxx2si`.

## Instruções aritméticas

Muitas operações com números de ponto flutuante usam instruções com um nome parecido com o equivalente para inteiros, mas acrescentando o marcador necessário (`ss` ou `sd`) no final.
Essas instruções têm dois operandos, com a semântica de sempre, inclusive as que fazem multiplicação ou divisão:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## Movimentação

As instruções para mover de um registrador XMM para outro são `movss` ou `movsd`:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

**Não** é possível mover um valor imediato (um inteiro com sinal constante) diretamente para um registrador xmm.
Esse número precisa primeiro ser movido para um registrador de uso geral e então convertido com `cvtsi2xx`:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## Comparações

Há dois grupos de instruções para fazer uma comparação entre dois números de ponto flutuante.
Elas têm a forma `comixx` e `ucomixx`, em que `xx` é `ss` ou `sd`.
Ambas definem flags em `rflags` como de costume, seguindo a mesma semântica de `cmp`.

A diferença entre elas é que a `ucomixx` define a `parity flag (PF)` se um dos dois números de ponto flutuante tiver um valor `NaN`, enquanto a `comixx` gera uma exceção nesse caso.

A comparação entre valores de ponto flutuante é _sem sinal_:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## Convenção de chamada

Na ABI System V, os oito primeiros argumentos de ponto flutuante são passados para as funções em ordem, de `xmm0` a `xmm7`.
Valores de ponto flutuante são retornados pelas funções em `xmm0` e, se necessário, em `xmm1`.

Todos os registradores `xmm` estão livres para uso; nenhum deles é reservado para o chamador.

## Memória

Valores de ponto flutuante podem ser definidos na memória seguindo a mesma semântica dos inteiros do mesmo tamanho.
O NASM (The Netwide Assembler, o montador usado por esta trilha) também permite declarar valores de ponto flutuante em notação científica.

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```
