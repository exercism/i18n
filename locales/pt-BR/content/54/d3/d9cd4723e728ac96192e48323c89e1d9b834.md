# Sobre

No Gleam, uma expressão `case` pode ser usada para executar código condicionalmente. Com uma expressão `case`, é possível testar um valor em relação a um ou mais _padrões_. Um exemplo desse tipo de padrão é o _padrão literal_, que compara um valor com um valor literal (por exemplo, `1` ou `"hello"`).

As expressões `case` são escritas com a palavra-chave `case`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    1 -> "One"
  }
}
```

Embora isso possa parecer com instruções `switch` de outras linguagens, a correspondência de padrões começa a brilhar quando também usamos outros padrões. Um desses padrões é o _padrão de variável_, que permite atribuir um valor a uma variável. Neste exemplo, a variável `i` receberá o valor de `number` se ele não for `0`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i -> "Non zero"
  }
}
```

Em alguns casos, você pode querer adicionar uma condição extra a um padrão. Isso é conhecido como uma _guarda_ (cláusula), que pode ser adicionada com a palavra-chave `if`:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
  }
}
```

Por questões de desempenho, apenas operadores matemáticos e booleanos básicos são permitidos em guardas; outras funções não podem ser usadas nelas.

No exemplo acima, nem todo valor de entrada possível terá um padrão correspondente. O compilador detecta isso e emite um erro. Isso é conhecido como _verificação de exaustividade_. Para resolver o aviso, é preciso tratar todos os casos. Para isso, pode-se usar o _padrão de descarte_, que é um padrão que corresponde a qualquer valor:

```gleam
pub fn describe(number: Int) -> String {
  case number {
    0 -> "Zero"
    i if i < 0 -> "Negative number"
    _ -> "Positive number"
  }
}

// No compiler error
```

As expressões `case` testam um valor em relação a cada padrão, de cima para baixo, até encontrar um padrão correspondente e executar a lógica associada a ele. A ordem dos padrões importa!
