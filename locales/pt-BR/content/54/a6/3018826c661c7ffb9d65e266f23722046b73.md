# Introdução à aritmética no shell Bash

O Bash consegue fazer aritmética, mas _apenas com números inteiros_.
Se você precisar fazer cálculos com ponto flutuante, vai precisar chamar algum programa externo (como [awk][awk] ou [bc][bc]).

Os operadores aritméticos estão listados (em ordem de precedência) no manual: [Aritmética do shell][arithmetic].

Além disso, o Bash só realiza aritmética em determinados lugares (conhecidos como "contextos" aritméticos).

## Expansão aritmética

A expansão aritmética se parece com a [substituição de comando][cmd-sub], mas com parênteses duplos.

```bash
$(( expression ))
```

Essa sintaxe expande para o resultado da avaliação da expressão.
É comum usá-la para guardar o resultado em uma variável:

```bash
x=$(( 3 + 4 ))
```

~~~~exercism/note
A quantidade de espaços em branco dentro dos parênteses fica a seu critério.
É uma questão de estilo e legibilidade.

```bash
x=$(( 3 + 4 ))
y=$((5+6))
```

Seu amigável autor gosta de adicionar espaços para que a expressão aritmética fique mais visível dentro dos parênteses.
~~~~

## Condicional aritmética

A condicional aritmética é feita dentro de parênteses duplos _sem_ o `$` inicial:

```bash
(( expression ))
```

Isso não expande para o resultado.
No entanto, produz um _status de saída_.

* O status de saída é 0 (sucesso) se o resultado da expressão for **diferente de zero**.
* O status de saída é 1 (falha) se o resultado da expressão for **zero**.

~~~~exercism/note
Dentro de `((` o Bash usa o mesmo sentido de verdadeiro/falso da linguagem C: zero é falso, diferente de zero é verdadeiro.
**Isso é o oposto de como o Bash avalia os status de saída!**
~~~~

Essa sintaxe costuma ser usada em dois lugares:

1. como a parte de COMANDO de uma [condicional `if`][conditional-if] ou de um [laço `while`][looping-while].

   ```bash
   if (( x == y - 1 )); then ...
   while (( y > 0 )); do ...
   ```

1. como um comando isolado para modificar o valor de uma variável.

   ```bash
   (( x = x + 1 ))
   echo "new value for x is $x"
   ```

   ~~~~exercism/caution
   Cuidado ao usar aritmética assim combinada com `set -e`.
   Se a expressão resultar em zero, o status de saída será diferente de zero e o Bash vai encerrar.

   ```bash
   x=0
   (( x++ ))
   echo "you will see this"

   set -e
   x=0
   (( x++ ))
   echo "shell exits on the previous line; you won't see this"
   ```

   Para uma discussão mais detalhada sobre o operador `++`, veja este artigo sobre [Pós-incremento vs Pré-incremento][incr]

   [incr]: https://thisvsthat.io/postincrement-vs-preincrement
   ~~~~


## Outros lugares com contexto aritmético

Existem alguns outros lugares que são contextos aritméticos:

* O [laço `for` aritmético][looping-for].

  ```bash
  for (( i = 0; i < 10; i++ )); do
      echo "$i"
  done
  ```

* A parte do índice de um array indexado numericamente.

  ```bash
  echo "The next element is ${array[x + 1]}"
  # ................................^^^^^
  ```

  Para saber mais sobre arrays, leia o documento do conceito [Arrays][arrays].

* As partes de deslocamento e comprimento da expansão `${var:offset:length}`.
* O [comando interno `let`][let].
  * Observe que `(( expression ))` é preferível a `let "expresson"`.
    Diferente da construção da condicional aritmética, a expressão `let` está sujeita à expansão de nomes de arquivo e à divisão de palavras, e exige o uso de aspas.
* Atribuição de variável, quando a variável tem o "atributo de inteiro".

  ```bash
  # variable x does not have the integer attribute
  x="3 + 4"
  declare -p x      # => declare -- x="3 + 4"

  # variable y has the integer attribute
  declare -i y
  y="4 + 5"
  declare -p y      # => declare -i y="9"
  ```

  ~~~~exercism/note
  Na opinião do autor, o `declare -i` tem uso limitado.
  Seu principal benefício é permitir aritmética "pura" (sem a sintaxe de expressão aritmética).
  Isso pode causar confusão para quem lê o seu código, porque expressões aritméticas são avaliadas em lugares inesperados.
  ~~~~

## Usando variáveis em expressões aritméticas

Aqui está um aspecto dos contextos aritméticos que melhora a legibilidade.

```bash
height=10
width=20
area=$(( height * width ))
```

Você reparou que os cifrões `$` estão faltando nas variáveis da expressão aritmética?
O Bash permite isso.
Isso deixa as expressões muito mais fáceis de ler.

O manual diz:

> Dentro de uma expressão, as variáveis do shell também podem ser referenciadas pelo nome, sem usar a sintaxe de expansão de parâmetros.

Isso funciona até para elementos de array:

```bash
point1=(10 15)  # these are (x, y) coordinates
point2=(20 7)
distance_squared=$(( (point1[0] - point2[0])**2 + (point1[1] - point2[1])**2 ))
```

Mas outras expressões de parâmetros precisam usar a sintaxe especial delas.
Por exemplo, dobrar o comprimento de uma string:

```bash
s="hello world"
len=$(( ${#s} * 2 ))
```

E os parâmetros posicionais também precisam.
Se os dois primeiros parâmetros posicionais representam largura e altura:

```bash
area=$(( $1 * $2 ))
```
