# Ordenação

```sather
   numbers.sort;                                  -- the natural order
   words.insertion_sort_by(bind(before(_, _)));   -- an order you supply
```

## O que a ordenação precisa

`sort` exige que o tipo do elemento tenha `is_lt`. `INT`, `STR`, `CHAR`,
`FLTD` e `INTI` têm. Uma classe sua não tem, até você escrever um.

`insertion_sort_by` não exige nada do tipo do elemento: tudo o que ela
precisa saber está na rotina que você passa para ela.

## Como deve ser uma comparação

A rotina precisa definir uma ordem consistente, senão o resultado não é definido:

- se `before(a, b)` for verdadeiro, então `before(b, a)` precisa ser falso;
- se `a` vem antes de `b` e `b` antes de `c`, então `a` vem antes de `c`;
- `before(a, a)` precisa ser falso.

É na última que as pessoas tropeçam. Escrever `<=` em vez de `<` diz que uma
coisa vem antes dela mesma, e uma ordenação que recebe isso pode produzir
qualquer coisa.

## Empates

Nem `sort` nem `insertion_sort_by` são **estáveis**: coisas que a comparação
considera iguais podem sair em qualquer ordem, e nesta biblioteca elas geralmente
saem invertidas.

Então o truque de ordenar duas vezes, primeiro por nome, depois por pontos,
esperando que times empatados em pontos continuem em ordem alfabética, não
funciona aqui. Nem contar com a ordem da entrada para qualquer coisa.

Se os empates importarem, resolva-os **na comparação**. Faça dela uma ordem
total, de modo que duas coisas diferentes nunca sejam consideradas iguais:

```sather
   shorter(a, b : STR) : BOOL is
      if a.size /= b.size then return a.size < b.size; end;
      return a < b;                  -- same length: alphabetical
   end;
```

Vale a pena fazer isso mesmo quando você acha que empates não podem acontecer.
Uma comparação que responde falso nos dois sentidos deixa o resultado
indefinido, e o bug aparece como uma ordem que muda sem motivo visível.

## Os demais

| Chamada | O que faz |
| --- | --- |
| `a.sort` | no local, ordem natural, não estável |
| `a.insertion_sort_by(lt)` | no local, sua ordem, estável |
| `a.is_sorted` | verifica |
| `a.is_sorted_by(lt)` | verifica em relação à sua ordem |
| `a.binary_search(e)` | busca, em um array ordenado |
| `a.binary_search_by(e, lt)` | busca, em relação à sua ordem |

`binary_search` em um array não ordenado não falha: ele responde bobagem.
A pré-condição dele diz exatamente isso, e as pré-condições não são verificadas
a menos que o compilador receba `-chk`.

## Custo

A ordenação por inserção faz um trabalho proporcional ao quadrado do
comprimento, o que é bom para uma classificação de uma dúzia de times e errado
para dez mil registros. `ARR_SORT_ALG::sort_by` é a versão quicksort da mesma
ideia, para quando o array é grande e a estabilidade não importa.
