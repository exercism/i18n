# Apêndice das instruções

## Prós e contras de `from_quote`

Este exercício define uma função `from_quote` no tipo `Time`. Isso torna possível escrever um código como este:

```roc
time : Time
time = "00:01:23"
```

Esse código chama `Time.from_quote("00:01:23")` implicitamente em tempo de compilação. Isso pode acelerar o programa, já que ele não precisa fazer o parsing em tempo de execução, e garante que horários rejeitados por `from_quote` sejam detectados em tempo de compilação, e não em tempo de execução. Além disso, deixa o código bonito e legível. Por exemplo, aqui está um dos testes deste exercício:

```roc
## start initiates time tracking for current lap
expect {
	result = Stopwatch.create()
		.start()?
		.advance_time("00:00:05")
		|> expect_current_lap("00:00:05")

	result.is_ok()
}
```

No entanto, quem lê esse código pode supor que a função `advance_time` recebe uma `Str`, quando na verdade ela recebe um `Time`. Isso pode gerar confusão e erros. Por esse motivo, você pode preferir o formato um pouco mais longo, mas mais explícito: `"00:00:05".Time`, que também chama `from_quote` em tempo de compilação.

Nos seus próprios programas, você pode preferir usar `from_str`:

```roc
Time := { ... }.{
    from_str : time_str -> Try(Time, [InvalidTime])
    from_str = |time_str| ...
}
```

Você também pode chamar `from_str` (ou qualquer outra função pura) em tempo de compilação, assim:

```roc
Ok(time) = Time.from_str("00:01:23")
```

Observação: colocar essa definição no nível superior faz com que ela seja executada em tempo de compilação (já que a função é pura e sua entrada é conhecida em tempo de compilação). Dentro de uma função, você pode usar `from_str` em tempo de execução.
