# Introdução às condicionais

## Veracidade no Bash

O Bash não tem o conceito de valores Boolean.
Existem strings e números, e arrays de strings ou números.
Então como os comandos condicionais lidam com verdadeiro e falso?

## Status de saída

Os comandos produzem um _status de saída_ quando terminam.
Um status de saída é um número inteiro entre 0 e 255, inclusive.
O Bash considera que um status de saída **zero** representa _sucesso_.
Qualquer outro status de saída representa _falha_.

Isso vale para todos os comandos, incluindo comandos internos do Bash, palavras-chave e funções.

## O comando "if"

A sintaxe básica do comando `if` é

```bash
if CONDITIONAL_COMMANDS; then TRUE_COMMANDS; else FALSE_COMMANDS; fi
```

Ele começa com `if`; os comandos de condição são separados dos comandos de "sucesso" por `then`; e termina com `fi`.
A cláusula `else` é opcional.

Os CONDITIONAL_COMMANDS podem ser um único comando ou uma [lista de comandos][command-list].

Os CONDITIONAL_COMMANDS são executados e

* se o status de saída for zero (sucesso), os TRUE_COMMANDS são executados.
* se o status de saída não for zero (falha), os FALSE_COMMANDS são executados, se estiverem presentes.

Bifurcações em cascata podem ser feitas com `elif`
```bash
if CONDITIONAL_COMMANDS
then TRUE_COMMANDS
elif CONDITIONAL_COMMANDS_2
then TRUE_COMMANDS_2
# more elif branches ...
else FALSE_COMMANDS
fi
```

É preciso haver um ponto e vírgula ou uma quebra de linha antes das palavras `then`, `elif`, `else` e `fi`.

Vale reforçar: é o **status de saída** dos comandos condicionais que controla o fluxo.
Por exemplo, o `grep` retorna 0 se encontrar uma correspondência e 1 se não encontrar.
A opção `-q` suprime a saída, produzindo apenas o status de saída.

```bash
if grep -q "my pattern" my_file; then echo "the pattern is found in the file"; fi
```

## Os comandos "[" e "test"

Não há sintaxe especial em torno dos CONDITIONAL_COMMANDS.
Talvez você já tenha visto condicionais assim:

```if
if [ "$password" = "secure" ]; then
    echo "Welcome!"
fi
```

`[` não é sintaxe especial.
É um _comando_ que avalia a expressão condicional e termina com status de sucesso ou falha.
Como em todo comando, é **obrigatório** haver um espaço em branco entre ele e os argumentos.

Na verdade, `[` é sinônimo do comando `test`.
Eles são exatamente iguais, exceto que o último argumento de `[` _precisa_ ser `]`.

### Expressões condicionais

Dentro de `[` e `]`, você escreve uma expressão condicional.
Algumas expressões condicionais típicas incluem:

```bash
[ -f "$filename" ]             # file operations
[ "$string1" = "$string2" ]    # string comparisons
[ "$num1" -eq "$num2" ]        # arithmetic comparisons
```

Existem muitas outras operações disponíveis; elas estão listadas na seção [Expressões Condicionais do Bash][cond-expr] do manual.

~~~~exercism/note
Nos exemplos acima, repare que todas as variáveis estão entre aspas.
Os comandos `test` e `[` são comandos comuns, nos quais os argumentos estão sujeitos à divisão de palavras e à expansão de nomes de arquivos como em qualquer outro comando.

Vale destacar isso porque as expressões condicionais são avaliadas de forma diferente conforme _quantos argumentos_ você fornece:

* 0 argumentos: o status de saída não é zero (falha)
* 1 argumento: o status de saída é zero (sucesso) se o argumento não estiver vazio, e não é zero se estiver vazio.
* 2 argumentos: o primeiro argumento deve ser um operador unário (como em `[ -z "$name" ]`) ou um `!` (que nega o status do teste de 1 argumento)
* e [mais][test].

Você pode obter resultados inesperados se esquecer de usar aspas:

```bash
str=""

# this prints "empty"
if [ -n "$str" ]; then echo "not empty"; else echo "empty"; fi

# leaving the variable unquoted results in incorrect "not empty" output
if [ -n $str ]; then echo "not empty"; else echo "empty"; fi
```

[test]: https://www.gnu.org/software/bash/manual/bash.html#index-test
~~~~

## A palavra-chave "[["

A [construção condicional `[[...]]`][cond-construct] não é um _comando_, é uma **palavra-chave**.
Isso significa que, embora seja tratada como qualquer outro comando, ela tem regras especiais de análise sintática.
O que há de especial no `[[` é que as variáveis expandidas dentro dele **não** estão sujeitas à divisão de palavras nem à expansão de nomes de arquivos.
Ou seja, esse comando se comporta como você espera, mesmo sem aspas.

```bash
if [[ -n $str ]]; then echo "not empty"; else echo "empty"; fi
```

O `[[` aceita todas as expressões condicionais que o `test` e o `[` conseguem tratar.
Além disso, o `[[` oferece

* o operador de correspondência de expressão regular `=~`,
* `==` e `!=` funcionando como operadores de correspondência de padrões glob,
* `&&` e `||` como operadores lógicos (regra especial de análise sintática),
* `<` e `>` como operadores de comparação de strings "puros" (regra especial de análise sintática: como são símbolos de redirecionamento, no `[` eles precisam ser escapados).

É amplamente aceito que esses recursos especiais oferecem tantos benefícios que o `[[` deveria ser usado exclusivamente.
(Por exemplo, o [Google Shell Style Guide][goog-test].)

## O comando "case"

O [`case`][case] é outro comando de controle de fluxo.
Ele é como uma instrução "switch" de outras linguagens.

```bash
case WORD in [PATTERN [| PATTERN]...) COMMANDS ;;]... esac
```

A WORD é comparada com cada PATTERN.
Quando uma delas corresponde, os COMMANDS são executados.

```bash
read -p "Guess the secret word: " word
case "$word" in
    secret) echo "Yes, you guessed it!" ;;
    ??????) echo "That's the right number of letters." ;;
    s*)     echo "You guessed the first letter." ;;
    *)      echo "Not even close! Try again." ;;
esac
```

Cada cláusula COMMANDS deve terminar com **dois** pontos e vírgula, `;;`.
