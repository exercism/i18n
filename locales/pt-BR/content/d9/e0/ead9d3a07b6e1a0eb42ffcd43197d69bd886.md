# Sobre

É pouco provável que você encontre muito código de produção que não faça uso de namespaces.

Um exemplo da sintaxe é:

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

Namespaces são uma forma de agrupar código relacionado e de evitar conflitos de nomes.

De acordo com a [documentação oficial][namespaces], os namespaces têm dois papéis principais:

- Primeiro, o .NET usa namespaces para organizar suas muitas classes
- Segundo, declarar seus próprios namespaces pode ajudar você a controlar o escopo de nomes de classes e métodos em projetos de programação maiores.

Os namespaces são amplamente usados pela biblioteca de classes base (BCL) para organizar sua funcionalidade.

## Referências a tipos em namespaces

Tipos contidos em namespaces são referenciados fora do namespace prefixando o nome do tipo com a sintaxe de ponto. Como alternativa, e mais comumente, você pode colocar uma diretiva `using` no topo do arquivo (ou dentro de um namespace), e qualquer tipo do namespace importado pode ser usado sem o prefixo. Dentro do mesmo namespace, não é preciso qualificar os nomes dos tipos.

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

Este [artigo][using] explica com clareza as formas como a diretiva `using` pode ser usada:

- `using`: evita ter que qualificar tipos com o namespace
- `using static`: evita ter que qualificar membros com tipos (um bom exemplo é `Math.Max()`).
- `using MyAlias = YourNamespace;`: substitui o nome do namespace por um nome mais legível.

## Conflito de namespaces

O .NET trata a questão de dois namespaces com o mesmo nome em assemblies diferentes, onde haveria um conflito de nomes de identificadores totalmente qualificados (talvez um cenário em que várias versões de um assembly estejam carregadas). Essa questão é resolvida com o [qualificador de alias de namespace][namespace-alias-qualifier] e o [alias extern][extern-alias].

Um motivo para levantar esse tópico um tanto nichado é o seu uso do [operador `::`][dot-dot-operator]. Você vai ver com frequência o qualificador `global::` prefixando namespaces, principalmente em código gerado. A intenção aqui é evitar um possível conflito com algum namespace aninhado ou nome de classe. Ao prefixar um namespace com `global::`, você garante que um namespace de nível superior seja selecionado.

## Nota para quem programa em Java

Ao comparar com o `import` dos `packages` do Java, vale notar algumas diferenças e semelhanças:

- Não há equivalente em C# para importar tipos específicos.
- `using static` e `import static` são equivalentes.
- No Java, os nomes de pacotes têm impacto na acessibilidade entre jars. Em C#, os assemblies são o que importa, e pertencer ao mesmo namespace não afeta o nível de acesso.
- A relação entre caminhos do sistema de arquivos e nomes de classes totalmente qualificados no Java não se reflete nos namespaces do C#, embora seja boa prática, quando possível, dar a um arquivo o mesmo nome da classe principal que ele contém.
