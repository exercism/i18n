# Sobre

Os caracteres individuais de uma `String` podem ser acessados com o mesmo método de subscrito usado em arrays.
No entanto, os [índices][string-indices] usados em strings _não_ são inteiros e não podem ser usados diretamente.
Em vez disso, eles precisam ser calculados a partir de algum outro índice conhecido, como `startIndex`, que aponta para a posição do primeiro caractere de uma string não vazia, usando os métodos disponíveis nas bibliotecas [`String`][string-docs] e [`NSString`][nsstring-docs] (quando o módulo `Foundation` é importado, as strings em Swift têm acesso a todas as propriedades e métodos de NSString).

Por exemplo, dada a seguinte string:

```swift
let csv = "apple,pear,peach,orange,cherry,lime,goosberry"
```

Não dá para escrever `csv[21]` para obter o "g" de "orange"; em vez disso, é preciso calcular um valor do tipo `String.Index` e passar esse índice.
Repare que esses índices não foram feitos para serem consumidos por humanos por conta própria.
Eles são o que chamamos de _índices opacos_, já que não é preciso saber o que há dentro deles.

```swift
let index = csv.index(csv.startIndex, offsetBy: 21)
csv[index]
// "g"
print(index)
// prints Index(_rawBits: 1376513)
```

Observe, porém, que se o deslocamento não for um índice válido, ou seja, se ele apontar para o índice anterior a `startIndex` ou posterior a `endIndex`, a operação vai gerar um erro e derrubar o programa.
Para evitar esse problema, dá para especificar um índice limitante.
Assim você recebe um índice opcional, e ele vai devolver nil para índices que de outra forma seriam inválidos.

```swift
let tooFar = csv.index(csv.startIndex, offsetBy: 200)
// error: Execution was interrupted, reason: EXC_BAD_INSTRUCTION (code=EXC_I386_INVOP, subcode=0x0).
let tooFarButSafe = csv.index(csv.startIndex, offsetBy: 200, limitedBy: csv.endIndex)
// nil
```

Além disso, os índices não podem ser compartilhados entre strings.
Por exemplo, usar o `index` do "g" de "orange" calculado acima para indexar a string `fam = "This is my family: 👨‍👩‍👦‍👦, this is our dog: 🐶, this is our cat: 🐱!"`, ou seja, `fam[index]`, vai derrubar o seu programa.

Existem muitos motivos para tudo isso, mas no fundo todos se resumem a "Unicode é complicado".

De modo geral, se você precisa de acesso aleatório a caracteres individuais, provavelmente é melhor usar outra estrutura de dados, como `Array<Character>`.

## Alguns métodos úteis

O Swift tem os métodos `first` e `last` para obter o primeiro e o último caractere de uma string.
Esses métodos retornam um caractere opcional, então, se a string estiver vazia, eles retornam nil.

```swift
let str = "Hello, world!"
print(str.first) // Prints Optional("H")
print(str.last)  // Prints Optional("!")
```

Você também pode usar os métodos `prefix` e `suffix` para obter uma substring de uma string.
Esses métodos recebem um inteiro como argumento e retornam uma substring com os primeiros ou os últimos n caracteres da string.

```swift
let str = "Hello, world!"
print(str.prefix(5)) // Prints "Hello"
print(str.suffix(6)) // Prints "world!"
```

## Aprofundando: indexação Unicode

~~~~exercism/advanced

O [Unicode][unicode] é um padrão para codificar texto e reúne um grande número de caracteres de diversos idiomas e sistemas de escrita.
Ele é um superconjunto do ASCII, o que significa que todos os caracteres ASCII também são caracteres Unicode.
O Unicode é uma codificação de comprimento variável, ou seja, alguns caracteres ocupam mais bytes do que outros.
E por que isso importa será explicado na próxima seção.

Então precisamos ir a outros idiomas (além do inglês) para realmente ver o problema. Vamos pegar o caractere "ü" do alemão (repare que aqui estamos usando a variante de 2 bytes; também existe uma versão de 1 byte).
À primeira vista, ele pode parecer um único caractere, mas na verdade são dois caracteres: "u" e "¨". Então, se você imprimisse o comprimento da string "ü", ele seria 2 em linguagens como Python.
No entanto, como usuário ou programador, diríamos que é um único caractere, e o Swift concorda com a gente.
Mas por que o Swift faz isso e o Python não?
A resposta é que o Swift usa uma representação de strings diferente do Python.
No Python, as strings são representadas como uma sequência de bytes, o que significa que o comprimento de uma string é o número de bytes que ela ocupa na memória.
No Swift, as strings são representadas como uma sequência de caracteres, o que significa que o comprimento de uma string é o número de caracteres que ela contém.
Essa é uma distinção muito importante, porque significa que, no Swift, o comprimento de uma string não é necessariamente igual ao número de bytes que ela ocupa na memória.
E é justamente isso que faz com que não possamos usar inteiros para indexar strings.
