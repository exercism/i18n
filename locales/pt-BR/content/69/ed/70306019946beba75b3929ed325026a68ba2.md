# Instruções

Você está escrevendo código para o sistema de dados do chão de fábrica de uma fábrica de peças automotivas.
Componentes de motor e chassi passam por uma série de estações de usinagem.
Cada estação produz medições que precisam ser combinadas, comparadas, calibradas ou normalizadas antes que a próxima etapa rode.
As funções que você implementa aqui são uma para cada estação.

~~~~exercism/note
As computações neste exercício devem ser feitas usando instruções SIMD, não operações escalares.
~~~~

## 1. Combine os rendimentos de duas linhas

O chão de fábrica opera duas linhas de montagem paralelas.
No fim de cada turno, as duas linhas reportam seus rendimentos para 4 caixas de peças como números de precisão simples.
O painel do supervisor mostra o rendimento combinado por caixa, então os dois relatórios são somados caixa a caixa.
Os três buffers são gerenciados pelo sistema de relatórios e estão sempre alinhados em 16 bytes.

Defina uma função `sum_yields` que, dados os rendimentos por caixa de `line_a` e `line_b`, escreve a soma caixa a caixa em `result`.
Os argumentos, em ordem, são:

1. `line_a`: endereço de memória alinhado em 16 bytes que armazena 4 números de ponto flutuante de 32 bits
2. `line_b`: endereço de memória alinhado em 16 bytes que armazena 4 números de ponto flutuante de 32 bits
3. `result`: endereço de memória alinhado em 16 bytes onde a função escreverá 4 números de ponto flutuante de 32 bits

Esta função não tem valor de retorno; em vez disso, o resultado é armazenado no buffer passado (`result`):

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. Calcule o desvio escalado

Entre as operações, uma estação de amostragem mede peças usinadas e as compara com as dimensões alvo.
Os valores medidos chegam em fluxo de um medidor de precisão para um buffer que está sempre alinhado em 16 bytes.
Os valores alvo vêm do pacote de ordem de serviço, que não tem garantia de alinhamento.
O desvio é multiplicado por um fator de sensibilidade por eixo antes de ser passado para o verificador de tolerância a jusante.
Para esta etapa, o verificador a jusante lê o desvio diretamente de um registrador SIMD, e não da memória.

Defina uma função `scaled_deviation` que, dados `measured` e `target` e uma `sensitivity`, escreve o desvio escalado em `result`.
Os argumentos, em ordem, são:

1. `measured`: endereço de memória alinhado em 16 bytes que armazena 2 números de ponto flutuante de 64 bits
2. `target`: endereço de memória que armazena 2 números de ponto flutuante de 64 bits (alinhamento não garantido)
3. `sensitivity`: endereço de memória que armazena 2 números de ponto flutuante de 64 bits (alinhamento não garantido)
4. `result`: endereço de memória para um buffer onde a função escreverá 2 números de ponto flutuante de 64 bits (alinhamento não garantido)

O desvio escalado é `(measured - target) * sensitivity`, lane a lane.

Esta função não tem valor de retorno; em vez disso, o resultado é armazenado no buffer passado (`result`) como um par de números de ponto flutuante de 64 bits.

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. Calibre um lote

Antes que as peças entrem na baía de inspeção final, as leituras dimensionais de um lote de 4 peças são reescaladas para precisão dupla e corrigidas quanto à deriva de temperatura conhecida.

As 4 leituras brutas chegam como números de precisão simples.
Para cada linha de 2 leituras, a calibração calcula `reference / (raw - offset)` e depois multiplica esse resultado por um fator de conversão constante de `0.5`.

Repare que a referência e o offset são os mesmos para as duas linhas do lote.
O fator de conversão é o mesmo em toda calibração, então, em vez de recebê-lo como argumento, você deve declará-lo como uma constante de 16 bytes empacotada na memória.

Defina uma função `calibrate_batch` que, dados um lote `raw`, uma `reference`, um `offset` e um buffer `result`, escreve os valores calibrados em `result`.
Os argumentos, em ordem, são:

1. `raw`: endereço de memória que armazena 4 números de ponto flutuante de 32 bits (alinhamento não garantido)
2. `reference`: endereço de memória alinhado em 16 bytes que armazena 2 números de ponto flutuante de 64 bits
3. `offset`: endereço de memória alinhado em 16 bytes que armazena 2 números de ponto flutuante de 64 bits
4. `result`: endereço de memória alinhado em 16 bytes onde a função escreverá 4 números de ponto flutuante de 64 bits (32 bytes no total)

A função deve, para cada uma das duas linhas do lote:

1. Converter os 2 valores brutos de precisão simples da linha para precisão dupla.
2. Subtrair `offset` do par convertido.
3. Dividir `reference` pelo resultado.
4. Multiplicar lane a lane cada número de ponto flutuante de 64 bits pelo fator de conversão fixo de `0.5`.
5. Armazenar os 2 números de ponto flutuante de 64 bits nos 16 bytes correspondentes de `result`.

Esta função não tem valor de retorno; em vez disso, o resultado é armazenado no buffer passado (`result`):

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. Normalize as pontuações ao longo de uma linha

No fim da linha, cada peça tem uma pontuação de qualidade que precisa ser normalizada antes de ser reportada.
Cada pontuação é multiplicada pelo seu próprio ganho por peça e depois dividida por uma escala de produção por eixo.
O buffer de ganhos contém um ganho por peça.

A escala de produção é a mesma para toda a execução e é passada em um endereço de memória que armazena dois números de ponto flutuante de 64 bits.
As pontuações são atualizadas **no próprio local**: o mesmo buffer que continha as pontuações brutas agora contém as pontuações normalizadas.

Defina uma função `normalize_scores` que, dados um array `scores`, um array `gains`, uma `scale` e uma contagem `n`, normaliza as pontuações no próprio local.
Os argumentos, em ordem, são:

1. `scores`: endereço de memória alinhado em 16 bytes que armazena `n` números de ponto flutuante de 64 bits (modificado no próprio local)
2. `gains`: endereço de memória alinhado em 16 bytes que armazena `n` números de ponto flutuante de 64 bits
3. `scale`: endereço de memória alinhado em 16 bytes que armazena 2 números de ponto flutuante de 64 bits
4. `n`: um inteiro positivo e par de 64 bits (mínimo `2`), o número de pontuações a normalizar

Os dois lanes da escala se aplicam aos dois elementos de cada par.
O primeiro lane escala o primeiro elemento de cada par (lanes em posições pares), o segundo lane escala o segundo (lanes em posições ímpares).
Cada pontuação é multiplicada pelo ganho correspondente e depois dividida pelo lane de escala apropriado: `score * gain / scale_lane`.

Esta função não tem valor de retorno; em vez disso, o resultado é armazenado no buffer de entrada (`scores`), na mesma posição da `score` correspondente que foi normalizada:

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
