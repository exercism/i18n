# Sobre

Em muitas linguagens orientadas a objetos, é comum estender comportamentos criando uma [subclasse][wiki-subclass] de uma classe pai, herdando métodos do pai e também adicionando novos.
Assim, obtemos uma hierarquia de objetos.

Julia _não tem classes_, então, por extensão, _não tem subclasses_.
Como herdamos e estendemos comportamentos existentes?

Vimos em conceitos anteriores como criar uma hierarquia de tipos, além de aprender como Julia usa [multiple dispatch][concept-multiple-dispatch] para escolher métodos com base nos tipos dos argumentos.

Julia também tem várias [interfaces][ref-interfaces] informais, que permitem que seus tipos personalizados se conectem a comportamentos já definidos para os tipos padrão.

Isso fica mais fácil de ilustrar com a interface de iteradores.

## [Iteradores][ref-iterators]

Anteriormente, no programa de estudos, vimos várias maneiras de Julia operar sobre cada elemento de uma coleção.

- [Laços][concept-loops], como `for item in items...`
- [Broadcasting][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Funções de ordem superior][concept-hof]: `map(√, [1, 4, 9])`
- [Compreensões de listas][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Geradores][concept-comprehensions]: `(x^2 for x in 1:1e6)`, que é avaliado de forma preguiçosa.

Claramente, Julia sabe percorrer coleções padrão item por item: vetores e intervalos nos exemplos acima, além de Sets, Dicts, etc.

Como adicionamos essa capacidade às nossas próprias coleções personalizadas, especialmente se elas puderem ser iteradas de forma preguiçosa como um gerador?

### Requisitos mínimos

Para criar uma sequência para iteração, precisamos de (pelo menos) duas coisas:

1. Uma forma de obter o _primeiro_ item.
2. Uma forma de obter o _próximo_ item a partir do estado atual.

Julia realiza essas tarefas com métodos da função `Base.iterate()`, seguindo os passos abaixo:

1. `Base.iterate(iter)` é chamado automaticamente primeiro.
    - Se não houver nada para iterar, retorna `nothing`.
    - Caso contrário, retorna a `Tuple` formada pelo primeiro item retornado e pelo primeiro estado: `(firstitem, firststate)`.
2. `Base.iterate(iter, state)` é chamado automaticamente se um item foi retornado na iteração anterior, usando `firststate` como seu argumento `state`.
    - Se a iteração terminar, retorna `nothing`.
    - Caso contrário, retorna a `Tuple` do próximo item e do próximo estado: `(nextitem, nextstate)`.
3. Repete o passo 2 até a terminação.

Todos esses passos acontecem "por baixo do capô", ou seja, as chamadas de método e o estado são gerenciados internamente pelo protocolo de iteração (com o estado permanecendo opaco), e apenas o item é exposto a construções de alto nível, como os laços.
Em outras palavras, só vemos o `item`, enquanto todo o resto permanece numa caixa preta.

O [multiple dispatch][concept-multiple-dispatch] é fundamental aqui.
O tipo de `iter` determina quais métodos são chamados, e o número de argumentos determina se o primeiro item ou o próximo item é retornado.

Os métodos para os tipos padrão já estão definidos: `Vector`, `Range`, `Set`, etc ([atualmente][ref-iterations-collections], 14 tipos no total).

Para que um `MyType` personalizado compartilhe os mesmos comportamentos, primeiro precisamos definir:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Tudo isso provavelmente soa confuso no abstrato, mas pode ser bem simples.
Para ilustrar, imagine que queremos um tipo que forneça as potências de um inteiro `n` dado, até uma contagem máxima.

Primeiro, defina um tipo personalizado:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Agora podemos definir os métodos `iterate` para esse tipo, mas quais são o primeiro item e o primeiro estado?

Para obter o primeiro item, alguns iteradores precisam de uma preparação complicada, mas neste caso de brinquedo podemos perceber que o primeiro item retornado é apenas o número base, então só precisamos verificar se o valor de `count` é maior ou igual a um.

Agora podemos considerar o primeiro estado, que carrega informações usadas na próxima iteração.
Fica a seu critério decidir quais informações você precisa acompanhar para fazer isso, e elas podem ser de qualquer tipo.

Neste caso, poderíamos apenas acompanhar o "índice" ao qual elevar `n`, ou podemos encontrar uma opção mais eficiente usando a potência mais recente de `n` (ou seja, o item retornado) e o próximo "índice" da sequência.
Esses dois números podem ser envolvidos em uma `Tuple` e retornados como o `state`.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

Neste exemplo, o primeiro item (`p.n`) é retornado ao laço, e o primeiro estado `(p.n, 2)` é passado ao método `iterate(P::Powers, state)`.
Lá, podemos processar o estado para produzir o próximo item multiplicando o item atual pelo número base, aumentando assim sua potência em `1`.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Se o valor do índice ainda estiver dentro de `count`, a `Tuple` é retornada com o item `next` e o estado incrementado `(next, index + 1)`.
Quando o valor de `index` ultrapassa `count`, `nothing` é retornado, indicando que a iteração terminou.

Talvez você tenha notado que os métodos `iterate(p::Powers)` e `iterate(p::Powers, state)` têm corpos de função bastante parecidos.
Na verdade, se formos espertos, essa semelhança permite uma implementação mais enxuta, usando apenas a versão de dois argumentos com um argumento padrão para o estado: `Base.iterate(p::Powers, state=(1, 1))`
Com isso, não precisaríamos do método separado de um único argumento `iterate(p::Powers)`.
Isso é feito com frequência na prática quando possível.

~~~~exercism/advanced
Quando introduzimos os argumentos opcionais no conceito de [Funções][concept-functions], nada foi dito sobre a implementação.

Desde então, aprendemos sobre multiple dispatch, então agora faz mais sentido saber que Julia converte automaticamente uma função _com_ argumentos opcionais em vários métodos _sem_ argumentos opcionais.

Definir `Base.iterate(P::Powers, state=(1, 1))` é exatamente equivalente a definir `Base.iterate(P::Powers, state)` e `Base.iterate(P::Powers)` separadamente.

[concept-functions]: https://exercism.org/tracks/julia/concepts/functions
~~~~

Até aqui, já temos uma funcionalidade útil: para as 4 primeiras potências de 3, podemos percorrer os resultados com um laço, verificar se um número está nos resultados e aplicar funções de agregação como `sum()`.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Métodos adicionais

Apesar desse bom começo, nem tudo funciona ainda.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers)
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

De fato, `length(Powers(3, 4))` dá exatamente a mesma mensagem de erro.

Isso é fácil de corrigir, já que o comprimento faz parte do construtor do tipo: 4, neste caso.
Basta definir `Base.length()` para esse tipo, e então podemos usar compreensões de listas e `collect()` na sequência.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Por eficiência, é melhor também definir `Base.eltype()`: o tipo de elemento do resultado.
Isso permite que funções como `collect()` reservem espaço antecipadamente para o `Vector{Int}` de saída, em vez de fazer repetidamente um `push!()` em um `Vector{Any}`.

Repare na sintaxe, que você talvez não tenha visto antes: esse método é definido no _tipo_, não em uma _instância_ do tipo.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Não é _obrigatório_ que iteradores tenham comprimento finito.
O uso de sequências "infinitas" é mais limitado, mas percorrê-las com um laço pode ser útil desde que haja alguma forma de `break` para sair do laço.
Por exemplo, poderíamos definir uma variante de `Powers` que gerasse valores menores que um certo limite (talvez `typemax(Int)`, para evitar estouro de inteiro).

## Outras interfaces

### [Indexação][ref-indexing]

A interface de iteradores nos permite pegar um tipo personalizado qualquer e fazê-lo se comportar como uma sequência, apenas definindo alguns métodos simples.

Suponha que também quiséssemos poder indexar a sequência:

```julia-repl
julia> P = Powers(3, 4)
Powers(3, 4)

julia> P[2]
ERROR: MethodError: no method matching getindex(::Powers, ::Int64)
The function `getindex` exists, but no method is defined for this combination of argument types.
```

Podemos adicionar esse comportamento, e o [manual][ref-indexing] explica como.

No mínimo, precisamos definir `getindex()`.

```julia-repl
julia> function Base.getindex(P::Powers, i::Int)
          1 ≤ i ≤ P.count || throw(BoundsError(P, i))
          return p.n ^ i
       end

julia> p = Powers(3, 4)
Powers(3, 4)

julia> p[3]
27
```

Também precisamos definir:

- `firstindex()` e `lastindex()` para dar suporte a `P[begin]` e `P[end]`.
- Variantes de `getindex()` para dar suporte à indexação com vetores e intervalos.
- Em teoria, `setindex!()`, embora seja difícil ver o que isso significaria neste exemplo.

No entanto, a essa altura já estamos fazendo muito trabalho só para deixar nosso iterador mais parecido com um Vector.

### [AbstractArray][ref-abstractarray]

Pode valer a pena pensar em interfaces alternativas que ofereçam um ponto de partida melhor.

Neste caso, poderíamos considerar fazer de `Powers` um subtipo de [`AbstractArray`][ref-abstractarray], o que nos dá bastante comportamento de array de graça.

Para a sequência `Powers`, o array correspondente é de inteiros, com 1 dimensão.
Às vezes você verá isso escrito como `AbstractArray{Int, 1}`, mas os apelidos `AbstractVector{Int}` para 1-D e `AbstractMatrix{Int}` para 2-D são mais comuns em código Julia mais recente.

```julia-repl
julia> struct PowersArray <: AbstractVector{Int}
           n::Int
           count::Int
       end
```

Em vez de `length()`, agora precisamos definir `size()` com uma tupla de comprimentos ao longo de cada dimensão: apenas uma dimensão neste caso.

```julia-repl
julia> Base.size(PA::PowersArray) = (PA.count,)
```

Como queremos indexar as entradas?
No [conceito de Arrays Multidimensionais][concept-multi-dimensional-arrays], apresentamos as duas abordagens principais:

- Um índice por dimensão, então `M[row, col]` para uma Matrix `M`.
- Um único índice, correspondendo ao layout das entradas na memória

Esses são chamados de `Cartesian` e `Linear`, respectivamente.

Temos apenas uma dimensão no exemplo, então a indexação linear é apropriada.

```julia-repl
julia> Base.IndexStyle(::Type{PowersArray}) = IndexLinear()

julia> Base.getindex(PA::PowersArray, i::Int) = PA.n ^ i

julia> p = PowersArray(3, 4)
4-element PowersArray:
  3
  9
 27
 81

julia> p[3]
27
```

Repare que não definimos `iterate()` neste caso.
Julia fornece uma implementação padrão automaticamente, com base na nossa definição de `getindex()`.

Ainda é possível definir nossa própria versão de `iterate()`, e em alguns casos ela pode ser mais eficiente.

Usar a interface `AbstractArray` é especialmente valioso se quisermos iteração de dimensões maiores.
Correndo o risco de forçar o exemplo de brinquedo além do limite, isso poderia significar as primeiras `m` potências dos números em `1:n`, o que definirá iterativamente um array de tamanho `(m, n)`.

```julia-repl
struct PowersMatrix{Int} <: AbstractMatrix{Int}
    ns::AbstractVector{Int}
    count::Int
end

Base.size(PM::PowersMatrix) = (PM.count, length(PM.ns))
Base.IndexStyle(::Type{PowersMatrix}) = IndexCartesian()
Base.getindex(PM::PowersMatrix, i::Int, j::Int) = PM.ns[j] ^ i

julia> PM = PowersMatrix(2:6, 4)
4×5 PowersMatrix{Int64}:
  2   3    4    5     6
  4   9   16   25    36
  8  27   64  125   216
 16  81  256  625  1296

julia> PM[3, 2]
27

julia> PM[7] # column major linear indexing
27

julia> PM[21]
BoundsError: attempt to access 4×5 PowersMatrix{Int64} at index [21]
[...]
```

### [Arredondamento][ref-rounding]

Conceitos anteriores mencionaram vários tipos de arredondamento para tipos numéricos.

```julia-repl
julia> round(1.7)
2.0

julia> floor(1.7)
1.0

julia> ceil(1.7)
2.0

# specify output type
julia> round(Int, 1.7)
2

julia> round(2.4 + 7.3im)
2.0 + 7.0im
```

A função [`round()`][ref-round] é mais flexível do que isso, permitindo especificar o [`RoundingMode`][ref-roundingmode] (dos 7 atualmente suportados), as casas decimais da saída e a base numérica.

Podemos querer que as mesmas funções lidem com nossos tipos personalizados.
Normalmente isso significa tipos compostos, como coordenadas.

```julia-repl
julia> struct Point3D
           x::Float64
           y::Float64
           z::Float64
       end

julia> p = Point3D(7.63, 9.24, 4.50)
Point3D(7.63, 9.24, 4.5)

julia> round(p)
ERROR: MethodError: no method matching round(::Point3D, ::RoundingMode{:Nearest})
The function `round` exists, but no method is defined for this combination of argument types.
```

Como era de se esperar, existe uma interface `Rounding`, que no mínimo exige que definamos `round()` para o nosso tipo.

```julia-repl
julia> Base.round(P3D::Point3D, r::RoundingMode) = Point3D(round(P3D.x, r), round(P3D.y, r),round(P3D.z, r))

julia> round(p)
Point3D(8.0, 9.0, 4.0)

julia> ceil(p)
Point3D(8.0, 10.0, 5.0)
```

Como incluímos o `RoundingMode` na definição, `floor()` e `ceil()` funcionam automaticamente.

Claro que somos livres para definir formas mais complicadas de arredondamento.

- Podemos querer arredondar `Point3D` para uma distância inteira da origem, na mesma direção.
- Para ângulos, podemos querer arredondar para as 16 direções usadas pelos meteorologistas (_"vento de SSO a 15 nós"_), ou seja, múltiplos de π/8 radianos.
- Podemos querer adicionar a capacidade de especificar `digits`, `sigdigits` ou `base`.
- Existem [opções especiais][ref-round-periods] para períodos de tempo

## Resumo

Interfaces são bem confusas de explicar, porque a abordagem de Julia é muito diferente da maioria das outras linguagens.
Em particular, o nome da interface pode nunca ser mencionado na implementação: muito diferente de [criar subclasses][wiki-subclass] ou [mixins][wiki-mixins].

No entanto, na prática elas são surpreendentemente simples:

1. Defina um tipo adequado, decidindo se vale a pena criar um subtipo.
2. Descubra quais métodos são necessários (na [documentação][ref-interfaces]).
3. Implemente esses métodos para o seu tipo personalizado; normalmente são só alguns métodos, bem curtos e simples.
4. Deixe o [multiple dispatch][concept-multiple-dispatch] cuidar do resto, automaticamente.
