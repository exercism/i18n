# Para mantenedores

## Gerando testes: `bin/generate_tests.py`

Os arquivos de teste são gerados a partir dos dados canônicos de
[exercism/problem-specifications](https://github.com/exercism/problem-specifications)
usando um template Jinja guardado em cada exercício em `.meta/template.j2`.

```bash
bin/generate_tests.py bob            # regenerate one exercise
bin/generate_tests.py                # regenerate every exercise that has a template
bin/generate_tests.py --no-pull bob  # skip `git pull` of problem-specifications
```

O script lê o problem-specifications do cache do configlet
(`~/.cache/exercism/configlet/problem-specifications`, preenchido por `bin/configlet sync`),
ou de um diretório pai chamado `problem-specifications`.
Só são gerados os casos incluídos em `.meta/tests.toml`.

Literais de string em Fortran não podem conter escapes como `\n` e `\t`.
O filtro de template `escape_quote_whitespace` reescreve esses escapes como
`" // NEWLINE // "`, `" // TAB // "` e `" // CARRIAGE_RETURN // "`,
então o template precisa declarar essas constantes (veja `exercises/practice/bob/.meta/template.j2`).

### Pré-requisitos

- CMake e compilador Fortran funcionando
- Python 3.12+ com `jinja2`
- git

### Fluxo de trabalho para adicionar um novo exercício

Usando `bob` como exemplo:

- Crie um novo branch, por exemplo `git checkout -b exercise-bob`
- Rode `bin/add-exercise bob` (precisa de `jq` e `curl`). Isso:
  - baixa o configlet e roda `configlet create`, que adiciona o exercício ao `config.json` e sincroniza seus docs, metadados e `tests.toml` a partir do problem-specifications
  - ordena o `config.json` com `bin/reorder-exercises`
  - copia `exercises/shared/CMakeLists.txt` para o diretório do exercício
  - escreve uma solução stub, um `.meta/example.f90` stub e um `.meta/template.j2` inicial (a partir de `exercises/shared/template.j2`)

  Ele pede seu nome de usuário do GitHub, a menos que você passe `-a <username>`, e define a dificuldade como 1, a menos que você passe `-d <difficulty>`.

- Edite o `.meta/template.j2` para que cada caso chame a função certa com as entradas certas, e depois gere os testes:

  ```bash
  bin/generate_tests.py bob
  ```

- Escreva uma solução que funcione em `.meta/example.f90`. Substitua o arquivo do estudante (por exemplo `bob.f90`) por um esqueleto das funções ou sub-rotinas que os testes chamam, para ajudar o estudante a começar
- Verifique se todos os testes passam, rodando o build completo a partir da raiz do repositório:

  ```bash
  mkdir -p build && cd build
  cmake ..
  cmake --build .
  ctest -V -R bob
  ```

- Rode `bin/reorder-exercises` e `bin/configlet lint`
- Se tudo passar, abra um pull request com suas mudanças

### Alterando `CMakeLists.txt`

Ao alterar o arquivo do cmake, atualize a cópia principal em `exercises/shared/` e use `bin/update-cmake-files` para copiá-la para todos os diretórios de exercícios.
