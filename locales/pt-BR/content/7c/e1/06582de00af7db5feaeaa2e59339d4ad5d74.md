# Introdução

As expressões `if/else` podem ser usadas para executar lógica condicional, mas Haskell também tem uma forma mais poderosa de fazer isso: o [casamento de padrões][pattern-matching].
Com o casamento de padrões, um valor pode ser testado em relação a um ou mais _padrões_.
Um exemplo desses padrões é o _padrão constante_, que compara um valor com uma constante (por exemplo, `1` ou `"hello"`).

Ao definir funções, você pode definir corpos de função separados para padrões diferentes.
Isso leva a um código limpo, simples e legível.
Você pode fazer casamento de padrões com qualquer tipo de dados: números, caracteres, listas, tuplas, etc.

Por exemplo, uma função trivial que recebe um número inteiro (`Int`) e o deixa _1_ mais perto de _0_ poderia ser escrita assim:

```haskell
closerToZero :: Int -> Int
closerToZero 0 = 0
closerToZero 1 = 0
```

O casamento de padrões começa a brilhar quando é usado junto com outros padrões, por exemplo o _padrão variável_:

```haskell
closerToZero :: Int -> Int
closerToZero 0 = 0
closerToZero n = n - 1
```

O exemplo acima trata todas as entradas diferentes de _0_ da mesma forma e produziria resultados incorretos para números negativos.
Isso pode ser resolvido usando padrões condicionais, conhecidos como _guardas_, que são expressos com o símbolo `|`:

```haskell
closerToZero :: Int -> Int
closerToZero n
    | n < 0 = n + 1
    | n > 0 = n - 1
```

Nos exemplos acima, nem todas as entradas possíveis têm um padrão correspondente.
O compilador vai detectar isso e emitir um aviso.
Esse é um recurso muito útil de Haskell, que ajuda a garantir que todos os caminhos possíveis sejam cobertos, evitando erros em tempo de execução.
Ele é conhecido como _verificação exaustiva_.
Para resolver o aviso, você precisa tratar todos os casos.
Dentro das _guardas_, você pode usar a expressão `otherwise` como açúcar sintático para `True`, para capturar todos os padrões restantes.

```haskell
closerToZero :: Int -> Int
closerToZero n
    | n < 0 = n + 1
    | n > 0 = n - 1
    | otherwise = 0
```

O casamento de padrões testa um valor contra cada padrão, de cima para baixo, até encontrar um padrão correspondente e executar a lógica associada a esse padrão.
**A ordem dos padrões importa!**
