# Contratos

Os argumentos e o tipo de retorno de uma rotina dizem que *tipo* de coisa entra e sai. Eles não conseguem dizer que um peso precisa ser positivo, nem que um arnês nunca informa mais capacidade livre do que realmente tem.

Um **contrato** diz essas coisas, no próprio cabeçalho da rotina, onde qualquer pessoa que o leia vai vê-las.

## pre

`pre` afirma o que precisa ser verdadeiro quando a rotina é chamada. Fica entre o tipo de retorno e o `is`.

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

Isso é uma exigência para quem chama: não chame a rotina com uma carga negativa.

## post

`post` afirma o que será verdadeiro quando a rotina responder. Dentro dele, `result` é o valor que está sendo retornado.

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

Isso é uma promessa para quem chama. Uma rotina com os dois é um trato: me dê isto, e eu te dou aquilo.

Várias condições se juntam com `and`, como qualquer Boolean faz:

```sather
      pre load >= 0 and load <= limit
```

## Contratos não são exceções

Uma exceção lançada serve para algo que pode acontecer. Um contrato quebrado significa um **bug**: alguém chamou a rotina de forma errada, ou a rotina não fez o que disse que faria.

Então um contrato quebrado não lança algo que se possa capturar. Quando a verificação de contratos está ligada, o programa para e imprime qual rotina e qual condição. Quando está desligada, a condição nem sequer é testada, e o programa segue adiante para qualquer bobagem que venha depois.

É por isso que um contrato é uma afirmação sobre correção, e não uma forma de lidar com entrada inválida. Se a entrada inválida é esperada, verifique-a e use `raise`. Se a entrada inválida significa que quem chama está errado, diga isso com `pre`.

## Ligando a verificação

Este Sather verifica contratos quando o compilador recebe `-chk`:

```
sacomp -chk mine.sa -main MAIN -o mine
```

Sem isso, `pre` e `post` são apenas documentação que o compilador leu e concordou que está bem formada, e nada mais. Os testes deste exercício são compilados sem `-chk`, então eles não conseguem detectar um contrato quebrado para você; eles verificam que as rotinas fazem a coisa certa quando usadas corretamente.
