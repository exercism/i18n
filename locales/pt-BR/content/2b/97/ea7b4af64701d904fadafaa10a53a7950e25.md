# Sobre

Os hash-sets implementam o [protocolo][set-protocol] [`sets`][sets] com hashing por baixo dos panos, o que dá inserção, busca e remoção em O(1) na média. Eles são mutáveis no local, o que os torna ideais para o padrão de *conjunto de visitados* em travessias de grafos.

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| palavra       | efeito                                    |
|---------------|-------------------------------------------|
| `HS{ }`       | literal de hash-set vazio (compartilhado, então use `clone`!) |
| `>hash-set`   | `( seq -- set )` — constrói um conjunto novo a partir de uma sequência (remove duplicatas) |
| `adjoin`      | `( elt set -- )` — inserção destrutiva    |
| `in?`         | `( elt set -- ? )` — pertinência          |
| `delete`      | `( elt set -- )` — remoção destrutiva     |
| `cardinality` | `( set -- n )` — número de elementos      |
| `null?`       | `( set -- ? )` — verdadeiro quando o conjunto está vazio |
| `members`     | `( set -- seq )` — enumera como sequência |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )` — converte `set` para a classe de `exemplar` |

Para construir um conjunto a partir de dados que você já tem, `>hash-set` converte qualquer sequência em um único passo, descartando as duplicatas: `{ 2 3 2 5 } >hash-set` resulta em `HS{ 2 3 5 }`. É a versão em lote de crescer um conjunto com vários `adjoin` repetidos.

Um ponto sutil sobre `in?` versus `member?` (de `sequences`): os dois testam pertinência, mas `member?` faz uma varredura linear sobre a sequência, enquanto `in?` despacha para o que for o método de protocolo do tipo do conjunto. No caso de `HS{ }`, isso é uma busca em hash. Use `in?` quando seu contêiner de "visitados" tiver mais do que um punhado de entradas.

`null?` responde "este conjunto está vazio?" sem calcular toda a `cardinality`. É a guarda natural para "ainda temos algo para processar?". Para uma lista de trabalho mantida como um conjunto, `[ set null? ] [ … ] until` a esvazia até o fim.

## Combina bem com hashtables

`HS{ }` para "X já foi visitado?" combina naturalmente com `H{ }` para "quem são os vizinhos de X?". Uma DFS de livro-texto é só isto:

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

O conjunto de visitados elimina trabalho repetido; a pilha encadeia os nós da fronteira (LIFO via `push`/`pop`); o mapa de vizinhos (um hashtable) fornece o grafo. A ordem de visita não importa para uma pergunta de alcançabilidade, e é por isso que um vetor usado como pilha basta. Uma BFS de verdade sobre o mesmo formato troca o vetor por uma [`<dlist>`][dlist] e desenfileira pela frente.
