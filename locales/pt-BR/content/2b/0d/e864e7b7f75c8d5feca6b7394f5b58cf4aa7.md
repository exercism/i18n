# Sobre

Os `Complex numbers` não são complicados.
Eles só precisam de um nome menos assustador.

Eles são tão úteis, especialmente na engenharia e na ciência, que o Python inclui [`complex`][complex] como um tipo numérico padrão, ao lado dos inteiros ([`int`s][ints]) e dos números de ponto flutuante ([`float`s][floats]).


## Noções básicas

Um valor `complex` no Python é essencialmente um par de números de ponto flutuante.
Eles são chamados de partes "real" e "imaginária", por motivos históricos infelizes.
Mais uma vez, é melhor focar na simplicidade por trás disso e não nos nomes estranhos.

Existem duas formas comuns de criar números complexos.

1) O construtor [`complex(real, imag)`][complex] recebe dois parâmetros `float`:

```python
>>> z1 = complex(1.5, 2.0)
>>> z1
(1.5+2j)
```

O construtor também pode interpretar uma string como entrada.
Isso tem a limitação curiosa de falhar se a string contiver espaços.

```python
>>> complex('4+2j')
(4+2j)

>>> complex('4 + 2j')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ValueError: complex() arg is a malformed string
```


2) O número complexo pode ser especificado como o literal `<real part> + <complex part>j`, ou apenas `<complex part>j` se a parte real for zero:


```python
>>> z2 = 2.0 + 1.5j
>>> z2
(2+1.5j)
```
O resultado final é idêntico ao de usar o construtor `complex()`.


Existem duas regras para essa parte imaginária do número complexo:


- Ela é indicada com `j` (não `i`, como você pode ver em livros de matemática).

- O `j` deve vir imediatamente após um número, para que o Python não o veja como um nome de variável. Se necessário, use `1j`.

```python
>>> j
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
NameError: name 'j' is not defined

>>> 1j
1j

>>> type(1j)
<class 'complex'>
```

A maioria dos engenheiros fica satisfeita com `j`.
A maioria dos cientistas e matemáticos prefere a notação matemática `i` para _imaginário_, mas essa notação entra em conflito com o uso de `i` para significar _corrente_ na Engenharia Elétrica.
Então, ao projetar o Python, os engenheiros elétricos venceram.


Para acessar as partes de um número complexo individualmente:

```python
>>> z2.real
2.0
>>> z2.imag
1.5
```

Qualquer uma das partes pode ser zero, e os matemáticos podem então falar que o número é "totalmente real" ou "totalmente imaginário".
Mesmo assim, ele continua sendo um número complexo no Python:


```python
>>> complex(0, 1)
1j
>>> type(complex(0, 1))
<class 'complex'>

>>> complex(1, 0)
(1+0j)
```

Você pode ter ouvido que "`i` (ou `j`) é a raiz quadrada de -1".

Por enquanto, tudo o que isso significa é que a parte imaginária _por definição_ satisfaz a igualdade
```python
1j * 1j == -1  # => True
```

É uma ideia simples, mas leva a consequências interessantes.

## Aritmética

A maioria dos [`operators`][operators] usados com números de ponto flutuante e inteiros também funciona com números complexos:


```python
>>> z1 = (1.5+2j)
>>> z2 = (2+1.5j)


>>> z1 + z2  # addition
(3.5+3.5j)

>>> z1 - z2  # subtraction
(-0.5+0.5j)

>>> z1 * z2  # multiplication
6.25j

>>> z1 / z2  # division
(0.96+0.28j)

>>> z1 ** 2  # exponentiation
(-1.75+6j)

>>> 2 ** z1  # another exponentiation
(0.5188946835878313+2.7804223253571183j)

>>> 1j ** 2  # j * j == -1
(-1+0j)
```

Explicar as regras de multiplicação e divisão de números complexos está fora do escopo deste conceito (_e é pouco provável que você precise fazer essas operações "à mão" com frequência_).

Qualquer introdução [matemática][math-complex] ou de [engenharia elétrica][engineering-complex] aos números complexos aborda isso, caso você queira se aprofundar no assunto.

Como alternativa, o Exercism tem um exercício de prática `Complex Numbers`, no qual você pode implementar uma classe de números complexos com essas operações a partir dos primeiros princípios.


A divisão inteira ___não___ é possível com números complexos, então os operadores `//` e `%` e a função `divmod()` vão falhar para o tipo de número complexo.


Há duas funções implementadas para tipos numéricos que são muito úteis ao trabalhar com números complexos:

- `<complex number>.conjugate()` simplesmente inverte o sinal da parte imaginária de um número complexo (_de + para - ou vice-versa_).
    - Por causa de como a multiplicação de complexos funciona, isso é mais útil do que você imagina.
- `abs(<complex number>)` tem a garantia de retornar um número real sem parte imaginária.


```python
>>> z1
(1.5+2j)

>>> z1.conjugate() # flip the z1.imag sign
(1.5-2j)

>>> abs(z1) # sqrt(z1.real ** 2 + z1.imag ** 2)
2.5
```

## O módulo `cmath`

A biblioteca padrão do Python tem um módulo [`math`][math-module] cheio de funcionalidades úteis para trabalhar com números reais.

Ela também tem um módulo equivalente, [`cmath`][cmath], para trabalhar com números complexos.


Recomendamos que você leia o módulo e experimente, mas as principais categorias são:

- Conversão entre coordenadas cartesianas e polares,
- Funções exponenciais e logarítmicas,
- Funções trigonométricas,
- Funções hiperbólicas,
- Funções de classificação, e
- Constantes úteis.

Veja um exemplo usando algumas constantes:

```python
>>> import cmath

>>> euler = cmath.exp(1j * cmath.pi) # Euler's equation

>>> euler.real
-1.0
>>> round(euler.imag, 15) # round to 15 decimal places
0.0
```

Então, uma expressão simples com três das constantes mais importantes da natureza, `e`, `i` (ou `j`) e `pi`, dá o resultado `-1`.
Algumas pessoas acreditam que este é o resultado mais belo de toda a matemática.
Ele remonta a cerca de 1740.

## Seção opcional: perguntas frequentes sobre números complexos

Esta parte pode ser pulada, a menos que você tenha interesse.

### Isso não é algum ramo novo e estranho da matemática pura?

Era estranho e novo no século XVI.

500 anos depois, é central para a maior parte da engenharia e das ciências físicas.

### Por que alguém usaria isso?

Acontece que os números complexos são a forma mais simples de descrever qualquer coisa que gira ou que tenha uma propriedade ondulatória.
Por isso, são amplamente usados em engenharia elétrica, processamento de áudio, física, jogos de computador e navegação, para citar apenas algumas aplicações.

Você consegue ver as coisas girando.
Os números complexos podem não fazer o mundo girar, mas são ótimos para explicar _o que acontece_ como resultado do giro do mundo: basta olhar qualquer imagem de satélite de uma grande tempestade.


De forma menos óbvia, o som é ondulatório, a luz é ondulatória, os sinais de rádio são ondulatórios, e até a economia do seu país é, pelo menos em parte, ondulatória.


Boa parte desse processamento de ondas pode ser feito com funções trigonométricas (`sin()` e `cos()`), mas isso fica confuso bem rápido.

Exponenciais complexas são ___muito___ mais fáceis de usar.

### Mas eu não preciso de números complexos!


Só é verdade se você mora numa caverna e busca seu próprio alimento.

Se você está lendo isto em qualquer tipo de tela, depende totalmente de alguns avanços úteis do século XX obtidos com o uso de números complexos.


1. __Chips semicondutores__.
    - Eles não fazem sentido na física clássica e só podem ser explicados (e projetados) pela mecânica quântica (MQ).
    - Na MQ, tudo tem valor complexo por definição. (_é forma de onda até o fim_)

2. __O algoritmo da Transformada Rápida de Fourier (FFT)__.
    - A FFT é uma aplicação dos números complexos e está em _tudo_ ligado à transmissão de som, ao processamento de áudio, às fotos e ao vídeo.

    - MP3 e outros formatos de áudio usam a FFT para compressão, garantindo que mais áudio caiba em um espaço de armazenamento menor.
    - A compressão JPEG e o vídeo MP4, entre muitos outros formatos de imagem e vídeo, também usam a FFT para compressão.

    - A FFT também é usada nos filtros digitais que permitem às torres de celular separar o sinal do seu telefone do de todo mundo.


Então, você provavelmente usa tecnologia que depende de cálculos com números complexos milhares de vezes por segundo.
