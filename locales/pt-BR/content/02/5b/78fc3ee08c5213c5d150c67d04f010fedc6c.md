# Dicas

`Option` é usado para indicar uma computação que pode não ter um resultado útil
(por exemplo, devido a um erro ou a uma entrada inválida).
Se você não conhece `Option`, pode ler [este tutorial](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html).
`Option` é o que se chama de [mônada](https://en.wikipedia.org/wiki/Monad_(functional_programming)), que cobre um "aspecto computacional", neste caso a possível ausência de um valor.
O uso correto de mônadas pode resultar em um código bem conciso, mas ainda assim elegante
e legível. O uso incorreto pode facilmente resultar no contrário.
Assista a [este vídeo](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) para saber mais.

## Armadilhas comuns que você deve evitar

Existem algumas regras práticas para `Option`:

1. Se você não precisa, não use. Em vez de
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
é melhor ter
```scala
def add1(x: Int): Int = x + 1
```
(existe o `Option.map` para aplicar funções simples como essas,
então você não precisa poluí-las com `Option`).
2. Não faça "unwrap" se você realmente não precisar.
Muitas vezes existem funções prontas para o seu objetivo. Indicadores de unwrap prematuro
são `isDefined/isEmpty` ou pattern matching. Em vez de
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
é melhor ter
```scala
x map (_ + 1) getOrElse 0
```
3. Mônadas podem ser usadas dentro de uma for-comprehension. Isso é demais.
Isso é recomendável quando você quer "compor" várias instâncias de `Option`. Em vez de
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
é melhor ter
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
