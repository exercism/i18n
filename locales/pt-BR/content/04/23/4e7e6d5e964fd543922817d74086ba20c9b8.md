# Mutabilidade

A mutabilidade é uma propriedade de uma vinculação específica em Rust. Uma vinculação é imutável ou mutável. O valor de uma vinculação imutável não pode ser alterado; o valor de uma vinculação mutável pode ser alterado. Todas as vinculações são imutáveis por padrão.

## Vinculações

Uma vinculação é a associação entre um nome de variável específico, tal como ele aparece no código-fonte, e uma região de memória específica, tal como ela aparece durante a execução. A rigor, as vinculações só existem durante a compilação: antes da compilação, não há memória de fato alocada, e depois da compilação, o código de máquina lida exclusivamente com endereços de memória em vez de variáveis nomeadas.

As vinculações normalmente são criadas com a palavra-chave `let`. Além disso, vinculações são criadas a partir de parâmetros de função e em certas outras circunstâncias.

As vinculações podem ter várias propriedades, e a mais importante delas é a mutabilidade. Uma vinculação mutável é aquela para a qual é legal alterar o valor da memória vinculada. O Rust rastreia e impõe rigorosamente a mutabilidade de cada vinculação para ajudar a garantir que os programas estejam corretos, rejeitando programas que tentam, incorretamente, modificar uma vinculação que deveria ser imutável.

## Mutabilidade

Na prática, a mutabilidade muitas vezes é simples. Ao usar a palavra-chave `mut` na definição da vinculação, você ganha a capacidade de alterar o valor.

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### Rebaixar de mutável para imutável

Uma vinculação sempre pode ser rebaixada de mutável para imutável. Essa operação é transparente.

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### Promover de imutável para mutável

Em geral, é possível promover um valor de imutável para mutável sempre que ocorre uma transferência de ownership.

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

Em `(1)`, o ownership da string é transferido de `x` para `y`, o que nos permite promover o valor para mutável.

### Mutabilidade em parâmetros de função

Existem duas maneiras diferentes de um parâmetro de função ser mutável. O primeiro método, mais comum, lembra a passagem por referência em C:

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

Neste exemplo, a mutabilidade foi anotada explicitamente em três lugares. Todas as três declarações de mutabilidade são necessárias para que referências mutáveis funcionem.
Em `(2)`, a vinculação `x` é declarada como mutável. Essa vinculação é o dono de nível superior do valor.
Em `(3)`, esse valor é emprestado mutavelmente, para ser passado para a função `increment`.
Em `(1)`, uma nova vinculação mutável `n` é criada para a referência apropriada.

Há outro estilo de mutabilidade de parâmetro, menos comum, mas às vezes ainda útil. Nesse estilo, o valor tem um dono, mas a vinculação é mutável.

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

Este exemplo exige menos anotações explícitas porque, na verdade, é uma transferência de ownership com promoção de mutabilidade embutida. Ele funciona porque `i32` é um tipo `Copy`, que copia dados de forma transparente.
Em `(1)`, declaramos que `increment_internally` aceita um `i32` mutável com dono, chamado `n`, como seu parâmetro.
Em `(2)`, declaramos `x` como uma vinculação imutável ao valor `1`.
Em `(3)`, `x` é copiado para um novo local na memória. `x` continua imutável. `n` é mutável.

É claro que é possível combinar as formas, dando uma vinculação mutável a uma referência mutável (`mut n: &mut i32` etc.), mas raramente é isso que se deseja de fato.

### Mutabilidade sem `let`

Várias construções em Rust (`if let`, `match` etc.) também podem criar vinculações. Essas vinculações também podem ser mutáveis.

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

Este exemplo produz primeiro `v = Some(2)` e depois `v = None`.

## Sombreamento

É possível, e muitas vezes idiomático, reutilizar um nome de variável conforme um valor específico vai sendo transformado, redeclarando-o com várias invocações de `let`. Isso é conhecido como sombreamento.

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

No entanto, este não é um caso de mutabilidade; os valores originais, em princípio, ainda estão presentes. No caso de tipos que não são `Drop`, o compilador pode optar por alterar um local na memória em vez de alocar um novo. Porém, ele nunca fará isso no caso de um tipo `Drop` ou se a vinculação antiga for usada novamente.

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
