# Geradores de testes

A trilha de C# usa um [gerador de testes](https://exercism.org/docs/building/tooling/test-generators) para gerar automaticamente os testes dos exercícios de prática.
Ele usa o fato de que a maioria dos exercícios definidos no [repositório problem-specifications](https://github.com/exercism/problem-specifications/) também tem um arquivo `canonical-data.json`, que contém entradas e saídas de teste padronizadas que podem ser usadas para implementar o exercício.

## Etapas

Para gerar os testes de um exercício de prática, o gerador de testes:

1. Lê os casos de teste do exercício no arquivo `canonical-data.json`
2. Usa o arquivo `tests.toml` para omitir os casos de teste excluídos
3. Renderiza os casos de teste usando o template do gerador do exercício
4. Formata o template renderizado usando Roslyn
5. Escreve o template formatado no arquivo de teste do exercício

### Etapa 1: ler o arquivo `canonical-data.json`

O gerador de testes analisa os casos de teste do `canonical-data.json` do exercício usando o [namespace System.Text.Json](https://learn.microsoft.com/en-us/dotnet/api/system.text.json).

Como alguns dados canônicos usam aninhamento, o caso de teste analisado inclui um campo `path` adicional que contém as propriedades `description` de quaisquer elementos pais, assim como a propriedade `description` do próprio caso de teste.

### Etapa 2: omitir testes excluídos do arquivo `tests.toml`

Cada exercício tem um arquivo `tests.toml`, no qual testes individuais podem ser excluídos/desabilitados.
O gerador de testes removerá quaisquer casos de teste marcados como excluídos (`include = false`).

### Etapa 3: renderizar os casos de teste

Os casos de teste (potencialmente transformados) são então passados para o arquivo `.meta/Generator.tpl`, que define como os testes devem ser renderizados com base nesses casos de teste.

### Etapa 4: formatar o template renderizado usando Roslyn

O template renderizado é então formatado usando o [Roslyn](https://github.com/dotnet/roslyn).
Isso tem os seguintes benefícios:

- Os exercícios são formatados de forma consistente
- Você não precisa se preocupar muito com espaços em branco e alinhamento ao escrever templates

### Etapa 5: escrever o template renderizado no arquivo de teste do exercício

Por fim, a saída do template renderizado é escrita no arquivo de teste do exercício.

## Templates

Os templates são renderizados usando a [biblioteca Scriban](https://github.com/scriban/scriban/).

## Interface de linha de comando

Há duas formas de executar o gerador de testes:

1. `bin/update-tests.ps1`: atualiza os testes de todos os exercícios que têm um template de gerador
2. `bin/update-tests.ps1 -e <slug>`: atualiza os testes do exercício especificado, se ele tiver um template de gerador
