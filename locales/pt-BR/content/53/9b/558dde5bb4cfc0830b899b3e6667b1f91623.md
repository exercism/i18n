# Dicas

## 1. Gerar consultas SELECT

- Lembre-se de que você não precisa inicializar o builder com um construtor nem com um literal. Um simples `var sb strings.Builder` já fica operacional na hora.
- Não deixe de tratar o caso em que o slice `columns` está vazio ou é `nil`, acrescentando o símbolo curinga `*`.
- Repare que você não precisa tratar metacaracteres nem fazer sanitização de SQL aqui, e isso também não é esperado. Você pode acrescentar os nomes das colunas diretamente com `sb.WriteString(col)` sem problema.

## 2. Gerar instruções INSERT em lote

- Alocar um `strings.Builder` novinho em folha dentro de um laço `for` anula os ganhos de desempenho. Em vez disso, declare um único builder *antes* de o laço começar.
- No início de cada iteração do laço, chame o método `Reset()` na sua instância do builder. Isso esvazia o buffer para você começar uma consulta nova, preservando por baixo dos panos a capacidade de memória já alocada.
- Não esqueça que os valores string na cláusula `VALUES` do SQL precisam ser envolvidos explicitamente em aspas simples `'`. Você pode usar `WriteByte('\'')` para adicioná-las de forma limpa.
- Assim como nas consultas SELECT, não se preocupe em escapar caracteres especiais nem em evitar injeções de SQL nos valores das colunas. Trate as strings de entrada como seguras para uso direto.
