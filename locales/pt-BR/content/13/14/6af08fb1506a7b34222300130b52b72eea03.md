# Instruções

Quanto mais você aprende sobre programação, mais começa a achar que isso pode ser mais do que só uma moda.
Talvez até existam oportunidades de negócio: as pessoas escrevem código, querem salvá-lo, compartilhá-lo, colaborar, quem sabe até receber um feedback.

Beleza, vamos fazer isso, vamos construir um serviço para incentivar as pessoas a programar: hup, hup, gente, comecem a usar git!
Vamos chamar de... GitHup.

Você começa a construir uma API REST JSON: usuários, pull requests, comentários, e o backend fica pronto rapidinho.
Aqui está um exemplo do payload que é servido quando você pede ao servidor a lista de comentários de um pull request:

```json
[
  {
    "id": 256,
    "pull_request_review_id": 42,
    "user": {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    },
    "body": "Great stuff!",
    "side": "RIGHT",
    "_links": {
      "self": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1"
      },
      "html": {
        "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1"
      },
      "pull_request": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1"
      }
    }
  },
  {
    "id": 11,
    "pull_request_review_id": null,
    "user": {
      "id": 2,
      "login": "hexacat",
      "name": "Alex Kate",
      "avatar_url": "https://githup.com/images/error/hexacat_happy.gif",
      "site_admin": true
    },
    "body": "Amazing stuff!",
    "side": "LEFT",
    "_links": {
      "self": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1"
      }
    }
  }

```

Claro, o frontend vai ser feito em Elm, mas primeiro você precisa entender o que são esses tais decodificadores/codificadores.

```exercism/note
Deixando a historinha de lado, os requisitos do exercício vêm diretamente dos endpoints da API REST do GitHub para comentários de revisão de pull request.
Alguns campos foram removidos dos esquemas JSON para simplificar, mas isso é o mais próximo de aplicações do mundo real que dá para chegar.
```

## 1. ID, por favor!

Seu olho de águia percebeu que tanto os comentários quanto os usuários têm um campo `id`, lugar perfeito para começar.

Defina `decodeId` de forma que ele consiga decodificar um objeto JSON com um `id` inteiro.

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. Qual é o meu nome mesmo?

Você percebe no exemplo acima que nem todos os usuários têm um nome.

Defina `decodeName` de forma que ele consiga decodificar uma string no campo `name`, se houver uma.
Sem nome? Sem problema, basta retornar `Nothing`.
Esse decodificador nunca deve falhar.

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. Usuário? Mal te conheço!

Já estamos quase na metade para decodificar usuários, vamos terminar isso.

Defina `decodeUser` de forma que ele consiga decodificar um objeto JSON de usuário.
Não deixe de usar `decodeId` e `decodeName` em `decodeUser`.

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. Sou um comentário forte e independente

Alguns comentários em uma revisão de pull são independentes e, portanto, não têm um `pull_request_review_id`.
No entanto, a especificação diz que, nesse caso, ainda deve haver um campo `pull_request_review_id`, mas o valor deve ser `null`, o `Nothing` dos pobres.

Defina `decodePullRequestReviewId` de forma que ele consiga decodificar um inteiro no campo `pull_request_review_id`, se houver um.
Se não houver um inteiro, deve haver um `null`; se não houver um `null`, o decodificador deve falhar.

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. Um bico

Agora este campo `side` de aparência interessante.
Em uma revisão de pull, você pode comentar sobre código que foi removido (no lado `Left` da tela) ou sobre código que foi adicionado (no lado `Right` da tela).

Defina `decodeSide` de forma que ele consiga decodificar `"LEFT"` ou `"RIGHT"` no campo `side` e associá-los à variante de tipo correspondente.

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. O despertar dos links

Cada comentário tem um conjunto de links, que parece não ser consistente entre os comentários.

Defina `decodeLinks` de forma que ele consiga decodificar uma coleção de URLs no campo `_links`.
Os nomes e a quantidade de links podem variar, então dê um jeito de lidar com isso.
Os próprios links são objetos JSON que sempre devem ter um campo `href`.

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. Sim, comentários

Quase lá, vamos terminar.

Defina `decodeComment` e `decodeComments` de forma que consigam decodificar um único objeto JSON de comentário ou uma lista de comentários, respectivamente.
Não deixe de usar todas as funções definidas até agora em `decodeComment`, com exceção de `decodeName`.
Claro, `decodeComments` também deve usar `decodeComment`.

## 8. Tudo se encaixa

Falta ainda um recurso em tudo isso: conseguir enviar um novo comentário ao servidor.
Para isso, você precisa fazer o oposto de um decodificador: transformar um `Comment` do Elm em um `Value` JSON.

Defina `encodeComment` de forma que ele consiga codificar qualquer `Comment` válido.
A ordem dos campos não importa, desde que o codificador produza um valor que `decodeComment` consiga decodificar.
