# Introdução

`Complex numbers` não são complicados.
Só precisam de um nome menos assustador.

Eles são tão úteis, especialmente em engenharia e ciência, que o R inclui números complexos como tipos atômicos padrão, ao lado de integer, double, logical, character e raw.

## Noções básicas

Um número `complex` em R é um único valor.
Na prática, porém, dá para pensar nele como um par de números.
Essas partes são chamadas de "real" e "imaginária", por razões históricas infelizes.
Mais uma vez, o melhor é focar na simplicidade por trás de tudo, e não nos nomes estranhos.

Para criar números complexos a partir de dois números reais, basta adicionar o sufixo `i` à parte imaginária.

```r
2+3i
#> [1] 2+3i

typeof(2+3i)
#> [1] "complex"
```

Para criar um número complexo a partir de variáveis reais, a sintaxe acima não funciona.
Escrever `r + imi` confunde o parser, fazendo-o pensar que `imi` é um nome de variável (inexistente).

Multiplique a parte imaginária por `1i` ou use a função [`complex()`][ref-complex]:

```r
r <- 2
im <- 3

r + im * 1i
#> [1] 2+3i

# must include the `real` and `imaginary` keywords
complex(real = r, imaginary = im)
#> [1] 2+3i
```

Você pode se perguntar: por que `i` e não `j`?

A maioria dos engenheiros prefere `j`.
A maioria dos cientistas e matemáticos prefere a notação matemática `i` para _imaginário_, mas essa notação entra em conflito com o uso de `i` para significar _corrente_ na Engenharia Elétrica.

O R escolheu `i`, o Python escolheu `j`, e o Julia contornou a polêmica escolhendo `im`.
Tenha cuidado ao alternar entre linguagens de programação [STEM][wiki-STEM].

Para acessar as partes de um número complexo individualmente:

```r
z <- 2+3i

Re(z)  # real part
#> [1] 2

Im(z)  # imaginary part
#> [1] 3
```

Qualquer uma das partes pode ser zero, e os matemáticos podem então dizer que o número é "totalmente real" ou "totalmente imaginário".
No entanto, ele ainda é um número complexo em R.

```r
1.2 + 0i
#> [1] 1.2+0i

typeof(1.2 + 0i)
#> [1] "complex"

2i
#> [1] 0+2i

typeof(2i)
#> [1] "complex"
```

Você talvez já tenha ouvido que "`i` (ou `j`) é a raiz quadrada de -1".

Por enquanto, tudo o que isso significa é que a parte imaginária, _por definição_, satisfaz a seguinte igualdade:

```r
1i * 1i == -1  # more precisely, 1i * 1i == -1 + 0i
#> [1] TRUE
```

É uma ideia simples, mas leva a consequências interessantes.

## Aritmética

A maioria dos operadores usados com números de ponto flutuante e inteiros também funciona com números complexos:

```r
z1 = 1.5 + 2i
z2 = 2 + 1.5i

z1 + z2  # addition
#> [1] 3.5+3.5i

z1 * z2  # multiplication
#> [1] 0+6.25i

z1 / z2  # division
#> [1] 0.96+0.28i

z1^2  # exponentiation
#> [1] -1.75+6i

2^z1  # another exponentiation
#> [1] 0.518895+2.780422i
```

## Funções

A maioria das funções matemáticas funciona com entradas complexas.

Existem várias funções, além de `Re()` e `Im()`, com relevância especial para números complexos.

- `Conj()` simplesmente inverte o sinal da parte imaginária de um número complexo (_de + para -, ou vice-versa_).
  - Por causa de como a multiplicação de números complexos funciona, isso é mais útil do que você imagina.
- `abs(<complex number>)` tem garantia de retornar um número real sem parte imaginária (sua "magnitude"), e `Mod(<complex number>)` é um sinônimo.
- `Arg(<complex number>)` retorna o ângulo de fase em radianos.

```r
z1
#> [1] 1.5+2i

abs(z1)
#> [1] 2.5

Mod(z1)  # same as previous
#> [1] 2.5

Conj(z1)  # flip sign
#> [1] 1.5-2i

Arg(z1)
#> [1] 0.9272952
```
