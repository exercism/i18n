# Debug

YS tem uma função `DBG` embutida que pode ser útil para depurar o código da sua solução.
Ela aceita qualquer número de argumentos e os imprime no console em stderr.
Ela retorna o último argumento, então você pode usá-la inline no seu código.


Você pode usar o operador inline `.>` que é um atalho para `.DBG()`.

Veja um exemplo de arquivo de código:

```yaml
# file: program.ys

!YS-v0

defn do-it(nums):
  x =: 5

  DBG: -'my vars' x nums

  nums: .map(\(_ * x)).>
        .reverse().>
        .map(str).>
        .join(' - ')

say: do-it(3 .. 5)
```

Quando você rodar este código com `ys`, verá a seguinte saída:

```txt
>>>
"my vars"
5
(3 4 5)
<<<
>>>(15 20 25)<<<
>>>(25 20 15)<<<
>>>("25" "20" "15")<<<
25 - 20 - 15
```


## Compilação

Outra forma comum de entender um problema é olhar o código Clojure para o qual seu código YS é compilado.

Você pode fazer isso executando o interpretador de linha de comando `ys` com a flag `-c`.

Veja como o arquivo `program.ys` acima fica quando compilado:

```clojure
$ ys -c program.ys
(defn do-it [nums]
 (let [x 5]
  (DBG "my vars" x nums)
  (join
   (DBG
    (+map
     (DBG (reverse (DBG (+map nums (fn [& [_1]] (mul+ _1 x))))))
     str))
   " - ")))
(say (do-it (rng 3 5)))
```

Você pode ver claramente como o operador `.>` foi compilado para a chamada da função `DBG`.
