# Introdução

## Comentários

O Common Lisp permite que o programador escreva "comentários" que são ignorados pelo computador.
Comentários de uma linha começam com um ou mais pontos e vírgulas (`;`) e, de vez em quando, você pode ver o seguinte:

```lisp
(code...) ; => value
```

Aqui, o comentário está sendo usado para indicar qual valor o Common Lisp retorna depois de rodar o código daquela linha.

É idiomático usar um único ponto e vírgula para um comentário curto no fim de uma linha, dois para um comentário mais longo acima de um trecho de código, três para um comentário longo que descreve algo como uma função, e quatro para um comentário como um cabeçalho no topo de um arquivo-fonte.

## Cons

Todos os objetos do Common Lisp são "átomos" (valores únicos e indivisíveis) ou "conses" (construídos pela função "cons").
Um cons é formado por duas partes: o primeiro elemento e o restante dos elementos.
Por razões históricas, essas duas partes são chamadas de `car` e `cdr`.
Quando esses conses são avaliados como código, o primeiro elemento (`car`) representa a função que está sendo chamada, enquanto o restante dos elementos
(`cdr`) representa os argumentos dessa função:

```lisp
(<function> <arg1> <arg2> ... <argN>)
; ^ car ^  |        ^ cdr ^
```

## Expressões

Todo código em Common Lisp é feito de S-Expressions (Expressões Simbólicas). Para encurtar, elas são chamadas de sexprs. Toda sexpr é um átomo ou um cons. Quando as S-Expressions são avaliadas, elas retornam automaticamente algum valor, que toma o lugar da expressão. Quando você escreve suas próprias funções (usando `defun`), o último valor dentro do corpo do `defun` é retornado automaticamente:

```lisp
;; Defining a new function
(defun gimme-foo () 'foo)
;; Calling the function as an S-Expression
(gimme-foo) ; => FOO
```

## Símbolos

Os símbolos em Common Lisp são valores especiais que podem apontar para outros valores ou, no caso das _palavras-chave_, para si mesmos.
Quando o Lisp avalia símbolos, eles são substituídos pelos valores para os quais apontam:

```lisp
foo  ; => <whatever-foo-points-to>
:foo ; => :FOO
```

Repare que as palavras-chave são indicadas por dois-pontos (`:`) no início.

A citação, que é a adição de `'` antes de uma S-expression, instrui o Lisp a não avaliar essa expressão.
Ao citar `'foo` no nosso exemplo de `defun`, evitamos que o Lisp tentasse procurar (e não encontrasse) aquilo para o que `FOO` deveria apontar, retornando em vez disso o próprio valor `FOO`.
Se `FOO` não tiver sido definido em lugar nenhum do nosso programa:

```lisp
foo  ; => <ERROR! Lisp doesn't know what foo points to!>
'foo ; => FOO
```

Por enquanto, você pode encarar isso apenas como uma forma de retornar símbolos de uma função, mas vamos voltar a falar sobre citação e explorar melhor suas implicações em exercícios de conceito futuros.
