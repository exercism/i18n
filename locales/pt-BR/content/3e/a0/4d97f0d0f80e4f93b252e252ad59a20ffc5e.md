# Dicas

## Geral

- Uma comparação empacotada escreve uma **máscara**: cada lane fica com todos os bits em 1 onde a condição vale e todos em 0 onde ela não vale.
- As comparações de ponto flutuante recebem a condição como um imediato, ou você pode usar os pseudo-ops do NASM, como `cmpltps` e `cmpeqps`.
- As comparações de inteiros recebem a condição como sufixo: `pcmpgtd` para maior que com sinal, `pcmpeqd` para igualdade.
- Os blocos estão alinhados em 16 bytes, então `movaps` e `movdqa` são ambos seguros.

## 1. Sinalize as pontuações acima do limite

- `a > b` é o mesmo que `not (a <= b)` (imediato 6) ou que `b < a` (imediato 1, com os operandos trocados).
- A igualdade não deve contar como acima.

## 2. Sinalize as pontuações perfeitas

- Esta é uma igualdade de ponto flutuante direta com `cmpeqps`.
- Compare as pontuações com os valores máximos.
  Cada lane é definido onde elas coincidem.

## 3. Atribua uma classificação

- Você pode definir o limite `50.0` e os valores de classificação `1`, `2` e `3` como constantes empacotadas na memória, com quatro lanes cada.
- Você pode definir duas máscaras.
  Uma para "acima do limite", como na tarefa 1 (mas contra a constante empacotada `50.0`).
  Outra para "pontuação perfeita" (como na tarefa 2).
- A classificação básica é `1`.
  A classificação `2` deve ser selecionada para os lanes onde a máscara de acima do limite está definida.
  A classificação `3` deve ser selecionada para os lanes onde a máscara de pontuação perfeita está definida.
- As pontuações perfeitas também estão acima do limite.
  Se a máscara de acima do limite for aplicada primeiro, a máscara de pontuação perfeita a sobrescreve corretamente onde for necessário.
- `blendvps` recebe a máscara de `xmm0` e seleciona de acordo com o bit mais significativo de cada lane.
  Nos lanes onde esse bit está definido, seleciona o operando de origem.
  Nos outros, mantém o lane que já está no operando de destino.

## 4. Conte as reprovações

- Uma classificação falha quando está estritamente abaixo do limite, ou seja, `threshold > rank`.
  Você pode usar `pcmpgtd` com o limite como destino e as classificações como origem.
- Para cada bloco, `movmskps` pode ser usado para colapsar a máscara de falhas em um registrador de uso geral, pegando o bit mais significativo de cada lane.
  Esse registrador de uso geral pode ter 32 ou 64 bits.
- Você pode usar `popcnt` para contar o número de bits definidos em um registrador de uso geral.
- Pode haver mais de um bloco, então um laço é necessário para iterar sobre eles e acumular um resultado.
- Cada bloco tem 16 bytes.

## 5. Todos passaram?

- "todos passaram" é representado por um resultado com todos os bits em zero na máscara de falhas.
  Um único lane diferente de zero é um resultado falso.
- Pode haver mais de um bloco, então um laço é necessário para iterar sobre eles e acumular um resultado.
- Cada bloco tem 16 bytes.
- Um `ptest` de um registrador com ele mesmo pode ser usado para verificar se todos os bits são zero.
- Uma operação OR preserva os bits definidos e uma operação AND preserva os bits limpos.
  As duas podem ser usadas para acumular valores lógicos em um laço.
- Um flag pode ser transformado em um resultado `0/1` com `setcc`.
