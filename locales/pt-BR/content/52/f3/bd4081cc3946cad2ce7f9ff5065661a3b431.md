# Sobre

O Factor divide a E/S de stream em duas camadas. A camada inferior é a API de *stream explícito*: cada word recebe o stream como argumento. A camada superior é a API de *stream ambiente*: words curtas, de uma linha, que agem sobre o stream que estiver vinculado no momento. As duas camadas ficam sobre o mesmo [protocolo][stream-protocol]; as words da camada superior apenas consultam o stream ambiente e repassam a chamada.

## Words de stream explícito

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents` drena tudo; `stream-lines` drena e divide nos limites de linha; `stream-readln` retorna uma linha de cada vez (ou `f` no fim do stream).

## Words de stream ambiente

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

Essas são as words de E/S do dia a dia. Elas consultam o stream de entrada ou de saída atual nas variáveis dinâmicas `input-stream` / `output-stream` e repassam. É por isso que redirecionar `print` para uma string é só uma questão de vincular `output-stream` durante a execução de uma quotation.

## Construtores de stream incluídos

| word              | vocabulário                | o que ele constrói                  |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | lê uma string literal          |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | acumula as escritas em uma string   |
| `<file-reader>`   | [`io.files`][io.files]           | lê um arquivo com uma codificação   |
| `<file-writer>`   | [`io.files`][io.files]           | escreve um arquivo com uma codificação  |

Os quatro produzem disposables: eles estendem `disposable` de `destructors`, então os combinators `with-…` abaixo os liberam na saída.

## Vinculação com escopo

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

Cada uma abre um stream, o vincula como a entrada ou a saída ambiente da quotation interna e o descarta na saída, mesmo que a quotation lance uma exceção. São os combinators de destruição do `boatswains-bilge`, especializados para streams.

`with-string-writer` é uma variante especialmente limpa: constrói automaticamente um `<string-writer>` novo, roda a quotation com esse writer como a saída ambiente e retorna a string acumulada. Todo o padrão de "capturar a saída de uma quotation" é uma única word.

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## Por que o ambiente, afinal?

A vinculação por variável dinâmica é o motivo pelo qual `print` funciona em um programa que não sabe se está sendo executado de forma interativa, em um arquivo de log ou em um buffer de teste capturado. Troque a vinculação uma vez e toda word que chama `print` faz a coisa certa, sem precisar reconfigurar nada. É essa a inversão que a camada superior traz para você.

Para *implementar* um stream (definindo sua própria classe que se encaixa no protocolo), veja o conceito `streams` (ensinado em `telegraphers-tape`).
