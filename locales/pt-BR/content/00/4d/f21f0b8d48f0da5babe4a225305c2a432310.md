# Sobre

[8th](https://8th-dev.com) é uma linguagem fortemente tipada, derivada do FORTH e baseada em pilha, com sintaxe RPN.

O 8th oferece suporte às plataformas android, ios32, lin64, mac64, rpi32 e win64. Com o 8th, você usa sua plataforma preferida para escrever e testar seu código. Com um clique, você gera os executáveis *para* qualquer plataforma compatível com o 8th, *a partir de* qualquer plataforma que ele suporte!

O 8th inclui tudo o que você precisa: suporte a interface gráfica multiplataforma, criptografia forte, suporte a banco de dados SQLite, FFI, acesso REST, localização simples, acesso ao hardware, suporte a JSON, um REPL e muito mais!

A segurança não é um detalhe deixado para depois no 8th. Ele foi projetado desde o início para evitar os problemas de segurança de software mais comuns. Trabalhamos continuamente para deixá-lo ainda mais seguro.

O 8th tem um [fórum](https://8th-dev.com/forum/) e também uma documentação extensa, incluindo um [manual](https://8th-dev.com/manual.html) e um dicionário de [palavras](https://8th-dev.com/words.html) internas e de biblioteca com hyperlinks. [Compare](https://8th-dev.com/compare.html) o 8th com outras linguagens!


## Introdução rápida para quem usa linguagens “mainstream”

Se você vem do C, do Java ou da maioria das linguagens mais comuns, pode achar o 8th um pouco desconcertante. Para ajudar você a seguir pelo caminho certo, aqui estão algumas das principais diferenças entre o 8th e as linguagens “mainstream”, além de algumas dicas úteis:

* Por causa da forma como o intérprete procura os itens, você precisa declarar um var ou uma palavra antes do primeiro uso. Se não fizer isso, o resultado é a exceção can’t find ...
    
* Um var é um contêiner nomeado para outros itens. Ele não é o nome do item ao qual se refere! Assim, var x pode conter um array, mas é errado tentar acessar x como se ele mesmo fosse um array, e isso fará com que uma exceção seja lançada
    
* Você não pode declarar um var dentro (ou seja, local a) uma palavra, não tente! Você pode, no entanto, usar w:@ e w:! para acessar variáveis locais da palavra
    
* Procure escrever suas próprias palavras de modo que elas possam ser encadeadas com outras palavras. Por exemplo: as “palavras de arquivo” fazem alguma operação em um arquivo e deixam o item do arquivo na pilha (e talvez outras informações) para a próxima palavra usar

* Mantenha suas palavras curtas. Comente-as. Certifique-se, principalmente, de comentar o efeito na pilha e…

* … teste cada palavra que você escrever (de preferência enquanto escreve ou logo depois), garantindo que ela siga o SED (Diagrama de Efeito na Pilha) documentado. Isso vai ajudar você a escrever código sem bugs. Teste de novo se mudar o SED ou o código

* Consulte as palavras help e apropos para detalhes sobre a ação do SED e os efeitos colaterais de qualquer palavra sobre a qual você não tenha certeza
    
* No 8th, uma exceção é um erro fatal e fará o aplicativo encerrar (esse é o comportamento padrão). Não espere “capturar” uma exceção e tratá-la de forma eficaz
    
* Não existe ciclo de compilação e linkedição. Em vez disso, o 8th é um motor que primeiro interpreta seu código e, se necessário, o compila em tempo de execução. Ao rodar em um dispositivo, seu código é código nativo da plataforma, não bytecode rodando dentro de uma VM
