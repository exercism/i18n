# Sobre

O tipo `Result` é a solução da linguagem Elm para relatar erros e se recuperar deles. Ele é um pouco parecido com o tipo `Maybe`, mas, enquanto o `Nothing` do `Maybe` codifica algum tipo de falha, ele não diz nada sobre _por que_ ela falhou. O `Result` inclui um contexto sobre por que algo falhou.

## Definição e variável de tipo

O tipo `Result` é definido assim:

```elm
type Result error value
  = Ok value
  | Err error
```

Em resumo, esse tipo codifica o resultado de uma operação que pode dar certo e retornar um `value` ou falhar e retornar uma explicação para a falha (`error`).

Isso é conhecido como uma definição de "tipo personalizado" na terminologia do Elm.
Tipos personalizados são apresentados em detalhes em outro conceito desta trilha, mas não precisamos disso para entender o `Result` especificamente.
O `error` e o `value` em `OK value` e `Error error` representam uma variável de tipo, ou seja, podem ser qualquer tipo, como `Int`, `Bool` ou `String`.
Assim, um `Result String Int` é um valor que se espera conter um `Int` e, se houver um erro, ele será representado por uma `String`.

```elm
ageFromString : String -> Result String Int
ageFromString input =
  case String.toInt input of
    Nothing ->
      Err "That is not a number!"

    Just age ->
      if age < 0 then
        Err "Please try again after you are born."

      else if age > 135 then
        Err "Are you some kind of turtle?"

      else
        Ok age
```

## Lendo o conteúdo de um valor Result

A leitura do conteúdo de um valor `Result` é feita por meio de "pattern matching".
O pattern matching também é apresentado em mais detalhes em outro conceito, então vamos focar só em como funciona o pattern matching de um `Result`.

```elm
formatAge : Int -> String
formatAge age =
    "You are " ++ toString(age)

howOldAmI : String -> String
howOldAmI age =
    case ageFromString age of
        Err message -> message
        Ok age -> formatAge age

howOldAmI "Bananas"
    --> "That is not a number!"

howOldAmI "32"
    --> "You are 32"
```

Toda vez que você usa um valor `Result`, o compilador do Elm verifica se o seu código trata todas as possibilidades, então você nunca pode fazer pattern matching de um `Result` tratando só o caso em que há um `Ok value`.
Isso pode parecer chato no começo, mas é um dos maiores pontos fortes da linguagem Elm.
Isso evita centenas de bugs e faz da refatoração guiada pelo compilador uma experiência sem medo e gratificante.

## Manipulando o conteúdo de um valor Result

Existem várias funções para trabalhar com tipos `Result`, que geralmente são preferíveis ao pattern matching. Você pode usar `Result.map` para mapear o valor e `Result.andThen` para encadear funções que podem falhar.

O Result.map é usado para mudar o valor Ok e é útil para encadear funções sem precisar se preocupar se o Result contém um erro ou não. Se o valor for Ok, o Result.map chama a função encadeada (`formatAge` abaixo), mas, se houver um erro, o Result.map não faz nada e apenas retorna o erro.

```elm
howOldAmI : String -> Result String String
howOldAmI age =
    Result.map formatAge (ageFromString age)

howOldAmI "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.map just returns the Err)

howOldAmI "32"
    --> Ok "You are 32" (ageFromString returns Ok 32, Result.map passses this to formatAge)
```

O Result.andThen é usado para mudar o valor Ok e é útil para encadear funções sem precisar se preocupar se o Result contém um erro ou não. Ele é parecido com o Result.map, mas o Result.andThen trabalha com uma função encadeada (`formatSpecialBirthday` abaixo) que também retorna um Result. O `Result.map` também consegue fazer isso, mas acaba gerando uma camada extra de aninhamento, que o `andThen` evita de forma inteligente.

```elm
formatSpecialBirthday : Int -> Result String String
formatSpecialBirthday age =
    if age == 18 then
        Ok "Welcome to adulthood!"

    else if age == 65 then
        Ok "Welcome to retirement!"

    else
        Err "Not a special birthday"

specialBirthdayMessage : String -> Result String String
specialBirthdayMessage age =
    Result.andThen formatSpecialBirthday (ageFromString age)

specialBirthdayMessage "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.andThen just returns the Err)

specialBirthdayMessage "32"
    --> Err "Not a special birthday" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Err)

specialBirthdayMessage "18"
    --> Ok "Welcome to adulthood" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Ok)
    --> If we used Result.map, it would be OK (Ok "Welcome to audulthood"), which is annoying
```
