# Anexo às instruções

## Processo do Node

Diferente de outros exercícios, `grep.js` _não_ é importado dentro do arquivo de teste `grep.spec.js`. Em vez disso, ele será usado como se fosse um executável. Para facilitar isso, o arquivo `grep.js` foi preparado com um shebang e um comentário que explica o que isso faz:

```javascript
#!/usr/bin/env node

// The above line is a shebang. On Unix-like operating systems, or environments,
// this will allow the script to be run by node, and thus turn this JavaScript
// file into an executable. In other words, to execute this file, you may run
// the following from your terminal:
//
// ./grep.js args
//
// If you do not have a Unix-like operating system or environment, for example
// Windows without WSL, you can use the following inside a window terminal,
// such as cmd.exe:
//
// node grep.js args
//
// Read more about shebangs here: https://en.wikipedia.org/wiki/Shebang_(Unix)
```

Os testes vão iniciar um novo _processo_ do node, executando `grep.js`.

## Lendo os argumentos

Para obter os argumentos com que o _processo_ foi iniciado, use `process.argv`.

## Lendo arquivos

A função `readLines` já foi fornecida. Não é preciso transformar o caminho do arquivo para usá-la. A função `readlines` vai _resolver_ o caminho a partir do diretório de trabalho atual, que, para os processos do `grep.js`, é definido como o diretório do exercício.

## Escrevendo a saída

Para escrever a saída, use

- `console.log` para escrever no fluxo de saída padrão,
- `console.error` para escrever no fluxo de erro padrão.

Os testes consideram a execução bem-sucedida (resolvida) se nada for escrito no fluxo de erro padrão, e malsucedida (rejeitada) se algo for escrito no fluxo de erro padrão.
