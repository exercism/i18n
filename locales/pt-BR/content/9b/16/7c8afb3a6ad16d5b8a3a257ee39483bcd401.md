# Sobre

`TUPLE: child < parent extra-slots ;` declara uma classe cujas
instâncias também são instâncias de `parent`. A busca de fendas
percorre a hierarquia: a classe `child` tem todas as fendas que a
classe pai declarou, mais as suas próprias, nessa ordem.

```factor
TUPLE: vessel name tonnage ;
TUPLE: cargo-vessel < vessel capacity ;
TUPLE: tanker < cargo-vessel fuel-type ;
```

## Ordem dos argumentos de `boa`

O construtor `boa` gerado automaticamente recebe as fendas na
ordem de declaração, *primeiro as classes pai*. Para o `tanker`
acima:

```
tanker boa ( name tonnage capacity fuel-type -- tanker )
```

A ordem das fendas é fixada pela cadeia de herança. Não há como
intercalar as fendas das classes pai e filho, e reordenar as
fendas de uma classe pai quebra a compatibilidade com o `boa` de
todo descendente.

## Hierarquia de predicados

Toda declaração de `TUPLE:` gera um predicado de classe
(`name?`). Com herança, os predicados se aninham:

```factor
"Esso" 50000 100000 "diesel" tanker boa .

! all three predicates fire
dup tanker?        .   ! => t
dup cargo-vessel?  .   ! => t
dup vessel?        .   ! => t
```

`instance?` (do [`classes`][classes]) faz a mesma pergunta com a
classe como argumento de pilha, em vez de embutida no nome de uma
word: `obj tanker instance?` é `obj tanker?`:

```factor
USING: classes ;

"Esso" 50000 100000 "diesel" tanker boa
dup vessel instance? .   ! => t
```

Como a classe agora é um valor, o mesmo ponto de chamada pode
testar contra qualquer classe que receba, algo que um predicado
`name?` fixo não consegue fazer.

A relação transitiva de `is-a` também é o que o despacho de
métodos `M:` percorre: um método definido em `vessel` se aplica a
todo `cargo-vessel` e a todo `tanker`, a menos que uma sobrescrita
mais específica tenha precedência. Esse lado da história está em
[`generics`][generics].

## Herança de acessores

As words acessoras (`slot>>`, `>>slot`, `change-slot`) vêm de
[`accessors`][accessors] e não estão presas à classe para a qual
foram geradas: qualquer tupla que *tenha* a fenda pode usá-las.

```factor
USING: accessors ;

"Esso" 50000 100000 "diesel" tanker boa
[ 1 + ] change-tonnage tonnage>> .   ! => 50001
```

`change-tonnage` foi gerado para `vessel`, mas funciona em um
`tanker` porque todo `tanker` é um `vessel`.

## O que isso não é

- **Mixins** (`MIXIN:` / `INSTANCE:`): uma classe pode entrar em
  vários mixins; a relação é de muitos para muitos e serve
  principalmente para despacho genérico sobre um protocolo
  compartilhado. O conceito de streams as apresenta em contexto.
- **Classes de predicado** (`PREDICATE:`): recortam uma subclasse
  de uma classe existente por meio de um predicado de tempo de
  execução. É um recurso separado do Factor e não é abordado aqui.
