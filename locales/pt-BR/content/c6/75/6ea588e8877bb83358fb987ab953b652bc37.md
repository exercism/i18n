# Introdução

O sistema de erros do Factor tem três partes: `throw` para sinalizar um erro,
`recover` para tratar um, e `ERROR:` para definir seu próprio tipo de
erro.

## `throw`

`throw` (em [`kernel`][kernel]) lança um erro. O argumento pode ser
*qualquer* valor, uma string, um número ou uma tupla, e ele se torna o
erro que você pode inspecionar depois:

```factor
! DOCTEST: SKIP
"file not found" throw
```

`throw` não retorna; o resto da palavra atual é ignorado.

## `recover`

`recover` (em [`continuations`][continuations]) é o try/catch do Factor.
Ele recebe uma quotation *try* e uma quotation *recovery*:

```
recover ( try recovery -- )
```

Se `try` terminar sem lançar nada, `recovery` é ignorado. Se `try`
lançar um erro, o erro é empilhado na pilha e `recovery` é executado:

```factor
[ "boom" throw ] [ drop "caught" ] recover .
! => "caught"

[ "ok" ] [ drop "never runs" ] recover .
! => "ok"
```

`when`, do [`kernel`][kernel], é o companheiro natural: ele executa uma
quotation apenas quando o topo da pilha é verdadeiro:

```factor
: check-positive ( n -- )
    0 < [ "negative!" throw ] when ;
```

## `ERROR:`

`ERROR:` define uma classe de tupla *e* uma palavra que constrói uma nova
instância e a lança:

```factor
! DOCTEST: SKIP
ERROR: not-found path ;

"/missing" not-found
! throws T{ not-found { path "/missing" } }
```

Um erro sem slots é apenas `ERROR: name ;`. Chamar `name` lança uma
instância vazia. Tuplas definidas com `ERROR:` carregam um predicado de classe
`name?` que você pode usar para testar se um erro capturado era desse tipo.

## Lendo os slots de volta

Um erro capturado é apenas uma tupla, então cada slot de `ERROR:` vem com o
mesmo leitor `slot>>` gerado automaticamente que qualquer outra tupla.

```factor
! DOCTEST: SKIP
{
    T{ not-found { path "/a" } }
    T{ not-found { path "/b" } }
}
[ path>> ] map .   ! => { "/a" "/b" }
```
