# Sobre

Uma lista de palavras-chave é uma lista de [tuplas][exercism-tuples] `{key, value}`. Há duas formas de escrever uma lista de palavras-chave:

```elixir
# concise
[month: "April", year: 2018]

# explicit
[{:month, "April"}, {:year, 2018}]
```

## As chaves precisam ser átomos

Nem toda lista de tuplas de 2 elementos é uma lista de palavras-chave. As chaves precisam ser átomos:

```elixir
Keyword.keyword?([{"month", "April"}])
# => false
```

Se você quiser usar caracteres diferentes de letras, números e `_` na chave, precisa envolvê-la em aspas. Isso, porém, não a transforma em uma string: ela continua sendo um átomo.

[//]: # (elixir-formatter-disable-next-block)

```elixir
Keyword.keyword?(["day of week": "Monday"])
# => true
```

## As chaves podem se repetir

As chaves em uma lista de palavras-chave podem se repetir, e os [pares chave-valor são ordenados][keyword-duplicate-keys-and-ordering]. Ao tentar obter um único valor de uma determinada chave, você recebe o primeiro valor, e qualquer outro valor sob a mesma chave será ignorado silenciosamente.

```elixir
list = [month: "April", month: "May"]

Keyword.get_values(list, :month)
# => ["April", "May"]

Keyword.get(list, :month)
# => "April"
```

As listas de palavras-chave também suportam o [_comportamento Access_][access-behaviour].

```elixir
list[:month]
# => "April"
```

## Listas de palavras-chave como opções

As características das listas de palavras-chave fizeram delas o mecanismo padrão para passar opções a funções em Elixir.

Quando você aprendeu sobre `if`, viu uma sintaxe especial mais curta:

```elixir
if age >= 16, do: "beer", else: "no beer"
```

Pode parecer que `if` aceita dois argumentos, mas o par `do:` e `else:` é, na verdade, um único argumento: uma lista de palavras-chave. O mesmo código poderia ser escrito assim:

[//]: # (elixir-formatter-disable-next-block)

```elixir
if age >= 16, [do: "beer", else: "no beer"]
# or
if age >= 16, [{:do, "beer"}, {:else, "no beer"}]
```

O uso de listas de palavras-chave como opções de função é tão comum que o Elixir permite que você [omita os colchetes quando a lista de palavras-chave é o último argumento][keyword-call-syntax] passado para uma função.

Como tuplas, listas, mapas e outros são tratados da mesma forma que chamadas de função na sintaxe do Elixir, essa propriedade também está disponível para eles.

```elixir
[1, 2, three: 3]
# => [1, 2, {:three, 3}]
```

## Casamento de padrões

Para fazer casamento de padrões em uma lista de palavras-chave usando a sintaxe concisa, você precisaria especificar todas as chaves na ordem correta. Isso faz com que o casamento de padrões seja uma escolha improvável para trabalhar com listas de palavras-chave. Em vez disso, use o módulo [`Keyword`][keyword] ou o [_comportamento Access_][access-behaviour].

```elixir
[month: month] = [month: "April", year: 2018]
# => ** (MatchError) no match of right hand side value: [month: "April", year: 2018]

[year: year, month: month] = [month: "April", year: 2018]
# => ** (MatchError) no match of right hand side value: [month: "April", year: 2018]
```

## Listas de palavras-chave vs mapas

|                  | Lista de palavras-chave       | Mapa                                |
| ---------------- | ----------------------------- | ----------------------------------- |
| Tipo de chave    | Átomos                        | Qualquer, pode ser misturado em um mesmo mapa |
| Chaves duplicadas | Sim                          | Não                                 |
| Chaves ordenadas | Sim                           | Não                                 |
| Acesso           | `list[:key]`, `Keyword.get/2` | `map.key`, `map[:key]`, `Map.get/2` |
| Tempo de acesso  | Linear                        | Logarítmico                         |
| Casamento de padrões | Não é muito útil          | Útil                                |

Tempo de acesso mais rápido, tipo de chave flexível e casamento de padrões útil fazem dos mapas a escolha padrão na maioria dos casos.

Use listas de palavras-chave quando você não tem muitos dados, mas precisa de chaves duplicadas ou de chaves em uma ordem específica.
