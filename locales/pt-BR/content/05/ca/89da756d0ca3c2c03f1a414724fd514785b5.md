# Testes

Cada exercício vem com um conjunto de testes de unidade e tudo o que é preciso para compilar e rodar esses testes.
A implementação é você que faz.

## Rodando os testes

Abra um terminal na pasta do exercício e rode:

```
make
```

Isso compila a sua solução e os testes e, em seguida, roda os testes.
Rode de novo sempre que alterar a sua solução.

Se você tiver a [Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally), pode usar este comando, que também roda o `make`:

```
exercism test
```

Para remover os arquivos criados pelo build, rode `make clean`.

### Sem o make

Se você não tiver o `make` (no Windows, por exemplo), pode compilar e rodar os testes diretamente.
Para o exercício "Bob":

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

Depois, rode os testes no Linux ou no macOS:

```
./run_tests
```

Ou no Windows:

```
.\run_tests
```

## Trabalhando em um exercício

Os arquivos de cada exercício recebem o nome dele.
Para o exercício "Bob":

| Arquivo          | Conteúdo                                                          |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90`        | um esboço da solução, pronto para você completar                  |
| `bob_test.f90`   | os testes                                                         |
| `TesterMain.f90` | a biblioteca de testes                                            |
| `Makefile`       | instruções para o `make`                                          |
| `CMakeLists.txt` | instruções para o [CMake](#using-cmake-instead), que é opcional   |

Você só precisa editar o arquivo da solução.

Trabalhar em cada exercício é um processo de repetir estes passos até que todos os testes passem:

- Corrigir os erros de compilação e depois rodar os testes para ver quais falham.
- Implementar só o suficiente para fazer o próximo teste que falha passar.
- Refatorar a sua implementação para melhorar a legibilidade, reduzir duplicação etc.
- Rodar os testes de novo e passar para o próximo teste que falha.

Uma mensagem é impressa para cada teste que falha, seguida de um resumo.
Se algum teste falhar, o `make` termina com um erro.

Cada teste tem um comentário descrevendo o teste e, em seguida, o teste em si, começando com `call assert_equal`, por exemplo.

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Para desabilitar um teste, basta comentá-lo com um `'!'`, por exemplo

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## Usando o CMake em vez do make

Você não precisa do CMake, mas ele pode ser útil se você trabalhar em uma IDE como o Visual Studio ou o Xcode, ou usar um compilador diferente do GFortran.

A pasta do exercício precisa manter o nome original, porque o CMake usa esse nome para encontrar os arquivos-fonte.
Comece na pasta do exercício:

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

Depois de alterar a sua solução, só os dois últimos comandos são necessários.

**Observação:** rode sempre o `cmake` a partir de uma pasta separada, como `build`.
Rodar `cmake .` na pasta do exercício substitui o `Makefile` que vem com o exercício.

O CMake escolhe um gerador adequado ao seu sistema.
Para escolher outro, use a opção `-G`, por exemplo `cmake -G Xcode ..`.
Rode `cmake --help` para listar os geradores que você pode usar.
Com o Visual Studio ou o Xcode, rode os testes com `ctest -V -C Debug`.

Se a pasta do seu exercício não tiver um `Makefile`, ela foi baixada antes de esses arquivos serem adicionados aos exercícios.
Você ainda pode usar o CMake.
