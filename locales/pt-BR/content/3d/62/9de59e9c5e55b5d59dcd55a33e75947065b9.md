# Iteradores personalizados

```sather
   markers!(once spacing : INT, once count : INT) : INT is
      loop
         yield spacing * 1.upto!(count);
      end;
   end;
```

| | rotina | iterador |
| --- | --- | --- |
| nome | `foo` | `foo!` |
| entrega um valor | `return` | `yield` |
| termina | `return`, ou o fim | `quit`, ou se esgotar |
| pode ser chamado | em qualquer lugar | só dentro de um `loop` |
| mantém sua posição | não | sim |

## yield

O `yield` entrega um valor e suspende a execução. Tudo é restaurado na
próxima volta: as variáveis locais, a posição nos laços do próprio iterador
e as posições de quaisquer iteradores que ele mesmo esteja chamando.

Um `yield` dentro de laços aninhados é retomado no mais interno, e é isso
que torna simples escrever uma travessia por algo aninhado:

```sather
   all_cells!(grid : ARRAY{ARRAY{INT}}) : INT is
      loop
         row ::= grid.elt!;
         loop
            yield row.elt!;
         end;
      end;
   end;
```

## quit

Encerra o iterador e, com ele, o laço que o chamou. Não carrega valor
nenhum: um `quit` não é um último resultado, é o aviso de que não há nenhum.

Um iterador com tipo de retorno precisa entregar um valor a cada vez que
cede; é com `quit` que ele se recusa a fazê-lo.

## once

```sather
   markers!(once count : INT) : INT is
```

Um argumento `once` é avaliado quando o laço começa e fica guardado. Um
argumento comum é reavaliado a cada volta, o que faz diferença quando a
expressão passada contém outra chamada de iterador:

```sather
   loop
      #OUT + TRAIL::markers!(sizes.elt!);     -- a new count every turn
   end;
```

Marque os argumentos como `once`, a menos que você queira especificamente
esse comportamento. A biblioteca inteira faz assim.

## self e iteradores

Um iterador pode ser chamado em um objeto, e então `self` é esse objeto. Seu
estado pausado pertence ao local da chamada, não ao objeto, então dois laços
percorrendo o mesmo objeto não interferem um no outro.

## Quando escrever um

Escreva um iterador quando a resposta for uma sequência e quem chama deve
decidir quanto dela pegar. Parar cedo não custa nada, e nada é construído
sem ser usado, enquanto uma rotina que retorna um `ARRAY` precisa construir
tudo primeiro.
