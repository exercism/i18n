# Sobre bits

Os dígitos binários, em última análise, correspondem diretamente aos transistores da sua CPU ou da sua memória RAM, e ao fato de cada um estar "ligado" ou "desligado".

A manipulação de baixo nível, chamada informalmente de "bit-twiddling", é especialmente importante em linguagens de sistemas.

Linguagens de nível mais alto, como Kotlin, normalmente abstraem a maior parte desse detalhe.
No entanto, há uma gama básica de operações em nível de bits [disponível][ref-bitwise].

~~~~exercism/note

Isso distrai visualmente, então a maior parte das ocorrências dessa função foi removida, e os resultados são representados com a notação `0b`.

## Operações de deslocamento de bits

Os tipos `Int` ou `Long`, tanto com sinal quanto sem sinal, podem ser representados como uma string de 1s e 0s, e manipulados como uma sequência de bits.

Talvez de forma surpreendente, os tipos `Byte` ou `Short` não são compatíveis com a maioria das operações bit a bit em Kotlin.
Todos os exemplos abaixo usam inteiros de 32 bits (`Int` ou `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

Os deslocamentos de bits movem tudo para a esquerda ou para a direita em um número especificado de posições.
Alguns bits caem de uma ponta, e a outra ponta é preenchida com zeros ou uns.

- Deslocamento à esquerda com `shl`: preenchimento com zeros.
- Deslocamento à direita com `shr` ou `ushr`: preenchimento com zeros para números positivos (veja a seção mais adiante sobre números negativos).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Cada deslocamento à esquerda dobra o valor, e cada deslocamento à direita o divide pela metade (sujeito a truncamento).
Isso fica mais óbvio na representação decimal:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Esse tipo de deslocamento de bits é muito mais rápido do que a aritmética "de verdade", o que torna a técnica muito popular na programação de baixo nível.

### Deslocamento de bits com números negativos

Com _números negativos_, precisamos ter um pouco mais de cuidado.

Valores negativos são armazenados na forma de [complemento de dois][wiki-2complement], o que significa que o bit mais à esquerda é 1.
Nenhum problema para um deslocamento à esquerda, mas, ao deslocar à direita, como preenchemos os bits mais à esquerda?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

O operador [`shr`][ref-shr] realiza um [deslocamento aritmético][wiki-arithmetic], preservando o bit de sinal.

O operador [`ushr`][ref-ushr] realiza um [deslocamento lógico][wiki-logical], preenchendo com zeros como se o número não tivesse sinal.

## Lógica bit a bit

Vimos no [conceito de Boolean][concept-booleans] que os operadores `&&` (and), `||` (or) e `!` (not) são usados com valores booleanos.

Existem operadores equivalentes `and`, `or` e `xor` ([ou exclusivo][wiki-xor]) para comparar os bits de dois inteiros, e uma função `inv` (inversão) para inverter todos os bits.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
