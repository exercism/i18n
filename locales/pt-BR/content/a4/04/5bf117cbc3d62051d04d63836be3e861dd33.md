# Sobre

Elm é uma linguagem encantadora para construir aplicações web confiáveis.
Ela tem mensagens de erro amigáveis, ótimo desempenho, assets pequenos e nenhuma exceção em tempo de execução.

Provavelmente a parte mais famosa e mais amplamente copiada do Elm é The Elm Architecture, que é um padrão simples para estruturar aplicações web e é como todas as aplicações web em Elm são escritas.

A ideia central é que o seu código é construído em torno de um `Model` do estado da sua aplicação, de uma forma de `update` desse modelo e de uma forma de `view` desse modelo.

O `Model` contém o estado da aplicação: todos os dados de que a aplicação precisa.
Pode ser de qualquer tipo, mas em qualquer aplicação útil costuma ser um [record][record].
Se você imaginar uma aplicação simples com uma caixa de texto e um texto mostrando o inverso desse texto, o modelo ficaria assim.
Você também pode ver esse exemplo no [Elm Guide][elm-guide-text-fields].

```elm
type alias Model =
  { text : String
  }
```

`update` é uma função que é chamada com uma `Msg` quando há uma mudança (como o usuário clicar em um botão).
Ela recebe a `Msg` e o `Model` atual e retorna um novo `Model`.
A `Msg` pode ser de qualquer tipo, mas costuma ser um [custom type][custom-type].

```elm
type Msg
  = TextChanged String

update : Msg -> Model -> Model
update msg model =
  case msg of
    TextChanged newText ->
      { model | text = newText }
```

Como em todos os custom types, as variantes da `Msg` podem incluir quanta informação arbitrária precisarem.
No exemplo acima, a variante `TextChanged` inclui uma `String`.

`view` é uma função que retorna HTML para mostrar ao usuário no navegador.
Ela recebe o `Model` atual e retorna um `Html Msg` (o tipo que Elm usa para representar HTML).
Cada elemento HTML (por exemplo, `<div>`) tem uma função Elm correspondente (`Html.div`), no pacote `Html`.
Cada uma dessas funções recebe dois parâmetros: o primeiro é uma lista de atributos (dos pacotes `Html.Attributes` e `Html.Events`) e o segundo é uma lista de elementos filhos (funções do pacote `Html`).
Há também uma função `text` que representa conteúdo HTML do tipo string, que só recebe um parâmetro do tipo string, mas fora isso é usada da mesma forma que todas as outras funções / elementos do pacote `Html`.

A função `view` pode especificar que certos eventos, como clicar em um botão ou editar o texto em uma caixa de texto, resultam na criação de uma `Msg`, que o Elm Runtime vai usar para chamar a função `update`, modificar o `Model` e gerar HTML atualizado.
No código abaixo, isso acontece com `Html.Events.onInput TextChanged`.

```elm
view : Model -> Html Msg
view model =
  Html.div []
    [ Html.input
      [ Html.Attributes.placeholder "Text to reverse"
      , Html.Attributes.value model.text
      , Html.Events.onInput TextChanged
      ]
      []
    , Html.div [] [ Html.text (String.reverse model.text) ]
    ]
```

`Html.Events.onInput` espera receber uma função (`String -> Msg`) que ele vai usar para criar a `Msg`.
Eventos diferentes esperam funções diferentes, dependendo da informação que podem fornecer; por exemplo, `Html.Events.onCheck` (para caixas de seleção) espera `Bool -> Msg` e `Html.Events.onClick` espera apenas uma `Msg`.

A linguagem Elm é pura e funcional, e nenhuma mutação é possível, então o Elm Runtime cuida de todas as coisas que mudam.
Você pode ver todos os diferentes [Elementos HTML][html-elements], [Atributos de Elementos][element-attributes] e [Eventos HTML][html-events] no registro de pacotes do Elm.

Existem 4 "níveis" de aplicação web que você pode escrever em Elm, que ficam progressivamente mais poderosos e mais complicados (embora Elm continue sendo uma linguagem e um ecossistema deliciosamente simples).
Todos eles estão definidos no [pacote Browser][browser-package]:

- [sandbox][browser-sandbox]: reagir à entrada do usuário, como botões e caixas de seleção
- [element][browser-element]: conversar com o mundo exterior, usando HTTP e interoperabilidade com JavaScript
- [document][browser-document]: controlar o `<title>` e o `<body>` de uma página web
- [application][browser-application]: criar aplicações completas de página única que lidam com roteamento / mudanças de URL

Este conceito usa o [sandbox][browser-sandbox], por ser o mais simples (e, como é um sandbox, é relativamente fácil trabalhar com o editor online do Exercism).
O módulo de entrada de um programa Elm precisa se chamar `Main`, e a função que cria a aplicação precisa se chamar `main`, como abaixo.

```elm
import Browser
import Html exposing (Html, Attribute, div, input, text)
import Html.Attributes exposing (placeholder, value)
import Html.Events exposing (onInput)

main =
  Browser.sandbox { init = init, update = update, view = view }

init : Model
init =
  { text = "" }

-- Add Model, Msg, update and view here
```

Já vimos as funções `update` e `view`, e o [sandbox][browser-sandbox] exige também uma função `init`, para retornar o estado inicial do `Model`.
