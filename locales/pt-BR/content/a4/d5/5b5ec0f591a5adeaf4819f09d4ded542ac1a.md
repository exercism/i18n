# Instruções

Este problema é modelado a partir do escalonamento estático não preemptivo de sistemas operacionais de tempo real, mas também é semelhante ao Job-Shop Scheduling Problem (JSP) com apenas um recurso. Este problema assume que todas as tarefas são conhecidas estaticamente. Em outras palavras, os tempos de liberação de todas as tarefas deste problema são conhecidos no início do programa. Na prática, o tempo de liberação das tarefas não é conhecido no início de um programa e pode ser gerado a qualquer momento por meio de E/S, interrupções etc.

Dada uma lista de tarefas com parâmetros, determine um escalonamento no qual as tarefas possam ser executadas em sequência, sem sobreposição. Como o problema é modelado a partir do escalonamento de processos de um RTOS, vamos assumir que existe um tempo diferente de zero necessário entre as tarefas, também conhecido como sobrecarga de troca de contexto. Existem dois tipos diferentes de tarefas: periódicas e dinâmicas. Os dois tipos têm um parâmetro de ID de tarefa, que é uma string usada para diferenciar as diferentes tarefas na lista de tarefas.

Uma **tarefa periódica** é definida como uma tarefa que é executada periodicamente. Em outras palavras, a tarefa será executada uma vez a cada T segundos, em que T é definido como o período.
Uma tarefa periódica é definida pelos seguintes parâmetros:
* Tempo de início - momento em que começa a primeira repetição, ou instância, da tarefa
* Período - tempo entre o início das repetições da tarefa
* Tempo de execução - tempo que cada repetição roda
* Tempo de término - momento em que a tarefa inteira deixa de ser escalonada

Uma **tarefa dinâmica** é definida como uma tarefa que é executada apenas uma vez.
Uma tarefa dinâmica é definida pelos seguintes parâmetros:
* Tempo de liberação - primeira vez em que a tarefa PODE ser escalonada (NÃO é o mesmo que o tempo de início)
* Tempo de execução - tempo que a tarefa roda
* Prazo final - momento até o qual a tarefa precisa terminar a execução

A função a ser implementada tem duas entradas. A primeira entrada é uma lista de instâncias de `RealTimeTask`. As instâncias de `RealTimeTask` serão passadas como uma instância de `PeriodicRealTimeTask` ou de `DynamicRealTimeTask`, com todos os parâmetros da tarefa como números inteiros. A função interna `isinstance()` do Python pode ser usada para diferenciar as duas tarefas na lista. A ordem da lista é irrelevante; olhe apenas os parâmetros das tarefas. A segunda entrada é um único número inteiro que especifica a sobrecarga de troca de contexto. A sobrecarga de troca de contexto será sempre um número inteiro não negativo.

A saída deve ser um dicionário em que as chaves são o ID da tarefa das instâncias de `RealTimeTask` e o valor deve ser uma lista de tuplas de dois elementos. O formato das tuplas de dois elementos é (tempo de início, tempo de término). Tarefas dinâmicas devem conter apenas uma tupla de dois elementos na lista, enquanto tarefas periódicas podem conter mais de uma. A ordem das tuplas de dois elementos na lista não importa. Se não for possível criar um escalonamento válido a partir da lista de tarefas com a sobrecarga de troca de contexto dada, levante uma exceção `NoRtosStaticScheduleProducible`. Observe que os resultados do modelo Z3 para as variáveis precisarão ser convertidos para int antes de serem exibidos. Se o resultado do modelo Z3 for do tipo `IntNumRef`, o método de classe `as_long()` pode ser usado para converter para um número inteiro.

Uma função adicional é fornecida para permitir que você visualize a ordem sequencial das tarefas. Essa função também pode ser habilitada para casos de teste individuais definindo o argumento nomeado `plot` como `True` na função `check()`. Um gráfico de barras horizontais quebradas é usado para representar e rotular cada tarefa. Para usar essa função, é preciso instalar a biblioteca *matplotlib* do Python. Os detalhes de instalação da *matplotlib* estão [aqui](https://matplotlib.org/stable/users/installing.html).
