# Sobre

Um [laço `for`][for-statement] permite executar código repetidamente em um laço até que uma condição seja satisfeita.

```csharp
for (int i = 0; i < 5; i++)
{
    System.Console.Write(i);
}

// => 01234
```

Um laço `for` é composto de quatro partes:

1. O inicializador: executado uma vez antes de entrar no laço. Normalmente usado para definir variáveis usadas dentro do laço.
2. A condição: executada antes de cada iteração do laço. O laço continua a executar enquanto isso for avaliado como `true`.
3. O iterador: executado após cada iteração do laço. Normalmente usado para modificar (muitas vezes incrementar ou decrementar) as variáveis do laço.
4. O corpo: o código que é executado a cada iteração do laço.

## Laços for vs laços foreach

Em geral, [concept:csharp/foreach-loops]() são preferíveis aos laços `for` pelos seguintes motivos:

- É garantido que um laço `foreach` itere sobre _todos_ os valores. Com um laço `for`, é fácil deixar elementos de fora, por exemplo, por causa de um erro de um a mais ou um a menos.
- Um laço `foreach` é mais _declarativo_: seu código comunica _o que_ você quer que ele faça, em vez de um laço `for`, que comunica _como_ você quer fazer.
- Um laço `foreach` é à prova de erros, enquanto com laços `for` é fácil cometer um erro de um a mais ou um a menos.
- Um laço `foreach` funciona com todos os tipos de coleção, incluindo aqueles que não permitem usar um indexador para acessar elementos.

Para garantir que um laço `foreach` itere sobre _todos_ os valores, o compilador não permite atualizar uma coleção dentro de um laço `foreach`:

```csharp
char[] vowels = new [] { 'a', 'e', 'i', 'o', 'u' };

foreach (char vowel in vowels)
{
    // This would result in a compiler error
    // vowel = 'Y';
}
```

Um laço `for` tem algumas vantagens sobre um laço `foreach`:

- Você pode começar ou parar no índice que quiser.
- Você pode usar qualquer condição de término (Boolean) que quiser.
- Você pode pular elementos personalizando o incremento da variável do laço.
- Você pode processar coleções de trás para frente, contando de forma decrescente.
- Você pode usar laços `for` em cenários que não envolvem coleções.
