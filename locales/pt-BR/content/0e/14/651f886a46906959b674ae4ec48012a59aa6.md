# Testes

Os testes de um projeto Elm ficam no subdiretório `tests/` desse projeto.
O conjunto de testes de cada exercício pode ser executado a partir do diretório raiz do exercício.

```bash
$ cd ~/exercism/elm/hello-world
$ elm-test
```

## Fique de olho nas mudanças

Execute os testes de novo automaticamente quando você salvar as alterações:

```bash
$ elm-test --watch
```

## Fluxo de desenvolvimento guiado por testes

Na maioria dos exercícios, os testes já estão escritos no arquivo `tests/Tests.elm`.
Seu objetivo é fazê-los passar, escrevendo o código necessário
no arquivo `src/<exercise>.elm`.
Foque no primeiro teste que falhar, corrija-o,
depois remova ou comente o próximo trecho `skip <|` no arquivo de testes e repita
até que todos os testes passem.

## Travou?

Seu primeiro objetivo é fazer seu código compilar, mesmo com `Debug.todo` nele.
Se você sentir que não sabe como fazer algo,
muitas vezes é útil extrair essa parte para uma função própria ainda não implementada.

```elm
complexOperationOnMultipleStrings : List String -> List String
complexOperationOnMultipleStrings allStrings =
    List.map complexOperation allStrings


complexOperation : String -> String
complexOperation input =
    Debug.todo "Extracted operation into its own function"
```

Adicionar uma anotação de tipo nessa função extraída
vai ajudar tanto o seu raciocínio quanto o compilador a lhe dar mensagens de erro melhores.

## Limpando o seu código

Considere executar o [`elm-format`](https://github.com/avh4/elm-format) no seu código antes de enviá-lo
e até configurá-lo no seu editor de texto para formatar automaticamente ao salvar.
