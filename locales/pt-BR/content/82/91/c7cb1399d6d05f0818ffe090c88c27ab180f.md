# Sobre

As [compreensões][for] fornecem um recurso para transformar _enumeráveis_ de forma fácil e declarativa. Elas são _açúcar sintático_ para iterar sobre enumeráveis em Elixir.

[//]: # (elixir-formatter-disable-next-block)

```elixir
for s <- ["a", "b", "hello", "c"], # 1. generator
  String.length(s) == 1,           # 2. filter
  into: "",                        # 3. collectable
  do: String.upcase(s)

# => "ABC"
```

Uma compreensão tem três partes:

1. _Geradores_:
   - Valores enumerados a partir de estruturas que implementam o protocolo [_Enumerable_][enumerable].
   - Expressões de correspondência de padrões para desestruturar valores enumerados.
2. _Filtros_: condições Boolean, usadas para selecionar quais valores enumerados usar ao criar os novos valores.
3. _Coletáveis_: uma estrutura que implementa o protocolo [_Collectable_][collectable], usada para coletar os novos valores.

Existem compreensões de uma linha e de várias linhas. Quando mais de um gerador é usado, um [produto cartesiano][cartesian-product] dos valores gerados é enumerado. Isso significa que cada valor gerado pelo primeiro gerador será combinado uma vez com cada valor gerado pelo segundo gerador.

```elixir
for n <- [0, 1, 2, 3], do: n + 1
# => [1, 2, 3, 4]

for x <- [0, 1],
    y <- [0, 1] do
  {x, y}
end

# => [{0, 0}, {0, 1}, {1, 0}, {1, 1}]
```

O valor dentro do bloco é inserido no _coletável_ **para cada valor gerado** a partir do _enumerável_.

```elixir
for _ <- [1, 2, 3], do: :a
# => [:a, :a, :a]
```

A correspondência de padrões pode ocorrer na compreensão, seja no lado esquerdo do `<-` ou em uma linha própria.

```elixir
for {atom, str} <- [a: "string"], do: str
# => ["string"]

for pair <- [a: "string"],
    {atom, str} = pair do
  str
end

# => ["string"]
```
