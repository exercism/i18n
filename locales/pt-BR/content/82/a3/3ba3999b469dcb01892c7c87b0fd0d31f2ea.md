# Classes imutáveis

```sather
immutable class BEARING is
   readonly attr degrees : INT;
   create(d : INT) : SAME is
      b : SAME;
      return b.degrees(d);
   end;
end;
```

## O que muda

| | classe comum | classe imutável |
| --- | --- | --- |
| atribuição | compartilha o objeto | copia o valor |
| pode ser void | sim | não |
| `attr` de escrita | `x.a := v` | `x := x.a(v)` |
| `new` | sim | não; `x : SAME` já existe |

Um objeto imutável não pode ser void, então `void(b)` é sempre falso e nenhuma
rotina sobre ele pode falhar por falta de um objeto. Isso elimina toda uma
categoria de erro, ao custo de nunca poder dizer "ainda não há um rumo".

## Onde o valor fica

O valor fica armazenado onde a variável está (dentro de outro objeto ou na
pilha), em vez de ser alcançado por meio de uma referência. Assim, um
`ARRAY{BEARING}` guarda os próprios rumos, e não ponteiros para eles, o que
ocupa menos espaço e é mais rápido de percorrer.

O custo é a cópia: passar um objeto imutável grande o copia todas as vezes.
Por isso, o melhor é mantê-los pequenos.

## As rotinas de atributo

`readonly attr degrees : INT` fornece duas rotinas:

```sather
   b.degrees          -- read: INT
   b.degrees(90)      -- answer a new BEARING with degrees changed
```

A segunda existe mesmo sob `readonly`, porque não muda nada: ela constrói um
novo valor. Sob um `attr` comum, ela é pública; sob `private attr`, não.

## is_eq e str

Nenhum dos dois vem pronto. Escreva `is_eq` para `=`, e `str` para que o objeto
possa ser impresso e concatenado a strings:

```sather
   is_eq(other : SAME) : BOOL is return degrees = other.degrees; end;
   str : STR is return degrees.str + " degrees"; end;
```

Escrever `str` faz a classe se conformar com `$STR`, que é o que permite que
`+` e `#OUT` a aceitem.

## As embutidas

`INT`, `BOOL`, `CHAR`, `FLTD` e `TUP` são todas classes imutáveis. Elas não têm
nada de especial: são escritas em Sather na biblioteca do mesmo jeito e se
comportam como se comportam pelos motivos acima.
