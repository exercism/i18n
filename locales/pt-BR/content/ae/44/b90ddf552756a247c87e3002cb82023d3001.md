# Listas

Um `ARRAY` é fixo. Ele é criado com um tamanho e continua com esse tamanho: não dá para acrescentar nada a ele nem remover nada dele.

O caderno de um detetive não é assim. As pistas aparecem uma de cada vez e são riscadas quando são descartadas. Para isso, o que você quer é uma **lista**.

```sather
   notes ::= #LIST{STR};
   notes.append("muddy boots");
   notes.append("broken window");
   notes.size                   -- 2
```

`LIST{T}` guarda valores do tipo `T` em ordem, como um array, e cresce e encolhe conforme você pede.

## Muda no lugar

O `append` altera a lista em que foi chamado e não retorna nada:

```sather
   notes.append("muddy boots");        -- yes
   notes := notes.append("muddy boots");   -- no: append answers nothing
```

Isso é diferente de `FMAP` e `FSET`, em que toda mudança precisava ser atribuída de volta. Uma `LIST` é um objeto comum, como um `SCOREBOARD`: passe-a para uma rotina e a rotina consegue alterar a sua.

## Leitura e escrita

Colchetes, contando a partir do zero, exatamente como em um array:

```sather
   notes[0]                     -- "muddy boots"
   notes[1] := "smashed window";
   notes.size                   -- how many
   notes.is_empty               -- true when there are none
```

## Remover

`remove_index` tira uma posição, e tudo depois dela sobe uma posição:

```sather
   notes.remove_index(0);       -- the first clue is struck out
```

Então as posições não são permanentes. A posição de uma pista muda quando uma pista anterior é removida, o que vale lembrar antes de guardar uma.

## Percorrer a lista

`elt!` funciona, como funciona em um array:

```sather
   loop
      #OUT + notes.elt! + "\n";
   end;
```

## As chaves

`LIST{STR}` é uma lista de strings, `LIST{INT}` uma lista de números. É uma classe genérica, exatamente como a que você escreveu em `lost-property`, e agora você consegue ler a da própria biblioteca do mesmo jeito.
