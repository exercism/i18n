# Exceções

Algumas rotinas não conseguem responder. Pedida uma prop que não está na mesa, `count_of` não tem número para dar, e zero seria mentira, porque zero quer dizer “não temos nenhuma dessas”, e não “não existe tal coisa”.

Uma **exceção** é como uma rotina diz que não consegue responder.

## Lançando

`raise` abandona a rotina e entrega um valor a quem a chamou.

```sather
   count_of(props : FMAP{STR,INT}, prop : STR) : INT is
      if ~props.has_ind(prop) then
         raise "Unknown prop: " + prop;
      end;
      return props.get(prop);
   end;
```

Nada depois de um `raise` é executado. A rotina não retorna, então não há resposta para verificar nem como quem chamou continuar como se houvesse.

O valor lançado normalmente é uma string dizendo o que deu errado.

## Capturando

`protect` executa um trecho de código, preparado para que ele lance uma exceção.

```sather
   protect
      taken ::= count_of(props, prop);
      #OUT + "There are " + taken;
   when $STR then
      #OUT + "Cannot: " + exception.str;
   end;
```

Se nada for lançado, a parte depois de `protect` roda e o braço `when` é ignorado. Se algo for lançado, o resto da parte `protect` é abandonado e o `when` correspondente roda em seu lugar.

`when $STR then` captura uma string lançada. `exception` é o valor que foi lançado, disponível dentro do braço.

## Passando adiante

Uma rotina que não captura uma exceção não precisa fazer nada a respeito. Ela viaja para fora, passando por cada chamador, até que algo a capture:

```sather
   take_one(props : FMAP{STR,INT}, prop : STR) : INT is
      -- If this raises, take_one raises too. Nothing here says so.
      have ::= count_of(props, prop);
      ...
   end;
```

É esse o ponto das exceções. A rotina que percebe o problema e a rotina que sabe o que fazer a respeito normalmente não são a mesma rotina, e tudo o que está no meio pode simplesmente ignorar.
