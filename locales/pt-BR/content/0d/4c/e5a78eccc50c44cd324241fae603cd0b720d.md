# Instruções

A gerência está começando a aplicar princípios darwinianos ao projeto Remote Control Car [exercise:csharp/remote-control-competition](). As pessoas desenvolvedoras foram divididas em duas equipes, _Red_ e _Blue_, e cada uma tem a tarefa de melhorar o design de forma independente da outra. Elas não precisam se preocupar com as decisões de design da outra equipe.

Você recebeu a tarefa de dar uma olhada no código e ver qual é a melhor forma de combinar os dois esforços para fins de teste.

## 1. Encontre uma forma mais adequada de isolar o código das duas equipes

Use `namespaces` para expressar melhor a intenção do código.

No momento, tipos importantes como `Motor` e `Telemetry`, sem falar do próprio `RemoteControlCar`, estão aninhados dentro de uma classe estática externa, `<Color>RemoteControlCarTeam`. O único propósito da classe externa é permitir que tipos com o mesmo nome coexistam no programa. Isso é melhor expresso com o uso de um namespace. Você vai ver no próximo exercício que, para esses fins, um `namespace` tem vantagens sobre uma `static class`.

## 2. Simplifique o sistema de nomes

Embora a gerência insista que as equipes se chamem `RedRemoteControlCarTeam` e `BlueRemoteControlCarTeam` nas definições, esses nomes são bem complicados na hora de referenciar as equipes. Encontre uma forma de usar os identificadores mais curtos `Red` e `Blue` ao construir os carros.
