# Dicas

## Geral

- Dê uma olhada no [Guia do Elm][elm-guide], que tem um exemplo prático bem legal e parecido.

## 1. Defina os tipos Model e Msg da aplicação e escreva a função init

- O `Model` contém o estado da aplicação: todos os dados de que a aplicação precisa.
- Ele deve ser um [record][record].
- Esta aplicação só precisa de uma `String` para guardar o texto na caixa de texto (os testes exigem que ela se chame `content`).

- O tipo `Msg` define as mensagens passadas para a função `update`, para disparar mudanças específicas no modelo.
- Ele deve ser um [custom type][custom-type].
- Esta aplicação só precisa de uma mudança no modelo: atualizar o modelo quando o texto na caixa de texto muda.

- A função `init` deve simplesmente retornar um `Model` com um valor padrão razoável (os testes exigem uma string vazia).

## 2. Escreva a função update

- Em qualquer aplicação útil, a função update vai usar uma instrução `case` para fazer pattern matching no parâmetro `Msg`.
- Em cada bloco da instrução case, ela extrai as informações de que precisa do parâmetro `Msg` e retorna um `Model` atualizado.
- O `Model` deve ser um record, e normalmente se usa a [sintaxe de atualização de records][record-update-syntax].

## 3. Escreva a função view

- A função `view` deve retornar uma `div` para o elemento raiz.
- O primeiro filho deve ser um `input`, com um atributo `value` para o texto atual, e um atributo/evento `onInput` com a variante relevante de `Msg`.
- O segundo filho deve ser outra `div` com um filho `text`, informando se o texto é um palíndromo ou não.

## 4. Escreva a função main

- A função main deve simplesmente chamar [`Browser.sandbox`][browser-sandbox].
- `Browser.sandbox` exige um argumento do tipo [record][record] com as funções `init`, `update` e `view`.
