# Sobre

O tipo `Option` é um enum fornecido pela biblioteca padrão. É útil para expressar um valor que pode não existir.
Embora isso possa soar como `null` ou `nil`, é bem diferente e especial.

`Option<T>` contém outros tipos e tem duas variantes: `Some(T)` e `None`.

Por exemplo, `Option<u32>` contém o tipo `u32`.

## Uso

### Usando o `T` dentro de `Option<T>`

Há vários padrões comuns para usar o valor que pode estar presente em um `Option`:

- `if let Some(t) = optional { ... }`.

    O idioma `if let` extrai o valor de um `Option<T>` e o vincula à variável `t`. Isso permite usá-lo diretamente nesse escopo de bloco.

- `match optional { Some(t) => {...}, None => {...}}`

    O operador `match` também permite desempacotar e tratar os casos `None` em uma única instrução ou expressão. É uma alternativa a uma sequência de instruções if e else. Usar `match` pode aumentar a legibilidade de alguns trechos de código.
- `optional.map(|t| ...)`
   `Option::map` atualiza um `Option` no próprio local, potencialmente com um novo tipo, a partir da função fornecida.

   **Nota**: opera sobre o valor contido, se ele estiver presente. O vínculo passa a ser um `Option<U>`, em que o closure dado é `FnOnce(T) -> U`.
- `optional.unwrap()`.
   Fazer `unwrap` em um `Option<T>` extrai `T`, mas dará panic se `T` não estiver lá. É prático em alguns casos.

   **Importante**: Fazer `unwrap` pode facilitar o desenvolvimento no curto prazo ou em código de teste, mas introduz a possibilidade de panics em tempo de execução. Deve ser evitado quando possível.

- `optional.expect("Unexpected None found! Aborting program.)`.
   O método `expect` em `Option<T>` é bem parecido com `unwrap()`, mas dará panic usando a mensagem fornecida se o valor for `None`.

## Exemplos

Quando um valor existe em um `Option<u32>`:

```rust
let has_something: Option<u32> = Some(100);
assert_eq!(has_something.unwrap(), 100);
```

Quando um valor *não* existe em um `Option<u32>`:

```rust
let has_nothing: Option<u32> = None;
assert_eq!(has_nothing, None);
```
