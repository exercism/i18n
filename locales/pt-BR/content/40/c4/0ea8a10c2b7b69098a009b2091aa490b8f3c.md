# Introdução

Um [operador de comparação][comparisons] em Python (_também chamado de operador relacional do Python_) examina os _valores_ de dois [operandos][operand] e retorna um Boolean `True` ou `False` conforme a condição `comparison` seja satisfeita ou não.

A tabela abaixo mostra os operadores de comparação mais comuns do Python:

| Operator | Operation                  | Description                                                               |
| -------- | -------------------------- | ------------------------------------------------------------------------- |
| `>`      | "maior que"             | `a > b` é `True` se `a` for **estritamente** maior em valor que `b`        |
| `<`      | "menor que"                | `a < b` é `True` se `a` for **estritamente** menor em valor que `b`           |
| `==`     | "igual a"                 | `a == b` é `True` se `a` for **estritamente** igual a `b` em valor           |
| `>=`     | "maior que ou igual a" | `a >= b` é `True` se `a > b` OU `a == b` em valor                        |
| `<=`     | "menor que ou igual a"    | `a <= b` é `True` se `a < b` ou `a == b` em valor                        |
| `!=`     | "diferente de"             | `a != b` é `True` se `a == b` for `False`                                 |
| `is`     | "identidade"                 | `a is b` é `True` se **_e somente se_** `a` e `b` forem o mesmo _objeto_ |
| `is not` | "identidade negada"         | `a is not b` é `True` se  **_e somente se_** `a` e `b` **não** forem o mesmo _objeto_       |
| `in`     | "teste de pertencimento"         | `a in b` é `True` se `a` for membro, subconjunto ou elemento de `b`            |
| `not in` | "teste de pertencimento negado" | `a not in b` é `True` se `a` não for membro, subconjunto ou elemento de `b`  |

Todos têm a mesma precedência (_que é maior que a das [operações Boolean][boolean operations], mas menor que a das operações aritméticas ou bit a bit_).

## Comparação entre tipos de dados diferentes

Objetos de tipos diferentes (_exceto tipos numéricos_) nunca são considerados iguais na comparação por padrão.
Instâncias não idênticas de uma `class` também _**não**_ serão consideradas iguais, a menos que a `class` defina métodos especiais que personalizam o comportamento padrão de comparação de `object`.

Os tipos numéricos são (em grande parte) uma exceção a essa regra de correspondência de tipos.
Um `integer` **pode** ser considerado igual a um `float` (_ou um [`octal`][octal] igual a um [`hexadecimal`][hex]_), desde que os tipos possam ser convertidos implicitamente para a comparação.

Para os outros tipos numéricos ([números complexos][complex numbers], [números decimais][decimal numbers], [frações][rational numbers]), os operadores de comparação são definidos onde "fazem sentido" (_onde a conversão implícita não muda o resultado_), mas lançam um `TypeError` se os objetos subjacentes não puderem ser convertidos com precisão para a comparação.

## Comparando a identidade de objetos

Os operadores `is` e `is not` testam a [_identidade_][object identity] de um objeto, em oposição ao _valor_ do objeto.
A identidade de um objeto nunca muda depois de criado e pode ser obtida com a função [`id()`][id function].

`<apple> is <orange>` é avaliado como `True` se _**e somente se**_ `id(<apple>)` == `id(<orange>)`.
`<apple> is not <orange>` produz o inverso.

## Comparações de pertinência

Os operadores `in` e `not in` testam a _pertinência_.
`<fish> in <soup>` é avaliado como `True` se `<fish>` for um membro de `<soup>` (_se `<fish>` for um subconjunto de `<soup>` ou estiver contido em `<soup>`_), e é avaliado como `False` caso contrário.
`<fish> not in <soup>` retorna a negação, ou o _oposto de_ `<fish> in <soup>`.

Para os tipos string e bytes, `<name> in <fullname>` é `True` _**se e somente se**_ `<name>` for uma substring de `<fullname>`.
