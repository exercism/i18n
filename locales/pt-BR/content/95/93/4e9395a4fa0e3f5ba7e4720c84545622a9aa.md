# Instruções

A gerência começou a aplicar princípios darwinianos a um projeto de Carrinho de Controle Remoto.
Os desenvolvedores foram divididos em dois times, _Red_ e _Blue_, e a tarefa deles é melhorar o projeto de forma independente um do outro.
Eles não precisam se preocupar com as decisões de projeto do outro time.
Pedimos que você dê uma olhada no código e veja como pode combinar melhor os dois esforços para fins de teste.

## 1. Encontre uma forma mais adequada de isolar o código dos dois times

Use módulos para expressar melhor a intenção do código.

No momento, tipos importantes como `Motor` e `Telemetry`, sem falar no próprio `RemoteControlCar`, são prefixados com a cor do time correspondente, `<Color>RemoteControlCarTeam`.
O único propósito do prefixo é permitir que tipos com o mesmo nome coexistam no programa.
Um módulo expressa isso melhor.
Você vai ver que, para esses propósitos, um módulo tem vantagens em relação a prefixar tipos.

## 2. Simplifique o sistema de nomes

A gerência exige que os times sejam chamados de "Red Remote Control Car Team" e "Blue Remote Control Car Team" nas definições, e que esses nomes longos sejam usados até no próprio código.
No entanto, os nomes são bem incômodos na hora de referenciar os times.

Encontre uma forma de usar os identificadores mais curtos "Red" e "Blue" dentro do módulo em que você vai construir os carros.
