# Introdução

Tuplas podem estender outras tuplas. `TUPLE: child < parent slots ;` declara uma classe cujas instâncias também são instâncias de `parent`: elas recebem as fendas do pai além das suas próprias, e os acessores do pai também funcionam nelas, como se tivessem sido definidos na classe filha.

```factor
USING: accessors ;

TUPLE: animal name age ;
TUPLE: dog < animal breed ;

"Rex" 4 "labrador" dog boa .
! => T{ dog { name "Rex" } { age 4 } { breed "labrador" } }

"Rex" 4 "labrador" dog boa name>> .   ! => "Rex"   (inherited accessor)
```

## Ordem das fendas do `boa`

O construtor `boa` recebe as fendas na *ordem de declaração, com os pais primeiro*. Para o `dog` acima:

```
dog boa ( name age breed -- dog )
```

Um neto `puppy < dog ` que acrescentasse `weeks` ficaria assim:

```
puppy boa ( name age breed weeks -- puppy )
```

## Hierarquia de predicados

Toda declaração `TUPLE:` gera um predicado (`name?`). Com a herança, os predicados se aninham, ou seja, todo descendente satisfaz os predicados dos seus ancestrais:

```factor
"Rex" 4 "labrador" dog boa
dup dog? .        ! => t
dup animal? .     ! => t
```

O contrário não é verdade: um `animal` que não é um `dog` não passa no `dog?`.

## Nota sobre o que vem a seguir

Os métodos genéricos (`M:`, ensinados em [`generics`][generics]) também despacham pela hierarquia: um método em `animal` é acionado para todo descendente, a menos que uma sobrescrita mais específica tenha prioridade. Você vai ver isso em `boatswains-bilge` logo depois deste exercício.
