# Sobre

## JSON

[JSON][json] (JavaScript Object Notation) é um formato de dados e de arquivo legível por humanos, muito usado para trocar dados, em particular em aplicações web.
Por isso, não surpreende que ele ocupe um lugar especial na linguagem Elm.

O Elm fornece os módulos centrais [`Json.Decode`][decode] e [`Json.Encode`][encode] para ler e escrever dados JSON.
Os decoders JSON são uma forma de _declarar_ que tipo de dado é esperado e a qual estrutura de dados o dado deve ser mapeado.

Quando você vem de linguagens de tipagem dinâmica, os decoders muitas vezes parecem complicados, ou rígidos demais à primeira vista.
Embora sejam certamente verbosos, pelo menos no Elm, eles são uma ferramenta valiosa para descrever explicitamente as expectativas dos programas em relação aos dados que chegam, e são [não menos expressivos que os tipos dinâmicos][dynamic-types-not-more-open].

Vamos importar alguns aliases e tipos dos módulos:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

Usar `Decode.decodeString : Decoder a -> String -> Result Error a` com um decoder e uma string JSON vai ter sucesso se a string estiver de acordo com as especificações do decoder, ou falhar caso contrário.
Não há como inspecionar os dados JSON brutos ao definir o decoder, o que pode parecer incomum para quem vem de linguagens imperativas.

## Decoders de tipos de dados básicos

O JSON tem um pequeno número de tipos de dados centrais:

- String: codificada com aspas duplas `"hello world"`
- Boolean: `true` ou `false`
- Number: como `34` ou `0.12`
- Null: a ausência de dados `null`

Cada um deles está associado a uma função de `Decode`:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

Repare que `Decode.null` deixa você decidir como modelar um `null` no seu programa, exigindo um valor arbitrário como argumento (talvez `()`, `Nothing`, ou qualquer coisa adequada ao seu programa).

## Combinando decoders

O JSON também define duas estruturas de dados para agrupar tipos de dados básicos:

- Array: uma coleção de outros tipos de dados `[0, null, "none", []]`
- Object: uma coleção de pares chave-valor `{"id": 1, "is_admin": false, "more_info": {}}`

O `Decode` também oferece funções para decodificar esses dados:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

Essas funções `Decode.list : Decoder a -> Decoder (List a)` e `Decode.dict : Decoder a -> Decoder (Dict String a)` esperam cada uma um decoder como argumento, que deve decodificar cada elemento da estrutura de dados.
Se o decoder passado como argumento falhar ao decodificar qualquer elemento de um array ou de um objeto, o decoder inteiro falha, o que é um padrão comum.

Combinar decoders simples em decoders mais complexos é a ideia central da técnica.
Vamos apresentar várias outras funções que podem ser usadas para construir decoders de dados do mundo real arbitrariamente complexos, por meio de um exemplo.

## GeoJSON

Para praticar a combinação de decoders básicos na leitura de dados JSON complexos, vamos construir decoders para ler (um subconjunto de) dados GeoJSON.
O [GeoJSON][geojson] é um formato de dados especializado, baseado em JSON, usado para representar feições geográficas, como localizações, caminhos ou regiões, especificadas com coordenadas geográficas 2D ou 3D, junto com outras propriedades.

### Objeto de geometria

Um objeto de geometria GeoJSON é um objeto que contém um campo `type` com um valor do tipo string (há 7 valores possíveis para o tipo) e um campo `coordinates` com coordenadas geográficas (reunidas em uma estrutura que depende do tipo).
Por exemplo,

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

ou

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

Um objeto de geometria poderia ser representado em Elm com o seguinte tipo

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

Para inspecionar o valor de um certo campo, podemos usar `Decode.field : String -> Decoder a -> Decoder a`, que decodifica o valor de uma chave específica de um objeto.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

Para transformar o valor interpretado com sucesso por um decoder, podemos usar `Decode.map : (a -> value) -> Decoder a -> Decoder value`, ou qualquer um dos seus irmãos, de `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` até `Decode.map8`.

Nesse caso, queremos decidir qual decoder de coordenadas usar conforme o valor do campo `type`, o que é um trabalho perfeito para `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` e seus amigos `Decode.succeed : a -> Decoder a` e `Decode.fail : String -> Decoder a`.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

Repare neste ponto que poderíamos usar `Decode.andThen` para validar as coordenadas (verificando que as coordenadas vêm em pares ou trios e que os valores das coordenadas fazem sentido geograficamente).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### Objeto Feature

Um objeto Feature GeoJSON representa algo delimitado espacialmente: ele tem um campo `type` com o valor `"Feature"`, um campo `geometry` com um objeto de geometria ou um `null`, um campo `properties` com um objeto JSON arbitrário ou um `null`, e um campo opcional `id` com um valor de string ou número em JSON.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

ou

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

Vamos lidar primeiro com o campo `id`.
Se ele existir, precisa acomodar strings ou números, então poderíamos ou introduzir um tipo personalizado para o valor, ou sempre salvá-lo como uma string.

Para escolher entre dois decoders possíveis, podemos usar `Decode.oneOf : List (Decoder a) -> Decoder a`.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

Para expressar que o campo é opcional, poderíamos usar a mesma técnica

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

Mas poderíamos, em vez disso, usar `Decode.maybe : Decoder a -> Decoder (Maybe a)`

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

Repare que `decodeMaybeFeatureId` (ou qualquer decoder envolvido com `Decode.maybe`) sempre terá sucesso, já que pode sempre recorrer a `Ok Nothing`, embora um decoder que o use ainda possa falhar

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

A seguir, vamos nos concentrar no campo `geometry`, que pode ser um objeto de geometria ou `null`.
Poderíamos usar `Decode.oneOf` mais uma vez, mas há uma opção melhor: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` e `Decode.nullable` têm a mesma assinatura, mas seu comportamento é diferente, já que o resultado `OK Nothing` de um `Decode.nullable` só virá do valor JSON específico `null`.

Por fim, o campo `properties` pode conter um objeto JSON arbitrário ou um `null`, o que é um trabalho para `Decode.value : Decoder Value`.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

Repare que `Value` é um tipo opaco, o que significa que você não consegue inspecionar facilmente o seu conteúdo.
Para usá-lo, você pode escrever um decoder para ele e rodá-lo com `Decode.decodeValue : Decoder a -> Value -> Result Error a`, ou enviá-lo diretamente para o JavaScript por meio de uma porta.

Estamos prontos para ler objetos Feature:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## Encoders de JSON

Os encoders permitem escrever JSON válido a partir de valores Elm usando a função `Encode.encode : Int -> Value -> String`.
O primeiro argumento especifica a quantidade de indentação no resultado final, e o segundo argumento é o valor JSON a escrever.

Um `Value` pode ser obtido de `Decode.value` ou produzido por um dos encoders:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

bem como com `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

Vamos definir encoders para os decoders de GeoJSON definidos antes

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

Em geral, um bom teste para os seus pares de decoder e encoder é verificar que `elmValue |> encoder |> decoder == elmValue`.

## O que mais?

Não cobrimos todas as funções dos módulos `Json`.
Algumas das coisas não mencionadas incluem: decoders para transformar arrays em `Array` ou objetos em `List (String, a)`, decoders para arrays com um ou mais elementos, decoders para campos específicos em objetos JSON aninhados ou elementos específicos em arrays, como decodificar estruturas recursivas, além das diferentes variantes de `Error` e como exibi-las.

Outros pacotes usados com frequência incluem [`Json.Decode.Pipeline`][pipeline], que introduz um fluxo conveniente para estruturas JSON complexas, e [`Json.Decode.Extra`][extra], que oferece mais decoders, encoders e utilitários.
