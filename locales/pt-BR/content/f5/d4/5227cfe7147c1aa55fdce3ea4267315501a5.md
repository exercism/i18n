# Testes

Cada exercício contém um arquivo de teste.
Rode os testes com o programa `bats`.

```bash
bats test-hello-world.bats
```

O `bats` precisa estar instalado.
Consulte a página [Testing on the Bash track][bash] para instruções de como instalar o `bats` no seu sistema.

### O bats é implementado em bash

O arquivo bats é um script bash, com algumas funções especiais reconhecidas pelo comando `bats`.
Você vai encontrar alguns testes parecidos com

```sh
jq -f some-exercise.jq <<< "{some,json,here}"
```

Essa sintaxe `<<<` é um [Here String][here-string] do bash.
Ela envia a string do lado direito para a entrada padrão do programa do lado esquerdo.
É ([aproximadamente][so]) o mesmo que

```sh
echo "{some,json,here}" | jq -f some-exercise.jq
```

## Ajuda para as funções assert

Os testes usam funções da biblioteca [bats-assert][bats-assert].
A ajuda para as várias funções `assert*` está lá.

## Testes ignorados

Resolver um exercício significa fazer todos os testes passarem.
Por padrão, apenas um teste (o primeiro) é executado quando você roda os testes.
Isso é intencional, pois permite que você foque só em fazer esse teste passar.
Quando ele passar, você pode habilitar o próximo teste comentando ou removendo as

    [[ $BATS_RUN_SKIPPED == true ]] || skip

anotações que vêm antes dos outros testes.

## Sobrescrevendo os skips

Para rodar todos os testes, incluindo os que têm anotações `skip`, rode:

```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

Pode ser prático usar uma função wrapper para digitar menos: no `bash`, você pode fazer:

```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```

Depois, rode os testes apenas com:

```bash
bats
```

## Depurando em `jq`

O `jq` vem com um útil filtro [`debug`][debug].
Use-o enquanto você desenvolve as soluções dos seus exercícios para inspecionar os dados que estão no momento no pipeline do jq.
Consulte a [documentação de depuração][debugging] para mais detalhes.
