# Sobre

Um [laço][control] é uma sequência de instruções que pode ser executada mais de uma vez, até que uma condição de término seja satisfeita.

Em x86-64, um laço geralmente é criado com um salto para um rótulo anterior:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Repare que um salto incondicional para um rótulo anterior sempre transfere a execução para esse rótulo.
Isso significa que o laço vai se repetir para sempre, a menos que haja outro salto para fora da sequência repetida.

Por exemplo, este laço não termina:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

E este laço pode terminar, dependendo de a condição ser satisfeita:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## Laços de contagem

Um laço de contagem quase sempre termina da mesma forma: uma instrução que atualiza um contador ou compara dois valores, seguida imediatamente por um salto condicional que decide se deve dar mais uma volta.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
`cmp rsi, 0` não é necessário no código acima porque `sub rsi, 1` já define o `zero flag (ZF)` quando o resultado é `0`.

Embora `cmp` seja a principal forma de testar condições em assembly, muitas instruções atualizam as flags.
Por exemplo, muitas instruções de aritmética com inteiros ou de operações bit a bit atualizam `ZF` quando o resultado é `0`, e `SF` quando o resultado é negativo (ou seja, o bit mais significativo está definido).

Você pode consultar uma [referência][reference] para ver quais flags são afetadas por cada instrução.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Repare que, no exemplo acima, presume-se que `rsi` seja maior que `0`.
Se fosse `0`, então `sub rsi, 1` reduziria `rsi` a `-1`, que é um número sem sinal muito grande.
Seria preciso mais `18,446,744,073,709,551,615` iterações antes que o laço finalmente terminasse.
Além disso, como o comprimento do array é `0`, qualquer acesso à memória ficaria fora dos limites.

Se não houver garantias sobre o comprimento de um array, há duas abordagens comuns.

A primeira é mover a condição de término para o início do laço e, então, colocar um salto incondicional no final:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

A segunda é testar uma vez se o array tem comprimento zero antes do início do laço:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Essa segunda abordagem costuma ser mais eficiente que a primeira, porque há menos desvios no corpo do laço.
Você vai aprender mais sobre isso em um conceito futuro.

## Micro-operações

Um processador não executa uma instrução como `add` ou `jnz` diretamente.
O front-end da CPU primeiro _decodifica_ cada instrução em um ou mais passos internos menores, chamados de **micro-operações** (ou **micro-ops**).
O processador então agenda e executa essas micro-operações, muitas vezes várias por ciclo e fora da ordem original.

A maioria das instruções simples é decodificada em uma única micro-operação, enquanto uma instrução mais complexa pode ser decodificada em várias.
Como a carga de trabalho real do processador é o fluxo de micro-operações, produzir menos delas para a mesma tarefa é uma forma de tornar o código mais rápido.

## Macrofusão

Como mencionado antes, um laço geralmente termina com algum tipo de salto condicional.
Isso é tão comum que os processadores modernos são otimizados para esse padrão durante a decodificação.

Uma instrução que define flags seguida imediatamente por um salto condicional que lê essas flags pode ser decodificada em conjunto como uma **única** micro-operação, em vez de uma para cada.
Isso se chama **macrofusão**.

O par fundido se comporta como uma única operação: o contador é atualizado e a decisão de desvio é tomada em conjunto, em uma única micro-operação.
Assim, o fluxo de controle do laço quase não custa nada além do trabalho que o laço de fato realiza.

Como regra geral, dois tipos de pares costumam se fundir dessa forma:

- Instruções aritméticas como `add` ou `sub`, seguidas imediatamente por um salto condicional.
- Um `cmp`, `test` ou `and`, seguido imediatamente por um salto condicional.

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

A fusão só acontece quando o salto condicional vem **imediatamente** depois da instrução que define as flags, sem nada entre eles.

~~~~exercism/note
A macrofusão depende da CPU e há variação em quais instruções se fundem com qual salto condicional.

Uma referência útil é [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch].
A seção 3.4.2.2 (Optimizing for Macrofusion) do [Intel optimization reference manual][intel-opt] também lista os pares fundíveis para CPUs Intel.

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## A instrução `loop`

Existem algumas instruções que podem ser usadas para criar comportamentos semelhantes a um laço.
Uma delas é a [loop][loop].

Seu único operando é um rótulo que contém o endereço do início do laço.

A instrução `loop` usa o valor em `rcx` como contador, decrementando-o em 1 a cada vez.
Quando o valor em `rcx` chega a zero, o laço termina e a execução continua sequencialmente:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

Há duas variantes da instrução `loop` que verificam a flag de zero (`ZF`) a cada iteração.
Além de interromper o laço quando `rcx` chega a zero, elas também param quando a condição _não_ é satisfeita.

| instrução         | condição  |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == 1 |
| `loopne`/`loopnz` | `ZF` == 0 |

O `ZF` **não é definido** por essas instruções.
É preciso haver um `cmp`, um `test` ou outra instrução que altere o `ZF` antes delas:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
Apesar da conveniência, `loop`, `loope` e `loopne` costumam ser bem mais lentas nos processadores modernos do que a sequência equivalente de `sub`/`jnz` ou `cmp`/`jnz`.

Uma boa referência sobre o desempenho das instruções em várias CPUs diferentes são as [tabelas do Agner][agner-tables].

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
