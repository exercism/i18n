# Inclusão de código

`circus-acts` usava `<` para dizer que uma classe *pode fazer* o que uma classe abstrata descreve. Não dizia nada sobre como.

`include` é a outra metade: pega o código de verdade de outra classe e coloca uma cópia dele nesta.

```sather
class WARM_UP is

   count : INT is return 8; end;

   describe : STR is return count + " counts"; end;

end; -- class WARM_UP

class JAZZ_ROUTINE is

   include WARM_UP;

   -- count and describe are now here too, as though written out.

end; -- class JAZZ_ROUTINE
```

`JAZZ_ROUTINE::count` é 8, sem que `JAZZ_ROUTINE` mencione isso.

## São duas decisões separadas

A maioria das linguagens junta as duas: um único `extends` transmite o código e faz a subclasse ser usável em qualquer lugar onde a superclasse seja. Sather as mantém separadas.

| Escrito | Diz |
| --- | --- |
| `class A < $B` | um `A` pode ser usado em qualquer lugar onde se queira um `$B` |
| `class A is include B` | `A` começa com uma cópia do código de `B` |

Uma sem a outra, ou as duas. Incluir uma classe **não** a torna um subtipo: depois de `include WARM_UP`, um `JAZZ_ROUTINE` continua não podendo ser usado onde se queira um `WARM_UP`, e nada finge o contrário.

## Renomeação

Uma rotina incluída pode ser trazida com um nome diferente:

```sather
   include WARM_UP count -> warm_up_count;
```

Várias são separadas por vírgulas:

```sather
   include WARM_UP count -> warm_up_count, describe -> warm_up_describe;
```

## Deixando uma de fora

Renomear para *nada* deixa a rotina de fora, e é assim que se substitui uma rotina:

```sather
class TAP_ROUTINE is

   include WARM_UP describe -> ;

   describe : STR is return "Tap: " + count + " counts"; end;

end; -- class TAP_ROUTINE
```

`count` entra normalmente; `describe` não, então escrever uma aqui não gera conflito. Sem o `describe -> ;` o compilador recusaria: duas rotinas com o mesmo nome e os mesmos argumentos numa mesma classe é um erro, e Sather não vai adivinhar qual delas você quis.

É essa a diferença em relação à sobrescrita na maioria das linguagens: a substituição é anunciada, não implícita.
