# Sobre

Uma declaração `GENERIC:` introduz uma palavra cujo comportamento
depende da classe de um dos seus argumentos. O comportamento concreto
é fornecido por *métodos* (`M:`) que têm como alvo classes específicas.

```factor
GENERIC: stringify ( obj -- str )
M: integer stringify number>string ;
M: string  stringify ;
M: f       stringify drop "(none)" ;
```

Quando `stringify` é chamado, o Factor inspeciona o topo da pilha,
procura o método mais específico cuja classe corresponde e o executa.
Se nenhum método corresponder, um erro é lançado.

## Classe de despacho

Por padrão, o despacho acontece sobre o argumento do topo (a primeira
entrada declarada no efeito de pilha). Para despacho com múltiplos
argumentos, veja `HOOK:` e `MATH:`, que fazem o despacho sobre o segundo
argumento ou sobre a promoção numérica, respectivamente.

## Adicionar métodos a um genérico

Você pode estender um genérico a qualquer momento, até de um vocabulário
diferente, desde que você possa aplicar `USE:` tanto ao genérico quanto
à classe:

```factor
USING: math ;
M: ratio  area drop 0 ;     ! adds an `area` method for ratios
```

## Métodos em classes embutidas

Os genéricos funcionam tão bem em classes embutidas (`integer`,
`string`, `array`, `f`, `t`) quanto em tuplas definidas pelo usuário.
Métodos em `f` e `t` são especialmente úteis para predicados no estilo
"is-set?" que têm padrões naturais.

## Quando um genérico é a escolha certa

Recorra a `GENERIC:` quando:

- Uma única operação tem implementações *genuinamente diferentes*
  para entradas diferentes (não apenas um `case` sobre rótulos).
- Você espera que outro código acrescente novos tipos mais tarde.
- Você quer que o sistema de tipos garanta que a operação esteja
  definida para toda classe relevante. O Factor pode listar os
  métodos que faltam para você.

Se a variação for uma enumeração pequena e fixa de rótulos, um
`case` é mais simples.
