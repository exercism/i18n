# Rotinas vinculadas

```sather
   part : ROUT{STR}:STR := bind(shout(_));
   part.call("who's there");
```

## bind

`bind` recebe uma chamada na qual qualquer parte pode ser substituída por `_`. Tudo que não é um `_` é avaliado **agora** e mantido; cada `_` vira um argumento da rotina vinculada, na ordem em que foi escrito.

```sather
   bind(repeat(2, _))         -- ROUT{STR}:STR
   bind(repeat(_, "Ha"))      -- ROUT{INT}:STR
   bind(repeat(_, _))         -- ROUT{INT,STR}:STR
```

## Os tipos

| Tipo | Recebe | Responde |
| --- | --- | --- |
| `ROUT:INT` | nada | `INT` |
| `ROUT{STR}` | um `STR` | nada |
| `ROUT{STR}:STR` | um `STR` | um `STR` |
| `ROUT{INT,INT}:BOOL` | dois `INT` | `BOOL` |

`ITER{...}` é a mesma ideia para um iterador.

## call

`call` fornece os argumentos restantes. Uma rotina vinculada que não responde nada é chamada da mesma forma, como uma instrução.

## O `bind` fica à direita de uma atribuição

Um `bind` pode ser declarado em uma variável ou passado como argumento:

```sather
   part ::= bind(shout(_));                -- yes
   part : ROUT{STR}:STR := bind(shout(_)); -- yes
   rehearse("line", bind(shout(_)));       -- yes
```

mas não pode ir direto para um `return`:

```sather
   return bind(shout(_));                  -- does not parse
```

Coloque-o em uma variável e retorne essa variável. A mensagem de erro aponta para o `bind` e menciona underscores, o que não é óbvio a partir da própria linha.

## Onde eles são usados

A biblioteca os recebe onde quer que um comportamento precise ser fornecido:

```sather
   names.sort_by(bind(shorter(_, _)));
   scores.count_if(bind(over(10, _)));
   scores.find_if(bind(is_even(_)));
```

A ordenação é o caso mais claro: `sort_by` sabe ordenar e não sabe nada sobre a sua ideia de ordem, e a rotina vinculada é como as duas se encontram.

## Uma limitação neste compilador

O Sather 1.2 não implementa rotinas vinculadas **despachadas**: vincular uma rotina a uma variável de um tipo abstrato. O compilador diz isso claramente:

```
Dispatched bound routines are not implemented yet
```

Faça o bind em um tipo concreto, ou em uma classe, e tudo funciona. É por isso que a própria estrutura de testes da trilha escreve suas verificações de exceção à mão, em vez de usar uma rotina vinculada.

## Rotinas vinculadas ou classes abstratas?

As duas permitem que quem chama forneça um comportamento.

Uma rotina vinculada é uma única rotina, não precisa de classe e é escrita onde é usada. Uma classe abstrata carrega várias rotinas e algum estado, e vale a cerimônia quando a coisa fornecida tem mais de uma parte.

Uma rotina para entregar: faça o bind dela. Um colaborador com várias: escreva uma classe.
