# Gerador de testes da trilha Python do Exercism

A trilha Python usa um script gerador e templates [Jinja2][Jinja2] para
criar arquivos de teste a partir dos [dados canônicos][canonical data] do Exercism.

## Uso do script

A geração de testes exige uma cópia local do repositório
[problem-specifications][problem-specifications]. O script deve ser executado a partir do
diretório raiz `python`, para acessar os exercícios corretamente.

Execute `bin/generate_tests.py --help` para ver as informações de uso.


## Templates de teste

Os templates de teste dão suporte à sintaxe do [Jinja2] e têm as seguintes
variáveis de contexto disponíveis a partir dos dados canônicos:
- `exercise`: o nome do exercício com hífens (ex.: `two-fer`)
- `version`: a versão dos dados canônicos (ex.: `1.2.0`)
- `cases`: uma lista de objetos de caso ou uma lista de listas `cases`. Para saber a
estrutura exata do exercício em que você está trabalhando, consulte
`canonical-data.json`
- `has_error_case`: indica se algum caso de teste espera que um
erro seja lançado (ex.: `False`)
- `additional_cases`: estrutura semelhante a `cases`, mas é preenchida a partir do arquivo `.meta/additional_tests.json` do exercício, se ele existir (para um exemplo, veja `exercises/word-count/.meta/additional_tests.json`)

Além disso, os seguintes filtros de template são adicionados por conveniência:
- `to_snake`: converte uma string para snake_case (ex.: `{{ "CamelCaseString" | to_snake }}` -> `camel_case_string`)
- `camel_case`: converte uma string para CamelCase (ex.: `{{ "snake_case_string" | camel_case }}` -> `SnakeCaseString` )
- `error_case`: verifica se um caso de teste espera que um erro seja lançado (ex.: `{% for case in cases%}{% if case is error_case}`)
- `regex_replace`: substituição de string com regex (ex.: `{{ "abc123" | regex_replace("\\d", "D") }}` -> `abcDDD`)


### Convenções

- Macros de uso geral para estruturas de template muito repetidas são definidas em `config/generator_macros.j2`.
  - Elas podem ser importadas assim:
  `{%- import "generator_macros.j2" as macros with context -%}`
- Todos os templates de teste devem terminar com `{{ macros.footer() }}`.
- Todos os nomes de classe Python devem estar em CamelCase (ex.: `TwoFer`).
  - Converta usando `{{ "two-fer" | camel_case }}`
- Todos os nomes de módulo e de função Python devem estar em snake_case
(ex.: `high_scores`, `personal_best`).
  - Converta usando `{{ "personalBest" | to_snake }}`
- Os testes específicos da trilha são definidos no arquivo de opções `.meta/additional_tests.json`. O objeto JSON definido nesse arquivo deve
ter uma única chave, `cases`, com a mesma estrutura de `cases` em
`canonical-data.json`.
- Os testes específicos da trilha devem ser colocados depois dos testes canônicos nos
arquivos de teste.
- Os testes específicos da trilha devem ser marcados no arquivo de teste com o seguinte comentário:
```
# Additional tests for this track
```


### Layout

A maioria dos templates se parece com algo assim:

```Jinja2
{%- import "generator_macros.j2" as macros with context -%}
{{ macros.header() }}

class {{ exercise | camel_case }}Test(unittest.TestCase):
    {% for case in cases -%}
    def test_{{ case["description"] | to_snake }}(self):
        value = {{ case["input"]["value"] }}
        expected = {{ case["expected"] }}
        self.assertEqual({{ case["property"] }}(value), expected)

    {% endfor %}

{{ macros.footer() }}
```


### Sobrescrevendo importações

Os nomes importados em `macros.header()` podem ser sobrescritos adicionando
uma lista de nomes alternativos para importar (ex.: `clock`):

```Jinja2
{{ macros.header(["Clock"])}}
```


### Ignorando propriedades

Em raras ocasiões, pode ser necessário filtrar as propriedades que
não são testadas nesta trilha. A macro `header` também aceita um
argumento `ignore` (ex.: `high-scores`):

```Jinja2
{{ macros.header(ignore=["scores"]) }}
```

## Criando um template

1. Crie o arquivo `.meta/template.j2` para o exercício que você está implementando
  e abra-o no seu editor.
2. Copie e cole o [layout de exemplo](#Layout) no arquivo de template
  e salve.
3. Faça as alterações necessárias no arquivo de template até que ele produza
  código de teste válido, consultando o `canonical-data.json` do exercício para
  os nomes de entrada e a estrutura dos casos.
    - Use as [macros disponíveis](../config/generator_macros.j2) para evitar reescrever seções padronizadas.
    - Se você está implementando um template para um exercício já existente,
    reproduzir exatamente a estrutura do arquivo de teste atual não é
    obrigatório, mas minimizar as diferenças torna a revisão do PR um processo muito mais tranquilo para todo mundo.
