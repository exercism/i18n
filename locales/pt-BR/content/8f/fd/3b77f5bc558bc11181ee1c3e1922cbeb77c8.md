# Introdução

As exceções em Ruby, como em muitas linguagens, oferecem uma forma de lidar com eventos inesperados. O tratamento adequado de exceções é importante quando você quer evitar que seu programa quebre.

Quando uma exceção é lançada, seja porque você a lançou explicitamente, seja porque o interpretador Ruby a lançou, o programa desvia da operação normal e, por fim, encerra com uma mensagem de erro:

```ruby
raise ArgumentError.new("Something went wrong!")
=> Traceback (most recent call last):
.
.
ArgumentError (Something went wrong!)
```

```ruby
1/0
=> Traceback (most recent call last):
.
.
ZeroDivisionError (divided by 0)
```

Caso você queira impedir esse encerramento, precisa reagir à exceção. Isso se chama "resgatar" uma exceção:

```ruby
begin
  # ...any code that raises an exception
rescue
  puts 'Got an exception'
end
```

Este programa não vai quebrar e vai imprimir "Got an exception". Em vez de encerrar, o Ruby executa o código no bloco rescue, que imprime uma mensagem.

Como tudo em Ruby, as exceções também são objetos e normalmente carregam dados sobre a exceção. É assim que você pode obter o objeto da exceção:

```ruby
begin
  # ...any code that raises an exception
rescue => e
  puts "Exception class: #{ e.class.name }"
  puts "Exception Message:#{e.message}"
end
```

Em Ruby, também é possível lançar suas próprias exceções. Por exemplo:

```ruby
begin
  raise ArgumentError.new("Invalid argument")
rescue ArgumentError => e
  puts e.message
end
```

A exceção anterior é uma das exceções nativas do Ruby, mas também é possível definir exceções personalizadas e lançá-las:

```ruby
class CustomError < StandardError
end

raise CustomError.new("Something went wrong")
```
