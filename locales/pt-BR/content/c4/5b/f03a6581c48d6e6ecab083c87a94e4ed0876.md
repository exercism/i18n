# Testes

Execute os testes com:

```shell
corepack pnpm test
```

Certifique-se de que seu código segue as boas práticas e os estilos de codificação, assim como os de outros usuários, com o ESLint, uma ferramenta que faz análise estática do seu código.
Às vezes, ferramentas como essa economizam seu tempo ao detectar erros de digitação ou deslizes no seu código JavaScript:

```shell
corepack pnpm lint
```

Você também pode rodar o Jest no modo "watch", que roda seus testes de novo automaticamente quando você salva alterações no código ou no módulo de teste:

```shell
corepack pnpm watch
```

## Entendendo os testes ignorados

O método skip instrui a suíte de testes a não rodar um teste. Essa função também pode ser usada com os apelidos: `it.skip(name, fn)`, `xit(name, fn)` ou `xtest(name, fn)`.

- Por que eles são ignorados?

Para permitir que as pessoas se concentrem em um teste de cada vez e os ativem um a um conforme a solução evolui.

- Como ativá-los?

Troque `xtest` por `test`.

```javascript
test('title cased phrases', () => {
  expect(Acronyms.parse('Portable Network Graphics')).toEqual('PNG');
});
```

## Criando seu primeiro módulo JavaScript 2015

Normalmente, os testes desta trilha carregam sua implementação importando-a como um módulo JavaScript: `import { Bob } from './bob.js';`.
Você só precisa exportar sua implementação do arquivo referenciado, `bob.js`:

```javascript
export function hey(message) {}
```

Você encontra mais informações sobre módulos na [documentação do Babel](https://babeljs.io/docs/learn-es2015/#modules).
Para facilitar o começo, há um arquivo JavaScript _skeleton_ no diretório.
