# Sobre

## Boolean em Julia

Valores verdadeiros ou falsos são representados pelo tipo `Bool`.
Ele contém apenas dois valores: `true` e `false`.

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

Diferentemente de várias outras linguagens, Julia deliberadamente não tem nenhum conceito de "truthiness", e só expressões que resultam em `true` ou `false` são tratadas como `Bool`.

Especificamente, arrays ou strings vazios *não* serão interpretados como `false`.
É preciso uma verificação apropriada, como `isempty()`, se você quiser um tratamento especial para valores vazios.

## Operadores Boolean

Existem três [operadores Boolean][boolean-operators] em Julia.

O `&&` é o operador Boolean "e".
Ele resulta em `true` se as expressões dos *dois* lados de `&&` forem `true`.

```julia-repl
julia> true && true
true

julia> true && false
false
```

O `||` é o operador Boolean "ou".
Ele resulta em `true` se uma expressão de *qualquer* um dos lados de `||` for `true`.

```julia-repl
julia> true || true
true

julia> false || true
true
```

O `!` é o operador Boolean "não".
Ele troca (inverte) os valores `true` e `false`.

```julia-repl
julia> !true
false

julia> !false
true
```

Operadores parecidos vão ser conceitualmente familiares para quem usa muitas outras linguagens, embora a sintaxe exata possa variar de linguagem para linguagem.

## Precedência de operadores

Em expressões mais complexas, pode ser útil saber que `&&` tem uma [precedência][operator-precedence] um pouco maior que `||` *(do mesmo jeito que `*` é aplicado antes de `+` em expressões aritméticas)*.

Depender disso pode ser confuso e propenso a erros.
Para maior clareza, use parênteses e deixe clara a sua intenção.

## Avaliação de curto-circuito

A expressão `true || x` depende do valor de `x`, ou o compilador pode simplesmente ignorar `x`?

Julia avalia expressões Boolean da esquerda para a direita e para assim que tem um resultado inequívoco.

Por exemplo, `true || x` tem que ser `true`, independentemente de `x`, então `x` não é avaliado.
Do mesmo jeito, `false && y` é `false`, sem precisar avaliar `y`.

Por outro lado, `true && x` é `true` *somente se* `x` for `true`, então `x` precisa ser avaliado.

Do mesmo jeito, se encadearmos vários operadores:

```julia-repl
julia> true && false && something_else
false
```

Como `true && false` tem que ser `false`, o `something_else` não importa e é ignorado pelo compilador.

Neste caso, `something_else` não existia como variável, mas incluí-lo nesse contexto não gerou nenhum erro *(teste isso no REPL se você duvidar)*.

Esse tipo de avaliação de curto-circuito é usado com bastante frequência por quem programa em Julia como um atalho para capturar problemas de execução e casos extremos:

```julia
all_ok || do_something()

is_problem && do_something_else()
```

Por exemplo, o `do_something` pode ser um `return` antecipado da função, se `all_ok` for `false`, ou a atribuição de um valor padrão a uma variável antes de continuar.

Isso é um pequeno abuso da sintaxe Boolean, mas pode ser muito conveniente.

## Como os Bools funcionam internamente

Se um Bool fizer parte de uma expressão *aritmética*, `true` é interpretado como `1` e `false` como `0`, refletindo como eles são armazenados.

Se você tem experiência com linguagens de baixo nível (C e similares), *por favor* evite usar isso com frequência.
Isso reduz a legibilidade do código e dificulta a depuração.

Às vezes você pode ver os valores numéricos usados como um jeito rápido de contar quantas coisas são `true`.

```julia-repl
julia> true + false + true
2
```
