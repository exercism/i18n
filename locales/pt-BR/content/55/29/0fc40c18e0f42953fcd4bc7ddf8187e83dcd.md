# Sobre

## Representação, caracteres e inteiros

Assim como outros tipos simples (`int`s, `bool`s etc.), o `char` tem um tipo companheiro ou alias, neste caso, `System.Char`.

Na verdade, trata-se de uma `struct` com um campo de 16 bits, e é imutável por padrão.

O `char` tem alguns métodos de instância, como `Equals`, `ToString` e [`CompareTo`][compare-to].

O `char` tem a mesma largura que um [`ushort`][uint16], mas em geral eles não são usados de forma intercambiável, como acontece em algumas linguagens. É preciso converter `ushort` explicitamente para `char`.

Vale dizer que `char`s podem participar de operações aritméticas. O resultado dessas operações é um inteiro.

Obviamente, não há equivalência entre um `byte` de 8 bits e o `char` de 16 bits.

## Uso

Em geral, `char`s são fáceis de usar.

Eles podem ser definidos como literais com aspas simples:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

Um `char` individual pode ser obtido de uma string com indexação (a partir de zero):

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

Iterar sobre uma string retorna um `char` em cada passo:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

Como mostrado acima, um `char` pode ser convertido para seu valor `int`.
Isso também funciona (*pelo menos em alguns casos*) para outros sistemas de escrita:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

O Int16 subjacente é usado ao comparar caracteres:

```fsharp
'A' < 'D'
// => val it: bool = true
```

Além disso, um `int` pode ser convertido para `char`:

```fsharp
char 77
// => val it: char = 'M'
```

A biblioteca `System.Char` contém o conjunto completo de [métodos][Char-methods] esperado para uma linguagem .NET, como conversões para maiúsculas/minúsculas (mas veja as ressalvas na próxima seção):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

As bibliotecas .NET ajudam a extrair `char`s de strings; neste caso, métodos de `Seq`:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

Há várias formas de converter uma lista (ou um array) de caracteres em uma string, incluindo estas:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

Você encontra informações gerais sobre `char`s aqui:

- [Documentação de Chars][chars-docs]: documentação de referência para `char`.

No entanto, os `char`s têm várias imperfeições, como detalhado abaixo. Essas imperfeições se relacionam principalmente à oposição entre o padrão unicode completo, de um lado, e as representações históricas de texto, além de desempenho e uso de memória, do outro.

## Questões de Unicode

Ao lidar com strings, se houver métodos da biblioteca [`System.String`][System-string] disponíveis, procure usá-los em vez de quebrar a string em caracteres.

Alguns "caracteres" textuais consistem em mais de um `char`, porque o padrão unicode tem mais de 65536 pontos de código. Por exemplo, os emojis que aparecem em alguns dos testes têm 2 `char`s, pois são formados por caracteres [substitutos][surrogates].

Além disso, existem sequências de combinação; por exemplo, em alguns casos, um caractere acentuado pode consistir em um `char` para o caractere simples e outro `char` para o acento.

Se você tiver que lidar com caracteres individuais, tente usar métodos de biblioteca como [`System.Char.IsControl`][is-control] e [`System.Char.IsDigit`][is-digit], em vez de fazer comparações ingênuas, como verificar se um caractere está entre '0' e '9'.

Por exemplo, repare que '٢' é o dígito arábico 2. `IsDigit` vai retornar true para a versão arábica, então você precisa deixar claro, digamos, ao validar, qual faixa de entradas é aceitável.

Até mesmo os métodos da biblioteca `System.Char` podem não se comportar como você espera quando está lidando com linguagens mais obscuras.

Uma forma segura de dividir uma string em "caracteres" de exibição é usar [`StringInfo`][string-info] e métodos como [`GetNexttextElement`][get-next-text-element].
Isso pode ser necessário se você estiver lidando com globalização/localização.

Outro caminho, quando os valores escalares dos caracteres unicode são importantes (digamos que você esteja criando seu próprio sistema de codificação), é usar [runes][runes]. No entanto, se você sabe que a faixa de caracteres com que lida não inclui substitutos nem sequências de caracteres combinantes (por exemplo, ASCII latino) e sua entrada está bem validada, você pode evitar isso.

De novo, a melhor situação é poder usar os métodos de biblioteca de `String`.

Se você acabar na situação ingrata de lidar com as minúcias do unicode, [isto][char-encoding-net] é um bom ponto de partida.

## Globalização

Se você trabalha em um ambiente onde lida com várias culturas, ou onde a cultura é importante em algumas partes do código mas não em outras, fique atento às sobrecargas de [`ToUpper`][to-upper] e [`ToLower`][to-lower] que recebem uma cultura, e de [`ToUpperInvariant`][to-upper-invariant] e [`ToLowerInvariant`][to-lower-invariant], que fornecem um resultado consistente independentemente da [cultura][culture-info] atual.
