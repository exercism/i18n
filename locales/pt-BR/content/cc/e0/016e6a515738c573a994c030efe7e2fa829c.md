# Sobre

As `struct`s do C# são muito parecidas com as `class`es.
Elas têm estado e comportamento.
Podem ter os mesmos tipos de membros: construtores, métodos, campos, propriedades etc.

Campos e propriedades podem ser tipos simples, `struct`s ou tipos de referência.
As `struct`s seguem as mesmas regras de escopo, de leitura e escrita e de níveis de acesso que as `class`es.

```csharp
enum Unit
{
    Kg,
    Lb
}

struct Weight
{
    private double count;
    private Unit unit;

    public Weight(double count, Unit unit)
    {
        this.count = count;
        this.unit = unit;
    }

    public override string ToString()
    {
        return count.ToString() + unit.ToString();
    }
}

new Weight(77.5, Unit.Kg).ToString();
// => "77.6Kg"
```

Uma das principais coisas a lembrar é que, quando uma struct é atribuída a uma variável ou passada como parâmetro, os valores são copiados, então mudanças na variável original não afetam a cópia, e vice-versa.
Em resumo, `struct`s são **tipos de valor**.

Este [artigo][class-or-struct] discute as diferenças entre `struct`s e `class`es.
Você vai ver no artigo que as `struct`s tendem a ser leves e [imutáveis][structs-immutable], embora essa orientação não seja imposta (por padrão) pelo compilador nem pelo runtime.

Existem algumas coisas com que você vai se deparar (e sobre as quais o compilador vai te avisar):

1. Os membros de uma `struct` não podem ser inicializados na própria declaração.
2. Uma `struct` não pode ser herdada
3. Uma `struct` sempre tem um construtor padrão, mesmo que um construtor diferente dele seja fornecido, e você não pode fornecer um construtor sem parâmetros explícito.

Como resultado dos pontos 1 e 3 acima, não há como quem desenvolve uma `struct` impedir que instâncias inválidas venham a existir.

## Structs comuns

Você vai ver na documentação que existe uma relação estreita entre tipos primitivos e structs.
Veja [`Int32/int`][int32] como exemplo.
Um exemplo mais convencional de `struct` é o tipo [`TimeSpan`][time-span].

As instâncias de `TimeSpan` se comportam muito como números, com operadores de comparação como `>` e `<` e operadores aritméticos.
Você pode implementar esses operadores nas suas próprias `struct`s quando precisar deles.

Um detalhe a notar sobre `TimeSpan` é que ele implementa várias interfaces, como `IComparable<TimeSpan>`.
Embora as `struct`s não possam ser derivadas de outras `struct`s, elas podem implementar interfaces.

## Igualdade

Testar igualdade entre `struct`s costuma ser bem mais simples do que entre `class`es, porque, por padrão, basta comparar os campos.
Não é preciso sobrescrever `object.Equals()` (nem `GetHashCode()`).
Lembre-se de que, se você depende de `Object.GetHashCode()`, ainda precisa garantir que os campos envolvidos na geração do código hash (ou seja, todos os campos) não mudem enquanto uma coleção com hash estiver em uso.
Na prática, isso significa que structs usadas assim devem ser imutáveis.

Diferente do método `Equals()`, não existe implementação padrão dos operadores de igualdade, `==` e `!=`.
Se a sua `struct` precisar deles, você terá que implementá-los.

Por outro lado, este [artigo][equality] descreve como o desempenho pode ser otimizado criando seus próprios métodos `Equals()` e `GetHashCode()` personalizados, como costuma ser feito com `class`es.
No caso deste exercício, a diferença foi de cerca de 20% numa comparação não muito rigorosa, mas esse número pode estar subestimado, porque todos os campos são do mesmo tipo. Veja mais abaixo.

Há discussões na [web][equality-performance] sobre ganhos de velocidade quando o método `Equals()` não é sobrescrito, se todos os campos forem do mesmo tipo.
Neste exercício, a diferença ao incluir campos de tipos diferentes foi de cerca de 60%.
Isso não é mencionado na documentação da Microsoft, o que faz disso um detalhe de implementação não documentado, e deve ser explorado com bom senso.

```csharp
public bool Equals(Weight other)
{
    return count.Equals(other.count) && unit.Equals(other.unit);
}

public override bool Equals(object obj)
{
    return obj is Weight other && Equals(other);
}

public override int GetHashCode()
{
    return HashCode.Combine(count, unit);
}
```
