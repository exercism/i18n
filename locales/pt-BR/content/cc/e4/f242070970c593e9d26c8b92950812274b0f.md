# Sobre

O exercício de programação ilustra várias propriedades dos parâmetros:

- Parâmetros [passados][passing-parameters] sem um modificador (como `out` ou `ref`) são passados por valor. Ou seja, o parâmetro pode ser usado e receber atribuição no método chamado, mas quaisquer alterações não terão efeito sobre quem chama.
- Quando um parâmetro é uma referência a um array ou a uma instância de uma classe, o método chamado pode alterar os elementos/campos dessa instância, e quem chama vê essas alterações. Isso vale independentemente de o modificador `ref` estar presente.
- Um parâmetro com o modificador [`out`][out-parameter] transmite um valor do método chamado de volta para quem chama. O parâmetro pode ser passado ao método chamado sem ter sido inicializado e, de qualquer forma, dentro do método chamado ele é tratado como se, na entrada, não tivesse sido inicializado. A maneira mais fácil de entender o comportamento e as regras dos modificadores de parâmetros é por meio de exemplos (veja abaixo) e de mensagens do compilador.

```csharp
void Foo(out int val)
{
    val = 42;
}
void Bar(int val)
{
    val = 42;
}

int importantValue = 1729;
Foo(out importantValue);
var result = importantValue == 42;
// => true

importantValue = 1729;
Bar(importantValue);
result = importantValue == 1729;
// => true
```

- Parâmetros `out` precisam receber atribuição dentro do método chamado.

- Um parâmetro com o modificador [`ref`][ref-parameter] passa um valor para dentro do método chamado. Quando o método retorna, quem chama encontra nesse parâmetro as atualizações feitas pelo método chamado.

```csharp
void Foo(ref int val)
{
    val *= 7;
}

int importantValue = 6;
Foo(ref importantValue);
return importantValue;
// => 42
```

-`ref` parameters must be variables as the called method will be operating directly on the parameter as seen by the caller.

Tradução: Parâmetros `ref` precisam ser variáveis, pois o método chamado vai operar diretamente sobre o parâmetro tal como quem chama o vê.

- Os modificadores `out` e `ref` são exigidos tanto na assinatura do método chamado quanto no local da chamada.
- Parâmetros `out` podem ser declarados na própria linha da chamada, assim: `Foo(out int importantValue);`
- Se você chamar um método que tem parâmetros `out` mas não tiver interesse no valor atribuído a um ou mais deles, pode usar a variável fictícia [discard][discard] `_`, como em: `Foo(out int _);`

Todas as regras sobre parâmetros `ref` e `out` são impostas pelo compilador.

Parâmetros [`in`][in-parameter] também existem, mas são principalmente uma otimização de desempenho e são discutidos no exercício `structs`, onde são mais relevantes.

A documentação referenciada acima está resumida abaixo:

- [passing-parameters][passing-parameters]: explica como valores podem ser passados como argumentos. Observe que o assunto de structs+parâmetros é discutido no exercício `structs`.
- [ref-parameter][ref-parameter]: descreve como os parâmetros `ref` funcionam.
- [out-parameter][out-parameter]: descreve como os parâmetros `out` funcionam.

Ao estudar a documentação, note que ela usa os seguintes termos:

- parâmetro / parâmetro formal: refere-se ao parâmetro tal como o método chamado o vê.
- argumento: refere-se ao parâmetro tal como quem chama o vê.

Pode-se [argumentar][so-tuples-vs-out] que boa parte do valor dos parâmetros `out` foi eliminada com a introdução de `tuples` no C# 7. O exercício `tuples` mostra `tuples` sendo usados para retornar vários valores.

Embora `ref` seja fácil de usar e não traga penalidades de desempenho, vale a pena ver como os problemas que ele resolve são tratados em uma base de código específica antes de usá-lo amplamente. Existem alternativas, como passar por valor e usar o valor da instrução de retorno do método chamado. Novamente, `tuples` podem ter um papel.

Você verá na documentação que `out` e `ref` não podem ser usados em certas situações, mas pode ignorá-las por enquanto. O compilador vai avisar quando essas situações surgirem.

Observe que `optional parameters` e `named arguments` são discutidos no exercício `method-overloading`.

Os tópicos relacionados de [`ref local`][ref-local] e [`ref return`][ref-return] são discutidos em outro lugar.

## Alocações na pilha

As regras sobre parâmetros e seus modificadores são bastante diretas, de modo que você pode aceitá-las como estão e entendê-las no nível de abstração em que estão. No entanto, se você tem interesse nos mecanismos por trás disso e em por que essas palavras-chave podem fazer diferença no desempenho, pelo menos no caso de `struct`s, pode começar por este [_artigo da Wikipédia_][calling-conventions], observando que o C# usa `stdcall` em x86/64.

A essência da história é que, no caso de parâmetros sem modificador, o **valor** de uma variável é copiado para a pilha do programa para deixá-lo disponível a uma rotina chamada, enquanto para parâmetros `ref`, `out` e `in` um ponteiro (**referência**) para a memória que contém o valor é colocado na pilha do programa, e os valores são atribuídos à memória apontada pela referência.
