# Sobre

Além de classes de caracteres e quantificadores, as expressões regulares podem
descrever a *estrutura* e o *contexto* de um texto. Esses recursos vivem no
mesmo vocabulário [`regexp`][regexp], escrito com o literal `R/ /`.

## Agrupamento e alternância

Os parênteses `( )` agrupam parte de um padrão para que um quantificador ou um
`|` ("isto ou aquilo") se aplique ao grupo inteiro. O `?` depois de um grupo o
torna opcional:

```factor
USING: regexp ;

"abab"    R/ (ab)+/ matches? .             ! => t
"cat"     R/ cat|dog/ matches? .           ! => t
"$100.50" R/ \$\d+(\.\d{2})?/ matches? .   ! => t
"$100"    R/ \$\d+(\.\d{2})?/ matches? .   ! => t   (group optional)
```

## Âncoras

```
^    ! start of the string
$    ! end of the string
\b   ! a word boundary
```

Um *limite de palavra* (`\b`) é onde um caractere de palavra (uma letra, um
dígito ou um sublinhado) encontra um caractere que não é de palavra, incluindo
as extremidades da string. Assim, `\bcat\b` casa com `cat` só quando ele
aparece sozinho:

```factor
USING: regexp ;

"cat nap" R/ \bcat\b/ re-contains? .   ! => t
"scatter" R/ \bcat\b/ re-contains? .   ! => f
```

## Lookaround

Um *lookaround* testa o que vem logo antes ou depois de um ponto sem tornar
esses caracteres parte da correspondência: ele tem largura zero.

```
(?=...)    ! lookahead
(?!...)    ! negative lookahead
(?<=...)   ! lookbehind
```

```factor
USING: regexp ;

"spent $100 and $25" R/ (?<=\$)\d+/ all-matching-subseqs .
! => { "100" "25" }

"up 5% then 12%" R/ \d+(?=%)/ all-matching-subseqs .
! => { "5" "12" }
```

## Opções

Uma letra de opção depois do `/` de fechamento muda o padrão inteiro. O `i`
ignora maiúsculas e minúsculas:

```factor
USING: regexp ;

"REFUND" R/ refund/i matches? .   ! => t
```

## Transformando cada correspondência

`map-matches` executa uma quotation em cada correspondência e reúne os
resultados; `each-match` faz o mesmo apenas para efeitos colaterais. Os dois
passam para a quotation o índice `start` da correspondência, o índice `end` e a
string inteira, então `subseq` recupera o texto correspondido:

```
map-matches ( string regexp quot: ( start end string -- obj ) -- seq )
each-match  ( string regexp quot: ( start end string --     ) --     )
```

```factor
USING: math regexp sequences ;

"a1 b22 c333" R/ \d+/ [ subseq length ] map-matches .
! => { 1 2 3 }
```

## O que o Factor não suporta

O motor de regexp do Factor não tem **extração de grupos de captura** (um grupo
`( )` estrutura o padrão, mas você não consegue ler de volta o texto com que
ele casou), nem **back-references** (`\1`), nem quantificadores
**lazy/non-greedy** (`*?`, `+?`). O lookaround é o substituto idiomático para
os grupos de captura: case com a parte que você quer, reconhecida pelo contexto
ao redor dela.
