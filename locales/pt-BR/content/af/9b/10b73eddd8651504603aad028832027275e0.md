# Testes

Rodar os testes envolve rodar `cmake -G` e depois usar o comando de build adequado para a sua plataforma.
As instruções detalhadas de como fazer isso estão na página [Rodando os testes][cpp-tests-instructions] do C++ no exercism.org.

## Passando nos testes

Quando você começa um novo exercício localmente, os arquivos vêm configurados para que apenas o primeiro teste seja executado.
Faça esse primeiro teste compilar, linkar e passar seguindo as [três leis do desenvolvimento orientado a testes][three-laws-of-tdd].
Crie apenas a estrutura suficiente declarando namespaces, funções, classes etc., para satisfazer os erros do compilador e fazer o teste falhar.
Depois escreva apenas o código suficiente para fazer o teste passar.
Quando você fizer isso, descomente o próximo teste movendo a linha `if defined(EXERCISM_RUN_ALL_TESTS)` para depois do próximo teste.

Veja o exemplo abaixo, do exercício Bob (arquivo `bob_test.cpp`, linha 15):

```diff
-#if defined(EXERCISM_RUN_ALL_TESTS)
TEST_CASE("shouting")
{
    REQUIRE("Whoa, chill out!" == bob::hey("WATCH OUT!"));
}
+#if defined(EXERCISM_RUN_ALL_TESTS)
```

Mover essa linha para depois do próximo teste pode causar erros de compilação, já que novas construções podem ser usadas sem que você as tenha declarado ou definido ainda.
De novo, corrija os erros de compilação minimamente para obter um teste que falha, depois mude o código minimamente para passar no teste, refatore sua implementação pensando em legibilidade e expressividade e então siga para o próximo teste.

Procure usar os recursos padrão do C++17 em vez de escrever seus próprios algoritmos ou recursos de baixo nível na mão.
