# Sobre

O módulo `Time` serve para exibir datas e horários legíveis por humanos. Embora seja tecnicamente possível manipular horários com `Time`, existem pacotes da comunidade Elm muito mais adequados para essa tarefa, como [`justinmimbs/date`][date] ou [`CoderDennis/elm-time-format`][elm-time-format].

## Posix

Os horários são representados pelo tipo opaco `Posix`, que encapsula o tempo Unix epoch, o número de milissegundos decorridos desde 1º de janeiro de 1970 à meia-noite UTC.
Um `Posix` é um valor não ambíguo que não varia entre fusos horários e, por isso, é uma boa escolha para guardar horários.
Em uma aplicação Elm, os horários `Posix` normalmente vêm de fontes externas, como o navegador.

É possível transformar um `Posix` em um número de milissegundos, e vice-versa, com as seguintes funções:

```elm
posixToMillis : Posix -> Int
millisToPosix : Int -> Posix
```

## Fusos horários

No nosso dia a dia, nós, humanos, geralmente não lemos um `Posix` e preferimos o horário local, que depende da nossa localização na Terra e das regras locais de horário de verão.
Em Elm, essas informações ficam codificadas no tipo opaco `Zone`, normalmente fornecido pelo navegador.

Existe um `Zone` especial que está sempre acessível:

```elm
utc : Zone
```

## Horários legíveis

Com um `Posix` e um `Zone`, temos informação suficiente para exibir o horário local em qualquer nível de detalhe.
Veja uma lista das funções que podem ser usadas para isso:

```elm
toYear : Zone -> Posix -> Int
toMonth : Zone -> Posix -> Month
toDay : Zone -> Posix -> Int
toWeekday : Zone -> Posix -> Weekday
toHour : Zone -> Posix -> Int
toMinute : Zone -> Posix -> Int
toSecond : Zone -> Posix -> Int
toMillis : Zone -> Posix -> Int
```

Você deve ter notado mais dois tipos personalizados de `Time`:

```elm
type Month = Jan | Feb | Mar | Apr | May | Jun | Jul | Aug | Sep | Oct | Nov | Dec
type Weekday = Mon | Tue | Wed | Thu | Fri | Sat | Sun
```

Fica a cargo de quem usa converter esses tipos personalizados em valores legíveis por humanos.
