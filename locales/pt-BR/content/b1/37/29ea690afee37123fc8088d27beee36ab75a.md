# Classes genéricas

Você usa `ARRAY{STR}`, `FMAP{STR,INT}` e `FSET{STR}` desde o início.
As chaves sempre guardaram um tipo. Agora você escreve uma classe com
chaves próprias.

## O problema

O setor de achados e perdidos precisa de uma caixa que guarde uma coisa e
lembre quem a entregou. Uma caixa para um suéter:

```sather
class JUMPER_BOX is
   attr item : JUMPER;
   ...
end;
```

e depois a mesma classe de novo para uma garrafa de água, e de novo para um
celular. Três cópias que diferem em uma palavra.

## O parâmetro de tipo

```sather
class LOST_BOX{T} is

   attr item : T;

   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;

end; -- class LOST_BOX{T}
```

O `{T}` depois do nome da classe é um **parâmetro de tipo**. `T` não é um
tipo: é um substituto para o tipo que for fornecido quando a classe for
usada. Dentro da classe, `T` é usado exatamente como qualquer nome de tipo.

## Como usar

Forneça o tipo entre chaves:

```sather
   jumper ::= #LOST_BOX{STR}("blue jumper");
   count ::= #LOST_BOX{INT}(3);

   jumper.item      -- "blue jumper", a STR
   count.item       -- 3, an INT
```

`LOST_BOX{STR}` e `LOST_BOX{INT}` são dois tipos diferentes. Colocar um
onde o outro é esperado é um erro que o compilador detecta, exatamente como
se você tivesse escrito as duas classes à mão, o que, na prática, é o que
acontece: Sather constrói uma classe separada a partir do molde para cada
tipo realmente usado.

Então isso não tem custo nenhum em tempo de execução, nem perda de
informação de tipo: `jumper.item` é mesmo um `STR`, não algo que precise ser
verificado ou convertido.

## Mais de um

Uma classe pode receber vários parâmetros, separados por vírgulas.
`FMAP{K,T}` é o exemplo que você já conhece.

```sather
class LABELLED{L,T} is
   attr label : L;
   attr item : T;
   ...
end;
```

## Nomes

Letras maiúsculas únicas, por convenção: `T` para uma coisa, `K` para uma
chave, `E` para um elemento. A biblioteca as usa em toda parte.
