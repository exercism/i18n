# Introdução

Este exercício parte do que você viu em [Observador de Aves no Quintal][backyard-birdwatcher] e apresenta as palavras de ordem superior que recebem uma *quotation*, um trecho de código entre colchetes `[ ]`, para conduzir a operação.

## Quotations como valores

Uma quotation é apenas um trecho literal de código. Você pode passá-la como dado para outra palavra:

```factor
{ 1 2 3 4 5 } [ 2 > ] count .   ! => 3
```

Aqui, `[ 2 > ]` é uma quotation que recebe um número e deixa um boolean. `count` a executa em cada elemento e conta os resultados verdadeiros.

## Filtrar e rejeitar

```
find      ( seq quot    -- i/f elt/f ) ! first match: index and element, or f f
find-last ( seq quot    -- i/f elt/f ) ! same, but searches from the end
filter    ( seq quot    -- newseq )    ! keep elements where quot is truthy
reject    ( seq quot    -- newseq )    ! drop them instead
without   ( seq exclude -- newseq )    ! drop every element that's in `exclude`
sift      ( seq         -- newseq )    ! drop every `f`, keep the rest
```

```factor
{ 1 2 3 4 5 } [ 3 > ] find .s
! => 3            (index)
! => 4            (element)
{ 1 2 3 4 5 } [ 3 > ] find-last .s
! => 4            (index)
! => 5            (element)
{ 1 2 3 4 5 } [ even? ] filter .    ! => { 2 4 }
{ 1 2 3 4 5 } [ even? ] reject .    ! => { 1 3 5 }
"hello world" " ld" without .       ! => "heowor"
{ 1 f 2 f 3 } sift .                ! => { 1 2 3 }
```

`without` trata seu segundo argumento como um conjunto: qualquer elemento de `seq` que seja `=` a *qualquer* elemento de `exclude` é descartado. `sift` é o caso especial de `reject` sem quotation: ele mantém todos os elementos exceto `f`, o que é útil para limpar as lacunas que um `map` anterior deixou para trás.

### Manter o resultado do teste

`find` devolve o *elemento* que casou. Quando o teste já *calcula* o valor que você realmente quer, `map-find` economiza uma segunda passada: ele executa a quotation em cada elemento e retorna o primeiro resultado diferente de `f` **e** o elemento que o produziu.

```
map-find ( seq quot: ( elt -- result/f ) -- result elt )
```

```factor
USING: kernel math sequences ;

! First multiple of 3, paired with that multiple divided by 3.
{ 11 13 15 17 } [ dup 3 mod 0 = [ 3 /i ] [ drop f ] if ] map-find .s
! => 5            (result: 15/3)
! => 15           (element)
```

A quotation retorna `f` para os elementos que não se qualificam e o resultado que você quer manter para o que se qualifica. Se nada se qualificar, `map-find` deixa `f f`, assim como `find`.

### Filtrar registros por um slot

Quando os elementos são *tuples*, o predicado geralmente projeta um slot pelo seu leitor gerado automaticamente `slot>>` e testa sobre ele:

```factor
USING: accessors sequences ;

TUPLE: customer name vip? ;

{
    T{ customer { name "Alice" } { vip? t } }
    T{ customer { name "Bob"   } { vip? f } }
    T{ customer { name "Carol" } { vip? t } }
}
[ vip?>> ] filter [ name>> ] map .
! => { "Alice" "Carol" }
```

## Encadear um valor fixo com `with`

Às vezes o predicado precisa de um valor que é o mesmo em todas as chamadas: um limite, um divisor, uma string de destino. `with` (em [`kernel`][kernel]) embute esse valor fixo na quotation, transformando uma quotation de dois argumentos `( value elt -- ? )` na quotation de um argumento que `filter`, `count`, `map` e `each` esperam:

```
with ( value seq quot -- seq curry )
```

Cada chamada por elemento vê `( value elt )` na pilha: o valor fixo primeiro, o elemento atual depois:

```factor
USING: kernel sequences ;

! Count elements greater than 5 — value=5 is threaded in
5 { 2 7 4 9 1 8 } [ < ] with count .   ! => 3
```

## Mapear e iterar

`map` (em [`sequences`][sequences]) aplica uma quotation a cada elemento e retorna o array de resultados. `each` faz a mesma caminhada, mas descarta os resultados, o que é útil quando a quotation roda puramente pelos seus efeitos colaterais. `2map` percorre *duas* sequências em sincronia e combina os elementos correspondentes; `2each` e `2reduce` são seus primos de apenas efeitos colaterais e de redução; `zip` é o atalho para "emparelhá-los sem combiná-los":

```
map     ( seq       quot           -- newseq )
map-as  ( seq       quot exemplar  -- newseq )
each    ( seq       quot           -- )
2map    ( seq1 seq2 quot           -- newseq )
2each   ( seq1 seq2 quot           -- )
2reduce ( seq1 seq2 identity quot  -- result )
zip     ( seq1 seq2                -- pairs )
```

`2reduce` encadeia um acumulador pelas duas sequências ao mesmo tempo: sua quotation recebe `( accumulator elt1 elt2 -- accumulator' )`. Aqui ele acumula um produto escalar: cada par é multiplicado, e os produtos são somados (`1*10 + 2*20 + 3*30`):

```factor
{ 1 2 3 } { 10 20 30 } 0 [ * + ] 2reduce .   ! => 140
```

`map-as` é o primo de `map` que força o tipo da sequência de saída: passe um `{ }` ou `V{ }` vazio como exemplar para sobrescrever o padrão do tipo de entrada (caso contrário, mapear uma string para algo que não sejam chars dá erro quando o Factor tenta empacotar os resultados de volta em uma string).

```factor
USING: formatting math sequences ;

{ 1 2 3 } [ sq ] map .                         ! => { 1 4 9 }
{ 1 2 3 } [ . ] each                           ! prints 1, then 2, then 3
{ 1 2 3 } { 10 20 30 } [ + ] 2map .            ! => { 11 22 33 }
{ "x" "y" } { 1 2 } [ "%s%d" sprintf ] 2map .  ! => { "x1" "y2" }
{ 1 2 3 } { 10 20 30 } [ + . ] 2each           ! prints 11, then 22, then 33
{ "a" "b" "c" } { 1 2 3 } zip .                ! => { { "a" 1 } { "b" 2 } { "c" 3 } }
```

As duas formas que percorrem duas sequências param no comprimento da entrada mais curta. `zip` é o mesmo que `[ 2array ] 2map`: manter os pares em vez de colapsá-los.

## Ordenação

`sort` retorna uma cópia ordenada em ordem natural; `sort-by` (em [`sorting`][sorting]) ordena por uma chave extraída de cada elemento:

```
sort    ( seq      -- sortedseq )
sort-by ( seq quot -- sortedseq )
```

```factor
{ 3 1 4 1 5 9 2 6 } sort .
! => { 1 1 2 3 4 5 6 9 }

{ -3 5 -1 4 } [ abs ] sort-by .
! => { -1 -3 4 5 }
```

## Agregar

`map-sum` (em [`sequences`][sequences]) mapeia uma quotation pela sequência e soma os resultados em uma única passada:

```
map-sum ( seq quot -- n )
```

```factor
{ 1 2 3 4 } [ sq ] map-sum .   ! => 30
```

## Mínimo e máximo

`minimum` e `maximum` retornam diretamente o menor ou o maior elemento de uma sequência. `minimum-by` e `maximum-by` (todas em [`sequences`][sequences]) retornam o elemento cuja chave extraída é a menor ou a maior:

```
minimum     ( seq      -- elt )
maximum     ( seq      -- elt )
minimum-by  ( seq quot -- elt )
maximum-by  ( seq quot -- elt )
```

```factor
{ 3 1 4 1 5 9 2 6 } minimum .       ! => 1
{ 3 1 4 1 5 9 2 6 } maximum .       ! => 9

{ -3 5 -1 4 } [ abs ] minimum-by .
! => -1
```

## Escrever sua própria palavra de ordem superior

Quando *sua* palavra recebe uma quotation como argumento de tempo de execução e a repassa para `map`, `filter`, `each` etc., declare sua palavra com `; inline`. Isso diz ao compilador para embutir sua palavra em cada ponto de chamada, onde a quotation é um literal conhecido: sem isso, o compilador não tem como saber o efeito de pilha da quotation.

```factor
USING: math sequences ;

: tax-on ( inventory quot -- total )
    map-sum ; inline

{ { "shirt" 20 } { "hat" 15 } } [ second 1/10 * ] tax-on .
! => 3+1/2
```

Palavras construídas apenas com quotations literais não precisam de `inline`: só as que repassam uma quotation *recebida*.

Se uma palavra `inline` dessas chamar a si *mesma* (um combinador recursivo), declare-a `; inline recursive` em vez disso. Sem a palavra extra, o compilador para com *"The inline recursive word ... must be declared recursive"*, que diz exatamente o que acrescentar.

## Pegar o segundo elemento

Para um array de 2 elementos, `second` retorna seu segundo elemento. `first` retorna o primeiro. Ambas estão em [`sequences`][sequences].

## Números para strings

`number>string ( n -- str )` (em [`math.parser`][math.parser]) transforma um número em sua forma de string decimal:

```factor
42 number>string .     ! => "42"
3.5 number>string .    ! => "3.5"
```
