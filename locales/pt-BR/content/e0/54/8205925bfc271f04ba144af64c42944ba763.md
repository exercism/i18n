# Notas sobre chaves, colchetes e parênteses

O Tcl é uma [linguagem muito simples](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm),
mas a forma como o intérprete analisa o código tem alguns casos extremos desagradáveis.

## Chaves

No Tcl, as chaves são simplesmente uma forma de delimitar um bloco de texto; esse texto pode ser interpretado como código ou como dados. Dentro das chaves, podem aparecer chaves aninhadas, mas as chaves aninhadas precisam estar balanceadas. A página de manual do Tcl diz o seguinte:

> As chaves se aninham dentro da palavra: para cada chave de abertura adicional deve haver
> uma chave de fechamento adicional (no entanto, se uma chave de abertura ou de fechamento
> dentro da palavra estiver _escapada com uma barra invertida_, ela não é contada na
> localização da chave de fechamento correspondente).

O texto ali é bem específico: se você quiser ter um caractere de chave de abertura ou de fechamento sem par, ele precisa ser escapado com uma barra invertida. Então não faça isto:
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "{"}]
    # ......................^ will not work
}
```
Você precisa fazer isto
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "\{"}]
    # ......................^^ will work
}
```

Isso pode ser problemático por causa da forma como o Tcl analisa comentários, que é diferente da maioria das linguagens. Há mais discussão na [wiki do Tcl](https://wiki.tcl-lang.org/page/Why+can+I+not+place+unmatched+braces+in+Tcl+comments).

## Colchetes

Da mesma forma, como o Tcl usa colchetes para [substituição de comandos](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M11), mesmo dentro de strings entre aspas duplas, você precisa tomar cuidado ao escapar colchetes de abertura.

## Parênteses

Com exceção das [variáveis de array associativo](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M12), os parênteses são simplesmente caracteres comuns.
