# Sobre

O tipo `Result` permite que uma função retorne um único valor que indica todas estas coisas:
- Se a operação teve sucesso ou falhou
- Em caso de sucesso, o valor resultante da operação
- Em caso de falha, o motivo da falha

Em outras linguagens de programação que não têm algo como o tipo `Result`, é comum encontrar os seguintes padrões para alcançar esses objetivos:
- Uma função que retorna um código numérico indicando sucesso ou o motivo da falha e que exige um parâmetro de saída para receber o valor em caso de sucesso.
- Uma função que retorna o valor em caso de sucesso ou NULL em caso de erro, e depois uma função diferente para obter o código de erro que indica o motivo da falha.

Outro mecanismo comum de tratamento de erros é a exceção, que sai abruptamente da função atual e
transfere o controle para o primeiro tratador na pilha de chamadas quando ocorre uma falha.  
Se nenhum tratador "capturar" a exceção, o programa é abortado.

## Vantagens de usar o tipo `Result`

* __Segurança em tempo de compilação__: ao tornar o sucesso ou a falha de uma chamada de função explícito no sistema de tipos, o compilador consegue garantir que o código que faz a chamada trate todos os casos de falha, evitando uma grande categoria de bugs que poderiam ocorrer com valores nulos.

* __Segurança em tempo de execução__: em vez de usar `null`, o tipo `Result` usa `Error` para representar uma falha, o que torna impossível a ocorrência de uma `NullReferenceException`.

* __Tratamento explícito de erros__: o código que chama uma função que retorna um `Result` precisa reconhecer que a
chamada pode falhar; o código que faz a chamada deve tratar essas falhas de forma intencional.  Não há falhas silenciosas nem exceções surpresa.

* __Fluxo de controle previsível__: um `Result` é retornado como qualquer outro valor; ele não salta para fora da pilha de chamadas como uma exceção.  Você sempre sabe de onde os erros vêm e como eles se propagam.

* __Legibilidade e facilidade de manutenção aprimoradas__: ao retornar um `Result`, a assinatura de uma função indica claramente o comportamento esperado em caso de sucesso e de falha.

## Uso

O tipo `Result` é um tipo genérico que contém dois tipos subjacentes:
- O tipo do valor resultante em uma operação bem-sucedida
- O tipo que representa o motivo da falha em caso de falha

O tipo `Result` também é uma [união discriminada][discriminated-union] com os seguintes casos possíveis:
* `Ok <value>`, que representa um resultado bem-sucedido
* `Error <reason>`, que representa uma falha

A função a seguir mostra como criar um valor `Result`:

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

Neste exemplo, o valor `Ok` é uma string (o nome informado), e o valor `Error` também é uma string (a causa do erro, em formato legível para humanos).

## Lendo o conteúdo de um valor `Result`

Considere a definição de tipo e a assinatura de função a seguir:

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

O código que chama a função `openFile` pode usar correspondência de padrões para tratar os casos de sucesso e de falha, como no exemplo a seguir:

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
