# Sobre

Uma declaração `MACRO:` é uma palavra cujo *corpo* roda em tempo de compilação. O corpo consome argumentos literais da pilha de compilação e precisa deixar uma quotation nela. O compilador então substitui a chamada da macro por essa quotation, de modo que o programa em tempo de execução nunca vê a macro, apenas o código que ela produziu.

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- compound )
    dup append ;
```

Se quem chama escreve `[ 1 + ] twice`, o compilador roda o corpo com `[ 1 + ]` na pilha, recebe de volta `[ 1 + 1 + ]` e insere isso no lugar. Não há custo em tempo de execução: o laço ou combinador que a macro substituiu simplesmente desapareceu.

## As entradas precisam ser literais

Como o corpo roda em tempo de compilação, toda entrada precisa ser um *literal* no ponto da chamada: uma quotation `[ … ]`, um número, um array, uma string. Passar um valor que não é literal (um valor conhecido só em tempo de execução) é um erro de compilação.

```factor
! works: [ 1 + ] is a literal quotation
: inc-twice ( x -- y ) [ 1 + ] twice ;

! refused: f is a literal, but the macro can't run with a non-quotation
! input where the body expects to call `append` on it
```

## Entradas estruturais geram saídas estruturais

As macros interessantes recebem uma *estrutura* (um array, uma sequência literal de pares) e produzem código cuja forma depende dessa estrutura. O `each-literal` deste exercício recebe uma sequência literal e uma quotation e emite uma cópia currificada e embutida da quotation para cada elemento. O programa em tempo de execução é código linear, sem `each` e sem despacho por elemento, e a iteração da sequência aconteceu inteiramente em tempo de compilação.

## Por que não há problema de higiene

As macros de Lisp lidam com *higiene*: uma macro que introduz um nome local pode colidir com nomes do ponto da chamada, o que exige `gensym` ou um sistema de higiene. Factor não tem esse problema, porque quotations são sequências de *referências de palavras já resolvidas*: cada palavra é procurada no momento da análise, e não simbolicamente no momento da expansão. Um `dup` dentro de uma quotation construída por macro será sempre `kernel:dup`, independentemente dos nomes que existam no ponto da chamada.

O custo: as macros de Factor não podem introduzir novas ligações como o `defmacro` pode. Elas constroem código a partir de palavras que o analisador já viu. Para a maior parte da metaprogramação, isso basta.

## Formas relacionadas (não exercitadas aqui)

- `MACRO::`: variante com locals de `MACRO:`, do mesmo jeito que `::` é a forma com locals de `:`. Útil quando o corpo faz referência às suas entradas mais de uma vez.
- `<< … >>`: bloco de avaliação em tempo de análise. Roda Factor comum em tempo de compilação, sem o contrato de devolver uma quotation. É útil para calcular um valor que precisa existir no momento da análise (por exemplo, uma `CONSTANT:` derivada de uma consulta ao ambiente).
- `SYNTAX:`: *palavras de análise*. Uma coisa bem diferente: elas operam sobre o fluxo de tokens do analisador, não sobre valores, e rodam numa fase ainda mais inicial. Servem para definir novas sintaxes literais (`T{ }`, `H{ }`). Fora do escopo deste conceito.
- `functor:`: templates declarativos que geram conjuntos de palavras relacionadas a partir de uma única especificação. Construídos sobre a maquinaria das macros; território de quem escreve bibliotecas.
