# Introdução

Um conceito anterior apresentou valores de ponto flutuante empacotados: vários números guardados em um único registro `xmm`, operados lane a lane e em paralelo.
Os mesmos registradores `xmm` também podem guardar _inteiros_ empacotados.

## Sintaxe

A maior parte do modelo de ponto flutuante SIMD se aplica, sem mudanças, aos inteiros empacotados:

- Um registrador de 128 bits é dividido em lanes
- As instruções atuam em paralelo sobre as lanes que estão na mesma posição
- Os operandos de memória seguem as mesmas regras de alinhamento de 16 bytes

No entanto, a sintaxe é um pouco diferente:

1. Um _prefixo_ `p` para indicar que a instrução opera sobre dados _empacotados_.
2. A operação realizada, com o mesmo nome da sua equivalente não SIMD (também chamada de _escalar_) (por exemplo, `add`, `mul`, etc.).
3. Um sufixo para indicar o tamanho de cada lane.

Os inteiros empacotados têm quatro tamanhos de lane, e cada um tem seu próprio sufixo:

| largura da lane | bytes | lanes em 128 bits | sufixo |
|-----------------|-------|-------------------|--------|
| byte            | 1     | 16                | b      |
| word            | 2     | 8                 | w      |
| dword           | 4     | 4                 | d      |
| qword           | 8     | 2                 | q      |

Por exemplo:

| instrução | significado                                      |
|-----------|--------------------------------------------------|
| `paddb`   | `add` empacotado, lanes de 8 bits (16 lanes)     |
| `paddw`   | `add` empacotado, lanes de 16 bits (8 lanes)     |
| `paddd`   | `add` empacotado, lanes de 32 bits (4 lanes)     |
| `paddq`   | `add` empacotado, lanes de 64 bits (2 lanes)     |

Algumas instruções recebem lanes de um tamanho como entrada, mas produzem lanes de outro tamanho como saída.
Elas seguem a mesma convenção geral, mas com _dois_ sufixos de tamanho.
O primeiro indica o tamanho da lane de entrada, o segundo indica o tamanho da lane de saída:

| instrução  | significado                                          |
|------------|------------------------------------------------------|
| `pmovsxwd` | `movsx` empacotado, de lanes de 16 bits para lanes de 32 bits |
| `pmuldq`   | `mul` empacotado, de lanes de 32 bits para lanes de 64 bits   |

## Movimentações de memória

Duas instruções com nome de inteiro copiam 128 bits entre um registrador `xmm` e a memória:

| instrução | descrição                                                    |
|-----------|--------------------------------------------------------------|
| `movdqa`  | copia inteiros empacotados de ou para um local _alinhado_    |
| `movdqu`  | copia inteiros empacotados de ou para um local _desalinhado_ |

Elas se comportam como `movaps` e `movups`: `movdqa` gera falta em um endereço desalinhado, enquanto `movdqu` aceita qualquer um.
Todas as quatro copiam 128 bits sem interpretá-los.
O par com nome de inteiro é usado com dados inteiros por convenção, não por obrigação.

~~~~exercism/note
Aqui, `dq` significa `double-qword`, ou seja, 128 bits (16 bytes).
~~~~

## Adição e subtração

A adição e a subtração seguem a regra de nomenclatura:

```x86asm
paddb xmm0, xmm1 ; 16 lanes: each  8-bit, xmm0 += xmm1
paddw xmm2, xmm3 ;  8 lanes: each 16-bit, xmm2 += xmm3

psubd xmm4, xmm5 ;  4 lanes: each 32-bit, xmm4 -= xmm5
psubq xmm6, xmm7 ;  2 lanes: each 64-bit, xmm6 -= xmm7
```

Não há uma forma separada para com sinal e sem sinal.
No complemento de dois, a adição e a subtração produzem os mesmos bits independentemente de as lanes serem lidas com sinal ou sem sinal, então uma única instrução atende aos dois casos.
A interpretação fica por sua conta, exatamente como com `add` e `sub` escalares.

Essas instruções **dão a volta** em caso de transbordamento, como suas equivalentes escalares.
Uma lane de 8 bits guarda valores módulo 256, então um `paddb` de `200 + 100` produz `300 - 256 = 44`, descartando os bits que não cabem.

Repare que esses bits extras não passam para a próxima lane.
Cada lane é operada separadamente das demais, mesmo que compartilhem o mesmo registrador.

## Adição e subtração com saturação

O SIMD de inteiros acrescenta uma operação que o SIMD de ponto flutuante não tem: adição e subtração **saturantes**, que _limitam_ o valor em vez de dar a volta.
Um resultado acima do intervalo da lane se torna o maior valor que a lane pode guardar; um resultado abaixo do intervalo se torna o menor.

As formas saturantes inserem `s` (com sinal) ou `us` (sem sinal) antes do sufixo de tamanho:

| instrução | significado                                 |
|-----------|---------------------------------------------|
| `paddsb`  | `add`, saturante, lanes de 8 bits com sinal |
| `paddusb` | `add`, saturante, lanes de 8 bits sem sinal |
| `psubsw`  | `sub`, saturante, lanes de 16 bits com sinal |
| `psubusw` | `sub`, saturante, lanes de 16 bits sem sinal |

O intervalo de limitação é todo o intervalo representável para um inteiro do tamanho e da presença de sinal correspondentes.
Para um byte:

- Bytes sem sinal se limitam a `[0, 255]`: um `paddusb` de `200 + 100` dá `255`, e um `psubusb` de `5 - 10` dá `0`.
- Bytes com sinal se limitam a `[-128, 127]`: um `paddsb` de `100 + 50` dá `127`.

A saturação importa quando uma lane guarda uma quantidade limitada, como um canal de pixel ou uma amostra de áudio.
Dar a volta deixaria um pixel brilhante demais escuro, enquanto a limitação o mantém no brilho máximo, que é o resultado que você quer.

~~~~exercism/note
A adição e a subtração saturantes existem apenas para lanes de byte e de word, não para dword ou qword.
~~~~

## Multiplicação

Multiplicar dois valores de N bits pode produzir um produto de 2N bits, mas a lane de destino tem apenas N bits de largura.
As operações SIMD resolvem isso especificando qual metade do produto guardar, os N bits baixos ou os N bits altos.

Para lanes de 16 bits, usam-se três instruções:

| instrução | significado                                                    |
|-----------|----------------------------------------------------------------|
| `pmullw`  | `mul`, lanes de 16 bits, mantém os 16 bits baixos de cada produto |
| `pmulhw`  | `mul`, lanes de 16 bits, mantém os 16 bits altos, operandos com sinal |
| `pmulhuw` | `mul`, lanes de 16 bits, mantém os 16 bits altos, operandos sem sinal |

Os 16 bits baixos de um produto são os mesmos independentemente de os operandos serem lidos com sinal ou sem sinal, então há um único `pmullw`.

Os 16 bits altos, porém, variam conforme a presença de sinal do resultado.
É por isso que a multiplicação da metade alta tem formas separadas para multiplicação com sinal e sem sinal:

1. `pmulhw`, para multiplicação com sinal.
2. `pmulhuw`, com um `u` extra, para multiplicação sem sinal.

Repare na sintaxe:

1. Um `p`, de inteiro empacotado.
2. A operação realizada, `mul`.
3. Um `h`, para indicar que os bits altos ("high") do resultado estão sendo selecionados.
4. Um `u` opcional se o resultado deve ser interpretado como sem sinal (ou seja, ele não é estendido com sinal).
5. Por fim, o sufixo de tamanho `w`, para indicar que é uma operação de word (16 bits).

A multiplicação empacotada para words segue exatamente a regra acima.
A multiplicação de dwords (32 bits) também segue a regra, mas há apenas a variante que seleciona a metade baixa: `pmulld`.

Não há variante para a multiplicação de dwords que selecione os bits altos.
No entanto, há variantes que _ampliam_ a multiplicação, guardando o produto completo de 64 bits das lanes de _índice par_ (ou seja, as lanes nas posições 0 e 2):

| instrução | significado                                                                       |
|-----------|-----------------------------------------------------------------------------------|
| `pmuludq` | multiplica os elementos de 32 bits de índice par, sem sinal, em 2 produtos completos de 64 bits |
| `pmuldq`  | multiplica os elementos de 32 bits de índice par, com sinal, em 2 produtos completos de 64 bits |

Repare que a sintaxe usa `dq`, possivelmente com um `u` antes dele para multiplicação sem sinal.
Isso porque as instruções recebem lanes de `dword` e produzem lanes de `qword`.

## Divisão

Não há divisão de inteiros empacotada.
O código que precisa dela converte os valores para ponto flutuante, divide e converte de volta.

## Ampliação de inteiros

Há equivalentes empacotados para `movsx` e `movzx`.
Eles seguem a mesma sintaxe que mencionamos para instruções que recebem entradas com um tamanho de lane diferente do da saída:

```x86asm
pmovsxwd xmm0, xmm1   ; 4 words -> 4 dwords, sign-extended
pmovzxbw xmm0, xmm1   ; 8 bytes -> 8 words, zero-extended
```

Repare que o número de lanes é definido pela largura maior (a de saída).
A instrução lê essa quantidade de lanes da parte baixa da origem.
Essa é a mesma semântica que já vimos para as instruções `cvt` empacotadas entre números de ponto flutuante de precisão simples e dupla.

## Conversão entre inteiros e números de ponto flutuante

Há instruções para converter entre inteiros de 32 bits com sinal e lanes de ponto flutuante.
Elas seguem a sintaxe usual das instruções `cvt` e `cvtt`, mas, em vez de `si`, um inteiro empacotado é representado por `dq`:

```x86asm
cvtdq2ps xmm0, xmm1 ; convert 32-bit signed integers in xmm1 to 32-bit floats in xmm0
cvtdq2pd xmm2, xmm3 ; convert 32-bit signed integers in xmm3 to 64-bit floats in xmm2
cvtps2dq xmm4, xmm5 ; convert 32-bit floats in xmm5 to 32-bit signed integers in xmm4
```

~~~~exercism/caution
As instruções que usam `pi` para representar inteiros empacotados escrevem nos registradores `mmx` legados e estão efetivamente obsoletas no x86-64.
Prefira as formas `dq`, que usam registradores `xmm`.
~~~~

Os mesmos comentários feitos para a conversão escalar entre números de ponto flutuante e inteiros valem aqui.
Os números de ponto flutuante são arredondados de acordo com um registrador especial chamado MXCSR, cujo modo você não pode presumir na entrada da função.
Há uma variante `cvtt` (com um `t` extra) que sempre trunca o resultado.

Também é possível usar `round` para deixar os valores de ponto flutuante empacotados em um estado conhecido antes de converter.
O valor de controle do `round` é o mesmo do `round` escalar, e a sintaxe também é a mesma para valores de ponto flutuante empacotados:

```x86asm
roundps xmm0, xmm1, 1 ; xmm0 = floor(xmm1), packed 32-bit floats
roundpd xmm2, xmm3, 2 ; xmm2 = ceil(xmm3), packed 64-bit floats
```
