# Instruções adicionais

## Gerando valores pseudoaleatórios em Lean

Em linguagens funcionais, a maioria das funções é _pura_.
Isso significa que elas sempre retornam a mesma saída para o mesmo conjunto de argumentos, e não fazem mais nada.
Em outras palavras, funções puras são determinísticas.

No entanto, por definição, um valor aleatório é imprevisível e não determinístico.
Até mesmo a [pseudoaleatoriedade][pseudorandomness], ou seja, retornar uma sequência de números que _parecem_ aleatórios, não é tão fácil de alcançar em um contexto puro.
Isso acontece porque um [gerador de números pseudoaleatórios (PRNG)][PRNG] precisa acompanhar um estado interno para retornar o próximo número da sequência.

O Lean oferece duas abordagens possíveis para esse problema:

1. Usar uma mônada que permita mudar o estado interno de um PRNG.
Existe uma função pronta, `IO.rand`, que faz exatamente isso.

2. Usar funções puras que recebem um gerador como argumento e retornam não só o valor pseudoaleatório produzido, mas também um gerador atualizado, "preparado" para o próximo número da sequência.

Este exercício usa a segunda abordagem.
Um gerador é passado para cada função que deve produzir um valor pseudoaleatório, e espera-se que a função retorne tanto o valor quanto um gerador atualizado.

Repare que um gerador é determinístico, ou seja, ele _sempre_ produz o mesmo valor.
Para gerar o próximo valor pseudoaleatório de uma sequência, é preciso usar o gerador atualizado.

## Verificando a aleatoriedade

Neste exercício, o caráter aleatório é verificado por um [teste do qui-quadrado][chi-squared-test] com um [nível de significância][p-value] de `p < 0.0001`.

Isso significa que, se um valor de habilidade for gerado de acordo com as instruções, há menos de 0,01% de chance de uma implementação correta falhar no teste por acaso.

Repare que, de acordo com as instruções, um valor de habilidade é _a soma dos três maiores resultados de quatro lançamentos de um d6 não viciado (dado de seis faces)_.
