# Sobre

## Trailing closures

O Swift oferece mais uma variação da sua sintaxe ao lidar com closures, conhecida como [trailing closures][trailing-closures]. Trailing closures aparecem quando o último parâmetro da lista de parâmetros de uma função tem um tipo de função. Nesse caso, se você estiver passando uma closure, ela pode ser escrita _depois_ do parêntese de fechamento, e o rótulo do argumento é omitido. Repare que, se a função tiver apenas um parâmetro, os parênteses podem ser omitidos por completo.

```swift
func fetchURL(_ urlString: String,
              uponReceipt handleResult: (String) -> ()
             )  -> () {
  if let url = URL(string: urlString), let htmlString = fetch(url) {
    handleResult(htmlString)
  }
}

fetchURL("https://www.swift.org") { print($0) }
// prints the fetched html string

["apple", "ball", "carrot"].sorted { $0.count < $1.count }
```

## Várias trailing closures

Embora versões anteriores do Swift só aceitassem o uso de uma única trailing closure, a partir da versão 5.2.4 o Swift oferece suporte a várias trailing closures.

Se uma função tiver mais de uma closure no final da sua lista de parâmetros, a sintaxe de trailing closure pode ser usada para mover todas elas para fora dos parênteses. No entanto, apenas o primeiro rótulo de argumento é omitido; os demais precisam ser rotulados:

```swift
func fetchURL(_ urlString: String,
              uponReceipt handleResult: (String) -> (),
              onFailure handleFailure: () -> ()
             )  -> () {
  if let url = URL(string: urlString), let htmlString = fetch(url) {
    handleResult(htmlString)
  } else {
    handleFailure()
  }
}

fetchURL("https://www.swift.org") {
  print($0)
} onFailure: {
  print("Error: https://www.swift.org could not be fetched")
}
// prints the fetched html string on successful fetch or prints error message on failure
```

[trailing-closures]: https://docs.swift.org/swift-book/LanguageGuide/Closures.html#ID102
