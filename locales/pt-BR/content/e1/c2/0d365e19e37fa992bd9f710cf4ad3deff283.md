# Introdução

TypeScript é JavaScript com sintaxe para tipos, o que faz dele uma linguagem de programação fortemente tipada, com suporte a estilos orientado a objetos, imperativo e declarativo (por exemplo, programação funcional), oferecendo ferramentas melhores em qualquer escala.

Como [você não consegue aprender TypeScript sem aprender JavaScript][handbook-js-or-ts], parte do conteúdo desta trilha é focada em ensinar conceitos de JavaScript e parte dos conceitos foca apenas em recursos específicos do TypeScript.

## (Re-)Atribuição

Existem algumas formas principais de atribuir valores a nomes em TypeScript: usando variáveis ou constantes.
No Exercism, variáveis são sempre escritas em [camelCase][wiki-camel-case]; constantes são escritas em [SCREAMING_SNAKE_CASE][wiki-snake-case].
Não existe um guia oficial a seguir, e diversas empresas e organizações têm guias de estilo diferentes.
_Sinta-se à vontade para escrever variáveis do jeito que você quiser_.
A vantagem de escrevê-las do jeito que os exercícios são preparados é que elas aparecerão destacadas de forma diferente na interface web e na maioria das IDEs.

Variáveis em TypeScript podem ser definidas usando a palavra-chave [`const`][mdn-const], [`let`][mdn-let] ou [`var`][mdn-var].

Uma variável pode referenciar valores diferentes ao longo de sua vida útil quando você usa `let` ou `var`.
Por exemplo, `myFirstVariable` pode ser definida e redefinida várias vezes usando o operador de atribuição `=`:

```typescript
let myFirstVariable = 1
myFirstVariable = 0
myFirstVariable = 42
```

Em contraste com `let` e `var`, variáveis definidas com `const` só podem ser atribuídas uma vez.
Isso é usado para definir constantes em TypeScript.

```typescript
const MY_FIRST_CONSTANT = 10

// Can not be re-assigned.
MY_FIRST_CONSTANT = 20
// => TypeError: Assignment to constant variable.
```

Como o TypeScript consegue detectar isso estaticamente, o compilador do TypeScript também vai gerar um erro:

```typescript
// ^? Cannot assign to 'MY_FIRST_CONSTANT' because it is a constant.(2588)
```

Isso significa que você não precisa rodar o código para detectar o `TypeError`.

## Inferência de tipos

Sem entrar muito fundo no assunto de [inferência de tipos][handbook-type-inference], você deve saber que uma variável atribuída normalmente tem um tipo inferido, mesmo sem uma anotação de tipo.

```typescript
const MY_FIRST_CONSTANT = 10
// ^? const MY_FIRST_CONSTANT: number
```

Esse tipo é então aplicado em todo o código.
Isso também significa que, onde o código a seguir é JavaScript válido:

```javascript
let myFirstVariable = 1
myFirstVariable = 'Some string'
```

O TypeScript reclama:

```typescript
let myFirstVariable = 1
myFirstVariable = 'Some string'
// ^? Type 'string' is not assignable to type 'number'.(2322)
```

Esse recurso garante a segurança de tipos mesmo quando anotações de tipo não são usadas.

## Declarações de Função

Em TypeScript, unidades de funcionalidade são encapsuladas em _funções_, geralmente agrupando funções no mesmo arquivo quando elas andam juntas.
Essas funções podem receber parâmetros (argumentos) e podem _retornar_ um valor usando a palavra-chave `return`.
Funções são invocadas usando a sintaxe `()`.

```typescript
function add(num1: number, num2: number): number {
  return num1 + num2
}

add(1, 3)
// => 4
```

Os parâmetros de uma função geralmente devem ser anotados com um tipo usando dois-pontos (`:`) seguidos do tipo.
Os valores de retorno de uma função podem ser anotados depois de fechar a lista de parâmetros usando dois-pontos (`:`) seguidos do tipo.

## Anotações de Tipo

Como mostrado na declaração de função de `add`, os parâmetros têm uma anotação de tipo explícita `: number`.
Declarações de variáveis, propriedades de classe, declarações de função e muito mais suportam anotações de tipo.

Tanto a anotação de tipo explícita quanto os tipos inferidos são verificados pelo verificador de tipos.

```typescript
add('foo', 3)
// ^? Argument of type 'string' is not assignable to parameter of type 'number'.(2345)
```

## Expondo para Outros Arquivos

Para tornar uma `function`, uma constante ou uma variável disponível em _outros arquivos_, elas precisam ser [exportadas][mdn-export] usando a palavra-chave `export`.
Outro arquivo pode então [importá-las][mdn-import] usando a palavra-chave `import`.
Isso também é conhecido como sistema de módulos.
Um ótimo exemplo é como todos os testes funcionam.
Cada exercício tem pelo menos um arquivo, por exemplo `lasagna.ts`, que contém a _implementação_.
Além disso, existe pelo menos um outro arquivo, por exemplo `lasagna.test.ts`, que contém os _testes_.
Esse arquivo _importa_ as entidades públicas (ou seja, exportadas) para testar a implementação:

```typescript
// file.ts
export const MY_VALUE = 10

export function add(num1, num2) {
  return num1 + num2
}

// file.test.ts
import { MY_VALUE, add } from './file.js'

add(MY_VALUE, 5)
// => 15
```
