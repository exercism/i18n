# Anexo das instruções

## Observação

Não é estritamente necessário modelar os alunos como um objeto separado; você pode usar uma estrutura de dados interna conveniente, já que os requisitos são bem simples (e desde que isso não vaze para os resultados).

~~~~exercism/note
Este exercício foi levemente modificado em relação à problem-specification, pois faz mais sentido separar a adição de alunos e a consulta a eles em métodos separados (em vez de ter um único método fazendo as duas coisas, o que soa menos como Pharo/Smalltalk).
~~~~
