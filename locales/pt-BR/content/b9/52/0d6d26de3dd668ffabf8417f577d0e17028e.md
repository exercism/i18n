## Geral

Não implemente a struct `SimpleLinkedList` como um wrapper em volta de um `Vec`. Em vez disso, aloque os nós no heap.

Uma forma de fazer isso é:

```
pub struct SimpleLinkedList<T> {
    head: Option<Box<Node<T>>>,
}
```

O campo `head` aponta para o primeiro elemento (Node) da lista encadeada.

Essa implementação também exige uma struct `Node` com os seguintes campos:

```
struct Node<T> {
    data: T,
    next: Option<Box<Node<T>>>,
}
```

`data` contém os dados armazenados, e `next` aponta para o nó seguinte (se houver) ou para None.

## Por que `Option<Box<Node<T>>>` e não apenas `Option<Node<T>>`?

Experimente por conta própria. Você vai receber o seguinte erro.

```
| struct Node<T>
| ^^^^^^^^^^^^^^ recursive type has infinite size
...
|     next: Option<Node<T>>,
|     --------------------- recursive without indirection
```

O problema é que, em tempo de compilação, o tamanho de next precisa ser conhecido.
Como `next` é recursivo ("um nó tem um nó que tem um nó..."), o compilador não sabe quanta memória deve ser alocada.
Em contrapartida, [Box](https://doc.rust-lang.org/std/boxed/) é um ponteiro para o heap com tamanho definido.
