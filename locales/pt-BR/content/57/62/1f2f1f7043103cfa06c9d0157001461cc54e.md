# Introdução

Uma função é [recursiva em cauda][recursion-tc] se a _última_ coisa executada pela função for uma chamada a ela mesma.

Cada vez que uma função é chamada, um _quadro da pilha_ com suas variáveis locais e seus argumentos é colocado no topo da [pilha de chamadas de função][call-stack].
Quando a função retorna, o quadro da pilha é removido da pilha.

Funções recursivas em cauda permitem a [otimização de chamada de cauda][tail-call-optimization] (ou a eliminação da chamada de cauda).
É uma otimização que permite reaproveitar o último quadro da pilha na próxima chamada de função, quando é garantido que a função anterior não precisa mais dele.
Isso reduz o risco de estourar a pilha de chamadas de função. Essa situação acontece quando há tantos quadros na pilha de chamadas que não sobra memória para criar mais um.

## Otimização de chamada de cauda no Elm

Em determinadas condições, o compilador do Elm consegue realizar automaticamente uma otimização de chamada de cauda ao compilar para JavaScript.

A otimização pode acontecer em uma função recursiva quando a _última_ operação de um bloco é uma chamada da própria função em uma aplicação simples de função.
Vamos ver alguns exemplos:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

A implementação acima não é recursiva em cauda, porque a última operação do bloco `else` é uma multiplicação `n *`.

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

A implementação acima é recursiva em cauda e será otimizada, porque a última operação do bloco `else` é o `factorialHelper` chamando a si mesmo.
Isso não seria possível em uma função com a assinatura de tipo `Int -> Int` e, na prática, a otimização de chamada de cauda costuma ser obtida definindo funções auxiliares.
