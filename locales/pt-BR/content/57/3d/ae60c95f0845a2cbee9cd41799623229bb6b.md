# Introdução

Uma declaração `GENERIC:` cria uma palavra cujo comportamento depende da *classe* de um dos seus argumentos. O comportamento concreto vem dos *métodos*, definidos com `M:`.

```factor
GENERIC: area ( shape -- n )

TUPLE: square side ;
TUPLE: circle radius ;

M: square area
    side>> dup * ;
M: circle area
    radius>> dup * pi * ;
```

Quando `area` é chamada, o Factor inspeciona o topo da pilha, procura o método mais específico cuja classe corresponde e o executa. Com locals, você pode usar `M::`:

```factor
TUPLE: rectangle width height ;

M:: rectangle area ( r -- n )
    r width>> r height>> * ;

T{ rectangle { width 3 } { height 4 } } area .   ! => 12
```

Os genéricos permitem adicionar novas representações depois, sem alterar o código que chama: `area` já funcionava para `square` e `circle`, e o método de `rectangle` é reconhecido automaticamente em qualquer lugar onde `area` seja chamada.

## Quando um genérico é a escolha certa

Recorra a `GENERIC:` quando:

- Uma mesma operação tem implementações *genuinamente diferentes* para entradas diferentes.
- Você espera que código futuro adicione novos tipos.
- Você quer que o sistema de tipos exija definições por classe.

Se a variação for apenas uma pequena enumeração de rótulos, um `case` é mais simples.

## Como se juntar a um mixin com `INSTANCE:`

Um *mixin* é uma classe genérica que é *aberta*: qualquer um pode registrar uma nova classe como membro. Muitos dos protocolos nativos do Factor (sequences, sets, streams, …) são expostos como mixins, então um tuple personalizado pode optar pelos métodos padrão do protocolo declarando-se uma instância:

```factor
MIXIN: shape
M: shape area                   ! a default area for any shape
    drop 0 ;

TUPLE: my-shape ;
INSTANCE: my-shape shape         ! my-shape is now a `shape`

T{ my-shape } area .   ! => 0
```

Depois do `INSTANCE:`, todo método padrão `M: shape …` passa a despachar automaticamente para `my-shape`, e qualquer código que peça um `shape` aceita um `my-shape`. `M:` serve para adicionar métodos a um genérico; `INSTANCE:` serve para juntar uma classe a um mixin.

## `TYPED::`: entradas verificadas para uma palavra comum

`GENERIC:`/`M:` escolhem um método pela classe de um argumento. Às vezes você não quer despacho, e sim *uma* palavra que exija que suas entradas sejam de uma determinada classe. `TYPED::` (no vocabulário `typed`) é o `::` com uma classe escrita depois de cada nome de entrada:

```factor
TYPED:: triple ( n: integer -- m )
    n 3 * ;

14 triple .   ! => 42
```

`n: integer` lê-se como os locals que você já usa, com a classe escrita depois dos dois-pontos. Não há despacho (uma definição, um comportamento), mas cada argumento agora é verificado em relação à sua classe: uma incompatibilidade como `"x" triple` é rejeitada (*expected input value of type integer but got string*) em vez de passar silenciosamente.

A saída pode ser anotada da mesma forma. `yes?` tipa tanto a entrada quanto o resultado:

```factor
TYPED:: yes? ( word: string -- answer: boolean )
    word "yes" = ;

"yes" yes? .   ! => t
"no" yes? .    ! => f
```

## Funções e constantes matemáticas

Este exercício também conta com algumas palavras de `math.constants` e `math.functions` que você vai conhecer pela primeira vez aqui:

- `pi`: a constante π, de `math.constants`.
- `sin ( x -- y )`, `cos ( x -- y )`: seno e cosseno de um ângulo em radianos.
- `e^ ( x -- y )`: `e` elevado à potência `x`. (Para uma base qualquer, use `^`.)

```factor
pi 2 / sin   ! → 1.0
0 cos        ! → 1.0
1 e^         ! → 2.718281828459045
```
