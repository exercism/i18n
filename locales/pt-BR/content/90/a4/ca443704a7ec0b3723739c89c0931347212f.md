# seção sobre comentários

Go tem [ótimos guias](https://golang.org/doc/effective_go.html) sobre como escrever comentários. Existe um formato padrão que você pode usar para comentários de documentação, e a ferramenta `godoc` consegue transformá-los automaticamente em uma documentação muito bonita.

O comentário do pacote deve começar com a palavra `Package` seguida do nome do pacote, assim:

```go
// Package cook provides handy conversion methods for units typically used in recipes.
package cook
```

Para funções, métodos, constantes e variáveis de pacote exportados, o comentário deve começar com o nome e continuar com uma frase verbal:

```go
// TbsToMl converts tablespoons to milliliters.
func TbsToMl(tbs int) int {
	// ...
}
```

A wiki [CodeReviewComments](https://github.com/golang/go/wiki/CodeReviewComments#comment-sentences) especifica ainda que os comentários de documentação devem ser frases completas, terminadas com um ponto.

Além de melhorar a legibilidade, seguir essas recomendações deixa o seu código com uma cara melhor nas [ferramentas de documentação do Go](http://whipperstacker.com/2015/09/30/go-documentation-godoc-godoc-godoc-org-and-go-doc/) como o [godoc.org](http://godoc.org), o `godoc` e o `go doc`.

Reserve um momento para ler a seção sobre comentários de documentação no guia de estilo oficial, o [Effective Go](https://golang.org/doc/effective_go.html), e entender o raciocínio por trás dessas escolhas.
