# Noções básicas de Unison

## Termos e funções

Termos e funções são as unidades básicas para escrever um programa em Unison.

Um "termo" é o que chamamos de valor estático. Ele é definido com `name = expression`, opcionalmente precedido por uma assinatura de tipo com o formato `name : MyType`. O Unison tem inferência de tipos, então você pode ver a assinatura de tipo omitida em definições simples.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

As funções do Unison se parecem com `myFunctionName argument1 argument2 = myImplementation`: elas começam com o nome da função seguido de argumentos separados por espaços.

```
getMax a b = Nat.max a b
```

As funções podem incluir, opcionalmente, uma assinatura de tipo. O último tipo à direita é sempre o tipo de retorno final da função, e cada argumento é separado pela seta de função `->`.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Para chamar uma função, use o nome dela seguido dos argumentos separados apenas por espaços.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Ao chamar uma função, o Unison vai tentar tratar o que vem imediatamente à direita como argumento dela, o que nem sempre produz a ordem desejada de avaliação das funções.

Digamos que queremos obter o valor `1` da seguinte expressão

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

Como está escrito, `shouldBe1` resulta em `0` porque a ordem implícita de aplicação de funções é `getMax 1 10`, que dá `10`, e depois `10 - 10`, que dá `0`.

Você pode usar parênteses para reagrupar a expressão na ordem de operações desejada.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Expressões de observação

O Unison oferece uma forma de avaliar código rapidamente chamada de "expressão de observação". Uma expressão de observação começa com o símbolo `>` e vem seguida da expressão a ser avaliada. As expressões de observação podem ser escritas em qualquer arquivo com sufixo `.u`. Ao salvar o arquivo, você deve ver o valor da expressão no console do Unison Codebase Manager (UCM). Sempre que possível nesta documentação, vamos tentar mostrar uma expressão com a saída esperada depois de avaliá-la em uma expressão de observação.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Funções multilinha

As funções multilinha do Unison usam indentação ou blocos `let` para definir os limites do código, ou seja, o "escopo lexical".

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Tudo no mesmo nível de indentação compartilha o mesmo escopo, e é por isso que podemos referenciar a variável `newBeginning` na última linha.

## Namespaces e instruções `use`

Namespaces são a forma como agrupamos e organizamos as funções do Unison. Você pode pensar neles como análogos a "diretórios". Eles fornecem estrutura e agrupamento lógico.

Você pode trazer as funções de um namespace para o escopo com uma instrução `use`.

Digamos que você esteja escrevendo uma função que usa valores `List` do Unison. Você sabe que vai precisar de funções como `List.map` e `List.flatMap`, em que `List` é o namespace e `map` e `flatMap` são funções. Para não se repetir, você pode optar por trazer tudo do namespace `List` para o escopo lexical da sua função assim:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

A linha `use List` desfaz a ambiguidade das referências a `map` e `flatMap`. Você pode ler mais sobre [instruções `use` aqui][use-statements].

## A biblioteca padrão do Unison

A biblioteca padrão do Unison se chama `base`. Se você seguiu o guia de início rápido e tem uma base de código criada localmente, a biblioteca padrão já deve ter sido baixada automaticamente. Você pode navegar pela documentação da biblioteca padrão online em [Unison Share][unison-share-base].

## Comentários e literais de documentação

Os comentários em Unison são um recurso um tanto incomum. Ao escrever código Unison, você pode criar texto no seu arquivo com sufixo `.u` que não é interpretado, com a seguinte sintaxe:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_No entanto_, o código Unison é salvo como um hash da sua árvore de sintaxe abstrata, e não como arquivos de texto no sistema de arquivos. Por isso, comentários que são "decorações" de texto de uma determinada função ou termo Unison no arquivo não podem realmente ser salvos nem renderizados novamente para compartilhamento. Se você quiser adicionar uma informação ao seu termo Unison de uma forma que fique armazenada para que outras pessoas leiam e entendam, você pode usar um literal de documentação.

A documentação é um valor de primeira classe na linguagem de programação Unison. Isso significa que um elemento `Doc` pode ser atribuído a um valor, passado como valor para uma função ou retornado como valor de uma função. Os elementos de literal de documentação são abertos e fechados com chaves duplas. Veja como podemos usar o elemento `Doc` como comentário.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
