# Contratos

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| Cláusula | Diz | De quem é a culpa se for violada |
| --- | --- | --- |
| `pre` | o que precisa valer na entrada | de quem chama |
| `post` | o que vale no retorno | da rotina |

As duas recebem um `BOOL` e podem usar os argumentos da rotina e os atributos do objeto. `post` também pode usar `result`, o valor que está sendo retornado.

## assert

Dentro do corpo de uma rotina, `assert` afirma algo que precisa ser verdadeiro naquele ponto:

```sather
      assert load <= limit;
```

É verificado pela mesma opção que as outras verificações.

## Invariantes de classe

Uma classe pode afirmar algo que é verdadeiro para todos os seus objetos entre chamadas:

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

Verificado na entrada e na saída de toda rotina pública, quando a verificação está ativada.

## Como ativar

| Opção | Verifica |
| --- | --- |
| `-chk` | tudo: pre, post, assert, invariante, limites, aritmética |
| `-chk_no` | nada |

Repare que `-chk_pre` sozinho *não* ativa a verificação de pré-condições neste compilador; quem funciona é `-chk`. Uma violação imprime a rotina e a linha do código-fonte e para o programa. Não é uma exceção, e `protect` não vai capturá-la.

O costume é desenvolver e testar com `-chk` e publicar sem ele, assim as verificações não custam nada no programa publicado. Isso só compensa se os testes realmente exercitarem esses caminhos.

## O que faz um bom contrato

Diga o que a rotina precisa, não como ela funciona:

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

Um `post` que repete o corpo não ensina nada a ninguém:

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## Herança

Um subtipo pode enfraquecer um `pre` e reforçar um `post` (aceitar mais, prometer mais), mas nunca o contrário, senão o código escrito para o supertipo quebraria. É justamente essa regra que os contratos existem para tornar verificável.
