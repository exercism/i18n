# Trilha

Uma trilha é composta de muitas partes diferentes.

## Metadados

A configuração e os metadados da trilha são especificados no arquivo `config.json`. Nele estão listados os exercícios, os conceitos, as configurações do editor e muito mais. Confira a [documentação do config.json](/docs/building/tracks/config-json).

## Conceitos

Todos os exercícios de conceito e de prática de uma trilha envolvem _conceitos_. Esses conceitos são entidades próprias e independentes. Confira a [documentação](/docs/building/tracks/concepts) para saber mais.

Os conceitos ensinados nos exercícios de conceito da trilha formam um _currículo_.
O _currículo_ é mostrado aos estudantes como um _mapa de conceitos_.
Confira a [documentação do _mapa de conceitos_](/docs/building/tracks/concept-map) para saber como montar o mapa de conceitos de um _currículo_.

Para saber mais sobre como projetar um currículo, confira a [documentação do currículo](/docs/building/tracks/syllabus).

## Exercícios

As trilhas têm dois tipos de exercícios:

- Exercícios de conceito: são projetados para ensinar um ou mais conceitos a um estudante. Confira a [documentação](/docs/building/tracks/concept-exercises) para saber mais.
- Exercícios de prática: são projetados para praticar os conceitos aprendidos. Confira a [documentação](/docs/building/tracks/practice-exercises) para saber mais.

### Aprofunde-se

Cada exercício tem uma seção opcional Aprofunde-se, que pode conter:

- [Abordagens](/docs/building/tracks/approaches): diferentes formas de resolver o exercício
- [Artigos](/docs/building/tracks/articles): descrevem aspectos interessantes do exercício
- Vídeos da comunidade: vídeos que mostram o exercício, geralmente com alguém resolvendo o exercício do zero

## Arquivos compartilhados

Alguns arquivos não são específicos de exercícios individuais, mas se aplicam a _todos_ os exercícios. Confira a [documentação](/docs/building/tracks/shared-files) para saber mais.

## Documentação

Cada trilha tem alguns arquivos de documentação obrigatórios. Confira a [documentação](/docs/building/tracks/docs) para saber mais.

## Widgets

Algumas partes da trilha podem ser exibidas em [widgets](/docs/building/markdown/widgets).

## Guia de estilo

Todos os documentos devem seguir o [guia de estilo](/docs/building/markdown/style-guide). Documentos Markdown
também devem seguir os nossos [padrões de Markdown](/docs/building/markdown/markdown).

## Manutenção

### Permissões do repositório

Cada trilha recebe (automaticamente) uma [categoria de manutenção](/docs/building/github/maintainers-repo-permissions#maintenance-category), que determina as [permissões do mantenedor da trilha no repositório do GitHub](/docs/building/github/maintainers-repo-permissions#repo-permissions).

### Evitar disparar execuções de testes desnecessárias

Quando você faz merge de um PR de trilha que mexe em um exercício, isso faz com que _todas_ as últimas iterações publicadas das soluções dos estudantes sejam testadas de novo.
Para exercícios populares, essa é uma operação _muito_ cara (70.000 execuções de testes no Hello World de Python, em um caso extremo!).

**Recomendamos que você tente evitar fazer isso sem necessidade.**

As soluções **não** serão testadas de novo se o commit mesclado:

- mexer apenas em arquivos `.docs` ou `.meta`, ou em outros arquivos com os quais os usuários não interagem
- ou contiver `[no important files changed]` no corpo do commit.

As soluções **serão** testadas de novo se o commit mesclado:

- não tiver `[no important files changed]` no corpo do commit
- e mexer em um dos seguintes arquivos de um exercício (conforme especificado no arquivo `.meta/config.json` dele):
  - arquivos de teste
  - arquivos do editor
  - arquivos de invalidação

Alguns exemplos:

- [Python#3423](https://github.com/exercism/python/pull/3423): só mexe em documentação, então nenhum teste foi executado
- [Python#3437](https://github.com/exercism/python/commit/29a64a4889f94bafbd0062d7fc5052858523b25c): foi mesclado com `[no important files changed]` adicionado, então nenhum teste foi executado
- [Csharp#2138](https://github.com/exercism/csharp/pull/2138): espaços em branco foram removidos dos testes. A palavra-chave **não** foi adicionada. Os testes foram executados de novo sem necessidade.
