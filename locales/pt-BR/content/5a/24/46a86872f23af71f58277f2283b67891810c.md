# Introdução aos here documents

Em scripts Bash, um "here document" (ou "heredoc") redireciona várias linhas de entrada para um comando ou programa, como se você as estivesse digitando diretamente no terminal.
É uma ferramenta poderosa para embutir texto com várias linhas nos seus scripts sem precisar de arquivos externos nem de manipulação complexa de strings.

## Principais recursos e sintaxe

1. Delimitador: um heredoc começa com o operador `<<` seguido de uma palavra delimitadora (muitas vezes chamada de "marcador" ou "terminador").
   Essa palavra pode ser qualquer palavra que você escolher, mas é comum usar algo como `EOF`, `END` ou `TEXT` para deixar claro.
   Para um código mais legível, você pode usar algo descritivo como delimitador, por exemplo `END_INSTALLATION_INSTRUCTIONS`.

1. Conteúdo: depois do `<< DELIMITER` inicial, você escreve o conteúdo que quer redirecionar.
   Pode ser várias linhas de texto, código ou qualquer outra coisa.

1. Término: o heredoc termina quando a palavra delimitadora aparece de novo sozinha em uma linha, sem espaço em branco no início nem no fim.

## Sintaxe básica

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## Como funciona

* O Bash lê todas as linhas entre o `<< DELIMITER` inicial e o `DELIMITER` final.
* O Bash conecta esse conteúdo à entrada padrão do comando.
* O comando processa essa entrada como se ela viesse do teclado.

### Exemplo 1: saída de texto simples

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

Saída:

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

Neste exemplo:

* `cat` é o comando.
* `<< EOF` inicia o heredoc com `EOF` como delimitador.
* As três linhas de texto são o conteúdo.
* `EOF` sozinho em uma linha encerra o heredoc.
* Em seguida, `cat` gera como saída o conteúdo que recebeu.

### Exemplo 2: usando com wc (contagem de palavras)

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

Saída:

```plaintext
3
```

Aqui, `wc -l` conta o número de linhas.
O heredoc fornece as três linhas como entrada.

### Exemplo 3: passando dados para um script

O script:

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

Chame o script em um prompt interativo do bash usando um heredoc:

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

Saída:

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## Variações e recursos avançados

### Conteúdo literal

O Bash realiza expansão de variáveis, substituição de comandos e expansão aritmética dentro de um heredoc.
Nesse sentido, os heredocs se comportam como strings entre aspas duplas.

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

Saída:

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

Quando o delimitador está entre aspas (usando aspas simples ou duplas), essas expansões são impedidas.
O conteúdo é usado literalmente.
Isso é como strings entre aspas simples.

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

Saída:

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### Removendo tabulações no início

Se você usar `<<-` (com um hífen no final) em vez de `<<`, o Bash remove os _caracteres de tabulação_ no início de cada linha do heredoc.
Isso é útil para indentar o conteúdo do heredoc dentro do seu script sem afetar a saída.

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

A saída é impressa com todas as tabulações iniciais removidas:

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
O autor não recomenda esse uso.
Embora ele possa melhorar a legibilidade do script,

1. é fácil substituir os caracteres de tabulação por espaços sem querer (seu editor pode fazer isso automaticamente), e
1. é difícil perceber a diferença entre espaços e tabulações.
~~~~

## Quando usar here documents

* Entrada com várias linhas: quando você precisa fornecer várias linhas de texto para um comando.
* Arquivos de configuração: embutir pequenos trechos de configuração dentro de um script.
* Geração de código: criar código na hora dentro de um script.
* Interações por script: simular a entrada do usuário para programas interativos.
* Evitar arquivos externos: quando você quer evitar criar arquivos temporários.

Um uso típico pode ser fornecer um texto de ajuda:

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## Possíveis desvantagens

* Documentos embutidos grandes podem deixar seu código mais difícil de ler.
  Pode ser melhor publicar seu script com a documentação em arquivos separados.
* Os here documents podem quebrar o fluxo do código.
  Você pode estar em uma seção de código bastante aninhada quando quiser passar um texto para um programa.
  A indentação do heredoc pode parecer estranha em comparação com o código ao redor.

## Here strings

Assim como os here documents, as _here strings_ (ou "herestrings") fornecem entrada para um comando.
No entanto, enquanto os heredocs são fornecidos como um bloco de texto, as herestrings são fornecidas como uma única string de texto.
As here strings usam a sintaxe `<<< "text"`.

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

Saída:

```plaintext
UPPER CASE THIS STRING
```

Ao contrário dos heredocs, não é preciso um delimitador final.

### Por que usar here strings?

É possível usar um pipeline em vez de uma here string:

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

Então por que usar uma here string?

Considere o caso em que você obtém a string como saída de uma computação demorada e quer enviar o resultado para dois comandos separados.
Usando pipelines, você precisa executar a computação duas vezes:

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

Uma abordagem mais eficiente é capturar a saída da computação (usando substituição de comandos) e usar here strings para fornecer entrada aos dois comandos seguintes:

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

Veja uma aplicação real desse exemplo:

* capturar a resposta JSON de uma consulta a uma API REST (que é paginada),
* fornecer os dados JSON a um programa jq para analisar os resultados e gravá-los em um arquivo, e então
* fornecer os dados JSON a outro programa jq para determinar a URL da próxima consulta.

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

Repare na posição do redirecionamento de saída.
Toda a saída do laço `while` será acrescentada ao arquivo `data.csv`.

## Heredocs e herestrings como redirecionamento

Como são apenas formas de redirecionamento, eles podem ser combinados com outras operações de redirecionamento:

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## Resumindo

Os here documents (ou "heredocs") são uma forma flexível e prática de gerenciar entrada com várias linhas em scripts Bash.
Eles simplificam o processo de embutir texto e dados diretamente nos seus scripts, deixando-os mais autossuficientes e mais fáceis de ler.

As here strings (ou "herestrings") são como os here documents, mas oferecem uma sintaxe mais simples e mais dinâmica.
