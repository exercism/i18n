# Dicas

## Geral

- Um contrato vem depois do tipo de retorno e antes do `is`:

  ```sather
     spare_capacity(load : INT) : INT
        pre load >= 0
     is
        ...
     end;
  ```

- Dentro de um contrato, você pode usar os argumentos e os atributos do
  objeto, então `limit` fica disponível.
- Os testes são compilados sem `-chk`, então um contrato errado não vai
  fazê-los falhar. Escreva os contratos pensando em quem vai ler.

## 1. Monte um arnês

- `pre kg > 0`, no `create`.
- O corpo é o `new` de sempre: defina o atributo e retorne-o.

## 2. Quanto ainda sobra?

- Duas condições unidas com `and`: `pre load >= 0 and load <= limit`.
- `post result >= 0`. Isso decorre do `pre`, e é justamente o que faz valer
  a pena dizê-lo: registra por que dá para confiar na resposta.

## 3. Quão cheio ele está?

- `pre load >= 0` e `post result >= 0`.
- `load * 100 / limit`, nessa ordem. Dividir primeiro jogaria tudo fora,
  como aconteceria em `tuning-the-strings`.

## 4. É seguro?

- Nenhum `pre`: o ponto é que se pode perguntar sobre qualquer carga.
- O `post` repete a pergunta: `post result = (load <= limit)`.
  Parênteses, porque o `=` está sendo usado duas vezes para coisas
  diferentes.
