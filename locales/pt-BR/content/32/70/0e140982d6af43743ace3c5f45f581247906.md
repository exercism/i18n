# Sobre

Ao escrever funções em Haskell, podemos usar o [casamento de padrões][pattern-matching].
O casamento de padrões é um recurso muito poderoso de Haskell que permite fazer casamento com construtores de dados e vincular variáveis aos valores dentro deles.
Como o nome sugere, o que fazemos é casar valores com padrões e, se o valor casar com o padrão, podemos vincular variáveis aos valores dentro do padrão.
O casamento de padrões é composto principalmente destes conceitos: reconhecer valores, vincular variáveis e decompor valores.

~~~~exercism/note
O casamento de padrões em linguagens como Elixir é um pouco diferente do casamento de padrões em Haskell.
Elixir, por exemplo, permite múltiplos nomes de vinculação iguais em um padrão, enquanto Haskell não permite.
~~~~


Veja esta função como exemplo:

```haskell
lucky :: Int -> String
lucky 7 = "Lucky number seven!"
lucky x = "Sorry, you're out of luck, pal!"
```

Aqui temos uma função `lucky` que recebe um `Int` e retorna uma `String`.
Definimos dois padrões para a função, um que casa com o número `7` e outro que casa com qualquer outro número; o nome pode ser qualquer coisa (desde que siga a convenção de nomes de Haskell), mas usamos `x` aqui.
Se o número for `7`, a função retornará `"Lucky number seven!"`; caso contrário, retornará `"Sorry, you're out of luck, pal!"`.
O importante de notar aqui é que os padrões são verificados de cima para baixo, então se tivéssemos trocado a ordem dos padrões, a função sempre retornaria `"Lucky number seven!"`.

## Padrões de lista

Um padrão muito comum é fazer casamento com listas, o que significa pegar a cabeça e a cauda da lista.
Isso se deve à natureza das listas de serem listas encadeadas.
Veja um exemplo de uma função que retorna a cabeça e a cauda de uma lista:

```haskell
headAndTail :: [Int] -> (Int, [Int])
headAndTail [] = error "Can't call head on an empty list"
headAndTail (x:xs) = (x, xs)
```

Aqui temos dois padrões, um que casa com uma lista vazia e outro que casa com uma lista com pelo menos um elemento.
Isso porque, se a lista estiver vazia, precisamos ter um caso para isso; caso contrário, teríamos um erro em tempo de execução.
Se a lista não estiver vazia, podemos casar a cabeça da lista com `x` e a cauda da lista com `xs`.
Isso é feito usando o operador `:` (cons), que é usado para adicionar um elemento no início de uma lista.
Mas, no casamento de padrões, ele permite decompor uma lista em sua cabeça e cauda, de certa forma fazendo o oposto.

O `xs` é um nome comum para a cauda de uma lista; ele destaca que é uma lista, mas se você estivesse trabalhando com uma lista aninhada, poderia usar `xss` para destacar que é uma lista de listas.

## Padrões de tupla

Assim como nas listas, também podemos casar com tuplas.
Veja um exemplo de uma função que recebe uma tupla e retorna o primeiro e o segundo elemento:

```haskell
sumTuple :: (Int, Int) -> Int
sumTuple (x, y) = x + y
```

Aqui temos um padrão que casa com uma tupla de dois elementos; o primeiro elemento é vinculado a `x` e o segundo elemento é vinculado a `y`.

## Padrões curinga

Às vezes não nos importamos com o valor de uma variável, só queremos casar com o padrão.
É aí que entra o padrão curinga, que é indicado por um sublinhado `_`.

Veja um exemplo de uma função que retorna o primeiro elemento de uma lista:

```haskell
head' :: [Int] -> Int
head' [] = error "Can't call head on an empty list"
head' (x:_) = x
```

Aqui dizemos que não precisamos da cauda da lista, então usamos o padrão curinga para ignorá-la.

## Padrões de tipo

Também podemos casar com tipos; isso é feito usando o construtor desse tipo.
Também podemos extrair valores do tipo, como fizemos com tuplas.

```haskell
data AccountType = Guest | User String 

greet :: AccountType -> String
greet Guest = "Welcome, guest!"
greet (User name) = "Welcome, " ++ name ++ "!"
```

No primeiro padrão, casamos com o construtor `Guest` e, no segundo padrão, casamos com o construtor `User` e vinculamos o valor interno a `name`.
