# Introdução ao redirecionamento

No mundo da interface de linha de comando, os programas costumam interagir com três fluxos de dados padrão:

1. **Entrada padrão** (`stdin`): de onde um programa recebe sua entrada (normalmente do teclado).
1. **Saída padrão** (`stdout`): para onde um programa envia sua saída normal (normalmente para a tela do terminal).
1. **Erro padrão** (`stderr`): para onde um programa envia mensagens de erro (normalmente para a tela do terminal).

Lembre-se de que apresentamos esses fluxos no capítulo [Pipelines e listas de comandos][pipelines].

~~~~exercism/note
Pipelines podem ser considerados uma forma de redirecionamento: a saída padrão de um programa é enviada diretamente para a entrada padrão de outro.
Já vimos pipelines.
Este conceito vai abordar o redirecionamento de e para arquivos.
~~~~

O redirecionamento do shell é um mecanismo poderoso que permite mudar o destino desses fluxos.
Em vez de um programa ler do teclado ou escrever na tela, você pode redirecionar a entrada de um arquivo ou enviar a saída para um arquivo.
Isso dá bastante flexibilidade e controle sobre como os programas interagem com os dados.

## Principais operadores de redirecionamento

Veja os operadores de redirecionamento mais comuns e o que eles fazem:

### `>` (redirecionamento de saída)

* Objetivo: redirecionar a saída padrão (`stdout`) de um comando para um arquivo.
* Comportamento:
  * Se o arquivo não existir, ele é criado.
  * Se o arquivo existir, seu conteúdo é sobrescrito.
* Exemplo:

  ```bash
  # Sends the output of 'ls -l' to 'file_listing.txt'
  ls -l > file_listing.txt
  ```

~~~~exercism/caution
O redirecionamento acontece **antes** de o comando ser executado.
Isso significa que você não pode redirecionar para o mesmo arquivo de onde precisa ler.

```bash
date > date.txt         # populate the file with the current date
cat date.txt > date.txt # 'date.txt' is now empty!
```

No segundo comando do exemplo acima,

1. Primeiro, o Bash trunca o arquivo indicado no redirecionamento.
   Isso destrói o conteúdo anterior e deixa um arquivo vazio.
2. Em seguida, o Bash lê o arquivo recém-esvaziado.
3. Por fim, o Bash escreve o conteúdo (ou seja, nada) de volta no arquivo.
~~~~

### `>>` (redirecionamento de saída com acréscimo)

* Objetivo: acrescentar a saída padrão (`stdout`) de um comando a um arquivo.
* Comportamento:
  * Se o arquivo não existir, ele é criado.
  * Se o arquivo existir, a saída é adicionada ao final do arquivo.
* Exemplo:

  ```bash
  # Adds "Another line" to the end of the file
  echo "Another line" >> file_listing.txt
  ```

### `<` (redirecionamento de entrada)

* Objetivo: redirecionar a entrada padrão (`stdin`) de um comando a partir de um arquivo.
* Comportamento: o comando lê sua entrada do arquivo indicado em vez do teclado.
* Exemplo:

  ```bash
  # 'tr' reads from 'lowercase.txt' and
  # output is redirected to 'uppercase.txt'
  tr 'a-z' 'A-Z' < lowercase.txt > uppercase.txt
  ```

### `2>` (redirecionamento de erro):

* Objetivo: redirecionar o erro padrão (`stderr`) de um comando para um arquivo.
* Comportamento: as mensagens de erro são enviadas para o arquivo indicado em vez do terminal.
* Exemplo:
  ```bash
  # Error message from 'rm' is sent to 'error_log.txt'
  rm non_existent_file 2> error_log.txt
  ```

Você pode _acrescentar_ o erro padrão a um arquivo com `2>>`.

### Outros redirecionamentos

Existem também redirecionamentos que podem mesclar `stdin` e `stderr`.
Consulte o [manual][manual] para mais detalhes.

## `/dev/null`

`/dev/null` é um arquivo especial que

* é um arquivo vazio quando você lê dele, e
* descarta todos os dados escritos nele.

Às vezes ele é chamado de "the bitbucket".
Ele é útil para suprimir saída ou erros.

```bash
some_command > /dev/null  # Discards stdout
some_command 2> /dev/null # Discards stderr

# Using /dev/null as input will prevent the command
# from reading data from the keyboard
some_command < /dev/null
```

## Combinando redirecionamentos

É possível informar vários redirecionamentos de uma só vez.

```bash
some_command < input.txt > output.txt 2> error.txt
```

Um redirecionamento pode ser copiado.

```bash
# send stderr to the same destination as stdout
some_command > output.txt 2>&1
```

Quando você vir `2>&1`, leia isso como "redirecione o stderr para _onde quer que o stdout esteja apontando **no momento**_".
O Bash processa as instruções de redirecionamento estritamente da esquerda para a direita, o que significa que você pode fazer:

```bash
# redirect stdout to 'output1.txt'
# redirect stderr to the same place
# then change stdout to 'output2.txt'
some_command > output1.txt 2>&1 > output2.txt
```

## Descritores de arquivo

No contexto da programação de shell e de sistemas operacionais como Linux/Unix, um descritor de arquivo (FD) é um número inteiro não negativo que serve como identificador ou referência para um arquivo aberto ou um recurso de E/S (entrada/saída).
Pense nele como um rótulo ou um número de referência que o sistema operacional usa para acompanhar arquivos abertos e fluxos de dados.

Os números que você vê do lado esquerdo dos redirecionamentos são descritores de arquivo.

Os fluxos de E/S padrão recebem os 3 primeiros descritores de arquivo:

* a entrada padrão é o FD 0
* a saída padrão é o FD 1
* o erro padrão é o FD 2

Novos descritores de arquivo podem ser definidos ou criados com o comando `exec` e operadores de redirecionamento.

```bash
# create FD 3 as a copy of stdout
exec 3>&1
# send stdout to a log file
exec > log.txt

# then redirect both stdout and file descriptor 3
echo "some debug message" >&3  # displayed in the terminal
some_command  2>&1 # stdout and stderr send to 'log.txt'
```

Essa técnica parece bem complicada, mas pode ser muito útil em situações em que seu script é executado por outro pacote de software e a saída padrão é capturada automaticamente pelo software.
O comando `bats`, usado para rodar os testes de unidade desta trilha, funciona assim: o `bats` captura o stdout e o stderr de um teste, mas as mensagens de depuração enviadas para o FD 3 aparecem no terminal.
~~~~

## Em resumo

Por que o redirecionamento é útil?

* Salvar a saída: armazenar os resultados de um comando para revisar ou processar depois.
* Registro em log: capturar mensagens de erro para depuração.
* Automação: encadear comandos, usando a saída de um como entrada de outro.
* Filtragem: descartar saída indesejada.
* Processamento em lote: processar dados de arquivos em vez de digitá-los manualmente.
* Criação de scripts: os redirecionamentos são essenciais para escrever scripts de shell robustos.

Os redirecionamentos do shell dão a você um controle refinado sobre como os programas interagem com os dados, permitindo construir fluxos de trabalho complexos e gerenciar informações com eficiência.
