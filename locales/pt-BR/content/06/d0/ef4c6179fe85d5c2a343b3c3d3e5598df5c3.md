# Testes

Uma forma de resolver os exercícios do Exercism é acessar o site e usar o editor do navegador, onde você pode editar e testar sua solução.

Como alternativa, você pode baixar os exercícios para o seu computador, onde usa o seu próprio editor e um conjunto de ferramentas para criar, testar e, por fim, enviar sua solução.

Isso envolve o uso da interface de linha de comando do Exercism, ou CLI, um aplicativo que roda dentro de um terminal ou de uma janela de linha de comando. As instruções de instalação estão aqui: [Documentação da CLI do Exercism](https://exercism.org/docs/using/solving-exercises/working-locally).

## Abordagem de testes

O Exercism pressupõe alguma experiência com desenvolvimento orientado a testes. Cada exercício consiste em um _`stub file`_, um _`test file`_ que contém uma série de testes já escritos, e um _`test script`_ usado para executar os testes.

Resolver um exercício exige que o _`stub file`_ seja desenvolvido aos poucos até conter o código que, no fim, vai passar em todos os testes.

Na prática, isso significa que tanto o _`stub file`_ quanto o _`test file`_ serão editados o tempo todo. Repare que o _`test file`_ é editado não para alterar o código dos testes, mas para comentar os testes que estão falhando.

No começo, todos os testes, menos um, ficam comentados. Depois, conforme o _`stub file`_ avança em direção a uma solução que funciona, mais testes vão sendo descomentados até que todos rodem com sucesso.

## Infraestrutura de testes

Não é preciso instalar nenhum software adicional, pois os componentes do framework de testes já vêm junto com o download do exercício.

O framework de testes é formado por três arquivos Rexx que, na hora dos testes, se juntam à solução do exercício para formar a unidade de código de teste. Essa unidade é então executada pelo _`test script`_, e os resultados dos testes são impressos no terminal.

Não edite nem apague o _`test script`_ nem qualquer outro arquivo do framework de testes. Se algum gremlin provocar isso, basta baixar o exercício de novo pela CLI do Exercism, tomando o cuidado de salvar o código da sua solução.

## Rodando os testes

Resolver um exercício segue estes passos:

1. Abra um terminal
2. Baixe o exercício escolhido
3. Entre no diretório do exercício
4. Carregue o stub file e o test file no seu editor
5. Repita, de forma iterativa:

    1. Execute o test script
    2. Escreva código no seu stub file (transformando-o aos poucos em um arquivo de solução) e comente ou descomente testes no seu test file

6. Quando todos os testes passarem, envie a solução para o Exercism
7. Feche o terminal
8. Comemore o seu sucesso

Um exemplo concreto em um terminal Linux usando o exercício `acronym` (suponha que o workspace do exercism seja: `/home/exercism`)

Baixe o exercício:

`exercism download --track=rexx --exercise=acronym`

Entre no diretório do exercício:

`cd /home/exercism/rexx/acronym`

Em outra janela, talvez uma interface gráfica, carregue `acronym.rexx` e `acronym-check.rexx`, os arquivos stub e de teste, respectivamente, no seu editor.

Execute o test script: `./test-acronym`

e todos os testes devem falhar:

```bash
1..9
not ok 1 - basic Abbreviate("Portable Network Graphics")
not ok 2 - lowercase words Abbreviate("Ruby on Rails")
not ok 3 - punctuation Abbreviate("First In, First Out")
not ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
not ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
not ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
not ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
not ok 8 - apostrophes Abbreviate("Halley's Comet")
not ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Comente todos os testes, menos o primeiro, no arquivo `acronym-check.rexx`, e rode o test script de novo. O resultado deve ser:

```bash
1..1
not ok 1 - basic Abbreviate("Portable Network Graphics")
```

Reescreva o `acronym.rexx` até que ele contenha um código que funcione, e a saída da execução do test script deve acabar sendo:

```bash
1..1
ok 1 - basic Abbreviate("Portable Network Graphics")
```

Agora descomente os outros testes, execute o test script de novo e, no fim, a saída deve ser:

```bash
1..9
ok 1 - basic Abbreviate("Portable Network Graphics")
ok 2 - lowercase words Abbreviate("Ruby on Rails")
ok 3 - punctuation Abbreviate("First In, First Out")
ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
ok 8 - apostrophes Abbreviate("Halley's Comet")
ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Agora você pode enviar a solução do seu exercício:

`exercism submit acronym.rexx`

e ganhar mais um ponto de reputação. Feche o terminal quando terminar.

O processo para quem usa MacOS é bem parecido, já que é um sistema operacional derivado do UNIX.

O processo para quem usa Windows é, em linhas gerais, parecido, mas tem algumas pequenas diferenças:

- A janela do _Command Prompt_ é o terminal
- As barras invertidas substituem as barras normais nos caminhos, então o diretório de trabalho pode ser:

  `cd C:\Users\MyName\exercism\rexx\acronym`

- A execução do test script é feita com:

  `test-acronym`  ou  `test-acronym.bat`

A saída dos testes será idêntica.
