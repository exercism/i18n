# Sobre

[Closures][closures] em Swift são blocos de código autocontidos aos quais é possível passar parâmetros para acionar seu cálculo e retornar valores. Os closures também capturam valores do seu ambiente e os usam em seus cálculos. Como são autocontidos, podem circular pelo programa como qualquer outro valor, ou ser atribuídos a constantes e variáveis.

Closures podem soar muito parecidos com funções de Swift; e de fato são, com bons motivos. As funções em Swift são casos especiais de closures, que precisam ter um nome e são definidas com uma sintaxe um pouco diferente.

Embora as funções em Swift sejam tecnicamente closures, quando as pessoas falam em "closures" em Swift, estão se referindo a [expressões de closure][closure-expressions]. Uma expressão de closure é escrita como uma lista de parâmetros seguida por um tipo de retorno e a palavra-chave `in`, seguida pelo corpo do closure, tudo dentro de um par de chaves:

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}
```

Isso define uma expressão de closure do tipo `(Double, Double) -> Double`, e ela pode ser executada de forma semelhante a uma função desse tipo, aplicando-a a parâmetros do tipo adequado:

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}(10.0, 15.0)
// returns 12.5
```

Como não é muito prático escrever a expressão de closure completa toda vez que se quer executá-la, closures podem ser atribuídos a nomes, como qualquer outro valor em Swift. Depois, podem ser chamados aplicando o nome aos parâmetros:

```swift
let mean = { (a: Double, b: Double) -> Double in
  (a + b) / 2.0
}

mean(13.0, 100.0)
// returns 56.5
```

Como visto acima, closures, assim como funções normais, podem omitir a palavra-chave `return` se o corpo do closure for uma única expressão.

Na maioria das vezes, closures são usados com funções de ordem superior, seja passados como parâmetros, seja retornados como resultado:

```swift
[11, 75, 3, 99, 53].contains(where: { (x: Int) -> Bool in x > 100 })
// returns false

["apple", "ball", "carrot"].sorted(by: { (s1: String, s2: String) -> Bool in s1.count < s2.count })
// returns ["ball", "apple", "carrot"]

func makeAdder(base: Int) -> (Int) -> Int {
  { (x: Int) -> Int in base + x }
}
```

## Inferindo os tipos de closure

Quando o tipo de retorno ou os tipos dos parâmetros podem ser [inferidos a partir do contexto][inferring-closure-types], eles podem ser omitidos da expressão de closure. Além disso, se os tipos dos parâmetros podem ser omitidos, os parênteses em volta dos nomes dos parâmetros também podem:

```swift
let mean: (Double, Double) -> Double = { a, b in a + b / 2.0 }

func makeAdder(base: Int) -> (Int) -> Int {
  { x in base + x }
}

["apple", "ball", "carrot"].sorted(by: { s1, s2 in s1.count < s2.count })
```

- No primeiro exemplo, o tipo pode ser inferido a partir da anotação na constante `mean`.
- No segundo, o compilador sabe, pela definição de `makeAdder`, que `base` é um int e que a função retornada deve ser do tipo `(Int) -> Int`. A partir daí, ele pode verificar que, se `x` for um `Int`, então o closure terá o tipo `(Int) -> Int`; assim, podemos omitir a assinatura de tipo no closure, já que `(Int) -> Int` é a única assinatura válida possível que o closure pode ter.
- O terceiro exemplo é parecido, mas o compilador precisa obter parte das informações de tipo a partir do array com o qual o método está sendo usado. Ele sabe que o método `sorted(by:)` recebe como parâmetro um closure com dois parâmetros do mesmo tipo que os elementos da coleção que está sendo ordenada, e que retorna um `Bool`, então o compilador pode inferir que o tipo de retorno do closure deve ser `Bool`. E como o método está sendo usado com um array de String, ele pode determinar que os tipos dos parâmetros `s1` e `s2` devem ser ambos `String`.

## Limitações dos closures

Como mencionado acima, funções e closures são muito parecidos em Swift, mas há algumas diferenças importantes:

- Closures não podem usar rótulos de argumento externos. Não há como defini-los, e tentar usar o nome de um parâmetro ao chamar o closure resulta em erro:

```swift
let add5 = { x in x + 5 }
add5(x: 10)
// Error: Extraneous argument label 'x:' in call
```

- Parâmetros em closures não podem ter valor padrão.
- Parâmetros em closures podem ser parâmetros variádicos, mas precisam ter um nome e uma anotação de tipo.
