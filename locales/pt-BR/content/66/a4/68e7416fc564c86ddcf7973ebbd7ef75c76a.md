# Sobre

## Introdução

Tipos opacos são uma técnica de encapsulamento em Elm.
Algumas pessoas também chamam isso de ocultação de informação, ou de ocultação de detalhes de implementação.
Eles também são usados comumente para garantir a validação, usando o padrão [Parse, dont validate][parse-dont-validate].
Por exemplo, você pode ter um tipo opaco `EmailAddress`, que só pode conter endereços de email válidos (ao contrário de uma `String`, que pode conter qualquer coisa).

## Criando um tipo opaco

[Tipos personalizados][custom-types] têm uma ou mais *variantes*, e o compilador gera automaticamente uma função para criar cada *variante*, usando o nome da *variante*.
Essa é a única forma de criar tipos personalizados.
O compilador também permite a desestruturação dessas variantes.

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

Por padrão, tudo isso é interno ao arquivo / módulo, e usamos a palavra-chave `exposing` para escolher o que exportar.
Para criar um tipo opaco, você simplesmente escolhe não exportar as *variantes*.

Quando você faz isso, quase sempre precisa fornecer outra forma de criar e obter as *variantes*, expondo funções personalizadas.
Essas funções personalizadas permitem aplicar alguma lógica ao criar e obter as *variantes*.
Isso esconde os detalhes de implementação internos do módulo. Você pode mudar esses detalhes o quanto quiser, desde que as funções expostas continuem as mesmas.

## Parse, don't validate

O uso mais comum dos tipos opacos é provavelmente garantir a validação, usando o padrão [Parse, dont validate][parse-dont-validate].
Nesse padrão, você expõe uma função que recebe uma entrada com menos estrutura / segurança de tipos do que você quer, como uma `String`, e então faz o parse dela em um tipo mais estruturado, como `EmailAddress`, retornando o tipo ou retornando um erro (normalmente `Maybe` ou `Result`).

Por exemplo, no código abaixo, módulos externos só conseguem criar um tipo `EmailAddress` usando a função `parseEmailAddress`. Assim, quando você trabalha com o tipo `EmailAddress`, tem certeza de que ele é válido.

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
