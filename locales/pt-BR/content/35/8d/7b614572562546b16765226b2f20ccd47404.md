# uso de especificação

[comment]: # (Este aviso é exibido quando a solução não tem uma especificação de tipo)

Inclua [especificações de tipo](https://elixir-lang.org/getting-started/typespecs-and-behaviours.html#types-and-specs) (`@spec`) para comunicar o contrato entre as entradas e a saída de uma função.

- Elixir é uma linguagem de tipagem dinâmica, o que significa que a verificação de tipos só acontece em tempo de execução. O uso de especificações de tipo permite que linters e ferramentas de análise estática como o [`Dialyxir`](https://hexdocs.pm/dialyxir/readme.html) (baseado no [`Dialyzer`](http://erlang.org/doc/man/dialyzer.html) do Erlang) avaliem o código em busca de comportamentos indesejados.
- Você pode encontrar uma [lista completa](https://hexdocs.pm/elixir/typespecs.html#basic-types) de todos os tipos embutidos na [documentação da linguagem](https://hexdocs.pm/elixir/typespecs.html#content)
- os tipos podem ser especificados com ou sem parênteses: `atom()` vs `atom`
  - o estilo do Elixir no Exercism é especificar sem parênteses.

```elixir
# Example 1
@spec add_one(int) :: int
def add_one(n) when is_integer(n) do
  n + 1
end

# Example 2
@spec hello(String.t) :: String.t
def hello(what \\ "world") when is_binary(what) do
  "Hello, #{what}"
end
```
