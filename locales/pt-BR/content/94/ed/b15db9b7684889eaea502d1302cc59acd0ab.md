# Introdução

Elixir oferece uma construção para resgatar de erros usando `try .. rescue`

```elixir
try do
  raise RuntimeError, "error"
rescue
  e in RuntimeError -> :error
end
```

Vamos examinar essa construção:

- **Linha 1**, o bloco é declarado com `try`.
- **Linha 2**, a chamada de função que pode gerar erro fica aqui, neste caso estamos chamando `raise/2`.
- **Linha 4**, na seção `rescue`, fazemos um pattern match no nome do _Módulo_ do erro levantado
  - no lado esquerdo de `->`:
    - `e` é associado ao struct do erro.
    - `in` é uma palavra-chave.
    - `RuntimeError` é o erro do qual queremos resgatar.
      - Se quiséssemos resgatar de todos os erros, poderíamos usar `_` em vez do nome do módulo ou omitir a palavra-chave `in` por completo.
  - no lado direito:
    - as instruções a serem executadas se o erro corresponder.

## Structs de erro

Os erros (às vezes também chamados de "exceções") que você resgata desse jeito são structs.
Resgatar erros em Elixir é algo bem raro.
Normalmente, o erro resgatado é registrado em um log ou enviado a um serviço externo de monitoramento, e então é relançado.
Isso significa que normalmente não nos importamos com a estrutura interna do struct de erro específico.

No [conceito de Exceções][exercism-exceptions] você vai aprender mais sobre structs de erro, incluindo como definir seu próprio erro personalizado.

[exercism-exceptions]: https://exercism.org/tracks/elixir/concepts/exceptions
