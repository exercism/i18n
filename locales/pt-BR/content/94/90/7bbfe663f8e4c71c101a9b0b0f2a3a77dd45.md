# Criar um executor de testes

O executor de testes é uma ferramenta essencial que permite:

- Que o site verifique automaticamente se uma iteração passa em todos os testes.
- Que os estudantes resolvam exercícios usando o [editor no navegador](/docs/using/solving-exercises/using-the-online-editor) ([sem precisar de CLI](/docs/using/solving-exercises/working-locally)).

Para começar a criar um executor de testes, consulte o documento [Criar um executor de testes do zero](/docs/building/tooling/test-runners/creating-from-scratch).

## Implementação

As ferramentas de um track geralmente são (na maioria das vezes) escritas na linguagem do track.

```exercism/caution
Embora você tenha liberdade para usar outras linguagens, cada linguagem adicional dificulta a manutenção e a contribuição no track.
Por isso, recomendamos usar a linguagem do track sempre que possível, pois isso facilita a manutenção e a contribuição.
```

## Publicação

O executor de testes é empacotado e executado como um [contêiner Docker](/docs/building/tooling/docker).
As imagens Docker do executor de testes são publicadas automaticamente usando um [fluxo de trabalho do GitHub Actions](https://github.com/exercism/generic-test-runner/blob/main/.github/workflows/docker.yml).

## Testes

Depois de criar um executor de testes, você pode usar a imagem Docker dele na configuração de CI do seu track para verificar os exercícios do track.
O principal benefício dessa abordagem é que ela imita melhor a configuração de produção; em outras palavras, você pode ter mais confiança de que tudo também funciona em produção.
Uma possível desvantagem é que isso pode deixar o fluxo de trabalho de CI mais lento.
Cabe a você, mantenedor, decidir qual abordagem funciona melhor para o seu track.
