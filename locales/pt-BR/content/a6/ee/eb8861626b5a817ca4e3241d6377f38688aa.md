# Sobre

Ruby é uma linguagem dinâmica e fortemente tipada.
Em linguagens dinâmicas, o tipo de uma variável ou de um objeto é resolvido em tempo de execução. Isso significa que o valor ou o tipo pode mudar até o último momento (quando o código é analisado pelo intérprete).
E o que queremos dizer com fortemente tipada?
Depois que sabemos o tipo de uma variável ou de um objeto, o Ruby é rígido quanto ao que você pode fazer com ele, por exemplo:

```ruby
x = '2'
y = x + 'n'
# => '2n'
```

**Mas**

```ruby
x = '2'
y = x + 2
# => TypeError (no implicit conversion of Integer into String)
```

Lembre-se: no Ruby, tudo é um objeto.
Até as classes são instâncias da classe `Class`.

Por exemplo:

```ruby
1.class
# => Integer

Integer.is_a?(Object)
# => true

Class.is_a?(Object)
# => true
```

Isso significa que também podemos definir classes assim:

```ruby
Car = Class.new do
  def run
    'running'
  end
end

Car.new.run
# => 'running'
```

Por fim, tenha em mente que o objeto `Integer` armazena valores que podem ser definidos como um ou mais dígitos (consecutivos) e que seus métodos dão suporte a vários dos [operadores matemáticos][integers-docs].

[integers-docs]: https://docs.ruby-lang.org/en/master/Integer.html

~~~~exercism/note
A comunicação na documentação muitas vezes faz referência a métodos de instância usando uma sintaxe como `Class#method_name`, enquanto métodos de nível de classe ou de módulo são referenciados como `Class::method_name`.
O `::` é chamado de _Operador de Resolução de Escopo_: é ele que referencia a constante ou o método no nível da classe ou do módulo.
Você vai encontrar isso na documentação do Ruby, em listas de discussão e em outros espaços de suporte.
Por outro lado, você vai ver que, aqui nos nossos textos, referenciamos métodos de classe e de módulo como `ClassName.method_name` ou `ModuleName.method_name`.
~~~~
