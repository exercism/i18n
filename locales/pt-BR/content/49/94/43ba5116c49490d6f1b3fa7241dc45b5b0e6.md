# Introdução

O código escalar depende de flags definidas por várias instruções para desviar em resposta a uma certa condição.
Valores empacotados, porém, representam não um, mas muitos valores em paralelo.
Uma única condição pode falhar para uma lane e ter sucesso para outra.

É por isso que o código SIMD é _branchless_ por padrão.

Em vez de depender de flags, as comparações empacotadas geralmente produzem uma **máscara** no operando de destino.
Para cada lane, a comparação preenche a lane inteira com uns quando a condição é verdadeira e com zeros quando ela é falsa.
Lida como um inteiro com sinal, uma lane verdadeira é `-1` e uma lane falsa é `0`.

Essa máscara pode então ser combinada com operações bit a bit para filtrar lanes específicas.

## Comparações empacotadas

Um `cmp` escalar é genérico no sentido de que é usado para definir várias flags ao mesmo tempo.
Outra instrução pode então consumir essas flags para desviar ou realizar cálculos.

No entanto, como uma comparação empacotada tanto verifica uma condição quanto calcula uma máscara, ela não é genérica.
É preciso informar à comparação a condição exata que está sendo testada.

Há duas formas de fazer isso:

- As comparações de inteiros recebem a condição como sufixo: `eq` para igualdade e `gt` para maior que.
  Outras variantes são construídas compondo o resultado de uma dessas.
- As comparações de ponto flutuante recebem a condição codificada em um imediato.
  Valores diferentes desse imediato correspondem a condições diferentes sendo testadas.

Afora o uso de um sufixo condicional específico nas comparações de inteiros, a sintaxe segue a mesma estrutura que já vimos:

- Para inteiros, `p` + `cmp` + condição + tamanho (`b`, `w`, `d` ou `q`).
- Para floats, `cmp` + `p` + tamanho (`s` ou `d`).
  A condição é passada em um imediato como operando extra.

### Comparações de inteiros

Como mencionado, existem apenas comparações de inteiros para igualdade e maior que:

| instrução                                  | descrição                        |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | igualdade por lane               |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | maior que **com sinal**, por lane |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

Para criar uma comparação de menor que, use `gt` com os operandos trocados: `a < b` == `b > a`.

Repare que a comparação é **com sinal**.
Para fazer uma comparação sem sinal, inverta o bit mais significativo de ambos os operandos.
Isso pode ser feito com um XOR com uma máscara em que apenas o bit mais significativo está definido.

~~~~exercism/note
Dois truques úteis são:

1. Fazer XOR de um registrador com ele mesmo para produzir todos zeros.
2. Comparar um registrador com ele mesmo para produzir todos uns.

Por exemplo:

```x86asm
pxor xmm4, xmm4    ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

Máscaras de todos zeros e de todos uns são comuns para codificar "falso em toda parte" e "verdadeiro em toda parte", respectivamente.
Elas também podem ser usadas para representar `0` empacotado ou `-1` empacotado, que são valores sentinela comuns.
Por exemplo, o NUL que marca o fim de uma string é um `0`.
~~~~

### Comparações de ponto flutuante

As lanes de ponto flutuante usam um formato diferente: uma única instrução, `cmpps` (e `cmppd` para lanes de 64 bits), com a condição como um imediato:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

O NASM também tem pseudo-ops que mapeiam para o imediato correto e são mais fáceis de lembrar.
Em todos os itens a seguir, o `x` em `px` pode ser `s` (floats de 32 bits) ou `d` (floats de 64 bits):

| pseudo-op    | imediato | comparação             |
|--------------|----------|------------------------|
| `cmpeqpx`    | 0        | a == b                 |
| `cmpltpx`    | 1        | a <  b                 |
| `cmplepx`    | 2        | a <= b                 |
| `cmpunordpx` | 3        | a é NaN ou b é NaN     |
| `cmpneqpx`   | 4        | a != b                 |
| `cmpnltpx`   | 5        | a >= b                 |
| `cmpnlepx`   | 6        | a >  b                 |
| `cmpordpx`   | 7        | nem a nem b é NaN      |

## Selecionando com uma máscara

Uma máscara codifica o resultado de uma condição.
Ela pode então ser usada para escolher, lane por lane, entre dois conjuntos de valores de acordo com essa condição.
Pegamos a lane de um valor onde a máscara é verdadeira, e de outro onde ela é falsa:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

Esse padrão é a forma empacotada da seleção branchless.
Todas as lanes são calculadas, e a máscara sozinha decide qual valor permanece, sem nenhum `jcc` em lugar algum.

## Blends dedicados

Há instruções que realizam essa mesma seleção diretamente, lendo um bit por elemento de um registrador de máscara.
Elas são chamadas de instruções **blend**:

| instrução  | elemento    | origem da máscara |
|------------|-------------|-------------------|
| `pblendvb` | byte        | `xmm0` implícito  |
| `blendvps` | lane de 32 bits | `xmm0` implícito  |
| `blendvpd` | lane de 64 bits | `xmm0` implícito  |

Repare que a primeira instrução segue a sintaxe de inteiros, enquanto as outras duas seguem a sintaxe de floats.
No entanto, como essas instruções simplesmente selecionam bytes brutos, qualquer uma delas pode ser usada tanto com inteiros quanto com floats.

Para cada elemento, o blend mantém o destino quando o bit mais significativo do elemento de máscara correspondente está zerado, e pega a origem quando ele está definido.
Apenas esse **bit mais significativo** é consultado, o que uma máscara de comparação satisfaz, já que suas lanes são todos uns ou todos zeros.
O registrador de máscara é sempre `xmm0`, que é implícito:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

Também é possível usar `pblendvb` para selecionar lanes a partir de uma máscara de comparação para qualquer outro tamanho.
Como todos os bytes de uma lane verdadeira são todos uns, o `pblendvb` seleciona todos eles.

~~~~exercism/note
Essas instruções adicionam um `v` depois da operação que está sendo realizada (`blend`).
Esse `v` vem de _variável_, porque a seleção não é estática: ela depende de um registrador.

Existem também variantes sem o `v`, que selecionam de acordo com um imediato.
Elas seguem o mesmo padrão, selecionando uma lane `i` se o bit `i` do imediato estiver definido.
~~~~

## De uma máscara de volta para um escalar

Embora poderoso, o código SIMD não tem boa parte da flexibilidade do código escalar.
Em muitas situações, é necessário sair de um registrador empacotado e voltar ao mundo das instruções escalares.

A família de instruções `movmsk` serve como uma ponte entre os dois mundos.
Essas instruções extraem o **bit mais significativo** de cada lane para um registrador de uso geral:

| instrução  | coleta                                  | largura do resultado |
|------------|-----------------------------------------|----------------------|
| `pmovmskb` | bit mais significativo de cada um dos 16 bytes | 16 bits       |
| `movmskps` | bit mais significativo de cada um dos 4 dwords | 4 bits        |
| `movmskpd` | bit mais significativo de cada um dos 2 qwords | 2 bits        |

Se usada após uma comparação, cada bit definido representa uma lane "verdadeira" e cada bit zerado, uma lane "falsa".
Esse resultado pode então ser manipulado como de costume com instruções escalares.
Por exemplo, um `popcnt` conta o número de correspondências, e o `tzcnt` encontra a primeira.

O registrador de uso geral pode ter 32 ou 64 bits de largura.

## Testando um vetor inteiro

Também existe uma variante empacotada da instrução escalar `test`: a `ptest`.

Ela é parecida com sua equivalente escalar no sentido de que realiza uma operação AND entre dois operandos, sem modificá-los.
Diferente do `test`, a `ptest` também realiza uma operação ANDN, negando o primeiro operando.

Assim, a `ptest` pode ser vista como uma versão não destrutiva do `pand` e do `pandn` que define flags de acordo com o resultado.
Assim como essas duas instruções, a `ptest` trata todo o registrador SIMD como uma única lane e, por isso, não recebe um prefixo de tamanho.

Se o resultado de uma operação AND for `0`, a `ZF` é definida, e se a operação ANDN resultar em `0`, é a `CF` que é definida.
Isso significa que a `ptest` pode ser usada para verificar tanto uma máscara de todos uns quanto uma de todos zeros:

1. Usar `ptest` em um registrador com ele mesmo define a `ZF` apenas se o registrador for todos zeros.
   Isso imita o truque escalar comum de usar `test` em um registrador com ele mesmo para verificar se ele é `0`.
2. Usar `ptest` em um registrador com uma máscara de todos uns define a `CF` apenas se o registrador for todos uns.
   Além disso, define a `ZF` apenas se o registrador for todos zeros, o que torna possível verificar as duas máscaras ao mesmo tempo.

```x86asm
pxor    xmm0, xmm0   ; all zeros
pcmpeqb xmm1, xmm1   ; all ones
pcmpeqb xmm2, xmm2

ptest xmm0, xmm0     ; ZF set: a register against itself detects all zeros
ptest xmm0, xmm1     ; ZF set, CF clear: xmm0 is all zeros, not all ones
ptest xmm2, xmm1     ; CF is set only if xmm2 is all ones
```

O resultado de uma `ptest` pode ser usado para desviar ou em instruções branchless como `setcc` ou `cmovcc`, como de costume.
