# Introdução

## Funções

Você pode definir suas próprias **funções personalizadas** em `jq` para encapsular a lógica que precisar.
_Funções_ funcionam igual às funções nativas: elas recebem uma entrada e emitem zero, um ou mais resultados.

### Definindo uma função

Você pode definir uma _função_ `jq` usando a seguinte sintaxe:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- começa com a palavra-chave `def`,
- dois-pontos antes do corpo da função,
- o corpo consiste em uma única expressão,
- termina com ponto e vírgula,
- como no resto da sintaxe do `jq`, você pode usar espaços em branco à vontade para facilitar a leitura.

### Onde colocar funções

_Funções_ precisam ser definidas antes de serem usadas: isto é um erro:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Isso significa que você precisa colocar as _funções_ no topo do seu código `jq`, antes da expressão "principal".

#### Funções aninhadas

_Funções_ podem ser aninhadas:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Aqui, a _função_ `B` só é visível no corpo de `A`.

### Escopo

Uma _função_ introduz um novo **escopo** para variáveis e funções aninhadas.

### Argumentos

Os **argumentos** de uma _função_ são separados por _ponto e vírgula_, não por vírgulas.
Por exemplo, uma _função_ que recebe um número, e depois soma um número e multiplica por um número:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
Ponto e vírgula é necessário porque a vírgula já tem uma finalidade no `jq`: um operador que junta fluxos.

Usar uma vírgula em vez de ponto e vírgula vai tentar fazer duas chamadas a uma função `add_mul` de _1 argumento_, que não existe e, portanto, vai falhar na primeira tentativa de chamada:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```
~~~~

#### Argumentos são _expressões_

Os _argumentos_ de uma função são filtros, não valores.
Nesse sentido, eles funcionam como o que outras linguagens descrevem como callbacks:

Usando a função `add_mul` como exemplo:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

O que está acontecendo aqui?

- o argumento `adder` recebe a _expressão_ `. + 5`
  - quando a função faz `. + adder`, isso vira `. + . + 5`
  - isso resulta em 25, já que `. == 10`
- da mesma forma, o argumento `multiplier` é a expressão `. - 2`
  - isso resulta em 8
  - então o resultado é `25 * 8 == 200`

#### Argumentos como valores

Às vezes você vai querer "materializar" um _argumento_ em uma variável:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Existe uma forma abreviada para isso:

```jq
def my_func($arg):
    other stuff ...
;
```

Vale notar que isso é apenas "açúcar sintático": o nome `arg` sem `$` continua no escopo dentro da _função_.

### Aridade

_Funções_ têm uma **aridade**, ou seja, o número de _argumentos_ que recebem.

_Funções_ podem usar o mesmo nome com _aridades_ diferentes.
A função nativa [`range`][man-range] demonstra isso: `range/1`, `range/2` e `range/3` coexistem.

Isso pode ser útil para definir funções recursivas que carregam estado por meio de argumentos.
Por exemplo, `map` _poderia_ ser implementado assim:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

### Recursão

O `jq` faz otimização de chamadas de cauda, mas apenas para funções de aridade 0.

### Módulos

Um módulo `jq` é um arquivo contendo apenas funções.
Módulos são incluídos em um programa jq com os comandos [`include`][man-include] ou [`import`][man-import].
