# Introdução

Ponteiros inteligentes são um recurso moderno do C++ criado para oferecer gerenciamento automático de memória, ajudando a evitar vazamentos de memória e ponteiros pendentes, problemas comuns quando se usam ponteiros brutos.
Eles funcionam como wrappers em torno de ponteiros brutos, acrescentando funcionalidades extras, como a liberação automática da memória quando o ponteiro não é mais necessário.

## Sintaxe geral

Os ponteiros inteligentes normalmente são implementados como templates de classe na biblioteca padrão do C++.
Os dois ponteiros inteligentes mais usados são `std::unique_ptr` e `std::shared_ptr`.

## Ponteiros únicos

`std::unique_ptr` é um ponteiro inteligente que possui o objeto com exclusividade.
Ele garante que, a qualquer momento, apenas um objeto `std::unique_ptr` seja dono do recurso.
Quando o `std::unique_ptr` dono é destruído ou reiniciado, ele destrói automaticamente os objetos e libera a memória.

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## Vantagens de `std::make_unique()`

Ao criar um `std::unique_ptr`, é preferível usar `std::make_unique()` em vez de usar `new` diretamente para alocar memória.
`std::make_unique()` oferece várias vantagens:
1. **Segurança de exceções**: `std::make_unique()` garante segurança de exceções.
  Se uma exceção for lançada durante a construção do objeto, a memória será desalocada automaticamente, evitando vazamentos de memória.
2. **Clareza**: usar `std::make_unique()` deixa o código mais claro e mais conciso.
  Elimina a necessidade de especificar explicitamente o tipo que está sendo alocado, já que os argumentos de template são deduzidos automaticamente.
3. **Oportunidades de otimização**: os compiladores têm a oportunidade de otimizar `std::make_unique()` de forma mais eficaz do que alocar memória manualmente com `new`, o que pode resultar em desempenho melhor.
4. **Evitar uso indevido**: é possível excluir o recurso subjacente quando o `std::unique_ptr` é construído manualmente.
  Isso levaria a comportamento indefinido quando o `std::unique_ptr` tenta excluí-lo no fim do seu escopo.

## Ponteiros compartilhados

`std::shared_ptr` é um ponteiro inteligente que permite que vários objetos `std::shared_ptr` compartilhem a propriedade do mesmo recurso.
Ele mantém o controle de quantos ponteiros compartilhados estão referenciando o recurso e desaloca a memória apenas quando o último ponteiro compartilhado dono do recurso sai de escopo ou é reiniciado.

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

~~~~exercism/caution
Em C++17 e versões anteriores, o uso de `std::shared_ptr` com arrays por meio de `std::make_shared<T[]>` não tem suporte direto.
Embora seja possível alocar arrays com `std::make_shared<T[]>`, criar ponteiros compartilhados diretamente a partir deles pode levar a comportamento indefinido, por causa das diferenças no gerenciamento de memória entre objetos individuais e arrays.
Em vez disso, considere usar `std::vector` ou funções de exclusão personalizadas para gerenciar arrays com ponteiros compartilhados de forma eficaz.
Ao lidar com alocação de arrays e ponteiros compartilhados em C++17, garanta sempre a compatibilidade com seu compilador e com a implementação da biblioteca padrão.
~~~~

## Vantagens de `std::make_shared()`

Assim como `std::make_unique()`, `std::make_shared()` oferece benefícios como maior eficiência de memória, segurança de exceções e legibilidade.
Ele combina a alocação de memória do bloco de controle e do objeto gerenciado em uma única operação, o que aumenta a eficiência e reduz o risco de vazamentos de memória.
Além disso, a dedução automática dos argumentos de template simplifica o código e melhora a legibilidade.
Usar `std::make_shared()` promove um código mais limpo, mais seguro e mais eficiente ao trabalhar com objetos `std::shared_ptr` em C++.

## Ponteiros fracos

`std::weak_ptr` é uma classe complementar a `std::shared_ptr` que oferece uma referência "fraca" a um objeto gerenciado por um ponteiro compartilhado, sem deter sua propriedade.

```cpp
// Creating a shared pointer
auto your_account = std::make_shared<std::string>("secret_subscription_password");
// Creating a shared pointer that shares ownership
auto your_flatmates_account = your_account;

// Creating a weak pointer from the shared pointer
auto your_flatmates_boyfriends_account = your_flatmates_account;
// if your_account and your_flatmates_account are deleted, there is no more reference to the shared pointer.
// your_flatmates_boyfriends_account will be a null pointer and cannot use the associated object any longer.
```

Ponteiros fracos são úteis em cenários em que referências cíclicas precisam ser quebradas para evitar vazamentos de memória.
`std::weak_ptr` foi criado para resolver o problema da propriedade cíclica, também conhecida como referências circulares, que pode ocorrer ao usar `std::shared_ptr`.
Em um cenário de propriedade cíclica, dois ou mais objetos `std::shared_ptr` referenciam uns aos outros, criando um ciclo em que nenhum dos objetos pode ser excluído, porque todos têm referências fortes entre si, o que leva a vazamentos de memória.
`std::weak_ptr` oferece uma solução para esse problema ao permitir referências fracas a objetos compartilhados sem contribuir para a contagem de referências deles.
Isso significa que ele pode observar e acessar o objeto compartilhado, mas não impede que ele seja excluído.
~~~~

## Recomendações de uso

Use ponteiros inteligentes por padrão: `std::unique_ptr` para propriedade exclusiva e `std::shared_ptr` para propriedade compartilhada.
Reserve os ponteiros brutos para referências que não detêm propriedade ou para interagir com código legado.
Na maioria dos casos, `std::unique_ptr` é suficiente para propriedade exclusiva, pois oferece um gerenciamento de memória leve, sem a sobrecarga da contagem de referências.
`std::shared_ptr` deve ser usado com moderação, pois introduz sobrecarga e complexidade, a menos que a propriedade compartilhada seja realmente necessária.
`std::weak_ptr` é especializado em quebrar dependências cíclicas ou observar objetos compartilhados, mas não é usado com frequência.
