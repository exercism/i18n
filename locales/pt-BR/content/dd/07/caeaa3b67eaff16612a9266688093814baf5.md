# Sobre

## Introdução

Genéricos são um recurso da linguagem que possibilita o reuso de código.
Por exemplo, não deveria importar qual tipo uma lista guarda para calcular o seu comprimento.
É por isso que a função `length` usa um parâmetro de tipo genérico `a` na sua assinatura de tipo.

```elm
length : List a -> Int
```

## Parâmetros em tipos

Quando um tipo é genérico em relação a outro tipo, usamos um nome em minúsculas para esse outro tipo e o chamamos de parâmetro de tipo.
Exemplos comuns são os tipos personalizados `List`, `Maybe` e `Result`.

```elm
-- Maybe is generic over the type a
type Maybe a
    = Nothing
    | Just a

someString : Maybe String
someString = Just "hello"

someInt : Maybe Int
someInt = Just 42
```

Uma observação importante sobre os nomes dos parâmetros de tipo é que eles podem ter mais de um caractere.
A única restrição é que devem ser nomes em minúsculas.
Por isso, quando é útil, costumamos dar a eles nomes descritivos.

Um tipo pode ser genérico em relação a vários outros tipos e, assim, ter vários parâmetros de tipo.
Nesse caso, cada tipo independente recebe um nome em minúsculas diferente.
Serem independentes não impede que eles se tornem o mesmo tipo; apenas permite que sejam diferentes.

```elm
-- Result is generic over the types error and value
type Result error value
    = Ok value
    | Err error
```

Aliases de tipo de registro também podem ter parâmetros de tipo, embora seja menos comum.

```elm
-- Event is generic over the type a
type alias Event a =
    { at : Time
    , data : a 
    }
```

> É por isso que o pacote `Html` define o tipo `Html msg`, com um parâmetro de tipo chamado `msg`.
> A arquitetura Elm orienta você a criar um tipo personalizado `Msg` que descreve todas as mensagens que a sua página web pode disparar.
> Como resultado, seu código vai construir views do tipo `Html Msg`, em que `Msg` é o tipo concreto que você definiu.
> Quem está começando às vezes se confunde entre erros que mencionam `Html msg` (em minúsculas) e erros com `Html Msg`.
> Agora você já sabe!
> A diferença é que o primeiro é genérico em relação a qualquer tipo `msg`, enquanto o segundo é específico para o seu tipo `Msg`.

## Parâmetros de tipo em funções

Como os tipos podem ser genéricos, as funções também podem.
É possível escrever funções que lidam com tipos genéricos, como a `Maybe.withDefault`.

```elm
withDefault : a -> Maybe a -> a
withDefault default maybe =
    case maybe of
      Just value -> value
      Nothing -> default
```

Funções que recebem outras funções como parâmetros são chamadas de funções de ordem superior, e essas também podem ser genéricas.

```elm
map : (a -> b) -> Maybe a -> Maybe b
map function maybe =
  case maybe of
    Just value ->
      Just (function value)

    Nothing ->
      Nothing
```

Parâmetros de tipo podem aparecer tanto nas entradas quanto na saída de uma função, e a genericidade possibilitada pelos parâmetros de tipo costuma ser chamada de **polimorfismo paramétrico**.
Isso contrasta com o polimorfismo ad hoc, também conhecido como sobrecarga de funções, em que o mesmo nome de função pode ser usado em várias implementações em que os tipos são diferentes.
Também contrasta com o polimorfismo de subtipo, em que os tipos podem ser definidos em uma hierarquia, e as funções definidas em um tipo também podem ser chamadas com argumentos de seus subtipos.
Em Elm, o único mecanismo de genericidade disponível é o polimorfismo paramétrico.
