# Diretrizes de contribuição

Se você quer participar do desenvolvimento da trilha de Pharo, siga as instruções abaixo, que vão ajudar você a começar.

Estamos animados para melhorar esta trilha e mostrar aos desenvolvedores uma forma diferente de pensar sobre programação! :tada:

Leia como [participar de uma trilha do Exercism](https://github.com/exercism/docs/tree/master/contributing-to-language-tracks) e não deixe de ler o [Código de Conduta do Exercism](https://exercism.io/code-of-conduct).

Acolhemos pull requests de todos os tipos. Nenhuma contribuição é pequena demais, especialmente as que trazem correções e melhorias para exercícios existentes. Observe que os exercícios desta trilha precisam seguir os [padrões válidos para todo o Exercism](https://github.com/exercism/docs/tree/master/language-tracks/exercises), mas se você não tiver certeza de como fazer uma mudança, abra uma issue no GitHub e vamos conversar sobre isso.

>__Nota__: A organização do Exercism decidiu [pausar as contribuições da comunidade em geral](https://exercism.org/blog/freeing-our-maintainers). A trilha de Pharo ficou de fora dessa política, já que nossa comunidade é bem pequena (em outras palavras: qualquer contribuidor da trilha de Pharo ainda pode criar issues e enviar PRs).

## Pré-requisitos de conhecimento

Espera-se que você já esteja [familiarizado](./docs/RESOURCES.md) com o desenvolvimento em Pharo e com o uso do [Iceberg Git](https://github.com/pharo-vcs/iceberg).

## Preparação do ambiente de desenvolvimento

Para começar, você precisa garantir que tem um ambiente de desenvolvimento do Exercism completo e que instalou os seguintes itens:

### __Imagem e IDE do Pharo__

Você precisa de um ambiente de desenvolvimento Pharo (uma imagem Pharo em execução, ou seja, a IDE) para criar os exemplos de código propriamente ditos.

1. Use o [PharoLauncher](https://pharo.org/download) para criar uma imagem de desenvolvimento nova e estável a partir da categoria `Official distributions` (em 05/24, a imagem estável é: Pharo 12.0 - 64bit (stable)) e inicie-a (você também pode usar o [zerconf](https://get.pharo.org/) se já estiver familiarizado com ele).
2. Inicie a sua imagem para testar se tudo roda sem problemas.

> __Nota__: Se você tiver algum problema de TIMEOUT, consulte as [instruções de instalação para usuários](./docs/INSTALLATION.md).

### __Configuração dos repositórios git__

1. Se você ainda não fez isso antes, faça um fork de `https://exercism/pharo-smalltalk` no GitHub.
2. Para clonar o seu fork, execute o seguinte comando no Playground da imagem Pharo em execução:
```
Metacello new
 baseline: 'Exercism';
 repository: 'github://exercism/pharo-smalltalk:main/releases/latest';
 load: 'dev'
```
Isso vai, de fato, clonar o repositório git da trilha de Pharo e carregar o código-fonte da trilha na imagem Pharo, a sua baseline de desenvolvimento. A pasta local com o repositório clonado ficará em (dependendo das suas preferências do Iceberg): `<path-to-Pharo-image>/pharo-local/iceberg/<your-id/pharo-smalltalk`.
> __Nota__: Os fontes da imagem Pharo são sincronizados e serializados em arquivos `*.st` localizados na subpasta `src` do diretório mencionado acima.

2. Outra forma de fazer o mesmo é clonar o seu fork pela CLI: `git clone https://github.com/<your id>/pharo-smalltalk` como um projeto do GitHub e especificar `<your id>` como o nome do proprietário e `pharo-smalltalk` como o nome do projeto.
Depois, instale a baseline `dev` do Metacello (não a padrão) no Iceberg usando o menu de contexto do Metacello da imagem Pharo em execução. (por exemplo, clique com o botão direito no projeto "pharo-smalltalk" que você acabou de clonar, selecione a segunda opção do menu do Metacello e digite `dev`)

3. Depois de carregar o projeto na imagem Pharo, não esqueça de __Salvar imagem__ com as alterações (item de menu Pharo -> Save).

__Repositórios opcionais__
1. Como alternativa, você pode fazer `git clone https://github.com/exercism/pharo-smalltalk` como um repositório de staging, no qual você vai gerar exercícios e assets para incluir no check-in (separadamente da codificação no Pharo). Observe que as mudanças geradas pela ferramenta Configlet nesse repositório precisarão ser copiadas para o repositório do seu fork local. A sugestão é usar algo como `~/development/exercism/pharo-staging` para evitar qualquer confusão (observação: ele pode ficar em qualquer lugar). Esse repositório não é necessário: você ainda pode gerar as mudanças do configlet diretamente no repositório do seu fork (que está sincronizado com a sua imagem Pharo), se tiver certeza de quais mudanças incluir no commit.
2. Você também pode clonar as [especificações de problemas](https://github.com/exercism/problem-specifications) do Exercism, caso queira trabalhar em exercícios de prática do zero. Coloque-as também em uma subpasta do workspace do exercism configurado abaixo (esse repositório é usado para gerar os arquivos readme.md dos exercícios e serve de referência para os testes sugeridos).

### __Observação sobre os branches usados no repositório__

O branch `main` é o branch principal de desenvolvimento, para o qual tudo é mesclado. Se você trabalhar em alguma mudança no código, crie um branch de feature originado do main e faça seus commits nele. Quando terminar, abra um PR no GitHub para que ele seja mesclado no `main` do repositório base (Exercism/pharo-smalltalk). Esse branch antes se chamava `master`, __agora obsoleto__.

### __Configuração das ferramentas de CLI do Exercism__

Essas ferramentas são necessárias para interagir com o projeto Exercism:
1. a [interface de linha de comando do exercism](https://exercism.io/cli-walkthrough), configurada para o diretório de desenvolvimento de exercícios do Exercism chamado workspace (por exemplo, `exercism configure -w ~/development/exercism`). Esse caminho pode ser tanto o do repositório do seu fork local quanto o (opcional) repositório de staging.
2. o linter/gerador [configlet](https://github.com/exercism/configlet#usage) do Exercism, para gerar metadados de exercícios e rodar validações. Para instalar o Configlet, siga as instruções do parágrafo [Usar na sua trilha](https://github.com/exercism/configlet#use-in-your-track) (veja bin/fetch-configlet).

## Trabalhando nos exercícios do Exercism

A organização do Exercism distingue entre exercícios de conceito (que explicam a teoria das linguagens de programação) e exercícios de prática. Por enquanto, os parágrafos abaixo focam apenas na contribuição com exercícios de prática.

### __Visão geral__

Etapas para completar um exercício:
1a. Criar um exercício de prática do zero (a partir das especificações de problemas).
1b. Trabalhar na solução de um exercício de prática existente.
2a. Gerar os arquivos-fonte serializados da solução do exercício no diretório e gerar os metadados do exercício.
2b. Ajustar a baseline do projeto para incluir o exercício recém-concluído como parte do projeto.
3. Fazer commit das mudanças no fork do seu repositório e publicar as mudanças abrindo um PR.

#### TLDR: Guia rápido para gerar e exportar um exercício de prática
Resumindo: tudo o que você precisa é gerar e exportar o exercício do Pharo; execute no Playground:
```Smalltalk
"Obtain exercise from problem specification"
ExercismExerciseGenerator new generateExerciseFrom: 'path-to-problem-specifications/exercises/slug-name' asFileReference.

"Update exercise version within Pharo image  (with updated test cases) to output exercise directory (once you have solution class defined)"
ExercismGenerator new 
	exercisesDirReference: 'path-to-local-repository/exercises/practice' asFileReference;
	generateForExercise: 'slug-name'.
```
  > __Nota__: Mais detalhes nas etapas abaixo. 

![Fluxo de trabalho para completar um exercício de prática](/docs/images/overview-exercism-pharo-contribution.svg)

### __1. Criar um novo exercício de prática__
*TLDR: Todos os detalhes e a descrição da API relacionados à geração de exercícios estão no comentário de classe da classe `ExercismExerciseGenerator`.*  

__Novos exercícios a partir do repositório de problemas__
- Se você quiser começar um exercício de prática totalmente novo (etapa 1a.), use o repositório de especificações de problemas e gere a classe de teste para o exercício em questão executando: 
`ExercismExerciseGenerator generateFrom: <path-to-problem-specifications/exercises>` - isso vai gerar as classes de teste de todos os exercícios do repositório de especificações de problemas no pacote `ExerciseWIP`.  

  > __Nota__: Você pode usar um item de menu na imagem Pharo para fazer o mesmo (World menu -> Exercism -> Generate test cases).
- Mais especificamente, você pode gerar a classe de teste de um exercício específico com: `ExercismExerciseGenerator generateExerciseFrom: '<path-to-problem-specifications/exercises/slug-name>' asFileReference`.

O resultado do comando anterior será uma nova classe de teste `<SlugNameTest>` (uma subclasse de ExercismTest) com os métodos de teste gerados no pacote `ExerciseWIP`.

__Regenerar um exercício existente a partir do repositório de problemas__
Se você quiser regenerar os métodos de teste de um exercício existente (já definido no pacote da solução, por exemplo `Exercise@TwoFer`), use o código a seguir. Observe que os outros métodos não serão alterados (por exemplo, uuid, version etc.) 

 `ExercismExerciseGenerator new regenerateExerciseFrom: 'path-to-problem-specifications/exercises/exercise-slug' asFileReference`

__Do zero__  
Se você tiver uma ideia interessante, consulte a documentação sobre como adicionar novos exercícios.

Há um exemplo de exercício definido pelo usuário no projeto, veja: `DieTest`. Ao sobrescrever o método customData, o gerador cria os arquivos relevantes para você.

Observe que:
- Cada exercício deve ser independente. Não referencie arquivos fora do diretório do exercício. Eles não serão incluídos quando o usuário baixar o exercício.
- Os exercícios precisam seguir os [padrões válidos para todo o Exercism](https://exercism.org/docs/building/tracks/practice-exercises).
- Os exercícios devem usar apenas as bibliotecas centrais do Pharo.
- Cada exercício deve:
  - ficar armazenado em um projeto de nível superior chamado `Exercism@<ExerciseName>`
  - ter um TestCase chamado `<ExerciseName>Test` (em CamelCase) e uma solução de exemplo chamada `<ExerciseName>`
  - o TestCase deve ter um comentário de classe em formato markdown que descreva o exercício. Esse texto também é usado para gerar um arquivo README.md.
- Não faça commit de nenhum arquivo ou diretório de configuração dentro do exercício (isso pode ser revisto para exercícios futuros; avise a gente se virar um problema).
- Certifique-se de gerar um novo UUID para o exercício com `UUIDGenerator next` e colocar esse valor no método `uuid` do teste.

> __Nota__: Infelizmente, o gerador de UUID atual do Pharo não é compatível com a RFC 4122, versão 4. Por isso, o UUID gerado pelo configlet deve ser usado, avaliando: `/bin/configlet uuid`

### __2. Trabalhar em um exercício existente__

Embora existam muitas formas de ajudar, de longe a contribuição mais fácil e mais útil é completar a solução de algum dos exercícios que estão "abertos" no momento.

  * Garanta que a sua imagem esteja atualizada com o main do exercism/pharo-smalltalk (e envie quaisquer mudanças de volta para o seu fork)

  * Os exercícios são todos TestCases gerados automaticamente a partir do repositório problem-specifications mencionado acima. Você vai encontrá-los como subclasses de ExercismTest no pacote ExercismWIP. Observe que um ExercismTest regenerado pode já estar no pacote do exercício em questão, se a solução já existir. O pacote ExercismWIP é usado para os exercícios novos ou em andamento que ainda não foram publicados, junto com a classe de solução.

  * Depois de escolher um exercício no qual você quer trabalhar, crie uma issue no GitHub especificando "Convert Exercise <name>". Assim, outras pessoas vão saber que você está trabalhando nele, e isso também vai servir de base para o seu pull request depois.

  * Cada exercício em andamento já tem a descrição do problema no comentário de classe; você roda os testes dele e desenvolve a solução com TDD (no debugger, se você rodar o primeiro teste sozinho).

  * Talvez você precise __ajustar o teste se ele não for Smalltalk idiomático__ (nosso gerador é bem básico; dito isso, algumas correções podem ser apropriadas como PRs de volta para o texto upstream das [especificações de problemas](https://github.com/exercism/problem-specifications)).

  * Atualize os metadados do exercício no lado da classe do exercício, sobrescrevendo o método #exercise e preenchendo a dificuldade, os tópicos etc. Você também deve preencher um texto de dica na aba de comentário do Test (na parte de baixo, substituindo o texto TBD)

  * Atualize o pacote do exemplo escolhido para `Exercise@<ExerciseName>` (ou seja, tire-o do pacote WIP), etapa 1b.
  * Crie um novo branch no Iceberg com o nome do exercício que você escolheu (você pode usar a ferramenta Iceberg para isso e informar o número da issue que criou acima).
  * Antes de enviar o seu pull request, rode todos os testes dos exercícios de Pharo e garanta que __todos passem__.


### Testes

No nível mais básico, o Exercism gira em torno dos testes e de testar com [suítes de testes](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md).

Os exercícios de Pharo do Exercism são organizados em subpacotes, e cada um contém um TestCase que precisa ser compatível com o [SUunit](https://en.wikipedia.org/wiki/SUnit). Essa é a biblioteca xUnit original, e não são necessários frameworks de terceiros adicionais para os exercícios.

Para testar um exercício, rode-o pelo executor de testes integrado, clicando no orbe de teste. O orbe fica verde se os testes passarem, ou laranja ou vermelho se houver falhas ou erros, respectivamente. Como alternativa, você pode rodar os testes manualmente no playground avaliando:

```smalltalk
<ExerciseName>Test suite run. "single exercise"

AllExercismTests suite run. "all exercises"
```
> __Nota:__ Se você quiser definir o seu próprio caso de teste (não gerado), pode colocá-lo no protocolo `extra` da classe de teste.
Por consistência, usamos a ordem dos parâmetros nos testes: `self assert: actual equals: expected` no método de teste.


Para testar em uma imagem que não é de desenvolvimento, siga as [etapas de instalação para usuários](./docs/INSTALLATION.md). Se você
estiver usando essa imagem para testar baselines de desenvolvimento seguintes, talvez precise apagar os seguintes diretórios de desenvolvimento para garantir que vai pegar o código mais recente:
`./pharo/pharo-local/iceberg, ./pharo/pharo-local/package-cache`


### __3. Publicando um exercício concluído__

Agora que você terminou a solução e fez os commits no seu branch de feature local, siga estas etapas:  
#### Gerar o código-fonte do exercício
Isso se refere à etapa 2a: __Gerar os arquivos de código-fonte__ da solução e da(s) classe(s) de teste.

__Gerar os fontes de saída de todos os exercícios__ 
- `ExercismGenerator generate` -> isso vai gerar todos os arquivos-fonte de todos os exercícios. Ele roda o comando `generate` do configlet e também regenera o `config.json`, que lista todos os exercícios válidos. (Ou, no menu World, escolha: "Exercism" -> "Regenerate meta data")

#### Gerar os fontes de saída de um exercício específico
- Para usar o diretório padrão (`repository-root/exercises/practice`)
```
ExercismGenerator new generateForExercise: 'slug-name'
```

Quando precisar exportar para um diretório de exercício específico:
```
ExercismGenerator new 
	exercisesDirReference: 'path-to-exercises/practice' asFileReference;
	generateForExercise: 'slug-name'
```

> __Notas__: 
  - O ExercismGenerator vai atualizar o config.json principal automaticamente (cria um novo, se não existir).
  - vai sincronizar todos os docs, metadados e caminhos de arquivo do(s) exercício(s) especificado(s) usando o comando configlet. Veja detalhes: [Usar sync ao adicionar um novo exercício](https://github.com/exercism/configlet#using-sync-when-adding-a-new-exercise-to-a-track)

####  Atualizar a baseline do projeto Pharo-smalltalk
Etapa 2b: atualize a baseline do projeto Pharo-smalltalk adicionando o nome do exercício na lista do método `BaselineOfExercism>>exercisePackageNames`. Isso garante que o seu exercício seja carregado quando o projeto for carregado incluindo o novo exercício pelo comando do Metacello.
  
#### Enviando um pull request
Etapa 3: antes de criar o PR, verifique se os artefatos do Exercism estão corretos rodando o comando de CLI:
`bin/configlet lint` (a automação de CI vai rodar o lint de qualquer forma quando o PR for enviado).  
Se tudo estiver certo, o PR pode ser criado:
- envie o seu branch para o seu fork e depois crie um pull request em `exercism/pharo-Smalltalk` 

> __Detalhes finais__: 

- É importante [permitir edições de mantenedores](https://help.github.com/en/articles/allowing-changes-to-a-pull-request-branch-created-from-a-fork), para que possamos colaborar com você no seu branch.
- Os pull requests devem ser focados em um único exercício, issue ou mudança conceitualmente coesa. Consulte as [diretrizes de pull request](https://github.com/exercism/docs/tree/main/building/github#guides) do Exercism para mais detalhes.
- Acompanhe o seu PR e responda a quaisquer perguntas que surgirem.
- Por fim, envie os ajustes necessários, e um mantenedor vai mesclar o seu pull request para que a solução final apareça no site.

## Informações adicionais para mantenedores

### Estilo de código

O código deste repositório deve seguir as convenções do [Pharo with style](https://github.com/SquareBracketAssociates/Booklet-PharoWithStyle) sempre que possível. Você também pode consultar o [Smalltalk with style](http://sdmeta.gforge.inria.fr/FreeBooks/WithStyle/SmalltalkWithStyle.pdf), que é mais genérico.

Você também deve usar o formatador de código integrado (meta-t FO no editor) ao criar exercícios, assim como as críticas de código.

### Mudanças que quebram compatibilidade

Se você planeja fazer mudanças significativas ou que quebrem compatibilidade, abra uma issue para que possamos discutir antes de mesclar. Se essa discussão for relevante para além da trilha de Pharo, abra também uma issue em [exercism/discussions](https://github.com/exercism/discussions/issues).
