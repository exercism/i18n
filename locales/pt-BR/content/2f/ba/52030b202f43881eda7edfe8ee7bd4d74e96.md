# Introdução

## Strings

### Caracteres

Uma **codificação de caracteres** é uma convenção específica usada para representar elementos de texto de uma língua natural como uma sequência de bytes.
Um "elemento de texto" aqui pode ser qualquer unidade que tenha significado em uma língua natural, por exemplo, letras, espaços, pontuação, emojis, ideogramas, etc.

O NASM (The Netwide Assembler, o montador usado por esta trilha) tem suporte à definição de dados usando **ASCII**.

Constantes de caractere no NASM podem ter até 8 bytes e podem ser definidas com aspas simples (`'`), aspas duplas (`"`) ou crases (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Caracteres especiais precisam ser definidos entre crases e escapados com `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Observe que não há suporte nativo a nenhuma codificação de caracteres no x86-64 como um tipo distinto.
Em assembly, os dados são uma sequência de bytes, e a interpretação desses bytes como um caractere, um número ou qualquer outra coisa fica a cargo de quem programa.

Por exemplo, o caractere ASCII '0' é um único byte com o valor 48.
Então, armazenar 48 em um byte é exatamente o mesmo que armazenar o caractere ASCII '0':

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Pela mesma razão, manipular caracteres é feito transformando diretamente os valores nesses bytes:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

### Strings

Uma **string** é uma sequência de caracteres.
Em assembly, ela costuma ser implementada como um array.

É possível declarar uma string no NASM da mesma forma que qualquer array pode ser declarado:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Uma diferença entre strings e outros arrays é que o NASM também tem suporte à declaração de strings sem uma vírgula (`,`) separando os valores.
Também é possível intercalar valores com vírgulas:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Observe que, como já foi dito, caracteres são apenas bytes (ou uma sequência de bytes em codificação Unicode):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Como cada caractere ASCII ocupa um único byte, qualquer byte seguinte em um tamanho maior é `0`.
Por exemplo, declarar `'a'` como um qword (8 bytes) significa que o primeiro byte é `'a'` (`97`) e os outros sete bytes são todos `0`.

Por essa razão, todos estes são equivalentes:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
Em assembly, strings não são terminadas automaticamente por um caractere NUL do ASCII (valor `0`).

Ao fazer interface com linguagens de nível mais alto, como C, é responsabilidade de quem programa garantir que o terminador correto, se houver, seja acrescentado ao final da string.
~~~~

### Instruções de string

Como strings são arrays, você pode trabalhar com elas da mesma forma que com qualquer array, desreferenciando a memória explicitamente:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Além disso, existem algumas instruções para carregar, mover e armazenar valores em sequências de bytes na memória.
Embora sejam chamadas de _instruções de string_, podem ser usadas com qualquer sequência de bytes na memória, ou seja, com qualquer array.

As três instruções de string mais importantes são `lods`, `stos` e `movs`:

| instrução | o que ela faz                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | carrega um valor de um local de memória indicado por `rsi` para `rax`                                                |
| `stos`      | armazena um valor de `rax` em um local de memória indicado por `rdi`                                               |
| `movs`      | copia um valor de um local de memória indicado por `rsi` e o armazena em um local de memória indicado por `rdi`    |

Observe que essas instruções _não_ recebem nenhum operando explícito.
Seus operandos são implícitos.

Como regra geral:

1. Quando o operando de origem delas é um local de memória, o endereço dele deve ser armazenado em `rsi` (`s` de source).
2. Quando o operando de destino delas é um local de memória, o endereço dele deve ser armazenado em `rdi` (`d` de destination).
3. Se um dos operandos não for um local de memória, ele é o registrador `rax`.

Observe que essas instruções desreferenciam automaticamente os endereços de memória de acordo com a operação específica que executam.

Todas elas podem operar em tamanhos diferentes.
Um sufixo é acrescentado para indicar esse tamanho:

| sufixo | significado | tamanho    |
| :----: | ------- | :------ |
|  `b`   | byte    | 1 byte  |
|  `w`   | word    | 2 bytes |
|  `d`   | dword   | 4 bytes |
|  `q`   | qword   | 8 bytes |

Por exemplo:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

Elas também atualizam todo endereço usado pelo tamanho da operação.
Essa atualização é feita de acordo com o valor da **flag de direção (DF)**:

- Se a `DF` estiver limpa, os endereços são _aumentados_ pelo tamanho da operação.
- Se a `DF` estiver definida, os endereços são _diminuídos_ pelo mesmo valor.

A ABI do System V determina que a flag de direção precisa estar limpa na entrada da função.
Então, _o comportamento padrão é que a memória seja lida/gravada em ordem crescente de endereços_.

A instrução `cld` pode ser usada para limpar a flag de direção, enquanto a instrução `std` a define:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Quem chama espera que a `DF` esteja limpa depois que qualquer função chamada retorna, conforme a ABI do System V.
Se você alguma vez definir a `DF`, certifique-se de limpá-la antes do `ret`.
~~~~

#### Rep

Além dessas, a instrução **rep** não interage diretamente com a memória.
Em vez disso, ela pode ser adicionada como prefixo às outras instruções mencionadas, _repetindo_ essas instruções.

Quando prefixadas com `rep`, as instruções de string são repetidas um número de vezes igual ao valor em `rcx`.
A cada vez, o valor em `rcx` é decrementado em `1`.
Observe que o valor em `rcx` precisa ser definido antes de a instrução ser usada:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
Em CPUs modernas, `rep movs` e `rep stos` costumam ser opções rápidas ao mover dados em blocos grandes.
Já outras instruções de string, e até `movs` e `stos` quando operam sem `rep`, costumam ser mais lentas que um laço comum.

Uma visão mais aprofundada sobre esse tópico pode ser encontrada no [Capítulo 16.9, "String instructions", deste livro de referência][agner-optimization-guide].
