# golint não está satisfeito

Existe uma ótima ferramenta chamada [`golint`](https://github.com/golang/lint) que examina o código em busca de problemas comuns e questões de estilo.
Rode o `golint` na solução, por exemplo: `golint two_fer.go`; ela vai fazer algumas sugestões úteis.

É uma boa ideia sempre conferir o código com o `golint`.
Quando você escreve software em Go para produção, muitos pipelines de build falham automaticamente se o código não passar no `golint`.

Se você quiser receber muito mais feedback de linters de código, existe o projeto [golangci-lint](https://github.com/golangci/golangci-lint), que permite rodar vários linters com um único comando.
Um arquivo de configuração do projeto pode ajustar o comportamento às necessidades dele.

```
> golint
%{golint}
```
