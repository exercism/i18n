# Sobre

Neste ponto do programa de estudos, você já viu muitas definições de função. Normalmente, elas apareciam sem muitos comentários sobre a saída no REPL:

```julia-repl
julia> f(x) = x^2
f (generic function with 1 method)
```

Por que _"generic function with 1 method"_?

Suponha que você queira ser mais específico quanto aos tipos dos argumentos.

```julia-repl
julia> f(x::Integer) = x^2
f (generic function with 2 methods)

julia> f(x::Real) = x^2
f (generic function with 3 methods)
```

Ou poderíamos mudar o número de argumentos:

```julia-repl
julia> f(x, y) = x * y
f (generic function with 4 methods)
```

Parece que novas definições da mesma função são chamadas de "métodos". Os métodos são acrescentados a uma lista, em vez de sobrescrever a definição antiga.

Podemos listar os métodos com facilidade:

```julia-repl
julia> methods(f)  # output edited for brevity
# 4 methods for generic function "f" from Main:
 [1] f(x, y)
 [2] f(x::Integer)
 [3] f(x::Real)
 [4] f(x)
 ```

Se chamarmos a função `f`, Julia de alguma forma sabe qual método usar:

```julia-repl
julia> f(2.5)  # Float64
6.25

julia> f(2)  # Int64
4

julia> f(2, 3)  # Int64, Int64
6
```

## O que é uma função?

Segundo o [manual][function], uma função é um objeto que mapeia uma tupla de argumentos para um valor de retorno. Isso é próximo da definição que os matemáticos usam.

Normalmente pensamos nos argumentos da função em `f(2, 3)` como dois itens separados, mas o compilador os vê como uma única [tupla][tuple]. Isso vale até para um único argumento (embora precisemos acrescentar uma vírgula para deixar isso mais claro):

```julia-repl
julia> typeof( (2, 3) )
Tuple{Int64, Int64}

julia> typeof( (2,) )
Tuple{Int64}
```

Enxergando a função como uma caixa preta, podemos dizer que uma tupla entra e um valor de retorno sai. De forma mais formal, a tupla é _mapeada_ para um valor de retorno.

## Como as funções lidam com diferentes números e tipos de argumentos?

Isso costuma ser chamado de ["polimorfismo"][polymorphism].

Esse tem sido um grande tema na ciência da computação há várias décadas, e diferentes abordagens foram adotadas.

A abordagem de Julia é incomum, embora não seja única.

- As funções são ["genéricas"][generic], ou seja, podem ter vários métodos associados a elas.
- As funções são apenas nomes, até que tenham métodos associados.
- Os métodos podem ser adicionados conforme a necessidade, potencialmente em grande número (atualmente, o operador `+` é uma função com 161 métodos).
- Quando uma função é chamada, Julia examina a assinatura da chamada: o número de argumentos e o tipo atual de cada um.
- O método que corresponde mais de perto à assinatura da chamada é selecionado.
  - Em geral, o número de argumentos precisa corresponder exatamente (embora o operador [splat/slurp][splat] `...` possa contornar isso parcialmente).
  - Métodos cujos tipos correspondem exatamente à assinatura da chamada têm preferência.
  - Se necessário, Julia examina os supertipos de cada argumento da assinatura da chamada para encontrar o método mais específico e que corresponde mais de perto.
- O método escolhido é [`dispatched`][dispatch] com os argumentos fornecidos e retorna um resultado.
- Se nenhum método adequado for encontrado, um [`MethodError`][methoderror] é lançado.

Observe que Julia tem tipagem dinâmica, então o despacho de métodos acontece em _tempo de execução_.

## Despacho múltiplo: um exemplo

A seção anterior teve muitas palavras, então vamos transformar essas ideias em código. Para simplificar, as funções abaixo têm apenas um argumento, mas não é incomum encontrar funções com dezenas de argumentos (como em pacotes de plotagem ou em aprendizado de máquina).

Comece definindo alguns tipos personalizados para representar formas geométricas.

```julia-repl
julia> abstract type Shape end

julia> struct Circle <: Shape
           radius::Float64
       end

julia> struct Square <: Shape
           side::Float64
       end

julia> struct Rectangle <: Shape
           length::Float64
           width::Float64
       end
```

Em seguida, podemos definir métodos para calcular a área de cada forma. Cada um recebe um argumento, de um tipo concreto e definido pelo usuário diferente em cada caso.

```julia-repl
julia> area(c::Circle) = π * c.radius^2
area (generic function with 1 method)

julia> area(s::Square) = s.side^2
area (generic function with 2 methods)

julia> area(r::Rectangle) = r.length * r.width
area (generic function with 3 methods)
```

Agora podemos criar algumas formas e calcular as áreas, contando com o mecanismo de despacho de Julia para usar a fórmula correta em cada caso.

```julia-repl
julia> circle = Circle(2.3)
Circle(2.3)

julia> area(circle)  # call signature Tuple{Circle}
16.619025137490002

julia> square = Square(1.6)
Square(1.6)

julia> area(square)  # call signature Tuple{Square}
2.5600000000000005

julia> rectangle = Rectangle(1.4, 2.1)
Rectangle(1.4, 2.1)

julia> area(rectangle)  # call signature Tuple{Rectangle}
2.94
```

## [Métodos paramétricos][parametric]

As assinaturas de métodos podem receber valores de tipo fictícios, mais ou menos da mesma forma que os tipos paramétricos.

A sintaxe é peculiar e exige uma cláusula `where`:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T} = true
same_type (generic function with 1 method)

julia> same_type([1, 2], 3)
true

julia> same_type([1, 2], "three")
ERROR: MethodError: no method matching same_type(::Vector{Int64}, ::String)
```

O exemplo acima exige que os dois argumentos usem o mesmo tipo `T`, seja ele qual for.

Podemos ser mais específicos impondo uma restrição a `T`:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T<:Number} = true
same_type (generic function with 2 methods)
```

Com esse método, apenas tipos numéricos idênticos retornam `true`.

É possível ter várias variáveis fictícias, separadas por vírgulas na cláusula `where`. Os dois métodos a seguir são parecidos:

```julia-repl
julia> func(v::Vector{Number}, x::Number) = true
func (generic function with 1 method)

julia> func(v::Vector{S}, x::T) where {S<:Number, T<:Number} = true
func (generic function with 2 methods)
```

Uma diferença é que os valores de tipo `S` e `T` ficam disponíveis para uso dentro do corpo da função do segundo método. Esse é o tipo de truque que você talvez não use com frequência, mas que pode evitar muita dor de cabeça em algumas situações.

Por exemplo, na definição de tipo paramétrico a seguir, os campos precisam ser do mesmo tipo `T`, que é restrito a ser um subtipo de `Real`:
```julia
struct Point{T<:Real}
    x::T
    y::T
end
```
Essa definição de `Point` aceita um `x` e um `y` do mesmo tipo, ou pode aceitar um `x` e um `y` de tipos diferentes, mas nesse caso é preciso fornecer explicitamente um tipo de conversão.
```julia-repl
julia> Point(4, 5)
 Point{Int64}(4, 5)

julia> Point(3.5, 2)
 MethodError: no method matching Point(::Float64, ::Int64)    # Output truncated for brevity

julia> Point{Float32}(3.5, 2)
 Point{Float32}(3.5f0, 2.0f0)

julia> Point{Int64}(3.5, 2) 
 InexactError: Int64(3.5)      # Output truncated for brevity
```
Embora esse nível de controle sobre os tipos possa ser desejável, também pode ser útil ter um pouco de abstração.
```julia
Point(x::T, y::S) where {T<:Real, S<:Real} = Point{promote_type(T,  S)}(x, y)
```
Esse construtor externo oferece isso ao permitir que um `Point` aceite tipos heterogêneos para `x` e `y` sem especificar explicitamente o tipo de conversão. Os valores de tipo `T` e `S` são usados no corpo da função, em `promote_type(T, S)`, para fornecer o tipo de conversão explícito para a definição original.
```julia-repl
julia> Point(3.5, 2)
 Point{Float64}(3.5, 2.0)
```

## Comparação com outras linguagens

Como Julia examina todos os argumentos ao selecionar um método, isso é chamado de [`multiple dispatch`][multiple-dispatch].

Algumas outras linguagens permitem despacho múltiplo, como o Common Lisp, embora isso raramente seja tão central no projeto da linguagem quanto em Julia.

Em contrapartida, em uma linguagem orientada a objetos (OO) (por exemplo, Ruby), os métodos costumam ser chamados em uma [instância][instance]. A definição passa a privilegiar o primeiro argumento (com um nome como `self` ou `this` na definição), e o nome do método é ligado à instância com um ponto para chamá-lo:

```ruby
irb(main):004:0> "abc".sub("b", "*")
=> "a*c"
```

Isso é chamado de [`single dispatch`][single-dispatch], já que apenas a classe da instância (da string "abc" no exemplo acima) é usada para escolher um método.

Algumas linguagens OO de tipagem estática dão suporte a polimorfismo de métodos, que se parece um pouco com o despacho múltiplo. A grande diferença é que a seleção do método acontece apenas em _tempo de compilação_.

Linguagens funcionais costumam ter apenas uma única definição de função, com algum tipo de expressão Select/Case/Match para lidar com as diversas possibilidades. Você escreve sua própria lógica, geralmente com a ajuda de uma sintaxe concisa de correspondência de padrões que não existe em Julia. É claro que Julia também faz uma forma de correspondência de padrões, mas no despacho em vez de dentro do corpo da função.

## Conclusão

O despacho múltiplo é muito flexível e tem ótimo desempenho em Julia, por isso é amplamente usado.

Como sugere o exemplo dos 161 métodos para `+`, quem programa em Julia busca definir métodos com tipos bem específicos. Somar dois inteiros é muito diferente de somar dois números de ponto flutuante no nível do bytecode, e somar um inteiro a um ponto flutuante acrescenta ainda a complicação da promoção de tipos.

Quanto mais específico o tipo, mais otimizações o compilador pode fazer: algo de importância marginal em um exercício simples no Exercism, mas vital para o desempenho nas grandes simulações numéricas para as quais Julia foi projetada.

_Se você sabe quais entradas um método vai receber, conte isso ao compilador!_
