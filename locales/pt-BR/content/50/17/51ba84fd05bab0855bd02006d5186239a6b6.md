# Sobre

Embora Swift tenha muitos tipos diferentes, cada um deles se encaixa em uma de duas classificações: _tipos de valor_ e _tipos de referência_. Em Swift, [structs são tipos de valor][structs-are-value-types], enquanto [classes são tipos de referência][classes-are-reference-types].

A principal diferença entre tipos de valor e tipos de referência é que, quando um tipo de valor é atribuído a uma variável ou constante, ou passado para uma função, o que é atribuído ou passado é na verdade uma cópia do valor, e não aquele valor específico. Modificar uma cópia de um struct não afeta as outras cópias. Com tipos de referência, o que é atribuído ou passado é uma referência àquele valor, então dois nomes diferentes podem se referir à mesma instância de uma classe. Isso pode levar à modificação da instância original quando ela é acessada por outro nome.

Então, considerando o struct e a classe que definem um personagem em um jogo e suas estatísticas de jogo, dá para ver o que acontece quando esses itens são copiados e alterados.

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

Repare como alterar as propriedades de `charB` afetou as de `charA`, já que os dois nomes se referem à mesma instância. Repare também que, com as estatísticas dos dois personagens, os tipos de valor dentro de um tipo de referência mudam junto com o tipo de referência. Isso, porém, não é uma violação do comportamento dos tipos de valor, porque `charA.stats` é a mesma instância de `CharacterStats` que `charB.stats`, já que `charA` e `charB` se referem à mesma instância da classe `GameCharacter`. Como dá para ver, cópias desses tipos de valor não afetam umas às outras, por exemplo.

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

É por isso que os structs exigem a palavra-chave `mutating` antes dos métodos que alteram o estado das propriedades do struct. Alterar a propriedade de um struct na verdade cria uma nova cópia do struct com o novo valor definido para aquela propriedade, e a nova cópia substitui a antiga. É um indicador visual de que essa cópia e substituição podem acontecer para valores desse tipo.

Isso tem o efeito colateral de que qualquer instância de struct cujas propriedades variáveis mudam, seja chamando funções mutating ou por atribuição direta, _precisa_ ser atribuída a variáveis, e não a constantes. Caso contrário, o compilador gera um erro:

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

Os valores iniciais ainda podem ser criados e acessados, mas não têm permissão para mudar. Essa restrição não se aplica a classes. Se uma instância de uma classe é atribuída a um nome usando `let`, o que a constante guarda é a referência à instância, e é isso que não pode mudar, não a instância em si. Então a instância em si pode mudar, mas a referência não pode ser alterada para apontar para uma instância diferente.

Um resumo do que pode ser alterado em structs e classes definidos com `let` ou `var` é o seguinte

|         | **struct**                                                                                  | **class**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | _Não_ é possível atribuir um novo struct ao nome.</br>_Não_ é possível modificar nenhuma propriedade do struct. | _Não_ é possível atribuir uma nova classe ao nome.</br>_É possível_ modificar as propriedades mutáveis da classe. |
| **var** | _É possível_ atribuir um novo struct ao nome.</br>_É possível_ modificar as propriedades mutáveis do struct.   | _É possível_ atribuir uma nova classe ao nome.</br>_É possível_ modificar as propriedades mutáveis da classe.    |

## Identidade

Como dois nomes diferentes podem guardar uma referência à mesma instância de uma classe, às vezes é útil testar se é esse o caso. Swift usa o operador _idêntico_ `===` para testar isso (junto com sua negação, `!==`).

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

Como não existem dois nomes que possam se referir à mesma instância de um struct, esses operadores de identidade não são definidos para structs.

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

Repare que identidade não é a mesma coisa que igualdade. Por muitas definições, `char1` e `char3` seriam considerados iguais, já que todas as suas propriedades têm os mesmos valores, mas eles não compartilham a mesma identidade. A identidade está disponível automaticamente para todas as classes em Swift, mas normalmente quem desenvolve precisa escrever seus próprios operadores de igualdade para determinar se duas instâncias de um struct ou classe são _iguais_. Fazer isso está além do escopo deste exercício.
