# Sobre

As threads do Factor são *corrotinas cooperativas* em uma única thread do sistema operacional.
Uma thread roda até ceder o controle explicitamente ou fazer uma operação de E/S bloqueante;
nesse momento, o escalonador escolhe outra thread pronta para executar. Duas consequências:

- Tudo o que acontece entre um yield e outro é efetivamente atômico.
- O paralelismo real entre vários núcleos exige sair do vocabulário padrão `threads`
  (por exemplo, `concurrency.distributed` para projetos com múltiplos processos).

As primitivas de concorrência padrão são organizadas em camadas:

| Vocabulário                 | Fornece                                |
|-----------------------------|----------------------------------------|
| [`threads`][threads]                   | `spawn`, `yield`, identidade da thread |
| [`concurrency.promises`][concurrency.promises]      | `<promise>`, `fulfill`, `?promise`     |
| [`concurrency.locks`][concurrency.locks]         | `<lock>`, `with-lock`                  |
| [`concurrency.combinators`][concurrency.combinators]   | `parallel-map`, `parallel-each`        |
| [`concurrency.semaphores`][concurrency.semaphores]    | `<semaphore>`, `acquire`, `release`    |
| [`concurrency.mailboxes`][concurrency.mailboxes]     | caixas de entrada por thread, `send`, `receive` |
| [`concurrency.channels`][concurrency.channels]      | handles de encontro, `to`, `from`      |

```factor
USING: concurrency.combinators concurrency.locks
concurrency.promises kernel sequences threads ;

! parallel-map: fork-join, in order
{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }

! spawn + promise: hand-rolled fork-join
<promise> [
    [ "hello, world" swap fulfill ] curry "greeter" spawn drop
] keep ?promise .   ! => "hello, world"

! <lock> + with-lock: protect a shared mutable slot
<lock> :> guard
guard [ "do thing under lock" drop ] with-lock
```

`parallel-map` é a API de alto nível e a primeira ferramenta a que o Factor idiomático
recorre. O trio `spawn` / `<promise>` / `?promise` é a base sobre a qual `parallel-map` é
construído, o que ajuda quando o formato da iteração não se encaixa em map (por exemplo,
quando você cria workers que respondem por outros canais).

Os locks protegem *estado mutável compartilhado*, normalmente o slot de uma tupla ou uma
hashtable que mais de uma thread lê ou escreve. Considere que tanto as leituras quanto as
escritas precisam do lock sempre que houver qualquer atualização composta que não seja
atômica; esquecer o lock de um dos lados é a receita clássica para uma leitura parcial.
