# Instruções

Você trabalha no escritório da cidade há um tempo e desenvolveu um conjunto de ferramentas que agilizam seu dia a dia, por exemplo para preencher formulários.

Agora, um novo colega está chegando, e você percebeu que suas ferramentas podem não ser autoexplicativas. Há muitas convenções estranhas no seu escritório, como sempre preencher formulários com letras maiúsculas e evitar deixar campos vazios.

Você decide escrever uma documentação para que seu novo colega possa começar a usar suas ferramentas rapidamente.

## 1. Documente o propósito das ferramentas de formulário

Adicione documentação ao módulo `Form` que descreva seu propósito. Ela deve dizer:

```
A collection of loosely related functions helpful for filling out various forms at the city office.
```

## 2. Documente o preenchimento de campos com valores em branco

Adicione documentação e um typespec à função `Form.blanks/1`. A documentação deve dizer:

```
Generates a string of a given length.

This string can be used to fill out a form field that is supposed to have no value.
Such fields cannot be left empty because a malicious third party could fill them out with false data.
```

O typespec deve explicar que a função aceita um único argumento, um número inteiro não negativo, e retorna uma string.

## 3. Documente a divisão de valores em listas de letras maiúsculas

Adicione documentação e um typespec à função `Form.letters/1`. A documentação deve dizer:

```
Splits the string into a list of uppercase letters.

This is needed for form fields that don't offer a single input for the whole string,
but instead require splitting the string into a predefined number of single-letter inputs.
```

O typespec deve explicar que a função aceita um único argumento, uma string, e retorna uma lista de strings.

## 4. Documente a verificação se um valor cabe em um campo com tamanho máximo

Adicione documentação e um typespec à função `Form.check_length/2`. A documentação deve dizer:

```
Checks if the value has no more than the maximum allowed number of letters.

This is needed to check that the values of fields do not exceed the maximum allowed length.
It also tells you by how much the value exceeds the maximum.
```

O typespec deve explicar que a função aceita dois argumentos, uma string e um número inteiro não negativo, e retorna um de dois valores possíveis. Ela retorna ou o átomo `:ok` ou uma tupla de 2 elementos, em que o primeiro elemento é o átomo `:error` e o segundo é um número inteiro positivo.

## 5. Documente os diferentes formatos de endereço

Por algum motivo que você desconhece, o sistema interno do escritório da cidade usa duas formas diferentes de representar endereços: como um mapa ou como uma tupla.

Documente esse fato definindo três tipos públicos personalizados:

- `address_map`: um mapa com as chaves `:street`, `:postal_code` e `:city`. Cada chave guarda um valor do tipo string.
- `address_tuple`: uma tupla com três valores, `street`, `postal_code` e `city`. Cada valor é do tipo string. Diferencie os valores dando nomes a eles no typespec.
- `address`: pode ser um `address_map` ou um `address_tuple`.

## 6. Documente a formatação do endereço

Adicione documentação e um typespec à função `Form.format_address/1`. A documentação deve dizer:

```
Formats the address as an uppercase multiline string.
```

O typespec deve explicar que a função aceita um argumento, um endereço, e retorna uma string.
