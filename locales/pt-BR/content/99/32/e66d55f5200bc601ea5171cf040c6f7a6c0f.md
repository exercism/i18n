# Introdução

Antes de a classe `Promise` ser introduzida, havia apenas uma forma de lidar com código assíncrono: o _padrão de callback_.

Um callback é uma função que é passada como argumento para outra função e será chamado assim que alguma ação nessa outra função terminar. Um padrão comum para essas funções de callback é que elas recebem um "error" como primeiro parâmetro (veja o exemplo abaixo).

```javascript
function callback(error, arg2, arg3) {}
```

E como isso se relaciona com código assíncrono?

Historicamente, os callbacks têm sido usados para nos permitir fazer algum trabalho depois que uma tarefa assíncrona terminou e sem bloquear o programa inteiro.

```javascript
fetchProduct(productId, function (error, data) {
  if (error) {
    // Handle the error
  } else {
    // Do some work
  }
});
```

No exemplo acima, a função `fetchProduct` (que é assíncrona) recebe um callback como segundo argumento, que decide o que fazer quando os dados do produto tiverem sido recuperados.
