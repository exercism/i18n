# Sobre

Funções recursivas são funções que chamam a si mesmas.

Uma função recursiva precisa ter pelo menos um _caso base_ e pelo menos um _caso recursivo_.

Um _caso base_ retorna um valor sem chamar a função de novo.
Um _caso recursivo_ chama a função de novo, modificando a entrada para que em algum momento ela corresponda ao caso base.

Em Elm, funções recursivas normalmente são definidas usando correspondência de padrões com expressões `case`.

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

Uma função recursiva pode ter vários casos base e/ou vários casos recursivos.
Por exemplo, [a sequência de Fibonacci][fibonacci] é uma sequência recursiva com dois casos base:

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

Repare que essa implementação em particular é exponencialmente lenta, já que os números de Fibonacci relacionados são calculados do zero em duas chamadas recursivas independentes.

Contar o número de ocorrências de um determinado valor `x` em uma lista tem dois casos recursivos:

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## Laços por meio da recursão

Por causa da imutabilidade, os laços em Elm são escritos de forma diferente das linguagens imperativas.
Por exemplo, os laços costumam se parecer com isto:

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

Em uma linguagem funcional como Elm, não é possível modificar variáveis.
Por isso, os laços precisam ser implementados com recursão.

O equivalente a um laço `for` em Elm ficaria assim:

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

Na prática, iterar sobre listas e outras estruturas de dados em Elm é feito na maioria das vezes com funções do módulo [`List`][module-list], como `List.map`, `List.filter` e `List.foldl`.
Por baixo dos panos, essas funções são implementadas com recursão.

## Execução infinita

Funções recursivas podem nunca retornar o resultado se forem implementadas incorretamente ou se o número de chamadas recursivas for grande demais.
Isso pode ser um problema porque, a cada vez que uma função é chamada, uma referência é guardada na memória no ponto para onde o runtime deve retornar o resultado (na [pilha de chamadas][wiki-call-stack]).
Se uma função recursiva chama a si mesma vezes demais ou até infinitamente, é possível ficar sem memória, o que faz o runtime travar (um [erro de estouro de pilha][wiki-stack-overflow]).
O runtime de Elm é otimizado para recursão e confiabilidade, mas a recursão infinita ainda pode causar problemas.

Esse problema de execução infinita pode ser causado por:

- Esquecer de implementar um caso base.
- Não tratar todos os casos possíveis na correspondência de padrões.
- Não modificar o argumento corretamente ao fazer a chamada recursiva e, com isso, nunca chegar ao caso base.
