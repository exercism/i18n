# Instruções

Você está escrevendo o firmware do sistema de pontuação de um console portátil retrô.
A CPU da máquina é modesta, e o visor do placar é atualizado a uma taxa fixa.
Para que a imagem fique fluida, as rotinas de pontuação precisam rodar em um número previsível de ciclos, independentemente do que o jogador estiver fazendo.

Você tem quatro tarefas.

~~~~exercism/note
O código das tarefas deve ser escrito sem desvios.
Use `cmovcc`, `setcc` e aritmética em vez de desvios condicionais.
~~~~

## 1. Adicione um bônus sem estourar o visor

A região de pontuação do LCD do console tem espaço para seis dígitos decimais.
Ele não consegue mostrar nenhum número acima de `999999`.
Quando um bônus levaria o total corrente além desse limite, o total exibido fica no máximo, em vez de dar a volta.

Defina uma função `add_bonus` que, dado um total atual e um bônus a adicionar, retorna o novo total limitado a `999999`.
Os argumentos, na ordem, são:

1. `total`: o total de pontos atual (sempre entre `0` e `999999`)
2. `bonus`: o bônus a adicionar (sempre não negativo)

O valor de retorno é `total + bonus` se essa soma for menor ou igual a `999999`, e `999999` caso contrário:

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

Tanto os argumentos quanto o valor de retorno são inteiros de 64 bits com sinal.

~~~~exercism/note
Você pode assumir que `total + bonus` não estoura um inteiro de 64 bits com sinal.
~~~~

## 2. Compare duas pontuações

O console mantém um pequeno ranking das melhores pontuações recentes do jogador no seu arquivo de save.
Depois de cada partida, a nova pontuação é inserida no ranking na posição correta.
A rotina de ordenação pergunta qual de duas pontuações está na frente e espera a resposta como um pequeno número inteiro.

Defina uma função `compare_scores` que, dadas duas pontuações, retorna:

- `+1` se a primeira pontuação for _maior_
- `-1` se a primeira pontuação for _menor_
- `0` se as duas pontuações forem _iguais_

Exemplo:

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

Tanto os argumentos quanto o valor de retorno são inteiros de 64 bits com sinal.

## 3. Valide uma pontuação bruta

O console pode se conectar a outro aparelho pelo cabo de conexão para compartilhar pontuações depois de uma partida multiplayer.
O cabo tem ruído elétrico e os bytes recebidos às vezes chegam corrompidos, gerando valores muito abaixo do mínimo permitido ou muito acima do máximo permitido.
O validador limita cada pontuação recebida à faixa permitida antes que o resto do sistema a veja.

Defina uma função `validate_score` que, dada uma pontuação bruta e os limites permitidos, retorna a pontuação limitada a `[min, max]`.
Os argumentos, na ordem, são:

1. `score`: a pontuação bruta recebida pelo cabo de conexão
2. `min`: a menor pontuação permitida
3. `max`: a maior pontuação permitida

O valor de retorno é `min` se `score < min`, `max` se `score > max`, e `score` caso contrário.
Você pode assumir que `min <= max`.

Exemplo:

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

Todos os argumentos e o valor de retorno são inteiros de 64 bits com sinal.

## 4. Acompanhe as duas maiores pontuações

No fim de cada sessão de jogo, o console varre o registro de partidas recentes no seu arquivo de save para encontrar as duas maiores pontuações já registradas.
O registro é um array comum de inteiros de 64 bits com sinal na memória.
A varredura percorre o array uma vez e mantém dois máximos correntes: o maior visto até agora e o segundo maior.

Repare que os dois números devem ser pelo menos `0`.
Qualquer número negativo é descartado.

Uma primeira versão da função foi escrita com desvios condicionais em cascata.
Para cada candidato, o código pergunta onde ele se encaixa (acima do primeiro, entre o primeiro e o segundo, ou em lugar nenhum) e desloca os máximos correntes de acordo, descartando qualquer resultado negativo.

Isso funciona.
No entanto, como os valores de entrada são aleatórios, cada desvio condicional causa muitos erros de predição de desvio.
É por isso que você decidiu refatorar o laço principal para ficar sem desvios.

Abaixo está a função com a seção de desvios comentada:

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

Substitua a seção comentada por uma implementação sem desvios.
O único desvio permitido no novo código é aquele que volta ao início do laço para verificar um novo elemento do array.

A função não tem valor de retorno e recebe os mesmos argumentos da versão com desvios:

1. `out`: buffer de saída onde a função vai escrever as duas maiores pontuações não negativas, em ordem decrescente, como inteiros de 64 bits com sinal
2. `array`: array de entrada de inteiros de 64 bits com sinal
3. `length`: o número de elementos do array, como um inteiro sem sinal de 64 bits

~~~~exercism/note
Se o array contiver valores duplicados, os duplicados podem aparecer nos dois espaços de saída se forem as duas maiores pontuações.
~~~~
