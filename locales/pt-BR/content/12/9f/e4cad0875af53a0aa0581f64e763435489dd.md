# Sobre

Dá para iterar sobre [concept:csharp/enumerables]() usando um [laço `foreach`][foreach-statement]:

```csharp
char[] vowels = new [] { 'a', 'e', 'i', 'o', 'u' };

foreach (char vowel in vowels)
{
    // Output the vowel
    System.Console.Write(vowel);
}

// => aeiou
```

Um laço `foreach` é composto de três partes:

1. A declaração: defina a variável que vai conter o valor iterado. Essa variável pode (só) ser usada dentro do laço.
2. O objeto iterável: o objeto sobre o qual dá para iterar.
3. O corpo do laço.

## Laços `for` vs `foreach`

No entanto, em geral um laço `foreach` é preferível a um laço `for` pelos seguintes motivos:

- Um laço `foreach` tem a garantia de iterar sobre _todos_ os valores. Com um laço `for`, é fácil deixar elementos de fora, por exemplo por causa de um erro de off-by-one.
- Um laço `foreach` é mais _declarativo_: seu código comunica _o que_ você quer fazer, em vez de um laço `for` que comunica _como_ você quer fazer.
- Um laço `foreach` é à prova de falhas, enquanto com laços `for` é fácil cometer um erro de off-by-one.
- Um laço `foreach` funciona com todos os tipos de coleção, inclusive os que não aceitam o uso de um indexador para acessar os elementos.

Para garantir que um laço `foreach` itere sobre _todos_ os valores, o compilador não permite atualizar uma coleção dentro de um laço `foreach`:

```csharp
char[] vowels = new [] { 'a', 'e', 'i', 'o', 'u' };

foreach (char vowel in vowels)
{
    // This would result in a compiler error
    // vowel = 'Y';
}
```

Um laço `for` tem, sim, algumas vantagens em relação a um laço `foreach`:

- Você pode começar ou parar no índice que quiser.
- Você pode usar qualquer condição de término (Boolean) que quiser.
- Você pode pular elementos personalizando o incremento da variável do laço.
- Você pode processar coleções de trás para frente, contando de forma decrescente.
- Você pode usar laços `for` em cenários que não envolvem coleções.

Tópicos relacionados:

- Vale saber que o C# tem suporte a [arrays multidimensionais][multi-dimensional-arrays] como `int[,] arr = new int[10, 5]`, o que pode ser muito útil.
- Vale saber também que você pode instanciar objetos do tipo [`System.Array`][system-array-object] com `Array.CreateInstance`. Esses objetos são de pouca utilidade, principalmente para interoperabilidade com código VB.NET. Eles não são intercambiáveis com arrays padrão (`T[]`). Eles podem ter um limite inferior diferente de zero.
