# Introdução

_"Datas e horas são algo que ensinamos a crianças pequenas. Quão difícil pode ser?"_

Muitos programadores já cometeram esse erro, e a experiência que vem depois costuma ter um efeito ruim sobre a saúde e a felicidade deles.

Quem faz programação não trivial com datas e horas deveria, no mínimo, se preparar para entender e mitigar possíveis problemas.

Este documento tenta dar uma visão geral de como Julia lida com datas e horas, mas será necessário consultar o [manual][Dates] para mais detalhes.
Há também um [Wikibook][Wikibook] cujas explicações alguns leitores podem achar mais claras, e ele inclui um [diagrama][type-hierarchy] útil da hierarquia de tipos.

## O módulo `Dates`

A maior parte da funcionalidade básica está em `Dates`, um módulo incluído numa instalação padrão, mas que não faz parte da biblioteca padrão.

Para usar o módulo, há duas opções:

1. Adicione `import Dates` e depois coloque `Dates.` antes de todas as chamadas de função.
2. Adicione `using Dates`, o que traz o módulo inteiro para o namespace atual (_exceto alguns nomes problemáticos_).

```julia-repl
# option 1
julia> import Dates

julia> Dates.now()
2025-06-21T16:02:39.080

julia> now()  # wrong: need to include `Dates.` after an import
ERROR: UndefVarError: `now` not defined in `Main`


# option 2
julia> using Dates

julia> now()  # functions are now in the namespace
2025-06-21T16:03:04.161
```

O módulo `Dates` é grande e complicado, mas oferece quatro tipos principais de funcionalidade:

- `Dates.Date`, que inclui dia, mês e ano, mas não a hora do dia.
- `Dates.Time`, que inclui a hora do dia, mas não a data.
- `Dates.DateTime`, que combina data e hora.
- `Dates.Period`, que lida com intervalos de tempo/data.

Observe que um `DateTime` geralmente _não_ inclui informações de fuso horário (o Python chamaria isso de datetime "naive").
Uma exceção é `now()`, que pega a hora local do relógio do seu sistema e pode convertê-la para UTC, se for preciso.

Talvez as necessidades mais frequentes sejam:

- Interpretar algum formato de entrada adequado para construir um tipo `Dates`.
- Obter o formato numérico ou de string desejado a partir de um tipo `Dates`.
- Aplicar um deslocamento a um valor `Date`, `Time` ou `DateTime`.
- Calcular o intervalo entre dois desses valores.
- Obter a data atual (com `today()`) e/ou a hora atual (com `now()`).

### Formatos de data e hora

Há muitas formas de escrever datas e horas, que tendem a variar conforme a cultura.
Datas só com números, como "7/6/23", são ambíguas, confusas e já causaram muitos erros caros em organizações multinacionais (_o autor fala isso por amarga experiência própria_).

O padrão internacional é definido na `ISO 8601`, com duas vantagens principais:

- A interpretação é rápida e sem ambiguidade.
- A ordenação é fácil, pois o datetime pode ser tratado como texto comum e ordenado alfabeticamente.

Vimos num exemplo anterior que `Date.now()` retornou `2025-06-21T16:03:04.161`.

Ele é formado por várias partes:

- `YYYY-MM-DD` para a parte da data.
- `hh:mm:ss` para a parte da hora.
- Opcionalmente, milissegundos (ou uma unidade ainda menor) depois do ponto decimal.

Outros formatos de string serão discutidos numa seção mais adiante.

## Datas

`Dates.Date` é um tipo relativamente simples, só de data, sem nenhuma noção de horas ou fusos horários.

```julia-repl
# constructor with year, month, day arguments
julia> date1 = Date(2025, 06, 23)
2025-06-23

# constructor with ISO 8601 string
julia> date2 = Date("2025-06-23")
2025-06-23

julia> date1 == date2
true

julia> typeof(date1)
Date
```

Há funções de acesso para cada parte individual da data, e essas funções vêm em pares diferenciados pelo uso de maiúsculas e minúsculas.

```julia-repl
# lowercase returns an integer
julia> month(date1)
6

julia> typeof(month(date1))
Int64

# Propercase returns a Period type
julia> Month(date1)
6 months

julia> typeof(Month(date1))
Month
```

### Funções de consulta

Há várias funções com alguma noção do calendário.
O próximo exemplo mostra apenas algumas.

```julia-repl
julia> date1
2025-06-23

julia> dayofweek(date1) # 1 = Monday, 7 = Sunday
1

julia> dayname(date1)
"Monday"

julia> daysinmonth(date1)
30

julia> isleapyear(date1)
false

julia> lastdayofmonth(date1)
2025-06-30
```

## Horas

`Dates.Time` é o tipo básico, só de hora.
Ele não tem nenhuma noção de datas: as horas passam automaticamente para `Time(0, 0, 0)` à meia-noite.

O formato completo do construtor é `Time(hour, min, sec, millisec, microsec)` ou o equivalente em ISO 8601.

Todos os parâmetros são opcionais e assumem `0` por padrão.

```julia-repl
julia> Time(14, 57, 25, 142)
14:57:25.142

julia> Time("14:57:25.142")
14:57:25.142

julia> Time(14, 57, 25, 142, 32)
14:57:25.142032
```

Assim como com `Date`, as partes individuais ficam disponíveis com funções de acesso:

```julia-repl
julia> minute(t) # => integer
57

julia> Minute(t) # => Period
57 minutes
```

## DateTimes

`Dates.DateTime` combina a maior parte dos recursos dos tipos `Date` e `Time`.

```julia-repl
julia> dt1 = DateTime(2025, 6, 23, 14, 57, 25, 142)
2025-06-23T14:57:25.142

# date1 and t were defined in previous examples
julia> dt2 = DateTime(date1, t)
2025-06-23T14:57:25.142
```

Os parâmetros de ano, mês e dia assumem `1` por padrão, e todos os parâmetros de hora assumem `0`.

Manter todos esses parâmetros na ordem certa pode ser um desafio, então o formato ISO pode ser preferível para a entrada.

Como alternativa, um `DateTime` pode ser construído a partir de um `Date` e um `Time`, como no exemplo acima.

## Períodos

Cada um dos componentes de data/hora tem seu próprio tipo `Period`, de `Year` até `Nanosecond`, representando um intervalo de tempo.
Eles são especialmente úteis para aritmética.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Year(21)
21 years

julia> Second(61)
61 seconds

julia> dt1 + Year(21) - Second(61)
2046-06-23T14:56:24.142

julia> Date(2025, 07, 03) - Date(2025, 04, 25)
69 days
```

Ao trabalhar com tipos `Period`, Julia tenta lidar de forma inteligente com irregularidades do calendário, como a duração dos meses, arredondando quando necessário.

```julia-repl
# February has fewer days than January
julia> Date(2025, 1, 31) + Month(1) 
2025-02-28
```

## Representações em string

Mencionamos antes o padrão ISO 8601, que é a representação padrão de data/hora do Julia ao formatar ou interpretar strings.

Evidentemente, muitos outros formatos são usados com frequência, muitas vezes de formas específicas de cada cultura.
Para lidar com isso, Julia tem o tipo `DateFormat`, que pode ser construído a partir de uma string de formato de complexidade arbitrária.

```julia-repl
# dateformat"" string syntax
julia> dtfmt = dateformat"d/m/y"
dateformat"d/m/y"

julia> typeof(dtfmt)
DateFormat{Symbol("d/m/y"), Tuple{Dates.DatePart{'d'}, Dates.Delim{Char, 1}, Dates.DatePart{'m'}, Dates.Delim{Char, 1}, Dates.DatePart{'y'}}}

# DateFormat constructor
julia> DateFormat("d/m/y")
dateformat"d/m/y"
```

O exemplo acima é bem simples: apenas uma data no formato dia/mês/ano comum na Europa.
Duas variantes da sintaxe são mostradas, mas o resultado é idêntico.

Um `DateFormat` pode então ser usado para interpretar qualquer string adequada:

```julia-repl
julia> DateTime("14/7/2023", dtfmt)
2023-07-14T00:00:00
```

Criar um `DateFormat` envolve uma sobrecarga considerável, então fazer essa etapa uma única vez (como aqui com `dtfmt`) ajuda no desempenho ao percorrer muitas strings de data/hora.

Os formatos podem ser bem mais complexos do que isso, então consulte o [manual][dateformat] para detalhes.

O mesmo `DateFormat` também pode ser usado para gerar uma data/hora em qualquer formato de string desejado, com a função [`Dates.format()`][format].

Infelizmente, parece haver um conflito de namespace com `format` (pelo menos na versão Julia 1.11.5), então é melhor incluir o prefixo `Dates.` mesmo depois de `using Dates`.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Dates.format(dt1, dateformat"e, u d")
"Mon, Jun 23"
```

Como [documentado][wiki-format], `"e, u d"` dá a representação textual abreviada do dia da semana e do mês.

A representação textual assume o inglês por padrão.
Outros idiomas podem ser adicionados, embora o suporte a isso atualmente seja abaixo do ideal.
