# Complemento das instruções

## Definindo a sintaxe

~~~~exercism/caution
Este exercício é uma continuação de [`Resistor Color`][resistor-color] e se apoia nele.
Embora você possa resolver os exercícios de prática em qualquer ordem, recomendamos seguir a sequência sugerida.

[resistor-color]: https://exercism.org/tracks/lean/exercises/resistor-color
~~~~

Neste exercício, você recebe a sintaxe de cores já predefinidas usando o prefixo `c*`, por exemplo, `c*black`.
Você deve então definir uma sintaxe que associe uma sequência de cores a um número, de acordo com as instruções.
As cores ficam entre `*[[` e `]]` e são separadas por `, `, por exemplo, `*[[c*black, c*yellow, c*violet]]`.

Esta tarefa provavelmente vai exigir que você use notações ou macros.
Talvez você queira consultar uma [referência][macro-reference].

Como uma nova sintaxe é expandida em tempo de compilação, qualquer teste falharia na compilação se toda a sintaxe necessária não estivesse definida.
Por esse motivo, em vez de contar com os testes tradicionais de tempo de execução, usamos [`#guard_msgs`][guard-msgs].
Esse comando compara uma docstring fornecida com uma mensagem gerada por outro comando, neste caso [`#eval`][eval], e relata um erro se elas forem diferentes.
Você pode considerar a ausência de erro como um teste que passou.

Se você trabalhar localmente ou no [playground online][playground] do Lean, receberá feedback instantâneo sobre qualquer erro relatado pelo `#guard_msgs` através do InfoView do Lean.

~~~~exercism/caution
No momento, o executor de testes online não oferece suporte à importação da biblioteca completa de metaprogramação do `Lean`.
Você tem liberdade para usar qualquer recurso disponível no Lean por padrão, incluindo os que estão no namespace `Lean`, mas adicionar `import Lean` ou importar módulos específicos do namespace `Lean` fará sua submissão falhar quando você enviá-la para o Exercism.

Repare que não é necessário importar a biblioteca do Lean para resolver este exercício.
~~~~
