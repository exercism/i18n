# Sobre

Recursos que mantêm estado do sistema operacional (handles de arquivo, sockets, locks)
precisam de limpeza *garantida*, mesmo quando uma exceção desenrola a
pilha. O vocabulário [`destructors`][destructors] do Factor oferece um
pequeno framework para isso, e a maioria dos recursos embutidos
(`<file-reader>`, `<file-writer>`, sockets, …) já se integra a ele.

## A classe e o genérico

Uma classe entra no framework estendendo `disposable` e implementando
`dispose*`:

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )` aloca a tupla *e* a registra no escopo
de destrutores atual, então uma exceção entre a alocação e o próximo ponto
seguro não pode vazar o recurso. O framework garante que `dispose*` roda
**no máximo uma vez** por objeto: chamadas repetidas de `dispose` não fazem
nada.

## Quem chama de fora usa `dispose`

| palavra           | efeito                                        |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )` libera; seguro chamar duas vezes |
| `with-disposal`   | `( disposable quot -- )` abre o escopo de um recurso |
| `with-destructors`| `( quot -- )` abre um escopo de registro      |
| `&dispose`        | `( obj -- obj )` descarta na saída normal *ou* em caso de falha |
| `|dispose`        | `( obj -- obj )` descarta apenas se o escopo se desenrolar |

`with-disposal` é a forma para um único recurso. Para mais de um
recurso, abra um escopo `with-destructors` e registre cada aquisição com
`&dispose` (você sempre quer liberá-la) ou `|dispose` (libera só em caso
de falha, já que o caminho de sucesso a mantém).

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup` é a primitiva básica

Para um try/finally pontual sem registro, [`cleanup`][cleanup]
(de `continuations`) é a palavra de nível mais baixo:

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors` é estritamente mais poderoso (o registro pode
crescer em tempo de execução), mas `cleanup` é a escolha natural quando o
par adquirir/liberar é fixo e local.
