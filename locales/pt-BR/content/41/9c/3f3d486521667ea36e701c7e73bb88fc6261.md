# Introdução

`Complex numbers` não são complicados.
Só precisam de um nome menos assustador.


Eles são tão úteis, especialmente em engenharia e ciência, que o Python inclui [`complex`][complex] como um tipo numérico padrão, ao lado de inteiros ([`int`s][ints]) e números de ponto flutuante ([`float`s][floats]).


Um valor `complex` em Python é essencialmente um par de números de ponto flutuante:

```python
>>> my_complex = 5.443+6.77j
(5.443+6.77j)
```

Essas partes são chamadas de "real" e "imaginária".
Você pode ter ouvido que "`i` (ou `j`) é a raiz quadrada de -1".
Por enquanto, isso significa apenas que a parte imaginária, _por definição_, satisfaz a igualdade `1j * 1j == -1`.
É uma ideia simples, mas que leva a consequências matemáticas interessantes.

Em Python, a parte "imaginária" é indicada com `j` (_e não `i`, como você veria em livros de matemática_), e
o `j` precisa vir imediatamente depois de um número, para o Python não interpretá-lo como o nome de uma variável:


```python
>>> j
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
NameError: name 'j' is not defined

>>> 1j
1j

>>> type(1j)
<class 'complex'>
```


Há duas formas comuns de criar números complexos.

1) O construtor [`complex(real, imag)`][complex] recebe dois parâmetros `float`:

    ```python
    >>> z1 = complex(1.5, 2.0)
    >>> z1
    (1.5+2j)
    ```

    O construtor também consegue interpretar uma entrada do tipo string.
    Isso tem a estranha limitação de falhar se a string contiver espaços.

    ```python
    >>> complex('4+2j')
    (4+2j)
    
    >>> complex('4 + 2j')
    Traceback (most recent call last):
      File "<stdin>", line 1, in <module>
    ValueError: complex() arg is a malformed string
    ```


2) O número complexo pode ser especificado como um literal `<real part> + <complex part>j`, ou apenas `<complex part>j` se a parte real for zero:


    ```python
    >>> z2 = 2.0 + 1.5j
    >>> z2
    (2+1.5j)
    ```
    O resultado final é idêntico ao de usar o construtor `complex()`.


## Aritmética

A maioria dos [`operators`][operators] usados com números de ponto flutuante e inteiros também funciona com números complexos.

A divisão inteira _**não**_ é possível com números complexos, então os operadores `//` e `%` e a função `divmod()` vão falhar com o tipo complex.

Explicar as regras de multiplicação e divisão de números complexos está fora do escopo deste conceito (_e é pouco provável que você precise fazer essas operações "à mão" com muita frequência_).

Qualquer introdução [matemática][math-complex] ou de [engenharia elétrica][engineering-complex] aos números complexos vai cobrir esses cenários, caso você queira se aprofundar no assunto.

A biblioteca padrão do Python tem um módulo [`math`][math-module] cheio de funcionalidades úteis para trabalhar com números reais, e o módulo [`cmath`][cmath] é o equivalente dele para trabalhar com números complexos.
