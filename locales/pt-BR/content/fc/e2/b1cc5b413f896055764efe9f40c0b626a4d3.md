# Mapas e conjuntos

| Tipo | Armazena | Acesso por |
| --- | --- | --- |
| `ARRAY{T}` | valores em ordem | posição |
| `FMAP{K,T}` | pares de chave e destino | chave |
| `FSET{T}` | valores, sem repetições | pertinência |

## FMAP

```sather
   m ::= #FMAP{STR,INT};
   m := m.insert("emu", 2);
   m.get("emu")          -- 2
   m.has_ind("emu")      -- true
   m.size                -- 1
   m := m.delete("emu");
```

`m["emu"]` **não** é a forma de ler um mapa: o `FMAP` não tem essa rotina, e essa linha não vai compilar. A forma é `get`.

### Chaves ausentes

`get` em uma chave que não existe devolve o valor vazio do tipo em vez de reclamar: `0`, `false` ou void. Um `STR` void não falha onde é produzido; falha depois, onde quer que acabe sendo usado. Chamar `has_ind` primeiro é o hábito que vale a pena formar.

## FSET

```sather
   s ::= #FSET{STR};
   s := s.insert("emu");
   s.has("emu")          -- true
   s.size                -- 1
   s := s.delete("emu");
```

Os conjuntos se combinam:

```sather
   a.union(b)            -- in either
   a.intersect(b)        -- in both
   a.difference(b)       -- in a but not b
   a.is_subset(b)
```

## Atribuir de volta e copiar

`insert` e `delete` devolvem o container que você deve usar de agora em diante. Normalmente é o mesmo objeto, alterado no lugar; quando precisa crescer, é um objeto novo e maior. Então:

```sather
   m := m.insert(k, v);     -- always
```

e o nome à esquerda é o único em que se pode confiar depois disso. Outro nome para o mesmo mapa, obtido antes do `insert`, pode estar desatualizado.

Para manter uma cópia independente, faça uma cópia primeiro:

```sather
   n ::= m.copy.insert(k, v);      -- m is unchanged
```

com uma ressalva: um mapa em que nunca se inseriu nada é **void**, e `copy` em um mapa void falha. `insert`, `get`, `has_ind` e `size` dão conta de um mapa void (o próprio `#FMAP{K,T}` é void, e é inserindo nele que um mapa passa a existir), mas `copy` não dá conta.

`HMAP` e `HSET` são as versões que só mudam no lugar. São mais rápidas para construir algo grande, e são o padrão errado enquanto você aprende.

## Como percorrer um mapa ou um conjunto

| Iterador | Fornece |
| --- | --- |
| `m.ind!` | cada chave |
| `m.target!` | cada destino |
| `m.pair!` | cada chave e destino juntos |
| `s.elt!` | cada valor de um conjunto |

Nem um mapa nem um conjunto têm ordem. Duas execuções podem percorrê-los de formas diferentes, então nunca escreva nada que dependa de qual vem primeiro.

```sather
   loop
      #OUT + guide.ind! + "\n";
   end;
```
