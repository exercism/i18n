# Propriedade

Em Cairo, o conceito de propriedade está ligado às _variáveis_, e não aos _valores_ que elas guardam.

Os valores em Cairo são imutáveis. Essa imutabilidade garante que, mesmo que muitas variáveis se refiram ao mesmo valor, o valor em si permaneça constante e inalterado.
Por isso, o compilador precisa garantir que quem programa os use corretamente.
É esse o significado da _propriedade_ de uma variável: o proprietário é o código que pode ler (e escrever, se for mutável) a variável.

## Regras de propriedade de variáveis

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## Escopo de variável

Um escopo é o intervalo dentro de um programa em que uma variável é válida.
Vamos ver o exemplo a seguir, que declara uma variável `x` do tipo inteiro sem sinal, com comentários indicando onde a variável é válida:

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

Notas:

- Quando `x` entra em escopo, ela é válida.
- Ela permanece válida até sair de escopo, neste caso até o fim da função `main()`.

## Movendo valores

Uma movimentação ocorre quando um valor é passado para outra função, destruindo a variável original que se referia ao valor (o que torna a variável inútil) e criando uma nova variável para guardar o mesmo valor.

Arrays são um exemplo de tipo complexo que é movido quando passado para outra função.
Veja um rápido lembrete de como um array se parece:

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

Como o sistema de tipos garante que o programa em Cairo nunca tente escrever duas vezes na mesma célula de memória?
Considere o código a seguir, em que tentamos remover a frente do array duas vezes:

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

Neste caso, tentamos passar o mesmo valor (o array na variável `arr`) para as duas chamadas de função.
Isso significa que nosso código tenta remover o primeiro elemento duas vezes, o que tentaria escrever duas vezes na mesma célula de memória, algo proibido pela VM do Cairo e que leva a um erro em tempo de execução.
Felizmente, esse código não compila.
Depois de passarmos o array para a função `foo`, a variável `arr` não é mais utilizável.
Recebemos este erro em tempo de compilação, que nos diz que precisaríamos que `Array` implementasse o trait `Copy`:

## O trait Copy

Se um tipo implementa o trait `Copy`, passá-lo para uma função não move o valor, mas cria uma nova variável que se refere ao mesmo valor.
Isso é uma operação gratuita, porque as variáveis são uma abstração do Cairo e os valores são sempre imutáveis.

Para implementar o trait `Copy` no seu tipo, adicione a anotação `#[derive(Copy)]` à definição do tipo.
No entanto, o Cairo não vai permitir isso se o tipo, ou qualquer um dos seus componentes, não implementar o trait `Copy`.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## Destruindo valores

Tipos lineares também podem ser utilizados sendo destruídos, o que garante que o recurso associado seja liberado corretamente.
Isso é feito implementando ou derivando o trait `Drop`, que sinaliza ao compilador que o tipo pode ser destruído com segurança quando não for mais útil.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

No momento, a implementação de `Drop` pode ser derivada para todos os tipos, exceto dicionários (`Felt252Dict`) e tipos que contenham dicionários.
Isso porque os dicionários precisam ser "squashed" quando são destruídos.
Para isso, derivamos o trait `Destruct`:

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## Valores de retorno e escopo

Retornar valores é equivalente a movê-los.
O exemplo abaixo mostra uma função que retorna algum valor:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
