# Classes Abstratas

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## O $ faz parte do nome

Toda classe abstrata tem um `$` no início do nome, e só as classes abstratas têm. Então um tipo que começa com `$` é um tipo do qual você não pode criar um objeto, e isso fica visível em todo lugar onde o nome aparece.

## O que pode entrar nela

Assinaturas de rotinas e de iteradores, terminando no ponto e vírgula. Sem corpos, sem atributos, sem `create`. Uma classe abstrata descreve o que pode ser *pedido* a algo, nunca o que ele guarda.

## Conformidade

```sather
class TRAPEZE < $ACT is
```

A classe precisa definir toda rotina listada, com tipos de argumento e tipo de retorno compatíveis. Isso é verificado na compilação.

Uma classe pode estar em conformidade com várias:

```sather
class TRAPEZE < $ACT, $RISKY is
```

e classes abstratas podem estender umas às outras:

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## Onde acontece o despacho

Uma variável de um tipo abstrato guarda uma referência a algum objeto que esteja em conformidade. Chamar uma rotina nela escolhe a versão que pertence à classe real do objeto, em tempo de execução.

Esse é o único lugar onde Sather decide algo em tempo de execução. Uma chamada em uma variável de um tipo concreto é resolvida na compilação.

## typecase

Às vezes o tipo realmente importa. O `typecase` pergunta:

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

Dentro de um braço, a variável tem o tipo mais estreito. Use isso raramente: um `typecase` sobre todo tipo de ato geralmente é uma rotina que já deveria estar na classe abstrata desde o início.

## $OB

`$OB` é a classe abstrata com a qual todo objeto está em conformidade. Ela é útil de vez em quando e, na maioria das vezes, é sinal de que um tipo se perdeu pelo caminho.

## Por que não herança?

Sather separa duas coisas que a maioria das linguagens junta. O `<` diz apenas o que uma classe pode *fazer*. Obter uma implementação de outro lugar é o `include`, que é o exercício seguinte ao próximo e é uma decisão à parte.
