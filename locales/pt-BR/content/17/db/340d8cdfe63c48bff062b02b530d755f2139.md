# Sobre

O Common Lisp oferece ao programador vários condicionais diferentes, que podem ser classificados pela quantidade de "blocos" que cada um suporta.

Além disso, ao contrário de muitas outras linguagens de programação, todos os condicionais em Common Lisp são _expressões_, não instruções.
Isso significa que todos os condicionais do Lisp são avaliados para algum valor e podem ser usados no lugar de parâmetros concretos.

Um exemplo:

```lisp
;; Doubles x when it's even
(* x (if (evenp x) 2 1))
```

## Condicionais de bloco único

Os condicionais `when` e `unless` avaliam algum código apenas quando o teste fornecido é verdadeiro ou falso, respectivamente, e resultam em `nil` caso contrário.

A seção depois da expressão de teste pode conter mais de uma expressão.

```lisp
(when (= 2 2) "All is well")      ; => "All is well"
(unless (= 2 2) "Time to panic!") ; => NIL
```

## O condicional de dois blocos

O condicional `if` avalia a primeira expressão do corpo quando o teste é verdadeiro e a segunda caso contrário.

```lisp
(if (= 2 2) 'how-honest 'you-liar) ; => HOW-HONEST
```

Repare que tanto a cláusula then quanto a cláusula else só podem ser uma única expressão.

## Condicionais de muitos blocos

O "supercondicional" do Lisp é o `cond`, que pode ter um número infinito de blocos.
Cada bloco tem uma condição de teste e uma expressão de corpo, envolvidas por um par extra de parênteses.
Se todos os testes forem falsos, `nil` é retornado.

```lisp
(cond ((= 0 2) 'nope)
      ((= 1 2) 'try-again)
      ((= 2 2) 'quite-true)
      ((= 3 2) 'too-far)
      (t 'something-else))
; => QUITE-TRUE
```

Repare que não há limite para o número de expressões depois da expressão de teste.


Se você só quer testar um valor contra vários blocos, pode usar a expressão `case`, que é mais limpa.
Se nenhum dos casos corresponder, `nil` é retornado.
Tanto `t` quanto `otherwise` podem ser usados como casos que cobrem tudo:

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark")
  (otherwise "???"))
; => "???"
```

Repare que, assim como no `cond`, não há limite para o número de expressões depois da expressão de teste.

## Os condicionais furtivos

As operações booleanas `and` e `or` em Common Lisp são macros de curto-circuito que podem ser usadas para reduzir a duplicação de certas expressões condicionais.

A macro `and` retorna `nil` imediatamente se encontrar um único valor falso, mas caso contrário retorna o último valor verdadeiro do `and`:

```lisp
(and 42 "Magic" :cool) ; => :COOL
(and () "Magic" :cool) ; => NIL
```

A macro `or` retorna o primeiro valor verdadeiro que encontrar ou `nil` se não houver nenhum valor verdadeiro:

```lisp
(or () 42 nil)  ; => 42
(or () NIL nil) ; => NIL
```

## Estou exausto...

Como mencionado antes, quando nenhum dos blocos em uma instrução `case` corresponder e não houver uma cláusula `otherwise`, `nil` é retornado.
Às vezes, porém, a falha em corresponder a qualquer bloco deve ser tratada como um erro. É aí que entra o `ecase` (de correspondência **exaustiva**).

Ele é usado exatamente da mesma forma que o `case`, mas sinaliza um erro em vez de retornar `nil` quando não há correspondência.

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => NIL

(ecase 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => ERROR: ELDER-BEAST fell through ECASE expression. Wanted one of (CAT BIRD DOG).
```
