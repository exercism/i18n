# Sobre

Como muitas outras linguagens, Go tem ponteiros.
Se ponteiros são novidade para você, eles podem parecer um pouco misteriosos, mas quando você se acostuma com eles, são bem simples.
Eles são uma parte crucial de Go, então reserve um tempo para entendê-los de verdade.

Antes de entrar nos detalhes, vale a pena entender para que servem os ponteiros.
Ponteiros são uma forma de compartilhar memória com outras partes do nosso programa, o que é útil por dois motivos principais:

1. Quando temos grandes quantidades de dados, fazer cópias para passar entre funções é muito ineficiente.
   Passando em vez disso o local na memória onde os dados estão guardados, podemos reduzir drasticamente o consumo de recursos dos nossos programas.
2. Passando ponteiros entre funções, podemos acessar e modificar a única cópia dos dados diretamente, ou seja, qualquer mudança feita por uma função fica imediatamente visível para outras partes do programa quando a função termina.

## Variáveis e memória

Digamos que temos uma variável inteira comum `a`:

```go
var a int
```

Quando declaramos uma variável, Go precisa encontrar um lugar na memória para guardar seu valor.
Isso é amplamente abstraído para nós: quando precisamos buscar o valor guardado naquele pedaço de memória, basta nos referirmos a ele pelo nome da variável.

Por exemplo, quando escrevemos `a + 2`, estamos efetivamente buscando o valor guardado na memória associada à variável `a` e somando 2 a ele.

Da mesma forma, quando precisamos mudar o valor no pedaço de memória de `a`, podemos usar o nome da variável para fazer uma atribuição:

```go
a = 3
```

O pedaço de memória associado a `a` agora vai guardar o valor `3`.

## Ponteiros

Enquanto as variáveis nos permitem nos referir a valores na memória, às vezes é útil saber o **endereço de memória** para o qual a variável aponta.
Os **ponteiros** guardam os endereços de memória desses valores.
Você declara uma variável de tipo ponteiro colocando um asterisco antes do tipo base:

```go
var p *int // 'p' contains the memory address of an integer
```

Aqui declaramos uma variável `p` do tipo "ponteiro para int" (`*int`).
Isso significa que `p` vai guardar o endereço de memória de um inteiro.
O valor zero dos ponteiros é `nil`, porque um ponteiro `nil` não guarda nenhum endereço de memória.

### Obtendo um ponteiro para uma variável

Para encontrar o endereço de memória do valor de uma variável, podemos usar o operador `&`.
Por exemplo, se quisermos encontrar e guardar o endereço de memória da variável `a` no ponteiro `p`, podemos fazer o seguinte:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### Acessando o valor por meio de um ponteiro (desreferenciamento)

Quando temos um ponteiro, podemos querer saber o valor guardado no endereço de memória que o ponteiro representa.
Podemos fazer isso usando o operador `*`:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

A operação `*p` busca o valor guardado no endereço de memória guardado em `p`.
Essa operação costuma ser chamada de "desreferenciamento".

Também podemos usar o operador de desreferência para atribuir um novo valor ao endereço de memória referenciado pelo ponteiro:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

Atribuir a `*pa` vai mudar o valor guardado no endereço de memória que `pa` contém.
Como `pa` guarda o endereço de memória de `a`, ao atribuir a `*pa` estamos efetivamente mudando o valor de `a`!

Uma observação de cautela, porém: sempre verifique se um ponteiro não é `nil` antes de desreferenciá-lo.
Desreferenciar um ponteiro `nil` vai fazer o programa travar em tempo de execução!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### Ponteiros para structs

Até agora só vimos ponteiros para valores primitivos.
Também podemos criar ponteiros para structs:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

Também poderíamos ter criado um novo `Person` e guardado um ponteiro para ele imediatamente:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

Quando temos um ponteiro para uma struct, não precisamos desreferenciar o ponteiro antes de acessar um dos campos:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## Slices e maps já são ponteiros

Slices e maps são tipos especiais porque já têm ponteiros em sua implementação.
Isso significa que, na maioria das vezes, não precisamos criar ponteiros para esses tipos para compartilhar o endereço de memória de seus valores.
Imagine que temos uma função que incrementa o valor de uma chave em um map:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

Se criarmos um map e chamarmos essa função, as mudanças que a função fez no map persistem depois que a função termina.
Esse é um comportamento parecido com o que teríamos se estivéssemos usando um ponteiro, mas repare que neste exemplo não estamos usando referência nem desreferência, nem nenhuma sintaxe de ponteiro:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

O mesmo vale quando mudamos um item existente em um slice.

Porém, ações que retornam um novo slice, como `append`, são um caso especial e **podem não** modificar o slice fora da função.
Isso acontece por causa da forma como os slices funcionam internamente, mas não vamos cobrir isso em detalhes, pois é um tópico mais avançado.
Se você quiser saber mais, pode ler sobre isso em [Go Blog: Mechanics of 'append'][mechanics-of-append]

## Aritmética de ponteiros

Diferente de outras linguagens, Go não suporta aritmética de ponteiros.
Isso significa que você não pode ir do endereço de memória de um valor para o endereço de outro incrementando o valor do ponteiro.
Então trechos como o seguinte são inválidos:

```go
var a int
a = 2

var pa *int
pa = &a
pa++ // NOT ALLOWED: incrementing the pointer or any other pointer arithmetic operations are invalid
```
