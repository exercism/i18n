# Testes

Rode os testes com:

```bash
$ wrenc exercise-name.spec.wren
```

Por exemplo, para `hello-world`:

```bash
$ wrenc hello-world.spec.wren
```


## Entendendo os testes com skip

O método `skip` diz à suíte de testes para não rodar um teste específico.

- Por que eles são pulados?

Para que você possa se concentrar em um teste de cada vez e ir habilitando um a um conforme evolui a solução.

- Como habilitá-los?

Um teste pulado:

```js
// this test will be skipped and not run
skip.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

Basta trocar `skip.test` por `do.test`.

```js
// now the test will be run normally
do.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

## Criando seu primeiro módulo Wren

Os testes desta trilha carregam sua implementação importando-a como um módulo Wren:
`import "./bob" for Bob`. Não existe sintaxe especial para exportar sua
implementação. Basta nomear sua classe como `Bob` para casar com as instruções de import `for Bob` e tudo deve funcionar.

```javascript
class Bob {
  static hey(message) {
    // Your solution to the exercise goes here
  }
}
```

Você encontra mais informações sobre módulos na
[documentação de Modularidade do Wren][modularity].
Para facilitar o começo, há um arquivo Wren _esqueleto_ no
diretório de cada exercício.

[modularity]: https://wren.io/modularity.html
