# Introdução

Vimos em Conceitos anteriores que os tipos em Julia formam uma hierarquia, com `Any` no topo.

Tipos abstratos como `Number` têm subtipos, mas não podem ser instanciados por si mesmos.
Definir uma variável com um tipo abstrato _restringe_ os valores da variável a qualquer subtipo do tipo abstrato.
Por exemplo:

```julia-repl
julia> x::Number = 3
3
julia> typeof(x)  # one subtype of Number
Int64
julia> x = 4.2
4.2
julia> typeof(x) # another subtype of Number
Float64
julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

Isso nos dá um tipo de flexibilidade para restringir quais valores são válidos.

No entanto, suponha que queremos que uma variável aceite tanto valores inteiros quanto strings?
Esses tipos não estão no mesmo ramo da hierarquia.

Poderíamos definir o tipo como `Any`, ou deixar que ele seja esse por padrão, mas aí perdemos todo o controle dos tipos permitidos.

Para uma abordagem melhor, temos a sintaxe `Union{ }`, com dois ou mais tipos listados dentro das chaves.

```julia-repl
julia> y::Union{Integer, String} = 4
4
julia> typeof(y)
Int64
julia> y = "works"
"works"
julia> typeof(y)
String
julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

Outro exemplo usa a mesma união de tipos em uma assinatura de função:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}
julia> f(z::IntOrString) = z^3
f (generic function with 1 method)
julia> f(2) # integers are cubed
8
julia> f("ab") # strings are repeated 3 times
"ababab"
```

Aqui, demos um nome ao tipo, o que pode fornecer uma forma abreviada conveniente, mas não é estritamente necessário.
A função `g(z::Union{Integer, String}) = z^3` se comporta da mesma forma.

Haverá muito mais a dizer sobre assinaturas de função no Conceito de Despacho Múltiplo.

## Uniões com nada

Várias outras linguagens têm tipos que podem ou não conter um valor, com nomes como `Option`, `Nullable` ou `Maybe`.

Julia não tem sintaxe específica para isso, mas uniões de tipos são uma generalização da mesma ideia.

Vimos no Conceito `Nothingness` que Julia tem várias maneiras de representar não-valores, incluindo `nothing` e `missing`.
Qualquer um deles pode ser incluído em uma união de tipos.

Por exemplo, ao definir algum tipo de lista encadeada, precisamos de uma maneira de terminar a lista se não houver mais nós.
`Nothing` é o tipo com valor singleton `nothing`, e esta definição de Node torna possível sinalizar o fim da cadeia:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

Da mesma forma, `missing` pode ser usado como um placeholder para valores ausentes, especialmente em coleções como vetores.
O exemplo abaixo é muito artificial, mas valores ausentes são comuns em conjuntos de dados do mundo real.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)
julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
