# Verificação

O uso principal do [configlet](/docs/building/configlet) é a verificação: checar se os arquivos de configuração de uma track estão estruturados corretamente, tanto sintática quanto semanticamente. Tracks mal configuradas podem não sincronizar corretamente, podem parecer erradas no site ou podem oferecer uma experiência ruim para quem usa. Por isso, as proteções do configlet têm um papel importante em manter a integridade do Exercism.

## Uso

O comando `lint` pode ser usado para verificar uma track.

```
configlet [global-options] lint [command-options]

Global options:
  -h, --help                   Show this help message and exit
      --version                Show this tool's version information and exit
  -t, --track-dir <dir>        Specify a track directory to use instead of the current directory
  -v, --verbosity <verbosity>  The verbosity of output. Allowed values: q[uiet], n[ormal], d[etailed]
```

## Regras

Estas são as regras de verificação que são checadas.

### Regra: os arquivos obrigatórios estão presentes

O verificador deve checar se todos os arquivos obrigatórios estão presentes. Os arquivos que não são específicos de exercícios e que devem estar presentes são:

- `config.json`
- `docs/ABOUT.md`
- `docs/INSTALLATION.md`
- `docs/LEARNING.md`
- `docs/RESOURCES.md`
- `docs/SNIPPET.txt`
- `docs/TESTS.md`
- `exercises/shared/.docs/help.md`
- `exercises/shared/.docs/tests.md`

Os arquivos específicos de exercícios de conceito que devem estar presentes são:

- `exercises/concept/<slug>/.docs/hints.md`
- `exercises/concept/<slug>/.docs/instructions.md`
- `exercises/concept/<slug>/.docs/introduction.md`
- `exercises/concept/<slug>/.meta/config.json`

Haverá uma lista semelhante para os exercícios de prática, mas ainda não definimos a especificação para isso.

Cada conceito listado no `config.json` deve ter os seguintes arquivos:

- `concepts/<slug>/about.md`
- `concepts/<slug>/introduction.md`
- `concepts/<slug>/links.json`

## Glossário

1. **String não vazia**: uma string que contém pelo menos um caractere que não seja espaço em branco.
2. **String em kebab-case**: uma string que contém apenas caracteres no intervalo `[a-z0-9]`, opcionalmente separados por hífens (por exemplo, "two-fer"). Ela deve corresponder à expressão regular: `^[a-z0-9]+(-[a-z0-9]+)*$`
3. **String em Title Case**: uma string não vazia que segue as [diretrizes do Chicago Manual of Style](https://en.wikipedia.org/wiki/Title_case#Chicago_Manual_of_Style) abaixo:
   - Coloque em maiúscula a primeira e a última palavra de títulos e subtítulos.
   - Coloque em maiúscula as palavras "principais" (substantivos, pronomes, verbos, adjetivos, advérbios e algumas conjunções).
   - Deixe em minúscula as conjunções _and_, _but_, _for_, _or_ e _nor_.
   - Deixe em minúscula os artigos _the_, _a_ e _an_.
   - Deixe em minúscula as preposições, independentemente do comprimento, exceto quando forem enfatizadas, usadas de forma adverbial ou adjetival, ou usadas como conjunções.
   - Deixe em minúscula as palavras _to_ e _as_.
   - Deixe em minúscula a segunda parte de nomes científicos em latim.
4. **String em Sentence Case**: uma string não vazia que segue as [diretrizes](https://en.wikipedia.org/wiki/Letter_case#Sentence_case) abaixo:
   - Coloque em maiúscula a primeira palavra da frase, bem como nomes próprios e outras palavras conforme exigido por uma regra mais específica.
5. **Padrão `files` válido**: uma string não vazia¹ que especifica a localização de um arquivo usado em um exercício, relativa ao diretório do exercício. Um padrão pode usar um dos seguintes placeholders:

   - `%{kebab_slug}`: o slug do exercício em `kebab-case` (por exemplo, `bit-manipulation`)
   - `%{snake_slug}`: o slug do exercício em `snake_case` (por exemplo, `bit_manipulation`)
   - `%{camel_slug}`: o slug do exercício em `camelCase` (por exemplo, `bitManipulation`)
   - `%{pascal_slug}`: o slug do exercício em `PascalCase` (por exemplo, `BitManipulation`)

6. **String UUID versão 4 única**: uma string que satisfaz todas estas condições:

   - Ela existe apenas uma vez no arquivo `config.json` de nível de track de uma determinada track do Exercism
   - Ela não existe no arquivo `config.json` de nível de track de nenhuma outra track do Exercism
   - Ela não existe em nenhum arquivo `canonical-data.json` em https://github.com/exercism/problem-specifications
   - Ela não existe em nenhum outro lugar no Exercism
   - Ela corresponde à expressão regular:

   ```
   ^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$
   ```

   Por exemplo, o UUID abaixo tem a forma correta:

   ```
   d334ffe3-657e-4725-a950-290b284b6d9f
   ```

   Você pode rodar `configlet uuid` para gerar um UUID adequado.

7. **`tag` de analisador válida**: uma string não vazia¹ formatada como `<category>:<thing>`.
   O valor de `<category>` deve ser um dos seguintes:

- `paradigm` (por exemplo, `paradigm:functional`)
- `technique` (por exemplo, `technique:recursion`)
- `construct` (por exemplo, `construct:bitwise-and`)
- `uses` (por exemplo, `uses:DateTime.add_seconds`)

O valor de `<thing>` deve ser uma string não vazia¹.
