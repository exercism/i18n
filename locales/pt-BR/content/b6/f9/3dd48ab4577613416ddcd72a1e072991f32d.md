# Sobre

Neste ponto do programa de estudos, você já viu o R ser usado com frequência como uma linguagem imperativa e, cada vez mais, como uma linguagem funcional (especialmente com as bibliotecas [`purrr`][ref-purrr] e [`dplyr`][ref-dplyr]).

Sugerir agora que o R é principalmente orientado a objetos pode provocar um certo ceticismo!

Por estranho que pareça, isso é verdade.
Internamente, o R é implementado usando classes, herança, polimorfismo e o tipo de atitude típica dos programadores de POO.

No entanto, quem conhece Java ou Ruby (explicitamente POO) ou até Python (POO meio disfarçada, em alguns aspectos) vai achar a abordagem do R ... _pouco familiar_.

Para começar, existem vários modelos de classe: talvez três em uso comum (S3, S4, R6), além de vários outros de interesse principalmente teórico.

Uma discussão aprofundada pode ser encontrada em [Advanced R, 2ª ed.][book-advanced-r], capítulos 12 a 16.
Esse livro de 2019 é voltado principalmente para quem quer entender e dar manutenção nas entranhas do R, então POO é essencial.

Os livros mais voltados para o usuário final variam.

- The Art of R Programming (2011, somente em versão impressa) tem um capítulo sobre POO que aborda S3 e (mais brevemente) S4, que eram importantes naquela época.
  O comentário de que _"as classes S3 têm uma estrutura meio remendada"_ continua surpreendentemente verdadeiro.
- R in Action (3ª ed., 2022) relega a POO a 3 páginas em um capítulo sobre Programação Avançada perto do fim.
- [R for Data Science, 2ª ed.][book-r-data-sci] (2023, com 548 páginas na edição impressa) não faz nenhuma menção a POO.

Este Conceito vai se concentrar nas classes S3, que são as mais simples, mais comuns e mais relevantes para problemas do tipo Exercism.
Alguns dos exercícios de prática da trilha de R exigem que você crie uma classe S3; outros tornam isso opcional, mas incentivado de forma leve.

## Classes S3

Elas são antigas: o nome S3 só significa que foram introduzidas na versão 3 da linguagem S (uma precursora comercial do R).

Uma classe S3 também é bem simples: tipicamente, uma [Lista][concept-lists] com pelo menos um atributo extra.

Citando o [Advanced R][book-s3]: _"S3 é informal e ad hoc, mas há uma certa elegância em seu minimalismo: você não pode tirar nenhuma parte dele e ainda ter um sistema de OO útil."_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

Então fazer uma atribuição a [`class(obj)`][ref-class] apenas adiciona um atributo a `obj`, neste caso identificando pt2d como uma instância da classe point2d.

As etapas de criação podem ser combinadas com [`structure()`][ref-structure]:

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

Embora as instâncias resultantes sejam teoricamente idênticas, ainda não implementamos uma forma de o R confirmar isso.

### Métodos genéricos

Quem conhece POO em outras linguagens pode estar se perguntando: _"as classes não deveriam ser capazes de FAZER coisas?"_

Podemos verificar os métodos disponíveis para instâncias de `point2d` e descobrir que (ao contrário da `list` subjacente) no momento não existe nenhum.

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

Na maioria das linguagens de POO, os métodos são definidos dentro da definição da classe.
Algumas linguagens (notavelmente Ruby) permitem adicionar e modificar métodos de classe depois.

As classes S3 são bem diferentes.
Em vez de adicionar métodos a uma classe, adicionamos a classe a um método genérico.

Quem trabalha de forma interativa no console do R usa métodos genéricos o tempo todo, geralmente sem pensar em como eles são implementados.

Um exemplo muito comum é `print()`, mesmo que você raramente digite o nome da função.
Digitar um valor `x` sozinho no prompt do console é apenas açúcar sintático para `print(x)`.

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

Já conseguimos imprimir `pt2d`.
Embora `print()` não saiba nada sobre a classe `point2d`, ela tem padrões razoáveis para lidar com uma grande variedade de objetos.

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

Isso é bem verboso, e talvez a gente queira uma forma de imprimir o ponto de maneira mais bonita e concisa.

Fácil: basta adicionar uma função chamada `print.point2d()`.
O nome precisa estar no formato `methodname.classname`, para que o mecanismo de despacho saiba o que procurar.

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

Agora suponha que queremos criar um novo método genérico, por exemplo `flipvert()` para inverter o sinal da coordenada `y`.

De novo, fácil:

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

Isso cria um mecanismo de despacho, onde `x` é o nosso objeto com uma classe S3, e `...` trata quaisquer argumentos extras de que as definições de método precisem ("dot args", como descrito no [Conceito de Funções][concept-functions]).

Podemos então definir o método para `point2d` e usá-lo.

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

O R agora sabe como inverter nosso ponto e como exibir o resultado.

Poderíamos expandir isso criando classes para 3D, para coordenadas polares etc., e depois definir métodos para cada uma.

Do ponto de vista do usuário final, existe apenas `flipvert(x, ...)`, e podemos contar com o R para determinar a classe da entrada e usar a implementação subjacente apropriada.

~~~~exercism/caution
Nomes de função no formato `verb.class` parecem métodos S3, tanto para os usuários quanto para o parser do R.
Evite usar nomes parecidos em outros contextos.

É verdade que o R base às vezes viola essa regra.
Devemos encarar isso como um acidente histórico lamentável (para funções ainda mais antigas que o S3), que precisa ser preservado por compatibilidade com versões anteriores.
~~~~

### Herança

Entusiastas de POO podem escrever vários capítulos longos de livro sobre herança, subclasses, mixins e todo o resto.

O R simplesmente permite fornecer vários nomes ao atributo `class`: um vetor de strings mais longo, em vez de uma única string.

Com o risco de forçar o exemplo até o limite, suponha que tivéssemos criado uma classe genérica `point` e quiséssemos criar subclasses dela: `point2d`, `point3d` etc.

Então a definição de `point2d` simplesmente usa `class = c("point2d", "point")`: a classe específica e a classe pai (ou classes).

Métodos genéricos como `print()` vão então procurar em sequência por `print.point2d()`, `print.point()` e (provavelmente) `print.default()`, usando a primeira implementação que o mecanismo de despacho encontrar.

### Segurança

Muitas linguagens de POO (Java, C# etc.) aproveitam o encapsulamento de dados dentro das classes para fazer verificações cuidadosas em tempo de compilação e impor segurança de tipos.

Lembre-se de que o S3 permite fazer praticamente tudo o que você quiser, mesmo que não faça sentido (qualquer mensagem de erro aparece depois, se aparecer).

Citando o ["Advanced R"][book-s3] (2ª ed., seção 13.3):

> _Se você já usou outras linguagens OO, isso pode causar um certo enjoo, mas na prática essa flexibilidade causa poucos problemas. O R não te impede de dar um tiro no próprio pé, mas enquanto você não apontar a arma para os dedos dos pés e puxar o gatilho, não vai ter problema._

Bom, _tudo bem?_
O R é excelente para ciência de dados exploratória e estatística, muitas vezes ao trabalhar de forma interativa.
Ninguém está sugerindo que você deva usá-lo para escrever sistemas de finanças corporativas altamente seguros!
