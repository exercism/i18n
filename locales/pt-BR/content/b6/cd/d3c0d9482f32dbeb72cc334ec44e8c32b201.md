# Instalando o Factor

A trilha de Factor usa o **Factor 0.101**. Versões anteriores não são suportadas.

Você pode instalar uma compilação [estável](#stable) ou [nightly](#nightly), ou [compilar a partir do código-fonte](#build-from-source).

Para verificar a instalação, execute `factor -e='vm-version print'`: o resultado deve ser `0.101` ou superior.

---
### Estável

<https://factorcode.org#stable-release> oferece binários estáveis na seção "Stable release".

---
### Nightly

<https://factorcode.org#development-release> oferece binários nightly na seção "Development release". Esses binários são compilados a partir do git, mas só são mostradas as compilações que passam.

---
### Compilar a partir do código-fonte

Se você quer o que há de mais recente e até o nightly é velho demais para você, vai precisar de um compilador de C++ moderno (GCC >=4.8 ou Clang >=3.5), do `make` e do `curl`.

Atendidos esses requisitos simples, você pode:

1. Baixar o script de shell `build`: [**aqui** para sistemas tipo Unix / shells POSIX](https://raw.githubusercontent.com/factor/factor/master/build.sh) ou [**aqui** para Windows](https://raw.githubusercontent.com/factor/factor/master/build.cmd). Coloque-o no diretório no qual o Factor deve ser instalado. Será criado um diretório chamado `factor` com o código.

2. Executá-lo assim: `./build.sh install`, ou `.\build.cmd install` no Windows. <sub>Isso vai clonar o repositório `git` do Factor, compilá-lo e baixar uma imagem da VM do Factor de <https://factorcode.org>. Esse processo pode levar de 2 a 20 minutos, dependendo da sua conexão e da velocidade do processador.</sub>

3. Agora você pode executar o binário `factor` ou `factor.exe` gerado dentro do subdiretório `factor`. Experimente `factor --help` para ver a ajuda. Você também pode acessar a documentação pela linha de comando ou pressionando <kbd>F1</kbd> no Listener gráfico, que abre o navegador de ajuda.

4. Daqui em diante, use o `build.sh` (ou o `build.cmd`, no Windows) dentro do subdiretório `factor` para puxar do git e recompilar no mesmo lugar, além de baixar uma nova imagem da VM quando for preciso.

A estrutura de arquivos agora deve ficar assim:

```
.
├── build.sh                   <- delete if you like
└── factor
    ├── basis
    ├── boot.unix-x86.64.image
    ├── build.cmd              <- use these from now on
    ├── build.sh               <-
    ├── core
    ├── extra
    ├── factor
    ├── Factor.app
    ├── factor.image
    ├── GNUmakefile
    ├── libfactor.a
    ├── libfactor-ffi-test.so
    ├── LICENSE.txt
    ├── misc
    ├── Nmakefile
    ├── README.md
    ├── unmaintained
    ├── vm
    └── work
```

Você não precisa mais do script `build` de nível superior, pois daqui em diante é o que você baixou que deve ser usado.

---

### Compilar manualmente a partir do código-fonte (não recomendado)

Clone o [repositório](https://github.com/factor/factor) e use `make` nessa pasta.

Se o `make` falhar com um erro sobre um alvo inexistente, tente `make factor` ou, se você souber ler um Makefile, encontre o alvo do make para a sua plataforma no `GNUmakefile`.

Se *isso* também falhar, abra uma issue em [factor/factor](https://github.com/factor/factor) com o erro; os desenvolvedores são gente boa e vão adorar ajudar.
