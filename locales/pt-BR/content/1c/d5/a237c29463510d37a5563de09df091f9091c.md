# Sobre

Lá no nível do hardware, os transistores só podem estar ligados ou desligados: dois estados que tradicionalmente representamos com `1` e `0`.
Esses são os [`binary digits`][binary-digits], abreviados como [`bits`][bits].
Entender `bits` e `binary` é especialmente importante para quem programa sistemas e trabalha com linguagens de baixo nível.

No entanto, durante a maior parte da história da computação, a prioridade da programação foi encontrar formas cada vez mais sofisticadas de _abstrair_ essa realidade binária.
Em Python (e em muitas outras [linguagens de programação de alto nível][high-level-language]), trabalhamos com `int`, `float`, `string` e outros _tipos_ definidos, incluindo até formatos de áudio e vídeo.
Deixamos os detalhes internos do Python cuidarem de (eventualmente) traduzir tudo para bits.

Ainda assim, usar [operadores bit a bit][python-bitwise-operators] e [operações bit a bit][python-bitwise-operations] pode, às vezes, trazer vantagens significativas de velocidade e eficiência de memória, mesmo em uma linguagem de alto nível como Python.


## Inserindo e exibindo números binários

Como era de esperar, o Python interage com o usuário usando números decimais, mas quem programa pode mudar esse padrão.
Na verdade, o Python aceita sem problemas um `int` nos formatos `binary`, `hexadecimal` ou `octal`, e realiza operações matemáticas entre eles tranquilamente.
Para mais detalhes, você pode revisar o conceito [concept:python/binary-octal-hexadecimal]().

Números binários são inseridos com o prefixo `0b`, assim como `0x` pode ser usado para hexadecimal (_números hex são uma forma concisa de representar grupos de 4 bits_) e `oct` pode ser usado para números octais.

Há várias formas de converter inteiros em strings binárias, que variam conforme incluam ou não o prefixo `0b` e conforme suportem ou não preenchimento à esquerda com zeros:


```python
# Binary entry.
>>> 0b10111
23

# Converting an int display to binary string, with prefix.
>>> bin(23)  
'0b10111'

>>> number = 23

# Binary without prefix, padded to 8 digits.
>>> format(number, '08b')  
'00010111'

# Same format, but using an f-string.
>>> f"{number} in decimal is {number:08b} in binary and {number:x} in hex" 
'23 in decimal is 00010111 in binary and 17 in hex'
```


## [`Bitwise Logic`][python-bitwise-operations]

No conceito [concept:python/bools](), discutimos os _operadores lógicos_ `and`, `or` e `not` usados com valores Boolean (_`True` e `False`_).
As mesmas regras de lógica se aplicam ao trabalhar com bits.

No entanto, os equivalentes bit a bit dos operadores lógicos `&` (_and_), `|` (_or_), `~` (_not_) e `^` (_[XOR][xor]_) são aplicados a cada _bit_ de uma representação binária, tratando `1` como `True` ("ligado") e `0` como `False` ("desligado").
Um exemplo com o `&` bit a bit pode deixar isso mais claro:


```python
>>> x = 0b01100110
>>> y = 0b00101010

>>> format(x & y, '08b')
'00100010'
```

Somente as posições com um `1` em _**ambos**_ os números de entrada são definidas como `1` na saída.

O `&` bit a bit costuma ser usado para isolar bits individuais em um conjunto compactado de valores `True`/`False`, como configurações que o usuário ajusta em um aplicativo.
Isso permite que o valor de bits individuais controle a lógica do programa:


```python
>>> number = 0b0110
>>> number & 0b0001 > 0
False

>>> number & 0b0010 > 0
True
```


Para o `|` bit a bit (or), define-se um `1` na saída se houver um `1` em _**qualquer uma**_ das entradas:


```python
>>> x = 0b01100110
>>> y = 0b00101010

>>> format(x | y, '08b')
'01101110'
```


Com o operador `^` para o **ou** e**x**clusivo bit a bit (xor), define-se um `1` se ele aparecer em _**uma ou outra**_ das entradas, _**mas não em ambas**_.
Esse símbolo pode parecer familiar do conceito [concept:python/sets](), onde ele é usado para a _diferença simétrica_ de `set`, que é a mesma coisa que [xor aplicado a conjuntos][symmetric-difference].
Se o xor `^` parecer estranho, saiba que essa é de longe a [operação mais comum em criptografia][xor-cipher].


```python
>>> x = 0b01100110
>>> y = 0b00101010

>>> format(x ^ y, '08b')
'01001100'
```


Por fim, há o operador `~` (_o caractere [til][tilde]_), que é um `not` bit a bit que recebe uma única entrada e _**inverte todos os bits**_, o que pode não ser o resultado que você esperava!
Cada `1` na representação vira `0`, e vice-versa.
Veja a seção abaixo para mais detalhes.


## Números negativos e representação binária

Na representação decimal, distinguimos números positivos e negativos usando um sinal `+` ou `-` à esquerda dos dígitos.
Usar esses símbolos no nível binário se mostrou ineficiente para a computação digital e trouxe o problema de que `+0` não é o mesmo que `-0`.

Em vez de usar `-` e `+`, todos os computadores modernos usam a representação de [`two's complement`][twos-complement] para números negativos, até o nível do chip de silício.
Isso significa que todos os bits são invertidos e um número é _**interpretado como negativo**_ se o bit mais à esquerda (também chamado de "bit mais significativo", ou MSB) for `1`.
Números positivos têm MSB igual a `0`.
Essa representação tem a vantagem de ter apenas uma versão do zero, de modo que quem programa não precisa lidar com `-0` e `+0`.

Essa forma de representar números negativos e positivos cria uma complicação para o Python: não há conceitos de inteiros de tamanho finito como `int32` ou `int64` internamente na linguagem principal.
No Python 'moderno', os `int`s têm tamanho ilimitado (_limitado apenas pela capacidade do hardware_), e um número negativo ou com bits invertidos tem uma quantidade (_teoricamente_) infinita de `1`s à esquerda, assim como um número positivo tem `0`s ilimitados.

Isso torna difícil dar um exemplo útil do `bitwise not`:

```python
>>> x = 0b01100110
>>> format(x, '08b')
'01100110'

# This is a negative binary (not twos-complement display).
>>> format(~x, '08b')
'-1100111'  

 # Decimal representation.
>>> x
102

# Using the Bitwise not, with an unintuitive result.
>>> ~x
-103
```

Isto **não** é o `0b10011001` que veríamos em linguagens com inteiros de tamanho fixo.

O operador `~` só funciona como esperado com tipos de byte ou inteiro _**sem sinal**_, ou com tipos de inteiro de tamanho fixo.
Esses tipos numéricos são suportados em pacotes de terceiros como [`NumPy`][numpy], [`pandas`][pandas] e [`sympy`][sympy], mas não no Python principal.

Na prática, quem programa em Python costuma usar `&`, `|`, `^` e os operadores de deslocamento descritos abaixo somente com números positivos.
Operações bit a bit com números negativos são bem menos comuns.
Uma técnica é somar [`2**32 (or 1 << 32)`][unsigned-int-python] a um valor negativo para tornar um `int` sem sinal, mas isso fica difícil de gerenciar.
Outra estratégia é trabalhar com o módulo [`ctypes`][ctypes-module] e usar tipos de inteiro no estilo C, mas isso é igualmente complicado.


## [`Shift operators`][bitwise-shift-operators]

O operador de deslocamento à esquerda `x << y` move todos os bits de `x` em `y` posições para a esquerda, preenchendo as novas lacunas com zeros.
Repare que isso é aritmeticamente idêntico a multiplicar um número por `(2**y)`.

O operador de deslocamento à direita `x >> y` faz o oposto.
Isso é aritmeticamente idêntico à divisão inteira `x // (2**y)`.

Tenha em mente a seção anterior sobre números negativos e as armadilhas de deslocá-los em Python.


```python
>>> x = 8
>>> format(x, '08b')
'00001000'

# A left bit shift. 
>>> x << 2  
32

>>> format(x << 2, '08b')
'00100000'

# A right bit shift. 
>>> format(x >> 2, '08b')
'00000010'
```
