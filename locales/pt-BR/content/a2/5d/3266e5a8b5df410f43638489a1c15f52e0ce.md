# Testes

Cada exercício contém um arquivo de testes.
Rode os testes com o programa `bats`.
```bash
bats test-hello-world.bats
```

O `bats` precisa estar instalado.
Consulte a página [Testes no Bash][bash] para saber como instalar o `bats` no seu sistema.

### O bats é implementado em bash

O arquivo do bats é um script bash, com algumas funções especiais reconhecidas pelo comando `bats`.
Você vai ver alguns testes parecidos com
```sh
gawk -f some-exercise.awk <<< "some,input,here"
```
Essa sintaxe `<<<` é uma [Here String][here-string] do bash.
Ela envia a string do lado direito para a entrada padrão do programa do lado esquerdo.
É ([aproximadamente][so]) o mesmo que
```sh
echo "some,input,here" | gawk -f some-exercise.awk
```

## Ajuda para as funções assert

Os testes usam funções da biblioteca [bats-assert][bats-assert].
Você encontra lá a ajuda para as várias funções `assert*`.

## Testes ignorados

Resolver um exercício significa fazer todos os testes passarem.
Por padrão, só um teste (o primeiro) é executado quando você roda os testes.
Isso é intencional, pois permite que você se concentre em fazer apenas esse teste passar.
Quando ele passar, você pode habilitar o próximo teste comentando ou removendo as

    [[ $BATS_RUN_SKIPPED == true ]] || skip

anotações que precedem os outros testes.

## Como sobrescrever os skips

Para rodar todos os testes, incluindo os que têm anotações `skip`, rode:
```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

Pode ser prático usar uma função wrapper para digitar menos: no `bash`, você pode fazer:
```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```
Depois, rode os testes só com:
```bash
bats
```

## Saída de debug

```exercism/caution
Isso funciona localmente com o `bats`, mas **não** no editor online do Exercism.
```

Quando roda os testes, o `bats` captura tanto a stdout quanto a stderr para comparar com a saída esperada.
Se você imprimir mensagens de debug na stdout ou na stderr, elas serão incluídas na saída capturada e podem fazer o teste falhar.

Para imprimir informações de debug sem afetar o resultado dos testes, o `bats` disponibiliza o descritor de arquivo **3** para isso.
Qualquer coisa impressa no arquivo `/dev/fd/3` aparece durante a execução dos testes, mas não é incluída na saída capturada usada nas asserções.

Exemplo:

```awk
BEGIN {
    # This debug message will not interfere with test output comparison
    print "a debug message" > "/dev/fd/3"

    # Normal program output (this is what your tests will see and compare)
    print "Hello, World!"
}
```

Exemplo de execução:

```none
$ bats test-hello-world.bats
test-hello-world.bats
 ✓ Say Hi!
a debug message

1 test, 0 failures
```

Assim você vê uma saída de debug útil sem afetar os testes.

Esconder os detalhes em uma função pode melhorar a legibilidade se você usar isso em vários lugares do seu código:

```awk
BEGIN {
    debug("starting ...")
}

# do stuff here ...

END {
    debug("... finished")
}

function debug(msg) {print msg > "/dev/fd/3"}
```
