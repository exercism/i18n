# Sobre

## const

O modificador [`const`][constants] pode ser aplicado (e em geral deve ser) a qualquer campo cujo valor seja conhecido em tempo de compilação e não mude durante o tempo de vida do programa.

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

O compilador vai te orientar sobre quais expressões podem ser avaliadas em tempo de compilação. Operações aritméticas simples são permitidas, assim como a concatenação de strings. Isso exclui qualquer avaliação que exigiria o uso do heap ou da pilha, então chamadas de método e referências a tipos não primitivos não estão disponíveis.

Há alguma discussão na web sobre as vantagens de desempenho de `const` em relação a variáveis. No caso de uma comparação com campos de instância que não são `const`, pode haver uma economia perceptível de memória, mas, comparado a variáveis estáticas, isso é decididamente trivial. Qualquer consideração sobre desempenho de CPU provavelmente será vista pelos seus colegas como [otimização prematura][premature-optimization].

Um motivo mais convincente para usar `const` é que ele melhora a capacidade do mantenedor de raciocinar sobre o código. Perceber que um campo está marcado como `const` ou `readonly`, ou que uma propriedade não tem um setter, permite que o mantenedor praticamente o descarte da sua análise. É pouco provável que ele seja a origem de bugs. É pouco provável que ele traga dificuldades num exercício de refatoração. Este [comentário no Stack Overflow][so-consts] trata disso.

O modificador `const` também pode ser aplicado a valores dentro de métodos:

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

Identificar um valor com `const` desse jeito pode ser útil se ele for usado várias vezes no método ou se você quiser chamar atenção para o significado dele. Não há ganho de desempenho em relação a usar literais diretamente.

## readonly

O modificador [`readonly`][readonly-fields] pode ser aplicado (e em geral deve ser) a qualquer campo que não possa ser `const`, cujo valor não mude durante o tempo de vida do programa e que seja definido por um inicializador em linha ou durante a instanciação (pelo construtor ou por um método chamado pelo construtor).

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

O uso do modificador `readonly` é incentivado pelos mesmos motivos que se aplicam ao `const`. A prática de restringir campos desse jeito ajuda os mantenedores a raciocinar sobre o código.

Repare que adicionar o modificador `readonly` a um campo impede apenas que o valor do campo seja alterado. No caso de tipos agregados, ele não protege os campos nem as propriedades desse tipo. Em particular, ele não protege o conteúdo dos arrays.

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

Para garantir que todos os membros de um tipo de referência estejam protegidos, os campos podem ser marcados como `readonly` e propriedades automáticas podem ser definidas sem um acessador `set`.

Vale a pena examinar as [coleções somente leitura][readonly-collections] na Biblioteca de Classes Base.

Para arrays, o mais próximo que você consegue chegar de uma versão somente leitura é o método [`Array.AsReadOnly<T>()`][as-read-only].
