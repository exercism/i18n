# Exceção

No mundo ideal, tudo funciona perfeitamente.
Mas no mundo real, as coisas podem dar errado, e a forma como lidamos com essas situações é importante para garantir que nosso software seja robusto e confiável.
As exceções são um conceito crucial na programação que nos permite lidar com erros e situações inesperadas de forma elegante.

Lançar um erro, se não for tratado, interrompe o programa e exibe uma mensagem de erro.
Na maioria dos casos, você não quer que seu programa pare quando ocorre um erro; em vez disso, você quer tratar o erro e continuar executando o programa.

## Lançando uma exceção

No Crystal, as exceções são lançadas com a palavra-chave `raise` e podem receber uma `String` ou um objeto `Exception`.
Se não for tratada, o programa para e imprime a mensagem de erro.

```crystal
raise "This is an error"
```

Existem várias exceções embutidas no Crystal, como `ArgumentError`, `IndexError`, `KeyError`, `IOError`, `SystemCallError`, `TypeError`, `ZeroDivisionError` e muitas outras.
Essas exigem que você passe uma mensagem para a exceção.

```crystal
raise ArgumentError.new("This is an argument error")
```

## [Tratando exceções][exception-handling]

Não queremos que nosso programa quebre quando uma exceção é lançada.
Por isso, quando sabemos que um trecho de código é propenso a erros, podemos envolvê-lo em um bloco `begin` e capturar a exceção com um bloco `rescue`.
O bloco `begin` marca o início do código que pode lançar uma exceção, e o bloco `rescue` trata a exceção.

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
end
```

O bloco `rescue` também pode especificar uma variável para obter o objeto da exceção.

```crystal
begin
 raise "This is an error"
rescue ex
 puts "An error occurred: #{ex.message}"
end
```

O bloco `rescue` também pode especificar um tipo de exceção específico, para capturar apenas aquela exceção.

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
end

# or

begin
 raise ArgumentError.new("This is an argument error")
rescue ex : ArgumentError
 puts "An argument error occurred: #{ex.message}"
end
```

Vários blocos `rescue` podem ser usados para tratar tipos diferentes de exceções.
No exemplo abaixo, o primeiro bloco `rescue` vai capturar um `ArgumentError`, e o segundo bloco `rescue` vai capturar qualquer outra exceção.

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
rescue
 puts "An error occurred!"
end
```

O bloco `begin` também pode ter um bloco `else`, que é executado se nenhuma exceção for lançada.

```crystal
begin
 puts "No error occurred"
rescue
 puts "An error occurred!"
else
 puts "No error occurred"
end
```

Por fim, existe um bloco `ensure`, que é sempre executado, independentemente de uma exceção ter sido lançada.

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
ensure
 puts "This is always executed"
end
```

## Convenções de métodos

Alguns métodos têm duas versões: uma com `!` e outra sem.
Isso pode significar duas coisas diferentes.
Uma é que o método modifica o objeto, e a outra é que o método pode lançar uma exceção.

Mas também existe outra convenção sobre terminar um método com `?`, mencionada no conceito de Boolean.
Alguns métodos lançam uma exceção por padrão, mas também têm uma versão terminada em `?` que retorna `nil` em vez de lançar uma exceção.

Isso é ideal quando você quer evitar que um erro seja lançado.
Isso pode beneficiar o desempenho, já que não é preciso criar um stacktrace e, se configurado corretamente, pode deixar o código mais seguro.

## Exceções personalizadas

Você também pode criar suas próprias exceções herdando da classe [`Exception`][exception].
Ao fazer isso, você pode, opcionalmente, sobrescrever o método `initialize` para definir a mensagem da exceção.
Isso pode ser feito atribuindo a mensagem a uma variável de instância chamada `@message`.

```crystal
class MyException < Exception
 def initialize
   @message = "This is my exception"
 end
end

raise MyException.new
```
