# Dicas

## Geral

- Seu arquivo de solução é incluído em outro, que chama suas macros.
  Mantenha o nome e a ordem dos argumentos de cada macro exatamente como a tarefa os apresenta, ou o arquivo não será montado.
- Os argumentos de uma macro são tokens, substituídos como `%1`, `%2`, `%3` onde quer que apareçam no corpo.
  Eles podem ser registradores, expressões de endereço ou literais, desde que cada expansão seja uma instrução válida.
- Cada macro é verificada quanto aos registradores que ela deixa intactos, não apenas quanto ao que ela escreve.
  Leia a nota de clobber em cada tarefa e altere apenas os registradores que ela permite.

## 1. Nomeie as constantes de formato

- Um `%define` de uma linha dá um nome a um valor, para que o resto do código leia o nome em vez de um número solto.
  Para um número fixo, `equ` faz o mesmo e é a escolha usual para uma constante.
- As constantes de byte podem ser escritas como hexadecimal (`0x20`) ou como um literal de caractere (`' '`).
  As duas formas montam para o mesmo valor.

## 2. Escreva a macro `fill_run`

- Você deve dar a `rcx` o nome legível `COUNTER`.
- `fill_run` é uma macro de várias linhas que recebe 3 argumentos.
  Macros de várias linhas são definidas com `%macro ... %endmacro`.
- O primeiro argumento de `fill_run` é um endereço de memória em um registrador de uso geral de 64 bits.
  O segundo é a contagem, que pode ser passada em um registrador de uso geral de 64 bits ou como um imediato.
  O terceiro é um byte a ser escrito, como um imediato.
  Planeje o código da macro levando essas especificações em conta.
- O único registrador que `fill_run` pode modificar é `COUNTER`.
- Um laço dentro de uma macro geralmente precisa de um rótulo com o prefixo `%%`.
  Sem esse prefixo, o mesmo rótulo é criado toda vez que a macro é chamada, o que pode causar um erro se a macro for chamada mais de uma vez.

## 3. Escreva a macro `lay_columns`

- `lay_columns` é uma macro de várias linhas que recebe 2 argumentos.
  Macros de várias linhas são definidas com `%macro ... %endmacro`.
- Os dois argumentos de `lay_columns` são passados em registradores de uso geral de 64 bits.
  O primeiro é um endereço de memória, o segundo é um número inteiro.
  Planeje o código da macro levando essas especificações em conta.
- Os únicos registradores que `lay_columns` pode modificar são os dois passados como argumentos.
- O número de deslocamentos que a macro deve escrever é fixado em tempo de montagem.
  Você pode usar `%rep ... %endrep` para repetir o código.
- O cálculo dos deslocamentos é feito com `offset[i] = margin + i * COLUMN_STRIDE`.
  `margin` é o segundo argumento da macro.
  `i` é um contador de laço que pode ser definido como uma variável `%assign`.

## 4. Escreva a macro `set_header`

- `set_header` é uma macro de várias linhas que recebe 2 argumentos.
  Macros de várias linhas são definidas com `%macro ... %endmacro`.
- O primeiro argumento de `set_header` é a expressão de um endereço de memória efetivo.
  Ela aceita um registrador base que pode ser somado a um registrador de índice multiplicado por `1`, `2`, `4` ou `8`, e um imediato.
  Isso significa que um `rdi` simples é válido, assim como `rdi+rax*4+2`.
- O segundo argumento de `set_header` é um imediato que pode ter os valores `0`, `1` ou `2`.
- `set_header` não pode modificar nenhum registrador.
- Você deve copiar um byte para o endereço de destino condicionalmente, em tempo de montagem, de acordo com o segundo argumento.
  Um valor `0` deve copiar `PLAIN`, um valor `1` deve copiar `RULED` e um valor `2` deve copiar `BOXED`.
