# Introdução

Quase todo programa em Factor é uma sequência de palavras que consomem e produzem valores na *pilha de dados*. Quando as entradas e as saídas se alinham direitinho, o código se lê da esquerda para a direita sem esforço. Quando não se alinham, você recorre às *shuffle words*, e o código vira uma bagunça rapidinho.

Este exercício apresenta a solução padrão do Factor: os combinators.

## Shuffle words

As shuffle words mais comuns ficam em [`kernel`][kernel]:

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

Você já deve ter usado `dup` e `swap`. O `over` faz uma cópia do *segundo* elemento a partir do topo, o que ajuda quando a mesma entrada precisa alimentar dois cálculos:

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

Isso funciona bem para um uso só. Mas, emendadas uma na outra, as sequências de `dup`, `swap`, `over`, `rot` ficam rapidamente ilegíveis.

## `keep`: preserva a entrada

O `keep` (em [`kernel`][kernel]) chama uma quotation no topo da pilha, mas deixa o valor original acima do resultado:

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

Isso substitui o padrão de `dup` seguido de algo e depois um shuffle: em qualquer lugar onde você escreveria `dup something swap`, basta dizer `[ something ] keep`.

## `bi`: duas funções de uma entrada

O `bi` (em [`kernel`][kernel]) aplica *duas* quotations ao mesmo valor, deixando os dois resultados na pilha:

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

Sem o `bi`, você escreveria `dup sq swap neg`, o que é legível o bastante para duas operações, mas complicado para três.

## `tri` e `cleave`: muitas funções de uma entrada

O `tri` estende o `bi` para três quotations:

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

O `cleave` (em [`combinators`][combinators]) é a mesma ideia para um *array* com qualquer número de quotations:

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

A quotation vazia `[ ]` funciona como a identidade, o que é útil quando uma das fendas do corte deve ser a própria entrada.

## `dip` e `2dip`: operar por baixo

O `dip` (em [`kernel`][kernel]) chama uma quotation nos valores *abaixo* do topo da pilha, deixando o topo intacto. O `2dip` faz o mesmo, mas protege os *dois* valores do topo:

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

Aqui o `dip` escondeu o `11`, rodou `9 10 +` e recolocou o `11` no topo. O `2dip` escondeu `11 12`, rodou `9 10 +` por baixo e depois restaurou `11 12`.

O `dip` é a ferramenta certa quando a ordem natural dos argumentos deixa o valor "de passagem" no topo da pilha. Recorra a ele em vez do sanduíche `swap … swap`.

## `bi@`: a mesma operação em dois valores

O `bi@` (em [`kernel`][kernel]) aplica uma quotation a dois valores da pilha:

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*`: operações diferentes em dois valores

O `bi*` (em [`kernel`][kernel]) aplica quotations *diferentes* aos dois valores da pilha: a primeira quotation ao valor mais baixo, a segunda ao do topo:

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

Recorra ao `bi@` quando os dois valores recebem o mesmo tratamento, e ao `bi*` quando cada um precisa do seu.

## `tri*`: operações diferentes em três valores

O `tri*` (em [`combinators`][combinators]) estende o `bi*` para três valores e três quotations, aplicando cada quotation a um valor, na ordem:

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```
