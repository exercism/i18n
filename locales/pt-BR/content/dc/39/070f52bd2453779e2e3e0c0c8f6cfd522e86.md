# Introdução

No Go 1.18, o Go ganhou suporte a **generics**.
Generics permitem que você escreva funções e estruturas de dados que funcionam com tipos diferentes sem duplicar código.

## Por que usar generics?

No Go, funções e tipos normalmente trabalham com tipos específicos, como `int` ou `string`.
Antes de generics, você tinha duas opções para dar suporte a vários tipos.
Primeiro, você podia escrever várias funções com nomes diferentes, como `SumInts` e `SumFloats`.
Essa abordagem gera código duplicado, que é difícil de manter.
Segundo, você podia usar a interface vazia `any` (`interface{}`).
Porém, a interface vazia elimina as verificações de tipo em tempo de compilação e exige asserções de tipo em tempo de execução.
Generics resolvem esse problema: você ganha segurança de tipos e evita código duplicado.

## Funções genéricas

Você define uma função genérica adicionando **parâmetros de tipo** entre colchetes `[...]` depois do nome da função.
Veja um exemplo de função genérica que retorna um slice invertido:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

Neste exemplo, `T` é um parâmetro de tipo.
Você pode pensar em `T` como um espaço reservado para um tipo real.
A palavra-chave `any` entre colchetes é uma **restrição de tipo**.
A restrição diz ao compilador quais tipos são permitidos para `T`.
Aqui, `any` significa que `T` pode ser qualquer tipo.

### Como chamar funções genéricas

Você pode chamar uma função genérica passando o tipo real entre colchetes.
Esse tipo real é chamado de **argumento de tipo**.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

Na maioria dos casos, o compilador do Go consegue detectar o tipo automaticamente a partir dos argumentos da função.
Esse recurso se chama **inferência de tipo**.
Com a inferência de tipo, você não precisa escrever o argumento de tipo entre colchetes.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

Neste exemplo, o compilador vê que `words` é um slice de strings, então infere que `T` é `string`.

## Restrições de tipo

Todo parâmetro de tipo precisa ter uma restrição.
A restrição especifica quais tipos você pode usar como argumentos de tipo.
Ela também determina quais operações você pode fazer com valores desse tipo.

### A restrição `any`

A restrição `any` permite qualquer tipo.
No Go, `any` é um alias para a interface vazia `interface{}`.
Como `any` permite todos os tipos, a função só pode realizar operações que funcionem com todos os tipos do Go.
Por exemplo, se você tem dois valores `any` que guardam slices, eles não podem ser comparados com `==`, porque slices não podem ser comparados com `==`.

### A restrição `comparable`

O Go oferece uma restrição embutida chamada `comparable`.
A restrição `comparable` permite qualquer tipo que aceite os operadores `==` e `!=`.
Entre os tipos comparáveis estão Boolean, números, strings, ponteiros, canais e structs ou arrays formados por tipos comparáveis.

Veja um exemplo de função que verifica se um slice contém um item específico:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

Como `T` usa a restrição `comparable`, usar `elem == target` é válido.
Se você trocar `comparable` por `any`, o compilador vai acusar um erro.

### Restrições personalizadas com conjuntos de tipos em interfaces

A partir do Go 1.18, as interfaces podem definir conjuntos de tipos além de métodos.
Você pode usar o caractere de barra vertical `|` para listar os tipos permitidos em uma interface.

```go
type Number interface {
    int | int64 | float64
}
```

Agora você pode usar `Number` como restrição de uma função:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

Como todos os tipos de `Number` aceitam o operador `*`, o Go permite `value * 2` dentro da função.

### A aproximação de tipo subjacente `~`

Às vezes você cria uma definição de tipo personalizada com base em um tipo primitivo:

```go
type MyInt int
```

A restrição `Number` definida acima permite apenas os tipos exatos `int`, `int64` e `float64`.
Se você passar um valor `MyInt` para `Double`, o compilador gera um erro, porque `MyInt` não corresponde a `int`.
Para permitir qualquer tipo cujo tipo subjacente seja `int`, adicione um til `~` antes do tipo:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

Agora você pode usar `Double` com valores do tipo `MyInt`.

### A restrição `cmp.Ordered`

A biblioteca padrão oferece a restrição `cmp.Ordered` no [pacote `cmp`][doc-cmp].
A restrição `cmp.Ordered` permite qualquer tipo que aceite os operadores de comparação `<`, `<=`, `>` e `>=`.

## Tipos genéricos

Você também pode usar parâmetros de tipo para definir tipos genéricos, como structs.
Veja um exemplo de uma estrutura de dados `Stack` genérica:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

Ao declarar uma variável de um tipo genérico, você precisa informar o argumento de tipo entre colchetes:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

A inferência de tipo funciona apenas para funções genéricas.
Ao criar valores de um tipo genérico, você sempre precisa especificar o argumento de tipo.

## Quando usar generics

Generics são um recurso poderoso, mas você não precisa usá-los em todo problema.

Use generics nestas situações:
- Você está construindo estruturas de dados, como árvores, listas ligadas ou caches, que funcionam com qualquer tipo de elemento.
- Você está escrevendo funções utilitárias que operam sobre slices ou maps de qualquer tipo, como filtrar, ordenar ou buscar.
- Você precisa da mesma implementação exata para vários tipos e quer segurança de tipos em tempo de compilação.

Nestas situações, use interfaces:
- Você se importa com comportamento e métodos, e não com o tipo de dado subjacente.
  Por exemplo, se você quer ler e processar dados de fontes de vários tipos (arquivos, rede, TTY), prefira `func Process(src io.Reader)` a `func Process[T](src T)`.
- Tipos diferentes exigem implementações de métodos diferentes para realizar seu trabalho.
