# Executando os testes

No terminal, vá até o diretório base do exercício e execute os testes com:

```bash
$ mix test
```

Isso executa o arquivo de teste que fica na subpasta `test`, um arquivo com terminação `_test.exs`.

Documentação:

* [`mix test` - ferramenta de execução de testes do Elixir](https://hexdocs.pm/mix/Mix.Tasks.Test.html)
* [`ExUnit` - biblioteca de testes unitários do Elixir](https://hexdocs.pm/ex_unit/ExUnit.html)

## Testes pendentes

Nas suítes de testes dos exercícios de prática, todos os testes, exceto o primeiro, estão marcados para serem pulados.

Depois que um teste passar, você pode desmarcar o próximo comentando o `@tag :pending` correspondente com o símbolo `#`.

Por exemplo:

```elixir
# @tag :pending
test "shouting" do
  assert Bob.hey("WATCH OUT!") == "Whoa, chill out!"
end
```

Se você quiser executar todos os testes de uma vez, pode incluir todos os testes pulados usando a flag `--include` no comando `mix test`:

```bash
$ mix test --include pending
```

Ou você pode habilitar todos os testes comentando a linha `ExUnit.configure` no arquivo `test/test_helper.exs`.

```elixir
# ExUnit.configure(exclude: :pending, trace: true)
```

## Opções úteis do `mix test`

* `test/<FILE>.exs:LINENUM` - executa apenas um único teste, o teste de `<FILE>.exs` cuja definição está na linha `LINENUM`
* `--failed` - executa apenas os testes que falharam na última vez em que foram executados
* `--max-failures` - a suíte para de avaliar os testes quando esse número de falhas é atingido
* `--seed 0` - desativa a aleatoriedade, para que os testes de um mesmo arquivo sejam sempre executados na mesma ordem em que foram definidos
