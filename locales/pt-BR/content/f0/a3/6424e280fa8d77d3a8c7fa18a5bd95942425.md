# Sobre

## Opcionais

O Swift usa [_opcionais_][optionals] para permitir que programadores representem a possível ausência de um valor.
Um opcional é um tipo que pode conter um valor ou ser [`nil`][nil], que representa a ausência de um valor.
Usar um opcional exige que o programa verifique se o valor realmente existe antes de usá-lo, depois de desempacotá-lo.

Qualquer tipo pode virar um opcional acrescentando um `?` ao final do nome do tipo.
Assim, um inteiro opcional teria o tipo `Int?` e uma string opcional teria o tipo `String?`.
Definir constantes ou variáveis de tipo opcional e atribuir valores a elas funciona do mesmo jeito que para valores de tipos não opcionais.

```swift
let x: Int? = 42
var y: String? = "Hello"
y = "Goodbye"
```

Você pode atribuir a ausência de um valor a uma variável de tipo opcional atribuindo a ela o valor especial `nil`.
O `nil` pode ser usado com todos os tipos opcionais, mas `nil`s atribuídos a dois tipos opcionais diferentes não têm o mesmo tipo, e não podem ser trocados nem comparados.

```swift
let intOpt: Int? = nil
let stringOpt: String? = nil

intOpt = stringOpt
// Compiler error: Cannot assign value of type 'String?' to type 'Int?'

intOpt == stringOpt
// Compiler error: Binary operator '==' cannot be applied to operands of type 'Int?' and 'String?'
```

Repare também que, mesmo que o `nil` possa ser atribuído a qualquer tipo opcional, ele não pode ser atribuído a um tipo não opcional (mesmo que essa variável não guarde `nil` de verdade).
E um método que espera um tipo não opcional não pode receber um tipo opcional sem desempacotá-lo antes.

```swift
var x: Int = 42
var y: Int? = 42

y = x
// Works fine
x = y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
x + y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

## Usando opcionais

Como os tipos opcionais não são os mesmos tipos que os seus tipos base, os dois não podem ser usados da mesma forma.
Por exemplo: `Int("123") + 1` gera o erro de compilação "Value of optional type 'Int?' must be unwrapped to a value of type 'Int'".
Isso acontece porque `Int("123")` retorna um tipo `Int?` opcional, e não um `Int`, já que, se a string não puder ser convertida em inteiro, o resultado será `nil`.
Para acessar o `Int` da conversão, é preciso "desempacotá-lo" primeiro.

No Swift, isso costuma ser feito com as construções `if-let` e `guard-let` de [_vinculação opcional_][optional-binding], que verificam se há `nil` e seguem um caminho de código com o valor desempacotado vinculado a um nome fornecido, se existir um valor, ou seguem um caminho diferente, se `nil` for encontrado.

```swift
if let safeNum = Int("123") {
	let sum = safeNum + 1
	…
} else {
  // code for the case where nil was found -- may be left out
}
```

Vale notar que a variável `safeNum` tem o tipo `Int`, e não `Int?`.
No exemplo abaixo, `num` é do tipo `Int?` e `safeNum` é do tipo `Int`.

```swift
let num = Int("123")
if let safeNum = num {
  // num is of type Int
}
```

Essa _vinculação opcional_ é importante porque desempacota (ou "remove") o tipo opcional do valor, permitindo usá-lo como um valor não opcional.
Se você apenas fizesse uma verificação condicional para saber se o valor é `nil`, o valor continuaria sendo de tipo opcional:

```swift
let num = Int("123")
if num != nil {
  // num is of type Int?
}
```

A opção `guard-let` também pode ser usada nos casos em que um retorno antecipado é desejado:

```swift
guard let num = Int("123") else { return nil }
let sum = num + 1
…
```

## Comparando opcionais

Repare que, mesmo que o tipo base de um par de opcionais possa ser comparado com os operadores de comparação padrão, os próprios opcionais não podem ser comparados.
Eles só podem ser verificados quanto à igualdade.
Dois opcionais são iguais se ambos forem `nil` ou se os valores que eles envolvem forem iguais dentro de seus tipos base.

No entanto, dá para escrever código que faça uma comparação personalizada entre dois valores opcionais.
Abaixo está um exemplo de uma instrução `switch` que retorna `true` apenas se os dois valores opcionais não forem `nil` e o primeiro valor for menor que o segundo.
Para isso, ela usa o _padrão opcional_ `varName?`, que corresponde apenas a opcionais que não são `nil`, vinculando o valor dentro do opcional ao nome `varName`.

```swift
switch (optionalA, optionalB) {
case let (valA?, valB?): return valA < valB
default: return false
}
```

## Coalescência de nil

Existe outra opção de desempacotamento quando é possível usar um [valor alternativo][fallback] se houver `nil`.
Isso pode ser feito com o _operador de coalescência de nil_, `??`. Supondo que `x` seja um `Int?`, se escrevermos `let y = x ?? 0`, o Swift verifica se `x` é `nil`.
Se não for, ele desempacota `x` e atribui o valor desempacotado a `y`; e, se `x` _for_ `nil`, ele atribui 0 a `y`.

Como `x ?? y` é apenas uma forma abreviada de `x != nil ? x! : y`, se `x` não for `nil`, a expressão `y` nem chega a ser avaliada.

Por fim, vale notar que o operador de coalescência de nil é associativo à direita, o que pode gerar resultados surpreendentes para quem não está atento.

```swift
let k = 42 ?? 0 + 1    // returns 42
let j = nil ?? 0 + 1   // returns 1
```

Você pode ler mais sobre o operador de coalescência de nil em [Um tour pelo Swift: operador de coalescência de nil][nil-coalescing].
