# Sobre

## Números e operadores numéricos

Todos os **números**, sejam inteiros ou não, são números de ponto flutuante de precisão dupla IEEE754.
A implementação do `jq` usa o tipo `double` do C.
Isso nos limita a 53 bits de precisão.

Os operadores de sempre estão disponíveis para usar com números:

- aritmética: `+`, `-`, `*`, `/`, `%`
- comparação: `==`, `!=`, `<`, `<=`, `>=`, `>`
- as [funções matemáticas][man-math] padrão

  Para funções de uma entrada, passe o valor por pipe para a função

  ```sh
  $ jq -n '(1 | atan) * 4'
  3.141592653589793
  ```

  Para funções de duas entradas, as funções ignoram a entrada e esperam as
  entradas como parâmetros

  ```sh
  $ jq -n 'pow(2; 10)'
  1024
  ```

  O ponto e vírgula é o separador dos argumentos de função, não a vírgula.

~~~~exercism/caution
O que significa dizer "Isso nos limita a 53 bits de precisão"?

Uma demonstração:

```sh
$ jq -n 'pow(2;52) as $n | [$n, $n+1]'
[
  4503599627370496,
  4503599627370497
]
```

Isso parece bom. E se aumentarmos o expoente?

```sh
$ jq -n 'pow(2;53) as $n | [$n, $n+1]'
[
  9007199254740992,
  9007199254740992
]
```

Esses números não deveriam ser iguais.
É assim que se parece a "perda de precisão".
Isso significa que o `jq` não consegue lidar com números arbitrariamente grandes.
~~~~

## Expressões condicionais

O `jq` usa uma [expressão `if-then-else`][if-then-else] para **expressões condicionais**.
Como uma _expressão_, ela é colocada em um pipeline.

A sintaxe é: `if CONDTITION then TRUE_EXPR else FALSE_EXPR end`.

A cláusula `else` é opcional.

```jq
42 | if . < 33 then "small" else "larger" end
# => "larger"
```

Condições adicionais usam `elif`

```jq
42 | if . < 33 then "small"
     elif . < 67 then "medium"
     else "large"
     end
# => "medium"
```
