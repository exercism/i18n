# Introdução

## Enumerações

Até agora, lidamos principalmente com números e strings.
Para modelar o mundo real, muitas vezes queremos um conjunto limitado de valores que uma variável pode assumir.
Você pode querer um tipo dedicado com alguns valores distintos, cada um com um nome distinto.
Por exemplo, numa fábrica de skates, o material do shape pode ser apenas maple, bamboo ou plastic.

Você poderia usar números inteiros para codificar esses valores, mas precisaria de código extra para verificar se o sistema mandou um valor inválido para o material.
O significado desses [_números mágicos_][magic numbers] é difícil de rastrear ao longo do código-fonte, e eles são fáceis de confundir.
`enumerations` podem ser usadas para incentivar um código expressivo e restringir comparações acidentais.

## Exemplo de uso

O termo específico para esse tipo de enumeração é `scoped enumeration`.
O trecho abaixo mostra como escrever uma `enumeration` chamada `DeckMaterial`.
Repare na palavra-chave `enum class` e no `;` no final da definição:

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
Agora, veja uma função de precificação na loja de skates e observe o operador de resolução de escopo (`::`) especificando um `enumerator` da `enumeration`:

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## Escopo

Imagine que você tem uma segunda `enumeration` para o material das rodas:

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
Embora as rodas e o shape possam ser feitos de _plastic_, os dois não podem ser confundidos.
São _tipos_ diferentes: o plastic de `DeckMaterial` e o plastic de `WheelMaterial`.
Cada `enumeration` mantém seus `enumerators` no próprio escopo: o próprio `namespace`.
É por isso que elas recebem o nome de `scoped enumerations`.

## Enumerações sem escopo
Você pode estar pensando que, se existe o nome `scoped`, também devem existir enumerações `unscoped`, e você está certo.
As `unscoped enumerations` estão ficando menos populares porque todas compartilham o mesmo namespace global.
Por causa desse compartilhamento, você não poderia ter duas `unscoped enumerations` com os mesmos `enumerators`, como _plastic_ no exemplo acima.

Além disso, as `Unscoped enumerations` são convertidas implicitamente em números inteiros.
Veja o exemplo abaixo, com um resultado surpreendente:

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

Se você quiser converter `scoped enumerations` em números inteiros, pode usar `static_cast<int>`.
