# Introdução

Ao fazer pattern matching em um valor em Gleam, precisamos garantir que os padrões cubram todos os valores possíveis do tipo, caso contrário o código não compila.

Esta função deve ser rejeitada, pois não trata o caso em que a lista está vazia:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Na maioria das vezes, em programas Gleam, queremos tratar todos os casos possíveis, mas em alguns programas, como protótipos e scripts rápidos, podemos querer focar só no caminho feliz e não escrever código para os outros casos. É aí que o `let assert` do Gleam entra.

Com o `let assert`, um padrão pode corresponder apenas a alguns dos valores possíveis de um tipo e, se o padrão não corresponder a um valor, o programa quebra. Usando `let assert`, podemos escrever a função acima assim:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Bibliotecas de Gleam nunca devem usar let assert, pois isso pode quebrar o programa. Em vez disso, elas devem usar o tipo `Result` e deixar quem desenvolve a aplicação decidir como tratar os erros.
