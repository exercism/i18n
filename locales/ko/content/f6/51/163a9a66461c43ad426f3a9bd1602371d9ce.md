# Unison 기초

## 항과 함수

항과 함수는 Unison 프로그램을 작성하는 기본 단위예요.

"항"은 정적 값을 부르는 말이에요. `name = expression` 형태로 정의하고, 앞에 `name : MyType` 형태의 타입 시그니처를 붙일 수도 있어요. Unison은 타입 추론을 지원하기 때문에, 단순한 정의에서는 타입 시그니처를 생략한 모습을 볼 수도 있어요.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unison 함수는 `myFunctionName argument1 argument2 = myImplementation`처럼 생겼어요. 함수 이름으로 시작하고, 그 뒤에 공백으로 구분한 인자들이 와요.

```
getMax a b = Nat.max a b
```

함수에는 타입 시그니처를 선택적으로 붙일 수 있어요. 오른쪽 맨 끝의 타입이 항상 함수의 최종 반환 타입이고, 각 인자는 함수 화살표 `->`로 구분해요.

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

함수를 호출할 때는 함수 이름 뒤에 인자들을 오직 공백으로만 구분해서 이어 써요.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

함수를 호출할 때 Unison은 바로 오른쪽에 있는 것을 그 함수의 인자로 취급하려고 해요. 그래서 항상 원하는 순서로 함수가 평가되지는 않아요.

다음 식에서 값 `1`을 얻고 싶다고 해봐요.

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

작성된 그대로라면 `shouldBe1`은 `0`으로 평가돼요. 암묵적인 함수 적용 순서가 `getMax 1 10`을 먼저 계산해 `10`이 되고, 그다음 `10 - 10`을 계산해 `0`이 되기 때문이에요.

괄호를 사용하면 식을 원하는 연산 순서로 다시 묶을 수 있어요.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## 와치 식

Unison에는 코드를 빠르게 평가해 볼 수 있는 방법이 있는데, 이를 "와치 식"이라고 해요. 와치 식은 `>` 기호로 시작하고, 그 뒤에 평가할 식이 와요. 와치 식은 `.u` 확장자가 붙은 파일이면 어디에나 쓸 수 있어요. 파일을 저장하면 Unison Codebase Manager (UCM) 콘솔에서 그 식이 어떤 값으로 평가되는지 확인할 수 있어요. 이 문서에서는 가능한 한, 식을 와치 식으로 평가했을 때의 예상 출력과 함께 보여 드리려고 해요.

```
> helloThere
  ⧩
  "Hello, World!"
```

## 여러 줄 함수

Unison의 여러 줄 함수는 들여쓰기나 `let` 블록으로 코드의 경계를 정해요. 이 경계를 "렉시컬 스코프"라고 불러요.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

들여쓰기 수준이 같은 것은 모두 같은 스코프를 공유해요. 그래서 마지막 줄에서도 `newBeginning` 변수를 참조할 수 있는 거예요.

## 네임스페이스와 `use`문

네임스페이스는 Unison 함수를 묶어서 정리하는 방법이에요. "디렉터리"와 비슷하다고 생각하면 돼요. 구조와 논리적인 그룹을 만들어 줘요.

`use`문을 쓰면 네임스페이스 안의 함수들을 스코프로 가져올 수 있어요.

Unison의 `List` 값을 사용하는 함수를 작성한다고 해봐요. `List.map`이나 `List.flatMap` 같은 함수가 필요하다는 걸 알고 있어요. 여기서 `List`는 네임스페이스이고, `map`과 `flatMap`은 함수예요. 같은 걸 반복해서 쓰지 않으려고, 다음과 같이 `List` 네임스페이스의 모든 것을 함수의 렉시컬 스코프로 가져올 수 있어요.

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

`use List` 줄은 `map`과 `flatMap`에 대한 참조가 무엇을 가리키는지 명확히 해줘요. `use`문에 대해서는 [여기][use-statements]에서 더 읽어볼 수 있어요.

## Unison의 표준 라이브러리

Unison의 표준 라이브러리는 `base`라고 불러요. 퀵스타트 가이드를 따라 해서 로컬에 코드베이스를 만들어 두었다면, 표준 라이브러리는 자동으로 내려받아졌을 거예요. 표준 라이브러리 문서는 [Unison Share][unison-share-base]에서 온라인으로 볼 수 있어요.

## 주석과 문서 리터럴

Unison의 주석은 조금 특이한 기능이에요. Unison 코드를 작성할 때, `.u` 확장자가 붙은 파일 안에 해석되지 않는 텍스트를 다음과 같은 문법으로 만들 수 있어요.

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_하지만_ Unison 코드는 파일 시스템 위의 텍스트 파일이 아니라 추상 구문 트리의 해시로 저장돼요. 그래서 파일 안에서 특정 Unison 함수나 항을 텍스트로 "장식"하는 주석은 저장해 두고 다시 꺼내 공유할 수가 없어요. 다른 사람이 읽고 이해할 수 있도록 저장되는 방식으로 Unison 항에 정보를 추가하고 싶다면, 문서 리터럴을 사용하면 돼요.

문서는 Unison 프로그래밍 언어에서 일급 값이에요. 즉, `Doc` 요소는 값에 할당할 수 있고, 함수에 값으로 넘길 수도 있고, 함수의 값으로 반환할 수도 있어요. 문서 리터럴 요소는 이중 중괄호로 열고 닫아요. `Doc` 요소를 주석처럼 사용하는 방법은 다음과 같아요.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
