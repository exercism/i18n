# 지시 사항 추가

## Roc에서 개수 세기

작성하는 래퍼는 기록 관리를 맡고, 제공된 백엔드가 실제 읽기와 쓰기를 수행해요. 직접 열어야 할 파일이나 연결은 없어요.

`Paasio(state, err)`는 어떤 백엔드 상태와 오류 타입과도 함께 동작해요.
백엔드는 초기의 `state`와 두 개의 콜백을 들고 있어요.

- `read!(state, max_bytes)`는 `{ state, result }`를 반환해요. 이때 결과는 `Ok(bytes)`이거나 `Err(error)`예요.
- `write!(state, bytes)`는 `{ state, result }`를 반환해요. 이때 결과는 `Ok(bytes_written)`이거나 `Err(error)`예요.

각 래퍼의 네 개 카운터는 0에서 시작해요.
`create`, `stats`, `get_state`는 콜백을 호출하지 않아야 해요.
`read!`나 `write!`를 처리할 때는 해당 콜백을 정확히 한 번만 호출하고, 인자는 그대로 전달해요.
실패한 경우에도 반환된 상태와 결과는 그대로 보관하고, `{ io, result }`를 반환해요.
이렇게 갱신된 `io`를 다음 호출로 넘겨요.

## 모든 시도가 집계에 들어가요

읽기와 쓰기 통계는 따로 관리해요.

- 실패, EOF, 0바이트 읽기, 빈 쓰기를 포함해 모든 호출을 세요.
- 바이트 수는 성공한 경우에만 세요. 읽기는 반환된 리스트의 길이를, 쓰기는 보고된 숫자를 사용해요.
- 전송량이 적어도 한 번의 호출로 집계해요. 이 작업이나 실패한 작업을 다시 시도하지는 않아요.

백엔드가 보고한 값을 그대로 세면 돼요. 운영 체제 호출이나 버퍼링을 따로 추적할 필요는 없어요.
백엔드의 바이트 수는 믿어도 되고, 카운터가 `U64`에 들어간다고 가정해도 돼요.

## 테스트 실행하기

테스트는 메모리 안에 있는 백엔드와 임시 디렉터리에 만든 실제 파일을 모두 사용해요. 임시 디렉터리는 테스트가 끝난 뒤에 정리돼요.

대부분의 다른 연습 문제와 달리, 이 연습 문제는 effectful 함수를 사용해요. 여기서는 `basic-cli` 플랫폼을 기반으로 하죠.
따라서 테스트를 로컬에서 실행하려면 `roc test` 대신 `roc --opt=speed paasio-test.roc`를 사용해야 해요. 현재 `expect` 문으로는 effectful 함수를 테스트할 수 없기 때문이에요.

Roc 코드가 반환하는 오류는 플랫폼이 평소와 다른 형식으로 보고해요.
