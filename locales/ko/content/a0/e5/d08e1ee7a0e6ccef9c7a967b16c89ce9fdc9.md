# 개요

이전 [SIMD][SIMD] 개념에서는 여러 숫자를 하나의 `xmm` 레지스터에 담아 레인 단위로 병렬 연산하는, 패킹된 부동소수점 값을 소개했어요.
같은 `xmm` 레지스터에는 패킹된 _정수_도 담을 수 있어요.

## 구문

SIMD 부동소수점 모델의 대부분은 패킹된 정수에도 그대로 적용돼요:

- 128비트 레지스터는 레인으로 나뉘어요
- 명령어는 같은 위치의 레인에서 병렬로 동작해요
- 메모리 피연산자는 동일한 16바이트 정렬 규칙을 따라요

하지만 구문은 조금 달라요:

1. 명령어가 _패킹된_ 데이터를 대상으로 동작함을 나타내는 _접두사_ `p`.
2. 수행하는 연산으로, 비SIMD(_스칼라_라고도 해요) 대응 연산과 이름이 같아요 (예: `add`, `mul` 등).
3. 각 레인의 크기를 나타내는 접미사.

패킹된 정수에는 네 가지 레인 크기가 있고, 각각 고유한 접미사가 있어요:

| 레인 너비 | 바이트 | 128비트 내 레인 수 | 접미사 |
|------------|-------|-------------------|--------|
| 바이트     | 1     | 16                | b      |
| 워드       | 2     | 8                 | w      |
| dword      | 4     | 4                 | d      |
| qword      | 8     | 2                 | q      |

예를 들어:

| 명령어      | 의미                                  |
|-------------|---------------------------------------|
| `paddb`     | 패킹된 `add`, 8비트 레인 (16개)       |
| `paddw`     | 패킹된 `add`, 16비트 레인 (8개)       |
| `paddd`     | 패킹된 `add`, 32비트 레인 (4개)       |
| `paddq`     | 패킹된 `add`, 64비트 레인 (2개)       |

어떤 명령어는 한 크기의 레인을 입력으로 받고 다른 크기의 레인을 출력으로 내놓아요.
이런 명령어도 같은 일반 규칙을 따르는데, 크기 접미사가 _두 개_ 붙어요.
첫 번째는 입력 레인의 크기를, 두 번째는 출력 레인의 크기를 나타내요:

| 명령어       | 의미                                              |
|--------------|---------------------------------------------------|
| `pmovsxwd`   | 패킹된 `movsx`, 16비트 레인에서 32비트 레인으로   |
| `pmuldq`     | 패킹된 `mul`, 32비트 레인에서 64비트 레인으로     |

## 메모리 이동

정수 이름을 가진 두 명령어는 `xmm` 레지스터와 메모리 사이에서 128비트를 복사해요:

| 명령어      | 설명                                                     |
|-------------|----------------------------------------------------------|
| `movdqa`    | 패킹된 정수를 _정렬된_ 위치로 또는 그 위치에서 복사해요  |
| `movdqu`    | 패킹된 정수를 _정렬되지 않은_ 위치로 또는 그 위치에서 복사해요 |

이 명령어들은 `movaps`, `movups`와 비슷하게 동작해요. `movdqa`는 정렬되지 않은 주소에서 폴트를 일으키는 반면, `movdqu`는 어떤 주소든 받아들여요.
네 명령어 모두 128비트를 해석하지 않고 그대로 복사해요.
정수 이름이 붙은 두 명령어를 정수 데이터와 함께 쓰는 건 관례일 뿐, 필수는 아니에요.

~~~~exercism/note
여기서 `dq`는 `double-qword`, 즉 128비트(16바이트)를 뜻해요.
~~~~

## 덧셈과 뺄셈

덧셈과 뺄셈은 이름 규칙을 따라요:

```x86asm
paddb xmm0, xmm1 ; 16 lanes: each  8-bit, xmm0 += xmm1
paddw xmm2, xmm3 ;  8 lanes: each 16-bit, xmm2 += xmm3

psubd xmm4, xmm5 ;  4 lanes: each 32-bit, xmm4 -= xmm5
psubq xmm6, xmm7 ;  2 lanes: each 64-bit, xmm6 -= xmm7
```

부호 있는 형식과 부호 없는 형식이 따로 있지는 않아요.
2의 보수에서는 레인을 부호 있는 값으로 읽든 부호 없는 값으로 읽든 덧셈과 뺄셈이 같은 비트를 만들어 내기 때문에, 명령어 하나가 둘 다 처리해요.
해석은 스칼라 `add`, `sub`에서와 마찬가지로 전적으로 자유예요.

이 명령어들은 스칼라 대응 명령어와 마찬가지로 오버플로가 나면 값이 **되돌아가요**.
8비트 레인은 값을 256으로 나눈 나머지로 담기 때문에, `200 + 100`을 `paddb`하면 `300 - 256 = 44`가 되어, 들어가지 않는 비트는 버려져요.

이렇게 남는 비트가 다음 레인으로 넘어가지 않는다는 점에 주의해요.
레인들은 같은 레지스터를 공유하지만, 각각 따로 연산돼요.

## 포화 덧셈과 뺄셈

정수 SIMD에는 부동소수점 SIMD에 없는 연산이 있어요. 바로 [포화][saturation] 덧셈과 뺄셈인데, 되돌아가는 대신 값을 _클램프_해요.
레인 범위를 넘는 결과는 그 레인이 담을 수 있는 가장 큰 값이 되고, 범위보다 작은 결과는 가장 작은 값이 돼요.

포화 형식은 크기 접미사 앞에 `s`(부호 있음) 또는 `us`(부호 없음)를 넣어요:

| 명령어      | 의미                                    |
|-------------|--------------------------------------------|
| `paddsb`    | `add`, 포화, 부호 있는 8비트 레인      |
| `paddusb`   | `add`, 포화, 부호 없는 8비트 레인    |
| `psubsw`    | `sub`, 포화, 부호 있는 16비트 레인     |
| `psubusw`   | `sub`, 포화, 부호 없는 16비트 레인   |

클램프 범위는 해당 크기와 부호 여부에 맞는 정수가 표현할 수 있는 전체 범위예요.
바이트의 경우:

- 부호 없는 바이트는 `[0, 255]`로 클램프돼요. `200 + 100`을 `paddusb`하면 `255`가 되고, `5 - 10`을 `psubusb`하면 `0`이 돼요.
- 부호 있는 바이트는 `[-128, 127]`로 클램프돼요. `100 + 50`을 `paddsb`하면 `127`이 돼요.

포화는 레인이 픽셀 채널이나 오디오 샘플처럼 한계가 있는 양을 담을 때 중요해요.
값이 되돌아가면 너무 밝은 픽셀이 어두워지지만, 클램프하면 최대 밝기를 유지하는데, 이게 바로 원하는 결과예요.

~~~~exercism/note
포화 덧셈과 뺄셈은 바이트와 워드 레인에만 있고, dword나 qword에는 없어요.
~~~~

## 곱셈

N비트 값 두 개를 곱하면 2N비트 곱이 나올 수 있지만, 목적지 레인은 N비트 폭밖에 안 돼요.
SIMD 연산은 곱의 어느 절반을 남길지, 즉 하위 N비트를 남길지 상위 N비트를 남길지 지정해서 이 문제를 해결해요.

16비트 레인에는 세 가지 명령어를 사용해요:

| 명령어      | 의미                                                       |
|-------------|---------------------------------------------------------------|
| `pmullw`    | `mul`, 16비트 레인, 각 곱의 하위 16비트를 남겨요     |
| `pmulhw`    | `mul`, 16비트 레인, 상위 16비트를 남기고, 부호 있는 피연산자   |
| `pmulhuw`   | `mul`, 16비트 레인, 상위 16비트를 남기고, 부호 없는 피연산자 |

곱의 하위 16비트는 피연산자를 부호 있는 값으로 읽든 부호 없는 값으로 읽든 같기 때문에, `pmullw` 하나만 있어요.

하지만 상위 16비트는 결과의 부호 여부에 따라 달라져요.
그래서 상위 절반 곱셈에는 부호 있는 곱셈과 부호 없는 곱셈을 위한 형식이 따로 있어요:

1. `pmulhw`: 부호 있는 곱셈용이에요.
2. `pmulhuw`: `u`가 하나 더 붙은 형태로, 부호 없는 곱셈용이에요.

구문을 살펴봐요:

1. 패킹된 정수를 나타내는 `p`.
2. 수행하는 연산 `mul`.
3. 결과의 상위("high") 비트를 선택한다는 것을 나타내는 `h`.
4. 결과를 부호 없는 값으로 해석해야 할 때(즉, 부호 확장되지 않을 때) 붙는 선택적 `u`.
5. 마지막으로, 워드(16비트) 연산임을 나타내는 크기 접미사 `w`.

워드에 대한 패킹 곱셈은 위 규칙을 정확히 따라요.
dword(32비트) 곱셈도 이 규칙을 따르지만, 하위 절반을 선택하는 변형 `pmulld`만 있어요.

상위 비트를 선택하는 dword 곱셈 변형은 없어요.
하지만 곱셈을 _확장_해서 _짝수 인덱스_ 레인(즉, 0번과 2번 위치의 레인)의 완전한 64비트 곱을 저장하는 변형은 있어요:

| 명령어      | 의미                                                                          |
|-------------|----------------------------------------------------------------------------------|
| `pmuludq`   | 짝수 인덱스 32비트 원소를 부호 없이 곱해 2개의 완전한 64비트 곱으로 만들어요 |
| `pmuldq`    | 짝수 인덱스 32비트 원소를 부호 있게 곱해 2개의 완전한 64비트 곱으로 만들어요   |

구문에 `dq`가 쓰이고, 부호 없는 곱셈일 때는 그 앞에 `u`가 붙을 수 있다는 점에 주의해요.
이는 이 명령어들이 `dword` 레인을 입력으로 받아 `qword` 레인을 출력하기 때문이에요.

## 나눗셈

패킹된 정수 나눗셈은 없어요.
나눗셈이 필요한 코드는 값을 부동소수점으로 변환한 뒤 나누고, 다시 되돌려 변환해요.

## 정수 확장

`movsx`와 `movzx`에도 패킹된 대응 명령어가 있어요.
이들은 입력과 출력의 레인 크기가 다른 명령어에 대해 앞서 언급한 것과 같은 구문을 따라요:

```x86asm
pmovsxwd xmm0, xmm1   ; 4 words -> 4 dwords, sign-extended
pmovzxbw xmm0, xmm1   ; 8 bytes -> 8 words, zero-extended
```

레인 수는 더 큰 (출력) 폭에 의해 정해진다는 점에 주의해요.
명령어는 소스의 하위 부분에서 그만큼의 레인을 읽어요.
이는 단정밀도와 배정밀도 부동소수점 사이의 패킹된 `cvt` 명령어에서 이미 본 것과 같은 의미예요.

## 정수와 부동소수점 사이의 변환

32비트 부호 있는 정수와 부동소수점 레인 사이를 변환하는 명령어가 있어요.
이들은 `cvt`, `cvtt` 명령어의 일반적인 구문을 따르는데, `si` 대신 패킹된 정수를 `dq`로 나타내요:

```x86asm
cvtdq2ps xmm0, xmm1 ; convert 32-bit signed integers in xmm1 to 32-bit floats in xmm0
cvtdq2pd xmm2, xmm3 ; convert 32-bit signed integers in xmm3 to 64-bit floats in xmm2
cvtps2dq xmm4, xmm5 ; convert 32-bit floats in xmm5 to 32-bit signed integers in xmm4
```

~~~~exercism/caution
`pi`를 써서 패킹된 정수를 나타내는 명령어는 레거시 `mmx` 레지스터에 쓰기 때문에 x86-64에서는 사실상 폐기됐어요.
`xmm` 레지스터를 사용하는 `dq` 형식을 선호해요.
~~~~

부동소수점 수와 정수 사이의 스칼라 변환에 대해 했던 것과 같은 설명이 여기에도 그대로 적용돼요.
부동소수점 수는 MXCSR이라는 특수 레지스터에 따라 반올림되는데, 함수 진입 시점에는 이 레지스터의 모드를 가정할 수 없어요.
결과를 항상 버림하는 `cvtt` 변형(`t`가 하나 더 붙어요)이 있어요.

변환하기 전에 `round`를 써서 패킹된 부동소수점 값을 알려진 상태로 만들어 둘 수도 있어요.
반올림 제어 값은 스칼라 `round`와 같고, 구문도 패킹된 부동소수점 값에 대해 동일해요:

```x86asm
roundps xmm0, xmm1, 1 ; xmm0 = floor(xmm1), packed 32-bit floats
roundpd xmm2, xmm3, 2 ; xmm2 = ceil(xmm3), packed 64-bit floats
```
