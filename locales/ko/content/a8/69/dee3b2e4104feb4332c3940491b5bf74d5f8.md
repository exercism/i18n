# 소개

behaviour를 사용하면 _behaviour 모듈_ 안에 인터페이스(함수와 매크로의 집합)를 정의하고, 나중에 여러 _콜백 모듈_에서 구현할 수 있어요. 인터페이스를 공유하기 때문에 이런 콜백 모듈들은 서로 바꿔서 사용할 수 있어요.

~~~~exercism/note
"behaviours"의 영국식 철자에 주의해 주세요.
~~~~

## behaviour 정의하기

behaviour를 정의하려면 새 모듈을 만들고, 원하는 인터페이스에 속하는 함수 목록을 지정해야 해요. 각 함수는 `@callback` 모듈 속성으로 정의해요. 문법은 [함수 타입스펙][concept-typespecs] (`@spec`)과 똑같아요. 함수 이름, 인자 타입 목록, 가능한 모든 반환 타입을 지정해야 해요.

```elixir
defmodule Countable do
  @callback count(collection :: any) :: pos_integer
end
```

## behaviour 구현하기

우리 모듈에 기존 behaviour를 추가하려면(콜백 모듈을 만들려면) `@behaviour` 모듈 속성을 사용해요. 이 속성의 값은 추가하려는 behaviour 모듈의 이름이에요.

그다음에는 그 behaviour 모듈이 요구하는 모든 함수(콜백)를 정의해야 해요. Elixir에 내장된 `Access`나 `GenServer` behaviour처럼 다른 사람이 만든 behaviour를 구현한다면, behaviour의 모든 콜백 목록은 [hexdocs.pm][hexdocs] 문서에서 찾을 수 있어요.

콜백 모듈은 자기 behaviour에 속한 함수만 구현해야 하는 게 아니에요. 하나의 모듈이 여러 behaviour를 구현할 수도 있어요.

어떤 함수가 어떤 behaviour에서 온 것인지 표시하려면 각 함수 앞에 `@impl` 모듈 속성을 사용해요. 값은 그 콜백을 정의한 behaviour 모듈의 이름이에요.

```elixir
defmodule BookCollection do
  @behaviour Countable

  defstruct [:list, :owner]

  @impl Countable
  def count(collection) do
    Enum.count(collection.list)
  end

  def mark_as_read(collection, book) do
    # other function unrelated to the Countable behaviour
  end
end
```

## 기본 콜백 구현

behaviour를 정의할 때는 콜백의 기본 구현을 함께 제공할 수 있어요. 이 구현은 `__using__/1` 매크로의 quoted 식 안에 정의해요. behaviour 모듈을 사용하는 쪽에서 기본 구현을 재정의할 수 있게 하려면 함수 구현 뒤에 `defoverridable/1` 매크로를 호출해요. 이 매크로는 함수 이름을 키로, 함수의 인자 수를 값으로 하는 키워드 리스트를 받아요.

```elixir
defmodule Countable do
  @callback count(collection :: any) :: pos_integer

  defmacro __using__(_) do
    quote do
      @behaviour Countable
      def count(collection), do: Enum.count(collection)
      defoverridable count: 1
    end
  end
end
```

`__using__/1` 안에 함수를 정의하는 것은 기본 콜백 구현을 정의할 때 말고는 권장하지 않아요. 하지만 언제든 다른 모듈에 함수를 정의하고 `__using__/1` 매크로에서 가져와 쓸 수는 있어요.
