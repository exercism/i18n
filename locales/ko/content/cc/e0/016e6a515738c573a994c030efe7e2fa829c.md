# 자세히 알아보기

C#의 `struct`는 `class`와 밀접한 관련이 있어요.
상태와 동작을 가질 수 있죠.
생성자, 메서드, 필드, 속성 등 `class`와 같은 종류의 멤버를 가질 수 있어요.

필드와 속성은 단순 타입, `struct`, 참조 타입이 될 수 있어요.
`struct`는 스코프, 읽기/쓰기 규칙, 접근 수준에 대해 `class`와 동일한 규칙을 따라요.

```csharp
enum Unit
{
    Kg,
    Lb
}

struct Weight
{
    private double count;
    private Unit unit;

    public Weight(double count, Unit unit)
    {
        this.count = count;
        this.unit = unit;
    }

    public override string ToString()
    {
        return count.ToString() + unit.ToString();
    }
}

new Weight(77.5, Unit.Kg).ToString();
// => "77.6Kg"
```

가장 기억해야 할 점 중 하나는 하나의 struct가 변수에 할당되거나 매개변수로 전달될 때 값이 복사된다는 거예요.
그래서 원래 변수를 바꿔도 복사된 변수에는 영향을 주지 않고, 그 반대도 마찬가지예요.
요약하자면 `struct`는 **값 타입**이에요.

이 [글][class-or-struct]에서는 `struct`와 `class`의 차이를 다뤄요.
글을 보면 `struct`는 가볍고 [불변][structs-immutable]인 경향이 있다는 걸 알 수 있어요.
물론 이 지침이 컴파일러나 런타임에 의해 (기본적으로) 강제되는 건 아니에요.

작업하다 보면 마주치게 되는 (그리고 컴파일러가 친절히 알려 주는) 몇 가지가 있어요:

1. `struct`의 멤버는 인라인으로 초기화할 수 없어요.
2. `struct`는 상속될 수 없어요
3. `struct`에는 기본이 아닌 생성자를 제공하더라도 항상 기본 생성자가 있고, 매개변수가 없는 생성자를 명시적으로 제공할 수는 없어요.

위의 1번과 3번 때문에 `struct`를 만드는 사람이 잘못된 인스턴스가 만들어지는 것을 막을 방법이 없어요.

## 자주 쓰이는 struct

문서를 보면 기본형과 struct가 밀접한 관계가 있다는 것을 알 수 있어요.
예를 들어 [`Int32/int`][int32]를 살펴봐요.
더 일반적인 `struct`의 예로는 [`TimeSpan`][time-span] 타입이 있어요.

`TimeSpan`의 인스턴스는 `>`나 `<` 같은 비교 연산자와 산술 연산자를 가진 숫자처럼 동작해요.
필요하다면 직접 만든 `struct`에 이런 연산자를 구현할 수 있어요.

`TimeSpan`에 대해 한 가지 짚고 넘어갈 점은 여러 인터페이스(예: `IComparable<TimeSpan>`)를 구현한다는 거예요.
`struct`는 다른 `struct`로부터 파생될 수 없지만 인터페이스는 구현할 수 있어요.

## 같음

`struct`의 같음 비교는 기본적으로 단순히 필드를 비교하기 때문에 `class`의 경우보다 훨씬 간단할 때가 많아요.
`object.Equals()`(또는 `GetHashCode()`)를 재정의할 필요가 없어요.
`Object.GetHashCode()`에 의존한다면 해시 코드를 생성하는 데 관여하는 필드(즉, 모든 필드)가 해시 컬렉션을 사용하는 동안에는 바뀌지 않아야 한다는 점을 기억해요.
사실상 이는 이런 식으로 사용되는 struct는 불변이어야 한다는 뜻이에요.

`Equals()` 메서드와 달리 같음 연산자 `==`와 `!=`에는 기본 구현이 없어요.
`struct`에 이 연산자가 필요하다면 직접 구현해야 해요.

반면 이 [글][equality]에서는 `class`에서 흔히 하듯 직접 `Equals()`와 `GetHashCode()` 메서드를 만들어 성능을 최적화하는 방법을 설명해요.
이 연습 문제의 경우, 그다지 엄격하지 않은 비교에서 차이가 약 20%였는데, 모든 필드가 같은 타입이라서 이 수치는 낮은 편일 수 있어요. 아래를 참고해요.

모든 필드가 같은 타입일 때 `Equals()` 메서드를 재정의하지 않았을 경우의 속도 개선에 관한 논의가 [웹][equality-performance]에 있어요.
이 연습 문제에서 서로 다른 타입의 필드를 포함했을 때의 차이는 약 60%였어요.
마이크로소프트 문서에는 언급되지 않은 내용이라 문서화되지 않은 구현 세부 사항이며, 신중하게 활용해야 해요.

```csharp
public bool Equals(Weight other)
{
    return count.Equals(other.count) && unit.Equals(other.unit);
}

public override bool Equals(object obj)
{
    return obj is Weight other && Equals(other);
}

public override int GetHashCode()
{
    return HashCode.Combine(count, unit);
}
```
