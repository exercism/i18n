# 개요

이 연습 문제는 매개변수의 여러 가지 특성을 보여줘요:

- `out`이나 `ref` 같은 한정자 없이 전달되는 매개변수는 [값으로 전달][passing-parameters]돼요. 즉, 호출된 메서드 안에서 매개변수를 사용하거나 값을 대입할 수는 있지만, 그 변경은 호출한 쪽에 아무런 영향을 주지 않아요.
- 배열이나 클래스 인스턴스에 대한 참조가 매개변수일 때는 호출된 메서드가 그 인스턴스의 원소나 필드를 바꿀 수 있고, 호출한 쪽에서도 그 변경을 확인할 수 있어요. 이는 `ref` 한정자가 있든 없든 마찬가지예요.
- [`out`][out-parameter] 한정자가 붙은 매개변수는 호출된 메서드에서 호출한 쪽으로 값을 돌려줘요. 이 매개변수는 초기화하지 않고도 호출된 메서드에 전달할 수 있고, 어느 경우든 호출된 메서드 안에서는 진입 시점에 초기화되지 않은 것처럼 취급돼요. 매개변수 한정자의 동작과 규칙은 예제(아래 참고)와 컴파일러 메시지를 통해 가장 쉽게 이해할 수 있어요.

```csharp
void Foo(out int val)
{
    val = 42;
}
void Bar(int val)
{
    val = 42;
}

int importantValue = 1729;
Foo(out importantValue);
var result = importantValue == 42;
// => true

importantValue = 1729;
Bar(importantValue);
result = importantValue == 1729;
// => true
```

- `out` 매개변수는 호출된 메서드 안에서 반드시 값을 대입해야 해요.

- [`ref`][ref-parameter] 한정자가 붙은 매개변수는 값을 호출된 메서드로 전달해요. 메서드가 반환하면 호출한 쪽에서는 그 매개변수에서 호출된 메서드가 만든 변경 사항을 확인할 수 있어요.

```csharp
void Foo(ref int val)
{
    val *= 7;
}

int importantValue = 6;
Foo(ref importantValue);
return importantValue;
// => 42
```

- `ref` 매개변수는 변수여야 해요. 호출된 메서드가 호출한 쪽이 보는 바로 그 매개변수를 직접 다루기 때문이에요.

- `out`과 `ref` 한정자는 호출된 메서드의 시그니처와 호출하는 곳 양쪽 모두에 필요해요.
- `out` 매개변수는 호출하는 곳에서 바로 선언할 수 있어요. 예를 들어 `Foo(out int importantValue);`처럼요.
- `out` 매개변수를 가진 메서드를 호출하는데 그중 하나 이상에 대입되는 값에 관심이 없다면, [무시][discard] 더미 변수 `_`를 사용할 수 있어요. 예를 들어 `Foo(out int _);`처럼요.

`ref`와 `out` 매개변수에 관한 모든 규칙은 컴파일러가 강제해요.

[`in`][in-parameter] 매개변수도 있지만, 주로 성능 최적화를 위한 것이고 가장 관련이 깊은 `structs` 연습 문제에서 다뤄요.

위에서 링크한 문서를 아래에 요약했어요:

- [매개변수 전달][passing-parameters]: 값을 어떻게 인자로 전달할 수 있는지 설명해요. 구조체와 매개변수라는 주제는 `structs` 연습 문제에서 다룬다는 점에 유의해요.
- [ref 매개변수][ref-parameter]: `ref` 매개변수가 어떻게 동작하는지 설명해요.
- [out 매개변수][out-parameter]: `out` 매개변수가 어떻게 동작하는지 설명해요.

문서를 공부할 때 다음 용어를 사용한다는 점에 유의해요:

- 매개변수 / 형식 매개변수: 호출된 메서드가 보는 매개변수를 가리켜요.
- 인자: 호출한 쪽이 보는 매개변수를 가리켜요.

[어찌 보면][so-tuples-vs-out] C# 7에 `tuples`가 도입되면서 `out` 매개변수의 가치 대부분은 사라졌어요. `tuples` 연습 문제에서는 여러 값을 반환할 때 `tuples`를 사용하는 모습을 볼 수 있어요.

`ref`는 사용하기 쉽고 성능 저하도 없지만, 널리 쓰기 전에 그것이 해결하려는 문제를 특정 코드베이스에서 어떻게 다루는지 살펴볼 만해요. 값으로 전달한 뒤 호출된 메서드의 반환문에서 값을 사용하는 것 같은 대안도 있어요. 여기서도 `tuples`가 역할을 할 수 있어요.

[문서][ref-parameter]를 보면 `out`과 `ref`를 특정 상황에서는 사용할 수 없다는 것을 알 수 있지만, 지금은 무시해도 돼요. 그런 상황이 생기면 컴파일러가 알려줄 거예요.

`optional parameters`와 `named arguments`는 `method-overloading` 연습 문제에서 다룬다는 점에 유의해요.

관련 주제인 [`ref local`][ref-local]과 [`ref return`][ref-return]은 다른 곳에서 다뤄요.

## 스택 할당

매개변수와 그 한정자에 관한 규칙은 충분히 단순해서, 액면 그대로 받아들이고 그 추상화 수준에서 이해해도 돼요. 하지만 그 밑에 깔린 메커니즘과, 적어도 `struct`의 경우에는 이 키워드들이 왜 성능 차이를 만들 수 있는지에 관심이 있다면, 이 [_위키백과 문서_][calling-conventions]부터 시작해 볼 수 있어요. C#은 x86/64에서 `stdcall`을 사용한다는 점에 유의해요.

핵심은 이래요. 한정자가 없는 매개변수의 경우 변수의 **값**이 호출된 루틴에서 쓸 수 있도록 프로그램의 스택에 복사돼요. 반면 `ref`, `out`, `in` 매개변수의 경우에는 값을 담고 있는 메모리에 대한 포인터(**참조**)가 프로그램의 스택에 놓이고, 값은 그 참조가 가리키는 메모리에 대입돼요.
