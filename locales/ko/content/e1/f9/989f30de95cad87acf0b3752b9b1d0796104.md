# 개요

[조건문][conditionals-concept] 개념에서는 조건에 따라 분기하는 명령어 계열인 `jcc`를 소개해요.
`jcc`는 조건이 충족될 때만 실행 흐름을 프로그램의 다른 지점으로 옮겨요.

그런데 최신 CPU는 빠르고, 여러 명령어를 병렬로 실행할 수 있어요.
CPU가 조건을 런타임에 검사하느라 기다리는 동안 모든 작업을 멈춰 세우는 것은 비용이 너무 많이 들어요.

그래서 CPU는 내부적으로 기다리지 않아요.
대신 [분기 예측기][branch-predictor]를 사용해 조건의 결과를 추측하고, 예측한 경로를 _추측 실행_하기 시작해요.

예측이 맞으면 분기가 없었던 것처럼 실행이 이어져요.
반대로 예측이 틀리면 CPU는 예측한 경로에서 _했던 작업을 버리고_ 올바른 경로에서 다시 시작해야 해요.

이것을 **분기 예측 실패**라고 하며, 지연을 일으키기 때문에 비용이 커요.

분기를 예측하기 어려우면 이런 예측 실패가 쌓여요.
그런 경우에는 분기를 아예 피해서 조건과 상관없이 같은 명령어가 실행되도록 하는 편이 더 나을 때가 있어요.
`jcc` 없이 값들 중에서 선택하는 코드를 **분기 없는 코드**라고 해요.

코드를 구성해서 분기가 덜 일어나게 하거나, 분기가 일어나더라도 더 예측하기 쉽게 만드는 방법은 여러 가지가 있어요.
특히 x86-64는 분기 없는 코드를 작성할 때 흔히 쓰이는 두 가지 명령어 계열을 제공해요.

## 조건부 이동

[cmovcc][cmov] 명령어 계열은 특정 조건이 충족될 때만 소스 피연산자를 대상 피연산자로 복사해요.
그렇지 않으면 대상은 그대로 유지돼요.

`cc` 접미사는 `jcc`와 같은 이름 규칙을 따르고, 의미도 같아요:

| 명령어  | 이동 조건                            |
|---------|--------------------------------------|
| `cmove` | `cmp A, B` 후 A == B                 |
| `cmovne`| `cmp A, B` 후 A != B                 |
| `cmovl` | `cmp A, B` 후 A < B (부호 있음)      |
| `cmovb` | `cmp A, B` 후 A < B (부호 없음)      |
| `cmovg` | `cmp A, B` 후 A > B (부호 있음)      |
| `cmova` | `cmp A, B` 후 A > B (부호 없음)      |

규칙은 `jcc`와 비슷해요:

1. `l`과 `g`는 부호 있는 비교에, `b`와 `a`는 부호 없는 비교에 사용해요.
2. 접미사에 `e`를 더하면 같음을 포함해요.
3. 접미사에 `n`을 더하면 조건을 부정해요.
4. 플래그가 설정된 상태를 가리키는 변형도 있어요.
   예를 들어 `cmovz`와 `cmovc`가 있어요.

`rdi`에 있는 부호 있는 정수의 절댓값을 `rax`에 반환하는 경우를 생각해 봐요.
`jcc`로 작성하면 함수는 두 경로 중 하나를 선택해요:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

`cmovcc`로 작성하면 두 후보 값을 조건 없이 모두 계산하고, 조건부 이동이 그중 하나를 골라요:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; if rdi >= 0, rax = rdi
                       ; otherwise rax stays = -rdi
    ; now rax = abs(rdi)
    ret
```

분기 없는 버전은 항상 같은 명령어를 실행해요.
예측기가 추측할 `jcc`가 없어요.

`cmovcc`의 대상은 레지스터여야 해요.
소스는 레지스터나 메모리 위치일 수 있지만, 즉시값은 될 수 없어요.

~~~~exercism/note
위 코드에서 `neg` 명령어는 결과에 따라 여러 플래그를 설정하는데, 부호 플래그(SF)도 그중 하나예요.
따라서 `cmp rdi, 0`은 아예 없앨 수 있어요:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF = 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

`rdi`가 양수이면 `neg`는 음수 결과를 만들어 SF = 1이 되고, 그래서 `cmovs`가 `rdi`를 복원해요.
`rdi`가 0이거나 음수이면 `neg`는 음수가 아닌 결과를 만들어 SF = 0이 되고, 그래서 `rax`는 부정된 값(올바른 절댓값)을 그대로 유지해요.

어셈블리 코드에서 값을 비교하는 주된 방법은 `cmp`지만, 많은 명령어가 자신의 결과에 따라 플래그를 설정하기도 해요.
어떤 명령어가 영향을 주는 플래그의 전체 목록은 보통 그 명령어의 [레퍼런스][reference]에 나와 있어요.
`neg`의 경우에는 SF, ZF, CF, OF, PF예요.

[reference]: https://www.felixcloutier.com/x86/
~~~~

## 조건부 설정

[setcc][set] 명령어 계열은 특정 조건이 충족되면 대상 피연산자를 `1`로, 그렇지 않으면 `0`으로 설정해요.
대상은 항상 _8비트 피연산자_예요.

`cc` 접미사는 `jcc`와 `cmovcc`에서와 같은 이름 규칙을 따라요.
예를 들어 `setz`는 `ZF == 1`이면 대상을 `1`로, 그렇지 않으면 `0`으로 설정해요.

대상이 8비트이기 때문에, 더 넓은 값이 필요할 때는 `setcc` 뒤에 `movzx` 명령어를 쓰는 경우가 많아요:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

비교 결과를 정수 `0`이나 `1`로 바꾸는 흔한 관용구예요.

## 분기 없는 코드를 사용할 때

분기 없는 코드가 항상 분기 있는 코드보다 빠른 것은 아니에요.
분기를 거의 확실하게 예측할 수 있으면 예측기가 거의 항상 맞고, `jcc`는 사실상 비용이 들지 않아요.
그런 분기를 대체하는 분기 없는 코드는 오히려 더 느려요. 두 후보 계산을 항상 모두 실행하기 때문이에요.

대표적인 예가 루프 카운터예요.
`rdi`에서 시작하는 64비트 정수 `rsi`개를 모두 더하는 함수를 생각해 봐요:

```x86asm
sum_array:
    xor rax, rax
.loop:
    add rax, [rdi]
    add rdi, 8
    dec rsi
    jnz .loop          ; taken on every iteration except the last
    ret
```

이런 패턴이 바로 분기 예측기가 잘 처리하는 유형이라서, `sum_array`가 원소를 몇 개 처리하든 분기는 사실상 공짜예요.

분기 없는 코드는 분기를 예측하기 어려울 때, 또는 입력과 상관없이 일정한 실행 시간이 필요할 때 효과를 봐요.
