# 소개

TypeScript는 타입을 위한 문법을 갖춘 JavaScript예요. 그래서 엄격한 타입 시스템을 갖춘 프로그래밍 언어이고, 객체 지향, 명령형, 선언형(예: 함수형 프로그래밍) 스타일을 지원하며, 어떤 규모에서든 더 나은 도구 지원을 받을 수 있게 해줘요.

[JavaScript를 배우지 않고는 TypeScript를 배울 수 없기][handbook-js-or-ts] 때문에, 이 트랙의 내용 중 일부는 JavaScript 개념을 가르치는 데 집중하고, 일부 개념은 TypeScript만의 기능에 초점을 맞춰요.

## (재)할당

TypeScript에서 이름에 값을 할당하는 방법은 크게 몇 가지가 있어요. 변수를 쓰는 방법과 상수를 쓰는 방법이에요.
Exercism에서는 변수를 항상 [camelCase][wiki-camel-case]로 쓰고, 상수는 [SCREAMING_SNAKE_CASE][wiki-snake-case]로 써요.
꼭 따라야 하는 공식 가이드가 있는 건 아니고, 회사나 조직마다 스타일 가이드가 달라요.
_변수는 원하는 방식으로 자유롭게 써도 돼요_.
연습 문제에서 준비한 방식대로 변수를 쓰면, 웹 인터페이스와 대부분의 IDE에서 다르게 강조 표시된다는 장점이 있어요.

TypeScript에서 변수는 [`const`][mdn-const], [`let`][mdn-let], [`var`][mdn-var] 키워드로 정의할 수 있어요.

`let`이나 `var`로 선언한 변수는 살아 있는 동안 여러 값을 가리킬 수 있어요.
예를 들어 `myFirstVariable`은 할당 연산자 `=`를 사용해 여러 번 정의하고 다시 정의할 수 있어요:

```typescript
let myFirstVariable = 1
myFirstVariable = 0
myFirstVariable = 42
```

`let`과 `var`와 달리, `const`로 정의한 변수는 한 번만 할당할 수 있어요.
TypeScript에서는 이렇게 상수를 정의해요.

```typescript
const MY_FIRST_CONSTANT = 10

// Can not be re-assigned.
MY_FIRST_CONSTANT = 20
// => TypeError: Assignment to constant variable.
```

TypeScript는 이를 정적으로 감지할 수 있기 때문에, TypeScript 컴파일러도 오류를 내요:

```typescript
// ^? Cannot assign to 'MY_FIRST_CONSTANT' because it is a constant.(2588)
```

즉, `TypeError`를 찾기 위해 코드를 실행할 필요가 없어요.

## 타입 추론

[타입 추론][handbook-type-inference]에 너무 깊이 들어가지 않고도 알아 둘 점은, 할당된 변수는 보통 타입 애너테이션이 없어도 추론된 타입을 가진다는 거예요.

```typescript
const MY_FIRST_CONSTANT = 10
// ^? const MY_FIRST_CONSTANT: number
```

그러면 이 타입이 코드 전체에서 강제돼요.
덕분에 다음 코드가 JavaScript에서는 유효해도:

```javascript
let myFirstVariable = 1
myFirstVariable = 'Some string'
```

TypeScript에서는 오류를 내요:

```typescript
let myFirstVariable = 1
myFirstVariable = 'Some string'
// ^? Type 'string' is not assignable to type 'number'.(2322)
```

이 기능 덕분에 타입 애너테이션을 쓰지 않아도 타입 안전성이 보장돼요.

## 함수 선언

TypeScript에서는 기능 단위를 _함수_로 묶어요. 보통 서로 관련 있는 함수라면 같은 파일에 모아 둬요.
함수는 매개변수(인자)를 받을 수 있고, `return` 키워드로 값을 _반환_할 수 있어요.
함수는 `()` 문법으로 호출해요.

```typescript
function add(num1: number, num2: number): number {
  return num1 + num2
}

add(1, 3)
// => 4
```

함수 매개변수에는 보통 콜론(`:`) 뒤에 타입을 적는 방식으로 타입 애너테이션을 붙여요.
함수의 반환 값에는 매개변수 목록을 닫은 뒤 콜론(`:`) 뒤에 타입을 적어 애너테이션을 붙일 수 있어요.

~~~~exercism/note
💡 TypeScript에서는 함수를 선언하는 방법이 _아주 여러 가지_예요.
다른 방법들은 `function` 키워드를 쓰는 것과는 모양이 달라요.
이 트랙에서는 이런 방법들을 차근차근 소개하려고 하지만, 이미 알고 있다면 어떤 방법을 써도 좋아요.
대부분의 경우 어느 쪽을 쓰든 더 낫거나 나쁘지 않아요.
~~~~

## 타입 애너테이션

`add`의 함수 선언에서 볼 수 있듯이, 매개변수에는 명시적인 타입 애너테이션 `: number`가 붙어 있어요.
변수 선언, 클래스 속성, 함수 선언 등 다양한 곳에서 타입 애너테이션을 지원해요.

명시적인 타입 애너테이션이든 추론된 타입이든 모두 타입 검사기가 강제해요.

```typescript
add('foo', 3)
// ^? Argument of type 'string' is not assignable to parameter of type 'number'.(2345)
```

## 다른 파일에 공개하기

`function`, 상수, 변수를 _다른 파일_에서 쓸 수 있게 하려면 `export` 키워드로 [내보내야][mdn-export] 해요.
그러면 다른 파일에서 `import` 키워드로 이들을 [가져올][mdn-import] 수 있어요.
이런 방식을 모듈 시스템이라고도 해요.
좋은 예가 모든 테스트가 동작하는 방식이에요.
각 연습 문제에는 최소한 하나의 파일이 있고, 예를 들어 `lasagna.ts`에는 _구현_이 담겨 있어요.
또한 최소한 하나의 다른 파일이 있는데, 예를 들어 `lasagna.test.ts`에는 _테스트_가 담겨 있어요.
이 파일은 구현을 테스트하기 위해 공개된(즉, 내보낸) 요소를 _가져와요_:

```typescript
// file.ts
export const MY_VALUE = 10

export function add(num1, num2) {
  return num1 + num2
}

// file.test.ts
import { MY_VALUE, add } from './file.js'

add(MY_VALUE, 5)
// => 15
```
