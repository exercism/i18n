# 소개

## 꼬리 호출 최적화

함수가 호출될 때마다 함수의 인자와 지역 변수를 저장하기 위해 메모리에 새로운 스택 프레임이 생성되고, 함수가 반환되면 이 스택 프레임은 해제돼요. Gleam은 반복문 문법 대신 재귀 함수 호출을 사용하기 때문에 이런 스택 프레임으로 인해 많은 메모리가 사용될 수 있어요.

이 문제를 피하기 위해 Gleam은 꼬리 호출 최적화를 지원해요. 이는 함수 호출이 함수가 하는 마지막 작업일 때 컴파일러가 현재 함수의 스택 프레임을 재사용할 수 있게 해줘요. 즉, 함수는 추가 메모리를 사용하지 않고 무한히 자신을 호출할 수 있어요.

최적화되지 않은 재귀 함수는 종종 _누산기_를 사용해 꼬리 호출 최적화된 함수로 다시 작성할 수 있어요.

누산기는 데이터에 추가로 함께 전달되는 변수예요. 기저 사례에 도달할 때까지 함수 실행의 현재 상태를 전달하는 데 사용돼요.

누산기는 함수의 사용자가 아니라 함수 작성자가 초기화해야 해요. 이를 위해 두 개의 함수를 선언해요. 필요한 데이터만 인자로 받고 누산기를 초기화하는 공개 함수와, 누산기도 함께 받는 비공개 함수예요.

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
