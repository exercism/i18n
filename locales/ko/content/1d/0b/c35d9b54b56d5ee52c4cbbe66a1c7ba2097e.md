# 자세히 알아보기

C#에서는 _상속_을 사용해 _클래스_ 계층 구조를 정의할 수 있어요. 상속을 사용하면 파생 클래스(`Car`)가 부모 클래스(`Vehicle`)의 동작과 데이터를 물려받을 수 있죠. 부모 클래스를 지정하지 않으면 `object` 클래스를 상속받아요.

부모 클래스는 세 가지 방식으로 파생 클래스에 기능을 제공할 수 있어요.

- 일반 메서드를 정의해요.
- [`virtual` 메서드][virtual-keyword]를 정의해요. `virtual` 메서드는 일반 메서드와 비슷하지만, 파생 클래스가 _바꿀 수 있는_ 메서드예요.
- [`abstract` 메서드][abstract-keyword]를 정의해요. `abstract` 메서드는 구현이 없고 파생 클래스가 _반드시_ 구현해야 하는 메서드죠. `abstract` 메서드가 있는 클래스도 [`abstract`][abstract-classes]로 표시해야 해요. 추상 클래스는 인스턴스로 만들 수 없어요.

[`protected` 접근 한정자][protected-keyword]를 사용하면 부모 클래스의 멤버에 파생 클래스에서 접근할 수 있지만, 다른 클래스의 접근은 막아요. 따라서 파생 클래스는 부모 클래스의 `public` 및 `protected` 멤버에는 접근할 수 있지만, `private` 멤버에는 접근할 수 없어요.

파생 클래스는 [`base` 키워드][base-keyword]를 통해 부모 클래스의 멤버에 접근할 수 있어요.

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

// Cannot be inherited from
sealed class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

파생 클래스의 생성자는 자신의 생성자 로직을 실행하기 _전에_ [부모 클래스의 생성자를 자동으로 호출][constructors]해요. [`base` 키워드][base-keyword-constructor]를 사용하면 부모 클래스의 생성자에 인자를 전달할 수 있어요. 추상 클래스는 인스턴스로 만들 수 없으므로 생성자를 `protected`로 만들 수 있어요.

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

기반 클래스에서 둘 이상의 클래스가 파생되면, 두 개 이상의 하위 클래스가 기반 클래스 메서드를 서로 다른 버전으로 구현하는 경우가 많아요. 이것이 [다형성][polymorphism]이라는 아주 중요한 원리예요. 예를 들어 위 예제를 변형한 다음 코드는 `Vehicle`을 사용하는 코드가 인스턴스화된 vehicle의 종류에 따라 동작을 바꿀 수 있음을 보여줘요.

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```

클래스가 상속되는 것을 막으려면 [`sealed` 한정자][sealed-classes]를 추가해요. 일부 실무자는 구체 클래스에서 상속받는 것을 피하려고 하는데([이 SO 질문][pro-sealed]에서 다뤄요), _sealed_ 한정자가 이런 접근 방식을 뒷받침해요. 반면 많은 C# 개발자는 [이 질문][anti-sealed]의 여러 댓글에서 논의하듯이 이를 유지보수에 방해가 된다고 봐요. 요구 사항에 맞게 사용할 자신이 생길 때까지는 sealed 한정자를 아껴 쓰라는 것이 권고예요.

다음 [글][new-vs-override]에서는 `override` 한정자의 대안으로 `new`를 설명해요. 이는 복잡하게 얽힌 클래스 계층 구조나 라이브러리 간의 충돌이 있을 때 가끔 유용해요.
