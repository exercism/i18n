# 테스트

각 연습 문제는 단위 테스트와 CMake 빌드 레시피를 제공해요. 구현은 직접 작성해요.
각 테스트 파일은 여러분의 구현과 링크되어, 테스트를 실행하는 콘솔 실행 파일을 만들어요. 테스트 실행 파일을 실행하면 실패한 테스트마다 메시지를 출력하고, 테스트가 실패하면 0이 아닌 종료 상태를 보고해요.

테스트 파일의 이름은 `<exercise>_test.f90`이에요. 따라서 "Bob" 연습 문제에서 테스트가 들어 있는 파일은 `bob_test.f90`이에요. 각 테스트에는 테스트를 설명하는 주석이 있고, 그다음에 `call assert_equal`로 시작하는 실제 테스트가 있어요. 예를 들면:

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

테스트를 비활성화하려면 `'!'`로 주석 처리하기만 하면 돼요. 예를 들면:

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

각 연습 문제를 진행하는 과정은 다음과 같아요:

* CMake로 초기 빌드 만들기
* 각 단위 테스트마다:
 * 컴파일 오류를 해결해서 테스트가 실패하도록 만들어요.
 * 테스트가 통과할 만큼만 구현해요.
 * 가독성을 높이고 중복을 줄이는 등 구현을 리팩터링해요.
 * 다음 테스트의 주석을 해제해요.


## CMake로 초기 빌드 만들기

각 연습 문제에는 단위 테스트와 함께 `CMakeLists.txt` 파일이 들어 있어요. 이 파일에는 빌드를 대신 처리해 주는 미리 만들어진 CMake 레시피가 담겨 있어요. 이 파일은 수정할 필요가 없어요. 제공된 레시피는 구현이 연습 문제의 이름을 딴 소스 파일에 있다고 가정해요.

예를 들어 "Bob" 연습 문제는 `bob.f90` 파일에 구현이 있기를 기대해요.

**CMake를 실행하기 전에 초기 구현 파일을 만들어 두세요.**
"Bob" 연습 문제에서 CMake를 실행할 때 `bob.f90` 파일이 없으면, CMake는 파일을 찾을 수 없다는 오류를 발생시켜요.
**이 파일은 비어 있어도 되지만, 반드시 존재해야 해요.**

이 레시피를 사용하면, 적절한 제너레이터와 연습 문제 디렉터리의 위치를 지정해 `cmake -G`를 실행함으로써 환경에 맞는 프로젝트를 생성할 수 있어요. CMake는 운영 체제에 맞는 빌드 스크립트를 만들어요. 생성된 파일을 연습 문제 소스 코드와 분리해 두려면, 생성된 빌드 파일과 컴파일된 코드를 담을 `build`라는 디렉터리를 만드는 것이 일반적이에요.

이렇게 하면 연습 문제 폴더를 깔끔하게 유지할 수 있어요.

**참고: `cmake`를 처음 호출하면 [testlib](###-Testlib)가 자동으로 다운로드돼요. `testlib`는 단위 테스트가 작동하는 데 필요해요.

각 과제마다 빌드 지침을 만들기 위해 CMake를 실행하게 되니, 이 명령을 위한 bash 스크립트(Linux/MacOS)나 배치 파일(Windows)을 만들어 두는 것도 좋아요.

CMake가 빌드 환경을 만들어 주면, 환경에 맞는 명령으로 코드를 빌드할 수 있어요:

* make를 사용하는 Linux: `make`
* Visual Studio를 사용하는 Windows: 메뉴에서 Build / Build Solution을 선택해요.
* MingW를 사용하는 Windows: `mingw32-make.exe`
* nMake를 사용하는 Windows: `nmake.exe`
* Xcode를 사용하는 MacOS: 툴바에서 Build를 선택해요.

다양한 환경에서 CMake를 실행하는 예시는 아래와 같아요.

### Make를 사용하는 Linux\MacOS

CMake의 제너레이터 이름은 `Unix Makefiles`예요.
현재 연습 문제가 `bob`이고 연습 문제 폴더에 있다고 가정해요:

```
$ touch bob.f90
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

이 예시는 CMake를 실행하기 전에 구현을 위한 빈 파일을 만드는 방법을 보여줘요.

테스트를 컴파일하려면 build 디렉터리에서 make를 입력하기만 하면 돼요. 그러면 컴파일 시점 오류가 발생할 거예요. 오류를 고친 뒤 `make`를 다시 실행해요. 모든 빌드 오류를 고쳤으면 테스트를 실행해요:

```
$ ctest -V
```
### Visual Studio 2017을 사용하는 Windows

CMake의 제너레이터 이름은 `Visual Studio 15`예요. 같은 제너레이터가 Visual Studio 2017의 모든 IDE 에디션(Community, Professional, Enterprise)을 지원해요. 현재 연습 문제가 `bob`이고 연습 문제 폴더에 있다고 가정해요:

```
> copy nul: bob.f90
> mkdir build
> cd build
> cmake -G "Visual Studio 15" ..
```

이 예시는 CMake를 실행하기 전에 구현을 위한 빈 파일을 만드는 방법을 보여줘요.

### Testlib

테스트는 `testlib`라는 작은 라이브러리에 의존하는데, 이 라이브러리는 cmake로 빌드를 처음 구성할 때 github에서 다운로드돼요.

다운로드가 실패하면 직접 다운로드할 수도 있어요. 예를 들면:

```
mkdir testlib
cd testlib
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/CMakeLists.txt
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/TesterMain.f90
```
