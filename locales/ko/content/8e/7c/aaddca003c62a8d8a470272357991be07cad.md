# C 스타일 가이드

이 가이드는 C 트랙 연습 문제의 예제 파일과 테스트 파일에 사용할 스타일을 설명해요.

이 가이드의 규칙은 [.clang-format][] 파일이 정한 규칙에 더하는 것이거나, 그 규칙을 짚어 주는 것이에요.

## C 표준

코드는 C99 표준, 공식 명칭으로 ISO/IEC 9899:1999를 따라야 해요.
POSIX나 그 밖의 비표준 라이브러리 함수, 타입, 또는 구현 외부를 가리키는 다른 참조는 사용하지 않아요.

## 이름

일반적으로 타입, 변수, 구조체, 파일의 이름은 스네이크 케이스를 사용하고, 모든 글자를 소문자로 쓰며, 이름의 구성 요소는 밑줄 `_`로 구분해요.

```c
void some_foo_function(char * input_string, int input_string_length);
```

### 열거형

열거형 이름은 보통 복수형보다 단수형을 써요.

열거형 레이블은 스네이크 케이스를 사용하고 모든 글자를 대문자로 써요.

```c
enum heading {
    HEADING_NORTH,
    HEADING_EAST,
    HEADING_SOUTH,
    HEADING_WEST
}
```

### 매크로

상수를 정의하는 매크로는 스네이크 케이스를 사용하고 모든 글자를 대문자로 써서 이름을 지어요.

```c
#define CONSTANT 0x4000
```

매크로 이름에 대문자 스네이크 케이스를 쓰면 좋지만, 함수처럼 동작하는 매크로는 소문자 스네이크 케이스로 이름을 지어도 돼요.

### 타입

기본 정수 타입보다 표준 고정 너비 타입(`stdint.h`에 있는)을 선호해요.

`_Bool`보다 `stdbool.h`의 `bool` 타입을 선호해요.

마찬가지로 메모리와 관련된 양을 나타낼 때는 `stddef.h`의 `size_t`와 `ptrdiff_t`를 선호해요.

프로그램에서 `typedef`로 정의한 타입은 `_t` 접미사를 붙여 이름을 지어요.
POSIX가 `_t` 접미사를 예약해 두고 있다는 점은 알고 있지만, 이 트랙은 현재 POSIX를 사용하지 않아요.

## 인클루드 가드

모든 헤더 파일에는 인클루드 가드를 사용해요.

일반적으로 인클루드 가드 한 세트가 헤더의 전체 내용을 감싸요.

예시 구현(`.meta/example.h`)과 연습 문제 스텁(`exercise_name.h`)의 가드는 연습 문제 이름을 따르는 매크로 이름을 사용해요.
가드 매크로 이름은 위의 매크로 대소문자 규칙을 따라요.

예를 들어 `hello-world` 연습 문제에서는 이렇게 써요:

```c
#ifndef HELLO_WORLD_H
#define HELLO_WORLD_H

//...

#endif
```

## 매개변수

모든 함수는 선언과 정의 모두에서 매개변수에 이름을 붙여요.
이는 `.c` 파일과 `.h` 파일 모두에 적용돼요.
사용하는 이름은 모든 곳에서 일치해야 해요.
즉, 다음 함수 원형은 유효한 C이지만 매개변수에 이름이 없어서 스타일에 맞지 않아요: `void foo(int);`.
다른 모든 선언과 정의에서도 매개변수 이름으로 `bar`를 쓴다면, 올바른 원형은 `void foo(int bar);`예요.

더 간단하거나 더 적절한 경우에는 포인터가 아니라 값으로 인자를 전달하는 매개변수를 선호해요.
특히 여기에는 `struct` 타입 매개변수도 포함된다는 점에 주의해요.

학생이 구현에서 포인터 타입 매개변수의 값을 바꾸지 않아도 되는 경우에는 그 매개변수에 `const`를 붙여요.

## 테스트 파일 구성

각 연습 문제의 테스트 파일은 정해진 구성을 따라요.
이 구성은 기여자가 파일의 각 부분을 알아보기 쉽게 하고, 학습자가 테스트가 어떻게 동작하는지 이해하도록 돕기 위한 것이에요.

대부분의 C 소스 파일처럼, 테스트 파일은 인클루드로 시작해요.

```c
#include "vendor/unity.h"
#include "../src/file_under_test.h"
// any other includes here
```

인클루드 다음에는 `setUp()`과 `tearDown()` 함수가 와요.
지금까지 이 함수들을 사용하는 연습 문제는 없지만(함수 본문이 비어 있어요), 모든 플랫폼에서 테스트 파일이 올바르게 컴파일되도록 이 함수들은 그대로 남아 있어야 해요.

```c
void setUp(void)
{
}

void tearDown(void)
{
}
```

그다음에는 테스트 함수에서 사용하는 도우미 함수가 와요.
이런 도우미 함수의 이름에는 `test_` 접두사를 붙이지 않아요.

그다음은 테스트 함수 자체예요.
이 함수들의 이름에는 `test_` 접두사를 붙여요.
첫 번째 테스트 함수를 제외하고, 각 테스트 함수는 첫 번째 문으로 `TEST_IGNORE();`를 가져야 해요.
이것이 처음 나오는 곳에는 그다음 줄에 `// delete this line to run test` 줄 주석이 와야 해요.

예를 들면 이래요:

```c
static void test_the_first(void)
{
   test_first_foo();
}

static void test_the_second(void)
{
   TEST_IGNORE();               // delete this line to run test
   test_second_foo();
}

static void test_the_third(void)
{
   TEST_IGNORE();
   char grade = 'A';
   test_third_foo(grade);
}
```

파일의 마지막에는 `main()` 함수가 와요.
main 함수의 본문도 그 자체로 정해진 구성을 따라요.
먼저 `UNITY_BEGIN()` 호출이 오고 그 뒤에 빈 줄, 그다음에 테스트가 와요.
마지막 테스트 뒤에는 빈 줄이 하나 더 오고, 그다음에 `UNITY_END()`의 결과를 반환해요.

```c
int main(void)
{
    UNITY_BEGIN();

    RUN_TEST(test_foo);
    RUN_TEST(test_bar);

    return UNITY_END();
}
```
