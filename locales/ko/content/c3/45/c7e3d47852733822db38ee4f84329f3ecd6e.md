# 소개

대부분의 경우 Factor는 `each`, `map`, `count` 같은 컴비네이터를 통해 반복을 처리해요. 하지만 때로는 계산을 가장 깔끔하게 표현하는 방법이 **재귀**, 즉 자기 자신을 호출하는 단어예요.

## 재귀 단어 정의하기

`:` 정의는 자기 자신을 직접 호출할 수 있어요.

```factor
: count-down ( n -- )
    dup 0 = [ drop ] [ dup . 1 - count-down ] if ;

5 count-down
! prints 5 4 3 2 1
```

## 비었는지 아닌지 분기하기

`if-empty`([`sequences`][sequences]에 있어요)는 재귀의 자연스러운 기저 조건이에요.

```
if-empty ( seq emptyquot nonemptyquot -- )
```

```factor
{ 4 0 9 } [ "empty" ] [ "got data" ] if-empty .
! => "got data"
```

`emptyquot`는 (비어 있는) 시퀀스가 이미 소비된 상태로 실행되고, `nonemptyquot`는 시퀀스가 아직 스택에 남아 있는 상태로 실행돼요.

## `cond`, 조건부 분기들의 연쇄

재귀에 두 가지가 넘는 경우가 있을 때는 [`combinators`][combinators]에 있는 `cond`를 쓰면 코드를 읽기 좋게 유지할 수 있어요.

```factor
: classify ( n -- label )
    {
        { [ dup 0 < ] [ drop "negative" ] }
        { [ dup 0 = ] [ drop "zero"     ] }
        [ drop "positive" ]
    } cond ;
```

## `DEFER:`로 순방향 참조하기

`:` 정의는 자기 자신을 직접 호출할 수 있지만, 두 단어가 *서로를* 호출할 때는 파서가 두 번째 단어가 존재하기 전에 첫 번째 단어를 먼저 보게 돼요. `DEFER:`는 이름을 미리 잡아 두어 첫 번째 정의가 컴파일될 수 있게 해줘요.

```factor
DEFER: even?

: odd? ( n -- ? ) dup 0 = [ drop f ] [ 1 - even? ] if ;
: even? ( n -- ? ) dup 0 = [ drop t ] [ 1 - odd? ] if ;
```

`DEFER:`는 도우미 단어를 그것을 사용하는 단어 *뒤에* 두는 편이 더 자연스러울 때도 유용해요.
