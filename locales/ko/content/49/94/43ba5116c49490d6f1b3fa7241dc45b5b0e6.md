# 소개

스칼라 코드는 특정 조건에 따라 분기하려고 여러 명령어가 설정한 플래그에 의존해요.
그런데 패킹된 값은 값을 하나가 아니라 여러 개를 병렬로 나타내요.
하나의 조건이 어떤 레인에서는 성립하지 않고 다른 레인에서는 성립할 수 있어요.

그래서 SIMD 코드는 기본적으로 _분기 없이_ 동작해요.

플래그에 의존하는 대신, 패킹된 비교는 보통 목적지 피연산자에 **마스크**를 만들어요.
각 레인마다, 비교는 조건이 참이면 레인 전체를 1로 채우고 거짓이면 0으로 채워요.
부호 있는 정수로 읽으면 참인 레인은 `-1`, 거짓인 레인은 `0`이에요.

이 마스크는 그다음 비트 연산과 조합해서 특정 레인만 걸러내는 데 쓸 수 있어요.

## 패킹된 비교

스칼라 `cmp`는 여러 플래그를 한꺼번에 설정하는 데 쓰인다는 점에서 범용적이에요.
그러면 다른 명령어가 그 플래그를 받아서 분기하거나 계산을 수행할 수 있어요.

하지만 패킹된 비교는 조건을 확인하는 동시에 마스크를 계산하기 때문에 범용적이지 않아요.
비교에는 검사할 조건을 정확히 지정해야 해요.

방법은 두 가지예요:

- 정수 비교는 조건을 접미사로 받아요: 같음은 `eq`, 큼은 `gt`예요.
  다른 변형은 이중 하나의 결과를 조합해서 만들어요.
- 부동소수점 비교는 조건을 즉시값에 인코딩해서 받아요.
  이 즉시값의 값에 따라 검사하는 조건이 달라져요.

정수 비교에 특정 조건 접미사를 붙이는 점을 빼면, 문법은 앞서 본 것과 같은 구조를 따라요:

- 정수의 경우, `p` + `cmp` + 조건 + 크기(`b`, `w`, `d` 또는 `q`).
- 부동소수점의 경우, `cmp` + `p` + 크기(`s` 또는 `d`).
  조건은 추가 피연산자로 즉시값에 담아 전달해요.

### 정수 비교

앞서 말했듯이 정수 비교에는 같음과 큼만 있어요:

| 명령어                                     | 설명                             |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | 레인별 같음                      |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | 레인별 **부호 있는** 큼          |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

미만 비교를 만들려면 `gt`를 쓰면서 피연산자를 서로 바꿔요: `a < b` == `b > a`.

비교가 **부호 있는** 비교라는 점에 주의해요.
부호 없는 비교를 하려면 두 피연산자의 최상위 비트를 뒤집어요.
최상위 비트만 설정된 마스크와 XOR하면 돼요.

~~~~exercism/note
유용한 관용구 두 가지가 있어요:

1. 레지스터를 자기 자신과 XOR해서 모두 0으로 만들기.
2. 레지스터를 자기 자신과 비교해서 모두 1로 만들기.

예를 들어:

```x86asm
pxor xmm4, xmm4    ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

모두 0과 모두 1은 각각 "모든 곳에서 거짓"과 "모든 곳에서 참"을 인코딩하는 흔한 마스크예요.
패킹된 `0`이나 패킹된 `-1`을 나타내는 데도 쓸 수 있는데, 둘 다 흔한 센티널 값이에요.
예를 들어 문자열의 끝을 표시하는 NUL은 `0`이에요.
~~~~

### 부동소수점 비교

부동소수점 레인은 모양이 달라요. 명령어 하나, `cmpps`(64비트 레인에는 `cmppd`)를 쓰고 조건은 즉시값으로 넘겨요:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM에는 올바른 즉시값으로 대응되면서 외우기 더 쉬운 의사 명령어도 있어요.
다음 모두에서 `px`의 `x`는 `s`(32비트 부동소수점)나 `d`(64비트 부동소수점)가 될 수 있어요:

| 의사 명령어  | 즉시값    | 비교                   |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | a가 NaN이거나 b가 NaN  |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | a도 b도 NaN이 아님     |

## 마스크로 선택하기

마스크는 조건의 결과를 인코딩해요.
그러면 이 마스크로 그 조건에 따라 두 값 집합 중에서 레인별로 하나를 고를 수 있어요.
마스크가 참인 레인은 한쪽 값에서 가져오고, 거짓인 레인은 다른 쪽 값에서 가져와요:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

이 패턴은 분기 없는 선택의 패킹된 형태예요.
모든 레인이 계산되고, 마스크만이 어떤 값이 살아남을지 결정해요. 어디에도 `jcc`가 없어요.

## 전용 블렌드

같은 선택을 직접 수행하는 명령어도 있는데, 마스크 레지스터에서 원소마다 비트 하나를 읽어요.
이런 명령어를 **블렌드** 명령어라고 해요:

| 명령어      | 원소        | 마스크 출처     |
|-------------|-------------|-----------------|
| `pblendvb`  | 바이트      | 암시적 `xmm0`   |
| `blendvps`  | 32비트 레인 | 암시적 `xmm0`   |
| `blendvpd`  | 64비트 레인 | 암시적 `xmm0`   |

첫 번째 명령어는 정수 문법을 따르고, 나머지 둘은 부동소수점 문법을 따른다는 점에 주의해요.
그런데 이 명령어들은 그냥 원시 바이트를 선택할 뿐이라, 어느 것이든 정수와 부동소수점 양쪽에 쓸 수 있어요.

각 원소마다, 블렌드는 대응하는 마스크 원소의 최상위 비트가 0이면 목적지를 유지하고, 1이면 소스를 가져와요.
**최상위 비트**만 참고하는데, 비교 마스크는 레인이 모두 1이거나 모두 0이라 이 조건을 만족해요.
마스크 레지스터는 언제나 `xmm0`이고, 암시적이에요:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

`pblendvb`를 써서 다른 크기의 비교 마스크에서도 레인을 선택할 수 있어요.
참인 레인의 모든 바이트가 1이므로, `pblendvb`는 그 바이트를 전부 선택해요.

~~~~exercism/note
이 명령어들은 수행하는 연산(`blend`) 뒤에 `v`를 붙여요.
이 `v`는 선택이 고정되어 있지 않고 레지스터에 따라 달라진다는 뜻에서 _가변_을 나타내요.

`v`가 없는 변형도 있는데, 이들은 즉시값에 따라 선택해요.
같은 패턴을 따라, 즉시값의 비트 `i`가 1이면 레인 `i`를 선택해요.
~~~~

## 마스크에서 다시 스칼라로

SIMD 코드는 강력하지만 스칼라 코드가 가진 유연성은 많이 부족해요.
많은 상황에서 패킹된 레지스터에서 스칼라 명령어의 세계로 다시 돌아가야 해요.

`movmsk` 명령어 패밀리는 두 세계 사이의 다리 역할을 해요.
이 명령어들은 모든 레인의 **최상위 비트**를 범용 레지스터로 추출해요:

| 명령어      | 모으는 것                     | 결과 너비 |
|-------------|-------------------------------|-----------|
| `pmovmskb`  | 16개 바이트 각각의 최상위 비트 | 16비트    |
| `movmskps`  | 4개 dword 각각의 최상위 비트   | 4비트     |
| `movmskpd`  | 2개 qword 각각의 최상위 비트   | 2비트     |

비교 뒤에 사용하면, 설정된 비트는 "참" 레인을, 지워진 비트는 "거짓" 레인을 나타내요.
이 결과는 그다음 평소처럼 스칼라 명령어로 다룰 수 있어요.
예를 들어 `popcnt`는 일치하는 개수를 세고, `tzcnt`는 첫 번째를 찾아요.

범용 레지스터는 32비트나 64비트일 수 있어요.

## 벡터 전체 검사하기

스칼라 `test` 명령어에는 패킹된 변형도 있어요: `ptest`예요.

두 피연산자 사이에 AND 연산을 수행하면서 피연산자를 수정하지 않는다는 점에서 스칼라 짝과 비슷해요.
`test`와 달리 `ptest`는 ANDN 연산도 수행해서 첫 번째 피연산자를 부정해요.

따라서 `ptest`는 결과에 따라 플래그를 설정하는, `pand`와 `pandn`의 비파괴 버전이라고 생각할 수 있어요.
이 두 명령어와 거의 같은 방식으로, `ptest`는 SIMD 레지스터 전체를 하나의 레인으로 취급하기 때문에 크기 접두사를 받지 않아요.

AND 연산의 결과가 `0`이면 `ZF`가 설정되고, ANDN 연산의 결과가 `0`이면 `CF`가 설정돼요.
즉, `ptest`로 모두 1인 마스크와 모두 0인 마스크를 모두 확인할 수 있어요:

1. 레지스터에 자기 자신을 대상으로 `ptest`를 쓰면 레지스터가 모두 0일 때만 `ZF`가 설정돼요.
   이는 `0`인지 확인하려고 레지스터에 자기 자신을 대상으로 `test`를 쓰는 흔한 스칼라 관용구를 그대로 따른 거예요.
2. 모두 1인 마스크와 함께 레지스터에 `ptest`를 쓰면 레지스터가 모두 1일 때만 `CF`가 설정돼요.
   또한 레지스터가 모두 0일 때만 `ZF`가 설정되므로, 두 마스크를 한 번에 확인할 수 있어요.

```x86asm
pxor    xmm0, xmm0   ; all zeros
pcmpeqb xmm1, xmm1   ; all ones
pcmpeqb xmm2, xmm2

ptest xmm0, xmm0     ; ZF set: a register against itself detects all zeros
ptest xmm0, xmm1     ; ZF set, CF clear: xmm0 is all zeros, not all ones
ptest xmm2, xmm1     ; CF is set only if xmm2 is all ones
```

`ptest`의 결과는 평소처럼 분기에 쓰거나 `setcc`, `cmovcc` 같은 분기 없는 명령어에 쓸 수 있어요.
