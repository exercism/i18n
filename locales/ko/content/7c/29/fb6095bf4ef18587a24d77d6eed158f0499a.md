# 개요

많은 객체 지향 언어에서는 부모 클래스를 [하위 클래스로 만들어][wiki-subclass] 부모의 메서드를 물려받으면서 새로운 메서드도 추가하는 식으로 기능을 확장하는 경우가 많아요. 이렇게 해서 객체 계층 구조가 만들어지죠.

Julia에는 _클래스가 없어요_. 따라서 _하위 클래스도 없어요_.
그렇다면 기존 기능은 어떻게 상속하고 확장할까요?

이전 개념에서 타입 계층 구조를 만드는 방법을 살펴봤고, Julia가 인자 타입에 따라 메서드를 선택하기 위해 [다중 디스패치][concept-multiple-dispatch]를 어떻게 사용하는지도 배웠어요.

Julia에는 몇 가지 비공식 [인터페이스][ref-interfaces]도 있어요. 이를 이용하면 직접 만든 타입을 표준 타입에 이미 정의된 동작에 연결할 수 있어요.

이것은 이터레이터 인터페이스를 보면 가장 쉽게 이해할 수 있어요.

## [이터레이터][ref-iterators]

지금까지의 강의 내용에서 Julia가 컬렉션의 각 원소를 다루는 여러 가지 방법을 봤어요.

- `for item in items...` 같은 [루프][concept-loops]
- [브로드캐스팅][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [고차 함수][concept-hof]: `map(√, [1, 4, 9])`
- [컴프리헨션][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [제너레이터][concept-comprehensions]: `(x^2 for x in 1:1e6)`, 지연 평가돼요.

보다시피 Julia는 표준 컬렉션을 항목 하나하나씩 순회할 줄 알아요. 위 예시의 벡터와 범위가 그렇고, Set, Dict 등도 마찬가지예요.

그럼 직접 만든 컬렉션에, 특히 제너레이터처럼 지연 평가로 순회할 수 있는 컬렉션에 이 기능을 어떻게 추가할까요?

### 최소 요구 사항

순회할 수 있는 시퀀스를 만들려면 (적어도) 두 가지가 필요해요:

1. _첫 번째_ 항목을 얻는 방법.
2. 현재 상태에서 _다음_ 항목을 얻는 방법.

Julia는 `Base.iterate()` 함수의 메서드로 이 일을 하는데, 그 과정은 다음과 같아요:

1. 먼저 `Base.iterate(iter)`가 자동으로 호출돼요.
    - 순회할 것이 없으면 `nothing`을 반환해요.
    - 그렇지 않으면 처음 반환되는 항목과 첫 번째 상태의 `Tuple`인 `(firstitem, firststate)`를 반환해요.
2. 이전 순회에서 항목이 반환되었으면 `Base.iterate(iter, state)`가 자동으로 호출되는데, 이때 `firststate`가 `state` 인자로 전달돼요.
    - 순회가 끝나면 `nothing`을 반환해요.
    - 그렇지 않으면 다음 항목과 다음 상태의 `Tuple`인 `(nextitem, nextstate)`를 반환해요.
3. 순회가 끝날 때까지 2번을 반복해요.

이 단계들은 모두 "내부에서" 처리돼요. 즉, 메서드 호출과 상태는 순회 프로토콜이 내부에서 관리하고(상태는 불투명하게 유지돼요), 루프 같은 상위 수준 구조에는 항목만 드러나요.
다시 말해, `item`만 보이고 나머지는 모두 블랙박스 안에 남아 있어요.

[다중 디스패치][concept-multiple-dispatch]가 이 모든 것의 중심이에요.
`iter`의 타입이 어떤 메서드가 호출될지 결정하고, 인자의 개수가 첫 번째 항목을 반환할지 다음 항목을 반환할지 결정해요.

표준 타입에 대한 메서드는 이미 정의되어 있어요: `Vector`, `Range`, `Set` 등([현재][ref-iterations-collections] 모두 14개 타입)이요.

직접 만든 `MyType`이 같은 동작을 하도록 하려면 먼저 다음을 정의해야 해요:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

추상적으로 들으면 혼란스럽겠지만, 실제로는 아주 간단할 수 있어요.
예를 들어, 주어진 정수 `n`의 거듭제곱을 최대 개수만큼 내놓는 타입을 원한다고 해봐요.

먼저 직접 만든 타입을 정의해요:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

이제 이 타입에 대한 `iterate` 메서드를 정의할 수 있는데, 첫 번째 항목과 첫 번째 상태는 무엇일까요?

첫 번째 항목을 얻으려면 복잡한 준비가 필요한 이터레이터도 있지만, 이 장난감 예제에서는 처음 반환되는 항목이 그냥 밑인 수라는 걸 알 수 있어요. 따라서 `count`의 값이 1 이상인지만 확인하면 돼요.

이제 다음 순회에 사용할 정보를 담는 첫 번째 상태를 생각해볼까요?
이를 위해 어떤 정보를 기억해야 할지는 스스로 정하면 되고, 타입은 무엇이든 괜찮아요.

이 경우에는 `n`을 거듭제곱할 "인덱스"만 기억해도 되고, 더 빠른 방법으로 `n`의 가장 최근 거듭제곱(즉, 반환된 항목)과 시퀀스의 다음 "인덱스"를 사용할 수도 있어요.
이 두 수를 `Tuple`로 묶어 `state`로 반환할 수 있어요.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

이 예제에서는 첫 번째 항목(`p.n`)이 루프로 반환되고, 첫 번째 상태 `(p.n, 2)`가 `iterate(P::Powers, state)` 메서드로 전달돼요.
거기서 현재 항목에 밑인 수를 곱해 지수를 `1`만큼 늘리는 방식으로 상태를 처리해 다음 항목을 만들 수 있어요.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

인덱스 값이 아직 `count` 이내라면 `next` 항목과 증가된 상태 `(next, index + 1)`를 담은 `Tuple`이 반환돼요.
`index` 값이 `count`를 넘으면 대신 `nothing`이 반환되어 순회가 끝났음을 알려줘요.

`iterate(p::Powers)`와 `iterate(p::Powers, state)` 메서드의 함수 본문이 꽤 비슷하다는 걸 눈치챘을지도 몰라요.
사실 이 유사성을 잘 이용하면 상태에 기본값을 지정한 두 인자 버전만 사용해 구현을 간결하게 만들 수 있어요: `Base.iterate(p::Powers, state=(1, 1))`
그러면 인자가 하나뿐인 `iterate(p::Powers)`를 따로 둘 필요가 없어요.
가능할 때는 실제로도 흔히 이렇게 해요.

~~~~exercism/advanced
[함수][concept-functions] 개념에서 선택적 인자를 소개할 때는 구현에 대해서는 아무 말도 하지 않았어요.

그 뒤에 다중 디스패치를 배웠으니, 이제 Julia가 선택적 인자가 _있는_ 함수를 선택적 인자가 _없는_ 여러 메서드로 자동 변환한다는 점이 더 잘 이해될 거예요.

`Base.iterate(P::Powers, state=(1, 1))`를 정의하는 것은 `Base.iterate(P::Powers, state)`와 `Base.iterate(P::Powers)`를 각각 정의하는 것과 완전히 같아요.

[concept-functions]: https://exercism.org/tracks/julia/concepts/functions
~~~~

지금까지도 이미 쓸 만한 기능이 있어요. 3의 처음 네 개 거듭제곱에 대해 결과를 루프로 돌 수 있고, 어떤 수가 결과에 들어 있는지 확인할 수 있으며, `sum()` 같은 집계 함수를 적용할 수 있어요.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### 추가 메서드

이렇게 좋은 출발을 했지만, 아직 모든 것이 동작하는 건 아니에요.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers)
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

역시 `length(Powers(3, 4))`도 똑같은 오류 메시지를 내놓아요.

길이는 타입 생성자의 일부이므로(이 경우에는 4) 쉽게 고칠 수 있어요.
이 타입에 `Base.length()`만 정의하면 시퀀스에 컴프리헨션과 `collect()`를 사용할 수 있어요.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

효율을 위해서는 결과의 원소 타입을 알려 주는 `Base.eltype()`도 정의하는 게 좋아요.
그러면 `collect()` 같은 함수가 `Vector{Any}`에 `push!()`를 반복하는 대신 출력 `Vector{Int}`를 위한 공간을 미리 확보할 수 있어요.

이전에 보지 못했을 수도 있는 문법에 주목해요. 이 메서드는 타입의 _인스턴스_가 아니라 _타입_에 정의돼요.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

이터레이터는 길이가 유한할 _필요는_ 없어요.
"무한한" 시퀀스는 쓰임새가 더 제한적이지만, 루프를 `break`로 빠져나갈 방법만 있다면 그 위를 반복하는 것이 유용할 수 있어요.
예를 들어, 특정 한계보다 작은 값만 생성하는 `Powers`의 변형을 정의할 수도 있어요(정수 오버플로를 피하려면 아마 `typemax(Int)`겠죠).

## 다른 인터페이스

### [인덱싱][ref-indexing]

이터레이터 인터페이스를 사용하면 간단한 메서드 몇 개만 정의해서 임의의 커스텀 타입을 시퀀스처럼 동작하게 만들 수 있어요.

시퀀스에 인덱스로 접근할 수도 있으면 좋겠다고 해봐요:

```julia-repl
julia> P = Powers(3, 4)
Powers(3, 4)

julia> P[2]
ERROR: MethodError: no method matching getindex(::Powers, ::Int64)
The function `getindex` exists, but no method is defined for this combination of argument types.
```

이 동작을 추가할 수 있는데, [매뉴얼][ref-indexing]에서 방법을 설명해요.

최소한 `getindex()`를 정의해야 해요.

```julia-repl
julia> function Base.getindex(P::Powers, i::Int)
          1 ≤ i ≤ P.count || throw(BoundsError(P, i))
          return p.n ^ i
       end

julia> p = Powers(3, 4)
Powers(3, 4)

julia> p[3]
27
```

그 밖에도 다음을 정의해야 해요:

- `P[begin]`과 `P[end]`를 지원하기 위한 `firstindex()`와 `lastindex()`.
- 벡터와 범위로 인덱싱을 지원하기 위한 `getindex()`의 변형.
- 이론적으로는 `setindex!()`인데, 이 예제에서 그게 무슨 의미일지조차 잘 떠오르지 않아요.

그런데 이쯤 되면 이터레이터를 그저 Vector처럼 보이게 만들기 위해 꽤 많은 일을 하고 있는 셈이에요.

### [AbstractArray][ref-abstractarray]

더 좋은 출발점을 제공하는 다른 인터페이스를 생각해볼 만해요.

이 경우에는 `Powers`를 [`AbstractArray`][ref-abstractarray]의 하위 타입으로 만드는 것을 고려할 수 있는데, 그러면 배열과 비슷한 동작을 많이 공짜로 얻을 수 있어요.

`Powers` 시퀀스에 대응하는 배열은 1차원 정수 배열이에요.
이것이 `AbstractArray{Int, 1}`로 쓰인 경우도 가끔 볼 수 있지만, 최신 Julia 코드에서는 1차원을 뜻하는 `AbstractVector{Int}`와 2차원을 뜻하는 `AbstractMatrix{Int}` 별칭이 더 흔해요.

```julia-repl
julia> struct PowersArray <: AbstractVector{Int}
           n::Int
           count::Int
       end
```

이제는 `length()` 대신 각 차원의 길이를 담은 튜플을 받는 `size()`를 정의해야 해요. 이 경우에는 차원이 하나뿐이죠.

```julia-repl
julia> Base.size(PA::PowersArray) = (PA.count,)
```

항목에 어떻게 인덱스를 붙이고 싶을까요?
[다차원 배열 개념][concept-multi-dimensional-arrays]에서 두 가지 주요 방식을 소개했어요:

- 차원마다 인덱스 하나씩, 즉 행렬 `M`에 대해 `M[row, col]`처럼 쓰는 방식.
- 메모리에서 항목이 배치된 순서에 대응하는 단일 인덱스.

이들은 각각 `Cartesian`과 `Linear`라고 해요.

예제에는 차원이 하나뿐이므로 선형 인덱싱이 적절해요.

```julia-repl
julia> Base.IndexStyle(::Type{PowersArray}) = IndexLinear()

julia> Base.getindex(PA::PowersArray, i::Int) = PA.n ^ i

julia> p = PowersArray(3, 4)
4-element PowersArray:
  3
  9
 27
 81

julia> p[3]
27
```

이 경우에는 `iterate()`를 정의하지 않았다는 점에 주목해요.
Julia가 우리가 정의한 `getindex()`를 바탕으로 기본 구현을 자동으로 제공해요.

직접 `iterate()`를 정의하는 것도 여전히 가능하고, 어떤 경우에는 더 효율적일 수도 있어요.

`AbstractArray` 인터페이스는 더 높은 차원의 순회를 원할 때 특히 유용해요.
이 장난감 예제를 한계까지 늘려 본다면, `1:n`에 있는 수들의 처음 `m`개 거듭제곱을 뜻할 수 있고, 그러면 크기가 `(m, n)`인 배열이 순회를 통해 정의돼요.

```julia-repl
struct PowersMatrix{Int} <: AbstractMatrix{Int}
    ns::AbstractVector{Int}
    count::Int
end

Base.size(PM::PowersMatrix) = (PM.count, length(PM.ns))
Base.IndexStyle(::Type{PowersMatrix}) = IndexCartesian()
Base.getindex(PM::PowersMatrix, i::Int, j::Int) = PM.ns[j] ^ i

julia> PM = PowersMatrix(2:6, 4)
4×5 PowersMatrix{Int64}:
  2   3    4    5     6
  4   9   16   25    36
  8  27   64  125   216
 16  81  256  625  1296

julia> PM[3, 2]
27

julia> PM[7] # column major linear indexing
27

julia> PM[21]
BoundsError: attempt to access 4×5 PowersMatrix{Int64} at index [21]
[...]
```

### [반올림][ref-rounding]

이전 개념에서 수치 타입에 대한 여러 가지 반올림 방식을 언급했어요.

```julia-repl
julia> round(1.7)
2.0

julia> floor(1.7)
1.0

julia> ceil(1.7)
2.0

# specify output type
julia> round(Int, 1.7)
2

julia> round(2.4 + 7.3im)
2.0 + 7.0im
```

[`round()`][ref-round] 함수는 이보다 더 유연해서, (현재 지원되는 7가지 중) [`RoundingMode`][ref-roundingmode], 출력의 소수 자릿수, 기수를 지정할 수 있어요.

같은 함수가 직접 만든 타입도 처리해 주면 좋을 때가 있어요.
흔히 좌표 같은 복합 타입이 그 대상이죠.

```julia-repl
julia> struct Point3D
           x::Float64
           y::Float64
           z::Float64
       end

julia> p = Point3D(7.63, 9.24, 4.50)
Point3D(7.63, 9.24, 4.5)

julia> round(p)
ERROR: MethodError: no method matching round(::Point3D, ::RoundingMode{:Nearest})
The function `round` exists, but no method is defined for this combination of argument types.
```

당연히도 `Rounding` 인터페이스가 있고, 최소한 우리 타입에 대한 `round()`를 정의해야 해요.

```julia-repl
julia> Base.round(P3D::Point3D, r::RoundingMode) = Point3D(round(P3D.x, r), round(P3D.y, r),round(P3D.z, r))

julia> round(p)
Point3D(8.0, 9.0, 4.0)

julia> ceil(p)
Point3D(8.0, 10.0, 5.0)
```

정의에 `RoundingMode`를 포함했기 때문에 `floor()`와 `ceil()`이 자동으로 동작해요.

물론 더 복잡한 반올림 방식을 정의할 수도 있어요.

- `Point3D`를 원점에서 같은 방향으로 정수 거리가 되도록 반올림하고 싶을 수 있어요.
- 각도의 경우 기상 예보관이 쓰는 16방위(_"남남서풍 15노트"_)로 반올림하고 싶을 수 있는데, 이는 π/8 라디안의 배수를 뜻해요.
- `digits`, `sigdigits`, `base`를 지정하는 기능을 추가하고 싶을 수도 있어요.
- 시간 기간에는 [특별한 옵션][ref-round-periods]이 있어요.

## 정리

인터페이스는 설명하기 꽤 혼란스러운데, Julia의 접근 방식이 대부분의 다른 언어와 아주 다르기 때문이에요.
특히 인터페이스의 이름은 구현에서 한 번도 언급되지 않을 수 있어요. [하위 클래스 만들기][wiki-subclass]나 [믹스인][wiki-mixins]과는 아주 다르죠.

그렇지만 실제로는 놀랄 만큼 간단해요:

1. 하위 타입 지정이 유용한지 판단하면서 적절한 타입을 정의해요.
2. ([문서][ref-interfaces]에서) 어떤 메서드가 필요한지 찾아요.
3. 직접 만든 타입에 그 메서드들을 구현해요. 보통 몇 개 안 되고, 아주 짧고 간단해요.
4. 나머지는 [다중 디스패치][concept-multiple-dispatch]가 자동으로 처리하게 해요.
