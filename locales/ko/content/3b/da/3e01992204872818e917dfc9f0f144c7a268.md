# 코드 포함

```sather
   include WARM_UP;
   include WARM_UP count -> warm_up_count;
   include WARM_UP describe -> ;
   include WARM_UP count -> beats, describe -> ;
```

`include`는 다른 클래스의 코드를 이 클래스 안으로 복사해요. 컴파일 시점에 이루어지는 연산이라 실행 시점 비용도 없고 실행 시점 관계도 없어요. 두 클래스는 그 뒤로 이어지지 않아요.

## 절

```
   include CLASS  old_name -> new_name , old_name -> ;
```

각 항목은 기능 하나씩의 이름을 바꿔요. 새 이름 없이 `-> ;`만 쓰면 그 기능은 빠져요. 언급하지 않은 것은 이름 그대로 들어와요.

이름 바꾸기는 *바깥*에서 보이는 것에 적용돼요. 포함된 루틴들 사이의 호출은 그대로 동작해요. `describe`가 `count`를 호출하는데 `count`의 이름이 `beats`로 바뀌었다면, `describe`는 `beats`를 호출해요.

## 여러 개 포함하기

```sather
   include WARM_UP;
   include COOL_DOWN;
```

이렇게 하는 것도 가능하고, 이것이 Sather가 다른 언어에서 다중 상속이라고 부르는 것을 얻는 방식이에요. 흔히 따라오는 골칫거리도 없어요. 충돌은 컴파일 오류로 처리되고, 해결책은 이름을 바꾸거나 하나를 빼는 것이기 때문이에요. 외워야 하는 우선순위 규칙으로 해결되는 것은 아무것도 없어요.

## private include

```sather
   private include WARM_UP;
```

이 클래스가 스스로 쓰기 위해 코드를 들여오되 겉으로 드러내지는 않아요. 인터페이스가 아니라 구현이 필요할 때 유용해요.

## 두 가지 함께 쓰기

클래스 패밀리를 만들 때 흔히 쓰는 형태예요:

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class ACT_BASICS is
   minutes : INT is return 5; end;
end;

class JUGGLING < $ACT is
   include ACT_BASICS;
   name : STR is return "Juggling"; end;
end;
```

`< $ACT`는 그 클래스가 무엇을 할 수 있는지를 말하고, `include ACT_BASICS`는 그 방법의 일부를 제공해요. 방법에 대한 생각이 바뀌어도 `<`는 움직이지 않아요.

## 왜 이렇게 하는 걸까요

추상 클래스에는 코드가 없어서 실수로 상속받을 수 없고, 발밑에서 동작이 바뀌는 슈퍼클래스 같은 것도 없어요. 재사용은 컴파일 시점에, 이름을 대준 클래스에서 가져오는 복사본이고, 이름 바꾸기는 모두 적어 둬요.

대가는 재사용을 각 클래스에서 명시적으로 요청해야 한다는 점이에요. 그것이 맞바꿈이에요. 입력할 것이 더 많고, 암묵적인 것은 없어요.
