# 소개

Factor의 오류 시스템은 세 부분으로 이루어져 있어요: 오류를 알리는 `throw`, 오류를 처리하는 `recover`, 그리고 나만의 오류 종류를 정의하는 `ERROR:`예요.

## `throw`

`throw`는 ([`kernel`][kernel]에 있는) 오류를 발생시켜요. 인자는 *어떤* 값이든 될 수 있어요. 문자열, 숫자, 튜플 등 무엇이든 나중에 살펴볼 수 있는 오류가 돼요.

```factor
! DOCTEST: SKIP
"file not found" throw
```

`throw`는 반환하지 않아요. 현재 word의 나머지 부분은 건너뛰어요.

## `recover`

`recover`는 ([`continuations`][continuations]에 있는) Factor의 try/catch예요. *try* quotation과 *recovery* quotation을 받아요:

```
recover ( try recovery -- )
```

`try`가 아무것도 던지지 않고 끝나면 `recovery`는 무시돼요. `try`가 오류를 던지면, 그 오류가 스택에 푸시되고 `recovery`가 실행돼요:

```factor
[ "boom" throw ] [ drop "caught" ] recover .
! => "caught"

[ "ok" ] [ drop "never runs" ] recover .
! => "ok"
```

[`kernel`][kernel]의 `when`은 자연스러운 짝이에요. 스택 맨 위의 값이 참으로 평가될 때만 quotation을 실행해요:

```factor
: check-positive ( n -- )
    0 < [ "negative!" throw ] when ;
```

## `ERROR:`

`ERROR:`는 튜플 클래스를 정의하고, *동시에* 새로운 인스턴스를 만들어 던지는 word도 정의해요:

```factor
! DOCTEST: SKIP
ERROR: not-found path ;

"/missing" not-found
! throws T{ not-found { path "/missing" } }
```

슬롯이 없는 오류는 그냥 `ERROR: name ;`예요. `name`을 호출하면 빈 인스턴스를 던져요. `ERROR:`로 정의한 튜플에는 클래스 술어 `name?`이 따라오는데, 잡은 오류가 그 타입인지 검사할 때 쓸 수 있어요.

## 슬롯을 다시 읽어내기

잡은 오류는 그냥 튜플이라서, 각 `ERROR:` 슬롯에는 다른 튜플과 똑같이 자동 생성된 `slot>>` 리더가 따라와요.

```factor
! DOCTEST: SKIP
{
    T{ not-found { path "/a" } }
    T{ not-found { path "/b" } }
}
[ path>> ] map .   ! => { "/a" "/b" }
```
