# 개요

키워드 리스트는 `{key, value}` [튜플][exercism-tuples]의 리스트예요. 키워드 리스트를 작성하는 방법에는 두 가지가 있어요:

```elixir
# concise
[month: "April", year: 2018]

# explicit
[{:month, "April"}, {:year, 2018}]
```

## 키는 아톰이어야 해요

2-튜플의 리스트라고 해서 모두 키워드 리스트인 것은 아니에요. 키는 아톰이어야 해요:

```elixir
Keyword.keyword?([{"month", "April"}])
# => false
```

키에 문자, 숫자, `_` 이외의 문자를 사용하고 싶다면 따옴표로 감싸야 해요. 하지만 그렇게 해도 문자열이 되는 것은 아니에요. 여전히 아톰이에요.

[//]: # (elixir-formatter-disable-next-block)

```elixir
Keyword.keyword?(["day of week": "Monday"])
# => true
```

## 키는 반복될 수 있어요

키워드 리스트의 키는 반복될 수 있고, [키-값 쌍은 순서를 가져요][keyword-duplicate-keys-and-ordering]. 주어진 키로 단일 값을 가져오려고 하면 첫 번째 값을 얻게 되고, 같은 키에 있는 다른 값들은 조용히 무시돼요.

```elixir
list = [month: "April", month: "May"]

Keyword.get_values(list, :month)
# => ["April", "May"]

Keyword.get(list, :month)
# => "April"
```

키워드 리스트는 [_Access behaviour_][access-behaviour]도 지원해요.

```elixir
list[:month]
# => "April"
```

## 옵션으로 쓰이는 키워드 리스트

키워드 리스트의 이런 특성 덕분에 Elixir에서 함수에 옵션을 전달하는 기본 방식이 되었어요.

`if`를 배울 때 특별한 축약 문법을 보셨을 거예요:

```elixir
if age >= 16, do: "beer", else: "no beer"
```

`if`가 인자 두 개를 받는 것처럼 보일 수 있지만, `do:`와 `else:` 쌍은 사실 하나의 인자, 즉 키워드 리스트예요. 같은 코드를 이렇게 쓸 수도 있어요:

[//]: # (elixir-formatter-disable-next-block)

```elixir
if age >= 16, [do: "beer", else: "no beer"]
# or
if age >= 16, [{:do, "beer"}, {:else, "no beer"}]
```

키워드 리스트를 함수 옵션으로 사용하는 일이 워낙 흔해서, Elixir는 키워드 리스트가 함수에 전달되는 [마지막 인자일 때 대괄호를 생략할 수 있게 해줘요][keyword-call-syntax].

튜플, 리스트, 맵 등을 Elixir 문법에서는 함수 호출과 똑같이 취급하기 때문에, 이 속성은 이것들에도 적용돼요.

```elixir
[1, 2, three: 3]
# => [1, 2, {:three, 3}]
```

## 패턴 매칭

축약 문법으로 키워드 리스트를 성공적으로 패턴 매칭하려면 모든 키를 올바른 순서로 지정해야 해요. 그래서 키워드 리스트를 다룰 때는 패턴 매칭을 거의 쓰지 않아요. 대신 [`Keyword`][keyword] 모듈이나 [_Access behaviour_][access-behaviour]를 사용해요.

```elixir
[month: month] = [month: "April", year: 2018]
# => ** (MatchError) no match of right hand side value: [month: "April", year: 2018]

[year: year, month: month] = [month: "April", year: 2018]
# => ** (MatchError) no match of right hand side value: [month: "April", year: 2018]
```

## 키워드 리스트와 맵 비교

|                  | 키워드 리스트                 | 맵                                   |
| ---------------- | ----------------------------- | ----------------------------------- |
| 키 타입          | 아톰                          | 아무거나, 한 맵에 섞일 수 있어요     |
| 중복 키          | 있음                          | 없음                                 |
| 키 순서          | 있음                          | 없음                                 |
| 접근             | `list[:key]`, `Keyword.get/2` | `map.key`, `map[:key]`, `Map.get/2` |
| 접근 시간        | 선형                          | 로그                                 |
| 패턴 매칭        | 그다지 유용하지 않음          | 유용함                               |

더 빠른 접근 시간, 유연한 키 타입, 유용한 패턴 매칭 덕분에 대부분의 경우 맵이 기본 선택이에요.

데이터가 많지 않지만 중복 키가 필요하거나 키가 특정 순서를 가져야 할 때는 키워드 리스트를 사용해요.
