# 소개

*덱*(양방향 큐)은 양쪽 끝에서 push와 pop을 O(1)로 지원해요. Factor의 표준 구현은 [`dlists`][dlists]에 있는 `<dlist>`(이중 연결 리스트)이고, 연산들은 [`deques`][deques]에 있어요.

## 덱 API

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque`는 덱을 제자리에서 비워요. 다시 할당하지 않고 덱을 재사용하고 싶을 때 유용하죠.

같은 쪽 끝에서 push와 pop을 하면 LIFO 스택이 돼요. 한쪽 끝에서 push하고 다른 쪽 끝에서 pop하면 FIFO 큐가 돼요.

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

LIFO에는 `push`/`pop`이 있는 벡터(`V{ }`)를 쓰게 돼요. 연산마다 드는 부담이 더 적거든요. *양쪽* 끝 모두에서 O(1)이 필요할 때는 `<dlist>`를 골라요. 거의 항상 FIFO 큐를 만들 때죠.

## 너비 우선 탐색

FIFO로 사용하는 방식이 덱을 *BFS*에 알맞은 경계로 만들어 줘요. 노드 하나에서 시작해서 이웃을 뒤쪽에 push하고, 앞쪽에서 후보를 pop하며, 해시 집합으로 중복을 제거해요.

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

오래된 후보가 새 후보보다 먼저 방문돼요. 그래서 탐색은 시작점에서 바깥으로 층을 이루며 퍼져 나가죠. 이것이 BFS에 최단 경로 성질을 안겨 줘요. 목표 노드에 처음 도달할 때의 경로가 최소 홉 경로가 되거든요.

## `MEMO:`: 자동 캐싱

BFS가 호출하는 노드별 조회가 비쌀 때가 있어요. Factor의 [`memoize`][memoize] vocab이 제공하는 `MEMO:`는 `:`를 그대로 대신할 수 있고, 단어의 결과를 입력값을 기준으로 캐시해요.

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

`MEMO:` 단어는 각 입력을 처음 만날 때 본문을 실행하고, 그다음부터는 캐시된 결과를 반환해요. 인터페이스는 그대로이고, 호출하는 쪽에서 추가로 할 일도 없이 반복할 때 더 빠르기만 하죠.
