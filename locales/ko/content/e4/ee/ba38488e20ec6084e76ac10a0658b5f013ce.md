# 소개

## 문자

**문자 인코딩**은 자연어의 텍스트 요소를 바이트의 나열로 표현하기 위해 사용하는 특정한 규약이에요.
여기서 "텍스트 요소"란 자연어에서 의미를 가지는 모든 단위를 말해요. 예를 들어 글자, 공백, 문장 부호, 이모지, 표의 문자 등이에요.

NASM(Netwide Assembler, 이 트랙에서 사용하는 어셈블러)은 **ASCII**를 사용한 데이터 정의를 지원해요.

NASM에서 문자 상수는 최대 8바이트까지 가능하며, 작은따옴표(`'`), 큰따옴표(`"`), 백틱(`` ` ``)을 사용해 정의할 수 있어요:

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

특수 문자는 백틱으로 정의하고 `\`로 이스케이프해야 해요:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

x86-64에서는 어떤 문자 인코딩도 별도의 타입으로 내장 지원하지 않아요.
어셈블리에서 데이터는 바이트의 나열이고, 그 바이트를 문자로, 숫자로, 또는 무엇으로 해석할지는 프로그래머에게 달려 있어요.

예를 들어 ASCII 문자 '0'은 값 48을 가지는 한 바이트예요.
따라서 한 바이트에 48을 저장하는 것은 ASCII 문자 '0'을 저장하는 것과 완전히 같아요:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

같은 이유로, 문자를 조작하는 것은 그 바이트의 값을 직접 변환함으로써 이루어져요:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## 문자열

**문자열**은 문자의 나열이에요.
어셈블리에서는 보통 배열로 구현해요.

NASM에서는 다른 배열을 선언하는 것과 같은 방식으로 문자열을 선언할 수 있어요:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

문자열과 다른 배열의 한 가지 차이는 NASM이 값을 쉼표(`,`)로 구분하지 않고도 문자열을 선언하는 기능을 지원한다는 점이에요.
값을 쉼표로 섞어 쓰는 것도 가능해요:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

앞서 언급한 것처럼, 문자는 그저 바이트예요 (유니코드 인코딩에서는 바이트의 나열이고요):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

각 ASCII 문자는 한 바이트를 차지하기 때문에, 더 넓은 크기에서 뒤따르는 바이트는 모두 `0`이에요.
예를 들어 `'a'`를 qword(8바이트)로 선언하면 첫 번째 바이트는 `'a'`(`97`)이고 나머지 일곱 바이트는 모두 `0`이에요.

이런 이유로, 다음은 모두 같아요:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
어셈블리에서 문자열은 ASCII NUL 문자(값 `0`)로 자동 종료되지 않아요.

C와 같은 고수준 언어와 연동할 때에는 문자열 끝에 올바른 종료 문자(있다면)를 붙이는 것이 프로그래머의 책임이에요.
~~~~

## 문자열 명령어

문자열은 배열이기 때문에, 메모리를 명시적으로 역참조하여 다른 배열과 같은 방식으로 다룰 수 있어요:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

그 외에도, 메모리의 바이트 나열에서 값을 불러오고, 옮기고, 저장하는 명령어들이 있어요.
_문자열 명령어_라고 불리지만, 메모리에 있는 어떤 바이트 나열과도, 즉 어떤 배열과도 함께 사용할 수 있어요.

가장 중요한 세 가지 문자열 명령어는 `lods`, `stos`, `movs`예요:

| 명령어 | 하는 일                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | `rsi`가 가리키는 메모리 위치에서 값을 불러와 `rax`에 넣어요                                                |
| `stos`      | `rax`의 값을 `rdi`가 가리키는 메모리 위치에 저장해요                                               |
| `movs`      | `rsi`가 가리키는 메모리 위치에서 값을 복사해 `rdi`가 가리키는 메모리 위치에 저장해요    |

이 명령어들은 명시적인 피연산자를 _받지 않아요_.
피연산자는 암묵적이에요.

대략적인 규칙은 다음과 같아요:

1. 원본 피연산자가 메모리 위치일 때, 그 주소는 `rsi`에 저장해야 해요 (`s`는 source를 뜻해요).
2. 목적지 피연산자가 메모리 위치일 때, 그 주소는 `rdi`에 저장해야 해요 (`d`는 destination을 뜻해요).
3. 피연산자 중 하나가 메모리 위치가 아니면, 그것은 `rax` 레지스터예요.

이 명령어들은 수행하는 구체적인 연산에 따라 메모리 주소를 자동으로 역참조해요.

이들 모두는 서로 다른 크기로 동작할 수 있어요.
이 크기를 나타내기 위해 접미사가 붙어요:

| 접미사 | 의미 | 크기    |
| :----: | ------- | :------ |
|  `b`   | byte    | 1바이트  |
|  `w`   | word    | 2바이트 |
|  `d`   | dword   | 4바이트 |
|  `q`   | qword   | 8바이트 |

예를 들어:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

이 명령어들은 또한 사용된 주소를 연산의 크기만큼 갱신해요.
이 갱신은 **방향 플래그(DF)** 의 값에 따라 이루어져요:

- `DF`가 클리어되어 있으면, 주소는 연산의 크기만큼 _증가_해요.
- `DF`가 설정되어 있으면, 주소는 대신 같은 크기만큼 _감소_해요.

System V ABI는 함수 진입 시 방향 플래그가 클리어되어 있어야 한다고 규정해요.
따라서 _기본 동작은 메모리를 주소가 커지는 순서로 읽고 쓰는 것이에요_.

`cld` 명령어로 방향 플래그를 클리어할 수 있고, `std` 명령어로 설정할 수 있어요:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
System V ABI에 따라, 호출자는 호출된 함수가 반환된 뒤 `DF`가 클리어되어 있을 것으로 기대해요.
만약 `DF`를 설정했다면, `ret` 전에 반드시 클리어해야 해요.
~~~~

### Rep

그 외에, **rep** 명령어는 메모리와 직접 상호작용하지 않아요.
대신, 앞서 언급한 다른 명령어들에 접두사로 붙어 그 명령어들을 _반복_할 수 있어요.

`rep`가 접두사로 붙으면, 문자열 명령어는 `rcx`의 값과 같은 횟수만큼 반복돼요.
매번 `rcx`의 값은 `1`씩 감소해요.
`rcx`의 값은 명령어를 사용하기 전에 설정해야 한다는 점에 유의해요:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
최신 CPU에서는 큰 블록의 데이터를 옮길 때 `rep movs`와 `rep stos`가 보통 빠른 선택이에요.
하지만 다른 문자열 명령어들, 심지어 `rep` 없이 동작하는 `movs`와 `stos`도 보통 평범한 루프보다 느려요.

이 주제에 대한 더 자세한 내용은 [이 참고서의 16.9장, "String instructions"][agner-optimization-guide]에서 볼 수 있어요.
