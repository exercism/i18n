# 소개

각 값이 자신의 위치에 따라 결정되는 `n`개의 값이 필요할 때, Factor의 `<iota>`와 `map`이 힘을 합쳐 루프 카운터를 작성하지 않고도 그 일을 해내요.

## `<iota>`와 `map`

[`sequences`][sequences]에 있는 `<iota>`는 음이 아닌 정수 `n`을 받아 정수 `0, 1, …, n-1`로 이루어진 *가상의* 시퀀스를 반환해요. 그러면 `map`이 그 시퀀스를 따라가면서 각 원소에 쿼테이션을 적용해요:

```factor
USING: math sequences ;

5 <iota> [ 2 * ] map .   ! => { 0 2 4 6 8 }
```

쿼테이션은 정수 하나, 즉 인덱스를 받아서 그 위치에 해당하는 값을 스택에 남겨요.

## 개수만큼 순회하고 반복하기

각 인덱스를 방문하는 *부수 효과*만 필요하고 새로운 시퀀스는 필요하지 않을 때는, [`math`][math]에 있는 `each-integer`가 `0, 1, …, n-1`에 대해 쿼테이션을 실행해요:

```
each-integer ( n quot: ( i -- ) -- )
```

[`sequences`][sequences]에 있는 `replicate`는 인덱스는 무시한 채 쿼테이션을 `n`번 호출해서 그 결과를 모아요. 서로 독립적인 `n`개의 값을 만들 때 편리해요:

```
replicate ( n quot: ( -- elt ) -- seq )
```

```factor
USING: sequences ;

3 [ { 0 0 } ] replicate .   ! => { { 0 0 } { 0 0 } { 0 0 } }
```

## 양끝이 정해진 범위

인덱스 범위가 `0`에서 시작하지 않거나 양쪽 끝을 모두 포함해야 할 때는, [`ranges`][ranges] 보캐블러리가 대괄호 표기 리터럴을 제공해요. 대괄호는 끝점을 포함하고, 소괄호는 포함하지 않아요.

```
[a..b]    ! a, a+1, …, b      (inclusive)
[a..b)    ! a, a+1, …, b-1    (half-open at the top)
```

```factor
USING: math ranges sequences ;

3 7 [a..b] [ 2 * ] map .   ! => { 6 8 10 12 14 }
3 7 [a..b) [ 2 * ] map .   ! => { 6 8 10 12 }
```

자주 쓰이는 인자 하나짜리 축약형도 있어요:

```
[1..b]    ! 1, 2, …, b        (same as 1 b [a..b])
[1..b)    ! 1, 2, …, b-1      (same as 1 b [a..b))
[0..b)    ! 0, 1, …, b-1      (same as 0 b [a..b), and same as `b <iota>`)
```

```factor
6 [1..b] [ sq ] map .      ! => { 1 4 9 16 25 36 }
6 [1..b) [ sq ] map .      ! => { 1 4 9 16 25 }
4 [0..b) [ 1 + ] map .     ! => { 1 2 3 4 }
```

`<iota>`가 가장 흔한 형태이고, `[a..b]` 같은 것들은 범위가 `0`이 아닌 다른 곳에서 시작하거나 위쪽 끝을 포함해야 할 때 알맞은 도구예요.

## 아래쪽이 열린 범위와 비어 있을 수 있는 범위

대괄호는 끝점을 *포함*하고, 소괄호는 *포함하지 않아요*. 왼쪽에 같은 방식을 적용하면 `(a..b]`와 `(a..b)`가 돼요:

```
(a..b]    ! a+1, …, b              (lower open, upper inclusive)
(a..b)    ! a+1, …, b-1            (both open)
```

`0 n (a..b]`는 `n > 0`일 때 `{ 1 … n }`을, `n = 0`일 때 `{ }`를 만들어요. 즉 `n`까지 포함한 모든 양의 정수를 순회할 때 자연스러운 형태예요.

## 내림차순 범위

네 가지 대괄호 형태, 즉 `[a..b]`, `[a..b)`, `(a..b]`, `(a..b)`는 모두 `a > b`일 때 빈 결과가 아니라 *내림차순*으로 세요:

```factor
USING: ranges sequences ;

5 1 [a..b] >array .   ! => { 5 4 3 2 1 }
1 0 [a..b] >array .   ! => { 1 0 }   (not empty!)
```

## 위치에 따라 문자열 만들기

`map`은 쿼테이션이 반환하는 모양을 그대로 만들어요. 쿼테이션이 스택에 문자 코드를 남기면, [`strings`][strings]에 있는 `>string`이 그 결과를 문자열로 바꿔요:

```factor
USING: math sequences strings ;

4 <iota> [ 2 * CHAR: A + ] map >string .   ! => "ACEG"
```

`CHAR: A`는 정수 `65`로 파싱돼요. 여기서 쿼테이션은 인덱스를 두 배로 하고 그 기준값을 더해서, 결과적으로 한 글자씩 건너뛴 대문자에 차례로 도달해요. 인덱스 위에 어떤 연산을 얹든 그 위치에 어떤 문자가 오를지가 결정돼요.

## 위치마다 선택하기

문자가 인덱스에 대한 *조건*에 따라 달라질 때는 선택을 쿼테이션 안에서 해요:

```factor
USING: kernel math sequences strings ;

5 <iota> [ 3 < [ CHAR: a ] [ CHAR: b ] if ] map >string .
! => "aaabb"
```

처음 세 위치는 `i 3 <`가 `t`로 나와서 `a`를 갖고, 나머지는 `b`를 가져요. 같은 형태, 즉 `[ <test> [ <yes> ] [ <no> ] if ]`는 [`math`][math]에 있는 `even?` / `odd?`를 사용한 짝수/홀수 판정과 `mod`와 `zero?`를 사용한 "k번째 위치마다" 검사에도 그대로 적용돼요.
