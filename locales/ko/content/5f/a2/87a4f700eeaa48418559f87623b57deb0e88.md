# Markdown 명세

다음은 Exercism의 모든 Markdown 파일이 따라야 하는 구조예요.

이 문서에 있는 규칙 중 일부는 아직 Exercism 전체에 적용되지 않았어요.
이런 부분을 고치는 PR을 환영해요.
모든 규칙은 우리의 CI와 린팅 도구에 추가되고 있으며, 새로운 변경 사항에서는 이를 따라야 해요.

## 제목

- 모든 파일은 레벨 1 제목(`# Some heading text`)으로 시작해야 해요.
- 레벨 1 제목은 순전히 GitHub나 이와 동등한 환경에서 소비되기 위해 존재해요.
- 파일이 Exercism에 의해 렌더링되면(예: 웹사이트에 표시되거나 CLI를 통해 렌더링되면), 이 제목은 제거되고 상황에 맞는 제목이 삽입돼요.
- 어떤 제목도 이전 제목보다 한 단계 넘게 내려갈 수 없어요(예: `##` 다음에는 `###`만 올 수 있고, `####`는 올 수 없어요).
- 단 하나의 레벨 1(`#`) 제목 외에는 레벨 2(`##`), 레벨 3(`###`), 레벨 4(`####`) 제목만 사용할 수 있어요.

## 링크

Markdown 파일 하단에 정의되고 참조 슬러그에 매핑되며, 본문에서 그 슬러그로 참조되는 [참조 링크][reference-links]를 사용해 주세요.

이 방법은 링크를 한 곳에서만 업데이트하면 되기 때문에 유지 보수가 더 쉬워요.

예:

```
I have a paragraph of text that links to the same page twice.

The [first link][indirect-reference] in one sentence.

Then, another sentence with the [link repeated][indirect-reference].

[indirect-reference]: https://example.com/link-to-page
```

링크에는 URL 자체를 본문에 넣는 대신 항상 앵커 텍스트가 있어야 해요. 예를 들어, 다음은 앵커 텍스트를 사용하지 않아 읽기 어려워요.

```
If you want some more information, please visit https://google.com.
```

앵커 텍스트를 사용하고 링크를 걸면 이해하고 맥락을 파악하기가 더 쉬워요.

```
If you want some more information, [Google][google-link] is a useful resource.

[google-link]: https://google.com
```

그러면 "If you want some more information, [Google][google-link] is a useful resource."로 렌더링돼요.

## 코드

코드 요소(예: 함수나 키워드)를 언급할 때는 코드를 백틱으로 감싸야 해요:

```
- The `printf()` function writes to the console.
```

그러면 다음과 같이 렌더링돼요:

- The `printf()` function writes to the console.

더 복잡한 코드(예: 여러 줄짜리 코드)는 백틱 세 개로 감싸야 해요. 구문 강조를 사용하려면 여는 백틱 세 개 뒤에 [언어 식별자][language-identifier]를 지정해야 해요:

````python
```python
# Define a variable
album = "Abbey Road"
```
````

가능하면 코드가 제시되는 환경에 가장 적합한 방식으로 코드를 포맷해요. 사용할 수 있다면 해당 언어의 문서를 참고해 주세요.

예를 들어, Python에는 REPL(read-eval-print loop)이 있어서 프로그래머가 터미널에 코드를 직접 입력할 수 있어요. 사용자가 코드를 디버깅하거나, 함수가 어떻게 동작하는지 로컬에서 실행해 테스트하고 관찰할 때는 그곳에서 상호작용하며 입력하는 편이 더 편리하기 때문에 REPL을 사용할 가능성이 높아요. 이런 상황에서는 예제 코드를 REPL에 입력하듯 앞에 `>>>`를 붙여 포맷하는 걸 선호해요:

```python
# This is the expected output a student would see while testing a function they wrote.
>>> print(extract_message("[INFO] Logline message"))
'Logline message'
```

다른 경우에는 코드를 `.py` 파일에 있는 것처럼 포맷해 두는 게 더 합리적이에요. 이때는 학생이 코드를 직접 작성하는 방식과 비슷한 형태로 코드를 보게 되므로 도움이 돼요.

```python
# presenting how functions are defined in Python:
def sample_func(argument1):
    pass
```

명확하지 않을 때 두 경우를 구분하는 빠른 방법이 있어요. 학생이 터미널에서 실행할 수 있는 코드라면 그렇게 포맷해요. Exercism이 실행할 코드(테스트, 학생이 작성할 라이브러리 코드 등)라면 실행 가능한 코드로 포맷하는 걸 기본으로 해요.

## 특별 블록 (어드모니션이라고도 해요)

본문에 어울리지 않는 부연을 따로 뽑아내기 위해 문서에 추가할 수 있는 특별한 유형의 블록을 지원해요.

<img width="500" alt="Markdown 고급 블록" src="https://user-images.githubusercontent.com/20866761/139531236-72259046-68a9-4934-9440-a730befde155.png">

세 가지 유형의 블록을 지원해요:

- **exercism/note:** 특별한 정보를 따로 뽑아 보여 주는 블록이에요
- **exercism/caution:** 알아 두거나 주의해서 다뤄야 하는 내용이에요
- **exercism/advanced:** 어떤 주제를 더 깊이 파고들고 싶어 하거나, 좀 더 고급 지식을 갖춘 것으로 기대되는 사람에게만 관련 있는 정보예요.

모든 블록은 4개의 물결표를 사용해 다음과 같은 형태로 작성해요:

````
~~~~exercism/note
Content goes here

You can include code:
```ruby
str = "Hello, World"
```

A [reference link][forum-link] must have the link definition inside the block.

[forum-link]: https://forum.exercism.org/t/link-references-in-special-blocks-admonitions-are-not-rendered/3803
~~~~
````

(참고: 예외적인 상황에서는 백틱이나 다른 개수의 물결표를 사용해도 돼요)

## 레이아웃

### 한 줄에 한 문장

단락은 한 줄에 한 문장씩 배치해야 해요. [Ascii Doctor 문서][asciidoctor]가 이 논리를 명확하게 설명해 줘요.

예를 들어, 하나의 단락은 다음과 같이 배치해야 해요:

```
Exercism has been designed, engineered and built by thousands of very talented individuals.
Nearly everything with Exercism has been debated, discussed and rewritten many times.
Exercism is a very intentional product - things are there because they've been designed to be there, and things are often left out because they've been designed to be left out.
```

순서 없는 목록에는 하이픈 문자(`-`)를 불릿 목록 표시로 사용해요.

## 주석

- HTML 주석 대신 Markdown 주석을 선호해요(예: `<!-- Actual comment -->` 대신 `[comment]: # (Actual comment...)`를 사용해요)

Markdown 주석이 제거되는지 테스트하려면 [babelmark3]에서 commonmark로 렌더링했을 때 주석이 어떻게 보이는지 확인하면 돼요.

## 인라인 HTML

- 인라인 HTML은 허용되지만, 아껴서 사용해야 해요
- 사용할 수 있다면 항상 기본 Markdown 대안을 사용해요(예: `<h1>...</h1>` 대신 `# ...`를 사용해요)

## 이미지

웹사이트가 라이트 테마와 다크 테마를 지원하기 때문에, 커뮤니티가 제출한 이미지는 두 테마 모두에서 잘 보여야 해요.
이에 대한 해결책은 이미지 이름(파일 확장자 앞)에 접미사를 붙이는 거예요:

1. 이미지 이름이 `-invertible`로 끝나게 해요(예: `graph-invertible.svg`). 이 이미지는 다크 테마에서 표시될 때 자동으로 반전돼요(`filter: invert(100%)` 사용).
1. 이미지 이름이 `-light`로 끝나게 하고(예: `graph-light.png`), `-dark`로 끝나는 다크 테마 호환 버전도 만들어요(이 경우 `graph-dark.png`). 사용자의 테마에 따라 올바른 이미지를 자동으로 렌더링해요.

두 접미사가 모두 없는 이미지는 두 테마에서 수정 없이 그대로 사용돼요.
즉, 그레이스케일 이미지를 만들고 싶다면 일반적으로 라이트 테마에서 잘 보이게 만든 다음, 반전 가능하도록 설정하면 돼요.
하지만 색이 많은 이미지를 사용한다면 두 가지 버전을 만드는 게 좋을 수 있어요.

이미지가 렌더링되는 Markdown 위치에는 (`-invertible`을 포함한) 전체 이미지 이름을 넣어야 해요.
라이트/다크 이미지의 경우에는 `-light` 버전**만** 포함해요.
이 논리는 모든 Markdown 문서에서 지켜져요.

## 자동 포맷

일부 저장소는 모든 Markdown이 일관되게 포맷되도록 [prettier][prettier]를 사용해요. 그러면 다음과 같은 이점이 있어요:

- 포맷 논쟁이 없어요.
- 파일을 저장할 때 포맷할 수 있도록 편집기/IDE와 잘 통합돼요.
- 포맷 검사를 CI에 쉽게 추가할 수 있어요.
- 스크립트로 파일을 자동 포맷하기 쉬워요.

위의 모든 것은 리뷰에서 오가는 불필요한 변경을 크게 줄여 줘요. 이런 변경은 리뷰하는 사람과 리뷰받는 사람 모두를 지치게 해요.
