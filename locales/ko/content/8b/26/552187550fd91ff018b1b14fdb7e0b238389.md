# 지침

최근 보안 검토를 거친 뒤, 조직의 보관된 로그 파일을 정리해 달라는 요청을 받았어요.

## 1. 잘못된 로그 줄 식별하기

보관된 로그 줄 중에서 현재 표준을 따르지 않는 줄이 얼마나 되는지 파악해야 해요.
간단한 검사로 로그 줄이 유효한지 알 수 있다고 생각해요.
유효한 줄로 인정되려면 다음 문자열 중 하나로 시작해야 해요:

- `[DEBUG]`
- `[INFO]`
- `[WARNING]`
- `[ERROR]`

로그 줄이 유효하면 `True`를 반환하도록 `is_valid_line` 함수를 구현해요.

```gleam
log_parser.valid_line("[ERROR] Network Failure")
// -> True

log_parser.valid_line("Network Failure")
// -> False
```

## 2. 로그 줄 나누기

로그 파싱 프로젝트를 시작한 지 얼마 안 되어, 한 애플리케이션의 로그는 다른 로그들처럼 줄로 나뉘어 있지 않다는 걸 알게 돼요. 이 프로젝트에서는 원래 별도의 줄이어야 할 내용이 하나의 줄에 담겨 있고, `<--->`나 `<*~*~>` 같은 특이한 화살표로 연결되어 있어요.

실제로 첫 문자가 `<`, 마지막 문자가 `>`이고, 그 사이에 `~`, `*`, `=`, `-` 문자가 0개 이상 있는 문자열은 모두 이 프로젝트의 로그에서 구분자로 사용할 수 있어요.

줄을 받아서 문자열 배열을 반환하는 `split_line` 함수를 구현해요.

```gleam
log_parser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
// -> ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. 줄에 사용자 이름 태그 달기

일부 로그 줄에 사용자를 가리키는 문장이 포함되어 있다는 걸 눈치챘어요.
이런 문장에는 항상 문자열 `"User"`가 있고, 그 뒤에 하나 이상의 공백 문자가 오고, 그다음에 사용자 이름이 와요.
그런 줄에는 태그를 달기로 해요.

로그 줄을 처리하는 `tag_with_user_name` 함수를 구현해요:

- 문자열 `"User"`를 포함하지 않는 줄은 그대로 둬요.
- 문자열 `"User"`를 포함하는 줄에는 줄 앞에 `[USER]`와 사용자 이름을 붙여요.

```gleam
log_parser.tag_with_user_name("[INFO] User Alice created a new project")
// -> "[USER] Alice [INFO] User Alice created a new project"
```

다음과 같다고 가정해도 돼요:

- 문자열 `"User"`가 나올 때마다 그 뒤에 하나 이상의 공백 문자와 사용자 이름이 와요.
- 각 줄에는 문자열 `"User"`가 많아야 한 번 나와요.
- 사용자 이름은 공백을 포함하지 않는 비어 있지 않은 문자열이에요.
