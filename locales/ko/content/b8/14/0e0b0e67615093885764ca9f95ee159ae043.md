# 소개

교육 과정에서 이쯤 오면, R이 명령형 언어로 자주 쓰이는 모습을 봤을 거예요. 그리고 점점 더 함수형 언어로도 쓰이는 모습도요(특히 [`purrr`][ref-purrr]와 [`dplyr`][ref-dplyr] 라이브러리와 함께요).

이제 와서 R이 주로 객체 지향이라고 하면 좀 회의적으로 들릴 수도 있어요!

이상하게도, 이 말은 사실이에요.
내부적으로 R은 클래스, 상속, 다형성, 그리고 OOP 프로그래머들에게 흔한 사고방식 같은 걸 사용해 구현돼 있어요.

하지만 Java나 Ruby(명시적 OOP), 또는 Python(어떤 면에서는 반쯤 숨은 OOP)에 익숙한 사람이라면 R의 접근 방식이 ... _낯설게_ 느껴질 거예요.

우선 클래스 설계가 여러 가지예요. 흔히 쓰이는 게 아마 세 가지(S3, S4, R6)이고, 그 외에 주로 이론적인 관심 대상인 여러 방식도 있어요.

자세한 논의는 [Advanced R, 2e][book-advanced-r]의 12~16장에서 찾을 수 있어요.
이 2019년 책은 R의 내부를 이해하고 유지 보수하려는 사람을 주로 대상으로 하기 때문에 OOP가 꼭 필요해요.

최종 사용자에 더 초점을 맞춘 교재들은 조금씩 달라요.

- The Art of R Programming(2011, 종이책만)에는 OOP 장이 있어서 당시 중요했던 S3와 (더 짧게) S4를 다뤄요.
  _"S3 클래스는 구조가 꽤 임시변통으로 짜맞춘 듯하다"_라는 코멘트는 지금도 놀랍도록 사실이에요.
- R in Action(3판, 2022)은 OOP를 뒤쪽의 고급 프로그래밍 장에서 3쪽으로만 다뤄요.
- [R for Data Science, 2e][book-r-data-sci](2023, 종이책 기준 548쪽)는 OOP를 전혀 언급하지 않아요.

이번 개념에서는 S3 클래스에 집중해요. S3 클래스는 가장 단순하고 가장 흔하며 Exercism 유형의 문제와 가장 관련이 깊어요.
R 트랙의 일부 연습 문제는 S3 클래스를 만들도록 요구하고, 다른 문제들은 선택 사항이지만 살짝 권장해요.

## S3 클래스

이건 오래됐어요. S3라는 이름은 S 언어(R의 상업적 전신) 버전 3에서 도입됐다는 뜻일 뿐이에요.

S3 클래스도 아주 단순해요. 보통 추가 속성이 최소 하나 있는 [배열][concept-lists]이에요.

[Advanced R][book-s3]을 인용하면 이래요. _"S3는 격식 없고 즉흥적이지만, 그 미니멀리즘에는 나름의 우아함이 있어요. 어느 한 부분이라도 떼어 내고서도 쓸모 있는 OO 시스템이 되지는 않아요."_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

그래서 [`class(obj)`][ref-class]에 값을 할당하면 `obj`에 속성이 하나 추가될 뿐이에요. 여기서는 pt2d를 point2d 클래스의 인스턴스로 식별해 줘요.

생성 단계는 [`structure()`][ref-structure]로 합칠 수 있어요:

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

결과로 나온 인스턴스들은 개념상 동일하지만, R이 이걸 확인할 방법은 아직 구현하지 않았어요.

### 제네릭 메서드

다른 언어의 OOP에 익숙한 사람이라면 이렇게 궁금할 수 있어요. _"클래스는 뭔가를 할 수 있어야 하는 거 아니에요?"_

`point2d` 인스턴스에 사용할 수 있는 메서드를 확인해 보면, (바탕이 되는 `list`와 달리) 지금은 아무것도 없다는 걸 알 수 있어요.

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

대부분의 OOP 언어에서는 메서드를 클래스 정의 안에 정의해요.
몇몇 언어(특히 Ruby)는 나중에 클래스 메서드를 추가하고 수정할 수 있게 해줘요.

S3 클래스는 아주 달라요.
클래스에 메서드를 추가하는 대신, 제네릭 메서드에 클래스를 추가해요.

R 콘솔에서 대화형으로 작업하는 사람은 누구나 제네릭 메서드를 늘 사용해요. 보통은 그게 어떻게 구현됐는지 생각하지 않고요.

아주 흔한 예가 `print()`예요. 함수 이름을 직접 입력하는 일은 거의 없지만요.
콘솔 프롬프트에서 값 `x`를 그냥 입력하는 건 `print(x)`의 문법적 설탕일 뿐이에요.

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

`pt2d`는 이미 출력할 수 있어요.
`print()`는 `point2d` 클래스에 대해 아무것도 모르지만, 다양한 객체를 처리할 수 있는 합리적인 기본 동작을 갖고 있어요.

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

꽤 장황하죠. 그래서 이 점을 간결하고 보기 좋게 출력할 방법이 있으면 좋겠어요.

간단해요. `print.point2d()`라는 함수를 추가하면 돼요.
이름은 `methodname.classname` 형식이어야 해요. 그래야 디스패처가 무엇을 찾아야 할지 알 수 있어요.

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

이제 새 제네릭 메서드를 만들고 싶다고 해봐요. 예를 들어 `y` 좌표의 부호를 반대로 바꾸는 `flipvert()`요.

이번에도 간단해요:

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

이렇게 하면 디스패처가 만들어져요. 여기서 `x`는 S3 클래스를 가진 객체이고, `...`는 메서드 정의에 필요할 수 있는 추가 인자를 처리해요([함수 개념][concept-functions]에서 설명하는 "dot args"예요).

그런 다음 `point2d`에 대한 메서드를 정의하고 사용할 수 있어요.

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

이제 R은 점을 뒤집는 방법과 결과를 표시하는 방법을 알아요.

3D나 극좌표 등을 위한 클래스를 만들고 각각에 메서드를 정의해서 이걸 확장할 수도 있어요.

최종 사용자 입장에서는 `flipvert(x, ...)`만 있고, 입력 클래스를 판별해 알맞은 내부 구현을 사용하는 건 R에 맡기면 돼요.

~~~~exercism/caution
`verb.class` 형식의 함수 이름은 사용자에게도, R 파서에게도 S3 메서드처럼 보여요.
다른 맥락에서는 비슷한 이름 짓기를 피해 주세요.

물론 기본 R도 가끔 이 규칙을 어기기도 해요.
이건 안타까운 역사적 사고로 봐야 하고(S3보다도 오래된 함수들에 있는), 하위 호환성을 위해 유지해야 해요.
~~~~

### 상속

OOP 애호가들은 상속, 서브클래싱, 믹스인 등등에 대해 교재 여러 장을 길게 쓸 수 있어요.

R은 그냥 `class` 속성에 여러 이름을 넣을 수 있게 해줘요. 문자열 하나가 아니라 더 긴 문자열 벡터요.

예시를 무리하게 늘려 볼 위험을 무릅쓰고, 일반적인 `point` 클래스를 만들고 이걸 `point2d`, `point3d` 등으로 서브클래싱하고 싶다고 해봐요.

그러면 `point2d` 정의는 그냥 `class = c("point2d", "point")`를 사용해요. 특정 클래스와 부모 클래스(또는 클래스들)예요.

그러면 `print()` 같은 제네릭 메서드가 `print.point2d()`, `print.point()`, 그리고 (아마) `print.default()`를 차례로 찾고, 디스패처가 가장 먼저 찾은 구현을 사용해요.

### 안전성

많은 OOP 언어(Java, C# 등)는 클래스 안의 데이터 캡슐화를 활용해 꼼꼼한 컴파일 타임 검사를 하고 타입 안전성을 강제해요.

S3는 말이 안 되는 짓이라도 거의 뭐든 할 수 있게 해준다는 걸 알아 두세요(오류 메시지가 나온다면 나중에 나오고, 아예 안 나올 수도 있어요).

["Advanced R"][book-s3](2판, 13.3절)을 인용하면 이래요:

> _다른 OO 언어를 써 봤다면 이게 좀 속이 울렁거릴 수도 있어요. 하지만 실제로는 이 유연성이 문제를 거의 일으키지 않아요. R은 제 발등을 찍는 걸 막아 주지 않아요. 하지만 총을 발가락에 겨누고 방아쇠를 당기지만 않으면 문제없어요._

뭐, _그럴 수도 있죠?_
R은 탐색적 데이터 과학과 통계에 뛰어나요. 흔히 대화형으로 작업할 때 말이죠.
R로 보안이 아주 중요한 기업 금융 시스템을 작성하라고 권하는 사람은 아무도 없어요!
