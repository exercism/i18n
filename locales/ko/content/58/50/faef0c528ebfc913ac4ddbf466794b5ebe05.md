# 소개

Go의 슬라이스는 다른 언어의 배열과 비슷해요.
특정 타입(또는 인터페이스)의 원소 여러 개를 담아요.

Go의 슬라이스는 배열을 기반으로 해요.
배열은 크기가 고정되어 있어요.
반면에 슬라이스는 동적으로 크기가 변하는, 배열 원소에 대한 유연한 뷰예요.

슬라이스는 `[]T`처럼 쓰고, `T`는 슬라이스에 담기는 원소의 타입이에요:

```go
var empty []int                 // an empty slice
withData := []int{0,1,2,3,4,5}  // a slice pre-filled with some data
```

0부터 시작하는 인덱스로 원소를 가져오거나 설정할 때는 대괄호 표기법을 사용해요:

```go
withData[1] = 5
x := withData[1] // x is now 5
```

기존 슬라이스에서 원소 범위를 가져와 새 슬라이스를 만들 수 있어요.
이때도 대괄호 표기법을 사용하는데, 시작 인덱스(포함)와 끝 인덱스(미포함)를 모두 지정해요.
시작 인덱스를 지정하지 않으면 0이 기본값이에요.
끝 인덱스를 지정하지 않으면 슬라이스의 길이가 기본값이에요.

```go
newSlice := withData[2:4]
// => []int{2,3}
newSlice := withData[:2]
// => []int{0,1}
newSlice := withData[2:]
// => []int{2,3,4,5}
newSlice := withData[:]
// => []int{0,1,2,3,4,5}
```

`append` 함수로 슬라이스에 원소를 추가할 수 있어요.
아래에서는 `a` 슬라이스에 `4`와 `2`를 추가해요.

```go
a := []int{1, 3}
a = append(a, 4, 2)
// => []int{1,3,4,2}
```

`append`는 항상 새 슬라이스를 반환하는데, 기존 슬라이스에 원소를 추가하고 싶을 때는 위에서처럼 첫 번째 인자로 넘긴 슬라이스 변수에 결과를 다시 할당하는 경우가 많아요.

`append`로 두 슬라이스를 합칠 수도 있어요:

```go
nextSlice := []int{100,101,102}
newSlice  := append(withData, nextSlice...)
// => []int{0,1,2,3,4,5,100,101,102}
```

## 슬라이스의 인덱스

슬라이스의 인덱스를 다룰 때는 인덱스가 실제로 존재하는지 확인하는 검사로 항상 어느 정도 보호해야 해요.
그렇게 하지 않으면 애플리케이션 전체가 중단돼요.

## 빈 슬라이스

`nil` 슬라이스가 기본 빈 슬라이스예요.
값이 하나도 없는 슬라이스에 비해 아무런 단점도 없어요.
`len` 함수가 `nil` 슬라이스에서도 동작하고, 초기화하지 않고도 원소를 추가할 수 있는 등등이에요.
새 슬라이스를 만들 때는 `s := []int{}`(비어 있지만 `nil`이 아닌 슬라이스)보다 `var s []int`(`nil` 슬라이스)를 선호해요.

## 성능

슬라이스를 만들어 반복적으로 채울 때, 최종 크기를 알고 있다면 성능을 개선할 수 있는 손쉬운 방법이 있어요.
핵심은 메모리를 할당하는 횟수를 최소화하는 거예요. 메모리 할당은 꽤 비용이 큰 작업이고, 슬라이스가 할당된 메모리 공간을 넘어 커지면 일어나요.
가장 안전한 방법은 `s := make([]int, 0, cap)`처럼 슬라이스에 용량 `cap`을 지정한 다음 평소처럼 슬라이스에 `append`하는 거예요.
이렇게 하면 슬라이스 길이는 0인 채로 `cap`개 원소만큼의 공간이 즉시 할당돼요.
실제로는 `cap`에 다른 슬라이스의 길이를 넣는 경우가 많아요: `s := make([]int, 0, len(otherSlice))`.

## `append`는 순수 함수가 아니에요

Go의 `append` 함수는 성능을 위해 최적화되어 있어서 입력 슬라이스를 복사하지 않아요.
그래서 원본 슬라이스(`append`의 첫 번째 매개변수)가 때때로 바뀌기도 해요.
