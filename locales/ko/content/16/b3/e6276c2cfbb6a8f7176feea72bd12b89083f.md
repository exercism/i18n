# 개요

`Result` 타입은 Elm 언어에서 오류 보고와 오류 복구를 위한 해법이에요. `Maybe` 타입과 어느 정도 비슷하지만, `Maybe`의 `Nothing`은 어떤 실패를 나타낼 뿐 그 실패가 _왜_ 일어났는지는 알려주지 않아요. `Result`는 무언가가 왜 실패했는지에 대한 맥락까지 담고 있어요.

## 정의와 타입 변수

`Result` 타입은 다음과 같이 정의돼요:

```elm
type Result error value
  = Ok value
  | Err error
```

간단히 말해, 이 타입은 성공해서 `value`를 반환하거나 실패해서 그 실패에 대한 설명(`error`)을 반환할 수 있는 연산의 결과를 나타내요.

이런 것을 Elm 용어로 "custom type" 정의라고 해요. custom type은 이 트랙의 다른 개념에서 자세히 소개하지만, `Result`만 이해하는 데에는 필요하지 않아요. `OK value`와 `Error error`에서 `error`와 `value`는 타입 변수를 나타내는데, `Int`, `Bool`, `String`처럼 어떤 타입이든 될 수 있다는 뜻이에요. 따라서 `Result String Int`는 `Int`를 담을 것으로 기대되는 값이고, 오류가 있으면 그 오류는 `String`으로 표현돼요.

```elm
ageFromString : String -> Result String Int
ageFromString input =
  case String.toInt input of
    Nothing ->
      Err "That is not a number!"

    Just age ->
      if age < 0 then
        Err "Please try again after you are born."

      else if age > 135 then
        Err "Are you some kind of turtle?"

      else
        Ok age
```

## Result 값의 내용 읽기

`Result` 값의 내용은 "패턴 매칭"을 통해 읽어요. 패턴 매칭도 다른 개념에서 더 자세히 소개하니, 여기서는 `Result`를 패턴 매칭하는 방법에만 집중할게요.

```elm
formatAge : Int -> String
formatAge age =
    "You are " ++ toString(age)

howOldAmI : String -> String
howOldAmI age =
    case ageFromString age of
        Err message -> message
        Ok age -> formatAge age

howOldAmI "Bananas"
    --> "That is not a number!"

howOldAmI "32"
    --> "You are 32"
```

`Result` 값을 사용할 때마다 Elm 컴파일러는 코드가 가능한 모든 경우를 처리하는지 확인하기 때문에, `Result`를 패턴 매칭하면서 `Ok value`인 경우만 처리하는 일은 있을 수 없어요. 처음에는 번거롭게 느껴질 수 있지만, 이는 Elm 언어의 가장 큰 장점 중 하나예요. 이 덕분에 수백 개의 버그를 막을 수 있고, 컴파일러가 이끄는 리팩터링을 두려움 없이 즐겁게 해낼 수 있어요.

## Result 값의 내용 다루기

`Result` 타입을 다루는 여러 함수가 있는데, 보통은 패턴 매칭보다 이런 함수를 쓰는 게 더 좋아요. `Result.map`은 값을 매핑할 때 쓸 수 있고, `Result.andThen`은 실패할 수 있는 함수들을 이어 붙일 때 쓸 수 있어요.

Result.map은 Ok 값을 바꿀 때 사용하며, Result에 오류가 있는지 걱정하지 않고 함수들을 이어 붙이는 데 유용해요. 값이 Ok이면 Result.map은 이어 붙인 함수(아래의 `formatAge`)를 호출하지만, 오류가 있으면 Result.map은 아무것도 하지 않고 그 오류를 그대로 반환해요.

```elm
howOldAmI : String -> Result String String
howOldAmI age =
    Result.map formatAge (ageFromString age)

howOldAmI "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.map just returns the Err)

howOldAmI "32"
    --> Ok "You are 32" (ageFromString returns Ok 32, Result.map passses this to formatAge)
```

Result.andThen은 Ok 값을 바꿀 때 사용하며, Result에 오류가 있는지 걱정하지 않고 함수들을 이어 붙이는 데 유용해요. Result.map과 비슷하지만, Result.andThen은 Result를 반환하는 함수(아래의 `formatSpecialBirthday`)와 함께 동작해요. `Result.map`으로도 할 수 있지만, 그렇게 하면 중첩이 한 겹 더 생기는데, `andThen`은 이를 영리하게 피해요.

```elm
formatSpecialBirthday : Int -> Result String String
formatSpecialBirthday age =
    if age == 18 then
        Ok "Welcome to adulthood!"

    else if age == 65 then
        Ok "Welcome to retirement!"

    else
        Err "Not a special birthday"

specialBirthdayMessage : String -> Result String String
specialBirthdayMessage age =
    Result.andThen formatSpecialBirthday (ageFromString age)

specialBirthdayMessage "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.andThen just returns the Err)

specialBirthdayMessage "32"
    --> Err "Not a special birthday" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Err)

specialBirthdayMessage "18"
    --> Ok "Welcome to adulthood" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Ok)
    --> If we used Result.map, it would be OK (Ok "Welcome to audulthood"), which is annoying
```
