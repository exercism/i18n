# 개요

Julia는 대부분의 프로그래밍 언어처럼 다양한 컬렉션 타입을 제공해요.

어떤 컬렉션은 본질적으로 순서가 있어요(`Vectors`와 다차원 `Arrays` 등). 그래서 위치로 원소에 접근할 수 있어요.
다른 컬렉션은 순서가 없고(`Sets`, `Dicts`), 원소에 키나 값으로 접근해야 해요.

가장 단순한 경우를 생각해 봐요. `Ints`로 이루어진 `Vector`가 있고, 이를 오름차순으로 [정렬][ref-sorting]하고 싶다고 해요.

```julia-repl
julia> v = [3, 2, 4, 1]
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v)
4-element Vector{Int64}:
 1
 2
 3
 4

# sort descending
julia> sort(v, rev=true)
4-element Vector{Int64}:
 4
 3
 2
 1
```

간단하죠!
[`sort()`][ref-sort] 함수는 이름만 봐도 알 수 있고, 정렬된 `Vector`를 반환하는 것처럼 보여요.

_농담이에요!_
실러버스에서 이 단계쯤이면, 우리가 논의해야 할 미묘한 점이 있다는 걸 (제대로) 짐작하고 있을 거예요.

## 변경하는 함수와 변경하지 않는 함수

`sort(v)`를 실행한 뒤에 `v`는 어떻게 될까요?

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> issorted(v)
false
```

원래 벡터는 그대로예요.
`sort()`는 입력의 _복사본_을 반환하는 ***변경하지 않는*** 함수예요.

이건 많은 상황에서 좋은 설계예요. [순수 함수][wiki-pure-func]라서 병렬·분산 코드에서도 동작을 추론하기 쉬워요.

반면에, 10억 개의 문자열로 이루어진 배열을 정렬하고 싶다고 해요.

정렬은 아마 느릴 거예요(이건 나중에 더 다뤄요).
게다가 모든 것을 복사해야 하고(_느려요!_), 복사본을 저장할 메모리도 충분히 할당해야 해요(_몇 기가바이트나요!_).

이와 아주 비슷한 코드를 비교해 봐요:

```julia-repl
# v is as previously

julia> issorted(v)
false

julia> sort!(v)
4-element Vector{Int64}:
 1
 2
 3
 4

julia> v
4-element Vector{Int64}:
 1
 2
 3
 4

julia> issorted(v)
true
```

이제 입력 `Vector`는 복사 없이 제자리에서 정렬되고, 원래 순서는 영영 사라져요.

효율적일 수도 있고, 버그를 만들어 예상치 못한 [부작용][wiki-side-effect]을 일으킬 수도 있고, 코드를 사용하는 다른 사람을 혼란스럽게 할 수도 있어요.
_신중하게 선택해요!_

[`sort!()`][ref-sort!]는 [변경하는 함수][ref-mutating-func]예요. 그리고 (_아주 강한_) 관례에 따라, 입력을 변경하는 함수는 이름 끝에 `!`를 붙여 프로그래머에게 경고해요.

## 무엇을 기준으로 정렬할까요?

`Int64` 값을 정렬하는 건 비교적 간단해요. 어린아이도 2가 1보다 크고 3보다 작다는 걸 알아요.

다른 타입은 더 복잡할 수 있지만, 일반적으로 `isless(x, y) == true`이면 `x < y`예요.
Julia는 대부분의 표준 타입에 대해 `isless()` 구현을 제공하고, 여러분의 [사용자 정의 타입][concept-composite-types]을 비교하는 동등한 [메서드][concept-multiple-dispatch]를 정의할 수 있어요.

예를 들어, 유니코드 문자는 다음과 같아요(유럽 문자에서는 대문자가 소문자보다 먼저 정렬돼요):

```julia-repl
julia> j = collect("Julia")
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)

julia> sort(j)
5-element Vector{Char}:
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0false069 (category Ll: Letter, lowercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)
```

정렬하기 전에 각 항목에 임의의 함수를 적용할 수도 있어요. 부호를 무시하는 [`abs`][ref-abs]나 대소문자를 구분하지 않고 정렬하는 [`uppercase`][ref-uppercase]처럼요:

```julia-repl
julia> nums = [3, -2, -4, 1]
4-element Vector{Int64}:
  3
 -2
 -4
  1

julia> sort(nums)
4-element Vector{Int64}:
 -4
 -2
  1
  3

julia> sort(nums, by=abs)
4-element Vector{Int64}:
  1
 -2
  3
 -4

# j is from "Julia", as previously

julia> sort(j, by=uppercase)
5-element Vector{Char}:
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'i': ASCII/Unicode U+0069 (category Ll: Letter, lowercase)
 'J': ASCII/Unicode U+004A (category Lu: Letter, uppercase)
 'l': ASCII/Unicode U+006C (category Ll: Letter, lowercase)
 'u': ASCII/Unicode U+0075 (category Ll: Letter, lowercase)

julia> vecs = [[1, 3], [4, 2], [3, 4], [2, 1]];

julia> sort(vecs)  # by default sorts by the first element of the (2-element) vectors
4-element Vector{Vector{Int64}}:
 [1, 3]
 [2, 1]
 [3, 4]
 [4, 2]

julia> sort(vecs, by=last)
4-element Vector{Vector{Int64}}:
 [2, 1]
 [4, 2]
 [1, 3]
 [3, 4]
```

[다차원 배열][concept-mda]에서는 `dims` 키워드를 지정해 정렬 방향을 제어할 수 있어요.

```julia-repl
# create a matrix of integers in random order
julia> A = reshape(Random.shuffle(1:9), (3, 3))
3×3 Matrix{Int64}:
 8  4  9
 6  7  5
 2  1  3

julia> sort(A, dims=1)  # sort rows
3×3 Matrix{Int64}:
 2  1  3
 6  4  5
 8  7  9

julia> sort(A, dims=2)  # sort columns
3×3 Matrix{Int64}:
 4  8  9
 5  6  7
 1  2  3
```

## 인덱스 배열로 정렬하기

정렬할 원소가 큰 객체라면, 위치 인덱스로 다루는 게 더 쉬울 수 있어요.

```julia-repl
julia> langs = ["Julia", "C++", "Python", "Elixir"]
4-element Vector{String}:
 "Julia"
 "C++"
 "Python"
 "Elixir"

julia> inxs = sortperm(langs)  # => Integers
4-element Vector{Int64}:
 2
 4
 1
 3

julia> langs[inxs]  # sort the entire vector
4-element Vector{String}:
 "C++"
 "Elixir"
 "Julia"
 "Python"

julia> langs[inxs[1:2]]  # slice the indices
2-element Vector{String}:
 "C++"
 "Elixir"
```

`langs`가 Vector이므로 각 인덱스는 [범위][concept-range] `1:length(langs)` 안의 정수예요.
Vector에 [sortperm()][ref-sortperm]을 호출한 결과는 이 정수들의 [순열][wiki-permutation]이고, 이는 입력 Vector를 정렬한 것에 대응해요.

## 부분 정렬

프로그램이 입력 전체를 정렬할 필요가 있나요?
앞쪽 몇 개나 뒤쪽 몇 개 항목에만 관심이 있는 경우, [부분 정렬][wiki-partial-sort]을 하면 훨씬 빠를 수 있어요.

Julia는 [`partialsort()`][ref-partialsort]와 [`partialsort!()`][ref-partialsort!] 함수를 제공해요. 이 함수들은 지정한 항목이나 항목 범위가 올바르다는 것만 보장하고, 나머지 입력에 대해서는 아무것도 보장하지 않아요.

두 번째 인자는 정수나 범위일 수 있고, 정렬된 입력에서의 인덱스를 나타내요:

```julia-repl
julia> vsq = [9, 4, 16, 1];  # would be [1, 4, 9, 16] after a full sort

julia> partialsort(vsq, 4)
16

julia> partialsort(vsq, 2:3)
2-element view(::Vector{Int64}, 2:3) with eltype Int64:
 4
 9
```

## 정렬 알고리즘

`[3, 2, 4, 1]`을 정렬하는 건 사람이든 컴퓨터든 쉬운 과제예요.

입력이 _훨씬_ 크다면, 정렬하는 가장 좋은 방법은 무엇일까요?

이러면 '가장 좋은'이 뭔지 정의해야 해요!

- 평균 시간이 가장 빠른가?
- 최선의 경우인가, 최악의 경우인가? 아니면 90번째 백분위 시간처럼 그 중간 기준인가?
- 메모리 사용량이 최소인가?
- 현재 애플리케이션에 '충분히 좋은' 근사 정렬이나 부분 정렬인가?

또, 입력은 무엇인가요?
거의 무작위일 수도 있지만, 이미 정렬되어 있거나 역순으로 정렬되어 있거나 같은 항목이 많이 반복되는 배열 같은 특수한 경우도 있어요.
이런 상황에서 알고리즘마다 성능이 크게 달라져요.

새롭고 더 나은 정렬 알고리즘을 설계하는 일은 (_특정 성향의 사람에게는_) 지적으로 매혹적이고 상업적으로도 가치가 있어요. _강력한 조합이죠!_

그래서 이 주제에 관한 방대한 문헌이 있고, 지금도 꾸준히 늘고 있어요.

Julia는 대부분의 경우 합리적인 기본 알고리즘을 선택하려고 해요. 필요하면 프로그래머가 [원하는 알고리즘을 지정][ref-algorithms]할 수도 있어요.

다음의 장난감 예제는 우스꽝스럽지만 문법을 잘 보여줘요:

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v, alg=InsertionSort)
4-element Vector{Int64}:
 1
 2
 3
 4
```
