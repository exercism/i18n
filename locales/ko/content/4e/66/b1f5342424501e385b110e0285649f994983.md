# 지시 사항

신호소의 코드 생성 툴킷을 관리하고 있어요. 각 매크로는 *스텐실*, 즉 컴파일러가 호출 지점마다 특수화된 코드를 찍어 내는 데 쓰는 작은 템플릿이에요.

직접 작성할 것은 네 개의 매크로뿐이에요. 테스트 파일은 여러분의 매크로를 *호출*하는 작은 래퍼 워드들을 정의하고(매크로는 자신이 생성하는 코드를 통해서만 볼 수 있어요), 이어서 래퍼들의 런타임 결과를 검사해요. 래퍼는 그대로 두면 돼요.

각 과제에서 매크로 본문은 호출 지점의 리터럴 입력을 스택으로 받고, **쿼테이션 하나**를 남겨야 해요. '컴파일 결과' 줄은 쿼테이션이 만들어 내야 하는 직선 코드를 보여줘요.

## 1. 두 번 실행

`twice`는 리터럴 쿼테이션을 받아서, 원본을 두 번 연달아 실행하는 쿼테이션을 반환해요.

```factor
! : inc-twice ( x -- y ) [ 1 + ] twice ;
! body receives [ 1 + ]  ->  must build [ 1 + 1 + ]
5 inc-twice .   ! => 7
```

## 2. N번 반복

`repeat-quot`은 리터럴 쿼테이션과 리터럴 개수 `n`을 받아서, 원본을 `n`번 연달아 실행하는 쿼테이션을 반환해요. `n = 0`이면 빈 쿼테이션 `[ ]`를 반환해요.

```factor
! : inc-thrice ( x -- y ) [ 1 + ] 3 repeat-quot ;
! body receives [ 1 + ] 3  ->  must build [ 1 + 1 + 1 + ]
5 inc-thrice .   ! => 8
```

## 3. 여러 개 합성하기

`compose-many`는 쿼테이션들이 담긴 리터럴 배열을 받아서, 각 쿼테이션을 차례로 실행하는 쿼테이션 하나를 반환해요. 빈 배열이면 빈 쿼테이션을 반환해요.

```factor
! : pipeline ( x -- y ) { [ 1 + ] [ 2 * ] [ 1 - ] } compose-many ;
! body receives { [ 1 + ] [ 2 * ] [ 1 - ] }  ->  must build [ 1 + 2 * 1 - ]
5 pipeline .   ! => 11
```

## 4. 전개된 반복

`each-literal`은 리터럴 시퀀스와 쿼테이션을 받아요. 시퀀스의 각 원소를 스택에 올린 다음 쿼테이션을 실행하는 쿼테이션을 반환하죠. 컴파일 시간에 일어나는 반복이라, 생성되는 코드는 직선 코드예요.

```factor
! : sum-three ( -- n ) 0 { 10 20 30 } [ + ] each-literal ;
! body receives { 10 20 30 } [ + ]  ->  must build [ 10 + 20 + 30 + ]
sum-three .   ! => 60
```

이 넷 중에서는 생성되는 코드의 구조가 가장 크게 달라지는 과제예요. 시퀀스의 길이*와* 원소 값이 모두 코드의 모양을 결정하죠. 힌트에서 한 단계씩 만들어 가는 과정을 안내해요.
