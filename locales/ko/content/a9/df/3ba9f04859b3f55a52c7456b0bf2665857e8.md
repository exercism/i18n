# 안내

_Instruments of Texas_에서 일하는 동안, RPN 계산기의 Elixir 구현에 진전이 있었어요. 팀은 표준 라이브러리가 제공하는 일반적인 오류보다 더 구체적인 오류를 발생시킬 수 있기를 바라고 있어요. 지금은 조사를 좀 하고 있지만, _Exception Behaviour_를 구현하는 두 가지 새로운 오류를 만들기로 결정했어요.

## 1. 0으로 나누기 오류

숫자를 0으로 나누면 정의되지 않은 결과가 나오는데, 팀은 이를 오류로 나타내는 것이 가장 좋다고 판단했어요.

오류 메시지가 `"division by zero occurred"`가 되도록 `DivisionByZeroError` 모듈을 구현해요.

```elixir
raise DivisionByZeroError
# => ** (DivisionByZeroError) division by zero occurred
```

## 2. 스택 언더플로가 발생했을 때의 오류

RPN 계산기는 숫자들이 더해지기 전에 이들을 추적하기 위해 _스택_을 사용해요. 팀은 이 _스택_을 숫자(정수와 실수)의 배열로 표현하는데, 예를 들어 `[3, 4.0]`과 같아요. 각 연산은 계산을 수행하기 위해 스택에 특정 개수의 숫자가 있어야 해요. 스택에 숫자가 충분하지 않을 때, 이를 스택 언더플로 오류라고 해요. 기본 메시지와 선택적인 추가 컨텍스트를 제공하는 `StackUnderflowError` 예외를 구현해요.

```elixir
raise StackUnderflowError
# => ** (StackUnderflowError) stack underflow occurred

raise StackUnderflowError, "when dividing"
# => ** (StackUnderflowError) stack underflow occurred, context: when dividing
```

## 3. 나누기 함수 작성하기

스택 _(숫자 두 개의 배열)_ 을 받아 다음과 같이 동작하는 `divide/1` 함수를 구현해요.

- 스택에 숫자가 충분하지 않으면 _스택 언더플로_ 오류를 발생시켜요
- 제수가 0이면 _0으로 나누기_ 오류를 발생시켜요 (숫자 스택은 역순으로 저장된다는 점에 주의해요)
- 오류가 발생하지 않으면 나눗셈을 수행해요

```elixir
RPNCalculator.Exception.divide([])
# => ** (StackUnderflowError) stack underflow occurred, context: when dividing

RPNCalculator.Exception.divide([0, 100])
# => ** (DivisionByZeroError) division by zero occurred

RPNCalculator.Exception.divide([4, 16])
# => 4
```

> 배열의 순서는 뒤집혀 있다는 점에 주의해요!
