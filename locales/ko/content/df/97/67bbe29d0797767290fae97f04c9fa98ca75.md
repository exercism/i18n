# 예외

이상적인 세계에서는 모든 것이 완벽하게 동작해요.
하지만 현실에서는 일이 잘못될 수 있고, 이런 상황을 어떻게 처리하느냐가 소프트웨어를 견고하고 안정적으로 만드는 데 중요해요.
예외는 오류와 예상치 못한 상황을 우아하게 처리할 수 있게 해 주는 프로그래밍의 중요한 개념이에요.

오류를 발생시켰을 때 처리하지 않으면 프로그램이 멈추고 오류 메시지를 출력해요.
대부분의 경우 오류가 발생했을 때 프로그램이 멈추는 것을 원하지 않고, 오류를 처리한 뒤 프로그램을 계속 실행하고 싶어 해요.

## 예외 발생시키기

Crystal에서는 `raise` 키워드로 예외를 발생시킬 수 있고, `String`이나 `Exception` 객체를 전달할 수 있어요.
처리하지 않으면 프로그램이 멈추고 오류 메시지를 출력해요.

```crystal
raise "This is an error"
```

Crystal에는 `ArgumentError`, `IndexError`, `KeyError`, `IOError`, `SystemCallError`, `TypeError`, `ZeroDivisionError` 등 여러 내장 예외가 있어요.
이런 예외에는 메시지를 전달해야 해요.

```crystal
raise ArgumentError.new("This is an argument error")
```

## [예외 처리][exception-handling]

예외가 발생했을 때 프로그램이 중단되는 것은 바라지 않아요.
그래서 오류가 발생하기 쉬운 코드가 있다면, 그 코드를 `begin` 블록으로 감싸고 `rescue` 블록으로 예외를 처리할 수 있어요.
`begin` 블록은 예외가 발생할 수 있는 코드의 시작을 표시하고, `rescue` 블록은 예외를 처리해요.

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
end
```

`rescue` 블록에 변수를 지정해서 예외 객체를 받을 수도 있어요.

```crystal
begin
 raise "This is an error"
rescue ex
 puts "An error occurred: #{ex.message}"
end
```

`rescue` 블록에 특정 예외 타입만 지정해서 그 예외만 잡을 수도 있어요.

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
end

# or

begin
 raise ArgumentError.new("This is an argument error")
rescue ex : ArgumentError
 puts "An argument error occurred: #{ex.message}"
end
```

여러 개의 `rescue` 블록을 사용해서 서로 다른 타입의 예외를 처리할 수 있어요.
아래 예제에서 첫 번째 `rescue` 블록은 `ArgumentError`를 잡고, 두 번째 `rescue` 블록은 그 밖의 다른 예외를 잡아요.

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
rescue
 puts "An error occurred!"
end
```

`begin` 블록에는 `else` 블록을 둘 수도 있는데, 예외가 발생하지 않았을 때 실행돼요.

```crystal
begin
 puts "No error occurred"
rescue
 puts "An error occurred!"
else
 puts "No error occurred"
end
```

마지막으로, 예외 발생 여부와 상관없이 항상 실행되는 `ensure` 블록이 있어요.

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
ensure
 puts "This is always executed"
end
```

## 메서드 관례

어떤 메서드는 `!`가 붙은 버전과 붙지 않은 버전, 두 가지가 있어요.
이는 두 가지 다른 의미일 수 있는데, 하나는 메서드가 객체를 변경한다는 뜻이고, 다른 하나는 메서드가 예외를 발생시킬 수 있다는 뜻이에요.

그런데 불리언 개념에서 언급한 것처럼, 메서드 이름을 `?`로 끝내는 또 다른 관례도 있어요.
어떤 메서드는 기본적으로 예외를 발생시키지만, 예외를 발생시키는 대신 `nil`을 반환하는 `?`로 끝나는 버전도 있어요.

오류가 발생하는 것을 피하고 싶을 때 이 방법이 이상적이에요.
스택트레이스를 만들 필요가 없어서 성능에 도움이 되고, 제대로 설정하면 코드를 더 안전하게 만들 수도 있어요.

## 사용자 정의 예외

[`Exception`][exception] 클래스를 상속해서 나만의 예외를 만들 수도 있어요.
이때 선택적으로 `initialize` 메서드를 재정의해서 예외 메시지를 설정할 수 있어요.
메시지를 담은 `@message`라는 인스턴스 변수를 할당하면 돼요.

```crystal
class MyException < Exception
 def initialize
   @message = "This is my exception"
 end
end

raise MyException.new
```
