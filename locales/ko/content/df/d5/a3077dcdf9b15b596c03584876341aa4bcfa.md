# 소개

거의 모든 Factor 프로그램은 *데이터 스택*에서 값을 소비하고 생산하는 단어들의 연속이에요. 입력과 출력이 깔끔하게 맞아떨어지면 코드는 군더더기 없이 왼쪽에서 오른쪽으로 읽혀요. 그렇지 않으면 *셔플 단어*에 손을 뻗게 되는데, 그러면 코드가 금방 지저분해져요.

이 연습 문제는 Factor의 표준 해법인 컴비네이터를 차근차근 안내해요.

## 셔플 단어

가장 흔히 쓰는 셔플 단어들은 [`kernel`][kernel]에 있어요:

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

`dup`과 `swap`은 이미 써봤을 거예요. `over`는 스택 맨 위에서 *두 번째* 원소의 복사본을 만들어요. 같은 입력을 두 계산에 넣어야 할 때 편리하죠:

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

한 번 쓰기에는 괜찮아요. 그런데 `dup`, `swap`, `over`, `rot`을 연달아 엮으면 금세 읽기 어려워져요.

## `keep`: 입력 보존하기

`keep`([`kernel`][kernel])은 스택 맨 위의 값에 쿼테이션을 호출하지만, 원래 값은 결과 위에 그대로 남겨둬요:

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

이건 `dup`하고 뭔가를 한 다음 셔플하는 패턴을 대신해요. `dup something swap`이라고 쓸 자리라면 어디든 `[ something ] keep`이라고 쓰면 돼요.

## `bi`: 하나의 입력에 두 함수

`bi`([`kernel`][kernel])는 같은 값에 *두 개*의 쿼테이션을 적용하고, 두 결과를 모두 스택에 남겨요:

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

`bi`가 없다면 `dup sq swap neg`라고 써야 해요. 두 개 연산까지는 그럭저럭 읽히지만, 세 개가 되면 골치 아파져요.

## `tri`와 `cleave`: 하나의 입력에 여러 함수

`tri`는 `bi`를 세 개의 쿼테이션으로 확장해요:

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

`cleave`([`combinators`][combinators])는 같은 발상을 임의 개수의 쿼테이션을 담은 *배열*에 적용한 거예요:

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

빈 쿼테이션 `[ ]`은 항등 역할을 해요. 나눈 조각 중 한 자리에 입력 자체가 들어가야 할 때 유용하죠.

## `dip`와 `2dip`: 아래에서 연산하기

`dip`([`kernel`][kernel])은 스택 맨 위 *아래*에 있는 값들에 쿼테이션을 호출하고, 맨 위 값은 건드리지 않아요. `2dip`은 같은 일을 하지만 맨 위 *두* 값을 보호해요:

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

여기서 `dip`은 `11`을 숨기고 `9 10 +`를 실행한 다음, `11`을 다시 맨 위에 올렸어요. `2dip`은 `11 12`를 숨기고 그 아래에서 `9 10 +`를 실행한 다음, `11 12`를 되돌려 놓았죠.

자연스러운 인자 순서 때문에 "그냥 지나가는" 값이 스택 맨 위에 남을 때 `dip`이 제대로 된 도구예요. `swap … swap` 샌드위치 대신 `dip`을 떠올려 봐요.

## `bi@`: 두 값에 같은 연산

`bi@`([`kernel`][kernel])는 하나의 쿼테이션을 스택의 두 값에 적용해요:

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*`: 두 값에 서로 다른 연산

`bi*`([`kernel`][kernel])는 스택의 두 값에 *서로 다른* 쿼테이션을 적용해요. 첫 번째 쿼테이션은 아래쪽 값에, 두 번째는 맨 위 값에 적용하죠:

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

두 값이 같은 처리를 받으면 `bi@`을, 각자 다른 처리가 필요하면 `bi*`를 떠올려 봐요.

## `tri*`: 세 값에 서로 다른 연산

`tri*`([`combinators`][combinators])는 `bi*`를 세 값과 세 쿼테이션으로 확장해서, 각 쿼테이션을 순서대로 값 하나씩에 적용해요:

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```
