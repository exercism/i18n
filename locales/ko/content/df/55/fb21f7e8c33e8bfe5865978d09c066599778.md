# 개요

컴비네이터는 스택 뒤섞기 패턴을 이름이 붙은, 조합 가능한 워드로 바꿔 줘요. Factor를 충분히 쓰다 보면 "`dup`하고, F를 실행하고, 원본을 남겨 둬야지" 하고 생각하는 대신 그냥 `[ F ] keep`이라고 쓰게 돼요.

| 패턴                               | 뒤섞기                        | 컴비네이터        |
|------------------------------------|-------------------------------|-----------------|
| F를 적용하고 입력을 보존           | `dup F swap`                  | `[ F ] keep`    |
| 입력 하나에 함수 두 개             | `dup F swap G`                | `[ F ] [ G ] bi`|
| 입력 하나에 함수 세 개             | 복잡함                        | `[ F ] [ G ] [ H ] tri` |
| 입력 하나에 함수 여러 개           | 아주 복잡함                   | `{ Fs … } cleave`|
| 맨 위 *아래*의 값을 조작           | `swap F swap`                 | `[ F ] dip`     |
| 값 두 개에 같은 연산               | `swap F swap F`               | `[ F ] bi@`     |
| 값 두 개에 다른 연산               | `swap F swap G`               | `[ F ] [ G ] bi*`|

`2`가 앞에 붙는 계열(`2bi`, `2dip`, `2tri`, `2dup`, `2drop`, `2nip`, `2swap`)은 각 연산이 입력 *두 개*를 필요로 할 때 같은 일을 해요. `3dup`과 `4dup`은 이 복제 관용구를 스택 맨 위의 값 세 개나 네 개로 확장해요.

cleave/dip/bi 계열을 넘어서, [`kernel`][kernel]은 `f`를 깔끔하게 전파하는 제어 흐름 변형도 제공해요.

| 워드        | 효과                                                |
|-------------|-----------------------------------------------------|
| `if*`       | 참인 분기는 값을 보고, 거짓인 분기는 보지 않아요    |
| `?last`     | 시퀀스의 마지막 원소, 비어 있으면 `f`               |
| `pop*`      | `pop`의 버림 변형 (벡터를 변경해요)                 |
| `dupd`      | 위에서 두 번째를 복제해요                           |
| `pick`      | 위에서 세 번째를 맨 위로 복사해요                   |
| `swapd`     | 위에서 두 번째와 세 번째를 맞바꿔요                 |
| `rotd`      | 네 개 깊이 스택의 아래쪽 세 개를 회전시켜요         |
| `tuck`      | 맨 위를 위에서 두 번째 아래로 복사해요              |
| `with`      | HOS를 위해 고정값을 쿼테이션에 미리 넣어요          |
| `while`     | 프레디킷이 성립하는 동안 반복해요                   |
| `until`     | 프레디킷이 성립할 때까지 반복해요                   |

알맞은 컴비네이터를 고르는 것 자체가 하나의 기술이에요. 일반적인 규칙은 이래요. 정의의 본문에 뒤섞기 워드가 연달아 두 개 이상 나오면, 보통 그 의도를 더 잘 담아내는 컴비네이터가 있어요.
