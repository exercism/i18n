# 소개

직접 작성한 어셈블리 코드는 반복투성이예요.
같은 명령어 몇 줄이 조금씩만 바뀐 채 몇 번이고 되풀이되고, 이런 반복을 줄여 줄 추상화는 거의 없어요.
게다가 어셈블리로 코딩하려면 뚜렷한 의미도 없는 값들을 직접 관리해야 해요.
이름이 붙은 매개변수도 없고, 뒤에서 돌아가는 구조의 세부 사항 대부분을 프로그래머가 직접 다뤄야 하죠.

이 트랙에서 사용하는 어셈블러인 NASM은 이 두 가지 문제를 모두 도와줄 도구를 몇 가지 제공해요.
이 도구들은 어떤 명령어도 프로세서에 도달하기 전, 즉 _어셈블 시점_ 에 동작해요.
소스 텍스트가 기계어로 번역되기도 전에, 어셈블러가 소스를 어떻게 고쳐 쓸지 알려주는 거예요.

그중 가장 중요한 도구가 **매크로**예요. 어셈블러를 위한 요리법이라고 생각하면 돼요.
매크로는 사용된 위치에 펼쳐져요. 마치 그 자리에 코드를 직접 써 넣은 것처럼요.

[매크로][macro]는 여러 리터럴 토큰을 매개변수로 받을 수 있어서, 다양한 상황에서 재사용할 수 있어요.
하지만 함수는 아니에요. `call`도 없고 `ret`도 없고, 코드의 다른 지점으로 제어를 옮기는 일도 없어요.

## 한 줄 매크로

가장 단순한 정의는 `%define`으로 값이나 짧은 식에 이름을 붙이는 거예요.

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

이후에 `WIDTH`가 나올 때마다 어셈블 전에 `8`로 바뀌어요.
치환이 텍스트 단위로 이뤄지기 때문에, 피연산자 안이든 다른 정의 안이든 이름이 나타나는 곳마다 그대로 바뀌어요.

~~~~exercism/note
숫자 _상수_ 에는 `%define` 대신 `equ`를 쓰는 게 좋아요.

`%define`으로 선언한 한 줄 매크로는 사용될 때만 펼쳐지고, 다시 지정하거나 정의를 해제할 수 있어요.
반면 `equ` 상수는 정의된 시점에 값이 정해지고, 그 뒤로 바뀌지 않아요.
~~~~

`%define`은 _이름이 있는_ 매개변수도 받을 수 있어서, 작은 인라인 함수처럼 동작해요.

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
본문 전체와 각 매개변수를 모두 괄호로 감싸요.
`%define square(x) x*x`라고 하면 `square(1+1)` 호출은 `1+1*1+1`로 펼쳐져서 `3`이 돼요.
`%define square(x) ((x)*(x))`라고 쓰면 같은 호출이 `((1+1)*(1+1))`로 펼쳐져서 `4`가 돼요.
~~~~

`%define`으로 정의한 이름은 대소문자를 구분해요.
변형인 `%idefine`을 쓰면, 필요할 경우 이름의 대소문자를 구분하지 않게 만들 수 있어요.

한 줄 매크로는 코드 곳곳에 의미를 부여할 때 유용해요.
조심해서 사용하면 가독성이 좋아지고 실수로 잘못 칠 가능성도 줄어들어요.
예를 들어 함수 안에서 특정한 용도로만 쓰는 레지스터라면, 그 용도를 이름으로 붙여 줄 수 있어요.

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## 여러 줄 매크로

여러 줄이든 상관없이 코드 전체 묶음은 `%macro`로 시작하고 `%endmacro`로 닫아요.
이름 뒤의 숫자는 그 매크로가 받는 인자의 개수를 나타내며, 0일 수도 있어요.
인자를 넘길 때는 쉼표(`,`)로 구분해요.

```x86asm
%macro example_macro 0
...
%endmacro
```

여러 줄 매크로의 인자에는 이름이 없어요.
넘겨진 순서대로 `%1`, `%2` 같은 식으로 가리켜요.

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

인자는 매크로 본문에서 수행하는 연산에 맞는 올바른 문법이어야 한다는 점에 주의해요.
여기서 `mult_two eax, ecx`와 `mult_two r8, r9`는 둘 다 어셈블되지만, `mult_two eax, cl`은 안 돼요. `imul eax, cl`이라는 명령이 정의되어 있지 않기 때문이에요.

매크로는 임의 개수의 인자를 받을 수도 있어요.
이때는 `n-*` 표기를 쓰는데, `n`은 최소 인자 개수예요.

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

여러 줄 매크로에서 `%0`은 매크로가 받은 인자의 _개수_ 를 나타내요.
인자 개수가 정해지지 않은 매크로에서 특히 유용해요.

### 매크로 안의 레이블

일반 레이블을 정의하는 매크로는 두 번 사용되는 순간 깨져요. 레이블이 두 번 정의되니까요.
여러 번 호출될 수 있는 매크로 안에서 레이블을 쓰려면, 그 레이블 앞에 `%%`를 붙여야 해요.
이렇게 하면 어셈블러가 펼쳐질 때마다 그 레이블에 서로 다른 고유한 이름을 붙여요.

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## 어셈블 시점에 반복하기

[`times`][times]를 사용하면 한 줄짜리 코드 블록을 반복할 수 있어요.
메모리에 같은 값을 반복해서 선언할 때 특히 유용해요.

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

여러 줄을 반복할 때는 대신 `%rep`를 사용할 수 있어요.

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

반복 횟수는 `%rep` 바로 뒤에 쓰고, 반복 블록을 닫을 때는 `%endrep`을 쓴다는 점을 기억해요.

실행 시점의 루프가 카운터를 쓰는 것처럼, `%rep` 블록 안에서 어셈블 시점 카운터를 쓰는 일도 흔해요.
이미 봤듯이 어셈블 시점 정수 상수는 `equ`로 선언할 수 있지만, 어셈블 시점 정수 _변수_ 에는 대신 `%assign`을 사용해요.
`%define`과 달리 `%assign`은 즉시 숫자로 계산되고, 다시 지정할 수도 있어요.

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

전처리기가 실행되고 나면 루프는 사라지고 `add` 명령 네 개만 남아요. 즉시값 `0`, `1`, `2`, `3`이 그대로 박혀 있죠.
이것이 어셈블러가 해 주는 루프 언롤링이에요. 카운터 레지스터도, 분기도 없이 그저 곧게 이어지는 코드만 남아요.

`%rep`의 또 다른 흔한 쓰임은 임의 개수의 인자를 받는 매크로에서 그 인자들을 처리하는 거예요.
이때 `%rep`는 보통 `%rotate`와 함께 쓰이는데, `%rotate`는 매크로의 인자들을 회전시켜서 두 번째 인자가 첫 번째가 되게 해요.
`%rotate`를 반복해서 적용하면 세 번째, 네 번째 인자가 차례로 첫 번째가 되어, 모든 인자를 하나씩 처리할 수 있어요.

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## 조건부 어셈블리

[전처리기][preprocessor]에는 다양한 조건부 지시문이 있어요.
이들은 여러 경로 중 하나를 선택하며, 조건이 참일 때만 자기 본문을 그 자리에 펼쳐요.

`%if` ... `%elif` ... `%else` ... `%endif`는 숫자 비교 결과에 따라 분기를 선택해요.

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

`%ifdef`와 `%ifndef`도 비슷하지만, 어떤 이름이 정의되어 있는지를 검사해요.
예를 들어 파일이 여러 소스에서 불려 와도 그 내용이 한 번만 포함되도록 보장할 때 쓸 수 있어요.

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

이 트랙의 모든 `.asm` 파일 끝에 이런 코드가 있다는 걸 눈치챘을지도 몰라요.

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

`%ifidn`은 두 텍스트가 정확히 일치하는지 비교해요.
내장된 `__OUTPUT_FORMAT__`은 현재 출력 형식으로 펼쳐지므로, 이 코드는 출력 형식이 `elf64`인지, 즉 리눅스 시스템에서 쓰는 형식인지 확인해요.
맞다면 오브젝트 파일에 스택이 가져야 할 권한을 선언하는 노트가 추가되는데, 이는 흔한 안전 조치예요.
아니라면 아무것도 바뀌지 않아요.

## 구조체

메모리에 있는 레코드의 어떤 필드에 접근하려면, 기준 주소에 그 필드의 바이트 오프셋을 더해야 해요.
이 오프셋을 날것의 숫자로 쓰는 건 실수하기 쉽고, 그 의미도 가려 버려요.
대신 [`struc`][struc]와 `endstruc`는 레이아웃에 이름을 붙여서, 각 필드를 어셈블 시점에 계산되는 기호적 오프셋으로 만들어 줘요.

블록 안에서는 예약 지시문 `resb`, `resw`, `resd`, `resq`가 각각 바이트, 워드, 더블워드, 쿼드워드 단위로 하나 이상의 공간을 확보해요.
각 필드 이름 앞에 `.`을 붙이면 그 이름이 구조체 안으로 범위가 제한돼요.

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

이제 각 필드 이름이 자기 오프셋을 나타내서, `thread.color`는 `0`, `thread.tension`은 `4`, `thread.name`은 `12`예요.
NASM은 `<struc>_size`도 전체 크기로 정의하는데, 여기서 `<struc>`는 `struc`의 이름이에요.
예를 들어 여기서 `thread_size`는 `4 + 8 + 16 = 28`이 돼요.

필드는 기준 레지스터에 그 오프셋을 더해서 접근하고, `thread_size`는 레코드 하나에서 다음 레코드로 건너가는 폭이에요.

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

`struc`은 모양만 설명할 뿐, 스스로 메모리를 할당하지는 않아요.
초기화된 인스턴스를 만들려면 어떤 레이블 뒤에 `istruc ... iend`를 사용하면 돼요.
인스턴스 안에서 `at`은 이름이 붙은 필드에 값을 넣어요.

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

`thread.name`은 `"warp", 0`으로 초기화되는데, 이는 5바이트만 차지해요.
`struc`에서 이 필드에 예약된 나머지 11바이트는 `iend`가 자동으로 0으로 채워서, 인스턴스를 `thread_size`까지 `0`으로 패딩해요.

`struc`은 직접 선언할 수도 있는 메모리를 위한 편의 문법일 뿐이에요.
예를 들어 위 코드는 아래 코드와 같아요. 아래에서 `times 11 db 0`은 끝에 16바이트가 할당되도록 보장해요.

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## 파일로 나누기

매크로는 보통 별도의 파일에 두고, 필요한 소스마다 `%include`로 불러와요.

```x86asm
%include "patterns.mac"
```

지정한 파일은 어셈블 전에 그 위치에 그대로 삽입돼요. 마치 그 자리에 내용을 직접 타이핑한 것처럼요.
이렇게 하면 정의를 한곳에 모아 두고 여러 소스 파일이 함께 쓸 수 있어요.

매크로 파일을 단독으로 어셈블할 수도 있다면 `.asm` 확장자를 붙이는 게 좋아요.
매크로에는 링키지가 없다는 점에 주의해요.
매크로 파일을 어셈블하더라도, 그 매크로는 이 파일을 `%include`하는 다른 파일에서만 보여요.

그렇지 않고 `%include`용으로만 쓴다면 확장자는 아무거나 상관없어요.
`.asm`이나 `.mac`을 쓰는 건 흔한 관례예요.
