# 불변 클래스

```sather
immutable class BEARING is
   readonly attr degrees : INT;
   create(d : INT) : SAME is
      b : SAME;
      return b.degrees(d);
   end;
end;
```

## 달라지는 점

| | 일반 클래스 | 불변 클래스 |
| --- | --- | --- |
| 대입 | 객체를 공유해요 | 값을 복사해요 |
| void 여부 | 예 | 아니요 |
| `attr` 쓰기 | `x.a := v` | `x := x.a(v)` |
| `new` | 예 | 아니요. `x : SAME`이 이미 있어요 |

불변 객체는 void가 될 수 없어요. 그래서 `void(b)`는 언제나 false이고, 그런 객체의 어떤 루틴도 객체가 없다는 이유로 실패할 수 없어요. 이렇게 하면 한 부류의 실수를 통째로 없앨 수 있지만, 그 대가로 "아직 베어링이 없음"이라고 말할 수는 없게 돼요.

## 값이 저장되는 곳

값은 참조를 거쳐 접근되는 대신 변수가 있는 곳, 즉 다른 객체 안이나 스택 위에 저장돼요. 그래서 `ARRAY{BEARING}`는 베어링을 가리키는 포인터가 아니라 베어링 자체를 담아요. 이 편이 더 작고 순회하기도 더 빨라요.

대가는 복사예요. 큰 불변 객체를 넘기면 매번 복사돼요. 그래서 작게 유지하는 게 좋아요.

## 속성 루틴

`readonly attr degrees : INT`는 두 개의 루틴을 만들어요:

```sather
   b.degrees          -- read: INT
   b.degrees(90)      -- answer a new BEARING with degrees changed
```

두 번째는 아무것도 바꾸지 않기 때문에 `readonly` 아래에서도 존재해요. 대신 새로운 값을 만들어요. 일반 `attr`에서는 공개되지만 `private attr`에서는 그렇지 않아요.

## is_eq와 str

둘 다 기본으로 제공되지는 않아요. `=`를 위해 `is_eq`를 작성하고, 객체를 출력하거나 문자열에 이어 붙일 수 있도록 `str`을 작성해요:

```sather
   is_eq(other : SAME) : BOOL is return degrees = other.degrees; end;
   str : STR is return degrees.str + " degrees"; end;
```

`str`을 작성하면 클래스가 `$STR`을 따르게 되고, 그래야 `+`와 `#OUT`이 이 객체를 받아들여요.

## 기본 제공 클래스

`INT`, `BOOL`, `CHAR`, `FLTD`, `TUP`은 모두 불변 클래스예요. 이들에 특별한 점은 없어요. 라이브러리에서도 똑같은 방식으로 Sather로 작성되어 있고, 위에서 설명한 이유로 지금처럼 동작해요.
