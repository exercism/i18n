# 소개

이상적인 세상이라면 모든 것이 잘 정의되어 있고, 값이 구체적이며 빈틈도 없을 거예요.

하지만 이는 우리의 일상적인 경험과 어긋나요. 그래서 많은 프로그래밍 언어에는 값이 없음을 나타내는 방법이 있어요. null이나 NULL, nil, None, nothing 등이요.

이 아이디어는 (1965년에) 도입하기는 쉬웠지만, 곧 후회를 낳았어요. 발명자는 나중에 이것을 자신의 "Billion Dollar Mistake"라고 불렀어요.

최근 수십 년 동안 언어 설계자들은 null을 쓸 수 있으면서도 (대부분) 안전하게 만드는 여러 방법을 연구해 왔어요.

Kotlin에는 Java와 크게 다른 [일반 원칙][ref-null-safety]이 몇 가지 있어요.


- Kotlin에는 특별한 `null` 값이 있어요.
- 모든 타입은 _기본적으로_ 널을 허용하지 않아요.
- 대부분의 타입은 널을 허용하도록 _만들_ 수 있지만, 프로그래머가 명시적으로 지정해야 해요.
- 예외와 함께 실패할 수 있는 함수에는 널을 반환할 수 있는 변형이 있는 경우가 많아요.
- 널인지 확인하고 널에 대응하는 일을 최대한 쉽게 하려고, 아주 간결한 특수 문법이 마련되어 있어요.

## 널을 허용하는 변수 만들기

일반적인 타입에는 보통 `?` 접미사를 붙인 널 허용 버전이 있어요. 예를 들어 `String` 대신 `String?`을 써요.

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## 유용한 연산자와 함수

### 안전 호출 연산자 `?.`

널을 허용하지 않는 `String`에서는 `.length` 프로퍼티를 가져올 수 있어요.

`String?`처럼 널을 허용하는 타입에서 같은 문법을 쓰면 오류가 나지만, `?.length`를 쓰면 null일 가능성을 처리할 수 있어요.
반환 타입은 `Int?`예요.

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

위의 마지막 줄에서 봤듯이, `?.`는 널을 허용하지 않는 타입에서도 동작해요.

### 엘비스 연산자 `?:`

안전 호출 연산자의 아이디어를 확장한 [엘비스 연산자][wiki-elvis]를 쓰면, `null`을 대신할 기본값을 지정할 수 있어요.

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### 널 아님 단언 연산자 `!!`

이 연산자를 쓰면, 프로그래머가 확신할 때 널을 허용하는 타입을 강제로 널이 아닌 것처럼 다루게 해요.
어쩌면 우리가 지나치게 신중한 컴파일러보다 프로그램 로직을 더 잘 이해할 때도 있지 않을까요?

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

이제 책임은 우리에게 있어요. `b`가 여전히 `null`이면 `NullPointerException`이 발생해요.

### let 함수 `?.let`

널을 허용하는 값을 코드 블록에 넘길 때, `if (item != null) { do something }`처럼 널 검사를 직접 할 수도 있어요.

`item?.let { do something }`를 쓰는 편이 더 간단하고 관용적이에요.
`do something`은 `item`이 null이 아닐 때만 실행돼요.

### `somethingOrNone()` 형태의 함수

일부 함수는 실패할 수 있어요. 예를 들어 문자열이나 배열에서 유효하지 않은 인덱스를 요청할 때요.

예외를 던지는 대신, 함수의 `...OrNull` 변형을 써서 (이 경우에는) `Int?` 반환 값을 받을 수 있어요.

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
