# 소개

어떤 루프는 "시퀀스의 각 요소마다 이걸 해요"처럼 쓸 수 없어요. 어떤 조건이 뒤집힐 때까지 계속 반복해야 하죠. 그럴 때 쓰는 도구가 바로 Factor의 `while` 컴비네이터예요. 조건 쿼테이션이 "계속 갈까요?"를 알려 주고, 본문 쿼테이션이 한 단계의 일을 처리하며, `while`은 조건이 `f`를 줄 때까지 반복해요.

## `while`과 `until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred`와 `body`는 모두 데이터 스택에서 동작하는 쿼테이션이에요. `while`은 `pred`가 참으로 여겨지는 값을 남기는 동안 계속 반복해요. `until`은 그 반대예요. `pred`가 참이 *될 때까지*, 그러니까 `pred`가 `f`를 남기는 동안 계속 반복하죠.

하나의 상태 값이 조건과 본문 사이에서 스택 위를 흘러갈 수 있어요.

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

실행 과정을 따라가 봐요. 조건 `dup 0 >`는 현재 카운터를 살짝 들여다보고, 본문 `dup . 1 -`는 그 값을 출력한 뒤 하나 줄여요. 카운터가 `0`에 도달하면 루프가 멈춰요. 맨 끝의 `drop`은 스택에 남은 마지막 `0`을 버려요.

## `while*`: 조건의 값을 그대로 유지해요

```
while* ( pred body -- )
```

`while`은 조건이 참인 값을 남겼는지만 따져요. 본문을 실행하기 전에 그 값 자체는 버리죠. 반면 `while*`은 *그 값을 본문에 그대로 넘겨줘요*. 검사와 본문이 방금 계산한 같은 값을 필요로 할 때는 이걸 쓰면 좋아요. 조회 결과나 일치하는 값, 파싱한 토큰처럼요.

여기서는 각 이름이 체인에서 다음 이름을 가리켜요. 조건은 현재 이름으로 조회를 하고, 다음 이름이 있는 한 `while*`은 그 이름을 본문에 넘겨줘요. 그러면 본문이 그 이름을 출력하고 거기서부터 계속 나아가죠.

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

`links at`은 다음 이름을 반환하고, 어떤 이름에 대응하는 항목이 없으면 `f`를 반환해요. 이름을 반환하는 동안 `while*`은 그 이름을 `dup .`에 넘겨주고, `dup .`은 그걸 출력한 뒤 다음 조회에 쓸 키로 남겨 둬요. 처음 나온 `f`가 루프를 멈춰요. `while*`이 그 `f`를 버리기 때문에 아무것도 남지 않아요.

## 지역 변수로 여러 상태 값 다루기

루프가 값 하나 이상을 나를 때, 이를테면 남은 목록과 누적 합계를 함께 다룰 때는 스택을 이리저리 다루느라 코드가 지저분해져요. 가장 깔끔한 방법은 `::`로 *지역 변수*를 선언하는 거예요.

```
:: word ( inputs -- outputs ) ... ;
```

본문 안에서 `:> name!`은 변경 가능한 지역 변수를 하나 추가해요. 읽을 때는 `name`을 쓰고, 값을 넣을 때는 `name!`을 써요. `name!`은 스택에서 새 값을 꺼내 변수에 할당하죠.

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

여기서 지역 변수 두 개(`rest`와 `running`)가 루프의 상태 전체를 담당해요. 조건이 이들을 살펴보고, 본문이 이들을 갱신하며, 마지막에 최종 값이 반환돼요.

`unclip ( seq -- rest first )`는 시퀀스에서 첫 번째 요소를 떼어 내요. 루프가 반복마다 요소 하나씩 목록을 소비하고 싶을 때 유용하죠. `[ rest! ] dip` 형태는 `rest`를 남은 꼬리로 갱신하면서, 방금 꺼낸 요소는 본문이 쓸 수 있도록 스택에 남겨 둬요.
