# 소개

튜플은 다른 튜플을 확장할 수 있어요. `TUPLE: child < parent slots ;`는 인스턴스가 `parent`의 인스턴스이기도 한 클래스를 선언해요. 이런 인스턴스는 자신의 슬롯에 더해 부모의 슬롯도 가지고, 부모의 접근자도 자식에 정의된 것처럼 그대로 동작해요.

```factor
USING: accessors ;

TUPLE: animal name age ;
TUPLE: dog < animal breed ;

"Rex" 4 "labrador" dog boa .
! => T{ dog { name "Rex" } { age 4 } { breed "labrador" } }

"Rex" 4 "labrador" dog boa name>> .   ! => "Rex"   (inherited accessor)
```

## `boa` 슬롯 순서

`boa` 생성자는 슬롯을 *선언 순서대로, 부모 먼저* 받아요. 위의 `dog`의 경우에는 다음과 같아요:

```
dog boa ( name age breed -- dog )
```

`weeks`를 추가한 손자 `puppy < dog `의 경우에는 다음과 같아요:

```
puppy boa ( name age breed weeks -- puppy )
```

## 프레디킷 계층

모든 `TUPLE:` 선언은 프레디킷(`name?`)을 만들어요. 상속을 하면 프레디킷이 중첩돼서, 모든 자손이 조상의 프레디킷을 만족해요:

```factor
"Rex" 4 "labrador" dog boa
dup dog? .        ! => t
dup animal? .     ! => t
```

그 반대는 성립하지 않아요. `dog`가 아닌 `animal`은 `dog?`를 만족하지 못해요.

## 미리 보는 내용

제네릭 메서드(`M:`, [`generics`][generics]에서 배워요)도 계층을 따라 디스패치해요. 더 구체적인 오버라이드가 우선하지 않는 한, `animal`에 정의된 메서드는 모든 자손에 대해 실행돼요. 이 연습 문제 바로 다음에 나오는 `boatswains-bilge`에서 그것을 보게 될 거예요.
