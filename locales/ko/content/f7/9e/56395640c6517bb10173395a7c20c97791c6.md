# 워크플로

GitHub Actions는 _워크플로_라는 개념을 사용해요. 워크플로는 특정 이벤트가 발생할 때(예: 커밋을 푸시할 때) 자동으로 실행되는 스크립트예요.

각 GitHub Actions 워크플로는 `.github/workflows` 디렉터리 안의 `.yml` 파일에 정의해요.
워크플로에 대한 자세한 내용은 다음 문서를 참고해요:

- [워크플로 구문](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions)
- [워크플로가 실행되는 시점 선택](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/triggering-a-workflow)
- [워크플로가 실행되는 위치 선택](https://docs.github.com/en/actions/writing-workflows/choosing-where-your-workflow-runs)
- [워크플로가 하는 일 선택](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does)
- [워크플로 작성](https://docs.github.com/en/actions/writing-workflows)
- [모범 사례](/docs/building/github/gha-best-practices)

## 공유 워크플로

일부 워크플로는 여러 리포지토리에서 공유해요.

```exercism/caution
공유 워크플로는 ([org-wide-files 리포지토리](https://github.com/exercism/org-wide-files/)에서) 자동으로 동기화돼요.
따라서 그 내용을 직접 수정하면 안 돼요.
```

### 일반 워크플로

- [레이블 동기화](/docs/building/tracks/ci/workflows/sync-labels): 파일에서 리포지토리의 레이블을 동기화해요

### 트랙 전용 워크플로

- [configlet](/docs/building/tracks/ci/workflows/configlet): 트랙의 (구성) 파일이 구문적으로나 의미적으로 제대로 구성되어 있는지 확인해요
- [중요한 파일 변경 없음](/docs/building/tracks/ci/workflows/no-important-files-changed): 기존 풀이를 다시 테스트하게 만들 풀 리퀘스트에 댓글을 달아요
- [테스트](/docs/building/tracks/new/setup-continuous-integration#h-test-workflow): 트랙의 연습 문제를 검증해요

### 툴링 전용 워크플로

- [배포](/docs/building/tracks/ci/workflows/deploy): 트랙 툴링 Docker 이미지를 Docker Hub와 ECR에 배포해요

### 선택적 워크플로

트랙에서 선택적으로 사용할 수 있는 워크플로도 있어요:

- [커뮤니티 기여 일시 중지](/docs/building/tracks/ci/workflows/pause-community-contributions): Exercism GitHub 조직의 구성원이 아닌 사용자가 새로 만든 이슈와 PR에 자동으로 댓글을 달아요
