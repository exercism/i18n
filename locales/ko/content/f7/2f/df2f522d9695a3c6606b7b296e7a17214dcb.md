# 소개

## JSON

JSON(JavaScript Object Notation)은 사람이 읽을 수 있는 데이터 및 파일 형식으로, 주로 웹 애플리케이션에서 데이터를 주고받는 데 쓰여요. 그래서 JSON이 Elm 언어에서 특별한 자리를 차지하는 것도 놀랄 일이 아니에요.

Elm은 JSON 데이터를 파싱하고 작성하기 위한 핵심 모듈 `Json.Decode`와 `Json.Encode`를 제공해요. JSON 디코더는 어떤 타입의 데이터를 기대하는지, 그리고 그 데이터가 어떤 자료 구조로 매핑되어야 하는지를 _선언_하는 방법이에요.

모듈에서 몇 가지 별칭과 타입을 가져와 봐요:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

디코더와 JSON 문자열을 함께 `Decode.decodeString : Decoder a -> String -> Result Error a`에 넘기면, 문자열이 디코더의 명세에 맞으면 성공하고 그렇지 않으면 실패해요. 디코더를 정의할 때 원시 JSON 데이터를 들여다볼 방법은 없는데, 명령형 언어에 익숙한 사람이라면 이 점이 낯설게 느껴질 수 있어요.

## 기본 데이터 타입 디코더

JSON에는 몇 가지 핵심 데이터 타입이 있어요:

- 문자열: 큰따옴표로 인코딩해요 (`"hello world"`)
- 불리언: `true` 또는 `false`
- 숫자: `34`나 `0.12` 같은 값
- Null: 데이터가 없음을 나타내는 `null`

이들 각각에는 대응하는 `Decode` 함수가 있어요:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

`Decode.null`은 임의의 값을 인자로 요구해서, 프로그램에서 `null`을 어떻게 모델링할지 직접 정할 수 있게 해줘요 (예를 들어 `()`, `Nothing`, 또는 프로그램에 맞는 아무 값이나 가능해요).

## 디코더 조합하기

JSON은 또한 핵심 데이터 타입을 모아 담는 두 가지 자료 구조를 정의해요:

- 배열: 다른 데이터 타입들을 모아 놓은 `[0, null, "none", []]`
- 객체: 키-값 쌍을 모아 놓은 `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode`는 이런 값들을 디코딩하는 함수도 제공해요:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

이 함수들 `Decode.list : Decoder a -> Decoder (List a)`와 `Decode.dict : Decoder a -> Decoder (Dict String a)`는 각각 디코더를 인자로 받는데, 이 디코더는 자료 구조의 모든 원소를 하나하나 디코딩할 수 있어야 해요. 인자로 받은 디코더가 배열이나 객체 값의 원소 중 하나라도 디코딩하지 못하면 전체 디코더가 실패하는데, 이는 흔한 패턴이에요.

단순한 디코더를 더 복잡한 디코더로 조합하는 것이 이 기법의 핵심 아이디어예요. 예제를 통해, 실무에서 쓰이는 아무리 복잡한 데이터 디코더든 만들 수 있는 여러 함수를 더 소개할게요.

## GeoJSON

기본 디코더를 조합해 복잡한 JSON 데이터를 파싱하는 연습을 위해, GeoJSON 데이터(의 일부)를 파싱하는 디코더를 만들어 봐요. GeoJSON은 위치, 경로, 지역 같은 지리적 요소를 표현하는 데 쓰이는 특화된 JSON 기반 데이터 형식으로, 2D 또는 3D 지리 좌표와 그 밖의 속성으로 나타내요.

### 지오메트리 객체

GeoJSON 지오메트리 객체는 문자열 값을 가진 `type` 필드(가능한 타입 값은 7가지예요)와 지리 좌표를 담은 `coordinates` 필드(좌표를 어떤 구조로 모으는지는 타입에 따라 달라요)를 가진 객체예요. 예를 들어,

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

또는

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

지오메트리 객체는 Elm에서 다음과 같은 타입으로 나타낼 수 있어요

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

특정 필드의 값을 들여다보려면 `Decode.field : String -> Decoder a -> Decoder a`를 쓸 수 있는데, 이 함수는 객체의 특정 키에 해당하는 값을 디코딩해요.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

디코더가 성공적으로 파싱한 값을 변환하려면 `Decode.map : (a -> value) -> Decoder a -> Decoder value`나 그 형제 함수들, 즉 `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value`부터 `Decode.map8`까지를 쓸 수 있어요.

이 경우, `type` 필드의 값에 따라 어떤 좌표 디코더를 쓸지 결정하고 싶은데, 이는 `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b`와 그 친구들인 `Decode.succeed : a -> Decoder a`, `Decode.fail : String -> Decoder a`에 딱 맞는 작업이에요.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

여기서 짚고 넘어갈 점은, `Decode.andThen`을 써서 좌표를 검증할 수도 있다는 거예요(좌표가 쌍이나 세 개 묶음으로 오는지, 좌표 값이 지리적으로 말이 되는지 확인하는 식으로요).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### 피처 객체

GeoJSON 피처 객체는 공간적으로 경계가 있는 대상을 나타내요. `"Feature"` 값을 가진 `type` 필드, 지오메트리 객체 또는 `null`을 값으로 갖는 `geometry` 필드, 임의의 JSON 객체 또는 `null`을 값으로 갖는 `properties` 필드, 그리고 JSON 문자열이나 숫자 값을 갖는 선택적 `id` 필드를 가져요.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

또는

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

먼저 `id` 필드부터 다뤄 봐요. 이 필드가 존재한다면 문자열이나 숫자를 담을 수 있어야 하니, 값을 위한 커스텀 타입을 도입하거나, 아니면 항상 문자열로 저장할 수 있어요.

두 가지 가능한 디코더 중에서 고르려면 `Decode.oneOf : List (Decoder a) -> Decoder a`를 쓸 수 있어요.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

이 필드가 선택적임을 표현하려면 같은 기법을 쓸 수도 있어요

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

하지만 대신 `Decode.maybe : Decoder a -> Decoder (Maybe a)`를 쓸 수도 있어요

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

`decodeMaybeFeatureId`(또는 `Decode.maybe`로 감싼 아무 디코더)는 언제나 `Ok Nothing`으로 대체할 수 있으니 항상 성공한다는 점에 유의해요. 다만 이를 사용하는 디코더는 여전히 실패할 수 있어요.

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

다음으로 `geometry` 필드에 집중해 봐요. 이 필드는 지오메트리 객체이거나 `null`일 수 있어요. `Decode.oneOf`를 다시 쓸 수도 있지만, 더 나은 선택지가 있어요: 바로 `Decode.nullable : Decoder a -> Decoder (Maybe a)`예요.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe`와 `Decode.nullable`은 시그니처가 같지만 동작은 달라요. `Decode.nullable`의 `OK Nothing` 결과는 특정 JSON 값 `null`에서만 나오기 때문이에요.

마지막으로, `properties` 필드는 임의의 JSON 객체나 `null`을 담을 수 있는데, 이는 `Decode.value : Decoder Value`가 할 일이에요.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

`Value`는 불투명 타입이라 내용을 쉽게 들여다볼 수 없다는 점에 유의해요. 이 값을 활용하려면, 값을 위한 디코더를 작성해서 `Decode.decodeValue : Decoder a -> Value -> Result Error a`로 실행하거나, 포트를 통해 JavaScript로 직접 보낼 수 있어요.

이제 피처 객체를 파싱할 준비가 됐어요:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## JSON 인코더

인코더를 사용하면 `Encode.encode : Int -> Value -> String` 함수로 Elm 값에서 유효한 JSON을 작성할 수 있어요. 첫 번째 인자는 최종 결과에서 들여쓰기 칸 수를 지정하고, 두 번째 인자는 작성할 JSON 값이에요.

`Value`는 `Decode.value`에서 얻거나, 인코더 중 하나로 만들어낼 수 있어요:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

`Encode.object : List ( String, Value ) -> Value`로도 마찬가지예요

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

앞에서 정의한 GeoJSON 디코더에 대응하는 인코더를 정의해 봐요

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

일반적으로 디코더-인코더 쌍이 잘 맞는지 확인하는 좋은 방법은 `elmValue |> encoder |> decoder == elmValue`인지 검사하는 거예요.
