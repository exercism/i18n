# 자세히 알아보기

함수가 실행하는 _마지막_ 동작이 자기 자신을 호출하는 것이라면, 그 함수는 [꼬리 재귀][recursion-tc] 함수예요.

함수가 호출될 때마다, 지역 변수와 인자를 담은 _스택 프레임_이 [함수 호출 스택][call-stack] 맨 위에 쌓여요.
함수가 반환되면, 그 스택 프레임은 스택에서 제거돼요.

꼬리 재귀 함수는 [꼬리 호출 최적화][tail-call-optimization](또는 꼬리 호출 제거)를 가능하게 해요.
이전 함수가 더 이상 그 프레임을 필요로 하지 않는다고 보장될 때, 다음 함수 호출이 마지막 스택 프레임을 재사용할 수 있게 해 주는 최적화예요.
이 최적화는 함수 호출 스택이 넘치는 문제를 완화해 줘요. 함수 호출 스택에 프레임이 너무 많이 쌓여서 새 프레임을 하나 더 만들 메모리가 남아 있지 않은 상황을 말해요.

## Elm에서의 꼬리 호출 최적화

특정 조건에서는 Elm 컴파일러가 JavaScript로 컴파일할 때 꼬리 호출 최적화를 자동으로 수행할 수 있어요.

재귀 함수에서 어떤 분기의 _마지막_ 연산이 단순한 함수 적용으로 자기 자신을 호출하는 것일 때 이 최적화가 일어날 수 있어요.
몇 가지 예를 살펴봐요:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

위 구현은 꼬리 재귀가 아니에요. `else` 분기의 마지막 연산이 곱셈 `n *`이기 때문이에요.

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

위 구현은 꼬리 재귀이고 최적화될 거예요. `else` 분기의 마지막 연산이 `factorialHelper`가 자기 자신을 호출하는 것이기 때문이에요.
`Int -> Int`라는 타입 시그니처를 가진 함수에서는 이렇게 할 수 없고, 실제로는 꼬리 호출 최적화를 도우미 함수를 정의해서 이루는 경우가 많아요.

## 경계 사례

어떤 경우에는 컴파일러가 재귀 함수를 최적화하지 못해요. 몇 가지 예를 살펴봐요.

`f x = f (x - 1)`은 꼬리 재귀지만, `f x = (x - 1) |> f`는 아니에요. `|>`라는 함수 적용이 마지막 연산이고 `f`와 별개로 취급되기 때문이에요.
마찬가지로, 불리언 조건으로 끝나는 함수 `f x = x > 0 || f (x - 1)`도 꼬리 재귀가 아니에요.

함수 `f x = if f (x - 1) then 1 else 0`은 꼬리 재귀가 아니에요. `if` 안의 표현식이 분기로 취급되지 않기 때문이에요.
마찬가지로, `case`문 안의 재귀 호출도 최적화되지 않아요.

함수 `f x = let y = f (x - 1) in y`는 꼬리 재귀가 아니에요. `let`문 안에서 자기 자신을 호출하는데, 이는 분기로 취급되지 않기 때문이에요.
하지만 `f x = let g x = g (x - 1) in g x`에서는 함수 `g`가 꼬리 재귀이고, `let`문 안에 정의되어 있더라도 최적화될 거예요.

함수 `f x = if x > 0 then f (x + 1) else 1 + f x`는 _부분적으로_ 최적화될 거예요. `then` 분기는 최적화될 수 있지만 `else` 분기는 그럴 수 없어요.
트리 같은 구조를 순회하거나 상호 재귀 함수를 정의하는 등 일부 상황에서는 부분 최적화가 최선이에요.
