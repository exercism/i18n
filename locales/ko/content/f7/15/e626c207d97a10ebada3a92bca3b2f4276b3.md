# 지침

_Instruments of Texas_에서 실험용 RPN 계산기를 만드는 작업은 계속되고 있어요. 팀에서는 대량 생산할 수 있는 최적의 하나를 고르기 위해, 철저한 검사를 거쳐야 하는 프로토타입 몇 개를 만들어 두었어요.

두 가지 종류의 검사를 진행하려고 해요.

먼저, 검사 대상 계산기가 충돌하거나 충분히 빠르게 응답하지 못하는 입력값을 찾아내는 신뢰성 검사예요. 실패를 격리하려면 각 입력값에 대한 계산을 별도의 프로세스에서 실행해야 해요. 호출한 프로세스에서 링크와 exit 트랩을 사용하면 계산이 완료됐는지 충돌했는지를 감지할 수 있어요.

둘째, 주어진 입력값에 대해 계산기가 반환한 결과가 예상대로인지 확인하는 정확성 검사예요. 신뢰성 검사를 이미 통과한 계산기만 정확성 검사를 거치므로, 충돌은 걱정할 필요가 없어요. 다만 과정을 빠르게 하려면 연산을 동시에 실행해야 하는데, 이는 비동기 작업에 안성맞춤인 활용 사례예요.

## 1. 단일 입력값에 대한 신뢰성 검사 시작하기

`RPNCalculatorInspection.start_reliability_check/2` 함수를 구현해요. 인자 두 개, 즉 함수(계산기)와 계산기에 전달할 입력값을 받아야 해요. 입력값과 생성된 프로세스의 PID를 담은 맵을 반환해야 해요.

생성된 프로세스는 주어진 계산기 함수를 주어진 입력값으로 호출해야 해요. 이 프로세스는 호출한 프로세스에 링크되어야 해요.

```elixir
RPNCalculatorInspection.start_reliability_check(fn _ -> 0 end, "2 3 +")
# => %{input: "2 3 +", pid: #PID<0.169.0>}
```

## 2. 신뢰성 검사 결과 해석하기

`RPNCalculatorInspection.await_reliability_check_result/2` 함수를 구현해요. 인자 두 개를 받아야 해요. 첫 번째 인자는 `RPNCalculatorInspection.start_reliability_check/2`가 반환한 것처럼, 신뢰성 검사의 입력값과 이 입력값에 대한 신뢰성 검사를 실행하는 프로세스의 PID를 담은 맵이에요. 두 번째 인자는 서로 다른 입력값에 대한 신뢰성 검사 결과를 모아 두는 맵이에요.

이 함수는 exit 메시지를 기다려야 해요.

신뢰성 검사를 실행하는 같은 프로세스로부터 이유가 `:normal`인 exit 메시지(`{:EXIT, from, reason}`)를 받으면, 결과 맵의 `input` 키 아래에 `:ok` 값을 추가하여 반환해야 해요.

신뢰성 검사를 실행하는 같은 프로세스로부터 다른 이유의 exit 메시지를 받으면, 결과 맵의 `input` 키 아래에 `:error` 값을 추가하여 반환해야 해요.

100ms 안에 그러한 조건에 맞는 메시지를 받지 못하면, 결과 맵의 `input` 키 아래에 `:timeout` 값을 추가하여 반환해야 해요.

```elixir
# when an exit message is waiting for the process in its inbox
send(self(), {:EXIT, pid, :normal})

RPNCalculatorInspection.await_reliability_check_result(
  %{input: "5 7 -", pid: pid},
  %{}
)

# => %{"5 7 -" => :ok}

# when there are no messages in the process inbox
RPNCalculatorInspection.await_reliability_check_result(
  %{input: "3 2 *", pid: pid},
  %{"5 7 -" => :ok}
)

# => %{"5 7 -" => :ok, "3 2 *" => :timeout}
```

## 3. 여러 입력값에 대한 동시 신뢰성 검사 실행하기

`RPNCalculatorInspection.reliability_check/2` 함수를 구현해요. 인자 두 개, 즉 함수(계산기)와 계산기에 전달할 입력값 목록을 받아야 해요.

목록의 모든 입력값에 대해 `start_reliability_check/2`를 사용하여 새로 링크된 프로세스에서 신뢰성 검사를 시작해야 해요. 그런 다음 이렇게 시작한 모든 프로세스에 대해 `await_reliability_check_result/2`를 사용하여 결과를 기다려야 해요.

프로세스를 시작하기 전에, 함수는 exit 메시지를 받을 수 있도록 현재 프로세스가 exit을 트랩하도록 플래그를 설정해야 해요. 그런 다음 이 플래그를 원래 값으로 되돌려야 해요.

함수는 모든 입력값에 대한 신뢰성 검사 결과를 담은 맵을 반환해야 해요.

```elixir
fake_broken_calculator = fn input ->
  if String.ends_with?(input, "*"), do: raise("oops")
end

inputs = ["2 3 +", "10 3 *", "20 2 /"]

RPNCalculatorInspection.reliability_check(fake_broken_calculator, inputs)
# => %{
#       "2 3 +" => :ok,
#       "10 3 *" => :error,
#       "20 2 /" => :ok
#     }
```

## 4. 여러 입력값에 대한 동시 정확성 검사 실행하기

`RPNCalculatorInspection.correctness_check/2` 함수를 구현해요. 인자 두 개, 즉 함수(계산기)와 계산기에 전달할 입력값 목록을 받아야 해요.

목록의 모든 입력값에 대해 주어진 입력값으로 계산기를 호출할 비동기 작업을 시작해야 해요. 그런 다음 이렇게 시작한 모든 작업에 대해 100ms 동안 결과를 기다려야 해요.

```elixir
fast_cheating_calculator = fn input -> 14 end
inputs = ["13 1 +", "50 2 *", "1000 2 /"]
RPNCalculatorInspection.correctness_check(fast_cheating_calculator, inputs)
# => [14, 14, 14]
```
