# 개요

Swift에는 다양한 타입이 있지만, 그 타입들은 모두 _값 타입_과 _참조 타입_이라는 두 가지 분류 중 하나에 속해요. Swift에서는 [구조체가 값 타입이고][structs-are-value-types] [클래스가 참조 타입이에요][classes-are-reference-types].

값 타입과 참조 타입의 가장 큰 차이는, 값 타입을 변수나 상수에 할당하거나 함수에 전달할 때 실제로 할당되거나 전달되는 것이 그 값 자체가 아니라 값의 복사본이라는 점이에요. 구조체의 복사본 하나를 수정해도 다른 복사본에는 영향을 주지 않아요. 참조 타입에서는 그 값에 대한 참조가 할당되거나 전달되기 때문에, 서로 다른 두 이름이 클래스의 같은 인스턴스를 가리킬 수 있어요. 그래서 다른 이름으로 접근하면 원래 인스턴스가 수정될 수 있어요.

그럼 게임 속 캐릭터와 그 캐릭터의 게임 능력치를 정의하는 구조체와 클래스를 통해, 이런 항목을 복사하고 변경하면 무슨 일이 일어나는지 살펴볼까요.

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

`charB`의 프로퍼티를 바꾸면 두 이름이 같은 인스턴스를 가리키기 때문에 `charA`의 프로퍼티도 바뀐다는 점을 눈여겨봐요. 또한 두 캐릭터의 능력치에서 보듯, 참조 타입 안에 들어 있는 값 타입은 그 참조 타입을 따라 함께 변경돼요. 하지만 이것이 값 타입의 동작을 위반하는 것은 아니에요. `charA`와 `charB`가 `GameCharacter` 클래스의 같은 인스턴스를 가리키므로 `charA.stats`는 `charB.stats`와 같은 `CharacterStats` 인스턴스이기 때문이에요. 아래 예시에서 보듯, 그런 값 타입의 복사본끼리는 서로 영향을 주지 않아요.

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

그래서 구조체는 프로퍼티의 상태를 바꾸는 메서드 앞에 `mutating` 키워드를 붙여야 해요. 구조체의 프로퍼티를 바꾸면 실제로는 그 프로퍼티에 새 값이 설정된 구조체의 복사본이 새로 만들어지고, 그 새 복사본이 예전 복사본을 대체해요. 이 키워드는 그 타입의 값에서 이런 복사와 대체가 일어날 수 있다는 것을 눈으로 확인시켜 주는 표시예요.

이 때문에 가변 프로퍼티가 있는 구조체 인스턴스는, 변경 메서드를 호출하든 직접 할당하든, 반드시 상수가 아니라 변수에 할당_해야_ 해요. 그렇지 않으면 컴파일러 오류가 발생해요.

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

초기값은 여전히 만들고 접근할 수 있지만, 변경은 허용되지 않아요. 이 제약은 클래스에는 적용되지 않아요. `let`으로 클래스 인스턴스를 이름에 할당하면, 상수가 붙잡고 있는 것은 인스턴스 자체가 아니라 인스턴스에 대한 참조이므로 바뀔 수 없는 것도 인스턴스 자체가 아니라 그 참조예요. 그래서 인스턴스 자체는 바뀔 수 있지만, 참조를 다른 인스턴스를 가리키도록 바꿀 수는 없어요.

`let`이나 `var`로 정의한 구조체와 클래스에서 무엇을 바꿀 수 있는지 정리하면 다음과 같아요.

|         | **구조체**                                                                                  | **클래스**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | 이름에 새 구조체를 할당할 수 _없어요_.</br>구조체의 어떤 프로퍼티도 수정할 수 _없어요_. | 이름에 새 클래스를 할당할 수 _없어요_.</br>클래스의 가변 프로퍼티는 수정할 수 _있어요_. |
| **var** | 이름에 새 구조체를 할당할 수 _있어요_.</br>구조체의 가변 프로퍼티는 수정할 수 _있어요_.   | 이름에 새 클래스를 할당할 수 _있어요_.</br>클래스의 가변 프로퍼티는 수정할 수 _있어요_.    |

## 동일성

서로 다른 두 이름이 같은 클래스 인스턴스에 대한 참조를 가질 수 있기 때문에, 실제로 그런 경우인지 확인하는 것이 유용할 때가 있어요. Swift에서는 이를 확인할 때 `===` _동일_ 연산자를 사용해요(부정형인 `!==`도 있어요).

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

두 이름이 같은 구조체 인스턴스를 가리킬 수는 없으므로, 이런 동일성 연산자는 구조체에 대해 정의되어 있지 않아요.

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

동일성은 동등성과 같지 않아요. 많은 정의에 따르면 `char1`과 `char3`은 모든 프로퍼티가 같은 값을 가지고 있으므로 동등하다고 볼 수 있지만, 같은 동일성을 공유하지는 않아요. Swift에서는 모든 클래스에 동일성을 자동으로 사용할 수 있지만, 구조체나 클래스의 두 인스턴스가 _동등한지_ 판단하려면 개발자가 보통 직접 동등성 연산자를 작성해야 해요. 이 내용은 이 연습 문제의 범위를 벗어나요.
