# 지침

식료품 쇼핑 자동화 회사인 Mecha Munch™가 주문 앱 작업을 맡길 사람으로 방금 여러분을 채용했어요.
여러분의 팀은 장바구니의 기본적인 활동을 모두 관리하는 MVP(_[최소 기능 제품][mvp]_)를 만드는 임무를 맡았어요. 사용자가 식료품 주문을 추가하고, 삭제하고, 정렬할 수 있게 해주는 제품이죠.
다행히도 결제와 계산 기능은 다른 팀이 담당하고 있어요!

## 1. 사용자의 장바구니에 품목 추가하기

MVP는 사용자가 장바구니에 품목을 추가할 수 있어야 해요.
한 번에 하나일 수도, 여러 개일 수도 있어요.
MVP이므로 품목의 수량은 _반복_으로 나타내요.
사용자가 'Oranges'를 2개 추가하려면 입력 이터러블에 'Oranges'가 두 번 나타나요.
사용자의 장바구니에 이미 있는 품목이라면 장바구니 수량을 1만큼 늘려요.
장바구니에 _새로운_ 품목이라면 수량 1로 추가해요.

장바구니 딕셔너리와 추가할 품목의 이터러블을 인자로 받는 함수 `add_items!(<cart>, <items>)`를 만들어요.
이 함수는 사용자의 갱신된 장바구니 딕셔너리를 반환해야 해요.

```julia-repl
julia> additems!(Dict("Banana" => 3, "Apple" => 2, "Orange" => 1),
                 ("Apple", "Apple", "Orange", "Apple", "Banana"))
Dict{String, Int64} with 3 entries:
  "Apple"  => 5
  "Orange" => 2
  "Banana" => 4

julia> additems!(Dict("Banana" => 3, "Apple" => 2, "Orange" => 1),
                 ["Banana", "Orange", "Blueberries", "Banana"])
Dict{String, Int64} with 4 entries:
  "Blueberries" => 1
  "Apple"       => 2
  "Orange"      => 2
  "Banana"      => 5
```

## 2. 레시피 "아이디어" 섹션 업데이트하기

앱에는 다양한 요리의 완성된 레시피로 채워진 "아이디어" 섹션이 있어요.
사용자는 이 레시피 중 하나를 골라 모든 재료를 장바구니에 자동으로 추가할 수 있어요.
콘텐츠 팀이 재료와 수량을 자꾸 바꾸고 있어서, 프로젝트 매니저는 이런 "아이디어" 레시피를 편집하는 방법을 만들어 달라고 요청했어요.

"아이디어" 딕셔너리와 레시피 업데이트 딕셔너리를 인자로 받는 함수 `update_recipes!(<ideas>, <updates>)`를 만들어요.
이 함수는 갱신된 "아이디어" 딕셔너리를 반환해야 해요.

## 3. 사용자 장바구니를 매장으로 보내 주문 처리하기

앱은 특정 사용자의 장바구니를 매장으로 보내 주문을 처리해야 해요.
그런데 매장 직원은 고유한 진열대 코드를 통해 품목이 어디에 있는지 알아야 해요.
"처리용 장바구니"는 직원들이 더 효율적으로 일할 수 있도록 품목의 진열대 코드 순서대로 정렬되어야 해요.

사용자 장바구니와 매장 진열대 번호를 담은 딕셔너리를 인자로 받는 함수 `send_to_store(<cart>, <aislecodes>)`를 만들어요.
이 함수는 고객이 주문하는 각 품목마다 `aislecode => quantity` 쌍을 담은 결합된 "처리용 장바구니"를 반환해야 해요.
품목은 진열대 코드 순서대로 나타나야 해요.

```julia-repl
julia> cart = Dict("Orange" => 1, "Milk" => 2, "Banana" => 3, "Apple" => 2, "Chocolate" => 2);

julia> aislecodes = Dict("Orange" => 2.4, "Milk" => 3.3, "Banana" => 2.6, "Apple" => 2.2, "Chocolate" => 5.7);

julia> send_to_store(cart, aislecodes)
5-element Vector{Pair{Float64, Int64}}:
 2.2 => 2
 2.4 => 1
 2.6 => 3
 3.3 => 2
 5.7 => 2
```

## 4. 사용자가 주문한 내용을 반영하도록 매장 재고 업데이트하기

앱이 고객 주문을 끝없이 받기만 할 수는 없어요.
결국 매장은 여러 제품이 떨어지게 돼요.
그래서 앱 MVP는 사용자가 주문을 매장으로 보낼 때마다 매장 재고를 업데이트해야 해요.
그렇지 않으면 고객이 실제로는 없는 제품을 주문하게 될 거예요.

`cart`와 `inventory`를 인자로 받는 함수 `update_store_inventory!(<inventory>, <cart>)`를 만들어요.
이 함수는 "cart"에서 "주문된" 수량만큼 매장 재고 수량을 줄이고, 재고가 없는(즉 `0`이 된) 품목들의 딕셔너리를 반환해야 해요.

```julia-repl
julia> inventory = Dict("Banana" => 15, "Apple" => 12, "Orange" => 1, "Milk" => 4);

julia> cart = Dict("Orange" => 1, "Milk" => 2, "Banana" => 3, "Apple" => 2);

julia> update_store_inventory!(inventory, cart)
Dict{String, Int64} with 1 entry:
  "Orange" => 0

julia> inventory
Dict{String, Int64} with 4 entries:
  "Milk"   => 2
  "Apple"  => 10
  "Orange" => 0
  "Banana" => 12
```

## 5. 품절 품목 재주문하기

재고를 업데이트하는 것에 더해, 앱은 재고를 다시 채우는 일도 도울 수 있어요.
MVP는 고객 주문 후 품절된 품목들의 소규모 주문을 준비할 수 있어야 해요.
이렇게 하면 대규모 주문을 시작하기가 더 쉬워져요.
게다가 가끔은 재고 목록에 없는 기간 한정 프로모션 품목도 있어요.
이런 품목이 프로모션 기간이 끝나기 전에 다 팔렸다면 인기가 있다는 뜻이므로 재고 목록에 추가할 수 있어요.

`outofstock`과 `stock`을 인자로 받는 `reorder!(<outofstock>, <stock>)`를 만들어요.
`stock` 딕셔너리에는 표준 재고 품목과 그 재주문 수량이 들어 있어요.
`outofstock` 딕셔너리는 `update_store_inventory!`의 결과, 즉 수량이 0인 품목들의 딕셔너리예요.
`outofstock`의 수량은 `stock`에 있는 값으로 업데이트되어 반환되어야 해요.
또한 `outofstock`에 있지만 `stock`에는 없는 품목은 기본 수량 `100`으로 `stock`에 추가되어야 해요.

```julia-repl
julia> inventory = Dict("Banana" => 15, "Apple" => 12, "Orange" => 1, "Milk" => 4, "Chocolate" => 2);

julia> cart = Dict("Orange" => 1, "Milk" => 2, "Banana" => 3, "Apple" => 2, "Chocolate" => 2);

julia> stock = Dict("Banana" => 150, "Apple" => 120, "Orange" => 120, "Milk" => 45);

julia> outofstock = update_store_inventory!(inventory, cart)
Dict{String, Int64} with 1 entry:
  "Orange"    => 0
  "Chocolate" => 0

julia> reorder!(outofstock, stock)
Dict{String, Int64} with 1 entry:
  "Orange"    => 120
  "Chocolate" => 100

julia> stock 
Dict{String, Int64} with 5 entries:
  "Milk"      => 45
  "Apple"     => 120
  "Chocolate" => 100
  "Orange"    => 120
  "Banana"    => 150
```
