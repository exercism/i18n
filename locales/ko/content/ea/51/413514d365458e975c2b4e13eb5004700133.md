# 제네릭 데이터 타입

Cairo의 제네릭을 사용하면 다양한 타입과 함께 동작하는 재사용 가능한 코드를 작성할 수 있어요. 중복을 피하고 유지보수성을 높여줘요.

제네릭은 함수, 구조체, 열거형, 트레이트, 메서드에 사용할 수 있어요.

## 제네릭 함수

제네릭 함수는 여러 타입에 대해 동작하며, 타입마다 따로 구현할 필요가 없어요.

예를 들어볼게요.

```rust
fn largest_list<T>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

여기서 `T`는 모든 타입을 대신하는 자리 표시자예요.

그런데 Cairo에서는 제네릭 타입이 특정 요구 사항을 만족하도록 트레이트 바운드가 필요해요.

`T`가 드롭 가능해야 한다면 시그니처를 이렇게 바꿀 수 있어요.

```rust
fn largest_list<T, impl TDrop: Drop<T>>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

`Drop`이나 `PartialOrd` 같은 트레이트 바운드는 제네릭에 제약을 추가해서 특정 연산을 가능하게 해요.

## 익명 제약

함수에서 트레이트 구현을 직접 사용하지 않는다면 `+`를 사용해 익명 제약을 쓸 수 있어요.

```rust
fn smallest_element<T, +PartialOrd<T>, +Drop<T>, +Copy<T>>(list: @Array<T>) -> T {
    let mut smallest = *list[0];
    let mut index = 1;

    while index < list.len() {
        if *list[index] < smallest {
            smallest = *list[index];
        }
        index += 1;
    };

    smallest
}
```

이렇게 하면 `TPartialOrd`처럼 트레이트에 이름을 붙이지 않아도 되어서 코드가 간결해져요.

## 제네릭을 사용하는 구조체

구조체에서 제네릭을 사용하면 필드를 유연하게 만들 수 있어요.

예를 들어볼게요.

```rust
#[derive(Drop)]
struct Wallet<T> {
    balance: T,
}

let w = Wallet { balance: 42 };
```

구조체에 여러 제네릭 타입이 필요하다면 자리 표시자를 더 추가하면 돼요.

```rust
#[derive(Drop)]
struct Wallet<T, U> {
    balance: T,
    address: U,
}

let w = Wallet { balance: 42, address: '0xabc' };
```

## 제네릭을 사용하는 열거형

열거형도 제네릭 데이터 타입을 담을 수 있어요.

예를 들어볼게요.

```rust
enum Option<T> {
    Some: T,
    None,
}
```

`Option<T>` 열거형은 모든 타입의 선택적 값을 나타낼 수 있어요.

마찬가지로 `Result<T, E>`는 성공과 실패 타입을 정의할 수 있게 해줘요.

```rust
enum Result<T, E> {
    Ok: T,
    Err: E,
}
```

## 제네릭 메서드

메서드도 제네릭을 사용할 수 있어요.

예를 들어볼게요.

```rust
#[derive(Copy, Drop)]
struct Wallet<T> {
    balance: T,
}

trait WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T;
}

impl WalletImpl<T, +Copy<T>> of WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T {
        *self.balance
    }
}

let w = Wallet { balance: 50 };
assert!(w.balance() == 50);
```

`Wallet<u128>`처럼 특정 제네릭 타입에 대한 메서드를 정의할 수도 있어요.

```rust
trait WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128);
}

impl WalletReceiveImpl of WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128) {
        self.balance += value;
    }
}

let mut w = Wallet { balance: 50 };
w.receive(100);
assert!(w.balance() == 150);
```

## 제네릭 타입 조합하기

제네릭은 복잡한 조합도 다룰 수 있어요.

예를 들어 서로 다른 타입의 `Wallet` 인스턴스 두 개를 조합해볼게요.

```rust
trait WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2>;
}

impl WalletMixImpl<T1, +Drop<T1>, U1, +Drop<U1>> of WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2> {
        Wallet { balance: self.balance, address: other.address }
    }
}

let w1 = Wallet { balance: true, address: 10 };
let w2 = Wallet { balance: 32, address: 100 };
let w3 = w1.mixup(w2);

assert!(w3.balance);
assert!(w3.address == 100);
```

`+Drop` 제약을 추가하면 컴파일러가 리소스를 적절히 처리하도록 보장해요.

제네릭은 강력하지만 제약을 신중하게 관리해야 해요.

제네릭을 활용해서 재사용 가능하고 타입에 구애받지 않으며 간결한 코드를 작성해 봐요.
