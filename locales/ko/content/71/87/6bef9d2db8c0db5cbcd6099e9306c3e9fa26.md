# 설명

## 복합 타입

프로그램에서 사용자 정의 타입을 정의하는 것은 유용할 때가 많아요.

새로운 기본 타입을 만드는 것도 가능하지만, 거의 하지 않아요.
내장된 [기본 타입][primitive]은 임의로 정한 선택이 아니에요. Julia가 JIT 컴파일을 위해 사용하는 LLVM 컴파일러의 표준 타입과 밀접하게 대응해요.

훨씬 유용한 것은 이름이 붙은 필드를 가진 [복합 타입][composite-types]을 정의하는 기능이에요.

다른 언어에도 비슷한 것이 있어서 `structs`나 `records`라고 불러요.
Julia 문서에서는 이것을 `composite types`라고 부르지만, (약간 어긋나게도) 언어 문법에서는 `struct` 키워드로 정의해요.

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

위 예제에서 짚어 볼 점이 몇 가지 있어요:

- `id`에는 타입을 지정하지 않았으므로 컴파일러는 이를 `id::Any`로 해석해요.
  - **참고:** 실제로는 필드의 타입을 구체 타입으로 지정해서 컴파일러를 도와주는 것이 가장 좋아요.
  - 매개변수를 사용하는 것도 또 하나의 방법이라는 점은 [나중에 다룰 개념][parametric]에서 살펴봐요.
- 타입 이름은 생성자로 사용돼요. `Person(id, name, age)`처럼 쓰면 `Person` 타입의 인스턴스를 만들어요.
- 개별 필드는 [이름 있는 튜플][named-tuple]과 마찬가지로 점 표기법으로 접근할 수 있어요.

`Person` 타입의 항목은 불변이므로 수정할 수 없어요.

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

가변성이 필요하면 정의에 `mutable`을 추가해요.

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

기본적으로 생성자는 필드가 정의된 순서와 같은 순서로 나타나야 하는데, 타입이 복잡해지면 이게 불편해져요.

`@kwdef` 매크로를 사용하면 두 가지 새로운 기능을 쓸 수 있어요:

- 생성자가 위치가 아니라 키워드를 사용해요.
- 필드에 기본값을 지정할 수 있고, 생성자에서 생략할 수도 있어요.

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## 복합 타입 계층 구조

지금까지는 구체 복합 타입만 만들어 봤어요.
확인해 보면 모두 `Any`의 하위 타입이에요.

서로 관련된 타입을 여러 개 만들 때는 그 타입들을 위한 계층 구조를 정의하는 편이 더 합리적일 거예요.
이건 아주 쉽게 할 수 있어요.

먼저 추상 타입을 만들어요:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

그다음, 타입 정의에 `<:` 연산자를 넣어서 관계를 나타내요.

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

필요한 만큼 반복해요. 구체 타입의 하위 타입을 만드는 것은 허용되지 않는다는 점을 기억해요.

더 복잡한 계층 구조가 필요하면 추상 하위 타입을 필요한 만큼 만들어요.

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

이런 계층 구조의 가치는 함수가 인자 타입을 어떻게 다루는지 보게 되는 `Multiple Dispatch` 개념에 이르면 더 분명해져요.


## 내부 생성자

이 개념의 처음에서 타입 이름이 생성자로 사용되어 그 타입의 항목을 만든다는 것을 봤어요:

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)
```

여기서 `Person()`은 `outer constructor`라고 해요.
필드 타입은 타입 정의와 호환되는지 검사하고, 필요하면 오류를 발생시켜요.

들어오는 _타입_뿐 아니라 _값_에도 제약을 두고 싶다면 어떻게 할까요?

그럴 때는 타입 정의 안에 `inner constructor`를 넣어서 적절한 검사를 수행할 수 있어요.

예를 들어 `(x, y)` 좌표를 받도록 만든 추상 타입 `AbstractPoint`가 있는데, `y > x`라는 제약을 가진 하위 타입을 원한다고 해봐요.

```julia-repl
julia> abstract type AbstractPoint end;

julia> struct Point <: AbstractPoint
           x::Integer
           y::Integer
       end;

julia> struct ConstrainedPoint <: AbstractPoint
           x::Integer
           y::Integer
           
           ConstrainedPoint(x, y) =
               y > x ? new(x, y) : @error("require y > x")
       end;
       
julia> Point(3, 2)
Point(3, 2)

julia> ConstrainedPoint(3, 2)
Error: require y > x

julia> ConstrainedPoint(3, 5)
ConstrainedPoint(3, 5)
```

`new()` 함수는 _오직_ 내부 생성자에서만 사용할 수 있고, 입력이 유효하다고 판단되면 원하는 항목을 반환해요.

유효하지 않은 입력에 대해서는 예제처럼 오류 메시지를 내고 멈출 수도 있어요.
또는 `nothing`이나 `missing` 같은 자리 표시자를 사용하는 편이 좋을 수도 있어요.
이에 대한 자세한 내용은 [`Nothingness`][nothingness] 개념을 참고해요.
