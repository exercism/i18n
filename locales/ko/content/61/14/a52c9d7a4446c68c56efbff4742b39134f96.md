# 소개

정규 표현식은 문자열을 _패턴 매칭_하는 매우 다재다능한 방법으로, 이를 위해 설계된 도메인 특화 언어(DSL)를 사용해요.

정규 표현식 기능 중 상당수는 Base R에 내장되어 있어서, 오래된 코드에서 그런 예를 볼 수 있어요.

새로 작성하는 코드에서는 [`stringr`][web-stringr] 라이브러리를 사용하기를 _강력히_ 권장해요.

[Strings 개념][concept-strings]에서 언급했듯이, `stringr`은 문서가 잘 갖춰져 있고, 보통 패키지 작성자가 직접 작성해요.

[`Strings`][concept-strings] 개념에서 이미 다룬 함수 중 상당수는 기본적으로 정규 표현식 검색을 염두에 두고 설계되어 있어요.

Strings 개념에서는 문자열 리터럴에만 매칭하도록 비교적 단순하게 설명했지만, 대신 어떤 정규 표현식 패턴이든 사용할 수 있어요.

엄밀히 말하면, R에서는 [`regex()`][ref-regex]를 호출해서 정규 표현식을 만들어요.
편의를 위해, `stringr` 함수들은 어떤 패턴 문자열이든 정규 표현식으로 취급해요.
아래 예제에서 첫 번째 `str_replace_all()`은 두 번째 형태의 편의 문법이에요.

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[치트시트][cheat-stringr]는 유용한 안내서예요. `pattern` 인자를 가지는 함수는 모두(빨간색으로 표시돼 있어요) 정규 표현식을 받아들이고, 2쪽에는 정규 표현식 문법이 요약되어 있어요.

대소문자 구분이나 로케일처럼 기본 설정을 바꿔야 할 때는 [`regex()`][ref-regex] 함수가 여전히 중요할 수 있어요.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

많은 정규 표현식 기호에는 위에서 쓴 `\s`처럼 백슬래시가 들어가요.
일반 R 문자열에서는 `\`를 두 번 써서 이스케이프해야 하므로 `"\\s"`가 돼요.

백슬래시가 많아지면 헷갈리기 쉬우니, 복잡한 경우에는 [원시 문자열][book-raw]을 쓰면 도움이 돼요.

기본적으로 원시 문자열을 정의하는 문법은 `r"( )"`이지만, 다른 구분자도 쓸 수 있어요.
정규 표현식 문법에서는 괄호 `( )`와 대괄호 `[ ]`가 (캡처 그룹과 옵션 그룹에) 모두 자주 쓰이니, 중괄호 `{ }`가 좋은 선택일 수 있어요.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## 매치 탐지하기

다음은 몇 가지 질문과, 그 답을 찾는 데 도움이 되는 함수들이에요.

일부 예제에서는 연습용으로 `stringr`에 포함된, 과일 이름 80개로 이루어진 벡터 `fruit`를 사용해요.

_문자열에 매치가 들어 있나요?_
`str_detect()`를 쓰거나, `^`나 `$` 앵커를 피하려면 `str_starts()`, `str_ends()`를 써요.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_매치를 포함하는 문자열만 반환하고 싶나요?_
문자열은 `str_subset()`으로, 인덱스는 `str_which()`로 얻어요.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_각 문자열에 매치가 몇 개 있나요?_
`str_count()`를 써요.

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_매치가 어디에 있나요?_
대화형으로 쓰려면 `str_view()`, 더 일반적으로는 `str_locate()`나 `str_locate_all()`을 써요.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## 캡처

흔히 우리는 _무엇이_ 매치되는지 알고 싶어 해요.
이는 정규 표현식 안에 괄호로 캡처 그룹을 넣어서 얻을 수 있어요.

같은 정규 표현식 안에서 `\1`, `\2` 등으로 캡처를 다시 참조할 수 있어요.
예를 들어, 반복되는 두 글자 쌍을 찾는 경우예요.

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

비슷한 문법으로, 캡처를 치환 문자열에서도 사용할 수 있어요.

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

나중에 처리할 수 있도록 매치를 모으려면 첫 번째 매치만 필요할 때는 `str_match()`, 모든 매치가 필요할 때는 `str_match_all()`을 써요.

캡처 그룹은 어떤 언어에서든 복잡한 출력을 만들어 내기 마련이에요.
R의 방식은 (_덤으로 벡터화까지 되어 있어요_) `str_match()`로 행렬을 만드는 것인데, 입력 문자열마다 행이 하나씩 생기고, 1열에는 전체 매치된 문자열이, 나머지 열에는 각각의 캡처 그룹이 들어가요.

이름 있는 그룹을 쓰면 결과 행렬의 열 이름이 되기 때문에 이점이 될 수 있어요.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

여기서는 행렬에 대해 많이 다루지 않았지만, 참고할 수 있는 [개념 문서][concept-matrices-arrays]가 있어요.
행렬은 오랫동안 Base R의 일부였지만, Tidyverse 생태계와는 잘 어울리지 않아요.

간단히 요약하면, 행렬은 인덱스가 두 개인 벡터처럼 다루면 되고, 순서는 `[rows, cols]`예요.
인덱스를 비워 두면 해당 행이나 열 전체를 얻어요.

`m[r,]`로 행 하나 `r`을 가져오거나 `m[,c]`로 열 하나 `c`를 가져오면, 반환되는 값은 기본적으로 벡터로 평탄화돼요.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

`str_match_all()`은 어쩔 수 없이 훨씬 더 복잡한 구조의 출력을 만들어요.

- 결과는 리스트이고, 입력 문자열마다 원소가 하나씩 있어요.
- 입력 문자열이 하나뿐이라면, [Lists 개념][concept-lists]에서 설명한 대로 `[[1]]` 인덱싱으로 출력의 리스트를 풀어요.
- 각 원소는 행렬이고, 열의 구성은 `match()`와 같아요.
- 행렬의 각 행은 성공한 캡처 하나예요.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

물론 매치는 실패할 수도 있어요.
그러면 결과는 특별한 값 `NA`가 돼요.
[Nothingness 개념][concept-nothingness]에서 설명한 대로, 이 경우를 검사할 준비를 해두세요.

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
