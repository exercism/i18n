# 불리언

`BOOL`은 두 값, `true`와 `false` 중 하나를 저장해요.

```sather
   ready : BOOL is
      return true;
   end;
```

## 비교

| 연산자 | 묻는 것 | 예시 |
| --- | --- | --- |
| `=` | 같은가? | `age = 13` |
| `/=` | 다른가? | `age /= 13` |
| `<` | 미만 | `age < 13` |
| `<=` | 이하 | `age <= 13` |
| `>` | 초과 | `age > 13` |
| `>=` | 이상 | `age >= 13` |

이 연산자들은 숫자에 쓸 수 있고, `=`와 `/=`는 문자열에도 쓸 수 있어요.

## 세 가지 연산자

| 연산자 | 표기 | 참인 경우 |
| --- | --- | --- |
| and | `a and b` | 둘 다 참일 때 |
| or | `a or b` | 적어도 하나가 참일 때 |
| not | `~a` | `a`가 거짓일 때 |

`and`와 `or`는 **단락 평가**를 해요. `a and b`에서 `a`가 거짓으로 밝혀지면 답은 이미 정해졌으니 `b`는 볼 필요조차 없어요. 마찬가지로 `a or b`는 `a`가 참이면 거기서 멈춰요. 오른쪽 항을 계산하는 데 비용이 많이 들거나, 실행되면 잘못될 상황에서 이 점이 중요해요.

## 비교 결과를 그대로 반환하기

질문을 던지는 것이 전부인 루틴이라면, 조건문으로 답을 고르는 대신 그 질문을 그대로 반환해야 해요.

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

`if age >= 13 then return true else return false end`라고 쓰면, 비교식이 이미 말한 내용을 세 줄에 걸쳐 다시 말하는 셈이고, 경험 많은 독자라면 누구나 알아차려요.

## 우선순위

`~`가 가장 강하게 묶이고, 그다음이 `and`, 마지막이 `or`예요. 그래서

```sather
~a and b or c
```

는 `((~a) and b) or c`를 뜻해요. 괄호는 쓰는 데 드는 비용이 없고, 독자가 그 순서를 기억해 내야만 줄을 따라갈 수 있는 상황이라면 쓸 만한 가치가 있어요.
