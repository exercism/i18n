# 소개

다른 많은 언어와 마찬가지로, C++에도 _포인터_가 있어요.
_참조_와 _포인터_가 비슷하다는 건 이미 알겠지만, 이들을 컴퓨터 내부 동작에 한 단계 더 가까이 있는 개념이라고 생각해 봐요.
_포인터_는 객체의 주소를 담는 변수예요.
포인터는 객체와 직접 상호작용하는 데 쓰이며, C++에서 동적 메모리 할당과 효율적인 데이터 조작을 가능하게 해요.

_포인터_가 처음이라면 조금 신비롭게 느껴질 수 있지만, 한번 익숙해지면 아주 단순해요.

포인터는 C++에서 아주 중요한 부분이니, 시간을 들여 제대로 이해해 봐요.
이 개념에서 다루는 가장 기본적인 형태는 _dumb pointer_ 또는 _raw pointer_라고도 불러요.
현대 C++에는 _smart pointer_도 있는데, 기본 타입은 전혀 똑똑하지 않아서 모든 작업을 직접 처리해야 해요.

세부 사항을 파헤치기 전에, _포인터_의 쓰임새를 먼저 이해해 두면 좋아요.
_포인터_는 객체의 주소를 프로그램의 다른 부분과 공유하는 방법이에요. 이는 크게 두 가지 이유에서 유용해요:

1. _참조_처럼, 포인터는 복사를 피하고 프로그램의 리소스 사용량을 줄이는 데 도움을 줘요.
1. _참조_와 달리, 포인터는 다른 객체를 가리키도록 다시 할당할 수 있어요.
1. 포인터는 null 값을 가리킬 수도 있는데, 이는 현재 아무 객체도 가리키지 않는다는 것을 나타내요.

## 일반적인 문법

C++에서 포인터를 선언할 때는 포인터가 가리킬 데이터 타입을 지정하고, 그 뒤에 별표(`*`)와 포인터의 이름을 붙여요.
포인터는 선언한다고 해서 자동으로 초기화되지 않아요.
명시적으로 값을 할당하지 않으면 포인터는 보통 불확정한 값을 가지는데, 이를 흔히 "쓰레기 주소"라고 불러요.
일부 컴파일러는 포인터를 `nullptr`로 초기화하기도 하지만, 이 동작이 모든 컴파일러에서 보장되는 것은 아니므로 여기에 의존하지 않는 것이 중요해요.
잠재적인 문제를 피하려면 raw pointer를 명시적으로 초기화하고, 사용하기 전에 null이 아닌지 확인하는 것이 좋아요.

```cpp
int* ptr{nullptr}; // Declares a pointer and makes sure it is not invalid
```

변수의 주소를 포인터에 할당하려면 주소 연산자(`&`)를 사용해요.
포인터를 역참조할 때는 _간접 참조 연산자_(`*`)를 사용해요.

```cpp
std::string opponent{"Solomon Lane"};
// 'ethan' points to the address of the string opponent
std::string* ethan{&opponent};
// Instead of ethan's, the opponent's name address is given to the passPort
std::string passportName{*ethan};
```

한 가지 주의할 점이 있어요. 역참조는 명시적으로 해야 하지만, _참조_는 그냥 별칭처럼 동작해요.

## 포인터 연산

_포인터 연산_을 사용하면 포인터에 산술 연산을 할 수 있는데, 배열을 다룰 때 특히 유용해요.
포인터에 정수를 더하면 다른 원소를 가리키게 돼요.

```cpp
// Stargate Coordinate Code
int gateCode[] = {462, 753, 218, 611, 977};
// 'ptr' points to the first element of 'gateCode'
int* ptr{&gateCode[0]};
// Accesses the third Stargate address through pointer arithmetic
int dialedAddress{*(ptr + 2)};
// Chevron encoded! Dialing Stargate address:
openStarGate(dialedAddress);
```

~~~~exercism/caution
C++에서 포인터 연산은 주의 깊게 다루지 않으면 __정의되지 않은 동작__으로 이어지기 쉬워요.
정의되지 않은 동작은 예상치 못한 프로그램 결과나 충돌, 심지어 보안 취약점으로 나타날 수 있어요.
정의되지 않은 동작이 낳은 결과의 악명 높은 사례가 1996년 [아리안 5호 로켓 폭발][ariane-flight-v88]이에요. 당시 64비트 부동소수점 수를 16비트 부호 있는 정수로 변환하면서 발생한 소프트웨어 예외가 치명적인 실패로 이어졌어요.

## 멤버 변수에 접근하기

C++에서는 `->` 연산자를 사용해 객체를 가리키는 포인터를 통해 그 객체의 멤버에 접근해요.
이 연산자는 포인터가 가리키는 객체의 멤버에 접근하는 작업을 간결하게 만들어 주는 축약형이에요.
예를 들어, `ptr`이 멤버 변수 `x`를 가진 객체를 가리키는 포인터라면, `(*ptr).x` 대신 `ptr->x`를 바로 사용할 수 있어요.
이 연산자는 객체를 가리키는 포인터를 다룰 때 코드 가독성을 높이고 군더더기를 줄여줘요.

멤버 변수 `superpower`를 가진 _struct_ `Superhero`를 사용한 간단한 예제를 볼까요.
main 함수는 `Superhero` 객체(원더 우먼을 나타내요)를 가리키는 포인터 `dianaPrince`를 만들어요.
`->` 연산자로 멤버 변수 `superpower`에 접근해서, 원더 우먼의 상징적인 "진실의 올가미"를 보여줘요.

```cpp
struct Superhero {
    std::string superpower;
};
Superhero wonder_woman{};
Superhero* dianaPrince = &wonder_woman;
dianaPrince->superpower = "Lasso of Truth";
// Using the -> operator to access member variable superpower:
std::cout << "Wonder Woman, possesses the mighty " << dianaPrince->superpower;
// Memory cleanup:
delete dianaPrince;
```

## 포인터와 참조

포인터와 참조는 모두 객체에 간접적으로 접근할 수 있게 해주지만, 기능과 안전성 측면에서 차이가 있어요.
포인터는 가리키는 대상을 바꿀 수 있는 유연성을 제공하고, null을 할당할 수도 있어요.
하지만 이런 유연성은 null 포인터를 역참조하거나 댕글링 포인터를 만드는 등의 위험을 가져와요.
반면 참조는 null이 될 수 없고 생성될 때 유효한 객체에 묶이기 때문에, 이런 위험을 피할 수 있어요.
참조가 더 안전하므로, 포인터가 제공하는 추가 기능이 꼭 필요한 경우가 아니라면 참조를 포인터보다 선호하는 게 좋아요.
