# 소개

## SIMD: 비트 연산

대부분의 스칼라 비트 연산에는 패킹된 변형이 있어요.
이들은 SIMD 정수 연산과 같은 일반적인 문법을 따르지만, 크기 접미사가 없어요:

| 명령어 | 설명 |
|-------------|-----------------------------------|
| `pand`      | 두 128비트 값의 비트 AND |
| `por`       | 두 128비트 값의 비트 OR |
| `pxor`      | 두 128비트 값의 비트 XOR |

패킹된 `NOT`은 없어요.
대신 ANDN 연산이 있는데, 이 연산은 **목적지** 피연산자를 보수화(모든 비트를 뒤집기)한 다음 두 피연산자 사이의 AND를 계산해요.
NOT과 AND를 합쳐 놓은 것이라고 생각하면 돼요:

| 명령어 | 설명 |
|-------------|-----------------------------------------------------------------|
| `pandn`     | **보수화된** 목적지와 소스의 비트 AND |

비트 연산은 서로 다른 두 피연산자의 같은 위치에 있는 비트를 결합하므로, 레인 경계가 결과를 바꿀 수 없어요.
그래서 이 명령어들에는 크기 접미사가 없고, 레지스터는 하나의 128비트 레인처럼 동작해요:

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
이 개념의 모든 명령어는 비트를 계산할 뿐, 플래그는 설정하지 않아요.
패킹된 값으로 조건을 다루는 방법은 이후 개념에서 살펴봐요.
~~~~

### 레인별 시프트

시프트는 순수한 비트 연산과 달리 실제로 비트를 다른 위치로 옮기기 때문에, 경계를 정할 레인 크기가 필요해요.
각 레인 안에서는 스칼라 연산과 같은 방식으로 동작하고, 비트가 이웃 레인으로 넘어가는 일은 없어요:

| 명령어               | 설명                         |
|---------------------------|-------------------------------------|
| `psllw`, `pslld`, `psllq` | 레인별 논리 왼쪽 시프트        |
| `psrlw`, `psrld`, `psrlq` | 레인별 논리 오른쪽 시프트       |
| `psraw`, `psrad`          | 레인별 산술 오른쪽 시프트    |

이 명령어들은 크기 접미사를 포함해 패킹된 정수 연산의 문법을 따라요.
바이트 레인 시프트는 없고, 워드와 dword, 그리고 산술 오른쪽 시프트를 빼면 qword만 있어요.

패킹된 시프트와 스칼라 시프트의 한 가지 차이는 연산 이름에 있어요:

- `shl`과 `shr` 대신에 **s**hift **l**eft (**r**ight) **l**ogical의 약자인 `sll`과 `srl`을 써요.
- `sar` 대신에 **s**hift **r**ight **a**rithmetic의 약자인 `sra`를 써요.

이름은 다르지만 연산은 같아요:

- 논리 오른쪽 시프트는 가장 위쪽 비트를 0으로 채워요.
  2의 거듭제곱으로 나누는 부호 없는 나눗셈과 같아요.
- 산술 오른쪽 시프트는 가장 위쪽 비트를 부호 비트의 값으로 채워요.
  음의 무한대 방향으로 반올림하는, 2의 거듭제곱으로 나누는 부호 있는 나눗셈과 같아요.
- 왼쪽 시프트는 항상 0으로 채워요(그래서 산술 왼쪽 시프트가 필요 없어요).

시프트 횟수는 모든 레인에서 같아요.
즉시값일 수도 있고, `xmm` 레지스터의 하위 64비트일 수도 있어요:

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
레인 폭보다 큰 시프트 횟수는 스칼라 `shl`/`shr` 계열처럼 순환하지 않아요.
그냥 0을 만들어요(산술 오른쪽 시프트라면 부호 비트로 모두 채워요).
~~~~

### 부동소수점 비트 연산

각 비트 연산 명령어에는 부동소수점 이름을 가진 쌍둥이도 있는데, 패킹된 부동소수점 연산에서 봤던 것과 같은 문법을 따라요:

| 정수 이름 | 부동소수점 이름          |
|--------------|----------------------|
| `pand`       | `andps`, `andpd`     |
| `pandn`      | `andnps`, `andnpd`   |
| `por`        | `orps`, `orpd`       |
| `pxor`       | `xorps`, `xorpd`     |

비트 연산은 비트를 다루기 때문에, 실제로 정수 연산과 부동소수점 연산은 같은 결과를 계산해요.
이름이 다른 데에는 두 가지 이유가 있어요:

1. 의도를 문서화하기 위해서예요. 복사하는 바이트의 성격에 따라 `movdqa`, `movaps`, `movapd` 중 하나를 고르는 것과 같은 이치예요.
2. 정수 연산과 부동소수점 연산은 실행 도메인이 다른 경우가 많아요.
   같은 실행 도메인에 속한 연산들은 보통 더 빠르게 이어서 실행할 수 있어요.

부동소수점 값에는 시프트 연산이 없어요.

### 부동소수점 비트 표현

IEEE 부동소수점 수의 비트 표현은 정수와 아주 달라요.

부호 없는 정수에서 각 비트는 똑같은 의미를 가져요. 즉 비트 인덱스에 해당하는 2의 거듭제곱을 나타내죠.
정수는 1로 설정된 비트에 해당하는 2의 거듭제곱들의 합이에요.
그래서 비트를 시프트하면 수를 2의 거듭제곱으로 곱하거나 나눌 수 있어요. 각 설정된 비트의 인덱스를 바꾸는 것뿐이니까요.

부호 있는 정수에서는 대부분의 비트가 부호 없는 정수와 같은 방식으로 해석돼요.
하지만 가장 위쪽 비트는 특별해요.
이 비트가 1이면 다른 비트들처럼 더하는 대신, 해당하는 2의 거듭제곱을 빼야 하고, 그 결과 음수가 돼요.
실제로 수의 부호를 바꾸려면 개념적으로 두 단계가 필요해요. 모든 비트를 뒤집고(`not`), 그 결과에 1을 더하는(`inc`) 것이죠.

부동소수점 수의 비트들은 똑같은 의미를 가지지 않고, 위치에 따라 아주 다르게 해석해야 해요:

| 필드    | 인덱스(32비트) | 인덱스(64비트) |
|----------|------------------|------------------|
| 부호     | 31               | 63               |
| 지수 | 30-23            | 62-52            |
| 가수 | 22-0             | 51-0             |

결과 수는 `(-1)^sign * 1.fraction * 2^(exponent - bias)`로 계산돼요.
바이어스는 정밀도에 따라 달라져요:

| 크기   | 바이어스 |
|--------|------|
| 32비트 | 127  |
| 64비트 | 1023 |

두 형식 모두에서 수의 부호는 오로지 부호 비트로만 결정돼요.
부동소수점 수의 부호를 바꾸려면 이 비트를 뒤집기만 하면 돼요(XOR 연산).
절댓값을 구하려면 이 비트를 지우기만 하면 돼요(해당 비트를 지우는 AND 연산):

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

이 비트 표현에서는 비트를 시프트해도 예측 가능하고 일관된 결과가 나오지 않아요.
가수가 지수 자리로 '흘러넘칠' 수 있고, 지수가 부호 자리로 흘러넘칠 수 있어요.

그래도 표현의 각 부분을 따로 떼어내어 다루는 것이 편리할 때가 있어요.

예를 들어 지수의 비트들은 바이어스를 빼기 전에 먼저 부호 없는 수로 해석해야 해요.
이 말은, 기반 비트 표현이 해당 부동소수점 형식에서 어떤 2의 거듭제곱에 대응하는 32비트나 64비트 정수를 만들 수 있다는 뜻이에요.
그러면 이 원시 비트 표현을 써서 다른 부동소수점 수를 곱하거나 나눌 수 있어요.

예를 들어:

```x86asm
mov eax, 210             ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23              ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax           ; we move the raw bits to xmm0
mulss xmm1, xmm0         ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

반대로, 지수 비트는 1로, 나머지 비트는 0으로 설정된 마스크와 AND를 수행해 패킹된 부동소수점 수의 지수를 추출할 수 있어요.
여기에 시프트와 뺄셈을 더하면, 모든 레인의 바이어스가 제거된 지수를 부호 있는 정수로 얻을 수 있어요:

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
부동소수점 수의 원시 비트를 직접 다루는 것은 어떤 상황에서는 유용하지만, 주의해서 해야 해요.
지수 필드에 더하거나 빼는 것은 오버플로나 언더플로가 없고 입력 수가 정규 수일 때만 안전해요.
또한 `0.0`의 지수 필드에 유효한 `x`를 더하면 `2^(x - bias)`가 되지, `0.0 * 2^x`가 되지 않아요.
~~~~
