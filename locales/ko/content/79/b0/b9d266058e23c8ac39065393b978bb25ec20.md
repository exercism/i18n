# 개요

동적 메모리는 프로그래머가 런타임에 메모리를 할당하고 해제할 때 사용하는 라이브러리 함수로 구현돼요.
메모리의 할당과 해제를 프로그래머가 직접 제어하기 때문에, 동적 메모리는 프로그래머가 실수를 하지 않는 만큼만 안전해요.
그래서 동적 메모리는 프로그래밍 버그의 주요 원인 중 하나이고, 해킹 공격의 주요 표적이기도 해요.

동적 메모리는 크기를 실행 중에야 알 수 있는 변수에 사용해요.
이런 변수는 실행할 때마다 원소 개수가 달라질 수 있는 배열에서 특히 유용해요.
가변 길이 배열(VLA)은 원소의 크기를 실행 중에만 알 수 있는 배열을 다루는 또 다른 방법이에요.
VLA는 자동 저장을 사용하기 때문에, 정의된 블록을 벗어나면 메모리가 소멸돼요.
(저장에 대한 자세한 내용은 [저장 클래스 지정자](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers) 개념을 참고해요.)
VLA는 C99에서 C 언어에 도입됐지만, C11부터는 선택 사항이라 C11 이후를 지원하는 컴파일러가 VLA를 반드시 지원해야 하는 것은 아니에요.
가변 길이 배열에 대한 자세한 분석은 이 글의 범위를 벗어나요.

## malloc

`malloc`은 `stdlib.h`에 선언된 함수로, 동적 메모리를 할당할 때 사용해요.
할당에 성공하면 할당된 메모리의 첫 번째 바이트 주소를 가리키는 포인터가 반환돼요.
할당에 실패하면 `NULL`이 반환돼요.
`malloc`의 결과가 `NULL`인지 확인하고, 실패했을 때 적절히 처리하는 것이 좋아요.
반환되는 포인터는 `pointer-to-void` 타입인데, 이는 대략 메모리에서 사용할 구체적인 타입으로 변환할 수 있는 "일반적인" 포인터라고 볼 수 있어요.
`malloc`은 매개변수가 하나이고, 그 값은 원하는 메모리의 크기를 바이트 단위로 나타내요.
배열을 할당할 때 필요한 전체 크기는 각 원소의 데이터 타입 크기에 원소 개수를 곱한 값이에요.
`sizeof` 연산자는 각 원소의 데이터 타입 크기를 구할 때 흔히 사용해요.
다음 예제를 보면 알 수 있어요.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

`malloc`으로 새로 할당한 메모리는 초기화되지 않고 쓰레기 값이 들어 있을 수 있다는 점을 기억하는 게 중요해요.
`numbers` 포인터에 `sizeof`를 적용한 값은 배열의 원소 개수도, 할당된 메모리의 총량도 아니에요.
`malloc`이 반환한 포인터의 크기는 그 시스템에서 모든 포인터가 가지는 크기와 같아요.
예제 코드는 64비트 시스템에서 실행했기 때문에 포인터의 크기가 8바이트였어요(바이트당 8비트를 곱하면 64비트예요).
포인터 타입은 void 포인터에서 int 포인터로 암묵적으로 변환됐어요.
int 포인터가 `int` 하나를 가리키는지 `ints` 배열을 가리키는지는 프로그래머가 상황에 맞게 다루면 돼요.
예를 들어 볼까요.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

값을 읽기 전에 반드시 쓸 거라면, `malloc`으로 메모리를 할당하는 것이 효율적인 방법이 될 수 있어요.
하지만 초기화되기 전에 값을 읽을 가능성이 있다면 `malloc`을 쓰는 건 위험해요.
더 안전하게 메모리를 할당하는 방법은 `calloc`을 사용하는 것인데, `calloc`은 새로 할당한 메모리를 0으로 초기화해요.

위 예제에서 `free(numbers)`를 사용했다는 점에 주목해요.

## free

`free`는 `stdlib.h`에 선언된 함수로, 동적으로 할당한 메모리를 해제할 때 사용해요.
동적으로 할당한 메모리는 `free`로 해제할 때까지 메모리에서 계속 차지된 상태로 남아 있어요.
일부 운영체제는 프로그램이 끝날 때 동적으로 할당한 메모리를 자동으로 해제하기도 하지만, 그것에 의존하지 않는 것이 좋은 습관이에요.
`free`는 매개변수가 하나이고, 그 값은 동적으로 할당한 메모리를 가리키는 포인터예요.
`free`를 쓰는지 쓰지 않는지는 여러 가지 메모리 문제와 관련이 있어요.

#### 메모리 누수

동적으로 할당한 메모리를 가리키는 참조가 수명을 다하거나 다른 이유로 사라진 뒤에도 그 메모리를 해제하지 않는 것을 메모리 누수라고 해요.
누수된 메모리는 시스템이 계속 차지하고 있지만 프로그램에서 더 이상 접근할 수 없는 메모리예요.
루프 안에서 메모리를 할당하고, 루프가 끝날 때 해제하지 않은 채, 다음 루프가 시작될 때 다시 할당하면 특히 문제가 될 수 있어요.
해제하지 않은 채 메모리를 계속 할당하면, 남은 메모리가 부족해져서 메모리 할당 호출이 실패하게 돼요.
동적으로 할당한 메모리는 해제할 때까지 시스템이 차지하고 있지만, 그 메모리를 가리키도록 대입한 포인터는 블록 스코프만 가질 수 있다는 점을 기억하는 게 중요해요.
예를 들어 `malloc` 예제에서는 `my_function` 안에서 메모리를 할당해요.
그 메모리를 가리키는 포인터를 반환해서 `main`의 `numbers` 포인터에 대입하지 않았다면, 그 메모리는 누수됐을 거예요.
따라서 그 `numbers` 포인터를 `free`에 넘기면 `my_function`에서 할당한 메모리가 해제돼요.

#### 해제 후 사용 (**UAF**)

메모리를 해제한 뒤에 접근하면, 그 값이 무엇이든 될 수 있어요.
다음 예제에서는 `numbers`가 가리키는 메모리를 해제한 뒤 `printf`에서 그 값을 읽어요.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

`numbers` 포인터는 해제된 뒤에는 댕글링 포인터라고 해요.
댕글링 포인터는 원래 의도한 메모리가 아닌 다른 메모리를 가리킬 수 있어요.
그래서 댕글링 포인터는 데이터 손상과 임의 코드 대체 및 실행으로 이어질 수 있어요.
할당한 메모리를 가리키는 포인터를 `NULL`로 설정해 비우지 않으면, 그 포인터를 이용해 프로그램을 해킹할 수 있어요.
위 예제에서 `numbers`를 해제한 뒤 `numbers = NULL;`처럼 `NULL`로 설정했다면, 뒤따르는 `printf`는 `numbers[0]`을 읽으려 할 때 세그멘테이션 오류를 보고하면서 프로그램을 종료시켰을 거예요.

#### 이중 해제

동적으로 할당한 메모리를 가리키는 포인터에 `free`를 두 번 호출하면 정의되지 않은 동작(**UB**)이 돼요.
이는 컴파일러가 원하는 대로 임의로 처리할 수 있다는 뜻이에요.
다음 예제는 서로 다른 두 컴파일러로 컴파일하면 서로 다른 결과가 나올 수 있어요.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

첫 번째와 두 번째 컴파일러는 `free`를 호출할 때마다 그 사이에 `numbers`를 `NULL`로 설정했을 때 런타임 오류를 내지 않았지만, 세 번째 컴파일러에서도 그렇게 동작한다는 보장은 없어요.
이중 해제의 흔한 원인은 같은 동적으로 할당한 메모리를 가리키는 포인터가 두 개 있는 경우예요.
한 포인터는 프로그램의 한 위치에서 배열의 시작을 가리키고, 다른 포인터는 프로그램의 다른 위치에서 배열을 순회할 때 사용될 수 있어요.
프로그램의 서로 다른 위치에서 각각의 포인터를 해제하면 이중 해제가 발생해요.

## calloc

`calloc`은 `stdlib.h`에 선언된 함수로, 동적 메모리를 할당하는 것과 새로 할당한 메모리를 0으로 초기화하는 것을 모두 해요.
할당에 성공하면 할당된 메모리의 첫 번째 바이트 주소를 가리키는 포인터가 반환돼요.
할당에 실패하면 `NULL`이 반환돼요.
`calloc`의 결과가 `NULL`인지 확인하고, 실패했을 때 적절히 처리하는 것이 좋아요.
반환되는 포인터는 `pointer-to-void` 타입인데, 이는 대략 메모리에서 사용할 구체적인 타입으로 변환할 수 있는 "일반적인" 포인터라고 볼 수 있어요.
`calloc`은 매개변수가 두 개예요.
첫 번째 매개변수는 지정한 데이터 타입을 몇 개 할당할지를 나타내요.
두 번째 매개변수는 할당할 지정한 데이터 타입의 크기를 나타내요.

다음 예제에서 모든 `printf` 문은 항상 `0`을 출력해야 하는데, `calloc`은 새로 할당한 값을 0으로 만드는 것이 보장되기 때문이에요.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc`은 `stdlib.h`에 선언된 함수로, 이미 할당된 메모리를 늘리거나 줄일 때 사용해요.
재할당에 성공하면 재할당된 메모리의 첫 번째 바이트 주소를 가리키는 포인터가 반환돼요.
재할당에 실패하면 `NULL`이 반환돼요.
`realloc`의 결과가 `NULL`인지 확인하고, 실패했을 때 적절히 처리하는 것이 좋아요.
`realloc`은 매개변수가 두 개예요.
첫 번째 매개변수는 재할당할 기존 메모리를 가리키는 포인터예요.
두 번째 매개변수는 재할당할 메모리의 크기를 바이트 단위로 나타내요.
메모리를 늘리기 전에 설정한 값은 그대로 유지돼요.
메모리를 늘릴 때 추가되는 메모리는 0으로 초기화되지 않으며 그 값이 무엇이든 될 수 있다는 점을 기억하는 게 중요해요.
또한 메모리를 줄일 때 제거되는 메모리도 초기화되지 않고 값을 그대로 가지고 있을 수 있어요.
다음 예제는 배열을 늘리고 줄이는 것을 보여줘요.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## 크기가 0일 때

`malloc`, `calloc` 또는 `relloac`에 넘긴 크기가 `0`이면, 어떻게 될지는 컴파일러가 그것을 어떻게 구현했는지에 따라 달라요.
컴파일러는 `NULL` 포인터를 반환할 수도 있고, 널이 아닌 포인터를 반환할 수도 있어요.
예를 들어 `char`를 가리키는 포인터를 위한 메모리를 할당할 때, 컴파일러는 `NULL`을 반환할 수도 있고 빈 문자열을 가리키는 널이 아닌 포인터를 반환할 수도 있어요.
컴파일러마다 결과가 달라지는 것을 피하려면 크기가 0인 할당은 하지 않는 것이 가장 좋아요.
