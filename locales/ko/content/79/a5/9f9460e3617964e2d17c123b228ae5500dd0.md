# 소개

`channel-chatter`에서 스트림을 *사용*해 봤고, `boatswains-bilge`에서 스트림을 정리했어요. 이번 연습 문제는 직접 만드는 첫 스트림이에요. [프로토콜][stream-protocol]을 구현하는 클래스로, `<string-reader>`에서 작동하던 `with-input-stream` / `read1` / `stream-read1` 코드가 여러분의 스트림에서도 똑같이 작동하게 해줘요.

## 믹스인: 클래스 계층의 나머지 절반

`dragons-descendants`에서 `TUPLE: child < parent …`를 이미 알고 있어요. 슬롯이 아래로 흐르는 단일 부모 계층이죠. Factor에는 클래스 그래프를 확장하는 *또 다른* 방법이 있어요. 바로 **열린 믹스인**이에요. `MIXIN: m`은 슬롯이 없는 클래스를 선언하고, 다른 클래스들은 나중에 `INSTANCE: c m`으로 그 클래스에 참여할 수 있어요. 소속 관계는 다대다라서, 하나의 클래스는 원하는 만큼 많은 믹스인의 인스턴스가 될 수 있어요.

스트림 프로토콜은 두 개의 믹스인으로 클래스가 인터페이스의 어느 쪽을 구현하는지 표시해요.

```factor
INSTANCE: my-stream input-stream    ! readable
INSTANCE: my-stream output-stream   ! writable
```

스트림은 둘 중 하나일 수도, 둘 다일 수도 있어요. 그러면 `input-stream`(또는 `output-stream`)의 제네릭 메서드가 믹스인에 참여한 모든 클래스로 디스패치돼요. 주변의 `read1`, `stream-contents`, `with-input-stream` 같은 것들이 여러분의 클래스로 찾아가는 방식이 바로 이거예요.

믹스인은 *열려* 있어요. 믹스인을 선언한 뒤에도, 심지어 다른 보캐뷸러리에서도 새 멤버를 추가할 수 있어요. 자식 클래스를 선언할 때 관계가 고정되는 `TUPLE: < parent`와는 대조적이죠.

## 프로토콜 제네릭

프로토콜 제네릭은 `io`에 있어요.

```
stream-read1         ( stream -- elt/f )
stream-read          ( n stream -- seq/f )
stream-read-unsafe   ( n buf stream -- count )
stream-write1        ( elt stream -- )
stream-write         ( seq stream -- )
stream-flush         ( stream -- )
stream-element-type  ( stream -- type )
```

`stream-read1`은 다음 바이트를 반환해요(스트림 끝에서는 `f`). `stream-write1`은 바이트 하나를 써요. `stream-read-unsafe`는 대부분의 입력 스트림이 제공하는 더 저수준의 일괄 읽기이고, `stream-read`는 그 위에 만들어져 메모리 할당을 처리해요. `stream-element-type`은 스트림이 바이트(`+byte+`)를 다루는지 문자(`+character+`)를 다루는지 알려줘요. 다른 스트림을 감쌀 때는, 가장 간단한 구현은 그냥 기반 스트림에 위임하는 거예요.

## 정리는 `destructors`가 담당해요

스트림은 정리 가능한 자원이에요. 직접 만든 스트림은 `disposable`을 상속하고 `dispose*`를 구현해요. `boatswains-bilge`에서 배운 프레임워크를 스트림 클래스에 적용한 것이죠.

```factor
TUPLE: my-stream < disposable underlying ;

: <my-stream> ( underlying -- s )
    my-stream new-disposable swap >>underlying ;

M: my-stream dispose* underlying>> dispose ;
```

이걸 갖추고 나면, `channel-chatter`에서 본 모든 `with-…` 컴비네이터가 여러분의 스트림에서 자동으로 작동해요.
