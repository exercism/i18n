## 스크립트 사용법

테스트를 생성하려면 [problem-specifications][problem-specifications] 저장소를 로컬에 복사해 두어야 해요.
스크립트는 연습 문제에 올바르게 접근할 수 있도록 `python` 루트 디렉터리에서 실행해야 해요.

사용법을 보려면 `bin/generate_tests.py --help`를 실행해요.


## 테스트 템플릿

테스트 템플릿은 [Jinja2] 문법을 지원하며, 표준 데이터에서 다음과 같은 컨텍스트 변수를 사용할 수 있어요:
- `exercise`: 하이픈으로 연결된 연습 문제 이름이에요 (예: `two-fer`)
- `version`: 표준 데이터 버전이에요 (예: `1.2.0`)
- `cases`: 케이스 객체의 배열이거나 `cases` 배열의 배열이에요. 작업 중인 연습 문제의 정확한
구조는 `canonical-data.json`을 참고해요.
- `has_error_case`: 오류가 발생하기를 기대하는 테스트 케이스가 있는지 나타내요 (예: `False`)
- `additional_cases`: `cases`와 비슷한 구조지만, 해당 파일이 있으면 연습 문제의 `.meta/additional_tests.json` 파일에서 채워져요 (예시는 `exercises/word-count/.meta/additional_tests.json`을 참고해요)

또한 편의를 위해 다음과 같은 템플릿 필터가 추가되어 있어요:
- `to_snake`: 문자열을 snake_case로 변환해요 (예: `{{ "CamelCaseString" | to_snake }}` -> `camel_case_string`)
- `camel_case`: 문자열을 CamelCase로 변환해요 (예: `{{ "snake_case_string" | camel_case }}` -> `SnakeCaseString` )
- `error_case`: 테스트 케이스가 오류 발생을 기대하는지 확인해요 (예: `{% for case in cases%}{% if case is error_case}`)
- `regex_replace`: 정규식 문자열 치환이에요 (예: `{{ "abc123" | regex_replace("\\d", "D") }}` -> `abcDDD`)


### 규칙

- 자주 반복되는 템플릿 구조를 위한 범용 매크로는 `config/generator_macros.j2`에 정의되어 있어요.
  - 다음과 같이 임포트할 수 있어요:
  `{%- import "generator_macros.j2" as macros with context -%}`
- 모든 테스트 템플릿은 `{{ macros.footer() }}`로 끝나야 해요.
- 모든 Python 클래스 이름은 CamelCase로 작성해요 (예: `TwoFer`).
  - `{{ "two-fer" | camel_case }}`로 변환해요.
- 모든 Python 모듈과 함수 이름은 snake_case로 작성해요
(예: `high_scores`, `personal_best`).
  - `{{ "personalBest" | to_snake }}`로 변환해요.
- 트랙 전용 테스트는 옵션 파일 `.meta/additional_tests.json`에 정의해요. 이 파일에 정의하는 JSON 객체는
`cases` 키 하나만 가져야 하며, 이 키는 `canonical-data.json`의 `cases`와 같은 구조예요.
- 트랙 전용 테스트는 테스트 파일에서 표준 테스트 뒤에 배치해요.
- 트랙 전용 테스트는 테스트 파일에 다음 주석으로 표시해요:
```
# Additional tests for this track
```


### 레이아웃

대부분의 템플릿은 다음과 비슷한 모습이에요:

```Jinja2
{%- import "generator_macros.j2" as macros with context -%}
{{ macros.header() }}

class {{ exercise | camel_case }}Test(unittest.TestCase):
    {% for case in cases -%}
    def test_{{ case["description"] | to_snake }}(self):
        value = {{ case["input"]["value"] }}
        expected = {{ case["expected"] }}
        self.assertEqual({{ case["property"] }}(value), expected)

    {% endfor %}

{{ macros.footer() }}
```


### 임포트 재정의

`macros.header()`에서 임포트하는 이름은 임포트할 대체 이름 목록을 추가해서 재정의할 수 있어요
(예: `clock`):

```Jinja2
{{ macros.header(["Clock"])}}
```


### 속성 무시

드물게 이 트랙에서 테스트하지 않는 속성을 걸러내야 할 때가 있어요. `header` 매크로는
`ignore` 인자도 받아요 (예: `high-scores`):

```Jinja2
{{ macros.header(ignore=["scores"]) }}
```

## 템플릿 만들기

1. 구현하려는 연습 문제의 `.meta/template.j2`를 만들고 편집기에서 열어요.
2. 템플릿 파일에 [예시 레이아웃](#Layout)을 복사해서 붙여 넣고 저장해요.
3. 연습 문제의 `canonical-data.json`에서 입력 이름과 케이스 구조를 참고하면서,
  유효한 테스트 코드가 나올 때까지 템플릿 파일을 알맞게 수정해요.
    - 표준화된 부분을 다시 작성하지 않도록 [사용 가능한 매크로](../config/generator_macros.j2)를 활용해요.
    - 기존 연습 문제의 템플릿을 구현하는 경우,
    기존 테스트 파일의 구조와 정확히 일치시킬 필요는 없지만, 차이를 최소화하면 관련된 모든 사람이 PR 리뷰를 훨씬 수월하게 진행할 수 있어요.
