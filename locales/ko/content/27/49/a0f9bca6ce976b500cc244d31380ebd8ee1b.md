# 지침

이 연습 문제에서는 로그 라인을 처리해요.

각 로그 라인은 다음과 같은 형식의 문자열이에요: `"[<LVL>]: <MESSAGE>"`.

로그 레벨에는 다음과 같은 것들이 있어요:

- `TRC` (추적)
- `DBG` (디버그)
- `INF` (정보)
- `WRN` (경고)
- `ERR` (오류)
- `FTL` (치명적)

세 가지 과제가 있어요.

## 1. 로그 레벨 파싱하기

위의 로그 레벨에 해당하는 여섯 개의 원소를 가진 `LogLevel` 열거형을 정의해요.

- `Trace`
- `Debug`
- `Info`
- `Warning`
- `Error`
- `Fatal`

다음으로, 로그 라인의 로그 레벨을 파싱하는 (_static_) `LogLine.ParseLogLevel()` 메서드를 구현해요:

```csharp
LogLine.ParseLogLevel("[INF]: File deleted")
// => LogLevel.Info
```

## 2. 알 수 없는 로그 레벨 지원하기

안타깝게도, 때때로 일부 로그 라인에는 알 수 없는 로그 레벨이 있어요. 이런 로그 라인을 매끄럽게 처리하려면, `LogLevel` 열거형에 `Unknown` 원소를 추가해서 알 수 없는 로그 레벨을 파싱할 때 반환되게 해요:

```csharp
LogLine.ParseLogLevel("[XYZ]: Overly specific, out of context message")
// => LogLevel.Unknown
```

## 3. 로그 라인을 짧은 형식으로 변환하기

로그 라인의 로그 레벨은 꽤 길어요. 로그 라인을 저장하는 데 필요한 디스크 공간을 줄이기 위해 짧은 형식이 만들어졌어요: `"[<ENCODED_LEVEL>]:<MESSAGE>"`.

인코딩된 로그 레벨은 로그 레벨을 숫자로 단순하게 매핑한 것이에요:

- `Unknown` - `0`
- `Trace` - `1`
- `Debug` - `2`
- `Info` - `4`
- `Warning` - `5`
- `Error` - `6`
- `Fatal` - `42`

짧아진 로그 라인 형식을 출력할 수 있는 (_static_) `LogLine.OutputForShortLog()` 메서드를 구현해요:

```csharp
LogLine.OutputForShortLog(LogLevel.Error, "Stack overflow")
// => "6:Stack overflow"
```
