# 테스트 생성기

C# 트랙은 [테스트 생성기](https://exercism.org/docs/building/tooling/test-generators)를 사용해 실습 문제의 테스트를 자동으로 생성해요.
[problem-specifications 저장소](https://github.com/exercism/problem-specifications/)에 정의된 대부분의 연습 문제에는 표준화된 테스트 입력과 출력을 담은 `canonical-data.json` 파일도 함께 있다는 점을 활용해요. 이 입출력은 연습 문제를 구현하는 데 사용할 수 있어요.

## 단계

실습 문제의 테스트를 생성할 때 테스트 생성기는 다음 순서로 동작해요:

1. 연습 문제의 `canonical-data.json` 파일에서 테스트 케이스를 읽어요
2. `tests.toml` 파일을 사용해 제외할 테스트 케이스를 생략해요
3. 연습 문제의 생성기 템플릿을 사용해 테스트 케이스를 렌더링해요
4. Roslyn을 사용해 렌더링된 템플릿의 서식을 지정해요
5. 서식이 지정된 템플릿을 연습 문제의 테스트 파일에 써요

### 1단계: `canonical-data.json` 파일 읽기

테스트 생성기는 [System.Text.Json 네임스페이스](https://learn.microsoft.com/en-us/dotnet/api/system.text.json)를 사용해 연습 문제의 `canonical-data.json`에서 테스트 케이스를 파싱해요.

일부 canonical 데이터는 중첩 구조를 사용하기 때문에, 파싱된 테스트 케이스에는 상위 원소들의 `description` 속성과 테스트 케이스 자신의 `description` 속성을 담은 `path` 필드가 추가로 포함돼요.

### 2단계: `tests.toml` 파일에서 제외된 테스트 생략하기

각 연습 문제에는 `tests.toml` 파일이 있고, 이 파일에서 개별 테스트를 제외하거나 비활성화할 수 있어요.
테스트 생성기는 제외된 것으로 표시된 테스트 케이스(`include = false`)를 모두 제거해요.

### 3단계: 테스트 케이스 렌더링하기

그다음 (경우에 따라 변형된) 테스트 케이스가 `.meta/Generator.tpl` 파일로 전달돼요. 이 파일은 해당 테스트 케이스를 바탕으로 테스트를 어떻게 렌더링할지 정의해요.

### 4단계: Roslyn으로 렌더링된 템플릿 서식 지정하기

그다음 렌더링된 템플릿은 [Roslyn](https://github.com/dotnet/roslyn)으로 서식을 지정해요.
이렇게 하면 다음과 같은 장점이 있어요:

- 연습 문제의 서식이 일관되게 유지돼요
- 템플릿을 작성할 때 공백과 정렬에 크게 신경 쓰지 않아도 돼요

### 5단계: 렌더링된 템플릿을 연습 문제의 테스트 파일에 쓰기

마지막으로 렌더링된 템플릿의 출력을 연습 문제의 테스트 파일에 써요.

## 템플릿

템플릿은 [Scriban 라이브러리](https://github.com/scriban/scriban/)를 사용해 렌더링해요.

## 명령줄 인터페이스

테스트 생성기는 두 가지 방법으로 실행할 수 있어요:

1. `bin/update-tests.ps1`: 생성기 템플릿이 있는 모든 연습 문제의 테스트를 갱신해요
2. `bin/update-tests.ps1 -e <slug>`: 생성기 템플릿이 있는 경우, 지정한 연습 문제의 테스트를 갱신해요
