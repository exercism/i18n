# 추가 지침

## 예외 직접 정의하고 발생시키기

코드에서 예외를 [직접 정의](https://docs.python.org/3/tutorial/errors.html#user-defined-exceptions)하고 [`raise`](https://docs.python.org/3/tutorial/errors.html#raising-exceptions)해야 할 때가 있어요. 이럴 때는 오류의 원인이 무엇인지 알려 주는 **의미 있는 오류 메시지**를 항상 포함해야 해요. 그래야 코드를 더 읽기 쉽고, 디버깅할 때도 훨씬 도움이 돼요.

사용자 정의 예외는 새로운 예외 클래스를 만들어서 만들 수 있는데, 이런 클래스는 보통 [`Exception`](https://docs.python.org/3/library/exceptions.html#Exception)의 하위 클래스예요(자세한 내용은 [`classes`](https://docs.python.org/3/tutorial/classes.html#tut-classes)를 참고해요).

오류의 원인이 특정 예외 유형에서 파생된 것임을 알고 있는 경우에는, _Exception_ 클래스 아래에 있는 [`built in error types`](https://docs.python.org/3/library/exceptions.html#base-classes) 중 하나를 상속받도록 선택할 수 있어요. 오류를 발생시킬 때도 의미 있는 메시지는 여전히 포함해야 해요.

이 연습 문제에서는 _사용자 정의 예외_ 두 개를 만들어야 해요. 하나는 원형 버퍼가 **가득 찼을** 때 [발생시키거나](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement) "던지는" 예외이고, 다른 하나는 **비어 있을** 때를 위한 예외예요. 적절한 예외를 직접 정의하고, 그 예외를 `raise`하고, 적절한 오류 메시지를 포함해야만 테스트를 통과할 수 있어요.

`built-in exception`을 직접 정의하려면, 그 예외를 상속받는 `class`를 만들어요. 사용자 정의 예외를 메시지와 함께 발생시킬 때는, 메시지를 `exception` 타입의 인자로 적어요:

```python
# subclassing the built-in BufferError to create BufferFullException
class BufferFullException(BufferError):
    """Exception raised when CircularBuffer is full.

    message: explanation of the error.

    """
    def __init__(self, message):
        self.message = message

        
# raising a BufferFullException
raise BufferFullException("Circular buffer is full")
```
