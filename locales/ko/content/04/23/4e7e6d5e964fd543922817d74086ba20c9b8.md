# 가변성

가변성은 Rust에서 특정 바인딩이 가지는 속성이에요. 바인딩은 불변이거나 가변이에요. 불변 바인딩의 값은 바꿀 수 없고, 가변 바인딩의 값은 바꿀 수 있어요. 모든 바인딩은 기본적으로 불변이에요.

## 바인딩

바인딩은 소스 코드에 나타나는 특정 변수 이름과 실행 중에 존재하는 특정 메모리 영역 사이의 연결이에요. 엄밀히 말하면 바인딩은 컴파일 중에만 존재해요. 컴파일 전에는 실제로 할당된 메모리가 없고, 컴파일 후에는 기계어가 이름이 붙은 변수 대신 메모리 주소만 다뤄요.

바인딩은 보통 `let` 키워드로 만들어요. 그 밖에도 함수 매개변수에서, 그리고 몇 가지 특정한 상황에서 바인딩이 만들어져요.

바인딩은 여러 속성을 가질 수 있는데, 그중 가장 중요한 것이 가변성이에요. 가변 바인딩은 바인딩된 메모리의 값을 바꾸는 것이 허용되는 바인딩이에요. Rust는 각 바인딩의 가변성을 엄격하게 추적하고 강제해서 프로그램이 올바르도록 도와요. 불변이어야 할 바인딩을 잘못 수정하려는 프로그램은 거부하는 식이에요.

## 가변성

실제로 가변성은 대개 단순해요. 바인딩을 정의할 때 `mut` 키워드를 쓰면 값을 바꿀 수 있는 능력이 생겨요.

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### 가변에서 불변으로 낮추기

바인딩은 언제든 가변에서 불변으로 낮출 수 있어요. 이 변환은 투명하게 일어나요.

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### 불변에서 가변으로 올리기

일반적으로 소유권이 이전되는 시점이라면 언제든 값을 불변에서 가변으로 올릴 수 있어요.

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

`(1)`에서 문자열의 소유권이 `x`에서 `y`로 이전되는데, 덕분에 값을 가변으로 올릴 수 있어요.

### 함수 매개변수의 가변성

함수 매개변수를 가변으로 만드는 방법에는 두 가지가 있어요. 첫 번째이자 더 흔한 방법은 C의 참조 전달과 비슷해요.

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

이 예제에서는 세 곳에 가변성을 명시적으로 표시했어요. 가변 참조가 동작하려면 이 세 가지 가변성 선언이 모두 필요해요.
`(2)`에서는 바인딩 `x`를 가변으로 선언해요. 이 바인딩이 값의 최상위 소유자예요.
`(3)`에서는 그 값을 가변으로 빌려서 `increment` 함수에 넘겨요.
`(1)`에서는 해당 참조를 가리키는 새 가변 바인딩 `n`을 만들어요.

매개변수 가변성을 다루는 또 다른 방식도 있는데, 덜 흔하지만 여전히 가끔 유용해요. 이 방식에서는 값은 소유하지만 바인딩은 가변이에요.

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

이 예제는 명시적인 표시가 더 적어요. 실제로는 가변성 승격이 내장된 소유권 이전이기 때문이에요. `i32`는 데이터를 투명하게 복사하는 `Copy` 타입이라서 가능한 거예요.
`(1)`에서는 `increment_internally`가 `n`이라는 가변 소유 `i32`를 매개변수로 받는다고 선언해요.
`(2)`에서는 `x`를 값 `1`에 대한 불변 바인딩으로 선언해요.
`(3)`에서는 `x`가 메모리의 새 위치로 복사돼요. `x`는 그대로 불변이고, `n`은 가변이에요.

물론 두 방식을 조합해서 가변 참조에 대한 가변 바인딩(`mut n: &mut i32` 등)을 만들 수도 있지만, 실제로 바라는 경우는 드물어요.

### `let` 없이 가변성 사용하기

Rust의 여러 구문(`if let`, `match` 등)도 바인딩을 만들 수 있어요. 이런 바인딩도 가변으로 만들 수 있어요.

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

이 예제는 먼저 `v = Some(2)`를, 그다음 `v = None`을 출력해요.

## 섀도잉

여러 번 `let`으로 다시 선언해서, 값이 변환되는 과정에서 같은 변수 이름을 재사용하는 것이 가능하고 흔히 자연스러운 방식이기도 해요. 이를 섀도잉이라고 해요.

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

하지만 이건 가변성의 경우가 아니에요. 원래 값은 원칙적으로 여전히 남아 있어요. `Drop`이 아닌 타입이라면 컴파일러가 새 메모리를 할당하는 대신 메모리 위치를 변경하기로 선택할 수도 있어요. 그러나 `Drop` 타입이거나 예전 바인딩이 다시 사용되면 절대 그러지 않아요.

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
