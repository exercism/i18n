# 개요

연결은 코드에서 식별자에 어디에서 접근할 수 있는지를 설명해요.
블록 스코프, 함수 스코프, 함수 원형 스코프를 가지는 값에는 연결이 없어요.
따라서 해당 스코프 밖에서는 접근할 수 없어요.
스코프에 대해 더 알고 싶다면 [스코프 개념](../scope/introduction.md#Introduction)을 참고해요.

## 외부 연결

파일 스코프를 가지는 식별자는 기본적으로 외부 연결을 가져요.
외부 연결을 가지는 식별자는 프로그램의 어떤 파일에서도 호출할 수 있어요.

## 내부 연결

파일 스코프를 가지는 식별자는 `static` 지정자를 사용해 내부 연결을 가지도록 만들 수 있어요.
내부 연결을 가지는 식별자는 해당 파일 안에서만 사용할 수 있어요.

예를 들어요.

```c
int public_count = 0; // file scope, external linkage by default
static int private_count = 0;  // file scope, internal linkage 

// file scope, internal linkage
static void some_function()
{
    // code snipped
}

// file scope, external linkage by default
int main()
{
    // code snipped
}
```

정적 연결을 정적 저장 기간과 혼동하면 안 돼요.
정적 저장 기간에 대해 더 알고 싶다면 [저장 기간 개념](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#static-the-storage-specifier-not-to-be-confused-with-the-static-linkage-type)을 참고해요.

함수가 아니라 값이 헤더에서 선언되었지만, 소스 파일에서는 초기화된 값을 가지는 `static` 파일 스코프 식별자로 정의된 경우, 그 초기화된 값은 소스 파일 밖에서 접근할 수 없어요.
오류 없이 컴파일되고 링크되고 실행될 수는 있지만, 값이 `extern`으로 선언되어 있더라도 그 값은 해당 식별자의 0 값이 돼요.
(`extern`에 대해 더 알고 싶다면 [extern 개념](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#extern-how-to-access-a-variable-in-another-translation-unit)을 참고해요.)
소스 파일에서 `static`으로 표시된 파일 스코프 식별자는 헤더 파일에 선언하면 안 돼요.
