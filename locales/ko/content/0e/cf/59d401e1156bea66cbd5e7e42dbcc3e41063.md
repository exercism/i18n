# 소개

`String`의 개별 문자는 배열에서 쓰는 서브스크립트 방식으로 접근할 수 있어요.
하지만 문자열에 사용하는 [인덱스][string-indices]는 _정수가 아니고_, 직접 다룰 수도 없어요.
대신 `startIndex`처럼 이미 알고 있는 다른 인덱스를 기준으로 계산해야 해요. `startIndex`는 비어 있지 않은 문자열에서 첫 번째 문자의 위치를 가리키고, [`String`][string-docs]과 [`NSString`][nsstring-docs] 라이브러리에서 제공하는 메서드를 사용해요 (`Foundation` 모듈을 가져오면 Swift의 문자열은 NSString의 모든 프로퍼티와 메서드를 사용할 수 있어요).

예를 들어, 다음과 같은 문자열이 있다고 해봐요:

```swift
let csv = "apple,pear,peach,orange,cherry,lime,goosberry"
```

"orange"의 "g"를 얻으려고 `csv[21]`이라고 쓸 수는 없어요. 대신 `String.Index` 타입의 값을 계산해서 그 인덱스를 넘겨야 해요.
이 인덱스는 그 자체로 사람이 읽고 다루도록 만든 값이 아니라는 점에 주목해요.
사람이 그 안에 무엇이 들어 있는지 알 필요가 없기 때문에, 이런 인덱스를 _불투명 인덱스_라고 불러요.

```swift
let index = csv.index(csv.startIndex, offsetBy: 21)
csv[index]
// "g"
print(index)
// prints Index(_rawBits: 1376513)
```

그런데 오프셋이 유효한 인덱스가 아니면, 즉 `startIndex`보다 앞이나 `endIndex`보다 뒤의 인덱스를 반환한다면 연산에서 오류가 발생해 프로그램이 중단돼요.
이 문제를 막으려면 제한 인덱스를 지정하면 돼요.
그러면 옵셔널 인덱스가 반환되는데, 유효하지 않은 인덱스에 대해서는 nil을 반환해요.

```swift
let tooFar = csv.index(csv.startIndex, offsetBy: 200)
// error: Execution was interrupted, reason: EXC_BAD_INSTRUCTION (code=EXC_I386_INVOP, subcode=0x0).
let tooFarButSafe = csv.index(csv.startIndex, offsetBy: 200, limitedBy: csv.endIndex)
// nil
```

게다가 인덱스는 문자열끼리 공유할 수 없어요.
예를 들어, 위에서 계산한 "orange"의 "g"에 대한 `index`로 문자열 `fam = "This is my family: 👨‍👩‍👦‍👦, this is our dog: 🐶, this is our cat: 🐱!"`을 인덱싱하는, 즉 `fam[index]`는 프로그램을 중단시켜요.

이런 데에는 여러 이유가 있지만, 결국 핵심은 "유니코드는 까다롭다"는 거예요.

일반적으로 개별 문자에 임의 접근이 필요하다면, `Array<Character>` 같은 다른 자료 구조를 쓰는 게 좋아요.

## 유용한 메서드 몇 가지

Swift에는 문자열의 첫 번째와 마지막 문자를 가져오는 `first`와 `last` 메서드가 있어요.
두 메서드는 옵셔널 문자를 반환하므로, 문자열이 비어 있으면 nil을 반환해요.

```swift
let str = "Hello, world!"
print(str.first) // Prints Optional("H")
print(str.last)  // Prints Optional("!")
```

`prefix`와 `suffix` 메서드로 문자열의 일부를 가져올 수도 있어요.
두 메서드는 정수를 인자로 받아서, 문자열의 앞이나 뒤에서 n개의 문자를 포함하는 부분 문자열을 반환해요.

```swift
let str = "Hello, world!"
print(str.prefix(5)) // Prints "Hello"
print(str.suffix(6)) // Prints "world!"
```
