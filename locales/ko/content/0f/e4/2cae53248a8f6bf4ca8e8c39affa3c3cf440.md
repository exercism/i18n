# 소개

단순한 타입(문자열과 기본형)은 보통 `==`와 `!=`로 같은지 비교해요.

참조 타입(클래스의 인스턴스)은 `Object`에서 상속받은 `Equals()` 메서드로 비교해요. 같음 비교의 목적이 두 객체가 정확히 같은 인스턴스인지 확인하는 것이라면 `Object`의 구현에 기대는 것으로 충분해요. 그렇지 않다면 `object.Equals()`를 재정의해야 해요.

클래스의 모든 인스턴스가 한 곳에서 만들어진다고 확신할 수 있다면, 예를 들어 어떤 게임이나 시뮬레이션의 캐릭터라면, 참조 동등성만으로 충분해요. 하지만 같은 실세계 객체가 여러 인스턴스로 만들어지는 경우가 많아요(데이터베이스에서, 사용자 입력으로, 웹 요청을 통해). 이 경우에는 그 객체를 유일하게 식별하는 값들을 같은지 비교해야 해요. 따라서 `Equals()`를 재정의하고 클래스의 적절한 데이터 멤버들을 비교해야 해요.

재정의한 `Equals()` 메서드에는 단순한 타입의 멤버는 `==`로, 참조 타입의 멤버는 `Equals()`를 재귀 호출해서 비교하는 코드가 들어가요.

`Object` 클래스는 두 객체가 같은 하나의 인스턴스인지 확인하기 위해 비교하는 적절한 메서드를 제공해요.

## `Object.GetHashCode()`

`Object.GetHashCode()` 메서드는 32비트 정수 형태의 해시 코드를 반환해요. 해시 코드는 `Dictionary<T>`나 `HashSet<T>` 같은 _딕셔너리_와 _집합_ 클래스가 객체를 효율적으로 저장하고 꺼내는 데 사용해요.

해시 코드와 같음의 관계는, 두 객체가 같다면(`Equal()`이 true를 반환한다면) 두 객체의 `GetHashCode()`가 같은 값을 반환해야 한다는 거예요. 반대 방향은 성립하지 않아요. 대칭적이지 않거든요. 두 객체의 해시 코드가 같다고 해서 반드시 같아야 하는 건 아니에요. 먼저 해시 코드를 기준으로 "버킷"으로 간 다음, 같음 비교로 특정 항목을 골라내는 조회 함수를 떠올려 봐요.

HashCode 라이브러리 API 문서에서는 해시 코드를 생성하는 가장 좋은 방법을 다뤄요

같음 비교에 사용하는 값은 해시 컬렉션을 사용하는 동안 안정적이어야 해요. 어떤 값으로 객체를 컬렉션에 추가한 뒤 그 값을 바꾸면 해시 코드가 더 이상 올바른 "버킷"을 가리키지 않아요. 실제로 이 말은 객체가 불변이어야 한다는 뜻이에요. 다른 접근 방식은 유지보수하는 사람에게 골칫거리를 만들 위험이 있어요.
