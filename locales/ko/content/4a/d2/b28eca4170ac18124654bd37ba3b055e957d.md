# 소개

## 같음

단순 형식(문자열과 기본 형식)은 보통 `==`와 `!=`로 같은지 비교해요.

참조 형식(클래스의 인스턴스)은 `Object`에서 상속받은 `Equals()` 메서드로 비교해요. 같음 검사의 목표가 두 객체가 정확히 같은 인스턴스인지 확인하는 것이라면 `Object`의 구현을 그대로 믿어도 돼요. 그렇지 않다면 `object.Equals()`를 재정의해야 해요.

클래스의 모든 인스턴스가 한 곳에서 만들어진다고 알고 있다면, 예를 들어 어떤 게임이나 시뮬레이션의 캐릭터라면, 참조 같음만으로 충분해요. 하지만 같은 실세계 대상에 대해 여러 인스턴스가 만들어지는 경우가 많아요(데이터베이스에서, 사용자 입력으로, 웹 요청을 통해). 이때는 대상을 고유하게 식별하는 값을 같은지 검사해야 해요. 따라서 `Equals()`를 재정의하고 클래스의 적절한 데이터 멤버를 같은지 검사해야 해요.

재정의한 `Equals()` 메서드는 단순 형식 멤버에 대해서는 `==`를 사용한 같음 검사를, 참조 형식 멤버에 대해서는 `Equals()`를 재귀 호출한 같음 검사를 담게 돼요.

`Object` 클래스는 두 객체가 같은 하나의 인스턴스인지 판별할 수 있도록 적절한 메서드를 제공해요.

### `Object.GetHashCode()`

`Object.GetHashCode()` 메서드는 32비트 정수 형태의 해시 코드를 반환해요. 해시 코드는 `Dictionary<T>`와 `HashSet<T>` 같은 _딕셔너리_와 _집합_ 클래스가 객체를 성능 좋게 저장하고 가져오는 데 사용돼요.

해시 코드와 같음의 관계는 이래요. 두 객체가 같다면(`Equal()`이 true를 반환한다면) 두 객체의 `GetHashCode()`는 반드시 같은 값을 반환해야 해요. 하지만 반대 방향으로는 적용되지 않아요. 대칭적이지 않죠. 두 객체의 해시 코드가 같다고 해서 두 객체가 반드시 같아야 하는 건 아니에요. 해시 코드를 기준으로 먼저 "버킷"으로 가서, 같음 검사로 특정 항목을 골라내는 조회 함수를 떠올려 봐요.

HashCode 라이브러리의 API 문서에서는 해시 코드를 생성하는 가장 좋은 방법을 다뤄요

같음 검사에 사용하는 값은 해시 컬렉션을 사용하는 동안 변하지 않아야 해요. 어떤 객체를 한 값 집합과 함께 컬렉션에 추가한 뒤 그 값을 바꾸면 해시 코드가 더 이상 올바른 "버킷"을 가리키지 않아요. 실제로는 객체가 불변이어야 한다는 뜻이에요. 다른 방식은 유지보수하는 사람에게 예상치 못한 함정을 만들 위험이 있어요.

## 집합

집합은 고유한 값들의 모음이에요. .NET에서 기본으로 제공하는 집합 구현은 `HashSet<T>` 클래스이고, 이는 고유한 값만 담는 컬렉션이에요.
