# 소개

Julia는 대부분의 프로그래밍 언어처럼 다양한 종류의 컬렉션을 제공해요.

일부는 본질적으로 순서가 있어요 (`Vectors`와 더 높은 차원의 `Arrays` 등). 그래서 위치로 원소에 접근할 수 있어요.
다른 컬렉션은 순서가 없고 (`Sets`, `Dicts`), 원소에 키나 값으로 접근해야 해요.

가장 단순한 경우로, `Ints`의 `Vector`가 있고 이를 오름차순으로 정렬하고 싶다고 해봐요.

```julia-repl
julia> v = [3, 2, 4, 1]
4-element Vector{Int64}:
 3
 2
 4
 1

julia> sort(v)
4-element Vector{Int64}:
 1
 2
 3
 4

# sort descending
julia> sort(v, rev=true)
4-element Vector{Int64}:
 4
 3
 2
 1
```

간단하죠!
`sort()` 함수는 이름만 봐도 알 수 있듯이, 겉보기에는 정렬된 `Vector`를 반환하는 것처럼 보여요.

_농담이에요!_
커리큘럼상 이 단계쯤이면, 우리가 논의해야 할 미묘한 점이 있다고 (제대로) 짐작하고 있을지도 몰라요.

## 변경 함수와 비변경 함수

`sort(v)`를 실행한 뒤, `v`는 어떻게 됐을까요?

```julia-repl
julia> v
4-element Vector{Int64}:
 3
 2
 4
 1

julia> issorted(v)
false
```

원래 벡터는 그대로예요.
`sort()`는 ***비변경*** 함수로, 입력의 _복사본_을 반환해요.

이것은 많은 상황에서 좋은 설계예요. 순수 함수라서, 병렬 분산 code에서도 동작을 추론하기 쉬워요.

반면에, 10억 개의 문자열로 이루어진 배열을 정렬한다고 해봐요.

정렬은 아마 느릴 거예요.
게다가 모든 것을 복사해야 하고 (_느려요!_), 복사본을 저장할 메모리 (_수 기가바이트!_)도 충분히 확보해야 해요.

아주 비슷한 다음 code와 비교해봐요:

```julia-repl
# v is as previously

julia> issorted(v)
false

julia> sort!(v)
4-element Vector{Int64}:
 1
 2
 3
 4

julia> v
4-element Vector{Int64}:
 1
 2
 3
 4

julia> issorted(v)
true
```

이제 입력 `Vector`는 복사 없이 제자리에서 정렬되고, 원래 순서는 영구히 사라져요.

이 방식은 효율적일 수도 있고, bug가 생기거나 예상치 못한 부작용을 일으킬 수도 있으며, code를 사용하는 다른 사람을 혼란스럽게 할 수도 있어요.
_신중하게 선택해요!_

`sort!()`는 "변경 함수"이고, (_아주 강한_) 관례에 따라 입력을 변경하는 함수는 프로그래머에게 경고하는 의미로 이름 끝에 `!`를 붙여요.

## 정렬 인덱스 배열

정렬하려는 원소가 큰 객체라면, 각 원소의 위치 인덱스로 작업하는 편이 더 쉬울 수 있어요.

```julia-repl
julia> langs = ["Julia", "C++", "Python", "Elixir"]
4-element Vector{String}:
 "Julia"
 "C++"
 "Python"
 "Elixir"

julia> inxs = sortperm(langs)  # => Integers
4-element Vector{Int64}:
 2
 4
 1
 3

julia> langs[inxs]  # sort the entire vector
4-element Vector{String}:
 "C++"
 "Elixir"
 "Julia"
 "Python"

julia> langs[inxs[1:2]]  # slice the indices
2-element Vector{String}:
 "C++"
 "Elixir"
```

`langs`가 Vector라서, 각 인덱스는 `1:length(langs)` 범위의 정수예요.
`sortperm()`의 출력은 이 정수들의 순열이고, 이는 입력 벡터를 정렬한 결과에 대응해요.
