# here document 소개

Bash 스크립트에서 "here document"(또는 "heredoc")라는 기능은 여러 줄의 입력을 마치 터미널에 직접 입력하듯이 명령이나 프로그램으로 리디렉션해요.
외부 파일이나 복잡한 문자열 조작 없이 스크립트 안에 여러 줄의 텍스트를 넣을 수 있게 해 주는 강력한 도구예요.

## 주요 특징과 문법

1. 구분자: heredoc은 `<<` 연산자로 시작하고, 그 뒤에 구분자 단어가 와요(흔히 "마커"나 "종료자"라고 불러요).
   이 구분자는 원하는 아무 단어나 쓸 수 있지만, 보통은 알아보기 쉽도록 `EOF`, `END`, `TEXT` 같은 걸 많이 써요.
   코드를 더 읽기 쉽게 하려면 `END_INSTALLATION_INSTRUCTIONS`처럼 의미가 드러나는 단어를 구분자로 쓸 수도 있어요.

1. 내용: 맨 앞의 `<< DELIMITER` 뒤에 리디렉션하려는 내용을 적어요.
   여러 줄의 텍스트일 수도, 코드일 수도, 그 밖의 무엇이든 될 수 있어요.

1. 종료: 구분자 단어가 앞뒤에 공백 없이 한 줄에 단독으로 다시 나타나면 heredoc이 끝나요.

## 기본 문법

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## 동작 방식

* Bash는 시작하는 `<< DELIMITER`와 끝나는 `DELIMITER` 사이의 모든 줄을 읽어요.
* Bash는 이 내용을 명령의 표준 입력에 연결해요.
* 명령은 이 입력을 마치 키보드에서 온 것처럼 처리해요.

### 예제 1: 간단한 텍스트 출력

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

출력:

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

이 예제에서는:

* `cat`이 명령이에요.
* `<< EOF`가 `EOF`를 구분자로 해서 heredoc을 시작해요.
* 세 줄의 텍스트가 내용이에요.
* `EOF`가 단독으로 있는 줄에서 heredoc이 끝나요.
* 그러면 `cat`이 받은 내용을 출력해요.

### 예제 2: wc(단어 수 세기)와 함께 사용하기

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

출력:

```plaintext
3
```

여기서 `wc -l`은 줄 수를 세요.
heredoc이 세 줄을 입력으로 제공해요.

### 예제 3: 스크립트에 데이터 전달하기

스크립트:

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

대화형 bash 프롬프트에서 heredoc을 사용해 스크립트를 호출해 봐요:

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

출력:

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## 변형과 고급 기능

### 리터럴 내용

Bash는 heredoc 안에서 변수 확장, 명령 치환, 산술 확장을 수행해요.
그런 의미에서 heredoc은 큰따옴표 문자열처럼 동작해요.

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

출력:

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

구분자에 따옴표를 붙이면(작은따옴표나 큰따옴표를 사용하면) 이런 확장이 일어나지 않아요.
내용은 그대로 취급돼요.
작은따옴표 문자열과 비슷해요.

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

출력:

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### 앞쪽 탭 제거하기

`<<` 대신 `<<-`(뒤에 하이픈이 붙은 형태)를 쓰면, Bash가 heredoc 각 줄의 앞쪽 _탭 문자_를 모두 없애요.
스크립트 안에서 heredoc 내용을 들여쓰기하면서도 출력에는 영향을 주지 않고 싶을 때 유용해요.

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

출력할 때는 앞쪽 탭이 모두 제거된 상태로 인쇄돼요:

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
글쓴이는 이 사용법을 권하지 않아요.
스크립트의 가독성을 높여 주기도 하지만,

1. 탭 문자를 실수로 공백으로 바꾸기 쉬워요(편집기가 자동으로 그렇게 할 수도 있어요). 그리고 
1. 공백과 탭의 차이를 알아보기가 어려워요.
~~~~

## here document는 언제 사용할까요

* 여러 줄 입력: 명령에 여러 줄의 텍스트를 전달해야 할 때.
* 설정 파일: 스크립트 안에 작은 설정 조각을 넣을 때.
* 코드 생성: 스크립트 안에서 즉석으로 코드를 만들 때.
* 스크립트로 상호작용하기: 대화형 프로그램에 사용자 입력을 흉내 낼 때.
* 외부 파일 피하기: 임시 파일을 만들고 싶지 않을 때.

대표적인 예로 도움말 텍스트를 제공하는 경우가 있어요:

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## 단점

* 포함된 문서가 크면 코드를 읽기 어려워질 수 있어요.
  문서는 별도 파일로 두고 스크립트를 배포하는 편이 더 나을 수 있어요.
* here document는 코드의 흐름을 끊을 수 있어요.
  프로그램에 텍스트를 전달하려는 순간이 코드가 깊게 중첩된 부분일 수도 있죠.
  heredoc의 들여쓰기는 주변 코드와 비교해 어색해 보일 수 있어요.

## here string

here string(또는 "herestring")은 here document처럼 명령에 입력을 제공해요.
다만 heredoc은 텍스트 덩어리로 주어지는 반면, herestring은 하나의 문자열로 주어져요.
here string은 `<<< "text"` 문법을 사용해요.

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

출력:

```plaintext
UPPER CASE THIS STRING
```

heredoc과 달리 종료 구분자가 필요 없어요.

### here string을 왜 사용할까요?

here string 대신 파이프라인을 사용할 수도 있어요:

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

그럼 here string은 왜 쓸까요?

오래 걸리는 계산의 출력으로 문자열을 얻었고, 그 결과를 서로 다른 두 명령에 각각 넣고 싶은 경우를 생각해 봐요.
파이프라인을 쓰면 계산을 두 번 실행해야 해요:

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

더 효율적인 방법은 계산의 출력을 (명령 치환으로) 저장해 두고, here string으로 뒤따르는 두 명령에 입력을 제공하는 거예요:

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

실제로 이런 식으로 활용할 수 있어요:

* 페이지 단위로 나뉜 REST API 쿼리의 JSON 응답을 받아 두고,
* 그 JSON 데이터를 jq 프로그램에 넘겨 결과를 파싱해 파일로 출력한 다음,
* 같은 JSON 데이터를 또 다른 jq 프로그램에 넘겨 다음 쿼리의 URL을 알아내요.

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

출력 리디렉션이 놓인 위치에 주목해요.
`while`문에서 나오는 모든 출력이 `data.csv` 파일에 이어서 추가돼요.

## 리디렉션으로 쓰는 heredoc과 herestring

이 둘은 그저 리디렉션의 한 형태일 뿐이라서, 다른 리디렉션 연산과 함께 쓸 수 있어요:

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## 정리

here document(또는 "heredoc")를 사용하면 Bash 스크립트에서 여러 줄 입력을 유연하고 편리하게 다룰 수 있어요.
스크립트 안에 텍스트와 데이터를 직접 넣는 과정을 단순하게 만들어 주어서, 스크립트만으로 완결되게 해 주고 읽기도 더 쉬워져요.

here string(또는 "herestring")은 here document와 비슷하지만, 더 단순하고 유연한 문법을 제공해요.
