# 소개

## 분기 없는 코드

조건문 개념에서는 조건에 따라 분기하는 명령어 계열인 `jcc`를 소개해요.
`jcc`는 조건이 충족될 때만 실행을 프로그램의 다른 지점으로 옮겨요.

그런데 최신 CPU는 빠르고, 여러 명령어를 동시에 실행할 수 있어요.
CPU가 조건을 실행 중에 검사하느라 기다리는 동안 모든 작업을 멈추게 하면 비용이 너무 커요.

그래서 CPU는 내부적으로 기다리지 않아요.
**분기 예측기**로 조건의 결과를 추측하고, 예측한 경로를 _추측 실행_하기 시작해요.

예측이 맞으면 분기가 없었던 것처럼 실행이 이어져요.
하지만 예측이 틀리면 CPU는 예측한 경로에서 _한 작업을 버리고_ 올바른 경로에서 다시 시작해야 해요.

이것을 **분기 예측 실패**라고 하는데, 지연이 생기기 때문에 비용이 커요.

분기를 예측하기 어려우면 이런 예측 실패가 쌓여요.
그럴 때는 분기 자체를 피해서 조건과 상관없이 같은 명령어가 실행되게 하는 편이 더 나을 때도 있어요.
`jcc` 없이 값 사이에서 선택하는 코드를 **분기 없는 코드**라고 해요.

코드가 덜 분기하도록, 또는 실제로 있는 분기가 더 예측하기 쉽도록 코드를 구성하는 방법은 여러 가지예요.
특히 x86-64에는 분기 없는 코드를 작성할 때 흔히 쓰이는 두 가지 명령어 계열이 있어요.

### 조건부 이동

`cmovcc` 명령어 계열은 특정 조건이 충족될 때만 소스 피연산자를 목적지로 복사해요.
그렇지 않으면 목적지는 그대로 둬요.

`cc` 접미사는 `jcc`에서와 같은 이름 규칙을 따르고, 의미도 같아요:

| 명령어 | 이동 조건                            |
|-------------|--------------------------------------|
| `cmove`     | `cmp A, B` 후 A == B              |
| `cmovne`    | `cmp A, B` 후 A != B              |
| `cmovl`     | `cmp A, B` 후 A < B (부호 있음)      |
| `cmovb`     | `cmp A, B` 후 A < B (부호 없음)    |
| `cmovg`     | `cmp A, B` 후 A > B (부호 있음)      |
| `cmova`     | `cmp A, B` 후 A > B (부호 없음)    |

규칙은 `jcc`와 비슷해요:

1. `l`과 `g`는 부호 있는 비교에 쓰이고, `b`와 `a`는 부호 없는 비교에 쓰여요.
2. 접미사에 `e`를 붙이면 같음을 포함해요.
3. `n`을 붙이면 조건을 부정해요.
4. 플래그가 설정된 상태를 가리키는 변형도 있어요.
   예를 들어 `cmovz`와 `cmovc`가 그래요.

`rdi`에 있는 부호 있는 정수의 절댓값을 구해 `rax`에 반환하는 경우를 생각해 봐요.
`jcc`로 작성하면 함수는 두 경로 중 하나를 선택해요:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

`cmovcc`로 작성하면 두 후보 값을 조건 없이 모두 계산하고, 조건부 이동이 그중 하나를 골라요:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

분기 없는 버전은 항상 같은 명령어를 실행해요.
예측기가 추측할 `jcc`가 없어요.

`cmovcc`의 목적지는 레지스터여야 해요.
소스는 레지스터나 메모리 위치일 수 있지만, 즉치는 안 돼요.

~~~~exercism/note
위 코드에서 `neg` 명령어는 결과에 따라 여러 플래그를 설정하는데, 부호 플래그(SF)도 그중 하나예요.
따라서 `cmp rdi, 0`은 아예 없앨 수 있어요:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

`rdi`가 양수이면 `neg`는 음수 결과를 만들고 SF == 1이 되므로, `cmovs`가 `rdi`를 복원해요.
`rdi`가 0이거나 음수이면 `neg`는 음수가 아닌 결과를 만들고 SF == 0이 되므로, `rax`는 부정된 값(올바른 절댓값)을 그대로 유지해요.

어셈블리 코드에서 값을 비교하는 주된 방법은 `cmp`지만, 많은 명령어가 자신의 결과에 따라 플래그를 설정하기도 해요.
어떤 명령어가 영향을 주는 플래그의 전체 목록은 보통 그 명령어의 [참고 자료][reference]에 나와 있어요.
`neg`의 경우에는 SF, ZF, CF, OF, PF예요.

[reference]: https://www.felixcloutier.com/x86/
~~~~

### 조건부 설정

`setcc` 명령어 계열은 특정 조건이 충족되면 목적지 피연산자를 `1`로, 그렇지 않으면 `0`으로 설정해요.
목적지는 항상 _8비트 피연산자_예요.

`cc` 접미사는 `jcc`와 `cmovcc`에서와 같은 이름 규칙을 따라요.
예를 들어 `setz`는 `ZF == 1`이면 목적지를 `1`로, 그렇지 않으면 `0`으로 설정해요.

목적지가 8비트이기 때문에, 더 넓은 값이 필요할 때는 `setcc` 뒤에 `movzx`를 쓰는 것이 일반적이에요:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

비교 결과를 정수 `0` 또는 `1`로 바꾸는 흔한 관용구예요.
