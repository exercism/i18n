# 지침

최근 보안 검토 이후, 조직의 보관된 로그 파일을 정리해 달라는 요청을 받았어요.

## 1. 손상된 로그 줄 식별하기

보관된 로그 줄 중 현재 표준을 따르지 않는 것이 몇 개인지 파악해야 해요.
간단한 검사로 로그 줄이 유효한지 알 수 있다고 생각해요.
유효한 줄로 인정되려면 다음 문자열 중 하나로 시작해야 해요:

- [DEBUG]
- [INFO]
- [WARNING]
- [ERROR]

로그 줄이 유효하면 `true`를 반환하도록 `valid_line?/1` 함수를 구현해요.

```elixir
LogParser.valid_line?("[ERROR] Network Failure")
# => true

LogParser.valid_line?("Network Failure")
# => false
```

## 2. 로그 줄 분리하기

로그 파싱 프로젝트를 시작한 지 얼마 안 되어, 한 애플리케이션의 로그는 다른 것들처럼 줄로 나뉘어 있지 않다는 걸 알게 돼요. 이 프로젝트에서는 별도의 줄이어야 할 것들이 하나의 줄에 들어 있고, `<--->`나 `<*~*~>` 같은 특이한 화살표로 연결되어 있어요.

실제로 첫 문자가 `<`, 마지막 문자가 `>`, 그 사이에 `~`, `*`, `=`, `-` 문자를 어떤 조합으로든 포함하는 문자열이라면 이 프로젝트 로그의 구분자로 쓸 수 있어요.

줄을 받아서 문자열 목록을 반환하는 `split_line/1` 함수를 구현해요.

```elixir
LogParser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
# => ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. 로그에서 잔여물 제거하기

로그를 처리하는 상위 단계 어딘가에서, "end-of-line"이라는 텍스트 뒤에 (공백 없이) 줄 번호가 붙은 문자열이 로그 전반에 흩뿌려져 있다는 걸 발견했어요.

문자열을 받아서 end-of-line 텍스트를 모두 제거하고(대소문자 구분 없이) 깨끗한 로그 줄을 반환하는 `remove_artifacts/1` 함수를 구현해요.

end-of-line 텍스트가 없는 줄은 그대로 반환해야 해요.

end-of-line 문자열만 제거하면 되고, 공백을 조정할 필요는 없어요.

```elixir
LogParser.remove_artifacts("[WARNING] end-of-line23033 Network Failure end-of-line27")
# => "[WARNING]  Network Failure "
```

## 4. 줄에 사용자 이름 태그 달기

일부 로그 줄에 사용자를 언급하는 문장이 포함되어 있다는 걸 알아챘어요.
이런 문장에는 항상 `"User"` 문자열 뒤에 하나 이상의 공백 문자가 오고, 그다음 사용자 이름이 와요.
이런 줄에는 태그를 달기로 해요.

로그 줄을 처리하는 `tag_with_user_name/1` 함수를 구현해요:

- `"User"` 문자열이 없는 줄은 그대로 둬요.
- `"User"` 문자열이 있는 줄은 줄 앞에 `[USER]`와 사용자 이름을 붙여요.

```elixir
LogParser.tag_with_user_name("[INFO] User Alice created a new project")
# => "[USER] Alice [INFO] User Alice created a new project"
```

다음과 같다고 가정해도 돼요:

- `"User"` 문자열이 나올 때마다 하나 이상의 공백 문자와 사용자 이름이 뒤따라요.
- 각 줄에는 `"User"` 문자열이 많아야 한 번 나와요.
- 사용자 이름은 공백을 포함하지 않는 비어 있지 않은 문자열이에요.
