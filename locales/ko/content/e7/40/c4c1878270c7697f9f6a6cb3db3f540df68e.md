# `jq`의 함수

`jq`에서는 필요한 로직을 캡슐화하기 위해 나만의 **사용자 정의 함수**를 정의할 수 있어요.
_함수_는 내장 함수와 똑같이 동작해요. 입력을 받아서 0개, 1개 또는 그 이상의 출력을 내보내요.

## 함수 정의하기

다음 문법으로 `jq` _함수_를 정의할 수 있어요:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- `def` 키워드로 시작해요.
- 함수 본문 앞에 콜론이 와요.
- 본문은 하나의 표현식으로 이루어져요.
- 세미콜론으로 끝나요.
- 나머지 `jq` 문법과 마찬가지로, 가독성을 위해 원하는 만큼 공백을 써도 돼요.

## 함수는 어디에 둘까요

_함수_는 사용하기 전에 정의해야 해요. 다음은 오류예요:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

이 말인즉슨, _함수_를 `jq` 코드의 맨 위, 즉 "메인" 표현식보다 앞에 두어야 한다는 뜻이에요.

### 중첩 함수

_함수_는 중첩할 수 있어요:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

여기서 `B` _함수_는 `A`의 본문 안에서만 보여요.

## 스코프

_함수_는 변수와 중첩 함수를 위한 새로운 **스코프**를 만들어요.

## 인자

_함수_ **인자**는 쉼표가 아니라 _세미콜론_으로 구분해요.
예를 들어, 숫자를 하나 받아서 숫자를 더한 다음 숫자를 곱하는 _함수_는 이렇게 써요:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
세미콜론이 필요한 이유는 쉼표가 `jq`에서 이미 쓰임새가 있기 때문이에요. 바로 스트림을 이어 붙이는 연산자죠.

세미콜론 대신 쉼표를 쓰면 _인자를 1개 받는_ `add_mul` 함수를 두 번 호출하려고 하게 돼요. 그런 함수는 없으니 첫 번째 호출 시도에서 바로 실패하죠:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

`5, 4`에서 쉼표는 숫자 5와 4를 하나의 스트림으로 이어 붙여요.
스트림을 인자로 넘겨 함수를 호출하면, `jq`는 스트림에 있는 값마다 한 번씩 그 함수를 여러 번 호출해요.
이것이 `jq` 스트림에 원래부터 있는 "암시적 반복"의 한 예예요.
`10 | add_mul(5, 4)`는 다음 코드와 같아요.

```jq
(10 | add_mul(5)), (10 | add_mul(4))
```
이제 `add_mul/1 is not defined` 오류가 왜 나타나는지 알 수 있어요.
~~~~

<!-- prettier-ignore-end -->

### 인자는 _표현식_이에요

함수 _인자_는 값이 아니라 필터예요.
그런 점에서 다른 언어들이 콜백이라고 부르는 것과 비슷하게 동작해요:

`add_mul` 함수를 예로 들어 볼게요:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

여기서 무슨 일이 일어나고 있을까요?

- `adder` 인자는 _표현식_ `. + 5`를 받아요.
  - 함수가 `. + adder`를 실행하면, 그건 `. + . + 5`가 돼요.
  - `. == 10`이므로 25로 평가돼요.
- 마찬가지로 `multiplier` 인자는 표현식 `. - 2`예요.
  - 8로 평가돼요.
  - 그러면 결과는 `25 * 8 == 200`이에요.

### 값으로서의 인자

때로는 _인자_를 변수로 "구체화"하고 싶을 때가 있어요:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

이를 위한 축약형이 있어요:

```jq
def my_func($arg):
    other stuff ...
;
```

이건 그저 "문법적 설탕"일 뿐이라는 점을 기억해요. `$`가 없는 `arg`라는 이름도 여전히 _함수_ 안의 스코프에 남아 있어요.

<!-- prettier-ignore -->
~~~~exercism/caution
예를 들어, 저는 연습 문제 하나를 풀려고 이렇게 작성했어요:

```jq
# function that encodes the input value
def code:
    # expression here
    ;

def equals($code):
    (. | code) as $this_code
    | $code == $this_code
    ;

("some key value" | code) as $key
| ["array", "of", "values"]
| map(select(equals($key)))
```

그런데 배열의 모든 값이 그 키와 같다는 사실에 놀랐어요.

이런 일이 일어난 건 jq가 `equals` 함수를 이렇게 본 때문이에요:

```jq
def equals(code):
    code as $code
    | (. | code) as $this_code
    | $code == $this_code
    ;
```

**인자** `code`가 앞서 정의된 **함수** `code`를 _덮어썼어요_.
그래서 `(. | code)`는 입력값을 바탕으로 새 코드를 계산하는 대신 그냥 **인자**를 출력했어요.
따라서 `$this_code`와 `$code`는 항상 같은 값이었어요.
~~~~

<!-- prettier-ignore-end -->

## 인자 개수

_함수_에는 **인자 개수**가 있어요. 함수가 받는 _인자_의 수를 말해요.

_함수_는 같은 이름을 서로 다른 _인자 개수_로 사용할 수 있어요.
내장 [`range`][man-range] 함수가 이를 잘 보여줘요. `range/1`, `range/2`, `range/3`이 모두 함께 존재하죠.

이런 방식은 인자를 통해 상태를 전달하는 재귀 함수를 정의할 때 유용해요.
예를 들어 `map`은 이렇게 구현할 _수도_ 있어요:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## 재귀

`jq`는 꼬리 호출 최적화를 수행하지만, 인자 개수가 0인 함수에만 해당해요.
