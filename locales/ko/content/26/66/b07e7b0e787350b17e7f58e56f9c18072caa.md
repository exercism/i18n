# 정보

## 문자

[문자 인코딩][char-encoding]은 자연어의 텍스트 요소를 바이트의 나열로 표현하기 위해 사용하는 구체적인 규칙이에요.
여기서 "텍스트 요소"란 자연어에서 의미를 가지는 모든 단위를 말해요. 예를 들어 글자, 공백, 문장 부호, 이모지, 표의 문자 등이 있어요.

NASM(Netwide Assembler, 이 트랙에서 사용하는 어셈블러)은 [ASCII][ascii]를 사용한 데이터 정의를 지원해요.

NASM의 문자 상수는 최대 8바이트까지 가능하며, 작은따옴표(`'`), 큰따옴표(`"`), 백틱(`` ` ``)으로 정의할 수 있어요:

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

특수 문자는 백틱 안에 정의하고 `\`로 이스케이프해야 해요:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

NASM은 [UTF-8][utf8] 인코딩의 [유니코드 문자][unicode]도 지원하는데, 백틱 안에서 `\u`나 `\U`로 지정해요:

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

x86-64에는 어떤 문자 인코딩도 별도의 타입으로 지원하는 기능이 없다는 점에 주의해요.
어셈블리에서 데이터는 바이트의 나열이고, 그 바이트를 문자로, 숫자로, 또는 무엇으로 해석할지는 프로그래머의 몫이에요.

예를 들어 ASCII 문자 '0'은 값이 48인 1바이트예요.
따라서 어떤 바이트에 48을 저장하는 것과 ASCII 문자 '0'을 저장하는 것은 완전히 같아요:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

같은 이유로, 문자를 조작하는 것은 그 바이트의 값을 직접 변환해서 해요:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## 문자열

[문자열][string]은 문자의 나열이에요.
어셈블리에서는 보통 배열로 구현해요.

NASM에서는 다른 배열을 선언하는 것과 같은 방식으로 문자열을 선언할 수 있어요:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

문자열이 다른 배열과 다른 점 하나는, NASM에서는 값을 쉼표(`,`)로 구분하지 않고 문자열을 선언하는 것도 지원한다는 거예요.
쉼표로 값을 섞어 쓰는 것도 가능해요:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

이미 언급했듯이, 문자는 그냥 바이트(유니코드 인코딩에서는 바이트의 나열)라는 점에 주의해요:

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

각 ASCII 문자는 1바이트를 차지하므로, 더 큰 크기에서 뒤따르는 바이트는 모두 `0`이에요.
예를 들어 `'a'`를 qword(8바이트)로 선언하면 첫 번째 바이트는 `'a'`(`97`)이고 나머지 일곱 바이트는 모두 `0`이에요.

이런 이유로, 다음은 모두 동등해요:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
어셈블리에서 문자열은 ASCII NUL 문자(값 `0`)로 자동으로 끝나지 않아요.

C 같은 고급 언어와 연동할 때에는 문자열 끝에 올바른 종료 문자(필요한 경우)가 붙도록 하는 것이 프로그래머의 책임이에요.
~~~~

## 문자열 명령어

문자열은 배열이므로, 메모리를 명시적으로 역참조해서 다른 배열과 같은 방식으로 다룰 수 있어요:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

그 외에도, 메모리에 있는 바이트 나열에서 값을 로드하고, 옮기고, 저장하는 명령어들이 있어요.
_문자열 명령어_라고 부르지만, 메모리에 있는 어떤 바이트 나열, 즉 어떤 배열과도 함께 사용할 수 있어요:

| 명령어  | 하는 일                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | `rsi`가 가리키는 메모리 위치에서 `rax`로 값을 로드해요                                                |
| [stos][stos] | `rax`의 값을 `rdi`가 가리키는 메모리 위치에 저장해요                                               |
| [movs][movs] | `rsi`가 가리키는 메모리 위치에서 값을 복사해서 `rdi`가 가리키는 메모리 위치에 저장해요    |
| [cmps][cmps] | `rsi`가 가리키는 메모리 위치의 값과 `rdi`가 가리키는 메모리 위치의 값을 비교해요 |
| [scas][scas] | `rax`의 값과 `rdi`가 가리키는 메모리 위치의 값을 비교해요                                |

이 명령어들은 명시적인 피연산자를 _받지 않는다_는 점에 주의해요.
피연산자는 암묵적이에요.

경험칙으로는:

1. 원본 피연산자가 메모리 위치일 때, 그 주소는 `rsi`에 저장해야 해요(`s`는 source).
2. 목적지 피연산자가 메모리 위치일 때, 그 주소는 대신 `rdi`에 저장해야 해요(`d`는 destination).
3. 피연산자 중 하나가 메모리 위치가 아니라면, 그 피연산자는 `rax` 레지스터예요.

이 명령어들은 수행하는 구체적인 연산에 따라 메모리 주소를 자동으로 역참조한다는 점에 주의해요.

이들은 모두 다양한 크기로 동작할 수 있어요.
이 크기를 나타내기 위해 접미사가 붙어요:

| 접미사 | 의미 | 크기    |
| :----: | ------- | :------ |
|  `b`   | byte    | 1바이트  |
|  `w`   | word    | 2바이트 |
|  `d`   | dword   | 4바이트 |
|  `q`   | qword   | 8바이트 |

예를 들어:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

또한 사용된 주소를 연산의 크기만큼 갱신해요.
이 갱신은 **방향 플래그(direction flag, DF)**의 값에 따라 이루어져요:

- `DF`가 클리어되어 있으면 주소는 연산의 크기만큼 _증가_해요.
- `DF`가 세트되어 있으면 주소는 대신 같은 크기만큼 _감소_해요.

System V ABI는 함수 진입 시 방향 플래그가 클리어되어 있어야 한다고 규정해요.
따라서 _기본 동작은 메모리를 주소가 오름차순인 순서로 읽고 쓰는 것_이에요.

[cld][cld] 명령어로 방향 플래그를 클리어할 수 있고, [std][std] 명령어로 세트할 수 있어요:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
System V ABI에 따라, 호출자는 호출된 함수가 반환한 뒤 `DF`가 클리어되어 있을 것을 기대해요.
`DF`를 세트했다면 반드시 `ret` 전에 클리어해요.
~~~~

### Lods

이 명령어는 `rsi`에 주소가 있는 메모리 위치에서 값을 _읽어서_ `rax`로 복사해요.

`rsi`의 값은 읽은 바이트 수만큼 갱신돼요:

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

이 명령어는 `rax`의 값을 복사해서 `rdi`에 주소가 있는 메모리 위치에 _써요_.

`rdi`의 값은 쓴 바이트 수만큼 갱신돼요:

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

이 명령어는 `rsi`에 주소가 있는 메모리 위치에서 값을 _읽고_, `rdi`에 주소가 있는 메모리 위치에 그 값을 _써요_.
`rax`의 값은 이 명령어의 영향을 받지 않아요.

`rsi`와 `rdi` 모두 한 메모리 위치에서 다른 위치로 복사된 바이트 수만큼 갱신돼요:

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

이 명령어는 `rsi`에 주소가 있는 메모리 위치에서 값을 _읽고_, `rdi`에 주소가 있는 메모리 위치에서도 값을 _읽어요_.
그다음 두 값을 비교하고 `cmp`에 따라 플래그를 갱신해요.

`rsi`와 `rdi` 모두 두 위치에서 읽은 바이트 수만큼 갱신돼요:

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

이 명령어는 `rax`의 값과 `rdi`에 주소가 있는 메모리 위치에서 _읽은_ 값을 비교해요.
그다음 `cmp`에 따라 플래그를 갱신해요.

`rdi`의 값은 읽은 바이트 수만큼 갱신돼요:

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

이와는 별개로, [rep][rep] 명령어는 메모리와 직접 상호작용하지 않아요.
대신, 앞서 언급한 다른 명령어들에 접두사로 붙어서 그 명령어들을 _반복_할 수 있어요.

`rep`이 접두사로 붙으면, 문자열 명령어는 `rcx`의 값과 같은 횟수만큼 반복돼요.
반복할 때마다 `rcx`의 값은 `1`씩 감소해요.
`rcx`의 값은 명령어를 사용하기 전에 설정해야 한다는 점에 주의해요:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

`rcx`를 카운터로 사용하는 것 외에도, `repe`(또는 `repz`)와 `repne`(또는 `repnz`)는 각각 `zero flag (ZF)`가 클리어되거나 세트되면 실행을 멈춰요:

| 명령어      | 어디에 붙일 수 있는지     | 더 일찍 멈출 수 있는지        |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`, `lods`, `stos` | 아니요                      |
| `repe`,`repz`    | `cmps`, `scas`         | 예, ZF가 0일 때 멈춰요 |
| `repne`, `repnz` | `cmps`, `scas`         | 예, ZF가 1일 때 멈춰요 |

~~~~exercism/advanced
현대 CPU에서 `rep movs`와 `rep stos`는 큰 블록의 데이터를 옮길 때 보통 빠른 선택이에요.
하지만 다른 문자열 명령어들, 그리고 `rep` 없이 동작할 때의 `movs`와 `stos`조차도 보통 평범한 루프보다 느려요.
