# 소개

스마트 포인터는 자동 메모리 관리를 제공하기 위해 설계된 현대 C++의 기능이에요. 원시 포인터에서 흔히 발생하는 메모리 누수와 댕글링 포인터를 방지하는 데 도움을 줘요.
스마트 포인터는 원시 포인터를 감싸는 래퍼처럼 동작하면서, 포인터가 더 이상 필요하지 않을 때 메모리를 자동으로 해제하는 등의 추가 기능을 더해줘요.

## 일반적인 문법

스마트 포인터는 일반적으로 C++ 표준 라이브러리에 클래스 템플릿으로 구현되어 있어요.
가장 많이 쓰이는 스마트 포인터 두 가지는 `std::unique_ptr`와 `std::shared_ptr`예요.

## 고유 포인터

`std::unique_ptr`는 객체를 배타적으로 소유하는 스마트 포인터예요.
어느 시점에든 하나의 `std::unique_ptr` 객체만이 그 자원을 소유하도록 보장해요.
소유하고 있던 `std::unique_ptr`가 파괴되거나 리셋되면, 객체를 자동으로 파괴하고 메모리를 해제해요.

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## `std::make_unique()`의 장점

`std::unique_ptr`를 만들 때는 메모리를 할당하기 위해 `new`를 직접 쓰는 것보다 `std::make_unique()`를 사용하는 편이 좋아요.
`std::make_unique()`는 여러 가지 장점을 제공해요:
1. **예외 안전성**: `std::make_unique()`는 예외 안전성을 보장해요.
  객체를 생성하는 도중 예외가 발생하면 메모리가 자동으로 해제되어 메모리 누수를 막아줘요.
2. **명확성**: `std::make_unique()`를 사용하면 코드가 더 명확하고 간결해져요.
  템플릿 인자가 자동으로 추론되므로 할당할 타입을 일일이 명시할 필요가 없어요.
3. **최적화 기회**: 컴파일러는 `new`로 직접 메모리를 할당할 때보다 `std::make_unique()`를 더 효과적으로 최적화할 기회를 얻을 수 있어요. 그 결과 성능이 향상될 수도 있어요.
4. **오용 방지**: `std::unique_ptr`를 직접 생성하면 기반 자원을 삭제하는 것이 가능해져요.
  그러면 `std::unique_ptr`가 스코프를 벗어날 때 그 자원을 삭제하려고 하면서 정의되지 않은 동작으로 이어질 수 있어요.

## 공유 포인터

`std::shared_ptr`는 여러 `std::shared_ptr` 객체가 같은 자원의 소유권을 함께 가질 수 있게 해주는 스마트 포인터예요.
얼마나 많은 공유 포인터가 그 자원을 참조하는지 추적하고, 자원을 소유한 마지막 공유 포인터가 스코프를 벗어나거나 리셋될 때에만 메모리를 해제해요.

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

~~~~exercism/caution
C++17 이하에서는 `std::make_shared<T[]>`를 통해 배열과 함께 `std::shared_ptr`를 사용하는 것이 직접 지원되지 않아요.
`std::make_shared<T[]>`로 배열을 할당하는 것은 가능하지만, 단일 객체와 배열의 메모리 관리 방식이 다르기 때문에 그 배열로부터 공유 포인터를 직접 만들면 정의되지 않은 동작이 발생할 수 있어요.
대신 `std::vector`나 사용자 정의 삭제 함수를 사용해서 공유 포인터로 배열을 효과적으로 관리하는 방법을 고려해 봐요.
C++17에서 배열 할당과 공유 포인터를 다룰 때는 항상 사용하는 컴파일러와 표준 라이브러리 구현과의 호환성을 확인해야 해요.
~~~~

## `std::make_shared()`의 장점

`std::make_unique()`와 마찬가지로 `std::make_shared()`는 메모리 효율 향상, 예외 안전성, 가독성 같은 이점을 제공해요.
제어 블록과 관리 대상 객체를 위한 메모리 할당을 한 번의 연산으로 합쳐서 효율을 높이고 메모리 누수 위험을 줄여줘요.
또한 템플릿 인자를 자동으로 추론해 주므로 코드가 단순해지고 가독성이 좋아져요.
C++에서 `std::shared_ptr` 객체를 다룰 때 `std::make_shared()`를 사용하면 더 깔끔하고 안전하며 효율적인 코드를 쓸 수 있어요.

## 약한 포인터

`std::weak_ptr`는 `std::shared_ptr`가 관리하는 객체에 대한 비소유 "약한" 참조를 제공하는, `std::shared_ptr`의 동반 클래스예요.

```cpp
// Creating a shared pointer
auto your_account = std::make_shared<std::string>("secret_subscription_password");
// Creating a shared pointer that shares ownership
auto your_flatmates_account = your_account;

// Creating a weak pointer from the shared pointer
auto your_flatmates_boyfriends_account = your_flatmates_account;
// if your_account and your_flatmates_account are deleted, there is no more reference to the shared pointer.
// your_flatmates_boyfriends_account will be a null pointer and cannot use the associated object any longer.
```

약한 포인터는 메모리 누수를 막기 위해 순환 참조를 끊어야 하는 상황에서 유용해요.
`std::weak_ptr`는 `std::shared_ptr`를 사용할 때 생길 수 있는 순환 소유권, 즉 순환 참조 문제를 해결하기 위해 설계되었어요.
순환 소유권 상황에서는 둘 이상의 `std::shared_ptr` 객체가 서로를 참조하면서, 어느 객체도 삭제될 수 없는 순환이 만들어지고 이 때문에 메모리 누수가 발생해요.
`std::weak_ptr`는 참조 횟수에 영향을 주지 않으면서 공유 객체에 약한 참조를 허용하는 방식으로 이 문제의 해결책을 제공해요.
즉, 공유 객체를 관찰하고 접근할 수 있지만, 그 객체가 삭제되는 것을 막지는 않아요.
~~~~

## 사용 지침

기본적으로 스마트 포인터를 사용해요: 배타적 소유에는 `std::unique_ptr`를, 공유 소유에는 `std::shared_ptr`를 써요.
소유하지 않는 참조나 레거시 코드와 맞물릴 때를 위해 원시 포인터를 남겨둬요.
대부분의 경우 `std::unique_ptr`는 참조 카운팅의 부담 없이 가벼운 메모리 관리를 제공하므로 배타적 소유에 충분해요.
`std::shared_ptr`는 진짜 공유 소유가 필요하지 않다면 부담과 복잡성을 더하므로 아껴 써야 해요.
`std::weak_ptr`는 순환 의존성을 끊거나 공유 객체를 관찰하는 데 특화되어 있지만, 흔히 쓰이지는 않아요.
