# 이터레이터 조합

여러 이터레이터가 하나의 루프를 함께 쓸 수 있어요. 루프가 한 바퀴 돌 때마다 각각 한 번씩 나아가요.

```sather
   loop
      a ::= xs.elt!;
      b ::= ys.elt!;
      ...
   end;
```

## 종료

이터레이터 중 **하나라도** 남은 게 없으면 그 순간 루프가 끝나요. 나머지 이터레이터는 더 나아가지 않고, 본문의 나머지 부분도 실행되지 않아요.

즉, 두 배열을 함께 순회하면 `min(xs.size, ys.size)`바퀴만 돌게 돼요. 더 긴 쪽을 끝까지 순회하려면 위치를 기준으로 순회하면서 인덱스로 접근하고, 짧은 배열을 넘어가지 않도록 직접 확인해야 해요.

## 호출 지점마다 별개의 순회

이터레이터의 위치는 객체에 속하는 게 아니라, 그것이 쓰인 *프로그램상의 위치*에 속해요. 그래서 다음과 같이 쓰면

```sather
   loop
      #OUT + xs.elt! + xs.elt!;      -- two walks, each advancing separately
   end;
```

서로 독립적인 두 번의 순회에서 한 바퀴마다 서로 다른 원소 두 개를 가져와요. 값을 한 번만 꺼내서 담아 두세요.

## 끝없는 이터레이터

| 이터레이터 | 내놓는 값 |
| --- | --- |
| `n.up!` | `n`, `n+1`, `n+2`, … 를 끝없이 |
| `n.upto!(m)` | `n` … `m`까지 내놓고 끝나요 |

끝없는 이터레이터는 끝나는 것과 짝을 이루거나, `break!`나 `until!`과 함께 써야 해요. 혼자 두면 영원히 반복해요.

`1.up!`을 컬렉션 순회와 짝지으면 항목에 번호를 매기는 관용적인 방법이 되니, 보고 바로 알아볼 수 있으면 좋아요.

## 왜 이것이 독립된 개념일까요

*첫 번째* 이터레이터가 바닥나면 끝나는 루프는, 눈에 띄게 고장 나기보다 조용히 틀린 프로그램을 만들기 쉬운 바로 그 규칙이에요. 프로그램이 멈추지는 않고, 그냥 일찍 끝나 버려요. 이 내용을 이터레이터를 소개하는 연습 문제나 이터레이터를 직접 작성하는 연습 문제에 끼워 넣으면, 다른 것도 새로 배우는 와중에 이걸 마주치게 돼요.
