# 힌트

## 일반

- 포인터 문법에 특히 주의를 기울여요.
  `*`(역참조 연산자)와 `->`(포인터를 통한 멤버 접근)를 사용하게 될 거예요.
- 잘못된 메모리에 접근하는 일이 없도록, 필요한 곳에서는 널 포인터(`nullptr`)인지 반드시 확인해요.
- 코드가 완성되지 않았어도 테스트를 실행할 수 있어요. 대략적인 구조만 갖춰도 테스트 결과를 확인할 수 있어요.
- 테스트에서 사용하는 모든 함수는 헤더 파일에 선언해야 해요.
- 프로그램이 충돌하거나 예상과 다르게 동작할 때는 대개 널 포인터를 역참조했기 때문이에요.
  `nullptr`을 제대로 처리했는지 다시 확인해 봐요.
- 포인터 연산을 사용할 때는 센서 배열의 범위를 벗어나지 않도록 해요.
  배열의 크기를 넘어서면 메모리 문제가 생길 수 있어요.

## 1. 센서 연결 확인 (`connection_check`)

- 이 작업은 포인터가 널인지 아닌지 확인하는 것이 핵심이에요.
- 포인터가 유효한지 확인하려면 비교 연산자 `!=`를 사용해요.
- 포인터를 제대로 확인하고 있는지 확신이 서지 않는다면, `nullptr`이 무엇을 나타내는지(유효한 메모리 주소가 없음)를 생각해 봐요.

## 2. 센서 활동 횟수 세기 (`activity_counter`)

- 센서 배열을 순회해야 해요.
  C++에서 배열은 첫 번째 원소를 가리키는 포인터로 다룰 수 있어요.
- 인덱스 `i`의 센서에 접근하려면 포인터 연산(`sensor_array + i`)을 사용해요.
- `->` 연산자는 포인터를 통해 구조체의 멤버에 접근할 때 사용해요.

### 예시

```cpp
int sum = (sensor_array + i)->activity; // Access activity using pointer arithmetic
```

## 3. 경보 제어 (`alarm_control`)

- 먼저 센서에 접근하기 전에 포인터가 널인지 확인해요.
- `pillar_men_sensor` 구조체의 `activity` 멤버에 접근하려면 `->` 연산자를 사용해요.
- 센서의 활동 수준이 `0`이면 어떻게 되어야 할지 신중하게 생각해 봐요.
  경보가 울려야 할까요?

## 4. `uv_alarm` 함수로 데이터의 이상 여부 확인하기

- `uv_light_heuristic` 함수에 센서의 데이터 배열을 가리키는 포인터를 넘기려면 `&` 연산자를 사용해요.
- 센서의 데이터에 접근하기 전에 널 포인터인지 제대로 확인해야 해요.
- 경보가 울려야 하는지 판단하려면 `uv_light_heuristic`의 결과를 센서의 `activity` 값과 비교해요.
