# 안내 추가

## 스텁

`src/TreeBuilding.hs`에는 이미 모든 테스트를 통과하는 동작하는 풀이가 들어 있어요.
이 풀이는 느리고 읽기 어려워요. 테스트를 깨뜨리지 않으면서 이 풀이를 더 나은 코드로 고쳐 봐요.

`buildTree`는 레코드가 올바른 트리를 이루지 못하면 `Nothing`을 반환해요.

## 표현 방식 바꾸기

테스트는 `Tree`의 생성자를 직접 사용하지 않아요.
대신 다음 함수로 기대하는 트리를 만들어요.

```haskell
node :: Int -> [Tree] -> Tree
```

여기서 `node i children`은 id가 `i`이고 주어진 자식들을 id 오름차순으로 가진 노드예요.

즉, `Tree`를 어떻게 표현하든 자유롭게 바꿀 수 있어요. 예를 들어 다음처럼요.

```haskell
import qualified Data.Tree as T

type Tree = T.Tree Int

node :: Int -> [Tree] -> Tree
node = T.Node
```

`Tree`에 여전히 `Eq`와 `Show` 인스턴스가 있고 `node`가 같은 의미를 유지하기만 하면 돼요.
`containers` 같은 라이브러리를 사용한다면 `package.yaml`의 `dependencies`에 추가하는 것을 잊지 마세요.
