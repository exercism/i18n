# 안내

[exercise:csharp/object-relational-mapping]()에서 소개한 ORM(객체 관계 매핑) 시스템 작업으로 다시 돌아왔어요.

ORM 사용 분석 결과, 트랜잭션의 95%가 하나의 호출 메서드 안에서 실행된다고 해요. 그래서 트랜잭션을 열고, 쓰고, 커밋하는 단일 ORM 메서드를 두는 편이 더 적절하다고 결정했어요.

데이터베이스에는 다음과 같은 인스턴스 메서드가 있어요.

- `Database.BeginTransaction()`는 데이터베이스에서 트랜잭션을 시작해요.
- `Database.Write(string data)`는 트랜잭션 안에서 데이터를 데이터베이스에 써요. 잘못된 데이터를 받으면 예외가 발생해요. `Database.BeginTransaction()`를 호출하지 않은 상태에서 이 메서드를 호출하려고 하면 예외가 발생해요. 성공하면 데이터베이스의 내부 상태가 `DataWritten`으로 바뀌어요.
- `Database.EndTransaction()`는 데이터베이스에 트랜잭션을 커밋해요. 트랜잭션을 닫을 수 없거나 `BeginTransaction()`를 호출하지 않았을 때 예외가 발생할 수 있어요.
- `Database.Dispose()`를 호출하면 트랜잭션 도중 예외가 발생했을 때 데이터베이스를 정리해요. 그러면 데이터베이스의 상태가 `Closed`로 바뀌어요.

## 1. 데이터베이스에 쓰기

`Orm.Write()` 메서드를 구현해서 데이터베이스 트랜잭션을 시작하고, 전달받은 데이터를 쓰고, 트랜잭션을 커밋해요. `InvalidOperationException`을 비롯한 모든 예외는 로깅이나 다른 어떤 개입도 없이 호출자에게 그대로 전달되어야 해요.

```csharp
Database db = new Database();
Orm orm = new Orm(db);
orm.Write("good write");
// => database has an internal state of State.Closed
orm.Write("bad write");
// => an exception is thrown but database is left with an internal state of State.Closed
orm.Write("bad commit");
// => an exception is thrown but database is left with an internal state of State.Closed
```

## 2. 데이터베이스에 쓰고, 쓰기 성공 여부를 호출자에게 반환하기

`Orm.Write()`가 도입된 지 몇 달이 지났고, 팀 안에서 의견이 갈리고 있어요. 많은 개발자가 예외가 발생했을 때 _ORM_이 오류를 처리하고 호출자에게 성공 여부만 반환하기를 원해요.

`Orm.WriteSafely()` 메서드를 구현해서 데이터베이스 트랜잭션을 시작하고, 전달받은 데이터를 쓰고, 트랜잭션을 커밋해요(위와 같아요). _쓰기_가 성공하면 `true`를, 그렇지 않으면 `false`를 반환해야 해요. 예외를 로깅하려고 하지 마세요.

```csharp
Database db = new Database();
Orm orm = new Orm(db);
orm.WriteSafely("good write");
// => true
orm.WriteSafely("bad write");
// => false
orm.WriteSafely("bad commit");
// => false
```
