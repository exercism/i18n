# 추가 지침

## `from_quote`의 장단점

이 연습 문제에서는 `Card` 타입에 `from_quote` 함수를 정의해요. 덕분에 다음과 같은 코드를 작성할 수 있어요:

```roc
card : Card
card = "Q"
```

이 코드는 컴파일 시점에 `Card.from_quote("Q")`를 암시적으로 호출해요. 런타임에 파싱을 처리할 필요가 없어서 프로그램이 더 빨라질 수 있고, `from_quote`에서 거부한 카드는 런타임이 아니라 컴파일 시점에 걸러진다는 점도 보장해요. 게다가 코드가 깔끔하고 읽기 쉬워져요. 예를 들어, 이 연습 문제의 테스트 중 하나는 다음과 같아요:

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

하지만 이 코드를 읽는 사람은 `simulate_game` 함수가 `List(Str)` 두 개를 담은 레코드를 받는다고 생각할 수 있는데, 실제로는 `List(Card)` 두 개를 담은 레코드예요. 이 때문에 혼란이나 실수가 생길 수 있어요. 그래서 조금 길지만 더 명확한 형식인 `"Q".Card`를 선호할 수도 있어요. 이 형식도 컴파일 시점에 `from_quote` 함수를 호출해요.

직접 작성하는 프로그램에서는 대신 `from_str` 함수를 사용하는 편이 좋을 수도 있어요:

```roc
Card := { ... }.{
    from_str : card_str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

이렇게 컴파일 시점에 `from_str`뿐 아니라 다른 순수 함수도 호출할 수 있어요:

```roc
Ok(card) = Card.from_str("Q")
```

참고: 이 정의를 최상위에 두면 컴파일 시점에 실행돼요(함수가 순수하고 입력이 컴파일 시점에 알려져 있기 때문이에요). 함수 안에서는 런타임에 `from_str` 함수를 사용할 수 있어요.
