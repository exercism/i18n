# 소개

**루프**는 종료 조건이 충족될 때까지 여러 번 실행될 수 있는 명령어의 나열이에요.

x86-64에서는 보통 이전 레이블로 점프해서 루프를 만들어요:

```x86asm
example_loop:
    ...
    jmp example_loop
```

이전 레이블로 향하는 무조건 점프는 항상 실행을 그 레이블로 옮겨요.
즉, 반복되는 구간 밖으로 빠져나가는 점프가 따로 없다면, 루프는 영원히 반복돼요.

예를 들어, 이 루프는 끝나지 않아요:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

그리고 이 루프는 조건이 충족되는지에 따라 끝날 수도 있어요:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## 카운팅 루프

카운팅 루프는 거의 항상 같은 방식으로 끝나요. 카운터를 갱신하거나 두 값을 비교하는 명령어가 나오고, 바로 뒤에 다시 한 바퀴 돌지 결정하는 조건부 점프가 따라와요.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
위 코드에서는 `cmp rsi, 0`이 필요 없어요. `sub rsi, 1`이 결과가 `0`일 때 이미 `zero flag (ZF)`를 설정하기 때문이에요.

어셈블리에서 조건을 검사하는 주된 방법은 `cmp`이지만, 플래그를 갱신하는 명령어는 많아요.
예를 들어, 정수 산술이나 비트 연산 명령어 상당수는 결과가 `0`이면 `ZF`를, 결과가 음수이면 (즉, 최상위 비트가 설정되면) `SF`를 갱신해요.

각 명령어가 어떤 플래그에 영향을 주는지는 [레퍼런스][reference]에서 확인할 수 있어요.

[reference]: https://www.felixcloutier.com/x86/
~~~~

참고로 위 예제에서 `rsi`는 `0`보다 크다고 가정해요.
만약 `0`이었다면 `sub rsi, 1`이 `rsi`를 `-1`로 만들 텐데, 부호 없는 수로 보면 아주 큰 값이에요.
루프가 끝나려면 `18,446,744,073,709,551,615`번을 더 반복해야 해요.
또한 배열의 길이가 `0`이므로, 메모리에 접근하면 범위를 벗어나게 돼요.

배열의 길이를 보장할 수 없다면, 흔히 쓰는 방법이 두 가지 있어요.

첫 번째는 종료 조건을 루프의 시작으로 옮기고, 끝에 무조건 점프를 두는 방법이에요:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

두 번째는 루프를 시작하기 전에 길이가 `0`인 배열인지 한 번 검사하는 방법이에요:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

이 두 번째 방법은 루프 본문에 분기가 더 적어서, 보통 첫 번째보다 더 효율적이에요.
이 내용은 앞으로 나오는 개념에서 더 자세히 배우게 될 거예요.

~~~~exercism/advanced
경우에 따라 최신 CPU는 서로 다른 두 명령어를 하나의 연산으로 합칠 수 있어요.
이 최적화를 **macrofusion**이라고 해요.

`sub`나 `add` 같은 여러 산술 명령어는 물론 `cmp`와 `test`도, 바로 뒤따르는 조건부 점프와 흔히 합쳐져요.
즉, `cmp rax, rdx`처럼 바로 뒤에 조건부 점프가 오는 명령어는 CPU가 보통 하나의 연산으로 처리할 수 있어요.

macrofusion은 CPU에 따라 달라지고, 어떤 명령어가 어떤 조건부 점프와 합쳐지는지도 조금씩 차이가 있어요.

참고할 만한 자료로는 [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch]가 있어요.
[Intel optimization reference manual][intel-opt]의 3.4.2.2절(Optimizing for Macrofusion)에도 Intel CPU에서 합쳐질 수 있는 쌍이 나와 있어요.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
