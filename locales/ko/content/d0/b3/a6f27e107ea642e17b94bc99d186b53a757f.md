# 접근법

각 연습 문제에는 접근법을 연결할 수 있는데, 접근법은 그 문제를 푸는 여러 가지 방법을 설명해요.

## 접근법 작성하기

접근법은 어떤 문제를 특정한 방식으로 푸는 방법을 살펴봐요.

- 내용은 다음 중 하나여야 해요:
  - 관용적인 접근법 살펴보기
  - 관용적이지는 않지만 흥미로운 접근법 살펴보기
- (완전한) 코드 예시로 시작하기
  - 문서의 나머지 부분에서도 코드 예시를 아낌없이 활용하기
- 주제를 깊이 파고들어도 좋아요
- 유용한 자료(예: 문서)로 연결되는 링크 넣기
- 스니펫은 접근법의 핵심을 보여줘야 해요
  - 최대 8줄까지 쓸 수 있어요

여러 접근법을 비교하고 싶다면 [아티클](/docs/building/tracks/articles)을 작성해 보세요.

## 접근법 개요

- 문제의 맥락을 짚어 주기
  - _모든_ 접근법에 해당하는 중요한 점(예: 함정)을 설명하기
- 가장 관용적인 접근법들을 다루기
- 각 접근법은 그 접근법을 보여주는 스니펫으로 시작하기
- 내용은 비교적 개괄적인 수준으로 유지하기
  - 자세한 정보는 별도의 접근법 페이지에 넣기
  - 더 자세한 내용은 별도 접근법 페이지로 연결하기
- 접근법들 중에서 어떻게 고를지 이야기하기
  - 각각의 장단점은 무엇인가요?
  - 특정 사용 사례에 더 잘 맞는 접근법도 있나요?

## 일반적인 고려 사항

- 어떤 언어는 같은 내용을 여러 방식으로 표현할 수 있어요. 그중 일부 문법이 언어의 최신 버전에서야 등장했다면 "옛" 문법을 쓰는 것도 고려해 봐요. 그래야 학습자가 코드를 이해할 가능성이 더 높아요.
  - 다른 방식의 문법은 접근법 문서에서 보여줄 수 있어요
- 해당 언어에 권장 스타일 가이드가 있다면 (가능한 범위에서) 그 지침을 따라요

## 어떤 문제에 접근법을 써야 할까요?

일반적으로 [연습 문제](/docs/building/tracks/practice-exercises)는 보통 여러 가지 방법으로 풀 수 있기 때문에 접근법을 쓰기에 더 적합해요.

[개념 문제](/docs/building/tracks/concept-exercises)라면 모범 답안 접근법을 다루는 것도 흥미로울 수 있어요. 예를 들어, 가르치는 개념 덕분에 특정 코드를 어떻게 더 쉽게 작성할 수 있는지 보여줄 수 있어요.

## 파일

각 접근법은 다음 두 파일을 추가해야 해요:

- `.approaches/<approach-slug>/content.md`: 접근법에 대한 설명 ([문서](/docs/building/tracks/practice-exercises#file-approaches-approach-slug-content-md) 참고)
- `.approaches/<approach-slug>/snippet.txt`: 접근법을 보여주는 스니펫 ([문서](/docs/building/tracks/practice-exercises#file-approaches-approach-slug-snippet-txt) 참고)

그다음에는 다음을 추가하거나 갱신해야 해요:

- `.approaches/config.json`: 접근법의 메타데이터 ([문서](/docs/building/tracks/practice-exercises#file-approaches-config-json) 참고)

### 스니펫 확장자 설정하기

[트랙의 `config.json` 파일](/docs/building/tracks/config-json)에서 `approaches.snippet_extension` 필드를 설정하면 기본 `.txt` 확장자 대신 원하는 확장자를 쓸 수도 있어요.
이 필드를 설정했다면 추가해야 하는 스니펫 파일의 이름은 `.approaches/<approach-slug>/snippet.<approaches.snippet_extension>`이어야 해요.
