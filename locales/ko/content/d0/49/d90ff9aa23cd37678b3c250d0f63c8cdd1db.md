# 소개

프로그래머들은 보통 완벽한 소프트웨어를 작성하려고 노력하지만, 대개 실패해요.

예상치 못하게 문제가 생기기도 하는데, 우리는 그런 상황에 대처할 수 있어야 해요.

일부 언어 설계자들은 오류를 최대한 빨리 발견한 다음, 디버깅에 도움이 되는 메시지와 함께 실행을 종료하는 것을 우선순위로 여겨요.

데이터 과학 언어들은 좀 더 미묘한 접근을 취하는 편이에요.
어떤 오류는 즉시 종료해야 할 만큼 심각하지만, 대개는 문제를 나중에 처리할 것으로 표시해 두고 실행을 계속하는 편이 더 좋아요.

[없음][nothingness] 개념에서 Julia가 문제가 되는 값들을 위해 여러 가지 자리 표시자를 제공한다는 것을 봤어요: [`missing`][nothing], [`NaN`][NaN], `Inf`.
특정 상황에서 이런 값들이 프로그램을 종료하는 것보다 더 나은 접근인지는 프로그래머의 판단에 달려 있어요.

_용어에 관한 한 가지_를 먼저 짚고 넘어갈게요: Julia 문서는 "오류"와 "예외"라는 단어를 대체로 같은 뜻으로 사용해요.
아래 내용도 마찬가지로 일관성이 없을 수 있어요.

## 표준 오류 타입

교육 과정을 여기까지 따라오면서 Julia가 내놓는 오류 메시지를 많이 봤을 거예요.
예를 들어:

```julia-repl
julia> Int(3.14)
ERROR: InexactError: Int64(3.14)
```

실수를 정수로 변환하려면 정밀도가 손실되기 때문에 `InexactError`가 발생해요.

`InexactError`는 Julia에 기본으로 내장된 여러 타입 중 하나예요([현재 25개][errors]).
모두 `Exception`의 하위 타입이에요:

```julia-repl
julia> supertype(InexactError)
Exception
```

## `throw()`

표준 오류 타입 가운데 몇 가지는 직접 코드에서 발생시켜 보면 유용할 수 있어요.

모든 구체 타입과 마찬가지로, 오류에도 생성자가 있어요.
생성자는 다양한 인자를 받기 때문에, 사용하려는 오류의 [문서][errors]를 확인해 봐요.

```julia-repl
julia> DomainError(42, "out of range")
DomainError(42, "out of range")
```

오류를 사용하려면 생성자를 [`throw()`][throw] 함수로 감싸요:

```julia-repl
julia> throw(DomainError(42, "out of range"))
ERROR: DomainError with 42:
out of range
```

## `error()`

빠르고 간단하게 처리하고 싶을 때는 [`error()`][error] 함수가 편리해요.
이 함수는 문자열(또는 문자열의 구성 요소)을 인자로 받아요:

```julia-repl
julia> happy = false;
julia> happy || error("😞 something went wrong")
ERROR: 😞 something went wrong
```

## 사용자 정의 오류

새로운 오류 타입을 만드는 것은 원칙적으로 아주 쉬워요.
그냥 `Exception`의 하위 타입을 하나 더 추가하면 돼요:

```julia-repl
julia> struct MyError <: Exception end

julia> throw(MyError)
ERROR: MyError
```

하지만 위 예제에는 필드가 없고 생성자도 인자를 받지 않기 때문에, 오류 메시지를 제어할 수 없어요.
메시지 필드를 추가할 수 있어요:

```julia-repl
julia> struct AnotherError <: Exception
           msg::String
       end

julia> throw(AnotherError("Wrong!"))
ERROR: AnotherError("Wrong!")
```

생성자를 그냥 출력하는 것만으로는 아직 충분하지 않아요.
앞에서 `DomainError`를 발생시킨 예제와 비교해 봐요.

사용자 정의 오류를 내장 오류와 같은 방식으로 처리하려면 [`showerror()`][showerror] 메서드를 추가해야 해요:

```julia-repl
julia> Base.showerror(io::IO, e::AnotherError) =
           print(io, "AnotherError: ", e.msg)

julia> throw(AnotherError("Wrong!"))
ERROR: AnotherError: Wrong!
```

이 기능은 문서가 다소 부실하지만, 본질적으로 사용자 정의 오류 타입을 Julia의 표준 오류 처리 시스템에 연결해 줘요.

## 단언

단언의 기본 발상은 "이 명제는 참이어야 하니, 거짓이면 크게 알려 달라"는 거예요.
이것의 가치는 주로 디버깅 중에 있는데, 프로덕션 코드는 단언에 실패해서는 안 되기 때문이에요.

[타입][types] 개념에서 함수의 반환 타입을 확인하는 등 타입 단언을 추가할 수 있다는 것을 봤어요.

```julia-repl
julia> 42::Number
42

julia> "two"::Number
ERROR: TypeError: in typeassert, expected Number, got a value of type String
```

더 일반적으로, [`@assert`][assert] 매크로를 사용하면 불리언으로 평가되는 모든 표현식을 검사할 수 있어요:

```julia-repl
julia> n = 22;
julia> @assert isodd(n) "n must be odd"
ERROR: AssertionError: n must be odd
```

## `try`...`catch`

어떤 오류는 어쩔 수 없이 치명적이지만, 대개는 프로그램이 원활하게 복구하기를 기대해요.

기본적으로 오류가 발생하면 현재 함수가 즉시 종료되고, 오류는 (정보를 담은 메시지와 함께) 이 함수를 호출한 쪽으로 전달돼요.

이런 과정이 호출 스택을 따라 계속 올라가다가, 최상위 코드가 오류 메시지와 함께 종료돼요.

어느 단계에서든 [`try...catch`][try-catch] 블록으로 오류를 가로채 처리할 수 있어요.

```julia-repl
julia> n = -1;
julia> try
           log_n = log(n)
       catch problem
           if problem isa DomainError # number out of range
               # See next section for more on @warn and @info
               @warn "you may have supplied a negative real number: $n"
               @info "trying with complex argument"
               log_n = log(Complex(n))  # fallback calculation

           elseif problem isa MethodError # no idea what n is
               @error "please supply a valid argument"
 
           else
              rethrow() # the error could be anything else
           end
      end
┌ Warning: you may have supplied a negative real number: -1
└ @ Main REPL[3]:5
[ Info: trying with complex argument
0.0 + 3.141592653589793im  # success
```

위 예제에서 `log(n)`은 `n`이 양의 실수이거나 임의의 복소수여야 해요.
`try ... catch`는 음의 실수 값에서 생기는 문제를 잡아내고, 수학 표기법으로 올바른 복소수 답인 `iπ`를 반환해요.

예를 들어 문자열 인자를 넘기면, 사용자에게 바로잡아 달라고 요청하는 것 외에는 복구할 방법이 없어요.

마지막으로 모든 경우를 처리하기 위해, `DomainError`도 `MethodError`도 아닌 경우를 위한 [`rethrow()`][rethrow]를 추가했어요.

선택적으로 쓸 수 있는 절도 더 있어요:

- [`else`][else]: `try` 절이 성공하면 실행돼요.
- [`finally`][finally]: `try`가 성공하든 실패하든 외부 리소스를 정리할 때 사용할 수 있어요. 파일 닫기, 데이터베이스 연결 해제 등이에요.

***참고:*** 때로는 `try...catch`가 필요한 경우도 있지만, 남용하지 않도록 해요.
대신 `if...else` 블록을 사용할 수 있다면, 예외를 잡는 것보다 성능이 훨씬 좋아요.

## 로깅

위에서 설명한 `error()` 함수를 [`@error`][error_macro] 매크로와 혼동하면 안 돼요.

이 함수는 예외를 발생시키고, 이 예외는 잡히지 않으면 호출 스택을 따라 위로 전달돼요.

`@error` 매크로는 [`@debug`][debug_macro], [`@info`][info_macro], [`@warn`][warn_macro]과 함께 [`Logging`][logging] 모듈의 일부이며, 프로그램 흐름을 바꾸지 않으면서 정보를 담은 메시지를 생성하기 위한 것이에요.

출력은 기본적으로 터미널로 가고(심각도에 따라 색이 다르게 표시돼요), 실제 애플리케이션에서는 다른 여러 방법도 가능해요.

```julia-repl
julia> @warn "Something looks not quite right"
┌ Warning: Something looks not quite right
└ @ Main REPL[55]:1

julia> @error "Panic!"
┌ Error: Panic!
└ @ Main REPL[56]:1
```
