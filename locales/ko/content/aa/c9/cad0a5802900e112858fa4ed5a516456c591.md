# 개요

Elixir 프로그래머들은 흔히 ["let it crash"][let-it-crash]라고 말하고 ["happy path"][happy-path]를 기준으로 코드를 짜지만, 함수 호출에서 예외를 처리해 특정 값을 반환하거나 메시지를 전달하거나 시스템 자원을 해제해야 하는 때도 많아요.

- 정상적인 상황에서 오류를 발생시키는 함수는 이름 끝에 `!`를 붙여야 해요.
- 또는 성공과 실패를 나타내기 위해 애텀과 튜플을 반환하는 함수도 있어요:

  ```elixir
  Map.fetch(%{a: 1}, :a)
  # => {:ok, 1}
  Map.fetch(%{a: 1}, :b)
  # => :error

  Map.fetch!(%{a: 1}, :b)
  # => raises KeyError
  ```

## 안티 패턴 피하기

오류를 사용해 논리 흐름을 제어하는 프로그래밍 패턴은 피해요. Elixir에서는 이런 패턴을 안티 패턴이라고 해요.

```elixir
# Avoid using errors for control-flow.
try do
  {:ok, value} = MyModule.janky_function()
  "All good! #{value}."
rescue
  e in RuntimeError ->
    reason = e.message
    "Uh oh! #{reason}."
end

# Rather, use control-flow structures for control-flow.
case MyModule.janky_function() do
  {:ok, value} -> "All good! #{value}."
  {:error, reason} -> "Uh oh! #{reason}."
end
```
