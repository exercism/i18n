# 테스트
Exercism 연습 문제를 푸는 한 가지 방법은 웹사이트에 접속해서, 브라우저 안에서 풀이를 편집하고 테스트할 수 있는 편집기를 사용하는 거예요.

또는 연습 문제를 내 컴퓨터로 내려받아서, 자신만의 편집기와 여러 도구를 이용해 풀이를 만들고 테스트한 뒤 마지막으로 제출할 수도 있어요.

이 방법에는 터미널이나 명령줄 창에서 실행되는 애플리케이션인 Exercism 명령줄 인터페이스, 즉 CLI를 사용하게 돼요. 설치 방법은 여기에서 확인할 수 있어요: [Exercism CLI 문서](https://exercism.org/docs/using/solving-exercises/working-locally).

## 테스트 방식
Exercism은 테스트 주도 개발에 어느 정도 경험이 있다고 가정해요. 각 연습 문제는 _`stub file`_, 미리 작성된 일련의 테스트가 담긴 _`test file`_, 그리고 테스트를 실행하는 데 쓰이는 _`test script`_로 이루어져 있어요.

연습 문제를 풀려면 _`stub file`_을 점진적으로 발전시켜서, 결국에는 모든 테스트를 통과하는 코드를 담도록 만들어야 해요.

실제로는 _`stub file`_과 _`test file`_ 둘 다 활발히 편집하게 된다는 뜻이에요. _`test file`_을 편집하는 건 테스트 코드를 바꾸기 위해서가 아니라, 실패하는 테스트를 주석 처리하기 위해서라는 점에 주목해요.

처음에는 하나를 제외한 모든 테스트가 주석 처리되어 있고, 그다음 _`stub file`_이 동작하는 풀이로 나아감에 따라 더 많은 테스트의 주석이 풀리고, 결국 모든 테스트가 성공적으로 실행돼요.

## 테스트 인프라
테스트 프레임워크의 구성 요소가 연습 문제 다운로드에 포함되어 있으니, 추가 소프트웨어를 설치할 필요가 없어요.

테스트 프레임워크는 세 개의 Rexx 파일로 이루어져 있는데, 테스트할 때 이 파일들이 연습 문제 풀이와 결합해 테스트 코드 단위를 이루고, 그러면 _`test script`_가 그것을 실행해서 테스트 결과를 터미널에 출력해요.

_`test script`_나 다른 테스트 프레임워크 파일은 편집하거나 삭제하지 마세요. 만약 예기치 않게 그렇게 됐다면, 풀이 코드를 잘 저장해 두고 Exercism CLI로 연습 문제를 다시 내려받으면 돼요.

## 테스트 실행하기
연습 문제를 푸는 과정은 다음과 같아요:

1. 터미널을 열어요
2. 선택한 연습 문제를 내려받아요
3. 연습 문제 디렉터리로 이동해요
4. 편집기에 스텁 파일과 테스트 파일을 열어요
5. 다음을 반복해요,

    1. 테스트 스크립트를 실행해요
    2. 스텁 파일에 코드를 작성하고(천천히 풀이 파일로 바꿔 가면서), 테스트 파일의 테스트를 주석 처리하거나 주석을 풀어요

6. 모든 테스트가 통과하면, 풀이를 Exercism에 제출해요
7. 터미널을 닫아요
8. 성공을 축하해요

`acronym` 연습 문제를 사용한 Linux 터미널 안에서의 구체적인 예시예요(exercism 작업 공간이 `/home/exercism`이라고 가정해요).

연습 문제 내려받기:

`exercism download --track=rexx --exercise=acronym`

연습 문제 디렉터리로 이동:

`cd /home/exercism/rexx/acronym`

다른 창, 이를테면 GUI 창에서 `acronym.rexx`와 `acronym-check.rexx`를 각각 스텁 파일과 테스트 파일로 편집기에 열어요.

테스트 스크립트를 실행해요: `./test-acronym`

그러면 모든 테스트가 실패해야 해요:

```bash
1..9
not ok 1 - basic Abbreviate("Portable Network Graphics")
not ok 2 - lowercase words Abbreviate("Ruby on Rails")
not ok 3 - punctuation Abbreviate("First In, First Out")
not ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
not ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
not ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
not ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
not ok 8 - apostrophes Abbreviate("Halley's Comet")
not ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

`acronym-check.rexx` 파일에서 첫 번째 테스트를 제외한 나머지를 모두 주석 처리하고, 테스트 스크립트를 다시 실행해요. 그러면 다음 출력이 나와야 해요:

```bash
1..1
not ok 1 - basic Abbreviate("Portable Network Graphics")
```

`acronym.rexx`가 동작하는 코드를 담을 때까지 고쳐 봐요. 그러면 결국 테스트 스크립트를 실행한 출력이 다음과 같아져야 해요:

```bash
1..1
ok 1 - basic Abbreviate("Portable Network Graphics")
```

이어서 나머지 테스트의 주석을 풀고, 테스트 스크립트를 다시 실행해요. 그러면 결국 출력이 다음과 같아져야 해요:

```bash
1..9
ok 1 - basic Abbreviate("Portable Network Graphics")
ok 2 - lowercase words Abbreviate("Ruby on Rails")
ok 3 - punctuation Abbreviate("First In, First Out")
ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
ok 8 - apostrophes Abbreviate("Halley's Comet")
ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

이제 연습 문제 풀이를 제출할 수 있어요:

`exercism submit acronym.rexx`

그러면 평판 점수를 하나 더 얻게 돼요. 끝나면 터미널을 닫아요.

MacOS 사용자의 과정도 꽤 비슷한데, MacOS가 UNIX에서 파생된 운영체제이기 때문이에요.

Windows 사용자의 과정도 대체로 비슷하지만, 몇 가지 사소한 차이가 있어요:

- _Command Prompt_ 창이 터미널 역할을 해요
- 경로에서는 슬래시 대신 역슬래시를 사용하므로, 작업 디렉터리가 다음과 같을 수 있어요:

  `cd C:\Users\MyName\exercism\rexx\acronym`

- 테스트 스크립트는 다음으로 실행해요:

  `test-acronym`  또는  `test-acronym.bat`

테스트 출력은 동일해요.
