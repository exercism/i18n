# 문자열 빌더

`STR`은 절대 바뀌지 않아요. 그래서 `+`로 기존 문자열에 내용을 더할 수 없고, 양쪽 내용을 모두 담은 완전히 새로운 문자열을 만들어야 해요.

한 번이면 괜찮아요. 하지만 루프 안에서는 아니에요:

```sather
   -- don't
   script ::= "";
   loop
      script := script + lines.elt!;
   end;
```

매번 지금까지 만든 내용 전체를 새 문자열로 복사하고 이전 것은 버려요. 줄이 열 개면 복사본도 열 개고, 복사본은 갈수록 길어져요. 줄이 백 개면 복사도 백 번이에요. 작업량은 줄 수의 *제곱*에 비례해서 늘어나고, 아무 문제 없어 보이던 루프가 프로그램에서 가장 느린 부분이 돼요.

## FSTR

`FSTR`은 *바뀔 수 있는* 문자열, 즉 **문자열 빌더**예요. `FSTR`에 더하는 것은 보통 이미 확보된 공간에 그냥 써 넣는 것이라서, 백 줄을 도는 루프는 복사본 백 개가 아니라 백 줄 분량의 작업만 해요.

```sather
   script ::= #FSTR;
   loop
      script := script + lines.elt!;
   end;
   return script.str;
```

눈여겨볼 점이 세 가지 있어요.

**`#FSTR`은 빈 문자열 빌더를 만들어요.** `#FSTR(100)`은 문자 100개가 들어갈 공간을 미리 확보한 빌더를 만들어요. 크기를 미리 아는 경우에는 이렇게 하는 게 좋아요.

**결과는 반드시 다시 대입해야 해요.** `script := script + ...`처럼 써야 하고, `script + ...`만 단독으로 쓰면 안 돼요. 보통은 들어갔던 것과 같은 빌더가 돌아오지만, 공간이 부족하면 더 커진 새 빌더가 나와요. 결과를 버리면 예전 빌더에 계속 쓰게 되는 셈이에요.

**마지막에 `.str`을 붙여요.** `: STR`을 반환하기로 한 루틴은 `STR`을 돌려줘야 하는데, `.str`이 빌더에서 `STR`을 만들어 줘요.

## 무엇을 더할 수 있을까요

`FSTR`에 적용하는 `+`는 문자열, 문자, 정수, 불리언을 모두 받아요. 그래서 보통은 미리 변환할 필요가 없어요:

```sather
   line ::= #FSTR;
   line := line + 1 + ". " + "Enter" + '!';   -- "1. Enter!"
```

## 줄 바꿈

문자열 안에서 `"\n"`은 줄 바꿈을 뜻해요. 두 글자로 쓰지만 실제로는 한 글자예요.

```sather
   script := script + "Enter" + "\n" + "Exit";
```
