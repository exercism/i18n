# 계약

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| 조항 | 하는 말 | 어겼을 때 누구 잘못인가 |
| --- | --- | --- |
| `pre` | 진입할 때 반드시 성립해야 하는 것 | 호출자 |
| `post` | 반환할 때 성립하는 것 | 루틴 |

둘 다 `BOOL`을 받고, 둘 다 루틴의 인자와 객체의 속성을 사용할 수 있어요. `post`는 반환되는 값인 `result`도 사용할 수 있어요.

## assert

루틴 본문 안에서 `assert`는 그 지점에서 반드시 참이어야 하는 것을 나타내요:

```sather
      assert load <= limit;
```

다른 것들과 같은 스위치로 검사해요.

## 클래스 불변식

클래스는 호출과 호출 사이에 자신의 모든 객체에 대해 참인 어떤 것을 명시할 수 있어요:

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

검사가 켜져 있으면, 모든 public 루틴에 들어갈 때와 나올 때 검사해요.

## 검사 켜기

| 플래그 | 검사하는 것 |
| --- | --- |
| `-chk` | 모든 것: pre, post, assert, 불변식, 범위, 산술 |
| `-chk_no` | 아무것도 |

이 컴파일러에서는 `-chk_pre`만으로는 사전 조건 검사가 켜지지 *않아요*. 실제로 동작하는 것은 `-chk`예요. 위반이 생기면 루틴과 소스 줄을 출력하고 프로그램을 멈춰요. 예외가 아니어서 `protect`가 잡아내지도 못해요.

보통은 `-chk`로 개발하고 테스트한 뒤, 검사 없이 배포해요. 그러면 배포한 프로그램에서는 검사 비용이 들지 않아요. 다만 테스트가 실제로 그 경로들을 지나갈 때만 이득이 있어요.

## 좋은 계약이란

루틴이 무엇을 필요로 하는지 말하고, 어떻게 동작하는지는 말하지 않아요:

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

본문을 그대로 다시 말하는 `post`는 아무것도 가르쳐 주지 않아요:

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## 상속

하위 타입은 `pre`를 약화시키고 `post`를 강화할 수 있어요. 더 많이 받아들이고, 더 많이 약속하는 셈이에요. 하지만 그 반대는 절대 안 돼요. 그랬다가는 상위 타입을 기준으로 작성한 코드가 깨지니까요. 계약이 존재하는 까닭은 바로 이 규칙을 검사할 수 있게 만들기 위해서예요.
