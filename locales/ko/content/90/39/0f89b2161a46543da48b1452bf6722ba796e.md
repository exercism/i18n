# Unison 기초

## 텀과 함수

텀과 함수는 Unison 프로그램을 작성하는 기본 단위예요.

'텀'은 정적 값을 뜻해요. `name = expression`으로 정의하고, 필요하면 `name : MyType` 형태의 타입 시그니처를 앞에 붙일 수 있어요. Unison은 타입 추론을 지원해서, 단순한 정의에서는 타입 시그니처가 생략되기도 해요.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unison 함수는 `myFunctionName argument1 argument2 = myImplementation`처럼 생겼어요. 함수 이름으로 시작하고, 그 뒤에 공백으로 구분된 인자들이 와요.

```
getMax a b = Nat.max a b
```

함수에는 타입 시그니처를 선택적으로 붙일 수 있어요. 오른쪽의 마지막 타입이 항상 함수의 최종 반환 타입이고, 각 인자는 함수 화살표 `->`로 구분해요.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

함수를 호출하려면 함수 이름 뒤에 인자들을 공백으로만 구분해서 쓰면 돼요.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

함수를 호출할 때 Unison은 바로 오른쪽에 오는 것을 인자로 취급하려고 해요. 그래서 항상 원하는 함수 평가 순서가 만들어지지는 않을 수 있어요.

다음 식에서 값 `1`을 얻고 싶다고 해봐요.

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

지금 작성된 대로라면 `shouldBe1`은 `0`으로 평가돼요. 암시적인 함수 적용 순서가 `getMax 1 10`, 즉 `10`이고, 그다음 `10 - 10`, 즉 `0`이기 때문이에요.

괄호를 사용하면 식을 원하는 연산 순서로 다시 묶을 수 있어요.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## 워치 표현식

Unison은 코드를 빠르게 평가할 수 있는 방법인 '워치 표현식'을 제공해요. 워치 표현식은 `>` 기호로 시작하고, 평가할 식이 뒤따라요. 워치 표현식은 `.u` 확장자 파일 어디에나 작성할 수 있어요. 파일을 저장하면 Unison 코드베이스 관리자(UCM) 콘솔에서 식이 어떤 값으로 평가되는지 볼 수 있어요. 이 문서에서는 가능한 한, 워치 표현식으로 평가한 뒤의 예상 출력과 함께 식을 보여드릴게요.

```
> helloThere
  ⧩
  "Hello, World!"
```

## 여러 줄 함수

Unison의 여러 줄 함수는 들여쓰기나 `let` 블록으로 코드 경계, 즉 '렉시컬 스코프'를 정해요.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

같은 들여쓰기 수준에 있는 모든 것은 같은 스코프를 공유해요. 그래서 마지막 줄에서 변수 `newBeginning`을 참조할 수 있는 거예요.

## 네임스페이스와 `use`문

네임스페이스는 Unison 함수를 묶고 정리하는 방법이에요. '디렉터리'와 비슷하다고 생각하면 돼요. 구조와 논리적 그룹화를 제공하죠.

`use`문을 사용하면 네임스페이스의 함수를 스코프로 가져올 수 있어요.

Unison `List` 값을 사용하는 함수를 작성한다고 해봐요. `List.map`과 `List.flatMap` 같은 함수가 필요하다는 걸 알고 있고, 여기서 `List`는 네임스페이스, `map`과 `flatMap`은 함수예요. 반복을 피하려면 다음과 같이 `List` 네임스페이스의 모든 것을 함수의 렉시컬 스코프로 가져올 수 있어요:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

`use List` 줄은 `map`과 `flatMap`에 대한 참조를 명확히 구분해 줘요. [`use`문에 대해 더 알아보기][use-statements]에서 더 읽어볼 수 있어요.

## Unison 표준 라이브러리

Unison의 표준 라이브러리는 `base`라고 불러요. 퀵스타트 가이드를 따라 로컬에 코드베이스를 만들었다면, 표준 라이브러리는 자동으로 다운로드됐을 거예요. [Unison Share][unison-share-base]에서 표준 라이브러리 문서를 온라인으로 살펴볼 수 있어요.

## 주석과 문서 리터럴

Unison의 주석은 조금 특이한 기능이에요. Unison 코드를 작성할 때, `.u` 확장자 파일에서 다음 문법으로 해석되지 않는 텍스트를 만들 수 있어요:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_하지만_ Unison 코드는 파일 시스템의 텍스트 기반 파일이 아니라 추상 구문 트리의 해시로 저장돼요. 그래서 파일에 있는 특정 Unison 함수나 텀을 텍스트로 '장식'하는 주석은 실제로 저장되어 공유를 위해 다시 렌더링될 수 없어요. 다른 사람이 읽고 이해할 수 있도록 Unison 텀에 정보를 저장하고 싶다면 문서 리터럴을 사용할 수 있어요.

문서는 Unison 프로그래밍 언어에서 일급 값이에요. 즉 `Doc` 요소는 값에 할당하거나, 함수에 값으로 전달하거나, 함수의 값으로 반환할 수 있어요. 문서 리터럴 요소는 이중 중괄호로 열고 닫아요. `Doc` 요소를 주석처럼 사용하는 방법은 다음과 같아요.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
