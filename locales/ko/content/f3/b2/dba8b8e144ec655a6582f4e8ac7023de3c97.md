# 지침

레트로 휴대용 콘솔의 채점 시스템 펌웨어를 작성하고 있어요.
기기의 CPU는 그리 빠르지 않고, 점수판 디스플레이는 정해진 주기로 갱신돼요.
화면이 부드럽게 유지되려면, 플레이어가 무엇을 하든 점수 계산 루틴이 예측 가능한 사이클 수 안에서 실행돼야 해요.

풀어야 할 과제는 네 개예요.

~~~~exercism/note
과제의 코드는 분기 없이 작성해야 해요.
조건 점프 대신 `cmovcc`, `setcc`와 산술 연산을 사용해요.
~~~~

## 1. 디스플레이 용량을 넘기지 않고 보너스를 더해요

휴대용 기기의 LCD에서 점수가 표시되는 영역은 십진수 여섯 자리까지 들어가요.
`999999`보다 큰 숫자는 표시할 수 없어요.
보너스 때문에 누적 합계가 그 한도를 넘게 되면, 표시되는 합계는 넘친 부분을 되돌리는 대신 최댓값에 그대로 고정돼요.

현재 합계와 더할 보너스를 받아, `999999`를 넘지 않도록 제한한 새 합계를 반환하는 함수 `add_bonus`를 정의해요.
인자는 순서대로 다음과 같아요:

1. `total`: 현재 점수 합계예요 (`0`과 `999999` 사이).
2. `bonus`: 더할 보너스예요 (항상 0 이상).

반환값은 `total + bonus`가 `999999` 이하이면 그 합이고, 그렇지 않으면 `999999`예요:

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

두 인자와 반환값은 모두 64비트 부호 있는 정수예요.

~~~~exercism/note
`total + bonus`가 64비트 부호 있는 정수를 오버플로하지 않는다고 가정해도 돼요.
~~~~

## 2. 두 점수를 비교해요

휴대용 기기는 저장 파일 안에 플레이어의 최근 최고 점수 몇 개를 담은 작은 순위표를 보관해요.
플레이할 때마다 새 점수가 순위표의 알맞은 위치에 삽입돼요.
정렬 루틴은 두 점수 중 어느 쪽이 앞서는지 물어보고, 그 답을 작은 정수로 받아요.

두 점수를 받아 다음을 반환하는 함수 `compare_scores`를 정의해요:

- 첫 번째 점수가 _더 높으면_ `+1`
- 첫 번째 점수가 _더 낮으면_ `-1`
- 두 점수가 _같으면_ `0`

예시:

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

두 인자와 반환값은 모두 64비트 부호 있는 정수예요.

## 3. 원시 점수를 검증해요

휴대용 기기는 멀티플레이 대결이 끝난 뒤 링크 케이블로 다른 기기와 연결해 점수를 주고받을 수 있어요.
이 케이블은 전기적 잡음이 많아서 들어오는 바이트가 이따금 손상되고, 그러면 허용된 최솟값보다 훨씬 작거나 허용된 최댓값보다 훨씬 큰 값이 나와요.
검증기는 들어오는 각 점수를 나머지 시스템이 보기 전에 허용 범위 안으로 제한해요.

원시 점수와 허용 범위의 경곗값을 받아, `[min, max]` 범위로 제한한 점수를 반환하는 함수 `validate_score`를 정의해요.
인자는 순서대로 다음과 같아요:

1. `score`: 링크 케이블로 받은 원시 점수예요.
2. `min`: 허용되는 가장 작은 점수예요.
3. `max`: 허용되는 가장 큰 점수예요.

반환값은 `score < min`이면 `min`, `score > max`면 `max`, 그 외에는 `score`예요.
`min <= max`라고 가정해도 돼요.

예시:

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

모든 인자와 반환값은 64비트 부호 있는 정수예요.

## 4. 가장 높은 점수 두 개를 추적해요

플레이 세션이 끝날 때마다 휴대용 기기는 저장 파일의 최근 플레이 기록을 훑어서 지금까지 기록된 가장 높은 점수 두 개를 찾아요.
이 기록은 메모리에 있는 64비트 부호 있는 정수의 평범한 배열이에요.
훑기는 배열을 한 번만 순회하면서 두 개의 최댓값을 계속 관리해요. 지금까지 본 것 중 가장 큰 값과 두 번째로 큰 값이에요.

두 값 모두 `0` 이상이어야 한다는 점에 주의해요.
음수는 모두 무시해요.

함수의 첫 번째 버전은 연쇄적인 조건 점프로 작성했어요.
각 후보마다 코드는 그 값이 어디에 들어갈지(첫 번째보다 큰지, 첫 번째와 두 번째 사이인지, 아니면 어디에도 해당하지 않는지) 판단하고, 그에 따라 관리 중인 최댓값들을 옮기면서 음수 결과는 버려요.

이 방식은 잘 동작해요.
그런데 입력값이 무작위라서, 조건 점프마다 분기 예측 실패가 많이 생겨요.
그래서 메인 루프를 분기 없이 다시 작성하기로 했어요.

아래는 분기가 있던 부분을 주석 처리한 함수예요:

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

주석 처리된 부분을 분기 없는 구현으로 바꿔요.
새 코드에서 허용되는 유일한 점프는 배열의 새 원소를 확인하기 위해 루프 시작 지점으로 되돌아가는 점프예요.

이 함수는 반환값이 없고, 분기가 있던 버전과 같은 인자를 받아요:

1. `out`: 함수가 가장 큰 음이 아닌 점수 두 개를 내림차순으로 64비트 부호 있는 정수로 써 넣을 출력 버퍼예요.
2. `array`: 64비트 부호 있는 정수로 이루어진 입력 배열이에요.
3. `length`: 배열의 원소 개수로, 64비트 부호 없는 정수예요.

~~~~exercism/note
배열에 중복된 값이 있고 그 값들이 가장 큰 두 점수라면, 두 출력 자리에 같은 값이 모두 들어갈 수 있어요.
~~~~
