# 개요

재귀 함수는 자기 자신을 호출하는 함수예요.

재귀 함수에는 최소한 하나의 *기저 사례*와 최소한 하나의 *재귀 사례*가 있어야 해요.

*기저 사례*는 함수를 다시 호출하지 않고 값을 반환해요.
*재귀 사례*는 함수를 다시 호출하는데, 언젠가는 기저 사례와 일치하게 되도록 입력을 바꿔서 호출해요.

Elm에서 재귀 함수는 보통 `case` 표현식과 패턴 매칭을 사용해 정의해요.

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

재귀 함수는 기저 사례를 여러 개 가질 수도 있고, 재귀 사례를 여러 개 가질 수도 있어요.
예를 들어 [피보나치 수열][fibonacci]은 기저 사례가 두 개인 재귀 수열이에요:

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

다만 이 구현은 관련된 피보나치 수를 두 번의 독립적인 재귀 호출에서 매번 처음부터 다시 계산하기 때문에 지수적으로 느려요.

리스트에서 주어진 값 `x`가 몇 번 나타나는지 세는 함수에는 재귀 사례가 두 개 있어요:

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## 재귀로 구현하는 반복

불변성 때문에 Elm의 반복문은 명령형 언어와 다르게 작성해요.
예를 들어 반복문은 보통 이렇게 생겼어요:

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

Elm 같은 함수형 언어에서는 변수를 변경할 수 없어요.
그래서 반복문은 재귀로 구현해야 해요.

Elm에서 `for`문에 해당하는 것은 이렇게 생겼어요:

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

실제로 Elm에서 리스트나 다른 자료 구조를 순회할 때는 [`List`][module-list] 모듈의 `List.map`, `List.filter`, `List.foldl` 같은 함수를 가장 많이 사용해요.
내부적으로 이런 함수들은 재귀로 구현되어 있어요.

## 무한 실행

재귀 함수를 잘못 구현하거나 재귀 호출 횟수가 너무 많으면 결과를 끝내 반환하지 못할 수 있어요.
함수가 호출될 때마다 런타임이 결과를 반환해야 할 위치([호출 스택][wiki-call-stack])에 대한 참조가 메모리에 저장되기 때문에 이는 문제가 될 수 있어요.
재귀 함수가 자신을 너무 많이, 심지어 무한히 호출하면 메모리가 부족해져서 런타임이 충돌할 수 있어요([스택 오버플로 오류][wiki-stack-overflow]).
Elm의 런타임은 재귀와 안정성을 위해 최적화되어 있지만, 무한 재귀는 여전히 문제를 일으킬 수 있어요.

이런 무한 실행 문제는 다음과 같은 경우에 생겨요:

- 기저 사례를 구현하는 것을 잊었을 때.
- 패턴 매칭에서 가능한 모든 경우를 처리하지 않았을 때.
- 재귀 호출을 할 때 인자를 제대로 바꾸지 않아서 기저 사례에 끝내 도달하지 못할 때.
