# 맵과 집합

| 타입 | 담는 것 | 찾는 기준 |
| --- | --- | --- |
| `ARRAY{T}` | 순서가 있는 값 | 위치 |
| `FMAP{K,T}` | 키와 타깃 쌍 | 키 |
| `FSET{T}` | 중복 없는 값 | 포함 여부 |

## FMAP

```sather
   m ::= #FMAP{STR,INT};
   m := m.insert("emu", 2);
   m.get("emu")          -- 2
   m.has_ind("emu")      -- true
   m.size                -- 1
   m := m.delete("emu");
```

`m["emu"]`는 맵을 읽는 방법이 **아니에요**. `FMAP`에는 그런 루틴이 없고, 이 줄은 컴파일되지 않아요. 값을 읽을 때는 `get`을 써요.

### 없는 키

없는 키에 `get`을 쓰면 오류를 내는 대신 그 타입의 빈 값을 돌려줘요. `0`, `false`, 또는 void예요. void인 `STR`은 만들어지는 자리에서는 실패하지 않아요. 나중에 그 값이 실제로 쓰이는 곳에서 실패해요. 먼저 `has_ind`로 확인하는 습관을 들이는 게 좋아요.

## FSET

```sather
   s ::= #FSET{STR};
   s := s.insert("emu");
   s.has("emu")          -- true
   s.size                -- 1
   s := s.delete("emu");
```

집합은 이렇게 조합해요:

```sather
   a.union(b)            -- in either
   a.intersect(b)        -- in both
   a.difference(b)       -- in a but not b
   a.is_subset(b)
```

## 다시 대입하기와 복사하기

`insert`와 `delete`는 앞으로 사용할 컨테이너를 돌려줘요. 보통은 같은 객체가 그 자리에서 바뀐 것이고, 커져야 할 때는 더 큰 새 객체예요. 그래서 항상 이렇게 써요:

```sather
   m := m.insert(k, v);     -- always
```

이후에는 왼쪽의 이름만 믿을 수 있어요. 같은 맵을 가리키던 다른 이름을 `insert` 전에 따로 가져다 두었다면, 그 이름은 낡은 것을 가리킬 수 있어요.

독립된 복사본을 남기려면 먼저 복사해야 해요:

```sather
   n ::= m.copy.insert(k, v);      -- m is unchanged
```

다만 한 가지 주의할 점이 있어요. 한 번도 `insert`한 적이 없는 맵은 **void**이고, void 맵에 `copy`를 쓰면 실패해요. `insert`, `get`, `has_ind`, `size`는 모두 void 맵을 다룰 수 있어요. `#FMAP{K,T}`는 void이고, 여기에 `insert`하는 것이 맵이 처음 만들어지는 방법이에요. 하지만 `copy`는 안 돼요.

`HMAP`과 `HSET`은 항상 그 자리에서만 바뀌는 버전이에요. 큰 것을 만들 때는 더 빠르지만, 배우는 동안에는 기본으로 삼기엔 적절하지 않아요.

## 순회하기

| 반복자 | 주는 것 |
| --- | --- |
| `m.ind!` | 각 키 |
| `m.target!` | 각 타깃 |
| `m.pair!` | 키와 타깃을 함께 |
| `s.elt!` | 집합의 각 값 |

맵과 집합에는 순서가 없어요. 실행할 때마다 순회 순서가 다를 수 있으니, 무엇이 먼저 오는지에 의존하는 코드는 절대 쓰지 마세요.

```sather
   loop
      #OUT + guide.ind! + "\n";
   end;
```
