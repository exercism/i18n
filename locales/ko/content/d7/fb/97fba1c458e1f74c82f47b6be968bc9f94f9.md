# 소개

대부분의 스칼라 비트 연산에는 패킹된 변형이 있어요.
이들은 SIMD 정수 연산과 같은 일반적인 문법을 따르지만, 크기 접미사는 없어요:

| 명령어 | 설명 |
|-------------|-----------------------------------|
| `pand`      | 두 128비트 값의 비트 단위 AND |
| `por`       | 두 128비트 값의 비트 단위 OR  |
| `pxor`      | 두 128비트 값의 비트 단위 XOR |

패킹된 `NOT`은 없다는 점에 유의해요.
하지만 ANDN 연산이 있는데, 이 연산은 **목적지** 피연산자의 모든 비트를 반전시킨(보수) 다음, 두 피연산자 사이의 AND를 계산해요.
NOT과 AND를 결합한 것으로 생각할 수 있어요:

| 명령어 | 설명 |
|-------------|-----------------------------------------------------------------|
| `pandn`     | **보수화된** 목적지와 소스의 비트 단위 AND |

비트 연산은 서로 다른 두 피연산자의 같은 위치에 있는 비트끼리 결합하므로, 레인 경계가 결과를 바꿀 수 없다는 점에 유의해요.
그래서 이 명령어들에는 크기 접미사가 없고, 레지스터는 하나의 128비트 레인처럼 동작해요:

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
이 개념의 모든 명령어는 비트를 계산할 뿐, 플래그는 설정하지 않아요.
패킹된 값을 사용하는 조건문은 이후 개념에서 다뤄요.
~~~~

## 레인별 시프트

시프트는 순수한 비트 연산과 달리 비트를 다른 위치로 이동시키므로, 경계를 정하기 위해 레인 크기가 필요해요.
각 레인 안에서는 스칼라 대응 연산과 똑같이 동작하고, 비트가 한 레인에서 이웃 레인으로 넘어가는 일은 없어요:

| 명령어               | 설명                         |
|---------------------------|-------------------------------------|
| `psllw`, `pslld`, `psllq` | 레인별 논리 왼쪽 시프트        |
| `psrlw`, `psrld`, `psrlq` | 레인별 논리 오른쪽 시프트       |
| `psraw`, `psrad`          | 레인별 산술 오른쪽 시프트    |

이 명령어들은 크기 접미사를 포함해 패킹된 정수 연산의 문법을 따른다는 점에 유의해요.
바이트 레인 시프트는 없고, 워드와 dword, 그리고 산술 오른쪽 시프트를 제외하면 qword만 있어요.

패킹된 시프트와 스칼라 대응 연산의 차이 중 하나는 연산 이름에 있어요:

- `shl`과 `shr` 대신, **s**hift **l**eft(**r**ight) **l**ogical을 뜻하는 `sll`과 `srl`이 있어요.
- `sar` 대신, **s**hift **r**ight **a**rithmetic을 뜻하는 `sra`가 있어요.

이름은 다르지만 연산 자체는 같아요:

- 논리 오른쪽 시프트는 최상위 비트들을 0으로 채워요.
  부호 없는 수를 2의 거듭제곱으로 나눈 것과 같아요.
- 산술 오른쪽 시프트는 최상위 비트들을 부호 비트의 값으로 채워요.
  부호 있는 수를 2의 거듭제곱으로 나누되 음의 무한대 방향으로 반올림한 것과 같아요.
- 왼쪽 시프트는 항상 0으로 채워요(그래서 산술 왼쪽 시프트가 필요 없어요).

시프트 횟수는 모든 레인에서 동일해요.
즉시값이거나 `xmm` 레지스터의 하위 64비트일 수 있어요:

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
레인 너비보다 큰 시프트 횟수는 스칼라 `shl`/`shr` 계열처럼 순환하지 않아요.
그냥 0을 만들어요(산술 오른쪽 시프트의 경우에는 부호 비트가 모두 채워져요).
~~~~

## 부동소수점 비트 연산

각 비트 연산 명령어에는 부동소수점 이름을 가진 쌍둥이 명령어도 있어요. 지금까지 본 패킹된 부동소수점 연산과 같은 문법을 따라요:

| 정수 이름 | 부동소수점 이름          |
|--------------|----------------------|
| `pand`       | `andps`, `andpd`     |
| `pandn`      | `andnps`, `andnpd`   |
| `por`        | `orps`, `orpd`       |
| `pxor`       | `xorps`, `xorpd`     |

비트 연산은 비트 자체를 다루므로, 실제로는 정수 연산과 부동소수점 연산이 같은 결과를 계산해요.
이름이 다른 데에는 두 가지 이유가 있어요:

1. 의도를 문서화하기 위해서예요. 복사하는 바이트의 성격에 따라 `movdqa`, `movaps`, `movapd` 중 하나를 선호하는 것과 같은 이치예요.
2. 정수 연산과 부동소수점 연산은 실행 도메인이 다른 경우가 많아요.
   같은 실행 도메인 안에 있는 연산들은 보통 더 빠르게 이어서 실행할 수 있어요.

부동소수점 값에는 시프트 연산이 없어요.

## 부동소수점 비트 표현

IEEE 부동소수점 수의 비트 표현은 정수와 아주 달라요.

부호 없는 정수에서 각 비트는 모두 같은 의미를 가져요. 즉 비트 인덱스에 해당하는 2의 거듭제곱을 나타내요.
정수의 값은 1로 설정된 비트들에 해당하는 2의 거듭제곱들의 합이에요.
그래서 비트를 시프트하면 수를 2의 거듭제곱으로 곱하거나 나눌 수 있어요. 각 설정된 비트의 인덱스를 바꾸는 것뿐이니까요.

부호 있는 정수에서는 대부분의 비트가 부호 없는 정수와 같은 방식으로 해석돼요.
하지만 최상위 비트는 특별해요.
이 비트가 1이면, 다른 비트들에 더하는 대신 해당하는 2의 거듭제곱을 빼야 하고, 그 결과 음수가 돼요.
실제로 수의 부호를 바꾸려면 개념적으로 두 단계가 필요해요. 모든 비트를 뒤집고(`not`), 그 결과에 1을 더하는 것(`inc`)이에요.

부동소수점 수의 비트들은 의미가 균일하지 않고, 위치에 따라 아주 다른 방식으로 해석해야 해요:

| 필드    | 인덱스(32비트) | 인덱스(64비트) |
|----------|------------------|------------------|
| 부호     | 31               | 63               |
| 지수 | 30-23            | 62-52            |
| 가수 | 22-0             | 51-0             |

결과 수는 `(-1)^sign * 1.fraction * 2^(exponent - bias)`로 계산해요.
바이어스는 정밀도에 따라 달라져요:

| 크기   | 바이어스 |
|--------|------|
| 32비트 | 127  |
| 64비트 | 1023 |

두 형식 모두에서 수의 부호는 오로지 부호 비트에 의해서만 결정돼요.
부동소수점 수의 부호를 바꾸려면 이 비트만 뒤집으면 돼요(XOR 연산).
절댓값을 구하려면 이 비트만 0으로 지우면 돼요(해당 비트를 지우는 AND 연산):

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

이 비트 표현에서는 비트를 시프트해도 예측 가능하고 균일한 결과가 나오지 않는다는 점에 유의해요.
가수가 지수로 "흘러넘칠" 수 있고, 지수가 부호로 넘어갈 수 있어요.

하지만 표현의 각 부분을 따로 떼어내어 연산하는 것이 편리할 때도 있어요.

예를 들어 지수의 비트들은 바이어스를 빼기 전에 먼저 부호 없는 수로 해석해야 해요.
이 말은 곧, 해당 부동소수점 형식에서 어떤 2의 거듭제곱에 대응하는 비트 표현을 가진 32비트 또는 64비트 정수를 만들 수 있다는 뜻이에요.
그다음 이 원시 비트 표현을 사용해 다른 부동소수점 수를 곱하거나 나눌 수 있어요.

예를 들면 이래요:

```x86asm
mov eax, 210             ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23              ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax           ; we move the raw bits to xmm0
mulss xmm1, xmm0         ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

반대로, 지수 비트만 1이고 나머지는 모두 0인 마스크와 AND 연산을 하면 패킹된 부동소수점 수들의 지수를 추출할 수 있어요.
여기에 시프트와 뺄셈을 더하면, 각 레인의 바이어스가 제거된 지수를 부호 있는 정수로 얻을 수 있어요:

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
부동소수점 수의 원시 비트를 다루는 것은 어떤 상황에서는 유용하지만 주의해서 해야 해요.
지수 필드에 더하거나 빼는 것은 오버플로나 언더플로가 없고 입력 수가 정규 수일 때만 안전해요.
또한 `0.0`의 지수 필드에 유효한 `x`를 더하면 `0.0 * 2^x`가 아니라 `2^(x - bias)`가 돼요.
~~~~
