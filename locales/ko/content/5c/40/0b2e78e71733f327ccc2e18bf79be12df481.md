# Introduction

## 오류

오류는 언제든 생길 수 있어요. Elixir에서는 흔히 "그냥 크래시 나게 두자"라고 말하지만, 소프트웨어 계약을 지키기 위해 함수 호출을 복구해서 알려진 정상 상태로 되돌려야 할 때도 있어요. 어떤 언어에서는 오류를 제어 흐름의 수단으로 사용하기도 하지만, Elixir에서는 이런 방식을 권장하지 않아요. 오류를 발생시킬 수 있는 함수는 이름만 봐도 알아볼 수 있는 경우가 많아요. 오류를 발생시키는 함수는 이름 끝에 `!`가 붙어요. 이는 `{:ok, value}`나 `:error`를 반환하는 함수와 대비돼요. 라이브러리 예제를 살펴봐요:

```elixir
Map.fetch(%{a: 1}, :b)
# => :error
Map.fetch!(%{a: 1}, :b)
# => raises KeyError
```

## Try/Rescue

Elixir는 `try .. rescue`를 이용해 오류를 복구하는 구문을 제공해요.

```elixir
try do
  raise RuntimeError, "error"
rescue
  e in RuntimeError -> :error
end
```

이 구문을 하나씩 살펴봐요:

- **1번 줄**에서는 `try`로 블록을 선언해요.
- **2번 줄**에는 오류가 발생할 수 있는 함수 호출이 들어가요. 여기서는 `raise/2`를 호출하고 있어요.
- **4번 줄**에서는 `rescue` 절에서 발생한 오류의 _모듈_ 이름을 패턴 매칭해요.
  - `->`의 왼쪽에서는:
    - `e`가 오류 구조체와 매칭돼요.
    - `in`은 키워드예요.
    - `RuntimeError`는 복구하려는 오류예요.
      - 모든 오류를 복구하고 싶다면 모듈 이름 대신 `_`를 쓰거나 `in` 키워드를 아예 생략할 수 있어요.
  - 오른쪽에서는:
    - 오류가 매칭될 때 실행할 명령이에요.

### 오류 구조체

이렇게 복구한 오류(때로는 "예외"라고도 불러요)는 구조체예요.
Elixir에서 오류를 복구하는 일은 아주 드물게 일어나요.
보통은 복구한 오류를 로그로 남기거나 외부 모니터링 서비스로 보낸 뒤, 다시 발생시켜요.
그래서 특정 오류 구조체의 내부 구조에는 보통 관심을 두지 않아요.

[예외 개념][exercism-exceptions]에서 오류 구조체에 대해 더 자세히 배우게 돼요. 직접 오류를 정의하는 방법도 함께 다뤄요.

[exercism-exceptions]: https://exercism.org/tracks/elixir/concepts/exceptions
