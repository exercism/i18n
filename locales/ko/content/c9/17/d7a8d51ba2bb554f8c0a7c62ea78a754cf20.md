# 배열

`LIST{T}`는 크기를 늘릴 수 있는 순서 있는 컬렉션이에요. 내부는 배열로 되어 있고, 꽉 차면 더 큰 배열로 바뀌어요.

```sather
   notes ::= #LIST{STR};
   notes.append("muddy boots");
   notes[0]                     -- "muddy boots"
   notes[0] := "clean boots";
   notes.size
   notes.is_empty
   notes.has("clean boots")
   notes.remove_index(0);
```

## `ARRAY{T}` 아니면 `LIST{T}`?

| | `ARRAY{T}` | `LIST{T}` |
| --- | --- | --- |
| 크기 | 만들 때 고정돼요 | 달라져요 |
| 덧붙이기 | 안 돼요 | 돼요 |
| 제거 | 안 돼요 | 돼요 |
| 인덱싱 | `a[i]` | `l[i]` |
| 오버헤드 | 없어요 | 크기와 여유 공간 |

크기가 정해져 있고 바뀌지 않을 때는 `ARRAY`를 써요. 무용수 한 줄이라든지, 일주일치 개수처럼요. 뭔가가 들어오거나 나갈 때는 `LIST`를 써요.

## 제자리에서 바뀌어요, 함수형이 아니라

`append`, `remove_index`, `[i] :=` 같은 것들은 모두 배열 자체를 바꿔요. 되돌려서 다시 대입할 필요가 없고, 루틴에 넘긴 배열도 이런 변화에서 안전하지 않아요.

이건 `FMAP`, `FSET`과는 정반대예요. 지금 손에 쥔 게 어느 쪽인지 분명히 해두면 좋아요. 경험상 이름 앞에 `F`가 붙으면 함수형이고, 나머지는 모두 제자리에서 바뀌어요.

아무것도 망칠 수 없는 배열을 건네주려면, 복사본을 넘겨요:

```sather
   return notes.copy;
```

## 덧붙이는 비용

덧붙이기는 평균적으로 비용이 적게 들어요. 내부 배열이 꽉 차면, 두 배 크기의 새 배열을 마련해서 내용을 전부 복사해요. 그래서 대부분의 덧붙이기는 거의 비용이 들지 않고, 이따금 한 번씩은 복사 비용이 들어요. 덧붙이기를 아주 여러 번 하면 평균적으로 한 번당 상수 시간이 되는데, 그래서 매번 하나씩 늘리는 대신 두 배로 늘리는 거예요.

`remove_index`는 비용이 적지 않아요. 지운 위치 뒤에 있는 요소가 모두 한 칸씩 앞으로 당겨져요. 긴 배열의 맨 앞에서 자꾸 지우면, 알아채기 어려운 식으로 느려져요.

## 유용한 루틴

| 호출 | 하는 일 |
| --- | --- |
| `l.append(x)` | 끝에 더해요 |
| `l.insert_before(i, x)` | 특정 위치에 더해요 |
| `l.remove_index(i)` | 특정 위치의 요소를 빼요 |
| `l.has(x)` | 들어 있나요? |
| `l.copy` | 독립된 복사본 |
| `l.str` | 중괄호로 감싼 내용 |
| `l.elt!`, `l.ind!` | 값이나 위치를 차례로 순회해요 |
