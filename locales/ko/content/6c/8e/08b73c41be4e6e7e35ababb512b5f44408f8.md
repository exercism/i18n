# 개요

함수는 자기 자신을 호출할 때 [재귀적][recursion]이라고 해요.

함수 호출과 루프의 중요한 차이 하나는, 함수를 호출하면 반환될 주소를 스택에 푸시한다는 점이에요. 그래서 재귀 함수는 보통 같은 동작을 하는 루프보다 스택 공간을 더 많이 차지해요.

그 결과, 자기 자신을 계속 호출하는 함수는 결국 스택 공간을 모두 소진할 수도 있어요. 이것을 [스택 오버플로][stack-overflow]라고 해요.

이 때문에 모든 재귀 함수에는 베이스 케이스가 적어도 하나 있어야 해요. 베이스 케이스란 함수가 자기 자신을 호출하지 않고 반환하는 상황을 말해요. 모든 재귀 호출은 결국 베이스 케이스에 도달해야 해요.

예를 들어, 팩토리얼 함수 `n! = n * (n - 1) * ... * 1`은 `1`을 베이스 케이스로 두고 재귀적으로 정의할 수 있어요.

```x86asm
factorial:
    ; the argument `n` is passed on `rdi`
    ; the factorial will be returned on `rax`

    cmp rdi, 1
    jle .base_case     ; base case -> if rdi <= 1, return 1

    push rdi           ; save n
    dec rdi            ; rdi = n - 1
    call factorial     ; recursive call, rax = (n - 1)!
    pop rdi            ; restore n
    imul rax, rdi      ; rax = n * (n - 1)! = n!
    ret
.base_case:
    mov rax, 1
    ret
```

`factorial`은 재귀 호출 전에 `push rdi`를 하고, 호출이 끝난 뒤에 `pop rdi`를 해야 한다는 점에 주목해요. 재귀 호출이 반환된 뒤에도 `n * (n-1)!`을 계산하려면 여전히 `n`이 필요하기 때문이에요.

피호출자 보존 레지스터를 사용한다고 해서 이 문제가 해결되지는 않아요.

재귀 함수는 자기 자신을 호출할 수도 있는 호출자이지만, 동시에 다른 어떤 함수의 피호출자이기도 해요. 그러므로 함수는 피호출자 보존 레지스터를 사용하기 전에 그 값을 보존하고, 사용한 뒤에는 값을 복원해야 해요. 이전 개념에서 살펴본 것처럼, 보통 `push`/`pop` 순서로 이 작업을 해요.

베이스 케이스를 제외한 재귀 함수의 각 프레임은 자신의 지역 변수를 보존해야 하는 호출자이기도 하므로, 이 `push`/`pop` 순서는 프레임마다 반복되어야 해요. 레지스터를 사용하지 않고 변수를 스택에 바로 저장하더라도 프레임마다 똑같이 `8`바이트가 들어요.

즉, 재귀 호출이 있을 때마다 `call`이 푸시하는 반환 주소를 위해 스택에 `8`바이트가 더해지고, 저장해야 하는 지역 변수마다 `8`바이트가 더해져요. 함수는 베이스 케이스에 도달할 때까지 프레임마다 이 바이트를 스택에 계속 쌓아요. 그제서야 반대 순서로 되감기 시작하는데, 각 재귀 호출은 필요한 만큼 `pop`을 하고 `ret`를 실행해요.

예를 들어 `factorial`을 인자 `10`으로 호출하면, 베이스 케이스인 `1`에 도달하기 전까지 자기 자신을 아홉 번 호출해요. 그 시점에는 이전 프레임마다 `n`(`8`바이트)과 반환 주소(`8`바이트)를 저장하는 데 `144`바이트가 사용된 상태예요.

## 꼬리 호출

어떤 상황에서는 함수가 다른 함수를 호출한 뒤 반환하기 전에 더 이상 아무 작업도 하지 않아요.

예를 들어 다음을 봐요.

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    call times_three
    ret
```

`triple_of_square` 함수는:

- 전달받은 인자(`rdi`에 있는 값)를 자기 자신과 곱해서 제곱을 구해요.
- 그런 다음 `times_three`를 호출하는데, 이 함수는 전달받은 인자에 3을 곱한 값을 반환해요.

그 결과 `triple_of_square`는 `3*x²`를 반환하는데, 여기서 `x`는 `rdi`로 전달된 인자예요.

`times_three`를 호출한 뒤에는 `triple_of_square`에서 아무 작업도 하지 않고 그냥 반환한다는 점에 주목해요. 이런 상황에서는 `call`을 사용하는 대신 `jmp`로 실행을 호출된 함수로 넘길 수 있어요.

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    jmp times_three
```

이것을 [꼬리 호출][tail]이라고 해요.

꼬리 호출의 가장 큰 장점은 `call`의 추가 비용을 피할 수 있다는 점이에요. `call`은 반환 주소를 스택에 푸시하고, 제어가 그 지점으로 돌아오려면 짝을 이루는 `ret`가 있어야 해요.

꼬리 호출은 둘 다 건너뛰어요. 푸시할 반환 주소도 없고, 짝을 이룰 추가 `ret`도 없이 호출된 함수 자체의 `ret`만 있어요.

## 꼬리 재귀

꼬리 호출은 반환하기 전에 자기 자신을 여러 번 호출할 수 있는 재귀 함수에 특히 유용해요. 하지만 모든 재귀 호출을 꼬리 호출로 바로 바꿀 수 있는 것은 아니에요. `jmp`는 제어를 호출된 함수로 넘기기 때문에, 호출자는 꼬리 호출 이후에 더 이상 아무 작업도 할 수 없어요.

예를 들어, 앞에서 본 `factorial` 함수는 꼬리 재귀가 **아니에요**. 재귀 호출 뒤에도 `imul rax, rdi`를 사용해서 결과에 현재 `n`을 곱해야 하거든요.

이런 상황에서는 중간 계산 결과를 모아 두었다가 마지막에 반환하는 누산기를 사용할 수 있을 때도 있어요. 예를 들어, 대부분의 작업을 처리하는 `factorial_helper`를 정의하고, `factorial`이 누산기를 준비한 뒤 `factorial_helper`로 제어를 넘길 수 있어요.

```x86asm
factorial_helper:
    ; the argument `n` is passed on `rdi`
    ; `rax` is used as an accumulator and will be returned at the end

    cmp rdi, 1
    jle .base_case

    imul rax, rdi        ; we accumulate the partial result on `rax`
    dec rdi              ; rdi = n - 1
    jmp factorial_helper ; tail call to accumulate (n - 1)!
.base_case:
    ret                  ; returns the factorial already accumulated on `rax`

factorial:
    mov rax, 1           ; initial value for the accumulator
    jmp factorial_helper ; tail call
```

재귀 호출 뒤에 더 이상 하는 작업이 없으므로, 이제 `rdi`를 저장할 필요도 없어요. `call`도 `push rdi`도 없어서 재귀를 한 번 반복할 때마다 스택에 `0`바이트가 더해져요. 즉 추가 스택 공간이 전혀 사용되지 않아요. 이 버전은 스택이 넘치지 않으면서 아무리 큰 `n`도 처리할 수 있어요. 더 효율적이면서 더 안전해요.

어떤 경우에는 함수의 순서를 바꾸면 헬퍼로 가는 `jmp`조차 피할 수 있어요. 예를 들어, `factorial`과 `triple_of_square`를 이렇게 다시 쓸 수 있어요.

```x86asm
factorial:
    mov rax, 1
factorial_helper:
    cmp rdi, 1
    jle .base_case

    imul rax, rdi
    dec rdi
    jmp factorial_helper
.base_case:
    ret

triple_of_square:
    imul rdi, rdi
times_three:
    imul rax, rdi, 3
    ret
```

위 코드 조각에서 `factorial`의 실행은 `factorial_helper`로 자연스럽게 이어져요. `triple_of_square`와 `times_three`도 마찬가지예요. 두 경우 모두 실행이 순차적으로 이어져서, 꼬리 함수가 "메인" 함수 안의 지역 레이블에 불과한 것처럼 보여요.

사실 어떤 지역 레이블과 함수 사이에는 본질적인 차이가 없어요. x86-64 어셈블리는 어느 쪽에도 특별한 대우를 하지 않아요. 둘은 그저 `section .text` 같은 실행 가능한 코드가 담긴 섹션 안의 주소일 뿐이에요.

이렇게 보면 꼬리 재귀 함수는 재귀 호출이 맨 위로 다시 점프하고 베이스 케이스가 루프를 끝내는 조건이 되는 루프와 본질적으로 같다고 생각할 수 있어요.
