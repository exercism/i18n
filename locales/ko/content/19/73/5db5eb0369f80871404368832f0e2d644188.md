# 소개

실라버스에서 여기까지 오면서 함수 정의를 정말 많이 봐 왔어요. 보통은 REPL에 표시되는 출력에 대한 설명 없이 지나갔죠:

```julia-repl
julia> f(x) = x^2
f (generic function with 1 method)
```

왜 _generic function with 1 method_라고 나올까요?

인자 타입을 좀 더 구체적으로 지정하고 싶다고 해봐요.

```julia-repl
julia> f(x::Integer) = x^2
f (generic function with 2 methods)

julia> f(x::Real) = x^2
f (generic function with 3 methods)
```

아니면 인자의 개수를 바꿀 수도 있어요:

```julia-repl
julia> f(x, y) = x * y
f (generic function with 4 methods)
```

같은 함수에 대한 새로운 정의는 "메서드"라고 부르는 것 같아요.
메서드는 기존 정의를 덮어쓰지 않고 목록에 추가돼요.

메서드 목록은 쉽게 확인할 수 있어요:

```julia-repl
julia> methods(f)  # output edited for brevity
# 4 methods for generic function "f" from Main:
 [1] f(x, y)
 [2] f(x::Integer)
 [3] f(x::Real)
 [4] f(x)
 ```

함수 `f`를 호출하면 Julia는 어떤 메서드를 써야 할지 어떻게든 알아내요:

```julia-repl
julia> f(2.5)  # Float64
6.25

julia> f(2)  # Int64
4

julia> f(2, 3)  # Int64, Int64
6
```

## 함수란 무엇일까요?

[매뉴얼][function]에 따르면, 함수는 인자로 이루어진 튜플을 반환값으로 대응시키는 객체예요.
수학자들이 쓰는 정의와 비슷하죠.

우리는 보통 `f(2, 3)`의 함수 인자를 서로 별개의 두 항목으로 생각하지만, 컴파일러는 이를 하나의 [튜플][tuple]로 봐요.
인자가 하나뿐일 때도 마찬가지예요. (다만 이를 분명히 하려면 쉼표를 붙여야 하죠.)

```julia-repl
julia> typeof( (2, 3) )
Tuple{Int64, Int64}

julia> typeof( (2,) )
Tuple{Int64}
```

함수를 블랙박스로 보면, 튜플이 들어가고 반환값이 나온다고 말할 수 있어요.
더 엄밀히 말하면, 튜플은 반환값으로 _대응_돼요.

## 함수는 인자의 개수와 타입이 다를 때 어떻게 처리할까요?

이런 것을 보통 ["다형성"][polymorphism]이라고 해요.

이 주제는 수십 년 동안 컴퓨터 과학의 큰 화두였고, 여러 가지 접근 방식이 채택되어 왔어요.

Julia의 접근 방식은 독특하지만, 유일한 것은 아니에요.

- 함수는 ["제네릭"][generic]해서, 여러 메서드를 붙일 수 있어요.
- 함수는 메서드가 붙기 전까지는 그저 이름일 뿐이에요.
- 메서드는 필요할 때마다 추가할 수 있고, 그 수가 아주 많아질 수도 있어요 (현재 `+` 연산자는 161개의 메서드를 가진 함수예요).
- 함수가 호출되면, Julia는 호출 시그니처를 살펴봐요. 즉, 인자의 개수와 각 인자의 현재 타입이죠.
- 호출 시그니처에 가장 잘 맞는 메서드가 선택돼요.
  - 일반적으로 인자의 개수는 정확히 일치해야 해요 (다만 [splat/slurp][splat] 연산자 `...`로 이 규칙을 부분적으로 우회할 수 있어요).
  - 호출 시그니처와 타입이 정확히 일치하는 메서드가 우선돼요.
  - 필요하다면 Julia는 호출 시그니처에 있는 각 인자의 상위 타입까지 살펴서, 가장 잘 맞고 가장 구체적인 메서드를 찾아요.
- 선택된 메서드는 주어진 인자와 함께 [`dispatched`][dispatch]되고, 결과를 반환해요.
- 적합한 메서드를 찾지 못하면 [`MethodError`][methoderror]가 발생해요.

Julia는 동적 타입 언어라서, 메서드 디스패치가 _런타임_에 일어난다는 점에 유의해요.

## 다중 디스패치: 예제

앞 절은 말이 너무 많았으니, 이번엔 그 개념을 코드로 옮겨 봐요.
간단히 하기 위해 아래 함수들은 인자가 하나뿐이지만, 수십 개의 인자를 가진 함수(예를 들어 그래프 패키지나 머신러닝에서)도 흔히 볼 수 있어요.

먼저 도형을 나타낼 사용자 정의 타입 몇 개를 정의해 봐요.

```julia-repl
julia> abstract type Shape end

julia> struct Circle <: Shape
           radius::Float64
       end

julia> struct Square <: Shape
           side::Float64
       end

julia> struct Rectangle <: Shape
           length::Float64
           width::Float64
       end
```

다음으로 각 도형의 넓이를 계산하는 메서드를 정의할 수 있어요.
각 메서드는 인자를 하나씩 받는데, 경우마다 서로 다른 구체적인 사용자 정의 타입을 받아요.

```julia-repl
julia> area(c::Circle) = π * c.radius^2
area (generic function with 1 method)

julia> area(s::Square) = s.side^2
area (generic function with 2 methods)

julia> area(r::Rectangle) = r.length * r.width
area (generic function with 3 methods)
```

이제 도형 몇 개를 만들고 넓이를 계산해 봐요. 각 도형에 맞는 공식을 골라 주는 Julia의 디스패치 메커니즘에 맡기면 돼요.

```julia-repl
julia> circle = Circle(2.3)
Circle(2.3)

julia> area(circle)  # call signature Tuple{Circle}
16.619025137490002

julia> square = Square(1.6)
Square(1.6)

julia> area(square)  # call signature Tuple{Square}
2.5600000000000005

julia> rectangle = Rectangle(1.4, 2.1)
Rectangle(1.4, 2.1)

julia> area(rectangle)  # call signature Tuple{Rectangle}
2.94
```

## [파라메트릭 메서드][parametric]

메서드 시그니처는 파라메트릭 타입과 거의 같은 방식으로 더미 타입 값을 받을 수 있어요.

문법이 독특한데, `where` 절이 필요해요:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T} = true
same_type (generic function with 1 method)

julia> same_type([1, 2], 3)
true

julia> same_type([1, 2], "three")
ERROR: MethodError: no method matching same_type(::Vector{Int64}, ::String)
```

위 예제는 두 인자가 같은 타입 `T`를 쓰도록 요구해요. `T`가 무엇이든 말이죠.

`T`에 제약을 걸어 더 구체적으로 만들 수도 있어요:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T<:Number} = true
same_type (generic function with 2 methods)
```

이 메서드에서는 숫자 타입이 서로 같을 때만 `true`를 반환해요.

더미 변수는 여러 개를 쓸 수 있고, `where` 절에서 쉼표로 구분해요.
다음 두 메서드는 비슷해 보여요:

```julia-repl
julia> func(v::Vector{Number}, x::Number) = true
func (generic function with 1 method)

julia> func(v::Vector{S}, x::T) where {S<:Number, T<:Number} = true
func (generic function with 2 methods)
```

한 가지 차이는 두 번째 메서드에서는 타입 값 `S`와 `T`를 함수 본문 안에서 사용할 수 있다는 점이에요.
자주 쓰지는 않을 법한 요령이지만, 어떤 상황에서는 많은 수고를 덜어 줄 수 있어요.

예를 들어 다음 파라메트릭 타입 정의에서 필드들은 같은 타입 `T`여야 하는데, `T`는 `Real`의 서브타입으로 제약돼 있어요:
```julia
struct Point{T<:Real}
    x::T
    y::T
end
```
이 `Point` 정의는 같은 타입의 `x`와 `y`를 받거나, 서로 다른 타입의 `x`와 `y`도 받을 수 있어요. 다만 후자의 경우에는 변환 타입을 명시적으로 제공해야 해요.
```julia-repl
julia> Point(4, 5)
 Point{Int64}(4, 5)

julia> Point(3.5, 2)
 MethodError: no method matching Point(::Float64, ::Int64)    # Output truncated for brevity

julia> Point{Float32}(3.5, 2)
 Point{Float32}(3.5f0, 2.0f0)

julia> Point{Int64}(3.5, 2) 
 InexactError: Int64(3.5)      # Output truncated for brevity
```
이 정도로 타입을 세밀하게 제어하는 게 바람직할 수도 있지만, 약간의 추상화가 도움이 될 때도 있어요.
```julia
Point(x::T, y::S) where {T<:Real, S<:Real} = Point{promote_type(T,  S)}(x, y)
```
이 외부 생성자는 `x`와 `y`에 서로 다른 타입을 허용하면서도 변환 타입을 명시적으로 지정할 필요가 없게 해 줘요.
타입 값 `T`와 `S`는 함수 본문에서 `promote_type(T, S)`에 쓰여, 원래 정의에 필요한 명시적인 변환 타입을 제공해요.
```julia-repl
julia> Point(3.5, 2)
 Point{Float64}(3.5, 2.0)
```

## 다른 언어와의 비교

Julia는 메서드를 고를 때 모든 인자를 살펴보기 때문에, 이를 [`multiple dispatch`][multiple-dispatch]라고 해요.

Common Lisp 같은 몇몇 다른 언어도 다중 디스패치를 지원하지만, Julia만큼 언어 설계의 중심에 있는 경우는 드물어요.

반대로 객체 지향(OO) 언어(예: Ruby)에서는 보통 메서드를 [인스턴스][instance]에 대해 호출해요.
이때 정의는 첫 번째 인자를 특별 취급하는데(정의에서 `self`나 `this` 같은 이름을 붙이죠), 메서드 이름은 인스턴스에 점을 찍어 붙여 호출해요:

```ruby
irb(main):004:0> "abc".sub("b", "*")
=> "a*c"
```

이를 [`single dispatch`][single-dispatch]라고 하는데, 메서드를 고를 때 인스턴스의 클래스(위 예에서 문자열 "abc"의 클래스)만 사용하기 때문이에요.

정적 타입을 쓰는 객체 지향 언어 중에는 메서드 다형성을 지원하는 것도 있는데, 다중 디스패치와 다소 비슷해 보여요.
큰 차이는 메서드 선택이 _컴파일_ 시점에만 일어난다는 점이에요.

함수형 언어는 보통 함수 정의를 하나만 두고, Select/Case/Match 같은 표현식으로 여러 경우를 처리해요.
여기서는 여러분이 직접 로직을 작성하는데, 보통 Julia에는 없는 간결한 패턴 매칭 문법의 도움을 받아요.
물론 Julia도 어떤 형태의 패턴 매칭을 하지만, 함수 본문 안이 아니라 디스패치 단계에서 해요.

## 마무리

다중 디스패치는 Julia에서 매우 유연하고 성능도 뛰어나서 아주 널리 쓰여요.

`+`에 메서드가 161개나 있다는 예에서 알 수 있듯이, Julia 프로그래머들은 타입을 좁게 지정한 메서드를 정의하려고 해요.
정수 두 개를 더하는 것과 실수 두 개를 더하는 것은 바이트코드 수준에서 아주 다르고, 정수와 실수를 더하는 것은 타입 승격이라는 복잡한 문제가 하나 더 붙어요.

타입이 구체적일수록 컴파일러가 할 수 있는 최적화가 많아져요. Exercism의 장난감 같은 연습 문제에서는 별로 중요하지 않지만, Julia가 겨냥하는 대규모 수치 시뮬레이션에서는 성능에 결정적이에요.

_메서드가 어떤 입력을 받을지 안다면, 꼭 컴파일러에게 알려 주세요!_
