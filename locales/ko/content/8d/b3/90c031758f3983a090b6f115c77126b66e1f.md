# 지침

기사, 블로그 글, 그 밖의 여러 글 콘텐츠를 제공하는 웹사이트를 위한 콘텐츠 관리 시스템을 개발하고 있어요.
여러분은 우선순위 큐에 있는 작업을 처리할 작업 핸들러를 구현하는 일을 맡았어요.
작업 핸들러는 작업을 받아서, 서버의 부하와 작업의 우선순위를 바탕으로 다음에 어떤 작업을 실행할지 결정해요.
서버에 부하가 많이 걸려 있으면, 작업이 실행되려면 우선순위 숫자가 더 높아야 해요.
서버는 부하에 따라 부하 수준을 동적으로 바꿔요.

## 1. `TaskHandler` 초기화

`TaskHandler`는 큐와 기본 load_level로 초기화해야 해요.

`TaskHandler` 클래스의 초기화 메서드를 구현해요. 이 메서드는 작업 이름들의 `String` `Array`를 인자로 받아 `@tasks`라는 인스턴스 변수에 저장해요.
초기화 메서드는 `@task_condition_logic` 인스턴스 변수도 만들어야 해요. 이 변수에는 `Int32`를 받아서 인자가 0 이상이면 true를, 0보다 작으면 false를 반환하는 `Proc`이 저장돼요.

```crystal
task_handler = TaskHandler.new(["task1", "task2", "task3"])
# => #<TaskHandler:0x7fd8d4cfbf00 @tasks=["task1", "task2", "task3"], @task_condition_logic=#<Proc(Int32, Bool):0x562536a4a330>>
```

## 2. 작업 조건 로직 업데이트

서버는 서버의 부하에 따라 작업 조건 로직을 업데이트할 수 있어야 해요.

블록을 인자로 받는 `TaskHandler#update_task_condition_logic` 메서드를 구현해요. 이 블록은 `@task_condition_logic` 인스턴스 변수에 저장돼야 해요.

```crystal
task_handler = TaskHandler.new(["task1", "task2", "task3"])
task_handler.update_task_condition_logic { |load| load > 1 }
# => #<TaskHandler:0x7f068118cf00 @tasks=["task1", "task2", "task3"], @task_condition_logic=#<Proc(Int32, Bool):0x562df99d0370>>
```

## 3. 다음 작업 실행

서버는 큐에 있는 다음 작업을 실행할 수 있어야 해요.

`@tasks` 배열의 첫 번째 작업이 다음에 실행할 작업이에요.
주어진 작업의 우선순위 레벨을 `@task_condition_logic` proc에 넘겼을 때 true가 반환되면 그 작업을 실행해야 해요.

작업이 실행됐는지에 따라 메시지를 반환해요.
작업이 실행되면 `"Completed <task>"`를 반환해야 해요.
작업이 실행되지 않으면 `"Could not complete <task>"`를 반환해야 해요.

작업이 실행되면 `@tasks` 배열에서 제거돼야 해요.

다음 작업의 우선순위 레벨을 `Int32`로 받는 `TaskHandler#execute_next_task` 메서드를 구현해요. 이 메서드는 작업이 실행됐는지에 따라 `String`을 반환해요.

```crystal
task_handler = TaskHandler.new(["task1", "task2", "task3"])
task_handler.update_task_condition_logic { |load| load > 1 }
task_handler.execute_next_task(2)
# => "Completed task1"

task_handler.execute_next_task(1)
# => "Could not complete task2"
```
