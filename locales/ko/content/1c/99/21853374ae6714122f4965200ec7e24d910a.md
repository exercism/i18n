# 개요

[`interfaces`][interfaces]는 클래스의 사용부와 구현부를 [분리][wiki-loose-coupling]하는 주된 수단이에요. 이런 분리는 구현부를 유지보수할 때 유연성을 주고, 타입 안전한 제네릭 동작을 지원하는 데 도움이 돼요.

인터페이스의 문법은 클래스나 구조체와 비슷해요. 다만 메서드와 속성이 시그니처로만 나타나고 본문은 제공되지 않아요.

```csharp
public interface ILanguage
{
    string Speak();
}

public interface IItalianLanguage : ILanguage
{
    string Speak();
    string SpeakItalian();
}

public interface IScriptConverter
{
    string Version { get; set; }
    string ConvertCyrillicToLatin(string cyrillic);
}
```

인터페이스를 구현하는 클래스나 구조체는 인터페이스가 정의한 모든 연산을 구현해야 해요.

인터페이스는 보통 다음과 같은 일 중 하나 이상을 해요.

- 여러 서로 다른 클래스를 이를 사용하는 코드에서 제네릭하게 다룰 수 있게 해줘요. 이 경우 인터페이스는 기본 클래스와 같은 역할을 해요.
- 특정 목적을 위해 기능의 일부만 노출해요 (예: [`IComparable<T>`][icomparable]).
- 여러 구현이 공존할 수 있도록 클래스의 공개 API를 노출해요. 한 가지 예가 [테스트 더블][wiki-test-double]이에요.

```csharp
public class ItalianTraveller : IItalianLanguage
{
    public string Speak()
    {
        return "Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class ItalianTravellerV2 : IItalianLanguage
{
    public string Speak()
    {
        return "migliorata - Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class FrenchTraveller : ILanguage
{
    public string Speak()
    {
        return "Ça va?";
    }
}

public class RussianTraveller : ILanguage, IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Speak()
    {
        return "Привет мир";
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}

public class DocumentTranslator : IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Translate(string russian)
    {
        throw new NotImplementedException();
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}
```

위 인터페이스와 클래스를 사용하는 코드는 다음을 할 수 있어요.

- 언어에 관계없이 모든 화자를 같은 방식으로 다뤄요.
- 문자 체계 변환을 처리하는 일부 하위 시스템이 자신이 다루는 구체적인 타입이 무엇인지 신경 쓰지 않고 동작하도록 해요.
- 이탈리아어 화자의 변경 사항을 몰라도 돼요. 클래스 코드와 사용자 코드를 서로 다른 팀이 관리한다면 이 점이 편리해요.

인터페이스는 손쉬운 [모킹][so-mocking-interfaces]을 가능하게 하므로 테스트를 지원하는 데 널리 쓰여요.

인터페이스에 포함할 수 있는 멤버의 종류에 대한 자세한 내용은 이 [글][dt-interfaces]을 참고해요.

인터페이스는 다른 인터페이스로부터 상속받을 수 있어요.

인터페이스의 멤버는 기본적으로 public이에요.

인터페이스는 `const` 리터럴, `enums`, `delegates`, `classes`, `structs` 같은 중첩 타입을 포함할 수 있어요. 이때 인터페이스는 클래스나 구조체와 같은 방식으로 [네임스페이스][wiki-namespaces] 역할을 하고, 동작과 문법도 동일해요.

C#은 설계상 다중 상속을 지원하지 않지만, 인터페이스를 통해 일종의 다중 상속을 가능하게 해요.

게다가 [인터페이스를 통해 다형성을 구현할 수 있다][interface-polymorphism]는 개념이 인터페이스 메커니즘의 바탕을 이루고 있어요.

## 명시적 인터페이스 구현

때로는 메서드 이름과 시그니처가 서로 다른 두 인터페이스에서 겹칠 수 있어요.
이런 메서드들을 각각 다르게 구현할 수 있도록 C#은 [인터페이스의 명시적 구현][explicit-implementation]을 제공해요. 인터페이스의 특정 구현을 사용하려면, 객체를 참조하는 식을 해당 인터페이스로 변환해야 한다는 점에 유의해요. 할당하거나, 캐스팅하거나, 매개변수로 전달하면 돼요.

```csharp
public interface IFoo
{
    void X();
}

public interface IBar
{
    void X();
}

public class Census : IFoo, IBar
{
    void IFoo.X()
    {
        Console.Write("This is from Foo");
    }

    void IBar.X()
    {
        Console.Write("This is from Bar");
    }
}

public class User
{
    public void Use()
    {
        IFoo foo = new Census();
        IBar bar = new Census();
        foo.X();
        // => "This is from Foo"
        bar.X();
        // => "This is from Bar"
    }
}
```

다양한 사용 사례가 있어요.

- 메서드의 시그니처가 동일한, (위에서 본 것처럼) 영역 간의 충돌.
- 이름은 같지만 반환 타입이 다른 메서드: 직접 컬렉션 클래스를 구현하다 보면, 레거시 `IEnumerable.GetEnumerator()`를 위한 명시적 인터페이스가 `IEnumerable<T>.GetEnuerator()`와 함께 필요하다는 걸 알게 될 거예요. 그런 인터페이스를 전혀 쓰지 않더라도 컴파일러가 요구할 수 있어요.
- 인터페이스 간에 이름 충돌은 없지만 구현하는 클래스가 관련된 다른 목적으로 그 이름을 사용하는 게 바람직한 메서드: `IFormattable`에는 `IFormatProvider` 타입의 매개변수와 함께 _형식 타입_ 매개변수를 받는 `ToString()` 메서드가 있어요. BCL(Base Class Library)의 `FormattableString` 같은 클래스는 `IFormattable`을 받는 루틴에서 사용될 수 있도록 이 인터페이스를 구현하지만, 주된 버전인 `ToString(IFormatProvider)`에서는 _형식 타입_ 매개변수를 생략하는 편이 더 표현력이 좋아요. 구현에서 사용되지 않고 API 사용자를 혼란스럽게 할 뿐이니까요.

## 기본 구현

C# 8 버전은 API와 관련된 골칫거리 하나를 해결해요. 새로운 구현을 위해 인터페이스에 메서드를 추가하면, 기존 구현들이 비록 그 메서드에 대한 구현별 동작을 갖고 있지 않더라도 API 계약을 준수하도록 모두 수정해야 해요. 이제 C#에서는 인터페이스의 일부로 _기본 메서드_를 제공할 수 있어요 (Java 개발자에게는 익숙한 개념이에요). 예전에는 이런 변경이 생기면 인터페이스의 _버전 2_가 원래 버전과 나란히 존재해야 했어요.

이 [글][dt-interfaces]은 인터페이스에 관한 훌륭한 입문서로, _기본 구현_과 `static`, `private`, `virtual` 멤버 같은 다른 지원 기능에 초점을 맞춰요.
