# 소개

## 옵셔널

Swift는 값이 없을 가능성을 표현할 수 있도록 [_옵셔널_][optionals]을 사용해요.
옵셔널은 값을 담을 수도 있고, 값이 없음을 나타내는 [`nil`][nil]이 될 수도 있는 타입이에요.
옵셔널을 사용하려면 값을 언래핑한 뒤에 쓰기 전에, 값이 실제로 있는지 먼저 확인해야 해요.

어떤 타입이든 타입 이름 끝에 `?`를 붙이면 옵셔널로 만들 수 있어요.
그래서 옵셔널 정수의 타입은 `Int?`이고, 옵셔널 문자열의 타입은 `String?`이에요.
옵셔널 타입의 상수나 변수를 정의하고 값을 대입하는 방법은 옵셔널이 아닌 타입과 똑같아요.

```swift
let x: Int? = 42
var y: String? = "Hello"
y = "Goodbye"
```

옵셔널 타입의 변수에는 특별한 값 `nil`을 대입해서 값이 없음을 나타낼 수 있어요.
`nil`은 모든 옵셔널 타입에 쓸 수 있지만, 서로 다른 두 옵셔널 타입에 대입한 `nil`은 타입이 같지 않아서 서로 바꿔 쓸 수도, 비교할 수도 없어요.

```swift
let intOpt: Int? = nil
let stringOpt: String? = nil

intOpt = stringOpt
// Compiler error: Cannot assign value of type 'String?' to type 'Int?'

intOpt == stringOpt
// Compiler error: Binary operator '==' cannot be applied to operands of type 'Int?' and 'String?'
```

`nil`은 모든 옵셔널 타입에 대입할 수 있지만, 옵셔널이 아닌 타입에는 대입할 수 없다는 점도 기억해 두세요(실제로 `nil`을 담고 있지 않더라도요).
그리고 옵셔널이 아닌 타입을 기대하는 메서드에는 먼저 언래핑하지 않고 옵셔널을 넘길 수 없어요.

```swift
var x: Int = 42
var y: Int? = 42

y = x
// Works fine
x = y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
x + y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

## 옵셔널 사용하기

옵셔널 타입은 기반 타입과 같은 타입이 아니기 때문에, 두 타입을 같은 방식으로 쓸 수는 없어요.
예를 들어 `Int("123") + 1`은 "Value of optional type 'Int?' must be unwrapped to a value of type 'Int'"라는 컴파일 오류를 내요.
`Int("123")`이 `Int` 타입이 아니라 옵셔널 `Int?` 타입을 반환하기 때문이에요. 문자열을 정수로 변환할 수 없으면 결과가 `nil`이 되니까요.
변환 결과에서 `Int`를 꺼내 쓰려면 먼저 "언래핑"해야 해요.

Swift에서는 주로 [_옵셔널 바인딩_][optional-binding]을 위한 `if-let`과 `guard-let` 구문으로 이걸 해요.
이 구문은 `nil`인지 확인해서, 값이 있으면 언래핑한 값을 지정한 이름에 묶은 채로 한 갈래의 코드를 실행하고, `nil`이면 다른 갈래의 코드를 실행해요.

```swift
if let safeNum = Int("123") {
	let sum = safeNum + 1
	…
} else {
  // code for the case where nil was found -- may be left out
}
```

`safeNum` 변수의 타입은 `Int?`가 아니라 `Int`라는 점도 눈여겨볼 만해요.
아래 예시에서 `num`은 `Int?` 타입이고 `safeNum`은 `Int` 타입이에요.

```swift
let num = Int("123")
if let safeNum = num {
  // num is of type Int
}
```

이 _옵셔널 바인딩_이 중요한 이유는 값에서 옵셔널 타입을 언래핑(또는 "제거")해서, 옵셔널이 아닌 값처럼 쓸 수 있게 해 주기 때문이에요.
값이 `nil`인지 조건문으로 확인만 하면, 값은 여전히 옵셔널 타입이에요:

```swift
let num = Int("123")
if num != nil {
  // num is of type Int?
}
```

일찍 반환하고 싶을 때는 `guard-let`을 쓸 수도 있어요:

```swift
guard let num = Int("123") else { return nil }
let sum = num + 1
…
```

## 옵셔널 비교하기

두 옵셔널의 기반 타입은 표준 비교 연산자로 비교할 수 있지만, 옵셔널 자체는 비교할 수 없다는 점에 주의해요.
옵셔널은 같은지 여부만 확인할 수 있어요.
두 옵셔널은 둘 다 `nil`이거나, 감싸고 있는 값이 각자의 기반 타입 안에서 같으면 서로 같아요.

그래도 두 옵셔널 값을 직접 비교하는 코드를 작성할 수 있어요.
아래는 두 옵셔널 값이 모두 nil이 아니고 첫 번째 값이 두 번째 값보다 작을 때만 `true`를 반환하는 `switch`문 예시예요.
이를 위해 nil이 아닌 옵셔널에만 매칭되면서 옵셔널 안의 값을 `varName`이라는 이름에 묶어 주는 _옵셔널 패턴_ `varName?`을 사용해요.

```swift
switch (optionalA, optionalB) {
case let (valA?, valB?): return valA < valB
default: return false
}
```

## nil 병합

`nil`일 때 [대체 값][fallback]을 쓰는 방법으로도 언래핑할 수 있어요.
이때는 _nil 병합 연산자_ `??`를 사용해요.
`x`가 `Int?`라고 할 때 `let y = x ?? 0`이라고 쓰면, Swift는 x가 `nil`인지 확인해요.
`nil`이 아니면 `x`를 언래핑해서 그 값을 `y`에 대입하고, `x`가 `nil`_이면_ `y`에 0을 대입해요.

`x ?? y`는 `x != nil ? x! : y`를 줄여 쓴 것일 뿐이라서, `x`가 nil이 아니면 표현식 `y`는 아예 평가되지 않아요.

마지막으로, nil 병합 연산자는 오른쪽 결합이라서 모르고 쓰면 뜻밖의 결과를 얻을 수 있다는 점도 알아 두세요.

```swift
let k = 42 ?? 0 + 1    // returns 42
let j = nil ?? 0 + 1   // returns 1
```

nil 병합 연산자에 대해서는 [A Tour of Swift: Nil-Coalescing Operator][nil-coalescing]에서 더 읽어볼 수 있어요.
