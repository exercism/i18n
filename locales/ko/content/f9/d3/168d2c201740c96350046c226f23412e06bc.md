# 자세히 알아보기

Go에서 문자열은 불변이에요.
루프 안에서 `+`로 문자열을 이어 붙이면 할당이 자주 일어나고 데이터가 여러 번 복사돼요.
[`strings` 패키지](https://pkg.go.dev/strings)는 문자열을 효율적으로 만들어 메모리 오버헤드를 줄여 주는 [`Builder`](https://pkg.go.dev/strings#Builder)를 제공해요.

## 문자열 만들기

`strings.Builder`의 제로 값은 별도의 초기화나 할당 없이 바로 사용할 수 있어요.
전용 쓰기 메서드를 사용해 빌더에 새 데이터를 넣을 수 있어요.
각 쓰기 메서드는 Go 표준 인터페이스를 충족하기 위해 오류 값을 반환하지만, 항상 `nil`이라는 것이 보장되기 때문에 실제 코드에서는 보통 무시해요.

가장 자주 사용하는 메서드는 다음과 같아요.

- `WriteString(s string) (int, error)`: 버퍼에 문자열을 덧붙여요.
- `WriteRune(r rune) (int, error)`: 룬의 UTF-8 인코딩을 덧붙여요.
- `WriteByte(c byte) error`: 바이트 하나를 덧붙여요.

```go
var sb strings.Builder

sb.WriteString("Hello")
var r rune = ' '
sb.WriteRune(r)
var b byte = '.'
sb.WriteByte(b)
```

## 문자열 가져오기와 초기화

텍스트 조립을 마쳤다면 `String()` 메서드를 호출해 지금까지 모인 내용을 일반적인 Go 문자열로 가져올 수 있어요.
`String()`은 모인 데이터를 복사하지 않고 내부 바이트 슬라이스를 문자열로 그대로 반환하기 때문에 비용이 거의 들지 않아요.

같은 빌더 인스턴스를 재사용해 새 문자열을 만들어야 한다면(예를 들어 루프 안에서) `Reset()` 메서드를 호출할 수 있어요.
이 메서드는 내부 버퍼를 비워서, 이미 할당된 메모리 용량은 그대로 유지한 채 처음부터 다시 다음 문자열을 만들 수 있게 해줘요.

```go
var sb strings.Builder

sb.WriteString("Task One")
fmt.Println(sb.String()) // Output: Task One

// Clear the buffer for resource reuse
sb.Reset()

sb.WriteString("Task Two")
fmt.Println(sb.String()) // Output: Task Two
```
