# 테스트

각 연습 문제에는 단위 테스트와 CMake 빌드 레시피가 함께 제공돼요. 구현은 직접 작성해요.
각 테스트 파일은 구현과 링크되어, 테스트를 실행하는 콘솔 실행 파일을 만들어요. 테스트 실행 파일을 실행하면 실패한 각 테스트에 대한 메시지를 출력하고, 테스트가 실패하면 0이 아닌 종료 상태를 보고해요.

*참고:* 프로젝트를 빌드할 때마다 코드는 테스트 스위트에 대해 테스트돼요. 유효한 C++ 코드지만 하나 이상의 테스트를 통과하지 못하더라도 컴파일은 여전히 돼요.

각 연습 문제를 푸는 과정은 다음과 같아요.

* CMake로 최초 빌드 만들기
* 각 단위 테스트마다:
  * 컴파일 오류를 해결해서 테스트가 실패하도록 만들어요.
  * 테스트를 통과할 만큼만 구현해요.
  * 가독성을 높이고 중복을 줄이는 등으로 구현을 리팩터링해요.
  * 다음 테스트의 주석을 풀어요.

## CMake로 최초 빌드 만들기

각 연습 문제에는 단위 테스트와 함께 `CMakeLists.txt` 파일이 딸려 와요. 이 파일에는 빌드를 대신 처리해 주는 미리 준비된 CMake 레시피가 들어 있어요. 이 파일은 따로 수정할 필요가 없어요. 제공된 레시피는 구현이 연습 문제 이름을 딴 헤더 파일과 소스 파일로 존재한다고 가정해요.

예를 들어 `bob` 연습 문제는 `bob.h`와 `bob.cpp`에 구현이 있기를 기대해요. 이름에 하이픈이 들어간 연습 문제라면 소스 파일은 밑줄을 쓴다고 가정해요. 그래서 `word-count`는 `word_count.h`와 `word_count.cpp`를 기대해요. 구현이 충분히 단순해서 헤더 파일에 전부 담을 수 있다고 판단되면 `cpp` 파일은 생략해도 돼요.

**CMake를 실행하기 전에 최초 구현 파일을 먼저 만들어요.** `bob` 연습 문제에서 CMake를 실행할 때 `bob.h`와 `bob.cpp` 파일이 없으면, CMake가 파일을 찾을 수 없다는 오류를 내요. **이 파일들은 비어 있어도 되지만, 반드시 존재해야 해요.**

이 레시피를 사용하면, 알맞은 제너레이터와 연습 문제 디렉터리 위치를 지정해 `cmake -G`를 실행함으로써 환경에 맞는 프로젝트를 CMake가 생성할 수 있어요. CMake는 사용 중인 운영체제에 맞는 빌드 스크립트를 생성해요. 생성된 파일들을 연습 문제 소스 코드와 분리해 두려면, 생성된 빌드 파일과 컴파일된 코드를 담을 `build`라는 디렉터리를 만드는 것이 일반적이에요. 이렇게 하면 연습 문제 폴더를 깔끔하게 유지할 수 있어요.

CMake가 빌드 환경을 만들어 주면, 환경에 맞는 명령으로 코드를 빌드할 수 있어요.

* Linux에서 make 사용: `make`
* Windows에서 Visual Studio 사용: 메뉴에서 Build / Build Solution을 선택해요.
* MacOS에서 Xcode 사용: 툴바에서 Build를 선택해요.
* MacOS에서 "Unix Makefile" 사용: `make` _Exercism CLI 앱을 사용하는 경우_

다양한 환경에서 CMake를 실행하는 예시는 아래와 같아요.

### Linux에서 make 사용

CMake의 제너레이터 이름은 `Unix Makefiles`예요. 현재 연습 문제가 `bob`이고 연습 문제 폴더에 있다고 가정해요.

```sh
$ touch bob.{h,cpp}
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

이 예시는 CMake를 실행하기 전에 구현을 위한 빈 파일을 만드는 방법을 보여줘요.

빌드 디렉터리에서 `make`를 입력하기만 하면 테스트가 컴파일돼요. 그러면 컴파일 시점 오류가 발생할 거예요. 오류를 모두 고치면, `make`가 테스트를 빌드하고 실행해요.

### Windows에서 Visual Studio 사용

Visual Studio는 CMake 프로젝트를 기본으로 지원하기 때문에, CMake를 따로 설치하거나 Visual Studio 밖에서 실행할 필요가 없어요. Visual Studio에서 CMake 프로젝트를 설정하려면 [이 가이드](https://docs.microsoft.com/en-us/cpp/build/cmake-projects-in-visual-studio)를 따라 해요.

### MacOS에서 Xcode 사용

CMake의 제너레이터 이름은 `Xcode`예요. 현재 연습 문제가 `bob`이고 연습 문제 폴더에 있다고 가정해요.

```sh
$ touch bob.{h,cpp}
$ mkdir build
$ cd build
$ cmake -G Xcode ..
```

이 예시는 XCode에서 프로젝트를 열 수 있도록 XCode 파일을 생성해요. XCode에서 프로젝트를 연 다음에는 다른 타깃을 추가해야 할 수도 있어요. 새 타깃을 만들려면 메뉴에서 File -> New -> Target으로 이동한 뒤, _OS X \ Application \ Command Line Tool_ -> Next를 선택하고, 언어로 _C++_를 지정하고 타깃 이름을 입력해요. 그 타깃으로 코드를 실행해요.

터미널에서 `Xcode x.x not supported` 오류가 나오면, 컴퓨터에 Xcode가 설치되어 있지 않거나 버전이 오래된 경우일 가능성이 높아요. App Store나 [이 링크][web-xcode-download]를 통해 Xcode를 내려받아 설치해요. `The CXX compiler identification is unknown`과 비슷한 오류는 [GCC 설치 안내][cpp-installation-instructions]를 따르거나 위 문단처럼 Xcode에서 다른 타깃을 추가하면 대부분 해결돼요.

[web-xcode-download]: https://apps.apple.com/us/app/xcode/id497799835?mt=12
[cpp-installation-instructions]: https://exercism.org/docs/tracks/cpp/installation

### MacOS에서 make 사용 _Exercism CLI를 사용할 때_
#### 이 예시는 Exercism CLI 앱으로 C++ 연습 문제를 설정하고 테스트하고 제출하려는 분들을 위해 특별히 준비했어요.

CMake의 제너레이터 이름은 `Unix Makefiles`예요. 현재 연습 문제가 `bob`이고 연습 문제 폴더에 있다고 가정해요.

```sh
$ touch bob.{h,cpp}
$ cmake -G "Unix Makefiles" .
$ exercism test
```

이 예시에서는 CMake를 실행하기 전에 구현을 위한 빈 파일은 만들지만, 빈 빌드 디렉터리는 **만들지 않아요**. Exercism CLI가 루트 디렉터리의 `.exercism/metadata.json` 파일을 사용해 테스트 케이스를 분석하기 때문이에요.

루트 디렉터리에서 `exercism test`를 입력하기만 하면 테스트가 컴파일돼요. 그러면 컴파일 시점 오류가 발생할 거예요. 오류를 고친 뒤 `exercism test`를 다시 실행하면 Exercism CLI가 테스트를 빌드하고 실행해요.

[cpp-installation-instructions]: https://exercism.org/docs/tracks/cpp/installation
