# 지시 사항 추가

## `from_quote`의 장단점

이 연습 문제는 `DateOfBirth` 타입에 `from_quote` 함수를 정의해요. 덕분에 다음과 같은 코드를 작성할 수 있어요:

```roc
birthdate : DateOfBirth
birthdate = "2019-01-20"
```

이 코드는 컴파일 시점에 `DateOfBirth.from_quote("2019-01-20")`를 암묵적으로 호출해요. 런타임에 파싱을 처리할 필요가 없으니 프로그램 속도를 높일 수 있고, `from_quote`가 거부한 날짜를 런타임이 아니라 컴파일 시점에 잡아낼 수 있어요. 게다가 코드가 깔끔하고 읽기 쉬워져요. 예를 들어, 이 연습 문제에 있는 테스트 중 하나를 볼까요:

```roc
# multiple birthdates with one shared birthday
expect {
	shared_birthday(["1966-07-29", "1977-02-12", "2001-07-29", "1980-11-10"])
}
```

그런데 이 코드를 읽는 사람은 `shared_birthday` 함수가 `List(Str)`를 받는다고 생각할 수 있어요. 실제로 받는 건 `List(DateOfBirth)`인데 말이에요. 이 때문에 혼란이나 오류가 생길 수 있어요. 그래서 조금 더 길지만 더 명확한 형식인 `"2019-01-20".DateOfBirth`를 선호할 수도 있어요. 이 형식도 컴파일 시점에 `from_quote`를 호출해요.

직접 작성하는 프로그램에서는 다음과 같이 편리한 생성자를 제공하는 편이 좋을 수도 있어요:

```roc
DateOfBirth := { year : I64, month : U8, day : U8 }.{
    from_ymd : I64, U8, U8 -> Try(DateOfBirth, [InvalidMonth, InvalidDay])
    from_ymd = |year, month, day| ...
}
```

이 생성자도 다음과 같이 컴파일 시점에 호출할 수 있어요:

```roc
Ok(birthdate) = DateOfBirth.from_ymd(2019, 1, 20)
```

참고: 이 정의를 최상위에 두면 컴파일 시점에 실행돼요(함수가 순수하고 입력이 컴파일 시점에 알려져 있기 때문이에요). 함수 안에서는 같은 생성자를 런타임에 사용할 수 있어요.
