# 트랙 도구

트랙 도구에는 두 가지 유형이 있어요.

- 프로덕션: 해당 언어의 학습 경험에 핵심적인 기능을 제공해요
- 유지보수: 트랙 유지보수를 도와줘요

도구는 (일반적으로) 해당 트랙의 언어로 작성되고, 메인테이너가 만들고 관리해요.

## 프로덕션 도구

이 도구들은 Exercism의 프로덕션 서버에서 실행돼요.

### 트랙별 프로덕션 도구

트랙별 프로덕션 도구는 세 가지예요.

- **[테스트 러너](/docs/building/tooling/test-runners)** (필수)
- **[리프레젠터](/docs/building/tooling/representers)** (선택 사항)
- **[분석기](/docs/building/tooling/analyzers)** (선택 사항)

### 범용 프로덕션 도구

트랙에 설정할 수 있는 범용 프로덕션 도구는 두 가지예요.

- **[코드 줄 수 카운터](/docs/building/tooling/lines-of-code-counter)** (선택 사항)
- **[스니펫 추출기](/docs/building/tooling/snippet-extractor)** (선택 사항)

### 배포

프로덕션 도구는 Docker 이미지로 빌드돼요.
CI 워크플로를 사용해 Exercism의 프로덕션 서버에 자동으로 배포돼요.

## 유지보수 도구

유지보수 도구는 트랙 유지보수를 돕기 위해 만들어졌어요.
보통은 로컬(메인테이너나 기여자의 컴퓨터)에서 실행되고, 때로는 CI에서도 실행되지만, 프로덕션에서는 절대 실행되지 않아요.

유지보수 도구의 예는 다음과 같아요.

- **[테스트 생성기](/docs/building/tooling/test-generators)**

## 구현

트랙 도구는 보통 (대부분) 트랙의 언어로 작성돼요.

```exercism/caution
다른 언어를 사용하는 건 자유지만, 언어가 하나씩 늘어날수록 트랙을 유지보수하거나 기여하기가 더 어려워져요.
따라서 가능하면 트랙의 언어를 사용하기를 권장해요. 그렇게 하면 유지보수와 기여가 더 쉬워지기 때문이에요.
```
