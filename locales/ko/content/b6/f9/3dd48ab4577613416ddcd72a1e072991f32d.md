# 자세히 알아보기

실러버스에서 이쯤까지 오면, R이 명령형 언어로 자주 쓰이는 모습을, 그리고 점점 더 함수형 언어로, 특히 [`purrr`][ref-purrr]와 [`dplyr`][ref-dplyr] 라이브러리와 함께 쓰이는 모습을 보았을 거예요.

이제 와서 R이 주로 객체 지향적이라고 말하면 다소 회의적인 반응이 나올지도 몰라요!

이상하게도, 이 말은 사실이에요.
R은 내부적으로 클래스, 상속, 다형성, 그리고 객체 지향 프로그래머 특유의 사고방식을 사용해 구현되어 있어요.

하지만 Java나 Ruby(명시적으로 객체 지향), 심지어 Python(어떤 면에서는 은근히 객체 지향)에 익숙한 사람이라도 R의 방식은 ... _낯설게_ 느껴질 거예요.

우선, 클래스 설계가 여러 가지예요. 널리 쓰이는 것만 아마 세 가지(S3, S4, R6)이고, 그 밖에 주로 이론적인 관심 대상인 여러 방식이 더 있어요.

자세한 논의는 [Advanced R, 2e][book-advanced-r] 12-16장에서 찾을 수 있어요.
이 2019년 책은 주로 R의 내부를 이해하고 유지보수하려는 사람을 겨냥하기 때문에, 객체 지향이 꼭 필요해요.

최종 사용자에 더 초점을 맞춘 교재들은 이와 달라요.

- The Art of R Programming(2011, 인쇄본으로만 출간)에는 S3와 (더 간략히) S4를 다루는 객체 지향 장이 있어요. 당시에는 둘 다 중요했죠. _"S3 클래스는 다소 짜깁기된 구조를 지녔다"_라는 언급은 지금 봐도 놀랍도록 사실이에요.
- R in Action(3판, 2022)은 객체 지향을 끝부분의 고급 프로그래밍 장에서 3쪽으로만 다뤄요.
- [R for Data Science, 2e][book-r-data-sci] (2023, 인쇄본 기준 548쪽)는 객체 지향을 아예 언급하지 않아요.

이번 개념에서는 S3 클래스에 집중할게요. S3 클래스는 가장 단순하고 가장 흔하며, Exercism 유형의 문제에 가장 잘 맞아요.
R 트랙의 실습 문제 중에는 S3 클래스를 만들도록 요구하는 것도 있고, 선택 사항이지만 살짝 권장하는 것도 있어요.

## S3 클래스

S3 클래스는 꽤 오래됐어요. S3라는 이름은 S 언어(R의 상용 전신)의 버전 3에서 도입되었다는 뜻일 뿐이에요.

S3 클래스는 아주 단순하기도 해요. 보통 [배열][concept-lists]에 속성을 최소한 하나 더 붙인 형태예요.

[Advanced R][book-s3]을 인용하면: _"S3는 격식 없고 즉흥적이지만, 그 미니멀리즘에는 나름의 우아함이 있어요. 어떤 부분을 떼어내도 여전히 쓸모 있는 객체 지향 시스템이 되지는 않아요."_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

따라서 [`class(obj)`][ref-class]에 값을 대입하면 `obj`에 속성이 하나 추가될 뿐이에요. 이 경우에는 pt2d를 point2d 클래스의 인스턴스로 식별해 줘요.

생성 단계는 [`structure()`][ref-structure]와 결합할 수 있어요:

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

두 결과 인스턴스는 이론상 동일하지만, 아직 R이 이를 확인할 방법을 구현하지 않았어요.

### 제네릭 메서드

다른 언어의 객체 지향에 익숙한 사람이라면 이런 생각이 들 수도 있어요. _"클래스는 뭔가를 할 수 있어야 하는 거 아닌가?"_

`point2d` 인스턴스에 쓸 수 있는 메서드를 확인해 보면, (바탕이 되는 `list`와 달리) 현재는 아무것도 없다는 걸 알 수 있어요.

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

대부분의 객체 지향 언어에서는 메서드가 클래스 정의 안에 함께 정의돼요.
몇몇 언어(특히 Ruby)에서는 나중에 클래스 메서드를 추가하고 수정할 수 있어요.

S3 클래스는 이와 아주 달라요.
클래스에 메서드를 추가하는 대신, 제네릭 메서드에 클래스를 추가해요.

R 콘솔에서 대화식으로 작업하는 사람이라면 누구나 제네릭 메서드를 늘 사용해요. 대개는 그것이 어떻게 구현되는지 생각하지도 않고요.

아주 흔한 예가 `print()`예요. 함수 이름을 직접 입력하는 일은 드물지만요.
콘솔 프롬프트에서 값 `x`를 그냥 입력하는 것은 `print(x)`의 편의 문법일 뿐이에요.

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

이미 `pt2d`를 출력할 수 있어요.
`print()`가 `point2d` 클래스에 대해 아무것도 모르더라도, 다양한 객체를 다룰 수 있는 합리적인 기본 동작을 갖추고 있어요.

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

이 출력은 꽤 장황한데, 좌표를 간결하고 보기 좋게 출력할 방법이 있으면 좋겠어요.

간단해요. `print.point2d()`라는 함수를 추가하기만 하면 돼요.
이름은 `methodname.classname` 형식이어야 해요. 그래야 디스패처가 무엇을 찾아야 할지 알 수 있어요.

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

이제 새로운 제네릭 메서드를 만들고 싶다고 해봐요. 예를 들어 `y` 좌표의 부호를 뒤집는 `flipvert()` 말이에요.

이번에도 간단해요.

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

이렇게 하면 디스패처가 만들어져요. 여기서 `x`는 S3 클래스를 가진 객체이고, `...`는 메서드 정의에 필요할 수 있는 추가 인자를 처리해요. ('점 인자'로, [함수 개념][concept-functions]에서 설명해요.)

그다음 `point2d`에 대한 메서드를 정의해서 사용할 수 있어요.

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

이제 R은 우리 점을 뒤집는 방법과 결과를 표시하는 방법을 알아요.

3D나 극좌표 등을 위한 클래스를 만들어 각각의 메서드를 정의하는 식으로 확장할 수도 있어요.

최종 사용자 입장에서는 `flipvert(x, ...)`만 있을 뿐이고, 입력 클래스를 판별해 알맞은 내부 구현을 사용하는 일은 R에 맡기면 돼요.

~~~~exercism/caution
`verb.class` 형식의 함수 이름은 사용자에게도, R 파서에게도 S3 메서드처럼 보여요.
다른 맥락에서는 비슷한 이름을 피하는 게 좋아요.

물론 기본 R도 가끔 이 규칙을 어겨요.
이것은 (S3보다도 더 오래된 함수들에서 비롯된) 안타까운 역사적 사고로 봐야 하고, 하위 호환성을 위해 유지해야 해요.
~~~~

### 상속

객체 지향 애호가라면 상속, 서브클래싱, 믹스인 등등에 대해 교과서 여러 장을 길게 써 내려갈 수 있어요.

R은 그냥 `class` 속성에 여러 이름을 줄 수 있어요. 문자열 하나가 아니라 더 긴 문자열 벡터를 넣는 거예요.

이 예제를 한계까지 끌어다 쓸 위험을 무릅쓰고, 일반적인 `point` 클래스를 만들어 이를 `point2d`, `point3d` 등으로 서브클래싱하고 싶다고 해봐요.

그러면 `point2d` 정의는 그냥 `class = c("point2d", "point")`를 사용해요. 구체적인 클래스와 부모 클래스(들)를 나열하는 거예요.

그러면 `print()` 같은 제네릭 메서드가 `print.point2d()`, `print.point()`, 그리고 (아마도) `print.default()`를 순서대로 찾아, 디스패처가 가장 먼저 발견한 구현을 사용해요.

### 안전성

많은 객체 지향 언어(Java, C# 등)는 클래스 안의 데이터 캡슐화를 활용해 컴파일 시점에 신중한 검사를 수행하고 타입 안전성을 강제해요.

S3는 말이 안 되는 짓이라도 거의 무엇이든 하도록 내버려 둔다는 점을 알아두세요. (오류 메시지가 나온다 해도 훨씬 나중이에요.)

["Advanced R"][book-s3](2판, 13.3절)을 인용하면:

> _다른 객체 지향 언어를 써 봤다면 이게 좀 불편하게 느껴질 수도 있어요. 하지만 실제로는 이런 유연성이 거의 문제를 일으키지 않아요. R이 발등을 쏘는 걸 막아 주지는 않아요. 하지만 총구를 발가락에 겨누고 방아쇠를 당기지만 않으면 문제될 일은 없어요._

뭐, _그럴 만도 하네요?_
R은 탐색적 데이터 과학과 통계, 특히 대화식으로 작업할 때 뛰어나요.
R로 보안이 철저한 기업 금융 시스템을 작성하라고 권하는 사람은 아무도 없어요!
