# 소개

## 불투명 타입

### 소개

불투명 타입은 Elm에서 쓰는 캡슐화 기법이에요.
정보 은닉이나 구현 세부 사항 감추기라고 부르기도 해요.
[검증하지 말고 파싱하기][parse-dont-validate] 패턴을 사용해 검증을 강제할 때도 흔히 쓰여요.
예를 들어 유효한 이메일 주소만 담을 수 있는 `EmailAddress` 불투명 타입을 만들 수 있어요. 무엇이든 담을 수 있는 `String`과는 달라요.

### 불투명 타입 만들기

[커스텀 타입][custom-types]은 하나 이상의 *변형*을 가지고, 컴파일러는 *변형* 이름을 사용해 각 *변형*을 만드는 함수를 자동으로 만들어 줘요.
커스텀 타입은 이 방법으로만 만들 수 있어요.
컴파일러는 이런 변형에 대한 구조 분해도 허용해요.

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

기본적으로 이 모든 것은 파일이나 모듈 내부에만 있고, `exposing` 키워드로 무엇을 내보낼지 선택해요.
불투명 타입을 만들려면 *변형*을 내보내지 않으면 돼요.

이렇게 하면 거의 항상 커스텀 함수를 노출해서 *변형*을 만들고 가져오는 다른 방법을 마련해야 해요.
이 커스텀 함수들을 사용하면 *변형*을 만들고 가져올 때 어떤 로직을 적용할 수 있어요.
이렇게 하면 모듈의 내부 구현 세부 사항이 숨겨지고, 노출된 함수가 그대로인 한 구현 세부 사항을 얼마든지 바꿀 수 있어요.

### 검증하지 말고 파싱하기

아마 불투명 타입의 가장 흔한 쓰임은 [검증하지 말고 파싱하기][parse-dont-validate] 패턴으로 검증을 강제하는 거예요.
이 패턴에서는 `String`처럼 원하는 것보다 구조나 타입 안전성이 덜한 입력을 받아서, `EmailAddress`처럼 더 구조화된 타입으로 파싱하는 함수를 노출해요. 결과로 타입을 반환하거나 오류(보통 `Maybe`나 `Result`)를 반환해요.

예를 들어 아래 코드에서는 외부 모듈이 `parseEmailAddress` 함수로만 `EmailAddress` 타입을 만들 수 있어요. 그래서 `EmailAddress` 타입을 다룰 때는 그것이 유효하다고 확신할 수 있어요.

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
