# 리스트

`ARRAY`는 고정되어 있어요. 만들어질 때 크기가 정해지고 그대로 남아요. 뒤에 덧붙일 수도, 하나를 빼낼 수도 없어요.

탐정의 수첩은 그렇지 않아요. 단서는 하나씩 나타나고, 아니라고 판명되면 줄이 그어져요. 그럴 때 필요한 게 바로 **리스트**예요.

```sather
   notes ::= #LIST{STR};
   notes.append("muddy boots");
   notes.append("broken window");
   notes.size                   -- 2
```

`LIST{T}`는 배열처럼 `T` 타입의 값을 순서대로 담고, 요청하면 늘어나고 줄어들어요.

## 제자리에서 바뀌어요

`append`는 자신이 호출된 리스트를 바꾸고 아무것도 반환하지 않아요:

```sather
   notes.append("muddy boots");        -- yes
   notes := notes.append("muddy boots");   -- no: append answers nothing
```

`FMAP`과 `FSET`과는 달라요. 그쪽에서는 변경할 때마다 결과를 다시 대입해야 했죠. `LIST`는 `SCOREBOARD`처럼 평범한 객체예요. 루틴에 넘겨주면 그 루틴이 내 리스트를 바꿀 수도 있어요.

## 읽기와 쓰기

대괄호를 쓰고, 0부터 세요. 배열과 똑같아요:

```sather
   notes[0]                     -- "muddy boots"
   notes[1] := "smashed window";
   notes.size                   -- how many
   notes.is_empty               -- true when there are none
```

## 제거하기

`remove_index`는 특정 위치를 없애고, 그 뒤에 있는 원소는 모두 한 칸씩 앞으로 당겨져요:

```sather
   notes.remove_index(0);       -- the first clue is struck out
```

그래서 위치는 영원하지 않아요. 앞의 단서가 없어지면 어떤 단서의 위치도 바뀌어요. 위치를 저장하기 전에 이 점을 기억해 두면 좋아요.

## 하나씩 순회하기

`elt!`도 배열에서처럼 잘 동작해요:

```sather
   loop
      #OUT + notes.elt! + "\n";
   end;
```

## 중괄호

`LIST{STR}`는 문자열의 리스트이고, `LIST{INT}`는 숫자의 리스트예요. `lost-property`에서 직접 만든 것과 꼭 같은 제네릭 클래스죠. 이제는 라이브러리에 있는 것도 같은 방식으로 읽을 수 있어요.
