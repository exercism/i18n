# 셸 기초 소개

## 셸

_셸_은 운영 체제와 상호 작용할 수 있도록 명령을 입력하게 해 주는 프로그램이에요.
셸은 그래픽 방식일 수도 있어요. 마우스나 트랙패드로 사용하는 데스크톱 환경도 셸이에요.
여기서는 명령줄 인터페이스에 집중해 볼게요. 명령을 입력하면 그 결과가 (보통은) 터미널에 출력되는 방식이에요.

명령줄 셸에는 여러 가지가 있어요.
Windows에는 **cmd**와 **powershell**이 있어요.
Mac과 Linux에는 여러 가지 "유닉스 셸"이 있어요.
Mac의 기본 셸은 **zsh**예요.
**csh**는 C와 비슷한 문법을 가진 예전 셸이에요.
**bash**는 특히 Linux에서 가장 널리 쓰이는 셸 중 하나예요.

가장 초기의 셸 중 하나는 Bourne 셸인 **sh**예요.
시간이 지나면서 이 셸은 모든 Unix 계열 시스템에서 제공되도록 [표준화][posix]되었어요.
많은 셸이 Bourne 셸을 기반으로 하며, 대개 대화형 기능이나 프로그래밍 기능을 추가로 제공해요.

**Bash**는 Bourne 셸을 기반으로 해요.
그래서 이름이 "**B**ourne-**a**gain **sh**ell"이에요.
많은 Linux 시스템에서 기본 셸로 쓰여요.
Bash는 대화형 셸을 즐겁게 쓸 수 있게 해 주는 여러 기능을 제공해요.

* 자유롭게 꾸밀 수 있는 프롬프트,
* 기록에서 명령을 다시 불러오고 수정하는 기능,
* 실행 중인 프로세스를 조작하는 기능,
* 입력을 줄여 주는 앨리어스,
* 그 밖에도 여러 가지가 있어요.

이 트랙은 bash를 대화형 셸로 사용하는 방법을 다루지 않아요.
bash로 프로그램을 작성하는 법을 배우는 내용이에요.
문제를 해결할 때 _오직_ bash만 사용하는 데 중점을 둘 거예요. 물론 외부 도구를 불러오는 것을 막지는 않아요.

## Bash 기초: 명령과 인자

Bash는 입력(보통 터미널이나 파일)에서 명령을 읽어요.
읽어 들인 각 줄은 _명령_, 즉 수행해야 할 지시로 취급돼요.
(여러 줄에 걸친 명령처럼 몇 가지 고급 사례가 있는데, 이건 나중에 다뤄요.)

Bash는 각 줄을 공백 문자(스페이스와 탭)로 구분된 **단어**로 나눠요.
줄의 첫 번째 단어가 실행할 _명령_의 이름이에요.
나머지 단어는 모두 그 명령의 _인자_(옵션, 파일 이름 등)가 돼요.

~~~~exercism/note
아래 예시에서는 직접 실행해 볼 수 있는 대화형 명령 몇 가지를 보여 드릴게요.

* `#` 문자는 _주석_을 시작해요.
  주석 뒤에 오는 단어는 셸이 무시해요. 주석은 읽기 위한 것일 뿐이에요.
* `$` 문자는 셸 프롬프트를 나타내요. 
  명령을 복사할 때는 프롬프트를 포함하지 마세요.
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

`rm`은 주어진 파일을 삭제하는 애플리케이션이에요.
`*`는 [glob][glob] 문자로, 현재 디렉터리의 모든 파일과 일치하는 "와일드카드" 패턴이에요.
glob에 대해서는 나중에 더 이야기해요.

`a`와 `b` 사이에는 스페이스가 여러 개 있고 `b`와 `c` 사이에는 하나뿐이라는 걸 눈치챘나요?
인자 사이의 공백 양은 중요하지 않아요!
예를 들어 볼까요?

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

`echo`는 인자를 표준 출력(여기서는 터미널)에 출력하는 명령이에요.
Bash는 이 명령을 다섯 개의 단어로 나누고, 네 개의 인자로 `echo` 명령을 실행해요.
두 번째 예시의 여분의 스페이스는 아무 차이도 만들지 않아요.
`echo`는 단어 사이에 원래 스페이스가 어떻게 있었는지 알지 못해요.

여분의 공백을 그대로 유지하고 싶다면 문장을 하나의 인자로 넘겨야 해요.
[따옴표][Quotes]를 사용하면 돼요.

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

따옴표는 그 안의 모든 내용을 _하나의 인자_로 묶어요.
이때 인자는 그 특정한 스페이스 문자들을 포함한 `This    is    a    test.`예요.
따옴표 자체는 인자의 일부가 아니라는 점에 주목해요. bash는 그 하나의 인자를 `echo`에 넘기기 전에 따옴표를 제거해요.

인자는 명령 이름과, 그리고 서로 간에 공백으로 구분돼요.
이 점은 꼭 기억해 두세요.
예를 들어 다음은 잘못된 방식이에요.

```bash
$ [-f file]
bash: [-f: command not found
```

`file`이라는 이름의 파일이 존재하는지 확인하려는 의도예요.
`[`와 `]` 주위의 공백은 상관없다고 생각하기 쉬워요. 하지만 `[`는 실제로 하나의 명령이고, 마지막 인자가 `]`여야 해요.
(`[` 명령에 대해서는 나중에 더 자세히 다뤄요.) 
따라서 `[`는 `-f`와, `]`는 `file`과 분리해야 해요.
그렇지 않으면 bash는 `file]`이라는 인자 하나를 가진 `[-f`라는 명령을 실행하려는 것으로 생각해요.
올바른 명령은 모든 인자를 공백으로 구분해요.

```bash
$ [ -f file ]
```

(이런 동작에 혼란스러워하는 사람을 많이 봐요. `[...]`는 그저 "문법"일 뿐이라 스페이스를 생략해도 된다고 생각하죠. 하지만 `[`는 명령이고 공백이 꼭 필요해요.)

파일 이름에 공백이나 다른 특수 문자가 들어 있다면 마찬가지로 따옴표로 묶어야 해요.

```bash
$ [ -f "my file" ]
```

## 명령의 종류

Bash는 여러 가지 종류의 명령을 알아들어요. 앨리어스, 함수, 빌트인, 키워드, 실행 파일이에요.
이들은 모두 _명령_이고, 아주 비슷하게 동작해요.

기본적으로 앨리어스는 대화형 셸에서만 활성화되고 셸 스크립트에서는 활성화되지 않아요.
여기서는 다루지 않을게요.

### 함수

함수는 셸 명령을 담고 있고, 작은 스크립트처럼 동작해요. 인자를 받거나 지역 변수를 만들 수도 있어요.
함수를 호출하면 그 안의 명령이 실행돼요.
함수는 나중에 자세히 다뤄요.

### 빌트인

Bash에는 `cd`(디렉터리 변경), `echo`(출력 쓰기) 같은 기본 명령이 내장돼 있어요.
이미 제공되는 함수라고 생각하면 돼요.

### 키워드

키워드는 빌트인과 비슷한데, 가장 큰 차이는 키워드가 실제로 bash 문법이고 특별한 규칙으로 분석될 수 있다는 점이에요.
예를 들어 `[`는 bash 빌트인이고 `[[`는 bash 키워드예요. 둘 다 다양한 조건을 검사할 때 사용해요.
그런데 `[[` 키워드에는 추가 기능이 있어요.
예를 들어 정규 표현식 검사를 하는 `=~` 연산자를 제공해요.

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

문자열 비교 연산자 `<`와 `>`도 키워드가 코드를 다르게 분석하는 예예요.
`[[...]]` 안에서는 이 연산자들을 특별히 조심할 필요가 없어요.

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

하지만 `[...]` 안에서는 셸이 이들을 리다이렉션 연산자로 분석하지 못하도록 따옴표로 묶거나 이스케이프해야 해요.

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### 실행 파일

bash가 실행할 수 있는 마지막 종류의 명령은 _실행 파일_이에요.
컴퓨터 파일 시스템에 있는, 실행할 수 있는 실행 파일(프로그램)이에요.
(실행 파일은 _외부 명령_ 또는 _애플리케이션_이라고도 해요.)
실행 파일은 보통 이름만 입력해서 실행해요. 파일의 전체 경로는 대개 필요하지 않아요.
이게 가능한 이유는 bash가 미리 정의된 변수를 사용해 흔한 실행 파일의 위치를 찾기 때문이에요.
이 변수의 이름은 `PATH`예요.
콜론으로 구분된 디렉터리 이름의 집합이에요(예: `/usr/bin:/bin`). 
파일 경로 없이 명령(예: `myprogram`, `ls`)이 지정되면(그리고 그것이 앨리어스, 함수, 빌트인, 키워드가 아니면) bash는 `PATH`의 디렉터리들을 검색해요.
디렉터리는 왼쪽에서 오른쪽으로 순서대로 검색하면서 주어진 이름의 실행 파일이 있는지 확인해요.

실행 파일이 알려진 경로 밖에 있다면 그 실행 파일의 경로를 지정해야 해요.
현재 디렉터리에 있는 `myprogram` 실행 파일이라면 `./myprogram`을 사용하고, `/opt/somedirectory` 디렉터리에 있다면 `/opt/somedirectory/myprogram`을 사용해요.

팁: `type` 명령으로 그 명령에 대한 자세한 정보를 얻을 수 있어요.

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## 스크립트

_스크립트_는 파일에 저장된 일련의 명령이에요.
Bash는 파일을 읽고 명령을 순서대로 처리해요.
현재 명령이 끝나야만 다음 명령으로 넘어가요.
예외는 명령이 비동기로(백그라운드에서) 실행되도록 지정된 경우예요.
이 경우는 아직 너무 걱정하지 마세요. 나중에 어떻게 동작하는지 배워요.

이 안내서의 모든 명령줄 예시는 스크립트에서도 사용할 수 있어요.

스크립트를 만드는 건 쉬워요.
새 파일을 만든 다음 첫 줄에 이렇게 적어 봐요.

```bash
#!/bin/bash
```

이 줄을 _인터프리터 지시문_이라고 해요(_해시뱅_ 또는 **_셰뱅_**이라고도 하죠).
이 줄은 파일이 명령의 실행 파일로 사용될 때 `/bin/bash`를 인터프리터로 쓰라고 지정해요.
OS의 커널이 _바이너리가 아닌 파일_을 실행할 때는 파일의 첫 줄을 읽어요.
그 줄이 `#!`로 시작하면 커널은 그 줄을 보고 파일을 넘겨줄 인터프리터를 결정해요.
(이 외에도 유효한 방법이 있어요. 아래를 봐요.)
`#!`는 파일의 맨 처음에 있어야 하고, 앞에 스페이스나 빈 줄이 있으면 안 돼요.
우리 스크립트의 명령은 이 줄 아래에 각각 다른 줄로 나타나요.

팁: `#!/bin/bash` 대신 다음과 같이 쓸 수도 있어요.

```bash
#!/usr/bin/env bash
```

`env`는 첫 번째 인자로 주어진 이름(여기서는 "bash")의 실행 파일을 `$PATH`에서 찾아요.
이 기법에 대한 더 자세한 설명과 평범한 `#!/bin/bash`와 어떻게 다른지는 [StackOverflow의 이 질문][env bash]을 봐요.

인터넷에 있는 스크립트나 예시가 인터프리터로 `/bin/sh`를 쓴다고 해서 속지 마세요.
**`sh`는 `bash`가 아니에요!**
Bash 자체는 "sh 호환" 셸이라서 대부분의 `sh` 스크립트를 실행할 수 있고 같은 문법을 많이 담고 있어요.
하지만 그 반대는 성립하지 않아요. bash의 일부 기능은 `sh`에서 깨지거나 예상치 못한 동작을 일으켜요.
사실 단 하나의 `sh` 셸이라는 것은 없어요.
POSIX-sh 문법을 지원하는 셸 구현이 아주 많아요.
OS에 따라 `sh`를 실행했을 때 실제로는 bash, ash, dash 또는 다른 셸이 실행될 수 있어요.

스크립트 파일을 만들었으면 이렇게 실행할 수 있어요.

```bash
$ bash myscript
```

이 예시에서는 `bash`라는 _명령_을 실행하면서 인자로 넘긴 스크립트를 읽으라고 알려 주는 거예요.
이렇게 실행하면 `#!` 줄은 그냥 _주석_일 뿐이에요.

다른 방법으로는 스크립트에 실행 권한을 줄 수 있어요.
이 방법을 쓰면 bash를 직접 호출하는 대신 다른 실행 파일처럼 스크립트를 실행할 수 있어요.

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

이렇게 명령을 실행하면 운영 체제(OS)가 `#!` 줄을 보고 스크립트를 실행할 인터프리터를 결정해요.
