# 맵과 집합

배열은 값을 번호가 붙은 자리에 담아요. 그런데 때로는 쓸모 있는 이름표가 숫자가 아닐 때도 있어요.

## 맵

**맵**은 각 **키**를 **타깃**과 짝지어요. 키로 무언가를 찾으면, 맵은 그 키 아래에 넣어 둔 것을 돌려줘요.

`FMAP{K,T}`는 `K` 타입 키에서 `T` 타입 타깃으로 가는 맵이에요. 동물 이름과 사는 곳을 짝지어 둔 guide는 `FMAP{STR,STR}`이에요.

```sather
   guide ::= #FMAP{STR,STR};
   guide := guide.insert("emu", "grassland");
   guide.get("emu")               -- "grassland"
```

## 결과는 항상 다시 대입해요

가운데 줄을 다시 봐요. `insert`는 그 쌍이 추가된 맵을 결과로 돌려주고, 그 결과를 꼭 받아 둬야 해요.

```sather
   guide := guide.insert("emu", "grassland");     -- yes
   guide.insert("emu", "grassland");              -- no: the answer is lost
```

`FSTR`에서와 같은 규칙이고, 이유도 같아요. 결과는 보통 들어간 그 맵 자체가 제자리에서 바뀐 것이지만, 가끔 맵에 자리가 다 차면 더 큰 맵이에요. 어느 쪽인지 알 수 없으니, **결과를 쓰고 예전 이름은 그만 쓰세요.** `insert` 이전에 남은 이름은 오래된 것일 수도 있고, 애초에 쓸 수 있는 맵을 가리키지 않을 수도 있어요.

그 말은 루틴에 넘긴 맵도 그 루틴으로부터 안전하지 않다는 뜻이에요. 원본이 살아남아야 한다면 개념 페이지의 `copy`를 봐요.

## 키가 있을까요?

`has_ind`는 어떤 키가 맵 안에 있는지 물어봐요. 이 이름은 "has index"를 줄인 것으로, 여기서 인덱스는 이 맵들이 키라고 부르는 것을 뜻해요.

```sather
   guide.has_ind("emu")           -- true
   guide.has_ind("moa")           -- false
```

없는 키를 찾아도 **불평하지 않아요**. `get`은 그 타입의 빈 값을 돌려줘요. `INT`라면 0이고, `STR`이라면 void인데, 이건 나중에 다른 곳에서 문제를 일으켜요. 그러니 가져오기 전에 먼저 확인해요.

```sather
   if guide.has_ind(animal) then
      return guide.get(animal);
   else
      return "Unknown";
   end;
```

## 집합

**집합**은 중복도 순서도 없이 값을 담아요. `FSET{T}`는 `T` 타입 값들의 집합이에요.

```sather
   seen ::= #FSET{STR};
   seen := seen.insert("emu");
   seen := seen.insert("emu");    -- already there; nothing changes
   seen.size                      -- 1
   seen.has("emu")                -- true
```

같은 것을 두 번 넣어도 하나만 남아요. 집합은 바로 이런 용도예요. 무엇인가를 모으면서, 그것이 몇 번 나왔는지는 잊는 거예요.

집합의 `insert`도 맵과 똑같이, 그다음부터 쓸 집합을 결과로 돌려줘요. 그러니 매번 다시 대입해요.

## 몇 개일까요

`.size`는 둘 다에서 동작해요. 맵이 담고 있는 쌍이 몇 개인지, 집합에 값이 몇 개 들어 있는지 알려줘요.
