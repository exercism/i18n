# 테스트 러너 만들기

테스트 러너는 다음과 같은 일을 가능하게 해 주는 꼭 필요한 도구예요:

- 웹사이트에서 제출한 풀이가 모든 테스트를 통과했는지 자동으로 확인할 수 있어요.
- 학습자가 [온라인 에디터](/docs/using/solving-exercises/using-the-online-editor)로 ([CLI 없이도](/docs/using/solving-exercises/working-locally)) 연습 문제를 풀 수 있어요.

테스트 러너를 만들기 시작하려면 [테스트 러너를 처음부터 만들기](/docs/building/tooling/test-runners/creating-from-scratch) 문서를 확인해 보세요.

## 구현

트랙 도구는 보통 (대부분) 트랙의 언어로 작성해요.

```exercism/caution
다른 언어를 사용해도 괜찮지만, 언어가 하나 늘어날 때마다 트랙을 유지보수하거나 기여하기가 더 어려워져요.
따라서 가능하면 트랙의 언어를 사용하는 걸 권장해요. 유지보수와 기여가 더 쉬워지기 때문이에요.
```

## 배포

테스트 러너는 [Docker 컨테이너](/docs/building/tooling/docker)로 패키징해서 실행해요.
테스트 러너 Docker 이미지는 [GitHub Actions 워크플로](https://github.com/exercism/generic-test-runner/blob/main/.github/workflows/docker.yml)를 사용해 자동으로 배포돼요.

## 테스트

테스트 러너를 만들고 나면, 트랙의 CI 설정에서 그 Docker 이미지를 사용해 트랙의 연습 문제를 검증할 수 있어요.
이 방식의 가장 큰 장점은 실제 운영 환경을 더 잘 흉내 낸다는 점이에요. 다시 말해, 운영 환경에서도 잘 동작한다고 더 안심할 수 있어요.
단점이 될 수도 있는 점은 CI 워크플로가 느려질 수 있다는 거예요.
어떤 방식이 트랙에 가장 잘 맞는지는 유지보수자가 결정하면 돼요.
