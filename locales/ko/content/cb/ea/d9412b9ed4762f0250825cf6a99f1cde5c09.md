# 계약

루틴의 인자와 반환 타입은 어떤 *종류*의 것이 들어오고 나가는지를 말해 줘요. 하지만 무게가 반드시 양수여야 한다거나, 하네스가 실제로 가진 것보다 더 많은 여유 용량을 보고한 적이 없다는 것까지는 말해 주지 못해요.

**계약**은 그런 것들을 루틴의 헤더 자체에 명시해서, 읽는 사람 누구나 볼 수 있게 해요.

## pre

`pre`는 루틴이 호출될 때 참이어야 하는 것을 명시해요. 반환 타입과 `is` 사이에 위치해요.

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

이는 **호출자**에 대한 요구 사항이에요. 음수 load로 이 루틴을 호출하면 안 돼요.

## post

`post`는 루틴이 답할 때 참이 될 것을 명시해요. 그 안에서 `result`는 반환되는 값이에요.

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

이는 호출자에 대한 약속이에요. 둘 다 가진 루틴은 일종의 거래예요. 이것을 주면 저것을 준다는 뜻이죠.

여러 조건은 여느 불리언처럼 `and`로 결합해요.

```sather
      pre load >= 0 and load <= limit
```

## 계약은 예외가 아니에요

던져진 예외는 일어날 수 있는 일을 위한 것이에요. 깨진 계약은 **버그**를 뜻해요. 누군가 루틴을 잘못 호출했거나, 루틴이 말한 대로 하지 않은 거예요.

그래서 계약이 깨져도 잡을 수 있는 무언가를 던지지 않아요. 계약 검사를 켜면 프로그램이 멈추고 어느 루틴인지, 어느 조건인지 출력해요. 끄면 그 조건은 검사조차 되지 않고, 프로그램은 이어지는 온갖 엉뚱한 결과 속으로 계속 실행돼요.

그래서 계약은 잘못된 입력을 처리하는 방법이라기보다 정확성에 대한 진술이에요. 잘못된 입력이 예상되는 것이라면, 검사한 뒤 `raise`해요. 잘못된 입력이 호출자가 잘못했다는 뜻이라면, `pre`로 그렇게 밝혀요.

## 검사 켜기

이 Sather는 컴파일러에 `-chk`를 주면 계약을 검사해요.

```
sacomp -chk mine.sa -main MAIN -o mine
```

이 옵션이 없으면 `pre`와 `post`는 컴파일러가 읽고 형식이 올바르다고 확인한 문서일 뿐, 그 이상은 아니에요. 이 연습 문제의 테스트는 `-chk` 없이 빌드되기 때문에, 깨진 계약을 대신 잡아 주지 못해요. 테스트는 루틴을 올바르게 사용했을 때 제대로 동작하는지를 확인해요.
