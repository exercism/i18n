# 트레이트

트레이트는 타입이 구현할 수 있는 메서드의 집합을 지정해요.
트레이트는 타입들 사이에서 공유되어야 하는 메서드를 정의할 때 유용해요.
트레이트를 제네릭 타입과 함께 사용하면, 정의된 메서드를 특정 타입에서 호출할 수 있을 뿐만 아니라 다른 데이터 타입에서도 호출할 수 있어요.
추상적으로 말하면, _트레이트 바운드_를 사용해서 제네릭 타입이 특정 동작을 공유하도록 지정할 수 있어요.

> **참고:** 트레이트는 다른 프로그래밍 언어에서 인터페이스라고 알려진 것과 비슷한 기능을 공유하지만, 몇 가지 차이점이 있어요.

## 트레이트 정의

트레이트를 정의하면, 어떤 타입이 결과를 얻기 위해 구현할 수 있는 동작들의 집합을 이루는 함수 시그니처를 파악하는 데 도움이 돼요.
이 메서드들이 타입의 동작을 구성해요.
서로 다른 타입에서 같은 메서드를 호출할 수 있다면, 관련된 타입들이 같은 동작을 가진다는 뜻이에요.

```rust
#[derive(Drop)]
pub struct NewsArticle {
    pub headline: ByteArray,
    pub location: ByteArray,
    pub author: ByteArray,
    pub content: ByteArray,
}

// A trait for NewsArticle struct type
pub trait Summary {
    fn summarize(self: @NewsArticle) -> ByteArray;
}
```

위의 `Summary` 트레이트 정의에 따르면, `summarize` 메서드는 `NewsArticle` 구조체 타입에서만 호출할 수 있는 동작이에요.
다른 타입의 인스턴스에서 호출하면 컴파일 오류가 발생해요.
`pub` 키워드로 트레이트를 선언하면 이 크레이트의 트레이트가, 이 트레이트를 활용하려는 다른 크레이트에도 노출돼요.
트레이트에서 메서드 시그니처를 선언한 뒤에는 세미콜론을 쓴다는 점도 눈여겨봐요.

트레이트는 제네릭 인자를 사용해 정의할 수도 있는데, 그러면 함수가 어떤 데이터 타입의 인자든 받을 수 있어요.
이는 함수 시그니처에 유연성을 더해 다양한 데이터 타입을 다룰 수 있게 해줘요.
아래 `Summary` 트레이트의 경우, 어떤 데이터 타입에서도 동작하도록 다시 설계되어서 `summarize` 메서드를 호출하면 `ByteArray`를 반환해요.

```rust
// A trait for a generic type
pub trait Summary<T> {
    fn summarize(self: @T) -> ByteArray;
}
```

트레이트는 본문에 메서드를 하나 이상 가질 수 있어요. 선언된 각 메서드 시그니처는 세미콜론으로 끝나는 한 줄짜리예요.

## 타입에 트레이트 구현하기

트레이트를 구성하는 함수 시그니처를 정의한 뒤에는, 컴파일러가 트레이트를 채택한 타입들에 대해서도 구현이 정의되도록 강제해요.
아래에는 `NewsArticle`과 `Tweet` 인스턴스에서 일부 데이터를 요약하는 미디어 `aggregator` 라이브러리 크레이트를 작성했어요.
`NewsArticle` 구조체의 경우 headline, author, location 타입을 사용해 `Summary` 트레이트의 `summarize` 메서드 값을 반환하고, `Tweet` 구조체의 경우 username과 content를 사용한다고 가정하는데, 트윗 내용에는 280자 제한이 있다고 가정해요.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray;
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {
        fn summarize(self: @NewsArticle) -> ByteArray {
            format!("{} by {} ({})", self.headline, self.author, self.location)
        }
    }

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    let tweet = Tweet {
        username: "EliBenSasson",
        content: "Crypto is full of short-term maximizing projects. \n @Starknet and @StarkWareLtd are about long-term vision maximization.",
        reply: false,
        retweet: false
    };

    println!("New article available! {}", news.summarize());
    println!("New tweet! {}", tweet.summarize());
}
```

## 기본 구현

때로는 트레이트를 구성하는 메서드 일부 또는 전부에 대해 기본 구현을 함께 정의할 수 있어요.
이는 모든 타입에서 모든 메서드를 구현하도록 요구하지 않아도 되고 코드 가독성도 좋아져요.
특정 타입이 트레이트 메서드의 특별한 구현을 필요로 하면 기본 구현을 재정의할 수 있어요.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray {
            "(Read more...)"
        }
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {}

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    println!("New article available! {}", news.summarize()); // prints "New article available! (Read more...)"


    let tweet = Tweet {
        username: "Alice",
        content: "Cairo is fun and engaging.",
        reply: true,
        retweet: true,
    };
    println!("New tweet from {}", tweet.summarize()); // prints "New tweet from Alice: Cairo is fun and engaging."
}
```

## 외부 트레이트를 사용하고 관리하는 방법

트레이트와 구현은 외부 모듈에 정의해서 다른 모듈에서 사용할 수 있어요. 올바르게 가져오기만 하면 돼요.
`Circle`과 `Rectangle` 구조체 모두에 구현해야 하는 `boundary` 메서드를 가진 `ShapeGeometry` 트레이트가 있다고 해봐요.
아래는 트레이트와 구현을 모듈 간에 가져오고, 관리하고, 사용하는 방법의 예예요.

```rust
// Here T is an alias type which will be provided during implementation
pub trait ShapeGeometry<T> {
    fn boundary(self: T) -> u64;
    fn area(self: T) -> u64;
}

mod rectangle {
    // Importing ShapeGeometry is required to implement this trait for Rectangle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Rectangle {
        pub height: u64,
        pub width: u64,
    }

    // Implementation RectangleGeometry passes in <Rectangle>
    // to implement the trait for that type
    impl RectangleGeometry of ShapeGeometry<Rectangle> {
        fn boundary(self: Rectangle) -> u64 {
            2 * (self.height + self.width)
        }
        fn area(self: Rectangle) -> u64 {
            self.height * self.width
        }
    }
}

mod circle {
    // Importing ShapeGeometry is required to implement this trait for Circle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Circle {
        pub radius: u64
    }

    // Implementation CircleGeometry passes in <Circle>
    // to implement the imported trait for that type
    impl CircleGeometry of ShapeGeometry<Circle> {
        fn boundary(self: Circle) -> u64 {
            (2 * 314 * self.radius) / 100
        }
        fn area(self: Circle) -> u64 {
            (314 * self.radius * self.radius) / 100
        }
    }
}

use rectangle::Rectangle;
use circle::Circle;

fn main() {
    let rect = Rectangle { height: 5, width: 7 };
    println!("Rectangle area: {}", ShapeGeometry::area(rect)); //35
    println!("Rectangle boundary: {}", ShapeGeometry::boundary(rect)); //24

    let circ = Circle { radius: 5 };
    println!("Circle area: {}", ShapeGeometry::area(circ)); //78
    println!("Circle boundary: {}", ShapeGeometry::boundary(circ)); //31
}
```

`CircleGeometry`와 `RectangleGeometry`의 구현 가시성은 public일 필요가 없어요. `ShapeGeometry` 트레이트가 public으로 만들어져 컴파일러가 쉽게 찾을 수 있기 때문이에요.

## Impl 별칭

구현은 가져올 때 `impl` 키워드를 사용해 별칭을 붙일 수 있어요.
이는 구체 타입에 대해 제네릭 구현을 인스턴스화할 때 도움이 돼요.
`One` 트레이트를 구현하는 모든 타입에 대해, `One`의 값을 두 번 더한 뒤 그 합을 반환하는 간단한 `Two` 트레이트 구현을 정의해봐요.
그런 다음 `u8`과 `u128` 타입에서만 동작하는 `Two` 구현을 노출할 수 있어요.

```rust
trait Two<T> {
    fn two() -> T;
}

mod one_based {
    pub impl TwoImpl<
        T, +Copy<T>, +Drop<T>, +Add<T>, impl One: core::num::traits::One<T>
    > of super::Two<T> {
        fn two() -> T {
            One::one() + One::one()
        }
    }
}

pub impl U8Two = one_based::TwoImpl<u8>;
pub impl U128Two = one_based::TwoImpl<u128>;
```

제네릭 구현은 비공개 모듈에 작성할 수 있고, impl 별칭을 사용하면 이 두 구체 타입의 제네릭 구현을 인스턴스화할 수 있어요.
비공개로 노출되지 않은 제네릭 구현을 사용하면 파일 간 코드 중복을 막을 수 있다는 장점이 있어요.
또한 public API를 단순하고 깔끔하게 유지해줘요.
