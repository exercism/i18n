# 개요

[concept:csharp/resource-cleanup]()는 `IDispose` 인터페이스를 사용해서, 어떤 객체가 더 이상 필요하지 않게 되었을 때 적절한 시점에 해제하거나 초기화해야 할 자원이나 프로그램 상태가 있다는 사실을 그 클래스의 호출자에게 알려줘요. 이 연습 문제에서는 `using` 키워드라는 문법적 편의 기능을 도입했어요. 덕분에 코드가 더 간결해지고, 중요한 호출을 빠뜨릴 가능성도 줄어들어요.

`using`은 일부 사용 사례에서 [`try/finally`][try-finally]를 대체하는 것으로 볼 수 있어요.

```csharp
File file = null;
try
{
    file = new File("myStuff.txt");
    file.Write("more stuff");
}
finally
{
    file.Dispose();
}
```

이 문법은 더 간결하고 실수할 여지가 적은 다음 형태로 대체돼요.

```csharp
using (var file = new File("myStuff.txt")
{
    file.Write("more stuff");
}
```

한 줄 블록에 대한 일반적인 규칙을 따라 여러 자원을 편리하게 조합할 수도 있어요.

```csharp
using (var file = new File("mystuff.txt")
using (var fileWriter = new StreamWriter(file)
{
     ...
}
```

C# 8에서는 `using` 문이 블록의 시작에 오는 다음과 같은 변형이 도입됐어요.

```csharp
using var file = new File("myStuff.txt");
file.Write("more stuff");
```

이 방식은 같은 블록 안에 여러 개의 Dispose 가능한 객체를 둘 수 있게 해 주고, [`try/catch`][try-catch]를 더 자연스럽게 다룰 수 있게 해줘요.

```csharp
using var fileIn = new File("myStuff.txt");
using var fileOut = new File("yourStuff.txt");
try
{
    var stuff = fileIn.Read();
    fileOut.Write(stuff);
}
catch (Exception)
{
    LogStuff();
}
```

`using` 키워드를 어떻게 사용할 수 있는지, 그리고 어떤 종류의 타입 인스턴스와 함께 쓸 수 있는지에 대한 규칙은 [여기][using-statement]에 자세히 나와 있어요.

## Java 개발자를 위한 참고 사항

Java 개발자라면 Java 7에서 도입된 [_자동 자원 관리_][automatic-resource-management] 메커니즘과 비슷하다는 것을 알아챌지도 몰라요. 둘은 아주 비슷해요. `try`를 재활용하는 Java의 문법은, C#의 `using`보다 `catch` 블록을 더 자연스럽게 통합할 수 있다는 장점이 있어요.

## 버전

자체적인 문법 블록을 갖지 않는, 더 유연한 버전의 `using`은 C# 8에서 도입됐어요. 그래서 작업 중인 코드베이스가 C# 8 이상을 사용하는지 확인해야 할 수도 있어요.
