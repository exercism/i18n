# 지침

친구 Linus는 도시 사이에서 화물 열차를 운전하는 기관사예요.
Linus는 열차를 다루는 일은 정말 잘하지만, 물류나 컴퓨터를 다루는 일은 잘하지 못해요.
그래서 열차 정보를 정리하고 경로 데이터의 실수를 바로잡는 일에 프로그래밍 도움을 받고 싶어 해요.

~~~~exercism/note
이 연습 문제는 슬라이싱, 인덱싱, 그리고 다양한 `hash` 메서드를 사용하면 쉽게 풀 수 있어요.
하지만 아래 각 과제를 풀 때에는 패킹, 언패킹, 다중 할당을 연습해 보는 것이 목표예요.
~~~~

## 1. 모든 화차를 담은 배열 만들기

Linus는 화차 식별자(ID)를 하나하나 기록해 왔지만, 시스템이 한 번에 몇 대의 화차를 처리해야 할지는 전혀 알 수 없어요.
이 데이터를 하나의 **배열**로 묶어 두면 나머지 물류 프로그램이 훨씬 쉽게 처리할 수 있어요.

임의의 개수만큼 화차 ID를 받는 `generate_list_of_wagons()` 메서드를 구현해요.
각 ID는 양의 정수예요.
그런 다음 메서드는 주어진 ID들을 하나의 **배열**로 `return`해야 해요.

```ruby
LocomotiveEngineer.generate_list_of_wagons(1, 7, 12, 3, 14, 8, 5)
# => [1, 7, 12, 3, 14, 8, 5]
```

## 2. 화차 배열 바로잡기

이쯤 되면 데이터와 물류 프로그램에서 데이터가 어떻게 쓰이는지 감이 잡히기 시작할 거예요.
ID 시스템은 항상 기관차에 **1**이라는 ID를 부여하고, 열차의 나머지 화차에는 **1**보다 큰 임의의 ID를 부여해요.

Linus는 열차에 새 화차 두 대를 연결하고는 시스템을 업데이트하는 걸 잊었어요!
이제 열차 **배열**의 맨 앞 두 화차를 끝으로 옮겨야 해요. 그렇지 않으면 모든 순서가 엉망이 돼요.

게다가 Linus는 빠진 화차 ID가 들어 있는 것 같은 두 번째 **배열**을 방금 발견했어요.
새 화차를 옮기고 나면, 이 두 번째 **배열**의 ID들을 지정된 기관차 바로 뒤에 놓아야 한다는 것만 기억하고 있어요.

Linus는 실수를 고치고 데이터를 하나로 합쳐 주면 정말 고마워할 거예요.

화차 ID가 담긴 두 개의 **배열**을 받는 `fix_list_of_wagons()` 메서드를 구현해요.
이 메서드는 첫 번째 **배열**의 처음 두 항목을 끝으로 옮기고, 두 번째 **배열**의 값들을 기관차 ID(**1**) 뒤(_오른쪽_)에 삽입해야 해요.
그런 다음 메서드는 수정된 **배열**을 `return`해야 해요.

```ruby
LocomotiveEngineer.fix_list_of_wagons([2, 5, 1, 7, 4, 12, 6, 3, 13], [3, 17, 6, 15])
# => [1, 3, 17, 6, 15, 7, 4, 12, 6, 3, 13, 2, 5]
```

## 3. 빠진 정차역 추가하기

이제 화차 데이터가 모두 올바르니, Linus는 시스템의 경로 정보를 업데이트해 주기를 바라요.
운송 경로를 따라가다 보면, 열차가 화물을 싣거나 내리기 위해 여러 역에 정차할 수 있어요.
여정마다 이러한 중간 배송 지점의 개수가 다를 수 있어요.
Linus는 빠졌거나 추가된 배송 정보로 시스템의 경로 **해시**를 업데이트해 주기를 바라요.

경로 **해시**와 그 뒤에 오는 가변 개수의 키워드 인자를 받는 `add_missing_stops()` 메서드를 구현해요.
이 인자들은 하나 이상의 정차역을 담은 **해시** 형태일 수도 있고, `stop_<number>: "city"` 형태의 키워드 쌍 여러 개일 수도 있어요.
그런 다음 메서드는 추가된 모든 정차역을 순서대로 담은 **키**가 더해진 경로 **해시**를 반환해야 해요.

```ruby
LocomotiveEngineer.add_missing_stops({from: "New York", to: "Miami"},
                    stop_1: "Washington, DC", stop_2: "Charlotte", stop_3: "Atlanta",
                    stop_4: "Jacksonville", stop_5: "Orlando")
# => {from: "New York", to: "Miami", stops: ["Washington, DC", "Charlotte", "Atlanta", "Jacksonville", "Orlando"]}
```

~~~~exercism/note
정차역은 항상 올바른 순서로 전달되니, 정렬은 걱정하지 않아도 돼요.
~~~~

## 4. 경로 정보 확장하기

Linus는 경로 프로그램을 작업하다가 일부 경로에 중요한 세부 정보가 빠져 있다는 걸 알아챘어요.
초기 경로 정보는 **해시**로 만들어져 있는데, Linus는 빠진 부분이 있으면 그 **해시**를 업데이트해 주기를 바라요.
시스템의 모든 경로는 조금씩 다른 세부 정보를 필요로 해서, Linus는 범용적인 해결책을 정말 원해요.

두 개의 **해시**를 받는 `extend_route_information()` 메서드를 구현해요.
첫 번째 **해시**에는 열차 경로가 오가는 출발지와 도착지 도시가 들어 있어요.

두 번째 **해시**에는 열차 속도, 길이, 온도 같은 다른 경로 세부 정보가 들어 있어요.
메서드는 모든 경로 정보를 하나로 합친 **해시**를 반환해야 해요.

~~~~exercism/note
두 번째 **해시**는 예시에 나온 것과 다르거나 더 많은 속성을 담을 수 있어요.
~~~~

```ruby
LocomotiveEngineer.extend_route_information({"from": "Berlin", "to": "Hamburg"}, {"length": "100", "speed": "50"})
# => {"from": "Berlin", "to": "Hamburg", "length": "100", "speed": "50"}
```
