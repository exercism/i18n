# 소개

해안 초계정에 타고 있는 *신호병*은 통신 일지를 관리해요. 가공되지 않은 신호기는 표식 문자로 테두리가 둘러진 채 들어오고, 측정값은 통신선으로 보낼 수 있게 렌더링해야 하며, 두 개나 세 개씩 묶인 관측값은 그때그때 요약돼요. Factor 표준 라이브러리에 있는 몇 가지 관용 표현이 대부분의 일을 해내요.

## `unparse`: 값을 소스로

`prettyprint`에 있는 [`unparse`][unparse]는 어떤 값이든 그 소스 형태의 텍스트를 반환해요:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse`는 파서의 역연산이에요. `dup unparse parse` 왕복을 거치면 원래 값이 복원돼요. 수신자가 다시 파싱할 전송 형식으로 직렬화할 때는 알맞은 도구지만, 사람이 읽기 좋은 출력에는 맞지 않아요 (문자열은 따옴표를 그대로 유지하고, 벡터는 `V{ ... }`를 그대로 유지하는 식이거든요).

## 슬라이스 변형: 복사가 아니라 뷰

`sequences`에 있는 `head`와 `tail`은 남겨 둘 부분을 *복사*해서 새 시퀀스에 담아요. `-slice`가 붙은 짝은 `slice` 객체를 반환해요. 이 객체는 시작 인덱스, 끝 인덱스, 바탕이 되는 시퀀스를 담은 튜플로, 복사 없이 [시퀀스 프로토콜][sequence-protocol]을 구현해요:

| 워드          | 효과                                          |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )`: 처음 n개를 복사           |
| `head-slice`  | `( seq n -- slice )`: 처음 n개의 뷰           |
| `tail`        | `( seq n -- newseq )`: 인덱스 n부터 복사   |
| `tail-slice`  | `( seq n -- slice )`: 인덱스 n부터의 뷰      |
| `head*`       | `( seq n -- newseq )`: 마지막 n개를 뺀 나머지를 복사    |
| `head-slice*` | `( seq n -- slice )`: 마지막 n개를 뺀 나머지의 뷰    |
| `tail*`       | `( seq n -- newseq )`: 마지막 n개를 복사            |
| `tail-slice*` | `( seq n -- slice )`: 마지막 n개의 뷰            |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

`slice`는 *그 자체로* 시퀀스라서, 시퀀스를 받는 것은 무엇이든 슬라이스를 받아요. `length`, `first`, `each` 등이 모두 복사 없이 동작해요. 리터럴 문자열과 비교해야 하는 테스트라면 `>string`으로 강제 변환하면 돼요.

## `?head`와 `?tail`: 표식이 있으면 벗겨내기

테두리가 둘러진 측정값에는 있을 수도 있고 없을 수도 있는 표식 텍스트가 붙어 있어요. `splitting`에 있는 `?head`와 `?tail`은 접두사나 접미사를 벗겨내려고 시도하면서, (짧아졌을 수도 있는) 시퀀스*와* 표식을 찾았는지 알려 주는 불리언을 함께 반환해요:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

뒤따르는 불리언 덕분에 이 둘은 가드에 잘 어울려요. `?head`를 `if`와 짝지으면 프레임이 있었는지에 따라 분기할 수 있고, `unless`와 짝지으면 기대한 표식이 없는 입력을 걸러낼 수 있어요.

## `<repetition>`: N개 복사본을 가상으로

`sequences`에 있는 [`<repetition>`][repetition]은 또 하나의 복사 없는 가상 시퀀스예요. `( len elt -- repetition )`은 모두 `elt`인 `len`개의 요소로 이루어진 시퀀스를, 그만큼의 슬롯을 할당하지 않고 만들어요:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

`elt` 자체가 시퀀스일 수도 있어요. 그러면 각 복사본이 바로 그 시퀀스예요. `concat`은 복사본들을 처음부터 끝까지 이어 붙여요:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

`slice`와 마찬가지로 결과는 *그 자체로* 시퀀스예요. `length`, `each` 같은 것들이 바로 동작해요. 신호 부호를 고정 폭으로 채우거나 반복되는 표식을 죽 늘어놓고 싶을 때 쓰면 돼요. 실제로 구체적인 시퀀스가 필요할 때만 `>string`(또는 `>array`)으로 강제 변환해요.

## `<clumps>`: 겹치는 창을 가상으로

`grouping`에 있는 [`<clumps>`][clumps]는 세 번째 복사 없는 가상 시퀀스예요. `( seq n -- clumps )`는 `seq`를 그 위에 *겹쳐지는* 길이 `n`의 창들이 이어진 것으로 바라보고, 각 창은 슬라이스예요:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

길이가 n인 시퀀스에서는 `length - n + 1`개의 창이 나와요. 각 창이 슬라이스라서 연속한 측정값을 짝지어도 복사 비용이 들지 않아요. 각 `2`-clump에 `[ first2 ]`를 적용하면 투영해 볼 수 있는 모든 연속한 쌍을 얻어요. (겹치지 않는 사촌인 `<groups>`는 시퀀스를 서로 겹치지 않는 블록으로 잘라요.)

## 다중 입력 클리브: `2bi`, `3bi`, `2tri`, `3tri`

기본 클리브 워드인 `bi`와 `tri`는 *하나*의 입력에 두 개 또는 세 개의 쿼테이션을 적용해요. `2`가 붙은 변형과 `3`이 붙은 변형은 각 쿼테이션을 *두 개* 또는 *세 개*의 입력에 적용해요:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

각 쿼테이션은 입력을 *전부* 받아요. 같은 값 쌍(또는 세 값)에 둘 이상의 투영이 달려 있을 때 이 워드들을 써요. 각 입력에 *같은* 연산을 따로따로 적용하려는 때가 아니라요 (그건 `bi@`나 `tri@`를 써요).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
