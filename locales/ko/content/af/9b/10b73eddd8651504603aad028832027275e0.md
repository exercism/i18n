# 테스트

테스트를 실행하려면 `cmake -G`를 실행한 다음, 사용하는 플랫폼에 맞는 빌드 명령을 실행해야 해요.
자세한 방법은 exercism.org의 C++ [테스트 실행하기][cpp-tests-instructions] 페이지에서 확인할 수 있어요.

## 테스트 통과하기

로컬에서 새 연습 문제를 시작하면, 첫 번째 테스트만 실행되도록 파일이 설정되어 있어요.
[테스트 주도 개발의 세 가지 규칙][three-laws-of-tdd]을 따라 첫 번째 테스트가 컴파일되고 링크되고 통과하도록 만들어 봐요.
컴파일러 오류를 해결하고 테스트가 실패하도록 만들 만큼만 네임스페이스, 함수, 클래스 등을 선언해서 구조를 만들어요.
그다음에는 테스트가 통과할 만큼만 코드를 작성해요.
이렇게 했다면, `if defined(EXERCISM_RUN_ALL_TESTS)` 줄을 다음 테스트 뒤로 옮겨서 다음 테스트의 주석을 풀어요.

아래는 Bob 연습 문제의 예시예요 (`bob_test.cpp` 파일, 15번째 줄):

```diff
-#if defined(EXERCISM_RUN_ALL_TESTS)
TEST_CASE("shouting")
{
    REQUIRE("Whoa, chill out!" == bob::hey("WATCH OUT!"));
}
+#if defined(EXERCISM_RUN_ALL_TESTS)
```

이 줄을 다음 테스트 뒤로 옮기면, 아직 선언하거나 정의하지 않은 새로운 구문이 쓰여서 컴파일 오류가 생길 수 있어요.
이때도 마찬가지로, 컴파일 오류를 최소한으로 고쳐서 실패하는 테스트를 만들고, 테스트를 통과할 만큼만 코드를 최소한으로 바꾼 다음, 가독성과 표현력을 위해 구현을 리팩터링하고 나서 다음 테스트로 넘어가요.

저수준 알고리즘이나 기능을 직접 손으로 작성하기보다는 표준 C++17에서 제공하는 기능을 사용해 봐요.
