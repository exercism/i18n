# 개요

속성의 두 가지 주요 유형은 다음과 같아요.

1. `get`과 `set` 접근자에 본문이 없는 자동 구현 속성이에요.
   명시적으로 초기화할 수도 있고, 하지 않을 수도 있어요. 예를 들면:
   ```csharp
   public int MyProperty {get; set;} = 42;
   ```
2. 접근자가 식을 평가하고 문을 실행하는 속성이에요. 코드는
   지원 필드를 반환하거나 할당하는 것처럼 간단할 수 있어요. 예를 들면:
   ```csharp
   private int myField;
   public int MyProperty
   {
     get { return myField; }
     set { myField = value; }
   }
   ```

속성과 메서드 사이에는 동작과 기능 면에서 상당히 겹치는 부분이 있어요.
자동 구현 속성이 아닌 경우, 속성에는 클래스의 범위 안에 나타날 수 있는 모든 문이나 식을
담을 수 있어요. 흔히 지원 필드를 감싸는 것이라고 설명하기도 해요.
대부분의 경우 특정 상황에서 동작을 속성으로 코딩할지 메서드로 코딩할지는 명확하지만,
특히 접근자 안에서 코드를 얼마나 실행해야 할지는 코더가 판단할 몫인 경우가
많아요. set 접근자의 유효성 검사와
get 접근자의 간단한 계산이나 서식 지정은 흔히 볼 수 있어요:

```csharp
private float fraction;
public float Percentage
{
  get { return fraction * 100; }
  set
  {
    if (value < 0 || value > 100)
    {
      throw new ArgumentException("Percentage must be between 0 and 100");
    }
    fraction = value / 100;
  }
}
```

다른 클래스 멤버와 마찬가지로 속성도 접근 수준을 가질 수 있어요.
대부분 속성은 본래의 목적에 맞게 private이 아닌 접근 수준을 가져요. 때로는 접근자 중 하나가
속성과 다른 접근 수준을 가질 수 있어요. 다소 인위적인 "보안" 제약 아래에 있던 `TareWeight`의
경우에는 private getter를 가진 public 속성을 둘 수 있는 여지가 있었어요. 즉, 클래스 외부의
코드는 속성 값을 설정할 수 있지만, 값을 읽는 것(get)은 클래스 내부의 코드만
할 수 있어요.

```csharp
public int ConfidentialValueUsedInternally {private get; set; }
```

public이 아닌 set 접근자도 지원하지만, 더 흔한 경우는
set 접근자를 아예 생략하는 것이에요. 이는 아마도
클래스의 생성자에서 속성 값을 설정하기 때문일 거예요.

```csharp
class MyClass
{
  public MyClass( int importantValue)
  {
    ConstructedValue = importantValue;
  }
  public int ConstructedValue {get;}
}
```

이번 연습 문제에서는 속성의 기본적인 사용법을 다뤘어요. 더 고급 주제는
다른 연습 문제에서 찾아볼 수 있어요:

- 식 본문 속성, get 접근자와 set 접근자 (식 본문 멤버에서 다뤄요)
- 인터페이스의 속성 (인터페이스에서 다뤄요)
- 추상 클래스의 속성/추상 속성 (상속에서 다뤄요)
- 속성에 `readonly` 키워드 사용하기 (불변성에서 다뤄요)
- 정적 속성 (정적에서 다뤄요)
- 인덱서 (인덱서에서 다뤄요)
