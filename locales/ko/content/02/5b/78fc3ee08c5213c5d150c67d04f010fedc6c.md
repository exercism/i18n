# 힌트
`Option`은 유용한 결과가 없을 수도 있는 계산을 나타낼 때 사용해요
(예를 들어 오류나 잘못된 입력 때문일 수 있어요).
`Option`이 낯설다면 [이 튜토리얼](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html)을 읽어봐요.
`Option`은 이른바 [모나드](https://en.wikipedia.org/wiki/Monad_(functional_programming))로, "계산적 측면"을 다뤄요. 여기서는 값이 없을 가능성 말이에요.
모나드를 제대로 사용하면 아주 간결하면서도 우아하고 읽기 좋은 코드를 만들 수 있어요. 잘못 사용하면 반대로 되기 십상이죠.
더 알아보려면 [이 영상](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA)을 봐요.
## 피해야 할 흔한 함정
`Option`에는 몇 가지 경험칙이 있어요:
1. 필요하지 않다면 쓰지 마세요. 이렇게 쓰기보다는
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
이렇게 쓰는 게 더 좋아요
```scala
def add1(x: Int): Int = x + 1
```
(이런 단순한 함수를 적용할 때는 `Option.map`이 있으니, 굳이 `Option`으로 코드를 어지럽힐 필요가 없어요.)
2. 정말 필요하지 않다면 "unwrap"하지 마세요.
원하는 목적에 딱 맞는 내장 함수가 있는 경우가 많아요. 성급하게 값을 꺼내고 있다는 신호는 `isDefined/isEmpty`나 패턴 매칭이에요. 이렇게 쓰기보다는
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
이렇게 쓰는 게 더 좋아요
```scala
x map (_ + 1) getOrElse 0
```
3. 모나드는 for 컴프리헨션 안에서 쓰면 아주 좋아요.
여러 `Option` 인스턴스를 "조합"하고 싶을 때 이 방법이 좋아요. 이렇게 쓰기보다는
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
이렇게 쓰는 게 더 좋아요
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
