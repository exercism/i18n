# 제너레이터

`generator`는 [`generator iterator`][generator-iterator]라고 불리는 특별한 종류의 [이터레이터][iterator]를 반환하는 함수나 표현식이에요.
`Generator-iterator`는 [게으른 평가][lazy iterator]를 따르는데, `values`를 메모리에 저장해 두지 않고 필요할 때 값들을 _생성_해요.

제너레이터 함수는 다른 함수와 똑같이 생겼지만, 하나 이상의 [yield 표현식][yield expression]을 포함해요.
`yield`를 만나면 코드 실행이 잠시 멈추고, 현재 실행 상태(_모든 지역 변수와 try 문을 포함한_)를 저장해요.
제너레이터가 다시 실행되면, 중단된 지점의 상태를 그대로 이어받아요. 호출할 때마다 초기화되는 일반 함수와는 다르죠.


## 제너레이터 만들기

제너레이터는 다른 반복문이나 재귀 함수와 비슷하게 만들지만, [`yield` 표현식](#the-yield-expression)이 필요해요. 이건 조금 뒤에 자세히 살펴볼게요.

예를 들어 주어진 숫자 목록에서 각 숫자의 _제곱_을 반환하는 함수를 생각해 봐요.
지금처럼 작성하면, 값을 하나라도 반환하기 전에 모든 입력을 다 처리해야 해요:

```python
>>> def squares(list_of_numbers):
...     squares = []
...     for number in list_of_numbers:
...         squares.append(number ** 2)
...     return squares
```

이 함수를 다음과 같이 제너레이터로 바꿀 수 있어요:

```python
>>> def squares_generator(list_of_numbers):
...     for number in list_of_numbers:
...         yield number ** 2
```

이렇게 하는 이유는, 모든 값을 _한꺼번에_ 만들 필요가 없을 때 제너레이터를 쓰기 때문이에요.
_지금 작업 중인_ 값만 계산하니 메모리와 처리 성능을 아낄 수 있죠.


## 제너레이터 사용하기

제너레이터는 Python에서 대부분의 `iterables` 대신 사용할 수 있어요.
`iterable`이나 `iterator`를 인자로 요구하는 _함수_나 _객체_도 마찬가지죠.

`squares_generator()` 제너레이터를 사용하려면 이렇게 해요:

```python
>>> squared_numbers = squares_generator([1, 2, 3, 4])

>>> for square in squared_numbers:
...     print(square)
...
1
4
9
16
```

`generator` 안의 값은 `next()` 함수로도 꺼내거나 접근할 수 있어요.
`next()`는 제너레이터-이터레이터 객체의 `__next__()` 메서드를 호출해서 코드를 `yield` 표현식까지 "진행"시키거나 평가하고, 그러면 값 하나를 "yield"하거나 반환해요:

```python
>>> squared_numbers = squares_generator([1, 2])

>>> next(squared_numbers)
1
>>> next(squared_numbers)
4
```

`generator-iterator`를 끝까지 다 써서 더 반환할 값이 없으면, `StopIteration` 오류를 던져요.

```python
>>> next(squared_numbers)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
StopIteration
```


~~~~exercism/note

제너레이터-이터레이터는 [이터레이터][iterator]의 특별한 부분집합이에요.
`Iterators`는 _이터러블_을 반복할 수 있게 해 주는 메커니즘, 즉 프로토콜이에요.
제너레이터-이터레이터와 일반적인 Python [`iterables`][iterables]가 반환하는 이터레이터는 아주 비슷하게 동작하지만, 몇 가지 중요한 차이점이 있어요:

- _[게으르게 평가][lazy evaluation]_되는데, 반복은 _한 방향_으로만 진행되고 이전 값으로 "되돌아가는" 방법이 없어요.
- 반환된 값들을 반복하면 _소모_되어 버려요. 메모리에 다시 저장하거나 초기화하지 않죠.
- 정렬할 수 없고, 순서를 뒤집을 수도 없어요.
- 시퀀스 타입이 아니고 `indexes`가 _없어요_. 
  덧셈이나 뺄셈으로 이전 값이나 이후 값을 참조할 수 없고, 대괄호(`[]`) 표기법이나 슬라이싱도 쓸 수 없어요.
- 길이가 없어서 `len()` 함수와 함께 쓸 수 없어요.
- _유한_할 수도 있고 _무한_할 수도 있어요. _무한_ `generator-iterator`에서 값을 전부 모을 때는 조심해요!

## yield 표현식

[yield 표현식][yield expression]은 `return` 표현식과 아주 비슷해요.
`return` 표현식과는 _달리_, `yield`는 _특정 지점_에서 호출한 쪽에 값을 넘겨주고, 그 값들이 다시 요청될 때까지 추가 값의 평가와 반환을 멈춰요.
`yield`가 평가되면, 감싸고 있는 함수의 실행을 잠시 멈추고 _그 시점의_ 함수 값들을 반환해요.
그러면 함수는 _스코프에 그대로 남아 있고_, `__next__()`가 호출되면 다시 `yield`를 만날 때까지 실행을 이어가요.


~~~~exercism/note
함수 밖에서는 `yield` 표현식을 사용할 수 없어요.
~~~~

```python
>>> def infinite_sequence():
...     current_number = 0
...     while True:
...         yield current_number
...         current_number += 1

>>> lets_try = infinite_sequence()
>>> lets_try.__next__()
0
>>> lets_try.__next__()
1
```


## 제너레이터는 왜 만들까요?

제너레이터는 여러 곳에서 유용하게 쓰여요.

값이 아주 많을 수도 있는 컬렉션을 다룰 때는, 그 값들을 전부 메모리에 올리고 싶지 않을 수 있어요.
제너레이터를 쓰면 큰 데이터를 조각조각 처리하면서 메모리를 아끼고 성능을 높일 수 있죠.

처리나 계산이 _복잡_하거나 _비용이 많이 들_거나 _무한_할 때도 제너레이터가 아주 유용해요:

```python
>>> def infinite_sequence():
...     current_number = 0
...     while True:
...         yield current_number
...         current_number += 1
```

이제 `infinite_sequence` 객체에 `__next__()`를 호출할 때마다 _이전 숫자_ + 1을 반환해요.
