# 소유권

Cairo에서 소유권이라는 개념은 변수가 담고 있는 _값_이 아니라 _변수_ 자체에 붙어 있어요.

Cairo의 값은 불변이에요. 이 불변성 덕분에 여러 변수가 같은 값을 가리키더라도 값 자체는 변하지 않고 그대로 유지돼요.
그래서 컴파일러는 프로그래머가 값들을 올바르게 사용하는지 보장해야 해요.
이것이 변수 _소유권_의 의미예요. 소유자란 변수를 읽을 수 있는(가변이면 쓸 수도 있는) 코드를 말해요.

## 변수 소유권 규칙

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## 변수 스코프

스코프는 프로그램 안에서 변수가 유효한 범위예요.
부호 없는 정수 타입의 변수 `x`를 선언하고, 변수가 어디에서 유효한지 주석으로 표시한 다음 예제를 살펴봐요:

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

참고:

- `x`가 스코프에 들어오면 유효해요.
- 스코프를 벗어날 때까지, 여기서는 `main()` 함수가 끝날 때까지 유효해요.

## 값 이동

이동은 값이 다른 함수로 전달될 때 일어나요. 값을 가리키던 원래 변수는 파괴되어 쓸모없어지고, 같은 값을 담을 새로운 변수가 만들어져요.

배열은 다른 함수로 전달할 때 이동되는 복합 타입의 한 예예요.
배열이 어떻게 생겼는지 짧게 다시 살펴볼까요:

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

타입 시스템은 Cairo 프로그램이 같은 메모리 셀에 두 번 쓰려고 시도하지 않도록 어떻게 보장할까요?
배열의 앞부분을 두 번 제거하려고 하는 다음 코드를 살펴봐요:

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

이 경우 같은 값(`arr` 변수의 배열)을 두 함수 호출에 모두 전달하려고 해요.
이것은 코드가 첫 번째 원소를 두 번 제거하려 한다는 뜻이고, 이는 같은 메모리 셀에 두 번 쓰려는 것과 같아요. 이런 동작은 Cairo VM이 금지하기 때문에 런타임 오류로 이어져요.
다행히 이 코드는 실제로 컴파일되지 않아요.
배열을 `foo` 함수에 전달하고 나면 변수 `arr`은 더 이상 사용할 수 없어요.
`Array`가 `Copy` 트레이트를 구현해야 한다는 컴파일 타임 오류가 나와요:

## Copy 트레이트

타입이 `Copy` 트레이트를 구현하면, 함수에 전달해도 값이 이동하지 않고 같은 값을 가리키는 새 변수가 만들어져요.
변수는 Cairo의 추상화이고 값은 항상 불변이기 때문에 이것은 공짜 연산이에요.

타입에 `Copy` 트레이트를 구현하려면 타입 정의에 `#[derive(Copy)]` 애너테이션을 추가해요.
하지만 타입이나 그 구성 요소 중 하나라도 `Copy` 트레이트를 구현하지 않으면 Cairo는 이를 허용하지 않아요.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## 값 파괴

선형 타입은 파괴됨으로써도 활용될 수 있는데, 이는 관련된 자원이 올바르게 해제되도록 보장해요.
이는 `Drop` 트레이트를 구현하거나 derive함으로써 이루어져요. 이 트레이트는 더 이상 쓸모없어지면 타입을 안전하게 파괴할 수 있다고 컴파일러에 알려줘요.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

현재 `Drop` 구현은 모든 타입에 대해 derive할 수 있어요. 단, 딕셔너리(`Felt252Dict`)와 딕셔너리를 포함하는 타입은 예외예요.
왜냐하면 딕셔너리는 파괴될 때 "스쿼시"되어야 하기 때문이에요.
이를 위해 `Destruct` 트레이트를 derive해요:

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## 반환 값과 스코프

값을 반환하는 것은 값을 이동하는 것과 같아요.
아래 예제는 어떤 값을 반환하는 함수의 예를 보여줘요:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
