# 소개

## 메서드 집합으로서의 인터페이스

가장 단순한 형태에서 **인터페이스 타입**은 메서드 시그니처의 집합이에요.
다음은 `Add`와 `Value` 두 메서드를 포함하는 인터페이스 정의의 예예요:

```go
type Counter interface {
    Add(increment int)
    Value() int
}
```

`increment` 같은 매개변수 이름은 인터페이스 정의에서 생략할 수 있지만, 이름을 붙이면 가독성이 좋아지는 경우가 많아요.

Go에서 인터페이스 이름에는 `Interface`나 `I`라는 단어를 넣지 않아요.
대신 `er`로 끝나는 경우가 많아요. 예를 들어 `Reader`, `Stringer` 같은 식이에요.

## 인터페이스 구현하기

인터페이스의 메서드들을 정의한 타입은 자동으로, 암묵적으로 그 인터페이스를 "구현"해요.
Go에는 `implements` 키워드가 없어요.

다음 타입은 위에서 본 `Counter` 인터페이스를 구현해요.

```go
type Stats struct {
    value int
    // ...
}

func (s Stats) Add(v int) {
    s.value += v
}

func (s Stats) Value() int {
    return s.value
}

func (s Stats) SomeOtherMethod() {
    // The type can have additional methods not mentioned in the interface.
}
```

인터페이스를 구현하는 데에는 메서드가 값 리시버를 가지는지 포인터 리시버를 가지는지는 상관없어요.
(이 부분이 확실하지 않다면 [메서드 개념][concept-methods]을 다시 살펴봐요.)

> 인터페이스 타입의 값은 그 메서드들을 구현하는 어떤 값이든 담을 수 있어요. [^1]

즉, 이제 `Stats`는 `Counter` 인터페이스를 기대하는 모든 곳에서 사용할 수 있어요.

```go
func SetUpAnalytics(counter Counter) {
    // ...
}

stats := Stats{}
SetUpAnalytics(stats)
// works because Stats implements Counter
```

인터페이스는 암묵적으로 구현되기 때문에, 타입은 여러 인터페이스를 손쉽게 구현할 수 있어요.
필요한 메서드들을 모두 정의하기만 하면 돼요.

## 빈 인터페이스

Go에는 아주 특별한 인터페이스 타입이 하나 있는데, 메서드를 하나도 포함하지 않는 **빈 인터페이스** 타입이에요.
빈 인터페이스는 이렇게 써요: `interface{}`.
`any`는 `interface{}`의 별칭이며, 더 흔히 사용돼요.

빈 인터페이스는 메서드가 없기 때문에, 모든 타입이 이를 암묵적으로 구현해요.
이 점은 어떤 값이든 일반적으로 받을 수 있는 함수를 정의할 때 유용해요.
이 경우 함수 매개변수는 빈 인터페이스 타입을 사용해요.
