# 개요

`Result` 타입을 사용하면 함수가 다음 정보를 모두 담은 하나의 값을 반환할 수 있어요:
- 작업이 성공했는지 실패했는지
- 성공한 경우, 작업의 결과 값
- 실패한 경우, 실패한 이유

`Result` 타입과 같은 기능을 지원하지 않는 다른 프로그래밍 언어에서는 앞서 말한 목표를 이루기 위해 다음과 같은 패턴을 흔히 볼 수 있어요:
- 성공 여부나 실패 이유를 나타내는 숫자 코드를 반환하고, 성공한 경우의 값을 받기 위한 출력 매개변수를 함께 요구하는 함수.
- 성공하면 값을 반환하고 오류가 나면 NULL을 반환하는 함수, 그리고 실패 이유를 나타내는 오류 코드를 가져오는 또 다른 함수.

또 다른 흔한 오류 처리 방식은 예외예요. 예외는 실패가 발생하면 현재 함수에서 곧바로 빠져나와 호출 스택의 첫 번째 핸들러로 제어를 넘겨요.  
어떤 핸들러도 예외를 "잡지" 못하면 프로그램은 중단돼요.

## `Result` 타입을 사용하면 좋은 점

* __컴파일 타임 안전성__: 함수 호출의 성공 또는 실패를 타입 시스템에서 명시적으로 드러내면, 컴파일러는 호출하는 쪽 코드가 모든 실패 경우를 처리하도록 보장할 수 있어요. 이로써 null 때문에 생길 수 있는 큰 범주의 버그를 막을 수 있어요.

* __런타임 안전성__: `Result` 타입은 `null` 대신 `Error`로 실패를 나타내기 때문에 `NullReferenceException`이 발생하는 일 자체가 불가능해요.

* __명시적인 오류 처리__: `Result`를 반환하는 함수를 호출하는 코드는 그 호출이 실패할 수 있음을 인정해야 하고, 실패를 의도적으로 처리해야 해요.  조용히 넘어가는 실패도, 뜻밖의 예외도 없어요.

* __예측 가능한 제어 흐름__: `Result`는 다른 값과 똑같이 반환돼요. 예외처럼 호출 스택을 뛰쳐나가지 않아요.  오류가 어디서 시작되고 어떻게 전파되는지 항상 알 수 있어요.

* __나아진 가독성과 유지보수성__: `Result`를 반환하면 함수 시그니처만 보고도 성공과 실패 때 기대되는 동작이 분명하게 드러나요.

## 사용법

`Result` 타입은 두 가지 하위 타입을 담는 제네릭 타입이에요:
- 성공한 작업의 결과 값 타입
- 실패했을 때 실패 이유를 나타내는 타입

`Result` 타입은 [판별 공용체][discriminated-union]이기도 하고, 다음과 같은 경우를 가질 수 있어요:
* `Ok <value>`는 성공한 결과를 나타내요
* `Error <reason>`는 실패를 나타내요

다음 함수는 `Result` 값을 만드는 방법을 보여줘요:

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

이 예에서 `Ok` 값은 문자열(주어진 이름)이고, `Error` 값도 문자열(사람이 읽을 수 있는 형태의 오류 원인)이에요.

## `Result` 값의 내용 읽기

다음 타입 정의와 함수 시그니처를 살펴봐요:

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

`openFile` 함수를 호출하는 코드는 다음 예처럼 패턴 매칭으로 성공과 실패 경우를 처리할 수 있어요:

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
