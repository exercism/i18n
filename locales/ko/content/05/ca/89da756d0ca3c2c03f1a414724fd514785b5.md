# 테스트

각 연습 문제에는 단위 테스트와 그것을 빌드하고 실행하는 데 필요한 모든 것이 함께 들어 있어요.
구현은 직접 작성해요.

## 테스트 실행하기

연습 문제 폴더에서 터미널을 열고 다음을 실행해요.

```
make
```

이 명령은 솔루션과 테스트를 컴파일한 뒤 테스트를 실행해요.
솔루션을 수정할 때마다 다시 실행해요.

[Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally)가 있다면 대신 이 명령을 사용할 수 있어요. 이 명령은 `make`도 함께 실행해요.

```
exercism test
```

빌드로 만들어진 파일을 지우려면 `make clean`을 실행해요.

### make 없이 하기

`make`가 없는 경우(예를 들어 Windows)에는 테스트를 직접 컴파일하고 실행할 수 있어요.
"Bob" 연습 문제라면 다음과 같아요.

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

그다음 Linux나 macOS에서는 이렇게 테스트를 실행해요.

```
./run_tests
```

Windows에서는 이렇게 실행해요.

```
.\run_tests
```

## 연습 문제 풀어 나가기

각 연습 문제의 파일 이름은 연습 문제 이름을 따서 지어져요.
"Bob" 연습 문제를 예로 들면 다음과 같아요.

| 파일 | 내용 |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90` | 완성하기만 하면 되는 솔루션 스텁 |
| `bob_test.f90` | 테스트 |
| `TesterMain.f90` | 테스트 라이브러리 |
| `Makefile` | `make`를 위한 지시 사항 |
| `CMakeLists.txt` | 선택 사항인 [CMake](#using-cmake-instead)를 위한 지시 사항 |

수정해야 하는 파일은 솔루션 파일 하나뿐이에요.

모든 테스트가 통과할 때까지 다음 단계를 반복하면서 연습 문제를 풀어 나가요.

- 컴파일 오류가 있으면 고친 뒤 테스트를 실행해서 어떤 테스트가 실패하는지 확인해요.
- 다음으로 실패하는 테스트가 통과할 만큼만 구현해요.
- 가독성을 높이고 중복을 줄이도록 구현을 리팩터링해요.
- 테스트를 다시 실행하고 다음으로 실패하는 테스트로 넘어가요.

실패한 테스트마다 메시지가 출력되고, 마지막에는 요약이 나와요.
테스트가 하나라도 실패하면 `make`는 오류와 함께 끝나요.

각 테스트에는 테스트를 설명하는 주석이 먼저 나오고, 그다음 `call assert_equal`로 시작하는 실제 테스트가 나와요. 예를 들면 다음과 같아요.

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

테스트를 비활성화하려면 `'!'`로 주석 처리하면 돼요. 예를 들면 다음과 같아요.

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## 대신 CMake 사용하기

CMake는 꼭 필요하지는 않지만, Visual Studio나 Xcode 같은 IDE에서 작업하거나 GFortran이 아닌 다른 컴파일러를 쓴다면 유용할 수 있어요.

CMake는 폴더 이름으로 소스 파일을 찾기 때문에, 연습 문제 폴더는 원래 이름을 그대로 유지해야 해요.
연습 문제 폴더에서 시작해요.

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

솔루션을 수정한 뒤에는 마지막 두 명령만 실행하면 돼요.

**참고:** `cmake`는 항상 `build`처럼 별도의 폴더에서 실행해요.
연습 문제 폴더에서 `cmake .`를 실행하면 연습 문제에 함께 들어 있는 `Makefile`이 덮어써져요.

CMake는 시스템에 맞는 제너레이터를 알아서 골라요.
다른 제너레이터를 쓰려면 `-G` 옵션을 사용해요. 예를 들어 `cmake -G Xcode ..`처럼요.
사용할 수 있는 제너레이터 목록은 `cmake --help`를 실행하면 볼 수 있어요.
Visual Studio나 Xcode를 쓴다면 `ctest -V -C Debug`로 테스트를 실행해요.

연습 문제 폴더에 `Makefile`이 없다면, 그 폴더는 이 파일들이 연습 문제에 추가되기 전에 내려받은 거예요.
그래도 CMake는 계속 사용할 수 있어요.
