# 자세히 알아보기

C#의 대표적인 객체 지향 구성 요소는 데이터([_필드_][fields])와 동작([_메서드_][methods])을 결합한 _클래스_예요. 클래스의 필드와 메서드를 _멤버_라고 해요.

멤버에 대한 접근은 접근 한정자를 통해 제한할 수 있는데, 가장 흔히 쓰이는 두 가지는 다음과 같아요:

- [`public`][public]: 어떤 코드든 접근할 수 있어요(제한 없음).
- [`private`][private]: 같은 클래스 안의 코드만 접근할 수 있어요.

모든 멤버에 접근 한정자를 지정하는 것이 관례예요. 접근 한정자를 지정하지 않으면 기본적으로 `private`이 돼요.

앞에서 말한 것처럼 관련 있는 데이터와 동작을 묶고 멤버에 대한 접근을 제한하는 것을 [캡슐화][encapsulation]라고 하며, 이는 객체 지향의 핵심 개념 중 하나예요.

어느 한 시점에 객체가 가진 필드 값들의 조합을 객체의 [상태][object-state]라고 해요.

클래스는 그 클래스의 인스턴스를 만들기 위한 틀이라고 생각하면 돼요. 클래스의 인스턴스(즉 _객체_)를 [만들려면][creating-objects] [`new` 키워드][new]를 사용해요:

```csharp
class Car
{
}

// Create two car instances
var myCar = new Car();
var yourCar = new Car();
```

[필드][fields]는 타입을 가지며 클래스 어디에서든 정의할 수 있어요.
public 필드는 [파스칼 표기법][pascal-case]으로, private 필드는 [카멜 표기법][camel-case]으로 정의하고 앞에 밑줄 `_`을 붙여요:

```csharp
class Car
{
    // Accessible by anyone
    public int Weight;

    // Only accessible by code in this class
    private string _color;
}
```

필드에는 선택적으로 초깃값을 지정할 수 있어요. 필드에 초깃값을 지정하지 _않으면_, 해당 타입의 [기본값][default-values]으로 설정돼요. 인스턴스의 필드 값은 점 표기법으로 접근하고 갱신할 수 있어요.

```csharp
class Car
{
    // Will be set to specified value
    public int Weight = 2500;

    // Will be set to default value (0)
    public int Year;
}

var newCar = new Car();
newCar.Weight; // => 2500
newCar.Year;   // => 0

// Update value of the field
newCar.Year = 2018;
```

private 필드는 보통 메서드를 호출할 때의 부수 효과로 갱신돼요. 이런 메서드는 보통 아무 값도 반환하지 않는데, 이 경우 반환 타입은 [`void`][void]여야 해요:

```csharp
class CarImporter
{
    private int _carsImported;

    public void ImportCars(int numberOfCars)
    {
        // Update private field
        _carsImported = _carsImported + numberOfCars;
    }
}
```

C# 클래스에서는 public 필드를 사용하는 것이 관례가 아니라는 점에 유의해요. private 필드를 사용하거나, 이후 연습 문제에서 다룰 다른 종류의 멤버를 사용해요.

클래스 안에서 [`this` 키워드][this]는 현재 클래스를 가리켜요. 이는 매개변수가 필드와 같은 이름을 가질 때 특히 유용해요:

```csharp
class CarImporter
{
    private int carsImported;

    public void SetImportedCars(int carsImported)
    {
        // Update private field from public method
        this.carsImported = carsImported;
    }
}
```

클래스와 메서드 구조는 필드나 메서드 같은 프로그램 요소의 가시성을 제한하고 잘 알려진 [전역 상태 문제][so-global-state-problem]를 피할 수 있는 자연스러운 방법을 제공해요. public 필드, 메서드 및 기타 멤버가 클래스 외부의 코드에서 보이려면 객체 이름, 즉 `object.field`나 `object.method()`(정적인 경우에는 클래스 이름)로 한정해야 해요. 메서드 안에서 선언한 변수와 매개변수는 그 메서드 안에서만 보여요.

이 방식에서 조심할 점은, 필드 이름과 메서드 안의 변수 또는 매개변수 이름이 같으면 메서드 안의 코드에서는 필드 이름이 무시된다는 것이고, 이는 원하는 동작이 아닐 수 있어요. 일반적으로 생성자에서는 흔한 패턴이지만, 가능하면 이런 상황을 피하는 게 좋아요. 필드와 변수 이름을 같게 두는 것이 적절하다면 메서드 안에서 `this` 키워드로 필드 이름을 한정해요.

이 [접근 한정자][access-modifiers]를 사용하면 가시성을 더 제한할 수 있어요.
