# 기여 가이드라인

Pharo 트랙 개발에 참여하고 싶다면, 시작하는 데 도움이 될 아래 안내를 따라 주세요.

우리는 이 트랙을 개선하고 개발자들에게 코딩에 대해 색다른 사고방식을 보여주고 싶어요! :tada:

[Exercism 트랙에 참여하는 방법](https://github.com/exercism/docs/tree/master/contributing-to-language-tracks)을 읽어 보시고, [Exercism 행동 강령](https://exercism.io/code-of-conduct)도 꼭 읽어 주세요.

모든 종류의 풀 리퀘스트를 환영해요. 아무리 작은 기여도 환영하며, 특히 기존 연습 문제를 수정하고 개선하는 기여를 반겨요. 이 트랙의 연습 문제는 [Exercism 전체 표준](https://github.com/exercism/docs/tree/master/language-tracks/exercises)을 따라야 하지만, 변경 방법이 확실하지 않다면 GitHub 이슈를 열어 주세요. 함께 논의해 봐요.

>__참고__: Exercism 조직은 [Exercism의 폭넓은 커뮤니티 기여를 잠정 중단](https://exercism.org/blog/freeing-our-maintainers)하기로 결정했어요. Pharo 트랙은 커뮤니티가 다소 작아서 이 방침에서 제외되었어요. (다시 말해, Pharo 트랙 기여자라면 누구나 여전히 이슈를 만들고 PR을 제출할 수 있어요.)

## 사전 지식

Pharo 개발과 [Iceberg Git](https://github.com/pharo-vcs/iceberg) 사용에 이미 [익숙하다고](./docs/RESOURCES.md) 가정해요.

## 개발 환경 설정

시작하려면 완전한 Exercism 개발 환경을 갖추고 다음 구성 요소가 설치되어 있는지 확인해야 해요:

### __Pharo 이미지와 IDE__

실제 코딩 예제를 만들려면 Pharo 개발 환경(실행 중인 Pharo 이미지, 즉 IDE)이 필요해요.

1. [PharoLauncher](https://pharo.org/download)를 사용해 `Official distributions` 카테고리에서 새롭고 안정적인 개발 이미지를 만들어 실행해요 (05/24 기준 안정 이미지는 Pharo 12.0 - 64bit (stable)예요). ([zerconf](https://get.pharo.org/)에 익숙하다면 그것을 써도 돼요.)
2. 이미지를 실행해서 모든 것이 제대로 동작하는지 테스트해요.

> __참고__: TIMEOUT 문제가 있다면 [사용자 설치 안내](./docs/INSTALLATION.md)를 참고해요.

### __git 저장소 설정__

1. 아직 하지 않았다면 GitHub에서 `https://exercism/pharo-smalltalk`를 포크해요.
2. 포크를 클론하려면 실행 중인 Pharo 이미지의 Playground에서 다음 명령을 실행해요:
```
Metacello new
 baseline: 'Exercism';
 repository: 'github://exercism/pharo-smalltalk:main/releases/latest';
 load: 'dev'
```
이렇게 하면 Pharo 트랙의 git 저장소가 실제로 클론되고 Pharo 트랙 소스 코드가 Pharo 이미지, 즉 개발 베이스라인으로 로드돼요. 클론된 저장소가 있는 로컬 폴더는 (Iceberg 설정에 따라) 다음 위치에 생겨요: `<path-to-Pharo-image>/pharo-local/iceberg/<your-id/pharo-smalltalk`.
> __참고__: Pharo 이미지 소스는 앞서 말한 디렉터리의 `src` 하위 폴더에 있는 `*.st` 파일에 동기화되어 직렬화돼요.

2. 같은 작업을 하는 다른 방법은 CLI로 포크를 클론하는 거예요: `git clone https://github.com/<your id>/pharo-smalltalk`를 GitHub 프로젝트로 클론하고, `<your id>`를 소유자 이름으로, `pharo-smalltalk`를 프로젝트 이름으로 지정해요.
그런 다음 실행 중인 Pharo 이미지의 Metacello 컨텍스트 메뉴를 사용해 Iceberg에 Metacello 베이스라인 `dev`(기본값이 아니에요)를 설치해요. (예: 방금 클론한 "pharo-smalltalk" 프로젝트를 오른쪽 클릭하고 Metacello 메뉴에서 두 번째 옵션을 선택한 뒤 `dev`를 입력해요)

3. 프로젝트를 Pharo 이미지에 로드한 후에는 이미지 변경 사항을 __저장__하는 것을 잊지 마세요 (메뉴 항목 Pharo -> Save).

__선택적 저장소__
1. 또는 `git clone https://github.com/exercism/pharo-smalltalk`를 스테이징 저장소로 클론해서, 체크인할 연습 문제와 에셋을 여기서 생성할 수 있어요(Pharo에서 코딩하는 것과는 별개예요). 이 저장소에서 Configlet 도구로 생성한 변경 사항은 로컬 포크 저장소로 복사해야 한다는 점을 기억해요. 혼동을 피하려면 `~/development/exercism/pharo-staging` 같은 경로를 쓰는 걸 추천해요(참고: 어디에 두어도 괜찮아요). 이 저장소는 꼭 필요하지는 않아요. 어떤 변경 사항을 커밋에 포함할지 확실하다면, 포크한 저장소(Pharo 이미지와 동기화되는)에서 바로 configlet 변경 사항을 생성해도 돼요.
2. Practise 연습 문제를 처음부터 작업하고 싶다면 Exercism [문제 명세](https://github.com/exercism/problem-specifications)도 클론할 수 있어요. 이것도 아래에서 설정할 exercism 워크스페이스의 하위 디렉터리에 넣어요(이 저장소는 연습 문제의 readme.md 파일을 생성하는 데 쓰이고, 권장 테스트의 참고 자료가 돼요).

### __사용하는 저장소 브랜치에 대한 참고__

`main` 브랜치는 모든 것이 병합되는 기본 개발 브랜치예요. 코드에 어떤 변경을 작업한다면 main에서 갈라진 기능 브랜치를 만들고 거기에 변경 사항을 커밋해요. 작업이 끝나면 github에서 PR을 올려 기본 저장소(Exercism/pharo-smalltalk)의 `main`에 병합되도록 해요. 이 브랜치는 예전에 `master`라고 불렸는데, __이제는 사용하지 않아요__.

### __Exercism CLI 도구 설정__

이 도구들은 Exercism 프로젝트와 상호작용하는 데 필요해요:
1. [exercism 명령줄 인터페이스](https://exercism.io/cli-walkthrough)를 설치하고, Exercism 연습 문제 개발용 디렉터리인 워크스페이스로 설정해요(예: `exercism configure -w ~/development/exercism`). 이 경로는 로컬 포크 저장소일 수도 있고 (선택 사항인) 스테이징 저장소일 수도 있어요.
2. 연습 문제 메타데이터를 생성하고 검증을 실행하기 위한 Exercism [configlet](https://github.com/exercism/configlet#usage) 린터/생성기예요. Configlet을 설치하려면 [트랙에서 사용하기](https://github.com/exercism/configlet#use-in-your-track) 문단의 안내를 따라 주세요(bin/fetch-configlet 참고).

## Exercism 연습 문제 작업하기

Exercism 조직은 Concept 연습 문제(프로그래밍 언어 이론을 설명하는)와 Practise 연습 문제를 구분해요. 아래 문단들은 지금까지는 Practise 연습 문제 기여에만 초점을 맞춰요.

### __개요__

연습 문제를 완료하는 단계:
1a. 문제 명세로부터 Practise 연습 문제를 처음부터 만들어요.
1b. 기존 Practise 연습 문제의 풀이를 작업해요.
2a. 연습 문제 풀이의 직렬화된 소스 파일을 디렉터리에 생성하고 연습 문제 메타데이터를 만들어요.
2b. 프로젝트 베이스라인을 조정해 새로 완성한 연습 문제를 프로젝트의 일부로 포함해요.
3. 저장소 포크에 변경 사항을 커밋하고 PR을 올려 변경 사항을 게시해요.

#### TLDR: Practise 연습 문제를 생성하고 내보내는 빠른 가이드
요약하면, Pharo에서 연습 문제를 생성하고 내보내기만 하면 돼요. Playground에서 실행해요:
```Smalltalk
"Obtain exercise from problem specification"
ExercismExerciseGenerator new generateExerciseFrom: 'path-to-problem-specifications/exercises/slug-name' asFileReference.

"Update exercise version within Pharo image  (with updated test cases) to output exercise directory (once you have solution class defined)"
ExercismGenerator new 
	exercisesDirReference: 'path-to-local-repository/exercises/practice' asFileReference;
	generateForExercise: 'slug-name'.
```
  > __참고__: 자세한 내용은 아래 단계에 있어요. 

![Practise 연습 문제를 완료하는 워크플로](/docs/images/overview-exercism-pharo-contribution.svg)

### __1. 새 Practise 연습 문제 만들기__
*TLDR: 연습 문제 생성과 관련된 모든 세부 사항과 API 설명은 `ExercismExerciseGenerator` 클래스의 클래스 주석에서 찾을 수 있어요.*  

__문제 저장소에서 새 연습 문제 만들기__
- 완전히 새로운 Practise 연습 문제를 시작하려면(1a단계), 문제 명세 저장소를 사용해 주어진 연습 문제의 테스트 클래스를 생성할 수 있어요. 다음을 실행해요: 
`ExercismExerciseGenerator generateFrom: <path-to-problem-specifications/exercises>` 그러면 문제 명세 저장소의 모든 연습 문제에 대한 테스트 클래스가 `ExerciseWIP` 패키지에 생성돼요.  

  > __참고__: Pharo 이미지의 메뉴 항목을 써서 같은 작업을 할 수도 있어요 (World menu -> Exercism -> Generate test cases).
- 더 구체적으로, 특정 연습 문제의 테스트 클래스는 이렇게 생성할 수 있어요: `ExercismExerciseGenerator generateExerciseFrom: '<path-to-problem-specifications/exercises/slug-name>' asFileReference`.

앞의 문장을 실행한 결과로 `ExerciseWIP` 패키지에 생성된 테스트 메서드를 가진 새 `<SlugNameTest>`(ExercismTest의 서브클래스) 테스트 클래스가 만들어져요.

__문제 저장소에서 기존 연습 문제 다시 생성하기__
기존 연습 문제(이미 풀이 패키지에 정의된, 예: `Exercise@TwoFer`)의 테스트 메서드를 다시 생성하려면 다음 코드를 사용해요. 다른 메서드(예: uuid, version 등)는 건드리지 않아요. 

 `ExercismExerciseGenerator new regenerateExerciseFrom: 'path-to-problem-specifications/exercises/exercise-slug' asFileReference`

__처음부터__  
흥미로운 아이디어가 있다면, 새 연습 문제를 추가하는 방법에 대한 문서를 참고해요.

프로젝트에 사용자 정의 연습 문제 예시가 있어요: `DieTest`를 참고해요. customData 메서드를 오버라이드하면 생성기가 관련 파일을 만들어 줘요.

참고하세요:
- 각 연습 문제는 독립적이어야 해요. 연습 문제 디렉터리 밖의 파일을 참조하지 마세요. 사용자가 연습 문제를 내려받을 때 그런 파일은 포함되지 않아요.
- 연습 문제는 [Exercism 전체 표준](https://exercism.org/docs/building/tracks/practice-exercises)을 따라야 해요.
- 연습 문제는 Pharo 핵심 라이브러리만 사용해야 해요.
- 각 연습 문제는 다음과 같아야 해요:
  - `Exercism@<ExerciseName>`이라는 최상위 프로젝트에 저장돼야 해요.
  - `<ExerciseName>Test`(CamelCase)라는 TestCase와 `<ExerciseName>`이라는 예시 풀이를 가져야 해요.
  - TestCase에는 연습 문제를 설명하는 마크다운 형식의 클래스 주석이 있어야 해요. 이 텍스트는 README.md 파일을 생성하는 데도 사용돼요.
- 연습 문제 안에 어떤 구성 파일이나 디렉터리도 커밋하지 마세요(향후 연습 문제에서 재검토될 수 있어요. 문제가 되면 알려 주세요).
- `UUIDGenerator next`를 사용해 연습 문제의 새 UUID를 생성하고, 그 값을 테스트의 `uuid` 메서드에 넣어 주세요.

> __참고__: 현재 Pharo UUID 생성기는 아쉽게도 RFC 4122 버전 4를 준수하지 않아요. 따라서 configlet으로 생성한 UUID를 사용해야 하며, 다음과 같이 실행해요: `/bin/configlet uuid`

### __2. 기존 연습 문제 작업하기__

도울 수 있는 방법은 많지만, 가장 쉽고 유용한 기여는 현재 "open" 상태인 연습 문제의 풀이를 완성하는 거예요.

  * 이미지가 exercism/pharo-smalltalk main과 최신 상태로 맞춰져 있는지 확인하고, 변경 사항이 있으면 포크로 다시 푸시해요.

  * 연습 문제는 모두 앞서 말한 문제 명세 저장소에서 자동으로 생성된 TestCase예요. ExercismWIP 패키지에서 ExercismTest의 서브클래스로 찾을 수 있어요. 이미 풀이가 있는 경우, 다시 생성된 ExercismTest가 해당 연습 문제 패키지에 이미 있을 수 있어요. ExercismWIP 패키지는 아직 배포되지 않은 새 연습 문제나 작업 중인 연습 문제에, 풀이 클래스와 함께 사용돼요.

  * 작업하고 싶은 연습 문제를 골랐다면, GitHub에 "Convert Exercise <name>"이라고 명시한 이슈를 만들어요. 그러면 다른 사람들이 어떤 연습 문제를 작업 중인지 알 수 있고, 나중에 올릴 풀 리퀘스트의 기반도 돼요.

  * 각 WIP 연습 문제에는 이미 클래스 주석에 문제 설명이 있고, 테스트를 실행하면서 TDD로 풀이를 만들어요(첫 번째 테스트를 단독으로 실행한다면 디버거에서 하면 돼요).

  * 테스트가 관용적인 Smalltalk이 아니라면 __테스트를 조정해야 할 수도 있어요__ (우리 생성기는 꽤 기본적이에요. 그렇긴 해도, 일부 수정은 업스트림 [문제 명세](https://github.com/exercism/problem-specifications) 텍스트로 되돌려 보내는 PR로 적절할 수 있어요).

  * #exercise 메서드를 오버라이드하고 난이도, 주제 등을 채워서 연습 문제의 클래스 측 메타데이터를 갱신해요. Test comment 탭(하단에 있어요)에서 TBD 텍스트를 바꿔서 Hint 텍스트도 채워 넣어요.

  * 선택한 예시의 패키지를 `Exercise@<ExerciseName>`으로 갱신해요(즉 WIP 패키지에서 옮겨요). 1b단계예요.
  * Iceberg에서 선택한 연습 문제의 이름으로 새 브랜치를 만들어요(이때 Iceberg 도구를 사용하고, 위에서 만든 이슈 번호를 입력해요).
  * 풀 리퀘스트를 제출하기 전에, Pharo 연습 문제의 모든 테스트를 실행하고 __모두 통과__하는지 확인해요.

### 테스트

가장 기본적으로, Exercism은 테스트와 [테스트 스위트](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md)를 통한 테스트가 전부예요.

Pharo exercism 연습 문제는 하위 패키지로 구성되고, 각 패키지에는 [SUunit](https://en.wikipedia.org/wiki/SUnit)과 호환되어야 하는 TestCase가 들어 있어요. SUnit은 원조 xUnit 라이브러리이며, 연습 문제에 별도의 서드파티 프레임워크는 필요하지 않아요.

연습 문제를 테스트하려면 내장 테스트 러너에서 테스트 orb를 클릭해서 실행해요. 테스트가 성공하면 orb가 초록색으로, 실패나 오류가 있으면 각각 주황색이나 빨간색으로 바뀌어요. 또는 Playground에서 직접 테스트를 실행할 수도 있어요:

```smalltalk
<ExerciseName>Test suite run. "single exercise"

AllExercismTests suite run. "all exercises"
```
> __참고:__ 직접 (생성되지 않은) 테스트 케이스를 정의하고 싶다면, 테스트 클래스의 `extra` 프로토콜에 넣을 수 있어요.
일관성을 위해 테스트 메서드에서는 `self assert: actual equals: expected`라는 테스트 매개변수 순서를 사용해요.

개발용이 아닌 이미지에서 테스트하려면 [사용자 설치 단계](./docs/INSTALLATION.md)를 따라야 해요. 그 이미지를 사용해 이후 개발 베이스라인을 테스트한다면, 최신 코드를 받기 위해 다음 개발 디렉터리를 삭제해야 할 수도 있어요:
`./pharo/pharo-local/iceberg, ./pharo/pharo-local/package-cache`

### __3. 완성된 연습 문제 게시하기__

이제 풀이를 마치고 로컬 기능 브랜치에 커밋했다면, 다음 단계를 완료해요:  
#### 연습 문제 소스 코드 생성하기
이것은 2a단계를 말해요: 풀이와 테스트 클래스의 __소스 코드__ 파일을 생성해요.

__모든 연습 문제의 출력 소스 생성하기__ 
- `ExercismGenerator generate` -> 그러면 모든 연습 문제의 소스 파일이 생성돼요. configlet의 `generate` 명령을 실행하고, 유효한 모든 연습 문제를 나열하는 `config.json`도 다시 생성해요. (또는 World menu에서 "Exercism" -> "Regenerate meta data"를 선택해요.)

#### 특정 연습 문제의 출력 소스 생성하기
- 기본 디렉터리(`repository-root/exercises/practice`)를 사용하려면
```
ExercismGenerator new generateForExercise: 'slug-name'
```

특정 연습 문제 디렉터리로 내보내야 할 때는:
```
ExercismGenerator new 
	exercisesDirReference: 'path-to-exercises/practice' asFileReference;
	generateForExercise: 'slug-name'
```

> __참고__: 
  - ExercismGenerator는 기본 config.json을 자동으로 갱신해요(없으면 새로 만들어요).
  - configlet 명령을 사용해 지정한 연습 문제의 모든 문서, 메타데이터, 파일 경로를 동기화해요. 자세한 내용은 [새 연습 문제를 추가할 때 sync 사용하기](https://github.com/exercism/configlet#using-sync-when-adding-a-new-exercise-to-a-track)를 참고해요.

####  Pharo-smalltalk 프로젝트 베이스라인 갱신하기
2b단계: `BaselineOfExercism>>exercisePackageNames` 메서드의 목록에 연습 문제 이름을 추가해서 Pharo-smalltalk 프로젝트 베이스라인을 갱신해요. 그러면 Metacello 명령으로 새 연습 문제를 포함해 프로젝트를 로드할 때 연습 문제도 함께 로드돼요.
  
#### 풀 리퀘스트 제출하기
3단계: PR을 만들기 전에 CLI 명령 `bin/configlet lint`를 실행해서 Exercism 구성 요소가 올바른지 확인해요(CI 자동화가 PR이 제출되면 어차피 린팅을 실행해요).  
모든 것이 괜찮다면 PR을 만들 수 있어요:
- 브랜치를 포크에 푸시한 다음 `exercism/pharo-Smalltalk`에 풀 리퀘스트를 만들어요 

> __마지막 세부 사항__: 

- 브랜치에서 함께 협업할 수 있도록 [유지 관리자 편집 허용](https://help.github.com/en/articles/allowing-changes-to-a-pull-request-branch-created-from-a-fork)을 활성화하는 것이 중요해요.
-  풀 리퀘스트는 하나의 연습 문제, 이슈, 또는 개념적으로 일관된 변경에 집중해야 해요. 자세한 내용은 Exercism의 [풀 리퀘스트 가이드라인](https://github.com/exercism/docs/tree/main/building/github#guides)을 참고해요.
- 자신의 PR을 계속 지켜보고, 이어지는 질문에 답해요.
- 마지막으로 수정 사항을 제출하면, 유지 관리자가 풀 리퀘스트를 병합해 최종 풀이가 사이트에 나타나게 해요.
