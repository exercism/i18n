# 지시 사항

Grand Marquee의 개막 밤이에요. 직원 모두가 한꺼번에 움직이고 있어요.
관객은 모든 문으로 쏟아져 들어오고, 여러 매표소 창구에서는 같은 티켓 롤에서 표를 팔고, 시사회는 매진에 가까워지고 있으며, 영사실에서는 릴이 계속 돌아가야 해요.

직원들이 공유하는 모든 것은 메모리 주소에 자리 잡고 있고, 테스트는 여러 스레드에서 동시에 함수를 호출해요.
값을 읽고, 바꾸고, 다시 쓰는 과정이 여러 단계로 나뉘어 있으면 그런 부하 속에서 갱신이 유실돼요. 그래서 각 함수는 갱신을 원자적으로 처리해야 해요.

이 연습 문제에서 공유되는 값은 모두 64비트 부호 있는 정수예요.

다섯 가지 과제가 있어요.

~~~~exercism/note
이 연습 문제의 갱신은 _원자적_ 명령어로 수행해야 해요.
테스트는 함수를 동시에 실행하면서 갱신이 하나도 유실되지 않는지 확인해요. 따라서 원자적이지 않은 읽기-수정-쓰기는 테스트를 통과하기 어려워요.
~~~~

## 1. 입장 인원 세기

문이 열려 있고, 각 문에서는 안내원이 표를 찢고 있어요.
들여보낸 일행은 하나의 공유 입장 집계에 더해져요. 모든 문에서 동시에 세더라도 극장 전체 인원은 정확하게 나와야 해요.

`admit_group` 함수를 구현해요. 이 함수는 일행의 인원수를 집계에 원자적으로 더해요.

이 함수는 다음 순서로 인자를 받아요.

- `admissions`: 공유 입장 집계의 메모리 주소, 64비트 부호 있는 정수예요.
- `group_size`: 일행의 인원수, 64비트 부호 있는 정수이며 항상 `0`보다 커요.

```c
admissions = 120, group_size = 4
// admissions is now 124
```

테스트는 여러 문을 통해 동시에 일행을 입장시켜요.
최종 집계는 들여보낸 모든 일행의 합과 같아야 해요.

이 함수는 반환값이 없어요.
집계는 제자리에서 갱신되어야 해요.

## 2. 릴 교체하기

영사기에는 릴이 딱 하나 장착돼요.
다음 릴을 장착하고 현재 릴을 빼내는 일은 한 동작으로 이뤄져야 해요. 영사기 앞에 영사기사가 둘이라면, 두 단계로 나뉘었을 때 같은 릴이 둘 모두에게 넘어가거나 릴 하나를 바닥에 떨어뜨릴 수 있어요.

`change_reel` 함수를 구현해요. 이 함수는 다음 릴을 원자적으로 장착하고, 장착되어 있던 릴을 반환해요.

이 함수는 다음 순서로 인자를 받아요.

- `mounted`: 장착된 릴 식별자의 메모리 주소, 64비트 부호 있는 정수예요.
- `next_reel`: 장착할 릴의 식별자, 64비트 부호 있는 정수예요.

```c
mounted = 7, next_reel = 9
// => 7, and mounted is now 9
```

이 함수는 이전에 장착되어 있던 릴의 식별자를 64비트 부호 있는 정수로 반환해요.
테스트는 여러 스레드가 같은 마운트를 통해 동시에 릴을 교체하게 하고, 넘겨준 모든 릴이 정확히 한 번씩 다시 나오는지 확인해요.

## 3. 표 한 장 팔기

모든 창구는 하나의 공유 판매 수량에서 표를 팔아요.
문에서처럼 수량을 더하기만 해서는 충분하지 않아요. 각 판매는 자신에게 주어진 번호도 알아내야 해요.
두 판매가 같은 번호를 공유해서는 안 되고, 손님들이 몰려든 뒤에는 집계가 판매된 표의 수와 정확히 같아야 해요.

`sell_ticket` 함수를 구현해요. 이 함수는 집계에 1을 원자적으로 더하고, 방금 판매한 표의 번호를 반환해요.
표 번호는 이번 판매 _이후_의 집계 값이에요. 집계가 `41`이었다면 이번 판매는 `42`번 표예요.

이 함수는 인자를 하나 받아요.

- `tickets_sold`: 공유 판매 수량의 메모리 주소, 64비트 부호 있는 정수예요.

```c
tickets_sold = 0
// => 1, and tickets_sold is now 1

tickets_sold = 41
// => 42, and tickets_sold is now 42
```

이 함수는 표 번호를 64비트 부호 있는 정수로 반환해요.
테스트는 여러 창구에서 동시에 표를 팔아요. 반환된 모든 번호는 서로 달라야 하고, 최종 집계는 판매 횟수와 같아야 해요.

## 4. 시사회 좌석 채우기

시사회에는 정해진 수의 좌석이 있고, 모든 창구에서 그 좌석을 팔아요.
좌석이 남아 있을 때만 판매가 이뤄져야 하고, 모든 창구가 같은 순간 마지막 좌석을 잡으려 해도 상영은 절대 초과 판매되어서는 안 돼요.
집계를 확인한 뒤 더하는 것을 두 단계로 나누면 그 사이에 빈틈이 생겨요. 그래서 확인과 갱신은 함께 성공하거나 함께 실패해야 해요.

`claim_seat` 함수를 구현해요. 이 함수는 좌석이 아직 남아 있을 때 다음 좌석을 원자적으로 차지해요.
좌석을 차지하면 함수는 좌석 번호를 반환하는데, 이는 이번 차지 이후의 판매된 좌석 수예요.
상영이 매진되면 `0`을 반환하고 집계는 그대로 둬요.

이 함수는 다음 순서로 인자를 받아요.

- `seats_taken`: 이미 판매된 좌석 수의 메모리 주소, 64비트 부호 있는 정수이며 `capacity`를 넘지 않아요.
- `capacity`: 상영의 좌석 수, 64비트 부호 있는 정수이며 항상 `0`보다 커요.

```c
seats_taken = 0, capacity = 150
// => 1, and seats_taken is now 1

seats_taken = 82, capacity = 150
// => 83, and seats_taken is now 83

seats_taken = 149, capacity = 150
// => 150, and seats_taken is now 150

seats_taken = 150, capacity = 150
// => 0, and seats_taken stays 150
```

이 함수는 좌석 번호를, 상영이 매진되었을 때는 `0`을 64비트 부호 있는 정수로 반환해요.

## 5. 영사실에 신경 쓰기

영사실에는 한 사람만 들어갈 수 있어요.
메모리에 있는 한 워드가 영사실이 사용 중인지 알려줘요. `0`은 비어 있음, `1`은 사용 중이에요.
직원들은 밤새 찾아오고, 저마다 안에서 할 일이 있어요. 일지에 서명하기, 영사기에 필름 끼우기, 릴 정리하기 같은 일이에요.
일이 무엇이든 영사실의 규칙은 같아요. 그 규칙을 코드로 지켜지게 하는 것이 이 과제예요. 한 번에 한 사람만, 자기 일이 시작될 때부터 끝날 때까지 안에 있어야 해요.

`visit_booth` 함수를 구현해요. 이 함수는 다음과 같아요.

1. 영사실이 비어 있을 때까지 기다려요.
2. 영사실을 차지해요.
3. 방문자의 일을 실행해요.
4. 일이 끝난 뒤, 반환하기 전에 영사실을 다시 열어요.

영사실을 다른 사람이 차지하고 있는 동안에는 `pause`로 예의 바르게 기다려야 해요.

이 함수는 다음 순서로 인자를 받아요.

- `booth`: 사용 중 표시 워드의 메모리 주소, `0` 또는 `1`인 64비트 부호 있는 정수예요.
- `task`: 방문자의 일, 매개변수를 받지 않고 반환값도 없는 함수예요.

테스트가 실행하는 일들은 영사실과 공유 일지를 들여다봐요.
즉, 영사실은 일이 진행되는 내내 사용 중이어야 하고, 모든 방문은 자기 일을 정확히 한 번만 실행해야 하며, 여러 방문자가 동시에 있어도 일지는 정확하게 기록되어야 해요.

~~~~exercism/caution
방문자의 일은 호출 규약을 따르는 평범한 함수예요.

- caller-saved 레지스터는 무엇이든 덮어쓸 수 있으므로, 일이 끝난 뒤에도 필요한 값은 호출이 건드릴 수 없는 곳에 보관해야 해요.
- 또한 호출 시점에 스택이 16바이트로 정렬되어 있기를 기대해요.

두 규칙 중 하나라도 어기면 검사 실패가 아니라 크래시로 나타날 수 있어요.
~~~~
