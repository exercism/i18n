# 힌트

## 일반

SGF 언어는 재귀적인 정의를 가지고 있어요:

```none
GameTree = "(" Sequence { GameTree } ")"
```

즉, GameTree는 `(`로 시작해서 "Sequence"(게임 노드의 목록)라는 텍스트가 이어지고, **그 뒤에 0개 이상의** 자식 GameTree가 오고, `)`로 끝나는 텍스트예요.

정규 표현식을 사용해서 SGF 텍스트를 파싱하고 싶을 수도 있어요.
하지만 게임 트리는 다른 게임 트리 안에 얼마든지 깊이 중첩될 수 있기 때문에, 표준 정규 표현식만으로는 중첩 깊이를 추적할 만큼 강력하지 않아요.

이 연습 문제를 푸는 방법은 몇 가지가 있어요:

### 상태 기계

입력 문자열을 한 문자씩 훑으면서 현재 위치를 담은 변수를 유지할 수 있어요.
현재 위치의 문자를 기준으로 파싱 중인 텍스트의 현재 상태를 추적하는 거예요.
"현재 상태"는 "속성 이름을 읽는 중"이나 "속성 값 안" 같은 것이 될 수 있어요.
이 방식에서는 추적해야 할 값이 아주 많아요.

### 파서

[PEG 기반 파서][PEG-parser]는 문법이 정의된 언어를 파싱하는 아주 좋은 방법이에요.
[LPeg][LPeg]는 PEG 파서이고 MoonScript의 필수 의존성 중 하나라서 이미 사용할 수 있어요.
파서를 사용하면 텍스트가 어떤 모양이어야 하는지 규칙을 쓸 수 있어요.
예를 들어 "속성 이름은 모두 대문자"라든지 "속성 값은 대괄호로 감싼다" 같은 식이죠.
그러면 파서가 입력 텍스트를 여러분의 규칙과 맞춰 보는 무거운 작업을 대신 해줘요.

LPeg 학습 자료 두 가지:

* lua-users 위키의 [LPeg 튜토리얼][tutorial].
* [Mastering LPeg][mastering-lpeg]는 LPeg와 Lua 자체의 저자 중 한 명이 썼어요.
  대학 교수이자 연구자라서 이 문서는 학술 논문처럼 읽혀요.
