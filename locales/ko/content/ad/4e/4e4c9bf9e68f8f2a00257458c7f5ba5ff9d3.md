# 소개

## 열거형

지금까지는 주로 숫자와 문자열을 다뤄 왔어요.
현실 세계를 모델링하려면 변수가 가질 수 있는 값을 몇 가지로 제한하고 싶을 때가 있어요.
서로 다른 이름을 가진 몇 개의 값만 가질 수 있는 전용 타입이 있으면 좋겠죠.
예를 들어 스케이트보드 공장에서 데크 소재를 단풍나무, 대나무, 플라스틱 중에서만 고르는 경우처럼요.

정수를 사용해 그 값들을 인코딩할 수도 있지만, 시스템에서 소재에 대해 잘못된 값이 들어오는지 확인하는 추가 코드를 써야 해요.
이런 [_매직 넘버_][magic numbers]는 소스 코드 전체에서 그 의미를 추적하기 어렵고, 서로 헷갈리기 쉬워요.
`enumerations`를 사용하면 표현력 있는 코드를 유도하고 의도치 않은 비교 실수를 막을 수 있어요.

## 사용 예시

이런 종류의 열거형을 가리키는 구체적인 용어는 `scoped enumeration`이에요.
아래 코드는 `DeckMaterial` `enumeration`을 작성하는 방법을 보여줘요.
정의 끝에 있는 `enum class` 키워드와 `;`에 주목해 봐요:

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
이제 스케이트 가게의 가격 계산 함수를 보고, `enumeration`에서 `enumerator`를 지정하는 스코프 지정 연산자(`::`)를 눈여겨봐요:

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## 스코프

바퀴 소재를 위한 두 번째 `enumeration`이 있다고 상상해 봐요:

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
바퀴와 데크는 모두 _플라스틱_으로 만들 수 있지만, 이 둘을 혼동할 수는 없어요.
둘은 서로 다른 _타입_이에요. `DeckMaterial`의 플라스틱과 `WheelMaterial`의 플라스틱이죠.
각 `enumeration`은 자신의 `enumerators`를 자기만의 스코프, 곧 자기만의 `namespace`에 둬요.
이런 이유로 이들을 `scoped enumerations`라고 불러요.

## 스코프가 없는 열거형
`scoped`라는 이름이 있으니 `unscoped` 열거형도 있겠다고 생각할 수 있어요. 맞아요.
`Unscoped enumerations`는 모두 같은 전역 `namespace`를 공유하기 때문에 점점 인기가 줄고 있어요.
이렇게 공유하다 보니, 위 예시의 _플라스틱_처럼 같은 `enumerators`를 가진 두 개의 `unscoped enumerations`를 만들 수는 없어요.

또한 `unscoped enumerations`는 암시적으로 정수로 변환돼요.
놀라운 결과를 보여 주는 아래 예시를 봐요:

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

`scoped enumerations`를 정수로 변환하고 싶다면 `static_cast<int>`를 사용하면 돼요.
