# 소개

## 루프

**루프**는 종료 조건이 충족될 때까지 잠재적으로 여러 번 실행되는 일련의 명령어예요.

x86-64에서는 보통 이전 레이블로 점프해서 루프를 만들어요:

```x86asm
example_loop:
    ...
    jmp example_loop
```

이전 레이블로의 무조건 점프는 항상 실행을 이 레이블로 옮겨요.
즉, 반복되는 시퀀스 밖으로 빠져나가는 다른 점프가 없다면 루프가 영원히 반복돼요.

예를 들어, 다음 루프는 끝나지 않아요:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

그리고 다음 루프는 조건이 충족되는지에 따라 끝날 수도 있어요:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

### 카운팅 루프

카운팅 루프는 거의 항상 같은 방식으로 끝나요: 카운터를 갱신하거나 두 값을 비교하는 명령어 바로 뒤에, 다시 돌지 말지를 결정하는 조건부 점프가 따라와요.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
위 코드에서 `cmp rsi, 0`은 필요하지 않아요. `sub rsi, 1`이 결과가 `0`일 때 이미 `zero flag (ZF)`를 설정하기 때문이에요.

`cmp`가 어셈블리에서 조건을 검사하는 주된 방법이긴 하지만, 많은 명령어가 플래그를 갱신해요.
예를 들어, 많은 정수 산술 또는 비트 연산 명령어는 결과가 `0`일 때 `ZF`를, 결과가 음수일 때(즉, 최상위 비트가 설정될 때) `SF`를 갱신해요.

각 명령어가 어떤 플래그에 영향을 주는지 확인하려면 [참고 자료][reference]를 참고해요.

[reference]: https://www.felixcloutier.com/x86/
~~~~

위 예제에서 `rsi`는 `0`보다 크다고 가정해요.
만약 `0`이었다면, `sub rsi, 1`은 `rsi`를 `-1`로 줄였을 거예요. `-1`은 매우 큰 부호 없는 수예요.
루프가 마침내 끝나기까지 `18,446,744,073,709,551,615`번의 반복이 더 필요했을 거예요.
또한 배열의 길이가 `0`이기 때문에, 어떤 메모리 접근도 범위를 벗어나게 돼요.

배열의 길이에 대한 보장이 없을 때는 일반적으로 두 가지 접근 방식이 있어요.

첫 번째는 종료 조건을 루프의 시작 부분으로 옮기고, 끝에 무조건 점프를 두는 거예요:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

두 번째는 루프를 시작하기 전에 길이가 0인 배열인지 한 번 검사하는 거예요:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

이 두 번째 접근 방식은 루프 본문에 분기가 더 적기 때문에 보통 첫 번째보다 더 효율적이에요.
이에 대해서는 나중에 다른 개념에서 더 배우게 될 거예요.

~~~~exercism/advanced
어떤 상황에서는 최신 CPU가 두 개의 다른 명령어를 하나의 연산으로 병합할 수 있어요.
이 최적화를 **매크로퓨전**이라고 해요.

`sub`와 `add` 같은 많은 산술 명령어는 물론 `cmp`와 `test`도 바로 뒤따르는 조건부 점프와 흔히 융합돼요.
즉, `cmp rax, rdx` 같은 명령어 바로 뒤에 조건부 점프가 오면 CPU는 보통 이를 하나의 연산으로 처리할 수 있어요.

매크로퓨전은 CPU에 따라 다르고, 어떤 명령어가 어떤 조건부 점프와 융합되는지에도 약간의 차이가 있어요.

유용한 참고 자료로는 [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch]가 있어요.
[Intel optimization reference manual][intel-opt]의 3.4.2.2절 (Optimizing for Macrofusion)에도 Intel CPU의 융합 가능한 쌍이 나와 있어요.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
