# 개요

## Julia의 불리언

참과 거짓 값은 `Bool` 타입으로 표현해요.
`Bool`에는 `true`와 `false`, 두 가지 값만 들어 있어요.

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

다른 여러 언어와 달리, Julia에는 "truthiness"라는 개념이 의도적으로 없어요. 그리고 `true`나 `false`로 평가되는 표현식만 `Bool`로 취급해요.

특히, 빈 배열이나 빈 문자열은 `false`로 해석되지 *않아요*.
빈 값에 대한 특별한 처리가 필요하다면 `isempty()` 같은 적절한 검사를 해야 해요.

## 불리언 연산자

Julia에는 세 가지 [불리언 연산자][boolean-operators]가 있어요.

`&&`는 불리언 "and"예요.
`&&`의 *양쪽* 표현식이 모두 `true`이면 `true`로 평가돼요.

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||`는 불리언 "or"예요.
`||`의 *어느 한쪽* 표현식이 `true`이면 `true`로 평가돼요.

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!`는 불리언 "not"이에요.
`true`와 `false` 값을 서로 바꿔요(반전시켜요).

```julia-repl
julia> !true
false

julia> !false
true
```

다른 많은 언어를 써 본 사람이라면 이런 연산자가 개념적으로 익숙할 거예요. 다만 정확한 문법은 언어마다 다를 수 있어요.

## 연산자 우선순위

더 복잡한 표현식에서는 `&&`가 `||`보다 [우선순위][operator-precedence]가 약간 높다는 걸 알아 두면 유용해요. *(산술 표현식에서 `*`가 `+`보다 먼저 적용되는 것과 같은 방식이에요.)*

이 규칙에 기대면 헷갈리기 쉽고 오류가 나기 쉬워요.
명확하게 하려면 괄호를 써서 의도를 분명히 밝혀요.

## 단락 평가

`true || x`라는 표현식은 `x`의 값에 따라 달라질까요? 아니면 컴파일러가 `x`를 무시할 수 있을까요?

Julia는 불리언 표현식을 왼쪽에서 오른쪽으로 평가하고, 결과가 명확해지면 멈춰요.

예를 들어 `true || x`는 `x`와 상관없이 반드시 `true`이므로 `x`는 평가되지 않아요.
마찬가지로 `false && y`는 `false`이고, `y`를 평가할 필요가 없어요.

반대로 `true && x`는 *`x`가 `true`일 때만* `true`이므로 `x`를 반드시 평가해야 해요.

비슷하게, 연산자를 여러 개 연결하면 어떻게 될까요?

```julia-repl
julia> true && false && something_else
false
```

`true && false`는 반드시 `false`이기 때문에 `something_else`는 중요하지 않고 컴파일러가 무시해요.

이 경우에 `something_else`는 변수로 존재하지도 않았지만, 이런 맥락에서 넣어도 오류가 나지 않았어요. *(의심된다면 REPL에서 직접 확인해 봐요.)*

Julia 프로그래머들은 이런 단락 평가를 런타임 문제와 엣지 케이스를 잡아내는 요령으로 자주 사용해요.

```julia
all_ok || do_something()

is_problem && do_something_else()
```

예를 들어 `do_something`은 `all_ok`가 `false`일 때 함수에서 일찍 `return`하는 일일 수도 있고, 계속 진행하기 전에 변수에 기본값을 할당하는 일일 수도 있어요.

불리언 문법을 살짝 남용하는 셈이지만, 아주 편리할 때가 있어요.

## `Bool`은 내부적으로 어떻게 동작할까요

`Bool`이 *산술* 표현식에 들어가면 `true`는 `1`, `false`는 `0`으로 해석되는데, 이는 이 값들이 저장되는 방식을 그대로 반영해요.

C 같은 저수준 언어에 익숙하다면, 이 방법을 자주 쓰는 건 *꼭* 피해요.
코드 가독성을 떨어뜨리고 디버깅을 어렵게 만들어요.

`true`인 값이 몇 개인지 빠르게 세는 방법으로 숫자 값을 쓰는 걸 가끔 보게 될 거예요.

```julia-repl
julia> true + false + true
2
```
