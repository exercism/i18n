# 린트

[configlet](/docs/building/configlet)의 주된 용도는 린트예요. 트랙의 설정 파일이 구문적으로나 의미적으로 올바르게 구성되어 있는지 확인하는 거죠. 설정이 잘못된 트랙은 제대로 동기화되지 않을 수 있고, 웹사이트에서 이상하게 보일 수 있으며, 사용자 경험이 좋지 않을 수도 있어요. 그래서 configlet의 검사는 Exercism의 무결성을 유지하는 데 중요한 역할을 해요.

## 사용법

`lint` 명령으로 트랙을 린트할 수 있어요.

```
configlet [global-options] lint [command-options]

Global options:
  -h, --help                   Show this help message and exit
      --version                Show this tool's version information and exit
  -t, --track-dir <dir>        Specify a track directory to use instead of the current directory
  -v, --verbosity <verbosity>  The verbosity of output. Allowed values: q[uiet], n[ormal], d[etailed]
```

## 규칙

다음은 검사하는 린트 규칙이에요.

### 규칙: 필수 파일이 있는지 확인

린터는 필수 파일이 모두 있는지 확인해야 해요. 연습 문제와 무관하게 반드시 있어야 하는 파일은 다음과 같아요:

- `config.json`
- `docs/ABOUT.md`
- `docs/INSTALLATION.md`
- `docs/LEARNING.md`
- `docs/RESOURCES.md`
- `docs/SNIPPET.txt`
- `docs/TESTS.md`
- `exercises/shared/.docs/help.md`
- `exercises/shared/.docs/tests.md`

개념 연습 문제에만 해당하며 반드시 있어야 하는 파일은 다음과 같아요:

- `exercises/concept/<slug>/.docs/hints.md`
- `exercises/concept/<slug>/.docs/instructions.md`
- `exercises/concept/<slug>/.docs/introduction.md`
- `exercises/concept/<slug>/.meta/config.json`

실습 연습 문제에도 비슷한 목록이 있을 예정이지만, 아직 그 명세는 정의하지 않았어요.

`config.json`에 나열된 각 개념에는 다음 파일이 있어야 해요:

- `concepts/<slug>/about.md`
- `concepts/<slug>/introduction.md`
- `concepts/<slug>/links.json`

## 용어 설명

1. **비어 있지 않은 문자열**: 공백이 아닌 문자를 하나 이상 포함하는 문자열이에요.
2. **kebab-case 문자열**: `[a-z0-9]` 범위의 문자만 포함하고, 선택적으로 대시로 구분되는 문자열이에요 (예: "two-fer"). 다음 정규 표현식과 일치해야 해요: `^[a-z0-9]+(-[a-z0-9]+)*$`
3. **Title Case 문자열**: 아래 [시카고 매뉴얼 오브 스타일의 지침](https://en.wikipedia.org/wiki/Title_case#Chicago_Manual_of_Style)을 따르는 비어 있지 않은 문자열이에요:
   - 제목과 부제목의 첫 단어와 마지막 단어는 대문자로 시작해요.
   - "주요" 단어(명사, 대명사, 동사, 형용사, 부사, 그리고 일부 접속사)는 대문자로 시작해요.
   - 접속사 _and_, _but_, _for_, _or_, _nor_는 소문자로 써요.
   - 관사 _the_, _a_, _an_은 소문자로 써요.
   - 전치사는 길이와 상관없이 소문자로 써요. 단, 강조되거나 부사적 또는 형용사적으로 쓰이거나 접속사로 쓰일 때는 예외예요.
   - _to_와 _as_는 소문자로 써요.
   - 라틴어 종명의 두 번째 부분은 소문자로 써요.
4. **Sentence Case 문자열**: 아래 [지침](https://en.wikipedia.org/wiki/Letter_case#Sentence_case)을 따르는 비어 있지 않은 문자열이에요:
   - 문장의 첫 단어와 고유 명사, 그리고 더 구체적인 규칙이 요구하는 다른 단어들은 대문자로 시작해요.
5. **유효한 `files` 패턴**: 연습 문제에서 사용하는 파일의 위치를 연습 문제 디렉터리 기준으로 지정하는 비어 있지 않은 문자열¹이에요. 패턴에는 다음 자리 표시자 중 하나를 사용할 수 있어요:

   - `%{kebab_slug}`: `kebab-case` 연습 문제 슬러그예요 (예: `bit-manipulation`)
   - `%{snake_slug}`: `snake_case` 연습 문제 슬러그예요 (예: `bit_manipulation`)
   - `%{camel_slug}`: `camelCase` 연습 문제 슬러그예요 (예: `bitManipulation`)
   - `%{pascal_slug}`: `PascalCase` 연습 문제 슬러그예요 (예: `BitManipulation`)

6. **고유한 버전 4 UUID 문자열**: 다음 조건을 모두 만족하는 문자열이에요:

   - 주어진 Exercism 트랙의 트랙 수준 `config.json` 파일에 한 번만 존재해요
   - 다른 어떤 Exercism 트랙의 트랙 수준 `config.json` 파일에도 존재하지 않아요
   - https://github.com/exercism/problem-specifications의 어떤 `canonical-data.json` 파일에도 존재하지 않아요
   - Exercism의 다른 어디에도 존재하지 않아요
   - 다음 정규 표현식과 일치해요:

   ```
   ^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$
   ```

   예를 들어, 아래 UUID는 올바른 형식이에요:

   ```
   d334ffe3-657e-4725-a950-290b284b6d9f
   ```

   `configlet uuid`를 실행하면 적절한 UUID를 생성할 수 있어요.

7. **유효한 분석기 `tag`**: `<category>:<thing>` 형식으로 작성된 비어 있지 않은 문자열¹이에요.
   `<category>` 값은 다음 중 하나여야 해요:

- `paradigm` (예: `paradigm:functional`)
- `technique` (예: `technique:recursion`)
- `construct` (예: `construct:bitwise-and`)
- `uses` (예: `uses:DateTime.add_seconds`)

`<thing>` 값은 비어 있지 않은 문자열¹이어야 해요.
