# 자세히 알아보기

어떤 값이든 오류가 될 수 있어요. `kernel`에 있는 `throw`는 신호를 보내요. 그러면 현재 워드의 스택 효과는 버려지고, 제어는 가장 가까운 바깥쪽 `recover`로 되감겨요.

```factor
[ 0 1 / ] [ "div by zero" prepend ] recover
```

`ERROR:`는 파싱 워드로, 오류 튜플 클래스*와* 생성자 워드를 한 번에 정의해요:

```factor
ERROR: not-found path ;
! defines:
!   TUPLE: not-found path ;
!   : not-found ( path -- * ) \ not-found boa throw ;
!   : not-found? ( object -- ? ) … class predicate
```

그래서 모든 사용자 정의 오류는 고유한 클래스, 오류를 던지는 친절한 생성자, 그리고 잡은 오류를 검사할 수 있는 클래스 프레디킷(`name?`)을 갖게 돼요:

```factor
[ "/missing" not-found ]
[ dup not-found? [ path>> "missing: " prepend ] [ drop "other" ] if ]
recover
```

finally 스타일 정리는 `continuations`의 `cleanup`을 참고해요. 재시작 가능한 조건은 `condition`을 참고해요.
