# 자세히 알아보기

Elm의 [사용자 정의 타입][custom-types]은 이름이 붙은 고정된 개수의 케이스를 나타내요. 각 값은 이름이 붙은 케이스 중 정확히 하나에 해당해요. 다른 언어나 맥락에서는 이런 것을 _sum types_, _discriminated unions_, _tagged unions_, _algebraic data types_라고 불러요.

이런 유니온은 케이스마다 선택적으로 데이터를 함께 담을 수 있고, 케이스마다 담는 데이터의 타입이 달라도 돼요. 케이스에 데이터가 하나도 붙지 않으면, 다른 언어에서 흔히 _enumeration_(또는 _enum_)이라고 부르는 것과 비슷해요.

사용자 정의 타입은 `type` 키워드로 정의하고, 필요한 문법도 아주 적어요. Elm 프로그래밍에서 가장 중요한 기법 중 하나로, 코드에서 가능한 값을 현실에서 유효한 값과 정확히 일치시키는 데 쓰여요. 그래서 잘못된 데이터가 끼어들 여지가 없고, [불가능한 상태는 코드로 표현할 수 없게][impossible-states] 만들어요.

```elm
-- Custom Type without associated data
type Season
    = Spring
    | Summer
    | Autumn
    | Winter

-- Custom Type with associated data
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

특정 케이스의 값은 그 이름(`Spring`)을 그대로 써서 만들 수 있어요. 케이스가 같은 모듈에 정의되어 있거나 `import SeasonModule exposing (Season(..))` 형태의 문법으로 임포트했다면 이름만 써도 되고, `import SeasonModule exposing (Season)` 형태로 임포트했다면 전체 이름(`Season.Spring`)을 써야 해요.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

사용자 정의 타입은 Elm의 모든 것과 마찬가지로 _구조적 동등성_을 가져요. 즉, 같은 케이스이면서 (선택적) 데이터까지 같은 두 값은 서로 같아요.

사용자 정의 타입을 다루는 가장 좋은 방법은 [패턴 매칭][pattern-matching]이에요.

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
