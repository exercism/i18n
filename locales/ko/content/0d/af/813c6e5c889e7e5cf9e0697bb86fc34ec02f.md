# 예외

어떤 루틴은 답을 줄 수 없어요. 테이블에 없는 prop을 달라고 하면, `count_of`는 내놓을 숫자가 없어요. 그렇다고 0을 반환할 수도 없어요. 0은 "그런 게 하나도 없다"는 뜻이지, "그런 것은 존재하지 않는다"는 뜻이 아니니까요.

**예외**는 루틴이 답을 줄 수 없다고 말하는 방식이에요.

## 예외 발생시키기

`raise`는 루틴을 중단하고, 호출한 쪽에 값을 넘겨요.

```sather
   count_of(props : FMAP{STR,INT}, prop : STR) : INT is
      if ~props.has_ind(prop) then
         raise "Unknown prop: " + prop;
      end;
      return props.get(prop);
   end;
```

`raise` 뒤에 있는 코드는 실행되지 않아요. 루틴이 반환하지 않으니 확인할 답도 없고, 답이 있었던 것처럼 호출한 쪽이 계속 진행할 방법도 없어요.

발생시키는 값은 보통 무엇이 잘못됐는지 알려 주는 문자열이에요.

## 예외 잡기

`protect`는 코드 조각을 실행하면서, 혹시 예외가 발생할까 대비해요.

```sather
   protect
      taken ::= count_of(props, prop);
      #OUT + "There are " + taken;
   when $STR then
      #OUT + "Cannot: " + exception.str;
   end;
```

아무것도 발생하지 않으면 `protect` 뒤의 부분이 실행되고 `when` 갈래는 건너뛰어요. 무언가 발생하면 `protect` 부분의 나머지는 중단되고, 대신 일치하는 `when`이 실행돼요.

`when $STR then`은 발생한 문자열을 잡아요. `exception`은 발생한 값으로, 갈래 안에서 사용할 수 있어요.

## 그대로 전달되기

예외를 잡지 않는 루틴은 그 예외에 대해 아무것도 할 필요가 없어요. 예외는 바깥으로, 호출한 모든 쪽을 거쳐, 누군가 잡을 때까지 이동해요.

```sather
   take_one(props : FMAP{STR,INT}, prop : STR) : INT is
      -- If this raises, take_one raises too. Nothing here says so.
      have ::= count_of(props, prop);
      ...
   end;
```

이것이 예외의 핵심이에요. 문제를 발견한 루틴과 그것을 어떻게 처리할지 아는 루틴은 보통 서로 다른 루틴이고, 그 사이에 있는 모든 것은 예외를 그냥 무시할 수 있어요.
