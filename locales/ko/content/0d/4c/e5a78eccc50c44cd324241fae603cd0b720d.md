# 지침

경영진이 원격 조종 자동차 프로젝트 [exercise:csharp/remote-control-competition]()에 다윈주의 원칙을 적용하기 시작했어요. 개발자들은 _Red_와 _Blue_ 두 팀으로 나뉘었고, 서로 독립적으로 설계를 개선하는 임무를 맡았어요. 다른 팀의 설계 결정에는 신경 쓸 필요가 없어요.

코드를 살펴보고, 테스트를 위해 두 팀의 작업을 가장 잘 합칠 방법을 찾아 달라는 요청을 받았어요.

## 1. 두 팀의 코드를 분리하는 더 적절한 방법 찾기

코드의 의도를 더 잘 드러낼 수 있도록 `namespaces`를 사용해 봐요.

현재 `Motor`와 `Telemetry` 같은 중요한 타입은 물론 `RemoteControlCar` 자체도 `<Color>RemoteControlCarTeam`이라는 바깥쪽 정적 클래스 안에 중첩되어 있어요. 바깥쪽 클래스의 유일한 목적은 같은 이름의 타입들이 프로그램 안에서 함께 존재할 수 있게 하는 것이에요. 이는 네임스페이스를 사용하면 더 잘 표현할 수 있어요. 다음 연습 문제에서 이런 목적에서는 `namespace`가 `static class`보다 유리하다는 것을 알게 될 거예요.

## 2. 명명 체계를 단순화하기

경영진은 정의에서는 팀을 `RedRemoteControlCarTeam`과 `BlueRemoteControlCarTeam`이라고 불러야 한다고 강하게 주장하지만, 팀을 참조할 때 이 이름은 다소 번거로워요. 자동차를 만들 때 더 짧은 식별자인 `Red`와 `Blue`를 사용할 방법을 찾아봐요.
