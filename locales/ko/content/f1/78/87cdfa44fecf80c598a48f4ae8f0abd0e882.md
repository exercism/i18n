# Unison 기초

## 텀과 함수

텀과 함수는 Unison 프로그램을 작성하는 기본 단위예요.

"텀"은 정적인 값을 부르는 말이에요. `name = expression` 형태로 정의하고, 앞에 `name : MyType` 형태의 타입 시그니처를 붙일 수도 있어요. Unison은 타입 추론을 지원하기 때문에, 간단한 정의에서는 타입 시그니처를 생략하는 경우도 볼 수 있어요.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Unison 함수는 `myFunctionName argument1 argument2 = myImplementation`처럼 생겼어요. 함수 이름으로 시작하고, 그 뒤에 공백으로 구분한 인자가 따라와요.

```
getMax a b = Nat.max a b
```

함수에는 타입 시그니처를 선택적으로 붙일 수 있어요. 오른쪽 맨 끝의 타입이 항상 함수의 최종 반환 타입이고, 각 인자는 함수 화살표 `->`로 구분해요.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

함수를 호출할 때는 함수 이름을 쓰고, 그 뒤에 인자들을 공백으로만 구분해서 나열해요.

```
maximum = getMax 1 10
```

함수를 호출할 때 Unison은 바로 오른쪽에 오는 것을 인자로 취급하려고 해요. 그래서 항상 원하는 함수 평가 순서가 나오지는 않을 수 있어요.

다음 식에서 값 `1`을 얻고 싶다고 해봐요.

```
shouldBe1 = getMax 1 10 - 10
```

이대로 쓰면 `shouldBe1`은 `0`으로 평가돼요. 암시적으로 적용되는 함수 적용 순서가 `getMax 1 10`, 즉 `10`이고, 그다음 `10 - 10`이 되어 `0`이 되기 때문이에요.

괄호를 사용하면 식을 원하는 연산 순서로 다시 묶을 수 있어요.

```
shouldBe1 = getMax 1 (10 - 10)
```

## 여러 줄 함수

Unison의 여러 줄 함수는 들여쓰기나 `let` 블록으로 코드의 경계, 즉 "어휘 스코프"를 정해요.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

들여쓰기 수준이 같은 것은 모두 같은 스코프를 공유해요. 그래서 마지막 줄에서 `newBeginning` 변수를 참조할 수 있죠.

## 네임스페이스와 `use`문

네임스페이스는 Unison 함수를 묶고 정리하는 방법이에요. "디렉터리"와 비슷하다고 생각하면 돼요. 구조와 논리적인 그룹화를 제공하죠.

`use`문을 사용하면 네임스페이스 안의 함수들을 스코프로 가져올 수 있어요.

Unison의 `List` 값을 사용하는 함수를 작성한다고 해봐요. `List.map`이나 `List.flatMap` 같은 함수가 필요하다는 걸 알고 있죠. 여기서 `List`는 네임스페이스이고, `map`과 `flatMap`은 함수예요. 같은 이름을 반복해서 쓰지 않으려면, 다음과 같이 함수 안에서 `List` 네임스페이스의 모든 것을 어휘 스코프로 가져올 수 있어요:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

`use List` 줄이 `map`과 `flatMap`에 대한 참조를 명확하게 해줘요. [`use`문][use-statements]에 대해 더 읽어볼 수 있어요.

## Unison의 표준 라이브러리

Unison의 표준 라이브러리는 `base`라고 불러요. 퀵스타트 가이드를 따라 해서 로컬에 코드베이스를 만들었다면, 표준 라이브러리는 자동으로 내려받아졌을 거예요. 표준 라이브러리 문서는 [Unison Share][unison-share-base]에서 온라인으로 볼 수 있어요.

## 주석과 문서 리터럴

Unison의 주석은 조금 특이한 기능이에요. Unison 코드를 작성할 때, 확장자가 `.u`인 파일 안에 다음과 같은 문법으로 해석되지 않는 텍스트를 만들 수 있어요:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_하지만_ Unison 코드는 파일 시스템의 텍스트 파일이 아니라 추상 구문 트리의 해시로 저장돼요. 그래서 파일 안에서 특정 Unison 함수나 텀을 장식하는 텍스트 기반 주석은 실제로 저장되어 공유용으로 다시 렌더링될 수 없어요. 다른 사람이 읽고 이해할 수 있도록 Unison 텀에 정보를 남기고 싶다면 문서 리터럴을 사용하면 돼요.

문서는 Unison 프로그래밍 언어에서 일급 값이에요. 즉 `Doc` 요소는 값에 할당하거나, 함수에 값으로 넘기거나, 함수의 값으로 반환할 수 있어요. 문서 리터럴 요소는 이중 중괄호로 열고 닫아요. 다음은 `Doc` 요소를 주석처럼 사용하는 예예요.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
