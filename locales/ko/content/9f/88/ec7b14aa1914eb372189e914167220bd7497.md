# 사용자 정의 이터레이터

`bird-survey` 때부터 이터레이터를 계속 사용해 왔어요. 이제는 직접 만들어 볼 차례예요.

## yield

이터레이터는 루틴과 비슷해 보이지만 두 가지가 달라요. 이름이 `!`로 끝나고, 값을 `return` 대신 `yield`로 넘겨줘요.

```sather
   markers!(count : INT) : INT is
      loop
         yield 100 * 1.upto!(count);
      end;
   end;
```

`yield`는 이터레이터를 호출한 루프에 값을 하나 건네고, 그다음 **기다려요**. 그 루프가 다시 돌아오면 이터레이터는 `yield` 바로 다음 지점부터 이어서 실행해요. 변수, 자신의 루프, 실행 위치까지, 모든 것이 떠날 때 그대로인 상태로요.

이터레이터란 바로 이런 거예요. 중간에 멈췄다가 다시 이어서 실행할 수 있는 루틴이죠.

```sather
   loop
      #OUT + TRAIL::markers!(3) + " ";      -- 100 200 300
   end;
```

## 끝나는 방식

이터레이터가 끝나는 방식은 두 가지예요.

**끝까지 다 돌았을 때.** 이터레이터 자신의 루프가 끝나거나 루틴이 끝에 다다르면 이터레이터는 거기서 끝나요. 그러면 호출한 루프도 곧바로 끝나요.

**quit.** `quit`은 값을 하나도 내놓지 않고 그 자리에서 바로 끝내요.

```sather
   named!(names : ARRAY{STR}) : STR is
      loop
         name ::= names.elt!;
         if name = "" then quit; end;
         yield name;
      end;
   end;
```

이 이터레이터는 빈 이름을 만날 때까지 이름을 내놓다가 멈춰요. `quit`은 루틴에서의 `return`과 같은 역할이에요. 다만 값을 실어 보내지 않는다는 점이 달라요. 넘겨줄 값이 남아 있지 않으니까요.

## once

`once`가 붙은 인자는 루프가 돌 때마다가 아니라, 루프가 시작할 때 딱 한 번만 계산돼요.

```sather
   markers!(once count : INT) : INT is
```

한 번 돌 때마다 바뀌지 않는 값에 쓰면 돼요. 대부분의 인자가 그렇죠. 라이브러리 자체 이터레이터들도 그렇게 해요: `upto!(once i : SAME)`.

## 값을 내놓지 않는 이터레이터

이터레이터가 꼭 값을 내놓아야 하는 건 아니에요. `times!`가 그런 이터레이터예요.

```sather
   steps!(once count : INT) is
      loop
         ignored ::= 1.upto!(count);
         yield;
      end;
   end;
```

`yield`만 단독으로 쓰면 아무 값도 넘기지 않고 그냥 루프를 한 바퀴 돌게 해요.

## 위치는 어디에 있을까요

이터레이터를 호출하는 *프로그램상의 위치*는 각자 자신만의 위치를 기억해요. 그래서 하나의 루프 본문에서 같은 이터레이터를 두 번 호출하면, 두 호출이 각각 따로 진행되는 거예요. 이제 그 이유가 보여요. 두 호출은 서로 별개로 멈춰 있는 두 개의 루틴이니까요.
