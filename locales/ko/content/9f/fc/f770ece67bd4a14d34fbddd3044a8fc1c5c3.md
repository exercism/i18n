# Char 알아보기

이건 어쩌면 _아주 큰_ 주제일지도 몰라요!
이 주제만으로도 두꺼운 책 한 권을 쓸 수 있고, 실제로 그렇게 한 사람도 여럿 있어요 (아마존에서 "unicode book"을 검색하면 몇 가지 예를 볼 수 있어요).

## 아주 짧은 역사

예전에는 컴퓨터에서 문자를 다루는 일이 훨씬 단순했어요. 그때 프로그래머들은 영어가 유일하게 중요한 언어라고 생각했거든요.
그래서 영문자 26개(대문자와 소문자), 숫자 10개, 몇 가지 문장 부호, 그리고 종을 울리는 코드(0x07)까지 모두 7비트 안에 들어갔어요. 바로 [ASCII][wiki-ascii] 문자 집합이에요.

당연히 사람들은 à, ä, Ł는 어떻게 하냐고 묻기 시작했고, 그러다 다른 사람들은 ऄ, ஹ, ญ는 어떠냐고 물었고, 젊은 사람들은 이모지 😱를 원했어요.
어떻게 해야 했을까요?

간단히 말하자면, 똑똑하고 인내심 강한 많은 사람이 몇 년 동안 위원회에 참여해 [Unicode][web-unicode] 문자 집합과 [UTF-8][wiki-utf-8] 같은 인코딩의 세부 사항을 정리해야 했고, 수많은 소프트웨어가 _아주_ 복잡한 재작성을 거쳐야 했어요.
물론 새로운 버그도 잔뜩 생겼고요.

_모든 것_이 망가지는 걸 막기 위해, Unicode/UTF-8 설계에서는 처음 127개 코드가 ASCII와 똑같도록 했어요 _(종까지도요)_.

## Kotlin의 문자

2005년 무렵 이후에 설계된 언어들은 이미 어느 정도 안정적인 Unicode 표준이 존재했다는 큰 장점을 누릴 수 있었어요.

Kotlin(2011년에 처음 공개됐어요)은 사용자들이 다양한 (사람의) 언어를 사용할 것이고, 그것을 표현하는 데 Unicode가 필요하다고 전제할 수 있었어요.

~~~~exercism/advanced
Kotlin의 [문자][ref-char]는 JVM `char`와 같은 16비트(UTF-16) [`codepoints`][wiki-codepoint]예요.
이 정도면 대부분의 문자 체계를 표현하기에 충분하지만, 모든 이모지를 표현하기에는 부족해요.

전체 Unicode 표준에서는 문자 하나당 최대 6바이트(48비트)를 사용해요(이를 [`grapheme`][wiki-grapheme]이라고 해요).

Kotlin `Strings`는 필요할 때 문자 하나에 여러 코드 포인트를 사용해 이 전체 표준을 지원해요.
예를 들어 😱는 `\uD83D`와 `\uDE31`로 이루어져요.

안타깝게도 Java에는 그래핌 지원이 내장되어 있지 않고, 호환성을 위해 Kotlin도 마찬가지예요.

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


문자 리터럴은 작은따옴표로 쓰고, 큰따옴표로 쓰는 문자열과는 구별돼요.
C/C++ 세계에서 온 사람들에게는 아마 당연하겠지만, Python과 JavaScript 프로그래머에게는 헷갈릴 수 있어요.

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

`Char`와 `Int` 사이의 변환은 간단해요:

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

컴파일러는 `Char`에 대한 _일부_ 정수 연산을 허용해요:

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## `Char`를 위한 몇 가지 함수

언제나 그렇듯, 여기서 다루기에는 [함수가 너무 많아서][ref-char-lib] 몇 가지만 골라 볼게요.

- 알파벳에 해당한다면 [`uppercase()`][ref-uppercase]와 [`lowercase()`][ref-lowercase]로 대소문자를 바꿀 수 있어요.
- [`isUpperCase()`][ref-isuppercase]와 [`isLowerCase()`][ref-islowercase]로 대소문자를 검사할 수 있어요.
- 다음과 같이 문자의 종류를 검사할 수 있어요:
  - [`isLetter()`][ref-isletter], 여러 문자 체계를 포괄해요 (유니코드의 Lu, Ll, Lt, Lm, Lo 범주)
  - [`isDigit()`][ref-isdigit], 0..9 범위예요 (유니코드의 Nd 범주)
  - `isLetterOrDigit()`, 앞의 두 가지를 합친 거예요
  - [`isWhitespace()`][ref-iswhitespace], 모든 공백 문자예요 (유니코드의 Cc, Zp, Zl, Zs 범주)

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

또한 [정규 표현식][ref-regex]을 쓰면 강력한 검색과 조작이 가능해요 (정규 표현식은 나중에 다룰 개념이에요).

## Char 리스트와 문자열 상호 변환

`String`을 `Char`의 `List`로 변환하려면 `toList()`를 사용하면 돼요.

`Char`의 `List`를 `String`으로 변환할 때는 [`joinToString()`][ref-jointostring] 함수를 써요. 이 함수는 구분자(보통 빈 문자열)를 인자로 받아요.

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

`joinToString()`은 List나 Array에서 동작한다는 점에 주의해요.
`Char` 하나를 1글자 문자열로 _캐스팅_ 하려면 `toString()`을 사용해요.

```kotlin
'a'.toString() // => "a"
```

문자가 `String`이나 `Char` 리스트, 배열 안에 있는지 확인할 때는 `in`을 써요. `in`은 [`contains()`][ref-contains] 함수로 연결돼요.

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
