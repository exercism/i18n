# 문자열 빌더

`STR`은 불변이고 `FSTR`은 아니에요. 완성된 텍스트에는 `STR`을, 아직 조립 중인
텍스트에는 `FSTR`을 써요.

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## 결과는 항상 다시 대입해요

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR`은 **분할 상환 방식의 두 배 확장**으로 커져요. 자리가 부족해지면 더 큰
새 배열(크기는 두 배예요)을 만들고 그쪽으로 복사해요. 그래서 결과는 보통 같은
객체지만, 가끔은 다른 객체예요. 매번 `b := b + x`라고 쓰는 방식은 두 경우 모두
올바르고, 배워 둘 가치가 있는 유일한 표기예요.

두 배로 늘리기 때문에 전체 작업량이 길이의 제곱이 아니라 길이에 비례하게
돼요. 복사가 드물어지는 속도만큼 복사 하나가 비싸지기 때문이에요.

## 그냥 STR에 `+`를 쓰면 안 될까요?

정해진 개수의 조각 몇 개를 `+`로 이어 붙이는 건 명확하고 괜찮아요.

```sather
   return piece + " by " + composer;
```

문제가 되는 건 `loop`문뿐이에요. 코드를 작성할 때는 이어 붙이는 횟수를 알 수
없으니까요. 대략적인 기준은 이래요. `+`가 `loop`문 안에 있다면 `FSTR`을 써요.

## 유용한 루틴

| 호출 | 하는 일 |
| --- | --- |
| `b + x` | 덧붙여요. `x`는 `STR`, `CHAR`, `INT`, `BOOL` … 이에요 |
| `b.size` | 지금까지의 문자 수 |
| `b.str` | 완성된 `STR` |
| `b.clear` | 내용을 비우고 공간은 그대로 둬요 |

## 이스케이프

| 표기 | 의미 |
| --- | --- |
| `"\n"` | 새 줄 |
| `"\t"` | 탭 |
| `"\""` | 큰따옴표 |
| `"\\"` | 역슬래시 |
