# 소개

Factor의 입출력은 *스트림*을 기반으로 해요. 스트림은 바이트나 문자를 읽어 오거나 써 넣는 객체예요. [`io`][io] 보카뷸러리는 같은 [프로토콜][stream-protocol]을 바라보는 두 가지 관점을 제공해요.

## 두 가지 관점

**명시적 스트림** 단어는 스트림을 인자로 받아요. 모두 `stream-`으로 시작해요.

```
stream-read       ( n stream -- seq/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

**주변 스트림** 단어는 *현재 바인딩된* 스트림, 즉 프로그램 전역 동적 변수 `input-stream`이나 `output-stream`에서 읽거나 거기에 써요. 이름이 짧아요.

```
read1 read readln write write1 print flush
```

일상적인 코드는 대부분 주변 스트림 형태를 사용해요. 특정 스트림을 직접 들고 있으면서 주변 스트림을 바꾸고 싶지 않을 때는 명시적 형태를 써요.

## 메모리 내 스트림

이 연습 문제에서는 [`io.streams.string`][io.streams.string]의 문자열 기반 스트림을 다뤄요.

```
<string-reader>   ( str -- reader )
<string-writer>   ( -- writer )
```

`<string-reader>`는 문자열 리터럴을 마치 파일인 것처럼 읽어요. `<string-writer>`는 자신에게 쓰인 내용을 모두 모아 두었다가 나중에 다시 읽어 볼 수 있게 해줘요. 둘 다 파일 스트림과 같은 프로토콜을 구현하기 때문에, 여기서 배운 내용은 `<file-reader>` / `<file-writer>`에 그대로 적용돼요.

## `with-…`로 스코프 지정하기

명시적 스트림을 쿼테이션 동안 주변 스트림으로 바인딩하고 나중에 해제하려면 `with-…` 컴비네이터를 사용해요.

```
with-input-stream    ( stream quot -- )
with-output-stream   ( stream quot -- )
with-string-writer   ( quot -- str )
with-file-reader     ( path encoding quot -- )
with-file-writer     ( path encoding quot -- )
```

[`with-string-writer`][with-string-writer]는 "이 쿼테이션이 출력하는 것을 모아라"에 딱 맞는 편의 형태예요. `<string-writer>`를 만들고, 그것을 주변 출력으로 삼아 쿼테이션을 실행한 다음, 캡처한 문자열을 반환해요.

```factor
USING: io io.streams.string ;

[ "captured" print ] with-string-writer .
! => "captured\n"
```

`with-…` 컴비네이터는 모두 소멸자 컴비네이터예요. [`boatswains-bilge`][boatswains-bilge]의 `with-disposal`, `with-destructors`와 같은 계열이고, 쿼테이션에서 오류가 발생하더라도 스트림은 빠져나갈 때 해제돼요.
