# 개요

## const

[`const`][constants] 한정자는 값이 컴파일 시점에 알려져 있고 프로그램이 실행되는 동안 바뀌지 않는 모든 필드에 적용할 수 있어요. 그리고 대체로 적용하는 게 좋아요.

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

컴파일러가 어떤 식을 컴파일 시점에 평가할 수 있는지 알려줄 거예요. 간단한 산술 연산과 문자열 연결은 허용돼요. 다만 힙이나 스택을 사용해야 하는 평가는 제외돼요. 따라서 모든 메서드 호출과 기본형이 아닌 타입에 대한 참조는 사용할 수 없어요.

웹에는 변수보다 `const`가 성능이 좋다는 이야기가 있어요. 인스턴스의 const가 아닌 필드와 비교하면 메모리를 눈에 띄게 아낄 수도 있지만, 정적 변수와 비교하면 그 차이는 확실히 사소해요. CPU 성능을 고려하는 건 동료들이 [성급한 최적화][premature-optimization]로 볼 가능성이 커요.

`const`를 써야 하는 더 설득력 있는 이유는 코드를 유지보수하는 사람이 코드를 이해하는 데 도움이 된다는 점이에요. 어떤 필드가 `const`나 `readonly`로 표시되어 있거나 속성에 setter가 없다는 걸 흘깃 보는 것만으로도, 유지보수하는 사람은 그 필드를 분석에서 대부분 제외할 수 있어요. 그 필드가 버그의 온상일 가능성은 낮고, 리팩터링할 때 어려움을 일으킬 가능성도 낮아요. 이 점은 [Stack Overflow 댓글][so-consts]에서 다루고 있어요.

`const` 한정자는 메서드 안의 값에도 적용할 수 있어요.

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

이렇게 `const`로 값을 지정하면, 그 값이 메서드 안에서 여러 번 쓰이거나 값의 의미에 주목하게 하고 싶을 때 유용해요. 리터럴을 그대로 쓰는 것보다 성능이 좋아지는 건 아니에요.

## readonly

[`readonly`][readonly-fields] 한정자는 `const`로 만들 수는 없지만 값이 프로그램이 실행되는 동안 바뀌지 않고, 인라인 초기화나 인스턴스를 만들 때(생성자 또는 생성자가 호출하는 메서드에서) 설정되는 모든 필드에 적용할 수 있어요. 이 경우에도 대체로 적용하는 게 좋아요.

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

`readonly` 한정자를 쓰는 것도 `const`와 같은 이유로 권장돼요. 이렇게 필드를 제약하는 습관은 유지보수하는 사람이 코드를 이해하는 데 도움을 줘요.

필드에 `readonly` 한정자를 붙여도 그 필드의 값이 바뀌는 것만 막을 뿐이에요. 집합 타입의 경우에는 그 타입의 필드나 속성을 보호하지 않아요. 특히 배열의 내용은 보호하지 않아요.

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

참조 타입의 모든 멤버를 보호하려면 필드를 `readonly`로 만들고, 자동 속성을 `set` 접근자 없이 정의하면 돼요.

베이스 클래스 라이브러리의 [읽기 전용 컬렉션][readonly-collections]을 살펴보는 게 좋아요.

배열의 경우 읽기 전용 버전에 가장 가까운 것은 [`Array.AsReadOnly<T>()`][as-read-only] 메서드예요.
