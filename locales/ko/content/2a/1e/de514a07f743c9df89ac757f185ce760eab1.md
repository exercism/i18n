# 자세히 알아보기

OS 상태(파일 핸들, 소켓, 잠금)를 들고 있는 자원은 스택이 예외로 풀려 나갈 때도 *반드시* 정리되어야 해요. Factor의 [`destructors`][destructors] vocab은 이를 위한 작은 프레임워크를 제공하고, 대부분의 내장 자원(`<file-reader>`, `<file-writer>`, 소켓 등)은 이미 여기에 연결되어 있어요.

## 클래스와 제네릭

클래스는 `disposable`을 상속하고 `dispose*`를 구현하면 참여할 수 있어요:

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )`은 튜플을 할당하면서 *동시에* 현재 소멸자 스코프에 등록해요. 그래서 할당과 다음 안전 지점 사이에서 예외가 발생해도 자원이 새어 나가지 않아요. 프레임워크는 객체마다 `dispose*`가 **최대 한 번만** 실행되도록 보장해요. `dispose`를 여러 번 호출해도 아무 일도 일어나지 않아요.

## 외부 호출자는 `dispose`를 사용해요

| 단어              | 효과                                          |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )`: 자원을 해제해요. 두 번 호출해도 안전해요 |
| `with-disposal`   | `( disposable quot -- )`: 자원 하나를 스코프로 감싸요 |
| `with-destructors`| `( quot -- )`: 레지스트리 스코프를 열어요      |
| `&dispose`        | `( obj -- obj )`: 정상 종료*든* 실패 종료든 해제해요 |
| `|dispose`        | `( obj -- obj )`: 스코프가 예외로 풀릴 때만 해제해요 |

`with-disposal`은 자원 하나를 다루는 형태예요. 자원이 둘 이상이면 `with-destructors` 스코프를 열고, 자원을 얻을 때마다 `&dispose`(항상 해제하고 싶을 때)나 `|dispose`(실패했을 때만 해제하고, 성공 경로에서는 그대로 유지할 때)로 등록해요.

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup`은 가장 기본이 되는 프리미티브예요

레지스트리 없이 한 번만 try/finally를 쓰고 싶다면, `continuations`에 있는 [`cleanup`][cleanup]이 더 낮은 수준의 단어예요:

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors`가 기능은 더 강력해요(레지스트리는 실행 중에도 늘어날 수 있어요). 하지만 자원을 얻고 해제하는 짝이 고정되어 있고 국소적이라면 `cleanup`이 자연스러운 선택이에요.
