# 소개

다른 많은 언어들처럼 Go에도 포인터가 있어요.
포인터가 처음이라면 조금 어렵게 느껴질 수도 있지만, 익숙해지면 아주 단순해요.
포인터는 Go에서 아주 중요한 부분이니, 시간을 들여 제대로 이해해 봐요.

자세한 내용을 파고들기 전에, 포인터가 어디에 쓰이는지 이해해 두면 좋아요.
포인터는 프로그램의 다른 부분과 메모리를 공유하는 방법인데, 크게 두 가지 이유에서 유용해요:

1. 데이터의 양이 많을 때, 함수 사이에 전달하려고 복사본을 만드는 것은 매우 비효율적이에요.
   대신 데이터가 저장된 메모리 위치를 전달하면, 프로그램이 사용하는 자원을 크게 줄일 수 있어요.
2. 함수 사이에 포인터를 전달하면 데이터의 단일 복사본에 직접 접근하고 수정할 수 있어요. 즉, 한 함수가 만든 변경 사항은 그 함수가 끝나는 즉시 프로그램의 다른 부분에서도 바로 보여요.

## 변수와 메모리

일반적인 정수 변수 `a`가 있다고 해봐요:

```go
var a int
```

변수를 선언하면 Go는 값을 저장할 메모리 공간을 찾아야 해요.
이 과정은 대부분 우리에게 감춰져 있어요. 그 메모리 공간에 저장된 값을 가져와야 할 때는 그냥 변수 이름으로 가리키면 돼요.

예를 들어 `a + 2`라고 쓰면, 변수 `a`와 연결된 메모리에 저장된 값을 가져와서 2를 더하는 것과 같아요.

마찬가지로 `a`의 메모리 공간에 있는 값을 바꾸고 싶을 때는 변수 이름을 사용해서 값을 할당할 수 있어요:

```go
a = 3
```

이제 `a`와 연결된 메모리 공간에는 값 `3`이 저장돼요.

## 포인터

변수를 사용하면 메모리에 있는 값들을 가리킬 수 있지만, 때로는 변수가 가리키는 **메모리 주소**를 아는 것이 유용해요. **포인터**는 그 값들의 메모리 주소를 담고 있어요.
포인터 타입의 변수는 기본 타입 앞에 별표를 붙여서 선언해요:

```go
var p *int // 'p' contains the memory address of an integer
```

여기서는 "int에 대한 포인터"(`*int`) 타입의 변수 `p`를 선언해요.
즉, `p`에는 정수의 메모리 주소가 담겨요.
포인터의 제로 값은 `nil`인데, `nil` 포인터는 메모리 주소를 담고 있지 않기 때문이에요.

### 변수에 대한 포인터 얻기

변수 값의 메모리 주소를 찾으려면 `&` 연산자를 사용하면 돼요.
예를 들어 변수 `a`의 메모리 주소를 찾아서 포인터 `p`에 저장하고 싶다면 다음과 같이 하면 돼요:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### 포인터를 통해 값에 접근하기 (역참조)

포인터가 있을 때, 그 포인터가 나타내는 메모리 주소에 저장된 값을 알고 싶을 수 있어요.
이때는 `*` 연산자를 사용하면 돼요:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p` 연산은 `p`에 저장된 메모리 주소에 있는 값을 가져와요.
이 연산을 흔히 "역참조"라고 불러요.

역참조 연산자를 사용해서 포인터가 가리키는 메모리 주소에 새로운 값을 할당할 수도 있어요:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

`*pa`에 값을 할당하면 `pa`가 담고 있는 메모리 주소에 저장된 값이 바뀌어요.
`pa`가 `a`의 메모리 주소를 담고 있으니, `*pa`에 값을 할당하는 것은 곧 `a`의 값을 바꾸는 것과 같아요!

다만 주의할 점이 있어요. 역참조하기 전에 포인터가 `nil`이 아닌지 항상 확인해요.
`nil` 포인터를 역참조하면 프로그램이 실행 중에 충돌해요!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### 구조체에 대한 포인터

지금까지는 기본 값에 대한 포인터만 봤어요.
구조체에 대한 포인터도 만들 수 있어요:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

새로운 `Person`을 만들면서 바로 포인터를 저장할 수도 있어요:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

구조체에 대한 포인터가 있을 때는 필드에 접근하기 전에 포인터를 역참조할 필요가 없어요:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## 슬라이스와 맵은 이미 포인터예요

슬라이스와 맵은 구현 안에 이미 포인터를 가지고 있어서 특별한 타입이에요.
그래서 이런 타입의 값에 대한 메모리 주소를 공유하려고 포인터를 만들 필요가 없는 경우가 대부분이에요.
맵의 키 값을 증가시키는 함수가 있다고 해봐요:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

맵을 만들고 이 함수를 호출하면, 함수가 맵에 가한 변경 사항은 함수가 끝난 뒤에도 그대로 남아 있어요.
포인터를 사용했을 때와 비슷한 동작이지만, 이 예시에서는 참조나 역참조, 또는 어떤 포인터 문법도 사용하지 않았다는 점을 눈여겨봐요:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

슬라이스에 이미 있는 요소를 바꿀 때도 마찬가지예요.

하지만 `append`처럼 새로운 슬라이스를 반환하는 동작은 특별한 경우라서, 함수 바깥의 슬라이스를 **바꾸지 않을 수도** 있어요.
이는 슬라이스가 내부적으로 동작하는 방식 때문인데, 좀 더 심화된 주제라서 이 연습 문제에서는 자세히 다루지 않아요.
정말 궁금하다면 [Go 블로그: 'append'의 동작 원리][mechanics-of-append]에서 더 읽어볼 수 있어요.
