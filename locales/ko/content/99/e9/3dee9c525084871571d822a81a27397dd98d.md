# 지침

한 해적이 숨겨진 만들이 그려진 해도를 보며 항로를 그리고 있어요.
이 해도는 만 이름을 키로 하는 해시 테이블이고, 각 값은 그 만에서
바로 갈 수 있는 만들의 배열이에요.

## 1. 밀물 대기열 비우기

`tide-queue`는 항목들의 배열을 받아서, 각 항목을 새 덱에 (순서대로)
넣은 다음, 원래 순서를 유지하는 배열로 다시 모두 꺼내도록 정의해요.
이것이 선입선출(FIFO) 형태예요. 뒤에 넣고, 앞에서 꺼내요.

```factor
{ "alpha" "bravo" "charlie" } tide-queue .
! => { "alpha" "bravo" "charlie" }
```

## 2. 도달할 수 있는 만

`coves-reachable`는 시작 만과 해도를 받아서, `start`에서 도달할 수
있는 모든 만(`start` 자신도 포함)을 해시 집합으로 반환하도록
정의해요.

```factor
"Skull Bay" H{
    { "Skull Bay"   { "Hidden Cove" } }
    { "Hidden Cove" { "Reef Point"  } }
    { "Reef Point"  { } }
} coves-reachable .
! => HS{ "Skull Bay" "Hidden Cove" "Reef Point" }
```

너비 우선 탐색(BFS)의 경계로 `<dlist>`를 사용하고, 방문한 만을 담는
집합으로는 `HS{ }`를 사용해요.

## 3. 이동 횟수

`hop-count`는 시작 만과 목표 만, 해도를 받아서, 두 만 사이의 최소
이동 횟수를 반환하도록 정의해요. 목표 만에 도달할 수 없으면 `f`를
반환해요.

```factor
"Skull Bay" "Hidden Cove"
H{
    { "Skull Bay"   { "Hidden Cove" } }
    { "Hidden Cove" { } }
} hop-count .
! => 1
```

덱에는 각 만을 시작 만으로부터의 거리와 함께 담아요(원소 두 개짜리
배열이면 돼요).

## 4. 금화 개수

스텁은 `gold-count`를 `:`로 선언해요. 각 만의 결과가 한 번만 계산되고
캐시되도록, 이것을 `MEMO:`(`:`가 아니에요)로 바꿔요. 만의 금화는 연습
문제에서 제공하는 `gold-distribution` 상수에서 찾아요.
분포에 없는 만은 금화가 0이에요.

```factor
"Smuggler's Hollow" gold-count .   ! => 200
"Davy Jones' Locker" gold-count .  ! => 0
```

## 5. 보물 경로

`treasure-route`는 시작 만과 해도를 받아서, 도달할 수 있는 만 중에서
금화가 가장 많은 만을 반환하도록 정의해요. 2번 문제의
`coves-reachable`와 4번 문제의 `gold-count`를 사용해요.

```factor
"Skull Bay" some-chart treasure-route .
! => "Smuggler's Hollow"   (the richest reachable cove)
```

메모이제이션된 `gold-count` 덕분에 같은 값을 다시 조회하는 데 드는
비용이 들지 않아요. 알고리즘의 여러 부분이 같은 만을 참조할 때
유용해요.
