# Introduction

## 이진 표기법

**정수**는 `4`, `-2`, `0`, `64532`와 같이 소수 부분이 없는 수를 나타내는 추상 개념이에요.

정수를 바이트 나열로 나타내려면 **이진 표기법**을 사용해요.
이 표기법에서 나열의 각 비트는 서로 다른 2의 거듭제곱을 나타내고, 비트의 인덱스가 오른쪽에서 왼쪽으로 커질수록 그 값도 커져요.

## 부호 없는 수

수가 음수가 될 수 없다면, 이를 **부호 없는** 수라고 해요.

부호 없는 수는 나열에서 설정된 모든 비트에 대응하는 2의 거듭제곱의 합으로 곧바로 나타내요.

레지스터에서 나타낼 수 있는 음수가 아닌 정수의 범위는 `0`(설정된 비트 없음)부터 `2⁶⁴ - 1`(64개 비트를 모두 설정한 값의 합)까지예요.

부호 없는 수를 더 큰 크기로 넓힐 때는 모든 상위 비트를 `0`으로 채워서, 새로운 비트가 값에 영향을 주지 않게 해요.
이를 **제로 확장**이라고 해요.

`movzx` 명령어는 (`z`는 zero를 뜻해요) 8비트 또는 16비트 소스 피연산자를 더 큰 목적지 피연산자로 제로 확장해요.
32비트 소스 피연산자는 단순한 `mov`만으로도 항상 목적지 피연산자의 64비트 전체로 제로 확장돼요.

## 부호 있는 수

정수가 양수나 음수 값을 가질 수 있으면, 이를 **부호 있는** 수라고 해요.

음수를 나타내기 위해 x86-64는 **2의 보수** 표현을 사용해요.

2의 보수에서도 부호 있는 수는 설정된 비트에 대응하는 2의 거듭제곱의 합으로 나타내요.
하지만 가장 위쪽 비트가 설정되어 있으면, 이 비트의 값은 다른 비트들에 더하는 대신 빼요.

이 비트는 다른 모든 비트의 합보다 더 큰 값에 대응하기 때문에, 실제로 이 비트가 설정된 수는 항상 음수예요.
이 특별한 비트를 **부호 비트**라고 해요.

부호 있는 수를 더 큰 크기로 넓힌다는 것은 새로운 상위 비트마다 부호 비트를 복사해서 채워 값이 그대로 유지되게 하는 거예요.
이를 **부호 확장**이라고 해요.

`movsx` 명령어는 (`s`는 sign을 뜻해요) 8비트 또는 16비트 소스 피연산자를 더 큰 목적지 피연산자로 부호 확장해요.
`movsxd`라는 `movsx`의 변형은 32비트 소스 피연산자에서 64비트 목적지 피연산자로 같은 일을 해요.

`neg` 명령어를 사용하면 수의 부호를 바꿀 수 있어요.

~~~~exercism/caution
어셈블리에서는 바이트 나열이 부호 있는 수를 나타내는지 부호 없는 수를 나타내는지 구분할 방법이 없어요.
그 바이트에 의미를 부여하는 것은 프로그래머의 몫이에요.

주석을 사용하면 이 작업에 큰 도움이 돼요.
~~~~

## 즉시값

이전 개념에서 `4`나 `-15` 같은 상수를 많은 명령어의 소스 피연산자로 사용할 수 있다고 언급했어요.
이런 수를 **즉시값**이라고 해요.

즉시값은 레지스터나 메모리에 담기지 않고, 명령어 자체 안에 인코딩돼요.
대부분의 명령어에서 즉시값을 위해 예약된 공간은 목적지 피연산자가 아무리 커도 32비트 폭밖에 되지 않아요.

목적지 피연산자가 64비트 폭이면, 그 32비트가 _부호 확장_되어 목적지 피연산자를 채워요.
피연산자의 위쪽 절반은 즉시값의 가장 위쪽 비트를 복사한 값으로 완전히 채워지기 때문에, _32비트 부호 있는 정수_ 범위의 수만 이런 방식으로 쓸 수 있어요:

```x86asm
add rax, -1          ; the immediate is sign-extended, so all 64 bits of rax are affected
add rax, 2147483647  ; the largest immediate an instruction like this accepts
```

그 범위를 벗어나는 수는 즉시값으로 사용할 수 없어요.
이 규칙의 예외는 `mov`인데, 목적지 피연산자가 레지스터일 때는 64비트 즉시값 전체를 받을 수 있어요.
64비트 즉시값이 필요하면, 먼저 `mov`으로 그 값을 레지스터에 넣고, 그 레지스터를 사용해요:

```x86asm
mov rax, 3435973837           ; this works, mov can take a 64-bit immediate
mov rdx, 18446744073709551615 ; the largest immediate mov accepts
sub rdx, rax
```

음수 즉시값과 같은 비트 표현을 가진 부호 없는 수는 서로 동등하고, 어셈블하면 정확히 같은 값이 된다는 점에 유의해요:

```x86asm
mov rax, -1                   ; rax = 18446744073709551615
mov rax, 18446744073709551615 ; rax = -1
```

## 덧셈

두 수의 덧셈은 `add` 명령어로 계산할 수 있어요.

피연산자의 값에 `1`을 더하는, 피연산자가 하나인 `inc` 명령어도 있어요:

```x86asm
inc rax ; rax = rax + 1
```

두 정수의 합은 부호 없는 수와 부호 있는 수 모두 같은 방식으로 동작해요.

## 뺄셈

두 정수의 뺄셈은 `sub` 명령어로 수행해요.

피연산자의 값에서 `1`을 빼는, 피연산자가 하나인 `dec` 명령어도 있어요:

```x86asm
dec rax ; rax = rax - 1
```

두 정수의 뺄셈도 부호 없는 수와 부호 있는 수 모두 같은 방식으로 동작해요.

## 곱셈

x86-64에서 두 수의 곱셈을 수행하는 명령어는 두 가지예요.
원칙적으로 부호 없는 곱셈에는 `mul` 명령어를, 부호 있는 곱셈에는 `imul`을 사용해요.

`mul` 명령어는 다음과 같이 피연산자가 하나인 형태를 취하는데, 여기서 `src`는 소스 피연산자예요:

```x86asm
mul src
```

`imul` 명령어는 피연산자가 하나, 둘 또는 셋인 형태를 취할 수 있어요:

```x86asm
imul src
imul dest, src
imul dest, src1, src2
```

### 피연산자가 하나인 곱셈

피연산자가 하나인 형태의 곱셈을 수행할 때는 `rax`와 `rdx` 두 레지스터가 암묵적으로 사용돼요.
두 64비트 수를 곱하면 결과의 하위 64비트는 `rax`에, 상위 64비트는 `rdx`에 들어가요.

두 레지스터가 함께 사용된다는 것을 나타내기 위해 보통 이를 `rdx:rax`라고 불러요:

```x86asm
mul rcx ; rax = lower 64 bits of rax * rcx
        ; rdx = upper 64 bits of rax * rcx
```

다른 피연산자 크기에도 같은 일이 일어나요.
예를 들어 두 32비트 수를 곱하면 `eax`와 `edx`가 사용돼요.

예외는 두 바이트 사이의 곱셈이에요.

이 경우에는 `dl:al` 대신 `ax`가 사용돼요.
`ax`의 아래쪽 부분(`al`)은 곱의 하위 8비트를, 위쪽 부분(`ah`)은 상위 8비트를 가져요.

~~~~exercism/caution
`rax`와 `rdx`처럼 곱셈에 암묵적으로 사용되는 레지스터는 항상 덮어써져요.
나중에 그 값이 필요하다면 연산 전에 저장해 둬야 해요.
~~~~

### 피연산자가 둘인 곱셈

`imul`의 피연산자가 둘인 형태는 목적지 피연산자를 명시하고, 일반적인 문법을 따라요.
`rdx`는 사용되지 않아요.
대신 결과가 목적지 피연산자에 맞게 잘려요.

```x86asm
imul r8, r9 ; r8 = lower 64 bits of r8 * r9
```

### 피연산자가 셋인 곱셈

`imul`의 피연산자가 셋인 형태는 소스 피연산자를 두 개 가지는데, 두 번째는 항상 즉시값(상수)이에요.
두 소스 피연산자를 곱한 뒤 결과를 잘라내어 목적지 피연산자에 넣어요:

```x86asm
imul r8, r9, 100 ; r8 = lower 64 bits of r9 * 100
```

목적지 피연산자는 곱셈에 사용되지 않는다는 점에 유의해요.
그저 결과를 받기만 해요.

### 오버플로 다루기

피연산자가 둘인 곱셈과 셋인 곱셈 모두 결과를 목적지 피연산자의 크기에 맞게 잘라요.
피연산자가 하나인 곱셈은 전체 범위를 보존하지만, 보통 `rdx`와 `rax` 두 레지스터로 나뉘어요.

그래서 곱셈 전에 피연산자를 넓혀서 전체 곱을 하나의 레지스터에 담을 공간을 만드는 것이 유용할 때가 있어요.
부호 없는 피연산자는 제로 확장하고, 부호 있는 피연산자는 부호 확장해요:

```x86asm
movzx eax, di ; di and si hold unsigned 16-bit numbers
movzx ecx, si
mul ecx       ; the 32-bit product fits in eax, and edx is cleared
```

## 나눗셈

곱셈과 마찬가지로, 두 수의 나눗셈을 수행하는 명령어도 두 가지예요.
부호 없는 나눗셈에는 `div` 명령어를, 부호 있는 나눗셈에는 `idiv`를 사용해요.

두 명령어 모두 피연산자를 하나만 사용해요:

```x86asm
div src
idiv src
```

16비트, 32비트, 64비트 나눗셈은 각각 `dx:ax`, `edx:eax`, `rdx:rax`를 피제수로 사용해요.
이 경우 두 레지스터가 함께 작용해 2N비트 값을 만들어요. 여기서 N은 연산의 크기(16비트, 32비트, 64비트)예요.
그런 다음 이 값을 소스 피연산자로 나눠요.
몫은 연산의 크기에 따라 `ax`, `eax`, `rax`에, 나머지는 `dx`, `edx`, `rdx`에 쓰여요.

바이트 사이의 나눗셈은 특별해서, `dl:al` 대신 `ax`를 사용해요.
`ax`의 하위 8비트(`al`)는 연산의 몫을, 상위 8비트(`ah`)는 나머지를 가져요.

나눗셈 전에 피제수의 모든 비트를 알맞게 설정해야 한다는 점에 유의해요.
`rdx`에 설정된 비트(8비트 나눗셈에서는 `ah`에 설정된 비트)는 나눠지는 값에 영향을 줘요.

부호 없는 나눗셈에서는 나눌 값이 아래쪽 절반에 들어갈 때 위쪽 절반을 비워야 해요.
그 비트를 비우는 명령어라면 무엇이든 괜찮아요.
예를 들어 32비트 나눗셈에서는 `mov edx, 0`이 상위 비트를 비워요.

부호 있는 나눗셈에서는 대신 값을 부호 확장해야 해요.
이 과정을 자동으로 처리하는 명령어들이 있어요: `cbw`, `cwd`, `cdq`, `cqo`예요.
첫 번째는 `al`의 부호에 따라 `ah`의 비트를 설정해요.
나머지들은 각각 `ax`에서 `dx`로, `eax`에서 `edx`로, `rax`에서 `rdx`로 부호 확장을 수행해요.

~~~~exercism/caution
`rax`와 `rdx`처럼 나눗셈에 암묵적으로 사용되는 레지스터는 항상 덮어써져요.
나중에 그 값이 필요하다면 나눗셈 전에 저장해 둬야 해요.
~~~~
