# 안내

프로그래밍을 배우면 배울수록, 이게 단순한 유행이 아닐 수도 있겠다는 생각이 점점 들어요.
어쩌면 사업 기회도 있을지 몰라요. 사람들은 코드를 작성하고, 그걸 저장하고 공유하고 함께 작업하고 싶어 하고, 어쩌면 피드백까지 받고 싶어 하니까요.

좋아요, 해봐요. 사람들이 코딩을 하도록 독려하는 서비스를 만들어 봐요. 자, 모두들, 이제 git을 써 봐요!
이름은... GitHup이라고 할까요?

REST JSON API를 만들기 시작해요. 사용자, 풀 리퀘스트, 댓글까지, 백엔드는 순식간에 완성돼요.
서버에 풀 리퀘스트의 댓글 목록을 요청했을 때 돌려주는 페이로드의 예시는 다음과 같아요.

```json
[
  {
    "id": 256,
    "pull_request_review_id": 42,
    "user": {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    },
    "body": "Great stuff!",
    "side": "RIGHT",
    "_links": {
      "self": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1"
      },
      "html": {
        "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1"
      },
      "pull_request": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1"
      }
    }
  },
  {
    "id": 11,
    "pull_request_review_id": null,
    "user": {
      "id": 2,
      "login": "hexacat",
      "name": "Alex Kate",
      "avatar_url": "https://githup.com/images/error/hexacat_happy.gif",
      "site_admin": true
    },
    "body": "Amazing stuff!",
    "side": "LEFT",
    "_links": {
      "self": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1"
      }
    }
  }
]
```

물론 프런트엔드는 Elm으로 만들 거지만, 그전에 그 악명 높은 디코더와 인코더가 대체 뭔지부터 알아내야 해요.

```exercism/note
재미있는 이야기는 여기까지 하고, 이 연습 문제의 요구 사항은 GitHub의 풀 리퀘스트 리뷰 댓글 REST API 엔드포인트에서 그대로 가져왔어요.
간단하게 하려고 JSON 스키마에서 일부 필드는 뺐지만, 실제 애플리케이션에 이만큼 가까운 건 없어요.
```

## 1. ID를 주세요!

예리한 눈으로 보니 댓글과 사용자 모두 `id` 필드를 가지고 있어요. 시작하기에 딱 좋은 곳이죠.

`decodeId`를 정의해서 정수 `id`가 있는 JSON 객체를 디코딩할 수 있게 해봐요.

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. 제 이름이 뭐였죠?

위 예시에서 모든 사용자에게 이름이 있는 건 아니라는 걸 눈치챘죠.

`decodeName`을 정의해서 `name` 필드에 문자열이 있으면 디코딩할 수 있게 해봐요.
이름이 없다고요? 문제없어요. 그냥 `Nothing`을 반환하면 돼요.
이 디코더는 절대 실패하면 안 돼요.

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. 사용자라고요? 잘 모르겠는데요!

사용자 디코딩은 거의 절반쯤 온 셈이에요. 마무리해 봐요.

`decodeUser`를 정의해서 JSON 사용자 객체를 디코딩할 수 있게 해봐요.
`decodeUser` 안에서 `decodeId`와 `decodeName`을 꼭 사용해야 해요.

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. 저는 강하고 독립적인 댓글이에요

풀 리뷰의 댓글 중에는 독립적으로 달리는 것도 있어서 `pull_request_review_id`가 없어요.
하지만 명세에 따르면 그런 경우에도 `pull_request_review_id` 필드는 있어야 하고, 값은 `null`, 그러니까 서민용 `Nothing`이어야 해요.

`decodePullRequestReviewId`를 정의해서 `pull_request_review_id` 필드에 정수가 있으면 디코딩할 수 있게 해봐요.
정수가 없으면 `null`이 있어야 하고, `null`도 없으면 디코더가 실패해야 해요.

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. 사이드잡

다음은 흥미롭게 생긴 `side` 필드예요.
풀 리뷰에서는 삭제된 코드(화면의 `Left` 쪽)에도, 추가된 코드(화면의 `Right` 쪽)에도 댓글을 달 수 있어요.

`decodeSide`를 정의해서 `side` 필드의 `"LEFT"` 또는 `"RIGHT"`를 디코딩하고, 그에 해당하는 타입 변형과 맞출 수 있게 해봐요.

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. 링크의 각성

각 댓글에는 링크 모음이 있는데, 댓글마다 일정해 보이지는 않아요.

`decodeLinks`를 정의해서 `_links` 필드에 있는 URL 모음을 디코딩할 수 있게 해봐요.
링크의 이름과 개수는 달라질 수 있으니, 그걸 처리할 수 있어야 해요.
링크 자체는 항상 `href` 필드를 가진 JSON 객체예요.

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. 네, 댓글이에요

거의 다 왔어요. 마무리해 봐요.

`decodeComment`와 `decodeComments`를 정의해서, 각각 JSON 댓글 객체 하나와 댓글 목록을 디코딩할 수 있게 해봐요.
`decodeName`을 빼고 지금까지 정의한 모든 함수를 `decodeComment`에서 사용해야 해요.
물론 `decodeComments`도 `decodeComment`를 사용해야 하고요.

## 8. 모두 하나로 이어져요

아직 하나 빠진 기능이 있어요. 바로 서버에 새 댓글을 보내는 거예요.
그러려면 디코더의 반대 역할이 필요해요. Elm `Comment`를 JSON `Value`로 변환할 수 있어야 하죠.

`encodeComment`를 정의해서 유효한 `Comment`라면 무엇이든 인코딩할 수 있게 해봐요.
필드 순서는 상관없어요. 인코더가 `decodeComment`로 디코딩할 수 있는 값을 만들어 내기만 하면 돼요.
