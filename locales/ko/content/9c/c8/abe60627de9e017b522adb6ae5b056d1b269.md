# 자세히 알아보기

[루프][control]는 종료 조건이 충족될 때까지 여러 번 실행될 수 있는 일련의 명령어예요.

x86-64에서는 보통 이전 레이블로 점프해서 루프를 만들어요:

```x86asm
example_loop:
    ...
    jmp example_loop
```

이전 레이블로 가는 무조건 점프는 항상 실행을 그 레이블로 옮긴다는 점에 유의해요. 즉, 반복되는 구간 밖으로 빠져나가는 점프가 따로 없다면, 루프는 영원히 계속 반복돼요.

예를 들어, 이 루프는 끝나지 않아요:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

반면 이 루프는 조건이 충족되는지에 따라 끝날 수도 있어요:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## 카운팅 루프

카운팅 루프는 거의 항상 같은 방식으로 끝나요. 카운터를 갱신하거나 두 값을 비교하는 명령어 바로 뒤에, 다시 한 바퀴 돌지 결정하는 조건부 점프가 따라와요.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
위 코드에서 `cmp rsi, 0`은 필요하지 않아요. `sub rsi, 1`이 결과가 `0`일 때 이미 `zero flag (ZF)`를 설정하기 때문이에요.

어셈블리에서 조건을 검사하는 주된 방법은 `cmp`지만, 플래그를 갱신하는 명령어는 많아요. 예를 들어 정수 산술이나 비트 연산 명령어 상당수는 결과가 `0`이면 `ZF`를, 결과가 음수(즉, 최상위 비트가 설정된 경우)면 `SF`를 갱신해요.

각 명령어가 어떤 플래그에 영향을 주는지는 [참고 자료][reference]에서 확인할 수 있어요.

[reference]: https://www.felixcloutier.com/x86/
~~~~

위 예제에서는 `rsi`가 `0`보다 크다고 가정한다는 점에 유의해요. 만약 `rsi`가 `0`이었다면, `sub rsi, 1`은 `rsi`를 `-1`로 만들 텐데, 이는 부호 없는 수로는 매우 큰 값이에요. 루프가 끝나기까지 `18,446,744,073,709,551,615`번을 더 반복해야 했을 거예요. 또한 배열의 길이가 `0`이므로, 어떤 메모리 접근이든 범위를 벗어나게 돼요.

배열의 길이를 보장할 수 없다면, 흔히 쓰는 두 가지 방법이 있어요.

첫 번째는 종료 조건을 루프의 맨 앞으로 옮기고, 끝에 무조건 점프를 두는 방법이에요:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

두 번째는 루프를 시작하기 전에 길이가 0인 배열인지 한 번 검사하는 방법이에요:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

이 두 번째 방법은 루프 본문에 분기가 더 적기 때문에 보통 첫 번째보다 더 효율적이에요. 이에 대해서는 이후 개념에서 더 배우게 돼요.

## 마이크로 연산

프로세서는 `add`나 `jnz` 같은 명령어를 그대로 실행하지 않아요. CPU의 프런트 엔드는 먼저 각 명령어를 하나 이상의 더 작은 내부 단계로 _디코딩_하는데, 이것을 **마이크로 연산**(또는 **마이크로 옵**)이라고 해요. 그다음 프로세서는 이 마이크로 연산들을 스케줄링하고 실행하는데, 흔히 한 사이클에 여러 개를 원래 순서와 다르게 실행해요.

대부분의 단순한 명령어는 하나의 마이크로 연산으로 디코딩되지만, 더 복잡한 명령어는 여러 개로 디코딩될 수 있어요. 프로세서가 실제로 처리하는 일은 마이크로 연산의 흐름이기 때문에, 같은 작업을 하면서 더 적은 마이크로 연산을 만들어 내는 것은 코드가 더 빨라지는 방법 중 하나예요.

## 매크로 융합

앞에서 언급했듯이, 루프는 보통 어떤 형태의 조건부 점프로 끝나요. 이 패턴이 워낙 흔해서, 최신 프로세서는 디코딩 단계에서 이 패턴에 맞게 최적화되어 있어요.

플래그를 설정하는 명령어 바로 뒤에 그 플래그를 읽는 조건부 점프가 오면, 둘을 각각 하나씩이 아니라 **단일** 마이크로 연산으로 함께 디코딩할 수 있어요. 이것을 **매크로 융합**이라고 해요.

융합된 쌍은 하나의 연산처럼 동작해요. 카운터 갱신과 분기 결정이 하나의 마이크로 연산 안에서 함께 이루어져요. 그러면 루프의 제어 흐름은 루프가 실제로 하는 일에 거의 아무 비용도 더하지 않아요.

경험적으로, 보통 다음 두 종류의 쌍이 이렇게 융합돼요:

- `add`나 `sub` 같은 산술 명령어 바로 뒤에 조건부 점프가 오는 경우
- `cmp`, `test`, `and` 바로 뒤에 조건부 점프가 오는 경우

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

융합은 조건부 점프가 플래그 설정 명령어 **바로** 뒤에, 사이에 아무것도 없이 올 때만 일어나요.

~~~~exercism/note
매크로 융합은 CPU에 따라 다르고, 어떤 명령어가 어떤 조건부 점프와 융합되는지에는 약간의 차이가 있어요.

유용한 참고 자료로 [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch]가 있어요. [Intel optimization reference manual][intel-opt]의 3.4.2.2절(Optimizing for Macrofusion)에도 Intel CPU에서 융합 가능한 쌍이 정리되어 있어요.

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## `loop` 명령어

루프와 비슷한 동작을 만들 때 쓸 수 있는 명령어가 몇 가지 있어요. 그중 하나가 [루프][loop]예요.

이 명령어의 유일한 피연산자는 루프 시작 위치의 주소를 가진 레이블이에요.

`loop` 명령어는 `rcx`의 값을 카운터로 사용하며, 매번 1씩 줄여요. `rcx`의 값이 0에 도달하면 루프가 끝나고 실행은 순차적으로 이어져요:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

`loop` 명령어에는 반복할 때마다 영 플래그(`ZF`)를 검사하는 두 가지 변형이 있어요. 이들은 `rcx`가 0에 도달하면 루프를 멈추는 것 외에도, 조건이 충족되지 _않을_ 때도 멈춰요.

| instruction       | condition |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == 1 |
| `loopne`/`loopnz` | `ZF` == 0 |

이 명령어들은 `ZF`를 **설정하지 않아요**. 그 앞에는 `ZF`를 바꾸는 `cmp`, `test` 또는 다른 명령어가 있어야 해요:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
편리함에도 불구하고, `loop`, `loope`, `loopne`는 최신 프로세서에서 대응하는 `sub`/`jnz`나 `cmp`/`jnz` 조합보다 보통 훨씬 느려요.

여러 CPU에서의 명령어 성능에 관한 좋은 참고 자료는 [Agner의 표][agner-tables]예요.

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
~~~~
