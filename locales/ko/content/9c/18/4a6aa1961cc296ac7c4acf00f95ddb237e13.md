# 코드 포함

`circus-acts`에서는 `<`를 써서 클래스가 추상 클래스가 설명하는 것을 *할 수 있다*고 표현했어요. 그 방법에 대해서는 아무 말도 하지 않았고요.

`include`는 나머지 절반이에요. 다른 클래스에 있는 실제 코드를 가져와서 이 클래스 안에 복사본을 넣어요.

```sather
class WARM_UP is

   count : INT is return 8; end;

   describe : STR is return count + " counts"; end;

end; -- class WARM_UP

class JAZZ_ROUTINE is

   include WARM_UP;

   -- count and describe are now here too, as though written out.

end; -- class JAZZ_ROUTINE
```

`JAZZ_ROUTINE`에서 따로 언급하지 않았는데도 `JAZZ_ROUTINE::count`는 8이에요.

## 이 둘은 서로 다른 결정이에요

대부분의 언어는 이 둘을 하나로 묶어요. `extends` 하나로 코드를 물려주는 동시에, 상위 클래스가 쓰이는 곳이면 어디든 하위 클래스를 쓸 수 있게 하죠. Sather는 이 둘을 따로 떼어 둬요.

| 작성 | 의미 |
| --- | --- |
| `class A < $B` | `$B`가 필요한 곳이면 어디든 `A`를 쓸 수 있어요 |
| `class A is include B` | `A`가 `B`의 코드 복사본으로 시작해요 |

둘 중 하나만 쓸 수도 있고, 둘 다 쓸 수도 있어요. 클래스를 포함한다고 해서 그 클래스가 하위 타입이 되는 것은 **아니에요**. `include WARM_UP`을 한 뒤에도 `WARM_UP`이 필요한 곳에 `JAZZ_ROUTINE`을 쓸 수는 없고, 그걸 하위 타입인 것처럼 속이지도 않아요.

## 이름 바꾸기

포함한 루틴은 다른 이름으로 가져올 수 있어요:

```sather
   include WARM_UP count -> warm_up_count;
```

여러 개는 쉼표로 구분해요:

```sather
   include WARM_UP count -> warm_up_count, describe -> warm_up_describe;
```

## 하나 제외하기

*없음*으로 이름을 바꾸면 그 루틴은 빠지는데, 이렇게 해서 교체할 수 있어요:

```sather
class TAP_ROUTINE is

   include WARM_UP describe -> ;

   describe : STR is return "Tap: " + count + " counts"; end;

end; -- class TAP_ROUTINE
```

`count`는 평소처럼 따라 들어와요. `describe`는 들어오지 않으니, 여기에 새로 하나를 써도 충돌하지 않아요. `describe -> ;`가 없다면 컴파일러는 받아들이지 않았을 거예요. 한 클래스 안에 이름과 인자가 같은 루틴이 둘 있으면 오류거든요. Sather는 어느 쪽을 의도한 건지 추측하지 않아요.

대부분의 언어에서 말하는 오버라이드와의 차이가 바로 이거예요. 교체한다는 사실을 암시하는 대신 드러내 놓고 알려주는 거죠.
