# 바인딩된 루틴

```sather
   part : ROUT{STR}:STR := bind(shout(_));
   part.call("who's there");
```

## bind

`bind`는 일부를 `_`로 대체할 수 있는 호출을 받아요. `_`가 아닌 부분은 **지금** 평가되어 그대로 유지되고, `_`는 모두 쓰인 순서대로 바인딩된 루틴의 인자가 돼요.

```sather
   bind(repeat(2, _))         -- ROUT{STR}:STR
   bind(repeat(_, "Ha"))      -- ROUT{INT}:STR
   bind(repeat(_, _))         -- ROUT{INT,STR}:STR
```

## 타입

| 타입 | 인자 | 반환값 |
| --- | --- | --- |
| `ROUT:INT` | 없음 | `INT` |
| `ROUT{STR}` | `STR` 하나 | 없음 |
| `ROUT{STR}:STR` | `STR` 하나 | `STR` 하나 |
| `ROUT{INT,INT}:BOOL` | `INT` 두 개 | `BOOL` |

`ITER{...}`는 이터레이터에 대해서도 같은 개념이에요.

## call

`call`은 나머지 인자를 채워 줘요. 아무것도 반환하지 않는 바인딩된 루틴도 문으로서 같은 방식으로 호출해요.

## bind는 대입의 오른쪽에 와요

`bind`는 변수에 선언하거나 인자로 넘길 수 있어요:

```sather
   part ::= bind(shout(_));                -- yes
   part : ROUT{STR}:STR := bind(shout(_)); -- yes
   rehearse("line", bind(shout(_)));       -- yes
```

하지만 `return`에 바로 넣을 수는 없어요:

```sather
   return bind(shout(_));                  -- does not parse
```

변수에 넣은 뒤 그 변수를 반환해요. 오류 메시지는 `bind`를 가리키고 밑줄 문자를 언급하는데, 이는 그 줄만 봐서는 분명하지 않아요.

## 어디에 쓰일까요

라이브러리에서는 동작을 넘겨줘야 하는 곳마다 이 루틴을 받아요:

```sather
   names.sort_by(bind(shorter(_, _)));
   scores.count_if(bind(over(10, _)));
   scores.find_if(bind(is_even(_)));
```

정렬이 가장 명확한 예예요. `sort_by`는 정렬하는 방법은 알지만 정렬 기준에 대해서는 아무것도 몰라요. 바인딩된 루틴이 이 둘을 만나게 해줘요.

## 이 컴파일러의 한 가지 한계

Sather 1.2는 **디스패치되는** 바인딩된 루틴, 즉 추상 타입의 변수에 루틴을 바인딩하는 기능을 구현하지 않았어요. 컴파일러는 이렇게 분명히 알려줘요:

```
Dispatched bound routines are not implemented yet
```

구체적인 타입이나 클래스에 바인딩하면 아무 문제 없어요. 이 트랙의 자체 테스트 하네스가 예외 검사를 바인딩된 루틴을 받아 쓰는 대신 직접 손으로 작성한 이유가 바로 여기에 있어요.

## 바인딩된 루틴일까요, 추상 클래스일까요?

둘 다 호출하는 쪽에서 동작을 넘겨줄 수 있게 해줘요.

바인딩된 루틴은 루틴 하나이고 클래스가 필요 없으며, 쓰이는 자리에서 바로 작성해요. 추상 클래스는 여러 루틴과 약간의 상태를 함께 가지며, 넘겨줄 대상이 여러 부분으로 이루어져 있을 때는 그만한 형식을 갖출 가치가 있어요.

넘겨줄 것이 루틴 하나라면 바인딩해요. 여러 개를 가진 협력자가 필요하다면 클래스를 만들어요.
