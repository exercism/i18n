# 개요

`GENERIC:` 선언은 인자 중 하나의 클래스에 따라 동작이 달라지는 단어를 만들어요. 구체적인 동작은 특정 클래스를 대상으로 하는 *메서드*(`M:`)가 제공해요.

```factor
GENERIC: stringify ( obj -- str )
M: integer stringify number>string ;
M: string  stringify ;
M: f       stringify drop "(none)" ;
```

`stringify`를 호출하면 Factor는 스택 맨 위를 살펴보고, 클래스가 일치하는 가장 구체적인 메서드를 찾아 실행해요. 일치하는 메서드가 없으면 오류가 발생해요.

## 디스패치 클래스

기본적으로 디스패치는 가장 위에 있는 인자(스택 효과에 선언된 첫 번째 입력)를 기준으로 일어나요. 여러 인자를 대상으로 하는 디스패치에 대해서는 `HOOK:`와 `MATH:`를 참고해요. 각각 두 번째 인자 또는 숫자 승격을 기준으로 디스패치해요.

## 제네릭에 메서드 추가하기

제네릭과 클래스 모두를 `USE:`할 수 있다면, 다른 보캐뷸러리에서라도 언제든지 제네릭을 확장할 수 있어요.

```factor
USING: math ;
M: ratio  area drop 0 ;     ! adds an `area` method for ratios
```

## 내장 클래스의 메서드

제네릭은 사용자 정의 튜플에서뿐만 아니라 내장 클래스(`integer`, `string`, `array`, `f`, `t`)에서도 똑같이 잘 동작해요. `f`와 `t`에 대한 메서드는 자연스러운 기본값을 가지는 "is-set?" 스타일의 프레디킷에 특히 유용해요.

## 제네릭이 적합한 경우

다음과 같은 경우에 `GENERIC:`을 사용해요.

- 하나의 연산이 서로 다른 입력에 대해 *정말로 다른* 구현을 가질 때(단순히 레이블을 나열한 `case`가 아닐 때).
- 나중에 다른 코드가 새로운 타입을 추가할 것으로 예상할 때.
- 관련된 모든 클래스에 대해 연산이 정의되어 있음을 타입 시스템이 보장해 주기를 바랄 때(Factor가 빠진 메서드를 대신 나열해 줄 수 있어요).

변형이 고정된 몇 개의 레이블 나열에 불과하다면 `case`가 더 간단해요.
