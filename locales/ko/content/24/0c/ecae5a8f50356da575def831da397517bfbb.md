# 소개

정수는 숫자 값으로만 볼 수 있는 게 아니라 비트 패턴으로도 볼 수 있어요. Factor의 [`math`][math] 어휘에는 이런 비트 패턴에 대한 표준 저수준 연산이 있고, [`math.bitwise`][bitwise] 어휘는 고정 너비 값을 다루는 데 도움이 되는 몇 가지 도우미를 더해줘요.

## 비트 시프트

`shift ( m n -- m' )`는 `m`의 비트를 시프트해요. *양수* `n`은 왼쪽으로 시프트하고(단계마다 2씩 곱해요), *음수* `n`은 오른쪽으로 시프트해요(단계마다 2씩 나눠요):

```factor
3 2 shift .     ! => 12   (3 << 2)
24 -3 shift .   ! => 3    (24 >> 3)
```

양의 정수에서 오른쪽 시프트는 아래쪽 비트를 버리고 0으로 채워요. *음수*의 경우 Factor의 `shift`는 산술 시프트예요. 부호 비트를 보존하며, 개념적으로 왼쪽에서 부호 비트를 복사해 채워요. (Factor 정수는 임의 정밀도라서 "왼쪽"은 필요한 만큼 얼마든지 늘어나요.)

## 비트 논리

네 가지 기본 논리 연산은 다음과 같아요:

```
bitor  ( x y -- z )   ! 1 in either operand
bitand ( x y -- z )   ! 1 in both operands
bitxor ( x y -- z )   ! 1 in exactly one operand
bitnot ( x   -- z )   ! flip every bit
bit?   ( x n -- ? )   ! true when bit at position n is set
```

```factor
0b1011 0b0010 bitor .    ! => 11  (0b1011)
0b1011 0b0010 bitand .   ! => 2   (0b0010)
0b1011 0b0010 bitxor .   ! => 9   (0b1001)
0b1011 bitnot .          ! => -12
0b1011 0 bit? .          ! => t   (low bit is set)
0b1011 2 bit? .          ! => f   (bit 2 is clear)
```

`0b1011`의 `bitnot`이 `-12`인 이유는 Factor 정수가 임의 정밀도이기 때문이에요. `0b1011`의 비트를 뒤집으면 개념적으로 "모두 1인데 하위 4비트만 `0100`으로 뒤집힌" 값이 되고, 이를 부호 있는 큰 정수로 읽으면 `-12`가 돼요.

## 값을 N비트로 취급하기

`math.bitwise`의 `bits ( x n -- y )`는 `x`를 하위 `n`비트로 마스킹해요. 이것이 값을 "N비트 부호 없는 정수로 재해석하는" Factor 방식이에요:

```factor
-1 8 bits .              ! => 255   (lowest 8 bits of -1 are all 1)
-2144333657 32 bits .    ! => 2150633639
```

두 번째 예시는 이 연습 문제에서 중요해요. 음수 2의 보수 Int32 값에서 시작해서 그 값을 `amount`만큼 "논리적으로" 오른쪽 시프트하고(왼쪽에서 0으로 채우고) 싶다면, Factor의 관용구는 다음과 같아요:

```
( value -- shifted )
32 bits  amount neg  shift
```

먼저 32비트로 마스킹해서 부호 없는 해석으로 바꾼 다음, 시프트해요. 마스킹된 값은 음수가 아니므로, `shift`는 그냥 아래쪽 비트를 버리고 0으로 채워요.
