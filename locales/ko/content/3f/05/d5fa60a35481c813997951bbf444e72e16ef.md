# 소개

다른 많은 언어와 마찬가지로 Go에도 포인터가 있어요.
포인터가 처음이라면 조금 신비롭게 느껴질 수 있지만, 익숙해지면 아주 간단해요.
포인터는 Go에서 아주 중요한 부분이니까, 시간을 들여 제대로 이해해 봐요.

세부 사항을 파고들기 전에, 포인터를 어디에 쓰는지 이해해 두면 좋아요.
포인터는 프로그램의 다른 부분과 메모리를 공유하는 방법이고, 두 가지 큰 이유에서 유용해요:

1. 데이터가 많을 때, 함수 사이에 전달하려고 복사본을 만드는 것은 매우 비효율적이에요.
   대신 데이터가 저장된 메모리 위치를 전달하면 프로그램이 사용하는 자원을 크게 줄일 수 있어요.
2. 함수 사이에 포인터를 전달하면 데이터의 단일 복사본에 직접 접근하고 수정할 수 있어요. 즉, 한 함수가 가한 변경 사항은 그 함수가 끝나면 프로그램의 다른 부분에서도 곧바로 확인할 수 있어요.

## 변수와 메모리

정수형 변수 `a`가 하나 있다고 해봐요:

```go
var a int
```

변수를 선언하면 Go는 그 값을 저장할 메모리 공간을 찾아야 해요.
이 과정은 대부분 우리에게서 추상화되어 있어요. 그 메모리 조각에 저장된 값을 가져올 때 우리는 그냥 변수 이름으로 가리키면 돼요.

예를 들어 `a + 2`라고 쓰면, 변수 `a`와 연결된 메모리에 저장된 값을 가져와 2를 더하는 셈이에요.

마찬가지로 `a`의 메모리 조각에 있는 값을 바꾸고 싶을 때는 변수 이름으로 값을 할당하면 돼요:

```go
a = 3
```

이제 `a`와 연결된 메모리 조각에는 값 `3`이 저장돼요.

## 포인터

변수를 사용하면 메모리에 있는 값을 가리킬 수 있지만, 때로는 그 변수가 가리키는 **메모리 주소**를 아는 것이 유용해요.
**포인터**는 그 값들의 메모리 주소를 담고 있어요.
기반 타입 앞에 별표를 붙이면 포인터 타입의 변수를 선언할 수 있어요:

```go
var p *int // 'p' contains the memory address of an integer
```

여기서는 "int에 대한 포인터"(`*int`) 타입의 변수 `p`를 선언해요.
이는 `p`가 정수의 메모리 주소를 담게 된다는 뜻이에요.
포인터의 제로 값은 `nil`이에요. `nil` 포인터는 어떤 메모리 주소도 담고 있지 않기 때문이에요.

### 변수에 대한 포인터 구하기

변수의 값이 있는 메모리 주소를 찾으려면 `&` 연산자를 사용하면 돼요.
예를 들어 변수 `a`의 메모리 주소를 찾아 포인터 `p`에 저장하고 싶다면, 다음과 같이 하면 돼요:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### 포인터를 통해 값에 접근하기 (역참조)

포인터가 있을 때, 그 포인터가 가리키는 메모리 주소에 저장된 값을 알고 싶을 수 있어요.
이때는 `*` 연산자를 사용하면 돼요:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

`*p` 연산은 `p`에 저장된 메모리 주소에 있는 값을 가져와요.
이 연산을 흔히 "역참조"라고 불러요.

역참조 연산자를 사용해 포인터가 참조하는 메모리 주소에 새로운 값을 할당할 수도 있어요:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

`*pa`에 값을 할당하면 `pa`가 담고 있는 메모리 주소에 저장된 값이 바뀌어요.
`pa`가 `a`의 메모리 주소를 담고 있으니, `*pa`에 값을 할당하는 것은 결국 `a`의 값을 바꾸는 거예요!

그런데 주의할 점이 있어요. 역참조하기 전에 항상 포인터가 `nil`이 아닌지 확인해요.
`nil` 포인터를 역참조하면 프로그램이 실행 중에 충돌해요!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### 구조체에 대한 포인터

지금까지는 기본형 값에 대한 포인터만 살펴봤어요.
구조체에 대한 포인터도 만들 수 있어요:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

새 `Person`을 만들면서 곧바로 그에 대한 포인터를 저장할 수도 있어요:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

구조체에 대한 포인터가 있으면, 필드에 접근하기 전에 포인터를 역참조할 필요가 없어요:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## 슬라이스와 맵은 이미 포인터예요

슬라이스와 맵은 구현에 이미 포인터가 들어 있는 특별한 타입이에요.
그래서 이런 타입에서는 값의 메모리 주소를 공유하려고 포인터를 만들 필요가 없는 경우가 대부분이에요.
맵에서 어떤 키의 값을 1 증가시키는 함수가 있다고 상상해 봐요:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

맵을 만들고 이 함수를 호출하면, 함수가 맵에 가한 변경 사항은 함수가 끝난 뒤에도 그대로 남아 있어요.
포인터를 사용했을 때와 비슷한 동작이에요. 그런데 이 예제에서는 참조나 역참조 같은 포인터 문법을 전혀 쓰지 않았다는 점을 눈여겨봐요:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

슬라이스에 이미 있는 항목을 바꿀 때도 마찬가지예요.

하지만 `append`처럼 새로운 슬라이스를 반환하는 동작은 특별한 경우라서, 함수 바깥의 슬라이스를 **바꾸지 않을 수도** 있어요.
이는 슬라이스가 내부적으로 동작하는 방식 때문인데, 더 고급 주제라 여기서는 자세히 다루지 않을게요.
정말 궁금하다면 [Go Blog: 'append'의 동작 원리][mechanics-of-append]에서 더 자세히 읽어볼 수 있어요.
