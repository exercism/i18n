# 힌트

## 일반

- `movapd`와 `movaps`는 메모리 피연산자가 정렬되어 있다고 알려진 경우에만 사용해야 해요.
  두 피연산자가 모두 `xmm` 레지스터일 때는 안전하게 사용할 수 있어요.
- 메모리 주소는 정수 값으로 전달돼요.
  처음 여섯 개의 정수 인자는 각각 `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9`를 통해 함수에 전달돼요.

## 1. 두 라인의 산출량 결합하기

- 32비트 부동소수점의 패킹된 덧셈은 `addps`예요.
- 세 개의 포인터 인자는 모두 16바이트로 정렬되어 있음이 보장되므로, 정렬된 이동 변형인 `movaps`가 적절해요.

## 2. 스케일된 편차 계산하기

- 64비트 부동소수점의 패킹된 뺄셈은 `subpd`예요.
- 64비트 부동소수점의 패킹된 곱셈은 `mulpd`예요.
- `measured`는 정렬되어 있지만 `target`은 그렇지 않으므로, 서로 다른 로드 변형이 필요해요.

## 3. 배치 보정하기

- `reference`와 `offset`은 둘 다 정렬되어 있지만 `raw`는 그렇지 않으므로, 서로 다른 로드 변형이 필요해요.
- 두 행 모두 `reference`와 `offset`이 필요해요.
- 피연산자가 두 개인 명령어는 보통 목적지 피연산자를 덮어써요.
- `raw`의 상위 두 개 부동소수점 값을 배정밀도 부동소수점 값으로 변환하려면, raw 포인터에서 8바이트만큼 오프셋된 메모리 피연산자와 함께 `cvtps2pd`를 사용해요.
- 변환 계수는 64비트 부동소수점 숫자 두 개(둘 다 `0.5`)로 메모리에 저장해야 해요.
- 결과는 32바이트(64비트 부동소수점 숫자 네 개)에 걸쳐 있어요. 처음 16바이트는 `[result]`에, 다음 16바이트는 `[result + 16]`에 있어요.

## 4. 라인을 따라 점수 정규화하기

- 피연산자가 두 개인 명령어는 보통 목적지 피연산자를 덮어써요.
- 산술 패킹 명령어에서 메모리는 목적지 피연산자가 될 수 없어요.
- `scores` 배열(첫 번째 인자)의 각 64비트 부동소수점 `score`에 대응하는 `gain`이 `gains` 배열(두 번째 인자)에 있어요.
  각 `score`는 같은 위치의 `gain`과 연산돼요.
- 세 번째 인자는 패킹된 64비트 부동소수점 숫자 두 개를 가진 고정된 `scale`이에요.
- 각 `score`와 `gain` 쌍에 대해 함수는 `score * gain / scale_lane`을 계산해요.
  `scale`의 첫 번째 레인은 각 쌍의 첫 번째 원소(짝수 위치의 레인)를 스케일하고, 두 번째 레인은 두 번째 원소(홀수 위치의 레인)를 스케일해요.
- 정규화된 점수는 입력 `score`와 같은 위치의 `scores` 배열에 제자리에 저장돼요.
- `scores`와 `gains`의 원소 개수는 서로 같고 `n`(네 번째 인자)의 값과 같아요.
- 모든 원소 쌍을 처리하려면 반복할 때마다 16바이트(원소 두 개)씩 이동하는 루프를 사용해야 해요.
