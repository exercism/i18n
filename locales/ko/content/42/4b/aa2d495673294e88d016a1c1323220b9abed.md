# 개요

이전 개념에서 `global` 지시문은 한 소스 파일에 정의된 함수나 변수를 다른 파일에서도 볼 수 있게 해준다고 했어요.
마찬가지로 `extern` 지시문은 현재 소스 파일에서 사용하는 함수나 변수가 다른 파일에 정의되어 있다는 것을 어셈블러에게 알려줘요.

이 두 지시문은 어셈블리 코드가 다른 소스 파일과 상호작용하며 모듈화를 이루는 주된 방법이에요.

이 지시문들 입장에서는 외부 코드가 어셈블리로 정의되었든 고급 언어로 정의되었든 상관없어요.
그래서 예를 들어 고급 언어로 정의된 함수라도 `extern`으로 선언하기만 하면 x86-64 코드에서 사용할 수 있어요.

같은 방식으로 호출 규약은 어셈블리든 고급 언어든 이 모든 함수에, 심지어 운영체제(OS)와도 공유돼요.

하지만 어셈블리에서 데이터는 그저 바이트의 나열일 뿐이라, 함께 사용하는 고급 언어가 메모리를 어떻게 관리하는지 알아두는 게 중요해요.

## C 타입

C 언어는 어셈블리 코드와 연동할 고급 언어로 흔히 선택돼요.
화면에 출력하기, 키보드에서 입력 받기, 동적 메모리 할당하기처럼 중요한 작업을 위한 고급 래퍼를 제공해서 운영체제와 상호작용하는 일을 더 쉽게 만들어줘요.

이 트랙에서는 테스트가 C로 작성되어 있어서, 이 언어를 전반적으로 훑어보는 게 중요해요.

### 기본 타입

C에는 기본 타입이 아주 많고, 크기는 바이트 단위로 달라질 수 있어요.
그중 몇 가지를 x86-64 시스템에서의 일반적인 크기와 함께 다음 표에 정리했어요:

| 타입      | 바이트 수 | 정수/부동소수점 |
|-----------|-----------------|------------------------|
| _Bool     | 1               | 정수                |
| char      | 1               | 정수                |
| short     | 2               | 정수                |
| int       | 4               | 정수                |
| long      | 4 또는 8          | 정수                |
| long long | 8               | 정수                |
| float     | 4               | 부동소수점         |
| double    | 8               | 부동소수점         |

이 정수 타입은 각각 부호 있는 형태(기본값)이거나 부호 없는 형태일 수 있어요.
부호 없는 경우에는 이를 명시해야 하는데, 예를 들어 `unsigned int`처럼 써요.

정수 타입에는 크기를 정확하게 제어할 수 있도록 정의된 별칭도 있어요:

| 별칭   | 바이트 수 |
|---------|-----------------|
| int8_t  | 1               |
| int16_t | 2               |
| int32_t | 4               |
| int64_t | 8               |

이 별칭들은 부호 없는 타입을 나타내기 위해 앞에 `u`를 붙일 수 있어요. 예를 들어 `uint64_t`처럼요.

그 밖에 알아둘 만한 별칭은 다음과 같아요:

| 별칭  | 타입                                          |
|--------|-----------------------------------------------|
| bool   | _Bool                                         |
| size_t | 보통 부호 없는 8바이트 정수            |

`_Bool`, 또는 그 별칭인 `bool`은 1바이트를 통째로 차지하면서도 `true`(`1`)와 `false`(`0`) 두 값 중 하나만 가질 수 있다는 점이 독특해요.

이 기본 타입의 값은 정수와 부동소수점 값에 대한 일반적인 규칙에 따라 함수에 전달되고 함수에서 반환돼요.

### enum

[enum][enum]은 명시적으로 나열된 여러 요소 중 하나의 값을 가질 수 있는 타입이에요:

```c
enum example {
    example_1,
    example_2,
    example_3,
    example_4
};
```

C에서 enum은 암묵적으로 정수 타입으로 변환되는데, 보통 `int`, 즉 4바이트 정수로 변환돼요.

기본적으로 enum의 첫 번째 요소는 `0`으로 변환되고, 그다음 요소들은 차례로 다음 정수로 변환돼요.
그래서 위에서 정의한 `enum example`에서는 `example_1`이 `0`, `example_2`가 `1`이 되는 식이에요.

enum의 각 요소에 값을 지정할 수도 있는데, 그러면 기본적으로 다음 요소는 그다음 정수를 값으로 가져요:

```c
enum example_2 {
    example_1 = 4,
    example_2 = 8,
    example_3
}; // example_3 is equal to 9
```

### 메모리 주소

C에서 메모리 주소는 어떤 타입을 가리키는 [포인터][pointer]로 참조하고, `*` 연산자로 나타내요.
예를 들어 `int64_t *`는 하나 이상의 `int64_t`가 있는 메모리 위치를 가리켜요.

주소는 늘 그렇듯 8바이트 정수로 취급돼요.

### 배열

배열은 첫 번째 요소를 가리키는 포인터로 함수에 전달되고 함수에서 반환돼요.

```c
int64_t example_arr[] = {1, 2, 3}; // this is an array of 3 signed 8-byte integers
fn(example_arr); // this is a function that passes a pointer (int64_t *) to the beginning of the array as argument
```

배열의 각 요소는 배열 요소 타입의 크기를 가져요.
예를 들어 위에서 정의한 `example_arr`은 8바이트짜리 요소 3개, 즉 총 24바이트예요.

배열은 길이를 저장하지 않기 때문에, 끝을 표시하는 센티넬 값이 없는 한 요소 개수를 알려주는 별도의 값이 보통 필요해요.

### 문자열

C에서 문자열은 `char`의 배열이고, `char`는 1바이트 타입이에요.
대부분의 문자열은 ASCII 문자로 이루어지고 NUL로 끝나서, 값이 `0`인 바이트를 만나면 끝나요.
즉, 문자열의 길이를 별도의 인자로 넘겨줄 필요가 보통은 없어요.

## C 라이브러리 함수 호출하기

`extern` 지시문은 어떤 심볼이 다른 파일에 정의되어 있다고 선언할 뿐이에요.
그 심볼을 실제로 어떻게 호출하는지는 그 외부 코드가 어떻게 링크되는지에 달려 있어요.

작성한 코드와 함께 링크되는 일반적인 함수라면 링커가 외부 함수를 직접 찾을 수 있어서, 그냥 `call`만 써도 충분해요.

하지만 `malloc`, `free`, `printf` 같은 표준 C 라이브러리 함수는 보통 런타임에 공유 라이브러리에서 해석되는데, 그 주소는 코드를 어셈블할 때 알 수 없어요.
따라서 호출은 알려진 오프셋에 놓인 [프로시저 링키지 테이블(PLT)][plt]의 스텁을 거쳐요.
어셈블리에서 외부 라이브러리 함수를 호출할 때는 NASM이 이 호출을 PLT에서 해석해야 한다는 표시를 요구해요.

`elf64`(Linux 프로그램이 사용하는 출력 형식)에서는 호출 뒤에 `wrt ..plt`("plt를 참조하라는 뜻")를 붙여서 표시해요.
예를 들어 `call printf wrt ..plt`처럼요.

반면 `macho64` 프로그램(macOS 프로그램이 사용하는 출력 형식)에서는 함수 이름 앞에 밑줄을 붙이면 충분해요.
예를 들어 `extern _printf`를 쓰고 `call _printf`를 호출하면 돼요.
그런데 이 트랙은 `macho64` 코드를 `--prefix _` 플래그로 어셈블하기 때문에, 두 경우 모두 이 밑줄이 어셈블러에 의해 자동으로 붙어요. 예를 들어 `extern printf`를 쓰고 `call printf`를 호출하면 돼요.

Exercism의 테스트 러너는 Linux 이미지에서 실행되므로, C 라이브러리 함수를 호출하는 제출한 풀이는 반드시 `wrt ..plt`를 써야 해요.
어셈블 시점의 가드를 사용하면 출력 형식에 따라 올바르게 분기할 수 있어요:

```x86asm
extern malloc

%ifidn __OUTPUT_FORMAT__,elf64
    call malloc wrt ..plt       ; elf64: reach the function through the PLT
%else
    call malloc                 ; macho64: the linker generates the call stub
                                ; the underscore is added automatically by an assembler flag
%endif
```

## 시스템 호출

이 트랙에서 실행되는 프로그램처럼 사용자 수준의 프로그램이 직접 수행할 수 없는 작업이 많아요.
`stdin`에서 읽기, `stdout`에 쓰기, 동적 메모리 요청, 주변기기와 상호작용하기 등은 모두 운영체제(OS)가 처리해요.

사용자 수준의 프로그램은 필요할 때 이런 작업을 수행해 달라고 운영체제에 명시적으로 요청해야 해요.
이때 [`syscall`][syscall] 명령어를 사용해요.
개념적으로 이 명령어는 미리 정의된 운영체제 프로시저, 즉 "시스템" 호출이라고 생각할 수 있어요.

시스템 호출에 필요한 인자는 범용 레지스터(GPR)에 담아 운영체제에 전달해요: `rdi`, `rsi`, `rdx`, `r10`, `r8`, `r9`.

이 순서는 함수 호출에서 쓰는 순서와 거의 같은데, `rcx` 대신 `r10`을 쓴다는 점이 달라요.
`syscall`이 반환 주소와 플래그를 저장하는 데 `rcx`와 `r11`을 사용하기 때문이에요. 이 값들은 제어권을 호출한 함수로 되돌리기 전에 복원돼요.
두 레지스터 모두 `syscall`을 거치면 값이 덮어써진다고 봐야 해요.

`call`과 달리 시스템 "함수"를 가리키는 레이블이 없어요.
대신 호출 전에 `rax`에 넣은 특정 번호를 통해 접근해요.
반환값이 있다면 그것도 `rax`에 담겨요.

위 규약은 [System V ABI의 부록][linux-convention]에 설명되어 있는데, 이 부록은 Linux를 구체적으로 다루며 정보 제공용으로만 표시되어 있어요.
실제로 사용할 수 있는 시스템 호출, 그 번호, 오류를 보고하는 방식은 운영체제 수준의 세부 사항이라 운영체제마다 크게 다르고, 같은 운영체제의 버전에 따라서도 달라요.

많은 C 라이브러리 함수와 운영체제가 정의한 다른 실제 함수들은 시스템 호출을 감싼 상위 수준의 래퍼예요.
ABI는 이런 래퍼를 그냥 `syscall`보다 우선해서 쓰라고 권장하고, Apple은 커널 시스템 호출 인터페이스에서 [호환성을 보장하지 않아요][mac-qa1118].
