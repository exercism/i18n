# 소개

## 배열

어셈블리에서 모든 데이터는 바이트의 연속이에요.
다시 말해, 어떤 데이터든 그 바탕이 되는 바이트들의 **배열**로 볼 수 있어요.

### 배열의 원소에 접근하기

메모리에 있는 어떤 값에든 접근하려면, 그 값의 **유효 주소**를 계산해야 해요.
유효 주소는 다음과 같이 구성될 수 있는 표현식이에요.

- _기준 주소_. 예를 들어 변수의 레이블이 가리키는 주소예요.
- `1`, `2`, `4`, `8`로 스케일될 수 있는 _인덱스 레지스터_ 하나.
- 기준 주소에 더하거나 빼는 수인, 부호 있는 32비트 _변위_ 하나.

이 주소의 인덱스는 _0부터 시작_한다는 점에 유의해요.
그래서 오프셋 없이 기준 주소만 사용하면 변수의 첫 번째 바이트를 가리켜요.
이전 개념에서 해 왔던 것처럼, 오프셋 없이 레이블만으로 메모리를 역참조하면 첫 번째 바이트에서 시작하는 값을 얻는 이유가 바로 여기에 있어요.

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64는 [리틀 엔디언][endianness]이에요.
즉, 여러 바이트로 이루어진 값에서 최하위 바이트가 가장 작은 메모리 주소에 저장돼요.

따라서 여러 바이트 값의 개별 바이트에 접근할 때는, 더 상위의 바이트에 닿기 위해 기준 주소에 양수 오프셋을 더해야 해요.

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

값의 목록으로 선언한 초기화된 변수는 그 값들의 배열이고, 각 원소는 지정한 크기를 가져요.
하지만 배열의 각 원소가 더 큰 크기를 가지더라도, 오프셋은 언제나 **_바이트_** 단위예요.

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

주소가 바이트 단위이므로, 배열의 어떤 원소든 개별 바이트에 곧바로 접근할 수 있다는 점에 유의해요.

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

같은 이유로, 한 명령어에서 원소의 크기보다 더 많은 바이트에 접근할 수도 있어요.

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
어셈블리는 배열 접근에 대해 경계 검사를 하지 않아요.
배열의 끝을 넘어선 인덱스는 배열 바깥의 메모리를 읽거나 써요.
이는 조용히 잘못된 결과를 낳거나 다른 데이터를 훼손할 수 있고, 접근한 메모리가 매핑되어 있지 않다면 런타임 오류로 이어질 수도 있어요.
모든 유효 주소를 배열 안에 유지하는 것은 프로그래머의 몫이에요.
~~~~

### 초기화된 배열의 크기 계산하기

NASM(Netwide Assembler, 이 트랙에서 사용하는 어셈블러)에는 메모리의 현재 위치를 나타내는 특별한 기호(`$`)가 있어요.
이 기호는 배열이 메모리에서 차지하는 전체 크기를 편리하게 계산하는 방법을 제공해요.

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

`example` 바로 뒤에 사용하면, `$`는 배열의 끝을 가리키는 메모리 주소를 가져요.
즉 `$ - example`은 그 주소와 레이블 `example`이 가리키는 주소의 차이예요.
이 값이 바로 `example`이 가리키는 배열이 차지하는 전체 크기(바이트)예요.

그래서 이 값으로 `example_length`를 정의하면, 배열의 크기, 즉 길이를 바이트 단위로 저장하는 8바이트 변수를 만든 셈이에요.

### .bss 섹션

초기화하지 않은 데이터는 **.bss 섹션**에 선언해요.
대부분의 플랫폼에서 이 데이터는 프로그램이 시작할 때 운영체제가 0으로 채워요.

NASM에서 초기화하지 않은 변수는 이름, 데이터 크기를 나타내는 지시자, 그리고 예약할 원소의 개수로 이루어져요.
이들은 각각 공백 하나로 구분해요.

주요 지시자와 그에 해당하는 데이터 크기는 다음과 같아요.

| 지시자 | 크기    |
| :-------: | :------ |
|   resb    | 1바이트  |
|   resw    | 2바이트 |
|   resd    | 4바이트 |
|   resq    | 8바이트 |

예를 들어, 다음은 `example`이라는 변수에 `3`바이트만큼의 초기화되지 않은 공간을 예약해요.

```x86asm
section .bss
    example resb 3
```

그리고 다음은 `arr`이라는 변수에 `10` 곱하기 `8`바이트, 즉 `80`바이트만큼의 초기화되지 않은 공간을 예약해요.

```x86asm
section .bss
    arr resq 10
```

`section .bss`의 변수는 변경 가능해요. 즉, 읽고 쓸 수 있어요.

초기화하지 않은 데이터도 유효 주소를 사용하면 초기화된 데이터와 같은 방식으로 접근할 수 있어요.
마찬가지로 정적 저장 기간을 가지며, 같은 소스 파일의 어떤 함수에서든 접근할 수 있어요(그리고 `global`로 선언했다면 다른 소스 파일에서도 접근할 수 있어요).

### Lea 명령어로 배열 주소에 접근하기

이전 개념에서 살펴봤듯이, `lea` 명령어는 유효 메모리 주소를 계산해요.
같은 방식으로 배열의 어떤 원소의 주소든 계산하는 데 사용할 수 있어요.

상대 주소 지정에서는 더 복잡한 주소를 만들기 전에 변수의 주소를 레지스터에 먼저 로드해야 하는 경우가 많아요.

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
`lea`의 장점 중 하나는, 해당 주소의 메모리에 실제로 접근하지 않고도 주소 계산용 산술을 이용해 값을 계산한다는 점이에요.
그래서 어떤 레지스터도 메모리 주소를 담고 있지 않을 때도 산술 계산을 하는 데 유용해요.

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
