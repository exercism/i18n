# 소개

함수형 프로그래밍이란 무엇일까요?

이 글에서 다룰 핵심 특징은 다음과 같아요.

- 순수 함수는 입력을 출력으로 일관되게 대응시키고, 부작용이 없어요.
- 불변 데이터.
- 일급 함수는 다른 자료형처럼 값으로 다룰 수 있어요.
- 고차 함수는 다른 함수를 인자로 받거나 반환값으로 내놓아요.

하지만 R은 순수 함수형 언어가 아니에요 (예를 들어 Haskell과는 달라요).

R을 실용적인 언어로 봐요. R은 어떤 일을 깔끔하고 쉽게 해내는 데 함수형 기능이 도움이 될 때, 그 기능을 (점점 더 많이) 제공해요.
일반적으로 목표는 데이터 분석이고, 프로그래밍은 그 목표를 이루는 수단일 뿐이에요.

## 파이프

`|>` 파이프로 함수를 연결하는 기법은 여러 언어에서 점점 흔해지고 있어요.

간단히 정리하면 다음과 같아요.

- 파이프 왼쪽의 결과가 오른쪽 함수의 첫 번째 인자가 돼요 (여기서 "오른쪽"은 선택적인 줄바꿈은 무시해요).
- 나머지 인자는 함수 호출에 함께 넣을 수 있어요.
- R에서는 함수 _이름_이 아니라 함수 _호출_로 파이프해야 하므로, 괄호가 항상 필요해요 (_다른 언어와는 다른 점이에요_).

어떤 프로그래머들은 코드를 훑어볼 때 파이프를 "그다음"이라고 읽으면 도움이 된다고 해요. 1단계를 하고, 그다음에 2단계를 해요...

아래 예제는 이 문법을 보여줘요.

```R
library(stringr)

"Monday-25-February" |> 
  str_split("-") |>     
  unlist() |>               # [1] "Monday"   "25"       "February"
  str_sub(1, 3) |>          # [1] "Mon" "25"  "Feb"
  str_to_upper() |>         # [1] "MON" "25"  "FEB"
  str_flatten(collapse = ", ")
#> [1] "MON, 25, FEB"
```

이런 종류의 파이프는 R 4.1.0에서 Base R에 추가됐고, "네이티브 파이프"라고도 불려요.

RStudio 편집기(다른 편집기도 마찬가지예요)에서는 `Ctrl-Shift-M` 단축키로 알맞은 공백과 함께 파이프를 넣을 수 있어요.

## apply 함수

앞에서 R의 많은 함수가 "벡터화"되어 있다는 걸 봤어요. 이런 함수는 명시적인 루프를 쓰지 않고도 벡터 전체에 작동해요.

벡터화된 함수만 사용하는 함수는 그 자체로 자동으로 벡터화될 가능성이 높아요.
간단한 예를 들어볼까요.

```R
triple <- function(x) return(3 * x)
triple(1:10)
 [1]  3  6  9 12 15 18 21 24 27 30
 ```

하지만 더 복잡한 함수는 벡터 입력을 받지 못할 수도 있어요. 예를 들어 루프나 if-else 블록을 포함한 경우가 그래요.

벡터에 함수를 적용하는 더 일반적인 방법이 필요해요 (다른 언어의 `map()`과 비슷해요).

R은 기본 언어에 다양한 자료 구조를 갖추고 있어서, 그것들을 다루는 `*apply()` 함수 패밀리도 통째로 갖고 있어요.
더 기술적으로 말하면, 함수를 인자로 받기 때문에 프로그래머들은 이런 함수를 흔히 "고차 함수"라고 부르고, 수학자들은 "범함수"라고 불러요.

지금은 `lapply()`와 `sapply()`를 살펴봐요.

### `lapply()`

"List-apply"는 배열 입력을 다루도록 설계됐지만, 필요하면 벡터가 조용히 배열로 변환돼요.

출력은 배열이라서, 벡터로 만들려면 다시 풀어내야 할 수도 있어요.

```R
h <- function(size) {
    switch(size,
           "small" = 6,
           "medium" = 8,
           "large" = 10
    )
}

v <- c("small", "large", "medium")

h(v) # bad use of an unvectorized function
#> Error in switch(size, small = 6, medium = 8, large = 10) : 
#>   EXPR must be a length 1 vector

lapply(v, h)  # output is a list
#> [[1]]
#> [1] 6

#> [[2]]
#> [1] 10

#> [[3]]
#> [1] 8

lapply(v, h) |> unlist() # output is a vector
#> [1]  6 10  8
```

[Switch 개념][concept-switch]을 아는 분이라면, 스칼라 `switch`를 [`dplyr`][ref-dplyr] 라이브러리의 벡터화된 [`recode_values()`][ref-recode_values]로 대신 바꿀 수도 있다는 걸 눈치챘을 거예요.
벡터화는 좋은 것이고, 현대 R은 벡터화를 이루는 여러 방법을 제공해요.

```R
library(dplyr)

h <- function(size) {
  recode_values(size,
         "small" ~ 6,
         "medium" ~ 8,
         "large" ~ 10
  )
}

v <- c("small", "large", "medium")
h(v)
#> [1]  6 10  8
```

### [`sapply()`][ref-lapply]

"Simplified-apply"는 `lapply`와 비슷한 일을 하지만, 반환값을 단순화하려고도 해요. 예를 들어 배열 대신 이름이 붙은 벡터를 돌려줘요.
상황에 따라 [`unname()`][ref-unname]을 써야 할 수도 있어요.

```R
sapply(v, h)
 small  large medium 
     6     10      8 

sapply(v, h) |> unname()
#> [1]  6 10  8
```

## `purrr` 라이브러리

`lapply`와 `sapply`는 간단하고, 대부분의 R 사용자에게 익숙하며, 벡터와 단순한 배열에는 여전히 꽤 인기가 많아요.

Base R에는 다른 apply 함수도 _아주 많아요_.
이런 혼란을 더 간단하고 일관된 것으로 대체하는 것이 Tidyverse의 핵심 목표예요.

이제 `purrr` 패키지가 있어서, `map()` 같은 여러 가지 추가 선택지를 제공하면서 설계의 일관성과 오류 메시지의 명확성도 높여줘요.

base R보다 하위 호환성에 덜 얽매인 이 패키지는, R을 다른 언어에서 볼 수 있는 현대적인 함수형 프로그래밍에 훨씬 가깝게 이끌어 줘요.

`purrr`에는 다양하고 많은 함수가 있어서 간단히 요약하기 어려워요.
라이브러리를 살펴보는 데 도움이 되는 자료는 다음과 같아요.

- [웹사이트][web-purrr]가 있고, [시작하기][web-starting] 안내도 있어요.
- 모든 함수를 담은 [레퍼런스 페이지][ref-purrr-funcs]도 있어요.
- PDF 형식의 [치트 시트][cheat-purrr]도 있어요.
- [Base R][web-from-R]에서 옮겨오는 방법을 다룬 안내도 있어요.

### 다양한 map 함수

[map()][ref-map] 함수는 입력의 각 원소에 함수를 적용하고, 항상 [배열][concept-lists]을 반환해요.

지금까지 들으면 [`lapply()`][ref-lapply]와 이름만 바꾼 것 같고, 오류 메시지가 조금 더 나은 정도로 들려요.

하지만 `map()`은 _거대한_ 패밀리의 한 구성원일 뿐이에요.

함수를 고를 때 생각해 볼 질문이 몇 가지 있어요.

- 무엇을 반환하고 싶나요? [`map()`][ref-map]은 항상 배열을 반환하지만, 특정한 원자 벡터를 원한다면 문자열에는 [`map_chr()`][ref-map_chr], 정수에는 [`map_int()`][ref-map_int] 등을 써요.
- 입력의 각 위치 인덱스가 필요한가요? [`imap()`][ref-imap]처럼 함수 이름 앞에 `i`를 붙여요.
- 여러 입력을 병렬로 처리하고 싶나요? 
  - 이름에서 `map`을 `map2`로 바꿔요. 두 입력(예: 값과 가중치로 가중 평균을 구할 때)에는 [`map2_dbl()`][ref-map2_dbl]처럼 써요.
  - 병렬 입력의 배열에는 `pmap`으로 바꿔요. [`pmap_chr()`][ref-pmap_chr]처럼요. 그리고 네, 하드웨어 수준의 병렬 처리도 가능해요.
- 입력의 모든 원소를 처리하고 싶나요? 아니라면 [`map_if()`][ref-map_if]로 조건자(불리언) 필터를 적용하거나, [`map_at()`][ref-map_at]으로 위치 인덱스 기준을 지정하거나, [`head_while()`][ref-head_while]로 어떤 원소가 조건자를 통과하지 못할 때까지 입력을 처리하는 방법을 생각해 봐요.
- 입력 데이터가 깊게 중첩돼 있나요? 그런 상황을 위한 [함수][ref-plucks]도 있어요.
- 반환값이 항상 입력과 같은 타입이길 원하나요? `map` 대신 [`modify()`][ref-modify] 함수를 쓰거나, 재귀적으로 적용하려면 [`modify_tree()`][ref-modify_tree]를 써요.

이 함수들은 파이프와 잘 맞도록, 가능하면 항상 입력 데이터를 첫 번째 인자로 받아요.

또한 `purrr`는 (일부러) Base R보다 더 깐깐해요. 특정한 것을 요청하면, 함수는 _정확히_ 그것을 반환하거나 오류 메시지와 함께 멈춰요.
가혹하지만, 찾기 어려운 버그를 줄이는 데 아주 효과적이에요.

### reduce 함수

map 함수는 일반적으로 입력과 길이가 같은 값을 반환해요.

다른 함수들은 데이터의 차원을 _줄여요_. 예를 들어 `sum()`이 그래요.

```R
sum(1:100)
#> [1] 5050
```

위의 경우, 길이 100인 벡터를 길이 1인 정수로 바꿨어요.
행렬과 배열을 다루는 이후 개념에서 차원 축소라는 개념이 더 일반적이라는 걸 보게 될 거예요.

`sum()` 함수는 기본 내장이에요 (다른 많은 통계 함수도 마찬가지예요).
하지만 `map()`에 해당하는 고차 함수를 써서, 임의의 차원 축소 함수를 자료 구조 전체에 적용할 방법이 필요해요.

다른 여러 언어에서는 `fold`, `foldl`, `foldr` 같은 함수 이름을 써요. R에서는 [`reduce()`][ref-reduce]가 그 역할을 하고, 알고리즘을 좋아하는 사람이라면 잘 아는 MapReduce 프레임워크에 해당해요.

첫 번째 인자는 늘 그렇듯 입력 데이터예요. 두 번째 인자는 인자가 두 개인 함수인데, 흔히 익명 함수지만 `+` 같은 산술 연산자처럼 단순할 수도 있어요.

```R
# surround an infix operator with backticks, to use as a function
reduce(1:100, `+`)
#> [1] 5050  # same as sum(1:100)

# anonymous function, alternately add and subtract
reduce(1:10, \(accum, nextval) ifelse(nextval %% 2 == 0, accum + nextval, accum - nextval))
#> [1] 7
```

함수를 입력의 앞에서부터 적용하든 끝에서부터 적용하든 결과가 달라질까요?

`+`나 `*`처럼 [결합 법칙][wiki-associative]이 성립하는 연산자에서는 달라지지 않아요.
`(1 + 2) + 3 == 1 + (2 + 3)`인 건 분명해요.

반대로 `-`와 `/`는 결합 법칙이 성립하지 않아요.

```R
(1 - 2) - 3
#> [1] -4
1 - (2 - 3)
#> [1] 2
```

방향이 중요한 함수에는 선택적인 `.dir` 인자가 있어요.

```R
# default is .dir = "forward"
reduce(1:10, `-`)
#> [1] -53
reduce(1:10, `-`, .dir = "backward")
#> [1] -5
```

`map()`과 `map2()`에서처럼, 두 입력 벡터를 병렬로 다루는 [`reduce2()`][ref-reduce] 함수도 있어요.

R에서는 벡터를 다루는 걸 좋아해요.
최종 값 하나 대신 모든 중간 단계를 보고 싶다고 해봐요.

이럴 때 쓰는 함수가 [`accumulate()`][ref-accumulate]와 `accumulate2()`예요.
문법은 `reduce()`와 비슷하고, 출력 타입을 지정하는 선택적 인자가 몇 개 더 있어요.

```R
accumulate(1:10, `+`)
#> [1]  1  3  6 10 15 21 28 36 45 55
 ```

흔히 쓰이는 accumulate에는 전용 함수가 있어요.
[벡터 함수][concept-vector-functions] 개념에서는 Base R의 [`cumsum()`][ref-cumsum]과 `cumprod()`를 다뤘고, `dplyr` 라이브러리에는 수치 평균을 위한 [`cummean()`][ref-dplyr-cum], 논리 벡터를 위한 `cumall()`과 `cumany()`가 있어요.

### 필터 함수

흔히 입력에서 특정 조건자에 맞는 원소를 포함하거나 제외하고 싶어요.

[벡터 필터링][concept-vector-filtering] 개념에서 이걸 하는 관용적인 방법 하나를 봤어요.

```R
v <- 1:3
v[v >= 2]
#> [1] 2 3
```

전통적인 R에서 많이 쓰이지만, 현대적인 함수형 파이프라인에는 잘 어울리지 않아요.

그래서 `purrr`는 [조건자 함수][ref-predicates] 모음을 제공하는데, 파이프와 잘 맞도록 `f(input, func, ...)`라는 늘 쓰는 인자 규칙을 따라요.

이름은 대부분의 다른 언어와 조금 달라요 (`filter`나 `drop` 같은 이름은 R에서 이미 전혀 다른 의미로 쓰여요).

해당하는 `purrr` 함수로는 [`keep()`][ref-keep]과 [`discard()`][ref-keep], 그 밖에 여러 가지가 있어요.

또한 논리값 하나를 반환하는 `all()`과 `any()`를 대신할 [`every()`][ref-every], [`some()`][ref-every], [`none()`][ref-every]도 있어요.
