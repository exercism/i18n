# 소개

[`Nothingness`][concept-nothingness] 개념에서 살펴봤듯이, R에는 데이터가 없거나(`NULL`), 알 수 없거나(`NA`), 수학적으로 유효하지 않은(`NaN`, `Inf`) 경우를 나타내는 여러 가지 방법이 있어요.
일반적으로 R은 이런 값들을 이용해 문제를 그 자리에서 표시하고, 예외를 발생시키지 않은 채 계속 실행하려고 해요.

## `stop()`

어떤 문제는 너무 근본적이라 프로그램을 계속 실행할 수 없어요.
이럴 때는 `stop(msg)`를 사용해요. 그러면 프로그램이 즉시 중단되면서 `Error`가 발생하고 `msg`가 출력돼요.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

다른 언어의 `assert`와 비슷한, `stop()`을 편리하게 감싼 함수예요.
매개변수로는 쉼표로 구분된 불리언 조건을 원하는 만큼 받고, 이 조건이 모두 `TRUE`여야 프로그램이 계속 실행돼요.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R에는 오류를 처리하는 다양한 방법이 있어요.
이 방법들은 Common Lisp에 기반을 두고 있으며, 많은 인기 언어와는 상당히 달라요.

가장 간단한 방법은 문제가 될 수 있는 코드를 `try()`로 감싸는 거예요.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
#> Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## `warning()`과 `message()`

이들은 치명적이지 않은 상황에 대한 응답이에요. 예를 들어:

- 프로그램이 적어도 부분적으로는 복구할 수 있는 문제를 경고할 때.
- 오래 실행되는 프로그램의 진행 상황을 사용자에게 알릴 때.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

`suppressWarnings()` 함수는 Exercism 내에서 가끔 유용하게 쓰일 수 있어요. 원치 않는 출력으로 테스트 러너를 헷갈리게 하는 걸 피할 수 있거든요.
