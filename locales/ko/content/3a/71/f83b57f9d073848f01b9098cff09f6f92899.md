# 소개

펌프, 밸브, 호스처럼 운영체제 리소스(열린 파일, 네트워크 연결)를 붙들고 있는 것은 무엇이든, 다 쓰고 나면 *해제*해야 해요. Factor의 [`destructors`][destructors] 보캡은 이런 것들을 프레임워크로 감싸서, 코드가 중간에 오류로 끊기더라도 정리가 반드시 이루어지도록 보장해요.

## 클래스와 제네릭

클래스는 `disposable`을 상속하고 `dispose*` 제네릭을 구현해서 이 프레임워크에 참여해요.

```factor
USING: accessors destructors kernel ;

TUPLE: pump < disposable opened ;

: <pump> ( -- pump )
    pump new-disposable t >>opened ;

M: pump dispose* f >>opened drop ;
```

`new-disposable ( class -- obj )`은 튜플을 할당할 뿐 아니라 프레임워크에 등록까지 해요. 할당과 다음 안전 지점 사이에서 예외가 발생해도 리소스가 새지 않아요. 프레임워크는 객체마다 `dispose*`가 **최대 한 번**만 실행되도록 보장해요. `dispose`를 여러 번 호출해도 아무 일도 일어나지 않아요.

## 호출하는 쪽은 `dispose`를 사용해요

```
dispose          ( obj -- )                ! release; safe to call twice
with-disposal    ( disposable quot -- )    ! scope one resource
with-destructors ( quot -- )               ! open a registry scope
&dispose         ( obj -- obj )            ! dispose on normal *or* failure exit
|dispose         ( obj -- obj )            ! dispose only if the scope unwinds
```

`with-disposal`은 리소스 하나를 다루는 형태예요. 안쪽 쿼테이션을 위해 disposable을 스택에 올리고, 빠져나갈 때 해제해요.

```factor
USING: destructors io ;

<pump> [
    "pumping" print
] with-disposal
! pump released on the way out — even if `print` had thrown
```

리소스가 둘 이상이라면 `with-destructors` 스코프를 열고, 확보한 리소스를 하나씩 등록해요. `&dispose`(앰퍼샌드)는 "성공하든 실패하든 나갈 때 항상 dispose한다"는 뜻이에요. `|dispose`(파이프)는 "실패했을 때**만** dispose한다"는 뜻인데, 성공 경로에서 리소스를 넘겨받아 소유권을 가질 호출자가 있을 때 유용해요.

```factor
[
    <pump> &dispose
    <pump> &dispose
    ! ... use the pumps ...
] with-destructors
! both pumps released
```

등록부 없이 try/finally만 쓰고 싶다면, `continuations`에 있는 [`cleanup`][cleanup]이 더 낮은 수준의 기본 연산이에요. 다만 요즘 Factor답게 쓰는 방식은 `with-destructors`예요.

[cleanup]: https://docs.factorcode.org/content/word-cleanup%2Ccontinuations.html
