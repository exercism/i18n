# 소개

이진 숫자는 궁극적으로 CPU나 RAM의 트랜지스터, 그리고 그 트랜지스터 각각이 "켜짐"인지 "꺼짐"인지에 직접 대응해요.

흔히 "비트 조작"이라고 부르는 저수준 조작은 시스템 언어에서 특히 중요해요.

Kotlin 같은 고수준 언어는 보통 이런 세부 사항 대부분을 감춰줘요. 하지만 기본적인 범위의 비트 단위 연산은 [사용할 수 있어요][ref-bitwise].

## 비트 시프트 연산

`Int`나 `Long` 타입은 부호가 있든 없든 1과 0의 문자열로 표현할 수 있고, 비트의 나열로 다룰 수 있어요.

놀랍게도, `Byte`나 `Short` 타입은 Kotlin의 대부분의 비트 연산과 호환되지 않아요. 아래 예제는 모두 32비트 정수(`Int` 또는 `UInt`)를 사용해요.

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

비트 시프트는 모든 비트를 지정한 개수만큼 왼쪽이나 오른쪽으로 옮기기만 해요. 한쪽 끝에서 비트 몇 개가 빠져나가고, 다른 쪽 끝은 0이나 1로 채워져요.

- `shl`로 왼쪽 시프트: 0으로 채워요.
- `shr`이나 `ushr`로 오른쪽 시프트: 양수에서는 0으로 채워요 (음수는 뒤에서 다뤄요).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

왼쪽 시프트를 할 때마다 값이 두 배가 되고, 오른쪽 시프트를 할 때마다 값이 절반이 돼요 (버림이 일어날 수 있어요). 이 점은 10진수 표현에서 더 분명하게 드러나요:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

이런 비트 시프트는 "제대로 된" 산술 연산보다 훨씬 빨라서, 저수준 코딩에서 아주 인기 있는 기법이에요.

_음수_에서는 조금 더 조심해야 해요.

음수 값은 [2의 보수][wiki-2complement] 형태로 저장되는데, 이는 가장 왼쪽 비트가 1이라는 뜻이에요. 왼쪽 시프트에는 문제가 없지만, 오른쪽 시프트를 할 때 가장 왼쪽 비트는 어떻게 채울까요?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

`shr` 연산자는 부호 비트를 보존하는 [산술 시프트][wiki-arithmetic]를 수행해요.

`ushr` 연산자는 숫자가 부호 없는 것처럼 0으로 채우는 [논리 시프트][wiki-logical]를 수행해요.

## 비트 논리 연산

[불리언 개념][concept-booleans]에서 연산자 `&&`(그리고), `||`(또는), `!`(아님)가 불리언 값과 함께 쓰인다는 걸 봤어요.

두 정수의 비트를 비교하는 `and`, `or`, `xor`([배타적 논리합][wiki-xor]) 연산자와, 모든 비트를 뒤집는 `inv`(반전) 함수가 있어요.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
