# 소개

Factor의 스레드는 *협력적 코루틴*이에요. 하나의 OS 스레드를 공유하면서 I/O 지점과 명시적인 양보 지점에서 서로에게 제어권을 넘기고, 진짜로 동시에 실행되는 법은 없어요. 양보 *사이*에 하는 일은 하나의 끊기지 않는 단계로 실행돼요. 그런데 복합 연산(읽기-수정-쓰기)이 중간에 양보하면, 다른 스레드가 끼어들어서 작업이 끝나기 전에 상태를 바꿔버릴 수 있어요. 이게 바로 경쟁 상태예요.

이 연습 문제에서는 반복해서 등장하는 네 가지 기본 요소를 살펴봐요:

## `parallel-map`: 시퀀스에 대한 fork/join

```
parallel-map ( seq quot: ( elt -- newelt ) -- newseq )
```

[`concurrency.combinators`][combinators]에 들어 있어요. 원소마다 스레드를 하나씩 만들고, 쿼테이션을 실행한 다음, 결과를 같은 순서로 새로운 시퀀스에 모아요:

```factor
USING: concurrency.combinators sequences ;

{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }
```

## `spawn`: 스레드 시작하기

```
spawn ( quot name -- thread )
```

[`threads`][threads]에 들어 있어요. 쿼테이션은 동시에 실행돼요. `name`은 디버깅용 이름표예요. 반환된 스레드 핸들은 이 단계에서는 별로 쓸모가 없어요. 그냥 `drop`해요.

## 프로미스: 한 번만 값을 넘겨주기

```
<promise>           ( -- promise )
fulfill             ( value promise -- )
?promise            ( promise -- value )
```

[`concurrency.promises`][promises]에 들어 있어요. 프로미스는 한 번만 쓸 수 있는 우체통이에요. 한 스레드가 값을 채우면 다른 스레드들이 그 값을 읽어요. `?promise`는 프로미스가 채워질 때까지 기다렸다가 값을 반환해요.

```factor
USING: concurrency.promises kernel threads ;

<promise> [
    [ 42 swap fulfill ] curry "answer" spawn drop
] keep ?promise .
! => 42
```

`parallel-map`도 `spawn`과 `<promise>`로 만들어졌어요. 각 작업이 "원소 하나를 계산하는" 것 말고 다른 일을 할 때는 이 둘을 직접 조합하면 유용해요.

시퀀스에 대한 전형적인 fan-out/join 형태는 이래요. 입력마다 새 프로미스를 만들고, 작업을 수행한 뒤 프로미스를 `fulfill`하는 스레드를 만들고, 모든 프로미스를 시퀀스에 모은 다음, 각 프로미스에 `?promise`를 호출해서 완료를 기다려요. `locals`를 쓰면 이 코드가 읽기 쉬워져요. `[| | ]` 람다 안에서 `:>`로 프로미스에 이름을 붙이면, 만들어진 쿼테이션이 그 이름을 닫힌 변수로 잡을 수 있어요:

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
inputs [| x |
    <promise> :> p
    [ x do-work t p fulfill ] "worker" spawn drop
    p
] map [ ?promise drop ] each
```

## 잠금: 상호 배제

```
<lock>     ( -- lock )
with-lock  ( lock quot -- )
```

[`concurrency.locks`][locks]에 들어 있어요. 한 번에 스레드 하나만 특정 잠금을 가질 수 있어요. `with-lock`은 잠금을 얻고, 쿼테이션을 실행하고, 놓아줘요. 쿼테이션이 예외를 던져도 마찬가지예요.

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
USING: concurrency.locks kernel locals ;

[let <lock> :> guard
    guard [ ! exclusive section ! ] with-lock
]
```

값을 *둘 이상의 스레드가 읽거나 쓰는데* 그 연산이 자연스럽게 원자적이지 않을 때는 잠금을 사용해요. 읽기도 쓰기도 모두 잠금이 필요해요. 읽는 도중에 양보하면 값이 반쯤만 바뀐 상태를 볼 수 있거든요.
