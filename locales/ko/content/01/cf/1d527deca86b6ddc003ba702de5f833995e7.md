# 개요

대부분의 스칼라 비트 연산에는 패킹된 변형이 있어요.
이들은 [SIMD 정수 연산][simd-integers]과 같은 일반적인 문법을 따르지만, 크기 접미사는 없어요:

| 명령어 | 설명                       |
|-------------|-----------------------------------|
| `pand`      | 두 128비트 값의 비트 AND |
| `por`       | 두 128비트 값의 비트 OR  |
| `pxor`      | 두 128비트 값의 비트 XOR |

패킹된 `NOT`은 없어요.
대신 ANDN 연산이 있는데, 이 연산은 **대상** 피연산자의 모든 비트를 반전시킨 다음 두 피연산자 사이의 AND를 계산해요.
NOT과 AND를 합친 것으로 생각할 수 있죠:

| 명령어 | 설명                                                     |
|-------------|-----------------------------------------------------------------|
| `pandn`     | **보수를 취한** 대상과 소스의 비트 AND |

비트 연산은 서로 다른 두 피연산자의 같은 위치에 있는 비트를 결합하므로, 레인 경계가 결과를 바꿀 수 없어요.
그래서 이런 명령어에는 크기 접미사가 없어요. 레지스터가 하나의 128비트 레인처럼 동작하기 때문이에요:

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
이 개념의 모든 명령어는 비트를 계산할 뿐 어떤 플래그도 설정하지 않아요.
패킹된 값으로 조건문을 다루는 방법은 나중에 나오는 개념에서 살펴봐요.
~~~~

## 레인별 시프트

시프트는 순수한 비트 연산과 달리 비트를 실제로 다른 위치로 이동시키므로, 경계를 정할 레인 크기가 필요해요.
각 레인 안에서 시프트는 스칼라 연산과 같은 방식으로 동작하고, 비트가 한 레인에서 이웃 레인으로 넘어가는 일은 없어요:

| 명령어               | 설명                         |
|---------------------------|-------------------------------------|
| `psllw`, `pslld`, `psllq` | 레인별 논리 왼쪽 시프트        |
| `psrlw`, `psrld`, `psrlq` | 레인별 논리 오른쪽 시프트       |
| `psraw`, `psrad`          | 레인별 산술 오른쪽 시프트    |

이 명령어들은 크기 접미사를 포함해 패킹된 정수 연산의 문법을 따라요.
바이트 레인 시프트는 없고, 워드와 dword, 그리고 qword(산술 오른쪽 시프트는 제외)만 있어요.

패킹된 시프트가 스칼라 시프트와 다른 점 한 가지는 연산 이름에 있어요:

- `shl`과 `shr` 대신 `sll`과 `srl`을 쓰는데, 이는 **s**hift **l**eft (**r**ight) **l**ogical의 약자예요.
- `sar` 대신 `sra`를 쓰는데, 이는 **s**hift **r**ight **a**rithmetic의 약자예요.

이름은 다르지만 연산 자체는 같아요:

- 논리 오른쪽 시프트는 가장 위쪽 비트를 0으로 채워요.
  2의 거듭제곱으로 나누는 부호 없는 나눗셈과 같아요.
- 산술 오른쪽 시프트는 가장 위쪽 비트를 부호 비트의 값으로 채워요.
  음의 무한대로 반올림하는, 2의 거듭제곱으로 나누는 부호 있는 나눗셈과 같아요.
- 왼쪽 시프트는 항상 0으로 채워요(그래서 산술 왼쪽 시프트가 필요 없어요).

시프트 횟수는 모든 레인에서 같아요.
즉시값일 수도 있고, `xmm` 레지스터의 하위 64비트일 수도 있어요:

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
레인 폭보다 큰 시프트 횟수는 스칼라 `shl`/`shr` 계열처럼 순환하지 않아요.
그냥 0이 돼요(산술 오른쪽 시프트라면 모든 비트가 부호 비트로 채워져요).
~~~~

## 부동소수점 비트 연산

각 비트 연산 명령어에는 부동소수점 이름을 가진 쌍둥이 명령어도 있는데, 패킹된 부동소수점 연산에서 본 것과 같은 문법을 따라요:

| 정수 이름 | 부동소수점 이름          |
|--------------|----------------------|
| `pand`       | `andps`, `andpd`     |
| `pandn`      | `andnps`, `andnpd`   |
| `por`        | `orps`, `orpd`       |
| `pxor`       | `xorps`, `xorpd`     |

비트 연산은 비트를 다루기 때문에, 실제로 정수 연산과 부동소수점 연산은 같은 결과를 계산해요.
이름이 다른 데에는 두 가지 이유가 있어요:

1. 의도를 문서화하기 위해서예요. 복사하는 바이트의 성격에 따라 `movdqa`, `movaps`, `movapd`를 선호하는 것과 같은 이치예요.
2. 정수 연산과 부동소수점 연산은 흔히 서로 다른 실행 도메인을 가져요.
   같은 실행 도메인에 속한 연산은 보통 더 빠르게 이어서 실행할 수 있어요.

부동소수점 값에는 시프트 연산이 없어요.

## 부동소수점 비트 표현

[IEEE 754][ieee-754] 부동소수점 수는 정수와 비트 표현이 아주 달라요.

부호 없는 정수에서는 각 비트가 똑같은 의미를 가져요. 비트 인덱스에 대응하는 2의 거듭제곱을 나타내죠.
정수의 값은 1로 설정된 비트에 대응하는 2의 거듭제곱들의 합이에요.
비트를 시프트해서 수를 2의 거듭제곱으로 곱하거나 나눌 수 있는 이유가 바로 여기에 있어요. 각 설정된 비트의 인덱스를 바꾸는 것뿐이거든요.

부호 있는 정수에서도 대부분의 비트는 부호 없는 정수와 같은 방식으로 해석돼요.
하지만 가장 위쪽 비트는 특별해요.
이 비트가 설정되어 있으면 다른 비트들에 더하는 대신 해당하는 2의 거듭제곱을 빼야 하고, 그 결과 음수가 돼요.
실제로 수의 부호를 바꾸려면 개념적으로 두 단계가 필요해요. 모든 비트를 뒤집고(`not`), 그 결과에 1을 더하는 거예요(`inc`).

부동소수점 수의 비트는 똑같은 의미를 갖지 않으며, 위치에 따라 아주 다른 방식으로 해석해야 해요:

| 필드    | 인덱스 (32비트) | 인덱스 (64비트) |
|----------|------------------|------------------|
| 부호     | 31               | 63               |
| 지수 | 30-23            | 62-52            |
| 가수부 | 22-0             | 51-0             |

결과 수는 `(-1)^sign * 1.fraction * 2^(exponent - bias)`로 계산해요.
바이어스는 정밀도에 따라 달라요:

| 크기   | 바이어스 |
|--------|------|
| 32비트 | 127  |
| 64비트 | 1023 |

두 형식 모두 수의 부호는 오로지 부호 비트로만 결정돼요.
부동소수점 수의 부호를 바꾸는 것은 이 비트를 뒤집기만 하면 돼요(XOR 연산).
절댓값을 구하는 것은 이 비트를 지우기만 하면 돼요(비트를 지우는 AND 연산):

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

이 비트 표현에서는 비트를 시프트해도 예측 가능하고 일관된 결과가 나오지 않아요.
가수부는 지수로, 지수는 부호로 "넘쳐흐를" 수 있어요.

하지만 표현의 여러 부분을 따로 떼어내서 다루는 것이 편할 때도 있어요.

예를 들어, 지수의 비트는 바이어스를 빼기 전에 먼저 부호 없는 수로 해석해야 해요.
즉, 해당 부동소수점 형식에서 어떤 2의 거듭제곱에 대응하는 비트 표현을 가진 32비트 또는 64비트 정수를 만들 수 있어요.
그런 다음 이 원시 비트 표현을 이용해 다른 부동소수점 수를 곱하거나 나눌 수 있어요.

예를 들어 볼까요:

```x86asm
mov eax, 210       ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23        ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax     ; we move the raw bits to xmm0
mulss xmm1, xmm0   ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

반대로, 지수 비트는 설정되고 나머지 비트는 모두 지워진 마스크와 AND 연산을 하면 패킹된 부동소수점 수의 지수를 추출할 수 있어요.
여기에 시프트와 뺄셈을 더하면, 모든 레인의 바이어스를 제거한 지수를 부호 있는 정수로 얻을 수 있어요:

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
부동소수점 수의 원시 비트를 직접 다루는 것은 어떤 상황에서는 유용하지만, 주의해서 해야 해요.
위 공식은 **정규** 수만 설명해요. 지수 필드가 모두 0이면 0과 비정규 수를 나타내고, 모두 1이면 무한대와 NaN을 나타내요.
지수 필드에 더하거나 빼는 것은 오버플로나 언더플로가 없고 입력 수가 정규 수일 때만 안전해요.
또한 `0.0`의 지수 필드에 유효한 `x`를 더하면 `0.0 * 2^x`가 아니라 `2^(x - bias)`가 돼요.
~~~~

## AVX와 그 이후

AVX는 여기 나오는 모든 명령어에 더 넓은 레지스터를 쓰는 `v` 접두사 3-피연산자 형식을 제공하며, 동작은 그대로예요:

```x86asm
vpand  ymm0, ymm1, ymm2 ; ymm0 = ymm1 AND ymm2, 256 bits
vxorps ymm3, ymm4, ymm5 ; ymm3 = ymm4 XOR ymm5, 256 bits
vpsrad ymm6, ymm7, 2    ; eight 32-bit lanes shifted right arithmetically
```

AVX2는 크기 접미사 앞에 `v`가 붙는 가변 시프트도 도입했어요.
이들은 시프트 횟수들로 이루어진 벡터를 받아서, 대응하는 레인의 횟수에 따라 시프트해요:

```x86asm
vpsllvd ymm0, ymm1, ymm2  ; each 32-bit lane shifted left by its own count
vpsravd ymm3, ymm4, ymm5  ; each 32-bit lane shifted right arithmetically by its own count
```

AVX-512는 SSE가 남겨 둔 두 가지 빈틈을 모두 메워요:

- `vpsraq`는 마침내 64비트 산술 오른쪽 시프트를 제공해요.
- `vpternlogd`와 `vpternlogq`는 **어떤** 3입력 비트 함수든 한 명령어로 계산해요.
  8비트 즉시값이 곧 진리표예요. 즉시값의 `i`번째 비트가 입력 조합 `i`에 대한 출력이에요.
  세 피연산자에 대한 `pand`/`pandn`/`por`/`pxor` 체인은 모두 하나의 `vpternlog`로 합쳐져요.

이 확장들은 완전성을 위해 언급했어요.
이 트랙의 연습 문제들은 SSE 형식을 사용해요.
