# 소개

Java 프로그래밍 언어는 오류와 그 밖의 예외적인 상황을 처리하기 위해 _예외_를 사용해요.

## 예외란 무엇일까요

예외는 프로그램을 실행하는 도중에 발생해서 명령의 정상적인 흐름을 방해하는 사건이에요.
Java에서는 예외를 명시적으로 발생시켜요. 예외를 발생시키는 행위를 _예외 던지기_라고 하고, 예외를 처리하는 행위를 _예외 잡기_라고 해요.

Java에서 모든 예외는 `Exception` 클래스의 하위 클래스이고, `Exception` 클래스 자체는 `Throwable`의 하위 클래스예요.

Java는 예외를 두 가지 유형으로 구분해요:

1. 체크 예외
2. 언체크 예외

### 체크 예외

_체크 예외_는 애플리케이션이 미리 예상하고 복구해야 하는 예외 상황이에요.
체크 예외의 한 예로는 `FileNotFoundException`이 있어요. 이는 메서드가 존재하지 않는 파일을 읽으려고 할 때 발생해요.

이런 유형의 예외는 컴파일 시점에 검사돼요. 체크 예외를 던지는 메서드는 메서드 시그니처에 이를 명시해야 하고, 체크 예외를 던질 수 있는 메서드를 호출하는 코드는 이를 반드시 처리해야 하며, 그렇지 않으면 코드가 컴파일되지 않아요.

모든 체크 예외는 `RuntimeException`을 상속하지 않는 `Exception`의 하위 클래스예요.

### 언체크 예외

_언체크 예외_는 애플리케이션이 보통 예상하거나 복구할 수 없는 예외 상황이에요.
언체크 예외의 한 예로는 `NullPointerException`이 있어요. 이는 null이 아닌 값을 기대하는 메서드가 `null`을 받을 때 발생해요.

이런 유형의 예외는 컴파일 시점에 검사되지 않아요. 언체크 예외를 던지는 메서드는 메서드 시그니처에 이를 명시할 필요가 없고, 언체크 예외를 던질 수 있는 메서드를 호출하는 코드도 이를 처리할 필요가 없어요.

모든 언체크 예외는 `RuntimeException`을 상속하고, `RuntimeException` 자체는 `Exception`을 확장한 것이에요.

## 예외 던지기

Java의 메서드는 `throw`문을 사용해서 예외를 던질 수 있어요.

### 체크 예외 던지기

메서드에서 체크 예외를 던질 때는 아래 예제처럼 `throws` 키워드를 사용해서 메서드 시그니처에 이를 명시해야 해요.
이렇게 하면 이 메서드를 호출하는 코드가 예외가 던져질 수 있음을 미리 예상하고 그에 맞게 처리하도록 강제돼요.

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### 언체크 예외 던지기

메서드에서 언체크 예외를 던질 때는 메서드 시그니처에 이를 명시할 필요가 없어요. 물론 명시하는 것도 가능해요.

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## 예외 처리하기

Java에서 예외를 처리할 때는 `try`, `catch`, `finally` 키워드를 사용해요.

- 예외를 던질 수 있는 코드는 `try` 블록으로 감싸야 해요.
- `try` 블록 뒤에는 `try` 블록에서 던져진 예외를 잡는 하나 이상의 `catch` 블록이 와요.
- `catch` 블록 뒤에는 선택적으로 `finally` 블록이 올 수 있는데, `finally` 블록은 예외가 던져졌는지와 상관없이 `try` 블록 다음에 항상 실행돼요.

다음 예제는 이 키워드들이 어떻게 동작하는지 보여줘요:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

이 예제에서 예외가 던져지지 않으면 다음과 같이 출력돼요:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

하지만 `bankAccount.withdraw(amount)` 문이 `InsufficientBalanceException`을 던지면 다음과 같이 출력돼요:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

또는 `bankAccount.withdraw(amount)`에서 언체크 예외가 던져지면 다음과 같이 출력돼요:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## 오류

Java에는 _오류_라는 별도의 범주도 있어요. 이는 애플리케이션 외부에 있는 심각한 문제를 나타내요.
오류의 한 예로는 `OutOfMemoryError`가 있어요. 이는 애플리케이션이 시스템에서 사용할 수 있는 것보다 더 많은 메모리를 사용하려고 할 때 발생해요.

언체크 예외와 마찬가지로 오류도 컴파일 시점에 검사되지 않아요.
차이점은 오류가 시스템 수준의 문제를 나타내며, 일반적으로 애플리케이션이 아니라 Java 가상 머신이나 환경에서 던져진다는 것이에요.
애플리케이션은 일반적으로 이들을 잡거나 처리하려고 시도해서는 안 돼요.

Java의 모든 오류는 `Error` 클래스를 상속해요.
