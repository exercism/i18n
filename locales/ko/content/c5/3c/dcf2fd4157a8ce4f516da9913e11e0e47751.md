# Null 허용성 알아보기

이상적인 세상에서는 모든 것이 잘 정의되어 있고, 구체적인 값이 있으며 빈틈이 없다고 믿을 수 있을 거예요.

하지만 이는 우리의 일상적인 경험과 어긋나요. 그래서 많은 프로그래밍 언어에는 값이 없음을 나타내는 방법이 있어요. null 또는 NULL, nil, None, nothing 등이에요.

이를 도입하는 것은 (1965년으로 거슬러 올라가요) 쉬웠지만, 곧 후회로 이어졌어요.
발명자는 나중에 이것을 자신의 ["10억 달러짜리 실수"][web-mistake]라고 불렀어요.

최근 수십 년 동안 언어 설계자들은 null을 사용할 수 있으면서도 (대부분) 안전하게 만드는 여러 방법을 연구해 왔어요.

Kotlin에는 몇 가지 [일반 원칙][ref-null-safety]이 있는데, 이는 [Java와 상당히 다릅니다][ref-java2kotlin].
_이런 차이 때문에 Kotlin에는 Java와의 상호 운용을 다루는 특별한 기능이 있어요. 다만 자세한 내용은 이 개념의 범위를 벗어나요._

- Kotlin에는 특별한 `null` 값이 있어요.
- 모든 타입은 _기본적으로_ non-nullable이에요 (즉, `null`이 될 수 없어요).
- 모든 타입은 _nullable_이 될 수 있지만, 명시적으로 지정해야 해요.
- 예외로 실패할 가능성이 있는 함수에는 nullable 반환 값을 가진 변형이 있는 경우가 많아요.
- null을 검사하고 처리하는 일을 최대한 쉽게 하려고 특별하고 매우 간결한 문법을 제공해요.

## nullable 변수 만들기

타입 이름 뒤에 `?`를 붙이면 타입을 [nullable][ref-nullable-type]로 만들 수 있어요 (예: `String` 대신 `String?`).

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## 유용한 연산자와 함수

### [안전 호출 연산자][ref-safe-call] `?.`

non-nullable `String`에서는 `.length` 프로퍼티를 얻을 수 있어요.

nullable `String?`에 같은 문법을 쓰면 오류가 나지만, `?.length`를 사용하면 `null`일 가능성을 처리할 수 있어요.
반환 타입은 `Int?`예요.

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

위의 마지막 줄에서 봤듯이, `?.`는 non-nullable 타입에서도 동작해요.

### [엘비스 연산자][ref-elvis] `?:`

안전 호출 연산자의 개념을 확장한 [엘비스 연산자][wiki-elvis]를 사용하면 `null`을 대신할 기본값을 지정할 수 있어요.

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### [not-null 단언 연산자][ref-not-null] `!!`

이 연산자를 사용하면, 프로그래머가 확신할 때 nullable 타입을 강제로 non-null로 취급해요.
어쩌면 우리가 지나치게 신중한 컴파일러보다 프로그램의 로직을 더 잘 이해할 때도 있지 않을까요?

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

이제 책임은 우리에게 있어요. 만약 `b`가 여전히 `null`이면 `NullPointerException`이 발생해요.

### [let 함수][ref-let] `?.let`

nullable 항목을 코드 블록에 넘기는 경우, `if (item != null) { do something }`처럼 null 검사를 직접 할 수도 있어요.

`item?.let { do something }`를 사용하는 편이 더 간단하고 관용적이에요.
`do something`은 `item`이 null이 아닐 때만 실행돼요.

### `somethingOrNone()` 타입의 함수

일부 함수는 실패할 수 있어요. 예를 들어 문자열이나 배열에서 잘못된 인덱스를 요청할 때요.

예외를 던지는 대신, 함수의 [`...OrNull` 변형][ref-elem-at-or-null]을 사용하면 (이 경우에는) `Int?` 반환 값을 얻을 수 있어요.

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
