# 개요

`LocalDate`나 `LocalDateTime` 같은 클래스는 시간상의 _한 지점_을 나타내요.
`java.time` 패키지에는 시간의 _양_을 나타내는 두 클래스도 있어요.

- [`Period`][period-docs]는 "2개월 5일"처럼 연, 월, 일로 표현되는 날짜 기반의 기간이에요.
- [`Duration`][duration-docs]는 "1시간 30분"처럼 시, 분, 초, 밀리초, 나노초로 표현되는 시간 기반의 지속 시간이에요.

이 차이가 중요한 이유는 달력 단위의 길이가 고정되어 있지 않기 때문이에요.
한 달은 28일, 29일, 30일, 31일이 될 수 있어서 "1개월"은 고정된 초 수가 아니에요.
`Period`는 달력을 따르고, `Duration`은 정확한 시간을 측정해요.

| | `Period` | `Duration` |
| --- | --- | --- |
| 저장하는 값 | 연, 월, 일 | 초와 나노초 |
| 함께 사용하는 클래스 | `LocalDate`, `LocalDateTime` | `LocalTime`, `LocalDateTime`, `Instant` |

두 클래스는 모두 불변 클래스예요.
`plusDays()`나 `multipliedBy()` 같은 메서드는 _새로운_ 인스턴스를 반환하고 원래 인스턴스는 그대로 둬요.

## `Period`

### `Period` 만들기

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

`toString()`의 결과는 [ISO-8601 기간 형식][iso-8601-durations]을 따라요. `P` 뒤에 연 수(`Y`), 월 수(`M`), 일 수(`D`)가 이어져요.
`Period`에는 주 단위가 없어요. `Period.ofWeeks(2)`는 14일로 저장돼요.
같은 표기는 `Period.parse()`로 다시 파싱할 수 있어요.

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### 날짜에 `Period` 더하기

날짜에는 `plus()`와 `minus()`로 `Period`를 더하거나 뺄 수 있어요.

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

`LocalDateTime`에도 같은 방식으로 `Period`를 더할 수 있고, 하루 중 시각은 그대로 유지돼요.

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

`Instant`에는 달력이 없어서 일 단위의 `Period`만 더할 수 있어요.
연이나 월이 포함된 `Period`를 더하면 예외가 발생해요.

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

연을 먼저 더하고, 그다음 월, 마지막으로 일을 더해요.
연이나 월을 더한 결과가 존재하지 않는 날짜가 되면, 그 달의 마지막 유효한 날로 조정돼요.

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

그래서 `Period`를 더한 뒤 다시 빼도 항상 원래 날짜로 돌아오지는 않아요.

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### 두 날짜 사이의 `Period`

`Period.between()`은 한 날짜(포함)부터 다른 날짜(제외)까지의 `Period`를 반환해요.
같은 결과를 `LocalDate.until()`로도 얻을 수 있어요.

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

`Period`의 구성 요소는 `getYears()`, `getMonths()`, `getDays()`로 확인할 수 있어요.
각 구성 요소는 서로 독립적이에요. `getDays()`는 전체 일수가 아니라 일 부분만 반환해요.
`toTotalMonths()`는 연과 월을 합쳐 월 수로 반환하지만, 전체 일수를 구하는 메서드는 없어요. 전체 일수는 어떤 월이 포함되는지에 따라 달라지기 때문이에요.

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### `Period` 정규화하기

팩토리 메서드로 만든 `Period`는 주어진 단위를 그대로 유지하고, `equals()`는 단위를 하나씩 비교해요.
`normalized()`는 월을 연으로 넘기지만 일은 그대로 둬요.

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## `ChronoUnit`으로 단위 세기

두 시점 사이에서 특정 단위의 전체 개수를 구하려면 [`ChronoUnit`][chronounit-docs]의 상수 중 하나에서 `between()` 메서드를 사용해요.

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

완전한 단위만 세고, 두 번째 인자가 첫 번째 인자보다 앞서면 결과가 음수가 돼요.

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

`ChronoUnit`은 시간 기반 단위와 날짜와 시간에도 사용할 수 있어요.

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### `Duration` 만들기

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

ISO-8601 표기에서 `T`는 날짜 부분과 시간 부분을 구분해요.
`Duration`에는 날짜 부분이 없어서 `toString()`의 결과가 항상 `PT`로 시작해요.
`Duration.ofDays()`는 하루를 정확히 24시간으로 취급해요.

`Duration`은 `Duration.parse()`로 파싱할 수도 있어요.

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### 시각에 `Duration` 더하기

`LocalTime`, `LocalDateTime`, `Instant`에는 `plus()`와 `minus()`로 `Duration`을 더하거나 뺄 수 있어요.

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

마지막 예제에서 볼 수 있듯이 `LocalTime`은 자정을 넘어가면 다시 돌아와요.

`LocalDate`에는 시간이 없어서 `Duration`과 함께 사용할 수 없어요.

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### 두 시각 사이의 `Duration`

`Duration.between()`은 두 시각 또는 날짜와 시간 사이의 정확한 시간량을 반환해요.

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

`Duration.between()`은 두 `LocalDate` 값을 받지 않아요. 날짜에는 측정할 초가 없기 때문이에요.

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

날짜에는 대신 `Period.between()`이나 `ChronoUnit.DAYS.between()`을 사용해요.

### `Duration` 변환하기

`toXxx()` 메서드는 `Duration`을 특정 단위의 _전체_ 양으로 변환하고, 소수점 아래는 버려요.

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

`toXxxPart()` 메서드는 시계처럼 `Duration`을 각 부분으로 나눠요.

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

`toHoursPart()`는 23에서 멈춰요. 그보다 큰 시간은 `toDaysPart()`가 세기 때문이에요.

### `Duration` 비교하고 계산하기

`Duration`은 `compareTo()`로 비교하고, `isZero()`와 `isNegative()`로 확인할 수 있어요.

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

`plus()`, `minus()`, `multipliedBy()`, `dividedBy()` 같은 산술 연산도 지원해요.

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## `Period`와 `Duration` 중 무엇을 쓸까요?

`LocalDate`나 `LocalTime`에서는 선택할 필요가 없어요. 날짜에는 측정할 시간이 없고, 시각에는 달력이 없기 때문이에요.
`LocalDateTime`에는 둘 다 있지만 시간대가 없어서, `Period.ofDays(1)`을 더하든 `Duration.ofDays(1)`을 더하든 결과가 같아요.
차이는 시간대가 있을 때 드러나요.
일광 절약 시간제로 시계가 앞으로 이동하는 날에는 달력상 하루가 23시간밖에 되지 않아요.

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

하루짜리 `Period`를 더하면 하루 중 시각이 유지되고, 하루짜리 `Duration`을 더하면 정확히 24시간이 더해져요.
사람들이 달력 기준으로 생각하는 양("다음 달 같은 날 같은 시각")에는 `Period`를, 경과한 시간("주차권은 2시간 동안 유효해요")에는 `Duration`을 사용해요.
