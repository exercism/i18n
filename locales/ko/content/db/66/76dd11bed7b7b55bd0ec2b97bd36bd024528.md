# 정확한 수

| 타입 | 담는 값 | 한계 |
| --- | --- | --- |
| `INT` | 정수 | 정확히 32비트 |
| `FLTD` | 분수 | 근사값 |
| `INTI` | 정수 | 메모리 |
| `RAT` | 분수 | 정확 |

## INTI

```sather
   #INTI(42)
   #INTI("123456789012345678901234567890")
   a + b, a - b, a * b, a / b
   a < b, a = b
   #INTI(25).factorial
   #INTI(48).gcd(#INTI(18))       -- 6
   #INTI(2).pow(100)
   big.str
   small.int                      -- back to an INT, if it fits
```

`INTI` 두 개에 적용하는 `/`는 나머지를 버리는 정수 나눗셈이에요. `INT`에서와
똑같아요.

`INT`에 담기에는 너무 큰 값에 `.int`를 쓰면 문제를 알려주지 않아요. 중요한
경우라면 먼저 확인해요.

## RAT

```sather
   #RAT(1, 3)
   #RAT(6)                        -- from a whole number
   a + b, a - b, a * b, a / b
   a < b, a = b
   r.is_int                       -- is it a whole number?
   r.is_zero, r.is_pos, r.is_neg
   r.abs, r.negate
   r.floor                        -- an INTI, rounded down
   r.str
```

`RAT`은 항상 기약분수이고, 부호는 항상 분자에 붙어요: `#RAT(1, -2)`는
`-1/2`예요. 두 `RAT`은 같은 분수일 때 정확히 같아요. 그래서 `=`는 원하는
대로 동작해요. 이것이 `FLTD`와의 차이 전부예요.

`RAT`은 `INTI` 위에 만들어져서, 분자와 분모에도 크기 제한이 없어요. 분모가
다른 분수를 많이 더하면 그 수가 점점 커져요. 덧셈할 때마다 약분하기 전에 분모를
곱하기 때문이에요.

`ceiling`은 선언되어 있지만 "not implemented" 오류를 내요. `floor`를 쓴 뒤
조정해요.

## 고르기

세는 값이 20억을 넘을 수 있을 때는 `INTI`를 골라요: 팩토리얼, 거듭제곱, 조합,
오랜 시간에 걸쳐 쌓이는 합계 같은 경우예요.

분수가 정확해야 하고 분모가 그리 크지 않을 때는 `RAT`를 골라요: 지분, 확률,
음표 값처럼, 그렇지 않으면 반올림 오차가 쌓일 수 있는 것들이에요.

기본적으로는 둘 다 고를 필요가 없어요. `INT`와 `FLTD`가 훨씬 빠르고, 대부분의
계산에는 그 이상이 필요 없어요.

돈을 다룰 때도 보통은 둘 다 답이 아니에요: 센트 단위 정수를 `INT`로 세요.
