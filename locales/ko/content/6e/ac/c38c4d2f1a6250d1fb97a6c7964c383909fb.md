# 소개

[레코드][records]는 관련 있는 정보를 이름표와 함께 묶어 놓은 자료 구조예요. JavaScript나 Java의 객체, 또는 C나 Rust의 구조체와 비슷하지만 몇 가지 중요한 차이가 있어요.

## 레코드 만들기

레코드는 중괄호로 [만들고][create], 각 원소는 쉼표로 구분해요.

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

레코드의 타입도 비슷한 문법으로 정의하는데, 등호 `=` 대신 콜론 `:`을 써요.

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

이런 타입 정의를 매번 반복하는 건 번거로워서, [타입 별칭][record-types]을 써서 정의를 공유하는 것이 흔한 관용구예요.

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

타입 별칭은 레코드를 위한 생성자 함수도 자동으로 만들어 줘요. Elm에서 함수는 반드시 소문자로 시작해야 해서 이게 가끔 놀라운데, 타입 생성자는 그 규칙의 예외 중 하나예요.

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

## 레코드 필드에 접근하기

레코드 인스턴스의 필드 값에 [접근하는][access] 주된 방법은 `firefly.creator`처럼 점 표기법을 사용하는 거예요.
Elm 컴파일러는 `.creator`처럼 점 `.`으로 시작하는 특별한 접근자 함수도 지원하는데, 이런 함수는 그 이름의 필드를 가진 어떤 레코드에서든 동작해요.
이것이 함수가 소문자로 시작해야 한다는 규칙의 두 번째 예외예요.
사실 사용자가 정의하는 함수는 소문자로 시작해야 하지만, 방금 본 두 가지 예시는 프로그래머가 아니라 컴파일러가 만들어 주는 거예요.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

레코드는 [레코드 패턴 매칭][pattern-matching]을 이용해 바인딩에서 _구조 분해_할 수도 있어요.
구조 분해는 해당 이름의 필드를 가진 어떤 레코드에서든 동작해요.

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

## 레코드 갱신하기

레코드는 Elm의 모든 것과 마찬가지로 불변이어서, 한 번 정의된 레코드의 필드 값은 절대 바뀌지 않아요.
[기존 레코드의 복사본을 만들면서 하나 이상의 필드를 바꾸는 특별한 문법][update]이 있어요.
이 문법은 파이프 기호 `|`를 써서 원본 레코드와 바뀔 필드를 구분하는데, `{ oldRecord | field1 = newValue }` 같은 식이에요.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

## 레코드 비교하기

Elm은 [구조적 동등성][equality]을 사용하는데, 이는 값이 같은 같은 레코드의 두 인스턴스는 서로 같다는 뜻이에요.

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

## 확장 가능한 레코드

Elm은 [구조적 타이핑][structural-typing]도 지원하는데, 이는 어떤 함수가 x와 y 필드를 가진 레코드를 요구하면 2D 점, 3D 점, 우주선 등 그 필드들을 가진 어떤 레코드에서든 동작한다는 뜻이에요.
이런 레코드 타입은 `{ a | x : Float, y : Float }`처럼 정의에 파이프 `|`가 들어가고, Elm 용어로 "확장 가능한 레코드"라고 불러요.
타입 정의에 있는 파이프 `|`는 확장 가능한 레코드 정의(`{ a | x : Int }`)이고, 실제 레코드 인스턴스에 있는 파이프 `|`는 그 레코드의 일부 필드를 갱신한다는 뜻이라는 차이를 조심해요.

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
