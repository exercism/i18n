# 소개

많은 객체 지향 언어에서는 부모 클래스를 [서브클래싱][wiki-subclass]해서 동작을 확장하는 것이 흔해요. 부모로부터 메서드를 상속받으면서 새로운 메서드도 추가하죠. 이렇게 해서 객체 계층 구조가 만들어져요.

Julia는 _클래스가 없어요_. 그러니 자연히 _서브클래스도 없어요_. 그러면 기존 동작을 어떻게 상속하고 확장할까요?

이전 개념들에서 타입 계층 구조를 만드는 방법을 살펴봤고, Julia가 [다중 디스패치][concept-multiple-dispatch]를 사용해 인자 타입에 따라 메서드를 선택하는 방식도 배웠어요.

Julia에는 몇 가지 비공식 인터페이스도 있는데, 이를 통해 직접 만든 타입이 표준 타입에 이미 정의된 동작에 연결될 수 있어요.

이것은 Iterator 인터페이스로 가장 쉽게 설명할 수 있어요.

## 반복자

앞서 교육 과정에서 Julia가 컬렉션의 각 요소를 다루는 여러 방법을 살펴봤어요.

- `for item in items...` 같은 [루프][concept-loops]
- [브로드캐스팅][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [고차 함수][concept-hof]: `map(√, [1, 4, 9])`
- [컴프리헨션][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [제너레이터][concept-comprehensions]: `(x^2 for x in 1:1e6)`, 지연 평가돼요.

위에서 보았듯이 Julia는 표준 컬렉션을 항목 단위로 순회할 줄 알아요. 위 예시의 벡터와 범위, 그리고 Set이나 Dict 등도 마찬가지죠.

그렇다면 직접 만든 컬렉션에도 이 기능을 추가하려면 어떻게 해야 할까요? 특히 제너레이터처럼 지연 평가로 순회할 수 있어야 한다면요.

### 최소 요구 사항

반복할 수 있는 시퀀스를 만들려면 (최소한) 두 가지가 필요해요:

1. _첫 번째_ 항목을 가져오는 방법
2. 현재 상태에서 _다음_ 항목을 가져오는 방법

Julia는 `Base.iterate()` 함수의 메서드로 이 작업을 수행하는데, 과정은 다음과 같아요:

1. `Base.iterate(iter)`가 먼저 자동으로 호출돼요.
    - 반복할 것이 없으면 `nothing`을 반환해요.
    - 그렇지 않으면 첫 번째 항목과 첫 번째 상태를 담은 `Tuple`을 반환해요: `(firstitem, firststate)`.
2. 이전 반복에서 항목이 반환되었다면 `Base.iterate(iter, state)`가 자동으로 호출되는데, `firststate`를 `state` 인자로 받아요.
    - 반복이 끝나면 `nothing`을 반환해요.
    - 그렇지 않으면 다음 항목과 다음 상태를 담은 `Tuple`을 반환해요: `(nextitem, nextstate)`.
3. 반복이 끝날 때까지 2단계를 되풀이해요.

이 단계들은 모두 "내부적으로" 처리되는데, 즉 메서드 호출과 상태는 반복 프로토콜이 내부에서 관리하고(상태는 불투명하게 남아 있고), 루프 같은 고수준 구조에는 항목만 노출돼요. 다시 말해, 우리는 `item`만 보게 되고 나머지는 모두 블랙박스 안에 남아 있어요.

[다중 디스패치][concept-multiple-dispatch]가 이 모든 것의 핵심이에요. `iter`의 타입이 어떤 메서드가 호출될지 결정하고, 인자의 개수가 첫 번째 항목을 반환할지 다음 항목을 반환할지 결정해요.

표준 타입에 대한 메서드는 이미 정의되어 있어요: `Vector`, `Range`, `Set` 등([현재][ref-iterations-collections] 총 14개 타입).

직접 만든 `MyType`이 같은 동작을 공유하게 하려면 먼저 다음을 정의해야 해요:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

추상적으로 들으면 혼란스러울 수 있지만, 실제로는 아주 간단할 수 있어요. 예를 들어, 주어진 정수 `n`의 거듭제곱을 최대 개수까지 내놓는 타입을 원한다고 상상해 봐요.

먼저 사용자 정의 타입을 정의해요:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

이제 이 타입에 대한 `iterate` 메서드를 정의할 수 있는데, 첫 번째 항목과 첫 번째 상태는 무엇일까요?

첫 번째 항목을 얻으려면 복잡한 준비가 필요한 반복자도 있지만, 이 장난감 같은 예시에서는 반환되는 첫 번째 항목이 그냥 밑수라는 것을 알 수 있어요. 따라서 `count`의 값이 1 이상인지만 확인하면 돼요.

이제 다음 반복에 사용되는 정보를 담은 첫 번째 상태를 생각해 봐요. 이를 위해 어떤 정보를 추적해야 할지는 직접 정하면 되고, 어떤 타입이든 괜찮아요.

이 경우에는 `n`을 거듭제곱할 "지수"를 추적할 수도 있고, 더 성능이 좋은 방법으로 `n`의 가장 최근 거듭제곱(즉, 반환된 항목)과 시퀀스의 다음 "지수"를 사용할 수도 있어요. 이 두 숫자를 `Tuple`로 감싸서 `state`로 반환할 수 있어요.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

이 예시에서 첫 번째 항목(`p.n`)은 루프로 반환되고, 첫 번째 상태 `(p.n, 2)`는 `iterate(P::Powers, state)` 메서드로 전달돼요. 거기서 현재 항목에 밑수를 곱해 다음 항목을 만들어 상태를 처리하고, 이렇게 해서 거듭제곱이 `1`씩 커져요.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

index 값이 아직 `count` 이내라면 `next` 항목과 증가된 상태 `Tuple`을 반환해요. `index` 값이 `count`를 넘으면 반복이 끝났음을 나타내기 위해 대신 `nothing`을 반환하죠.

`iterate(p::Powers)`와 `iterate(p::Powers, state)` 메서드의 함수 본문이 꽤 비슷하다는 것을 눈치챘을지도 몰라요. 사실 이 유사성을 잘 활용하면 상태에 기본 인자를 주는 두 인자 버전만 사용해서 구현을 간결하게 만들 수 있어요: `Base.iterate(p::Powers, state=(1, 1))`. 그러면 별도의 단일 인자 `iterate(p::Powers)`는 필요 없어요. 가능할 때 실제로 흔히 이렇게 해요.

지금까지 이미 쓸모 있는 기능을 갖췄어요. 3의 처음 4개 거듭제곱에 대해 결과를 루프로 순회하고, 주어진 숫자가 결과에 있는지 확인하고, `sum()` 같은 집계 함수를 적용할 수 있어요.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### 추가 메서드

이렇게 좋은 출발을 했지만, 아직 모든 것이 작동하는 건 아니에요.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

예상대로 `length(Powers(3, 4))`도 정확히 같은 오류 메시지를 내놓아요.

길이가 타입 생성자의 일부이므로(여기서는 4) 쉽게 고칠 수 있어요. 이 타입에 `Base.length()`를 정의하기만 하면, 시퀀스에 컴프리헨션과 `collect()`를 사용할 수 있어요.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

효율을 위해서는 `Base.eltype()`, 즉 결과의 요소 타입도 정의하는 게 좋아요. 그래야 `collect()` 같은 함수가 `Vector{Any}`에 `push!()`를 반복하는 대신 출력 `Vector{Int}`를 위한 공간을 미리 할당할 수 있어요.

전에 보지 못했을 수도 있는 문법에 주목해요. 이 메서드는 타입의 _인스턴스_가 아니라 _타입_ 자체에 정의돼요.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

반복자가 반드시 유한한 길이를 가질 _필요는 없어요_. "무한" 시퀀스의 활용은 더 제한적이지만, 루프를 `break`로 빠져나갈 방법이 있다면 그 위를 순회하는 것이 유용할 수 있어요. 예를 들어, 특정 한계보다 작은 값만 생성하는 `Powers`의 변형을 정의할 수도 있어요(정수 오버플로를 피하려면 아마 `typemax(Int)` 같은 값이요).

## 요약

인터페이스는 설명하기가 꽤 혼란스러운데, Julia의 접근 방식이 대부분의 다른 언어와 아주 다르기 때문이에요. 특히 구현부에서 인터페이스의 이름이 전혀 언급되지 않을 수도 있어요. [서브클래싱][wiki-subclass]이나 [믹스인][wiki-mixins]과는 아주 다르죠.

하지만 실제로는 놀랄 만큼 간단해요:

1. 알맞은 타입을 정의해요.
2. 어떤 메서드가 필요한지 알아내요.
3. 직접 만든 타입에 그 메서드들을 구현해요. 보통 몇 개 안 되는 메서드이고, 아주 짧고 간단해요.
4. 나머지는 [다중 디스패치][concept-multiple-dispatch]가 자동으로 처리하게 맡겨요.
