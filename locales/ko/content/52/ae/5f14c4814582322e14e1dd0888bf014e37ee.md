# 안내

정보 복구를 전문으로 하는 호주 회사 "Doctor Data"에서 첫 출근을 시작해요.
C++와 [폰 노이만 탐사선][van-neumann-probes]에 대한 지식으로 면접을 완벽하게 통과했어요.
많은 테스트 파일을 봐 왔기 때문에, 새 상사는 회사가 최근 복구한 테스트 코드로부터 해당 소스와 헤더 파일을 다시 만들기를 원해요.

이 연습 문제에서는 잃어버린 파일을 다시 만들어요.
현재 파일 내용은 사용할 수 없는 쓰레기 데이터예요.

~~~~exercism/note
이 개념 연습 문제의 진행 방식은 Exercism의 실습 문제 구조와 매우 비슷해요.
연습 문제 소개 글은 명세의 일부일 뿐이에요.
테스트 파일은 주어진 문제를 해결하는 데 가장 확실한 길잡이예요.
C++ 컴파일 방식 때문에, 테스트가 요구하는 모든 클래스, 함수, 열거형의 최소 버전을 구현하기 전까지는 테스트 결과가 웹 인터페이스에 나타나지 않을 수 있어요.
컴파일 오류가 나오더라도, 모든 작업과 테스트를 처리하고 나면 사라질 수 있어요.
~~~~

헤더와 소스 파일에서 잃어버린 코드를 복구하는 것과 관련된 네 가지 작업이 있어요.

## 1. 첫 단서를 추출해 봐요

테스트 파일에서 복구된 두 줄을 살펴봐요:

```cpp
heaven::Vessel bob{"Robert Johansson", 1};
heaven::Vessel will{"Riker", 2, star_map::System::BetaHydri};
```

예리한 눈은 즉시 `heaven` 네임스페이스를 알아차렸어요.
`Vessel`이라는 클래스가 있어야 한다는 것도 알 수 있어요.
생성자는 두 개 또는 세 개의 인자로 호출할 수 있는 것처럼 보여요.
첫 번째 인자는 `string` 타입인 것 같고, 두 번째는 숫자예요.
`Vessel` 클래스를 세 번째 인자로 초기화할 수도 있어요.
세 번째 인자는 `star_map` 네임스페이스에서 와요.
`System` 타입의 열거자예요.
심지어 열거자 중 하나인 `BetaHydri`도 알아냈어요.

알아낸 정보로 소스와 헤더 파일을 준비해요.
`heaven`과 `star_map`, 두 개의 네임스페이스가 필요해요.
`heaven` 네임스페이스에는 `Vessel` 클래스가 있고, 이 클래스는 두 개 또는 세 개의 인자로 호출할 수 있어요.
`System` 열거형은 `star_map` 네임스페이스에 두고, `BetaHydri` 열거자를 가져야 해요.
다른 열거자도 계속 눈여겨봐서 `System` 열거형을 꾸준히 갱신해요.

## 2. 자세한 내용을 찾아봐요

테스트에서 더 많은 줄을 발견해요:

```cpp
heaven::Vessel bob{"Robert Johansson", 1};
REQUIRE(bob.current_system == star_map::System::Sol);
REQUIRE(bob.generation == 1);
heaven::Vessel bob5 = bob.replicate("Mario");
REQUIRE(bob5.current_system == star_map::System::Sol);
REQUIRE(bob5.generation == 2);
```

새로 찾은 테스트 줄에서는 `Vessel` 클래스의 또 다른 멤버 함수 `replicate`를 알 수 있어요.
이 함수는 문자열을 받고 또 다른 `Vessel` 인스턴스를 반환해요.
이전 작업에서 생성자의 세 번째 인자 기본값에 대한 실마리를 얻어요.
`Vessel` 클래스의 public 멤버 변수 두 개와 `replicate` 멤버 함수의 명세도 보여요.

헤더와 소스 파일에 `replicate` 함수와 public 멤버 변수 `current_system`, `generation`을 추가해요.

## 3. 내부 동작을 살펴봐요

복구된 테스트 파일에서 더 흥미로운 줄을 찾아요:

```cpp
heaven::Vessel bob6{"Homer", 3, star_map::System::EpsilonEridani};
REQUIRE(bob6.busters == 0);
bob6.make_buster();
REQUIRE(bob6.busters == 1);
bool success = bob6.shoot_buster();
REQUIRE(success);
REQUIRE(bob6.busters == 0);
success = bob6.shoot_buster();
REQUIRE_FALSE(success);
```

`Vessel` 클래스에는 멤버 변수 `busters`가 있고, 이는 두 클래스 멤버 함수 `make_buster`와 `shoot_buster`로 바꿀 수 있는 것 같아요.
다른 정보가 나오기 전까지는 `make_buster` 함수가 `void`를 반환한다고 추측해요.
`shoot_buster`의 반환값을 검사하는 테스트가 있으므로, 이 함수는 `bool`을 반환한다고 가정해요.

`Vessel` 클래스에 두 함수와 멤버 변수를 추가해요.
다른 `System` 열거자도 계속 찾아봐요.

## 4. 전체 그림을 완성해요

테스트 파일을 훑어보는 동안 아직 밝혀지지 않은 코드 두 부분만 찾아요:

```cpp
heaven::Vessel bob1{"Bob", 1, star_map::System::AlphaCentauri};
heaven::Vessel marv{"Marvin", 2, star_map::System::DeltaEridani};
heaven::Vessel milo{"Milo", 3, star_map::System::DeltaEridani};
heaven::Vessel howie{"Howard", 4, star_map::System::Omicron2Eridani};

REQUIRE("Bob" == heaven::get_older_bob(bob1, marv));
REQUIRE(heaven::in_the_same_system(marv, milo));
REQUIRE_FALSE(heaven::in_the_same_system(marv, howie));
```

인스턴스로 호출되지 않으므로 `Vessel` 클래스의 멤버가 아닌 두 함수를 볼 수 있어요.
`get_older_bob`은 `Vessel` 인스턴스 두 개를 비교하고 `string`을 반환해요.
`in_the_same_system`은 `Vessel` 인스턴스 두 개를 비교하고 `bool`을 반환해요.

위에서 복구된 줄을 바탕으로 마지막으로 빠진 함수들을 구현해요.
