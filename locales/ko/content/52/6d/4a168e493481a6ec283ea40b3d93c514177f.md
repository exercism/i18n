# 지시 사항 추가

## 리팩터링

`Markdown.roc`의 구현은 이미 테스트를 통과해요.
동작과 `parse : Str -> Try(Str, _)` 인터페이스는 그대로 유지하면서 리팩터링해 봐요.
성공하면 `Ok(html)`을 반환하고, 파싱 오류는 `Err(...)`로 전달해요.
이 연습 문제는 Markdown의 작은 부분 집합만 다루며, 전체 Markdown 명세를 다루지는 않아요.
지켜야 할 동작은 테스트가 정의해요. 빈 줄과 짝이 맞지 않는 강조 표시를 어떻게 처리하는지도 여기에 포함돼요.

반복되는 로직, 깊게 중첩된 조건, 의미를 알기 어려운 이름, 불필요한 가변 상태를 찾아봐요.
줄 분류, 인라인 강조, HTML 렌더링을 서로 분리하는 것도 고려해 봐요.
테스트 앱에서 [`roc-parser` 패키지](https://github.com/lukewilliamboswell/roc-parser)를 `parser`로 사용할 수 있어요.
`Parser.one_of`, `Parser.many`, `Parser.between`은 작은 파서들을 조합하는 데 도움이 돼요.
평범한 문자열과 배열 함수로 만든 풀이도 똑같이 환영해요.
