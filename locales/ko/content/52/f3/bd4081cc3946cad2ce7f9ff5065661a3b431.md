# 개요

Factor는 스트림 I/O를 두 계층으로 나눠요. 아래쪽 계층은 *명시적 스트림* API예요. 모든 워드가 스트림을 인자로 받죠. 위쪽 계층은 *주변 스트림* API예요. 현재 바인딩된 스트림에 작용하는, 짧은 한 줄짜리 워드들이에요. 두 계층 모두 같은 [프로토콜][stream-protocol] 위에 올라가 있어요. 상위 계층 워드들은 주변 스트림을 찾아서 호출을 넘겨줄 뿐이죠.

## 명시적 스트림 워드

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents`는 스트림을 끝까지 읽어 들여요. `stream-lines`는 끝까지 읽은 뒤 줄 단위로 나누죠. `stream-readln`은 한 번에 한 줄씩 반환해요(스트림 끝에서는 `f`를 반환해요).

## 주변 스트림 워드

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

이 워드들이 일상적으로 쓰는 I/O 워드예요. 동적 변수 `input-stream` / `output-stream`에서 현재 입력 또는 출력 스트림을 찾아 호출을 넘겨줘요. 그래서 `print`의 출력을 문자열로 돌리는 일도, 쿼테이션이 실행되는 동안 `output-stream`을 바인딩하기만 하면 돼요.

## 기본 제공 스트림 생성자

| 워드              | 보캡                | 만드는 것                  |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | 문자열 리터럴을 읽어요          |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | 쓰기 결과를 문자열로 모아요   |
| `<file-reader>`   | [`io.files`][io.files]           | 인코딩을 지정해 파일을 읽어요   |
| `<file-writer>`   | [`io.files`][io.files]           | 인코딩을 지정해 파일에 써요  |

네 가지 모두 `disposable`을 만들어요. `destructors`의 `disposable`을 확장하기 때문에, 아래에 나오는 `with-…` 컴비네이터들이 빠져나올 때 이들을 해제해 줘요.

## 범위 지정 바인딩

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

각 워드는 스트림을 하나 열고, 안쪽 쿼테이션이 쓰는 주변 입력 또는 출력 스트림으로 바인딩한 뒤, 빠져나올 때 해제해요. 쿼테이션이 예외를 던져도 마찬가지예요. 이들은 `boatswains-bilge`의 소멸자 컴비네이터를 스트림에 맞게 특화한 것이에요.

`with-string-writer`는 특히 깔끔한 변형이에요. 새 `<string-writer>`를 자동으로 만들어서, 그 writer를 주변 출력으로 삼아 쿼테이션을 실행하고, 모인 문자열을 반환해요. "쿼테이션의 출력을 붙잡아 두는" 패턴 전체가 워드 하나로 끝나죠.

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## 왜 주변 스트림을 쓸까요?

동적 변수 바인딩 덕분에, `print`는 자신이 대화형으로 실행되는지, 로그 파일로 들어가는지, 테스트용 버퍼로 붙잡히는지 몰라도 제대로 동작해요. 바인딩을 한 번만 바꾸면 `print`를 호출하는 모든 워드가 알아서 알맞게 동작하죠. 배선을 다시 손볼 필요가 없어요. 이것이 바로 상위 계층이 가져다주는 역전이에요.

스트림을 *직접 구현*하는 방법, 즉 프로토콜에 끼워 넣을 클래스를 직접 정의하는 방법은 `streams` 개념에서 다뤄요(`telegraphers-tape`에서 배워요).
