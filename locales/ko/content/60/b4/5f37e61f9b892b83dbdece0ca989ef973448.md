# 소개

Elm의 [사용자 정의 타입][custom-types]은 이름이 붙은, 정해진 개수의 케이스를 나타내요. 각 값은 그중 정확히 하나의 케이스에 해당해요.

사용자 정의 타입은 `type` 키워드로 정의하며, 필요한 문법도 아주 적어요. Elm 프로그래밍에서 가장 중요한 기법 중 하나인데, 코드에서 다룰 수 있는 값을 실제 생활에서 유효한 값과 정확히 일치시키는 데 쓰여요. 덕분에 잘못된 데이터가 들어갈 여지가 없고, [불가능한 상태는 코드로 표현할 수 없게][impossible-states] 돼요.

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

사용자 정의 타입의 각 케이스에는 데이터를 함께 둘 수도 있고, 케이스마다 서로 다른 타입의 데이터를 가질 수 있어요. 어느 케이스에도 데이터가 없다면, 이렇게 케이스로 구분되는 합집합은 다른 언어에서 흔히 _열거형_(_enum_)이라고 부르는 것과 비슷해요.

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

특정 케이스의 값을 만들 때는 그 케이스가 같은 모듈에 정의되어 있거나 `import SeasonModule exposing (Season(..))` 형태의 문법으로 가져온 경우에는 이름(`Spring`)을 그대로 쓰면 돼요. `import SeasonModule exposing (Season)` 형태의 문법으로 가져온 경우에는 정규화된 이름(`Season.Spring`)을 쓰면 되고요.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

사용자 정의 타입은 Elm의 모든 것과 마찬가지로 _구조적 동등성_을 가져요. 다시 말해, 같은 케이스이면서 (있다면) 같은 데이터를 가진 두 값은 서로 같아요.

사용자 정의 타입을 다룰 때 가장 권장되는 방법은 [패턴 매칭][pattern-matching]이에요.

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
