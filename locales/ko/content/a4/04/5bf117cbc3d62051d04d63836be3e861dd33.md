# 개요

Elm은 안정적인 웹 애플리케이션을 만들기 위한 즐거운 언어예요.
친절한 오류 메시지, 뛰어난 성능, 작은 에셋, 그리고 런타임 예외가 없다는 점이 특징이에요.

아마도 Elm에서 가장 유명하고 널리 모방된 부분은 The Elm Architecture일 거예요.
The Elm Architecture는 웹 애플리케이션을 구조화하는 단순한 패턴이고, 모든 Elm 웹 애플리케이션이 이 방식으로 작성돼요.

핵심 아이디어는 애플리케이션 상태를 담는 `Model`, 모델을 `update`하는 방법, 모델을 `view`하는 방법을 중심으로 코드를 구성한다는 거예요.

`Model`에는 애플리케이션의 상태, 즉 애플리케이션에 필요한 모든 데이터가 들어 있어요.
어떤 타입이든 될 수 있지만, 쓸모 있는 애플리케이션에서는 보통 [레코드][record]예요.
텍스트 상자 하나와, 그 텍스트를 뒤집어서 보여 주는 텍스트가 있는 간단한 애플리케이션을 상상해 보면 모델은 아래와 같아요.
이 예제는 [Elm 가이드][elm-guide-text-fields]에서도 볼 수 있어요.

```elm
type alias Model =
  { text : String
  }
```

`update`는 변화가 있을 때(예를 들어 사용자가 버튼을 클릭할 때) `Msg`와 함께 호출되는 함수예요.
`Msg`와 현재 `Model`을 받아서 새로운 `Model`을 반환해요.
`Msg`는 어떤 타입이든 될 수 있지만 보통 [커스텀 타입][custom-type]이에요.

```elm
type Msg
  = TextChanged String

update : Msg -> Model -> Model
update msg model =
  case msg of
    TextChanged newText ->
      { model | text = newText }
```

모든 커스텀 타입과 마찬가지로, `Msg`의 각 변형은 필요한 만큼 임의의 정보를 담을 수 있어요.
위 예제에서 `TextChanged` 변형은 `String`을 담고 있어요.

`view`는 브라우저에서 사용자에게 보여 줄 HTML을 반환하는 함수예요.
현재 `Model`을 받아서 `Html Msg`(Elm이 HTML을 표현할 때 사용하는 타입)를 반환해요.
각 HTML 요소(예를 들어 `<div>`)에는 `Html` 패키지에 대응하는 Elm 함수(`Html.div`)가 있어요.
이 함수들은 각각 두 개의 매개변수를 받는데, 첫 번째는 (`Html.Attributes`와 `Html.Events` 패키지에서 온) 속성 목록이고, 두 번째는 자식 요소 목록(`Html` 패키지의 함수들)이에요.
HTML 문자열 콘텐츠를 나타내는 `text` 함수도 있는데, 이 함수는 문자열 매개변수 하나만 받고, 그 외에는 `Html` 패키지의 다른 모든 함수와 요소와 같은 방식으로 사용해요.

`view` 함수에서는 버튼 클릭이나 텍스트 상자의 텍스트 편집 같은 특정 이벤트가 `Msg`를 만들어 내도록 지정할 수 있어요.
그러면 Elm 런타임이 그 `Msg`로 `update` 함수를 호출해서 `Model`을 바꾸고, 갱신된 HTML을 만들어요.
아래 코드에서는 `Html.Events.onInput TextChanged`가 이 역할을 해요.

```elm
view : Model -> Html Msg
view model =
  Html.div []
    [ Html.input
      [ Html.Attributes.placeholder "Text to reverse"
      , Html.Attributes.value model.text
      , Html.Events.onInput TextChanged
      ]
      []
    , Html.div [] [ Html.text (String.reverse model.text) ]
    ]
```

`Html.Events.onInput`은 `Msg`를 만들 때 사용할 함수(`String -> Msg`)를 전달받기를 기대해요.
이벤트마다 제공할 수 있는 정보가 달라서 요구하는 함수도 다른데, 예를 들어 `Html.Events.onCheck`(체크박스용)는 `Bool -> Msg`를, `Html.Events.onClick`은 그냥 `Msg`를 기대해요.

Elm 언어는 순수하고 함수형이어서 값을 변경할 수 없기 때문에, Elm 런타임이 변하는 모든 것을 처리해요.
다양한 [HTML 요소][html-elements], [요소 속성][element-attributes], [HTML 이벤트][html-events]는 Elm 패키지 레지스트리에서 볼 수 있어요.

Elm으로 작성할 수 있는 웹 애플리케이션에는 4개의 "단계"가 있는데, 갈수록 더 강력해지고 더 복잡해져요(그래도 Elm은 놀랍도록 단순한 언어이자 생태계예요).
이 단계들은 모두 [Browser 패키지][browser-package]에 정의되어 있어요:

- [sandbox][browser-sandbox]: 버튼과 체크박스 같은 사용자 입력에 반응해요
- [element][browser-element]: HTTP와 JavaScript 상호 운용을 통해 바깥세상과 소통해요
- [document][browser-document]: 웹 페이지의 `<title>`과 `<body>`를 제어해요
- [application][browser-application]: 라우팅과 URL 변경을 처리하는 완전한 단일 페이지 애플리케이션을 만들어요

이 개념에서는 가장 단순한 [sandbox][browser-sandbox]를 사용해요(sandbox이기 때문에 Exercism 온라인 에디터에서 비교적 쉽게 작업할 수 있기도 해요).
Elm 프로그램의 진입 모듈은 `Main`이어야 하고, 애플리케이션을 만드는 함수는 `main`이어야 해요. 아래와 같이요.

```elm
import Browser
import Html exposing (Html, Attribute, div, input, text)
import Html.Attributes exposing (placeholder, value)
import Html.Events exposing (onInput)

main =
  Browser.sandbox { init = init, update = update, view = view }

init : Model
init =
  { text = "" }

-- Add Model, Msg, update and view here
```

`update`와 `view` 함수는 이미 살펴봤고, [sandbox][browser-sandbox]는 추가로 `Model`의 초기 상태를 반환하는 `init` 함수가 필요해요.
