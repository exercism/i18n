# 지침

이 문제는 실시간 운영체제의 비선점형 정적 스케줄링을 모델로 했어요. 하지만 자원이 하나뿐인 잡 숍 스케줄링 문제(Job-Shop Scheduling Problem, JSP)와도 비슷해요. 이 문제에서는 모든 태스크가 정적으로 알려져 있다고 가정해요. 다시 말해, 이 문제에 나오는 모든 태스크의 릴리스 시간은 프로그램을 시작하는 시점에 이미 알고 있어요. 실제로는 프로그램이 시작될 때 태스크의 릴리스 시간을 알 수 없고, 입출력이나 인터럽트 등을 통해 언제든지 만들어질 수 있어요.

매개변수를 가진 태스크 배열이 주어졌을 때, 태스크들이 겹치지 않고 순차적으로 실행될 수 있는 스케줄을 정해요. 이 문제는 RTOS 프로세스 스케줄링을 모델로 했기 때문에, 태스크 사이에 0이 아닌 시간이 필요하다고 가정해요. 이 시간을 문맥 교환 오버헤드라고 해요. 태스크에는 주기 태스크와 동적 태스크, 두 가지 종류가 있어요. 두 종류 모두 태스크 ID 매개변수를 가지고 있는데, 이는 태스크 배열에서 서로 다른 태스크를 구분하기 위해 사용하는 문자열이에요.

**주기 태스크**는 주기적으로 실행되는 태스크를 말해요. 다시 말해, T초마다 한 번씩 실행되는데, 여기서 T를 주기라고 해요.
주기 태스크는 다음 매개변수로 정의돼요:
* 시작 시간 - 태스크의 첫 번째 반복, 즉 인스턴스가 시작되는 시간
* 주기 - 태스크 반복이 시작되는 시점 사이의 시간
* 실행 시간 - 각 반복이 실행되는 시간
* 종료 시간 - 태스크 전체가 더 이상 스케줄링되지 않는 시점

**동적 태스크**는 딱 한 번만 실행되는 태스크를 말해요.
동적 태스크는 다음 매개변수로 정의돼요:
* 릴리스 시간 - 태스크가 스케줄될 수 있는 가장 이른 시점 (시작 시간과 같지 않아요)
* 실행 시간 - 태스크가 실행되는 시간
* 마감 시간 - 태스크가 실행을 끝내야 하는 시점

구현할 함수에는 두 개의 입력이 있어요. 첫 번째 입력은 `RealTimeTask` 인스턴스의 배열이에요. `RealTimeTask`의 인스턴스는 `PeriodicRealTimeTask` 또는 `DynamicRealTimeTask`의 인스턴스로 입력되고, 모든 태스크 매개변수는 정수예요. 파이썬의 내장 함수인 `isinstance()`를 사용하면 배열에 있는 두 종류의 태스크를 구분할 수 있어요. 배열의 순서는 상관없어요. 태스크의 매개변수만 보면 돼요. 두 번째 입력은 문맥 교환 오버헤드를 지정하는 정수 하나예요. 문맥 교환 오버헤드는 항상 음이 아닌 정수예요.

출력은 딕셔너리여야 하는데, 키는 `RealTimeTask` 인스턴스의 태스크 ID이고 값은 2-튜플의 배열이에요. 2-튜플의 형식은 (시작 시간, 종료 시간)이에요. 동적 태스크는 배열에 2-튜플을 하나만 가져야 하고, 주기 태스크는 여러 개를 가질 수 있어요. 배열에서 2-튜플의 순서는 상관없어요. 주어진 문맥 교환 오버헤드로 태스크 배열에서 유효한 스케줄을 만들 수 없다면 `NoRtosStaticScheduleProducible` 예외를 발생시켜요. 변수에 대한 Z3 모델 결과는 출력하기 전에 정수로 변환해야 한다는 점에 유의해요. Z3 모델 결과가 `IntNumRef` 타입이라면 `as_long()` 클래스 메서드를 사용해 정수로 변환할 수 있어요.

태스크의 순차적인 순서를 사용자가 눈으로 확인할 수 있도록 추가 함수가 제공돼요. 이 함수는 `check()` 함수에서 `plot` 키워드 인자를 `True`로 설정하면 개별 테스트 케이스에서도 활성화할 수 있어요. 각 태스크를 그래프로 그리고 이름을 붙이는 데에는 끊어진 가로 막대 그래프가 사용돼요. 이 함수를 사용하려면 파이썬 라이브러리 *matplotlib*이 설치되어 있어야 해요. *matplotlib*의 설치 방법은 [여기](https://matplotlib.org/stable/users/installing.html)에서 확인할 수 있어요.
