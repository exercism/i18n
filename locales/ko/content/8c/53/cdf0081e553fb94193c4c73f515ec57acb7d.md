# 개념과 개념 연습 문제 기여하기

[개념 연습 문제][product-concept]는 특정 언어에서 하나의 개념을 가르치는 것을 목표로 해요.
명확한 학습 목표를 가져야 하고, 학생이 불필요한 코드를 배우지 않아도 되도록 충분한 보일러플레이트를 제공해야 해요.
연관된 개념은 개념 연습 문제와 별개로 자체 문서를 가져요.
개념은 다른 개념을 선수 개념으로 가질 수 있고, 선수 개념의 개념 연습 문제를 완료할 때까지 잠겨 있을 수 있어요.
개념 연습 문제의 난이도는 트랙이 진행되어도 높아지지 않아야 해요.
개념 연습 문제는 선수 개념에 익숙한 개발자라면 누구나 5분에서 10분 안에 풀 수 있어야 해요.

이제 개념 연습 문제가 무엇인지 알았으니, 개념 연습 문제와 그에 연관된 개념을 어떻게 구현하는지 자세히 알아봐요.
참고로, [개념 연습 문제의 명세][concept-exercise-spec]와 [개념의 명세][concept-spec]는 exercism [문서 저장소][docs-repo]에서 확인할 수 있어요.
이 문서는 여러 자료에서 정보를 모아, 개념 연습 문제를 기여하는 방법을 단계별로 안내하는 편리한 가이드 역할을 해요.

## 1. 구현할 누락된 개념 찾기

이미 구현된 개념은 이 저장소의 [`concepts/`](/concepts) 디렉터리에 있어요.
이들은 [exercism 웹사이트][concepts-graph-exercism]에서 의존성 그래프로도 표현되어 있어요.
아래에 표시된, 우리가 구현하려는 개념 그래프와 비교해 볼 수 있어요(보이지 않으면 몇 초 기다렸다가 새로고침해 봐요).

이미 구현된 개념은 초록색 배경과 더 굵은 테두리로 표시되어야 해요.
위 그래프는 계속 바뀔 수 있고, 선수 개념이 달라져야 한다는 걸 발견하면 변경될 수 있다는 점을 유의해요.

아직 구현되지 않은 개념과 개념 연습 문제는 이 저장소의 GitHub 이슈에도 [`x:module/concept-exercise`](https://github.com/exercism/elm/issues?q=is%3Aissue+is%3Aopen+label%3Ax%3Amodule%2Fconcept-exercise) 레이블과 함께 등록되어 있어야 해요.

## 2. 학습 목표 정의하기

개념 연습 문제가 무엇을 가르치려는지, 무엇이 범위 밖인지 아는 것이 중요해요. 그럼 첫 번째 파일을 만들어 봐요: `exercises/concept/<story-name>/.meta/design.md`.
개념 연습 문제는 사용하는 스토리의 이름을 따서 지어지므로 아직 그 이름을 모르니까, 지금은 `story-name`으로 두고 나중에 바꿔요.
[`design.md` 명세][design-spec]에 따르면 이 문서는 연습 문제의 전체 목표, 여러 학습 목표, 범위 밖인 것들, 이 연습 문제가 잠금 해제하는 연관 개념, 그리고 연습 문제를 완료하기 위해 필요한 개념 선수 조건을 정의해야 해요.
[불리언 개념 연습 문제의 `design.md`][design-bool]를 템플릿 시작점으로 사용할 수 있어요.

## 3. 연습 문제를 위한 개념 소개 작성하기

학습 목표가 명확해지면, 학생이 연습 문제를 풀 수 있을 만큼 개념을 설명하는 소개를 작성할 차례예요.
`exercises/concept/<story-name>/.docs/introduction.md` 파일을 만들어요.
이 파일의 자세한 내용은 [명세][exercise-intro-spec]에 설명되어 있어요.
[불리언 개념 연습 문제의 `introduction.md`][intro-bool]를 템플릿 시작점으로 사용할 수 있어요.

제공하는 정보는 학생이 연습 문제의 해답을 스스로 알아낼 수 있을 만큼만 개념을 소개해야 해요.
학생이 온라인에서 검색하기 쉽도록 적절한 기술 용어를 사용해요.
링크는 피하고 대신 내용을 간결하게 본문 안에서 설명해요.
코드 문법은 코드 블록으로 소개해요.

## 4. 연습 문제를 위한 스토리 찾기

각 개념 연습 문제는 스토리나 테마를 바탕으로 해야 해요.
Exercism은 전 세계에서 사용된다는 점을 알고, 최대한 포용적으로 만들려고 노력해요.
첫 번째 방법은 [문서에 기록된 스토리 목록][stories]에 있는 기존 스토리를 재사용하는 거예요.
새로운 스토리를 만들고 싶다면, 주저하지 말고 PR에서 @exercism/leadership을 불러요.
이제 스토리에 맞게 `exercises/concept/<story-name>/` 디렉터리 이름을 바꿀 수 있어요.

## 5. 연습 문제 지침 작성하기

스토리를 찾았으면, 학생이 수행해야 할 작업을 나열한 정확한 지침을 작성해야 해요.
스토리와 지침은 모두 `exercises/concept/<story-name>/.docs/instructions.md` 문서에 작성해요.
[해당 문서 명세][instructions-spec]에서 설명하듯이, 각 작업은 고유한 2단계 마크다운 제목(`## 1. Do X`)을 가지고, 그 뒤에 설명과 예제 코드 사용법이 따라와요.
[불리언 개념 연습 문제의 `instructions.md`][instructions-bool]를 템플릿 시작점으로 사용할 수 있어요.

`instructions.md` 외에도 `hints.md` 파일도 필요해요.
이 파일에는 지침 파일과 동일한 2단계 제목(`## 1. Do X`)이 들어가야, 현재 작업 중인 문제에 맞는 힌트가 제공될 수 있어요.
모든 작업에 적용되는 힌트를 위한 `## General` 섹션을 둘 수도 있어요.
힌트는 해답을 직접 알려주면 안 돼요.
또한, 힌트를 클릭하는 사람은 이미 연습 문제 때문에 혼란스럽거나 압도되었거나 답답한 상태일 수 있다는 점을 유의해요.
이 문서에 대한 더 자세한 정보는 [명세][hints-spec]에서 확인할 수 있고, [불리언 개념 연습 문제의 `hints.md`][hints-bool]를 템플릿 시작점으로 사용할 수 있어요.

## 6. 설계를 검증하기 위해 드래프트 풀 리퀘스트 열기

지금이 개념 연습 문제를 위한 드래프트 풀 리퀘스트를 열기 좋은 때예요!
남은 필수 파일들을 위해 현재 상태로 확정하기 전에, 연습 문제를 평가하고 필요하면 고쳐서 다듬을 만큼의 자료가 준비됐어요.
문서가 없어서 CI의 자동 검사가 실패해도 걱정하지 마세요, 나중에 만들 거예요!

## 7. 코드 작성하기

연습 문제를 푸는 것처럼 코드를 작성하고, 나중에 명세에 맞게 파일을 옮겨요.
먼저 [`template/`][template] 디렉터리의 내용을 `exercises/concept/<story-name>/` 디렉터리 안에 복사하는 것부터 시작해요.
그러면 다음 파일들이 생겨요:

```txt
elm.json           # elm project configuration file
src/Exercise.elm   # code for the exercise
tests/Tests.elm    # tests for the exercise
```

그다음 `Exercise.elm`의 이름을 스토리 이름의 파스칼 케이스로 바꿔요.
예를 들어 `annalyns-infiltration`은 `AnnalynsInfiltration.elm`이 돼요.
그 소스 파일 안에, 방금 작성한 `instructions.md`에 설명된 모든 함수를 작성할 수 있어요.

연습 문제를 구현했으면, `tests/Tests.elm` 파일 내용을 `instructions.md`의 작업 순서를 자연스럽게 따르는 관련 테스트를 포함하도록 갱신해요.
개념 연습 문제의 테스트에서는 **`Fuzz` 사용을 삼가 주세요**. `Debug.log`로 코드를 디버깅하는 기능과 잘 어울리지 않기 때문이에요.
대신, 몇 가지 예외적인 경우와 일반적인 경우를 다루는 단위 테스트를 포함해요.
개념 연습 문제의 테스트에서 **`test`나 `describe` 함수 호출 바로 아래에 `let` 표현식을 사용하는 것을 삼가 주세요**. [elm test runner가 아직 이를 지원하지 않기](https://github.com/exercism/elm-test-runner/issues/30) 때문이에요.

연습 문제와 테스트가 모두 완성되고 잘 작동하면, 다음을 해요:

- `src/<ExerciseSlug>.elm`을 `.meta/Exemplar.elm`으로 복사해요. 여러분의 구현은 트랙 테스트를 실행할 때 사용되는, 해당 연습 문제의 참고 구현인 '모범 구현' 역할을 해요.
- `src/<ExerciseSlug>.elm` 안의 모든 구현을 제거해서, 학생이 연습 문제를 시작할 준비가 된 스타터 파일만 남겨요.

## 8. 개념 문서 작성하기

`exercises/concept/<story-name>` 연습 문제와 연관된 개념을 위한 `concepts/<concept>/` 디렉터리를 만들어요.
그 새 폴더 안에 두 개의 마크다운 문서 [`introduction.md`][concept-intro-spec]와 [`about.md`][concept-about-spec], 그리고 [`links.json`][concept-links-spec] 파일 하나를 만들어요(링크를 따라가면 각 명세로 연결돼요).

`introduction.md` 개념 파일에는, 학생이 연관된 개념 연습 문제를 완료하지 않은 동안 개념 페이지에서 보게 되는 소개가 담겨요.
학생이 연습 문제를 시작하면 무엇을 배우게 될지 잘 개괄해 줘야 해요.
반대로, `about.md` 개념 파일에는 학생이 연관된 개념 연습 문제를 완료한 뒤에만 개념 페이지에서 보게 되는 개념 요약이 담겨요.
따라서 이들은 앞서 작성한 `exercises/concept/<story-name>/.docs/introduction.md` 파일과 내용이 비슷하지만 같지는 않아요.
개념 파일 `introduction.md`는 연습 문제 소개 문서에서 시작해서 그 본질만 남기도록 단순화하는 걸 추천해요.
그리고 `about.md` 문서는 연습 문제 소개로 시작해서, 개념에 관한 모든 관련 정보가 그 페이지에 담기도록 완성해요.
`links.json`은 개념에 대한 추가 정보가 담긴 유용한 링크를 제공해요.
공식 문서나 훌륭한 튜토리얼 등이 될 수 있어요.
이 링크들은 개념의 about.md 파일 안에 있는 더 맥락적인 링크를 대체하지는 않고, 학생에게 전체를 아우르는 빠른 참고 지점을 제공해요.
링크에는 선택적으로 icon_url 필드를 둘 수 있고, 이걸로 링크가 표시될 때 보이는 아이콘을 지정할 수 있어요. 지정하지 않으면 아이콘은 기본값으로 favicon을 사용해요.
사용 가능한 아이콘은 [github.com/exercism/website-icons/tree/main/exercises][icons]에서 찾을 수 있어요.

## 9. 여러 구성 파일 완성하기

코드와 문서가 끝났으니, 이 PR을 완성하기 위해 몇 개의 구성 파일만 남았어요:

- [`concepts/<concept>/.meta/config.json`][concept-config-json]: 자신을 작성자로, 잠재적인 리뷰어를 기여자로 추가하고, 'blurb'(짧은 설명)를 추가해요.
- [`exercises/concept/<story-name>/.meta/config.json`][exercise-config-json]: 작성자(여러분), 기여자, blurb 및 기타 정보가 들어 있어요. 링크된 명세를 참고해요.
- `config.json`: 트랙 `config.json` 파일에 [개념 항목][track-config-json-concept]과 [개념 연습 문제 항목][track-config-json-concept-exercise]을 추가해요. 개념 연습 문제의 status 키에는 'wip'나 'beta'를 사용해요. UUID는 exercism에서 제공하는 [configlet 실행 파일][configlet]로 생성할 수 있어요.

## 10. 감사해요!

exercism에 기여해 주셔서 감사해요, 정말 멋져요!
