# 소개

이 연습 문제는 [뒷마당 새 관찰자][backyard-birdwatcher]에서 본 내용을 바탕으로, 연산을 이끌기 위해 *쿼테이션*(`[ ]` 괄호 안의 코드 조각)을 받는 고차 워드를 소개해요.

## 값으로서의 쿼테이션

쿼테이션은 그냥 코드 리터럴이에요. 데이터처럼 다른 워드에 넘길 수 있어요:

```factor
{ 1 2 3 4 5 } [ 2 > ] count .   ! => 3
```

여기서 `[ 2 > ]`는 숫자를 받아 불리언을 남기는 쿼테이션이에요. `count`는 각 원소에 대해 이것을 실행하고 참인 결과를 세요.

## 필터링과 걸러내기

```
find      ( seq quot    -- i/f elt/f ) ! first match: index and element, or f f
find-last ( seq quot    -- i/f elt/f ) ! same, but searches from the end
filter    ( seq quot    -- newseq )    ! keep elements where quot is truthy
reject    ( seq quot    -- newseq )    ! drop them instead
without   ( seq exclude -- newseq )    ! drop every element that's in `exclude`
sift      ( seq         -- newseq )    ! drop every `f`, keep the rest
```

```factor
{ 1 2 3 4 5 } [ 3 > ] find .s
! => 3            (index)
! => 4            (element)
{ 1 2 3 4 5 } [ 3 > ] find-last .s
! => 4            (index)
! => 5            (element)
{ 1 2 3 4 5 } [ even? ] filter .    ! => { 2 4 }
{ 1 2 3 4 5 } [ even? ] reject .    ! => { 1 3 5 }
"hello world" " ld" without .       ! => "heowor"
{ 1 f 2 f 3 } sift .                ! => { 1 2 3 }
```

`without`은 두 번째 인자를 집합으로 취급해요. `seq`의 원소 중 `exclude`의 *어떤* 원소와 `=`인 것은 모두 버려져요. `sift`는 `reject`의 쿼테이션 없는 특수한 경우예요. `f`를 제외한 모든 원소를 남기는데, 이전 `map`이 남긴 빈자리를 정리할 때 유용해요.

### 검사 결과 유지하기

`find`는 일치하는 *원소*를 돌려줘요. 검사가 이미 원하는 값을 *계산*해 준다면, `map-find`가 두 번째 순회를 아껴줘요. 각 원소에 대해 쿼테이션을 실행하고 처음 나온 `f`가 아닌 결과**와** 그것을 만들어 낸 원소를 반환해요.

```
map-find ( seq quot: ( elt -- result/f ) -- result elt )
```

```factor
USING: kernel math sequences ;

! First multiple of 3, paired with that multiple divided by 3.
{ 11 13 15 17 } [ dup 3 mod 0 = [ 3 /i ] [ drop f ] if ] map-find .s
! => 5            (result: 15/3)
! => 15           (element)
```

쿼테이션은 조건에 맞지 않는 원소에는 `f`를 반환하고, 맞는 원소에는 남기고 싶은 결과를 반환해요. 아무것도 조건에 맞지 않으면 `map-find`는 `find`처럼 `f f`를 남겨요.

### 슬롯으로 레코드 걸러내기

원소가 *튜플*일 때는, 술어가 보통 자동 생성된 리더 `slot>>`로 슬롯을 꺼내서 그것으로 검사해요:

```factor
USING: accessors sequences ;

TUPLE: customer name vip? ;

{
    T{ customer { name "Alice" } { vip? t } }
    T{ customer { name "Bob"   } { vip? f } }
    T{ customer { name "Carol" } { vip? t } }
}
[ vip?>> ] filter [ name>> ] map .
! => { "Alice" "Carol" }
```

## `with`로 고정값 흘려보내기

때로는 술어가 매 호출마다 같은 값이 필요해요. 임계값, 제수, 대상 문자열 같은 것이에요. `with`([`kernel`][kernel]에 있어요)는 그 고정값을 쿼테이션에 구워 넣어서, 두 인자 쿼테이션 `( value elt -- ? )`을 `filter`, `count`, `map`, `each`가 기대하는 한 인자 쿼테이션으로 바꿔줘요:

```
with ( value seq quot -- seq curry )
```

원소마다의 호출은 스택에서 `( value elt )`를 봐요. 고정값이 먼저, 현재 원소가 두 번째예요:

```factor
USING: kernel sequences ;

! Count elements greater than 5 — value=5 is threaded in
5 { 2 7 4 9 1 8 } [ < ] with count .   ! => 3
```

## 매핑과 반복

`map`([`sequences`][sequences]에 있어요)은 각 원소에 쿼테이션을 적용하고 결과들의 배열을 반환해요. `each`는 같은 순회를 하지만 결과를 버려요. 쿼테이션이 순전히 부수 효과를 위해 실행될 때 유용해요. `2map`은 *두* 시퀀스를 나란히 순회하며 대응하는 원소들을 결합해요. `2each`와 `2reduce`는 각각 부수 효과만을 위한 사촌과 접기 사촌이고, `zip`은 "결합하지 않고 짝지어 주기"의 줄임말이에요:

```
map     ( seq       quot           -- newseq )
map-as  ( seq       quot exemplar  -- newseq )
each    ( seq       quot           -- )
2map    ( seq1 seq2 quot           -- newseq )
2each   ( seq1 seq2 quot           -- )
2reduce ( seq1 seq2 identity quot  -- result )
zip     ( seq1 seq2                -- pairs )
```

`2reduce`는 누산기를 두 시퀀스에 동시에 흘려보내요. 그 쿼테이션은 `( accumulator elt1 elt2 -- accumulator' )`를 받아요. 여기서는 내적을 누적해요. 각 쌍이 곱해지고, 그 곱들이 더해져요(`1*10 + 2*20 + 3*30`):

```factor
{ 1 2 3 } { 10 20 30 } 0 [ * + ] 2reduce .   ! => 140
```

`map-as`는 출력 시퀀스의 타입을 강제하는 `map`의 사촌이에요. 입력 타입 기본값을 덮어쓰려면 빈 `{ }`나 `V{ }`를 exemplar로 넘겨요(그러지 않으면 문자열을 비문자로 매핑할 때 Factor가 결과를 다시 문자열로 묶으려다 오류가 나요).

```factor
USING: formatting math sequences ;

{ 1 2 3 } [ sq ] map .                         ! => { 1 4 9 }
{ 1 2 3 } [ . ] each                           ! prints 1, then 2, then 3
{ 1 2 3 } { 10 20 30 } [ + ] 2map .            ! => { 11 22 33 }
{ "x" "y" } { 1 2 } [ "%s%d" sprintf ] 2map .  ! => { "x1" "y2" }
{ 1 2 3 } { 10 20 30 } [ + . ] 2each           ! prints 11, then 22, then 33
{ "a" "b" "c" } { 1 2 3 } zip .                ! => { { "a" 1 } { "b" 2 } { "c" 3 } }
```

두 시퀀스를 받는 두 형태 모두 더 짧은 입력의 길이에서 멈춰요. `zip`은 `[ 2array ] 2map`과 같아요. 짝을 합치는 게 아니라 짝을 유지하는 거예요.

## 정렬

`sort`는 자연 순서로 정렬된 복사본을 반환해요. `sort-by`([`sorting`][sorting]에 있어요)는 각 원소에서 뽑아낸 키로 정렬해요:

```
sort    ( seq      -- sortedseq )
sort-by ( seq quot -- sortedseq )
```

```factor
{ 3 1 4 1 5 9 2 6 } sort .
! => { 1 1 2 3 4 5 6 9 }

{ -3 5 -1 4 } [ abs ] sort-by .
! => { -1 -3 4 5 }
```

## 집계하기

`map-sum`([`sequences`][sequences]에 있어요)은 시퀀스 전체에 쿼테이션을 매핑하고 결과를 한 번의 순회로 더해요:

```
map-sum ( seq quot -- n )
```

```factor
{ 1 2 3 4 } [ sq ] map-sum .   ! => 30
```

## 최솟값과 최댓값

`minimum`과 `maximum`은 시퀀스에서 가장 작거나 큰 원소를 그대로 반환해요. `minimum-by`와 `maximum-by`(모두 [`sequences`][sequences]에 있어요)는 뽑아낸 키가 가장 작거나 큰 원소를 반환해요:

```
minimum     ( seq      -- elt )
maximum     ( seq      -- elt )
minimum-by  ( seq quot -- elt )
maximum-by  ( seq quot -- elt )
```

```factor
{ 3 1 4 1 5 9 2 6 } minimum .       ! => 1
{ 3 1 4 1 5 9 2 6 } maximum .       ! => 9

{ -3 5 -1 4 } [ abs ] minimum-by .
! => -1
```

## 나만의 고차 워드 만들기

*직접 만든* 워드가 쿼테이션을 런타임 인자로 받아서 `map`, `filter`, `each` 등에 넘길 때는, 그 워드를 `; inline`으로 선언해요. 그러면 컴파일러가 쿼테이션이 알려진 리터럴인 각 호출 지점에 그 워드를 인라인하도록 해요. 이것이 없으면 컴파일러는 쿼테이션의 스택 효과를 알 방법이 없어요.

```factor
USING: math sequences ;

: tax-on ( inventory quot -- total )
    map-sum ; inline

{ { "shirt" 20 } { "hat" 15 } } [ second 1/10 * ] tax-on .
! => 3+1/2
```

리터럴 쿼테이션만으로 만들어진 워드는 `inline`이 필요 없어요. *들어오는* 쿼테이션을 넘겨주는 워드만 필요해요.

그런 `inline` 워드가 *자기 자신*을 호출하면(재귀 컴비네이터), 대신 `; inline recursive`로 선언해요. 이 추가 워드가 없으면 컴파일러는 *"The inline recursive word ... must be declared recursive"*와 함께 멈춰요. 이는 정확히 무엇을 추가해야 하는지 알려줘요.

## 두 번째 원소 꺼내기

원소가 2개인 배열에서 `second`는 두 번째 원소를 반환해요. `first`는 첫 번째를 반환해요. 둘 다 [`sequences`][sequences]에 있어요.

## 숫자를 문자열로

`number>string ( n -- str )`([`math.parser`][math.parser]에 있어요)은 숫자를 십진 문자열 형태로 바꿔요:

```factor
42 number>string .     ! => "42"
3.5 number>string .    ! => "3.5"
```
