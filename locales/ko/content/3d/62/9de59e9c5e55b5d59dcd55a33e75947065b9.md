# 사용자 정의 이터레이터

```sather
   markers!(once spacing : INT, once count : INT) : INT is
      loop
         yield spacing * 1.upto!(count);
      end;
   end;
```

| | 루틴 | 이터레이터 |
| --- | --- | --- |
| 이름 | `foo` | `foo!` |
| 값 넘겨주기 | `return` | `yield` |
| 끝내기 | `return`, 또는 끝까지 | `quit`, 또는 더 이상 없을 때 |
| 호출할 수 있는 곳 | 어디서나 | `loop` 안에서만 |
| 위치 유지 | 아니요 | 예 |

## yield

`yield`는 값을 넘겨주고 실행을 잠시 멈춰요. 다음 차례가 되면 모든 것이 그대로 복원돼요. 지역 변수, 이터레이터 자체의 루프에서의 위치, 그리고 이 이터레이터가 호출하고 있는 다른 이터레이터들의 위치까지요.

중첩된 루프 안의 `yield`는 가장 안쪽 루프에서 다시 이어져요. 덕분에 중첩된 구조를 순회하는 코드를 간단하게 작성할 수 있어요.

```sather
   all_cells!(grid : ARRAY{ARRAY{INT}}) : INT is
      loop
         row ::= grid.elt!;
         loop
            yield row.elt!;
         end;
      end;
   end;
```

## quit

이터레이터를 끝내고, 따라서 그것을 호출한 루프도 끝내요. 값을 담고 있지는 않아요. `quit`는 마지막 결과가 아니라, 결과가 더 이상 없다는 선언이에요.

반환 타입이 있는 이터레이터는 값을 넘겨줄 때마다 반드시 값을 `yield`해야 해요. 그렇게 하지 않겠다고 밝힐 때 쓰는 것이 `quit`예요.

## once

```sather
   markers!(once count : INT) : INT is
```

`once` 인자는 루프에 들어갈 때 한 번 평가되고 그 값이 유지돼요. 일반 인자는 매 차례마다 다시 평가되는데, 넘겨받은 식에 다른 이터레이터 호출이 들어 있을 때 이 차이가 중요해요:

```sather
   loop
      #OUT + TRAIL::markers!(sizes.elt!);     -- a new count every turn
   end;
```

특별히 그렇게 하고 싶은 게 아니라면 인자에 `once`를 표시해요. 라이브러리 전체가 그렇게 해요.

## self와 이터레이터

이터레이터는 객체에 대해 호출될 수 있는데, 그러면 `self`가 그 객체예요. 일시 정지된 상태는 객체가 아니라 호출한 위치에 속하기 때문에, 같은 객체를 순회하는 두 루프가 서로 간섭하지 않아요.

## 언제 이터레이터를 만들어야 할까요

결과가 연속된 값의 나열이고, 호출하는 쪽이 그중 얼마나 가져갈지 결정해야 할 때 이터레이터를 작성해요. 중간에 멈추는 데 아무 비용이 들지 않고, 쓰지 않을 것은 만들어지지도 않아요. `ARRAY`를 반환하는 루틴이라면 전체를 먼저 다 만들어야 하는 것과는 다르죠.
