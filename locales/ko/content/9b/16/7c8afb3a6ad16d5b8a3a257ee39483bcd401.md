# 개요

`TUPLE: child < parent extra-slots ;`는 인스턴스가 `parent`의 인스턴스이기도 한 클래스를 선언해요. 슬롯 조회는 계층 구조를 따라가요: `child`는 `parent`가 선언한 모든 슬롯에 자신의 슬롯까지, 바로 그 순서대로 가지고 있어요.

```factor
TUPLE: vessel name tonnage ;
TUPLE: cargo-vessel < vessel capacity ;
TUPLE: tanker < cargo-vessel fuel-type ;
```

## `boa` 인자 순서

자동으로 생성되는 `boa` 생성자는 슬롯을 선언 순서대로, *부모가 먼저* 오는 순서로 받아요. 위의 `tanker`라면 이렇게 돼요:

```
tanker boa ( name tonnage capacity fuel-type -- tanker )
```

슬롯 순서는 상속 체인에 의해 고정돼요. 부모 슬롯과 자식 슬롯을 서로 섞을 방법은 없고, 부모의 슬롯 순서를 바꾸는 것은 모든 자손의 `boa`에 영향을 주는 호환성 깨는 변경이에요.

## 술어 계층 구조

모든 `TUPLE:` 선언은 클래스 술어(`name?`)를 만들어요. 상속을 쓰면 술어들이 중첩돼요:

```factor
"Esso" 50000 100000 "diesel" tanker boa .

! all three predicates fire
dup tanker?        .   ! => t
dup cargo-vessel?  .   ! => t
dup vessel?        .   ! => t
```

`instance?`([`classes`][classes]에서 왔어요)는 클래스를 단어 이름에 박아 넣는 대신 스택 인자로 받아 같은 질문을 던져요. `obj tanker instance?`는 `obj tanker?`와 같아요:

```factor
USING: classes ;

"Esso" 50000 100000 "diesel" tanker boa
dup vessel instance? .   ! => t
```

이제 클래스가 값이기 때문에, 같은 호출 지점에서 넘겨받은 어떤 클래스에 대해서든 검사할 수 있어요. 이름이 고정된 `name?` 술어는 그렇게 할 수 없어요.

전이적인 `is-a` 관계는 `M:` 메서드 디스패치가 따라가는 경로이기도 해요. `vessel`에 정의된 메서드는 더 구체적인 재정의가 먼저 발동하지 않는 한 모든 `cargo-vessel`과 모든 `tanker`에 적용돼요. 이 이야기의 나머지는 [`generics`][generics]에 있어요.

## 접근자 상속

접근자 단어(`slot>>`, `>>slot`, `change-slot`)는 [`accessors`][accessors]에서 왔고, 자신이 생성된 클래스에 묶여 있지 않아요. 슬롯을 *가지고 있는* 튜플이라면 무엇이든 이들을 쓸 수 있어요.

```factor
USING: accessors ;

"Esso" 50000 100000 "diesel" tanker boa
[ 1 + ] change-tonnage tonnage>> .   ! => 50001
```

`change-tonnage`는 `vessel`을 위해 생성됐지만, 모든 `tanker`가 `vessel`이기 때문에 `tanker`에서도 동작해요.

## 여기서 다루지 않는 것

- **믹스인**(`MIXIN:` / `INSTANCE:`): 클래스는 여러 믹스인에 참여할 수 있어요. 관계가 다대다이고, 주로 공유 프로토콜에 대한 제네릭 디스패치에 쓰여요. 스트림 개념에서 문맥과 함께 소개해요.
- **술어 클래스**(`PREDICATE:`): 런타임 술어로 기존 클래스에서 하위 클래스를 잘라내요. 별도의 Factor 기능이라 여기서는 다루지 않아요.
