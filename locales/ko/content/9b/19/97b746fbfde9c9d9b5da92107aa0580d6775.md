# 개요

메모리는 보통 운영 체제(OS)가 프로그램을 위해 다음과 같은 일반적인 배치로 매핑해요.

| 주소 | 메모리 영역 |
| :-----: | :--------------------- |
| 높은 주소 | 스택 |
| | ... |
| | 힙 |
| | 읽고 쓰기 세그먼트 |
| | 코드/읽기 전용 세그먼트 |
| 낮은 주소 | 예약됨 |

세그먼트로 나뉜 메모리는 서로 다른 권한을 가진 여러 섹션으로 구성돼요.

지금까지 정의한 함수는 모두 **섹션 .text**에 있었어요.
이 섹션은 읽기 전용이며 실행 가능한 데이터를 담고 있어요.
다른 섹션은 데이터 변수를 선언하는 데 쓰이는데, 이런 변수는 읽기 전용일 수도, 읽고 쓸 수도 있지만 실행할 수는 없어요.

## 섹션 .data

초기화된 데이터는 **[섹션 .data][data]**에 선언해요.

NASM(Netwide Assembler, 이 트랙에서 사용하는 어셈블러)에서 초기화된 변수는 이름, 데이터 크기를 나타내는 지시어, 그리고 쉼표로 구분된 값의 목록으로 이루어져 있어요.
이 요소들은 서로 공백으로 구분되고, 레이블 뒤에는 선택적으로 `:`가 올 수 있어요.

주요 지시어와 그에 해당하는 데이터 크기는 다음과 같아요.

| 지시어 | 크기 |
| :-------: | :------ |
| db | 1바이트 |
| dw | 2바이트 |
| dd | 4바이트 |
| dq | 8바이트 |

예를 들어, 다음은 `space`라는 이름의 바이트 변수를 값 `10`으로 선언해요.

```x86asm
section .data
    space db 10
```

`section .data`에 선언한 변수는 가변이에요. 즉, 읽고 쓸 수 있어요.
또한 이 변수들은 _정적_ 저장 기간을 가지는데, 이는 프로그램이 실행되는 내내 존재한다는 뜻이에요.

## 섹션 .rodata

**섹션 .rodata**는 `section .data`와 비슷해요.
두 섹션 모두 초기화된 데이터를 담고 있고, 이 데이터는 같은 방식으로 선언되며 같은 저장 기간을 가져요.

둘의 주된 차이는 `section .rodata`에 있는 데이터가 불변, 즉 읽기 전용이라는 점이에요.

~~~~exercism/note
`equ`로 정의한 상수는 `section .rodata`에 정의한 상수와 달라요.

`equ`로 정의한 상수는 메모리 공간을 차지하지 않고, 어셈블러가 상수를 그 값으로 직접 치환해요.
사실상 그 값을 위한 자리 표시자예요.

반면, `section .rodata`에 정의한 상수는 실제로 메모리에 저장되며 주소를 가져요.
~~~~

## 데이터에 접근하기

### 레이블과 간접 참조

선언된 데이터에는 반드시 이름이 연결되어 있어야 해요.
이 이름을 **레이블**이라고 해요.

레이블은 메모리에 있는 데이터의 특정 주소를 나타내는 기호예요.
**x86-64의 주소는 64비트 값이에요**.
이런 주소를 담고 있는 값은 레지스터에 있든 메모리에 저장되어 있든, 고급 언어에서 **[포인터][pointer]**라고 불러요.

NASM에서는 레이블로 데이터에 직접 접근하려고 하면 할당된 메모리가 아니라 그 주소를 얻게 돼요.

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

메모리 주소의 내용에 접근하려면 그 주소를 _역참조_해야 해요.
이것을 **간접 참조**라고 해요.

NASM에서는 `[]`로 이걸 해요.

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

하지만 역참조하는 메모리의 크기가 분명하지 않은 상황도 있어요.
그런 경우에는 이 크기를 지정하는 접두사를 사용해야 해요.

다음은 일반적인 x86-64 프로그램에서 가장 중요한 접두사와 그 크기예요.

| 접두사 | 크기 |
| :----- | :------ |
| byte   | 1바이트 |
| word   | 2바이트 |
| dword  | 4바이트 |
| qword  | 8바이트 |

같은 로드를 크기를 명시적으로 밝혀서 쓸 수도 있어요.

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

메모리를 역참조할 때는 항상 접두사를 사용하는 것이 좋은 관례예요.

### 메모리에 쓰기

메모리에 쓰는 것도 주소를 역참조한다는 점에서 같은 방식이에요.

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

대부분의 명령어에서 메모리 피연산자는 내용을 먼저 레지스터에 로드하지 않고도 사용할 수 있다는 점에 유의해요.
하지만 보통은 소스 피연산자와 목적지 피연산자 둘 다에 사용할 수는 없고, 둘 중 하나에만 사용할 수 있어요.

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### LEA 명령어

`mov`로 변수의 주소를 레지스터에 저장할 수 있지만, 이 특정 목적을 위한 명령어가 있어요: **[lea][lea]**.

이 명령어는 메모리 형식의 피연산자를 사용하지만, 메모리를 _읽지는 않아요_.
대신 유효 주소 식을 계산해서 그 결과를 목적지 피연산자에 써요.

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

메모리 주소를 계산해 레지스터에 저장할 때는 `lea`를 쓰는 것이 더 자연스러워요.

### 상대 주소 지정

메모리 위치에 접근할 때 NASM의 기본 동작은 **절대 주소**, 즉 고정된 메모리 주소를 생성하는 거예요.

보안상의 이유로 실행 파일은 흔히 **PIE(위치 독립 실행 파일)**로 빌드되는데, 이때 메모리 영역은 무작위 위치에 배치돼요.
`PIE`에서는 변수의 최종 주소가 링크 시점에 알려지지 않아요.
그래서 코드는 대신 `rip`라는 특수 레지스터에 담긴 값을 기준으로 한 오프셋으로 주소를 계산해요. `rip`는 다음에 실행될 명령어를 가리켜요.

이것을 보통 **RIP 상대 주소 지정**이라고 해요.

NASM에서는 **[rel 연산자][rel]**로 RIP 상대 접근을 요청할 수 있어요.

```x86asm
mov rax, qword [rel variable]
```

소스 파일 맨 위에 `default rel`을 두면 상대 주소 지정을 기본값으로 만들 수도 있어요.

이 트랙의 모든 연습 문제는 `PIE`로 컴파일되고 링크되므로, 상대 주소를 생성하려면 `rel`을 사용해야 해요.

위에서 언급한 무작위 배치는 주소 공간 배치 무작위화라는 완화 기법이에요.
각 메모리 영역의 시작 위치를 예측할 수 없게 만들어서, 많은 공격 기법이 의존하는 고정 주소를 공격자가 쓸 수 없게 해요. 그리고 `PIE`는 로더가 그 영역들을 아무 데나 배치할 수 있게 해주는 것이에요.

이 때문에 이 트랙에서 절대 주소 지정은 권장되지 않는 정도가 아니라 아예 쓸 수 없어요.
`[abs variable]`과 같은 절대 참조는 어셈블러에게 명령어 안에 고정된 32비트 주소를 넣으라고 요청하는 셈이에요.
Linux에서는 `PIE` 링커가 이렇게 만들어지는 재배치를 거부하고, macOS에서는 `macho64` 형식이 32비트 절대 주소를 아예 지원하지 않아서 파일이 어셈블되지 않아요.

RIP 상대 주소 지정은 두 문제를 모두 피할 수 있어요. 명령어가 `rip`로부터의 오프셋만 인코딩하고 고정 주소는 전혀 인코딩하지 않기 때문이에요.
따라서 `PIE`에서 주소를 레지스터에 넣는 자연스러운 방법은 `rel` 피연산자를 사용하는 `lea`예요.

```x86asm
default rel

section .data
    variable dq 7

section .text
fn:
    lea rax, [rel variable]       ; materialize the address (PIE-safe)
    mov rcx, qword [rel variable] ; load the value through a RIP-relative access
    ...
```

### 가시성

어떤 섹션(예: `.text`, `.data`, `.rodata`)에 정의된 레이블(함수와 데이터)은 같은 소스 파일 안에서 볼 수 있어요.
`global`로 선언하면 다른 소스 파일에서도 볼 수 있어요.

반대로, 다른 소스 파일에 정의된 레이블은 `extern`으로 선언하면 현재 소스 파일에서 볼 수 있어요.
이 경우 어셈블리에서는 데이터 크기를 알 수 있는 단서가 없어서, 크기를 미리 알고 있어야 해요.

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
