# 자세히 알아보기

Factor에서 데이터를 주고받는 유일한 규약은 *데이터 스택*이에요. 워드는 입력값을 꺼내고 출력값을 밀어 넣어요. 모든 워드 정의는 그 규약을 적어 둔 *스택 효과*를 함께 선언해요.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

`( … -- … )` 안에 있는 이름은 읽는 사람을 위한 것이고, 컴파일러가 검사하는 것은 입력과 출력의 *개수*예요. 개수가 맞지 않으면 컴파일 시점 오류가 나요. 이런 선언이 없는 동적 타입 언어라면 실행 시점 오류로 나타났을 부류의 버그를 컴파일 시점에 미리 잡아 주는 거예요.

스택에서는 값의 위치가 곧 의미이기 때문에, 다음 워드가 실행되기 전에 스택 위쪽을 끊임없이 다시 정리해야 해요. `kernel`의 **순서 바꾸기 워드**가 바로 그 일을 해요.

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

순서 바꾸기 워드 패밀리 전체는 여기에 `-rot`(반대쪽으로 돌리기), 한 칸 더 깊은 항목에 작용하는 `d`가 붙은 워드들(`dupd`, `swapd`), 짝을 대상으로 작용하는 `2`가 붙은 워드들(`2dup`, `2drop`, `2nip`), 그리고 `pick`, `tuck` 같은 워드들을 더해요. 이 워드들은 뒤의 연습 문제에서 필요해질 때 소개돼요. 순서 바꾸기 워드를 한꺼번에 너무 많이 꺼내 쓰는 건 보통 *로컬*(이름을 붙인 값)이 더 읽기 좋다는 신호예요.

관례상 워드 이름은 `lowercase-kebab-case`를 따르고, 술어는 `?`로 끝나며 불리언을 반환하고(`even?`, `empty?`), 세터는 `>>name`, 게터는 `name>>`로 쓰고, 어떤 워드와 그 변형 워드는 흔히 이름을 공유해서 문맥으로만 구분해요.
