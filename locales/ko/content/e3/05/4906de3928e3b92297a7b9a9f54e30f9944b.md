# 힌트

`Either`는 계산이 오류를 낼 수도 있음을 나타낼 때 흔히 사용해요(실제 오류 자체에는 관심이 없다면 더 단순한 `Option` 타입이 더 나은 선택일 수 있어요). 오류가 없을 때 결과는 보통 `Right`(기억법: '올바른' 값)이고, 오류일 때는 `Left`예요. 예를 들어 오류 메시지를 담은 `Left[String]`처럼요.

Scala 2.12에서 `Either`는 기본적으로 Right 쪽에 치우쳐 있어서, `filter`, `map`, `flatMap` 같은 연산이나 for 컴프리헨션에서 기대한 대로 동작해요. `Either`가 낯설다면 [이 튜토리얼](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html)을 읽어봐도 좋아요. 다만 이 튜토리얼은 2.12 이전 버전의 Scala를 다룬다는 점을 알아두세요. Scala 2.12에서는 `RightProjection`을 안심하고 무시해도 되고, `.right`도 생략할 수 있어요.

`Either`는 이른바 [모나드](https://en.wikipedia.org/wiki/Monad_(functional_programming))로, "계산적 측면"을 다뤄요. 여기서는 오류 처리죠. 모나드를 제대로 쓰면 아주 간결하면서도 우아하고 읽기 쉬운 코드가 나와요. 잘못 쓰면 그 반대가 되기 쉬워요. 더 알아보려면 [이 영상](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA)을 봐요.

## 피해야 할 흔한 함정

`Either`에 관해서는 몇 가지 경험 법칙이 있어요:

1. 필요하지 않으면 쓰지 않아요. 다음처럼 쓰기보다는

```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```

이렇게 쓰는 게 더 좋아요.

```scala
def add1(x: Int): Int = x + 1
```

(이런 단순한 함수를 적용할 때는 `Either.map`이 있으니, 굳이 `Either`로 코드를 어지럽힐 필요가 없어요.)

2. 정말로 필요하지 않다면 "unwrap"하지 않아요. 목적에 맞는 내장 함수가 있는 경우가 많아요. 성급하게 "unwrap"하고 있다는 신호는 `isLeft/isRight`나 패턴 매칭이에요. 예를 들어 다음처럼 쓰기보다는

```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```

이렇게 쓰는 게 더 좋아요.

```scala
x fold (identity, _ + 1)
```

3. 모나드는 for 컴프리헨션 안에서도 쓸 수 있어요(FTW). 여러 `Either` 인스턴스를 "조합"하고 싶을 때 이 방법이 좋아요. 다음처럼 쓰기보다는

```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```

이렇게 쓰는 게 더 좋아요.

```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
