# 설치

## 머리말

Regina Rexx는 다양한 플랫폼으로 이식되었지만, 여기서는 Windows, Linux, MacOS를 실행하는 64비트 데스크톱 플랫폼을 기준으로 설치 방법을 설명해요.

## 설치 단계

이 트랙은 최신 버전의 [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/)가 설치되어 있다고 가정해요(글을 쓰는 시점 기준 3.9.5예요). 위 링크를 누르면 Files 섹션으로 바로 이동하고, 거기서 내려받을 파일을 고르면 돼요.

### Windows

Windows에서 네이티브로(CMD 또는 Powershell 창을 통해) 실행할 수 있도록 설치하는 방법은 브라우저에서 [`Download Latest Version`](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/Regina395w64.exe/download) 버튼을 누르면 간단히 끝나요. 그냥 클릭하고, 내려받고, 설치하면 돼요.

다음과 같은 Linux 에뮬레이션 환경이 이미 있거나 사용할 생각이라면:

* [Git for Windows](https://gitforwindows.org/)
* [Cygwin](https://cygwin.com/)
* [MinGW](http://mingw.org/)

Windows 네이티브 Regina 바이너리에 접근할 수 있으니, 이런 환경에서 그냥 실행하면 돼요. 대부분의 경우에는 이걸로 충분해요.

다만 한 가지 주의할 점이 있는데, ADDRESS 명령어는 제대로 동작하지 않아요(호스트 운영체제와 연결되기 때문이에요). 이런 환경에서 최상의 결과를 얻으려면 해당 환경 전용 패키지를 받아서 설치해요. 예를 들어 Regina 웹사이트에는 설치할 수 있는 [Cygwin 전용](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-pc-cygwin.tgz/download) 빌드가 있어요.

또는 Windows 위에서 [WSL](https://docs.microsoft.com/en-us/windows/wsl/about)이나 [Virtual Box](https://www.virtualbox.org/) 같은 _진짜_ Linux 배포판을 사용하고 있거나 사용할 생각이라면, Linux 섹션에서 해당 배포판에 맞는 안내를 그대로 따라 하면 돼요.

### Linux

Linux에서는 보통 시스템의 패키지 관리자를 쓰면 설치가 아주 간단해요. 그런데 사용할 수 있는 패키지가 최신 버전이 _아닐_ 때는 문제가 생겨요. 안타깝게도 Regina가 그런 경우예요.

최신 패키지를 직접 받아오면 패키지 기반 설치도 여전히 가능해요. [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/) 웹사이트에는 Debian 계열(Ubuntu 포함)과 RHEL 계열(Fedora, CentOS, Rocky, Alma 포함) 배포판 등을 위한 패키지가 있어요.

선택한 배포판에 따라 라이브러리 패키지와 바이너리 패키지, 두 개의 패키지를 내려받아야 해요. 예를 들어 Debian이나 Ubuntu에 설치하려면 다음과 같이 해요:

```plain
sudo apt update && sudo apt -y install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx_3.9.5-2_amd64-Debian-11.deb > regina-rexx_3.9.5-2_amd64-Debian-11.deb
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3_3.9.5-2_amd64-Debian-11.deb > libregina3_3.9.5-2_amd64-Debian-11.deb
sudo apt -y install libregina3_3.9.5-2_amd64-Debian-11.deb regina-rexx_3.9.5-2_amd64-Debian-11.deb
```

그리고 CentOS와 RHEL 7에서는 이렇게 해봐요:
```plain
sudo yum update && sudo yum install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm > libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
sudo yum localinstall libregina3-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm regina-rexx-3.9.5-220823.1647.x86_64-CentOS-7.9.2009.rpm
```

Fedora, Rocky, Alma에서는 이렇게 해봐요:
```plain
sudo dnf update && sudo dnf install curl
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm > libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
sudo dnf localinstall libregina3-3.9.5-220826.0951.x86_64-rocky-9.0.rpm regina-rexx-3.9.5-220826.0951.x86_64-rocky-9.0.rpm
```

패키지 기반 설치가 불가능하거나 다른 이유로 문제가 있다면, 언제든 소스에서 빌드할 수 있어요. 압축 파일은 다음에서 받을 수 있어요:

```plain
curl -sLk https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5.tar.gz > regina-rexx-3.9.5.tar.gz
```

표준 빌드 도구(gcc, make)가 설치되어 있다고 가정하고(설치되어 있지 않다면 여기 안내를 따라 해요: [개발 도구 설치](https://ostechnix.com/install-development-tools-linux/)), 다음 단계를 진행해요:

```plain
tar -xzvf regina-rexx-3.9.5.tar.gz && cd regina-rexx-3.9.5
./configure
sudo make
sudo make install
```

라이브러리(`libregina.so`)와 두 가지 바이너리(`rexx`와 `regina`)가 설치돼요(기본 위치는 `/usr/local/bin`이에요).

`rexx` 바이너리는 정적 링크되어 있어서 그 자체로 완결되어 있고 바로 사용할 수 있어요.

`regina` 바이너리는 동적 링크되어 있어서, 실행할 때 `libregina.so` 공유 라이브러리를 찾을 수 있도록 설정이 좀 필요해요. 그러려면 다음 단계를 따라 해요:

```plain
# Configure shared library location
sudo su
echo /usr/local/lib64/ > /etc/ld.so.conf.d/regina-rexx-3.9.5-x86_64.conf
echo /usr/local/lib64/regina-rexx/addons > /etc/ld.so.conf.d/regina-rexx-addons-x86_64.conf
cd /usr/local/lib64
rm -f libregina.so libregina.so.3
ln -s libregina.so.3.9 libregina.so
ln -s libregina.so.3.9 libregina.so.3
ldconfig
exit

# Check symbolic link creation
ls -l /usr/local/lib64/

# Output should be similar. Note symbolic links.
-rw-r--r--. 1 root root 3887554 Dec  1 18:22 libregina.a
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so -> libregina.so.3.9
lrwxrwxrwx. 1 root root      16 Dec  2 06:03 libregina.so.3 -> libregina.so.3.9
-rwxr-xr-x. 1 root root  574104 Dec  1 18:22 libregina.so.3.9
drwxr-xr-x. 2 root root      26 Dec  1 18:22 pkgconfig
drwxr-xr-x. 4 root root      33 Dec  1 18:22 regina-rexx

# Check library path, and executable using that path
ldconfig -p | grep regina
ldd /usr/local/bin/regina

# Alternate for local user
export LD_LIBRARY_PATH=${LD_LIBRARY_PATH}:/usr/local/lib64:/usr/local/lib64/regina-rexx/addons
```

참고로, 소스에서 빌드하는 것과 그에 따르는 시스템 설정은 경험 많은 사용자가 하는 게 좋아요.

### MacOS

설치는 세 단계로 이루어져요:

* [Homebrew](https://brew.sh) 패키지 관리자를 설치해요
* `Terminal` 애플리케이션을 찾아서 실행해요
* `Terminal` 명령줄에서 다음을 입력해요:

   `brew install regina-rexx`

이렇게 하면 최신 버전이 설치_될_ 거예요.

만약 그렇게 되지 않으면 [Regina for MacOS](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/regina-rexx-3.9.5-x86_64-apple-darwin21.6.0.tgz/download) 패키지를 내려받아 직접 설치하면 돼요.

## 설치 후

### 설치 확인

설치를 마친 뒤 터미널에서 다음 명령을 실행하면 [Regina](https://sourceforge.net/projects/regina-rexx/files/regina-rexx/3.9.5/)가 제대로 설치되었는지 확인할 수 있어요:

```plain
rexx --version=v
```

Windows와 Linux 플랫폼 모두에서 터미널에 다음과 같은 출력이 나타나요:

```plain
3.9.5
```

이게 바로 인터프리터의 버전 번호예요.

두 번째 바이너리인 `regina`도 함께 설치돼요. 이 바이너리는 공유 라이브러리에 링크된다는 점만 빼면 `rexx`와 모든 면에서 똑같고, 외부 유틸리티 함수에 접근하고 싶을 때 대신 사용하는 인터프리터예요. [외부 루틴 사용하기](###accessing-external-routines) 섹션을 참고해요.

트랙을 시작하는 데 필요한 다른 소프트웨어는 없어요(Exercism CLI가 설치되어 있다고 가정해요).

아래 사용 안내를 보면 명령줄에서 인터프리터를 사용하는 기본기를 익힐 수 있어요.

### 사용법

Rexx 스크립트는 보통 _`.rexx`_ 확장자를 가져요. 하지만 꼭 그래야 하는 건 아니에요. 인터프리터는 인자로 넘겨받은 파일 이름을 그대로 실행하려고 시도하고, 그 안에 올바른 Rexx 코드가 들어 있으면 잘 실행되거든요.

다음 명령은 `hello.rexx`라는 파일을 실행하려고 시도해요:

```plain
rexx hello.rexx
```

파일에 다음 코드가 들어 있다고 하면:

```rexx
say "Hello, world!"
exit 0
```

터미널 출력은 이렇게 돼요:

```plain
Hello, world!
```

파일 이름을 `hello.txt`로 바꾸고 다음과 같이 실행해도 같은 출력이 나타나요:

```plain
rexx hello.txt
```

스크립트 코드를 파일에 저장해 두지 않고 인터프리터로 파이프로 넘길 수도 있다는 것도 알아 두면 아주 유용해요. 앞의 코드는 다음과 같이 파이프로 실행할 수 있어요:

```plain
echo "say 'Hello, world' ; exit 0" | rexx
```

Linux 터미널에서든 Windows Powershell 터미널에서든 똑같이 잘 동작해요.

### 고급 사용법

스크립트 파일에는 명령줄 인자를 하나 이상 넘길 수 있고, 임의의 정수 반환 코드를 돌려줄 수도 있어요. 다만 인터프리터는 스크립트에 여러 인자가 넘어간다는 걸 알아야 하는데, 이는 `-a` 옵션으로 처리해요.

예를 들어 `multiarg.rexx` 파일에 다음 코드가 들어 있다고 해봐요:

```rexx
say "My name is" ARG(1) || ", your name is" ARG(2) || ", and the script return code will be" ARG(3) || "."
exit ABS(ARG(3))
```

여러 스크립트 인자가 제대로 해석되게 하려면 스크립트를 다음과 같이 실행해요:

```plain
rexx -a multiarg.rexx "John" "Jill" 5
```

그러면 터미널에 다음 출력이 나타나요:

```plain
My name is John, your name is Jill, and the script return code will be 5.
```

그리고 프로그램 반환 코드(Linux에서는 `$?`, Windows에서는 `%errorlevel%`로 확인할 수 있어요)는 5로 설정돼요.

### 외부 루틴 사용하기

Regina는 외부 공유 라이브러리에 있는 루틴을 사용하는 걸 지원해요. Regina 웹사이트에서 여러 가지를 받을 수 있어요. 다만 그런 라이브러리를 설치하는 방법은 여기서 다루지 않아요.

Regina에는 그런 라이브러리 중 하나인 _regutil_이 함께 들어 있어요. 여기에는 수학, 파일 및 파일 시스템 조작, 시스템 접근 작업 등을 위한 여러 범용 루틴이 들어 있어요.

추가로 설치할 것은 없어요. 다만 스크립트에서 이 루틴들을 사용하려면 인터프리터가 로드될 때 이들을 등록해야 해요. 함수 호출 두 번이면 되고, 그 과정은 다음과 같아요.

`access-external.rexx` 파일에 다음 코드가 들어 있어요:

```rexx
/* Register external library and functions */
call RxFuncAdd 'SysLoadFuncs', 'regutil', 'SysLoadFuncs'
call SysLoadFuncs

say "Value of pi is" SysPi()
say "Square root of 25 is" SysSqrt(25)
say "Square root of 2 is" SysSqrt(2)

/* Deregister */
call SysDropFuncs

exit 0
```

이 루틴들을 로드해서 사용하려면 `regina` 바이너리를 써야 하므로, 스크립트는 이렇게 실행해요:

```plain
regina access-external.rexx
```

그러면 터미널에 다음 출력이 나타나요:

```plain
Value of pi is 3.141592654
Square root of 25 is 5.000000000
Square root of 2 is 1.414213562
```

만약 대신 `rexx` 바이너리를 사용했다면 Windows 플랫폼에서는 터미널 출력이 이렇게 됐을 거예요:

```plain
'SYSLOADFUNCS' is not recognized as an internal or external command,
operable program or batch file.
'SYSPI' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSSQRT' is not recognized as an internal or external command,
operable program or batch file.
'SYSDROPFUNCS' is not recognized as an internal or external command,
operable program or batch file.
```

Linux 플랫폼에서는 터미널 출력이 이렇게 됐을 거예요:

```plain
sh: SYSLOADFUNCS: command not found
sh: SYSPI: command not found
sh: SYSSQRT: command not found
sh: SYSSQRT: command not found
sh: SYSDROPFUNCS: command not found
```
