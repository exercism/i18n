# 구조체

구조체는 서로 다른 타입으로 이루어진 고정된 데이터 집합을 하나의 단위로 모아요. Rust의 구조체에는 다음과 같은 특징이 있어요:

- 모든 구조체 타입에는 고유한 이름이 있어요.
- 구조체의 각 멤버를 **필드**라고 해요.
- 구조체의 각 필드에는 고유한 이름이 있어요.
- 가시성은 필드 단위로 관리돼요: 각 필드는 각각 공개, 비공개 또는 그 밖의 다른 상태일 수 있어요[^1].

# 구조체 개요

구조체는 `struct` 키워드를 사용해 정의하며, 그 뒤에 구조체가 설명하는 타입의 이름을 써요.
이름 뒤에는 중괄호(일반 구조체), 괄호(튜플 구조체) 또는 세미콜론(유닛 구조체)이 올 수 있어요.

```rust
struct Item {}
```

그다음에는 각자 자신만의 타입을 가진 추가 타입들을 구조체 본문에 구조체의 _필드_ 로 넣어요:

```rust
struct Item {
    name: String,
    weight: f32,
    worth: u32,
}
```

마지막으로, 구조체에는 `impl` 블록 안에서 메서드를 정의할 수 있어요:

```rust
impl Item {
    // initializes and returns a new instance of our Item struct
    fn new() -> Self {
        todo!()
    }
}
```

# 구조체의 종류

구조체에는 세 가지 종류가 있어요: 이름 있는 필드를 가진 구조체(일반 구조체), 튜플 구조체, 유닛 구조체예요.

구조체는 **튜플**과 아주 비슷해요. 사실 구조체와 튜플의 유일한 차이는 무엇이 익명인지에 관한 것이에요. 일반적인 형태는 이렇게 생겼어요:

- 구조체는 이름이 있고 이름 있는 필드를 가져요:

  ```rust
  struct Foo {
      bar: Bar,
      bat: Bat,
  }
  ```

  필드는 이름으로 접근해요:

  ```rust
  let bar = foo.bar;
  ```

- 튜플 구조체는 이름이 있고 익명 필드를 가져요:

  ```rust
  Foo(Bar, Bat)
  ```

  필드는 구조 분해하거나 숫자 인덱스로 접근해요:

  ```rust
  // unpacking
  let (bar, bat) = foo;
  ```

  ```rust
  // numeric index
  let bar = foo.0;
  let bat = foo.1;
  ```

- 튜플은 익명이고 익명 필드를 가져요:

  ```rust
  (Bar, Bat)
  ```

  튜플 구조체와 마찬가지로, 필드는 구조 분해하거나 숫자 인덱스로 접근해요.

- 익명 구조체는 이름에서 알 수 있듯이 익명이지만, 필드에는 이름이 있어요. Go나 Java 같은 다른 언어에서 익숙할 수도 있어요. 익명 구조체는 Rust에는 존재하지 않아요. 대신 튜플을 사용하는 것이 관용적이에요.

# 제로 크기 타입

구조체는 필요한 만큼 필드를 많이 또는 적게 가질 수 있어요. 그 말은 곧 구조체가 필드를 하나도 갖지 않는 것도 허용된다는 뜻이에요. 필드가 하나도 없는 구조체를 **제로 크기 타입**이라고 하며, 컴파일러가 특별하게 다뤄요: 제로 크기 타입(흔히 **ZST**로 줄여요)은 스택이나 힙 공간을 전혀 차지하지 않아요, 그럴 거라고 예상되는 경우에도 마찬가지예요. 예를 들어 `T`가 ZST라면 `Box<T>`는 힙 메모리를 전혀 할당하지 않아요.

ZST를 작성할 때는 일반 구조체나 튜플 구조체 문법을 사용할 수 있어요:

```rust
// declaration
struct Foo {}
// instantiation
let foo = Foo {}
```

```rust
// declaration
struct Foo();
// instantiation
let foo = Foo();
```

ZST를 위한 축약형도 있어요:

```rust
// declaration
struct Foo;
// instantiation
let foo = Foo;
```

보통 ZST를 작성할 때는 축약형을 선호해요. 왜냐하면 섞어 쓸 수 없기 때문이에요: ZST를 선언할 때 사용한 스타일[^2]이 인스턴스를 만들 때도 똑같이 요구되는 스타일이에요.

ZST의 문법에 대해 이렇게 이야기했으니, 이제 이런 게 왜 필요할지 이야기해볼까요. ZST는 어떤 데이터도 저장할 수 없지만, 트레이트를 구현하기에는 아주 좋아요.

---

[^1]: [이 문서](https://doc.rust-lang.org/reference/visibility-and-privacy.html)는 덜 흔히 쓰이는 가시성 옵션 몇 가지를 설명해요.
[^2]: 이것은 일반 규칙의 특별한 사례예요: 어떤 구조체 타입을 선언할 때 사용한 스타일이 그 구조체의 인스턴스를 만들 때도 똑같이 요구되는 스타일이에요.
