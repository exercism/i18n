# 개요

스칼라 코드는 여러 명령어가 설정한 플래그에 의존해 특정 조건에 따라 분기해요.
그런데 패킹된 값은 하나가 아니라 여러 값을 병렬로 나타내요.
하나의 조건이 어떤 레인에서는 거짓이고 다른 레인에서는 참일 수 있죠.

그래서 SIMD 코드는 기본적으로 [분기 없는][branchless-code] 코드예요.

플래그에 의존하는 대신, 패킹된 비교는 보통 목적지 피연산자에 **마스크**를 만들어요.
각 레인마다, 비교 결과가 참이면 레인 전체를 1로 채우고 거짓이면 0으로 채워요.
부호 있는 정수로 읽으면 참인 레인은 `-1`, 거짓인 레인은 `0`이에요.

그러면 이 마스크를 [비트 연산][simd-bitwise]과 조합해 특정 레인만 걸러낼 수 있어요.

## 패킹된 비교

스칼라 `cmp`는 여러 플래그를 한꺼번에 설정한다는 점에서 범용적이에요.
그러면 다른 명령어가 그 플래그를 받아 분기하거나 계산을 수행할 수 있죠.

하지만 패킹된 비교는 조건을 검사하는 동시에 마스크를 계산하므로 범용적이지 않아요.
검사할 정확한 조건을 비교 명령어에 알려 줘야 하죠.

이를 위한 방법은 두 가지예요:

- 정수 비교는 조건을 접미사로 붙여요. 같음은 `eq`, 큼은 `gt`예요.
  다른 변형은 이 둘 중 하나의 결과를 조합해 만들어요.
- 부동소수점 비교는 조건을 즉시값에 담아 전달해요.
  이 즉시값의 값이 다르면 검사하는 조건도 달라져요.

정수 비교에 특정 조건 접미사를 쓴다는 점을 빼면, 문법은 앞서 본 것과 같은 구조를 따라요:

- 정수의 경우 `p` + `cmp` + 조건 + 크기(`b`, `w`, `d`, `q`)예요.
- 부동소수점의 경우 `cmp` + `p` + 크기(`s`, `d`)예요.
  조건은 추가 피연산자로 즉시값에 담겨 전달돼요.

### 정수 비교

앞서 말했듯이, 정수 비교에는 같음과 큼만 있어요:

| instruction                                | description                      |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | per-lane equality                |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | per-lane **signed** greater-than |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

작음 비교를 만들려면 피연산자를 바꿔서 `gt`를 사용해요: `a < b` == `b > a`.

비교가 **부호 있는** 비교라는 점에 주의해요.
부호 없는 비교를 하려면 두 피연산자의 최상위 비트를 뒤집어요.
최상위 비트만 설정된 마스크와 XOR하면 돼요.

~~~~exercism/note
유용한 관용구 두 가지가 있어요:

1. 레지스터를 자기 자신과 XOR해서 전부 0으로 만드는 것.
2. 레지스터를 자기 자신과 비교해서 전부 1로 만드는 것.

예를 들어:

```x86asm
pxor    xmm4, xmm4 ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

전부 0과 전부 1은 각각 "모두 거짓"과 "모두 참"을 나타내는 흔한 마스크예요.
또한 흔한 센티넬 값인 패킹된 `0`이나 패킹된 `-1`을 나타내는 데도 쓸 수 있어요.
예를 들어 문자열의 끝을 표시하는 NUL은 `0`이에요.
~~~~

### 부동소수점 비교

부동소수점 레인은 다른 형태를 써요. 명령어 하나, `cmpps`(64비트 레인은 `cmppd`)를 쓰고, 조건은 즉시값으로 전달해요:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM에는 올바른 즉시값으로 연결되고 기억하기 더 쉬운 의사 명령도 있어요.
다음에서 `px`의 `x`는 `s`(32비트 부동소수점) 또는 `d`(64비트 부동소수점)가 될 수 있어요:

| pseudo-op    | immediate | comparison             |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | a is NaN or b is NaN   |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | neither a nor b is NaN |

~~~~exercism/caution
NaN은 순서 없음으로 비교돼요. NaN은 자기 자신을 포함해 그 무엇과도 작지도, 같지도, 크지도 않아요.
`cmpltps` 같은 순서가 있는 조건자는 피연산자 중 하나라도 NaN이면 거짓을 내놓고, 순서가 없는 조건자는 참을 내놓아요.
`cmpordps`와 `cmpunordps`가 존재하는 이유가 바로 NaN인지 명시적으로 검사하기 위해서예요.
~~~~

## 마스크로 선택하기

마스크는 조건의 결과를 담아요.
그러면 그 조건에 따라 두 값 집합 중에서 레인별로 하나를 고르는 데 쓸 수 있어요.
마스크가 참인 레인은 한 값에서, 거짓인 레인은 다른 값에서 가져와요:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

이 패턴은 분기 없는 선택의 패킹된 형태예요.
모든 레인이 계산되고, 어디에도 `jcc` 없이 마스크만이 어떤 값이 살아남을지 결정해요.

## 전용 블렌드

마스크 레지스터에서 원소마다 한 비트씩 읽어 같은 선택을 직접 수행하는 명령어도 있어요.
이런 명령어를 **블렌드** 명령어라고 해요:

| instruction | element     | mask source     |
|-------------|-------------|-----------------|
| `pblendvb`  | byte        | implicit `xmm0` |
| `blendvps`  | 32-bit lane | implicit `xmm0` |
| `blendvpd`  | 64-bit lane | implicit `xmm0` |

첫 번째 명령어는 정수 문법을 따르고 나머지 둘은 부동소수점 문법을 따른다는 점에 주의해요.
하지만 이 명령어들은 그저 원시 바이트를 선택할 뿐이라 정수와 부동소수점 모두에 쓸 수 있어요.

원소마다, 블렌드는 대응하는 마스크 원소의 최상위 비트가 0이면 목적지를 유지하고, 1이면 출처를 가져와요.
참조하는 것은 그 **최상위 비트**뿐이고, 비교 마스크는 레인이 전부 1이거나 전부 0이라 이 조건을 만족해요.
마스크 레지스터는 항상 `xmm0`이고 이는 암시적이에요:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

`pblendvb`를 써서 다른 크기의 비교 마스크에서 레인을 선택할 수도 있어요.
참인 레인의 모든 바이트가 1이므로 `pblendvb`는 그 바이트를 전부 선택해요.

~~~~exercism/note
이 명령어들은 모두 수행하는 연산(`blend`) 뒤에 `v`를 붙여요.
이 `v`는 _variable_(가변)을 뜻하는데, 선택이 고정적이지 않고 레지스터에 의존하기 때문이에요.

`v`가 없는 변형도 있고, 이들은 즉시값에 따라 선택해요.
같은 패턴을 따라, 즉시값의 비트 `i`가 설정되어 있으면 레인 `i`를 선택해요.
~~~~

## 마스크에서 다시 스칼라로

강력하긴 하지만 SIMD 코드는 스칼라 코드의 유연성을 많이 갖추지 못했어요.
여러 상황에서 패킹된 레지스터에서 스칼라 명령어의 세계로 되돌아가야 해요.

`movmsk` 계열 명령어가 두 세계를 잇는 다리 역할을 해요.
이 명령어들은 모든 레인의 **최상위 비트**를 범용 레지스터로 추출해요:

| instruction | gathers                     | result width |
|-------------|-----------------------------|--------------|
| `pmovmskb`  | top bit of each of 16 bytes | 16 bits      |
| `movmskps`  | top bit of each of 4 dwords | 4 bits       |
| `movmskpd`  | top bit of each of 2 qwords | 2 bits       |

비교 후에 사용하면, 설정된 각 비트는 "참"인 레인을 나타내고 0으로 지워진 각 비트는 "거짓"인 레인을 나타내요.
그러면 이 결과를 평소처럼 스칼라 명령어로 다룰 수 있어요.
예를 들어 `popcnt`는 일치하는 개수를 세고, `tzcnt`는 첫 번째를 찾아요.

범용 레지스터는 32비트나 64비트 폭일 수 있어요.

## 벡터 전체 검사하기

스칼라 명령어 `test`에는 패킹된 변형도 있어요: `ptest`예요.

`ptest`는 두 피연산자 사이에 AND 연산을 수행하고 피연산자를 수정하지 않는다는 점에서 스칼라 짝과 비슷해요.
`test`와 달리 `ptest`는 첫 번째 피연산자를 부정하는 ANDN 연산도 수행해요.

따라서 `ptest`는 결과에 따라 플래그를 설정하는 `pand`와 `pandn`의 비파괴 버전이라고 볼 수 있어요.
이 두 명령어와 거의 같은 방식으로, `ptest`는 SIMD 레지스터 전체를 하나의 레인으로 취급하므로 크기 접두사를 붙이지 않아요.

AND 연산의 결과가 `0`이면 `ZF`가 설정되고, ANDN 연산의 결과가 `0`이면 `CF`가 설정돼요.
즉, `ptest`로 전부 1인 마스크와 전부 0인 마스크를 모두 검사할 수 있어요:

1. 레지스터에 자기 자신으로 `ptest`를 하면 레지스터가 전부 0일 때만 `ZF`가 설정돼요.
   이는 레지스터가 `0`인지 확인하려고 자기 자신에 `test`를 하는 흔한 스칼라 관용구를 흉내 낸 거예요.
2. 레지스터에 전부 1인 마스크로 `ptest`를 하면 레지스터가 전부 1일 때만 `CF`가 설정돼요.
   또한 레지스터가 전부 0일 때만 `ZF`가 설정되어, 두 마스크를 한 번에 검사할 수 있어요.

```x86asm
pxor  xmm0, xmm0   ; xmm0 = all zeros
ptest xmm0, xmm0   ; xmm0 AND xmm0 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm0 == 0 => CF is set

; Using ptest on a register with itself makes ZF set only if the register is all zeros

pcmpeqb xmm1, xmm1 ; xmm1 = all ones
ptest   xmm0, xmm1 ; xmm0 AND xmm1 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm1 != 0 => CF is cleared

pcmpeqb xmm3, xmm3 ; xmm3 = all ones
ptest   xmm3, xmm1 ; xmm3 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm3) AND xmm1 == 0 => CF is set

mov eax, -1
movd  xmm2, eax    ; xmm2 = {-1, 0, 0, 0}
ptest xmm2, xmm1   ; xmm2 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm2) AND xmm1 != 0 => CF is cleared

; After using ptest on a register with an all-ones mask, ZF is only set if the register is all zeros.
; CF may be:
; 1. cleared, if the register is all zeros or is partially set
; 2. set, if the register is all ones
```

`ptest`의 결과는 평소처럼 분기에 쓰거나 `setcc`, `cmovcc` 같은 분기 없는 명령어에 쓸 수 있어요.

## AVX와 그 이후

AVX는 비교, 블렌드, `ptest`에 더 넓은 레지스터에서 쓸 수 있는 `v` 접두사 형태를 줘요.

가변 블렌드는 형태가 바뀌어요.
마스크가 더 이상 암시적인 `xmm0`이 아니라 명시적인 네 번째 피연산자예요:

```x86asm
vpcmpgtd  ymm0, ymm1, ymm2       ; eight 32-bit lanes compared at once
vblendvps ymm0, ymm1, ymm2, ymm3 ; ymm3 is the mask, named explicitly
vptest    ymm0, ymm0
```

AVX-512 확장은 모델을 더 근본적으로 바꿔요.

먼저, `zmm`이라 불리는 64바이트 SIMD 레지스터의 새 부류를 추가해요.
이들은 `ymm` 레지스터가 `xmm` 레지스터를 확장하는 것과 같은 방식으로 대응하는 `ymm` 레지스터를 확장해요.

둘째, 이 확장은 `k0`부터 `k7`까지의 **opmask 레지스터**라는 완전히 새로운 부류도 만들어요. 이들의 주된 목적은 SIMD 명령어의 마스크로 쓰이는 거예요.
비교는 더 이상 벡터에 쓰지 않고 이 새로운 레지스터 중 하나에 써요.
또한 `{k}` 쓰기 마스크를 써서 많은 명령어에 조건자로 직접 사용해 레인을 _직접_ 선택할 수도 있어요:

```x86asm
vpcmpgtd  k1, zmm0, zmm1         ; k1 gets one bit per lane
vmovdqa32 zmm2{k1}, zmm3         ; copy only the lanes whose bits are set in k1
```

마지막으로, 이 새로운 레지스터를 다루는 새 명령어가 있어요. 범용 레지스터로 복사하는 것도 포함돼요.
덕분에 `movmsk` 명령어는 불필요해졌고, `zmm` 레지스터에는 `movmsk` 명령어를 지원하지 않아요.

이 확장들은 완전성을 위해 언급했어요.
이 트랙의 연습 문제들은 SSE 형태를 사용해요.
