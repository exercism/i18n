# 추상 클래스

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## `$`는 이름의 일부예요

모든 추상 클래스의 이름은 맨 앞에 `$`가 붙어요. 그리고 `$`가 붙는 것은 추상 클래스뿐이에요. 그래서 `$`로 시작하는 타입은 객체를 만들 수 없는 타입이고, 이 사실은 이름이 나타나는 곳마다 그대로 드러나요.

## 무엇이 들어갈 수 있을까요

루틴과 이터레이터의 시그니처만 들어가고, 세미콜론에서 끝나요. 본문도, 속성도, `create`도 없어요. 추상 클래스는 어떤 대상에게 무엇을 *물어볼* 수 있는지만 설명하고, 그 대상이 무엇을 담고 있는지는 설명하지 않아요.

## 적합성

```sather
class TRAPEZE < $ACT is
```

클래스는 나열된 모든 루틴을 인자 타입과 반환 타입까지 맞춰서 정의해야 해요. 이는 컴파일할 때 검사해요.

클래스는 여러 클래스에 적합할 수 있어요:

```sather
class TRAPEZE < $ACT, $RISKY is
```

그리고 추상 클래스는 서로를 확장할 수 있어요:

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## 디스패치가 일어나는 곳

추상 타입의 변수는 그 타입에 적합한 어떤 객체에 대한 참조를 담아요. 그 변수로 루틴을 호출하면 런타임에 그 객체의 실제 클래스에 속한 버전이 선택돼요.

Sather가 런타임에 무언가를 결정하는 곳은 여기 한 곳뿐이에요. 구체 타입의 변수에 대한 호출은 컴파일할 때 정해져요.

## typecase

때로는 종류가 정말 중요할 때가 있어요. `typecase`는 이렇게 물어요:

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

분기 안에서는 변수가 더 좁은 타입을 가져요. 하지만 좀처럼 쓸 일이 없어요. 온갖 종류의 act를 대상으로 하는 `typecase`는 보통 처음부터 추상 클래스에 있었어야 할 루틴이거든요.

## $OB

`$OB`는 모든 객체가 적합하는 추상 클래스예요. 가끔은 유용하지만, 대개는 어딘가에서 타입을 잃어버렸다는 신호예요.

## 상속을 쓰지 않는 이유는요?

Sather는 대부분의 언어가 붙여 놓은 두 가지를 분리해요. `<`는 클래스가 무엇을 *할 수 있는지*만 말해요. 구현을 다른 곳에서 가져오는 것은 `include`이고, 이건 그다음다음에 나오는 연습 문제에서 다루는데, 별개의 결정이에요.
