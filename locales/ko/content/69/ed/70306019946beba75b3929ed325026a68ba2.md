# 지시 사항

자동차 부품 공장 현장의 데이터 시스템을 위한 코드를 작성해요.
엔진과 섀시 부품은 일련의 가공 스테이션을 거쳐 이동해요.
각 스테이션은 측정값을 만들어 내는데, 다음 단계가 실행되기 전에 이 값들을 결합하거나 비교하거나 보정하거나 정규화해야 해요.
여기서 구현할 함수는 스테이션마다 하나씩이에요.

~~~~exercism/note
이 연습 문제의 계산은 스칼라 연산이 아니라 SIMD 명령어를 사용해서 수행해야 해요.
~~~~

## 1. 두 라인의 생산량 합치기

공장 현장에서는 나란히 돌아가는 두 개의 조립 라인이 있어요.
각 교대 근무가 끝날 때마다 두 라인 모두 부품 4개 구간의 생산량을 단정밀도 숫자로 보고해요.
관리자 대시보드는 구간별로 합쳐진 생산량을 보여주기 때문에, 두 보고 값은 구간별로 더해져요.
세 버퍼는 모두 보고 시스템이 관리하며 항상 16바이트로 정렬되어 있어요.

`line_a`와 `line_b`의 구간별 생산량이 주어졌을 때, 구간별 합을 `result`에 쓰는 `sum_yields` 함수를 정의해요.
인자는 순서대로 다음과 같아요:

1. `line_a`: 32비트 부동소수점 숫자 4개를 담고 있는 16바이트로 정렬된 메모리 주소
2. `line_b`: 32비트 부동소수점 숫자 4개를 담고 있는 16바이트로 정렬된 메모리 주소
3. `result`: 함수가 32비트 부동소수점 숫자 4개를 쓸 16바이트로 정렬된 메모리 주소

이 함수는 반환 값이 없고, 대신 결과는 전달받은 버퍼(`result`)에 저장돼요:

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. 조정된 편차 계산하기

작업 사이사이에 샘플링 스테이션이 가공된 부품을 측정하고 목표 치수와 비교해요.
측정값은 정밀 게이지에서 항상 16바이트로 정렬된 버퍼로 흘러 들어와요.
목표 값은 작업 지시 패킷에서 오는데, 이 패킷은 정렬이 보장되지 않아요.
편차는 하위 공정의 공차 검사기로 전달되기 전에 축별 민감도 계수와 곱해져요.
이 단계에서 하위 공정 검사기는 메모리가 아니라 SIMD 레지스터에서 편차를 직접 읽어요.

`measured`와 `target`, 그리고 `sensitivity`가 주어졌을 때 조정된 편차를 `result`에 쓰는 `scaled_deviation` 함수를 정의해요.
인자는 순서대로 다음과 같아요:

1. `measured`: 64비트 부동소수점 숫자 2개를 담고 있는 16바이트로 정렬된 메모리 주소
2. `target`: 64비트 부동소수점 숫자 2개를 담고 있는 메모리 주소(정렬 보장 안 됨)
3. `sensitivity`: 64비트 부동소수점 숫자 2개를 담고 있는 메모리 주소(정렬 보장 안 됨)
4. `result`: 함수가 64비트 부동소수점 숫자 2개를 쓸 버퍼의 메모리 주소(정렬 보장 안 됨)

조정된 편차는 레인별로 `(measured - target) * sensitivity`예요.

이 함수는 반환 값이 없고, 대신 결과는 64비트 부동소수점 숫자 한 쌍으로 전달받은 버퍼(`result`)에 저장돼요.

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. 배치 보정하기

부품이 최종 검사 구역에 들어가기 전에, 부품 4개로 이루어진 배치의 치수 판독값을 배정밀도로 다시 스케일링하고 알려진 온도 드리프트를 보정해요.

4개의 원시 판독값은 단정밀도 숫자로 들어와요.
판독값 2개로 이루어진 각 행에 대해, 보정은 `reference / (raw - offset)`을 계산한 다음 이 결과에 상수 변환 계수 `0.5`를 곱해요.

참고로 reference와 offset은 배치의 두 행 모두에 대해 같아요.
변환 계수는 모든 보정에서 같기 때문에, 인자로 받는 대신 메모리에 16바이트로 압축된 상수로 선언해야 해요.

`raw` 배치, `reference`, `offset`, `result` 버퍼가 주어졌을 때 보정된 값들을 `result`에 쓰는 `calibrate_batch` 함수를 정의해요.
인자는 순서대로 다음과 같아요:

1. `raw`: 32비트 부동소수점 숫자 4개를 담고 있는 메모리 주소(정렬 보장 안 됨)
2. `reference`: 64비트 부동소수점 숫자 2개를 담고 있는 16바이트로 정렬된 메모리 주소
3. `offset`: 64비트 부동소수점 숫자 2개를 담고 있는 16바이트로 정렬된 메모리 주소
4. `result`: 함수가 64비트 부동소수점 숫자 4개(총 32바이트)를 쓸 16바이트로 정렬된 메모리 주소

이 함수는 배치의 두 행 각각에 대해 다음을 수행해야 해요:

1. 행의 단정밀도 원시 값 2개를 배정밀도로 변환해요.
2. 변환된 쌍에서 `offset`을 빼요.
3. `reference`를 그 결과로 나눠요.
4. 각 64비트 부동소수점 숫자에 고정 변환 계수 `0.5`를 레인별로 곱해요.
5. 64비트 부동소수점 숫자 2개를 `result`의 해당하는 16바이트에 저장해요.

이 함수는 반환 값이 없고, 대신 결과는 전달받은 버퍼(`result`)에 저장돼요:

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. 라인을 따라 점수 정규화하기

라인 끝에서 모든 부품은 품질 점수를 가지는데, 이 점수는 보고되기 전에 정규화되어야 해요.
각 점수는 부품별 자체 게인과 곱해진 다음, 축별 생산 스케일로 나눠져요.
게인 버퍼는 부품마다 게인을 하나씩 담고 있어요.

생산 스케일은 전체 실행에 대해 같으며, 64비트 부동소수점 숫자 두 개를 담고 있는 메모리 주소로 전달돼요.
점수는 **제자리에서** 갱신돼요: 원시 점수를 담고 있던 바로 그 버퍼가 이제 정규화된 점수를 담아요.

`scores` 배열, `gains` 배열, `scale`, 그리고 개수 `n`이 주어졌을 때 점수를 제자리에서 정규화하는 `normalize_scores` 함수를 정의해요.
인자는 순서대로 다음과 같아요:

1. `scores`: `n`개의 64비트 부동소수점 숫자를 담고 있는 16바이트로 정렬된 메모리 주소(제자리에서 수정됨)
2. `gains`: `n`개의 64비트 부동소수점 숫자를 담고 있는 16바이트로 정렬된 메모리 주소
3. `scale`: 64비트 부동소수점 숫자 2개를 담고 있는 16바이트로 정렬된 메모리 주소
4. `n`: 64비트 양의 짝수 정수(최솟값 `2`)로, 정규화할 점수의 개수예요

두 스케일 레인은 각 쌍의 두 원소에 적용돼요.
첫 번째 레인은 모든 쌍의 첫 번째 원소(짝수 위치의 레인)를 스케일링하고, 두 번째 레인은 두 번째 원소(홀수 위치의 레인)를 스케일링해요.
각 점수는 그에 대응하는 게인과 곱해진 다음, 알맞은 스케일 레인으로 나눠져요: `score * gain / scale_lane`.

이 함수는 반환 값이 없고, 대신 결과는 입력 버퍼(`scores`)에서 정규화된 해당 `score`와 같은 위치에 저장돼요:

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
