# 소개

## 튜플

엘릭서에서 튜플은 데이터를 정리하는 자료 구조예요. 어떤 타입의 항목이든 정해진 개수만큼 담을 수 있지만, 각 원소에 이름이 따로 붙지는 않아요. 튜플은 엘릭서에서 메모리를 많이 읽는 연산에 자주 쓰여요. 원소를 읽는 데 걸리는 시간이 항상 일정하기 때문이에요. 반대로 원소를 동적으로 추가하거나 제거해야 할 때는 보통 튜플을 쓰지 않아요. 기존 튜플을 수정하는 대신 새 튜플을 만들어야 하고, 그러려면 메모리를 미리 할당해 두어야 하기 때문이에요.

실제로 엘릭서에서 튜플은 중괄호로 만들어요. 튜플의 원소는 `elem/2` 함수로 하나씩 접근할 수 있는데, 인덱스는 0부터 시작해요:

```elixir
empty_tuple = {}
one_element_tuple = {1}
multiple_element_tuple = {1, :a, "hello"}

elem(multiple_element_tuple, 2)
# => "hello"
```

### 정보를 묶어 표현하는 튜플

실제로는 여러 정보를 하나로 묶어 표현할 때 튜플을 자주 사용해요.

```elixir
Float.ratio(0.25)
# => {1, 4} indicating the numerator and denominator of the fraction ¼
```

## 패턴 매칭

단언적인 관용 엘릭서 코드에서는 패턴 매칭이 특히 많이 쓰여요. `=/2`는 대입 연산자가 아니라 매치 연산자라고 설명한다는 점을 기억하고 있을 거예요. 매치 연산자를 쓸 때 왼쪽의 패턴이 오른쪽과 매치되면 왼쪽의 변수들이 바인딩되고, 오른쪽의 값이 반환돼요. 매치되지 않으면 `MatchError`가 발생해요.

```elixir
2 = 2
# => 2
# Literals can be matched if they are the same

2 = 3
# => ** (MatchError) no match of right hand side value: 3

{_, denominator} = Float.ratio(0.25)
# => {1, 4}
# the variable `denominator` is bound to the value 4
```

매치는 오른쪽에서 왼쪽으로 일어난다는 걸 기억해요.

마지막 예제에서 패턴 매칭에 변수가 필요 없다면 `_`를 써서 그 자리를 버릴 수 있어요. `_`로 시작하는 변수는 런타임이 추적하지 않아요.

### 이름 있는 함수에서의 패턴 매칭

패턴 매칭은 여러 개의 함수 절을 만들 때도 유용한 도구예요. 함수의 인자에 패턴 매칭을 사용할 수 있는데, 이렇게 하면 어떤 함수 절을 실행할지가 정해져요. 파일 위에서부터 아래로 내려가면서 처음 매치되는 절이 선택돼요. 변수는 함수 헤드에서 바인딩하고 함수 본문에서 사용할 수 있어요.

```elixir
defmodule Example do
  def named_function(:a = variable_a) do
    {variable_a, 1}
  end

  def named_function(:b = variable_b) do
    {variable_b, 2}
  end
end

Example.named_function(:a)
# => {:a, 1}

Example.named_function(:b)
# => {:b, 2}

Example.named_function(:c)
# => ** (FunctionClauseError) no function clause matching in Example.named_function/1
```
