# 자세히 알아보기

## 표현 방식, 문자, 정수

다른 단순 타입(`int`, `bool` 등)과 마찬가지로 `char`에도 짝이 되거나 별칭이 되는 타입이 있어요. 여기서는 `System.Char`예요.

사실 이 타입은 16비트 필드를 가진 `struct`이고, 기본적으로 불변이에요.

`char`에는 `Equals`, `ToString`, [`CompareTo`][compare-to] 같은 인스턴스 메서드가 있어요.

`char`는 [`ushort`][uint16]와 크기가 같지만, 일부 언어에서처럼 이 둘을 서로 바꿔서 쓰지는 않아요. `ushort`는 `char`로 명시적으로 캐스팅해야 해요.

참고로 `char`에는 산술 연산을 적용할 수 있어요. 이런 연산의 결과는 정수예요.

당연히 8비트인 `byte`와 16비트인 `char` 사이에는 같다는 관계가 성립하지 않아요.

## 사용법

`char`는 대체로 사용하기 쉬워요.

작은따옴표로 리터럴을 정의할 수 있어요:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

문자열에서 (0부터 시작하는) 인덱싱으로 개별 `char`를 꺼낼 수 있어요:

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

문자열을 반복하면 각 단계마다 `char`가 반환돼요:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

위에서 보았듯이 `char`는 자신의 `int` 값으로 캐스팅할 수 있어요.
다른 문자 체계에서도 (*적어도 때로는*) 잘 동작해요:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

문자를 비교할 때는 내부의 Int16 값이 사용돼요:

```fsharp
'A' < 'D'
// => val it: bool = true
```

`int`를 `char`로 캐스팅할 수도 있어요:

```fsharp
char 77
// => val it: char = 'M'
```

`System.Char` 라이브러리에는 .NET 언어에 기대되는 [메서드][Char-methods]가 모두 들어 있어요. 대소문자 변환 같은 것들이죠(다만 다음 섹션의 주의 사항도 살펴보세요):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

.NET 라이브러리는 문자열에서 `char`를 추출하는 데도 도움을 줘요. 여기서는 `Seq` 메서드를 사용해 볼게요:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

문자 리스트(또는 배열)를 문자열로 변환하는 방법은 여러 가지가 있어요. 다음은 그중 몇 가지예요:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

`char`에 대한 일반적인 정보는 여기에서 찾을 수 있어요:

- [Chars 문서][chars-docs]: `char`에 대한 참조 문서예요.

하지만 `char`에는 아래에서 자세히 설명하듯 여러 가지 거친 부분이 있어요. 이런 부분은 대부분 한쪽의 완전한 유니코드 표준과, 다른 쪽의 텍스트에 대한 역사적 표현 방식, 그리고 성능과 메모리 사용량 사이의 대립과 관련이 있어요.

## 유니코드 관련 문제

문자열을 다룰 때 [`System.String`][System-string] 라이브러리 메서드를 사용할 수 있다면, 문자열을 문자 단위로 쪼개기보다 그런 메서드를 찾아서 쓰는 게 좋아요.

유니코드 표준에는 65536개가 넘는 코드 포인트가 있기 때문에, 어떤 텍스트 "문자"는 `char` 하나로 이루어지지 않아요. 예를 들어 일부 테스트에 등장하는 이모지는 [서로게이트][surrogates] 문자로 이루어져 있어서 `char`가 2개예요.

또한 결합 시퀀스도 있어요. 예를 들어 어떤 경우에는 악센트가 붙은 문자가 기본 문자의 `char` 하나와 악센트의 `char` 하나로 이루어질 수 있어요.

개별 문자를 다뤄야 한다면 '0'과 '9' 사이에 있는지 확인하는 식의 순진한 비교 대신 [`System.Char.IsControl`][is-control], [`System.Char.IsDigit`][is-digit] 같은 라이브러리 메서드를 사용해 보세요.

예를 들어 '٢'는 아라비아 숫자 2예요. `IsDigit`는 아라비아 숫자에 대해서도 true를 반환하므로, 입력을 검증할 때 어떤 범위의 입력을 허용할지 분명히 정해야 해요.

심지어 `System.Char` 라이브러리 메서드도 생소한 언어를 다룰 때는 기대한 대로 동작하지 않을 수 있어요.

문자열을 화면에 보이는 "문자" 단위로 안전하게 나누는 한 가지 방법은 [`StringInfo`][string-info]와 [`GetNexttextElement`][get-next-text-element] 같은 메서드를 사용하는 거예요.
세계화/지역화를 다룰 때는 이게 필요할 수도 있어요.

유니코드 문자의 스칼라 값이 중요한 경우(예를 들어 직접 인코딩 시스템을 만드는 경우)에는 [룬][runes]을 사용하는 방법도 있어요. 하지만 다루는 문자의 범위에 서로게이트나 결합 문자 시퀀스가 포함되지 않고(예: 라틴 ASCII) 입력이 잘 검증되어 있다면 이 방법은 피할 수 있어요.

다시 말하지만 가장 좋은 상황은 `String`의 라이브러리 메서드를 사용할 수 있는 경우예요.

유니코드의 세부 사항까지 다뤄야 하는 곤란한 상황에 놓였다면 [이 문서][char-encoding-net]가 좋은 출발점이에요.

## 세계화

여러 문화권을 다루는 환경에서 작업하거나, 코드의 일부에서는 문화권이 중요하지만 다른 부분에서는 그렇지 않은 경우에는 [`ToUpper`][to-upper]와 [`ToLower`][to-lower] 중 문화권을 받는 오버로드와, 현재 [문화권][culture-info]과 무관하게 일관된 결과를 주는 [`ToUpperInvariant`][to-upper-invariant], [`ToLowerInvariant`][to-lower-invariant]를 잘 알고 있어야 해요.
