# 지침

이 연습 문제는 로그 파일 파싱을 다뤄요.

최근 보안 검토 이후, 조직에서 보관 중인 로그 파일을 정리해 달라는 요청을 받았어요.

메서드에 전달되는 모든 문자열은 null이 아니며 앞뒤에 공백이 없다고 보장돼요.

## 1. 손상된 로그 줄 식별하기

보관된 로그 중에서 현재 표준을 따르지 않는 줄이 얼마나 되는지 대략 알아야 해요. 간단한 검사만으로 로그 줄이 유효한지 알 수 있다고 생각해요. 유효하다고 인정되려면 줄이 다음 문자열 중 하나로 시작해야 해요:

- [TRC]
- [DBG]
- [INF]
- [WRN]
- [ERR]
- [FTL]

문자열이 유효하지 않으면 `false`를, 그렇지 않으면 `true`를 반환하도록 `LogParser.IsValidLine()` 메서드를 구현해요.

```csharp
var lp = new LogParser();
lp.IsValidLine("[ERR] A good error here");
// => true
lp.IsValidLine("Any old [ERR] text");
// => false
lp.IsValidLine("[BOB] Any old text");
// => false
```

## 2. 로그 줄 분리하기

새로운 팀이 조직에 합류했는데, 그 팀의 로그 파일은 "필드"를 구분할 때 이상한 구분자를 사용하고 있어요. 콜론(":")처럼 합리적인 무언가 대신 "<--->"나 "<=>" 같은 문자열을 써요 (더 예뻐 보이니까요). 사실 첫 문자가 "<"이고 마지막 문자가 ">"이면서, 그 사이에 "^", "\*", "=" 그리고 "-"가 어떤 조합으로든 들어 있는 문자열이면 무엇이든 돼요.

한 줄을 받아서 각각 필드 하나를 담은 문자열 배열을 반환하는 `LogParser.SplitLogLine()` 메서드를 구현해요.

```csharp
var lp = new LogParser();
lp.SplitLogLine("Section 1<===>Section 2<^-^>Section 3");
// => {"Section 1", "Section 2", "Section 3"}
```

## 3. 따옴표로 묶인 비밀번호가 포함된 줄 개수 세기

팀은 따옴표로 묶인 텍스트에 나타나는 비밀번호를 알아야 해요. 그래야 수동으로 검토할 수 있어요.

`LogParser.CountQuotedPasswords()` 메서드를 구현해서 수동 작업의 예상 규모를 가늠할 수 있게 해요.

리터럴 문자열 "password"가 대소문자 어떤 조합으로든 나타날 수 있으며, 큰따옴표로 둘러싸인 로그 줄을 찾아내요. 큰따옴표 안에서 "password" 앞뒤에 다른 내용이 있을 가능성도 고려해야 해요.

이 메서드에 전달되는 줄은 1번 작업에서 정의한 대로 유효할 수도 있고 그렇지 않을 수도 있어요. 유효 여부와 상관없이 같은 방식으로 처리해요.

```csharp
string lines =
    "[INF] passWord " + Environment.NewLine + // contains 'password' but not surrounded by quotation marks
    "\"passWord\"" + Environment.NewLine + // count this one
    "[INF] User saw error message \"Unexpected Error\" on page load." + Environment.NewLine + //does not contain 'password'
    "[INF] \"The secret password was added by the user\""; // count this one

var lp = new LogParser();
lp.CountQuotedPasswords(lines);
// => 2
```

## 4. 로그에서 불필요한 잔여물 제거하기

로그를 처리하는 상위 단계 어딘가에서 "end-of-line" 뒤에 줄 번호가 (사이에 공백 없이) 붙은 텍스트를 로그 전체에 흩뿌리고 있다는 걸 발견했어요.

문자열을 받아서 end-of-line 텍스트를 제거하고 "깨끗한" 문자열을 반환하는 `LogParser.RemoveEndOfLineText()` 메서드를 구현해요.

end-of-line 텍스트가 없는 줄은 그대로 반환해야 해요.

end-of-line 문자열만 제거해요. 공백을 조정하려고 하지 마세요.

```csharp
var lp = new LogParser();
lp.RemoveEndOfLineText("[INF] end-of-line23033 Network Failure end-of-line27");
// => "[INF]  Network Failure "
```

## 5. 죄지은 사람이 처벌받도록 매우 취약한 비밀번호가 있는 줄을 나열하기

파일에서 비밀번호를 삭제하기 전에, 비밀번호가 "password"라는 텍스트로 시작하는 모든 경우를 나열해야 해요.

문제가 되는 비밀번호를 먼저 출력하고 그 뒤에 전체 줄을 출력하도록 `LogParser.ListLinesWithPasswords()` 메서드를 구현해요.

따옴표로 묶인 비밀번호가 있는 줄은 이미 제거되었고, 줄이 유효한지 여부와 상관없이 처리해요 (1번 작업에서처럼).

문제가 되는 비밀번호가 있는 줄은 "<password>: "가 앞에 붙은 채로 반환해야 해요.

문제가 되는 비밀번호가 없는 줄은 "--------: "가 앞에 붙은 채로 반환해야 해요.

```csharp
var lp = new LogParser();
lp.ListLinesWithPasswords(new string[] {"my passwordsecret is great"});
// => "passwordsecret: my passwordsecret is great"
lp.ListLinesWithPasswords(new string[] {"my password secret"});
// => {"--------: my password secret"}

```
