# 개요

Factor의 I/O는 어떤 데이터 원본이나 출력 대상이든 구현할 수 있는 하나의 [프로토콜][stream-protocol] 위에 세워져 있어요. 기본으로 함께 제공되는 스트림, 즉 `<file-reader>`, `<file-writer>`, `<string-reader>`, `<string-writer>`, 네트워크 소켓, 바이트 배열, tty는 모두 [`io`][io]에서 가져온 몇 가지 제네릭을 똑같이 구현하고, [`destructors`][destructors]의 `disposable`을 확장한 클래스예요.

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe`는 저수준 일괄 읽기예요. 호출하는 쪽에서 넘겨준 버퍼를 채우고, 원소를 몇 개나 썼는지 반환해요. 공개된 단어인 `stream-read`와 `stream-read-partial`은 이 위에 만들어져 있고 할당도 처리해요. 사용자가 정의한 스트림은 대부분 `stream-read1`(한 번에 원소 하나씩 읽는 경우)이나 `stream-read-unsafe`(읽기를 모아서 처리할 수 있는 경우) 둘 중 하나를 구현해요.

`stream-element-type`은 두 개의 싱글턴 토큰 중 하나를 반환해요. 바이트 스트림(파일 리더, 소켓)에는 `+byte+`, 문자 스트림(문자열 리더, tty)에는 `+character+`예요. 래퍼 스트림은 보통 기반 스트림에 그대로 위임하기만 해요.

## 믹스인에 참여하기

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

클래스는 둘 중 하나일 수도, 둘 다일 수도 있어요. 믹스인에 참여하면 `input-stream` / `output-stream`의 기본 메서드가 정의한 클래스로 디스패치돼요. `sets` 보캡의 `set`과 같은 오픈 믹스인 패턴이에요.

## disposable 프레임워크

`new-disposable ( class -- disposable )`은 새 인스턴스를 현재 소멸자 스코프에 등록해서, 리소스를 설정하다가 중간에 예외가 발생해도 깔끔하게 정리되도록 해요.

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose`는 공개된 단어이고, `dispose*`는 클래스가 구현하는 제네릭이에요. 하위 클래스에서 `dispose*`를 재정의할 때는 자신의 상태를 먼저 정리한 다음, 자신이 소유한 리소스를 해제해야 해요.

```factor
M: my-stream dispose* underlying>> dispose ;
```

프레임워크는 객체마다 `dispose*`가 많아야 한 번만 실행된다는 것을 보장해요. `dispose`를 반복해서 호출해도 아무 동작도 하지 않아요.

## 스코프 접근자

세 개의 컴비네이터가 `print`, `read1` 등에서 사용하는 전역 "현재 입력/출력 스트림"을 설정해요.

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

각 컴비네이터는 빠져나갈 때 리소스를 해제해요. 쿼테이션이 예외를 던져도 마찬가지예요. 대부분의 코드는 사용자 정의 스트림을 모든 호출에 넘겨주는 대신 이 컴비네이터들을 통해 사용해요.
