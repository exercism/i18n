# 개요

Factor의 스레드는 단일 OS 스레드 위에서 동작하는 *협력적 코루틴*이에요.
스레드는 스스로 실행을 양보하거나 블로킹 I/O를 수행할 때까지 실행되고,
그 시점에 스케줄러가 실행 가능한 다른 스레드를 골라요. 여기서 두 가지를
알 수 있어요:

- 양보 지점 사이에 있는 코드는 사실상 원자적이에요.
- 진정한 멀티코어 병렬 처리는 표준 `threads` vocab을 벗어나야 가능해요
  (예: 멀티 프로세스 설계를 위한 `concurrency.distributed`).

표준 동시성 기본 요소들은 계층을 이뤄요:

| Vocab                       | 제공하는 것                            |
|-----------------------------|----------------------------------------|
| [`threads`][threads]                   | `spawn`, `yield`, 스레드 식별자        |
| [`concurrency.promises`][concurrency.promises]      | `<promise>`, `fulfill`, `?promise`     |
| [`concurrency.locks`][concurrency.locks]         | `<lock>`, `with-lock`                  |
| [`concurrency.combinators`][concurrency.combinators]   | `parallel-map`, `parallel-each`        |
| [`concurrency.semaphores`][concurrency.semaphores]    | `<semaphore>`, `acquire`, `release`    |
| [`concurrency.mailboxes`][concurrency.mailboxes]     | 스레드별 우편함, `send`, `receive`     |
| [`concurrency.channels`][concurrency.channels]      | 랑데부 핸들, `to`, `from`              |

```factor
USING: concurrency.combinators concurrency.locks
concurrency.promises kernel sequences threads ;

! parallel-map: fork-join, in order
{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }

! spawn + promise: hand-rolled fork-join
<promise> [
    [ "hello, world" swap fulfill ] curry "greeter" spawn drop
] keep ?promise .   ! => "hello, world"

! <lock> + with-lock: protect a shared mutable slot
<lock> :> guard
guard [ "do thing under lock" drop ] with-lock
```

`parallel-map`은 고수준 API이고, 관용적인 Factor 코드가 가장 먼저
손을 뻗는 도구예요. `spawn` / `<promise>` / `?promise` 조합은
`parallel-map`을 이루는 재료죠. 반복 형태가 map에 맞지 않을 때
유용해요 (예: 다른 채널로 응답을 주고받는 워커를 띄울 때).

락은 *공유 가변 상태*를 보호해요. 보통 둘 이상의 스레드가 읽거나 쓰는
튜플 슬롯이나 해시테이블이죠. 비원자적인 복합 갱신이 있다면 읽기와 쓰기
모두 락이 필요하다고 봐요. 어느 한쪽이든 락을 빠뜨리면 읽는 도중 값이
뒤섞이는 전형적인 원인이 돼요.
