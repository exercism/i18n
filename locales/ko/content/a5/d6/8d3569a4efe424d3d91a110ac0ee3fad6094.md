# 소개

지금까지 본 대부분의 시퀀스 워드는 *새로운* 시퀀스를 반환하고 입력은 그대로 둬요. `suffix`, `reverse`, `map` 등이 그렇죠. 그런데 배열과 벡터는 **제자리 변경**도 지원해요. 시간에 따라 변하는 상태를 기록하고 싶을 때는 이 둘 다 등장해요.

## 변경 가능한 시퀀스의 두 가지 종류

- **배열**(`{ … }`)은 길이가 고정되어 있어요. `arrays`에 있는 `<array> ( n elt -- array )`는 `elt`의 복사본으로 채워진 길이 `n`의 새 배열을 만들어요.
- **벡터**(`V{ … }`)는 늘어나고 줄어들어요. 새로 빈 벡터를 만들려면 `V{ } clone`을 사용해요. `vectors`에 있는 `<vector> ( n -- vector )`는 `n`개 요소를 위한 용량을 미리 할당해요.

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## 슬롯 바꾸기

이 두 워드는 두 종류의 시퀀스 모두에서 동작해요. 둘 다 인덱스 뒤에 시퀀스가 오기를 기대하죠.

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

`set-nth`는 값을 할당하고, `change-nth`는 위치 `n`의 요소에 콰테이션을 적용해요. 이 [`sequences`][sequences] 워드 둘 다 스택에 아무것도 반환하지 않아요. 변경 자체가 효과예요.

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## 늘리고 줄이기

이 세 워드는 배열은 길이를 바꿀 수 없으니 벡터에서만 의미가 있어요.

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## 벡터 → 배열

벡터를 쌓아 올렸고 길이가 고정된 배열로 돌려주고 싶다면, `arrays`에 있는 `>array ( seq -- array )`가 같은 요소를 담은 새 배열을 반환해요.

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`으로 스냅샷 남겨 두기

변경은 시퀀스를 제자리에서 수정해요. 호출자가 시퀀스를 넘겨줬는데 그걸 바꾸려고 한다면, `kernel`에 있는 `clone`이 독립적인 새 복사본을 만들어 줘서 호출자가 보는 내용이 발밑에서 바뀌지 않아요.

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

같은 주의가 `V{ }`와 다른 빈 리터럴에도 적용돼요. 어떤 언어에서는 `[]`나 `vec![]`가 표현식이 평가될 때마다 새 컨테이너를 할당해요. Factor에서는 소스에 적은 `V{ }` 리터럴이 *하나의* 객체이고, 그걸 언급하는 모든 호출 지점이 이를 공유해요. `V{ }`에 직접 `push`하면 다음 호출에서 남은 것들이 보여요. `V{ } clone`이 거의 항상 원하는 새 복사본을 만들어 줘요.
