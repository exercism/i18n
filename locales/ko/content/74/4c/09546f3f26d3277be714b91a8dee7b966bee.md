# 소개

## 부분 적용

Elm의 모든 함수는 [커링][currying]되어 있어요. 그래서 인자를 모두 전달하지 않고 함수를 호출하면 새로운 함수가 반환돼요.

이렇게 하는 것을 [부분 적용][partial-application]이라고 해요. 함수에 모든 인자를 전달하는 게 아니라 일부만 적용하는 거예요.

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

부분 적용은 항상 인자를 순서대로 적용해요.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## 파이프 연산자 (`|>`)

`x |> f`는 `f x`와 정확히 같아요. 구체적인 예로, `"5" |> String.toInt`는 `String.toInt "5"`와 같아요.

처음에는 그다지 유용해 보이지 않지만, "파이프라인" 코드를 작성할 수 있게 해 주기 때문에 [파이프 연산자][pipe-operator]라고 불러요.

예를 들어, 사용자 입력을 정수로 바꿔 주는 sanitize 함수가 있다고 해봐요.

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

이렇게 다시 쓸 수 있어요.

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

이렇게 하면 괄호를 쓰지 않아도 되고, 함수가 적용되는 순서(먼저 `String.trim`, 그다음 `String.toInt`)를 그대로 보여 주기 때문에 읽기가 더 쉬워요.

[역방향 파이프 연산자 `(<|)`][reverse-pipe-operator]도 있어요.
`f <| x`는 `f x`와 정확히 같아요.
이것도 언뜻 보기에는 별로 유용해 보이지 않고, 파이프 연산자만큼 자주 쓰이지는 않지만, 어떤 상황에서는 괄호를 피하는 데 도움이 돼요.

## 함수 합성 / 포인트 프리 스타일

[`(>>)`][forward-composition] 연산자는 타입이 `(a -> b) -> (b -> c) -> (a -> c)`이고, 타입이 `a -> b `인 함수와 `b -> c`인 함수를 합성해서 타입이 `a -> c`인 함수를 만들어요.
첫 번째 함수의 출력(타입 `b`)을 가져와서 두 번째 함수(같은 타입 `b`여야 해요)의 첫 번째 인자로 사용하는 방식으로 동작해요.
만들어진 함수는 첫 번째 함수와 같은 입력(타입 `a`)을 받고, 두 번째 함수가 반환하는 `c`를 그대로 반환해요.

구체적인 예로 `String.trim >> String.toInt`가 있어요.
`String.trim`은 문자열 하나를 유일한 매개변수로 받으므로, 만들어진 함수도 이것을 받아요.
`String.toInt`는 `Maybe Int`를 반환하므로, 만들어진 함수도 이것을 반환해요.
`String.trim`은 `String`을 반환하고, `String.toInt`는 이것을 매개변수로 받아들이므로, 이 예제는 컴파일돼요.

이제 `sanitize` 함수를 다음과 같이 다시 쓸 수 있어요.

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

원래 예제에서 볼 수 있었던 `input` 매개변수를 더 이상 사용하지 않는다는 점에 주목해요. 기능은 완전히 같아요.
이렇게 매개변수를 참조하지 않고 함수를 만드는 방식을 "포인트 프리 스타일"이라고 해요.
이 스타일의 장점은 코드가 더 간결하다는 것이고, 단점은 특히 초보자에게 이해하기 어려울 수 있다는 거예요.

Elm에서는 모든 함수가 커링되어 있으므로 `String.length >> max`가 컴파일된다는 점을 기억해 둘 만해요.

- [`(>>)`][forward-composition] 연산자는 타입이 `(a -> b) -> (b -> c) -> (a -> c)`예요.
- `String.length`는 타입이 `String -> Int`이고, 이것이 `(a -> b)` 부분이에요. 따라서 `a`는 `String`이고 `b`는 - `Int`예요.
- `max`는 타입이 `Int -> Int -> Int`이고, 이것이 `b -> c` 부분이에요.
- `b`는 `Int`이므로 `max`가 부분 적용되고, 따라서 `c`는 이 부분 적용의 결과(`Int -> Int`)예요.
- 그러므로 `String.length >> max`의 타입은 `String -> (Int -> Int)`예요.
- 따라서 `((String.length >> max) "123") 2`는 `3`을 반환해요. `"123"`의 길이가 3이고, 이는 `Int` 인자로 들어온 2보다 크기 때문이에요.

## 함수 설계

Elm에서 우아한 코드를 쉽게 작성하려면, 주요 자료 구조를 함수의 마지막 매개변수로 두는 게 좋아요.
표준 라이브러리의 모든 흔한 함수가 이렇게 되어 있어요. 아래 타입 시그니처의 `List.map`처럼요.

```elm
map : (a -> b) -> List a -> List b
```

여기에서 `map` 함수의 마지막 매개변수가 `List a`이고 `List b`를 반환한다는 것을 알 수 있어요. 즉 주요 자료 구조(`List`)가 마지막 매개변수예요.

덕분에 아래처럼 우아한 파이프라인 코드를 작성할 수 있어요.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

또한 파이프라이닝 대신 함수 합성과 포인트 프리 스타일을 사용하기에도 편해요.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

함수 합성을 이용하면 이 예제를 `List.map` 호출 한 번으로 줄일 수도 있어요.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
