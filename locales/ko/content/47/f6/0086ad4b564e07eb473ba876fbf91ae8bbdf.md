# 소개

함수는 [기초][concept-basics] 개념에서 다음과 같은 예제와 함께 이미 소개했어요.

```R
squareit <- function(x) {
    x * x
}

squareit(3)
#> [1] 9

# shorter form
squareit_short <- function(x) x ^ 2
```

`squareit`의 정의를 자세히 살펴보면 여러 부분을 구분할 수 있어요.

- 함수는 `x`라는 매개변수를 받아요.
- 함수 본문이 있고, 보통 중괄호 `{ }`로 감싸요.
- 함수 객체가 만들어지면 변수 `squareit`에 할당돼요.

R에서 함수는 숫자나 문자열처럼 일급 객체예요.
따라서 `squareit <- function...`은 문법적으로 `x <- 42`와 똑같은 할당이에요.

## 인자

R은 Python이나 Julia 같은 다른 스크립팅 언어와 달리 위치 인자와 키워드 인자를 명확히 구분하지 않아요.

함수 호출은 값을 위치로 전달하거나 이름으로 전달할 수 있어요.
이름으로 전달하는 방식은 인자가 많아 순서를 기억하기 어려운 복잡한 함수에서 유용해요.

```R
f <- function(x, y) x / y

# call positionally
f(4, 2)
#> [1] 2

# call by name
f(y = 2, x = 4)
#> [1] 2
```

### 선택적 인자

기본값은 함수 정의에서 지정할 수 있지만, 기본값이 없는 인자들 뒤에 와야 해요.

그러면 기본값을 그대로 쓸지, 덮어쓸지 선택할 수 있어요.

```R
g <- function(x, y = 2) x / y

# default y value
g(6)
#> [1] 3

# explicit y value
g(6, 3)
#> [1] 2
```

### 추가 인자

임의 개수의 추가 인자를 받으려면 정의에 `...`(줄임표)를 사용해요.
함수 호출에서 넘어온 여분의 값들을 벡터로 변환할 수도 있지만, 이런 "dot args"(*다른 여러 언어에서는 "varargs"라고 불러요*)를 사용하는 다른 방법도 있으니 계속 읽어 봐요.

```R
var_f <- function(x, y, ...) {
  print(c(...))
}

var_f(2, 3, "opt1", "opt2")
#> [1] "opt1" "opt2"
```

## 함수 환경

앞서 우리는 매개변수와 본문이 모두 함수의 구성 요소라고 했어요.

사실 세 번째 구성 요소가 있어요. 바로 함수가 정의되는 *환경*이에요.

이것은 중첩 함수의 예로 설명할 수 있어요.

```R
outer_func <- function(x) {
  inner_func <- function(y) {
    x * y
  }
  
  inner_func(3)
}

outer_func(5)
#> [1] 15
```

이 함수 호출은 `x = 5`를 바깥 함수에 전달하고, 이 값은 그 함수 본문 안에서 사용할 수 있어요.

안쪽 함수는 바깥 함수 본문의 *일부*이고, `x`의 값에 접근할 수 있어요.
다르게 말하면 `x = 5`는 안쪽 함수의 *환경*에 있어요.

기술적으로 이것을 [클로저][wiki-closure]라고 해요.

환경은 dot args에서 특히 중요해요. 이렇게 전달된 값은 함수 본문 안의 함수 호출로 그대로 넘길 수 있거든요.
바깥 함수는 dot args가 무엇을 뜻하는지 알 필요도, 신경 쓸 필요도 없어요.

```R
f_var <- function(x, ...) {
  sum(x, ...)
}

x <- c(1, 2, NA, 6)

# for sum(), na.rm defaults to FALSE
f_var(x)
#> [1] NA

# pass through the na.rm value
f_var(x, na.rm = TRUE)
#> [1] 9
```

이 기법은 [`stringr`][ref-stringr] 같은 Tidyverse 라이브러리에서 아주 많이 사용해요.
`stringr` 함수 중 상당수는 `stringi`와 base R의 저수준 함수를 사용자 친화적으로 감싼 래퍼예요.

`str_*()` 함수에 전달한 추가 인자는 그대로 그 저수준 함수들로 넘어가요.

## 반환 값으로서의 함수

바깥 함수는 안쪽 함수(이름이 있든, 아래에서 설명하는 익명 함수든)를 정의하고 그것을 반환 값으로 사용할 수 있어요.

반환된 함수에는 그것이 정의된 환경이 함께 담겨 있어요.

```R
times_y <- function(x) {
  # anonymous function - see next section
  \(y) x * y
}

f <- times_y(3)
class(f)
#> [1] "function"

f(4)
#> [1] 12
```

## 익명 함수

함수를 정의할 때 보통 그 결과로 생긴 함수 객체를 변수에 바인딩해요.

```R
x <- 2

# function definition captures x from the environment
doubleit_short <- function(y) x * y
```

이렇게 하면 스크립트 뒷부분에서 그 함수를 쓰기 쉬워요. 하지만 꼭 바인딩해야 하는 건 아니에요.
짧고 한 번만 쓸 함수는 그 자리에서 바로 유용할 수 있죠.
이름을 붙이지 않은 이런 함수를 *익명 함수*라고 해요.

익명 함수는 워낙 흔히 쓰여서 (*R v4.1.0부터*) 정의하는 축약 문법이 있어요. `function`이라는 단어를 백슬래시 `\`로 바꾸면 돼요.

이 예는 반환 값에 대해 다룬 앞 섹션에서 사용했어요.

## 수정 시 복사

R은 벡터의 개별 요소에 값을 할당하는 것을 허용해요.
벡터를 함수 인자로 전달하고, 반환하기 전에 함수 본문에서 수정하면 수정된 벡터를 얻어요.

그런데 원본 벡터는 어떻게 됐을까요?

```R
f <- function(vec) {
  vec[1] <- 42
  vec
}

vals <- c(1, 3, 4)

# f() returns a modified vector
f(vals)
#> [1] 42  3  4  

# the original vector is unchanged.
vals
#> [1] 1 3 4
```

R은 데이터 과학을 위해 설계된 언어예요.
데이터를 모으는 데는 시간과 노력, 어쩌면 어마어마한 돈이 들 수 있어요. *그 데이터를 훼손하지 않는 것이 중요해요!*

일반적인 정책은 (몇 가지 예외를 빼면) *수정 시 복사*예요.
객체(예를 들어 벡터)가 나중에 문제를 일으킬 수 있는 방식으로 변경되면, R은 *수정된 복사본*을 반환하고 원본은 그대로 둬요.

큰 데이터 구조를 복사하는 것은 계산 비용이 클 수 있지만, 대안이 데이터 훼손이라면 보통 이쪽이 더 나은 선택이에요.

~~~~exercism/caution
같은 데이터를 반복해서 복사하게 만드는 연산을 조심해요.

(Tidyverse 저자) Hadley Wickham의 말을 인용하면:

> 루프는 본질적으로 느리지 않아요. 다만 루프 안에 느린 연산을 넣는 것을 위험할 만큼 쉽게 만들어요.

벡터화나 고차 함수가 이런 성능 저하 요인으로부터 지켜 주는 데 도움이 될 수 있어요.
~~~~
