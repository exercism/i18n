# 소개

손으로 작성한 어셈블리 코드는 반복투성이예요.
같은 짧은 명령어 묶음이 거의 똑같은 모습으로 몇 번이고 되풀이되고, 되풀이되는 코드를 줄여 줄 추상화도 거의 없어요.
게다가 어셈블리로 코딩할 때는 의미가 뚜렷하지 않은 값들을 관리해야 해요.
이름 붙은 매개변수도 없고, 밑바탕에서 돌아가는 기계의 세부 사항 대부분을 프로그래머가 직접 다뤄야 해요.

트랙에서 사용하는 어셈블러인 NASM은 이 두 문제를 모두 도와줄 수 있는 몇 가지 도구를 제공해요.
이 도구들은 명령어가 프로세서에 도달하기 전인 _어셈블 시간_ 에 실행돼요.
소스 텍스트가 기계어로 번역되기도 전에, 어떻게 고쳐 쓸지를 어셈블러에게 알려 주는 거예요.

이런 도구 중 가장 중요한 것은 **매크로**예요. 매크로는 어셈블러를 위한 조리법이라고 생각하면 돼요.
매크로는 사용된 위치에서 펼쳐져요. 마치 그 자리에 코드를 손으로 써 넣은 것처럼요.

매크로는 여러 개의 리터럴 토큰을 매개변수로 받을 수 있어서, 다양한 상황에서 재사용할 수 있어요.
하지만 매크로는 함수가 아니에요. `call`도, `ret`도, 코드의 다른 지점으로 제어를 옮기는 일도 없어요.

## 한 줄 매크로

가장 단순한 정의는 `%define`으로 값이나 짧은 표현식에 이름을 붙이는 거예요:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

이후에 나오는 `WIDTH`는 모두 어셈블 전에 `8`로 바뀌어요.
이 치환은 텍스트 차원에서 이루어지기 때문에, 피연산자 안이든 다른 정의 안이든 이름이 나타나는 곳이면 어디든 치환돼요.

~~~~exercism/note
숫자 _상수_ 에는 `%define` 대신 `equ`를 쓰는 게 좋아요.

`%define`으로 선언한 한 줄 매크로는 사용될 때만 펼쳐지고, 다시 지정하거나 정의를 해제할 수 있어요.
반면 `equ` 상수는 정의된 시점에 평가되고, 절대 바뀌지 않아요.
~~~~

`%define`은 _이름이 있는_ 매개변수를 받을 수도 있어요. 작은 인라인 함수처럼 동작해요:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
전체 본문과 각 매개변수를 모두 괄호로 감싸요.
`%define square(x) x*x`라고 하면, `square(1+1)` 호출은 `1+1*1+1`로 펼쳐져서 `3`이 돼요.
`%define square(x) ((x)*(x))`라고 쓰면 같은 호출이 `((1+1)*(1+1))`로 펼쳐져서 `4`가 돼요.
~~~~

`%define`으로 정의한 이름은 대소문자를 구분해요.
필요하다면 `%idefine`을 써서 이름이 대소문자를 구분하지 않게 할 수 있어요.

한 줄 매크로는 코드의 여러 부분에 의미를 부여할 때 유용해요.
주의해서 사용하면 가독성을 높이고 오타가 날 가능성을 줄여 줘요.
예를 들어, 함수 안에서 특정 용도로 쓰이는 레지스터는 그 용도로 정의할 수 있어요:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## 여러 줄 매크로

여러 줄이든 상관없이 코드 전체 묶음은 `%macro`로 잡고, `%endmacro`로 닫아요.
이름 뒤의 숫자는 매크로가 받는 인자의 개수를 나타내고, 0일 수도 있어요.
인자를 넘길 때는 쉼표(`,`)로 구분해요:

```x86asm
%macro example_macro 0
...
%endmacro
```

여러 줄 매크로의 인자에는 이름이 없어요.
전달된 순서대로 `%1`, `%2` 같은 식으로 가리켜요:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

인자는 매크로 본문에서 수행하는 연산에 맞는 유효한 문법이어야 한다는 점을 기억해요.
여기서 `mult_two eax, ecx`와 `mult_two r8, r9`는 둘 다 어셈블되지만, `mult_two eax, cl`은 어셈블되지 않아요. `imul eax, cl`이 정의되어 있지 않기 때문이에요.

### 매크로 안의 레이블

일반 레이블을 정의하는 매크로는 두 번 사용되는 순간 깨져요. 그 레이블도 두 번 정의되기 때문이에요.
두 번 이상 호출될 수 있는 매크로 안에서 레이블을 쓰려면, 그 레이블 앞에 `%%`를 붙여야 해요.
그러면 어셈블러가 펼칠 때마다 이 레이블에 서로 다른 고유한 이름을 붙여요:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## 어셈블 시간에 반복하기

`times`를 사용하면 한 줄짜리 코드 블록을 반복할 수 있어요.
특히 메모리에 같은 값을 반복해서 선언할 때 유용해요:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

여러 줄의 코드를 반복할 때는 대신 `%rep`를 사용할 수 있어요:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

반복 횟수는 `%rep` 바로 뒤에 적고, 반복 블록을 닫는 `%endrep`가 있다는 점을 기억해요.

실행 시간 루프가 카운터를 쓰듯이, `%rep` 블록 안에서 어셈블 시간 카운터를 쓰는 일도 흔해요.
어셈블 시간 정수 상수는 `equ`로 선언할 수 있지만, 어셈블 시간 정수 _변수_ 에는 대신 `%assign`을 사용해요.
`%define`과 달리 `%assign`은 즉시 숫자로 평가되고, 다시 지정할 수 있어요:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

전처리기가 실행되고 나면 루프는 사라지고 네 개의 `add` 명령어만 남아요. 즉시값 `0`, `1`, `2`, `3`이 그대로 박혀 있어요.
이건 어셈블러가 하는 루프 언롤링이에요. 카운터 레지스터도, 분기도 없이 그냥 일직선 코드만 남아요.

## 조건부 어셈블리

전처리기에서 사용할 수 있는 조건부 지시문이 여러 가지 있어요.
조건부 지시문은 여러 경로 중 하나를 선택하고, 조건이 참일 때만 본문을 제자리에 펼쳐요.

`%if` ... `%elif` ... `%else` ... `%endif`는 숫자 검사의 결과에 따라 분기를 선택해요:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## 파일로 나누기

매크로는 보통 별도의 파일에 두고, 필요한 각 소스에서 `%include`로 끌어와요:

```x86asm
%include "patterns.mac"
```

지정한 파일은 어셈블 전에 그 자리에 그대로 삽입돼요. 마치 그 내용을 그 자리에 직접 입력한 것과 똑같아요.
이렇게 하면 정의를 한곳에 모아 두고 여러 소스 파일이 함께 쓸 수 있어요.

매크로 파일을 단독으로 어셈블할 수도 있다면 `.asm` 확장자를 붙이는 게 좋아요.
매크로에는 링키지가 없다는 점을 기억해요.
매크로 파일을 어셈블하더라도, 그 매크로는 그 파일을 `%include`한 다른 파일에서만 보여요.

그렇지 않고 `%include` 전용이라면 확장자는 아무거나 괜찮아요.
`.asm`이나 `.mac`을 쓰는 건 흔한 관례예요.
