# 지침

무선 조종 자동차 프로젝트 작업이 계속되고 있어요. 텔레메트리 시스템의 대역폭이 매우 귀중한 상황이라, 텔레메트리 데이터를 주고받기 위한 메시지 프로토콜을 구현하라는 요청을 받았어요.

데이터는 버퍼(바이트 배열)로 전송돼요. 정수를 보낼 때는 아래에 설명된 프로토콜을 사용해 버퍼의 크기를 줄여요.

각 값은 가능한 한 가장 작은 정수 타입으로 표현해야 해요 (`byte`와 `sbyte` 타입은 절약되는 양이 미미해서 제외돼요):

| 부터                       | 까지                      | 타입     |
| -------------------------- | ------------------------- | -------- |
| 4_294_967_296              | 9_223_372_036_854_775_807 | `long`   |
| 2_147_483_648              | 4_294_967_295             | `uint`   |
| 65_536                     | 2_147_483_647             | `int`    |
| 0                          | 65_535                    | `ushort` |
| -32_768                    | -1                        | `short`  |
| -2_147_483_648             | -32_769                   | `int`    |
| -9_223_372_036_854_775_808 | -2_147_483_649            | `long`   |

값은 할당된 타입에 맞는 바이트 수로 변환해야 해요. 완전한 버퍼는 버퍼에 추가로 들어 있는 바이트 수를 나타내는 1바이트(_프리픽스 바이트_)와, 그 뒤에 정수를 담은 바이트들(_페이로드 바이트_)로 이루어져요.

일부 타입은 동일한 바이트 수를 사용해요 (예: `uint`와 `int` 타입). 보통은 같은 _프리픽스 바이트_를 가지겠지만, 그러면 디코딩에 문제가 생겨요. 이를 해결하기 위해 프로토콜은 작은 트릭을 도입해요. 부호 있는 타입의 경우 _프리픽스 바이트_ 값은 `256`에서 버퍼에 추가된 바이트 수를 뺀 값이에요.

통신에서는 프리픽스 바이트와, 그것이 나타내는 수만큼의 뒤따르는 바이트만 전송돼요. 내부적으로는 송신과 수신 루틴 모두에서 (필요에 따라 뒤에 0을 채운) 9바이트 버퍼를 사용해요.

## 1. 전송할 정수 값을 인코딩하기

메서드에 전달된 매개변수를 받아 버퍼를 인코딩하는 정적 메서드 `TelemetryBuffer.ToBuffer()`를 구현해 보세요.

```csharp
// Type: ushort, bytes: 2, signed: no, prefix byte: 2
TelemetryBuffer.ToBuffer(5)
// => {0x2, 0x5, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0 };

// Type: int, bytes: 4, signed: yes, prefix byte: 256 - 4
TelemetryBuffer.ToBuffer(Int32.MaxValue)
// => {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 };
```

## 2. 수신한 버퍼 디코딩하기

수신한 버퍼를 디코딩하고 값을 `long` 형태로 반환하는 정적 메서드 `TelemetryBuffer.FromBuffer()`를 구현해 보세요.

```csharp
TelemetryBuffer.FromBuffer(new byte[] {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 })
// => 2147483647
```

프리픽스 바이트의 값이 예상 밖이라면 `0`을 반환해야 해요.
