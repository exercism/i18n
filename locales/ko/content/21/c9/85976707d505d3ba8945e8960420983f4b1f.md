# 지시 사항

악의 지배자로서, 전 세계 악의 던전에 있는 `TreasureChest`의 품질에 큰 자부심을 느껴요.
품질을 유지하는 건 쉽지 않아요. 던전 관리자들이 자꾸 보물 제작을 엉망으로 만들거든요. 그래서 관리자들을 뜻대로 움직이게 할 Elm API를 제공하기로 해요.

양보할 수 없는 두 가지 조건이 있어요:
1. `TreasureChest`는 최소 8자 이상의 안전한 비밀번호로 보호되어야 해요
2. 특정 던전에서 각 `TreasureChest`는 고유한 보물 하나만 담아야 해요

던전 관리자들이 비밀번호와 보물 조합의 목록을 제안하면, 조건에 맞는 `TreasureChest`만 만들어져요.

이 기준에 따르면, 제안 목록에서 안전한 상자를 만드는 방법은 두 가지가 있어요:
1. 비밀번호가 안전하지 않은 것을 먼저 제거하고, 그다음 보물이 중복된 것을 제거해요
2. 보물이 중복된 것을 먼저 제거하고, 그다음 비밀번호가 안전하지 않은 것을 제거해요

두 방법의 결과가 다를 수도 있어요(예를 들어 `[("strong_password", GoldStatue), ("1234", GoldStatue)]`의 경우). 하지만 어느 쪽이든 상관없으니, 선택은 던전 관리자들에게 맡기고 싶어요.

사용자에게 어느 정도 선택의 여지를 주면서도, 최종 결과의 속성을 보장하는 API라고요?
팬텀 타입 기법에 딱 맞을 것 같아요!

## 1. 보물 상자의 자리 표시자를 마련해요

`TreasureChest` 타입과 그 동반 함수인 `getTreasure`는 이미 주어져 있어요. 하지만 상자 제안을 나타낼 타입은 직접 만들어야 해요.

`Chest` 타입과 `makeChest`를 구현하고, `secureChest`와 `uniqueTreasures`의 타입 시그니처를 고쳐요.
`makeChest`와 `makeTreasureChest`의 타입 시그니처는 요구 사항의 일부로 이미 제공되어 있으니, 수정하면 안 돼요.

`Chest`는 `TreasureChest`와 같은 데이터를 담아야 하고, 두 개의 타입 인자를 가져야 해요. 하나는 `treasure`를 위한 것이고, 다른 하나는 `conditions`를 위한 레코드 팬텀 타입이에요.
`Chest`는 팬텀 타입을 사용하므로, `TreasureFactory` 모듈 밖에서는 사용되지 않도록 불투명해야 한다는 점에 유의해요.
이 경우에는 아예 노출되지도 않아요.

확장 가능한 레코드를 팬텀 타입으로 사용해 제약을 추가하도록, `secureChest`와 `uniqueTreasures`의 타입 시그니처를 고쳐요.
`secureChest`는 특정 조건이 없는 `Chest`를 받아서 `Maybe Chest`를 반환해야 하며, 팬텀 레코드에 `securePassword : ()`라는 추가 조건이 있어야 해요.
`uniqueTreasures`는 특정 조건이 없는 `List Chest`를 받아서 `List Chest`를 반환해야 하며, 팬텀 레코드에 `uniqueTreasure : ()`라는 추가 조건이 더해져야 해요.

~~~~exercism/note
Elm 테스트는 노출된 함수에는 접근할 수 있지만 타입 시그니처에는 접근할 수 없어요. 따라서 올바른 시그니처를 사용하고 있는지 테스트로 검증하기는 불가능해요.
물론 올바른 시그니처를 사용했는지 확인하는 가장 확실한 방법은 모듈과 테스트를 컴파일하고 실행하는 데 성공하는 것이에요. 그래도 해답을 제출하면 타입 시그니처를 검사해 주는 분석기 규칙을 만들어 두었어요.
~~~~

## 2. 안전한 상자를 골라요

상자가 준비되면, 그중 안전한 상자를 골라내야 해요.

`secureChest`를 구현해서, 비밀번호가 8자 이상인 상자에만 `Just`를 반환하도록 해요.
그 조건을 만족하는 `Chest`는 팬텀 타입에 `securePassword : ()` 조건이 추가되어야 해요.

## 3. 고유한 보물을 골라요

던전에는 가장 희귀한 보물만 들어갈 수 있어요. 복제본이 하나라도 있으면 보물이 싸 보이거든요.

`uniqueTreasures`를 구현해서, `Chest` 목록을 받아 입력 목록에서 보물이 고유한 `Chest`들의 목록을 반환하도록 해요.
어떤 보물이 입력에 두 번 나타나면, 출력에 포함되면 안 돼요.
입력으로 들어오는 `Chest`에는 특정 조건이 없어야 하고, 출력되는 `Chest`에는 `uniqueTreasure : ()` 조건이 추가되어야 해요.

## 4. 최종 결과물을 즐겨요

모험가들을 꿀에 모여드는 파리처럼 끌어들일 최고의 `TreasureChest`를 마음껏 즐겨요.

`makeTreasureChest`를 구현해서, 안전하면서 고유한 `Chest`를 받아 `TreasureChest`를 만들어요.
`TreasureChest`는 불투명 타입이라 이것이 유일한 생성 방법이에요. 형편없는 던전 관리자라도 이걸 망칠 수 없어요.
