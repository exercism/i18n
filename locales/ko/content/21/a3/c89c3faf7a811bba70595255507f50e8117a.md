# 딕셔너리

Cairo의 딕셔너리는 다른 언어의 맵이나 해시 테이블과 비슷한 키-값 저장소예요.

하지만 Cairo의 불변 메모리 모델 때문에 몇 가지 독특한 특징이 있어요.

## 핵심 개념

`Felt252Dict<T>` 타입은 Cairo에서 딕셔너리 기능을 제공해요. 키 타입은 `felt252`이고, 값 타입은 지원되는 임의의 타입 `T`예요.

```rust
use core::dict::Felt252Dict;

fn main() {
    let mut balances: Felt252Dict<u64> = Default::default();
    balances.insert('Alice', 100);
    let balance = balances.get('Alice'); // Returns 100
}
```

## 중요한 특징

다른 언어의 딕셔너리와 달리, Cairo의 딕셔너리에는 몇 가지 특별한 성질이 있어요.

1. 키는 반드시 `felt252` 값이어야 해요.
2. 모든 키는 암묵적으로 0이라는 값으로 시작해요.
3. 항목을 삭제할 수는 없고, 값을 갱신할 수만 있어요.
4. 값은 `Felt252DictValue` 트레이트를 구현해야 해요.

## 성능에 관한 참고

Cairo의 불변 메모리 모델 때문에 딕셔너리 연산은 $O(n)$의 복잡도를 가져요. 여기서 $n$은 딕셔너리에 수행한 연산의 수예요.

연산을 할 때마다 그 변경을 기록하는 새 항목이 만들어져요.

## 복잡한 타입 다루기

`Felt252DictValue`를 구현하지 않는 타입(배열이나 구조체 같은)은 `Nullable<T>`로 감쌀 수 있어요.

```rust
let mut dict: Felt252Dict<Nullable<Span<felt252>>> = Default::default();
dict.insert(0, NullableTrait::new(array![1, 2, 3].span()));
```

## 메모리 관리

딕셔너리는 `Destruct` 트레이트를 구현해요. 그래서 스코프를 벗어나면 자동으로 "스쿼시"돼요. 이 과정에서 값이 검증되고 최적화돼요.

이건 Cairo의 증명 시스템의 일부이고, 내부에서 알아서 처리돼요.

기억해 둘 점은, 딕셔너리가 다른 언어보다 비효율적으로 보일 수 있지만, Cairo만의 메모리 모델과 증명 시스템 요구 사항에 맞게 동작하도록 이렇게 설계됐다는 거예요.
