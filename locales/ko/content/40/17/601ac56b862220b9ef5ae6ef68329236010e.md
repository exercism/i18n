# 자세히 알아보기

`Option` 타입은 표준 라이브러리에서 제공하는 enum이에요. 존재하지 않을 수도 있는 값을 표현할 때 유용하죠.
`null`이나 `nil`처럼 들릴 수도 있지만, 실제로는 상당히 다르고 특별한 타입이에요.

`Option<T>`는 다른 타입을 담을 수 있고, `Some(T)`와 `None`이라는 두 가지 변형이 있어요.

예를 들어, `Option<u32>`는 `u32` 타입을 담아요.

## 사용법

### `Option<T>` 안의 `T` 사용하기

`Option`에 들어 있을지도 모르는 값을 다루는 흔한 방법이 몇 가지 있어요:

- `if let Some(t) = optional { ... }`.

    `if let`은 `Option<T>`에서 값을 꺼내 변수 `t`에 바인딩해요. 그러면 그 블록 스코프 안에서 값을 바로 사용할 수 있어요.

- `match optional { Some(t) => {...}, None => {...}}`

    `match` 연산자도 하나의 문이나 표현식 안에서 값을 풀어내고 `None`인 경우까지 함께 처리할 수 있게 해줘요. if와 else 문을 길게 이어 붙이는 대신 쓸 수 있죠. `match`를 사용하면 일부 코드의 가독성을 높일 수 있어요.
- `optional.map(|t| ...)`
   `Option::map`은 전달받은 함수로 `Option`을 그 자리에서 갱신하는데, 경우에 따라 새로운 타입이 될 수도 있어요.

   **참고**: 값이 있으면 그 안에 담긴 값에 대해 동작해요. 바인딩은 `Option<U>`가 되고, 이때 주어진 클로저는 `FnOnce(T) -> U`예요.
- `optional.unwrap()`.
   `Option<T>`를 unwrap하면 `T`를 꺼내 주지만, `T`가 들어 있지 않으면 패닉이 발생해요. 어떤 경우에는 간편하게 쓸 수 있죠.

   **중요**: unwrap은 단기적으로나 테스트 코드에서 개발을 편하게 해주지만, 런타임 패닉이 발생할 가능성을 열어 둬요. 가능하면 피하는 게 좋아요.

- `optional.expect("Unexpected None found! Aborting program.)`.
   `Option<T>`의 `expect` 메서드는 `unwrap()`과 아주 비슷하지만, `None`일 때는 전달한 메시지를 담아 패닉이 발생해요.

## 예시

`Option<u32>`에 값이 들어 있을 때:

```rust
let has_something: Option<u32> = Some(100);
assert_eq!(has_something.unwrap(), 100);
```

`Option<u32>`에 값이 *없을* 때:

```rust
let has_nothing: Option<u32> = None;
assert_eq!(has_nothing, None);
```
