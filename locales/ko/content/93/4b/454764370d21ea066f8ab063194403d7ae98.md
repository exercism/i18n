# 불변 클래스

`SCOREBOARD`는 변하는 것이에요. 하나의 점수판을 가리키는 두 이름은 같은 점수를 봐요. 왜냐하면 판은 하나뿐이고, 두 이름 모두 그것을 가리키기 때문이에요.

방위는 그렇지 않아요. `350 degrees`는 다른 것이 되지 않고, 그냥 *그 자체*예요. 숫자도 그렇게 동작하고, 문자열도 마찬가지예요. 그리고 직접 만든 클래스도 그렇게 할 수 있어요.

## immutable

```sather
immutable class BEARING is

   readonly attr degrees : INT;

end; -- class BEARING
```

두 단어가 모든 것을 바꿔요. 불변 클래스의 객체는 가리키는 대상이 아니라 **값**이에요:

- 대입하거나 전달할 때 복사돼요. 그래서 다른 누구도 그 값을 바꿀 수 없어요.
- 절대 void가 될 수 없어요.
- 그리고 그 속성에는 대입할 수 없어요.

## 다른 것을 만들어 바꾸기

`degrees := 90`이 허용되지 않으므로, `attr`은 다른 방법을 줘요. 새 값을 받아 그 값이 바뀐 **새 객체**를 돌려주는 루틴이에요.

```sather
   b ::= b.degrees(90);      -- not b.degrees := 90
```

원본은 그대로 있어요. 이게 바로 이 방식의 전부이고, `create`도 이렇게 작성해요:

```sather
   create(d : INT) : SAME is
      b : SAME;                     -- starts with everything at nought
      return b.degrees(d);
   end;
```

여기에는 `new`가 없어요. 불변 객체는 항상 존재하므로, `b : SAME`은 이미 객체예요. 모든 속성이 빈 값인 상태로요.

그래서 방위를 "바꾸는" 루틴은 새 방위를 반환해요:

```sather
   turned(by : INT) : SAME is
      return #BEARING(degrees + by);
   end;
```

## 비교하기

값은 어떤 객체인지가 아니라 무엇을 담고 있는지로 비교돼요. 하지만 어떻게 비교할지는 직접 알려 줘야 해요. `is_eq`를 작성하면 `=`가 그것을 사용해요:

```sather
   is_eq(other : SAME) : BOOL is
      return degrees = other.degrees;
   end;
```

그게 없으면, 두 방위에 대한 `=`는 컴파일되지 않아요.

## 어떤 것을 선택할까요

그것에 정체성이 없고 그것에 대해 합리적으로 바뀔 수 있는 것이 아무것도 없을 때는 불변 클래스를 사용해요: 방위, 점, 날짜, 길이처럼요. 그 대상이 무슨 일들이 일어나는 특정한 하나의 대상일 때는 일반 클래스를 사용해요: 점수판, 하네스, 파일처럼요.

판단 기준은 "같은"이 "동등한"을 뜻하는지, "바로 그 하나"를 뜻하는지예요.
