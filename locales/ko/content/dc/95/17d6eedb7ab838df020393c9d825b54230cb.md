# 소개

이미 조각들을 모아 쿼테이션을 *만들고* 실행하는 방법을 알고 있어요. 쿼테이션은 그저 코드의 나열일 뿐이라서, 이미 알고 있는 시퀀스 단어들을 그대로 적용할 수 있어요:

```factor
USING: kernel math prettyprint quotations sequences ;

{ [ 1 ] [ 2 + ] [ 3 * ] } concat >quotation call .   ! => 9
[ 1 + ] dup append .                                 ! => [ 1 + 1 + ]
```

`append`는 두 쿼테이션을 이어 붙이고, `concat`은 쿼테이션 배열을 평평하게 펼치고, `map`은 데이터를 쿼테이션으로 바꾸고, `>quotation`은 그 결과를 호출할 수 있게 만들어요. `MACRO:`는 바로 이 기술을 가져다 **컴파일 타임**으로 옮겨요.

## 매크로란 무엇인가요

`MACRO:` 정의는 평범한 단어처럼 보이지만, 그 본문은 프로그램이 실행될 때가 아니라 *컴파일되는 동안* 실행돼요. 본문은 스택에 **쿼테이션 하나**를 남겨야 해요. 그러면 컴파일러가 **그 쿼테이션을 호출 지점에 끼워 넣어요**. 매크로 호출을 본문이 만들어 낸 코드로 바꾸는 거예요. 실행 시점에는 매크로가 남아 있지 않고, 생성된 코드만 있어요.

```factor
USING: kernel macros sequences ;

MACRO: twice ( quot -- spliced )
    dup append ;
```

`[ 1 + ] twice`를 어디에 쓰든, 컴파일러는:

1. 스택에 `[ 1 + ]`를 올려 둔 채로 본문을 실행하고,
2. `dup append`가 `[ 1 + 1 + ]` 쿼테이션을 만들고,
3. 그 코드 `1 + 1 +`를 그 자리에 끼워 넣어요.

그래서 `twice`를 호출하는 단어는 손으로 `1 + 1 +`를 쓴 것처럼 컴파일돼요:

```factor
: inc-twice ( x -- y ) [ 1 + ] twice ;

5 inc-twice .   ! => 7
```

핵심적인 차이는 이래요. 쿼테이션을 받는 일반적인 단어는 실행 시점에 그것을 `call`해요. 매크로는 아무것도 호출하지 않아요. 대신 컴파일러에게 *새로운 코드*를 건네서 그 자리에 대신 컴파일하게 해요.

## 입력은 리터럴이어야 해요

본문이 컴파일 타임에 실행되기 때문에, 매크로의 입력은 *그 시점에* 알려져 있어야 해요. 호출 지점에서 **리터럴**이어야 하는 거죠. `[ … ]` 쿼테이션, 숫자, 배열, 문자열 같은 것들이요. 실행 시점에만 존재하는 값은 매크로에 건넬 수 없어요.

```factor
! DOCTEST: SKIP — illustrative call sites, not standalone code
[ 1 + ] twice          ! ok: the quotation is a literal
[ 1 + ] 3 repeat-quot  ! ok: the quotation and the number are literals
```

## 도구 모음

매크로 본문은 쿼테이션을 반환하는 평범한 코드예요. 이미 만난 단어들이 대부분의 일을 해내요:

| 만들고 싶은 것…                        | 사용할 단어          |
|----------------------------------------|----------------------|
| `[ A ]`와 `[ B ]`로 `[ A B ]`          | `append`             |
| 쿼테이션 배열로 쿼테이션 하나          | `concat >quotation`  |
| 시퀀스의 각 원소마다 쿼테이션          | `map`, 그다음 `concat >quotation` |

`sequences`와 `kernel`에 있는 단어 두 개가 도구 모음을 완성해요.

**`<repetition>`**은 `sequences`에 있는데, 한 원소를 `n`개 복사한 시퀀스를 만들어요. 스택 효과는 `( length elt -- repetition )`이고, 개수가 먼저 와요. 결과는 *가상* 시퀀스라서, 평소처럼 펼쳐 주면 돼요:

```factor
3 [ 1 + ] <repetition> concat >quotation .   ! => [ 1 + 1 + 1 + ]
```

**`curry`**는 `kernel`에 있는데, 쿼테이션 앞에 값을 붙여서 그 값을 먼저 스택에 올리는 새 쿼테이션을 만들어요:

```factor
3 [ + ] curry .          ! => [ 3 + ]
{ 1 2 3 } [ . ] curry .  ! => [ { 1 2 3 } . ]
```

`curry`는 특정 원소 하나를 쿼테이션에 구워 넣는 방법이에요. `{ 10 20 30 }`과 `[ + ]`를 정확히 `[ 10 + ] [ 20 + ] [ 30 + ]`로 바꿔 주는 거죠.

## 생각보다 간단한 이유

어떤 언어에서는 매크로에 특별한 quote/unquote 문법과 이름 충돌을 피하기 위한 별도의 장치가 필요해요. Factor에는 그런 게 전혀 필요 없어요. 쿼테이션은 이미 *해석이 끝난* 단어들의 나열이거든요. 파서가 `[ … ]`를 읽을 때 각각의 `dup`, `+`, `append`를 찾아 두니까요. 그래서 매크로 본문은 이미 하고 있는 시퀀스 조작일 뿐이고, 그게 우연히 쿼테이션을 반환할 뿐이에요.

## 가까운 사촌: `$[ … ]`

매크로는 *호출*에 끼워 넣을 쿼테이션을 반환해요. 그 대신 파싱 시점에 계산되는 평범한 *값*을 원한다면, `$[ code ]`가 파일을 읽는 동안 `code`를 실행하고 그 결과를 리터럴로 소스에 접어 넣어요:

```factor
! DOCTEST: SKIP — compile-time value, shown for contrast
USING: calendar literals ;

CONSTANT: build-time $[ now ]
```

`$[ … ]`는 [`literals`][literals] 보캐뷸러리에 있는데, 파싱 시점의 결과를 리터럴에 끼워 넣는 단어들을 모아 둔 곳이에요. 완전성을 위해 언급했어요. 여러분이 작성하게 될 네 가지 스텐실, `twice`, `repeat-quot`, `compose-many`, `each-literal`은 모두 `MACRO:` 선언이에요.

[macros]: https://docs.factorcode.org/content/vocab-macros.html
[literals]: https://docs.factorcode.org/content/article-literals.html
