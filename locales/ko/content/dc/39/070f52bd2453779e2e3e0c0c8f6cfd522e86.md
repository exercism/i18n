# 소개

Go 1.18에서 Go는 **제네릭** 지원을 추가했어요.
제네릭을 사용하면 코드를 중복시키지 않으면서 여러 타입과 함께 동작하는 함수와 자료 구조를 작성할 수 있어요.

## 제네릭이 필요한 이유

Go에서 함수와 타입은 보통 `int`나 `string`처럼 특정한 타입과 함께 동작해요.
제네릭이 없던 시절에는 여러 타입을 지원하려면 두 가지 선택지가 있었어요.
첫째, `SumInts`와 `SumFloats`처럼 이름이 다른 여러 함수를 작성하는 방법이에요.
이 방법은 유지보수가 어려운 중복 코드를 만들어요.
둘째, 빈 인터페이스인 `any`(`interface{}`)를 사용하는 방법이에요.
하지만 빈 인터페이스는 컴파일 시점의 타입 검사를 없애고, 런타임에 타입 단언을 해야 해요.
제네릭은 중복 코드를 피하면서 타입 안전성을 제공함으로써 이 문제를 해결해요.

## 제네릭 함수

함수 이름 뒤에 대괄호 `[...]`로 **타입 매개변수**를 추가하면 제네릭 함수를 정의할 수 있어요.
다음은 뒤집힌 슬라이스를 반환하는 제네릭 함수의 예시예요.

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

이 예시에서 `T`는 타입 매개변수예요.
`T`는 실제 타입을 위한 자리 표시자라고 생각하면 돼요.
대괄호 안의 `any` 키워드는 **타입 제약**이에요.
제약은 컴파일러에게 `T`에 어떤 타입이 허용되는지 알려줘요.
여기서 `any`는 `T`가 어떤 타입이든 될 수 있다는 뜻이에요.

### 제네릭 함수 호출하기

대괄호 안에 실제 타입을 전달해서 제네릭 함수를 호출할 수 있어요.
이 실제 타입을 **타입 인자**라고 해요.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

대부분의 경우 Go 컴파일러는 함수 인자로부터 타입을 자동으로 추론할 수 있어요.
이 기능을 **타입 추론**이라고 해요.
타입 추론을 사용하면 대괄호 안에 타입 인자를 작성할 필요가 없어요.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

이 예시에서 컴파일러는 `words`가 문자열 슬라이스임을 확인하고, `T`가 `string`이라고 추론해요.

## 타입 제약

모든 타입 매개변수에는 제약이 있어야 해요.
제약은 어떤 타입을 타입 인자로 사용할 수 있는지 지정해요.
또한 제약은 해당 타입의 값에 허용되는 연산을 결정해요.

### `any` 제약

`any` 제약은 모든 타입을 허용해요.
Go에서 `any`는 빈 인터페이스 `interface{}`의 별칭이에요.
`any`는 모든 타입을 허용하기 때문에, 함수는 모든 Go 타입에 대해 동작하는 연산만 수행할 수 있어요.
예를 들어 슬라이스를 담고 있는 `any` 값 두 개가 있다면, 슬라이스는 `==`로 비교할 수 없으므로 두 값을 `==`로 비교할 수 없어요.

### `comparable` 제약

Go는 `comparable`이라는 내장 제약을 제공해요.
`comparable` 제약은 `==`와 `!=` 연산자를 지원하는 모든 타입을 허용해요.
비교 가능한 타입에는 불리언, 숫자, 문자열, 포인터, 채널, 그리고 비교 가능한 타입으로 이루어진 구조체나 배열이 있어요.

다음은 슬라이스에 특정 항목이 포함되어 있는지 확인하는 함수의 예시예요.

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

`T`가 `comparable` 제약을 사용하기 때문에 `elem == target`은 유효해요.
`comparable`을 `any`로 바꾸면 컴파일러가 오류를 보고해요.

### 인터페이스 타입 집합으로 사용자 정의 제약 만들기

Go 1.18부터 인터페이스는 메서드뿐 아니라 타입 집합도 정의할 수 있어요.
파이프 문자 `|`를 사용해서 인터페이스에 허용되는 타입을 나열할 수 있어요.

```go
type Number interface {
    int | int64 | float64
}
```

이제 `Number`를 함수의 제약으로 사용할 수 있어요.

```go
func Double[T Number](value T) T {
    return value * 2
}
```

`Number`의 모든 타입이 `*` 연산자를 지원하기 때문에, Go는 함수 안에서 `value * 2`를 허용해요.

### 기반 타입 근사 `~`

때로는 원시 타입을 기반으로 사용자 정의 타입 정의를 만들어요.

```go
type MyInt int
```

위에서 정의한 `Number` 제약은 정확히 `int`, `int64`, `float64` 타입만 허용해요.
`MyInt` 값을 `Double`에 전달하면 `MyInt`가 `int`와 일치하지 않기 때문에 컴파일러가 오류를 발생시켜요.
기반 타입이 `int`인 모든 타입을 허용하려면 타입 앞에 물결표 `~`를 붙여요.

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

이제 `MyInt` 타입의 값과 함께 `Double`을 사용할 수 있어요.

### `cmp.Ordered` 제약

표준 라이브러리는 [`cmp` 패키지][doc-cmp]에서 `cmp.Ordered` 제약을 제공해요.
`cmp.Ordered` 제약은 비교 연산자 `<`, `<=`, `>`, `>=`를 지원하는 모든 타입을 허용해요.

## 제네릭 타입

타입 매개변수를 사용해서 구조체 같은 제네릭 타입을 정의할 수도 있어요.
다음은 제네릭 `Stack` 자료 구조의 예시예요.

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

제네릭 타입의 변수를 선언할 때는 대괄호 안에 타입 인자를 제공해야 해요.

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

타입 추론은 제네릭 함수에서만 동작해요.
제네릭 타입의 값을 만들 때는 항상 타입 인자를 지정해야 해요.

## 제네릭을 사용해야 할 때

제네릭은 강력한 기능이지만, 모든 문제에 사용할 필요는 없어요.

다음과 같은 상황에서는 제네릭을 사용해요.
- 트리, 연결 리스트, 캐시처럼 어떤 원소 타입과도 동작하는 자료 구조를 만들 때.
- 필터링, 정렬, 검색처럼 어떤 타입의 슬라이스나 맵에서도 동작하는 유틸리티 함수를 작성할 때.
- 여러 타입에 대해 완전히 동일한 구현이 필요하고, 컴파일 시점의 타입 안전성을 원할 때.

다음과 같은 상황에서는 대신 인터페이스를 사용해요.
- 기반 데이터 타입보다 동작과 메서드가 중요할 때.
  예를 들어 파일, 네트워크, TTY처럼 다양한 타입의 소스에서 데이터를 읽고 처리하려면 `func Process[T](src T)`보다 `func Process(src io.Reader)`를 사용해요.
- 타입마다 작업을 수행하는 방식이 달라 서로 다른 메서드 구현이 필요할 때.
