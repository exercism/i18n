# 지침 추가

## 과제

프로시저 두 개를 구현해요.

- `custom_error_message message`는 오류를 발생시키고, `message`가 오류 메시지예요.
- `handle_error script`는 주어진 스크립트를 실행하고, 무슨 일이 일어났는지 설명하는 문자열을 반환해요:

  | 스크립트가…                    | 반환값                  |
  | ----------------------------- | ----------------------- |
  | 0으로 나누면                  | `"division by zero"`    |
  | 존재하지 않는 파일을 열면      | `"file does not exist"` |
  | 존재하지 않는 proc을 호출하면  | `"proc does not exist"` |
  | 그 밖의 다른 오류를 발생시키면 | `"unknown error"`       |
  | 성공하면                      | `"success"`             |

## 오류 발생시키기

Tcl에는 오류를 발생시키는 명령이 두 개 있어요.

```tcl
error "something went wrong"
throw {MYAPP BADTHING} "something went wrong"
```

`throw`는 첫 번째 인자로 _오류 코드_를 받아요.
오류 코드는 어떤 종류의 오류가 발생했는지 핸들러에게 알려 주는 리스트라서, 메시지 텍스트를 분석하지 않고도 대응할 수 있어요.
내용은 원하는 대로 정하면 돼요. `{MYAPP BADTHING}`은 예시일 뿐이고, 비어 있지 않은 리스트라면 무엇이든 괜찮아요.
관례적으로는 일반적인 것에서 구체적인 것으로 나열해요.
핸들러는 일치하는 `try ... trap` 패턴(아래에서 설명해요)으로 이걸 잡아요. 예를 들어 `trap {MYAPP BADTHING}`이나, 모든 `MYAPP` 오류를 잡는 `trap {MYAPP}`을 사용해요.
`error`는 세 번째 인자로 오류 코드를 선택적으로 받아요: `error message ?info? ?code?`.

## `catch`로 오류 처리하기

[`catch`][catch]는 스크립트를 실행하고, 오류를 발생시키는 대신 정수 _완료 코드_를 반환해요:

| 코드 | 의미       |
| ---- | ---------- |
| 0    | `ok`       |
| 1    | `error`    |
| 2    | `return`   |
| 3    | `break`    |
| 4    | `continue` |

```tcl
if {[catch {expr {1 / 0}} result options] == 1} {
    puts "error message: $result"
    puts "error code:    [dict get $options -errorcode]"
}
```
```none
error message: divide by zero
error code:    ARITH DIVZERO {divide by zero}
```

선택적인 두 번째 인자는 결과(또는 오류 메시지)를 받아요.
선택적인 세 번째 인자는 _옵션 딕셔너리_를 받는데, 여기에는 `-errorcode`와 `-errorinfo`(스택 트레이스)가 들어 있어요.

장점:

- 작고 유연해요.
- `if {[catch {open $f} fh]} {...}`처럼 간단한 경우에는 짧게 쓸 수 있어요.

단점:

- 완료 코드를 직접 확인해야 해요.
  `if {[catch ...] != 0} { handle error }`처럼 대충 작성하면 `return`, `break`, `continue`까지 오류로 취급해요.
- 처리하지 않은 오류는 직접 다시 발생시키지 않으면 그냥 사라져요.
- 스크립트가 실패했든 아니든 정리 코드를 실행하는 내장 방법이 없어요.

## `try`로 오류 처리하기

[`try`][try]는 스크립트를 실행하고, 그 결과를 처음 일치하는 핸들러로 보내요.
선택적인 `finally` 절은 항상 실행되기 때문에, 파일 채널 같은 자원을 해제하기에 좋은 자리예요.

```tcl
set fh [open $filename r]
try {
    set data [read $fh]
} on error {msg options} {
    puts "could not read $filename: $msg"
} finally {
    close $fh
}
```

장점:

- 구조가 명확해요. 결과의 종류마다 핸들러가 하나씩 있어요.
- `finally`는 항상 실행돼요.
- 어떤 핸들러와도 일치하지 않는 결과는 그대로 호출자에게 전달돼요.

단점:

- 간단한 경우에는 `catch`보다 조금 장황해요.

### `try ... on`과 `try ... trap`의 차이

핸들러에는 두 종류가 있어요.

`on code {msgVar optionsVar}`는 _완료 코드_와 일치하는지 확인해요: `ok`, `error`, `return`, `break`, `continue`.
모든 오류의 완료 코드는 `error`라서, `on error`만으로는 0으로 나눈 것인지 파일이 없는 것인지 구분할 수 없어요.
결국 메시지 텍스트를 들여다봐야 하는데, 이 방법은 깨지기 쉬워요. 메시지는 사람을 위한 것이고 Tcl 버전에 따라 바뀔 수 있거든요.

```tcl
try {
    expr {$a / $b}
} on error {msg} {
    if {[string match "*divide by zero*" $msg]} { ... }
}
```

`trap pattern {msgVar optionsVar}`는 _오류 코드_와 일치하는지 확인해요.
패턴이 `-errorcode` 리스트의 접두사일 때 핸들러가 일치해요.
이렇게 하면 오류의 종류를 안정적으로 집어낼 수 있어요.

```tcl
try {
    expr {$a / $b}
} trap {ARITH DIVZERO} {} {
    puts "division by zero"
} trap {} {msg} {
    puts "some other error: $msg"
}
```

빈 패턴인 `trap {}`은 모든 오류와 일치해요.
핸들러는 순서대로 확인되니까, 모든 걸 잡는 핸들러는 맨 마지막에 둬요.

## 오류 코드 찾기

`ARITH DIVZERO`는 어디에 문서화되어 있을까요?
대부분 소스 코드에만 있지만, Tcl이 직접 보여 줄 거예요.
오류가 발생한 뒤에는 전역 변수 `errorCode`에 가장 최근 오류의 오류 코드가 담겨 있어요:

```none
$ tclsh
% set a 1; set b 0
% expr {$a / $b}
divide by zero
% set errorInfo     ;# this is the stack trace
divide by zero
    while executing
"expr {$a / $b}"
% set errorCode     ;# this is what we're after
ARITH DIVZERO {divide by zero}
```

프로그램 안에서는 옵션 딕셔너리에서 꺼내면 돼요:

```tcl
try {
    expr {$a / $b}
} on error {msg options} {
    puts [dict get $options -errorcode]
}
```

오류 코드의 마지막 원소는 사람이 읽을 수 있는 메시지이거나, 오류를 일으킨 대상의 이름인 경우가 많아요.
`trap` 패턴에서는 이걸 빼요. `{ARITH DIVZERO {divide by zero}}`가 아니라 `{ARITH DIVZERO}`를 사용해요.

### 자주 쓰이는 오류 코드

이 표는 완전하지 않아요.
다른 오류의 코드를 찾고 싶다면 위에서 설명한 방법을 사용해요.

| 상황                   | 예시                | 오류 코드                 |
| ---------------------- | ------------------- | ------------------------- |
| 0으로 나누기           | `expr {1 / 0}`      | `ARITH DIVZERO ...`       |
| 수학 정의역 오류       | `expr {sqrt(-1)}`   | `ARITH DOMAIN ...`        |
| 파일을 찾을 수 없음    | `open nosuchfile r` | `POSIX ENOENT ...`        |
| 권한 거부됨            | `open /root/x w`    | `POSIX EACCES ...`        |
| 알 수 없는 명령        | `no::such::proc`    | `TCL LOOKUP COMMAND name` |
| 알 수 없는 변수        | `set nosuchvar`     | `TCL LOOKUP VARNAME name` |
| 인자 개수가 잘못됨     | `string length a b` | `TCL WRONGARGS`           |
| 잘못된 딕셔너리        | `dict size {1 2 3}` | `TCL VALUE DICTIONARY`    |
| 잘못된 리스트          | `llength "a \{b"`  | `TCL VALUE LIST ...`      |

`POSIX` 오류 코드는 `ENOENT`, `EACCES`, `EEXIST`처럼 운영체제의 `errno` 이름을 사용해요.

## 힌트: 스크립트가 실행되는 위치

`handle_error`는 호출자로부터 스크립트를 받아요.
이걸 `try $script`로 실행하면, 호출자의 스코프가 아니라 `handle_error`의 스코프에서 평가돼요.
스크립트가 작성된 곳에서 평가하려면 [`uplevel`][uplevel]을 사용해요: `try {uplevel 1 $script} ...`.
