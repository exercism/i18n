# 개요

[`Nothingness`][concept-nothingness] 개념에서 살펴본 것처럼, R에는 값이 없는 경우([`NULL`][ref-null]), 알 수 없는 경우([`NA`][ref-na]), 수학적으로 유효하지 않은 경우([`NaN`][ref-finite], [`Inf`][ref-finite])를 나타내는 여러 가지 방법이 있어요.
일반적으로 R은 이런 값들을 사용해 문제를 그 자리에서 표시하고, 예외를 발생시키지 않은 채 계속 진행하려고 해요.

## `stop()`

어떤 문제는 너무 근본적이어서 프로그램을 계속 실행할 수 없어요.
이럴 때는 [`stop(msg)`][ref-stop]를 사용해 프로그램을 즉시 중단하고 `Error`를 발생시키면서 `msg`를 출력해요.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

다른 언어의 [`assert`][wiki-assert]와 비슷하게, [`stopifnot()`][ref-stopifnot]은 `stop()`을 편리하게 감싼 함수예요.
인자로는 쉼표로 구분된 임의 개수의 불리언 조건을 받고, 모두 `TRUE`일 때만 프로그램이 계속 실행돼요.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R에는 오류를 처리하는 여러 가지 방법이 있어요.
이 방법들은 Common Lisp을 기반으로 하며, 많은 인기 언어들과는 상당히 달라요.

가장 간단한 방법은 문제가 될 수 있는 코드를 [`try()`][ref-try]로 감싸는 거예요.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning]과 [`message()`][ref-message]

이들은 치명적이지 않은 상황에 대한 반응이에요. 예를 들면:

- 프로그램이 적어도 부분적으로는 복구할 수 있는 문제를 경고할 때.
- 오래 실행되는 프로그램의 진행 상황을 사용자에게 알릴 때.

둘의 차이 중 하나는 경고는 저장해 두었다가 함수가 반환될 때 (기본적으로) 출력되지만, 메시지는 즉시 출력된다는 점이에요.
기본 동작을 바꾸는 방법은 여러 가지가 있지만, 여기서 다루기에는 범위를 벗어나요.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

[`suppressWarnings()`][ref-warning] 함수는 Exercism에서 원하지 않는 출력으로 테스트 러너가 혼란스러워지는 것을 막아야 할 때 가끔 유용하게 쓸 수 있어요.
