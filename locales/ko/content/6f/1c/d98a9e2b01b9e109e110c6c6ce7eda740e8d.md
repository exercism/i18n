# 부동소수점 수

`FLTD`는 소수 부분을 가질 수 있는 수를 담아요. 리터럴에는 소수점과 `d`가 필요해요:

```sather
   440.0d
   0.5d
   -2.25d
```

`FLT`는 정밀도가 절반인 같은 개념이에요. 이 트랙에서는 `FLTD`를 일관되게 사용해요. 메모리가 빠듯한 게 아니라면 `FLT`를 쓸 이유가 없어요.

## 산술 연산

| 연산자 | 의미 |
| --- | --- |
| `+` `-` `*` | `INT`와 같아요 |
| `/` | 나눗셈, 소수 부분을 유지해요 |

`FLTD`에는 `%`가 없어요.

두 피연산자는 모두 `FLTD`여야 해요. `INT`를 섞으면 조용히 변환되는 게 아니라 컴파일 오류가 나요. 이건 오히려 장점이에요. 이 부분이 문제가 되는 곳은 사람들이 정확히 실수하는 바로 그 지점이거든요.

## 변환하기

```sather
   7.fltd            -- 7.0, an INT made into an FLTD
   7.5d.int          -- 7, the fraction thrown away
   7.5d.round        -- 8, to the nearest whole number
   7.5d.floor        -- 7.0, down to a whole number
   7.5d.ceiling      -- 8.0, up to a whole number
```

나누기 전에 변환하고, 나눈 뒤에 변환하지 않아요. `n.fltd / 2.0d`는 반을 유지하지만, `(n / 2).fltd`는 이미 반을 잃은 뒤예요.

## 유용한 루틴

```sather
   (-2.5d).abs       -- 2.5
   2.0d.sqrt         -- 1.41421
   (2.0d).max(3.0d)  -- 3.0
```

## 부동소수점은 근사값이에요

`FLTD`는 정확한 값이 아니라 아주 가까운 근사값을 담아요. 3분의 1을 십진수로 정확히 쓸 수 없는 것처럼, 대부분의 소수는 정확히 저장할 수 없어요. 그래서 이런 일이 생겨요:

```sather
0.1d + 0.2d          -- very nearly 0.3, but not exactly
```

기억해 둘 만한 두 가지 결과가 있어요:

**`=`로 비교하지 않아요.** 같은 답을 내야 할 두 계산도 마지막 몇 자리에서 자주 달라져요. 대신 두 값이 가까운지 물어봐요:

```sather
   (a - b).abs < 0.0001d
```

**작은 값을 많이 더하면 정확도를 잃어요.** 더할 때마다 조금씩 반올림되고, 오류가 쌓여요.

값이 정확해야 할 때, 특히 돈을 다룰 때는 대신 `INT`로 정수 단위를 세요(달러가 아니라 센트처럼요).

## 출력하기

`.str`은 유효 숫자를 여섯 자리 정도만 보여줘요. 실제로 담고 있는 정밀도에는 미치지 못하죠:

```sather
   #OUT + (1.0d / 3.0d).str;      -- 0.333333
```
