# 안내

신문 공장의 새 품질 관리자인 Elena가 생산실을 모니터링할 작은 소프트웨어를 하나 만들어 달라고 부탁해요.

## 1. 사용자 정의 오류 정의하기

`ERROR:` 파싱 워드로 오류 튜플 클래스 `machine-error`를 정의해요. 슬롯은 필요 없어요.

```factor
machine-error   ! throws a fresh machine-error
```

## 2. 습도 확인하기

`check-humidity`를 정의해요. 이 워드는 스택에서 습도 측정값을 하나 꺼내고, 그 값이 `70`을 초과하면 문자열 `"humidity too high"`를 `throw`해요. 그렇지 않으면 아무것도 반환하지 않아요.

```factor
50 check-humidity   ! returns nothing
80 check-humidity   ! throws "humidity too high"
```

## 3. 온도 확인하기

`check-temperature`를 정의해요. 온도 측정값을 하나 꺼내고, 그 값이 `500`을 초과하면 문자열 `"temperature too high"`를 `throw`해요. 그렇지 않으면 아무것도 반환하지 않아요.

```factor
400 check-temperature   ! returns nothing
600 check-temperature   ! throws "temperature too high"
```

## 4. 기계 모니터링하기

`monitor`는 스택에서 습도와 온도를 꺼내 두 검사를 모두 실행하도록 정의해요. 두 검사 중 하나라도 `throw`하면 `monitor`는 대신 새 `machine-error`를 `throw`해야 해요. 둘 다 통과하면 `monitor`는 아무것도 반환하지 않아요.

```factor
50 400 monitor   ! returns nothing
80 400 monitor   ! throws a machine-error
50 600 monitor   ! throws a machine-error
```

## 5. 측정값 묶음 모니터링하기

`monitor-batch`는 `{ humidity temperature }` 측정값들의 배열을 받아서, 그중 몇 개가 실패하는지(즉, 몇 개가 `monitor`를 `throw`하게 만드는지)를 반환하도록 정의해요.

```factor
{ { 50 400 } { 80 400 } { 50 600 } { 60 200 } } monitor-batch .
! => 2
```
