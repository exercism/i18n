# 개요

해시셋은 내부적으로 해싱을 사용해 [`sets`][sets] [프로토콜][set-protocol]을 구현하며, 평균 O(1)의 삽입, 조회, 삭제를 제공해요. 제자리에서 변경할 수 있어서 그래프 순회의 *방문 집합* 패턴에 안성맞춤이죠.

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| 워드          | 스택 효과                                    |
|---------------|-------------------------------------------|
| `HS{ }`       | 빈 해시셋 리터럴 (공유되니 `clone` 해야 해요!) |
| `>hash-set`   | `( seq -- set )`, 시퀀스로부터 새 집합을 만들어요 (중복은 제거돼요) |
| `adjoin`      | `( elt set -- )`, 제자리 삽입              |
| `in?`         | `( elt set -- ? )`, 집합에 포함되는지 확인  |
| `delete`      | `( elt set -- )`, 제자리 제거              |
| `cardinality` | `( set -- n )`, 원소의 개수                |
| `null?`       | `( set -- ? )`, 집합이 비어 있으면 참       |
| `members`     | `( set -- seq )`, 시퀀스로 열거            |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )`, `set`을 `exemplar`의 클래스로 변환해요 |

이미 가지고 있는 데이터로 집합을 만들고 싶다면 `>hash-set`이 어떤 시퀀스든 한 단계로 변환하면서 중복을 버려요. `{ 2 3 2 5 } >hash-set`은 `HS{ 2 3 5 }`를 만들어요. `adjoin`을 반복해 집합을 키우는 것에 대응하는 일괄 처리 방식이죠.

`in?`와 `sequences`의 `member?` 사이에는 미묘한 차이가 있어요. 둘 다 소속 여부를 검사하지만, `member?`는 시퀀스를 처음부터 끝까지 훑는 반면 `in?`은 집합 타입의 프로토콜 메서드로 처리를 넘겨요. `HS{ }`의 경우에는 해시 조회가 되죠. "방문" 컨테이너에 담긴 항목이 손에 꼽을 정도를 넘어가면 `in?`을 사용해요.

`null?`은 전체 `cardinality`를 계산하지 않고 "이 집합이 비었나?"라는 질문에 답해요. "아직 처리할 게 남아 있나?"를 확인하는 자연스러운 가드죠. 작업 목록을 집합으로 들고 있다면 `[ set null? ] [ … ] until`로 목록이 빌 때까지 비워낼 수 있어요.

## 해시테이블과 잘 어울려요

"X를 방문했나?"를 담당하는 `HS{ }`는 "X의 이웃은 누구인가?"를 담당하는 `H{ }`와 자연스럽게 짝을 이뤄요. 교과서적인 DFS는 그냥 이렇게 돼요.

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

방문 집합은 중복 작업을 걸러내고, 스택은 경계 노드를 이어 나가며(`push`/`pop`으로 LIFO), 이웃 맵(해시테이블)은 그래프를 제공해요. 도달 가능성을 묻는 문제에서는 방문 순서가 상관없기 때문에 벡터를 스택처럼 쓰는 것으로 충분해요. 같은 구조로 진짜 BFS를 구현한다면 벡터 대신 [`<dlist>`][dlist]를 쓰고 앞에서부터 꺼내면 돼요.
