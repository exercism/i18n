# 예외

```sather
   raise "Unknown prop: " + prop;
```

```sather
   protect
      ...
   when $STR then
      #OUT + exception.str;
   end;
```

## raise

`raise`는 어떤 객체든 받아요. `STR`을 `raise`하는 게 가장 단순한 경우이고, 이 연습 문제에서 쓰는 방식이에요. 직접 만든 클래스를 쓰면 더 많은 걸 담을 수 있어요. 어떤 prop이었는지, 몇 개가 필요했는지 같은 정보를요. 그 대신 그 클래스를 정의할 곳이 있어야 하죠.

예외는 `protect`가 잡을 때까지 호출자를 거쳐 바깥으로 이동해요. 아무도 잡지 않으면 프로그램이 멈추고 예외를 출력해요.

Sather는 루틴이 어떤 예외를 `raise`할 수 있는지 기록하지 않고, 호출자가 그것을 처리하도록 강제하지도 않아요. 루틴의 타입 어디에도 실패할 수 있다는 정보가 없어요.

## protect

```sather
   protect
      body
   when $STR then
      ...
   when SOME_CLASS then
      ...
   end;
```

`when` 절들은 순서대로 시도되고, raise된 값의 타입과 처음 일치하는 절이 실행돼요. `exception`은 바로 그 값이고, 절 안에서만 스코프에 들어와요.

일치하는 절이 없는 `protect`는 잡지 않아요. 예외는 마치 `protect`가 없었던 것처럼 바깥으로 계속 나아가요.

## 어디에서 잡을까요

실제로 뭔가 할 수 있는 곳에서 잡아요. 예외를 삼켜버리고 지어낸 값으로 계속 진행하는 `protect`는 크게 드러날 실패를 조용한 오답으로 바꿔버리는데, 그게 더 나빠요.

```sather
   -- almost always wrong
   protect
      return risky;
   when $STR then
      return 0;
   end;
```

## 예외일까요, 계약일까요?

둘 다 잘못되는 상황에 관한 것이지만, 서로 반대되는 경우를 위한 거예요.

**예외**는 실제로 일어날 수 있고 호출자가 합리적으로는 막을 수 없었을 만한 일을 위한 거예요. 표에 prop이 빠져 있다든지, 파일이 없다든지 하는 것들이죠.

다음 연습 문제에서 다루는 **계약**은 절대 일어나서는 안 되는 일을 위한 거예요. 호출자가 음수 무게를 넘기는 경우처럼요. 그리고 호출자에게 Bug가 있다는 명제이기도 해요. 계약은 요청했을 때만 검사되고, 위반된 계약은 잡을 수 있는 무언가를 `raise`하는 대신 프로그램을 멈춰요.

대략 이렇게 정리해요. 꼼꼼한 호출자라도 여전히 부딪힐 수 있는 일이면 `raise`해요. 부딪힌다는 게 호출자가 잘못했다는 뜻이면 계약에 넣어요.
