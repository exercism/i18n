# 개요

Rust에서 이터레이터는 [`Iterator`](https://doc.rust-lang.org/stable/std/iter/trait.Iterator.html) 트레이트를 구현하는 모든 값이에요.
이터레이터의 값은 이터레이터에서 `next` 메서드를 호출해서 수동으로 진행시킬 수 있어요.

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // many built-in methods implemented
}
```

Rust의 많은 [`collections`](https://doc.rust-lang.org/std/collections/index.html)는 [`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html)를 구현하는데, 이것은 컬렉션의 값으로부터 `Iterator`를 만들어낼 수 있어요.

```rust
trait IntoIterator where Self::IntoIter: Iterator<Item=Self::Item> {
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}
```

`IntoIterator::into_iter`는 자신의 `self` 타입을 소비하지만, 그 타입이 반드시 소유된 값일 필요는 없다는 점에 주목해요.
따라서 [`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-2)에 대한, [`&'a Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator)에 대한, 그리고 [`&'a mut Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-1)에 대한 `IntoIterator` 구현이 있어요.
이렇게 다양한 소유권 정도에 대한 구현은 유용한 유연성을 제공해요.

이 개념을 이해하는 데 `traits`에 대한 지식이 필요한 것은 아니고, `traits`를 익힐 수 있는 연습 문제가 따로 준비되어 있어요.
지금은 다음 내용만 기억해요:

- `IntoIterator`를 구현하는 타입은 이터레이터로 바뀔 수 있기 때문에 _이터러블_이라고 불러요.
- `Iterator`를 구현하는 타입은 이터레이터이고, 값을 _생성_하며 _순회_할 수 있어요.
- `IntoIterator`를 구현하는 모든 타입에서 `into_iter` 메서드를 호출하면 이터레이터를 얻을 수 있어요.
- 모든 이터레이터는 [`IntoIterator`를 구현](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html#impl-IntoIterator-25)하고 자기 자신을 생성해요.
- `for`문은 항상 이터레이터를 대상으로 동작하며, 범위 인자에 대해 `IntoIterator`를 암묵적으로 호출해요.

## `into_iter`와 `for`문

벡터를 순회하는 `for`문은 아마 익숙할 거예요:

```rust
// lor is a `Vec`, which implements `IntoIterator`
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
for people in &lor {
    println!("{people}");
}
```

기본적으로 `for`문은 인자의 `into_iter` 메서드를 호출한 다음, 항목을 더 이상 생성하지 않을 때까지 `next()`를 호출하는 것의 축약형일 뿐이에요. 다시 말해, 앞의 루프는 다음과 같이 풀어 쓴 것과 같아요:

```rust
{
    let mut iterator = (&lor).into_iter();
    while let Some(people) = iterator.next() {
        println!("{people}");
    }
}
```

## `iter`와 `iter_mut` 메서드

대부분의 Rust 컬렉션 타입은 `iter`와 `iter_mut` 메서드를 제공해요.
`T` 타입의 컬렉션에서, 이 두 메서드는 관례적으로 다음을 수행해요:

- `iter`가 반환하는 이터레이터는 불변으로 빌린 `&T`를 산출해요.
- `iter_mut`가 반환하는 이터레이터는 가변으로 빌린 `&mut T`를 산출해요.

```rust
let mut v = vec![1, 2, 3];

// Using `iter` method
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&1));
assert_eq!(iterator.next(), Some(&2));
assert_eq!(iterator.next(), Some(&3));
assert_eq!(iterator.next(), None);

// Using `iter_mut` method
for value in v.iter_mut() {
     *value *= *value;
}
println!("{v:?}");
// => [1, 4, 9]
```

## `iter`, `iter_mut`, `into_iter`의 차이

`iter`, `iter_mut`, `into_iter`가 모두 이터레이터를 만들어낸다면, 차이는 무엇일까요?

- `iter`가 반환하는 이터레이터는 관례적으로 불변으로 빌린 `&T`를 산출해요.
- `iter_mut`가 반환하는 이터레이터는 관례적으로 가변으로 빌린 `&mut T`를 산출해요.
- `into_iter`가 반환하는 이터레이터는 상황에 따라 `T`, `&T`, `&mut T`를 산출할 수 있어요.

`into_iter` 호출에서 말하는 상황이란 무엇일까요?
바로 자신의 `self` 타입이에요.
`Vec`, `&'a Vec`, `&'a mut Vec`에 대한 `IntoIterator` 구현이 있다는 것을 기억해요.
따라서:

- `(&v).into_iter()`는 `v.iter()`와 같아요 => `&T`를 반환해요
- `(&mut v).into_iter()`는 `v.iter_mut()`와 같아요 => `&mut T`를 반환해요
- `v.into_iter()` => `T`를 반환하고 값을 이동시켜요

이 점은 `for`문에서 가장 분명하게 드러나요:

- `for num in &v {...}` => `&T`를 바인딩해요
- `for num in &mut v {...}` => `&mut T`를 바인딩해요
- `for num in v {...}` => `T`를 바인딩하고 값을 이동시켜요

`(&v).into_iter()` 대신 `v.iter()`라고 쓰는 편이 종종 더 명확해요.
따라서 `into_iter`보다 `iter`와 `iter_mut`를 선호하게 되는 사용성 측면의 이유가 있어요.

## 이터레이터의 내장 메서드 사용하기

이터레이터는 `map`, `filter`, `collect`처럼 수많은 내장 메서드를 제공해요.
이 메서드들은 때때로 클로저와 함께 사용해요.

`map`은 클로저를 사용해서 이터레이터의 값을 변환해요.
`take`는 (무한할 수도 있는) 이터레이터를, 지정한 개수 이하의 항목을 낸 뒤 종료되는 이터레이터로 잘라내요.

```rust
for even_number in (0..).into_iter().map(|x| x * 2).take(4) {
    let odd_number = even_number + 1;
    println!("{even_number} => {odd_number}");
}
// 0 => 1
// 2 => 3
// 4 => 5
// 6 => 7
```

`filter`는 이터레이터를, 클로저가 `true`로 평가되는 값만 반환하는 이터레이터로 변환해요.
`count`는 이터레이터를 소비하고, 생성된 항목의 개수를 반환해요.

```rust
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
let short_people = ["Dwarves", "Hobbits"];
let num_tall_people = lor.iter().filter(|people| !short_people.contains(people)).count();
assert_eq!(num_tall_people, 5);
```

`flat_map`은 주어진 클로저를 통해 각 항목을 새로운 이터레이터로 변환한 다음, 생성된 모든 새 이터레이터를 서로 이어 붙여 평평하게 만드는 방식으로 이터레이터를 변환해요.
`collect`는 컬렉션 타입이 [`FromIterator`](https://doc.rust-lang.org/std/iter/trait.FromIterator.html)를 구현하기만 하면 새로운 컬렉션을 만들어내요.

```rust
let words = ["alpha", "beta", "gamma"];
// chars() returns an iterator
let merged: String = words.iter()
                          .flat_map(|s| s.chars())
                          .collect();
assert_eq!(merged, "alphabetagamma");
```

[`Iterator` 트레이트](https://doc.rust-lang.org/std/iter/trait.Iterator.html)는 이렇게 유용한 이터레이터 변환을 _정말 많이_ 제공해요. 문서를 읽어보고 익숙해질 만한 가치가 있어요.

## 지연 평가

Rust의 이터레이터가 지연 평가된다는 점을 아는 것이 중요해요. 이터레이터를 소비하기 전까지는 아무 값도 만들어내지 않아요.
다음 코드를 작성해서 실행하면:

```rust
(0..5).map(|x| x * x);
```

다음과 같은 컴파일러 오류가 나타나요:

```rust
 --> src/main.rs:2:5
  |
2 |     (0..5).map(|x| x * x);
  |     ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

`map`은 또 다른 이터레이터를 반환하는 어댑터 메서드이기 때문이에요.

이터레이터를 소비하려면, `for`문을 사용하거나 그 자체가 이터레이터가 아닌 어떤 값을 만들어내는 이터레이터 메서드를 사용해요.

예를 들어, `collect`는 소비자 메서드예요 (함수 시그니처가 이터레이터가 아니라 제네릭 타입을 반환해요):

```rust
//         Iterator   Adaptor        Consumer
//                |      |               |
let v: Vec<_> = (0..5).map(|x| x * x).collect();
```
