# 개요

`String`과 `&str`은 Rust에서 텍스트 데이터를 다루는 두 가지 기본적인 방법이에요. 두 타입의 특징과 둘이 어떻게 함께 동작하는지 알아 두면 아주 유용해요. 이 문서에서는 두 타입이 어떻게 겹치는지 살펴보고 몇 가지 기본적인 조언도 해요.
`String`은 `u8` 바이트의 벡터를 소유하는 타입이에요.
`String`은 값을 바꿀 수 있어요.
`&str`은 String 슬라이스에 대한 빌린 참조예요.
`&str`은 값을 바꿀 수 없어요.

`&str`의 올바른 발음은 "ref string"이에요.
`String`은 유니코드 코드 포인트 시퀀스를 UTF-8로 인코딩한, 잠재적으로 가변적인 표현이에요.

`&str`은 올바른 형식의 UTF-8 시퀀스를 읽기 전용으로 바라보는 뷰예요.
참조이기 때문에 `Copy`이고, 공유할 수 있어요.

Rust의 `String`과 `&str`은 다른 언어에서처럼 인덱스로 접근할 수 없어요.
예를 들어 다음 코드는 동작하지 않아요:

```rust,invalid
let hello = "Hello";
println!("First letter = {}", hello[0]);
```

이것은 다음과 같은 속성에서 비롯돼요:

- 문자열은 UTF-8이고, 그 기본 단위는 바이트가 아니라 유니코드 코드 포인트인 `char`예요.
- 유니코드 코드 포인트는 최대 4바이트까지 차지하지만, 인코딩되는 너비는 가변적이에요.
- 따라서 실제로 인코딩된 문자를 하나씩 순회하지 않고서는 `n`번째 코드 포인트의 위치를 계산할 수 없어요. 첫 번째 문자 이후로는 다음 문자의 위치가 앞선 문자들이 몇 바이트를 차지했는지에 달려 있기 때문이에요.
- 그래서 Rust 표준 라이브러리 개발자들은 문자열에 `Index` 트레이트를 구현하지 않기로 했어요. 바이트 배열은 인덱스로 접근하는 데 상수 시간이 걸리지만, 문자열은 인덱스로 접근하는 데 꽤 오랜 시간이 걸릴 수 있거든요. 이는 최소 놀람의 원칙을 위반해요.

```rust
let example = "I'm not entirely ASCII! ❤";

let n_chars = example.chars().count();
let final_byte = example.as_bytes()[example.len()-1];

println!("n_chars = {}", n_chars);             // 25
println!("example.len() = {}", example.len()); // 27

println!("final char: {}", example.chars().nth(n_chars-1).unwrap()); // ❤
println!("final byte: {final_byte}");                                // 164
println!("char of final byte: {}", final_byte as char);              // ¤
```

## `String`을 `&str`로 변환하기

`String`은 `Deref<Target=str>`을 구현해요.
이 트레이트에는 컴파일러의 특별 처리가 있어요. 즉 `String`에 대한 참조는 자동으로, 투명하게 `&str`로 강제 변환될 수 있어요.
이는 다음을 의미해요:

- 예를 들어 `&str` 인자를 기대하는 코드는 대신 `&String`을 받을 수 있어요.
- `&str`에 구현된 메서드는 `String`에서도 호출할 수 있어요.

(`str`에 대한 어떤 형태의 참조든 받을 수 있게 일반화하고 싶다면 `impl AsRef<str>` 타입의 인자를 쓸 수도 있지만, 보통은 인자 타입을 `&str`로 지정하는 것이 흔해요.)

## `&str`을 `String`으로 변환하기

`&str`로 `String`을 만드는 방법은 여러 가지예요:

- `String::from("my str")`
- `"my str".to_string()`
- `"my str".to_owned()`
- `let s: String = "my str".into();`

위 방법들은 모두 `String`을 위한 메모리를 (힙에) 할당해야 해요.
그래서 no_std에서는 `&str`은 쓸 수 있지만 `String`은 쓸 수 없어요.

(no_std에서 문자열을 다룰 때는 [heapless](https://crates.io/crates/heapless) 크레이트를 자주 사용해요.)

## 구조체에서 `String`과 `&str` 사용하기

이 섹션에서는 구조체 필드에 `String`과 `&str` 중 무엇을 쓸지 살펴봐요.
필드 값에 `&str` 대신 `String`을 써서 구조체를 정의하는 경우를 자주 보게 돼요.

```rust
struct Record {
    latitude: f64,
    longitude: f64,
    population: Option<u64>,
    city: String,
    state: String,
}
```

`String`을 사용하면 구조체가 데이터를 소유해요.
이렇게 하면 코드를 읽기 쉽고, 초보자에게 설명하기도 쉬워요.
하지만 각 필드마다 힙 할당이 일어난다는 뜻이기도 해요.
`&str`은 텍스트 데이터를 빌려 오기 때문에 성능은 더 좋지만, 그 대신 구조체에 수명 매개변수를 정의해야 해요.
[csv 크레이트 튜토리얼][csv-tutorial]에서 이런 개념들을 아주 잘 보여 주고 설명해요.

## 성능 관련 참고 사항

`String`은 힙에 할당되기 때문에 사용 비용이 더 클 수 있어요.
`&str`은 공유 참조이기 때문에 자주 재할당할 필요가 없어요.
