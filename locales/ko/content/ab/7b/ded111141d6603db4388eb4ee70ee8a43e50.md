# 지침

헐의 부두에서는 야간 근무가 한창이에요. 화물선 *Olwen*이 부두에 접안해 있고, 부두 인부들이 적하 목록을 병렬로 처리하고 있어요. 모든 상자는 배에 실리기 전에 무게를 재야 하고, 항만 관리자는 모든 인양 작업이 갱신하는 하나의 **톤수 집계**를 관리해요. 문제는 부두에 크레인이 하나뿐이라서, 두 인부가 동시에 갱신하면 집계가 깨질 수 있다는 점이에요.

각 상자는 품목 무게의 배열이에요. 상자의 무게는 그 품목들의 합이에요.

## 1. 상자 무게 재기

`weigh-crate`를 정의해서 상자를 받아 전체 무게를 반환하게 해요. 이건 평범한 순차 작업이에요. 상자 하나면 숫자 하나가 나와요.

```factor
{ 12 8 15 } weigh-crate .
! => 35
```

## 2. 적하 목록 전체를 병렬로 무게 재기

`weigh-all`을 정의해서 상자 배열을 받아 같은 순서로 각 상자의 무게를 담은 배열을 반환하게 해요. `parallel-map`을 사용해서 상자별 작업이 동시에 일어나도록 해요.

```factor
{ { 5 5 } { 10 } { 3 4 5 } } weigh-all .
! => { 10 10 12 }
```

## 3. 새 크레인 만들기

`<crane>`을 정의해서 새 크레인을 만들어요. 새 `<lock>`과 톤수 `0`을 가진 튜플이에요. 크레인은 이후 작업들이 보호하게 될 공유 자원이에요.

```factor
<crane> tonnage>> .
! => 0
```

## 4. 상자를 인양해 집계에 더하기

`hoist-crate`를 정의해서 `weight`와 `crane`을 받아, **크레인의 `<lock>`을 잡은 채로** 크레인의 톤수에 무게를 더하게 해요. 그래야 다른 인부들이 동시에 인양할 때도 읽기-더하기-쓰기가 원자적으로 이루어져요.

```factor
<crane>
35 over hoist-crate
17 over hoist-crate
tonnage>> .
! => 52
```

## 5. 현재 톤수 읽기

`crane-tonnage`를 정의해서 크레인의 현재 톤수를 반환하게 해요. 이때도 `<lock>`을 잡은 채로 읽어야, 인양 도중에 깨진 값을 보지 않아요.

```factor
<crane>
35 over hoist-crate
crane-tonnage .
! => 35
```

## 6. 화물 싣기

`load-cargo`를 정의해서 상자 배열과 크레인을 받고, **각 상자마다 상자의 무게를 재고 그 무게를 크레인에 인양하는 부두 인부 스레드를 하나씩 만들어요**. 이 단어는 모든 인부가 끝난 뒤에야 반환해요. 합류를 조율하려면 `<promise>`와 `?promise`를 사용해요.

```factor
<crane> :> crane
{ { 5 5 } { 10 } { 3 4 5 } } crane load-cargo
crane crane-tonnage .
! => 32
```
