# 소개

많은 객체 지향 언어에서는 부모 클래스를 [하위 클래스로 만들어][wiki-subclass] 동작을 확장하는 일이 흔해요. 부모의 메서드를 물려받으면서 새로운 메서드도 추가하죠.
이렇게 해서 객체 계층 구조가 만들어져요.

Julia에는 _클래스가 없어요_. 그러니 자연히 _하위 클래스도 없어요_.
그럼 기존 동작을 어떻게 물려받고 확장할까요?

이전 개념들에서 타입 계층 구조를 만드는 방법을 살펴봤고, Julia가 인자 타입에 따라 메서드를 고르기 위해 [다중 디스패치][concept-multiple-dispatch]를 어떻게 활용하는지도 배웠어요.

Julia에는 몇 가지 비공식 인터페이스도 있는데, 이를 통해 사용자 정의 타입을 표준 타입에 이미 정의된 동작에 연결할 수 있어요.

이 점은 반복자 인터페이스로 가장 쉽게 설명할 수 있어요.

## 반복자

앞서 교육 과정에서, Julia가 컬렉션의 각 원소를 다루는 여러 방법을 살펴봤어요.

- [루프][concept-loops], 예를 들어 `for item in items...`
- [브로드캐스팅][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [고차 함수][concept-hof]: `map(√, [1, 4, 9])`
- [컴프리헨션][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [제너레이터][concept-comprehensions]: `(x^2 for x in 1:1e6)`, 지연 평가돼요.

이처럼 Julia는 표준 컬렉션을 항목 하나씩 순회하는 방법을 알고 있어요. 위 예시의 벡터와 범위는 물론 Set, Dict 등도 마찬가지예요.

그럼 우리가 직접 만든 컬렉션에도 이 기능을 어떻게 추가할까요? 특히 제너레이터처럼 지연 평가로 순회할 수 있는 컬렉션이라면 더욱요.

### 최소 요구 사항

순회할 수 있는 수열을 만들려면 (최소한) 두 가지가 필요해요.

1. _첫 번째_ 항목을 얻는 방법.
2. 현재 상태에서 _다음_ 항목을 얻는 방법.

Julia는 `Base.iterate()` 함수의 메서드로 이 작업을 다음과 같은 단계로 수행해요.

1. 먼저 `Base.iterate(iter)`가 자동으로 호출돼요.
    - 순회할 것이 없으면 `nothing`을 반환해요.
    - 그렇지 않으면 첫 번째 항목과 첫 번째 상태를 담은 `Tuple`을 반환해요: `(firstitem, firststate)`.
2. 이전 순회에서 항목이 반환되었다면 `Base.iterate(iter, state)`가 자동으로 호출되고, `firststate`가 `state` 인자로 전달돼요.
    - 순회가 끝나면 `nothing`을 반환해요.
    - 그렇지 않으면 다음 항목과 다음 상태를 담은 `Tuple`을 반환해요: `(nextitem, nextstate)`.
3. 끝날 때까지 2단계를 반복해요.

이 단계들은 모두 "내부적으로" 처리돼요. 즉, 메서드 호출과 상태는 순회 프로토콜이 내부에서 관리하고(상태는 불투명하게 남아 있어요), 반복문 같은 고수준 구문에는 항목만 드러나요.
다시 말해, 우리가 보는 건 언제나 `item`뿐이고 나머지는 모두 블랙박스 안에 남아 있어요.

여기서 [다중 디스패치][concept-multiple-dispatch]가 핵심적인 역할을 해요.
`iter`의 타입이 어떤 메서드가 호출될지 결정하고, 인자의 개수가 첫 번째 항목을 반환할지 다음 항목을 반환할지 결정해요.

표준 타입에 대한 메서드는 이미 정의되어 있어요. `Vector`, `Range`, `Set` 등이요([현재][ref-iterations-collections] 총 14개 타입이에요).

사용자 정의 `MyType`이 같은 동작을 공유하게 하려면 먼저 다음을 정의해야 해요.
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

추상적으로 들으면 아마 혼란스럽겠지만, 사실 아주 간단할 수 있어요.
예를 들어, 주어진 정수 `n`의 거듭제곱을 최대 개수까지 만들어 주는 타입을 원한다고 상상해 봐요.

먼저 사용자 정의 타입을 정의해요.

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

이제 이 타입에 대한 `iterate` 메서드를 정의할 수 있는데, 첫 번째 항목과 첫 번째 상태는 무엇일까요?

첫 번째 항목을 얻기 위해 복잡한 준비가 필요한 반복자도 있지만, 이 장난감 같은 예에서는 반환되는 첫 번째 항목이 그냥 밑수라는 걸 알 수 있어요. 그래서 `count`의 값이 1 이상인지만 확인하면 돼요.

이제 다음 순회에 사용할 정보를 담는 첫 번째 상태를 생각해 볼 수 있어요.
이를 위해 어떤 정보를 추적해야 하는지는 직접 정하면 되고, 어떤 타입이든 괜찮아요.

이 경우에는 `n`을 거듭제곱할 "지수"만 추적할 수도 있고, `n`의 가장 최근 거듭제곱(즉, 반환된 항목)과 수열의 다음 "지수"를 사용해서 더 효율적인 방법을 찾을 수도 있어요.
이 두 숫자를 `Tuple`로 묶어 `state`로 반환할 수 있어요.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

이 예시에서 첫 번째 항목(`p.n`)은 반복문으로 반환되고, 첫 번째 상태 `(p.n, 2)`는 `iterate(P::Powers, state)` 메서드로 전달돼요.
거기서 현재 항목에 밑수를 곱해 다음 항목을 만들어 상태를 처리할 수 있고, 이렇게 해서 거듭제곱이 `1`만큼 커져요.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

지수 값이 아직 `count` 이내라면 `next` 항목과 증가된 상태 `Tuple`을 반환해요.
`index` 값이 `count`를 넘으면 순회가 끝났음을 알리기 위해 대신 `nothing`을 반환해요.

`iterate(p::Powers)`와 `iterate(p::Powers, state)` 메서드의 함수 본문이 꽤 비슷하다는 걸 눈치챘을지도 모르겠어요.
사실, 머리를 좀 쓰면 이 유사성 덕분에 상태에 기본값을 주는 두 인자 버전만 사용해서 구현을 간결하게 만들 수 있어요: `Base.iterate(p::Powers, state=(1, 1))`
그러면 별도의 단일 인자 `iterate(p::Powers)`가 필요 없어요.
가능할 때 실무에서 흔히 이렇게 해요.

지금까지 벌써 몇 가지 유용한 기능을 갖췄어요. 3의 처음 4개 거듭제곱에 대해 결과를 반복문으로 돌릴 수 있고, 주어진 숫자가 결과에 있는지 확인할 수 있으며, `sum()` 같은 집계 함수를 적용할 수 있어요.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### 추가 메서드

이렇게 좋은 출발을 했지만, 아직 모든 것이 작동하는 건 아니에요.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

예상대로, `length(Powers(3, 4))`도 정확히 같은 오류 메시지를 내요.

이건 쉽게 고칠 수 있어요. 길이는 타입 생성자의 일부니까요. 이 경우에는 4예요.
이 타입에 `Base.length()`를 정의하기만 하면, 그 수열에 컴프리헨션과 `collect()`를 사용할 수 있어요.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

효율을 위해서는 `Base.eltype()`도 정의하는 게 가장 좋아요. 결과의 원소 타입이에요.
그러면 `collect()` 같은 함수가 `Vector{Any}`에 `push!()`를 반복하는 대신, 출력 `Vector{Int}`를 위한 공간을 미리 할당할 수 있어요.

전에 본 적 없을 수도 있는 문법에 주목해 봐요. 이 메서드는 타입의 _인스턴스_가 아니라 _타입_ 자체에 정의돼요.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

반복자가 유한한 길이를 가질 _필요는_ 없어요.
"무한" 수열의 활용은 더 제한적이지만, 반복문을 `break`로 빠져나갈 방법만 있다면 그 위를 순회하는 게 유용할 수 있어요.
예를 들어, 특정 한계보다 작은 값만 생성하는 `Powers` 변형을 정의할 수도 있어요(정수 오버플로를 피하려면 아마 `typemax(Int)` 정도요).

## 요약

인터페이스는 설명하기가 꽤 혼란스러운데, Julia의 접근 방식이 대부분의 다른 언어와 아주 다르기 때문이에요.
특히 구현에서 인터페이스의 이름이 한 번도 언급되지 않을 수도 있어요. [하위 클래스 만들기][wiki-subclass]나 [믹스인][wiki-mixins]과는 아주 달라요.

하지만 실제로는 놀랄 만큼 간단해요.

1. 적절한 타입을 정의해요.
2. 어떤 메서드가 필요한지 알아내요.
3. 사용자 정의 타입에 그 메서드들을 구현해요. 보통 몇 개 안 되고, 아주 짧고 간단해요.
4. 나머지는 [다중 디스패치][concept-multiple-dispatch]가 자동으로 처리하게 해요.
