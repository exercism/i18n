# 따옴표로 묶기 소개

bash를 새로 배우는 프로그래머라면 계속해서 듣게 되는 조언이 하나 있어요:

> 변수를 따옴표로 묶어요!

왜 그럴까요?

변수(예를 들어 `$name`)를 확장할 때는 거의 항상 그 변수의 _값_을 하나의 문자열(또는 숫자)로 다루고 싶어요. 그 값이 예기치 않게 두 개 이상의 별도 문자열로 처리되기를 바라지는 않으니까요.

## 따옴표로 묶기

따옴표로 묶기는 어떤 텍스트를 하나의 단어로 다루도록 보장하는 가장 기본적인 방법이에요. 따옴표에는 크게 두 가지가 있어요.

### 큰따옴표

큰따옴표 안에서는 매개변수 확장, 산술 확장, 명령어 치환을 사용할 수 있어요.

```bash
echo "This is bash version $BASH_VERSION"
```

큰따옴표로 묶은 문자열 안에 큰따옴표 자체를 넣고 싶다면 앞에 백슬래시를 붙이면 돼요.

```bash
echo "She said \"Let me teach you about bash.\""
```

### 작은따옴표

작은따옴표 안에서는 어떤 확장도 _허용하지 않아요_.

```bash
echo 'This is bash version $BASH_VERSION'
# ...^..................................^
# prints exactly: This is bash version $BASH_VERSION
```

작은따옴표로 묶은 문자열 안에 작은따옴표를 넣는 것은 _불가능해요_.

## 따옴표로 묶는 것이 중요한 이유

그럼 `echo $name`은 정확히 무엇이 문제일까요?

셸이 코드 한 줄을 해석할 때는 [여러 종류의 확장][expansions]을 순서대로 수행해요. 마지막에 수행되는 확장 중 두 가지가 바로 _단어 분할_과 _파일 이름 확장_이에요.

### 단어 분할

매개변수 확장, 명령어 치환, 산술 확장의 결과 중 _큰따옴표 안에서 일어나지 않은 것_은 "단어 분할"의 대상이 돼요. 셸은 확장된 결과를 가져다가 `$IFS` 값에 들어 있는 문자들이 연속으로 나타나는 곳마다 나눠요. 기본값은 공백, 탭, 줄 바꿈이에요.

셸 루프를 사용하면 이 동작을 직접 확인할 수 있어요:

```bash
sentence="The quick brown fox jumps."
i=0
for word in "$sentence"; do echo "$((++i)) $word"; done
# ..........^.........^
```
다음과 같이 출력해요
```none
1 The quick brown fox jumps.
```

그런데 따옴표를 쓰지 않으면 이렇게 돼요:

```bash
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
다음과 같이 출력해요
```none
1 The
2 quick
3 brown
4 fox
5 jumps.
```

이번에는 `$IFS` 값을 다르게 해서 볼까요?

```bash
csv="first,second,third"
IFS=","
for word in $csv; do echo "$word"; done
```
다음과 같이 출력해요
```none
first
second
third
```

#### 단어 분할 끄기

단어 분할을 끄는 한 가지 방법은 `$IFS`를 빈 문자열로 설정하는 거예요.

```bash
sentence="The quick brown fox jumps."
IFS=    # or explicitly, IFS=""
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
다음과 같이 출력해요
```none
1 The quick brown fox jumps.
```

하지만 파일 이름 확장까지 함께 끄지 않는다면, 변수를 따옴표로 묶지 않고 두는 것은 권장하지 않아요. 방법은 아래에서 살펴볼게요.

### 파일 이름 확장

"글롭" 패턴은 여러 파일을 한꺼번에 가리키는 간결한 표현을 만드는 데 사용해요. 예를 들어 디렉터리에 있는 모든 Markdown 파일을 `*.md`로 가리킬 수 있죠. [글롭 패턴][glob]은 유닉스가 만들어진 이래로 쭉 있어 왔어요.

글롭의 와일드카드 문자는 다음과 같아요:

* `*`는 임의의 문자 0개 이상과 일치해요.
* `?`는 임의의 문자 정확히 한 개와 일치해요.
* `[...]`는 괄호 안에 나열된 문자 집합에서 정확히 한 문자와 일치해요.

   ~~~~exercism/advanced
   <details><summary>
   문자 집합에는 아주 많은 세부 사항이 있어요.
   여기를 클릭해서 확인해 보세요.
   </summary>

    * `[abc]`는 `a` 또는 `b` 또는 `c` 중 정확히 한 문자와 일치해요.
        * 표현식 안에 닫는 괄호를 문자 그대로 넣으려면, 여는 괄호 바로 뒤(선택적인 `^` 뒤)의 첫 번째 문자로 만들어요.
            * `[][]`는 닫는 괄호나 여는 괄호와 일치하는 문자 집합이에요.
            * 또는 백슬래시로 이스케이프해요: `[[\]]`
    * `[x-y]`는 `x`부터 `y`까지의 _범위_ 안에 있는 정확히 한 문자와 일치해요.
        * 문자 집합 안에 하이픈 문자를 문자 그대로 넣으려면, 여는 괄호 바로 뒤(선택적인 `^` 뒤)의 첫 번째 문자이거나 닫는 괄호 바로 앞의 마지막 문자여야 해요.
            * `[-xy]`나 `[xy-]`는 각각 `-` 또는 `x` 또는 `y` 중 정확히 한 문자와 일치해요.
            * 또는 백슬래시로 이스케이프해요: `[x\-y]`
        * 여러 범위를 지정할 수도 있는데, 예를 들어 `[0-9A-Fa-f]`는 16진수 한 자리와 일치해요.
    * `[^abc]`는 `a` 또는 `b` 또는 `c`가 **아닌** 정확히 한 문자와 일치해요.
    * `[^x-y]`는 `x`부터 `y`까지의 범위에 **속하지 않는** 정확히 한 문자와 일치해요.
    * `[[:character_class:]]`는 이름이 "character_class"인 클래스에 속한 문자 하나와 일치해요.
        * 사용할 수 있는 문자 클래스는 다음과 같아요: 
            * `lower`: 소문자
            * `upper`: 대문자
            * `alpha`: 문자
            * `digit`: 숫자
            * `alnum`: 문자와 숫자
            * `space`: 공백 문자
            * `blank`: 가로 공백(스페이스와 탭)
            * `xdigit`: 16진수
            * `word`: 식별자에 허용되는 문자(문자, 숫자, 밑줄)
            * `punct`: 구두점
            * `cntrl`: 제어 문자
            * `graph`: "보이는" 문자
            * `print`: 보이는 문자와 공백
        * 서로 조합할 수도 있어요.
            * `[[:alpha:]]` 클래스는 `[[:lower:][:upper:]]`로 구성돼요.
            * `[[:alnum:]]` 클래스는 `[[:alpha:][:digit:]]`로 구성돼요.
            * `[[:word:]]` 클래스는 `[[:alnum:]_]`로 구성돼요.
            * 밑줄(8진수 137)은 `[[:word:]]`이면서 동시에 `[[:punct:]]`예요.
            * `[[:graph:]]` 클래스는 `[[:alnum:][:punct:]]`로 구성돼요.
            * `[[:print:]]` 클래스는 `[[:graph:] ]`로 구성돼요. 즉, 다른 공백 문자는 빼고 공백(8진수 040)만 포함해요.
   </details>   
   ~~~~

#### 파일 목록 순회하기

`for`문으로 파일 목록을 순회할 수 있어요.

```bash
for file in *.csv; do
    do_something_with "$file"
done
```

변수 `"$file"`이 따옴표로 묶여 있다는 점에 주목해요. 글롭 패턴은 이름에 공백이 들어 있는 파일을 반환할 수도 있어요. `do_something_with` 명령이 파일 이름이라는 인자를 정확히 하나만 받도록 변수를 따옴표로 묶어야 해요.

#### 글롭 패턴은 정규 표현식이 아니에요

글롭 패턴은 정규 표현식이 **아니에요**.

* 정확히 한 문자와 일치하기
   * 정규 표현식 `.`
   * 글롭 `?`
* 문자 0개 이상과 일치하기
   * 정규 표현식 `.*`
   * 글롭 `*`
        * 글롭 패턴 `.*`는 "첫 문자가 문자 그대로의 마침표이고 그 뒤에 임의의 문자가 0개 이상 오는 파일 이름과 일치한다"는 뜻이에요.
* 문자 1개 이상과 일치하기
   * 정규 표현식 `.+`
   * 글롭 `?*`
* 정규 표현식의 문자 집합과 글롭의 문자 집합은 같은 방식으로 동작해요.

#### 따옴표로 묶기와 파일 이름 확장

파일 이름 확장을 막고 싶을 때가 있어요. 사용자 입력을 처리할 때가 그렇죠. 다음 코드를 봐요.

```bash
read -p "Enter something: " user_input
echo $user_input
```

사용자가 별표(`*`)를 입력하면 무엇이 출력될까요? 현재 디렉터리에 있는 파일 목록이에요. 아마 원하는 동작은 아닐 거예요.

또 다른 예로, 패턴을 인자로 받는 프로그램에 패턴을 넘겨주는 경우가 있어요. `tr` 프로그램은 텍스트를 다룰 때 자주 사용해요. 변수 값을 소문자로 바꾸려면 이렇게 하면 돼요.

```bash
var="My Puppet"
echo "$var" | tr '[:upper:]' '[:lower:]'
```
다음과 같이 출력해요
```none
my puppet
```

흔한 실수는 `tr`의 인자에 따옴표를 빠뜨리는 거예요: `tr [:upper:] [:lower:]`

~~~~exercism/caution
왜 문제가 될까요? 
따옴표로 묶지 않은 글롭 패턴은 일치하는 파일 목록으로 확장돼요.
스크립트를 사용하는 사람의 현재 디렉터리에 `p`, `u`, `w`라는 파일이 있다고 해봐요.

```bash
touch p u w
var="My Puppet"
echo "$var" | tr [:upper:] [:lower:]
```

그러면 오류가 발생해요!

따옴표로 묶지 않은 `[:upper:]` 패턴은 `:`, `u`, `p`, `e`, `r` 중 하나와 일치해요. 따옴표로 묶지 않은 `[:lower:]` 패턴은 `:`, `l`, `o`, `w`, `e`, `r` 중 하나와 일치해요. Bash는 첫 번째 패턴에 대해 `p`와 `u` 파일을, 두 번째 패턴에 대해 `w` 파일을 찾아내고, `tr`은 이렇게 호출돼요.

```bash
echo "$var" | tr p u w
```

그런데 이건 `tr`에 맞지 않는 인자 개수예요.
~~~~

#### 파일 이름 확장 끄기

[`set`][set] 명령으로 파일 이름 확장을 끌 수 있어요.

```bash
echo *      # prints a list of files
set -f      # disable filename expansion
echo *      # prints a literal asterisk
set +f      # enable filename expansion
```

#### 파일 이름 확장 제어하기

내장 [`shopt`][shopt] 명령에는 파일 이름 확장이 동작하는 방식을 제어하는 여러 설정이 있어요. 흥미로운 것 몇 가지를 소개할게요.

* `shopt -s nocaseglob`: 대소문자를 구분하지 않고 일치시켜요.
* `shopt -s extglob`: 확장 패턴을 켜요.
* `shopt -s nullglob`: 일치하는 파일이 없으면 패턴을 아무것도 아닌 것으로 바꿔요.
   기본 동작은 패턴을 리터럴 문자열 그대로 남겨 두는 거예요.
