# 지침 추가

## `from_quote`의 장단점

이 연습 문제에서는 `Time` 타입에 `from_quote` 함수를 정의해요. 덕분에 다음과 같은 코드를 작성할 수 있어요:

```roc
time : Time
time = "00:01:23"
```

이 코드는 컴파일 시점에 `Time.from_quote("00:01:23")` 함수를 암시적으로 호출해요. 이렇게 하면 런타임에 파싱을 처리할 필요가 없어서 프로그램 속도를 높일 수 있고, `from_quote`가 거부한 시간은 런타임이 아니라 컴파일 시점에 잡을 수 있어요. 게다가 코드가 깔끔하고 읽기 쉬워져요. 예를 들어, 이 연습 문제의 테스트 중 하나를 볼까요:

```roc
## start initiates time tracking for current lap
expect {
	result = Stopwatch.create()
		.start()?
		.advance_time("00:00:05")
		|> expect_current_lap("00:00:05")

	result.is_ok()
}
```

그런데 이 코드를 읽는 사람은 `advance_time` 함수가 `Str` 타입을 받는다고 생각할 수 있지만, 실제로는 `Time` 타입을 받아요. 이러면 혼란과 오류가 생길 수 있어요. 그래서 조금 길지만 더 명확한 형식인 `"00:00:05".Time`을 선호할 수도 있어요. 이 형식 역시 컴파일 시점에 `from_quote`를 호출해요.

직접 작성하는 프로그램에서는 대신 `from_str` 함수를 쓰는 편이 좋아요:

```roc
Time := { ... }.{
    from_str : time_str -> Try(Time, [InvalidTime])
    from_str = |time_str| ...
}
```

`from_str`, 또는 다른 순수 함수는 컴파일 시점에 호출할 수도 있어요. 이렇게요:

```roc
Ok(time) = Time.from_str("00:01:23")
```

참고: 이 정의를 최상위 수준에 두면 컴파일 시점에 실행돼요(함수가 순수하고 입력이 컴파일 시점에 알려져 있기 때문이에요). 함수 안에서는 런타임에 `from_str`를 사용할 수 있어요.
