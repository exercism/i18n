# 지침 추가

## Python에서 이 연습 문제가 구성되는 방식

한 달의 다섯 번째 요일이 있을 때를 위한 추가 서술자(`fifth`)를 넣었어요.  
한 달에 다섯 번째 요일이 없으면 예외를 발생시켜야 해요.

## 예외를 사용자 정의하고 발생시키기

code에서 예외를 [사용자 정의](https://docs.python.org/3/tutorial/errors.html#user-defined-exceptions)하고 [`raise`](https://docs.python.org/3/tutorial/errors.html#raising-exceptions)해야 할 때가 있어요. 이럴 때는 오류의 원인이 무엇인지 알려 주는 **의미 있는 오류 메시지**를 항상 포함해야 해요. 그러면 code를 더 읽기 쉽게 만들고 디버깅에 큰 도움이 돼요.

사용자 정의 예외는 새로운 예외 클래스로 만들 수 있어요(자세한 내용은 [`classes`](https://docs.python.org/3/tutorial/classes.html#tut-classes)를 참고해요). 이런 클래스는 보통 [`Exception`](https://docs.python.org/3/library/exceptions.html#Exception)의 서브클래스예요.

오류의 원인이 특정 예외 타입에서 파생된 것임을 알고 있는 상황이라면, _Exception_ 클래스 아래에 있는 [`built in error types`](https://docs.python.org/3/library/exceptions.html#base-classes) 중 하나를 상속받는 쪽을 선택할 수 있어요. 이때도 오류를 발생시킬 때는 의미 있는 메시지를 꼭 포함해야 해요.

이 연습 문제에서는 `meetup()` 함수에 유효하지 않은 요일 이름과 숫자 조합이 주어졌을 때 [발생](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement)시키거나 "던질" _사용자 정의 예외_를 만들어야 해요. 테스트는 알맞은 예외를 사용자 정의하고, 그 예외를 `raise`하고, 알맞은 오류 메시지를 포함할 때만 통과해요.

`built-in exception`을 사용자 정의하려면 그 예외를 상속받는 `class`를 만들어요. 메시지와 함께 사용자 정의 예외를 발생시킬 때는 메시지를 `exception` 타입의 인자로 써요:

```python
# subclassing the built-in ValueError to create MeetupDayException
class MeetupDayException(ValueError):
    """Exception raised when the Meetup weekday and count do not result in a valid date.

    message: explanation of the error.

    """
    def __init__(self, message):
        self.message = message

        
# raising a MeetupDayException
raise MeetupDayException("That day does not exist.")
```
