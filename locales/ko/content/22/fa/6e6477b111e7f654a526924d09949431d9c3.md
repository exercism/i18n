# 개요

파일은 디스크에 이름을 가진 스트림이에요. [`io.files`][io.files] vocabulary는 파일을 다루는 두 가지 방법을 제공해요. 첫째는 한 번의 호출로 파일 전체를 읽거나 쓰는 편의 워드이고, 둘째는 조금씩 읽고 쓰기 위한 스트림 열기 워드(`with-…` 컴비네이터)예요. 두 방법 모두 `io-streams` 개념의 메모리 내 스트림과 같은 [스트림 프로토콜][stream-protocol]을 따르고, `<file-reader>`와 `<string-reader>`는 같은 워드에 똑같이 응답해요.

모든 파일 워드는 **인코딩**을 받아요. 인코딩은 바이트를 문자로, 다시 문자를 바이트로 대응시키는 방식이에요. 텍스트라면 거의 항상 `io.encodings.utf8`의 [`utf8`][utf8] 인코딩을 쓰고, 이진 데이터를 다룰 때는 `latin1`이나 `<byte-array>` 인코딩을 써요.

## 파일 전체 읽기

```
file-contents   ( path encoding -- str )
file-lines      ( path encoding -- seq )
```

`file-contents`는 파일 전체를 하나의 문자열로 반환해요. `file-lines`는 줄바꿈 문자를 떼어 낸 줄들을 배열로 반환해요. 각 줄이 하나의 레코드일 때 유용하죠.

```factor
USING: io.encodings.utf8 io.files ;

"forecast.txt" utf8 file-contents   ! => "sunny\ncloudy\n"
"forecast.txt" utf8 file-lines      ! => { "sunny" "cloudy" }
```

## 파일 전체 쓰기

```
set-file-contents   ( str path encoding -- )
set-file-lines      ( seq path encoding -- )
```

두 워드 모두 파일을 **덮어써요**. 파일이 없으면 새로 만들어요. `set-file-contents`는 문자열을 그대로 쓰고, `set-file-lines`는 시퀀스의 각 원소를 한 줄에 하나씩 쓰면서 줄바꿈 문자를 넣어 줘요.

```factor
{ "sunny" "cloudy" } "forecast.txt" utf8 set-file-lines
! forecast.txt now holds "sunny\ncloudy\n"
```

## 스코프가 있는 스트림

파일에 내용을 덧붙이거나 조금씩 읽고 쓰고 싶다면, `with-…` 컴비네이터로 파일을 열고 quotation 안에서 현재 스트림을 다루는 워드를 써요:

```
with-file-reader     ( path encoding quot -- )
with-file-writer     ( path encoding quot -- )
with-file-appender   ( path encoding quot -- )
```

```factor
USING: io io.encodings.utf8 io.files ;

"log.txt" utf8 [ "another line" print ] with-file-appender
```

`with-file-writer`는 파일을 먼저 잘라 내고, `with-file-appender`는 기존 내용을 남겨 둔 채 그 뒤에 써요. 둘 다 소멸자 스코프라서 quotation이 끝나면 파일 핸들이 닫혀요. 중간에 오류가 나더라도요. 이는 `boatswains-bilge` 컴비네이터가 제공하는 것과 같은 보장을 파일에 맞게 특화한 거예요.

## 파일 전체를 다룰까요, 스코프로 다룰까요?

파일이 메모리에 담을 만큼 작고 전체를 한 번에 다루고 싶다면 `file-contents` / `file-lines` / `set-file-contents` / `set-file-lines`을 써요. 덧붙여야 하거나, `readln`으로 큰 파일을 한 줄씩 스트리밍해야 하거나, 읽기와 쓰기를 번갈아 해야 한다면 `with-…` 열기 워드를 써요. 파일 전체를 메모리에 담아 두는 게 낭비이거나 아예 잘못인 상황이라면 어디든요.
