# 소개

[패턴 매칭][pattern-matching]은 표현력 있는 분기 코드를 가능하게 하고, [구조 분해][destructuring]는 값을 변수에 우아하게 바인딩해 줘요.
Elm 프로그래머라면 둘 다 꼭 익혀 둘 만하고, 함께 사용하면 코드 가독성이 크게 좋아져요.

## 단순한 패턴 매칭

패턴 매칭은 다루는 데이터의 형태에 따라 분기하는 코드를 말해요.
그래서 어떤 데이터가 가질 수 있는 여러 형태를 표현하는 커스텀 타입 개념과 자연스럽게 어울려요.
예를 들어 `Blue` 또는 `Red` 중 하나로 정의된 `Color` 커스텀 타입이 있다면, 색을 패턴 매칭해서 알맞은 문자열을 반환하는 `toString` 함수를 작성할 수 있어요.

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

패턴 매칭은 단순한 열거형이 아닌 커스텀 타입에도 동작해요.
사람 이름이나 아무것도 담지 않은 `Maybe String`을 매개변수로 받는 `hello` 함수를 생각해 봐요.
패턴 매칭을 할 때는 데이터에 소문자로 된 이름을 붙여 그 데이터를 변수에 바인딩할 수 있고, 매치의 오른쪽에서 그 변수를 사용할 수 있어요.

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

패턴 매칭은 모든 경우를 다뤄야 하고, 그렇지 않으면 컴파일러가 컴파일을 거부해요.
그런데 때로는 어떤 데이터나 case 식의 일부 분기에 신경 쓰고 싶지 않을 때가 있어요.
그럴 때는 바인딩할 변수 이름을 찾고 모든 경우에 대한 분기를 만들 필요 없이, 밑줄 와일드카드 `_`를 사용할 수 있어요.

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## 고급 패턴 매칭

커스텀 타입 외에도 `Char`, `String`, `Int`, `Floats`처럼 리터럴을 가지는 타입을 패턴 매칭할 수 있어요.

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

중첩 없이 여러 값을 매칭하려면, 매칭할 값들을 [_애드혹 튜플_][ad-hoc-tuples]로 묶는 것이 Elm에서 흔히 쓰는 방법이에요.

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

그리고 함수형 프로그래머에게 리스트는 각별한 존재인데, 리스트 역시 [패턴 매칭할 수 있어요][pattern-match-lists]. 리스트를 만들 때와 같은 문법, 즉 `::` 연산자를 사용하면 돼요.

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

마지막으로, 패턴 매칭은 재귀적으로도 동작해서 복잡하고 재귀적인 타입을 깊이 파고들 수 있게 해줘요.

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## 구조 분해

구조 분해는 타입 안의 데이터를 변수에 바인딩할 수 있다는 점에서 패턴 매칭과 아주 비슷해요.
주된 차이는, 가능한 형태가 하나뿐일 때는 그 방식을 "구조 분해"라고 부르고, 여러 형태일 때는 패턴 매칭이라고 부른다는 점이에요.
구조 분해는 `let` 바인딩이나 함수 인자에서 자주 볼 수 있고, 물론 패턴 매칭과 섞여 case 식에서도 나타나요.

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

구조 분해는 변형이 하나뿐인 커스텀 타입, 튜플, 그리고 레코드에 사용할 수 있는데, 레코드에서는 특히 편리해요.
[레코드를 구조 분해][records-pattern-matching]할 때는 필드를 하나, 둘, ..., 또는 전부, 원하는 만큼 사용할 수 있어요.

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

아쉽게도 Elm 문법으로는 레코드를 재귀적으로 구조 분해할 수 없어요.
앞선 `Circle` 예제에서는 원의 중심이 가진 `x`` and `y 위치에 한 번에 접근할 방법이 없어요.
먼저 `center`에 접근한 다음, 그것을 구조 분해해서 `x`와 `y` 위치를 얻어야 해요.

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

그리고 마지막 팁이 하나 더 있어요!
때로는 어떤 것 전체와 그 일부분 모두에 손쉽게 접근하고 싶을 때가 있어요.
이럴 때 [`as` 키워드][as-keyword]가 유용해요.
전체에는 별칭을 붙이면서도 그 내용은 구조 분해할 수 있게 해줘요.

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
