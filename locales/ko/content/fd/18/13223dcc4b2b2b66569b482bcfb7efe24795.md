# 지침 추가

## 예외 사용자 정의와 발생시키기

때로는 코드에서 예외를 [사용자 정의](https://docs.python.org/3/tutorial/errors.html#user-defined-exceptions)하고 [`raise`](https://docs.python.org/3/tutorial/errors.html#raising-exceptions)해야 할 필요가 있어요. 이렇게 할 때는 오류의 원인이 무엇인지 알려 주는 **의미 있는 오류 메시지**를 항상 포함해야 해요. 그러면 코드를 더 읽기 쉽게 만들고 디버깅에 큰 도움이 돼요.

사용자 정의 예외는 새로운 예외 클래스를 통해 만들 수 있어요(자세한 내용은 [`classes`](https://docs.python.org/3/tutorial/classes.html#tut-classes)를 참고해요). 이런 클래스는 보통 [`Exception`](https://docs.python.org/3/library/exceptions.html#Exception)의 하위 클래스예요.

오류 원인이 특정 예외 타입에서 파생된 것임을 알고 있는 상황이라면, _Exception_ 클래스 아래에 있는 [`built in error types`](https://docs.python.org/3/library/exceptions.html#base-classes) 중 하나를 상속받도록 선택할 수 있어요. 오류를 발생시킬 때도 여전히 의미 있는 메시지를 포함해야 해요.

이 연습 문제에서는 스택이 충분히 채워지지 않았을 때 [발생](https://docs.python.org/3/reference/simple_stmts.html#the-raise-statement)시키거나 "던지는" _사용자 정의 예외_를 만들어야 해요. 적절한 예외를 사용자 정의하고, 그 예외를 `raise`하고, 적절한 오류 메시지를 포함해야만 테스트를 통과할 수 있어요.


```python
# subclassing the Exception to create a StackUnderflowError
class StackUnderflowError(Exception):
    """Exception raised when Stack is not full.
       message: explanation of the error.
    """
    def __init__(self, message):
        self.message = message

        
# raising a StackUnderflowError
raise StackUnderflowError("Insufficient number of items in stack")
```

또한 이 연습 문제에서는 오류 메시지와 함께 몇 가지 `built-in exceptions`를 발생시켜야 해요.
메시지와 함께 `built-in exception`을 발생시키려면, 메시지를 `exception` 타입의 인자로 작성해요:

```python
# an example when division by zero is attempted.
raise ZeroDivisionError("divide by zero")

#an example when the operation is undefined.
raise ValueError("undefined operation")
```
