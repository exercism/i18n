# 개요

C#에서 튜플은 데이터를 정리하는 자료 구조로, 어떤 타입의 필드든 두 개 이상 담을 수 있어요.

튜플은 보통 두 개 이상의 식을 쉼표로 구분해 괄호 안에 넣어 만들어요.

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

튜플은 여느 식과 마찬가지로 여러 방식으로 쓸 수 있어요. [대입][tuple-assignment]에 쓰거나, 필드나 변수를 초기화하거나, 메서드의 [반환 값][tuple-return-values]으로 쓰거나 매개변수로 전달할 수 있죠. 튜플은 [동등성][tuple-equality]을 검사할 수도 있어요. 튜플의 동등성은 `pattern-matching-tuples` 연습 문제에서 자세히 설명하지만, 여기서도 완전성을 위해 아래 코드에 예제를 넣어 두었어요.

필드는 점 표기법으로 꺼내요. 기본적으로 첫 번째 필드는 `Item1`, 두 번째는 `Item2`이고, 이런 식으로 이어져요. 기본이 아닌 이름은 아래 _이름 지정_에서 다뤄요.

튜플은 제네릭 매개변수로도 쓸 수 있어요. 예를 들어 `IList<(bool, string)>`처럼요.

게다가 튜플은 아래에서 다루는 "분해"를 지원하고, 뒤의 연습 문제에서 다루는 패턴 매칭에도 쓸 수 있어요.

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

이 [소개][tuples]에서는 튜플을 정의하고 사용하는 방법을 보여줘요.

## 이름 지정

`Item1` 같은 필드 이름만으로는 읽기 좋은 코드가 되지 않아요. 필드에 이름을 붙이는 방법은 세 가지가 있어요. a) 타입 선언에서 붙이거나, b) 튜플을 만드는 식에서 붙이거나, c) [튜플 프로젝션 이니셜라이저][tuple-projection-initializers]를 이용하는 방법이에요(여기서는 다루지 않아요).

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

이름 지정 방식에 너무 기교를 부리지 마세요. 사실 이것은 그저 문법적 설탕일 뿐이에요. 예를 들어, 다른 튜플을 대입할 때 그 튜플의 필드 이름을 바꿀 수는 없어요.

## 분해

때로는 튜플의 필드를 여러 변수에 나눠 담고, 필요하면 그 변수들을 초기화하는 게 편할 때가 있어요. 이런 방식을 [분해][tuple-deconstruction]라고 해요. (직접 만든 객체에도 적용할 수 있어요. [여기][udt-deconstruction]를 참고하세요.)

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## 필드 대입

튜플의 필드에는 개별적으로 값을 대입할 수 있어요. 하지만 C#이 불변성을 지향하는 추세라 이런 사용법은 흔하지 않아요. 튜플은 흔히 불변인 것처럼 쓰이지만, 물론 불변이 아니에요.

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## 배경

여기서 다루는 튜플을 [`System.Tuple`][system-tuple]과 혼동하면 안 돼요. `System.Tuple`은 아마 레거시 코드베이스에서만 볼 수 있을 거예요.

`System.ValueTuple`로 넘어오면 상황이 조금 더 헷갈려요. [`System.ValueTuple`][system-value-tuple]의 마지막 오버로드에 대한 [문서][system-value-tuple]에는 이렇게 나와 있어요. "값 튜플 타입은 C#에서 튜플을 지원하는 런타임 구현을 제공합니다." 여기서 "값 튜플 타입"은 `System.ValueTuple`의 제네릭 오버로드를 가리켜요. "튜플"이라고 할 때는 이 연습 문제에서 다뤄 온 바로 그것을 뜻하고요. 사실상 `System.ValueTuple`은 튜플의 구현 세부 사항이라고 말하는 셈이에요. 대부분의 사람에게는 별로 흥미로운 얘기가 아닐 거예요. 안타깝게도 마이크로소프트 문서를 비롯해 "튜플"에 관한 문서 곳곳에 `System.ValueTuple`에 대한 언급이 잔뜩 등장해요. 그런 언급은 그냥 넘어가도 괜찮아요.

## 그 밖의 용도와 한계

패턴 매칭은 튜플을 특히 유용하게 쓸 수 있는 방법이에요. 이 내용은 뒤의 연습 문제에서 다뤄요.

튜플을 이용하면 몇 가지 자잘한 스타일 기교도 부릴 수 있어요.

- 다중 대입(특히 생성자에서) 예: `(this.field1, this.field2) = (arg1, arg2);`
- 값 맞바꾸기나 재활용 예: `(a, b) = (b, a);`
- 리스트에서 `struct` 대신 사용하기
- 딕셔너리 키나 집합의 내용으로 사용하기
- LINQ에서 사용하기. (LINQ는 뒤의 연습 문제에서 다뤄요.)

문서에서는 튜플을 가벼운 메커니즘이라고 설명하는데, 바로 그 점이 튜플을 잘 쓰는 비결이에요. 클래스나 구조체 대신 튜플을 쓰면 필드 타입과 어쩌면 이름까지 지루하게 반복하게 될 수 있어요. 특히 메서드 인자로 쓰거나 컬렉션의 제네릭 인자로 쓸 때 그렇죠.

다중 대입이나 값 맞바꾸기 같은 기법은 적절히 사용하는 게 좋아요.

동등성과 비동등성 비교를 제외한 관계 연산은 지원하지 않아요.

튜플은 비교적 최근(C# 7)에 언어에 도입됐으니, 튜플을 쓰려면 코드베이스에서 언어의 [버전][language-version] 7 이상을 사용하고 있는지 확인하세요.
