# 정보

네임스페이스를 전혀 사용하지 않는 프로덕션 코드를 만나는 일은 거의 없어요.

문법 예시는 다음과 같아요:

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

네임스페이스는 관련 있는 코드를 묶고 이름 충돌을 피하는 방법이에요.

[공식 문서][namespaces]에 따르면 네임스페이스에는 두 가지 주요 역할이 있어요:

- 첫째, .NET은 네임스페이스로 수많은 클래스를 체계적으로 정리해요.
- 둘째, 네임스페이스를 직접 선언하면 규모가 큰 프로그래밍 프로젝트에서 클래스와 메서드 이름의 스코프를 관리하는 데 도움이 돼요.

기본 클래스 라이브러리(BCL)는 이런 네임스페이스를 폭넓게 사용해 기능을 구성해요.

## 네임스페이스에 포함된 형식 참조하기

네임스페이스에 포함된 형식은 네임스페이스 밖에서 참조할 때 형식 이름 앞에 점 구문을 붙여요. 또는 더 흔하게는 파일 맨 위(또는 네임스페이스 안)에 `using` 지시문을 두면, 가져온 네임스페이스의 모든 형식을 접두사 없이 사용할 수 있어요. 같은 네임스페이스 안에서는 형식 이름을 한정할 필요가 없어요.

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

이 [글][using]에서는 `using` 지시문을 사용하는 방법을 명확하게 설명해요:

- `using`: 형식을 네임스페이스로 한정하지 않아도 돼요.
- `using static`: 멤버를 형식으로 한정하지 않아도 돼요(좋은 예가 `Math.Max()`예요).
- `using MyAlias = YourNamespace;`: 네임스페이스 이름 대신 읽기 쉬운 이름을 사용할 수 있어요.

## 네임스페이스 충돌

서로 다른 어셈블리에 이름이 같은 네임스페이스가 두 개 있어 완전히 정규화된 식별자 이름이 충돌하는 경우가 있어요(어셈블리 여러 버전이 로드되는 상황일 수 있어요). .NET은 이 문제를 [네임스페이스 별칭 한정자][namespace-alias-qualifier]와 [extern 별칭][extern-alias]으로 해결해요.

이 다소 특수한 주제를 언급하는 이유 중 하나는 [`::` 연산자][dot-dot-operator]를 사용하기 때문이에요. 특히 생성된 코드에서 네임스페이스 앞에 `global::` 한정자가 붙은 모습을 자주 보게 돼요. 여기서 의도는 중첩된 네임스페이스나 클래스 이름과 충돌할 가능성을 피하는 거예요. 네임스페이스 앞에 `global::`를 붙이면 최상위 네임스페이스가 선택되도록 보장할 수 있어요.

## Java 개발자를 위한 참고 사항

Java `packages`의 `import`와 비교하면 몇 가지 차이점과 유사점을 짚어볼 필요가 있어요:

- C#에는 특정 형식만 가져오는 기능에 해당하는 것이 없어요.
- `using static`과 `import static`은 서로 같아요.
- Java에서는 패키지 이름이 jar 사이의 접근성에 영향을 줘요. C#에서는 어셈블리가 가장 중요하고, 같은 네임스페이스에 속하는지는 접근 수준에 영향을 주지 않아요.
- Java에서 파일 시스템 경로와 완전히 정규화된 클래스 이름 사이의 관계는 C#의 네임스페이스에는 반영되지 않아요. 다만 가능하면 파일에 그 안에 담긴 주요 클래스와 같은 이름을 붙이는 것이 좋은 관행이에요.
