# 지침 추가

## Odin 관련 지침

### 이진 트리에서의 zipper

위 지침에서는 rose tree(노드마다 자식이 여러 개)를 사용해 zipper를 설명하지만, zipper 개념은 어떤 트리에도, 심지어 배열에도 적용할 수 있어요.
이 연습 문제에서는 이진 트리(각 노드에 자식이 두 개)를 사용해서, 자식 수를 동적으로 관리하는 일에 신경 쓰는 대신 zipper 연산에 집중할 수 있어요.

지침에 나열된 연산은 다음과 같이 이진 트리에 맞게 바뀌었어요:

| 연산            | 설명                                                                       |
| --------------- | -------------------------------------------------------------------------- |
|`zip_from_tree`  | 트리에서 zipper를 꺼내요. 포커스는 루트 노드에 있어요.                     |
|`zip_to_tree`    | zipper에서 트리를 꺼내요.                                                  |
| `zip_value`     | 포커스 노드의 값을 가져와요.                                               |
| `zip_left`      | 포커스를 포커스 노드의 왼쪽 자식으로 옮기고, 새로운 zipper를 반환해요.     |
| `zip_right`     | 포커스를 포커스 노드의 오른쪽 자식으로 옮기고, 새로운 zipper를 반환해요.   |
| `zip_up`        | 포커스를 포커스 노드의 부모로 옮기고, 새로운 zipper를 반환해요.            |
| `zip_set_value` | 포커스 노드의 값을 설정하고, 새로운 zipper를 반환해요.                     |
| `zip_set_left`  | 포커스 노드의 왼쪽 서브트리를 설정하고, 새로운 zipper를 반환해요.          |
| `zip_set_right` | 포커스 노드의 오른쪽 서브트리를 설정하고, 새로운 zipper를 반환해요.        |

### 메모리 관리

Odin에서는 메모리를 직접 관리해야 해요.
연습 문제를 단순하게 만들고 zipper 연산에 집중할 수 있도록, 트리 노드와 trail에 할당된 메모리는 arena 할당자를 통해 자동으로 관리돼요.
`new(Node)`와 `new(Step)`으로 필요할 때만 메모리를 할당하면 돼요. 트리 작업을 마치면 테스트가 arena의 `free_all()`을 자동으로 호출해요.
이 방식은 게임 루프나 요청/응답 묶음처럼 주기적으로 반복되는 작업에서 Odin으로 메모리를 할당할 때 쓰는 관용적인 방법이에요.

Odin의 할당자, 그중에서도 arena 할당자에 대해 더 알아보고 싶다면 다음 문서가 도움이 될 거예요: [Odin 개요의 할당자 장][allocators-overview], [Understand the Temporary Allocator; Understand arenas by Karl Zylinski][allocators-zylinksi], [Linear/Arena Allocators by gingerBill][allocators-gingerbill].
