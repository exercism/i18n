# 개요

[`Box`][box]를 이해하려면 [스택과 힙][stack and heap]이 무엇인지 먼저 알아두면 좋아요.

스택은 후입선출(LIFO) 버퍼처럼 동작하는 메모리 영역이에요. 스택에 데이터를 밀어 넣는 것도 매우 빠르고, 꺼내는 것도 빨라요. 여기에는 변수나 함수 주소가 들어갈 수 있지만, 데이터는 컴파일 시점에 고정된 크기를 알 수 있어야 해요.

반대로 컴파일 시점에 크기를 알 수 없거나 크기가 바뀔 수 있는 데이터라면 힙에 할당해야 해요. 할당 과정에서는 데이터를 저장할 만큼 큰 공간을 힙에서 찾고, 데이터를 힙에 쓰고, 그 데이터의 메모리 주소를 스택에 넣어야 하는데, 이 모든 작업은 데이터를 스택에 그냥 넣는 것보다 훨씬 오래 걸려요. 힙에서 데이터를 가져오는 것도 조금 느린데, 스택에 있는 주소를 거쳐 힙에서 데이터가 있는 위치까지 따라가야 하기 때문이에요.

`Box`는 데이터를 힙에 할당하는 스마트 포인터예요. 주소는 스택에 있고, 힙에 있는 데이터를 가리켜요. `Box`를 사용하는 [이유][reasons] 중 하나는, 크기를 컴파일 시점에 알 수 없는 타입이 있고 그 타입의 값을 정확한 크기가 필요한 상황에서 쓰고 싶을 때 데이터를 힙에 두기 위해서예요. 대표적인 활용 예는 여러 구조체를, 그 모두가 구현하는 하나의 트레이트를 통해 같은 방식으로 다루고 싶을 때예요. 아래에서 예를 들어 볼게요.

구조체 두 개가 있다고 해봐요. 각 구조체는 짜증 나게 할 수 있는 무언가를 나타내요. 다음과 같이 각 구조체가 Annoyance 트레이트를 구현하도록 할 수 있어요.

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

이번에는 넘겨받은 시간대에 따라 Annoyance를 돌려주는 함수를 만들고 싶다고 해봐요. 먼저 이렇게 시도해 볼 수 있는데, 컴파일되지 않는다는 걸 알게 돼요.

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

컴파일러는 친절하게도 무엇을 해야 하는지 정확히 알려줘요. 바로 박싱된 트레이트 객체를 반환하는 거예요. 트레이트 객체가 무엇인지 모른다면, 간단히 말해 지정된 트레이트를 구현하는 어떤 객체든 반환할 수 있는 함수에서 [동적 디스패치][dynamic dispatch]를 통해 특정 객체를 반환하는 방법이라고 할 수 있어요. 동적 디스패치가 필요하니, 트레이트 이름 앞에 그냥 `dyn`을 붙여서 되는지 한번 해볼 수 있어요.

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

오류 중 하나는 `dyn Annoyance`의 크기를 컴파일 시점에 알 수 없다는 거예요. `annoy_me`는 호출되기 전에 어떤 트레이트 객체를 반환할지 알 수 없기 때문이에요. Annoyance를 구현하는 구조체는 서로 다른 필드를 가질 수도 있고 크기도 다를 수 있어요. 그리고 `Box`의 용도 중 하나가 바로 크기를 컴파일 시점에 알 수 없는 타입을 위한 것이라는 점도 떠올리게 돼요. 그래서 이번에는 `Box`로 감싼 반환값을 사용해 보고, `match` 식에서 반환되는 값들을 `Box`로 감싸요. 이렇게요.

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

`Box`의 시그니처는 `Box<T>`이고, 여기서 `T`는 박싱할 구체적인 타입을 나타내며 꺾쇠괄호 안에 들어가요. 위의 `Box<dyn Annoyance>`처럼요.

박싱된 트레이트 객체는 이렇게 사용할 수 있어요.

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

이 코드는 다음을 출력해요.

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

`my_annoyance`는 `Box<dyn Annoyance>` 타입이므로, 역참조 연산자 `*`를 사용해 `Box`에서 역참조해야 해요. 그러면 `be_annoying` 함수가 빌려갈 수 있도록 `dyn Annoyance`로 참조돼요.

다른 방법은 매개변수가 크기를 가져야 한다는 요구사항을 없애는 거예요. 그러면 컴파일 시점에 Annoyance의 각 변형마다 별도의 함수를 만들어 정적 디스패치를 할 수 있는데(이 과정을 [단형화][monomorphization]라고 해요), 이렇게요.

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

또 다른 방법은 `be_annoying` 함수가 `Box<dyn Annoyance>`를 받도록 하고 [역참조 강제][deref coercion]를 사용해 `Box`를 직접 역참조하지 않아도 되게 하는 거예요. 이 경우 Annoyance 트레이트 객체의 소유권이 `be_annoying` 함수로 넘어가요. 그러면 함수가 끝날 때 스코프를 벗어나 더 이상 사용할 수 없게 돼요.

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
