# درباره

فاکتور ورودی/خروجی جریانی را به دو لایه تقسیم می‌کند. لایه‌ی پایین‌تر API *جریان صریح* است: هر واژه جریان را به عنوان آرگومان می‌گیرد. لایه‌ی بالاتر API *جریان محیطی* است: واژه‌های کوتاه و یک‌خطی که روی هر جریانی که در آن لحظه متصل است عمل می‌کنند. هر دو لایه روی همان [پروتکل][stream-protocol] سوارند؛ واژه‌های لایه‌ی بالایی فقط جریان محیطی را می‌جویند و فراخوانی را هدایت می‌کنند.

## واژه‌های جریان صریح

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents` همه‌چیز را تخلیه می‌کند؛ `stream-lines` تخلیه می‌کند و بر مرزهای خط تقسیم می‌کند؛ `stream-readln` هر بار یک خط برمی‌گرداند (یا در پایان جریان `f`).

## واژه‌های جریان محیطی

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

این‌ها واژه‌های روزمره‌ی I/O هستند. جریان ورودی یا خروجی جاری را از متغیرهای پویای `input-stream` / `output-stream` بازیابی می‌کنند و فراخوانی را هدایت می‌کنند. به همین دلیل، تغییر مسیر دادن `print` به یک رشته فقط به متصل کردن `output-stream` در طول اجرای یک کوتیشن نیاز دارد.

## سازنده‌های جریان همراه

| واژه              | واژگان                | آنچه می‌سازد                    |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | یک رشته‌ی عینی را می‌خواند |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | نوشتن‌ها را در یک رشته جمع می‌کند |
| `<file-reader>`   | [`io.files`][io.files]           | یک فایل را با یک کدگذاری می‌خواند |
| `<file-writer>`   | [`io.files`][io.files]           | یک فایل را با یک کدگذاری می‌نویسد |

هر چهار مورد شیءهایی قابل‌آزادسازی تولید می‌کنند، چون `disposable` را از `destructors` گسترش می‌دهند؛ بنابراین ترکیب‌گرهای `with-…` زیر آن‌ها را هنگام خروج آزاد می‌کنند.

## اتصال دامنه‌محور

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

هر کدام یک جریان باز می‌کند، آن را به عنوان ورودی یا خروجی محیطی برای کوتیشن درونی متصل می‌کند و هنگام خروج آزادش می‌کند، حتی اگر کوتیشن خطا بدهد. این‌ها ترکیب‌گرهای تخریب‌گرِ `boatswains-bilge` هستند که برای جریان‌ها تخصص یافته‌اند.

`with-string-writer` گونه‌ای به‌ویژه پاکیزه است: به‌طور خودکار یک `<string-writer>` تازه می‌سازد، کوتیشن را با آن نویسنده به عنوان خروجی محیطی اجرا می‌کند و رشته‌ی انباشته‌شده را برمی‌گرداند. کل الگوی «گرفتن خروجی یک کوتیشن» فقط یک واژه است.

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## اصلاً چرا محیطی؟

اتصال متغیر پویا دلیل آن است که `print` در برنامه‌ای کار می‌کند که نمی‌داند به‌صورت تعاملی اجرا می‌شود، به یک فایل گزارش می‌نویسد، یا در بافر آزمونی ثبت می‌شود. کافی است اتصال را یک بار عوض کنید تا هر واژه‌ای که `print` را فراخوانی می‌کند کار درست را انجام دهد، بدون نیاز به سیم‌کشی مجدد. این همان وارونگی است که لایه‌ی بالایی برایتان به ارمغان می‌آورد.

برای *پیاده‌سازی* یک جریان، یعنی تعریف کلاس خودتان که به پروتکل وصل می‌شود، مفهوم `streams` را ببینید (که در `telegraphers-tape` آموزش داده می‌شود).
