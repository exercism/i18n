# کلاس‌های جنریک

شما از همان اوایل از `ARRAY{STR}`، `FMAP{STR,INT}` و `FSET{STR}` استفاده کرده‌اید. آکولادها همیشه یک نوع را در خود داشته‌اند. حالا خودتان کلاسی می‌نویسید که آکولادهای خودش را دارد.

## مسئله

اداره‌ی اشیای گمشده به جعبه‌ای نیاز دارد که یک شیء را نگه دارد و به خاطر بسپارد چه کسی آن را تحویل داده است. یک جعبه برای پلیور:

```sather
class JUMPER_BOX is
   attr item : JUMPER;
   ...
end;
```

و بعد همان کلاس را دوباره برای یک بطری آب و باز هم برای یک تلفن می‌نویسید. سه نسخه که فقط در یک کلمه تفاوت دارند.

## پارامتر نوع

```sather
class LOST_BOX{T} is

   attr item : T;

   create(thing : T) : SAME is
      box ::= new;
      box.item := thing;
      return box;
   end;

end; -- class LOST_BOX{T}
```

`{T}` پس از اسم کلاس، یک **«پارامتر نوع»** است. `T` خودش یک نوع نیست؛ جانشینی است برای هر نوعی که هنگام استفاده از کلاس داده می‌شود. در داخل کلاس، `T` دقیقاً همان‌طور به کار می‌رود که هر نوع دیگری به کار می‌رود.

## استفاده از آن

نوع را داخل آکولادها بدهید:

```sather
   jumper ::= #LOST_BOX{STR}("blue jumper");
   count ::= #LOST_BOX{INT}(3);

   jumper.item      -- "blue jumper", a STR
   count.item       -- 3, an INT
```

`LOST_BOX{STR}` و `LOST_BOX{INT}` دو نوع متفاوت‌اند. اگر یکی را جایی به کار ببرید که دیگری لازم است، خطایی است که کامپایلر آن را تشخیص می‌دهد؛ دقیقاً مثل این می‌ماند که آن دو کلاس را دستی نوشته باشید. و در واقع همین اتفاق هم می‌افتد: Sather برای هر نوعی که واقعاً استفاده شود، یک کلاس جداگانه از آن الگو می‌سازد.

پس این کار در زمان اجرا هیچ هزینه‌ای ندارد و هیچ اطلاعات نوعی هم از دست نمی‌رود: `jumper.item` واقعاً یک `STR` است، نه مقداری که باید بررسی یا تبدیل شود.

## بیش از یکی

یک کلاس می‌تواند چندین پارامتر بگیرد که با ویرگول از هم جدا می‌شوند. `FMAP{K,T}` همان مثالی است که پیش‌تر می‌شناسید.

```sather
class LABELLED{L,T} is
   attr label : L;
   attr item : T;
   ...
end;
```

## اسم‌گذاری

طبق قرارداد، حروف بزرگ تک‌حرفی به کار می‌روند: `T` برای یک شیء، `K` برای یک کلید و `E` برای یک عنصر. کتابخانه در همه‌جا از همین‌ها استفاده می‌کند.
