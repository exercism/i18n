# درباره

کد اسکالر برای انشعاب در پاسخ به یک شرط خاص، به پرچم‌هایی تکیه می‌کند که دستورهای مختلف تنظیم می‌کنند.
اما مقادیر بسته‌بندی‌شده نه یک مقدار، بلکه بسیاری از مقادیر را به‌صورت موازی نمایش می‌دهند.
یک شرط واحد ممکن است برای یک خط ناموفق و برای خط دیگری موفق باشد.

به همین دلیل است که کد SIMD به‌طور پیش‌فرض [بدون انشعاب][branchless-code] است.

مقایسه‌های بسته‌بندی‌شده به‌جای تکیه بر پرچم‌ها، معمولاً یک **ماسک** در عملوند مقصد تولید می‌کنند.
مقایسه برای هر خط، وقتی شرط درست باشد کل خط را با یک‌ها و وقتی نادرست باشد با صفرها پر می‌کند.
اگر به‌صورت یک عدد صحیح علامت‌دار خوانده شود، خط درست برابر `-1` و خط نادرست برابر `0` است.

سپس می‌توان این ماسک را همراه با [عملیات بیتی][simd-bitwise] به کار برد تا خط‌های خاصی را پالایش کرد.

## مقایسه‌های بسته‌بندی‌شده

یک `cmp` اسکالر از این نظر عمومی است که برای تنظیم هم‌زمان پرچم‌های مختلف به کار می‌رود.
سپس دستور دیگری می‌تواند از آن پرچم‌ها برای انشعاب یا انجام محاسبات استفاده کند.

اما چون یک مقایسه‌ی بسته‌بندی‌شده هم شرط را بررسی می‌کند و هم ماسک را محاسبه می‌کند، عمومی نیست.
باید شرط دقیقی که آزموده می‌شود به مقایسه داده شود.

دو راه برای این کار وجود دارد:

- به مقایسه‌های صحیح، شرط به‌صورت یک پسوند داده می‌شود: `eq` برای تساوی و `gt` برای بزرگ‌تر بودن.
  سایر گونه‌ها با ترکیب نتیجه‌ی یکی از این‌ها ساخته می‌شوند.
- به مقایسه‌های اعشاری، شرط به‌صورت کدشده در یک مقدار فوری داده می‌شود.
  مقادیر مختلف این مقدار فوری متناظر با شرط‌های مختلفی هستند که آزموده می‌شوند.

جز استفاده از یک پسوند شرطی مشخص در مقایسه‌های صحیح، نحوه‌ی نگارش از همان ساختاری پیروی می‌کند که پیش‌تر دیده‌ایم:

- برای اعداد صحیح، `p` + `cmp` + شرط + اندازه (`b`، `w`، `d` یا `q`).
- برای اعداد اعشاری، `cmp` + `p` + اندازه (`s` یا `d`).
  شرط به‌صورت یک عملوند اضافی در یک مقدار فوری منتقل می‌شود.

### مقایسه‌های صحیح

همان‌طور که گفته شد، مقایسه‌های صحیح فقط برای تساوی و بزرگ‌تر بودن وجود دارند:

| دستور                                      | توضیح                            |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | تساوی در هر خط                   |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | بزرگ‌تر بودن **علامت‌دار** در هر خط |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

برای ساختن یک مقایسه‌ی کوچک‌تر بودن، از `gt` با جابه‌جایی عملوندها استفاده کنید: `a < b` == `b > a`.

توجه کنید که مقایسه **علامت‌دار** است.
برای انجام یک مقایسه‌ی بدون علامت، بالاترین بیت هر دو عملوند را وارونه کنید.
این کار با یک XOR با ماسکی انجام می‌شود که فقط بالاترین بیتش تنظیم شده است.

~~~~exercism/note
دو شگرد کاربردی وجود دارد:

1. XOR کردن یک ثبات با خودش برای تولید همه‌صفر.
2. مقایسه‌ی یک ثبات با خودش برای تولید همه‌یک.

برای نمونه:

```x86asm
pxor    xmm4, xmm4 ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

همه‌صفر و همه‌یک ماسک‌های رایجی هستند که به‌ترتیب «نادرست در همه‌جا» و «درست در همه‌جا» را رمزگذاری می‌کنند.
از آن‌ها می‌توان برای نمایش `0` بسته‌بندی‌شده یا `-1` بسته‌بندی‌شده هم استفاده کرد که مقادیر نگهبان رایجی هستند.
برای نمونه، NUL که پایان یک رشته را مشخص می‌کند یک `0` است.
~~~~

### مقایسه‌های اعشاری

خط‌های اعشاری شکل متفاوتی دارند: یک دستور، `cmpps` (و `cmppd` برای خط‌های ۶۴ بیتی)، با شرط به‌صورت یک مقدار فوری:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM همچنین شبه‌عملگرهایی دارد که به مقدار فوری درست نگاشت می‌شوند و به‌خاطر سپردنشان آسان‌تر است.
در همه‌ی موارد زیر، `x` در `px` می‌تواند `s` (اعشاری ۳۲ بیتی) یا `d` (اعشاری ۶۴ بیتی) باشد:

| شبه‌عملگر    | مقدار فوری | مقایسه                |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | a عدد NaN است یا b عدد NaN است |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | نه a و نه b عدد NaN است |

~~~~exercism/caution
NaN به‌صورت نامرتب مقایسه می‌شود: نه کوچک‌تر از چیزی است، نه برابر با آن و نه بزرگ‌تر از آن، حتی نسبت به خودش.
گزاره‌های مرتب، مانند `cmpltps`، وقتی هر یک از عملوندها NaN باشد نتیجه‌ی نادرست می‌دهند، در حالی که گزاره‌های نامرتب نتیجه‌ی درست می‌دهند.
به همین دلیل `cmpordps` و `cmpunordps` وجود دارند تا NaN را به‌صورت صریح آزمون کنند.
~~~~

## انتخاب با یک ماسک

یک ماسک نتیجه‌ی یک شرط را رمزگذاری می‌کند.
سپس می‌توان از آن برای انتخاب خط‌به‌خط میان دو مجموعه مقدار بر اساس آن شرط استفاده کرد.
خط را از یک مقدار می‌گیریم که ماسک درست است و از مقدار دیگر که نادرست است:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

این الگو شکل بسته‌بندی‌شده‌ی انتخاب بدون انشعاب است.
هر خط محاسبه می‌شود و تنها ماسک تعیین می‌کند کدام مقدار باقی می‌ماند، بدون هیچ `jcc` در هیچ کجا.

## ترکیب‌های اختصاصی

دستورهایی وجود دارند که همان انتخاب را به‌صورت مستقیم انجام می‌دهند و برای هر عنصر یک بیت از یک ثبات ماسک می‌خوانند.
به آن‌ها دستورهای **ترکیب** می‌گویند:

| دستور      | عنصر       | منبع ماسک  |
|-------------|-------------|-----------------|
| `pblendvb`  | بایت        | `xmm0` ضمنی |
| `blendvps`  | خط ۳۲ بیتی  | `xmm0` ضمنی |
| `blendvpd`  | خط ۶۴ بیتی  | `xmm0` ضمنی |

توجه کنید که دستور اول از نحوه‌ی نگارش اعداد صحیح پیروی می‌کند، در حالی که دو دستور دیگر از نحوه‌ی نگارش اعداد اعشاری پیروی می‌کنند.
اما چون این دستورها صرفاً بایت‌های خام را انتخاب می‌کنند، هر یک از آن‌ها هم با اعداد صحیح و هم با اعداد اعشاری قابل استفاده است.

ترکیب برای هر عنصر، وقتی بالاترین بیت عنصر متناظر ماسک پاک باشد مقصد را نگه می‌دارد و وقتی تنظیم باشد منبع را برمی‌دارد.
تنها همان **بالاترین بیت** بررسی می‌شود، که یک ماسک مقایسه آن را برآورده می‌کند، چون خط‌هایش همه‌یک یا همه‌صفر هستند.
ثبات ماسک همیشه `xmm0` است که ضمنی است:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

همچنین می‌توان از `pblendvb` برای انتخاب خط‌ها از یک ماسک مقایسه برای هر اندازه‌ی دیگری استفاده کرد.
چون همه‌ی بایت‌های یک خط درست همه‌یک هستند، `pblendvb` همه‌ی آن‌ها را انتخاب می‌کند.

~~~~exercism/note
همه‌ی این دستورها یک `v` بعد از عملِ انجام‌شده (`blend`) اضافه می‌کنند.
این `v` مخفف _variable_ است، چون انتخاب ایستا نیست و به یک ثبات وابسته است.

گونه‌هایی هم بدون `v` وجود دارند که بر اساس یک مقدار فوری انتخاب می‌کنند.
آن‌ها از همان الگو پیروی می‌کنند و خط `i` را در صورتی انتخاب می‌کنند که بیت `i` آن مقدار فوری تنظیم باشد.
~~~~

## بازگشت از ماسک به اسکالر

کد SIMD با همه‌ی قدرتش، بخش زیادی از انعطاف کد اسکالر را ندارد.
در بسیاری از موقعیت‌ها لازم است از یک ثبات بسته‌بندی‌شده به دنیای دستورهای اسکالر بازگردیم.

خانواده‌ی دستورهای `movmsk` به‌عنوان پلی میان این دو دنیا عمل می‌کند.
این دستورها **بالاترین بیت** هر خط را در یک ثبات همه‌کاره استخراج می‌کنند:

| دستور      | گردآوری                    | عرض نتیجه |
|-------------|-----------------------------|--------------|
| `pmovmskb`  | بالاترین بیت هر یک از ۱۶ بایت | ۱۶ بیت      |
| `movmskps`  | بالاترین بیت هر یک از ۴ کلمه‌ی دوگانه | ۴ بیت       |
| `movmskpd`  | بالاترین بیت هر یک از ۲ کلمه‌ی چهارگانه | ۲ بیت       |

اگر بعد از یک مقایسه استفاده شود، هر بیت تنظیم‌شده نماینده‌ی یک خط «درست» و هر بیت پاک نماینده‌ی یک خط «نادرست» است.
سپس می‌توان این نتیجه را مثل همیشه با دستورهای اسکالر دستکاری کرد.
برای نمونه، یک `popcnt` تعداد تطابق‌ها را می‌شمارد و `tzcnt` اولین بیت تنظیم‌شده را پیدا می‌کند.

ثبات همه‌کاره می‌تواند ۳۲ بیتی یا ۶۴ بیتی باشد.

## آزمودن یک بردار کامل

گونه‌ی بسته‌بندی‌شده‌ای از دستور اسکالر `test` هم وجود دارد: `ptest`.

این دستور شبیه همتای اسکالرش است، از این نظر که یک عمل AND میان دو عملوند انجام می‌دهد بدون آنکه آن‌ها را تغییر دهد.
برخلاف `test`، دستور `ptest` یک عمل ANDN هم انجام می‌دهد و عملوند اول را نقیض می‌کند.

بنابراین می‌توان `ptest` را نسخه‌ای غیرمخرب از `pand` و `pandn` دانست که پرچم‌ها را بر اساس نتیجه تنظیم می‌کند.
`ptest` تقریباً به همان شیوه‌ی این دو دستور، کل ثبات SIMD را یک خط واحد در نظر می‌گیرد و بنابراین پیشوند اندازه نمی‌گیرد.

اگر نتیجه‌ی عمل AND برابر `0` باشد، پرچم `ZF` تنظیم می‌شود و اگر نتیجه‌ی عمل ANDN برابر `0` شود، این `CF` است که تنظیم می‌شود.
این یعنی می‌توان از `ptest` برای بررسی هم ماسک همه‌یک و هم ماسک همه‌صفر استفاده کرد:

1. استفاده از `ptest` روی یک ثبات با خودش، `ZF` را فقط در صورتی تنظیم می‌کند که ثبات همه‌صفر باشد.
   این کار همان شگرد رایج اسکالر را تقلید می‌کند: استفاده از `test` روی یک ثبات با خودش برای بررسی `0`.
2. استفاده از `ptest` روی یک ثبات با یک ماسک همه‌یک، `CF` را فقط در صورتی تنظیم می‌کند که ثبات همه‌یک باشد.
   همچنین `ZF` را فقط در صورتی تنظیم می‌کند که ثبات همه‌صفر باشد، و این امکان را می‌دهد که هر دو ماسک را هم‌زمان بررسی کرد.

```x86asm
pxor  xmm0, xmm0   ; xmm0 = all zeros
ptest xmm0, xmm0   ; xmm0 AND xmm0 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm0 == 0 => CF is set

; Using ptest on a register with itself makes ZF set only if the register is all zeros

pcmpeqb xmm1, xmm1 ; xmm1 = all ones
ptest   xmm0, xmm1 ; xmm0 AND xmm1 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm1 != 0 => CF is cleared

pcmpeqb xmm3, xmm3 ; xmm3 = all ones
ptest   xmm3, xmm1 ; xmm3 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm3) AND xmm1 == 0 => CF is set

mov eax, -1
movd  xmm2, eax    ; xmm2 = {-1, 0, 0, 0}
ptest xmm2, xmm1   ; xmm2 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm2) AND xmm1 != 0 => CF is cleared

; After using ptest on a register with an all-ones mask, ZF is only set if the register is all zeros.
; CF may be:
; 1. cleared, if the register is all zeros or is partially set
; 2. set, if the register is all ones
```

از نتیجه‌ی یک `ptest` می‌توان مثل همیشه برای انشعاب یا در دستورهای بدون انشعاب مانند `setcc` یا `cmovcc` استفاده کرد.

## AVX و فراتر از آن

AVX به مقایسه‌ها، ترکیب‌ها و `ptest` قالبی با پیشوند `v` روی ثبات‌های پهن‌تر می‌دهد.

ترکیب متغیر شکلش را عوض می‌کند.
ماسک دیگر `xmm0` ضمنی نیست، بلکه یک عملوند چهارم صریح است:

```x86asm
vpcmpgtd  ymm0, ymm1, ymm2       ; eight 32-bit lanes compared at once
vblendvps ymm0, ymm1, ymm2, ymm3 ; ymm3 is the mask, named explicitly
vptest    ymm0, ymm0
```

افزونه‌های AVX-512 این مدل را عمیق‌تر تغییر می‌دهند.

نخست، رده‌ی تازه‌ای از ثبات‌های SIMD ۶۴ بایتی اضافه می‌کند که `zmm` نام دارند.
آن‌ها ثبات‌های متناظر `ymm` را گسترش می‌دهند، همان‌طور که ثبات‌های `ymm` ثبات‌های `xmm` را گسترش می‌دهند.

دوم، این افزونه‌ها رده‌ی کاملاً تازه‌ای از **ثبات‌های ماسک عملیات**، از `k0` تا `k7`، ایجاد می‌کنند که هدف اصلی‌شان ایفای نقش ماسک برای دستورهای SIMD است.
مقایسه‌ها دیگر در بردارها نمی‌نویسند، بلکه در یکی از این ثبات‌های تازه می‌نویسند.
می‌توان آن‌ها را به‌صورت مستقیم روی بسیاری از دستورها به‌عنوان گزاره با یک ماسک نوشتن `{k}` به کار برد و خط‌ها را _مستقیماً_ انتخاب کرد:

```x86asm
vpcmpgtd  k1, zmm0, zmm1         ; k1 gets one bit per lane
vmovdqa32 zmm2{k1}, zmm3         ; copy only the lanes whose bits are set in k1
```

در پایان، دستورهای تازه‌ای برای کار با آن ثبات‌های تازه وجود دارد، از جمله کپی‌کردن آن‌ها در ثبات‌های همه‌کاره.
این کار دستورهای `movmsk` را غیرضروری می‌کند و هیچ پشتیبانی‌ای برای دستورهای `movmsk` روی ثبات‌های `zmm` وجود ندارد.

این افزونه‌ها فقط برای کامل بودن مطلب ذکر شده‌اند.
تمرین‌های این مسیر از شکل‌های SSE استفاده می‌کنند.
