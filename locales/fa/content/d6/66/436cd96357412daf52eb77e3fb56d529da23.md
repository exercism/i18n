# مقدمه

ماژول `Time` برای نمایش تاریخ و زمان به شکلی که برای انسان خوانا باشد استفاده می‌شود. هرچند از نظر فنی امکان دست‌کاری زمان‌ها با `Time` وجود دارد، بسته‌های جامعه‌ی Elm هستند که برای این کار بسیار مناسب‌ترند، مثل [`justinmimbs/date`][date] یا [`CoderDennis/elm-time-format`][elm-time-format].

## Posix

زمان‌ها با نوع مبهم `Posix` نشان داده می‌شوند که زمان مبدأ یونیکس را در خود می‌پیچد، یعنی تعداد میلی‌ثانیه‌های سپری‌شده از اول ژانویه ۱۹۷۰ در نیمه‌شب UTC.
یک `Posix` مقداری بدون ابهام است که بین مناطق زمانی تغییر نمی‌کند، بنابراین گزینه‌ی خوبی برای نگه داشتن زمان است.
در یک برنامه‌ی Elm، زمان‌های `Posix` معمولاً از منابع بیرونی مثل مرورگر تأمین می‌شوند.

می‌توان یک `Posix` را با توابع زیر به تعدادی میلی‌ثانیه تبدیل کرد و برعکس:

```elm
posixToMillis : Posix -> Int
millisToPosix : Int -> Posix
```

## مناطق زمانی

در زندگی روزمره، ما انسان‌ها معمولاً `Posix` را نمی‌خوانیم و در عوض زمان محلی را ترجیح می‌دهیم، که به موقعیت ما روی زمین و قواعد محلی ساعت تابستانی بستگی دارد.
در Elm، این اطلاعات در نوع مبهم `Zone` کدگذاری می‌شود که معمولاً مرورگر آن را تأمین می‌کند.

یک `Zone` ویژه وجود دارد که همیشه در دسترس است:

```elm
utc : Zone
```

## زمان‌های خوانا برای انسان

با یک `Posix` و یک `Zone`، اطلاعات کافی برای نمایش زمان محلی در هر سطحی از جزئیات را داریم.
در ادامه فهرستی از توابعی می‌آید که می‌توان برای این کار از آن‌ها استفاده کرد:

```elm
toYear : Zone -> Posix -> Int
toMonth : Zone -> Posix -> Month
toDay : Zone -> Posix -> Int
toWeekday : Zone -> Posix -> Weekday
toHour : Zone -> Posix -> Int
toMinute : Zone -> Posix -> Int
toSecond : Zone -> Posix -> Int
toMillis : Zone -> Posix -> Int
```

حتماً دو نوع سفارشی دیگر از `Time` را هم دیده‌اید:

```elm
type Month = Jan | Feb | Mar | Apr | May | Jun | Jul | Aug | Sep | Oct | Nov | Dec
type Weekday = Mon | Tue | Wed | Thu | Fri | Sat | Sun
```

تبدیل این انواع سفارشی به مقادیر خوانا برای انسان بر عهده‌ی کاربران گذاشته شده است.
