# درباره

یک [حلقه][control] دنباله‌ای از دستورهاست که ممکن است بیش از یک بار اجرا شود، تا زمانی که یک شرط پایانی برآورده شود.

در x86-64 معمولاً یک حلقه با یک پرش به یک برچسب پیشین ساخته می‌شود:

```x86asm
example_loop:
    ...
    jmp example_loop
```

توجه داشته باشید که یک پرش غیرشرطی به برچسب پیشین، همیشه اجرا را به همان برچسب منتقل می‌کند.
یعنی حلقه تا ابد تکرار می‌شود، مگر اینکه پرش دیگری به بیرون از دنباله‌ی تکرارشونده وجود داشته باشد.

برای نمونه، این حلقه پایان نمی‌یابد:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

و این حلقه ممکن است پایان یابد، بسته به اینکه شرط برآورده شود:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## حلقه‌های شمارشی

یک حلقه‌ی شمارشی تقریباً همیشه به یک شکل پایان می‌یابد: دستوری که یک شمارنده را به‌روزرسانی می‌کند یا دو مقدار را با هم مقایسه می‌کند و بلافاصله پس از آن یک پرش شرطی می‌آید که تصمیم می‌گیرد آیا یک دور دیگر تکرار شود یا نه.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
در کد بالا، `cmp rsi, 0` لازم نیست، چون `sub rsi, 1` وقتی نتیجه `0` باشد، از پیش `zero flag (ZF)` را تنظیم می‌کند.

هرچند `cmp` روش اصلی آزمودن شرط‌ها در اسمبلی است، بسیاری از دستورها پرچم‌ها را به‌روزرسانی می‌کنند.
برای نمونه، بسیاری از دستورهای حساب عدد صحیح یا بیتی، وقتی نتیجه `0` باشد `ZF` را و وقتی نتیجه منفی باشد (یعنی بیت بالا تنظیم شده باشد) `SF` را به‌روزرسانی می‌کنند.

می‌توانید یک [مرجع][reference] را ببینید تا بفهمید هر دستور کدام پرچم‌ها را تغییر می‌دهد.

[reference]: https://www.felixcloutier.com/x86/
~~~~

توجه داشته باشید که در مثال بالا فرض می‌شود `rsi` بزرگ‌تر از `0` است.
اگر مقدار آن `0` بود، آن‌گاه `sub rsi, 1` مقدار `rsi` را به `-1` کاهش می‌داد که یک عدد بدون علامت بسیار بزرگ است.
پیش از آنکه حلقه سرانجام پایان یابد، `18,446,744,073,709,551,615` تکرار دیگر لازم بود.
همچنین چون طول آرایه `0` است، هر دسترسی به حافظه بیرون از محدوده خواهد بود.

اگر هیچ تضمینی درباره‌ی طول آرایه وجود نداشته باشد، دو رویکرد رایج هست.

رویکرد اول این است که شرط پایانی به ابتدای حلقه منتقل شود و سپس در پایان یک پرش غیرشرطی قرار گیرد:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

رویکرد دوم این است که پیش از آغاز حلقه، یک بار برای آرایه‌ی با طول صفر بررسی شود:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

این رویکرد دوم معمولاً از اولی کارآمدتر است، چون در بدنه‌ی حلقه شاخه‌های کمتری وجود دارد.
در یک مفهوم آینده درباره‌ی این موضوع بیشتر خواهید آموخت.

## ریزعملیات

پردازنده دستوری مانند `add` یا `jnz` را مستقیماً اجرا نمی‌کند.
بخش front-end پردازنده ابتدا هر دستور را به یک یا چند گام داخلی کوچک‌تر _رمزگشایی_ می‌کند که «ریزعملیات» (یا «ریزعمل») نامیده می‌شوند.
سپس پردازنده این ریزعمل‌ها را زمان‌بندی و اجرا می‌کند، اغلب چند تا در هر چرخه و بیرون از ترتیب اصلی‌شان.

بیشتر دستورهای ساده به یک ریزعمل رمزگشایی می‌شوند، در حالی که یک دستور پیچیده‌تر ممکن است به چند ریزعمل رمزگشایی شود.
چون بار کاری واقعی پردازنده همان جریان ریزعمل‌هاست، تولید تعداد کمتری از آن‌ها برای یک کار یکسان، یکی از راه‌های سریع‌تر شدن کد است.

## Macrofusion

همان‌طور که پیش‌تر گفته شد، یک حلقه معمولاً با نوعی پرش شرطی پایان می‌یابد.
این الگو آن‌قدر رایج است که پردازنده‌های امروزی در هنگام رمزگشایی برای آن بهینه‌سازی شده‌اند.

یک دستور تنظیم‌کننده‌ی پرچم که بلافاصله پس از آن یک پرش شرطی می‌آید که همان پرچم‌ها را می‌خواند، می‌تواند با هم، به شکل **یک** ریزعمل واحد رمزگشایی شود، نه یک ریزعمل جداگانه برای هرکدام.
به این کار **macrofusion** می‌گویند.

جفت ادغام‌شده مانند یک عملیات واحد رفتار می‌کند: شمارنده به‌روزرسانی می‌شود و تصمیم شاخه‌گیری نیز همراه آن، در همان یک ریزعمل گرفته می‌شود.
در نتیجه، جریان کنترل حلقه تقریباً هیچ هزینه‌ای روی کار واقعی حلقه اضافه نمی‌کند.

به‌عنوان یک قاعده‌ی سرانگشتی، دو نوع جفت معمولاً به این شکل ادغام می‌شوند:

- دستورهای حساب مانند `add` یا `sub` که بلافاصله پس از آن‌ها یک پرش شرطی می‌آید.
- یک `cmp`، `test` یا `and` که بلافاصله پس از آن یک پرش شرطی می‌آید.

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

ادغام تنها زمانی رخ می‌دهد که پرش شرطی **بلافاصله** پس از دستور تنظیم‌کننده‌ی پرچم بیاید و چیزی میان آن‌ها نباشد.

~~~~exercism/note
Macrofusion به پردازنده بستگی دارد و در اینکه کدام دستورها با کدام پرش شرطی ادغام می‌شوند، تفاوت‌هایی وجود دارد.

یک مرجع مفید، [ریزمعماری پردازنده‌های Intel، AMD و VIA، نوشته‌ی Agner Fog][agner-uarch] است.
بخش ۳.۴.۲.۲ (بهینه‌سازی برای Macrofusion) از [راهنمای مرجع بهینه‌سازی Intel][intel-opt] نیز جفت‌های قابل ادغام را برای پردازنده‌های Intel فهرست می‌کند.

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## دستور `loop`

دستورهایی وجود دارند که می‌توان از آن‌ها برای ساختن رفتاری شبیه حلقه استفاده کرد.
یکی از آن‌ها [loop][loop] است.

تنها عملوند آن یک برچسب است که نشانی آغاز حلقه را در خود دارد.

دستور `loop` از مقدار موجود در `rcx` به‌عنوان شمارنده استفاده می‌کند و در هر بار یک واحد از آن کم می‌کند.
وقتی مقدار `rcx` به صفر برسد، حلقه پایان می‌یابد و اجرا به‌صورت ترتیبی ادامه پیدا می‌کند:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

دو گونه از دستور `loop` وجود دارد که در هر تکرار پرچم صفر (`ZF`) را بررسی می‌کنند.
علاوه بر متوقف کردن حلقه وقتی `rcx` به صفر می‌رسد، هنگامی هم که شرط _برآورده نشود_ متوقف می‌شوند.

| دستور | شرط |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == ۱ |
| `loopne`/`loopnz` | `ZF` == ۰ |

`ZF` **توسط این دستورها تنظیم نمی‌شود**.
پیش از آن‌ها باید یک `cmp`، `test` یا دستور دیگری وجود داشته باشد که `ZF` را تغییر دهد:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
با وجود راحتی‌شان، دستورهای `loop`، `loope` و `loopne` روی پردازنده‌های امروزی معمولاً بسیار کندتر از دنباله‌ی معادل `sub`/`jnz` یا `cmp`/`jnz` هستند.

یک مرجع خوب درباره‌ی کارایی دستورها در پردازنده‌های گوناگون، [جدول‌های Agner][agner-tables] است.

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
~~~~
