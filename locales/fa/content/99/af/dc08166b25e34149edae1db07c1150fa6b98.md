# مقدمه

Go هم مانند بسیاری از زبان‌های دیگر، «اشارهگر» دارد.
اگر تازه با اشارهگرها آشنا شده‌اید، ممکن است کمی مرموز به نظر برسند، اما وقتی به آن‌ها عادت کنید، کاملاً ساده می‌شوند.
اشارهگرها بخش مهمی از Go هستند، پس وقت بگذارید و آن‌ها را واقعاً درک کنید.

پیش از پرداختن به جزئیات، خوب است کاربرد اشارهگرها را بفهمید.
اشارهگرها روشی برای به اشتراک گذاشتن حافظه با بخش‌های دیگر برنامه‌ی ما هستند و به دو دلیل عمده مفیدند:

1. وقتی حجم زیادی داده داریم، ساختن رونوشت برای انتقال بین توابع بسیار ناکارآمد است.
   در عوض، با انتقال نشانی حافظه‌ای که داده در آن ذخیره شده، می‌توانیم میزان مصرف منابع برنامه‌هایمان را به‌طور چشمگیری کاهش دهیم.
2. با انتقال اشارهگرها بین توابع، می‌توانیم مستقیماً به تنها نسخه‌ی داده دسترسی داشته باشیم و آن را تغییر دهیم؛ یعنی هر تغییری که یک تابع ایجاد کند، پس از پایان آن تابع بلافاصله برای بخش‌های دیگر برنامه قابل مشاهده است.

## متغیرها و حافظه

فرض کنید یک متغیر صحیح معمولی به اسم `a` داریم:

```go
var a int
```

وقتی متغیری تعریف می‌کنیم، Go باید جایی در حافظه برای ذخیره‌ی مقدار آن پیدا کند.
این کار تا حد زیادی از دید ما پنهان است؛ وقتی بخواهیم مقدار ذخیره‌شده در آن بخش از حافظه را واکشی کنیم، کافی است با اسم متغیر به آن ارجاع دهیم.

برای مثال، وقتی `a + 2` را می‌نویسیم، در واقع مقدار ذخیره‌شده در حافظه‌ی مرتبط با متغیر `a` را واکشی می‌کنیم و ۲ به آن اضافه می‌کنیم.

به همین ترتیب، وقتی بخواهیم مقدار موجود در بخش حافظه‌ی `a` را تغییر دهیم، می‌توانیم با اسم متغیر یک انتساب انجام دهیم:

```go
a = 3
```

بخش حافظه‌ای که با `a` مرتبط است، اکنون مقدار `3` را ذخیره می‌کند.

## اشارهگرها

متغیرها به ما اجازه می‌دهند به مقادیر موجود در حافظه ارجاع دهیم، اما گاهی دانستن **نشانی حافظه**ای که متغیر به آن اشاره می‌کند مفید است. **اشارهگرها** نشانی‌های حافظه‌ی این مقادیر را نگه می‌دارند.
متغیری با نوع اشارهگر را با گذاشتن یک ستاره پیش از نوع پایه تعریف می‌کنید:

```go
var p *int // 'p' contains the memory address of an integer
```

اینجا متغیری به اسم `p` از نوع «اشارهگر به `int`» (`*int`) تعریف می‌کنیم.
یعنی `p` نشانی حافظه‌ی یک عدد صحیح را نگه می‌دارد.
«مقدار صفر» اشارهگرها `nil` است، چون اشارهگر `nil` هیچ نشانی حافظه‌ای در خود ندارد.

### گرفتن اشارهگری به یک متغیر

برای یافتن نشانی حافظه‌ی مقدار یک متغیر، می‌توانیم از عملگر `&` استفاده کنیم.
برای مثال، اگر بخواهیم نشانی حافظه‌ی متغیر `a` را پیدا کنیم و در اشارهگر `p` ذخیره کنیم، می‌توانیم این کار را انجام دهیم:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### دسترسی به مقدار از طریق اشارهگر (مرجع‌زدایی)

وقتی اشارهگری داریم، ممکن است بخواهیم مقدار ذخیره‌شده در نشانی حافظه‌ای را که اشارهگر نمایندگی می‌کند بدانیم.
این کار را می‌توانیم با عملگر `*` انجام دهیم:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

عملیات `*p` مقداری را که در نشانی حافظه‌ی ذخیره‌شده در `p` قرار دارد واکشی می‌کند.
به این عملیات اغلب «مرجع‌زدایی» می‌گویند.

می‌توانیم از عملگر مرجع‌زدایی استفاده کنیم تا مقدار تازه‌ای به نشانی حافظه‌ای که اشارهگر به آن ارجاع می‌دهد اختصاص دهیم:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

انتساب به `*pa` مقداری را که در نشانی حافظه‌ای که `pa` نگه می‌دارد تغییر می‌دهد.
چون `pa` نشانی حافظه‌ی `a` را در خود دارد، با انتساب به `*pa` در واقع مقدار `a` را تغییر می‌دهیم!

اما یک نکته‌ی احتیاط: پیش از مرجع‌زدایی، همیشه بررسی کنید که اشارهگر `nil` نباشد.
مرجع‌زدایی از یک اشارهگر `nil` باعث می‌شود برنامه در زمان اجرا از کار بیفتد!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### اشارهگرها به `struct`ها

تا اینجا فقط اشارهگرها به مقادیر اولیه را دیده‌ایم.
می‌توانیم برای `struct`ها هم اشارهگر بسازیم:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

می‌توانستیم یک `Person` تازه هم بسازیم و بلافاصله اشارهگری به آن ذخیره کنیم:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

وقتی اشارهگری به یک `struct` داریم، لازم نیست پیش از دسترسی به یکی از فیلدها اشارهگر را مرجع‌زدایی کنیم:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## اسلایس‌ها و مپ‌ها از قبل اشارهگر هستند

اسلایس‌ها و مپ‌ها نوع‌های ویژه‌ای هستند، چون در پیاده‌سازی خود از قبل اشارهگر دارند.
یعنی در بیشتر موارد لازم نیست برای این نوع‌ها اشارهگر بسازیم تا نشانی حافظه‌ی مقادیرشان را به اشتراک بگذاریم.
تصور کنید تابعی داریم که مقدار یک کلید را در یک مپ یک واحد افزایش می‌دهد:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

اگر یک مپ بسازیم و این تابع را فراخوانی کنیم، تغییراتی که تابع در مپ ایجاد کرده پس از پایان تابع باقی می‌مانند.
این رفتار مشابه چیزی است که با استفاده از اشارهگر به دست می‌آوریم، اما توجه کنید که در این مثال از هیچ ارجاع‌دهی یا مرجع‌زدایی و هیچ بخشی از نحوه‌ی نگارش اشارهگر استفاده نمی‌کنیم:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

همین موضوع وقتی یک عنصر موجود در یک اسلایس را تغییر می‌دهیم هم صدق می‌کند.

اما کارهایی که یک اسلایس تازه برمی‌گردانند، مانند `append`، حالت ویژه‌ای دارند و **ممکن است** اسلایس بیرون از تابع را تغییر ندهند.
این به نحوه‌ی کار داخلی اسلایس‌ها مربوط است، اما در این تمرین به جزئیات آن نمی‌پردازیم، چون موضوعی پیشرفته‌تر است.
