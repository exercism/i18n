# درباره

Swift انواع مختلفی دارد، اما هر یک از این انواع در یکی از دو دسته‌ی متفاوت قرار می‌گیرد: _انواع مقداری_ و _انواع ارجاعی_. در Swift، [ساختارها نوع مقداری هستند][structs-are-value-types] و [کلاس‌ها نوع ارجاعی هستند][classes-are-reference-types].

تفاوت اصلی میان انواع مقداری و انواع ارجاعی این است که وقتی یک نوع مقداری به یک متغیر یا ثابت نسبت داده می‌شود، یا به یک تابع پاس داده می‌شود، در واقع آنچه نسبت داده یا پاس داده می‌شود یک رونوشت از آن مقدار است، نه خود آن مقدار. تغییر دادن یک رونوشت از یک ساختار بر رونوشت‌های دیگر اثری ندارد. در انواع ارجاعی، یک ارجاع به آن مقدار نسبت داده یا پاس داده می‌شود، بنابراین دو اسم متفاوت می‌توانند به یک نمونه‌ی یکسان از یک کلاس اشاره کنند. این می‌تواند باعث شود که نمونه‌ی اصلی وقتی با اسمی دیگر به آن دسترسی پیدا می‌کنیم تغییر کند.

حالا با ساختار و کلاسی که یک شخصیت در یک بازی و آمار بازی‌اش را تعریف می‌کنند، می‌توان دید وقتی این موارد رونوشت و تغییر داده می‌شوند چه اتفاقی می‌افتد.

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

دقت کنید که تغییر ویژگی‌های `charB` چگونه بر `charA` اثر گذاشت، چون هر دو اسم به یک نمونه‌ی یکسان اشاره می‌کنند. همچنین توجه کنید که در مورد آمار این دو شخصیت، انواع مقداری داخل یک نوع ارجاعی درون همان نوع ارجاعی تغییر می‌کنند. اما این نقض رفتار نوع مقداری نیست، چون `charA.stats` همان نمونه‌ی `CharacterStats` است که `charB.stats` هست، چرا که `charA` و `charB` به یک نمونه‌ی یکسان از کلاس `GameCharacter` اشاره می‌کنند. همان‌طور که می‌بینیم، برای مثال رونوشت‌های آن انواع مقداری بر یکدیگر اثری ندارند.

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

به همین دلیل ساختارها برای متدهایی که وضعیت ویژگی‌های ساختار را تغییر می‌دهند، به کلیدواژه‌ی `mutating` در ابتدای متد نیاز دارند. تغییر یک ویژگی ساختار در واقع رونوشت تازه‌ای از ساختار می‌سازد که مقدار جدید برای آن ویژگی در آن قرار گرفته است، و رونوشت تازه جای رونوشت قدیمی را می‌گیرد. این یک نشانه‌ی دیداری است که نشان می‌دهد این رونوشت‌گیری و جایگزینی ممکن است برای مقادیر آن نوع رخ دهد.

این یک اثر جانبی دارد: هر نمونه‌ای از ساختار که ویژگی‌های متغیرش تغییر می‌کنند، چه از راه فراخوانی توابع تغییردهنده و چه با انتساب مستقیم، _باید_ به یک متغیر نسبت داده شود، نه به یک ثابت. در غیر این صورت یک خطای کامپایلر تولید می‌شود:

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

مقدارهای اولیه هنوز می‌توانند ساخته و خوانده شوند، اما اجازه‌ی تغییر ندارند. این محدودیت برای کلاس‌ها اعمال نمی‌شود. اگر نمونه‌ای از یک کلاس با `let` به یک اسم نسبت داده شود، آنچه ثابت در خود نگه می‌دارد ارجاع به آن نمونه است و بنابراین ارجاع نمی‌تواند تغییر کند، نه خود نمونه. پس خود نمونه می‌تواند تغییر کند، اما ارجاع نمی‌تواند طوری تغییر کند که به نمونه‌ی دیگری اشاره کند.

خلاصه‌ای از آنچه با ساختارها و کلاس‌های تعریف‌شده با `let` یا `var` می‌تواند تغییر کند، به این صورت است

|         | **struct**                                                                                  | **class**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | _نمی‌توان_ ساختار تازه‌ای به این اسم نسبت داد.</br>_نمی‌توان_ هیچ‌یک از ویژگی‌های ساختار را تغییر داد. | _نمی‌توان_ کلاس تازه‌ای به این اسم نسبت داد.</br>_می‌توان_ ویژگی‌های تغییرپذیر کلاس را تغییر داد. |
| **var** | _می‌توان_ ساختار تازه‌ای به این اسم نسبت داد.</br>_می‌توان_ ویژگی‌های تغییرپذیر ساختار را تغییر داد.   | _می‌توان_ کلاس تازه‌ای به این اسم نسبت داد.</br>_می‌توان_ ویژگی‌های تغییرپذیر کلاس را تغییر داد.    |

## هویت

چون دو اسم متفاوت ممکن است ارجاعی به یک نمونه‌ی یکسان از یک کلاس در خود داشته باشند، گاهی بررسی این موضوع مفید است. Swift برای این کار از عملگر _هویت_، یعنی `===`، استفاده می‌کند (و همچنین نقیض آن، `!==`).

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

چون هیچ دو اسمی نمی‌توانند به یک نمونه‌ی یکسان از یک ساختار اشاره کنند، این عملگرهای هویت برای ساختارها تعریف نشده‌اند.

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

دقت کنید که هویت با برابری یکسان نیست. بر اساس بسیاری از تعریف‌ها، `char1` و `char3` برابر در نظر گرفته می‌شوند چون همه‌ی ویژگی‌هایشان مقدارهای یکسانی دارند، اما هویت یکسانی ندارند. هویت در Swift به‌طور خودکار برای همه‌ی کلاس‌ها فراهم است، اما توسعه‌دهندگان معمولاً باید عملگرهای برابری خودشان را بنویسند تا تعیین کنند آیا دو نمونه از یک ساختار یا کلاس _برابر_ هستند یا نه. انجام این کار فراتر از محدوده‌ی این تمرین است.
