# مقدمه

همان‌طور که در مفهوم [`Nothingness`][concept-nothingness] بررسی شد، R روش‌های گوناگونی برای نمایش داده‌هایی دارد که غایب (`NULL`)، نامعلوم (`NA`) یا از نظر ریاضی نامعتبر (`NaN`، `Inf`) هستند.
به طور کلی، R تلاش می‌کند از این‌ها برای علامت‌گذاری مشکلات در همان‌جا استفاده کند و بدون ایجاد خطا ادامه دهد.

## `stop()`

برخی مشکلات آن‌قدر بنیادی هستند که نمی‌توان اجازه داد برنامه ادامه یابد.
در این حالت، از `stop(msg)` استفاده کنید تا برنامه بی‌درنگ با یک `Error` متوقف شود و `msg` چاپ شود.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

این تابع، مشابه `assert` در زبان‌های دیگر، پوششی مناسب برای `stop()` است.
پارامترها تعدادی دلخواه از شرط‌های منطقی جداشده با کاما هستند و برنامه فقط در صورتی ادامه می‌یابد که همه‌ی آن‌ها `TRUE` باشند.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `warning()` و `message()`

این‌ها پاسخ‌هایی به شرایط غیرکشنده هستند، برای مثال:

- برای هشدار دادن درباره‌ی مشکلی که برنامه دست‌کم تا حدی می‌تواند از آن بازیابی کند.
- برای آگاه کردن کاربر از پیشرفت در برنامه‌ای که مدت طولانی اجرا می‌شود.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

تابع `suppressWarnings()` گاهی می‌تواند در Exercism مفید باشد، تا از سردرگم شدن تست‌رانر با خروجی‌های ناخواسته جلوگیری شود.
