# مقدمه

مفهوم [`Basics`][basics] دو روش برای تعریف تابع معرفی کرد.

به‌طور کلی، شکل چندخطی:

```julia
function muladd(x, y, z)
    x * y + z
end
```

و شکل «انتساب»، یا شکل «تک‌خطی»، برای تعریف‌های کوتاه:
```julia
muladd(x, y, z) = x * y + z
```

در شکل سوم و حتی کوتاه‌تر، می‌توان تابعی کوتاه و یک‌بارمصرف را بدون اسم ساخت:

```julia-repl
julia> map(x -> 2x, 1:3)
4-element Vector{Int64}:
 2
 4
 6

julia> map((x, y) -> x * y, 1:3, 4:6)
3-element Vector{Int64}:
  4
 10
 18
```

در این حالت، `x -> 2x` یک «تابع بی‌نام» است.
این معادل چیزی است که برخی زبان‌های دیگر «تابع لامبدا» می‌نامند.

توجه کنید که چند آرگومان به پرانتز نیاز دارند، مانند `(x, y) -> x * y`.

توابع بی‌نام در کد Julia رایج‌اند، به‌ویژه وقتی با توابع مرتبه‌بالاتر مانند `map()` و `filter()` ترکیب شوند (که در مفهومی بعدی با جزئیات بیشتری بررسی می‌شوند).

```julia-repl
julia> map(x -> x^4, [1, 2, 3])
3-element Vector{Int64}:
  1
 16
 81
```

## آرگومان‌های تابع

تا اینجای برنامه‌ی درسی، فقط توابعی را بررسی کرده‌ایم که تعداد مشخصی آرگومان دارند و لازم است فراخوانی تابع همه‌ی آن‌ها را به ترتیب درست بدهد.
این محدودکننده و ناخوشایند می‌بود، بنابراین گزینه‌های دیگری هم وجود دارد.

### آرگومان‌های اختیاری

مانند بسیاری از زبان‌ها، Julia اجازه می‌دهد تعریف تابع برای هر آرگومان مقدار پیش‌فرض تعیین کند.

در این صورت، فراخوانی تابع می‌تواند یا مقداری برای آن آرگومان بدهد، یا آن را حذف کند و به مقدار پیش‌فرض تکیه کند.

```julia-repl
julia> f(x, y=10) = x * y
f (generic function with 2 methods)

julia> f(2, 3)
6

julia> f(2)
20
```

همه‌ی آرگومان‌های _بدون_ پیش‌فرض باید قبل از آرگومان‌های _دارای_ پیش‌فرض بیایند، یعنی `f(x=2, y)` نامعتبر است.

### آرگومان‌های کلیدواژه‌ای

همه‌ی مثال‌های تا اینجا از `positional arguments` استفاده می‌کنند، که در آن‌ها مقادیر داده‌شده در فراخوانی تابع باید با ترتیب آرگومان‌های متناظر در تعریف تابع مطابقت داشته باشد.

مانند بسیاری از زبان‌ها، Julia هم `keyword arguments` را مجاز می‌داند.
فراخوانی تابع باید اسم آرگومان را مشخص کند، اما آن‌وقت می‌توان چند آرگومان کلیدواژه‌ای را به هر ترتیبی نوشت.

یکی از ویژگی‌های متمایز Julia این است که آرگومان‌های کلیدواژه‌ای (اگر وجود داشته باشند) در تعریف تابع باید با یک نقطه‌ویرگول `;` بیایند تا از آرگومان‌های مکانی جدا شوند.
فراخوانی تابع می‌تواند بین آخرین آرگومان مکانی و اولین آرگومان کلیدواژه‌ای از `;` یا `,` استفاده کند.

```julia-repl
julia> b(x; y) = x + y
b (generic function with 1 method)

julia> b(2, y=3)
5

# keyword is required when calling
julia> b(2, 3)
ERROR: MethodError: no method matching b(::Int64, ::Int64)
The function `b` exists, but no method is defined for this combination of argument types.
```

می‌توان به‌صورت اختیاری مقدار پیش‌فرض تعیین کرد، دقیقاً مانند آرگومان‌های مکانی.

اغلب پیش می‌آید که در فراخوانی تابع چیزی شبیه `myarg=myarg` بنویسید، وقتی متغیری با همان اسم پارامتر قبلاً محاسبه شده باشد.
در این حالت، یک شکل کوتاه‌شده مجاز است:

```julia-repl
julia> width = 4.0
4.0

julia> height = √ width
2.0

julia> area(; width, height) = width * height
area (generic function with 1 method)

# repetition
julia> area(; width=width, height=height)
8.0

# shorthand form
julia> area(; width, height)
8.0
```

### Splat و slurp

اگر برایتان سؤال بوده، این‌ها نام‌های استانداردی برای جنبه‌ای مفید از نحوه‌ی نگارش Julia هستند.
هر دو به عملگر `...` اشاره دارند.

#### Splat

Splat کردن در _فراخوانی‌های_ تابع به کار می‌رود تا مجموعه‌ها را به مقادیر تکی موردنیاز تابع بگشاید.

شاید نشان دادن این موضوع آسان‌تر از توضیح دادنش باشد:

```julia-repl
julia> fxyz(x, y, z) = x * y * z
fxyz (generic function with 1 method)

julia> xyz = [2, 3, 4]
3-element Vector{Int64}:
 2
 3
 4

# Using the vector directly in a function call is invalid
julia> fxyz(xyz)
ERROR: MethodError: no method matching fxyz(::Vector{Int64})
The function `fxyz` exists, but no method is defined for this combination of argument types.

# splatting converts the vector to 3 numbers, used as positional arguments
julia> fxyz(xyz...)
24
```

برخی «فراخوانی‌های تابع» با شکر نحوی پنهان می‌شوند، بنابراین splat را می‌توان به شکل‌های نامحسوس‌تری هم به کار برد.

برای مثال، انتساب چندگانه در باطن از یک تابع سازنده‌ی tuple استفاده می‌کند:

```julia-repl
julia> first, rest... = [1, 2, 3, 4]
4-element Vector{Int64}:
 1
 2
 3
 4

julia> first
1

julia> rest
3-element Vector{Int64}:
 2
 3
 4
```

آرگومان‌های کلیدواژه‌ای را هم می‌توان با splat کردن داد، معمولاً با استفاده از یک `named tuple`.
`Dict` هم کار می‌کند، اما کلیدها باید symbol باشند (رشته‌ها کار نمی‌کنند).

```julia-repl
# function with 3 keyword arguments
julia> fabc(; a, b, c) = a + b + c
fabc (generic function with 1 method)

# named tuple
julia> abc_nt = (a=2, b=3, c=4)
(a = 2, b = 3, c = 4)

# there are no positional arguments, so need to use ; before kw argument
julia> fabc(;abc_nt...)
9

# Dict
julia> abc_dict = Dict(:a=>2, :b=>3, :c=>4)
Dict{Symbol, Int64} with 3 entries:
  :a => 2
  :b => 3
  :c => 4

julia> fabc(;abc_dict...)
9
```

#### Slurp

Slurp کردن در _تعریف_ تابع به کار می‌رود تا تعداد دلخواهی از مقادیر تکی را در یک مجموعه بسته‌بندی کند.

```julia-repl
julia> f_more(i, j, more...) = i + j + sum(more)
f_more (generic function with 1 method)

julia> f_more(1, 3, 5, 7, 9, 11)
36
```

اسم آرگومان slurpشده (در اینجا `more`) اهمیتی ندارد.
نوع این متغیر را کامپایلر انتخاب می‌کند، اما برای آرگومان‌های مکانی احتمالاً `tuple` یا چیزی شبیه آن است.

آرگومان‌های کلیدواژه‌ای را هم می‌توان slurp کرد که یک `Dict` (یا مشابه آن) به دست می‌دهد.

```julia-repl
julia> f_kwslurp(x, y; switches...) = :mult in keys(switches) ? x * y : x + y
f_kwslurp (generic function with 1 method)

julia> f_kwslurp(5, 6; mult=true)
30

julia> f_kwslurp(5, 6)
11
```

در فراخوانی می‌توان از هر آرگومان کلیدواژه‌ای استفاده کرد.
این تعریف تابع است که تصمیم می‌گیرد به کدام کلیدواژه‌ها پاسخ دهد و کدام‌ها را نادیده بگیرد.
