# مقدمه

بیشتر واژه‌های دنباله که تا حالا دیده‌اید یک دنباله‌ی *جدید* برمی‌گردانند و ورودی‌هایشان را دست‌نخورده رها می‌کنند، مانند `suffix`، `reverse`، `map` و غیره. اما آرایه‌ها و بردارها از **«تغییر درجا»** هم پشتیبانی می‌کنند و هر دو وقتی به کار می‌آیند که بخواهید وضعیتی را ثبت کنید که در طول زمان تغییر می‌کند.

## دو گونه دنباله‌ی تغییرپذیر

- **آرایه‌ها** (`{ … }`) طول ثابتی دارند. `<array> ( n elt -- array )` (در [`arrays`][arrays]) یک آرایه‌ی تازه به طول `n` می‌سازد که پر از رونوشت‌های `elt` است.
- **بردارها** (`V{ … }`) رشد می‌کنند و کوچک می‌شوند. برای یک بردار تازه‌ی خالی از `V{ } clone` استفاده کنید؛ `<vector> ( n -- vector )` (در [`vectors`][vectors]) ظرفیت لازم برای `n` عنصر را از پیش تخصیص می‌دهد.

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## تغییر یک جایگاه

این دو روی هر دو نوع دنباله کار می‌کنند، و هر دو انتظار دارند دنباله بعد از اندیس بیاید:

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

`set-nth` مقداردهی می‌کند؛ `change-nth` یک بلوک کد را روی عنصر در موقعیت `n` اعمال می‌کند. هر دوی این واژه‌های [`sequences`][sequences] چیزی روی پشته برنمی‌گردانند؛ اثر همان تغییر است.

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## رشد و کوچک شدن

این سه فقط برای بردارها معنا دارند، چون آرایه‌ها نمی‌توانند طولشان را تغییر دهند:

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## بردار → آرایه

وقتی برداری ساخته‌اید و می‌خواهید یک آرایه‌ی با طول ثابت تحویل بدهید، `>array ( seq -- array )` (در [`arrays`][arrays]) یک آرایه‌ی تازه با همان عناصر برمی‌گرداند:

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`، نگه داشتن عکس فوری

تغییر درجا، دنباله را در همان جا اصلاح می‌کند. اگر فراخوانی‌کننده‌ای دنباله‌ای به شما بدهد و شما در آستانه‌ی تغییر دادن آن باشید، `clone` (در [`kernel`][kernel]) یک رونوشت تازه و مستقل به شما می‌دهد تا دید فراخوانی‌کننده دستخوش تغییر نشود:

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

همین احتیاط درباره‌ی `V{ }` و دیگر مقادیر ثابت خالی هم صادق است. در بعضی زبان‌ها، `[]` یا `vec![]` هر بار که عبارت ارزیابی می‌شود یک ظرف تازه تخصیص می‌دهد. در Factor، مقدار ثابت `V{ }` که در سورس کدتان نوشته‌اید *یک* شیء است که همه‌ی محل‌های فراخوانی که به آن اشاره می‌کنند در آن شریک‌اند. اگر مستقیماً روی `V{ }` عمل `push` را انجام دهید، فراخوانی بعدی باقی‌مانده‌ها را می‌بیند. `V{ } clone` همان رونوشت تازه‌ای را می‌سازد که تقریباً همیشه می‌خواهید.
