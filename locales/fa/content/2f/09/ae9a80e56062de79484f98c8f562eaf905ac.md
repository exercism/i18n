# درباره

اصلی‌ترین ساختار شیءگرا در C# «کلاس» است که ترکیبی از داده ([«فیلدها»][fields]) و رفتار ([«متدها»][methods]) است. به فیلدها و متدهای یک کلاس، «اعضای» آن می‌گویند.

دسترسی به اعضا را می‌توان از طریق تغییردهنده‌های دسترسی محدود کرد. دو مورد رایج‌تر این‌ها هستند:

- [`public`][public]: هر کدی می‌تواند به این عضو دسترسی داشته باشد (بدون محدودیت).
- [`private`][private]: فقط کدی در همان کلاس می‌تواند به این عضو دسترسی داشته باشد.

مرسوم است که برای همه‌ی اعضا یک تغییردهنده‌ی دسترسی مشخص شود. اگر هیچ تغییردهنده‌ای مشخص نشود، به‌طور پیش‌فرض `private` در نظر گرفته می‌شود.

به این کار که داده و رفتار مرتبط را در کنار هم قرار می‌دهید و دسترسی به اعضا را محدود می‌کنید، [«کپسوله‌سازی»][encapsulation] می‌گویند که یکی از مفاهیم اصلی شیءگراست.

ترکیب مقادیر فیلدهای یک شیء در یک لحظه‌ی مشخص، [«حالت»][object-state] آن شیء نامیده می‌شود.

می‌توان کلاس را به‌عنوان قالبی برای ساختن نمونه‌هایی از آن کلاس در نظر گرفت. برای [ساختن نمونه‌ای از یک کلاس][creating-objects] (که به آن «شیء» هم می‌گویند)، از [کلیدواژه‌ی `new`][new] استفاده می‌شود:

```csharp
class Car
{
}

// Create two car instances
var myCar = new Car();
var yourCar = new Car();
```

[فیلدها][fields] یک نوع دارند و می‌توانند در هر جایی از یک کلاس تعریف شوند. فیلدهای عمومی به سبک [PascalCase][pascal-case] و فیلدهای خصوصی به سبک [camelCase][camel-case] تعریف می‌شوند و با یک زیرخط `_` شروع می‌شوند:

```csharp
class Car
{
    // Accessible by anyone
    public int Weight;

    // Only accessible by code in this class
    private string _color;
}
```

می‌توان به‌صورت اختیاری یک مقدار اولیه به یک فیلد نسبت داد. اگر فیلدی مقدار اولیه تعیین نکند، به [مقدار پیش‌فرض][default-values] نوعش تنظیم می‌شود. مقادیر فیلدهای یک نمونه را می‌توان با نقطه‌گذاری خواند و به‌روزرسانی کرد.

```csharp
class Car
{
    // Will be set to specified value
    public int Weight = 2500;

    // Will be set to default value (0)
    public int Year;
}

var newCar = new Car();
newCar.Weight; // => 2500
newCar.Year;   // => 0

// Update value of the field
newCar.Year = 2018;
```

فیلدهای خصوصی معمولاً به‌عنوان اثر جانبی فراخوانی یک متد به‌روزرسانی می‌شوند. چنین متدهایی معمولاً مقداری برنمی‌گردانند. در این حالت نوع بازگشتی باید [`void`][void] باشد:

```csharp
class CarImporter
{
    private int _carsImported;

    public void ImportCars(int numberOfCars)
    {
        // Update private field
        _carsImported = _carsImported + numberOfCars;
    }
}
```

توجه داشته باشید که استفاده از فیلدهای عمومی در کلاس‌های C# مرسوم نیست. یا از فیلدهای خصوصی استفاده می‌شود یا از انواع دیگر اعضا که در تمرین‌های بعدی به آن‌ها پرداخته خواهد شد.

درون یک کلاس، [کلیدواژه‌ی `this`][this] به کلاس جاری اشاره می‌کند. این موضوع به‌ویژه زمانی مفید است که اسم یک پارامتر با اسم یک فیلد یکی باشد:

```csharp
class CarImporter
{
    private int carsImported;

    public void SetImportedCars(int carsImported)
    {
        // Update private field from public method
        this.carsImported = carsImported;
    }
}
```

ساختار کلاس و متد راهی طبیعی برای محدود کردن دیدپذیری عناصر برنامه مانند فیلدها و متدها فراهم می‌کند. همچنین از [مشکل حالت سراسری][so-global-state-problem] که به‌خوبی شناخته شده است جلوگیری می‌کند. فیلدها، متدها و دیگر اعضای عمومی برای آن‌که کدی بیرون از کلاس بتواند آن‌ها را ببیند، باید با اسم شیء مشخص شوند، یعنی `object.field` یا `object.method()` (و در مورد اعضای استاتیک، با اسم کلاس). متغیرها و پارامترهایی که درون یک متد تعریف می‌شوند، فقط در همان متد قابل دیدن هستند.

در این روش یک نکته هم هست که باید مراقبش باشید. اگر اسم یک فیلد با اسم یک متغیر یا پارامتر درون یک متد یکی باشد، کد درون متد اسم فیلد را نادیده می‌گیرد و این ممکن است آن چیزی نباشد که می‌خواهید. به‌طور کلی بهتر است در صورت امکان از این کار پرهیز کنید، هرچند الگویی رایج در سازنده‌ها است. اگر مناسب است که اسم فیلد و متغیر یکی باشد، اسم فیلد را درون متد با کلیدواژه‌ی `this` مشخص کنید.

از این [تغییردهنده‌های دسترسی][access-modifiers] می‌توان برای محدود کردن بیشتر دیدپذیری استفاده کرد.
