# مقدمه

## رشته

### کاراکتر

**کدگذاری کاراکتر** قراردادی مشخص است که برای نمایش عناصر متن در یک زبان طبیعی به‌صورت دنباله‌ای از بایت به کار می‌رود.
منظور از «عنصر متن» در اینجا هر واحدی است که در یک زبان طبیعی معنادار باشد؛ برای مثال حروف، فاصله‌ها، نشانه‌های نگارشی، ایموجی‌ها، تصویرنگاشت‌ها و غیره.

NASM (همان Netwide Assembler، اسمبلری که این ترک از آن استفاده می‌کند) از تعریف داده با **ASCII** پشتیبانی می‌کند.

ثابت‌های کاراکتری در NASM می‌توانند تا ۸ بایت طول داشته باشند و می‌توان آن‌ها را با کوتیشن تکی (`'`)، کوتیشن دوتایی (`"`) یا بک‌تیک (`` ` ``) تعریف کرد:

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

کاراکترهای خاص باید در بک‌تیک تعریف شوند و با `\` فرار داده شوند:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

توجه کنید که در x86-64 هیچ پشتیبانی توکاری برای هیچ کدگذاری کاراکتری به‌عنوان یک نوع متمایز وجود ندارد.
داده در اسمبلی دنباله‌ای از بایت است و تفسیر آن بایت‌ها به‌عنوان کاراکتر، عدد یا هر چیز دیگر، به عهده‌ی برنامه‌نویس گذاشته می‌شود.

برای نمونه، کاراکتر ASCII '0' یک بایت واحد با مقدار ۴۸ است.
بنابراین، ذخیره‌ی ۴۸ در یک بایت دقیقاً همان ذخیره‌ی کاراکتر ASCII '0' است:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

به همین دلیل، کار کردن با کاراکترها با دگرگون‌سازی مستقیم مقادیر آن بایت‌ها انجام می‌شود:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

### رشته

**رشته** دنباله‌ای از کاراکترهاست.
در اسمبلی، معمولاً به‌صورت یک آرایه پیاده‌سازی می‌شود.

می‌توان یک رشته را در NASM به همان شیوه‌ای که هر آرایه‌ای اعلان می‌شود، اعلان کرد:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

یک تفاوت میان رشته‌ها و سایر آرایه‌ها این است که NASM از اعلان رشته‌ها بدون کاما (`,`) میان مقادیر هم پشتیبانی می‌کند.
همچنین می‌توان مقادیر را با کاما درهم آمیخت:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

توجه کنید که همان‌طور که پیش‌تر گفته شد، کاراکترها فقط بایت هستند (یا دنباله‌ای از بایت در کدگذاری یونیکد):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

از آنجا که هر کاراکتر ASCII یک بایت را اشغال می‌کند، هر بایت بعدی در یک اندازه‌ی بزرگ‌تر `0` است.
برای مثال، اعلان `'a'` به‌صورت qword (۸ بایت) به این معناست که بایت اول `'a'` (`97`) است و هفت بایت دیگر همه `0` هستند.

به همین دلیل، همه‌ی این‌ها معادل‌اند:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
در اسمبلی، رشته‌ها به‌طور خودکار با کاراکتر NUL در ASCII (مقدار `0`) پایان نمی‌یابند.

هنگام تعامل با زبان‌های سطح‌بالاتر، مانند C، مسئولیت اطمینان از پیوست شدن پایان‌دهنده‌ی درست (در صورت وجود) در انتهای رشته بر عهده‌ی برنامه‌نویس است.
~~~~

### دستورهای رشته

از آنجا که رشته‌ها آرایه هستند، می‌توانید مانند هر آرایه‌ی دیگری با آن‌ها کار کنید، با مرجع‌زدایی صریح از حافظه:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

علاوه بر این، دستورهایی برای بارگذاری، جابه‌جایی و ذخیره‌ی مقادیر در دنباله‌های بایت در حافظه وجود دارد.
اگرچه _دستورهای رشته_ نامیده می‌شوند، می‌توان از آن‌ها با هر دنباله‌ی بایتی در حافظه، یعنی با هر آرایه، استفاده کرد.

سه دستور رشته‌ی مهم عبارت‌اند از `lods`، `stos` و `movs`:

| دستور | کاری که انجام می‌دهد |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | مقداری را از موقعیت حافظه‌ای که `rsi` نشان می‌دهد در `rax` بارگذاری می‌کند                                                |
| `stos`      | مقداری را از `rax` در موقعیت حافظه‌ای که `rdi` نشان می‌دهد ذخیره می‌کند                                               |
| `movs`      | مقداری را از موقعیت حافظه‌ای که `rsi` نشان می‌دهد کپی می‌کند و آن را در موقعیت حافظه‌ای که `rdi` نشان می‌دهد ذخیره می‌کند    |

توجه کنید که این دستورها _هیچ_ عملوند صریحی نمی‌گیرند.
عملوندهایشان ضمنی هستند.

به‌عنوان یک قاعده‌ی کلی:

1. وقتی عملوند مبدأشان یک موقعیت حافظه است، آدرس آن باید در `rsi` ذخیره شود (`s` به‌معنی source).
2. وقتی عملوند مقصدشان یک موقعیت حافظه است، آدرس آن باید به‌جای آن در `rdi` ذخیره شود (`d` به‌معنی destination).
3. اگر یکی از عملوندها موقعیت حافظه نباشد، همان ثبات `rax` است.

توجه کنید که این دستورها بر اساس عملیات خاصی که انجام می‌دهند، به‌طور خودکار آدرس‌های حافظه را مرجع‌زدایی می‌کنند.

همه‌ی آن‌ها می‌توانند با اندازه‌های مختلف کار کنند.
برای نشان دادن این اندازه، یک پسوند به انتهایشان افزوده می‌شود:

| پسوند | معنا | اندازه    |
| :----: | ------- | :------ |
|  `b`   | بایت    | ۱ بایت  |
|  `w`   | کلمه    | ۲ بایت |
|  `d`   | dword   | ۴ بایت |
|  `q`   | qword   | ۸ بایت |

برای مثال:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

آن‌ها همچنین هر آدرس استفاده‌شده را به اندازه‌ی عملیات به‌روزرسانی می‌کنند.
این به‌روزرسانی بر اساس مقدار **پرچم جهت (DF)** انجام می‌شود:

- اگر `DF` پاک شده باشد، آدرس‌ها به اندازه‌ی عملیات _افزایش_ می‌یابند.
- اگر `DF` تنظیم شده باشد، آدرس‌ها به‌جای آن به همان اندازه _کاهش_ می‌یابند.

ABI سیستموی مقرر می‌کند که پرچم جهت باید هنگام ورود به تابع پاک باشد.
بنابراین، _رفتار پیش‌فرض این است که حافظه به ترتیب صعودی آدرس‌ها خوانده/نوشته شود_.

می‌توان از دستور `cld` برای پاک کردن پرچم جهت استفاده کرد، در حالی که دستور `std` آن را تنظیم می‌کند:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
طبق ABI سیستموی، فراخوان انتظار دارد که `DF` پس از بازگشت هر تابع فراخوانی‌شده پاک شده باشد.
اگر `DF` را تنظیم کردید، حتماً پیش از `ret` آن را پاک کنید.
~~~~

#### Rep

علاوه بر آن‌ها، دستور **rep** مستقیماً با حافظه تعامل نمی‌کند.
در عوض، می‌توان آن را به‌عنوان پیشوند به سایر دستورهای نام‌برده افزود و آن دستورها را _تکرار_ کرد.

وقتی پیشوند `rep` به آن‌ها افزوده شود، دستورهای رشته به تعدادی برابر مقدار `rcx` تکرار می‌شوند.
هر بار، مقدار `rcx` به اندازه‌ی `1` کاهش می‌یابد.
توجه کنید که مقدار `rcx` باید پیش از استفاده از دستور تنظیم شود:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
در پردازنده‌های مدرن، `rep movs` و `rep stos` معمولاً گزینه‌های سریعی برای جابه‌جایی داده در بلوک‌های بزرگ هستند.
با این حال، سایر دستورهای رشته، و حتی `movs` و `stos` هنگام کار بدون `rep`، معمولاً از یک حلقه‌ی ساده کندترند.

نمای عمیق‌تر این موضوع را می‌توانید در [فصل ۱۶.۹، «دستورهای رشته»، از این کتاب مرجع][agner-optimization-guide] بیابید.
