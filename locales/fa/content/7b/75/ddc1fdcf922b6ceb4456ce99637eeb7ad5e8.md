# تاپل

یک [تاپل][tuple] فهرستی متناهی و مرتب از عنصرهاست که تغییرناپذیر است.
تاپل می‌طلبد که همه‌ی موقعیت‌ها نوعی ثابت داشته باشند.
این به‌نوبه‌ی خود یعنی کامپایلر می‌داند در هر موقعیت چه نوعی قرار دارد.
نوع‌های به‌کاررفته در یک تاپل می‌توانند در هر موقعیت متفاوت باشند، اما باید در زمان کامپایل معلوم باشند.

## ساختن تاپل

بسته به اینکه بشود نوع مقدارهای تاپل را در زمان کامپایل استنباط کرد یا نه، می‌توان تاپل را به روش‌های مختلفی ساخت.
اگر مقدارها در زمان کامپایل معلوم باشند، می‌توان تاپل را با نحوه‌ی نگارش لیترال تاپل ساخت؛ در غیر این صورت باید صریحاً اعلام شوند.
همچنین مهم است که نوع مقدارها با نوع‌های تعیین‌شده در تاپل بخواند و تعداد مقدارها با تعداد نوع‌های تعیین‌شده یکی باشد.
اینجا نمونه‌ای از تعریف با نحوه‌ی نگارش لیترال تاپل را می‌بینید:

```crystal
tuple = {1, "foo", 'c'} # Tuple(Int32, String, Char)
```

همچنین می‌توان تاپل را با کلاس `Tuple` ساخت.

```crystal
tuple = Tuple(Int32, String, Char).new(1, "foo", 'c')
```

به‌جای آن، می‌توانید نوع متغیری را که به تاپل نسبت داده می‌شود، صریحاً مشخص کنید.

```crystal
tuple : Tuple(Int32, String, Char) = {1, "foo", 'c'}
```

مشخص کردن صریح نوع تاپل می‌تواند مفید باشد، چون به شما اجازه می‌دهد تعیین کنید که یک موقعیت باید «نوع اجتماع» داشته باشد.
یعنی یک موقعیت می‌تواند چند نوع را در خود جای دهد.

```crystal
tuple : Tuple(Int32 | String, String, Char) = {1, "foo", 'c'}
```

## تبدیل

### ساختن تاپل از آرایه

می‌توانید با متد `from` کلاس `Tuple` از یک آرایه تاپل بسازید.
این کار نیاز دارد که نوع تاپل مشخص شده باشد.

```crystal
array = [1, "foo", 'c']
tuple = Tuple(Int32, String, Char).from(array)
```

### تبدیل به آرایه

می‌توانید با متد `to_a` یک تاپل را به آرایه تبدیل کنید.
نوع عنصرهای آرایه‌ی حاصل، اجتماع نوع هر فیلد در تاپل است.

```crystal
tuple = {1, "foo", 'c'}
array = tuple.to_a
array # => [1, "foo", 'c']
```

## دسترسی به عنصرها

تاپل‌ها هم مانند آرایه‌ها از صفر ایندکس می‌شوند؛ یعنی عنصر اول در ایندکس ۰ قرار دارد.
اما برخلاف آرایه‌ها، نوع هر عنصر ثابت و در زمان کامپایل معلوم است؛ بنابراین هنگام ایندکس کردن یک تاپل، نوع عنصر مخصوص همان موقعیت است.
برای دسترسی به یک عنصر در تاپل، می‌توانید از عملگر `[]` استفاده کنید.

```crystal
array = [1, "foo", 'c']
array[0]         # => 1
typeof(array[0]) # => Int32 | String | Char

tuple = {1, "foo", 'c'}
tuple[0]         # => 1
typeof(tuple[0]) # => Int32
```

تفاوت دیگر در دسترسی به عنصرهای آرایه این است که اگر ایندکس مشخص شده باشد، کامپایلر بررسی می‌کند که ایندکس در محدوده‌ی تاپل باشد.
یعنی به‌جای خطای زمان اجرا، خطای زمان کامپایل می‌گیرید.

```crystal
tuple = {1, "foo", 'c'}
tuple[3]
# => Error: index out of bounds for Tuple(Int32, String, Char) (3 not in -3..2)
```

اما اگر ایندکس در یک متغیر ذخیره شده باشد، کامپایلر نمی‌تواند در زمان کامپایل بررسی کند که ایندکس در محدوده‌ی تاپل هست یا نه و در عوض خطای زمان اجرا می‌دهد.

## زیرتاپل

می‌توانید با استفاده از عملگر `[]` همراه با یک بازه، زیرتاپلی از یک تاپل به دست آورید.
چیزی که برگردانده می‌شود یک تاپل تازه است با عنصرهای بازه‌ی مشخص‌شده.
بازه باید در زمان کامپایل داده شود؛ در غیر این صورت کامپایلر نمی‌تواند نوع عنصرهای زیرتاپل را بداند.
یعنی بازه باید یک لیترال بازه باشد و به متغیری نسبت داده نشود.

```crystal
tuple = {1, "foo", 'c'}
subtuple = tuple[0..1] # Tuple(Int32, String)

i = 0..1
tuple[i]
# Error: Tuple#[](Range) can only be called with range literals known at compile-time
```

## چه زمانی از تاپل استفاده کنیم

تاپل‌ها وقتی به کار می‌آیند که بخواهید تعداد ثابتی مقدار را کنار هم گروه کنید و نوع مقدارها در زمان کامپایل معلوم باشد.
دلیلش این است که تاپل‌ها به‌دلیل تغییرناپذیر بودنشان حافظه‌ی کمتری مصرف می‌کنند و از آرایه‌ها سریع‌ترند.
کاربرد دیگرشان برگرداندن چند مقدار از یک متد است.
این کار به‌ویژه وقتی مفید است که مقدارها نوع‌های متفاوتی داشته باشند، چون هر موقعیت در تاپل می‌تواند نوع متفاوتی داشته باشد.

وقتی به ساختار داده‌ای نیاز دارید که بتواند بزرگ و کوچک شود یا اغلب باید تغییر کند، نباید از تاپل استفاده کنید.
