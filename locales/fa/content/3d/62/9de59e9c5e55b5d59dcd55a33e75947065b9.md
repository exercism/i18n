# تکرارگر سفارشی

```sather
   markers!(once spacing : INT, once count : INT) : INT is
      loop
         yield spacing * 1.upto!(count);
      end;
   end;
```

| | «روال» | «تکرارگر» |
| --- | --- | --- |
| اسم | `foo` | `foo!` |
| یک مقدار را برمی‌گرداند | `return` | `yield` |
| پایان می‌یابد | `return` یا رسیدن به پایان | `quit` یا تمام شدن |
| می‌توان فراخوانی کرد | هر جا | فقط داخل یک `loop` |
| جای خود را نگه می‌دارد | خیر | بله |

## yield

`yield` یک مقدار را تحویل می‌دهد و متوقف می‌شود. در نوبت بعد همه‌چیز بازیابی می‌شود: متغیرهای محلی، جایگاه در حلقه‌های خود تکرارگر و جایگاه هر تکرارگری که خودش آن را فراخوانی می‌کند.

`yield` داخل حلقه‌های تو در تو از درونی‌ترین حلقه ادامه می‌یابد و همین است که نوشتن یک پیمایش روی ساختاری تو در تو را ساده می‌کند:

```sather
   all_cells!(grid : ARRAY{ARRAY{INT}}) : INT is
      loop
         row ::= grid.elt!;
         loop
            yield row.elt!;
         end;
      end;
   end;
```

## quit

تکرارگر را پایان می‌دهد و به این ترتیب، حلقه‌ای را هم که آن را فراخوانی می‌کند. هیچ مقداری حمل نمی‌کند: `quit` یک نتیجه‌ی آخر نیست، بلکه اعلام این است که هیچ نتیجه‌ای وجود ندارد.

تکرارگری که نوع بازگشتی دارد، باید هر بار که `yield` می‌کند یک مقدار هم ارائه دهد؛ `quit` همان راهی است که با آن از این کار سر باز می‌زند.

## once

```sather
   markers!(once count : INT) : INT is
```

آرگومان `once` هنگامی که حلقه وارد می‌شود ارزیابی و نگه داشته می‌شود. یک آرگومان معمولی در هر نوبت دوباره ارزیابی می‌شود و این زمانی اهمیت دارد که عبارت پاس‌داده‌شده شامل فراخوانی یک تکرارگر دیگر باشد:

```sather
   loop
      #OUT + TRAIL::markers!(sizes.elt!);     -- a new count every turn
   end;
```

آرگومان‌ها را `once` علامت بزنید، مگر اینکه دقیقاً همین رفتار را بخواهید. تمام کتابخانه هم همین کار را می‌کند.

## self و تکرارگرها

می‌توان یک تکرارگر را روی یک شیء فراخوانی کرد، و در آن صورت `self` همان شیء است. حالت متوقف‌شده‌ی آن به محل فراخوانی تعلق دارد، نه به شیء، بنابراین دو حلقه‌ای که روی یک شیء یکسان پیمایش می‌کنند با هم تداخل نمی‌کنند.

## چه زمانی یکی بنویسیم

زمانی یک تکرارگر بنویسید که پاسخ یک دنباله باشد و فراخوان باید تصمیم بگیرد چه مقدار از آن را بردارد. توقف زودهنگام هیچ هزینه‌ای ندارد و چیزی ساخته نمی‌شود که به کار نیاید؛ در مقابل، روالی که `ARRAY` برمی‌گرداند ناچار است ابتدا کل آن را بسازد.
