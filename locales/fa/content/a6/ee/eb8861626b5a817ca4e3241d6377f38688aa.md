# درباره

Ruby زبانی پویا و با نوع‌بندی قوی است.
در زبان‌های پویا، نوع یک متغیر یا شیء در زمان اجرا مشخص می‌شود؛ یعنی مقدار یا نوع آن تا آخرین لحظه (زمانی که مفسر آن را تجزیه می‌کند) می‌تواند تغییر کند.
و منظورمان از نوع‌بندی قوی چیست؟
وقتی نوع یک متغیر یا شیء را بدانیم، Ruby درباره‌ی کارهایی که می‌توانید با آن انجام دهید سخت‌گیر است، مثلاً:

```ruby
x = '2'
y = x + 'n'
# => '2n'
```

**اما**

```ruby
x = '2'
y = x + 2
# => TypeError (no implicit conversion of Integer into String)
```

یادتان باشد که در Ruby همه‌چیز یک شیء است.
حتی کلاس‌ها هم نمونه‌هایی از کلاس `Class` هستند.

برای مثال:

```ruby
1.class
# => Integer

Integer.is_a?(Object)
# => true

Class.is_a?(Object)
# => true
```

این یعنی می‌توانیم کلاس‌ها را به این شکل هم تعریف کنیم:

```ruby
Car = Class.new do
  def run
    'running'
  end
end

Car.new.run
# => 'running'
```

و در پایان، در نظر داشته باشید که شیء `Integer` مقادیری را در خود نگه می‌دارد که می‌توان آن‌ها را به‌صورت یک یا چند رقم (پشت سر هم) تعریف کرد و متدهایش از بسیاری از [عملگرهای ریاضی][integers-docs] پشتیبانی می‌کنند.

[integers-docs]: https://docs.ruby-lang.org/en/master/Integer.html

~~~~exercism/note
در مستندات، معمولاً متدهای نمونه با نگارشی مانند `Class#method_name` ارجاع داده می‌شوند، در حالی که متدهای سطح کلاس یا ماژول با `Class::method_name` ارجاع داده می‌شوند.
به `::`، _Scope Resolution Operator_ می‌گویند؛ همان ثابت یا متدی که در سطح کلاس یا ماژول به آن ارجاع داده می‌شود.
این را در مستندات Ruby و در فهرست‌های پستی و دیگر جاهای پشتیبانی خواهید دید.
خواهید دید که ما در نوشته‌هایمان به‌جای آن، متدهای کلاس و ماژول را به‌صورت `ClassName.method_name` یا `ModuleName.method_name` ارجاع می‌دهیم.
~~~~
