# درباره

Gleam می‌تواند روی ماشین مجازی Erlang (BEAM) یا روی زمان‌های اجرای JavaScript اجرا شود. زبان‌های بسیار دیگری هم هستند که از این زمان‌های اجرا استفاده می‌کنند و اغلب مفید است که بتوان کدی را که با این زبان‌ها نوشته شده از داخل Gleam فراخوانی کرد.

قابلیت _«توابع خارجی»_ در Gleam اجازه می‌دهد توابعی که به زبان‌های دیگر نوشته شده‌اند به Gleam وارد شوند و بدون هیچ هزینه‌ی اضافی زمان اجرا فراخوانی شوند.

اگر پروژه‌ی Gleam شما روی ماشین مجازی Erlang اجرا می‌شود و می‌خواهید تابع `reverse` را از ماژول `lists` در Erlang فراخوانی کنید، می‌توانید با افزودن ویژگی `@external` به سرِ تابع Gleam این کار را انجام دهید، به این شکل:

```gleam
@external(erlang, "lists", "reverse")
pub fn reverse_list(x: List(a)) -> List(a)
```

سپس می‌توان آن را مثل یک تابع معمولی Gleam فراخوانی کرد:

```gleam
let reversed = reverse_list([1, 2, 3])
// -> [3, 2, 1]
```

اگر بخواهید این کد را برای زمان‌های اجرای JavaScript کامپایل کنید، با یک پیام خطا شکست می‌خورد، چون پیاده‌سازی‌ای برای JavaScript وجود ندارد. می‌توان پیاده‌سازی دیگری را برای زمان‌های اجرای JavaScript مشخص کرد، به این شکل:

```gleam
@external(erlang, "lists", "reverse")
@external(javascript, "./my_module.mjs", "reverse")
pub fn reverse_list(x: List(a)) -> List(a)
```

همچنین می‌توان پیاده‌سازی‌ای به زبان Gleam نوشت که وقتی برای هدف کامپایل فعلی پیاده‌سازی خارجی وجود ندارد استفاده شود:

```gleam
@external(erlang, "lists", "reverse")
pub fn reverse_list(x: List(a)) -> List(a) {
  tail_recursive_reverse(x, [])
}

fn tail_recursive_reverse(list, reversed) {
  case list {
    [] -> reversed
    [x, ..xs] -> tail_recursive_reverse(xs, [x, ..reversed])
  }
}
```
