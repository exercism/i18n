# مقدمه

## اعمال جزئی و ترکیب توابع

### اعمال جزئی

همه‌ی توابع در Elm [کارینگ‌شده][currying] هستند؛ یعنی اگر تابعی را بدون فرستادن همه‌ی آرگومان‌ها فراخوانی کنید، یک تابع تازه برمی‌گرداند.

به نتیجه‌ی این کار [اعمال جزئی][partial-application] می‌گویند (شما همه‌ی آرگومان‌ها را به تابع نمی‌فرستید، بلکه فقط بخشی از آن‌ها را اعمال می‌کنید).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

اعمال جزئی همیشه آرگومان‌ها را به ترتیب اعمال می‌کند.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

### عملگر لوله (`|>`)

گفتن `x |> f` دقیقاً همان `f x` است. یک مثال عینی: `"5" |> String.toInt` همان `String.toInt "5"` است.

در نگاه اول چندان مفید به نظر نمی‌رسد، اما به آن [عملگر لوله][pipe-operator] می‌گویند، چون به شما اجازه می‌دهد کد را به سبک «لوله‌ای» بنویسید.

برای نمونه، فرض کنید تابعی به اسم `sanitize` داریم که ورودی کاربر را به عدد صحیح تبدیل می‌کند:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

می‌توانیم آن را این‌طور بازنویسی کنیم:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

این کار استفاده از پرانتز را کنار می‌گذارد و توابع را به ترتیبی که اعمال می‌شوند نشان می‌دهد (اول `String.trim`، بعد `String.toInt`)، که به خوانایی کمک می‌کند.

[عملگر لوله‌ی معکوس `(<|)`][reverse-pipe-operator] هم وجود دارد.
گفتن `f <| x` دقیقاً همان `f x` است.
این هم در نگاه اول چندان مفید به نظر نمی‌رسد و قطعاً به اندازه‌ی عملگر لوله استفاده نمی‌شود، اما در بعضی موقعیت‌ها به کنار گذاشتن پرانتز کمک می‌کند.

### ترکیب توابع / سبک بدون نقطه

عملگر [`(>>)`][forward-composition] نوع `(a -> b) -> (b -> c) -> (a -> c)` را دارد و با ترکیب دو تابع سازگار از نوع `a -> b ` و `b -> c` تابعی از نوع `a -> c` می‌سازد.
این کار را با گرفتن خروجی (از نوع `b`) از تابع اول و به کار بردن آن به عنوان آرگومان اول تابع دوم (که باید از همان نوع `b` باشد) انجام می‌دهد.
تابع ساخته‌شده همان ورودی (از نوع `a`) تابع اول را می‌گیرد و هر `c`ی که تابع دوم برگرداند را برمی‌گرداند.

یک مثال عینی `String.trim >> String.toInt` است.
`String.trim` تنها پارامترش یک رشته است، پس تابع ساخته‌شده هم همین را می‌گیرد.
`String.toInt` یک `Maybe Int` برمی‌گرداند، پس تابع ساخته‌شده هم همین را برمی‌گرداند.
`String.trim` یک `String` برمی‌گرداند که `String.toInt` آن را به عنوان پارامتر می‌پذیرد، پس مثال کامپایل می‌شود.

حالا می‌توانیم تابع `sanitize` خودمان را این‌طور بازنویسی کنیم:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

دقت کنید که دیگر از پارامتر `input` که در مثال اصلی می‌بینید استفاده نمی‌کنیم، هرچند کارکرد دقیقاً یکسان است.
به این روش ساختن توابع که هیچ اشاره‌ای به پارامترهایشان نمی‌کنند، «سبک بدون نقطه» می‌گویند.
مزیت این سبک این است که کد موجزتر است؛ عیبش این است که فهم آن دشوارتر می‌شود، به‌ویژه برای تازه‌کارها.

به خاطر داشته باشید که همه‌ی توابع در Elm کارینگ‌شده‌اند، پس `String.length >> max` کامپایل می‌شود.

- عملگر [`(>>)`][forward-composition] نوع `(a -> b) -> (b -> c) -> (a -> c)` را دارد.
- `String.length` نوع `String -> Int` را دارد که همان بخش `(a -> b)` است، پس `a` همان `String` و `b` همان `Int` است.
- `max` نوع `Int -> Int -> Int` را دارد که همان بخش `b -> c` است.
- `b` همان `Int` است، پس `max` به شکل جزئی اعمال می‌شود، پس `c` نتیجه‌ی این اعمال جزئی است (`Int -> Int`).
- پس نوع `String.length >> max` همان `String -> (Int -> Int)` است.
- پس `((String.length >> max) "123") 2` عدد `3` را برمی‌گرداند، چون طول `"123"` برابر ۳ است که از ۲ (آرگومان `Int`) بزرگ‌تر است.

### طراحی توابع

برای اینکه نوشتن کد شیک در Elm آسان باشد، بهتر است ساختار داده‌ی اصلی را آخرین پارامتر توابع قرار دهید.
همه‌ی توابع رایج در کتابخانه‌ی استاندارد همین کار را می‌کنند، مثل `List.map` (امضای نوعش در پایین).

```elm
map : (a -> b) -> List a -> List b
```

اینجا می‌بینیم که آخرین پارامتر تابع `map` همان `List a` است و `List b` را برمی‌گرداند، پس ساختار داده‌ی اصلی (`List`) آخرین پارامتر است.

این کار نوشتن کد شیک و لوله‌ای را ممکن می‌کند، مثل نمونه‌ی زیر.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

همچنین استفاده از ترکیب توابع و سبک بدون نقطه را، به عنوان جایگزینی برای لوله‌کشی، راحت می‌کند.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

ترکیب توابع همچنین اجازه می‌دهد این مثال را به یک فراخوانی واحد `List.map` کاهش دهید.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
