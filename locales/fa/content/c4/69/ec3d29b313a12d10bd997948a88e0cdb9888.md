# درباره

Gleam برای مدیریت خطا از استثنا استفاده نمی‌کند؛ در عوض، توابعی که ممکن است موفق شوند یا شکست بخورند، نوع عمومی `Result` را برمی‌گردانند.

نوع `Result` در خود زبان تعبیه شده است، بنابراین نیازی نیست آن را تعریف یا وارد کنید، اما اگر بخواهید خودتان آن را تعریف کنید، این‌طور به نظر می‌رسد:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

گونه‌ی `Ok` زمانی برگردانده می‌شود که یک تابع موفق شود و گونه‌ی `Error` زمانی برگردانده می‌شود که یک تابع شکست بخورد.

نتیجه‌ها در Gleam بسیار رایج هستند و برنامه‌نویسان Gleam معمولاً برای راحت‌تر شدن کار با آن‌ها از [ماژول `gleam/result`](https://hexdocs.pm/gleam_stdlib/gleam/result.html) استفاده می‌کنند.

از تابع `result.map` می‌توان استفاده کرد تا اگر نتیجه `Ok` است، یک تابع را روی مقدار درون آن فراخوانی کنیم، یا یک `Error` را بدون تغییر عبور دهیم.

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

تابع `result.try` مشابه است، اما انتظار می‌رود تابع کالبک یک نتیجه برگرداند. این برای زنجیره کردن چند تابع که نتیجه برمی‌گردانند مفید است.

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
