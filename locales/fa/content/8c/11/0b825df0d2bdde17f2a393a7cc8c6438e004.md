# معرفی دستورها و آرگومان‌ها

این مسیر درباره‌ی نحوه‌ی استفاده از bash به‌عنوان یک شل تعاملی نیست.
بلکه درباره‌ی یادگیری نوشتن برنامه با bash است، همان زبان برنامه‌نویسی.

یک برنامه‌ی bash، یا _اسکریپت_، دنباله‌ای از دستورهاست که در یک فایل ذخیره شده است.
bash (همان فایل اجرایی) فایل را می‌خواند و دستورها را به ترتیب اجرا می‌کند.

## شبنگ

خط اول یک اسکریپت معمولاً یک _دستورالعمل مفسر_ است که به آن _هش‌بنگ_ یا _شبنگ_ هم می‌گویند:

```bash
#!/usr/bin/env bash
```

وقتی سیستم‌عامل یک فایل غیر دودویی را اجرا می‌کند، خط اول آن را می‌خواند.
اگر خط با `#!` شروع شود، هسته از آن برای تعیین مفسری استفاده می‌کند که باید فایل را اجرا کند.
`#!` باید در ابتدای ابتدای فایل باشد، بدون هیچ فاصله یا خط خالی پیش از آن.

در اینجا، `env` فایل اجرایی `bash` را در `PATH` جست‌وجو می‌کند.
ممکن است شکل ساده‌تر `#!/bin/bash` را هم دیده باشید که مکان مفسر را ثابت تعیین می‌کند؛ شکل `env` قابل‌حمل‌تر است.

~~~~exercism/note
فریب اسکریپت‌ها یا مثال‌های اینترنتی را نخورید که از `/bin/sh` به‌عنوان مفسر استفاده می‌کنند.
**`sh` همان `bash` نیست!**
bash با sh سازگار است و می‌تواند بیشتر اسکریپت‌های `sh` را اجرا کند، اما بعضی ویژگی‌های bash در `sh` می‌شکنند یا رفتار غیرمنتظره نشان می‌دهند.
~~~~

## کامنت‌ها

خطی که با `#` شروع شود یک _کامنت_ است و bash آن را نادیده می‌گیرد.
کامنت می‌تواند پس از یک دستور در همان خط هم بیاید: هر چیزی از `#` تا پایان خط نادیده گرفته می‌شود.
کامنت‌ها برای انسان‌هایی هستند که اسکریپت را می‌خوانند.

## کلمه‌ها و آرگومان‌ها

Bash دستورها را از ورودی خود می‌خواند (که معمولاً یا یک ترمینال است یا یک فایل).
هر خطی از ورودی که می‌خواند به‌عنوان یک _دستور_ در نظر گرفته می‌شود، یعنی دستوری که باید اجرا شود.
(چند مورد پیشرفته هم هست، مثل دستورهایی که چند خط را در بر می‌گیرند، که بعداً درباره‌شان صحبت می‌کنیم.)

Bash هر دستور را به **کلمه‌هایی** تقسیم می‌کند که با کاراکترهای فاصله (اسپیس و تب) از هم جدا می‌شوند.
اولین کلمه، اسم _دستوری_ است که باید اجرا شود.
بقیه‌ی کلمه‌ها به _آرگومان_های آن دستور تبدیل می‌شوند (گزینه‌ها، نام فایل‌ها و غیره).

یک دستور می‌تواند یک _دستور توکار_ bash باشد، مثل `echo`، یا یک برنامه‌ی _اجرایی_، مثل `head`، `awk` یا `sed`.

## دستور `echo`

`echo` آرگومان‌هایش را با یک فاصله از هم چاپ می‌کند و در پایان یک خط جدید می‌زند:

```bash
echo flour sugar eggs
```

خروجی:

```text
flour sugar eggs
```

مقدار فاصله بین آرگومان‌ها اهمیتی ندارد:

```bash
echo flour       sugar        eggs
```

```text
flour sugar eggs
```

فراخوانی `echo` بدون هیچ آرگومانی یک خط خالی چاپ می‌کند.

## گزینه‌ها هم فقط آرگومان‌اند

بسیاری از دستورها _گزینه_هایی می‌پذیرند که رفتارشان را تغییر می‌دهند.
برای bash، گزینه چیز خاصی نیست: کلمه‌ای است مثل هر کلمه‌ی دیگر که با فاصله از همسایه‌هایش جدا می‌شود.
خود دستور تصمیم می‌گیرد آرگومان‌هایش را چطور تفسیر کند.
بر اساس قرارداد، گزینه‌ها با `-` شروع می‌شوند.

دستور `head` خطوط اول یک فایل را چاپ می‌کند.
فرض کنید فایلی به اسم `list.txt` داریم:

```bash
head -n 2 list.txt
```

Bash این خط را به چهار کلمه تقسیم می‌کند:

| کلمه       | نقش                                             |
| ---------- | ----------------------------------------------- |
| `head`     | دستوری که باید اجرا شود                         |
| `-n`       | یک گزینه که به `head` می‌گوید _خط‌ها_ را بشمارد |
| `2`        | مقدار گزینه‌ی `-n`                              |
| `list.txt` | فایلی که باید خوانده شود                        |

Bash سه کلمه‌ی آخر را بدون تغییر به `head` می‌دهد.
این `head` است که می‌داند پس از `-n` یک عدد می‌آید و کلمه‌ی باقی‌مانده یک فایل است.

چون فاصله همان چیزی است که کلمه‌ها را از هم جدا می‌کند، جای آن اهمیت دارد.
`head -n 2` به `head` دو آرگومان می‌دهد (`-n` و `2`)، در حالی که `head -n2` فقط یکی می‌دهد (`-n2`).
بسیاری از دستورها هر دو شکل را می‌پذیرند، اما این به خود دستور بستگی دارد.
Bash اهمیتی نمی‌دهد؛ فقط خط را به کلمه‌ها تقسیم می‌کند.

## قرار دادن آرگومان‌ها در گیومه

[گیومه‌ها][Quotes] کلمه‌ها را در یک _آرگومان واحد_ گرد هم می‌آورند.
فاصله‌های داخل گیومه حفظ می‌شوند و خود کاراکترهای گیومه بخشی از آرگومان نیستند:

```bash
echo "flour       sugar        eggs"
```

```text
flour       sugar        eggs
```

اگر آرگومانی مثل اسم فایل دارای فاصله باشد، آن را در گیومه بگذارید:

```bash
head -n 1 my shopping list.txt     # three files: "my", "shopping", "list.txt"
head -n 1 "my shopping list.txt"   # one file
```

## اجرای اسکریپت

برای اجرای یک اسکریپت، آن را به‌عنوان آرگومان به دستور `bash` بدهید:

```bash
bash myscript
```

وقتی این‌طور استفاده می‌شود، خط `#!` فقط یک کامنت است.
شما به سیستم‌عامل می‌گویید فایل را چطور اجرا کند.

از طرف دیگر، فایل اسکریپت را اجرایی علامت بزنید و آن را مثل هر برنامه‌ی دیگری اجرا کنید:

```bash
chmod +x myscript
./myscript
```

حالا سیستم‌عامل از خط `#!` استفاده می‌کند تا تعیین کند کدام مفسر را به کار ببرد.
