# مقدمه

[concept:csharp/resource-cleanup]() از رابط `IDispose` استفاده می‌کند تا نشان دهد که منبع یک شیء یا سایر وضعیت‌های برنامه باید آزاد یا بازنشانی می‌شد وقتی که آن شیء دیگر لازم نبود (و اینکه تکیه بر جمع‌کننده‌ی زباله این کار را انجام نمی‌داد یا سطح کنترل لازم را فراهم نمی‌کرد) و اینکه متد `IDisposable.Dispose()` جای طبیعی چنین عملیات پاک‌سازی بود.

سازه‌ی دیگری هم وجود دارد، «بلوک `using`»، که از دید فراخوان امکان می‌دهد تمام مدیریت طول عمر منابع در یک دستور جمع شود.

```csharp
using (var file = new File("my_secrets"))
{
    file.WriteSecret("xxxxxxx");
}
```

در مثال بالا، منابع سیستم فایل مرتبط با `file` وقتی از بلوک `using` خارج می‌شویم به سیستم‌عامل بازگردانده می‌شوند.

برای اینکه این الگو کار کند، متغیر موجود در دستور `using` باید نوعی ارجاعی باشد که رابط `IDisposable` را پیاده‌سازی می‌کند و باید در متد `Dispose()` خود منابع را آزاد کند یا وضعیت برنامه را بازنشانی کند.

C# ۸ اصلاحی بر این الگو معرفی می‌کند. دستور `using` را می‌توان در ابتدای یک بلوک قرار داد.

```csharp
using var drawingResource = some_provided_or_new_object;
try
{
    drawingResource.DrawSomething();
}
catch (Exception)
{
    throw;
}
```

برنامه‌نویسان Java ممکن است این را معادلی برای سازوکار _مدیریت خودکار منابع_ بدانند که در Java ۷ معرفی شد.
