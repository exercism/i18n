# مقدمه

## توابع

می‌توانید **توابع سفارشی** خودتان را در `jq` تعریف کنید تا هر منطقی را که لازم دارید در آن بگنجانید.
_توابع_ درست مثل توابع داخلی عمل می‌کنند: یک ورودی می‌گیرند و صفر، یک یا چند خروجی تولید می‌کنند.

### تعریف یک تابع

می‌توانید یک _تابع_ `jq` را با نحوه‌ی نگارش زیر تعریف کنید:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- با کلیدواژه‌ی `def` شروع می‌شود،
- پیش از بدنه‌ی تابع یک دونقطه می‌آید،
- بدنه از یک عبارت واحد تشکیل شده است،
- با یک نقطه‌ویرگول پایان می‌یابد،
- مثل بقیه‌ی نحوه‌ی نگارش `jq`، می‌توانید برای خوانایی از فاصله‌های دلخواه استفاده کنید.

### توابع را کجا قرار دهیم

_توابع_ باید پیش از استفاده تعریف شوند؛ این یک خطاست:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

این یعنی باید _توابع_ را در ابتدای کد `jq` خود، پیش از عبارت «اصلی» قرار دهید.

#### توابع تودرتو

_توابع_ می‌توانند تودرتو باشند:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

اینجا، _تابع_ `B` فقط در بدنه‌ی `A` قابل مشاهده است.

### دامنه

یک _تابع_ یک **دامنه**ی تازه برای متغیرها و توابع تودرتو می‌سازد.

### آرگومان‌ها

**آرگومان‌های** _تابع_ با _نقطه‌ویرگول_ از هم جدا می‌شوند، نه با ویرگول.
برای نمونه، _تابعی_ که یک عدد می‌گیرد و بعد یک عدد به آن اضافه می‌کند و در یک عدد ضرب می‌کند:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

#### آرگومان‌ها _عبارت_ هستند

_آرگومان‌های_ تابع فیلتر هستند، نه مقدار.
به این معنا، مثل چیزی عمل می‌کنند که در زبان‌های دیگر «کالبک» نامیده می‌شود:

با استفاده از تابع `add_mul` به عنوان نمونه:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

اینجا چه اتفاقی می‌افتد؟

- آرگومان `adder` _عبارت_ `. + 5` را می‌گیرد
  - وقتی تابع `. + adder` را انجام می‌دهد، تبدیل به `. + . + 5` می‌شود
  - و چون `. == 10` است، حاصل ۲۵ می‌شود
- به همین ترتیب، آرگومان `multiplier` عبارت `. - 2` است
  - که حاصلش ۸ می‌شود
  - و بعد نتیجه `25 * 8 == 200` است

#### آرگومان‌ها به عنوان مقدار

گاهی می‌خواهید یک _آرگومان_ را به یک متغیر تبدیل کنید:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

برای این کار یک میانبر وجود دارد:

```jq
def my_func($arg):
    other stuff ...
;
```

توجه کنید که این فقط یک میانبر نگارشی است: اسم `arg` بدون `$` همچنان در دامنه‌ی _تابع_ قابل دسترسی است.

### تعداد آرگومان‌ها

_توابع_ یک **تعداد آرگومان** دارند، یعنی شمار _آرگومان‌هایی_ که می‌گیرند.

_توابع_ می‌توانند با تعداد آرگومان‌های متفاوت، از اسم یکسان استفاده کنند.
تابع داخلی [`range`][man-range] این را نشان می‌دهد: `range/1`، `range/2` و `range/3` هر سه در کنار هم وجود دارند.

این می‌تواند برای تعریف توابع بازگشتی که وضعیت را از طریق آرگومان‌ها با خود حمل می‌کنند مفید باشد.
برای نمونه، `map` _می‌توانست_ این‌طور پیاده‌سازی شود:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

### بازگشت

`jq` بهینه‌سازی فراخوانی انتهایی را انجام می‌دهد، اما فقط برای توابع با تعداد آرگومان صفر.

### ماژول‌ها

ماژول `jq` فایلی است که فقط شامل توابع می‌شود.
ماژول‌ها با فرمان‌های [`include`][man-include] یا [`import`][man-import] به یک برنامه‌ی `jq` وارد می‌شوند.
