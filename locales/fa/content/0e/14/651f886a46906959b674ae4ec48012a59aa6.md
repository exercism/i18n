# Tests

testهای یک پروژه‌ی Elm در زیرپوشه‌ی `tests/` آن پروژه قرار دارند.
مجموعه testهای هر تمرین را می‌توان از پوشه‌ی ریشه‌ی همان تمرین اجرا کرد.

```bash
$ cd ~/exercism/elm/hello-world
$ elm-test
```

## تماشای تغییرات

با هر بار ذخیره‌ی تغییرات، testها را به‌طور خودکار دوباره اجرا کنید:

```bash
$ elm-test --watch
```

## روال توسعه‌ی مبتنی بر test

در بیشتر تمرین‌ها، testها از قبل در فایل `tests/Tests.elm` نوشته شده‌اند.
هدف شما این است که با نوشتن کد لازم در فایل `src/<exercise>.elm`، این testها را پاس کنید.
روی نخستین test شکست‌خورده تمرکز کنید، آن را درست کنید،
سپس قطعه‌ی بعدی `skip <|` را در فایل testها حذف یا کامنت کنید و این کار را تکرار کنید
تا زمانی که همه‌ی testها پاس شوند.

## گیر کرده‌اید؟

هدف اول شما این است که کدتان کامپایل شود، حتی اگر `Debug.todo` در آن باشد.
اگر حس می‌کنید نمی‌دانید کاری را چطور انجام دهید،
اغلب مفید است که آن بخش را به‌صورت یک تابع پیاده‌سازی‌نشده‌ی جداگانه استخراج کنید.

```elm
complexOperationOnMultipleStrings : List String -> List String
complexOperationOnMultipleStrings allStrings =
    List.map complexOperation allStrings


complexOperation : String -> String
complexOperation input =
    Debug.todo "Extracted operation into its own function"
```

افزودن حاشیه‌نویسی نوع به این تابع استخراج‌شده
هم به فکر کردن شما کمک می‌کند و هم به کامپایلر تا پیام‌های خطای بهتری به شما بدهد.

## تمیز کردن کدتان

بهتر است پیش از ارسال کدتان، [`elm-format`](https://github.com/avh4/elm-format) را روی آن اجرا کنید
و حتی آن را در ویرایشگر متن خود طوری تنظیم کنید که هنگام ذخیره به‌طور خودکار قالب‌بندی شود.
