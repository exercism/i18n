# معرفی

در Go، رشته‌ها تغییرناپذیرند. به هم چسباندن رشته‌ها با `+` در یک حلقه باعث تخصیص حافظه‌ی مکرر و چندبار کپی شدن داده می‌شود. بسته‌ی [`strings`](https://pkg.go.dev/strings) ابزار [`Builder`](https://pkg.go.dev/strings#Builder) را فراهم می‌کند تا با سرهم‌کردن کارآمد رشته‌ها، سربار حافظه را کمینه کند.

## ساختن رشته‌ها

مقدار صفرِ یک `strings.Builder` بی‌درنگ و بدون هیچ مقداردهی اولیه یا تخصیص حافظه‌ی صریحی آماده‌ی استفاده است. می‌توانید داده‌ی تازه را با متدهای نوشتن مشخص به بیلدر اضافه کنید. هر متد نوشتن یک مقدار خطا برمی‌گرداند تا رابط‌های استاندارد Go را برآورده کند، اما تضمین شده که همیشه `nil` باشد و در کد روزمره معمولاً نادیده گرفته می‌شود.

پرتکرارترین متدها این‌ها هستند:

- `WriteString(s string) (int, error)`: رشته‌ای را به بافر می‌افزاید.
- `WriteRune(r rune) (int, error)`: کدگذاری UTF-8 یک rune را می‌افزاید.
- `WriteByte(c byte) error`: یک بایت را می‌افزاید.

```go
var sb strings.Builder

sb.WriteString("Hello")
var r rune = ' '
sb.WriteRune(r)
var b byte = '.'
sb.WriteByte(b)
```

## بازیابی و بازنشانی

وقتی سرهم‌کردن متن را تمام کردید، می‌توانید محتوای انباشته‌شده را با فراخوانی متد `String()` به‌صورت یک رشته‌ی استاندارد Go بیرون بکشید. فراخوانی `String()` عملیات بسیار کم‌هزینه‌ای است، چون اسلایس بایت زیرین را بی‌درنگ و بدون کپی کردن داده‌های انباشته‌شده به‌صورت رشته برمی‌گرداند.

اگر لازم است از همان نمونه‌ی بیلدر برای ساختن رشته‌ای تازه دوباره استفاده کنید (مثلاً داخل یک حلقه)، می‌توانید متد `Reset()` را فراخوانی کنید. این کار بافر داخلی را خالی می‌کند تا از نو شروع کنید و رشته‌ی بعدی را بسازید، در حالی که ظرفیت حافظه‌ای که از پیش تخصیص یافته در پس‌زمینه حفظ می‌شود.

```go
var sb strings.Builder

sb.WriteString("Task One")
fmt.Println(sb.String()) // Output: Task One

// Clear the buffer for resource reuse
sb.Reset()

sb.WriteString("Task Two")
fmt.Println(sb.String()) // Output: Task Two
```
