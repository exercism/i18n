# مقدمه

عبارت‌های باقاعده روشی بسیار انعطاف‌پذیر برای _تطبیق الگو_ با رشته‌ها هستند و از یک زبان دامنه‌ویژه (DSL) استفاده می‌کنند که برای همین منظور طراحی شده است.

بسیاری از قابلیت‌های عبارت‌های باقاعده در Base R تعبیه شده‌اند و ممکن است نمونه‌هایشان را در کدهای قدیمی‌تر ببینید.

برای کدهای جدید، به‌شدت توصیه می‌شود از کتابخانه‌ی [`stringr`][web-stringr] استفاده کنید.

همان‌طور که در [مفهوم رشته‌ها][concept-strings] اشاره شد، `stringr` مستندات خوبی دارد که معمولاً خودِ نویسنده یا نویسندگان بسته آن را نوشته‌اند.

- یک [وب‌سایت مرجع][web-stringr]
- یک [برگه‌ی تقلب][cheat-stringr].
- یک [فصل رشته‌ها][book-strings] و یک [فصل عبارت‌های باقاعده][book-regex] در کتاب «R for Data Science».

بسیاری از توابعی که پیش‌تر در مفهوم [`Strings`][concept-strings] بررسی کردیم، به‌طور پیش‌فرض برای جست‌وجو با عبارت‌های باقاعده طراحی شده‌اند.

ما مفهوم Strings را نسبتاً ساده نگه داشتیم و فقط با رشته‌های تحت‌اللفظی تطبیق دادیم، اما در عوض می‌توان از هر الگوی عبارت باقاعده‌ای استفاده کرد.

به‌طور رسمی، یک عبارت باقاعده در R با فراخوانی [`regex()`][ref-regex] ساخته می‌شود.
برای راحتی کار، توابع `stringr` هر رشته‌ی الگو را به‌عنوان یک عبارت باقاعده در نظر می‌گیرند.
در مثال زیر، `str_replace_all()` اولی فقط «شکر نحوی» نسخه‌ی دوم است:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[برگه‌ی تقلب][cheat-stringr] راهنمای مفیدی است: همه‌ی توابعی که آرگومان `pattern` دارند (که با رنگ قرمز چاپ شده‌اند) یک عبارت باقاعده می‌پذیرند و صفحه‌ی ۲ خلاصه‌ای از نحوه‌ی نگارش عبارت‌های باقاعده ارائه می‌دهد.

توجه داشته باشید که تابع [`regex()`][ref-regex] هنوز هم می‌تواند مهم باشد، مثلاً وقتی بخواهید پیش‌فرض‌ها مانند حساسیت به بزرگی و کوچکی حروف یا `locale` را تغییر دهید.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

بسیاری از الگوهای عبارت باقاعده شامل بک‌اسلش هستند، مانند `\s` که در بالا استفاده شد.
در رشته‌های معمولی R، کاراکتر `\` باید با دو برابر کردن escape شود، و به همین دلیل به شکل `"\\s"` نوشته می‌شود.

بک‌اسلش‌ها می‌توانند زیاد شوند و گیج‌کننده شوند، پس در موارد پیچیده ممکن است استفاده از [رشته‌های خام][book-raw] کمک‌کننده باشد.

به‌طور پیش‌فرض، نحوه‌ی نگارش برای تعریف یک رشته‌ی خام `r"( )"` است، اما جداکننده‌های دیگری هم مجازند.
چون هم پرانتزهای `( )` و هم کروشه‌های `[ ]` در نحوه‌ی نگارش عبارت‌های باقاعده رایج‌اند (برای گروه‌های گیرش و گروه‌های گزینه)، آکولادهای `{ }` ممکن است انتخاب خوبی باشند.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## تشخیص تطبیق‌ها

در ادامه چند پرسش می‌آید و توابعی که می‌توانند در پاسخ دادن به آن‌ها کمک کنند.

برخی مثال‌ها از `fruit` استفاده می‌کنند، برداری از ۸۰ اسم میوه که همراه `stringr` برای تمرین ارائه شده است.

_آیا یک رشته شامل تطبیق است؟_
از `str_detect()`، یا `str_starts()` و `str_ends()` استفاده کنید تا نیازی به لنگرهای `^` یا `$` نباشد.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_فقط رشته‌هایی را برگردان که شامل تطبیق هستند؟_
برای گرفتن خود رشته‌ها از `str_subset()` و برای گرفتن اندیس‌ها از `str_which()` استفاده کنید.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_در هر رشته چند تطبیق وجود دارد؟_
از `str_count()` استفاده کنید.

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_تطبیق کجاست؟_
برای استفاده‌ی تعاملی `str_view()` و به‌طور کلی‌تر `str_locate()` یا `str_locate_all()`.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## گروه‌های گیرش

معمولاً می‌خواهیم بدانیم _چه چیزی_ تطبیق پیدا کرده است.
این کار با گنجاندن گروه‌های گیرش داخل پرانتز در عبارت باقاعده انجام می‌شود.

می‌توان درون همان عبارت باقاعده به گیرش‌ها ارجاع داد، با استفاده از `\1`، `\2` و به همین ترتیب.
برای نمونه، یافتن جفت‌های تکراری حروف:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

با نحوه‌ی نگارشی مشابه، می‌توان از گیرش‌ها در رشته‌های جایگزینی هم استفاده کرد:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

برای پردازش‌های بعدی، تطبیق‌ها را با تابع `str_match()` برای فقط تطبیق اول، یا با `str_match_all()` برای همه‌ی تطبیق‌ها جمع‌آوری کنید.

گروه‌های گیرش در هر زبانی معمولاً خروجی پیچیده‌ای تولید می‌کنند.
رویکرد R (_که به‌عنوان چالشی اضافه، برداری‌شده هم هست_) این است که از `str_match()` یک ماتریس بسازد؛ یک سطر برای هر رشته‌ی ورودی، ستون ۱ شامل کل رشته‌ی تطبیق‌خورده و ستون‌های باقی‌مانده شامل گروه‌های گیرش مختلف.

استفاده از گروه‌های نام‌دار می‌تواند یک مزیت باشد، چون به اسم ستون‌ها در ماتریس نتایج تبدیل می‌شوند.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

در این سرفصل‌ها درباره‌ی ماتریس‌ها زیاد صحبت نکرده‌ایم، هرچند یک [سند مفهوم][concept-matrices-arrays] در دسترس شما هست.
ماتریس‌ها با اکوسیستم Tidyverse چندان جور در نمی‌آیند، با اینکه مدت‌هاست بخشی از Base R هستند.

به‌طور خلاصه: با ماتریس‌ها مثل بردارهایی با ۲ اندیس رفتار کنید، به ترتیب `[rows, cols]`.
هر کدام از اندیس‌ها را خالی بگذارید تا کل سطر یا ستون را بگیرید.

وقتی یک سطر مشخص `r` را با `m[r,]` یا یک ستون مشخص `c` را با `m[,c]` می‌گیرید، مقدار بازگشتی به‌طور پیش‌فرض به یک بردار تخت می‌شود.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

طبیعتاً `str_match_all()` خروجی‌ای با ساختاری حتی پیچیده‌تر تولید می‌کند:

- نتیجه یک لیست است، با یک عنصر برای هر رشته‌ی ورودی.
- اگر فقط یک رشته‌ی ورودی وجود داشته باشد، خروجی را با اندیس‌دهی `[[1]]` از حالت لیست درآورید، همان‌طور که در [مفهوم لیست‌ها][concept-lists] توضیح داده شده است.
- هر عنصر یک ماتریس است، با ستون‌هایی مانند `match()`.
- هر سطر در ماتریس یک گیرش موفق است.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

البته ممکن است تطبیق شکست بخورد.
در این حالت نتیجه مقدار ویژه‌ی `NA` خواهد بود.
آماده باشید که این حالت را بررسی کنید، همان‌طور که در [مفهوم هیچ‌بودگی][concept-nothingness] توضیح داده شده است.

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
