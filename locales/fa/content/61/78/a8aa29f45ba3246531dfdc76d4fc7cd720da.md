# منطقی

`BOOL` یکی از دو مقدار `true` و `false` را نگه می‌دارد.

```sather
   ready : BOOL is
      return true;
   end;
```

## مقایسه

| عملگر | می‌پرسد | مثال |
| --- | --- | --- |
| `=` | یکسان؟ | `age = 13` |
| `/=` | متفاوت؟ | `age /= 13` |
| `<` | کوچک‌تر از | `age < 13` |
| `<=` | کوچک‌تر یا مساوی | `age <= 13` |
| `>` | بزرگ‌تر از | `age > 13` |
| `>=` | بزرگ‌تر یا مساوی | `age >= 13` |

این‌ها روی اعداد کار می‌کنند و `=` و `/=` روی رشته‌ها هم کار می‌کنند.

## سه عملگر

| عملگر | نوشته | وقتی «درست» است |
| --- | --- | --- |
| and | `a and b` | هر دو «درست» هستند |
| or | `a or b` | حداقل یکی «درست» است |
| not | `~a` | `a` «غلط» است |

`and` و `or` **به‌صورت کوتاه ارزیابی می‌شوند**: `a and b` وقتی معلوم شود `a` «غلط» است، دیگر به `b` نگاه نمی‌کند، چون پاسخ از پیش روشن است. به همین ترتیب، `a or b` اگر `a` «درست» باشد، متوقف می‌شود. این موضوع وقتی مهم می‌شود که سمت راست پرهزینه باشد، یا اگر اجرا شود به خطا برود.

## بازگرداندن مستقیم یک مقایسه

روتینی که تمام کارش پرسیدن یک پرسش است، باید همان پرسش را برگرداند، نه اینکه با یک شرط پاسخ را انتخاب کند:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

نوشتن `if age >= 13 then return true else return false end` سه خط طول می‌کشد تا همان چیزی را بگوید که مقایسه از قبل گفته است و هر خواننده‌ی باتجربه‌ای هم متوجه می‌شود.

## اولویت

`~` بالاترین اولویت را دارد، سپس `and`، سپس `or`. پس

```sather
~a and b or c
```

یعنی `((~a) and b) or c`. نوشتن پرانتز هزینه‌ای ندارد و هر جا که خواننده در غیر این صورت باید آن ترتیب را به خاطر بسپارد تا خط را دنبال کند، ارزشش را دارد.
