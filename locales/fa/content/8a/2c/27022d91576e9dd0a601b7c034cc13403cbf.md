# مقدمه

## استثنا

همه‌ی خطاها در Elixir «رفتار استثنا» را پیاده‌سازی می‌کنند. «رفتار استثنا» درست مانند «رفتار دسترسی»، توابع کالبکی را تعریف می‌کند که یک ماژول برای ایفای قرارداد نرم‌افزاری این رفتار باید پیاده‌سازی کند. وقتی یک خطا تعریف می‌شود، ویژگی‌های زیر را دارد:

- اسم ماژول، اسم خطا را تعیین می‌کند.
- ماژول یک ساختار خطا تعریف می‌کند.
- این ساختار یک فیلد `:message` خواهد داشت.
- می‌توان از ماژول همراه با `raise/1` و `raise/2` برای raise کردن خطای مورد نظر استفاده کرد.

«رفتار استثنا» همچنین دو تابع کالبک را مشخص می‌کند: `message/1` و `exception/1`. اگر پیاده‌سازی نشوند، از پیاده‌سازی‌های پیش‌فرض استفاده می‌شود. `message/1` هنگام فراخوانی با `raise`، ساختار خطا را به یک پیام خوانا تبدیل می‌کند. `exception/1` امکان می‌دهد هنگام فراخوانی با `raise/2`، زمینه‌ی بیشتری به پیام اضافه شود.

### تعریف یک استثنا

برای تعریف یک استثنا از یک ماژول خطا، از ماکروی `defexception` استفاده می‌کنیم:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

### استفاده از استثنا

از خطاهای تعریف‌شده می‌توان مانند یک خطای داخلی و با `raise/1` یا `raise/2` استفاده کرد.

- `raise/1` یک خطای مشخص را با اسم ماژولش raise می‌کند، یا اگر آرگومان یک رشته باشد، یک `RuntimeError` را با آن رشته به عنوان پیام raise می‌کند.
- `raise/2` یک خطای مشخص را با اسم ماژولش raise می‌کند و یک آرگومان ویژگی‌ها می‌پذیرد که برای به دست آوردن خطا با پیام مناسب به کار می‌رود.
