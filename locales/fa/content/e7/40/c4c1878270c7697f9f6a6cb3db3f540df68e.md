# توابع در `jq`

می‌توانید در `jq` **توابع سفارشی** خودتان را تعریف کنید تا هر منطقی را که لازم دارید در آن‌ها بگنجانید.
_توابع_ درست مثل توابع درون‌ساخت عمل می‌کنند: یک ورودی می‌گیرند و صفر، یک یا چند خروجی تولید می‌کنند.

## تعریف یک تابع

می‌توانید یک _تابع_ `jq` را با نحوه‌ی نگارش زیر تعریف کنید:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- با کلیدواژه‌ی `def` شروع می‌شود،
- پیش از بدنه‌ی تابع یک دونقطه می‌آید،
- بدنه از یک عبارت واحد تشکیل شده است،
- با یک نقطه‌ویرگول تمام می‌شود،
- مثل بقیه‌ی نحوه‌ی نگارش `jq`، می‌توانید برای خوانایی از فاصله‌های دلخواه استفاده کنید.

## توابع را کجا قرار دهیم

_توابع_ باید پیش از استفاده تعریف شوند؛ این یک خطاست:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

این یعنی باید _توابع_ را در بالای کد `jq` خود و پیش از عبارت «اصلی» قرار دهید.

### توابع تودرتو

_توابع_ می‌توانند تودرتو باشند:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

در اینجا _تابع_ `B` فقط در بدنه‌ی `A` دیده می‌شود.

## محدوده

هر _تابع_ یک **محدوده‌ی** تازه برای متغیرها و توابع تودرتو ایجاد می‌کند.

## آرگومان‌ها

**آرگومان‌های** _تابع_ با _نقطه‌ویرگول_ از هم جدا می‌شوند، نه با ویرگول.
برای مثال، _تابعی_ که یک عدد می‌گیرد و بعد یک عدد به آن اضافه می‌کند و در عددی ضرب می‌کند:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
نقطه‌ویرگول لازم است چون ویرگول در `jq` از قبل یک کاربرد دارد: عملگری که جریان‌ها را به هم می‌پیوندد.

استفاده از ویرگول به‌جای نقطه‌ویرگول تلاش می‌کند دو بار تابع `add_mul` با _یک آرگومان_ را فراخوانی کند، که چنین تابعی وجود ندارد و بنابراین در همان اولین فراخوانی شکست می‌خورد:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

ویرگول در `5, 4` اعداد ۵ و ۴ را به یک جریان به هم می‌چسباند.
وقتی تابعی را با یک جریان به‌عنوان آرگومان فراخوانی می‌کنیم، `jq` آن تابع را چند بار فراخوانی می‌کند، یک بار برای هر مقدار در جریان.
این نمونه‌ای از «تکرار ضمنی» است که ذاتی جریان‌های `jq` است.
`10 | add_mul(5, 4)` معادل این است:

```jq
(10 | add_mul(5)), (10 | add_mul(4))
```
حالا می‌بینیم خطای `add_mul/1 is not defined` چطور پدیدار می‌شود.
~~~~

<!-- prettier-ignore-end -->

### آرگومان‌ها _عبارت_ هستند

آرگومان‌های تابع فیلتر هستند، نه مقدار.
از این نظر، مثل چیزی عمل می‌کنند که در زبان‌های دیگر به آن «کال‌بک» می‌گویند:

با استفاده از تابع `add_mul` به‌عنوان مثال:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

اینجا چه اتفاقی می‌افتد؟

- آرگومان `adder` _عبارتِ_ `. + 5` را می‌گیرد
  - وقتی تابع `. + adder` را انجام می‌دهد، آن به `. + . + 5` تبدیل می‌شود
  - که چون `. == 10` است، به ۲۵ ارزیابی می‌شود
- به همین ترتیب، آرگومان `multiplier` عبارتِ `. - 2` است
  - که به ۸ ارزیابی می‌شود
  - و بعد نتیجه `25 * 8 == 200` است

### آرگومان‌ها به‌عنوان مقدار

گاهی می‌خواهید یک _آرگومان_ را به یک متغیر تبدیل کنید:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

یک شکل کوتاه‌تر هم برای این کار وجود دارد:

```jq
def my_func($arg):
    other stuff ...
;
```

توجه کنید که این فقط یک میان‌بر نوشتاری است: اسم `arg` که `$` ندارد، هنوز هم در محدوده‌ی _تابع_ قرار دارد.

<!-- prettier-ignore -->
~~~~exercism/caution
برای مثال، من برای حل یک تمرین چیزی شبیه به این نوشتم:

```jq
# function that encodes the input value
def code:
    # expression here
    ;

def equals($code):
    (. | code) as $this_code
    | $code == $this_code
    ;

("some key value" | code) as $key
| ["array", "of", "values"]
| map(select(equals($key)))
```

و تعجب کردم که هر مقدار آرایه با کلید برابر بود.

این اتفاق افتاد چون jq تابع `equals` را این‌طور می‌دید:

```jq
def equals(code):
    code as $code
    | (. | code) as $this_code
    | $code == $this_code
    ;
```

**آرگومانِ** `code` روی **تابعِ** `code` که پیش‌تر تعریف شده بود _سایه انداخت_.
یعنی `(. | code)` به‌جای محاسبه‌ی یک `code` تازه بر اساس مقدار ورودی، فقط همان **آرگومان** را خروجی می‌داد.
در نتیجه `$this_code` و `$code` همیشه یکی بودند.
~~~~

<!-- prettier-ignore-end -->

## آریتی

_توابع_ یک **آریتی** دارند، یعنی تعداد _آرگومان‌هایی_ که می‌گیرند.

_توابع_ می‌توانند اسم یکسان را با آریتی‌های متفاوت به کار ببرند.
تابع درون‌ساختِ [`range`][man-range] این را نشان می‌دهد: `range/1`، `range/2` و `range/3` همه در کنار هم وجود دارند.

این می‌تواند برای تعریف توابع بازگشتی که حالت را از طریق آرگومان‌ها با خود می‌برند مفید باشد.
برای مثال، `map` _می‌توانست_ این‌طور پیاده‌سازی شود:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## بازگشت

`jq` بهینه‌سازی فراخوانی پایانی را انجام می‌دهد، اما فقط برای توابعی با آریتی صفر.

## ماژول‌ها

ماژول `jq` فایلی است که فقط توابع در آن قرار دارند.
ماژول‌ها با دستورهای [`include`][man-include] یا [`import`][man-import] به یک برنامه‌ی jq وارد می‌شوند.
