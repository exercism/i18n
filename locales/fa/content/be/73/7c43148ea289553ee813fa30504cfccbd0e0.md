# درباره

Go مانند بسیاری از زبان‌های دیگر اشاره‌گر دارد.
اگر تازه با اشاره‌گرها آشنا شده‌اید، ممکن است کمی رمزآلود به نظر برسند، اما وقتی به آن‌ها عادت کنید، کاملاً سرراست می‌شوند.
آن‌ها بخشی حیاتی از Go هستند، پس وقت بگذارید تا واقعاً آن‌ها را درک کنید.

پیش از پرداختن به جزئیات، بهتر است کاربرد اشاره‌گرها را درک کنید.
اشاره‌گرها راهی برای به اشتراک گذاشتن حافظه با سایر بخش‌های برنامه‌ی ما هستند، که به دو دلیل عمده مفید است:

1. وقتی حجم زیادی داده داریم، ساختن کپی برای انتقال بین توابع بسیار ناکارآمد است.
   در عوض، با انتقال مکان حافظه‌ای که داده در آن ذخیره شده، می‌توانیم ردپای منابع برنامه‌هایمان را به‌طور چشمگیری کاهش دهیم.
2. با انتقال اشاره‌گرها بین توابع، می‌توانیم مستقیماً به تنها نسخه‌ی داده دسترسی داشته باشیم و آن را تغییر دهیم؛ یعنی هر تغییری که یک تابع ایجاد می‌کند، به محض پایان یافتن تابع برای سایر بخش‌های برنامه فوراً قابل مشاهده است.

## متغیرها و حافظه

فرض کنید یک متغیر عدد صحیح معمولی به اسم `a` داریم:

```go
var a int
```

وقتی متغیری تعریف می‌کنیم، Go باید جایی در حافظه برای ذخیره‌ی مقدار آن پیدا کند.
این موضوع عمدتاً از ما انتزاع شده است؛ وقتی بخواهیم مقدار ذخیره‌شده در آن تکه از حافظه را بازیابی کنیم، کافی است با اسم متغیر به آن ارجاع دهیم.

برای مثال، وقتی `a + 2` را می‌نویسیم، در واقع مقدار ذخیره‌شده در حافظه‌ی مرتبط با متغیر `a` را بازیابی می‌کنیم و ۲ را به آن اضافه می‌کنیم.

به‌طور مشابه، وقتی بخواهیم مقدار موجود در تکه‌حافظه‌ی `a` را تغییر دهیم، می‌توانیم با استفاده از اسم متغیر یک انتساب انجام دهیم:

```go
a = 3
```

تکه‌حافظه‌ای که با `a` مرتبط است، اکنون مقدار `3` را ذخیره می‌کند.

## اشاره‌گرها

متغیرها به ما اجازه می‌دهند به مقادیر موجود در حافظه ارجاع دهیم، اما گاهی دانستن **آدرس حافظه**ای که متغیر به آن اشاره می‌کند مفید است.
**اشاره‌گرها** آدرس‌های حافظه‌ی آن مقادیر را نگه می‌دارند.
متغیری با نوع اشاره‌گر را با قرار دادن یک ستاره پیش از نوع پایه تعریف می‌کنید:

```go
var p *int // 'p' contains the memory address of an integer
```

در اینجا متغیر `p` را با نوع «اشاره‌گر به `int`» (`*int`) تعریف می‌کنیم.
یعنی `p` آدرس حافظه‌ی یک عدد صحیح را نگه می‌دارد.
مقدار صفر اشاره‌گرها `nil` است، زیرا یک اشاره‌گر `nil` هیچ آدرس حافظه‌ای نگه نمی‌دارد.

### گرفتن اشاره‌گر به یک متغیر

برای یافتن آدرس حافظه‌ی مقدار یک متغیر، می‌توانیم از عملگر `&` استفاده کنیم.
برای مثال، اگر بخواهیم آدرس حافظه‌ی متغیر `a` را پیدا کنیم و در اشاره‌گر `p` ذخیره کنیم، می‌توانیم این کار را انجام دهیم:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### دسترسی به مقدار از طریق اشاره‌گر (ارجاع‌زدایی)

وقتی اشاره‌گری داریم، ممکن است بخواهیم مقدار ذخیره‌شده در آدرس حافظه‌ای را بدانیم که اشاره‌گر به آن اشاره دارد.
می‌توانیم این کار را با استفاده از عملگر `*` انجام دهیم:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

عمل `*p` مقدار ذخیره‌شده در آدرس حافظه‌ای را که در `p` ذخیره شده است، بازیابی می‌کند.
این عمل اغلب «ارجاع‌زدایی» نامیده می‌شود.

همچنین می‌توانیم از عملگر ارجاع‌زدایی برای انتساب مقدار جدیدی به آدرس حافظه‌ای که اشاره‌گر به آن ارجاع دارد استفاده کنیم:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

انتساب به `*pa` مقدار ذخیره‌شده در آدرس حافظه‌ای را که `pa` نگه می‌دارد تغییر می‌دهد.
از آنجا که `pa` آدرس حافظه‌ی `a` را نگه می‌دارد، با انتساب به `*pa` در واقع مقدار `a` را تغییر می‌دهیم!

اما یک هشدار: همیشه پیش از ارجاع‌زدایی بررسی کنید که اشاره‌گر `nil` نباشد.
ارجاع‌زدایی از یک اشاره‌گر `nil` باعث می‌شود برنامه در زمان اجرا از کار بیفتد!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### اشاره‌گرها به ساختارها

تا اینجا فقط اشاره‌گرها به مقادیر پایه را دیده‌ایم.
می‌توانیم برای ساختارها هم اشاره‌گر بسازیم:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

می‌توانستیم یک `Person` جدید هم بسازیم و بلافاصله اشاره‌گری به آن ذخیره کنیم:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

وقتی اشاره‌گری به یک ساختار داریم، برای دسترسی به یکی از فیلدها نیازی نیست اشاره‌گر را ارجاع‌زدایی کنیم:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## اسلایس‌ها و مپ‌ها از قبل اشاره‌گر هستند

اسلایس‌ها و مپ‌ها انواع خاصی هستند، زیرا از قبل در پیاده‌سازی‌شان اشاره‌گر دارند.
این یعنی اغلب اوقات، برای به اشتراک گذاشتن آدرس حافظه‌ی مقادیر این انواع، نیازی به ساختن اشاره‌گر برای آن‌ها نداریم.
تصور کنید تابعی داریم که مقدار یک کلید را در یک مپ افزایش می‌دهد:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

اگر یک مپ بسازیم و این تابع را فراخوانی کنیم، تغییراتی که تابع در مپ ایجاد کرده است پس از پایان تابع باقی می‌مانند.
این رفتار مشابه حالتی است که از اشاره‌گر استفاده می‌کردیم، اما توجه کنید که در این مثال از هیچ ارجاع‌دهی/ارجاع‌زدایی یا هیچ‌یک از روش‌های نوشتن اشاره‌گر استفاده نمی‌کنیم:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

همین موضوع در مورد تغییر یک عنصر موجود در یک اسلایس هم صدق می‌کند.

با این حال، کارهایی که یک اسلایس جدید برمی‌گردانند، مانند `append`، یک حالت خاص هستند و **ممکن است** اسلایس بیرون از تابع را تغییر ندهند.
این به دلیل نحوه‌ی کار داخلی اسلایس‌هاست، اما به‌طور جزئی به آن نمی‌پردازیم، چون موضوع پیشرفته‌تری است.
اگر واقعاً کنجکاو هستید، می‌توانید در [وبلاگ Go: مکانیزم `append`][mechanics-of-append] بیشتر درباره‌ی این موضوع بخوانید.

## حساب اشاره‌گر

برخلاف زبان‌های دیگر، Go از حساب اشاره‌گر پشتیبانی نمی‌کند.
یعنی نمی‌توانید با افزایش مقدار اشاره‌گر، از آدرس حافظه‌ی یک مقدار به آدرس مقدار دیگر بروید.
بنابراین قطعه‌کدهایی مانند زیر نامعتبر هستند:

```go
var a int
a = 2

var pa *int
pa = &a
pa++ // NOT ALLOWED: incrementing the pointer or any other pointer arithmetic operations are invalid
```
