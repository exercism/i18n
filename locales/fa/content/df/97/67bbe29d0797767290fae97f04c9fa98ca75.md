# استثنا

در دنیای ایده‌آل، همه‌چیز بی‌نقص کار می‌کند.
اما در دنیای واقعی، ممکن است خطاهایی رخ دهد، و نحوه‌ی برخورد ما با این موقعیت‌ها مهم است تا مطمئن شویم نرم‌افزارمان مقاوم و قابل‌اعتماد است.
استثناها مفهومی حیاتی در برنامه‌نویسی هستند که به ما امکان می‌دهند خطاها و موقعیت‌های پیش‌بینی‌نشده را به‌شکلی روان مدیریت کنیم.

ایجاد یک خطا، اگر مدیریت نشود، برنامه را متوقف می‌کند و یک پیام خطا بیرون می‌دهد.
در بیشتر موارد، نمی‌خواهید برنامه‌تان هنگام بروز خطا متوقف شود؛ در عوض می‌خواهید خطا را مدیریت کنید و اجرای برنامه را ادامه دهید.

## ایجاد یک استثنا

در Crystal، استثناها با «کلیدواژه»ی `raise` ایجاد می‌شوند و می‌توان به آن‌ها یک `String` یا یک شیء `Exception` داد.
اگر مدیریت نشود، برنامه متوقف می‌شود و پیام خطا را چاپ می‌کند.

```crystal
raise "This is an error"
```

در Crystal چندین استثنای داخلی وجود دارد، مانند `ArgumentError`، `IndexError`، `KeyError`، `IOError`، `SystemCallError`، `TypeError`، `ZeroDivisionError` و بسیاری دیگر.
برای این‌ها باید پیامی به استثنا بدهید.

```crystal
raise ArgumentError.new("This is an argument error")
```

## [مدیریت استثناها][exception-handling]

نمی‌خواهیم برنامه‌مان وقتی استثنایی ایجاد می‌شود از کار بیفتد.
بنابراین، وقتی می‌دانیم بخشی از کد مستعد خطاست، می‌توانیم آن را در یک «بلوک» `begin` بپیچیم و استثنا را با یک بلوک `rescue` بگیریم.
بلوک `begin` آغاز کدی را مشخص می‌کند که ممکن است استثنا ایجاد کند، و بلوک `rescue` استثنا را مدیریت می‌کند.

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
end
```

بلوک `rescue` را می‌توان با یک متغیر هم مشخص کرد تا شیء استثنا را دریافت کنید.

```crystal
begin
 raise "This is an error"
rescue ex
 puts "An error occurred: #{ex.message}"
end
```

بلوک `rescue` را می‌توان تنها با یک نوع استثنای مشخص هم تعیین کرد تا فقط همان استثنا گرفته شود.

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
end

# or

begin
 raise ArgumentError.new("This is an argument error")
rescue ex : ArgumentError
 puts "An argument error occurred: #{ex.message}"
end
```

می‌توان از چند بلوک `rescue` برای مدیریت انواع مختلف استثناها استفاده کرد.
در مثال زیر، بلوک `rescue` اول یک `ArgumentError` را می‌گیرد و بلوک `rescue` دوم هر استثنای دیگری را می‌گیرد.

```crystal
begin
 raise ArgumentError.new("This is an argument error")
rescue ArgumentError
 puts "An argument error occurred!"
rescue
 puts "An error occurred!"
end
```

بلوک `begin` می‌تواند یک بلوک `else` هم داشته باشد که در صورت ایجاد نشدن استثنا اجرا می‌شود.

```crystal
begin
 puts "No error occurred"
rescue
 puts "An error occurred!"
else
 puts "No error occurred"
end
```

در پایان، یک بلوک `ensure` هست که همیشه اجرا می‌شود، فارغ از اینکه استثنایی ایجاد شده باشد یا نه.

```crystal
begin
 raise "This is an error"
rescue
 puts "An error occurred!"
ensure
 puts "This is always executed"
end
```

## قرارداد متدها

برخی متدها دو نسخه دارند، یکی با `!` و دیگری بدون آن.
این می‌تواند دو معنای متفاوت داشته باشد.
یکی اینکه متد شیء را تغییر می‌دهد، و دیگری اینکه متد می‌تواند استثنا ایجاد کند.

اما قرارداد دیگری هم هست که مربوط به پایان یافتن نام متد با `?` است و در مفهوم «منطقی» به آن اشاره شده است.
برخی متدها به‌طور پیش‌فرض استثنا ایجاد می‌کنند، اما نسخه‌ای هم دارند که با `?` تمام می‌شود و به‌جای ایجاد استثنا `nil` برمی‌گرداند.

این زمانی ایده‌آل است که می‌خواهید از ایجاد یک خطا جلوگیری کنید.
این می‌تواند به کارایی کمک کند، چون نیازی نیست «استک‌تریس» ساخته شود و اگر درست تنظیم شود، می‌تواند کد را امن‌تر کند.

## استثناهای سفارشی

همچنین می‌توانید استثناهای خودتان را با ارث‌بری از کلاس [`Exception`][exception] بسازید.
با این کار، می‌توانید به‌صورت اختیاری متد `initialize` را بازنویسی کنید تا پیام استثنا را تعیین کنید.
این کار را می‌توان با اختصاص دادن پیام به یک متغیر نمونه به اسم `@message` انجام داد.

```crystal
class MyException < Exception
 def initialize
   @message = "This is my exception"
 end
end

raise MyException.new
```
