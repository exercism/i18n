# مقدمه

تقریباً هر برنامه‌ی Factor دنباله‌ای از واژه‌هاست که مقادیر را روی «پشته‌ی داده» مصرف و تولید می‌کنند. وقتی ورودی‌ها و خروجی‌ها مرتب کنار هم قرار بگیرند، کد بدون هیچ دردسری از چپ به راست خوانده می‌شود. اما وقتی این‌طور نباشد، باید به سراغ «واژه‌های جابه‌جایی» بروید و کد به‌سرعت شلوغ می‌شود.

این تمرین شما را با راه‌حل استاندارد Factor، یعنی «ترکیب‌کننده‌ها»، آشنا می‌کند.

## واژه‌های جابه‌جایی

رایج‌ترین واژه‌های جابه‌جایی در [`kernel`][kernel] قرار دارند:

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

شما پیش‌تر از `dup` و `swap` استفاده کرده‌اید. `over` یک کپی از *دومین* عنصر از بالای پشته می‌سازد؛ این وقتی به کار می‌آید که یک ورودی واحد باید دو محاسبه را تغذیه کند:

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

این کار برای یک بار استفاده خوب است. اما وقتی پشت سر هم بیایند، دنباله‌هایی از `dup`، `swap`، `over` و `rot` به‌سرعت ناخوانا می‌شوند.

## `keep`: نگه‌داشتن ورودی

`keep` (در [`kernel`][kernel]) یک «کوتیشن» را روی بالای پشته فراخوانی می‌کند، اما مقدار اصلی را بالای نتیجه باقی می‌گذارد:

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

این الگوی «`dup`، بعد یک چیز، و بعد جابه‌جایی» را جایگزین می‌کند: هرجا که `dup something swap` می‌نوشتید، می‌توانید فقط `[ something ] keep` بنویسید.

## `bi`: دو تابع روی یک ورودی

`bi` (در [`kernel`][kernel]) *دو* کوتیشن را روی یک مقدار اعمال می‌کند و هر دو نتیجه را روی پشته باقی می‌گذارد:

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

بدون `bi` باید `dup sq swap neg` می‌نوشتید؛ برای دو عمل هنوز خواناست، اما برای سه عمل پیچیده و ناخوانا می‌شود.

## `tri` و `cleave`: چند تابع روی یک ورودی

`tri` قابلیت `bi` را به سه کوتیشن گسترش می‌دهد:

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

`cleave` (در [`combinators`][combinators]) همان ایده را برای یک *آرایه* با هر تعداد کوتیشن به کار می‌برد:

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

کوتیشن خالی `[ ]` نقش تابع همانی را بازی می‌کند؛ وقتی به کار می‌آید که یکی از جایگاه‌های کارت برش باید خودِ ورودی باشد.

## `dip` و `2dip`: کار کردن در زیر

`dip` (در [`kernel`][kernel]) یک کوتیشن را روی مقادیر *زیر* بالای پشته فراخوانی می‌کند و بالای پشته را دست‌نخورده باقی می‌گذارد. `2dip` همین کار را می‌کند، اما از *دو* مقدار بالای پشته محافظت می‌کند:

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

اینجا `dip` مقدار `11` را پنهان کرد، `9 10 +` را اجرا کرد و `11` را دوباره روی بالا گذاشت. `2dip` مقدارهای `11 12` را پنهان کرد، `9 10 +` را در زیر اجرا کرد و سپس `11 12` را بازگرداند.

`dip` ابزار درست است وقتی ترتیب طبیعی آرگومان‌ها مقدار «عبوری» را روی بالای پشته باقی می‌گذارد. به‌جای ساندویچ `swap … swap` سراغ آن بروید.

## `bi@`: یک عمل روی دو مقدار

`bi@` (در [`kernel`][kernel]) یک کوتیشن را روی دو مقدار پشته اعمال می‌کند:

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*`: عمل‌های متفاوت روی دو مقدار

`bi*` (در [`kernel`][kernel]) دو کوتیشن *متفاوت* را روی دو مقدار پشته اعمال می‌کند؛ کوتیشن اول روی مقدار پایین‌تر و کوتیشن دوم روی بالای پشته:

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

وقتی با هر دو مقدار یکسان رفتار می‌شود، سراغ `bi@` بروید، و وقتی هرکدام به رفتار خودش نیاز دارد، سراغ `bi*`.

## `tri*`: عمل‌های متفاوت روی سه مقدار

`tri*` (در [`combinators`][combinators]) قابلیت `bi*` را به سه مقدار و سه کوتیشن گسترش می‌دهد و هر کوتیشن را به ترتیب روی یک مقدار اعمال می‌کند:

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```
