# درباره

Common Lisp چندین شرطی متفاوت در اختیار برنامه‌نویس می‌گذارد که می‌توان آن‌ها را بر اساس تعداد «شاخه‌هایی» که پشتیبانی می‌کنند دسته‌بندی کرد.

همچنین، برخلاف بسیاری از زبان‌های برنامه‌نویسی دیگر، همه‌ی شرطی‌ها در Common Lisp _عبارت‌اند_، نه دستور.
یعنی همه‌ی شرطی‌های Lisp به مقداری ارزیابی می‌شوند و می‌توان آن‌ها را جای پارامترهای مشخص گذاشت.

برای نمونه:

```lisp
;; Doubles x when it's even
(* x (if (evenp x) 2 1))
```

## شرطی‌های تک‌شاخه

شرطی‌های `when` و `unless` کدی را فقط زمانی ارزیابی می‌کنند که آزمون ارائه‌شده به ترتیب «درست» یا «غلط» باشد؛ در غیر این صورت به `nil` ارزیابی می‌شوند.

بخش پس از عبارت آزمون می‌تواند بیش از یک عبارت باشد.

```lisp
(when (= 2 2) "All is well")      ; => "All is well"
(unless (= 2 2) "Time to panic!") ; => NIL
```

## شرطی دو شاخه‌ای

شرطی `if` وقتی آزمون درست باشد اولین عبارت بدنه را ارزیابی می‌کند و در غیر این صورت دومی را.

```lisp
(if (= 2 2) 'how-honest 'you-liar) ; => HOW-HONEST
```

توجه کنید که بندهای `then` و `else` هر کدام فقط می‌توانند یک عبارت باشند.

## شرطی‌های چندشاخه

«ابَرشرطی» لیسپ `cond` است، که می‌تواند بی‌شمار شاخه داشته باشد.
هر شاخه یک شرط آزمون و یک عبارت بدنه دارد که در یک جفت پرانتز اضافی قرار می‌گیرند.
اگر همه‌ی آزمون‌ها به «غلط» ارزیابی شوند، آنگاه `nil` برگردانده می‌شود.

```lisp
(cond ((= 0 2) 'nope)
      ((= 1 2) 'try-again)
      ((= 2 2) 'quite-true)
      ((= 3 2) 'too-far)
      (t 'something-else))
; => QUITE-TRUE
```

توجه کنید که تعداد عبارت‌های پس از عبارت آزمون محدودیتی ندارد.


اگر فقط می‌خواهید یک مقدار را در برابر چند شاخه بیازمایید، می‌توانید از عبارت مرتب‌تر `case` استفاده کنید.
اگر هیچ‌یک از حالت‌ها مطابقت نداشته باشند، `nil` برگردانده می‌شود.
هم `t` و هم `otherwise` می‌توانند به عنوان حالت‌های همه‌گیر به کار روند:

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark")
  (otherwise "???"))
; => "???"
```

توجه کنید که مانند `cond`، تعداد عبارت‌های پس از عبارت آزمون محدودیتی ندارد.

## شرطی‌های پنهان‌کار

عملگرهای «منطقیِ» `and` و `or` در Common Lisp ماکروهایی با ارزیابی اتصال‌کوتاه‌اند که می‌توان از آن‌ها برای کاهش تکرار برخی عبارت‌های شرطی استفاده کرد.

ماکروی `and` اگر حتی یک مقدار «غلط» ببیند بی‌درنگ `nil` برمی‌گرداند، اما در غیر این صورت آخرین مقدار «درست» را برمی‌گرداند:

```lisp
(and 42 "Magic" :cool) ; => :COOL
(and () "Magic" :cool) ; => NIL
```

ماکروی `or` نخستین مقدار «درست»ی را که ببیند برمی‌گرداند، یا اگر هیچ مقدار «درست»ی نبود `nil` را:

```lisp
(or () 42 nil)  ; => 42
(or () NIL nil) ; => NIL
```

## دیگر خسته‌ام...

همان‌طور که پیش‌تر اشاره شد، وقتی هیچ‌یک از شاخه‌های یک دستور `case` مطابقت نداشته باشد و بند `otherwise` هم نباشد، `nil` برگردانده می‌شود.
اما گاهی اوقات، ناموفق بودن در مطابقت با هر شاخه باید به عنوان خطا در نظر گرفته شود؛ اینجاست که `ecase` (برای مطابقت **جامع**) به کار می‌آید.

دقیقاً به همان شیوه‌ی `case` به کار می‌رود، اما وقتی مطابقتی وجود نداشته باشد به جای برگرداندن `nil` خطا اعلام می‌کند.

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => NIL

(ecase 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => ERROR: ELDER-BEAST fell through ECASE expression. Wanted one of (CAT BIRD DOG).
```
