# درباره

[concept:csharp/resource-cleanup]() از رابط `IDispose` استفاده می‌کند تا به فراخوان‌کنندگان یک کلاس اطلاع دهد که منابع یا وضعیت برنامه‌ای وجود دارد که وقتی شیء موردنظر دیگر لازم نیست، باید به‌موقع آزاد یا بازنشانی شوند. در این تمرین مقداری «شکر نحوی» با کلیدواژه‌ی `using` معرفی کرده‌ایم که کد را کم‌حجم‌تر می‌کند و احتمال حذف فراخوانی‌های مهم را کاهش می‌دهد.

می‌توان `using` را در برخی موارد جایگزین [`try/finally`][try-finally] دانست.

```csharp
File file = null;
try
{
    file = new File("myStuff.txt");
    file.Write("more stuff");
}
finally
{
    file.Dispose();
}
```

این نحوه‌ی نگارش با شکل فشرده‌تر و خطاناپذیرتر زیر جایگزین می‌شود:

```csharp
using (var file = new File("myStuff.txt")
{
    file.Write("more stuff");
}
```

توجه کنید که می‌توان چندین منبع را طبق قواعد استاندارد بلوک‌های تک‌خطی به‌راحتی با هم ترکیب کرد:

```csharp
using (var file = new File("mystuff.txt")
using (var fileWriter = new StreamWriter(file)
{
     ...
}
```

در C# ۸ گونه‌ی زیر معرفی شد که در آن دستور `using` در ابتدای بلوک می‌آید:

```csharp
using var file = new File("myStuff.txt");
file.Write("more stuff");
```

این کار به شما امکان می‌دهد چندین شیء قابل‌آزادسازی را در یک بلوک داشته باشید و [`try/catch`][try-catch] را طبیعی‌تر مدیریت کنید:

```csharp
using var fileIn = new File("myStuff.txt");
using var fileOut = new File("yourStuff.txt");
try
{
    var stuff = fileIn.Read();
    fileOut.Write(stuff);
}
catch (Exception)
{
    LogStuff();
}
```

قواعد مربوط به نحوه‌ی استفاده از کلیدواژه‌ی `using` و اینکه روی نمونه‌های چه نوع‌هایی می‌توان آن را به کار برد، [اینجا][using-statement] به تفصیل آمده است.

## نکته‌ای برای برنامه‌نویسان Java

برنامه‌نویسان Java ممکن است این را معادلی برای سازوکار [_مدیریت خودکار منابع_][automatic-resource-management] بدانند که در Java ۷ معرفی شد. این دو بسیار شبیه هم هستند. نحوه‌ی نگارش در Java، که `try` را بازاستفاده می‌کند، این مزیت را دارد که بلوک‌های `catch` را طبیعی‌تر از `using` در C# در خود جای می‌دهد.

## نسخه‌ها

توجه کنید که نسخه‌ی انعطاف‌پذیرتر `using`، که بلوک نگارشی مستقل خود را ندارد، در C# ۸ معرفی شد؛ پس ممکن است لازم باشد بررسی کنید که کدبیسی که روی آن کار می‌کنید از C# ۸ یا بالاتر استفاده می‌کند یا نه.
