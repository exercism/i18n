# خصیصه

«خصیصه» مجموعه‌ای از متدها را مشخص می‌کند که یک نوع می‌تواند پیاده‌سازی کند.
خصیصه‌ها برای تعریف متدهایی به کار می‌آیند که باید میان نوع‌ها مشترک باشند.
وقتی خصیصه‌ها با نوع‌های جنریک به کار می‌روند، متدهای تعریف‌شده را می‌توان روی یک نوع خاص فراخوانی کرد و همچنین می‌توان آن‌ها را روی نوع داده‌ی دیگری فراخوانی کرد.
به شکلی انتزاعی، با استفاده از _محدوده‌های خصیصه_ می‌توانیم مشخص کنیم که نوع جنریک باید رفتار خاصی را به اشتراک بگذارد.

> **توجه:** خصیصه‌ها ویژگی‌ای مشابه آنچه در زبان‌های برنامه‌نویسی دیگر «رابط» نامیده می‌شود دارند، البته با چند تفاوت.

## تعریف خصیصه

تعریف یک خصیصه به شناسایی امضای تابعی کمک می‌کند که مجموعه‌ی رفتارهایی را می‌سازد که یک نوع می‌تواند برای رسیدن به یک نتیجه پیاده‌سازی کند.
این متدها رفتار یک نوع را می‌سازند.
اگر بتوانیم متدهای یکسانی را روی نوع‌های مختلف فراخوانی کنیم، یعنی نوع‌های درگیر رفتار یکسانی دارند.

```rust
#[derive(Drop)]
pub struct NewsArticle {
    pub headline: ByteArray,
    pub location: ByteArray,
    pub author: ByteArray,
    pub content: ByteArray,
}

// A trait for NewsArticle struct type
pub trait Summary {
    fn summarize(self: @NewsArticle) -> ByteArray;
}
```

بر اساس تعریف خصیصه‌ی `Summary` در بالا، متد `summarize` رفتاری است که فقط نوع ساختار `NewsArticle` می‌تواند آن را فراخوانی کند.
اگر روی نمونه‌های نوع دیگری فراخوانی شود، خطای کامپایل می‌دهد.
اعلام خصیصه با «کلیدواژه»ی `pub`، این خصیصه را در این کریت برای کریت‌های دیگری که قصد استفاده از آن را هم دارند آشکار می‌کند.
همچنین توجه کنید که پس از اعلام امضای متدها در خصیصه‌ها، از نقطه‌ویرگول استفاده می‌کنیم.

می‌توان خصیصه را با یک آرگومان جنریک تعریف کرد که به یک تابع اجازه می‌دهد آرگومانی از هر نوع داده را بپذیرد.
این انعطافی در امضای تابع به وجود می‌آورد تا بتواند انواع گوناگون داده را مدیریت کند.
در مورد خصیصه‌ی `Summary` زیر، آن را طوری بازطراحی کرده‌ایم که برای هر نوع داده کار کند، تا وقتی متد `summarize` روی آن‌ها فراخوانی می‌شود، یک `ByteArray` برگرداند.

```rust
// A trait for a generic type
pub trait Summary<T> {
    fn summarize(self: @T) -> ByteArray;
}
```

یک خصیصه می‌تواند بیش از یک متد در بدنه‌اش داشته باشد؛ هر امضای متد اعلام‌شده یک خط است که با نقطه‌ویرگول پایان می‌یابد.

## پیاده‌سازی خصیصه روی یک نوع

پس از تعریف امضاهای تابعی که یک خصیصه را می‌سازند، کامپایلر تضمین می‌کند که برای نوع‌هایی که خصیصه را می‌پذیرند، یک پیاده‌سازی نیز تعریف شده باشد.
در ادامه یک کریت کتابخانه‌ای رسانه‌ای به نام `aggregator` نوشته‌ایم که بخشی از داده‌های نمونه‌های `NewsArticle` و `Tweet` را خلاصه می‌کند.
برای ساختار `NewsArticle` از `headline`، `author` و `location` استفاده می‌کنیم تا مقدار متد `summarize` از خصیصه‌ی `Summary` را برگردانیم، و برای ساختار `Tweet` از `username` و `content` استفاده می‌کنیم، با این فرض که محتوای توییت محدودیت ۲۸۰ کاراکتری دارد.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray;
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {
        fn summarize(self: @NewsArticle) -> ByteArray {
            format!("{} by {} ({})", self.headline, self.author, self.location)
        }
    }

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    let tweet = Tweet {
        username: "EliBenSasson",
        content: "Crypto is full of short-term maximizing projects. \n @Starknet and @StarkWareLtd are about long-term vision maximization.",
        reply: false,
        retweet: false
    };

    println!("New article available! {}", news.summarize());
    println!("New tweet! {}", tweet.summarize());
}
```

## پیاده‌سازی‌های پیش‌فرض

گاهی می‌توان خصیصه را با یک پیاده‌سازی پیش‌فرض برای برخی یا همه‌ی متدهایی که آن را می‌سازند تعریف کرد.
هدف این است که نیازی نباشد همه‌ی متدها روی هر نوع پیاده‌سازی شوند و خوانایی کد بهتر شود.
اگر نوع خاصی به پیاده‌سازی ویژه‌ای از متد یک خصیصه نیاز داشته باشد، می‌تواند پیاده‌سازی پیش‌فرض را بازنویسی کند.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray {
            "(Read more...)"
        }
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {}

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    println!("New article available! {}", news.summarize()); // prints "New article available! (Read more...)"


    let tweet = Tweet {
        username: "Alice",
        content: "Cairo is fun and engaging.",
        reply: true,
        retweet: true,
    };
    println!("New tweet from {}", tweet.summarize()); // prints "New tweet from Alice: Cairo is fun and engaging."
}
```

## نحوه‌ی استفاده و مدیریت خصیصه‌های بیرونی

خصیصه‌ها و پیاده‌سازی‌ها را می‌توان در یک ماژول بیرونی تعریف کرد و در ماژول‌های دیگر به کار برد، به شرطی که به‌درستی وارد شده باشند.
فرض کنید یک خصیصه‌ی `ShapeGeometry` با متد `boundary` داریم که باید برای هر دو ساختار `Circle` و `Rectangle` پیاده‌سازی شود.
در ادامه مثالی می‌بینید از اینکه خصیصه و پیاده‌سازی‌اش چگونه در میان ماژول‌ها وارد، مدیریت و استفاده می‌شوند.

```rust
// Here T is an alias type which will be provided during implementation
pub trait ShapeGeometry<T> {
    fn boundary(self: T) -> u64;
    fn area(self: T) -> u64;
}

mod rectangle {
    // Importing ShapeGeometry is required to implement this trait for Rectangle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Rectangle {
        pub height: u64,
        pub width: u64,
    }

    // Implementation RectangleGeometry passes in <Rectangle>
    // to implement the trait for that type
    impl RectangleGeometry of ShapeGeometry<Rectangle> {
        fn boundary(self: Rectangle) -> u64 {
            2 * (self.height + self.width)
        }
        fn area(self: Rectangle) -> u64 {
            self.height * self.width
        }
    }
}

mod circle {
    // Importing ShapeGeometry is required to implement this trait for Circle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Circle {
        pub radius: u64
    }

    // Implementation CircleGeometry passes in <Circle>
    // to implement the imported trait for that type
    impl CircleGeometry of ShapeGeometry<Circle> {
        fn boundary(self: Circle) -> u64 {
            (2 * 314 * self.radius) / 100
        }
        fn area(self: Circle) -> u64 {
            (314 * self.radius * self.radius) / 100
        }
    }
}

use rectangle::Rectangle;
use circle::Circle;

fn main() {
    let rect = Rectangle { height: 5, width: 7 };
    println!("Rectangle area: {}", ShapeGeometry::area(rect)); //35
    println!("Rectangle boundary: {}", ShapeGeometry::boundary(rect)); //24

    let circ = Circle { radius: 5 };
    println!("Circle area: {}", ShapeGeometry::area(circ)); //78
    println!("Circle boundary: {}", ShapeGeometry::boundary(circ)); //31
}
```

دیدپذیری پیاده‌سازی برای هر دو `CircleGeometry` و `RectangleGeometry` نیازی به عمومی بودن ندارد، چون خصیصه‌ی `ShapeGeometry` عمومی شده است و کامپایلر باید به‌راحتی آن را پیدا کند.

## نام‌های مستعار پیاده‌سازی

هنگام وارد کردن پیاده‌سازی‌ها می‌توان با استفاده از کلیدواژه‌ی `impl` برای آن‌ها نام مستعار تعریف کرد.
این کار هنگام نمونه‌سازی یک پیاده‌سازی جنریک برای نوع‌های مشخص به کار می‌آید.
بیایید یک پیاده‌سازی ساده از خصیصه‌ی `Two` برای همه‌ی نوع‌هایی که خصیصه‌ی `One` را پیاده‌سازی می‌کنند تعریف کنیم، به این صورت که دو برابر مقدار `One` را جمع کنیم و حاصل‌جمع را برگردانیم.
بعد از آن می‌توانیم پیاده‌سازی `Two` را که فقط برای نوع‌های `u8` و `u128` کار می‌کند، در دسترس قرار دهیم.

```rust
trait Two<T> {
    fn two() -> T;
}

mod one_based {
    pub impl TwoImpl<
        T, +Copy<T>, +Drop<T>, +Add<T>, impl One: core::num::traits::One<T>
    > of super::Two<T> {
        fn two() -> T {
            One::one() + One::one()
        }
    }
}

pub impl U8Two = one_based::TwoImpl<u8>;
pub impl U128Two = one_based::TwoImpl<u128>;
```

پیاده‌سازی جنریک را می‌توان در یک ماژول خصوصی نوشت و با استفاده از نام مستعار `impl`، پیاده‌سازی جنریک این دو نوع مشخص را نمونه‌سازی کرد.
مزیت استفاده از یک پیاده‌سازی جنریک خصوصی و پنهان این است که از تکرار کد در میان فایل‌ها جلوگیری می‌کند.
همچنین API عمومی را ساده و تمیز نگه می‌دارد.
