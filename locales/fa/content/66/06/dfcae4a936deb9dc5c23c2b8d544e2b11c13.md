# تاپل

یک [تاپل][tuple] فهرستی متناهی و مرتب از عناصر است که تغییرناپذیر است.
در تاپل، هر موقعیت باید نوعی ثابت داشته باشد.
به این ترتیب، کامپایلر می‌داند که در هر موقعیت چه نوعی قرار دارد.
نوع‌های به‌کاررفته در یک تاپل می‌توانند در هر موقعیت متفاوت باشند، اما باید در زمان کامپایل معلوم باشند.

## ساختن یک تاپل

بسته به اینکه آیا نوع مقادیر تاپل در زمان کامپایل قابل تشخیص است یا نه، تاپل به روش‌های مختلفی ساخته می‌شود.
اگر مقادیر در زمان کامپایل معلوم باشند، می‌توان تاپل را با نحوه‌ی نگارش «لیترال تاپل» ساخت؛ در غیر این صورت باید صریحاً اعلام شوند.
همچنین مهم است که نوع مقادیر با نوع‌های مشخص‌شده در تاپل هم‌خوانی داشته باشند و تعداد مقادیر با تعداد نوع‌های مشخص‌شده برابر باشد.
نمونه‌ی زیر تعریف با نحوه‌ی نگارش لیترال تاپل را نشان می‌دهد:

```crystal
tuple = {1, "foo", 'c'} # Tuple(Int32, String, Char)
```

همچنین می‌توان تاپل را با کلاس `Tuple` ساخت.

```crystal
tuple = Tuple(Int32, String, Char).new(1, "foo", 'c')
```

به‌عنوان گزینه‌ی دیگر، می‌توانید نوع متغیری را که به تاپل نسبت داده می‌شود، صریحاً مشخص کنید.

```crystal
tuple : Tuple(Int32, String, Char) = {1, "foo", 'c'}
```

مشخص‌کردن صریح نوع تاپل می‌تواند مفید باشد، زیرا به شما امکان می‌دهد تعیین کنید که یک موقعیت نوع اجتماع را در خود جای دهد.
یعنی یک موقعیت می‌تواند چند نوع را در خود جای دهد.

```crystal
tuple : Tuple(Int32 | String, String, Char) = {1, "foo", 'c'}
```

## تبدیل

### ساختن تاپل از آرایه

می‌توانید با متد `from` کلاس `Tuple` یک تاپل از یک آرایه بسازید.
این کار نیازمند آن است که نوع تاپل مشخص شده باشد.

```crystal
array = [1, "foo", 'c']
tuple = Tuple(Int32, String, Char).from(array)
```

### تبدیل به آرایه

می‌توانید با متد `to_a` یک تاپل را به آرایه تبدیل کنید.
نوع عناصر آرایه‌ی حاصل، اجتماع نوع هر فیلد در تاپل است.

```crystal
tuple = {1, "foo", 'c'}
array = tuple.to_a
array # => [1, "foo", 'c']
```

### شکل کوتاه تعریف تاپل

شکل کوتاهی برای تعریف نوع‌های صریح تاپل وجود دارد.
آن هم با نوشتن نوع‌ها درون لیترال تاپل.

```crystal
tuple : {Int32, String, Char} = {1, "foo", 'c'}
```

## دسترسی به عناصر

مانند آرایه‌ها، اندیس‌گذاری تاپل‌ها از صفر شروع می‌شود، یعنی عنصر اول در اندیس ۰ قرار دارد.
اما برخلاف آرایه‌ها، نوع هر عنصر ثابت است و در زمان کامپایل معلوم می‌شود؛ بنابراین هنگام اندیس‌گذاری یک تاپل، نوع عنصر مخصوص همان موقعیت است.
برای دسترسی به یک عنصر در تاپل، می‌توانید از عملگر `[]` استفاده کنید.

```crystal
array = [1, "foo", 'c']
array[0]         # => 1
typeof(array[0]) # => Int32 | String | Char

tuple = {1, "foo", 'c'}
tuple[0]         # => 1
typeof(tuple[0]) # => Int32
```

تفاوت دیگر در دسترسی به عناصر آرایه‌ها این است که اگر اندیس مشخص شده باشد، کامپایلر بررسی می‌کند که اندیس در محدوده‌ی تاپل قرار دارد یا نه.
یعنی به‌جای خطای زمان اجرا، خطای زمان کامپایل دریافت می‌کنید.

```crystal
tuple = {1, "foo", 'c'}
tuple[3]
# => Error: index out of bounds for Tuple(Int32, String, Char) (3 not in -3..2)
```

اما اگر اندیس در یک متغیر ذخیره شده باشد، کامپایلر نمی‌تواند در زمان کامپایل بررسی کند که اندیس در محدوده‌ی تاپل قرار دارد یا نه و در عوض خطای زمان اجرا می‌دهد.

## زیرتاپل

می‌توانید با استفاده از عملگر `[]` به‌همراه یک بازه، زیرتاپلی از یک تاپل بگیرید.
مقداری که برگردانده می‌شود، تاپل جدیدی است که عناصر بازه‌ی مشخص‌شده را در خود دارد.
بازه باید در زمان کامپایل داده شود؛ در غیر این صورت کامپایلر نمی‌تواند نوع عناصر زیرتاپل را بداند.
یعنی بازه باید یک لیترال بازه باشد و به متغیری نسبت داده نشود.

```crystal
tuple = {1, "foo", 'c'}
subtuple = tuple[0..1] # Tuple(Int32, String)

i = 0..1
tuple[i]
# Error: Tuple#[](Range) can only be called with range literals known at compile-time
```

## چه زمانی از تاپل استفاده کنیم

تاپل‌ها زمانی مفیدند که بخواهید تعداد ثابتی مقدار را کنار هم گروه‌بندی کنید و نوع این مقادیر در زمان کامپایل معلوم باشد.
دلیلش این است که تاپل‌ها حافظه‌ی کمتری مصرف می‌کنند و به دلیل تغییرناپذیر بودنشان از آرایه‌ها سریع‌ترند.
کاربرد دیگر، برگرداندن چند مقدار از یک متد است.
این کار به‌ویژه هنگامی کمک‌کننده است که مقادیر نوع‌های متفاوتی داشته باشند، چون هر موقعیت در تاپل می‌تواند نوع متفاوتی داشته باشد.

نباید از تاپل استفاده کرد وقتی به ساختار داده‌ای نیاز دارید که بتواند بزرگ یا کوچک شود یا اغلب نیاز به تغییر داشته باشد.
