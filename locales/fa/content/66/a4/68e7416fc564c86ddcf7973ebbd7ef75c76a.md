# درباره

## مقدمه

«نوع مات» یک تکنیک کپسوله‌سازی در Elm است.
بعضی‌ها به این کار پنهان‌سازی اطلاعات یا پنهان کردن جزئیات پیاده‌سازی هم می‌گویند.
از نوع مات معمولاً برای اعمال اعتبارسنجی هم استفاده می‌شود، به کمک الگوی [تجزیه کنید، اعتبارسنجی نکنید][parse-dont-validate].
برای مثال، می‌توانید یک نوع مات `EmailAddress` داشته باشید که فقط می‌تواند نشانی‌های ایمیل معتبر را در خود نگه دارد (برخلاف `String` که هر محتوایی را در خود می‌گنجاند).

## ساختن یک نوع مات

[نوع‌های سفارشی][custom-types] یک یا چند *گونه* دارند و کامپایلر به‌طور خودکار برای ساختن هر *گونه* تابعی تولید می‌کند، با استفاده از اسم همان *گونه*.
این‌ها تنها راه ساختن نوع سفارشی هستند.
کامپایلر همچنین امکان «واکاوی» این گونه‌ها را فراهم می‌کند.

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

به‌طور پیش‌فرض، همه‌ی این‌ها درونیِ فایل یا ماژول است و از کلیدواژه‌ی `exposing` استفاده می‌کنیم تا انتخاب کنیم چه بخشی آشکار شود.
برای ساختن یک نوع مات، کافی است انتخاب کنید که *گونه‌ها* را آشکار نکنید.

وقتی این کار را می‌کنید، تقریباً همیشه باید راه دیگری برای ساختن و دریافت *گونه‌ها* فراهم کنید، با آشکار کردن توابع سفارشی.
این توابع سفارشی به شما اجازه می‌دهند هنگام ساختن و دریافت *گونه‌ها* منطقی را اعمال کنید.
این کار جزئیات پیاده‌سازی درونی ماژول را پنهان می‌کند و یعنی می‌توانید جزئیات پیاده‌سازی را هرقدر که بخواهید تغییر دهید، تا زمانی که توابع آشکارشده یکسان بمانند.

## تجزیه کنید، اعتبارسنجی نکنید

احتمالاً رایج‌ترین کاربرد نوع مات، اعمال اعتبارسنجی است، با الگوی [تجزیه کنید، اعتبارسنجی نکنید][parse-dont-validate].
در این الگو، تابعی را آشکار می‌کنید که ورودی‌ای با ساختار یا ایمنی نوع کمتر از آنچه می‌خواهید می‌گیرد، مثل `String`. این تابع ورودی را به نوعی ساختاریافته‌تر تجزیه می‌کند، مثل `EmailAddress`، و یا آن نوع را برمی‌گرداند یا یک خطا (معمولاً `Maybe` یا `Result`).

برای مثال، در کد زیر فقط ماژول‌های بیرونی می‌توانند با استفاده از تابع `parseEmailAddress` یک `EmailAddress` بسازند، بنابراین وقتی با نوع `EmailAddress` کار می‌کنید، مطمئن هستید که معتبر است.

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
