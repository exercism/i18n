# مقدمه

هر بار که یک تابع فراخوانی می‌شود، یک قاب پشته‌ی تازه در حافظه ساخته می‌شود تا آرگومان‌ها و متغیرهای محلی تابع را در خود ذخیره کند، و این قاب پشته هنگام بازگشت تابع آزاد می‌شود. چون Gleam به‌جای نگارش حلقه‌ای از فراخوانی توابع بازگشتی استفاده می‌کند، ممکن است در نتیجه حافظه‌ی زیادی صرف این قاب‌های پشته شود.

برای پرهیز از این مشکل، Gleam از «بهینه‌سازی فراخوانی پایانی» پشتیبانی می‌کند. این بهینه‌سازی به کامپایلر اجازه می‌دهد اگر فراخوانی یک تابع آخرین کاری باشد که تابع انجام می‌دهد، قاب پشته‌ی تابع فعلی را دوباره به کار بگیرد. یعنی یک تابع می‌تواند بی‌نهایت بار خود را فراخوانی کند، بدون آنکه حافظه‌ی اضافی مصرف شود.

اغلب می‌توان با استفاده از یک «انباشتگر»، توابع بازگشتی بهینه‌نشده را به توابع بهینه‌شده با فراخوانی پایانی بازنویسی کرد.

انباشتگر متغیری است که علاوه بر داده‌ها به تابع فرستاده می‌شود. از آن برای انتقال وضعیت فعلی اجرای تابع استفاده می‌شود، تا زمانی که به حالت پایه برسیم.

انباشتگر را باید نویسنده‌ی تابع مقداردهی اولیه کند، نه کاربر تابع. برای این کار دو تابع تعریف کنید: یک تابع عمومی که تنها داده‌های لازم را به‌عنوان آرگومان می‌گیرد و انباشتگر را مقداردهی اولیه می‌کند، و یک تابع خصوصی که انباشتگر را هم می‌گیرد.

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
