# Nil

کریستال نوعی به نام [`Nil`][nil] دارد که فقط می‌تواند یک مقدار داشته باشد: `nil`.
از آن برای نمایش نبودِ مقدار استفاده می‌شود و در زبان‌های دیگر شبیه `null` یا `None` است.

مقادیر Nil می‌توانند از متدهای مختلفی برگردانده شوند، مثلاً [`String#[]?`][string-index] که اگر اندیس خارج از محدوده باشد `nil` برمی‌گرداند.

```crystal
"foo"[10]? # => nil
```

کریستال چیزی دارد که به آن **بررسی ارجاع تهی** می‌گویند؛ یعنی همه‌ی نوع‌ها به‌طور پیش‌فرض نمی‌توانند `nil` باشند.
این یعنی نمی‌توانید به یک متغیر مقدار `nil` نسبت دهید، مگر اینکه صراحتاً آن را از نوع `Nil` اعلام کنید.
به همین ترتیب، کامپایلر به‌طور خودکار ارجاع‌های تهی را بررسی می‌کند.

## مقدار کاذب

برای برخورد با مقادیر `nil` می‌توان روش‌های خاصی به کار برد.
`nil` یک [«مقدار کاذب»][truthy-falsey] است و `false` هم همین‌طور.
این یعنی در دستورها و هر جای دیگری که یک مقدار کاذب یا صادق انتظار می‌رود، با آن مثل `false` رفتار می‌شود.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

این یعنی اگر متغیری که می‌تواند `nil` باشد مقدار `nil` داشته باشد، شاخه‌ی صادق اجرا نمی‌شود.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## بررسی `nil`

کریستال متدی دارد که می‌توان با آن بررسی کرد آیا یک مقدار `nil` است یا نه.
اسم آن [`nil?`][nil?] است و روی همه‌ی اشیاء در دسترس قرار دارد.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

این تا حدی با حالتی فرق دارد که فقط مقدار را در یک دستور شرطی به کار می‌بریم؛ چون در مثال‌های قبلی هم `false` و هم `nil` کاذب در نظر گرفته می‌شدند.
اینجا فقط `nil` کاذب به حساب می‌آید؛ چون اگر مقدار `false` بود، دیگر `nil` نبود و در نتیجه صادق می‌بود.

## عملگر or

ساده‌ترین راه برخورد با مقادیر `nil` این است که از همان ابتدا مطمئن شوید هیچ‌وقت `nil` نمی‌شوند.
عملگر or ([`||`][or]) غالباً هنگام کار با `Bools` به کار می‌رود، اما اگر درست فهمیده شود، می‌توان از آن برای مقادیر `nil` هم استفاده کرد.
عملگر or بررسی می‌کند که آیا مقدار اول صادق است یا نه؛ اگر نباشد، از مقدار دوم استفاده می‌شود.
با این کار می‌توان کاری کرد که اگر مقدار `nil` بود، کاذب به حساب بیاید و در نتیجه از مقدار دوم استفاده شود.

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
این روش را باید آخرین راه‌حل دانست و فقط زمانی باید به کار رود که **مطمئن** هستید مقدار `nil` نیست.
در صورت امکان، به‌جای آن از روش‌های دیگر استفاده کنید.
~~~~

[`not_nil!`][not_nil] متدی است که به شما امکان می‌دهد به کامپایلر بگویید یک مقدار `nil` نیست و در نتیجه نوعی که آن مقدار دارد نمی‌تواند `nil` باشد.
این کار را با پرتاب یک استثنا انجام می‌دهد، اگر مقدار `nil` باشد.

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
