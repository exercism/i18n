# مقدمه

استثناها در Ruby، مانند بسیاری از زبان‌ها، راهی برای برخورد با رویدادهای غیرمنتظره فراهم می‌کنند. مدیریت درست استثناها زمانی مهم است که بخواهید جلوی از کار افتادن برنامه‌تان را بگیرید.

وقتی استثنایی ایجاد می‌شود، چه با ایجاد صریح آن و چه با ایجاد آن توسط مفسر Ruby، برنامه از روند عادی خود خارج می‌شود و در نهایت با یک پیام خطا پایان می‌یابد:

```ruby
raise ArgumentError.new("Something went wrong!")
=> Traceback (most recent call last):
.
.
ArgumentError (Something went wrong!)
```

```ruby
1/0
=> Traceback (most recent call last):
.
.
ZeroDivisionError (divided by 0)
```

اگر بخواهیم جلوی این فرایند خاتمه را بگیریم، باید به استثنا واکنش نشان دهیم. به این کار `rescue` کردن استثنا می‌گویند:

```ruby
begin
  # ...any code that raises an exception
rescue
  puts 'Got an exception'
end
```

این برنامه از کار نمی‌افتد و «Got an exception» را نمایش می‌دهد. Ruby به جای خروج، کد داخل بلوک `rescue` را اجرا می‌کند که پیامی را چاپ می‌کند.

مانند هر چیز دیگری در Ruby، استثناها هم شیء هستند و معمولاً داده‌هایی درباره‌ی خود استثنا نگه می‌دارند. این‌گونه می‌توانیم شیء استثنا را به دست آوریم:

```ruby
begin
  # ...any code that raises an exception
rescue => e
  puts "Exception class: #{ e.class.name }"
  puts "Exception Message:#{e.message}"
end
```

در Ruby همچنین می‌توانید استثناهای خودتان را ایجاد کنید. برای مثال:

```ruby
begin
  raise ArgumentError.new("Invalid argument")
rescue ArgumentError => e
  puts e.message
end
```

استثنای قبلی یکی از استثناهای داخلی Ruby است، اما می‌توان استثناهای سفارشی هم تعریف کرد و آن‌ها را ایجاد کرد:

```ruby
class CustomError < StandardError
end

raise CustomError.new("Something went wrong")
```
