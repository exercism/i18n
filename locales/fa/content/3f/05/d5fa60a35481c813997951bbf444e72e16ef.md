# مقدمه

Go هم مثل بسیاری از زبان‌های دیگر اشاره‌گر دارد.
اگر تازه با اشاره‌گرها آشنا می‌شوید، ممکن است کمی رمزآلود به نظر برسند، اما وقتی به آن‌ها عادت کنید، کاملاً سرراست می‌شوند.
اشاره‌گرها بخش مهمی از Go هستند، پس وقت بگذارید و آن‌ها را واقعاً درک کنید.

پیش از پرداختن به جزئیات، بهتر است کاربرد اشاره‌گرها را بفهمید.
اشاره‌گرها راهی برای به اشتراک گذاشتن حافظه با بخش‌های دیگر برنامه‌ی ما هستند که به دو دلیل عمده مفید است:

1. وقتی حجم زیادی داده داریم، ساختن نسخه‌های کپی برای فرستادن بین توابع بسیار ناکارآمد است.
   اگر به‌جای آن، آدرس حافظه‌ی محل ذخیره‌ی داده را بفرستیم، می‌توانیم ردپای منابع برنامه‌هایمان را به‌شکل چشمگیری کاهش دهیم.
2. با فرستادن اشاره‌گرها بین توابع، می‌توانیم مستقیماً به تنها نسخه‌ی داده دسترسی داشته باشیم و آن را تغییر دهیم؛ یعنی هر تغییری که یک تابع ایجاد می‌کند، وقتی تابع تمام می‌شود، بلافاصله برای بخش‌های دیگر برنامه قابل مشاهده است.

## متغیرها و حافظه

فرض کنید یک متغیر معمولی از نوع عدد صحیح به اسم `a` داریم:

```go
var a int
```

وقتی متغیری اعلام می‌کنیم، Go باید جایی در حافظه پیدا کند تا مقدار آن را ذخیره کند.
این فرایند تا حد زیادی از ما پنهان است: وقتی بخواهیم مقدار ذخیره‌شده در آن تکه از حافظه را بخوانیم، کافی است به نام متغیر اشاره کنیم.

برای نمونه، وقتی `a + 2` را می‌نویسیم، در واقع مقدار ذخیره‌شده در حافظه‌ای که به متغیر `a` مربوط است را می‌خوانیم و ۲ به آن اضافه می‌کنیم.

به همین ترتیب، وقتی بخواهیم مقدار آن تکه از حافظه‌ی `a` را تغییر دهیم، می‌توانیم با استفاده از نام متغیر یک انتساب انجام دهیم:

```go
a = 3
```

آن تکه از حافظه که به `a` مربوط است، اکنون مقدار `3` را ذخیره می‌کند.

## اشاره‌گرها

متغیرها به ما اجازه می‌دهند به مقادیر موجود در حافظه اشاره کنیم، اما گاهی دانستن **آدرس حافظه**ای که متغیر به آن اشاره می‌کند مفید است.
**اشاره‌گرها** آدرس حافظه‌ی آن مقادیر را نگه می‌دارند.
برای اعلام متغیری با نوع اشاره‌گر، یک ستاره پیش از نوع پایه می‌گذارید:

```go
var p *int // 'p' contains the memory address of an integer
```

اینجا متغیری به اسم `p` از نوع «اشاره‌گر به int» (`*int`) اعلام می‌کنیم.
یعنی `p` آدرس حافظه‌ی یک عدد صحیح را نگه می‌دارد.
مقدار صفر اشاره‌گرها `nil` است، چون اشاره‌گر `nil` هیچ آدرس حافظه‌ای را نگه نمی‌دارد.

### گرفتن اشاره‌گر به یک متغیر

برای یافتن آدرس حافظه‌ی مقدار یک متغیر، می‌توانیم از عملگر `&` استفاده کنیم.
برای نمونه، اگر بخواهیم آدرس حافظه‌ی متغیر `a` را پیدا کنیم و در اشاره‌گر `p` ذخیره کنیم، می‌توانیم این کار را انجام دهیم:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### دسترسی به مقدار از طریق اشاره‌گر (ارجاع‌زدایی)

وقتی اشاره‌گری داریم، ممکن است بخواهیم بدانیم چه مقداری در آدرس حافظه‌ای که اشاره‌گر نشان می‌دهد ذخیره شده است.
برای این کار می‌توانیم از عملگر `*` استفاده کنیم:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

عمل `*p` مقداری را می‌خواند که در آدرس حافظه‌ی ذخیره‌شده در `p` قرار دارد.
به این عمل اغلب «ارجاع‌زدایی» می‌گویند.

همچنین می‌توانیم از عملگر ارجاع‌زدایی استفاده کنیم تا مقدار تازه‌ای به آدرس حافظه‌ای که اشاره‌گر به آن اشاره دارد اختصاص دهیم:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

انتساب به `*pa` مقداری را که در آدرس حافظه‌ی نگه‌داشته‌شده توسط `pa` ذخیره شده تغییر می‌دهد.
چون `pa` آدرس حافظه‌ی `a` را نگه می‌دارد، با انتساب به `*pa` در واقع مقدار `a` را تغییر می‌دهیم!

اما یک هشدار: پیش از ارجاع‌زدایی، همیشه بررسی کنید که اشاره‌گر `nil` نباشد.
ارجاع‌زدایی از یک اشاره‌گر `nil` باعث می‌شود برنامه در زمان اجرا از کار بیفتد!

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### اشاره‌گرها به ساختارها

تا اینجا فقط اشاره‌گرهایی به مقادیر ابتدایی دیده‌ایم.
می‌توانیم برای ساختارها هم اشاره‌گر بسازیم:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

همچنین می‌توانستیم یک `Person` تازه بسازیم و بلافاصله اشاره‌گری به آن ذخیره کنیم:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

وقتی اشاره‌گری به یک ساختار داریم، برای دسترسی به یکی از فیلدها لازم نیست اشاره‌گر را ارجاع‌زدایی کنیم:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## اسلایس‌ها و مپ‌ها خودشان اشاره‌گر هستند

اسلایس‌ها و مپ‌ها نوع‌های ویژه‌ای هستند، چون در پیاده‌سازی خود از قبل اشاره‌گر دارند.
یعنی در بیشتر مواقع لازم نیست برای این نوع‌ها اشاره‌گر بسازیم تا آدرس حافظه‌ی مقادیرشان را به اشتراک بگذاریم.
تصور کنید تابعی داریم که مقدار یک کلید در یک مپ را افزایش می‌دهد:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

اگر یک مپ بسازیم و این تابع را فراخوانی کنیم، تغییراتی که تابع در مپ ایجاد کرده، پس از پایان تابع هم باقی می‌ماند.
این رفتار شبیه چیزی است که با استفاده از اشاره‌گر به دست می‌آوریم، اما توجه کنید که در این مثال هیچ ارجاع‌دهی یا ارجاع‌زدایی‌ای و از نحوه‌ی نگارش اشاره‌گر هم استفاده نکرده‌ایم:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

همین موضوع درباره‌ی تغییر یک عنصر موجود در یک اسلایس هم صادق است.

اما کارهایی که یک اسلایس تازه برمی‌گردانند، مثل `append`، حالت ویژه‌ای دارند و **ممکن است** اسلایس بیرون از تابع را تغییر ندهند.
این موضوع به شیوه‌ی کار داخلی اسلایس‌ها مربوط است، اما به‌تفصیل به آن نمی‌پردازیم، چون موضوعی پیشرفته‌تر است.
اگر واقعاً کنجکاو هستید، می‌توانید بیشتر درباره‌ی این موضوع در [بلاگ Go: سازوکار «append»][mechanics-of-append] بخوانید.
