# مقدمه

## اعمال جزئی

همه‌ی توابع در Elm [کری‌شده][currying] هستند؛ یعنی اگر تابعی را بدون فرستادن همه‌ی آرگومان‌هایش فراخوانی کنید، تابعی تازه برمی‌گرداند.

به نتیجه‌ی این کار [اعمال جزئی][partial-application] می‌گویند (شما همه‌ی آرگومان‌ها را به تابع نمی‌فرستید، بلکه فقط بخشی از آن‌ها را اعمال می‌کنید).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

اعمال جزئی همیشه آرگومان‌ها را به ترتیب اعمال می‌کند.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## عملگر لوله (`|>`)

نوشتن `x |> f` دقیقاً معادل `f x` است. یک مثال عینی این است که `"5" |> String.toInt` همان `String.toInt "5"` است.

این در نگاه اول چندان کاربردی به نظر نمی‌رسد، اما به آن [عملگر لوله][pipe-operator] می‌گویند، چون به شما امکان می‌دهد کدی به سبک خط لوله بنویسید.

برای نمونه، فرض کنید یک تابع پاک‌سازی داریم که ورودی کاربر را به عدد صحیح تبدیل می‌کند:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

می‌توانیم آن را به این شکل بازنویسی کنیم:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

این شکل، استفاده از پرانتز را کنار می‌گذارد و توابع را به همان ترتیبی نشان می‌دهد که اعمال می‌شوند (اول `String.trim`، بعد `String.toInt`) که به خوانایی کمک می‌کند.

[عملگر لوله‌ی معکوس `(<|)`][reverse-pipe-operator] هم وجود دارد.
نوشتن `f <| x` دقیقاً معادل `f x` است.
این هم در نگاه اول چندان کاربردی به نظر نمی‌رسد و قطعاً به اندازه‌ی عملگر لوله استفاده نمی‌شود، اما در برخی موقعیت‌ها به پرهیز از پرانتز کمک می‌کند.

## ترکیب توابع / سبک بدون نقطه

عملگر [`(>>)`][forward-composition] از نوع `(a -> b) -> (b -> c) -> (a -> c)` است و با ترکیب دو تابع سازگار از نوع `a -> b ` و `b -> c`، تابعی از نوع `a -> c` می‌سازد.
این کار را با گرفتن خروجی تابع اول (از نوع `b`) و استفاده از آن به‌عنوان آرگومان اول تابع دوم انجام می‌دهد (که باید از همان نوع `b` باشد).
تابع ساخته‌شده همان ورودی تابع اول (از نوع `a`) را می‌گیرد و هر `c`ی را که تابع دوم برمی‌گرداند برمی‌گرداند.

یک مثال عینی `String.trim >> String.toInt` است.
`String.trim` یک رشته را به‌عنوان تنها پارامترش می‌گیرد، پس تابع ساخته‌شده هم همین را می‌گیرد.
`String.toInt` یک `Maybe Int` برمی‌گرداند، پس تابع ساخته‌شده همین را برمی‌گرداند.
`String.trim` یک `String` برمی‌گرداند که `String.toInt` آن را به‌عنوان پارامتر می‌پذیرد، پس مثال کامپایل می‌شود.

اکنون می‌توانیم تابع `sanitize` را به این شکل بازنویسی کنیم:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

توجه کنید که دیگر از پارامتر `input` که در مثال اصلی می‌بینید استفاده نمی‌کنیم، هرچند کارکرد دقیقاً یکسان است.
به این شیوه‌ی ساختن توابع که هیچ اشاره‌ای به پارامترهایشان نمی‌کنند، «سبک بدون نقطه» می‌گویند.
مزیت این سبک این است که کد خلاصه‌تر می‌شود و عیبش این است که درک آن می‌تواند دشوارتر باشد، به‌ویژه برای تازه‌کارها.

به خاطر داشته باشید که در Elm همه‌ی توابع کری‌شده هستند، پس `String.length >> max` کامپایل می‌شود.

- عملگر [`(>>)`][forward-composition] از نوع `(a -> b) -> (b -> c) -> (a -> c)` است.
- `String.length` از نوع `String -> Int` است که همان بخش `(a -> b)` است، پس `a` برابر `String` و `b` برابر `Int` است.
- `max` از نوع `Int -> Int -> Int` است که همان بخش `b -> c` است.
- `b` برابر `Int` است، پس `max` به‌صورت جزئی اعمال می‌شود و `c` نتیجه‌ی این اعمال جزئی (`Int -> Int`) است.
- پس نوع `String.length >> max` برابر `String -> (Int -> Int)` است.
- پس `((String.length >> max) "123") 2` مقدار `3` را برمی‌گرداند، چون طول `"123"` برابر ۳ است که از ۲ (آرگومان `Int`) بزرگ‌تر است.

## طراحی تابع

برای اینکه نوشتن کد زیبا در Elm آسان باشد، بهتر است ساختار داده‌ی اصلی را آخرین پارامتر توابع قرار دهید.
همه‌ی توابع پرکاربرد کتابخانه‌ی استاندارد همین کار را می‌کنند، مثل `List.map` (امضای نوع آن در ادامه آمده است).

```elm
map : (a -> b) -> List a -> List b
```

در اینجا می‌بینیم که آخرین پارامتر تابع `map` برابر `List a` است و `List b` برمی‌گرداند، پس ساختار داده‌ی اصلی (`List`) آخرین پارامتر است.

این کار نوشتن کدی زیبا به سبک خط لوله را ممکن می‌کند، مثل نمونه‌ی زیر.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

همچنین استفاده از ترکیب توابع و سبک بدون نقطه را به‌عنوان جایگزینی برای خط لوله راحت می‌کند.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

ترکیب توابع همچنین به شما امکان می‌دهد این مثال را به یک فراخوانی واحد `List.map` کاهش دهید.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
