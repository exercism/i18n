# درباره

تجزیه فرایندی است که طی آن متن به داده‌ی معنادار تبدیل می‌شود.
توابع بسته‌ی `String` در این زمینه محدودکننده‌اند و استفاده از عبارات باقاعده دشوار است، بنابراین روش اصطلاحی در Elm برای تجزیه، استفاده از بسته‌ی `elm/parser` است.

بیایید نمونه‌ای از نوشتن یک تجزیه‌کننده برای (زیرمجموعه‌ای از) زبان برنامه‌نویسی [LOLCODE][lolcode] را با هم مرور کنیم.
بیایید برنامه‌ی کامنت‌گذاری‌شده‌ی زیر را در نظر بگیریم:

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

ابتدا بیایید یک نوع در Elm بنویسیم که دستورهای ممکن را نمایش دهد:

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

سپس می‌توان برنامه‌ی LOLCODE خود را به شکل یک `List Command` مدل‌سازی کرد.
بیایید با یک تجزیه‌کننده برای خط `HAI 1` شروع کنیم:

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

`versionP` با استفاده از یک _خط لوله‌ی تجزیه‌کننده_ ساخته می‌شود.
عملگر `(|.)` یعنی «رشته را تجزیه کن اما نتیجه را دور بریز» و `(|=)` یعنی «رشته را تجزیه کن و نتیجه را نگه دار».
در این مثال، `Parser.keyword "HAI"` یک «HAI» را مصرف می‌کند، اما آن نتیجه نادیده گرفته می‌شود.
`Parser.spaces` هر تعداد از کاراکترهای ' '، '\n' و '\r' را مصرف می‌کند، اما آن هم نادیده گرفته می‌شود.
`Parser.int` یک عدد صحیح را تجزیه می‌کند و مقدار آن عدد صحیح (مثلاً ۱) به بالاترین `Parser.succeed Version` پاس داده می‌شود و تجزیه‌کننده با موفقیت مقدار `Version 1` را برمی‌گرداند.

اگر هر یک از تجزیه‌کننده‌های خط لوله شکست بخورد، یک `Parser.DeadEnd` برمی‌گرداند و کل تجزیه‌کننده شکست می‌خورد.
یک تجزیه‌کننده را می‌توان با `Parser.run` اجرا کرد:

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

بیایید خط «CAN HAS STDIO?» را این‌طور بررسی کنیم:

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP` هم یک خط لوله‌ی تجزیه‌کننده است، اما این بار با `Parser.symbol` تمام می‌شود که برای تجزیه‌ی نمادهایی مانند «?» مناسب است.
مقداری که می‌خواهیم نگه داریم (اسم بسته‌ای که باید وارد شود) با کد زیر تجزیه می‌شود:

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

از آنجا که نمی‌دانیم اسم بسته چه خواهد بود، نمی‌توانیم از `Parser.keyword` استفاده کنیم، بنابراین به‌جای آن از `Parser.chompWhile` استفاده می‌کنیم که کاراکترها را تا زمانی که یک شرط را برآورده کنند (اینجا، الفبایی‌عددی بودن) یکی‌یکی مصرف می‌کند.
سپس این کاراکترهای مصرف‌شده توسط `Parser.getChompedString` جمع‌آوری می‌شوند که یک `Parser String` برمی‌گرداند.
در این حالت، می‌خواهیم اسم‌های بسته را یکدست کنیم، بنابراین از `Parser.map` استفاده می‌کنیم تا رشته‌ی موجود در تجزیه‌کننده را تغییر دهیم و آن را به حروف کوچک تبدیل کنیم.

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

در ادامه، `VISIBLE "HAI WORLD!"` با این کد تجزیه می‌شود:

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

حالا برای هر دستور یک تجزیه‌کننده داریم.
البته در یک برنامه‌ی کلی، ترتیب این دستورها قابل پیش‌بینی نیست، بنابراین یک تجزیه‌کننده‌ی دستور عمومی می‌سازیم:

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

`Parser.oneOf` تجزیه‌کننده‌ها را به ترتیبی که داده شده یکی‌یکی امتحان می‌کند.
اگر یک تجزیه‌کننده شکست بخورد، تجزیه‌کننده‌ی بعدی امتحان می‌شود، اما اگر موفق شود، نتیجه‌اش بدون امتحان کردن بقیه‌ی تجزیه‌کننده‌ها برگردانده می‌شود.
اگر همه‌ی تجزیه‌کننده‌ها شکست بخورند، `Parser.oneOf` شکست می‌خورد.

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

دقت کنید که هر تلاش ناموفق یک `Parser.DeadEnd` تولید می‌کند که توسط `Parser.oneOf` جمع‌آوری می‌شود.

برای تجزیه‌ی یک برنامه‌ی کامل، باید چندین دستور را پشت سر هم با این کد تجزیه کنیم:

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence` یک تجزیه‌کننده‌ی بسیار قابل سفارشی‌سازی است که گزینه‌های متعددی دارد.
`start`، `separator` و `end` رشته‌هایی می‌گیرند که عنصرهای دنباله را از هم جدا می‌کنند. برای تجزیه‌ی یک لیست در Elm از "[", "," و "]" استفاده می‌کنیم.
`spaces` با گرفتن یک تجزیه‌کننده انعطاف‌پذیری فراهم می‌کند؛ این تجزیه‌کننده فاصله‌های احتمالی بین عنصرها و جداکننده‌ها را مدیریت می‌کند. برای تجزیه‌ی یک لیست در Elm از `Parser.spaces` استفاده می‌کنیم، اما در این حالت هیچ فاصله‌ای نمی‌پذیریم، بنابراین از `Parser.succeed ()` استفاده می‌کنیم که بی‌درنگ موفق می‌شود و در واقع چیزی مصرف نمی‌کند.
`item` تجزیه‌کننده‌ی عنصر را می‌گیرد و در نهایت `trailing` به ما امکان می‌دهد تعیین کنیم که جداکننده‌های انتهایی `Parser.Forbidden`، `Parser.Mandatory` یا `Parser.Optional` باشند.

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

وقتی تجزیه‌کننده‌ها موفق می‌شوند، مصرف رشته را متوقف می‌کنند:

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

بنابراین اگر لازم است مطمئن شویم که همه‌ی رشته را تجزیه کرده‌ایم، می‌توانیم از `Parser.end` استفاده کنیم:

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

در نهایت، گاهی لازم است بسته به محتوای تجزیه‌شده‌ی یک تجزیه‌کننده تصمیم بگیریم که آن را شکست دهیم.
برای مثال، اگر به تجزیه‌کننده‌ای نیاز داشتیم که برنامه‌هایی را که با دو دستور «HAI» پشت سر هم شروع می‌شوند شکست دهد، می‌توانستیم از این کد استفاده کنیم:

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

`Parser.andThen` می‌تواند محتوای یک تجزیه‌کننده را بررسی کند و بسته به مقدارش یک تجزیه‌کننده‌ی جدید برمی‌گرداند.
در اینجا در یک حالت، تجزیه‌کننده را با یک پیام سفارشی و با استفاده از `Parser.problem` شکست دادیم و در حالت دیگر مقدار اصلی را برگرداندیم.

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
