# درباره

## کاراکتر

یک [کدگذاری کاراکتر][char-encoding] قراردادی مشخص است که برای نمایش عناصر متن در یک زبان طبیعی به‌صورت دنباله‌ای از بایت‌ها به کار می‌رود.
منظور از «عنصر متن» در اینجا می‌تواند هر واحدی باشد که در یک زبان طبیعی معنادار است؛ مثلاً حروف، فاصله‌ها، نشانه‌های نگارشی، اموجی‌ها، ایدئوگرام‌ها و غیره.

NASM (همان Netwide Assembler، اسمبلری که این مسیر از آن استفاده می‌کند) از تعریف داده‌ها با [ASCII][ascii] پشتیبانی می‌کند.

ثابت‌های کاراکتری در NASM می‌توانند تا ۸ بایت طول داشته باشند و می‌توان آن‌ها را با کوتیشن تکی (`'`)، کوتیشن دوگانه (`"`) یا بک‌تیک (`` ` ``) تعریف کرد:

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

کاراکترهای خاص باید با بک‌تیک تعریف شوند و با `\` اسکیپ شوند:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

NASM همچنین از [کاراکترهای یونیکد][unicode] در [UTF-8][utf8] پشتیبانی می‌کند که با `\u` یا `\U` و داخل بک‌تیک مشخص می‌شوند:

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

توجه کنید که در x86-64 هیچ پشتیبانی درونی برای هیچ کدگذاری کاراکتری به‌عنوان یک نوع داده‌ی مجزا وجود ندارد.
داده در اسمبلی دنباله‌ای از بایت‌هاست و تفسیر این بایت‌ها به‌عنوان کاراکتر، عدد یا هر چیز دیگر، به عهده‌ی برنامه‌نویس است.

برای نمونه، کاراکتر ASCII '0' یک بایت تک با مقدار ۴۸ است.
بنابراین، ذخیره کردن ۴۸ در یک بایت دقیقاً همان ذخیره کردن کاراکتر ASCII '0' است:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

به همین دلیل، کار کردن با کاراکترها با تغییر مستقیم مقدارهای داخل همان بایت‌ها انجام می‌شود:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## رشته

یک [رشته][string] دنباله‌ای از کاراکترهاست.
در اسمبلی، معمولاً به‌صورت یک آرایه پیاده‌سازی می‌شود.

می‌توان یک رشته را در NASM دقیقاً مانند هر آرایه‌ی دیگری تعریف کرد:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

یک تفاوت رشته‌ها با سایر آرایه‌ها این است که NASM از تعریف رشته‌ها بدون جدا کردن مقدارها با کاما (`,`) هم پشتیبانی می‌کند.
همچنین می‌توان مقدارها را به‌صورت ترکیبی و با کاما هم نوشت:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

توجه کنید که، همان‌طور که پیش‌تر گفتیم، کاراکترها فقط بایت هستند (یا در کدگذاری یونیکد، دنباله‌ای از بایت‌ها):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

چون هر کاراکتر ASCII یک بایت را اشغال می‌کند، هر بایت بعدی در یک اندازه‌ی بزرگ‌تر `0` است.
برای مثال، تعریف `'a'` به‌صورت یک کلمه‌ی چهارگانه (۸ بایت) یعنی بایت اول `'a'` (`97`) است و هفت بایت دیگر همه `0` هستند.

به همین دلیل، همه‌ی این‌ها معادل‌اند:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
در اسمبلی، رشته‌ها به‌طور خودکار با کاراکتر NUL در ASCII (مقدار `0`) پایان نمی‌یابند.

هنگام تعامل با زبان‌های سطح بالاتر، مانند C، مسئولیت برنامه‌نویس است که مطمئن شود پایان‌دهنده‌ی درست، در صورت وجود، به انتهای رشته افزوده شده است.
~~~~

## دستورهای رشته

چون رشته‌ها آرایه هستند، می‌توانید دقیقاً مانند هر آرایه‌ی دیگری با آن‌ها کار کنید، یعنی با ارجاع صریح به حافظه:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

علاوه بر این، دستورهایی برای بارگذاری، جابه‌جایی و ذخیره‌ی مقدارها در دنباله‌های بایت در حافظه وجود دارد.
هرچند به آن‌ها _دستورهای رشته_ می‌گویند، می‌توان از آن‌ها با هر دنباله‌ای از بایت در حافظه، یعنی با هر آرایه‌ای، استفاده کرد:

| دستور  | کاری که انجام می‌دهد                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | مقداری را از یک مکان حافظه که با `rsi` مشخص شده است بارگذاری می‌کند و در `rax` قرار می‌دهد                                                |
| [stos][stos] | مقداری را از `rax` در یک مکان حافظه که با `rdi` مشخص شده است ذخیره می‌کند                                               |
| [movs][movs] | مقداری را از یک مکان حافظه که با `rsi` مشخص شده است رونوشت می‌کند و آن را در یک مکان حافظه که با `rdi` مشخص شده است ذخیره می‌کند    |
| [cmps][cmps] | مقدار موجود در یک مکان حافظه را که با `rsi` مشخص شده است با مقدار موجود در یک مکان حافظه که با `rdi` مشخص شده است مقایسه می‌کند |
| [scas][scas] | مقدار `rax` را با مقداری که از یک مکان حافظه که با `rdi` مشخص شده است می‌خواند مقایسه می‌کند                                |

توجه کنید که این دستورها هیچ عملوند صریحی _نمی‌گیرند_.
عملوندهایشان ضمنی هستند.

به‌عنوان یک قاعده‌ی سرانگشتی:

۱. وقتی عملوند مبدأشان یک مکان حافظه است، آدرس آن باید در `rsi` ذخیره شود (`s` به معنی source).
۲. وقتی عملوند مقصدشان یک مکان حافظه است، آدرس آن باید به‌جای آن در `rdi` ذخیره شود (`d` به معنی destination).
۳. اگر یکی از عملوندها مکان حافظه نباشد، آن عملوند ثبات `rax` است.

توجه کنید که این دستورها بر اساس عملیاتی که انجام می‌دهند، به‌طور خودکار به آدرس‌های حافظه ارجاع می‌دهند.

همه‌ی آن‌ها می‌توانند در اندازه‌های مختلف عمل کنند.
برای نشان دادن این اندازه، یک پسوند به آن‌ها افزوده می‌شود:

| پسوند | معنا | اندازه    |
| :----: | ------- | :------ |
|  `b`   | بایت    | ۱ بایت  |
|  `w`   | کلمه    | ۲ بایت |
|  `d`   | کلمه‌ی دوگانه   | ۴ بایت |
|  `q`   | کلمه‌ی چهارگانه   | ۸ بایت |

برای مثال:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

این دستورها همچنین هر آدرس به‌کاررفته را به اندازه‌ی عملیات به‌روزرسانی می‌کنند.
این به‌روزرسانی بر اساس مقدار **پرچم جهت (DF)** انجام می‌شود:

- اگر `DF` پاک باشد، آدرس‌ها به اندازه‌ی عملیات _افزایش_ می‌یابند.
- اگر `DF` تنظیم شده باشد، آدرس‌ها به همان مقدار _کاهش_ می‌یابند.

استاندارد System V ABI می‌گوید که پرچم جهت باید در هنگام ورود به تابع پاک باشد.
بنابراین، _رفتار پیش‌فرض این است که حافظه به ترتیب صعودی آدرس‌ها خوانده/نوشته شود_.

از دستور [cld][cld] می‌توان برای پاک کردن پرچم جهت استفاده کرد، و از دستور [std][std] برای تنظیم آن:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
فراخوان انتظار دارد که `DF` پس از بازگشت هر تابع فراخوانی‌شده، طبق System V ABI، پاک باشد.
اگر `DF` را تنظیم کردید، حتماً پیش از `ret` آن را پاک کنید.
~~~~

### Lods

این دستور از مکانی از حافظه که آدرسش در `rsi` است _می‌خواند_ و مقدار را در `rax` رونوشت می‌کند.

مقدار `rsi` به اندازه‌ی تعداد بایت‌های خوانده‌شده به‌روزرسانی می‌شود:

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

این دستور مقدار `rax` را رونوشت می‌کند و آن را در مکانی از حافظه که آدرسش در `rdi` است _می‌نویسد_.

مقدار `rdi` به اندازه‌ی تعداد بایت‌های نوشته‌شده به‌روزرسانی می‌شود:

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

این دستور از مکانی از حافظه که آدرسش در `rsi` است _می‌خواند_ و مقدار را در مکانی از حافظه که آدرسش در `rdi` است _می‌نویسد_.
مقدار `rax` تحت تأثیر این دستور قرار نمی‌گیرد.

هم `rsi` و هم `rdi` به اندازه‌ی تعداد بایت‌های رونوشت‌شده از یک مکان حافظه به مکان دیگر به‌روزرسانی می‌شوند:

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

این دستور از مکانی از حافظه که آدرسش در `rsi` است _می‌خواند_ و همچنین از مکانی از حافظه که آدرسش در `rdi` است _می‌خواند_.
سپس مقدارها را مقایسه می‌کند و پرچم‌ها را طبق `cmp` به‌روزرسانی می‌کند.

هم `rsi` و هم `rdi` به اندازه‌ی تعداد بایت‌های خوانده‌شده از هر دو مکان به‌روزرسانی می‌شوند:

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

این دستور مقدار `rax` را با مقداری که از مکانی از حافظه که آدرسش در `rdi` است _می‌خواند_ مقایسه می‌کند.
سپس پرچم‌ها را طبق `cmp` به‌روزرسانی می‌کند.

مقدار `rdi` به اندازه‌ی تعداد بایت‌های خوانده‌شده به‌روزرسانی می‌شود:

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

علاوه بر این‌ها، دستور [rep][rep] به‌طور مستقیم با حافظه تعامل نمی‌کند.
در عوض، می‌توان آن را به‌عنوان پیشوند به سایر دستورهای یادشده افزود و آن دستورها را _تکرار_ کرد.

وقتی پیشوند `rep` به کار می‌رود، دستورهای رشته به تعداد برابر با مقدار `rcx` تکرار می‌شوند.
هر بار، مقدار `rcx` به اندازه‌ی `1` کاهش می‌یابد.
توجه کنید که مقدار `rcx` باید پیش از استفاده از دستور تنظیم شود:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

علاوه بر استفاده از `rcx` به‌عنوان شمارنده، `repe` (یا `repz`) و `repne` (یا `repnz`) اگر `zero flag (ZF)` به‌ترتیب پاک یا تنظیم باشد، اجرا را متوقف می‌کنند:

| دستور      | کجا می‌تواند اضافه شود     | ممکن است زودتر متوقف شود        |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`, `lods`, `stos` | خیر                      |
| `repe`,`repz`    | `cmps`, `scas`         | بله، وقتی ZF برابر ۰ است متوقف می‌شود |
| `repne`, `repnz` | `cmps`, `scas`         | بله، وقتی ZF برابر ۱ است متوقف می‌شود |

~~~~exercism/advanced
روی پردازنده‌های مدرن، `rep movs` و `rep stos` معمولاً گزینه‌های سریعی برای جابه‌جایی داده در بلوک‌های بزرگ هستند.
اما سایر دستورهای رشته، و حتی `movs` و `stos` وقتی بدون `rep` اجرا می‌شوند، معمولاً از یک حلقه‌ی ساده کندتر هستند.
