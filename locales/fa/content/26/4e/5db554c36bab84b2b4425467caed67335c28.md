# درباره

[«بستارها»][closures] در Swift بلوک‌های کدی خودبسنده هستند که می‌توان پارامترهایی به آن‌ها داد تا محاسبه‌ی خود را انجام دهند و مقداری برگردانند
بستارها همچنین مقادیری را از محیط خود می‌گیرند و در محاسباتشان به کار می‌برند.
از آنجا که خودبسنده هستند، می‌توان آن‌ها را مانند سایر مقادیر در برنامه دست‌به‌دست کرد یا به ثابت‌ها و متغیرها اختصاص داد.

بستارها شاید خیلی شبیه توابع Swift به نظر برسند؛ بله، شبیه‌اند، و دلیل خوبی هم برایش وجود دارد.
توابع در Swift حالت خاصی از بستارها هستند که باید اسمی داشته باشند و با نحوه‌ی نگارش کمی متفاوت تعریف می‌شوند.

با اینکه توابع در Swift از نظر فنی بستار محسوب می‌شوند، وقتی مردم در Swift از «بستارها» حرف می‌زنند، منظورشان [عبارت‌های بستار][closure-expressions] است.
عبارت بستار به این شکل نوشته می‌شود: فهرست پارامترها، سپس نوع بازگشتی، سپس کلیدواژه‌ی `in` و پس از آن بدنه‌ی بستار، که همه در یک جفت آکولاد قرار می‌گیرند:

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}
```

این یک عبارت بستار از نوع `(Double, Double) -> Double` تعریف می‌کند و می‌توان آن را مشابه تابعی از این نوع، با اعمال آن به پارامترهایی از نوع مناسب، اجرا کرد:

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}(10.0, 15.0)
// returns 12.5
```

از آنجا که نوشتن کامل عبارت بستار هر بار که بخواهید آن را اجرا کنید چندان راحت نیست، می‌توان بستارها را مانند هر مقدار دیگری در Swift به یک اسم اختصاص داد.
سپس می‌توان با اعمال آن اسم به پارامترها، آن‌ها را فراخوانی کرد:

```swift
let mean = { (a: Double, b: Double) -> Double in
  (a + b) / 2.0
}

mean(13.0, 100.0)
// returns 56.5
```

همان‌طور که در بالا دیدید، بستارها هم مانند توابع معمولی می‌توانند در صورتی که بدنه‌شان یک عبارت واحد باشد، کلیدواژه‌ی `return` را حذف کنند.

بیشتر اوقات، بستارها همراه با توابع مرتبه‌ی بالاتر به کار می‌روند، یا به عنوان پارامتر به آن‌ها داده می‌شوند یا به عنوان نتیجه برگردانده می‌شوند:

```swift
[11, 75, 3, 99, 53].contains(where: { (x: Int) -> Bool in x > 100 })
// returns false

["apple", "ball", "carrot"].sorted(by: { (s1: String, s2: String) -> Bool in s1.count < s2.count })
// returns ["ball", "apple", "carrot"]

func makeAdder(base: Int) -> (Int) -> Int {
  { (x: Int) -> Int in base + x }
}
```

## استنتاج نوع بستار

وقتی نوع بازگشتی یا نوع پارامترها را بتوان [از بافت استنتاج کرد][inferring-closure-types]، می‌توان آن‌ها را از عبارت بستار حذف کرد.
به‌علاوه، اگر نوع پارامترها را بتوان حذف کرد، پرانتزهای دور اسم پارامترها هم قابل حذف‌اند:

```swift
let mean: (Double, Double) -> Double = { a, b in a + b / 2.0 }

func makeAdder(base: Int) -> (Int) -> Int {
  { x in base + x }
}

["apple", "ball", "carrot"].sorted(by: { s1, s2 in s1.count < s2.count })
```

- در مثال اول، نوع را می‌توان از حاشیه‌نویسی روی ثابت `mean` استنتاج کرد.
- در مثال دوم، کامپایلر از تعریف `makeAdder` می‌داند که `base` یک Int است و تابع بازگردانده‌شده باید از نوع `(Int) -> Int` باشد. از آنجا می‌تواند بررسی کند که اگر `x` یک `Int` باشد، بستار نوع `(Int) -> Int` خواهد داشت و بنابراین می‌توان امضای نوع را در بستار حذف کرد، چون `(Int) -> Int` تنها امضای معتبر ممکن برای این بستار است.
- مثال سوم مشابه است، اما کامپایلر باید بخشی از اطلاعات نوع را از آرایه‌ای بگیرد که متد با آن به کار می‌رود. می‌داند که متد `sorted(by:)` پارامتری از نوع بستار می‌گیرد با دو پارامتر که هم‌نوع عناصر مجموعه‌ی در حال مرتب‌سازی هستند و یک `Bool` برمی‌گرداند، پس کامپایلر می‌تواند استنتاج کند که نوع بازگشتی بستار باید `Bool` باشد. و چون متد با یک آرایه‌ی String به کار می‌رود، می‌تواند تعیین کند که نوع پارامترهای `s1` و `s2` هر دو باید `String` باشد.

## محدودیت‌های بستار

همان‌طور که در بالا اشاره شد، توابع و بستارها در Swift بسیار شبیه هم هستند، اما تفاوت‌های مهمی هم دارند:

- بستارها نمی‌توانند از برچسب‌های آرگومان بیرونی استفاده کنند. راهی برای تعریف آن‌ها وجود ندارد و تلاش برای استفاده از اسم یک پارامتر هنگام فراخوانی بستار به خطا می‌انجامد:

```swift
let add5 = { x in x + 5 }
add5(x: 10)
// Error: Extraneous argument label 'x:' in call
```

- پارامترهای بستار نمی‌توانند مقدار پیش‌فرض داشته باشند.
- پارامترهای بستار می‌توانند پارامترهایی با تعداد متغیر باشند، اما باید اسم و حاشیه‌نویسی نوع داشته باشند.
