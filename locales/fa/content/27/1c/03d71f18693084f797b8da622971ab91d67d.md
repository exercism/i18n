## استفاده از اسکریپت

تولید تست به یک نسخه‌ی محلی از مخزن [problem-specifications][problem-specifications] نیاز دارد.
اسکریپت باید از پوشه‌ی ریشه‌ی `python` اجرا شود تا به‌درستی به تمرین‌ها دسترسی داشته باشد.

برای اطلاع از نحوه‌ی استفاده، `bin/generate_tests.py --help` را اجرا کنید.


## قالب‌های تست

قالب‌های تست از «نحوه‌ی نگارش» [Jinja2] پشتیبانی می‌کنند و متغیرهای زمینه‌ی زیر از داده‌های استاندارد در دسترس آن‌ها قرار دارند:
- `exercise`: اسم خط‌فاصله‌دار تمرین (مثلاً `two-fer`)
- `version`: نسخه‌ی داده‌های استاندارد (مثلاً `1.2.0`)
- `cases`: فهرستی از شیءهای مورد آزمون یا فهرستی از فهرست‌های `cases`. برای ساختار دقیق تمرینی که روی آن کار می‌کنید، لطفاً به `canonical-data.json` مراجعه کنید
- `has_error_case`: نشان می‌دهد که آیا مورد آزمونی وجود دارد که انتظار پرتاب یک خطا را داشته باشد (مثلاً `False`)
- `additional_cases`: ساختاری مشابه `cases` دارد، اما در صورت وجود، از فایل `.meta/additional_tests.json` تمرین پر می‌شود (برای نمونه، `exercises/word-count/.meta/additional_tests.json` را ببینید)

علاوه بر این، فیلترهای قالب زیر برای سهولت کار اضافه شده‌اند:
- `to_snake`: یک رشته را به snake_case تبدیل می‌کند (مثلاً `{{ "CamelCaseString" | to_snake }}` -> `camel_case_string`)
- `camel_case`: یک رشته را به CamelCase تبدیل می‌کند (مثلاً `{{ "snake_case_string" | camel_case }}` -> `SnakeCaseString` )
- `error_case`: بررسی می‌کند که آیا یک مورد آزمون انتظار پرتاب یک خطا دارد (مثلاً `{% for case in cases%}{% if case is error_case}`)
- `regex_replace`: جایگزینی رشته بر پایه‌ی عبارت باقاعده (مثلاً `{{ "abc123" | regex_replace("\\d", "D") }}` -> `abcDDD`)


### قراردادها

- ماکروهای عمومی برای ساختارهای قالبی که بسیار تکرار می‌شوند، در `config/generator_macros.j2` تعریف شده‌اند.
  - این‌ها را می‌توان به شکل زیر وارد کرد:
  `{%- import "generator_macros.j2" as macros with context -%}`
- همه‌ی قالب‌های تست باید با `{{ macros.footer() }}` پایان یابند.
- همه‌ی اسم‌های کلاس پایتون باید به شکل CamelCase باشند (مثلاً `TwoFer`).
  - تبدیل با `{{ "two-fer" | camel_case }}`
- همه‌ی اسم‌های ماژول و تابع پایتون باید به شکل snake_case باشند
(مثلاً `high_scores`، `personal_best`).
  - تبدیل با `{{ "personalBest" | to_snake }}`
- تست‌های مخصوص ترک در فایل اختیاری `.meta/additional_tests.json` تعریف می‌شوند. شیء JSON تعریف‌شده در این فایل باید یک کلید داشته باشد، `cases`، که ساختاری مشابه `cases` در
`canonical-data.json` دارد.
- تست‌های مخصوص ترک باید در فایل تست بعد از تست‌های استاندارد قرار بگیرند.
- تست‌های مخصوص ترک باید در فایل تست با کامنت زیر مشخص شوند:
```
# Additional tests for this track
```


### ساختار

بیشتر قالب‌ها چیزی شبیه به این خواهند بود:

```Jinja2
{%- import "generator_macros.j2" as macros with context -%}
{{ macros.header() }}

class {{ exercise | camel_case }}Test(unittest.TestCase):
    {% for case in cases -%}
    def test_{{ case["description"] | to_snake }}(self):
        value = {{ case["input"]["value"] }}
        expected = {{ case["expected"] }}
        self.assertEqual({{ case["property"] }}(value), expected)

    {% endfor %}

{{ macros.footer() }}
```


### بازنویسی نام‌های واردشده

اسم‌های واردشده در `macros.header()` را می‌توان با افزودن فهرستی از اسم‌های جانشین برای وارد کردن، بازنویسی کرد (مثلاً `clock`):

```Jinja2
{{ macros.header(["Clock"])}}
```


### نادیده گرفتن ویژگی‌ها

به‌ندرت ممکن است لازم باشد ویژگی‌هایی را که در این ترک تست نمی‌شوند فیلتر کنید. ماکروی `header` آرگومان `ignore` را هم می‌پذیرد (مثلاً `high-scores`):

```Jinja2
{{ macros.header(ignore=["scores"]) }}
```

## ساختن قالب

1. برای تمرینی که پیاده‌سازی می‌کنید، `.meta/template.j2` را بسازید
  و آن را در ویرایشگر خود باز کنید.
2. [ساختار نمونه](#Layout) را در فایل قالب کپی و جای‌گذاری کنید
  و ذخیره کنید.
3. تغییرات لازم را در فایل قالب اعمال کنید تا کد تست معتبری تولید
  کند، و برای اسم‌های ورودی و ساختار مورد آزمون به `canonical-data.json`
  تمرین مراجعه کنید.
    - از [ماکروهای موجود](../config/generator_macros.j2) استفاده کنید تا بخش‌های استاندارد را دوباره ننویسید.
    - اگر برای تمرینی موجود قالب پیاده‌سازی می‌کنید،
    تطبیق دقیق با ساختار فایل تست موجود الزامی نیست،
    اما کم کردن تفاوت‌ها فرایند بازبینی درخواست ادغام را برای همه‌ی افراد درگیر بسیار روان‌تر می‌کند.
