## چرخه‌ی حیات یک `Promise`

یک `Promise` سه حالت دارد:

1. pending
2. fulfilled
3. rejected

وقتی ساخته می‌شود، یک `Promise` در حالت `pending` است.
در نقطه‌ای در آینده ممکن است `resolve` یا `reject` شود.
وقتی یک `Promise` یک بار `resolve` یا `reject` شد، دیگر هرگز نمی‌تواند دوباره `resolve` یا `reject` شود و حالتش هم تغییر نمی‌کند.

به بیان دیگر:

1. یک `Promise` در حالت `pending`:
   - می‌تواند به حالت `fulfilled` یا `rejected` منتقل شود.
2. یک `Promise` در حالت `fulfilled`:
   - نباید به هیچ حالت دیگری منتقل شود.
   - باید مقداری داشته باشد که نباید تغییر کند.
3. یک `Promise` در حالت `rejected`:
   - نباید به هیچ حالت دیگری منتقل شود.
   - باید دلیلی داشته باشد که نباید تغییر کند.

## `resolve` کردن یک `Promise`

یک `Promise` به روش‌های مختلفی `resolve` می‌شود:

```javascript
// Creates a promise that is immediately resolved
Promise.resolve(value);

// Creates a promise that is immediately resolved
new Promise((resolve) => {
  resolve(value);
});

// Chaining a promise leads to a resolved promise
somePromise.then(() => {
  // ...
  return value;
});
```

در مثال‌های بالا `value` می‌تواند _هر چیزی_ باشد، از جمله یک خطا، `undefined`، `null` یا یک `Promise` دیگر.
معمولاً می‌خواهید با مقداری که خطا نیست `resolve` کنید.

## `reject` کردن یک `Promise`

یک `Promise` به روش‌های مختلفی `reject` می‌شود:

```javascript
// Creates a promise that is immediately rejected
Promise.reject(reason)

// Creates a promise that is immediately rejected
new Promise((_, reject) {
  reject(reason)
})

// Chaining a promise with an error leads to a rejected promise
somePromise.then(() => {
  // ...
  throw reason
})
```

در مثال‌های بالا `reason` می‌تواند _هر چیزی_ باشد، از جمله یک خطا، `undefined` یا `null`.
معمولاً می‌خواهید با یک خطا `reject` کنید.

## زنجیره کردن یک `Promise`

پس از آنکه یک `Promise` `resolve` یا `reject` شد، می‌توان با یک اقدام آینده آن را _ادامه_ داد.

- [`promise.then()`][promise-then] زمانی فراخوانی می‌شود که `promise` `resolve` شود
- [`promise.catch()`][promise-catch] زمانی فراخوانی می‌شود که `promise` `reject` شود
- [`promise.finally()`][promise-finally] زمانی فراخوانی می‌شود که `promise` یا `resolve` شود یا `reject`

### **then**

هر `Promise` «thenable» است.
یعنی یک تابع `then` در دسترس است که وقتی `Promise` اصلی `resolve` شد، اجرا می‌شود.
با `promise.then(onResolved)`، تابع بازگشتی `onResolved` مقداری را دریافت می‌کند که `Promise` اصلی با آن `resolve` شده است.
این همیشه یک `Promise` «زنجیره‌ای» _جدید_ برمی‌گرداند.

بازگرداندن یک `value` از `then` باعث `resolve` شدن `Promise` «زنجیره‌ای» می‌شود.
پرتاب یک `reason` در `then` باعث `reject` شدن `Promise` «زنجیره‌ای» می‌شود.

```javascript
const promise1 = new Promise(function (resolve, reject) {
  setTimeout(() => {
    resolve('Success!');
  }, 1000);
});

const promise2 = promise1.then(function (value) {
  console.log(value);
  // expected output: "Success!"

  return true;
});
```

این پس از حدود ۱۰۰۰ میلی‌ثانیه `"Success!"` را لاگ می‌کند.
حالت و مقدار `promise1` برابر `resolved` و `"Success!"` خواهد بود.
حالت و مقدار `promise2` برابر `resolved` و `true` خواهد بود.

آرگومان دومی هم در دسترس است که وقتی `Promise` اصلی `reject` می‌شود، اجرا می‌شود.
با `promise.then(onResolved, onRejected)`، تابع بازگشتی `onResolved` مقداری را دریافت می‌کند که `Promise` اصلی با آن `resolve` شده است، یا تابع بازگشتی `onRejected` دلیلی را دریافت می‌کند که `Promise` با آن `reject` شده است.

```javascript
const promise1 = new Promise(function (resolve, reject) {
  setTimeout(() => {
    resolve('Success!');
  }, 1000);

  if (Math.random() < 0.5) {
    reject('Nope!');
  }
});

function log(value) {
  console.log(value);
  return true;
}

function shout(reason) {
  console.error(reason.toUpperCase());
  return false;
}

const promise2 = promise1.then(log, shout);
```

- در حدود ۱/۲ موارد، این پس از حدود ۱۰۰۰ میلی‌ثانیه `"Success!"` را لاگ می‌کند.
  - حالت و مقدار `promise1` برابر `resolved` و `"Success!"` خواهد بود.
  - حالت و مقدار `promise2` برابر `resolved` و `true` خواهد بود.
- در حدود ۱/۲ موارد، این بلافاصله `"NOPE!"` را لاگ می‌کند.
  - حالت و مقدار `promise1` برابر `rejected` و `Nope!` خواهد بود.
  - حالت و مقدار `promise2` برابر `resolved` و `false` خواهد بود.

درک این نکته مهم است که به دلیل قواعد چرخه‌ی حیات، وقتی یک `Promise` عمل `reject` را انجام می‌دهد، `resolve`ی که حدود ۱۰۰۰ میلی‌ثانیه بعد می‌آید بی‌صدا نادیده گرفته می‌شود، چون حالت داخلی پس از `reject` یا `resolve` شدن دیگر نمی‌تواند تغییر کند.
درک این نکته هم مهم است که بازگرداندن یک مقدار از یک `Promise` آن را `resolve` می‌کند و پرتاب یک مقدار آن را `reject` می‌کند.
وقتی `promise1` `resolve` می‌شود و یک `onResolved` زنجیره‌شده دارد: `then(onResolved)`، آن ادامه یک `Promise` جدید است که می‌تواند `resolve` یا `reject` شود.
وقتی `promise1` `reject` می‌شود اما یک `onRejected` زنجیره‌شده دارد: `then(, onRejected)`، آن ادامه یک `Promise` جدید است که می‌تواند `resolve` یا `reject` شود.

### **catch**

گاهی می‌خواهید خطاها را بگیرید و فقط زمانی ادامه دهید که `Promise` اصلی `reject` شود.
با `promise.catch(onCatch)`، تابع بازگشتی `onCatch` دلیلی را دریافت می‌کند که `Promise` اصلی با آن `reject` شده است.
این همیشه یک `Promise` «زنجیره‌ای» _جدید_ برمی‌گرداند.

بازگرداندن یک `value` از `catch` باعث `resolve` شدن `Promise` «زنجیره‌ای» می‌شود.
پرتاب یک `reason` در `catch` باعث `reject` شدن `Promise` «زنجیره‌ای» می‌شود.

```javascript
const promise1 = new Promise(function (resolve, reject) {
  setTimeout(() => {
    resolve('Success!');
  }, 1000);

  if (Math.random() < 0.5) {
    reject('Nope!');
  }
});

function log(value) {
  console.log(value);
  return 'done';
}

function recover(reason) {
  console.error(reason.toUpperCase());
  return 42;
}

const promise2 = promise1.catch(recover).then(log);
```

در حدود ۱/۲ موارد، این پس از حدود ۱۰۰۰ میلی‌ثانیه `"Success!"` را لاگ می‌کند.
در ۱/۲ دیگر موارد، این بلافاصله `42` را لاگ می‌کند.

- اگر `promise1` `resolve` شود، `catch` نادیده گرفته می‌شود و به `then` می‌رسد و مقدار را لاگ می‌کند.
  - حالت و مقدار `promise1` برابر `resolved` و `"Success!"` خواهد بود.
  - حالت و مقدار `promise2` برابر `resolved` و `"done"` خواهد بود؛
- اگر `promise1` `reject` شود، `catch` اجرا می‌شود، که _مقداری را برمی‌گرداند_ و بنابراین زنجیره اکنون `resolved` است و به `then` می‌رسد و مقدار را لاگ می‌کند.
  - حالت و مقدار `promise1` برابر `rejected` و `"Nope!"` خواهد بود.
  - حالت و مقدار `promise2` برابر `resolved` و `"done"` خواهد بود؛

### **finally**

گاهی می‌خواهید پس از مشخص شدن سرانجام یک `Promise`، کدی را اجرا کنید، بی‌آنکه مهم باشد آن `Promise` `resolve` می‌شود یا `reject`.
با `promise.finally(onSettled)`، تابع بازگشتی `onSettled` هیچ مقداری دریافت نمی‌کند.
این همیشه یک `Promise` «زنجیره‌ای» _جدید_ برمی‌گرداند.

بازگرداندن یک `value` از `finally` وضعیت و مقدار `Promise` اصلی را کپی می‌کند و `value` را نادیده می‌گیرد.
پرتاب یک `reason` در `finally` باعث `reject` شدن `Promise` «زنجیره‌ای» می‌شود و هر وضعیت و مقدار یا دلیلی را از `Promise` اصلی بازنویسی می‌کند.

## مثال

چند مورد از این متدها در کنار هم:

```javascript
const myPromise = new Promise(function (resolve, reject) {
  const sampleData = [2, 4, 6, 8];
  const randomNumber = Math.round(Math.random() * 5);

  if (sampleData[randomNumber]) {
    resolve(sampleData[randomNumber]);
  } else {
    reject('Sampling did not result in a sample');
  }
});

const finalPromise = myPromise
  .then(function (sampled) {
    // If the random number was 0, 1, 2, or 3, this will be
    // reached and the number 2, 4, 6, or 8 will be logged.
    console.log(`Sampled data: ${sampled}`);
    return 'yay';
  })
  .catch(function (reason) {
    // If the random number was 4 or 5, this will be reached and
    // reason will be "An error occurred". The entire chain will
    // then reject with an Error with the reason as message.
    throw new Error(reason);
  })
  .finally(function () {
    // This will always log after either the sampled data is
    // logged or the error is raised.
    console.log('Promise completed');
  });
```

- در مواردی که `randomNumber` برابر `0-3` است:
  - `myPromise` با مقدار `2, 4, 6, or 8` `resolve` می‌شود
  - `finalPromise` با مقدار `'yay'` `resolve` می‌شود
  - دو لاگ ثبت می‌شود:
    - `Sampled data: ...`
    - `Promise completed`
- در مواردی که `randomNumber` برابر `4-5` است:
  - `myPromise` با دلیل `'Sampling did not result in a sample'` `reject` می‌شود
  - `finalPromise` با دلیل `Error('Sampling did not result in a sample')` `reject` می‌شود
  - یک لاگ ثبت می‌شود:
    - `Promise completed`
    - _در برخی محیط‌ها_ این یک لاگ `"uncaught rejected promise: Error('Sampling did not result in a sample')"` تولید می‌کند

همان‌طور که در بالا نشان داده شد، `reject` با یک رشته کار می‌کند و یک `Promise` می‌تواند با یک `Error` هم `reject` شود.
