# مقدمه

در C# می‌توان یک سلسله‌مراتب «کلاس» را با «ارث‌بری» تعریف کرد؛ به این ترتیب، یک کلاس مشتق‌شده (`Car`) می‌تواند رفتار و داده‌های کلاس والد خود (`Vehicle`) را به ارث ببرد. اگر والدی مشخص نشده باشد، کلاس از کلاس `object` ارث‌بری می‌کند.

کلاس‌های والد می‌توانند به سه روش در اختیار کلاس‌های مشتق‌شده قابلیت بگذارند:

- تعریف یک متد معمولی.
- تعریف یک متد `virtual` که مانند یک متد معمولی است، با این تفاوت که کلاس‌های مشتق‌شده _می‌توانند_ آن را تغییر دهند.
- تعریف یک متد `abstract` که متدی بدون پیاده‌سازی است و کلاس‌های مشتق‌شده _باید_ آن را پیاده‌سازی کنند. کلاسی که متدهای `abstract` دارد باید خودش هم با `abstract` علامت‌گذاری شود. کلاس انتزاعی را نمی‌توان نمونه‌سازی کرد.

اصلاح‌کننده‌ی دسترسی `protected` اجازه می‌دهد که به اعضای کلاس والد در کلاس مشتق‌شده دسترسی داشته باشیم، اما دسترسی از کلاس‌های دیگر را می‌بندد.

کلاس‌های مشتق‌شده می‌توانند از طریق «کلیدواژه‌ی» `base` به اعضای کلاس والد دسترسی داشته باشند.

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

«سازنده‌ی» کلاس مشتق‌شده به‌طور خودکار سازنده‌ی والد خود را _پیش از_ اجرای منطق سازنده‌ی خودش فراخوانی می‌کند. با کلیدواژه‌ی `base` می‌توان آرگومان‌هایی به سازنده‌ی کلاس والد فرستاد:

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

وقتی بیش از یک کلاس از یک کلاس پایه مشتق می‌شود، این دو کلاس (یا بیشتر) غالباً نسخه‌های متفاوتی از یک متد کلاس پایه را پیاده‌سازی می‌کنند. این اصل بسیار مهمی است که به آن «چندریختی» می‌گویند. برای نمونه، در گونه‌ای از مثال بالا نشان می‌دهیم که کدِ استفاده‌کننده از `Vehicle` چگونه بسته به این‌که چه نوع خودرویی نمونه‌سازی شده است، رفتارش تغییر می‌کند.

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```
