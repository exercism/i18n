# مقدمه

ریسههای Factor از نوع *همرویههای مشارکتی* هستند: همگی یک «ریسه»ی سیستمعامل را به اشتراک میگذارند، در ورودی/خروجی و در نقاط واگذاری صریح، کنترل را به یکدیگر میسپارند و هرگز واقعاً همزمان اجرا نمیشوند. هر کاری که *بین* واگذاریها انجام دهید، بهصورت یک گام پیوسته و بیوقفه پیش میرود. اما اگر یک عملیات ترکیبی (خواندن، تغییر، نوشتن) در میانهی کار واگذار شود، ریسهی دیگری میتواند پیش از تمامشدن کار شما خودش را وارد کند و وضعیت را عوض کند؛ و این همان «شرایط رقابتی» است.

این تمرین چهار سازهی اولیه را پوشش میدهد که بارها و بارها به کار میآیند:

## `parallel-map`: انشعاب/پیوستن روی یک دنباله

```
parallel-map ( seq quot: ( elt -- newelt ) -- newseq )
```

در [`concurrency.combinators`][combinators] قرار دارد. برای هر عنصر یک ریسه ایجاد میکند، یک «نقلقول» را اجرا میکند و نتایج را با همان ترتیب در یک دنبالهی جدید جمع میکند:

```factor
USING: concurrency.combinators sequences ;

{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }
```

## `spawn`: آغاز یک ریسه

```
spawn ( quot name -- thread )
```

در [`threads`][threads] قرار دارد. نقلقول بهصورت همروند اجرا میشود؛ `name` برچسبی برای debug است. دستگیرهی ریسهای که برگردانده میشود در این سطح چندان مهم نیست؛ آن را `drop` کنید.

## Promiseها: انتقال یکبارهی مقدار

```
<promise>           ( -- promise )
fulfill             ( value promise -- )
?promise            ( promise -- value )
```

در [`concurrency.promises`][promises] قرار دارد. Promise یک صندوق پستی یکبارمصرف است: یک ریسه آن را `fulfill` میکند و ریسههای دیگر آن را میخوانند. `?promise` تا زمانی که Promise پر نشده باشد منتظر میماند و سپس مقدار را برمیگرداند.

```factor
USING: concurrency.promises kernel threads ;

<promise> [
    [ 42 swap fulfill ] curry "answer" spawn drop
] keep ?promise .
! => 42
```

`spawn` و `<promise>` همان چیزهایی هستند که `parallel-map` از آنها ساخته شده است؛ ساختن دستی آنها زمانی به کار میآید که هر کار چیزی جز «محاسبهی یک عنصر» انجام دهد.

الگوی معمول پخش و پیوستن روی یک دنباله این است: برای هر ورودی یک Promise تازه بسازید، ریسهای ایجاد کنید که کار را انجام دهد و Promise را `fulfill` کند، همهی Promiseها را در یک دنباله جمع کنید و سپس روی هر یک `?promise` بزنید تا پایان کار را انتظار بکشید. متغیرهای محلی این کار را خوانا میکنند: با `:>` درون یک لامبدای `[| | ]` به Promise یک اسم بدهید تا نقلقولی که ایجاد میشود بتواند به آن دسترسی داشته باشد:

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
inputs [| x |
    <promise> :> p
    [ x do-work t p fulfill ] "worker" spawn drop
    p
] map [ ?promise drop ] each
```

## قفلها: انحصار متقابل

```
<lock>     ( -- lock )
with-lock  ( lock quot -- )
```

در [`concurrency.locks`][locks] قرار دارد. در هر لحظه تنها یک ریسه میتواند قفلی مشخص را در دست داشته باشد. `with-lock` قفل را میگیرد، نقلقول را اجرا میکند و آزاد میکند، حتی اگر نقلقول خطا پرتاب کند.

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
USING: concurrency.locks kernel locals ;

[let <lock> :> guard
    guard [ ! exclusive section ! ] with-lock
]
```

هر زمان که یک مقدار *توسط بیش از یک ریسه خوانده یا نوشته میشود* و عملیات روی آن بهطور طبیعی اتمیک نیست، از قفل استفاده کنید. هم خواندن و هم نوشتن به قفل نیاز دارند؛ خواندنی که در میانهی کار واگذار شود ممکن است وضعیت نیمهکاره را ببیند.
