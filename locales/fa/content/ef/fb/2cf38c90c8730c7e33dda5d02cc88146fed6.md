# مقدمه

«استثنا»ها در C# روشی ساختاریافته، یکنواخت و ایمن از نظر نوع برای مدیریت شرایط خطایی فراهم می‌کنند که در زمان اجرا رخ می‌دهند. مدیریت درست استثناها و خطا زمانی اهمیت دارد که بخواهید از از کار افتادن برنامه جلوگیری کنید.

در C#، همه‌ی استثناها کلاس `System.Exception` را به‌عنوان نوع پایه‌ی خود دارند. این کلاس ویژگی‌های مهمی مانند `Message` دارد که توضیحی خوانا برای انسان از دلیل پرتاب شدن استثنا ارائه می‌دهد.

برای نشان دادن این‌که در بخش مشخصی از کد باید خطایی وجود داشته باشد، باید یک شیء استثنای جدید ساخت و سپس آن را با استفاده از «کلیدواژه»ی `throw` پرتاب کرد:

```csharp
using System;
static int Square(int number)
{
    if (number >= 46341)
    {
        throw new ArgumentException($"Argument {number} cannot be higher than 46340 as its' square doesn't fit into int type.");
    }
    return number * number;
}
```

وقتی استثنایی پرتاب می‌شود، وظیفه‌ی زمان اجرا این است که قطعه‌کدی را پیدا کند که مسئول مدیریت آن استثنا باشد. اگر هیچ مدیریت‌کننده‌ی مناسبی پیدا نشود، زمان اجرا پیام استثنای مدیریت‌نشده را نمایش می‌دهد و علاوه بر آن، اجرای برنامه را متوقف می‌کند.

برای ساختن یک مدیریت‌کننده برای استثنا، C# از دستور try-catch استفاده می‌کند که شامل یک «بلوک» `try` و یک یا چند بند `catch` است. بلوک `try` باید کدی را در بر بگیرد و محافظت کند که ممکن است باعث پرتاب استثنا شود. بندهای `catch` باید کدی را در بر بگیرند که رفتار برنامه را پس از وقوع خطا مدیریت می‌کند. توجه به این نکته مهم است که ترتیب استثناها پس از بلوک `try` اهمیت دارد، چون وقتی چندین استثنا فهرست می‌شوند، اولین بند `catch` که مطابقت داشته باشد اجرا می‌شود.

```csharp
try
{
   if (number == 42)
   {
       throw new ArgumentException("The number cannot be equal to 42.", "number");
   }

   if (number < 0)
   {
      throw new ArgumentOutOfRangeException("number", "The number cannot be negative.");
   }

    // Process number ...
}
catch (ArgumentOutOfRangeException e)
{
    Console.WriteLine($"Number is out of range: {e.Message}.");
}
catch (ArgumentException)
{
    Console.WriteLine("Invalid number.");
}
```
