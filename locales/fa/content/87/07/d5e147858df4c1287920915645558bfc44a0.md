## تاریخچه‌ای بسیار کوتاه

پردازش کاراکترها در رایانه‌ها در دهه‌های پیشین بسیار ساده‌تر بود، زمانی که برنامه‌نویسان فرض می‌کردند انگلیسی تنها زبان مهم است.
یعنی: ۲۶ حرف، بزرگ و کوچک، ۱۰ رقم، چند نشانه‌ی نگارشی، به‌علاوه کدی (0x07) برای به صدا درآوردن زنگ، و همه‌ی این‌ها در ۷ بیت جا می‌شد: مجموعه‌کاراکتر [ASCII][wiki-ascii].

طبیعتاً، مردم کم‌کم پرسیدند که تکلیف à، ä و Ł چیست، بعد دیگران پرسیدند که تکلیف ऄ، ஹ و ญ چیست، و جوان‌ها ایموجی 😱 می‌خواستند.
چه باید کرد؟

خلاصه که، بسیاری از افراد باهوش و صبور مجبور شدند سال‌ها در کمیته‌ها خدمت کنند و جزئیات مجموعه‌کاراکتر [Unicode][web-unicode] و کدگذاری‌هایی مانند [UTF-8][wiki-utf-8] را مشخص کنند، و بسیاری از نرم‌افزارها به بازنویسی‌ای _بسیار_ پیچیده نیاز داشتند.
همچنین، Bugهای تازه‌ی زیادی هم به وجود آمد.

برای اینکه _همه‌چیز_ نشکند، طراحی Unicode/UTF-8 تضمین می‌کند که ۱۲۷ کد نخست با ASCII یکسان‌اند _(حتی همان زنگ)_.

## کاراکترها در Kotlin

زبان‌هایی که حدوداً پس از ۲۰۰۵ طراحی شدند، این مزیت بزرگ را دارند که یک استاندارد Unicode نسبتاً پایدار از قبل وجود داشت.

Kotlin (که نخستین بار در ۲۰۱۱ منتشر شد) می‌توانست این فرض را بگذارد که کاربران از زبان‌های (انسانی) گوناگونی استفاده می‌کنند و برای بیان آن‌ها به Unicode نیاز خواهند داشت.

لیترال‌های کاراکتر با کوتیشن تک نوشته می‌شوند و از رشته‌هایی که با کوتیشن دوگانه نوشته می‌شوند متفاوت‌اند.
این موضوع احتمالاً برای افرادی که از دنیای C/C++ می‌آیند بدیهی است، اما ممکن است برای برنامه‌نویسان Python و JavaScript گیج‌کننده باشد.

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code  // => 65535 (64k, the largest code point allowed)
```

تبدیل میان `Char` و `Int` ساده است:

```kotlin
a.code  // => 97  (a.toInt() is deprecated)
Char(97) // => 'a'
```

کامپایلر _برخی_ شکل‌های حساب عدد صحیح را روی `Char`ها مجاز می‌داند:

```kotlin
'a' + 5       // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## چند تابع برای `Char`

مثل همیشه، تعداد [توابع بسیار][ref-char-lib] بیشتری از آن است که اینجا بتوان درباره‌شان بحث کرد، پس این فقط یک گزیده است.

- برای الفباهای مناسب، حالت را با [`uppercase()`][ref-uppercase] و [`lowercase()`][ref-lowercase] تغییر دهید.
- حالت را با [`isUpperCase()`][ref-isuppercase] و [`isLowerCase()`][ref-islowercase] بررسی کنید.
- نوع کاراکتر را با این‌ها بررسی کنید:
    - [`isLetter()`][ref-isletter]، بسیاری از الفباها را پوشش می‌دهد
    - [`isDigit()`][ref-isdigit]، در بازه‌ی 0..9
    - `isLetterOrDigit()`، دو مورد قبلی را با هم ترکیب می‌کند
    - [`isWhitespace()`][ref-iswhitespace]، هر کاراکتر فضای خالی

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

## تبدیل‌های متقابل میان Char List و String

برای تبدیل String به Char List می‌توانیم از `toList()` استفاده کنیم.

برای تبدیل Char List به String، تابع [`joinToString()`][ref-jointostring] وجود دارد که یک جداکننده (اغلب رشته‌ی خالی) را به عنوان آرگومان می‌گیرد.

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

توجه کنید که `joinToString()` روی یک List یا Array عمل می‌کند.
برای _تبدیل_ یک `Char` تنها به رشته‌ای یک‌کاراکتری، از `toString()` استفاده کنید.

```kotlin
'a'.toString() // => "a"
```

برای بررسی اینکه آیا کاراکتری در یک `String`، یا در یک لیست یا آرایه‌ی `Char` وجود دارد، `in` را داریم که به تابع [`contains()`][ref-contains] نگاشت می‌شود.

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
