# درباره

`<dlist>` (در [`dlists`][dlists]) یک لیست پیوندی دوطرفه‌ی تازه می‌سازد. عملیات در [`deques`][deques] جای دارند و بر اساس [پروتکل دیک][deque-protocol] دیسپچ می‌شوند، بنابراین سایر ظرف‌ها، به‌ویژه `<dlist>`، می‌توانند آن‌ها را پیاده‌سازی کنند.

| واژه            | اثر                              |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )` ، یک «دیک» تازه و خالی  |
| `push-front`    | `( elt deque -- )` ، افزودن به ابتدا |
| `push-back`     | `( elt deque -- )` ، افزودن به انتها  |
| `pop-front`     | `( deque -- elt )` ، حذف از ابتدا |
| `pop-back`      | `( deque -- elt )` ، حذف از انتها  |
| `peek-front`    | `( deque -- elt )` ، خواندن ابتدا بدون حذف کردن |
| `peek-back`     | `( deque -- elt )` ، خواندن انتها بدون حذف کردن  |
| `deque-empty?`  | `( deque -- ? )` ، آیا دیک خالی است؟ |
| `dlist-length`  | `( dlist -- n )` ، تعداد عناصر |

همه‌ی عملیات push/pop دیک را در جا تغییر می‌دهند. سپردن یک دیک به یک رویه و سپس خواندن دوباره از آن، الگوی معمول است.

## پشته در برابر صف

دو الگوی معمول دیسپچ:

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

یک وکتور با `push` و `pop` (از `mutation`) زمانی انتخاب درست است که تنها چیزی که لازم دارید ترتیب LIFO باشد، چون `<dlist>` سربار لیست پیوندی را با خود دارد. وقتی به O(1) در *هر دو* سر نیاز دارید سراغ `<dlist>` بروید؛ این تقریباً همیشه برای یک صف FIFO است.

## الگوی BFS

جست‌وجوی سطح‌به‌سطح، کاربرد استاندارد FIFO است:

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

دیک «مرز» جست‌وجو را با خود می‌برد و مجموعه‌ی هش کار حذف تکراری‌ها را انجام می‌دهد. کافی است `pop-front` را با `pop-back` عوض کنید تا همین ساختار به جست‌وجوی عمق‌به‌عمق تبدیل شود.

## ذخیره‌سازی خودکار با `MEMO:`

گاهی جست‌وجویی که BFS برای هر گره انجام می‌دهد گران است. Factor نیز [`MEMO:`][memo-decl] را فراهم می‌کند؛ جایگزینی برای `:` که نتیجه‌ی واژه را بر پایه‌ی ورودی‌هایش به‌طور خودکار در کش ذخیره می‌کند:

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

یک واژه‌ی `MEMO:` بار اولی که هر ورودی دیده می‌شود بدنه‌اش را اجرا می‌کند و از آن پس نتیجه‌ی کش‌شده را برمی‌گرداند. این کش تا پایان عمر تصویر زنده می‌ماند و هیچ حذفی بر اساس زمان یا اندازه انجام نمی‌شود. از آن برای توابع خالصی استفاده کنید که ورودی‌هایشان از یک مجموعه‌ی متناهی و قابل مدیریت می‌آید.
