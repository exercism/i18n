# مقدمه

برنامه‌ی `jq` که هنگام پردازش یک مقدار به مشکل بخورد، مثلاً ایندکس کردن یک عدد با یک رشته، تجزیه‌ی متن JSON نامعتبر، یا فراخوانی یک تابع با آرگومانی از نوع اشتباه، یک **خطای زمان اجرا** ایجاد می‌کند.
خطای زمان اجرایی که گرفته نشود باعث می‌شود `jq` پیامی را به _خطای استاندارد_ چاپ کند و با کد وضعیت `5` از برنامه خارج شود.

## ایجاد خطا: `error` و `error(message)`

- `error` خطایی ایجاد می‌کند که مقدارش **مقدار ورودی** است.
- `error(message)` خطایی ایجاد می‌کند که مقدارش نتیجه‌ی `message` است.

مقدار خطا می‌تواند _هر_ مقدار JSON باشد، نه فقط یک رشته.

```jq
42 | error("invalid value: \(.)")
# => "invalid value: 42"

42 | error
(not a string): 42
```

## گرفتن خطاها: `try` و `catch`

خطاها را می‌توان با `try EXP catch HANDLER` گرفت.
ابتدا عبارت اول اجرا می‌شود؛ اگر خطایی ایجاد کند، عبارت `HANDLER` **با مقدار خطا به عنوان ورودی‌اش** اجرا می‌شود.
خروجی `try catch` همان خروجی عبارتی است که آخر از همه اجرا شده باشد (یا `EXP` یا `HANDLER`).

```jq
{a: 42} | try .a catch "no index a in \(.)"
# => 42

true | try .a catch "cannot index a \(type)"
# => "cannot index a boolean"

true | try error("some exception") catch .
# => "some exception"
```

شکل کوتاه‌تر `try EXP` معادل `try EXP catch empty` است: خطا دور ریخته می‌شود و هیچ خروجی‌ای تولید نمی‌شود.

```jq
[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]
```

## نادیده گرفتن خطاها: عملگر `?`

عملگر `?`، وقتی به شکل `EXP?` به کار برود، کوتاه‌نویسی `try EXP` است.
این عملگر یک عبارت شکست‌خورده را به عبارتی تبدیل می‌کند که به سادگی هیچ خروجی‌ای تولید نمی‌کند.

```jq
["1", "invalid", "3", 4] | [.[] | tonumber?]
# => [1, 3, 4]
```

معمولاً این عملگر را چسبیده به عملگرهای ایندکس می‌بینید: `.foo?` و `.[]?`.

## متوقف کردن برنامه: `halt_error` و `halt`

`halt_error` برنامه را متوقف می‌کند، ورودی‌اش را به صورت متن خام به _خطای استاندارد_ چاپ می‌کند و با وضعیت داده‌شده از برنامه خارج می‌شود که به طور پیش‌فرض `5` است.
فیلتر مرتبط `halt` برنامه را بی‌صدا و با کد وضعیت `0` متوقف می‌کند.

```jq
"Error: something went wrong" | halt_error(1)
```
