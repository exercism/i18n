# مقدمه

## نوع مات

### مقدمه

نوع مات یک تکنیک کپسوله‌سازی در Elm است.
برخی این کار را پنهان‌سازی اطلاعات یا پنهان‌کردن جزئیات پیاده‌سازی هم می‌نامند.
این نوع معمولاً برای اعمال اعتبارسنجی و با استفاده از الگوی [تجزیه کنید، اعتبارسنجی نکنید][parse-dont-validate] به‌کار می‌رود.
برای مثال، می‌توانید یک نوع مات `EmailAddress` داشته باشید که تنها می‌تواند نشانی ایمیل معتبر را در خود نگه دارد (برخلاف `String` که می‌تواند هر چیزی را شامل شود).

### ساخت نوع مات

[انواع سفارشی][custom-types] یک یا چند *گونه* دارند و کامپایلر به‌طور خودکار تابعی برای ساخت هر *گونه* تولید می‌کند که از اسم آن *گونه* استفاده می‌کند.
این تنها راه ساخت انواع سفارشی است.
کامپایلر همچنین شکستن ساختار را برای این گونه‌ها ممکن می‌کند.

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

به‌طور پیش‌فرض، همه‌ی این‌ها درونیِ فایل / ماژول هستند و ما با «کلیدواژه»ی `exposing` انتخاب می‌کنیم چه چیزی صادر شود.
برای ساخت یک نوع مات، تنها کاری که می‌کنید این است که انتخاب کنید *گونه*ها صادر نشوند.

وقتی این کار را می‌کنید، تقریباً همیشه لازم است راه دیگری برای ساخت و گرفتن *گونه*ها فراهم کنید، با صادر کردن توابع سفارشی.
این توابع سفارشی به شما امکان می‌دهند هنگام ساخت و گرفتن *گونه*ها منطقی را اعمال کنید.
این کار جزئیات پیاده‌سازی درونی ماژول را پنهان می‌کند و به این معناست که تا زمانی که توابع صادرشده یکسان بمانند، می‌توانید جزئیات پیاده‌سازی را هرقدر که بخواهید تغییر دهید.

### تجزیه کنید، اعتبارسنجی نکنید

احتمالاً رایج‌ترین کاربرد نوع مات، اعمال اعتبارسنجی با الگوی «تجزیه کنید، اعتبارسنجی نکنید» است.
در این الگو، تابعی را صادر می‌کنید که ورودی‌ای با ساختار / ایمنی نوعی کمتر از آنچه می‌خواهید می‌گیرد، مانند `String`، و سپس آن را به نوعی ساختارمندتر، مانند `EmailAddress`، تجزیه می‌کنید؛ و یا آن نوع را برمی‌گردانید یا یک خطا (معمولاً `Maybe` یا `Result`) را برمی‌گردانید.

برای مثال، در کد زیر تنها ماژول‌های بیرونی می‌توانند با استفاده از تابع `parseEmailAddress` یک نوع `EmailAddress` بسازند؛ پس وقتی با نوع `EmailAddress` کار می‌کنید، مطمئن هستید که معتبر است.

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
