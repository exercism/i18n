# معرفی

در بسیاری از زبان‌های شیءگرا، رایج است که رفتارها را با [زیرکلاس‌سازی][wiki-subclass] یک کلاس والد گسترش می‌دهند، متدها را از والد به ارث می‌برند و در همان حال متدهای تازه هم اضافه می‌کنند. به این ترتیب به یک سلسله‌مراتب اشیاء می‌رسیم.

زبان Julia _کلاس ندارد_، پس به‌تبع آن _زیرکلاس هم ندارد_.
حالا چگونه رفتارهای موجود را به ارث می‌بریم و گسترش می‌دهیم؟

در مفاهیم پیشین دیدیم که چگونه یک سلسله‌مراتب نوع بسازیم و همچنین آموختیم که Julia چگونه از [اعزام چندگانه][concept-multiple-dispatch] برای انتخاب متد بر اساس نوع آرگومان‌ها استفاده می‌کند.

Julia چندین رابط غیررسمی هم دارد که به انواع سفارشی شما اجازه می‌دهند به رفتارهایی که از پیش برای انواع استاندارد تعریف شده‌اند متصل شوند.

ساده‌ترین راه نشان دادن این موضوع، رابط تکرارگر است.

## تکرارگر

پیش‌تر در سرفصل‌های دوره، چندین روش دیده‌ایم که Julia می‌تواند با آن‌ها روی هر عنصر یک مجموعه کار کند.

- [حلقه‌ها][concept-loops]، مانند `for item in items...`
- [پخش][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [توابع مرتبه‌بالا][concept-hof]: `map(√, [1, 4, 9])`
- [درک فهرستی][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [مولدها][concept-comprehensions]: `(x^2 for x in 1:1e6)`، که به‌صورت تنبل ارزیابی می‌شود.

بدیهی است که Julia می‌داند چگونه مجموعه‌های استاندارد را عنصر به عنصر پیمایش کند: بردارها و بازه‌ها در مثال‌های بالا، و همچنین `Set`ها، `Dict`ها و غیره.

چگونه این توانایی را به مجموعه‌های سفارشی خودمان اضافه می‌کنیم، به‌ویژه اگر بتوان مانند یک مولد آن‌ها را به‌صورت تنبل تکرار کرد؟

### حداقل الزامات

برای ساختن یک دنباله برای تکرار، به (حداقل) دو مورد نیاز داریم:

1. راهی برای گرفتن _اولین_ عنصر.
2. راهی برای گرفتن عنصر _بعدی_ از حالت فعلی.

Julia این کارها را با متدهایی از تابع `Base.iterate()` و با گام‌های زیر انجام می‌دهد:

1. ابتدا `Base.iterate(iter)` به‌طور خودکار فراخوانی می‌شود.
    - اگر موردی برای تکرار وجود نداشته باشد، `nothing` برمی‌گرداند.
    - در غیر این صورت، یک `Tuple` از اولین عنصر برگردانده‌شده و اولین حالت را برمی‌گرداند: `(firstitem, firststate)`.
2. اگر در تکرار قبلی عنصری برگردانده شده باشد، `Base.iterate(iter, state)` به‌طور خودکار فراخوانی می‌شود و `firststate` را به‌عنوان آرگومان `state` خود می‌گیرد.
    - اگر تکرار پایان یابد، `nothing` برمی‌گرداند.
    - در غیر این صورت، یک `Tuple` از عنصر بعدی و حالت بعدی را برمی‌گرداند: `(nextitem, nextstate)`.
3. گام ۲ را تا پایان تکرار می‌کند.

همه‌ی این گام‌ها «در پشت صحنه» انجام می‌شوند؛ یعنی فراخوانی متدها و حالت، به‌صورت داخلی توسط پروتکل تکرار مدیریت می‌شوند (و حالت مبهم می‌ماند) و تنها عنصر در معرض سازه‌های سطح بالا، مانند حلقه‌ها، قرار می‌گیرد.
به بیان دیگر، ما همیشه فقط `item` را می‌بینیم و بقیه‌ی موارد در جعبه‌ی سیاه باقی می‌مانند.

[اعزام چندگانه][concept-multiple-dispatch] در اینجا نقش محوری دارد.
نوع `iter` تعیین می‌کند که کدام متدها فراخوانی شوند و تعداد آرگومان‌ها تعیین می‌کند که عنصر اول برگردانده شود یا عنصر بعدی.

متدهایی برای انواع استاندارد از قبل تعریف شده‌اند: `Vector`، `Range`، `Set` و غیره ([در حال حاضر][ref-iterations-collections] در مجموع ۱۴ نوع).

برای اینکه یک `MyType` سفارشی همان رفتارها را داشته باشد، ابتدا باید این‌ها را تعریف کنیم:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

همه‌ی این‌ها در حالت انتزاعی احتمالاً گیج‌کننده به نظر می‌رسند، اما می‌تواند کاملاً ساده باشد.
برای نمونه، فرض کنید نوعی می‌خواهیم که توان‌های یک عدد صحیح مفروض `n` را تا یک تعداد بیشینه بدهد.

ابتدا یک نوع سفارشی تعریف کنید:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

حالا می‌توانیم متدهای `iterate` را برای این نوع تعریف کنیم، اما اولین عنصر و اولین حالت کدام‌اند؟

برای به دست آوردن اولین عنصر، بعضی تکرارگرها به مقدمات پیچیده‌ای نیاز دارند، اما در این مثال ساده می‌بینیم که اولین عنصر برگردانده‌شده همان عدد پایه است، پس فقط باید بررسی کنیم که مقدار `count` بزرگ‌تر یا مساوی یک باشد.

حالا می‌توانیم به اولین حالت فکر کنیم، که اطلاعاتی را حمل می‌کند که در تکرار بعدی استفاده می‌شود.
تصمیم اینکه برای این کار به نگه‌داشتن چه اطلاعاتی نیاز دارید با خودتان است و می‌تواند هر نوعی باشد.

در این حالت، می‌توانیم فقط «اندیس»ی را که `n` به آن توان می‌رسد نگه داریم، یا می‌توانیم با استفاده از آخرین توان `n` (یعنی همان عنصر برگردانده‌شده) و «اندیس» بعدی در دنباله، گزینه‌ای کاراتر پیدا کنیم.
این دو عدد را می‌توان در یک `Tuple` بسته‌بندی کرد و به‌عنوان `state` برگرداند.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

در این مثال، اولین عنصر (`p.n`) به حلقه برگردانده می‌شود و اولین حالت `(p.n, 2)` به متد `iterate(P::Powers, state)` پاس داده می‌شود.
آنجا می‌توانیم حالت را پردازش کنیم تا با ضرب عنصر فعلی در عدد پایه، عنصر بعدی را تولید کنیم و به این ترتیب توان آن را `1` واحد افزایش دهیم.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

اگر مقدار اندیس هنوز در محدوده‌ی `count` باشد، `Tuple`ی با عنصر `next` و حالت افزایش‌یافته برگردانده می‌شود.
وقتی مقدار `index` از `count` فراتر رود، به‌جای آن `nothing` برگردانده می‌شود تا نشان دهد تکرار پایان یافته است.

شاید متوجه شده باشید که بدنه‌ی متدهای `iterate(p::Powers)` و `iterate(p::Powers, state)` نسبتاً شبیه هم است.
در واقع، اگر زیرک باشیم، این شباهت امکان یک پیاده‌سازی ساده‌تر را می‌دهد: استفاده از فقط نسخه‌ی دوآرگومانی همراه با یک آرگومان پیش‌فرض برای حالت، یعنی `Base.iterate(p::Powers, state=(1, 1))`
با این کار، دیگر به نسخه‌ی تک‌آرگومانی جداگانه‌ی `iterate(p::Powers)` نیازی نداریم.
در عمل، هرجا ممکن باشد این کار رایج است.

تا اینجا، همین حالا هم کمی قابلیت مفید داریم: برای ۴ توان اول ۳ می‌توانیم روی نتایج حلقه بزنیم، بررسی کنیم که یک عدد مفروض در نتایج هست یا نه، و توابع تجمعی‌ای مانند `sum()` را اعمال کنیم.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### متدهای بیشتر

با وجود این شروع خوب، هنوز همه‌چیز کار نمی‌کند.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

و همان‌طور که انتظار می‌رفت، `length(Powers(3, 4))` دقیقاً همان پیام خطا را می‌دهد.

این مشکل به‌راحتی حل می‌شود، چون طول بخشی از سازنده‌ی نوع است: در این حالت ۴.
فقط باید `Base.length()` را برای این نوع تعریف کنیم؛ آن‌وقت می‌توانیم از درک فهرستی و `collect()` روی دنباله استفاده کنیم.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

برای کارایی بهتر، بهتر است `Base.eltype()` را هم تعریف کنید: نوع عناصر نتیجه.
این کار به توابعی مانند `collect()` اجازه می‌دهد که از پیش فضا برای خروجی `Vector{Int}` تخصیص دهند، به‌جای اینکه مکرراً روی یک `Vector{Any}` عملیات `push!()` انجام دهند.

به نحوه‌ی نگارش توجه کنید، که ممکن است پیش‌تر ندیده باشید: این متد روی خود _نوع_ تعریف می‌شود، نه روی یک _نمونه_ از آن نوع.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

تکرارگرها _الزامی_ نیست که طول متناهی داشته باشند.
استفاده از دنباله‌های «نامتناهی» محدودتر است، اما تا زمانی که راهی برای `break` از حلقه وجود داشته باشد، حلقه زدن روی آن‌ها می‌تواند مفید باشد.
برای مثال، می‌توانستیم گونه‌ای از `Powers` تعریف کنیم که مقادیری کوچک‌تر از یک حد معین تولید کند (شاید `typemax(Int)`، برای پرهیز از سرریز عدد صحیح).

## خلاصه

توضیح دادن رابط‌ها نسبتاً گیج‌کننده است، چون رویکرد Julia با بیشتر زبان‌های دیگر بسیار متفاوت است.
به‌ویژه اینکه ممکن است نام رابط هرگز در پیاده‌سازی ذکر نشود؛ بسیار برخلاف [زیرکلاس‌سازی][wiki-subclass] یا [میکسین‌ها][wiki-mixins].

اما در عمل، به‌طور شگفت‌آوری ساده‌اند:

1. یک نوع مناسب تعریف کنید.
2. بفهمید کدام متدها لازم‌اند.
3. آن متدها را برای نوع سفارشی خود پیاده‌سازی کنید؛ معمولاً فقط چند متد، و کاملاً کوتاه و ساده.
4. بگذارید [اعزام چندگانه][concept-multiple-dispatch] بقیه را به‌طور خودکار انجام دهد.
