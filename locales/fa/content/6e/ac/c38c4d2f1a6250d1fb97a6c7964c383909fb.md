# درباره

[رکوردها][records] ساختارهای داده‌ای هستند که اطلاعات مرتبط را همراه با برچسب کنار هم گروه‌بندی می‌کنند. آن‌ها شبیه به اشیاء در JavaScript یا Java، یا `struct` در C یا Rust هستند، اما چند تفاوت کلیدی دارند.

## ساختن رکوردها

رکوردها با آکولاد [ساخته می‌شوند][create] و عناصرشان با ویرگول از هم جدا می‌شوند.

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

نوع یک رکورد هم با نگارش مشابهی تعریف می‌شود، با این تفاوت که علامت‌های مساوی `=` با علامت‌های دو نقطه `:` جایگزین می‌شوند.

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

تکرار این تعریف‌های نوع دست‌وپاگیر است، بنابراین استفاده از [نام مستعار نوع][record-types] برای به اشتراک گذاشتن تعریف، روشی رایج است.

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

نام مستعار نوع همچنین به‌طور خودکار یک تابع سازنده برای رکورد فراهم می‌کند. این گاهی غافلگیرکننده است، چون توابع در Elm باید با حرف کوچک شروع شوند، اما سازنده‌های نوع یک استثنا هستند.

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

## دسترسی به فیلدهای رکورد

راه اصلی [دسترسی به مقدار یک فیلد از یک نمونه‌ی رکورد][access] استفاده از نگارش نقطه‌ای مانند `firefly.creator` است.
کامپایلر Elm همچنین از توابع دسترسی ویژه‌ای که با نقطه‌ی `.` شروع می‌شوند، مانند `.creator`، پشتیبانی می‌کند که روی هر رکوردی با فیلدی به آن اسم کار می‌کنند.
این دومین استثنا بر قاعده‌ی این است که توابع باید با حرف کوچک شروع شوند.
در واقع توابعی که کاربر تعریف می‌کند باید با حرف کوچک شروع شوند، اما دو نمونه‌ای که همین حالا دیدیم را کامپایلر می‌سازد، نه برنامه‌نویس.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

رکوردها را می‌توان در اتصال‌ها هم با استفاده از [تطبیق الگوی رکورد][pattern-matching] _از هم باز کرد_.
این بازکردن با هر رکوردی که فیلدهایی با اسم‌های مربوطه داشته باشد کار می‌کند.

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

## به‌روزرسانی رکوردها

رکوردها مانند همه‌چیز در Elm تغییرناپذیرند، بنابراین وقتی رکوردی تعریف شد، مقادیر فیلدهایش هرگز تغییر نمی‌کنند.
[نگارش ویژه‌ای برای ساختن نسخه‌ای از یک رکورد موجود با تغییر یک یا چند فیلد][update] وجود دارد.
این نگارش از علامت خط عمودی `|` استفاده می‌کند تا رکورد اصلی را از فیلدهایی که تغییر خواهند کرد جدا کند، مانند `{ oldRecord | field1 = newValue }`.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

## مقایسه‌ی رکوردها

Elm از [برابری ساختاری][equality] استفاده می‌کند، یعنی دو نمونه از یک رکورد با مقادیر یکسان برابرند.

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

## رکوردهای گسترش‌پذیر

Elm همچنین از [نوع‌دهی ساختاری][structural-typing] پشتیبانی می‌کند، یعنی اگر تابعی به رکوردی با فیلدهای `x` و `y` نیاز داشته باشد، با هر رکوردی که آن فیلدها را داشته باشد کار می‌کند؛ مثل نقاط دوبعدی، نقاط سه‌بعدی، سفینه‌های فضایی و غیره.
این نوع‌های رکورد در تعریفشان یک خط عمودی `|` دارند، مانند `{ a | x : Float, y : Float }`، و در اصطلاح Elm «رکوردهای گسترش‌پذیر» نامیده می‌شوند.
مراقب تفاوت میان خط عمودی `|` در یک تعریف نوع، که تعریف یک رکورد گسترش‌پذیر است (`{ a | x : Int }`)، و خط عمودی `|` در یک نمونه‌ی واقعی رکورد باشید، که یعنی داریم چند فیلد از آن رکورد را به‌روزرسانی می‌کنیم.

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
