# مبانی نحوه‌ی نگارش Haskell

## ثابت‌ها و توابع

برنامه‌های Haskell از تعریف‌ها و عبارت‌ها ساخته شده‌اند.

یک مقدار ثابت با `name = expression` تعریف می‌شود.

```haskell
five = 5

six = 3 + 3
```

توابع با `name parameters... = expression` تعریف می‌شوند و پارامترها فقط با فاصله از هم جدا می‌شوند.

```haskell
add number1 number2 = number1 + number2
```

فراخوانی یک تابع هم خودش یک عبارت است و با مشخص کردن اسم آن و دادن آرگومان برای هر یک از پارامترهای تابع انجام می‌شود؛ آرگومان‌ها هم درست مثل تعریف توابع فقط با فاصله از هم جدا می‌شوند.

```haskell
five = add 2 3
```

از پرانتز می‌توان برای مشخص کردن ترتیب ارزیابی یک عبارت استفاده کرد.

```haskell
six = add 2 (1 * 4)

twelve = add 2 1 * 4
```

## تورفتگی / فاصله‌های معنادار

Haskell از فاصله‌ها و تورفتگی برای مشخص کردن مرزهای کد استفاده می‌کند.
***کدی که بخشی از یک عبارت است باید با تورفتگی بیشتری نسبت به ابتدای آن عبارت نوشته شود.***

- تعریف‌های ماژول، `import` و توابع سطح‌بالا باید از چپ‌ترین ستون شروع شوند.
- اگر یک عبارت به چند خط تقسیم شود، کدی که بخشی از آن عبارت است باید با حداقل یک فاصله زیر آن عبارت تو رفته باشد.
- بخش‌هایی از عبارت که با هم گروه‌بندی می‌شوند باید با تعداد فاصله‌های برابر تو رفته باشند.

```haskell
-- A function split over multiple lines, so subsequent lines must be indented
add number1 number2 =
    number1 + number2
```

https://en.wikibooks.org/wiki/Haskell/Indentation

## ماژول‌ها

ماژول‌ها توابع را صادر می‌کنند.
یعنی می‌توانید از توابعی استفاده کنید که ماژول در دستور صادرات خود در اختیار می‌گذارد.
یک ماژول می‌تواند توابعی را هم فقط برای استفاده‌ی داخلی تعریف کند.
به طور پیش‌فرض، توابعی که به‌صراحت صادر نشده باشند نمی‌توانند از بیرون ماژول استفاده شوند.

در ابتدای یک ماژول، اسم ماژول را مشخص می‌کنیم.
اگر فایلی به اسم `Calculator.hs` داشته باشیم، باید ماژولمان را `Calculator` بنامیم.
سپس توابعی را که صادر می‌کند مشخص می‌کنیم و بعد از آن می‌توانیم نوشتن توابع را شروع کنیم.
پس با این شروع می‌کنیم.

```haskell
module Calculator ( add ) where
```

https://learnyouahaskell.github.io/modules#making-our-own-modules

## توضیحات

توضیح متنی است درون فایل Haskell که به عنوان کد تفسیر نمی‌شود.
هدف اصلی آن این است که خودتان و برنامه‌نویسان دیگر آن را بخوانید.
برای توضیح‌های یک‌خطی، یک روش نگارش سبک بر پایه‌ی دو خط تیره وجود دارد.
توضیح‌های چندخطی هم با جفت جداکننده‌ی باز و بسته‌ی `{-` و `-}` ممکن است.

```haskell
-- a single line comment
-- another single line comment

{- a multiline comment
   spanning multiple lines
-}
```
