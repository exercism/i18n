# مقدمه

تابع زمانی «بازگشتی دنباله‌ای» است که _آخرین_ کاری که در آن اجرا می‌شود، فراخوانی خودش باشد.

هر بار که تابعی فراخوانی می‌شود، یک _قاب پشته_ همراه با متغیرهای محلی و آرگومان‌هایش روی [پشته‌ی فراخوانی تابع][call-stack] قرار می‌گیرد. وقتی تابع برمی‌گردد، قاب پشته از پشته برداشته می‌شود.

توابع بازگشتی دنباله‌ای امکان [بهینه‌سازی فراخوانی دنباله][tail-call-optimization] (یا حذف فراخوانی دنباله) را فراهم می‌کنند. این یک بهینه‌سازی است که اجازه می‌دهد قاب پشته‌ی آخرین بار، توسط فراخوانی بعدی دوباره استفاده شود، آن هم وقتی تضمین شده که تابع قبلی دیگر به آن نیازی ندارد. این کار نگرانی سرریز شدن پشته‌ی فراخوانی تابع را کم می‌کند؛ وضعیتی که در آن آن‌قدر قاب روی پشته‌ی فراخوانی نشسته است که حافظه‌ای برای ساختن یکی دیگر باقی نمی‌ماند.

## بهینه‌سازی فراخوانی دنباله در Elm

تحت شرایطی، کامپایلر Elm هنگام کامپایل کردن به JavaScript می‌تواند به‌طور خودکار بهینه‌سازی فراخوانی دنباله را انجام دهد.

این بهینه‌سازی می‌تواند برای یک تابع بازگشتی رخ دهد، زمانی که _آخرین_ عملیات در یک شاخه، فراخوانی خود تابع در یک کاربرد ساده‌ی تابع باشد. بیایید چند مثال ببینیم:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

پیاده‌سازی بالا بازگشتی دنباله‌ای نیست، چون آخرین عملیات در شاخه‌ی `else` یک ضرب `n *` است.

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

پیاده‌سازی بالا بازگشتی دنباله‌ای است و بهینه می‌شود، چون آخرین عملیات در شاخه‌ی `else` این است که `factorialHelper` خودش را فراخوانی می‌کند. این کار برای تابعی با امضای نوع `Int -> Int` ممکن نبود، و در عمل بهینه‌سازی فراخوانی دنباله اغلب با تعریف توابع کمکی به دست می‌آید.
