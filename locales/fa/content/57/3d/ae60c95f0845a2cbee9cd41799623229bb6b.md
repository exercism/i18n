# مقدمه

یک اعلان `GENERIC:` یک «واژه» می‌سازد که رفتارش به *کلاس* یکی از آرگومان‌هایش بستگی دارد. رفتار مشخص از *متدها* می‌آید که با `M:` تعریف می‌شوند.

```factor
GENERIC: area ( shape -- n )

TUPLE: square side ;
TUPLE: circle radius ;

M: square area
    side>> dup * ;
M: circle area
    radius>> dup * pi * ;
```

وقتی `area` فراخوانی شود، Factor بالای پشته را بررسی می‌کند، خاص‌ترین متدی را که کلاسش تطبیق دارد جست‌وجو می‌کند و آن را اجرا می‌کند. با متغیرهای محلی می‌توانید از `M::` استفاده کنید:

```factor
TUPLE: rectangle width height ;

M:: rectangle area ( r -- n )
    r width>> r height>> * ;

T{ rectangle { width 3 } { height 4 } } area .   ! => 12
```

جنریک به شما اجازه می‌دهد بعداً بازنمایی‌های تازه اضافه کنید، بدون اینکه کد فراخوان‌کننده را تغییر دهید: `area` پیش‌تر برای `square` و `circle` کار می‌کرد و متد `rectangle` هرجا که `area` فراخوانی شود، به‌طور خودکار به کار گرفته می‌شود.

## چه وقت یک جنریک انتخاب درست است

وقتی سراغ `GENERIC:` بروید که:

- یک عملیات واحد برای ورودی‌های مختلف، پیاده‌سازی‌های *واقعاً متفاوتی* داشته باشد.
- انتظار دارید در آینده نوع‌های تازه به آن اضافه شود.
- می‌خواهید سیستم نوع، تعریف‌های مخصوص هر کلاس را الزام کند.

اگر این تفاوت فقط یک برشماری کوچک از برچسب‌ها باشد، `case` ساده‌تر است.

## پیوستن به یک میکسین با `INSTANCE:`

یک *میکسین* یک کلاس جنریک است که *باز* است. هرکس می‌تواند یک کلاس تازه را به‌عنوان عضو ثبت کند. بسیاری از پروتکل‌های داخلی Factor (دنباله‌ها، مجموعه‌ها، جریان‌ها، …) به‌صورت میکسین در دسترس‌اند، بنابراین یک تاپل سفارشی می‌تواند با اعلام خود به‌عنوان یک نمونه، متدهای پیش‌فرض پروتکل را بپذیرد:

```factor
MIXIN: shape
M: shape area                   ! a default area for any shape
    drop 0 ;

TUPLE: my-shape ;
INSTANCE: my-shape shape         ! my-shape is now a `shape`

T{ my-shape } area .   ! => 0
```

بعد از `INSTANCE:`، هر متد پیش‌فرض `M: shape …` به‌طور خودکار روی `my-shape` دیسپچ می‌شود و هر کدی که یک `shape` بخواهد، یک `my-shape` را می‌پذیرد. `M:` برای افزودن متد به یک جنریک است. `INSTANCE:` برای پیوستن یک کلاس به یک میکسین.

## `TYPED::`، ورودی‌های بررسی‌شده برای یک واژه‌ی ساده

`GENERIC:`/`M:` متد را بر اساس کلاس یک آرگومان انتخاب می‌کنند. گاهی دیسپچ نمی‌خواهید، فقط *یک* واژه که تأکید دارد ورودی‌هایش از کلاس مشخصی هستند. `TYPED::` (در واژگان `typed`) همان `::` است، با این تفاوت که بعد از اسم هر ورودی یک کلاس نوشته می‌شود:

```factor
TYPED:: triple ( n: integer -- m )
    n 3 * ;

14 triple .   ! => 42
```

`n: integer` شبیه همان متغیرهای محلی‌ای است که تا حالا استفاده کرده‌اید، فقط کلاس بعد از دونقطه نوشته می‌شود. هیچ دیسپچی در کار نیست (یک تعریف، یک رفتار)، اما هر آرگومان حالا با کلاسش بررسی می‌شود: ناسازگاری‌ای مثل `"x" triple` رد می‌شود (*expected input value of type integer but got string*) و بی‌صدا از آن عبور نمی‌کند.

خروجی را هم می‌توان به همین شکل نشانه‌گذاری کرد. `yes?` هم ورودی و هم نتیجه‌اش را نوع‌بندی می‌کند:

```factor
TYPED:: yes? ( word: string -- answer: boolean )
    word "yes" = ;

"yes" yes? .   ! => t
"no" yes? .    ! => f
```

## توابع و ثابت‌های ریاضی

این تمرین به چند واژه از `math.constants` و `math.functions` هم تکیه می‌کند که اولین بار همین‌جا با آن‌ها روبه‌رو می‌شوید:

- `pi`، ثابت π، از `math.constants`.
- `sin ( x -- y )`، `cos ( x -- y )`، سینوس و کسینوس یک زاویه بر حسب رادیان.
- `e^ ( x -- y )`، یعنی `e` به توان `x`. (برای هر پایه‌ی دلخواه، از `^` استفاده کنید.)

```factor
pi 2 / sin   ! → 1.0
0 cos        ! → 1.0
1 e^         ! → 2.718281828459045
```
