# درباره

تنها قرارداد انتقال داده در Factor، *پشته‌ی داده* است: واژه‌ها ورودی‌هایشان را از پشته برمی‌دارند و خروجی‌هایشان را روی آن می‌گذارند. هر تعریف واژه، آن قرارداد را در قالب یک *اثر پشته* اعلام می‌کند.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

نام‌های داخل `( … -- … )` به سود خواننده‌اند؛ چیزی که کامپایلر بررسی می‌کند *تعداد* ورودی‌ها و خروجی‌هاست. ناهمخوانی یک خطای زمان کامپایل است که دسته‌ای از باگ‌ها را می‌گیرد که در یک زبان با نوع‌دهی پویا و بدون این نوع اعلام، به خطاهای زمان اجرا تبدیل می‌شدند.

چون پشته موقعیت‌محور است، باید پیوسته بالای آن را بازآرایی کنید تا واژه‌ی بعدی بتواند اجرا شود. **واژه‌های جابه‌جایی** در `kernel` دقیقاً همین کار را می‌کنند:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

خانواده‌ی کامل جابه‌جایی این‌ها را با `-rot` (چرخاندن در جهت مخالف)، عموزاده‌های پسوند-`d` که یک عنصر عمیق‌تر عمل می‌کنند (`dupd`، `swapd`)، عموزاده‌های پیشوند-`2` که روی جفت‌ها عمل می‌کنند (`2dup`، `2drop`، `2nip`) و موارد دیگری مانند `pick` و `tuck` گسترش می‌دهد. این واژه‌ها بر حسب نیاز تمرین‌های بعدی معرفی می‌شوند؛ به‌کار بردن همزمان تعداد زیادی واژه‌ی جابه‌جایی معمولاً نشانه‌ای است بر اینکه یک *متغیر محلی* (مقدار نامدار) خواناتر خواهد بود.

بر اساس قرارداد، واژه‌ها از `lowercase-kebab-case` استفاده می‌کنند، محمول‌ها به `?` ختم می‌شوند و یک «مقدار منطقی» تولید می‌کنند (`even?`، `empty?`)، setterها به شکل `>>name` و getterها به شکل `name>>` نوشته می‌شوند، و یک واژه و نسخه‌ی تغیردهنده‌اش اغلب اسم یکسانی دارند که تنها با بافت از هم تشخیص داده می‌شوند.
