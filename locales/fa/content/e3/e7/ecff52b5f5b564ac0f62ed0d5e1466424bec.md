# مقدمه

تعریف نوع‌های سفارشی در برنامه‌هایمان اغلب مفید است.

ساختن نوع‌های اولیه‌ی جدید ممکن است، اما به‌ندرت انجام می‌شود.
نوع‌های اولیه‌ی از پیش تعریف‌شده انتخابی دلبخواهی نیستند: آن‌ها به‌طور نزدیک با نوع‌های استاندارد در کامپایلر LLVM که جولیا برای کامپایل JIT به کار می‌برد، مطابقت دارند.

بسیار مفیدتر، توانایی تعریف «نوع‌های ترکیبی» با فیلدهای نامدار است.

زبان‌های دیگر نیز مفهوم مشابهی دارند و آن‌ها را `structs` یا `records` می‌نامند.
مستندات جولیا آن‌ها را `composite types` می‌نامد، هرچند (با کمی ناهمخوانی) نحوه‌ی نگارش زبان آن‌ها را با «کلیدواژه»ی `struct` تعریف می‌کند.

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

چند نکته در مثال بالا ارزش توجه دارد:

- هیچ نوعی برای `id` مشخص نشده است، پس کامپایلر آن را `id::Any` تفسیر می‌کند.
  - در عمل، بهتر است با مشخص کردن نوع یک فیلد به‌صورت یک نوع مشخص، به کامپایلر کمک کنید
- اسم نوع به‌عنوان یک «سازنده» به کار می‌رود، مانند `Person(id, name, age)`، تا نمونه‌ای از نوع `Person` بسازد.
- می‌توان با نشانه‌گذاری نقطه‌ای به فیلدهای جداگانه دسترسی داشت، درست مانند تاپل‌های نامدار.

نمونه‌هایی از نوع `Person` تغییرناپذیرند، بنابراین به‌روزرسانی مجاز نیست.

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

اگر تغییرپذیری لازم است، `mutable` را به تعریف اضافه کنید.

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

سازنده به‌طور پیش‌فرض لازم می‌داند که فیلدها به همان ترتیبی که در تعریف آمده‌اند ظاهر شوند، که برای نوع‌های پیچیده‌تر ناخوشایند می‌شود.

استفاده از ماکروی `@kwdef` دو قابلیت تازه را ممکن می‌کند:

- سازنده از کلیدواژه‌ها استفاده می‌کند، نه از موقعیت.
- فیلدها می‌توانند مقادیر پیش‌فرض داشته باشند و به‌صورت اختیاری می‌توان آن‌ها را از سازنده حذف کرد.

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## سلسله‌مراتب نوع‌های ترکیبی

تا اینجا، ما فقط نوع‌های ترکیبی مشخص ساخته‌ایم.
اگر بررسی کنید، همه زیرنوع‌های `Any` هستند.

هنگام ساختن چند نوع مرتبط، احتمالاً منطقی‌تر است که برای آن‌ها یک «سلسله‌مراتب» تعریف کنید.
این کار بسیار به‌سادگی انجام می‌شود.

ابتدا یک «نوع انتزاعی» بسازید:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

سپس، عملگر `<:` را در تعریف یک نوع بگنجانید تا رابطه را نشان دهید.

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

به تعداد لازم تکرار کنید و به یاد داشته باشید که زیرنوع‌سازی نوع‌های مشخص مجاز نیست.

برای سلسله‌مراتبی پیچیده‌تر، در صورت نیاز زیرنوع‌های انتزاعی بسازید.

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

ارزش چنین سلسله‌مراتبی زمانی روشن‌تر می‌شود که به مفهوم `Multiple Dispatch` برسیم و ببینیم توابع چگونه با نوع‌های آرگومان رفتار می‌کنند.
