# راهنمایی‌ها

یکی از کاربردهای رایج `Either` نشان دادن محاسباتی است که ممکن است به خطا منجر شود (اگر خود خطا اهمیتی برایتان ندارد، شاید نوع ساده‌تر `Option` انتخاب بهتری باشد).
در نبود خطا، نتیجه معمولاً یک `Right` است (یادیار: مقدار «درست»)، در حالی که خطا یک `Left` است؛ برای مثال یک `Left[String]` که پیام خطا را در خود دارد.
توجه کنید که در Scala ۲.۱۲، `Either` به‌طور پیش‌فرض به سمت `Right` گرایش دارد، بنابراین برای عملیاتی مثل `filter`، `map`، `flatMap` یا داخل یک for-comprehension همان‌طور که انتظار دارید عمل می‌کند.
اگر با `Either` آشنا نیستید، می‌توانید [این آموزش](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html) را بخوانید. اما توجه داشته باشید که این آموزش مربوط به نسخه‌های Scala پیش از ۲.۱۲ است. برای Scala ۲.۱۲ می‌توانید `RightProjection` را با خیال راحت نادیده بگیرید و `.right` را حذف کنید.
`Either` چیزی است که به آن [موناد](https://en.wikipedia.org/wiki/Monad_(functional_programming)) می‌گویند و یک «جنبه‌ی محاسباتی» را در بر می‌گیرد؛ در اینجا منظور مدیریت خطاست.
استفاده‌ی درست از مونادها می‌تواند به کدی بسیار مختصر و در عین حال زیبا و خوانا منجر شود. استفاده‌ی نادرست به‌راحتی نتیجه‌ی برعکس می‌دهد.
برای یادگیری بیشتر [این ویدیو](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) را تماشا کنید.

## دام‌های رایجی که باید از آن‌ها دوری کنید

چند قاعده‌ی سرانگشتی برای `Either` وجود دارد:

1. اگر به آن نیازی ندارید، از آن استفاده نکنید. به‌جای این

```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```

بهتر است این را بنویسید

```scala
def add1(x: Int): Int = x + 1
```

(برای اعمال چنین توابع ساده‌ای `Either.map` وجود دارد، پس لازم نیست آن‌ها را با `Either` شلوغ کنید).

2. اگر واقعاً نیازی نیست، مقدار را «بازگشایی» نکنید.
اغلب توابع آماده‌ای برای هدف شما وجود دارد. نشانه‌های بازگشایی زودهنگام `isLeft/isRight` یا تطبیق الگو هستند. برای مثال، به‌جای این

```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```

بهتر است این را بنویسید

```scala
x fold (identity, _ + 1)
```

3. می‌توان مونادها را داخل یک for-comprehension هم به کار برد؛ نتیجه‌اش هم عالی است.
این کار وقتی توصیه می‌شود که بخواهید چند نمونه‌ی `Either` را با هم «ترکیب» کنید. به‌جای این

```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```

بهتر است این را بنویسید

```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
