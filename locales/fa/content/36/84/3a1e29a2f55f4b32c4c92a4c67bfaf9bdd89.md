# درباره

## اعمال جزئی

همه‌ی توابع در Elm [کار‌ی‌شده][currying] هستند؛ یعنی اگر تابعی را بدون ارسال همه‌ی آرگومان‌ها فراخوانی کنید، یک تابع جدید برمی‌گرداند.

به نتیجه‌ی این کار [اعمال جزئی][partial-application] می‌گویند (شما همه‌ی آرگومان‌ها را به تابع نمی‌فرستید، بلکه فقط بخشی از آن‌ها را اعمال می‌کنید).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

اعمال جزئی همیشه آرگومان‌ها را به ترتیب اعمال می‌کند.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## عملگر لوله (`|>`)

نوشتن `x |> f` دقیقاً معادل `f x` است. یک مثال عینی: `"5" |> String.toInt` معادل `String.toInt "5"` است.

این در نگاه اول چندان کاربردی به نظر نمی‌رسد، اما به آن [عملگر لوله][pipe-operator] می‌گویند، چون به شما امکان می‌دهد کد را به سبک «زنجیره‌ای» بنویسید.

برای مثال، فرض کنید یک تابع `sanitize` داریم که ورودی کاربر را به عدد تبدیل می‌کند:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

می‌توانیم آن را این‌طور بازنویسی کنیم:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

این روش استفاده از پرانتز را حذف می‌کند و توابع را به ترتیبی نشان می‌دهد که اعمال می‌شوند (اول `String.trim`، بعد `String.toInt`) که به خوانایی کمک می‌کند.

یک [عملگر لوله‌ی معکوس `(<|)`][reverse-pipe-operator] هم وجود دارد. نوشتن `x <| f` دقیقاً معادل `f x` است. این هم در نگاه اول چندان کاربردی به نظر نمی‌رسد و قطعاً به اندازه‌ی عملگر لوله استفاده نمی‌شود، اما در برخی موقعیت‌ها به حذف پرانتزها کمک می‌کند.

## ترکیب توابع / سبک بدون آرگومان

عملگر [`(>>)`][forward-composition] نوع `(a -> b) -> (b -> c) -> (a -> c)` را دارد و با ترکیب دو تابع سازگار از نوع `a -> b `و `b -> c`، تابعی از نوع `a -> c` می‌سازد. این کار را با گرفتن خروجی (از نوع `b`) از تابع اول و استفاده از آن به‌عنوان اولین آرگومان تابع دوم انجام می‌دهد (که باید از همان نوع `b` باشد). تابع ساخته‌شده همان ورودی تابع اول (از نوع `a`) را می‌گیرد و هر مقدار `c`ی را که تابع دوم برگرداند، برمی‌گرداند.

یک مثال عینی `String.trim >> String.toInt` است. `String.trim` یک رشته را به‌عنوان تنها پارامترش می‌گیرد، پس تابع ساخته‌شده هم همین را می‌گیرد. `String.toInt` یک `Maybe Int` برمی‌گرداند، پس تابع ساخته‌شده هم همین را برمی‌گرداند. `String.trim` یک `String` برمی‌گرداند که `String.toInt` آن را به‌عنوان پارامتر می‌پذیرد، پس مثال کامپایل می‌شود.

حالا می‌توانیم تابع `sanitize` خود را این‌طور بازنویسی کنیم:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

دقت کنید که دیگر از پارامتر `input` که در مثال اصلی می‌بینید استفاده نمی‌کنیم، هرچند کارکرد یکسان است. به این روش ساختن توابعی که هیچ اشاره‌ای به پارامترهایشان نمی‌کنند، «سبک بدون آرگومان» می‌گویند. مزیت این سبک این است که کد مختصرتر می‌شود؛ عیبش این است که درک آن، به‌ویژه برای تازه‌کارها، می‌تواند سخت‌تر باشد.

به یاد داشته باشید که در Elm همه‌ی توابع کاری‌شده هستند، پس `String.length >> max` کامپایل می‌شود و نتیجه‌ی زیر را می‌دهد:

- یک تابع (۱) که یک پارامتر رشته دارد (ورودی `String.length`)
- `max` تابعی است که دو پارامتر `Int` دارد، اما تابع ۱ یک `Int` واحد به آن می‌فرستد (خروجی `String.length`)، پس `max` به‌صورت جزئی اعمال می‌شود.
- مقدار بازگشتی تابع `max` که جزئی اعمال شده، تابع دیگری (۲) است که یک `Int` می‌گیرد و بزرگ‌ترین مقدار میان این `Int` و `Int` حاصل از اعمال جزئی `String.length` را برمی‌گرداند.
- در نتیجه تابع ۱ (`String -> Int`) تابع ۲ (`Int -> Int`) را برمی‌گرداند.
- پس `((String.length >> max) "123") 2` مقدار `3` را برمی‌گرداند، چون طول `"123"` برابر ۳ است که از ۲ (آرگومان `Int`) بزرگ‌تر است.

## طراحی توابع

برای اینکه نوشتن کد زیبا در Elm آسان شود، بهتر است ساختار داده‌ی اصلی را آخرین پارامتر توابع قرار دهید. همه‌ی توابع رایج در کتابخانه‌ی استاندارد همین کار را می‌کنند، مثل `List.map` (امضای نوع آن در ادامه).

```elm
map : (a -> b) -> List a -> List b
```

اینجا می‌بینیم که آخرین پارامتر تابع `map` برابر `List a` است و `List b` را برمی‌گرداند، پس ساختار داده‌ی اصلی (`List`) آخرین پارامتر است.

این کار نوشتن کد زنجیره‌ای زیبا را ممکن می‌کند، مثل نمونه‌ی زیر.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

همچنین استفاده از ترکیب توابع و سبک بدون آرگومان را، به‌عنوان جایگزینی برای زنجیره‌سازی، راحت می‌کند.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

ترکیب توابع همچنین به شما اجازه می‌دهد این مثال را به یک فراخوانی واحد `List.map` کاهش دهید.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
