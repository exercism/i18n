# درباره

ورودی/خروجی در Factor بر پایه‌ی یک [پروتکل][stream-protocol] واحد بنا شده است که هر منبع یا مقصد داده می‌تواند آن را پیاده‌سازی کند. جریان‌هایی که همراه Factor عرضه می‌شوند، یعنی `<file-reader>`، `<file-writer>`، `<string-reader>`، `<string-writer>`، سوکت‌های شبکه، آرایه‌های بایتی و ttyها، همگی کلاس‌هایی‌اند که همان چند جنریکِ [`io`][io] را پیاده‌سازی می‌کنند و `disposable` را از [`destructors`][destructors] گسترش می‌دهند.

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe` خواندنِ دسته‌ایِ سطح‌پایین است: بافری را که فراخوان در اختیار می‌گذارد پر می‌کند و برمی‌گرداند که چند عنصر نوشته شده است. `stream-read` و `stream-read-partial` عمومی بر پایه‌ی آن ساخته شده‌اند و تخصیص حافظه را انجام می‌دهند. بیشتر جریان‌هایی که کاربر تعریف می‌کند یا `stream-read1` را پیاده‌سازی می‌کنند (وقتی خواندن‌ها هر بار یک عنصر انجام می‌شود) یا `stream-read-unsafe` را (وقتی خواندن‌ها می‌توانند دسته‌ای شوند).

`stream-element-type` یکی از دو توکن یگانه را برمی‌گرداند: `+byte+` برای جریان‌های بایتی (خواننده‌های فایل، سوکت‌ها) و `+character+` برای جریان‌های نویسه‌ای (خواننده‌های رشته، ttyها). یک جریان پوشاننده معمولاً فقط کار را به جریان زیرین خود واگذار می‌کند.

## پیوستن به میکسین‌ها

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

یک کلاس می‌تواند یکی، دیگری یا هر دو باشد. پیوستن به میکسین باعث می‌شود متدهای پیش‌فرض `input-stream` / `output-stream` به کلاس شما ارسال شوند؛ همان الگوی میکسین باز مثل `set` از ووکبِ `sets`.

## چارچوب disposable

`new-disposable ( class -- disposable )` یک نمونه‌ی تازه را با دامنه‌ی فعلی تخریب‌گر ثبت می‌کند تا اگر در میانه‌ی آماده‌سازی منابع استثنایی رخ دهد، همه‌چیز به‌شکل تمیز باز شود:

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose` کلمه‌ی عمومی است؛ `dispose*` همان جنریکی است که کلاس پیاده‌سازی می‌کند. بازنویسی `dispose*` در یک زیرکلاس باید وضعیت خودش را تمیز کند و سپس هر منبعی را که در اختیار دارد آزاد کند:

```factor
M: my-stream dispose* underlying>> dispose ;
```

این چارچوب تضمین می‌کند که `dispose*` حداکثر یک بار برای هر شیء اجرا شود؛ فراخوانی‌های مکرر `dispose` بی‌اثرند.

## دسترسی‌گرهای محدوده‌دار

سه ترکیب‌گر، جریان ورودی/خروجی جاری سراسری را راه‌اندازی می‌کنند که `print`، `read1` و مانند این‌ها از آن استفاده می‌کنند:

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

هرکدام هنگام خروج منبع را آزاد می‌کنند، حتی اگر نقل‌قول خطا بدهد. بیشتر کدها برای استفاده از یک جریان سفارشی از همین‌ها استفاده می‌کنند، به‌جای اینکه آن را در هر فراخوانی دست‌به‌دست کنند.
