# مقدمه

Gleam برای مدیریت خطا از «استثنا» استفاده نمی‌کند؛ در عوض، توابعی که ممکن است موفق شوند یا شکست بخورند، نوع عمومی `Result` را برمی‌گردانند.

نوع `Result` در خود زبان تعبیه شده است، بنابراین نیازی نیست آن را تعریف یا وارد کنید. اما اگر خودتان آن را تعریف کنید، به این شکل خواهد بود:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

وقتی یک تابع موفق شود، گونه‌ی `Ok` برگردانده می‌شود و وقتی یک تابع شکست بخورد، گونه‌ی `Error` برگردانده می‌شود.

نتایج در Gleam بسیار رایج‌اند و برنامه‌نویسان Gleam معمولاً از [ماژول `gleam/result`](https://hexdocs.pm/gleam_stdlib/gleam/result.html) استفاده می‌کنند تا کار با آن‌ها آسان‌تر شود.

از تابع `result.map` می‌توان استفاده کرد تا روی مقدار درون یک نتیجه، در صورتی که `Ok` باشد، یک تابع فراخوانی شود؛ یا تا یک `Error` بدون تغییر عبور داده شود.

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

تابع `result.try` مشابه است، اما انتظار می‌رود که تابع بازخوان یک نتیجه برگرداند. این برای زنجیره کردن چندین تابع که نتیجه برمی‌گردانند مفید است.

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
