# مقدمه

TypeScript همان JavaScript است که نحوه‌ی نگارش مربوط به نوع‌ها را نیز در خود دارد؛ همین آن را به یک زبان برنامه‌نویسی با نوع‌های قوی تبدیل می‌کند که از سبک‌های شیءگرا، دستوری و اعلانی (مثلاً برنامه‌نویسی تابعی) پشتیبانی می‌کند و در هر مقیاسی ابزارهای بهتری در اختیار شما می‌گذارد.

چون [بدون یادگیری JavaScript نمی‌توانید TypeScript یاد بگیرید][handbook-js-or-ts]، بخشی از محتوای این مسیر به آموزش مفهوم‌های JavaScript اختصاص دارد و بخشی از این مفهوم‌ها فقط به قابلیت‌های مخصوص TypeScript می‌پردازند.

## انتساب (مجدد)

چند راه اصلی برای انتساب مقدار به اسم‌ها در TypeScript وجود دارد: استفاده از متغیر یا ثابت.
در Exercism، نام متغیرها همیشه به‌صورت [camelCase][wiki-camel-case] نوشته می‌شود و نام ثابت‌ها به‌صورت [SCREAMING_SNAKE_CASE][wiki-snake-case].
راهنمای رسمی واحدی برای پیروی وجود ندارد و شرکت‌ها و سازمان‌های مختلف راهنماهای سبک متفاوتی دارند.
_متغیرها را به هر شکلی که دوست دارید بنویسید._
مزیت نوشتن آن‌ها به همان شکلی که تمرین‌ها آماده شده‌اند این است که در رابط وب و بیشتر IDEها به شکل متفاوتی برجسته می‌شوند.

متغیرها در TypeScript را می‌توان با کلیدواژه‌های [`const`][mdn-const]، [`let`][mdn-let] یا [`var`][mdn-var] تعریف کرد.

وقتی از `let` یا `var` استفاده می‌کنید، یک متغیر می‌تواند در طول عمرش به مقدارهای متفاوتی اشاره کند.
برای مثال، `myFirstVariable` را می‌توان با عملگر انتساب `=` بارها تعریف و بازتعریف کرد:

```typescript
let myFirstVariable = 1
myFirstVariable = 0
myFirstVariable = 42
```

برخلاف `let` و `var`، متغیرهایی که با `const` تعریف می‌شوند فقط یک بار می‌توانند مقدار بگیرند.
از این ویژگی برای تعریف ثابت‌ها در TypeScript استفاده می‌شود.

```typescript
const MY_FIRST_CONSTANT = 10

// Can not be re-assigned.
MY_FIRST_CONSTANT = 20
// => TypeError: Assignment to constant variable.
```

چون TypeScript می‌تواند این را به‌صورت ایستا تشخیص دهد، کامپایلر TypeScript هم خطا می‌دهد:

```typescript
// ^? Cannot assign to 'MY_FIRST_CONSTANT' because it is a constant.(2588)
```

یعنی برای تشخیص `TypeError` لازم نیست کد را اجرا کنید.

## استنتاج نوع

بدون اینکه خیلی عمیق به موضوع [استنتاج نوع][handbook-type-inference] بپردازیم، باید بدانید که یک متغیر مقدارگرفته معمولاً نوعی استنتاج‌شده دارد، حتی بدون یادداشت نوع.

```typescript
const MY_FIRST_CONSTANT = 10
// ^? const MY_FIRST_CONSTANT: number
```

این نوع بعد از آن در سراسر کد اعمال می‌شود.
این یعنی جایی که کد زیر در JavaScript معتبر است:

```javascript
let myFirstVariable = 1
myFirstVariable = 'Some string'
```

در TypeScript خطا می‌دهد:

```typescript
let myFirstVariable = 1
myFirstVariable = 'Some string'
// ^? Type 'string' is not assignable to type 'number'.(2322)
```

این قابلیت حتی وقتی از یادداشت نوع استفاده نمی‌شود، ایمنی نوع را تضمین می‌کند.

## اعلان تابع

در TypeScript، واحدهای عملکردی در _تابع‌ها_ کپسوله می‌شوند؛ معمولاً اگر تابع‌ها به هم مربوط باشند، در یک فایل کنار هم قرار می‌گیرند.
این تابع‌ها می‌توانند پارامتر (آرگومان) بگیرند و با کلیدواژه‌ی `return` یک مقدار _برگردانند_.
تابع‌ها با نوشتن `()` فراخوانی می‌شوند.

```typescript
function add(num1: number, num2: number): number {
  return num1 + num2
}

add(1, 3)
// => 4
```

معمولاً باید نوع پارامترهای تابع را با یک دونقطه (`:`) و سپس نوع، یادداشت کرد.
مقدار بازگشتی تابع را می‌توان بعد از بستن فهرست پارامترها، با یک دونقطه (`:`) و سپس نوع، یادداشت کرد.

<!--prettier-ignore -->
~~~~exercism/note
💡 در TypeScript راه‌های _بسیار_ متفاوتی برای اعلان یک تابع وجود دارد.
این راه‌های دیگر با استفاده از کلیدواژه‌ی `function` فرق دارند.
این مسیر می‌کوشد آن‌ها را به‌تدریج معرفی کند، اما اگر از قبل با آن‌ها آشنا هستید، هر کدام را که خواستید به کار ببرید.
در بیشتر موارد، استفاده از یکی یا دیگری بهتر یا بدتر نیست.
~~~~

## یادداشت نوع

همان‌طور که در اعلان تابع `add` دیدید، پارامترها یک یادداشت نوع صریح `: number` دارند.
اعلان‌های متغیر، ویژگی‌های کلاس، اعلان‌های تابع و موارد بیشتر، همگی از یادداشت نوع پشتیبانی می‌کنند.

هم یادداشت نوع صریح و هم نوع‌های استنتاج‌شده توسط بررسی‌کننده‌ی نوع اعمال می‌شوند.

```typescript
add('foo', 3)
// ^? Argument of type 'string' is not assignable to parameter of type 'number'.(2345)
```

## در دسترس قرار دادن برای فایل‌های دیگر

برای اینکه یک `function`، یک ثابت یا یک متغیر در _فایل‌های دیگر_ در دسترس باشد، باید با کلیدواژه‌ی `export` [صادر][mdn-export] شوند.
سپس فایل دیگری می‌تواند این‌ها را با کلیدواژه‌ی `import` [وارد][mdn-import] کند.
به این کار سیستم ماژول هم می‌گویند.
مثال خوبی از این، نحوه‌ی کار همه‌ی تست‌هاست.
هر تمرین دست‌کم یک فایل دارد، برای مثال `lasagna.ts`، که شامل _پیاده‌سازی_ است.
علاوه بر این، دست‌کم یک فایل دیگر هم وجود دارد، برای مثال `lasagna.test.ts`، که شامل _تست‌ها_ است.
این فایل موجودیت‌های عمومی (یعنی صادرشده) را _وارد_ می‌کند تا پیاده‌سازی را تست کند:

```typescript
// file.ts
export const MY_VALUE = 10

export function add(num1, num2) {
  return num1 + num2
}

// file.test.ts
import { MY_VALUE, add } from './file.js'

add(MY_VALUE, 5)
// => 15
```
