# مقدمه

در دنیای آرمانی، می‌توانستیم روی این حساب کنیم که همه‌چیز به‌خوبی تعریف شده باشد، با مقادیر مشخص و بدون شکاف.

این با تجربه‌ی روزمره‌ی ما در تناقض است، و از این رو بسیاری از زبان‌های برنامه‌نویسی راهی برای نمایش نبودِ یک مقدار دارند: null یا NULL، nil، None، nothing و...

معرفی این مفهوم آسان بود (در سال ۱۹۶۵)، اما به‌زودی باعث پشیمانی شد.
مخترع آن بعدها این را «اشتباه میلیارد دلاری» خود نامید.

در دهه‌های اخیر، طراحان زبان راه‌های بسیاری را بررسی کرده‌اند تا مقادیر null در دسترس باشند اما (عمدتاً) ایمن.

Kotlin چند [اصل کلی][ref-null-safety] دارد که با Java تفاوت چشمگیری دارند.


- Kotlin یک مقدار `null` ویژه دارد.
- همه‌ی نوع‌ها به‌طور _پیش‌فرض_ غیر nullable هستند.
- بیشتر نوع‌ها را می‌توان _nullable_ کرد، اما برنامه‌نویس باید صریحاً این کار را درخواست کند.
- توابعی که ممکن است با یک استثنا شکست بخورند، احتمالاً گونه‌ای با مقدار بازگشتی nullable دارند.
- نحوه‌ی نگارشِ ویژه و بسیار موجز تلاش می‌کند بررسی nullها و واکنش به آن‌ها را تا حد امکان آسان کند.

## ساخت متغیرهای nullable

نوع‌های استاندارد عموماً معادل nullable دارند، با پسوند `?`: برای نمونه `String?` به‌جای `String`.

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## عملگرها و توابع مفید

### عملگر فراخوانی ایمن `?.`

برای یک `String` غیر nullable، می‌توانیم به ویژگی `.length` دست پیدا کنیم.

یک `String?` nullable با همان نحوه‌ی نگارش خطا می‌دهد، اما استفاده از `?.length` احتمال `null` را در نظر می‌گیرد.
نوع بازگشتی `Int?` است.

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

همان‌طور که در خط آخر بالا دیدیم، `?.` با نوع‌های غیر nullable هم کار می‌کند.

### عملگر Elvis `?:`

با گسترش ایده‌ی عملگر فراخوانی ایمن، [عملگر Elvis][wiki-elvis] به ما امکان می‌دهد تا یک مقدار پیش‌فرض به‌جای `null` بدهیم.

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### عملگر تأیید غیر-null `!!`

با این عملگر، وقتی برنامه‌نویس مطمئن باشد، یک نوع nullable به‌اجبار به‌صورت غیر nullable در نظر گرفته می‌شود.
شاید ما گاهی منطق برنامه را بهتر از یک کامپایلر بیش از حد محتاط درک می‌کنیم؟

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

حالا مسئولیت بر عهده‌ی ماست: اگر `b` هنوز `null` باشد، یک `NullPointerException` می‌گیریم.

### تابع `let` (`?.let`)

اگر یک عنصر nullable را به یک بلوک کد بدهیم، می‌توانیم بررسی‌های مشخص null انجام دهیم: `if (item != null) { do something }`.

استفاده از `item?.let { do something }` ساده‌تر و طبیعی‌تر است،
`do something` تنها زمانی اجرا می‌شود که `item` برابر null نباشد.

### توابعی از نوع `somethingOrNone()`

برخی توابع ممکن است شکست بخورند، برای نمونه هنگام درخواست یک اندیس نامعتبر در یک رشته یا فهرست.

به‌جای پرتاب یک استثنا، می‌توانیم از گونه‌ی `...OrNull` تابع استفاده کنیم تا (در این حالت) یک مقدار بازگشتی `Int?` بگیریم.

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
