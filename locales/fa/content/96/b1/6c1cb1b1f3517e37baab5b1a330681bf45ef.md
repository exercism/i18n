# مسیر

یک مسیر از بخش‌های مختلفی تشکیل شده است.

## فراداده

پیکربندی و فراداده‌ی مسیر در فایل `config.json` مشخص می‌شود. این فایل تمرین‌ها، مفاهیم، تنظیمات ویرایشگر و موارد بسیار بیشتری از مسیر را فهرست می‌کند. [مستندات config.json](/docs/building/tracks/config-json) را ببینید.

## مفاهیم

همه‌ی تمرین‌های مفهومی و عملی یک مسیر، _مفاهیم_ را در بر می‌گیرند. این مفاهیم خودشان موجودیت‌های جداگانه‌ای هستند. برای اطلاعات بیشتر [مستندات](/docs/building/tracks/concepts) را ببینید.

مفاهیمی که در تمرین‌های مفهومی مسیر آموزش داده می‌شوند، یک _برنامه‌ی درسی_ را تشکیل می‌دهند.
_برنامه‌ی درسی_ به‌صورت یک _نقشه‌ی مفهومی_ به دانش‌آموزان نشان داده می‌شود.
برای یادگیری درباره‌ی ساخت نقشه‌ی مفهومی برای یک _برنامه‌ی درسی_، [مستندات _نقشه‌ی مفهومی_](/docs/building/tracks/concept-map) را ببینید.

برای اطلاعات بیشتر درباره‌ی نحوه‌ی طراحی یک برنامه‌ی درسی، [مستندات برنامه‌ی درسی](/docs/building/tracks/syllabus) را ببینید.

## تمرین‌ها

مسیر دو نوع تمرین دارد:

- تمرین‌های مفهومی: برای آموزش یک یا چند مفهوم به یک دانش‌آموز طراحی شده‌اند. برای اطلاعات بیشتر [مستندات](/docs/building/tracks/concept-exercises) را ببینید.
- تمرین‌های عملی: برای تمرین مفاهیم آموخته‌شده طراحی شده‌اند. برای اطلاعات بیشتر [مستندات](/docs/building/tracks/practice-exercises) را ببینید.

### Dig Deeper

هر تمرین یک بخش اختیاری Dig Deeper دارد که می‌تواند شامل موارد زیر باشد:

- [رویکردها](/docs/building/tracks/approaches): روش‌های مختلفی که تمرین می‌تواند با آن‌ها حل شود
- [مقاله‌ها](/docs/building/tracks/articles): جنبه‌های جالب تمرین را توصیف می‌کنند
- ویدیوهای انجمن: ویدیوهایی که تمرین را نشان می‌دهند، معمولاً با حل کردن تمرین از صفر توسط یک نفر

## فایل‌های مشترک

برخی فایل‌ها مخصوص تمرین‌های جداگانه نیستند، بلکه برای _همه‌ی_ تمرین‌ها کاربرد دارند. برای اطلاعات بیشتر [مستندات](/docs/building/tracks/shared-files) را ببینید.

## مستندات

هر مسیر چند فایل مستندات ضروری دارد. برای اطلاعات بیشتر [مستندات](/docs/building/tracks/docs) را ببینید.

## ویجت‌ها

برخی بخش‌های مسیر می‌توانند در [ویجت‌ها](/docs/building/markdown/widgets) نمایش داده شوند.

## راهنمای سبک

همه‌ی اسناد باید از [راهنمای سبک](/docs/building/markdown/style-guide) پیروی کنند. اسناد Markdown
نیز باید از [استانداردهای Markdown](/docs/building/markdown/markdown) ما پیروی کنند.

## نگهداری

### مجوزهای مخزن

به هر مسیر به‌طور خودکار یک [دسته‌بندی نگهداری](/docs/building/github/maintainers-repo-permissions#maintenance-category) اختصاص داده می‌شود که [مجوزهای مخزن GitHub نگهدارنده‌ی مسیر](/docs/building/github/maintainers-repo-permissions#repo-permissions) را تعیین می‌کند.

### اجتناب از ایجاد اجراهای Test غیرضروری

وقتی یک PR مسیر را که به یک تمرین دست می‌زند ادغام می‌کنید، باعث می‌شود _همه‌ی_ آخرین نسخه‌های منتشرشده‌ی راه‌حل‌های دانش‌آموزان دوباره Test شوند.
برای تمرین‌های محبوب، این یک عملیات _بسیار_ پرهزینه است (۷۰٬۰۰۰ اجرای Test برای Hello World در Python به‌عنوان یک نمونه‌ی حاد!).

**از شما می‌خواهیم سعی کنید این کار را بی‌دلیل انجام ندهید.**

راه‌حل‌ها **دوباره Test نمی‌شوند** اگر کامیت ادغام‌شده یا:

- فقط فایل‌های `.docs` یا `.meta` یا فایل‌های دیگری را لمس کند که کاربران با آن‌ها تعامل ندارند
- یا در بدنه‌ی کامیت شامل `[no important files changed]` باشد.

راه‌حل‌ها **دوباره Test می‌شوند** اگر کامیت ادغام‌شده هر دو شرط زیر را داشته باشد:

- در بدنه‌ی کامیت `[no important files changed]` را نداشته باشد
- و یکی از فایل‌های زیر را برای یک تمرین لمس کند (همان‌طور که در فایل `.meta/config.json` آن مشخص شده است):
  - فایل‌های Test
  - فایل‌های ویرایشگر
  - فایل‌های invalidator

چند مثال:

- [Python#۳۴۲۳](https://github.com/exercism/python/pull/3423): فقط مستندات را لمس می‌کند، بنابراین هیچ Testی اجرا نشد
- [Python#۳۴۳۷](https://github.com/exercism/python/commit/29a64a4889f94bafbd0062d7fc5052858523b25c): با `[no important files changed]` اضافه‌شده ادغام شد، بنابراین هیچ Testی اجرا نشد
- [Csharp#۲۱۳۸](https://github.com/exercism/csharp/pull/2138): فاصله‌های خالی از Testها حذف شد. کلیدواژه **اضافه نشد**. Testها بی‌دلیل دوباره اجرا شدند.
