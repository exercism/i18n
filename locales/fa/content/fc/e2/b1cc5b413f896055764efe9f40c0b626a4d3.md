# نقشه و مجموعه

| نوع | چه چیزی نگه می‌دارد | جست‌وجو بر اساس |
| --- | --- | --- |
| `ARRAY{T}` | مقادیر به ترتیب | موقعیت |
| `FMAP{K,T}` | جفت‌های کلید-هدف | کلید |
| `FSET{T}` | مقادیر، بدون تکرار | عضویت |

## FMAP

```sather
   m ::= #FMAP{STR,INT};
   m := m.insert("emu", 2);
   m.get("emu")          -- 2
   m.has_ind("emu")      -- true
   m.size                -- 1
   m := m.delete("emu");
```

`m["emu"]` روش خواندن یک نقشه **نیست**؛ `FMAP` چنین روالتی ندارد و آن خط کامپایل نمی‌شود. باید از `get` استفاده کنید.

### کلیدهای ناموجود

`get` روی کلیدی که وجود ندارد، به‌جای گلایه، مقدار خالی آن نوع را برمی‌گرداند: `0`، `false` یا void. یک `STR` تهی همان‌جا که تولید می‌شود خطا نمی‌دهد؛ بعداً، هر جا که در نهایت به کار برود، خطا می‌دهد. اول `has_ind` را بررسی کنید؛ همین عادتی است که ارزش ساختن دارد.

## FSET

```sather
   s ::= #FSET{STR};
   s := s.insert("emu");
   s.has("emu")          -- true
   s.size                -- 1
   s := s.delete("emu");
```

مجموعه‌ها با هم ترکیب می‌شوند:

```sather
   a.union(b)            -- in either
   a.intersect(b)        -- in both
   a.difference(b)       -- in a but not b
   a.is_subset(b)
```

## بازنسبت‌دهی و کپی گرفتن

`insert` و `delete` ظرفی را برمی‌گردانند که از این پس باید از آن استفاده کنید. معمولاً همان شیء است که در جای خودش تغییر کرده؛ وقتی لازم باشد بزرگ‌تر شود، شیء تازه‌ای است، بزرگ‌تر. بنابراین:

```sather
   m := m.insert(k, v);     -- always
```

و بعد از آن، تنها اسمی که می‌توانید به آن اعتماد کنید اسم سمت چپ است. اسم دیگری برای همان نقشه که پیش از `insert` گرفته‌اید، ممکن است کهنه باشد.

برای نگه‌داشتن یک کپی مستقل، اول یکی بگیرید:

```sather
   n ::= m.copy.insert(k, v);      -- m is unchanged
```

فقط یک نکته هست: نقشه‌ای که هرگز چیزی در آن درج نشده **void** است و `copy` روی یک نقشه‌ی void خطا می‌دهد. `insert`، `get`، `has_ind` و `size` همگی با یک نقشه‌ی void کنار می‌آیند: `#FMAP{K,T}` void است و درج کردن در آن، اولین بار یک نقشه را پدید می‌آورد. اما `copy` این‌طور نیست.

`HMAP` و `HSET` نسخه‌هایی هستند که همیشه فقط در جای خودشان تغییر می‌کنند. برای ساختن ساختارهای بزرگ سریع‌ترند، اما در حین یادگیری پیش‌فرض نادرستی هستند.

## پیمایش یک نقشه یا یک مجموعه

| پیمایشگر | خروجی |
| --- | --- |
| `m.ind!` | هر کلید |
| `m.target!` | هر هدف |
| `m.pair!` | هر کلید و هدف با هم |
| `s.elt!` | هر مقدار از یک مجموعه |

نه نقشه ترتیبی دارد و نه مجموعه. ممکن است دو بار اجرا، آن‌ها را به شکل متفاوتی پیمایش کند، پس هرگز کدی ننویسید که به ترتیب پیمایش وابسته باشد.

```sather
   loop
      #OUT + guide.ind! + "\n";
   end;
```
