## تاریخچه‌ای بسیار کوتاه

پردازش نویسه‌ها در رایانه در دهه‌های پیشین بسیار ساده‌تر بود، زمانی که برنامه‌نویسان گمان می‌کردند انگلیسی تنها زبان مهم است.
یعنی: ۲۶ حرف، بزرگ و کوچک، ۱۰ رقم، چند نشانه‌ی سجاوندی، به‌علاوه یک کد (0x07) برای به صدا درآوردن زنگ، و همه‌ی این‌ها در ۷ بیت جا می‌شد: مجموعه‌نویسه‌ی ASCII.

طبیعتاً مردم شروع کردند به پرسیدن درباره‌ی à، ä و Ł، بعد افراد دیگری درباره‌ی ऄ، ஹ و ญ پرسیدند و جوان‌ها ایموجی 😱 می‌خواستند.
چه باید کرد؟

خلاصه‌ی ماجرا اینکه افراد باهوش و شکیبای زیادی باید سال‌ها در کمیته‌ها خدمت می‌کردند و جزئیات مجموعه‌نویسه‌ی Unicode و کدگذاری‌هایی مثل UTF-8 را مشخص می‌کردند و نرم‌افزارهای زیادی به بازنویسی _بسیار_ پیچیده‌ای نیاز داشتند.
همچنین Bugهای جدید زیادی به وجود آمد.

برای اینکه _همه‌چیز_ از کار نیفتد، طراحی Unicode/UTF-8 تضمین می‌کند که ۱۲۷ کد اول با ASCII یکسان باشند _(حتی زنگ)_.

## نویسه‌ها در Julia

زبان‌هایی که پس از حدود ۲۰۰۵ طراحی شده‌اند این مزیت بزرگ را دارند که استاندارد Unicode نسبتاً پایداری از قبل وجود داشته است.

Julia (اولین انتشار در ۲۰۱۲) می‌توانست فرض کند که همه‌چیز Unicode خواهد بود: نویسه‌ها، رشته‌ها، اسم متغیرها و توابع، عملگرهای ریاضی...

به نقل از کتابچه‌ی راهنما، «Julia کار با متن ASCII ساده را ساده و کارآمد می‌کند و مدیریت Unicode تا حد ممکن ساده و کارآمد است.»
به «تا حد ممکن» دقت کنید، این بخش مهمی از این جمله است.

***لیترال‌های نویسه با کوتیشن تک نوشته می‌شوند و با رشته‌هایی که با کوتیشن دوگانه نوشته می‌شوند فرق دارند.***

این برای کسانی که از دنیای C/C++ می‌آیند واضح است، اما می‌تواند برای برنامه‌نویسان Python و Javascript گیج‌کننده باشد.

```julia-repl
julia> a = 'a'  # Roman alphabet
'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)

julia> typeof(a)
Char

julia> jha = 'झ'  # Devanagari alphabet
'झ': Unicode U+091D (category Lo: Letter, other)

julia> typeof(jha)
Char

julia> '❤'  # heart emoji
'❤': Unicode U+2764 (category So: Symbol, other)
```

از این مثال‌ها می‌بینیم که نوع `Char` است و Julia اطلاعات بیشتری درباره‌ی دسته‌ی نویسه دارد.

اگر دقیق‌تر نگاه کنیم، به نظر می‌رسد این نویسه‌ها را می‌توان با ۴ رقم هگزادسیمال نشان داد.
مجموعه‌نویسه‌ی کامل به حداکثر ۶ رقم هگز نیاز دارد.

به این عددها «نقطه‌ی کد» می‌گویند و در حال حاضر از U+0000 تا U+10FFFF را در بر می‌گیرند.
این‌ها در REPL نمایش داده می‌شوند، اما در code برای به‌دست آوردنشان از `codepoints()` استفاده کنید.

تبدیل میان `Char` و `Int` ساده است:

```julia-repl
julia> Int('a')
97

julia> Char(97)
'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
```

کامپایلر _برخی_ شکل‌های حساب عدد صحیح روی `Char`ها را مجاز می‌داند:

```julia-repl
julia> 'b' - 'a'  # interval, in alphabetic order
1

julia> 'b' + 'a'
ERROR: MethodError: no method matching +(::Char, ::Char)

julia> 'a' + 5
'f': ASCII/Unicode U+0066 (category Ll: Letter, lowercase)

julia> 'f' + ('A' - 'a')  # same as `uppercase('f')`
'F': ASCII/Unicode U+0046 (category Lu: Letter, uppercase)
```

## توابع برای نویسه‌ها

بسیاری از توابع کار با رشته روی ورودی `Char` هم کار می‌کنند.

- برای الفباهای مناسب، با `uppercase()` و `lowercase()` حالت حرف را تغییر دهید.
- حالت حرف را با `isuppercase()` و `islowercase()` بررسی کنید.
- نوع نویسه را با این‌ها بررسی کنید:
  - `isletter()` بسیاری از الفباها را پوشش می‌دهد
  - `isdigit()`، فقط برای 0:9 آزمایش می‌کند
  - `isnumeric()`، گسترده‌تر از `isdigit`، پس برای ¾ و خطوط غیراروپایی مختلف `true` است
  - `isxdigit()`، رقم‌های هگزادسیمال
  - `isascii()`، نویسه‌ی پیش از Unicode
  - `ispunct()`، نشانه‌ی سجاوندی
  - `isspace()`، هر نویسه‌ی فاصله
  - `isprint()`، نویسه‌های چاپ‌شدنی (مخالفش `iscntrl()` است)

```julia
islowercase('A')  # false
uppercase('γ')  # 'Γ': Unicode U+0393 (category Lu: Letter, uppercase)
ispunct('@')  # true
isdigit('A')  # false
isxdigit('A')  # true
```

## تبدیل‌های متقابل بردار Char و رشته

برای تبدیل رشته به بردار Char می‌توان از `collect()` استفاده کرد.

برای تبدیل بردار Char به رشته، سازنده‌ی `String()` وجود دارد.

```julia-repl
julia> s = "abcde"
"abcde"

julia> cv = collect(s)
5-element Vector{Char}:
 'a': ASCII/Unicode U+0061 (category Ll: Letter, lowercase)
 'b': ASCII/Unicode U+0062 (category Ll: Letter, lowercase)
 'c': ASCII/Unicode U+0063 (category Ll: Letter, lowercase)
 'd': ASCII/Unicode U+0064 (category Ll: Letter, lowercase)
 'e': ASCII/Unicode U+0065 (category Ll: Letter, lowercase)

julia> String(cv)
"abcde"
```

این کار با هر نویسه‌ای انجام می‌شود، نه فقط ASCII.

```julia-repl
julia> collect("❤,😱")
3-element Vector{Char}:
 '❤': Unicode U+2764 (category So: Symbol, other)
 ',': ASCII/Unicode U+002C (category Po: Punctuation, other)
 '😱': Unicode U+1F631 (category So: Symbol, other)
```

دقت کنید که سازنده‌ی `String()` روی یک بردار کار می‌کند.
برای _تبدیل کردن_ یک `Char` تنها به رشته‌ای یک‌نویسه‌ای، تابع `string()` است، با `s` کوچک.

```julia-repl
julia> string('a')
"a"
```

## ذخیره‌سازی

تا اینجای این نوشته همه‌چیز نسبتاً ساده به نظر می‌رسد، پس واقعاً نگرانی چندانی وجود ندارد؟

متأسفانه این خوش‌بینی بیش از حد است!

یک پیچیدگی از نیاز به «حداکثر» ۶ رقم هگز برای هر نقطه‌ی کد ناشی می‌شود.
این یعنی نویسه‌های مختلف هنگام کدگذاری UTF-8 به مقدارهای متفاوتی فضا در حافظه نیاز دارند.

یک بایت فقط می‌تواند عددهای (بدون علامت) تا ۲۵۵ را ذخیره کند، یعنی دو رقم هگز، بنابراین UTF-8 برای ذخیره‌ی یک `Char` از تعداد متغیری بایت (۱ تا ۴) استفاده می‌کند.
به این‌ها «واحد کد» می‌گویند و تابع `ncodeunits()` تعداد لازم برای یک نویسه‌ی داده‌شده را برمی‌گرداند.

```julia-repl
julia> codepoint(jha)  # jha 'झ' is defined in an earlier example
0x0000091d

julia> ncodeunits(jha)
3

julia> ncodeunits('a')  # ASCII character
1

julia> ncodeunits('😱')  # emoji
4
```

همچنین، همه‌ی آنچه روی صفحه نمایش داده می‌شود نقطه‌ی کد یکتای خودش را ندارد.
برخی نویسه‌ها که از نظر ظاهری متفاوت‌اند، برگرفته از نویسه‌های دیگر در نظر گرفته می‌شوند، بنابراین Unicode آن‌ها را به‌صورت یک نویسه‌ی والد به‌همراه یک اصلاح‌کننده در نظر می‌گیرد.
