# دستورالعمل‌ها

مدیریت کم‌کم دارد اصول داروینی را روی پروژه‌ی ماشین کنترل از راه دور اعمال می‌کند.
توسعه‌دهندگان به دو تیم _Red_ و _Blue_ تقسیم شده‌اند و وظیفه دارند طراحی را مستقل از یکدیگر بهبود دهند.
لازم نیست خودشان را درگیر تصمیم‌های طراحی تیم دیگر کنند.
از شما خواسته شده است نگاهی به Code بیندازید و ببینید چگونه می‌توانید این دو تلاش را برای اهداف Test به بهترین شکل با هم ترکیب کنید.

## 1. روش مناسب‌تری برای جدا کردن Code دو تیم پیدا کنید

لطفاً از ماژول استفاده کنید تا منظور Code را بهتر بیان کنید.

در حال حاضر نوع‌های مهمی مثل `Motor` و `Telemetry` و حتی خودِ `RemoteControlCar` با رنگ تیم مربوطه پیشوند می‌گیرند: `<Color>RemoteControlCarTeam`.
تنها هدف این پیشوند این است که نوع‌هایی با اسم یکسان بتوانند در برنامه در کنار هم وجود داشته باشند.
استفاده از ماژول این موضوع را بهتر بیان می‌کند.
خواهید دید که برای این منظور، ماژول مزایایی نسبت به پیشوند کردن نوع‌ها دارد.

## 2. سیستم اسم‌گذاری را ساده کنید

مدیریت الزام کرده است که اسم تیم‌ها در تعریف‌ها «Red Remote Control Car Team» و «Blue Remote Control Car Team» باشد و این اسم‌های طولانی حتی در خود Code نیز به کار روند.
اما ارجاع دادن به تیم‌ها با این اسم‌ها تا حدی دست‌وپاگیر است.

راهی پیدا کنید که در همان ماژولی که ماشین‌ها را در آن خواهید ساخت، از شناسه‌های کوتاه‌تر «Red» و «Blue» استفاده کنید.
