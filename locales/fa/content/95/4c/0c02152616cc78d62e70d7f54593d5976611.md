# مقدمه

«تاپل»ها می‌توانند تاپل‌های دیگر را گسترش دهند. دستور `TUPLE: child < parent slots ;` کلاسی را اعلان می‌کند که نمونه‌هایش هم نمونه‌های `parent` به شمار می‌آیند؛ چنین نمونه‌ای علاوه بر «اسلات»های خودش، اسلات‌های والد را هم دارد و «اکسسور»های والد هم روی آن کار می‌کنند، درست همان‌طور که اگر روی خود فرزند تعریف شده باشند.

```factor
USING: accessors ;

TUPLE: animal name age ;
TUPLE: dog < animal breed ;

"Rex" 4 "labrador" dog boa .
! => T{ dog { name "Rex" } { age 4 } { breed "labrador" } }

"Rex" 4 "labrador" dog boa name>> .   ! => "Rex"   (inherited accessor)
```

## ترتیب اسلات‌ها در `boa`

سازنده‌ی `boa` اسلات‌ها را به *ترتیب اعلان، اول والدها* می‌گیرد. برای `dog` بالا:

```
dog boa ( name age breed -- dog )
```

نوه‌ی `puppy < dog ` که `weeks` را اضافه کند، چنین می‌شود:

```
puppy boa ( name age breed weeks -- puppy )
```

## سلسله‌مراتب محمول

هر اعلان `TUPLE:` یک «محمول» تولید می‌کند (`name?`).
با وراثت، محمول‌ها تودرتو می‌شوند: هر فرزند، محمول‌های نیاکانش را برآورده می‌کند:

```factor
"Rex" 4 "labrador" dog boa
dup dog? .        ! => t
dup animal? .     ! => t
```

عکسش درست نیست: یک `animal` که `dog` نباشد، محمول `dog?` را برآورده نمی‌کند.

## نکته‌ای درباره‌ی ادامه

«متدهای عمومی» (همان `M:` که در [`generics`][generics] آموزش داده می‌شود) هم به سمت بالای سلسله‌مراتب اعزام می‌شوند؛ یعنی متدی که روی `animal` تعریف شده باشد، برای هر فرزندی اجرا می‌شود، مگر اینکه بازنویسی خاص‌تری اولویت بگیرد. این را بلافاصله پس از این تمرین در `boatswains-bilge` خواهید دید.

[generics]: https://docs.factorcode.org/content/article-generic.html
