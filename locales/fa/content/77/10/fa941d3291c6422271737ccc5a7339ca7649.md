# ضمیمه‌ی دستورالعمل‌ها

## فرایند IO

برخلاف تمرین‌های دیگر، `grep` نیازمند تعامل با «دنیای بیرونی» است: خواندن فایل‌ها، مدیریت خطاهای سیستمی و چاپ در `stdout`.

در Lean، تعامل با سیستم معمولاً در موناد [IO][io] انجام می‌شود، که اجازه می‌دهد عوارض جانبی در محیطی محدود رخ دهند بدون آنکه وضعیت خالص بیشتر توابع دیگر را تحت تأثیر قرار دهند.

## خواندن آرگومان‌ها

Lean اجازه می‌دهد یک فایل به‌عنوان اسکریپت فراخوانی شود، چه مستقیم به‌صورت یک اسکریپت مستقل با `lean --run` و چه با استفاده از `lake`.

یک پروژه‌ی Lean یک نقطه‌ی ورود دارد، تابعی به اسم `main` که یک `List String` با همه‌ی آرگومان‌های ارسال‌شده به آن می‌گیرد.
برای شبیه‌سازی اجرای `Grep.lean` به‌عنوان یک فایل اجرایی، در این تمرین آرگومان‌ها به همین شکل ارسال می‌شوند.

## خواندن فایل‌ها

Lean [توابعی][files] برای کار با فایل‌ها در موناد `IO.FS` ارائه می‌دهد.
برای مثال، می‌توان از `IO.FS.readFile` استفاده کرد تا محتوای فایلی در یک مسیر مشخص را به‌صورت یک `String` بخواند.

## نوشتن خروجی

این تمرین به‌جای برگرداندن یک مقدار، نوشتن نتایج در خروجی استاندارد یا خطای استاندارد را لازم می‌داند.
[توابعی][console] در Lean برای این منظور وجود دارد.

## مدیریت خطاهای سیستمی

برخلاف خطاها در `Except`، استثناهای `IO` در واقع استثناهای زمان اجرا هستند.
می‌توانید از `try`/`catch` برای مدیریت آن‌ها استفاده کنید:

```
try
    /- 
        code that may possibly raise an exception 
    -/
catch msg =>
    /-
        code that is executed only if an exception was thrown
    -/
```
