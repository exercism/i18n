# مقدمه‌ای بر نوع جنریک

یک **«نوع جنریک»** یک کلاس یا اینترفیس جنریک است که روی نوع‌ها پارامتربندی می‌شود. این کار به کامپایلر اجازه می‌دهد ایمنی نوع را روی کلاس یا اینترفیس اعمال کند.

به این اینترفیس `Container` که جنریک نیست نگاه کنید:

```java
class Container {
    private Object object;

    public void set(Object object) { this.object = object; }
    public Object get() { return object; }
}
```

از آنجا که انواع `Object` را می‌پذیرد و برمی‌گرداند، با هر نوع غیر اولیه‌ای کار می‌کند. اما این کار هزینه دارد، چون ممکن است بخشی از کد `get` را فراخوانی کند و انتظار `Integer` داشته باشد، در حالی که بخش دیگری `set` را فراخوانی می‌کند و `String` اضافه می‌کند، که به خطای زمان اجرا می‌انجامد.

یک **کلاس جنریک** و یک **اینترفیس جنریک** قالب‌های زیر را دارند:

```java
class ClassName<T1, T2, ..., Tn> { ... }
interface InterfaceName<T1, T2, ..., Tn> { ... }
```

بخش پارامترهای نوع که با براکت‌های زاویه‌دار (`<>`) مشخص می‌شود و پس از اسم کلاس یا اینترفیس می‌آید، پارامترهای نوع (که به آن‌ها «متغیرهای نوع» هم می‌گویند) یعنی `T1`، `T2`، ... و `Tn` را تعیین می‌کند. می‌توان از این‌ها در بدنه‌ی کلاس یا اینترفیس استفاده کرد تا ایمنی نوع جنریک به دست آید.

این هم نسخه‌ی جنریک `Container` است:

```java
class Container<E> {
    private E object;

    public void set(E object) { this.object = object; }
    public E get() { return object; }
}
```

وقتی نمونه ساخته می‌شود، باید اعلام کنیم که چه نوعی را در خود نگه می‌دارد و کامپایلر همان محدودیت را اعمال می‌کند:

```java
// empty <> can infer from context
Container<String> stringContainer = new Container<>();
// compiler knows this is a String, so it is allowed
stringContainer.set("Some string");
// no cast needed, compiler knows it is a String
String result = stringContainer.get();
// this causes a compiler error:
stringContainer.set(42);
```
