# درباره

بعید است به کد تولیدی زیادی بربخورید که از «فضای نام» استفاده نکند.

نمونه‌ای از نحوه‌ی نگارش چنین است:

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

فضای نام روشی است برای گروه‌بندی کدهای مرتبط و جلوگیری از تداخل اسم‌ها.

بر اساس [مستندات رسمی][namespaces]، فضای نام دو نقش اصلی دارد:

- نخست، .NET از فضای نام برای سازمان‌دهی کلاس‌های متعدد خود استفاده می‌کند.
- دوم، تعریف فضای نام‌های خودتان می‌تواند به شما کمک کند دامنه‌ی نام کلاس‌ها و متدها را در پروژه‌های برنامه‌نویسی بزرگ‌تر کنترل کنید.

کتابخانه‌ی کلاس پایه (BCL) به‌طور گسترده از فضای نام برای سازمان‌دهی قابلیت‌های خود استفاده می‌کند.

## ارجاع به انواع درون فضای نام

به انواعی که درون فضای نام قرار دارند، از بیرون فضای نام با قرار دادن فضای نام و یک نقطه پیش از نام نوع ارجاع داده می‌شود. در روشی جایگزین، و معمول‌تر، می‌توانید یک دستور `using` را در بالای فایل (یا درون یک فضای نام) قرار دهید؛ آن‌گاه هر نوعی در فضای نام واردشده را می‌توان بدون پیشوند به کار برد. درون خود یک فضای نام، نیازی به کامل کردن نام انواع نیست.

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

این [مقاله][using] به‌روشنی روش‌هایی را توضیح می‌دهد که می‌توان از دستور `using` استفاده کرد:

- `using`: پرهیز از نیاز به کامل کردن انواع با فضای نام
- `using static`: پرهیز از نیاز به کامل کردن اعضا با انواع (نمونه‌ی خوبی از آن `Math.Max()` است).
- `using MyAlias = YourNamespace;`: جایگزین کردن نامی خواناتر برای نام فضای نام.

## تداخل فضاهای نام

.NET مسئله‌ی وجود دو فضای نام با نام یکسان در اسمبلی‌های مختلف را، آنجا که تداخلی میان نام شناسه‌های کاملاً مشخص پیش می‌آید، حل می‌کند (شاید سناریویی که در آن چند نسخه از یک اسمبلی بارگذاری می‌شوند). این مسئله با [مشخص‌کننده‌ی نام مستعار فضای نام][namespace-alias-qualifier] و [نام مستعار خارجی][extern-alias] حل می‌شود.

یکی از دلایل مطرح کردن این موضوع نسبتاً خاص، استفاده‌ی آن از [عملگر `::`][dot-dot-operator] است. اغلب خواهید دید که مشخص‌کننده‌ی `global::` به‌عنوان پیشوند فضاهای نام می‌آید، به‌ویژه در کد تولیدشده. منظور در اینجا پرهیز از یک تداخل بالقوه با برخی فضای نام تودرتو یا نام کلاس است. با پیشوند کردن یک فضای نام با `global::` مطمئن می‌شوید که یک فضای نام سطح بالا انتخاب می‌شود.

## نکته‌ای برای توسعه‌دهندگان Java

هنگام مقایسه با `import` در `packages`های Java، باید به تفاوت‌ها و شباهت‌هایی توجه کرد:

- در C# معادلی برای وارد کردن انواع مشخص وجود ندارد.
- `using static` و `import static` معادل هم هستند.
- در Java، نام بسته‌ها بر سطح دسترسی میان jarها تأثیر می‌گذارد. در C#، اسمبلی‌ها اهمیت اصلی را دارند و تعلق داشتن به یک فضای نام یکسان بر سطح دسترسی اثری ندارد.
- رابطه‌ی میان مسیرهای سیستم فایل و نام‌های کاملاً مشخص کلاس‌ها در Java در فضای نام C# بازتاب نمی‌یابد، هرچند که در جایی که ممکن باشد، دادن نام یکسان به یک فایل و کلاس اصلی درون آن، روش خوبی است.
