# آشنایی با شرط‌ها

## درست و غلط در Bash

Bash مفهوم مقادیر «منطقی» را ندارد.
فقط رشته‌ها و اعداد وجود دارند و آرایه‌هایی از رشته‌ها یا اعداد.
حالا دستورهای شرطی چطور با «درست» و «غلط» برخورد می‌کنند؟

## وضعیت خروج

دستورها وقتی به پایان می‌رسند یک _وضعیت خروج_ تولید می‌کنند.
وضعیت خروج یک عدد صحیح بین ۰ تا ۲۵۵ است (شامل هر دو سر).
Bash وضعیت خروج **صفر** را نشانه‌ی _موفقیت_ می‌داند.
هر وضعیت خروج دیگری نشانه‌ی _شکست_ است.

این موضوع برای همه‌ی دستورها صادق است، از جمله دستورهای توکار bash، کلیدواژه‌ها و توابع.

## دستور `if`

نحوه‌ی نگارش پایه‌ی دستور `if` این‌گونه است

```bash
if CONDITIONAL_COMMANDS; then TRUE_COMMANDS; else FALSE_COMMANDS; fi
```

با `if` شروع می‌شود؛ دستورهای شرط با `then` از دستورهای «موفقیت» جدا می‌شوند و با `fi` پایان می‌یابد.
بخش `else` اختیاری است.

CONDITIONAL_COMMANDS می‌تواند یک دستور تکی باشد یا یک [فهرست از دستورها][command-list].

CONDITIONAL_COMMANDS اجرا می‌شوند و

* اگر وضعیت خروج صفر باشد (موفقیت)، آن‌گاه TRUE_COMMANDS اجرا می‌شوند.
* اگر وضعیت خروج مخالف صفر باشد (شکست)، آن‌گاه FALSE_COMMANDS اجرا می‌شوند، البته اگر وجود داشته باشند.

شاخه‌های آبشاری را می‌توان با `elif` نوشت
```bash
if CONDITIONAL_COMMANDS
then TRUE_COMMANDS
elif CONDITIONAL_COMMANDS_2
then TRUE_COMMANDS_2
# more elif branches ...
else FALSE_COMMANDS
fi
```

قبل از کلمات `then`، `elif`، `else` و `fi` باید یک نقطه‌ویرگول یا یک خط جدید باشد.

برای تأکید: آنچه جریان اجرا را کنترل می‌کند، **وضعیت خروج** دستورهای شرطی است.
به‌عنوان مثال، `grep` در صورت پیدا شدن تطابق ۰ و در صورت پیدا نشدن تطابق ۱ برمی‌گرداند.
گزینه‌ی `-q` خروجی را چاپ نمی‌کند و تنها وضعیت خروج را تولید می‌کند.

```bash
if grep -q "my pattern" my_file; then echo "the pattern is found in the file"; fi
```

## دستورهای `[` و `test`

هیچ نحوه‌ی نگارش ویژه‌ای پیرامون CONDITIONAL_COMMANDS وجود ندارد.
شاید عادت داشته باشید دستورهای شرطی‌ای ببینید که این‌گونه به نظر می‌رسند:

```if
if [ "$password" = "secure" ]; then
    echo "Welcome!"
fi
```

`[` نحوه‌ی نگارش ویژه‌ای نیست.
یک _دستور_ است که عبارت شرطی را ارزیابی می‌کند و با وضعیت موفقیت یا شکست خارج می‌شود.
مانند همه‌ی دستورها، فاصله میان آن و آرگومان‌هایش **الزامی** است.

`[` در واقع مترادف دستور `test` است.
این دو دقیقاً یکسان‌اند، فقط با این تفاوت که آخرین آرگومان `[` _باید_ `]` باشد.

### عبارت‌های شرطی

درون `[` و `]` یک عبارت شرطی می‌نویسید.
برخی از عبارت‌های شرطی رایج عبارت‌اند از:

```bash
[ -f "$filename" ]             # file operations
[ "$string1" = "$string2" ]    # string comparisons
[ "$num1" -eq "$num2" ]        # arithmetic comparisons
```

عملگرهای بسیار بیشتری هم در دسترس است؛ آن‌ها در بخش [عبارت‌های شرطی Bash][cond-expr] در دفترچه‌ی راهنما فهرست شده‌اند.

~~~~exercism/note
در مثال‌های بالا دقت کنید که همه‌ی متغیرها در گیومه گذاشته شده‌اند.
دستورهای `test` و `[` دستورهای معمولی‌اند و آرگومان‌هایشان مثل هر دستور دیگری در معرض جداسازی کلمات و بسط نام فایل قرار می‌گیرند.

اشاره به این نکته مهم است، چون عبارت‌های شرطی بر اساس _تعداد آرگومان‌هایی_ که می‌دهید متفاوت ارزیابی می‌شوند:

* ۰ آرگومان: وضعیت خروج مخالف صفر است (شکست)
* ۱ آرگومان: اگر آرگومان خالی نباشد وضعیت خروج صفر است (موفقیت) و اگر خالی باشد مخالف صفر.
* ۲ آرگومان: آرگومان اول باید یک عملگر یکانی باشد (مانند `[ -z "$name" ]`) یا یک `!` (که وضعیت آزمون ۱ آرگومانی را نقیض می‌کند)
* و [موارد بیشتر][test].

اگر گیومه‌گذاری را فراموش کنید ممکن است نتایج غیرمنتظره‌ای بگیرید:

```bash
str=""

# this prints "empty"
if [ -n "$str" ]; then echo "not empty"; else echo "empty"; fi

# leaving the variable unquoted results in incorrect "not empty" output
if [ -n $str ]; then echo "not empty"; else echo "empty"; fi
```

[test]: https://www.gnu.org/software/bash/manual/bash.html#index-test
~~~~

## کلیدواژه‌ی `[[`

ساختار شرطی [`[[...]]`][cond-construct] یک _دستور_ نیست، بلکه یک **کلیدواژه** است.
یعنی با آن‌که مانند هر دستور دیگری پردازش می‌شود، قواعد تجزیه‌ی ویژه‌ای دارد.
نکته‌ی ویژه درباره‌ی `[[` این است که متغیرهای بسط‌یافته درون آن **تحت** تأثیر جداسازی کلمات یا بسط نام فایل قرار نمی‌گیرند.
این یعنی این دستور همان‌طور که انتظار دارید عمل می‌کند، حتی بدون گیومه‌گذاری.

```bash
if [[ -n $str ]]; then echo "not empty"; else echo "empty"; fi
```

`[[` از همه‌ی عبارت‌های شرطی‌ای که `test` و `[` می‌توانند پردازش کنند پشتیبانی می‌کند.
علاوه بر این، `[[` موارد زیر را فراهم می‌کند

* عملگر تطبیق با عبارت باقاعده `=~`،
* `==` و `!=` به‌عنوان عملگر تطبیق الگوی glob،
* `&&` و `||` به‌عنوان عملگرهای منطقی (قاعده‌ی تجزیه‌ی ویژه)،
* `<` و `>` به‌عنوان عملگرهای مقایسه‌ی رشته‌ای «خالی» (قاعده‌ی تجزیه‌ی ویژه: چون این‌ها نمادهای تغییرمسیر هستند، در `[` باید escape شوند).

عقیده‌ی رایجی است که این ویژگی‌های ویژه چنان سود زیادی دارند که باید منحصراً از `[[` استفاده کرد.
(برای مثال، [راهنمای سبک نگارش شل گوگل][goog-test].)

## دستور `case`

[`case`][case] یکی دیگر از دستورهای جریان کنترل است.
مانند دستور `switch` در زبان‌های دیگر است.

```bash
case WORD in [PATTERN [| PATTERN]...) COMMANDS ;;]... esac
```

WORD با هر PATTERN مطابقت داده می‌شود.
وقتی یکی مطابقت پیدا کند، COMMANDS اجرا می‌شوند.

```bash
read -p "Guess the secret word: " word
case "$word" in
    secret) echo "Yes, you guessed it!" ;;
    ??????) echo "That's the right number of letters." ;;
    s*)     echo "You guessed the first letter." ;;
    *)      echo "Not even close! Try again." ;;
esac
```

هر بند COMMANDS باید با **دو** نقطه‌ویرگول، `;;`، پایان یابد.
