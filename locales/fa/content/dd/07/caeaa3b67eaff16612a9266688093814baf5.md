# درباره

## مقدمه

«جنریک» یک ویژگی زبانی است که استفاده‌ی مجدد از کد را ممکن می‌کند.
برای مثال، برای محاسبه‌ی طول یک فهرست نباید مهم باشد که آن فهرست چه نوعی را نگه می‌دارد.
به همین دلیل هم تابع `length` در امضای نوع خود از یک «پارامتر نوع» جنریک به اسم `a` استفاده می‌کند.

```elm
length : List a -> Int
```

## پارامترها در نوع‌ها

وقتی یک نوع نسبت به نوعی دیگر جنریک است، برای آن نوع دیگر از اسمی با حروف کوچک استفاده می‌کنیم و آن را پارامتر نوع می‌نامیم.
نمونه‌های رایج، «نوع‌های سفارشی» `List`، `Maybe` و `Result` هستند.

```elm
-- Maybe is generic over the type a
type Maybe a
    = Nothing
    | Just a

someString : Maybe String
someString = Just "hello"

someInt : Maybe Int
someInt = Just 42
```

یک نکته‌ی مهم درباره‌ی اسم پارامترهای نوع این است که طولشان می‌تواند چند نویسه باشد.
تنها محدودیت این است که باید اسم‌هایی با حروف کوچک باشند.
به همین دلیل، هر جا مفید باشد، معمولاً اسم‌هایی توصیفی برایشان انتخاب می‌کنیم.

یک نوع می‌تواند نسبت به چند نوع دیگر جنریک باشد و بنابراین چند پارامتر نوع داشته باشد.
در این حالت، هر نوع مستقل اسمی متفاوت با حروف کوچک می‌گیرد.
مستقل بودنشان مانع یکی شدنشان نمی‌شود، فقط این امکان را می‌دهد که متفاوت باشند.

```elm
-- Result is generic over the types error and value
type Result error value
    = Ok value
    | Err error
```

نام‌های مستعار نوع رکورد هم می‌توانند پارامتر نوع داشته باشند، هرچند این کار کمتر رایج است.

```elm
-- Event is generic over the type a
type alias Event a =
    { at : Time
    , data : a 
    }
```

> به همین دلیل است که بسته‌ی `Html` نوع `Html msg` را تعریف می‌کند، با یک پارامتر نوع به اسم `msg`.
> معماری Elm شما را به سمت ساختن یک نوع سفارشی `Msg` هدایت می‌کند که همه‌ی پیام‌هایی را توصیف می‌کند که صفحه‌ی وب شما می‌تواند ایجاد کند.
> در نتیجه، کد شما نماهایی از نوع `Html Msg` می‌سازد که در آن `Msg` همان نوع مشخصی است که خودتان تعریف کرده‌اید.
> تازه‌کارها گاهی بین خطاهایی که به `Html msg` (با حروف کوچک) اشاره می‌کنند و خطاهای `Html Msg` سردرگم می‌شوند.
> حالا دیگر می‌دانید!
> تفاوت این است که اولی نسبت به هر نوع `msg` جنریک است، در حالی که دومی مخصوص نوع `Msg` شماست.

## پارامترهای نوع در توابع

از آنجا که نوع‌ها می‌توانند جنریک باشند، توابع هم می‌توانند.
می‌توان توابعی نوشت که با نوع‌های جنریک کار می‌کنند، مانند `Maybe.withDefault`.

```elm
withDefault : a -> Maybe a -> a
withDefault default maybe =
    case maybe of
      Just value -> value
      Nothing -> default
```

به توابعی که توابع دیگر را به عنوان پارامتر می‌گیرند، «توابع مرتبه‌بالا» می‌گویند و این توابع هم می‌توانند جنریک باشند.

```elm
map : (a -> b) -> Maybe a -> Maybe b
map function maybe =
  case maybe of
    Just value ->
      Just (function value)

    Nothing ->
      Nothing
```

پارامترهای نوع می‌توانند هم در ورودی‌ها و هم در خروجی یک تابع ظاهر شوند و به جنریک بودنِ حاصل از پارامترهای نوع، معمولاً **چندریختی پارامتری** می‌گویند.
این با «چندریختی موردی»، که به «سربارگذاری تابع» هم شناخته می‌شود، در تضاد است؛ در آنجا از یک اسم تابع یکسان می‌توان در چند پیاده‌سازی مختلف که نوع‌هایشان فرق می‌کند استفاده کرد.
همچنین با «چندریختی زیرگونه‌ای» در تضاد است؛ در آنجا نوع‌ها را می‌توان در یک سلسله‌مراتب تعریف کرد و می‌توان توابعی را که روی یک نوع تعریف شده‌اند با آرگومان‌هایی از زیرگونه‌های آن هم فراخوانی کرد.
در Elm، تنها سازوکار موجود برای جنریک بودن، چندریختی پارامتری است.
