# مقدمه

اشاره‌گرهای هوشمند یکی از ویژگی‌های مدرن C++ هستند که برای فراهم کردن مدیریت خودکار حافظه طراحی شده‌اند و به جلوگیری از نشت حافظه و اشاره‌گرهای معلقی که معمولاً با اشاره‌گرهای خام همراه‌اند کمک می‌کنند.
آنها به‌عنوان پوششی دور اشاره‌گرهای خام عمل می‌کنند و قابلیت‌های بیشتری مانند آزادسازی خودکار حافظه را، وقتی دیگر به اشاره‌گر نیازی نیست، اضافه می‌کنند.

## نحوه‌ی نگارش کلی

اشاره‌گرهای هوشمند معمولاً به‌صورت قالب‌های کلاس در کتابخانه‌ی استاندارد C++ پیاده‌سازی می‌شوند.
دو مورد از پرکاربردترین اشاره‌گرهای هوشمند `std::unique_ptr` و `std::shared_ptr` هستند.

## اشاره‌گرهای یکتا

`std::unique_ptr` یک اشاره‌گر هوشمند است که مالکیت شیء را به‌صورت انحصاری در اختیار دارد.
این اشاره‌گر تضمین می‌کند که در هر لحظه فقط یک شیء `std::unique_ptr` مالک منبع باشد.
وقتی `std::unique_ptr` مالک نابود یا بازنشانی شود، به‌طور خودکار اشیاء را از بین می‌برد و حافظه‌ی آن‌ها را آزاد می‌کند.

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## مزایای `std::make_unique()`

هنگام ساخت یک `std::unique_ptr`، بهتر است به‌جای استفاده‌ی مستقیم از `new` برای تخصیص حافظه، از `std::make_unique()` استفاده کنید.
`std::make_unique()` چندین مزیت دارد:
1. **ایمنی در برابر استثنا**: `std::make_unique()` ایمنی در برابر استثنا را تضمین می‌کند.
  اگر در حین ساخت شیء استثنایی پرتاب شود، حافظه به‌طور خودکار آزاد می‌شود و از نشت حافظه جلوگیری می‌شود.
2. **وضوح**: استفاده از `std::make_unique()` کد را واضح‌تر و مختصرتر می‌کند.
  دیگر نیازی نیست نوعی که تخصیص داده می‌شود را صریحاً مشخص کنید، چون آرگومان‌های قالب به‌طور خودکار استنتاج می‌شوند.
3. **فرصت‌های بهینه‌سازی**: کامپایلرها می‌توانند `std::make_unique()` را مؤثرتر از تخصیص دستی حافظه با `new` بهینه کنند و این می‌تواند به بهبود عملکرد منجر شود.
4. **پرهیز از استفاده‌ی نادرست**: وقتی `std::unique_ptr` به‌صورت دستی ساخته شود، حذف منبع زیربنایی امکان‌پذیر است.
  این کار وقتی `std::unique_ptr` بخواهد در پایان دامنه‌ی خود آن را حذف کند، به رفتار تعریف‌نشده منجر می‌شود.

## اشاره‌گرهای اشتراکی

`std::shared_ptr` یک اشاره‌گر هوشمند است که به چندین شیء `std::shared_ptr` اجازه می‌دهد مالکیت یک منبع یکسان را به اشتراک بگذارند.
این اشاره‌گر پیگیری می‌کند که چند اشاره‌گر اشتراکی به منبع ارجاع می‌دهند و حافظه را فقط زمانی آزاد می‌کند که آخرین اشاره‌گر اشتراکی مالک منبع از دامنه خارج شود یا بازنشانی گردد.

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

~~~~exercism/caution
در C++17 و پایین‌تر، استفاده از `std::shared_ptr` با آرایه‌ها از طریق `std::make_shared<T[]>` به‌طور مستقیم پشتیبانی نمی‌شود.
هرچند تخصیص آرایه‌ها با `std::make_shared<T[]>` امکان‌پذیر است، ساختن اشاره‌گرهای اشتراکی مستقیماً از آن‌ها می‌تواند به دلیل تفاوت‌های مدیریت حافظه میان اشیاء منفرد و آرایه‌ها به رفتار تعریف‌نشده منجر شود.
در عوض، برای مدیریت مؤثر آرایه‌ها با اشاره‌گرهای اشتراکی، استفاده از `std::vector` یا توابع حذف سفارشی را در نظر بگیرید.
هنگام سر و کار داشتن با تخصیص آرایه‌ها و اشاره‌گرهای اشتراکی در C++17، همیشه سازگاری با کامپایلر و پیاده‌سازی کتابخانه‌ی استاندارد خود را تضمین کنید.
~~~~

## مزایای `std::make_shared()`

مشابه `std::make_unique()`، تابع `std::make_shared()` مزایایی مانند کارایی بهتر حافظه، ایمنی در برابر استثنا و خوانایی بیشتری ارائه می‌دهد.
این تابع تخصیص حافظه برای بلوک کنترل و شیء مدیریت‌شده را در یک عملیات ترکیب می‌کند و بدین ترتیب کارایی را بالا می‌برد و خطر نشت حافظه را کاهش می‌دهد.
علاوه بر این، استنتاج خودکار آرگومان‌های قالب کد را ساده‌تر و خواناتر می‌کند.
استفاده از `std::make_shared()` هنگام کار با اشیاء `std::shared_ptr` در C++ کدی تمیزتر، ایمن‌تر و کارآمدتر به همراه دارد.

## اشاره‌گرهای ضعیف

`std::weak_ptr` یک کلاس همراه برای `std::shared_ptr` است که یک ارجاع غیرمالکانه و «ضعیف» به شیئی فراهم می‌کند که توسط یک اشاره‌گر اشتراکی مدیریت می‌شود.

```cpp
// Creating a shared pointer
auto your_account = std::make_shared<std::string>("secret_subscription_password");
// Creating a shared pointer that shares ownership
auto your_flatmates_account = your_account;

// Creating a weak pointer from the shared pointer
auto your_flatmates_boyfriends_account = your_flatmates_account;
// if your_account and your_flatmates_account are deleted, there is no more reference to the shared pointer.
// your_flatmates_boyfriends_account will be a null pointer and cannot use the associated object any longer.
```

اشاره‌گرهای ضعیف در موقعیت‌هایی مفیدند که باید ارجاع‌های حلقه‌ای شکسته شوند تا از نشت حافظه جلوگیری شود.
`std::weak_ptr` برای رفع مسئله‌ی مالکیت حلقه‌ای طراحی شده است. به این مسئله ارجاع‌های دایره‌ای هم می‌گویند و می‌تواند هنگام استفاده از `std::shared_ptr` رخ دهد.
در سناریوی مالکیت حلقه‌ای، دو یا چند شیء `std::shared_ptr` به یکدیگر ارجاع می‌دهند و حلقه‌ای می‌سازند که در آن هیچ‌یک از اشیاء حذف نمی‌شود، چون ارجاع‌های قوی به هم دارند و این به نشت حافظه منجر می‌شود.
`std::weak_ptr` با اجازه دادن به ارجاع‌های ضعیف به اشیاء اشتراکی، بدون اینکه به شمارش ارجاع آن‌ها اضافه کند، راه‌حلی برای این مشکل ارائه می‌دهد.
یعنی می‌تواند شیء اشتراکی را مشاهده و به آن دسترسی پیدا کند، اما مانع حذف آن نمی‌شود.
~~~~

## توصیه‌ی استفاده

اشاره‌گرهای هوشمند را به‌طور پیش‌فرض به کار ببرید: `std::unique_ptr` برای مالکیت انحصاری و `std::shared_ptr` برای مالکیت اشتراکی.
اشاره‌گرهای خام را برای ارجاع‌های غیرمالکانه یا هنگام تعامل با کد قدیمی نگه دارید.
در بیشتر موارد، `std::unique_ptr` برای مالکیت انحصاری کافی است، چون مدیریت حافظه‌ی سبکی بدون سربار شمارش ارجاع ارائه می‌دهد.
`std::shared_ptr` را باید کم به کار برد، چون سربار و پیچیدگی می‌آورد، مگر آنکه واقعاً مالکیت اشتراکی لازم باشد.
`std::weak_ptr` برای شکستن وابستگی‌های حلقه‌ای یا مشاهده‌ی اشیاء اشتراکی تخصص یافته است، اما زیاد استفاده نمی‌شود.
