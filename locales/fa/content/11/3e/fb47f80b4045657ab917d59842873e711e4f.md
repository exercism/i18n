# مقدمه

در مفاهیم پیشین دیدیم که نوع‌ها در Julia یک سلسله‌مراتب تشکیل می‌دهند که `Any` در بالای آن قرار دارد.

نوع‌های انتزاعی مانند `Number` زیرنوع دارند، اما خودشان قابل نمونه‌سازی نیستند.
تعیین نوع انتزاعی برای یک متغیر، مقدارهای آن متغیر را _محدود_ می‌کند به اینکه هر زیرنوعی از آن نوع انتزاعی باشند.
برای مثال:

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

این به ما یک نوع انعطاف در محدود کردن ورودی‌های معتبر می‌دهد.

اما فرض کنید می‌خواهیم یک متغیر هم مقدارهای صحیح و هم مقدارهای رشته‌ای را بپذیرد؟
این نوع‌ها در یک شاخه از سلسله‌مراتب قرار ندارند.

می‌توانستیم نوع را `Any` بگذاریم، یا بگذاریم به‌طور پیش‌فرض همان باشد، اما در آن صورت کنترل همه‌ی نوع‌های مجاز را از دست می‌دهیم.

برای روشی بهتر، نحوه‌ی نگارش `Union{ }` را داریم که دو یا چند نوع درون آکولادها فهرست می‌شوند.

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

مثال دیگری از همان اتحاد نوع در امضای یک تابع استفاده می‌کند:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

اینجا به نوع یک اسم دادیم که می‌تواند کوتاه‌نویسی راحتی فراهم کند، اما کاملاً ضروری نیست.
تابع `g(z::Union{Integer, String}) = z^3` هم همین‌طور رفتار می‌کند.

درباره‌ی امضای تابع در مفهوم Multiple Dispatch بسیار بیشتر خواهیم گفت.

## اتحاد با `nothing`

چند زبان دیگر نوع‌هایی دارند که ممکن است مقدار داشته باشند یا نداشته باشند، با اسم‌هایی مانند `Option`، `Nullable` یا `Maybe`.

Julia نحوه‌ی نگارش خاصی برای این کار ندارد، اما اتحاد نوع تعمیمی از همان ایده است.

در مفهوم `Nothingness` دیدیم که Julia روش‌های مختلفی برای نمایش نبودِ مقدار دارد، از جمله `nothing` و `missing`.
هر کدام از این‌ها را می‌توان در یک اتحاد نوع گنجاند.

برای مثال، در تعریف نوعی لیست پیوندی، به روشی نیاز داریم تا اگر گره‌ی دیگری وجود ندارد، لیست را پایان دهیم.
`Nothing` نوعی است که مقدار یگانه‌اش `nothing` است، و این تعریف Node امکان نشانه‌گذاری پایان زنجیره را فراهم می‌کند:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

به‌طور مشابه، `missing` می‌تواند به‌عنوان جانگهدار مقدارهای ناموجود به کار رود، به‌ویژه در مجموعه‌هایی مانند بردارها.
مثال زیر خیلی ساختگی است، اما مقدارهای گمشده در مجموعه‌داده‌های دنیای واقعی رایج‌اند.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
