# درباره

این تمرین برنامه‌نویسی چند ویژگی پارامترها را نشان می‌دهد:

- پارامترهایی که بدون تغییردهنده (مانند `out` یا `ref`) [پاس داده می‌شوند][passing-parameters]، به‌صورت مقداری پاس داده می‌شوند. یعنی می‌توان از پارامتر در متد فراخوانی‌شده استفاده کرد و به آن مقدار نسبت داد، اما هیچ تغییری بر فراخوانی‌کننده اثر نمی‌گذارد.
- وقتی ارجاعی به یک آرایه یا نمونه‌ای از یک کلاس پارامتر باشد، متد فراخوانی‌شده می‌تواند عناصر/فیلدهای آن نمونه را تغییر دهد و فراخوانی‌کننده این تغییرات را می‌بیند. این موضوع مستقل از آن است که تغییردهنده‌ی `ref` حضور داشته باشد یا نه.
- پارامتری که تغییردهنده‌ی [`out`][out-parameter] را دارد، مقداری را از متد فراخوانی‌شده به فراخوانی‌کننده برمی‌گرداند. این پارامتر را می‌توان بدون مقداردهی اولیه به متد فراخوانی‌شده پاس داد و در هر صورت، داخل متد فراخوانی‌شده با آن طوری رفتار می‌شود که گویی در زمان ورود، مقداردهی اولیه نشده است. درک رفتار و قواعد مربوط به تغییردهنده‌های پارامتر، بیش از همه از راه مثال‌ها (به پایین نگاه کنید) و پیام‌های کامپایلر به دست می‌آید.

```csharp
void Foo(out int val)
{
    val = 42;
}
void Bar(int val)
{
    val = 42;
}

int importantValue = 1729;
Foo(out importantValue);
var result = importantValue == 42;
// => true

importantValue = 1729;
Bar(importantValue);
result = importantValue == 1729;
// => true
```

- پارامترهای `out` باید حتماً درون متد فراخوانی‌شده مقدار بگیرند.

- پارامتری که تغییردهنده‌ی [`ref`][ref-parameter] را دارد، مقداری را به متد فراخوانی‌شده می‌فرستد. وقتی متد بازگردد، فراخوانی‌کننده هر به‌روزرسانی‌ای را که متد فراخوانی‌شده در آن پارامتر انجام داده است، در همان پارامتر می‌بیند.

```csharp
void Foo(ref int val)
{
    val *= 7;
}

int importantValue = 6;
Foo(ref importantValue);
return importantValue;
// => 42
```

- پارامترهای `ref` باید متغیر باشند، چون متد فراخوانی‌شده مستقیماً روی همان پارامتری کار می‌کند که فراخوانی‌کننده می‌بیند.

- تغییردهنده‌های `out` و `ref` هم در امضای متد فراخوانی‌شده و هم در محل فراخوانی لازم هستند.
- پارامترهای `out` را می‌توان در محل فراخوانی به‌صورت درجا اعلام کرد، یعنی: `Foo(out int importantValue);`
- اگر متدی را فراخوانی می‌کنید که پارامترهای `out` دارد ولی به مقدار نسبت داده‌شده به یکی از آن‌ها یا بیشتر علاقه‌ای ندارید، می‌توانید از متغیر ساختگی [discard][discard] یعنی `_` استفاده کنید، مانند: `Foo(out int _);`

همه‌ی قواعد مربوط به پارامترهای `ref` و `out` توسط کامپایلر اعمال می‌شوند.

پارامترهای [`in`][in-parameter] هم وجود دارند، اما عمدتاً یک بهینه‌سازی کارایی هستند و در تمرین `structs` که بیشترین ارتباط را دارند بحث شده‌اند.

مستندات پیوندشده در بالا، در ادامه خلاصه شده است:

- [passing-parameters][passing-parameters]: توضیح می‌دهد که مقادیر چگونه می‌توانند به‌عنوان آرگومان پاس داده شوند. توجه کنید که موضوع `struct`ها و پارامترها در تمرین `structs` بحث شده است.
- [ref-parameter][ref-parameter]: چگونگی کار پارامترهای `ref` را توصیف می‌کند.
- [out-parameter][out-parameter]: چگونگی کار پارامترهای `out` را توصیف می‌کند.

هنگام مطالعه‌ی مستندات، توجه کنید که در آن از این اصطلاحات استفاده می‌شود:

- پارامتر / پارامتر صوری: به پارامتری اشاره دارد که متد فراخوانی‌شده می‌بیند.
- آرگومان: به پارامتری اشاره دارد که فراخوانی‌کننده می‌بیند.

[به عقیده‌ی برخی][so-tuples-vs-out] با معرفی `tuples` در C# ۷، بخش زیادی از ارزش پارامترهای `out` از بین رفته است. در تمرین `tuples` نشان داده می‌شود که از `tuples` برای برگرداندن چند مقدار استفاده می‌شود.

با اینکه استفاده از `ref` آسان است و جریمه‌ی کارایی ندارد، ارزش دارد پیش از استفاده‌ی گسترده از آن ببینید مسائلی که حل می‌کند در یک کدبیس مشخص چگونه مدیریت می‌شوند. جایگزین‌هایی هم وجود دارند، مثل پاس دادن به‌صورت مقداری و استفاده از مقدار موجود در دستور return متد فراخوانی‌شده. اینجا هم `tuples` می‌تواند نقشی ایفا کند.

از [مستندات][ref-parameter] خواهید دید که `out` و `ref` در برخی موقعیت‌ها قابل استفاده نیستند، اما فعلاً می‌توانید آن‌ها را نادیده بگیرید. کامپایلر هر وقت چنین موقعیت‌هایی پیش بیاید، به شما اطلاع می‌دهد.

توجه کنید که `optional parameters` و `named arguments` در تمرین `method-overloading` بحث شده‌اند.

موضوع‌های مرتبط [`ref local`][ref-local] و [`ref return`][ref-return] جای دیگری بحث شده‌اند.

## تخصیص پشته

قواعد مربوط به پارامترها و تغییردهنده‌هایشان آن‌قدر سرراست هستند که می‌توانید آن‌ها را همان‌طور که هستند بپذیرید و در سطح انتزاع خودشان درک کنید. اما اگر به سازوکارهای زیربنایی علاقه‌مندید و می‌خواهید بدانید چرا این کلیدواژه‌ها ممکن است تفاوت کارایی ایجاد کنند، دست‌کم در مورد `struct`ها، می‌توانید با این [_مقاله‌ی ویکی‌پدیا_][calling-conventions] شروع کنید و توجه داشته باشید که C# روی x86/64 از `stdcall` استفاده می‌کند.

جان مطلب این است که در مورد پارامترهای بدون تغییردهنده، **مقدار** یک متغیر روی پشته‌ی برنامه کپی می‌شود تا در دسترس روتین فراخوانی‌شده قرار بگیرد، در حالی که برای پارامترهای `ref`، `out` و `in`، یک اشاره‌گر (**ارجاع**) به حافظه‌ای که مقدار را در خود دارد، روی پشته‌ی برنامه قرار می‌گیرد و مقادیر به حافظه‌ای نسبت داده می‌شوند که ارجاع به آن اشاره دارد.
