# دستورالعمل

دوست شما هلما یک بازی آنلاین کوچک ساخته است که به‌سرعت محبوب شد.
اسم این بازی _HellMath_ است.
این جامعه‌ی کوچک چند ترول را جذب کرد که بازی و انجمن‌ها را نسبتاً ناخوشایند می‌کنند.
هلما از شما خواسته است که روی یک سیستم مجوز جدید کار کنید تا دردسرسازها را جدا کنید.

انجمن از سه کنش مختلف پشتیبانی می‌کند:

- Read
- Write
- Remove

چهار نوع حساب وجود دارد که هر کدام مجوزهای پیش‌فرض متفاوتی دارند:

- مهمان‌ها: می‌توانند پست‌ها را بخوانند.
- کاربران و ترول‌ها: می‌توانند پست‌ها را بخوانند و بنویسند.
- ناظران: می‌توانند پست‌ها را بخوانند، بنویسند و حذف کنند؛ همه‌ی مجوزها را دارند.

هلما متوجه شده است که مسدود کردن حساب‌های ترول فایده‌ای ندارد.
راهبرد او این است که به آن‌ها این توهم را بدهد که وقتشان «خوب سرمایه‌گذاری شده است»، اما پست‌هایشان فقط به ترول‌های دیگر نشان داده می‌شود.
برای هر چیزی که به ترتیب اولویت نیاز دارد، ترول‌ها در هر ترتیبی آخر قرار می‌گیرند.
وقتی وارد یک بازی می‌شوند، مجموعه‌ی بازیکنان در دسترس هم به ترول‌های دیگر محدود می‌شود.

به این کار [شادوبن][shadow-ban] می‌گویند.

## 1. انواع کاربر و مجوزها را تنظیم کنید.

ابتدا یک شمارش به اسم `AccountStatus` تعریف کنید که چهار نوع حساب را نشان دهد: `troll`، `guest`، `user` و `mod`.

سپس یک شمارش به اسم `Action` تعریف کنید که سه نوع مجوز را نشان دهد: `read`، `write` و `remove`.


## 2. ترول‌ها را فقط به ترول‌های دیگر نشان دهید.

هر پستی در انجمن، `AccountStatus` نویسنده‌ی پست را در فراداده‌ی خود ذخیره می‌کند.
مطمئن شوید که پست‌های ترول‌ها فقط به ترول‌های دیگر نمایش داده می‌شوند.

هلما به یک تابع `display_post` نیاز دارد که دو آرگومان از نوع `AccountStatus` می‌گیرد و یک `bool` برمی‌گرداند.
آرگومان اول وضعیت نویسنده‌ی پست است و آرگومان دوم وضعیت بیننده.

```cpp
using namespace hellmath;
display_post(AccountStatus::troll, AccountStatus::user);
// => false
display_post(AccountStatus::mod, AccountStatus::guest);
// => true
```

## 3. مجوزهای کاربران مختلف را بررسی کنید.

هلما به راهی نیاز دارد که بررسی کند آیا یک کنش خاص برای یک کاربر مجاز است یا نه.

لطفاً تابعی به اسم `permission_check` پیاده‌سازی کنید که یک `Action` را به عنوان آرگومان اول و یک `AccountStatus` را برای بررسی مجوز می‌گیرد.
این تابع باید بر اساس مجوزهایی که در مقدمه فهرست شده‌اند یک `bool` برگرداند.

```cpp
permission_check(Action::remove, AccountStatus::guest);
// => false
permission_check(Action::write, AccountStatus::mod);
// => true
```

## 4. دسترسی به بازی را بدهید و بازیکنان را جفت کنید.

برای اینکه بازیکنان واقعی بازی در قبال کنش‌هایشان پاسخگو بمانند، _Hellmath_ به کاربران مهمان دسترسی نمی‌دهد.
همان‌طور که در بالا اشاره شد، هلما می‌خواهد ترول‌ها ترول‌های دیگر را ترول کنند.
ارتباط‌های بازی میان سایر کاربران محدودیتی ندارد.

تابع `valid_player_combination` را پیاده‌سازی کنید که بررسی می‌کند آیا دو بازیکن می‌توانند به یک بازی مشترک بپیوندند.
این تابع دو پارامتر از نوع `AccountStatus` دارد و یک `bool` برمی‌گرداند.

```cpp
valid_player_combination(AccountStatus::guest, AccountStatus::mod);
// => false
valid_player_combination(AccountStatus::troll, AccountStatus::troll);
// => true
```

## 5. صف‌بندی اولویت را بسازید.

با رشد عظیم بازی و انجمن‌ها، هلما اکنون باید توان پردازشی و پهنای باند را میان کاربران تقسیم کند.
برای رسیدگی به شرایط اضطراری، به ناظران بالاترین اولویت داده می‌شود.
مهمان‌ها پس از کاربران عادی در صف قرار می‌گیرند و ترول‌ها بعد از همه‌ی افراد دیگر در صف قرار می‌گیرند.

تابع `has_priority` را پیاده‌سازی کنید که دو آرگومان از نوع `AccountStatus` می‌گیرد و اگر و تنها اگر حساب اول اولویت اکیداً بالاتری از حساب دوم داشته باشد، `true` برمی‌گرداند.

```cpp
has_priority(AccountStatus::guest, AccountStatus::mod);
// => false
has_priority(AccountStatus::user, AccountStatus::troll);
// => true
```
