# درباره

فایل یک «جریان» است که اسمی روی دیسک دارد. واژگان [`io.files`][io.files] دو راه برای کار با آن پیش می‌گذارد: واژه‌های راحتیِ کل فایل که همه‌چیز را در یک فراخوانی می‌خوانند یا می‌نویسند، و بازکننده‌های جریان (ترکیب‌گرهای `with-…`) برای خواندن یا نوشتن تدریجی. هر دو بر همان [پروتکل جریان][stream-protocol] استوارند که جریان‌های درون‌حافظه از مفهوم `io-streams` دارند: یک `<file-reader>` و یک `<string-reader>` به واژه‌های یکسانی پاسخ می‌دهند.

هر واژه‌ی فایل یک **کدگذاری** می‌گیرد، یعنی طرحی که بایت‌ها را به نویسه‌ها و برعکس نگاشت می‌کند. برای متن، این تقریباً همیشه [`utf8`][utf8] از `io.encodings.utf8` است؛ کار دودویی از `latin1` یا کدگذاری `<byte-array>` استفاده می‌کند.

## خواندن کل فایل

```
file-contents   ( path encoding -- str )
file-lines      ( path encoding -- seq )
```

`file-contents` کل فایل را به‌صورت یک رشته برمی‌گرداند. `file-lines` خطوط آن را به‌صورت یک آرایه برمی‌گرداند، با حذف پایانه‌های خط؛ این وقتی به کار می‌آید که هر خط یک رکورد باشد.

```factor
USING: io.encodings.utf8 io.files ;

"forecast.txt" utf8 file-contents   ! => "sunny\ncloudy\n"
"forecast.txt" utf8 file-lines      ! => { "sunny" "cloudy" }
```

## نوشتن کل فایل

```
set-file-contents   ( str path encoding -- )
set-file-lines      ( seq path encoding -- )
```

هر دو فایل را **جایگزین** می‌کنند و اگر وجود نداشته باشد آن را می‌سازند. `set-file-contents` یک رشته را عیناً می‌نویسد؛ `set-file-lines` هر عنصر از یک دنباله را در خط خودش می‌نویسد و خودش خط‌های جدید را می‌گذارد.

```factor
{ "sunny" "cloudy" } "forecast.txt" utf8 set-file-lines
! forecast.txt now holds "sunny\ncloudy\n"
```

## جریان‌های دامنه‌ای

وقتی می‌خواهید چیزی به فایلی بیفزایید، یا تکه‌تکه بخوانید و بنویسید، آن را با یک ترکیب‌گر `with-…` باز کنید و واژه‌های جریان محیطی را داخل کوتیشن به کار ببرید:

```
with-file-reader     ( path encoding quot -- )
with-file-writer     ( path encoding quot -- )
with-file-appender   ( path encoding quot -- )
```

```factor
USING: io io.encodings.utf8 io.files ;

"log.txt" utf8 [ "another line" print ] with-file-appender
```

`with-file-writer` ابتدا فایل را کوتاه می‌کند؛ `with-file-appender` محتویات موجود را نگه می‌دارد و بعد از آن‌ها می‌نویسد. هر کدام یک دامنه‌ی تخریب است: وقتی کوتیشن تمام شود، دستگیره‌ی فایل بسته می‌شود، حتی اگر خطا پرتاب کند؛ همان تضمینی که ترکیب‌گرهای `boatswains-bilge` می‌دهند، که اینجا برای فایل‌ها تخصصی شده است.

## کل فایل یا جریان دامنه‌ای؟

وقتی فایل به‌قدری کوچک است که در حافظه جا شود و همه‌ی آن را یک‌جا می‌خواهید، سراغ `file-contents` / `file-lines` / `set-file-contents` / `set-file-lines` بروید. وقتی لازم است چیزی به فایل بیفزایید، فایل بزرگی را خط‌به‌خط با `readln` جریان دهید، یا خواندن‌ها و نوشتن‌ها را درهم بیامیزید، سراغ بازکننده‌های `with-…` بروید؛ هرجا نگه‌داشتن کل فایل در حافظه پرهزینه یا نادرست باشد.
