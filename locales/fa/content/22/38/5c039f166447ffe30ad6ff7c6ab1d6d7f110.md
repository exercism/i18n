# مقدمه

[«تطبیق الگو»][pattern-matching] امکان نوشتن کد انشعابی گویا را فراهم می‌کند و [«تجزیه»][destructuring] اتصال ظریف مقادیر به متغیرها را به ارمغان می‌آورد.
تسلط بر هر دوی این‌ها برای ما به‌عنوان برنامه‌نویس elm بسیار سودمند است و وقتی با هم به کار روند، خوانایی کد را به‌شکل چشمگیری بهبود می‌دهند.

## تطبیق الگوی ساده

تطبیق الگو به کدی انشعابی اشاره دارد که به شکل داده‌ی مورد پردازش بستگی دارد.
بنابراین به‌طور طبیعی با مفهوم «نوع داده‌ی سفارشی» همخوانی دارد؛ نوع‌هایی که شکل‌های گوناگونی را بیان می‌کنند که یک داده می‌تواند به خود بگیرد.
برای نمونه، با داشتن یک نوع داده‌ی سفارشی `Color` که به‌صورت `Blue` یا `Red` تعریف شده است، می‌توانیم یک تابع `toString` بنویسیم که روی رنگ تطبیق الگو انجام می‌دهد تا رشته‌ی درست را برگرداند.

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

تطبیق الگو برای نوع‌های داده‌ی سفارشی‌ای هم کار می‌کند که صرفاً یک «برشماری» ساده نیستند.
بیایید تابع `hello` را در نظر بگیریم که پارامتری از نوع `Maybe String` می‌گیرد و یا اسم یک شخص را در خود دارد یا هیچ.
هنگام تطبیق الگو می‌توانیم به داده اسم‌هایی با حروف کوچک بدهیم تا آن داده به آن متغیر متصل شود و بتوانیم از آن در سمت راست تطبیق استفاده کنیم.

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

تطبیق الگو باید «جامع» باشد، وگرنه کامپایلر از کامپایل کردن آن سر باز می‌زند.
اما گاهی به بعضی داده‌ها یا بعضی شاخه‌های یک عبارت case اهمیتی نمی‌دهیم.
در چنین مواردی، به‌جای آن‌که مجبور باشیم برای اتصال اسمی برای متغیر پیدا کنیم و برای همه‌ی حالت‌ها شاخه بسازیم، می‌توانیم از «نویسه‌ی عام» زیرخط `_` استفاده کنیم.

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## تطبیق الگوی پیشرفته

علاوه بر نوع‌های داده‌ی سفارشی، می‌توانیم روی نوع‌هایی هم تطبیق الگو انجام دهیم که مقادیر تحت‌اللفظی دارند، مثل `Char`، `String`، `Int` و `Floats`.

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

برای تطبیق بیش از یک مقدار بدون تودرتویی، یک ترفند رایج در Elm این است که مقادیر مورد تطبیق را در [_تاپل‌های موردی_][ad-hoc-tuples] این‌گونه ترکیب کنیم:

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

و چون لیست‌ها برای برنامه‌نویسان تابعی عزیزند، [می‌توان روی آن‌ها هم تطبیق الگو انجام داد][pattern-match-lists]، با همان نحوه‌ی نگارشی که برای ساختن‌شان به کار می‌رود، با استفاده از عملگر `::`.

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

در نهایت، تطبیق الگو حتی به‌صورت بازگشتی هم کار می‌کند و امکان کاوش عمیق در نوع‌های پیچیده و بازگشتی را فراهم می‌کند.

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## تجزیه

تجزیه از این نظر بسیار شبیه تطبیق الگو است که اتصال متغیرها به داده‌های درون نوع‌ها را ممکن می‌کند.
تفاوت اصلی این است که وقتی فقط یک شکل ممکن وجود دارد، به این سازوکار «تجزیه» می‌گوییم و وقتی چند شکل وجود دارد، آن را تطبیق الگو می‌نامیم.
تجزیه اغلب در اتصال‌های `let`، در آرگومان‌های تابع و البته در عبارت‌های case، آمیخته با تطبیق الگو، دیده می‌شود.

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

تجزیه را می‌توان برای نوع‌های داده‌ی سفارشی تک‌حالته، برای تاپل‌ها و همچنین برای رکوردها به کار برد، که در آن‌جا بسیار راحت است.
برای [تجزیه‌ی یک رکورد][records-pattern-matching]، می‌توان از هر تعداد از فیلدهای آن استفاده کرد: یکی، دو تا، ... یا همه‌ی فیلدها.

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

متأسفانه نحوه‌ی نگارش elm تجزیه‌ی بازگشتی رکوردها را ممکن نمی‌کند.
در مثال `Circle` قبلی، هیچ راهی برای دسترسی به موقعیت‌های `x`` and `y مرکز دایره در یک مرحله وجود ندارد.
باید ابتدا به `center` دسترسی پیدا کنیم و بعد آن را برای موقعیت‌های `x` و `y`اش تجزیه کنیم.

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

و یک نکته‌ی آخر هم داریم!
گاهی می‌خواهیم هم به کل و هم به بخشی از آن دسترسی آسانی داشته باشیم.
اینجاست که [کلیدواژه‌ی `as`][as-keyword] می‌تواند مفید باشد.
این کلیدواژه امکان می‌دهد به کل یک مقدار نام مستعار بدهیم و در همان حال بتوانیم محتوایش را تجزیه کنیم.

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
