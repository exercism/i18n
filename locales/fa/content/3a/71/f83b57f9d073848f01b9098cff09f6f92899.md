# مقدمه

پمپ‌ها، شیرها، شلنگ‌ها: هر آنچه منبعی از سیستم‌عامل (یک فایل باز، یک اتصال شبکه) را در اختیار می‌گیرد، باید وقتی کارتان با آن تمام شد *آزاد* شود. واژگان `destructors` در Factor اینها را در چارچوبی می‌گنجاند که پاک‌سازی را تضمین می‌کند، حتی اگر خطایی کد شما را در میانه‌ی کار قطع کند.

## کلاس و جنریک

یک کلاس با ارث‌بری از `disposable` و پیاده‌سازی جنریک `dispose*` به چارچوب می‌پیوندد:

```factor
USING: accessors destructors kernel ;

TUPLE: pump < disposable opened ;

: <pump> ( -- pump )
    pump new-disposable t >>opened ;

M: pump dispose* f >>opened drop ;
```

‏`new-disposable ( class -- obj )` تاپل را تخصیص می‌دهد *و* آن را در چارچوب ثبت می‌کند؛ استثنایی که بین تخصیص و نقطه‌ی ایمن بعدی رخ دهد نمی‌تواند منبع را نشت دهد. چارچوب تضمین می‌کند که `dispose*` برای هر شیء **حداکثر یک بار** اجرا می‌شود؛ فراخوانی‌های تکراری `dispose` بی‌اثرند.

## فراخوان‌کنندگان عمومی از `dispose` استفاده می‌کنند

```
dispose          ( obj -- )                ! release; safe to call twice
with-disposal    ( disposable quot -- )    ! scope one resource
with-destructors ( quot -- )               ! open a registry scope
&dispose         ( obj -- obj )            ! dispose on normal *or* failure exit
|dispose         ( obj -- obj )            ! dispose only if the scope unwinds
```

‏`with-disposal` شکل تک‌منبعی است: `disposable` را برای `quotation` درونی روی پشته می‌گذارد و هنگام خروج آزادش می‌کند.

```factor
USING: destructors io ;

<pump> [
    "pumping" print
] with-disposal
! pump released on the way out — even if `print` had thrown
```

برای بیش از یک منبع، یک اسکوپ `with-destructors` باز کنید و هر بار تخصیص را ثبت کنید. `&dispose` (آمپرسند) یعنی «هنگام خروج، چه موفق چه ناموفق، همیشه آزادسازی انجام شود». `|dispose` (پایپ) یعنی «**فقط** در صورت شکست آزادسازی انجام شود»؛ وقتی مسیر موفقیت منبع را به فراخوان‌کننده‌ای می‌سپارد که مالکیتش را برمی‌دارد، این به کار می‌آید.

```factor
[
    <pump> &dispose
    <pump> &dispose
    ! ... use the pumps ...
] with-destructors
! both pumps released
```

برای یک try/finally ساده بدون رجیستری، [`cleanup`][cleanup] (در `continuations`) ابتدایی‌تر و سطح‌پایین‌تر است، اما `with-destructors` روش اصطلاحی و مدرن در Factor است.

[cleanup]: https://docs.factorcode.org/content/word-cleanup%2Ccontinuations.html
