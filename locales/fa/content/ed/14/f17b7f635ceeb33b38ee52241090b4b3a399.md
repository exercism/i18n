# درباره

برای درک [`Box`][box]، کمک‌کننده است که بدانید [«پشته و هیپ»][stack and heap] چیست.

پشته ناحیه‌ای از حافظه است که مثل یک «بافر» آخرین‌ورودی، اولین‌خروجی (LIFO) کار می‌کند. قرار دادن داده روی پشته بسیار سریع است و برداشتن آن هم سریع. داده می‌تواند شامل متغیرها یا آدرس توابع باشد، اما باید در زمان کامپایل اندازه‌ی ثابت و معلومی داشته باشد.

اگر اندازه‌ی داده در زمان کامپایل نامعلوم باشد یا اندازه‌ای داشته باشد که ممکن است تغییر کند، باید روی هیپ تخصیص داده شود. فرایند تخصیص باید فضایی در هیپ پیدا کند که برای نگهداری داده به‌قدر کافی بزرگ باشد، داده را در هیپ بنویسد و آدرس حافظه‌ی آن داده را روی پشته قرار دهد؛ همه‌ی این کارها زمان بسیار بیشتری از صرفاً قرار دادن داده روی پشته می‌برد. بازیابی داده از هیپ کمی کندتر است، چون باید از آدرس روی پشته بگذریم و آن را تا محل قرارگیری داده روی هیپ دنبال کنیم.

`Box` یک «اشاره‌گر هوشمند» است که داده را روی هیپ تخصیص می‌دهد. آدرس روی پشته است و به داده روی هیپ اشاره می‌کند. یکی از [دلایل][reasons] استفاده از `Box` این است که داده را روی هیپ قرار دهید، آن هم وقتی نوعی دارید که اندازه‌اش در زمان کامپایل قابل دانستن نیست و می‌خواهید مقداری از آن نوع را در بافتی به کار ببرید که به اندازه‌ی دقیق نیاز دارد. یک کاربرد عملی این موضوع جایی است که چند `struct` دارید و می‌خواهید همه‌ی آنها را از طریق یک `trait` که همه‌شان پیاده‌سازی می‌کنند به یک شکل مدیریت کنید، همان‌طور که نمونه‌اش را در ادامه می‌بینید.

فرض کنید دو `struct` داریم. هر `struct` نماینده‌ی چیزی است که می‌تواند آزاردهنده باشد. می‌توانیم کاری کنیم که هر `struct` یک `trait` به نام `Annoyance` را این‌طور پیاده‌سازی کند

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

حالا فرض کنید تابعی می‌خواهیم که بر اساس زمان روزی که به آن پاس داده می‌شود، به ما یک `Annoyance` بدهد. اول می‌توانیم این را امتحان کنیم، و می‌بینیم که کامپایل نمی‌شود

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

کامپایلر با همه‌ی مهربانی‌اش دقیقاً می‌گوید چه باید بکنیم: باید یک trait object «جعبه‌بندی‌شده» برگردانیم. اگر نمی‌دانید trait object چیست، توصیف ساده‌ای برایش این است که راهی است برای برگرداندن یک شیء مشخص، از طریق [«اعزام پویا»][dynamic dispatch]، از دل تابعی که می‌تواند هر شیئی را که `trait` مشخصی را پیاده‌سازی می‌کند برگرداند. چون به اعزام پویا نیاز داریم، می‌توانیم امتحان کنیم و فقط یک `dyn` جلوی اسم `trait` بگذاریم و ببینیم آیا از عهده‌اش برمی‌آییم.

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

یکی از خطاها این است که اندازه‌ی `dyn Annoyance` در زمان کامپایل قابل دانستن نیست. علتش این است که `annoy_me` پیش از فراخوانی نمی‌داند چه trait object مشخصی را برمی‌گرداند. `struct`هایی که `Annoyance` را پیاده‌سازی می‌کنند می‌توانند فیلدهای متفاوت و اندازه‌های متفاوتی داشته باشند. و به یادمان می‌آید که یکی از کاربردهای `Box` برای نوعی است که اندازه‌اش در زمان کامپایل قابل دانستن نیست. حالا امتحان می‌کنیم که از یک مقدار بازگشتی «جعبه‌بندی‌شده» استفاده کنیم و مقادیری را که از عبارت `match` برگردانده می‌شوند «جعبه‌بندی» کنیم، این‌طور

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

امضای `Box` به شکل `Box<T>` است که در آن `T` نماد نوع مشخصی است که باید جعبه‌بندی شود و داخل براکت‌های زاویه‌دار قرار می‌گیرد، همان‌طور که در `Box<dyn Annoyance>` بالا دیدیم.

می‌توانیم از trait object جعبه‌بندی‌شده این‌طور استفاده کنیم

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

که این را چاپ می‌کند

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

چون `my_annoyance` از نوع `Box<dyn Annoyance>` است، باید با عملگر `deref`، یعنی `*`، از `Box` ارجاع‌زدایی شود. سپس به‌عنوان یک `dyn Annoyance` ارجاع می‌شود تا تابع `be_annoying` آن را قرض بگیرد.

راه دیگری برای پیاده‌سازی این کار این است که شرط سایزشده بودن پارامتر را حذف کنیم. در آن صورت، کامپایل برای هر حالت از `Annoyance` یک تابع جداگانه می‌سازد تا بتوان آن را به‌صورت ایستا اعزام کرد (فرایندی به نام [monomorphization][monomorphization])، این‌طور

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

راه دیگری برای پیاده‌سازی این کار این است که تابع `be_annoying` یک `Box<dyn Annoyance>` بپذیرد و از [تبدیل خودکار ارجاع‌زدایی][deref coercion] استفاده کند تا لازم نباشد `Box` را دستی ارجاع‌زدایی کنیم. این کار مالکیت trait object مربوط به `Annoyance` را به تابع `be_annoying` منتقل می‌کند. این شیء در پایان تابع از حوزه خارج می‌شود و دیگر در دسترس نخواهد بود.

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
