# مقدمه

وقتی به ردیفی از `n` مقدار نیاز دارید که هر یک به موقعیتش وابسته باشد، `<iota>` و `map` در Factor با هم همکاری می‌کنند تا این کار را بدون نوشتن یک شمارنده‌ی حلقه انجام دهند.

## `<iota>` و `map`

`<iota>` (در [`sequences`][sequences]) یک عدد صحیح نامنفی `n` می‌گیرد و دنباله‌ای *مجازی* از اعداد صحیح `0, 1, …, n-1` برمی‌گرداند. سپس `map` آن را پیمایش می‌کند و کوتیشن شما را روی هر عنصر اعمال می‌کند:

```factor
USING: math sequences ;

5 <iota> [ 2 * ] map .   ! => { 0 2 4 6 8 }
```

کوتیشن یک عدد صحیح دریافت می‌کند (همان اندیس) و مقدار آن موقعیت را روی پشته باقی می‌گذارد.

## پیمایش و تکرار بر اساس تعداد

وقتی تنها به *عوارض جانبی* سر زدن به هر اندیس نیاز دارید و نه یک دنباله‌ی تازه، `each-integer` (در [`math`][math]) یک کوتیشن را روی `0, 1, …, n-1` اجرا می‌کند:

```
each-integer ( n quot: ( i -- ) -- )
```

`replicate` (در [`sequences`][sequences]) یک کوتیشن را `n` بار فراخوانی می‌کند و نتایج را جمع می‌کند، و اندیس را نادیده می‌گیرد. این برای ساختن `n` مقدار مستقل کارآمد است:

```
replicate ( n quot: ( -- elt ) -- seq )
```

```factor
USING: sequences ;

3 [ { 0 0 } ] replicate .   ! => { { 0 0 } { 0 0 } { 0 0 } }
```

## بازه‌های کران‌دار

وقتی بازه‌ی اندیس‌ها از `0` شروع نمی‌شود، یا می‌خواهید در هر دو انتها فراگیر باشد، واژگان [`ranges`][ranges] مقادیر ثابت براکتی را فراهم می‌کند. براکت مربع نقطه‌ی پایانی را شامل می‌شود؛ پرانتز آن را حذف می‌کند.

```
[a..b]    ! a, a+1, …, b      (inclusive)
[a..b)    ! a, a+1, …, b-1    (half-open at the top)
```

```factor
USING: math ranges sequences ;

3 7 [a..b] [ 2 * ] map .   ! => { 6 8 10 12 14 }
3 7 [a..b) [ 2 * ] map .   ! => { 6 8 10 12 }
```

چند کوتاه‌نوشت رایج تک‌آرگومانی:

```
[1..b]    ! 1, 2, …, b        (same as 1 b [a..b])
[1..b)    ! 1, 2, …, b-1      (same as 1 b [a..b))
[0..b)    ! 0, 1, …, b-1      (same as 0 b [a..b), and same as `b <iota>`)
```

```factor
6 [1..b] [ sq ] map .      ! => { 1 4 9 16 25 36 }
6 [1..b) [ sq ] map .      ! => { 1 4 9 16 25 }
4 [0..b) [ 1 + ] map .     ! => { 1 2 3 4 }
```

`<iota>` رایج‌ترین شکل است؛ وقتی بازه از جایی جز `0` شروع می‌شود یا به یک کران بالای فراگیر نیاز دارد، `[a..b]` و مشابه‌هایش ابزار درست هستند.

## کران‌های پایین باز و بازه‌های احتمالاً خالی

براکت مربع یک نقطه‌ی پایانی را *شامل می‌شود*؛ براکت گرد آن را *حذف می‌کند*. همان ترفند در سمت چپ `(a..b]` و `(a..b)` را می‌دهد:

```
(a..b]    ! a+1, …, b              (lower open, upper inclusive)
(a..b)    ! a+1, …, b-1            (both open)
```

`0 n (a..b]` برای `n > 0` مقدار `{ 1 … n }` را می‌دهد و برای `n = 0` مقدار `{ }` را. این شکل طبیعی هنگام پیمایش «هر عدد صحیح مثبت تا خود `n`» است.

## بازه‌های نزولی

همه‌ی چهار شکل براکتی (`[a..b]`، `[a..b)`، `(a..b]` و `(a..b)`) وقتی `a > b` باشد *رو به پایین* می‌شمارند، نه به سمت نتیجه‌ی خالی:

```factor
USING: ranges sequences ;

5 1 [a..b] >array .   ! => { 5 4 3 2 1 }
1 0 [a..b] >array .   ! => { 1 0 }   (not empty!)
```

## ساختن رشته بر اساس موقعیت

`map` هر شکلی که کوتیشنش برمی‌گرداند را تولید می‌کند. اگر کوتیشن یک کد نویسه روی پشته باقی بگذارد، `>string` (در [`strings`][strings]) نتیجه را به رشته تبدیل می‌کند:

```factor
USING: math sequences strings ;

4 <iota> [ 2 * CHAR: A + ] map >string .   ! => "ACEG"
```

`CHAR: A` به عدد صحیح `65` تجزیه می‌شود. کوتیشن اینجا اندیس را دو برابر می‌کند و آن مبنا را می‌افزاید، که به هر حرف بزرگ یکی در میان می‌رسد. هر حسابی که روی اندیس بیفزایید تعیین می‌کند چه نویسه‌ای در آن موقعیت قرار می‌گیرد.

## انتخاب برای هر موقعیت

وقتی نویسه به یک *شرط* درباره‌ی اندیس وابسته است، انتخاب را داخل کوتیشن انجام دهید:

```factor
USING: kernel math sequences strings ;

5 <iota> [ 3 < [ CHAR: a ] [ CHAR: b ] if ] map >string .
! => "aaabb"
```

در سه موقعیت نخست، آزمون `i 3 <` نتیجه‌ی `t` می‌دهد، پس `a` می‌گیرند؛ بقیه `b` می‌گیرند. همین شکل (`[ <test> [ <yes> ] [ <no> ] if ]`) آزمون‌های زوج/فرد را با `even?` / `odd?` (در [`math`][math]) و آزمون‌های «هر موقعیت kاُم» را با `mod` و `zero?` پوشش می‌دهد.
