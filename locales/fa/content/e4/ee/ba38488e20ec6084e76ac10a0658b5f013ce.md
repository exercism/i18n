# مقدمه

## کاراکترها

**کدگذاری کاراکتر** قراردادی مشخص است که برای نمایش عناصر متن در یک زبان طبیعی به‌صورت دنباله‌ای از بایت‌ها به کار می‌رود.
«عنصر متن» در اینجا می‌تواند هر واحدی باشد که در یک زبان طبیعی اهمیت دارد؛ برای مثال، حروف، فاصله‌ها، علائم نگارشی، ایموجی‌ها، ایدئوگرام‌ها و غیره.

NASM (اسمبلر Netwide، همان اسمبلری که این مسیر از آن استفاده می‌کند) از تعریف داده با **ASCII** پشتیبانی می‌کند.

ثابت‌های کاراکتری در NASM می‌توانند تا ۸ بایت طول داشته باشند و می‌توان آن‌ها را با کوتیشن تکی (`'`)، کوتیشن دوتایی (`"`) یا بک‌تیک (`` ` ``) تعریف کرد:

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

کاراکترهای خاص باید داخل بک‌تیک تعریف شوند و با `\` فرار داده شوند:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

توجه داشته باشید که در x86-64 هیچ پشتیبانی داخلی برای هیچ کدگذاری کاراکتری به‌عنوان یک نوع داده‌ی مجزا وجود ندارد.
داده در اسمبلی دنباله‌ای از بایت‌ها است و تفسیر آن بایت‌ها به‌عنوان یک کاراکتر، یک عدد یا هر چیز دیگری، به عهده‌ی برنامه‌نویس است.

برای مثال، کاراکتر ASCII '0' یک بایت تک با مقدار ۴۸ است.
پس ذخیره‌ی ۴۸ در یک بایت دقیقاً همان ذخیره‌ی کاراکتر ASCII '0' است:

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

به همین دلیل، دست‌کاری کاراکترها با تغییر مستقیم مقدار آن بایت‌ها انجام می‌شود:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## رشته‌ها

**رشته** دنباله‌ای از کاراکترها است.
در اسمبلی، معمولاً به‌صورت یک آرایه پیاده‌سازی می‌شود.

می‌توان یک رشته را در NASM همان‌گونه که هر آرایه‌ای تعریف می‌شود، تعریف کرد:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

یک تفاوت میان رشته‌ها و دیگر آرایه‌ها این است که NASM از تعریف رشته‌ها بدون ویرگول (`,`) جداکننده‌ی مقادیر هم پشتیبانی می‌کند.
همچنین می‌توان مقادیر را با ویرگول درهم آمیخت:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

توجه داشته باشید که همان‌طور که پیش‌تر گفته شد، کاراکترها فقط بایت هستند (یا در کدگذاری یونیکد، دنباله‌ای از بایت‌ها):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

از آنجا که هر کاراکتر ASCII یک بایت تک را اشغال می‌کند، هر بایت بعدی در اندازه‌ای بزرگ‌تر `0` است.
برای مثال، تعریف `'a'` به‌صورت یک واژه‌ی چهارگانه (۸ بایت) یعنی بایت اول `'a'` (`97`) است و هفت بایت دیگر همه `0` هستند.

به همین دلیل، همه‌ی این‌ها معادل‌اند:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
در اسمبلی، رشته‌ها به‌طور خودکار با کاراکتر NUL در ASCII (مقدار `0`) پایان نمی‌یابند.

هنگام تعامل با زبان‌های سطح بالاتر، مانند C، مسئولیت برنامه‌نویس است که مطمئن شود پایان‌دهنده‌ی درست، در صورت وجود، به انتهای رشته افزوده می‌شود.
~~~~

## دستورهای رشته

از آنجا که رشته‌ها آرایه‌اند، می‌توانید مانند هر آرایه‌ی دیگری با آن‌ها کار کنید، یعنی با ارجاع‌زدایی صریح از حافظه:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

علاوه بر این، دستورهایی برای بارگذاری، جابه‌جایی و ذخیره‌ی مقادیر در دنباله‌هایی از بایت در حافظه وجود دارد.
هرچند به آن‌ها _دستورهای رشته_ می‌گویند، می‌توان از آن‌ها با هر دنباله‌ی بایتی در حافظه، یعنی با هر آرایه‌ای، استفاده کرد.

سه دستور رشته‌ی مهم عبارت‌اند از `lods`، `stos` و `movs`:

| دستور  | کاری که انجام می‌دهد                                                                                             |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | مقداری را از مکانی از حافظه که با `rsi` مشخص شده در `rax` بارگذاری می‌کند                                        |
| `stos`      | مقداری را از `rax` در مکانی از حافظه که با `rdi` مشخص شده ذخیره می‌کند                                            |
| `movs`      | مقداری را از مکانی از حافظه که با `rsi` مشخص شده رونوشت می‌کند و آن را در مکانی از حافظه که با `rdi` مشخص شده ذخیره می‌کند |

توجه داشته باشید که آن دستورها هیچ عملوند صریحی _نمی‌گیرند_.
عملوندهای آن‌ها ضمنی هستند.

به‌عنوان یک قاعده‌ی کلی:

۱. وقتی عملوند مبدأ آن‌ها یک مکان حافظه است، آدرسش باید در `rsi` ذخیره شود (`s` به معنی source).
۲. وقتی عملوند مقصد آن‌ها یک مکان حافظه است، آدرسش باید به‌جای آن در `rdi` ذخیره شود (`d` به معنی destination).
۳. اگر یکی از عملوندها مکان حافظه نباشد، آن عملوند ثبات `rax` است.

توجه داشته باشید که آن دستورها بسته به عملیات خاصی که انجام می‌دهند، به‌طور خودکار آدرس‌های حافظه را ارجاع‌زدایی می‌کنند.

همه‌ی آن‌ها می‌توانند با اندازه‌های مختلف کار کنند.
برای نشان دادن این اندازه، پسوندی به آن‌ها افزوده می‌شود:

| پسوند | معنی | اندازه |
| :----: | ------- | :------ |
|  `b`   | بایت    | ۱ بایت  |
|  `w`   | واژه    | ۲ بایت |
|  `d`   | واژه‌ی دوگانه   | ۴ بایت |
|  `q`   | واژه‌ی چهارگانه   | ۸ بایت |

برای مثال:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

آن‌ها همچنین هر آدرسی را که به کار می‌برند، به اندازه‌ی عملیات تغییر می‌دهند.
این تغییر بر اساس مقدار **پرچم جهت (DF)** انجام می‌شود:

- اگر `DF` پاک باشد، آدرس‌ها به اندازه‌ی عملیات _افزایش_ می‌یابند.
- اگر `DF` تنظیم باشد، آدرس‌ها به همان اندازه _کاهش_ می‌یابند.

قرارداد System V ABI مقرر می‌کند که پرچم جهت باید در ورود به تابع پاک باشد.
بنابراین، _رفتار پیش‌فرض این است که حافظه به ترتیب صعودی آدرس‌ها خوانده و نوشته می‌شود_.

از دستور `cld` می‌توان برای پاک کردن پرچم جهت استفاده کرد، و از دستور `std` برای تنظیم آن:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
فراخوان انتظار دارد که `DF` پس از بازگشت هر تابع فراخوانی‌شده، مطابق System V ABI، پاک باشد.
اگر زمانی `DF` را تنظیم کردید، حتماً پیش از `ret` آن را پاک کنید.
~~~~

### Rep

علاوه بر آن‌ها، دستور **rep** به‌طور مستقیم با حافظه تعامل نمی‌کند.
در عوض، می‌توان آن را به‌عنوان پیشوند به دیگر دستورهای یادشده افزود و آن دستورها را _تکرار_ کرد.

وقتی پیشوند `rep` به کار می‌رود، دستورهای رشته به تعدادی برابر با مقدار `rcx` تکرار می‌شوند.
هر بار، مقدار `rcx` به اندازه‌ی `1` کاهش می‌یابد.
توجه داشته باشید که مقدار `rcx` باید پیش از استفاده از دستور تنظیم شود:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
روی پردازنده‌های مدرن، `rep movs` و `rep stos` معمولاً گزینه‌های سریعی برای جابه‌جایی داده در بلوک‌های بزرگ هستند.
اما دیگر دستورهای رشته، و حتی `movs` و `stos` هنگام کار بدون `rep`، معمولاً از یک حلقه‌ی ساده کندترند.
