# مقدمه

## ادعای `let`

وقتی در Gleam روی یک مقدار «تطبیق الگو» انجام می‌دهیم، باید مطمئن شویم که الگوها با همه‌ی مقادیر ممکن آن نوع مطابقت می‌کنند، وگرنه کد کامپایل نمی‌شود.

این تابع باید رد شود، چون حالتی را که لیست خالی است مدیریت نکرده است:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

بیشتر اوقات در برنامه‌های Gleam می‌خواهیم همه‌ی حالت‌های ممکن را مدیریت کنیم، اما در بعضی برنامه‌ها، مثل نمونه‌های اولیه و اسکریپت‌های سریع، ممکن است بخواهیم فقط روی «مسیر بدون خطا» تمرکز کنیم و برای بقیه‌ی حالت‌ها کد ننویسیم. اینجاست که `let assert` در Gleam به کار می‌آید.

با ادعاهای `let`، یک الگو می‌تواند فقط با بعضی از مقادیر ممکن یک نوع مطابقت کند و اگر الگو با مقداری مطابقت نکند، برنامه کرش می‌کند. با استفاده از `let assert` می‌توانیم تابع بالا را این‌طور بنویسیم:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

کتابخانه‌های Gleam هرگز نباید از ادعاهای `let` استفاده کنند، چون می‌توانند برنامه را کرش کنند. در عوض، باید از نوع `Result` استفاده کنند و بگذارند توسعه‌دهنده‌ی برنامه تصمیم بگیرد که خطاها را چطور مدیریت کند.
