# درباره

«نخ»های Factor روی یک نخ سیستمعامل، *«همرویه‌های تعاونی»* هستند. یک نخ آن‌قدر اجرا می‌شود تا خودش به‌طور صریح کنترل را واگذار کند یا یک عملیات ورودی/خروجی مسدودکننده انجام دهد؛ در همین نقطه است که زمان‌بند نخ دیگری را که قابل اجراست برمی‌گزیند. این موضوع دو پیامد دارد:

- هر آنچه بین دو واگذاری رخ می‌دهد، عملاً اتمی است.
- موازی‌سازی واقعی روی چند هسته مستلزم آن است که از واژگان استاندارد `threads` فراتر بروید (برای نمونه، `concurrency.distributed` برای طرح‌های چندفرایندی).

سازه‌های اولیه‌ی «همروندی» استاندارد در چند لایه سازمان یافته‌اند:

| واژگان                       | آنچه فراهم می‌کند                               |
|-----------------------------|----------------------------------------|
| [`threads`][threads]                   | `spawn`، `yield`، هویت نخ      |
| [`concurrency.promises`][concurrency.promises]      | `<promise>`، `fulfill`، `?promise`     |
| [`concurrency.locks`][concurrency.locks]         | `<lock>`، `with-lock`                  |
| [`concurrency.combinators`][concurrency.combinators]   | `parallel-map`، `parallel-each`        |
| [`concurrency.semaphores`][concurrency.semaphores]    | `<semaphore>`، `acquire`، `release`    |
| [`concurrency.mailboxes`][concurrency.mailboxes]     | صندوق‌های ورودی هر نخ، `send`، `receive`  |
| [`concurrency.channels`][concurrency.channels]      | دستگیره‌های هم‌ملاقات، `to`، `from`       |

```factor
USING: concurrency.combinators concurrency.locks
concurrency.promises kernel sequences threads ;

! parallel-map: fork-join, in order
{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }

! spawn + promise: hand-rolled fork-join
<promise> [
    [ "hello, world" swap fulfill ] curry "greeter" spawn drop
] keep ?promise .   ! => "hello, world"

! <lock> + with-lock: protect a shared mutable slot
<lock> :> guard
guard [ "do thing under lock" drop ] with-lock
```

`parallel-map` یک API سطح‌بالا است و همان چیزی است که کد اصطلاحی Factor نخست سراغش می‌رود. سه‌گانه‌ی `spawn` / `<promise>` / `?promise` همان چیزی است که `parallel-map` از آن ساخته شده است. این سه‌گانه وقتی به کار می‌آید که الگوی تکرار با map جور درنیاید (برای نمونه، ساختن کارگرهایی که از طریق کانال‌های دیگر پاسخ می‌دهند).

«قفل»ها از *وضعیت تغییرپذیر مشترک* محافظت می‌کنند، معمولاً یک خانه‌ی تاپل یا یک جدول درهم‌سازی که بیش از یک نخ آن را می‌خواند یا در آن می‌نویسد. اگر هرگونه به‌روزرسانی ترکیبیِ غیراتمی در کار باشد، هم خواندن و هم نوشتن را نیازمند قفل بدانید؛ جا انداختن قفل در هر یک از این دو طرف، دستور کلاسیک ایجاد یک خواندن پاره است.
