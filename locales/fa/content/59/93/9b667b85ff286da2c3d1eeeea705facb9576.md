# درباره

[رکورد][records] یک ساختار داده است که اطلاعات مرتبط را همراه با برچسب کنار هم جمع می‌کند.
رکورد شبیه به آبجکت در JavaScript یا Java است، یا شبیه به struct در C یا Rust، اما چند تفاوت کلیدی دارد.

## ساختن رکورد

رکورد با آکولاد [ساخته می‌شود][create] و عناصر آن با کاما از هم جدا می‌شوند.

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

نوع یک رکورد هم با نحوه‌ی نگارش مشابهی تعریف می‌شود، با این تفاوت که علامت‌های تساوی `=` با علامت‌های دونقطه `:` جایگزین می‌شوند.

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

تکرار این تعریف‌های نوع دست‌وپاگیر است، بنابراین استفاده از یک [نام مستعار نوع][record-types] برای به اشتراک گذاشتن تعریف، روشی رایج است.

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

نام مستعار نوع به‌طور خودکار یک تابع سازنده هم برای رکورد فراهم می‌کند.
این گاهی غافلگیرکننده است، چون توابع در Elm باید با حرف کوچک شروع شوند، اما سازنده‌های نوع یکی از استثناها هستند.

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

## دسترسی به فیلدهای رکورد

راه اصلی [دسترسی به مقدار یک فیلد از یک نمونه‌ی رکورد][access] استفاده از نشانه‌گذاری نقطه‌ای است، مانند `firefly.creator`.
کامپایلر Elm همچنین از توابع دسترسی ویژه‌ای پشتیبانی می‌کند که با یک نقطه `.` شروع می‌شوند، مانند `.creator`، و روی هر رکوردی که فیلدی با آن اسم داشته باشد کار می‌کنند.
این دومین استثنا از قاعده‌ی شروع توابع با حرف کوچک است.
در واقع توابع تعریف‌شده توسط برنامه‌نویس باید با حرف کوچک شروع شوند، اما دو مثالی که همین حالا دیدیم توسط کامپایلر ساخته می‌شوند، نه برنامه‌نویس.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

رکورد را می‌توان در اتصال‌ها هم با [تطبیق الگوی رکورد][pattern-matching] از هم باز کرد.
از هم باز کردن روی هر رکوردی که فیلدهایی با اسم‌های مربوطه داشته باشد کار می‌کند.

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

## به‌روزرسانی رکورد

رکورد تغییرناپذیر است، مثل همه‌چیز در Elm؛ پس وقتی رکوردی تعریف می‌شود، مقادیر فیلدهایش هرگز تغییر نمی‌کنند.
یک [نحوه‌ی نگارش ویژه برای ساختن نسخه‌ای از یک رکورد موجود با تغییر یک یا چند فیلد][update] وجود دارد.
این نحوه‌ی نگارش از نماد خط عمودی `|` استفاده می‌کند تا رکورد اصلی را از فیلدهایی که تغییر خواهند کرد جدا کند، مانند `{ oldRecord | field1 = newValue }`.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

## مقایسه‌ی رکورد

Elm از [تساوی ساختاری][equality] استفاده می‌کند، یعنی دو نمونه از یک رکورد با مقادیر یکسان برابرند.

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

## رکورد گسترش‌پذیر

Elm همچنین از [تایپ ساختاری][structural-typing] پشتیبانی می‌کند؛ یعنی اگر تابعی رکوردی با فیلدهای x و y بخواهد، با هر رکوردی که آن فیلدها را داشته باشد کار می‌کند، مثل نقاط دوبعدی، نقاط سه‌بعدی، سفینه‌های فضایی و غیره.
آن نوع‌های رکورد در تعریفشان یک خط عمودی `|` دارند، مانند `{ a | x : Float, y : Float }`، و در اصطلاح Elm «رکورد گسترش‌پذیر» نامیده می‌شوند.
مراقب تفاوت میان یک خط عمودی `|` در تعریف نوع باشید، که تعریف یک رکورد گسترش‌پذیر است (`{ a | x : Int }`)، و یک خط عمودی `|` در یک نمونه‌ی واقعی رکورد، که یعنی داریم چند فیلد آن رکورد را به‌روزرسانی می‌کنیم.

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
