# درباره

در مفاهیم پیشین دیدیم که نوعها در Julia یک سلسله‌مراتب تشکیل می‌دهند و `Any` در بالای آن قرار دارد.

نوع‌های انتزاعی مانند `Number` زیرنوع دارند، اما خودشان نمی‌توانند نمونه‌سازی شوند.
اختصاص دادن یک نوع انتزاعی به یک متغیر، مقادیر آن متغیر را _محدود_ می‌کند تا هر زیرنوعی از آن نوع انتزاعی باشند.
برای مثال:

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

این یک نوع انعطاف‌پذیری در محدود کردن ورودی‌های معتبر به ما می‌دهد.

اما فرض کنید می‌خواهیم یک متغیر هم مقادیر صحیح و هم مقادیر رشته‌ای را بپذیرد؟
این نوع‌ها در یک شاخه از سلسله‌مراتب قرار ندارند.

می‌توانستیم نوع را روی [`Any`][any] تنظیم کنیم، یا بگذاریم به‌صورت پیش‌فرض همان باشد، اما آن‌وقت کنترل روی همه‌ی نوع‌های مجاز را از دست می‌دهیم.

برای رویکردی بهتر، نحوه‌ی نگارش [`Union{ }`][union] را داریم که دو یا چند نوع درون آکولادها فهرست می‌شوند.

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

مثال دیگری همان اجتماع نوع را در امضای یک تابع به کار می‌برد:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

اینجا به نوع یک اسم دادیم، که می‌تواند کوتاه‌نویسی راحتی فراهم کند اما اکیداً ضروری نیست.
تابع `g(z::Union{Integer, String}) = z^3` همین‌طور رفتار می‌کند.

درباره‌ی امضاهای تابع در مفهوم Multiple Dispatch مطالب بسیار بیشتری برای گفتن وجود خواهد داشت.

## اجتماع‌ها با `nothing`

چندین زبان دیگر نوع‌هایی دارند که ممکن است مقدار داشته باشند یا نداشته باشند، با اسم‌هایی مانند `Option`، `Nullable` یا `Maybe`.

Julia نحوه‌ی نگارش خاصی برای این کار ندارد، اما اجتماع‌های نوع تعمیمی از همان ایده هستند.

در مفهوم [`Nothingness`][nothingness] دیدیم که Julia راه‌های گوناگونی برای نمایش نبودِ مقدار دارد، از جمله [`nothing`][nothing] و [`missing`][missing].
هر کدام از این‌ها را می‌توان در یک اجتماع نوع گنجاند.

برای مثال، در تعریف نوعی [لیست پیوندی][linked]، به روشی نیاز داریم که اگر گره دیگری وجود نداشته باشد، لیست را پایان دهد.
`Nothing` نوعی است که مقدار یگانه‌اش `nothing` است و این تعریف `Node` امکان می‌دهد که پایان زنجیره را علامت بدهیم:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

به همین ترتیب، `missing` می‌تواند به‌عنوان جانگهدار برای مقدارهای غایب استفاده شود، به‌ویژه در مجموعه‌هایی مانند بردارها.
مثال زیر بسیار ساختگی است، اما مقدارهای `missing` در مجموعه‌داده‌های دنیای واقعی رایج‌اند.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
