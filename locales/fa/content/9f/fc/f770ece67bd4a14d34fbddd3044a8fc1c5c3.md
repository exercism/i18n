# درباره نویسه

این موضوع بالقوه _بزرگ_ است!
می‌توان کتابی طولانی درباره‌اش نوشت، و چند نفر هم این کار را کرده‌اند (در Amazon عبارت «unicode book» را جست‌وجو کنید تا چند نمونه ببینید).

## یک تاریخچه‌ی بسیار کوتاه

کار با نویسه‌ها در رایانه در دهه‌های پیشین بسیار ساده‌تر بود، زمانی که برنامه‌نویسان فرض می‌کردند انگلیسی تنها زبان مهم است.
یعنی: ۲۶ حرف، بزرگ و کوچک، ۱۰ رقم، چند علامت نگارشی، به‌علاوه‌ی یک کد (0x07) برای به صدا درآوردن زنگ، و همه‌ی این‌ها در ۷ بیت جا می‌شد: مجموعه‌نویسه‌ی [ASCII][wiki-ascii].

طبیعتاً مردم شروع کردند به پرسیدن که پس تکلیف à، ä و Ł چه می‌شود، بعد افراد دیگری درباره‌ی ऄ، ஹ و ญ پرسیدند، و جوان‌ها ایموجی 😱 می‌خواستند.
چه باید کرد؟

خلاصه‌ی ماجرا اینکه بسیاری از افراد باهوش و شکیبا مجبور شدند سال‌ها در کمیته‌ها کار کنند و جزئیات مجموعه‌نویسه‌ی [Unicode][web-unicode] و کدگذاری‌هایی مانند [UTF-8][wiki-utf-8] را مشخص کنند، و کلی نرم‌افزار نیازمند بازنویسی _بسیار_ پیچیده‌ای شد.
همچنین باگ‌های جدید زیادی به وجود آمد.

برای اینکه _همه‌چیز_ از کار نیفتد، طراحی یونیکد/UTF-8 تضمین می‌کند که ۱۲۷ کد اول با ASCII یکسان باشند _(حتی زنگ)_.

## نویسه‌ها در Kotlin

زبان‌هایی که پس از حدود ۲۰۰۵ طراحی شدند این مزیت بزرگ را دارند که استاندارد نسبتاً پایداری از یونیکد از قبل وجود داشت.

Kotlin (که نخستین بار در ۲۰۱۱ منتشر شد) می‌توانست فرض کند که کاربران از زبان‌های (انسانی) گوناگون استفاده می‌کنند و برای بیان آن‌ها به یونیکد نیاز خواهند داشت.

~~~~exercism/advanced
[نویسه‌ها][ref-char] در Kotlin همانند `char` در JVM، [`codepoints`][wiki-codepoint] شانزده‌بیتی (UTF-16) هستند.
این برای بیان بیشتر الفباهای نوشتاری کافی است، اما برای تمام گستره‌ی ایموجی‌ها نه.

استاندارد کامل یونیکد برای هر نویسه تا شش بایت (۴۸ بیت) استفاده می‌کند (که [`grapheme`][wiki-grapheme] نامیده می‌شود).

`Strings` در Kotlin با به‌کارگیری چند کدپوینت برای هر نویسه، در صورت نیاز، از این استاندارد کامل پشتیبانی می‌کنند.
برای مثال، 😱 از `\uD83D` و `\uDE31` ساخته می‌شود.

متأسفانه Java پشتیبانی داخلی از گرافم ندارد، و Kotlin هم برای حفظ سازگاری چنین پشتیبانی‌ای ندارد.

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


لیترال‌های نویسه با کوتیشن تکی نوشته می‌شوند و با رشته‌هایی که در کوتیشن دوتایی نوشته می‌شوند فرق دارند.
این موضوع احتمالاً برای افرادی که از دنیای C/C++ می‌آیند واضح است، اما می‌تواند برای برنامه‌نویسان Python و JavaScript گیج‌کننده باشد.

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

تبدیل میان `Char` و `Int` ساده است:

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

کامپایلر _برخی_ شکل‌های حساب عدد صحیح را روی `Char`ها مجاز می‌داند:

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## چند تابع برای `Char`

مثل همیشه، [توابع بسیار زیادی][ref-char-lib] وجود دارد که نمی‌توان اینجا به همه‌شان پرداخت، پس این‌ها فقط یک گزیده است.

- برای الفباهای مناسب، بزرگی و کوچکی حروف را با [`uppercase()`][ref-uppercase] و [`lowercase()`][ref-lowercase] تغییر دهید.
- بزرگی و کوچکی حروف را با [`isUpperCase()`][ref-isuppercase] و [`isLowerCase()`][ref-islowercase] بررسی کنید.
- نوع نویسه را با این‌ها بررسی کنید:
  - [`isLetter()`][ref-isletter]، بسیاری از الفباها را پوشش می‌دهد (دسته‌های Lu، Ll، Lt، Lm و Lo در یونیکد)
  - [`isDigit()`][ref-isdigit]، در بازه‌ی 0..9 (دسته‌ی Nd در یونیکد)
  - `isLetterOrDigit()`، دو مورد قبلی را با هم ترکیب می‌کند
  - [`isWhitespace()`][ref-iswhitespace]، هر نویسه‌ی فضای خالی (دسته‌های Cc، Zp، Zl و Zs در یونیکد)

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

همچنین [عبارت‌های باقاعده][ref-regex] (که موضوع یکی از مفاهیم بعدی خواهد بود) امکان جست‌وجو و دست‌کاری قدرتمند را فراهم می‌کنند.

## تبدیل‌های متقابل میان `Char`، فهرست و رشته

برای تبدیل یک `String` به یک `List` از `Char`ها می‌توانیم از `toList()` استفاده کنیم.

برای تبدیل یک `List` از `Char`ها به یک `String`، تابع [`joinToString()`][ref-jointostring] وجود دارد که یک جداکننده (اغلب رشته‌ی خالی) را به عنوان آرگومان می‌گیرد.

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

توجه داشته باشید که `joinToString()` روی یک List یا Array عمل می‌کند.
برای _تبدیل نوع_ یک `Char` تنها به رشته‌ای یک‌نویسه‌ای، از `toString()` استفاده کنید.

```kotlin
'a'.toString() // => "a"
```

برای بررسی اینکه آیا نویسه‌ای در یک `String`، یا در یک فهرست یا آرایه‌ی `Char` وجود دارد، `in` را داریم که به تابع [`contains()`][ref-contains] نگاشت می‌شود.

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
