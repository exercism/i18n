# درباره

واژگان، واحد سازماندهی در Factor است: مجموعه‌ای نام‌دار از تعریف‌های واژه.

```factor
USING: kernel ;
IN: greetings.formal

: hello ( name -- str ) "Greetings, " prepend ;
```

## چیدمان فایل و پوشه

اسم‌های واژگان از `.` به عنوان جداکننده استفاده می‌کنند. مسیر از همین نقطه‌ها پیروی می‌کند:

| واژگان | فایل |
| ---                    | ---                                        |
| `greetings`            | `greetings/greetings.factor`               |
| `greetings.formal`     | `greetings/formal/formal.factor`           |
| `greetings.casual`     | `greetings/casual/casual.factor`           |

بارگذارِ Factor واژگان‌ها را با پیمودن *ریشه‌های واژگان* پیدا می‌کند (ریشه‌ی پروژه و کتابخانه‌ی پایه‌ی همراهش)، تا اینکه پوشه‌ای بیابد که اسمش با هر بخش مسیر مطابقت داشته باشد. بخش آخر به عنوان اسم فایل تکرار می‌شود.

## `USING:` و `IN:`

`USING:` (و در کنارش `USE:` برای افزودن یک واژگان در هر بار) واژگان‌های دیگر را به مسیر جست‌وجوی فایل جاری می‌آورد. `IN:` اعلام می‌کند که واژه‌های تعریف‌شده در این فایل به کدام واژگان *تعلق دارند*؛ اسم کاملشان با همان پیشوند شروع می‌شود.

```factor
USING: kernel sequences greetings.formal ;
IN: greetings

: greet-everyone ( names -- strs )
    [ hello ] map ;
```

اینجا `greet-everyone` در `greetings` قرار دارد، `hello` را از `greetings.formal` فراخوانی می‌کند و `map` را از `sequences`.

## چرا یک راه‌حل را میان واژگان‌ها تقسیم کنیم

تقسیم کد میان واژگان‌ها به شما امکان می‌دهد:

- واژه‌های کمکی کوچک را بر اساس وظیفه‌شان دسته‌بندی کنید، جدا از روال سطح‌بالایی که آن‌ها را ترکیب می‌کند.
- از این واژه‌های کمکی از جای دیگری دوباره استفاده کنید، بی‌آنکه روال اصلی را هم با خود بکشید.
- هر فایل را به عنوان یک لایه‌ی منسجم از انتزاع بخوانید.

بارگذارِ Factor آن‌قدر سریع و تنبل است که تقسیم *به سمت پایین* به واژگان‌های کوچک‌تر هزینه‌ی چندانی ندارد. رسم رایج در کتابخانه‌ی استاندارد این است که کد را تا حد ممکن به واحدهای کوچک‌تر بشکنید.
