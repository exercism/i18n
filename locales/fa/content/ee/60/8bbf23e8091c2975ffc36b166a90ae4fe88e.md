# مقدمه

Elixir از «Behaviour»ها استفاده می‌کند تا رابط‌های عمومی مشترکی فراهم کند و در همان حال پیاده‌سازی‌های اختصاصی هر ماژولی را که آن را پیاده‌سازی می‌کند ممکن سازد. یکی از نمونه‌های رایج این کار، «Access Behaviour» است.

«Access Behaviour» یک رابط مشترک برای بازیابی داده از یک ساختمان داده‌ی مبتنی بر کلید فراهم می‌کند. Access Behaviour برای `map`ها و `keyword list`ها پیاده‌سازی شده است، اما بیایید کاربردش را برای `map`ها ببینیم تا با آن آشنا شویم. Access Behaviour مشخص می‌کند که وقتی یک `map` دارید، می‌توانید بعد از آن «کروشه» بگذارید و سپس با کلید، مقدار مرتبط با آن کلید را به دست آورید.

```elixir
# Suppose we have these two maps defined (note the difference in the key type)
my_map = %{key: "my value"}
your_map = %{"key" => "your value"}

# Obtain the value using the Access Behaviour
my_map[:key] == "my value"
your_map[:key] == nil
your_map["key"] == "your value"
```

اگر کلید در ساختمان داده وجود نداشته باشد، `nil` برگردانده می‌شود. این می‌تواند منشأ رفتار ناخواسته باشد، چون خطایی ایجاد نمی‌کند. توجه کنید که خود `nil` هم Access Behaviour را پیاده‌سازی می‌کند و برای هر کلیدی همیشه `nil` برمی‌گرداند.
