# معرفی خط لوله و فهرست دستورها

تا اینجا دیده‌ایم که چطور دستورهای ساده بنویسیم؛ دستورهایی که پس از آن‌ها آرگومان‌ها می‌آیند.
حالا می‌خواهیم ببینیم چطور با ترکیب دستورهای ساده، دستورهایی پیچیده‌تر بسازیم.

## ورودی و خروجی

پیش از شروع، یک آشنایی کوتاه با ورودی/خروجی.

فرایندها «کانال‌های ورودی/خروجی استاندارد» دارند.

* یک فرایند می‌تواند _ورودی_ را از «stdin» مصرف کند.
* یک فرایند می‌تواند _خروجی_ را روی «stdout» بفرستد.
* یک فرایند می‌تواند _خروجی خطا_ را روی «stderr» بفرستد.

دستور `tr` نمونه‌ی بسیار خالصی از این موضوع است.
تنها کاری که می‌کند این است: متن را از ورودی‌اش می‌خواند، نویسه‌ها را تبدیل می‌کند و متن حاصل را به خروجی‌اش می‌فرستد.

بعدتر در برنامه‌ی درسی، بیشتر درباره‌ی کار با کانال‌های «stdio» خواهیم دید.

## خط لوله

این یکی از قابلیت‌های فوق‌العاده‌ی برنامه‌نویسی شل است.
خط لوله به شما امکان می‌دهد روی جریانی از متن، تبدیل‌های پیچیده انجام دهید.

برای تولید فهرستی مرتب از کاربران:

```bash
cat /etc/passwd | cut -d : -f 1 | sort
```

نماد لوله (`|`) خروجی یک دستور را به ورودی دستور دیگر وصل می‌کند.
`cut` خروجی `cat` را می‌خواند و `sort` خروجی `cut` را.

~~~~exercism/advanced
* به‌طور پیش‌فرض، هر دستور در یک خط لوله در یک زیرشل جداگانه اجرا می‌شود.
  (زیرشل یک فرایند فرزند است که نسخه‌ای از شل در حال اجرا است.)

* اجرای خط لوله هزینه‌ی کارایی دارد.
  اگر دیدید خط لوله‌های طولانی از دستورهای مشابه دارید، به ترکیب آن‌ها در یک دستور واحد فکر کنید.
  برای نمونه، خط لوله‌هایی که چند بار از `grep`، `cut`، `sed`، `awk` و `tr` استفاده می‌کنند، معمولاً می‌توان برای کارایی بیشتر در یک دستور `awk` ترکیب کرد.

* وضعیت خروج یک خط لوله، وضعیت خروج آخرین دستور در آن خط لوله است.
  یعنی اگر دستورهای قبلی شکست خورده باشند ولی آخرین دستور موفق شده باشد، وضعیت خروج کل خط لوله صفر است.

  تنظیمی در شل هست که می‌تواند این را تغییر دهد؛
  اگر تنظیم «pipefail» فعال باشد (با `set -o pipefail`)، وضعیت خروج خط لوله چنین خواهد بود:
  * اگر همه‌ی دستورها موفق شوند، صفر؛ در غیر این صورت
  * _**آخرین** وضعیت خروج ناصفر_ دستورهای آن خط لوله.
~~~~

## فهرست دستورها

فهرست دستورها دنباله‌ای از خط لوله‌هاست که با `;` (یا خط جدید)، `&&` یا `||` از هم جدا می‌شوند.

* `A; B` فهرستی از دستورهاست که در آن `B` پس از پایان `A` اجرا می‌شود.
* `A && B` که در آن `B` فقط در صورت موفقیت `A` اجرا می‌شود (با وضعیت صفر خارج می‌شود).
* `A || B` که در آن `B` فقط در صورت شکست `A` اجرا می‌شود (با وضعیت ناصفر خارج می‌شود).

وضعیت خروج یک فهرست دستورها، وضعیت خروج آخرین دستوری است که اجرا شده است.

عملگرهای `&&` و `||` را می‌توان زنجیره‌ای به کار برد، به این ترتیب که دستور بعدی بر پایه‌ی وضعیت دستورهای پیشین به‌صورت شرطی اجرا می‌شود.
برای نمونه

```bash
A && B && C && D || E
```

* اگر A موفق شود، B اجرا می‌شود،
* اگر A و B موفق شوند، C اجرا می‌شود،
* اگر A و B و C موفق شوند، D اجرا می‌شود،
* اگر **هر یک** از A، B، C یا D شکست بخورد، E اجرا می‌شود.

~~~~exercism/caution
از این عملگرهای منطقی کم استفاده کنید.
خیلی زود به کدی ناخوانا یا منطقی دشوارفهم می‌انجامند.

برای نمونه، ممکن است فکر کنید این دو یکی هستند:

```bash
if A; then B; else C; fi
```

```bash
A && B || C
```

تفاوت اینجاست: C چه زمانی اجرا می‌شود؟

* در قطعه‌ی اول (دستور شرطی)، C فقط در صورت شکست A اجرا می‌شود.
* در قطعه‌ی دوم، C در صورتی اجرا می‌شود که A شکست بخورد _یا A موفق شود ولی B شکست بخورد_!
~~~~

### کاربردهای فهرست دستورها

در ادامه چند نمونه می‌بینیم که فهرست دستورها می‌تواند کد را ساده‌تر کند.

#### خواندن بلوک‌هایی از خطوط از یک فایل

فرض کنید فایل داده‌ای دارید که اطلاعاتی درباره‌ی مثلث‌ها در آن است
و هر مثلث با سه خط جداگانه نمایش داده می‌شود که اضلاع مثلث را در خود دارند.

```bash
$ cat triangle.dat
3
4
5
9
12
14
```

می‌توانید از یک حلقه‌ی while استفاده کنید که شرطش سه دستور `read` جداگانه است:

```bash
while read a && read b && read c; do
    if is_pythagorean "$a" "$b" "$c"; then
        echo "$a:$b:$c is pythagorean"
    else
        echo "$a:$b:$c is not pythagorean"
    fi
done < triangle.dat
```

با فرض اینکه `is_pythagorean` دستوری باشد که تعیین می‌کند آیا سه ضلع در معادله‌ی فیثاغورس صدق می‌کنند یا نه، خروجی چنین خواهد بود:

```none
3:4:5 is pythagorean
9:12:14 is not pythagorean
```

#### ادعاها

بسیاری از زبان‌های برنامه‌نویسی گونه‌ای ادعا دارند که اگر شرطی برقرار نباشد، استثنایی پرتاب می‌شود

```
assert(user == "Administrator", "wrong user");
```

می‌توانیم در Bash از عملگر OR استفاده کنیم تا آن کارکرد را شبیه‌سازی کنیم:

```bash
die () { # a little convenience function
    echo "$*" >&2
    exit 1
}

[[ $user == "Administrator" ]] || die "wrong user"
[[ $password == "secret!" ]]   || die "incorrect password"
```

## ملاحظات سبک

فهرست‌های دستور طولانی خیلی زود ناخوانا می‌شوند.
استفاده‌ی فراوان از خطوط جدید می‌تواند بسیار کمک کند.

این نمونه را در نظر بگیرید که در آن اگر دو شرط برقرار باشند، واژه‌ای به یک آرایه افزوده می‌شود.

```bash
[[ "$word" != "$topic" ]] && [[ "$key" == "$(sorted "$topic")" ]] && anagrams+=("$candidate")
```

Bash اجازه می‌دهد بعد از یک لوله یا یک عملگر منطقی خط جدید بگذارید.

```bash
[[ "$word" != "$topic" ]] &&
[[ "$key" == "$(sorted "$topic")" ]] &&
anagrams+=("$candidate")
```

با این حال، عملگر در انتهای خط به‌راحتی از چشم می‌افتد.
با استفاده از _ادامه‌ی خط_ می‌توانید عملگر را اول بگذارید و این‌طور آشکارتر می‌شود که فهرست ادامه دارد:

```bash
[[ "$word" != "$topic" ]] \
&& [[ "$key" == "$(sorted "$topic")" ]] \
&& anagrams+=("$candidate")
```

~~~~exercism/note
_ادامه‌ی خط_ دنباله‌ای دو نویسی از «بک‌اسلش» و «خط جدید» است (`\` + `\n`).
وقتی Bash آن دنباله را می‌بیند، به‌سادگی از کد حذف می‌شود و بدین ترتیب خط جاری را با خط بعدی _ادامه_ می‌دهد.
دقت کنید که بین بک‌اسلش و خط جدید هیچ فاصله‌ای نباشد.
~~~~

نمونه‌ی دیگری هم هست

```bash
printf "%s\n" "${numbers[@]}" | bc --mathlib | sort --general-numeric-sort
```

یا

```bash
printf "%s\n" "${numbers[@]}" \
| bc --mathlib \
| sort --general-numeric-sort
```
