# درباره

استثناها گونهای از مدیریت خطا هستند.
به آنها استثنا میگویند، چون معمولاً هنگام روبه‌رو شدن با رویدادی غیرمنتظره ظاهر می‌شوند.

در هر نقطه‌ای از کدمان می‌توانیم یک استثنا را `raise` کنیم.
این کار را با متد `raise` انجام می‌دهیم و یک شیء به آن می‌دهیم؛ معمولاً یک شیء Exception، هرچند می‌توانیم از رشته‌های ساده هم استفاده کنیم.
برای مثال، در اسکلت‌های تمرین می‌بینید که از `RuntimeError` توکار استفاده می‌کنیم تا به Ruby بگوییم متدی پیاده‌سازی نشده است.
همچنین می‌توانید از نحوه‌ی نگارش خلاصه‌ی `raise(ExceptionObject, params)` استفاده کنید.
اگر کلاس استثنا حذف شود، به‌طور پیش‌فرض از `RuntimeError` استفاده می‌شود.

برای مثال:

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

وقتی Ruby این را می‌بیند، خطا را به بالای برنامه می‌فرستد و سپس خارج می‌شود.

برای مثال، اگر بخواهید چیزی را بر صفر تقسیم کنید، چیزی شبیه این می‌بینید:

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

مهم است که توجه داشته باشید استثناها باید در مواردی به کار روند که اتفاقی استثنایی می‌افتد، خطایی که به رسیدگی ویژه نیاز دارد.
استثناها نباید برای کنترل جریان برنامه به کار روند، چون این کار طراحی بدی به شمار می‌آید که اغلب به عملکرد و قابلیت نگهداری بدی می‌انجامد.

## سلسله‌مراتب کلاس‌ها

در Ruby استثناها از یک سلسله‌مراتب کلاس‌ها پیروی می‌کنند که در آن `Exception` کلاس پایه است.
این‌ها رایج‌ترین استثناهای توکار Ruby هستند:

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

وقتی خطاهای یک کلاس خاص را `rescue` می‌کنید، خطاهای فرزندان آن هم `rescue` می‌شوند.
به همین دلیل است که `rescue` کردن از `Exception` می‌تواند خطرناک باشد.
Ruby از استثناها برای مدیریت پیام‌های «سیگنال»های سیستم‌عامل هم استفاده می‌کند، برای مثال `ctrl-c`.
این یعنی `rescue` کردن از `Exception` این «سیگنال»های سیستمی را هم می‌گیرد.
بنابراین برای جلوگیری از رفتارهای غیرمنتظره، روش رایج برای گرفتن «همه‌ی خطاها» این است که از `StandardError` استفاده کنید.

## نحوه‌ی نگارش `rescue`

Ruby همچنین بندهای `rescue` گسترده‌ای برای موقعیت‌هایی که به رسیدگی ویژه نیاز دارند فراهم می‌کند:

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

این می‌تواند برای مثال هنگام کار با ورودی/خروجی شبکه مفید باشد، جایی که همیشه باید یادمان باشد اتصال را ببندیم.

بلوک‌های `rescue` در Ruby می‌توانند از کلیدواژه‌ی `retry` هم استفاده کنند که همه‌چیز بین begin و rescue را دوباره اجرا می‌کند:

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
