# مقدمه

دستکاری پشته برای توابع کوتاه خوب است. وقتی یک تابع چند ورودی دارد و لازم است با اسم به آنها ارجاع بدهید، Factor امکانی به اسم «متغیرهای محلی» در اختیارتان می‌گذارد: اتصال‌های نامداری که با `::` (برای تعریف‌های تابع) یا `[| | ]` (برای لامبداهای درون‌خطی) معرفی می‌شوند.

## `:: ( inputs -- outputs )`

`:` را با `::` عوض کنید تا اسم‌های ورودی در بدنه به متغیرهای محلی تبدیل شوند:

```factor
USING: locals ;

:: hypotenuse ( a b -- c )
    a a *
    b b *
    + sqrt ;
```

این را با نسخه‌ی دستکاری پشته مقایسه کنید:

```factor
! DOCTEST: SKIP   (shown for comparison — would re-define hypotenuse)
: hypotenuse ( a b -- c )
    [ sq ] bi@ + sqrt ;
```

هر دو درست‌اند؛ متغیرهای محلی وقتی می‌درخشند که به یک ورودی بیش از یک بار ارجاع داده شود یا ترتیب عملیات به‌طور طبیعی با ترتیب پشته جور در نیاید.

## اتصال مقادیر میانی با `:>`

داخل بدنه‌ی یک `::` (یا یک لامبدای درون‌خطی `[| ... |]`)، `:>` یک مقدار را از بالای پشته‌ی داده برمی‌دارد و آن را به یک متغیر محلی تازه متصل می‌کند:

```
value :> name      ! immutable binding
value :> name!     ! mutable binding (name! is its setter)
```

شکل تغییرناپذیر رایج‌تر است؛ از آن برای نام‌گذاری یک مقدار میانی استفاده کنید تا بدنه از بالا به پایین خوانده شود:

```factor
USING: locals math ;

:: average-3 ( x y z -- avg )
    x y + z + :> sum
    sum 3 / ;
```

گونه‌ی `!` متغیر محلی را تغییرپذیر اعلام می‌کند؛ در ادامه‌ی بدنه، `value name!` (بدون دونقطه و بدون `:>`) مقدارش را دوباره تعیین می‌کند:

```factor
USING: kernel locals math math.order ;

:: clamped ( x lo hi -- y )
    x :> v!
    v lo < [ lo v! ] when
    v hi > [ hi v! ] when
    v ;
```

متغیرهای محلی تغییرپذیر داخل توابع پیمایشی که در تمرین‌های بعدی می‌بینید (مثلاً `while`) می‌درخشند.

## `[let`، یک دامنه از هر جا

`:>` فقط داخل یک دامنه‌ی واژگانی کار می‌کند، دامنه‌ای که `::` و `[| ... |]` خودکار می‌سازند. برای معرفی متغیرهای محلی از یک تابع معمولی که با `:` تعریف شده یا در محیط تعاملی، کد را در `[let ... ]` بپیچید:

```
[let code :> name code :> name ... body ]
```

هر `:> name` مقدار بالای پشته‌ی عبارت قبلی را متصل می‌کند؛ اتصال‌ها برای بقیه‌ی فرم قابل مشاهده‌اند.

```factor
USING: locals math ;

[let 3 :> x 4 :> y x x * y y * + ] .   ! => 25
```

`[let` پلی است میان تعریف‌های `:` به سبک پشته و اتصال‌های نامدار؛ زمانی به کار می‌آید که فقط بخشی از یک تابع از متغیرهای محلی سود ببرد.

## لامبداها، `[| inputs | body ]`

داخل یک قطعه‌کد، `[| inputs | body ]` متغیرهای محلی‌ای را معرفی می‌کند که بدنه می‌تواند با اسم به آنها ارجاع بدهد. این کار به‌ویژه با توابع مرتبه‌بالایی مثل `assoc-map` مفید است، که قطعه‌کدش هم `key` و هم `value` را دریافت می‌کند:

```factor
USING: assocs locals ;

H{ { "a" 1 } { "b" 2 } }
[| key value | key value neg ] assoc-map .
! => H{ { "a" -1 } { "b" -2 } }
```

همین شکل برای `map-index` (در [`sequences`][sequences]) هم کار می‌کند، که قطعه‌کدش هم عنصر و هم اندیس آن را دریافت می‌کند. اسم‌ها روشن می‌کنند که هر عملوند چه نقشی بازی می‌کند:

```factor
USING: locals sequences ;

! Divide each element by its 1-based position:
{ 10 80 270 } [| elt i | elt i 1 + / ] map-index .
! => { 10 40 90 }
```

اثر پشته‌ای لامبدا را فهرست ورودی‌ها و آنچه بدنه‌اش تولید می‌کند تعیین می‌کند.

## چه وقت از متغیرهای محلی استفاده کنیم

سراغ متغیرهای محلی بروید وقتی:

- یک ورودی یکسان در بیش از یک جا استفاده می‌شود.
- ترتیب طبیعی عملیات با ترتیب پشته همخوانی ندارد و `dup`/`swap`/`rot` که برای درست‌کردنش لازم است، خواندنش سخت است.
- داخل یک لامبدای درون‌خطی هستید که به تابعی مرتبه‌بالا داده شده و آن تابع چند مقدار را یکجا به شما می‌دهد (مثل `assoc-map`).

وقتی بدنه جریانی خطی و تمیز است، تعریف‌های ساده‌ی `:` کوتاه‌تر و دست‌کم به همان اندازه خوانا می‌مانند.

## `assoc-map`، هر بار یک درایه

`assoc-map` (در [`assocs`][assocs]) یک قطعه‌کد را روی هر درایه‌ی یک مجموعه‌ی انجمنی نگاشت می‌کند:

```
assoc-map ( assoc quot: ( key value -- newkey newvalue ) -- newassoc )
```

یک لامبدای متغیرهای محلی، تمیزترین راه برای نوشتن این قطعه‌کد است.

## نگاهی دوباره به `cond`

وقتی لازم است روی `f` یا روی یک مقدار عددی انشعاب بگیرید، `cond` دقیقاً شکل درست است؛ به `case` نیازی نیست، چون مقدار واحدی برای مقایسه وجود ندارد.
