# پیوست دستورالعمل

## مسئولیت‌های Roc و Host

در کد Roc معمولاً روی منطق کسب‌وکار تمرکز می‌کنیم و پلتفرم است که هم‌روندی و وضعیت مشترک را مدیریت می‌کند.
بنابراین در این تمرین فقط کافی است عملیات حساب را در `BankAccount.roc` پیاده‌سازی کنید و لازم نیست نگران هم‌روندی باشید.
حساب‌ها در ابتدا بسته‌اند، بازگشایی مجدد موجودی را بازنشانی می‌کند و واریزها و برداشت‌ها باید مثبت باشند.

## دموی اختیاری سرور

فایل `bank-account-demo.roc` که همراه تمرین آمده نشان می‌دهد پیاده‌سازی شما چطور می‌تواند در یک سرویس وب کوچک به کار برود.
می‌توانید آن را در ویرایشگر بخوانید، اما این فایل از آزمون‌ها مستقل است و بخشی از راه‌حل شما نیست.

برای اجرای دمو، باید [Roc را روی رایانه‌ی خود نصب کنید](https://www.roc-lang.org/install/)، [Exercism CLI](https://exercism.org/cli-walkthrough) را نصب کنید و سپس این فرمان را در ترمینال اجرا کنید:

```sh
exercism download --exercise=bank-account --track=roc
```

در ادامه، `BankAccount.roc` را پیاده‌سازی کنید و با فرمان زیر بیازماییدش (اگر مسیر دانلودی که CLI چاپ می‌کند با مسیر زیر فرق دارد، آن را تغییر دهید):

```sh
cd ~/Exercism/roc/bank-account
roc test bank-account-test.roc
```

وقتی همه‌ی آزمون‌ها قبول شدند، می‌توانید سرور دمو را با فرمان زیر راه‌اندازی کنید:

```sh
roc bank-account-demo.roc
```

سرور از [پلتفرم basic-webserver](https://github.com/roc-lang/basic-webserver) و پشتیبانی داخلی آن از SQLite استفاده می‌کند (Roc در نخستین اجرا پلتفرم را دانلود می‌کند).
نیازی به سرور پایگاه‌داده‌ی جداگانه نیست.
سرور روی `http://127.0.0.1:8000` گوش می‌دهد و فایل `bank-account-demo.db` را در پوشه‌ی جاری شما می‌سازد (برای استفاده از فایل پایگاه‌داده‌ای دیگر، `DB_PATH` را تنظیم کنید).
سرور را با Ctrl-C متوقف کنید.
داده‌ها پس از راه‌اندازی مجدد هم باقی می‌مانند.

در ترمینال دیگری می‌توانید سرویس وب را با `curl` فراخوانی کنید (در ویندوز همه‌جا از `curl.exe` استفاده کنید تا با مستعار `curl` در PowerShell قاطی نشود).
برای نمونه، این‌طور حساب شماره‌ی ۱۲۳ را باز می‌کنید، ۵۰ واریز می‌کنید، ۱۰ برداشت می‌کنید و موجودی آن را بررسی می‌کنید:

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/open
curl -X POST http://127.0.0.1:8000/accounts/123/deposit/50
curl -X POST http://127.0.0.1:8000/accounts/123/withdraw/10
curl http://127.0.0.1:8000/accounts/123/balance
```

موجودی `40` است.
شناسه‌های حساب و مبالغ باید عدد صحیح بدون علامت باشند.
به‌روزرسانی‌ها در صورت موفقیت `OK` برمی‌گردانند و در صورت شکست، خطایی از پیاده‌سازی حساب شما.
برای بستن حساب شماره‌ی ۱۲۳:

```sh
curl -X POST http://127.0.0.1:8000/accounts/123/close
```

برای آزمودن درخواست‌های هم‌زمان در لینوکس/macOS، یک شناسه‌ی حساب تازه بردارید و ۱۰۰ واریز را از هشت کلاینت بفرستید:

```sh
curl -X POST http://127.0.0.1:8000/accounts/456/open
seq 100 | xargs -P 8 -I '{}' curl --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1
curl http://127.0.0.1:8000/accounts/456/balance
```

در ویندوز برای نمونه‌ی موازی از [PowerShell 7+](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows) استفاده کنید:

```powershell
curl.exe -X POST http://127.0.0.1:8000/accounts/456/open
1..100 | ForEach-Object -Parallel { curl.exe --fail --silent --show-error -X POST http://127.0.0.1:8000/accounts/456/deposit/1 } -ThrottleLimit 8
curl.exe http://127.0.0.1:8000/accounts/456/balance
```

همه‌ی واریزها باید موفق شوند و موجودی باید `100` باشد.

## دمو چطور هم‌روندی را مدیریت می‌کند

هر درخواست حساب را می‌خواند، توابع Roc شما را فراخوانی می‌کند و نتیجه را درون یک تراکنش `Immediate` در SQLite ذخیره می‌کند.
عملیات‌های ناموفق بدون تغییر حساب برگشت داده می‌شوند.
SQLite در هر لحظه فقط یک نویسنده را اجازه می‌دهد و همین جلوی آن را می‌گیرد که درخواست‌های هم‌زمان به‌روزرسانی‌های یکدیگر را بازنویسی کنند (حتی وقتی حساب‌ها متفاوت باشند).

توجه: این تمرین از `U64` استفاده می‌کند، اما دمو موجودی‌ها را به‌صورت عدد صحیح SQLite ذخیره می‌کند و به‌روزرسانی‌هایی را که از بیشینه‌ی مقدار `I64` بزرگ‌تر باشند رد می‌کند (`9223372036854775807`).

برای نمونه‌ای از اجرای محاسبات مستقل به‌صورت موازی، [تمرین parallel-letter-frequency](https://exercism.org/tracks/roc/exercises/parallel-letter-frequency) را امتحان کنید.
