# پیوست دستورالعمل‌ها

## پیام‌های استثنا

گاهی لازم است یک [استثنا ایجاد کنید][raise-an-exception]. وقتی این کار را می‌کنید، همیشه باید یک **پیام خطای معنادار** را هم بیاورید تا نشان دهید منبع خطا چیست. این کار کد شما را خواناتر می‌کند و کمک زیادی به Debug می‌کند. در موقعیت‌هایی که می‌دانید منبع خطا از نوع مشخصی است، می‌توانید یکی از [انواع خطای داخلی][built-in-errors] را ایجاد کنید، اما همچنان باید پیام معناداری را هم بیاورید.

این تمرین به‌طور خاص می‌خواهد که اگر پرسش داده‌شده به `answer()` بدشکل یا نامعتبر باشد، یا عملیات ناشناخته‌ای داشته باشد، با [دستور raise][raise-statement] یک `ValueError` را «پرتاب» کنید. آزمون‌ها تنها زمانی قبول می‌شوند که هم `exception` را `raise` کنید و هم پیامی همراه آن بیاورید.
**توجه کنید**: پیام لازم برای هر سناریو متفاوت است، حتی اگر همان _نوع خطا_ ایجاد شود.
آزمون‌ها را با دقت بررسی کنید.

برای ایجاد یک [`ValueError`][value-error] همراه با پیام، پیام را به‌عنوان آرگومانی برای نوع `exception` بنویسید:


```python
# if the question contains an unknown operation.
raise ValueError("unknown operation")

# if the question is malformed or invalid.
raise ValueError("syntax error")
```

برای _رسیدگی_ به یک خطای ایجادشده درون یک بلوک کد مشخص، می‌توان از یک [try-except][handling-exceptions] استفاده کرد.
بلوک‌های `try-except` کدی را که ممکن است خطا ایجاد کند «در بر می‌گیرند» و همه‌ی استثناها را به یک خطا، چند خطا، یا بخش‌های دیگری از کد نگاشت می‌کنند تا مشکل را حل کنند:


```python
while len(equation) > 1:
        try:
           # The questionable/error-prone code goes here,in an indented block
           # It can contain statements, loops, if-else blocks, or other executable code.
           x_value, operation, y_value, *rest = equation
           ...
           ...

        except:
            # Code for what to do when an error gets thrown in the code above.
            # This could be one error, or more complicated logging, error checking and messaging.
            raise ValueError("syntax error")
```
