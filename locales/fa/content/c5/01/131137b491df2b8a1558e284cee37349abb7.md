# مقدمه

زبان برنامه‌نویسی Java برای مدیریت خطاها و سایر رویدادهای استثنایی از «استثنا» استفاده می‌کند.

## استثنا چیست؟

استثنا رویدادی است که در حین اجرای یک برنامه رخ می‌دهد و جریان عادی دستورها را مختل می‌کند.
استثناها در جاوا به‌صراحت پرتاب می‌شوند و نام این کار، «پرتاب استثنا» است.
به عمل مدیریت یک استثنا هم، «گرفتن استثنا» می‌گویند.

در جاوا، همه‌ی استثناها زیرکلاس‌های کلاس `Exception` هستند که خودش زیرکلاسی از `Throwable` است.

جاوا دو نوع استثنا را از هم جدا می‌کند:

1. استثناهای بررسی‌شده
2. استثناهای بررسی‌نشده

### استثناهای بررسی‌شده

استثناهای بررسی‌شده شرایط استثنایی‌ای هستند که یک برنامه باید آن‌ها را پیش‌بینی کند و از آن‌ها بازیابی کند.
یک نمونه از استثنای بررسی‌شده، `FileNotFoundException` است که زمانی رخ می‌دهد که متدی در حال خواندن فایلی باشد که وجود ندارد.

این نوع استثنا در زمان کامپایل بررسی می‌شود: متدهایی که استثناهای بررسی‌شده پرتاب می‌کنند باید این را در امضای متد خود مشخص کنند. همچنین کدی که متدی را فراخوانی می‌کند که ممکن است استثنای بررسی‌شده پرتاب کند، باید آن را مدیریت کند، در غیر این صورت کد کامپایل نمی‌شود.

همه‌ی استثناهای بررسی‌شده زیرکلاس‌هایی از `Exception` هستند که `RuntimeException` را گسترش نمی‌دهند.

### استثناهای بررسی‌نشده

استثناهای بررسی‌نشده شرایط استثنایی‌ای هستند که یک برنامه معمولاً نمی‌تواند آن‌ها را پیش‌بینی کند یا از آن‌ها بازیابی کند.
یک نمونه از استثنای بررسی‌نشده، `NullPointerException` است که زمانی رخ می‌دهد که متدی انتظار دارد مقدار `null` نباشد اما `null` دریافت می‌کند.

این نوع استثنا در زمان کامپایل بررسی نمی‌شود: متدهایی که استثناهای بررسی‌نشده پرتاب می‌کنند ملزم نیستند این را در امضای متد خود مشخص کنند. کدی هم که متدی را فراخوانی می‌کند که ممکن است استثنای بررسی‌نشده پرتاب کند، ملزم نیست آن را مدیریت کند.

همه‌ی استثناهای بررسی‌نشده از `RuntimeException` ارث می‌برند، که خودش گسترشی از `Exception` است.

## پرتاب استثنا

یک متد در جاوا می‌تواند با استفاده از دستور `throw` استثنایی پرتاب کند.

### پرتاب یک استثنای بررسی‌شده

وقتی از داخل یک متد استثنای بررسی‌شده‌ای پرتاب می‌کنید، باید این را با استفاده از کلیدواژه‌ی `throws` در امضای متد مشخص کنید، همان‌طور که در مثال زیر نشان داده شده است.
این کار کد فراخوان را مجبور می‌کند پیش‌بینی کند که ممکن است استثنایی پرتاب شود و آن را به‌طور مناسب مدیریت کند.

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### پرتاب یک استثنای بررسی‌نشده

وقتی از داخل یک متد استثنای بررسی‌نشده‌ای پرتاب می‌کنید، ملزم نیستید این را در امضای متد مشخص کنید، هرچند پشتیبانی می‌شود.

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## مدیریت استثناها

مدیریت استثناها در جاوا با کلیدواژه‌های `try`، `catch` و `finally` انجام می‌شود.

- دستورهای کدی که ممکن است استثنایی پرتاب کنند باید در یک بلوک `try` قرار بگیرند.
- بلوک `try` با یک یا چند بلوک `catch` دنبال می‌شود که استثناهای پرتاب‌شده در بلوک `try` را می‌گیرند.
- بلوک‌های `catch` به‌صورت اختیاری با یک بلوک `finally` دنبال می‌شوند که همیشه بعد از بلوک `try` اجرا می‌شود، فرقی نمی‌کند استثنایی پرتاب شده باشد یا نه.

مثال زیر نشان می‌دهد این کلیدواژه‌ها چگونه کار می‌کنند:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

در این مثال، وقتی هیچ استثنایی پرتاب نمی‌شود، خروجی زیر چاپ می‌شود:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

اما اگر دستور `bankAccount.withdraw(amount)` یک `InsufficientBalanceException` پرتاب کند، خروجی زیر چاپ می‌شود:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

یا در صورتی که `bankAccount.withdraw(amount)` یک استثنای بررسی‌نشده پرتاب کند، خروجی زیر چاپ می‌شود:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## خطا

جاوا دسته‌ی جداگانه‌ای هم به نام «خطا» دارد که مشکلات جدی و بیرون از برنامه هستند.
یک نمونه از خطا، `OutOfMemoryError` است که زمانی رخ می‌دهد که یک برنامه تلاش می‌کند از حافظه‌ای بیشتر از حافظه‌ی موجود در سیستم استفاده کند.

مانند استثناهای بررسی‌نشده، خطاها هم در زمان کامپایل بررسی نمی‌شوند.
تفاوت این است که آن‌ها مشکلات سطح سیستم را نشان می‌دهند و معمولاً توسط ماشین مجازی جاوا یا محیط، و نه خود برنامه، پرتاب می‌شوند.
برنامه‌ها معمولاً نباید تلاش کنند آن‌ها را بگیرند یا مدیریت کنند.

همه‌ی خطاها در جاوا از کلاس `Error` ارث می‌برند.
