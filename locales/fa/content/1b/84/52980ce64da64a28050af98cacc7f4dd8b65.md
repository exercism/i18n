# درباره

[پشته‌ی فراخوانی][stack]، یا به‌طور ساده **پشته**، یک ساختار داده‌ی ویژه است که از بالاترین نقطه‌ی حافظه شروع می‌شود و به سمت پایین رشد می‌کند.

## Push و Pop

پشته حداقل دو عملیات را پشتیبانی می‌کند که دستورهایشان هم‌نام‌اند:

| دستور | عملیات انجام‌شده |
| ----------- | --------------------------------------------------- |
| `push`      | یک عنصر را به پشته اضافه می‌کند |
| `pop`       | آخرین عنصر اضافه‌شده را حذف کرده و برمی‌گرداند |

این یعنی پشته یک ساختار داده‌ی **آخرین ورودی، اولین خروجی (LIFO)** است.

برای پیگیری نقطه‌ی فعلی پشته، جایی که آخرین عنصر قرار دارد، از ثبات `rsp` استفاده می‌شود.

بنابراین، یک دستور [push][push] یک عملوند می‌گیرد و محتویات این عملوند را در پشته ذخیره می‌کند.
از آنجا که پشته به سمت پایین رشد می‌کند، مقدار `rsp` به اندازه‌ی مقدار ذخیره‌شده کاهش می‌یابد.

به همین ترتیب، یک دستور [pop][pop] یک عملوند می‌گیرد و آخرین مقدار موجود در پشته (همان که `rsp` به آن اشاره می‌کند) را در آن ذخیره می‌کند.
سپس مقدار `rsp` به اندازه‌ی مقدار بازیابی‌شده افزایش می‌یابد.

## متغیرهای محلی

همچنین می‌توان مقدار `rsp` را مستقیماً دستکاری کرد.
این کار اغلب برای ایجاد متغیرهای محلی برای یک تابع استفاده می‌شود.

```x86asm
sub rsp, 24 ; this reserves 24 bytes of space in the stack
add rsp, 24 ; this restores the previous value of rsp, "reducing" the stack by 24 bytes
```

توجه کنید که در لحظه‌ی رزرو فضا در پشته، مقداری که در آن فضا ذخیره می‌شود _تعریف‌نشده_ است.

~~~~exercism/note
نه `pop` و نه دستکاری مستقیم `rsp` در واقع محتویات ذخیره‌شده در حافظه را حذف نمی‌کنند.
«حذف» پشته از آدرس جدید در `rsp` انتزاع می‌شود.

در برخی زمینه‌ها، این ممکن است با افشای مقادیر داخلی به منابع خارجی، نگرانی‌های امنیتی ایجاد کند.
یکی از راه‌های مقابله با آن، صفر کردن محتویات هر فضای پشته‌ای است که تابع استفاده می‌کند.
~~~~

## Call و Ret

هدف اصلی پشته، پیگیری آدرس بازگشت برای توابع فراخوانی‌شده است.

همان‌طور که در مفهوم قبلی اشاره شد، یک ثبات ویژه به نام `rip` وجود دارد که به دستور بعدی برای اجرا اشاره می‌کند.
این ثبات برای کنترل جریان برنامه استفاده می‌شود و توسط دستورهایی مانند `jmp` و `call` تغییر می‌کند.

هر بار که از دستور `call` استفاده می‌شود، مقدار فعلی `rip` به‌طور ضمنی پوش می‌شود.
سپس، عملوند دستور به `rip` منتقل می‌شود تا اجرا در تابع فراخوانی‌شده ادامه یابد.

دستور `ret` عملیات معکوس را انجام می‌دهد.
از پشته به `rip` پاپ می‌کند تا اجرا به تابع فراخواننده بازگردد.

در نقطه‌ی ورود، `rsp` به آدرسی اشاره می‌کند که باید بازگردانده شود.
این همان آدرسی است که `ret` باید از پشته پاپ کند.

بنابراین، هر تغییری در مقدار `rsp` در داخل یک تابع، چه مستقیماً و چه با `push`، باید قبل از بازگشت تابع معکوس شود.

## ثبات‌های ذخیره‌شده توسط فراخوانی‌شده و ذخیره‌شده توسط فراخواننده

علاوه بر `rsp`، ثبات‌های دیگری نیز وجود دارند که باید در طول فراخوانی‌های تابع حفظ شوند: `rbp`، `rbx`، `r12`، `r13`، `r14` و `r15`.
به‌طور کلی، تابع فراخواننده انتظار دارد بتواند از آن ثبات‌ها استفاده کند بدون اینکه توسط تابع فراخوانی‌شده تغییر کنند.

این یعنی تابع _فراخوانی‌شده_ باید مقادیر آن ثبات‌ها را قبل از استفاده ذخیره کند و آن‌ها را قبل از بازگشت به مقادیر اصلی‌شان بازگرداند.
به همین دلیل به آن‌ها **ثبات‌های ذخیره‌شده توسط فراخوانی‌شده** می‌گویند.

سایر ثبات‌های همه‌کاره مستقیماً برای استفاده‌ی تابع فراخوانی‌شده در دسترس هستند.

این یعنی تابع _فراخواننده_ باید مقادیر آن ثبات‌ها را قبل از فراخوانی هر تابعی ذخیره کند، در صورتی که توسط تابع فراخوانی‌شده تغییر کنند.
به همین دلیل به آن‌ها **ثبات‌های ذخیره‌شده توسط فراخواننده** می‌گویند.

_رایج‌ترین راه برای ذخیره‌ی محتویات یک ثبات، ذخیره‌ی آن در پشته است._

## پیش‌درآمد و پس‌درآمد

در برخی موارد، ممکن است پشته به‌شدت استفاده شود و تغییرات زیادی قبل از بازگشت تابع رخ دهد.
بنابراین، پیگیری همه‌ی آن تغییرات برای معکوس کردن آن‌ها ممکن است پیچیده باشد.

در چنین مواردی، یک راهبرد رایج این است که آدرس `rsp` را در ثبات دیگری ذخیره کنیم که در غیر این صورت در داخل تابع بدون تغییر می‌ماند.
و سپس، مقدار `rsp` ممکن است با یک دستور `mov` ساده در انتها، قبل از بازگشت تابع، بازیابی شود.

اگرچه هر ثباتی ممکن است برای این منظور استفاده شود، مرسوم است که از `rbp` به‌عنوان اشاره‌گر پایه استفاده شود.
از آنجا که `rbp` خودش یک ثبات ذخیره‌شده توسط فراخوانی‌شده است، معمولاً قبل از آن یک `push rbp` انجام می‌شود.
این توالی معمولاً **پیش‌درآمد** نامیده می‌شود.

در انتها، بازیابی `rsp` با یک `mov rsp, rbp` انجام می‌شود و سپس `rbp` نیز با یک `pop` از پشته بازیابی می‌شود.
این توالی معمولاً **پس‌درآمد** نامیده می‌شود.

```x86asm
section .text
fn:
    ; prologue
    push rbp
    mov rbp, rsp
    ...
    ; epilogue
    mov rsp, rbp
    pop rbp
    ret
```

~~~~exercism/note
هدف اصلی توالی‌های پیش‌درآمد/پس‌درآمد کمک به برنامه‌نویس در پیگیری تغییرات `rsp` است.
البته این کار برای یک کامپایلر بسیار آسان‌تر است.

به همین دلیل بسیاری از کامپایلرها یک بهینه‌سازی تولید می‌کنند تا اشاره‌گر قاب را حذف کرده و هر زمان ممکن است پیش‌درآمدها/پس‌درآمدها را حذف کنند.
~~~~

## انتقال آرگومان‌ها با پشته

در قرارداد فراخوانی [System V ABI][SystemV]، آرگومان‌ها معمولاً در ثبات‌ها به توابع منتقل می‌شوند.
با این حال، وقتی تعداد آرگومان‌ها زیاد باشد، یا به بیش از اندازه‌ی یک ثبات نیاز داشته باشند، ممکن است از پشته استفاده شود.

در چنین مواردی، مقادیر به ترتیب معکوس به پشته اضافه می‌شوند، به‌طوری که اولین آرگومان به `rsp` نزدیک‌تر باشد.
از آنجا که در نقطه‌ی ورود، `rsp` به آدرس بازگشت اشاره می‌کند، که در x86-64 یک مقدار ۸ بایتی است، اولین آرگومان روی پشته، در صورت وجود، می‌تواند در `rsp + 8` دسترسی شود:

```x86asm
mov rdi, 4   ; first argument
mov rsi, 8   ; second argument
mov rdx, 15  ; third argument
mov rcx, 16  ; fourth argument
mov r8, 23   ; fifth argument
mov r9, 42   ; sixth argument

; any remaining integer argument goes on the stack in reversed order
sub rsp, 16
mov qword [rsp], 100      ; seventh argument
mov qword [rsp + 8], 300  ; eighth argument

call many_arguments_fn ; call implicitly pushes `rip` to the stack
; so, at point of entry, 'many_arguments_fn' finds the first six integer arguments in the usual registers
; the seventh argument is found in rsp + 8
; and the eighth argument is found in rsp + 16
```

## هم‌ترازی پشته

System V ABI بیان می‌کند که پشته باید بلافاصله _قبل از_ اجرای دستور call، ۱۶ بایتی هم‌تراز باشد.
از آنجا که `call` مقدار `rip` را به پشته پوش می‌کند، در نقطه‌ی ورود، پشته برای تابع فراخوانی‌شده **۱۶ بایتی هم‌تراز نیست**.

این یعنی تابعی که تابع دیگری را فراخوانی می‌کند (و به‌طور خاص، توابع خارجی) باید قبل از استفاده از `call` پشته را هم‌تراز کند.

این کار را می‌توان با کم کردن یک مقدار مناسب از `rsp` انجام داد.
در نقطه‌ی ورود، این مقدار باید ۸ واحد بیشتر از مضربی از ۱۶ باشد: ۸، ۲۴، ۴۰ و غیره.
از آنجا که دستور `push` از `rsp` کم می‌کند، ممکن است از تعداد فردی `push` برای همان اثر استفاده شود:

```x86asm
fn_a:
    sub rsp, 24 ; subtracting 8 more than a multiple of 16: this aligns the stack
    call fn_b
    add rsp, 24
    ret

fn_b:
    push rbx    ; odd number of pushes: this aligns the stack
    call fn_c
    pop rbx
    ret
```

## ناحیه‌ی سرخ

System V ABI یک فضای ۱۲۸ بایتی را دقیقاً زیر `rsp` رزرو می‌کند که ممکن است بدون هیچ تنظیمی از `rsp` استفاده شود.
این فضا به عنوان [ناحیه‌ی سرخ][red-zone] شناخته می‌شود:

```x86asm
fn:
    mov [rsp - 8], rax ; this is safe to use because it is in the red zone
    ret                ; no need to restore rsp
```

ناحیه‌ی سرخ فقط برای استفاده توسط یک تابع برگ امن است، یعنی تابعی که تابع دیگری را فراخوانی نمی‌کند.
