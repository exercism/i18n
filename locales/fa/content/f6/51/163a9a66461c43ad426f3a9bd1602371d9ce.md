# مبانی Unison

## ترم‌ها و توابع

ترم‌ها و توابع، واحدهای پایه در نوشتن یک برنامه‌ی Unison هستند.

«ترم» به چیزی می‌گوییم که یک مقدار ایستا است. با `name = expression` تعریف می‌شود و می‌تواند به‌صورت اختیاری با یک امضای نوع به شکل `name : MyType` در ابتدای آن همراه باشد. Unison از استنتاج نوع پشتیبانی می‌کند، بنابراین ممکن است ببینید امضای نوع در تعریف‌های ساده حذف شده است.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

توابع Unison به شکل `myFunctionName argument1 argument2 = myImplementation` هستند؛ با اسم تابع شروع می‌شوند و پس از آن آرگومان‌ها با فاصله از هم جدا می‌شوند.

```
getMax a b = Nat.max a b
```

توابع می‌توانند به‌صورت اختیاری شامل یک امضای نوع باشند. آخرین نوع در سمت راست، همیشه نوع بازگشتی نهایی تابع است و هر آرگومان با فلش تابع `->` جدا می‌شود.

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

برای فراخوانی یک تابع، از اسم آن استفاده کنید و پس از آن آرگومان‌ها را فقط با فاصله بنویسید.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

هنگام فراخوانی یک تابع، Unison تلاش می‌کند هر چیزی را که بلافاصله در سمت راست می‌آید به‌عنوان آرگومان آن در نظر بگیرد، که ممکن است همیشه ترتیب دلخواه ارزیابی تابع را ایجاد نکند.

فرض کنید می‌خواهیم مقدار `1` را از عبارت زیر به دست آوریم

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

همان‌طور که نوشته شده است، `shouldBe1` به `0` ارزیابی می‌شود، چون ترتیب ضمنی اعمال تابع `getMax 1 10` است که `10` می‌شود و سپس `10 - 10` که `0` می‌شود.

می‌توانید با پرانتزها عبارت را دوباره به ترتیب دلخواه عملیات گروه‌بندی کنید.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## عبارت‌های دیده‌بانی

Unison روشی برای ارزیابی سریع کد فراهم می‌کند که «عبارت دیده‌بانی» نام دارد. یک عبارت دیده‌بانی با نماد `>` شروع می‌شود و پس از آن عبارت مورد ارزیابی می‌آید. عبارت‌های دیده‌بانی را می‌توان در هر فایلی با پسوند `.u` نوشت. با ذخیره‌ی فایل باید ببینید که عبارت در کنسول Unison Codebase Manager (UCM) به چه چیزی ارزیابی می‌شود. هرجا ممکن باشد، در این مستندات تلاش می‌کنیم یک عبارت را همراه با خروجی مورد انتظارش پس از ارزیابی در یک عبارت دیده‌بانی نشان دهیم.

```
> helloThere
  ⧩
  "Hello, World!"
```

## توابع چندخطی

توابع چندخطی Unison از تورفتگی یا بلوک‌های `let` برای تعیین مرزهای کد استفاده می‌کنند، که به آن «دامنه‌ی واژگانی» می‌گویند.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

هر چیزی که در یک سطح تورفتگی قرار دارد، دامنه‌ی یکسانی دارد؛ به همین دلیل می‌توانیم در خط آخر به متغیر `newBeginning` ارجاع دهیم.

## فضاهای نام و دستورهای `use`

فضاهای نام روشی برای گروه‌بندی و سازمان‌دهی توابع Unison هستند. می‌توانید آن‌ها را مشابه «پوشه‌ها» در نظر بگیرید. آن‌ها ساختار و گروه‌بندی منطقی فراهم می‌کنند.

می‌توانید توابع یک فضای نام را با یک دستور `use` به دامنه بیاورید.

فرض کنید تابعی می‌نوشتید که از مقادیر `List` در Unison استفاده می‌کرد. می‌دانید که به توابعی مثل `List.map` و `List.flatMap` نیاز خواهید داشت، که در آن‌ها `List` فضای نام است و `map` و `flatMap` توابع هستند. برای اینکه خودتان را تکرار نکنید، می‌توانید همه‌چیز را از فضای نام `List` به دامنه‌ی واژگانی تابع خود بیاورید، به این شکل:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

خط `use List` ابهام ارجاع‌ها به `map` و `flatMap` را برطرف می‌کند. می‌توانید درباره‌ی [دستورهای `use` اینجا بیشتر بخوانید][use-statements].

## کتابخانه‌ی استاندارد Unison

کتابخانه‌ی استاندارد Unison `base` نام دارد. اگر راهنمای شروع سریع را دنبال کرده و یک پایگاه کد به‌صورت محلی ساخته‌اید، کتابخانه‌ی استاندارد باید به‌طور خودکار دانلود شده باشد. می‌توانید مستندات کتابخانه‌ی استاندارد را به‌صورت آنلاین در [Unison Share][unison-share-base] مرور کنید.

## توضیحات و لیترال‌های مستندسازی

توضیحات در Unison ویژگی تا حدودی غیرمعمولی هستند. هنگام نوشتن کد Unison، می‌توانید متنی در فایل با پسوند `.u` خود بسازید که با نحوه‌ی نگارش زیر تفسیر نمی‌شود:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_اما_، چون کد Unison به‌صورت هش درخت نحوی انتزاعی‌اش ذخیره می‌شود، نه به‌صورت فایل‌های متنی روی سیستم فایل، توضیحاتی که «تزیینات» متنی یک تابع یا ترم Unison در فایل هستند، واقعاً نمی‌توانند ذخیره و برای اشتراک‌گذاری دوباره بازنمایی شوند. اگر می‌خواهید اطلاعاتی به ترم Unison خود اضافه کنید که برای دیگران ذخیره شود تا آن را بخوانند و بفهمند، می‌توانید از یک لیترال مستندسازی استفاده کنید.

مستندسازی یک مقدار درجه‌یک در زبان برنامه‌نویسی Unison است. این یعنی یک عنصر `Doc` را می‌توان به یک مقدار نسبت داد، به‌عنوان مقدار به یک تابع پاس داد، یا به‌عنوان مقدار بازگشتی یک تابع برگرداند. عناصر لیترال مستندسازی با آکولادهای دوتایی باز و بسته می‌شوند. در ادامه می‌بینیم چگونه ممکن است از عنصر `Doc` به‌عنوان توضیح استفاده کنیم.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
