# مالکیت

در Cairo، مفهوم مالکیت به _متغیرها_ گره خورده است، نه به _مقدارهایی_ که آن‌ها در خود نگه می‌دارند.

مقدارها در Cairo تغییرناپذیرند و همین تغییرناپذیری تضمین می‌کند که حتی اگر متغیرهای زیادی به یک مقدار اشاره کنند، خود مقدار ثابت و بی‌تغییر بماند.
پس کامپایلر باید استفاده‌ی درست برنامه‌نویس از آن‌ها را تضمین کند.
معنای _مالکیت_ متغیر همین است: مالک، همان کدی است که می‌تواند متغیر را بخواند (و اگر تغییرپذیر باشد، در آن بنویسد).

## قواعد مالکیت متغیر

```console
1. Each variable in Cairo has an owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the variable is destroyed.
```

## حوزه‌ی متغیر

حوزه، محدوده‌ای درون یک برنامه است که یک متغیر در آن معتبر است.
بیایید به مثال زیر نگاه کنیم که متغیری به اسم `x` از نوع عدد صحیح بدون علامت تعریف می‌کند و توضیحات داخلش مشخص می‌کنند متغیر کجا معتبر است:

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

نکته‌ها:

- وقتی `x` وارد حوزه می‌شود، معتبر است.
- تا وقتی از حوزه خارج شود معتبر می‌ماند، در این نمونه تا پایان تابع `main()`.

## انتقال مقدارها

انتقال زمانی رخ می‌دهد که مقداری به تابعی دیگر پاس داده می‌شود؛ متغیر اصلی که به آن مقدار اشاره می‌کرد نابود می‌شود (و بدین ترتیب بی‌فایده می‌ماند) و متغیری تازه برای نگه داشتن همان مقدار ساخته می‌شود.

آرایه نمونه‌ای از یک نوع داده‌ی ترکیبی است که هنگام پاس داده شدن به تابعی دیگر منتقل می‌شود.
یادآوری کوتاهی از شکل یک آرایه:

```rust
    let mut arr: Array<u128> = array![];
    arr.append(1);
    arr.append(2);
```

سیستم نوع چطور تضمین می‌کند که برنامه‌ی Cairo هرگز نخواهد دو بار در یک خانه‌ی حافظه بنویسد؟
کد زیر را در نظر بگیرید که در آن می‌خواهیم دو بار عنصر ابتدای آرایه را حذف کنیم:

```rust
fn foo(mut arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let arr: Array<u128> = array![1];
    foo(arr);
    foo(arr); // -> compiler error: Variable was previously moved.
}
```

در این حالت، می‌خواهیم همان مقدار (آرایه‌ی داخل متغیر `arr`) را به هر دو فراخوانی تابع پاس بدهیم.
یعنی کد ما می‌خواهد اولین عنصر را دو بار حذف کند، که به معنای دو بار نوشتن در یک خانه‌ی حافظه است؛ کاری که ماشین مجازی Cairo آن را ممنوع کرده و به خطای زمان اجرا می‌انجامد.
خوشبختانه، این کد در واقع کامپایل نمی‌شود.
به‌محض اینکه آرایه را به تابع `foo` پاس بدهیم، متغیر `arr` دیگر قابل استفاده نیست.
این خطای زمان کامپایل را می‌گیریم که به ما می‌گوید باید `Array` خصیصه‌ی `Copy` را پیاده‌سازی کند:

## خصیصه‌ی Copy

اگر یک نوع، خصیصه‌ی `Copy` را پیاده‌سازی کند، پاس دادنش به یک تابع مقدار را منتقل نمی‌کند، بلکه متغیری تازه می‌سازد که به همان مقدار اشاره می‌کند.
این عملیاتی بدون هزینه است، چون متغیرها تجریدی در Cairo هستند و مقدارها همیشه تغییرناپذیرند.

برای پیاده‌سازی خصیصه‌ی `Copy` روی نوع خودتان، حاشیه‌نویسی `#[derive(Copy)]` را به تعریف نوع اضافه کنید.
اما Cairo اجازه‌ی این کار را نمی‌دهد اگر خود نوع یا هر یک از اجزایش خصیصه‌ی `Copy` را پیاده‌سازی نکرده باشد.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn main() {
    let p1 = Point { x: 5, y: 10 };
    foo(p1);
    foo(p1);
}

fn foo(p: Point) { // do something with p
}
```

## نابود کردن مقدارها

نوع‌های خطی را می‌توان با نابود کردنشان هم به کار گرفت، که تضمین می‌کند منبع مرتبط به‌درستی آزاد می‌شود.
این کار با پیاده‌سازی یا استخراج خصیصه‌ی `Drop` انجام می‌شود، که به کامپایلر اطلاع می‌دهد نوع را می‌توان وقتی دیگر به کار نمی‌آید، به‌سلامت نابود کرد.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

در حال حاضر، پیاده‌سازی `Drop` را می‌توان برای همه‌ی نوع‌ها استخراج کرد، به‌جز دیکشنری‌ها (`Felt252Dict`) و نوع‌هایی که دیکشنری دارند.
چون دیکشنری‌ها باید هنگام نابود شدن «فشرده» شوند.
برای همین، خصیصه‌ی `Destruct` را استخراج می‌کنیم:

```rust
#[derive(Destruct)]
struct A {
    dict: Felt252Dict<u128>
}

fn main() {
    A { dict: Default::default() };
}
```

## مقدارهای بازگشتی و حوزه

بازگرداندن مقدارها معادل انتقال آن‌هاست.
مثال زیر تابعی را نشان می‌دهد که مقداری را برمی‌گرداند:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    let a1 = gives_ownership();           // gives_ownership moves its return
                                          // value into a1

    let a2 = A {};                        // a2 comes into scope

    let a3 = takes_and_gives_back(a2);    // a2 is moved into
                                          // takes_and_gives_back, which also
                                          // moves its return value into a3

} // Here, a3 goes out of scope and is dropped. a2 was moved, so nothing
  // happens. a1 goes out of scope and is dropped.

fn gives_ownership() -> A {               // gives_ownership will move its
                                          // return value into the function
                                          // that calls it

    let some_a = A {};                    // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A { // some_a comes into scope

    some_a                                // some_a is returned and
                                          // moves ownership to the calling
                                          // function
}
```
