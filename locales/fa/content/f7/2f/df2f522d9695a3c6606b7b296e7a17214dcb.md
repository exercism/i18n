# مقدمه

## JSON

JSON (JavaScript Object Notation) یک قالب داده و فایل خوانا برای انسان است که معمولاً برای تبادل داده به کار می‌رود، به‌ویژه در برنامه‌های وب.
به همین دلیل جای تعجب نیست که در زبان Elm جایگاه ویژه‌ای دارد.

Elm ماژول‌های اصلی `Json.Decode` و `Json.Encode` را برای تجزیه و نوشتن داده‌ی JSON فراهم می‌کند.
«دیکودرهای JSON» راهی برای _اعلام_ این هستند که چه نوع داده‌ای انتظار می‌رود و داده باید به کدام ساختار داده نگاشت شود.

بیایید چند نام مستعار و نوع را از این ماژول‌ها وارد کنیم:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

استفاده از `Decode.decodeString : Decoder a -> String -> Result Error a` همراه با یک دیکودر و یک رشته‌ی JSON یا موفق می‌شود، اگر رشته با مشخصات دیکودر مطابقت داشته باشد، و یا در غیر این صورت شکست می‌خورد.
هنگام تعریف دیکودر هیچ راهی برای بررسی داده‌ی خام JSON وجود ندارد، و این برای کسی که از زبان‌های امری می‌آید ممکن است غیرعادی به نظر برسد.

## دیکودرهای انواع داده‌ی پایه

JSON تعداد کمی نوع داده‌ی اصلی دارد:

- رشته: با گیومه‌ی دوگانه `"hello world"` کدگذاری می‌شود
- منطقی: یا `true` یا `false`
- عدد: مانند `34` یا `0.12`
- تهی: نبودِ داده، `null`

هر یک از این‌ها با یک تابع `Decode` مرتبط است:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

توجه کنید که `Decode.null` به شما اجازه می‌دهد با گرفتن یک مقدار دلبخواه به عنوان آرگومان (شاید `()`، `Nothing`، یا هر چیزی که مناسب برنامه‌تان باشد) تصمیم بگیرید `null` را در برنامه‌تان چگونه مدل کنید.

## ترکیب دیکودرها

JSON همچنین دو ساختار داده برای گردآوردن انواع داده‌ی اصلی تعریف می‌کند:

- آرایه: مجموعه‌ای از انواع داده‌ی دیگر `[0, null, "none", []]`
- شیء: مجموعه‌ای از جفت‌های کلید-مقدار `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode` هم توابعی برای دیکود کردن این‌ها ارائه می‌دهد:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

هر یک از این توابع، `Decode.list : Decoder a -> Decoder (List a)` و `Decode.dict : Decoder a -> Decoder (Dict String a)`، یک دیکودر به عنوان آرگومان می‌گیرد، و انتظار می‌رود که این دیکودر هر عنصر ساختار داده را دیکود کند.
اگر دیکودر آرگومان در دیکود کردن هر یک از عناصر یک مقدار آرایه یا شیء شکست بخورد، کل دیکودر شکست می‌خورد، و این الگویی رایج است.

ترکیب دیکودرهای ساده و ساختن دیکودرهای پیچیده‌تر، ایده‌ی اصلی این تکنیک است.
با کمک یک مثال، چند تابع دیگر را هم معرفی می‌کنیم که می‌توان با آن‌ها دیکودرهایی برای داده‌های واقعی و به هر اندازه پیچیده ساخت.

## GeoJSON

برای تمرین ترکیب دیکودرهای پایه و تجزیه‌ی داده‌های پیچیده‌ی JSON، بیایید دیکودرهایی برای تجزیه‌ی (زیرمجموعه‌ای از) داده‌های GeoJSON بسازیم.
GeoJSON یک قالب داده‌ی تخصصی مبتنی بر JSON است که برای نمایش عارضه‌های جغرافیایی، مانند مکان‌ها، مسیرها یا نواحی، به کار می‌رود؛ این عارضه‌ها با مختصات جغرافیایی دوبعدی یا سه‌بعدی و همراه با ویژگی‌های دیگر مشخص می‌شوند.

### شیء هندسی

یک شیء هندسی GeoJSON شیئی است که یک فیلد `type` با مقدار رشته‌ای دارد (۷ مقدار ممکن برای `type` وجود دارد) و یک فیلد `coordinates` با مختصات جغرافیایی (که در ساختاری بسته به نوع گردآوری می‌شوند).
برای مثال،

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

یا

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

یک شیء هندسی را می‌توان در Elm با نوع زیر نمایش داد

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

برای بررسی مقدار یک فیلد مشخص، می‌توانیم از `Decode.field : String -> Decoder a -> Decoder a` استفاده کنیم که مقدار یک کلید مشخص از یک شیء را دیکود می‌کند.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

برای تغییر دادن مقداری که یک دیکودر با موفقیت تجزیه کرده است، می‌توانیم از `Decode.map : (a -> value) -> Decoder a -> Decoder value` یا هر یک از هم‌خانواده‌هایش استفاده کنیم، از `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` تا `Decode.map8`.

در این مورد، می‌خواهیم بسته به مقدار فیلد `type` تصمیم بگیریم از کدام دیکودر مختصات استفاده کنیم، و این کار دقیقاً به عهده‌ی `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` و دوستانش `Decode.succeed : a -> Decoder a` و `Decode.fail : String -> Decoder a` است.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

در اینجا توجه کنید که می‌توانستیم از `Decode.andThen` برای اعتبارسنجی مختصات استفاده کنیم (بررسی اینکه مختصات دوتایی یا سه‌تایی می‌آیند و بررسی اینکه مقادیر مختصات از نظر جغرافیایی منطقی هستند).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### شیء عارضه

یک شیء عارضه‌ی GeoJSON نماینده‌ی چیزی است که از نظر مکانی محدوده دارد: یک فیلد `type` با مقدار `"Feature"` دارد، یک فیلد `geometry` با یک شیء هندسی یا یک `null`، یک فیلد `properties` با یک شیء JSON دلبخواه یا یک `null`، و یک فیلد اختیاری `id` با یک مقدار رشته‌ای یا عددی JSON.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

یا

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

بیایید اول به فیلد `id` بپردازیم.
اگر وجود داشته باشد، باید هم رشته‌ها و هم اعداد را بپذیرد، بنابراین می‌توانیم یا یک نوع سفارشی برای مقدار آن تعریف کنیم، یا همیشه آن را به صورت رشته ذخیره کنیم.

برای انتخاب میان دو دیکودر ممکن، می‌توانیم از `Decode.oneOf : List (Decoder a) -> Decoder a` استفاده کنیم.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

برای بیان اینکه فیلد اختیاری است، می‌توانستیم از همان تکنیک استفاده کنیم

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

اما در عوض می‌توانستیم از `Decode.maybe : Decoder a -> Decoder (Maybe a)` استفاده کنیم

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

توجه کنید که `decodeMaybeFeatureId` (یا هر دیکودری که با `Decode.maybe` پوشانده شده باشد) همیشه موفق می‌شود، چون همیشه می‌تواند به `Ok Nothing` پناه ببرد؛ هرچند دیکودری که از آن استفاده می‌کند ممکن است همچنان شکست بخورد

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

بعد، بیایید به فیلد `geometry` بپردازیم، که می‌تواند یا یک شیء هندسی باشد یا `null`.
می‌توانستیم دوباره از `Decode.oneOf` استفاده کنیم، اما گزینه‌ی بهتری هست: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` و `Decode.nullable` امضای یکسانی دارند، اما رفتارشان متفاوت است، چون نتیجه‌ی `OK Nothing` در یک `Decode.nullable` فقط از مقدار مشخص `null` در JSON می‌آید.

در نهایت، فیلد `properties` می‌تواند یک شیء JSON دلبخواه یا یک `null` در خود داشته باشد، و این کار به عهده‌ی `Decode.value : Decoder Value` است.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

توجه کنید که `Value` یک نوع مات است، یعنی نمی‌توانید به‌راحتی محتوای آن را بررسی کنید.
برای استفاده از آن، می‌توانید یا یک دیکودر برایش بنویسید و آن را با `Decode.decodeValue : Decoder a -> Value -> Result Error a` اجرا کنید، یا آن را مستقیماً از طریق یک پورت به JavaScript بفرستید.

حالا آماده‌ایم شیءهای عارضه را تجزیه کنیم:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## انکودرهای JSON

«انکودرها» به کمک تابع `Encode.encode : Int -> Value -> String` امکان نوشتن JSON معتبر از مقادیر Elm را فراهم می‌کنند.
آرگومان اول میزان تورفتگی در نتیجه‌ی نهایی را مشخص می‌کند، و آرگومان دوم مقدار JSONی است که باید نوشته شود.

یک `Value` را می‌توان یا از `Decode.value` به دست آورد یا از یکی از انکودرها تولید کرد:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

و همچنین با `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

بیایید برای دیکودرهای GeoJSON که قبلاً تعریف کردیم، انکودر تعریف کنیم

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

به طور کلی، آزمایش خوبی برای جفت‌های دیکودر و انکودر شما این است که بررسی کنید `elmValue |> encoder |> decoder == elmValue`.
