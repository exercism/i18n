# دستورالعمل‌ها

کار شما در _Instruments of Texas_ روی یک ماشین‌حساب RPN آزمایشی ادامه دارد. تیم شما چند نمونه‌ی اولیه ساخته است که باید بررسی دقیقی روی آن‌ها انجام شود تا بهترین نمونه‌ای انتخاب شود که می‌توان آن را به تولید انبوه رساند.

شما می‌خواهید دو نوع بررسی انجام دهید.

نخست، بررسی اطمینان‌پذیری که ورودی‌هایی را تشخیص می‌دهد که ماشین‌حسابِ تحت بررسی برای آن‌ها یا از کار می‌افتد یا به‌اندازه‌ی کافی سریع پاسخ نمی‌دهد. برای جدا کردن خطاها، محاسباتِ هر ورودی باید در یک فرایند جداگانه اجرا شود. می‌توان از لینک کردن و تله‌گذاری خروج‌ها در فرایند فراخوان استفاده کرد تا تشخیص داد که محاسبه تمام شده است یا از کار افتاده است.

دوم، بررسی درستی که بررسی می‌کند آیا برای یک ورودی مشخص، نتیجه‌ای که ماشین‌حساب برمی‌گرداند همان چیزی است که انتظار می‌رود یا نه. تنها ماشین‌حساب‌هایی که پیش‌تر بررسی اطمینان‌پذیری را گذرانده‌اند بررسی درستی روی آن‌ها انجام می‌شود، بنابراین از کار افتادن نگرانی‌ای ایجاد نمی‌کند. با این حال، برای سریع‌تر شدن فرایند، عملیات باید به‌صورت همزمان اجرا شوند و همین آن را به مورد استفاده‌ی ایده‌آل برای کارهای ناهمگام تبدیل می‌کند.

## 1. شروع یک بررسی اطمینان‌پذیری برای یک ورودی

تابع `RPNCalculatorInspection.start_reliability_check/2` را پیاده‌سازی کنید. این تابع باید ۲ آرگومان بگیرد: یک تابع (ماشین‌حساب) و یک ورودی برای ماشین‌حساب. باید یک «نگاشت» برگرداند که ورودی و شناسه‌ی فرایندِ ایجادشده را در خود دارد.

فرایند ایجادشده باید تابع ماشین‌حسابِ داده‌شده را با ورودی داده‌شده فراخوانی کند. این فرایند باید به فرایند فراخوان لینک شود.

```elixir
RPNCalculatorInspection.start_reliability_check(fn _ -> 0 end, "2 3 +")
# => %{input: "2 3 +", pid: #PID<0.169.0>}
```

## 2. تفسیر نتایج یک بررسی اطمینان‌پذیری

تابع `RPNCalculatorInspection.await_reliability_check_result/2` را پیاده‌سازی کنید. این تابع باید دو آرگومان بگیرد. آرگومان اول نگاشتی است که ورودیِ بررسی اطمینان‌پذیری و شناسه‌ی فرایندی را در خود دارد که بررسی اطمینان‌پذیری را برای این ورودی اجرا می‌کند، همان‌طور که `RPNCalculatorInspection.start_reliability_check/2` برمی‌گرداند. آرگومان دوم نگاشتی است که به‌عنوان «انباشتگر» نتایج بررسی‌های اطمینان‌پذیری با ورودی‌های مختلف عمل می‌کند.

تابع باید منتظر یک پیام خروج بماند.

اگر پیام خروجی (`{:EXIT, from, reason}`) با دلیل `:normal` را از همان فرایندی دریافت کند که بررسی اطمینان‌پذیری را اجرا می‌کند، باید نگاشت نتایج را با مقدار `:ok` که زیر کلید `input` افزوده شده است برگرداند.

اگر پیام خروجی با دلیلی متفاوت را از همان فرایندی دریافت کند که بررسی اطمینان‌پذیری را اجرا می‌کند، باید نگاشت نتایج را با مقدار `:error` که زیر کلید `input` افزوده شده است برگرداند.

اگر در ۱۰۰ میلی‌ثانیه هیچ پیامی که با این معیارها مطابقت داشته باشد دریافت نکند، باید نگاشت نتایج را با مقدار `:timeout` که زیر کلید `input` افزوده شده است برگرداند.

```elixir
# when an exit message is waiting for the process in its inbox
send(self(), {:EXIT, pid, :normal})

RPNCalculatorInspection.await_reliability_check_result(
  %{input: "5 7 -", pid: pid},
  %{}
)

# => %{"5 7 -" => :ok}

# when there are no messages in the process inbox
RPNCalculatorInspection.await_reliability_check_result(
  %{input: "3 2 *", pid: pid},
  %{"5 7 -" => :ok}
)

# => %{"5 7 -" => :ok, "3 2 *" => :timeout}
```

## 3. اجرای یک بررسی اطمینان‌پذیری همزمان برای چندین ورودی

تابع `RPNCalculatorInspection.reliability_check/2` را پیاده‌سازی کنید. این تابع باید ۲ آرگومان بگیرد: یک تابع (ماشین‌حساب) و فهرستی از ورودی‌ها برای ماشین‌حساب.

برای هر ورودی در فهرست، باید با استفاده از `start_reliability_check/2` بررسی اطمینان‌پذیری را در یک فرایند لینک‌شده‌ی جدید آغاز کند. سپس، برای هر فرایندی که به این شکل آغاز شده است، باید با استفاده از `await_reliability_check_result/2` منتظر نتایج آن بماند.

پیش از آغاز هر فرایندی، تابع باید روی فرایند جاری پرچمِ تله‌گذاری خروج‌ها را فعال کند تا بتواند پیام‌های خروج را دریافت کند. پس از آن، باید این پرچم را به مقدار اولیه‌اش بازگرداند.

تابع باید نگاشتی را برگرداند که نتایج بررسی‌های اطمینان‌پذیری همه‌ی ورودی‌ها را در خود دارد.

```elixir
fake_broken_calculator = fn input ->
  if String.ends_with?(input, "*"), do: raise("oops")
end

inputs = ["2 3 +", "10 3 *", "20 2 /"]

RPNCalculatorInspection.reliability_check(fake_broken_calculator, inputs)
# => %{
#       "2 3 +" => :ok,
#       "10 3 *" => :error,
#       "20 2 /" => :ok
#     }
```

## 4. اجرای یک بررسی درستی همزمان برای چندین ورودی

تابع `RPNCalculatorInspection.correctness_check/2` را پیاده‌سازی کنید. این تابع باید ۲ آرگومان بگیرد: یک تابع (ماشین‌حساب) و فهرستی از ورودی‌ها برای ماشین‌حساب.

برای هر ورودی در فهرست، باید یک کار ناهمگام آغاز کند که ماشین‌حساب را با ورودی داده‌شده فراخوانی می‌کند. سپس، برای هر کاری که به این شکل آغاز شده است، باید ۱۰۰ میلی‌ثانیه منتظر نتایج آن بماند.

```elixir
fast_cheating_calculator = fn input -> 14 end
inputs = ["13 1 +", "50 2 *", "1000 2 /"]
RPNCalculatorInspection.correctness_check(fast_cheating_calculator, inputs)
# => [14, 14, 14]
```
