# درباره مبانی

کاتلین زبانی با نوع‌بندی ایستا است که طوری طراحی شده است که کاملاً با جاوا قابل استفاده‌ی متقابل باشد.

ویژگی‌هایی که کاتلین را از جاوا متمایز می‌کند:

- نحوه‌ی نگارش آن تمیزتر و مختصرتر است؛
- بسیاری از ویژگی‌های زبان‌های تابعی را در خود جای داده است؛
- از مقادیر تهی‌پذیر پشتیبانی گسترده‌ای دارد.

## متغیر

از آنجا که کاتلین نوع‌بندی ایستا دارد، باید نوع هر مقدار را در زمان کامپایل _بدانیم_.

اما [استنتاج نوع][inference] در کاتلین بسیار قدرتمند است، بنابراین _تعیین_ نوع اغلب اختیاری است.

برای تعریف یک متغیر دو راه وجود دارد.

۱. `val` یک متغیر تغییرناپذیر می‌سازد و تلاش برای تغییر آن خطای زمان کامپایل است.

```kotlin
val x = 42  // => 42
x = 43      // => 'val' cannot be reasssigned
```

۲. `var` یک متغیر تغییرپذیر می‌سازد.

```Kotlin
var x = 42  // => 42
x = 43      // => 43
```

از آنجا که متغیرهای تغییرناپذیر یک دسته‌ی رایج از `bug`ها را از بین می‌برند، هر جا که ممکن باشد استفاده از `val` تشویق می‌شود.

همچنین، حتی یک `var` هم نمی‌تواند نوع خود را تغییر دهد:

```kotlin
var x = 42
x = "foobar" // => Type mismatch: inferred type is String but Int was expected
```

برای کم کردن حواس‌پرتی بصری، در این سرفصل نوع‌های صریح عمدتاً حذف خواهند شد.
با این حال، توصیه می‌شود نوع‌ها را حداقل برای این موارد مشخص کنید:

- APIهای عمومی
- امضای توابع
- جاهایی که به مستندسازی نیاز دارد

برخی شرکت‌ها و سازمان‌ها ایمنی سخت‌گیرانه‌ی نوع را الزامی می‌کنند و استنتاج نوع را مجاز نمی‌دانند، در حالی که برخی دیگر آن را به نوع‌های «ساده» محدود می‌کنند یا کاملاً از استنتاج نوع استقبال می‌کنند.

```kotlin
val x: Int = 42  // => 42
```

به طور کلی، اسم متغیرها و توابع باید به شکل `camelCase` باشد، نه `snake_case`.

## تابع

تابع را با «کلیدواژه»ی `fun` تعریف کنید.
برخلاف جاوا، توابع لازم نیست بخشی از یک کلاس باشند.

```Kotlin
fun hello(): String {
    return "Hello, World!"
}

fun add(x: Int, y: Int): Int {
    return x + y
}
```

چند نکته‌ی قابل توجه:

- بعد از اسم تابع، پرانتزهای `()` لازم است، حتی اگر تابع هیچ آرگومانی نگیرد.
- آرگومان‌های تابع باید نوع را مشخص کنند: استنتاج نوع وجود ندارد (برخلاف متغیرها).
- بدنه‌ی تابع داخل آکولادهای `{ }` قرار می‌گیرد (هرچند پایین‌تر را ببینید).
- در صورت بازگرداندن یک مقدار، کلیدواژه‌ی `return` الزامی است.
- نقطه‌ویرگول‌های `;` در پایان خط‌ها اختیاری‌اند و معمولاً حذف می‌شوند.
- عملگرهای حسابی `+`، `-`، `*`، `/` مشابه بیشتر زبان‌های رایج هستند.

اما برای این توابع بسیار ساده‌ی «تک‌عبارتی»، نحوه‌ی نگارشی کوتاه‌شده وجود دارد:

```Kotlin
// return type is usually omitted for single-expression functions
fun add(x: Int, y: Int) = x + y  
```
توابع می‌توانند پارامترهایی با مقدارهای پیش‌فرض داشته باشند. 
اگر هنگام فراخوانی تابع این مقدارها حذف شوند، از آن‌ها استفاده می‌شود:

```kotlin
fun ping(host: String = "localhost") {
    println("PING --> $host")
}

ping("exercism.io")  // PING --> exercism.io
ping()               // PING --> localhost
```

توابع در Exercism معمولاً یک مقدار برمی‌گردانند (به دلیل نحوه‌ی ساختار `test runner`).
برای استفاده‌ی گسترده‌تر از کاتلین، ممکن است دانستن این نکته مفید باشد که تابعی که هیچ مقداری برنمی‌گرداند، می‌تواند نوع بازگشتی و کلیدواژه‌ی `return` را حذف کند.

در این صورت می‌گویند نوع بازگشتی آن `Unit` است: معادل `void` در جاوا و چند زبان دیگر.

## توضیحات

توضیحات یک‌خطی با `//` شروع می‌شوند و سپس بقیه‌ی خط نادیده گرفته می‌شود.

توضیحات چندخطی با `/*` شروع می‌شوند و با `*/` به پایان می‌رسند

```Kotlin
fun hello(): String {
    /*
     * Failing to run this program on a new installation 
     * is considered bad luck
    */
    return "Hello, World!" // the compiler pixies are now happy
}
```

این موضوع همانند جاوا است.
