# مقدمه

## ارجاع‌های `null`

اگر تا به حال از زبان برنامه‌نویسی دیگری استفاده کرده باشید (C/C++, Python, Java, Ruby, Lisp و غیره)، احتمالاً قبلاً با `null` یا `nil` روبه‌رو شده‌اید.
استفاده از `null` یا `nil` روشی است که این زبان‌ها با آن نشان می‌دهند یک متغیر خاص هیچ مقداری ندارد.
اما همین باعث می‌شود که استفاده‌ی تصادفی از متغیری که به `null` اشاره می‌کند، اشتباهی آسان (و پرتکرار) باشد.
همان‌طور که می‌توانید تصور کنید، تلاش برای فراخوانی تابعی که وجود ندارد، یا دسترسی به مقداری که وجود ندارد، می‌تواند به انواع و اقسام bug و کرش منجر شود.
سازنده‌ی `null` تا آنجا پیش رفت که آن را [«اشتباه میلیارد دلاری».](https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/) خود نامید.

## نوع `Option`

برای پرهیز از این مشکلات، Rust از ارجاع‌های `null` استفاده نمی‌کند.
با این حال، همچنان به روشی امن نیاز دارد تا نشان دهد یک متغیر خاص هیچ مقداری ندارد.
اینجاست که `Option` وارد می‌شود.
به جای اینکه متغیری داشته باشید که مقداری ندارد، متغیرهای Rust می‌توانند از enum `Option` استفاده کنند.
این enum دو گونه دارد: `None`، معادل `null` در Rust؛ و `Some(T)` که در آن T مقداری از هر نوعی است.

به این شکل است:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

می‌توانید `Option` را لایه‌ای از امنیت میان خودتان و مشکلاتی در نظر بگیرید که ارجاع‌های `null` می‌توانند به بار بیاورند، و در همان حال کاربرد مفهومی آن‌ها را حفظ کنید.

## استفاده از `Option`

تنظیم یک متغیر روی `None` کاملاً سرراست است:

```rust
let nothing: Option<u32> = None;  // Variable nothing is set to None
```

اما اگر می‌خواهید نوع `Option` مقداری را حمل کند، نمی‌توانید این مقدار را مستقیماً تخصیص دهید.
یک متغیر از نوع `Option` و مثلاً یک متغیر از نوع `i32` معادل هم نیستند.
باید از `Some` استفاده کنید:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Some(-4); // This will work
let another_right_way = Some(-4); // Compiler infers that this is Option<i32>
```

به همین دلیل هم قطعه‌ی زیر کار نمی‌کند:

```rust
let number = 47;
let option_number = Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

اگر می‌خواهید مقداری را که درون `Some` نگه داشته شده به‌دست آورید، اول باید بررسی کنید که وجود دارد:

```rust
let mut some_words = Some("choose something to say"); // some_words set to something

match some_words {
    Some(str) => println!("Here, we will {}", str),
    None => println!("I've got nothing to say"),
} // Prints "Here, we will choose something to say"

some_words = None; // some_words now set to None

// exactly the same match block as above
match some_words {
    Some(str) => println!("Here, we will {}", str),
    None => println!("I've got nothing to say"),
} // Prints "I've got nothing to say"
```

علاوه بر `match`، ابزارهای دیگری هم در Rust برای بررسی و دسترسی به مقادیر درون `Option` وجود دارد، اما `match` باید تا حالا برایتان آشنا شده باشد.

به‌علاوه، این را نمایشی از دلیل استفاده‌ی Rust از `Option` به‌جای ارجاع `null` در نظر بگیرید.
نکته این است که **باید _حتماً_ بررسی کنید** که متغیر `Option` برابر با `Some` است (که در آن صورت می‌توانید پیش بروید و مقدار درون آن را استخراج و استفاده کنید) یا `None`.
در غیر این صورت، برنامه‌تان کامپایل نمی‌شود؛ کامپایلر شما را از `null` در امان نگه می‌دارد.
