# درباره

`interfaces` اصلی‌ترین راه برای [جدا کردن][wiki-loose-coupling] کاربردهای یک کلاس از پیاده‌سازی آن هستند. این جداسازی، انعطاف‌پذیری لازم برای نگهداری پیاده‌سازی را فراهم می‌کند و به پشتیبانی از رفتار جنریکِ ایمن از نظر نوع کمک می‌کند.

نحوه‌ی نگارش یک رابط شبیه به یک کلاس یا `struct` است، با این تفاوت که متدها و ویژگی‌ها فقط به شکل امضا ظاهر می‌شوند و هیچ بدنه‌ای ارائه نمی‌شود.

```csharp
public interface ILanguage
{
    string Speak();
}

public interface IItalianLanguage : ILanguage
{
    string Speak();
    string SpeakItalian();
}

public interface IScriptConverter
{
    string Version { get; set; }
    string ConvertCyrillicToLatin(string cyrillic);
}
```

کلاس یا `struct`ی که رابط را پیاده‌سازی می‌کند باید همه‌ی عملیات تعریف‌شده توسط رابط را پیاده‌سازی کند.

رابط‌ها معمولاً یک یا چند مورد از کارهای زیر را انجام می‌دهند:

- به کد استفاده‌کننده اجازه می‌دهند با تعدادی کلاس مختلف به صورت جنریک رفتار کند. در این حالت، رابط‌ها همان نقش یک کلاس پایه را ایفا می‌کنند
- زیرمجموعه‌ای از قابلیت‌ها را برای هدفی مشخص در دسترس قرار می‌دهند (مانند [`IComparable<T>`][icomparable])، یا
- API عمومی یک کلاس را در دسترس قرار می‌دهند تا چندین پیاده‌سازی بتوانند در کنار هم وجود داشته باشند. یک نمونه، [تست دابل][wiki-test-double] است

```csharp
public class ItalianTraveller : IItalianLanguage
{
    public string Speak()
    {
        return "Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class ItalianTravellerV2 : IItalianLanguage
{
    public string Speak()
    {
        return "migliorata - Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class FrenchTraveller : ILanguage
{
    public string Speak()
    {
        return "Ça va?";
    }
}

public class RussianTraveller : ILanguage, IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Speak()
    {
        return "Привет мир";
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}

public class DocumentTranslator : IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Translate(string russian)
    {
        throw new NotImplementedException();
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}
```

کدی که از رابط‌ها و کلاس‌های بالا استفاده می‌کند می‌تواند:

- با همه‌ی گوینده‌ها، صرف‌نظر از زبان، یکسان رفتار کند.
- به زیرسیستمی که تبدیل خط را انجام می‌دهد اجازه دهد بدون توجه به اینکه با چه نوع‌های مشخصی سروکار دارد، کار کند.
- از تغییرات گوینده‌ی ایتالیایی بی‌خبر بماند، که اگر کد کلاس و کد کاربر را تیم‌های مختلف نگهداری کنند، مناسب است

رابط‌ها به‌طور گسترده‌ای برای پشتیبانی از تست به کار می‌روند، زیرا [ماک کردن][so-mocking-interfaces] را آسان می‌کنند.

برای اطلاع از جزئیات اینکه چه نوع عضوهایی می‌توانند در یک رابط گنجانده شوند، این [مقاله][dt-interfaces] را ببینید.

رابط‌ها می‌توانند از رابط‌های دیگر ارث ببرند.

اعضای یک رابط به‌طور پیش‌فرض `public` هستند.

رابط‌ها می‌توانند انواع تودرتو داشته باشند، مانند لیترال‌های `const`، `enums`، `delegates`، `classes` و `structs`. در اینجا، رابط‌ها همانند کلاس‌ها و `struct`ها به عنوان [فضای نام][wiki-namespaces] عمل می‌کنند و رفتار و نحوه‌ی نگارششان یکسان است.

C# طبق طراحی خود از وراثت چندگانه پشتیبانی نمی‌کند، اما گونه‌ای از وراثت چندگانه را از طریق رابط‌ها ممکن می‌سازد.

علاوه بر این، مفهوم [چندریختی که می‌توان از طریق رابط‌ها پیاده‌سازی کرد][interface-polymorphism]، زیربنای سازوکار رابط است.

## پیاده‌سازی صریح رابط

گاهی ممکن است نام‌ها و امضاهای متدها بین دو رابط مختلف مشترک باشند. برای ارائه‌ی پیاده‌سازی متمایز این متدها، C# [پیاده‌سازی صریح رابط‌ها][explicit-implementation] را فراهم می‌کند. توجه داشته باشید که برای استفاده از پیاده‌سازی خاصی از یک رابط، باید عبارتی را که به شیء ارجاع می‌دهد به آن رابط تبدیل کنید. انتساب، تبدیل نوع یا ارسال به عنوان پارامتر این کار را انجام می‌دهد.

```csharp
public interface IFoo
{
    void X();
}

public interface IBar
{
    void X();
}

public class Census : IFoo, IBar
{
    void IFoo.X()
    {
        Console.Write("This is from Foo");
    }

    void IBar.X()
    {
        Console.Write("This is from Bar");
    }
}

public class User
{
    public void Use()
    {
        IFoo foo = new Census();
        IBar bar = new Census();
        foo.X();
        // => "This is from Foo"
        bar.X();
        // => "This is from Bar"
    }
}
```

چندین مورد استفاده وجود دارد:

- برخورد حوزه‌ها (همان‌طور که در بالا نشان داده شد) که در آن متدها امضاهای یکسانی دارند.
- متدهایی با نام یکسان اما نوع بازگشتی متفاوت: اگر کلاس‌های مجموعه‌ی خودتان را پیاده‌سازی کنید، ممکن است ببینید که یک رابط صریح برای `IEnumerable.GetEnumerator()` قدیمی، در کنار `IEnumerable<T>.GetEnuerator()`، لازم است. ممکن است هرگز از چنین رابطی استفاده نکنید، اما کامپایلر ممکن است اصرار کند.
- متدهایی که در آن‌ها نام‌ها بین رابط‌ها برخوردی ندارند، اما مطلوب است که کلاس پیاده‌ساز، نام را برای هدفی مرتبط به کار ببرد: `IFormattable` یک متد `ToString()` دارد که علاوه بر پارامتری از نوع `IFormatProvider`، پارامتری از نوع _نوع قالب_ می‌گیرد. کلاسی مانند `FormattableString` از کتابخانه‌ی کلاس پایه (BCL) این رابط را دارد تا مطمئن شود روال‌هایی که یک `IFormattable` می‌گیرند می‌توانند از آن استفاده کنند، اما بیانگرتر است که نسخه‌ی اصلی `ToString(IFormatProvider)` آن پارامتر _نوع قالب_ را حذف کند، چون در پیاده‌سازی به کار نمی‌رود و کاربران API را سردرگم می‌کند.

## پیاده‌سازی پیش‌فرض

نسخه‌ی ۸ C# مشکلی آزاردهنده را در APIها حل می‌کند. اگر برای بهبود قابلیت‌ها برای پیاده‌سازی‌های جدید، متدهایی به یک رابط اضافه کنید، لازم است همه‌ی پیاده‌سازی‌های موجود آن رابط را طوری تغییر دهید که با قرارداد API سازگار شوند، حتی اگر رفتار خاصی برای پیاده‌سازی نداشته باشند. C# اکنون اجازه می‌دهد یک _متد پیش‌فرض_ به عنوان بخشی از رابط ارائه شود (توسعه‌دهندگان Java با آن آشنا هستند). پیش‌تر، وقتی چنین تغییری رخ می‌داد، یک _نسخه‌ی ۲_ از رابط در کنار نسخه‌ی اصلی وجود داشت.

این [مقاله][dt-interfaces] مقدمه‌ای عالی درباره‌ی رابط‌ها است و بر _پیاده‌سازی پیش‌فرض_ و دیگر نوآوری‌های پشتیبان مانند اعضای `static`، `private` و `virtual` تمرکز دارد.
