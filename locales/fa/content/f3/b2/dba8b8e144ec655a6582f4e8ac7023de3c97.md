# دستورالعمل‌ها

شما در حال نوشتن فریم‌ور برای سیستم امتیازدهی یک کنسول دستی رترو هستید.
پردازنده‌ی این دستگاه ساده است و صفحه‌نمایش جدول امتیاز با نرخ ثابتی تازه‌سازی می‌شود.
برای اینکه تصویر روان بماند، روال‌های امتیازدهی باید بدون توجه به اینکه بازیکن چه کاری انجام می‌دهد، در تعداد چرخه‌ی قابل پیش‌بینی اجرا شوند.

چهار وظیفه دارید.

~~~~exercism/note
کد این وظیفه‌ها باید بدون شاخه باشد.
به‌جای پرش‌های شرطی از `cmovcc`، `setcc` و عملیات حسابی استفاده کنید.
~~~~

## 1. افزودن پاداش بدون سرریز کردن نمایشگر

ناحیه‌ی امتیاز در صفحه‌نمایش LCD کنسول دستی گنجایش شش رقم دهدهی را دارد.
نمی‌تواند هیچ عددی بزرگ‌تر از `999999` را نشان دهد.
وقتی پاداشی باعث شود امتیاز جاری از این حد بگذرد، امتیاز نمایش‌داده‌شده به‌جای اینکه به دور بچرخد، در بیشترین مقدار نگه داشته می‌شود.

تابعی به اسم `add_bonus` تعریف کنید که با گرفتن امتیاز جاری و پاداشی که باید اضافه شود، امتیاز جدید را که در `999999` محدود شده است برمی‌گرداند.
آرگومان‌ها به ترتیب عبارت‌اند از:

1. `total`: امتیاز کل جاری (همیشه بین `0` و `999999`)
2. `bonus`: پاداشی که باید اضافه شود (همیشه نامنفی)

مقدار بازگشتی `total + bonus` است اگر این جمع کوچک‌تر یا مساوی `999999` باشد، و در غیر این صورت `999999`:

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

هم آرگومان‌ها و هم مقدار بازگشتی اعداد صحیح علامت‌دار ۶۴ بیتی هستند.

~~~~exercism/note
می‌توانید فرض کنید که `total + bonus` از یک عدد صحیح علامت‌دار ۶۴ بیتی سرریز نمی‌کند.
~~~~

## 2. مقایسه‌ی دو امتیاز

کنسول دستی یک جدول امتیاز کوچک از بهترین امتیازهای اخیر بازیکن را در فایل ذخیره‌ی خود نگه می‌دارد.
بعد از هر بازی، امتیاز جدید در جایگاه درست خود در جدول امتیازات درج می‌شود.
روال مرتب‌سازی می‌پرسد که کدام‌یک از دو امتیاز جلوتر است و پاسخ را به‌صورت یک عدد صحیح کوچک انتظار دارد.

تابعی به اسم `compare_scores` تعریف کنید که با گرفتن دو امتیاز، این مقادیر را برمی‌گرداند:

- `+1` اگر امتیاز اول _بزرگ‌تر_ باشد
- `-1` اگر امتیاز اول _کوچک‌تر_ باشد
- `0` اگر دو امتیاز _برابر_ باشند

مثال:

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

هم آرگومان‌ها و هم مقدار بازگشتی اعداد صحیح علامت‌دار ۶۴ بیتی هستند.

## 3. اعتبارسنجی امتیاز خام

کنسول دستی می‌تواند از طریق کابل اتصال خود به دستگاه دیگری متصل شود تا بعد از یک مسابقه‌ی چندنفره امتیازها را به اشتراک بگذارد.
این کابل نویز الکتریکی دارد و بایت‌های ورودی گاهی خراب می‌شوند، به‌طوری که مقادیری بسیار کمتر از کمینه‌ی مجاز یا بسیار بیشتر از بیشینه‌ی مجاز تولید می‌کنند.
اعتبارسنج هر امتیاز ورودی را پیش از آنکه بقیه‌ی سیستم آن را ببیند، در محدوده‌ی مجاز محدود می‌کند.

تابعی به اسم `validate_score` تعریف کنید که با گرفتن یک امتیاز خام و کرانه‌های مجاز، امتیاز محدودشده به بازه‌ی `[min, max]` را برمی‌گرداند.
آرگومان‌ها به ترتیب عبارت‌اند از:

1. `score`: امتیاز خامی که از کابل اتصال دریافت شده است
2. `min`: کوچک‌ترین امتیاز مجاز
3. `max`: بزرگ‌ترین امتیاز مجاز

مقدار بازگشتی `min` است اگر `score < min` باشد و `max` اگر `score > max` باشد.
در غیر این صورت، `score` برگردانده می‌شود.
می‌توانید فرض کنید که `min <= max`.

مثال:

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

همه‌ی آرگومان‌ها و مقدار بازگشتی اعداد صحیح علامت‌دار ۶۴ بیتی هستند.

## 4. پیگیری دو امتیاز برتر

در پایان هر جلسه‌ی بازی، کنسول دستی گزارش بازی‌های اخیر را در فایل ذخیره‌ی خود پیمایش می‌کند تا دو بالاترین امتیاز ثبت‌شده تا آن لحظه را پیدا کند.
این گزارش آرایه‌ای ساده از اعداد صحیح علامت‌دار ۶۴ بیتی در حافظه است.
پیمایش یک بار روی آرایه گام برمی‌دارد و دو بیشینه‌ی جاری را نگه می‌دارد: بالاترین مقداری که تا این لحظه دیده شده و دومین بالاترین مقدار.

توجه کنید که هر دو عدد باید حداقل `0` باشند.
هر عدد منفی نادیده گرفته می‌شود.

نسخه‌ی اول این تابع با پرش‌های شرطی زنجیره‌ای نوشته شده بود.
کد برای هر کاندید می‌پرسد که کجا جا می‌گیرد (بالای اولی، بین اولی و دومی، یا هیچ‌کجا) و بیشینه‌های جاری را بر همان اساس جابه‌جا می‌کند و هر نتیجه‌ی منفی را دور می‌ریزد.

این روش کار می‌کند.
اما چون مقادیر ورودی تصادفی‌اند، هر پرش شرطی به پیش‌بینی‌های نادرست زیادی منجر می‌شود.
به همین دلیل تصمیم گرفته‌اید حلقه‌ی اصلی را طوری بازنویسی کنید که بدون شاخه باشد.

در ادامه تابعی را می‌بینید که بخش شاخه‌دارش کامنت شده است:

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

بخش کامنت‌شده را با پیاده‌سازی‌ای بدون شاخه جایگزین کنید.
تنها پرش مجاز در کد جدید، همان پرشی است که به ابتدای حلقه برمی‌گردد تا عنصر جدیدی از آرایه را بررسی کند.

این تابع مقدار بازگشتی ندارد و همان آرگومان‌های نسخه‌ی شاخه‌دار را می‌گیرد:

1. `out`: بافر خروجی که تابع دو امتیاز نامنفی برتر را به‌ترتیب نزولی به‌صورت اعداد صحیح علامت‌دار ۶۴ بیتی در آن می‌نویسد
2. `array`: آرایه‌ی ورودی از اعداد صحیح علامت‌دار ۶۴ بیتی
3. `length`: تعداد عناصر آرایه، به‌صورت یک عدد صحیح بدون علامت ۶۴ بیتی

~~~~exercism/note
اگر آرایه شامل مقادیر تکراری باشد، چنانچه این مقادیر تکراری دو امتیاز برتر باشند، ممکن است در هر دو خانه‌ی خروجی ظاهر شوند.
~~~~
