# درباره

توابع بازگشتی توابعی هستند که خودشان را فراخوانی می‌کنند.

یک تابع بازگشتی باید حداقل یک _حالت پایه_ و حداقل یک _حالت بازگشتی_ داشته باشد.

یک _حالت پایه_ مقداری را بدون فراخوانی دوباره‌ی تابع برمی‌گرداند.
یک _حالت بازگشتی_ تابع را دوباره فراخوانی می‌کند و ورودی را طوری تغییر می‌دهد که در نقطه‌ای با حالت پایه مطابقت کند.

در Elm، توابع بازگشتی معمولاً با استفاده از تطبیق الگو به کمک عبارات `case` تعریف می‌شوند.

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

یک تابع بازگشتی می‌تواند چندین حالت پایه و/یا چندین حالت بازگشتی داشته باشد.
برای مثال، [دنباله‌ی فیبوناچی][fibonacci] یک دنباله‌ی بازگشتی با دو حالت پایه است:

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

توجه کنید که این پیاده‌سازی خاص به‌صورت نمایی کند است، چون اعداد فیبوناچی مرتبط در دو فراخوانی بازگشتی مستقل از صفر محاسبه می‌شوند.

شمردن تعداد تکرارهای مقدار مشخصی مثل `x` در یک فهرست، دو حالت بازگشتی دارد:

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## حلقه از طریق بازگشت

به دلیل تغییرناپذیری، حلقه‌ها در Elm متفاوت از زبان‌های امری نوشته می‌شوند.
برای مثال، حلقه‌ها معمولاً به این شکل‌اند:

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

در یک زبان تابعی مثل Elm، تغییر دادن متغیرها ممکن نیست.
بنابراین، حلقه‌ها باید با بازگشت پیاده‌سازی شوند.

معادل یک حلقه‌ی `for` در Elm به این شکل خواهد بود:

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

در عمل، پیمایش فهرست‌ها و دیگر ساختارهای داده در Elm بیشتر وقت‌ها با توابعی از ماژول [`List`][module-list] انجام می‌شود، مثل `List.map`، `List.filter` و `List.foldl`.
در پشت‌صحنه، این توابع با بازگشت پیاده‌سازی شده‌اند.

## اجرای بی‌نهایت

توابع بازگشتی، اگر نادرست پیاده‌سازی شوند یا تعداد فراخوانی‌های بازگشتی بیش از حد بزرگ باشد، ممکن است هرگز نتیجه‌شان را برنگردانند.
این می‌تواند مشکل‌آفرین باشد، چون هر بار که تابعی فراخوانی می‌شود، ارجاعی در حافظه ذخیره می‌شود که محیط اجرا باید نتیجه را به آنجا برگرداند (روی [پشته‌ی فراخوانی][wiki-call-stack]).
اگر یک تابع بازگشتی بیش از حد یا حتی بی‌نهایت خودش را فراخوانی کند، ممکن است حافظه تمام شود و محیط اجرا از کار بیفتد (یک [خطای سرریز پشته][wiki-stack-overflow]).
محیط اجرای Elm برای بازگشت و اطمینان‌پذیری بهینه شده است، اما بازگشت بی‌نهایت همچنان می‌تواند مشکل ایجاد کند.

این مشکل اجرای بی‌نهایت می‌تواند ناشی از این موارد باشد:

- فراموش کردن پیاده‌سازی حالت پایه.
- رسیدگی نکردن به همه‌ی حالت‌های ممکن در تطبیق الگو.
- تغییر نادرست آرگومان هنگام انجام فراخوانی بازگشتی و در نتیجه هرگز نرسیدن به حالت پایه.
