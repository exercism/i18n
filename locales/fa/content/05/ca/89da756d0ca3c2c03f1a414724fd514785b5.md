# تست‌ها

هر تمرین مجموعه‌ای از تست‌های واحد و هر آنچه برای ساخت و اجرای آن‌ها لازم است را همراه دارد. پیاده‌سازی را خودتان ارائه می‌دهید.

## اجرای تست‌ها

یک ترمینال در پوشه‌ی تمرین باز کنید و اجرا کنید:

```
make
```

این دستور راه‌حل شما و تست‌ها را کامپایل می‌کند و سپس تست‌ها را اجرا می‌کند.
هر بار که راه‌حل خود را تغییر می‌دهید، آن را دوباره اجرا کنید.

اگر [Exercism CLI](https://exercism.org/docs/using/solving-exercises/working-locally) را دارید، می‌توانید به‌جای آن از این دستور استفاده کنید که `make` را هم اجرا می‌کند:

```
exercism test
```

برای حذف فایل‌های ایجادشده توسط ساخت، `make clean` را اجرا کنید.

### بدون `make`

اگر `make` را ندارید (برای نمونه در Windows)، می‌توانید تست‌ها را مستقیم کامپایل و اجرا کنید.
برای تمرین «Bob»:

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

سپس تست‌ها را در Linux یا macOS اجرا کنید:

```
./run_tests
```

یا در Windows:

```
.\run_tests
```

## کار کردن روی یک تمرین

فایل‌های هر تمرین به اسم همان تمرین نام‌گذاری می‌شوند.
برای تمرین «Bob»:

| فایل | محتوا |
| ---------------- | ----------------------------------------------------------------- |
| `bob.f90`        | نسخه‌ی اولیه‌ی راه‌حل، آماده برای کامل کردن توسط شما |
| `bob_test.f90`   | تست‌ها |
| `TesterMain.f90` | کتابخانه‌ی تست |
| `Makefile`       | دستورهای `make` |
| `CMakeLists.txt` | دستورهای [CMake](#using-cmake-instead) که اختیاری است |

فقط لازم است فایل راه‌حل را ویرایش کنید.

کار کردن روی هر تمرین یعنی تکرار این مراحل تا وقتی همه‌ی تست‌ها پاس شوند:

- خطاهای کامپایل را رفع کنید، سپس تست‌ها را اجرا کنید تا ببینید کدام‌ها شکست می‌خورند.
- فقط به اندازه‌ای پیاده‌سازی کنید که تست شکست‌خورده‌ی بعدی پاس شود.
- پیاده‌سازی خود را بازآرایی کنید تا خوانایی را بالا ببرید، تکرار را کم کنید و غیره.
- دوباره تست‌ها را اجرا کنید و به تست شکست‌خورده‌ی بعدی بروید.

برای هر تست شکست‌خورده پیامی چاپ می‌شود و در پایان خلاصه‌ای می‌آید.
اگر هر یک از تست‌ها شکست بخورد، `make` با یک خطا پایان می‌یابد.

هر تست یک توضیح دارد که آن تست را توصیف می‌کند و سپس خود تست قرار دارد که با `call assert_equal` شروع می‌شود، مثلاً

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

برای غیرفعال کردن یک تست، کافی است آن را با `'!'` کامنت کنید، مثلاً

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## استفاده از CMake به‌جای آن

به CMake نیازی ندارید، اما اگر در محیط توسعه‌ای مانند Visual Studio یا Xcode کار می‌کنید یا از کامپایلری غیر از GFortran استفاده می‌کنید، ممکن است به کارتان بیاید.

پوشه‌ی تمرین باید اسم اصلی خود را حفظ کند، چون CMake از آن برای پیدا کردن فایل‌های منبع استفاده می‌کند.
از داخل پوشه‌ی تمرین شروع کنید:

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

پس از تغییر راه‌حل خود، فقط به دو دستور آخر نیاز است.

**توجه:** همیشه `cmake` را از یک پوشه‌ی جداگانه مانند `build` اجرا کنید.
اجرای `cmake .` در پوشه‌ی تمرین، `Makefile` ای را که همراه تمرین می‌آید جایگزین می‌کند.

CMake یک تولیدکننده‌ی مناسب برای سیستم شما انتخاب می‌کند.
برای انتخاب یکی دیگر، از گزینه‌ی `-G` استفاده کنید، مثلاً `cmake -G Xcode ..`.
دستور `cmake --help` را اجرا کنید تا تولیدکننده‌هایی که می‌توانید استفاده کنید فهرست شوند.
با Visual Studio یا Xcode، تست‌ها را با `ctest -V -C Debug` اجرا کنید.

اگر پوشه‌ی تمرین شما `Makefile` ندارد، یعنی پیش از افزوده شدن این فایل‌ها به تمرین‌ها دانلود شده است.
با این حال هنوز می‌توانید از CMake استفاده کنید.
