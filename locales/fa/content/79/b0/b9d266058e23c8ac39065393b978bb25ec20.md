# درباره

حافظه‌ی پویا توسط توابع کتابخانه‌ای پیاده‌سازی می‌شود که برنامه‌نویس از آن‌ها برای تخصیص و آزادسازی حافظه در زمان اجرا استفاده می‌کند.
از آنجا که برنامه‌نویس تخصیص و آزادسازی حافظه را کنترل می‌کند، حافظه‌ی پویا تنها تا همان اندازه‌ای ایمن است که برنامه‌نویس از خطای انسانی در امان باشد.
به همین دلیل، حافظه‌ی پویا یکی از منابع اصلی باگ‌های برنامه‌نویسی و یکی از اهداف اصلی حملات هکری است.

حافظه‌ی پویا برای متغیرهایی به کار می‌رود که اندازه‌شان فقط در زمان اجرا مشخص می‌شود.
این کار معمولاً برای آرایه‌هایی مفید است که تعداد عناصرشان از یک بار اجرا به بار بعدی ممکن است تغییر کند.
آرایه‌های با طول متغیر (VLA) روش دیگری برای کار با آرایه‌هایی هستند که اندازه‌ی عنصرشان فقط در زمان اجرا مشخص می‌شود.
یک VLA از حافظه‌ی خودکار استفاده می‌کند، یعنی حافظه‌اش هنگام خروج از بلوکی که در آن تعریف شده از بین می‌رود.
(برای اطلاعات بیشتر درباره‌ی حافظه، لطفاً مفهوم [مشخص‌کننده‌های کلاس ذخیره‌سازی](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers) را ببینید.)
آرایه‌های با طول متغیر با C99 به زبان C وارد شدند، اما از C11 به بعد اختیاری هستند، بنابراین کامپایلرهایی که از C11 به بعد پشتیبانی می‌کنند اجباری به پشتیبانی از آن‌ها ندارند.
تحلیل دقیق آرایه‌های با طول متغیر از حیطه‌ی این مقاله خارج است.

## malloc

`malloc` تابعی است که در `stdlib.h` اعلام شده و برای تخصیص حافظه‌ی پویا به کار می‌رود.
اگر تخصیص موفقیت‌آمیز باشد، اشاره‌گری برگردانده می‌شود که به آدرس اولین بایت حافظه‌ی تخصیص‌یافته اشاره می‌کند.
اگر تخصیص موفقیت‌آمیز نباشد، `NULL` برگردانده می‌شود.
عاقلانه است که نتیجه‌ی `malloc` را برای `NULL` بررسی کنید و در صورت شکست، به‌شکلی مناسب با آن برخورد کنید.
اشاره‌گر برگردانده‌شده از نوع `pointer-to-void` است که تقریباً می‌توان آن را اشاره‌گری «عمومی» در نظر گرفت که می‌تواند به نوع مشخصی که حافظه از آن استفاده می‌کند تبدیل شود.
`malloc` یک پارامتر دارد که اندازه‌ی حافظه‌ی موردنظر بر حسب بایت است.
اندازه‌ی کل برای تخصیص یک آرایه، اندازه‌ی نوع داده‌ی هر عنصر ضرب در تعداد عناصر است.
عملگر `sizeof` معمولاً برای به‌دست آوردن اندازه‌ی نوع داده‌ی هر عنصر به کار می‌رود.
مثال زیر این موضوع را نشان می‌دهد

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

مهم است به یاد داشته باشید که حافظه‌ای که `malloc` تازه تخصیص می‌دهد مقداردهی اولیه نمی‌شود، بلکه ممکن است مقادیر بی‌مصرف در خود داشته باشد.
توجه کنید که `sizeof` اشاره‌گر `numbers` نه تعداد عناصر آرایه است و نه کل حافظه‌ی تخصیص‌یافته.
اندازه‌ی اشاره‌گری که `malloc` برمی‌گرداند، اندازه‌ی هر اشاره‌گر روی آن سیستم خاص است.
کد مثال روی یک سیستم ۶۴ بیتی اجرا شد، بنابراین اندازه‌ی اشاره‌گر ۸ بایت بود (ضرب در ۸ بیت در هر بایت = ۶۴ بیت).
نوع اشاره‌گر به‌صورت ضمنی از pointer-to-void به pointer-to-int تبدیل شد.
اینکه اشاره‌گر pointer-to-int به یک `int` واحد اشاره می‌کند یا به آرایه‌ای از `ints`ها، چیزی است که برنامه‌نویس می‌تواند به هر شکلی که مناسب می‌داند با آن برخورد کند.
برای مثال

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

اگر مطمئن باشید که مقدار(ها) پیش از خوانده شدن نوشته می‌شوند، استفاده از `malloc` می‌تواند روشی کارآمد برای تخصیص حافظه باشد.
اما اگر احتمال داشته باشد که مقدار(ها) پیش از مقداردهی اولیه خوانده شوند، استفاده از `malloc` پرخطر است.
روش ایمن‌تر برای تخصیص حافظه استفاده از `calloc` است که حافظه‌ی تازه تخصیص‌یافته را به صفر مقداردهی اولیه می‌کند.

توجه کنید که در مثال‌های بالا از `free(numbers)` استفاده شده است.

## free

`free` تابعی است که در `stdlib.h` اعلام شده و برای آزادسازی حافظه‌ای که به‌صورت پویا تخصیص یافته به کار می‌رود.
حافظه‌ی تخصیص‌یافته‌ی پویا تا زمانی که با `free` آزاد نشود، در حافظه در تصرف باقی می‌ماند.
برخی سیستم‌عامل‌ها ممکن است هنگام پایان برنامه، حافظه‌ی تخصیص‌یافته‌ی پویا را به‌طور خودکار آزاد کنند، اما بهترین کار این است که به آن تکیه نکنید.
`free` یک پارامتر دارد که اشاره‌گری به حافظه‌ای است که به‌صورت پویا تخصیص یافته است.
استفاده یا عدم استفاده از `free` با چندین مشکل مربوط به حافظه مرتبط است.

#### نشتی حافظه

آزاد نکردن حافظه‌ی تخصیص‌یافته‌ی پویا پس از آنکه ارجاع به آن حافظه به پایان عمرش می‌رسد، یا به شکل دیگری از بین می‌رود، «نشتی حافظه» نامیده می‌شود.
حافظه‌ی نشت‌کرده حافظه‌ای است که در تصرف سیستم است اما دیگر برای برنامه قابل دسترسی نیست.
این می‌تواند مشکل خاصی باشد اگر حافظه در یک حلقه تخصیص یابد، در پایان حلقه آزاد نشود و در ابتدای حلقه دوباره تخصیص یابد.
اگر به‌اندازه‌ی کافی حافظه بدون آزاد شدن تخصیص یابد، فراخوانی تخصیص حافظه به‌دلیل ناکافی بودن حافظه‌ی باقی‌مانده برای تخصیص شکست می‌خورد.
مهم است به یاد داشته باشید که هرچند حافظه‌ی تخصیص‌یافته‌ی پویا تا زمان آزاد شدن در تصرف سیستم باقی می‌ماند، اشاره‌گری که به آن نسبت داده می‌شود ممکن است فقط دامنه‌ی بلوک داشته باشد.
برای نمونه، در مثال‌های `malloc`، حافظه در `my_function` تخصیص می‌یابد.
اگر اشاره‌گر به آن حافظه بازگردانده نمی‌شد و برای مقداردهی به اشاره‌گر `numbers` در `main` استفاده نمی‌شد، آن حافظه نشت می‌کرد.
بنابراین، سپردن آن اشاره‌گر `numbers` به `free` حافظه‌ی تخصیص‌یافته در `my_function` را آزاد می‌کند.

#### استفاده پس از آزادسازی (**UAF**)

اگر پس از آزاد شدن به حافظه دسترسی پیدا شود، مقدار(ها) می‌تواند هرچه باشد.
در مثال زیر، حافظه‌ای که `numbers` به آن اشاره می‌کند آزاد می‌شود و سپس در `printf` از آن خوانده می‌شود.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

اشاره‌گر `numbers` پس از آزاد شدن، «اشاره‌گر آویزان» نامیده می‌شود.
اشاره‌گر آویزان می‌تواند به حافظه‌ای غیر از آنچه برایش در نظر گرفته شده بود اشاره کند.
بنابراین، اشاره‌گر آویزان می‌تواند به خرابی داده‌ها و جایگزینی و اجرای کد دلخواه منجر شود.
اشاره‌گری به حافظه‌ی تخصیص‌یافته که با مقداردهی به `NULL` پاک نشده باشد، می‌تواند برای هک کردن برنامه به کار رود.
در مثال بالا، اگر `numbers` پس از آزاد شدن به این شکل روی `NULL` تنظیم می‌شد: `numbers = NULL;`، آنگاه `printf` بعدی به خاتمه‌ی برنامه می‌انجامید، و احتمالاً هنگام تلاش برای خواندن `numbers[0]` یک segmentation fault گزارش می‌کرد.

#### آزادسازی دوباره

اگر `free` دو بار روی اشاره‌گری به حافظه‌ی تخصیص‌یافته‌ی پویا فراخوانی شود، به رفتار تعریف‌نشده (**UB**) منجر می‌شود.
این یعنی کامپایلر می‌تواند آن را به هر شکلی که بخواهد، دلبخواهانه مدیریت کند.
مثال زیر که با دو کامپایلر مختلف کامپایل شده است، می‌تواند دو نتیجه‌ی متفاوت داشته باشد

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

کامپایلر اول و دوم وقتی `numbers` بین هر فراخوانی `free` روی `NULL` تنظیم می‌شد، هیچ خطای زمان اجرایی تولید نکردند، اما این تضمینی برای کار کردن با یک کامپایلر سوم نیست.
یکی از منابع رایج آزادسازی دوباره این است که دو اشاره‌گر داشته باشیم که به یک حافظه‌ی تخصیص‌یافته‌ی پویا اشاره کنند.
یک اشاره‌گر ممکن است در نقطه‌ای از برنامه به ابتدای یک آرایه اشاره کند و اشاره‌گر دیگر ممکن است در نقطه‌ی دیگری از برنامه برای گام‌زدن در آرایه به کار رود.
در نقاط مختلف برنامه، هر اشاره‌گر آزاد می‌شود و بدین‌ترتیب آزادسازی دوباره رخ می‌دهد.

## calloc

`calloc` تابعی است که در `stdlib.h` اعلام شده و هم برای تخصیص حافظه‌ی پویا و هم برای مقداردهی صفر به حافظه‌ی تازه تخصیص‌یافته به کار می‌رود.
اگر تخصیص موفقیت‌آمیز باشد، اشاره‌گری برگردانده می‌شود که به آدرس اولین بایت حافظه‌ی تخصیص‌یافته اشاره می‌کند.
اگر تخصیص موفقیت‌آمیز نباشد، `NULL` برگردانده می‌شود.
عاقلانه است که نتیجه‌ی `calloc` را برای `NULL` بررسی کنید و در صورت شکست، به‌شکلی مناسب با آن برخورد کنید.
اشاره‌گر برگردانده‌شده از نوع `pointer-to-void` است که تقریباً می‌توان آن را اشاره‌گری «عمومی» در نظر گرفت که می‌تواند به نوع مشخصی که حافظه از آن استفاده می‌کند تبدیل شود.
`calloc` دو پارامتر دارد.
پارامتر اول مشخص می‌کند که چه تعداد از نوع داده‌ی مشخص‌شده باید تخصیص یابد.
پارامتر دوم اندازه‌ی نوع داده‌ی مشخص‌شده برای تخصیص است.

در مثال زیر همه‌ی دستورهای `printf` باید همیشه `0` را نشان دهند، چون `calloc` تضمین می‌کند که مقادیر تازه تخصیص‌یافته را صفر کند.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc` تابعی است که در `stdlib.h` اعلام شده و برای گسترش یا کوچک‌کردن حافظه‌ی تخصیص‌یافته‌ی موجود به کار می‌رود.
اگر تخصیص مجدد موفقیت‌آمیز باشد، اشاره‌گری برگردانده می‌شود که به آدرس اولین بایت حافظه‌ی تخصیص‌مجددشده اشاره می‌کند.
اگر تخصیص مجدد موفقیت‌آمیز نباشد، `NULL` برگردانده می‌شود.
عاقلانه است که نتیجه‌ی `realloc` را برای `NULL` بررسی کنید و در صورت شکست، به‌شکلی مناسب با آن برخورد کنید.
`realloc` دو پارامتر دارد.
پارامتر اول اشاره‌گری به حافظه‌ی موجودِ در انتظار تخصیص مجدد است.
پارامتر دوم اندازه‌ی حافظه‌ی تخصیص‌مجددشده بر حسب بایت است.
مقادیری که پیش از گسترش حافظه تنظیم شده‌اند حفظ می‌شوند.
مهم است به یاد داشته باشید که حافظه‌ای که هنگام گسترش حافظه اضافه می‌شود، به صفر مقداردهی اولیه نمی‌شود و مقدار(های) آن می‌تواند هرچه باشد.
همچنین، حافظه‌ای که هنگام کوچک‌کردن حافظه حذف می‌شود نیز مقداردهی اولیه نمی‌شود و ممکن است مقدار(ها) را حفظ کند.
مثال زیر گسترش و کوچک‌کردن یک آرایه را نشان می‌دهد

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## وقتی اندازه‌ی سپرده‌شده ۰ است

اگر اندازه‌ی سپرده‌شده به `malloc`، `calloc` یا `relloac` برابر با `0` باشد، آنچه رخ می‌دهد بستگی به این دارد که کامپایلر آن را چگونه پیاده‌سازی کرده است.
یک کامپایلر ممکن است اشاره‌گر `NULL` برگرداند یا اشاره‌گری غیرتهی.
برای مثال، اگر حافظه برای یک اشاره‌گر به `char` تخصیص یابد، کامپایلر ممکن است `NULL` یا اشاره‌گری غیرتهی به یک رشته‌ی خالی برگرداند.
برای پرهیز از نتایج متفاوت با کامپایلرهای مختلف، بهتر است با اندازه‌ی ۰ تخصیص ندهید.
