# مقدمه

سیستم خطای Factor سه بخش دارد: `throw` برای اعلام یک خطا،
`recover` برای رسیدگی به یکی، و `ERROR:` برای تعریف نوع خطای
خودتان.

## `throw`

`throw` (در [`kernel`][kernel]) یک خطا ایجاد می‌کند. آرگومان می‌تواند
*هر* مقداری باشد (یک رشته، یک عدد، یا یک «تاپل») و همان خطایی
می‌شود که بعداً می‌توانید بررسی کنید:

```factor
! DOCTEST: SKIP
"file not found" throw
```

`throw` برنمی‌گردد؛ بقیه‌ی «واژه»ی جاری نادیده گرفته می‌شود.

## `recover`

`recover` (در [`continuations`][continuations]) معادل try/catch در
Factor است. یک «quotation» *try* و یک quotation *recovery* می‌گیرد:

```
recover ( try recovery -- )
```

اگر `try` بدون پرتاب خطا تمام شود، `recovery` نادیده گرفته
می‌شود. اگر `try` خطا پرتاب کند، خطا روی «پشته» قرار می‌گیرد و
`recovery` اجرا می‌شود:

```factor
[ "boom" throw ] [ drop "caught" ] recover .
! => "caught"

[ "ok" ] [ drop "never runs" ] recover .
! => "ok"
```

`when` از [`kernel`][kernel] همراه طبیعی آن است: یک quotation را
تنها زمانی اجرا می‌کند که بالای پشته مقداری باشد که درست ارزیابی
می‌شود:

```factor
: check-positive ( n -- )
    0 < [ "negative!" throw ] when ;
```

## `ERROR:`

`ERROR:` یک کلاس تاپل *و* یک واژه تعریف می‌کند که یک «نمونه»ی
تازه می‌سازد و آن را پرتاب می‌کند:

```factor
! DOCTEST: SKIP
ERROR: not-found path ;

"/missing" not-found
! throws T{ not-found { path "/missing" } }
```

یک خطای بدون «شکاف» فقط `ERROR: name ;` است؛ فراخوانی `name` یک
نمونه‌ی خالی پرتاب می‌کند. تاپل‌هایی که با `ERROR:` تعریف می‌شوند
یک «محمول» کلاس `name?` دارند که می‌توانید از آن برای آزمودن
اینکه آیا خطای گرفته‌شده از آن نوع بوده است استفاده کنید.

## خواندن مقادیر از شکاف‌ها

یک خطای گرفته‌شده فقط یک تاپل است، بنابراین هر شکاف `ERROR:` همان
«خواننده»ی `slot>>` خودکار را دارد که هر تاپل دیگری دارد.

```factor
! DOCTEST: SKIP
{
    T{ not-found { path "/a" } }
    T{ not-found { path "/b" } }
}
[ path>> ] map .   ! => { "/a" "/b" }
```
