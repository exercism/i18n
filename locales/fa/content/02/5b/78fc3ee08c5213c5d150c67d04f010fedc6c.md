# نکات
از `Option` برای نشان دادن محاسبه‌ای استفاده می‌شود که ممکن است هیچ نتیجه‌ی مفیدی نداشته باشد
(برای مثال، به دلیل یک خطا یا ورودی نامعتبر).
اگر با `Option` آشنایی ندارید، می‌توانید [این آموزش](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html) را بخوانید.
`Option` یک [موناد](https://en.wikipedia.org/wiki/Monad_(functional_programming)) است که به اصطلاح یک «جنبه‌ی محاسباتی» را پوشش می‌دهد، در این مورد، امکان نبودن یک مقدار.
استفاده‌ی درست از مونادها می‌تواند به کدی بسیار مختصر و در عین حال زیبا و خوانا منجر شود. استفاده‌ی نادرست به‌راحتی می‌تواند نتیجه‌ی برعکس بدهد.
برای یادگیری بیشتر [این ویدیو](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) را ببینید.
## دام‌های رایجی که باید از آن‌ها دوری کنید
چند قاعده‌ی سرانگشتی برای `Option` وجود دارد:
1. اگر به آن نیاز ندارید، از آن استفاده نکنید. به‌جای
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
بهتر است این را داشته باشید
```scala
def add1(x: Int): Int = x + 1
```
(تابع `Option.map` برای اعمال چنین توابع ساده‌ای وجود دارد،
بنابراین لازم نیست آن‌ها را با `Option` شلوغ کنید).
2. اگر واقعاً نیازی ندارید، مقدار را «بازگشایی» نکنید.
غالباً توابع توکاری برای هدف شما وجود دارد. نشانه‌های بازگشایی زودهنگام
`isDefined/isEmpty` یا تطبیق الگو هستند. به‌جای
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
بهتر است این را داشته باشید
```scala
x map (_ + 1) getOrElse 0
```
3. مونادها را می‌توان داخل یک for-comprehension به کار برد؛ FTW.
این کار زمانی توصیه می‌شود که بخواهید چند نمونه‌ی `Option` را «ترکیب» کنید. به‌جای
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
بهتر است این را داشته باشید
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
