# مقدمه

## نتیجه

Gleam برای مدیریت خطا از استثناها استفاده نمی‌کند؛ در عوض، توابعی که می‌توانند موفق شوند یا شکست بخورند، نوع جنریک `Result` را برمی‌گردانند.

نوع `Result` در خود زبان تعبیه شده است، پس نیازی نیست آن را تعریف یا ایمپورت کنید. اما اگر خودتان آن را تعریف می‌کردید، به این شکل بود:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

واریانت `Ok` زمانی برگردانده می‌شود که یک تابع موفق شود. واریانت `Error` هم زمانی برگردانده می‌شود که یک تابع شکست بخورد.

نتایج در Gleam بسیار رایج‌اند و برنامه‌نویسان Gleam معمولاً از [ماژول `gleam/result`](https://hexdocs.pm/gleam_stdlib/gleam/result.html) استفاده می‌کنند تا کار کردن با آن‌ها آسان‌تر شود.

از تابع `result.map` می‌توان استفاده کرد تا در صورتی که نتیجه `Ok` باشد، تابعی را روی مقدار درون آن فراخوانی کنیم، یا اگر `Error` بود، آن را بدون تغییر عبور دهیم.

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

تابع `result.try` مشابه است، اما انتظار می‌رود تابع کال‌بک یک نتیجه برگرداند. این برای زنجیره‌کردن چندین تابعی که نتیجه برمی‌گردانند مفید است.

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
