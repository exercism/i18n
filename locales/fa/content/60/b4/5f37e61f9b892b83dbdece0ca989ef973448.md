# مقدمه

[نوع‌های سفارشی][custom-types] در Elm تعداد ثابتی «حالت نام‌دار» را نمایش می‌دهند. هر مقدار دقیقاً با یکی از این حالت‌های نام‌دار متناظر است.

یک «نوع سفارشی» با کلیدواژه‌ی `type` تعریف می‌شود و نحوه‌ی نگارشش بسیار ساده است. انواع سفارشی یکی از مهم‌ترین تکنیک‌ها در برنامه‌نویسی Elm هستند و به کار می‌روند تا مقادیر ممکن در کد دقیقاً با مقادیر معتبر در دنیای واقعی منطبق شوند؛ این کار جایی برای داده‌های نامعتبر باقی نمی‌گذارد و باعث می‌شود حالت‌های ناممکن در کد قابل نمایش نباشند.

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

هر حالت از یک نوع سفارشی می‌تواند به‌صورت اختیاری داده‌ای همراه داشته باشد و حالت‌های مختلف می‌توانند انواع مختلفی از داده داشته باشند. اگر هیچ‌یک از حالت‌ها داده‌ای همراه نداشته باشند، این اجتماع تفکیک‌شده شبیه چیزی است که زبان‌های دیگر معمولاً آن را «شمارش» (یا «enum») می‌نامند.

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

برای ساختن یک مقدار برای یک حالت مشخص، می‌توان به اسم آن حالت (`Spring`) ارجاع داد، چه هنگامیکه آن حالت در همان ماژول تعریف شده باشد و چه هنگامیکه با نگارش `import SeasonModule exposing (Season(..))` وارد شده باشد. همچنین می‌توان با ارجاع به نام کامل آن (`Season.Spring`) مقدار ساخت، هنگامیکه با نگارش `import SeasonModule exposing (Season)` وارد شده باشد.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

انواع سفارشی، همانند همه‌ی موارد دیگر در Elm، «برابری ساختاری» دارند؛ یعنی دو مقدار برای یک حالت یکسان و با داده‌ی (اختیاری) یکسان، معادل‌اند.

روش ترجیحی کار با انواع سفارشی، [تطبیق الگو][pattern-matching] است:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
