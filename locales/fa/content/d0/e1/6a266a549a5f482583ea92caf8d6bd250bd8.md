# مقدمه

یک **«حلقه»** دنباله‌ای از دستورهاست که ممکن است بیش از یک بار اجرا شود، تا اینکه شرط پایانی برقرار شود.

در x86-64، حلقه معمولاً با یک پرش به برچسب قبلی ساخته می‌شود:

```x86asm
example_loop:
    ...
    jmp example_loop
```

توجه کنید که یک پرش غیرشرطی به برچسب قبلی همیشه اجرا را به این برچسب منتقل می‌کند.
یعنی حلقه تا ابد تکرار می‌شود، مگر اینکه پرش دیگری به بیرون از دنباله‌ی تکرارشده وجود داشته باشد.

برای نمونه، این حلقه پایان نمی‌یابد:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

و این حلقه ممکن است پایان یابد، بسته به اینکه شرط برقرار شود:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## حلقه‌ی شمارشی

یک حلقه‌ی شمارشی تقریباً همیشه به یک شکل پایان می‌یابد: دستوری که یک شمارنده را به‌روزرسانی می‌کند یا دو مقدار را مقایسه می‌کند و بلافاصله پس از آن یک پرش شرطی می‌آید که تصمیم می‌گیرد آیا یک دور دیگر تکرار شود یا نه.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
در کد بالا، `cmp rsi, 0` لازم نیست، چون `sub rsi, 1` وقتی نتیجه `0` باشد از قبل `zero flag (ZF)` را تنظیم می‌کند.

هرچند `cmp` روش اصلی آزمودن شرط‌ها در اسمبلی است، بسیاری از دستورها پرچم‌ها را به‌روزرسانی می‌کنند.
برای نمونه، بسیاری از دستورهای حساب صحیح یا بیتی، `ZF` را وقتی نتیجه `0` باشد و `SF` را وقتی نتیجه منفی باشد (یعنی بالاترین بیت تنظیم شده باشد) به‌روزرسانی می‌کنند.

می‌توانید به یک [مرجع][reference] مراجعه کنید تا ببینید هر دستور روی کدام پرچم‌ها اثر می‌گذارد.

[reference]: https://www.felixcloutier.com/x86/
~~~~

توجه کنید که در مثال بالا، فرض می‌شود `rsi` بزرگ‌تر از `0` است.
اگر `0` بود، آنگاه `sub rsi, 1` مقدار `rsi` را به `-1` کاهش می‌داد که یک عدد بدون‌علامت بسیار بزرگ است.
پیش از آنکه حلقه سرانجام پایان یابد، `18,446,744,073,709,551,615` تکرار دیگر لازم است.
همچنین چون طول آرایه `0` است، هر دسترسی به حافظه خارج از محدوده خواهد بود.

اگر هیچ تضمینی درباره‌ی طول آرایه وجود نداشته باشد، دو رویکرد رایج وجود دارد.

رویکرد اول این است که شرط پایانی را به ابتدای حلقه منتقل کنید و بعد یک پرش غیرشرطی در انتها داشته باشید:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

رویکرد دوم این است که پیش از آغاز حلقه، یک بار بررسی کنید که آیا طول آرایه صفر است:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

این رویکرد دوم معمولاً کارآمدتر از رویکرد اول است، چون انشعاب‌های کمتری در بدنه‌ی حلقه وجود دارد.
در یک مفهوم آینده درباره‌ی این بیشتر خواهید آموخت.

~~~~exercism/advanced
در برخی موقعیت‌ها، پردازنده‌های مدرن می‌توانند دو دستور متفاوت را در یک عملیات ادغام کنند.
به این بهینه‌سازی **«ماکروفیوژن»** می‌گویند.

بسیاری از دستورهای حسابی مانند `sub` و `add` و همچنین `cmp` و `test`، معمولاً با پرش شرطی‌ای که بلافاصله پس از آن‌ها می‌آید ادغام می‌شوند.
یعنی دستوری مانند `cmp rax, rdx` که بلافاصله بعد از آن یک پرش شرطی می‌آید، معمولاً می‌تواند توسط پردازنده به عنوان یک عملیات واحد در نظر گرفته شود.

ماکروفیوژن به پردازنده بستگی دارد و در اینکه کدام دستورها با کدام پرش شرطی ادغام می‌شوند، تفاوت‌هایی وجود دارد.

یک مرجع مفید، [ریزمعماری پردازنده‌های Intel، AMD و VIA، نوشته‌ی Agner Fog][agner-uarch] است.
بخش ۳.۴.۲.۲ («بهینه‌سازی برای ماکروفیوژن») از [راهنمای مرجع بهینه‌سازی Intel][intel-opt] هم جفت‌های قابل ادغام برای پردازنده‌های Intel را فهرست می‌کند.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
