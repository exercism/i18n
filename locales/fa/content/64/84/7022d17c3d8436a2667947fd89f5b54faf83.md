# کلاس انتزاعی

یک نمایش سیرک فهرستی از اجراهاست. ژانگولربازی، تراپز و آکروبات‌بازی هر کدام متفاوت‌اند و درون متفاوتی دارند، اما کسی که ترتیب اجرا را می‌چیند از هر کدام فقط دو مورد می‌خواهد: اینکه چه اسمی دارد و چقدر طول می‌کشد.

یک **«کلاس انتزاعی»** فقط همین اندازه را توصیف می‌کند، نه بیشتر.

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end; -- abstract class $ACT
```

اسمش با `$` شروع می‌شود. روال‌هایی را فهرست می‌کند بدون بدنه: فقط امضا، و هر یک به نقطه‌ویرگول ختم می‌شود. از آن نمی‌توان چیزی ساخت؛ نه `create` دارد و نه `new`.

## انطباق

یک کلاس واقعی با نوشتن اسم آن بعد از `<` تعهد می‌دهد که یک `$ACT` باشد:

```sather
class JUGGLING < $ACT is

   create : SAME is return new; end;

   name : STR is return "Juggling"; end;

   minutes : INT is return 5; end;

end; -- class JUGGLING
```

علامت `<` به معنای «یک ... است» خوانده می‌شود. کلاس باید همه‌ی روال‌هایی را که کلاس انتزاعی فهرست می‌کند فراهم کند، با همان آرگومان‌ها و همان نوع بازگشتی. جا انداختن یکی از آن‌ها خطای زمان کامپایل است، نه غافلگیری در زمان اجرا.

یک کلاس می‌تواند هر چه بخواهد به آن اضافه کند. `TRAPEZE` می‌تواند ارتفاعی داشته باشد که هیچ اجرای دیگری ندارد؛ کلاس انتزاعی نه آن را می‌داند و نه برایش مهم است.

## استفاده از نوع

`$ACT` یک نوع است، بنابراین هر چیزی را می‌توان با آن اعلام کرد:

```sather
   acts : ARRAY{$ACT} := |#JUGGLING, #TRAPEZE(4), #TUMBLING|;
```

آن آرایه هم‌زمان اشیایی از سه کلاس متفاوت را در خود نگه می‌دارد، کاری که یک `ARRAY{JUGGLING}` نمی‌توانست انجام دهد.

## اعزام

```sather
   loop
      total := total + acts.elt!.minutes;
   end;
```

`acts.elt!` یک `$ACT` است. اینکه کدام `minutes` اجرا شود، وقتی این خط اجرا می‌شود و بر اساس اینکه شیء واقعاً چیست تعیین می‌شود: برای ژانگولربازی `JUGGLING::minutes` و برای تراپز `TRAPEZE::minutes`. به این انتخاب، **«اعزام»** می‌گویند.

روالی که این جمع را انجام می‌دهد هیچ‌وقت نمی‌پرسد که با چه نوع اجرایی سر و کار دارد. اضافه کردن یک نوع چهارم از اجرا یعنی نوشتن یک کلاس تازه و دست نزدن به باقی کد؛ و همین دلیل اصلی انجام این کار به این شکل است.
