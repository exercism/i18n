# دستورالعمل‌ها

به شما سپرده شده است که یک کتابخانه‌ی لاگ بسازید تا در مدیریت لاگ‌های سازمانتان کمک کند.
این کتابخانه به کاربران امکان می‌دهد تشخیص دهند کدام برنامه یک لاگ مشخص را تولید کرده است، لاگ‌های خراب را اصلاح کنند و تعیین کنند که آیا یک خط لاگ مشخص در محدوده‌ی تعداد کاراکتر معینی قرار دارد یا نه.

## 1. مشخص کنید کدام برنامه یک لاگ را تولید کرده است

لاگ‌ها از چندین برنامه می‌آیند که هر کدام از قالب لاگ اختصاصی خودش استفاده می‌کند.
پیش از آنکه یک لاگ در سیستم تجمیع لاگ ذخیره شود، باید برنامه‌ای که آن را تولید کرده است مشخص شود.

تابع `Application` را پیاده‌سازی کنید که یک خط لاگ را می‌گیرد و برنامه‌ای را برمی‌گرداند که آن خط لاگ را تولید کرده است.

برای تشخیص اینکه کدام برنامه یک خط لاگ مشخص را تولید کرده است، خط لاگ را برای یافتن کاراکتر مشخصی که در جدول زیر آمده است جست‌وجو کنید:

| برنامه           | کاراکتر | نقطه‌ی کد یونیکد    |
|------------------|-----------|--------------------|
| `recommendation` | ❗        | `U+2757`           |
| `search`         | 🔍        | `U+1F50D`          |
| `weather`        | ☀         | `U+2600`           |

اگر یک خط لاگ هیچ‌کدام از کاراکترهای جدول بالا را نداشته باشد، مقدار `default` را به فراخوانی‌کننده برگردانید.
اگر یک خط لاگ بیش از یک کاراکتر از جدول بالا داشته باشد، برنامه‌ای را برگردانید که با نخستین کاراکتر یافت‌شده در خط لاگ، از چپ به راست، متناظر است.

```go
Application("❗ recommended search product 🔍")
// => recommendation
```

## 2. لاگ‌های خراب را اصلاح کنید

به دلیل یک باگ نادر اما پایدار در زیرساخت لاگ‌گیری، برخی کاراکترها در لاگ‌ها می‌توانند خراب شوند.
پس از آنکه زمانی را صرف شناسایی کاراکترهای خراب و مقدار اصلی آن‌ها کردید، تصمیم می‌گیرید کتابخانه‌ی لاگ را به‌روزرسانی کنید تا در اصلاح لاگ‌های خراب کمک کند.

تابع `Replace` را پیاده‌سازی کنید که یک خط لاگ، یک کاراکتر خراب و مقدار اصلی را می‌گیرد و یک خط لاگ تغییر‌یافته را برمی‌گرداند که در آن همه‌ی موارد وقوع کاراکتر خراب با مقدار اصلی جایگزین شده‌اند.

```go
log := "please replace '👎' with '👍'"

Replace(log, '👎', '👍')
// => please replace '👍' with '👍'"
```

## 3. تعیین کنید که آیا یک لاگ قابل نمایش است

سیستم‌هایی که مسئول نمایش لاگ‌ها هستند، محدودیتی روی تعداد کاراکترهایی دارند که می‌توان در هر خط لاگ نمایش داد.
به همین دلیل، کاربران می‌خواهند این کتابخانه یک تابع کمکی داشته باشد تا تعیین کند آیا یک خط لاگ در محدوده‌ی تعداد کاراکتر مشخصی قرار دارد یا نه.

تابع `WithinLimit` را پیاده‌سازی کنید که یک خط لاگ و سقف کاراکتر را می‌گیرد و برمی‌گرداند که آیا خط لاگ در محدوده‌ی سقف کاراکتر قرار دارد یا نه.

```go
WithinLimit("hello❗", 6)
// => true
```
