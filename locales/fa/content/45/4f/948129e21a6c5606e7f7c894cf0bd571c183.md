# مقدمه

جاوااسکریپت یک شیء داخلی به اسم `Date` دارد که تاریخ و زمان را ذخیره می‌کند و متدهایی برای مدیریت آن‌ها فراهم می‌کند.

<!-- prettier-ignore -->
~~~exercism/caution
این شیء بر پایه‌ی کلاس `java.util.Date` در جاوا ساخته شد، که در اوایل دهه‌ی ۲۰۱۰ جایگزین شد، اما جاوااسکریپت برای سازگاری با گذشته هنوز `Date` را نگه داشته است.

چون کار کردن با تاریخ‌ها به‌طور کلی دشوار است و چون مدیریت منطقه‌ی زمانی ضعیف است یا تقریباً وجود ندارد، کتابخانه‌های زیادی مثل `moment.js`، `day.js`، `date-fns` و `luxon` ساخته شده‌اند.
هیچ‌کدام از این‌ها در Exercism در دسترس نیستند.

در پروژه‌های خودتان از بسته‌های منسوخ یا بدون پشتیبانی مثل `moment.js` استفاده نکنید و به‌جای آن به گزینه‌های مدرن‌تری مثل `luxon` یا [Temporal][mdn-temporal] که هنوز به‌طور گسترده در دسترس نیست تکیه کنید.
این تمرین روی `Date` تمرکز دارد، که تا پایان عمر جاوااسکریپت مهم و کاربردی می‌ماند.

[mdn-temporal]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal
~~~

## ساخت

یک شیء `Date` نمونه‌ای از کلاس `Date` است.
می‌توان آن را بدون فرستادن هیچ آرگومانی به تابع سازنده ساخت.
نتیجه یک شیء `Date` است که تاریخ و زمان کنونی را نشان می‌دهد:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### مهر زمانی یونیکس (عدد)

اگر عددی فرستاده شود، به‌عنوان یک `timestamp` تفسیر می‌شود.
یک مهر زمانی عددی صحیح است که تعداد **میلی‌ثانیه**هایی را نشان می‌دهد که از ۱ ژانویه ۱۹۷۰ [UTC][defn-utc]+۰ گذشته است.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

شاید انتظار داشته باشید که `new Date(0)` «زودترین» شیء تاریخ را بسازد، اما جاوااسکریپت تاریخ را به منطقه‌ی زمانی محلی شما تبدیل می‌کند، یعنی فقط کسانی که در محدوده‌ی منطقه‌ی زمانی [GMT / با UTC+۰][defn-gmt] قرار دارند در واقع مقدار [Unix epoch][defn-unix-epoch] را به دست می‌آورند.

### مهر زمانی ISO 8601 (رشته)

می‌توانید یک مقدار رشته‌ای که نماینده‌ی یک تاریخ است به سازنده‌ی `Date` بفرستید.
**تنها** قالبی که در همه‌ی پیاده‌سازی‌ها یکسان است، [نسخه‌ی ساده‌شده][mdn-date-string-format] رشته‌های به‌اصطلاح [مهر زمانی ISO 8601][defn-iso8601] است که در سطح بین‌المللی شناخته و استاندارد شده‌اند.

یک لحظه‌ی زمانی در [UTC][defn-gmt] به این شکل است:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

که در آن جایگذاری‌های زیر انجام می‌شود:

| کلید | توضیح                                         | پیش‌فرض |
| ---- | --------------------------------------------- | ------- |
| YYYY | سال تقویمی، با ۴ رقم                          |         |
| MM   | ماه تقویمی، با ۲ رقم                          | 01      |
| DD   | روز تقویمی، با ۲ رقم                          | 01      |
| T    | حرف ثابت T، که تاریخ را از زمان جدا می‌کند    |         |
| HH   | ساعت‌ها در قالب ۲۴ساعته، ۲ رقم                | 00      |
| mm   | دقیقه‌ها، ۲ رقم                               | 00      |
| ss   | ثانیه‌ها، ۲ رقم                               | 00      |
| mss  | میلی‌ثانیه‌ها، ۳ رقم                          | 000     |
| Z    | حرف ثابت Z، یا یک انحراف `+/-HH:mm`           |         |

حرف ثابت `Z` نشان‌دهنده‌ی UTC است (بدون منطقه‌ی زمانی، بدون ساعت تابستانی).

چون برای بیشتر اجزا مقدار پیش‌فرض وجود دارد، حذف بخش‌هایی از انتها مجاز است:

```text
YYYY-MM-DD
```

مقدار پیش‌فرض آن زمانی برابر 00:00:00.000 است.

اگر مهر زمانی به `Z` ختم نشود و با `+HH:mm` یا `-HH:mm` هم پایان نیابد (که نشان‌دهنده‌ی انحراف منطقه‌ی زمانی است)، به دلایل تاریخی، قاعده‌ی زیر برقرار است:

> وقتی انحراف منطقه‌ی زمانی وجود ندارد، شکل‌های فقط-تاریخ به‌عنوان زمان UTC و شکل‌های تاریخ-زمان به‌عنوان زمان محلی تفسیر می‌شوند.
> تفسیر به‌عنوان زمان UTC ناشی از یک خطای تاریخی در مشخصات است که با ISO 8601 سازگار نبود، اما به دلیل سازگاری با وب نمی‌توانست تغییر کند.
> به [Broken Parser – A Web Reality Issue][ref-broken-parser] نگاه کنید.

### شیء Date

از یک شیء Date موجود هم می‌توان به‌عنوان آرگومان سازنده استفاده کرد.
این کار یک نسخه از شیء `Date` موجود با همان تاریخ و زمان می‌سازد.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### وارد کردن مقادیر جداگانه‌ی اجزای تاریخ و زمان

شیء تاریخی که فقط یک تاریخ را نشان می‌دهد با فرستادن سه عدد ساخته می‌شود.
و شیء تاریخی که تاریخ و زمان را نشان می‌دهد با فرستادن ۶ عدد ساخته می‌شود.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

مقدار دوم `month` است که از `0` برای ژانویه شروع می‌شود و تا `11` برای دسامبر ادامه دارد.

## `Date.parse()`

ممکن است اشاره‌ها یا ارجاع‌هایی به یک تابع تجزیه‌ی تاریخ به اسم `Date.parse` ببینید.
چون برای این تابع فقط چند ویژگی ثابت (و درست) وجود دارد و چون بقیه‌ی پیاده‌سازی مشخص نشده است (و بنابراین استاندارد نیست)، نباید از آن استفاده کرد.

## دسترسی به اجزای `Date`

متدهای مختلفی روی شیءهای Date وجود دارد که اجزای تاریخ را برمی‌گردانند:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

هر یک از این‌ها یک نسخه‌ی `set` متناظر دارد (مثلاً `setFullYear`) که مقدار را به‌روزرسانی می‌کند.
هر مقدار سرریزی به جزء بعدی منتقل می‌شود:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

برای همه‌ی متدهایی که منطقه‌ی زمانی محلی را نادیده می‌گیرند، نسخه‌های UTC هم وجود دارد.

## تبدیل از تاریخ

شیءهای Date متدی به نام `getTime()` دارند که مهر زمانی UNIX را بر حسب میلی‌ثانیه برمی‌گرداند، یعنی تعداد میلی‌ثانیه‌های نیمه‌شب اول ژانویه ۱۹۷۰ به وقت UTC.
همچنین متد `toISOString()` در دسترس است تا یک شیء تاریخ را به رشته‌ی مهر زمانی ISO 8601 تبدیل کند.

## مقایسه‌ی تاریخ‌ها

عملگرهای بزرگ‌تر از (`>`) و بزرگ‌تر یا مساوی (`>=`) و همچنین کوچک‌تر از (`<`) و کوچک‌تر یا مساوی (`<=`) را می‌توان مستقیماً بین دو تاریخ یا بین یک تاریخ و یک عدد به کار برد.
این کار جواب می‌دهد چون جاوااسکریپت تلاش می‌کند تاریخ را به یک مقدار اولیه تبدیل کند.
