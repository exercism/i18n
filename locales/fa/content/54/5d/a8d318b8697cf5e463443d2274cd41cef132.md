# مقدمه

یک **ممیز شناور** عددی است که می‌تواند بخش کسری داشته باشد، مانند `-1.23` یا `3.1415`.

برای نمایش چنین عددی به‌صورت دنباله‌ای از بایت‌ها، x86-64 از استاندارد **IEEE-754** استفاده می‌کند.
دو قالب رایج‌تر در این استاندارد، اعداد ممیز شناور با دقت ساده و ممیز شناور با دقت مضاعف هستند.
x86-64 از هر دو پشتیبانی می‌کند.

یک عدد ممیز شناور با دقت ساده ۳۲ بیت عرض دارد، در حالی که نوع دقت مضاعف ۶۴ بیت عرض دارد.

## رجیسترهای XMM

در x86-64، شانزده رجیستر اختصاصی برای انجام محاسبات ممیز شناور وجود دارد که `xmm0` تا `xmm15` نام دارند.

این رجیسترها دست‌کم ۱۲۸ بیت عرض دارند، اما پردازنده‌های جدیدتر این مقدار را به ۲۵۶ یا ۵۱۲ بیت افزایش می‌دهند.
با این حال، در عمل، بیشتر اعداد ممیز شناور تنها از پایین‌ترین ۳۲ یا ۶۴ بیت استفاده می‌کنند، بسته به دقت موردنظر.

## تبدیل بین اعداد

خانواده‌ای از دستورها برای تبدیل بین قالب‌های عددی وجود دارد: `cvtxx2yy`.

هر دو `xx` و `yy` مقدار ثابت نیستند، بلکه جای‌نگهدار هستند:

- `xx` جای‌نگهدار نوع عملوند مبدأ است.
- `yy` جای‌نگهدار نوع عملوند مقصد است.

این جای‌نگهدار می‌تواند شکل‌های گوناگونی داشته باشد، از جمله:

| جای‌نگهدار | معنی                  |
| ----------- | --------------------- |
| `si`        | عدد صحیح علامت‌دار     |
| `ss`        | ممیز شناور ۳۲ بیتی    |
| `sd`        | ممیز شناور ۶۴ بیتی    |

برای مثال:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

توجه کنید که می‌توان یک عدد صحیح ۳۲ بیتی را به یک ممیز شناور ۶۴ بیتی یا یک عدد صحیح ۶۴ بیتی را به یک ممیز شناور ۳۲ بیتی تبدیل کرد.
به‌همین‌ترتیب، می‌توان یک ممیز شناور ۳۲ بیتی را به یک عدد صحیح ۶۴ بیتی یا یک ممیز شناور ۶۴ بیتی را به یک عدد صحیح ۳۲ بیتی تبدیل کرد.
به عبارت دیگر، اندازه‌ی هر دو عملوند در یک `cvtxx2yy` _لازم نیست یکسان باشند_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

وقتی عدد ممیز شناور نتواند به‌طور دقیق به‌صورت یک عدد صحیح بیان شود، `cvtxx2si` عدد را بر اساس کنترل گرد کردن در یک رجیستر ویژه به نام `mxcsr` گرد می‌کند.
این می‌تواند گرد کردن به نزدیک‌ترین، گرد کردن به پایین، گرد کردن به بالا یا برش باشد.
هیچ حالت پیش‌فرض تضمین‌شده‌ای در ورود به تابع وجود ندارد.

توجه کنید که یک نتیجه‌ی دقیق گرد نمی‌شود و بنابراین تحت تأثیر کنترل گرد کردن قرار نمی‌گیرد.
برای نمونه، `42.0` _همیشه_ به `42` تبدیل می‌شود.

خانواده‌ی مشابهی از دستورها با قالب `cvttxx2si` (با یک `t` اضافه) وجود دارد که همیشه نتیجه را برش می‌دهد.

## گرد کردن

خانواده‌ی دستورهای `roundxx` یک ممیز شناور در عملوند مبدأ را به یک ممیز شناور گردشده تبدیل می‌کند که در عملوند مقصد ذخیره می‌شود.

در اینجا، `xx` مانند همیشه جای‌نگهدار نوع عملوندها است: `ss` برای ممیز شناور با دقت ساده و `sd` برای ممیز شناور با دقت مضاعف.

این دستورها یک عدد ثابت را به‌عنوان عملوند سوم می‌گیرند.
این عدد حالت گرد کردن را مشخص می‌کند:

| عدد | حالت         |
| :----- | :----------- |
| 0      | نزدیک‌ترین   |
| 1      | کف (پایین)   |
| 2      | سقف (بالا)   |
| 3      | برش          |

برای مثال:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

از آنجا که این دستورها نتیجه‌ی دقیقی تولید می‌کنند، می‌توانند به‌عنوان آماده‌سازی برای یک `cvtxx2si` به کار روند.

## دستورهای ریاضی

بسیاری از عملیات با اعداد ممیز شناور، دستورهایی با نامی مشابه معادل عدد صحیح خود می‌گیرند، با این تفاوت که جای‌نگهدار لازم (`ss` یا `sd`) به انتهای آن اضافه می‌شود.
این دستورها دو عملوندی هستند، با معناشناسی معمول، حتی آن‌هایی که ضرب یا تقسیم انجام می‌دهند:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## انتقال

دستورهای انتقال از یک رجیستر XMM به رجیستر دیگر `movss` یا `movsd` هستند:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

**نمی‌توان** یک مقدار بی‌واسطه (یک عدد صحیح ثابت علامت‌دار) را به‌طور مستقیم به یک رجیستر xmm منتقل کرد.
این عدد ابتدا باید به یک رجیستر همه‌منظوره منتقل شود و سپس با استفاده از `cvtsi2xx` تبدیل گردد:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## مقایسه

دو گروه دستور برای مقایسه بین دو عدد ممیز شناور وجود دارد.
آن‌ها به شکل `comixx` و `ucomixx` هستند، که در آن‌ها `xx` یا `ss` است یا `sd`.
هر دو مانند همیشه پرچم‌هایی در `rflags` تنظیم می‌کنند و همان معناشناسی `cmp` را دنبال می‌کنند.

تفاوت آن‌ها در این است که `ucomixx` اگر یکی از دو عدد ممیز شناور مقدار `NaN` داشته باشد، `parity flag (PF)` را تنظیم می‌کند، در حالی که `comixx` در این حالت یک استثنا ایجاد می‌کند.

مقایسه بین مقادیر ممیز شناور _بدون علامت_ است:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## قرارداد فراخوانی

در System V ABI، هشت آرگومان اول ممیز شناور به‌ترتیب، از `xmm0` تا `xmm7`، به توابع فرستاده می‌شوند.
مقادیر ممیز شناور از توابع در `xmm0` و در صورت لزوم در `xmm1` برگردانده می‌شوند.

همه‌ی رجیسترهای `xmm` آزادانه در دسترس هستند و هیچ‌کدام برای فراخوان‌کننده رزرو نشده است.

## حافظه

مقادیر ممیز شناور را می‌توان در حافظه با همان معناشناسی اعداد صحیح هم‌اندازه تعریف کرد.
NASM (اسمبلر Netwide، اسمبلری که این مسیر از آن استفاده می‌کند) همچنین اعلان مقادیر ممیز شناور را در نماد علمی ممکن می‌سازد.

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```
