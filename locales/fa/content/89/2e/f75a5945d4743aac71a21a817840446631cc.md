# درباره

در C#، یک تاپل یک ساختار داده است که داده‌ها را سازمان می‌دهد و دو یا چند فیلد از هر نوعی را در خود نگه می‌دارد.

یک تاپل معمولاً با قرار دادن ۲ عبارت یا بیشتر که با کاما از هم جدا شده‌اند، داخل یک جفت پرانتز ساخته می‌شود.

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

تاپل مثل هر عبارت دیگری می‌تواند به روش‌های گوناگونی به کار رود: در [تخصیص‌ها][tuple-assignment]، برای مقداردهی اولیه به یک فیلد یا متغیر، به عنوان [مقدار بازگشتی][tuple-return-values] از یک متد، یا به عنوان پارامتری که پاس داده می‌شود. می‌توان [برابری][tuple-equality] آن‌ها را آزمایش کرد. برابری تاپل‌ها به‌طور کامل در تمرین `pattern-matching-tuples` نشان داده شده است، اما برای کامل بودن، مثالی در کد زیر آورده شده است.

فیلدها با استفاده از نحوه‌ی نگارش نقطه‌ای استخراج می‌شوند. به‌طور پیش‌فرض، فیلد اول `Item1` است، دومی `Item2` و به همین ترتیب. اسم‌های غیرپیش‌فرض در ادامه، زیر بخش _نام‌گذاری_، بحث می‌شوند.

یک تاپل می‌تواند به عنوان یک پارامتر جنریک به کار رود، مثلاً `IList<(bool, string)>`

علاوه بر این، تاپل‌ها از «ساختارشکنی» پشتیبانی می‌کنند که در ادامه بحث می‌شود، و می‌توانند در تطبیق الگو به کار روند که در تمرینی بعدی پوشش داده می‌شود.

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

این [مقدمه][tuples] نشان می‌دهد که چگونه تاپل‌ها را تعریف و استفاده کنیم.

## نام‌گذاری

اسم‌های فیلدهایی مثل `Item1` کد خوانا تولید نمی‌کنند. سه راه برای اسم دادن به فیلدها وجود دارد: الف) در اعلان نوع، ب) در عبارتی که آن را می‌سازد، پ) با استفاده از [مقداردهی‌های اولیه‌ی تصویرسازی تاپل][tuple-projection-initializers] (که اینجا نشان داده نشده است).

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

سعی نکنید با سازوکار نام‌گذاری بیش از حد زیرکانه رفتار کنید. این در واقع فقط یک میانبر در نحوه‌ی نگارش است. برای مثال، وقتی از یک تاپل دیگر به یک تاپل مقدار تخصیص می‌دهید، نمی‌توانید اسم‌های آن را تغییر دهید.

## ساختارشکنی

گاهی راحت است که یک تاپل را بردارید و فیلدهایش را به چند متغیر تخصیص دهید و در صورت لزوم آن‌ها را مقداردهی اولیه کنید. به این سازوکار [ساختارشکنی][tuple-deconstruction] می‌گویند. (می‌توان آن را روی اشیای خودتان هم اعمال کرد. [اینجا][udt-deconstruction] را ببینید).

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## تخصیص فیلد

می‌توان به فیلدهای تاپل‌ها به‌صورت جداگانه مقدار تخصیص داد. اما با توجه به گرایش C# به سمت تغییرناپذیری، این نوع استفاده چندان رایج نیست. تاپل‌ها اغلب طوری به کار می‌روند که گویی تغییرناپذیرند، که البته چنین نیستند.

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## پیشینه

تاپل‌هایی که درباره‌شان بحث می‌کنیم را نباید با [`System.Tuple`][system-tuple] اشتباه گرفت که احتمالاً فقط در پایگاه‌های کد قدیمی یافت می‌شود.

وقتی به `System.ValueTuple` می‌رسیم، وضعیت کمی گیج‌کننده‌تر است. در [مستندات][system-value-tuple] مربوط به آخرین بارگذاری مجددِ [`System.ValueTuple`][system-value-tuple] آمده است که «انواع تاپل مقداری، پیاده‌سازی زمان اجرایی را فراهم می‌کنند که از تاپل‌ها در C# پشتیبانی می‌کند». منظورشان از «انواع تاپل مقداری» در اینجا بارگذاری‌های مجدد جنریک `System.ValueTuple` است. منظورشان از «تاپل‌ها» چیزهایی است که در این تمرین به آن‌ها پرداخته‌ایم. در واقع دارند می‌گویند که `System.ValueTuple` یک جزئیات پیاده‌سازی از تاپل‌هاست. احتمالاً این موضوع بیشتر وقت‌ها برای بیشتر افراد چندان جالب نیست. متأسفانه بسیاری از مستندات مربوط به «تاپل‌ها»، از جمله مستندات خود مایکروسافت، به‌طور سخاوتمندانه‌ای با ارجاع به `System.ValueTuple` آمیخته شده‌اند. احتمالاً بی‌خطر است که از این ارجاع‌ها سرسری بگذریم.

## دیگر کاربردها و محدودیت‌ها

تطبیق الگو یکی از کاربردهای بسیار پربار تاپل‌هاست. این موضوع در تمرینی بعدی پوشش داده می‌شود.

تاپل‌ها امکان چند ظرافت سبکی جزئی دیگر را هم فراهم می‌کنند:

- تخصیص چندگانه (به‌ویژه در سازنده‌ها)، مثلاً `(this.field1, this.field2) = (arg1, arg2);`
- جابه‌جایی یا بازیافت مقادیر، مثلاً `(a, b) = (b, a);`
- استفاده به‌جای یک `struct` در یک لیست
- استفاده به عنوان کلید یک دیکشنری یا محتویات یک مجموعه.
- استفاده در LINQ. (LINQ در تمرین‌های بعدی پوشش داده می‌شود).

مستندات تاپل‌ها را سازوکاری سبک توصیف می‌کند و همین کلید استفاده‌ی موفق از آن‌هاست. استفاده از یک تاپل به‌جای یک کلاس یا struct می‌تواند به تکرار خسته‌کننده‌ی انواع فیلدهایش و احتمالاً اسم‌هایشان بیانجامد. این موضوع به‌ویژه در استفاده از آن به عنوان آرگومان یک متد یا به عنوان آرگومان جنریک در مجموعه‌ها صدق می‌کند.

بهتر است از ترفندهایی مثل تخصیص چندگانه و جابه‌جایی با سنجیدگی استفاده کنید.

عملیات رابطه‌ای غیر از برابری و نابرابری پشتیبانی نمی‌شوند.

توجه داشته باشید که تاپل‌ها نسبتاً به‌تازگی به این زبان اضافه شده‌اند (C# ۷)، بنابراین اگر می‌خواهید از آن‌ها استفاده کنید باید مطمئن شوید که کد شما از [نسخه][language-version] ۷ یا بالاتر این زبان استفاده می‌کند.
