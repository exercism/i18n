# تست‌ها

هر تمرین یک فایل تست دارد.
تست‌ها را با برنامه‌ی `bats` اجرا کنید.

```bash
bats test-hello-world.bats
```

`bats` باید نصب شده باشد.
برای دستورالعمل‌های نصب `bats` روی سیستم خودتان، صفحه‌ی [تست در مسیر Bash][bash] را ببینید.

### `bats` با `bash` پیاده‌سازی شده است

فایل `bats` یک اسکریپت `bash` است و چند تابع ویژه دارد که دستور `bats` آن‌ها را می‌شناسد.
تست‌هایی می‌بینید که به این شکل هستند:

```sh
jq -f some-exercise.jq <<< "{some,json,here}"
```

آن نحوه‌ی نگارش `<<<` همان [Here String][here-string] در `bash` است.
این ساختار، رشته‌ی سمت راست را به ورودی استاندارد برنامه‌ی سمت چپ می‌فرستد.
معادل ([تقریباً][so]) این کد است:

```sh
echo "{some,json,here}" | jq -f some-exercise.jq
```

## راهنما برای توابع `assert`

تست‌ها از توابع کتابخانه‌ی [bats-assert][bats-assert] استفاده می‌کنند.
راهنمای توابع مختلف `assert*` را همان‌جا می‌توانید پیدا کنید.

## تست‌های نادیده‌گرفته‌شده

حل کردن یک تمرین یعنی این‌که همه‌ی تست‌های آن پاس شوند.
به‌طور پیش‌فرض، وقتی تست‌ها را اجرا می‌کنید، فقط یک تست (اولین تست) اجرا می‌شود.
این کار عمدی است، چون به شما امکان می‌دهد فقط روی پاس کردن همان یک تست تمرکز کنید.
وقتی آن تست پاس شد، می‌توانید تست بعدی را فعال کنید.

    [[ $BATS_RUN_SKIPPED == true ]] || skip

کافی است این حاشیه‌نویسی را که پیش از تست‌های دیگر می‌آید، کامنت کنید یا حذف کنید.

## لغو نادیده‌گرفتن تست‌ها

برای اجرای همه‌ی تست‌ها، از جمله آن‌هایی که حاشیه‌نویسی `skip` دارند، می‌توانید این دستور را اجرا کنید:

```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

ممکن است استفاده از یک تابع پوششی برای صرفه‌جویی در تایپ کردن راحت باشد؛ در `bash` می‌توانید این کار را انجام دهید:

```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```

بعد از آن، تست‌ها را فقط با این دستور اجرا کنید:

```bash
bats
```

## دیباگ در `jq`

`jq` یک فیلتر [`debug`][debug] کاربردی دارد.
هنگام توسعه‌ی راه‌حل‌های تمرینتان از آن استفاده کنید تا داده‌هایی را که در همان لحظه در پایپ‌لاین `jq` قرار دارند بررسی کنید.
برای جزئیات بیشتر، [مستند دیباگ][debugging] را ببینید.
