# معرفی مبانی شل

## شل

_شل_ برنامه‌ای است که به شما اجازه می‌دهد برای تعامل با سیستم‌عامل دستور وارد کنید.
شل‌ها می‌توانند گرافیکی باشند؛ محیط دسکتاپی که با ماوس یا تاچ‌پد از آن استفاده می‌کنید خودش یک شل است.
ما روی رابط‌های خط فرمان تمرکز می‌کنیم، جایی که شما دستورها را تایپ می‌کنید و نتیجه‌ها (معمولاً) در ترمینال شما چاپ می‌شوند.

شل‌های خط فرمان مختلفی وجود دارد.
ویندوز **cmd** و **powershell** را ارائه می‌دهد.
مک و لینوکس «شل‌های یونیکس» را ارائه می‌دهند که تعدادشان زیاد است.
شل پیش‌فرض مک **zsh** است.
**csh** یک شل قدیمی با نحوه‌ی نگارش شبیه به C است.
**bash** یکی از محبوب‌ترین شل‌هاست، به‌ویژه در لینوکس.

یکی از نخستین شل‌ها، شل Bourne است: **sh**.
با گذشت زمان، این شل [استاندارد][posix] شد تا روی هر سیستم شبه‌یونیکس ارائه شود.
بسیاری از شل‌ها بر پایه‌ی شل Bourne ساخته شده‌اند و اغلب قابلیت‌های تعاملی یا برنامه‌نویسی بیشتری ارائه می‌دهند.

**Bash** بر پایه‌ی شل Bourne است.
به همین دلیل به آن «**B**ourne-**a**gain **sh**ell» می‌گویند.
این شل پیش‌فرض بسیاری از سیستم‌های لینوکس است.
Bash امکانات زیادی فراهم می‌کند که آن را به شلی تعاملی و لذت‌بخش تبدیل می‌کند، از جمله:

* یک پرامپت کاملاً قابل سفارشی‌سازی،
* توانایی یادآوری و ویرایش دستورها از تاریخچه،
* توانایی دست‌کاری فرایندهای در حال اجرا،
* نام‌های مستعار که می‌توانند تایپ را کم کنند،
* و موارد دیگر.

این مسیر درباره‌ی نحوه‌ی استفاده از bash به‌عنوان یک شل تعاملی نیست، بلکه درباره‌ی یادگیری نوشتن برنامه با bash است.
تأکید بر استفاده از _فقط_ bash برای حل مسئله خواهد بود، هرچند محدودیتی در فراخوانی ابزارهای بیرونی وجود ندارد.

## مبانی Bash: دستورها و آرگومان‌ها

Bash دستورها را از ورودی خود می‌خواند (که معمولاً یا یک ترمینال است یا یک فایل).
هر خطی از ورودی که می‌خواند به‌عنوان یک _دستور_ در نظر گرفته می‌شود، یعنی دستوری که باید اجرا شود.
(چند مورد پیشرفته هم هست، مثل دستورهایی که چند خط را در بر می‌گیرند، که بعداً درباره‌شان صحبت می‌کنیم.)

Bash هر خط را به **کلمه‌هایی** تقسیم می‌کند که با یک کاراکتر فاصله (اسپیس و تب) از هم جدا می‌شوند.
اولین کلمه‌ی خط، اسم _دستوری_ است که باید اجرا شود.
بقیه‌ی کلمه‌ها به _آرگومان_های آن دستور تبدیل می‌شوند (گزینه‌ها، نام فایل‌ها و غیره).

~~~~exercism/note
در مثال‌های زیر، چند دستور تعاملی را نشان می‌دهیم که می‌توانید اجرا کنید.

* کاراکتر `#` یک _کامنت_ را آغاز می‌کند.
  هر کلمه‌ای که پس از آن بیاید توسط شل نادیده گرفته می‌شود؛ کامنت فقط برای خواندن است.
* کاراکتر `$` نشان‌دهنده‌ی پرامپت شل است. 
  اگر دستور را کپی می‌کنید، پرامپت را وارد نکنید.
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

`rm` برنامه‌ای است که فایل‌های داده‌شده به آن را حذف می‌کند.
`*` یک کاراکتر [glob][glob] است، الگویی «ویلدکارد» که با همه‌ی فایل‌های پوشه‌ی جاری مطابقت می‌کند.
بعداً بیشتر درباره‌ی globها صحبت می‌کنیم.

آیا توجه کردید که بین `a` و `b` چند فاصله هست و بین `b` و `c` فقط یکی؟
مقدار فاصله بین آرگومان‌ها اهمیتی ندارد!
برای مثال:

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

`echo` دستوری است که آرگومان‌هایش را در خروجی استاندارد چاپ می‌کند (که در مورد ما ترمینال است).
Bash دستور را به پنج کلمه تقسیم می‌کند و دستور `echo` را با چهار آرگومان فراخوانی می‌کند.
فاصله‌های اضافی در مثال دوم تفاوتی ایجاد نمی‌کنند.
`echo` نمی‌داند که در اصل چه فاصله‌هایی بین کلمه‌ها بوده است.

اگر بخواهیم فاصله‌های اضافی را نگه داریم، باید جمله را به‌عنوان یک آرگومان واحد بفرستیم.
می‌توانیم این کار را با استفاده از [گیومه][Quotes] انجام دهیم:

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

گیومه‌ها هر چیزی که داخلشان باشد را در یک _آرگومان واحد_ قرار می‌دهند.
آرگومان `This    is    a    test.` است، شامل همان کاراکترهای فاصله.
توجه کنید که گیومه‌ها بخشی از آرگومان نیستند؛ bash آن‌ها را حذف می‌کند و سپس آن آرگومان واحد را به `echo` می‌دهد.

آرگومان‌ها با فاصله از اسم دستور و از یکدیگر جدا می‌شوند.
به خاطر سپردن این نکته مهم است.
برای مثال، دستور زیر نادرست است:

```bash
$ [-f file]
bash: [-f: command not found
```

این دستور برای بررسی وجود فایلی به اسم `file` در نظر گرفته شده است.
معقول است که فرض کنیم فاصله‌های اطراف `[` و `]` اهمیتی ندارند، اما `[` در واقع یک دستور است و آخرین آرگومانش باید `]` باشد.
(بعداً دستور `[` را با جزئیات بیشتری بررسی می‌کنیم.) 
بنابراین باید `[` را از `-f` و `]` را از `file` جدا کنیم.
در غیر این صورت bash فکر می‌کند می‌خواهیم دستوری به اسم `[-f` را با یک آرگومان `file]` اجرا کنیم.
دستور درست همه‌ی آرگومان‌ها را با فاصله جدا می‌کند:

```bash
$ [ -f file ]
```

(افراد زیادی را می‌بینیم که این رفتار گیجشان می‌کند؛ فکر می‌کنند `[...]` فقط «نحوه‌ی نگارش» است و می‌توانند فاصله‌ها را حذف کنند؛ اما `[` یک دستور است و فاصله لازم است.)

اگر اسم فایل ما فاصله یا کاراکترهای خاص دیگری داشته باشد، باید در گیومه هم قرار بگیرد:

```bash
$ [ -f "my file" ]
```

## انواع دستورها

Bash چند نوع مختلف دستور را می‌شناسد: نام‌های مستعار، توابع، دستورهای توکار، کلیدواژه‌ها و فایل‌های اجرایی.
همه‌ی این‌ها _دستور_ هستند و همه به شکلی بسیار مشابه عمل می‌کنند.

به‌طور پیش‌فرض نام‌های مستعار فقط در شل‌های تعاملی فعال هستند، نه در اسکریپت‌های شل.
اینجا به آن‌ها نمی‌پردازیم.

### توابع

یک تابع شامل دستورهای شل است و بسیار شبیه یک اسکریپت کوچک عمل می‌کند؛ حتی می‌تواند آرگومان بگیرد و متغیرهای محلی بسازد.
وقتی تابعی فراخوانی می‌شود، دستورهای داخل آن اجرا می‌شوند.
توابع بعداً به‌طور عمیق بررسی می‌شوند.

### دستورهای توکار

Bash چند دستور پایه دارد که در خودش تعبیه شده‌اند، مثل: `cd` (تغییر پوشه)، `echo` (نوشتن خروجی) و غیره.
می‌توان آن‌ها را توابعی در نظر گرفت که از پیش فراهم شده‌اند.

### کلیدواژه‌ها

کلیدواژه‌ها شبیه دستورهای توکار هستند، با این تفاوت اصلی که کلیدواژه‌ها در واقع نحوه‌ی نگارش bash هستند و ممکن است با قواعد خاصی تجزیه شوند.
برای مثال، `[` یک دستور توکار bash است، در حالی که `[[` یک کلیدواژه‌ی bash است؛ هر دو برای آزمودن انواع شرط‌ها استفاده می‌شوند.
اما کلیدواژه‌ی `[[` قابلیت‌های اضافی دارد.
برای مثال، عملگر `=~` را فراهم می‌کند که آزمون عبارت باقاعده انجام می‌دهد.

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

عملگرهای مقایسه‌ی رشته `<` و `>` مثال دیگری از این هستند که کلیدواژه‌ها کد را متفاوت تجزیه می‌کنند.
درون `[[...]]`، این عملگرها به هیچ مراقبت خاصی نیاز ندارند.

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

اما درون `[...]` باید آن‌ها را در گیومه بگذارید یا escape کنید تا شل آن‌ها را به‌عنوان عملگرهای تغییر مسیر تجزیه نکند.

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### فایل‌های اجرایی

آخرین نوع دستوری که bash می‌تواند اجرا کند یک _فایل اجرایی_ است.
این‌ها فایل‌های اجرایی (برنامه‌هایی) روی سیستم فایل رایانه‌ی شما هستند که می‌توانید اجرا کنید.
(به فایل‌های اجرایی ممکن است _دستورهای بیرونی_ یا _برنامه‌ها_ هم گفته شود.)
معمولاً فایل‌های اجرایی فقط با تایپ اسمشان فراخوانی می‌شوند؛ معمولاً به مسیر کامل فایل نیازی نیست.
این کار ممکن است چون bash از یک متغیر از پیش تعریف‌شده استفاده می‌کند که به آن کمک می‌کند مکان فایل‌های اجرایی رایج را پیدا کند.
اسم این متغیر `PATH` است.
این مجموعه‌ای از نام پوشه‌هاست که با دونقطه از هم جدا شده‌اند (مثلاً `/usr/bin:/bin`). 
وقتی دستوری (مثلاً `myprogram` یا `ls`) بدون مسیر فایل مشخص می‌شود (و نام مستعار، تابع، دستور توکار یا کلیدواژه نباشد)، bash پوشه‌های `PATH` را جست‌وجو می‌کند.
پوشه‌ها به ترتیب، از چپ به راست، جست‌وجو می‌شوند تا ببینند آیا فایل اجرایی با اسم داده‌شده در آن‌ها هست یا نه.

اگر فایل اجرایی خارج از مسیر شناخته‌شده باشد، باید مسیر فایل آن مشخص شود.
برای فایل اجرایی `myprogram` در پوشه‌ی جاری، از `./myprogram` استفاده کنید؛ اگر در پوشه‌ی `/opt/somedirectory` باشد، از `/opt/somedirectory/myprogram` استفاده کنید.

نکته: می‌توان از دستور `type` برای گرفتن جزئیات درباره‌ی دستور استفاده کرد:

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## اسکریپت‌ها

یک _اسکریپت_ دنباله‌ای از دستورهاست که در یک فایل ذخیره شده است.
Bash فایل را می‌خواند و دستورها را به ترتیب پردازش می‌کند.
فقط وقتی دستور جاری پایان یابد به دستور بعدی می‌رود.
استثنا این است که دستوری برای اجرای ناهمگام (در پس‌زمینه) مشخص شده باشد.
هنوز خیلی نگران این مورد نباشید؛ بعداً یاد می‌گیریم که چطور کار می‌کند.

هر مثال خط فرمانی در این راهنما را می‌توان در یک اسکریپت هم استفاده کرد.

ساختن اسکریپت آسان است.
با ساختن یک فایل جدید شروع کنید و این را در خط اول بگذارید:

```bash
#!/bin/bash
```

این خط یک _دستورالعمل مفسر_ نامیده می‌شود (به آن _هش‌بنگ_ یا **_شبنگ_** هم می‌گویند).
این خط مشخص می‌کند که وقتی فایل به‌عنوان فایل اجرایی در یک دستور استفاده می‌شود، `/bin/bash` به‌عنوان مفسر به کار رود.
وقتی هسته‌ی سیستم‌عامل یک _فایل غیر دودویی_ را اجرا می‌کند، خط اول فایل را می‌خواند.
اگر خط با `#!` شروع شود، هسته از آن خط برای تعیین مفسری استفاده می‌کند که فایل به آن سپرده شود.
(راه‌های معتبر دیگری هم برای این کار هست، پایین را ببینید.)
`#!` باید در ابتدای ابتدای فایل باشد، بدون هیچ فاصله یا خط خالی پیش از آن.
دستورهای اسکریپت ما در خط‌های جداگانه‌ای زیر این خط می‌آیند.

نکته: به‌جای `#!/bin/bash` می‌توانید از این استفاده کنید:

```bash
#!/usr/bin/env bash
```

`env` در `$PATH` به دنبال فایل اجرایی‌ای می‌گردد که اولین آرگومانش نامش را داده است (در این مورد، «bash»).
برای توضیح مفصل‌تر این تکنیک و اینکه چطور با `#!/bin/bash` ساده فرق دارد، [این پرسش در StackOverflow][env bash] را ببینید.

لطفاً فریب اسکریپت‌ها یا مثال‌های اینترنتی را نخورید که از `/bin/sh` به‌عنوان مفسر استفاده می‌کنند.
**`sh` همان `bash` نیست!**
خود bash یک شل «سازگار با sh» است، یعنی می‌تواند بیشتر اسکریپت‌های `sh` را اجرا کند و بخش زیادی از نحوه‌ی نگارش یکسان را دارد.
اما عکس آن درست نیست؛ بعضی ویژگی‌های bash در `sh` می‌شکنند یا رفتار غیرمنتظره ایجاد می‌کنند.
در واقع، `sh` یک شل واحد نیست.
پیاده‌سازی‌های زیادی از شل وجود دارد که نحوه‌ی نگارش POSIX-sh را پشتیبانی می‌کنند.
بسته به سیستم‌عامل شما، وقتی `sh` را اجرا می‌کنید ممکن است در واقع bash، ash، dash یا شل دیگری را اجرا کنید.

وقتی فایل اسکریپت ساخته شد، می‌توان آن را این‌طور اجرا کرد:

```bash
$ bash myscript
```

در این مثال، _دستور_ `bash` را اجرا می‌کنیم و به آن می‌گوییم اسکریپتی را که به‌عنوان _آرگومان_ دادیم بخواند.
وقتی این‌طور انجامش می‌دهیم، خط `#!` فقط یک _کامنت_ است.

از طرف دیگر، می‌توانیم به اسکریپت‌هایمان مجوز اجرا بدهیم.
با این روش می‌توانیم اسکریپت را مثل هر فایل اجرایی دیگری اجرا کنیم، به‌جای آنکه دستی bash را فراخوانی کنیم:

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

وقتی دستور را این‌طور اجرا می‌کنیم، سیستم‌عامل از خط `#!` برای تعیین این استفاده می‌کند که کدام مفسر برای اجرای اسکریپت شما به کار رود.
