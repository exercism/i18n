# درباره

منابعی که وضعیت سیستم‌عامل را نگه می‌دارند (دستگیره‌های فایل، سوکت‌ها، قفل‌ها) به پاک‌سازی *تضمین‌شده* نیاز دارند، حتی وقتی یک استثنا باعث باز شدن پشته می‌شود. واژگان [`destructors`][destructors] در Factor چارچوب کوچکی برای این کار فراهم می‌کند و بیشتر منابع داخلی (`<file-reader>`، `<file-writer>`، سوکت‌ها، …) از قبل به آن متصل‌اند.

## کلاس و جنریک

یک کلاس با ارث‌بری از `disposable` و پیاده‌سازی `dispose*` به آن می‌پیوندد:

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )` تاپل را تخصیص می‌دهد *و* آن را در دامنه‌ی نابودگر جاری ثبت می‌کند، بنابراین یک استثنا بین تخصیص و نقطه‌ی ایمن بعدی نمی‌تواند منبع را نشت دهد. این چارچوب تضمین می‌کند که `dispose*` برای هر شیء **حداکثر یک بار** اجرا شود؛ فراخوانی‌های مکرر `dispose` بی‌اثرند.

## فراخوان‌کنندگان عمومی از `dispose` استفاده می‌کنند

| کلمه              | اثر                                        |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )`، آزادسازی؛ فراخوانی دوباره امن است    |
| `with-disposal`   | `( disposable quot -- )`، دامنه‌دار کردن یک منبع |
| `with-destructors`| `( quot -- )`، باز کردن یک دامنه‌ی ثبت         |
| `&dispose`        | `( obj -- obj )`، آزادسازی هنگام خروج عادی *یا* شکست |
| `|dispose`        | `( obj -- obj )`، آزادسازی فقط هنگام خروج غیرعادی از دامنه |

`with-disposal` شکل تک‌منبعی است. برای بیش از یک منبع، یک دامنه‌ی `with-destructors` باز کنید و هر تخصیص را با `&dispose` (همیشه می‌خواهید آزادش کنید) یا `|dispose` (فقط در صورت شکست آزاد کنید؛ مسیر موفقیت آن را نگه می‌دارد) ثبت کنید.

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup` عنصر پایه است

برای یک try/finally یک‌باره بدون ثبت، [`cleanup`][cleanup] (از `continuations`) کلمه‌ی سطح‌پایین‌تری است:

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors` به‌طور قطع قدرتمندتر است (ثبت می‌تواند در زمان اجرا رشد کند)، اما `cleanup` انتخاب طبیعی است وقتی جفت‌شدن تخصیص/آزادسازی ثابت و محلی باشد.

[destructors]: https://docs.factorcode.org/content/vocab-destructors.html
[cleanup]: https://docs.factorcode.org/content/word-cleanup%2Ccontinuations.html
