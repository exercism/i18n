# مقدمه

یک *«دِک»* (صف دوطرفه) از عملیات push و pop در هر دو سر، در زمان O(1) پشتیبانی می‌کند. پیاده‌سازی استاندارد Factor، `<dlist>` (یک فهرست پیوندی دوطرفه) در [`dlists`][dlists] است؛ عملیات آن در [`deques`][deques] قرار دارند.

## API دِک

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

`clear-deque` دِک را در جای خودش خالی می‌کند، که برای استفاده‌ی دوباره بدون تخصیص دوباره‌ی حافظه مفید است.

اگر در یک سر push و pop کنید، یک پشته‌ی LIFO به دست می‌آید. اگر در یک سر push و در سر دیگر pop کنید، یک صف FIFO به دست می‌آید:

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

برای LIFO سراغ یک بردار (`V{ }`) با `push`/`pop` می‌روید، که سربار هر عملیاتش کمتر است. وقتی در *هر دو* سر به O(1) نیاز دارید، سراغ `<dlist>` بروید؛ تقریباً همیشه برای یک صف FIFO همین لازم است.

## جست‌وجوی سطحی

همین کاربرد FIFO است که دِک‌ها را به مرز مناسب برای *جست‌وجوی سطحی* تبدیل می‌کند. با یک گره‌ی واحد شروع می‌کنید، همسایه‌ها را به انتها push می‌کنید و نامزدها را از ابتدا pop می‌کنید، و تکراری‌ها را با یک مجموعه‌ی هش حذف می‌کنید:

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

نامزدهای قدیمی‌تر پیش از نامزدهای جدیدتر بررسی می‌شوند؛ بنابراین جست‌وجو از همان ابتدا لایه‌به‌لایه به بیرون گسترش می‌یابد. همین ویژگی است که خاصیت کوتاه‌ترین مسیر را به جست‌وجوی سطحی می‌دهد: نخستین باری که به یک گره‌ی هدف می‌رسید، از مسیری با کمترین تعداد گام گذشته‌اید.

## `MEMO:`، ذخیره‌سازی خودکار

گاهی جست‌وجویی که جست‌وجوی سطحی برای هر گره انجام می‌دهد، پرهزینه است. ووکب [`memoize`][memoize] در Factor به شما `MEMO:` را می‌دهد؛ جانشینی مستقیم برای `:` که نتیجه‌ی واژه را بر پایه‌ی ورودی‌هایش ذخیره می‌کند:

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

یک واژه‌ی `MEMO:` نخستین باری که هر ورودی دیده شود بدنه‌اش را اجرا می‌کند و از آن پس نتیجه‌ی ذخیره‌شده را برمی‌گرداند؛ همان رابط، بدون فراخوانی اضافی در محل فراخوانی، فقط در تکرارها سریع‌تر.
