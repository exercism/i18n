# درباره

وقت آن رسیده که به یکی از پارادایم‌های اصلی C++ بپردازیم: برنامه‌نویسی شیءگرا، یا همان OOP.
OOP حول محور `classes` می‌چرخد؛ یعنی نوع‌های داده‌ای که خودتان تعریف می‌کنید و مجموعه‌ای از توابع مرتبط به خودشان دارند.
از مبانی شروع می‌کنیم و در ادامه‌ی برنامه‌ی درسی به موضوع‌های پیشرفته‌تر می‌رسیم.

## اعضا

کلاس می‌تواند **متغیرهای عضو** و **توابع عضو** داشته باشد.
به آن‌ها با عملگر **انتخاب عضو** `.` دسترسی پیدا می‌کنید.
همان‌طور که برای متغیرهای بیرون از `classes` توصیه می‌شود، بهتر است متغیرهای عضو را هم هنگام اعلام با یک مقدار مقداردهی اولیه کنید.
این مقدار، مقدار پیش‌فرض شیءهای تازه‌ساخته‌شده از این کلاس می‌شود.

## کپسوله‌سازی و پنهان‌سازی اطلاعات

کلاس این امکان را می‌دهد که دسترسی به اعضایش را محدود کنید.
دو حالت اصلی `private` و `public` هستند.
اعضای `private` از بیرون کلاس قابل دسترسی نیستند.
اعضای `public` را می‌توان آزادانه فراخوانی کرد.
همه‌ی اعضا به‌طور پیش‌فرض `private` هستند و باید صریحاً علامت‌گذاری شوند تا از بیرون کلاس قابل استفاده باشند.

## یک مثال ساده

تعریف یک `class` تازه را در مثال زیر می‌بینید.
به `;` بعد از تعریف دقت کنید.

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

از داخل کلاس به همه‌ی متغیرها دسترسی دارید.
نگاهی به `damage` درون تابع `cast_spell` بیندازید.
اعضای `private` را از بیرون کلاس نمی‌توانید بخوانید یا تغییر دهید:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## سازنده‌ها

سازنده‌ها این امکان را می‌دهند که هنگام ساختن یک شیء، به متغیرهای عضو مقدار بدهید.
اسم آن‌ها همان اسم `class` است و نوع بازگشتی ندارند.
یک کلاس می‌تواند چندین سازنده داشته باشد.
این وقتی به کار می‌آید که همیشه نیازی به تعیین همه‌ی متغیرها نداشته باشید.

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

سازنده‌ها موضوعی بزرگ‌اند و ظرافت‌های زیادی دارند.
اگر برای `class` خود صریحاً یک `constructor` تعریف نکنید، آن‌وقت (و فقط آن‌وقت) کامپایلر این کار را برایتان انجام می‌دهد.
همین اتفاق در مثال اول بالا افتاده است.
شیء _silverhand_ با فراخوانی سازنده‌ی پیش‌فرض ساخته شده است و هیچ آرگومانی به آن پاس داده نشده.
همه‌ی متغیرها روی مقداری تنظیم می‌شوند که در تعریف کلاس ذکر شده است.
اگر در آن تعریف هیچ مقداری نداده بودید، ممکن بود متغیرها مقداردهی اولیه نشده باقی بمانند و این می‌توانست پیامدهای ناخواسته‌ای داشته باشد.

## ساختارها

ساختارها از ریشه‌های اولیه‌ی زبان C می‌آیند و به قدمت خود C++ هستند.
آن‌ها عملاً همان `classes` هستند، با یک استثنای مهم.
به‌طور پیش‌فرض، همه‌چیز درون یک `class` برابر `private` است.
اما ساختارها تا وقتی خلافش تعریف نشود، `public` هستند.
طبق قرارداد، از کلیدواژه‌ی `struct` بیشتر برای **ساختارهای صرفاً داده** استفاده می‌شود.
کلیدواژه‌ی `class` برای شیءهایی ترجیح داده می‌شود که باید ویژگی‌های خاصی را تضمین کنند.
یک «ناوردا» می‌تواند این باشد که `damage` در `class` شما به اسم `Wizzard` هرگز منفی نشود.
متغیر `damage` از نوع `private` است و هر تابعی که `damage` را تغییر دهد، تضمین می‌کند که این ناوردا حفظ شود.
