# دستورالعمل

شما روی سیستمی کار می‌کنید که فرایند ورود به شبکه‌ی سازمان شما را ساده می‌کند. این کارها به بخش احراز هویت مربوط می‌شوند. این سیستم برای اثبات هویت از «تشخیص چهره» استفاده می‌کند.

در همه‌ی موارد تضمین شده است که پارامتر رنگ چشم `null` نیست.

## 1. مطمئن شوید که ویژگی‌های چهره با هم مطابقت دارند

متد `Authenticator.AreSameFace()` را پیاده‌سازی کنید تا بررسی کند که آیا دو چهره با هم مطابقت دارند یا نه.

روال‌های برابری را برای کلاس `FacialFeatures` اضافه کنید.

```csharp
Authenticator.AreSameFace(new FacialFeatures("green", 0.9m), new FacialFeatures("green", 0.9m);
// => true
Authenticator.AreSameFace(new FacialFeatures("blue", 0.9m), new FacialFeatures("green", 0.9m);
// => false
```

## 2. مدیر سیستم را احراز هویت کنید

با وجود اعتراض‌های شما، مدیر سیستم اصرار دارد که در طول آزمون پذیرش یک هویت درون‌ساخته داشته باشد تا همیشه بتوان او را احراز هویت کرد.

ایمیل مدیر admin@exerc.ism است. چشمان او سبز است و پهنای شیار زیر بینی‌اش ۰٫۹ است.

روال‌های برابری را برای کلاس `Identity` اضافه کنید.

متد `Authenticator.IsAdmin()` را پیاده‌سازی کنید تا بررسی کند که هویت داده‌شده با هویت مدیر مطابقت دارد.

```csharp
var authenticator = new Authenticator();
authenticator.IsAdmin(new Identity("admin@exerc.ism", new FacialFeatures("green", 0.9m)));
// => true
authenticator.IsAdmin(new Identity("admin@thecompetition.com", new FacialFeatures("green", 0.9m)));
// => false
```

## 3. ثبت هویت‌های جدید

متد `Authenticator.Register()` را پیاده‌سازی کنید که یک هویت را روی خودش ذخیره می‌کند، به‌گونه‌ای که فراخوانی‌های `IsRegistered()` برای این هویت `true` برگردانند و در غیر این صورت `IsRegistered()` مقدار `false` را برمی‌گرداند.

برای تشخیص تلاش‌های تکراری برای ثبت یک هویت، اگر هویت پیش‌تر ثبت شده باشد، `Authenticator.Register()` مقدار `false` را برمی‌گرداند و در غیر این صورت مقدار `true` را برمی‌گرداند.

```csharp
var authenticator = new Authenticator();
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.IsRegistered(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => false
```

## 4. نگذارید هویت‌های نامعتبر احراز هویت شوند

متد `Authenticator.IsRegistered()` را پیاده‌سازی کنید و مطمئن شوید که وقتی هیچ هویتی ثبت نشده است، «غلط» برمی‌گرداند.

```csharp
var authenticator = new Authenticator();
authenticator.IsRegistered(new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.8m)));
// => false
```

## 5. افزودن ابزار تشخیص برای شناسایی تلاش‌های متعدد احراز هویت

باگی گزارش شده است که در آن متد `Authenticator.IsRegistered()` چندین بار پشت سر هم برای یک هویت یکسان فراخوانی می‌شود. شما فکر می‌کنید نوعی مشکل «bounce» وجود دارد که در آن دقیقاً همان رکورد چندین بار ارسال می‌شود. وظیفه‌ی شما این است که یک روال تشخیصی `Authenticator.AreSameObject()` اضافه کنید تا از هر آزمونی که انجام می‌شود پشتیبانی کند. این روال دو شیء را با هم مقایسه می‌کند و اگر دقیقاً همان نمونه باشند `true` را برمی‌گرداند و در غیر این صورت `false` را برمی‌گرداند.

```csharp
var identityA = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityB = identityA;
Authenticator.AreSameObject(identityA, identityB);
// => true

var identityC = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityD = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
Authenticator.AreSameObject(identityC, identityD);
// => false
```
