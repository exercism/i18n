# معرفی here document

در اسکریپت‌نویسی Bash، یک «here document» (یا «heredoc») چندین خط ورودی را به یک دستور یا برنامه تغییر مسیر می‌دهد، انگار که آن‌ها را مستقیم در ترمینال تایپ می‌کنید.
این ابزار قدرتمندی برای جاسازی متن چندخطی درون اسکریپت‌هایتان است، بدون نیاز به فایل‌های خارجی یا دستکاری پیچیده‌ی رشته‌ها.

## ویژگی‌های کلیدی و نحوه‌ی نگارش

1. جداکننده: یک heredoc با عملگر `<<` شروع می‌شود و پس از آن یک واژه‌ی جداکننده می‌آید (که اغلب «نشانگر» یا «پایان‌دهنده» نامیده می‌شود).
   این جداکننده می‌تواند هر واژه‌ای باشد که انتخاب می‌کنید، اما معمولاً برای وضوح از چیزهایی مانند `EOF`، `END` یا `TEXT` استفاده می‌شود.
   برای کد خواناتر، می‌توانید از یک واژه‌ی توصیفی به‌عنوان جداکننده استفاده کنید، مثلاً `END_INSTALLATION_INSTRUCTIONS`.

1. محتوا: پس از `<< DELIMITER` اولیه، محتوایی را می‌نویسید که می‌خواهید تغییر مسیر دهید.
   این می‌تواند چندین خط متن، کد یا هر چیز دیگری باشد.

1. پایان: heredoc زمانی تمام می‌شود که واژه‌ی جداکننده دوباره در خطی جداگانه ظاهر شود، بدون فاصله‌ی ابتدایی یا انتهایی.

## نحوه‌ی نگارش پایه

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## چگونه کار می‌کند

* Bash همه‌ی خطوط بین `<< DELIMITER` شروع و `DELIMITER` پایانی را می‌خواند.
* Bash این محتوا را به ورودی استاندارد دستور متصل می‌کند.
* دستور این ورودی را پردازش می‌کند، انگار که از صفحه‌کلید آمده است.

### مثال ۱: خروجی متن ساده

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

خروجی:

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

در این مثال:

* `cat` دستور است.
* `<< EOF` heredoc را با `EOF` به‌عنوان جداکننده شروع می‌کند.
* سه خط متن محتوا هستند.
* `EOF` در خط خودش heredoc را پایان می‌دهد.
* سپس `cat` محتوایی را که دریافت کرده خروجی می‌دهد.

### مثال ۲: استفاده با wc (شمارش کلمات)

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

خروجی:

```plaintext
3
```

اینجا، `wc -l` تعداد خطوط را می‌شمارد.
heredoc سه خط را به‌عنوان ورودی فراهم می‌کند.

### مثال ۳: انتقال داده به یک اسکریپت

اسکریپت:

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

اسکریپت را از یک اعلان تعاملی bash با یک heredoc فراخوانی کنید:

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

خروجی:

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## گونه‌ها و ویژگی‌های پیشرفته

### محتوای تحت‌اللفظی

Bash درون یک heredoc بسط متغیر، جایگزینی دستور و بسط حسابی را انجام می‌دهد.
از این نظر، heredocها مانند رشته‌های داخل گیومه‌ی دوگانه عمل می‌کنند.

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

خروجی:

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

وقتی جداکننده در گیومه باشد (با استفاده از گیومه‌ی تک یا دوگانه)، این بسط‌ها جلوگیری می‌شوند.
محتوا تحت‌اللفظی گرفته می‌شود.
این مانند رشته‌های داخل گیومه‌ی تک است.

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

خروجی:

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### حذف تب‌های ابتدای خط

اگر از `<<-` (با یک خط تیره در انتها) به‌جای `<<` استفاده کنید، Bash هر _نویسه‌ی تب_ ابتدای هر خط از heredoc را حذف می‌کند.
این برای تورفتگی محتوای heredoc درون اسکریپتتان بدون تأثیر بر خروجی مفید است.

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

خروجی با حذف همه‌ی تب‌های ابتدایی چاپ می‌شود:

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
نویسنده این استفاده را توصیه نمی‌کند.
گرچه می‌تواند خوانایی اسکریپت را بهبود دهد،

1. جایگزینی تصادفی نویسه‌های تب با فاصله آسان است (ممکن است ویرایشگرتان این کار را خودکار انجام دهد) و
1. تشخیص تفاوت بین فاصله و تب دشوار است.
~~~~

## چه زمانی از here document استفاده کنیم

* ورودی چندخطی: وقتی باید چندین خط متن را به یک دستور بدهید.
* فایل‌های پیکربندی: جاسازی قطعه‌های کوچک پیکربندی درون یک اسکریپت.
* تولید کد: ساختن کد به‌صورت پویا درون یک اسکریپت.
* تعاملات اسکریپتی: شبیه‌سازی ورودی کاربر برای برنامه‌های تعاملی.
* پرهیز از فایل‌های خارجی: وقتی می‌خواهید از ساختن فایل‌های موقت دوری کنید.

یک کاربرد معمول می‌تواند فراهم کردن متنی راهنما باشد:

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## معایب احتمالی

* اسناد جاسازی‌شده‌ی بزرگ می‌توانند خواندن کدتان را دشوارتر کنند.
  بهتر است اسکریپتتان را همراه با مستندات در فایل‌های جداگانه منتشر کنید.
* here documentها می‌توانند جریان کد را مختل کنند.
  ممکن است در بخشی عمیقاً تودرتو از کد باشید که می‌خواهید متنی را به برنامه‌ای بدهید.
  تورفتگی heredoc در مقایسه با کد اطراف می‌تواند ناهنجار به نظر برسد.

## here string

مانند here documentها، _here stringها_ (یا «herestringها») ورودی را به یک دستور می‌دهند.
اما در حالی که heredocها به‌صورت یک بلوک متن داده می‌شوند، herestringها به‌صورت یک رشته‌ی متنی واحد داده می‌شوند.
here stringها از نحوه‌ی نگارش `<<< "text"` استفاده می‌کنند.

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

خروجی:

```plaintext
UPPER CASE THIS STRING
```

برخلاف heredocها، به جداکننده‌ی پایانی نیازی نیست.

### چرا از here string استفاده کنیم؟

می‌توان به‌جای یک here string از یک خط لوله استفاده کرد:

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

حالا چرا از here string استفاده کنیم؟

حالتی را در نظر بگیرید که رشته را به‌عنوان خروجی از یک محاسبه‌ی طولانی می‌گیرید و می‌خواهید نتیجه را به دو دستور جداگانه بدهید.
با استفاده از خط لوله، باید محاسبه را دو بار اجرا کنید:

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

رویکرد کارآمدتر این است که خروجی محاسبه را ثبت کنید (با استفاده از جایگزینی دستور) و از here stringها برای دادن ورودی به دو دستور بعدی استفاده کنید:

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

یک کاربرد واقعی از آن مثال:

* پاسخ JSON به یک پرس‌وجوی REST API را ثبت کنید (که صفحه‌بندی شده است)،
* داده‌ی JSON را به یک برنامه‌ی jq بدهید تا نتایج را تجزیه کند و آن را در یک فایل خروجی دهد و سپس
* داده‌ی JSON را به برنامه‌ی jq دیگری بدهید تا URL پرس‌وجوی بعدی را مشخص کند.

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

به موقعیت تغییر مسیر خروجی توجه کنید.
همه‌ی خروجی حلقه‌ی while به فایل `data.csv` افزوده می‌شود.

## here document و here string به‌عنوان تغییر مسیر

چون این‌ها فقط شکل‌هایی از تغییر مسیر هستند، می‌توانند با سایر عملیات تغییر مسیر ترکیب شوند:

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## جمع‌بندی

here documentها (یا «heredocها») روشی انعطاف‌پذیر و راحت برای مدیریت ورودی چندخطی در اسکریپت‌های Bash هستند.
آن‌ها فرایند جاسازی متن و داده را مستقیماً درون اسکریپت‌هایتان ساده می‌کنند و آن‌ها را خودکفا‌تر و خواناتر می‌سازند.

here stringها (یا «herestringها») مانند here documentها هستند، اما نحوه‌ی نگارش ساده‌تر و پویاتری ارائه می‌دهند.
