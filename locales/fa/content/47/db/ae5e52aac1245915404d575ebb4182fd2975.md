# پیوست دستورالعمل‌ها

## دستورالعمل‌های ویژه‌ی این مسیر

بر اساس [این اصطلاح‌شناسی][terminology]، باید برنامه‌ای «موازی» و «قطعی» بنویسید و (حتماً هم این کار را بکنید!) بگذارید Scala به جنبه‌ی «همروندی» رسیدگی کند.
وگرنه ممکن است code شما به‌سرعت به‌هم‌ریخته و مستعد خطا شود، با انواع و اقسام bugهای بدِ همروندی.
به‌ویژه اینکه برنامه‌تان ممکن است غیرقطعی شود، که در عمل یعنی: debug کردن، test کردن و استدلال درباره‌ی آن بسیار (در واقع، بسیار بسیار) دشوار می‌شود.

با این همه، شاید ایده‌ی خوبی باشد که اول یک راه‌حل متوالی بنویسید (و با test suite درستی‌اش را بررسی کنید).
فقط پس از آن است که باید تلاش کنید آن را موازی کنید، در حالی که بخش‌های متوالی و موازی code شما را تا حد امکان جدا از هم نگه می‌دارید.

نخستین دور می‌تواند استفاده از [مجموعه‌های موازی][parallel collections] Scala باشد.
ممکن است ببینید که این تقریباً بیش از حد ساده است (به‌ویژه اگر توصیه‌ی ما را گوش کرده باشید و از قبل یک راه‌حل متوالی داشته باشید).

برای دور دوم توصیه می‌کنیم راه‌حلی با [`scala.concurrent.Future`][Future] را امتحان کنید.
برای گرفتن کمی کمک می‌توانید به [این آموزش][tutorial] و [ادامه‌ی آن][sequel] سر بزنید.
مطمئن شوید که:

- فقط یک فراخوانی مسدودکننده‌ی واحد برای انتظار نتیجه داشته باشید
- آن درست در انتهای برنامه‌تان باشد
- و مهلت زمانی داشته باشد.

`scala.concurrent.Future` در کتابخانه‌های زیادی به کار می‌رود و توصیه‌ی پزشک برای برنامه‌نویسی موازی و ناهمگام در Scala است.
پس برای تسلط بر زبان ضروری است و باید بخشی از زرادخانه‌ی Scala شما شود.
