# مقدمه

توابع پیشتر در مفهوم [مبانی][concept-basics] معرفی شدند، با مثال‌هایی مانند این:

```R
squareit <- function(x) {
    x * x
}

squareit(3)
#> [1] 9

# shorter form
squareit_short <- function(x) x ^ 2
```

اگر دقیق‌تر به تعریف `squareit` نگاه کنیم، می‌توانیم بخش‌های مختلفی را تشخیص دهیم:

- این تابع یک آرگومان صوری به اسم `x` می‌گیرد.
- یک بدنه‌ی تابع وجود دارد که معمولاً داخل آکولاد `{ }` نوشته می‌شود.
- وقتی شیء تابع ساخته شد، به یک متغیر به اسم `squareit` نسبت داده می‌شود.

تابع در R یک شیء درجه‌یک است، تقریباً مانند اعداد و رشته‌ها.
بنابراین `squareit <- function...` یک انتساب است که از نظر نحوه‌ی نگارش دقیقاً مانند `x <- 42` است.

## آرگومان‌ها

R بین آرگومان‌های مکانی و آرگومان‌های کلیدواژه‌ای تفاوت روشنی قائل نمی‌شود، برخلاف دیگر زبان‌های اسکریپتی مانند Python و Julia.

فراخوانی توابع می‌تواند مقادیر را به‌صورت مکانی یا با اسم منتقل کند.
حالت دوم برای توابع پیچیده با آرگومان‌های زیاد مفید است، جایی که به خاطر سپردن ترتیب آن‌ها دشوار است.

```R
f <- function(x, y) x / y

# call positionally
f(4, 2)
#> [1] 2

# call by name
f(y = 2, x = 4)
#> [1] 2
```

### آرگومان‌های اختیاری

مقادیر پیش‌فرض آرگومان‌ها را می‌توان در تعریف تابع مشخص کرد، اما باید بعد از همه‌ی آرگومان‌های بدون پیش‌فرض بیایند.

سپس می‌توانیم انتخاب کنیم که پیش‌فرض را بپذیریم یا آن را بازنویسی کنیم.

```R
g <- function(x, y = 2) x / y

# default y value
g(6)
#> [1] 3

# explicit y value
g(6, 3)
#> [1] 2
```

### آرگومان‌های اضافی

برای پذیرفتن تعداد دلخواهی از آرگومان‌های اضافی، از `...` (سه‌نقطه) در تعریف استفاده کنید.
می‌توان هر مقدار اضافی در فراخوانی تابع را به یک بردار تبدیل کرد، اما لطفاً برای روشی جایگزین برای استفاده از این «آرگومان‌های نقطه‌ای» *که در چند زبان دیگر «varargs» نامیده می‌شوند* ادامه‌ی مطلب را بخوانید.

```R
var_f <- function(x, y, ...) {
  print(c(...))
}

var_f(2, 3, "opt1", "opt2")
#> [1] "opt1" "opt2"
```

## محیط تابع

پیش‌تر گفتیم که آرگومان‌های صوری و بدنه هر دو اجزای یک تابع هستند.

در واقع، جزء سومی هم وجود دارد: *محیطی* که تابع در آن تعریف می‌شود.

این را می‌توان با حالت توابع تودرتو نشان داد:

```R
outer_func <- function(x) {
  inner_func <- function(y) {
    x * y
  }
  
  inner_func(3)
}

outer_func(5)
#> [1] 15
```

فراخوانی تابع مقدار `x = 5` را به تابع بیرونی می‌فرستد و این مقدار در بدنه‌ی آن تابع در دسترس است.

تابع درونی *بخشی* از بدنه‌ی تابع بیرونی است و به مقدار `x` دسترسی دارد.
به بیان دیگر، `x = 5` در *محیط* تابع درونی قرار دارد.

از نظر فنی، به این «بستار» می‌گویند و همین است که در [ویکی‌پدیا][wiki-closure] هم توضیح داده شده است.

محیط به‌ویژه در مورد آرگومان‌های نقطه‌ای مهم است، چون هر مقداری که از این راه داده شود می‌تواند به فراخوانی‌های تابع در بدنه‌ی تابع منتقل شود.
تابع بیرونی نیازی ندارد بداند یا اهمیت دهد که آرگومان‌های نقطه‌ای چه معنایی دارند.

```R
f_var <- function(x, ...) {
  sum(x, ...)
}

x <- c(1, 2, NA, 6)

# for sum(), na.rm defaults to FALSE
f_var(x)
#> [1] NA

# pass through the na.rm value
f_var(x, na.rm = TRUE)
#> [1] 9
```

این تکنیک به‌طور گسترده توسط کتابخانه‌های Tidyverse مانند [`stringr`][ref-stringr] استفاده می‌شود.
بسیاری از توابع `stringr` پوششی کاربرپسند دور توابع سطح‌پایین `stringi` و R پایه هستند.

آرگومان‌های اضافی که به توابع `str_*()` داده می‌شوند، به‌سادگی به همان توابع سطح‌پایین منتقل می‌شوند.

## توابع به‌عنوان مقدار بازگشتی

یک تابع بیرونی می‌تواند یک تابع درونی تعریف کند (خواه نام‌دار، خواه بی‌نام، همان‌طور که در ادامه توضیح داده می‌شود) و آن را به‌عنوان مقدار بازگشتی استفاده کند.

تابع بازگردانده‌شده، محیطی را که در آن تعریف شده در بر می‌گیرد.

```R
times_y <- function(x) {
  # anonymous function - see next section
  \(y) x * y
}

f <- times_y(3)
class(f)
#> [1] "function"

f(4)
#> [1] 12
```

## توابع بی‌نام

وقتی تابعی تعریف می‌کنیم، معمولاً شیء تابع حاصل را به یک متغیر مقید می‌کنیم:

```R
x <- 2

# function definition captures x from the environment
doubleit_short <- function(y) x * y
```

این کار استفاده از تابع را در ادامه‌ی اسکریپت آسان می‌کند، اما چنین مقیدسازی‌ای ضروری نیست.
یک تابع کوتاه که فقط یک‌بار استفاده می‌شود می‌تواند در همان بافت فوری مفید باشد.
بدون مقیدسازی به اسم، به آن *تابع بی‌نام* می‌گویند.

استفاده از توابع بی‌نام آن‌قدر رایج است که (*از R v4.1.0 به بعد*) یک نحوه‌ی نگارش کوتاه برای تعریف آن‌ها وجود دارد: کلمه‌ی `function` را با یک بک‌اسلش `\` جایگزین کنید.

نمونه‌ای از این در بخش قبلی، درباره‌ی مقادیر بازگشتی، استفاده شد.

## کپی هنگام تغییر

R امکان انتساب به عناصر تک‌تک یک بردار را فراهم می‌کند.
اگر برداری را به‌عنوان آرگومان تابع بدهیم و آن را در بدنه‌ی تابع پیش از بازگرداندن تغییر دهیم، یک بردار تغییر‌یافته به دست می‌آوریم.

اما بردار اصلی چه شد؟

```R
f <- function(vec) {
  vec[1] <- 42
  vec
}

vals <- c(1, 3, 4)

# f() returns a modified vector
f(vals)
#> [1] 42  3  4  

# the original vector is unchanged.
vals
#> [1] 1 3 4
```

R زبانی است که برای علم داده طراحی شده است.
جمع‌آوری آن داده‌ها می‌تواند زمان و تلاش زیادی ببرد و به‌طور بالقوه هزینه‌ی سرسام‌آوری داشته باشد: *مهم است که داده‌ها را خراب نکنیم!*

سیاست کلی (با چند استثنا) *کپی هنگام تغییر* است.
اگر یک شیء (مانند یک بردار) به‌گونه‌ای تغییر کند که بعداً مشکل‌ساز شود، R یک *نسخه‌ی تغییر‌یافته* بازمی‌گرداند و اصل را دست‌نخورده رها می‌کند.

کپی کردن ساختارهای داده‌ی بزرگ می‌تواند از نظر محاسباتی پرهزینه باشد، اما این معمولاً شر کمتر است وقتی جایگزین آن خرابی داده باشد.
