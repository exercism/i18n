# مقدمه

در زبان C، یک **struct** یک نوع داده‌ی ترکیبی است که از فیلدهای مختلف ساخته می‌شود.
هر «فیلد» نوع و اندازه‌ی خودش را دارد.

برای نمونه، قطعه‌ی زیر نوعی را تعریف می‌کند که از سه عدد صحیح تشکیل شده است: دو عدد ۴ بایتی و یک عدد ۸ بایتی:

```c
struct example {
    int32_t first_four_byte_integer;
    uint32_t second_four_byte_integer;
    uint64_t eight_byte_integer;
};
```

یک struct می‌تواند structهای دیگری را هم در خود جای دهد:

```c
struct example_2 {
    struct example first;
    struct example second;
};
```

اگر یکی از فیلدهای struct یک آرایه باشد، همه‌ی بایت‌هایی که برای آن آرایه تخصیص داده می‌شوند بخشی از struct هستند.
اما اگر فیلد فقط یک اشاره‌گر به آرایه باشد، آن‌گاه آرایه باید جای دیگری ذخیره شود:

```c
struct with_array {
    char string[20];
};
// all 20 bytes of string are inside struct with_array

struct with_pointer {
    const char *string;
};
// only the 8-byte pointer to the string is inside struct with_pointer
```

## همترازی

**همترازی** یک نوع، توانی نامنفی از دو است (۱، ۲، ۴، ۸، ...) که شرطی را برای آدرس آن نوع بیان می‌کند.
هر شیء از آن نوع باید در آدرسی قرار بگیرد که مضربی از همترازی‌اش باشد.

برای یک نوع داده‌ی اولیه، همترازی معمولاً با اندازه‌ی آن برابر است؛ بنابراین برای نمونه، یک `int32_t` معمولاً همترازی ۴ بایتی دارد.
این یعنی `int32_t` باید در مرزهای ۴ بایتی تخصیص داده شود.

اما همترازی یک struct، بیشترین همترازی میان فیلدهای آن است.
پس برای مثال، `struct example` که در بالا تعریف شد، همترازی ۸ بایتی خواهد داشت، چون این همان همترازی `uint64_t` است.

اگر همترازی یک فیلد از struct کمتر از همترازی خود struct باشد، ممکن است بعد از آن فیلد بایت‌های پرکننده درج شوند.
این کار تضمین می‌کند که فیلدهای بعدی و کل struct الزامات همترازی را برآورده کنند.
در عمل، این یعنی هرچند آن بایت‌های پرکننده به اندازه‌ی struct اضافه می‌کنند، در مقدار struct استفاده نمی‌شوند:

```c
struct example_3 {
    char one_byte; // alignment of 1
    int four_byte; // alignment of 4
};
// example_3 has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one_byte'
// 3 padding bytes (with undefined value)
// 4 bytes for field 'four_byte'
```

توجه کنید که در struct تعریف‌شده در بالا، فیلد «one_byte» همترازی ۱ دارد و می‌تواند در هر آدرسی قرار بگیرد.
چون فیلد «four_byte» همترازی ۴ دارد، فیلدهای داخل struct هم باید مرزهای ۴ بایتی را رعایت کنند.
این یعنی بین هر دو فیلد در struct باید تعدادی بایت باشد که مضربی از ۴ است.
چون «one_byte» فقط ۱ بایت را اشغال می‌کند، برای رعایت این مرز ۳ بایت پرکننده بعد از آن درج می‌شود.

فیلدهای مجاور هرجا که ممکن باشد کنار هم گروه‌بندی می‌شوند تا تعداد بایت‌های پرکننده‌ی لازم کمینه شود:

```c
struct two_padding {
    char one; // alignment of 1
    char two; // alignment of 1
    int three; // alignment of 4
};
// struct two_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 byte for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
```

این گروه‌بندی باید همترازی هر فیلد را هم رعایت کند:

```c
struct one_padding {
    char one; // alignment of 1
    int16_t two; // alignment of 2
    int three; // alignment of 4
};
// struct one_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 padding byte
// 2 bytes for field 'two'
// 4 bytes for field 'three'
// Since 'two' has alignment of 2, it must be placed in a 2-byte boundary
// So, there must be 1 padding byte between 'one' and 'two'
```

این یعنی تغییر ترتیب فیلدها در یک struct گاهی می‌تواند به تفاوت در اندازه‌ی آن منجر شود:

```c
struct example_4 {
    int64_t one;
    short two;
    int32_t three;
};
// example_4 has one 8-byte field, one 4-byte field and one 2-byte field
// it has an alignment of 8 and occupies 16 bytes in space:
// 8 bytes for field 'one'
// 2 bytes for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
// two' and 'three' are adjacent and can be grouped to sum up 8 bytes with only 2 bytes of padding

struct example_5 {
    short one;
    int64_t two;
    int32_t three;
};
// example_5 also has one 8-byte field, one 4-byte field and one 2-byte field, in different positions
// it also has an alignment of 8, however, it occupies 24 bytes in space:
// 2 bytes for field 'one'
// 6 bytes for padding
// 8 bytes for field 'two'
// 4 bytes for field 'three'
// 4 bytes for padding
// 'one' can't be grouped with 'two' because their sum would be higher than the struct's alignment
// 'two' and 'three' also can't be grouped, for the same reason
// so padding bytes must be inserted in full after each field with less than 8 bytes in alignment
```

توجه کنید که همترازی یک آرایه با همترازی نوع پایه‌ی آن یکسان است:

```c
struct array_example {
    char string[10]; // alignment of 1
};
// array_example has alignment of 1 (it can be placed at any address)
// it occupies 10 bytes in space, one for each char in 'string'
```

عنصرهای یک آرایه هم می‌توانند همان‌طور گروه‌بندی شوند که گویی بخشی از یک آرایه نیستند:

```c
struct group_array {
    int16_t arr[3];
    int8_t one_byte;
    int32_t four_byte;
};
// group_array has alignment of 4 because this is the alignment of 'four_byte'
// it occupies 12 bytes in space:
// 4 bytes for arr[0] and arr[1]
// 2 bytes for arr[2]
// 1 byte for 'one_byte'
// 1 padding byte (arr[2] is grouped with 'one_byte')
// 4 bytes for 'four_byte'
```

هر زمان که به یک struct در اسمبلی دسترسی پیدا می‌کنید، مهم است که بایت‌های پرکننده‌ی احتمالی را در نظر بگیرید.

## قرارداد فراخوانی

به‌طور کلی، مقادیر همان‌طور که انتظار می‌رود به توابع فرستاده و از آن‌ها برگردانده می‌شوند:

- مقادیر صحیح، از جمله آدرس‌های حافظه و enumها، در ثبات‌های همه‌کاره (GPR) فرستاده می‌شوند.
- مقادیر اعشاری در ثبات‌های `xmm` فرستاده می‌شوند.

اما structها حالت خاصی دارند.
به‌عنوان یک قاعده‌ی سرانگشتی، همه‌ی فیلدهای یک struct در حافظه فضای مجاور هم را اشغال می‌کنند و باید هرجا که ممکن باشد در یک ثبات واحد قرار بگیرند:

```c
struct single_type {
    int16_t first;
    int16_t second;
    int16_t third;
    int16_t fourth;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'first' is passed on the lowest 2 bytes
// each subsequent field is passed in the following 2 bytes
```

اگر struct هم فیلدهایی با مقادیر صحیح داشته باشد و هم فیلدهایی با مقادیر اعشاری، هر ۸ بایت متوالی در struct باید جداگانه دسته‌بندی شود:

```c
struct mixed_types {
    double first;
    int second;
    int third;
};
// this struct occupies 16 bytes
// the field 'first' is passed in the first 8 bytes of a xmm register
// the fields 'second' and 'third' are passed in the same GPR register:
// the field 'second' is passed on the lowest 4 bytes
// the field 'third' is passed in the next 4 bytes
```

اگر اعداد صحیح و مقادیر اعشاری در همان ۸ بایت قرار بگیرند، نوع آن صحیح است و کل ۸ بایت (شامل مقدار اعشاری) در یک GPR قرار می‌گیرد:

```c
struct mixed_types {
    int32_t integer;
    float floating_point;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'integer' is passed on the lowest 4 bytes
// the field 'floating_point' is passed on the next 4 bytes
```

~~~~exercism/caution
وقتی با استفاده از `cvtss2si` یا `cvtsd2si` تبدیلی از یک مقدار اعشاری به یک عدد صحیح انجام می‌شود، چیدمان بایت‌های زیربنایی تغییر می‌کند.

برای جابه‌جایی بایت‌های خام از یک ثبات `xmm` به یک GPR، بدون تغییر نمایش بیتی، می‌توانید از `movd` (برای مقادیر ۳۲ بیتی) و `movq` (برای مقادیر ۶۴ بیتی) استفاده کنید.
~~~~

اما structهایی که اندازه‌شان بیشتر از ۱۶ بایت است، صرف‌نظر از نوع هر ۸ بایت، معمولاً در حافظه قرار می‌گیرند:

```c
struct big_struct {
    uint8_t first;
    double second;
    int64_t third;
};
// this struct occupies 24 bytes, including 7 padding bytes between 'first' and 'second'
// it is entirely passed in memory
```

وقتی یک struct به‌عنوان آرگومان به تابعی فرستاده می‌شود، از هر تعداد ثباتی که لازم باشد استفاده می‌شود.
اگر در حافظه قرار بگیرد، به‌جایش از پشته استفاده می‌شود.

قواعد مشابهی برای structهایی که از یک تابع برگردانده می‌شوند هم برقرار است.
این‌ها معمولاً ابتدا در `rax` و `rdx` (اگر مقدار صحیح باشند) یا `xmm0` و `xmm1` (اگر مقدار اعشاری باشند) برگردانده می‌شوند.
اما اگر در حافظه قرار بگیرند، فراخوان باید برای آن فضا رزرو کند و آدرس آن محل حافظه را به‌عنوان آرگومان اول ضمنی به تابع بفرستد (در `rdi`).
سپس تابع struct را در این فضا ذخیره می‌کند و آدرس آن را در `rax` برمی‌گرداند.
