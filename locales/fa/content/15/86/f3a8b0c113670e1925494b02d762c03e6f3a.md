# درباره

این تمرین رفتار انواع مختلف عددی را هنگام سرریز نشان می‌دهد؛ یعنی زمانی که ظرفیتشان برای نگه‌داشتن مقداری که از محاسبه‌ای مانند یک عمل حسابی یا تبدیل نوع حاصل می‌شود کافی نیست.

- [اعداد صحیح][integral-numeric-types] بدون علامت (`byte`، `ushort`، `uint`، `ulong`) به صفر دور می‌زنند (بیشترین مقدار نوع به‌علاوه‌ی ۱ به عنوان پیمانه عمل می‌کند)، مگر آن‌که [به طور کلی][checked-compiler-setting] درون یک بلوک [`checked`][checked-and-unchecked] قرار بگیرند که در آن صورت نمونه‌ای از `OverflowException` پرتاب می‌شود. `int` و `long` هم رفتار مشابهی دارند، با این تفاوت که به ترتیب به `int.MinValue` و `long.minValue` دور می‌زنند.

```csharp
int one = 1;
checked
{
    int expr = int.MaxValue + one;  // overflow exception is thrown
}

// or

int expr2 = checked(int.MaxValue + one);  // overflow exception is thrown
```

- اگر یک عبارت لیترال باعث سرریز متغیری شود که به آن انتساب داده می‌شود، خطای زمان کامپایل رخ می‌دهد.
- وضعیت `checked` فقط به عبارت‌هایی اعمال می‌شود که مستقیماً درون بلوک هستند. وضعیت‌های سرریز در توابع فراخوانی‌شده گرفته نمی‌شوند.
- انواع [`float` و `double`][floating-point-numeric-types] به وضعیتی به نام _بینهایت_ درمی‌آیند که می‌توان آن را با `float.IsInfinity()` و موارد مشابه آزمایش کرد.

```csharp
double d = double.MaxValue;
d *= 2d;
Double.IsFinite(d)
// => false
```

- اعدادی از نوع [`decimal`][floating-point-numeric-types] باعث پرتاب نمونه‌ای از `OverflowException` می‌شوند.
- همچنین «کلیدواژه»ی متناظر `unchecked` برای مواقعی وجود دارد که می‌خواهید اثر `unchecked` را درون یک بلوک `checked` خنثی کنید یا زمانی که تنظیم کامپایلر به کار رفته است.

سرریزهایی که بدون پرتاب «استثنا» رخ می‌دهند می‌توانند مشکل‌ساز باشند، چون به طور کلی هرچه زودتر بتوان یک وضعیت خطا را گزارش کرد، بهتر است.

مشکلات سرریز در `int` و `float` را می‌توان با انتساب نتیجه به متغیری از نوع `long`، `decimal` یا `double` کاهش داد.

اگر اعداد صحیح بزرگ برای کدتان ضروری‌اند، استفاده از نوع [`BigInteger`][big-integer] یک گزینه است.

طبیعتاً مواقعی هم هست که دور زدن یک عدد صحیح مجاز است، به ویژه در مورد مقادیر بدون علامت. نمونه‌ی کلاسیک آن کدهای هش است که از عرض عدد صحیح به عنوان نوعی پیمانه استفاده می‌کنند.

معمولاً در کدبیس‌ها می‌بینید که وقتی `uint` یا `ulong` به عنوان شناسه به کار می‌رود، غالباً بررسی‌ای انجام نمی‌شود، چون ارزش دردسرش را ندارد. این موضوع در جایی هم صدق می‌کند که از دامنه‌ی مسئله روشن است که مقادیر خیلی بزرگ پیش نخواهد آمد. اما برای عبرت [این][computerphile-gangnam-style] را ببینید.
