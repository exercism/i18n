# درباره

«پیوند» توصیف می‌کند که یک «شناسه» از کدام نقطه از کد قابل دسترسی است.
مقادیری که حوزه‌ی بلوک، تابع یا پیش‌نمونه‌ی تابع دارند، هیچ پیوندی ندارند.
یعنی نمی‌توان از بیرون از حوزه‌ی آن‌ها به آن‌ها دسترسی داشت.
برای اطلاعات بیشتر درباره‌ی حوزه، [مفهوم حوزه](../scope/introduction.md#Introduction) را ببینید.

## پیوند خارجی

شناسه‌هایی که حوزه‌ی فایل دارند، به‌طور پیش‌فرض پیوند خارجی دارند.
یک شناسه با پیوند خارجی را می‌توان از هر فایلی در برنامه فراخوانی کرد.

## پیوند داخلی

می‌توان کاری کرد که یک شناسه با حوزه‌ی فایل، با استفاده از مشخص‌کننده‌ی `static` پیوند داخلی داشته باشد.
شناسه‌ای که پیوند داخلی دارد، فقط می‌تواند در همان فایل خودش استفاده شود.

برای مثال

```c
int public_count = 0; // file scope, external linkage by default
static int private_count = 0;  // file scope, internal linkage 

// file scope, internal linkage
static void some_function()
{
    // code snipped
}

// file scope, external linkage by default
int main()
{
    // code snipped
}
```

پیوند ایستا را نباید با مدت‌زمان ذخیره‌سازی ایستا اشتباه گرفت.
برای اطلاعات بیشتر درباره‌ی مدت‌زمان ذخیره‌سازی ایستا، [مفهوم مدت‌زمان ذخیره‌سازی](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#static-the-storage-specifier-not-to-be-confused-with-the-static-linkage-type) را ببینید.

اگر یک مقدار (و نه یک تابع) در یک هدر اعلان شود اما در فایل مبدأ به‌صورت یک شناسه‌ی `static` با حوزه‌ی فایل و دارای مقدار اولیه تعریف شود، مقدار اولیه‌ی آن از بیرون از فایل مبدأ قابل دسترسی نخواهد بود.
ممکن است بدون خطا کامپایل و پیوند و اجرا شود، اما مقدار آن برای شناسه مقدار صفر خواهد بود، حتی اگر مقدار با `extern` اعلان شده باشد.
(برای اطلاعات بیشتر درباره‌ی `extern`، [مفهوم `extern`](https://github.com/exercism/c/blob/main/concepts/storage-class-specifiers/about.md#extern-how-to-access-a-variable-in-another-translation-unit) را ببینید.)
شناسه‌ای با حوزه‌ی فایل که در یک فایل مبدأ با `static` مشخص شده است، نباید در فایل هدر آن اعلان شود.
