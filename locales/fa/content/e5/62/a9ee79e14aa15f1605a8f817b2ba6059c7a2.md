# مقدمه

یک *«عبارت باقاعده»* یا همان regex، الگوی کوچکی است که توصیف می‌کند یک متن باید چه شکلی باشد. به‌جای اینکه خودتان رشته‌ای را نویسه‌به‌نویسه بررسی کنید، یک بار شکل موردنظرتان را می‌نویسید و می‌گذارید Factor کار تطبیق را انجام دهد. ابزارهای regex در Factor در واژگان [`regexp`][regexp] قرار دارند.

## نوشتن یک الگو

در Factor، یک regex را بین `R/ ` و `/` می‌نویسید:

```factor
R/ cat/      ! the pattern that matches the letters c, a, t
```

بیشتر نویسه‌ها در یک الگو فقط به معنای خودشان هستند؛ `R/ cat/` با متن `cat` تطبیق پیدا می‌کند. توان این کار از چند قطعه‌ی خاص می‌آید که نماینده‌ی *انواع* نویسه‌ها یا *تعدادشان* هستند.

### کلاس‌های نویسه، «یک نویسه از یک مجموعه»

```
\d        ! any digit, 0–9
\D        ! any NON-digit (the opposite of \d)
\s        ! any space, tab, or newline
\S        ! any NON-space character (the opposite of \s)
\w        ! a "word" character: a letter, a digit, or an underscore
\W        ! any NON-word character (the opposite of \w)
[A-Z]     ! any one capital letter A to Z
[a-z]     ! any one lowercase letter
[0-9]     ! any one digit (same as \d)
.         ! any single character at all
```

هر کلاس دقیقاً با *یک* نویسه تطبیق پیدا می‌کند. `[A-Z]` با `Q` تطبیق پیدا می‌کند، اما با `QQ` نه.

### کمیت‌نماها، «چند بار»

یکی از این‌ها را *بعد* از یک قطعه بگذارید تا بگویید چند بار می‌تواند تکرار شود:

```
{4}       ! exactly 4 times
{2,5}     ! between 2 and 5 times
+         ! one or more
*         ! zero or more
?         ! zero or one (optional)
```

پس `\d{4}` یعنی چهار رقم پشت سر هم و `[A-Z]+` یعنی یک یا چند حرف بزرگ. اگر این‌ها را کنار هم بگذاریم، `R/ [A-Z]+-\d+/` توصیف‌کننده‌ی «یک یا چند حرف بزرگ، یک خط تیره و بعد یک یا چند رقم» است؛ متنی مثل `SALE-2024`. `-` در اینجا یک نویسه‌ی معمولی است: بیرون از `[ ]` خط تیره فقط با خط تیره تطبیق پیدا می‌کند (داخل یک کلاس، مثل `[A-Z]`، محدوده را مشخص می‌کند).

## تطبیق با یک رشته‌ی کامل

`matches?` به این پرسش پاسخ می‌دهد که «آیا کل این رشته با الگو همخوانی دارد؟»؛ الگو باید هر نویسه را از ابتدا تا انتها در نظر بگیرد:

```
matches? ( string regexp -- ? )
```

```factor
USING: regexp ;

"SALE-2024"     R/ [A-Z]+-\d+/ matches? .   ! => t
"GET SALE-2024" R/ [A-Z]+-\d+/ matches? .   ! => f   (extra text before)
"SALE-2024 NOW" R/ [A-Z]+-\d+/ matches? .   ! => f   (extra text after)
"sale-2024"     R/ [A-Z]+-\d+/ matches? .   ! => f   (lowercase letters)
```

با اینکه `SALE-2024` داخل `"GET SALE-2024"` قرار دارد، `matches?` باز هم `f` برمی‌گرداند: نویسه‌های اضافی بخشی از رشته‌اند و با الگو همخوانی ندارند. وقتی فقط مهم است که الگو *جایی* ظاهر شود، سراغ `re-contains?` بروید؛ این کلمه دقیقاً همان‌جا که `matches?` مقدار `f` را برگردانده بود، `t` برمی‌گرداند:

```
re-contains? ( string regexp -- ? )
```

```factor
USING: regexp ;

"GET SALE-2024" R/ [A-Z]+-\d+/ matches? .      ! => f
"GET SALE-2024" R/ [A-Z]+-\d+/ re-contains? .  ! => t
```

## یافتن تطبیق‌ها در متن‌های بلندتر

`re-contains?` فقط می‌گوید الگو *آیا* در متن هست یا نه. کلمه‌های بعدی داخل متن را نگاه می‌کنند و گزارش می‌دهند *چه چیزی* تطبیق پیدا کرده: `all-matching-subseqs` هر جایی که الگو تطبیق پیدا می‌کند را به‌صورت دنباله‌ای از رشته‌ها برمی‌گرداند و `count-matches` فقط آن‌ها را می‌شمارد:

```
all-matching-subseqs ( string regexp -- seq )
count-matches        ( string regexp -- n )
```

```factor
USING: regexp ;

"3 cats, 12 dogs, 1 fish" R/ \d+/ all-matching-subseqs .
! => { "3" "12" "1" }            (every run of digits)

"the quick fox" R/ \S+/ all-matching-subseqs .
! => { "the" "quick" "fox" }     (every run of non-space characters)

"id_7!" R/ \w/ count-matches .   ! => 4   (i, d, _ and 7 count; ! does not)
```

## جایگزینی تطبیق‌ها

`re-replace` هر تطبیق را با یک قطعه متن جایگزین عوض می‌کند و رشته‌ی جدید را برمی‌گرداند:

```
re-replace ( string regexp replacement -- result )
```

```factor
USING: regexp ;

"page 7 of 12" R/ \d+/ "N" re-replace .
! => "page N of N"
```

واژگان `regexp` کلمه‌های بیشتری دارد که ارزش دانستن دارند؛ برای جزئیات پیوندها را دنبال کنید: [`first-match`][first-match] (فقط اولین تطبیق) و [`re-split`][re-split] (شکستن یک رشته در هر جایی که الگو تطبیق پیدا می‌کند).
