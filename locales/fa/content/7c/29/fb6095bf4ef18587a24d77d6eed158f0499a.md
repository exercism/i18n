# درباره

در بسیاری از زبان‌های شیءگرا، رایج است که رفتارها را با [زیرکلاس‌سازی][wiki-subclass] یک کلاس والد گسترش دهند؛ به این ترتیب متدهایی را از والد به ارث می‌برند و در همان حال متدهای تازه هم اضافه می‌کنند. این‌گونه سلسله‌مراتبی از اشیاء به دست می‌آید.

Julia _کلاس ندارد_، و در نتیجه _زیرکلاس هم ندارد_.
چگونه رفتارهای موجود را به ارث می‌بریم و گسترش می‌دهیم؟

در مفاهیم پیشین دیدیم که چگونه سلسله‌مراتب نوع‌ها را بسازیم و همچنین آموختیم که Julia چگونه از [ارسال چندگانه][concept-multiple-dispatch] برای انتخاب متد بر پایه‌ی نوع آرگومان‌ها استفاده می‌کند.

Julia همچنین چند [رابط][ref-interfaces] غیررسمی دارد که به نوع‌های سفارشی شما امکان می‌دهند به رفتارهایی متصل شوند که از پیش برای نوع‌های استاندارد تعریف شده‌اند.

این موضوع را به‌سادگی می‌توان با رابط Iterator نشان داد.

## [تکرارگر][ref-iterators]

پیش‌تر در برنامه‌ی درسی، چند روش دیده‌ایم که Julia با آن‌ها می‌تواند روی هر عنصر یک مجموعه کار کند.

- [حلقه][concept-loops]، مانند `for item in items...`
- [پخش][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [توابع مرتبه‌بالا][concept-hof]: `map(√, [1, 4, 9])`
- [درک][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [مولد][concept-comprehensions]: `(x^2 for x in 1:1e6)`، که به‌صورت تنبل ارزیابی می‌شود.

روشن است که Julia می‌داند چگونه مجموعه‌های استاندارد را عنصر به عنصر پیمایش کند: در مثال‌های بالا بردارها و بازه‌ها، و همچنین Setها، Dictها و غیره.

چگونه این قابلیت را به مجموعه‌های سفارشی خودمان اضافه کنیم، به‌ویژه اگر بتوان آن‌ها را مانند یک مولد به‌صورت تنبل تکرار کرد؟

### حداقل نیازها

برای ساختن یک دنباله برای تکرار، حداقل به دو مورد نیاز داریم:

1. راهی برای گرفتن _اولین_ عنصر.
2. راهی برای گرفتن _عنصر بعدی_ از وضعیت جاری.

Julia این کارها را با متدهای تابع `Base.iterate()` و در این مراحل انجام می‌دهد:

1. نخست `Base.iterate(iter)` به‌صورت خودکار فراخوانی می‌شود.
    - اگر چیزی برای تکرار باقی نمانده باشد، `nothing` برمی‌گرداند.
    - در غیر این صورت، یک `Tuple` از اولین عنصر بازگشتی و اولین وضعیت برمی‌گرداند: `(firstitem, firststate)`.
2. اگر در تکرار پیشین عنصری بازگردانده شده باشد، `Base.iterate(iter, state)` به‌صورت خودکار فراخوانی می‌شود و `firststate` را به عنوان آرگومان `state` خود می‌گیرد.
    - اگر تکرار پایان یابد، `nothing` برمی‌گرداند.
    - در غیر این صورت، یک `Tuple` از عنصر بعدی و وضعیت بعدی برمی‌گرداند: `(nextitem, nextstate)`.
3. مرحله‌ی ۲ تا پایان تکرار می‌شود.

همه‌ی این مراحل «در پشت صحنه» انجام می‌شوند؛ یعنی فراخوانی‌های متد و وضعیت به‌صورت درونی توسط قرارداد تکرار مدیریت می‌شوند (و وضعیت مبهم می‌ماند) و تنها عنصر در معرض ساختارهای سطح‌بالا مانند حلقه‌ها قرار می‌گیرد.
به بیان دیگر، ما فقط `item` را می‌بینیم و باقی در یک جعبه‌ی سیاه می‌ماند.

[ارسال چندگانه][concept-multiple-dispatch] در اینجا نقش محوری دارد.
نوع `iter` تعیین می‌کند کدام متدها فراخوانی شوند و تعداد آرگومان‌ها تعیین می‌کند که عنصر اول بازگردانده شود یا عنصر بعدی.

متدهای نوع‌های استاندارد از پیش تعریف شده‌اند: `Vector`، `Range`، `Set` و غیره ([در حال حاضر][ref-iterations-collections] در مجموع ۱۴ نوع).

برای اینکه یک `MyType` سفارشی همان رفتارها را داشته باشد، ابتدا باید این‌ها را تعریف کنیم:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

همه‌ی این‌ها در حالت انتزاعی احتمالاً گیج‌کننده به نظر می‌رسد، اما می‌تواند کاملاً ساده باشد.
برای نمونه، تصور کنید نوعی می‌خواهیم که توان‌های یک عدد صحیح داده‌شده `n` را تا یک شمارش حداکثری تولید می‌کند.

ابتدا یک نوع سفارشی تعریف کنید:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

اکنون می‌توانیم متدهای `iterate` را برای این نوع تعریف کنیم، اما عنصر اول و وضعیت اول چیست؟

برای به دست آوردن عنصر اول، بعضی تکرارگرها به آماده‌سازی پیچیده‌ای نیاز دارند، اما در این مثال ساده می‌بینیم که اولین عنصر بازگشتی همان عدد پایه است؛ پس فقط باید بررسی کنیم که مقدار `count` بزرگ‌تر یا مساوی یک باشد.

حال می‌توانیم وضعیت اول را در نظر بگیریم، که اطلاعاتی را حمل می‌کند که در تکرار بعدی استفاده می‌شود.
این به خودتان بستگی دارد که تصمیم بگیرید برای این کار چه اطلاعاتی را باید پیگیری کنید و آن می‌تواند هر نوعی باشد.

در این حالت، می‌توانیم فقط «اندیس»ی را که `n` به آن توان رسانده می‌شود پیگیری کنیم، یا با استفاده از تازه‌ترین توان `n` (یعنی همان عنصر بازگشتی) و «اندیس» بعدی در دنباله، گزینه‌ی کارآمدتری پیدا کنیم.
این دو عدد را می‌توان در یک `Tuple` پیچید و به عنوان `state` بازگرداند.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

در این مثال، عنصر اول (`p.n`) به حلقه بازگردانده می‌شود و وضعیت اول `(p.n, 2)` به متد `iterate(P::Powers, state)` فرستاده می‌شود.
آنجا می‌توانیم وضعیت را پردازش کنیم تا با ضرب عنصر جاری در عدد پایه، عنصر بعدی را بسازیم و بدین ترتیب توان آن را `1` واحد افزایش دهیم.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

اگر مقدار اندیس هنوز در محدوده‌ی `count` باشد، `Tuple` با عنصر `next` و وضعیت افزایش‌یافته‌ی `(next, index + 1)` بازگردانده می‌شود.
وقتی مقدار `index` از `count` فراتر می‌رود، به جای آن `nothing` بازگردانده می‌شود تا نشان دهد تکرار پایان یافته است.

شاید متوجه شده باشید که بدنه‌ی توابع متدهای `iterate(p::Powers)` و `iterate(p::Powers, state)` تقریباً شبیه هم است.
در واقع، اگر زیرک باشیم، این شباهت امکان یک پیاده‌سازی ساده‌تر را می‌دهد: استفاده از تنها نسخه‌ی دوآرگومانی همراه با یک آرگومان پیش‌فرض برای وضعیت: `Base.iterate(p::Powers, state=(1, 1))`
با این کار، به نسخه‌ی جداگانه‌ی تک‌آرگومانی `iterate(p::Powers)` نیازی نخواهیم داشت.
در عمل هر جا امکان داشته باشد، این کار رایج است.

~~~~exercism/advanced
وقتی آرگومان‌های اختیاری را در مفهوم [توابع][concept-functions] معرفی کردیم، هیچ سخنی درباره‌ی پیاده‌سازی گفته نشد.

از آن زمان، درباره‌ی ارسال چندگانه آموختیم؛ پس اکنون منطقی‌تر است که بدانیم Julia به‌طور خودکار یک تابع _با_ آرگومان‌های اختیاری را به چندین متد _بدون_ آرگومان‌های اختیاری تبدیل می‌کند.

تعریف `Base.iterate(P::Powers, state=(1, 1))` دقیقاً معادل تعریف جداگانه‌ی هر دو متد `Base.iterate(P::Powers, state)` و `Base.iterate(P::Powers)` است.

تا اینجا، کارکردی مفید به دست آورده‌ایم: برای ۴ توان اول ۳، می‌توانیم روی نتایج حلقه بزنیم، بررسی کنیم آیا یک عدد داده‌شده در نتایج هست یا نه، و توابع تجمعی مانند `sum()` را اعمال کنیم.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### متدهای بیشتر

با وجود این شروع خوب، هنوز همه چیز کار نمی‌کند.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers)
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

و همان‌طور که انتظار می‌رفت، `length(Powers(3, 4))` دقیقاً همان پیام خطا را می‌دهد.

رفع این مشکل آسان است، چون طول بخشی از سازنده‌ی نوع است: در این حالت ۴.
فقط باید `Base.length()` را برای این نوع تعریف کنیم؛ سپس می‌توانیم از درک‌ها و `collect()` روی دنباله استفاده کنیم.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

برای کارایی، بهتر است `Base.eltype()` را هم تعریف کنیم: نوع عنصر نتیجه.
این کار به توابعی مانند `collect()` اجازه می‌دهد از پیش فضایی برای `Vector{Int}` خروجی اختصاص دهند، به جای اینکه بارها `push!()` را روی یک `Vector{Any}` انجام دهند.

به نحوه‌ی نگارش توجه کنید، که ممکن است پیش‌تر ندیده باشید: این متد روی _نوع_ تعریف می‌شود، نه روی یک _نمونه_ از نوع.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

تکرارگرها _ملزم_ نیستند طول متناهی داشته باشند.
استفاده از دنباله‌های «بی‌نهایت» محدودتر است، اما تا زمانی که راهی برای `break` از حلقه وجود داشته باشد، حلقه زدن روی آن‌ها می‌تواند مفید باشد.
برای نمونه، می‌توانیم گونه‌ای از `Powers` تعریف کنیم که مقادیری کوچک‌تر از یک حد مشخص تولید کند (شاید `typemax(Int)`، برای جلوگیری از سرریز عدد صحیح).

## رابط‌های دیگر

### [نمایه‌سازی][ref-indexing]

رابط تکرارگر به ما اجازه می‌دهد هر نوع سفارشی دلخواهی را برداریم و کاری کنیم که مانند یک دنباله رفتار کند، فقط با تعریف چند متد ساده.

فرض کنید می‌خواستیم بتوانیم روی دنباله نمایه هم اعمال کنیم:

```julia-repl
julia> P = Powers(3, 4)
Powers(3, 4)

julia> P[2]
ERROR: MethodError: no method matching getindex(::Powers, ::Int64)
The function `getindex` exists, but no method is defined for this combination of argument types.
```

می‌توانیم این رفتار را اضافه کنیم، و [راهنما][ref-indexing] توضیح می‌دهد که چگونه.

حداقل، باید `getindex()` را تعریف کنیم.

```julia-repl
julia> function Base.getindex(P::Powers, i::Int)
          1 ≤ i ≤ P.count || throw(BoundsError(P, i))
          return p.n ^ i
       end

julia> p = Powers(3, 4)
Powers(3, 4)

julia> p[3]
27
```

همچنین باید این‌ها را تعریف کنیم:

- `firstindex()` و `lastindex()` برای پشتیبانی از `P[begin]` و `P[end]`.
- گونه‌هایی از `getindex()` برای پشتیبانی از نمایه‌گذاری با بردارها و بازه‌ها.
- در تئوری، `setindex!()`، هرچند به‌سختی می‌توان دید این در این مثال چه معنایی می‌تواند داشته باشد.

با این حال، تا اینجا کار زیادی کرده‌ایم فقط برای اینکه تکرارگرمان بیشتر شبیه بردار شود.

### [AbstractArray][ref-abstractarray]

شاید ارزش داشته باشد به رابط‌های جایگزینی فکر کنیم که نقطه‌ی شروع بهتری فراهم می‌کنند.

در این حالت، می‌توانیم در نظر بگیریم که `Powers` را زیرنوعی از [`AbstractArray`][ref-abstractarray] کنیم، که بسیاری از رفتارهای مشابه آرایه را به‌رایگان به ما می‌دهد.

برای دنباله‌ی `Powers`، آرایه‌ی متناظر از اعداد صحیح است و یک بُعد دارد.
گاهی این را به‌شکل `AbstractArray{Int, 1}` می‌بینید، اما نام‌های مستعار `AbstractVector{Int}` برای یک‌بعدی و `AbstractMatrix{Int}` برای دوبعدی در کدهای جدیدتر Julia رایج‌ترند.

```julia-repl
julia> struct PowersArray <: AbstractVector{Int}
           n::Int
           count::Int
       end
```

حالا به جای `length()` باید `size()` را با یک چندتایی از طول‌ها در هر بُعد تعریف کنیم: در این حالت فقط یک بُعد.

```julia-repl
julia> Base.size(PA::PowersArray) = (PA.count,)
```

می‌خواهیم درایه‌ها را چگونه نمایه کنیم؟
در [مفهوم آرایه‌های چندبعدی][concept-multi-dimensional-arrays] دو رویکرد اصلی را معرفی کردیم:

- یک نمایه برای هر بُعد، مانند `M[row, col]` برای یک ماتریس `M`.
- یک نمایه‌ی واحد، متناظر با چیدمان درایه‌ها در حافظه

به این‌ها به ترتیب `Cartesian` و `Linear` می‌گویند.

در این مثال فقط یک بُعد داریم، پس نمایه‌گذاری خطی مناسب است.

```julia-repl
julia> Base.IndexStyle(::Type{PowersArray}) = IndexLinear()

julia> Base.getindex(PA::PowersArray, i::Int) = PA.n ^ i

julia> p = PowersArray(3, 4)
4-element PowersArray:
  3
  9
 27
 81

julia> p[3]
27
```

توجه کنید که در این حالت `iterate()` را تعریف نکردیم.
Julia بر پایه‌ی تعریف ما از `getindex()`، به‌طور خودکار یک پیاده‌سازی پیش‌فرض فراهم می‌کند.

تعریف نسخه‌ی خودمان از `iterate()` همچنان ممکن است و در برخی موارد می‌تواند کارآمدتر باشد.

استفاده از رابط `AbstractArray` به‌ویژه زمانی ارزشمند است که تکرار چندبعدی می‌خواهیم.
با این خطر که مثال ساده را بیش از حد بکشیم، این می‌تواند به معنای `m` توان اول اعداد در `1:n` باشد، که به‌صورت تکرارشونده آرایه‌ای با اندازه‌ی `(m, n)` تعریف می‌کند.

```julia-repl
struct PowersMatrix{Int} <: AbstractMatrix{Int}
    ns::AbstractVector{Int}
    count::Int
end

Base.size(PM::PowersMatrix) = (PM.count, length(PM.ns))
Base.IndexStyle(::Type{PowersMatrix}) = IndexCartesian()
Base.getindex(PM::PowersMatrix, i::Int, j::Int) = PM.ns[j] ^ i

julia> PM = PowersMatrix(2:6, 4)
4×5 PowersMatrix{Int64}:
  2   3    4    5     6
  4   9   16   25    36
  8  27   64  125   216
 16  81  256  625  1296

julia> PM[3, 2]
27

julia> PM[7] # column major linear indexing
27

julia> PM[21]
BoundsError: attempt to access 4×5 PowersMatrix{Int64} at index [21]
[...]
```

### [گرد کردن][ref-rounding]

مفاهیم پیشین انواع مختلف گرد کردن را برای نوع‌های عددی ذکر کرده‌اند.

```julia-repl
julia> round(1.7)
2.0

julia> floor(1.7)
1.0

julia> ceil(1.7)
2.0

# specify output type
julia> round(Int, 1.7)
2

julia> round(2.4 + 7.3im)
2.0 + 7.0im
```

تابع [`round()`][ref-round] از این انعطاف‌پذیرتر است و به شما اجازه می‌دهد [`RoundingMode`][ref-roundingmode] (از ۷ حالت پشتیبانی‌شده‌ی کنونی)، تعداد ارقام اعشار در خروجی و پایه‌ی عدد را مشخص کنید.

ممکن است بخواهیم همان توابع با نوع‌های سفارشی ما هم کار کنند.
معمولاً این به معنای نوع‌های ترکیبی مانند مختصات است.

```julia-repl
julia> struct Point3D
           x::Float64
           y::Float64
           z::Float64
       end

julia> p = Point3D(7.63, 9.24, 4.50)
Point3D(7.63, 9.24, 4.5)

julia> round(p)
ERROR: MethodError: no method matching round(::Point3D, ::RoundingMode{:Nearest})
The function `round` exists, but no method is defined for this combination of argument types.
```

جای تعجب نیست که یک رابط `Rounding` وجود دارد که حداقل ما را ملزم می‌کند `round()` را برای نوع خودمان تعریف کنیم.

```julia-repl
julia> Base.round(P3D::Point3D, r::RoundingMode) = Point3D(round(P3D.x, r), round(P3D.y, r),round(P3D.z, r))

julia> round(p)
Point3D(8.0, 9.0, 4.0)

julia> ceil(p)
Point3D(8.0, 10.0, 5.0)
```

چون `RoundingMode` را در تعریف گنجانده‌ایم، `floor()` و `ceil()` به‌طور خودکار کار می‌کنند.

البته آزادیم شکل‌های پیچیده‌تری از گرد کردن را تعریف کنیم.

- ممکن است بخواهیم `Point3D` را به فاصله‌ای صحیح از مبدأ و در همان جهت گرد کنیم.
- برای زاویه‌ها، ممکن است بخواهیم به ۱۶ جهتی که هواشناسان استفاده می‌کنند گرد کنیم (_«باد از جنوب‌جنوب‌غرب با ۱۵ گره»_)، یعنی مضارب π/8 رادیان.
- ممکن است بخواهیم امکان مشخص کردن `digits`، `sigdigits` یا `base` را اضافه کنیم.
- [گزینه‌های ویژه][ref-round-periods] برای بازه‌های زمانی وجود دارد

## خلاصه

توضیح رابط‌ها نسبتاً گیج‌کننده است، چون رویکرد Julia با بیشتر زبان‌های دیگر بسیار متفاوت است.
به‌ویژه، ممکن است اسم رابط هرگز در پیاده‌سازی ذکر نشود: برخلاف [زیرکلاس‌سازی][wiki-subclass] یا [میکسین‌ها][wiki-mixins].

با این حال، در عمل به‌طور شگفت‌انگیزی ساده‌اند:

1. یک نوع مناسب تعریف کنید و تصمیم بگیرید که زیرنوع‌سازی مفید است یا نه.
2. بفهمید کدام متدها لازم‌اند (از [مستندات][ref-interfaces]).
3. آن متدها را برای نوع سفارشی خود پیاده‌سازی کنید؛ معمولاً فقط چند متد، و نسبتاً کوتاه و ساده.
4. بگذارید [ارسال چندگانه][concept-multiple-dispatch] بقیه را به‌طور خودکار انجام دهد.
