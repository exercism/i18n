# درباره

[نوع سفارشی][custom-types] در الم نمایندهٔ تعداد ثابتی از حالت‌های نامدار است. هر مقدار دقیقاً با یکی از این حالت‌های نامدار متناظر است. در زبان‌ها یا بافت‌های دیگر، این مفهوم با نام‌های _انواع مجموع_، _اتحادهای تفکیک‌شده_، _اتحادهای برچسب‌دار_ و _انواع دادهٔ جبری_ شناخته می‌شود.

هر حالت از یک اتحاد تفکیک‌شده می‌تواند به‌صورت اختیاری داده‌ای همراه داشته باشد و حالت‌های مختلف می‌توانند انواع متفاوتی از داده داشته باشند. اگر هیچ‌یک از حالت‌ها داده‌ای همراه نداشته باشند، این اتحاد تفکیک‌شده شبیه چیزی است که زبان‌های دیگر معمولاً آن را _شمارش_ (یا _enum_) می‌نامند.

نوع سفارشی با «کلیدواژهٔ `type` تعریف می‌شود و نحوهٔ نگارشش بسیار ساده است. این نوع‌ها یکی از مهم‌ترین تکنیک‌ها در برنامه‌نویسی الم هستند و از آن‌ها استفاده می‌شود تا مقادیر ممکن در کد دقیقاً با مقادیر معتبر در دنیای واقعی منطبق شوند؛ این کار جایی برای داده‌های نامعتبر باقی نمی‌گذارد و باعث می‌شود که [حالت‌های ناممکن در کد قابل نمایش نباشند][impossible-states].

```elm
-- Custom Type without associated data
type Season
    = Spring
    | Summer
    | Autumn
    | Winter

-- Custom Type with associated data
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

ساختن یک مقدار برای یک حالت مشخص، با ارجاع به اسم آن (`Spring`) انجام می‌شود؛ این کار وقتی ممکن است که آن حالت در همان ماژول تعریف شده باشد یا با نحوهٔ نگارش `import SeasonModule exposing (Season(..))` وارد شده باشد. راه دیگر، ارجاع به اسم کامل آن (`Season.Spring`) است، وقتی که با نحوهٔ نگارش `import SeasonModule exposing (Season)` وارد شده باشد.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

نوع‌های سفارشی، مانند همه‌چیز در الم، _برابری ساختاری_ دارند؛ یعنی دو مقدار از یک حالت با دادهٔ (اختیاری) یکسان، معادل یکدیگرند.

روش ترجیح‌داده‌شده برای کار با نوع‌های سفارشی، [تطبیق الگو][pattern-matching] است:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
