# استثنا

بعضی روال‌ها نمی‌توانند پاسخ دهند. `count_of` وقتی `prop`ی خواسته می‌شود که روی میز نیست، هیچ عددی برای دادن ندارد؛ و صفر دروغ می‌بود، چون صفر یعنی «از این‌ها هیچ‌کدام را نداریم»، نه «چنین چیزی وجود ندارد».

یک **«استثنا»** روشی است که یک روال با آن می‌گوید نمی‌تواند پاسخ دهد.

## پرتاب استثنا

`raise` روال را رها می‌کند و مقداری را به هر کس که آن را فراخوانی کرده است تحویل می‌دهد.

```sather
   count_of(props : FMAP{STR,INT}, prop : STR) : INT is
      if ~props.has_ind(prop) then
         raise "Unknown prop: " + prop;
      end;
      return props.get(prop);
   end;
```

هیچ چیزی بعد از `raise` اجرا نمی‌شود. روال بازنمی‌گردد، پس پاسخی برای بررسی وجود ندارد و فراخوانی‌کننده نمی‌تواند طوری ادامه دهد که گویی پاسخی وجود دارد.

مقداری که پرتاب می‌شود معمولاً رشته‌ای است که می‌گوید چه اشکالی پیش آمده است.

## گرفتن استثنا

`protect` قطعه‌ای کد را اجرا می‌کند و آماده است که آن کد استثنا پرتاب کند.

```sather
   protect
      taken ::= count_of(props, prop);
      #OUT + "There are " + taken;
   when $STR then
      #OUT + "Cannot: " + exception.str;
   end;
```

اگر چیزی پرتاب نشود، بخش بعد از `protect` اجرا می‌شود و شاخه‌ی `when` نادیده گرفته می‌شود. اگر چیزی پرتاب شود، بقیه‌ی بخش `protect` رها می‌شود و در عوض `when` متناظر اجرا می‌شود.

`when $STR then` یک رشته‌ی پرتاب‌شده را می‌گیرد. `exception` همان مقداری است که پرتاب شد و داخل شاخه در دسترس است.

## عبور کردن

روالی که استثنایی را نمی‌گیرد، لازم نیست کار خاصی درباره‌ی آن انجام دهد. استثنا به سمت بیرون و از میان همه‌ی فراخوانی‌کننده‌ها پیش می‌رود تا اینکه چیزی آن را بگیرد:

```sather
   take_one(props : FMAP{STR,INT}, prop : STR) : INT is
      -- If this raises, take_one raises too. Nothing here says so.
      have ::= count_of(props, prop);
      ...
   end;
```

نکته‌ی استثناها همین است. روالی که مشکل را می‌بیند و روالی که می‌داند با آن چه باید کرد، معمولاً یکی نیستند و هر روالی که در این میان قرار دارد می‌تواند آن را نادیده بگیرد.
