# مقدمه

در مفاهیم قبلی دیدیم که نوع‌ها در Julia یک سلسله‌مراتب تشکیل می‌دهند که `Any` در بالای آن قرار دارد.

نوع‌های انتزاعی مانند `Number` زیرنوع دارند، اما خودشان را نمی‌توان نمونه‌سازی کرد.
اگر نوع یک متغیر را یک نوع انتزاعی قرار دهید، مقادیر آن متغیر _محدود_ می‌شوند به هر زیرنوعی از آن نوع انتزاعی.
برای مثال:

```julia-repl
julia> x::Number = 3
3
julia> typeof(x)  # one subtype of Number
Int64
julia> x = 4.2
4.2
julia> typeof(x) # another subtype of Number
Float64
julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

این به ما یک شکل انعطاف در محدود کردن ورودی‌های معتبر می‌دهد.

اما فرض کنید بخواهیم یک متغیر هم مقادیر صحیح و هم مقادیر رشته‌ای را بپذیرد؟
این دو نوع در یک شاخه از سلسله‌مراتب نیستند.

می‌توانستیم نوع را `Any` قرار دهیم، یا بگذاریم به‌طور پیش‌فرض همان باشد، اما در آن صورت کنترل کامل نوع‌های مجاز را از دست می‌دهیم.

برای رویکردی بهتر، «نحوه‌ی نگارش `Union{ }`» را داریم که دو یا چند نوع داخل آکولادهای آن فهرست می‌شوند.

```julia-repl
julia> y::Union{Integer, String} = 4
4
julia> typeof(y)
Int64
julia> y = "works"
"works"
julia> typeof(y)
String
julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

مثال دیگری همان اجتماع نوع را در امضای یک تابع به کار می‌برد:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}
julia> f(z::IntOrString) = z^3
f (generic function with 1 method)
julia> f(2) # integers are cubed
8
julia> f("ab") # strings are repeated 3 times
"ababab"
```

اینجا به آن نوع یک اسم دادیم که می‌تواند کوتاه‌نویسی راحتی فراهم کند، اما اکیداً ضروری نیست.
تابع `g(z::Union{Integer, String}) = z^3` به همان شکل رفتار می‌کند.

در مفهوم Multiple Dispatch حرف‌های بسیار بیشتری درباره‌ی امضای توابع خواهیم داشت.

## اجتماع نوع‌ها با nothing

چندین زبان دیگر نوع‌هایی دارند که ممکن است مقدار داشته باشند یا نه، با اسم‌هایی مانند `Option`، `Nullable` یا `Maybe`.

Julia نحوه‌ی نگارش خاصی برای این کار ندارد، اما اجتماع نوع‌ها تعمیمی از همان ایده است.

در مفهوم `Nothingness` دیدیم که Julia راه‌های گوناگونی برای نمایش مقادیر ناموجود دارد، از جمله `nothing` و `missing`.
هر یک از اینها را می‌توان در یک اجتماع نوع گنجاند.

برای مثال، در تعریف نوعی لیست پیوندی، به راهی نیاز داریم که اگر گره‌ی دیگری نبود، لیست را پایان دهیم.
`Nothing` نوعی است که تنها مقدارش `nothing` است، و این تعریف `Node` امکان می‌دهد پایان زنجیره را علامت دهیم:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

به همین ترتیب، می‌توان `missing` را به عنوان جای‌نگهدار مقادیر غایب به کار برد، به‌ویژه در مجموعه‌هایی مانند بردارها.
مثال زیر بسیار ساختگی است، اما مقادیر missing در مجموعه‌داده‌های دنیای واقعی رایج‌اند.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)
julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
