بسیاری از قابلیت‌های عبارت‌های باقاعده در Base R تعبیه شده‌اند و ممکن است نمونه‌هایی از آن‌ها را در کدهای قدیمی‌تر ببینید.

برای کدهای جدید، _به‌شدت_ توصیه می‌شود از کتابخانه‌ی [`stringr`][web-stringr] استفاده کنید.

همان‌طور که در [مفهوم رشته‌ها][concept-strings] اشاره شد، `stringr` مستندات خوبی دارد که معمولاً خودِ نویسنده(ی) بسته آن را نوشته است.

- یک [وب‌سایت مرجع][web-stringr]
- یک [برگه‌ی تقلب][cheat-stringr].
- یک [فصل رشته‌ها][book-strings] و یک [فصل عبارت‌های باقاعده][book-regex] در «R for Data Science».

بسیاری از توابعی که پیش‌تر در مفهوم [`Strings`][concept-strings] بحث شدند، به‌طور استاندارد برای جست‌وجوهای عبارت باقاعده طراحی شده‌اند.

ما مفهوم رشته‌ها را نسبتاً ساده نگه داشتیم و فقط روی رشته‌های ثابت تطبیق انجام دادیم، اما در عوض می‌توان از هر الگوی عبارت باقاعده‌ای استفاده کرد.

به‌طور رسمی، یک عبارت باقاعده در R با فراخوانی [`regex()`][ref-regex] ساخته می‌شود.
برای راحتی، توابع `stringr` هر رشته‌ی الگو را به‌عنوان یک عبارت باقاعده در نظر می‌گیرند.
در مثال زیر، اولین `str_replace_all()` یک شکر نحوی برای نسخه‌ی دوم است:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[برگه‌ی تقلب][cheat-stringr] راهنمای مفیدی است: همه‌ی توابعی که آرگومان `pattern` دارند (با رنگ قرمز چاپ شده‌اند) یک عبارت باقاعده می‌پذیرند و صفحه‌ی ۲ خلاصه‌ای از نحوه‌ی نگارش عبارت‌های باقاعده را ارائه می‌دهد.

توجه داشته باشید که تابع [`regex()`][ref-regex] همچنان می‌تواند مهم باشد اگر بخواهید مقادیر پیش‌فرض را بازنویسی کنید، مثلاً حساسیت به بزرگی و کوچکی حروف یا محیط زبانی.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

بسیاری از کدهای عبارت باقاعده شامل بک‌اسلش هستند، مانند `\s` که در بالا استفاده شد.
در رشته‌های معمولی R، `\` باید با دو برابر کردن escape شود، از این رو `"\\s"`.

بک‌اسلش‌ها می‌توانند زیاد شوند و گیج‌کننده شوند، بنابراین در موارد پیچیده ممکن است استفاده از [رشته‌های خام][book-raw] کمک کند.

به‌طور پیش‌فرض، نحوه‌ی نگارش تعریف یک رشته‌ی خام `r"( )"` است، اما جداکننده‌های دیگری هم مجازند.
از آنجا که هم پرانتزها `( )` و هم کروشه‌ها `[ ]` در نحوه‌ی نگارش عبارت‌های باقاعده رایج‌اند (برای گروه‌های ثبت و گروه‌های گزینه)، آکولادها `{ }` ممکن است انتخاب خوبی باشند.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## تشخیص تطبیق‌ها

در ادامه چند پرسش و توابعی آمده است که می‌توانند در پاسخ دادن به آن‌ها کمک کنند.

برخی مثال‌ها از [`fruit`][ref-fruit] استفاده می‌کنند، یک بردار از ۸۰ اسم میوه که همراه `stringr` برای تمرین گنجانده شده است.

_آیا یک رشته شامل یک تطبیق است؟_
[`str_detect()`][ref-str_detect]، یا [`str_starts()`][ref-str_starts]، `str_ends()` تا نیازی به استفاده از لنگرهای `^` یا `$` نباشد.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_آیا فقط رشته‌های حاوی یک تطبیق بازگردانده شوند؟_
از [`str_subset()`][ref-str_subset] برای گرفتن خود رشته‌ها و از `str_which()` برای گرفتن اندیس‌ها استفاده کنید.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_چند تطبیق در هر رشته وجود دارد؟_
[`str_count()`][ref-str_count]

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_تطبیق کجاست؟_
[`str_view()`][ref-str_view] برای استفاده‌ی تعاملی، [`str_locate()`][ref-str_locate] یا `str_locate_all()` به‌طور کلی‌تر.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## ثبت‌ها

معمولاً می‌خواهیم بدانیم که _چه چیزی_ تطبیق می‌دهد.
این کار با گنجاندن «گروه‌های ثبت» داخل پرانتز در عبارت باقاعده انجام می‌شود.

می‌توان در همان عبارت باقاعده با استفاده از `\1`، `\2` و غیره به ثبت‌ها ارجاع داد.
برای مثال، یافتن جفت‌های تکراری از حروف:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

با نحوه‌ی نگارش مشابه، می‌توان از ثبت‌ها در رشته‌های جایگزینی استفاده کرد:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

برای پردازش بعدی، تطبیق‌ها را با تابع [`str_match()`][ref-str_match] فقط برای اولین تطبیق، یا با `str_match_all()` برای همه‌ی تطبیق‌ها جمع‌آوری کنید.

گروه‌های ثبت در هر زبانی تمایل دارند خروجی پیچیده‌ای تولید کنند.
رویکرد R (_که به‌عنوان یک چالش اضافه، برداری‌شده هم هست_) این است که از `str_match()` یک ماتریس تولید کند، با یک سطر برای هر رشته‌ی ورودی، ستون ۱ شامل کل رشته‌ی تطبیق‌خورده و ستون‌های باقیمانده شامل گروه‌های ثبت مختلف.

استفاده از گروه‌های نامدار می‌تواند مزیتی باشد، چون به اسم ستون‌ها در ماتریس نتایج تبدیل می‌شوند.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

در این برنامه‌ی درسی زیاد درباره‌ی ماتریس‌ها صحبت نکرده‌ایم، هرچند یک [سند مفهومی][concept-matrices-arrays] وجود دارد که می‌توانید به آن دسترسی داشته باشید.
ماتریس‌ها با اکوسیستم Tidyverse چندان سازگار نیستند، با اینکه مدت زیادی بخشی از Base R بوده‌اند.

به‌طور خلاصه: با ماتریس‌ها مثل بردارهایی با ۲ اندیس رفتار کنید، به ترتیب `[rows, cols]`.
هر کدام از اندیس‌ها را خالی بگذارید تا کل سطر/ستون را بگیرید.

وقتی یک سطر تنها `r` را با `m[r,]` یا یک ستون تنها `c` را با `m[, c]` می‌گیرید، مقدار بازگردانده‌شده به‌طور پیش‌فرض به یک بردار تخت می‌شود.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```

به‌ناچار، [`str_match_all()`][ref-str_match] خروجی‌ای با ساختار حتی بیشتری تولید می‌کند:

- نتیجه یک لیست است، با یک عنصر برای هر رشته‌ی ورودی.
- اگر فقط یک رشته‌ی ورودی وجود داشته باشد، خروجی را با اندیس‌گذاری `[[1]]` از لیست خارج کنید، همان‌طور که در [مفهوم لیست‌ها][concept-lists] توضیح داده شده است.
- هر عنصر یک ماتریس است، با ستون‌هایی مانند `match()`.
- هر سطر در ماتریس یک ثبت موفق است.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

البته، تطبیق‌ها می‌توانند شکست بخورند.
در این صورت نتیجه مقدار ویژه‌ی `NA` خواهد بود.
آماده باشید که این را بررسی کنید، همان‌طور که در [مفهوم نیستی][concept-nothingness] توضیح داده شده است.

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
