# مقدمه

## کامنت

مسیر x86-64 در Exercism از **NASM** (The Netwide Assembler) به‌عنوان اسمبلر خود استفاده می‌کند.
در NASM، کامنت‌ها با یک نقطه‌ویرگول (`;`) شروع می‌شوند.

کامنت‌ها را می‌توان هر جایی در برنامه قرار داد و هر چیزی که بعد از یک `;` بیاید توسط اسمبلر نادیده گرفته می‌شود.

## ثابت

می‌توان یک ثابت زمان اسمبل را در NASM با **equ** تعریف کرد.
برای نمونه، این کد یک ثابت به نام `UNIVERSE` با مقدار `42` تعریف می‌کند:

```x86asm
UNIVERSE equ 42
```

ثابت‌ها یک بار، هنگام تعریف، ارزیابی می‌شوند و بعداً _نمی‌توان_ دوباره تعریفشان کرد.

## رجیسترهای همه‌منظوره (GPRs)

در اسمبلی، به‌جای متغیرها، معمولاً از رجیسترها برای ذخیره‌ی مقادیر استفاده می‌کنیم.
یک **رجیستر پردازنده** قطعه‌ای از حافظه‌ی سریع درون پردازنده‌ی رایانه است.
بیشتر محاسبات در رجیسترهای پردازنده انجام می‌شوند.

از برخی از این رجیسترها برای انواع محاسبات مختلف استفاده می‌شود و به آن‌ها **رجیسترهای همه‌منظوره (GPRs)** می‌گویند.
بقیه کاربردهای ویژه یا اختصاصی دارند.

در x86-64، ۱۶ رجیستر ۶۴ بیتی همه‌منظوره (GPRs) وجود دارد که می‌توان به آن‌ها به‌صورت ۳۲ بیتی، ۱۶ بیتی یا ۸ بیتی هم دسترسی داشت.
این رجیسترها در ادامه توضیح داده شده‌اند، که در آن `n` در `rn` از ۸ تا ۱۵ متغیر است: `r8`، `r9`، `r10`، `r11`، `r12`، `r13`، `r14` و `r15`.

| ۶۴ بیتی | ۳۲ بیتی | ۱۶ بیتی | ۸ بیتی |
| :----: | :----: | :----: | :---: |
|  rax   |  eax   |   ax   | ah/al |
|  rbx   |  ebx   |   bx   | bh/bl |
|  rcx   |  ecx   |   cx   | ch/cl |
|  rdx   |  edx   |   dx   | dh/dl |
|  rsi   |  esi   |   si   |  sil  |
|  rdi   |  edi   |   di   |  dil  |
|  rbp   |  ebp   |   bp   |  bpl  |
|  rsp   |  esp   |   sp   |  spl  |
|   rn   |  rnd   |  rnw   |  rnb  |

وقتی از کمتر از ۶۴ بیت استفاده می‌کنید، بیت‌های دسترسی‌یافته معمولاً از بخش پایینی رجیستر هستند.
استثنای این قاعده `ah`، `bh`، `ch` و `dh` هستند که به ۸ بیت بالایی از بخش ۱۶ بیتی رجیستر دسترسی دارند.

نمایش نحوه‌ی دسترسی به بیت‌ها برای رجیستر `rax`:

```
+--------+---------------------------------------+
| 64-bit |                  rax                  |
+--------+-------------------+-------------------+
| 32-bit |                   |        eax        |
+--------+-------------------+---------+---------+
| 16-bit |                             |    ax   |
+--------+-----------------------------+----+----+
| 8-bit  |                             | ah | al |
+--------+-----------------------------+----+----+
```

برخی از این رجیسترها باید در طول فراخوانی توابع حفظ شوند: `rbp`، `rsp`، `rbx`، `r12`، `r13`، `r14` و `r15`.
حفظ نکردن آن‌ها می‌تواند به خطا یا رفتار تعریف‌نشده منجر شود.

بقیه حفظ نمی‌شوند و می‌توان آزادانه از آن‌ها استفاده کرد: `rax`، `rcx`، `rdx`، `rdi`، `rsi`، `r8`، `r9`، `r10` و `r11`.

~~~~exercism/caution
در ادامه‌ی برنامه‌ی درسی، یاد می‌گیرید چگونه رجیسترها را حفظ کنید.
فعلاً فقط از نوع دوم رجیسترها استفاده کنید: `rax`، `rcx`، `rdx`، `rdi`، `rsi`، `r8`، `r9`، `r10` و `r11`.
~~~~

## دستورالعمل

دستورالعمل‌ها قطعه‌هایی از محاسبات هستند که یک پردازنده می‌تواند انجام دهد.
معمولاً شکل زیر را دارند:

```x86asm
name destination, source
```

بنابراین، نام دستورالعمل اول می‌آید، سپس حداقل یک فاصله، بعد عملوند مقصد، یک ویرگول (`,`) و در نهایت یک عملوند مبدأ.
دستورالعمل معمولاً عملوند مبدأ را تغییر نمی‌دهد، فقط عملوند مقصد را تغییر می‌دهد.

هر دو عملوند باید اندازه‌ی یکسانی داشته باشند، مگر اینکه خلاف آن ذکر شود.
برای مثال، اگر عملوند مبدأ ۱۶ بیت داشته باشد، عملوند مقصد هم باید ۱۶ بیت داشته باشد.

برای نمونه، برای ذخیره‌ی یک مقدار در یک رجیستر می‌توانیم از دستورالعمل `mov` استفاده کنیم:

```x86asm
mov rax, rdx  ; rax = rdx
              ; mov is the name, rax is the destination operand and rdx is the source operand
```

قطعه‌کد بالا محتویات تمام ۶۴ بیت `rdx`، یعنی عملوند مبدأ، را در تمام ۶۴ بیت `rax`، که عملوند مقصد این دستورالعمل است، کپی می‌کند.

در بیشتر دستورالعمل‌ها می‌توان از اعداد صحیح ثابت به‌عنوان عملوند مبدأ (اما نه به‌عنوان عملوند مقصد) استفاده کرد:

```x86asm
mov rcx, 42 ; rcx = 42
            ; rcx is the destination operand and 42 is the source operand
```

توجه کنید که نوشتن در یک رجیستر ۳۲ بیتی بیت‌های بالایی را هم پاک می‌کند، بنابراین `mov eax, 42` معادل `mov rax, 42` است.
این موضوع برای رجیسترهای ۱۶ بیتی و ۸ بیتی صادق نیست.

برای عملیات حسابی جمع، تفریق و ضرب می‌توانیم از دستورالعمل‌های `add`، `sub` و `imul` استفاده کنیم:

```x86asm
add rax, rsi ; rax = rax + rsi
imul rax, rdi ; rax = rax * rdi
sub rax, r8 ; rax = rax - r8
```

## تابع

دستورالعمل‌ها در توابع سازمان‌دهی می‌شوند.
همه‌ی توابع در **section .text** فایل مبدأ قرار می‌گیرند.

تعریف یک تابع شامل موارد زیر است:

1. یک برچسب با نام تابع، که بعد از آن `:` می‌آید.
2. دستورالعمل‌هایی که تابع را تعریف می‌کنند.
3. دستورالعمل بازگشت، `ret`.

این مسیر از قرارداد فراخوانی System V AMD64 ABI استفاده می‌کند و شش آرگومان صحیح اول در رجیسترها به تابع پاس داده می‌شوند.
آن‌ها به ترتیب زیر پاس داده می‌شوند: `rdi`، `rsi`، `rdx`، `rcx`، `r8` و `r9`.

یک مقدار صحیح از تابع در رجیستر `rax` بازگردانده می‌شود.

برای فراخوانی یک تابع، از دستورالعمل `call` استفاده می‌کنیم.
یک تابع را می‌توان در هر جایی از همان فایل مبدأ فراخوانی کرد.
برای اینکه یک تابع برای سایر فایل‌های مبدأ قابل مشاهده باشد، باید از دستور `global` استفاده کرد.

برای نمونه، این کد تابع `sum` را تعریف می‌کند:

```x86asm
section .text ; functions are placed here

global sum ; sum is visible to other source files

sum:
    ; first argument is passed in rdi
    ; second argument is passed in rsi
    ; return value is placed in rax

    mov rax, rdi ; rax is now equal to rdi
    add rax, rsi ; rax = rax + rsi

    ret ; function return
```

و این کد تابع `sum` ما را با آرگومان‌های ۳ و ۵ فراخوانی می‌کند:

```x86asm
mov rdi, 3  ; First argument in rdi
mov rsi, 5  ; Second argument in rsi
call sum

; The rax register now contains the value 8 (3 + 5), after sum returns
```
