# مقدمه

دانستن این که نوع یک داده چیست، اغلب برای اجرای روان و بدون خطای کد بسیار مهم است.

JavaScript چندین روش برای بررسی نوع یک مقدار یا شیء دارد.

```exercism/note
سازوکارهای بررسی نوع در JavaScript می‌توانند تا حدی غیرقابل‌اعتماد باشند.

برای ایمنی نوع بیشتر و نوع‌های قوی‌تر، احتمالاً بهتر است از TypeScript استفاده کنید؛ زبانی که روی JavaScript بنا شده است، اما با نحو نوع‌دهی یک زبان با نوع ایستا.
```

## عملگر `typeof`

عملگر `typeof` نوع عملوند خود را برمی‌گرداند.
خروجی رشته‌ای است که با اسم یکی از [انواع داده‌ی اولیه][primitives] مطابقت دارد، به‌جز `"null"`.
همچنین می‌تواند `"function"` یا `"object"` باشد.

```javascript
typeof undefined;
// => "undefined"

typeof true;
// => "boolean"

typeof 42;
// => "number"

typeof 'Hello, World!';
// => "string"

typeof function () {
  return 'Hello, World';
};
// => "function"

typeof [1, 2, 3, 4];
// => "object"

typeof { city: 'Stockholm', country: 'Sweden' };
// => "object"
```

به [دلایل تاریخی][`typeof null` is `"object"`].

## عملگر `instanceof`

برای بررسی نوع یک شیء می‌توانید از عملگر `instanceof` استفاده کنید.
این عملگر بسته به این که آیا عملوند دوم در [زنجیره‌ی پروتوتایپ][prototype chain] عملوند اول قرار دارد یا نه، به یک `boolean` ارزیابی می‌شود.
برای روشن‌تر شدن مطلب، `instanceof` برمی‌گرداند که آیا عملوند اول نمونه‌ای از عملوند دوم یا یکی از کلاس‌های فرزند آن است یا نه.
`instanceof` فقط روی شیءها کار می‌کند.

```javascript
class Beverage {
  // ...
}

// The Coffee class is a child of the Beverage class.
class Coffee extends Beverage {
  // ...
}

const java = new Coffee();

java instanceof Coffee;
// => true

java instanceof Beverage;
// => true
```

````exercism/advanced
کلاس Array متدی به اسم `Array.isArray()` دارد که بررسی می‌کند آیا آرگومانش یک آرایه است یا نه.

در حالی که `instanceof Array` با آرایه‌ای که در قلمروی متفاوت ساخته شده باشد، مانند یک `iframe` در یک صفحه‌ی وب، کار نمی‌کند، `Array.isArray()` کار می‌کند.

دلیلش این است که کلاس Array در هر قلمرو سازنده‌ی متفاوتی دارد و هر `iframe` قلمرو خودش را دارد؛ یعنی تابع موجود در زنجیره‌ی پروتوتایپ متفاوت خواهد بود و همین باعث شکست خوردن `instanceof Array` می‌شود.
`Array.isArray()` می‌تواند این را نادیده بگیرد و بهتر است هر جا ممکن بود همیشه استفاده شود.

همچنین می‌تواند از پس مثبت‌های کاذب هم بربیاید؛ جاهایی که یک شیء در واقع `Array` نیست و فقط `Array` را در زنجیره‌ی پروتوتایپ خود دارد.

```javascript
({ __proto__: Array.prototype }) instanceof Array
// => true

Array.isArray({ __proto__: Array.prototype })
// => false
```
````

## عملگر `in`

عملگر `in` برمی‌گرداند که آیا عملوند اول ویژگی‌ای از عملوند دوم است یا نه.
بررسی نمی‌کند که آن ویژگی مقدار تعریف‌شده‌ای داشته باشد یا نه.
ویژگی‌ای که مقدارش `undefined` تنظیم شده باشد، همچنان با `in` تشخیص داده می‌شود.

```javascript
class Coffee {
  constructor() {
    this.temperature = 'hot';
    this.isDarkMatter = undefined;
  }

  coolDown() {
    this.temperature = 'warm';
  }
}

const espresso = new Coffee();

'temperature' in espresso;
// => true

'color' in espresso;
// => false

'isDarkMatter' in espresso;
// => true
```

````exercism/note
`in` برای ویژگی‌ها و متدهای ارث‌بری‌شده `true` برمی‌گرداند.

```javascript
"coolDown" in espresso
// => true

"constructor" in espresso
// => true
```
````

## تابع `Object.hasOwn()`

متد `Object.hasOwn()` برمی‌گرداند که آیا شیء مشخص‌شده _ویژگی داده‌شده را خودش دارد_ (این ویژگی ارث‌بری نشده است و متد هم نیست).

```javascript
class Coffee {
  constructor() {
    this.temperature = 'hot';
  }

  coolDown() {
    this.temperature = 'warm';
  }
}
const cappuccino = new Coffee();

Object.hasOwn(cappucino, 'temperature');
// => true

Object.hasOwn(cappucino, 'constructor');
// => false

Object.hasOwn(cappucino, 'coolDown');
// => false
```
