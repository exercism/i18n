# درباره

**عدد ممیز شناور** عددی است که می‌تواند بخش کسری داشته باشد، مثل `-1.23` یا `3.1415`.

برای نمایش چنین عددی به‌صورت دنباله‌ای از بایت‌ها، x86-64 از استاندارد [IEEE-754][ieee] استفاده می‌کند.
دو قالب رایج‌تر در این استاندارد، اعداد ممیز شناور با دقت تک و اعداد ممیز شناور با دقت مضاعف هستند.
x86-64 از هر دو پشتیبانی می‌کند.

یک عدد ممیز شناور با دقت تک ۳۲ بیت عرض دارد، در حالی که یک عدد با دقت مضاعف ۶۴ بیت عرض دارد.

~~~~exercism/note
از آنجا که اعداد ممیز شناور تقریبی از تمام اعداد حقیقی هستند، عملیات با آن‌ها ممکن است نتایج نادقیقی به دست دهد.

برای توضیحی مفصل، لطفاً به [پیوست D][guide] از راهنمای محاسبات عددی اوراکل، «آنچه هر دانشمند رایانه باید درباره‌ی حساب ممیز شناور بداند»، مراجعه کنید.

[صفحه‌ی Float Toy][toy] توضیح گرافیکی خوبی دارد از این‌که بیت‌های یک عدد ممیز شناور چگونه به یک مقدار ممیز شناور واقعی تبدیل می‌شوند.

[guide]: https://docs.oracle.com/cd/E19957-01/806-3568/ncg_goldberg.html
[toy]: https://evanw.github.io/float-toy
~~~~

## ثبات‌های XMM

در x86-64، ۱۶ ثبات اختصاصی برای انجام محاسبات ممیز شناور وجود دارد که `xmm0` تا `xmm15` نام دارند.

این ثبات‌ها حداقل ۱۲۸ بیت عرض دارند، اما پردازنده‌های جدیدتر این مقدار را به ۲۵۶ یا ۵۱۲ بیت افزایش می‌دهند.
با این حال، در عمل بیشتر اعداد ممیز شناور فقط از پایین‌ترین ۳۲ بیت یا ۶۴ بیت استفاده می‌کنند، بسته به دقت مورد نظر.

## تبدیل بین اعداد

خانواده‌ای از دستورها برای تبدیل بین قالب‌های عددی وجود دارد: `cvtxx2yy`.

هر دو `xx` و `yy` ثابت نیستند، بلکه جانگهدار هستند:

- `xx` جانگهداری برای نوع عملوند مبدأ است.
- `yy` جانگهداری برای نوع عملوند مقصد است.

این جانگهدار می‌تواند شکل‌های زیادی داشته باشد، از جمله:

| جانگهدار | معنا                  |
| ----------- | --------------------- |
| `si`        | عدد صحیح علامت‌دار        |
| `ss`        | ممیز شناور ۳۲ بیتی |
| `sd`        | ممیز شناور ۶۴ بیتی |

برای مثال:

```x86asm
cvtsi2ss xmm0, eax ; converts a 32-bit signed integer to a single-precision floating-point
cvtsd2si rax, xmm1 ; converts a double-precision floating-point to a 64-bit signed integer
```

توجه کنید که می‌توان یک عدد صحیح ۳۲ بیتی را به یک ممیز شناور ۶۴ بیتی تبدیل کرد یا یک عدد صحیح ۶۴ بیتی را به یک ممیز شناور ۳۲ بیتی.
به همین ترتیب، می‌توان یک ممیز شناور ۳۲ بیتی را به یک عدد صحیح ۶۴ بیتی یا یک ممیز شناور ۶۴ بیتی را به یک عدد صحیح ۳۲ بیتی تبدیل کرد.
به عبارت دیگر، اندازه‌ی دو عملوند در یک `cvtxx2yy` _لازم نیست یکسان باشند_:

```x86asm
cvtsi2sd xmm0, eax ; converts a 32-bit signed integer to a double-precision floating-point
cvtsi2ss xmm0, rax ; converts a 64-bit signed integer to a single-precision floating-point
cvtss2si rax, xmm0 ; converts a single-precision floating-point to a 64-bit signed integer
cvtsd2si eax, xmm0 ; converts a double-precision floating-point to a 32-bit signed integer
```

وقتی نتوان عدد ممیز شناور را دقیقاً به‌صورت یک عدد صحیح بیان کرد، `cvtxx2si` عدد را بر اساس کنترل گرد کردن در یک ثبات ویژه به اسم `mxcsr` گرد می‌کند.
این می‌تواند گرد کردن به نزدیک‌ترین، گرد کردن به پایین، گرد کردن به بالا یا قطع کردن باشد.
هیچ پیش‌فرض تضمین‌شده‌ای هنگام ورود به تابع وجود ندارد.

توجه کنید که یک نتیجه‌ی دقیق گرد نمی‌شود و بنابراین تحت تأثیر کنترل گرد کردن قرار نمی‌گیرد.
برای نمونه، `42.0` _همیشه_ به `42` تبدیل می‌شود.

خانواده‌ی مشابهی از دستورها با قالب `cvttxx2si` (با یک `t` اضافه) وجود دارد که همیشه نتیجه را قطع می‌کند.

## گرد کردن

خانواده‌ی دستور `roundxx` یک ممیز شناور در عملوند مبدأ را به یک ممیز شناور گردشده که در عملوند مقصد ذخیره می‌شود تبدیل می‌کند.

در اینجا، مثل همیشه، `xx` جانگهداری برای نوع عملوندها است: `ss` برای ممیز شناور با دقت تک و `sd` برای ممیز شناور با دقت مضاعف.

این دستورها یک عدد ثابت را به عنوان عملوند سوم می‌گیرند.
این عدد حالت گرد کردن را مشخص می‌کند:

| عدد | حالت          |
| :----- | :----------- |
| 0      | نزدیک‌ترین      |
| 1      | کف (پایین) |
| 2      | سقف (بالا)    |
| 3      | قطع کردن     |

برای مثال:

```x86asm
roundss xmm0, xmm1, 1 ; this rounds down (takes the floor) a 32-bit floating-point in xmm1 and stores it in xmm0
roundsd xmm2, xmm2, 2 ; this rounds up (takes the ceil) a 64-bit floating-point in xmm2 and stores it in xmm2
```

از آنجا که این دستورها نتیجه‌ی دقیقی تولید می‌کنند، می‌توانند در آماده‌سازی برای یک `cvtxx2si` استفاده شوند.

## دستورهای محاسباتی

بسیاری از عملیات با اعداد ممیز شناور از دستورهایی استفاده می‌کنند که نامی مشابه معادل‌شان برای اعداد صحیح دارند، اما جانگهدار لازم (`ss` یا `sd`) به آخرشان اضافه شده است.
این دستورها دو عملوندی هستند، با معناشناسی معمول، حتی آن‌هایی که ضرب یا تقسیم انجام می‌دهند:

```x86asm
addss xmm1, xmm2 ; xmm1 = xmm1 + xmm2 (all 32-bit floating-point)
mulsd xmm4, xmm5 ; xmm4 = xmm4 * xmm5 (all 64-bit floating-point)
divss xmm0, xmm3 ; xmm0 = xmm0 / xmm3 (all 32-bit floating-point)
```

## انتقال

دستورهای انتقال از یک ثبات XMM به ثباتی دیگر `movss` یا `movsd` هستند:

```x86asm
movss xmm1, xmm0 ; this copies a 32-bit floating-point from xmm0 to xmm1
movsd xmm6, xmm4 ; this copies a 64-bit floating-point from xmm4 to xmm6
```

انتقال یک مقدار فوری (یک عدد صحیح ثابت علامت‌دار) به یک ثبات xmm به‌طور مستقیم **ممکن نیست**.
این عدد ابتدا باید به یک ثبات همه‌کاره منتقل شود و سپس با استفاده از `cvtsi2xx` تبدیل شود:

```x86asm
mov rax, 10        ; rax is a 64-bit integer with value 10
cvtsi2sd xmm0, rax ; xmm0 is a 64-bit floating-point with value 10.0
```

## مقایسه‌ها

دو گروه دستور برای مقایسه‌ی دو عدد ممیز شناور وجود دارد.
این‌ها به شکل `comixx` و `ucomixx` هستند، که `xx` یا `ss` است یا `sd`.
هر دو مثل همیشه پرچم‌هایی را در `rflags` تنظیم می‌کنند و از همان معناشناسی `cmp` پیروی می‌کنند.

تفاوت آن‌ها این است که `ucomixx` اگر یکی از دو عدد ممیز شناور مقدار `NaN` داشته باشد، پرچم `parity flag (PF)` را تنظیم می‌کند، در حالی که `comixx` در این حالت یک استثنا ایجاد می‌کند.

مقایسه بین مقادیر ممیز شناور _بدون علامت_ است:

```x86asm
ucomisd xmm0, xmm1
ja .greater         ; 'ja' must be used for "greater", not 'jg'
jb .lesser          ; 'jb' must be used for "lesser", not 'jl'
```

## دستورهای دیگر

دستورهای بسیار بیشتری برای کار با اعداد ممیز شناور وجود دارد که عملیات رایج را پیاده‌سازی می‌کنند.
برخی از آن‌ها عبارت‌اند از:

| دستور | توضیح                                      |
| :---------- | :----------------------------------------------- |
| `sqrtxx`    | جذر را محاسبه می‌کند (`sqrt(x)`)                 |
| `rcpss`     | معکوس را محاسبه می‌کند (`1/x`)                      |
| `rsqrtss`   | معکوس جذر را محاسبه می‌کند (`1/sqrt(x)`) |
| `minxx`     | کمینه را محاسبه می‌کند (`min(x, y)`)                   |
| `maxxx`     | بیشینه را محاسبه می‌کند (`max(x, y)`)                   |

هر جا از جانگهدار `xx` استفاده شود، می‌تواند مثل همیشه به شکل `ss` یا `sd` باشد.
اما `rcpss` و `rsqrtss` فقط با اعداد ممیز شناور با دقت تک کار می‌کنند.

این دستورها همه دو عملوندی هستند.

## قرارداد فراخوانی

در System V ABI، هشت آرگومان ممیز شناور اول به ترتیب، از `xmm0` تا `xmm7`، به توابع پاس داده می‌شوند.
مقادیر ممیز شناور از توابع در `xmm0` و در صورت لزوم در `xmm1` برگردانده می‌شوند.

همه‌ی ثبات‌های `xmm` آزادانه برای استفاده در دسترس هستند و هیچ‌کدام برای فراخواننده رزرو نشده است.

## حافظه

مقادیر ممیز شناور را می‌توان در حافظه با همان معناشناسی اعداد صحیح هم‌اندازه تعریف کرد.
NASM (اسمبلر Netwide، اسمبلری که این مسیر از آن استفاده می‌کند) همچنین اعلام مقادیر ممیز شناور را در نماد علمی مجاز می‌داند.

```x86asm
section .data
    pi dq 3.141592653589793 ; this is a double-precision floating-point value
    exp_num dd 1.e5 ; this is a single precision floating-point value equal to 1 * 10⁵
    exp_num2 dd 1.e+5 ; this is a single precision floating-point value equal to 1 * 10⁵
    frac dq 1.e-10 ; this is a double precision floating-point value equal to 1 * 10⁻¹⁰, i.e., 0.0000000001
```

## AVX/AVX2

افزونه‌های AVX/AVX2 در معماری x86-64 شکل‌های جدید سه‌عملوندی را برای دستورهای ممیز شناور معرفی می‌کنند که مقصد را از مبدأها جدا می‌کنند.
این‌ها یک پیشوند `v` (به معنی _برداری_) می‌گیرند تا از شکل قدیمی SSE که در بالا دیدیم متمایز شوند:

```x86asm
vaddss xmm0, xmm1, xmm2 ; xmm0 = xmm1 + xmm2 (32-bit floating-point)
vmulsd xmm2, xmm3, xmm4 ; xmm2 = xmm3 * xmm4 (64-bit floating-point)
```

در این مسیر، ما خود را به دستورها و ثبات‌های تا افزونه‌های پیشین SSE محدود کرده‌ایم.
این مقدار برای آموزش مبانی کافی است و سازگاری با طیف گسترده‌ای از پردازنده‌ها را تضمین می‌کند.

با این حال، اجراکننده‌ی تست به‌طور کامل از AVX و AVX2 پشتیبانی می‌کند.
