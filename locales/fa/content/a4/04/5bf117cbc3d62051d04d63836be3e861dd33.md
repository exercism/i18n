# درباره

Elm زبانی دلپذیر برای ساخت برنامه‌های وب قابل‌اعتماد است.
پیام‌های خطای دوستانه، کارایی عالی، حجم خروجی کم و هیچ استثنای زمان اجرایی ندارد.

احتمالاً مشهورترین بخش Elm، و بخشی که بیش از همه از آن کپی شده، معماری Elm است؛ الگویی ساده برای ساختاردهی به برنامه‌های وب که همه‌ی برنامه‌های وب Elm با آن نوشته می‌شوند.

ایده‌ی اصلی این است که کد شما حول یک `Model` از وضعیت برنامه‌تان، راهی برای `update` کردن مدل و راهی برای `view` کردن مدل ساخته می‌شود.

`Model` وضعیت برنامه را در خود دارد، یعنی همه‌ی داده‌ای که برنامه به آن نیاز دارد.
می‌تواند هر نوعی باشد، اما در هر برنامه‌ی کاربردی معمولاً یک [رکورد][record] است.
اگر برنامه‌ای ساده با یک کادر متن و متنی که معکوس آن متن را نشان می‌دهد در نظر بگیرید، مدل چیزی شبیه زیر خواهد بود.
این مثال را در [راهنمای Elm][elm-guide-text-fields] هم می‌توانید ببینید.

```elm
type alias Model =
  { text : String
  }
```

`update` تابعی است که هنگام رخ دادن تغییری (مثلاً کلیک کاربر روی یک دکمه) با یک `Msg` فراخوانی می‌شود.
این تابع `Msg` و `Model` فعلی را می‌گیرد و یک `Model` جدید برمی‌گرداند.
`Msg` می‌تواند هر نوعی باشد، اما معمولاً یک [نوع سفارشی][custom-type] است.

```elm
type Msg
  = TextChanged String

update : Msg -> Model -> Model
update msg model =
  case msg of
    TextChanged newText ->
      { model | text = newText }
```

مانند همه‌ی انواع سفارشی، گونه‌های `Msg` می‌توانند هر مقدار اطلاعات دلخواهی که لازم دارند را در خود جای دهند.
در مثال بالا گونه‌ی `TextChanged` یک `String` را شامل می‌شود.

`view` تابعی است که HTMLی را برمی‌گرداند که باید در مرورگر به کاربر نمایش داده شود.
`Model` فعلی را می‌گیرد و یک `Html Msg` برمی‌گرداند (نوعی که Elm برای نمایش HTML از آن استفاده می‌کند).
هر عنصر HTML (مثلاً `<div>`) تابع متناظری در Elm دارد (`Html.div`) که در بسته‌ی `Html` قرار دارد.
هر یک از این توابع دو پارامتر می‌گیرد: اولی فهرستی از ویژگی‌ها (از بسته‌های `Html.Attributes` و `Html.Events`) و دومی فهرستی از عناصر فرزند (توابعی از بسته‌ی `Html`).
تابع `text` هم وجود دارد که محتوای رشته‌ای HTML را نمایش می‌دهد؛ این تابع فقط یک پارامتر رشته‌ای می‌گیرد، اما در غیر این صورت دقیقاً مانند بقیه‌ی توابع و عناصر بسته‌ی `Html` استفاده می‌شود.

تابع `view` می‌تواند مشخص کند که رویدادهای خاصی، مانند کلیک روی یک دکمه یا ویرایش متن در یک کادر متن، به ایجاد یک `Msg` منجر شوند؛ سپس زمان اجرای Elm از آن برای فراخوانی تابع `update` استفاده می‌کند، `Model` را تغییر می‌دهد و HTML به‌روزرسانی‌شده تولید می‌کند.
در کد زیر این کار با `Html.Events.onInput TextChanged` انجام می‌شود.

```elm
view : Model -> Html Msg
view model =
  Html.div []
    [ Html.input
      [ Html.Attributes.placeholder "Text to reverse"
      , Html.Attributes.value model.text
      , Html.Events.onInput TextChanged
      ]
      []
    , Html.div [] [ Html.text (String.reverse model.text) ]
    ]
```

`Html.Events.onInput` انتظار دارد تابعی (`String -> Msg`) به آن داده شود که از آن برای ساخت `Msg` استفاده می‌کند.
رویدادهای مختلف بسته به اطلاعاتی که می‌توانند فراهم کنند، توابع متفاوتی می‌خواهند؛ مثلاً `Html.Events.onCheck` (برای چک‌باکس‌ها) `Bool -> Msg` می‌خواهد و `Html.Events.onClick` فقط یک `Msg` می‌خواهد.

زبان Elm خالص و تابعی است و امکان هیچ تغییر در جایی وجود ندارد، بنابراین زمان اجرای Elm همه‌ی مواردی را که تغییر می‌کنند مدیریت می‌کند.
می‌توانید همه‌ی [عناصر HTML][html-elements]، [ویژگی‌های عنصر][element-attributes] و [رویدادهای HTML][html-events] مختلف را در رجیستری بسته‌های Elm ببینید.

در Elm می‌توانید ۴ سطح از برنامه‌ی وب بنویسید که به‌تدریج قدرتمندتر و پیچیده‌تر می‌شوند (هرچند Elm زبانی و اکوسیستمی دلپذیر و ساده باقی می‌ماند).
همه‌ی این‌ها در [بسته‌ی Browser][browser-package] تعریف شده‌اند:

- [sandbox][browser-sandbox]: به ورودی کاربر، مانند دکمه‌ها و چک‌باکس‌ها، واکنش نشان می‌دهد
- [element][browser-element]: با دنیای بیرون صحبت می‌کند، با استفاده از HTTP و تعامل با JavaScript
- [document][browser-document]: `<title>` و `<body>` یک صفحه‌ی وب را کنترل می‌کند
- [application][browser-application]: برنامه‌های تک‌صفحه‌ای کامل می‌سازد که مسیریابی و تغییرهای URL را مدیریت می‌کنند

این مفهوم از [sandbox][browser-sandbox] استفاده می‌کند، چون ساده‌ترین است (و به دلیل sandbox بودن، کار با ویرایشگر آنلاین Exercism نسبتاً آسان است).
ماژول ورودی یک برنامه‌ی Elm باید `Main` نام داشته باشد و تابعی که برنامه را می‌سازد باید `main` نام داشته باشد، مانند زیر.

```elm
import Browser
import Html exposing (Html, Attribute, div, input, text)
import Html.Attributes exposing (placeholder, value)
import Html.Events exposing (onInput)

main =
  Browser.sandbox { init = init, update = update, view = view }

init : Model
init =
  { text = "" }

-- Add Model, Msg, update and view here
```

توابع `update` و `view` را قبلاً دیده‌ایم و [sandbox][browser-sandbox] علاوه بر این به تابع `init` هم نیاز دارد تا وضعیت اولیه‌ی `Model` را برگرداند.
