# درباره

## برابری

انواع Elm را می‌توان با [عملگر برابری][equality-operator] `(==)` از نظر «یکسان بودن» بررسی کرد.
عملگر نابرابری `(/=)` است (*نه* `!=` مانند بسیاری از زبان‌ها).

```elm
1 == 2
    --> False

1 /= 2
    --> True
```

هر دو مقداری که مقایسه می‌شوند باید از یک نوع باشند.
عملگر برابری روی مقدارهای ثابت، تاپل‌ها، رکوردها و انواع سفارشی کار می‌کند.
این عملگر برابری ساختاری را بررسی می‌کند، یعنی مقادیر برابر محتوا و ساختار عمیق یکسانی دارند، مستقل از حاشیه‌نویسی نوع یا موقعیت در حافظه.

```elm
(1, 2) == (2, 1)
    --> False

type alias MyRecord = { myInt : Int, myStrings : List String }
a : MyRecord
a = MyRecord (1 + 1) ["hello world"]

type alias MyOtherRecord = { myInt : Int, myStrings : List String }
myStrings =  (String.join " " ["hello", "world"]) :: []
b : MyOtherRecord
b = { myInt = 2, myStrings = myStrings}

a == b
    --> True
```

توجه کنید که *هرگز نباید* توابع را مقایسه کنید، چون این کار باعث می‌شود برنامه در زمان اجرا از کار بیفتد.
اطلاعات بیشتر درباره‌ی این محدودیت [اینجا][equality-operator] است.

## مقایسه‌ها

[عملگرهای مقایسه][comparison-operators] `(<)`، `(<=)`، `(>)`، `(>=)` و توابع `min`، `max`، `compare` روی انواع `comparable` کار می‌کنند.
نوع `comparable` نوعی ویژه است که همه‌ی انواع درون‌ساخت قابل مقایسه را گرد هم می‌آورد: اعداد، نویسه‌ها، رشته‌ها، لیست‌هایی از موارد `comparable` و تاپل‌هایی از موارد `comparable`.
نویسه‌ها بر اساس [کدپوینت‌های یونی‌کد][unicode-codepoint]شان مقایسه می‌شوند.

```elm
1 < 1 + 1
    --> True

'x' < 'X'
    --> False

'互' < '🙏'
    --> True
```

انواع شبیه به دنباله (رشته‌ها، لیست‌ها و تاپل‌ها) به [ترتیب فرهنگ‌نامه‌ای][lexicographic-order] مقایسه می‌شوند.
به‌طور خلاصه، عناصر دنباله به‌ترتیب و دوبه‌دو مقایسه می‌شوند تا اینکه عنصری کوچک‌تر پیدا شود یا یکی از دنباله‌ها تمام شود.

```elm
"abc" < "abz"
    --> True

"abc" < "abcd"
    --> True

"abc" < "b"
    --> True

min [1 , 2, 9000] [10]
    --> [1 , 2, 9000]

min (1, "hello") (3, "bye")
    --> (1, "hello")

min (1, ['a', 'b']) (1, ['A', 'B'])
    --> (1, ['A', 'B'])
```

مقادیر انواع دیگر مانند رکوردها یا انواع سفارشی را نمی‌توان مستقیماً مقایسه کرد.

برخی انواع درون‌ساخت نیاز دارند که محتوایشان `comparable` باشد، مانند کلیدهای `Set` یا `Dict`، چون ساختارشان به یک ترتیب درونی تکیه دارد.
این یعنی انواع سفارشی را نمی‌توان در `Set` ذخیره کرد، هرچند جایگزین‌هایی از سوی جامعه وجود دارد: [`AnySet`][any-set]، [`AnyDict`][any-dict]، [`Sort`][sort] و موارد دیگر.

لیست‌هایی از مقادیر `comparable` را می‌توان با `List.sort` مرتب کرد. همچنین لیست‌هایی از مقادیری که می‌توان به مقادیر `comparable` نگاشت را می‌توان با `List.sortBy` مرتب کرد.
اگر به مرتب‌سازی سلسله‌مراتبی نیاز دارید (مرتب‌سازی بر اساس یک ویژگی و شکستن تساوی با ویژگی دیگر)، می‌توان از تاپل‌ها یا لیست‌ها همراه با `List.sortBy` استفاده کرد (در کنار [جایگزین‌های][sort-by] دیگر)، چون تاپل‌ها و لیست‌ها به ترتیب فرهنگ‌نامه‌ای مرتب می‌شوند.


```elm
List.sort ["hi", "hello", "bye", "goodbye"]
    --> ["bye", "goodbye", "hello", "hi"]

List.sortBy String.length ["hi", "hello", "bye", "goodbye"]
    --> ["hi", "bye", "hello", "goodbye"]

-- sort by length, then alphabetically
List.sortBy (\str -> (String.length str, str)) ["hi", "mum", "hello", "sis", "bye", "dad"]
    --> ["hi", "bye", "dad", "mum", "sis", "hello"]
```

تابع `compare` دو مقدار `comparable` می‌گیرد و یک `Order` برمی‌گرداند.
`Order` نوعی است که در یک عملیات واحد بررسی می‌کند آیا مقداری بزرگ‌تر (`GT`)، برابر (`EQ`) یا کوچک‌تر (`LT`) از دیگری است.

```elm
compare 1 2
    --> LT

compare "" ""
    --> EQ

compare [12] []
    --> GT
```

توابع مقایسه را می‌توان برای انواع دلخواه ساخت و مثلاً برای مرتب‌سازی با `List.sortWith` به کار برد:

```elm
type Color = Red | Green | Blue

compareColors : Color -> Color -> Order
compareColors a b =
  case (a, b) of
    (Red, Red) -> EQ
    (Red, _) -> LT
    (_, Red) -> GT
    (Green, Green) -> EQ
    (Green, _) -> LT
    (_, Green) -> GT
    (Blue, Blue) -> EQ

List.sortWith compareColors [Blue, Red, Green, Green, Blue]
    --> [Red, Green, Green, Blue, Blue]
```
