# تولیدکننده‌ی Test

ترک C# از یک [تولیدکننده‌ی Test](https://exercism.org/docs/building/tooling/test-generators) برای تولید خودکار Testهای تمرین‌های عملی استفاده می‌کند.
تولیدکننده‌ی Test از این واقعیت بهره می‌برد که بیشتر تمرین‌های تعریف‌شده در [مخزن problem-specifications](https://github.com/exercism/problem-specifications/) یک فایل `canonical-data.json` هم دارند که دربردارنده‌ی ورودی‌ها و خروجی‌های Test استانداردشده‌ای است که می‌توان از آن‌ها برای پیاده‌سازی تمرین استفاده کرد.

## گام‌ها

تولیدکننده‌ی Test برای تولید Testهای یک تمرین عملی، این گام‌ها را انجام می‌دهد:

1. Test caseهای تمرین را از فایل `canonical-data.json` آن می‌خواند
2. از فایل `tests.toml` برای کنار گذاشتن و حذف Test caseها استفاده می‌کند
3. Test caseها را با قالب تولیدکننده‌ی تمرین رندر می‌کند
4. قالب رندرشده را با Roslyn فرمت می‌کند
5. قالب فرمت‌شده را در فایل Test تمرین می‌نویسد

### گام ۱: خواندن فایل `canonical-data.json`

تولیدکننده‌ی Test، Test caseها را با استفاده از [فضای نام System.Text.Json](https://learn.microsoft.com/en-us/dotnet/api/system.text.json) از فایل `canonical-data.json` تمرین تجزیه می‌کند.

چون برخی از داده‌های canonical از تودرتویی استفاده می‌کنند، Test case تجزیه‌شده یک فیلد اضافی `path` را هم در بر می‌گیرد که ویژگی‌های `description` عناصر والد و همچنین ویژگی `description` خود Test case را شامل می‌شود.

### گام ۲: کنار گذاشتن Testهای حذف‌شده از فایل `tests.toml`

هر تمرین یک فایل `tests.toml` دارد که می‌توان Testهای تک‌تک را در آن کنار گذاشت یا غیرفعال کرد.
تولیدکننده‌ی Test هر Test caseای را که به‌عنوان حذف‌شده علامت خورده باشد (`include = false`) حذف می‌کند.

### گام ۳: رندر کردن Test caseها

سپس Test caseها (که ممکن است تغییر کرده باشند) به فایل `.meta/Generator.tpl` داده می‌شوند؛ این فایل تعیین می‌کند که Testها بر پایه‌ی همان Test caseها چگونه رندر شوند.

### گام ۴: فرمت کردن قالب رندرشده با Roslyn

سپس قالب رندرشده با [Roslyn](https://github.com/dotnet/roslyn) فرمت می‌شود.
این کار مزایای زیر را دارد:

- تمرین‌ها به‌شکل یکدستی فرمت می‌شوند
- هنگام نوشتن قالب‌ها لازم نیست زیاد نگران فضای خالی و هم‌ترازی باشید

### گام ۵: نوشتن قالب رندرشده در فایل Test تمرین

در پایان، خروجی قالب رندرشده در فایل Test تمرین نوشته می‌شود.

## قالب‌ها

قالب‌ها با استفاده از [کتابخانه‌ی Scriban](https://github.com/scriban/scriban/) رندر می‌شوند.

## رابط خط فرمان

تولیدکننده‌ی Test به دو روش اجرا می‌شود:

1. `bin/update-tests.ps1`: به‌روزرسانی Testهای همه‌ی تمرین‌هایی که قالب تولیدکننده دارند
2. `bin/update-tests.ps1 -e <slug>`: به‌روزرسانی Testهای تمرین مشخص‌شده، در صورتی که قالب تولیدکننده داشته باشد
