# تغییرپذیری

تغییرپذیری ویژگی یک اتصال خاص در Rust است. هر اتصال یا تغییرناپذیر است یا تغییرپذیر. مقدار یک اتصال تغییرناپذیر را نمی‌توان تغییر داد؛ مقدار یک اتصال تغییرپذیر را می‌توان تغییر داد. همه‌ی اتصال‌ها به‌طور پیش‌فرض تغییرناپذیرند.

## اتصال‌ها

اتصال، پیوند میان یک اسم متغیر خاص آن‌گونه که در کد نوشته می‌شود و یک ناحیه‌ی مشخص از حافظه آن‌گونه که در زمان اجرا پدیدار می‌شود است. به‌طور دقیق، اتصال‌ها فقط در زمان کامپایل وجود دارند: پیش از کامپایل، هیچ حافظه‌ای واقعاً تخصیص نمی‌یابد، و پس از کامپایل، کد ماشین به‌جای متغیرهای نام‌دار، صرفاً با آدرس‌های حافظه سر و کار دارد.

اتصال‌ها معمولاً با کلیدواژه‌ی `let` ساخته می‌شوند. علاوه بر این، اتصال‌ها از پارامترهای تابع و در برخی موقعیت‌های دیگر هم ساخته می‌شوند.

اتصال‌ها می‌توانند ویژگی‌های گوناگونی داشته باشند که مهم‌ترینشان تغییرپذیری است. اتصال تغییرپذیر اتصالی است که تغییر دادن مقدار حافظه‌ی متصل به آن مجاز است. Rust تغییرپذیری هر اتصال را به‌طور دقیق ردیابی و اعمال می‌کند تا درستی برنامه‌ها را تضمین کند، و برنامه‌هایی را رد می‌کند که به‌اشتباه می‌کوشند اتصالی را تغییر دهند که باید تغییرناپذیر باشد.

## تغییرپذیری

در عمل، تغییرپذیری اغلب ساده است. با استفاده از کلیدواژه‌ی `mut` در تعریف اتصال، توانایی تغییر مقدار را به دست می‌آورید.

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### تنزل از تغییرپذیر به تغییرناپذیر

همیشه می‌توان یک اتصال را از تغییرپذیر به تغییرناپذیر تنزل داد. این عملیات شفاف است.

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### ارتقا از تغییرناپذیر به تغییرپذیر

به‌طور کلی، هر زمان که مالکیت منتقل شود، می‌توان مقداری را از تغییرناپذیر به تغییرپذیر ارتقا داد.

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

در `(1)`، مالکیت رشته از `x` به `y` منتقل می‌شود و همین به ما اجازه می‌دهد مقدار را به تغییرپذیر ارتقا دهیم.

### تغییرپذیری در پارامترهای تابع

دو روش متفاوت برای تغییرپذیر بودن پارامترهای تابع وجود دارد. روش اول و رایج‌تر شبیه ارسال با ارجاع در C است:

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

در این مثال، تغییرپذیری در سه جا به‌صراحت مشخص شده است. برای کار کردن ارجاع‌های تغییرپذیر، هر سه اعلان تغییرپذیری لازم‌اند.
در `(2)`، اتصال `x` تغییرپذیر اعلان شده است. این اتصال، مالک سطح بالای مقدار است.
در `(3)`، آن مقدار به‌صورت تغییرپذیر قرض گرفته می‌شود تا به تابع `increment` داده شود.
در `(1)`، یک اتصال تغییرپذیر تازه به اسم `n` برای همان ارجاع مناسب ساخته می‌شود.

سبک دیگری هم برای تغییرپذیری پارامتر وجود دارد که کم‌رایج‌تر است، اما گاهی هنوز مفید است. در این سبک، مقدار مالک‌شده است، اما اتصال تغییرپذیر است.

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

این مثال اعلان‌های صریح کمتری لازم دارد، چون در واقع انتقال مالکیت همراه با ارتقای تغییرپذیری درونی است. کار می‌کند چون `i32` نوعی `Copy` است که داده را به‌طور شفاف کپی می‌کند.
در `(1)` اعلان می‌کنیم که `increment_internally` یک `i32` مالک‌شده و تغییرپذیر به اسم `n` را به عنوان پارامتر می‌پذیرد.
در `(2)` اعلان می‌کنیم که `x` اتصالی تغییرناپذیر به مقدار `1` است.
در `(3)` مقدار `x` در جای تازه‌ای از حافظه کپی می‌شود. `x` تغییرناپذیر می‌ماند. `n` تغییرپذیر است.

البته می‌توان این شکل‌ها را ترکیب کرد و اتصالی تغییرپذیر به ارجاعی تغییرپذیر داد (`mut n: &mut i32` و مانند آن)، اما به‌ندرت پیش می‌آید که واقعاً همین خواسته شده باشد.

### تغییرپذیری بدون `let`

چند ساختار در Rust (`if let`، `match` و مانند آن) هم می‌توانند اتصال بسازند. این اتصال‌ها هم می‌توانند تغییرپذیر باشند.

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

این مثال نخست `v = Some(2)` و سپس `v = None` را تولید می‌کند.

## سایه‌اندازی

می‌توان، و اغلب اصطلاحی است، وقتی مقداری دگرگون می‌شود اسم متغیر را دوباره به کار برد، با اعلان دوباره‌ی آن به کمک چند فراخوانی `let`. به این کار سایه‌اندازی می‌گویند.

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

اما این موردی از تغییرپذیری نیست؛ مقادیر اصلی اصولاً هنوز حاضرند. در مورد انواع غیر `Drop`، کامپایلر ممکن است به‌جای تخصیص یک مکان تازه، همان مکان حافظه را تغییر دهد. با این حال، هرگز این کار را در مورد یک نوع `Drop` یا وقتی اتصال قدیمی دوباره استفاده شود انجام نمی‌دهد.

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
