# درباره

`String` و `&str` دو روش بنیادین برای کار با داده‌های متنی در Rust هستند. شناخت ویژگی‌های آن‌ها و اینکه چگونه با هم کار می‌کنند بسیار به کار می‌آید. این سند درباره‌ی نحوه‌ی همپوشانی آن‌ها بحث می‌کند و چند توصیه‌ی پایه‌ای ارائه می‌دهد. `String` یک بردار دارای مالکیت از بایت‌های `u8` است. `String` تغییرپذیر است. `&str` یک ارجاع قرض‌گرفته‌شده به یک برش رشته است. `&str` تغییرناپذیر است.

تلفظ درست `&str` «ref string» است.
`String` نمایشی با کدگذاری UTF-8 و بالقوه تغییرپذیر از دنباله‌ای از نقاط کد یونیکد است.

`&str` نمایی فقط‌خواندنی از یک دنباله‌ی UTF-8 خوش‌ساخت است. چون یک ارجاع است، `Copy` است و می‌توان آن را به اشتراک گذاشت.

در Rust نمی‌توان مانند زبان‌های دیگر روی `String` و `&str` اندیس‌گذاری کرد. برای نمونه، این کار نمی‌کند:

```rust,invalid
let hello = "Hello";
println!("First letter = {}", hello[0]);
```

این موضوع از ویژگی‌های زیر ناشی می‌شود:

- رشته‌ها UTF-8 هستند و واحد بنیادی آن‌ها بایت نیست، بلکه یک نقطه‌ی کد یونیکد است: `char`.
- نقاط کد یونیکد حداکثر ۴ بایت پهنا دارند، اما با پهنای متغیر کدگذاری می‌شوند.
- بنابراین محاسبه‌ی موقعیت `n`اُمین نقطه‌ی کد بدون پیمایش روی نویسه‌های کدگذاری‌شده‌ی واقعی ناممکن است، چون پس از نویسه‌ی اول، موقعیت نویسه‌ی بعدی به پهنای نویسه‌های قبلی بستگی دارد.
- نویسندگان کتابخانه‌ی استاندارد Rust به همین دلیل تصمیم گرفتند خصیصه‌ی `Index` را برای رشته‌ها پیاده‌سازی نکنند: اندیس‌گذاری در یک آرایه‌ی بایتی زمان ثابت می‌برد، اما اندیس‌گذاری در یک رشته ممکن است زمان بسیار زیادی ببرد. این کار اصل کمترین شگفتی را نقض می‌کند.

```rust
let example = "I'm not entirely ASCII! ❤";

let n_chars = example.chars().count();
let final_byte = example.as_bytes()[example.len()-1];

println!("n_chars = {}", n_chars);             // 25
println!("example.len() = {}", example.len()); // 27

println!("final char: {}", example.chars().nth(n_chars-1).unwrap()); // ❤
println!("final byte: {final_byte}");                                // 164
println!("char of final byte: {}", final_byte as char);              // ¤
```

## تبدیل یک `String` به یک `&str`

`String` خصیصه‌ی `Deref<Target=str>` را پیاده‌سازی می‌کند.
این خصیصه در کامپایلر حالت‌های ویژه‌ای دارد: یعنی هر ارجاعی به یک `String` می‌تواند به‌طور خودکار و شفاف به یک `&str` تبدیل اجباری شود.
این موضوع موارد زیر را در پی دارد:

- هر کدی که مثلاً انتظار یک آرگومان `&str` دارد، می‌تواند به‌جای آن یک `&String` بپذیرد.
- هر متدی که برای `&str` پیاده‌سازی شده باشد، روی یک `String` هم می‌تواند فراخوانی شود.

(اگر بخواهید به‌صورت عمومی هر شکلی از ارجاع به یک `str` را بپذیرید، می‌توانید آرگومانی از نوع `impl AsRef<str>` داشته باشید؛ اما معمولاً تعیین نوع آرگومان‌ها به‌صورت `&str` رایج است.)

## تبدیل یک `&str` به یک `String`

راه‌های زیادی برای ساختن یک `String` از یک `&str` وجود دارد:

- `String::from("my str")`
- `"my str".to_string()`
- `"my str".to_owned()`
- `let s: String = "my str".into();`

همه‌ی راه‌های بالا به تخصیص حافظه برای `String` نیاز دارند (روی heap).
به همین دلیل `&str` در no_std در دسترس است اما `String` نیست.

(وقتی در no_std رشته‌ها را دست‌کاری می‌کنید، اغلب از crate [heapless](https://crates.io/crates/heapless) استفاده می‌شود.)

## استفاده از String و `&str` در struct

این بخش درباره‌ی این است که چه زمانی برای فیلدهای struct از `String` یا `&str` استفاده کنیم.
اغلب می‌بینید که structها با `String` به‌جای `&str` برای مقدارهای فیلد تعریف می‌شوند.

```rust
struct Record {
    latitude: f64,
    longitude: f64,
    population: Option<u64>,
    city: String,
    state: String,
}
```

با استفاده از `String`، struct مالک داده‌هاست.
این کار خواندن کد و آموزش آن به تازه‌کارها را آسان‌تر می‌کند.
اما به این معنا هم هست که برای هر فیلد تخصیص حافظه روی heap رخ می‌دهد.
`&str` داده‌های متنی را قرض می‌گیرد، پس عملکرد بهتری دارد، به این قیمت که struct شما باید پارامترهای طول عمر را تعریف کند.
[آموزش crateی csv][csv-tutorial] این ایده‌ها را به‌شکلی عملی و بسیار خوب نشان می‌دهد و توضیح می‌دهد.

## نکته‌های عملکرد

`String`ها روی heap تخصیص می‌یابند، پس استفاده از آن‌ها می‌تواند پرهزینه‌تر باشد.
`&str`ها یک ارجاع مشترک هستند و بنابراین نیازی به تخصیص مکرر ندارند.
