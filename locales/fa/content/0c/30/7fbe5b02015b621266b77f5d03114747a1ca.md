# مقدمه

جاوااسکریپت یک شیء توکار به اسم `Date` دارد که تاریخ و زمان را ذخیره می‌کند و روش‌هایی برای مدیریت آن‌ها فراهم می‌کند.

<!-- prettier-ignore -->
~~~exercism/caution

چون کار کردن با تاریخ‌ها به‌طور کلی دشوار است و چون مدیریت منطقه‌ی زمانی یا بسیار ضعیف است یا اصلاً وجود ندارد، کتابخانه‌های زیادی مثل `moment.js`، `day.js`، `date-fns` و `luxon` به وجود آمده‌اند.

در پروژه‌های خودتان از بسته‌ای منسوخ یا بدون پشتیبان مثل `moment.js` استفاده نکنید و به گزینه‌های مدرن‌تری مثل `luxon` یا [Temporal][mdn-temporal] که هنوز به‌طور گسترده در دسترس نیست تکیه کنید.
این تمرین روی `Date` تمرکز دارد که تا پایان عمر جاوااسکریپت مرتبط باقی خواهد ماند.

[mdn-temporal]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal

## ساخت

یک شیء `Date` نمونه‌ای از کلاس `Date` است.
می‌توان آن را بدون فرستادن هیچ آرگومانی به تابع سازنده ساخت.
نتیجه‌ی این کار یک شیء `Date` است که تاریخ و زمان کنونی را نشان می‌دهد:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### مُهر زمانی یونیکس (عدد)

اگر عددی فرستاده شود، به‌عنوان یک `timestamp` تفسیر می‌شود.
«مُهر زمانی» عددی صحیح است که تعداد **میلی‌ثانیه**های سپری‌شده از **۱ ژانویه‌ی ۱۹۷۰ [UTC][defn-utc]+۰** را نشان می‌دهد.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

ممکن است انتظار داشته باشید که `new Date(0)` «زودترین» شیء تاریخ را بسازد، اما جاوااسکریپت تاریخ را به منطقه‌ی زمانی محلی شما تبدیل می‌کند، یعنی فقط کسانی که در منطقه‌ی زمانی [GMT / با UTC+۰][defn-gmt] هستند واقعاً مقدار [مبدأ یونیکس][defn-unix-epoch] را می‌گیرند.

### مُهر زمانی ISO 8601 (رشته)

می‌توانید یک مقدار رشته‌ای که نماینده‌ی یک تاریخ است به سازنده‌ی `Date` بفرستید.
**تنها** قالبی که در همه‌ی پیاده‌سازی‌ها یکسان است، [نسخه‌ی ساده‌شده‌ی][mdn-date-string-format] چیزی است که به‌عنوان [رشته‌های مُهر زمانی ISO 8601][defn-iso8601] در سطح بین‌المللی شناخته و استاندارد شده است.

یک لحظه از زمان در [UTC][defn-gmt] به این شکل است:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

که در آن جای‌گذاری‌های زیر انجام می‌شود:

| کلید | توضیح                                        | پیش‌فرض |
| ---- | ------------------------------------------- | ------- |
| YYYY | سال تقویمی، در ۴ رقم                         |         |
| MM   | ماه تقویمی، در ۲ رقم                         | 01      |
| DD   | روز تقویمی، در ۲ رقم                         | 01      |
| T    | حرف T به‌صورت تحت‌اللفظی، که تاریخ و زمان را جدا می‌کند | T       |
| HH   | ساعت در قالب ۲۴ساعته، ۲ رقم                  | 00      |
| mm   | دقیقه، ۲ رقم                                 | 00      |
| ss   | ثانیه، ۲ رقم                                 | 00      |
| mss  | میلی‌ثانیه، ۳ رقم                            | 000     |
| Z    | حرف Z به‌صورت تحت‌اللفظی، یا یک اختلاف `+/-HH:mm` |         |

حرف تحت‌اللفظی `Z` نشان‌دهنده‌ی UTC است (بدون منطقه‌ی زمانی، بدون ساعت تابستانی).

چون برای بیشتر اجزا مقدار پیش‌فرض وجود دارد، حذف بخش‌های انتهایی مجاز است:

```text
YYYY-MM-DD
```

به‌طور پیش‌فرض زمانی برابر با 00:00:00.000 است

اگر مُهر زمانی به `Z` ختم نشود و با `+HH:mm` یا `-HH:mm` هم (که نشان‌دهنده‌ی اختلاف منطقه‌ی زمانی است) پایان نیابد، به دلایل تاریخی موارد زیر اعمال می‌شود:

> وقتی اختلاف منطقه‌ی زمانی وجود ندارد، قالب‌های فقط-تاریخ به‌عنوان زمان UTC تفسیر می‌شوند و قالب‌های تاریخ-زمان به‌عنوان زمان محلی تفسیر می‌شوند.
> تفسیر به‌عنوان زمان UTC به دلیل یک خطای تاریخی در مشخصات است که با ISO 8601 سازگار نبود، اما به دلیل سازگاری وب امکان تغییرش نبود.
> به [تجزیه‌گر شکسته، یک مسئله‌ی واقعی وب][ref-broken-parser] نگاه کنید.

### شیء `Date`

از یک شیء تاریخ موجود هم می‌توان به‌عنوان آرگومان سازنده استفاده کرد.
این کار یک کپی از شیء `Date` موجود با همان تاریخ و زمان می‌سازد.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### فرستادن مقادیر تکی اجزای تاریخ و زمان

برای ساختن تاریخی که فقط تاریخ را نشان می‌دهد، سه عدد بفرستید.
و برای ساختن تاریخی که تاریخ و زمان را نشان می‌دهد، ۶ عدد بفرستید.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

مقدار دوم `month` است که از `0` برای ژانویه شروع می‌شود و تا `11` برای دسامبر می‌رسد.

## `Date.parse()`

ممکن است به اشاره‌ها یا ارجاع‌هایی به تابع تجزیه‌ی تاریخ `Date.parse` بربخورید.
چون برای این تابع تنها چند ویژگی تغییرناپذیر (حقیقت) وجود دارد و چون بقیه‌ی پیاده‌سازی مشخص نشده است (و در نتیجه استاندارد نیست)، نباید از آن استفاده کرد.

## دسترسی به اجزای `Date`

روش‌های گوناگونی روی شیءهای تاریخ وجود دارد که اجزای تاریخ را برمی‌گردانند:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

هرکدام از این‌ها یک نسخه‌ی `set` متناظر دارد (مثلاً `setFullYear`) که مقدار را به‌روزرسانی می‌کند.
هر مقدار سرریزی به جزء بعدی منتقل می‌شود:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

برای همه‌ی روش‌ها نسخه‌های UTC وجود دارد که منطقه‌ی زمانی محلی را نادیده می‌گیرند.

## تبدیل از تاریخ

شیءهای `Date` یک روش `getTime()` دارند که مُهر زمانی UNIX را بر حسب میلی‌ثانیه برمی‌گرداند، یعنی تعداد میلی‌ثانیه‌های نیمه‌شب آغاز ۱ ژانویه‌ی ۱۹۷۰ به وقت UTC.
به‌علاوه، روش `toISOString()` در دسترس است تا یک شیء تاریخ را به رشته‌ی مُهر زمانی ISO 8601 تبدیل کند.

## مقایسه‌ی تاریخ‌ها

عملگرهای بزرگ‌تر از (`>`) و بزرگ‌تر یا مساوی (`>=`) و همچنین کوچک‌تر از (`<`) و کوچک‌تر یا مساوی (`<=`) را می‌توان مستقیماً میان دو تاریخ یا میان یک تاریخ و یک عدد به کار برد.
این کار می‌کند چون جاوااسکریپت سعی می‌کند تاریخ را به یک مقدار اولیه تبدیل کند.
