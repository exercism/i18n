# مبانی Unison

## termها و توابع

termها و توابع، واحدهای پایه‌ی نوشتن یک برنامه‌ی Unison هستند.

«term» همان چیزی است که ما آن را یک مقدار ایستا می‌نامیم. با `name = expression` تعریف می‌شود و به‌طور اختیاری می‌توان پیش از آن امضای نوعی به شکل `name : MyType` نوشت. Unison از استنتاج نوع پشتیبانی می‌کند، بنابراین ممکن است ببینید که برای تعریف‌های ساده، امضای نوع حذف شده است.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

توابع Unison به این شکل‌اند: `myFunctionName argument1 argument2 = myImplementation`؛ آن‌ها با اسم تابع شروع می‌شوند و پس از آن، آرگومان‌ها با فاصله از هم می‌آیند.

```
getMax a b = Nat.max a b
```

توابع می‌توانند به‌طور اختیاری امضای نوع داشته باشند. آخرین نوع در سمت راست، همیشه نوع بازگشتی نهایی تابع است و هر آرگومان با پیکان تابع `->` از دیگری جدا می‌شود.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

برای فراخوانی یک تابع، اسم آن را بنویسید و پس از آن آرگومان‌ها را فقط با فاصله جدا کنید.

```
maximum = getMax 1 10
```

هنگام فراخوانی یک تابع، Unison تلاش می‌کند هر چیزی را که بلافاصله در سمت راست می‌آید به‌عنوان آرگومان آن در نظر بگیرد؛ این کار همیشه ترتیب دلخواه ارزیابی تابع را ایجاد نمی‌کند.

فرض کنید می‌خواهیم مقدار `1` را از عبارت زیر به دست آوریم

```
shouldBe1 = getMax 1 10 - 10
```

همان‌طور که نوشته شده است، `shouldBe1` به `0` ارزیابی می‌شود، چون ترتیب ضمنی اعمال تابع `getMax 1 10` است که `10` می‌شود و بعد `10 - 10` که `0` است.

می‌توانید با پرانتز، عبارت را به ترتیب دلخواه عملیات بازگروه‌بندی کنید.

```
shouldBe1 = getMax 1 (10 - 10)
```

## توابع چندخطی

توابع چندخطی در Unison برای مشخص کردن مرزهای کد، از تورفتگی یا بلوک‌های `let` استفاده می‌کنند؛ همان چیزی که به آن «محدوده‌ی واژگانی» می‌گویند.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

هر چیزی که در سطح یکسانی از تورفتگی باشد، محدوده‌ی یکسانی دارد؛ به همین دلیل می‌توانیم در خط آخر به متغیر `newBeginning` ارجاع دهیم.

## فضاهای نام و دستورهای `use`

فضاهای نام روشی برای گروه‌بندی و سازمان‌دهی توابع Unison هستند. می‌توانید آن‌ها را مشابه «پوشه‌ها» در نظر بگیرید. فضاهای نام ساختار و گروه‌بندی منطقی فراهم می‌کنند.

می‌توانید توابع یک فضای نام را با یک دستور `use` به محدوده بیاورید.

فرض کنید تابعی می‌نوشتید که از مقادیر `List` در Unison استفاده می‌کرد. می‌دانید که به توابعی مانند `List.map` و `List.flatMap` نیاز پیدا می‌کنید؛ `List` همان فضای نام است و `map` و `flatMap` توابع‌اند. برای اینکه خودتان را تکرار نکنید، ممکن است تصمیم بگیرید همه چیز را از فضای نام `List` به محدوده‌ی واژگانی تابع خود بیاورید، به این شکل:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

خط `use List` ارجاع‌های `map` و `flatMap` را رفع ابهام می‌کند. می‌توانید درباره‌ی [دستورهای `use` اینجا][use-statements] بیشتر بخوانید.

## کتابخانه‌ی استاندارد Unison

کتابخانه‌ی استاندارد Unison `base` نام دارد. اگر راهنمای شروع سریع را دنبال کرده و یک پایگاه کد به‌صورت محلی ساخته‌اید، کتابخانه‌ی استاندارد باید به‌طور خودکار دانلود شده باشد. می‌توانید مستندات کتابخانه‌ی استاندارد را به‌صورت آنلاین در [Unison Share][unison-share-base] مرور کنید.

## توضیحات و لیترال‌های مستندات

توضیحات در Unison تا حدی ویژگی غیرمعمولی هستند. هنگام نوشتن کد Unison، می‌توانید در فایلی با پسوند `.u` متنی بنویسید که با روش زیر تفسیر نمی‌شود:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_اما_ چون کد Unison به‌صورت هشی از درخت نگارش انتزاعی‌اش ذخیره می‌شود، نه به‌صورت فایل‌های متنی روی فایل‌سیستم، توضیحاتی که «تزئینات» متنیِ یک تابع یا term مشخص در فایل به شمار می‌روند، واقعاً نمی‌توانند ذخیره شوند و برای اشتراک‌گذاری دوباره بازنمایی شوند. اگر می‌خواهید اطلاعاتی به term خود در Unison اضافه کنید که ذخیره شود تا دیگران آن را بخوانند و درک کنند، می‌توانید از یک لیترال مستندات استفاده کنید.

مستندات در زبان برنامه‌نویسی Unison یک مقدار درجه‌یک است. یعنی یک عنصر `Doc` را می‌توان به یک مقدار نسبت داد، آن را به‌عنوان مقدار به تابعی پاس داد، یا به‌عنوان مقدار بازگشتی تابع برگرداند. عناصر لیترال مستندات با دو آکولاد باز و بسته می‌شوند. در ادامه می‌بینیم که چگونه می‌توانیم از عنصر `Doc` به‌عنوان یک توضیح استفاده کنیم.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
