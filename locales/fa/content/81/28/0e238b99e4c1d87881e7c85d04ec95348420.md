# درباره

در Rust، متدها توابعی هستند که برای یک `struct` (یا یک `enum` یا شیء `trait`) تعریف می‌شوند.
این موضوع الگوی فراخوانی را تغییر می‌دهد: به‌جای `frobnicate(foo)`، یک متد به‌صورت `foo.frobnicate()` فراخوانی می‌شود.

متدها شبیه توابع هستند: با کلیدواژه‌ی `fn` اعلام می‌شوند، اسم دارند و می‌توانند پارامتر و مقدار بازگشتی داشته باشند.

برخلاف توابع، پارامتر اول یک متد همیشه `self` است (یا یکی از گونه‌هایش) که نماینده‌ی نمونه‌ای از `struct` است که متد روی آن فراخوانی می‌شود (جزئیات بیشتر در ادامه).

بیایید یک `enum` برای خانه‌های هاگوارتز و یک `struct` بسازیم که `age` و `house` یک جادوگر را توصیف می‌کند:

```rust
#[derive(Debug)]
enum House {
    Gryffindor,
    Hufflepuff,
    Ravenclaw,
    Slytherin,
}

struct Wizard {
    age: u32,
    house: House,
}
```

## تعریف متدها

برای تعریف متدها برای `struct` به اسم `Wizard`، یک بلوک `impl` (خلاصه‌شده‌ی implementation) برای `Wizard` شروع می‌کنیم.

```rust
impl Wizard { }
```

هر چیزی که داخل این بلوک `impl` باشد، به نوع `Wizard` مرتبط می‌شود.
توجه کنید که یک `struct` می‌تواند چندین بلوک `impl` داشته باشد.

### استفاده از `self`

یک متد باید به‌عنوان پارامتر اول، پارامتری به اسم `self` و از نوع `Self` داشته باشد.
نوع `Self` نام دیگری برای نوعی است که بلوک `impl` برای آن نوشته شده است.
در مثال ما، `Self` نماینده‌ی `Wizard` است.

Rust برای راحتی به ما اجازه می‌دهد این را کوتاه کنیم و در جایگاه پارامتر اول فقط اسم `self` را بنویسیم.
انواع رایج `self` برای متدها عبارت‌اند از:

- `self`: خلاصه‌ی `self: Self` است. امضای `self` تنها، نمونه را مصرف می‌کند.
- `&self`: خلاصه‌ی `self: &Self` است. این، نمونه را به‌صورت تغییرناپذیر قرض می‌گیرد.
- `&mut self`: خلاصه‌ی `self: &mut Self` است. این، نمونه را به‌صورت تغییرپذیر قرض می‌گیرد.

در کدهای پیشرفته‌تر ممکن است امضاهایی مثل `self: Pin<&self>`، `self: Rc<Self>` و غیره هم ببینید.
اما این موضوع از دامنه‌ی این آموزش فعلی خارج است.

### تعریف یک متد با `&self`

اگر بخواهیم متدی به اسم `info` پیاده‌سازی کنیم که اطلاعات پایه‌ی جادوگر را نمایش دهد، می‌توانیم این متد را داخل یک بلوک `impl` برای `Wizard` تعریف کنیم:

```rust
impl Wizard {
    fn info(&self) {
        println!(
            "A wizard of age {} who studies in House {:?} at Hogwarts",
            self.age,
            self.house,
        );
    }
}
```

توجه کنید که در امضای `info`، نمونه را با `&self` به‌صورت تغییرناپذیر قرض می‌گیریم.
به این ترتیب، می‌توانستیم فیلدهای `age` و `house` یک نمونه‌ی `Wizard` را بدون تغییر دادنشان بخوانیم.
اگر به‌جای قرض گرفتن از یک `self` مصرف‌کننده استفاده کرده بودیم، نمونه پس از فراخوانی متد غیرقابل‌دسترس می‌شد.

وقتی متد `info` پیاده‌سازی شد، می‌توانستیم اطلاعات پایه‌ی یک جادوگر را چاپ کنیم:

```rust
let harry = Wizard { age: 11, house: House::Gryffindor };
harry.info();
// => A wizard of age 11 who studies in House Gryffindor at Hogwarts
```

### تعریف یک متد با `&mut self`

اگر بخواهیم متدی پیاده‌سازی کنیم که فیلدهای یک نمونه‌ی `struct` را تغییر دهد، در امضای متد، نمونه را با `&mut self` به‌صورت تغییرپذیر قرض می‌گیریم.

فرض کنید می‌خواهیم قانون جدیدی در هاگوارتز وضع کنیم که به دانش‌آموزان اجازه دهد خانه‌شان را عوض کنند.
می‌توانیم متدی به اسم `switch_house` را به این صورت پیاده‌سازی کنیم:

```rust
impl Wizard {
    fn switch_house(&mut self, new_house: House) {
        self.house = new_house;
    }
}
```

حالا می‌توانیم خانه‌ی جادوگری که در هاگوارتز درس می‌خواند را عوض کنیم:

```rust
// Note that the variable must be mutable
let mut cedric = Wizard {age: 14, house: House::Hufflepuff};
cedric.info();
// => A wizard of age 14 who studies in House Hufflepuff at Hogwarts
cedric.switch_house(House::Slytherin);
cedric.info()
// => A wizard of age 14 who studies in House Slytherin at Hogwarts
```

## چندین بلوک `impl`

در Rust، هر مورد می‌تواند چندین بلوک `impl` داشته باشد.
بنابراین می‌توانیم همه‌ی متدها را در یک بلوک `impl` گروه‌بندی کنیم، یا برای گروه‌های مختلف متدها چندین بلوک `impl` داشته باشیم.
هر دو رویکرد از نظر نحوه‌ی نگارش معتبرند، اما سازمان‌دهی معمول پروژه‌ها از یک بلوک `impl` برای هر مجموعه‌ی یکتای قیدهای `where` در سطح `impl` استفاده می‌کند.

## توابع مرتبط

می‌توان توابعی را داخل یک بلوک `impl` تعریف کرد که پارامتر `self` ندارند.
چون پارامتر `self` ندارند، متد محسوب نمی‌شوند.
با این حال، همچنان به نوع پیاده‌سازی‌شده مرتبط‌اند و با نام‌بردن از آن نوع فراخوانی می‌شوند.
به همین دلیل، به آن‌ها «توابع مرتبط» (یا توابع مرتبط با نوع) می‌گویند.

شما قبلاً چند تابع مرتبط دیده‌اید، مثل `String::from()`:

```rust
let some_string = String::from("This is an associated function but not a method");
```

سازنده‌ها اغلب به‌صورت توابع مرتبط پیاده‌سازی می‌شوند.
بیایید تابعی به اسم `new` مرتبط با نوع `Wizard` بسازیم:

```rust
impl Wizard {
    fn new(age: u32, house: House) -> Self {
        Self {
            age,
            house,
        }
    }
}
```

توجه کنید که می‌توانیم به‌جای `Wizard` از `Self` استفاده کنیم تا نوعی را نشان دهیم که از تابع بازگردانده می‌شود.
استفاده از `Self` به‌عنوان نام دیگر نوع به این شکل اجباری نیست، اما می‌تواند پیاده‌سازی را برای انواعی با اسم‌های پیچیده یا طولانی ساده‌تر کند.
حالا می‌توانیم موارد زیر را اجرا کنیم:

```rust
let myrtle = Wizard::new(14, House::Ravenclaw);

myrtle.info();
// => A wizard of age 14 who studies in House Ravenclaw at Hogwarts
```
