# مقدمه

## Iterator

یک `Iterator` در Gleam از این نظر شبیه لیست است که مجموعه‌ی مرتبی از مقادیر است و همه‌ی آن مقادیر از یک نوع‌اند. تفاوتش با لیست این است که «تنبل» است، یعنی همه‌ی مقادیرش را یکجا در حافظه ذخیره نمی‌کند و در عوض آن‌ها را همان وقت که لازم شوند محاسبه می‌کند.

این موضوع هنگام کار با دنباله‌هایی که بسیار بزرگ‌اند یا حتی بینهایت‌اند مفید است، چون اجازه می‌دهد حتی وقتی حافظه‌ی آزاد کافی برای ذخیره‌ی همه‌ی آن‌ها نداریم، با آن‌ها کار کنیم.

ماژول `gleam/iterator` هم نوع `Iterator` را تعریف می‌کند و هم توابعی برای کار با iterator‌ها.

بسیاری از توابع مربوط به لیست‌ها برای iterator‌ها هم وجود دارند، مثل `map`، `filter` و `take`. این توابع خودشان iterator برمی‌گردانند، پس تا زمانی که iterator مصرف نشود، در واقع هیچ کاری انجام نمی‌دهند.

```gleam
let iter = 
  [1, 2, 3, 4, 5, 6]
  |> iterator.from_list
  |> iterator.filter(fn(x) { x > 2 })
  |> iterator.take(2)

// No work has been done yet as the iterator has not been consumed

// Consume the iterator and collect the values into a list
iterator.to_list(iter)
// -> [3, 4]
```

از تابع `unfold` می‌توان برای ساختن iterator از تابعی استفاده کرد که به‌طور مکرر فراخوانی می‌شود تا مقدار بعدی دنباله را تولید کند.

در اینجا از تابع `unfold` برای ساختن iterator‌ی استفاده می‌شود که دنباله‌ی فیبوناچی را تولید می‌کند:

```gleam 
iterator.unfold(#(0, 1), fn(pair) {
  let x = pair.0 + pair.1
  iterator.Next(element: x, accumulator: #(pair.1, x))
})
|> iterator.take(6)
|> iterator.to_list
// -> [1, 2, 3, 5, 8, 13]
```

دنباله‌ی اینجا بینهایت است، پس از تابع `take` استفاده می‌شود تا پیش از جمع‌کردن مقادیر در یک لیست، آن را متناهی کند. اگر `to_list` روی یک iterator بینهایت فراخوانی شود، برنامه آن‌قدر اجرا می‌شود تا حافظه تمام شود و از کار بیفتد.
