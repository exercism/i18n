# مقدمه

## توابع خارجی

Gleam می‌تواند روی ماشین مجازی Erlang (BEAM) یا روی زمان‌های اجرای JavaScript اجرا شود. زبان‌های دیگری هم هستند که از این زمان‌های اجرا استفاده می‌کنند و اغلب مفید است که بتوانیم کدی را که با آن زبان‌ها نوشته شده از Gleam فراخوانی کنیم.

قابلیت «توابع خارجی» در Gleam اجازه می‌دهد توابعی که به زبان‌های دیگر نوشته شده‌اند به Gleam وارد شوند و بدون هیچ سربار زمان اجرا فراخوانی شوند.

اگر پروژه‌ی Gleam شما روی ماشین مجازی Erlang اجرا می‌شود و می‌خواهید تابع `reverse` را از ماژول `lists` در Erlang فراخوانی کنید، می‌توانید ویژگی `@external` را به سر تابع Gleam اضافه کنید، به این شکل:

```gleam
@external(erlang, "lists", "reverse")
pub fn reverse_list(x: List(a)) -> List(a)
```

سپس می‌توان آن را مانند یک تابع معمولی Gleam فراخوانی کرد:

```gleam
let reversed = reverse_list([1, 2, 3])
// -> [3, 2, 1]
```

اگر بخواهید این کد را برای زمان‌های اجرای JavaScript کامپایل کنید، شکست می‌خورد و پیام خطا می‌دهد، چون پیاده‌سازی‌ای برای JavaScript وجود ندارد. می‌توان برای زمان‌های اجرای JavaScript پیاده‌سازی دیگری مشخص کرد، به این شکل:

```gleam
@external(erlang, "lists", "reverse")
@external(javascript, "./my_module.mjs", "reverse")
pub fn reverse_list(x: List(a)) -> List(a)
```

همچنین می‌توان پیاده‌سازی‌ای به زبان Gleam نوشت که وقتی برای هدف کامپایل فعلی پیاده‌سازی خارجی وجود ندارد استفاده شود:

```gleam
@external(erlang, "lists", "reverse")
pub fn reverse_list(x: List(a)) -> List(a) {
  tail_recursive_reverse(x, [])
}

fn tail_recursive_reverse(list, reversed) {
  case list {
    [] -> reversed
    [x, ..xs] -> tail_recursive_reverse(xs, [x, ..reversed])
  }
}
```

## انواع خارجی

انواع خارجی را می‌توان برای اشاره به انواع داده‌ای به کار برد که در زبان‌های دیگری مانند Erlang یا JavaScript تعریف شده‌اند.

برای تعریف یک نوع خارجی، یک نوع اعلام کنید اما هیچ سازنده‌ای ارائه ندهید. سپس می‌توان آن را مانند هر نوع دیگری به کار برد.

```gleam
pub type OrderedDictionary(element)
```
