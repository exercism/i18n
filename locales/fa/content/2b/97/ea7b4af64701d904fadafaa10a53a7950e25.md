# درباره

مجموعه‌های هش، [پروتکل][set-protocol] [`sets`][sets] را با هش‌کردن در پشت صحنه پیاده‌سازی می‌کنند و به‌طور میانگین درج، جست‌وجو و حذف را با هزینه‌ی O(1) انجام می‌دهند. این مجموعه‌ها در جا تغییرپذیرند و همین آن‌ها را برای الگوی *مجموعه‌ی بازدیدشده* در پیمایش گراف ایدئال می‌کند.

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| واژه          | اثر                                    |
|---------------|-------------------------------------------|
| `HS{ }`       | لیترال مجموعه‌ی هش خالی (مشترک است، پس آن را `clone` کنید!) |
| `>hash-set`   | `( seq -- set )`؛ یک مجموعه‌ی تازه از یک دنباله می‌سازد (موارد تکراری را حذف می‌کند) |
| `adjoin`      | `( elt set -- )`؛ درج مخرب     |
| `in?`         | `( elt set -- ? )`؛ بررسی عضویت           |
| `delete`      | `( elt set -- )`؛ حذف مخرب     |
| `cardinality` | `( set -- n )`؛ تعداد عناصر       |
| `null?`       | `( set -- ? )`؛ وقتی مجموعه خالی است «درست» می‌شود |
| `members`     | `( set -- seq )`؛ برشماری به‌صورت دنباله  |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )`؛ تبدیل `set` به کلاس `exemplar` |

برای ساختن یک مجموعه از داده‌هایی که از قبل در اختیار دارید، `>hash-set` هر دنباله‌ای را در یک مرحله تبدیل می‌کند و موارد تکراری را دور می‌ریزد؛ `{ 2 3 2 5 } >hash-set` نتیجه‌ی `HS{ 2 3 5 }` را می‌دهد. این همتای دسته‌جمعیِ بزرگ‌کردن یک مجموعه با `adjoin`های پیاپی است.

نکته‌ای ظریف درباره‌ی `in?` در برابر `member?` (از `sequences`): هر دو عضویت را بررسی می‌کنند، اما `member?` یک پیمایش خطی روی دنباله انجام می‌دهد، در حالی که `in?` کار را به متدی می‌سپارد که نوع مجموعه در پروتکل خود دارد؛ برای `HS{ }` این متد همان جست‌وجو در جدول هش است. هر وقت ظرفِ «بازدید» شما بیش از چند عنصر داشته باشد، از `in?` استفاده کنید.

`null?` پاسخ «آیا این مجموعه خالی است؟» را بدون محاسبه‌ی کل `cardinality` می‌دهد؛ نگهبان طبیعیِ پرسش «آیا هنوز چیزی برای پردازش مانده است؟» همین است. برای یک فهرست کارها که در قالب مجموعه نگه داشته می‌شود، `[ set null? ] [ … ] until` آن را تا خالی‌شدن تخلیه می‌کند.

## هم‌نشینی خوب با جدول‌های هش

`HS{ }` برای پاسخ به «آیا X بازدید شده است؟» به‌طور طبیعی با `H{ }` برای پاسخ به «همسایه‌های X کدام‌اند؟» جفت می‌شود. یک جست‌وجوی اول‌عمق (DFS) کتاب‌درسی چیزی جز این نیست:

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

مجموعه‌ی بازدیدشده کار را یکتا می‌کند؛ پشته گره‌های مرزی را پیش می‌برد (به‌سبک LIFO، یعنی آخرین ورودی و اولین خروجی، با `push`/`pop`)؛ و نگاشت همسایه‌ها (یک جدول هش) گراف را تأمین می‌کند. ترتیب بازدید برای پرسش دسترس‌پذیری مهم نیست و همین دلیل کافی‌بودن یک بردار در نقش پشته است؛ یک جست‌وجوی سطح‌به‌سطح (BFS) واقعی روی همین ساختار، بردار را با [`<dlist>`][dlist] عوض می‌کند و در عوض از سر صف خارج می‌کند.
