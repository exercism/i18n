# درباره

## نمایش، نویسه‌ها و اعداد صحیح

مانند دیگر انواع ساده (`int`ها، `bool`ها و غیره)، `char` یک نوع همراه یا نام مستعار دارد که در این مورد `System.Char` است.

این در واقع یک `struct` با یک فیلد ۱۶ بیتی است و به‌طور پیش‌فرض تغییرناپذیر است.

`char` چند متد نمونه‌ای دارد، مانند `Equals`، `ToString` و [`CompareTo`][compare-to].

`char` همان عرض [`ushort`][uint16] را دارد، اما این دو معمولاً به‌جای یکدیگر به کار نمی‌روند، برخلاف آنچه در برخی زبان‌ها رایج است. برای تبدیل `ushort` به `char` باید صریحاً تبدیل نوع انجام داد.

به هر حال، `char`ها می‌توانند تحت عملیات حسابی قرار بگیرند. نتیجه‌ی این عملیات یک عدد صحیح است.

طبیعتاً میان یک `byte` ۸ بیتی و `char` ۱۶ بیتی هیچ هم‌ارزی‌ای وجود ندارد.

## کاربرد

کار با `char`ها عموماً ساده است.

می‌توان آن‌ها را با کوتیشن تک به‌صورت مقدار ثابت تعریف کرد:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

می‌توان یک `char` تکی را با نمایه‌گذاری (از صفر) از یک رشته استخراج کرد:

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

پیمایش روی یک رشته در هر گام یک `char` برمی‌گرداند:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

همان‌طور که بالا نشان داده شد، می‌توان یک `char` را به مقدار `int` آن تبدیل کرد.
این کار (*دست‌کم در برخی موارد*) برای سایر سیستم‌های نوشتاری هم جواب می‌دهد:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

هنگام مقایسه‌ی نویسه‌ها از Int16 زیربنایی استفاده می‌شود:

```fsharp
'A' < 'D'
// => val it: bool = true
```

همچنین می‌توان یک `int` را به `char` تبدیل کرد:

```fsharp
char 77
// => val it: char = 'M'
```

کتابخانه‌ی `System.Char` مجموعه‌ی کاملِ [متدها][Char-methods]ی را در خود دارد که از یک زبان .NET انتظار می‌رود، مانند تبدیل به حروف بزرگ/کوچک (اما هشدارهای بخش بعد را ببینید):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

کتابخانه‌های .NET به استخراج `char`ها از رشته‌ها کمک می‌کنند، در این مورد متدهای `Seq`:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

راه‌های گوناگونی برای تبدیل یک فهرست (یا آرایه‌ی) نویسه به رشته وجود دارد، از جمله این‌ها:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

اطلاعات کلی درباره‌ی `char`ها را می‌توانید اینجا پیدا کنید:

- [مستندات نویسه‌ها][chars-docs]: مستندات مرجع برای `char`.

با این حال، `char`ها چند ناهمواری دارند که در ادامه به تفصیل آمده است. این ناهمواری‌ها بیشتر به تقابل میان استاندارد کامل یونیکد از یک سو و بازنمایی‌های تاریخی متن و همچنین کارایی و مصرف حافظه از سوی دیگر مربوط می‌شود.

## مسائل یونیکد

هنگام کار با رشته‌ها، اگر متدهای کتابخانه‌ی [`System.String`][System-string] در دسترس هستند، بهتر است به سراغ آن‌ها بروید و از آن‌ها استفاده کنید، نه اینکه رشته را به نویسه‌ها بشکنید.

برخی «نویسه»های متنی از بیش از یک `char` تشکیل شده‌اند، چون استاندارد یونیکد بیش از ۶۵۵۳۶ نقطه‌ی کد دارد. برای نمونه، اموجی‌هایی که در برخی از آزمون‌ها ظاهر می‌شوند ۲ `char` دارند، چون از نویسه‌های [جانشین][surrogates] تشکیل شده‌اند.

علاوه بر این، دنباله‌های ترکیبی هم وجود دارند؛ برای نمونه در برخی موارد یک نویسه‌ی اکسنت‌دار ممکن است از یک `char` برای نویسه‌ی پایه و یک `char` دیگر برای اکسنت تشکیل شود.

اگر ناچار به کار با نویسه‌های تکی هستید، بهتر است از متدهای کتابخانه مانند [`System.Char.IsControl`][is-control] و [`System.Char.IsDigit`][is-digit] استفاده کنید، نه مقایسه‌های ساده‌لوحانه‌ای مثل بررسی اینکه یک نویسه بین '0' و '9' است.

برای نمونه، توجه کنید که '٢' رقم ۲ عربی است. `IsDigit` برای نسخه‌ی عربی مقدار true را برمی‌گرداند، پس هنگام اعتبارسنجی باید مشخص کنید چه بازه‌ای از ورودی‌ها قابل قبول است.

حتی متدهای کتابخانه‌ی `System.Char` هم ممکن است هنگام کار با زبان‌های کمترشناخته‌شده آن‌طور که انتظار دارید رفتار نکنند.

یکی از راه‌های امن شکستن یک رشته به «نویسه»های نمایشی، استفاده از [`StringInfo`][string-info] و متدهایی مانند [`GetNexttextElement`][get-next-text-element] است.
اگر با جهانی‌سازی/بومی‌سازی سر و کار دارید، این کار ممکن است لازم باشد.

راه دیگر، جایی که مقادیر اسکالر نویسه‌های یونیکد اهمیت دارد (مثلاً وقتی سیستم کدگذاری خودتان را می‌سازید)، استفاده از [runes][runes] است. اما اگر می‌دانید بازه‌ی نویسه‌هایی که با آن‌ها سر و کار دارید شامل نویسه‌های جانشین یا دنباله‌های نویسه‌ی ترکیبی نمی‌شود (مثلاً ASCII لاتین) و ورودی‌تان به‌خوبی اعتبارسنجی شده است، می‌توانید از این کار صرف‌نظر کنید.

باز هم، بهترین حالت این است که بتوانید از متدهای کتابخانه‌ی `String` استفاده کنید.

اگر واقعاً در وضعیت ناخوشایند پرداختن به ریزه‌کاری‌های یونیکد قرار گرفتید، [این][char-encoding-net] نقطه‌ی شروع خوبی است.

## جهانی‌سازی

اگر در محیطی کار می‌کنید که با چندین فرهنگ سر و کار دارید، یا فرهنگ در بخش‌هایی از کد مهم است و در بخش‌های دیگر نه، توجه داشته باشید که [`ToUpper`][to-upper] و [`ToLower`][to-lower] نسخه‌های سربارگذاری‌شده‌ای دارند که یک فرهنگ می‌گیرند، و [`ToUpperInvariant`][to-upper-invariant] و [`ToLowerInvariant`][to-lower-invariant] نتیجه‌ی یکسانی مستقل از [فرهنگ][culture-info] جاری ارائه می‌دهند.
