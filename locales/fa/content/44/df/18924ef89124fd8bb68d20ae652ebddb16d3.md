# روال‌های مقید

```sather
   part : ROUT{STR}:STR := bind(shout(_));
   part.call("who's there");
```

## bind

`bind` یک فراخوانی می‌گیرد که در آن هر بخشی می‌تواند با `_` جایگزین شود. هر چیزی که `_` نیست، **همین حالا** ارزیابی و نگه داشته می‌شود؛ هر `_` به آرگومانی از روال مقید تبدیل می‌شود، به همان ترتیبی که نوشته شده است.

```sather
   bind(repeat(2, _))         -- ROUT{STR}:STR
   bind(repeat(_, "Ha"))      -- ROUT{INT}:STR
   bind(repeat(_, _))         -- ROUT{INT,STR}:STR
```

## نوع‌ها

| نوع | می‌گیرد | پاسخ می‌دهد |
| --- | --- | --- |
| `ROUT:INT` | هیچ | `INT` |
| `ROUT{STR}` | یک `STR` | هیچ |
| `ROUT{STR}:STR` | یک `STR` | یک `STR` |
| `ROUT{INT,INT}:BOOL` | دو `INT` | `BOOL` |

`ITER{...}` همان ایده برای یک تکرارگر است.

## call

`call` آرگومان‌های باقی‌مانده را تأمین می‌کند. روال مقیدی که پاسخی نمی‌دهد هم به همین شکل، به‌عنوان یک دستور، فراخوانی می‌شود.

## bind در سمت راست انتساب قرار می‌گیرد

می‌توان یک `bind` را در متغیری اعلان کرد، یا آن را به‌عنوان آرگومان پاس داد:

```sather
   part ::= bind(shout(_));                -- yes
   part : ROUT{STR}:STR := bind(shout(_)); -- yes
   rehearse("line", bind(shout(_)));       -- yes
```

اما نمی‌توان آن را مستقیم داخل یک `return` گذاشت:

```sather
   return bind(shout(_));                  -- does not parse
```

آن را در متغیری بگذارید و همان را برگردانید. پیام خطا به `bind` اشاره می‌کند و از زیرخط‌ها نام می‌برد، که از خودِ خط چندان پیدا نیست.

## کجا به کار می‌روند

کتابخانه آن‌ها را هرجا که باید رفتاری تأمین شود، می‌پذیرد:

```sather
   names.sort_by(bind(shorter(_, _)));
   scores.count_if(bind(over(10, _)));
   scores.find_if(bind(is_even(_)));
```

مرتب‌سازی روشن‌ترین مورد است: `sort_by` می‌داند چطور مرتب کند و هیچ نمی‌داند که تصور شما از ترتیب چیست، و روال مقید همان جایی است که این دو به هم می‌رسند.

## یک محدودیت در این کامپایلر

Sather ۱.۲ روال‌های مقید **dispatched** را پیاده‌سازی نمی‌کند، یعنی مقید کردن یک روال روی متغیری از یک نوع انتزاعی. کامپایلر صریحاً همین را می‌گوید:

```
Dispatched bound routines are not implemented yet
```

روی یک نوع مشخص، یا روی یک کلاس مقید کنید و همه‌چیز خوب است. به همین دلیل است که هارنس آزمون خودِ «track» بررسی‌های استثنای خود را دستی می‌نویسد، نه اینکه یک روال مقید بگیرد.

## روال مقید یا کلاس انتزاعی؟

هر دو این امکان را به فراخواننده می‌دهند که رفتاری را تأمین کند.

روال مقید یک روال است، به هیچ کلاسی نیاز ندارد، و همان‌جا که به کار می‌رود نوشته می‌شود. کلاس انتزاعی چند روال و مقداری حالت را با خود حمل می‌کند، و زمانی که آنچه تأمین می‌شود بیش از یک بخش داشته باشد، ارزش این تشریفات را دارد.

یک روال برای واگذاری: آن را مقید کنید. یک همکار با چند روال: یک کلاس بنویسید.
