# درباره

`TUPLE: child < parent extra-slots ;` کلاسی را اعلان می‌کند که نمونه‌هایش نمونه‌ی `parent` هم هستند. جست‌وجوی اسلات، سلسله‌مراتب را طی می‌کند: یک `child` همه‌ی اسلات‌هایی را که والد اعلان کرده دارد، به‌علاوه‌ی اسلات‌های خودش، به همان ترتیب.

```factor
TUPLE: vessel name tonnage ;
TUPLE: cargo-vessel < vessel capacity ;
TUPLE: tanker < cargo-vessel fuel-type ;
```

## ترتیب آرگومان‌های `boa`

سازنده‌ی `boa` که خودکار تولید می‌شود، اسلات‌ها را به ترتیب اعلان می‌گیرد، *ابتدا والدها*. برای `tanker` بالا:

```
tanker boa ( name tonnage capacity fuel-type -- tanker )
```

ترتیب اسلات‌ها را زنجیره‌ی وراثت تعیین می‌کند؛ راهی برای درهم‌آمیختن اسلات‌های والد و فرزند وجود ندارد و تغییر ترتیب اسلات‌های والد برای `boa` هر زیرکلاس یک تغییر ناسازگار است.

## سلسله‌مراتب محمول‌ها

هر اعلان `TUPLE:` یک محمول کلاس (`name?`) تولید می‌کند. با وراثت، محمول‌ها تودرتو می‌شوند:

```factor
"Esso" 50000 100000 "diesel" tanker boa .

! all three predicates fire
dup tanker?        .   ! => t
dup cargo-vessel?  .   ! => t
dup vessel?        .   ! => t
```

`instance?` (از [`classes`][classes]) همین پرسش را با کلاس به‌عنوان آرگومانی روی پشته می‌پرسد، نه با کلاسی که در اسم یک واژه تعبیه شده باشد؛ `obj tanker instance?` همان `obj tanker?` است:

```factor
USING: classes ;

"Esso" 50000 100000 "diesel" tanker boa
dup vessel instance? .   ! => t
```

چون کلاس اکنون یک مقدار است، همان نقطه‌ی فراخوانی می‌تواند هر کلاسی را که به آن داده می‌شود بیازماید، کاری که یک محمول ثابت `name?` از عهده‌اش برنمی‌آید.

رابطه‌ی تراگذر `is-a` همان چیزی است که اعزام متد `M:` هم آن را طی می‌کند؛ متدی که روی `vessel` تعریف شده باشد روی هر `cargo-vessel` و هر `tanker` اعمال می‌شود، مگر اینکه بازنویسی خاص‌تری اول اجرا شود. آن بخش ماجرا در [`generics`][generics] آمده است.

## وراثت اکسسورها

واژه‌های اکسسور (`slot>>`، `>>slot`، `change-slot`) از [`accessors`][accessors] می‌آیند و به کلاسی که برایش تولید شده‌اند وابسته نیستند: هر چندتایی که آن اسلات را *داشته باشد* می‌تواند از آنها استفاده کند.

```factor
USING: accessors ;

"Esso" 50000 100000 "diesel" tanker boa
[ 1 + ] change-tonnage tonnage>> .   ! => 50001
```

`change-tonnage` برای `vessel` تولید شده، اما روی یک `tanker` کار می‌کند، چون هر `tanker` یک `vessel` است.

## آنچه این نیست

- **میکسین‌ها** (`MIXIN:` / `INSTANCE:`): یک کلاس می‌تواند به میکسین‌های زیادی بپیوندد؛ این رابطه چندبه‌چند است و بیشتر برای اعزام ژنریک روی یک پروتکل مشترک به کار می‌رود. مفهوم streams آنها را در بافت خودش معرفی می‌کند.
- **کلاس‌های محمولی** (`PREDICATE:`): یک زیرکلاس را با یک محمول زمان اجرا از یک کلاس موجود جدا می‌کنند. قابلیتی جدا در Factor است؛ اینجا به آن نمی‌پردازیم.
