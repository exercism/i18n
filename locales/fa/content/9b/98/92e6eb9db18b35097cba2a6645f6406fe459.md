# درباره

همان‌طور که در مفهوم [`Nothingness`][concept-nothingness] بررسی شد، R راه‌های گوناگونی برای نمایش داده‌هایی دارد که غایب ([`NULL`][ref-null])، نامعلوم ([`NA`][ref-na]) یا از نظر ریاضی نامعتبر ([`NaN`][ref-finite]، [`Inf`][ref-finite]) هستند.
به طور کلی، R تلاش می‌کند از این مقادیر برای علامت‌گذاری مشکل‌ها در همان‌جا استفاده کند و بدون پرتاب استثنا ادامه دهد.

## `stop()`

برخی مشکل‌ها آن‌قدر بنیادی‌اند که نمی‌گذارند برنامه ادامه دهد.
در این صورت، از [`stop(msg)`][ref-stop] استفاده کنید تا برنامه را بی‌درنگ با یک `Error` متوقف کنید و `msg` را چاپ کنید.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

همانند [`assert`][wiki-assert] در زبان‌های دیگر، [`stopifnot()`][ref-stopifnot] راهی ساده برای فراخوانی `stop()` است.
آرگومان‌های آن تعدادی دلخواه از شرط‌های «منطقی» هستند که با ویرگول از هم جدا می‌شوند و برنامه فقط در صورتی ادامه می‌دهد که همه‌ی آن‌ها `TRUE` باشند.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R راه‌های متنوعی برای مدیریت خطاها دارد.
این راه‌ها بر پایه‌ی Common Lisp هستند و با بسیاری از زبان‌های پرکاربرد تفاوت چشمگیری دارند.

ساده‌ترین راه این است که کدی که ممکن است مشکل‌دار باشد را در [`try()`][ref-try] بپیچید.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning] و [`message()`][ref-message]

این‌ها پاسخ‌هایی به شرط‌های غیرکشنده‌اند، برای نمونه:

- هشدار دادن درباره‌ی مشکلی که برنامه می‌تواند دست‌کم تا حدی از آن بازیابی شود.
- آگاه کردن کاربر از پیشرفت در برنامه‌ای که مدت زیادی اجرا می‌شود.

یک تفاوت میان این دو این است که هشدارها ذخیره می‌شوند و (به‌طور پیش‌فرض) هنگام بازگشت تابع نمایش داده می‌شوند، اما پیام‌ها بی‌درنگ نمایش داده می‌شوند.
راه‌های زیادی برای تغییر رفتار پیش‌فرض وجود دارد که بررسی آن‌ها از حوصله‌ی این‌جا بیرون است.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

تابع [`suppressWarnings()`][ref-warning] گاهی در Exercism می‌تواند سودمند باشد تا با خروجی ناخواسته، test runner را گیج نکنید.
