# درباره

«حافظه» معمولاً توسط «سیستم‌عامل» (OS) برای یک برنامه در یک چیدمان کلی نگاشت می‌شود:

| آدرس | ناحیه‌ی حافظه          |
| :-----: | :--------------------- |
|  بالا   | «پشته»                  |
|         | ...                    |
|         | «هیپ»                   |
|         | «بخش خواندنی-نوشتنی» |
|         | «بخش کد/فقط-خواندنی» |
|   پایین   | «رزرو شده»               |

«حافظه» در قالب قطعه‌ها در بخش‌هایی با مجوزهای متفاوت سازماندهی می‌شود.

توابعی که تاکنون تعریف کرده‌ایم همگی در **section .text** بودند.
این بخش داده‌های اجرایی فقط-خواندنی را نگه می‌دارد.
از بخش‌های دیگر برای اعلام متغیرهای داده استفاده می‌شود که ممکن است فقط‌خواندنی یا خواندنی-نوشتنی باشند، اما اجرایی نیستند.

## بخش .data

داده‌های مقداردهی‌شده در **[بخش .data][data]** اعلام می‌شوند.

در NASM (The Netwide Assembler، اسمبلری که در این مسیر استفاده می‌شود)، یک متغیر مقداردهی‌شده یک اسم، یک دستور که اندازه‌ی داده را نشان می‌دهد، و فهرستی از مقادیر جداشده با کاما دارد.
هر کدام از این‌ها با یک فاصله از دیگری جدا می‌شوند و برچسب ممکن است به صورت اختیاری با یک `:` دنبال شود.

دستورهای اصلی و اندازه‌های داده‌ی مرتبط با آن‌ها عبارت‌اند از:

| دستور | اندازه    |
| :-------: | :------ |
|    db     | ۱ بایت  |
|    dw     | ۲ بایت |
|    dd     | ۴ بایت |
|    dq     | ۸ بایت |

برای نمونه، این یک متغیر بایتی به اسم `space` با مقدار `10` اعلام می‌کند:

```x86asm
section .data
    space db 10
```

متغیرهای اعلام‌شده در `section .data` تغییرپذیر هستند، یعنی خواندنی-نوشتنی‌اند.
آن‌ها همچنین طول عمر ذخیره‌سازی _static_ دارند، یعنی در کل زمان اجرای برنامه وجود دارند.

## بخش .rodata

**بخش .rodata** مشابه `section .data` است.
هر دو بخش شامل داده‌های مقداردهی‌شده هستند که به یک روش اعلام می‌شوند و طول عمر ذخیره‌سازی یکسانی دارند.

تفاوت اصلی بین آن‌ها این است که داده در `section .rodata` تغییرناپذیر است، یعنی فقط‌خواندنی.

~~~~exercism/note
ثابت‌های تعریف‌شده با `equ` با آن‌هایی که در `section .rodata` تعریف شده‌اند متفاوت‌اند.

یک ثابت تعریف‌شده با `equ` فضایی در حافظه اشغال نمی‌کند و اسمبلر مستقیماً مقدارش را جایگزین آن می‌کند.
در واقع جای‌نگهدار برای آن مقدار است.

از طرف دیگر، ثابت‌های تعریف‌شده در `section .rodata` واقعاً در حافظه ذخیره می‌شوند و آدرس دارند.
~~~~

## دسترسی به داده

### برچسب‌ها و غیرمستقیم‌سازی

داده‌ی اعلام‌شده باید اسمی مرتبط با خود داشته باشد.
به این اسم یک **«برچسب»** می‌گویند.

یک برچسب نمادی است که آدرس مشخص داده در حافظه را رمزگذاری می‌کند.
**آدرس‌ها در x86-64 مقادیر ۶۴ بیتی هستند**.
مقداری که چنین آدرسی را نگه می‌دارد، چه در یک «ثبات» نگه‌داشته شود و چه در حافظه ذخیره شود، چیزی است که زبان‌های سطح بالاتر به آن **[«اشاره‌گر»][pointer]** می‌گویند.

در NASM، تلاش برای دسترسی مستقیم به داده با برچسبش، حافظه‌ی تخصیص‌یافته را به دست نمی‌دهد، بلکه آدرس آن را می‌دهد:

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

برای دسترسی به محتویات یک آدرس حافظه، لازم است آن را _«ارجاع‌زدایی»_ کنیم.
به این کار **«غیرمستقیم‌سازی»** می‌گویند.

در NASM، این کار با `[]` انجام می‌شود:

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

با این حال، موقعیت‌هایی وجود دارد که ممکن است در مورد اندازه‌ی حافظه‌ی ارجاع‌زدایی‌شده ابهام وجود داشته باشد.
در آن موارد، باید از یک پیشوند که این اندازه را مشخص می‌کند استفاده شود.

این‌ها مهم‌ترین پیشوندها و اندازه‌هایشان در یک برنامه‌ی معمول x86-64 هستند:

| پیشوند | اندازه    |
| :----- | :------ |
| byte   | ۱ بایت  |
| word   | ۲ بایت |
| dword  | ۴ بایت |
| qword  | ۸ بایت |

همان بارگذاری می‌تواند با ذکر صریح اندازه نوشته شود:

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

استفاده از پیشوند هنگام ارجاع‌زدایی حافظه، رویه‌ی خوبی است.

### نوشتن در حافظه

نوشتن در حافظه به همان روش، با ارجاع‌زدایی یک آدرس انجام می‌شود:

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

توجه داشته باشید که می‌توانید در بیشتر دستورالعمل‌ها از عملوندهای حافظه استفاده کنید بدون اینکه ابتدا محتویات را در یک ثبات بارگذاری کنید.
با این حال، معمولاً نمی‌توان از آن‌ها در هر دو عملوند مبدأ و مقصد استفاده کرد، فقط در یکی از این دو:

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### دستورالعمل LEA

اگرچه `mov` می‌تواند برای ذخیره‌ی آدرس یک متغیر در یک ثبات استفاده شود، دستورالعمل‌هایی با این هدف خاص وجود دارد: **[lea][lea]**.

این دستورالعمل از یک عملوند با شکل حافظه استفاده می‌کند، اما حافظه را _نمی‌خواند_.
در عوض، عبارت آدرس مؤثر را محاسبه می‌کند و نتیجه را در عملوند مقصد می‌نویسد:

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

استفاده از `lea` برای محاسبه و ذخیره‌ی آدرس‌های حافظه در ثبات‌ها، اصطلاحی‌تر است.

### آدرس‌دهی نسبی

هنگام دسترسی به مکان‌های حافظه، رفتار پیش‌فرض در NASM تولید **آدرس‌های مطلق** است، یعنی آدرس‌های حافظه‌ی ثابت.

به دلایل امنیتی، فایل‌های اجرایی اغلب به صورت **PIE (فایل اجرایی مستقل از موقعیت)** ساخته می‌شوند، که در آن نواحی حافظه در مکان‌های تصادفی قرار می‌گیرند.
در یک `PIE`، آدرس نهایی یک متغیر در زمان پیوند مشخص نیست.
بنابراین، کد به جای آن آدرس‌ها را به صورت یک افست از مقدار موجود در ثبات خاصی به نام `rip` محاسبه می‌کند، که به دستورالعمل بعدی برای اجرا اشاره می‌کند.

به این معمولاً **آدرس‌دهی نسبی RIP** می‌گویند.

در NASM می‌توانید دسترسی نسبی RIP را با **[عملگر rel][rel]** درخواست کنید:

```x86asm
mov rax, qword [rel variable]
```

آدرس‌دهی نسبی را همچنین می‌توان با قرار دادن `default rel` در بالای فایل مبدأ، به عنوان پیش‌فرض تنظیم کرد.

همه‌ی تمرین‌ها در این مسیر به صورت `PIE` کامپایل و پیوند می‌شوند، بنابراین برای تولید آدرس‌های نسبی باید از `rel` استفاده شود.

چیدمان تصادفی که در بالا ذکر شد، یک کاهش‌دهنده‌ی خطر به نام تصادفی‌سازی چیدمان فضای آدرس است.
با غیرقابل پیش‌بینی کردن پایه‌ی هر ناحیه‌ی حافظه، آدرس‌های ثابتی را که بسیاری از تکنیک‌های بهره‌کشی به آن‌ها متکی هستند از مهاجم می‌گیرد، و `PIE` همان چیزی است که به بارگذارنده اجازه می‌دهد آن نواحی را هر جایی قرار دهد.

به همین دلیل، آدرس‌دهی مطلق در این مسیر نه تنها توصیه نمی‌شود، بلکه غیرقابل استفاده است.
یک ارجاع مطلق مانند `[abs variable]` از اسمبلر می‌خواهد که یک آدرس ثابت ۳۲ بیتی را در دستورالعمل جایگذاری کند.
در لینوکس، پیونددهنده‌ی `PIE` جابه‌جایی حاصل را رد می‌کند، و در macOS قالب `macho64` اصلاً از آدرس‌های مطلق ۳۲ بیتی پشتیبانی نمی‌کند، بنابراین فایل مونتاژ نمی‌شود.

آدرس‌دهی نسبی RIP از هر دو مشکل اجتناب می‌کند، زیرا دستورالعمل فقط یک افست از `rip` را رمزگذاری می‌کند و هرگز یک آدرس ثابت را نه.
بنابراین، روش اصطلاحی برای قرار دادن یک آدرس در ثبات تحت `PIE`، استفاده از `lea` با یک عملوند `rel` است:

```x86asm
default rel

section .data
    variable dq 7

section .text
fn:
    lea rax, [rel variable]       ; materialize the address (PIE-safe)
    mov rcx, qword [rel variable] ; load the value through a RIP-relative access
    ...
```

### قابلیت مشاهده

برچسب‌ها (توابع و داده) که در هر بخشی تعریف می‌شوند (مثلاً `.text`، `.data`، `.rodata`) در همان فایل مبدأ قابل مشاهده هستند.
اگر `global` اعلام شوند، برای سایر فایل‌های مبدأ نیز قابل مشاهده هستند.

برعکس، برچسب‌هایی که در سایر فایل‌های مبدأ تعریف می‌شوند، در صورتی که `extern` اعلام شوند، برای فایل مبدأ جاری قابل مشاهده هستند.
در این حالت، هیچ نشانه‌ای از اندازه‌ی داده در اسمبلی وجود ندارد؛ این باید از قبل دانسته باشد.

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
