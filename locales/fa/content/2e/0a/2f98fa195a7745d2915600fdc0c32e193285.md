# درباره

در Rust، «تکرارگر» هر مقداری است که `trait` [`Iterator`](https://doc.rust-lang.org/stable/std/iter/trait.Iterator.html) را پیاده‌سازی می‌کند.
مقادیر یک تکرارگر را می‌توان با فراخوانی متد `next` روی تکرارگر، به‌صورت دستی پیش برد.

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // many built-in methods implemented
}
```

بسیاری از [`collections`](https://doc.rust-lang.org/std/collections/index.html) در Rust، `trait` [`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html) را پیاده‌سازی می‌کنند
که می‌تواند از مقادیر مجموعه یک `Iterator` تولید کند.

```rust
trait IntoIterator where Self::IntoIter: Iterator<Item=Self::Item> {
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}
```

توجه داشته باشید که هرچند `IntoIterator::into_iter` نوع `self` خود را مصرف می‌کند، آن نوع لزوماً نباید یک مقدار مالکیت‌شده باشد.
بنابراین پیاده‌سازی‌هایی از `IntoIterator` برای [`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-2)،
برای [`&'a Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator)
و برای [`&'a mut Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-1) وجود دارد.
این پیاده‌سازی‌ها برای درجات متفاوت مالکیت، انعطاف‌پذیری مفیدی فراهم می‌کنند.

برای این مفهوم، درک `traits` لازم نیست و یک تمرین کامل برای شما خواهیم داشت تا در `traits` مهارت پیدا کنید.
فعلاً فقط به خاطر بسپارید که:

- هر نوعی که `IntoIterator` را پیاده‌سازی می‌کند، «تکرارپذیر» نامیده می‌شود، چون می‌توان آن را به یک تکرارگر تبدیل کرد.
- هر نوعی که `Iterator` را پیاده‌سازی می‌کند، یک تکرارگر است؛ تکرارگر مقادیری را _تولید_ می‌کند و می‌توان _روی آن تکرار کرد_.
- می‌توانید از هر نوعی که `IntoIterator` را پیاده‌سازی می‌کند، با فراخوانی متد `into_iter` آن یک تکرارگر به دست آورید.
- هر تکرارگر [`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html#impl-IntoIterator-25) را پیاده‌سازی می‌کند و خودش را تولید می‌کند.
- حلقه‌های `for` همیشه روی تکرارگرها کار می‌کنند و به‌طور ضمنی `IntoIterator` را روی آرگومان بازه‌ی خود فراخوانی می‌کنند.

## `into_iter` و حلقه‌های `for`

احتمالاً با حلقه‌های `for` روی یک بردار آشنا هستید:

```rust
// lor is a `Vec`, which implements `IntoIterator`
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
for people in &lor {
    println!("{people}");
}
```

در اصل، یک حلقه‌ی `for` فقط شکل کوتاهی برای فراخوانی متد `into_iter` آرگومانش است و سپس فراخوانی `next()` تا زمانی که دیگر عنصری تولید نکند. به عبارت دیگر، حلقه‌ی قبلی به این صورت بازنویسی می‌شود:

```rust
{
    let mut iterator = (&lor).into_iter();
    while let Some(people) = iterator.next() {
        println!("{people}");
    }
}
```

## متدهای `iter` و `iter_mut`

بیشتر انواع مجموعه در Rust متدهای `iter` و `iter_mut` را فراهم می‌کنند.
برای مجموعه‌ای از نوع `T`، این دو متد طبق قرارداد کار زیر را انجام می‌دهند:

- تکرارگری که `iter` برمی‌گرداند، `&T` را به‌صورت قرض‌گرفته‌شده‌ی تغییرناپذیر تولید می‌کند.
- تکرارگری که `iter_mut` برمی‌گرداند، `&mut T` را به‌صورت قرض‌گرفته‌شده‌ی تغییرپذیر تولید می‌کند.

```rust
let mut v = vec![1, 2, 3];

// Using `iter` method
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&1));
assert_eq!(iterator.next(), Some(&2));
assert_eq!(iterator.next(), Some(&3));
assert_eq!(iterator.next(), None);

// Using `iter_mut` method
for value in v.iter_mut() {
     *value *= *value;
}
println!("{v:?}");
// => [1, 4, 9]
```

## تفاوت میان `iter`، `iter_mut` و `into_iter`

اگر `iter`، `iter_mut` و `into_iter` همه تکرارگر تولید می‌کنند، تفاوت‌شان چیست؟

- تکرارگری که `iter` برمی‌گرداند، طبق قرارداد `&T` را به‌صورت قرض‌گرفته‌شده‌ی تغییرناپذیر تولید می‌کند.
- تکرارگری که `iter_mut` برمی‌گرداند، طبق قرارداد `&mut T` را به‌صورت قرض‌گرفته‌شده‌ی تغییرپذیر تولید می‌کند.
- تکرارگری که `into_iter` برمی‌گرداند، بسته به بافت ممکن است `T` یا `&T` یا `&mut T` تولید کند.

بافت فراخوانی `into_iter` چیست؟
نوع `self` آن.
به یاد بیاورید که پیاده‌سازی‌هایی از `IntoIterator` برای `Vec`، `&'a Vec` و `&'a mut Vec` وجود دارد.
بنابراین:

- `(&v).into_iter()` برابر با `v.iter()` است => `&T` را برمی‌گرداند
- `(&mut v).into_iter()` برابر با `v.iter_mut()` است => `&mut T` را برمی‌گرداند
- `v.into_iter()` => `T` را برمی‌گرداند و مقادیر را جابه‌جا می‌کند

این موضوع در حلقه‌های `for` روشن‌تر است:

- `for num in &v {...}` => به `&T` مقید می‌شود
- `for num in &mut v {...}` => به `&mut T` مقید می‌شود
- `for num in v {...}` => به `T` مقید می‌شود و مقادیر را جابه‌جا می‌کند

غالباً نوشتن `v.iter()` به‌جای `(&v).into_iter()` خواناتر است.
بنابراین دلایل ارگونومیکی برای ترجیح `iter` و `iter_mut` بر `into_iter` وجود دارد.

## استفاده از متدهای داخلی تکرارگرها

تکرارگرها متدهای داخلی پرشماری دارند، مانند `map`، `filter` و `collect`.
این متدها گاهی همراه با بستارها استفاده می‌شوند.

`map` با استفاده از یک بستار، مقادیر یک تکرارگر را تبدیل می‌کند.
`take` یک تکرارگر (احتمالاً بی‌نهایت) را به تکرارگری کوتاه می‌کند که پس از حداکثر تعداد عناصر مشخص‌شده پایان می‌یابد.

```rust
for even_number in (0..).into_iter().map(|x| x * 2).take(4) {
    let odd_number = even_number + 1;
    println!("{even_number} => {odd_number}");
}
// 0 => 1
// 2 => 3
// 4 => 5
// 6 => 7
```

`filter` تکرارگر را به تکرارگری تبدیل می‌کند که فقط مقادیری را برمی‌گرداند که بستار برای‌شان `true` ارزیابی می‌شود.
`count` تکرارگر را مصرف می‌کند و تعداد عناصر تولیدشده را برمی‌گرداند.

```rust
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
let short_people = ["Dwarves", "Hobbits"];
let num_tall_people = lor.iter().filter(|people| !short_people.contains(people)).count();
assert_eq!(num_tall_people, 5);
```

`flat_map` یک تکرارگر را با تبدیل هر عنصر به یک تکرارگر تازه به کمک بستار داده‌شده، و سپس تخت‌کردن همه‌ی تکرارگرهای تازه‌ی تولیدشده با زنجیر کردن آن‌ها به هم، تبدیل می‌کند.
`collect` یک مجموعه‌ی تازه تولید می‌کند،
به شرطی که نوع مجموعه [`FromIterator`](https://doc.rust-lang.org/std/iter/trait.FromIterator.html) را پیاده‌سازی کند.

```rust
let words = ["alpha", "beta", "gamma"];
// chars() returns an iterator
let merged: String = words.iter()
                          .flat_map(|s| s.chars())
                          .collect();
assert_eq!(merged, "alphabetagamma");
```

[`trait` `Iterator`](https://doc.rust-lang.org/std/iter/trait.Iterator.html) _بسیاری_ از این تبدیل‌های مفید تکرارگر را فراهم می‌کند؛
ارزشش را دارد که مستندات را بخوانید و با آن‌ها آشنا شوید.

## تنبلی

مهم است بدانید که تکرارگرهای Rust تنبل‌اند:
تا زمانی که تکرارگر را مصرف نکنیم، هیچ مقداری تولید نمی‌کنند.
اگر کد زیر را بنویسید و اجرا کنید:

```rust
(0..5).map(|x| x * x);
```

این خطای کامپایلر را دریافت می‌کنید:

```rust
 --> src/main.rs:2:5
  |
2 |     (0..5).map(|x| x * x);
  |     ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

این به این دلیل است که `map` یک متد آداپتور است که تکرارگر دیگری برمی‌گرداند.

برای مصرف یک تکرارگر، یا از یک حلقه‌ی `for` استفاده کنید یا از متدی از تکرارگر که مقداری تولید می‌کند که خودش تکرارگر نیست.

برای نمونه، `collect` یک متد مصرف‌کننده است (امضای تابع آن به‌جای تکرارگر، یک نوع عمومی برمی‌گرداند):

```rust
//         Iterator   Adaptor        Consumer
//                |      |               |
let v: Vec<_> = (0..5).map(|x| x * x).collect();
```
