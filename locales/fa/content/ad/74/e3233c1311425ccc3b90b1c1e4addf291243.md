# مقدمه

## حلقه

**«حلقه»** دنباله‌ای از دستورهاست که به‌طور بالقوه بیش از یک بار اجرا می‌شود، تا اینکه شرط پایان برآورده شود.

در x86-64، یک حلقه معمولاً با پرش به یک برچسب پیشین ساخته می‌شود:

```x86asm
example_loop:
    ...
    jmp example_loop
```

توجه کنید که پرش بی‌قید و شرط به یک برچسب پیشین، همیشه اجرا را به همان برچسب منتقل می‌کند.
یعنی حلقه تا ابد تکرار می‌شود، مگر اینکه پرش دیگری به بیرون از دنباله‌ی تکرارشونده وجود داشته باشد.

برای نمونه، این حلقه پایان نمی‌یابد:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

و این حلقه بسته به اینکه آن شرط برآورده شود یا نه، ممکن است پایان یابد:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

### حلقه‌ی شمارشی

یک حلقه‌ی شمارشی تقریباً همیشه به یک شکل پایان می‌یابد: دستوری که یک شمارنده را به‌روزرسانی می‌کند یا دو مقدار را مقایسه می‌کند و بلافاصله پس از آن، یک پرش شرطی می‌آید که تصمیم می‌گیرد آیا دور دیگری زده شود یا نه.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
در کد بالا، `cmp rsi, 0` لازم نیست، چون `sub rsi, 1` وقتی نتیجه `0` باشد، `zero flag (ZF)` را از قبل تنظیم می‌کند.

هرچند `cmp` روش اصلی آزمودن شرط‌ها در اسمبلی است، بسیاری از دستورها پرچم‌ها را به‌روزرسانی می‌کنند.
برای نمونه، بسیاری از دستورهای حساب صحیح یا بیتی، وقتی نتیجه `0` باشد `ZF` را و وقتی نتیجه منفی باشد (یعنی بیت بالایی مقدار ۱ باشد) `SF` را به‌روزرسانی می‌کنند.

می‌توانید به یک [مرجع][reference] مراجعه کنید تا ببینید هر دستور روی کدام پرچم‌ها اثر می‌گذارد.

[reference]: https://www.felixcloutier.com/x86/
~~~~

توجه کنید که در مثال بالا، فرض شده است که `rsi` بزرگ‌تر از `0` است.
اگر `0` بود، آن‌وقت `sub rsi, 1` مقدار `rsi` را به `-1` کاهش می‌داد، که یک عدد بدون علامت بسیار بزرگ است.
`18,446,744,073,709,551,615` تکرار دیگر لازم می‌شد تا حلقه در نهایت پایان یابد.
همچنین چون طول آرایه `0` است، هر دسترسی به حافظه خارج از محدوده خواهد بود.

اگر هیچ تضمینی درباره‌ی طول آرایه وجود نداشته باشد، دو رویکرد رایج هست.

رویکرد اول این است که شرط پایان را به ابتدای حلقه منتقل کنید و سپس در پایان یک پرش بی‌قید و شرط داشته باشید:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

رویکرد دوم این است که یک بار پیش از شروع حلقه، بررسی کنید که طول آرایه صفر است یا نه:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

این رویکرد دوم معمولاً از اولی کارآمدتر است، چون شاخه‌های کمتری در بدنه‌ی حلقه وجود دارد.
در یک مفهوم آینده درباره‌ی این موضوع بیشتر یاد خواهید گرفت.

~~~~exercism/advanced
در برخی موقعیت‌ها، پردازنده‌های امروزی می‌توانند دو دستور مختلف را در یک عملیات ادغام کنند.
به این بهینه‌سازی **macrofusion** می‌گویند.

بسیاری از دستورهای حساب مانند `sub` و `add` و همچنین `cmp` و `test` معمولاً با پرش شرطی‌ای که بلافاصله پس از آن‌ها می‌آید، ادغام می‌شوند.
یعنی دستوری مانند `cmp rax, rdx` که بلافاصله پس از آن یک پرش شرطی می‌آید، معمولاً توسط پردازنده به‌عنوان یک عملیات واحد در نظر گرفته می‌شود.

macrofusion به پردازنده بستگی دارد و در اینکه کدام دستورها با کدام پرش شرطی ادغام می‌شوند، تفاوت‌هایی وجود دارد.

یک مرجع مفید، [خردمعماری پردازنده‌های Intel، AMD و VIA، نوشته‌ی Agner Fog][agner-uarch] است.
بخش ۳.۴.۲.۲ (بهینه‌سازی برای macrofusion) از [کتاب مرجع بهینه‌سازی Intel][intel-opt] هم جفت‌های قابل ادغام را برای پردازنده‌های Intel فهرست کرده است.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
