# مقدمه

هر داده‌ای در اسمبلی دنباله‌ای از بایت‌ها است.
این یعنی می‌توان هر داده‌ای را به‌صورت یک **آرایه** از همان بایت‌های زیربنایی دید.

## دسترسی به عنصرها در یک آرایه

برای دسترسی به هر مقدار در حافظه، لازم است **آدرس مؤثر** آن محاسبه شود.
آدرس مؤثر عبارتی است که می‌تواند از این موارد تشکیل شود:

- یک _آدرس پایه_، مثلاً آدرسی که برچسب یک متغیر نشان می‌دهد.
- یک _ثبات اندیس_، که ممکن است در `1`، `2`، `4` یا `8` ضرب شود.
- یک _جابه‌جایی_ ۳۲ بیتی علامت‌دار، که عددی است که به آدرس پایه اضافه می‌شود (یا از آن کم می‌شود).

توجه کنید که نمایه‌گذاری این آدرس _از صفر_ آغاز می‌شود، بنابراین یک آدرس پایه، بدون هیچ جابه‌جایی، به اولین بایت یک متغیر اشاره می‌کند.
به همین دلیل، ارجاع‌زدایی از حافظه فقط با یک برچسب و بدون هیچ جابه‌جایی، همان‌طور که در مفاهیم قبلی انجام داده‌ایم، مقداری را به دست می‌دهد که از اولین بایت آن شروع می‌شود:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
x86-64 به‌صورت [لیتل اندین][endianness] است.
این یعنی کم‌ارزش‌ترین بایت یک مقدار چندبایتی در کوچک‌ترین آدرس حافظه ذخیره می‌شود.

در نتیجه، هنگام دسترسی به بایت‌های جداگانه‌ی یک مقدار چندبایتی، لازم است یک جابه‌جایی مثبت به آدرس پایه اضافه شود تا به بایت‌های پرارزش‌تر رسید.

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

متغیری مقداردهی‌شده که با فهرستی از مقادیر اعلام می‌شود، آرایه‌ای از همان مقادیر است و هر عنصر اندازه‌ی مشخص‌شده را دارد.
با این حال، جابه‌جایی‌ها همیشه بر حسب **_بایت_** هستند، حتی وقتی هر عنصر آرایه اندازه‌ی بزرگ‌تری دارد:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

توجه کنید که چون آدرس‌ها بر حسب بایت هستند، می‌توان مستقیماً به یک بایت جداگانه از هر عنصر آرایه دسترسی پیدا کرد:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

به همین دلیل، می‌توان در یک دستور به بیش از اندازه‌ی یک عنصر دسترسی پیدا کرد:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
اسمبلی هیچ بررسی محدوده‌ای روی دسترسی‌های آرایه انجام نمی‌دهد.
اندیسی که از انتهای آرایه بگذرد، حافظه‌ای بیرون از آن را می‌خواند یا می‌نویسد.
این کار می‌تواند به نتایج نادرست و بی‌سروصدا، به خراب شدن داده‌های دیگر، و اگر حافظه‌ی مورد دسترسی نگاشت نشده باشد، به یک خطای زمان اجرا منجر شود.
مسئولیت برنامه‌نویس است که هر آدرس مؤثر را در محدوده‌ی آرایه نگه دارد.
~~~~

## محاسبه‌ی اندازه‌ی یک آرایه‌ی مقداردهی‌شده

NASM (همان Netwide Assembler، اسمبلری که این مسیر از آن استفاده می‌کند) یک نماد ویژه (`$`) دارد که مکان کنونی در حافظه را نشان می‌دهد.
این نماد روشی راحت برای محاسبه‌ی کل اندازه‌ی حافظه‌ای که یک آرایه اشغال می‌کند فراهم می‌کند:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

وقتی `$` دقیقاً بعد از `example` به کار می‌رود، آدرس انتهای آرایه در حافظه را دارد.
این یعنی `$ - example` تفاضل میان آن آدرس و آدرسی است که برچسب `example` به آن اشاره می‌کند.
این دقیقاً همان کل اندازه‌ی حافظه‌ای است که آرایه‌ی مورد اشاره‌ی `example`، بر حسب بایت، اشغال می‌کند.

پس با تعریف `example_length` با این مقدار، متغیری ۸ بایتی ساخته‌ایم که اندازه، یا طول، آرایه را بر حسب بایت ذخیره می‌کند.

## بخش `.bss`

داده‌های مقداردهی‌نشده در **بخش `.bss`** اعلام می‌شوند.
در بیشتر پلتفرم‌ها، سیستم‌عامل این داده‌ها را در آغاز برنامه با صفر پر می‌کند.

در NASM، یک متغیر مقداردهی‌نشده یک اسم، یک دستور که اندازه‌ی داده را نشان می‌دهد، و تعداد عنصرهایی که باید رزرو شوند دارد.
هر یک از این‌ها با یک فاصله از دیگری جدا می‌شود.

دستورهای اصلی و اندازه‌های داده‌ی مربوط به آن‌ها عبارت‌اند از:

| دستور | اندازه    |
| :-------: | :------ |
|   `resb`    | ۱ بایت  |
|   `resw`    | ۲ بایت |
|   `resd`    | ۴ بایت |
|   `resq`    | ۸ بایت |

برای نمونه، این کد فضایی مقداردهی‌نشده برای `3` بایت در متغیری به اسم `example` رزرو می‌کند:

```x86asm
section .bss
    example resb 3
```

و این کد فضایی مقداردهی‌نشده برای `10` ضربدر `8` بایت (یعنی `80` بایت) در متغیری به اسم `arr` رزرو می‌کند:

```x86asm
section .bss
    arr resq 10
```

متغیرهای داخل `section .bss` تغییرپذیرند، یعنی هم خواندنی و هم نوشتنی هستند.

به داده‌های مقداردهی‌نشده هم می‌توان همانند داده‌های مقداردهی‌شده، با استفاده از آدرس مؤثرشان دسترسی داشت.
به همین ترتیب، این داده‌ها هم عمر ذخیره‌سازی ایستا دارند و از هر تابعی در همان فایل مبدأ قابل دسترسی هستند (و اگر `global` اعلام شده باشند، در فایل‌های مبدأ دیگر هم).

## دسترسی به آدرس‌های آرایه با دستور `lea`

همان‌طور که در یک مفهوم قبلی بررسی شد، دستور `lea` یک آدرس مؤثر حافظه را محاسبه می‌کند.
می‌توان از آن برای محاسبه‌ی آدرس هر عنصر در یک آرایه، با همان قواعد، استفاده کرد.

توجه کنید که در آدرس‌دهی نسبی، اغلب لازم است آدرس متغیر پیش از ساختن یک آدرس پیچیده‌تر در یک ثبات بارگذاری شود:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
یکی از مزیت‌های `lea` این است که با حساب محاسبه‌ی آدرس، مقداری را بدون دسترسی واقعی به حافظه‌ی آن آدرس محاسبه می‌کند.
این باعث می‌شود حتی وقتی هیچ‌یک از ثبات‌ها آدرسی از حافظه را در خود ندارد، برای انجام محاسبات حسابی مفید باشد:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
