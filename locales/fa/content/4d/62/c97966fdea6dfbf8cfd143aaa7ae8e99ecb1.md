# درباره

مشخص‌کننده‌های کلاس ذخیره‌سازی به نحوه‌ی ذخیره‌ی متغیرها در حافظه مربوط می‌شوند.
آن‌ها ارتباط نزدیکی با «مدت ذخیره‌سازی» (که «عمر» هم نامیده می‌شود) یک مقدار دارند.

## `auto`: کلاس ذخیره‌سازی پیش‌فرض برای متغیرهای دامنه‌ی تابع یا بلوک

از آنجا که متغیرهای تعریف‌شده در یک بلوک یا تابع به‌طور پیش‌فرض `auto` هستند، استفاده‌ی صریح از این واژه رایج نیست.
دلیل دیگری که `auto` اغلب از آن پرهیز می‌شود این است که در C++ معنای متفاوتی دارد.
پایگاه‌های کدی که C و C++ را ترکیب می‌کنند، ممکن است با پرهیز از مشخص‌کننده‌ی ذخیره‌سازی `auto` کمتر گیج‌کننده باشند.
عمر یک متغیر `auto` وقتی آغاز می‌شود که بلوکش وارد شود و وقتی پایان می‌یابد که از بلوکش خارج شود.
وقتی بلوک یک متغیر `auto` وارد می‌شود، حافظه‌ای برای آن تخصیص داده می‌شود، _اما بدون مقدار پیش‌فرض_.
یک استثنا برای آرایه‌های با طول متغیر (VLA) است.
تخصیص یک VLA همان‌جا که در بلوکش اعلام یا تعریف شده رخ می‌دهد و با خارج شدن از بلوکش پایان می‌یابد.
یک متغیر `auto` را می‌توان با هر عبارت معتبری مقداردهی اولیه کرد.

## `static`: مشخص‌کننده‌ی ذخیره‌سازی که نباید با نوع اتصال `static` اشتباه گرفته شود

متغیری که بیرون از یک بلوک یا تابع تعریف می‌شود، «دامنه‌ی فایل» دارد و همیشه مدت ذخیره‌سازی `static` دارد.
دامنه‌ی فایل یعنی می‌توان در هر جای فایل به آن دسترسی داشت.
ذخیره‌سازی `static` یعنی از آغاز اجرای برنامه تا پایان آن وجود دارد.
یک متغیر `static` مگر آنکه به‌صراحت مقداردهی اولیه شود، با مقدار پیش‌فرض صفر خود مقداردهی اولیه می‌شود.
اگر یک متغیر دامنه‌ی فایل با `static` علامت‌گذاری شود، آن `static` به اتصال آن اشاره دارد.
یک متغیر دامنه‌ی فایل که با `static` علامت‌گذاری شده، اتصال داخلی دارد، یعنی فقط می‌توان در همان فایل به آن دسترسی داشت.
اگر متغیری درون یک تابع یا در بلوکی درون یک تابع تعریف شود و با `static` علامت‌گذاری شود، مدت ذخیره‌سازی `static` دارد.
مقدار متغیر `static` بین فراخوانی‌های تابع یا بلوک باقی می‌ماند.

در مثال زیر دو متغیر `static` را در عمل می‌بینیم.
متغیر `count` اول درون تابع `print_stuff` تعریف شده و مقدارش را بین فراخوانی‌های تابع حفظ می‌کند.
متغیر `count` دوم درون یک بلوک دلخواه تعریف شده و متغیر `count` اول را درون بلوکش پنهان (یا سایه‌انداز) می‌کند.
متغیر `count` دوم به‌طور مستقل مقدارش را بین ورودها به بلوک حفظ می‌کند.

```c
#include <stdio.h>

void print_stuff(void) {
    // static variable is initialized to 0
    static int count;
    count++;
    printf("function count is %d\n", count);
    {
        // static variable is initialized to 0
        static int count;
        count++;
        printf("block count is %d\n", count);
    }
}

int main() {
    // prints
    // function count is 1
    // block count is 1
    print_stuff();
    // prints
    // function count is 2
    // block count is 2    
    print_stuff();
}
```

اگر یک متغیر `static` به‌صراحت مقداردهی اولیه شود، باید این کار با یک «عبارت ثابت» انجام شود.
عبارت ثابت عبارتی است که می‌توان آن را در زمان کامپایل ارزیابی کرد.

## `extern`: چگونه به یک متغیر در واحد ترجمه‌ی دیگری دسترسی پیدا کنیم

یک «واحد ترجمه» از یک فایل مبدأ و هر فایل دیگری که آن `#include` می‌کند تشکیل می‌شود.
اگرچه یک متغیر با دامنه‌ی فایل را می‌توان به‌صورت `extern` اعلام و مقداردهی اولیه کرد، کلیدواژه‌ی `extern` معمولاً برای اشاره به یک متغیر موجود به کار می‌رود، نه برای تعریف یک متغیر جدید.
متغیری که `extern` به آن اشاره می‌کند باید دامنه‌ی فایل داشته باشد.
یک متغیر در دامنه‌ی فایل همیشه ذخیره‌سازی `static` دارد.
یک متغیر در یک فایل includeشده باید اتصال خارجی داشته باشد تا فایلی که آن را include می‌کند بتواند به آن دسترسی پیدا کند.

در مثال زیر از متغیر `val` که به‌صورت `extern` اعلام شده استفاده می‌کنیم تا به `val` تعریف‌شده در دامنه‌ی فایلش اشاره کند.
هر دو کاربرد `extern`، «اعلان ارجاعی» نامیده می‌شوند، چون به متغیری اشاره می‌کنند که جای دیگری تعریف شده است.

```c
#include <stdio.h>

void set_val() {
    // this declares val which is defined elsewhere
    extern int val;
    val += 42;
    // prints val is 42
    printf("val is %d\n", val);
}

int main() {
    set_val();
    // this declares val which is defined elsewhere
    extern int val;
    val += 42;
    // prints val is 84
    printf("val is %d\n", val);
}
// this value could be defined in another source file.
// as a variable with static storage, it is initialized to zero
int val;
```

اگر هر دو کلیدواژه‌ی `extern` حذف می‌شدند، برنامه ممکن بود چیزی شبیه این چاپ کند

```
val is 22038
val is 42
```

چنین خروجی‌ای نشان می‌دهد که هر اعلان `val` بدون `extern` یک «اعلان تعریف‌کننده» است و از سایر اعلان‌های `val` مستقل است.
حذف کامل اعلان‌های `val` از `set_val` و `main` به یک خطای کامپایل منجر می‌شود مبنی بر اینکه `val` در `set_val` و `main` اعلام نشده است.

اگر متغیری که `extern` به آن اشاره می‌کند در همان فایل باشد، می‌تواند اتصال داخلی یا خارجی داشته باشد.
تعریف `val` به‌صورت `static int val;` هیچ اثری بر استفاده از `val` در `set_val` یا `main` ندارد، جز اینکه برای کامپایل شدن باید تعریف به بالای آن‌ها منتقل شود.
اما اگر `val` بالای توابع تعریف شده بود، آن‌ها نیازی به اعلام `val` به‌صورت `extern` نداشتند.

مثال زیر کار می‌کند

```c
#include <stdio.h>

// val defining declaration before the function definitions
static int val;

void set_val() {
    val += 42;
    // prints val is 42
    printf("val is %d\n", val);
}

int main() {
    set_val();
    val += 42;
    // prints val is 84
    printf("val is %d\n", val);
}
```

می‌توان `static` را از `static int val;` حذف کرد و به `val` اتصال خارجی داد، و `val` همچنان در `set_val` و `main` یکسان کار می‌کند.
اگر فایل مبدأ دیگری این فایل را include می‌کرد، تنها زمانی می‌توانست از `val` استفاده کند که `val` اتصال خارجی داشته باشد (به‌صورت `static` اعلام نشده باشد) و آن فایل دیگر `extern int val;` را اعلام کرده باشد.

متغیری که `extern` به آن اشاره می‌کند نه‌تنها باید ذخیره‌سازی `static` داشته باشد، بلکه باید دامنه‌ی فایل هم داشته باشد.
مثال زیر به احتمال زیاد کامپایل نمی‌شود، چون `val` با اینکه `static` است، دامنه‌ی فایل ندارد.

```c
#include <stdio.h>

void set_val() {
    // defined with static storage, but not in file scope
    static int val;
    val += 42;
    printf("val is %d\n", val);
}

int main() {
    set_val();
    extern int val;
    printf("val is %d\n", val);
}
```

## `register`: چگونه شاید دسترسی به یک متغیر را سریع‌تر کنیم

متغیری که با `register` علامت‌گذاری شده، تمایل برنامه‌نویس را برای قرار گرفتن مقدار در یک ثبات، به‌منظور دسترسی سریع، بیان می‌کند.
یک متغیر `register` مانند یک متغیر `auto` است از این جهت که باید در دامنه‌ی تابع یا بلوک باشد.
از آنجا که قرار است مقدار به‌جای حافظه در یک ثبات قرار گیرد، کامپایلر باید دسترسی به آدرس متغیر را غیرمجاز بداند، چون نمی‌توان آدرس یک ثبات را گرفت.
با این حال، خودِ یک آدرس حافظه می‌تواند در یک ثبات قرار گیرد.
مثال زیر این را نشان می‌دهد

```c
#include <stdio.h>

int main() {
    int i = 42;
    register int *i_ptr = &i;
    // prints i is 42, i_ptr is 0x7ffd0c2055c4 (or some other address)
    printf("i is %d, i_ptr is %p", i, i_ptr);
}
```

register` اساساً یک راهنماست، چون کامپایلرها آزادند انتخاب کنند که این مشخص‌کننده را دنبال کنند یا نه، پس ممکن است مقدار واقعاً در یک ثبات قرار بگیرد یا نگیرد.

## `typedef`: مشخص‌کننده‌ی کلاس ذخیره‌سازی که واقعاً نیست

`typedef` فقط به دلایل نحوی به‌عنوان یک مشخص‌کننده‌ی کلاس ذخیره‌سازی توصیف می‌شود.
دلیلش این است که یک مشخص‌کننده‌ی کلاس ذخیره‌سازی نمی‌تواند همراه با مشخص‌کننده‌ی کلاس ذخیره‌سازی دیگری به کار رود.
پس `typedef auto int i = 42;` به‌همان اندازه `static auto int i = 42;` غیرمجاز است.
