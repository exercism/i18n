# مبانی `match`

عبارت `match` امکان مقایسه‌ی آسان یک مقدار با مجموعه‌ای از الگوها و سپس اجرای کد را بر اساس الگوی تطبیق‌یافته فراهم می‌کند.
مقادیر ثابت، اسم‌های متغیر، نویسه‌های عام و بسیاری موارد دیگر، اجزای تشکیل‌دهنده‌ی یک الگو هستند.

```rust
#[derive(Drop)]
enum Color {
    Red,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red => println!("The color is Red"),
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Yellow;
    print_color_type(color); // prints "The color is Yellow"
}
```

برای مدیریت چند خط کد، شاخه‌ی `match` باید در آکولاد `{}` قرار بگیرد:

```rust
fn specified_color(color: Color) -> felt252 {
    let mut response: felt252 = '';

    match color {
        Color::Red => {
            response = 'You passed in Red';
        },
        Color::Yellow => {
            response = 'You passed in Yellow';
        },
        Color::Green => {
            response = 'You passed in Green';
        },
    }

    response
}
```

عبارت `match` همچنین قابلیت مقیدشدن به مقادیری را دارد که با الگو تطبیق می‌کنند.
این کار استخراج مقدار همراه یک گونه‌ی `enum` را ممکن می‌کند.

```rust
#[derive(Drop, Debug)]
enum ColorType {
    Light,
    Dark,
}

#[derive(Drop)]
enum Color {
    Red: ColorType,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red(state) => {
            println!("The color is Red");
            println!("The Color Type is {:?}", state);
        },
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Red(ColorType::Dark);
    print_color_type(color);
}
```

گونه‌ی `Red` از `enum` `Color` را گسترش می‌دهیم تا یک `enum` همراه داشته باشد.
با کمک عبارت `match` می‌توانستیم مقدار همراه را استخراج کنیم؛ `state`.
این صرفاً یک اسم متغیر است که بعداً می‌توان از آن در شاخه‌ی کد استفاده کرد.

## تطبیق نوع `enum` `Option`

`enum` توکار `Option` را نیز می‌توان با عبارت `match` مدیریت کرد.

بیایید تابعی طراحی کنیم که یک پارامتر `Option<u8>` می‌گیرد.
اگر مقداری از پارامتر داده‌شده وجود داشته باشد، یک واحد به آن اضافه می‌کند؛ در غیر این صورت تابع باید مقدار `None` را بدون هیچ عملیاتی برگرداند.

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
        Option::None => Option::None,
    }
}

fn main() {
    let three: Option<u8> = Option::Some(3);
    let four: Option<u8> = add_one(three);
    let none = add_one(Option::None);

    println!("{three:?}"); // prints "Option::Some(3)"
    println!("{four:?}"); // prints "Option::Some(4)"
    println!("{none:?}"); // prints "Option::None(())"
}
```

> توجه: `{:?}` یک نحو قالب‌بندی ویژه است که امکان چاپ شکل Debug پارامتری را که به ماکروی `println!` داده شده فراهم می‌کند.
> می‌توانید اطلاعات بیشتر درباره‌ی آن را در [The Cairo Book][debugging] پیدا کنید.

یکی از مزیت‌های استفاده از ساختار کنترل جریان `match`، جامع‌بودن آن است: الگوهای شاخه‌ها باید _همه‌ی_ حالت‌های ممکن را پوشش دهند.
نسخه‌ای از مثال قبلی را در نظر بگیرید که حالت `None` را مدیریت نمی‌کند:

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
    }
     // this code does not compile, as we forgot to handle the `None` case
}
```

## الگوی همه‌گیر با نویسه‌ی عام `_`

با استفاده از نوع‌های `enum`، می‌توانیم برای چند مقدار خاص اقدام‌های ویژه‌ای انجام دهیم، اما برای همه‌ی مقادیر دیگر یک اقدام پیش‌فرض را با افزودن شاخه‌ای جدید با الگوی `_` به‌عنوان الگوی آخرین شاخه‌ی عبارت `match` انجام دهیم.
الگوی `_` یک الگوی ویژه است که با هر مقداری تطبیق می‌کند و به آن مقدار مقید نمی‌شود.

تابع `is_red` یک پارامتر دریافت می‌کند و اگر رنگ `Red` باشد `true` و برای هر رنگ دیگری `false` برمی‌گرداند:

```rust
fn is_red(color: Color) -> bool {
    match color {
        Color::Red => true,
        _ => false,
    }
}
```

## تطبیق الگو با عملگر `|`

ساختار کنترل جریان `match` در Cairo امکان تطبیق یک مقدار با چندین الگو را با استفاده از عملگر `|` (_یا_) فراهم می‌کند.
این کار به ساده‌تر شدن کد کمک می‌کند.

برای مثال، با استفاده از `enum` به نام `Color` می‌خواهیم تابعی بنویسیم که برای رنگ‌های `Red` یا `Green` مقدار `true` و برای رنگ‌های دیگر `false` برگرداند:

```rust
fn is_red_or_green(color: Color) -> bool {
    match color {
        Color::Red | Color::Green => true,
        _ => false,
    }
}
```

## تطبیق الگو با `felt252` و متغیرهای عدد صحیح

می‌توان `felt252` و متغیرهای عدد صحیح را با مجموعه‌ای از مقادیر تطبیق داد.
با این حال، چند محدودیت وجود دارد:

- فقط اعداد صحیحی پشتیبانی می‌شوند که در یک `felt252` جای بگیرند (یعنی `u256` پشتیبانی نمی‌شود).
- ۰ باید اولین شاخه باشد.
- هر شاخه باید یک قطعه‌ی متوالی را دنبال کند و با شاخه‌های دیگر پیوسته باشد.

بیایید یک بازی پرتاب تاس شش‌وجهی پیاده‌سازی کنیم.
وقتی این تاس پرتاب می‌شود، عددی بین ۰ و ۵ به دست می‌آوریم.
اگر پرتاب به ۰، ۱ یا ۲ منجر شود، برنده می‌شوید.
اگر ۳ بیاورید، دوباره پرتاب می‌کنید.
برای مقادیر دیگر می‌بازید:

```rust
fn toss(value: u8) {
    match value {
        0 | 1 | 2 => println!("you won!"),
        3 => println!("you can roll again!"),
        _ => println!("you lost...")
    }
}

fn main() {
    toss(2); // prints "you won!".
    toss(3); // prints "you can roll again!".
    toss(5); // prints "you lost...".
}
```

## تطبیق تاپل‌ها

تاپل‌ها را نیز می‌توان با مجموعه‌ای از الگوها تطبیق داد.
این الگوها به شکلی مشابه یک تاپل طراحی می‌شوند.

```rust
#[derive(Drop)]
enum DayType {
    Week,
    Weekend,
    Holiday
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn vending_machine_accept(c: (DayType, Coin)) -> bool {
    match c {
        (DayType::Week, _) => true, // accepts all coins during week day
        (_, Coin::Dime) | (_, Coin::Quarter) => true, // accepts only Dime or Quarter coin for all specified days
        (_, _) => false, // returns false for other instances
    }
}
```

در آخرین شاخه‌ی `match`، مهم نیست که از `(_, _)` استفاده کنیم یا فقط از نویسه‌ی عام `_` برای تطبیق هر ترکیبی از روز و سکه؛ زیرا از نظر عملکردی یکسان هستند.
