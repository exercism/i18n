# درباره

کلاس‌هایی مانند `LocalDate` و `LocalDateTime` یک _نقطه_ در زمان را توصیف می‌کنند.
بسته‌ی `java.time` دو کلاس دیگر هم دارد که یک _مقدار_ زمان را توصیف می‌کنند:

- [`Period`][period-docs] یک بازه‌ی تاریخ‌محور است که با سال و ماه و روز سنجیده می‌شود، مثل «۲ ماه و ۵ روز».
- [`Duration`][duration-docs] یک مدتِ زمان‌محور است که با ساعت و دقیقه و ثانیه و میلی‌ثانیه و نانویانیه سنجیده می‌شود، مثل «۱ ساعت و ۳۰ دقیقه».

این تفاوت مهم است، چون واحدهای تقویمی طول ثابتی ندارند.
یک ماه می‌تواند ۲۸، ۲۹، ۳۰ یا ۳۱ روز باشد، پس «یک ماه» تعداد ثابتی ثانیه نیست.
یک `Period` از تقویم پیروی می‌کند، در حالی که یک `Duration` زمان دقیق را اندازه می‌گیرد.

| | `Period` | `Duration` |
| --- | --- | --- |
| ذخیره می‌کند | سال، ماه و روز | ثانیه و نانویانیه |
| با این‌ها به کار می‌رود | `LocalDate`، `LocalDateTime` | `LocalTime`، `LocalDateTime`، `Instant` |

هر دو کلاس «تغییرناپذیر» هستند.
متدهایی مانند `plusDays()` یا `multipliedBy()` یک نمونه‌ی _جدید_ برمی‌گردانند و نمونه‌ی اصلی را بدون تغییر می‌گذارند.

## `Period`

### ساخت یک بازه

```java
Period.ofDays(10);
// => P10D

Period.ofWeeks(2);
// => P14D

Period.ofMonths(3);
// => P3M

Period.of(1, 2, 15);
// => P1Y2M15D
```

خروجی `toString()` از [قالب مدتِ ISO-8601][iso-8601-durations] استفاده می‌کند: حرف `P` و پس از آن تعداد سال‌ها (`Y`)، ماه‌ها (`M`) و روزها (`D`).
در یک `Period` هفته وجود ندارد: `Period.ofWeeks(2)` به صورت ۱۴ روز ذخیره می‌شود.
همین نمادگذاری را می‌توان با `Period.parse()` دوباره تجزیه کرد:

```java
Period.parse("P1Y2M15D");
// => P1Y2M15D
```

### افزودن یک بازه به یک تاریخ

یک بازه با `plus()` و `minus()` به یک تاریخ اضافه یا از آن کم می‌شود:

```java
LocalDate date = LocalDate.of(2024, 3, 10);

date.plus(Period.ofMonths(2));
// => 2024-05-10

date.minus(Period.ofDays(10));
// => 2024-02-29
```

یک بازه را می‌توان به همین شکل به یک `LocalDateTime` هم اضافه کرد و ساعتِ روز ثابت می‌ماند:

```java
LocalDateTime.of(2024, 3, 10, 9, 30).plus(Period.ofMonths(1));
// => 2024-04-10T09:30
```

`Instant` تقویم ندارد، بنابراین فقط می‌توان بازه‌ای از روزها به آن اضافه کرد.
بازه‌ای که سال یا ماه داشته باشد، استثنا پرتاب می‌کند:

```java
Instant instant = Instant.parse("2024-03-10T09:30:00Z");

instant.plus(Period.ofDays(2));
// => 2024-03-12T09:30:00Z

instant.plus(Period.ofMonths(1));
// => throws UnsupportedTemporalTypeException
```

ابتدا سال‌ها اضافه می‌شوند، بعد ماه‌ها و بعد روزها.
وقتی افزودن سال یا ماه به روزی می‌رسد که وجود ندارد، نتیجه به آخرین روز معتبر همان ماه بازگردانده می‌شود:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1));
// => 2025-02-28

LocalDate.of(2024, 2, 29).plus(Period.ofYears(1));
// => 2025-02-28
```

به همین دلیل هم اگر یک بازه را اضافه و بعد دوباره کم کنید، همیشه به تاریخ اولیه نمی‌رسید:

```java
LocalDate.of(2025, 1, 31).plus(Period.ofMonths(1)).minus(Period.ofMonths(1));
// => 2025-01-28
```

### بازه‌ی میان دو تاریخ

`Period.between()` بازه‌ی میان یک تاریخ (شامل خودش) تا تاریخ دیگر (بدون احتساب آن) را برمی‌گرداند.
همین نتیجه با `LocalDate.until()` هم در دسترس است:

```java
LocalDate start = LocalDate.of(2023, 3, 10);
LocalDate end = LocalDate.of(2024, 5, 25);

Period.between(start, end);
// => P1Y2M15D

start.until(end);
// => P1Y2M15D
```

اجزای یک بازه از طریق `getYears()`، `getMonths()` و `getDays()` در دسترس‌اند.
این اجزا مستقل از هم‌اند: `getDays()` فقط بخش روزها را برمی‌گرداند، نه تعداد کل روزها.
`toTotalMonths()` سال‌ها و ماه‌ها را با هم و به صورت تعداد ماه برمی‌گرداند، اما متدی برای تعداد کل روزها وجود ندارد، چون این مقدار به ماه‌هایی بستگی دارد که در بازه دخیل‌اند.

```java
Period period = Period.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => P2M5D

period.getDays();
// => 5

period.toTotalMonths();
// => 2
```

### نرمال‌سازی یک بازه

بازه‌ای که با یکی از متدهای کارخانه‌ای ساخته می‌شود، واحدهایش را دقیقاً همان‌طور که داده شده نگه می‌دارد و `equals()` واحدها را یکی‌یکی مقایسه می‌کند.
`normalized()` ماه‌ها را به سال تبدیل می‌کند، اما به روزها کاری ندارد:

```java
Period.ofMonths(14);
// => P14M

Period.ofMonths(14).equals(Period.of(1, 2, 0));
// => false

Period.ofMonths(14).normalized();
// => P1Y2M

Period.ofDays(45).normalized();
// => P45D
```

## شمارش واحدها با `ChronoUnit`

برای گرفتن تعداد کل یک واحد مشخص میان دو نقطه در زمان، از متد `between()` روی یکی از ثابت‌های [`ChronoUnit`][chronounit-docs] استفاده کنید:

```java
LocalDate start = LocalDate.of(2024, 1, 15);
LocalDate end = LocalDate.of(2024, 3, 20);

ChronoUnit.DAYS.between(start, end);
// => 65

ChronoUnit.WEEKS.between(start, end);
// => 9

ChronoUnit.MONTHS.between(start, end);
// => 2
```

فقط واحدهای کامل شمرده می‌شوند و اگر آرگومان دوم پیش از آرگومان اول باشد، نتیجه منفی است:

```java
ChronoUnit.DAYS.between(end, start);
// => -65
```

`ChronoUnit` با واحدهای زمان‌محور و تاریخ‌زمان‌ها هم کار می‌کند:

```java
ChronoUnit.MINUTES.between(
    LocalDateTime.of(2024, 3, 10, 18, 5),
    LocalDateTime.of(2024, 3, 10, 19, 40));
// => 95
```

## `Duration`

### ساخت یک مدت

```java
Duration.ofMinutes(90);
// => PT1H30M

Duration.ofSeconds(3725);
// => PT1H2M5S

Duration.ofDays(2);
// => PT48H

Duration.ofHours(2).plusMinutes(15);
// => PT2H15M
```

در نمادگذاری ISO-8601، حرف `T` بخش تاریخ را از بخش زمان جدا می‌کند.
یک `Duration` بخش تاریخ ندارد، پس خروجی `toString()` آن همیشه با `PT` آغاز می‌شود.
`Duration.ofDays()` هر روز را دقیقاً ۲۴ ساعت در نظر می‌گیرد.

یک مدت را می‌توان با `Duration.parse()` هم تجزیه کرد:

```java
Duration.parse("PT1H30M");
// => PT1H30M
```

### افزودن یک مدت به یک زمان

یک مدت با `plus()` و `minus()` به یک `LocalTime`، یک `LocalDateTime` یا یک `Instant` اضافه یا از آن کم می‌شود:

```java
LocalDateTime start = LocalDateTime.of(2024, 3, 10, 22, 30);

start.plus(Duration.ofMinutes(90));
// => 2024-03-11T00:00

LocalTime.of(23, 0).plus(Duration.ofHours(2));
// => 01:00
```

همان‌طور که مثال آخر نشان می‌دهد، `LocalTime` از نیمه‌شب عبور می‌کند و دوباره از ابتدا شروع می‌شود.

`LocalDate` زمانی ندارد، بنابراین نمی‌توان آن را با یک `Duration` ترکیب کرد:

```java
LocalDate.of(2024, 3, 10).plus(Duration.ofHours(1));
// => throws UnsupportedTemporalTypeException
```

### مدت میان دو زمان

`Duration.between()` مقدار دقیق زمان میان دو زمان یا دو تاریخ‌زمان را برمی‌گرداند:

```java
LocalDateTime checkIn = LocalDateTime.of(2024, 3, 10, 18, 5);
LocalDateTime checkOut = LocalDateTime.of(2024, 3, 10, 19, 40);

Duration.between(checkIn, checkOut);
// => PT1H35M

Duration.between(checkOut, checkIn);
// => PT-1H-35M
```

`Duration.between()` دو مقدار `LocalDate` را نمی‌پذیرد، چون یک تاریخ ثانیه‌ای برای اندازه‌گیری ندارد:

```java
Duration.between(LocalDate.of(2024, 1, 15), LocalDate.of(2024, 3, 20));
// => throws UnsupportedTemporalTypeException
```

برای تاریخ‌ها به جای آن از `Period.between()` یا `ChronoUnit.DAYS.between()` استفاده کنید.

### تبدیل یک مدت

متدهای `toXxx()` یک مدت را به مقدار _کل_ یک واحد تبدیل می‌کنند و آن را به سمت پایین گرد می‌کنند:

```java
Duration duration = Duration.ofSeconds(5730); // 1 hour, 35 minutes and 30 seconds

duration.toHours();
// => 1

duration.toMinutes();
// => 95

duration.toSeconds();
// => 5730
```

متدهای `toXxxPart()` یک مدت را، مانند یک ساعت، به اجزایش تقسیم می‌کنند:

```java
Duration duration = Duration.ofSeconds(5730);

duration.toHoursPart();
// => 1

duration.toMinutesPart();
// => 35

duration.toSecondsPart();
// => 30
```

`toHoursPart()` تا ۲۳ می‌رود و بیشتر نمی‌شود، چون ساعت‌های بالاتر را `toDaysPart()` می‌شمارد.

### مقایسه و محاسبه با مدت‌ها

مدت‌ها را می‌توان با `compareTo()` مقایسه کرد و با `isZero()` و `isNegative()` بررسی کرد:

```java
Duration visit = Duration.ofMinutes(95);
Duration limit = Duration.ofHours(2);

visit.compareTo(limit) > 0;
// => false

Duration.between(LocalTime.of(10, 0), LocalTime.of(9, 0)).isNegative();
// => true
```

مدت‌ها از عملیات حسابی هم پشتیبانی می‌کنند، مثل `plus()`، `minus()`، `multipliedBy()` و `dividedBy()`:

```java
Duration.ofMinutes(20).multipliedBy(3);
// => PT1H

Duration.ofHours(2).dividedBy(Duration.ofMinutes(15));
// => 8
```

## `Period` یا `Duration`؟

برای یک `LocalDate` یا یک `LocalTime`، انتخاب از پیش مشخص است: تاریخ زمانی برای اندازه‌گیری ندارد و زمان تقویمی ندارد.
یک `LocalDateTime` هر دو را دارد، اما منطقه‌ی زمانی ندارد، بنابراین افزودن `Period.ofDays(1)` یا `Duration.ofDays(1)` به آن نتیجه‌ی یکسانی می‌دهد.
تفاوت با منطقه‌های زمانی آشکار می‌شود.
وقتی ساعت‌ها برای وقت تابستانی به جلو می‌روند، یک روز تقویمی فقط ۲۳ ساعت است:

```java
ZonedDateTime noon = ZonedDateTime.of(2025, 3, 29, 12, 0, 0, 0, ZoneId.of("Europe/Amsterdam"));

noon.plus(Period.ofDays(1));
// => 2025-03-30T12:00+02:00[Europe/Amsterdam]

noon.plus(Duration.ofDays(1));
// => 2025-03-30T13:00+02:00[Europe/Amsterdam]
```

افزودن یک `Period` یک‌روزه ساعتِ روز را حفظ می‌کند، در حالی که افزودن یک `Duration` یک‌روزه دقیقاً ۲۴ ساعت اضافه می‌کند.
برای مقدارهایی که مردم به شکل تقویمی به آن‌ها فکر می‌کنند («همین ساعت، ماه بعد») از `Period` استفاده کنید و برای زمان سپری‌شده («بلیت پارکینگ ۲ ساعت اعتبار دارد») از `Duration`.
