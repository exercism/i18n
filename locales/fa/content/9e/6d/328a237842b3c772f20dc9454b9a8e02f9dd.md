# مقدمه

همان‌طور که در مفهوم [`Nothingness`][concept-nothingness] بررسی شد، R روش‌های گوناگونی برای نمایش داده‌هایی دارد که غایب (`NULL`)، نامعلوم (`NA`) یا از نظر ریاضی نامعتبر (`NaN`، `Inf`) هستند.
به‌طور کلی، R تلاش می‌کند با استفاده از این‌ها مشکل را در همان‌جا علامت‌گذاری کند و بدون ایجاد استثنا ادامه دهد.

## `stop()`

بعضی مشکلات آن‌قدر بنیادی هستند که نمی‌توان اجازه داد برنامه ادامه یابد.
در این حالت، از `stop(msg)` استفاده کنید تا برنامه بی‌درنگ با یک `Error` متوقف شود و `msg` چاپ شود.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

مشابه `assert` در زبان‌های دیگر، این تابع پوششی مناسب برای `stop()` است.
پارامترهای آن تعدادی دلخواه از شرط‌های منطقی هستند که با کاما از هم جدا شده‌اند و برنامه تنها در صورتی ادامه می‌یابد که همه‌ی آن‌ها `TRUE` باشند.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R روش‌های گوناگونی برای مدیریت خطاها دارد.
این روش‌ها بر پایه‌ی Common Lisp هستند و تفاوت چشمگیری با بسیاری از زبان‌های پرکاربرد دارند.

ساده‌ترین روش این است که کدی را که ممکن است مشکل‌ساز باشد در `try()` بپیچید.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
#> Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## `warning()` و `message()`

این‌ها پاسخ‌هایی به شرایط غیرکشنده هستند، برای نمونه:

- هشدار دادن درباره‌ی مشکلی که برنامه می‌تواند دست‌کم تا حدی از آن بهبود یابد.
- آگاه کردن کاربر از پیشرفت برنامه‌ای که مدت‌ها اجرا می‌شود.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

تابع `suppressWarnings()` گاهی می‌تواند در Exercism مفید باشد، تا از سردرگم شدن تست‌رانر با خروجی ناخواسته جلوگیری شود.
