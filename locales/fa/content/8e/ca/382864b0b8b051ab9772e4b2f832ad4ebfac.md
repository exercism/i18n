# Testها

هر تمرین Testهای واحد و یک دستور ساخت CMake را در اختیار شما می‌گذارد. پیاده‌سازی را شما ارائه می‌دهید.
هر فایل Test قرار است در برابر پیاده‌سازی شما لینک شود تا یک فایل اجرایی کنسولی بسازد که Testها را اجرا می‌کند. اجرای فایل اجرایی Test برای هر Test ناموفق پیامی چاپ می‌کند و وقتی Testها شکست بخورند، یک وضعیت خروج غیرصفر گزارش می‌دهد.

نام فایل Test به شکل `<exercise>_test.f90` خواهد بود؛ بنابراین برای تمرین «Bob» فایلی که Testها را در خود دارد `bob_test.f90` است. هر Test یک توضیح دارد که آن Test را توصیف می‌کند و سپس خود Test که با `call assert_equal` شروع می‌شود، مثل:

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

برای غیرفعال کردن یک Test، کافی است آن را با یک `'!'` به‌صورت توضیح درآورید، مثل:

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

کار کردن روی هر تمرین این مراحل را دارد:

* ساخت اولیه با CMake
* برای هر Test واحد:
 * خطاهای کامپایل را برطرف کنید تا Test اجرا شود و شکست بخورد.
 * فقط به اندازه‌ای پیاده‌سازی کنید که Test قبول شود.
 * پیاده‌سازی خود را بازآرایی کنید تا خوانایی بیشتر شود، تکرار کاهش یابد و مواردی از این دست.
 * Test بعدی را از حالت توضیح خارج کنید


## ساخت اولیه با CMake

هر تمرین در کنار Testهای واحد یک فایل `CMakeLists.txt` هم دارد. این فایل دستور ساخت آماده‌ی CMake را در خود دارد که کار ساخت را برایتان انجام می‌دهد. نیازی نیست این فایل را ویرایش کنید. دستور ساخت ارائه‌شده فرض می‌کند که پیاده‌سازی شما در یک فایل سورس هم‌نام تمرین قرار دارد.

برای نمونه، تمرین «Bob» انتظار دارد پیاده‌سازی در فایل `bob.f90` باشد.

**فایل‌های پیاده‌سازی اولیه‌تان را پیش از اجرای CMake بسازید.**
اگر هنگام اجرای CMake برای تمرین «Bob» فایل `bob.f90` را نداشته باشید، CMake خطایی درباره پیدا نشدن فایل‌ها تولید می‌کند.
**این فایل‌ها می‌توانند خالی باشند، اما باید وجود داشته باشند.**

با استفاده از این دستور ساخت، CMake می‌تواند با اجرای `cmake -G` همراه با یک generator مناسب و مسیر پوشه‌ی تمرین، پروژه‌ی مناسبی برای محیط شما بسازد. CMake یک اسکریپت ساخت مناسب سیستم‌عامل شما تولید می‌کند. برای جدا نگه داشتن این فایل‌های تولیدشده از سورس Code تمرین‌تان، معمول است که پوشه‌ای به نام `build` بسازید تا هم این فایل‌های ساخت تولیدشده و هم Code کامپایل‌شده را در خود جای دهد.

این کار پوشه‌ی تمرین شما را مرتب و بدون شلوغی نگه می‌دارد.

**نکته: نخستین باری که `cmake` فراخوانی شود، [testlib](###-Testlib) به‌طور خودکار دانلود می‌شود. وجود `testlib` برای کار کردن Testهای واحد لازم است.

از آنجا که برای هر تمرین CMake را اجرا می‌کنید تا دستورهای ساخت را بسازید، ممکن است بخواهید برای این دستور یک اسکریپت bash (Linux/MacOS) یا یک فایل batch (Windows) بسازید.

وقتی CMake محیط ساخت را ایجاد کرد، می‌توانید Code خود را با دستور مناسب محیط‌تان بسازید:

* Linux با make: `make`
* Windows با Visual Studio: از منو گزینه‌ی Build / Build Solution را انتخاب کنید.
* Windows با MingW: `mingw32-make.exe`
* Windows با nMake: `nmake.exe`
* MacOS با Xcode: از نوار ابزار گزینه‌ی Build را انتخاب کنید.

نمونه‌هایی از اجرای CMake در محیط‌های مختلف در ادامه آمده است.

### Linux\MacOS با Make

نام generator برای CMake برابر `Unix Makefiles` است.
با فرض اینکه تمرین فعلی `bob` است و در پوشه‌ی تمرین قرار داریم:

```
$ touch bob.f90
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

این نمونه ساخت فایل‌های خالی برای پیاده‌سازی را پیش از اجرای CMake نشان می‌دهد.

برای کامپایل کردن Testها کافی است در پوشه‌ی build دستور make را تایپ کنید. این کار باید خطاهای زمان کامپایل را تولید کند. پس از رفع خطاها یک بار دیگر `make` را اجرا کنید. وقتی همه‌ی خطاهای ساخت رفع شدند، Testها را اجرا کنید:

```
$ ctest -V
```
### Windows با Visual Studio 2017

نام generator برای CMake برابر `Visual Studio 15` است. همین generator از همه‌ی نسخه‌های IDE مربوط به Visual Studio 2017 پشتیبانی می‌کند: Community، Professional و Enterprise. با فرض اینکه تمرین فعلی `bob` است و در پوشه‌ی تمرین قرار داریم:

```
> copy nul: bob.f90
> mkdir build
> cd build
> cmake -G "Visual Studio 15" ..
```

این نمونه ساخت فایل‌های خالی برای پیاده‌سازی را پیش از اجرای CMake نشان می‌دهد.

### Testlib

Testها به یک کتابخانه‌ی کوچک به نام `testlib` وابسته‌اند که نخستین بار که ساخت با cmake پیکربندی می‌شود، از github دانلود می‌شود.

اگر دانلود ناموفق بود، می‌توانید آن را به‌صورت دستی انجام دهید، مثل:

```
mkdir testlib
cd testlib
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/CMakeLists.txt
wget https://raw.githubusercontent.com/exercism/fortran/master/testlib/TesterMain.f90
```
