# راهنمای سبک C

این راهنما سبکی را توصیف می‌کند که برای استفاده در فایل‌های نمونه و آزمونِ تمرین‌های مسیر C در نظر گرفته شده است.

قواعد این راهنما مکمل قواعدی است که فایل [.clang-format][] تعیین کرده است، یا برای تأکید بر آن‌ها آمده است.

## استاندارد C

کد باید با استاندارد C99، که نام رسمی‌تر آن ISO/IEC 9899:1999 است، سازگار باشد.
نباید از POSIX، یا در غیر این صورت از توابع کتابخانه‌ای غیراستاندارد، انواع یا ارجاع‌های دیگری که خارج از پیاده‌سازی‌اند استفاده شود.

## اسم‌ها

به طور کلی، اسم انواع، متغیرها، ساختارها و فایل‌ها باید به صورت «snake case» نوشته شود: همه‌ی حروف کوچک، و اجزای اسم با زیرخط `_` از هم جدا می‌شوند.

```c
void some_foo_function(char * input_string, int input_string_length);
```

### شمارشی‌ها

اسم‌های شمارشی معمولاً باید مفرد باشند، نه جمع.

برچسب‌های شمارشی باید به صورت «snake case» با همه‌ی حروف بزرگ نوشته شوند.

```c
enum heading {
    HEADING_NORTH,
    HEADING_EAST,
    HEADING_SOUTH,
    HEADING_WEST
}
```

### ماکروها

ماکروهایی که ثابت تعریف می‌کنند با «snake case» و همه‌ی حروف بزرگ نام‌گذاری می‌شوند.

```c
#define CONSTANT 0x4000
```

استفاده از «snake case» با حروف بزرگ برای اسم ماکروها پسندیده است، اما ماکروهایی که شبیه تابع‌اند می‌توانند با «snake case» و حروف کوچک نام‌گذاری شوند.

### انواع

انواع استاندارد با عرض ثابت (در `stdint.h`) بر انواع صحیح پایه ترجیح داده می‌شوند.

نوع `bool` (از `stdbool.h`) بر `_Bool` ترجیح داده می‌شود.

به همین ترتیب، برای نمایش کمیت‌های مرتبط با حافظه، `size_t` و `ptrdiff_t` (از `stddef.h`) ترجیح داده می‌شوند.

انواعی که یک برنامه با `typedef` تعریف می‌کند باید با پسوند `_t` نام‌گذاری شوند.
هرچند می‌دانیم که POSIX پسوند `_t` را رزرو کرده است، این مسیر در حال حاضر از POSIX استفاده نمی‌کند.

## محافظ‌های `include`

باید در همه‌ی فایل‌های هدر از محافظ `include` استفاده شود.

معمولاً یک مجموعه محافظ `include` باید کل محتوای هدر را در بر بگیرد.

محافظ‌های موجود در پیاده‌سازی نمونه (`.meta/example.h`) و اسکلت تمرین (`exercise_name.h`) باید از اسم ماکروهایی استفاده کنند که از اسم تمرین پیروی می‌کنند.
اسم ماکروهای محافظ باید درباره‌ی حروف بزرگ و کوچک از قاعده‌ی بالا برای ماکروها پیروی کنند.

برای مثال، برای تمرین `hello-world` از این استفاده کنید:

```c
#ifndef HELLO_WORLD_H
#define HELLO_WORLD_H

//...

#endif
```

## پارامترها

پارامترهای تابع باید هم در اعلان و هم در تعریف همه‌ی توابع نام‌گذاری شوند.
این موضوع برای فایل‌های `.c` و `.h` هر دو صادق است.
اسم‌های به‌کاررفته باید در همه‌ی موارد یکسان باشند.
یعنی هرچند پروتوتایپ تابع زیر C معتبر است، سبک آن نادرست است چون پارامتر نامی ندارد: `void foo(int);`.
پروتوتایپ درست، به شرط اینکه همه‌ی اعلان‌های دیگر و تعریف هم از اسم پارامتر `bar` استفاده کنند، `void foo(int bar);` خواهد بود.

هرجا این کار ساده‌تر یا مناسب‌تر باشد، پارامترهایی که باید آرگومان را به صورت مقدار و نه با اشاره‌گر دریافت کنند ترجیح داده می‌شوند.
به‌ویژه توجه کنید که این شامل پارامترهای نوع `struct` هم می‌شود.

اگر انتظار نمی‌رود که دانشجو مقادیر یک پارامتر اشاره‌گری را در پیاده‌سازی خود تغییر دهد، آن پارامتر باید با `const` مقید شود.

## چیدمان فایل آزمون

فایل آزمون هر تمرین از چیدمان خاصی پیروی می‌کند.
این چیدمان هم به مشارکت‌کنندگان کمک می‌کند بخش‌های فایل را تشخیص دهند و هم به یادگیرندگان کمک می‌کند بفهمند آزمون‌ها چطور کار می‌کنند.

فایل آزمون، مانند بیشتر فایل‌های مبدأ C، با دستورهای `#include` آغاز می‌شود.

```c
#include "vendor/unity.h"
#include "../src/file_under_test.h"
// any other includes here
```

پس از آن نوبت به توابع `setUp()` و `tearDown()` می‌رسد.
تا اینجا هیچ تمرینی از این دو استفاده نمی‌کند (بدنه‌ی توابع خالی است)، اما باید سر جای خود بمانند تا فایل‌های آزمون روی همه‌ی پلتفرم‌ها درست کامپایل شوند.

```c
void setUp(void)
{
}

void tearDown(void)
{
}
```

سپس هر تابع کمکی که توابع آزمون از آن استفاده می‌کنند می‌آید.
اسم چنین توابع کمکی نباید از پیشوند `test_` استفاده کند.

بعد از آن، خود توابع آزمون قرار دارند.
اسم این توابع از پیشوند `test_` استفاده می‌کند.
به‌جز تابع آزمون اول، هر تابع آزمون باید `TEST_IGNORE();` را به‌عنوان نخستین دستور خود داشته باشد.
پس از نخستین مورد از این دستور باید توضیح خطی `// delete this line to run test` بیاید.

برای مثال:

```c
static void test_the_first(void)
{
   test_first_foo();
}

static void test_the_second(void)
{
   TEST_IGNORE();               // delete this line to run test
   test_second_foo();
}

static void test_the_third(void)
{
   TEST_IGNORE();
   char grade = 'A';
   test_third_foo(grade);
}
```

در پایان فایل، تابع `main()` قرار دارد.
بدنه‌ی تابع `main` هم خودش از چیدمان خاصی پیروی می‌کند.
ابتدا یک فراخوانی `UNITY_BEGIN()` و بعد از آن یک خط خالی، سپس آزمون‌ها.
پس از آخرین آزمون هم یک خط خالی دیگر می‌آید و بعد نتیجه‌ی `UNITY_END()` برگردانده می‌شود.

```c
int main(void)
{
    UNITY_BEGIN();

    RUN_TEST(test_foo);
    RUN_TEST(test_bar);

    return UNITY_END();
}
```
