# مقدمه

`Complex numbers` پیچیده نیستند.
فقط به اسمی نیاز دارند که کمتر نگران‌کننده باشد.

آن‌ها چنان مفیدند، به‌ویژه در مهندسی و علوم، که Julia اعداد مختلط را در کنار اعداد صحیح و اعداد ممیز شناور، به عنوان انواع عددی استاندارد گنجانده است.

## مبانی

یک مقدار `complex` در Julia در اصل یک جفت عدد است: معمولاً ولی نه همیشه ممیز شناور.
به این دو، بنا به دلایل تاریخی نامبارک، بخش «حقیقی» و بخش «موهومی» می‌گویند.
باز هم بهتر است به‌جای اسم‌های عجیب، روی سادگی بنیادین تمرکز کنید.

برای ساختن اعداد مختلط از دو عدد حقیقی، کافی است پسوند `im` را به بخش موهومی اضافه کنید.

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im
julia> typeof(z)
ComplexF64 (alias for Complex{Float64})
julia> zi = 1 + 2im
1 + 2im
julia> typeof(zi)
Complex{Int64}
```

بنابراین انواع مختلف `Complex` وجود دارد که از نوع متناظر صحیح یا ممیز شناور مشتق می‌شوند.

برای ساختن یک عدد مختلط از متغیرهای حقیقی، روش نگارش بالا کار نمی‌کند.
نوشتن `a + bim` باعث می‌شود تجزیه‌گر فکر کند `bim` اسم یک متغیر (ناموجود) است.

نوشتن `b*im` ممکن است، اما روش ترجیحی از تابع `complex()` استفاده می‌کند که نیازی به عملیات ضرب و جمع ندارد.

```julia-repl
julia> a = 1.2; b = 3.4; complex(a, b)
1.2 + 3.4im
```

برای دسترسی جداگانه به بخش‌های یک عدد مختلط:

```julia-repl
julia> z = 1.2 + 3.4im
1.2 + 3.4im
julia> real(z)
1.2
julia> imag(z)
3.4
```

یا با هم:

```julia-repl
julia> reim(z)
(1.2, 3.4)
```

هر کدام از این دو بخش می‌تواند صفر باشد و ریاضی‌دانان آن‌وقت ممکن است بگویند عدد «تماماً حقیقی» یا «تماماً موهومی» است.
با این حال، در Julia هنوز یک عدد مختلط است.

```julia-repl
julia> zr = 1.2 + 0im
1.2 + 0.0im
julia> typeof(zr)
ComplexF64 (alias for Complex{Float64})
julia> zi = 3.4im
0.0 + 3.4im
julia> typeof(zi)
ComplexF64 (alias for Complex{Float64})
```

شاید شنیده باشید که «`i` (یا `j`) جذر ۱- است».

فعلاً تنها معنای این حرف آن است که بخش موهومی _طبق تعریف_ در برابری زیر صدق می‌کند:

```julia-repl
julia> 1im * 1im == -1
true
```

این ایده‌ی سادگی است، اما به نتایج جالبی می‌رسد.

## حساب

همه‌ی `operators` استاندارد ریاضی و توابع ابتدایی که با اعداد ممیز شناور و صحیح به کار می‌روند، با اعداد مختلط هم کار می‌کنند. یک نمونه‌ی کوچک:

```julia-repl
julia> z1 = 1.5 + 2im
1.5 + 2.0im
julia> z2 = 2 + 1.5im
2.0 + 1.5im
julia> z1 + z2  # addition
3.5 + 3.5im
julia> z1 * z2  # multiplication
0.0 + 6.25im
julia> z1 / z2  # division
0.96 + 0.28im
julia> z1^2  # exponentiation
-1.75 + 6.0im
julia> 2^z1  # another exponentiation
0.5188946835878313 + 2.7804223253571183im
```

## توابع

چندین تابع، علاوه بر `real()` و `imag()`، وجود دارد که به‌طور ویژه برای اعداد مختلط اهمیت دارند.

- `conj()` به‌سادگی علامت بخش موهومی یک عدد مختلط را معکوس می‌کند (_از + به - یا برعکس_).
    - به دلیل نحوه‌ی کار ضرب مختلط، این کار مفیدتر از آن است که فکر می‌کنید.
- `abs(<complex number>)` تضمین می‌شود که یک عدد حقیقی بدون بخش موهومی برگرداند.
- `abs2(<complex number>)` مربع `abs(<complex number>)` را برمی‌گرداند: محاسبه‌اش از `abs()` سریع‌تر است و اغلب همان چیزی است که یک محاسبه لازم دارد.
- `angle(<complex number>)` زاویه‌ی فاز را بر حسب رادیان برمی‌گرداند.

```julia-repl
julia> z1
1.5 + 2.0im
julia> conj(z1)
1.5 - 2.0im
julia> abs(z1)
2.5
julia> abs2(z1)
6.25
julia> angle(z1)
0.9272952180016122
```
توضیحی جزئی، برای علاقه‌مندان به ریاضیات:

- نمایش `(real, imag)` برای `z1` در واقع از مختصات دکارتی روی صفحه‌ی مختلط استفاده می‌کند.
- همان عدد مختلط را می‌توان با نمادگذاری `(r, θ)` و با استفاده از مختصات قطبی نمایش داد.
- در اینجا، `r` و `θ` به‌ترتیب با `abs(z1)` و `angle(z1)` به دست می‌آیند.

در اینجا مثالی با استفاده از چند ثابت آورده شده است:

```julia-repl
julia> euler = exp(1im * π)
-1.0 + 1.2246467991473532e-16im
julia> real(euler)
-1.0
julia> round(imag(euler), digits=15)  # round to 15 decimal places
0.0
```

نمادگذاری قطبی `(r, θ)` چنان مفید است که توابع توکار `cis` (کوتاه‌شده‌ی `cos(x) + isin(x)`) و `cispi` (کوتاه‌شده‌ی `cos(πx) + isin(πx)`) وجود دارند که می‌توانند به ساختن آن به شکلی کارآمدتر کمک کنند.

فایده‌ی نمادگذاری قطبی در فرمول زیبای اویلر دیده می‌شود: `ℯ^(iθ) = cos(θ) + isin(θ) = x + iy`، که در آن `|x + iy| = 1`.
با `|x + iy| = r`، به شکل قطبی کلی‌ترِ `r * ℯ^(iθ) = r * (cos(θ) + isin(θ)) = x + iy` می‌رسیم.
توجه کنید که شکل نمایی، به‌ویژه، فشرده و دستکاری‌اش آسان است.

```julia-repl
julia> exp(1im * π) ≈ cis(π) ≈ cispi(1)
true
```

برابری تقریبی بالا به این دلیل است که توابع `cis` و `cispi` می‌توانند خروجی‌های عددی بهتری بدهند، به‌ویژه `cispi` هنگام کار با آرگومان‌هایی که مضارب دلخواه π هستند (مثلاً رادیان!).

```julia-repl
julia> cis(π)
-1.0 + 0.0im
julia> cispi(1)
-1.0 + 0.0im
julia> θ = π/2;
julia> exp(im*θ)
6.123233995736766e-17 + 1.0im
julia> cis(θ)
6.123233995736766e-17 + 1.0im
julia> cispi(θ / π)  # θ/π == 1/2
0.0 + 1.0im
```

اتفاقاً همین باعث می‌شود اعداد مختلط برای انجام چرخش‌ها و جابه‌جایی‌های شعاعی در فضای دوبعدی بسیار مفید باشند.

برای چرخش‌ها، عدد مختلط `z = x + iy` را می‌توان با یک ضرب ساده به اندازه‌ی زاویه‌ی `θ` حول مبدأ چرخاند: `z * ℯ^(iθ)`.
توجه کنید که `x` و `y` در اینجا فقط مختصات معمول روی صفحه‌ی دکارتی دوبعدی حقیقی هستند، و یک زاویه‌ی مثبت به چرخشی *پادساعتگرد* می‌انجامد در حالی که یک زاویه‌ی منفی چرخشی *ساعتگرد* می‌دهد.

به همین سادگی، می‌توان یک جابه‌جایی شعاعی `Δr` را با اضافه کردن آن به اندازه‌ی `r` یک عدد مختلط در شکل قطبی انجام داد (مثلاً `z = r * ℯ^(iθ)` -> `z' = (r + Δr) * ℯ^(iθ)`).
توجه کنید که بخش زاویه‌ای ثابت می‌ماند و فقط اندازه، `r`، همان‌طور که انتظار می‌رود، تغییر می‌کند.
