# مقدمه

بیشتر اوقات، Factor تکرار را با ترکیبگرهایی مثل `each`، `map` و `count` انجام می‌دهد. اما گاهی تمیزترین راه برای بیان یک محاسبه، **«بازگشت»** است، یعنی واژه‌ای که خودش را فراخوانی می‌کند.

## تعریف یک واژه‌ی بازگشتی

یک تعریف `:` می‌تواند خودش را مستقیم فراخوانی کند:

```factor
: count-down ( n -- )
    dup 0 = [ drop ] [ dup . 1 - count-down ] if ;

5 count-down
! prints 5 4 3 2 1
```

## انشعاب بر اساس خالی بودن یا نبودن

`if-empty` (در [`sequences`][sequences]) حالت پایه‌ی طبیعی برای بازگشت است:

```
if-empty ( seq emptyquot nonemptyquot -- )
```

```factor
{ 4 0 9 } [ "empty" ] [ "got data" ] if-empty .
! => "got data"
```

`emptyquot` در حالی اجرا می‌شود که دنباله‌ی (خالی) پیش‌اپیش مصرف شده است؛ `nonemptyquot` در حالی اجرا می‌شود که دنباله هنوز روی پشته است.

## `cond`، زنجیره‌ای از شاخه‌های شرطی

وقتی بازگشت شما بیش از دو حالت دارد، `cond` (در [`combinators`][combinators]) کد را خوانا نگه می‌دارد:

```factor
: classify ( n -- label )
    {
        { [ dup 0 < ] [ drop "negative" ] }
        { [ dup 0 = ] [ drop "zero"     ] }
        [ drop "positive" ]
    } cond ;
```

## ارجاع رو به جلو با `DEFER:`

یک تعریف `:` می‌تواند خودش را مستقیم فراخوانی کند، اما وقتی دو واژه *یکدیگر* را فراخوانی می‌کنند، تجزیه‌گر واژه‌ی اول را پیش از آن‌که دومی وجود داشته باشد می‌بیند. `DEFER:` اسمی را رزرو می‌کند تا تعریف اول بتواند کامپایل شود:

```factor
DEFER: even?

: odd? ( n -- ? ) dup 0 = [ drop f ] [ 1 - even? ] if ;
: even? ( n -- ? ) dup 0 = [ drop t ] [ 1 - odd? ] if ;
```

`DEFER:` همچنین وقتی به کار می‌آید که خواندن یک واژه‌ی کمکی *بعد از* واژه‌ای که از آن استفاده می‌کند طبیعی‌تر باشد.
