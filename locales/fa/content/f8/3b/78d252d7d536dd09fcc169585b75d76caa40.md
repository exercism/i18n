# مقدمه

حافظه معمولاً توسط سیستم‌عامل (OS) در قالب یک چیدمان کلی برای یک برنامه نگاشت می‌شود:

| آدرس | ناحیه‌ی حافظه |
| :-----: | :--------------------- |
|  بالا   | پشته                  |
|         | ...                    |
|         | هیپ                   |
|         | قطعه‌ی خواندن و نوشتن |
|         | قطعه‌ی کد/فقط‌خواندنی |
|   پایین   | رزرو‌شده               |

حافظه در قالب قطعه‌ها به بخش‌هایی با مجوزهای متفاوت تقسیم می‌شود.

توابعی که تا اینجا تعریف کرده‌ایم، همه در **section .text** بودند. این بخش داده‌ی فقط‌خواندنیِ قابل اجرا را نگه می‌دارد. بخش‌های دیگر برای اعلان متغیرهای داده به کار می‌روند؛ این متغیرها ممکن است فقط‌خواندنی یا خواندنی و نوشتنی باشند، اما قابل اجرا نیستند.

## بخش .data

داده‌ی مقداردهی‌شده در **section .data** اعلان می‌شود.

در NASM (همان Netwide Assembler، اسمبلری که این ترک از آن استفاده می‌کند)، یک متغیر مقداردهی‌شده یک اسم، یک دستورالعمل که اندازه‌ی داده را مشخص می‌کند، و فهرستی از مقادیر جداشده با کاما دارد. هر یک از این‌ها با یک فاصله از دیگری جدا می‌شود و برچسب می‌تواند به‌صورت اختیاری با یک `:` دنبال شود.

دستورالعمل‌های اصلی و اندازه‌های داده‌ی مربوط به آن‌ها عبارت‌اند از:

| دستورالعمل | اندازه |
| :-------: | :------ |
|    db     | ۱ بایت  |
|    dw     | ۲ بایت |
|    dd     | ۴ بایت |
|    dq     | ۸ بایت |

برای نمونه، این یک متغیر بایتی به اسم `space` با مقدار `10` اعلان می‌کند:

```x86asm
section .data
    space db 10
```

متغیرهایی که در `section .data` اعلان می‌شوند تغییرپذیرند، یعنی خواندنی و نوشتنی. این متغیرها همچنین طول عمر ذخیره‌سازی _ایستا_ دارند، یعنی در تمام مدت اجرای برنامه وجود دارند.

## بخش .rodata

**section .rodata** مشابه `section .data` است. هر دو بخش شامل داده‌ی مقداردهی‌شده‌اند که به یک شکل اعلان می‌شود و طول عمر ذخیره‌سازی یکسانی دارد.

تفاوت اصلی آن‌ها این است که داده‌ی `section .rodata` تغییرناپذیر است، یعنی فقط‌خواندنی.

~~~~exercism/note
ثابت‌هایی که با `equ` تعریف می‌شوند با ثابت‌های تعریف‌شده در `section .rodata` فرق دارند.

ثابتی که با `equ` تعریف می‌شود فضایی از حافظه را اشغال نمی‌کند و اسمبلر مستقیماً مقدارش را جای آن می‌گذارد.
در واقع، این یک جای‌نگهدار برای آن مقدار است.

در مقابل، ثابت‌های تعریف‌شده در `section .rodata` واقعاً در حافظه ذخیره می‌شوند و یک آدرس دارند.
~~~~

## دسترسی به داده

### برچسب‌ها و ارجاع غیرمستقیم

داده‌ی اعلان‌شده باید اسمی داشته باشد که به آن نسبت داده شود. به این اسم **«برچسب»** می‌گویند.

برچسب نمادی است که آدرس مشخص داده در حافظه را کدگذاری می‌کند. **آدرس‌ها در x86-64 مقادیری ۶۴ بیتی هستند**.

در NASM، اگر بخواهید با برچسب مستقیماً به داده دسترسی پیدا کنید، حافظه‌ی تخصیص‌یافته را به دست نمی‌آورید، بلکه آدرس آن را به دست می‌آورید:

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

برای دسترسی به محتوای یک آدرس حافظه، لازم است آن را _ارجاع‌زدایی کنید_. به این کار **«ارجاع غیرمستقیم»** می‌گویند.

در NASM، این کار با `[]` انجام می‌شود:

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

اما موقعیت‌هایی هست که در آن‌ها اندازه‌ی حافظه‌ی ارجاع‌زدایی‌شده مبهم می‌شود. در چنین مواردی باید از یک پیشوند که این اندازه را مشخص می‌کند استفاده کرد.

این‌ها مهم‌ترین پیشوندها و اندازه‌هایشان در یک برنامه‌ی معمول x86-64 هستند:

| پیشوند | اندازه |
| :----- | :------ |
| byte   | ۱ بایت  |
| word   | ۲ بایت |
| dword  | ۴ بایت |
| qword  | ۸ بایت |

همان بارگذاری را می‌توان با ذکر صریح اندازه نوشت:

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

هنگام ارجاع‌زدایی از حافظه، همیشه از یک پیشوند استفاده کنید؛ این یک رویه‌ی خوب است.

### نوشتن در حافظه

نوشتن در حافظه هم به همان شکل، یعنی با ارجاع‌زدایی از یک آدرس، انجام می‌شود:

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

توجه کنید که در بیشتر دستورالعمل‌ها می‌توانید از عملوندهای حافظه استفاده کنید، بدون آنکه ابتدا محتوا را در یک ثبات بارگذاری کنید. اما معمولاً نمی‌توان از آن‌ها هم در عملوند مبدأ و هم در عملوند مقصد استفاده کرد؛ فقط یکی از این دو ممکن است:

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### دستورالعمل LEA

هرچند می‌توان از `mov` برای ذخیره‌ی آدرس یک متغیر در یک ثبات استفاده کرد، دستورالعمل‌ای هست که دقیقاً همین هدف را دنبال می‌کند: **lea**.

این دستورالعمل از یک عملوند به شکل حافظه استفاده می‌کند، اما حافظه را _نمی‌خواند_. در عوض، عبارت آدرس مؤثر را محاسبه می‌کند و نتیجه را در عملوند مقصد می‌نویسد:

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

معمول‌تر است که از `lea` برای محاسبه و ذخیره‌ی آدرس‌های حافظه در ثبات‌ها استفاده کنید.

### آدرس‌دهی نسبی

هنگام دسترسی به مکان‌های حافظه، رفتار پیش‌فرض در NASM تولید **آدرس‌های مطلق** است، یعنی آدرس‌های ثابت حافظه.

به دلایل امنیتی، فایل‌های اجرایی اغلب به‌صورت **PIE (Position Independent Executable)** ساخته می‌شوند که در آن نواحی حافظه در مکان‌های تصادفی قرار می‌گیرند. در یک `PIE`، آدرس نهایی یک متغیر در زمان پیوند مشخص نیست. بنابراین کد در عوض آدرس‌ها را به‌صورت یک افست از مقدار موجود در ثبات ویژه‌ای به اسم `rip` محاسبه می‌کند، ثباتی که به دستورالعمل بعدی که باید اجرا شود اشاره می‌کند.

به این کار معمولاً **آدرس‌دهی نسبی با RIP** می‌گویند.

در NASM می‌توانید با عملگر `rel` دسترسی نسبی نسبت به RIP را درخواست کنید:

```x86asm
mov rax, qword [rel variable]
```

همچنین می‌توان آدرس‌دهی نسبی را با قرار دادن `default rel` در ابتدای یک فایل مبدأ، به حالت پیش‌فرض آن فایل تبدیل کرد.

همه‌ی تمرین‌های این ترک به‌صورت `PIE` کامپایل و پیوند می‌شوند، بنابراین برای تولید آدرس‌های نسبی باید از `rel` استفاده کرد.

### دیدپذیری

برچسب‌ها (توابع و داده‌ها) که در هر بخشی (مثلاً `.text`، `.data`، `.rodata`) تعریف می‌شوند، در همان فایل مبدأ قابل مشاهده‌اند. اگر با `global` اعلان شوند، برای فایل‌های مبدأ دیگر هم قابل مشاهده خواهند بود.

در مقابل، برچسب‌هایی که در فایل‌های مبدأ دیگر تعریف شده‌اند، اگر با `extern` اعلان شوند، برای فایل مبدأ جاری قابل مشاهده‌اند. در این حالت هیچ نشانه‌ای از اندازه‌ی داده در اسمبلی وجود ندارد و این اندازه باید از قبل معلوم باشد.

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
