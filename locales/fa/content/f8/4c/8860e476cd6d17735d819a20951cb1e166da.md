# درباره

## مقادیر «منطقی» در Julia

مقادیر «درست» یا «غلط» با نوع `Bool` نمایش داده می‌شوند.
این نوع فقط دو مقدار دارد: `true` و `false`.

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

برخلاف چندین زبان دیگر، Julia عمداً مفهومی به اسم «truthiness» ندارد و تنها عبارت‌هایی که به `true` یا `false` ارزیابی می‌شوند، به‌عنوان `Bool` در نظر گرفته می‌شوند.

به‌طور خاص، آرایه‌ها یا رشته‌های خالی به‌عنوان `false` تفسیر *نمی‌شوند*.
اگر می‌خواهید برای مقادیر خالی رفتار ویژه‌ای داشته باشید، باید یک Test مناسب مانند `isempty()` وجود داشته باشد.

## عملگر منطقی

سه [عملگر منطقی][boolean-operators] در Julia وجود دارد.

`&&` به معنی «و» منطقی است.
اگر عبارت‌های دو طرف `&&` *هر دو* `true` باشند، نتیجه `true` است.

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||` به معنی «یا» منطقی است.
اگر عبارت *هر کدام* از دو طرف `||` برابر `true` باشد، نتیجه `true` است.

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!` به معنی «نه» منطقی است.
مقادیر `true` و `false` را جابه‌جا (معکوس) می‌کند.

```julia-repl
julia> !true
false

julia> !false
true
```

عملگرهای مشابه برای کاربران بسیاری از زبان‌های دیگر از نظر مفهومی آشناست، هرچند نحوه‌ی نگارش دقیق ممکن است بین زبان‌ها متفاوت باشد.

## تقدم عملگرها

در عبارت‌های پیچیده‌تر، می‌تواند مفید باشد که بدانید `&&` [تقدم][operator-precedence] کمی بالاتری از `||` دارد *(به همان روشی که در عبارت‌های حسابی، `*` پیش از `+` اعمال می‌شود)*.

اتکا به این می‌تواند گیج‌کننده و مستعد خطا باشد.
برای شفافیت، از پرانتز استفاده کنید تا منظورتان روشن باشد.

## ارزیابی اتصال کوتاه

آیا عبارت `true || x` به مقدار `x` بستگی دارد، یا کامپایلر می‌تواند `x` را نادیده بگیرد؟

Julia عبارت‌های منطقی را از چپ به راست ارزیابی می‌کند و وقتی به نتیجه‌ای بدون ابهام برسد، متوقف می‌شود.

برای مثال، `true || x` باید `true` باشد، صرف‌نظر از `x`، بنابراین `x` ارزیابی نمی‌شود.
به همین ترتیب، `false && y` برابر `false` است و نیازی به ارزیابی `y` نیست.

برعکس، `true && x` *تنها اگر* `x` برابر `true` باشد `true` است، بنابراین `x` باید ارزیابی شود.

به همین ترتیب، اگر چند عملگر را زنجیره کنیم:

```julia-repl
julia> true && false && something_else
false
```

چون `true && false` باید `false` باشد، `something_else` اهمیتی ندارد و کامپایلر آن را نادیده می‌گیرد.

در این حالت، `something_else` به‌عنوان متغیر وجود نداشت، اما قرار دادنش در این زمینه خطایی نداد *(اگر شک دارید این را در REPL Test کنید)*.

این ارزیابی اتصال کوتاه اغلب توسط برنامه‌نویسان Julia به‌عنوان میانبری برای به دام انداختن مشکلات زمان اجرا و موارد مرزی استفاده می‌شود:

```julia
all_ok || do_something()

is_problem && do_something_else()
```

برای مثال، `do_something` ممکن است یک `return` زودهنگام از تابع باشد اگر `all_ok` برابر `false` باشد، یا اینکه پیش از ادامه، مقدار پیش‌فرضی به یک متغیر اختصاص دهد.

این کمی سوءاستفاده از نحوه‌ی نگارش منطقی است، اما می‌تواند بسیار راحت باشد.

## نحوه کار `Bool`ها در داخل

اگر `Bool` در یک عبارت *حسابی* قرار بگیرد، `true` به‌صورت `1` و `false` به‌صورت `0` تفسیر می‌شود، که بازتاب‌دهنده‌ی نحوه‌ی ذخیره‌سازی آن‌هاست.

اگر به زبان‌های سطح‌پایین‌تر (C و مشابه آن) عادت دارید، *لطفاً* از استفاده‌ی مکرر از این کار بپرهیزید.
این کار خوانایی Code را کاهش می‌دهد و Debug کردن را سخت‌تر می‌کند.

ممکن است گاهی ببینید مقادیر عددی به‌عنوان راهی سریع برای شمردن تعداد مقادیری که `true` هستند به کار می‌روند.

```julia-repl
julia> true + false + true
2
```
