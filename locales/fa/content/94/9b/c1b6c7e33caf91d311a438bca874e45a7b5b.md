# دستورالعمل‌ها

النا مدیر کیفیت جدید یک کارخانه‌ی تولید روزنامه است.
او چون تازه به شرکت آمده، تصمیم گرفته برخی از فرایندهای کارخانه را بررسی کند تا ببیند چه چیزی را می‌توان بهبود داد.

او متوجه شده که تکنسین‌ها بسیاری از بررسی‌های کیفی را دستی انجام می‌دهند.

او فرصت خوبی برای خودکارسازی می‌بیند و از شما که یک برنامه‌نویس آزاد هستید می‌خواهد نرم‌افزاری برای پایش برخی از ماشین‌ها بنویسید.

## 1. پایش سطح رطوبت اتاق

مأموریت اول شما نوشتن نرم‌افزاری برای پایش سطح رطوبت اتاق تولید است.
از قبل حسگری به نرم‌افزار شرکت متصل است که به‌طور دوره‌ای درصد رطوبت اتاق را برمی‌گرداند.

باید تابعی در این نرم‌افزار پیاده‌سازی کنید که اگر درصد رطوبت بیش از حد بالا باشد، خطا بدهد.
اسم این تابع باید `check_humidity_level` باشد و درصد رطوبت را به عنوان پارامتر بگیرد.

اگر این درصد از ۷۰٪ فراتر رود، باید با یک خطا متوقف شوید (متن پیام مهم نیست).
در غیر این صورت، پیامی شامل «humidity test passed» صادر کنید و برای تأیید درست بودن اندازه‌گیری، `TRUE` را برگردانید.

```R
check_humidity_level(60)
#> humidity test passed
#> [1] TRUE

check_humidity_level(100)
#> Error in check_humidity_level(100) : pct_humidity <= 70 is not TRUE
```

## 2. تشخیص گرم شدن بیش از حد

النا از اولین مأموریت شما بسیار راضی است و از شما می‌خواهد پایش دمای ماشین‌ها را به عهده بگیرید.
در گفت‌وگو با تکنسینی به اسم گرگ، به شما می‌گویند که اگر دمای یک ماشین از ۵۰۰ درجه‌ی سانتی‌گراد فراتر رود، تکنسین‌ها نگران گرم شدن بیش از حد آن می‌شوند.

این ماشین به حسگری مجهز است که دمای داخلی‌اش را اندازه می‌گیرد.
باید بدانید که این حسگر بسیار حساس است و اغلب خراب می‌شود.
در این صورت، تکنسین‌ها باید آن را عوض کنند.

کار شما پیاده‌سازی تابعی به اسم `report_overheating` است که دما را به عنوان پارامتر می‌گیرد و اگر حسگر خراب باشد یا ماشین شروع به گرم شدن بیش از حد کند، خطا می‌دهد.

چون می‌دانید بعداً باید بسته به نوع خطا واکنش متفاوتی نشان دهید، به سازوکاری برای تفکیک این دو نوع خطا نیاز دارید.

- اگر حسگر خراب باشد، دما `NULL` خواهد بود.
  در این صورت باید با پیام خطایی متوقف شوید که «Sensor Broken» بخشی از آن رشته باشد.
- وقتی حسگر کار می‌کند، اگر دما از ۶۰۰ درجه‌ی سانتی‌گراد فراتر رود، باید با پیامی که دما را در خود دارد متوقف شوید.
- اگر دما از ۵۰۰ درجه‌ی سانتی‌گراد فراتر رود اما به ۶۰۰ نرسد، باید هشداری شامل دما صادر کنید و `FALSE` را برگردانید.
- در غیر این صورت همه‌چیز خوب است؛ پس پیام `"temperature check passed: t °C"` را صادر کنید که در آن `t` همان دماست و `TRUE` را برگردانید.

```R
report_overheating(NULL)
#> Error in report_overheating(NULL) : Sensor Broken

report_overheating(800)
#> Error in report_overheating(800) : Overheating: 800 C

report_overheating(550)
#> [1] FALSE
#> Warning message:
#> In report_overheating(550) : Risk of overheating: 550 C

report_overheating(450)
#> temperature check passed: 450 °C
#> [1] TRUE
```


## 3. پایش ماشین

حالا که ماشین شما می‌تواند خطاها را تشخیص دهد و یک خطای سفارشی ماشین دارید، تابع پوششی‌ای اضافه می‌کنید که بتواند گزارش دهد همه‌چیز چگونه کار می‌کند.
این پوشش، علاوه بر برگرداندن گزارش‌های توابع قبلی، باید بسته به هر نوع خرابی‌ای که رخ می‌دهد، گزارش‌هایی هم اضافه کند.

- رطوبت و دما را بررسی کنید.
- اگر مشکلی هست، بگذارید `check_humidity_level()` و `report_overheating()` خودشان گزارش‌هایشان را بیرون بدهند.
- اگر همه‌چیز خوب است، پیامی شامل «All OK» اضافه کنید.

تابعی به اسم `monitor_the_machine()` پیاده‌سازی کنید که رطوبت و دما را به عنوان آرگومان می‌گیرد.

```R
# Working well
monitor_the_machine(53, 200)
#> humidity test passed
#> temperature check passed: 200 °C
#> All OK!

# High humidity
monitor_the_machine(90, 200)
#> Error in check_humidity_level(pct_humidity) : 
#>   pct_humidity <= 70 is not TRUE

# Faulty sensor
monitor_the_machine(53, NULL)
#> humidity test passed
#> Error in report_overheating(temperature) : Sensor Broken

# Mild overheating
monitor_the_machine(53, 550)
#> humidity test passed
#> Warning message:
#> In report_overheating(temperature) : Risk of overheating: 550 C

# Dangerous overheating: shutdown
monitor_the_machine(53, 650)
#> humidity test passed
#> Error in report_overheating(temperature) : Overheating: 650 C
```
