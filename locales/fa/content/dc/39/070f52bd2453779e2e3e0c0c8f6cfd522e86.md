# مقدمه

Go در نسخه‌ی ۱.۱۸ پشتیبانی از **جنریک** را اضافه کرد.
جنریک به شما اجازه می‌دهد توابع و ساختارهای داده‌ای بنویسید که با انواع مختلف کار می‌کنند، بدون آنکه کد را تکرار کنید.

## چرا جنریک؟

در Go، توابع و انواع معمولاً با انواع مشخصی مانند `int` یا `string` کار می‌کنند.
پیش از جنریک، برای پشتیبانی از چند نوع دو گزینه داشتید.
نخست می‌توانستید چند تابع با اسم‌های مختلف بنویسید، مانند `SumInts` و `SumFloats`.
این رویکرد کد تکراری‌ای ایجاد می‌کند که نگهداری‌اش دشوار است.
دوم می‌توانستید از interface خالی `any` (`interface{}`) استفاده کنید.
با این حال، interface خالی بررسی‌های نوع در زمان کامپایل را حذف می‌کند و به type assertion در زمان اجرا نیاز دارد.
جنریک این مشکل را با فراهم کردن ایمنی نوع و پرهیز از کد تکراری حل می‌کند.

## توابع جنریک

تابع جنریک را با افزودن **پارامترهای نوع** در کروشه‌ها `[...]` بعد از اسم تابع تعریف می‌کنید.
این مثالی از یک تابع جنریک است که یک slice معکوس‌شده برمی‌گرداند:

```go
func Reverse[T any](s []T) []T {
    result := make([]T, len(s))
    for i, v := range s {
        result[len(s)-1-i] = v
    }
    return result
}
```

در این مثال، `T` یک پارامتر نوع است.
می‌توانید `T` را جای‌نگهدار یک نوع واقعی در نظر بگیرید.
کلیدواژه‌ی `any` درون کروشه‌ها یک **محدودیت نوع** است.
این محدودیت به کامپایلر می‌گوید چه انواعی برای `T` مجازند.
در اینجا، `any` یعنی `T` می‌تواند هر نوعی باشد.

### فراخوانی توابع جنریک

می‌توانید تابع جنریک را با فرستادن نوع واقعی در کروشه‌ها فراخوانی کنید.
به این نوع واقعی **آرگومان نوع** می‌گوییم.

```go
numbers := []int{1, 2, 3}
reversedNumbers := Reverse[int](numbers)
```

در بیشتر موارد، کامپایلر Go می‌تواند نوع را به‌طور خودکار از آرگومان‌های تابع تشخیص دهد.
به این ویژگی **استنتاج نوع** می‌گویند.
با استنتاج نوع، نیازی نیست آرگومان نوع را در کروشه‌ها بنویسید.

```go
words := []string{"apple", "banana"}
reversedWords := Reverse(words)
```

در این مثال، کامپایلر می‌بیند که `words` یک slice از رشته‌ها است، پس استنتاج می‌کند که `T` همان `string` است.

## محدودیت‌های نوع

هر پارامتر نوع باید یک محدودیت داشته باشد.
محدودیت مشخص می‌کند چه انواعی را می‌توانید به‌عنوان آرگومان نوع به کار ببرید.
محدودیت همچنین تعیین می‌کند چه عملیاتی را می‌توانید روی مقادیر آن نوع انجام دهید.

### محدودیت `any`

محدودیت `any` هر نوعی را مجاز می‌کند.
در Go، `any` نامی دیگر برای interface خالی `interface{}` است.
چون `any` همه‌ی انواع را مجاز می‌کند، تابع فقط می‌تواند عملیاتی انجام دهد که روی همه‌ی انواع Go کار می‌کنند.
برای نمونه، اگر دو مقدار `any` داشته باشید که slice نگه می‌دارند، نمی‌توان آن‌ها را با `==` مقایسه کرد، چون sliceها را نمی‌توان با `==` مقایسه کرد.

### محدودیت `comparable`

Go محدودیت درون‌ساخته‌ای به اسم `comparable` فراهم می‌کند.
محدودیت `comparable` هر نوعی را مجاز می‌کند که عملگرهای `==` و `!=` را پشتیبانی کند.
انواع قابل مقایسه شامل مقادیر منطقی، اعداد، رشته‌ها، اشاره‌گرها، کانال‌ها و structها یا آرایه‌هایی است که از انواع قابل مقایسه ساخته شده‌اند.

این مثالی از تابعی است که بررسی می‌کند آیا یک slice شامل عنصر مشخصی هست یا نه:

```go
func Contains[T comparable](elems []T, target T) bool {
    for _, elem := range elems {
        if elem == target {
            return true
        }
    }
    return false
}
```

چون `T` از محدودیت `comparable` استفاده می‌کند، استفاده از `elem == target` معتبر است.
اگر `comparable` را با `any` جایگزین کنید، کامپایلر خطا گزارش می‌دهد.

### محدودیت‌های سفارشی با مجموعه‌های نوع در interface

از Go ۱.۱۸ به بعد، interfaceها می‌توانند علاوه بر متدها مجموعه‌هایی از انواع را نیز تعریف کنند.
می‌توانید با کاراکتر خط عمودی `|` انواع مجاز را در یک interface فهرست کنید.

```go
type Number interface {
    int | int64 | float64
}
```

حالا می‌توانید از `Number` به‌عنوان محدودیت یک تابع استفاده کنید:

```go
func Double[T Number](value T) T {
    return value * 2
}
```

چون همه‌ی انواع در `Number` عملگر `*` را پشتیبانی می‌کنند، Go عبارت `value * 2` را درون تابع مجاز می‌داند.

### تقریب نوع زیربنایی `~`

گاهی یک تعریف نوع سفارشی بر پایه‌ی یک نوع اولیه می‌سازید:

```go
type MyInt int
```

محدودیت `Number` که بالا تعریف شد فقط انواع دقیق `int`، `int64` و `float64` را مجاز می‌کند.
اگر مقداری از نوع `MyInt` به `Double` بدهید، کامپایلر خطا تولید می‌کند، چون `MyInt` با `int` مطابقت ندارد.
برای مجاز کردن هر نوعی که نوع زیربنایی‌اش `int` است، علامت مدک `~` را پیش از نوع اضافه کنید:

```go
type Number interface {
    ~int | ~int64 | ~float64
}
```

حالا می‌توانید از `Double` با مقادیری از نوع `MyInt` استفاده کنید.

### محدودیت `cmp.Ordered`

کتابخانه‌ی استاندارد محدودیت `cmp.Ordered` را در [بسته‌ی `cmp`][doc-cmp] فراهم می‌کند.
محدودیت `cmp.Ordered` هر نوعی را مجاز می‌کند که عملگرهای مقایسه‌ی `<`، `<=`، `>` و `>=` را پشتیبانی کند.

## انواع جنریک

همچنین می‌توانید از پارامترهای نوع برای تعریف انواع جنریک، مانند structها، استفاده کنید.
این مثالی از یک ساختار داده‌ی `Stack` جنریک است:

```go
type Stack[T any] struct {
    elements []T
}

func (s *Stack[T]) Push(v T) {
    s.elements = append(s.elements, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.elements) == 0 {
        var zero T
        return zero, false
    }
    lastIndex := len(s.elements) - 1
    top := s.elements[lastIndex]
    s.elements = s.elements[:lastIndex]
    return top, true
}
```

وقتی متغیری از یک نوع جنریک اعلام می‌کنید، باید آرگومان نوع را در کروشه‌ها مشخص کنید:

```go
intStack := Stack[int]{}
intStack.Push(42)

stringStack := Stack[string]{}
stringStack.Push("hello")
```

استنتاج نوع فقط برای توابع جنریک کار می‌کند.
هنگام ساختن مقادیری از یک نوع جنریک، همیشه باید آرگومان نوع را مشخص کنید.

## چه زمانی از جنریک استفاده کنیم

جنریک ویژگی قدرتمندی است، اما لازم نیست برای هر مسئله‌ای از آن استفاده کنید.

در موقعیت‌هایی مانند این‌ها از جنریک استفاده کنید:
- در حال ساختن ساختارهای داده‌ای مانند درخت‌ها، لیست‌های پیوندی یا کش‌ها هستید که با هر نوع عنصری کار می‌کنند.
- در حال نوشتن توابع کمکی هستید که روی sliceها یا mapهایی از هر نوع کار می‌کنند، مانند فیلتر کردن، مرتب‌سازی یا جست‌وجو.
- برای چند نوع به پیاده‌سازی دقیقاً یکسانی نیاز دارید و ایمنی نوع در زمان کامپایل را می‌خواهید.

در موقعیت‌هایی مانند این‌ها به‌جای آن از interface استفاده کنید:
- رفتار و متدها برایتان مهم‌اند، نه نوع داده‌ی زیربنایی.
  برای نمونه، اگر می‌خواهید داده را از منابعی با انواع گوناگون (فایل، شبکه، TTY) بخوانید و پردازش کنید، `func Process(src io.Reader)` را به `func Process[T](src T)` ترجیح می‌دهید.
- انواع مختلف برای انجام کارشان به پیاده‌سازی‌های متفاوتی از متدها نیاز دارند.
