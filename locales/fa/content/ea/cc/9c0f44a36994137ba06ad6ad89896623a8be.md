# دستورالعمل‌ها

شرکت خودکارسازی خرید مواد غذایی Mecha Munch™ به‌تازگی شما را استخدام کرده است تا روی اپلیکیشن سفارش‌گیری آن کار کنید.
تیم شما مأمور است یک MVP (یعنی [حداقل محصول قابل ارائه][mvp]) بسازد که همه‌ی کارهای پایه‌ی سبد خرید را مدیریت کند و به کاربران اجازه دهد سفارش‌های مواد غذایی‌شان را اضافه، حذف و مرتب کنند.
خوشبختانه، تیم دیگری مسئول همه‌ی کارهای پول و تسویه است!

## 1. افزودن اقلام به سبد خرید کاربر

MVP باید به کاربر اجازه دهد اقلام را به سبد خریدش اضافه کند.
این می‌تواند یک قلم باشد یا چند قلم با هم.
چون این یک MVP است، تعداد هر قلم با _تکرار_ نشان داده می‌شود.
اگر کاربر بخواهد ۲ پرتقال اضافه کند، 'Oranges' دو بار در iterable ورودی ظاهر می‌شود.
اگر کاربر از قبل این قلم را در سبدش داشته باشد، تعداد آن در سبد یک واحد افزایش می‌یابد.
اگر قلم برای سبد _جدید_ باشد، باید با تعداد ۱ اضافه شود.

تابع `add_items!(<cart>, <items>)` را بسازید که یک دیکشنری سبد خرید و یک iterable از اقلام برای افزودن را به عنوان آرگومان می‌گیرد.
این تابع باید دیکشنری به‌روزشده‌ی سبد خرید کاربر را برگرداند.

```julia-repl
julia> additems!(Dict("Banana" => 3, "Apple" => 2, "Orange" => 1),
                 ("Apple", "Apple", "Orange", "Apple", "Banana"))
Dict{String, Int64} with 3 entries:
  "Apple"  => 5
  "Orange" => 2
  "Banana" => 4

julia> additems!(Dict("Banana" => 3, "Apple" => 2, "Orange" => 1),
                 ["Banana", "Orange", "Blueberries", "Banana"])
Dict{String, Int64} with 4 entries:
  "Blueberries" => 1
  "Apple"       => 2
  "Orange"      => 2
  "Banana"      => 5
```

## 2. به‌روزرسانی بخش «ایده‌ها»ی دستور پخت

اپلیکیشن بخشی به اسم «ایده‌ها» دارد که پر از دستورهای پخت آماده از آشپزی‌های گوناگون است.
کاربر می‌تواند هر یک از این دستورها را انتخاب کند و همه‌ی مواد لازم آن به‌طور خودکار به سبد خریدش اضافه شود.
مدیر پروژه از شما خواسته است راهی برای ویرایش این دستورهای «ایده‌ها» بسازید، چون تیم محتوا مدام مواد و مقدارها را تغییر می‌دهد.

تابع `update_recipes!(<ideas>, <updates>)` را بسازید که یک دیکشنری «ایده‌ها» و یک دیکشنری از به‌روزرسانی‌های دستور پخت را به عنوان آرگومان می‌گیرد.
این تابع باید دیکشنری «ایده‌ها»ی به‌روزشده را برگرداند.

## 3. ارسال سبد خرید کاربر به فروشگاه برای انجام سفارش

اپلیکیشن باید سبد خرید یک کاربر مشخص را برای انجام سفارش به فروشگاه بفرستد.
اما کسانی که در فروشگاه سفارش‌ها را آماده می‌کنند باید بدانند هر قلم را با یک کد راهروی یکتا کجا می‌توان پیدا کرد.
«سبد انجام سفارش» باید بر اساس کد راهروی اقلام مرتب شود تا کار آماده‌سازی سریع‌تر پیش برود.

تابع `send_to_store(<cart>, <aislecodes>)` را بسازید که یک سبد خرید کاربر و یک دیکشنری شامل شماره‌ی راهروهای فروشگاه را می‌گیرد.
این تابع باید یک «سبد انجام سفارش» ترکیبی برگرداند که برای هر قلم سفارش‌داده‌شده‌ی مشتری یک جفت `aislecode => quantity` دارد.
اقلام باید به ترتیب کد راهروی‌شان ظاهر شوند.

```julia-repl
julia> cart = Dict("Orange" => 1, "Milk" => 2, "Banana" => 3, "Apple" => 2, "Chocolate" => 2);

julia> aislecodes = Dict("Orange" => 2.4, "Milk" => 3.3, "Banana" => 2.6, "Apple" => 2.2, "Chocolate" => 5.7);

julia> send_to_store(cart, aislecodes)
5-element Vector{Pair{Float64, Int64}}:
 2.2 => 2
 2.4 => 1
 2.6 => 3
 3.3 => 2
 5.7 => 2
```

## 4. به‌روزرسانی موجودی فروشگاه بر اساس سفارش کاربر

اپلیکیشن نمی‌تواند بی‌پایان سفارش مشتریان را ثبت کند.
دیر یا زود، فروشگاه با کمبود محصولات مختلف روبه‌رو می‌شود.
پس MVP شما باید هر بار که کاربری سفارشش را به فروشگاه می‌فرستد، موجودی فروشگاه را به‌روز کند.
وگرنه، مشتریان محصولاتی را سفارش می‌دهند که در واقع موجود نیستند.

تابع `update_store_inventory!(<inventory>, <cart>)` را بسازید که یک `cart` و یک `inventory` می‌گیرد.
این تابع باید مقدار موجودی فروشگاه را به اندازه‌ی تعداد «سفارش‌داده‌شده» در `cart` کم کند و سپس یک دیکشنری از اقلامی را برگرداند که موجودی‌شان تمام شده است (یعنی به `0` رسیده‌اند).

```julia-repl
julia> inventory = Dict("Banana" => 15, "Apple" => 12, "Orange" => 1, "Milk" => 4);

julia> cart = Dict("Orange" => 1, "Milk" => 2, "Banana" => 3, "Apple" => 2);

julia> update_store_inventory!(inventory, cart)
Dict{String, Int64} with 1 entry:
  "Orange" => 0

julia> inventory
Dict{String, Int64} with 4 entries:
  "Milk"   => 2
  "Apple"  => 10
  "Orange" => 0
  "Banana" => 12
```

## 5. سفارش مجدد اقلام ناموجود

علاوه بر به‌روزرسانی موجودی، اپلیکیشن شما می‌تواند در پر کردن دوباره‌ی آن هم کمک کند.
MVP شما باید بتواند یک سفارش کوچک از هر قلمی که پس از سفارش مشتری ناموجود شده است آماده کند.
این کار ثبت یک سفارش بزرگ را ساده‌تر می‌کند.
از این گذشته، گاهی اقلام تبلیغاتی محدود هم هستند که در فهرست موجودی نمی‌آیند.
اگر این اقلام پیش از پایان دوره‌ی تبلیغاتی فروش بروند، یعنی محبوب بوده‌اند و می‌توان آن‌ها را به فهرست موجودی اضافه کرد.

تابع `reorder!(<outofstock>, <stock>)` را بسازید که `outofstock` و `stock` را می‌گیرد.
دیکشنری `stock` شامل اقلام استاندارد موجودی و مقدار سفارش مجدد آن‌هاست.
دیکشنری `outofstock` نتیجه‌ی `update_store_inventory!` است، یعنی دیکشنری اقلامی با موجودی صفر.
مقدارهای `outofstock` باید بر اساس مقدارهای `stock` به‌روز شوند و برگردانده شوند.
همچنین هر قلمی در `outofstock` که در `stock` وجود ندارد باید با مقدار پیش‌فرض `100` به `stock` اضافه شود.

```julia-repl
julia> inventory = Dict("Banana" => 15, "Apple" => 12, "Orange" => 1, "Milk" => 4, "Chocolate" => 2);

julia> cart = Dict("Orange" => 1, "Milk" => 2, "Banana" => 3, "Apple" => 2, "Chocolate" => 2);

julia> stock = Dict("Banana" => 150, "Apple" => 120, "Orange" => 120, "Milk" => 45);

julia> outofstock = update_store_inventory!(inventory, cart)
Dict{String, Int64} with 1 entry:
  "Orange"    => 0
  "Chocolate" => 0

julia> reorder!(outofstock, stock)
Dict{String, Int64} with 1 entry:
  "Orange"    => 120
  "Chocolate" => 100

julia> stock 
Dict{String, Int64} with 5 entries:
  "Milk"      => 45
  "Apple"     => 120
  "Chocolate" => 100
  "Orange"    => 120
  "Banana"    => 150
```
