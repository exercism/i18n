# نوع داده‌ی جنریک

جنریک‌ها در Cairo به شما این امکان را می‌دهند که کدی قابل استفاده‌ی مجدد بنویسید که با انواع گوناگون کار می‌کند؛ به این ترتیب از تکرار کد جلوگیری می‌کنید و نگهداری آن را آسان‌تر می‌سازید.

می‌توانید از جنریک‌ها با توابع، structها، enumها، traitها و متدها استفاده کنید.

## توابع جنریک

یک تابع جنریک با انواع مختلف کار می‌کند، بدون اینکه به پیاده‌سازی جداگانه برای هر نوع نیاز داشته باشد.

برای مثال:

```rust
fn largest_list<T>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

در اینجا `T` یک جای‌نگهدار برای هر نوعی است.

اما Cairo برای اینکه مطمئن شود نوع جنریک الزامات مشخصی را برآورده می‌کند، به محدودیت‌های trait نیاز دارد.

اگر لازم باشد `T` قابل Drop باشد، می‌توانیم امضا را به این صورت تغییر دهیم:

```rust
fn largest_list<T, impl TDrop: Drop<T>>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

محدودیت‌های trait، مثل `Drop` یا `PartialOrd`، قیدهایی به جنریک‌ها اضافه می‌کنند تا عملیات مشخصی ممکن شود.

## قیدهای بی‌نام

اگر یک پیاده‌سازی trait مستقیماً در تابع استفاده نشود، می‌توانید قیدهای بی‌نام را با `+` بنویسید:

```rust
fn smallest_element<T, +PartialOrd<T>, +Drop<T>, +Copy<T>>(list: @Array<T>) -> T {
    let mut smallest = *list[0];
    let mut index = 1;

    while index < list.len() {
        if *list[index] < smallest {
            smallest = *list[index];
        }
        index += 1;
    };

    smallest
}
```

این کار باعث می‌شود لازم نباشد اسم traitهایی مثل `TPartialOrd` را بنویسید و کد کوتاه‌تر می‌شود.

## structهای جنریک

جنریک‌ها در structها فیلدها را انعطاف‌پذیر می‌کنند.

برای مثال:

```rust
#[derive(Drop)]
struct Wallet<T> {
    balance: T,
}

let w = Wallet { balance: 42 };
```

اگر یک struct به چند نوع جنریک نیاز داشته باشد، فقط چند جای‌نگهدار دیگر اضافه کنید:

```rust
#[derive(Drop)]
struct Wallet<T, U> {
    balance: T,
    address: U,
}

let w = Wallet { balance: 42, address: '0xabc' };
```

## enumهای جنریک

enumها هم می‌توانند انواع داده‌ی جنریک را در خود نگه دارند.

برای مثال:

```rust
enum Option<T> {
    Some: T,
    None,
}
```

enum `Option<T>` می‌تواند مقدار اختیاری از هر نوعی را نشان دهد.

به همین ترتیب، `Result<T, E>` امکان تعریف نوع موفقیت و شکست را می‌دهد:

```rust
enum Result<T, E> {
    Ok: T,
    Err: E,
}
```

## متدهای جنریک

متدها هم می‌توانند از جنریک استفاده کنند.

برای مثال:

```rust
#[derive(Copy, Drop)]
struct Wallet<T> {
    balance: T,
}

trait WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T;
}

impl WalletImpl<T, +Copy<T>> of WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T {
        *self.balance
    }
}

let w = Wallet { balance: 50 };
assert!(w.balance() == 50);
```

می‌توانید متدهایی برای انواع جنریک مشخص هم تعریف کنید، مثل `Wallet<u128>`:

```rust
trait WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128);
}

impl WalletReceiveImpl of WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128) {
        self.balance += value;
    }
}

let mut w = Wallet { balance: 50 };
w.receive(100);
assert!(w.balance() == 150);
```

## ترکیب انواع جنریک

جنریک‌ها می‌توانند ترکیب‌های پیچیده را هم مدیریت کنند.

برای نمونه، ترکیب دو نمونه‌ی `Wallet` با دو نوع متفاوت:

```rust
trait WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2>;
}

impl WalletMixImpl<T1, +Drop<T1>, U1, +Drop<U1>> of WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2> {
        Wallet { balance: self.balance, address: other.address }
    }
}

let w1 = Wallet { balance: true, address: 10 };
let w2 = Wallet { balance: 32, address: 100 };
let w3 = w1.mixup(w2);

assert!(w3.balance);
assert!(w3.address == 100);
```

با افزودن قیدهای `+Drop`، کامپایلر از مدیریت درست منابع مطمئن می‌شود.

جنریک‌ها قدرتمندند، اما به مدیریت دقیق قیدها نیاز دارند.

از آن‌ها استفاده کنید تا کدی قابل استفاده‌ی مجدد، مستقل از نوع و کوتاه بنویسید.
