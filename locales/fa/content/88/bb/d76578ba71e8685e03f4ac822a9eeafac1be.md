# دستورالعمل‌ها

پس از یک بازبینی امنیتی اخیر، از شما خواسته شده است که فایل‌های لاگ آرشیوشده‌ی سازمان را پاک‌سازی کنید.

## 1. شناسایی خطوط لاگ درهم‌ریخته

باید تصوری کلی داشته باشید که چند خط لاگ در آرشیو شما با استانداردهای کنونی مطابقت ندارد.
معتقدید یک آزمون ساده مشخص می‌کند که یک خط لاگ معتبر است یا نه.
برای اینکه خطی معتبر به حساب بیاید، باید با یکی از رشته‌های زیر آغاز شود:

- [DEBUG]
- [INFO]
- [WARNING]
- [ERROR]

تابع `valid_line?/1` را طوری پیاده‌سازی کنید که اگر خط لاگ معتبر بود، `true` برگرداند.

```elixir
LogParser.valid_line?("[ERROR] Network Failure")
# => true

LogParser.valid_line?("Network Failure")
# => false
```

## 2. تقسیم خط لاگ

مدتی پس از شروع پروژه‌ی تجزیه‌ی لاگ، متوجه می‌شوید که لاگ‌های یک برنامه، برخلاف بقیه، به خطوط تقسیم نشده‌اند. در این پروژه، آنچه باید خطوطی جدا می‌بود، در عوض روی یک خط واحد آمده و با فلش‌های عجیب‌وغریبی مانند `<--->` یا `<*~*~>` به هم پیوند خورده است.

در واقع، هر رشته‌ای که نخستین نویسه‌اش `<` و واپسین نویسه‌اش `>` باشد و در میان آن‌ها هر ترکیبی از نویسه‌های `~`، `*`، `=` و `-` قرار بگیرد، می‌تواند به‌عنوان جداکننده در لاگ‌های این پروژه به کار رود.

تابع `split_line/1` را پیاده‌سازی کنید که یک خط می‌گیرد و فهرستی از رشته‌ها برمی‌گرداند.

```elixir
LogParser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
# => ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. حذف باقی‌مانده‌ها از لاگ

متوجه شده‌اید که بخشی از پردازش‌های بالادستی لاگ‌ها، متن «end-of-line» را به‌همراه یک شماره‌ی خط (بدون فاصله‌ای در میان) در سراسر لاگ‌ها پراکنده کرده است.

تابع `remove_artifacts/1` را پیاده‌سازی کنید تا یک رشته بگیرد و همه‌ی موارد متن «end-of-line» را (بدون در نظر گرفتن بزرگی و کوچکی حروف) حذف کند و یک خط لاگ پاک‌شده برگرداند.

خطوطی که متن «end-of-line» را ندارند باید بدون تغییر برگردانده شوند.

فقط رشته‌ی «end-of-line» را حذف کنید؛ نیازی به تنظیم فاصله‌های خالی نیست.

```elixir
LogParser.remove_artifacts("[WARNING] end-of-line23033 Network Failure end-of-line27")
# => "[WARNING]  Network Failure "
```

## 4. برچسب‌گذاری خطوط با اسم کاربر

متوجه شده‌اید که برخی از خطوط لاگ جمله‌هایی دارند که به کاربران اشاره می‌کنند.
این جمله‌ها همیشه رشته‌ی `"User"` را دارند که پس از آن یک یا چند نویسه‌ی فاصله و سپس اسم کاربر می‌آید.
تصمیم می‌گیرید چنین خطوطی را برچسب بزنید.

تابع `tag_with_user_name/1` را پیاده‌سازی کنید که خطوط لاگ را پردازش می‌کند:

- خطوطی که رشته‌ی `"User"` را ندارند، بدون تغییر می‌مانند.
- برای خطوطی که رشته‌ی `"User"` را دارند، خط را با `[USER]` و پس از آن اسم کاربر پیشوند کنید.

```elixir
LogParser.tag_with_user_name("[INFO] User Alice created a new project")
# => "[USER] Alice [INFO] User Alice created a new project"
```

می‌توانید فرض کنید که:

- پس از هر نمونه از رشته‌ی `"User"`، یک یا چند نویسه‌ی فاصله و سپس اسم کاربر می‌آید.
- در هر خط حداکثر یک نمونه از رشته‌ی `"User"` وجود دارد.
- اسم‌های کاربر رشته‌های ناتهی هستند که نویسه‌ی فاصله ندارند.
