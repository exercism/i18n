# مقدمه

بسیاری از زبان‌ها روشی مانند `null` یا `none` دارند تا مقداری را که وجود ندارد نشان دهند. چون R برای کار با حجم زیادی از داده‌ها (که اغلب به‌هم‌ریخته هستند) طراحی شده است، چندین شکل مختلف از «هیچ» دارد.

هدف کلی این است که مقادیر گمشده یا مشکوک را همان‌طور که با آن‌ها روبه‌رو می‌شویم علامت‌گذاری کنیم و سپس بدون ایجاد استثنا ادامه دهیم.

## NULL

اگر مقداری واقعاً وجود نداشته باشد، با `NULL` نمایش داده می‌شود. این رفتار احتمالاً نزدیک‌ترین چیز به رفتار زبان‌های C یا Python است.

```R
v <- c() # zero-length vector
v
#> NULL
is.null(v)
#> [1] TRUE
```

در بسیاری از موقعیت‌ها، مقادیر `NULL` به‌سادگی نادیده گرفته می‌شوند:

```R
c(2, 3, NULL, 5)
#> [1] 2 3 5
```

## NA

برای موقعیت‌هایی که مقدار وجود دارد اما نمی‌دانیم چیست، از `NA` استفاده می‌شود. برای مثال، هنگام شمارش خودروهایی که در جاده‌ای در حال حرکت‌اند، ممکن است ناظران انسانی بیمار شوند یا حسگرهای خودکار از کار بیفتند، اما جریان ترافیک ادامه دارد.

```R
v <- c(1, 2, NA, 4, 5)
v
#> [1]  1  2 NA 4  5
is.na(v) # test for data gaps
#> [1] FALSE FALSE  TRUE FALSE FALSE
```

بنابراین `NA` یک جای‌نگهدار است که به انسان‌ها هشدار می‌دهد باید تصمیم بگیرند چگونه با آن رفتار کنند.

## بردار خالی

شاید جای شگفتی باشد که R روش استانداردی برای بررسی خالی‌بودن ندارد، هرچند برخی بسته‌های شخص ثالث توابع خودشان را پیاده‌سازی می‌کنند، مانند `is.empty()`.

حتی ساختن یک بردار خالی هم چندان واضح نیست.
در بخش‌های پیشین دیدیم که `c()` بدون آرگومان، `NULL` برمی‌گرداند، نه یک بردار.

```R
is.vector(c())
#> [1] FALSE
```

توابعی مانند `logical()` یا `integer()` آرگومانی می‌گیرند که طول موردنظر را مشخص می‌کند و این طول می‌تواند صفر باشد.

```R
z <- logical(0)
is.vector(z)
#> [1] TRUE
length(z)
#> [1] 0
```

همچنین می‌توانیم برداری بسازیم و بعد همه‌ی عنصرهایش را حذف کنیم، همان‌طور که در [مفهوم بردار][concept-vectors] توضیح داده شده است.
نتیجه یک بردار با طول ۰ و از نوع مناسب است.

```R
v <- 5
v[-1]  # delete the first element
#> numeric(0)
```
