# مبانی Unison

## ترم‌ها و توابع

ترم‌ها و توابع، واحدهای پایه‌ی نوشتن یک برنامه‌ی Unison هستند.

به یک مقدار ایستا، «ترم» می‌گوییم. ترم با `name = expression` تعریف می‌شود و به‌طور اختیاری می‌تواند یک امضای نوع به شکل `name : MyType` مقدم بر آن بیاید. Unison از استنتاج نوع پشتیبانی می‌کند، بنابراین ممکن است ببینید که امضای نوع برای تعریف‌های ساده حذف شده است.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

توابع Unison به شکل `myFunctionName argument1 argument2 = myImplementation` هستند؛ با اسم تابع شروع می‌شوند و پس از آن آرگومان‌ها با فاصله از هم جدا می‌آیند.

```
getMax a b = Nat.max a b
```

توابع می‌توانند به‌طور اختیاری شامل یک امضای نوع باشند. آخرین نوع در سمت راست همیشه نوع بازگشتی نهایی تابع است و هر آرگومان با فلش تابع `->` از بقیه جدا می‌شود.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

برای فراخوانی یک تابع، اسم آن را بنویسید و پس از آن آرگومان‌ها را بیاورید که فقط با فاصله از هم جدا شده‌اند.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

هنگام فراخوانی یک تابع، Unison تلاش می‌کند هر چیزی را که بلافاصله در سمت راست می‌آید به‌عنوان آرگومان تابع در نظر بگیرد. این کار همیشه ترتیب مورد نظر برای ارزیابی تابع را به دست نمی‌دهد.

فرض کنید می‌خواهیم مقدار `1` را از عبارت زیر به دست آوریم.

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

همان‌طور که نوشته شده، `shouldBe1` به `0` ارزیابی می‌شود، چون ترتیب اعمال تابعی که به‌طور ضمنی در نظر گرفته می‌شود `getMax 1 10` است که `10` می‌شود و سپس `10 - 10` که `0` است.

می‌توانید از پرانتز استفاده کنید تا عبارت را به ترتیب عملیات مورد نظر دوباره گروه‌بندی کنید.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## عبارت‌های پایش

Unison روشی برای ارزیابی سریع کد فراهم می‌کند که «عبارت پایش» نام دارد. یک عبارت پایش با نماد `>` شروع می‌شود و پس از آن عبارتی می‌آید که باید ارزیابی شود. عبارت‌های پایش را می‌توان در هر فایلی با پسوند `.u` نوشت. به محض ذخیره‌ی فایل، باید ببینید که عبارت در کنسول Unison Codebase Manager (UCM) به چه چیزی ارزیابی می‌شود. در این مستندات، تا جایی که ممکن باشد تلاش می‌کنیم هر عبارت را همراه با خروجی مورد انتظارش پس از ارزیابی در یک عبارت پایش نشان دهیم.

```
> helloThere
  ⧩
  "Hello, World!"
```

## توابع چندخطی

توابع چندخطی Unison برای مشخص کردن مرزهای کد، یعنی «دامنه‌ی واژگانی»، از تورفتگی یا بلوک‌های `let` استفاده می‌کنند.

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

هر چیزی که در یک سطح تورفتگی قرار دارد، دامنه‌ی یکسانی دارد و به همین دلیل می‌توانیم در خط آخر به متغیر `newBeginning` ارجاع دهیم.

## فضاهای نام و دستورهای `use`

فضاهای نام روشی برای گروه‌بندی و سازمان‌دهی توابع Unison هستند. می‌توانید آن‌ها را مشابه «پوشه‌ها» در نظر بگیرید. فضاهای نام ساختار و گروه‌بندی منطقی فراهم می‌کنند.

می‌توانید توابع یک فضای نام را با یک دستور `use` به دامنه بیاورید.

فرض کنید تابعی می‌نوشتید که از مقادیر `List` در Unison استفاده می‌کرد. می‌دانید که به توابعی مثل `List.map` و `List.flatMap` نیاز خواهید داشت، که در آن‌ها `List` فضای نام است و `map` و `flatMap` تابع هستند. برای اینکه خودتان را تکرار نکنید، ممکن است تصمیم بگیرید همه‌چیز را از فضای نام `List` به دامنه‌ی واژگانی تابع خود بیاورید، به این شکل:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

خط `use List` ابهام ارجاع‌ها به `map` و `flatMap` را برطرف می‌کند. می‌توانید درباره‌ی [دستورهای `use` اینجا][use-statements] بیشتر بخوانید.

## کتابخانه‌ی استاندارد Unison

کتابخانه‌ی استاندارد Unison `base` نام دارد. اگر راهنمای شروع سریع را دنبال کرده باشید و یک پایگاه کد به‌صورت محلی ساخته باشید، باید کتابخانه‌ی استاندارد به‌طور خودکار دانلود شده باشد. می‌توانید مستندات کتابخانه‌ی استاندارد را به‌صورت آنلاین در [Unison Share][unison-share-base] مرور کنید.

## توضیحات و عناصر مستندسازی

توضیحات در Unison تا حدی ویژگی غیرمعمولی هستند. هنگام نوشتن کد Unison، می‌توانید در فایل با پسوند `.u` خود متنی بنویسید که با نحوه‌ی نگارش زیر تفسیر نمی‌شود:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_اما_ چون کد Unison به‌صورت هشی از درخت ساختار انتزاعی‌اش ذخیره می‌شود و نه به‌صورت فایل‌های متنی روی سیستم فایل، توضیحاتی که «تزئینات» متنی یک تابع یا ترم مشخص در فایل هستند در واقع نمی‌توانند ذخیره شوند و برای اشتراک‌گذاری دوباره رندر شوند. اگر می‌خواهید اطلاعاتی به ترم Unison خود اضافه کنید که برای خواندن و درک دیگران ذخیره شود، می‌توانید از یک عنصر مستندسازی استفاده کنید.

مستندسازی در زبان برنامه‌نویسی Unison یک مقدار درجه‌یک است. یعنی یک عنصر `Doc` را می‌توان به یک مقدار انتساب داد، به‌عنوان مقدار به تابع پاس داد یا به‌عنوان مقدار بازگشتی تابع برگرداند. عناصر مستندسازی با دو آکولاد باز و بسته می‌شوند. در ادامه می‌بینید که چگونه می‌توانیم از عنصر `Doc` به‌عنوان توضیح استفاده کنیم.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
