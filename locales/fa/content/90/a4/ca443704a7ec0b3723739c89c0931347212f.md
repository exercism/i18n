# بخشی درباره‌ی توضیحات

زبان Go [راهنمای عالی‌ای](https://golang.org/doc/effective_go.html) برای نحوه‌ی نوشتن توضیحات دارد. یک قالب استاندارد هم وجود دارد که می‌توانید برای توضیحات مستندات از آن استفاده کنید؛ ابزار `godoc` می‌تواند این توضیحات را به‌طور خودکار به مستنداتی زیبا تبدیل کند.

توضیح پکیج باید با واژه‌ی `Package` شروع شود و پس از آن اسم پکیج بیاید، به این شکل:

```go
// Package cook provides handy conversion methods for units typically used in recipes.
package cook
```

برای توابع، متدها، ثابت‌ها و متغیرهای پکیجی که صادر شده‌اند، توضیح باید با اسم شروع شود و با یک عبارت فعلی ادامه پیدا کند:

```go
// TbsToMl converts tablespoons to milliliters.
func TbsToMl(tbs int) int {
	// ...
}
```

ویکی [CodeReviewComments](https://github.com/golang/go/wiki/CodeReviewComments#comment-sentences) هم مشخص می‌کند که توضیحات مستندات باید جمله‌های کامل باشند و با نقطه پایان یابند.

علاوه بر اینکه خوانایی را بهتر می‌کند، رعایت این توصیه‌ها ظاهر کد شما را در [ابزارهای مستندسازی Go](http://whipperstacker.com/2015/09/30/go-documentation-godoc-godoc-godoc-org-and-go-doc/) مانند [godoc.org](http://godoc.org)، `godoc` و `go doc` بهبود می‌دهد.

کمی وقت بگذارید و بخش مربوط به توضیحات مستندات را در راهنمای رسمی سبک نگارش، [Effective Go](https://golang.org/doc/effective_go.html)، بخوانید تا دلیل این انتخاب‌ها را ببینید.
