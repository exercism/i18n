# درباره

در C#، می‌توان یک سلسله‌مراتب _کلاس_ را با _وراثت_ تعریف کرد؛ وراثت به یک کلاس مشتق‌شده (`Car`) اجازه می‌دهد رفتار و داده‌های کلاس والدش (`Vehicle`) را به ارث ببرد. اگر هیچ کلاس والدی مشخص نشود، کلاس از کلاس `object` ارث می‌برد.

کلاس‌های والد می‌توانند به سه روش قابلیت‌هایی را در اختیار کلاس‌های مشتق‌شده بگذارند:

- تعریف یک متد معمولی.
- تعریف یک متد [`virtual`][virtual-keyword] که مانند یک متد معمولی است، اما کلاس‌های مشتق‌شده _می‌توانند_ آن را تغییر دهند.
- تعریف یک متد [`abstract`][abstract-keyword] که متدی بدون پیاده‌سازی است و کلاس‌های مشتق‌شده _باید_ آن را پیاده‌سازی کنند. کلاسی که متدهای `abstract` دارد هم باید [`abstract`][abstract-classes] علامت‌گذاری شود. از کلاس‌های `abstract` نمی‌توان نمونه ساخت.

اصلاح‌کننده‌ی دسترسی [`protected`][protected-keyword] اجازه می‌دهد به یکی از اعضای کلاس والد از داخل کلاس مشتق‌شده دسترسی داشت، اما دسترسی از کلاس‌های دیگر را می‌بندد. بنابراین کلاس‌های مشتق‌شده می‌توانند به اعضای `public` و `protected` کلاس والد دسترسی داشته باشند، اما نه به اعضای `private` آن.

کلاس‌های مشتق‌شده می‌توانند از طریق [کلیدواژه‌ی `base`][base-keyword] به اعضای کلاس والد دسترسی داشته باشند.

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

// Cannot be inherited from
sealed class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

سازنده‌ی یک کلاس مشتق‌شده _پیش از_ اجرای منطق سازنده‌ی خودش، به‌طور خودکار [سازنده‌ی کلاس والدش را فراخوانی می‌کند][constructors]. می‌توان با استفاده از [کلیدواژه‌ی `base`][base-keyword-constructor] آرگومان‌هایی را به سازنده‌ی کلاس والد فرستاد. چون از کلاس‌های `abstract` نمی‌توان نمونه ساخت، می‌توان سازنده‌هایشان را `protected` کرد.

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

وقتی بیش از یک کلاس از یک کلاس پایه مشتق می‌شود، آن دو (یا چند) زیرکلاس اغلب نسخه‌های متفاوتی از یک متد کلاس پایه را پیاده‌سازی می‌کنند. این یک اصل بسیار مهم است که به آن [«چندریختی»][polymorphism] می‌گویند. برای نمونه، در تغییری بر مثال بالا نشان می‌دهیم کد با استفاده از `Vehicle` چگونه می‌تواند بسته به اینکه چه نوع خودرویی نمونه‌سازی شده است، رفتارش را تغییر دهد.

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```

برای جلوگیری از ارث‌بری یک کلاس، [اصلاح‌کننده‌ی `sealed`][sealed-classes] را اضافه کنید.
برخی برنامه‌نویسان می‌کوشند از ارث‌بری از کلاس‌های غیرانتزاعی پرهیز کنند (همان‌طور که در [این پرسش در SO][pro-sealed] بحث شده است) و اصلاح‌کننده‌ی _sealed_ از این رویکرد پشتیبانی می‌کند. از سوی دیگر، بسیاری از برنامه‌نویسان C# آن‌ها را مانعی برای نگهداری می‌دانند، همان‌طور که در برخی از نظرات [این پرسش][anti-sealed] بحث شده است. توصیه این است که اصلاح‌کننده‌ی `sealed` را کم و با احتیاط به کار ببرید، تا زمانی که برای نیازهایتان به کاربردشان اطمینان پیدا کنید.

[مقاله‌ی زیر][new-vs-override] کاربرد `new` را به عنوان جایگزینی برای اصلاح‌کننده‌ی `override` شرح می‌دهد. این گاهی سودمند است، مثلاً در سلسله‌مراتب‌های پیچیده‌ی کلاس‌ها و/یا نوعی تداخل میان کتابخانه‌ها.
