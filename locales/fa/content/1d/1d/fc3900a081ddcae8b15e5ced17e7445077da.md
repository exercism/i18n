# درباره

آماده‌کردن یک مقدار برای انتقال یعنی سه کار به‌طور همزمان: سریالایز کردن آن، بیرون کشیدن بخش درست آن، و کپی نکردن وقتی نیازی نیست. سه اصطلاح در Factor این حوزه را پوشش می‌دهند.

## `unparse`، از مقدار به متن مبدأ

[`unparse`][unparse] (در `prettyprint`) متن مبدأ هر مقدار را برمی‌گرداند. وارون تجزیه‌گر است؛ رفت‌وبرگشت `dup unparse parse` مقدار را بازسازی می‌کند.

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

آن را با `>string` (که فقط روی دنباله‌های نویسه کار می‌کند) و `number>string` (فقط اعداد) مقایسه کنید. `unparse` همه‌کاره است، اما هزینه‌اش این است که نحوه‌ی نگارش Factor را تولید می‌کند (رشته‌های نقل‌شده علامت نقل‌قولشان را نگه می‌دارند). پس وقتی گیرنده متن را دوباره تجزیه می‌کند ابزار درست است، و برای خروجی خوانا برای انسان ابزار نادرست.

## برش‌ها، نما نه کپی

| واژه          | کارکرد                                         |
|---------------|------------------------------------------------|
| `head`        | `( seq n -- newseq )`؛ n عنصر اول را کپی می‌کند          |
| `head-slice`  | `( seq n -- slice )`؛ نمایی از n عنصر اول          |
| `tail`        | `( seq n -- newseq )`؛ از اندیس n به بعد را کپی می‌کند  |
| `tail-slice`  | `( seq n -- slice )`؛ نمایی از اندیس n به بعد     |
| `head*`       | `( seq n -- newseq )`؛ همه به‌جز n عنصر آخر را کپی می‌کند   |
| `head-slice*` | `( seq n -- slice )`؛ نمایی از همه به‌جز n عنصر آخر   |
| `tail*`       | `( seq n -- newseq )`؛ n عنصر آخر را کپی می‌کند           |
| `tail-slice*` | `( seq n -- slice )`؛ نمایی از n عنصر آخر           |

یک `slice` چندتایی‌ای است که اندیس شروع، اندیس پایان و دنباله‌ی زیربنایی را در خود نگه می‌دارد؛ این [پروتکل دنباله][sequence-protocol] را پیاده‌سازی می‌کند، بنابراین هر عملیات دنباله‌ای روی آن کار می‌کند. وقتی در غیر این صورت فقط برای خواندن باید حافظه تخصیص دهید، سراغ گونه‌های برشی بروید؛ و وقتی می‌خواهید داده را پس از تغییر احتمالی دنباله‌ی زیربنایی نگه دارید، سراغ گونه‌های کپی‌کننده بروید.

## شکاف چندورودی: `2bi`، `3bi`، `2tri`، `3tri`

واژه‌های ساده‌ی شکاف، `bi` و `tri`، دو یا سه نقل‌قول را روی *یک* ورودی در پشته اعمال می‌کنند. گونه‌های دارای پیشوند `2` و پیشوند `3` هر نقل‌قول را روی *دو* یا *سه* ورودی اعمال می‌کنند:

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

هر نقل‌قول *همه‌ی* ورودی‌ها را دریافت می‌کند؛ پس وقتی نتیجه‌ی هر دو نقل‌قول به آن جفت وابسته است از `2bi` استفاده کنید، نه وقتی می‌خواهید یک محاسبه‌ی یکسان جداگانه روی هر ورودی اعمال شود (آن کار `bi@` است).

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

برای اینکه *یک* نقل‌قول جداگانه روی هر ورودی اعمال شود، به‌جای آن سراغ `bi@` (دو ورودی) یا `tri@` (سه ورودی) بروید؛ از یک خانواده‌اند، اما شکلشان فرق دارد.
