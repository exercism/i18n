# مقدمه

## بهینه‌سازی فراخوانی دنباله

هر بار که تابعی فراخوانی می‌شود، یک «فریم پشته»ی جدید در حافظه ساخته می‌شود تا آرگومان‌ها و متغیرهای محلی تابع را در خود نگه دارد. این فریم پشته هنگام بازگشت تابع آزاد می‌شود. چون Gleam به‌جای نحوه‌ی نگارش حلقه‌ای از فراخوانی‌های بازگشتی توابع استفاده می‌کند، ممکن است این فریم‌های پشته حجم زیادی از حافظه را اشغال کنند.

برای جلوگیری از این مشکل، Gleam از «بهینه‌سازی فراخوانی دنباله» پشتیبانی می‌کند. این بهینه‌سازی به کامپایلر اجازه می‌دهد اگر آخرین کار تابع، فراخوانی یک تابع باشد، فریم پشته‌ی تابع جاری را دوباره به کار بگیرد. یعنی یک تابع می‌تواند بی‌نهایت بار خودش را فراخوانی کند بدون آنکه حافظه‌ی اضافی مصرف شود.

اغلب می‌توان توابع بازگشتی بهینه‌نشده را با استفاده از یک «تجمیع‌کننده» به توابعی بازنویسی کرد که بهینه‌سازی فراخوانی دنباله دارند.

تجمیع‌کننده متغیری است که علاوه بر داده‌ها منتقل می‌شود. از آن برای انتقال وضعیت جاری اجرای تابع استفاده می‌شود، تا زمانی که به «حالت پایه» برسیم.

تجمیع‌کننده‌ها را باید نویسنده‌ی تابع مقداردهی اولیه کند، نه کاربر تابع. برای این کار دو تابع تعریف کنید. یک تابع عمومی که فقط داده‌های لازم را به‌عنوان آرگومان می‌گیرد و تجمیع‌کننده را مقداردهی اولیه می‌کند و یک تابع خصوصی که تجمیع‌کننده را هم می‌گیرد.

```gleam
// Count the length of a list without tail call optimisation
pub fn count(list: List(String)) -> Int {
  case list {
    [] -> 0
    [_, ..rest] -> {
      let amount = count(rest) // Non-tail recursive call
      amount + 1
    }
  }
}
```

```gleam
// Count the length of a list with tail call optimisation
pub fn count(list: List(String)) -> Int {
  count_elements(list, 0)
}

fn count_elements(list: List(String), accumulator: Int) -> Int {
  case list {
    [] -> accumulator
    [_, ..rest] -> {
      let accumulator = accumulator + 1
      count_elements(rest, accumulator) // Tail recursive call
    }
  }
}
```
