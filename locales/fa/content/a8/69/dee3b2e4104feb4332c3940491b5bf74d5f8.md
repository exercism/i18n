# مقدمه

«behaviours» به ما اجازه می‌دهند رابط‌هایی (مجموعه‌ای از توابع و ماکروها) را در یک _ماژول behaviour_ تعریف کنیم که بعداً می‌توانند توسط _ماژول‌های callback_ مختلف پیاده‌سازی شوند. به لطف رابط مشترک، آن ماژول‌های callback را می‌توان به‌جای یکدیگر به کار برد.

~~~~exercism/note
به املای بریتانیاییِ «behaviours» توجه داشته باشید.
~~~~

## تعریف behaviours

برای تعریف یک behaviour، باید یک ماژول جدید بسازیم و توابعی را که بخشی از رابط مورد نظرند مشخص کنیم. هر تابع باید با استفاده از ویژگی ماژول `@callback` تعریف شود. نحوه‌ی نگارش آن دقیقاً همانند [typespec تابع][concept-typespecs] (`@spec`) است. باید اسم تابع، فهرستی از نوع آرگومان‌ها و همه‌ی نوع‌های بازگشتی ممکن را مشخص کنیم.

```elixir
defmodule Countable do
  @callback count(collection :: any) :: pos_integer
end
```

## پیاده‌سازی behaviours

برای افزودن یک behaviour موجود به ماژولمان (ساخت یک ماژول callback) از ویژگی ماژول `@behaviour` استفاده می‌کنیم. مقدار آن باید اسم همان ماژول behaviour باشد که داریم اضافه می‌کنیم.

سپس باید همه‌ی توابع (callbackها)ی موردنیاز آن ماژول behaviour را تعریف کنیم. اگر داریم behaviour شخص دیگری را پیاده‌سازی می‌کنیم، مثل behaviourهای درونی Elixir مانند `Access` یا `GenServer`، فهرست همه‌ی callbackهای آن behaviour را در مستندات [hexdocs.pm][hexdocs] پیدا می‌کنیم.

یک ماژول callback محدود به پیاده‌سازی فقط توابعی که بخشی از behaviour آن هستند نیست. همچنین ممکن است یک ماژول واحد چندین behaviour را پیاده‌سازی کند.

برای مشخص کردن اینکه هر تابع از کدام behaviour می‌آید، باید پیش از هر تابع از ویژگی ماژول `@impl` استفاده کنیم. مقدار آن باید اسم همان ماژول behaviour باشد که این callback را تعریف می‌کند.

```elixir
defmodule BookCollection do
  @behaviour Countable

  defstruct [:list, :owner]

  @impl Countable
  def count(collection) do
    Enum.count(collection.list)
  end

  def mark_as_read(collection, book) do
    # other function unrelated to the Countable behaviour
  end
end
```

## پیاده‌سازی‌های پیش‌فرض callback

هنگام تعریف یک behaviour، می‌توان پیاده‌سازی پیش‌فرضی برای یک callback فراهم کرد. این پیاده‌سازی باید در عبارت نقل‌قول‌شده‌ی ماکروی `__using__/1` تعریف شود. تا کاربران ماژول behaviour بتوانند پیاده‌سازی پیش‌فرض را بازنویسی کنند، بعد از پیاده‌سازی تابع، ماکروی `defoverridable/1` را فراخوانی کنید. این ماکرو یک فهرست کلیدواژه‌ای می‌پذیرد که کلیدهایش اسم توابع و مقدارهایش تعداد آرگومان‌های آن توابع است.

```elixir
defmodule Countable do
  @callback count(collection :: any) :: pos_integer

  defmacro __using__(_) do
    quote do
      @behaviour Countable
      def count(collection), do: Enum.count(collection)
      defoverridable count: 1
    end
  end
end
```

توجه داشته باشید که تعریف توابع در داخل `__using__/1` برای هر هدفی جز تعریف پیاده‌سازی‌های پیش‌فرض callback توصیه نمی‌شود، اما همیشه می‌توانید توابع را در ماژول دیگری تعریف کنید و آن‌ها را در ماکروی `__using__/1` با `import` وارد کنید.
