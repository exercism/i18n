# مقدمه

یک *علامت‌دهنده* روی یک شناور گشت ساحلی، دفتر گزارش پیام‌ها را نگه می‌دارد. پرچم‌های خام علامت، قاب‌بندی‌شده با نویسه‌های نشانگر می‌رسند؛ خوانش‌ها باید برای مخابره آماده شوند؛ و جفت‌ها و سه‌گانه‌های مشاهدات در لحظه خلاصه می‌شوند. چند اصطلاح از کتابخانه‌ی استاندارد Factor بیشتر کار را انجام می‌دهند.

## `unparse`، تبدیل مقدار به متن مبدأ

[`unparse`][unparse] (در `prettyprint`) متن صورت مبدأ هر مقدار را برمی‌گرداند:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse` وارون تجزیه‌گر است؛ رفت‌وبرگشت `dup unparse parse` مقدار را بازسازی می‌کند. ابزار درست برای سریال‌ی‌کردن به قالب مخابره است که گیرنده دوباره آن را تجزیه می‌کند، و ابزار نادرست برای خروجی خوانا برای انسان (رشته‌ها گیومه‌هایشان را نگه می‌دارند، بردارها `V{ ... }` خود را، و غیره).

## گونه‌های `slice`، نما نه کپی

`head` و `tail` از `sequences` بخشی که نگه می‌دارید را در یک توالی تازه *کپی* می‌کنند. همتاهای `-slice` آن دو، یک شیء `slice` برمی‌گردانند، یک تاپل شامل اندیس شروع، اندیس پایان و توالی زیربنایی، که [پروتکل توالی][sequence-protocol] را بدون کپی پیاده‌سازی می‌کند:

| واژه          | اثر                                             |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )`، n عنصر اول را کپی می‌کند |
| `head-slice`  | `( seq n -- slice )`، نمای n عنصر اول           |
| `tail`        | `( seq n -- newseq )`، از اندیس n به بعد را کپی می‌کند |
| `tail-slice`  | `( seq n -- slice )`، نمای از اندیس n به بعد    |
| `head*`       | `( seq n -- newseq )`، همه به جز n عنصر آخر را کپی می‌کند |
| `head-slice*` | `( seq n -- slice )`، نمای همه به جز n عنصر آخر |
| `tail*`       | `( seq n -- newseq )`، n عنصر آخر را کپی می‌کند |
| `tail-slice*` | `( seq n -- slice )`، نمای n عنصر آخر           |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

یک `slice` *یک* توالی است، پس هر چیزی که توالی می‌گیرد، `slice` هم می‌گیرد؛ `length`، `first`، `each` و مانند این‌ها همه بدون کپی کار می‌کنند. آزمون‌هایی که باید با یک رشته‌ی ثابت مقایسه کنند می‌توانند با `>string` تبدیل کنند.

## `?head` و `?tail`، حذف نشانگر در صورت وجود

خوانش‌های قاب‌بندی‌شده متنی نشانگر همراه دارند که ممکن است آنجا باشد یا نباشد. `?head` و `?tail` (در `splitting`) می‌کوشند پیشوند یا پسوندی را جدا کنند و توالی (احتمالاً کوتاه‌شده) را *به‌همراه* یک «منطقی» برمی‌گردانند که گزارش می‌دهد نشانگر پیدا شد یا نه:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

این مقدار منطقی پایانی آن‌ها را برای نقش نگهبان مناسب می‌کند: `?head` را با `if` جفت کنید تا بر پایه‌ی وجود داشتن قاب انشعاب بگیرید، یا با `unless` تا ورودی‌ای را که نشانگر موردانتظار را ندارد رد کنید.

## `<repetition>`، N نسخه، به‌صورت مجازی

[`<repetition>`][repetition] (در `sequences`) یک توالی مجازی بدون کپی دیگر است؛ `( len elt -- repetition )` توالی‌ای از `len` عنصر می‌سازد که همه `elt` هستند، بدون تخصیص آن تعداد خانه:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

خود `elt` می‌تواند یک توالی باشد؛ هر نسخه همان توالی است. بعد `concat` نسخه‌ها را سر به سر به هم می‌چسباند:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

مثل `slice`، نتیجه *یک* توالی است؛ `length`، `each` و بقیه‌ی دوستان، مستقیماً روی آن کار می‌کنند. از آن استفاده کنید تا یک کد علامت را به عرضی ثابت برسانید یا رشته‌ای از نشانگرهای تکراری بچینید؛ فقط وقتی واقعاً به یک توالی مشخص نیاز دارید با `>string` (یا `>array`) تبدیل کنید.

## `<clumps>`، پنجره‌های هم‌پوشان، به‌صورت مجازی

[`<clumps>`][clumps] (در `grouping`) سومین توالی مجازی بدون کپی است؛ `( seq n -- clumps )` به `seq` به‌عنوان رشته‌ای از پنجره‌های *هم‌پوشان* به طول `n` نگاه می‌کند، که هر پنجره یک `slice` است:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

یک توالی به طول n، `length - n + 1` پنجره می‌دهد. چون هر پنجره یک `slice` است، جفت‌کردن خوانش‌های پیاپی هیچ هزینه‌ای برای کپی ندارد؛ `[ first2 ]` روی هر clumpِ `2`تایی، هر جفت پیاپی را برای تصویر کردن به شما می‌دهد. (همتای بدون هم‌پوشانی، `<groups>`، به‌جایش توالی را به بلوک‌های جدا از هم خرد می‌کند.)

## cleave چندورودی، `2bi`، `3bi`، `2tri`، `3tri`

واژه‌های ساده‌ی cleave، یعنی `bi` و `tri`، دو یا سه «نقل‌قول» را روی *یک* ورودی اعمال می‌کنند. گونه‌های با پیشوند `2` و پیشوند `3`، هر نقل‌قول را روی *دو* یا *سه* ورودی اعمال می‌کنند:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

هر نقل‌قول *همه‌ی* ورودی‌ها را دریافت می‌کند. از این‌ها وقتی استفاده کنید که بیش از یک تصویر به همان جفت (یا سه‌گانه) مقادیر وابسته باشد؛ نه وقتی می‌خواهید *همان* عملیات جداگانه روی هر ورودی اعمال شود (آن کار `bi@` یا `tri@` است).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
