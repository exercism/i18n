# درباره

تابع زمانی «بازگشتی دنباله» است که _آخرین_ کاری که انجام می‌دهد، فراخوانی خودش باشد.

هر بار که تابعی فراخوانی می‌شود، یک «فریم پشته» همراه با متغیرهای محلی، آرگومان‌ها و مواردی از این دست‌اش، روی [پشته‌ی فراخوانی تابع][call-stack] قرار می‌گیرد. وقتی تابع برمی‌گردد، فریم پشته از پشته حذف می‌شود.

توابع بازگشتی دنباله امکان [بهینه‌سازی فراخوانی دنباله][tail-call-optimization] را فراهم می‌کنند. این بهینه‌سازی اجازه می‌دهد فراخوانی تابع بعدی از آخرین فریم پشته دوباره استفاده کند، چون تابع قبلی مطمئناً دیگر به آن نیازی ندارد. این کار نگرانی از سرریز شدن پشته‌ی فراخوانی تابع را کاهش می‌دهد؛ وضعیتی که در آن آن‌قدر فریم روی پشته‌ی فراخوانی تابع وجود دارد که حافظه‌ای برای ساختن فریم دیگری باقی نمانده است.

- برای دستیابی به بازگشت دنباله در Elixir، معمولاً به یک «انباشتگر» نیاز است، به دلیل قواعد تغییرناپذیری داده‌ها.

  - انباشتگر متغیری است که همراه با فراخوانی بازگشتی منتقل می‌شود و وضعیت فعلی تابع بازگشتی را _تا این‌جای کار_ نگه می‌دارد، تا در «حالت پایه» نتیجه‌ی نهایی برگردانده شود.

    ```elixir
    # Count the length of a list without an accumulator
    def count([]), do: 0
    def count([_head | tail]), do: 1 + count(tail)

    # Count the length of a list with an accumulator
    def count(list), do: do_count(list, 0)

    defp do_count([], count), do: count
    defp do_count([_head | tail], count), do: do_count(tail, count + 1)
    ```

- وقتی با لیست‌ها کار می‌کنید، به یاد داشته باشید که به صورت «لیست‌های پیوندی یک‌طرفه» پیاده‌سازی شده‌اند: عملیات افزودن به ابتدا خیلی سریع است، اما عملیات افزودن به انتها خیلی کند است.

  ```elixir
  # Reverse a list with an accumulator
  def reverse(list), do: do_reverse(list, [])

  defp do_reverse([], acc), do: acc

  defp do_reverse([head | tail], acc) do
    do_reverse(tail, [head | acc])
  end
  ```
