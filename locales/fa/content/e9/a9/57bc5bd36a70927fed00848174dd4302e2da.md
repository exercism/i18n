# مقدمه

وقت آن رسیده که به یکی از پارادایم‌های اصلی C++ بپردازیم: برنامه‌نویسی شیءگرا (OOP).
برنامه‌نویسی شیءگرا حول `classes` می‌چرخد: انواع داده‌ای که خود کاربر تعریف می‌کند و مجموعه‌ی توابع مرتبط خودشان را دارند.
ما از مبانی شروع می‌کنیم و در ادامه‌ی درخت سرفصل به موضوعات پیشرفته‌تر می‌پردازیم.

## اعضا

کلاس‌ها می‌توانند **متغیرهای عضو** و **توابع عضو** داشته باشند.
دسترسی به آن‌ها با عملگر **انتخاب عضو** یعنی `.` انجام می‌شود.
همان‌طور که درباره‌ی متغیرهای بیرون از `classes` توصیه می‌شود، بهتر است متغیرهای عضو را هم هنگام تعریف با یک مقدار مقداردهی اولیه کنید.
این مقدار از آن پس، مقدار پیش‌فرض شیءهای تازه‌ساخته‌شده از این کلاس خواهد بود.

## کپسوله‌سازی و پنهان‌سازی اطلاعات

کلاس‌ها این امکان را می‌دهند که دسترسی به اعضایشان محدود شود.
دو حالت پایه‌ی آن `private` و `public` هستند.
اعضای `private` از بیرون کلاس قابل دسترسی نیستند.
اعضای `public` را می‌توان آزادانه فراخوانی کرد.
همه‌ی اعضا به‌طور پیش‌فرض `private` هستند و برای اینکه بیرون از کلاس قابل استفاده باشند، باید صریحاً علامت‌گذاری شوند.

## یک مثال ساده

تعریف یک `class` تازه را در مثال زیر می‌بینید.
به `;` بعد از تعریف دقت کنید.

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

از داخل کلاس می‌توانید به همه‌ی متغیرها دسترسی داشته باشید.
نگاهی به `damage` درون تابع `cast_spell` بیندازید.
نمی‌توانید اعضای `private` را بیرون از کلاس بخوانید یا تغییر دهید:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## سازنده‌ها

«سازنده»ها این امکان را فراهم می‌کنند که هنگام ساخت شیء، به متغیرهای عضو مقدار بدهید.
اسم آن‌ها همان اسم `class` است و نوع بازگشتی ندارند.
یک کلاس می‌تواند چندین سازنده داشته باشد.
این موضوع وقتی به کار می‌آید که همیشه نیازی به مقداردهی همه‌ی متغیرها نداشته باشید.

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

سازنده‌ها موضوعی بزرگ‌اند و ظرافت‌های زیادی دارند.
اگر برای `class` خود صریحاً `constructor` تعریف نکنید، آن‌وقت (و فقط در این صورت) کامپایلر این کار را برایتان انجام می‌دهد.
این اتفاق در مثال اول بالا افتاده است.
شیء _silverhand_ با فراخوانی سازنده‌ی پیش‌فرض ساخته می‌شود و هیچ آرگومانی به آن داده نشده است.
همه‌ی متغیرها روی مقداری تنظیم می‌شوند که در تعریف کلاس ذکر شده است.
اگر در آن تعریف هیچ مقداری نداده بودید، ممکن بود متغیرها مقداردهی اولیه نشده باقی بمانند و این می‌توانست پیامدهای ناخواسته‌ای داشته باشد.

## ساختارها

ساختارها از ریشه‌های اصلی زبان C آمده‌اند و به قدمت خود C++ هستند.
آن‌ها در عمل همان `classes` هستند، با یک استثنای مهم.
به‌طور پیش‌فرض، همه‌ی اعضای یک `class` از نوع `private` است.
اما اعضای یک ساختار تا وقتی خلاف آن تعریف نشود، `public` هستند.
طبق قرارداد، کلیدواژه‌ی `struct` اغلب برای **ساختارهای صرفاً داده** به کار می‌رود.
در عوض، کلیدواژه‌ی `class` برای شیءهایی ترجیح داده می‌شود که باید ویژگی‌های خاصی را تضمین کنند.
نمونه‌ای از یک «ناوردا» می‌تواند این باشد که `damage` در `class` به اسم `Wizzard` شما هرگز منفی نشود.
متغیر `damage` خصوصی است و هر تابعی که `damage` را تغییر دهد، تضمین می‌کند که ناوردا حفظ شود.
