# مقدمه

## کلاس‌ها

وقت آن رسیده که به یکی از پارادایم‌های اصلی C++ بپردازیم: برنامه‌نویسی شیءگرا (OOP).
برنامه‌نویسی شیءگرا حول `classes` می‌چرخد؛ انواع داده‌ای که خود کاربر تعریف می‌کند و مجموعه‌ای از توابع مرتبط خودشان را دارند.
با مبانی شروع می‌کنیم و در ادامه‌ی مسیر آموزشی به موضوع‌های پیشرفته‌تر می‌پردازیم.

### اعضا

هر «کلاس» می‌تواند **متغیر عضو** و **تابع عضو** داشته باشد.
دسترسی به آن‌ها با عملگر **انتخاب عضو** یعنی `.` انجام می‌شود.
همانند متغیرهای بیرون از `classes`، بهتر است متغیرهای عضو را در زمان اعلان با یک مقدار، مقداردهی اولیه کنید.
این مقدار سپس به مقدار پیش‌فرض برای اشیای تازه‌ساخته‌شده‌ی این کلاس تبدیل می‌شود.

### کپسوله‌سازی و پنهان‌سازی اطلاعات

کلاس‌ها این امکان را فراهم می‌کنند که دسترسی به اعضایشان محدود شود.
دو `access specifiers` پایه، `private` و `public` هستند.
اعضای `private` از بیرون کلاس قابل دسترسی نیستند.
اعضای `public` آزادانه قابل دسترسی‌اند.
همه‌ی اعضای یک `class` به‌طور پیش‌فرض `private` هستند.
تنها اعضایی که صریحاً با `public` علامت خورده‌اند، بیرون از کلاس آزادانه قابل استفاده‌اند.

### یک مثال ساده

تعریف یک `class` را می‌توانید در مثال زیر ببینید.
به `;` بعد از تعریف توجه کنید:

```cpp
class Wizard {
  public:               // from here on all members are publicly accessible
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

از درون کلاس می‌توانید به همه‌ی متغیرهای عضو دسترسی داشته باشید.
نگاهی به `damage` درون تابع `cast_spell` بیندازید.
نمی‌توانید اعضای `private` را بیرون از کلاس بخوانید یا تغییر دهید:

```cpp
Wizard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

### سازنده‌ها

سازنده‌ها این امکان را می‌دهند که هنگام ساخت شیء، به متغیرهای عضو مقدار اختصاص دهید.
آن‌ها همان اسم `class` را دارند و نوع بازگشتی ندارند.
یک کلاس می‌تواند چندین سازنده داشته باشد.
این زمانی مفید است که همیشه نیازی به تنظیم همه‌ی متغیرها نداشته باشید.
گاهی ممکن است بخواهید همه‌چیز را پیش‌فرض نگه دارید اما متغیر `name` را تغییر دهید.
در مورد یک جادوگر قدرتمند ممکن است بخواهید آسیب را هم تغییر دهید، بنابراین به دو `constructors` نیاز دارید.

```cpp
class Wizard {
  public:
    Wizard(std::string new_name) {
      name = new_name;
    }
    Wizard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizard el{"Eleven"};       // deals  5 damage
Wizard vecna{"Vecna", 50}; // deals 50 damage
```

سازنده‌ها موضوعی بزرگ‌اند و ظرافت‌های زیادی دارند.
اگر برای `class` خود صریحاً `constructor` تعریف نکنید، آن‌گاه، و تنها آن‌گاه، کامپایلر این کار را برایتان انجام می‌دهد.
این اتفاق در مثال اول بالا رخ داده است.
شیء _silverhand_ با فراخوانی سازنده‌ی پیش‌فرض ساخته می‌شود و هیچ آرگومانی به آن داده نشده است.
همه‌ی متغیرها روی مقداری تنظیم می‌شوند که در تعریف کلاس ذکر شده است.
اگر در آن تعریف هیچ مقداری نداده بودید، متغیرها ممکن بود مقداردهی اولیه‌نشده باقی بمانند و این می‌توانست پیامدهای ناخواسته‌ای داشته باشد.

## ساختارها

ساختارها از ریشه‌های اولیه‌ی زبان C می‌آیند و به قدمت خود C++ هستند.
آن‌ها عملاً همان `classes` هستند، با یک استثنای مهم.
به‌طور پیش‌فرض، همه‌چیز در یک `class` از نوع `private` است.
ساختارها اما تا وقتی خلافشان تعریف نشود، `public` هستند.
به‌طور قراردادی، کلیدواژه‌ی `struct` اغلب برای **ساختارهای فقط-داده** استفاده می‌شود.
کلیدواژه‌ی `class` برای اشیایی ترجیح داده می‌شود که باید ویژگی‌های خاصی را تضمین کنند.
نمونه‌ای از چنین «ناوردایی» می‌تواند این باشد که `damage` در `class`ِ `Wizard` شما نتواند منفی شود.
متغیر `damage` از نوع `private` است و هر تابعی که آسیب را تغییر دهد، تضمین می‌کند که ناوردا حفظ شود.
