# درباره

## const

اصلاح‌کننده‌ی [`const`][constants] را می‌توان (و عموماً باید) روی هر فیلدی به کار برد که مقدارش در زمان کامپایل معلوم است و در طول عمر برنامه تغییر نمی‌کند.

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

کامپایلر به شما نشان می‌دهد که چه عبارت‌هایی را می‌توان در زمان کامپایل ارزیابی کرد. عملیات ساده‌ی حسابی و همچنین الحاق رشته‌ها مجازند. این کار هر ارزیابی‌ای را که به استفاده از «هیپ» یا «پشته» نیاز داشته باشد کنار می‌گذارد؛ در نتیجه همه‌ی فراخوانی‌های متد و ارجاع به انواع غیرابتدایی در دسترس نیستند.

در وب بحث‌هایی درباره‌ی مزایای کارایی [`const`][constants] نسبت به متغیرها وجود دارد. در مقایسه با فیلدهای نمونه‌ای که `const` نیستند، ممکن است صرفه‌جویی محسوسی در حافظه وجود داشته باشد، اما در مقایسه با متغیرهای استاتیک این مقدار قطعاً ناچیز است. هر توجهی به کارایی CPU احتمالاً از نظر همکارانتان [بهینه‌سازی زودهنگام][premature-optimization] به حساب می‌آید.

دلیل قانع‌کننده‌تری برای استفاده از [`const`][constants] این است که توانایی نگه‌دارنده را برای استدلال درباره‌ی کد بالا می‌برد. وقتی نگه‌دارنده ببیند فیلدی با `const` یا `readonly` علامت خورده است یا خاصیتی setter ندارد، می‌تواند آن را تا حد زیادی از تحلیل خود کنار بگذارد. بعید است که کانون باگ‌ها باشد. بعید است که در بازآرایی کد دردسری ایجاد کند. این [نظر Stack Overflow][so-consts] به همین موضوع می‌پردازد.

اصلاح‌کننده‌ی `const` را می‌توان روی مقادیر داخل متدها هم به کار برد:

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

نام‌گذاری یک مقدار با `const` به این شکل می‌تواند مفید باشد اگر آن مقدار چند بار در متد استفاده شود یا بخواهید به معنای آن توجه جلب کنید. نسبت به استفاده از لیترال‌ها به‌صورت درجا هیچ بهبودی در کارایی ندارد.

## readonly

اصلاح‌کننده‌ی [`readonly`][readonly-fields] را می‌توان (و عموماً باید) روی هر فیلدی به کار برد که نمی‌توان آن را `const` کرد و مقدارش در طول عمر برنامه تغییر نمی‌کند، و یا با یک مقداردهی اولیه‌ی درجا تنظیم می‌شود یا در زمان نمونه‌سازی (توسط سازنده یا متدی که سازنده فراخوانی می‌کند).

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

استفاده از اصلاح‌کننده‌ی `readonly` به همان دلایلی که برای `const` گفتیم تشویق می‌شود. محدود کردن فیلدها به این شکل به نگه‌دارندگان کمک می‌کند درباره‌ی کد استدلال کنند.

توجه داشته باشید که افزودن اصلاح‌کننده‌ی `readonly` به یک فیلد فقط از تغییر مقدار همان فیلد جلوگیری می‌کند. در مورد انواع تجمیعی، از فیلدها یا خاصیت‌های آن نوع محافظت نمی‌کند. به‌ویژه، از محتوای آرایه محافظت نمی‌کند.

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

برای اطمینان از اینکه همه‌ی اعضای یک نوع ارجاعی محافظت می‌شوند، می‌توان فیلدها را `readonly` کرد و خاصیت‌های خودکار را بدون accessor `set` تعریف کرد.

بهتر است [مجموعه‌های فقط‌خواندنی][readonly-collections] در کتابخانه‌ی کلاس پایه را بررسی کنید.

برای آرایه، نزدیک‌ترین چیزی که به یک نسخه‌ی فقط‌خواندنی می‌توانید داشته باشید، متد [`Array.AsReadOnly<T>()`][as-read-only] است.
