# مقدمه

«تجزیه» فرایندی است که متن را به داده‌ی معنادار تبدیل می‌کند.
توابع بسته‌ی `String` در این زمینه محدودند و استفاده از عبارت‌های باقاعده دشوار است، بنابراین روش مرسوم تجزیه در Elm استفاده از بسته‌ی `elm/parser` است.

بیایید مثالی از نوشتن یک تجزیه‌گر برای (زیرمجموعه‌ای از) زبان برنامه‌نویسی [LOLCODE][lolcode] را با هم بررسی کنیم.
برنامه‌ی زیر را در نظر بگیرید که کامنت‌گذاری شده است:

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

ابتدا بیایید یک نوع Elm بنویسیم که دستورهای ممکن را نمایش دهد:

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

آنگاه می‌توان برنامه‌ی LOLCODE ما را به‌صورت یک `List Command` مدل کرد.
بیایید با یک تجزیه‌گر برای خط `HAI 1` شروع کنیم:

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

`versionP` با استفاده از یک _خط لوله‌ی تجزیه_ ساخته شده است.
عملگر `(|.)` به این معناست که رشته تجزیه می‌شود اما نتیجه دور ریخته می‌شود و `(|=)` به این معناست که رشته تجزیه می‌شود و نتیجه نگه داشته می‌شود.
در این مثال، `Parser.keyword "HAI"` یک «HAI» را مصرف می‌کند، اما آن نتیجه نادیده گرفته می‌شود.
`Parser.spaces` هر تعداد از کاراکترهای ' '، '\n' و '\r' را مصرف می‌کند، اما آن هم نادیده گرفته می‌شود.
`Parser.int` یک عدد صحیح را تجزیه می‌کند و مقدار آن عدد صحیح (مثلاً ۱) به بالاترین `Parser.succeed Version` فرستاده می‌شود و تجزیه‌گر با موفقیت مقدار `Version 1` را برمی‌گرداند.

اگر هر یک از تجزیه‌گرهای خط لوله شکست بخورد، یک `Parser.DeadEnd` برمی‌گرداند و کل تجزیه‌گر شکست می‌خورد.
یک تجزیه‌گر را می‌توان با `Parser.run` اجرا کرد:

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

حالا با این کد به سراغ خط «CAN HAS STDIO?» می‌رویم:

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP` هم یک خط لوله‌ی تجزیه است، اما این بار با `Parser.symbol` پایان می‌یابد که برای تجزیه‌ی نمادهایی مانند «?» مناسب است.
مقداری که می‌خواهیم نگه داریم (اسم بسته‌ای که باید وارد شود) با این کد تجزیه می‌شود:

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

از آنجا که نمی‌دانیم اسم بسته چه خواهد بود، نمی‌توانیم از `Parser.keyword` استفاده کنیم، بنابراین به‌جای آن از `Parser.chompWhile` استفاده می‌کنیم که کاراکترها را تک‌تک تا زمانی که یک شرط را برآورده کنند مصرف می‌کند (در اینجا، الفبایی‌عددی بودن).
این کاراکترهای مصرف‌شده سپس توسط `Parser.getChompedString` جمع‌آوری می‌شوند که یک `Parser String` برمی‌گرداند.
در این مورد، می‌خواهیم اسم بسته‌ها را یکدست کنیم، بنابراین از `Parser.map` استفاده می‌کنیم تا رشته‌ی موجود در تجزیه‌گر را تغییر دهیم و آن را به حروف کوچک تبدیل کنیم.

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

در ادامه، `VISIBLE "HAI WORLD!"` با این کد تجزیه می‌شود:

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

اکنون برای هر دستور یک تجزیه‌گر داریم.
البته در یک برنامه‌ی کلی، ترتیب این دستورها قابل پیش‌بینی نیست، بنابراین یک تجزیه‌گر عمومی برای دستورها می‌سازیم:

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

`Parser.oneOf` هر تجزیه‌گر را به ترتیب داده‌شده امتحان می‌کند.
اگر تجزیه‌گری شکست بخورد، تجزیه‌گر بعدی امتحان می‌شود، اما اگر موفق شود، نتیجه‌اش بدون امتحان کردن تجزیه‌گرهای باقی‌مانده برگردانده می‌شود.
اگر همه‌ی تجزیه‌گرها شکست بخورند، `Parser.oneOf` هم شکست می‌خورد.

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

توجه کنید که هر تلاش ناموفق یک `Parser.DeadEnd` تولید می‌کند که `Parser.oneOf` آن‌ها را جمع‌آوری می‌کند.

برای تجزیه‌ی یک برنامه‌ی کامل، باید چندین دستور را پشت سر هم با این کد تجزیه کنیم:

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence` یک تجزیه‌گر بسیار قابل‌تنظیم با چندین گزینه است.
`start`، `separator` و `end` رشته‌هایی می‌گیرند که عناصر دنباله را از هم جدا می‌کنند؛ برای تجزیه‌ی یک لیست Elm از «[»، «,» و «]» استفاده می‌کردیم.
`spaces` با گرفتن تجزیه‌گری که فاصله‌های احتمالی بین عناصر و جداکننده‌ها را مدیریت می‌کند انعطاف‌پذیری فراهم می‌کند؛ برای تجزیه‌ی یک لیست Elm از `Parser.spaces` استفاده می‌کردیم، اما در این مورد هیچ فاصله‌ای را نمی‌پذیریم، بنابراین از `Parser.succeed ()` استفاده می‌کنیم که بلافاصله و بدون مصرف واقعی چیزی موفق می‌شود.
`item` تجزیه‌گر عنصر را می‌گیرد، و در نهایت `trailing` به ما اجازه می‌دهد تصمیم بگیریم که جداکننده‌های انتهایی `Parser.Forbidden`، `Parser.Mandatory` یا `Parser.Optional` باشند.

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

وقتی تجزیه‌گرها موفق می‌شوند، مصرف رشته را متوقف می‌کنند:

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

پس اگر بخواهیم مطمئن شویم که تمام رشته را تجزیه کرده‌ایم، می‌توانیم از `Parser.end` استفاده کنیم:

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

در نهایت، گاهی لازم است بر اساس محتوای تجزیه‌شده‌ی یک تجزیه‌گر تصمیم بگیریم که آن را شکست دهیم.
برای مثال، اگر به تجزیه‌گری نیاز داشتیم که برنامه‌هایی را که با دو دستور «HAI» پشت سر هم شروع می‌شوند شکست دهد، می‌توانستیم از این کد استفاده کنیم:

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

`Parser.andThen` می‌تواند محتوای یک تجزیه‌گر را بررسی کند و بر اساس مقدارش یک تجزیه‌گر جدید برمی‌گرداند.
در اینجا، در یک حالت تجزیه‌گر را با یک پیام سفارشی و با استفاده از `Parser.problem` شکست دادیم، و در حالت دیگر مقدار اصلی را برگرداندیم.

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
