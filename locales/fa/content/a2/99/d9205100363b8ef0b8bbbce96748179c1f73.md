# تست

برای اجرای تست‌ها، دستور زیر را در پوشه‌ی تمرین اجرا کنید:

```bash
dub test
```

## قبولی در تست‌ها

با پیروی از [سه قانون توسعه‌ی تست‌محور](http://butunclebob.com/ArticleS.UncleBob.TheThreeRulesOfTdd)، اولین تست را کامپایل و لینک کنید و کاری کنید که پاس شود. با اعلان فضاهای نام، توابع، کلاس‌ها و موارد دیگر، فقط به اندازه‌ای ساختار بسازید که خطاهای کامپایلر برطرف شوند و تست شکست بخورد. سپس فقط به اندازه‌ای کد بنویسید که تست پاس شود. پس از این کار، خط زیر را به بعد از تست بعدی منتقل کنید تا تست بعدی از حالت کامنت خارج شود.

```D
static if (all_tests_enabled)
```

ممکن است این کار به خطاهای کامپایل منجر شود، چون ممکن است ساختارهای جدیدی فراخوانی شوند که هنوز آن‌ها را اعلان یا تعریف نکرده‌اید. دوباره، خطاهای کامپایل را به شکلی حداقلی برطرف کنید تا تست شکست بخورد، سپس کد را به شکلی حداقلی تغییر دهید تا تست پاس شود، پیاده‌سازی خود را برای خوانایی و رسایی بازآرایی کنید و بعد به سراغ تست بعدی بروید.

بکوشید به‌جای نوشتن دستی الگوریتم‌ها یا امکانات سطح‌پایین خودتان، از امکانات استاندارد D استفاده کنید.
