# تست‌ها

هر تمرین یک فایل تست دارد.
تست‌ها را با برنامه‌ی `bats` اجرا کنید.
```bash
bats test-hello-world.bats
```

`bats` باید نصب شود.
برای دستورالعمل‌های نصب `bats` روی سیستم خود، صفحه‌ی [اجرای تست‌ها در مسیر Bash][bash] را ببینید.

### `bats` با `bash` پیاده‌سازی شده است

فایل `bats` یک اسکریپت `bash` است و چند تابع ویژه دارد که دستور `bats` آن‌ها را می‌شناسد.
تست‌هایی را خواهید دید که شبیه این هستند:
```sh
gawk -f some-exercise.awk <<< "some,input,here"
```
آن نحو `<<<` یک [Here String][here-string] در `bash` است.
رشته‌ی سمت راست را به ورودی استاندارد برنامه‌ی سمت چپ می‌فرستد.
این ([تقریباً][so]) معادل این است:
```sh
echo "some,input,here" | gawk -f some-exercise.awk
```

## راهنما برای توابع assert

تست‌ها از توابع کتابخانه‌ی [bats-assert][bats-assert] استفاده می‌کنند.
راهنمای توابع مختلف `assert*` را همان‌جا می‌توانید پیدا کنید.

## تست‌های ردشده

حل کردن یک تمرین یعنی کاری کنید که همه‌ی تست‌های آن پاس شوند.
به‌صورت پیش‌فرض، وقتی تست‌ها را اجرا می‌کنید، فقط یک تست (اولین تست) اجرا می‌شود.
این کار عمدی است، چون به شما امکان می‌دهد فقط روی پاس کردن همان یک تست تمرکز کنید.
وقتی آن تست پاس شد، می‌توانید با کامنت کردن یا حذف کردنِ

    [[ $BATS_RUN_SKIPPED == true ]] || skip

حاشیه‌نویسی‌هایی که پیش از تست‌های دیگر آمده‌اند، تست بعدی را فعال کنید.

## لغو رد شدن‌ها

برای اجرای همه‌ی تست‌ها، از جمله تست‌هایی که حاشیه‌نویسی `skip` دارند، می‌توانید این دستور را اجرا کنید:
```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

استفاده از یک تابع پوشش‌دهنده برای صرفه‌جویی در تایپ می‌تواند راحت باشد: در `bash` می‌توانید این کار را بکنید:
```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```
بعد تست‌ها را فقط با این دستور اجرا کنید:
```bash
bats
```

## خروجی دیباگ

```exercism/caution
این کار به‌صورت محلی با `bats` جواب می‌دهد، اما در ویرایشگر آنلاین Exercism **نه**.
```

وقتی تست‌ها را اجرا می‌کنید، `bats` هم stdout و هم stderr را برای مقایسه با خروجی مورد انتظار ثبت می‌کند.
اگر پیام‌های دیباگ را به stdout یا stderr چاپ کنید، در خروجی ثبت‌شده گنجانده می‌شوند و ممکن است باعث شکست تست شوند.

برای چاپ اطلاعات دیباگ بدون اثر گذاشتن روی نتیجه‌ی تست‌ها، `bats` توصیف‌گر فایل **۳** را برای همین کار در اختیارتان می‌گذارد.
هر چیزی که به فایل `/dev/fd/3` چاپ شود، در هنگام اجرای تست نمایش داده می‌شود، اما در خروجی ثبت‌شده‌ای که مبنای ادعاها قرار می‌گیرد، گنجانده نمی‌شود.

مثال:

```awk
BEGIN {
    # This debug message will not interfere with test output comparison
    print "a debug message" > "/dev/fd/3"

    # Normal program output (this is what your tests will see and compare)
    print "Hello, World!"
}
```

نمونه‌ی اجرا:

```none
$ bats test-hello-world.bats
test-hello-world.bats
 ✓ Say Hi!
a debug message

1 test, 0 failures
```

این کار به شما امکان می‌دهد خروجی دیباگ مفیدی را ببینید، بدون آنکه روی تست‌ها اثری بگذارد.

اگر در چند جای کدتان از آن استفاده می‌کنید، پنهان کردن جزئیات در یک تابع ممکن است خوانایی را بهتر کند:

```awk
BEGIN {
    debug("starting ...")
}

# do stuff here ...

END {
    debug("... finished")
}

function debug(msg) {print msg > "/dev/fd/3"}
```
