# مقدمه

همه‌ی خطاها در Elixir، _Exception Behaviour_ را پیاده‌سازی می‌کنند. دقیقاً مثل _Access Behaviour_، _Exception Behaviour_ توابع «کالبک» را تعریف می‌کند که یک ماژول باید پیاده‌سازی کند تا قرارداد نرم‌افزاری این رفتار را برآورده کند. وقتی یک خطا تعریف شد، ویژگی‌های زیر را دارد:

- اسم ماژول، اسم خطا را تعیین می‌کند.
- ماژول یک struct خطا تعریف می‌کند.
- این struct یک فیلد `:message` خواهد داشت.
- می‌توان ماژول را با `raise/1` و `raise/2` به کار برد تا خطای موردنظر ایجاد شود

_Exception Behaviour_ همچنین دو «کالبک» را مشخص می‌کند: `message/1` و `exception/1`. اگر پیاده‌سازی نشوند، از پیاده‌سازی‌های پیش‌فرض استفاده می‌شود. `message/1` وقتی با `raise` فراخوانی شود، struct خطا را به یک پیام خوانا تبدیل می‌کند. `exception/1` وقتی با `raise/2` فراخوانی شود، امکان افزودن زمینه‌ی بیشتری به پیام را می‌دهد

## تعریف یک استثنا

برای تعریف یک استثنا از یک ماژول خطا، از «ماکرو»ی `defexception` استفاده می‌کنیم:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

## استفاده از استثنا

خطاهای تعریف‌شده را می‌توان مانند یک خطای داخلی، با `raise/1` یا `raise/2` به کار برد.

- `raise/1` یک خطای مشخص را با اسم ماژولش ایجاد می‌کند، یا اگر آرگومان یک رشته باشد، یک `RuntimeError` با آن رشته به عنوان پیام ایجاد می‌کند.
- `raise/2` یک خطای مشخص را با اسم ماژولش ایجاد می‌کند و یک آرگومان ویژگی‌ها می‌پذیرد که برای به دست آوردن آن خطا با پیام مناسب به کار می‌رود.
