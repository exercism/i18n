# مقدمه

اغلب مفید است که در برنامه‌هایمان نوع‌های سفارشی تعریف کنیم.

ساختن نوع‌های اولیه‌ی جدید ممکن است، اما به‌ندرت انجام می‌شود.
نوع‌های اولیه‌ی توکار انتخابی دلبخواهی نیستند: آنها به‌شکل نزدیکی با نوع‌های استاندارد کامپایلر LLVM، که جولیا برای کامپایل JIT از آن استفاده می‌کند، مطابقت دارند.

بسیار مفیدتر، توانایی تعریف نوع‌های ترکیبی با فیلدهای نام‌دار است.

زبان‌های دیگر ساختار مشابهی دارند و آنها را `structs` یا `records` می‌نامند.
مستندات جولیا آنها را `composite types` می‌نامد، هرچند (با کمی ناهمخوانی) نحوه‌ی نگارش زبان آنها را با کلیدواژه‌ی `struct` تعریف می‌کند.

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

چند نکته در مثال بالا قابل توجه است:

- هیچ نوعی برای `id` مشخص نشده است، بنابراین کامپایلر آن را به‌صورت `id::Any` تفسیر می‌کند.
- از اسم نوع به‌عنوان سازنده استفاده می‌شود، مانند `Person(id, name, age)`، تا نمونه‌ای از نوع `Person` به‌دست آید.
- می‌توان با نشانه‌گذاری نقطه‌ای به فیلدهای تک‌تک دسترسی داشت، درست مانند تاپل‌های نام‌دار.

نمونه‌های نوع `Person` تغییرناپذیرند، بنابراین به‌روزرسانی مجاز نیست.

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

اگر تغییرپذیری لازم است، `mutable` را به تعریف اضافه کنید.

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

سازنده به‌طور پیش‌فرض لازم می‌داند که فیلدها به همان ترتیبی که در تعریف آمده‌اند ظاهر شوند، که برای نوع‌های پیچیده‌تر ناخوشایند می‌شود.

استفاده از ماکروی `@kwdef` دو قابلیت جدید فراهم می‌کند:

- سازنده از کلیدواژه‌ها استفاده می‌کند، نه از موقعیت.
- فیلدها می‌توانند مقدار پیش‌فرض داشته باشند و به‌صورت اختیاری می‌توان آنها را از سازنده حذف کرد.

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## سلسله‌مراتب نوع‌های ترکیبی

تا اینجا، فقط نوع‌های ترکیبی مشخص ساخته‌ایم.
اگر بررسی کنید، همه زیرنوع `Any` هستند.

وقتی چند نوع مرتبط می‌سازید، احتمالاً منطقی‌تر است که برایشان سلسله‌مراتبی تعریف کنید.
این کار خیلی راحت انجام می‌شود.

اول، یک نوع انتزاعی بسازید:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

سپس، عملگر `<:` را در تعریف یک نوع بگنجانید تا رابطه را نشان دهید.

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

به تعداد لازم تکرار کنید و به یاد داشته باشید که زیرنوع‌سازی نوع‌های مشخص مجاز نیست.

برای سلسله‌مراتب پیچیده‌تر، در صورت نیاز زیرنوع‌های انتزاعی بسازید.

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

ارزش چنین سلسله‌مراتبی وقتی روشن‌تر می‌شود که به مفهوم `Multiple Dispatch` برسیم و ببینیم توابع با نوع‌های آرگومان چگونه رفتار می‌کنند.
