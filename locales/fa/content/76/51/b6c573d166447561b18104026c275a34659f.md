# کلیات

- فراموش نکنید که همه‌ی توابعی را که tests لازم دارند، آشکار کنید.

## 1. تعریف نوع مبهم Password با الگوی «Parse, don't validate»

- راهنمای Elm بخشی درباره‌ی [انواع سفارشی][custom-types] دارد.
- نوع سفارشی `Password` فقط یک گونه دارد.
- در Elm رسم بر این است که وقتی یک نوع سفارشی فقط یک گونه دارد، گونه و نوع همنام باشند (در این مورد، اسم هر دو `Password` خواهد بود).
- اگر نیاز به یادآوری دارید، راهنمای Elm بخشی درباره‌ی [Maybe][maybe] دارد.

## 2. آشکار کردن SecureTreasureChest، اما نه گونه‌ی آن

- راهنمای Elm بخشی درباره‌ی [انواع سفارشی][custom-types] دارد.
- نوع سفارشی `SecureTreasureChest` فقط یک گونه دارد.
- در Elm رسم بر این است که وقتی یک نوع سفارشی فقط یک گونه دارد، گونه و نوع همنام باشند (در این مورد، اسم هر دو `SecureTreasureChest` خواهد بود).

## 3. تعریف تابع createTreasure

- یک [روش کوتاه برای ساختارشکنی انواع سفارشی تک‌عضوی][single-member-custom-destructuring] وجود دارد.

## 4. تعریف تابع getTreasure

- ساده‌ترین راه انجام این کار استفاده از یک عبارت `if` است.
- اگر نیاز به یادآوری دارید، راهنمای Elm بخشی درباره‌ی [Maybe][maybe] دارد.
