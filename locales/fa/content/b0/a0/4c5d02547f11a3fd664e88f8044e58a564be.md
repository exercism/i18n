# درباره

## JSON

[JSON][json] (نشانه‌گذاری شیء JavaScript) یک قالب داده و فایل انسان‌خوان است که معمولاً برای تبادل داده، به‌ویژه برای برنامه‌های وب، استفاده می‌شود. بنابراین جای تعجب نیست که در زبان Elm جایگاه ویژه‌ای دارد.

Elm ماژول‌های اصلی [`Json.Decode`][decode] و [`Json.Encode`][encode] را برای تجزیه و نوشتن داده‌های JSON فراهم می‌کند. «رمزگشاهای JSON» روشی برای _اعلان_ این هستند که چه نوع داده‌ای انتظار می‌رود و داده باید به کدام ساختار داده نگاشت شود.

وقتی از زبان‌های با نوع‌دهی پویا می‌آیید، رمزگشاها در نگاه اول اغلب دست‌وپاگیر یا بیش از حد سخت‌گیر به نظر می‌رسند. گرچه قطعاً پرگو هستند، دست‌کم در Elm، ابزاری ارزشمند برای توصیف صریح انتظارات برنامه‌ها از داده‌های ورودی به شمار می‌روند و [از انواع پویا کم‌بیان‌تر نیستند][dynamic-types-not-more-open].

بیایید چند نام مستعار و نوع را از ماژول‌ها وارد کنیم:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

استفاده از `Decode.decodeString : Decoder a -> String -> Result Error a` همراه با یک رمزگشا و یک رشته‌ی JSON یا موفق می‌شود، اگر رشته با مشخصات رمزگشا مطابقت داشته باشد، یا در غیر این صورت شکست می‌خورد. هنگام تعریف رمزگشا، هیچ راهی برای بررسی داده‌های خام JSON وجود ندارد، که ممکن است برای کسانی که از زبان‌های امری می‌آیند غیرمعمول به نظر برسد.

## رمزگشاهای انواع داده‌ی پایه

JSON تعداد کمی نوع داده‌ی اصلی دارد:

- «رشته»: با گیومه‌های دوگانه کد می‌شود `"hello world"`
- «منطقی»: یا `true` یا `false`
- «عدد»: مانند `34` یا `0.12`
- «تهی»: نبود داده، `null`

هر یک از این‌ها با یک تابع `Decode` مرتبط است:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

توجه کنید که `Decode.null` به شما اجازه می‌دهد تصمیم بگیرید `null` را در برنامه‌تان چگونه مدل کنید، چون یک مقدار دلخواه را به‌عنوان آرگومان می‌گیرد (شاید `()`، `Nothing`، یا هر چیزی که برای برنامه‌تان مناسب است).

## ترکیب رمزگشاها

JSON همچنین دو ساختار داده برای گردآوری انواع داده‌ی اصلی تعریف می‌کند:

- «آرایه»: مجموعه‌ای از انواع داده‌ی دیگر `[0, null, "none", []]`
- «شیء»: مجموعه‌ای از «جفت‌های کلید-مقدار» `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode` نیز توابعی برای رمزگشایی این‌ها ارائه می‌دهد:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

این توابع `Decode.list : Decoder a -> Decoder (List a)` و `Decode.dict : Decoder a -> Decoder (Dict String a)` هرکدام یک رمزگشا به‌عنوان آرگومان انتظار دارند، که انتظار می‌رود هر تک‌عنصرِ ساختار داده را رمزگشایی کند. اگر رمزگشای آرگومان در رمزگشایی هر عنصری از یک مقدار آرایه یا شیء شکست بخورد، کل رمزگشا شکست می‌خورد، که الگویی رایج است.

ترکیب رمزگشاهای ساده در رمزگشاهای پیچیده‌تر، ایده‌ی اصلی این تکنیک است. چندین تابع دیگر را با یک مثال معرفی می‌کنیم که می‌توان از آن‌ها برای ساختن رمزگشاهای داده‌ی واقعی و به‌طور دلخواه پیچیده استفاده کرد.

## GeoJSON

برای تمرین ترکیب رمزگشاهای پایه جهت تجزیه‌ی داده‌های پیچیده‌ی JSON، بیایید رمزگشاهایی برای تجزیه‌ی (زیرمجموعه‌ای از) داده‌های GeoJSON بسازیم. [GeoJSON][geojson] یک قالب داده‌ی تخصصی مبتنی بر JSON است که برای نمایش عوارض جغرافیایی، مانند مکان‌ها، مسیرها یا مناطق، استفاده می‌شود و با مختصات جغرافیایی دوبعدی یا سه‌بعدی، همراه با سایر ویژگی‌ها، مشخص می‌شود.

### شیء هندسی

یک شیء هندسی GeoJSON شیئی است که یک فیلد `type` با مقدار رشته‌ای دارد (۷ مقدار ممکن برای نوع وجود دارد) و یک فیلد `coordinates` با مختصات جغرافیایی (گردآوری‌شده در ساختاری که به نوع بستگی دارد). برای مثال،

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

یا

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

یک شیء هندسی را می‌توان در Elm با نوع زیر نمایش داد

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

برای بررسی مقدار یک فیلد مشخص، می‌توانیم از `Decode.field : String -> Decoder a -> Decoder a` استفاده کنیم که مقدار یک کلید مشخص از یک شیء را رمزگشایی می‌کند.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

برای تبدیل مقداری که با موفقیت توسط یک رمزگشا تجزیه شده است، می‌توانیم از `Decode.map : (a -> value) -> Decoder a -> Decoder value` یا هر یک از هم‌خانواده‌هایش استفاده کنیم، از `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` تا `Decode.map8`.

در این حالت، می‌خواهیم بسته به مقدار فیلد `type` تصمیم بگیریم کدام رمزگشای مختصات را استفاده کنیم، که کاری ایده‌آل برای `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` و دوستانش `Decode.succeed : a -> Decoder a` و `Decode.fail : String -> Decoder a` است.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

توجه کنید که در این مرحله می‌توانستیم از `Decode.andThen` برای اعتبارسنجی مختصات استفاده کنیم (بررسی کنیم که مختصات به‌صورت جفت یا سه‌تایی می‌آیند و بررسی کنیم که مقادیر مختصات از نظر جغرافیایی معنا دارند).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### شیء عارضه

یک شیء عارضه‌ی GeoJSON نماینده‌ی عارضه‌ای است که مرز فضایی دارد: یک فیلد `type` با مقدار `"Feature"` دارد، یک فیلد `geometry` با یک شیء هندسی یا `null`، یک فیلد `properties` با یک شیء JSON دلخواه یا `null` و یک فیلد اختیاری `id` با یک مقدار رشته‌ای یا عددی JSON.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

یا

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

بیایید ابتدا به سراغ فیلد `id` برویم. اگر وجود داشته باشد، باید رشته‌ها یا اعداد را بپذیرد، بنابراین می‌توانیم یا یک نوع سفارشی برای مقدار معرفی کنیم، یا همیشه آن را به‌صورت رشته ذخیره کنیم.

برای انتخاب بین دو رمزگشای ممکن، می‌توانیم از `Decode.oneOf : List (Decoder a) -> Decoder a` استفاده کنیم.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

برای بیان اینکه فیلد اختیاری است، می‌توانستیم از همان تکنیک استفاده کنیم

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

اما در عوض می‌توانستیم از `Decode.maybe : Decoder a -> Decoder (Maybe a)` استفاده کنیم

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

توجه کنید که `decodeMaybeFeatureId` (یا هر رمزگشا که با `Decode.maybe` بسته‌بندی‌شده است) همیشه موفق می‌شود، چون همیشه می‌تواند به `Ok Nothing` به‌عنوان جایگزین تکیه کند، هرچند یک رمزگشا که از آن استفاده می‌کند ممکن است همچنان شکست بخورد

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

در ادامه، بیایید روی فیلد `geometry` تمرکز کنیم، که می‌تواند یا یک شیء هندسی باشد یا `null`. می‌توانستیم دوباره از `Decode.oneOf` استفاده کنیم، اما گزینه‌ی بهتری وجود دارد: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` و `Decode.nullable` امضای یکسانی دارند، اما رفتارشان متفاوت است، چون نتیجه‌ی `OK Nothing` در `Decode.nullable` فقط از مقدار مشخص `null` در JSON می‌آید.

در نهایت، فیلد `properties` می‌تواند یک شیء JSON دلخواه یا `null` داشته باشد، که کار `Decode.value : Decoder Value` است.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

توجه کنید که `Value` یک نوع مات است، یعنی نمی‌توانید به‌راحتی محتوای آن را بررسی کنید. برای استفاده از آن، می‌توانید یا یک رمزگشا برایش بنویسید و آن را با `Decode.decodeValue : Decoder a -> Value -> Result Error a` اجرا کنید، یا آن را مستقیماً از طریق یک `port` به JavaScript بفرستید.

حالا آماده‌ایم شیءهای عارضه را تجزیه کنیم:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## رمزگذارهای JSON

«رمزگذارها» اجازه می‌دهند با استفاده از تابع `Encode.encode : Int -> Value -> String` از مقادیر Elm، JSON معتبر بنویسید. آرگومان اول مقدار تورفتگی در نتیجه‌ی نهایی را مشخص می‌کند و آرگومان دوم مقدار JSON برای نوشتن است.

یک `Value` را می‌توان یا از `Decode.value` به دست آورد یا از یکی از رمزگذارها تولید کرد:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

و همچنین با `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

بیایید رمزگذارهایی برای رمزگشاهای GeoJSON که پیش‌تر تعریف شدند تعریف کنیم

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

به‌طور کلی، آزمون خوبی برای جفت‌های رمزگشا-رمزگذار شما این است که بررسی کنید `elmValue |> encoder |> decoder == elmValue` برقرار است.

## دیگر چه؟

هر تک‌تابع در ماژول‌های `Json` را پوشش ندادیم. برخی از مواردی که ذکر نشدند عبارت‌اند از: رمزگشاهایی برای تبدیل آرایه‌ها به `Array` یا شیءها به `List (String, a)`، رمزگشاهایی برای آرایه‌های دارای یک یا چند عنصر، رمزگشاهایی برای فیلدهای مشخص در شیءهای تودرتوی JSON یا عناصر مشخص در آرایه‌ها، چگونگی رمزگشایی ساختارهای بازگشتی و همچنین گونه‌های مختلف `Error` و چگونگی نمایش آن‌ها.

بسته‌های پرکاربرد دیگر شامل [`Json.Decode.Pipeline`][pipeline] است که جریان راحتی برای ساختار JSON پیچیده معرفی می‌کند و [`Json.Decode.Extra`][extra] که رمزگشاها، رمزگذارها و توابع کمکی بیشتری فراهم می‌کند.
