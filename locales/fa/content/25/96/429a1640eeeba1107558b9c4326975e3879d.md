# درباره

وقتی یک تابع، تابع دیگری (یا کلوژر) را به عنوان پارامتر می‌پذیرد، به آن کلوژر ارسال‌شده به‌طور پیش‌فرض *غیرفرارکننده* می‌گویند.
می‌گویند یک کلوژر از یک تابع *فرار می‌کند* وقتی که پس از بازگشت خودِ تابع فراخوانی شود.

این وضعیت معمولاً زمانی پیش می‌آید که:

- یک کلوژر در متغیر یا ویژگی بیرونی ذخیره شود.
- یک کلوژر پس از کامل شدن یک عملیات، به‌صورت ناهمگام اجرا شود.
- یک کلوژر از تابع بازگردانده شود تا بعداً فراخوانی شود.

مثال زیر را در نظر بگیرید:

```swift
func emptyKitchen(_ order: String) -> String {
    "Sorry, we're all out of \(order)."
}

func prepare(order: String, kitchen: (String) -> String) -> (String) -> String {
    func newKitchen(_ newOrder: String) -> String {
        if newOrder == order {
            return "One \(order) coming up!"
        } else {
            return kitchen(newOrder)
        }
    }
    return newKitchen
}
```

در این کد، `prepare` تابعی به اسم `kitchen` را می‌پذیرد، تابع تازه‌ای به اسم `newKitchen` می‌سازد که `kitchen` را فراخوانی می‌کند و `newKitchen` را بازمی‌گرداند.
تلاش برای کامپایل این کد خطایی تولید می‌کند: `Escaping local function captures non-escaping parameter 'kitchen'`.

چون عمر `newKitchen` از `prepare` طولانی‌تر است، کلوژر `kitchen` فرار می‌کند.
برای اینکه این ممکن شود، نوع پارامتر را با صفت `@escaping` مشخص کنید.

```swift
func prepare(order: String, kitchen: @escaping (String) -> String) -> (String) -> String {
    func newKitchen(_ newOrder: String) -> String {
        if newOrder == order {
            return "One \(order) coming up!"
        } else {
            return kitchen(newOrder)
        }
    }
    return newKitchen
}

let restaurant = prepare(
    order: "sandwich",
    kitchen: prepare(
        order: "chicken",
        kitchen: prepare(order: "steak", kitchen: emptyKitchen)
    )
)

print(restaurant("pork chop"))
// Prints "Sorry, we're all out of pork chop."

print(restaurant("chicken"))
// Prints "One chicken coming up!"
```

صفت `@escaping` به کامپایلر Swift اطلاع می‌دهد که کلوژر عمری طولانی‌تر از فراخوانی بی‌واسطه‌ی تابع خواهد داشت و به این ترتیب Swift می‌تواند حافظه و ارجاع‌های ضبط‌شده را به‌درستی مدیریت کند.

[escaping]: https://docs.swift.org/swift-book/LanguageGuide/Closures.html#ID546
