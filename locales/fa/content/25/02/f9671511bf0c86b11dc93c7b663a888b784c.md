# مقدمه

در بسیاری از زبان‌های شیءگرا، رایج است که رفتارها را با [زیرکلاس‌سازی][wiki-subclass] از یک کلاس والد گسترش می‌دهند؛ به این صورت که متدها را از والد به ارث می‌برند و در همان حال متدهای تازه‌ای هم اضافه می‌کنند.
به این ترتیب یک سلسله‌مراتب شیء به دست می‌آید.

Julia _کلاس ندارد_، و در نتیجه _زیرکلاس هم ندارد_.
پس چطور رفتارهای موجود را به ارث می‌بریم و گسترش می‌دهیم؟

در مفاهیم پیشین دیدیم که چطور یک سلسله‌مراتب نوع بسازیم، و همچنین یاد گرفتیم Julia چطور از [چندگسیل][concept-multiple-dispatch] استفاده می‌کند تا متدها را بر اساس نوع آرگومان‌ها انتخاب کند.

Julia چند «رابط» غیررسمی هم دارد که به انواع سفارشی شما اجازه می‌دهند به رفتارهایی که از قبل برای انواع استاندارد تعریف شده‌اند وصل شوند.

این موضوع را به‌سادگی می‌توان با رابط «تکرارگر» نشان داد.

## تکرارگرها

پیش‌تر در برنامه‌ی درسی، چند روش دیده‌ایم که Julia با آن‌ها می‌تواند روی هر عنصر یک مجموعه عمل کند.

- [حلقه][concept-loops]، مانند `for item in items...`
- [پخش][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [توابع مرتبه‌بالا][concept-hof]: `map(√, [1, 4, 9])`
- [درک][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [مولد][concept-comprehensions]: `(x^2 for x in 1:1e6)`، که به‌صورت تنبل ارزیابی می‌شود.

واضح است که Julia می‌داند چطور روی مجموعه‌های استاندارد، عنصر به عنصر گام بردارد: بردارها و بازه‌ها در مثال‌های بالا، و همچنین `Set`ها، `Dict`ها و غیره.

چطور این قابلیت را به مجموعه‌های سفارشی خودمان اضافه کنیم، به‌ویژه اگر بتوان آن‌ها را مانند یک مولد به‌صورت تنبل تکرار کرد؟

### حداقل نیازها

برای ساختن یک دنباله برای تکرار، به (حداقل) دو مورد نیاز داریم:

1. راهی برای گرفتن _نخستین_ عنصر.
2. راهی برای گرفتن _عنصر بعدی_ از وضعیت کنونی.

Julia این کارها را با متدهایی از تابع `Base.iterate()` و با این گام‌ها انجام می‌دهد:

1. نخست `Base.iterate(iter)` به‌طور خودکار فراخوانی می‌شود.
    - اگر چیزی برای تکرار نباشد، `nothing` برمی‌گرداند.
    - در غیر این صورت، یک `Tuple` برمی‌گرداند که شامل نخستین عنصر برگشتی و نخستین وضعیت است: `(firstitem, firststate)`.
2. اگر در تکرار پیشین عنصری برگردانده شده باشد، `Base.iterate(iter, state)` به‌طور خودکار فراخوانی می‌شود و `firststate` را به عنوان آرگومان `state` خود می‌گیرد.
    - اگر تکرار پایان یابد، `nothing` برمی‌گرداند.
    - در غیر این صورت، یک `Tuple` برمی‌گرداند که شامل عنصر بعدی و وضعیت بعدی است: `(nextitem, nextstate)`.
3. گام ۲ را تا پایان تکرار می‌کند.

همه‌ی این گام‌ها «در پشت صحنه» انجام می‌شوند؛ یعنی فراخوانی متدها و وضعیت، به‌صورت درونی توسط پروتکل تکرار مدیریت می‌شوند (و وضعیت مبهم و پوشیده می‌ماند) و تنها عنصر در معرض ساختارهای سطح بالا، مانند حلقه‌ها، قرار می‌گیرد.
به عبارت دیگر، ما فقط `item` را می‌بینیم و بقیه در یک جعبه‌ی سیاه پنهان می‌ماند.

[چندگسیل][concept-multiple-dispatch] در اینجا نقش محوری دارد.
نوع `iter` تعیین می‌کند کدام متدها فراخوانی می‌شوند و تعداد آرگومان‌ها تعیین می‌کند که نخستین عنصر برگردانده شود یا عنصر بعدی.

متدهای انواع استاندارد از قبل تعریف شده‌اند: `Vector`، `Range`، `Set` و غیره ([در حال حاضر][ref-iterations-collections] در مجموع ۱۴ نوع).

برای اینکه یک `MyType` سفارشی همین رفتارها را داشته باشد، نخست باید این‌ها را تعریف کنیم:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

همه‌ی این‌ها در حالت انتزاعی احتمالاً گیج‌کننده به نظر می‌رسد، اما می‌تواند بسیار ساده باشد.
برای نمونه، فرض کنید می‌خواهیم نوعی داشته باشیم که توان‌های یک عدد صحیح مشخص `n` را تا یک شمار بیشینه بدهد.

نخست، یک نوع سفارشی تعریف کنید:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

اکنون می‌توانیم متدهای `iterate` را برای این نوع تعریف کنیم، اما نخستین عنصر و نخستین وضعیت کدام‌اند؟

برای گرفتن نخستین عنصر، بعضی تکرارگرها به آماده‌سازی پیچیده‌ای نیاز دارند، اما در این مثال ساده می‌بینیم که نخستین عنصر برگشتی همان عدد پایه است، پس فقط باید بررسی کنیم که مقدار `count` بزرگ‌تر یا مساوی یک باشد.

حالا می‌توانیم نخستین وضعیت را در نظر بگیریم؛ وضعیتی که اطلاعاتی را حمل می‌کند که در تکرار بعدی استفاده می‌شود.
خودتان تصمیم می‌گیرید که برای این کار به نگهداری چه اطلاعاتی نیاز دارید، و این اطلاعات می‌تواند از هر نوعی باشد.

در این مورد، می‌توانیم فقط «اندیس»ی را نگه داریم که `n` به توان آن می‌رسد، یا می‌توانیم گزینه‌ی کارآمدتری پیدا کنیم: با استفاده از تازه‌ترین توان `n` (یعنی همان عنصر برگشتی) و «اندیس» بعدی در دنباله.
این دو عدد را می‌توان در یک `Tuple` بسته‌بندی کرد و به عنوان `state` برگرداند.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

در این مثال، نخستین عنصر (`p.n`) به حلقه برگردانده می‌شود و نخستین وضعیت `(p.n, 2)` به متد `iterate(P::Powers, state)` پاس داده می‌شود.
آنجا می‌توانیم وضعیت را پردازش کنیم تا با ضرب عنصر کنونی در عدد پایه، عنصر بعدی را تولید کنیم و به این ترتیب توان آن را `1` واحد افزایش دهیم.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

اگر مقدار اندیس هنوز در محدوده‌ی `count` باشد، `Tuple`ی برگردانده می‌شود که شامل عنصر `next` و `Tuple` وضعیت افزایش‌یافته است.
وقتی مقدار `index` از `count` بیشتر شود، به جای آن `nothing` برگردانده می‌شود تا نشان دهد تکرار پایان یافته است.

شاید متوجه شده باشید که بدنه‌ی توابع متدهای `iterate(p::Powers)` و `iterate(p::Powers, state)` نسبتاً شبیه هم است.
در واقع، اگر زیرک باشیم، این شباهت به ما اجازه می‌دهد پیاده‌سازی را با استفاده از تنها نسخه‌ی دوآرگومانی و یک آرگومان پیش‌فرض برای وضعیت، ساده و یکدست کنیم: `Base.iterate(p::Powers, state=(1, 1))`
با آن، دیگر به متد جداگانه‌ی تک‌آرگومانی `iterate(p::Powers)` نیازی نداشتیم.
وقتی امکان‌پذیر باشد، در عمل معمولاً همین کار انجام می‌شود.

تا اینجا، از قبل چند قابلیت مفید داریم: برای ۴ توان نخست ۳، می‌توانیم روی نتایج حلقه بزنیم، بررسی کنیم که عددی مشخص در نتایج هست یا نه، و توابع تجمیعی مانند `sum()` را اعمال کنیم.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### متدهای بیشتر

با وجود این شروع خوب، هنوز همه چیز کار نمی‌کند.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

و همان‌طور که انتظار می‌رود، `length(Powers(3, 4))` دقیقاً همان پیام خطا را می‌دهد.

این را به‌راحتی می‌توان درست کرد، چون طول بخشی از سازنده‌ی نوع است: در این مورد ۴.
فقط باید `Base.length()` را برای این نوع تعریف کنیم، و سپس می‌توانیم از درک‌ها و `collect()` روی دنباله استفاده کنیم.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

برای کارآمدی، بهتر است `Base.eltype()` را هم تعریف کنیم: نوع عنصر نتیجه.
این کار به توابعی مانند `collect()` اجازه می‌دهد از پیش برای خروجی `Vector{Int}` فضا اختصاص دهند، به جای اینکه مکرراً روی یک `Vector{Any}` عمل `push!()` را انجام دهند.

به این نحوه‌ی نگارش توجه کنید که شاید پیش‌تر ندیده‌اید: این متد روی _نوع_ تعریف می‌شود، نه روی یک _نمونه_ از نوع.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

هیچ _الزامی_ نیست که تکرارگرها طول متناهی داشته باشند.
استفاده از دنباله‌های «نامتناهی» محدودتر است، اما تا زمانی که راهی برای `break` کردن از حلقه وجود داشته باشد، حلقه زدن روی آن‌ها می‌تواند مفید باشد.
برای نمونه، می‌توانیم گونه‌ای از `Powers` تعریف کنیم که مقادیری کوچک‌تر از یک حد مشخص تولید کند (شاید `typemax(Int)`، تا از سرریز عدد صحیح جلوگیری شود).

## خلاصه

توضیح رابط‌ها نسبتاً گیج‌کننده است، چون رویکرد Julia با بیشتر زبان‌های دیگر بسیار متفاوت است.
به‌ویژه، ممکن است نام رابط هرگز در پیاده‌سازی ذکر نشود: برخلاف [زیرکلاس‌سازی][wiki-subclass] یا [میکسین][wiki-mixins].

با این حال، در عمل به‌طرز غافلگیرکننده‌ای ساده‌اند:

1. یک نوع مناسب تعریف کنید.
2. پیدا کنید کدام متدها لازم هستند.
3. آن متدها را برای نوع سفارشی خود پیاده‌سازی کنید؛ معمولاً فقط چند متد، و بسیار کوتاه و ساده.
4. بگذارید [چندگسیل][concept-multiple-dispatch] به‌طور خودکار بقیه‌ی کار را انجام دهد.
