# مقدمه

## ارجاع‌های تهی

اگر تا به حال از زبان برنامه‌نویسی دیگری استفاده کرده باشید (C/C++، Python، Java، Ruby، Lisp و غیره)، احتمالاً پیش‌تر با `null` یا `nil` روبه‌رو شده‌اید.
این زبان‌ها با استفاده از `null` یا `nil` نشان می‌دهند که یک متغیر خاص مقداری ندارد.
اما همین باعث می‌شود که استفاده‌ی تصادفی از یک متغیر `null` به اشتباهی ساده (و پرتکرار) تبدیل شود.
همان‌طور که ممکن است تصور کنید، تلاش برای فراخوانی تابعی که وجود ندارد یا دسترسی به مقداری که وجود ندارد، می‌تواند به انواع و اقسام bug و از کار افتادن برنامه منجر شود.
خالق `null` تا آنجا پیش رفت که آن را [«اشتباه میلیارد دلاری»][billion-dollar-mistake] خود نامید.

[billion-dollar-mistake]: https://www.infoq.com/presentations/Null-References-The-Billion-Dollar-Mistake-Tony-Hoare/

## نوع `Option`

برای پرهیز از این مشکلات، متغیرهای Cairo می‌توانند از `enum` `Option` استفاده کنند تا نبود یک مقدار را به‌شکل ایمن نمایش دهند.
این `enum` دو حالت دارد: `None`، معادل تهی در Cairo؛ و `Some(T)` که در آن `T` مقداری از هر نوعی است.

ظاهر آن چنین است:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

می‌توانید `Option` را لایه‌ای از ایمنی میان خودتان و مشکلاتی در نظر بگیرید که ارجاع‌های تهی می‌توانند پدید آورند، در حالی که هنوز سودمندی مفهومی آن‌ها حفظ می‌شود.

## استفاده از `Option`

تنظیم یک متغیر روی `None` نسبتاً سرراست است:

```rust
let nothing: Option<u32> = Option::None;  // Variable nothing is set to None
```

اما اگر می‌خواهید نوع `Option` مقداری را در خود نگه دارد، نمی‌توانید آن مقدار را مستقیم انتساب دهید.
یک متغیر از نوع `Option` و مثلاً یک متغیر از نوع `i32` با هم معادل نیستند.
باید از `Some` استفاده کنید:

```rust
let wrong_way: Option<i32> = -4; // This will not work

let right_way: Option<i32> = Option::Some(-4); // This will work
let another_right_way = Option::Some(-4); // Compiler infers that this is Option<i32>
```

به همین دلیل مورد زیر هم کار نخواهد کرد:

```rust
let number = 47;
let option_number = Option::Some(15);

let compile_error = number + option_number; // Cannot add an i32 and an Option<i32> - they are of different types
```

برای به دست آوردن مقداری که در `Some` قرار دارد، ابتدا باید بررسی کنید که آن مقدار وجود دارد:

```rust
let mut some_words = Option::Some("choose something to say"); // some_words set to something

match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "Here, we will choose something to say"

some_words = Option::None; // some_words now set to None

// Exactly the same match block as above
match some_words {
    Option::Some(str) => println!("Here, we will {}", str),
    Option::None => println!("I've got nothing to say"),
} // Prints, "I've got nothing to say"
```

Cairo برای بررسی و دسترسی به مقادیر موجود در `Option` ابزارهای دیگری جز `match` هم در اختیار دارد، اما `match` تا الان باید برایتان آشنا شده باشد.

این را نمایشی از این بدانید که چرا Cairo به‌جای ارجاع تهی از `Option` استفاده می‌کند.
نکته این است که **باید _حتماً_ بررسی کنید** که متغیر `Option` برابر با `Some` است (که در آن صورت می‌توانید جلو بروید و مقدار درونش را استخراج و استفاده کنید) یا `None`.
در غیر این صورت برنامه‌تان کامپایل نمی‌شود؛ کامپایلر شما را از `null` در امان نگه می‌دارد.
