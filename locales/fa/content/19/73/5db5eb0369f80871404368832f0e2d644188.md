# درباره

تا این نقطه از برنامه‌ی درسی، تا حالا تعریف‌های زیادی از تابع دیده‌اید.
معمولاً این‌ها بدون توضیح زیادی درباره‌ی خروجی در REPL ارائه شده‌اند:

```julia-repl
julia> f(x) = x^2
f (generic function with 1 method)
```

چرا _"generic function with 1 method"_؟

فرض کنید می‌خواهیم درباره‌ی نوع آرگومان‌ها دقیق‌تر باشیم.

```julia-repl
julia> f(x::Integer) = x^2
f (generic function with 2 methods)

julia> f(x::Real) = x^2
f (generic function with 3 methods)
```

یا می‌توانستیم تعداد آرگومان‌ها را عوض کنیم:

```julia-repl
julia> f(x, y) = x * y
f (generic function with 4 methods)
```

به نظر می‌رسد تعریف‌های تازه‌ی یک تابع را «متد» می‌نامند.
متدها به یک فهرست اضافه می‌شوند، نه اینکه تعریف قبلی را بازنویسی کنند.

به‌راحتی می‌توانیم متدها را فهرست کنیم:

```julia-repl
julia> methods(f)  # output edited for brevity
# 4 methods for generic function "f" from Main:
 [1] f(x, y)
 [2] f(x::Integer)
 [3] f(x::Real)
 [4] f(x)
 ```

اگر تابع `f` را فراخوانی کنیم، Julia به‌نحوی می‌داند که کدام متد را به کار ببرد:

```julia-repl
julia> f(2.5)  # Float64
6.25

julia> f(2)  # Int64
4

julia> f(2, 3)  # Int64, Int64
6
```

## تابع چیست؟

بر اساس [راهنمای رسمی][function]، تابع شیئی است که یک تاپل از آرگومان‌ها را به یک مقدار بازگشتی نگاشت می‌کند.
این تعریف به تعریفی که ریاضی‌دان‌ها به کار می‌برند نزدیک است.

ما معمولاً آرگومان‌های تابع در `f(2, 3)` را دو عنصر جداگانه در نظر می‌گیریم، اما کامپایلر آن‌ها را یک [تاپل][tuple] می‌بیند.
این حتی برای یک آرگومان هم درست است (هرچند برای روشن‌تر شدنش باید یک ویرگول اضافه کنیم):

```julia-repl
julia> typeof( (2, 3) )
Tuple{Int64, Int64}

julia> typeof( (2,) )
Tuple{Int64}
```

اگر تابع را مثل یک جعبه‌ی سیاه در نظر بگیریم، می‌توان گفت یک تاپل وارد می‌شود و یک مقدار بازگشتی بیرون می‌آید.
به شکل رسمی‌تر، تاپل به یک مقدار بازگشتی _نگاشت_ می‌شود.

## توابع چگونه تعداد و نوع‌های متفاوت آرگومان‌ها را مدیریت می‌کنند؟

معمولاً به این [«چندریختی»][polymorphism] می‌گویند.

این موضوع چند دهه است که یکی از مباحث مهم علوم کامپیوتر بوده و رویکردهای مختلفی برایش در پیش گرفته شده است.

رویکرد Julia غیرمعمول است، هرچند بی‌نظیر نیست.

- توابع [«جنریک»][generic] هستند، یعنی می‌توان چندین متد به آن‌ها متصل کرد.
- توابع فقط یک اسم‌اند تا زمانی که متدهایی به آن‌ها متصل شود.
- متدها هر وقت لازم شود اضافه می‌شوند و می‌توانند تعدادشان زیاد باشد (عملگر `+` در حال حاضر تابعی با ۱۶۱ متد است).
- وقتی تابعی فراخوانی می‌شود، Julia امضای فراخوانی را بررسی می‌کند: تعداد آرگومان‌ها و نوع فعلی هرکدام.
- متدی که بیشترین تطابق را با امضای فراخوانی دارد انتخاب می‌شود.
  - به‌طور کلی، تعداد آرگومان‌ها باید دقیقاً یکی باشد (هرچند عملگر [splat/slurp][splat] `...` تا حدی می‌تواند از این قانون بگذرد).
  - متدهایی که نوع‌هایشان دقیقاً با امضای فراخوانی می‌خواند ترجیح داده می‌شوند.
  - در صورت لزوم، Julia برای یافتن نزدیک‌ترین و خاص‌ترین متد، اَبَرنوع‌های هر آرگومان در امضای فراخوانی را بررسی می‌کند.
- متد انتخاب‌شده با آرگومان‌های داده‌شده [`dispatched`][dispatch] می‌شود و نتیجه‌ای برمی‌گرداند.
- اگر متد مناسبی پیدا نشود، یک [`MethodError`][methoderror] ایجاد می‌شود.

توجه کنید که Julia به‌صورت پویا نوع‌دار است، پس دیسپچ متد در _زمان اجرا_ رخ می‌دهد.

## دیسپچ چندگانه: یک مثال

بخش قبلی خیلی حرف داشت، پس بیایید این ایده‌ها را به کد تبدیل کنیم.
برای سادگی، توابع زیر فقط یک آرگومان دارند، اما پیدا کردن توابعی با ده‌ها آرگومان غیرعادی نیست (مثلاً در بسته‌های ترسیم نمودار یا یادگیری ماشین).

با تعریف چند نوع سفارشی برای نمایش شکل‌های هندسی شروع کنید.

```julia-repl
julia> abstract type Shape end

julia> struct Circle <: Shape
           radius::Float64
       end

julia> struct Square <: Shape
           side::Float64
       end

julia> struct Rectangle <: Shape
           length::Float64
           width::Float64
       end
```

در ادامه می‌توانیم متدهایی برای محاسبه‌ی مساحت هر شکل تعریف کنیم.
هرکدام یک آرگومان می‌گیرد که در هر مورد از نوع مشخص و کاربرساخته‌ی متفاوتی است.

```julia-repl
julia> area(c::Circle) = π * c.radius^2
area (generic function with 1 method)

julia> area(s::Square) = s.side^2
area (generic function with 2 methods)

julia> area(r::Rectangle) = r.length * r.width
area (generic function with 3 methods)
```

حالا می‌توانیم چند شکل بسازیم و مساحت‌ها را حساب کنیم، با تکیه بر سازوکار دیسپچ Julia تا فرمول درست برای هرکدام به کار برود.

```julia-repl
julia> circle = Circle(2.3)
Circle(2.3)

julia> area(circle)  # call signature Tuple{Circle}
16.619025137490002

julia> square = Square(1.6)
Square(1.6)

julia> area(square)  # call signature Tuple{Square}
2.5600000000000005

julia> rectangle = Rectangle(1.4, 2.1)
Rectangle(1.4, 2.1)

julia> area(rectangle)  # call signature Tuple{Rectangle}
2.94
```

## [متدهای پارامتری][parametric]

امضاهای متد می‌توانند مقادیر نوع ساختگی بگیرند، تقریباً به همان شکلی که نوع‌های پارامتری این کار را می‌کنند.

نحوه‌ی نگارش آن متمایز است و به یک بند `where` نیاز دارد:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T} = true
same_type (generic function with 1 method)

julia> same_type([1, 2], 3)
true

julia> same_type([1, 2], "three")
ERROR: MethodError: no method matching same_type(::Vector{Int64}, ::String)
```

مثال بالا می‌خواهد هر دو آرگومان از یک نوع `T` باشند، هرچه که آن نوع باشد.

می‌توانیم با گذاشتن یک محدودیت روی `T` دقیق‌تر عمل کنیم:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T<:Number} = true
same_type (generic function with 2 methods)
```

با این متد، فقط نوع‌های عددی یکسان `true` برمی‌گردانند.

چند متغیر ساختگی هم ممکن است، که با ویرگول در بند `where` از هم جدا می‌شوند.
دو متد زیر شبیه هم به نظر می‌رسند:

```julia-repl
julia> func(v::Vector{Number}, x::Number) = true
func (generic function with 1 method)

julia> func(v::Vector{S}, x::T) where {S<:Number, T<:Number} = true
func (generic function with 2 methods)
```

یک تفاوت این است که در بدنه‌ی تابعِ متد دوم می‌توان از مقادیر نوع `S` و `T` استفاده کرد.
این نوعی ترفند است که شاید زیاد از آن استفاده نکنید، اما در بعضی موقعیت‌ها می‌تواند دردسر زیادی را کم کند.

برای مثال، در تعریف نوع پارامتری زیر، فیلدها باید از همان نوع `T` باشند، که محدود شده است تا زیرنوعی از `Real` باشد:
```julia
struct Point{T<:Real}
    x::T
    y::T
end
```
این تعریف `Point` یک `x` و یک `y` هم‌نوع می‌پذیرد، یا می‌تواند `x` و `y` با نوع‌های متفاوت را بپذیرد، اما در آن صورت باید نوع تبدیل صریح را مشخص کنید.
```julia-repl
julia> Point(4, 5)
 Point{Int64}(4, 5)

julia> Point(3.5, 2)
 MethodError: no method matching Point(::Float64, ::Int64)    # Output truncated for brevity

julia> Point{Float32}(3.5, 2)
 Point{Float32}(3.5f0, 2.0f0)

julia> Point{Int64}(3.5, 2) 
 InexactError: Int64(3.5)      # Output truncated for brevity
```
هرچند این سطح از کنترل روی نوع‌ها ممکن است مطلوب باشد، کمی انتزاع هم می‌تواند مفید باشد.
```julia
Point(x::T, y::S) where {T<:Real, S<:Real} = Point{promote_type(T,  S)}(x, y)
```
این سازنده‌ی بیرونی همین را ممکن می‌کند: به `Point` اجازه می‌دهد `x` و `y` با نوع‌های ناهمگون بپذیرد، بدون آنکه نوع تبدیل را صریحاً مشخص کنید.
مقادیر نوع `T` و `S` در بدنه‌ی تابع و در `promote_type(T, S)` به کار می‌روند تا نوع تبدیل صریح را برای تعریف اصلی فراهم کنند.
```julia-repl
julia> Point(3.5, 2)
 Point{Float64}(3.5, 2.0)
```

## مقایسه با زبان‌های دیگر

چون Julia هنگام انتخاب متد همه‌ی آرگومان‌ها را بررسی می‌کند، به این کار [`multiple dispatch`][multiple-dispatch] می‌گویند.

چند زبان دیگر هم دیسپچ چندگانه را دارند، مثل Common Lisp، هرچند به‌ندرت مثل Julia این‌قدر در طراحی زبان محور است.

در مقابل، در یک زبان شیءگرا (مثل Ruby)، متدها معمولاً روی یک [نمونه][instance] فراخوانی می‌شوند.
در تعریف، حالا آرگومان اول جایگاه ویژه‌ای دارد (با اسمی مثل `self` یا `this` در تعریف)، و برای فراخوانی متد، اسم آن با نقطه به نمونه متصل می‌شود:

```ruby
irb(main):004:0> "abc".sub("b", "*")
=> "a*c"
```

به این [`single dispatch`][single-dispatch] می‌گویند، چون فقط کلاس نمونه (رشته‌ی «abc» در مثال بالا) برای انتخاب متد استفاده می‌شود.

بعضی زبان‌های شیءگرای ایستا-نوع از چندریختی متد پشتیبانی می‌کنند که تا حدی شبیه دیسپچ چندگانه به نظر می‌رسد.
تفاوت بزرگ این است که انتخاب متد فقط در _زمان کامپایل_ انجام می‌شود.

زبان‌های تابعی معمولاً فقط یک تعریف تابع دارند، همراه با نوعی عبارت Select/Case/Match برای رسیدگی به حالت‌های مختلف.
شما منطق خودتان را می‌نویسید، معمولاً به کمک نحوه‌ی نگارش خلاصه‌ی تطبیق الگو که در Julia وجود ندارد.
البته Julia هم نوعی تطبیق الگو انجام می‌دهد، اما در زمان دیسپچ، نه درون بدنه‌ی تابع.

## نتیجه‌گیری

دیسپچ چندگانه در Julia بسیار انعطاف‌پذیر و بسیار کاراست و به همین دلیل بسیار گسترده استفاده می‌شود.

همان‌طور که مثال ۱۶۱ متد برای `+` نشان می‌دهد، برنامه‌نویسان Julia می‌کوشند متدهایی با نوع‌های باریک و دقیق تعریف کنند.
جمع دو عدد صحیح در سطح بایت‌کد با جمع دو عدد اعشاری بسیار متفاوت است، و جمع یک عدد صحیح با یک عدد اعشاری، پیچیدگی اضافه‌ی ارتقای نوع را هم به همراه دارد.

هرچه نوع خاص‌تر باشد، کامپایلر می‌تواند بهینه‌سازی بیشتری انجام دهد: در یک تمرین ساده در Exercism اهمیت حاشیه‌ای دارد، اما برای کارایی در شبیه‌سازی‌های عددی بزرگی که Julia برای آن‌ها طراحی شده، حیاتی است.

_اگر می‌دانید یک متد چه ورودی‌هایی دریافت می‌کند، لطفاً به کامپایلر بگویید!_
