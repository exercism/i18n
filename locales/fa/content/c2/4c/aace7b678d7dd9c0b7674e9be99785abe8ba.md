# مقدمه

Elixir زبانی با نوع‌دهی پویا است، یعنی بررسی نوع در زمان کامپایل انجام نمی‌دهد. با این حال، می‌توان از مشخصات نوع به عنوان نوعی مستندسازی استفاده کرد.

می‌توان با استفاده از ویژگی ماژول `@spec`، بلافاصله پیش از تعریف تابع، مشخصات نوع را به تابع افزود. پس از `@spec`، اسم تابع و فهرستی از نوع همه‌ی آرگومان‌های آن، داخل پرانتز و جداشده با ویرگول، می‌آید. نوع مقدار بازگشتی با دو دونقطه `::` از آرگومان‌های تابع جدا می‌شود.

```elixir
@spec longer_than?(String.t(), non_neg_integer()) :: boolean()
def longer_than?(string, length), do: String.length(string) > length
```

## انواع

از پرکاربردترین انواع می‌توان به این‌ها اشاره کرد:

- مقادیر منطقی: `boolean()`
- رشته‌ها: `String.t()`
- اعداد: `integer()`، `non_neg_integer()`، `pos_integer()`، `float()`
- فهرست‌ها: `list()`
- مقداری از هر نوع: `any()`

برخی انواع را هم می‌توان پارامتردار کرد؛ برای مثال `list(integer)` فهرستی از اعداد صحیح است.

از مقادیر لیترال هم می‌توان به عنوان نوع استفاده کرد.

می‌توان اجتماع انواع را با خط عمودی `|` نوشت. برای مثال، `integer() | :error` یعنی یا یک عدد صحیح یا لیترال اتم `:error`.

فهرست کامل همه‌ی انواع را می‌توانید در [بخش «Typespecs» در مستندات رسمی][types] بیابید.

## نام‌گذاری آرگومان‌ها

آرگومان‌ها در مشخصات نوع می‌توانند اسم هم داشته باشند، که برای تشخیص چند آرگومان هم‌نوع مفید است. اسم آرگومان، به‌همراه دو دونقطه، پیش از نوع آن می‌آید.

```elixir
@spec to_hex({hue :: integer, saturation :: integer, lightness :: integer}) :: String.t()
```

## انواع سفارشی

مشخصات نوع تنها به انواع ازپیش‌تعریف‌شده محدود نمی‌شود. می‌توان انواع سفارشی را با ویژگی ماژول `@type` تعریف کرد. تعریف یک نوع سفارشی با اسم نوع شروع می‌شود، سپس دو دونقطه و بعد خود نوع می‌آید.

```elixir
@type color :: {hue :: integer, saturation :: integer, lightness :: integer}

@spec to_hex(color()) :: String.t()
```

از یک نوع سفارشی می‌توان در همان ماژولی که تعریف شده، یا در ماژول دیگری استفاده کرد.
