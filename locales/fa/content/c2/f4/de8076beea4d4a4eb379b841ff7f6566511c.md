# اعتبار

اعتبار سیستمی است که به افراد امکان می‌دهد در اکوسیستم Exercism «اعتماد» به دست آورند.

اعتبار معیاری است از اینکه یک فرد چقدر به Exercism کمک کرده است؛ هم با مشارکت در پلتفرم (مثلاً از طریق ساختن نرم‌افزار، تمرین و مستندات) و هم با مشارکت در جامعه (مثلاً مربی‌گری).

اعتبار را نمی‌توان «خرج کرد» یا «استفاده کرد». با این حال، رسیدن به آستانه‌های مشخصی از اعتبار، دسترسی به اختیارات تازه و راه‌های جدید مشارکت را ممکن می‌کند. به زبان ساده، هرچه اعتبار یک فرد بیشتر باشد، احساس می‌کنیم بیشتر می‌توانیم به او اعتماد کنیم و در نتیجه قدرت بیشتری به دست می‌آورد. اعتبار همچنین معیاری است که همه می‌توانند ببینند و نشان می‌دهد چقدر به Exercism کمک کرده‌اید.

## هدف

هدف سیستم اعتبار این است که:

1. تعامل‌های متمرکز بر رشد میان دانش‌آموزان و مربیان را بیشینه کند
2. تمایل مربیان به مشارکت را بیشینه کند

## به دست آوردن اعتبار

اعتبار را می‌توان به روش‌های گوناگونی به دست آورد:

| اقدام                            | اعتبار |
| --------------------------------- | ---------- |
| مربی‌گری موفق یک راه‌حل | ۵          |
| انتشار یک راه‌حل             | ۱-۳        |
| نوشتن یک تمرین               | ۲۰         |
| به‌روزرسانی یک تمرین              | ۱۰         |
| نوشتن یک مفهوم               | ۱۰         |
| به‌روزرسانی یک مفهوم              | ۵          |
| ساختن pull request           | ۳-۱۰۰      |
| بازبینی pull request          | ۱-۲۰       |
| ادغام pull request            | ۱-۵        |

### مربی‌گری موفق یک راه‌حل

برای هر راه‌حلی که با موفقیت مربی‌گری شده باشد (بحث به پایان رسیده باشد)، `5` اعتبار داده می‌شود.

### انتشار یک راه‌حل

برای هر راه‌حل منتشرشده، اعتبار بر اساس سختی تمرین داده می‌شود:

| برچسب    | اعتبار |
| -------- | ---------- |
| `easy`   | ۱          |
| `medium` | ۲          |
| `hard`   | ۳          |

### نوشتن یک تمرین

برای هر تمرینی که کاربر به‌عنوان نویسنده در آن فهرست شده باشد، `20` اعتبار داده می‌شود.

### به‌روزرسانی یک تمرین

برای هر تمرینی که کاربر به‌عنوان مشارکت‌کننده فهرست شده باشد، `10` اعتبار داده می‌شود.

### نوشتن یک مفهوم

برای هر مفهومی که کاربر به‌عنوان نویسنده فهرست شده باشد، `10` اعتبار داده می‌شود.

### به‌روزرسانی یک مفهوم

برای هر مفهومی که کاربر به‌عنوان مشارکت‌کننده فهرست شده باشد، `5` اعتبار داده می‌شود.

### ساختن pull request

به طور پیش‌فرض، وقتی pull requestی که کاربر باز کرده است ادغام شود، `12` اعتبار داده می‌شود.

بسته به محتوای pull request، یک نگهدارنده می‌تواند با افزودن یکی از برچسب‌های زیر به آن، اعتبار بیشتری (یا کمتری) بدهد:

| برچسب           | اعتبار | مثال‌ها                                                                                                                                                                                                                                                                                                                                                            |
| --------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x:rep/tiny`    | ۳          | <ul><li>اصلاح یک غلط املایی یا لینک</li><li>حذف یک خط خالی یا افزودن یک خط جدید</li><li>تغییر یا افزودن یک کامنت کد</li></ul>                                                                                                                                                                                                                   |
| `x:rep/small`   | ۵          | <ul><li>اصلاح یک تست، وظیفه یا مثال</li><li>اصلاح چند غلط املایی یا لینک در یک فایل</li><li>شفاف‌سازی محتوا با افزودن چند خط به یک فایل</li></ul>                                                                                                                                                                                     |
| `x:rep/medium`  | ۱۲         | <ul><li>همگام‌سازی یک تمرین با problem-specifications (شامل ویرایش‌ها)</li><li>افزودن یک یا چند تست از صفر</li><li>بهبود چند فایل در یک تمرین</li><li>افزودن یادداشت‌های مربی برای یک تمرین از صفر</li><li>رفع یک باگ کوچک در یک test runner/analyzer/representer</li><li>افزودن کامنت‌های analyzer برای یک تمرین</li></ul> |
| `x:rep/large`   | ۳۰         | <ul><li>افزودن یک تمرین مفهوم یا تمرین عملی جدید</li><li>افزودن مستندات مفهوم جدید</li><li>بازنویسی اساسی یک مفهوم یا تمرین موجود</li><li>افزودن اسکریپت‌های CI جدید یا خودکارسازی‌های دیگر</li></ul>                                                                                                                                            |
| `x:rep/massive` | ۱۰۰        | <ul><li>ساختن یک test-runner، analyzer، representer یا generator از صفر</li><li>بازآرایی اساسی آن ابزارها</li><li>ساختن مستندات اساسی از صفر (مثلاً راهنماهای مشارکت یا تست)</li></ul>                                                                                                                                            |

مثال‌های بالا می‌توانند به‌عنوان راهنمای تقریبی برای اینکه کدام برچسب را چه وقت به کار ببرید عمل کنند، اما نگهدارنده‌ها آزادند از قضاوت خودشان استفاده کنند.

- تخمین زمان صرف‌شده را باید به‌عنوان میانگین زمانی تفسیر کرد که یک _نگهدارنده_ صرف انجام آن PR می‌کند.
- اگر بیش از یک برچسب مشخص شده باشد، برچسبی که بالاترین مقدار اعتبار را دارد، اعتبار اعطاشده را تعیین می‌کند.
- اگر pull request هنوز باز باشد، هیچ اعتباری (فعلاً) داده نمی‌شود.
- اگر pull request _بدون_ ادغام بسته شود، هیچ اعتباری داده نمی‌شود.

_برای سازگاری با نسخه‌های قبلی، از برچسب‌های `x:size` هم برای تعیین اعتبار اعطاشده پشتیبانی می‌کنیم._

### بازبینی pull request

برای هر pull request ادغام‌شده یا بسته‌شده‌ای که کاربر بازبینی کرده باشد، `5` اعتبار داده می‌شود.

- اگر pull request هنوز باز باشد، هیچ اعتباری (فعلاً) داده نمی‌شود.
- اعتبار بازبینی به ازای هر pull request برای هر کاربر فقط یک بار داده می‌شود.
- کاربری که pull request را باز کرده است، برای بازبینی pull request خودش اعتبار _نمی‌گیرد_.

- اگر یکی از برچسب‌های زیر به pull request اضافه شود، اعتبار داده‌شده برای بازبینی آن تغییر می‌کند:

  | برچسب           | اعتبار |
  | --------------- | ---------- |
  | `x:rep/tiny`    | ۱          |
  | `x:rep/small`   | ۲          |
  | `x:rep/medium`  | ۵          |
  | `x:rep/large`   | ۱۰         |
  | `x:rep/massive` | ۲۰         |

  استفاده از «اندازه»های متفاوت اعتبار برای نویسنده و بازبین یک pull request _ممکن نیست_.
  هر دو بر پایه‌ی همان برچسب `x:rep` هستند.

  اگر بیش از یک برچسب مشخص شده باشد، برچسبی که بالاترین مقدار اعتبار را دارد، اعتبار اعطاشده را تعیین می‌کند.

  _برای سازگاری با نسخه‌های قبلی، از برچسب‌های `x:size` هم برای تعیین اعتبار اعطاشده پشتیبانی می‌کنیم._

### ادغام pull request

برای هر pull request که کاربر ادغام کرده باشد، `1` اعتبار داده می‌شود.

- اگر pull request هنوز باز باشد، هیچ اعتباری (فعلاً) داده نمی‌شود.
- اگر pull request _بدون_ ادغام بسته شود، هیچ اعتباری داده نمی‌شود.
- کاربری که pull request را باز کرده است، برای ادغام pull request خودش اعتبار _نمی‌گیرد_.
- اگر pull request هیچ بازبینی‌ای نداشته باشد، به جای آن `5` اعتبار داده می‌شود.

### باز کردن یک issue

مانند pull requestها، به طور پیش‌فرض، وقتی یک issue باز می‌شود **هیچ اعتباری داده نمی‌شود**.
برخلاف pull requestها، اعتبار فقط برای issueهای large یا massive داده می‌شود.

بسته به محتوای issue، یک نگهدارنده می‌تواند با افزودن یکی از برچسب‌های زیر به آن، اعتبار بدهد:

| برچسب           | اعتبار | مثال‌ها                                             |
| --------------- | ---------- | ---------------------------------------------------- |
| `x:rep/large`   | ۳۰         | <ul><li>تمرین مفهوم کاملاً پرداخته‌شده</li></ul> |
| `x:rep/massive` | ۱۰۰        | <ul><li>طراحی برنامه‌ی درسی یک ترک</li></ul>       |

مثال‌های بالا می‌توانند به‌عنوان راهنمای تقریبی برای اینکه کدام برچسب را چه وقت به کار ببرید عمل کنند، اما نگهدارنده‌ها آزادند از قضاوت خودشان استفاده کنند.

- اعتبار باید بازتاب‌دهنده‌ی میزان تلاشی باشد که یک _نگهدارنده_ صرف ساختن آن issue می‌کند.

- اگر بیش از یک برچسب مشخص شده باشد، برچسبی که بالاترین مقدار اعتبار را دارد، اعتبار اعطاشده را تعیین می‌کند.
