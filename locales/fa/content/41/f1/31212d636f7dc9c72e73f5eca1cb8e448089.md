# ساختار

ساختار مجموعه‌ای ثابت و ناهمگون از داده‌ها را در یک واحد گرد هم می‌آورد. ساختار در Rust این ویژگی‌ها را دارد:

- هر نوع ساختار اسم مشخص خودش را دارد.
- به هر عضو ساختار یک **فیلد** می‌گویند.
- هر فیلد ساختار اسم مشخص خودش را دارد.
- قابلیت مشاهده در سطح فیلد پیگیری می‌شود: هر فیلد می‌تواند به‌طور مستقل عمومی، خصوصی یا از گونه‌ای دیگر باشد[^1].

# مروری بر ساختارها

ساختار با کلیدواژه‌ی `struct` تعریف می‌شود و پس از آن، اسم نوعی می‌آید که این ساختار توصیفش می‌کند.
بعد از اسم می‌تواند آکولاد بیاید (برای یک ساختار استاندارد)، پرانتز (برای یک ساختار تاپلی)، یا نقطه‌ویرگول (برای یک ساختار واحد).

```rust
struct Item {}
```

سپس انواع دیگری به‌عنوان _فیلد_های ساختار به بدنه‌ی آن آورده می‌شوند، که هرکدام نوع خودش را دارد:

```rust
struct Item {
    name: String,
    weight: f32,
    worth: u32,
}
```

در پایان، می‌توان متدها را روی ساختار، داخل یک بلوک `impl` تعریف کرد:

```rust
impl Item {
    // initializes and returns a new instance of our Item struct
    fn new() -> Self {
        todo!()
    }
}
```

# گونه‌های ساختار

ساختار سه گونه دارد: ساختار با فیلدهای نامدار (ساختار استاندارد)، ساختار تاپلی، و ساختار واحد.

ساختار بسیار شبیه **تاپل** است. در واقع، تنها تفاوت ساختار و تاپل به بی‌نام بودن مربوط می‌شود. شکل کلی چنین است:

- ساختارها نام دارند و فیلدهایشان هم نامدار است:

  ```rust
  struct Foo {
      bar: Bar,
      bat: Bat,
  }
  ```

  دسترسی به فیلدها با اسم انجام می‌شود:

  ```rust
  let bar = foo.bar;
  ```

- ساختارهای تاپلی نام دارند و فیلدهایشان بی‌نام است:

  ```rust
  Foo(Bar, Bat)
  ```

  دسترسی به فیلدها با بازگشایی یا با اندیس عددی انجام می‌شود:

  ```rust
  // unpacking
  let (bar, bat) = foo;
  ```

  ```rust
  // numeric index
  let bar = foo.0;
  let bat = foo.1;
  ```

- تاپل‌ها بی‌نام‌اند و فیلدهایشان هم بی‌نام است:

  ```rust
  (Bar, Bat)
  ```

  همانند ساختارهای تاپلی، دسترسی به فیلدها با بازگشایی یا با اندیس عددی انجام می‌شود.

- ساختارهای بی‌نام، همان‌طور که از اسمشان برمی‌آید، بی‌نام‌اند، اما فیلدهای نامدار دارند. ممکن است با آن‌ها از زبان‌های دیگری مانند Go یا Java آشنا باشید. این نوع در Rust وجود ندارد؛ به‌جای آن‌ها، استفاده از تاپل روش مرسوم به شمار می‌آید.

# انواع با اندازه‌ی صفر

تعداد فیلدهای یک ساختار می‌تواند هر قدر که لازم است باشد، کم یا زیاد. پیامد این حرف آن است که داشتن ۰ فیلد برای یک ساختار مجاز است. به ساختاری که ۰ فیلد دارد، **نوع با اندازه‌ی صفر** می‌گویند و کامپایلر با آن رفتار ویژه‌ای دارد: نوع‌های با اندازه‌ی صفر (که معمولاً با اختصار **ZST** از آن‌ها یاد می‌شود) هرگز فضایی از پشته یا هیپ مصرف نمی‌کنند، حتی وقتی انتظار داشته باشید چنین کاری بکنند. برای مثال، اگر `T` یک ZST باشد، `Box<T>` هیچ حافظه‌ای روی هیپ تخصیص نمی‌دهد.

هنگام نوشتن یک ZST می‌توانید از نحوه‌ی نگارش ساختار استاندارد یا ساختار تاپلی استفاده کنید:

```rust
// declaration
struct Foo {}
// instantiation
let foo = Foo {}
```

```rust
// declaration
struct Foo();
// instantiation
let foo = Foo();
```

یک شکل کوتاه‌شده هم برای ZST وجود دارد:

```rust
// declaration
struct Foo;
// instantiation
let foo = Foo;
```

معمولاً هنگام نوشتن یک ZST، شکل کوتاه‌شده ترجیح داده می‌شود، چون نمی‌توانید این دو را با هم قاطی کنید: هر سبکی که برای تعریف یک ZST به کار رفته باشد[^2]، همان سبک برای نمونه‌سازی از آن لازم است.

پس از این همه بحث درباره‌ی نحوه‌ی نگارش ZST، بیایید ببینیم چرا ممکن است اصلاً به چنین نوعی نیاز داشته باشید. یک ZST نمی‌تواند هیچ داده‌ای ذخیره کند، اما برای پیاده‌سازی trait روی آن بسیار مناسب است.

---

[^1]: [این مستندات](https://doc.rust-lang.org/reference/visibility-and-privacy.html) بعضی از گزینه‌های کم‌کاربرد قابلیت مشاهده را توضیح می‌دهد.
[^2]: این یک نمونه‌ی خاص از یک قاعده‌ی کلی است: هر سبکی که برای تعریف هر نوع ساختاری به کار رفته باشد، همان سبک برای نمونه‌سازی از آن لازم است.
