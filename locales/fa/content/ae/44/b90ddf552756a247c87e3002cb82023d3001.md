# لیست

یک `ARRAY` ثابت است. با یک اندازه ساخته می‌شود و همان اندازه می‌ماند: نه چیزی به آن اضافه می‌شود و نه چیزی از آن حذف می‌شود.

دفترچه‌ی یک کارآگاه این‌طور نیست. سرنخ‌ها یکی‌یکی پیدا می‌شوند و وقتی منتفی می‌شوند، خط می‌خورند. برای این کار به یک **لیست** نیاز دارید.

```sather
   notes ::= #LIST{STR};
   notes.append("muddy boots");
   notes.append("broken window");
   notes.size                   -- 2
```

`LIST{T}` مثل آرایه مقادیری از نوع `T` را به ترتیب نگه می‌دارد و هر وقت بخواهید بزرگ و کوچک می‌شود.

## درجا تغییر می‌کند

`append` لیستی را که روی آن فراخوانی می‌شود تغییر می‌دهد و چیزی برنمی‌گرداند:

```sather
   notes.append("muddy boots");        -- yes
   notes := notes.append("muddy boots");   -- no: append answers nothing
```

این با `FMAP` و `FSET` فرق دارد، که در آن‌ها هر تغییر باید دوباره به همان متغیر نسبت داده می‌شد. `LIST` یک شیء معمولی است، مثل `SCOREBOARD`: آن را به یک روال بدهید و آن روال می‌تواند لیست شما را تغییر دهد.

## خواندن و نوشتن

کروشه‌ها، با شمارش از صفر، دقیقاً مثل آرایه:

```sather
   notes[0]                     -- "muddy boots"
   notes[1] := "smashed window";
   notes.size                   -- how many
   notes.is_empty               -- true when there are none
```

## حذف کردن

`remove_index` یک موقعیت را بیرون می‌آورد و هر چیزی که بعد از آن است، یک خانه بالا می‌آید:

```sather
   notes.remove_index(0);       -- the first clue is struck out
```

پس موقعیت‌ها دائمی نیستند. موقعیت یک سرنخ وقتی سرنخ قبلی حذف می‌شود تغییر می‌کند، و این نکته پیش از ذخیره کردن یک موقعیت، ارزش به یاد سپردن دارد.

## پیمایش آن

`elt!` کار می‌کند، همان‌طور که روی آرایه کار می‌کند:

```sather
   loop
      #OUT + notes.elt! + "\n";
   end;
```

## آکولادها

`LIST{STR}` لیستی از رشته‌ها است و `LIST{INT}` لیستی از اعداد. این یک کلاس جنریک است، دقیقاً مثل همان کلاسی که در `lost-property` نوشتید. حالا می‌توانید کلاس‌های خودِ کتابخانه را هم به همین شکل بخوانید.
