# پیوست دستورالعمل‌ها

## پیام‌های استثنا

گاهی لازم است [یک استثنا را `raise` کنید][raising-exceptions].
وقتی این کار را می‌کنید، همیشه باید یک **پیام خطای معنادار** اضافه کنید تا نشان دهید منبع خطا چیست.
این کار کد شما را خواناتر می‌کند و به Debug کردن بسیار کمک می‌کند.
در موقعیت‌هایی که می‌دانید منبع خطا نوع مشخصی دارد، می‌توانید یکی از [انواع خطای داخلی][error-base-classes] را `raise` کنید، اما باز هم باید پیام معناداری اضافه کنید.


یک بازی معتبر `Tic Tac Toe` وقتی تمام می‌شود که یک بازیکن برنده شود.
اگر هر دو بازیکن در وضعیت برنده باشند، این تمرین از شما می‌خواهد که از [دستور `raise`][raise] استفاده کنید و در راه‌حل خود یک `ValueError` «پرتاب» کنید.
همچنین اگر تشخیص داده شود که یک بازیکن دو نوبت پشت سر هم بازی کرده است، یا حرکت اول را انجام داده در حالی که قرار بود حرکت دوم را انجام دهد، انتظار می‌رود کد شما یک `ValueError` پرتاب کند.


برای `raise` کردن یک `ValueError` همراه با پیام، پیام را به‌عنوان آرگومان به نوع `exception` بدهید:

```python
# Example when player O goes before player X.
raise ValueError("Wrong turn order: O started")

# Example when player X goes twice.
raise ValueError("Wrong turn order: X went twice")

# Example when player X wins AND player O wins.
raise ValueError("Impossible board: game should have ended after the game was won")
```

تست‌ها تطابق دقیق پیام خطا را بررسی می‌کنند، پس لطفاً نتایج مورد انتظار را با دقت بخوانید.
