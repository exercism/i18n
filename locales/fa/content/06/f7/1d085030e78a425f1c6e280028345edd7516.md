# مقدمه‌ای بر تغییر مسیر

در دنیای رابط خط فرمان، برنامه‌ها اغلب با سه جریان داده‌ی استاندارد سر و کار دارند:

1. **ورودی استاندارد** (`stdin`): جایی که برنامه ورودی خود را دریافت می‌کند (معمولاً از صفحه‌کلید).
1. **خروجی استاندارد** (`stdout`): جایی که برنامه خروجی معمول خود را می‌فرستد (معمولاً به صفحه‌نمایش ترمینال).
1. **خطای استاندارد** (`stderr`): جایی که برنامه پیام‌های خطا را می‌فرستد (معمولاً به صفحه‌نمایش ترمینال).

به یاد بیاورید که این‌ها را در فصل [پایپ‌لاین و فهرست دستورها][pipelines] معرفی کردیم.

~~~~exercism/note
می‌توان پایپ‌لاین را نوعی تغییر مسیر در نظر گرفت: خروجی استاندارد یک برنامه مستقیماً به ورودی استاندارد برنامه‌ی دیگری فرستاده می‌شود.
پیش‌تر به پایپ‌لاین پرداخته‌ایم.
در این مفهوم، تغییر مسیر به فایل‌ها و از فایل‌ها را بررسی می‌کنیم.
~~~~

تغییر مسیر در شل سازوکاری قدرتمند است که به شما امکان می‌دهد مقصد این جریان‌ها را تغییر دهید.
به جای اینکه برنامه از صفحه‌کلید بخواند یا روی صفحه بنویسد، می‌توانید ورودی را از یک فایل تغییر مسیر دهید یا خروجی را به یک فایل بفرستید.
این کار انعطاف و کنترل قابل‌توجهی بر نحوه‌ی تعامل برنامه‌ها با داده فراهم می‌کند.

## عملگرهای اصلی تغییر مسیر

در ادامه، رایج‌ترین عملگرهای تغییر مسیر و کاری که انجام می‌دهند آمده است:

### `>` (تغییر مسیر خروجی)

* هدف: تغییر مسیر دادن خروجی استاندارد (`stdout`) یک دستور به یک فایل.
* رفتار:
  * اگر فایل وجود نداشته باشد، ساخته می‌شود.
  * اگر فایل وجود داشته باشد، محتوایش بازنویسی می‌شود.
* مثال:

  ```bash
  # Sends the output of 'ls -l' to 'file_listing.txt'
  ls -l > file_listing.txt
  ```

~~~~exercism/caution
تغییر مسیر **پیش از** اجرای دستور انجام می‌شود.
یعنی نمی‌توانید به همان فایلی تغییر مسیر دهید که باید از آن بخوانید.

```bash
date > date.txt         # populate the file with the current date
cat date.txt > date.txt # 'date.txt' is now empty!
```

در دستور دوم مثال بالا،

1. Bash ابتدا فایلی را که در تغییر مسیر نام برده شده خالی می‌کند.
   این کار محتوای پیشین را از بین می‌برد و فایلی خالی بر جای می‌گذارد.
2. سپس Bash فایل تازه‌خالی‌شده را می‌خواند.
3. سپس Bash محتوا (یعنی هیچ چیز) را دوباره در فایل می‌نویسد.
~~~~

### `>>` (تغییر مسیر خروجی با افزودن)

* هدف: افزودن خروجی استاندارد (`stdout`) یک دستور به یک فایل.
* رفتار:
  * اگر فایل وجود نداشته باشد، ساخته می‌شود.
  * اگر فایل وجود داشته باشد، خروجی به انتهای فایل اضافه می‌شود.
* مثال:

  ```bash
  # Adds "Another line" to the end of the file
  echo "Another line" >> file_listing.txt
  ```

### `<` (تغییر مسیر ورودی)

* هدف: تغییر مسیر ورودی استاندارد (`stdin`) یک دستور از یک فایل.
* رفتار: دستور ورودی خود را به جای صفحه‌کلید از فایل مشخص‌شده می‌خواند.
* مثال:

  ```bash
  # 'tr' reads from 'lowercase.txt' and
  # output is redirected to 'uppercase.txt'
  tr 'a-z' 'A-Z' < lowercase.txt > uppercase.txt
  ```

### `2>` (تغییر مسیر خطا):

* هدف: تغییر مسیر خطای استاندارد (`stderr`) یک دستور به یک فایل.
* رفتار: پیام‌های خطا به جای ترمینال به فایل مشخص‌شده فرستاده می‌شوند.
* مثال:
  ```bash
  # Error message from 'rm' is sent to 'error_log.txt'
  rm non_existent_file 2> error_log.txt
  ```

می‌توانید خطای استاندارد را با `2>>` به یک فایل _اضافه کنید_.

### تغییر مسیرهای دیگر

تغییر مسیرهایی هم وجود دارند که می‌توانند `stdin` و `stderr` را با هم ادغام کنند.
برای جزئیات به [راهنما][manual] مراجعه کنید.

## `/dev/null`

`/dev/null` یک فایل ویژه است که

* وقتی از آن می‌خوانید، فایلی خالی است و
* همه‌ی داده‌ای که در آن نوشته می‌شود را دور می‌ریزد.

گاهی به آن «سبد بیت» می‌گویند.
برای پنهان کردن خروجی یا خطاها به کار می‌آید.

```bash
some_command > /dev/null  # Discards stdout
some_command 2> /dev/null # Discards stderr

# Using /dev/null as input will prevent the command
# from reading data from the keyboard
some_command < /dev/null
```

## ترکیب تغییر مسیرها

می‌توان چندین تغییر مسیر را همزمان به کار برد.

```bash
some_command < input.txt > output.txt 2> error.txt
```

می‌توان یک تغییر مسیر را کپی کرد.

```bash
# send stderr to the same destination as stdout
some_command > output.txt 2>&1
```

وقتی `2>&1` را می‌بینید، آن را این‌گونه بخوانید: «`stderr` را به _هر جایی که `stdout` **در حال حاضر** به آن اشاره می‌کند، تغییر مسیر بده_.»
Bash دستورهای تغییر مسیر را دقیقاً از چپ به راست پردازش می‌کند، یعنی می‌توانید این کار را انجام دهید:

```bash
# redirect stdout to 'output1.txt'
# redirect stderr to the same place
# then change stdout to 'output2.txt'
some_command > output1.txt 2>&1 > output2.txt
```

## توصیف‌گرهای فایل

در بافت شل‌نویسی و سیستم‌عامل‌هایی مثل Linux/Unix، توصیف‌گر فایل (FD) یک عدد صحیح نامنفی است که به‌عنوان شناسه یا مرجعی برای یک فایل باز یا منبع ورودی/خروجی عمل می‌کند.
آن را مانند یک برچسب یا شماره‌ی مرجع در نظر بگیرید که سیستم‌عامل برای پیگیری فایل‌های باز و جریان‌های داده از آن استفاده می‌کند.

شماره‌هایی که در سمت چپ تغییر مسیرها می‌بینید، توصیف‌گر فایل هستند.

به جریان‌های استاندارد ورودی/خروجی، ۳ توصیف‌گر فایل اول اختصاص داده می‌شود:

* ورودی استاندارد، توصیف‌گر فایل ۰ است
* خروجی استاندارد، توصیف‌گر فایل ۱ است
* خطای استاندارد، توصیف‌گر فایل ۲ است

می‌توان توصیف‌گرهای فایل جدید را با دستور `exec` و عملگرهای تغییر مسیر تنظیم یا ایجاد کرد.

```bash
# create FD 3 as a copy of stdout
exec 3>&1
# send stdout to a log file
exec > log.txt

# then redirect both stdout and file descriptor 3
echo "some debug message" >&3  # displayed in the terminal
some_command  2>&1 # stdout and stderr send to 'log.txt'
```

این تکنیک چندان پیچیده به نظر می‌رسد، اما در موقعیت‌هایی می‌تواند بسیار مفید باشد که اسکریپت شما توسط یک بسته‌ی نرم‌افزاری دیگر اجرا می‌شود و خروجی استاندارد به‌طور خودکار توسط آن نرم‌افزار گرفته می‌شود.
دستور `bats` که برای اجرای تست‌های واحد این مسیر به کار می‌رود، به همین شکل کار می‌کند: `bats` خروجی استاندارد و خطای استاندارد یک تست را می‌گیرد، اما پیام‌های Debug که به توصیف‌گر فایل ۳ فرستاده می‌شوند روی ترمینال نمایش داده خواهند شد.
~~~~

## خلاصه

تغییر مسیر چه فایده‌ای دارد؟

* ذخیره‌ی خروجی: نگه‌داشتن نتیجه‌ی یک دستور برای بررسی یا پردازش بعدی.
* ثبت وقایع: ذخیره‌ی پیام‌های خطا برای Debug کردن.
* خودکارسازی: زنجیره‌کردن دستورها به هم و استفاده از خروجی یکی به‌عنوان ورودی دیگری.
* پالایش: دور ریختن خروجی ناخواسته.
* پردازش دسته‌ای: پردازش داده از فایل‌ها به جای تایپ دستی آن.
* اسکریپت‌نویسی: تغییر مسیرها برای نوشتن اسکریپت‌های شل مقاوم ضروری‌اند.

تغییر مسیرهای شل کنترل دقیقی بر نحوه‌ی تعامل برنامه‌ها با داده به شما می‌دهند و امکان می‌دهند جریان‌های کاری پیچیده بسازید و اطلاعات را به‌شکل مؤثری مدیریت کنید.
