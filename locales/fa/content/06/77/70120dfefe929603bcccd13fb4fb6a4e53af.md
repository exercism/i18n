# مقدمه

عبارت‌های باقاعده روشی بسیار انعطاف‌پذیر برای _تطبیق الگو_ روی رشته‌ها هستند و از یک زبان دامنه‌ویژه که برای همین منظور طراحی شده است استفاده می‌کنند.

بسیاری از قابلیت‌های عبارت باقاعده در R پایه تعبیه شده‌اند و ممکن است نمونه‌هایی از آن‌ها را در کدهای قدیمی‌تر ببینید.

برای کد جدید، _به‌شدت_ توصیه می‌شود از کتابخانه‌ی [`stringr`][web-stringr] استفاده کنید.

همان‌طور که در [مفهوم رشته‌ها][concept-strings] اشاره شد، `stringr` مستندات خوبی دارد که معمولاً خود نویسنده‌ی بسته آن را نوشته است.

- یک [وب‌سایت مرجع][web-stringr]
- یک [برگه‌ی تقلب][cheat-stringr].
- یک [فصل رشته‌ها][book-strings] و یک [فصل عبارت باقاعده][book-regex] در «R for Data Science».

بسیاری از توابعی که پیش‌تر در مفهوم [`Strings`][concept-strings] بررسی شدند، به‌صورت پیش‌فرض برای جست‌وجوهای عبارت باقاعده طراحی شده‌اند.

ما مفهوم رشته‌ها را نسبتاً ساده نگه داشتیم و فقط روی رشته‌های تحت‌اللفظی تطبیق دادیم، اما در عوض می‌توان از هر الگوی عبارت باقاعده‌ای استفاده کرد.

به‌طور رسمی، یک عبارت باقاعده در R با فراخوانی [`regex()`][ref-regex] ساخته می‌شود.
برای راحتی کار، توابع `stringr` هر رشته‌ی الگو را به‌عنوان یک عبارت باقاعده در نظر می‌گیرند.
در مثال زیر، `str_replace_all()` اولی صرفاً شکل ساده‌شده‌ی نسخه‌ی دوم است:

```R
input <- "Some input string"

# "\\s" matches any whitespace character
input |> str_replace_all("\\s", "_")
[1] "Some_input_string"

input |> str_replace_all(regex("\\s"), "_")
[1] "Some_input_string"
```

[برگه‌ی تقلب][cheat-stringr] راهنمای مفیدی است: همه‌ی توابعی که آرگومان `pattern` دارند (با رنگ قرمز چاپ شده‌اند) یک عبارت باقاعده می‌پذیرند و صفحه‌ی ۲ خلاصه‌ای از نحوه‌ی نگارش عبارت باقاعده را ارائه می‌دهد.

توجه کنید که تابع [`regex()`][ref-regex] هنوز می‌تواند مهم باشد اگر بخواهید پیش‌فرض‌ها را، مانند حساسیت به بزرگی و کوچکی حروف یا تنظیمات محلی، بازنویسی کنید.

```R
# default is case sensitive
"A Mixed Assortment" |> 
    str_replace_all(regex("[aeiou]", ignore_case = TRUE), "*")
#> [1] "* M*x*d *ss*rtm*nt"
```

بسیاری از کدهای عبارت باقاعده شامل یک بک‌اسلش هستند، مانند `\s` که در بالا استفاده شد.
در رشته‌های معمولی R باید `\` را با دو بار نوشتن اسکیپ کرد، و به همین دلیل `"\\s"` نوشته می‌شود.

بک‌اسلش‌ها می‌توانند زیاد شوند و گیج‌کننده شوند، بنابراین در موارد پیچیده ممکن است استفاده از [رشته‌های خام][book-raw] کمک کند.

به‌طور پیش‌فرض، نحوه‌ی نگارش برای تعریف یک رشته‌ی خام `r"( )"` است، اما جداکننده‌های دیگری هم مجازند.
از آنجا که هم پرانتزهای `( )` و هم کروشه‌های `[ ]` در نحوه‌ی نگارش عبارت باقاعده رایج‌اند (برای گروه‌های ثبت و گروه‌های گزینه)، آکولادهای `{ }` ممکن است انتخاب خوبی باشند.

```R
input |> str_replace_all(r"{\s\w}", "__")
#> [1] "Some__nput__tring"
```

## تشخیص تطبیق

در ادامه چند پرسش و توابعی که می‌توانند در پاسخ به آن‌ها کمک کنند می‌آید.

برخی مثال‌ها از `fruit` استفاده می‌کنند، برداری با ۸۰ اسم میوه که برای تمرین همراه `stringr` ارائه شده است.

_آیا یک رشته شامل تطبیقی هست؟_
`str_detect()`، یا `str_starts()` و `str_ends()` تا از لنگرهای `^` و `$` استفاده نکنید.

```R
# berries begining with b
fruit |> str_detect("^b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE

# alternative syntax
fruit |> str_starts("b.*berry") |> head(15)
#> [1] FALSE FALSE FALSE FALSE FALSE  TRUE  TRUE FALSE FALSE  TRUE  TRUE FALSE FALSE FALSE FALSE
```

_فقط رشته‌هایی را برگردانیم که شامل تطبیق هستند؟_
برای گرفتن رشته‌ها از `str_subset()` و برای گرفتن اندیس‌ها از `str_which()` استفاده کنید.

```R
fruit |> str_subset("a...e")
[1] "apple"       "blackberry"  "mandarine"   "nectarine"   "pineapple"   "pomegranate" "raspberry"   "salal berry"
> fruit |> str_which("a...e")
[1]  1  7 48 51 62 64 70 73
```

_در هر رشته چند تطبیق وجود دارد؟_
از `str_count()` استفاده کنید.

```R
# count vowels
fruit |> str_count("[aeiou]") |> head(10)
#> [1] 2 3 4 3 3 2 2 3 5 3
```

_تطبیق کجاست؟_
`str_view()` برای استفاده‌ی تعاملی، و به‌طور کلی `str_locate()` یا `str_locate_all()`.

```R
# str_view only shows matching elements, with match in < > delimiters
fruit |> str_view("a...e")
 [1] │ <apple>
 [7] │ bl<ackbe>rry
[48] │ mand<arine>
[51] │ nect<arine>
[62] │ pine<apple>
[64] │ pomegr<anate>
[70] │ r<aspbe>rry
[73] │ sal<al be>rry

# str_locate returns all elements
fruit |> str_locate("a...e") |> head(10)
      start end
 [1,]     1   5
 [2,]    NA  NA
 [3,]    NA  NA
 [4,]    NA  NA
 [5,]    NA  NA
 [6,]    NA  NA
 [7,]     3   7
 [8,]    NA  NA
 [9,]    NA  NA
[10,]    NA  NA
```

## گروه‌های ثبت

معمولاً می‌خواهیم بدانیم _چه چیزی_ تطبیق پیدا می‌کند.
این کار با قرار دادن گروه‌های ثبت داخل پرانتز در عبارت باقاعده انجام می‌شود.

می‌توان در همان عبارت باقاعده با استفاده از `\1`، `\2` و غیره به گروه‌های ثبت ارجاع داد.
برای نمونه، یافتن جفت‌های تکراری از حروف:

```R
fruit |> str_subset("(..)\\1")
[1] "banana"      "coconut"     "cucumber"    "jujube"      "papaya"      "salal berry"
```

با نحوه‌ی نگارش مشابه، می‌توان از گروه‌های ثبت در رشته‌های جایگزین استفاده کرد:

```R
# double to triple
fruit |> 
  str_subset("(..)\\1") |> 
  str_replace("(..)\\1", "\\1\\1\\1")
[1] "bananana"      "cococonut"     "cucucumber"    "jujujube"      "papapaya"      "salalal berry"
```

تطبیق‌ها را برای پردازش بعدی با تابع `str_match()` برای فقط اولین تطبیق، یا `str_match_all()` برای همه‌ی تطبیق‌ها جمع کنید.

گروه‌های ثبت معمولاً در هر زبانی خروجی پیچیده‌ای تولید می‌کنند.
رویکرد R (_که برای چالش بیشتر، برداری‌شده هم هست_) این است که از `str_match()` یک ماتریس تولید کند: یک سطر به‌ازای هر رشته‌ی ورودی، ستون ۱ شامل رشته‌ی کامل تطبیق‌شده و ستون‌های باقی‌مانده شامل گروه‌های ثبت گوناگون.

استفاده از گروه‌های اسم‌دار می‌تواند مزیت باشد، چون به اسم ستون‌ها در ماتریس نتایج تبدیل می‌شوند.

```R
recipe <- "dissolve 25g sugar in 200ml water"
recipe |> str_match("(\\d+g) .* (\\d+ml)")
     [,1]                 [,2]  [,3]   
[1,] "25g sugar in 200ml" "25g" "200ml"

# use named capture groups
recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")
                          wt    vol    
[1,] "25g sugar in 200ml" "25g" "200ml"
```

~~~~exercism/note
در این برنامه‌ی درسی درباره‌ی ماتریس‌ها زیاد صحبت نکرده‌ایم، هرچند یک [سند مفهومی][concept-matrices-arrays] هست که می‌توانید به آن مراجعه کنید.
ماتریس‌ها با اکوسیستم Tidyverse چندان سازگار نیستند، هرچند از مدت‌ها پیش بخشی از R پایه بوده‌اند.

به‌طور خلاصه: با ماتریس‌ها مانند بردارهایی با ۲ اندیس رفتار کنید، به این ترتیب: `[rows, cols]`.
هر یک از اندیس‌ها را خالی بگذارید تا کل سطر یا ستون را به دست آورید.

وقتی سطر تنها `r` را با `m[r,]` یا ستون تنها `c` را با `m[,c]` می‌گیرید، مقدار بازگشتی به‌طور پیش‌فرض به یک بردار تخت می‌شود.

```R
> amounts <- recipe |> str_match("(?<wt>\\d+g) .* (?<vol>\\d+ml)")

# get all of row 1, as a named vector
> amt1 <- amounts[1,]
> amt1
                                       wt                  vol 
"25g sugar in 200ml"                "25g"              "200ml" 

# get a vector element
amt1["wt"] |> unname()
[1] "25g"
```
~~~~

طبیعتاً `str_match_all()` خروجی‌ای با ساختار حتی پیچیده‌تر تولید می‌کند:

- نتیجه یک لیست است، با یک عنصر به‌ازای هر رشته‌ی ورودی.
- اگر فقط یک رشته‌ی ورودی وجود داشته باشد، خروجی را با اندیس‌گذاری `[[1]]` از لیست خارج کنید، همان‌طور که در [مفهوم لیست‌ها][concept-lists] توضیح داده شده است.
- هر عنصر یک ماتریس است، با ستون‌هایی مانند `match()`.
- هر سطر ماتریس، یک گروه ثبت موفق است.

```R
mix <- "Mix 200g of sugar, 180g of flour and 150g of butter"

# raw output
> str_match_all(mix, "(\\d+)g")
[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# we just want the first list element
> str_match_all(mix, "(\\d+)g")[[1]]
     [,1]   [,2] 
[1,] "200g" "200"
[2,] "180g" "180"
[3,] "150g" "150"

# captures are in column 2, so get that as a vector
> str_match_all(mix, "(\\d+)g")[[1]][,2]
[1] "200" "180" "150"
```

البته تطبیق‌ها می‌توانند شکست بخورند.
در این صورت نتیجه مقدار ویژه‌ی `NA` خواهد بود.
آماده باشید که این را بررسی کنید، همان‌طور که در [مفهوم نیستی][concept-nothingness] توضیح داده شده است.

```R
# failed match
recipe |> str_match("(not here)")
     [,1] [,2]
[1,] NA   NA  
```
