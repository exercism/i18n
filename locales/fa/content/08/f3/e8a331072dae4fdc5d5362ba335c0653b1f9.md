# تست

تست‌ها را این‌گونه اجرا کنید:

```bash
$ wrenc exercise-name.spec.wren
```

برای مثال برای `hello-world`:

```bash
$ wrenc hello-world.spec.wren
```


## درک تست‌های ردشده

متد `skip` به مجموعه‌ی تست می‌گوید که یک تست مشخص را اجرا نکند.

- چرا رد می‌شوند؟

تا کاربران بتوانند هر بار روی یک تست تمرکز کنند و تست‌ها را یکی‌یکی، همراه با پیشرفت راه‌حلشان، فعال کنند.

- چگونه آن‌ها را فعال کنیم؟

یک تست ردشده:

```js
// this test will be skipped and not run
skip.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

کافی است `skip.test` را به `do.test` تغییر دهید.

```js
// now the test will be run normally
do.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

## ساخت اولین ماژول Wren شما

تست‌های این ترک، پیاده‌سازی شما را با وارد کردن آن به عنوان یک ماژول Wren بارگذاری می‌کنند: `import "./bob" for Bob`. برای صادر کردن پیاده‌سازی خود، به هیچ نحوه‌ی نگارش خاصی نیاز نیست. فقط اسم کلاس خود را `Bob` بگذارید تا با عبارت `for Bob` در دستورهای `import` هماهنگ باشد، و همه‌چیز باید درست کار کند.

```javascript
class Bob {
  static hey(message) {
    // Your solution to the exercise goes here
  }
}
```

می‌توانید اطلاعات بیشتر درباره‌ی ماژول‌ها را در [مستندات ماژولار بودن Wren][modularity] پیدا کنید.
برای اینکه شروع کار آسان‌تر شود، در پوشه‌ی هر تمرین یک فایل Wren _اسکلت_ وجود دارد.

[modularity]: https://wren.io/modularity.html
