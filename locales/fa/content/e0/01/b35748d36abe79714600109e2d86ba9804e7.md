# درباره

نوع `Result` این امکان را برای یک تابع فراهم می‌کند که مقدار واحدی را برگرداند که همه‌ی موارد زیر را نشان می‌دهد:
- موفق یا ناموفق بودن عملیات
- در صورت موفقیت، مقدار حاصل از عملیات
- در صورت شکست، دلیل شکست

در زبان‌های برنامه‌نویسی دیگری که از چیزی مانند نوع `Result` پشتیبانی نمی‌کنند، معمولاً الگوهای زیر برای رسیدن به اهداف بالا دیده می‌شود:
- تابعی که یک کد عددی برمی‌گرداند که موفقیت یا دلیل شکست را نشان می‌دهد و به یک پارامتر خروجی نیاز دارد تا در صورت موفقیت مقدار را بپذیرد.
- تابعی که در صورت موفقیت مقدار و در صورت خطا NULL را برمی‌گرداند و بعد تابعی دیگر برای گرفتن کد خطایی که دلیل شکست را نشان می‌دهد.

سازوکار رایج دیگر برای مدیریت خطا، استثنا است که هنگام بروز شکست، به‌طور ناگهانی از تابع جاری بیرون می‌زند و
کنترل را به اولین «گرداننده» در پشته‌ی فراخوانی منتقل می‌کند.  
اگر هیچ گرداننده‌ای استثنا را «نگیرد»، برنامه متوقف می‌شود.

## مزایای استفاده از نوع `Result`

* __ایمنی زمان کامپایل__: با صریح کردن موفقیت یا شکست یک فراخوانی تابع در سیستم نوع، کامپایلر می‌تواند تضمین کند که کد فراخوانی‌کننده همه‌ی حالت‌های شکست را مدیریت می‌کند و از این راه از دسته‌ی بزرگی از باگ‌ها که ممکن است به خاطر `null` رخ دهند جلوگیری می‌کند.

* __ایمنی زمان اجرا__: نوع `Result` به‌جای استفاده از `null`، از `Error` برای نمایش شکست استفاده می‌کند و همین باعث می‌شود که بروز `NullReferenceException` غیرممکن شود.

* __مدیریت صریح خطا__: کدی که تابعی را فراخوانی می‌کند که `Result` برمی‌گرداند، باید بپذیرد که آن فراخوانی می‌تواند شکست بخورد؛ کد فراخوانی‌کننده باید این شکست‌ها را آگاهانه مدیریت کند.  هیچ شکست خاموشی رخ نمی‌دهد و هیچ استثنای غافلگیرکننده‌ای وجود ندارد.

* __جریان کنترل قابل پیش‌بینی__: یک `Result` درست مانند هر مقدار دیگری برگردانده می‌شود؛ برخلاف استثنا از پشته‌ی فراخوانی بیرون نمی‌پرد.  همیشه می‌دانید خطاها از کجا سرچشمه می‌گیرند و چگونه منتشر می‌شوند.

* __خوانایی و نگهداری‌پذیری بهتر__: با برگرداندن یک `Result`، امضای تابع به‌روشنی رفتار مورد انتظار را در حالت موفقیت و شکست نشان می‌دهد.

## نحوه‌ی استفاده

نوع `Result` یک نوع جنریک است که دو نوع زیرین را در خود جای می‌دهد:
- نوع مقدار حاصل در یک عملیات موفق
- نوعی که دلیل شکست در یک شکست را نشان می‌دهد

نوع `Result` همچنین یک [اتحاد تفکیک‌شده][discriminated-union] است با حالت‌های ممکن زیر:
* `Ok <value>` که یک نتیجه‌ی موفق را نشان می‌دهد
* `Error <reason>` که یک شکست را نشان می‌دهد

تابع زیر نشان می‌دهد که چگونه یک مقدار `Result` بسازیم:

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

در این مثال، مقدار `Ok` یک رشته است (اسم داده‌شده) و مقدار `Error` هم یک رشته است (علت خطا، به شکل خوانا برای انسان).

## خواندن محتوای یک مقدار `Result`

تعریف نوع و امضای تابع زیر را در نظر بگیرید:

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

کدی که تابع `openFile` را فراخوانی می‌کند می‌تواند با تطبیق الگو، حالت‌های موفقیت و شکست را مدیریت کند، همان‌طور که در مثال زیر آمده است:

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
