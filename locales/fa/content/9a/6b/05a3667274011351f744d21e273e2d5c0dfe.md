# مقدمه

رقم‌های دودویی در نهایت مستقیماً با ترانزیستورهای CPU یا RAM شما و با «روشن» یا «خاموش» بودن هر کدام متناظرند.

دستکاری در سطح پایین، که به‌طور غیررسمی «بازی با بیت‌ها» نامیده می‌شود، در زبان‌های سیستمی اهمیت ویژه‌ای دارد.

زبان‌های سطح بالاتر مانند Kotlin معمولاً بیشتر این جزئیات را پنهان می‌کنند. با این حال، [مجموعه‌ای پایه از عملیات بیتی در دسترس است][ref-bitwise].

## عملیات شیفت بیتی

انواع `Int` یا `Long`، چه علامت‌دار و چه بدون علامت، می‌توانند به‌صورت رشته‌ای از ۱ها و ۰ها نمایش داده شوند و به‌عنوان دنباله‌ای از بیت‌ها دستکاری شوند.

شاید شگفت‌آور باشد که انواع `Byte` یا `Short` با بیشتر عملیات بیتی در Kotlin سازگار نیستند.
همه‌ی مثال‌های زیر از اعداد صحیح ۳۲بیتی (`Int` یا `UInt`) استفاده می‌کنند.

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

شیفت‌های بیتی فقط همه چیز را به اندازه‌ی تعداد مشخصی موقعیت به چپ یا راست می‌برند.
چند بیت از یک سر بیرون می‌ریزند و سر دیگر با صفر یا یک پر می‌شود.

- شیفت به چپ با `shl`: پر کردن با صفر.
- شیفت به راست با `shr` یا `ushr`: پر کردن با صفر برای اعداد مثبت (برای اعداد منفی بعداً را ببینید).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

هر شیفت به چپ مقدار را دو برابر می‌کند و هر شیفت به راست آن را نصف می‌کند (با بریده شدن بخش اعشاری).
این موضوع در نمایش ده‌دهی واضح‌تر است:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

این نوع شیفت بیتی بسیار سریع‌تر از محاسبات «معمولی» است و همین باعث می‌شود این تکنیک در برنامه‌نویسی سطح پایین بسیار رایج باشد.

با _اعداد صحیح منفی_ باید کمی محتاط‌تر باشیم.

مقادیر منفی به‌صورت [متمم دو][wiki-2complement] ذخیره می‌شوند، یعنی چپ‌ترین بیت ۱ است.
برای شیفت به چپ مشکلی نیست، اما هنگام شیفت به راست چطور چپ‌ترین بیت‌ها را پر کنیم؟

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

عملگر `shr` یک [شیفت حسابی][wiki-arithmetic] انجام می‌دهد و بیت علامت را حفظ می‌کند.

عملگر `ushr` یک [شیفت منطقی][wiki-logical] انجام می‌دهد و با صفر پر می‌کند، انگار عدد بدون علامت است.

## منطق بیتی

در [مفهوم منطقی][concept-booleans] دیدیم که عملگرهای `&&` (and)، `||` (or) و `!` (not) با مقادیر منطقی استفاده می‌شوند.

عملگرهای معادلی هم وجود دارند: `and`، `or`، `xor` ([یای انحصاری][wiki-xor]) برای مقایسه‌ی بیت‌های دو عدد صحیح، و یک تابع `inv` (وارون‌سازی) برای وارونه کردن همه‌ی بیت‌ها.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
