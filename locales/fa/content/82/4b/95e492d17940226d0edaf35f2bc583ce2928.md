# دستورالعملها

میکا، برگزارکنندهی رویدادها، در محل کارش ترفیع گرفته است و بهعنوان بخشی از مسئولیتهای جدیدش، مسئول پایگاهدادهی رویدادها شده است. او خیلی زود متوجه شد که بسیاری از دادهها به شکلهایی ذخیره شدهاند که کار کردن با آنها دشوار است، بنابراین شما با هم دست به کار شدهاید تا با یک اسکریپت یکبارمصرف آنها را مرتب کنید.

چون این اسکریپت فقط یک بار اجرا میشود و شما به ساختار دادهها اطمینان دارید، به نظرتان اینجا جای مناسبی برای استفاده از _let assertions_ زبان Gleam است.

## 1. استخراج خطاها

هر رویداد گذشته فهرستی از مشکلاتی دارد که در طول رویداد رخ دادهاند. این مشکلات بهصورت نتیجه ذخیره شدهاند، اما همیشه از گونهی `Error` هستند.


تابع `extract_error` را پیادهسازی کنید که نتیجهای میگیرد که انتظار میرود همیشه `Error` باشد و مقدار خطای درون آن را برمیگرداند.

```gleam
extract_error(Error("Not enough coffee"))
// -> "Not enough coffee"
```

## 2. حذف پیشوند تیم

به ابتدای اسم تیمها واژهی "Team " اضافه شده است، اما نیازی به آن نیست. تابع `remove_team_prefix` را پیادهسازی کنید تا این پیشوند را از اسم تیم حذف کند.

```gleam
remove_team_prefix("Team Turtle")
// -> "Turtle"
```

## 3. جداسازی منطقه و تیم

هر رویداد توسط یک تیم برگزار میشود و هر تیم به یک منطقه تعلق دارد. در پایگاهداده، این دو در یک رشتهی واحد ذخیره شدهاند که با کاما از هم جدا شدهاند.

تابع `split_region_and_team` را پیادهسازی کنید تا رشته را به یک تاپل از دو رشته تقسیم کند؛ یکی برای منطقه و یکی برای تیم. پیشوند "Team " باید از اسم تیم حذف شود.

```gleam
split_region_and_team("East,Team Orange")
// -> #("East", "Orange")
```
