# درباره

اسمبلی دست‌نویس پر از تکرار است.
همان دنباله‌ی کوتاه دستورها بارها و بارها و با تغییرات اندک تکرار می‌شود و انتزاع‌های اندکی برای کاهش کدهای تکراری وجود دارد.
نه تنها این، کدنویسی با اسمبلی مستلزم مدیریت مقادیری است که معنای روشنی ندارند.
پارامترهای اسم‌دار وجود ندارد و برنامه‌نویس باید بیشتر جزئیات سازوکار زیربنایی را به‌صورت دستی مدیریت کند.

NASM، اسمبلری که این ترک از آن استفاده می‌کند، ابزارهایی ارائه می‌دهد که می‌توانند در هر دو مشکل به برنامه‌نویس کمک کنند.
این ابزارها در _زمان اسمبلی_ اجرا می‌شوند، پیش از آنکه هر دستوری به پردازنده برسد.
آنها به اسمبلر می‌گویند که چگونه متن مبدأ را بازنویسی کند، پیش از آنکه حتی به کد ماشین ترجمه شود.

مهم‌ترین این ابزارها **«ماکرو»**ها هستند که می‌توان آنها را دستور پختی برای اسمبلر در نظر گرفت.
آنها در همان جایی که به کار می‌روند باز می‌شوند، انگار که کد آنجا با دست نوشته شده باشد.

[ماکروها][macro] می‌توانند تعدادی توکن لفظی را به عنوان پارامتر بپذیرند و این‌گونه در زمینه‌های مختلف قابل استفاده‌ی مجدد می‌شوند.
با این حال، آنها تابع نیستند: نه `call` هست، نه `ret` و نه انتقال کنترل به نقطه‌ی دیگری از کد.

## ماکروهای تک‌خطی

ساده‌ترین تعریف، با `%define` اسمی به یک مقدار یا یک عبارت کوتاه می‌دهد:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

هر بار که `WIDTH` بعداً ظاهر شود، پیش از اسمبلی با `8` جایگزین می‌شود.
این جایگزینی متنی است، بنابراین اسم در هر جایی که ظاهر شود جایگزین می‌شود، چه در یک عملوند و چه درون تعریف دیگر.

~~~~exercism/note
برای _ثابت‌های_ عددی، `equ` را به `%define` ترجیح دهید.

ماکروی تک‌خطی که با `%define` تعریف می‌شود، فقط هنگام استفاده باز می‌شود و می‌توان مقدارش را دوباره تعیین کرد یا تعریفش را لغو کرد.
از سوی دیگر، ثابت `equ` در همان نقطه‌ی تعریف ارزیابی می‌شود و هرگز تغییر نمی‌کند.
~~~~

یک `%define` می‌تواند پارامترهای _اسم‌دار_ هم بپذیرد و مانند یک تابع درون‌خطی کوچک عمل کند:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
هم کل بدنه و هم هر پارامتر را در پرانتز قرار دهید.
با `%define square(x) x*x`، فراخوانی `square(1+1)` به `1+1*1+1` باز می‌شود که برابر `3` است.
اگر به‌صورت `%define square(x) ((x)*(x))` نوشته شود، همان فراخوانی به `((1+1)*(1+1))` باز می‌شود که برابر `4` است.
~~~~

اسم‌هایی که با `%define` تعریف می‌شوند، به بزرگی و کوچکی حروف حساس‌اند.
گونه‌ی `%idefine` باعث می‌شود اسم به بزرگی و کوچکی حروف حساس نباشد، اگر چنین چیزی لازم باشد.

ماکروهای تک‌خطی برای معنادار کردن بخش‌های مختلف کد مفیدند.
اگر با دقت استفاده شوند، خوانایی را بهبود می‌دهند و احتمال غلط تایپی را کاهش می‌دهند.
برای مثال، ثباتی که درون یک تابع کاربرد مشخصی دارد، می‌تواند بر اساس همان کاربردش تعریف شود:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## ماکروهای چندخطی

یک توالی کامل از کد، با هر تعداد خط، با `%macro` ثبت می‌شود و با `%endmacro` بسته می‌شود.
عددی که بعد از اسم می‌آید نشان می‌دهد ماکرو چند آرگومان می‌گیرد که می‌تواند صفر باشد.
آرگومان‌ها هنگام ارسال با کاما (`,`) از هم جدا می‌شوند:

```x86asm
%macro example_macro 0
...
%endmacro
```

آرگومان‌ها در ماکروهای چندخطی اسمی ندارند.
آنها به ترتیب ارسال با `%1`، `%2` و به همین ترتیب ارجاع داده می‌شوند:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

توجه کنید که آرگومان‌ها باید نحوه‌ی نگارش معتبری برای عملیات انجام‌شده در بدنه‌ی ماکرو داشته باشند.
اینجا `mult_two eax, ecx` و `mult_two r8, r9` هر دو اسمبل می‌شوند، اما `mult_two eax, cl` اسمبل نمی‌شود، چون `imul eax, cl` تعریف نشده است.

ماکروها می‌توانند تعداد دلخواهی آرگومان هم بگیرند.
این کار با نماد `n-*` انجام می‌شود که در آن `n` کمترین تعداد آرگومان است:

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

در یک ماکروی چندخطی، `%0` نشان‌دهنده‌ی _تعداد_ آرگومان‌های ماکرو است.
این موضوع به‌ویژه در ماکروهایی مفید است که ممکن است تعداد دلخواهی آرگومان بگیرند.

### برچسب‌ها درون یک ماکرو

ماکرویی که یک برچسب معمولی تعریف می‌کند، به‌محض اینکه دو بار استفاده شود از کار می‌افتد، چون آن برچسب آن‌گاه دو بار تعریف می‌شود.
برای استفاده از برچسب‌ها درون ماکرویی که ممکن است بیش از یک بار فراخوانی شود، باید چنین برچسبی را با `%%` شروع کنید.
این کار به اسمبلر می‌گوید که در هر باز شدن، اسم متفاوت و یکتایی به این برچسب بدهد:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## تکرار در زمان اسمبلی

می‌توان یک بلوک کد تک‌خطی را با [`times`][times] تکرار کرد.
این کار به‌ویژه هنگام اعلام مقادیر تکراری در حافظه مفید است:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

برای تکرار کد چندخطی، می‌توانیم به‌جای آن از `%rep` استفاده کنیم:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

توجه کنید که تعداد تکرارها درست بعد از `%rep` مشخص می‌شود و یک `%endrep` برای بستن بلوک تکراری وجود دارد.

استفاده از یک شمارنده‌ی زمان اسمبلی درون بلوک `%rep` رایج است، درست همان‌طور که یک حلقه‌ی زمان اجرا از یک شمارنده استفاده می‌کند.
در حالی که همان‌طور که دیدیم یک ثابت عددی زمان اسمبلی را می‌توان با `equ` اعلام کرد، برای _متغیرهای_ عددی زمان اسمبلی از `%assign` استفاده می‌کنیم.
برخلاف `%define`، مقدار `%assign` بی‌درنگ به یک عدد ارزیابی می‌شود و می‌توان آن را دوباره تعیین کرد:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

پس از اجرای پیش‌پردازشگر، حلقه از میان می‌رود و چهار دستور `add` باقی می‌ماند که عملوندهای فوری `0`، `1`، `2` و `3` در آنها گنجانده شده است.
این همان بازکردن حلقه است که توسط اسمبلر انجام می‌شود: نه ثبات شمارنده‌ای و نه پرشی، فقط کدی خطی.

کاربرد رایج دیگر `%rep`، پردازش آرگومان‌ها در ماکرویی است که ممکن است هر تعدادی از آنها را بگیرد.
در آن صورت، `%rep` معمولاً با `%rotate` همراه می‌شود که آرگومان‌های یک ماکرو را می‌چرخاند، به‌گونه‌ای که آرگومان دوم، اولی می‌شود.
اعمال مکرر `%rotate` آرگومان سوم، سپس چهارم و به همین ترتیب را اولی می‌کند و تضمین می‌کند که هر آرگومان به‌نوبت پردازش شود:

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## اسمبلی شرطی

شرط‌های مختلفی در اختیار [پیش‌پردازشگر][preprocessor] است.
آنها بین چند مسیر مختلف انتخاب می‌کنند و بدنه‌ی خود را همان‌جا باز می‌کنند، اما تنها زمانی که شرطشان برقرار باشد.

`%if` ... `%elif` ... `%else` ... `%endif` یک شاخه را بر پایه‌ی یک آزمون عددی انتخاب می‌کنند:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

`%ifdef` و `%ifndef` مشابه‌اند، اما بررسی می‌کنند که آیا اسمی تعریف شده است یا نه.
برای مثال، می‌توان از آنها استفاده کرد تا مطمئن شویم محتوای یک فایل فقط یک بار درج می‌شود، حتی وقتی بیش از یک مبدأ آن فایل را فراخوانی می‌کند:

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

شاید متوجه شده باشید که در پایان هر فایل `.asm` در این ترک، این قطعه کد وجود دارد:

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

`%ifidn` دو متن را از نظر تطابق دقیق مقایسه می‌کند.
`__OUTPUT_FORMAT__` توکار به قالب خروجی فعلی باز می‌شود، پس آن کد بررسی می‌کند که آیا قالب خروجی `elf64` است، همان قالبی که سیستم‌های لینوکس از آن استفاده می‌کنند.
اگر چنین باشد، یادداشتی به فایل شیء افزوده می‌شود که مجوزهای موردنیاز پشته را اعلام می‌کند؛ اقدامی امنیتی رایج.
اگر نه، چیزی تغییر نمی‌کند.

## ساختارها

رسیدن به یک فیلد از یک رکورد در حافظه یعنی افزودن آفست بایتی آن فیلد به یک آدرس پایه.
نوشتن این آفست‌ها به‌صورت اعداد خام خطاپذیر است و معنایشان را پنهان می‌کند.
در عوض، [`struc`][struc] و `endstruc` یک چیدمان را اسم‌گذاری می‌کنند و هر فیلد را به آفستی نمادین تبدیل می‌کنند که در زمان اسمبلی محاسبه می‌شود.

درون این بلوک، دستورهای رزرو `resb`، `resw`، `resd` و `resq` یک یا چند بایت، واژه، واژه‌ی دوگانه یا واژه‌ی چهارگانه را کنار می‌گذارند.
قرار دادن یک `.` در ابتدای هر فیلد باعث می‌شود اسم آن محدود به ساختار بماند:

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

اکنون اسم هر فیلد نماینده‌ی آفست آن است، پس `thread.color` برابر `0`، `thread.tension` برابر `4` و `thread.name` برابر `12` است.
NASM همچنین `<struc>_size` را به‌عنوان مجموع تعریف می‌کند، که در آن `<struc>` اسم `struc` است.
برای مثال، اینجا `thread_size` برابر `4 + 8 + 16 = 28` می‌شود.

به یک فیلد با افزودن آفست آن به یک ثبات پایه دسترسی پیدا می‌کنیم و `thread_size` گام میان دو رکورد متوالی است:

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

یک `struc` تنها یک شکل را توصیف می‌کند و به‌تنهایی حافظه‌ای تخصیص نمی‌دهد.
برای ساختن یک نمونه‌ی مقدارگذاری‌شده، می‌توانید بعد از یک برچسب از `istruc ... iend` استفاده کنید.
درون یک نمونه، `at` مقداری را در یک فیلد اسم‌دار قرار می‌دهد:

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

توجه کنید که `thread.name` با `"warp", 0` مقداردهی اولیه می‌شود که فقط ۵ بایت را اشغال می‌کند.
۱۱ بایت دیگر که در `struc` برای آن رزرو شده است، به‌طور خودکار توسط `iend` با صفر پر می‌شود، که نمونه را با `0` تا `thread_size` پر می‌کند.

یک `struc` تنها یک میان‌بر نوشتاری برای حافظه‌ای است که می‌توانیم دستی هم اعلام کنیم.
برای مثال، کد بالا معادل کد زیر است، که در آن `times 11 db 0` تضمین می‌کند ۱۶ بایت در پایان تخصیص یابد:

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## تقسیم به چند فایل

ماکروها اغلب در فایل جداگانه‌ای نگهداری می‌شوند و با `%include` به هر مبدأیی که به آنها نیاز دارد وارد می‌شوند:

```x86asm
%include "patterns.mac"
```

فایلی که اسمش ذکر شده، عیناً در همان نقطه و پیش از اسمبلی درج می‌شود، درست همان‌طور که گویی محتوایش همان‌جا تایپ شده است.
این کار تعریف‌ها را در یک جا نگه می‌دارد و به چند فایل مبدأ اجازه می‌دهد آنها را به اشتراک بگذارند.

اگر ممکن است فایل ماکرو به‌تنهایی اسمبل شود، باید پسوند فایل `.asm` داشته باشد.
توجه کنید که ماکروها هیچ پیوندی ندارند.
حتی اگر فایل ماکرو اسمبل شود، ماکروهایش تنها برای فایل دیگری که آن را `%include` می‌کند قابل مشاهده‌اند.

در غیر این صورت، فایلی که فقط برای `%include` است می‌تواند هر پسوندی داشته باشد.
استفاده از `.asm` یا `.mac` یک قرارداد رایج است.
