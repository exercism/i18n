# Σχετικά

Μια συνάρτηση είναι [αναδρομική][recursion] όταν καλεί τον εαυτό της.

Μία βασική διαφορά μεταξύ μιας κλήσης συνάρτησης και ενός βρόχου είναι ότι η κλήση μιας συνάρτησης ωθεί στη στοίβα τη διεύθυνση επιστροφής.
Αυτό σημαίνει ότι μια αναδρομική συνάρτηση συνήθως απαιτεί περισσότερο χώρο στη στοίβα από έναν ισοδύναμο βρόχο.

Ως συνέπεια, μια συνάρτηση που συνεχίζει να καλεί τον εαυτό της μπορεί τελικά να εξαντλήσει όλο τον χώρο της στοίβας.
Αυτό ονομάζεται [υπερχείλιση στοίβας][stack-overflow].

Γι' αυτό κάθε αναδρομική συνάρτηση πρέπει να έχει τουλάχιστον μία βασική περίπτωση, δηλαδή μια κατάσταση όπου η συνάρτηση επιστρέφει χωρίς να καλέσει τον εαυτό της.
Κάθε αναδρομική κλήση πρέπει τελικά να φτάσει σε μια βασική περίπτωση.

Για παράδειγμα, η συνάρτηση παραγοντικού `n! = n * (n - 1) * ... * 1` μπορεί να οριστεί αναδρομικά με το `1` ως βασική περίπτωση:

```x86asm
factorial:
    ; the argument `n` is passed on `rdi`
    ; the factorial will be returned on `rax`

    cmp rdi, 1
    jle .base_case     ; base case -> if rdi <= 1, return 1

    push rdi           ; save n
    dec rdi            ; rdi = n - 1
    call factorial     ; recursive call, rax = (n - 1)!
    pop rdi            ; restore n
    imul rax, rdi      ; rax = n * (n - 1)! = n!
    ret
.base_case:
    mov rax, 1
    ret
```

Σημείωσε ότι η `factorial` πρέπει να κάνει `push rdi` πριν την αναδρομή και `pop rdi` μετά.
Αυτό συμβαίνει επειδή χρειάζεται ακόμα το `n` μόλις επιστρέψει η αναδρομική κλήση, για να υπολογίσει το `n * (n-1)!`.

Σημείωσε επίσης ότι η χρήση ενός καταχωρητή που διατηρείται από τον καλούμενο δεν θα έλυνε αυτό το πρόβλημα.

Ακόμα κι αν μια αναδρομική συνάρτηση είναι δυνητικά καλών του εαυτού της, η ίδια είναι καλούμενη από κάποια άλλη συνάρτηση.
Αυτό σημαίνει ότι η συνάρτηση πρέπει επίσης να διατηρεί τους καταχωρητές που διατηρούνται από τον καλούμενο πριν τους χρησιμοποιήσει, και να επαναφέρει την τιμή τους αφού χρησιμοποιηθούν.
Αυτό συνήθως γίνεται με μια ακολουθία `push`/`pop`, όπως έχουμε δει σε μια προηγούμενη έννοια.

Επειδή κάθε πλαίσιο μιας αναδρομικής συνάρτησης, με εξαίρεση τη βασική περίπτωση, είναι επίσης καλών που πρέπει να διατηρήσει τις δικές του τοπικές μεταβλητές, αυτή η ακολουθία `push`/`pop` πρέπει να επαναλαμβάνεται για κάθε πλαίσιο.
Ακόμα κι αν αποθηκεύαμε τη μεταβλητή απευθείας στη στοίβα, χωρίς τη χρήση καταχωρητών, θα κόστιζε πάλι τα ίδια `8` byte ανά πλαίσιο.

Αυτό σημαίνει ότι κάθε αναδρομική κλήση προσθέτει `8` byte στη στοίβα για τη διεύθυνση επιστροφής που ωθεί η `call`, συν `8` byte για κάθε τοπική μεταβλητή που χρειάζεται να αποθηκεύσει.
Η συνάρτηση θα συνεχίσει να προσθέτει αυτά τα byte στη στοίβα σε κάθε πλαίσιο μέχρι να φτάσει στη βασική της περίπτωση.
Μόνο τότε αρχίζει να ξετυλίγεται με την αντίστροφη σειρά, με κάθε αναδρομική κλήση να χρησιμοποιεί τόσα `pop` όσα χρειάζεται και στη συνέχεια ένα `ret`.

Για παράδειγμα, αν η `factorial` καλούνταν με όρισμα `10`, θα καλούσε τον εαυτό της εννέα φορές πριν φτάσει στη βασική περίπτωση του `1`.
Σε εκείνο το σημείο, `144` byte θα είχαν χρησιμοποιηθεί για την αποθήκευση του `n` (`8` byte) και της διεύθυνσης επιστροφής (`8` byte) για κάθε προηγούμενο πλαίσιο.

## Ουριαία Κλήση

Σε ορισμένες περιπτώσεις, μια συνάρτηση δεν εκτελεί άλλη εργασία αφού καλέσει μια άλλη και πριν επιστρέψει.

Σκέψου, για παράδειγμα:

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    call times_three
    ret
```

Η συνάρτηση `triple_of_square`:

- πολλαπλασιάζει το όρισμα που της περνάμε (στο `rdi`) με τον εαυτό του, υπολογίζοντας το τετράγωνό του;
- στη συνέχεια καλεί την `times_three`, η οποία επιστρέφει το τριπλάσιο του ορίσματος που της περνάμε.

Ως αποτέλεσμα, η `triple_of_square` επιστρέφει `3*x²`, όπου `x` είναι το όρισμά της, που περνιέται στο `rdi`.

Σημείωσε ότι δεν εκτελείται καμία εργασία στην `triple_of_square` αφού καλέσει την `times_three`, η συνάρτηση απλώς επιστρέφει.
Σε μια τέτοια περίπτωση, αντί να χρησιμοποιήσει `call`, μια συνάρτηση μπορεί να χρησιμοποιήσει `jmp` και να μεταφέρει την εκτέλεση στη συνάρτηση που καλείται:

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    jmp times_three
```

Αυτό ονομάζεται [ουριαία κλήση][tail].

Το κύριο πλεονέκτημα μιας ουριαίας κλήσης είναι ότι αποφεύγει το επιπλέον κόστος της `call`.
Μια `call` ωθεί μια διεύθυνση επιστροφής στη στοίβα, και για να επιστρέψει ο έλεγχος σε εκείνο το σημείο πρέπει να υπάρχει ένα αντίστοιχο `ret`.

Μια ουριαία κλήση παραλείπει και τα δύο: δεν υπάρχει διεύθυνση επιστροφής να ωθηθεί, ούτε επιπλέον `ret` για να αντιστοιχιστεί, παρά μόνο το `ret` της ίδιας της καλούμενης συνάρτησης.

## Ουριαία Αναδρομή

Μια ουριαία κλήση είναι ιδιαίτερα χρήσιμη για αναδρομικές συναρτήσεις που μπορεί να καλέσουν τον εαυτό τους πολλές φορές πριν επιστρέψουν.

Ωστόσο, δεν μπορεί κάθε αναδρομική κλήση να μετατραπεί άμεσα σε ουριαία κλήση.
Επειδή μια `jmp` μεταφέρει τον έλεγχο στη συνάρτηση που καλείται, ο καλών δεν μπορεί να εκτελέσει άλλη εργασία μετά την ουριαία κλήση.

Για παράδειγμα, η προηγούμενη συνάρτηση `factorial` **δεν** είναι ουριαία αναδρομική.
Μετά την αναδρομική κλήση, χρειάζεται ακόμα να πολλαπλασιάσει το αποτέλεσμα με το τρέχον `n`, χρησιμοποιώντας `imul rax, rdi`.

Σε τέτοιες περιπτώσεις, είναι μερικές φορές δυνατό να χρησιμοποιηθεί ένας συσσωρευτής που θα συλλέγει μερικούς υπολογισμούς και θα επιστρέφεται στο τέλος.
Για παράδειγμα, μπορούμε να ορίσουμε μια `factorial_helper` που κάνει το μεγαλύτερο μέρος της δουλειάς και στη συνέχεια η `factorial` ρυθμίζει έναν συσσωρευτή και μεταφέρει τον έλεγχο στη `factorial_helper`:

```x86asm
factorial_helper:
    ; the argument `n` is passed on `rdi`
    ; `rax` is used as an accumulator and will be returned at the end

    cmp rdi, 1
    jle .base_case

    imul rax, rdi        ; we accumulate the partial result on `rax`
    dec rdi              ; rdi = n - 1
    jmp factorial_helper ; tail call to accumulate (n - 1)!
.base_case:
    ret                  ; returns the factorial already accumulated on `rax`

factorial:
    mov rax, 1           ; initial value for the accumulator
    jmp factorial_helper ; tail call
```

Επειδή δεν εκτελείται άλλη εργασία μετά την αναδρομική κλήση, δεν χρειάζεται πλέον να αποθηκεύουμε το `rdi`.
Δεν υπάρχει `call` ή `push rdi` και έτσι κάθε αναδρομική επανάληψη προσθέτει `0` byte στη στοίβα: δεν χρησιμοποιείται επιπλέον χώρος στη στοίβα.
Αυτή η έκδοση μπορεί να χειριστεί αυθαίρετα μεγάλο `n` χωρίς υπερχείλιση της στοίβας.
Είναι ταυτόχρονα πιο αποδοτική και πιο ασφαλής.

Σε ορισμένες περιπτώσεις, με αναδιάταξη της σειράς των συναρτήσεων, μπορεί να αποφευχθεί ακόμη και η `jmp` προς τη βοηθητική συνάρτηση.
Για παράδειγμα, οι `factorial` και `triple_of_square` μπορούν να ξαναγραφτούν με αυτόν τον τρόπο:

```x86asm
factorial:
    mov rax, 1
factorial_helper:
    cmp rdi, 1
    jle .base_case

    imul rax, rdi
    dec rdi
    jmp factorial_helper
.base_case:
    ret

triple_of_square:
    imul rdi, rdi
times_three:
    imul rax, rdi, 3
    ret
```

Στο παραπάνω απόσπασμα, η εκτέλεση της `factorial` συνεχίζει απευθείας στη `factorial_helper`.
Το ίδιο συμβαίνει με τις `triple_of_square` και `times_three`.
Και στις δύο περιπτώσεις, η εκτέλεση συνεχίζεται διαδοχικά και φαίνεται ότι η συνάρτηση ουράς είναι απλώς μια τοπική ετικέτα μέσα στη "κύρια" συνάρτηση.

Στην πραγματικότητα, δεν υπάρχει ουσιαστική διαφορά μεταξύ οποιασδήποτε τοπικής ετικέτας και μιας συνάρτησης.
Η assembly x86-64 δεν δίνει ειδική μεταχείριση σε καμία από αυτές, είναι απλώς διευθύνσεις σε ένα τμήμα με εκτελέσιμο κώδικα, όπως το `section .text`.

Με αυτόν τον τρόπο, μια ουριαία αναδρομική συνάρτηση μπορεί να θεωρηθεί ουσιαστικά ίδια με έναν βρόχο όπου η αναδρομική κλήση πηδά πίσω στην αρχή, και η βασική περίπτωση είναι η συνθήκη που τερματίζει τον βρόχο.
