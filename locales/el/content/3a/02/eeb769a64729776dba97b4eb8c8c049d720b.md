# Σχετικά

Στις εφαρμογές C# η τυχαιότητα υλοποιείται συνήθως με την κλάση `System.Random`.

Αυτό το [άρθρο][system-random] αποτελεί εξαιρετική εισαγωγή στο θέμα.

Όταν εξοικειώνεσαι με μια κλάση βιβλιοθήκης, αξίζει πάντα να μελετάς την [τεκμηρίωση][system-random] για τις ιδιότητες και τις μεθόδους, καθώς και τις υπερφορτώσεις τους.

Η άσκηση προγραμματισμού ανέδειξε μια σειρά ζητημάτων:

- Η γεννήτρια τυχαίων αριθμών δεν απαιτεί [seed][random-seedless].
- Το `Random.Next()` μπορεί να παράγει ένα εύρος ακεραίων
- Το `Random.Double()` μπορεί να παράγει ένα double μεταξύ 0 και 1
- Τα άνω όρια στα `Next...()`, `Double()` και `Sample()` είναι **αποκλειστικά**, οπότε το `Random.Next(1,19)` θα δώσει τιμές από το 1 έως το 18 αλλά όχι το 19.
- Μόλις αποκτήσεις τον τυχαίο αριθμό σου, μπορείς να κάνεις ό,τι θέλεις με αυτόν

Υπάρχουν 3 μοτίβα για να υλοποιήσεις το τελευταίο σημείο:

- Μπορείς να πάρεις τον τυχαίο αριθμό και να τον επεξεργαστείς. Στην περίπτωση της άσκησης προγραμματισμού, αυτό θα σήμαινε να καλέσεις το `Random.NextDouble()` και να το πολλαπλασιάσεις επί 100. Αυτό το [κείμενο][random-use-case-array] συζητά πώς γίνονται τυχαίες επιλογές από έναν πίνακα.
- Μπορείς να κληρονομήσεις από το `System.Random` και να παρακάμψεις τη μέθοδο `Sample()`.
- Μπορείς να ενσωματώσεις ένα στιγμιότυπο του `System.Random` ως μέλος μιας δικής σου κλάσης, για παράδειγμα [για να παράγεις Boolean][random-use-cases].

Δεν είναι εγγυημένο ότι οι αριθμοί που παράγει το `Random` είναι μοναδικοί.

[Συνιστάται][random-thread-safety] να δημιουργήσεις το `System.Random` ως στατικό μέλος. Πρόσεξε όμως ότι δεν είναι ασφαλές για νήματα.

Μπορεί να δεις τεκμηρίωση που αποθαρρύνει τη χρήση κατασκευαστών χωρίς seed. Αυτό ισχύει κυρίως για το .NET Framework και όχι για το .NET Core (το οποίο χρησιμοποιεί το _Exercism_). Για την πλήρη εικόνα, διάβασε [αυτό][random-multiple-instantiations].

Σου συνιστούμε να μην χρησιμοποιείς το `System.Random` για κρυπτογραφία ή ασφάλεια. Δες αυτόν τον [πάροχο][crypto-provider] και αυτή τη [γεννήτρια αριθμών][crypto-rng].

## Ασφάλεια νημάτων

Όταν χρησιμοποιείται στο πλαίσιο των API βιβλιοθηκών, το "δεν είναι ασφαλές για νήματα" είναι απλώς ένας σύντομος τρόπος να πούμε ότι, αν είναι πιθανό να προσπελαύνεις στιγμιότυπα της κλάσης μέσω πολλαπλών ταυτόχρονων [νημάτων][threading], θα πρέπει να παρέχεις τους δικούς σου μηχανισμούς συγχρονισμού νημάτων ή, στην περίπτωση των συλλογών, να εξετάσεις το ενδεχόμενο να χρησιμοποιήσεις μια ταυτόχρονη έκδοση της κλάσης. Χωρίς αυτές τις προφυλάξεις, είναι πιθανό να προκύψουν [συνθήκες ανταγωνισμού][so-race-conditions]. Αν η βάση κώδικά σου δεν χρησιμοποιεί πολλά νήματα, και δεν πρόκειται να το κάνει, τότε αυτή η προειδοποίηση δεν έχει και μεγάλη σημασία.
