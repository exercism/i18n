# Σχετικά

Τα `String` και `&str` είναι δύο θεμελιώδεις τρόποι για να δουλεύεις με κειμενικά δεδομένα στη Rust.
Το να γνωρίζεις τα χαρακτηριστικά τους και το πώς συνεργάζονται είναι εξαιρετικά χρήσιμο.
Αυτό το κείμενο εξετάζει πώς αλληλεπικαλύπτονται και προσφέρει μερικές βασικές συμβουλές.
Το `String` είναι ένα owned διάνυσμα από bytes `u8`.
Το `String` είναι μεταβλητό.
Το `&str` είναι μια δανεισμένη αναφορά σε ένα slice του String.
Το `&str` είναι αμετάβλητο.

Η σωστή προφορά του `&str` είναι "ref string".
Το `String` είναι μια δυνητικά μεταβλητή, κωδικοποιημένη σε UTF-8 αναπαράσταση μιας ακολουθίας σημείων κώδικα Unicode.

Το `&str` είναι μια όψη μόνο για ανάγνωση μιας καλά σχηματισμένης ακολουθίας UTF-8.
Επειδή είναι μια αναφορά, είναι `Copy` και μπορεί να μοιραστεί.

Τα `String` και `&str` στη Rust δεν μπορούν να δεικτοδοτηθούν όπως ίσως κάνεις σε άλλες γλώσσες.
Για παράδειγμα, αυτό δεν θα δουλέψει:

```rust,invalid
let hello = "Hello";
println!("First letter = {}", hello[0]);
```

Αυτό προκύπτει από τις εξής ιδιότητες:

- Οι συμβολοσειρές είναι UTF-8, η στοιχειώδης μονάδα των οποίων δεν είναι το byte, αλλά ένα σημείο κώδικα Unicode: `char`.
- Τα σημεία κώδικα Unicode έχουν πλάτος έως 4 bytes, αλλά κωδικοποιούνται με μεταβλητό πλάτος.
- Είναι επομένως αδύνατο να υπολογίσεις τη θέση του `n`-οστού σημείου κώδικα χωρίς να διατρέξεις τους πραγματικούς κωδικοποιημένους χαρακτήρες, γιατί μετά τον πρώτο χαρακτήρα, η θέση του επόμενου εξαρτάται από το πόσο πλατιοί ήταν οι προηγούμενοι.
- Οι συγγραφείς της standard library της Rust επέλεξαν λοιπόν να μην υλοποιήσουν το trait `Index` για τις συμβολοσειρές: ενώ το να δεικτοδοτήσεις έναν πίνακα από bytes παίρνει σταθερό χρόνο, το να δεικτοδοτήσεις μια συμβολοσειρά μπορεί να πάρει αρκετά μεγάλο χρόνο. Αυτό παραβιάζει την αρχή της ελάχιστης έκπληξης.

```rust
let example = "I'm not entirely ASCII! ❤";

let n_chars = example.chars().count();
let final_byte = example.as_bytes()[example.len()-1];

println!("n_chars = {}", n_chars);             // 25
println!("example.len() = {}", example.len()); // 27

println!("final char: {}", example.chars().nth(n_chars-1).unwrap()); // ❤
println!("final byte: {final_byte}");                                // 164
println!("char of final byte: {}", final_byte as char);              // ¤
```

## Μετατροπή ενός `String` σε `&str`

Το `String` υλοποιεί το `Deref<Target=str>`.
Αυτό το trait έχει κάποια ειδική μεταχείριση από τον compiler: σημαίνει ότι οποιαδήποτε αναφορά σε ένα `String` μπορεί αυτόματα και διαφανώς να μετατραπεί σε `&str`.
Αυτό συνεπάγεται τα εξής:

- Οποιοσδήποτε κώδικας περιμένει, για παράδειγμα, ένα όρισμα `&str` μπορεί να δεχτεί αντ' αυτού ένα `&String`.
- Οποιαδήποτε μέθοδος υλοποιείται για `&str` μπορεί να κληθεί και σε ένα `String`.

(Αν ήθελες γενικά να μπορείς να δεχτείς οποιαδήποτε μορφή αναφοράς σε ένα `str`, θα μπορούσες να έχεις ένα όρισμα τύπου `impl AsRef<str>`, αλλά συνήθως το να δηλώνεις τα ορίσματα ως `&str` είναι το πιο συνηθισμένο.)

## Μετατροπή ενός `&str` σε `String`

Υπάρχουν πολλοί τρόποι να δημιουργήσεις ένα `String` από ένα `&str`:

- `String::from("my str")`
- `"my str".to_string()`
- `"my str".to_owned()`
- `let s: String = "my str".into();`

Όλοι οι παραπάνω τρόποι απαιτούν δέσμευση μνήμης για το `String` (στη heap).
Γι' αυτό το `&str` είναι διαθέσιμο σε no_std αλλά το `String` όχι.

(Το crate [heapless](https://crates.io/crates/heapless) χρησιμοποιείται συχνά όταν χειρίζεσαι συμβολοσειρές σε no_std.)

## Χρήση των String και `&str` σε structs

Αυτή η ενότητα εξετάζει πότε να χρησιμοποιείς `String` ή `&str` για πεδία struct.
Συχνά θα δεις structs ορισμένα με `String` αντί για `&str` για τις τιμές των πεδίων.

```rust
struct Record {
    latitude: f64,
    longitude: f64,
    population: Option<u64>,
    city: String,
    state: String,
}
```

Χρησιμοποιώντας `String`, το struct κατέχει τα δεδομένα.
Αυτό κάνει τον κώδικα πιο ευανάγνωστο και πιο εύκολο να τον διδάξεις σε αρχάριους.
Σημαίνει όμως επίσης ότι θα γίνονται δεσμεύσεις μνήμης στη heap για κάθε πεδίο.
Το `&str` δανείζεται τα κειμενικά δεδομένα, οπότε θα αποδώσει καλύτερα, με το τίμημα το struct σου να χρειάζεται να ορίσει παραμέτρους διάρκειας ζωής.
Το [csv crate tutorial][csv-tutorial] παρουσιάζει και εξηγεί αυτές τις ιδέες στην πράξη αρκετά καλά.

## Σημειώσεις απόδοσης

Τα `String` δεσμεύονται στη heap, οπότε η χρήση τους μπορεί να είναι πιο δαπανηρή.
Τα `&str` είναι μια κοινόχρηστη αναφορά και άρα δεν απαιτούν συχνές εκ νέου δεσμεύσεις.
