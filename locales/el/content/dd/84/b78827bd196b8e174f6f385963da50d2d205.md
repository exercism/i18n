# Εισαγωγή

Οι έξυπνοι δείκτες είναι μια σύγχρονη δυνατότητα της C++ που έχει σχεδιαστεί για να παρέχει αυτόματη διαχείριση μνήμης, βοηθώντας στην αποφυγή των διαρροών μνήμης και των εκκρεμών δεικτών που συνήθως συνδέονται με τους ακατέργαστους δείκτες.
Λειτουργούν ως περιτυλίγματα γύρω από ακατέργαστους δείκτες, προσθέτοντας επιπλέον λειτουργικότητα, όπως αυτόματη αποδέσμευση μνήμης όταν ο δείκτης δεν χρειάζεται πια.

## Γενική σύνταξη

Οι έξυπνοι δείκτες υλοποιούνται συνήθως ως πρότυπα κλάσεων στην πρότυπη βιβλιοθήκη της C++.
Οι δύο πιο συνηθισμένοι έξυπνοι δείκτες είναι οι `std::unique_ptr` και `std::shared_ptr`.

## Μοναδικοί δείκτες

Ο `std::unique_ptr` είναι ένας έξυπνος δείκτης που κατέχει το αντικείμενο αποκλειστικά.
Διασφαλίζει ότι ανά πάσα στιγμή μόνο ένα αντικείμενο `std::unique_ptr` κατέχει τον πόρο.
Όταν ο `std::unique_ptr` που κατέχει τον πόρο καταστραφεί ή γίνει reset, καταστρέφει αυτόματα τα αντικείμενα και απελευθερώνει τη μνήμη του.

```cpp
#include <memory>
// Declaring and defining a unique pointer
auto rightful_king_of_england = std::make_unique<std::string>("Excalibur");

// Unique pointers cannot be copied or assigned
auto mordred = rightful_king_of_england; // Error: Cannot copy a unique_ptr
```

## Πλεονεκτήματα του `std::make_unique()`

Όταν δημιουργείς ένα `std::unique_ptr`, είναι προτιμότερο να χρησιμοποιείς το `std::make_unique()` αντί να χρησιμοποιείς απευθείας το `new` για να δεσμεύσεις μνήμη.
Το `std::make_unique()` προσφέρει αρκετά πλεονεκτήματα:
1. **Ασφάλεια έναντι εξαιρέσεων**: Το `std::make_unique()` εγγυάται ασφάλεια έναντι εξαιρέσεων.
  Αν πεταχτεί μια εξαίρεση κατά την κατασκευή του αντικειμένου, η μνήμη θα αποδεσμευτεί αυτόματα, αποτρέποντας τις διαρροές μνήμης.
2. **Σαφήνεια**: Η χρήση του `std::make_unique()` κάνει τον κώδικα πιο σαφή και πιο συνοπτικό.
  Εξαλείφει την ανάγκη να προσδιορίζεις ρητά τον τύπο που δεσμεύεται, αφού τα ορίσματα προτύπου συνάγονται αυτόματα.
3. **Ευκαιρίες βελτιστοποίησης**: Οι μεταγλωττιστές έχουν τη δυνατότητα να βελτιστοποιήσουν το `std::make_unique()` πιο αποτελεσματικά από ό,τι τη χειροκίνητη δέσμευση μνήμης με το `new`, κάτι που μπορεί να οδηγήσει σε καλύτερες επιδόσεις.
4. **Αποφυγή κακής χρήσης**: Είναι δυνατό να διαγράψεις τον υποκείμενο πόρο, όταν το `std::unique_ptr` κατασκευαστεί χειροκίνητα.
  Αυτό θα οδηγούσε σε απροσδιόριστη συμπεριφορά, όταν το `std::unique_ptr` προσπαθήσει να τον διαγράψει στο τέλος της εμβέλειάς του.

## Κοινόχρηστοι δείκτες

Ο `std::shared_ptr` είναι ένας έξυπνος δείκτης που επιτρέπει σε πολλά αντικείμενα `std::shared_ptr` να μοιράζονται την κυριότητα του ίδιου πόρου.
Παρακολουθεί πόσοι κοινόχρηστοι δείκτες αναφέρονται στον πόρο και αποδεσμεύει τη μνήμη μόνο όταν ο τελευταίος κοινόχρηστος δείκτης που κατέχει τον πόρο βγει από την εμβέλεια ή γίνει reset.

```cpp
// Declaring and defining a shared pointer to a dynamically allocated string
auto martian_congressional_republic = std::make_shared<std::string>("protomolecule");

// Creating more shared pointer that shares ownership
auto outer_planets_alliance = martian_congressional_republic;
auto united_nations = martian_congressional_republic;
```

~~~~exercism/caution
Στην C++17 και σε προηγούμενες εκδόσεις, η χρήση του `std::shared_ptr` με πίνακες μέσω `std::make_shared<T[]>` δεν υποστηρίζεται άμεσα.
Αν και είναι δυνατό να δεσμεύσεις πίνακες με `std::make_shared<T[]>`, η δημιουργία κοινόχρηστων δεικτών απευθείας από αυτούς μπορεί να οδηγήσει σε απροσδιόριστη συμπεριφορά, λόγω των διαφορών στη διαχείριση μνήμης ανάμεσα σε μεμονωμένα αντικείμενα και σε πίνακες.
Αντ' αυτού, σκέψου να χρησιμοποιήσεις `std::vector` ή προσαρμοσμένες συναρτήσεις διαγραφής για να διαχειρίζεσαι αποτελεσματικά πίνακες με κοινόχρηστους δείκτες.
Να διασφαλίζεις πάντα τη συμβατότητα με τον μεταγλωττιστή και την υλοποίηση της πρότυπης βιβλιοθήκης σου, όταν ασχολείσαι με δεσμεύσεις πινάκων και κοινόχρηστους δείκτες στην C++17.
~~~~

## Πλεονεκτήματα του `std::make_shared()`

Όπως το `std::make_unique()`, έτσι και το `std::make_shared()` προσφέρει οφέλη όπως βελτιωμένη αποδοτικότητα μνήμης, ασφάλεια έναντι εξαιρέσεων και αναγνωσιμότητα.
Συνδυάζει τη δέσμευση μνήμης για το μπλοκ ελέγχου και για το διαχειριζόμενο αντικείμενο σε μία μόνο λειτουργία, βελτιώνοντας την αποδοτικότητα και μειώνοντας τον κίνδυνο διαρροών μνήμης.
Επιπλέον, η αυτόματη συναγωγή των ορισμάτων προτύπου απλοποιεί τον κώδικα και ενισχύει την αναγνωσιμότητα.
Η χρήση του `std::make_shared()` προωθεί καθαρότερο, ασφαλέστερο και πιο αποδοτικό κώδικα όταν δουλεύεις με αντικείμενα `std::shared_ptr` στην C++.

## Αδύναμοι δείκτες

Ο `std::weak_ptr` είναι μια συνοδευτική κλάση του `std::shared_ptr` που παρέχει μια μη κατέχουσα, "αδύναμη" αναφορά σε ένα αντικείμενο που διαχειρίζεται ένας κοινόχρηστος δείκτης.

```cpp
// Creating a shared pointer
auto your_account = std::make_shared<std::string>("secret_subscription_password");
// Creating a shared pointer that shares ownership
auto your_flatmates_account = your_account;

// Creating a weak pointer from the shared pointer
auto your_flatmates_boyfriends_account = your_flatmates_account;
// if your_account and your_flatmates_account are deleted, there is no more reference to the shared pointer.
// your_flatmates_boyfriends_account will be a null pointer and cannot use the associated object any longer.
```

Οι αδύναμοι δείκτες είναι χρήσιμοι σε περιπτώσεις όπου πρέπει να σπάσουν κυκλικές αναφορές για να αποτραπούν οι διαρροές μνήμης.
Ο `std::weak_ptr` σχεδιάστηκε για να αντιμετωπίσει το ζήτημα της κυκλικής κυριότητας, γνωστό και ως κυκλικές αναφορές, που μπορεί να προκύψει όταν χρησιμοποιείς `std::shared_ptr`.
Σε ένα σενάριο κυκλικής κυριότητας, δύο ή περισσότερα αντικείμενα `std::shared_ptr` αναφέρονται μεταξύ τους, δημιουργώντας έναν κύκλο όπου κανένα από τα αντικείμενα δεν μπορεί να διαγραφεί, επειδή έχουν ισχυρές αναφορές μεταξύ τους, κάτι που οδηγεί σε διαρροές μνήμης.
Ο `std::weak_ptr` προσφέρει μια λύση σε αυτό το πρόβλημα, επιτρέποντας αδύναμες αναφορές σε κοινόχρηστα αντικείμενα χωρίς να συμβάλλει στο πλήθος αναφορών τους.
Αυτό σημαίνει ότι μπορεί να παρατηρήσει και να προσπελάσει το κοινόχρηστο αντικείμενο, αλλά δεν εμποδίζει τη διαγραφή του.
~~~~

## Συμβουλές χρήσης

Χρησιμοποίησε έξυπνους δείκτες εξ ορισμού: `std::unique_ptr` για αποκλειστική κυριότητα και `std::shared_ptr` για κοινή κυριότητα.
Κράτησε τους ακατέργαστους δείκτες για μη κατέχουσες αναφορές ή όταν συνεργάζεσαι με παλιό κώδικα.
Στις περισσότερες περιπτώσεις, ο `std::unique_ptr` αρκεί για αποκλειστική κυριότητα, καθώς προσφέρει ελαφριά διαχείριση μνήμης χωρίς το κόστος της μέτρησης αναφορών.
Χρησιμοποίησε τον `std::shared_ptr` με φειδώ, καθώς εισάγει επιπλέον κόστος και πολυπλοκότητα, εκτός αν χρειάζεσαι πραγματικά κοινή κυριότητα.
Ο `std::weak_ptr` είναι εξειδικευμένος για το σπάσιμο κυκλικών εξαρτήσεων ή την παρατήρηση κοινόχρηστων αντικειμένων, αλλά δεν χρησιμοποιείται συχνά.
