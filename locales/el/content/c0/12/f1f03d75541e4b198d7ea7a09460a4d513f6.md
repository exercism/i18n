# Σχετικά

Το `<dlist>` (στο [`dlists`][dlists]) κατασκευάζει μια νέα διπλά συνδεδεμένη
λίστα. Οι πράξεις βρίσκονται στο [`deques`][deques] και κάνουν dispatch στο
[deque protocol][deque-protocol], ώστε και άλλα containers, κυρίως το `<dlist>`,
να μπορούν να τις υλοποιήσουν.

| λέξη            | αποτέλεσμα                              |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )`: νέα κενή deque  |
| `push-front`    | `( elt deque -- )`: προσθήκη στο μπροστινό μέρος |
| `push-back`     | `( elt deque -- )`: προσθήκη στο πίσω μέρος  |
| `pop-front`     | `( deque -- elt )`: αφαίρεση από το μπροστινό μέρος |
| `pop-back`      | `( deque -- elt )`: αφαίρεση από το πίσω μέρος  |
| `peek-front`    | `( deque -- elt )`: διάβασε το μπροστινό μέρος χωρίς να το αφαιρέσεις |
| `peek-back`     | `( deque -- elt )`: διάβασε το πίσω μέρος χωρίς να το αφαιρέσεις  |
| `deque-empty?`  | `( deque -- ? )`: είναι η deque κενή; |
| `dlist-length`  | `( dlist -- n )`: πλήθος στοιχείων |

Όλες οι πράξεις push/pop μεταβάλλουν τη deque επί τόπου: το να περνάς μια
deque σε μια ρουτίνα και μετά να τη διαβάζεις ξανά είναι το συνηθισμένο
μοτίβο.

## Στοίβα εναντίον ουράς

Δύο συμβατικά μοτίβα dispatch:

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

Ένα vector με `push` και `pop` (από το `mutation`) είναι η σωστή επιλογή όταν
το μόνο που χρειάζεσαι είναι η σειρά LIFO, αφού το `<dlist>` κουβαλάει το
βάρος μιας συνδεδεμένης λίστας. Προτίμησε το `<dlist>` όταν χρειάζεσαι O(1)
και στα *δύο* άκρα, σχεδόν πάντα για μια ουρά FIFO.

## Μοτίβο BFS

Η αναζήτηση κατά πλάτος είναι η κλασική περίπτωση χρήσης FIFO:

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

Η deque κουβαλάει το μέτωπο της αναζήτησης. Το hash-set κρατάει την απαλοιφή
διπλοτύπων. Άλλαξε το `pop-front` με το `pop-back` και το ίδιο σχήμα γίνεται
αναζήτηση κατά βάθος.

## `MEMO:` για αυτόματο caching

Μερικές φορές η αναζήτηση ανά κόμβο που καλεί το BFS είναι ακριβή. Το Factor
παρέχει το [`MEMO:`][memo-decl], έναν αντικαταστάτη του `:` που αποθηκεύει
αυτόματα το αποτέλεσμα της λέξης με κλειδί τις εισόδους της:

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

Μια λέξη `MEMO:` εκτελεί το σώμα της την πρώτη φορά που βλέπει κάθε είσοδο
και από εκεί και πέρα επιστρέφει το αποθηκευμένο αποτέλεσμα. Η cache ζει για
όλη τη διάρκεια ζωής του image. Δεν υπάρχει αποβολή με βάση τον χρόνο ή το
μέγεθος. Χρησιμοποίησέ το για καθαρές συναρτήσεις των οποίων οι είσοδοι
προέρχονται από ένα πεπερασμένο, διαχειρίσιμο σύνολο.
