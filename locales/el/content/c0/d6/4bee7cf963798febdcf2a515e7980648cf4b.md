# Εισαγωγή

Ο χειρόγραφος κώδικας assembly είναι γεμάτος επαναλήψεις.
Η ίδια σύντομη ακολουθία εντολών εμφανίζεται ξανά και ξανά, με ελάχιστες παραλλαγές, και υπάρχουν λίγες αφαιρέσεις για να μειώσουν τον τυποποιημένο κώδικα.
Και όχι μόνο αυτό: ο προγραμματισμός σε assembly απαιτεί να διαχειρίζεσαι τιμές χωρίς προφανή σημασιολογία.
Δεν υπάρχουν ονομασμένες παράμετροι και τις περισσότερες λεπτομέρειες του υποκείμενου μηχανισμού πρέπει να τις χειρίζεται με το χέρι ο προγραμματιστής.

Ο NASM, ο συμβολομεταφραστής που χρησιμοποιεί το track, προσφέρει κάποια εργαλεία που μπορούν να βοηθήσουν τον προγραμματιστή και στα δύο προβλήματα.
Αυτά τα εργαλεία εκτελούνται *τη στιγμή της συμβολομετάφρασης*, πριν φτάσει οποιαδήποτε εντολή στον επεξεργαστή.
Καθοδηγούν τον συμβολομεταφραστή στο πώς να ξαναγράψει το κείμενο του πηγαίου κώδικα, πριν αυτό μεταφραστεί ακόμη και σε κώδικα μηχανής.

Το πιο σημαντικό από αυτά τα εργαλεία είναι οι **μακροεντολές**, που μπορούμε να τις σκεφτούμε σαν μια συνταγή για τον συμβολομεταφραστή.
Επεκτείνονται στο σημείο όπου χρησιμοποιούνται, σαν να είχε γραφτεί εκεί ο κώδικας με το χέρι.

Οι μακροεντολές μπορούν να δεχτούν έναν αριθμό από literal tokens ως παραμέτρους, κάνοντάς τες επαναχρησιμοποιήσιμες σε διαφορετικά πλαίσια.
Ωστόσο, δεν είναι συναρτήσεις: δεν υπάρχει `call`, δεν υπάρχει `ret`, δεν υπάρχει μεταφορά του ελέγχου σε άλλο σημείο του κώδικα.

## Μακροεντολές μίας γραμμής

Ο πιο απλός ορισμός δίνει ένα όνομα σε μια τιμή ή σε μια σύντομη έκφραση με το `%define`:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Κάθε επόμενη εμφάνιση του `WIDTH` αντικαθίσταται από το `8` πριν από τη συμβολομετάφραση.
Η αντικατάσταση είναι κειμενική, οπότε το όνομα υποκαθίσταται όπου κι αν εμφανίζεται, είτε σε έναν τελεστέο είτε μέσα σε έναν άλλο ορισμό.

~~~~exercism/note
Για αριθμητικές *σταθερές*, προτίμησε το `equ` αντί για το `%define`.

Μια μακροεντολή μίας γραμμής που δηλώνεται με `%define` επεκτείνεται μόνο όταν χρησιμοποιηθεί, και μπορεί να επαναοριστεί ή να της αφαιρεθεί ο ορισμός.
Μια σταθερά `equ`, αντίθετα, αξιολογείται στο σημείο του ορισμού της και δεν τροποποιείται ποτέ.
~~~~

Ένα `%define` μπορεί επίσης να δεχτεί *ονομασμένες* παραμέτρους, συμπεριφερόμενο σαν μια μικρή συνάρτηση inline:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Βάλε σε παρενθέσεις και ολόκληρο το σώμα και κάθε παράμετρο.
Με το `%define square(x) x*x`, η κλήση `square(1+1)` επεκτείνεται σε `1+1*1+1`, που είναι `3`.
Γραμμένο ως `%define square(x) ((x)*(x))`, η ίδια κλήση επεκτείνεται σε `((1+1)*(1+1))`, που είναι `4`.
~~~~

Τα ονόματα που ορίζονται με `%define` κάνουν διάκριση πεζών-κεφαλαίων.
Η παραλλαγή `%idefine` κάνει το όνομα να μη διακρίνει πεζά-κεφαλαία, αν αυτό είναι επιθυμητό.

Οι μακροεντολές μίας γραμμής είναι χρήσιμες για να δίνουν νόημα σε διάφορα σημεία του κώδικα.
Αν χρησιμοποιηθούν με προσοχή, βελτιώνουν την αναγνωσιμότητα και μειώνουν την πιθανότητα τυπογραφικών λαθών.
Για παράδειγμα, ένας καταχωρητής που έχει έναν συγκεκριμένο σκοπό μέσα σε μια συνάρτηση μπορεί να οριστεί με βάση τον σκοπό του:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Μακροεντολές πολλών γραμμών

Μια ολόκληρη ακολουθία κώδικα, με οποιονδήποτε αριθμό γραμμών, συλλαμβάνεται με το `%macro` και κλείνει με το `%endmacro`.
Ένας αριθμός μετά το όνομα δείχνει πόσα ορίσματα δέχεται η μακροεντολή, που μπορεί να είναι μηδέν.
Όταν περνιούνται ορίσματα, χωρίζονται με κόμμα (`,`):

```x86asm
%macro example_macro 0
...
%endmacro
```

Τα ορίσματα στις μακροεντολές πολλών γραμμών δεν έχουν ονόματα.
Αναφέρονται ως `%1`, `%2` και ούτω καθεξής, με τη σειρά που περνιούνται:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Σημείωσε ότι τα ορίσματα πρέπει να έχουν έγκυρη σύνταξη για τις πράξεις που εκτελούνται στο σώμα της μακροεντολής.
Εδώ, τα `mult_two eax, ecx` και `mult_two r8, r9` μεταφράζονται κανονικά, αλλά το `mult_two eax, cl` όχι, αφού το `imul eax, cl` δεν ορίζεται.

### Ετικέτες μέσα σε μια μακροεντολή

Μια μακροεντολή που ορίζει μια συνηθισμένη ετικέτα χαλάει τη στιγμή που θα χρησιμοποιηθεί δεύτερη φορά, γιατί τότε η ετικέτα θα οριστεί κι αυτή δύο φορές.
Για να χρησιμοποιήσεις ετικέτες μέσα σε μια μακροεντολή που μπορεί να κληθεί πάνω από μία φορά, πρέπει να βάλεις μπροστά από μια τέτοια ετικέτα το `%%`.
Αυτό λέει στον συμβολομεταφραστή να δώσει σε αυτή την ετικέτα ένα διαφορετικό, μοναδικό όνομα σε κάθε επέκταση:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Επανάληψη τη στιγμή της συμβολομετάφρασης

Μπορείς να επαναλάβεις ένα μπλοκ κώδικα μίας γραμμής χρησιμοποιώντας το `times`.
Αυτό είναι ιδιαίτερα χρήσιμο όταν δηλώνεις επαναλαμβανόμενες τιμές στη μνήμη:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Για επανάληψη κώδικα πολλών γραμμών, μπορούμε αντ' αυτού να χρησιμοποιήσουμε το `%rep`:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Σημείωσε ότι ο αριθμός των επαναλήψεων δίνεται αμέσως μετά το `%rep` και υπάρχει ένα `%endrep` που κλείνει το επαναλαμβανόμενο μπλοκ.

Συνηθίζεται να χρησιμοποιείται ένας μετρητής χρόνου συμβολομετάφρασης μέσα σε ένα μπλοκ `%rep`, όπως ακριβώς ένας βρόχος χρόνου εκτέλεσης χρησιμοποιεί έναν μετρητή.
Ενώ μια ακέραια σταθερά χρόνου συμβολομετάφρασης μπορεί να δηλωθεί με `equ`, για ακέραιες *μεταβλητές* χρόνου συμβολομετάφρασης χρησιμοποιούμε αντ' αυτού το `%assign`.
Σε αντίθεση με το `%define`, το `%assign` αξιολογείται αμέσως σε έναν αριθμό και μπορεί να επαναοριστεί:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Αφού εκτελεστεί ο προεπεξεργαστής, ο βρόχος εξαφανίζεται και μένουν τέσσερις εντολές `add`, με τις άμεσες τιμές `0`, `1`, `2` και `3` ενσωματωμένες.
Αυτό είναι ξετύλιγμα βρόχου που κάνει ο συμβολομεταφραστής: ούτε καταχωρητής μετρητή ούτε διακλάδωση, μόνο ευθύγραμμος κώδικας.

## Υπό συνθήκη συμβολομετάφραση

Υπάρχουν διάφορες δομές υπό συνθήκη διαθέσιμες στον προεπεξεργαστή.
Επιλέγουν ανάμεσα σε έναν αριθμό διαφορετικών διαδρομών, επεκτείνοντας το σώμα τους επί τόπου, αλλά μόνο όταν η συνθήκη τους είναι αληθής.

Τα `%if` ... `%elif` ... `%else` ... `%endif` επιλέγουν έναν κλάδο με βάση έναν αριθμητικό έλεγχο:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

## Χωρισμός σε αρχεία

Οι μακροεντολές συχνά κρατιούνται σε δικό τους αρχείο και τραβιούνται σε κάθε πηγαίο αρχείο που τις χρειάζεται με το `%include`:

```x86asm
%include "patterns.mac"
```

Το αρχείο που ονομάζεται εισάγεται αυτούσιο σε εκείνο το σημείο, πριν από τη συμβολομετάφραση, ακριβώς σαν να είχε πληκτρολογηθεί το περιεχόμενό του εκεί.
Έτσι οι ορισμοί μένουν σε ένα σημείο και πολλά πηγαία αρχεία μπορούν να τους μοιράζονται.

Αν το αρχείο μακροεντολών μπορεί να συμβολομεταφραστεί και ως αυτόνομο αρχείο, θα πρέπει να έχει κατάληξη αρχείου `.asm`.
Σημείωσε ότι οι μακροεντολές δεν έχουν σύνδεση.
Ακόμη κι αν το αρχείο μακροεντολών συμβολομεταφραστεί, οι μακροεντολές του είναι ορατές μόνο σε ένα άλλο αρχείο που το κάνει `%include`.

Σε αντίθετη περίπτωση, ένα αρχείο που προορίζεται μόνο για `%include` μπορεί να έχει οποιαδήποτε κατάληξη αρχείου.
Η χρήση είτε του `.asm` είτε του `.mac` είναι μια συνηθισμένη σύμβαση.
