# Σχετικά

Σε πολλές αντικειμενοστρεφείς γλώσσες, είναι σύνηθες να επεκτείνεις συμπεριφορές δημιουργώντας [υποκλάσεις][wiki-subclass] μιας γονικής κλάσης, κληρονομώντας μεθόδους από τη γονική κλάση και προσθέτοντας παράλληλα νέες.
Έτσι προκύπτει μια ιεραρχία αντικειμένων.

Η Julia _δεν έχει κλάσεις_, άρα κατ' επέκταση _δεν έχει και υποκλάσεις_.
Πώς κληρονομούμε και επεκτείνουμε υπάρχουσες συμπεριφορές;

Σε προηγούμενες έννοιες είδαμε πώς να δημιουργούμε μια ιεραρχία τύπων, και μάθαμε πώς η Julia χρησιμοποιεί την [πολλαπλή αποστολή][concept-multiple-dispatch] για να επιλέγει μεθόδους με βάση τους τύπους των ορισμάτων.

Η Julia έχει επίσης αρκετές ανεπίσημες [διεπαφές][ref-interfaces], που επιτρέπουν στους προσαρμοσμένους τύπους σου να συνδεθούν με συμπεριφορές που έχουν ήδη οριστεί για τους βασικούς τύπους.

Ο πιο απλός τρόπος να το δείξουμε αυτό είναι με τη διεπαφή Iterator.

## [Επαναλήπτες][ref-iterators]

Προηγουμένως στο πρόγραμμα σπουδών, έχουμε δει αρκετούς τρόπους με τους οποίους η Julia μπορεί να επεξεργαστεί κάθε στοιχείο μιας συλλογής.

- [Βρόχοι][concept-loops], όπως `for item in items...`
- [Broadcasting][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Συναρτήσεις ανώτερης τάξης][concept-hof]: `map(√, [1, 4, 9])`
- [Κατανοήσεις λιστών][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Γεννήτριες][concept-comprehensions]: `(x^2 for x in 1:1e6)`, που αξιολογείται οκνηρά.

Είναι προφανές ότι η Julia ξέρει να διατρέχει τις βασικές συλλογές στοιχείο προς στοιχείο: διανύσματα και εύρη στα παραπάνω παραδείγματα, καθώς και Sets, Dicts κ.λπ.

Πώς προσθέτουμε αυτή τη δυνατότητα στις δικές μας προσαρμοσμένες συλλογές, ειδικά αν μπορούν να διατρέχονται οκνηρά όπως μια γεννήτρια;

### Ελάχιστες απαιτήσεις

Για να δημιουργήσουμε μια ακολουθία προς επανάληψη, χρειαζόμαστε (τουλάχιστον) δύο πράγματα:

1. Έναν τρόπο να πάρουμε το _πρώτο_ στοιχείο.
2. Έναν τρόπο να πάρουμε το _επόμενο_ στοιχείο από την τρέχουσα κατάσταση.

Η Julia πετυχαίνει αυτούς τους στόχους με μεθόδους της συνάρτησης `Base.iterate()`, ακολουθώντας τα εξής βήματα:

1. Η `Base.iterate(iter)` καλείται αυτόματα πρώτη.
    - Αν δεν υπάρχει τίποτα να διατρέξουμε, επιστρέφει `nothing`.
    - Αλλιώς, επιστρέφει το `Tuple` που περιέχει το πρώτο στοιχείο και την πρώτη κατάσταση: `(firstitem, firststate)`.
2. Η `Base.iterate(iter, state)` καλείται αυτόματα αν επιστράφηκε ένα στοιχείο στην προηγούμενη επανάληψη, παίρνοντας το `firststate` ως όρισμα `state`.
    - Αν η επανάληψη τερματιστεί, επιστρέφει `nothing`.
    - Αλλιώς, επιστρέφει το `Tuple` που περιέχει το επόμενο στοιχείο και την επόμενη κατάσταση: `(nextitem, nextstate)`.
3. Επαναλαμβάνει το βήμα 2 μέχρι τον τερματισμό.

Όλα αυτά τα βήματα γίνονται "στο παρασκήνιο", δηλαδή οι κλήσεις μεθόδων και η κατάσταση διαχειρίζονται εσωτερικά από το πρωτόκολλο επανάληψης (με την κατάσταση να παραμένει αδιαφανής), και μόνο το στοιχείο εκτίθεται σε δομές υψηλού επιπέδου, όπως οι βρόχοι.
Με άλλα λόγια, βλέπουμε πάντα μόνο το `item`, ενώ όλα τα υπόλοιπα παραμένουν σε ένα μαύρο κουτί.

Η [πολλαπλή αποστολή][concept-multiple-dispatch] είναι κεντρική σε αυτό.
Ο τύπος του `iter` καθορίζει ποιες μέθοδοι καλούνται, και ο αριθμός των ορισμάτων καθορίζει αν επιστρέφεται το πρώτο ή το επόμενο στοιχείο.

Οι μέθοδοι για τους βασικούς τύπους έχουν ήδη οριστεί: `Vector`, `Range`, `Set` κ.λπ. ([επί του παρόντος][ref-iterations-collections] 14 τύποι συνολικά).

Για να μοιραστεί ένας προσαρμοσμένος τύπος `MyType` τις ίδιες συμπεριφορές, πρέπει πρώτα να ορίσουμε:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Όλα αυτά ακούγονται μάλλον μπερδεμένα στη θεωρία, αλλά μπορεί να είναι αρκετά απλά.
Για παράδειγμα, φαντάσου ότι θέλουμε έναν τύπο που δίνει τις δυνάμεις ενός δεδομένου ακέραιου `n`, μέχρι έναν μέγιστο αριθμό.

Πρώτα, όρισε έναν προσαρμοσμένο τύπο:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Μπορούμε τώρα να ορίσουμε τις μεθόδους `iterate` για αυτόν τον τύπο, αλλά ποιο είναι το πρώτο στοιχείο και ποια η πρώτη κατάσταση;

Για να πάρουμε το πρώτο στοιχείο, ορισμένοι επαναλήπτες χρειάζονται περίπλοκη προετοιμασία, αλλά σε αυτό το απλοϊκό παράδειγμα παρατηρούμε ότι το πρώτο στοιχείο που επιστρέφεται είναι απλώς ο βασικός αριθμός, οπότε αρκεί να ελέγξουμε αν η τιμή του `count` είναι μεγαλύτερη ή ίση με ένα.

Τώρα μπορούμε να εξετάσουμε την πρώτη κατάσταση, που μεταφέρει πληροφορίες οι οποίες χρησιμοποιούνται στην επόμενη επανάληψη.
Εξαρτάται από εσένα να αποφασίσεις ποιες πληροφορίες πρέπει να παρακολουθείς για να το κάνεις αυτό, και μπορεί να είναι οποιουδήποτε τύπου.

Σε αυτή την περίπτωση, θα μπορούσαμε απλώς να παρακολουθούμε τη "θέση" στην οποία υψώνουμε το `n`, ή να βρούμε μια πιο αποδοτική λύση χρησιμοποιώντας την πιο πρόσφατη δύναμη του `n` (δηλαδή το στοιχείο που επιστράφηκε) και την επόμενη "θέση" στην ακολουθία.
Αυτοί οι δύο αριθμοί μπορούν να τυλιχτούν σε ένα `Tuple` και να επιστραφούν ως `state`.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

Σε αυτό το παράδειγμα, το πρώτο στοιχείο (`p.n`) επιστρέφεται στον βρόχο και η πρώτη κατάσταση `(p.n, 2)` περνά στη μέθοδο `iterate(P::Powers, state)`.
Εκεί μπορούμε να επεξεργαστούμε την κατάσταση για να παράγουμε το επόμενο στοιχείο, πολλαπλασιάζοντας το τρέχον στοιχείο με τον βασικό αριθμό και αυξάνοντας έτσι τη δύναμή του κατά `1`.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Αν η τιμή της θέσης είναι ακόμα εντός του `count`, επιστρέφεται το `Tuple` με το στοιχείο `next` και την αυξημένη κατάσταση `(next, index + 1)`.
Όταν η τιμή του `index` ξεπερνά το `count`, τότε επιστρέφεται `nothing`, για να δηλώσει ότι η επανάληψη τερματίστηκε.

Ίσως έχεις παρατηρήσει ότι οι μέθοδοι `iterate(p::Powers)` και `iterate(p::Powers, state)` έχουν αρκετά παρόμοια σώματα συναρτήσεων.
Στην πραγματικότητα, αν είμαστε έξυπνοι, αυτή η ομοιότητα επιτρέπει μια απλοποιημένη υλοποίηση χρησιμοποιώντας μόνο την έκδοση με τα δύο ορίσματα και μια προεπιλεγμένη τιμή για την κατάσταση: `Base.iterate(p::Powers, state=(1, 1))`
Έτσι, δεν θα χρειαζόμασταν την ξεχωριστή `iterate(p::Powers)` με ένα όρισμα.
Αυτό γίνεται συχνά στην πράξη, όταν είναι εφικτό.

~~~~exercism/advanced
Όταν παρουσιάσαμε τα προαιρετικά ορίσματα στην έννοια [Συναρτήσεις][concept-functions], δεν ειπώθηκε τίποτα για την υλοποίηση.

Από τότε, μάθαμε για την πολλαπλή αποστολή, οπότε τώρα βγάζει περισσότερο νόημα να ξέρουμε ότι η Julia μετατρέπει αυτόματα μια συνάρτηση _με_ προαιρετικά ορίσματα σε πολλαπλές μεθόδους _χωρίς_ προαιρετικά ορίσματα.

Ο ορισμός του `Base.iterate(P::Powers, state=(1, 1))` είναι ακριβώς ισοδύναμος με τον ξεχωριστό ορισμό τόσο του `Base.iterate(P::Powers, state)` όσο και του `Base.iterate(P::Powers)`.

[concept-functions]: https://exercism.org/tracks/julia/concepts/functions
~~~~

Μέχρι στιγμής, έχουμε ήδη κάποια χρήσιμη λειτουργικότητα: για τις πρώτες 4 δυνάμεις του 3, μπορούμε να διατρέξουμε τα αποτελέσματα με έναν βρόχο, να ελέγξουμε αν ένας δεδομένος αριθμός βρίσκεται στα αποτελέσματα και να εφαρμόσουμε συναθροιστικές συναρτήσεις όπως η `sum()`.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Επιπλέον μέθοδοι

Παρά την καλή αρχή, δεν λειτουργούν ακόμα όλα.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers)
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Πράγματι, η `length(Powers(3, 4))` δίνει ακριβώς το ίδιο μήνυμα σφάλματος.

Αυτό διορθώνεται εύκολα, καθώς το μήκος είναι μέρος του κατασκευαστή τύπου: 4 σε αυτή την περίπτωση.
Αρκεί να ορίσουμε τη `Base.length()` για αυτόν τον τύπο, και μετά μπορούμε να χρησιμοποιήσουμε κατανοήσεις και `collect()` στην ακολουθία.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Για λόγους αποδοτικότητας, είναι καλύτερο να ορίσουμε και τη `Base.eltype()`: τον τύπο στοιχείου του αποτελέσματος.
Αυτό επιτρέπει σε συναρτήσεις όπως η `collect()` να προδεσμεύσουν χώρο για το `Vector{Int}` εξόδου, αντί να κάνουν επανειλημμένα `push!()` σε ένα `Vector{Any}`.

Πρόσεξε τη σύνταξη, που μπορεί να μην έχεις ξαναδεί: αυτή η μέθοδος ορίζεται στον _τύπο_, όχι σε ένα _στιγμιότυπο_ του τύπου.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Οι επαναλήπτες δεν _απαιτείται_ να έχουν πεπερασμένο μήκος.
Η χρήση "άπειρων" ακολουθιών είναι πιο περιορισμένη, αλλά η επανάληψη πάνω τους μπορεί να είναι χρήσιμη, αρκεί να υπάρχει κάποιος τρόπος να βγεις από τον βρόχο με `break`.
Για παράδειγμα, θα μπορούσαμε να ορίσουμε μια παραλλαγή του `Powers` που παράγει τιμές μικρότερες από ένα συγκεκριμένο όριο (ίσως `typemax(Int)`, για να αποφύγουμε την υπερχείλιση ακεραίων).

## Άλλες διεπαφές

### [Προσπέλαση με θέση][ref-indexing]

Η διεπαφή των Επαναληπτών μάς επιτρέπει να πάρουμε έναν αυθαίρετο προσαρμοσμένο τύπο και να τον κάνουμε να συμπεριφέρεται ως ακολουθία, ορίζοντας απλώς μερικές απλές μεθόδους.

Ας υποθέσουμε ότι θέλαμε επίσης να μπορούμε να προσπελάσουμε την ακολουθία με θέση:

```julia-repl
julia> P = Powers(3, 4)
Powers(3, 4)

julia> P[2]
ERROR: MethodError: no method matching getindex(::Powers, ::Int64)
The function `getindex` exists, but no method is defined for this combination of argument types.
```

Μπορούμε να προσθέσουμε αυτή τη συμπεριφορά, και το [εγχειρίδιο][ref-indexing] εξηγεί πώς.

Στο ελάχιστο, πρέπει να ορίσουμε τη `getindex()`.

```julia-repl
julia> function Base.getindex(P::Powers, i::Int)
          1 ≤ i ≤ P.count || throw(BoundsError(P, i))
          return p.n ^ i
       end

julia> p = Powers(3, 4)
Powers(3, 4)

julia> p[3]
27
```

Πρέπει επίσης να ορίσουμε:

- Τις `firstindex()` και `lastindex()` για να υποστηρίζεται το `P[begin]` και το `P[end]`.
- Παραλλαγές της `getindex()` για να υποστηρίζεται η προσπέλαση με θέση χρησιμοποιώντας διανύσματα και εύρη.
- Θεωρητικά, τη `setindex!()`, αν και είναι δύσκολο να δούμε τι θα σήμαινε καν αυτό σε αυτό το παράδειγμα.

Ωστόσο, σε αυτό το σημείο κάνουμε πολλή δουλειά μόνο και μόνο για να μοιάζει ο επαναλήπτης μας περισσότερο με ένα Vector.

### [AbstractArray][ref-abstractarray]

Ίσως αξίζει να σκεφτούμε εναλλακτικές διεπαφές που προσφέρουν καλύτερο σημείο εκκίνησης.

Σε αυτή την περίπτωση, θα μπορούσαμε να κάνουμε το `Powers` υποτύπο του [`AbstractArray`][ref-abstractarray], που μας δίνει δωρεάν πολλή συμπεριφορά παρόμοια με πίνακα.

Για την ακολουθία `Powers`, ο αντίστοιχος πίνακας είναι ακεραίων, με 1 διάσταση.
Μερικές φορές θα το δεις γραμμένο ως `AbstractArray{Int, 1}`, αλλά τα ψευδώνυμα `AbstractVector{Int}` για 1-Δ και `AbstractMatrix{Int}` για 2-Δ είναι πιο συνηθισμένα στον νεότερο κώδικα Julia.

```julia-repl
julia> struct PowersArray <: AbstractVector{Int}
           n::Int
           count::Int
       end
```

Αντί για τη `length()`, τώρα πρέπει να ορίσουμε τη `size()` με μια πλειάδα μηκών κατά μήκος κάθε διάστασης: μόνο μία διάσταση σε αυτή την περίπτωση.

```julia-repl
julia> Base.size(PA::PowersArray) = (PA.count,)
```

Πώς θέλουμε να προσπελαύνουμε τις καταχωρήσεις με θέση;
Στην [έννοια των Πολυδιάστατων Πινάκων][concept-multi-dimensional-arrays] παρουσιάσαμε τις δύο βασικές προσεγγίσεις:

- Μία θέση ανά διάσταση, δηλαδή `M[row, col]` για έναν πίνακα `M`.
- Μία μοναδική θέση, που αντιστοιχεί στη διάταξη των καταχωρήσεων στη μνήμη

Αυτές ονομάζονται `Cartesian` και `Linear` αντίστοιχα.

Στο παράδειγμα έχουμε μόνο μία διάσταση, οπότε η γραμμική προσπέλαση με θέση είναι κατάλληλη.

```julia-repl
julia> Base.IndexStyle(::Type{PowersArray}) = IndexLinear()

julia> Base.getindex(PA::PowersArray, i::Int) = PA.n ^ i

julia> p = PowersArray(3, 4)
4-element PowersArray:
  3
  9
 27
 81

julia> p[3]
27
```

Σημείωσε ότι δεν ορίσαμε τη `iterate()` σε αυτή την περίπτωση.
Η Julia παρέχει αυτόματα μια προεπιλεγμένη υλοποίηση, βασισμένη στον ορισμό μας της `getindex()`.

Ο ορισμός της δικής μας έκδοσης της `iterate()` είναι ακόμα δυνατός, και σε ορισμένες περιπτώσεις μπορεί να είναι πιο αποδοτικός.

Η χρήση της διεπαφής `AbstractArray` είναι ιδιαίτερα πολύτιμη αν θέλουμε επανάληψη σε περισσότερες διαστάσεις.
Με τον κίνδυνο να τραβήξουμε το απλοϊκό παράδειγμα πέρα από τα όριά του, αυτό θα μπορούσε να σημαίνει τις πρώτες `m` δυνάμεις των αριθμών στο `1:n`, που θα ορίσει επαναληπτικά έναν πίνακα μεγέθους `(m, n)`.

```julia-repl
struct PowersMatrix{Int} <: AbstractMatrix{Int}
    ns::AbstractVector{Int}
    count::Int
end

Base.size(PM::PowersMatrix) = (PM.count, length(PM.ns))
Base.IndexStyle(::Type{PowersMatrix}) = IndexCartesian()
Base.getindex(PM::PowersMatrix, i::Int, j::Int) = PM.ns[j] ^ i

julia> PM = PowersMatrix(2:6, 4)
4×5 PowersMatrix{Int64}:
  2   3    4    5     6
  4   9   16   25    36
  8  27   64  125   216
 16  81  256  625  1296

julia> PM[3, 2]
27

julia> PM[7] # column major linear indexing
27

julia> PM[21]
BoundsError: attempt to access 4×5 PowersMatrix{Int64} at index [21]
[...]
```

### [Στρογγυλοποίηση][ref-rounding]

Προηγούμενες έννοιες ανέφεραν διάφορα είδη στρογγυλοποίησης για αριθμητικούς τύπους.

```julia-repl
julia> round(1.7)
2.0

julia> floor(1.7)
1.0

julia> ceil(1.7)
2.0

# specify output type
julia> round(Int, 1.7)
2

julia> round(2.4 + 7.3im)
2.0 + 7.0im
```

Η συνάρτηση [`round()`][ref-round] είναι πιο ευέλικτη από αυτό, επιτρέποντάς σου να καθορίσεις το [`RoundingMode`][ref-roundingmode] (από τα 7 που υποστηρίζονται αυτή τη στιγμή), τα δεκαδικά ψηφία της εξόδου και τη βάση αρίθμησης.

Μπορεί να θέλουμε οι ίδιες συναρτήσεις να χειρίζονται τους προσαρμοσμένους τύπους μας.
Συνήθως αυτό σημαίνει σύνθετους τύπους, όπως οι συντεταγμένες.

```julia-repl
julia> struct Point3D
           x::Float64
           y::Float64
           z::Float64
       end

julia> p = Point3D(7.63, 9.24, 4.50)
Point3D(7.63, 9.24, 4.5)

julia> round(p)
ERROR: MethodError: no method matching round(::Point3D, ::RoundingMode{:Nearest})
The function `round` exists, but no method is defined for this combination of argument types.
```

Όπως είναι αναμενόμενο, υπάρχει μια διεπαφή `Rounding`, που απαιτεί τουλάχιστον να ορίσουμε τη `round()` για τον τύπο μας.

```julia-repl
julia> Base.round(P3D::Point3D, r::RoundingMode) = Point3D(round(P3D.x, r), round(P3D.y, r),round(P3D.z, r))

julia> round(p)
Point3D(8.0, 9.0, 4.0)

julia> ceil(p)
Point3D(8.0, 10.0, 5.0)
```

Επειδή συμπεριλαμβάνουμε το `RoundingMode` στον ορισμό, οι `floor()` και `ceil()` λειτουργούν αυτόματα.

Φυσικά, είμαστε ελεύθεροι να ορίσουμε πιο περίπλοκες μορφές στρογγυλοποίησης.

- Μπορεί να θέλουμε να στρογγυλοποιήσουμε το `Point3D` ώστε να απέχει ακέραια απόσταση από την αρχή των αξόνων, στην ίδια κατεύθυνση.
- Για γωνίες, μπορεί να θέλουμε να στρογγυλοποιήσουμε στις 16 διευθύνσεις που χρησιμοποιούν οι μετεωρολόγοι (_"άνεμος ΝΝΔ με 15 κόμβους"_), δηλαδή πολλαπλάσια των π/8 ακτίνων.
- Μπορεί να θέλουμε να προσθέσουμε τη δυνατότητα να καθορίζουμε `digits`, `sigdigits` ή `base`.
- Υπάρχουν [ειδικές επιλογές][ref-round-periods] για χρονικά διαστήματα

## Σύνοψη

Οι διεπαφές είναι αρκετά μπερδεμένες στην εξήγηση, επειδή η προσέγγιση της Julia είναι τόσο διαφορετική από τις περισσότερες άλλες γλώσσες.
Ειδικότερα, το όνομα της διεπαφής μπορεί να μην αναφέρεται ποτέ στην υλοποίηση, σε μεγάλη αντίθεση με τη [δημιουργία υποκλάσεων][wiki-subclass] ή τα [mixins][wiki-mixins].

Ωστόσο, στην πράξη είναι εντυπωσιακά απλές:

1. Όρισε έναν κατάλληλο τύπο, αποφασίζοντας αν η υποτυποποίηση είναι χρήσιμη ή όχι.
2. Βρες ποιες μέθοδοι απαιτούνται (από την [τεκμηρίωση][ref-interfaces]).
3. Υλοποίησε αυτές τις μεθόδους για τον προσαρμοσμένο τύπο σου· συνήθως είναι λίγες μέθοδοι, αρκετά σύντομες και απλές.
4. Άφησε την [Πολλαπλή Αποστολή][concept-multiple-dispatch] να αναλάβει τα υπόλοιπα, αυτόματα.
