# Εισαγωγή

Στη C++, οι δηλώσεις συχνά διαχωρίζονται από τους ορισμούς.
Οι δηλώσεις ομαδοποιούνται σε αυτά που ονομάζουμε αρχεία κεφαλίδας, ενώ οι αντίστοιχες υλοποιήσεις τοποθετούνται σε αρχεία πηγαίου κώδικα.
Μπορείς να σκεφτείς τα αρχεία κεφαλίδας σαν ένα API.
Το αρχείο κεφαλίδας θα σου πει _τι_ έχει να προσφέρει μια βάση κώδικα, χωρίς να μπει στις λεπτομέρειες του _πώς_.

## Κεφαλίδα και πηγαίος κώδικας

Η πιο συνηθισμένη επέκταση αρχείου για τα αρχεία κεφαλίδας είναι το `.h`.
Κάποια project χρησιμοποιούν `.hpp` ή παραλείπουν εντελώς την επέκταση.

Οι ορισμοί βρίσκονται σε ένα ξεχωριστό αρχείο `.cpp`.
Για να ενωθούν ξανά τα κομμάτια, το αρχείο πηγαίου κώδικα ξεκινά _συμπεριλαμβάνοντας_ το αντίστοιχο αρχείο κεφαλίδας.

Αν θέλεις να γράψεις μια βιβλιοθήκη που ονομάζεται "quick_math" και προσφέρει μια συνάρτηση "super_root" που θέλεις να χρησιμοποιείς συχνά, τα αρχεία θα έμοιαζαν κάπως έτσι:

```cpp
// A file named quick_math.h
#pragma once
namespace quick_math {
    double super_root(double x, int n);
}
```

```cpp
// A file named quick_math.cpp
#include "quick_math.h"
#include <cmath>
double quick_math::super_root(double x, int n) {
    while(n) { x = std::sqrt(x), --n;}
    return x;
}
```

Αν χρειάζεται να συμπεριλάβεις μια κεφαλίδα που την απαιτεί μόνο η υλοποίηση, η αντίστοιχη γραμμή `#include` χρειάζεται μόνο στο αρχείο πηγαίου κώδικα.
Ό,τι συμπεριλαμβάνεται στην κεφαλίδα είναι διαθέσιμο και στο αρχείο `.cpp`, όπως η βιβλιοθήκη `string` στο παρακάτω παράδειγμα.
**Προσοχή**: το `;` χρειάζεται μετά τη δήλωση στο αρχείο κεφαλίδας, αλλά όχι μετά τον ορισμό στο αρχείο πηγαίου κώδικα.

## Κλάσεις και κεφαλίδες

Οι κλάσεις μπορούν να γίνουν πολύ περίπλοκες και η σχέση τους με τον διαχωρισμό κεφαλίδας / πηγαίου κώδικα μπορεί να σε μπερδέψει.
Μια πιθανή διάταξη είναι να κρατήσεις όλες τις λεπτομέρειες της υλοποίησης στο αρχείο πηγαίου κώδικα και όλες τις δηλώσεις και τις μεταβλητές μέλη στην κεφαλίδα:

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H
#include <string>
namespace robots {
    class Flower {
        private:
            bool needs_water{};
            int size{};
            std::string name{};
        public:
            Flower(std::string name, int size = 0);
            void give_water();
            std::string get_name();
            int get_size();
            void start_next_day();
    };
}
#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"
robots::Flower::Flower(std::string name, int size) {this->name = "Robotica " + name; this->size = size;}
void robots::Flower::start_next_day() {if (!needs_water) ++size; needs_water = true;}
std::string robots::Flower::get_name() {return name;}
int robots::Flower::get_size() {return size;}
```

Όταν η κεφαλίδα χρησιμοποιείται ως επισκόπηση του API, εκεί θα έψαχνε κάποιος για πληροφορίες όπως οι προεπιλεγμένες τιμές.
Η προεπιλεγμένη τιμή της παραμέτρου `size` του κατασκευαστή ορίζεται επομένως στην κεφαλίδα και όχι στην υλοποίηση.
Οι ορισμοί στο αρχείο πηγαίου κώδικα έχουν μπροστά τους το namespace `robots` και τον τύπο της κλάσης `Flower`.

Μια άλλη επιλογή διάταξης είναι μια βιβλιοθήκη _μόνο με κεφαλίδα_, που δεν έχει καθόλου αρχείο `.cpp`:

```cpp
// A file named robot_flower.h
#pragma once
#include <string>
namespace robots {
    class Flower {
        private:
            bool needs_water{};
            int size{};
            std::string name{};
        public:
            Flower(std::string name, int size = 0) {this->name = "Robotica " + name; this->size = size;}
            void give_water() {needs_water = false;}
            std::string get_name() {return name;}
            int get_size() {return size;}
            void start_next_day() {if (!needs_water) ++size; needs_water = true;}
    };
}
```

Τα project μπορεί να χρησιμοποιούν συνδυασμούς αυτών των διατάξεων και γίνεται μεγάλη συζήτηση για το ποια από αυτές ταιριάζει καλύτερα σε κάθε περίπτωση χρήσης.

## Φρουροί συμπερίληψης

Ίσως πρόσεξες τη γραμμή `#pragma once` στο παραπάνω παράδειγμα αρχείου κεφαλίδας.
Αυτό ονομάζεται φρουρός συμπερίληψης, και εξασφαλίζει ότι το περιεχόμενο του αρχείου συμπεριλαμβάνεται μόνο μία φορά κατά τη μεταγλώττιση, ώστε να αποφεύγονται σφάλματα.
Υπάρχει μια άλλη, πιο σύνθετη παραλλαγή ενός φρουρού συμπερίληψης που ξεκινά με `#ifndef` και τελειώνει με `#endif`.
Εξυπηρετεί τον ίδιο σκοπό και η χρήση της φαίνεται στο παραπάνω παράδειγμα της κλάσης `Flower`.
