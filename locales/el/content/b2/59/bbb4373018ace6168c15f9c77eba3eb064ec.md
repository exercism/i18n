# Εισαγωγή

## Βεβαιώσεις let

Όταν κάνουμε αντιστοίχιση προτύπων σε μια τιμή στη Gleam, πρέπει να διασφαλίζουμε ότι τα πρότυπα ταιριάζουν με κάθε πιθανή τιμή του τύπου, αλλιώς ο κώδικας δε θα μεταγλωττιστεί.

Αυτή η συνάρτηση θα πρέπει να απορριφθεί, καθώς δεν έχει χειριστεί την περίπτωση όπου η λίστα είναι κενή:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Τις περισσότερες φορές στα προγράμματα Gleam θέλουμε να χειριζόμαστε κάθε πιθανή περίπτωση, αλλά σε κάποια προγράμματα, όπως πρωτότυπα και γρήγορα σενάρια, μπορεί να θέλουμε να επικεντρωθούμε μόνο στην ευτυχή διαδρομή και να μην γράψουμε κώδικα για άλλες περιπτώσεις. Εδώ έρχεται το `let assert` της Gleam.

Με τις βεβαιώσεις let, ένα πρότυπο μπορεί να ταιριάξει μόνο με μερικές από τις πιθανές τιμές ενός τύπου, και αν το πρότυπο δεν ταιριάξει με μια τιμή, το πρόγραμμα θα καταρρεύσει. Χρησιμοποιώντας το `let assert` μπορούμε να γράψουμε την παραπάνω συνάρτηση ως εξής:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Οι βιβλιοθήκες Gleam δεν πρέπει ποτέ να χρησιμοποιούν βεβαιώσεις let, καθώς μπορούν να κάνουν το πρόγραμμα να καταρρεύσει. Αντ' αυτού, θα πρέπει να χρησιμοποιούν τον τύπο `Result` και να αφήνουν τον προγραμματιστή της εφαρμογής να αποφασίσει πώς να χειριστεί τα σφάλματα.
