# Εισαγωγή

Υπάρχουν packed παραλλαγές για τις περισσότερες scalar bitwise πράξεις.
Ακολουθούν την ίδια γενική σύνταξη με τις ακέραιες πράξεις SIMD, αλλά δεν έχουν κατάληξη μεγέθους:

| εντολή | περιγραφή                          |
|--------|------------------------------------|
| `pand` | bitwise AND δύο τιμών 128 bit      |
| `por`  | bitwise OR δύο τιμών 128 bit       |
| `pxor` | bitwise XOR δύο τιμών 128 bit      |

Σημείωσε ότι δεν υπάρχει packed `NOT`.
Ωστόσο, υπάρχει μια πράξη ANDN, η οποία συμπληρώνει (αντιστρέφει όλα τα bit) τον τελεστέο **προορισμού** και μετά υπολογίζει το AND μεταξύ των δύο τελεστέων.
Μπορεί να ιδωθεί ως ένα NOT σε συνδυασμό με ένα AND:

| εντολή  | περιγραφή                                                       |
|---------|-----------------------------------------------------------------|
| `pandn` | bitwise AND του **συμπληρωμένου** τελεστέου προορισμού με τον τελεστέο πηγής |

Σημείωσε ότι μια bitwise πράξη συνδυάζει bit στην ίδια θέση δύο διαφορετικών τελεστέων, οπότε τα όρια των lane δεν μπορούν να αλλάξουν το αποτέλεσμα.
Γι' αυτό αυτές οι εντολές δεν έχουν κατάληξη μεγέθους, αφού ο καταχωρητής συμπεριφέρεται σαν ένα μόνο lane των 128 bit:

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
Όλες οι εντολές αυτής της έννοιας υπολογίζουν bit αλλά δεν θέτουν σημαίες.
Μια επόμενη έννοια θα ασχοληθεί με εντολές υπό συνθήκη με packed τιμές.
~~~~

## Ολισθήσεις ανά lane

Οι ολισθήσεις, σε αντίθεση με τις καθαρά bitwise πράξεις, μετακινούν bit από τη μια θέση στην άλλη, οπότε χρειάζονται ένα μέγεθος lane για να ορίσουν ένα όριο.
Μέσα σε κάθε lane συμπεριφέρονται όπως τα scalar αντίστοιχά τους, και τα bit δεν περνούν ποτέ από το ένα lane στο γειτονικό:

| εντολή                    | περιγραφή                           |
|---------------------------|-------------------------------------|
| `psllw`, `pslld`, `psllq` | λογική ολίσθηση αριστερά, ανά lane  |
| `psrlw`, `psrld`, `psrlq` | λογική ολίσθηση δεξιά, ανά lane     |
| `psraw`, `psrad`          | αριθμητική ολίσθηση δεξιά, ανά lane |

Σημείωσε ότι αυτές οι εντολές ακολουθούν τη σύνταξη των packed ακέραιων πράξεων, περιλαμβάνοντας κατάληξη μεγέθους.
Δεν υπάρχει ολίσθηση για lane μεγέθους byte, μόνο word, dword και, με εξαίρεση την αριθμητική ολίσθηση δεξιά, qword.

Μια διαφορά ανάμεσα στις packed ολισθήσεις και τα scalar αντίστοιχά τους βρίσκεται στο όνομα της πράξης:

- Αντί για `shl` και `shr`, έχουμε `sll` και `srl`, που σημαίνουν **s**hift **l**eft (**r**ight) **l**ogical.
- Αντί για `sar`, έχουμε `sra`, που σημαίνει **s**hift **r**ight **a**rithmetic.

Αν και το όνομα είναι διαφορετικό, η πράξη είναι η ίδια:

- Μια λογική ολίσθηση δεξιά γεμίζει τα πιο πάνω bit με μηδενικά.
  Είναι ισοδύναμη με μια διαίρεση χωρίς πρόσημο με δύναμη του δύο.
- Μια αριθμητική ολίσθηση δεξιά γεμίζει τα πιο πάνω bit με την τιμή του bit προσήμου.
  Είναι ισοδύναμη με μια διαίρεση με πρόσημο με δύναμη του δύο, με στρογγυλοποίηση προς το αρνητικό άπειρο.
- Μια ολίσθηση αριστερά γεμίζει πάντα με μηδενικά (γι' αυτό δεν χρειάζεται αριθμητική ολίσθηση αριστερά).

Ο αριθμός των ολισθήσεων είναι ο ίδιος για κάθε lane.
Μπορεί να είναι μια άμεση τιμή, ή τα χαμηλότερα 64 bit ενός καταχωρητή `xmm`:

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
Ένας αριθμός ολισθήσεων μεγαλύτερος από το πλάτος του lane δεν κάνει αναδίπλωση, όπως η scalar οικογένεια `shl`/`shr`.
Απλώς παράγει μηδέν (ή όλα τα bit προσήμου, για την αριθμητική ολίσθηση δεξιά).
~~~~

## Bitwise πράξεις κινητής υποδιαστολής

Κάθε bitwise εντολή έχει επίσης δίδυμα με ονόματα κινητής υποδιαστολής, ακολουθώντας την ίδια σύνταξη που έχουμε δει για τις packed πράξεις κινητής υποδιαστολής:

| όνομα ακέραιου | ονόματα κινητής υποδιαστολής |
|----------------|------------------------------|
| `pand`         | `andps`, `andpd`             |
| `pandn`        | `andnps`, `andnpd`           |
| `por`          | `orps`, `orpd`               |
| `pxor`         | `xorps`, `xorpd`             |

Εφόσον οι bitwise πράξεις δρουν σε bit, στην πράξη οι ακέραιες πράξεις και οι πράξεις κινητής υποδιαστολής υπολογίζουν το ίδιο αποτέλεσμα.
Τα διαφορετικά ονόματα υπάρχουν για δύο λόγους:

1. Τεκμηριώνουν την πρόθεση, με τον ίδιο τρόπο που θα προτιμούσαμε `movdqa`, `movaps` ή `movapd` ανάλογα με τη φύση των byte που αντιγράφονται.
2. Οι ακέραιες πράξεις και οι πράξεις κινητής υποδιαστολής έχουν συχνά διαφορετικούς τομείς εκτέλεσης.
   Πράξεις μέσα στον ίδιο τομέα εκτέλεσης μπορούν συνήθως να αλληλουχηθούν πιο γρήγορα.

Δεν υπάρχει πράξη ολίσθησης για τιμές κινητής υποδιαστολής.

## Αναπαράσταση bit κινητής υποδιαστολής

Ένας αριθμός κινητής υποδιαστολής IEEE έχει πολύ διαφορετική αναπαράσταση bit από έναν ακέραιο.

Σε έναν ακέραιο χωρίς πρόσημο, κάθε bit έχει ομοιόμορφη σημασία: αντιπροσωπεύει μια δύναμη του δύο που αντιστοιχεί στη θέση του bit.
Ο ακέραιος είναι το άθροισμα των δυνάμεων του δύο που αντιστοιχούν στα bit που είναι 1.
Γι' αυτό η ολίσθηση των bit μπορεί να πολλαπλασιάσει ή να διαιρέσει τον αριθμό με δύναμη του δύο: απλώς αλλάζουμε τη θέση κάθε bit που είναι 1.

Σε έναν ακέραιο με πρόσημο, τα περισσότερα bit ερμηνεύονται με τον ίδιο τρόπο όπως σε έναν ακέραιο χωρίς πρόσημο.
Ωστόσο, το πιο πάνω bit είναι ξεχωριστό.
Αν είναι 1, αντί να προστεθεί στα υπόλοιπα, πρέπει να αφαιρέσουμε την αντίστοιχη δύναμη του δύο, κάτι που δίνει αρνητικό αριθμό.
Στην πράξη, για να αλλάξουμε το πρόσημο ενός αριθμού, θα χρειαζόμασταν εννοιολογικά δύο βήματα: την αντιστροφή όλων των bit (ένα `not`) και μετά την πρόσθεση 1 στο αποτέλεσμα (ένα `inc`).

Τα bit στους αριθμούς κινητής υποδιαστολής δεν έχουν ομοιόμορφη σημασία και πρέπει να ερμηνεύονται με πολύ διαφορετικούς τρόπους ανάλογα με τη θέση τους:

| πεδίο    | θέσεις (32 bit) | θέσεις (64 bit) |
|----------|-----------------|-----------------|
| πρόσημο  | 31              | 63              |
| εκθέτης  | 30-23           | 62-52           |
| κλάσμα   | 22-0            | 51-0            |

Ο αριθμός που προκύπτει υπολογίζεται από τον τύπο `(-1)^sign * 1.fraction * 2^(exponent - bias)`.
Η πόλωση εξαρτάται από την ακρίβεια:

| μέγεθος | πόλωση |
|---------|--------|
| 32 bit  | 127    |
| 64 bit  | 1023   |

Και στις δύο μορφές, το πρόσημο του αριθμού καθορίζεται αποκλειστικά από το bit προσήμου.
Η αλλαγή του προσήμου ενός αριθμού κινητής υποδιαστολής επιτυγχάνεται με την απλή αντιστροφή αυτού του bit (μια πράξη XOR).
Η λήψη της απόλυτης τιμής επιτυγχάνεται με τον απλό μηδενισμό του (ένα AND όπου το bit μηδενίζεται):

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

Σημείωσε ότι σε αυτή την αναπαράσταση bit, η ολίσθηση των bit δεν έχει προβλέψιμο και ομοιόμορφο αποτέλεσμα.
Το κλάσμα μπορεί να "ξεχειλίσει" στον εκθέτη και ο εκθέτης, στο πρόσημο.

Ωστόσο, μερικές φορές είναι βολικό να απομονώνουμε τα διάφορα μέρη της αναπαράστασης για να δουλέψουμε πάνω τους.

Για παράδειγμα, τα bit του εκθέτη πρέπει πρώτα να ερμηνευτούν ως αριθμός χωρίς πρόσημο, πριν αφαιρεθεί από αυτόν η πόλωση.
Αυτό σημαίνει ότι μπορούμε να παράγουμε έναν ακέραιο 32 ή 64 bit του οποίου η υποκείμενη αναπαράσταση bit αντιστοιχεί σε κάποια δύναμη του δύο στην αντίστοιχη μορφή κινητής υποδιαστολής.
Έπειτα αυτή η ακατέργαστη αναπαράσταση bit μπορεί να χρησιμοποιηθεί για να πολλαπλασιάσουμε ή να διαιρέσουμε κάποιον άλλο αριθμό κινητής υποδιαστολής.

Για παράδειγμα:

```x86asm
mov eax, 210             ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23              ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax           ; we move the raw bits to xmm0
mulss xmm1, xmm0         ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

Αντίστροφα, θα μπορούσαμε να εξαγάγουμε τους εκθέτες packed αριθμών κινητής υποδιαστολής κάνοντας ένα AND με μια μάσκα όπου τα bit του εκθέτη είναι 1 και όλα τα άλλα είναι 0.
Σε συνδυασμό με μια ολίσθηση και μια αφαίρεση, αυτό παράγει τον εκθέτη χωρίς πόλωση κάθε lane ως ακέραιο με πρόσημο:

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
Η εργασία πάνω στα ακατέργαστα bit αριθμών κινητής υποδιαστολής, αν και χρήσιμη σε ορισμένες περιπτώσεις, πρέπει να γίνεται με προσοχή.
Η πρόσθεση ή η αφαίρεση από το πεδίο του εκθέτη είναι ασφαλής μόνο αν δεν υπάρχει υπερχείλιση ή υποχείλιση και αν ο αριθμός εισόδου είναι κανονικός.
Επίσης, η πρόσθεση ενός έγκυρου `x` στο πεδίο του εκθέτη του `0.0` δίνει `2^(x - bias)`, όχι `0.0 * 2^x`.
~~~~
