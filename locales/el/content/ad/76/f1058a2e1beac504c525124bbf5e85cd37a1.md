# Εισαγωγή

Οποιαδήποτε δεδομένα στη assembly είναι μια ακολουθία από byte.
Αυτό σημαίνει ότι οποιαδήποτε δεδομένα μπορούν να θεωρηθούν ένας **πίνακας** από αυτά τα υποκείμενα byte.

## Πρόσβαση σε στοιχεία ενός πίνακα

Για να αποκτήσεις πρόσβαση σε οποιαδήποτε τιμή στη μνήμη, είναι απαραίτητο να υπολογίσεις την **ενεργή διεύθυνσή** της.
Μια ενεργή διεύθυνση είναι μια έκφραση που μπορεί να αποτελείται από:

- μια _βασική διεύθυνση_, για παράδειγμα αυτή που υποδεικνύει η ετικέτα μιας μεταβλητής.
- έναν _καταχωρητή θέσης_, που μπορεί να κλιμακωθεί κατά `1`, `2`, `4` ή `8`.
- μια προσημασμένη _εκτόπιση_ 32 bit, δηλαδή έναν αριθμό που προστίθεται στη βασική διεύθυνση (ή αφαιρείται από αυτή).

Σημείωσε ότι αυτή η διεύθυνση _ξεκινά από το 0_, οπότε μια βασική διεύθυνση, χωρίς καμία μετατόπιση, δείχνει στο πρώτο byte μιας μεταβλητής.
Γι' αυτό η αποαναφορά μνήμης χρησιμοποιώντας μόνο μια ετικέτα χωρίς μετατόπιση, όπως κάναμε σε προηγούμενες έννοιες, δίνει μια τιμή που ξεκινά από το πρώτο της byte:

```x86asm
section .data
    example dq 10 ; example is a 8-byte variable
                  ; so it can be viewed as an array of those 8 bytes
                  ; which can be accessed from index 0 to index 7

section .text
fn:
    mov al, byte [example] ; this accesses the first byte
    mov r8b, byte [example + 2] ; this accesses the third byte
    mov edx, dword [example + 1] ; this accesses 4 bytes starting at the second
```

~~~~exercism/note
Το x86-64 είναι [little endian][endianness].
Αυτό σημαίνει ότι το λιγότερο σημαντικό byte μιας τιμής πολλαπλών byte αποθηκεύεται στη μικρότερη διεύθυνση μνήμης.

Κατά συνέπεια, όταν αποκτάς πρόσβαση στα επιμέρους byte μιας τιμής πολλαπλών byte, είναι απαραίτητο να προσθέσεις μια θετική μετατόπιση στη βασική διεύθυνση για να φτάσεις σε πιο σημαντικά byte.

[endianness]: https://en.wikipedia.org/wiki/Endianness
~~~~

Μια αρχικοποιημένη μεταβλητή που δηλώνεται με μια λίστα τιμών είναι ένας πίνακας από αυτές τις τιμές, όπου κάθε στοιχείο έχει το καθορισμένο μέγεθος.
Ωστόσο, οι μετατοπίσεις είναι πάντα σε **_byte_**, ακόμα και όταν κάθε στοιχείο του πίνακα έχει μεγαλύτερο μέγεθος:

```x86asm
section .data
    arr dq 4, 8, 15, 23, 42 ; this defines an array of 5 qwords (8-byte elements)
                            ; the first qword has value 4 and can be accessed at [arr] (offset 0)
                            ; any subsequent qword can be accessed at offsets increasing by the size in bytes of each element (8)

section .text
fn:
    mov rdx, 2
    lea rcx, [rel arr]
    mov rax, qword [rcx + 8*rdx + 8]  ; rdx is an index register scaled by 8
                                      ; 8 is a signed 32-bit displacement
                                      ; rax now holds 8-bytes stored in 'arr' starting at offset:
                                      ; 8*rdx(2) + 8 = 16 + 8 = 24
                                      ; this is the fourth element of the array, i.e., the element 23
```

Σημείωσε ότι, εφόσον οι διευθύνσεις είναι για byte, είναι δυνατό να αποκτήσεις άμεσα πρόσβαση σε ένα μεμονωμένο byte οποιουδήποτε στοιχείου ενός πίνακα:

```x86asm
section .data
    arr dq 4, 8, 15, 16   ; this defines an array of 4 qwords (8-byte elements)

section .text
fn:
    mov r8, 3
    lea r9, [rel arr]
    mov r10b, byte [r9 + 2*r8 + 1] ; this accesses the byte in 'arr' at offset: 2*r8(3) + 1 = 7
                                   ; this byte is part of the first qword and has value 0 (the fist byte is the least significant one)
```

Για τον ίδιο λόγο, είναι δυνατό να αποκτήσεις πρόσβαση σε περισσότερα από το μέγεθος ενός στοιχείου με μία μόνο εντολή:

```x86asm
section .data
    arr db 1, 2, 3, 4 ; this defines an array of 4 bytes

section .text
fn:
    mov r11d, dword [rel arr] ; this accesses all bytes in arr as a 32-bit value with bytes
                              ; the least significant byte is 1, the next is 2 and so on
                              ; the resulting number is 0x04030201 or 67305985 in decimal
```

~~~~exercism/caution
Η assembly δεν εκτελεί κανέναν έλεγχο ορίων στις προσβάσεις πίνακα.
Μια θέση πέρα από το τέλος ενός πίνακα διαβάζει ή γράφει μνήμη έξω από αυτόν.
Αυτό μπορεί να οδηγήσει σε σιωπηλά λανθασμένα αποτελέσματα, σε αλλοίωση άλλων δεδομένων και, αν η μνήμη στην οποία γίνεται η πρόσβαση δεν είναι αντιστοιχισμένη, σε σφάλμα κατά την εκτέλεση.
Ο προγραμματιστής είναι υπεύθυνος να κρατά κάθε ενεργή διεύθυνση μέσα στα όρια του πίνακα.
~~~~

## Υπολογισμός του μεγέθους ενός αρχικοποιημένου πίνακα

Ο NASM (The Netwide Assembler - ο assembler που χρησιμοποιεί αυτό το track) έχει ένα ειδικό σύμβολο (`$`) που δηλώνει την τρέχουσα θέση στη μνήμη.
Αυτό το σύμβολο προσφέρει έναν βολικό τρόπο να υπολογίσεις το συνολικό μέγεθος σε μνήμη που καταλαμβάνει ένας πίνακας:

```x86asm
section .data
    example dd 4, 5, 6
    example_length dq $ - example  ; this is a qword variable with the size of the array, in bytes
```

Όταν χρησιμοποιείται ακριβώς μετά το `example`, το `$` έχει τη διεύθυνση στη μνήμη για το τέλος του πίνακα.
Αυτό σημαίνει ότι το `$ - example` είναι η διαφορά ανάμεσα σε αυτή τη διεύθυνση και εκείνη στην οποία δείχνει η ετικέτα `example`.
Αυτό είναι ακριβώς το συνολικό μέγεθος, σε byte, που καταλαμβάνει ο πίνακας στον οποίο δείχνει το `example`.

Έτσι, ορίζοντας το `example_length` με αυτή την τιμή, δημιουργήσαμε μια μεταβλητή 8 byte που αποθηκεύει το μέγεθος, ή μήκος, του πίνακα, σε byte.

## Η ενότητα .bss

Τα μη αρχικοποιημένα δεδομένα δηλώνονται στην **ενότητα .bss**.
Στις περισσότερες πλατφόρμες, το λειτουργικό σύστημα γεμίζει αυτά τα δεδομένα με μηδενικά στην αρχή του προγράμματος.

Στον NASM, μια μη αρχικοποιημένη μεταβλητή έχει ένα όνομα, μια οδηγία που δηλώνει το μέγεθος δεδομένων και τον αριθμό των στοιχείων που θα δεσμευτούν.
Κάθε ένα από αυτά χωρίζεται από το επόμενο με ένα κενό.

Οι κυριότερες οδηγίες και τα σχετικά μεγέθη δεδομένων τους είναι:

| οδηγία | μέγεθος |
| :-------: | :------ |
|   resb    | 1 byte  |
|   resw    | 2 byte  |
|   resd    | 4 byte  |
|   resq    | 8 byte  |

Για παράδειγμα, αυτό δεσμεύει μη αρχικοποιημένο χώρο για `3` byte σε μια μεταβλητή με όνομα `example`:

```x86asm
section .bss
    example resb 3
```

Και αυτό δεσμεύει μη αρχικοποιημένο χώρο για `10` επί `8` byte (δηλαδή `80` byte) σε μια μεταβλητή με όνομα `arr`:

```x86asm
section .bss
    arr resq 10
```

Οι μεταβλητές στην `section .bss` μπορούν να τροποποιηθούν, δηλαδή διαβάζονται και γράφονται.

Στα μη αρχικοποιημένα δεδομένα μπορείς να αποκτήσεις πρόσβαση με τον ίδιο τρόπο όπως στα αρχικοποιημένα, χρησιμοποιώντας την ενεργή διεύθυνσή τους.
Παρομοίως, έχουν επίσης στατική διάρκεια αποθήκευσης και είναι προσβάσιμα από οποιαδήποτε συνάρτηση στο ίδιο αρχείο πηγαίου κώδικα (και, αν δηλωθούν `global`, και σε άλλα αρχεία πηγαίου κώδικα).

## Πρόσβαση σε διευθύνσεις πίνακα με την εντολή Lea

Όπως εξετάστηκε σε μια προηγούμενη έννοια, η εντολή `lea` υπολογίζει μια ενεργή διεύθυνση μνήμης.
Μπορεί να χρησιμοποιηθεί για να υπολογίσεις τη διεύθυνση οποιουδήποτε στοιχείου ενός πίνακα, ακολουθώντας την ίδια σημασιολογία.

Σημείωσε ότι στη σχετική διευθυνσιοδότηση είναι συχνά απαραίτητο να φορτώσεις τη διεύθυνση της μεταβλητής σε έναν καταχωρητή πριν σχηματίσεις μια πιο σύνθετη διεύθυνση:

```x86asm
lea rax, [rel arr]
lea rdx, [rax + 8*r10 - 20] ; accessing 'arr' directly instead of loading it into rax first may yield an error
```

~~~~exercism/note
Ένα από τα πλεονεκτήματα του `lea` είναι ότι χρησιμοποιεί αριθμητική υπολογισμού διευθύνσεων για να υπολογίσει μια τιμή χωρίς να αποκτήσει πραγματικά πρόσβαση στη μνήμη σε αυτή τη διεύθυνση.
Αυτό το κάνει χρήσιμο για αριθμητικούς υπολογισμούς ακόμα και όταν κανένας από τους καταχωρητές δεν περιέχει διεύθυνση μνήμης:

```x86asm
mov rcx, 3
mov rdx, 5
lea rax, [rcx + 8*rdx + 10] ; rax = rcx(3) + 8*rdx(5) + 10 = 3 + 40 + 10 = 53
```
~~~~
