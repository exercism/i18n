# Εισαγωγή

## Βρόχοι

Ένας **βρόχος** είναι μια ακολουθία εντολών που εκτελείται ενδεχομένως περισσότερες από μία φορές, μέχρι να ικανοποιηθεί μια συνθήκη τερματισμού.

Στο x86-64 ένας βρόχος δημιουργείται συνήθως με ένα άλμα σε μια προηγούμενη ετικέτα:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Σημείωσε ότι ένα άλμα χωρίς συνθήκη σε μια προηγούμενη ετικέτα θα μεταφέρει πάντα την εκτέλεση σε αυτή την ετικέτα.
Αυτό σημαίνει ότι ο βρόχος θα επαναλαμβάνεται για πάντα, εκτός αν υπάρχει κάποιο άλλο άλμα προς τα έξω από την επαναλαμβανόμενη ακολουθία.

Για παράδειγμα, αυτός ο βρόχος δεν τερματίζεται:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

Και αυτός ο βρόχος μπορεί να τερματιστεί, ανάλογα με το αν ικανοποιείται η συνθήκη:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

### Βρόχοι μέτρησης

Ένας βρόχος μέτρησης τελειώνει σχεδόν πάντα με τον ίδιο τρόπο: μια εντολή που ενημερώνει έναν μετρητή ή συγκρίνει δύο τιμές, ακολουθούμενη αμέσως από ένα υπό συνθήκη άλμα που αποφασίζει αν θα επαναληφθεί.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
Το `cmp rsi, 0` δεν είναι απαραίτητο στον παραπάνω κώδικα, επειδή το `sub rsi, 1` θέτει ήδη το `zero flag (ZF)` όταν το αποτέλεσμα είναι `0`.

Παρόλο που το `cmp` είναι ο κύριος τρόπος με τον οποίο ελέγχονται οι συνθήκες στη assembly, πολλές εντολές ενημερώνουν τις σημαίες.
Για παράδειγμα, πολλές εντολές ακέραιας αριθμητικής ή πράξεων bit ενημερώνουν το `ZF` όταν το αποτέλεσμα είναι `0`, και το `SF` όταν το αποτέλεσμα είναι αρνητικό (δηλαδή, το πιο σημαντικό bit έχει τεθεί).

Μπορείς να συμβουλευτείς μια [αναφορά][reference] για να δεις ποιες σημαίες επηρεάζονται από κάθε εντολή.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Σημείωσε ότι στο παραπάνω παράδειγμα, η τιμή του `rsi` υποτίθεται ότι είναι μεγαλύτερη από `0`.
Αν η τιμή του ήταν `0`, τότε το `sub rsi, 1` θα έκανε το `rsi` να γίνει `-1`, που είναι ένας πολύ μεγάλος αριθμός χωρίς πρόσημο.
Θα χρειάζονταν άλλες `18,446,744,073,709,551,615` επαναλήψεις για να τερματιστεί τελικά ο βρόχος.
Επίσης, επειδή το μήκος του πίνακα είναι `0`, οποιαδήποτε πρόσβαση στη μνήμη θα ήταν εκτός ορίων.

Αν δεν υπάρχουν εγγυήσεις για το μήκος ενός πίνακα, υπάρχουν δύο συνήθεις προσεγγίσεις.

Η πρώτη είναι να μεταφερθεί η συνθήκη τερματισμού στην αρχή του βρόχου και να υπάρχει ένα άλμα χωρίς συνθήκη στο τέλος:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

Η δεύτερη είναι να ελέγξεις μία φορά για πίνακα μηδενικού μήκους πριν από την αρχή του βρόχου:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Αυτή η δεύτερη προσέγγιση είναι συνήθως πιο αποδοτική από την πρώτη, επειδή υπάρχουν λιγότερες διακλαδώσεις στο σώμα του βρόχου.
Θα μάθεις περισσότερα για αυτό σε μια μελλοντική έννοια.

~~~~exercism/advanced
Σε ορισμένες περιπτώσεις, οι σύγχρονοι επεξεργαστές μπορούν να συγχωνεύσουν δύο διαφορετικές εντολές σε μία μόνο πράξη.
Αυτή η βελτιστοποίηση ονομάζεται **macrofusion**.

Πολλές αριθμητικές εντολές, όπως οι `sub` και `add`, καθώς και οι `cmp` και `test`, συγχωνεύονται συνήθως με ένα υπό συνθήκη άλμα που τις ακολουθεί αμέσως.
Αυτό σημαίνει ότι μια εντολή όπως η `cmp rax, rdx`, όταν ακολουθείται αμέσως από ένα υπό συνθήκη άλμα, μπορεί συνήθως να αντιμετωπιστεί από τον επεξεργαστή ως μία μόνο πράξη.

Η macrofusion εξαρτάται από τον επεξεργαστή και υπάρχει κάποια διακύμανση στο ποιες εντολές συγχωνεύονται με ποιο υπό συνθήκη άλμα.

Μια χρήσιμη αναφορά είναι το [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch].
Η ενότητα 3.4.2.2 (Βελτιστοποίηση για τη macrofusion) του [Intel optimization reference manual][intel-opt] παραθέτει επίσης ζεύγη που μπορούν να συγχωνευθούν για επεξεργαστές Intel.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
