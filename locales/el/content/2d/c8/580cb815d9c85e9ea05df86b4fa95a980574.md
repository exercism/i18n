# Σχετικά με τα βασικά

Η Kotlin είναι μια στατικά τυποποιημένη γλώσσα, σχεδιασμένη να είναι πλήρως διαλειτουργική με τη Java.

Σε αντίθεση με τη Java, η Kotlin:

- έχει πιο καθαρή και πιο συνοπτική σύνταξη·
- ενσωματώνει πολλά χαρακτηριστικά των συναρτησιακών γλωσσών·
- έχει εκτεταμένη υποστήριξη για τιμές που μπορούν να είναι null.

## Μεταβλητές

Επειδή η Kotlin είναι στατικά τυποποιημένη, είναι απαραίτητο να _γνωρίζεις_ τον τύπο κάθε τιμής κατά τη μεταγλώττιση.

Ωστόσο, η [συμπερασματολογία τύπων][inference] της Kotlin είναι πολύ ισχυρή, οπότε ο _καθορισμός_ του τύπου είναι συχνά προαιρετικός.

Υπάρχουν δύο τρόποι να δηλώσεις μια μεταβλητή.

1. Το `val` δημιουργεί μια αμετάβλητη μεταβλητή, και αν προσπαθήσεις να την αλλάξεις, προκύπτει σφάλμα κατά τη μεταγλώττιση.

```kotlin
val x = 42  // => 42
x = 43      // => 'val' cannot be reasssigned
```

2. Το `var` δημιουργεί μια μεταβλητή που μπορεί να αλλάξει.

```Kotlin
var x = 42  // => 42
x = 43      // => 43
```

Επειδή οι αμετάβλητες μεταβλητές εξαλείφουν μια συνηθισμένη κατηγορία bugs, η χρήση του `val` ενθαρρύνεται όποτε είναι δυνατόν.

Επίσης, ακόμη και μια `var` δεν μπορεί να αλλάξει τύπο:

```kotlin
var x = 42
x = "foobar" // => Type mismatch: inferred type is String but Int was expected
```

Για να μειωθεί η οπτική απόσπαση, οι ρητοί τύποι θα παραλείπονται ως επί το πλείστον από αυτό το πρόγραμμα σπουδών.
Παρ' όλα αυτά, συνιστάται να προσδιορίζεις τους τύπους τουλάχιστον για:

- δημόσια API
- υπογραφές συναρτήσεων
- όπου χρειάζεται τεκμηρίωση

Κάποιες εταιρείες και οργανισμοί απαιτούν αυστηρή ασφάλεια τύπων και δεν επιτρέπουν τη συμπερασματολογία τύπων, ενώ άλλοι την περιορίζουν σε "απλούς" τύπους ή την υιοθετούν πλήρως.

```kotlin
val x: Int = 42  // => 42
```

Γενικά, τα ονόματα των μεταβλητών και των συναρτήσεων πρέπει να είναι σε `camelCase`, όχι σε `snake_case`

## Συναρτήσεις

Δηλώνεις μια συνάρτηση με τη λέξη-κλειδί `fun`.
Σε αντίθεση με τη Java, οι συναρτήσεις δεν χρειάζεται να αποτελούν μέρος μιας κλάσης.

```Kotlin
fun hello(): String {
    return "Hello, World!"
}

fun add(x: Int, y: Int): Int {
    return x + y
}
```

Μερικά σημεία που αξίζει να προσέξεις:

- Οι παρενθέσεις `()` είναι απαραίτητες μετά το όνομα της συνάρτησης, ακόμη και αν η συνάρτηση δεν παίρνει ορίσματα.
- Τα ορίσματα των συναρτήσεων πρέπει να προσδιορίζουν τον τύπο: δεν υπάρχει συμπερασματολογία τύπων (σε αντίθεση με τις μεταβλητές).
- Το σώμα της συνάρτησης περικλείεται σε άγκιστρα `{ }` (δες όμως παρακάτω).
- Η λέξη-κλειδί `return` είναι απαραίτητη, αν επιστρέφεται μια τιμή.
- Τα semicolons `;` στο τέλος των γραμμών είναι προαιρετικά και συνήθως παραλείπονται.
- Οι αριθμητικοί τελεστές `+`, `-`, `*`, `/` είναι παρόμοιοι με αυτούς των περισσότερων δημοφιλών γλωσσών.

Ωστόσο, για αυτές τις πολύ απλές συναρτήσεις "μίας έκφρασης", υπάρχει μια συντομευμένη σύνταξη:

```Kotlin
// return type is usually omitted for single-expression functions
fun add(x: Int, y: Int) = x + y  
```
Οι συναρτήσεις μπορούν να έχουν παραμέτρους με προεπιλεγμένες τιμές.
Αυτές οι τιμές θα χρησιμοποιηθούν αν παραλειφθούν στο σημείο όπου καλείται η συνάρτηση:

```kotlin
fun ping(host: String = "localhost") {
    println("PING --> $host")
}

ping("exercism.io")  // PING --> exercism.io
ping()               // PING --> localhost
```

Οι συναρτήσεις στο Exercism συνήθως θα επιστρέφουν μια τιμή (λόγω του τρόπου με τον οποίο είναι δομημένος ο test runner).
Για να χρησιμοποιείς την Kotlin πιο γενικά, μπορεί να σου φανεί χρήσιμο να ξέρεις ότι μια συνάρτηση που δεν επιστρέφει καμία τιμή μπορεί να παραλείψει τον τύπο επιστροφής και τη λέξη-κλειδί `return`.

Τότε λέμε ότι έχει τύπο επιστροφής `Unit`: ισοδύναμο με το `void` στη Java και σε αρκετές άλλες γλώσσες.

## Σχόλια

Τα σχόλια μίας γραμμής ξεκινούν με `//` και το υπόλοιπο της γραμμής αγνοείται.

Τα σχόλια πολλών γραμμών ξεκινούν με `/*` και τελειώνουν με `*/`

```Kotlin
fun hello(): String {
    /*
     * Failing to run this program on a new installation 
     * is considered bad luck
    */
    return "Hello, World!" // the compiler pixies are now happy
}
```

Το ίδιο ισχύει και στη Java.

~~~~exercism/note

Θα προσπαθήσουμε να επισημάνουμε τις ομοιότητες και τις διαφορές ανάμεσα στις γλώσσες σε όλο το πρόγραμμα σπουδών.
