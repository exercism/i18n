# Introduction

## Σύνδεσμοι

Οι [διαδικασίες][exercism-processes] της Elixir είναι απομονωμένες και δε μοιράζονται τίποτα από προεπιλογή. Όταν μια θυγατρική διαδικασία που δεν είναι συνδεδεμένη καταρρέει, η γονική της διαδικασία δεν επηρεάζεται.

Αυτή η συμπεριφορά μπορεί να αλλάξει με τη _σύνδεση_ των διαδικασιών μεταξύ τους. Αν δύο διαδικασίες είναι συνδεδεμένες, μια αποτυχία στη μία διαδικασία θα διαδοθεί στην άλλη. Οι σύνδεσμοι είναι **αμφίδρομοι**.

Οι διαδικασίες μπορούν να δημιουργηθούν ήδη συνδεδεμένες με την καλούσα διαδικασία χρησιμοποιώντας το `spawn_link/1`, το οποίο είναι μια ατομική λειτουργία, ή μπορούν να συνδεθούν αργότερα με το `Process.link/1`.

Η σύνδεση διαδικασιών μπορεί να είναι χρήσιμη όταν κάνεις παράλληλη εργασία, όταν κάθε κομμάτι εργασίας δεν θα έπρεπε να συνεχιστεί σε περίπτωση που κάποιο άλλο κομμάτι αποτύχει να ολοκληρωθεί.

### Παγίδευση εξόδων

Η σύνδεση μπορεί επίσης να χρησιμοποιηθεί για την _εποπτεία_ διαδικασιών. Αν μια διαδικασία _παγιδεύει εξόδους_, δε θα καταρρεύσει όταν καταρρεύσει μια διαδικασία με την οποία είναι συνδεδεμένη. Αντ' αυτού θα λάβει ένα μήνυμα για την κατάρρευση. Αυτό της επιτρέπει να χειριστεί την κατάρρευση με κομψό τρόπο, για παράδειγμα επανεκκινώντας τη διαδικασία που κατέρρευσε.

Μια διαδικασία μπορεί να ρυθμιστεί ώστε να παγιδεύει εξόδους καλώντας το `Process.flag(:trap_exit, true)`. Σημείωσε ότι το `Process.flag/2` επιστρέφει την _παλιά_ τιμή της σημαίας, όχι τη νέα.

Το μήνυμα που θα σταλεί στη διαδικασία σε περίπτωση που καταρρεύσει μια συνδεδεμένη διαδικασία θα ταιριάζει με το μοτίβο `{:EXIT, from, reason}`, όπου το `from` είναι ένα PID. Αν το `reason` είναι οτιδήποτε άλλο εκτός από το άτομο `:normal`, αυτό σημαίνει ότι η διαδικασία κατέρρευσε ή σκοτώθηκε βίαια.

## Εργασίες

Οι εργασίες είναι [διαδικασίες][exercism-processes] που προορίζονται να εκτελέσουν μία συγκεκριμένη λειτουργία. Συνήθως δεν επικοινωνούν με άλλες διαδικασίες, αλλά μπορούν να επιστρέψουν ένα αποτέλεσμα στη διαδικασία που ξεκίνησε την εργασία.

Οι εργασίες χρησιμοποιούνται συνήθως για την παραλληλοποίηση εργασίας.

### `async`/`await`

Για να ξεκινήσεις μια εργασία, χρησιμοποίησε το `Task.async/1`. Παίρνει μια ανώνυμη συνάρτηση ως όρισμα και την εκτελεί σε μια νέα διαδικασία που είναι συνδεδεμένη με τη διαδικασία που την κάλεσε. Επιστρέφει ένα struct `%Task{}`.

Για να πάρεις το αποτέλεσμα της εκτέλεσης, πέρασε το struct `%Task{}` στο `Task.await/2`. Θα περιμένει να ολοκληρωθεί η εργασία και θα επιστρέψει το αποτέλεσμά της. Το δεύτερο όρισμα είναι ένα χρονικό όριο σε χιλιοστά του δευτερολέπτου, με προεπιλογή το 5000.

Σημείωσε ότι μεταξύ της εκκίνησης της εργασίας και της αναμονής της, η διαδικασία που ξεκίνησε την εργασία δεν είναι αποκλεισμένη και μπορεί να κάνει άλλες λειτουργίες.

Κάθε εργασία που ξεκινά με το `Task.async/1` θα πρέπει να αναμένεται, γιατί θα στείλει ένα μήνυμα στη διαδικασία που την κάλεσε. Το `Task.await/2` μπορεί να κληθεί για κάθε εργασία μόνο μία φορά.

### `start`/`start_link`

Αν θέλεις να ξεκινήσεις μια εργασία μόνο για παρενέργειες, χρησιμοποίησε το `Task.start/1` ή το `Task.start_link/1`. Το `Task.start/1` θα ξεκινήσει μια εργασία που δεν είναι συνδεδεμένη με τη διαδικασία που την καλεί, και το `Task.start_link/1` θα ξεκινήσει μια εργασία που είναι συνδεδεμένη με τη διαδικασία που την καλεί. Και οι δύο συναρτήσεις επιστρέφουν ένα tuple `{:ok, pid}`.

[exercism-processes]: https://exercism.org/tracks/elixir/concepts/processes
