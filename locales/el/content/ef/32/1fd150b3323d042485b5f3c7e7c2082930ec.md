# Εισαγωγή

Τα νήματα της Factor είναι *συνεργατικές συνρουτίνες*: μοιράζονται ένα νήμα του λειτουργικού συστήματος, παραχωρούν τον έλεγχο το ένα στο άλλο σε λειτουργίες εισόδου/εξόδου και σε ρητά σημεία παραχώρησης, και δεν εκτελούνται ποτέ πραγματικά ταυτόχρονα. Ό,τι κάνεις *ανάμεσα* σε δύο παραχωρήσεις ελέγχου συμβαίνει ως ένα αδιατάρακτο βήμα. Αν όμως μια σύνθετη λειτουργία (ανάγνωση-τροποποίηση-εγγραφή) παραχωρήσει τον έλεγχο στη μέση, ένα άλλο νήμα μπορεί να παρεισφρήσει και να αλλάξει την κατάσταση πριν προλάβεις να τελειώσεις, και αυτό είναι μια συνθήκη ανταγωνισμού.

Αυτή η άσκηση καλύπτει τέσσερα βασικά στοιχεία που εμφανίζονται ξανά και ξανά:

## `parallel-map`: fork/join πάνω σε μια ακολουθία

```
parallel-map ( seq quot: ( elt -- newelt ) -- newseq )
```

Στο [`concurrency.combinators`][combinators]. Δημιουργεί ένα νήμα για κάθε στοιχείο, εκτελεί το quotation και μαζεύει τα αποτελέσματα πίσω σε μια νέα ακολουθία, με την ίδια σειρά:

```factor
USING: concurrency.combinators sequences ;

{ "alpha" "beta" "gamma" } [ length ] parallel-map .
! => { 5 4 5 }
```

## `spawn`: εκκίνηση ενός νήματος

```
spawn ( quot name -- thread )
```

Στο [`threads`][threads]. Το quotation εκτελείται ταυτόχρονα, ενώ το `name` είναι μια ετικέτα για αποσφαλμάτωση. Η λαβή νήματος που επιστρέφεται δεν έχει και μεγάλο ενδιαφέρον σε αυτό το επίπεδο, οπότε απλώς κάνε `drop`.

## Υποσχέσεις: μετάδοση τιμής μίας χρήσης

```
<promise>           ( -- promise )
fulfill             ( value promise -- )
?promise            ( promise -- value )
```

Στο [`concurrency.promises`][promises]. Μια υπόσχεση είναι ένα γραμματοκιβώτιο μίας χρήσης: ένα νήμα την εκπληρώνει, άλλα νήματα τη διαβάζουν. Το `?promise` μπλοκάρει μέχρι να εκπληρωθεί η υπόσχεση και μετά επιστρέφει την τιμή.

```factor
USING: concurrency.promises kernel threads ;

<promise> [
    [ 42 swap fulfill ] curry "answer" spawn drop
] keep ?promise .
! => 42
```

Το `spawn` μαζί με το `<promise>` είναι τα δομικά στοιχεία από τα οποία φτιάχνεται το `parallel-map`. Το να τα φτιάχνεις μόνος σου είναι χρήσιμο όταν κάθε εργασία κάνει κάτι διαφορετικό από το "υπολόγισε ένα στοιχείο".

Το τυπικό σχήμα fan-out/join πάνω σε μια ακολουθία είναι το εξής: για κάθε είσοδο φτιάχνεις μια καινούργια υπόσχεση, δημιουργείς ένα νήμα που κάνει τη δουλειά και εκτελεί `fulfill` στην υπόσχεση, συγκεντρώνεις όλες τις υποσχέσεις σε μια ακολουθία και μετά καλείς `?promise` σε κάθε μία για να περιμένεις να ολοκληρωθούν. Οι τοπικές μεταβλητές κάνουν αυτό το σχήμα ευανάγνωστο: δέσε την υπόσχεση σε ένα όνομα με το `:>` μέσα σε ένα lambda `[| | ]`, ώστε το quotation που δημιουργήθηκε να έχει πρόσβαση σε αυτήν:

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
inputs [| x |
    <promise> :> p
    [ x do-work t p fulfill ] "worker" spawn drop
    p
] map [ ?promise drop ] each
```

## Κλειδώματα: αμοιβαίος αποκλεισμός

```
<lock>     ( -- lock )
with-lock  ( lock quot -- )
```

Στο [`concurrency.locks`][locks]. Μόνο ένα νήμα μπορεί να κρατήσει ένα δεδομένο κλείδωμα κάθε φορά. Το `with-lock` αποκτά το κλείδωμα, εκτελεί το quotation και το απελευθερώνει, ακόμη και αν το quotation πετάξει ένα σφάλμα.

```factor
! DOCTEST: SKIP   (`:>` only works inside [let, [|, or :: forms)
USING: concurrency.locks kernel locals ;

[let <lock> :> guard
    guard [ ! exclusive section ! ] with-lock
]
```

Χρησιμοποίησε κλείδωμα όποτε μια τιμή *διαβάζεται ή γράφεται από περισσότερα από ένα νήματα* και οι πράξεις πάνω της δεν είναι από τη φύση τους ατομικές. Και οι αναγνώσεις και οι εγγραφές χρειάζονται το κλείδωμα: μια ανάγνωση που παραχωρεί τον έλεγχο στη μέση μπορεί να δει μια μισοτελειωμένη κατάσταση.
