# Σχετικά

Όταν κάνουμε αντιστοίχιση προτύπων σε μια τιμή στην Gleam, πρέπει να διασφαλίζουμε ότι τα πρότυπα ταιριάζουν με κάθε πιθανή τιμή του τύπου, αλλιώς ο κώδικας δεν θα μεταγλωττιστεί.

Αυτή η συνάρτηση θα πρέπει να απορριφθεί, καθώς δεν έχει χειριστεί την περίπτωση όπου η λίστα είναι κενή:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

Τις περισσότερες φορές, στα προγράμματα Gleam θέλουμε να χειριζόμαστε κάθε πιθανή περίπτωση, αλλά σε ορισμένα προγράμματα, όπως τα πρωτότυπα και τα γρήγορα σενάρια, μπορεί να θέλουμε να επικεντρωθούμε μόνο στην περίπτωση που όλα πάνε καλά και να μη γράψουμε κώδικα για τις υπόλοιπες. Εδώ μπαίνει στο παιχνίδι το `let assert` της Gleam.

Με το `let assert`, ένα πρότυπο μπορεί να ταιριάξει με μερικές μόνο από τις πιθανές τιμές ενός τύπου και, αν το πρότυπο δεν ταιριάξει με μια τιμή, το πρόγραμμα θα κρασάρει. Χρησιμοποιώντας το `let assert`, μπορούμε να γράψουμε τη συνάρτηση παραπάνω ως εξής:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Οι βιβλιοθήκες της Gleam δεν θα πρέπει ποτέ να χρησιμοποιούν let assertions, καθώς μπορούν να κρασάρουν το πρόγραμμα. Αντ' αυτού, θα πρέπει να χρησιμοποιούν τον τύπο `Result` και να αφήνουν τον προγραμματιστή της εφαρμογής να αποφασίσει πώς θα χειριστεί τα σφάλματα.
