# Σχετικά

## Χαρακτήρες

Η [κωδικοποίηση χαρακτήρων][char-encoding] είναι μια συγκεκριμένη σύμβαση που χρησιμοποιείται για την αναπαράσταση στοιχείων κειμένου μιας φυσικής γλώσσας ως ακολουθία byte.
Ένα "στοιχείο κειμένου" εδώ μπορεί να είναι οποιαδήποτε μονάδα έχει σημασία σε μια φυσική γλώσσα, για παράδειγμα, γράμματα, κενά, σημεία στίξης, emoji, ιδεογράμματα, κ.λπ.

Η NASM (The Netwide Assembler, ο assembler που χρησιμοποιείται από αυτό το track) υποστηρίζει τον ορισμό δεδομένων με χρήση [ASCII][ascii].

Οι σταθερές χαρακτήρων στη NASM μπορούν να έχουν μήκος έως 8 byte και μπορούν να οριστούν χρησιμοποιώντας μονά εισαγωγικά (`'`), διπλά εισαγωγικά (`"`) ή backticks (βαρείες) (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Οι ειδικοί χαρακτήρες πρέπει να ορίζονται σε backticks και να διαφεύγουν με `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Η NASM υποστηρίζει επίσης [χαρακτήρες Unicode][unicode] σε [UTF-8][utf8], που προσδιορίζονται με `\u` ή `\U` και σε backticks:

```x86asm
mov rax, `\u263a` ; UTF-8 smiley face (☺), value U+263a
mov rcx, `\u0393` ; UTF-8 capital letter gamma (Γ), value U+0393
```

Σημείωσε ότι δεν υπάρχει ενσωματωμένη υποστήριξη για καμία κωδικοποίηση χαρακτήρων στο x86-64 ως ξεχωριστό τύπο.
Τα δεδομένα στη assembly είναι μια ακολουθία byte και η ερμηνεία αυτών των byte ως χαρακτήρα, αριθμό ή οτιδήποτε άλλο, αφήνεται στον προγραμματιστή.

Για παράδειγμα, ο ASCII χαρακτήρας '0' είναι ένα μεμονωμένο byte με την τιμή 48.
Έτσι, η αποθήκευση του 48 σε ένα byte είναι ακριβώς το ίδιο με την αποθήκευση του ASCII χαρακτήρα '0':

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Για τον ίδιο λόγο, ο χειρισμός χαρακτήρων γίνεται μετασχηματίζοντας απευθείας τις τιμές σε αυτά τα byte:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## Συμβολοσειρές

Μια [συμβολοσειρά][string] είναι μια ακολουθία χαρακτήρων.
Στη assembly, συνήθως υλοποιείται ως πίνακας.

Είναι δυνατό να δηλώσεις μια συμβολοσειρά στη NASM με τον ίδιο τρόπο που θα δήλωνες οποιονδήποτε πίνακα:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Μια διαφορά μεταξύ συμβολοσειρών και άλλων πινάκων είναι ότι η NASM υποστηρίζει επίσης τη δήλωση συμβολοσειρών χωρίς κόμμα (`,`) να χωρίζει τις τιμές.
Είναι επίσης δυνατό να παρεμβάλλεις τιμές με κόμματα:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Σημείωσε ότι, όπως αναφέρθηκε ήδη, οι χαρακτήρες είναι απλώς byte (ή μια ακολουθία byte στην κωδικοποίηση Unicode):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Εφόσον κάθε ASCII χαρακτήρας καταλαμβάνει ένα μόνο byte, κάθε επόμενο byte σε μεγαλύτερο μέγεθος είναι `0`.
Για παράδειγμα, η δήλωση του `'a'` ως qword (8 byte) σημαίνει ότι το πρώτο byte είναι `'a'` (`97`) και τα άλλα επτά byte είναι όλα `0`.

Για αυτόν τον λόγο, όλα τα παρακάτω είναι ισοδύναμα:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
Στη assembly, οι συμβολοσειρές δεν τερματίζονται αυτόματα από έναν ASCII χαρακτήρα NUL (τιμή `0`).

Όταν συνεργάζεσαι με γλώσσες υψηλότερου επιπέδου, όπως η C, είναι ευθύνη του προγραμματιστή να διασφαλίσει ότι ο σωστός τερματιστής, αν υπάρχει, προστίθεται στο τέλος μιας συμβολοσειράς.
~~~~

## Εντολές συμβολοσειρών

Εφόσον οι συμβολοσειρές είναι πίνακες, μπορείς να δουλέψεις μαζί τους με τον ίδιο τρόπο όπως με οποιονδήποτε πίνακα, αποαναφέροντας ρητά τη μνήμη:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Επιπλέον, υπάρχουν κάποιες εντολές για τη φόρτωση, τη μετακίνηση και την αποθήκευση τιμών σε ακολουθίες byte στη μνήμη.
Αν και ονομάζονται _εντολές συμβολοσειρών_, μπορούν να χρησιμοποιηθούν με οποιαδήποτε ακολουθία byte στη μνήμη, δηλαδή με οποιονδήποτε πίνακα:

| εντολή       | τι κάνει                                                                                                         |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| [lods][lods] | φορτώνει μια τιμή από μια θέση μνήμης που υποδεικνύεται από το `rsi` στο `rax`                                    |
| [stos][stos] | αποθηκεύει μια τιμή από το `rax` σε μια θέση μνήμης που υποδεικνύεται από το `rdi`                                |
| [movs][movs] | αντιγράφει μια τιμή από μια θέση μνήμης που υποδεικνύεται από το `rsi` και την αποθηκεύει σε μια θέση μνήμης που υποδεικνύεται από το `rdi` |
| [cmps][cmps] | συγκρίνει την τιμή σε μια θέση μνήμης που υποδεικνύεται από το `rsi` με την τιμή σε μια θέση μνήμης που υποδεικνύεται από το `rdi` |
| [scas][scas] | συγκρίνει την τιμή στο `rax` με την τιμή σε μια θέση μνήμης που υποδεικνύεται από το `rdi`                        |

Σημείωσε ότι αυτές οι εντολές _δεν_ παίρνουν κανένα ρητό τελεστέο.
Οι τελεστέοι τους είναι έμμεσοι.

Ως γενικός κανόνας:

1. Όταν ο τελεστέος προέλευσης είναι μια θέση μνήμης, η διεύθυνσή της πρέπει να αποθηκεύεται στο `rsi` (`s` για source).
2. Όταν ο τελεστέος προορισμού είναι μια θέση μνήμης, η διεύθυνσή της πρέπει να αποθηκεύεται αντ' αυτού στο `rdi` (`d` για destination).
3. Αν ένας από τους τελεστέους δεν είναι θέση μνήμης, τότε είναι ο καταχωρητής `rax`.

Σημείωσε ότι αυτές οι εντολές αποαναφέρουν αυτόματα τις διευθύνσεις μνήμης σύμφωνα με τη συγκεκριμένη λειτουργία που εκτελούν.

Όλες τους μπορούν να λειτουργήσουν σε διαφορετικά μεγέθη.
Προστίθεται ένα επίθημα για να δηλώσει αυτό το μέγεθος:

| επίθημα | σημασία | μέγεθος |
| :----: | ------- | :------ |
|  `b`   | byte    | 1 byte  |
|  `w`   | word    | 2 byte |
|  `d`   | dword   | 4 byte |
|  `q`   | qword   | 8 byte |

Για παράδειγμα:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
cmpsd ; compares one dword (4 bytes) in the memory locations whose addresses are in `rsi` and `rdi`, setting flags as per `cmp`
```

Ενημερώνουν επίσης κάθε διεύθυνση που χρησιμοποιείται κατά το μέγεθος της λειτουργίας.
Αυτή η ενημέρωση γίνεται σύμφωνα με την τιμή της **σημαίας κατεύθυνσης (DF)**:

- Αν η `DF` έχει καθαριστεί, οι διευθύνσεις _αυξάνονται_ κατά το μέγεθος της λειτουργίας.
- Αν η `DF` έχει οριστεί, οι διευθύνσεις αντ' αυτού _μειώνονται_ κατά το ίδιο ποσό.

Το ABI System V ορίζει ότι η σημαία κατεύθυνσης πρέπει να έχει καθαριστεί κατά την είσοδο σε μια συνάρτηση.
Έτσι, _η προεπιλεγμένη συμπεριφορά είναι η μνήμη να διαβάζεται/γράφεται σε αύξουσα σειρά διευθύνσεων_.

Η εντολή [cld][cld] μπορεί να χρησιμοποιηθεί για να καθαρίσει τη σημαία κατεύθυνσης, ενώ η εντολή [std][std], για να την ορίσει:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Ο καλών αναμένει η `DF` να έχει καθαριστεί αφού επιστρέψει οποιαδήποτε καλούμενη συνάρτηση, σύμφωνα με το ABI System V.
Αν ποτέ ορίσεις τη `DF`, φρόντισε να την καθαρίσεις πριν από το `ret`.
~~~~

### Lods

Αυτή η εντολή _διαβάζει_ από μια θέση μνήμης της οποίας η διεύθυνση βρίσκεται στο `rsi` και αντιγράφει την τιμή στο `rax`.

Η τιμή στο `rsi` ενημερώνεται κατά τον αριθμό των byte που διαβάστηκαν:

```x86asm
lodsq ; copies one qword (8 bytes) from the address indicated by `rsi` to `rax`
; the address in `rsi` is now increased or decreased by 8, according to `DF` (by default, increased)
```

### Stos

Αυτή η εντολή αντιγράφει την τιμή στο `rax` και τη _γράφει_ σε μια θέση μνήμης της οποίας η διεύθυνση βρίσκεται στο `rdi`.

Η τιμή στο `rdi` ενημερώνεται κατά τον αριθμό των byte που γράφτηκαν:

```x86asm
stosw ; copies one word (2 bytes) from `rax` to the address indicated by `rdi`
; the address in `rdi` is now increased or decreased by 2, according to `DF` (by default, increased)
```

### Movs

Αυτή η εντολή _διαβάζει_ από μια θέση μνήμης της οποίας η διεύθυνση βρίσκεται στο `rsi` και _γράφει_ την τιμή σε μια θέση μνήμης της οποίας η διεύθυνση βρίσκεται στο `rdi`.
Η τιμή στο `rax` δεν επηρεάζεται από αυτή την εντολή.

Τόσο το `rsi` όσο και το `rdi` ενημερώνονται κατά τον αριθμό των byte που αντιγράφηκαν από τη μια θέση μνήμης στην άλλη:

```x86asm
movsb ; copies one byte from the address indicated by `rsi` to the address indicated by `rdi`
; the addresses in `rsi` and `rdi` are now increased or decreased by 1, according to `DF` (by default, increased)
```

### Cmps

Αυτή η εντολή _διαβάζει_ από μια θέση μνήμης της οποίας η διεύθυνση βρίσκεται στο `rsi` και επίσης _διαβάζει_ από μια θέση μνήμης της οποίας η διεύθυνση βρίσκεται στο `rdi`.
Στη συνέχεια συγκρίνει τις τιμές και ενημερώνει τις σημαίες, σύμφωνα με την `cmp`.

Τόσο το `rsi` όσο και το `rdi` ενημερώνονται κατά τον αριθμό των byte που διαβάστηκαν και από τις δύο θέσεις:

```x86asm
cmpsd ; reads one dword (4 bytes) from the addresses indicated by `rsi` and `rdi` and compares them
; the addresses in `rsi` and `rdi` are now increased or decreased by 4, according to `DF` (by default, increased)
```

### Scas

Αυτή η εντολή συγκρίνει την τιμή στο `rax` με την τιμή που _διαβάζει_ από μια θέση μνήμης της οποίας η διεύθυνση βρίσκεται στο `rdi`.
Στη συνέχεια ενημερώνει τις σημαίες, σύμφωνα με την `cmp`.

Η τιμή στο `rdi` ενημερώνεται κατά τον αριθμό των byte που διαβάστηκαν:

```x86asm
scasb ; compares one byte in `rax` with 1 byte read from the memory location whose address is in `rdi`
; the address in `rdi` is now increased or decreased by 1, according to `DF` (by default, increased)
```

### Rep

Εκτός από αυτές, η εντολή [rep][rep] δεν αλληλεπιδρά άμεσα με τη μνήμη.
Αντ' αυτού, μπορεί να προστεθεί ως πρόθεμα στις άλλες εντολές που αναφέρθηκαν, _επαναλαμβάνοντας_ αυτές τις εντολές.

Όταν έχουν ως πρόθεμα το `rep`, οι εντολές συμβολοσειρών επαναλαμβάνονται τόσες φορές όσες η τιμή στο `rcx`.
Κάθε φορά, η τιμή στο `rcx` μειώνεται κατά `1`.
Σημείωσε ότι η τιμή στο `rcx` πρέπει να οριστεί πριν χρησιμοποιηθεί η εντολή:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

Εκτός από τη χρήση του `rcx` ως μετρητή, οι `repe` (ή `repz`) και `repne` (ή `repnz`) σταματούν την εκτέλεση αν η `zero flag (ZF)` έχει καθαριστεί ή οριστεί, αντίστοιχα:

| εντολή      | πού μπορεί να προστεθεί     | μπορεί να σταματήσει νωρίτερα        |
| ---------------- | ---------------------- | ----------------------- |
| `rep`            | `movs`, `lods`, `stos` | όχι                      |
| `repe`,`repz`    | `cmps`, `scas`         | ναι, σταματά όταν το ZF είναι 0 |
| `repne`, `repnz` | `cmps`, `scas`         | ναι, σταματά όταν το ZF είναι 1 |

~~~~exercism/advanced
Σε σύγχρονους επεξεργαστές, οι `rep movs` και `rep stos` είναι συνήθως γρήγορες επιλογές όταν μετακινείς δεδομένα σε μεγάλα μπλοκ.
Οι άλλες εντολές συμβολοσειρών, ακόμη και οι `movs` και `stos` όταν λειτουργούν χωρίς το `rep`, ωστόσο, είναι συνήθως πιο αργές από έναν απλό βρόχο.

Μια πιο εις βάθος ματιά σε αυτό το θέμα μπορείς να βρεις στο [Κεφάλαιο 16.9, "String instructions", αυτού του βιβλίου αναφοράς][agner-optimization-guide].
