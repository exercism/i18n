# Σχετικά

Είναι απίθανο να συναντήσεις πολύ κώδικα παραγωγής που να μην κάνει χρήση χώρων ονομάτων.

Ένα παράδειγμα της σύνταξης είναι:

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

Οι χώροι ονομάτων είναι ένας τρόπος να ομαδοποιείς σχετικό κώδικα και να αποφεύγεις συγκρούσεις ονομάτων.

Σύμφωνα με την [επίσημη τεκμηρίωση][namespaces], οι χώροι ονομάτων έχουν δύο κύριους ρόλους:

- Πρώτον, το .NET χρησιμοποιεί χώρους ονομάτων για να οργανώνει τις πολλές κλάσεις του
- Δεύτερον, η δήλωση των δικών σου χώρων ονομάτων μπορεί να σε βοηθήσει να ελέγχεις την εμβέλεια των ονομάτων κλάσεων και μεθόδων σε μεγαλύτερα έργα προγραμματισμού.

Οι χώροι ονομάτων χρησιμοποιούνται ευρέως από τη βιβλιοθήκη βασικών κλάσεων (BCL) για να οργανώσει τη λειτουργικότητά της.

## Αναφορές σε τύπους που ανήκουν σε χώρους ονομάτων

Οι τύποι που περιέχονται σε χώρους ονομάτων αναφέρονται έξω από τον χώρο ονομάτων βάζοντας μπροστά από το όνομα του τύπου τη σύνταξη με την τελεία. Εναλλακτικά, και πιο συνηθισμένα, μπορείς να βάλεις μια οδηγία `using` στην αρχή του αρχείου (ή μέσα σε έναν χώρο ονομάτων) και τότε οποιοσδήποτε τύπος στον εισαγόμενο χώρο ονομάτων μπορεί να χρησιμοποιηθεί χωρίς το πρόθεμα. Μέσα στον ίδιο χώρο ονομάτων δεν χρειάζεται να προσδιορίζεις τα ονόματα των τύπων.

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

Αυτό το [άρθρο][using] εξηγεί καθαρά τους τρόπους με τους οποίους μπορεί να χρησιμοποιηθεί η οδηγία `using`:

- `using`: αποφεύγεις να χρειάζεται να προσδιορίζεις τύπους με τον χώρο ονομάτων
- `using static`: αποφεύγεις να χρειάζεται να προσδιορίζεις μέλη με τύπους (ένα καλό παράδειγμα είναι το `Math.Max()`).
- `using MyAlias = YourNamespace;`: αντικαθιστάς το όνομα του χώρου ονομάτων με ένα πιο ευανάγνωστο όνομα.

## Σύγκρουση χώρων ονομάτων

Το .NET αντιμετωπίζει το ζήτημα δύο χώρων ονομάτων με το ίδιο όνομα σε διαφορετικές συγκροτήσεις, όπου θα υπήρχε σύγκρουση πλήρως αναγνωρισμένων ονομάτων αναγνωριστικών (ίσως ένα σενάριο όπου φορτώνονται πολλές εκδόσεις μιας συγκρότησης). Το ζήτημα αυτό αντιμετωπίζεται με τον [προσδιοριστή ψευδωνύμου χώρου ονομάτων][namespace-alias-qualifier] και το [ψευδώνυμο extern][extern-alias].

Ένας λόγος για να αναφέρουμε αυτό το αρκετά εξειδικευμένο θέμα είναι η χρήση του [τελεστή `::`][dot-dot-operator]. Θα δεις συχνά τον προσδιοριστή `global::` μπροστά από χώρους ονομάτων, ειδικά σε παραγόμενο κώδικα. Η πρόθεση εδώ είναι να αποφευχθεί μια πιθανή σύγκρουση με κάποιον εμφωλευμένο χώρο ονομάτων ή όνομα κλάσης. Βάζοντας το πρόθεμα `global::` σε έναν χώρο ονομάτων, διασφαλίζεις ότι επιλέγεται ένας χώρος ονομάτων ανώτατου επιπέδου.

## Σημείωση για προγραμματιστές Java

Όταν συγκρίνεις με το `import` των `packages` της Java, αξίζει να σημειώσεις κάποιες διαφορές και ομοιότητες:

- Δεν υπάρχει αντίστοιχο στην C# για την εισαγωγή συγκεκριμένων τύπων.
- Τα `using static` και `import static` είναι ισοδύναμα.
- Στη Java, τα ονόματα των πακέτων επηρεάζουν την προσβασιμότητα μεταξύ των jars. Στην C#, οι συγκροτήσεις είναι αυτές που μετράνε και το να ανήκεις στον ίδιο χώρο ονομάτων δεν επηρεάζει το επίπεδο πρόσβασης.
- Η σχέση ανάμεσα στις διαδρομές του συστήματος αρχείων και στα πλήρως αναγνωρισμένα ονόματα κλάσεων στη Java δεν αποτυπώνεται στους χώρους ονομάτων της C#, αν και είναι καλή πρακτική, όπου είναι δυνατόν, να δίνεις σε ένα αρχείο το ίδιο όνομα με την κύρια κλάση που περιέχει.
