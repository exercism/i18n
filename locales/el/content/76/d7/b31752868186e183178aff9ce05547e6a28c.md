# Εισαγωγή

## Ορολογία

Έχεις ήδη χρησιμοποιήσει και γράψει συναρτήσεις C++ σε μερικές έννοιες.
Ήρθε η ώρα να γίνουμε τεχνικοί.
Το παρακάτω απόσπασμα κώδικα δείχνει τους πιο συνηθισμένους όρους για εύκολη αναφορά.
Επειδή η C++ αγνοεί τα κενά διαστήματα, η μορφοποίηση έχει αλλάξει ώστε κάθε στοιχείο να βρίσκεται σε μία γραμμή.

```cpp
// Function declaration:
bool                                              // Return type
admin_detected(string user, string password)      // Type signature
;                                                 // Don't forget the ';' for the declaration

// Function definition:
bool                                              // Return type
admin_detected                                    // Function name
(string user, string password)                    // Parameter list
{ return user == "admin" && password == "1234"; } // Function body
```
~~~~exercism/advanced
Η δήλωση λειτουργεί σαν ένα σημείωμα προς τον μεταγλωττιστή, ότι υπάρχει μια συνάρτηση με αυτό το όνομα, τον τύπο επιστροφής και τη λίστα παραμέτρων.
Ο κώδικας δεν θα λειτουργήσει, αν λείπει ο ορισμός.
Οι δηλώσεις είναι προαιρετικές, χρειάζονται αν χρησιμοποιείς τη συνάρτηση πριν από τον ορισμό της.
Οι δηλώσεις μπορούν να λύσουν προβλήματα όπως οι κυκλικές αναφορές και μπορούν να χρησιμοποιηθούν για να διαχωρίσουν τη διασύνδεση από την υλοποίηση.
~~~~

## Ο προσδιοριστής `const`

Μερικές φορές θέλεις να βεβαιωθείς ότι οι τιμές δεν μπορούν να αλλάξουν αφού έχουν αρχικοποιηθεί.
Η C++ χρησιμοποιεί τη λέξη-κλειδί `const` ως προσδιοριστή για σταθερές.

```cpp
const int number_of_dragon_balls{7};
number_of_dragon_balls--; // compilation error
```

~~~~exercism/note
Θα δεις συχνά σταθερές γραμμένες σε _UPPER_SNAKE_CASE_.
Συνιστάται να κρατάς αυτό το σχήμα κεφαλαίων για τις μακροεντολές, αν δεν υπάρχει κάποια άλλη σύμβαση.
~~~~

Αν προσπαθήσεις να αλλάξεις μια σταθερή μεταβλητή αφού έχει οριστεί, ο κώδικάς σου δεν θα μεταγλωττιστεί.
Αυτό βοηθά να αποφύγεις ακούσιες αλλαγές, αλλά ανοίγει και δυνατότητες βελτιστοποίησης για τον μεταγλωττιστή.
Ως άνθρωπος, είναι επίσης πιο εύκολο να συλλογιστείς πάνω στον κώδικα, αν ξέρεις ότι ορισμένα μέρη δεν θα επηρεαστούν.

Μπορείς επίσης να έχεις το `const` ως προσδιοριστή για παραμέτρους συνάρτησης.

```cpp
string guess_number(const int& secret, const int& guess) {
    if (secret < guess) return "lower.";
    if (secret > guess) return "higher.";
    return "exact!";
}
```

Όταν περνάς μια αναφορά `const` στη συνάρτηση, μπορείς να είσαι σίγουρος ότι θα μείνει αμετάβλητη.
Θα δεις συχνά αναφορές `const` για αντικείμενα των οποίων το αντίγραφο μπορεί να είναι δαπανηρό, όπως οι μεγαλύτερες συμβολοσειρές.
Μια τρίτη περίπτωση χρήσης για τον προσδιοριστή `const` είναι οι συναρτήσεις μέλους που δεν αλλάζουν το στιγμιότυπο μιας κλάσης.

```cpp
class Stubborn {
    public:
    Stubborn(string reply) {
        response = reply;
    }
    string answer(const string& question) const {
        if (question.length() == 0) { return ""; }
        return response;
    }
    private:
    string response{};
};
```

Η συνάρτηση μέλους `answer` της `Stubborn` χρησιμοποιεί μια αναφορά `const string&` ως παράμετρο.
Αυτό αποφεύγει μια πράξη αντιγραφής από το αρχικό αντικείμενο που πέρασε στη συνάρτηση.

## Υπερφόρτωση συναρτήσεων

Πολλές συναρτήσεις μπορούν να έχουν το ίδιο όνομα, αν η λίστα παραμέτρων είναι διαφορετική.
Αυτό λέγεται υπερφόρτωση συναρτήσεων και γίνεται συνήθως όταν αυτές οι συναρτήσεις εκτελούν πολύ παρόμοιες εργασίες.

Η κεφαλίδα της συνάρτησης χωρίς τον τύπο επιστροφής είναι η __υπογραφή τύπου__ της συνάρτησης.
Μια αλλαγή στην υπογραφή τύπου έχει ως αποτέλεσμα μια νέα συνάρτηση.

Το παράδειγμα `play_sound` έχει έξι διαφορετικές υπερφορτώσεις για να καλύψει διαφορετικά σενάρια:

```cpp
// different argument types:
void play_sound(char note);         // C, D, E, ..., B
void play_sound(string solfege);    // do, re, mi, ..., ti
void play_sound(int jianpu);        // 1, 2, 3, ..., 7

// different number of arguments:
void play_sound(string solfege, double duration);

// different qualifiers:
void play_sound(vector<string>& solfege);
void play_sound(const vector<string>& solfege);
```

~~~~exercism/advanced
Η υπογραφή τύπου ορίζεται από το όνομα της συνάρτησης, τον αριθμό των παραμέτρων, τους τύπους τους και τους προσδιοριστές τους (αλλά όχι τα ονόματά τους).
Ο τύπος επιστροφής δεν αποτελεί ρητά μέρος της υπογραφής τύπου και θα πάρεις σφάλματα μεταγλώττισης αν έχεις δύο συναρτήσεις που διαφέρουν μόνο ως προς τον τύπο επιστροφής.
Ο μεταγλωττιστής θα παραπονεθεί επειδή δεν είναι ξεκάθαρο ποια από τις δύο πρέπει να χρησιμοποιηθεί.
~~~~

## Προεπιλεγμένα ορίσματα

Κάποιες συναρτήσεις μπορεί να γίνουν πολύ μεγάλες και πολλές από τις κλήσεις τους μπορεί να χρησιμοποιούν τις ίδιες τιμές για τις περισσότερες παραμέτρους.
Η επανάληψη σε αυτές τις κλήσεις μπορεί να αποφευχθεί με προεπιλεγμένα ορίσματα.

```cpp
void record_new_horse_birth(string name, int weight, string color="brown-ish", string dam="Alruccaba", string sire="Poseidon");

record_new_horse_birth("Urban Sea", 130); // color will be brown, dam "Alruccabam", sire "Poseidon"
record_new_horse_birth("Highclere", 175, "off-white", "Fall Aspen");   // sire will be "Poseidon"
```

Επειδή η δήλωση της συνάρτησης συχνά διαβάζεται πριν από τον ορισμό, είναι το καλύτερο σημείο για να ορίσεις τα προεπιλεγμένα ορίσματα.
Αν μια παράμετρος έχει προεπιλεγμένη δήλωση, όλες οι παράμετροι στα δεξιά της χρειάζονται επίσης προεπιλεγμένη δήλωση.
Μερικές φορές οι περίπλοκες υπερφορτώσεις συναρτήσεων μπορούν να αναδιαμορφωθούν σε λιγότερες συναρτήσεις με προεπιλεγμένα ορίσματα, βελτιώνοντας τη συντηρησιμότητα.
