# Σχετικά

Ένας [βρόχος][control] είναι μια ακολουθία εντολών που μπορεί να εκτελεστεί περισσότερες από μία φορές, μέχρι να ικανοποιηθεί μια συνθήκη τερματισμού.

Στο x86-64 ένας βρόχος δημιουργείται συνήθως με ένα άλμα σε μια προηγούμενη ετικέτα:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Σημείωσε ότι ένα άλμα χωρίς συνθήκη σε μια προηγούμενη ετικέτα μεταφέρει πάντα την εκτέλεση σε αυτή την ετικέτα.
Αυτό σημαίνει ότι ο βρόχος θα επαναλαμβάνεται για πάντα, εκτός αν υπάρχει κάποιο άλλο άλμα έξω από την ακολουθία που επαναλαμβάνεται.

Για παράδειγμα, αυτός ο βρόχος δεν τελειώνει:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

Και αυτός ο βρόχος μπορεί να τελειώσει, ανάλογα με το αν ικανοποιείται η συνθήκη:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## Βρόχοι μέτρησης

Ένας βρόχος μέτρησης τελειώνει σχεδόν πάντα με τον ίδιο τρόπο: μια εντολή που ενημερώνει έναν μετρητή ή συγκρίνει δύο τιμές, αμέσως ακολουθούμενη από ένα υπό συνθήκη άλμα που αποφασίζει αν θα ξαναγίνει ο κύκλος.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
Το `cmp rsi, 0` δεν είναι απαραίτητο στον παραπάνω κώδικα, επειδή το `sub rsi, 1` θέτει ήδη το `zero flag (ZF)` όταν το αποτέλεσμα είναι `0`.

Αν και το `cmp` είναι ο κύριος τρόπος με τον οποίο ελέγχονται οι συνθήκες στη assembly, πολλές εντολές ενημερώνουν τις σημαίες.
Για παράδειγμα, πολλές ακέραιες αριθμητικές εντολές ή εντολές bitwise ενημερώνουν το `ZF` όταν το αποτέλεσμα είναι `0` και το `SF` όταν το αποτέλεσμα είναι αρνητικό (δηλαδή, όταν έχει τεθεί το πιο σημαντικό bit).

Μπορείς να συμβουλευτείς μια [αναφορά][reference] για να δεις ποιες σημαίες επηρεάζει κάθε εντολή.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Σημείωσε ότι στο παραπάνω παράδειγμα, υποθέτουμε ότι το `rsi` είναι μεγαλύτερο από το `0`.
Αν ήταν `0`, τότε το `sub rsi, 1` θα μείωνε το `rsi` σε `-1`, που είναι ένας πολύ μεγάλος αριθμός χωρίς πρόσημο.
Θα χρειάζονταν `18,446,744,073,709,551,615` ακόμη επαναλήψεις μέχρι να τελειώσει επιτέλους ο βρόχος.
Επίσης, επειδή το μήκος του πίνακα είναι `0`, οποιαδήποτε πρόσβαση στη μνήμη θα ήταν εκτός ορίων.

Αν δεν υπάρχουν εγγυήσεις για το μήκος ενός πίνακα, υπάρχουν δύο συνηθισμένες προσεγγίσεις.

Η πρώτη είναι να μεταφέρεις τη συνθήκη τερματισμού στην αρχή του βρόχου και μετά να έχεις ένα άλμα χωρίς συνθήκη στο τέλος:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

Η δεύτερη είναι να ελέγχεις μία φορά για πίνακα μηδενικού μήκους πριν από την αρχή του βρόχου:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Αυτή η δεύτερη προσέγγιση είναι συνήθως πιο αποδοτική από την πρώτη, επειδή υπάρχουν λιγότερες διακλαδώσεις στο σώμα του βρόχου.
Θα μάθεις περισσότερα γι' αυτό σε μια μελλοντική έννοια.

## Μικρο-λειτουργίες

Ένας επεξεργαστής δεν εκτελεί απευθείας μια εντολή όπως η `add` ή η `jnz`.
Το front-end της CPU πρώτα _αποκωδικοποιεί_ κάθε εντολή σε ένα ή περισσότερα μικρότερα εσωτερικά βήματα, που ονομάζονται **μικρο-λειτουργίες** (ή **micro-ops**).
Στη συνέχεια ο επεξεργαστής προγραμματίζει και εκτελεί αυτές τις μικρο-λειτουργίες, συχνά αρκετές ανά κύκλο και έξω από την αρχική τους σειρά.

Οι περισσότερες απλές εντολές αποκωδικοποιούνται σε μία μόνο μικρο-λειτουργία, ενώ μια πιο σύνθετη εντολή μπορεί να αποκωδικοποιηθεί σε αρκετές.
Επειδή ο πραγματικός φόρτος εργασίας του επεξεργαστή είναι η ροή των μικρο-λειτουργιών, η παραγωγή λιγότερων από αυτές για την ίδια εργασία είναι ένας τρόπος για να γίνει ο κώδικας ταχύτερος.

## Μακροσύντηξη

Όπως αναφέρθηκε προηγουμένως, ένας βρόχος τελειώνει συνήθως με κάποιο είδος υπό συνθήκη άλματος.
Αυτό είναι τόσο συνηθισμένο που οι σύγχρονοι επεξεργαστές είναι βελτιστοποιημένοι για αυτό το μοτίβο κατά την αποκωδικοποίηση.

Μια εντολή που θέτει σημαίες, αμέσως ακολουθούμενη από ένα υπό συνθήκη άλμα που διαβάζει αυτές τις σημαίες, μπορεί να αποκωδικοποιηθεί μαζί σε **μία μόνο** μικρο-λειτουργία, αντί για μία η καθεμία.
Αυτό ονομάζεται **μακροσύντηξη**.

Το συγχωνευμένο ζεύγος συμπεριφέρεται ως μία λειτουργία: ο μετρητής ενημερώνεται και η απόφαση διακλάδωσης λαμβάνεται μαζί, σε μία μόνο μικρο-λειτουργία.
Η ροή ελέγχου του βρόχου τότε δεν κοστίζει σχεδόν τίποτα πάνω από τη δουλειά που κάνει στην πραγματικότητα ο βρόχος.

Κατά κανόνα, δύο είδη ζευγών συνήθως συγχωνεύονται με αυτόν τον τρόπο:

- Αριθμητικές εντολές όπως οι `add` ή `sub`, αμέσως ακολουθούμενες από ένα υπό συνθήκη άλμα.
- Μια `cmp`, `test` ή `and`, αμέσως ακολουθούμενη από ένα υπό συνθήκη άλμα.

```x86asm
    ...
    add rdi, 8       ; advance a pointer
    cmp rdi, rsi     ; compare it against the end address
    jb .loop         ; repeat while still below the end
```

Η συγχώνευση συμβαίνει μόνο όταν το υπό συνθήκη άλμα έρχεται **αμέσως** μετά την εντολή που θέτει τις σημαίες, χωρίς τίποτα ανάμεσά τους.

~~~~exercism/note
Η μακροσύντηξη εξαρτάται από την CPU και υπάρχει κάποια διακύμανση ως προς το ποιες εντολές συγχωνεύονται με ποιο υπό συνθήκη άλμα.

Μια χρήσιμη αναφορά είναι [Η μικροαρχιτεκτονική των επεξεργαστών Intel, AMD και VIA, του Agner Fog][agner-uarch].
Η ενότητα 3.4.2.2 (Βελτιστοποίηση για μακροσύντηξη) του [εγχειριδίου αναφοράς βελτιστοποίησης της Intel][intel-opt] παραθέτει επίσης ζεύγη που μπορούν να συγχωνευτούν για επεξεργαστές Intel.

[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
~~~~

## Η εντολή `loop`

Υπάρχουν κάποιες εντολές που μπορούν να χρησιμοποιηθούν για να δημιουργήσουν συμπεριφορά παρόμοια με βρόχο.
Μία από αυτές είναι η [loop][loop].

Ο μοναδικός της τελεστέος είναι μια ετικέτα που περιέχει τη διεύθυνση της αρχής του βρόχου.

Η εντολή `loop` χρησιμοποιεί την τιμή στο `rcx` ως μετρητή, μειώνοντάς την κατά 1 κάθε φορά.
Μόλις η τιμή στο `rcx` φτάσει στο μηδέν, ο βρόχος τελειώνει και η εκτέλεση συνεχίζει διαδοχικά:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    loop .example ; this repeats the sequence starting in .example 10 times (the value in rcx)
                  ; at each time, rcx is decremented by 1
```

Υπάρχουν δύο παραλλαγές της εντολής `loop` που ελέγχουν τη σημαία μηδενός (`ZF`) σε κάθε επανάληψη.
Εκτός από το ότι σταματούν τον βρόχο μόλις το `rcx` φτάσει στο μηδέν, σταματούν επίσης όταν η συνθήκη _δεν_ ικανοποιείται.

| εντολή            | συνθήκη   |
| ----------------- | --------- |
| `loope`/`loopz`   | `ZF` == 1 |
| `loopne`/`loopnz` | `ZF` == 0 |

Το `ZF` **δεν τίθεται** από αυτές τις εντολές.
Πρέπει να υπάρχει μια `cmp`, `test` ή κάποια άλλη εντολή που αλλάζει το `ZF` πριν από αυτές:

```x86asm
section .text
fn:
    mov rax, 0
    mov rcx, 10
.example:
    inc rax
    cmp rax, 3
    loopne .example ; this repeats the sequence starting in .example while rcx > 0 and rax != 3
```

~~~~exercism/caution
Παρά την ευκολία τους, οι `loop`, `loope` και `loopne` είναι συνήθως πολύ πιο αργές στους σύγχρονους επεξεργαστές από την αντίστοιχη ακολουθία `sub`/`jnz` ή `cmp`/`jnz`.

Μια καλή αναφορά για την απόδοση των εντολών σε πολλούς διαφορετικούς επεξεργαστές είναι οι [πίνακες του Agner][agner-tables].

[agner-tables]: https://www.agner.org/optimize/instruction_tables.pdf
~~~~
