# Προσθήκη οδηγιών

## Πλεονεκτήματα και μειονεκτήματα της `from_quote`
Αυτή η άσκηση ορίζει μια συνάρτηση `from_quote` στον τύπο `Card`. Αυτό σου επιτρέπει να γράψεις κώδικα σαν τον παρακάτω:

```roc
card : Card
card = "Q"
```

Αυτός ο κώδικας καλεί έμμεσα τη `Card.from_quote("Q")` σε χρόνο μεταγλώττισης. Αυτό μπορεί δυνητικά να κάνει το πρόγραμμα πιο γρήγορο, αφού δεν χρειάζεται να χειρίζεται το parsing σε χρόνο εκτέλεσης, και διασφαλίζει ότι οι κάρτες που απορρίπτονται από τη `from_quote` εντοπίζονται σε χρόνο μεταγλώττισης αντί σε χρόνο εκτέλεσης. Επιπλέον, κάνει τον κώδικα ωραίο και ευανάγνωστο. Για παράδειγμα, ορίστε ένα από τα τεστ αυτής της άσκησης:

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

Ωστόσο, κάποιος που διαβάζει αυτόν τον κώδικα μπορεί να υποθέσει ότι η συνάρτηση `simulate_game` παίρνει μια καταγραφή που περιέχει δύο `List(Str)`, ενώ στην πραγματικότητα είναι μια καταγραφή που περιέχει δύο `List(Card)`. Αυτό μπορεί να προκαλέσει σύγχυση και λάθη. Για αυτόν τον λόγο, μπορεί να προτιμήσεις τη λίγο μεγαλύτερη αλλά πιο ρητή μορφή: `"Q".Card`, η οποία καλεί επίσης τη `from_quote` σε χρόνο μεταγλώττισης.

Στα δικά σου προγράμματα, μπορεί να προτιμήσεις να χρησιμοποιήσεις τη `from_str` αντ' αυτής:

```roc
Card := { ... }.{
    from_str : card_str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

Μπορείς επίσης να καλέσεις τη `from_str` (ή οποιαδήποτε άλλη καθαρή συνάρτηση) σε χρόνο μεταγλώττισης, όπως εδώ:

```roc
Ok(card) = Card.from_str("Q")
```

Σημείωση: Αν τοποθετήσεις αυτόν τον ορισμό στο ανώτατο επίπεδο, εκτελείται σε χρόνο μεταγλώττισης (αφού η συνάρτηση είναι καθαρή και η είσοδός της είναι γνωστή σε χρόνο μεταγλώττισης). Μέσα σε μια συνάρτηση, μπορείς να χρησιμοποιήσεις τη `from_str` σε χρόνο εκτέλεσης.
