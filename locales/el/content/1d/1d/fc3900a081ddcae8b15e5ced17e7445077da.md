# Σχετικά

Η προετοιμασία μιας τιμής για μετάδοση σημαίνει τρία πράγματα ταυτόχρονα:
να τη σειριοποιήσεις, να διαλέξεις το σωστό κομμάτι της και να μην την
αντιγράψεις όταν δεν χρειάζεται. Τρία ιδιώματα της Factor καλύπτουν αυτό το
πεδίο.

## `unparse`: από τιμή σε πηγαίο κείμενο

Το [`unparse`][unparse] (στο `prettyprint`) επιστρέφει το κείμενο σε μορφή
πηγαίου κώδικα οποιασδήποτε τιμής. Είναι το αντίστροφο του parser: η
αμφίδρομη διαδρομή `dup unparse parse` ανακατασκευάζει την τιμή.

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

Σύγκρινέ το με το `>string` (που δουλεύει μόνο σε ακολουθίες χαρακτήρων) και
το `number>string` (μόνο αριθμούς). Το `unparse` είναι το καθολικό, με το
κόστος να παράγει σύνταξη της Factor (οι συμβολοσειρές σε εισαγωγικά κρατούν
τα εισαγωγικά τους), οπότε είναι το σωστό εργαλείο όταν ο παραλήπτης θα
αναλύσει ξανά το κείμενο και το λάθος εργαλείο για έξοδο αναγνώσιμη από
άνθρωπο.

## Slices: προβολές, όχι αντίγραφα

| λέξη          | αποτέλεσμα                                     |
|---------------|------------------------------------------------|
| `head`        | `( seq n -- newseq )`: αντιγράφει τα πρώτα n    |
| `head-slice`  | `( seq n -- slice )`: προβολή των πρώτων n      |
| `tail`        | `( seq n -- newseq )`: αντιγράφει από τη θέση n και μετά |
| `tail-slice`  | `( seq n -- slice )`: προβολή από τη θέση n και μετά |
| `head*`       | `( seq n -- newseq )`: αντιγράφει όλα εκτός από τα τελευταία n |
| `head-slice*` | `( seq n -- slice )`: προβολή όλων εκτός από τα τελευταία n |
| `tail*`       | `( seq n -- newseq )`: αντιγράφει τα τελευταία n |
| `tail-slice*` | `( seq n -- slice )`: προβολή των τελευταίων n  |

Ένα `slice` είναι ένα tuple που κρατά μια θέση αρχής, μια θέση τέλους και την
υποκείμενη ακολουθία: υλοποιεί το [πρωτόκολλο ακολουθίας][sequence-protocol],
οπότε οποιαδήποτε πράξη σε ακολουθία δουλεύει πάνω του. Προτίμησε τις
παραλλαγές με slice όταν αλλιώς θα δεσμεύσεις μνήμη μόνο και μόνο για να
διαβάσεις· προτίμησε τις παραλλαγές που αντιγράφουν όταν πρέπει να κρατήσεις
τα δεδομένα μετά από ενδεχόμενη αλλαγή της υποκείμενης ακολουθίας.

## Cleave πολλαπλών εισόδων: `2bi`, `3bi`, `2tri`, `3tri`

Οι απλές λέξεις cleave `bi` και `tri` εφαρμόζουν δύο ή τρεις παραθέσεις σε
*μία* είσοδο στη στοίβα. Οι παραλλαγές με πρόθεμα `2` και `3` εφαρμόζουν κάθε
παράθεση σε *δύο* ή *τρεις* εισόδους:

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

Κάθε παράθεση δέχεται *όλες* τις εισόδους, οπότε χρησιμοποίησε το `2bi` όταν
και οι δύο προβολές εξαρτώνται από το ζεύγος, όχι όταν θέλεις την ίδια προβολή
να εφαρμόζεται σε κάθε είσοδο ξεχωριστά (αυτό είναι το `bi@`).

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

Για *μία* παράθεση που εφαρμόζεται σε κάθε είσοδο ξεχωριστά, προτίμησε το
`bi@` (δύο είσοδοι) ή το `tri@` (τρεις είσοδοι) αντ' αυτού: ίδια οικογένεια,
διαφορετικό σχήμα.
