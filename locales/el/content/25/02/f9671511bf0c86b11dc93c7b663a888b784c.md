# Εισαγωγή

Σε πολλές αντικειμενοστρεφείς γλώσσες, είναι συνηθισμένο να επεκτείνεις συμπεριφορές [δημιουργώντας μια υποκλάση][wiki-subclass] μιας γονικής κλάσης, κληρονομώντας μεθόδους από τη γονική κλάση και προσθέτοντας παράλληλα νέες.
Έτσι δημιουργείται μια ιεραρχία αντικειμένων.

Η Julia _δεν έχει κλάσεις_, άρα κατ' επέκταση _δεν έχει και υποκλάσεις_.
Πώς κληρονομούμε και επεκτείνουμε υπάρχουσες συμπεριφορές;

Σε προηγούμενες έννοιες είδαμε πώς δημιουργείται μια ιεραρχία τύπων, καθώς και πώς η Julia χρησιμοποιεί το [multiple dispatch][concept-multiple-dispatch] για να επιλέγει μεθόδους με βάση τους τύπους των ορισμάτων.

Η Julia έχει επίσης αρκετές ανεπίσημες διεπαφές, που επιτρέπουν στους προσαρμοσμένους τύπους σου να συνδεθούν με συμπεριφορές που έχουν ήδη οριστεί για τους τυπικούς τύπους.

Ο πιο εύκολος τρόπος να το δείξουμε αυτό είναι με τη διεπαφή του επαναληπτή.

## Επαναληπτές

Προηγουμένως στο syllabus, έχουμε δει αρκετούς τρόπους με τους οποίους η Julia μπορεί να λειτουργήσει πάνω σε κάθε στοιχείο μιας συλλογής.

- [Βρόχοι][concept-loops], όπως `for item in items...`
- [Μετάδοση][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Συναρτήσεις ανώτερης τάξης][concept-hof]: `map(√, [1, 4, 9])`
- [Κατανοήσεις][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Γεννήτριες][concept-comprehensions]: `(x^2 for x in 1:1e6)`, το οποίο αξιολογείται οκνηρά.

Είναι σαφές ότι η Julia ξέρει να διατρέχει τις τυπικές συλλογές στοιχείο προς στοιχείο: διανύσματα και διαστήματα στα παραπάνω παραδείγματα, αλλά και Sets, Dicts κ.λπ.

Πώς προσθέτουμε αυτή τη δυνατότητα στις δικές μας προσαρμοσμένες συλλογές, ειδικά αν μπορούν να διατρέχονται οκνηρά όπως μια γεννήτρια;

### Ελάχιστες απαιτήσεις

Για να δημιουργήσουμε μια ακολουθία προς επανάληψη, χρειαζόμαστε (τουλάχιστον) δύο πράγματα:

1. Έναν τρόπο να πάρουμε το _πρώτο_ στοιχείο.
2. Έναν τρόπο να πάρουμε το _επόμενο_ στοιχείο από την τρέχουσα κατάσταση.

Η Julia πετυχαίνει αυτούς τους στόχους με μεθόδους της συνάρτησης `Base.iterate()` ως εξής:

1. Η `Base.iterate(iter)` καλείται αυτόματα πρώτα.
    - Αν δεν υπάρχει τίποτα να διατρέξουμε, επιστρέφει `nothing`.
    - Αλλιώς, επιστρέφει την `Tuple` με το πρώτο στοιχείο που επιστρέφεται και την πρώτη κατάσταση: `(firstitem, firststate)`.
2. Η `Base.iterate(iter, state)` καλείται αυτόματα αν επιστράφηκε ένα στοιχείο στην προηγούμενη επανάληψη, παίρνοντας το `firststate` ως όρισμα `state`.
    - Αν η επανάληψη τερματιστεί, επιστρέφει `nothing`.
    - Αλλιώς, επιστρέφει την `Tuple` με το επόμενο στοιχείο και την επόμενη κατάσταση: `(nextitem, nextstate)`.
3. Επαναλαμβάνει το βήμα 2 μέχρι τον τερματισμό.

Όλα αυτά τα βήματα γίνονται "στο παρασκήνιο", που σημαίνει ότι οι κλήσεις μεθόδων και η κατάσταση διαχειρίζονται εσωτερικά από το πρωτόκολλο επανάληψης (με την κατάσταση να παραμένει αδιαφανής), και μόνο το στοιχείο εκτίθεται σε δομές υψηλού επιπέδου, όπως οι βρόχοι.
Με άλλα λόγια, βλέπουμε πάντα μόνο το `item`, ενώ όλα τα υπόλοιπα παραμένουν σε ένα μαύρο κουτί.

Το [multiple dispatch][concept-multiple-dispatch] είναι κεντρικό σε αυτό.
Ο τύπος του `iter` καθορίζει ποιες μέθοδοι καλούνται, και ο αριθμός των ορισμάτων καθορίζει αν επιστρέφεται το πρώτο ή το επόμενο στοιχείο.

Οι μέθοδοι για τους τυπικούς τύπους έχουν ήδη οριστεί: `Vector`, `Range`, `Set` κ.λπ. ([προς το παρόν][ref-iterations-collections] 14 τύποι συνολικά).

Για να μοιραστεί ένας προσαρμοσμένος τύπος `MyType` τις ίδιες συμπεριφορές, πρέπει πρώτα να ορίσουμε:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Όλα αυτά ακούγονται ίσως μπερδεμένα σε αφηρημένο επίπεδο, αλλά μπορεί να είναι αρκετά απλά.
Για παράδειγμα, φαντάσου ότι θέλουμε έναν τύπο που δίνει δυνάμεις ενός δεδομένου ακέραιου `n`, μέχρι έναν μέγιστο αριθμό.

Πρώτα, όρισε έναν προσαρμοσμένο τύπο:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Μπορούμε τώρα να ορίσουμε τις μεθόδους `iterate` για αυτόν τον τύπο, αλλά ποιο είναι το πρώτο στοιχείο και ποια η πρώτη κατάσταση;

Για να πάρουμε το πρώτο στοιχείο, κάποιοι επαναληπτές χρειάζονται περίπλοκη προετοιμασία, αλλά σε αυτό το απλό παράδειγμα μπορούμε να παρατηρήσουμε ότι το πρώτο στοιχείο που επιστρέφεται είναι απλώς ο βασικός αριθμός, οπότε αρκεί να ελέγξουμε αν η τιμή του `count` είναι μεγαλύτερη ή ίση με ένα.

Τώρα μπορούμε να εξετάσουμε την πρώτη κατάσταση, η οποία μεταφέρει πληροφορίες που χρησιμοποιούνται στην επόμενη επανάληψη.
Εξαρτάται από εσένα να αποφασίσεις ποιες πληροφορίες χρειάζεται να παρακολουθείς για να το κάνεις, και μπορεί να είναι οποιουδήποτε τύπου.

Σε αυτή την περίπτωση, θα μπορούσαμε απλώς να παρακολουθούμε τη "θέση" στην οποία θα υψώσουμε το `n`, ή μπορούμε να βρούμε μια πιο αποδοτική επιλογή χρησιμοποιώντας την πιο πρόσφατη δύναμη του `n` (δηλαδή το στοιχείο που επιστράφηκε) και την επόμενη "θέση" στην ακολουθία.
Αυτοί οι δύο αριθμοί μπορούν να τυλιχτούν σε μια `Tuple` και να επιστραφούν ως `state`.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

Σε αυτό το παράδειγμα, το πρώτο στοιχείο (`p.n`) επιστρέφεται στον βρόχο και η πρώτη κατάσταση `(p.n, 2)` περνά στη μέθοδο `iterate(P::Powers, state)`.
Εκεί μπορούμε να επεξεργαστούμε την κατάσταση για να παράγουμε το επόμενο στοιχείο πολλαπλασιάζοντας το τρέχον στοιχείο με τον βασικό αριθμό, αυξάνοντας έτσι τη δύναμή του κατά `1`.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Αν η τιμή της θέσης είναι ακόμα εντός του `count`, επιστρέφεται η `Tuple` με το στοιχείο `next` και την αυξημένη κατάσταση `Tuple`.
Όταν η τιμή του `index` ξεπερνά το `count`, τότε επιστρέφεται `nothing`, για να δηλωθεί ότι η επανάληψη τερματίστηκε.

Ίσως έχεις προσέξει ότι οι μέθοδοι `iterate(p::Powers)` και `iterate(p::Powers, state)` έχουν αρκετά παρόμοια σώματα συναρτήσεων.
Στην πραγματικότητα, αν είμαστε έξυπνοι, αυτή η ομοιότητα επιτρέπει μια πιο λιτή υλοποίηση χρησιμοποιώντας μόνο την έκδοση με δύο ορίσματα και ένα προεπιλεγμένο όρισμα για την κατάσταση: `Base.iterate(p::Powers, state=(1, 1))`
Έτσι, δε θα χρειαζόμασταν τη χωριστή έκδοση με ένα όρισμα, `iterate(p::Powers)`.
Αυτό γίνεται συνήθως στην πράξη, όταν είναι δυνατό.

Μέχρι στιγμής, έχουμε ήδη κάποια χρήσιμη λειτουργικότητα: για τις πρώτες 4 δυνάμεις του 3, μπορούμε να διατρέξουμε τα αποτελέσματα με έναν βρόχο, να ελέγξουμε αν ένας δεδομένος αριθμός υπάρχει στα αποτελέσματα και να εφαρμόσουμε συναθροιστικές συναρτήσεις όπως η `sum()`.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Πρόσθετες μέθοδοι

Παρά την καλή αρχή, δε λειτουργούν ακόμα όλα.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Όπως ήταν αναμενόμενο, το `length(Powers(3, 4))` δίνει ακριβώς το ίδιο μήνυμα σφάλματος.

Αυτό διορθώνεται εύκολα, καθώς το μήκος είναι μέρος του κατασκευαστή τύπου: 4 σε αυτή την περίπτωση.
Αρκεί να ορίσουμε τη `Base.length()` για αυτόν τον τύπο, και μετά μπορούμε να χρησιμοποιήσουμε κατανοήσεις και `collect()` στην ακολουθία.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Για λόγους απόδοσης, είναι καλύτερα να ορίσεις και τη `Base.eltype()`: τον τύπο στοιχείου του αποτελέσματος.
Αυτό επιτρέπει σε συναρτήσεις όπως η `collect()` να προδεσμεύσουν χώρο για το `Vector{Int}` εξόδου, αντί να κάνουν επανειλημμένα `push!()` σε ένα `Vector{Any}`.

Πρόσεξε τη σύνταξη, που ίσως να μην την έχεις ξαναδεί: αυτή η μέθοδος ορίζεται στον _τύπο_, όχι σε ένα _στιγμιότυπο_ του τύπου.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Οι επαναληπτές δεν _απαιτείται_ να έχουν πεπερασμένο μήκος.
Η χρήση "άπειρων" ακολουθιών είναι πιο περιορισμένη, αλλά το να διατρέχεις τέτοιες ακολουθίες με βρόχο μπορεί να είναι χρήσιμο, αρκεί να υπάρχει τρόπος να βγεις από τον βρόχο με `break`.
Για παράδειγμα, θα μπορούσαμε να ορίσουμε μια παραλλαγή του `Powers` που παράγει τιμές μικρότερες από ένα συγκεκριμένο όριο (ίσως `typemax(Int)`, για να αποφύγουμε την υπερχείλιση ακεραίων).

## Σύνοψη

Οι διεπαφές είναι αρκετά μπερδεμένες στην εξήγηση, γιατί η προσέγγιση της Julia διαφέρει τόσο πολύ από τις περισσότερες άλλες γλώσσες.
Ειδικότερα, το όνομα της διεπαφής μπορεί να μην αναφέρεται ποτέ στην υλοποίηση: σε αντίθεση με τη [δημιουργία υποκλάσης][wiki-subclass] ή τα [mixins][wiki-mixins].

Ωστόσο, στην πράξη είναι εκπληκτικά απλές:

1. Όρισε έναν κατάλληλο τύπο.
2. Βρες ποιες μέθοδοι απαιτούνται.
3. Υλοποίησε αυτές τις μεθόδους για τον προσαρμοσμένο τύπο σου: συνήθως μόνο λίγες μέθοδοι, αρκετά σύντομες και απλές.
4. Άφησε το [multiple dispatch][concept-multiple-dispatch] να αναλάβει τα υπόλοιπα, αυτόματα.
