# Εισαγωγή

Το TypeScript είναι η JavaScript με σύνταξη για τύπους, γεγονός που το κάνει μια αυστηρά τυποποιημένη γλώσσα προγραμματισμού, που υποστηρίζει αντικειμενοστρεφές, προστακτικό και δηλωτικό (π.χ. συναρτησιακό προγραμματισμό) στυλ, και σου προσφέρει καλύτερα εργαλεία σε οποιαδήποτε κλίμακα.

Επειδή [δεν μπορείς να μάθεις TypeScript χωρίς να μάθεις JavaScript][handbook-js-or-ts], ένα μέρος του περιεχομένου αυτής της διαδρομής είναι αφιερωμένο στη διδασκαλία εννοιών της JavaScript, ενώ κάποιες από τις έννοιες εστιάζουν μόνο σε χαρακτηριστικά ειδικά για το TypeScript.

## (Επανα)ανάθεση

Υπάρχουν μερικοί βασικοί τρόποι για να αναθέτεις τιμές σε ονόματα στο TypeScript: χρησιμοποιώντας μεταβλητές ή σταθερές.
Στο Exercism, οι μεταβλητές γράφονται πάντα σε [camelCase][wiki-camel-case]; οι σταθερές γράφονται σε [SCREAMING_SNAKE_CASE][wiki-snake-case].
Δεν υπάρχει κάποιος επίσημος οδηγός να ακολουθήσεις, και διάφορες εταιρείες και οργανισμοί έχουν διαφορετικούς οδηγούς στυλ.
_Μπορείς άνετα να γράψεις τις μεταβλητές όπως θέλεις_.
Το πλεονέκτημα του να τις γράφεις με τον τρόπο που είναι προετοιμασμένες οι ασκήσεις είναι ότι θα επισημαίνονται διαφορετικά στη διαδικτυακή διεπαφή και στα περισσότερα IDE.

Οι μεταβλητές στο TypeScript μπορούν να οριστούν χρησιμοποιώντας τη λέξη-κλειδί [`const`][mdn-const], [`let`][mdn-let] (έστω) ή [`var`][mdn-var].

Μια μεταβλητή μπορεί να αναφέρεται σε διαφορετικές τιμές κατά τη διάρκεια της ζωής της όταν χρησιμοποιείς `let` ή `var`.
Για παράδειγμα, η `myFirstVariable` μπορεί να ορίζεται και να επαναορίζεται πολλές φορές χρησιμοποιώντας τον τελεστή ανάθεσης `=`:

```typescript
let myFirstVariable = 1
myFirstVariable = 0
myFirstVariable = 42
```

Σε αντίθεση με το `let` και το `var`, οι μεταβλητές που ορίζονται με `const` μπορούν να πάρουν τιμή μόνο μία φορά.
Αυτό χρησιμοποιείται για να ορίζεις σταθερές στο TypeScript.

```typescript
const MY_FIRST_CONSTANT = 10

// Can not be re-assigned.
MY_FIRST_CONSTANT = 20
// => TypeError: Assignment to constant variable.
```

Επειδή το TypeScript μπορεί να το εντοπίσει στατικά, ο μεταγλωττιστής του TypeScript θα παράγει και αυτός ένα σφάλμα:

```typescript
// ^? Cannot assign to 'MY_FIRST_CONSTANT' because it is a constant.(2588)
```

Αυτό σημαίνει ότι δεν χρειάζεται να τρέξεις τον κώδικα για να εντοπίσεις το `TypeError`.

## Εξαγωγή τύπων

Χωρίς να μπούμε πολύ βαθιά στο θέμα της [εξαγωγής τύπων][handbook-type-inference], καλό είναι να ξέρεις ότι μια μεταβλητή στην οποία ανατίθεται μια τιμή έχει συνήθως έναν τύπο που συνάγεται αυτόματα, ακόμα κι αν δεν υπάρχει σχολιασμός τύπου.

```typescript
const MY_FIRST_CONSTANT = 10
// ^? const MY_FIRST_CONSTANT: number
```

Ο τύπος αυτός επιβάλλεται στη συνέχεια σε όλο τον κώδικα.
Αυτό σημαίνει επίσης ότι, ενώ ο παρακάτω κώδικας είναι έγκυρος JavaScript:

```javascript
let myFirstVariable = 1
myFirstVariable = 'Some string'
```

στο TypeScript παραπονιέται:

```typescript
let myFirstVariable = 1
myFirstVariable = 'Some string'
// ^? Type 'string' is not assignable to type 'number'.(2322)
```

Αυτό το χαρακτηριστικό εξασφαλίζει την ασφάλεια τύπων ακόμα κι όταν δεν χρησιμοποιούνται σχολιασμοί τύπων.

## Δηλώσεις συναρτήσεων

Στο TypeScript, οι μονάδες λειτουργικότητας ενσωματώνονται σε _συναρτήσεις_, και συνήθως οι συναρτήσεις που ανήκουν μαζί ομαδοποιούνται στο ίδιο αρχείο.
Αυτές οι συναρτήσεις μπορούν να δέχονται παραμέτρους (ορίσματα) και μπορούν να _επιστρέφουν_ μια τιμή χρησιμοποιώντας τη λέξη-κλειδί `return`.
Οι συναρτήσεις καλούνται χρησιμοποιώντας τη σύνταξη `()`.

```typescript
function add(num1: number, num2: number): number {
  return num1 + num2
}

add(1, 3)
// => 4
```

Οι παράμετροι μιας συνάρτησης θα πρέπει συνήθως να σχολιάζονται με έναν τύπο, χρησιμοποιώντας μια άνω και κάτω τελεία (`:`) που ακολουθείται από τον τύπο.
Οι τιμές επιστροφής μιας συνάρτησης μπορούν να σχολιαστούν μετά το κλείσιμο της λίστας παραμέτρων, χρησιμοποιώντας μια άνω και κάτω τελεία (`:`) που ακολουθείται από τον τύπο.

<!--prettier-ignore -->
~~~~exercism/note
💡 Στο TypeScript υπάρχουν _πολλοί_ διαφορετικοί τρόποι για να δηλώσεις μια συνάρτηση.
Αυτοί οι άλλοι τρόποι φαίνονται διαφορετικοί από τη χρήση της λέξης-κλειδιού `function`.
Η διαδρομή προσπαθεί να τους παρουσιάσει σταδιακά, αλλά αν τους ξέρεις ήδη, μη διστάσεις να χρησιμοποιήσεις οποιονδήποτε από αυτούς.
Στις περισσότερες περιπτώσεις, η χρήση του ενός ή του άλλου δεν είναι καλύτερη ούτε χειρότερη.
~~~~

## Σχολιασμοί τύπων

Όπως φαίνεται στη δήλωση της συνάρτησης `add`, οι παράμετροι έχουν έναν ρητό σχολιασμό τύπου `: number`.
Οι δηλώσεις μεταβλητών, οι ιδιότητες κλάσης, οι δηλώσεις συναρτήσεων και πολλά άλλα υποστηρίζουν σχολιασμούς τύπων.

Τόσο οι ρητοί σχολιασμοί τύπων όσο και οι τύποι που συνάγονται αυτόματα επιβάλλονται από τον ελεγκτή τύπων.

```typescript
add('foo', 3)
// ^? Argument of type 'string' is not assignable to parameter of type 'number'.(2345)
```

## Έκθεση σε άλλα αρχεία

Για να είναι διαθέσιμη μια `συνάρτηση`, μια σταθερά ή μια μεταβλητή σε _άλλα αρχεία_, πρέπει να γίνουν [export][mdn-export] χρησιμοποιώντας τη λέξη-κλειδί `export`.
Ένα άλλο αρχείο μπορεί στη συνέχεια να τα κάνει [import][mdn-import] χρησιμοποιώντας τη λέξη-κλειδί `import`.
Αυτό είναι επίσης γνωστό ως σύστημα αρθρωμάτων.
Ένα εξαιρετικό παράδειγμα είναι ο τρόπος με τον οποίο λειτουργούν όλα τα τεστ.
Κάθε άσκηση έχει τουλάχιστον ένα αρχείο, για παράδειγμα το `lasagna.ts`, το οποίο περιέχει την _υλοποίηση_.
Επιπλέον, υπάρχει τουλάχιστον ένα ακόμη αρχείο, για παράδειγμα το `lasagna.test.ts`, το οποίο περιέχει τα _τεστ_.
Αυτό το αρχείο _κάνει import_ τις δημόσιες (δηλαδή όσες έχουν γίνει export) οντότητες για να ελέγξει την υλοποίηση:

```typescript
// file.ts
export const MY_VALUE = 10

export function add(num1, num2) {
  return num1 + num2
}

// file.test.ts
import { MY_VALUE, add } from './file.js'

add(MY_VALUE, 5)
// => 15
```
