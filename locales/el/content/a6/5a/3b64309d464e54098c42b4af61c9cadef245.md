# Σχετικά

Τα [structs και οι κλάσεις][structs-and-classes] είναι δύο από τα βασικά δομικά στοιχεία του προγραμματισμού στη Swift. Και τα δύο είναι τρόποι να ομαδοποιείς σχετικά δεδομένα και συναρτήσεις σε αυτοτελείς μονάδες λειτουργικότητας. Όλοι οι βασικοί τύποι με τους οποίους έχεις δουλέψει μέχρι αυτό το σημείο, όπως οι `Int`, `Double` και `Character`, καθώς και οι τύποι συλλογών όπως οι `Array`, `String` και `Dictionary`, είναι στην πραγματικότητα structs. Και όταν ορίζεις ένα struct ή μια κλάση, ορίζεις έναν νέο τύπο που θα χρησιμοποιηθεί μέσα στη Swift, ακριβώς όπως χρησιμοποίησες εκείνους τους τύπους.

Υπάρχουν πολλές ομοιότητες μεταξύ των structs και των κλάσεων στη Swift. Μεταξύ άλλων ομοιοτήτων, και τα δύο μπορούν να αποθηκεύουν τιμές σε _ιδιότητες_ και να παρέχουν λειτουργικότητα μέσω της χρήσης _μεθόδων_.

Για πιο λεπτομερείς πληροφορίες, δες:

- [concept:swift/structs]()
- [concept:swift/classes]()

## Χρήση structs εναντίον κλάσεων

Ενώ μπορεί να φαίνεται ότι οι κλάσεις θα προτιμούνταν στη γενική χρήση έναντι των structs στη Swift, καθώς προσφέρουν περισσότερη λειτουργικότητα και δεν επιβαρύνονται με την επιβάρυνση της αντιγραφής, στην πραγματικότητα ισχύει το αντίθετο.

Η Swift, ως γλώσσα, επιλέγει να προτιμά την ασφάλεια ως βασική αρχή σχεδιασμού. Και οι κλάσεις είναι πιο δύσκολο να τις αναλύσεις ως προς την ασφάλεια, δεδομένου ότι τα περιεχόμενά τους μπορούν να αλλάξουν με απρόβλεπτους τρόπους, επειδή είναι τύποι αναφοράς. Γι' αυτό η Swift προτιμά τη χρήση structs έναντι κλάσεων και είναι βελτιστοποιημένη με πολλούς τρόπους με την παραδοχή ότι τα structs θα χρησιμοποιηθούν στις περισσότερες περιπτώσεις. Γι' αυτό βλέπουμε ότι σχεδόν κάθε τύπος στη βασική βιβλιοθήκη και σε μεγάλο μέρος της βιβλιοθήκης _Foundation_ της Apple είναι structs.

Αυτό όμως δεν σημαίνει ότι οι κλάσεις δεν έχουν τις χρήσεις τους. Με τα λόγια του Brent Royal-Gordon, μέλους της ομάδας της Swift στην Apple:

> Χρησιμοποίησε μια κλάση όταν το αντικείμενο αντιπροσωπεύει ένα συγκεκριμένο _πράγμα_ που δεν μπορεί να αντιγραφεί χωρίς συνέπειες. Χρησιμοποίησε ένα struct (ή enum) όταν το στιγμιότυπο αντιπροσωπεύει κάποια αφηρημένα δεδομένα χωρίς συγκεκριμένη ύπαρξη. Μερικά παραδείγματα που χρησιμοποιούν τύπους του framework:
>
> - Ένα κομμάτι κειμένου είναι απλώς δεδομένα. Η αντιγραφή του δεν κάνει τίποτα, παρά μόνο ίσως να καταναλώσει περισσότερη μνήμη. Άρα το `String` θα έπρεπε να είναι struct.
>
> - Μια ετικέτα είναι ένα συγκεκριμένο πράγμα που υπάρχει σε μια συγκεκριμένη θέση στην οθόνη. Αν την αντέγραφες, θα κατέληγες με δύο ετικέτες στην οθόνη, ή με ένα αντίγραφο μιας ετικέτας εκτός οθόνης που δεν θα είχε κανένα αποτέλεσμα όταν το τροποποιούσες. Άρα το `UILabel` θα έπρεπε να είναι κλάση.
>
> - Ένα URL είναι απλώς δεδομένα. Αν κατασκευάσεις δύο URL με το ίδιο περιεχόμενο, είναι εντελώς εναλλάξιμα. Άρα το `URL` θα έπρεπε να είναι struct.
>
> - Μια σύνδεση με έναν διακομιστή ιστού για την ανάκτηση του περιεχομένου ενός URL είναι ένα συγκεκριμένο πράγμα. Αν την αντέγραφες, είτε θα δημιουργούσες άλλη μια σύνδεση, είτε τα δύο στιγμιότυπα θα αλληλοεπηρεάζονταν (π.χ. η ακύρωση του ενός θα ακύρωνε το άλλο). Άρα τα `URLSessionTask` και `NSURLConnection` είναι κλάσεις.
>
> Μερικές φορές το ίδιο πρόβλημα, προσεγγισμένο με ελαφρώς διαφορετικούς τρόπους, θα σου επέτρεπε να χρησιμοποιήσεις οποιοδήποτε από τα δύο. Για παράδειγμα, μια καταγραφή βάσης δεδομένων είναι ένα συγκεκριμένο _πράγμα_ και πιθανότατα θα έπρεπε να είναι κλάση, αλλά αντέγραψε τις τιμές των πεδίων (ίσως παραλείποντας το ID) από αυτήν και ξαφνικά έχεις ένα εύλογο struct. Ως _γενικός_ κανόνας, είναι συνήθως καλύτερο να χρησιμοποιείς structs όπου είναι δυνατόν, επειδή είναι ευκολότερο να αναλύσεις τη συμπεριφορά τους: οι τροποποιήσεις σε μια συνάρτηση δεν εμφανίζονται ξαφνικά σε μια εντελώς άσχετη συνάρτηση. Ωστόσο, μερικές φορές ένας συγκεκριμένος τύπος λειτουργεί πολύ εύκολα ως κλάση και πολύ δύσκολα ως struct. Τελικά, είναι θέμα κρίσης.
