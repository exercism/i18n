# Σχετικά

Στη γλώσσα C, ένα [struct][struct] είναι ένας σύνθετος τύπος, που αποτελείται από διαφορετικά πεδία.
Κάθε πεδίο έχει τον δικό του τύπο και μέγεθος.

Για παράδειγμα, αυτό ορίζει έναν τύπο που αποτελείται από τρεις ακέραιους, δύο των 4 byte και έναν των 8 byte:

```c
struct example {
    int32_t first_four_byte_integer;
    uint32_t second_four_byte_integer;
    uint64_t eight_byte_integer;
};
```

Ένα struct μπορεί επίσης να περιέχει άλλα struct:

```c
struct example_2 {
    struct example first;
    struct example second;
};
```

Αν ένα από τα πεδία του struct είναι πίνακας, όλα τα byte που δεσμεύονται για τον πίνακα είναι μέρος του struct.
Ωστόσο, αν το πεδίο είναι μόνο ένας δείκτης προς τον πίνακα, τότε ο πίνακας πρέπει να αποθηκευτεί κάπου αλλού:

```c
struct with_array {
    char string[20];
};
// all 20 bytes of string are inside struct with_array

struct with_pointer {
    const char *string;
};
// only the 8-byte pointer to the string is inside struct with_pointer
```

## Ευθυγράμμιση

Η [ευθυγράμμιση][alignment] ενός τύπου είναι μια μη αρνητική δύναμη του δύο (1, 2, 4, 8, ...) που αντιπροσωπεύει μια απαίτηση για τη διεύθυνσή του.
Κάθε αντικείμενο αυτού του τύπου πρέπει να βρίσκεται σε μια διεύθυνση που να είναι πολλαπλάσιο της ευθυγράμμισής του.

Για έναν πρωτογενή τύπο, η ευθυγράμμιση είναι συνήθως ίση με το μέγεθός του, οπότε, για παράδειγμα, ένα `int32_t` έχει συνήθως ευθυγράμμιση 4 byte.
Αυτό σημαίνει ότι το `int32_t` πρέπει να δεσμεύεται σε όρια 4 byte.

Η ευθυγράμμιση ενός struct, ωστόσο, είναι η μέγιστη ευθυγράμμιση οποιουδήποτε από τα πεδία του.
Έτσι, για παράδειγμα, το `struct example`, που ορίστηκε παραπάνω, θα είχε ευθυγράμμιση 8 byte, αφού αυτή είναι η ευθυγράμμιση του `uint64_t`.

Αν η ευθυγράμμιση ενός πεδίου του struct είναι μικρότερη από αυτήν του struct, μπορούν να εισαχθούν bytes γεμίσματος μετά από αυτό το πεδίο.
Αυτό διασφαλίζει ότι τα επόμενα πεδία και το struct στο σύνολό του πληρούν τις απαιτήσεις ευθυγράμμισης.
Στην πράξη, αυτό σημαίνει ότι, παρόλο που αυτά τα bytes γεμίσματος συνεισφέρουν στο μέγεθος του struct, δεν χρησιμοποιούνται στην τιμή του struct:

```c
struct example_3 {
    char one_byte; // alignment of 1
    int four_byte; // alignment of 4
};
// example_3 has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one_byte'
// 3 padding bytes (with undefined value)
// 4 bytes for field 'four_byte'
```

Σημείωσε ότι στο struct που ορίστηκε παραπάνω, το πεδίο 'one_byte' έχει ευθυγράμμιση 1 και μπορεί να τοποθετηθεί σε οποιαδήποτε διεύθυνση.
Αφού το πεδίο 'four_byte' έχει ευθυγράμμιση 4, τα πεδία του struct πρέπει επίσης να σέβονται τα όρια των 4 byte.
Αυτό σημαίνει ότι πρέπει να υπάρχει ένας αριθμός byte που να είναι πολλαπλάσιο του 4 ανάμεσα σε οποιαδήποτε δύο πεδία του struct.
Αφού το 'one_byte' καταλαμβάνει μόνο 1 byte, τότε εισάγονται 3 bytes γεμίσματος μετά από αυτό για να τηρηθεί αυτό το όριο.

Τα γειτονικά πεδία ομαδοποιούνται όποτε είναι δυνατόν, ώστε να ελαχιστοποιείται ο αριθμός των απαραίτητων bytes γεμίσματος:

```c
struct two_padding {
    char one; // alignment of 1
    char two; // alignment of 1
    int three; // alignment of 4
};
// struct two_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 byte for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
```

Αυτή η ομαδοποίηση πρέπει επίσης να σέβεται την ευθυγράμμιση κάθε πεδίου:

```c
struct one_padding {
    char one; // alignment of 1
    int16_t two; // alignment of 2
    int three; // alignment of 4
};
// struct one_padding has alignment of 4 (the same as int)
// it occupies 8 bytes in space:
// 1 byte for field 'one'
// 1 padding byte
// 2 bytes for field 'two'
// 4 bytes for field 'three'
// Since 'two' has alignment of 2, it must be placed in a 2-byte boundary
// So, there must be 1 padding byte between 'one' and 'two'
```

Αυτό σημαίνει ότι η αλλαγή της σειράς των πεδίων σε ένα struct μπορεί μερικές φορές να οδηγήσει σε διαφορά στο μέγεθός του:

```c
struct example_4 {
    int64_t one;
    short two;
    int32_t three;
};
// example_4 has one 8-byte field, one 4-byte field and one 2-byte field
// it has an alignment of 8 and occupies 16 bytes in space:
// 8 bytes for field 'one'
// 2 bytes for field 'two'
// 2 padding bytes
// 4 bytes for field 'three'
// two' and 'three' are adjacent and can be grouped to sum up 8 bytes with only 2 bytes of padding

struct example_5 {
    short one;
    int64_t two;
    int32_t three;
};
// example_5 also has one 8-byte field, one 4-byte field and one 2-byte field, in different positions
// it also has an alignment of 8, however, it occupies 24 bytes in space:
// 2 bytes for field 'one'
// 6 bytes for padding
// 8 bytes for field 'two'
// 4 bytes for field 'three'
// 4 bytes for padding
// 'one' can't be grouped with 'two' because their sum would be higher than the struct's alignment
// 'two' and 'three' also can't be grouped, for the same reason
// so padding bytes must be inserted in full after each field with less than 8 bytes in alignment
```

Σημείωσε ότι η ευθυγράμμιση ενός πίνακα είναι ίδια με την ευθυγράμμιση του υποκείμενου τύπου του:

```c
struct array_example {
    char string[10]; // alignment of 1
};
// array_example has alignment of 1 (it can be placed at any address)
// it occupies 10 bytes in space, one for each char in 'string'
```

Τα στοιχεία ενός πίνακα μπορούν να ομαδοποιηθούν με τον ίδιο τρόπο όπως αν δεν ήταν μέρος ενός πίνακα:

```c
struct group_array {
    int16_t arr[3];
    int8_t one_byte;
    int32_t four_byte;
};
// group_array has alignment of 4 because this is the alignment of 'four_byte'
// it occupies 12 bytes in space:
// 4 bytes for arr[0] and arr[1]
// 2 bytes for arr[2]
// 1 byte for 'one_byte'
// 1 padding byte (arr[2] is grouped with 'one_byte')
// 4 bytes for 'four_byte'
```

Είναι σημαντικό να λαμβάνεις υπόψη τυχόν πιθανά bytes γεμίσματος όποτε προσπελαύνεις ένα struct σε assembly.

## Σύμβαση κλήσης

Γενικά, οι τιμές περνούν στις συναρτήσεις και επιστρέφονται από αυτές όπως θα περίμενε κανείς:

- Οι ακέραιες τιμές, συμπεριλαμβανομένων των διευθύνσεων μνήμης και των enum, περνούν σε καταχωρητές γενικού σκοπού (GPR).
- Οι τιμές κινητής υποδιαστολής περνούν σε καταχωρητές `xmm`.

Τα struct, ωστόσο, αποτελούν ειδική περίπτωση.
Κατά κανόνα, όλα τα πεδία ενός struct καταλαμβάνουν γειτονικό χώρο στη μνήμη και θα πρέπει να τοποθετούνται σε έναν μόνο καταχωρητή όποτε είναι δυνατόν:

```c
struct single_type {
    int16_t first;
    int16_t second;
    int16_t third;
    int16_t fourth;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'first' is passed on the lowest 2 bytes
// each subsequent field is passed in the following 2 bytes
```

Αν ένα struct έχει πεδία με ακέραιες τιμές και επίσης πεδία με τιμές κινητής υποδιαστολής, κάθε διαδοχικό τμήμα των 8 byte στο struct θα πρέπει να κατατάσσεται ξεχωριστά:

```c
struct mixed_types {
    double first;
    int second;
    int third;
};
// this struct occupies 16 bytes
// the field 'first' is passed in the first 8 bytes of a xmm register
// the fields 'second' and 'third' are passed in the same GPR register:
// the field 'second' is passed on the lowest 4 bytes
// the field 'third' is passed in the next 4 bytes
```

Σε περίπτωση που ακέραιοι και τιμές κινητής υποδιαστολής βρίσκονται στο ίδιο τμήμα των 8 byte, ο τύπος είναι ακέραιος και ολόκληρο το τμήμα των 8 byte (συμπεριλαμβανομένης της τιμής κινητής υποδιαστολής) τοποθετείται σε έναν GPR:

```c
struct mixed_types {
    int32_t integer;
    float floating_point;
};
// this struct occupies 8 bytes
// it is entirely passed in the same GPR register:
// the field 'integer' is passed on the lowest 4 bytes
// the field 'floating_point' is passed on the next 4 bytes
```

~~~~exercism/caution
Όταν γίνεται μια μετατροπή από κινητή υποδιαστολή σε ακέραιο χρησιμοποιώντας `cvtss2si` ή `cvtsd2si`, αυτό αλλάζει την οργάνωση των υποκείμενων byte.

Μπορείς να χρησιμοποιήσεις το [movd][mov] (για τιμές 32 bit) ή το [movq][mov] (για τιμές 64 bit) για να μεταφέρεις ακατέργαστα byte από έναν καταχωρητή `xmm` σε έναν GPR, χωρίς να αλλάξεις την αναπαράσταση των bit.

[mov]: https://www.felixcloutier.com/x86/movd:movq
~~~~

Ωστόσο, τα struct με μέγεθος μεγαλύτερο από 16 byte συνήθως τοποθετούνται στη μνήμη, ανεξάρτητα από τον τύπο κάθε τμήματος των 8 byte:

```c
struct big_struct {
    uint8_t first;
    double second;
    int64_t third;
};
// this struct occupies 24 bytes, including 7 padding bytes between 'first' and 'second'
// it is entirely passed in memory
```

Όταν ένα struct περνά ως όρισμα σε μια συνάρτηση, χρησιμοποιεί όσους καταχωρητές χρειάζεται.
Αν τοποθετείται στη μνήμη, χρησιμοποιείται αντ' αυτού η στοίβα.

Παρόμοιοι κανόνες ισχύουν για τα struct που επιστρέφονται από μια συνάρτηση.
Συνήθως επιστρέφονται πρώτα στους `rax` και `rdx` (αν είναι ακέραιας τιμής) ή στους `xmm0` και `xmm1` (αν είναι τιμής κινητής υποδιαστολής).
Αν τοποθετείται στη μνήμη, ωστόσο, ο καλών πρέπει να δεσμεύσει χώρο για αυτό και να περάσει τη διεύθυνση αυτής της θέσης μνήμης ως σιωπηρό πρώτο όρισμα στη συνάρτηση (στον `rdi`).
Στη συνέχεια, η συνάρτηση αποθηκεύει το struct σε αυτόν τον χώρο και επιστρέφει τη διεύθυνσή του στον `rax`.
