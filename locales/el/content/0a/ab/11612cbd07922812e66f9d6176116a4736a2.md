# Σχετικά

Οι τύποι της Elm επιτρέπουν γενικούς τύπους, που γενικά προσθέτουν ευελιξία σε μια διεπαφή.
Για παράδειγμα, ο τύπος `Maybe a` μπορεί να περιέχει μια τιμή οποιουδήποτε τύπου.

```elm
type Maybe a = Nothing | Just a
```

Παρατήρησε ότι στο παραπάνω παράδειγμα, η παράμετρος τύπου `a` χρησιμοποιείται και στις δύο πλευρές του συμβόλου ίσον `=`.
Λέμε ότι το `a` είναι δεσμευμένο σε κάποια δεδομένα μέσα στον ορισμό του τύπου.

## Η τεχνική του φανταστικού τύπου

Σε ορισμένες περιπτώσεις όμως, η παράμετρος τύπου εμφανίζεται μόνο στην αριστερή πλευρά της εξίσωσης.

```elm
type Distance unit = Distance Float
```

Στον ορισμό του `Distance` παραπάνω, το `unit` είναι μια ελεύθερη παράμετρος τύπου, που δεν είναι δεσμευμένη σε κανένα δεδομένο του τύπου.
Μπορούμε επίσης να ονομάσουμε αυτόν τον τύπο **φανταστικό τύπο**.

Είναι εντυπωσιακά χρήσιμο όταν θέλουμε να επιβάλουμε περιορισμούς σε χρόνο μεταγλώττισης.
Για παράδειγμα, θέλουμε να βεβαιωθούμε ότι προσθέτουμε μόνο αποστάσεις της ίδιας μονάδας.

```elm
-- Distance is an opaque type, since the module does not expose its variants.
-- This means that users may only use the functions meter, foot and add to manipulate distances.
module Distance exposing (Distance, Meter, Foot, meter, foot, add)

-- The Distance type has a phantom type 'unit'.
type Distance unit = Distance Float

-- We define two types that will be used in place
-- of the phantom type 'unit' in our constructor functions.
type Meter = Meter
type Foot = Foot

-- Constructor for Meter
meter : Distance Meter
meter = Distance 1.0

-- Constructor for Foot
foot : Distance Foot
foot = Distance 0.3048

-- The add function cannot take two parameters of different types.
-- So we cannot add meters and feet by mistake.
add : Distance unit -> Distance unit -> Distance unit
add (Distance d1) (Distance d2) = Distance (d1 + d2)
```

Ο κώδικας έξω από αυτό το module δεν μπορεί να έχει πρόσβαση στο εσωτερικό του τύπου `Distance`.
Οι χρήστες μπορούν να προσθέσουν δύο `Distance Meter` αλλά δεν μπορούν να προσθέσουν ένα `Distance Meter` με ένα `Distance Foot`.

```elm
import Distance exposing (Distance)

-- Compiles
twoMeters = Distance.add Distance.meter Distance.meter

-- Does not compile
errDist = Distance.add Distance.meter Distance.foot
```

## Επεκτάσιμες καταγραφές ως φανταστικοί τύποι

Δεν υπάρχει περιορισμός για το ποιοι τύποι μπορούν να είναι φανταστικοί, και οι τύποι καταγραφών μπορούν επίσης να χρησιμοποιηθούν.
Οι καταγραφές της Elm είναι [επεκτάσιμες][extensible-records], που σημαίνει ότι μπορούν να περιέχουν περισσότερα πεδία από όσα δηλώνουν.
Όταν χρησιμοποιούνται ως φανταστικοί τύποι, οι καταγραφές μπορούν να εκφράσουν σύνθετους περιορισμούς που μπορούν να μετασχηματιστούν μέσω συναρτήσεων.

Ας προσθέσουμε μια νέα μονάδα απόστασης μέσα στο module `Distance` που ονομάζεται `LegoBlock`.
Τα φυσικά τουβλάκια, καθώς είναι αντικείμενα που υπόκεινται σε κανόνες, έχουν πάντα δύο ιδιότητες: έχουν μη κλασματικές και μη αρνητικές αποστάσεις.

```elm
type LegoBlock = LegoBlock

fourStuds : Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
fourStuds = Distance 4.0
```

Τα `nonFractional` και `nonNegative` είναι τα πεδία μιας καταγραφής που δεν υπάρχει έξω από ένα όρισμα τύπου, οπότε είναι ταιριαστό να τους δώσουμε τον τύπο `()`, που ονομάζεται __τύπος μονάδας__, ο οποίος δεν κρατά καμία πληροφορία πέρα από το γεγονός ότι υπάρχει.

Η απόκτηση αυθαίρετων αποστάσεων `LegoBlock` είναι φυσικά δυνατή, για παράδειγμα μετά τον υπολογισμό διαφορών ή αναλογιών αποστάσεων.

```elm
negativeStud : Distance { properties | unit: LegoBlock, nonFractional : () }
negativeStud = Distance -1.0

threeFiddyStud : Distance { properties | unit: LegoBlock, nonNegative : () }
threeFiddyStud = Distance 3.50

crazyStud : Distance { properties | unit: LegoBlock }
crazyStud = Distance -13.37
```

Όλες οι παραπάνω τιμές είναι έγκυρες και θα μεταγλωττιστούν, ωστόσο έχουμε ένα ιδιαίτερο ενδιαφέρον για τιμές όπως το `fourStuds` που έχουν και τις δύο ιδιότητες `nonFractional` και `nonNegative`, επειδή αντιπροσωπεύουν φυσικά τουβλάκια που μπορούν να συνδυαστούν με

```elm
combineLegoBlocks
  :  Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
  -> Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
  -> Distance { properties | unit: LegoBlock, nonFractional : (), nonNegative: () }
combineLegoBlocks = add
```

Ας προσθέσουμε μερικές συναρτήσεις για να επιτρέψουμε στους χρήστες να δημιουργούν και να βελτιώνουν αποστάσεις `LegoBlock`.

```elm
newLegoBlock : Float -> Distance { properties | unit: LegoBlock }
newLegoBlock dist = Distance dist

floorDistance : Distance properties -> Distance { properties | nonFractional : () }
floorDistance (Distance dist) = Distance (toFloat (floor dist))

ceilingDistance : Distance properties -> Distance { properties | nonFractional : () }
ceilingDistance (Distance dist) = Distance (toFloat (ceiling dist))

absDistance : Distance properties -> Distance { properties | nonNegative : () }
absDistance (Distance dist) = Distance (abs dist)
```

Σημείωσε ότι οι `floorDistance`, `ceilingDistance` και `absDistance` μπορούν να χειριστούν μονάδες διαφορετικές από το `LegoBlock`, και γενικά δεν κάνουν καμία υπόθεση για τις ιδιότητες εισόδου, απλώς εγγυώνται ότι η έξοδος θα έχει μια συγκεκριμένη ιδιότητα, είτε `nonFractional` είτε `nonNegative`.

Ας δούμε μερικά αποτελέσματα.

```elm
import Distance exposing (Distance)

-- Compiles
distance1 = combineLegoBlocks fourStuds fourStuds

-- Does not compile
distance2 = combineLegoBlocks fourStuds threeFiddyStud

-- Compiles
distance3 = combineLegoBlocks fourStuds (floorDistance threeFiddyStud)

-- Does not compile
distance4 = combineLegoBlocks fourStuds negativeStud

-- Compiles
distance5 = combineLegoBlocks fourStuds (absDistance negativeStud)

-- Does not compile
distance6 = combineLegoBlocks fourStuds crazyStud

-- Compiles
distance7 = combineLegoBlocks fourStuds (floorDistance (absDistance crazyStud))

-- Compiles
distance8 = combineLegoBlocks fourStuds (ceilingDistance (absDistance crazyStud))
```

Γενικά, οι `floorDistance` και `ceilingDistance` παρέχουν διαφορετικά αποτελέσματα, αλλά τις ίδιες εγγυήσεις.
Αυτή είναι η δύναμη της τεχνικής του φανταστικού τύπου: παρέχει ευέλικτες επιλογές στους χρήστες διατηρώντας παράλληλα ισχυρές εγγυήσεις.
