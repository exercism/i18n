# Σχετικά

## Σφάλματα στη `jq`

Η `jq` αναφέρει δύο ευρείες κατηγορίες σφαλμάτων:

1. **Σφάλματα κατά τη μεταγλώττιση**: το ίδιο το πρόγραμμα είναι άκυρο, δηλαδή συντακτικά σφάλματα, αναφορές σε απροσδιόριστες συναρτήσεις ή μεταβλητές και τα λοιπά.
   Η `jq` αρνείται να εκτελέσει καθόλου το πρόγραμμα.

   ```sh
   $ jq -n '1 + $foo + 2'
   jq: error: $foo is not defined at <top-level>, line 1, column 5:
       1 + $foo + 2
           ^^^^
   jq: 1 compile error
   ```

2. **Σφάλματα κατά την εκτέλεση**: το πρόγραμμα είναι έγκυρο, αλλά κάτι πάει στραβά κατά την επεξεργασία μιας τιμής, όπως η πρόσβαση σε θέση ενός αριθμού με μια συμβολοσειρά, η ανάλυση άκυρου κειμένου JSON με το `fromjson`, η κλήση μιας συνάρτησης με ορίσματα λάθος τύπου και τα λοιπά.

   ```sh
   $ echo '42' | jq '.foo'
   jq: error (at <stdin>:1): Cannot index number with "foo"
   ```

Αυτή η ενότητα αφορά τα **σφάλματα κατά την εκτέλεση**: πώς να τα πετάς, πώς να τα πιάνεις και πώς να τα σταματάς.

Ένα σφάλμα κατά την εκτέλεση που δεν πιάνεται κάνει την `jq` να εκτυπώσει ένα μήνυμα στην _τυπική έξοδο σφαλμάτων_ και να τερματίσει με κωδικό κατάστασης `5`.

## Πώς πετάς σφάλματα: `error` και `error(message)`

Το φίλτρο [`error`][man-error] πετάει ένα σφάλμα.

- Το `error` πετάει ένα σφάλμα του οποίου η τιμή είναι η τιμή **εισόδου**.
- Το `error(message)` πετάει ένα σφάλμα του οποίου η τιμή είναι το αποτέλεσμα του `message`.

```jq
"bad input" | try error catch .
# => "bad input"

42 | try error("invalid value: \(.)") catch .
# => "invalid value: 42"
```

~~~~exercism/note
Η τιμή του σφάλματος μπορεί να είναι _οποιαδήποτε_ τιμή JSON, όχι μόνο μια συμβολοσειρά.
Το πέταγμα δομημένων σφαλμάτων επιτρέπει σε έναν χειριστή `catch` να παίρνει αποφάσεις με βάση το περιεχόμενο του σφάλματος.

```jq
try error({kind: "range", msg: "age must be non-negative"})
catch (if type == "object" then "\(.kind) error: \(.msg)" else "unexpected: \(.)" end)
# => "range error: age must be non-negative"
```
~~~~

Αν μια τιμή σφάλματος που δεν είναι συμβολοσειρά δεν πιαστεί, η `jq` την εκτυπώνει ως JSON, σημασμένη με `(not a string)`.

```sh
$ jq -n 'error({code: 42, msg: "boom"})'
jq: error (at <unknown>) (not a string): {"code":42,"msg":"boom"}
```

## Πώς πιάνεις σφάλματα: `try` και `catch`

Τα σφάλματα μπορούν να πιαστούν με το [`try EXP catch HANDLER`][man-try-catch].
Η πρώτη έκφραση εκτελείται· αν πετάξει κάποιο σφάλμα, τότε εκτελείται η έκφραση `HANDLER` **με την τιμή του σφάλματος ως είσοδό της**.
Η έξοδος του χειριστή εμφανίζεται σαν να ήταν η έξοδος της έκφρασης που δοκιμάστηκε.

```jq
true | try .a catch "cannot index a \(type)"
# => "cannot index a boolean"

[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]

true | try error("some exception") catch .
# => "some exception"
```

Η συντομότερη μορφή `try EXP` ισοδυναμεί με `try EXP catch empty`: το σφάλμα απορρίπτεται και δεν παράγεται καμία έξοδος.

```jq
[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]
```

~~~~exercism/note
Ένα σφάλμα **διακόπτει την υπόλοιπη ροή** μέσα στο `try`.
Οι τιμές που έχουν ήδη παραχθεί διατηρούνται, αλλά τίποτα μετά το σφάλμα δεν αξιολογείται.

```jq
jq -n 'try (1, error("x"), 3) catch "caught: \(.)"'
# outputs:
# 1
# "caught: x"
# (3 is never produced)
```
~~~~

Ένας χειριστής μπορεί να πετάξει ένα νέο σφάλμα ή να ξαναπετάξει το αρχικό με ένα σκέτο `error`. Επειδή η τιμή του σφάλματος είναι η είσοδος του χειριστή, αυτό τη διαδίδει αναλλοίωτη.

```jq
try repeat(f) catch
  if . == "break" then empty else error end
```

## Καταστολή σφαλμάτων: ο τελεστής `?`

Ο [τελεστής `?`][man-question-mark], όταν χρησιμοποιείται ως `EXP?`, είναι συντομογραφία του `try EXP`.
Μετατρέπει μια έκφραση που αποτυγχάνει σε μια έκφραση που απλώς δεν παράγει καμία έξοδο.

```jq
["1", "invalid", "3", 4] | [.[] | tonumber?]
# => [1, 3, 4]

true | [.a?]
# => []
```

Συχνά τον βλέπεις κολλημένο στους τελεστές πρόσβασης σε θέση:

- Το `.foo?` είναι το `.["foo"]?`
- Το `.[]?` κάνει επανάληψη μόνο αν η είσοδος είναι πίνακας ή αντικείμενο, αλλιώς δεν παράγει τίποτα

~~~~exercism/caution
Ο `?` καταστέλλει **κάθε** σφάλμα, ακόμα και εκείνα που δεν περίμενες.
Το `user.name?` δεν παράγει τίποτα σιωπηλά όταν το `user` δεν είναι αντικείμενο, κάτι που μπορεί να κρύψει προβλήματα δεδομένων ή τυπογραφικά λάθη στο πρόγραμμά σου.
Προτίμησε το `try ... catch` όταν χρειάζεται να ξέρεις _ότι_ κάτι απέτυχε, ή επικύρωσε την είσοδο ρητά.
~~~~

## Ο εναλλακτικός τελεστής `//`

Οι προγραμματιστές περιμένουν μερικές φορές ότι το `a // b` θα παράγει `b` όταν το `a` αποτυγχάνει.
Αυτό ίσχυε σε παλιές εκδόσεις της `jq`, αλλά όχι από την `jq` 1.6 και μετά.
Ο τελεστής `//` δεν καταστέλλει τα σφάλματα.
Αντικαθιστά το `b` μόνο όταν το `a` δεν παράγει καμία τιμή, όταν παράγει `false` ή `null`· τα σφάλματα στο `a` εξακολουθούν να διαδίδονται.

```sh
$ jq -n '(error("x")) // 42'
jq: error (at <unknown>): x
```

Χρησιμοποίησε το `try a catch b` αν θέλεις ένα εφεδρικό για τα σφάλματα.

## Ο εναλλακτικός τελεστής αποδόμησης `?//`

Ο [τελεστής `?//`][man-question-mark-slash-slash] συνδυάζει την αποδόμηση με τον χειρισμό σφαλμάτων.
Δοκιμάζει κάθε μοτίβο ανάθεσης με τη σειρά μέχρι ένα να πετύχει, και οι μεταβλητές που δεσμεύονται από τις αποτυχημένες εναλλακτικές ορίζονται σε `null`.

```jq
# input:
#   [
#     {"a": 1, "b": 2, "c": {"d": 3, "e": 4}},
#     {"a": 5, "b": 6, "c": [{"d": 7, "e": 8}]}
#   ]

.[] as {$a, $b, c: {$d, $e}} ?// {$a, $b, c: [{$d, $e}]}
| {$a, $b, $d, $e}

# outputs:
# {"a": 1, "b": 2, "d": 3, "e": 4}    # first element: c is an object, first pattern matched
# {"a": 5, "b": 6, "d": 7, "e": 8}    # second element: c is an array, second pattern matched
```

Εδώ το πρώτο μοτίβο περιμένει το `c` να είναι ένα _αντικείμενο_ με κλειδιά `d` και `e`, ενώ το δεύτερο περιμένει το `c` να είναι ένας _πίνακας_ που περιέχει ένα τέτοιο αντικείμενο.
Το πρώτο στοιχείο της εισόδου δεσμεύεται με το πρώτο μοτίβο· το δεύτερο στοιχείο αποτυγχάνει σε αυτό το μοτίβο, οπότε δοκιμάζεται το δεύτερο.

Έτσι, ένα μόνο πρόγραμμα μπορεί να αποδομήσει εισόδους που μπορεί να έχουν μία από πολλές μορφές, χωρίς να γράψεις ρητές αλυσίδες `if type == ...`.

## Τερματισμός του προγράμματος: `halt` και `halt_error`

Μερικές φορές η σωστή αντίδραση σε ένα σφάλμα είναι να σταματήσεις εντελώς την επεξεργασία.

- Το [`halt`][man-halt] σταματά αμέσως το πρόγραμμα `jq` χωρίς άλλη έξοδο· η κατάσταση εξόδου είναι `0`.
- Το [`halt_error`][man-halt-error] σταματά το πρόγραμμα, εκτυπώνει την **είσοδό** του στην _τυπική έξοδο σφαλμάτων_ ως ακατέργαστο κείμενο (χωρίς διακόσμηση, ούτε καν αλλαγή γραμμής) και τερματίζει με την κατάσταση που του δίνεται, με προεπιλογή το `5`.

```sh
$ echo '"Error: something went wrong"' | jq 'halt_error(1)'
Error: something went wrong    # printed on stderr, exit status 1
```

Σημείωσε ότι αυτά τα φίλτρα τερματίζουν το πρόγραμμα αμέσως, ακόμα κι αν απομένουν άλλες είσοδοι να διαβαστούν.

### Καταστάσεις εξόδου

Για αναφορά, η `jq` χρησιμοποιεί τις εξής καταστάσεις εξόδου:

| Κατάσταση | Σημασία                                          |
| :----: | ------------------------------------------------ |
| `0`    | επιτυχία                                          |
| `2`    | σφάλμα χρήσης (λάθος επιλογές γραμμής εντολών)    |
| `3`    | σφάλμα μεταγλώττισης                              |
| `5`    | σφάλμα κατά την εκτέλεση (ή `halt_error` χωρίς όρισμα) |

Με την επιλογή `--exit-status` / `-e`, η κατάσταση αντικατοπτρίζει αντίθετα την τελευταία τιμή εξόδου: `0` για `true` ή αριθμούς, `1` για `false` ή `null`, `4` για καμία έξοδο.

## Βοηθήματα αποσφαλμάτωσης

Όταν ψάχνεις από πού προέρχεται ένα σφάλμα, αυτά τα φίλτρα βοηθούν:

- Το [`debug`][man-debug] περνά την είσοδό του αναλλοίωτη, αλλά εκτυπώνει το `["DEBUG:", <input>]` στην τυπική έξοδο σφαλμάτων.
  Το `debug(msgs)` εκτυπώνει και τα `msgs` ως μηνύματα αποσφαλμάτωσης.
- Το [`stderr`][man-stderr] εκτυπώνει την είσοδό του, ακατέργαστη και συμπαγή, στην τυπική έξοδο σφαλμάτων.
- Το [`input_line_number`][man-input-line-number] βγάζει τον αριθμό γραμμής της εισόδου που φιλτράρεται εκείνη τη στιγμή. Είναι ανεκτίμητο όταν ένα αρχείο περιέχει πολλά κείμενα JSON και ένα από αυτά είναι προβληματικό.
- Το [`$__loc__`][man-loc] βγάζει ένα αντικείμενο με κλειδιά `file` και `line` που περιγράφουν πού εμφανίζεται μέσα στο πρόγραμμα, το οποίο μπορεί να ενσωματωθεί σε μηνύματα σφαλμάτων.

```jq
def checked_div($d):
  if $d == 0
  then error("\($__loc__): division by zero")
  else . / $d end;

try (10 | checked_div(0)) catch .
# => "{\"file\":\"<top-level>\",\"line\":3}: division by zero"
```
