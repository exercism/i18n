# Εισαγωγή

## Η διεπαφή error

Ο χειρισμός σφαλμάτων **δεν** γίνεται μέσω εξαιρέσεων στη Go.
Αντ' αυτού, τα σφάλματα είναι κανονικές _τιμές_ τύπων που υλοποιούν την ενσωματωμένη διεπαφή `error`.
Η διεπαφή `error` είναι πολύ λιτή.
Περιέχει μόνο μία μέθοδο, τη `Error()`, που επιστρέφει το μήνυμα σφάλματος ως συμβολοσειρά.

```go
type error interface {
  Error() string
}
```

Κάθε φορά που ορίζεις μια συνάρτηση στην οποία μπορεί να προκύψει ένα σφάλμα κατά την εκτέλεση που πρέπει να φτάσει στον καλούντα, πρέπει να συμπεριλάβεις το `error` ως έναν από τους τύπους επιστροφής.
Αν η συνάρτηση έχει πολλαπλές τιμές επιστροφής, κατά σύμβαση το `error` είναι πάντα η τελευταία.

```go
func DoSomething() (int, error) {
  // ...
}
```

## Δημιουργία και επιστροφή ενός απλού σφάλματος

Δε χρειάζεται να υλοποιείς πάντα μόνος σου τη διεπαφή error.
Για να δημιουργήσεις ένα απλό σφάλμα, μπορείς να χρησιμοποιήσεις τη συνάρτηση `errors.New()` που ανήκει στο πακέτο `errors` της πρότυπης βιβλιοθήκης.
Το μόνο που χρειάζεται να περάσεις είναι το μήνυμα σφάλματος ως συμβολοσειρά, και η `errors.New()` θα αναλάβει να δημιουργήσει μια τιμή που περιέχει το μήνυμά σου και υλοποιεί τη διεπαφή `error`.

Αν η συνάρτηση επιστρέφει σφάλμα, είναι καλή πρακτική να επιστρέφεις τη μηδενική τιμή για όλες τις άλλες παραμέτρους επιστροφής:

```go
func DoSomething() (SomeStruct, int, error) {
  // ...
  return SomeStruct{}, 0, errors.New("failed to calculate result")
}
```

~~~~exercism/caution
Δεν πρέπει να υποθέτεις ότι όλες οι συναρτήσεις επιστρέφουν μηδενικές τιμές για τις άλλες τιμές επιστροφής όταν υπάρχει σφάλμα.
Η καλύτερη πρακτική είναι να υποθέτεις ότι δεν είναι ασφαλές να χρησιμοποιήσεις καμία από τις άλλες τιμές επιστροφής αν προέκυψε σφάλμα.
Οι μόνες εξαιρέσεις είναι οι περιπτώσεις όπου η τεκμηρίωση δηλώνει ξεκάθαρα ότι άλλες τιμές επιστροφής έχουν νόημα σε περίπτωση σφάλματος.
~~~~

Αν θέλεις να χρησιμοποιήσεις ένα τέτοιο απλό σφάλμα σε πολλά σημεία, καλό είναι να δηλώσεις μια μεταβλητή για το σφάλμα αντί να χρησιμοποιείς την `errors.New` απευθείας.
Κατά σύμβαση, το όνομα της μεταβλητής πρέπει να ξεκινά με `Err` ή `err` (ανάλογα με το αν εξάγεται ή όχι).
Αυτές οι μεταβλητές σφάλματος συχνά ονομάζονται _sentinel errors_.

```go
import "errors"

var ErrNotFound = errors.New("resource was not found")

func DoSomething() error {
  // ...
  return ErrNotFound
}
```

Επίστρεψε `nil` για το σφάλμα, για να δηλώσεις ότι δεν υπήρξαν σφάλματα κατά την εκτέλεση της συνάρτησης:

```go
func Foo() (int, error) {
  return 10, nil
}
```

## Έλεγχος σφαλμάτων

Αν καλέσεις μια συνάρτηση που επιστρέφει σφάλμα, συνηθίζεται να αποθηκεύεις την τιμή του σφάλματος σε μια μεταβλητή με όνομα `err`.
Πριν χρησιμοποιήσεις το πραγματικό αποτέλεσμα της συνάρτησης, πρέπει να ελέγξεις ότι δεν υπήρξε σφάλμα.

Για να μην εμφωλευτεί το "happy path" του κώδικά σου, οι περιπτώσεις σφάλματος πρέπει να αντιμετωπίζονται πρώτες.
Μπορούμε να χρησιμοποιήσουμε τα `==` και `!=` για να συγκρίνουμε το σφάλμα με το `nil`, και ξέρουμε ότι υπήρξε σφάλμα όταν το `err` δεν είναι `nil`.

```go
func processUserFile() error {
	file, err := os.Open("./users.csv")
	if err != nil {
		return err
	}

	// do something with file
}
```

Τις περισσότερες φορές, το σφάλμα θα επιστραφεί προς τα πάνω στη στοίβα των συναρτήσεων, όπως φαίνεται στο παραπάνω παράδειγμα.
Ένας άλλος τρόπος να χειριστείς το σφάλμα θα ήταν να το καταγράψεις και να συνεχίσεις με κάποια άλλη ενέργεια.
Είναι καλή πρακτική είτε να επιστρέφεις είτε να καταγράφεις το σφάλμα, ποτέ και τα δύο.

Επειδή οι περισσότερες συναρτήσεις στη Go περιλαμβάνουν ένα σφάλμα ως μία από τις τιμές επιστροφής, θα δεις και θα χρησιμοποιήσεις το μοτίβο `if err != nil` παντού στον κώδικα Go.

## Προσαρμοσμένοι τύποι σφαλμάτων

Αν θέλεις το σφάλμα σου να περιλαμβάνει περισσότερες πληροφορίες από το απλό μήνυμα σφάλματος ως συμβολοσειρά, μπορείς να δημιουργήσεις έναν προσαρμοσμένο τύπο σφάλματος.
Όπως αναφέρθηκε προηγουμένως, ό,τι υλοποιεί τη διεπαφή `error` (δηλαδή έχει μέθοδο `Error() string`) μπορεί να λειτουργήσει ως σφάλμα στη Go.

Συνήθως, χρησιμοποιείται ένα struct για τη δημιουργία ενός προσαρμοσμένου τύπου σφάλματος.
Κατά σύμβαση, τα ονόματα των προσαρμοσμένων τύπων σφάλματος πρέπει να τελειώνουν σε `Error`.
Επίσης, είναι καλύτερο να ορίσεις τη μέθοδο `Error() string` με δέκτη δείκτη. Δες αυτό το [σχόλιο στο Stackoverflow][stackoverflow-errors] για να καταλάβεις το σκεπτικό.
Σημείωσε ότι αυτό σημαίνει πως πρέπει να επιστρέψεις έναν δείκτη στο προσαρμοσμένο σφάλμα σου, αλλιώς δε θα μετράει ως `error`, επειδή η τιμή που δεν είναι δείκτης δεν παρέχει τη μέθοδο `Error() string`.

```go
type MyCustomError struct {
  message string
  details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.message, e.details)
}

func someFunction() error {
  // ...
  return &MyCustomError{
    message: "...",
    details: "...",
  }
}
```
