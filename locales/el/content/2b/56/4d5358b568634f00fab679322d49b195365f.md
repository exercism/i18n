_"Οι ημερομηνίες και οι ώρες είναι κάτι που το μαθαίνουμε σε μικρά παιδιά. Πόσο δύσκολο μπορεί να είναι;"_

Πολλοί προγραμματιστές έχουν κάνει αυτό το λάθος και η εμπειρία που ακολουθεί συνήθως έχει άσχημη επίδραση στην υγεία και την ευτυχία τους.

Όποιος κάνει μη τετριμμένο προγραμματισμό με ημερομηνίες και ώρες θα πρέπει τουλάχιστον να είναι έτοιμος να κατανοήσει και να μετριάσει πιθανά προβλήματα.

Αυτό το κείμενο θα επιχειρήσει να δώσει μια επισκόπηση του πώς η R χειρίζεται τις ημερομηνίες και τις ώρες, αλλά για περισσότερες λεπτομέρειες θα χρειαστεί να συμβουλευτείς την πλήρη τεκμηρίωση.

Ως γλώσσα επιστήμης δεδομένων, η R δίνει ιδιαίτερη σημασία στις ημερομηνίες και τις ώρες.
Μεγάλο μέρος των δεδομένων φτάνει με τη μορφή χρονοσειρών: ο ημερήσιος αριθμός ασθενών κατά τη διάρκεια μιας επιδημίας, τα μηνιαία στοιχεία απασχόλησης που αναφέρουν οι κυβερνήσεις, οι πληθυσμοί πουλιών σε μια αποικία φωλιάσματος, το ετήσιο ΑΕΠ των μεγάλων οικονομιών και ατελείωτα ακόμη παραδείγματα.

_Αυτό σημαίνει ότι η R κάνει απλό τον χειρισμό ημερομηνιών και ώρας;_

Δυστυχώς, όχι!

Η λειτουργικότητα ημερομηνίας και ώρας στη Base R έχει κακή φήμη και το μεγαλύτερο μέρος της σπάνια χρησιμοποιείται πλέον.

Το πακέτο [`lubridate`][web-lubridate] είναι μεγάλη βελτίωση, αλλά να είσαι έτοιμος για μια μεγάλη και περίπλοκη βιβλιοθήκη, σχεδιασμένη να χειρίζεται ένα μεγάλο και περίπλοκο φάσμα προβλημάτων.

Αρχικά ανεξάρτητο, το `lubridate` πλέον διανέμεται μαζί με τη συλλογή `tidyverse`.

Πόροι που θα σε βοηθήσουν να δουλέψεις με το `lubridate` περιλαμβάνουν:

- Ένα [φύλλο γρήγορης αναφοράς][cheat-lubridate] σε μορφή PDF.

## Ημερομηνίες και ημερομηνίες-ώρες

Μια `date` είναι απλώς μια ημέρα, χωρίς πληροφορία ώρας.

Εσωτερικά, οι ημερομηνίες αποθηκεύονται ως ο (προσημασμένος) αριθμός ημερών από τις `1970-01-01`.

```R
today()
#> [1] "2026-04-22"
```

Μια `datetime` συνδυάζει πληροφορίες ημερομηνίας, ώρας και ζώνης ώρας.

Εσωτερικά, αποθηκεύεται ως ο αριθμός δευτερολέπτων από την αρχή του 1970 στη ζώνη ώρας UTC.

```R
now()
#> [1] "2026-04-22 15:37:11 MST"  # mid-afternoon in Arizona
```

Ίσως παραδόξως, η R δεν έχει εσωτερική αναπαράσταση για τιμές που περιέχουν μόνο ώρα.

## Εργασία με τιμές `date` και `datetime`

Ίσως οι πιο συχνές ανάγκες με ημερομηνίες και ώρες είναι:

- Να αναλύσεις μια κατάλληλη μορφή εισόδου για να κατασκευάσεις μια ημερομηνία ή ημερομηνία-ώρα.
- Να πάρεις την απαιτούμενη αριθμητική μορφή ή μορφή συμβολοσειράς από μια ημερομηνία ή ημερομηνία-ώρα.
- Να εφαρμόσεις μια μετατόπιση σε μια τιμή ημερομηνίας ή ημερομηνίας-ώρας.
- Να υπολογίσεις το χρονικό διάστημα ανάμεσα σε δύο τέτοιες τιμές.
- Να πάρεις την τρέχουσα ημερομηνία (με `today()`) ή/και την ημερομηνία-ώρα (με `now()`).

### Ανάλυση από συμβολοσειρές

Υπάρχουν πολλοί τρόποι να γράψεις ημερομηνίες και ώρες, και συνήθως εξαρτώνται από τον πολιτισμό.
Οι ημερομηνίες με μόνο αριθμούς, όπως "7/6/23", είναι διφορούμενες, μπερδεύουν και έχουν οδηγήσει σε πολλά ακριβά λάθη σε πολυεθνικούς οργανισμούς (_ο συγγραφέας το λέει αυτό από πικρή προσωπική εμπειρία_).

Το διεθνές πρότυπο (y-m-d) ορίζεται στο [`ISO 8601`][wiki-ISO8601] και έχει δύο βασικά πλεονεκτήματα:

- Η ανάλυση είναι γρήγορη και μονοσήμαντη.
- Η ταξινόμηση είναι εύκολη, αφού η ημερομηνία-ώρα μπορεί να αντιμετωπιστεί ως απλό κείμενο και να ταξινομηθεί αλφαβητικά.

Ωστόσο, η επιστήμη δεδομένων αφορά την εργασία με όποια δεδομένα μπορείς να βρεις, και συχνά είναι άσκοπο να παραπονιέσαι για το πώς τα μορφοποιούν οι άλλοι.

Η Base R έχει συναρτήσεις μετατροπής που δέχονται μια συμβολοσειρά μορφής (με προεπιλογή το ISO 8601).

```R
as.Date("2026-04-22")
#> [1] "2026-04-22"
as.Date("4/22/26", format = "%m/%d/%y")
#> [1] "2026-04-22"
as.POSIXct("2026-04-22 15:30:09 MST")
#> [1] "2026-04-22 15:30:09 MST"
```

Οι συμβολοσειρές μορφής μοιάζουν με τη συνάρτηση `strptime()`, που υπάρχει εδώ και δεκαετίες και περιλαμβάνεται σε _πολλές_ γλώσσες.
Οι προγραμματιστές που είναι εξοικειωμένοι με αυτή τη σύνταξη μπορούν προαιρετικά να χρησιμοποιήσουν τη συνάρτηση [`fast_strptime()`][ref-parse_dt] στο lubridate.

Ακόμη πιο βολικά, το `lubridate` παρέχει ένα ευρύ φάσμα [βοηθητικών συναρτήσεων][ref-parsing], με ονόματα που αντιπροσωπεύουν τη σειρά των πεδίων.
Μόλις οι συναρτήσεις ξέρουν ποιες τιμές να αναζητήσουν και με ποια σειρά, η ανάλυση είναι εντυπωσιακά ευέλικτη.

```R
mdy("4/22/26")
#> [1] "2026-04-22"
mdy("April 22nd 26")
#> [1] "2026-04-22"
mdy("Wednesday, April 22nd 2026")
#> [1] "2026-04-22"
mdy_hm("Wednesday, April 22nd 2026, 4:14 pm")
#> [1] "2026-04-22 16:14:00 UTC"  # defaults to your OS timezone
```

### Κατασκευή από αριθμητικές τιμές

Σε περιπτώσεις όπου το πρόγραμμά σου έχει τα συστατικά μιας ημερομηνίας/ημερομηνίας-ώρας ως ξεχωριστούς αριθμούς, μπορούν να συναρμολογηθούν με τις [`make_date()` ή `make_datetime()`][ref-make_datetime].

Αυτά είναι τα συστατικά που μπορούν να δοθούν, μαζί με τη σειρά και τις προεπιλεγμένες τιμές τους:

```R
make_datetime(
  year = 1970L,
  month = 1L,
  day = 1L,
  hour = 0L,
  min = 0L,
  sec = 0,
  tz = "UTC"
)
#> [1] "1970-01-01 UTC"


make_datetime(2026, 4, 22, 17)
#> [1] "2026-04-22 17:00:00 UTC"
```

Φυσικά, η `make_date()` δέχεται μόνο ορίσματα για έτος, μήνα και ημέρα.

### Έξοδος σε μορφή αναγνώσιμη από τον άνθρωπο

Η κονσόλα της R εμφανίζει αυτόματα τις ημερομηνίες/ημερομηνίες-ώρες ως αναπαράσταση συμβολοσειράς.
Αυτό είναι συνήθως βολικό, αλλά μερικές φορές παραπλανητικό.

Εσωτερικά, οι ημερομηνίες και οι ημερομηνίες-ώρες είναι αριθμοί (συν μερικά χαρακτηριστικά), όχι συμβολοσειρές.
Το να επιστρέψεις μια ημερομηνία(ώρα) όταν αναμένεται συμβολοσειρά θα προκαλέσει προβλήματα, οπότε πρέπει να ξέρουμε πώς να κάνουμε τη μετατροπή.

Μια απλή προσέγγιση είναι να χρησιμοποιήσεις τη [`as.character()`][ref-ascharacter] από τη Base R, που επιστρέφει μια συμβολοσειρά σε μορφή ISO 8601.

Υπάρχει επίσης μια συνάρτηση [`format_ISO8601()`][ref-iso8601] για ημερομηνίες-ώρες, που έχει επιλογές για στρογγυλοποίηση σε επιθυμητή ακρίβεια.

```R
today() |> as.character()  # a date
#> [1] "2026-04-23"
now() |> as.character()  # a datetime
#> [1] "2026-04-23 09:07:09.779319"
now() |> format_ISO8601() # defaults to nearest second
#> [1] "2026-04-23T09:07:38"
```

Λίγοι μη προγραμματιστές θέλουν να βλέπουν έξοδο ISO 8601, οπότε ο χειρισμός μορφών ημερομηνίας/ώρας που εξαρτώνται από τον πολιτισμό είναι απαραίτητος.

Η Base R παρέχει τη συνάρτηση [`format()`][ref-format], που χρησιμοποιεί συμβολοσειρές μορφής παρόμοιες με τις σεβάσμιες συναρτήσεις `strftime()` που υπάρχουν σε πολλές άλλες γλώσσες.

```R
format(today(), "%A, %d %B %Y")
#> [1] "Thursday, 23 April 2026"
```

Αυτή η προσέγγιση της Base R είναι άσχημη αλλά αξιόπιστη.
Αυτοί είναι μερικοί από τους πιο συνηθισμένους κωδικούς:

Κωδικός | Αποτέλεσμα
-- | --
%d | Αριθμός ημέρας του μήνα (5, 17, 28, κ.λπ.)
%a | Συντομευμένη ημέρα εβδομάδας (Mon, Tue, Wed, κ.λπ.)
%A | Πλήρες όνομα ημέρας (Monday, Tuesday, κ.λπ.)
%w | Αριθμός ημέρας εβδομάδας (0-6, η Κυριακή είναι 0)
%u | Αριθμός ημέρας εβδομάδας (1-7, η Δευτέρα είναι 1)
%b | Συντομευμένος μήνας (Jan, Feb, κ.λπ.)
%B | Πλήρες όνομα μήνα (January, February, κ.λπ.)
%y | Διψήφιο έτος (π.χ. 89)
%Y | Τετραψήφιο έτος (π.χ. 1989)
%h | ώρες (ρολόι 24 ώρων)
%m | λεπτά
%s | δευτερόλεπτα
%z | μετατόπιση από το UTC
%Z | Ζώνη ώρας (χαρακτήρες)

Το Lubridate στοχεύει να προσφέρει μια πιο φιλική προς τον άνθρωπο εναλλακτική με τη συνάρτηση [`stamp()`][ref-stamp], καθώς και τις στενότερες `stamp_date()` και `stamp_time()`.

Αυτές δέχονται μια συμβολοσειρά-πρότυπο που αποτελεί παράδειγμα της επιθυμητής εξόδου και δημιουργούν μια προσαρμοσμένη συνάρτηση για να παράγουν αυτή τη μορφή.

Το Lubridate προσπαθεί να μαντέψει τη μορφή, αλλά συχνά συναντά ασάφειες και παράγει λάθος αποτέλεσμα.
Να είσαι έτοιμος να δώσεις συμβολοσειρές μορφής (όπως `"dmy"`) για να άρεις την ασάφεια.

Στο Exercism, μπορεί επίσης να είναι χρήσιμο να ορίσεις `locale = "C"`, για να παρακάμψεις τις τοπικές ρυθμίσεις του συστήματός σου και να δουλέψεις στα αγγλικά (όπως περιμένουν τα τεστ).
_Οι τοπικές ρυθμίσεις είναι περίπλοκες!_

```R
sf <- stamp("Saturday, June 27, 2026 at 14:45", locale = "C")
#> Multiple formats matched: "%A, %B %d, %Y at %H:%M"(1), "Saturday, %Om %d, %Y at %H:%M"(1), "Saturday, %B %d, %Y at %H:%M"(1), "%A, %Om %d, %Y at %H:%M"(0)
#> Using: "%A, %B %d, %Y at %H:%M"

sf(make_datetime(2023, 3, 29, 15, 0, 0))
#> [1] "Wednesday, March 29, 2023 at 15:00"
```

### Ορισμός ή εξαγωγή συστατικών

Το Lubridate παρέχει [πολλές συναρτήσεις][ref-set-get] για να πάρεις ή να ορίσεις στοιχεία μιας ημερομηνίας ή ημερομηνίας-ώρας: προφανείς όπως οι `year()` και `second()`, αλλά και πιο εξειδικευμένες όπως οι `quarter()` και `epiweek()`.

Όλες αυτές οι συναρτήσεις μπορούν να χρησιμοποιηθούν για να πάρεις μια τιμή, και οι περισσότερες μπορούν επίσης να χρησιμοποιηθούν για να ορίσεις την τιμή.

```R
dt <- now()
dt
#> [1] "2026-04-23 15:47:11 MST"

# get
month(dt)
#> [1] 4

# set
month(dt) <- 11
dt
#> [1] "2026-11-23 15:47:11 MST"
```

Για τις `wday()` (ημέρα εβδομάδας) και `month()`, η προεπιλογή είναι ακέραια έξοδος, αλλά:

- Με `labels = TRUE` επιστρέφεται μια συντομευμένη συμβολοσειρά χαρακτήρων που αντιστοιχεί στις τρέχουσες τοπικές ρυθμίσεις.
- Με `abbr = FALSE` επιστρέφεται το πλήρες όνομα.

```R
d <- today()
d
#> [1] "2026-04-23"
wday(d)
#> [1] 5
wday(d, label = TRUE)
#> [1] Thu
#> Levels: Sun < Mon < Tue < Wed < Thu < Fri < Sat
wday(d, label = TRUE, abbr = FALSE)
#> [1] Thursday
#> Levels: Sunday < Monday < Tuesday < Wednesday < Thursday < Friday < Saturday
```

Οι ετικέτες είναι `categorical variables`, κάτι που θα αποτελέσει αντικείμενο άλλης Έννοιας.
Οι τιμές περιορίζονται στα καταγεγραμμένα `Levels`, που δείχνουν επίσης τη σειρά ταξινόμησης.

Η εβδομάδα ξεκινά την Κυριακή από προεπιλογή, αλλά αυτό μπορεί να αλλάξει με το όρισμα `week_start` (χρησιμοποίησε `1` για τη Δευτέρα).

```R
dt <- make_datetime(2026, 4, 23)

# default behavior
wday(dt)
#> [1] 5
wday(dt, label = T)
#> [1] Thu

# set week_start to Monday
wday(dt, week_start = 1)
#> [1] 4
```

Λίγες βοηθητικές συναρτήσεις επιστρέφουν τιμές `TRUE`/`FALSE`, όπως οι `leap_year()` και `dst()` (είναι ενεργή η θερινή ώρα;).

Οι μήνες έχουν διαφορετικό μήκος, οπότε η `days_in_month()` δίνει την ακέραια τιμή.

## Χρονικά διαστήματα

Τόσο οι τιμές `date` όσο και οι τιμές `datetime` αντιπροσωπεύουν μια χρονική στιγμή πάνω στη γραμμή του χρόνου.

Πώς χειριζόμαστε έννοιες όπως "χθες τέτοια ώρα" ή "σε μια εβδομάδα από τώρα";

Όσοι έχουν εξοικείωση με άλλες γλώσσες προσανατολισμένες στην επιστήμη μπορεί να γνωρίζουν το `datetime.timedelta` στην Python ή τον τύπο `Period` στη Julia.

Αντίθετα, η R έχει όχι λιγότερους από τρεις τρόπους να αναπαραστήσει χρονικά διαστήματα, με διαφορετικά πλεονεκτήματα και περιορισμούς.
Όπως πάντα, διάλεξε αυτόν που ταιριάζει καλύτερα στο πλαίσιό σου.

Τα διάφορα είδη διαστημάτων μπορούν εύκολα να μετατραπούν μεταξύ τους, με τις `as.period()`, `as_duration()` και `as.interval()`.

Οι τύποι διαστημάτων μπορούν να ελεγχθούν με την `is.period()` κ.λπ.

### Περίοδοι

Μια `period`, όπως η `hours(3)`, μπορεί να χρησιμοποιηθεί για να αυξήσεις μια ώρα ρολογιού κατά 3 ώρες.

Οι ανωμαλίες όπως η θερινή ώρα (DST) αγνοούνται σε μεγάλο βαθμό.

Όλες οι περίοδοι είναι το όνομα μιας μονάδας σε πληθυντικό: `years`, `weeks`, κ.λπ.

```R
d <- today()
d
#> [1] "2026-04-25"

d + weeks(2)
#> [1] "2026-05-09"

# dates are coerced to datetimes at midnight if necessary
d - hours(20)
#> [1] "2026-04-24 04:00:00 UTC"

hours(3)
#> [1] "3H 0M 0S"
```

### Διάρκειες

Μια `duration`, όπως η `dhours(3)`, αυξάνει τον φυσικό χρόνο κατά 3 ώρες, λαμβάνοντας υπόψη ανωμαλίες όπως η θερινή ώρα που κάνουν την ώρα ρολογιού να αποκλίνει από τον φυσικό χρόνο.

Όλες οι διάρκειες προσθέτουν το πρόθεμα `d` στην αντίστοιχη περίοδο: `dyears`, `dweeks`, κ.λπ.

```R
dhours(3)
#> [1] "10800s (~3 hours)"
```

### Διαστήματα

Ένα `interval` είναι ένας συνδυασμός χρόνου έναρξης και λήξης, που δημιουργείται είτε με τη συνάρτηση [`interval()`][ref-interval] είτε με τον ένθετο τελεστή `%--%`.

```R
# the next 2 lines were run about 33s apart, so now() is different
dt1 <- now()
dt2 <- now() + hours(1)

# interval(0 function)
ivl <- interval(dt1, dt2)
ivl
#> [1] 2026-04-24 16:24:54 MST--2026-04-24 17:25:27 MST

# infix operator
iv2 <- dt1 %--% dt2
iv2 == iv1
#> [1] TRUE
```

## Ζώνες ώρας

Η ενασχόληση με τις ζώνες ώρας μπορεί να είναι δύσκολη.
Το παρακάτω απόσπασμα είναι από την τεκμηρίωση της Python, αλλά είναι εξίσου σχετικό με τη R:

> "Οι κανόνες για τη ρύθμιση της ώρας σε όλο τον κόσμο είναι περισσότερο πολιτικοί παρά ορθολογικοί, αλλάζουν συχνά και δεν υπάρχει πρότυπο κατάλληλο για κάθε εφαρμογή εκτός από το UTC."

Μερικά γενικά σημεία για τις ζώνες ώρας:

- Μια `datetime` περιλαμβάνει πάντα μια ζώνη ώρας (`tz`); μια `date` δεν γνωρίζει ζώνη ώρας.
- Οι κατασκευαστές ημερομηνιών-ωρών έχουν γενικά προεπιλογή το [UTC][wiki-UTC].
- Η συνάρτηση [`now()`][ref-now] αποτελεί εξαίρεση: παίρνει την τοπική σου ώρα από το ρολόι του συστήματος, μαζί με το `tz`.
  Από προεπιλογή χρησιμοποιείται το τοπικό `tz`, αλλά μπορούν να οριστούν και άλλα, όπως `now("UTC")`.

```R
# timezone defaults to UTC
local <- ymd_hm("2026-04-25 10:32")
local
#> [1] "2026-04-25 10:32:00 UTC"

# timezone can be specified
AZ <- ymd_hm("2026-04-25 10:32", tz = "America/Phoenix")
AZ
#> [1] "2026-04-25 10:32:00 MST"

# same clocktime, different tz
local - AZ
#> Time difference of -7 hours
```

Η αριθμητική που σχετίζεται με ζώνες ώρας είναι πιο αξιόπιστη με διάρκειες παρά με περιόδους.
