# Εισαγωγή

Μια συνάρτηση είναι **αναδρομική** όταν καλεί τον εαυτό της.

Μια σημαντική διαφορά ανάμεσα σε μια κλήση συνάρτησης και έναν βρόχο είναι ότι η κλήση μιας συνάρτησης βάζει στη στοίβα τη διεύθυνση στην οποία θα επιστρέψει.
Αυτό σημαίνει ότι μια αναδρομική συνάρτηση συνήθως απαιτεί περισσότερο χώρο στη στοίβα από έναν ισοδύναμο βρόχο.

Κατά συνέπεια, μια συνάρτηση που καλεί συνέχεια τον εαυτό της μπορεί τελικά να εξαντλήσει όλο τον χώρο της στοίβας.
Αυτό ονομάζεται **υπερχείλιση στοίβας**.

Γι' αυτό κάθε αναδρομική συνάρτηση πρέπει να έχει τουλάχιστον μία βασική περίπτωση, δηλαδή μια περίπτωση όπου η συνάρτηση επιστρέφει χωρίς να καλέσει τον εαυτό της.
Κάθε αναδρομική κλήση πρέπει τελικά να φτάνει σε μια βασική περίπτωση.

Για παράδειγμα, η συνάρτηση παραγοντικού `n! = n * (n - 1) * ... * 1` μπορεί να οριστεί αναδρομικά με το `1` ως βασική περίπτωση:

```x86asm
factorial:
    ; the argument `n` is passed on `rdi`
    ; the factorial will be returned on `rax`

    cmp rdi, 1
    jle .base_case     ; base case -> if rdi <= 1, return 1

    push rdi           ; save n
    dec rdi            ; rdi = n - 1
    call factorial     ; recursive call, rax = (n - 1)!
    pop rdi            ; restore n
    imul rax, rdi      ; rax = n * (n - 1)! = n!
    ret
.base_case:
    mov rax, 1
    ret
```

Σημείωσε ότι η `factorial` πρέπει να κάνει `push rdi` πριν την αναδρομή και `pop rdi` μετά.
Ο λόγος είναι ότι χρειάζεται ακόμα το `n` όταν επιστρέψει η αναδρομική κλήση, για να υπολογίσει το `n * (n-1)!`.

Σημείωσε επίσης ότι η χρήση ενός καταχωρητή που διατηρείται από τον καλούμενο δεν θα έλυνε αυτό το πρόβλημα.

Αν και μια αναδρομική συνάρτηση είναι δυνητικά καλούσα του εαυτού της, είναι και η ίδια καλούμενη από κάποια άλλη συνάρτηση.
Αυτό σημαίνει ότι η συνάρτηση πρέπει επίσης να διατηρεί τους καταχωρητές που διατηρούνται από τον καλούμενο πριν τους χρησιμοποιήσει, και να επαναφέρει την τιμή τους αφού χρησιμοποιηθούν.
Αυτό γίνεται συνήθως με μια ακολουθία `push`/`pop`, όπως είδαμε σε μια προηγούμενη έννοια.

Επειδή κάθε πλαίσιο μιας αναδρομικής συνάρτησης, με εξαίρεση τη βασική περίπτωση, είναι επίσης καλών που πρέπει να διατηρήσει τις δικές του τοπικές μεταβλητές, αυτή η ακολουθία `push`/`pop` πρέπει να επαναλαμβάνεται για κάθε πλαίσιο.
Ακόμα και η αποθήκευση της μεταβλητής απευθείας στη στοίβα, χωρίς τη χρήση καταχωρητών, θα κόστιζε πάλι τα ίδια `8` byte ανά πλαίσιο.

Αυτό σημαίνει ότι κάθε αναδρομική κλήση προσθέτει `8` byte στη στοίβα για τη διεύθυνση επιστροφής που βάζει η `call`, συν `8` byte για κάθε τοπική μεταβλητή που χρειάζεται να διατηρήσει.
Η συνάρτηση θα συνεχίζει να προσθέτει αυτά τα byte στη στοίβα σε κάθε πλαίσιο, ώσπου να φτάσει στη βασική περίπτωση.
Μόνο τότε αρχίζει να ξετυλίγεται με αντίστροφη σειρά, με κάθε αναδρομική κλήση να χρησιμοποιεί όσα `pop` χρειάζεται και μετά ένα `ret`.

Για παράδειγμα, αν η `factorial` καλείτο με όρισμα `10`, θα καλούσε τον εαυτό της εννιά φορές πριν φτάσει στη βασική περίπτωση του `1`.
Σε εκείνο το σημείο, θα είχαν χρησιμοποιηθεί `144` byte για την αποθήκευση του `n` (`8` byte) και της διεύθυνσης επιστροφής (`8` byte) για κάθε προηγούμενο πλαίσιο.

## Ουραία κλήση

Σε ορισμένες περιπτώσεις, μια συνάρτηση δεν εκτελεί άλλη εργασία αφού καλέσει κάποια άλλη και πριν επιστρέψει.

Δες, για παράδειγμα:

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    call times_three
    ret
```

Η συνάρτηση `triple_of_square`:

- πολλαπλασιάζει το όρισμα που της περνιέται (στο `rdi`) με τον εαυτό του, βρίσκοντας το τετράγωνό του,
- μετά καλεί την `times_three`, η οποία επιστρέφει το τριπλάσιο του ορίσματος που της περνιέται.

Ως αποτέλεσμα, η `triple_of_square` επιστρέφει `3*x²`, όπου `x` είναι το όρισμά της, που περνιέται στο `rdi`.

Σημείωσε ότι δεν γίνεται καμία εργασία στην `triple_of_square` μετά την κλήση της `times_three`, η συνάρτηση απλώς επιστρέφει.
Σε μια τέτοια περίπτωση, αντί να χρησιμοποιήσει `call`, μια συνάρτηση μπορεί να χρησιμοποιήσει `jmp` και να μεταφέρει την εκτέλεση στην καλούμενη συνάρτηση:

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    jmp times_three
```

Αυτό ονομάζεται **ουραία κλήση**.

Το κύριο πλεονέκτημα της ουραίας κλήσης είναι ότι αποφεύγεται το επιπλέον κόστος της `call`.
Μια `call` βάζει μια διεύθυνση επιστροφής στη στοίβα, και για να επιστρέψει ο έλεγχος σε εκείνο το σημείο πρέπει να υπάρχει ένα αντίστοιχο `ret`.

Η ουραία κλήση τα παραλείπει και τα δύο: δεν υπάρχει διεύθυνση επιστροφής να μπει στη στοίβα, ούτε επιπλέον `ret` για να ταιριάξει μαζί της, μόνο το δικό της `ret` της καλούμενης συνάρτησης.

## Ουραία αναδρομή

Η ουραία κλήση είναι ιδιαίτερα χρήσιμη για αναδρομικές συναρτήσεις που μπορεί να καλέσουν τον εαυτό τους πολλές φορές πριν επιστρέψουν.

Ωστόσο, δεν μπορεί να μετατραπεί απευθείας κάθε αναδρομική κλήση σε ουραία κλήση.
Επειδή η `jmp` μεταφέρει τον έλεγχο στην καλούμενη συνάρτηση, ο καλών δεν μπορεί να εκτελέσει άλλη εργασία μετά την ουραία κλήση.

Για παράδειγμα, η `factorial` που είδαμε πιο πάνω **δεν** είναι ουραία αναδρομική.
Μετά την αναδρομική κλήση, χρειάζεται ακόμα να πολλαπλασιάσει το αποτέλεσμα με το τρέχον `n`, χρησιμοποιώντας το `imul rax, rdi`.

Σε τέτοιες περιπτώσεις, είναι μερικές φορές δυνατό να χρησιμοποιηθεί ένας συσσωρευτής που θα συγκεντρώνει τους μερικούς υπολογισμούς και θα επιστρέφεται στο τέλος.
Για παράδειγμα, μπορούμε να ορίσουμε μια `factorial_helper` που κάνει το μεγαλύτερο μέρος της δουλειάς, και μετά η `factorial` να ετοιμάσει έναν συσσωρευτή και να μεταφέρει τον έλεγχο στη `factorial_helper`:

```x86asm
factorial_helper:
    ; the argument `n` is passed on `rdi`
    ; `rax` is used as an accumulator and will be returned at the end

    cmp rdi, 1
    jle .base_case

    imul rax, rdi        ; we accumulate the partial result on `rax`
    dec rdi              ; rdi = n - 1
    jmp factorial_helper ; tail call to accumulate (n - 1)!
.base_case:
    ret                  ; returns the factorial already accumulated on `rax`

factorial:
    mov rax, 1           ; initial value for the accumulator
    jmp factorial_helper ; tail call
```

Επειδή δεν γίνεται άλλη εργασία μετά την αναδρομική κλήση, δεν χρειάζεται πια να διατηρήσουμε το `rdi`.
Δεν υπάρχει `call` ούτε `push rdi`, οπότε κάθε αναδρομική επανάληψη προσθέτει `0` byte στη στοίβα: δεν χρησιμοποιείται επιπλέον χώρος στη στοίβα.
Αυτή η έκδοση μπορεί να χειριστεί οσοδήποτε μεγάλο `n` χωρίς να υπερχειλίσει τη στοίβα.
Είναι ταυτόχρονα πιο αποδοτική και πιο ασφαλής.

Σε ορισμένες περιπτώσεις, με αναδιάταξη της σειράς των συναρτήσεων, μπορεί να αποφευχθεί ακόμα και η `jmp` προς τη βοηθητική συνάρτηση.
Για παράδειγμα, οι `factorial` και `triple_of_square` μπορούν να ξαναγραφτούν ως εξής:

```x86asm
factorial:
    mov rax, 1
factorial_helper:
    cmp rdi, 1
    jle .base_case

    imul rax, rdi
    dec rdi
    jmp factorial_helper
.base_case:
    ret

triple_of_square:
    imul rdi, rdi
times_three:
    imul rax, rdi, 3
    ret
```

Στο παραπάνω απόσπασμα, η εκτέλεση της `factorial` συνεχίζει αυτόματα στη `factorial_helper`.
Το ίδιο συμβαίνει με τις `triple_of_square` και `times_three`.
Και στις δύο περιπτώσεις, η εκτέλεση συνεχίζει διαδοχικά και φαίνεται πως η ουραία συνάρτηση είναι απλώς μια τοπική ετικέτα μέσα στη "βασική" συνάρτηση.

Στην πραγματικότητα, δεν υπάρχει ουσιαστική διαφορά ανάμεσα σε μια τοπική ετικέτα και σε μια συνάρτηση.
Στη assembly x86-64, κανένα από αυτά δεν τυγχάνει ειδικής μεταχείρισης: είναι απλώς διευθύνσεις σε ένα τμήμα με εκτελέσιμο κώδικα, όπως το `section .text`.

Με αυτόν τον τρόπο, μια ουραία αναδρομική συνάρτηση μπορεί να θεωρηθεί ουσιαστικά το ίδιο με έναν βρόχο, όπου η αναδρομική κλήση πηγαίνει πίσω στην αρχή και η βασική περίπτωση είναι η συνθήκη που τερματίζει τον βρόχο.
