# Σχετικά

Στη Rust, ένας iterator είναι οποιαδήποτε τιμή που υλοποιεί το trait [`Iterator`](https://doc.rust-lang.org/stable/std/iter/trait.Iterator.html).
Μπορείς να προχωρήσεις χειροκίνητα τις τιμές ενός iterator καλώντας τη μέθοδο `next` πάνω στον iterator.

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // many built-in methods implemented
}
```

Πολλές από τις [`collections`](https://doc.rust-lang.org/std/collections/index.html) της Rust υλοποιούν το
[`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html),
το οποίο μπορεί να παράγει έναν `Iterator` από τις τιμές της συλλογής.

```rust
trait IntoIterator where Self::IntoIter: Iterator<Item=Self::Item> {
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}
```

Σημείωσε ότι, ενώ το `IntoIterator::into_iter` καταναλώνει τον τύπο του `self`, ο τύπος αυτός δε χρειάζεται απαραίτητα να είναι μια τιμή που κατέχεται.
Έτσι, υπάρχουν υλοποιήσεις του `IntoIterator` για [`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-2),
για [`&'a Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator)
και για [`&'a mut Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-1).
Αυτές οι υλοποιήσεις για διαφορετικούς βαθμούς ιδιοκτησίας παρέχουν χρήσιμη ευελιξία.

Η κατανόηση των `traits` δεν είναι απαραίτητη για αυτή την έννοια, και θα έχεις μια ολόκληρη άσκηση για να τα κατακτήσεις.
Για την ώρα, απλώς θυμήσου ότι:

- Οποιοσδήποτε τύπος υλοποιεί το `IntoIterator` ονομάζεται _iterable_, επειδή μπορεί να μετατραπεί σε iterator.
- Οποιοσδήποτε τύπος υλοποιεί το `Iterator` είναι ένας iterator, ο οποίος _παράγει_ τιμές και μπορείς να τον _διατρέξεις_.
- Μπορείς να πάρεις έναν iterator από οποιονδήποτε τύπο υλοποιεί το `IntoIterator`, καλώντας τη μέθοδο `into_iter`.
- Κάθε iterator [υλοποιεί το `IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html#impl-IntoIterator-25) και παράγει τον εαυτό του.
- Οι `for` βρόχοι λειτουργούν πάντα πάνω σε iterators και καλούν το `IntoIterator` έμμεσα στο όρισμα εύρους τους.

## Το `into_iter` και οι `for` βρόχοι

Πιθανότατα να είσαι εξοικειωμένος με τους `for` βρόχους πάνω σε ένα διάνυσμα:

```rust
// lor is a `Vec`, which implements `IntoIterator`
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
for people in &lor {
    println!("{people}");
}
```

Στην ουσία, ένας `for` βρόχος δεν είναι παρά συντομογραφία για την κλήση της μεθόδου `into_iter` του ορίσματός του
και στη συνέχεια της κλήσης της `next()` μέχρι να σταματήσει να παράγει στοιχεία. Με άλλα λόγια, ο προηγούμενος βρόχος αποζαχαρώνεται ως εξής:

```rust
{
    let mut iterator = (&lor).into_iter();
    while let Some(people) = iterator.next() {
        println!("{people}");
    }
}
```

## Οι μέθοδοι `iter` και `iter_mut`

Οι περισσότεροι τύποι συλλογών της Rust παρέχουν τις μεθόδους `iter` και `iter_mut`.
Για μια συλλογή τύπου `T`, αυτές οι δύο μέθοδοι κάνουν κατά σύμβαση τα εξής:

- Ο iterator που επιστρέφει η `iter` παράγει ένα `&T` με αμετάβλητο δανεισμό.
- Ο iterator που επιστρέφει η `iter_mut` παράγει ένα `&mut T` με μεταβλητό δανεισμό.

```rust
let mut v = vec![1, 2, 3];

// Using `iter` method
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&1));
assert_eq!(iterator.next(), Some(&2));
assert_eq!(iterator.next(), Some(&3));
assert_eq!(iterator.next(), None);

// Using `iter_mut` method
for value in v.iter_mut() {
     *value *= *value;
}
println!("{v:?}");
// => [1, 4, 9]
```

## Διαφορά μεταξύ `iter`, `iter_mut` και `into_iter`

Αν οι `iter`, `iter_mut` και `into_iter` παράγουν όλες iterators, ποιες είναι οι διαφορές;

- Ο iterator που επιστρέφει η `iter` παράγει κατά σύμβαση ένα `&T` με αμετάβλητο δανεισμό.
- Ο iterator που επιστρέφει η `iter_mut` παράγει κατά σύμβαση ένα `&mut T` με μεταβλητό δανεισμό.
- Ο iterator που επιστρέφει η `into_iter` μπορεί να παράγει `T`, `&T` ή `&mut T`, ανάλογα με το πλαίσιο.

Ποιο είναι το πλαίσιο για μια κλήση της `into_iter`;
Ο τύπος του `self` της.
Θυμήσου ότι υπάρχουν υλοποιήσεις του `IntoIterator` για `Vec`, `&'a Vec` και `&'a mut Vec`.
Επομένως:

- `(&v).into_iter()` ισούται με `v.iter()` => επιστρέφει `&T`
- `(&mut v).into_iter()` ισούται με `v.iter_mut()` => επιστρέφει `&mut T`
- `v.into_iter()` => επιστρέφει `T` και μετακινεί τις τιμές

Αυτό γίνεται πιο ξεκάθαρο στους `for` βρόχους:

- `for num in &v {...}` => δεσμεύει `&T`
- `for num in &mut v {...}` => δεσμεύει `&mut T`
- `for num in v {...}` => δεσμεύει `T` και μετακινεί τις τιμές

Συχνά είναι πιο ξεκάθαρο να γράψεις `v.iter()` αντί για `(&v).into_iter()`.
Επομένως, υπάρχουν εργονομικοί λόγοι για να προτιμήσεις τις `iter` και `iter_mut` αντί για την `into_iter`.

## Χρησιμοποιώντας τις ενσωματωμένες μεθόδους των iterators

Οι iterators παρέχουν πολλές ενσωματωμένες μεθόδους, όπως οι `map`, `filter` και `collect`.
Αυτές οι μέθοδοι χρησιμοποιούνται μερικές φορές μαζί με closures.

Η `map` χρησιμοποιεί ένα closure για να μετασχηματίσει τις τιμές ενός iterator.
Η `take` περικόπτει έναν (δυνητικά άπειρο) iterator σε έναν που τερματίζει μετά από το πολύ τον καθορισμένο αριθμό στοιχείων.

```rust
for even_number in (0..).into_iter().map(|x| x * 2).take(4) {
    let odd_number = even_number + 1;
    println!("{even_number} => {odd_number}");
}
// 0 => 1
// 2 => 3
// 4 => 5
// 6 => 7
```

Η `filter` μετασχηματίζει τον iterator σε έναν που επιστρέφει μόνο τις τιμές για τις οποίες το closure αξιολογείται σε `true`.
Η `count` καταναλώνει τον iterator και επιστρέφει τον αριθμό των στοιχείων που παράγονται.

```rust
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
let short_people = ["Dwarves", "Hobbits"];
let num_tall_people = lor.iter().filter(|people| !short_people.contains(people)).count();
assert_eq!(num_tall_people, 5);
```

Η `flat_map` μετασχηματίζει έναν iterator μετασχηματίζοντας κάθε στοιχείο σε έναν νέο iterator μέσω του closure που παρέχεται
και στη συνέχεια ισοπεδώνει όλους τους νέους iterators που παράγονται, αλυσιδώνοντάς τους μεταξύ τους.
Η `collect` παράγει μια νέα συλλογή,
αρκεί ο τύπος της συλλογής να υλοποιεί το [`FromIterator`](https://doc.rust-lang.org/std/iter/trait.FromIterator.html).

```rust
let words = ["alpha", "beta", "gamma"];
// chars() returns an iterator
let merged: String = words.iter()
                          .flat_map(|s| s.chars())
                          .collect();
assert_eq!(merged, "alphabetagamma");
```

Το [`Iterator` trait](https://doc.rust-lang.org/std/iter/trait.Iterator.html) παρέχει _πολλούς_ τέτοιους χρήσιμους μετασχηματισμούς για iterators·
αξίζει να διαβάσεις την τεκμηρίωση και να εξοικειωθείς μαζί τους.

## Οκνηρία

Είναι σημαντικό να ξέρεις ότι οι iterators της Rust είναι οκνηροί:
δεν παράγουν καμία τιμή μέχρι να καταναλώσουμε τον iterator.
Αν γράψεις και τρέξεις τον παρακάτω κώδικα:

```rust
(0..5).map(|x| x * x);
```

Θα πάρεις το εξής σφάλμα του μεταγλωττιστή:

```rust
 --> src/main.rs:2:5
  |
2 |     (0..5).map(|x| x * x);
  |     ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

Αυτό συμβαίνει επειδή η `map` είναι μια μέθοδος προσαρμογέα που επιστρέφει έναν άλλο iterator.

Για να καταναλώσεις έναν iterator, χρησιμοποίησε είτε έναν `for` βρόχο είτε μια μέθοδο iterator που παράγει κάποια τιμή που δεν είναι η ίδια iterator.

Για παράδειγμα, η `collect` είναι μια μέθοδος καταναλωτή (η υπογραφή της συνάρτησής της δεν επιστρέφει iterator αλλά έναν γενικό τύπο):

```rust
//         Iterator   Adaptor        Consumer
//                |      |               |
let v: Vec<_> = (0..5).map(|x| x * x).collect();
```
