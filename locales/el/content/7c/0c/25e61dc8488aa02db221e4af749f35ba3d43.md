# Εισαγωγή

## Προσθήκη συμφραζομένων στα σφάλματα

Εξερευνήσαμε τον βασικό χειρισμό σφαλμάτων στη Go στην [έννοια errors][concept-errors].
Όπως έμαθες εκεί, από προεπιλογή τα σφάλματα δεν μεταφέρουν μαζί τους ίχνη στοίβας.
Αυτό κάνει κρίσιμο να διασφαλίσεις ότι το ίδιο το σφάλμα περιέχει αρκετές πληροφορίες ώστε να εντοπιστεί το πρόβλημα.

Αν θέλαμε να προσθέσουμε πληροφορίες σε ένα υπάρχον σφάλμα με τα εργαλεία που ήδη γνωρίζουμε, θα μπορούσαμε να γράψουμε κάτι σαν αυτό για να δημιουργήσουμε ένα νέο σφάλμα με το συνδυασμένο κείμενο του αρχικού σφάλματος και των πρόσθετων πληροφοριών:

```go
err := errors.New(fmt.Sprintf("parsing age for user %d: %v", userID, originalError))
```

Ευτυχώς, το πακέτο `fmt` από την τυπική βιβλιοθήκη περιέχει μια συντομευμένη εκδοχή αυτού με τη μορφή της συνάρτησης `Errorf`.
Αυτό σου επιτρέπει, για παράδειγμα, να προσθέσεις εύκολα πληροφορίες σχετικά με τα συμφραζόμενα στα οποία προέκυψε το σφάλμα.

```go
originalError := errors.New("unexpected negative number")
userID := 123
err := fmt.Errorf("parsing age for user %d: %v", userID, originalError)
err.Error()
// => "parsing age for user 123: unexpected negative number"
```

Συχνά αυτός ο τρόπος προσθήκης πληροφοριών σε ένα σφάλμα είναι αρκετά καλός, αλλά υπάρχουν περιπτώσεις όπου θέλεις να επιτρέψεις στον καταναλωτή του σφάλματός σου να ελέγξει ή να ανακτήσει το αρχικό υποκείμενο σφάλμα.
Η προσθήκη συμφραζομένων με τρόπο που το επιτρέπει αυτό ονομάζεται "περιτύλιξη σφάλματος" στη Go.

## Περιτύλιξη σφαλμάτων και έλεγχος για σφάλματα-φρουρούς

Η περιτύλιξη σφαλμάτων μπορεί να επιτευχθεί με μια πολύ μικρή αλλαγή στον κώδικα που είδαμε παραπάνω.
Για να περιτυλίξεις ένα σφάλμα, πρέπει να χρησιμοποιήσεις το ρήμα μορφοποίησης `%w` αντί για `%v`.
Στο παρασκήνιο, αυτό θα διασφαλίσει ότι το σφάλμα που προκύπτει υλοποιεί μια μέθοδο `Unwrap` που επιστρέφει το αρχικό σφάλμα.
Εξαιτίας αυτού, το `errors.Is` μπορεί να χρησιμοποιηθεί για να ελέγξεις αν ένα συγκεκριμένο σφάλμα-φρουρός εμφανίζεται κάπου κατά μήκος της "αλυσίδας σφαλμάτων".
Αυτό το κάνει καλώντας κρυφά το `Unwrap` επανειλημμένα, μέχρι να βρεθεί το εν λόγω σφάλμα ή να τελειώσει η αλυσίδα.

```go
originalError := errors.New("unexpected negative number")
err := fmt.Errorf("parsing age: %w", originalError)
errors.Is(err, originalError)
// => true
```

Είναι καλή πρακτική να χρησιμοποιείς `%v` από προεπιλογή και να χρησιμοποιείς `%w` μόνο αν θέλεις ρητά να επιτρέψεις στον καταναλωτή σου να έχει πρόσβαση σε ένα υποκείμενο σφάλμα ([Google Go Styleguide][google-go-styleguide]).

Αν βρεθείς σε μια κατάσταση όπου θέλεις να ελέγξεις για ένα σφάλμα-φρουρό αλλά ρητά δεν θέλεις να το ξετυλίξεις, μπορείς να χρησιμοποιήσεις `==` αντί για `errors.Is`.

```go
var originalError = errors.New("unexpected negative number")
func someFunc() error {
  return originalError
}

err := someFunc()
err == originalError 
// => true
```

Δεν πειράζει να δουλεύεις με το `errors.Is` από προεπιλογή, αλλά θα πρέπει πάντα να έχεις υπόψη σου ότι αυτό σημαίνει πως θα ερευνηθεί ολόκληρη η αλυσίδα σφαλμάτων.

## Έλεγχος για (προσαρμοσμένους) τύπους σφαλμάτων

Υπάρχει ένα ισοδύναμο του `errors.Is` που σου επιτρέπει να ελέγξεις και να ανακτήσεις ένα σφάλμα συγκεκριμένου τύπου από την αλυσίδα σφαλμάτων.
Η συνάρτηση γι' αυτό είναι η `errors.As` και, όπως ακριβώς το `errors.Is`, θα ψάξει για τον δεδομένο τύπο σφάλματος σε ολόκληρη την αλυσίδα.
Το `errors.As` εξάγει το σφάλμα που βρήκε και ταιριάζει με τον τύπο μόνο τότε, ώστε να μπορείς να δουλέψεις περαιτέρω μαζί του, π.χ. να ανακτήσεις συγκεκριμένα πεδία.

```go
type MyCustomError struct {
  Message string
  Details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.Message, e.Details)
}

func someFunc() error {
  originalError := &MyCustomError{
    Message: "some message",
    Details: "some details",
  }

  return fmt.Errorf("doing something: %w", originalError)
}

err := someFunc()
var customError *MyCustomError
errors.As(err, &customError)
// => true

// customError now contains the error that was found in the error chain.
customError.Details
// => "some details"
```

~~~~exercism/caution
Πρόσεχε τη σύνταξη σχετικά με τους δείκτες παραπάνω.
Ο κώδικας θα δουλέψει και θα μεταγλωττιστεί σωστά μόνο αν το `customError` έχει τον ακριβή τύπο που υλοποιεί τη διεπαφή error.
Στην περίπτωσή μας, αυτός είναι ο `*MyCustomError` (ένας [δείκτης][concept-pointers] προς το `MyCustomError`), όχι το ίδιο το `MyCustomError`.

Επιπλέον, το δεύτερο όρισμα πρέπει να είναι ένας δείκτης στη μεταβλητή του σφάλματος.
Επειδή το σφάλμα μας είναι ήδη δείκτης, αυτό που περνάμε στο `errors.As` είναι ένας δείκτης σε δείκτη (προς το MyCustomError).
Μόνο με αυτή τη σωστή ρύθμιση μπορεί η Go να γεμίσει τη μεταβλητή με το σφάλμα που βρήκε.
~~~~

Όπως και πριν, το `errors.As` δεν θα είχε βρει τον τύπο σφάλματος αν είχε χρησιμοποιηθεί το `%v` κατά την κλήση της `Errorf`.

Αν για κάποιον λόγο δεν θέλεις να ξετυλίξεις, μπορείς να χρησιμοποιήσεις αντ' αυτού το type assertion (ισοδύναμο με το `==` παραπάνω).

```go
// MyCustomError defined as above.

func someFunc() error {
  return &MyCustomError{
    Message: "some message",
    Details: "some details",
  }
}

err := someFunc()
customError, ok := err.(*CustomError)
// "ok" is now true
customError.Details
// => "some details"
```

Το type assertion δεν θα μπορέσει να αναγνωρίσει τον τύπο σφάλματος αν το σφάλμα έχει περιτυλιχθεί.

## Επιτρέποντας το ξετύλιγμα σφαλμάτων προσαρμοσμένων τύπων

Μερικές φορές, το να περιτυλίξεις απλώς ένα σφάλμα με κάποιο πρόσθετο κείμενο δεν αρκεί.
Μπορείς αντ' αυτού να δημιουργήσεις έναν προσαρμοσμένο τύπο σφάλματος που περιέχει το αρχικό σφάλμα και τα πρόσθετα δομημένα δεδομένα που θέλεις να προσθέσεις.
Αν θέλεις να επιτρέψεις το ξετύλιγμα για τον τύπο σφάλματος σου, το μόνο που έχεις να κάνεις είναι να προσθέσεις χειροκίνητα μια μέθοδο `Unwrap() error`, ώστε να ικανοποιείται η διεπαφή `Unwrap`.

```go
type SpecialError struct {
  originalError error
  metadata string
}

func (e *SpecialError) Error() string {
  // The usual serialization code goes here.
}

func (e *SpecialError) Unwrap() error {
  return e.originalError
}
```
