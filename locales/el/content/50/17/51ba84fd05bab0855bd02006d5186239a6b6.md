# Σχετικά

Αν και η Swift έχει πολλούς διαφορετικούς τύπους, καθένας από αυτούς τους τύπους ανήκει σε μία από δύο διαφορετικές κατηγορίες, τους _τύπους τιμών_ και τους _τύπους αναφοράς_. Στη Swift, [τα struct είναι τύποι τιμών][structs-are-value-types], ενώ [οι κλάσεις είναι τύποι αναφοράς][classes-are-reference-types].

Η κύρια διαφορά ανάμεσα στους τύπους τιμών και τους τύπους αναφοράς είναι ότι, όταν οι τύποι τιμών ανατίθενται σε μια μεταβλητή ή σταθερά, ή όταν περνούν σε μια συνάρτηση, αυτό που ανατίθεται ή περνά είναι στην πραγματικότητα ένα αντίγραφο της τιμής, όχι η ίδια η τιμή. Η τροποποίηση ενός αντιγράφου ενός struct δεν επηρεάζει τα άλλα αντίγραφα. Στους τύπους αναφοράς, αυτό που ανατίθεται ή περνά είναι μια αναφορά σε αυτή την τιμή, οπότε δύο διαφορετικά ονόματα μπορούν να δείχνουν στο ίδιο στιγμιότυπο μιας κλάσης. Αυτό μπορεί να οδηγήσει σε τροποποίηση του αρχικού στιγμιότυπου όταν το προσπελάσεις με διαφορετικό όνομα.

Έτσι, αν πάρουμε το struct και την κλάση που ορίζουν έναν χαρακτήρα σε ένα παιχνίδι, καθώς και τα στατιστικά τους στο παιχνίδι, μπορούμε να δούμε τι συμβαίνει όταν αυτά τα στοιχεία αντιγράφονται και αλλάζουν.

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

Πρόσεξε πώς η αλλαγή των ιδιοτήτων του `charB` επηρέασε τις ιδιότητες του `charA`, αφού και τα δύο ονόματα δείχνουν στο ίδιο στιγμιότυπο. Πρόσεξε επίσης ότι, με τα στατιστικά των δύο χαρακτήρων, οι τύποι τιμών μέσα σε έναν τύπο αναφοράς αλλάζουν μέσα στους τύπους αναφοράς. Αυτό όμως δεν παραβιάζει τη συμπεριφορά των τύπων τιμών, γιατί το `charA.stats` είναι το ίδιο στιγμιότυπο του `CharacterStats` με το `charB.stats`, εφόσον τα `charA` και `charB` δείχνουν στο ίδιο στιγμιότυπο της κλάσης `GameCharacter`. Όπως βλέπουμε, για παράδειγμα, τα αντίγραφα αυτών των τύπων τιμών δεν επηρεάζουν το ένα το άλλο.

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

Γι' αυτό τα struct απαιτούν τη λέξη-κλειδί `mutating` μπροστά από μεθόδους που αλλάζουν την κατάσταση των ιδιοτήτων του struct. Η αλλαγή μιας ιδιότητας ενός struct δημιουργεί στην πραγματικότητα ένα νέο αντίγραφο του struct με τη νέα τιμή στην ιδιότητα αυτή, και το νέο αντίγραφο αντικαθιστά το παλιό. Είναι μια οπτική ένδειξη ότι αυτή η αντιγραφή και αντικατάσταση μπορεί να συμβεί για τιμές αυτού του τύπου.

Αυτό έχει ως παρενέργεια ότι οποιαδήποτε στιγμιότυπα struct στα οποία αλλάζουν μεταβλητές ιδιότητες, είτε μέσω κλήσης συναρτήσεων mutating είτε με απευθείας ανάθεση, _πρέπει_ να ανατίθενται σε μεταβλητές, όχι σε σταθερές. Διαφορετικά, θα παραχθεί σφάλμα μεταγλωττιστή:

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

Οι αρχικές τιμές μπορούν ακόμα να δημιουργηθούν και να προσπελαστούν, αλλά δεν επιτρέπεται να αλλάξουν. Αυτός ο περιορισμός δεν ισχύει για τις κλάσεις. Αν ένα στιγμιότυπο μιας κλάσης ανατεθεί σε ένα όνομα με `let`, αυτό που κρατά η σταθερά είναι η αναφορά στο στιγμιότυπο και επομένως αυτή δεν μπορεί να αλλάξει, όχι το ίδιο το στιγμιότυπο. Έτσι, το ίδιο το στιγμιότυπο μπορεί να αλλάξει, αλλά η αναφορά δεν μπορεί να αλλάξει ώστε να δείχνει σε άλλο στιγμιότυπο.

Μια σύνοψη του τι μπορεί να αλλάξει σε struct και κλάσεις που ορίζονται με `let` ή `var` είναι η εξής

|         | **struct**                                                                                  | **κλάση**                                                                                  |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | _Δεν μπορείς_ να αναθέσεις ένα νέο struct στο όνομα.</br>_Δεν μπορείς_ να τροποποιήσεις καμία ιδιότητα του struct. | _Δεν μπορείς_ να αναθέσεις μια νέα κλάση στο όνομα.</br>_Μπορείς_ να τροποποιήσεις τις μεταβλητές ιδιότητες της κλάσης. |
| **var** | _Μπορείς_ να αναθέσεις ένα νέο struct στο όνομα.</br>_Μπορείς_ να τροποποιήσεις τις μεταβλητές ιδιότητες του struct.   | _Μπορείς_ να αναθέσεις μια νέα κλάση στο όνομα.</br>_Μπορείς_ να τροποποιήσεις τις μεταβλητές ιδιότητες της κλάσης.    |

## Ταυτότητα

Επειδή δύο διαφορετικά ονόματα μπορούν να κρατούν αναφορά στο ίδιο στιγμιότυπο μιας κλάσης, μερικές φορές είναι χρήσιμο να ελέγξεις αν συμβαίνει αυτό. Η Swift χρησιμοποιεί τον _τελεστή ταυτότητας_ `===` για αυτόν τον έλεγχο (μαζί με την άρνησή του, `!==`).

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

Επειδή κανένα ζεύγος ονομάτων δεν μπορεί να δείχνει στο ίδιο στιγμιότυπο ενός struct, αυτοί οι τελεστές ταυτότητας δεν ορίζονται για struct.

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

Σημείωσε ότι η ταυτότητα δεν είναι το ίδιο πράγμα με την ισότητα. Με πολλούς ορισμούς, τα `char1` και `char3` θα θεωρούνταν ίσα, αφού όλες οι ιδιότητές τους έχουν τις ίδιες τιμές, αλλά δεν μοιράζονται την ίδια ταυτότητα. Η ταυτότητα παρέχεται αυτόματα για όλες τις κλάσεις στη Swift, αλλά συνήθως οι προγραμματιστές χρειάζεται να γράψουν τους δικούς τους τελεστές ισότητας για να προσδιορίσουν αν δύο στιγμιότυπα ενός struct ή μιας κλάσης είναι _ίσα_. Αυτό ξεπερνά το πλαίσιο αυτής της άσκησης.
