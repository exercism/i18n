# Υποδείξεις
Το `Option` χρησιμοποιείται για να δηλώσει έναν υπολογισμό που μπορεί να μην έχει κάποιο χρήσιμο αποτέλεσμα
(για παράδειγμα, λόγω κάποιου σφάλματος ή μη έγκυρης εισόδου).
Αν δεν είσαι εξοικειωμένος με το `Option`, μπορείς να διαβάσεις [αυτό το σεμινάριο](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html).
Το `Option` είναι ένα λεγόμενο [Monad](https://en.wikipedia.org/wiki/Monad_(functional_programming)) που καλύπτει μια "υπολογιστική πτυχή", στην περίπτωση αυτή την πιθανή απουσία μιας τιμής.
Η σωστή χρήση των Monads μπορεί να οδηγήσει σε πολύ συνοπτικό αλλά κομψό
και ευανάγνωστο κώδικα. Η ακατάλληλη χρήση μπορεί εύκολα να έχει το αντίθετο αποτέλεσμα.
Δες [αυτό το βίντεο](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) για να μάθεις περισσότερα.
## Συνήθεις παγίδες που πρέπει να αποφύγεις
Υπάρχουν μερικοί εμπειρικοί κανόνες για το `Option`:
1. Αν δεν το χρειάζεσαι, μη το χρησιμοποιείς. Αντί για
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
καλύτερα να έχεις
```scala
def add1(x: Int): Int = x + 1
```
(υπάρχει το `Option.map` για να εφαρμόζεις τέτοιες απλές συναρτήσεις,
οπότε δε χρειάζεται να τις γεμίζεις με `Option`).
2. Μην κάνεις "unwrap" αν δεν το χρειάζεσαι πραγματικά.
Συχνά υπάρχουν έτοιμες συναρτήσεις για τον σκοπό σου. Ενδείξεις πρόωρου
unwrapping είναι τα `isDefined/isEmpty` ή το pattern matching. Αντί για
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
καλύτερα να έχεις
```scala
x map (_ + 1) getOrElse 0
```
3. Τα Monads μπορούν να χρησιμοποιηθούν μέσα σε ένα for-comprehension FTW.
Αυτό συνιστάται όταν θέλεις να "συνθέσεις" πολλαπλά στιγμιότυπα του `Option`. Αντί για
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
καλύτερα να έχεις
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
