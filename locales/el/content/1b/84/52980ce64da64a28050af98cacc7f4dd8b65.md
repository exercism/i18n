# Σχετικά

Η [στοίβα κλήσεων][stack], ή απλώς **στοίβα**, είναι μια ειδική δομή δεδομένων που ξεκινά από το υψηλότερο σημείο της μνήμης και μεγαλώνει προς τα κάτω.

## Push και Pop

Η στοίβα υποστηρίζει τουλάχιστον δύο πράξεις, με εντολές που έχουν το ίδιο όνομα:

| Εντολή | Πράξη που εκτελείται                              |
| ----------- | --------------------------------------------------- |
| `push`      | προσθέτει ένα στοιχείο στη στοίβα                   |
| `pop`       | αφαιρεί και επιστρέφει το πιο πρόσφατα προστιθέμενο στοιχείο |

Αυτό σημαίνει ότι η στοίβα είναι μια δομή δεδομένων **τελευταίο μέσα, πρώτο έξω (LIFO)**.

Για να παρακολουθείται το τρέχον σημείο της στοίβας, εκεί όπου βρίσκεται το πιο πρόσφατο στοιχείο, χρησιμοποιείται ο καταχωρητής `rsp`.

Έτσι, μια εντολή [push][push] παίρνει έναν τελεστέο και αποθηκεύει τα περιεχόμενά του στη στοίβα.
Επειδή η στοίβα μεγαλώνει προς τα κάτω, η τιμή του `rsp` μειώνεται κατά το μέγεθος της τιμής που αποθηκεύτηκε.

Παρόμοια, μια εντολή [pop][pop] παίρνει έναν τελεστέο και αποθηκεύει σε αυτόν την πιο πρόσφατη τιμή της στοίβας (αυτήν στην οποία δείχνει το `rsp`).
Στη συνέχεια, η τιμή του `rsp` αυξάνεται κατά το μέγεθος της τιμής που ανακτήθηκε.

## Τοπικές μεταβλητές

Είναι επίσης δυνατό να χειριστείς απευθείας την τιμή του `rsp`.
Αυτό χρησιμοποιείται συχνά για τη δημιουργία τοπικών μεταβλητών μιας συνάρτησης.

```x86asm
sub rsp, 24 ; this reserves 24 bytes of space in the stack
add rsp, 24 ; this restores the previous value of rsp, "reducing" the stack by 24 bytes
```

Σημείωσε ότι, τη στιγμή που δεσμεύεται χώρος στη στοίβα, η τιμή που είναι αποθηκευμένη σε αυτόν τον χώρο είναι _απροσδιόριστη_.

~~~~exercism/note
Ούτε το `pop` ούτε ο άμεσος χειρισμός του `rsp` αφαιρούν στην πραγματικότητα τα περιεχόμενα που είναι αποθηκευμένα στη μνήμη.
Η "αφαίρεση" από τη στοίβα είναι αφηρημένη σε σχέση με τη νέα διεύθυνση στο `rsp`.

Σε ορισμένα πλαίσια, αυτό μπορεί να δημιουργήσει προβλήματα ασφάλειας, εκθέτοντας εσωτερικές τιμές σε εξωτερικές πηγές.
Ένας τρόπος να το αντιμετωπίσεις είναι ο μηδενισμός των περιεχομένων κάθε χώρου της στοίβας που χρησιμοποιεί η συνάρτηση.
~~~~

## Call και Ret

Ο κύριος σκοπός της στοίβας είναι να παρακολουθεί τη διεύθυνση επιστροφής των καλούμενων συναρτήσεων.

Όπως αναφέρθηκε σε προηγούμενη έννοια, υπάρχει ένας ειδικός καταχωρητής, ο `rip`, που δείχνει στην επόμενη εντολή προς εκτέλεση.
Ο καταχωρητής αυτός χρησιμοποιείται για τον έλεγχο της ροής ενός προγράμματος και τροποποιείται από εντολές όπως οι `jmp` και `call`.

Κάθε φορά που χρησιμοποιείται μια εντολή `call`, η τρέχουσα τιμή του `rip` ωθείται σιωπηρά στη στοίβα.
Στη συνέχεια, ο τελεστέος της εντολής μεταφέρεται στο `rip`, ώστε η εκτέλεση να συνεχιστεί στην καλούμενη συνάρτηση.

Μια εντολή `ret` κάνει την αντίθετη πράξη.
Κάνει pop από τη στοίβα στο `rip`, ώστε η εκτέλεση να επιστρέψει στην καλούσα συνάρτηση.

Κατά την είσοδο στη συνάρτηση, το `rsp` δείχνει στη διεύθυνση στην οποία πρέπει να επιστρέψει η εκτέλεση.
Αυτή είναι η διεύθυνση που πρέπει να κάνει pop η `ret` από τη στοίβα.

Έτσι, κάθε αλλαγή στην τιμή του `rsp` μέσα σε μια συνάρτηση, είτε άμεση είτε με `push`, πρέπει να αντιστραφεί πριν επιστρέψει η συνάρτηση.

## Καταχωρητές που διατηρεί ο καλούμενος και ο καλών

Εκτός από το `rsp`, υπάρχουν και άλλοι καταχωρητές που πρέπει να διατηρούνται κατά τις κλήσεις συναρτήσεων: οι `rbp`, `rbx`, `r12`, `r13`, `r14` και `r15`.
Σε γενικές γραμμές, η καλούσα συνάρτηση περιμένει να μπορεί να χρησιμοποιήσει αυτούς τους καταχωρητές χωρίς να τους αλλάξει κάποια καλούμενη συνάρτηση.

Αυτό σημαίνει ότι η _καλούμενη_ συνάρτηση πρέπει να αποθηκεύσει τις τιμές αυτών των καταχωρητών πριν τους χρησιμοποιήσει και να τις επαναφέρει στις αρχικές τους τιμές πριν επιστρέψει.
Γι' αυτό ονομάζονται **καταχωρητές που διατηρεί ο καλούμενος**.

Οι υπόλοιποι καταχωρητές γενικού σκοπού είναι άμεσα διαθέσιμοι για χρήση από την καλούμενη συνάρτηση.

Αυτό σημαίνει ότι η _καλούσα_ συνάρτηση πρέπει να αποθηκεύσει τις τιμές αυτών των καταχωρητών πριν καλέσει οποιαδήποτε συνάρτηση, σε περίπτωση που τις τροποποιήσει η καλούμενη συνάρτηση.
Γι' αυτό ονομάζονται **καταχωρητές που διατηρεί ο καλών**.

_Ο πιο συνηθισμένος τρόπος για να αποθηκεύσεις τα περιεχόμενα ενός καταχωρητή είναι να τα βάλεις στη στοίβα._

## Πρόλογος και επίλογος

Σε ορισμένες περιπτώσεις, η στοίβα μπορεί να χρησιμοποιείται εντατικά, με πολλές τροποποιήσεις πριν επιστρέψει η συνάρτηση.
Έτσι, το να παρακολουθείς όλες αυτές τις αλλαγές για να τις αντιστρέψεις μπορεί να είναι περίπλοκο.

Σε αυτές τις περιπτώσεις, μια συνηθισμένη στρατηγική είναι να αποθηκεύσεις τη διεύθυνση του `rsp` σε έναν άλλο καταχωρητή που κατά τα άλλα μένει αμετάβλητος μέσα στη συνάρτηση.
Και μετά, η τιμή του `rsp` μπορεί να επαναφερθεί με μια απλή εντολή `mov` στο τέλος, πριν επιστρέψει η συνάρτηση.

Αν και οποιοσδήποτε καταχωρητής μπορεί να χρησιμοποιηθεί για αυτόν τον σκοπό, συνηθίζεται να χρησιμοποιείται ο `rbp` ως δείκτης βάσης.
Επειδή ο `rbp` είναι και ο ίδιος καταχωρητής που διατηρεί ο καλούμενος, αυτό συχνά προηγείται από ένα `push rbp`.
Αυτή η ακολουθία συνήθως ονομάζεται **πρόλογος**.

Στο τέλος, η επαναφορά του `rsp` γίνεται με ένα `mov rsp, rbp` και μετά ο `rbp` επαναφέρεται επίσης με ένα `pop` από τη στοίβα.
Αυτή η ακολουθία συνήθως ονομάζεται **επίλογος**.

```x86asm
section .text
fn:
    ; prologue
    push rbp
    mov rbp, rsp
    ...
    ; epilogue
    mov rsp, rbp
    pop rbp
    ret
```

~~~~exercism/note
Ο κύριος σκοπός των ακολουθιών προλόγου/επιλόγου είναι να βοηθήσουν τον προγραμματιστή να παρακολουθεί τις αλλαγές στο `rsp`.
Αυτό, φυσικά, είναι πολύ πιο εύκολο για έναν μεταγλωττιστή.

Γι' αυτό πολλοί μεταγλωττιστές εφαρμόζουν μια βελτιστοποίηση που παραλείπει τον δείκτη πλαισίου και αφαιρεί προλόγους/επιλόγους όποτε είναι δυνατόν.
~~~~

## Πέρασμα ορισμάτων με τη στοίβα

Στη σύμβαση κλήσης [System V ABI][SystemV], τα ορίσματα συνήθως περνιούνται στις συναρτήσεις μέσω καταχωρητών.
Ωστόσο, όταν τα ορίσματα είναι πάρα πολλά ή χρειάζονται περισσότερο χώρο από το μέγεθος ενός καταχωρητή, μπορεί να χρησιμοποιηθεί η στοίβα.

Σε αυτές τις περιπτώσεις, οι τιμές προστίθενται στη στοίβα με αντίστροφη σειρά, ώστε το πρώτο όρισμα να είναι πιο κοντά στο `rsp`.
Επειδή κατά την είσοδο το `rsp` δείχνει στη διεύθυνση επιστροφής, η οποία είναι μια τιμή 8 byte σε x86-64, το πρώτο όρισμα στη στοίβα, αν υπάρχει, μπορεί να προσπελαστεί στο `rsp + 8`:

```x86asm
mov rdi, 4   ; first argument
mov rsi, 8   ; second argument
mov rdx, 15  ; third argument
mov rcx, 16  ; fourth argument
mov r8, 23   ; fifth argument
mov r9, 42   ; sixth argument

; any remaining integer argument goes on the stack in reversed order
sub rsp, 16
mov qword [rsp], 100      ; seventh argument
mov qword [rsp + 8], 300  ; eighth argument

call many_arguments_fn ; call implicitly pushes `rip` to the stack
; so, at point of entry, 'many_arguments_fn' finds the first six integer arguments in the usual registers
; the seventh argument is found in rsp + 8
; and the eighth argument is found in rsp + 16
```

## Ευθυγράμμιση της στοίβας

Το System V ABI ορίζει ότι η στοίβα πρέπει να είναι ευθυγραμμισμένη στα 16 byte αμέσως _πριν_ εκτελεστεί η εντολή `call`.
Επειδή η `call` ωθεί το `rip` στη στοίβα, κατά την είσοδο η στοίβα της καλούμενης συνάρτησης **δεν** είναι ευθυγραμμισμένη στα 16 byte.

Αυτό σημαίνει ότι μια συνάρτηση που καλεί μια άλλη (και, ειδικότερα, εξωτερικές συναρτήσεις) πρέπει να ευθυγραμμίσει τη στοίβα πριν χρησιμοποιήσει την `call`.

Αυτό μπορεί να γίνει αφαιρώντας μια κατάλληλη τιμή από το `rsp`.
Κατά την είσοδο, αυτή η τιμή πρέπει να είναι 8 παραπάνω από ένα πολλαπλάσιο του 16: 8, 24, 40 κ.λπ.
Επειδή μια εντολή `push` αφαιρεί από το `rsp`, ένας περιττός αριθμός `push` μπορεί να χρησιμοποιηθεί για το ίδιο αποτέλεσμα:

```x86asm
fn_a:
    sub rsp, 24 ; subtracting 8 more than a multiple of 16: this aligns the stack
    call fn_b
    add rsp, 24
    ret

fn_b:
    push rbx    ; odd number of pushes: this aligns the stack
    call fn_c
    pop rbx
    ret
```

## Κόκκινη ζώνη

Το System V ABI δεσμεύει έναν χώρο 128 byte ακριβώς κάτω από το `rsp`, ο οποίος μπορεί να χρησιμοποιηθεί χωρίς καμία προσαρμογή του `rsp`.
Αυτός ο χώρος είναι γνωστός ως [κόκκινη ζώνη][red-zone]:

```x86asm
fn:
    mov [rsp - 8], rax ; this is safe to use because it is in the red zone
    ret                ; no need to restore rsp
```

Η κόκκινη ζώνη είναι ασφαλές να χρησιμοποιείται μόνο από μια συνάρτηση-φύλλο, δηλαδή μια συνάρτηση που δεν καλεί κάποια άλλη.
