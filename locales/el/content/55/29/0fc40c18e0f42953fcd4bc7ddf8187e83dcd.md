# Σχετικά

## Αναπαράσταση, χαρακτήρες και ακέραιοι

Όπως και οι άλλοι απλοί τύποι (`int`, `bool` κ.λπ.), το `char` έχει έναν συνοδευτικό ή ψευδώνυμο τύπο, στην περίπτωση αυτή το `System.Char`.

Στην πραγματικότητα πρόκειται για ένα `struct` με πεδίο 16 bit, και είναι αμετάβλητο από προεπιλογή.

Το `char` έχει μερικές μεθόδους στιγμιότυπου, όπως τις `Equals`, `ToString` και [`CompareTo`][compare-to].

Το `char` έχει το ίδιο πλάτος με ένα [`ushort`][uint16], αλλά γενικά δεν χρησιμοποιούνται εναλλάξιμα όπως σε κάποιες γλώσσες. Το `ushort` πρέπει να μετατραπεί ρητά σε `char`.

Για την ιστορία, τα `char` μπορούν να υποβληθούν σε αριθμητικές πράξεις. Το αποτέλεσμα αυτών των πράξεων είναι ακέραιος.

Προφανώς δεν υπάρχει αντιστοιχία μεταξύ ενός `byte` των 8 bit και του `char` των 16 bit.

## Χρήση

Τα `char` είναι γενικά εύκολα στη χρήση.

Μπορούν να οριστούν ως literal με απλά εισαγωγικά:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

Ένα μεμονωμένο `char` μπορεί να ανακτηθεί από μια συμβολοσειρά με πρόσβαση στη θέση (μηδενική βάση):

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

Η επανάληψη πάνω σε μια συμβολοσειρά επιστρέφει ένα `char` σε κάθε βήμα:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

Όπως φαίνεται παραπάνω, ένα `char` μπορεί να μετατραπεί στην `int` τιμή του.
Αυτό λειτουργεί επίσης (*τουλάχιστον ενίοτε*) και για άλλα συστήματα γραφής:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

Το υποκείμενο Int16 χρησιμοποιείται κατά τη σύγκριση χαρακτήρων:

```fsharp
'A' < 'D'
// => val it: bool = true
```

Επίσης, ένα `int` μπορεί να μετατραπεί σε `char`:

```fsharp
char 77
// => val it: char = 'M'
```

Η βιβλιοθήκη `System.Char` περιέχει το πλήρες σύνολο [μεθόδων][Char-methods] που αναμένονται για μια γλώσσα .NET, όπως μετατροπές σε πεζά/κεφαλαία (αλλά δες τις επιφυλάξεις στην επόμενη ενότητα):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

Οι βιβλιοθήκες .NET βοηθούν στην εξαγωγή `char` από συμβολοσειρές, στην προκειμένη περίπτωση μεθόδους `Seq`:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

Υπάρχουν διάφοροι τρόποι να μετατρέψεις μια λίστα (ή πίνακα) χαρακτήρων σε συμβολοσειρά, μεταξύ των οποίων οι εξής:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

Γενικές πληροφορίες για τα `char` μπορείς να βρεις εδώ:

- [Τεκμηρίωση Chars][chars-docs]: τεκμηρίωση αναφοράς για το `char`.

Ωστόσο, τα `char` έχουν αρκετές ιδιορρυθμίες, όπως περιγράφεται παρακάτω. Αυτές οι ιδιορρυθμίες σχετίζονται κυρίως με την αντίθεση ανάμεσα στο πλήρες πρότυπο unicode από τη μια πλευρά και στις ιστορικές αναπαραστάσεις κειμένου καθώς και στην απόδοση και τη χρήση μνήμης από την άλλη.

## Ζητήματα Unicode

Όταν δουλεύεις με συμβολοσειρές, αν υπάρχουν διαθέσιμες μέθοδοι της βιβλιοθήκης [`System.String`][System-string], καλό είναι να τις αναζητάς και να τις χρησιμοποιείς αντί να σπας τη συμβολοσειρά σε χαρακτήρες.

Κάποιοι "χαρακτήρες" κειμένου αποτελούνται από περισσότερα από ένα `char`, επειδή το πρότυπο unicode έχει περισσότερα από 65536 σημεία κώδικα. Για παράδειγμα, τα emoji που εμφανίζονται σε μερικά από τα tests έχουν 2 `char`, καθώς περιλαμβάνουν [surrogate][surrogates] χαρακτήρες.

Επιπλέον, υπάρχουν ακολουθίες συνδυασμού, όπου σε ορισμένες περιπτώσεις ένας χαρακτήρας με τόνο μπορεί να αποτελείται από ένα `char` για τον απλό χαρακτήρα και ένα άλλο `char` για τον τόνο.

Αν χρειαστεί να δουλέψεις με μεμονωμένους χαρακτήρες, καλό είναι να χρησιμοποιείς μεθόδους βιβλιοθήκης όπως τις [`System.Char.IsControl`][is-control], [`System.Char.IsDigit`][is-digit] αντί να κάνεις αφελείς συγκρίσεις, όπως να ελέγχεις αν ένας χαρακτήρας βρίσκεται μεταξύ '0' και '9'.

Για παράδειγμα, πρόσεξε ότι το '٢' είναι το αραβικό ψηφίο 2. Το `IsDigit` θα επιστρέψει αληθής για την αραβική εκδοχή, οπότε πρέπει να έχεις ξεκαθαρίσει, ας πούμε, κατά την επικύρωση, ποιο εύρος εισόδων είναι αποδεκτό.

Ακόμη και οι μέθοδοι της βιβλιοθήκης `System.Char` μπορεί να μη συμπεριφέρονται όπως θα περίμενες όταν έχεις να κάνεις με πιο ασαφείς γλώσσες.

Ένας ασφαλής τρόπος να σπάσεις μια συμβολοσειρά σε "χαρακτήρες" εμφάνισης είναι να χρησιμοποιήσεις το [`StringInfo`][string-info] και μεθόδους όπως τη [`GetNexttextElement`][get-next-text-element].
Αυτό μπορεί να είναι απαραίτητο αν ασχολείσαι με παγκοσμιοποίηση/τοπικοποίηση.

Ένας άλλος δρόμος, όταν οι βαθμωτές τιμές των χαρακτήρων unicode είναι σημαντικές (ας πούμε, φτιάχνεις το δικό σου σύστημα κωδικοποίησης), είναι να χρησιμοποιήσεις [runes][runes]. Ωστόσο, αν ξέρεις ότι το εύρος των χαρακτήρων με τους οποίους ασχολείσαι δεν περιλαμβάνει surrogate ή ακολουθίες συνδυασμού χαρακτήρων (π.χ. λατινικό ASCII) και η είσοδός σου είναι καλά επικυρωμένη, τότε μπορείς να το αποφύγεις.

Και πάλι, η καλύτερη θέση στην οποία μπορείς να βρεθείς είναι να μπορείς να χρησιμοποιήσεις τις μεθόδους της βιβλιοθήκης του `String`.

Αν πάντως βρεθείς στη δυσάρεστη θέση να ασχολείσαι με τις λεπτομέρειες του unicode, τότε [αυτό][char-encoding-net] είναι ένα καλό σημείο εκκίνησης.
