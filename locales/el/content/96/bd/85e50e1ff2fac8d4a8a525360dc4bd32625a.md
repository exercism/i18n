# Εισαγωγή

Σε έναν ιδανικό κόσμο, θα μπορούσαμε να βασιζόμαστε στο ότι τα πάντα είναι καλά ορισμένα, με συγκεκριμένες τιμές και χωρίς κενά.

Αυτό έρχεται σε αντίθεση με την καθημερινή μας εμπειρία, γι' αυτό πολλές γλώσσες προγραμματισμού έχουν έναν τρόπο να αναπαραστήσουν την απουσία μιας τιμής: null ή NULL, nil, None, nothing...

Ήταν εύκολο να εισαχθεί (πίσω στο 1965), αλλά σύντομα οδήγησε σε μεταμέλειες.
Ο εφευρέτης του το ονόμασε αργότερα "Το σφάλμα του ενός δισεκατομμυρίου δολαρίων".

Τις τελευταίες δεκαετίες, οι σχεδιαστές γλωσσών έχουν εξερευνήσει πολλούς τρόπους για να κάνουν τα null διαθέσιμα αλλά (κατά κύριο λόγο) ασφαλή.

Η Kotlin έχει μερικές [γενικές αρχές][ref-null-safety], που διαφέρουν σημαντικά από τη Java.


- Η Kotlin έχει μια ειδική τιμή `null`.
- Όλοι οι τύποι είναι _από προεπιλογή_ μη nullable.
- Οι περισσότεροι τύποι μπορούν να _γίνουν_ nullable, αλλά ο προγραμματιστής πρέπει να το ζητήσει ρητά.
- Οι συναρτήσεις που μπορεί να αποτύχουν με μια εξαίρεση συνήθως έχουν μια παραλλαγή με nullable τιμή επιστροφής.
- Μια ειδική, ιδιαίτερα λακωνική σύνταξη προσπαθεί να κάνει τον έλεγχο και τον χειρισμό των null όσο το δυνατόν πιο εύκολο.

## Δημιουργία nullable μεταβλητών

Οι συνηθισμένοι τύποι έχουν γενικά ένα nullable ισοδύναμο, με επίθημα `?`: για παράδειγμα `String?` αντί για `String`.

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## Χρήσιμοι τελεστές και συναρτήσεις

### Ο τελεστής ασφαλούς κλήσης `?.`

Για μια μη nullable `String`, μπορούμε να πάρουμε την ιδιότητα `.length`.

Μια nullable `String?` αποτυγχάνει με την ίδια σύνταξη, αλλά χρησιμοποιώντας `?.length` επιτρέπεται η περίπτωση ενός `null`.
Ο τύπος επιστροφής είναι `Int?`.

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

Όπως είδαμε στην τελευταία γραμμή παραπάνω, το `?.` λειτουργεί και με μη nullable τύπους.

### Ο τελεστής Elvis `?:`

Επεκτείνοντας την ιδέα του τελεστή ασφαλούς κλήσης, ο [τελεστής Elvis][wiki-elvis] μάς επιτρέπει να δώσουμε μια προεπιλεγμένη τιμή στη θέση του `null`.

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### Ο τελεστής βεβαίωσης μη null `!!`

Με αυτόν τον τελεστή, ένας nullable τύπος εξαναγκάζεται να αντιμετωπιστεί ως μη null, όταν ο προγραμματιστής είναι σίγουρος γι' αυτό.
Ίσως μερικές φορές καταλαβαίνουμε τη λογική του προγράμματος καλύτερα από έναν υπερβολικά προσεκτικό μεταγλωττιστή;

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

Η ευθύνη είναι πλέον δική μας: αν το `b` είναι ακόμα `null`, παίρνουμε ένα `NullPointerException`.

### Η συνάρτηση `let` (`?.let`)

Αν θέλουμε να περάσουμε ένα nullable στοιχείο σε ένα μπλοκ κώδικα, θα μπορούσαμε να κάνουμε συγκεκριμένους ελέγχους null, όπως `if (item != null) { do something }`.

Είναι απλούστερο και πιο ιδιωματικό να χρησιμοποιήσουμε το `item?.let { do something }`.
Το `do something` θα εκτελεστεί μόνο όταν το `item` δεν είναι null.

### Συναρτήσεις του τύπου `somethingOrNone()`

Μερικές συναρτήσεις μπορεί να αποτύχουν, για παράδειγμα όταν ζητάμε μια άκυρη θέση σε μια συμβολοσειρά ή μια λίστα.

Αντί να πετάξουμε μια εξαίρεση, θα μπορούσαμε να χρησιμοποιήσουμε την παραλλαγή `...OrNull` της συνάρτησης, για να πάρουμε (σε αυτή την περίπτωση) μια τιμή επιστροφής `Int?`.

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
