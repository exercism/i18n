# Συνεισφορά έννοιας + άσκησης έννοιας

Μια [άσκηση έννοιας][product-concept] στοχεύει να διδάξει μία μόνο έννοια σε μια δεδομένη γλώσσα.
Πρέπει να έχει σαφή μαθησιακό στόχο και να παρέχει αρκετό έτοιμο κώδικα, ώστε ο μαθητής να μην χρειάζεται να μάθει περιττό κώδικα.
Η έννοια που τη συνοδεύει έχει τη δική της τεκμηρίωση, ανεξάρτητη από την άσκηση έννοιας.
Οι έννοιες μπορεί να έχουν άλλες έννοιες ως προαπαιτούμενα και να είναι κλειδωμένες μέχρι να ολοκληρωθούν οι ασκήσεις εννοιών των προαπαιτούμενων εννοιών.
Η δυσκολία των ασκήσεων εννοιών δεν θα πρέπει να αυξάνεται όσο προχωράει η διαδρομή.
Μια άσκηση έννοιας πρέπει να μπορεί να λυθεί σε 5 με 10 λεπτά από οποιονδήποτε προγραμματιστή γνωρίζει τις προαπαιτούμενες έννοιες.

Τώρα που ξέρουμε τι είναι μια άσκηση έννοιας, ας δούμε αναλυτικά πώς να υλοποιήσουμε μία, μαζί με την έννοια που τη συνοδεύει.
Για αναφορά, η αναλυτική [προδιαγραφή μιας άσκησης έννοιας][concept-exercise-spec] και μιας [έννοιας][concept-spec] είναι διαθέσιμες στο [αποθετήριο τεκμηρίωσης][docs-repo] του exercism.
Αυτό το κείμενο συγκεντρώνει πληροφορίες από πολλές πηγές, ώστε να λειτουργεί ως ένας βολικός οδηγός βήμα προς βήμα για το πώς να συνεισφέρεις μια άσκηση έννοιας.

## 1. Εντόπισε μια έννοια που λείπει και πρέπει να υλοποιηθεί

Οι έννοιες που έχουν ήδη υλοποιηθεί βρίσκονται στον κατάλογο [`concepts/`](/concepts) αυτού του αποθετηρίου.
Παρουσιάζονται επίσης ως γράφημα εξαρτήσεων στην [ιστοσελίδα του exercism][concepts-graph-exercism].
Μπορείς να τις συγκρίνεις με το γράφημα των εννοιών που σκοπεύουμε να υλοποιήσουμε, το οποίο φαίνεται παρακάτω (περίμενε λίγα δευτερόλεπτα και κάνε ανανέωση αν δεν εμφανίζεται).

Οι έννοιες που έχουν ήδη υλοποιηθεί θα πρέπει να εμφανίζονται με πράσινο φόντο και πιο έντονο περίγραμμα.
Πρόσεξε ότι το παραπάνω γράφημα είναι διαρκώς μεταβαλλόμενο και μπορεί να αλλάξει καθώς ανακαλύπτουμε ότι τα προαπαιτούμενα πρέπει να είναι διαφορετικά.

Οι έννοιες και οι ασκήσεις εννοιών που δεν έχουν υλοποιηθεί ακόμα θα πρέπει επίσης να αναφέρονται στα GitHub issues αυτού του αποθετηρίου, με την ετικέτα [`x:module/concept-exercise`](https://github.com/exercism/elm/issues?q=is%3Aissue+is%3Aopen+label%3Ax%3Amodule%2Fconcept-exercise).

## 2. Καθόρισε τους μαθησιακούς στόχους

Είναι σημαντικό να ξέρουμε τι στοχεύει να διδάξει μια άσκηση έννοιας και τι είναι εκτός πεδίου, οπότε ας δημιουργήσουμε το πρώτο μας αρχείο: `exercises/concept/<story-name>/.meta/design.md`.
Επειδή οι ασκήσεις εννοιών ονομάζονται από την ιστορία που χρησιμοποιούν, δεν την ξέρουμε ακόμα, οπότε θα κρατήσουμε το `story-name` για την ώρα και θα το αντικαταστήσουμε αργότερα.
Η [προδιαγραφή του `design.md`][design-spec] ορίζει ότι αυτό το έγγραφο πρέπει να καθορίζει τον γενικό στόχο της άσκησης, τους επιμέρους μαθησιακούς στόχους της, τα πράγματα που είναι εκτός πεδίου, την έννοια που ξεκλειδώνει και τα προαπαιτούμενα εννοιών που χρειάζονται για να ολοκληρωθεί η άσκηση.
Μπορείς να χρησιμοποιήσεις το [`design.md` της άσκησης έννοιας boolean][design-bool] ως σημείο εκκίνησης, σαν πρότυπο.

## 3. Γράψε μια εισαγωγή στην έννοια για την άσκηση

Μόλις ξεκαθαρίσουν οι μαθησιακοί στόχοι, ήρθε η ώρα να γράψεις μια εισαγωγή που εξηγεί αρκετά από την έννοια, ώστε ο μαθητής να μπορέσει μετά να λύσει την άσκηση.
Δημιούργησε ένα αρχείο `exercises/concept/<story-name>/.docs/introduction.md`.
Τα αναλυτικά περιεχόμενα αυτού του αρχείου εξηγούνται στην [προδιαγραφή του][exercise-intro-spec].
Μπορείς να χρησιμοποιήσεις το [`introduction.md` της άσκησης έννοιας boolean][intro-bool] ως σημείο εκκίνησης, σαν πρότυπο.

Οι πληροφορίες που παρέχονται θα πρέπει να εισάγουν την έννοια τόσο όσο χρειάζεται, ώστε ο μαθητής να βρει μόνος του τη λύση της άσκησης.
Χρησιμοποίησε σωστούς τεχνικούς όρους, ώστε ο μαθητής να μπορεί να ψάξει online πιο εύκολα.
Προσπάθησε να αποφεύγεις τους συνδέσμους και αντί γι' αυτούς να εξηγείς τα πράγματα συνοπτικά μέσα στο κείμενο.
Παρουσίασε τη σύνταξη του κώδικα με μπλοκ κώδικα.

## 4. Βρες μια ιστορία για την άσκηση

Κάθε άσκηση έννοιας πρέπει να βασίζεται σε μια ιστορία ή ένα θέμα.
Προσπαθούμε να τις κάνουμε όσο το δυνατόν πιο συμπεριληπτικές, γνωρίζοντας ότι το Exercism χρησιμοποιείται σε όλο τον κόσμο.
Η πρώτη επιλογή είναι να επαναχρησιμοποιήσεις μια υπάρχουσα ιστορία από τη [λίστα ιστοριών που καταγράφονται στην τεκμηρίωση][stories].
Αν θέλεις να δημιουργήσεις μια νέα ιστορία, μη διστάσεις να κάνεις ping στο @exercism/leadership στο PR σου.
Τώρα μπορείς να μετονομάσεις τον κατάλογο `exercises/concept/<story-name>/` ώστε να ταιριάζει με την ιστορία σου.

## 5. Γράψε τις οδηγίες της άσκησης

Μόλις βρεθεί η ιστορία, πρέπει να γράψουμε ακριβείς οδηγίες που απαριθμούν τις εργασίες που θα πρέπει να εκτελέσει ο μαθητής.
Τόσο η ιστορία όσο και οι οδηγίες γράφονται στο έγγραφο `exercises/concept/<story-name>/.docs/instructions.md`.
Όπως εξηγείται στην [προδιαγραφή αυτού του εγγράφου][instructions-spec], κάθε εργασία έχει τον δικό της τίτλο markdown επιπέδου 2 (`## 1. Do X`) και ακολουθεί μια περιγραφή και ένα παράδειγμα χρήσης κώδικα.
Μπορείς να χρησιμοποιήσεις το [`instructions.md` της άσκησης έννοιας boolean][instructions-bool] ως σημείο εκκίνησης, σαν πρότυπο.

Εκτός από το `instructions.md`, χρειαζόμαστε επίσης ένα αρχείο `hints.md`.
Θα πρέπει να περιέχει τους ίδιους τίτλους επιπέδου 2 (`## 1. Do X`) με το αρχείο οδηγιών, ώστε να δίνονται οι σωστές υποδείξεις ανάλογα με την εργασία στην οποία δουλεύει ο μαθητής εκείνη τη στιγμή.
Μπορεί επίσης να υπάρχει μια ενότητα `## General` για υποδείξεις που ισχύουν για όλες τις εργασίες.
Οι υποδείξεις δεν θα πρέπει να δίνουν τη λύση στα ίσια.
Επίσης, πρόσεξε ότι οι άνθρωποι που κάνουν κλικ στις υποδείξεις μπορεί να είναι ήδη μπερδεμένοι, καταβεβλημένοι ή απογοητευμένοι από την άσκηση.
Περισσότερες πληροφορίες για αυτό το έγγραφο υπάρχουν στην [προδιαγραφή του][hints-spec] και μπορείς να χρησιμοποιήσεις το [`hints.md` της άσκησης έννοιας boolean][hints-bool] ως σημείο εκκίνησης, σαν πρότυπο.

## 6. Άνοιξε ένα draft pull request για να επικυρώσεις τον σχεδιασμό

Τώρα είναι καλή στιγμή να ανοίξεις ένα draft pull request για την άσκηση έννοιας σου!
Έχουμε αρκετό υλικό για να αξιολογήσουμε την άσκηση και να την αναδιαμορφώσουμε αν χρειαστεί, πριν δεσμευτούμε στην τρέχουσα μορφή της για τα υπόλοιπα απαιτούμενα αρχεία.
Μην ανησυχείς αν οι αυτόματοι έλεγχοι στο CI (Συνεχής Ενσωμάτωση) αποτύχουν επειδή λείπουν έγγραφα, θα τα δημιουργήσουμε αργότερα!

## 7. Γράψε τον κώδικα

Θα γράψουμε τον κώδικα σαν να λύναμε την άσκηση, και αργότερα θα μετακινήσουμε αρχεία για να συμμορφωθούμε με τις προδιαγραφές.
Ας ξεκινήσουμε αντιγράφοντας τα περιεχόμενα του καταλόγου [`template/`][template] μέσα στον κατάλογο `exercises/concept/<story-name>/` μας.
Αυτό σημαίνει ότι έχουμε τα εξής αρχεία:

```txt
elm.json           # elm project configuration file
src/Exercise.elm   # code for the exercise
tests/Tests.elm    # tests for the exercise
```

Στη συνέχεια, μετονόμασε το `Exercise.elm` ώστε να χρησιμοποιεί το PascalCase του ονόματος της ιστορίας.
Για παράδειγμα, το `annalyns-infiltration` γίνεται `AnnalynsInfiltration.elm`.
Μέσα σε αυτό το αρχείο πηγαίου κώδικα, μπορείς τώρα να γράψεις όλες τις συναρτήσεις που περιγράφονται στο `instructions.md` που μόλις γράψαμε.

Μόλις υλοποιηθεί η άσκηση, ενημέρωσε το περιεχόμενο του αρχείου `tests/Tests.elm` ώστε να περιλαμβάνει σχετικά τεστ που ακολουθούν φυσικά τη σειρά των εργασιών στο `instructions.md`.
**Απόφυγε να χρησιμοποιήσεις το `Fuzz`** στα τεστ των ασκήσεων εννοιών, καθώς δεν ταιριάζει καλά με τη δυνατότητα αποσφαλμάτωσης του κώδικα με το `Debug.log`.
Αντ' αυτού, συμπερίλαβε μερικά τεστ μονάδας για οριακές περιπτώσεις και για γενικές περιπτώσεις.
**Απόφυγε να χρησιμοποιήσεις εκφράσεις `let` ακριβώς κάτω από κλήσεις των συναρτήσεων `test` ή `describe`** στα τεστ των ασκήσεων εννοιών, καθώς ο [test runner του elm δεν το υποστηρίζει ακόμα](https://github.com/exercism/elm-test-runner/issues/30).

Μόλις ολοκληρωθούν τόσο η άσκηση όσο και τα τεστ και λειτουργούν καλά, κάνε τα εξής:

- Αντίγραψε το `src/<ExerciseSlug>.elm` στο `.meta/Exemplar.elm`. Η υλοποίησή σου χρησιμεύει ως σημείο αναφοράς, μια υποδειγματική ("exemplar") υλοποίηση για την άσκηση, η οποία χρησιμοποιείται όταν εκτελούνται τα τεστ της διαδρομής.
- Αφαίρεσε όλες τις υλοποιήσεις μέσα από το `src/<ExerciseSlug>.elm`, ώστε να μείνει ένα αρχικό αρχείο έτοιμο για τον μαθητή να ξεκινήσει την άσκηση.

## 8. Γράψε την τεκμηρίωση της έννοιας

Δημιούργησε έναν κατάλογο `concepts/<concept>/` για την έννοια που σχετίζεται με την άσκηση `exercises/concept/<story-name>`.
Μέσα σε αυτόν τον νέο φάκελο, δημιουργούμε δύο έγγραφα markdown, τα [`introduction.md`][concept-intro-spec] και [`about.md`][concept-about-spec], και ένα αρχείο [`links.json`][concept-links-spec] (οι σύνδεσμοι οδηγούν στις προδιαγραφές τους).

Το αρχείο έννοιας `introduction.md` περιέχει την παρουσίαση που θα βλέπουν οι μαθητές στη σελίδα της έννοιας, όσο δεν έχουν ολοκληρώσει την άσκηση έννοιας που τη συνοδεύει.
Θα πρέπει να τους δίνει μια καλή επισκόπηση του τι θα μάθουν αν ξεκινήσουν την άσκηση που τη συνοδεύει.
Αντίθετα, το αρχείο έννοιας `about.md` περιέχει τη σύνοψη της έννοιας που θα δει ο μαθητής στη σελίδα της έννοιας μόνο αφού ολοκληρώσει την άσκηση έννοιας που τη συνοδεύει.
Ως εκ τούτου, το περιεχόμενό τους μοιάζει με αυτό του αρχείου `exercises/concept/<story-name>/.docs/introduction.md` που έχουμε ήδη γράψει, αλλά δεν είναι το ίδιο.
Προτείνω να ξεκινήσεις από το έγγραφο εισαγωγής της άσκησης και να το απλοποιήσεις στην ουσία του για το αρχείο έννοιας `introduction.md`.
Και για το έγγραφο `about.md`, ξεκίνα από την εισαγωγή της άσκησης και συμπλήρωσέ το, ώστε όλες οι σχετικές πληροφορίες για την έννοια να υπάρχουν σε αυτή τη σελίδα.
Το `links.json` παρέχει χρήσιμους συνδέσμους με πρόσθετες πληροφορίες για μια έννοια.
Αυτοί μπορεί να είναι επίσημη τεκμηρίωση, ένα εξαιρετικό σεμινάριο κ.λπ.
Αυτοί οι σύνδεσμοι δεν αντικαθιστούν τους πιο συμφραζόμενους συνδέσμους μέσα στο αρχείο about.md μιας έννοιας, αλλά παρέχουν ένα γρήγορο σύνολο γενικών σημείων αναφοράς για τον μαθητή.
Οι σύνδεσμοι μπορούν επίσης προαιρετικά να έχουν ένα πεδίο icon_url, το οποίο μπορεί να χρησιμοποιηθεί για να προσαρμόσεις το εικονίδιο που εμφανίζεται όταν προβάλλεται ο σύνδεσμος. Αν δεν καθοριστεί, το εικονίδιο είναι εξ ορισμού το favicon.
Μπορείς να βρεις τα διαθέσιμα εικονίδια στο [github.com/exercism/website-icons/tree/main/exercises][icons].

## 9. Συμπλήρωσε τα διάφορα αρχεία config

Τώρα που ο κώδικας και η τεκμηρίωση είναι έτοιμα, μένουν λίγα αρχεία config για να ολοκληρωθεί αυτό το PR:

- [`concepts/<concept>/.meta/config.json`][concept-config-json]: βάλε τον εαυτό σου ως author, τους πιθανούς reviewers ως contributors και πρόσθεσε ένα "blurb" (σύντομη περιγραφή).
- [`exercises/concept/<story-name>/.meta/config.json`][exercise-config-json]: περιέχει τα authors (εσύ), τους contributors, το blurb και άλλα. Ανατρέξε στη συνδεδεμένη προδιαγραφή.
- `config.json`: πρόσθεσε μια [καταχώριση έννοιας][track-config-json-concept] και μια [καταχώριση άσκησης έννοιας][track-config-json-concept-exercise] στο αρχείο `config.json` της διαδρομής. Χρησιμοποίησε "wip" ή "beta" για το κλειδί status της άσκησης έννοιας. Τα UUID μπορούν να δημιουργηθούν χάρη στο [εκτελέσιμο configlet][configlet] που παρέχει το exercism.
