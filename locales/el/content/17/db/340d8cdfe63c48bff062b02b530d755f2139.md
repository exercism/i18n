# Σχετικά

Η Common Lisp παρέχει στον προγραμματιστή αρκετές διαφορετικές συνθήκες, οι οποίες μπορούν να κατηγοριοποιηθούν με βάση τον αριθμό των "διακλαδώσεων" που υποστηρίζουν.

Επίσης, σε αντίθεση με πολλές άλλες γλώσσες προγραμματισμού, όλες οι συνθήκες στην Common Lisp είναι _εκφράσεις_ και όχι εντολές.
Αυτό σημαίνει ότι όλες οι συνθήκες της Lisp αξιολογούνται σε κάποια τιμή και μπορούν να αντικαταστήσουν συγκεκριμένες παραμέτρους.

Για παράδειγμα:

```lisp
;; Doubles x when it's even
(* x (if (evenp x) 2 1))
```

## Συνθήκες με μία διακλάδωση

Οι συνθήκες `when` και `unless` αξιολογούν κάποιον κώδικα μόνο όταν ο έλεγχος που τους δίνεται είναι αληθής ή ψευδής αντίστοιχα, ενώ σε κάθε άλλη περίπτωση αξιολογούνται σε `nil`.

Το τμήμα μετά την έκφραση ελέγχου μπορεί να περιέχει περισσότερες από μία εκφράσεις.

```lisp
(when (= 2 2) "All is well")      ; => "All is well"
(unless (= 2 2) "Time to panic!") ; => NIL
```

## Η συνθήκη με δύο διακλαδώσεις

Η συνθήκη `if` αξιολογεί την πρώτη έκφραση του σώματος όταν ο έλεγχος είναι αληθής και τη δεύτερη σε κάθε άλλη περίπτωση.

```lisp
(if (= 2 2) 'how-honest 'you-liar) ; => HOW-HONEST
```

Σημείωσε ότι τόσο η ρήτρα then όσο και η ρήτρα else μπορούν να περιέχουν μόνο μία έκφραση.

## Συνθήκες με πολλές διακλαδώσεις

Η "σούπερ-συνθήκη" της Lisp είναι η `cond`, η οποία μπορεί να έχει άπειρο αριθμό διακλαδώσεων.
Κάθε διακλάδωση έχει μια συνθήκη ελέγχου και μια έκφραση σώματος, που περιβάλλονται από ένα επιπλέον ζεύγος παρενθέσεων.
Αν όλοι οι έλεγχοι αξιολογηθούν σε ψευδή τιμή, τότε επιστρέφεται το `nil`.

```lisp
(cond ((= 0 2) 'nope)
      ((= 1 2) 'try-again)
      ((= 2 2) 'quite-true)
      ((= 3 2) 'too-far)
      (t 'something-else))
; => QUITE-TRUE
```

Σημείωσε ότι δεν υπάρχει όριο στον αριθμό των εκφράσεων μετά την έκφραση ελέγχου. 


Αν θέλεις απλώς να ελέγξεις μία τιμή απέναντι σε έναν αριθμό διακλαδώσεων, μπορείς να χρησιμοποιήσεις την πιο καθαρή έκφραση `case`.
Αν καμία από τις περιπτώσεις δεν ταιριάζει, επιστρέφεται το `nil`.
Τόσο το `t` όσο και το `otherwise` μπορούν να χρησιμοποιηθούν ως περιπτώσεις που καλύπτουν τα πάντα:

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark")
  (otherwise "???"))
; => "???"
```

Σημείωσε ότι, όπως και με την `cond`, δεν υπάρχει όριο στον αριθμό των εκφράσεων μετά την έκφραση ελέγχου.

## Οι κρυφές συνθήκες

Οι πράξεις Boolean `and` και `or` στην Common Lisp είναι macros βραχυκυκλώματος που μπορούν να χρησιμοποιηθούν για να μειώσουν την επανάληψη ορισμένων συνθηκών.

Το macro `and` θα επιστρέψει αμέσως `nil` αν συναντήσει μία και μόνη ψευδή τιμή, αλλιώς επιστρέφει την τελευταία αληθή τιμή:

```lisp
(and 42 "Magic" :cool) ; => :COOL
(and () "Magic" :cool) ; => NIL
```

Το macro `or` επιστρέφει την πρώτη αληθή τιμή που συναντά ή `nil` αν δεν υπήρχαν αληθείς τιμές:

```lisp
(or () 42 nil)  ; => 42
(or () NIL nil) ; => NIL
```

## Έχω εξαντληθεί...

Όπως αναφέρθηκε προηγουμένως, όταν καμία από τις διακλαδώσεις σε μια εντολή `case` δεν ταιριάζει, και δεν υπάρχει ρήτρα `otherwise`, επιστρέφεται το `nil`.
Ωστόσο, περιστασιακά, μια αποτυχία να ταιριάξει οποιαδήποτε διακλάδωση θα πρέπει να αντιμετωπίζεται ως σφάλμα. Εδώ έρχεται το `ecase` (για **εξαντλητικό** ταίριασμα).

Χρησιμοποιείται με τον ίδιο ακριβώς τρόπο όπως το `case`, αλλά σηματοδοτεί ένα σφάλμα αντί να επιστρέψει `nil` όταν δεν υπάρχει ταίριασμα.

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => NIL

(ecase 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => ERROR: ELDER-BEAST fell through ECASE expression. Wanted one of (CAT BIRD DOG).
```
