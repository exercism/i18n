# Προσθήκη στις οδηγίες

## Η εργασία

Υλοποίησε δύο διαδικασίες.

- Το `custom_error_message message` πετάει ένα σφάλμα και το `message` είναι το μήνυμα του σφάλματος.
- Το `handle_error script` εκτελεί το δοσμένο script και επιστρέφει μια συμβολοσειρά που περιγράφει τι συνέβη:

  | Όταν το script…                  | επιστρέφει           |
  | --------------------------------- | -------------------- |
  | διαιρεί με το μηδέν               | `"division by zero"`    |
  | ανοίγει ένα αρχείο που δεν υπάρχει | `"file does not exist"` |
  | καλεί μια διαδικασία που δεν υπάρχει | `"proc does not exist"` |
  | πετάει οποιοδήποτε άλλο σφάλμα     | `"unknown error"`       |
  | πετυχαίνει                         | `"success"`             |

## Πώς πετάμε σφάλματα

Η Tcl έχει δύο εντολές για να πετάς ένα σφάλμα.

```tcl
error "something went wrong"
throw {MYAPP BADTHING} "something went wrong"
```

Το `throw` απαιτεί έναν _κωδικό σφάλματος_ ως πρώτο όρισμα.
Ο κωδικός σφάλματος είναι μια λίστα που λέει σε έναν χειριστή τι είδους σφάλμα συνέβη, ώστε να μπορεί να ανταποκριθεί χωρίς να αναλύει το κείμενο του μηνύματος.
Τα περιεχόμενά του είναι δική σου επιλογή: το `{MYAPP BADTHING}` είναι απλώς ένα παράδειγμα και οποιαδήποτε μη κενή λίστα κάνει.
Κατά σύμβαση, πηγαίνει από το γενικό στο ειδικό.
Ένας χειριστής το πιάνει με ένα αντίστοιχο μοτίβο `try ... trap` (περιγράφεται παρακάτω), όπως `trap {MYAPP BADTHING}`, ή `trap {MYAPP}` για να πιάνει κάθε σφάλμα `MYAPP`.
Το `error` δέχεται έναν προαιρετικό κωδικό σφάλματος ως τρίτο όρισμα: `error message ?info? ?code?`.

## Χειρισμός σφαλμάτων με `catch`

Το [`catch`][catch] εκτελεί ένα script και επιστρέφει έναν ακέραιο _κωδικό ολοκλήρωσης_ αντί να πετάξει το σφάλμα:

| κωδικός | σημασία    |
| ------- | ---------- |
| 0       | `ok`       |
| 1       | `error`    |
| 2       | `return`   |
| 3       | `break`    |
| 4       | `continue` |

```tcl
if {[catch {expr {1 / 0}} result options] == 1} {
    puts "error message: $result"
    puts "error code:    [dict get $options -errorcode]"
}
```
```none
error message: divide by zero
error code:    ARITH DIVZERO {divide by zero}
```

Το προαιρετικό δεύτερο όρισμα λαμβάνει το αποτέλεσμα (ή το μήνυμα του σφάλματος).
Το προαιρετικό τρίτο όρισμα λαμβάνει ένα _λεξικό επιλογών_, το οποίο έχει το `-errorcode` και το `-errorinfo` (το ίχνος στοίβας).

Πλεονεκτήματα:

- Είναι μικρό και ευέλικτο.
- Είναι σύντομο για απλές περιπτώσεις, όπως `if {[catch {open $f} fh]} {...}`.

Μειονεκτήματα:

- Πρέπει να ελέγξεις μόνος σου τον κωδικό ολοκλήρωσης.
  Ένα απρόσεκτο `if {[catch ...] != 0} { handle error }` αντιμετωπίζει το `return`, το `break` και το `continue` κι αυτά ως σφάλματα.
- Τα σφάλματα που δεν χειρίζεσαι καταπίνονται εκτός αν τα ξαναπετάξεις μόνος σου.
- Δεν υπάρχει ενσωματωμένος τρόπος να εκτελέσεις κώδικα καθαρισμού είτε το script απέτυχε είτε όχι.

## Χειρισμός σφαλμάτων με `try`

Το [`try`][try] εκτελεί ένα script και στέλνει το αποτέλεσμα στον πρώτο χειριστή που ταιριάζει.
Μια προαιρετική ρήτρα `finally` εκτελείται πάντα, γεγονός που την κάνει καλό μέρος για να απελευθερώσεις πόρους όπως κανάλια αρχείων.

```tcl
set fh [open $filename r]
try {
    set data [read $fh]
} on error {msg options} {
    puts "could not read $filename: $msg"
} finally {
    close $fh
}
```

Πλεονεκτήματα:

- Η δομή είναι ξεκάθαρη: ένας χειριστής για κάθε είδος έκβασης.
- Το `finally` εκτελείται πάντα.
- Οι εκβάσεις που δεν ταιριάζουν με κανέναν χειριστή περνούν στον καλούντα αμετάβλητες.

Μειονεκτήματα:

- Είναι λίγο πιο αναλυτικό από το `catch` για απλές περιπτώσεις.

### `try ... on` έναντι `try ... trap`

Υπάρχουν δύο είδη χειριστών.

Το `on code {msgVar optionsVar}` ταιριάζει με τον _κωδικό ολοκλήρωσης_: `ok`, `error`, `return`, `break` ή `continue`.
Κάθε σφάλμα έχει τον κωδικό ολοκλήρωσης `error`, οπότε το `on error` δεν μπορεί να ξεχωρίσει μια διαίρεση με το μηδέν από ένα αρχείο που λείπει.
Θα έπρεπε να κοιτάξεις το κείμενο του μηνύματος, κάτι που είναι εύθραυστο: τα μηνύματα προορίζονται για ανθρώπους και μπορούν να αλλάξουν μεταξύ εκδόσεων της Tcl.

```tcl
try {
    expr {$a / $b}
} on error {msg} {
    if {[string match "*divide by zero*" $msg]} { ... }
}
```

Το `trap pattern {msgVar optionsVar}` ταιριάζει με τον _κωδικό σφάλματος_.
Ο χειριστής ταιριάζει όταν το μοτίβο είναι πρόθεμα της λίστας `-errorcode`.
Αυτό ξεχωρίζει αξιόπιστα το είδος του σφάλματος.

```tcl
try {
    expr {$a / $b}
} trap {ARITH DIVZERO} {} {
    puts "division by zero"
} trap {} {msg} {
    puts "some other error: $msg"
}
```

Ένα κενό μοτίβο, το `trap {}`, ταιριάζει με οποιοδήποτε σφάλμα.
Οι χειριστές ελέγχονται με σειρά, οπότε βάλε τελευταίο τον χειριστή που πιάνει τα πάντα.

## Πώς βρίσκεις τον κωδικό σφάλματος

Πού τεκμηριώνεται το `ARITH DIVZERO`;
Κυρίως μόνο στον πηγαίο κώδικα, αλλά η Tcl θα σου το δείξει.
Μετά από ένα σφάλμα, η καθολική μεταβλητή `errorCode` κρατά τον κωδικό σφάλματος του πιο πρόσφατου σφάλματος:

```none
$ tclsh
% set a 1; set b 0
% expr {$a / $b}
divide by zero
% set errorInfo     ;# this is the stack trace
divide by zero
    while executing
"expr {$a / $b}"
% set errorCode     ;# this is what we're after
ARITH DIVZERO {divide by zero}
```

Μέσα σε ένα πρόγραμμα, πάρ' τον από το λεξικό επιλογών:

```tcl
try {
    expr {$a / $b}
} on error {msg options} {
    puts [dict get $options -errorcode]
}
```

Το τελευταίο στοιχείο ενός κωδικού σφάλματος είναι συχνά ένα μήνυμα αναγνώσιμο από άνθρωπο ή το όνομα του πράγματος που προκάλεσε το σφάλμα.
Άφησέ το έξω από το μοτίβο του `trap`: χρησιμοποίησε `{ARITH DIVZERO}`, όχι `{ARITH DIVZERO {divide by zero}}`.

### Μερικοί συνηθισμένοι κωδικοί σφάλματος

Αυτός ο πίνακας δεν είναι πλήρης.
Χρησιμοποίησε την παραπάνω τεχνική για να βρεις τον κωδικό για οποιοδήποτε άλλο σφάλμα.

| Περίπτωση             | Παράδειγμα               | Κωδικός σφάλματος             |
| --------------------- | ------------------------ | ----------------------------- |
| Διαίρεση με το μηδέν  | `expr {1 / 0}`           | `ARITH DIVZERO ...`           |
| Σφάλμα πεδίου ορισμού | `expr {sqrt(-1)}`        | `ARITH DOMAIN ...`            |
| Το αρχείο δεν βρέθηκε | `open nosuchfile r`      | `POSIX ENOENT ...`            |
| Άρνηση άδειας         | `open /root/x w`         | `POSIX EACCES ...`            |
| Άγνωστη εντολή        | `no::such::proc`         | `TCL LOOKUP COMMAND name`     |
| Άγνωστη μεταβλητή     | `set nosuchvar`          | `TCL LOOKUP VARNAME name`     |
| Λάθος αριθμός ορισμάτων | `string length a b`    | `TCL WRONGARGS`               |
| Μη έγκυρο λεξικό      | `dict size {1 2 3}`      | `TCL VALUE DICTIONARY`        |
| Μη έγκυρη λίστα       | `llength "a \{b"`      | `TCL VALUE LIST ...`          |

Οι κωδικοί σφάλματος `POSIX` χρησιμοποιούν τα ονόματα `errno` του λειτουργικού συστήματος, όπως `ENOENT`, `EACCES` και `EEXIST`.

## Υπόδειξη: πού εκτελείται το script

Το `handle_error` λαμβάνει ένα script από αυτόν που το καλεί.
Αν το εκτελέσεις με `try $script`, αξιολογείται στο πεδίο εμβέλειας του `handle_error`, όχι του καλούντα.
Για να το αξιολογήσεις εκεί που γράφτηκε, χρησιμοποίησε το [`uplevel`][uplevel]: `try {uplevel 1 $script} ...`.
