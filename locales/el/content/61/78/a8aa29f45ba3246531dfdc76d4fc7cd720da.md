# Boolean

Το `BOOL` περιέχει μία από δύο τιμές, `true` και `false`.

```sather
   ready : BOOL is
      return true;
   end;
```

## Σύγκριση

| Τελεστής | Τι ρωτάει | Παράδειγμα |
| --- | --- | --- |
| `=` | ίδια; | `age = 13` |
| `/=` | διαφορετικά; | `age /= 13` |
| `<` | μικρότερο από | `age < 13` |
| `<=` | μικρότερο ή ίσο | `age <= 13` |
| `>` | μεγαλύτερο από | `age > 13` |
| `>=` | μεγαλύτερο ή ίσο | `age >= 13` |

Αυτοί οι τελεστές δουλεύουν με αριθμούς, ενώ οι `=` και `/=` δουλεύουν και με συμβολοσειρές.

## Οι τρεις τελεστές

| Τελεστής | Γράφεται | Αληθές όταν |
| --- | --- | --- |
| and | `a and b` | και τα δύο είναι αληθή |
| or | `a or b` | τουλάχιστον ένα είναι αληθές |
| not | `~a` | το `a` είναι ψευδές |

Οι `and` και `or` **λειτουργούν με βραχυκύκλωμα**: το `a and b` δεν μπαίνει στον κόπο να κοιτάξει το `b` από τη στιγμή που το `a` αποδειχθεί ψευδές, γιατί η απάντηση έχει ήδη κριθεί. Παρομοίως, το `a or b` σταματάει αν το `a` είναι αληθές. Αυτό έχει σημασία όταν η δεξιά πλευρά είναι κοστοβόρα, ή όταν θα πήγαινε στραβά αν εκτελούνταν.

## Επιστροφή μιας σύγκρισης απευθείας

Μια ρουτίνα της οποίας όλη η δουλειά είναι να θέσει μια ερώτηση θα πρέπει να επιστρέφει την ερώτηση, όχι να διαλέγει την απάντηση με μια συνθήκη:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

Το `if age >= 13 then return true else return false end` χρειάζεται τρεις γραμμές για να πει αυτό που το είπε ήδη η σύγκριση, και κάθε έμπειρος αναγνώστης θα το προσέξει.

## Προτεραιότητα

Το `~` έχει τη μεγαλύτερη προτεραιότητα, μετά το `and` και μετά το `or`. Έτσι, το

```sather
~a and b or c
```

σημαίνει `((~a) and b) or c`. Οι παρενθέσεις δεν κοστίζουν τίποτα να τις γράψεις, και αξίζουν τον κόπο όποτε ο αναγνώστης θα έπρεπε αλλιώς να θυμηθεί αυτή τη σειρά για να παρακολουθήσει τη γραμμή.
