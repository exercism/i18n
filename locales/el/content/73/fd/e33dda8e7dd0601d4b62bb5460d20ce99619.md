# Εισαγωγή

## Στοίβα

Η **στοίβα κλήσεων**, ή απλώς **στοίβα**, είναι μια ειδική δομή δεδομένων που ξεκινά από το υψηλότερο σημείο της μνήμης και μεγαλώνει προς τα κάτω.

### Push και Pop

Η στοίβα υποστηρίζει τουλάχιστον δύο λειτουργίες, με εντολές που έχουν το ίδιο όνομα:

| Εντολή | Λειτουργία που εκτελείται                                 |
| ----------- | --------------------------------------------------- |
| `push`      | προσθέτει ένα στοιχείο στη στοίβα                        |
| `pop`       | αφαιρεί και επιστρέφει το πιο πρόσφατα προστιθέμενο στοιχείο |

Αυτό σημαίνει ότι η στοίβα είναι μια δομή δεδομένων **τελευταία είσοδος, πρώτη έξοδος (LIFO)**.

Για να παρακολουθείται το τρέχον σημείο της στοίβας, όπου βρίσκεται το πιο πρόσφατο στοιχείο, χρησιμοποιείται ο καταχωρητής `rsp`.

Έτσι, μια εντολή `push` παίρνει ένα τελεστέο και αποθηκεύει τα περιεχόμενα αυτού του τελεστέου στη στοίβα.
Καθώς η στοίβα μεγαλώνει προς τα κάτω, η τιμή του `rsp` μειώνεται κατά το μέγεθος της αποθηκευμένης τιμής.

Ομοίως, μια εντολή `pop` παίρνει ένα τελεστέο και αποθηκεύει σε αυτό την πιο πρόσφατη τιμή της στοίβας (αυτή στην οποία δείχνει το `rsp`).
Στη συνέχεια, η τιμή του `rsp` αυξάνεται κατά το μέγεθος της τιμής που ανακτήθηκε.

### Τοπικές μεταβλητές

Είναι επίσης δυνατό να χειριστείς απευθείας την τιμή του `rsp`.
Αυτό χρησιμοποιείται συχνά για τη δημιουργία τοπικών μεταβλητών για μια συνάρτηση.

```x86asm
sub rsp, 24 ; this reserves 24 bytes of space in the stack
add rsp, 24 ; this restores the previous value of rsp, "reducing" the stack by 24 bytes
```

Σημείωσε ότι, τη στιγμή που δεσμεύεται χώρος στη στοίβα, η τιμή που αποθηκεύεται σε αυτόν τον χώρο είναι _μη ορισμένη_.

~~~~exercism/note
Ούτε το `pop` ούτε ο άμεσος χειρισμός του `rsp` αφαιρούν στην πραγματικότητα τα περιεχόμενα που είναι αποθηκευμένα στη μνήμη.
Η "αφαίρεση" από τη στοίβα είναι αφηρημένη σε σχέση με τη νέα διεύθυνση στο `rsp`.

Σε ορισμένα πλαίσια, αυτό μπορεί να προκαλέσει ανησυχίες ασφαλείας, εκθέτοντας εσωτερικές τιμές σε εξωτερικές πηγές.
Ένας τρόπος να το αντιμετωπίσεις είναι μηδενίζοντας τα περιεχόμενα κάθε χώρου της στοίβας που χρησιμοποιεί η συνάρτηση.
~~~~

### Call και Ret

Ο κύριος σκοπός της στοίβας είναι να παρακολουθεί τη διεύθυνση επιστροφής για τις συναρτήσεις που καλούνται.

Όπως αναφέρθηκε σε προηγούμενη έννοια, υπάρχει ένας ειδικός καταχωρητής που ονομάζεται `rip` και δείχνει στην επόμενη εντολή που θα εκτελεστεί.
Αυτός ο καταχωρητής χρησιμοποιείται για τον έλεγχο της ροής ενός προγράμματος και τροποποιείται από εντολές όπως οι `jmp` και `call`.

Κάθε φορά που χρησιμοποιείται μια εντολή `call`, η τρέχουσα τιμή του `rip` ωθείται σιωπηρά στη στοίβα.
Στη συνέχεια, το τελεστέο της εντολής μεταφέρεται στο `rip`, ώστε η εκτέλεση να συνεχιστεί στη συνάρτηση που καλείται.

Μια εντολή `ret` κάνει την αντίθετη λειτουργία.
Κάνει pop από τη στοίβα στο `rip`, ώστε η εκτέλεση να επιστρέψει στη συνάρτηση που κάλεσε.

Κατά την είσοδο στη συνάρτηση, το `rsp` δείχνει στη διεύθυνση στην οποία πρέπει να γίνει η επιστροφή.
Αυτή είναι η διεύθυνση που πρέπει να κάνει pop η εντολή `ret` από τη στοίβα.

Έτσι, κάθε αλλαγή στην τιμή του `rsp` μέσα σε μια συνάρτηση, είτε άμεσα είτε με `push`, πρέπει να αντιστραφεί πριν επιστρέψει η συνάρτηση.

### Καταχωρητές που διατηρεί ο καλούμενος και καταχωρητές που διατηρεί ο καλών

Εκτός από το `rsp`, υπάρχουν και άλλοι καταχωρητές που πρέπει να διατηρούνται κατά τις κλήσεις συναρτήσεων: `rbp`, `rbx`, `r12`, `r13`, `r14` και `r15`.
Γενικά, η συνάρτηση που καλεί περιμένει να μπορεί να χρησιμοποιήσει αυτούς τους καταχωρητές χωρίς να τους αλλάξει η συνάρτηση που καλείται.

Αυτό σημαίνει ότι η συνάρτηση που _καλείται_ πρέπει να αποθηκεύσει τις τιμές αυτών των καταχωρητών πριν τους χρησιμοποιήσει και να τις επαναφέρει στις αρχικές τους τιμές πριν επιστρέψει.
Γι' αυτό ονομάζονται **καταχωρητές που διατηρεί ο καλούμενος**.

Οι άλλοι καταχωρητές γενικού σκοπού είναι άμεσα διαθέσιμοι για χρήση από τη συνάρτηση που καλείται.

Αυτό σημαίνει ότι η συνάρτηση που _καλεί_ πρέπει να αποθηκεύσει τις τιμές αυτών των καταχωρητών πριν καλέσει οποιαδήποτε συνάρτηση, σε περίπτωση που τροποποιηθούν από τη συνάρτηση που καλείται.
Γι' αυτό ονομάζονται **καταχωρητές που διατηρεί ο καλών**.

_Ο πιο συνηθισμένος τρόπος για να αποθηκεύσεις τα περιεχόμενα ενός καταχωρητή είναι να τα αποθηκεύσεις στη στοίβα._

### Πρόλογος και Επίλογος

Σε ορισμένες περιπτώσεις, η στοίβα μπορεί να χρησιμοποιηθεί πολύ, με πολλές τροποποιήσεις πριν επιστρέψει η συνάρτηση.
Έτσι, η παρακολούθηση όλων αυτών των αλλαγών για να αντιστραφούν μπορεί να είναι περίπλοκη.

Σε αυτές τις περιπτώσεις, μια συνηθισμένη στρατηγική είναι να αποθηκεύσεις τη διεύθυνση του `rsp` σε έναν άλλο καταχωρητή που κατά τα άλλα παραμένει αμετάβλητος μέσα στη συνάρτηση.
Και στη συνέχεια, η τιμή του `rsp` μπορεί να επαναφερθεί με μια απλή εντολή `mov` στο τέλος, πριν επιστρέψει η συνάρτηση.

Αν και οποιοσδήποτε καταχωρητής μπορεί να χρησιμοποιηθεί για αυτόν τον σκοπό, είναι συνηθισμένο να χρησιμοποιείται το `rbp` ως δείκτης βάσης.
Καθώς το ίδιο το `rbp` είναι καταχωρητής που διατηρεί ο καλούμενος, αυτό συχνά προηγείται από ένα `push rbp`.
Αυτή η ακολουθία συνήθως ονομάζεται **πρόλογος**.

Στο τέλος, η επαναφορά του `rsp` γίνεται με ένα `mov rsp, rbp` και στη συνέχεια το `rbp` επαναφέρεται επίσης με ένα `pop` από τη στοίβα.
Αυτή η ακολουθία συνήθως ονομάζεται **επίλογος**.

```x86asm
section .text
fn:
    ; prologue
    push rbp
    mov rbp, rsp
    ...
    ; epilogue
    mov rsp, rbp
    pop rbp
    ret
```

### Πέρασμα ορισμάτων με τη στοίβα

Στη σύμβαση κλήσης System V ABI, τα ορίσματα συνήθως περνούν στις συναρτήσεις μέσω καταχωρητών.
Ωστόσο, όταν υπάρχουν πάρα πολλά ορίσματα, ή χρειάζονται περισσότερο χώρο από το μέγεθος ενός καταχωρητή, μπορεί να χρησιμοποιηθεί η στοίβα.

Σε αυτές τις περιπτώσεις, οι τιμές προστίθενται στη στοίβα με αντίστροφη σειρά, ώστε το πρώτο όρισμα να είναι πιο κοντά στο `rsp`.
Καθώς κατά την είσοδο, το `rsp` δείχνει στη διεύθυνση επιστροφής, η οποία είναι μια τιμή 8 byte στην x86-64, το πρώτο όρισμα στη στοίβα, αν υπάρχει, είναι προσβάσιμο στο `rsp + 8`.

### Στοίχιση της στοίβας

Το System V ABI ορίζει ότι η στοίβα πρέπει να είναι στοιχισμένη στα 16 byte αμέσως _πριν_ εκτελεστεί η εντολή `call`.
Καθώς το `call` ωθεί το `rip` στη στοίβα, κατά την είσοδο η στοίβα για τη συνάρτηση που καλείται **δεν** είναι στοιχισμένη στα 16 byte.

Αυτό σημαίνει ότι μια συνάρτηση που καλεί μια άλλη (και, ειδικά, εξωτερικές συναρτήσεις) πρέπει να στοιχίσει τη στοίβα πριν χρησιμοποιήσει το `call`.

Αυτό μπορεί να γίνει αφαιρώντας μια κατάλληλη τιμή από το `rsp`.
Κατά την είσοδο, αυτή η τιμή πρέπει να είναι 8 περισσότερο από ένα πολλαπλάσιο του 16: 8, 24, 40 κ.λπ.
Καθώς μια εντολή `push` αφαιρεί από το `rsp`, ένας περιττός αριθμός `push` μπορεί να χρησιμοποιηθεί για το ίδιο αποτέλεσμα:

```x86asm
fn_a:
    sub rsp, 24 ; subtracting 8 more than a multiple of 16: this aligns the stack
    call fn_b
    add rsp, 24
    ret

fn_b:
    push rbx    ; odd number of pushes: this aligns the stack
    call fn_c
    pop rbx
    ret
```
