# Εισαγωγή

Μια *deque* (ουρά διπλού άκρου) υποστηρίζει push και pop και στα δύο
άκρα σε χρόνο O(1). Η τυπική υλοποίηση στον Factor είναι το `<dlist>` (μια
διπλά συνδεδεμένη λίστα) στο [`dlists`][dlists]; οι πράξεις βρίσκονται
στο [`deques`][deques].

## Το API της deque

```
<dlist>       ( -- dlist )
push-front    ( elt deque -- )
push-back     ( elt deque -- )
pop-front     ( deque -- elt )
pop-back      ( deque -- elt )
deque-empty?  ( deque -- ? )
dlist-length  ( dlist -- n )
clear-deque   ( deque -- )
```

Το `clear-deque` αδειάζει τη deque επί τόπου, κάτι χρήσιμο για να την
ξαναχρησιμοποιήσεις χωρίς νέα δέσμευση μνήμης.

Push και pop στο ίδιο άκρο σου δίνουν μια στοίβα LIFO. Push στο ένα
άκρο και pop στο άλλο σου δίνουν μια ουρά FIFO:

```factor
USING: deques dlists ;

<dlist>
"alpha" over push-back
"bravo" over push-back
"charlie" over push-back
dup pop-front .   ! => "alpha"   (FIFO — oldest first)
dup pop-front .   ! => "bravo"
pop-front .       ! => "charlie"
```

Για LIFO θα χρησιμοποιούσες ένα vector (`V{ }`) με `push`/`pop`,
που έχει μικρότερο κόστος ανά πράξη. Χρησιμοποίησε το `<dlist>` όταν
χρειάζεσαι O(1) και στα *δύο* άκρα, σχεδόν πάντα δηλαδή για μια ουρά FIFO.

## Αναζήτηση κατά πλάτος

Η χρήση FIFO είναι αυτή που κάνει τις deque το κατάλληλο μέτωπο για τη *BFS*.
Ξεκινάς με έναν μόνο κόμβο, κάνεις push τους γείτονες στο πίσω άκρο,
κάνεις pop υποψηφίους από το μπροστινό άκρο και αφαιρείς τα διπλότυπα με ένα
hash-set:

```factor
! DOCTEST: SKIP
USING: deques dlists hash-sets sets ;

! ... visited adjoin and frontier push-back ...
[ frontier deque-empty? ] [
    frontier pop-front ! ... look up neighbours, push unseen ones ...
] until
```

Οι παλαιότεροι υποψήφιοι επισκέπτονται πριν από τους νεότερους, οπότε η
αναζήτηση απλώνεται προς τα έξω σε στρώματα από την αφετηρία. Αυτό είναι που
δίνει στη BFS την ιδιότητα της συντομότερης διαδρομής: την πρώτη φορά που
φτάνεις σε έναν κόμβο-στόχο, το κάνεις μέσω μιας διαδρομής με τον ελάχιστο
αριθμό βημάτων.

## `MEMO:`: αυτόματη προσωρινή αποθήκευση

Κάποιες φορές η αναζήτηση ανά κόμβο που κάνει η BFS είναι ακριβή. Το
λεξιλόγιο [`memoize`][memoize] του Factor σου δίνει το `MEMO:`, ένα
υποκατάστατο του `:` που αποθηκεύει προσωρινά το αποτέλεσμα της λέξης με
κλειδί τις εισόδους της:

```factor
USING: memoize ;

MEMO: gold-count ( cove -- n )
    ! ... slow lookup ...
    ;
```

Μια λέξη `MEMO:` εκτελεί το σώμα της την πρώτη φορά που βλέπει κάθε είσοδο
και μετά επιστρέφει το αποθηκευμένο αποτέλεσμα. Ίδια διεπαφή, χωρίς επιπλέον
κλήσεις στο σημείο κλήσης, απλώς πιο γρήγορη στις επαναλήψεις.
