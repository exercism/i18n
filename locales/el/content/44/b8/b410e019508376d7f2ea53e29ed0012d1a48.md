# Σχετικά

Μια δήλωση `GENERIC:` εισάγει μια λέξη της οποίας η συμπεριφορά εξαρτάται από την κλάση ενός από τα ορίσματά της. Τη συγκεκριμένη συμπεριφορά την παρέχουν *μέθοδοι* (`M:`) που στοχεύουν συγκεκριμένες κλάσεις.

```factor
GENERIC: stringify ( obj -- str )
M: integer stringify number>string ;
M: string  stringify ;
M: f       stringify drop "(none)" ;
```

Όταν καλείται η `stringify`, η Factor εξετάζει την κορυφή της στοίβας, αναζητά την πιο συγκεκριμένη μέθοδο της οποίας η κλάση ταιριάζει και την εκτελεί. Αν καμία μέθοδος δεν ταιριάζει, πετιέται ένα σφάλμα.

## Κλάση αποστολής

Από προεπιλογή, η αποστολή γίνεται στο όρισμα που βρίσκεται στην κορυφή (την πρώτη είσοδο που δηλώνεται στη δήλωση στοίβας). Για αποστολή με πολλά ορίσματα, δες τα `HOOK:` και `MATH:`, που κάνουν αποστολή στο δεύτερο όρισμα ή στην αριθμητική προαγωγή αντίστοιχα.

## Προσθήκη μεθόδων σε μια γενική λέξη

Μπορείς να επεκτείνεις μια γενική λέξη ανά πάσα στιγμή, ακόμη και από διαφορετικό λεξιλόγιο, αρκεί να μπορείς να κάνεις `USE:` και τη γενική λέξη και την κλάση:

```factor
USING: math ;
M: ratio  area drop 0 ;     ! adds an `area` method for ratios
```

## Μέθοδοι σε ενσωματωμένες κλάσεις

Οι γενικές λέξεις δουλεύουν εξίσου καλά σε ενσωματωμένες κλάσεις (`integer`, `string`, `array`, `f`, `t`) όσο και σε πλειάδες που ορίζει ο χρήστης. Οι μέθοδοι στα `f` και `t` είναι ιδιαίτερα χρήσιμες για κατηγορήματα τύπου "is-set?" που έχουν φυσικές προεπιλογές.

## Πότε μια γενική λέξη είναι η σωστή επιλογή

Στρέψου στο `GENERIC:` όταν:

- Μια μεμονωμένη πράξη έχει *πραγματικά διαφορετικές* υλοποιήσεις για διαφορετικές εισόδους (όχι απλώς ένα `case` πάνω σε ετικέτες).
- Περιμένεις να προστεθούν νέοι τύποι αργότερα από άλλον κώδικα.
- Θέλεις το σύστημα τύπων να επιβάλλει ότι η πράξη ορίζεται για κάθε σχετική κλάση: η Factor μπορεί να σου απαριθμήσει τις μεθόδους που λείπουν.

Αν η διαφοροποίηση είναι μια μικρή, σταθερή απαρίθμηση ετικετών, ένα `case` είναι πιο απλό.
