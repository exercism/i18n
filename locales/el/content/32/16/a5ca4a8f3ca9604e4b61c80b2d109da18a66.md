# Υποδείξεις

## Γενικά

- Το συμβόλαιο μπαίνει μετά τον τύπο επιστροφής και πριν από το `is`:

  ```sather
     spare_capacity(load : INT) : INT
        pre load >= 0
     is
        ...
     end;
  ```

- Μέσα σε ένα συμβόλαιο μπορείς να χρησιμοποιήσεις τα ορίσματα και τα χαρακτηριστικά του αντικειμένου, οπότε το `limit` είναι διαθέσιμο.
- Τα tests χτίζονται χωρίς το `-chk`, οπότε ένα λάθος συμβόλαιο δεν θα τα κάνει να αποτύχουν. Γράψε τα συμβόλαια για τον αναγνώστη.

## 1. Στήσε έναν ιμάντα ασφαλείας

- `pre kg > 0`, στο `create`.
- Το σώμα είναι το συνηθισμένο `new`: βάλε την τιμή του χαρακτηριστικού και επέστρεψέ το.

## 2. Πόσο περισσεύει;

- Δύο συνθήκες ενωμένες με `and`: `pre load >= 0 and load <= limit`.
- `post result >= 0`. Αυτό προκύπτει από το `pre`, και γι' αυτό αξίζει να ειπωθεί: καταγράφει γιατί μπορεί κανείς να εμπιστευτεί την απάντηση.

## 3. Πόσο γεμάτο είναι;

- `pre load >= 0` και `post result >= 0`.
- `load * 100 / limit`, με αυτή τη σειρά. Η διαίρεση πρώτα θα πετούσε τα πάντα, όπως θα γινόταν και στο `tuning-the-strings`.

## 4. Είναι ασφαλές;

- Κανένα `pre`: το όλο νόημα είναι ότι μπορεί να ρωτηθεί για οποιοδήποτε φορτίο.
- Το `post` επαναδιατυπώνει την ερώτηση: `post result = (load <= limit)`. Παρενθέσεις, γιατί το `=` χρησιμοποιείται δύο φορές για διαφορετικά πράγματα.
