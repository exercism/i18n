# Σχετικά

## Μερική εφαρμογή

Όλες οι συναρτήσεις στην Elm είναι [curried][currying], που σημαίνει ότι αν καλέσεις μια συνάρτηση χωρίς να περάσεις όλα τα ορίσματα, αυτή επιστρέφει μια νέα συνάρτηση.

Το αποτέλεσμα αυτής της ενέργειας ονομάζεται [μερική εφαρμογή][partial-application] (δεν περνάς όλα τα ορίσματα στη συνάρτηση, αλλά εφαρμόζεις μερικά από αυτά).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

Η μερική εφαρμογή εφαρμόζει πάντα τα ορίσματα με τη σειρά.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## Ο τελεστής διοχέτευσης (`|>`)

Το να πεις `x |> f` είναι ακριβώς το ίδιο με το `f x`. Ένα συγκεκριμένο παράδειγμα είναι ότι το `"5" |> String.toInt` είναι το ίδιο με το `String.toInt "5"`.

Αυτό δεν ακούγεται και τόσο χρήσιμο με την πρώτη ματιά, αλλά ονομάζεται [τελεστής διοχέτευσης][pipe-operator], γιατί σου επιτρέπει να γράφεις κώδικα σε μορφή διοχέτευσης.

Για παράδειγμα, ας πούμε ότι έχουμε μια συνάρτηση sanitize που μετατρέπει την είσοδο του χρήστη σε ακέραιους:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Μπορούμε να την ξαναγράψουμε έτσι:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Έτσι αποφεύγεται η χρήση παρενθέσεων και φαίνονται οι συναρτήσεις με τη σειρά που εφαρμόζονται (πρώτα η `String.trim`, μετά η `String.toInt`), κάτι που βοηθά στην αναγνωσιμότητα.

Υπάρχει επίσης ένας [αντίστροφος τελεστής διοχέτευσης `(<|)`][reverse-pipe-operator].
Το να πεις `x <| f` είναι ακριβώς το ίδιο με το `f x`.
Ούτε αυτό φαίνεται και τόσο χρήσιμο με την πρώτη ματιά, και σίγουρα δεν χρησιμοποιείται τόσο πολύ όσο ο τελεστής διοχέτευσης, αλλά βοηθά να αποφεύγεις τις παρενθέσεις σε ορισμένες περιπτώσεις.

## Σύνθεση συναρτήσεων / point free style

Ο τελεστής [`(>>)`][forward-composition] έχει τύπο `(a -> b) -> (b -> c) -> (a -> c)` και δημιουργεί μια συνάρτηση τύπου `a -> c`, συνθέτοντας δύο συμβατές συναρτήσεις τύπου `a -> b `και `b -> c`.
Το κάνει αυτό παίρνοντας την έξοδο (τύπου `b`) από την πρώτη συνάρτηση και χρησιμοποιώντας την ως πρώτο όρισμα στη δεύτερη συνάρτηση (η οποία πρέπει να είναι του ίδιου τύπου `b`).
Η συνάρτηση που δημιουργείται θα πάρει την ίδια είσοδο (τύπου `a`) με την πρώτη συνάρτηση και θα επιστρέψει ό,τι κι αν επιστρέφει η δεύτερη συνάρτηση, δηλαδή `c`.

Ένα συγκεκριμένο παράδειγμα είναι το `String.trim >> String.toInt`.
Η `String.trim` παίρνει μια συμβολοσειρά ως μοναδική της παράμετρο, οπότε αυτό παίρνει και η συνάρτηση που δημιουργείται.
Η `String.toInt` επιστρέφει ένα `Maybe Int`, οπότε αυτό επιστρέφει και η συνάρτηση που δημιουργείται.
Η `String.trim` επιστρέφει μια `String`, την οποία η `String.toInt` δέχεται ως παράμετρο, οπότε το παράδειγμα μεταγλωττίζεται.

Μπορούμε τώρα να ξαναγράψουμε τη συνάρτηση `sanitize` ως εξής:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Πρόσεξε ότι δεν χρησιμοποιούμε πια την παράμετρο `input`, που βλέπεις στο αρχικό παράδειγμα, αν και η λειτουργικότητα είναι ίδια.
Αυτός ο τρόπος δημιουργίας συναρτήσεων που δεν αναφέρονται καθόλου στις παραμέτρους τους ονομάζεται "Point Free Style".
Το πλεονέκτημα αυτού του στυλ είναι ότι ο κώδικας είναι πιο συνοπτικός, το μειονέκτημα είναι ότι μπορεί να είναι πιο δύσκολος στην κατανόηση, ειδικά για αρχάριους.

Αξίζει να θυμάσαι ότι όλες οι συναρτήσεις στην Elm είναι curried, οπότε το `String.length >> max` μεταγλωττίζεται και έχει ως αποτέλεσμα τα εξής:

- Μια συνάρτηση (1) που έχει μια παράμετρο συμβολοσειράς (την είσοδο της `String.length`)
- Η `max` είναι μια συνάρτηση που έχει δύο παραμέτρους `Int`, αλλά η συνάρτηση 1 της περνά ένα μόνο `Int` (την τιμή επιστροφής της `String.length`), οπότε η `max` εφαρμόζεται μερικώς.
- Η τιμή επιστροφής της μερικώς εφαρμοσμένης συνάρτησης `max` είναι μια άλλη συνάρτηση (2) που παίρνει ένα `Int` και επιστρέφει το μεγαλύτερο από αυτό το `Int` και το μερικώς εφαρμοσμένο `Int` από τη `String.length`
- Επομένως η συνάρτηση 1 (`String -> Int`) επιστρέφει τη συνάρτηση 2 (`Int -> Int`)
- Έτσι, το `((String.length >> max) "123") 2` επιστρέφει `3`, γιατί το `"123"` έχει μήκος 3, που είναι μεγαλύτερο από το 2 του ορίσματος `Int`.

## Σχεδιασμός συναρτήσεων

Για να γράφεις εύκολα κομψό κώδικα στην Elm, καλό είναι να κάνεις τη βασική δομή δεδομένων τελευταία παράμετρο των συναρτήσεων.
Όλες οι κοινές συναρτήσεις στη βασική βιβλιοθήκη το κάνουν αυτό, όπως η `List.map` (η υπογραφή τύπου παρακάτω).

```elm
map : (a -> b) -> List a -> List b
```

Εδώ βλέπουμε ότι η τελευταία παράμετρος της συνάρτησης `map` είναι `List a` και επιστρέφει `List b`, οπότε η βασική δομή δεδομένων (`List`) είναι η τελευταία παράμετρος.

Αυτό καθιστά δυνατό να γράφεις κομψό κώδικα σε μορφή διοχέτευσης, όπως παρακάτω.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Κάνει επίσης βολική τη χρήση της σύνθεσης συναρτήσεων και του point free style, ως εναλλακτική στη διοχέτευση.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

Η σύνθεση συναρτήσεων σου επιτρέπει επίσης να περιορίσεις αυτό το παράδειγμα σε μία μόνο κλήση της `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
