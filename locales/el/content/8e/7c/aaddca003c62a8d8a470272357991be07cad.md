# Οδηγός στυλ για τη C

Αυτός ο οδηγός περιγράφει το στυλ που προορίζεται για χρήση με τα αρχεία παραδείγματος και δοκιμών των ασκήσεων της διαδρομής C.

Οι κανόνες αυτού του οδηγού έρχονται επιπλέον αυτών που ορίζει το αρχείο [.clang-format][], ή τους επισημαίνουν.

## Πρότυπο C

Ο κώδικας θα πρέπει να συμμορφώνεται με το πρότυπο C99, που είναι επίσημα γνωστό ως ISO/IEC 9899:1999.
Δεν θα πρέπει να χρησιμοποιούνται μη τυπικές συναρτήσεις βιβλιοθήκης (όπως αυτές του POSIX), τύποι ή άλλες αναφορές που είναι εξωτερικές ως προς την υλοποίηση.

## Ονόματα

Γενικά, τα ονόματα τύπων, μεταβλητών, δομών και αρχείων θα πρέπει να χρησιμοποιούν snake case, με όλα τα γράμματα πεζά, και κάτω παύλες `_` για να χωρίζουν τα συστατικά του ονόματος.

```c
void some_foo_function(char * input_string, int input_string_length);
```

### Απαριθμήσεις

Τα ονόματα των απαριθμήσεων θα πρέπει συνήθως να είναι στον ενικό και όχι στον πληθυντικό.

Οι ετικέτες των απαριθμήσεων θα πρέπει να χρησιμοποιούν snake case με όλα τα γράμματα κεφαλαία.

```c
enum heading {
    HEADING_NORTH,
    HEADING_EAST,
    HEADING_SOUTH,
    HEADING_WEST
}
```

### Μακροεντολές

Οι μακροεντολές που ορίζουν σταθερές ονομάζονται με snake case, με όλα τα γράμματα κεφαλαία.

```c
#define CONSTANT 0x4000
```

Το snake case με κεφαλαία για τα ονόματα μακροεντολών προτιμάται, αλλά οι μακροεντολές που μοιάζουν με συναρτήσεις μπορούν να ονομάζονται με snake case πεζών.

### Τύποι

Οι τυπικοί τύποι σταθερού πλάτους (στο `stdint.h`) προτιμώνται από τους βασικούς ακέραιους τύπους.

Ο τύπος `bool` (από το `stdbool.h`) προτιμάται από τον `_Bool`.

Παρομοίως, οι `size_t` και `ptrdiff_t` (του `stddef.h`) προτιμώνται για την αναπαράσταση ποσοτήτων που σχετίζονται με τη μνήμη.

Οι τύποι που ορίζει ένα πρόγραμμα με `typedef` θα πρέπει να ονομάζονται με κατάληξη `_t`.
Αν και γνωρίζουμε ότι το POSIX επιφυλάσσει την κατάληξη `_t`, η διαδρομή δεν χρησιμοποιεί προς το παρόν το POSIX.

## Φρουροί συμπερίληψης

Θα πρέπει να χρησιμοποιούνται φρουροί συμπερίληψης σε όλα τα αρχεία κεφαλίδας.

Γενικά, ένα σύνολο φρουρών συμπερίληψης θα πρέπει να περικλείει ολόκληρο το περιεχόμενο της κεφαλίδας.

Οι φρουροί στη δείγμα υλοποίησης (`.meta/example.h`) και στον σκελετό της άσκησης (`exercise_name.h`) θα πρέπει να χρησιμοποιούν ονόματα μακροεντολών που ακολουθούν το όνομα της άσκησης.
Τα ονόματα των μακροεντολών φρουρών θα πρέπει να ακολουθούν τον παραπάνω κανόνα για τις μακροεντολές όσον αφορά τη χρήση πεζών και κεφαλαίων.

Για παράδειγμα, για την άσκηση `hello-world`, χρησιμοποίησε:

```c
#ifndef HELLO_WORLD_H
#define HELLO_WORLD_H

//...

#endif
```

## Παράμετροι

Οι παράμετροι των συναρτήσεων θα πρέπει να έχουν όνομα τόσο στη δήλωση όσο και στον ορισμό όλων των συναρτήσεων.
Αυτό ισχύει τόσο για τα αρχεία `.c` όσο και για τα `.h`.
Τα ονόματα που χρησιμοποιούνται θα πρέπει να ταιριάζουν σε όλες τις περιπτώσεις.
Δηλαδή, ενώ το παρακάτω πρωτότυπο συνάρτησης είναι έγκυρο στη C, το στυλ είναι λανθασμένο επειδή η παράμετρος δεν έχει όνομα: `void foo(int);`.
Το σωστό πρωτότυπο, με την προϋπόθεση ότι όλες οι άλλες δηλώσεις και ο ορισμός χρησιμοποιούν επίσης το όνομα παραμέτρου `bar`, θα ήταν `void foo(int bar);`.

Όπου είναι απλούστερο ή πιο κατάλληλο, προτιμώνται παράμετροι που απαιτούν το πέρασμα ορισμάτων κατά τιμή και όχι κατά δείκτη.
Σημείωσε ειδικότερα ότι αυτό περιλαμβάνει παραμέτρους τύπου `struct`.

Στην περίπτωση που δεν αναμένεται από τον μαθητή να αλλάξει τις τιμές μιας παραμέτρου τύπου δείκτη μέσα στην υλοποίησή του, η παράμετρος αυτή θα πρέπει να χαρακτηρίζεται ως `const`.

## Διάταξη του αρχείου δοκιμών

Το αρχείο δοκιμών κάθε άσκησης ακολουθεί μια συγκεκριμένη διάταξη.
Η διάταξη αποσκοπεί τόσο στο να βοηθά τους συνεισφέροντες να εντοπίζουν τα μέρη του αρχείου, όσο και στο να βοηθά τους μαθητές να καταλαβαίνουν πώς λειτουργούν οι δοκιμές.

Όπως τα περισσότερα αρχεία πηγαίου κώδικα σε C, ένα αρχείο δοκιμών ξεκινά με εντολές include.

```c
#include "vendor/unity.h"
#include "../src/file_under_test.h"
// any other includes here
```

Τις εντολές include ακολουθούν έπειτα οι συναρτήσεις `setUp()` και `tearDown()`.
Μέχρι στιγμής, καμία άσκηση δεν τις χρησιμοποιεί (τα σώματα των συναρτήσεων είναι κενά), αλλά πρέπει να παραμένουν στη θέση τους για να μπορούν τα αρχεία δοκιμών να μεταγλωττίζονται σωστά σε όλες τις πλατφόρμες.

```c
void setUp(void)
{
}

void tearDown(void)
{
}
```

Έπειτα έρχονται οι βοηθητικές συναρτήσεις που χρησιμοποιούν οι συναρτήσεις δοκιμών.
Τα ονόματα τέτοιων βοηθητικών συναρτήσεων δεν θα πρέπει να χρησιμοποιούν το πρόθεμα `test_`.

Έπειτα έρχονται οι ίδιες οι συναρτήσεις δοκιμών.
Τα ονόματα αυτών των συναρτήσεων χρησιμοποιούν το πρόθεμα `test_`.
Εκτός από την πρώτη, κάθε συνάρτηση δοκιμής θα πρέπει να έχει την `TEST_IGNORE();` ως πρώτη εντολή.
Η πρώτη εμφάνισή της θα πρέπει να ακολουθείται από το σχόλιο γραμμής `// delete this line to run test`.

Για παράδειγμα:

```c
static void test_the_first(void)
{
   test_first_foo();
}

static void test_the_second(void)
{
   TEST_IGNORE();               // delete this line to run test
   test_second_foo();
}

static void test_the_third(void)
{
   TEST_IGNORE();
   char grade = 'A';
   test_third_foo(grade);
}
```

Τελευταία στο αρχείο είναι η συνάρτηση `main()`.
Το σώμα της συνάρτησης main ακολουθεί και αυτό μια συγκεκριμένη διάταξη.
Πρώτα μια κλήση στην `UNITY_BEGIN()` και μετά μια κενή γραμμή, έπειτα οι δοκιμές.
Μετά την τελευταία δοκιμή ακολουθεί άλλη μια κενή γραμμή, πριν επιστραφεί το αποτέλεσμα της `UNITY_END()`.

```c
int main(void)
{
    UNITY_BEGIN();

    RUN_TEST(test_foo);
    RUN_TEST(test_bar);

    return UNITY_END();
}
```
