# Σχετικά

Μια συνάρτηση έχει [αναδρομή ουράς][recursion-tc] αν το _τελευταίο_ πράγμα που εκτελεί η συνάρτηση είναι μια κλήση του εαυτού της.

Κάθε φορά που καλείται οποιαδήποτε συνάρτηση, ένα _πλαίσιο στοίβας_ με τις τοπικές μεταβλητές και τα ορίσματά της τοποθετείται στην κορυφή [της στοίβας κλήσεων συναρτήσεων][call-stack].
Όταν μια συνάρτηση επιστρέφει, το πλαίσιο στοίβας αφαιρείται από τη στοίβα.

Οι συναρτήσεις με αναδρομή ουράς επιτρέπουν τη [βελτιστοποίηση κλήσης ουράς][tail-call-optimization] (ή εξάλειψη κλήσης ουράς).
Είναι μια βελτιστοποίηση που επιτρέπει την επαναχρησιμοποίηση του τελευταίου πλαισίου στοίβας από την επόμενη κλήση συνάρτησης, όταν είναι βέβαιο ότι η προηγούμενη συνάρτηση δεν το χρειάζεται πια.
Αυτό περιορίζει τον κίνδυνο υπερχείλισης της στοίβας κλήσεων συναρτήσεων, μια κατάσταση όπου υπάρχουν τόσα πολλά πλαίσια στη στοίβα κλήσεων συναρτήσεων που δεν έχει απομείνει καθόλου μνήμη για να δημιουργηθεί άλλο.

## Βελτιστοποίηση κλήσης ουράς στην Elm

Υπό ορισμένες προϋποθέσεις, ο μεταγλωττιστής της Elm μπορεί να εκτελέσει αυτόματα μια βελτιστοποίηση κλήσης ουράς όταν μεταγλωττίζει σε JavaScript.

Η βελτιστοποίηση μπορεί να συμβεί σε μια αναδρομική συνάρτηση όταν η _τελευταία_ πράξη σε έναν κλάδο γίνεται καλώντας την ίδια τη συνάρτηση σε μια απλή εφαρμογή συνάρτησης.
Ας δούμε μερικά παραδείγματα:

```elm
factorial : Int -> Int
factorial n =
  if n <= 1 then
    n
  else
    n * factorial (n-1)
```

Η παραπάνω υλοποίηση δεν έχει αναδρομή ουράς, επειδή η τελευταία πράξη στον κλάδο `else` είναι ένας πολλαπλασιασμός `n *`.

```elm
factorial : Int -> Int
factorial n =
  factorialHelper n n

factorialHelper : Int -> Int -> Int
factorialHelper n resultSoFar =
  if n <= 1 then
    resultSoFar
  else
    factorialHelper (n-1) (n * resultSoFar)
```

Η παραπάνω υλοποίηση έχει αναδρομή ουράς και θα βελτιστοποιηθεί, επειδή η τελευταία πράξη στον κλάδο `else` είναι το `factorialHelper` που καλεί τον εαυτό του.
Αυτό δεν θα ήταν εφικτό για μια συνάρτηση με υπογραφή τύπου `Int -> Int`, και στην πράξη η βελτιστοποίηση κλήσης ουράς επιτυγχάνεται συχνά ορίζοντας βοηθητικές συναρτήσεις.

## Οριακές περιπτώσεις

Σε ορισμένες περιπτώσεις, ο μεταγλωττιστής δεν μπορεί να βελτιστοποιήσει αναδρομικές συναρτήσεις. Ας δούμε μερικά παραδείγματα.

Ενώ η `f x = f (x - 1)` έχει αναδρομή ουράς, η `f x = (x - 1) |> f` δεν έχει, επειδή η εφαρμογή συνάρτησης `|>` είναι η τελευταία πράξη και θεωρείται ξεχωριστή από την `f`.
Παρομοίως, οι συναρτήσεις που τελειώνουν με συνθήκες Boolean, όπως η `f x = x > 0 || f (x - 1)`, δεν έχουν αναδρομή ουράς.

Η συνάρτηση `f x = if f (x - 1) then 1 else 0` δεν έχει αναδρομή ουράς, επειδή η έκφραση στο `if` δεν θεωρείται κλάδος.
Παρομοίως, ούτε μια αναδρομική κλήση σε μια εντολή `case` θα βελτιστοποιούνταν.

Η συνάρτηση `f x = let y = f (x - 1) in y`, δεν έχει αναδρομή ουράς επειδή καλεί τον εαυτό της μέσα σε μια δήλωση `let`, η οποία δεν θεωρείται κλάδος.
Ωστόσο, στην `f x = let g x = g (x - 1) in g x` η συνάρτηση `g` έχει αναδρομή ουράς και θα βελτιστοποιηθεί, παρόλο που ορίζεται μέσα σε μια δήλωση `let`.

Η συνάρτηση `f x = if x > 0 then f (x + 1) else 1 + f x` θα βελτιστοποιηθεί _μερικώς_: ο κλάδος `then` μπορεί να βελτιστοποιηθεί, αλλά ο κλάδος `else` όχι.
Η μερική βελτιστοποίηση είναι το καλύτερο που μπορεί να επιτευχθεί σε ορισμένες καταστάσεις, όπως η διάσχιση δενδρικών δομών ή ο ορισμός συναναδρομικών συναρτήσεων.
