# Εισαγωγή

Συχνά είναι χρήσιμο να ορίζουμε δικούς μας τύπους στα προγράμματά μας.

Η δημιουργία νέων πρωταρχικών τύπων είναι δυνατή, αλλά σπάνια γίνεται.
Οι ενσωματωμένοι πρωταρχικοί τύποι δεν είναι μια αυθαίρετη επιλογή: αντιστοιχούν στενά με τους τυπικούς τύπους στον μεταγλωττιστή LLVM που χρησιμοποιεί η Julia για μεταγλώττιση JIT.

Πολύ πιο χρήσιμη είναι η δυνατότητα να ορίζουμε σύνθετους τύπους, με ονομασμένα πεδία.

Άλλες γλώσσες έχουν κάτι παρόμοιο, ονομάζοντάς τα `structs` ή `records`.
Η τεκμηρίωση της Julia τα αναφέρει ως `composite types`, αν και (με μια μικρή αναντιστοιχία) η σύνταξη της γλώσσας τα ορίζει με τη λέξη-κλειδί `struct`.

```julia-repl
julia> struct Person
           id
           name::String
           age::Integer
       end

julia> fred = Person(23, "Fred Smith", 46)
Person(23, "Fred Smith", 46)

julia> typeof(fred)
Person

julia> isstructtype(Person)
true

julia> isconcretetype(Person)
true

julia> fred.age
46
```

Αξίζει να σημειώσουμε μερικά σημεία στο παραπάνω παράδειγμα:

- Δεν έχει καθοριστεί τύπος για το `id`, οπότε ο μεταγλωττιστής το ερμηνεύει ως `id::Any`.
- Το όνομα του τύπου χρησιμοποιείται ως κατασκευαστής, όπως στο `Person(id, name, age)`, για να δώσει ένα στιγμιότυπο του τύπου `Person`.
- Τα επιμέρους πεδία είναι προσβάσιμα με σημειογραφία τελείας, όπως ακριβώς στις ονομασμένες πλειάδες.

Τα στοιχεία του τύπου `Person` είναι αμετάβλητα, οπότε δεν επιτρέπονται ενημερώσεις.

```julia-repl
julia> fred.age += 1
ERROR: setfield!: immutable struct of type Person cannot be changed
```

Αν η μεταβλητότητα είναι απαραίτητη, πρόσθεσε `mutable` στον ορισμό.

```julia-repl
julia> mutable struct MutPerson
           name
           age
       end

julia> shaila = MutPerson("Shaila", 23)
MutPerson("Shaila", 23)

julia> shaila.age += 1
24

julia> shaila
MutPerson("Shaila", 24)
```

Ο κατασκευαστής, από προεπιλογή, απαιτεί τα πεδία να εμφανίζονται με την ίδια σειρά όπως στον ορισμό, κάτι που γίνεται άβολο για πιο περίπλοκους τύπους.

Η χρήση της μακροεντολής `@kwdef` επιτρέπει δύο νέες δυνατότητες:

- Ο κατασκευαστής χρησιμοποιεί λέξεις-κλειδιά, όχι θέση.
- Τα πεδία μπορούν να έχουν προεπιλεγμένες τιμές και προαιρετικά μπορούν να παραλείπονται από τον κατασκευαστή.

```julia-repl
julia> @kwdef struct KwPerson
           name
           age = 42
       end
KwPerson

julia> suki = KwPerson(age=29, name="Suki")
KwPerson("Suki", 29)

julia> qi = KwPerson(name="Qi")
KwPerson("Qi", 42)

# create a Vector{KwPerson}

julia> friends = [suki, qi]
2-element Vector{KwPerson}:
 KwPerson("Suki", 29)
 KwPerson("Qi", 42)
```

## Ιεραρχίες σύνθετων τύπων

Μέχρι στιγμής, έχουμε δημιουργήσει μόνο συγκεκριμένους σύνθετους τύπους.
Αν το ελέγξεις, όλοι είναι υποτύποι του `Any`.

Όταν δημιουργείς πολλούς σχετιζόμενους τύπους, πιθανώς έχει περισσότερο νόημα να ορίσεις μια ιεραρχία γι' αυτούς.
Αυτό γίνεται πολύ εύκολα.

Πρώτα, δημιούργησε έναν αφηρημένο τύπο:

```julia-repl
julia> abstract type AbstractPerson end

julia> supertype(AbstractPerson)
Any
```

Στη συνέχεια, βάλε έναν τελεστή `<:` σε έναν ορισμό τύπου, για να δείξεις τη σχέση.

```julia-repl
julia> struct ConcretePerson <: AbstractPerson
            id
            name::String
            age::Integer
        end

julia> supertype(ConcretePerson)
AbstractPerson

julia> ConcretePerson(15, "Luis", 8)
ConcretePerson(15, "Luis", 8)
```

Επανάλαβε όπως χρειάζεται, χωρίς να ξεχνάς ότι δεν επιτρέπεται ο ορισμός υποτύπων για συγκεκριμένους τύπους.

Για μια πιο περίπλοκη ιεραρχία, δημιούργησε αφηρημένους υποτύπους όπως χρειάζεται.

```julia-repl
julia> abstract type AdultPerson <: AbstractPerson end

julia> supertype(AdultPerson)
AbstractPerson
```

Η αξία μιας τέτοιας ιεραρχίας θα γίνει πιο ξεκάθαρη όταν φτάσουμε στην έννοια `Multiple Dispatch` και δούμε πώς οι συναρτήσεις χειρίζονται τους τύπους των ορισμάτων.
