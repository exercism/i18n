# Σχετικά

[Οι καταγραφές][records] είναι δομές δεδομένων που ομαδοποιούν μαζί σχετικές πληροφορίες με ετικέτες.
Μοιάζουν με τα αντικείμενα στη JavaScript ή τη Java, ή με τα structs στη C ή τη Rust, αλλά έχουν μερικές βασικές διαφορές.

## Δημιουργία καταγραφών

Οι καταγραφές [δημιουργούνται][create] με άγκιστρα και τα στοιχεία τους χωρίζονται με κόμματα.

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

Ο τύπος μιας καταγραφής ορίζεται επίσης με παρόμοια σύνταξη, μόνο που τα σύμβολα ίσον `=` αντικαθίστανται από άνω και κάτω τελείες `:`.

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

Η επανάληψη αυτών των ορισμών τύπου είναι κουραστική, οπότε η χρήση ενός [ψευδώνυμου τύπου][record-types] για τον διαμοιρασμό του ορισμού είναι ένα συνηθισμένο ιδίωμα.

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

Το ψευδώνυμο τύπου παρέχει επίσης αυτόματα μια συνάρτηση κατασκευαστή για την καταγραφή.
Αυτό μερικές φορές προκαλεί έκπληξη, αφού οι συναρτήσεις στην Elm πρέπει να ξεκινούν με πεζό χαρακτήρα, αλλά οι κατασκευαστές τύπων αποτελούν μία εξαίρεση.

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

## Πρόσβαση στα πεδία μιας καταγραφής

Ο κύριος τρόπος για να [προσπελάσεις την τιμή ενός πεδίου ενός στιγμιότυπου καταγραφής][access] είναι να χρησιμοποιήσεις τη σημειογραφία με τελεία, όπως `firefly.creator`.
Ο μεταγλωττιστής της Elm υποστηρίζει επίσης ειδικές συναρτήσεις πρόσβασης που ξεκινούν με τελεία `.`, όπως η `.creator`, οι οποίες λειτουργούν σε οποιαδήποτε καταγραφή έχει πεδίο με αυτό το όνομα.
Αυτή είναι η δεύτερη εξαίρεση στον κανόνα ότι οι συναρτήσεις πρέπει να ξεκινούν με πεζό χαρακτήρα.
Στην πραγματικότητα, οι συναρτήσεις που ορίζει ο χρήστης πρέπει να ξεκινούν με πεζό χαρακτήρα, αλλά τα δύο παραδείγματα που μόλις ανακαλύψαμε παράγονται από τον μεταγλωττιστή, όχι από τον προγραμματιστή.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

Οι καταγραφές μπορούν επίσης να _αποδομηθούν_ σε δεσμεύσεις χρησιμοποιώντας την [αντιστοίχιση προτύπων καταγραφών][pattern-matching].
Η αποδόμηση λειτουργεί με οποιαδήποτε καταγραφή έχει πεδία με τα σχετικά ονόματα.

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

## Ενημέρωση καταγραφών

Οι καταγραφές είναι αμετάβλητες, όπως τα πάντα στην Elm, οπότε μόλις οριστεί μια καταγραφή, οι τιμές των πεδίων της δεν μπορούν ποτέ να αλλάξουν.
Υπάρχει μια [ειδική σύνταξη για να δημιουργήσεις ένα αντίγραφο μιας υπάρχουσας καταγραφής αλλάζοντας ένα ή περισσότερα πεδία][update].
Αυτή η σύνταξη χρησιμοποιεί το σύμβολο της κάθετης γραμμής `|` για να ξεχωρίζει την αρχική καταγραφή από τα πεδία που θα αλλάξουν, όπως `{ oldRecord | field1 = newValue }`.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

## Σύγκριση καταγραφών

Η Elm χρησιμοποιεί [δομική ισότητα][equality], που σημαίνει ότι δύο στιγμιότυπα της ίδιας καταγραφής με πανομοιότυπες τιμές είναι ίσα.

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

## Επεκτάσιμες καταγραφές

Η Elm υποστηρίζει επίσης [δομική τυποποίηση][structural-typing], που σημαίνει ότι αν μια συνάρτηση απαιτεί μια καταγραφή με πεδία x και y, θα λειτουργήσει με οποιαδήποτε καταγραφή έχει αυτά τα πεδία, όπως σημεία 2D, σημεία 3D, διαστημόπλοια κ.λπ.
Αυτοί οι τύποι καταγραφών έχουν μια κάθετη γραμμή `|` στον ορισμό τους, όπως `{ a | x : Float, y : Float }` και ονομάζονται "επεκτάσιμες καταγραφές" στην ορολογία της Elm.
Πρόσεχε τη διαφορά ανάμεσα σε μια κάθετη γραμμή `|` σε έναν ορισμό τύπου, που αποτελεί ορισμό επεκτάσιμης καταγραφής (`{ a | x : Int }`), και σε μια κάθετη γραμμή `|` σε ένα πραγματικό στιγμιότυπο καταγραφής, που σημαίνει ότι ενημερώνουμε μερικά πεδία αυτής της καταγραφής.

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
