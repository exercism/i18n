# Σχετικά

## Εισαγωγή

Οι αδιαφανείς τύποι είναι μια τεχνική ενθυλάκωσης στην Elm.
Μερικοί το αποκαλούν επίσης απόκρυψη πληροφοριών ή απόκρυψη λεπτομερειών υλοποίησης.
Χρησιμοποιούνται επίσης συνήθως για την επιβολή επικύρωσης, χρησιμοποιώντας το μοτίβο [Ανάλυση, μην επικυρώνεις][parse-dont-validate].
Για παράδειγμα, θα μπορούσες να έχεις έναν αδιαφανή τύπο `EmailAddress`, που μπορεί να περιέχει μόνο έγκυρες διευθύνσεις email (σε αντίθεση με μια `String`, που μπορεί να περιέχει οτιδήποτε).

## Δημιουργία ενός αδιαφανούς τύπου

[Οι προσαρμοσμένοι τύποι][custom-types] έχουν μία ή περισσότερες *παραλλαγές*, και ο μεταγλωττιστής δημιουργεί αυτόματα μια συνάρτηση για τη δημιουργία κάθε *παραλλαγής*, χρησιμοποιώντας το όνομα της *παραλλαγής*.
Αυτές είναι ο μόνος τρόπος με τον οποίο μπορούν να δημιουργηθούν οι προσαρμοσμένοι τύποι.
Ο μεταγλωττιστής επιτρέπει επίσης την αποδόμηση για αυτές τις παραλλαγές.

```elm
type Maybe a
    = Nothing --> Variant implies a 'Nothing' function, with type 'Maybe a', and destructuring of 'Nothing'
    | Just a  --> Variant implies a 'Just' function, with type 'a -> Maybe a', and destructuring of 'Just _'
```

Από προεπιλογή, όλα αυτά είναι εσωτερικά στο αρχείο / module, και χρησιμοποιούμε τη λέξη-κλειδί `exposing` για να επιλέξουμε τι θα εξάγουμε.
Για να δημιουργήσεις έναν αδιαφανή τύπο, απλώς επιλέγεις να μην εξάγεις τις *παραλλαγές*.

Όταν το κάνεις αυτό, σχεδόν πάντα χρειάζεται να παρέχεις έναν άλλο τρόπο για να δημιουργείς και να παίρνεις τις *παραλλαγές*, εκθέτοντας προσαρμοσμένες συναρτήσεις.
Αυτές οι προσαρμοσμένες συναρτήσεις σου επιτρέπουν να εφαρμόσεις κάποια λογική κατά τη δημιουργία και τη λήψη των *παραλλαγών*.
Αυτό κρύβει τις εσωτερικές λεπτομέρειες υλοποίησης του module, και σημαίνει ότι μπορείς να αλλάξεις τις λεπτομέρειες υλοποίησης όσο θέλεις, αρκεί οι εκτεθειμένες συναρτήσεις να παραμένουν ίδιες.

## Ανάλυση, μην επικυρώνεις

Η πιο συνηθισμένη χρήση των αδιαφανών τύπων είναι πιθανώς η επιβολή επικύρωσης, χρησιμοποιώντας το μοτίβο [Ανάλυση, μην επικυρώνεις][parse-dont-validate].
Σε αυτό το μοτίβο, εκθέτεις μια συνάρτηση που δέχεται μια είσοδο με λιγότερη δομή / ασφάλεια τύπων από ό,τι θέλεις, όπως μια `String`, και στη συνέχεια την αναλύεις σε έναν πιο δομημένο τύπο, όπως `EmailAddress`, είτε επιστρέφοντας τον τύπο, είτε επιστρέφοντας ένα σφάλμα (συνήθως `Maybe` ή `Result`).

Για παράδειγμα, στον παρακάτω κώδικα, είναι δυνατόν μόνο για εξωτερικά module να δημιουργήσουν έναν τύπο `EmailAddress` χρησιμοποιώντας τη συνάρτηση `parseEmailAddress`, οπότε όταν εργάζεσαι με τον τύπο `EmailAddress`, είσαι σίγουρος ότι είναι έγκυρος.

```elm
module EmailAddress exposing ( EmailAddress, parseEmailAddress, getEmailAddress )

-- The `EmailAddress` custom type has one variant, also called `EmailAddress`
-- When a custom type has one variant, it is idiomatic to use the same name for both.
type EmailAddress = 
  EmailAddress String

-- create an EmailAddress variant
parseEmailAddress: String -> Maybe EmailAddress
parseEmailAddress candidateEmailAddress =   
  if isValidEmailAddress candidateEmailAddress then
    Just (EmailAddress candidateEmailAddress)
  else
    Nothing

-- get an EmailAddress variant
getEmailAddress: EmailAddress -> String
getEmailAddress ( EmailAddress  emailAdress ) =
  emailAdress

isValidEmailAddress: String -> bool
-- ... 
```
