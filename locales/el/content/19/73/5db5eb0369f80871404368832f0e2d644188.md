# Σχετικά

Σε αυτό το σημείο του προγράμματος σπουδών, έχεις ήδη δει πολλούς ορισμούς συναρτήσεων.
Συνήθως, αυτοί παρουσιάζονταν χωρίς πολλά σχόλια για την έξοδο στο REPL:

```julia-repl
julia> f(x) = x^2
f (generic function with 1 method)
```

Γιατί _"generic function with 1 method"_ ;

Ας υποθέσουμε ότι θέλουμε να είμαστε πιο συγκεκριμένοι ως προς τους τύπους των ορισμάτων.

```julia-repl
julia> f(x::Integer) = x^2
f (generic function with 2 methods)

julia> f(x::Real) = x^2
f (generic function with 3 methods)
```

Ή θα μπορούσαμε να αλλάξουμε τον αριθμό των ορισμάτων:

```julia-repl
julia> f(x, y) = x * y
f (generic function with 4 methods)
```

Φαίνεται ότι οι νέοι ορισμοί της ίδιας συνάρτησης ονομάζονται "μέθοδοι".
Οι μέθοδοι προστίθενται σε μια λίστα, αντί να αντικαθιστούν τον παλιό ορισμό.

Μπορούμε εύκολα να δούμε τη λίστα με τις μεθόδους:

```julia-repl
julia> methods(f)  # output edited for brevity
# 4 methods for generic function "f" from Main:
 [1] f(x, y)
 [2] f(x::Integer)
 [3] f(x::Real)
 [4] f(x)
 ```

Αν καλέσουμε τη συνάρτηση `f`, η Julia με κάποιον τρόπο ξέρει ποια μέθοδο να χρησιμοποιήσει:

```julia-repl
julia> f(2.5)  # Float64
6.25

julia> f(2)  # Int64
4

julia> f(2, 3)  # Int64, Int64
6
```

## Τι είναι μια συνάρτηση;

Σύμφωνα με το [εγχειρίδιο][function], μια συνάρτηση είναι ένα αντικείμενο που αντιστοιχίζει μια πλειάδα ορισμάτων σε μια τιμή επιστροφής.
Αυτό είναι κοντά στον ορισμό που χρησιμοποιούν οι μαθηματικοί.

Συνήθως σκεφτόμαστε τα ορίσματα της συνάρτησης στο `f(2, 3)` ως δύο ξεχωριστά στοιχεία, αλλά ο μεταγλωττιστής τα βλέπει ως μία [πλειάδα][tuple].
Αυτό ισχύει ακόμη και για ένα μόνο όρισμα (αν και χρειάζεται να προσθέσουμε ένα κόμμα για να γίνει πιο σαφές):

```julia-repl
julia> typeof( (2, 3) )
Tuple{Int64, Int64}

julia> typeof( (2,) )
Tuple{Int64}
```

Βλέποντας τη συνάρτηση ως μαύρο κουτί, μπορούμε να πούμε ότι μπαίνει μια πλειάδα και βγαίνει μια τιμή επιστροφής.
Πιο τυπικά, η πλειάδα _αντιστοιχίζεται_ σε μια τιμή επιστροφής.

## Πώς χειρίζονται οι συναρτήσεις διαφορετικούς αριθμούς και τύπους ορισμάτων;

Αυτό συνήθως αναφέρεται ως ["πολυμορφισμός"][polymorphism].

Αυτό αποτελεί σημαντικό θέμα στην επιστήμη των υπολογιστών εδώ και αρκετές δεκαετίες, και έχουν υιοθετηθεί διαφορετικές προσεγγίσεις.

Η προσέγγιση της Julia είναι ασυνήθιστη, αν και όχι μοναδική.

- Οι συναρτήσεις είναι ["γενικές"][generic], δηλαδή μπορούν να έχουν πολλές μεθόδους συνδεδεμένες με αυτές.
- Οι συναρτήσεις είναι απλώς ονόματα, μέχρι να τους συνδεθούν μέθοδοι.
- Οι μέθοδοι μπορούν να προστεθούν κατά το δοκούν, δυνητικά σε μεγάλους αριθμούς (ο τελεστής `+` είναι μια συνάρτηση με 161 μεθόδους, αυτή τη στιγμή).
- Όταν καλείται μια συνάρτηση, η Julia εξετάζει την υπογραφή κλήσης: τον αριθμό των ορισμάτων και τον τρέχοντα τύπο καθενός.
- Επιλέγεται η μέθοδος που ταιριάζει περισσότερο με την υπογραφή κλήσης.
  - Σε γενικές γραμμές, ο αριθμός των ορισμάτων πρέπει να ταιριάζει ακριβώς (αν και ο τελεστής [splat/slurp][splat] `...` μπορεί εν μέρει να το παρακάμψει).
  - Προτιμώνται οι μέθοδοι με τύπους που ταιριάζουν ακριβώς με την υπογραφή κλήσης.
  - Αν χρειαστεί, η Julia θα κοιτάξει τους υπερτύπους κάθε ορίσματος στην υπογραφή κλήσης για να βρει τη μέθοδο που ταιριάζει περισσότερο, την πιο συγκεκριμένη.
- Η επιλεγμένη μέθοδος γίνεται [`dispatched`][dispatch] με τα δεδομένα ορίσματα και επιστρέφει ένα αποτέλεσμα.
- Αν δεν βρεθεί κατάλληλη μέθοδος, πετιέται ένα [`MethodError`][methoderror].

Σημείωσε ότι η Julia είναι δυναμικά τυποποιημένη, οπότε η αποστολή μεθόδων συμβαίνει σε _χρόνο εκτέλεσης_.

## Πολλαπλή αποστολή: ένα παράδειγμα

Η προηγούμενη ενότητα είχε πολλά λόγια, οπότε ας μεταφράσουμε αυτές τις ιδέες σε κώδικα.
Για απλότητα, οι παρακάτω συναρτήσεις έχουν μόνο ένα όρισμα, αλλά δεν είναι ασυνήθιστο να βρεις συναρτήσεις με δεκάδες ορίσματα (όπως σε πακέτα σχεδίασης γραφικών ή στη μηχανική μάθηση).

Ξεκίνα ορίζοντας μερικούς προσαρμοσμένους τύπους, για να αναπαραστήσεις γεωμετρικά σχήματα.

```julia-repl
julia> abstract type Shape end

julia> struct Circle <: Shape
           radius::Float64
       end

julia> struct Square <: Shape
           side::Float64
       end

julia> struct Rectangle <: Shape
           length::Float64
           width::Float64
       end
```

Στη συνέχεια μπορούμε να ορίσουμε μεθόδους για να υπολογίσουμε το εμβαδόν κάθε σχήματος.
Κάθε μία παίρνει ένα όρισμα, διαφορετικού συγκεκριμένου, ορισμένου από τον χρήστη τύπου σε κάθε περίπτωση.

```julia-repl
julia> area(c::Circle) = π * c.radius^2
area (generic function with 1 method)

julia> area(s::Square) = s.side^2
area (generic function with 2 methods)

julia> area(r::Rectangle) = r.length * r.width
area (generic function with 3 methods)
```

Τώρα μπορούμε να δημιουργήσουμε μερικά σχήματα και να υπολογίσουμε τα εμβαδά, βασιζόμενοι στον μηχανισμό αποστολής της Julia για να χρησιμοποιηθεί ο σωστός τύπος για το καθένα.

```julia-repl
julia> circle = Circle(2.3)
Circle(2.3)

julia> area(circle)  # call signature Tuple{Circle}
16.619025137490002

julia> square = Square(1.6)
Square(1.6)

julia> area(square)  # call signature Tuple{Square}
2.5600000000000005

julia> rectangle = Rectangle(1.4, 2.1)
Rectangle(1.4, 2.1)

julia> area(rectangle)  # call signature Tuple{Rectangle}
2.94
```

## [Παραμετρικές μέθοδοι][parametric]

Οι υπογραφές μεθόδων μπορούν να δέχονται εικονικές τιμές τύπου, περίπου με τον ίδιο τρόπο όπως οι παραμετρικοί τύποι.

Η σύνταξη είναι χαρακτηριστική, απαιτεί μια ρήτρα `where`:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T} = true
same_type (generic function with 1 method)

julia> same_type([1, 2], 3)
true

julia> same_type([1, 2], "three")
ERROR: MethodError: no method matching same_type(::Vector{Int64}, ::String)
```

Το παραπάνω παράδειγμα απαιτεί και τα δύο ορίσματα να χρησιμοποιούν τον ίδιο τύπο `T`, όποιος κι αν είναι.

Μπορούμε να γίνουμε πιο συγκεκριμένοι βάζοντας έναν περιορισμό στο `T`:

```julia-repl
julia> same_type(v::Vector{T}, x::T) where {T<:Number} = true
same_type (generic function with 2 methods)
```

Με αυτή τη μέθοδο, μόνο πανομοιότυποι αριθμητικοί τύποι επιστρέφουν `true`.

Είναι δυνατές πολλαπλές εικονικές μεταβλητές, χωρισμένες με κόμμα στη ρήτρα `where`.
Οι επόμενες δύο μέθοδοι φαίνονται παρόμοιες:

```julia-repl
julia> func(v::Vector{Number}, x::Number) = true
func (generic function with 1 method)

julia> func(v::Vector{S}, x::T) where {S<:Number, T<:Number} = true
func (generic function with 2 methods)
```

Μια διαφορά είναι ότι οι τιμές τύπων `S` και `T` είναι διαθέσιμες για χρήση μέσα στο σώμα της συνάρτησης της δεύτερης μεθόδου.
Αυτού του είδους το τρικ μπορεί να μη το χρησιμοποιείς συχνά, αλλά μπορεί να γλιτώσει πολλά προβλήματα σε ορισμένες περιπτώσεις.

Για παράδειγμα, στον παρακάτω ορισμό παραμετρικού τύπου, τα πεδία πρέπει να είναι του ίδιου τύπου `T`, ο οποίος περιορίζεται να είναι υπότυπος του `Real`:
```julia
struct Point{T<:Real}
    x::T
    y::T
end
```
Αυτός ο ορισμός του `Point` δέχεται ένα `x` και ένα `y` του ίδιου τύπου, ή μπορεί να δεχθεί ένα `x` και ένα `y` διαφορετικών τύπων, αλλά τότε πρέπει να δοθεί ένας ρητός τύπος μετατροπής.
```julia-repl
julia> Point(4, 5)
 Point{Int64}(4, 5)

julia> Point(3.5, 2)
 MethodError: no method matching Point(::Float64, ::Int64)    # Output truncated for brevity

julia> Point{Float32}(3.5, 2)
 Point{Float32}(3.5f0, 2.0f0)

julia> Point{Int64}(3.5, 2) 
 InexactError: Int64(3.5)      # Output truncated for brevity
```
Ενώ αυτό το επίπεδο ελέγχου πάνω στους τύπους μπορεί να είναι επιθυμητό, μπορεί επίσης να είναι χρήσιμο να έχουμε λίγη αφαίρεση.
```julia
Point(x::T, y::S) where {T<:Real, S<:Real} = Point{promote_type(T,  S)}(x, y)
```
Αυτός ο εξωτερικός κατασκευαστής το παρέχει αυτό επιτρέποντας σε ένα `Point` να δέχεται ανομοιογενείς τύπους για τα `x` και `y` χωρίς να προσδιορίζεται ρητά ο τύπος μετατροπής.
Οι τιμές τύπων `T` και `S` χρησιμοποιούνται στο σώμα της συνάρτησης στο `promote_type(T, S)` για να παρέχουν τον ρητό τύπο μετατροπής για τον αρχικό ορισμό.
```julia-repl
julia> Point(3.5, 2)
 Point{Float64}(3.5, 2.0)
```

## Σύγκριση με άλλες γλώσσες

Επειδή η Julia εξετάζει όλα τα ορίσματα κατά την επιλογή μιας μεθόδου, αυτό ονομάζεται [`multiple dispatch`][multiple-dispatch].

Λίγες άλλες γλώσσες επιτρέπουν την πολλαπλή αποστολή, όπως η Common Lisp, αν και σπάνια είναι τόσο κεντρική στον σχεδιασμό της γλώσσας όσο στη Julia.

Αντιθέτως, σε μια αντικειμενοστρεφή (OO) γλώσσα (π.χ. Ruby), οι μέθοδοι συνήθως καλούνται πάνω σε ένα [στιγμιότυπο][instance].
Ο ορισμός τώρα δίνει προτεραιότητα στο πρώτο όρισμα (με ένα όνομα όπως `self` ή `this` στον ορισμό), και το όνομα της μεθόδου μπαίνει με τελεία πάνω στο στιγμιότυπο για να την καλέσεις:

```ruby
irb(main):004:0> "abc".sub("b", "*")
=> "a*c"
```

Αυτό ονομάζεται [`single dispatch`][single-dispatch], καθώς μόνο η κλάση του στιγμιότυπου (της συμβολοσειράς "abc" στο παραπάνω παράδειγμα) χρησιμοποιείται για να επιλεγεί μια μέθοδος.

Κάποιες στατικά τυποποιημένες αντικειμενοστρεφείς γλώσσες υποστηρίζουν πολυμορφισμό μεθόδων, ο οποίος μοιάζει κάπως με την πολλαπλή αποστολή.
Η μεγάλη διαφορά είναι ότι η επιλογή μεθόδου συμβαίνει μόνο σε _χρόνο μεταγλώττισης_.

Οι συναρτησιακές γλώσσες τείνουν να έχουν μόνο έναν ορισμό συνάρτησης, με κάποια έκφραση Select/Case/Match για να χειρίζεται τις διάφορες περιπτώσεις.
Γράφεις τη δική σου λογική, συνήθως βοηθούμενος από μια συνοπτική σύνταξη αντιστοίχισης προτύπων που απουσιάζει από τη Julia.
Φυσικά, η Julia κάνει επίσης μια μορφή αντιστοίχισης προτύπων, αλλά κατά την αποστολή και όχι μέσα στο σώμα της συνάρτησης.

## Συμπέρασμα

Η πολλαπλή αποστολή είναι πολύ ευέλικτη και εξαιρετικά αποδοτική στη Julia, οπότε χρησιμοποιείται ευρέως.

Όπως υποδηλώνει το παράδειγμα των 161 μεθόδων για το `+`, οι προγραμματιστές της Julia στοχεύουν να ορίζουν μεθόδους με στενά καθορισμένους τύπους.
Η πρόσθεση δύο ακεραίων είναι πολύ διαφορετική από την πρόσθεση δύο αριθμών κινητής υποδιαστολής στο επίπεδο του bytecode, και η πρόσθεση ενός ακεραίου σε έναν αριθμό κινητής υποδιαστολής προσθέτει μια επιπλέον επιπλοκή προαγωγής τύπου.

Όσο πιο συγκεκριμένος ο τύπος, τόσο περισσότερη βελτιστοποίηση μπορεί να κάνει ο μεταγλωττιστής: ελάχιστης σημασίας σε μια απλή άσκηση στο Exercism, αλλά ζωτικής σημασίας για την απόδοση στις μεγάλες αριθμητικές προσομοιώσεις για τις οποίες έχει σχεδιαστεί η Julia.

_Αν ξέρεις τι εισόδους θα λάβει μια μέθοδος, πες το στον μεταγλωττιστή!_
