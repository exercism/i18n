# Σχετικά

## const

Ο τροποποιητής `const` μπορεί (και γενικά θα πρέπει) να εφαρμοστεί σε οποιοδήποτε πεδίο του οποίου η τιμή είναι γνωστή κατά τον χρόνο μεταγλώττισης και δε θα αλλάξει κατά τη διάρκεια ζωής του προγράμματος.

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

Ο μεταγλωττιστής θα σε καθοδηγήσει ως προς το ποιες εκφράσεις μπορούν να αξιολογηθούν κατά τον χρόνο μεταγλώττισης. Απλές αριθμητικές πράξεις επιτρέπονται, όπως και η συνένωση συμβολοσειρών. Αυτό αποκλείει οποιαδήποτε αξιολόγηση που θα απαιτούσε χρήση του σωρού ή της στοίβας, οπότε όλες οι κλήσεις μεθόδων και οι αναφορές σε μη πρωτογενείς τύπους δεν είναι διαθέσιμες.

Υπάρχει κάποια συζήτηση στο διαδίκτυο για τα πλεονεκτήματα απόδοσης του `const` έναντι των μεταβλητών. Στην περίπτωση σύγκρισης με πεδία στιγμιοτύπου που δεν είναι `const`, θα μπορούσε να υπάρξει αξιοσημείωτη εξοικονόμηση μνήμης, αλλά σε σύγκριση με στατικές μεταβλητές αυτό είναι σαφώς αμελητέο. Οποιαδήποτε σκέψη για την απόδοση του επεξεργαστή είναι πιθανό να θεωρηθεί από τους συναδέλφους σου ως [πρόωρη βελτιστοποίηση][premature-optimization].

Ένας πιο πειστικός λόγος για να χρησιμοποιήσεις `const` είναι ότι ενισχύει την ικανότητα του συντηρητή να συλλογίζεται τον κώδικα. Βλέποντας ότι ένα πεδίο είναι σημειωμένο ως `const` ή `readonly` ή ότι μια ιδιότητα δεν έχει setter, ο συντηρητής μπορεί σε μεγάλο βαθμό να το αγνοήσει στην ανάλυσή του. Είναι απίθανο να αποτελεί εστία bugs. Είναι απίθανο να προκαλέσει δυσκολίες σε μια εργασία αναδιαμόρφωσης. Αυτό το [σχόλιο στο Stack Overflow][so-consts] το εξηγεί.

Ο τροποποιητής `const` μπορεί επίσης να εφαρμοστεί σε τιμές μέσα σε μεθόδους:

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

Το να προσδιορίσεις μια τιμή με `const` με αυτόν τον τρόπο μπορεί να είναι χρήσιμο αν χρησιμοποιείται πολλές φορές μέσα στη μέθοδο ή αν θέλεις να επιστήσεις την προσοχή στη σημασία της. Δεν υπάρχει κέρδος στην απόδοση σε σχέση με τη χρήση κυριολεκτικών τιμών ενσωματωμένων στον κώδικα.

## readonly

Ο τροποποιητής [`readonly`][readonly-fields] μπορεί (και γενικά θα πρέπει) να εφαρμοστεί σε οποιοδήποτε πεδίο που δε μπορεί να γίνει `const`, όταν η τιμή του δε θα αλλάξει κατά τη διάρκεια ζωής του προγράμματος και είτε ορίζεται από έναν ενσωματωμένο αρχικοποιητή είτε κατά τη δημιουργία στιγμιοτύπου (από τον κατασκευαστή ή από μια μέθοδο που καλεί ο κατασκευαστής).

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

Η χρήση του τροποποιητή `readonly` ενθαρρύνεται για τους ίδιους λόγους που ισχύουν και για το `const`. Η πρακτική του περιορισμού των πεδίων με αυτόν τον τρόπο βοηθά τους συντηρητές να συλλογίζονται τον κώδικα.

Σημείωσε ότι η προσθήκη του τροποποιητή `readonly` σε ένα πεδίο εμποδίζει μόνο την αλλαγή της τιμής του πεδίου. Στην περίπτωση σύνθετων τύπων, δεν προστατεύει τα πεδία ή τις ιδιότητες αυτού του τύπου. Ειδικότερα, δεν προστατεύει τα περιεχόμενα των πινάκων.

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

Για να διασφαλίσεις ότι όλα τα μέλη ενός τύπου αναφοράς προστατεύονται, μπορείς να κάνεις τα πεδία `readonly` και να ορίσεις αυτόματες ιδιότητες χωρίς προσπελαστήρα `set`.

Θα πρέπει να εξετάσεις τις [συλλογές μόνο για ανάγνωση][readonly-collections] στη Βιβλιοθήκη Βασικών Κλάσεων.

Για τους πίνακες, ό,τι πιο κοντινό μπορείς να έχεις σε έκδοση μόνο για ανάγνωση είναι η μέθοδος [`Array.AsReadOnly<T>()`][as-read-only].
