# Σχετικά

Στις προηγούμενες έννοιες, αναφέρθηκε ότι η οδηγία `global` κάνει μια συνάρτηση ή μεταβλητή που ορίζεται σε ένα αρχείο πηγαίου κώδικα ορατή σε άλλα αρχεία.
Παρομοίως, η οδηγία `extern` ενημερώνει τον assembler ότι μια συνάρτηση ή μεταβλητή που χρησιμοποιείται στο τρέχον αρχείο πηγαίου κώδικα ορίζεται σε κάποιο άλλο.

Αυτές οι δύο οδηγίες είναι ο κύριος τρόπος με τον οποίο ο κώδικας assembly συνεργάζεται με άλλα αρχεία πηγαίου κώδικα για να επιτευχθεί η αρθρωτότητα.

Για τους σκοπούς αυτών των οδηγιών, δεν έχει σημασία αν ο εξωτερικός κώδικας ορίζεται ή χρησιμοποιείται σε assembly ή σε μια γλώσσα υψηλού επιπέδου.
Έτσι, για παράδειγμα, ακόμη και μια συνάρτηση που ορίζεται σε μια γλώσσα υψηλού επιπέδου μπορεί να χρησιμοποιηθεί σε κώδικα x86-64, αν δηλωθεί ως `extern`.

Με τον ίδιο τρόπο, η σύμβαση κλήσης είναι κοινή για όλες αυτές τις συναρτήσεις, είτε ορίζονται σε assembly είτε σε γλώσσες υψηλού επιπέδου, ακόμη και με το λειτουργικό σύστημα (OS).

Ωστόσο, επειδή στην assembly τα δεδομένα είναι απλώς μια ακολουθία από bytes, είναι σημαντικό να γνωρίζεις πώς η γλώσσα υψηλού επιπέδου με την οποία συνεργάζεσαι διαχειρίζεται τη μνήμη.

## Τύποι στη C

Η γλώσσα C είναι μια συνηθισμένη επιλογή ως γλώσσα υψηλού επιπέδου για διασύνδεση με κώδικα assembly.
Κάνει το έργο της αλληλεπίδρασης με το λειτουργικό σύστημα ευκολότερο, προσφέροντας wrappers υψηλού επιπέδου για πολλές σημαντικές εργασίες, όπως την εκτύπωση στην οθόνη, την ανάγνωση από το πληκτρολόγιο ή τη δέσμευση δυναμικής μνήμης.

Σε αυτό το track, οι δοκιμές είναι γραμμένες σε C, οπότε είναι σημαντικό να δώσουμε μια γενική επισκόπηση της γλώσσας.

~~~~exercism/note
Οποιοσδήποτε από τους τύπους που αναφέρονται παρακάτω μπορεί να χαρακτηριστεί με `const`.
Αυτό τους κάνει μόνο για ανάγνωση.
~~~~

### Πρωτόγονοι τύποι

Υπάρχουν πολλοί πρωτόγονοι τύποι στη C και το μέγεθός τους, σε bytes, μπορεί να ποικίλλει.
Κάποιοι από αυτούς συνοψίζονται στον παρακάτω πίνακα, με το τυπικό τους μέγεθος σε ένα σύστημα x86-64:

| τύπος     | αριθμός bytes | ακέραιος/κινητής υποδιαστολής |
|-----------|-----------------|------------------------|
| _Bool     | 1               | ακέραιος                |
| char      | 1               | ακέραιος                |
| short     | 2               | ακέραιος                |
| int       | 4               | ακέραιος                |
| long      | 4 ή 8           | ακέραιος                |
| long long | 8               | ακέραιος                |
| float     | 4               | κινητής υποδιαστολής         |
| double    | 8               | κινητής υποδιαστολής         |

Καθένας από αυτούς τους ακέραιους τύπους μπορεί να είναι signed (η προεπιλογή) ή unsigned.
Στην περίπτωση που είναι unsigned, αυτό πρέπει να δηλωθεί, για παράδειγμα: `unsigned int`.

Υπάρχουν ψευδώνυμα για τους ακέραιους τύπους, που ορίζονται για να παρέχουν ακριβή έλεγχο του μεγέθους τους:

| ψευδώνυμο   | αριθμός bytes |
|---------|-----------------|
| int8_t  | 1               |
| int16_t | 2               |
| int32_t | 4               |
| int64_t | 8               |

Αυτά τα ψευδώνυμα μπορούν να έχουν το πρόθεμα `u` για να δηλώσουν έναν τύπο unsigned, για παράδειγμα: `uint64_t`.

Άλλα αξιοσημείωτα ψευδώνυμα είναι:

| ψευδώνυμο  | τύπος                                          |
|--------|-----------------------------------------------|
| bool   | _Bool                                         |
| size_t | συνήθως ένας unsigned ακέραιος 8 bytes            |

Ένα `_Bool`, ή το ψευδώνυμό του `bool`, έχει την ιδιαιτερότητα ότι, αν και καταλαμβάνει 1 ολόκληρο byte, μπορεί να πάρει μόνο μία από δύο τιμές: `true` (`1`) και `false` (`0`).

Οι τιμές αυτών των πρωτόγονων τύπων περνούν ως ορίσματα σε συναρτήσεις και επιστρέφονται από αυτές σύμφωνα με τους συνήθεις κανόνες για ακέραιους και τιμές κινητής υποδιαστολής.

### Απαριθμήσεις

Ένα [enum][enum] είναι ένας τύπος που μπορεί να πάρει ένα από έναν αριθμό ρητά δηλωμένων στοιχείων:

```c
enum example {
    example_1,
    example_2,
    example_3,
    example_4
};
```

Στη C, οι enum μετατρέπονται σιωπηρά σε έναν ακέραιο τύπο, που συνήθως είναι `int`, δηλαδή ένας ακέραιος 4 bytes.

Από προεπιλογή, το πρώτο δυνατό στοιχείο σε ένα enum μετατρέπεται σε `0` και όλα τα επόμενα στοιχεία μετατρέπονται στον επόμενο ακέραιο.
Έτσι, στο `enum example` που ορίστηκε παραπάνω, το `example_1` θα είχε την τιμή `0`, το `example_2` θα είχε την τιμή `1` και ούτω καθεξής.

Είναι δυνατό να δηλώσεις την τιμή για οποιοδήποτε στοιχείο ενός enum και τότε, από προεπιλογή, το επόμενο στοιχείο θα έχει ως τιμή τον επόμενο ακέραιο:

```c
enum example_2 {
    example_1 = 4,
    example_2 = 8,
    example_3
}; // example_3 is equal to 9
```

### Διευθύνσεις μνήμης

Στη C, μια διεύθυνση μνήμης αναφέρεται μέσω ενός [δείκτη][pointer] σε έναν τύπο και συμβολίζεται με τον τελεστή `*`.
Έτσι, για παράδειγμα, το `int64_t *` αναφέρεται σε μια θέση μνήμης για ένα ή περισσότερα `int64_t`.

Οι διευθύνσεις αντιμετωπίζονται ως ακέραιοι 8 bytes, όπως συνήθως.

### Πίνακες

Οι πίνακες περνούν σε συναρτήσεις και επιστρέφονται από αυτές ως δείκτες στο πρώτο τους στοιχείο.

```c
int64_t example_arr[] = {1, 2, 3}; // this is an array of 3 signed 8-byte integers
fn(example_arr); // this is a function that passes a pointer (int64_t *) to the beginning of the array as argument
```

Κάθε στοιχείο σε έναν πίνακα έχει το μέγεθος του τύπου στοιχείου του πίνακα.
Το `example_arr` που ορίστηκε παραπάνω, για παράδειγμα, έχει 3 στοιχεία των 8 bytes το καθένα, δηλαδή 24 bytes συνολικά.

Επειδή οι πίνακες δεν αποθηκεύουν το μήκος τους, συνήθως χρειάζεται μια ξεχωριστή τιμή που να δηλώνει τον αριθμό των στοιχείων, εκτός αν μια τιμή-φρουρός σηματοδοτεί το τέλος.

### Συμβολοσειρές

Οι συμβολοσειρές στη C είναι ένας πίνακας από `char`, που είναι ένας τύπος 1 byte.
Οι περισσότερες συμβολοσειρές αποτελούνται από χαρακτήρες ASCII και τερματίζονται με NUL, οπότε τελειώνουν όταν βρεθεί ένα byte με την τιμή `0`.
Αυτό σημαίνει ότι το μήκος μιας συμβολοσειράς συνήθως δεν χρειάζεται να περαστεί ως ξεχωριστό όρισμα.

## Κλήση συναρτήσεων της βιβλιοθήκης C

Η οδηγία `extern` δηλώνει μόνο ότι ένα σύμβολο ορίζεται σε ένα άλλο αρχείο.
Το πώς γίνεται πραγματικά μια κλήση σε αυτό εξαρτάται από το πώς συνδέεται αυτός ο εξωτερικός κώδικας.

Για συνηθισμένες συναρτήσεις που συνδέονται μαζί με τον κώδικά σου, ο linker μπορεί να βρει απευθείας μια εξωτερική συνάρτηση, οπότε αρκεί ένα απλό `call`.

Ωστόσο, οι συναρτήσεις της πρότυπης βιβλιοθήκης C, όπως οι `malloc`, `free` και `printf`, συνήθως επιλύονται κατά τον χρόνο εκτέλεσης από μια κοινόχρηστη βιβλιοθήκη, της οποίας η διεύθυνση δεν είναι γνωστή όταν συναρμολογείται ο κώδικάς σου.
Η κλήση λοιπόν περνά μέσα από ένα stub σε έναν [Procedure Linkage Table (PLT)][plt], που βρίσκεται σε γνωστή μετατόπιση.
Όποτε καλείς μια εξωτερική συνάρτηση βιβλιοθήκης από assembly, ο NASM απαιτεί μια ένδειξη ότι αυτή η κλήση πρέπει να επιλυθεί από τον PLT.

Στο `elf64` (μορφότυπο εξόδου που χρησιμοποιούν τα προγράμματα Linux), αυτή η ένδειξη γίνεται προσθέτοντας `wrt ..plt` ("with reference to plt") μετά την κλήση.
Για παράδειγμα, `call printf wrt ..plt`.

Σε προγράμματα `macho64` (μορφότυπο εξόδου που χρησιμοποιούν τα προγράμματα macOS), από την άλλη, αρκεί μια κάτω παύλα πριν από το όνομα της συνάρτησης.
Για παράδειγμα, `extern _printf` και μετά `call _printf`.
Ωστόσο, επειδή αυτό το track συναρμολογεί κώδικα `macho64` με το flag `--prefix _`, αυτή η κάτω παύλα προστίθεται αυτόματα από τον assembler και στις δύο περιπτώσεις, για παράδειγμα `extern printf` και μετά `call printf`.

Σημείωσε ότι ο test-runner του Exercism εκτελείται σε ένα image Linux, οπότε οποιαδήποτε λύση υποβάλλεται και καλεί συναρτήσεις της βιβλιοθήκης C πρέπει να χρησιμοποιεί `wrt ..plt`.
Μπορεί να χρησιμοποιηθεί ένας έλεγχος σε επίπεδο assembler για να γίνεται σωστά η διάκριση ανάμεσα στα μορφότυπα εξόδου:

```x86asm
extern malloc

%ifidn __OUTPUT_FORMAT__,elf64
    call malloc wrt ..plt       ; elf64: reach the function through the PLT
%else
    call malloc                 ; macho64: the linker generates the call stub
                                ; the underscore is added automatically by an assembler flag
%endif
```

## Κλήσεις συστήματος

Υπάρχουν πολλές λειτουργίες που τα προγράμματα σε επίπεδο χρήστη, όπως αυτά που εκτελούνται σε αυτό το track, δεν μπορούν να εκτελέσουν απευθείας.
Η ανάγνωση από το `stdin`, η εγγραφή στο `stdout`, η δέσμευση δυναμικής μνήμης, η αλληλεπίδραση με περιφερειακά κ.λπ. γίνονται όλα από το λειτουργικό σύστημα (OS).

Ένα πρόγραμμα σε επίπεδο χρήστη πρέπει να ζητά ρητά από το λειτουργικό σύστημα να εκτελέσει αυτές τις λειτουργίες, όταν χρειάζεται.
Αυτό γίνεται με την εντολή [`syscall`][syscall].
Εννοιολογικά, αυτή η εντολή μπορεί να θεωρηθεί ως κλήση σε κάποια προκαθορισμένη διαδικασία του λειτουργικού συστήματος (μια κλήση "συστήματος").

Οποιοδήποτε όρισμα για την κλήση συστήματος πρέπει να περαστεί στο λειτουργικό σύστημα σε GPRs: `rdi`, `rsi`, `rdx`, `r10`, `r8` και `r9`.

Σημείωσε ότι η σειρά είναι σχεδόν ίδια με αυτή που χρησιμοποιείται σε μια κλήση συνάρτησης, αλλά το `rcx` αντικαθίσταται από το `r10`.
Αυτό συμβαίνει επειδή το `rcx` και το `r11` χρησιμοποιούνται από το `syscall` για να αποθηκεύσουν τη διεύθυνση επιστροφής και τα flags (που επαναφέρονται πριν επιστρέψει ο έλεγχος στη συνάρτηση που έκανε την κλήση).
Και οι δύο καταχωρητές πρέπει να θεωρούνται αλλοιωμένοι σε κάθε `syscall`.

Σε αντίθεση με το `call`, δεν υπάρχουν ετικέτες που να δείχνουν τις "συναρτήσεις" του συστήματος.
Αντ' αυτού, προσεγγίζονται μέσω συγκεκριμένων αριθμών που τοποθετούνται στο `rax` πριν από την κλήση.
Οποιαδήποτε τιμή επιστροφής, αν υπάρχει, τοποθετείται επίσης στο `rax`.

Οι παραπάνω συμβάσεις περιγράφονται [σε ένα παράρτημα του System V ABI][linux-convention] που αφορά ειδικά το Linux και χαρακτηρίζεται ως ενημερωτικό μόνο.
Στην πράξη, οι διαθέσιμες κλήσεις συστήματος, ο αριθμός τους και ο τρόπος με τον οποίο αναφέρονται τα σφάλματα είναι λεπτομέρειες σε επίπεδο λειτουργικού συστήματος που διαφέρουν πολύ από σύστημα σε σύστημα, ακόμη και ανάμεσα σε διαφορετικές εκδόσεις του ίδιου λειτουργικού συστήματος.

Πολλές συναρτήσεις της βιβλιοθήκης C, και άλλες πραγματικές συναρτήσεις που ορίζει το λειτουργικό σύστημα, είναι wrappers υψηλότερου επιπέδου πάνω από μια κλήση συστήματος.
Το ABI συνιστά να προτιμώνται αυτά τα wrappers έναντι ενός απλού `syscall`, και η Apple [δεν εγγυάται συμβατότητα][mac-qa1118] στη διεπαφή κλήσεων συστήματος του πυρήνα.
