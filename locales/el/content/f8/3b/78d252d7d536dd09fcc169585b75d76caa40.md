# Εισαγωγή

Η μνήμη συνήθως αντιστοιχίζεται για ένα πρόγραμμα από το Λειτουργικό Σύστημα (OS) σε μια γενική διάταξη:

| διεύθυνση | περιοχή μνήμης          |
| :-----: | :--------------------- |
|  υψηλή   | στοίβα                  |
|         | ...                    |
|         | σωρός                   |
|         | τμήμα ανάγνωσης-εγγραφής |
|         | τμήμα κώδικα/μόνο για ανάγνωση |
|   χαμηλή   | δεσμευμένη               |

Η μνήμη σε τμήματα οργανώνεται σε τομείς, με διαφορετικά δικαιώματα.

Οι συναρτήσεις που έχουμε ορίσει μέχρι τώρα βρίσκονταν όλες στον **τομέα .text**.
Αυτός ο τομέας περιέχει εκτελέσιμα δεδομένα μόνο για ανάγνωση.
Άλλοι τομείς χρησιμοποιούνται για να δηλώσεις μεταβλητές δεδομένων, οι οποίες μπορεί να είναι μόνο για ανάγνωση ή για ανάγνωση και εγγραφή, αλλά δεν είναι εκτελέσιμες.

## Ο τομέας .data

Τα αρχικοποιημένα δεδομένα δηλώνονται στον **τομέα .data**.

Στον NASM (The Netwide Assembler, τον συμβολομεταφραστή που χρησιμοποιεί αυτό το track), μια αρχικοποιημένη μεταβλητή έχει ένα όνομα, μια οδηγία που δηλώνει το μέγεθος των δεδομένων και μια λίστα τιμών χωρισμένων με κόμμα.
Καθένα από αυτά χωρίζεται από το άλλο με ένα κενό και η ετικέτα μπορεί προαιρετικά να ακολουθείται από `:`.

Οι κυριότερες οδηγίες και τα αντίστοιχα μεγέθη δεδομένων είναι:

| οδηγία | μέγεθος    |
| :-------: | :------ |
|    db     | 1 byte  |
|    dw     | 2 bytes |
|    dd     | 4 bytes |
|    dq     | 8 bytes |

Για παράδειγμα, αυτό δηλώνει μια μεταβλητή ενός byte με το όνομα `space` και την τιμή `10`:

```x86asm
section .data
    space db 10
```

Οι μεταβλητές που δηλώνονται στο `section .data` είναι τροποποιήσιμες, δηλαδή μπορούν να διαβαστούν και να τροποποιηθούν.
Έχουν επίσης _στατική_ διάρκεια αποθήκευσης, που σημαίνει ότι υπάρχουν για όλη τη διάρκεια εκτέλεσης του προγράμματος.

## Ο τομέας .rodata

Ο **τομέας .rodata** είναι παρόμοιος με το `section .data`.
Και οι δύο τομείς περιέχουν αρχικοποιημένα δεδομένα, τα οποία δηλώνονται με τον ίδιο τρόπο και έχουν την ίδια διάρκεια αποθήκευσης.

Η κύρια διαφορά τους είναι ότι τα δεδομένα στο `section .rodata` είναι μη τροποποιήσιμα, δηλαδή μόνο για ανάγνωση.

~~~~exercism/note
Οι σταθερές που ορίζονται με `equ` είναι διαφορετικές από εκείνες που ορίζονται στο `section .rodata`.

Μια σταθερά που ορίζεται με `equ` δεν καταλαμβάνει χώρο στη μνήμη και ο συμβολομεταφραστής την αντικαθιστά απευθείας με την τιμή της.
Στην πραγματικότητα, είναι ένα υποκατάστατο αυτής της τιμής.

Αντίθετα, οι σταθερές που ορίζονται στο `section .rodata` αποθηκεύονται πραγματικά στη μνήμη και έχουν διεύθυνση.
~~~~

## Πρόσβαση στα δεδομένα

### Ετικέτες και έμμεση προσπέλαση

Τα δεδομένα που δηλώνονται πρέπει να έχουν ένα όνομα συνδεδεμένο με αυτά.
Αυτό το όνομα ονομάζεται **ετικέτα**.

Μια ετικέτα είναι ένα σύμβολο που κωδικοποιεί τη συγκεκριμένη διεύθυνση των δεδομένων στη μνήμη.
**Οι διευθύνσεις στο x86-64 είναι τιμές 64 bit**.

Στον NASM, αν προσπαθήσεις να προσπελάσεις δεδομένα απευθείας με την ετικέτα τους, δεν παίρνεις τη δεσμευμένη μνήμη, αλλά τη διεύθυνσή τους:

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

Για να προσπελάσεις τα περιεχόμενα μιας διεύθυνσης μνήμης, πρέπει να κάνεις _αποαναφορά_ σε αυτήν.
Αυτό ονομάζεται **έμμεση προσπέλαση**.

Στον NASM, αυτό γίνεται με `[]`:

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

Ωστόσο, υπάρχουν περιπτώσεις όπου μπορεί να υπάρξει ασάφεια ως προς το μέγεθος της μνήμης στην οποία γίνεται η αποαναφορά.
Σε αυτές τις περιπτώσεις, πρέπει να χρησιμοποιηθεί ένα πρόθεμα που προσδιορίζει αυτό το μέγεθος.

Αυτά είναι τα σημαντικότερα προθέματα και τα μεγέθη τους σε ένα τυπικό πρόγραμμα x86-64:

| πρόθεμα | μέγεθος    |
| :----- | :------ |
| byte   | 1 byte  |
| word   | 2 bytes |
| dword  | 4 bytes |
| qword  | 8 bytes |

Η ίδια φόρτωση μπορεί να γραφτεί με το μέγεθος να δηλώνεται ρητά:

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

Είναι καλή πρακτική να χρησιμοποιείς πάντα ένα πρόθεμα όταν κάνεις αποαναφορά μνήμης.

### Εγγραφή στη μνήμη

Η εγγραφή στη μνήμη γίνεται με τον ίδιο τρόπο, κάνοντας αποαναφορά μιας διεύθυνσης:

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

Σημείωσε ότι μπορείς να χρησιμοποιήσεις τελεστέους μνήμης στις περισσότερες εντολές χωρίς πρώτα να φορτώσεις τα περιεχόμενα σε έναν καταχωρητή.
Ωστόσο, συνήθως δεν είναι δυνατό να τους χρησιμοποιήσεις και στον τελεστέο πηγής και στον τελεστέο προορισμού, μόνο σε έναν από τους δύο:

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### Η εντολή LEA

Αν και μπορείς να χρησιμοποιήσεις τη `mov` για να αποθηκεύσεις τη διεύθυνση μιας μεταβλητής σε έναν καταχωρητή, υπάρχει μια εντολή με αυτόν τον συγκεκριμένο σκοπό: **lea**.

Αυτή η εντολή χρησιμοποιεί έναν τελεστέο σε μορφή μνήμης, αλλά _δε_ διαβάζει τη μνήμη.
Αντ' αυτού, υπολογίζει την παράσταση της ενεργού διεύθυνσης και γράφει το αποτέλεσμα στον τελεστέο προορισμού:

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

Είναι πιο ιδιωματικό να χρησιμοποιείς τη `lea` για να υπολογίζεις και να αποθηκεύεις διευθύνσεις μνήμης σε καταχωρητές.

### Σχετική διευθυνσιοδότηση

Όταν προσπελαύνεις θέσεις μνήμης, η προεπιλεγμένη συμπεριφορά στον NASM είναι να παράγει **απόλυτες διευθύνσεις**, δηλαδή σταθερές διευθύνσεις μνήμης.

Για λόγους ασφάλειας, τα εκτελέσιμα συχνά κατασκευάζονται ως **PIE (Position Independent Executable, δηλαδή εκτελέσιμο ανεξάρτητο θέσης)**, όπου οι περιοχές μνήμης τοποθετούνται σε τυχαίες θέσεις.
Σε ένα `PIE`, η τελική διεύθυνση μιας μεταβλητής δεν είναι γνωστή τη στιγμή της σύνδεσης.
Έτσι, ο κώδικας υπολογίζει τις διευθύνσεις ως μετατόπιση από την τιμή ενός ειδικού καταχωρητή που ονομάζεται `rip`, ο οποίος δείχνει στην επόμενη εντολή που θα εκτελεστεί.

Αυτό συνήθως ονομάζεται **διευθυνσιοδότηση σχετική με τον RIP**.

Στον NASM μπορείς να ζητήσεις πρόσβαση σχετική με τον RIP με τον τελεστή `rel`:

```x86asm
mov rax, qword [rel variable]
```

Η σχετική διευθυνσιοδότηση μπορεί επίσης να γίνει η προεπιλογή για ένα αρχείο πηγαίου κώδικα με `default rel` στην αρχή.

Όλες οι ασκήσεις σε αυτό το track μεταγλωττίζονται και συνδέονται ως `PIE`, οπότε θα πρέπει να χρησιμοποιείς το `rel` για να παράγεις σχετικές διευθύνσεις.

### Ορατότητα

Οι ετικέτες (συναρτήσεις και δεδομένα) που ορίζονται σε οποιονδήποτε τομέα (π.χ. `.text`, `.data`, `.rodata`) είναι ορατές μέσα στο ίδιο αρχείο πηγαίου κώδικα.
Αν δηλωθούν ως `global`, είναι ορατές και σε άλλα αρχεία πηγαίου κώδικα.

Αντίστροφα, οι ετικέτες που ορίζονται σε άλλα αρχεία πηγαίου κώδικα είναι ορατές στο τρέχον αρχείο πηγαίου κώδικα αν δηλωθούν ως `extern`.
Σε αυτή την περίπτωση, δεν υπάρχει ένδειξη για το μέγεθος των δεδομένων στη γλώσσα assembly, οπότε αυτό πρέπει να είναι γνωστό εκ των προτέρων.

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
