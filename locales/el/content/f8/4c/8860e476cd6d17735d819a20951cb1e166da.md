# Σχετικά

## Οι Boolean στην Julia

Οι τιμές αληθής ή ψευδής αναπαρίστανται από τον τύπο `Bool`.
Περιέχει μόνο δύο τιμές: `true` και `false`.

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

Σε αντίθεση με αρκετές άλλες γλώσσες, η Julia δεν έχει σκόπιμα την έννοια του "truthiness", και μόνο οι εκφράσεις που αξιολογούνται σε `true` ή `false` αντιμετωπίζονται ως `Bool`.

Συγκεκριμένα, κενοί πίνακες ή συμβολοσειρές *δεν* θα ερμηνεύονται ως `false`.
Αν θέλεις ειδικό χειρισμό για κενές τιμές, πρέπει να κάνεις έναν κατάλληλο έλεγχο, όπως με το `isempty()`.

## Τελεστές Boolean

Υπάρχουν τρεις [τελεστές Boolean][boolean-operators] στην Julia.

Το `&&` είναι το λογικό "και".
Αξιολογείται σε `true` αν οι εκφράσεις και στις *δύο* πλευρές του `&&` είναι `true`.

```julia-repl
julia> true && true
true

julia> true && false
false
```

Το `||` είναι το λογικό "ή".
Αξιολογείται σε `true` αν μια έκφραση σε *οποιαδήποτε* πλευρά του `||` είναι `true`.

```julia-repl
julia> true || true
true

julia> false || true
true
```

Το `!` είναι το λογικό "όχι".
Ανταλλάσσει (αντιστρέφει) τις τιμές `true` και `false`.

```julia-repl
julia> !true
false

julia> !false
true
```

Παρόμοιοι τελεστές θα είναι εννοιολογικά οικείοι σε χρήστες πολλών άλλων γλωσσών, αν και η ακριβής σύνταξη μπορεί να διαφέρει από γλώσσα σε γλώσσα.

## Προτεραιότητα τελεστών

Σε πιο σύνθετες εκφράσεις, μπορεί να σου φανεί χρήσιμο να ξέρεις ότι το `&&` έχει ελαφρώς υψηλότερη [προτεραιότητα][operator-precedence] από το `||` *(με τον ίδιο τρόπο που το `*` εφαρμόζεται πριν από το `+` στις αριθμητικές εκφράσεις)*.

Το να βασίζεσαι σε αυτό μπορεί να είναι μπερδεμένο και επιρρεπές σε λάθη.
Για λόγους σαφήνειας, χρησιμοποίησε παρενθέσεις για να γίνει ξεκάθαρη η πρόθεσή σου.

## Αξιολόγηση βραχυκυκλώματος

Εξαρτάται η έκφραση `true || x` από την τιμή του `x`, ή μπορεί ο μεταγλωττιστής να αγνοήσει το `x`;

Η Julia αξιολογεί τις εκφράσεις Boolean από αριστερά προς τα δεξιά και σταματά όταν έχει ένα σαφές αποτέλεσμα.

Για παράδειγμα, το `true || x` πρέπει να είναι `true`, ανεξάρτητα από το `x`, οπότε το `x` δεν αξιολογείται.
Παρόμοια, το `false && y` είναι `false`, χωρίς να χρειάζεται να αξιολογηθεί το `y`.

Αντίστροφα, το `true && x` είναι `true` *μόνο αν* το `x` είναι `true`, οπότε το `x` πρέπει να αξιολογηθεί.

Παρόμοια, αν συνδυάσουμε πολλούς τελεστές:

```julia-repl
julia> true && false && something_else
false
```

Επειδή το `true && false` πρέπει να είναι `false`, το `something_else` δεν έχει σημασία και αγνοείται από τον μεταγλωττιστή.

Σε αυτή την περίπτωση, το `something_else` δεν υπήρχε ως μεταβλητή, αλλά η συμπερίληψή του σε αυτό το πλαίσιο δεν έδωσε σφάλμα *(δοκίμασέ το στο REPL αν δεν το πιστεύεις)*.

Αυτού του είδους η αξιολόγηση βραχυκυκλώματος χρησιμοποιείται αρκετά συχνά από προγραμματιστές της Julia ως ένας σύντομος τρόπος για να πιάνουν προβλήματα χρόνου εκτέλεσης και οριακές περιπτώσεις:

```julia
all_ok || do_something()

is_problem && do_something_else()
```

Για παράδειγμα, το `do_something` μπορεί να είναι μια πρόωρη `return` από τη συνάρτηση αν το `all_ok` είναι `false`, ή η ανάθεση μιας προεπιλεγμένης τιμής σε μια μεταβλητή πριν συνεχίσει.

Αυτή είναι μια μικρή κατάχρηση της σύνταξης Boolean, αλλά μπορεί να είναι πολύ βολική.

## Πώς λειτουργούν εσωτερικά τα Bool

Αν ένα Bool συμπεριληφθεί σε μια *αριθμητική* έκφραση, το `true` ερμηνεύεται ως `1` και το `false` ως `0`, αντανακλώντας τον τρόπο με τον οποίο αποθηκεύονται.

Αν είσαι συνηθισμένος σε γλώσσες χαμηλότερου επιπέδου (C και παρόμοιες), *σε παρακαλώ* απόφευγε να το χρησιμοποιείς συχνά.
Θα μειώσει την αναγνωσιμότητα του κώδικα και θα κάνει το debugging πιο δύσκολο.

Μπορεί μερικές φορές να δεις τις αριθμητικές τιμές να χρησιμοποιούνται ως ένας γρήγορος τρόπος για να μετρήσεις πόσα πράγματα είναι `true`.

```julia-repl
julia> true + false + true
2
```
