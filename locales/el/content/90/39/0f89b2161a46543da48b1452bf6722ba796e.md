# Τα βασικά της Unison

## Όροι και συναρτήσεις

Οι όροι και οι συναρτήσεις είναι οι βασικές μονάδες για να γράψεις ένα πρόγραμμα σε Unison.

Ένας "όρος" είναι αυτό που ονομάζουμε στατική τιμή. Ορίζεται με `name = expression`, και προαιρετικά μπορεί να προηγείται μια υπογραφή τύπου με τη μορφή `name : MyType`. Η Unison υποστηρίζει εξαγωγή τύπων, οπότε σε απλούς ορισμούς μπορεί να δεις την υπογραφή τύπου να παραλείπεται.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Οι συναρτήσεις της Unison έχουν τη μορφή `myFunctionName argument1 argument2 = myImplementation`· ξεκινούν με το όνομα της συνάρτησης και συνεχίζουν με τα ορίσματα χωρισμένα με κενό.

```
getMax a b = Nat.max a b
```

Οι συναρτήσεις μπορούν προαιρετικά να περιλαμβάνουν υπογραφή τύπου. Ο τελευταίος τύπος στα δεξιά είναι πάντα ο τελικός τύπος επιστροφής της συνάρτησης, και κάθε όρισμα χωρίζεται με το βέλος συνάρτησης `->`.

```
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Για να καλέσεις μια συνάρτηση, χρησιμοποίησε το όνομά της και μετά τα ορίσματά της, χωρισμένα μόνο με κενά.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Όταν καλείς μια συνάρτηση, η Unison θα προσπαθήσει να θεωρήσει ως όρισμά της ό,τι βρίσκεται αμέσως δεξιά, κάτι που δε δίνει πάντα τη σειρά αξιολόγησης που θέλεις.

Ας πούμε ότι θέλουμε να πάρουμε την τιμή `1` από την παρακάτω έκφραση

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

Όπως είναι γραμμένο, το `shouldBe1` αξιολογείται σε `0`, γιατί η υπονοούμενη σειρά εφαρμογής της συνάρτησης είναι `getMax 1 10`, που δίνει `10`, και μετά `10 - 10`, που δίνει `0`.

Μπορείς να χρησιμοποιήσεις παρενθέσεις για να ανασυγκροτήσεις την έκφραση στη σειρά πράξεων που θέλεις.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Εκφράσεις παρακολούθησης

Η Unison παρέχει έναν τρόπο για γρήγορη αξιολόγηση κώδικα που ονομάζεται "έκφραση παρακολούθησης". Μια έκφραση παρακολούθησης ξεκινά με το σύμβολο `>` και ακολουθεί η έκφραση που θέλεις να αξιολογήσεις. Οι εκφράσεις παρακολούθησης μπορούν να γραφτούν σε οποιοδήποτε αρχείο με κατάληξη `.u`. Μόλις αποθηκεύσεις το αρχείο, θα δεις σε τι αξιολογείται η έκφραση στην κονσόλα του Unison Codebase Manager (UCM). Όπου είναι εφικτό σε αυτή την τεκμηρίωση, θα προσπαθήσουμε να δείξουμε μια έκφραση μαζί με το αναμενόμενο αποτέλεσμά της, αφού την αξιολογήσουμε σε μια έκφραση παρακολούθησης.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Συναρτήσεις πολλαπλών γραμμών

Οι συναρτήσεις πολλαπλών γραμμών στη Unison χρησιμοποιούν εσοχή ή μπλοκ `let` για να καθορίσουν τα όρια του κώδικα, γνωστά και ως "λεκτική εμβέλεια".

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Όλα όσα βρίσκονται στο ίδιο επίπεδο εσοχής μοιράζονται την ίδια εμβέλεια, γι' αυτό μπορούμε να αναφέρουμε τη μεταβλητή `newBeginning` στην τελευταία γραμμή.

## Χώροι ονομάτων και εντολές `use`

Οι χώροι ονομάτων είναι ο τρόπος με τον οποίο ομαδοποιούμε και οργανώνουμε τις συναρτήσεις της Unison. Μπορείς να τους σκεφτείς ως κάτι ανάλογο με τους "καταλόγους". Παρέχουν δομή και λογική ομαδοποίηση.

Μπορείς να φέρεις τις συναρτήσεις ενός χώρου ονομάτων στην εμβέλεια με μια εντολή `use`.

Ας πούμε ότι έγραφες μια συνάρτηση που χρησιμοποιεί τιμές `List` της Unison. Ξέρεις ότι θα χρειαστείς συναρτήσεις όπως τις `List.map` και `List.flatMap`, όπου το `List` είναι ο χώρος ονομάτων και τα `map` και `flatMap` είναι συναρτήσεις. Για να μην επαναλαμβάνεσαι, μπορείς να επιλέξεις να φέρεις τα πάντα από τον χώρο ονομάτων `List` στη λεκτική εμβέλεια της συνάρτησής σου, όπως εδώ:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

Η γραμμή `use List` αποσαφηνίζει τις αναφορές στα `map` και `flatMap`. Μπορείς να διαβάσεις περισσότερα για τις [εντολές `use` εδώ][use-statements].

## Η τυπική βιβλιοθήκη της Unison

Η τυπική βιβλιοθήκη της Unison ονομάζεται `base`. Αν ακολούθησες τον οδηγό γρήγορης εκκίνησης και έχεις δημιουργήσει τοπικά μια βάση κώδικα, η τυπική βιβλιοθήκη θα έχει κατέβει αυτόματα. Μπορείς να περιηγηθείς στην τεκμηρίωση της τυπικής βιβλιοθήκης online στο [Unison Share][unison-share-base].

## Σχόλια και κυριολεκτικά τεκμηρίωσης

Τα σχόλια στη Unison είναι ένα κάπως ασυνήθιστο χαρακτηριστικό. Όταν γράφεις κώδικα σε Unison, μπορείς να δημιουργήσεις κείμενο στο αρχείο σου με κατάληξη `.u` που δεν ερμηνεύεται, με την εξής σύνταξη:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Ωστόσο_, επειδή ο κώδικας της Unison αποθηκεύεται ως κατακερματισμός του αφηρημένου συντακτικού δέντρου του και όχι ως αρχεία κειμένου στο σύστημα αρχείων, τα σχόλια που αποτελούν "διακοσμήσεις" κειμένου για μια δεδομένη συνάρτηση ή όρο της Unison στο αρχείο δεν μπορούν στην πραγματικότητα να αποθηκευτούν και να εμφανιστούν ξανά για κοινή χρήση. Αν θέλεις να προσθέσεις πληροφορίες στον όρο σου στη Unison με τρόπο που θα αποθηκεύεται, ώστε να μπορούν άλλοι να τις διαβάσουν και να τις καταλάβουν, μπορείς να χρησιμοποιήσεις ένα κυριολεκτικό τεκμηρίωσης.

Η τεκμηρίωση είναι τιμή πρώτης κατηγορίας στη γλώσσα προγραμματισμού Unison. Αυτό σημαίνει ότι ένα στοιχείο `Doc` μπορεί να ανατεθεί σε μια τιμή, να περαστεί ως τιμή σε μια συνάρτηση ή να επιστραφεί ως τιμή μιας συνάρτησης. Τα στοιχεία κυριολεκτικού τεκμηρίωσης ανοίγουν και κλείνουν με διπλά άγκιστρα. Δες πώς θα μπορούσαμε να χρησιμοποιήσουμε το στοιχείο `Doc` ως σχόλιο.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
