# Εισαγωγή

Οι περισσότερες λέξεις για ακολουθίες που έχεις δει επιστρέφουν *νέες* ακολουθίες και αφήνουν τις εισόδους τους ανέπαφες: `suffix`, `reverse`, `map` και τα λοιπά. Αλλά οι πίνακες και τα διανύσματα υποστηρίζουν και **μετάλλαξη επί τόπου**, και τα δύο χρειάζονται όταν θέλεις να καταγράψεις κατάσταση που αλλάζει με τον χρόνο.

## Δύο είδη μεταβλητών ακολουθιών

- **Οι πίνακες** (`{ … }`) έχουν σταθερό μήκος. Το `<array> ( n elt -- array )` (στη βιβλιοθήκη [`arrays`][arrays]) φτιάχνει έναν νέο πίνακα μήκους `n` γεμάτο με αντίγραφα του `elt`.
- **Τα διανύσματα** (`V{ … }`) μεγαλώνουν και μικραίνουν. Χρησιμοποίησε `V{ } clone` για ένα νέο κενό· το `<vector> ( n -- vector )` (στη βιβλιοθήκη [`vectors`][vectors]) προκατανέμει χωρητικότητα για `n` στοιχεία.

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## Αλλάζοντας μια θέση

Αυτές οι δύο δουλεύουν και με τα δύο είδη ακολουθίας: και οι δύο περιμένουν την ακολουθία μετά τη θέση:

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

Το `set-nth` αναθέτει· το `change-nth` εφαρμόζει ένα quotation στο στοιχείο στη θέση `n`.
Και οι δύο αυτές λέξεις του [`sequences`][sequences] δεν επιστρέφουν τίποτα στη στοίβα· η μετάλλαξη είναι το αποτέλεσμα.

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## Μεγαλώνοντας και μικραίνοντας

Αυτές οι τρεις έχουν νόημα μόνο στα διανύσματα, αφού οι πίνακες δεν μπορούν να αλλάξουν μήκος:

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## Από διάνυσμα σε πίνακα

Όταν έχεις φτιάξει ένα διάνυσμα και θέλεις να επιστρέψεις έναν πίνακα σταθερού μήκους, το `>array ( seq -- array )` (στη βιβλιοθήκη [`arrays`][arrays]) επιστρέφει έναν νέο πίνακα με τα ίδια στοιχεία:

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`: κράτα ένα στιγμιότυπο

Η μετάλλαξη τροποποιεί την ακολουθία επί τόπου. Αν κάποιος σου δίνει μια ακολουθία και πρόκειται να την αλλάξεις, το `clone` (στη βιβλιοθήκη [`kernel`][kernel]) σου δίνει ένα νέο ανεξάρτητο αντίγραφο, ώστε η οπτική αυτού που την έδωσε να μην αλλάξει κάτω από τα πόδια του:

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

Η ίδια προφύλαξη ισχύει και για το `V{ }` και για άλλα κενά literal. Σε κάποιες γλώσσες, το `[]` ή το `vec![]` δεσμεύει ένα νέο δοχείο κάθε φορά που αξιολογείται η έκφραση. Στη Factor, το literal `V{ }` που γράφεις στον κώδικά σου είναι *ένα* αντικείμενο, κοινόχρηστο σε κάθε σημείο κλήσης που το αναφέρει. Αν κάνεις `push` απευθείας πάνω στο `V{ }`, η επόμενη κλήση βλέπει τα υπολείμματα. Το `V{ } clone` φτιάχνει το νέο αντίγραφο που σχεδόν πάντα θέλεις.
