# Εισαγωγή

Όταν έχεις πολλές διακριτές πιθανές τιμές και θέλεις να αποφασίσεις με βάση αυτές, το `case` (στο [`combinators`][combinators]) ταιριάζει καλύτερα από μια αλυσίδα από `if`.

## `case`

```
case ( obj assoc -- )
```

Το `case` παίρνει την τιμή από την κορυφή της στοίβας και έναν *συσχετισμό* από ρήτρες. Κάθε ρήτρα είναι `{ value [ body ] }`. Η πρώτη ρήτρα της οποίας η τιμή είναι `=` με την είσοδο κερδίζει· το σώμα της εκτελείται με την τιμή εισόδου *ήδη καταναλωμένη*. Μια καταχώριση στο τέλος που είναι μόνο `[ body ]` είναι η προεπιλογή. Η είσοδος είναι *ακόμα στη στοίβα* όταν εκτελείται.

```factor
USING: combinators ;

: name-of ( n -- s )
    {
        { 1 [ "one" ] }
        { 2 [ "two" ] }
        [ drop "many" ]
    } case ;
```

Η ισότητα γίνεται με το `=`, οπότε ό,τι συγκρίνεται ως ίσο λειτουργεί ως κλειδί: αριθμοί, συμβολοσειρές και σύμβολα, όλα λειτουργούν.

## `cond` για φρουρούμενους κλάδους

Όταν η επιλογή εξαρτάται από ένα *κατηγόρημα* και όχι από ισότητα (π.χ. `x > 11`), το `cond` είναι το κατάλληλο εργαλείο. Γνώρισες το `cond` στο [Cars, Assemble!][cars-assemble].

## Σύμβολα

Ένα `SYMBOL:` δηλώνει μια λέξη που ωθεί τον εαυτό της στη στοίβα, μια τιμή-ετικέτα που αυτοαξιολογείται. Το `SYMBOLS:` δηλώνει πολλά ταυτόχρονα:

```factor
SYMBOLS: yes no maybe ;
```

Τώρα το `yes` είναι μια τιμή, συγκρίσιμη με το `=`, που μπορείς να τη χρησιμοποιήσεις ως κλειδί για case:

```factor
: invert ( ? -- ?' )
    { { yes [ no ] } { no [ yes ] } [ ] } case ;
```
