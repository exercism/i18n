# Εισαγωγή

## SIMD: Πράξεις bitwise

Υπάρχουν πακεταρισμένες παραλλαγές για τις περισσότερες βαθμωτές πράξεις bitwise.
Ακολουθούν την ίδια γενική σύνταξη με τις ακέραιες πράξεις SIMD, αλλά δεν έχουν κατάληξη μεγέθους:

| εντολή | περιγραφή                         |
|-------------|-----------------------------------|
| `pand`      | bitwise AND δύο τιμών των 128 bit |
| `por`       | bitwise OR δύο τιμών των 128 bit  |
| `pxor`      | bitwise XOR δύο τιμών των 128 bit |

Σημείωσε ότι δεν υπάρχει πακεταρισμένο `NOT`.
Ωστόσο, υπάρχει μια πράξη ANDN, η οποία συμπληρώνει (αντιστρέφει όλα τα bit σε) τον τελεστέο **προορισμού** και μετά υπολογίζει το AND μεταξύ των δύο τελεστέων.
Μπορεί να θεωρηθεί ως ένα NOT σε συνδυασμό με ένα AND:

| εντολή | περιγραφή                                                     |
|-------------|-----------------------------------------------------------------|
| `pandn`     | bitwise AND του **συμπληρωμένου** προορισμού με την πηγή |

Σημείωσε ότι μια πράξη bitwise συνδυάζει bit στην ίδια θέση σε δύο διαφορετικούς τελεστέους, οπότε τα όρια των λωρίδων δεν μπορούν να αλλάξουν το αποτέλεσμα.
Γι' αυτό αυτές οι εντολές δεν έχουν κατάληξη μεγέθους: ο καταχωρητής συμπεριφέρεται ως μία μόνο λωρίδα των 128 bit:

```x86asm
pand xmm0, xmm1   ; xmm0 = xmm0 AND xmm1
por  xmm2, xmm3   ; xmm2 = xmm2 OR xmm3
pxor xmm4, xmm5   ; xmm4 = xmm4 XOR xmm5
pandn xmm6, xmm7  ; xmm6 = (NOT xmm6) AND xmm7
```

~~~~exercism/note
Όλες οι εντολές αυτής της έννοιας υπολογίζουν bit αλλά δεν θέτουν σημαίες.
Μια επόμενη έννοια θα εξετάσει τις εντολές υπό συνθήκη με πακεταρισμένες τιμές.
~~~~

### Ολισθήσεις ανά λωρίδα

Οι ολισθήσεις, σε αντίθεση με τις καθαρά bitwise πράξεις, μετακινούν πράγματι bit από τη μια θέση στην άλλη, οπότε χρειάζονται ένα μέγεθος λωρίδας για να καθορίσουν ένα όριο.
Μέσα σε κάθε λωρίδα συμπεριφέρονται όπως τα βαθμωτά αντίστοιχά τους και τα bit δεν περνούν ποτέ από μια λωρίδα στη γειτονική της:

| εντολή               | περιγραφή                         |
|---------------------------|-------------------------------------|
| `psllw`, `pslld`, `psllq` | λογική ολίσθηση αριστερά, ανά λωρίδα |
| `psrlw`, `psrld`, `psrlq` | λογική ολίσθηση δεξιά, ανά λωρίδα    |
| `psraw`, `psrad`          | αριθμητική ολίσθηση δεξιά, ανά λωρίδα |

Σημείωσε ότι αυτές οι εντολές ακολουθούν τη σύνταξη των πακεταρισμένων ακέραιων πράξεων, περιλαμβανομένης της κατάληξης μεγέθους.
Δεν υπάρχει ολίσθηση λωρίδας byte, μόνο word, dword και, με εξαίρεση την αριθμητική ολίσθηση δεξιά, qword.

Μια διαφορά ανάμεσα στις πακεταρισμένες ολισθήσεις και τα βαθμωτά αντίστοιχά τους είναι το όνομα της πράξης:

- Αντί για `shl` και `shr`, έχουμε `sll` και `srl`, για **s**hift **l**eft (**r**ight) **l**ogical.
- Αντί για `sar`, έχουμε `sra`, για **s**hift **r**ight **a**rithmetic.

Αν και το όνομα είναι διαφορετικό, η πράξη είναι η ίδια:

- Μια λογική ολίσθηση δεξιά γεμίζει τα ανώτερα bit με μηδενικά.
  Ισοδυναμεί με μη προσημασμένη διαίρεση με δύναμη του δύο.
- Μια αριθμητική ολίσθηση δεξιά γεμίζει τα ανώτερα bit με την τιμή του bit προσήμου.
  Ισοδυναμεί με προσημασμένη διαίρεση με δύναμη του δύο, με στρογγυλοποίηση προς το αρνητικό άπειρο.
- Μια ολίσθηση αριστερά γεμίζει πάντα με μηδενικά (γι' αυτό δεν χρειάζεται αριθμητική ολίσθηση αριστερά).

Το πλήθος ολισθήσεων είναι το ίδιο για κάθε λωρίδα.
Μπορεί να είναι μια άμεση τιμή ή τα χαμηλότερα 64 bit ενός καταχωρητή `xmm`:

```x86asm
pslld xmm0, 4      ; each 32-bit lane shifted left by 4
psrlw xmm1, 1      ; each 16-bit lane shifted right by 1, zero-filled
psrad xmm2, xmm3   ; each 32-bit lane shifted right by the count in xmm3, sign-filled
```

~~~~exercism/note
Ένα πλήθος ολισθήσεων μεγαλύτερο από το πλάτος της λωρίδας δεν αναδιπλώνεται όπως η βαθμωτή οικογένεια `shl`/`shr`.
Απλώς παράγει μηδέν (ή όλα τα bit προσήμου, για την αριθμητική ολίσθηση δεξιά).
~~~~

### Πράξεις bitwise με αριθμούς κινητής υποδιαστολής

Κάθε bitwise εντολή έχει επίσης δίδυμα με όνομα κινητής υποδιαστολής, που ακολουθούν την ίδια σύνταξη που είδαμε για τις πακεταρισμένες πράξεις κινητής υποδιαστολής:

| όνομα ακέραιας εντολής | ονόματα κινητής υποδιαστολής          |
|--------------|----------------------|
| `pand`       | `andps`, `andpd`     |
| `pandn`      | `andnps`, `andnpd`   |
| `por`        | `orps`, `orpd`       |
| `pxor`       | `xorps`, `xorpd`     |

Επειδή οι πράξεις bitwise δρουν σε bit, στην πράξη οι ακέραιες πράξεις και οι πράξεις κινητής υποδιαστολής υπολογίζουν το ίδιο αποτέλεσμα.
Τα διαφορετικά ονόματα υπάρχουν για δύο λόγους:

1. Τεκμηριώνουν την πρόθεση, με τον ίδιο τρόπο που θα προτιμούσαμε `movdqa`, `movaps` ή `movapd` ανάλογα με τη φύση των byte που αντιγράφονται.
2. Οι ακέραιες πράξεις και οι πράξεις κινητής υποδιαστολής έχουν συχνά διαφορετικούς τομείς εκτέλεσης.
   Οι πράξεις στον ίδιο τομέα εκτέλεσης μπορούν συνήθως να εκτελεστούν ταχύτερα διαδοχικά.

Δεν υπάρχει πράξη ολίσθησης για τιμές κινητής υποδιαστολής.

### Αναπαράσταση bit των αριθμών κινητής υποδιαστολής

Ένας αριθμός κινητής υποδιαστολής IEEE έχει πολύ διαφορετική αναπαράσταση bit από έναν ακέραιο.

Σε έναν μη προσημασμένο ακέραιο, κάθε bit έχει ενιαία σημασία: αντιπροσωπεύει μια δύναμη του δύο που αντιστοιχεί στη θέση του bit.
Ο ακέραιος είναι το άθροισμα των δυνάμεων του δύο που αντιστοιχούν στα bit που έχουν τεθεί σε 1.
Γι' αυτό η ολίσθηση των bit μπορεί να πολλαπλασιάσει ή να διαιρέσει τον αριθμό με δύναμη του δύο: απλώς αλλάζουμε τη θέση κάθε bit που έχει τεθεί σε 1.

Σε έναν προσημασμένο ακέραιο, τα περισσότερα bit ερμηνεύονται με τον ίδιο τρόπο όπως σε έναν μη προσημασμένο ακέραιο.
Ωστόσο, το ανώτερο bit είναι ξεχωριστό.
Αν τεθεί σε 1, αντί να προστεθεί στα υπόλοιπα, πρέπει να αφαιρέσουμε τη δύναμη του δύο που του αντιστοιχεί, κάτι που δίνει αρνητικό αριθμό.
Στην πράξη, για να αλλάξουμε το πρόσημο ενός αριθμού, θα χρειαζόμασταν εννοιολογικά δύο βήματα: την αντιστροφή όλων των bit (ένα `not`) και μετά την πρόσθεση του 1 στο αποτέλεσμα (ένα `inc`).

Τα bit των αριθμών κινητής υποδιαστολής δεν έχουν ενιαία σημασία και πρέπει να ερμηνεύονται με πολύ διαφορετικούς τρόπους ανάλογα με τη θέση τους:

| πεδίο    | θέσεις (32 bit) | θέσεις (64 bit) |
|----------|------------------|------------------|
| πρόσημο     | 31               | 63               |
| εκθέτης | 30-23            | 62-52            |
| κλάσμα | 22-0             | 51-0             |

Ο αριθμός που προκύπτει υπολογίζεται ως `(-1)^sign * 1.fraction * 2^(exponent - bias)`.
Η πόλωση εξαρτάται από την ακρίβεια:

| μέγεθος   | πόλωση |
|--------|------|
| 32 bit | 127  |
| 64 bit | 1023 |

Και στις δύο μορφές, το πρόσημο του αριθμού καθορίζεται αποκλειστικά από το bit προσήμου.
Η αλλαγή του προσήμου ενός αριθμού κινητής υποδιαστολής επιτυγχάνεται απλώς αντιστρέφοντας αυτό το bit (μια πράξη XOR).
Η λήψη της απόλυτης τιμής επιτυγχάνεται απλώς μηδενίζοντάς το (ένα AND όπου το bit μηδενίζεται):

```x86asm
section .rodata
align 16
abs_mask:  dd 0b0_11111111_11111111111111111111111, 0x7FFFFFFF, 0x7FFFFFFF, 0x7FFFFFFF ; same number in binary and hexadecimal
sign_mask: dd 0b1_00000000_00000000000000000000000, 0x80000000, 0x80000000, 0x80000000 ; same number in binary and hexadecimal

section .text
fn:
  andps xmm0, [rel abs_mask]  ; absolute value: clear the sign bit of all 4 floats
  xorps xmm1, [rel sign_mask] ; negation: flip the sign bit of all 4 floats
  ...
```

Σημείωσε ότι σε αυτή την αναπαράσταση bit, η ολίσθηση των bit δεν έχει προβλέψιμο και ενιαίο αποτέλεσμα.
Το κλάσμα μπορεί να "χυθεί" στον εκθέτη και ο εκθέτης στο πρόσημο.

Ωστόσο, μερικές φορές είναι βολικό να απομονώνουμε τα διάφορα μέρη της αναπαράστασης για να δουλέψουμε πάνω τους.

Για παράδειγμα, τα bit του εκθέτη θα πρέπει πρώτα να ερμηνευτούν ως μη προσημασμένος αριθμός, πριν αφαιρεθεί από αυτά η πόλωση.
Αυτό σημαίνει ότι μπορούμε να παράγουμε έναν ακέραιο 32 ή 64 bit του οποίου η υποκείμενη αναπαράσταση bit αντιστοιχεί σε κάποια δύναμη του δύο στην αντίστοιχη μορφή κινητής υποδιαστολής.
Έπειτα, αυτή η ακατέργαστη αναπαράσταση bit μπορεί να χρησιμοποιηθεί για να πολλαπλασιάσουμε ή να διαιρέσουμε κάποιον άλλο αριθμό κινητής υποδιαστολής.

Για παράδειγμα:

```x86asm
mov eax, 210             ; in the exponent position, this would be 2^(210 - 127) = 2^83 in a 32-bit floating-point number
shl eax, 23              ; the bits are now in the correct position for the exponent of a 32-bit floating-point number
movd xmm0, eax           ; we move the raw bits to xmm0
mulss xmm1, xmm0         ; we are multiplying a 32-bit floating-point number in xmm1 by 2^83
```

Αντίστροφα, θα μπορούσαμε να εξαγάγουμε τους εκθέτες πακεταρισμένων αριθμών κινητής υποδιαστολής κάνοντας ένα AND με μια μάσκα όπου τα bit του εκθέτη είναι σε 1 και όλα τα άλλα σε 0.
Σε συνδυασμό με μια ολίσθηση και μια αφαίρεση, αυτό παράγει τον μη πολωμένο εκθέτη κάθε λωρίδας ως προσημασμένο ακέραιο:

```x86asm
section .rodata
align 16
exp_mask: dd 0b0_11111111_00000000000000000000000, 0x7F800000, 0x7F800000, 0x7F800000 ; same number in binary and hexadecimal
bias: dd 127, 127, 127, 127

section .text
fn:
  movdqa xmm0, [rel values]   ; 4 packed 32-bit floating-point numbers
  pand   xmm0, [rel exp_mask] ; keep bits 30-23
  psrld  xmm0, 23             ; slide the exponent field to the bottom of each lane
  psubd  xmm0, [rel bias]     ; remove the bias
  ...
```

~~~~exercism/caution
Η επέμβαση στα ακατέργαστα bit αριθμών κινητής υποδιαστολής, αν και χρήσιμη σε ορισμένες περιπτώσεις, πρέπει να γίνεται με προσοχή.
Η πρόσθεση ή η αφαίρεση στο πεδίο του εκθέτη είναι ασφαλής μόνο αν δεν υπάρχει υπερχείλιση ή υποχείλιση και αν ο αριθμός εισόδου είναι κανονικός.
Επίσης, η πρόσθεση ενός έγκυρου `x` στο πεδίο του εκθέτη του `0.0` έχει ως αποτέλεσμα `2^(x - bias)`, όχι `0.0 * 2^x`.
~~~~
