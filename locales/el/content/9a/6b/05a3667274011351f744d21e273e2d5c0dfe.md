# Εισαγωγή

Τα δυαδικά ψηφία αντιστοιχούν τελικά άμεσα στα τρανζίστορ της CPU ή της μνήμης RAM σου, και στο αν το καθένα είναι "αναμμένο" ή "σβηστό".

Ο χειρισμός χαμηλού επιπέδου, που ανεπίσημα ονομάζεται "bit-twiddling", είναι ιδιαίτερα σημαντικός στις γλώσσες συστημάτων.

Οι γλώσσες υψηλότερου επιπέδου, όπως η Kotlin, συνήθως αφαιρούν τις περισσότερες από αυτές τις λεπτομέρειες. Ωστόσο, μια βασική σειρά πράξεων σε επίπεδο bit [είναι διαθέσιμη][ref-bitwise].

## Πράξεις ολίσθησης bit

Οι τύποι `Int` ή `Long`, με ή χωρίς πρόσημο, μπορούν να αναπαρασταθούν ως συμβολοσειρά από 1 και 0 και να χειριστούν ως ακολουθία bit.

Ίσως παραδόξως, οι τύποι `Byte` ή `Short` δεν είναι συμβατοί με τις περισσότερες πράξεις bit στην Kotlin.
Όλα τα παρακάτω παραδείγματα χρησιμοποιούν ακέραιους 32 bit (`Int` ή `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

Οι ολισθήσεις bit απλώς μετακινούν τα πάντα προς τα αριστερά ή τα δεξιά κατά έναν καθορισμένο αριθμό θέσεων.
Κάποια bit πέφτουν από το ένα άκρο και το άλλο άκρο συμπληρώνεται με μηδενικά ή άσσους.

- Αριστερή ολίσθηση με `shl`: συμπλήρωση με μηδενικά.
- Δεξιά ολίσθηση με `shr` ή `ushr`: συμπλήρωση με μηδενικά για θετικούς αριθμούς (δες παρακάτω για αρνητικούς αριθμούς).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Κάθε αριστερή ολίσθηση διπλασιάζει την τιμή και κάθε δεξιά ολίσθηση την υποδιπλασιάζει (υπόκειται σε αποκοπή).
Αυτό είναι πιο προφανές στη δεκαδική αναπαράσταση:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Η ολίσθηση bit είναι πολύ ταχύτερη από την "κανονική" αριθμητική, γεγονός που κάνει την τεχνική πολύ δημοφιλή στον προγραμματισμό χαμηλού επιπέδου.

Με τους _αρνητικούς ακέραιους_, πρέπει να είμαστε λίγο πιο προσεκτικοί.

Οι αρνητικές τιμές αποθηκεύονται σε μορφή [συμπληρώματος ως προς δύο][wiki-2complement], που σημαίνει ότι το αριστερότερο bit είναι 1.
Κανένα πρόβλημα για μια αριστερή ολίσθηση, αλλά όταν κάνουμε δεξιά ολίσθηση, πώς συμπληρώνουμε τα αριστερότερα bit;

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

Ο τελεστής `shr` εκτελεί [αριθμητική ολίσθηση][wiki-arithmetic], διατηρώντας το bit προσήμου.

Ο τελεστής `ushr` εκτελεί [λογική ολίσθηση][wiki-logical], συμπληρώνοντας με μηδενικά σαν ο αριθμός να ήταν χωρίς πρόσημο.

## Λογική bit

Είδαμε στην [έννοια Booleans][concept-booleans] ότι οι τελεστές `&&` (and), `||` (or) και `!` (not) χρησιμοποιούνται με τιμές Boolean.

Υπάρχουν αντίστοιχοι τελεστές `and`, `or`, `xor` ([αποκλειστικό ή][wiki-xor]) για τη σύγκριση των bit σε δύο ακέραιους, και μια συνάρτηση `inv` (αντιστροφή) για να αντιστρέψεις όλα τα bit.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
