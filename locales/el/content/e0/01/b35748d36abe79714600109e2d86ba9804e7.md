# Σχετικά

Ο τύπος `Result` επιτρέπει σε μια συνάρτηση να επιστρέφει μία μόνο τιμή που δηλώνει όλα τα παρακάτω:
- Αν η πράξη πέτυχε ή απέτυχε
- Σε περίπτωση επιτυχίας, την τιμή που προέκυψε από την πράξη
- Σε περίπτωση αποτυχίας, τον λόγο της αποτυχίας

Σε άλλες γλώσσες προγραμματισμού που δεν υποστηρίζουν κάτι σαν τον τύπο `Result`, είναι σύνηθες να συναντάς τα παρακάτω μοτίβα για να πετύχεις τους προαναφερθέντες στόχους:
- Μια συνάρτηση που επιστρέφει έναν αριθμητικό κωδικό που δηλώνει επιτυχία ή τον λόγο της αποτυχίας και απαιτεί μια παράμετρο εξόδου για να δεχτεί την τιμή σε περίπτωση επιτυχίας.
- Μια συνάρτηση που επιστρέφει την τιμή σε περίπτωση επιτυχίας ή NULL σε περίπτωση σφάλματος, και μετά μια άλλη συνάρτηση για να πάρεις τον κωδικό σφάλματος που δηλώνει τον λόγο της αποτυχίας.

Ένας άλλος κοινός μηχανισμός διαχείρισης σφαλμάτων είναι η εξαίρεση, η οποία διακόπτει απότομα την τρέχουσα συνάρτηση και
μεταφέρει τον έλεγχο στον πρώτο χειριστή στη στοίβα κλήσεων όταν προκύψει αποτυχία.  
Αν κανένας χειριστής δεν "πιάσει" την εξαίρεση, τότε το πρόγραμμα τερματίζεται.

## Τα πλεονεκτήματα της χρήσης του τύπου `Result`

* __Ασφάλεια κατά τη μεταγλώττιση__: Κάνοντας την επιτυχία ή την αποτυχία μιας κλήσης συνάρτησης ρητή στο σύστημα τύπων, ο μεταγλωττιστής μπορεί να διασφαλίσει ότι ο κώδικας που καλεί τη συνάρτηση χειρίζεται όλες τις περιπτώσεις αποτυχίας, αποτρέποντας μια μεγάλη κατηγορία bugs που θα μπορούσαν να προκύψουν με τα null.

* __Ασφάλεια κατά την εκτέλεση__: Αντί να χρησιμοποιεί `null`, ο τύπος `Result` χρησιμοποιεί το `Error` για να αναπαραστήσει μια αποτυχία, καθιστώντας αδύνατο να προκύψει μια `NullReferenceException`.

* __Ρητή διαχείριση σφαλμάτων__: Ο κώδικας που καλεί μια συνάρτηση που επιστρέφει `Result` πρέπει να αναγνωρίσει ότι η
κλήση μπορεί να αποτύχει· ο κώδικας που καλεί πρέπει να χειρίζεται σκόπιμα τέτοιες αποτυχίες.  Δεν υπάρχουν σιωπηλές αποτυχίες και δεν υπάρχουν εξαιρέσεις-εκπλήξεις.

* __Προβλέψιμη ροή ελέγχου__: Ένα `Result` επιστρέφεται όπως κάθε άλλη τιμή· δεν πηδάει έξω από τη στοίβα κλήσεων όπως μια εξαίρεση.  Ξέρεις πάντα από πού προέρχονται τα σφάλματα και πώς διαδίδονται.

* __Βελτιωμένη αναγνωσιμότητα και συντηρησιμότητα__: Επιστρέφοντας ένα `Result`, η υπογραφή μιας συνάρτησης δείχνει καθαρά την αναμενόμενη συμπεριφορά σε περίπτωση επιτυχίας και αποτυχίας.

## Χρήση

Ο τύπος `Result` είναι ένας γενικός τύπος που περιέχει δύο υποκείμενους τύπους:
- Τον τύπο της τιμής που προκύπτει από μια επιτυχημένη πράξη
- Τον τύπο που αναπαριστά τον λόγο της αποτυχίας

Ο τύπος `Result` είναι επίσης μια [διακριτή ένωση][discriminated-union] με τις ακόλουθες δυνατές περιπτώσεις:
* `Ok <value>` που αναπαριστά ένα επιτυχημένο αποτέλεσμα
* `Error <reason>` που αναπαριστά μια αποτυχία

Η παρακάτω συνάρτηση δείχνει πώς να δημιουργήσεις μια τιμή `Result`:

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

Σε αυτό το παράδειγμα, η τιμή `Ok` είναι μια συμβολοσειρά (το όνομα που δόθηκε), και η τιμή `Error` είναι επίσης μια συμβολοσειρά (η αιτία του σφάλματος, σε μορφή που διαβάζεται από άνθρωπο).

## Ανάγνωση του περιεχομένου μιας τιμής `Result`

Θεώρησε τον παρακάτω ορισμό τύπου και την υπογραφή συνάρτησης:

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

Ο κώδικας που καλεί τη συνάρτηση `openFile` μπορεί να χρησιμοποιήσει αντιστοίχιση προτύπων για να χειριστεί τις περιπτώσεις επιτυχίας και αποτυχίας, όπως στο παρακάτω παράδειγμα:

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```

[discriminated-union]: https://learn.microsoft.com/en-us/dotnet/fsharp/language-reference/discriminated-unions
