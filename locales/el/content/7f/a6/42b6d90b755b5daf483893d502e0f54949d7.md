# Εισαγωγή στα βασικά του κελύφους

## Κελύφη

Ένα _κέλυφος_ είναι ένα πρόγραμμα που σου επιτρέπει να εισάγεις εντολές για να αλληλεπιδράς με το λειτουργικό σύστημα.
Τα κελύφη μπορεί να είναι γραφικά· το περιβάλλον επιφάνειας εργασίας που χρησιμοποιείς με ποντίκι ή touchpad είναι κι αυτό ένα κέλυφος.
Θα επικεντρωθούμε στις διεπαφές γραμμής εντολών, όπου πληκτρολογείς εντολές και τα αποτελέσματα εκτυπώνονται (συνήθως) στο τερματικό σου.

Υπάρχουν πολλά διαφορετικά κελύφη γραμμής εντολών.
Τα Windows προσφέρουν τα **cmd** και **powershell**.
Το Mac και το Linux προσφέρουν "κελύφη Unix", από τα οποία υπάρχουν πολλά.
Το προεπιλεγμένο κέλυφος στο Mac είναι το **zsh**.
Το **csh** είναι ένα παλαιότερο κέλυφος με σύνταξη παρόμοια με της C.
Το **bash** είναι ένα από τα πιο δημοφιλή κελύφη, ιδιαίτερα στο Linux.

Ένα από τα πολύ πρώτα κελύφη είναι το κέλυφος Bourne, το **sh**.
Με τον καιρό, αυτό το κέλυφος [τυποποιήθηκε][posix] ώστε να παρέχεται σε κάθε σύστημα τύπου Unix.
Πολλά κελύφη βασίζονται στο κέλυφος Bourne, παρέχοντας συχνά επιπλέον διαδραστική ή προγραμματιστική λειτουργικότητα.

Το **Bash** βασίζεται στο κέλυφος Bourne.
Γι' αυτό ονομάζεται "**B**ourne-**a**gain **sh**ell".
Είναι το προεπιλεγμένο κέλυφος σε πολλά συστήματα Linux.
Το Bash παρέχει πολλές δυνατότητες που το κάνουν ένα ευχάριστο διαδραστικό κέλυφος, όπως:

* μια πλήρως προσαρμόσιμη προτροπή,
* τη δυνατότητα να ανακαλείς και να τροποποιείς εντολές από το ιστορικό,
* τη δυνατότητα να χειρίζεσαι τις εκτελούμενες διεργασίες,
* ψευδώνυμα που μειώνουν την πληκτρολόγηση,
* και άλλα.

Αυτή η διαδρομή δεν αφορά το πώς να χρησιμοποιείς το bash ως διαδραστικό κέλυφος.
Αφορά την εκμάθηση του πώς να γράφεις προγράμματα με το bash.
Η έμφαση θα δοθεί στη χρήση _μόνο_ του bash για την επίλυση προβλημάτων, αν και δεν υπάρχουν περιορισμοί στο να καλείς εξωτερικά εργαλεία.

## Τα βασικά του Bash: Εντολές και ορίσματα

Το Bash διαβάζει εντολές από την είσοδό του (η οποία είναι συνήθως είτε ένα τερματικό είτε ένα αρχείο).
Κάθε γραμμή εισόδου που διαβάζει αντιμετωπίζεται ως _εντολή_, δηλαδή μια οδηγία που πρέπει να εκτελεστεί.
(Υπάρχουν μερικές προχωρημένες περιπτώσεις, όπως εντολές που εκτείνονται σε πολλές γραμμές, οι οποίες θα συζητηθούν αργότερα.)

Το Bash χωρίζει κάθε γραμμή σε **λέξεις** που ορίζονται από χαρακτήρες κενού διαστήματος (κενά και στηλοθέτες).
Η πρώτη λέξη της γραμμής είναι το όνομα της _εντολής_ που θα εκτελεστεί.
Όλες οι υπόλοιπες λέξεις γίνονται _ορίσματα_ αυτής της εντολής (επιλογές, ονόματα αρχείων κ.λπ.).

~~~~exercism/note
Στα παρακάτω παραδείγματα θα σου δείξουμε μερικές διαδραστικές εντολές που μπορείς να εκτελέσεις.

* Ο χαρακτήρας `#` ξεκινά ένα _σχόλιο_.
  Όποιες λέξεις ακολουθούν το σχόλιο αγνοούνται από το κέλυφος· το σχόλιο προορίζεται μόνο για ανάγνωση.
* Ο χαρακτήρας `$` δηλώνει την προτροπή του κελύφους. 
  Αν αντιγράφεις την εντολή, μη συμπεριλάβεις την προτροπή.
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

Το `rm` είναι μια εφαρμογή που διαγράφει τα αρχεία που της δίνονται.
Ο χαρακτήρας `*` είναι χαρακτήρας [glob][glob], ένα μοτίβο "μπαλαντέρ" που ταιριάζει με όλα τα αρχεία στον τρέχοντα κατάλογο.
Θα μιλήσουμε περισσότερο για τα globs αργότερα.

Πρόσεξες ότι υπάρχουν πολλά κενά ανάμεσα στο `a` και στο `b`, και μόνο ένα ανάμεσα στο `b` και στο `c`;
Το πλήθος των κενών ανάμεσα στα ορίσματα δεν έχει σημασία!
Για παράδειγμα:

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

Το `echo` είναι μια εντολή που εκτυπώνει τα ορίσματά της στην τυπική έξοδο (η οποία στην περίπτωσή μας είναι το τερματικό).
Το Bash χωρίζει την εντολή σε πέντε λέξεις και καλεί την εντολή `echo` με τέσσερα ορίσματα.
Τα επιπλέον κενά στο δεύτερο παράδειγμα δεν κάνουν καμία διαφορά.
Το `echo` δεν ξέρει πόσα κενά υπήρχαν αρχικά ανάμεσα στις λέξεις.

Αν θέλουμε να διατηρήσουμε τα επιπλέον κενά, πρέπει να περάσουμε την πρόταση ως ένα μοναδικό όρισμα.
Μπορούμε να το κάνουμε αυτό χρησιμοποιώντας [εισαγωγικά][Quotes]:

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

Τα εισαγωγικά ομαδοποιούν ό,τι βρίσκεται μέσα τους σε ένα _μοναδικό όρισμα_.
Το όρισμα είναι το `This    is    a    test.`, μαζί με αυτούς τους συγκεκριμένους χαρακτήρες κενού.
Σημείωσε ότι τα εισαγωγικά δεν αποτελούν μέρος του ορίσματος: το bash τα αφαιρεί πριν παραδώσει αυτό το μοναδικό όρισμα στο `echo`.

Τα ορίσματα χωρίζονται από το όνομα της εντολής και μεταξύ τους με κενό διάστημα.
Αυτό είναι σημαντικό να το θυμάσαι.
Για παράδειγμα, το παρακάτω είναι λάθος:

```bash
$ [-f file]
bash: [-f: command not found
```

Αυτό έχει σκοπό να ελέγξει αν υπάρχει ένα αρχείο με το όνομα `file`.
Είναι λογικό να υποθέσεις ότι τα κενά γύρω από το `[` και το `]` δεν έχουν σημασία, αλλά το `[` είναι στην πραγματικότητα μια εντολή και απαιτεί το τελευταίο όρισμά της να είναι το `]`.
(Θα καλύψουμε την εντολή `[` με περισσότερες λεπτομέρειες αργότερα.) 
Επομένως, πρέπει να χωρίσουμε το `[` από το `-f` και το `]` από το `file`.
Διαφορετικά, το bash θα νομίσει ότι προσπαθούμε να εκτελέσουμε μια εντολή με το όνομα `[-f` με ένα μοναδικό όρισμα `file]`.
Η σωστή εντολή χωρίζει όλα τα ορίσματα με κενό διάστημα:

```bash
$ [ -f file ]
```

(Βλέπουμε πολλούς ανθρώπους να μπερδεύονται με αυτή τη συμπεριφορά· νομίζουν ότι το `[...]` είναι "απλώς σύνταξη" και ότι μπορούν να παραλείψουν τα κενά· το `[` είναι μια εντολή και το κενό διάστημα είναι απαραίτητο.)

Αν το όνομα του αρχείου μας περιέχει κενά ή άλλους ειδικούς χαρακτήρες, θα πρέπει επίσης να μπει σε εισαγωγικά:

```bash
$ [ -f "my file" ]
```

## Τύποι εντολών

Το Bash κατανοεί αρκετούς διαφορετικούς τύπους εντολών: ψευδώνυμα, συναρτήσεις, ενσωματωμένες εντολές, λέξεις-κλειδιά και εκτελέσιμα αρχεία.
Όλα αυτά είναι _εντολές_ και όλα συμπεριφέρονται με πολύ παρόμοιο τρόπο.

Από προεπιλογή, τα ψευδώνυμα είναι ενεργοποιημένα μόνο στα διαδραστικά κελύφη, όχι στα σενάρια κελύφους.
Δε θα τα καλύψουμε εδώ.

### Συναρτήσεις

Μια συνάρτηση περιέχει εντολές κελύφους και λειτουργεί πολύ σαν ένα μικρό σενάριο· μπορεί μάλιστα να δέχεται ορίσματα και να δημιουργεί τοπικές μεταβλητές.
Όταν καλείται μια συνάρτηση, εκτελούνται οι εντολές που περιέχει.
Οι συναρτήσεις θα καλυφθούν σε βάθος αργότερα.

### Ενσωματωμένες εντολές

Το Bash έχει μερικές βασικές εντολές ενσωματωμένες, όπως: `cd` (αλλαγή καταλόγου), `echo` (εγγραφή εξόδου) και ούτω καθεξής.
Μπορούν να θεωρηθούν ως συναρτήσεις που παρέχονται ήδη.

### Λέξεις-κλειδιά

Οι λέξεις-κλειδιά μοιάζουν με τις ενσωματωμένες εντολές, με κύρια διαφορά ότι οι λέξεις-κλειδιά είναι στην πραγματικότητα σύνταξη του bash και μπορεί να αναλυθούν με ειδικούς κανόνες.
Για παράδειγμα, το `[` είναι ενσωματωμένη εντολή του bash, ενώ το `[[` είναι λέξη-κλειδί του bash· και τα δύο χρησιμοποιούνται για τον έλεγχο διάφορων συνθηκών.
Αλλά η λέξη-κλειδί `[[` έχει κάποιες επιπλέον δυνατότητες.
Για παράδειγμα, παρέχει τον τελεστή `=~` που κάνει έλεγχο με κανονικές εκφράσεις.

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

Οι τελεστές σύγκρισης συμβολοσειρών `<` και `>` είναι ένα άλλο παράδειγμα του πώς οι λέξεις-κλειδιά αναλύουν τον κώδικα διαφορετικά.
Μέσα σε `[[...]]`, αυτοί οι τελεστές δεν χρειάζονται ιδιαίτερη προσοχή.

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

Αλλά μέσα σε `[...]` πρέπει να τα βάλεις σε εισαγωγικά ή να τα διαφύγεις, ώστε να μην τα αναλύσει το κέλυφος ως τελεστές ανακατεύθυνσης.

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### Εκτελέσιμα

Ο τελευταίος τύπος εντολής που μπορεί να εκτελέσει το bash είναι ένα _εκτελέσιμο αρχείο_.
Πρόκειται για εκτελέσιμα αρχεία (προγράμματα) στο σύστημα αρχείων του υπολογιστή σου, τα οποία μπορείς να εκτελέσεις.
(Τα εκτελέσιμα αρχεία μπορεί επίσης να ονομάζονται _εξωτερικές εντολές_ ή _εφαρμογές_.)
Τα εκτελέσιμα αρχεία συνήθως καλούνται πληκτρολογώντας μόνο το όνομά τους· η πλήρης διαδρομή προς το αρχείο συνήθως δεν χρειάζεται.
Αυτό είναι εφικτό επειδή το bash χρησιμοποιεί μια προκαθορισμένη μεταβλητή που το βοηθά να βρει τη θέση των κοινών εκτελέσιμων αρχείων.
Αυτή η μεταβλητή ονομάζεται `PATH`.
Είναι ένα σύνολο ονομάτων καταλόγων που χωρίζονται με άνω και κάτω τελείες (π.χ. `/usr/bin:/bin`). 
Όταν δίνεται μια εντολή (π.χ. `myprogram` ή `ls`) χωρίς διαδρομή αρχείου (και δεν είναι ψευδώνυμο, συνάρτηση, ενσωματωμένη εντολή ή λέξη-κλειδί), το bash ψάχνει μέσα στους καταλόγους του `PATH`.
Οι κατάλογοι ελέγχονται με τη σειρά, από αριστερά προς τα δεξιά, για το αν περιέχουν εκτελέσιμο αρχείο με το συγκεκριμένο όνομα.

Αν το εκτελέσιμο αρχείο βρίσκεται έξω από μια γνωστή διαδρομή, θα πρέπει να δηλωθεί η διαδρομή του αρχείου.
Για το εκτελέσιμο `myprogram` στον τρέχοντα κατάλογο, χρησιμοποίησε `./myprogram`· αν βρίσκεται στον κατάλογο `/opt/somedirectory`, χρησιμοποίησε `/opt/somedirectory/myprogram`.

Συμβουλή: Η εντολή `type` μπορεί να χρησιμοποιηθεί για να πάρεις λεπτομέρειες σχετικά με την εντολή:

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## Σενάρια

Ένα _σενάριο_ είναι μια ακολουθία εντολών αποθηκευμένη σε ένα αρχείο.
Το Bash διαβάζει το αρχείο και επεξεργάζεται τις εντολές με τη σειρά.
Προχωρά στην επόμενη εντολή μόνο όταν ολοκληρωθεί η τρέχουσα.
Η εξαίρεση είναι όταν μια εντολή έχει οριστεί να εκτελεστεί ασύγχρονα (στο παρασκήνιο).
Μην ανησυχείς πολύ για αυτή την περίπτωση ακόμα· θα μάθουμε πώς λειτουργεί αργότερα.

Οποιοδήποτε παράδειγμα γραμμής εντολών σε αυτόν τον οδηγό μπορεί να χρησιμοποιηθεί και σε ένα σενάριο.

Το να φτιάξεις ένα σενάριο είναι εύκολο.
Ξεκίνα φτιάχνοντας ένα νέο αρχείο και βάλε αυτό στην πρώτη γραμμή:

```bash
#!/bin/bash
```

Αυτή η γραμμή ονομάζεται _οδηγία διερμηνευτή_ (ονομάζεται επίσης _hashbang_ ή **_shebang_**).
Καθορίζει ότι το `/bin/bash` θα χρησιμοποιηθεί ως διερμηνευτής όταν το αρχείο χρησιμοποιείται ως εκτελέσιμο σε μια εντολή.
Όταν ο πυρήνας του λειτουργικού συστήματος εκτελεί ένα _μη δυαδικό αρχείο_, διαβάζει την πρώτη γραμμή του αρχείου.
Αν η γραμμή ξεκινά με `#!`, ο πυρήνας τη χρησιμοποιεί για να καθορίσει σε ποιον διερμηνευτή θα προωθήσει το αρχείο.
(Υπάρχουν και άλλοι έγκυροι τρόποι να γίνει αυτό, δες παρακάτω.)
Το `#!` πρέπει να βρίσκεται στην αρχή ακριβώς του αρχείου, χωρίς κενά ή κενές γραμμές πριν από αυτό.
Οι εντολές του σεναρίου μας θα εμφανίζονται σε ξεχωριστές γραμμές κάτω από αυτή.

Συμβουλή: Αντί για `#!/bin/bash`, θα μπορούσες να χρησιμοποιήσεις

```bash
#!/usr/bin/env bash
```

Το `env` ψάχνει στο `$PATH` το εκτελέσιμο αρχείο που υποδεικνύει το πρώτο του όρισμα (στην περίπτωση αυτή, το "bash").
Για μια πιο λεπτομερή εξήγηση αυτής της τεχνικής και του πώς διαφέρει από το απλό `#!/bin/bash`, δες [αυτή την ερώτηση στο StackOverflow][env bash].

Μην ξεγελαστείς από σενάρια ή παραδείγματα στο διαδίκτυο που χρησιμοποιούν το `/bin/sh` ως διερμηνευτή.
**Το `sh` δεν είναι `bash`!**
Το ίδιο το Bash είναι ένα κέλυφος "συμβατό με το sh", που σημαίνει ότι μπορεί να εκτελέσει τα περισσότερα σενάρια `sh` και διαθέτει μεγάλο μέρος της ίδιας σύνταξης.
Ωστόσο, το αντίστροφο δεν ισχύει· ορισμένα χαρακτηριστικά του bash θα σπάσουν ή θα προκαλέσουν απροσδόκητη συμπεριφορά στο `sh`.
Στην πραγματικότητα, δεν υπάρχει ένα μοναδικό κέλυφος `sh`.
Υπάρχουν πολλές υλοποιήσεις κελυφών που υποστηρίζουν τη σύνταξη POSIX-sh.
Ανάλογα με το λειτουργικό σύστημά σου, όταν εκτελείς το `sh` μπορεί στην πραγματικότητα να εκτελείς το bash, το ash, το dash ή κάποιο άλλο κέλυφος.

Μόλις δημιουργηθεί το αρχείο σεναρίου, μπορείς να το εκτελέσεις ως εξής:

```bash
$ bash myscript
```

Σε αυτό το παράδειγμα, εκτελούμε την _εντολή_ `bash` και της λέμε να διαβάσει το σενάριο που της δώσαμε ως _όρισμα_.
Όταν το κάνουμε έτσι, η γραμμή `#!` είναι απλώς ένα _σχόλιο_.

Εναλλακτικά, μπορούμε να δώσουμε στα σενάριά μας δικαιώματα εκτέλεσης.
Με αυτή τη μέθοδο μπορούμε να εκτελέσουμε το σενάριο όπως οποιοδήποτε άλλο εκτελέσιμο αρχείο, αντί να καλέσουμε το bash χειροκίνητα:

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

Όταν εκτελούμε την εντολή με αυτόν τον τρόπο, το λειτουργικό σύστημα χρησιμοποιεί τη γραμμή `#!` για να καθορίσει ποιον διερμηνευτή θα χρησιμοποιήσει για να εκτελέσει το σενάριό σου.
