# Σχετικά

## Προσθήκη πλαισίου στα σφάλματα

Εξερευνήσαμε τη βασική διαχείριση σφαλμάτων στη Go στην [έννοια errors][concept-errors].
Όπως έμαθες εκεί, από προεπιλογή τα σφάλματα δε μεταφέρουν μαζί τους ίχνη στοίβας.
Αυτό κάνει κρίσιμο να διασφαλίσεις ότι το ίδιο το σφάλμα περιέχει αρκετές πληροφορίες για να προσδιορίσεις το πρόβλημα.

Αν θέλαμε να προσθέσουμε πληροφορίες σε ένα υπάρχον σφάλμα με τα εργαλεία που ήδη γνωρίζουμε, θα μπορούσαμε να γράψουμε κάτι σαν αυτό, για να δημιουργήσουμε ένα νέο σφάλμα με το συνδυασμένο κείμενο του αρχικού σφάλματος και των πρόσθετων πληροφοριών:

```go
err := errors.New(fmt.Sprintf("parsing age for user %d: %v", userID, originalError))
```

Ευτυχώς, το πακέτο `fmt` από την τυπική βιβλιοθήκη περιέχει μια συντομευμένη εκδοχή αυτού με τη μορφή της συνάρτησης `Errorf`.
Αυτό σου επιτρέπει, για παράδειγμα, να προσθέσεις εύκολα πληροφορίες για το πλαίσιο στο οποίο προέκυψε το σφάλμα.

```go
originalError := errors.New("unexpected negative number")
userID := 123
err := fmt.Errorf("parsing age for user %d: %v", userID, originalError)
err.Error()
// => "parsing age for user 123: unexpected negative number"
```

Εκτός αν είσαι σίγουρος ότι το σφάλμα περιέχει ήδη αρκετές πληροφορίες, καλό είναι να αποκτήσεις τη συνήθεια να προσθέτεις πάντα πλαίσιο σε ένα σφάλμα πριν το επιστρέψεις από μια συνάρτηση.
Αυτό σημαίνει ότι το βασικό μοτίβο διαχείρισης σφαλμάτων σου πρέπει να μοιάζει κάπως έτσι:

```go
result, err := calculateSomething()
if err != nil {
  return 0, fmt.Errorf("calculating something: %v", err)
}
```

Όπως φαίνεται στα παραδείγματα, η σύμβαση είναι να χωρίζεις το σφάλμα από το μήνυμα που προσθέτεις με άνω κάτω τελεία.
Όπως και το μήνυμα του αρχικού σφάλματος, έτσι και το μήνυμα πλαισίου δεν πρέπει να ξεκινά με κεφαλαίο και δεν πρέπει να προστίθεται τελεία στο τέλος.

~~~~exercism/note
Όταν προσθέτεις πλαίσιο σε ένα σφάλμα, είναι δελεαστικό να ξεκινάς το μήνυμα με "failed to ..." ή κάτι παρόμοιο.
Ωστόσο, επειδή ένα σφάλμα μπορεί να συσσωρεύσει πολύ επιπλέον πλαίσιο καθώς ανεβαίνει την αλυσίδα των συναρτήσεων, αυτό μπορεί να κάνει το τελικό μήνυμα που θα καταγραφεί ή που θα δει ο χρήστης πιο δύσκολο στην ανάγνωση και γεμάτο επαναλήψεις.

Ακολουθεί ένα παράδειγμα για να το δείξουμε:

```text
failed to validate request: failed to parse path parameter: failed to convert number: invalid input "abc"
vs.
validating request: parsing path parameter: converting to number: invalid input "abc"
```

Έχε λοιπόν στο μυαλό σου αυτό το τελικό αποτέλεσμα όταν γράφεις τα μηνύματα πλαισίου και απόφυγε να προσθέτεις κείμενο για το ότι κάτι δεν πήγε όπως περίμενες.
Αυτό είναι συνήθως σαφές από το πλαίσιο (π.χ. το επίπεδο καταγραφής "ERROR") και το μήνυμα του αρχικού σφάλματος.
~~~~

Συχνά αυτός ο τρόπος προσθήκης πληροφοριών σε ένα σφάλμα είναι αρκετά καλός, αλλά υπάρχουν περιπτώσεις όπου θέλεις να επιτρέψεις στον καταναλωτή του σφάλματος σου να ελέγξει ή να ανακτήσει το αρχικό υποκείμενο σφάλμα.
Η προσθήκη πλαισίου με τρόπο που το επιτρέπει αυτό ονομάζεται "περιτύλιξη σφάλματος" στη Go.

## Περιτύλιξη σφαλμάτων και έλεγχος για sentinel errors

Η περιτύλιξη σφάλματος μπορεί να επιτευχθεί με μια πολύ μικρή αλλαγή στον κώδικα που είδαμε παραπάνω.
Για να περιτυλίξεις ένα σφάλμα, πρέπει να χρησιμοποιήσεις το ρήμα μορφοποίησης `%w` αντί για το `%v`.
Στο παρασκήνιο, αυτό θα διασφαλίσει ότι το σφάλμα που προκύπτει υλοποιεί μια μέθοδο `Unwrap` που επιστρέφει το αρχικό σφάλμα.
Εξαιτίας αυτού, μπορείς να χρησιμοποιήσεις το `errors.Is` για να ελέγξεις αν ένα συγκεκριμένο sentinel error εμφανίζεται κάπου κατά μήκος της "αλυσίδας σφαλμάτων".
Αυτό το κάνει καλώντας κρυφά το `Unwrap` επανειλημμένα, μέχρι να βρεθεί το σφάλμα που ψάχνεις ή να τελειώσει η αλυσίδα.

```go
originalError := errors.New("unexpected negative number")
err := fmt.Errorf("parsing age: %w", originalError)
errors.Is(err, originalError)
// => true
```

Ο έλεγχος για το αρχικό σφάλμα με το `errors.Is` δεν θα λειτουργούσε με το συνηθισμένο ρήμα μορφοποίησης `%v`.

```go
originalError := errors.New("unexpected negative number")
err := fmt.Errorf("parsing age: %v", originalError)
errors.Is(err, originalError)
// => false
```

Ως αποτέλεσμα, είναι καλή πρακτική να χρησιμοποιείς `%v` από προεπιλογή και να χρησιμοποιείς `%w` μόνο αν θέλεις ρητά να επιτρέψεις στον καταναλωτή σου να έχει πρόσβαση σε ένα υποκείμενο σφάλμα ([Google Go Styleguide][google-go-styleguide]).

Αν βρεθείς σε μια κατάσταση όπου θέλεις να ελέγξεις για ένα sentinel error αλλά ρητά δε θέλεις να το ξετυλίξεις, μπορείς να χρησιμοποιήσεις το `==` αντί για το `errors.Is`.

```go
var originalError = errors.New("unexpected negative number")
func someFunc() error {
  return originalError
}

err := someFunc()
err == originalError 
// => true
```

Αντίθετα, το `==` δεν θα αναγνώριζε το σφάλμα αν αυτό ήταν περιτυλιγμένο.

```go
var originalError = errors.New("unexpected negative number")
func someFunc() error {
  return fmt.Errorf("parsing age: %v", originalError)
}

err := someFunc()
err == originalError 
// => false
```

Δεν πειράζει να δουλεύεις με το `errors.Is` από προεπιλογή, αλλά πρέπει πάντα να έχεις υπόψη σου ότι αυτό σημαίνει πως θα αναζητηθεί ολόκληρη η αλυσίδα σφαλμάτων.

## Έλεγχος για (προσαρμοσμένους) τύπους σφαλμάτων

Υπάρχει ένα αντίστοιχο του `errors.Is` που σου επιτρέπει να ελέγξεις και να ανακτήσεις ένα σφάλμα συγκεκριμένου τύπου από την αλυσίδα σφαλμάτων.
Η συνάρτηση για αυτό είναι η `errors.As` και, όπως ακριβώς το `errors.Is`, θα αναζητήσει τον δεδομένο τύπο σφάλματος σε ολόκληρη την αλυσίδα.
Η `errors.As` εξάγει το σφάλμα που βρήκε και ταιριάζει με τον τύπο μόνο τότε, ώστε να μπορείς να δουλέψεις περαιτέρω με αυτό, π.χ. να ανακτήσεις συγκεκριμένα πεδία.

```go
type MyCustomError struct {
  Message string
  Details string
}

func (e *MyCustomError) Error() string {
  return fmt.Sprintf("%s, details: %s", e.Message, e.Details)
}

func someFunc() error {
  originalError := &MyCustomError{
    Message: "some message",
    Details: "some details",
  }

  return fmt.Errorf("doing something: %w", originalError)
}

err := someFunc()
var customError *MyCustomError
errors.As(err, &customError)
// => true

// customError now contains the error that was found in the error chain.
customError.Details
// => "some details"
```

~~~~exercism/caution
Πρόσεχε με τη σύνταξη όσον αφορά τους δείκτες παραπάνω.
Ο κώδικας θα λειτουργήσει και θα μεταγλωττιστεί σωστά μόνο αν το `customError` έχει τον ακριβή τύπο που υλοποιεί τη διεπαφή error.
Στην περίπτωσή μας, αυτός είναι ο `*MyCustomError` (ένας [δείκτης][concept-pointers] προς το `MyCustomError`), όχι το ίδιο το `MyCustomError`.

Επιπλέον, το δεύτερο όρισμα πρέπει να είναι δείκτης στη μεταβλητή του σφάλματος.
Επειδή το σφάλμα μας είναι ήδη δείκτης, αυτό που περνάμε στο `errors.As` είναι δείκτης σε δείκτη (προς το MyCustomError).
Μόνο με αυτή τη σωστή ρύθμιση μπορεί η Go να γεμίσει τη μεταβλητή με το σφάλμα που βρήκε.
~~~~

Όπως και πριν, η `errors.As` δεν θα είχε βρει τον τύπο του σφάλματος αν είχε χρησιμοποιηθεί το `%v` κατά την κλήση της `Errorf`.

Αν για κάποιο λόγο δε θέλεις να ξετυλίξεις, μπορείς να χρησιμοποιήσεις αντ' αυτού type assertion (αντίστοιχο με το `==` παραπάνω).

```go
// MyCustomError defined as above.

func someFunc() error {
  return &MyCustomError{
    Message: "some message",
    Details: "some details",
  }
}

err := someFunc()
customError, ok := err.(*CustomError)
// "ok" is now true
customError.Details
// => "some details"
```

Το type assertion δεν θα μπορεί να αναγνωρίσει τον τύπο του σφάλματος αν το σφάλμα έχει περιτυλιχθεί.

## Επιτρέποντας το ξετύλιγμα σφαλμάτων προσαρμοσμένων τύπων

Μερικές φορές το να περιτυλίξεις απλώς ένα σφάλμα με λίγο επιπλέον κείμενο δεν αρκεί.
Μπορείς αντ' αυτού να δημιουργήσεις έναν προσαρμοσμένο τύπο σφάλματος που κρατά το αρχικό σφάλμα και τα επιπλέον δομημένα δεδομένα που θέλεις να προσθέσεις.
Αν θέλεις να επιτρέψεις το ξετύλιγμα για τον τύπο σφάλματος σου, το μόνο που έχεις να κάνεις είναι να προσθέσεις χειροκίνητα μια μέθοδο `Unwrap() error`, ώστε να ικανοποιείται η διεπαφή `Unwrap`.

```go
type SpecialError struct {
  originalError error
  metadata string
}

func (e *SpecialError) Error() string {
  // The usual serialization code goes here.
}

func (e *SpecialError) Unwrap() error {
  return e.originalError
}
```

## Συνδυασμός πολλαπλών σφαλμάτων

Στη Go 1.20, προστέθηκε μια νέα συνάρτηση `Join` στο ενσωματωμένο πακέτο `errors`.
Η `Join` επιτρέπει να συνδυάσεις πολλά σφάλματα μαζί με τρόπο που εξακολουθεί να επιτρέπει το ξετύλιγμα, δηλαδή τον έλεγχο για ένα συγκεκριμένο σφάλμα ή τύπο σφάλματος κατά μήκος της αλυσίδας.
Έτσι, η αλυσίδα σφαλμάτων μπορεί στην πραγματικότητα να είναι ένα δέντρο σφαλμάτων.
Περισσότερες πληροφορίες μπορείς να βρεις στις [σημειώσεις έκδοσης][release-notes] και στην [τεκμηρίωση][doc-join].
