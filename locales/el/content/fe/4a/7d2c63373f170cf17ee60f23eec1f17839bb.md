# Εισαγωγή

## Μερική εφαρμογή και σύνθεση συναρτήσεων

### Μερική εφαρμογή

Όλες οι συναρτήσεις στην Elm είναι [curried][currying], που σημαίνει ότι αν καλέσεις μια συνάρτηση χωρίς να περάσεις όλα τα ορίσματα, αυτή επιστρέφει μια νέα συνάρτηση.

Το αποτέλεσμα αυτής της διαδικασίας ονομάζεται [μερική εφαρμογή][partial-application] (δεν περνάς όλα τα ορίσματα στη συνάρτηση, αλλά εφαρμόζεις μερικά από αυτά).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

Η μερική εφαρμογή εφαρμόζει πάντα τα ορίσματα με τη σειρά.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

### Ο τελεστής σωλήνωσης (`|>`)

Το `x |> f` είναι ακριβώς το ίδιο με το `f x`. Ένα συγκεκριμένο παράδειγμα είναι ότι το `"5" |> String.toInt` είναι το ίδιο με το `String.toInt "5"`.

Αυτό δεν ακούγεται πολύ χρήσιμο με την πρώτη ματιά, αλλά ονομάζεται [τελεστής σωλήνωσης][pipe-operator] επειδή σου επιτρέπει να γράψεις κώδικα "σε σωλήνωση".

Για παράδειγμα, ας πούμε ότι έχουμε μια συνάρτηση sanitize που μετατρέπει την είσοδο του χρήστη σε ακέραιους:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Μπορούμε να την ξαναγράψουμε έτσι:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Έτσι αποφεύγεται η χρήση παρενθέσεων και οι συναρτήσεις εμφανίζονται με τη σειρά που εφαρμόζονται (πρώτα η `String.trim`, μετά η `String.toInt`), κάτι που βοηθά την αναγνωσιμότητα.

Υπάρχει επίσης ο [αντίστροφος τελεστής σωλήνωσης `(<|)`][reverse-pipe-operator].
Το `f <| x` είναι ακριβώς το ίδιο με το `f x`.
Ούτε αυτό φαίνεται πολύ χρήσιμο με την πρώτη ματιά, και σίγουρα δεν χρησιμοποιείται τόσο όσο ο τελεστής σωλήνωσης, αλλά βοηθά να αποφεύγεις τις παρενθέσεις σε ορισμένες περιπτώσεις.

### Σύνθεση συναρτήσεων / Point Free Style

Ο τελεστής [`(>>)`][forward-composition] έχει τύπο `(a -> b) -> (b -> c) -> (a -> c)` και δημιουργεί μια συνάρτηση τύπου `a -> c` συνθέτοντας δύο συμβατές συναρτήσεις τύπου `a -> b ` και `b -> c`.
Το κάνει παίρνοντας την έξοδο (τύπου `b`) από την πρώτη συνάρτηση και χρησιμοποιώντας την ως πρώτο όρισμα στη δεύτερη συνάρτηση (η οποία πρέπει να είναι του ίδιου τύπου `b`).
Η συνάρτηση που δημιουργείται θα δέχεται την ίδια είσοδο (τύπου `a`) με την πρώτη συνάρτηση και θα επιστρέφει ό,τι `c` επιστρέφει η δεύτερη συνάρτηση.

Ένα συγκεκριμένο παράδειγμα είναι το `String.trim >> String.toInt`.
Η `String.trim` δέχεται μια συμβολοσειρά ως μοναδική παράμετρο, οπότε αυτό δέχεται και η συνάρτηση που δημιουργείται.
Η `String.toInt` επιστρέφει ένα `Maybe Int`, οπότε αυτό επιστρέφει και η συνάρτηση που δημιουργείται.
Η `String.trim` επιστρέφει μια `String`, την οποία η `String.toInt` δέχεται ως παράμετρο, οπότε το παράδειγμα μεταγλωττίζεται.

Μπορούμε τώρα να ξαναγράψουμε τη συνάρτηση `sanitize` ως εξής:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Πρόσεξε ότι δεν χρησιμοποιούμε πια την παράμετρο `input` που βλέπεις στο αρχικό παράδειγμα, παρόλο που η λειτουργία είναι ίδια.
Αυτός ο τρόπος δημιουργίας συναρτήσεων που δεν αναφέρονται καθόλου στις παραμέτρους τους ονομάζεται "Point Free Style".
Το πλεονέκτημα αυτού του στυλ είναι ότι ο κώδικας είναι πιο συνοπτικός, το μειονέκτημα είναι ότι μπορεί να είναι πιο δύσκολος στην κατανόηση, ειδικά για αρχάριους.

Αξίζει να θυμάσαι ότι όλες οι συναρτήσεις στην Elm είναι curried, οπότε το `String.length >> max` μεταγλωττίζεται.

- Ο τελεστής [`(>>)`][forward-composition] έχει τύπο `(a -> b) -> (b -> c) -> (a -> c)`.
- Η `String.length` έχει τύπο `String -> Int`, που είναι το κομμάτι `(a -> b)`, άρα το `a` είναι `String` και το `b` είναι - `Int`.
- Η `max` έχει τύπο `Int -> Int -> Int`, που είναι το κομμάτι `b -> c`.
- Το `b` είναι `Int`, οπότε η `max` εφαρμόζεται μερικώς, άρα το `c` είναι το αποτέλεσμα αυτής της μερικής εφαρμογής (`Int -> Int`).
- Άρα ο τύπος του `String.length >> max` είναι `String -> (Int -> Int)`.
- Άρα το `((String.length >> max) "123") 2` επιστρέφει `3`, επειδή το `"123"` έχει μήκος 3, που είναι μεγαλύτερο από το 2 του ορίσματος `Int`.

### Σχεδιασμός συναρτήσεων

Για να γράφεις εύκολα κομψό κώδικα στην Elm, καλό είναι να βάζεις την κύρια δομή δεδομένων ως τελευταία παράμετρο των συναρτήσεων.
Όλες οι συνηθισμένες συναρτήσεις της τυπικής βιβλιοθήκης το κάνουν αυτό, όπως η `List.map` (υπογραφή τύπου παρακάτω).

```elm
map : (a -> b) -> List a -> List b
```

Εδώ βλέπουμε ότι η τελευταία παράμετρος της συνάρτησης `map` είναι `List a` και επιστρέφει `List b`, οπότε η κύρια δομή δεδομένων (`List`) είναι η τελευταία παράμετρος.

Αυτό καθιστά δυνατή τη συγγραφή κομψού κώδικα σε σωλήνωση, όπως παρακάτω.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

Κάνει επίσης βολική τη χρήση της σύνθεσης συναρτήσεων και του Point Free Style, ως εναλλακτική της σωλήνωσης.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

Η σύνθεση συναρτήσεων σου επιτρέπει επίσης να μειώσεις αυτό το παράδειγμα σε μία μόνο κλήση της `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
