# Εισαγωγή

Σε αυτό το σημείο του προγράμματος σπουδών, έχεις δει τη R να χρησιμοποιείται συχνά ως προστακτική γλώσσα, και ολοένα και περισσότερο ως συναρτησιακή γλώσσα (ειδικά με τις βιβλιοθήκες [`purrr`][ref-purrr] και [`dplyr`][ref-dplyr]).

Το να υποστηρίξουμε τώρα ότι η R είναι κατά κύριο λόγο αντικειμενοστρεφής μπορεί να προκαλέσει κάποιον σκεπτικισμό!

Παραδόξως, αυτή η δήλωση είναι αληθής.
Εσωτερικά, η R υλοποιείται χρησιμοποιώντας κλάσεις, κληρονομικότητα, πολυμορφισμό και τις νοοτροπίες που είναι χαρακτηριστικές των προγραμματιστών του αντικειμενοστρεφούς προγραμματισμού.

Ωστόσο, όποιος γνωρίζει Java ή Ruby (ρητά αντικειμενοστρεφείς) ή ακόμη και Python (ημι-κρυφά αντικειμενοστρεφή, από ορισμένες απόψεις) θα βρει την προσέγγιση της R ... _μη οικεία_.

Για αρχή, υπάρχουν πολλαπλοί σχεδιασμοί κλάσεων: περίπου τρεις σε κοινή χρήση (S3, S4, R6), συν διάφοροι άλλοι κυρίως θεωρητικού ενδιαφέροντος.

Μια διεξοδική συζήτηση υπάρχει στο [Advanced R, 2e][book-advanced-r], κεφάλαια 12-16.
Αυτό το βιβλίο του 2019 απευθύνεται σε μεγάλο βαθμό σε ανθρώπους που θέλουν να κατανοήσουν και να συντηρήσουν τα εσωτερικά της R, οπότε ο αντικειμενοστρεφής προγραμματισμός είναι απαραίτητος.

Τα πιο προσανατολισμένα στον τελικό χρήστη εγχειρίδια διαφέρουν.

- Το The Art of R Programming (2011, μόνο σε έντυπη μορφή) έχει ένα κεφάλαιο για τον αντικειμενοστρεφή προγραμματισμό που καλύπτει τις S3 και (πιο σύντομα) τις S4, οι οποίες ήταν σημαντικές εκείνη την εποχή.
  Το σχόλιο ότι _"οι κλάσεις S3 έχουν μια μάλλον αυτοσχέδια δομή"_ εξακολουθεί να είναι εντυπωσιακά αληθές.
- Το R in Action (3e, 2022) περιορίζει τον αντικειμενοστρεφή προγραμματισμό σε 3 σελίδες σε ένα κεφάλαιο για τον προχωρημένο προγραμματισμό προς το τέλος.
- Το [R for Data Science, 2e][book-r-data-sci] (2023, με 548 σελίδες στην έντυπη έκδοση) δεν αναφέρει καθόλου τον αντικειμενοστρεφή προγραμματισμό.

Αυτή η έννοια θα επικεντρωθεί στις κλάσεις S3, που είναι οι πιο απλές, οι πιο συνηθισμένες και οι πιο σχετικές με προβλήματα τύπου Exercism.
Μερικές από τις ασκήσεις εξάσκησης στη διαδρομή R σε βάζουν να δημιουργήσεις μια κλάση S3, ενώ άλλες το αφήνουν προαιρετικό αλλά το ενθαρρύνουν διακριτικά.

## Κλάσεις S3

Είναι παλιές: το όνομα S3 σημαίνει απλώς ότι εισήχθησαν στην έκδοση 3 της γλώσσας S (ενός εμπορικού προδρόμου της R).

Μια κλάση S3 είναι επίσης πολύ απλή: συνήθως, μια [λίστα][concept-lists] με τουλάχιστον ένα επιπλέον χαρακτηριστικό.

Όπως αναφέρει το [Advanced R][book-s3]: _"Το S3 είναι ανεπίσημο και ad hoc, αλλά υπάρχει μια ορισμένη κομψότητα στον μινιμαλισμό του: δεν μπορείς να αφαιρέσεις κανένα μέρος του και να έχεις ακόμη ένα χρήσιμο αντικειμενοστρεφές σύστημα."_

```R
# create a list
pt2d <- list(x = 2.5, y = 4.2)
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
class(pt2d)
#> [1] "list"
attributes(pt2d)
#> $names
#> [1] "x" "y"

# convert the list to an S3 class
class(pt2d) <- "point2d"
str(pt2d)
#> List of 2
#>  $ x: num 2.5
#>  $ y: num 4.2
#>  - attr(*, "class")= chr "point2d"
class(pt2d)
#> [1] "point2d"
attributes(pt2d)
#> $names
#> [1] "x" "y"

#> $class
#> [1] "point2d"
```

Έτσι, κάνοντας ανάθεση στο [`class(obj)`][ref-class] απλώς προσθέτεις ένα χαρακτηριστικό στο `obj`, στην περίπτωση αυτή προσδιορίζοντας το pt2d ως στιγμιότυπο της κλάσης point2d.

Τα βήματα δημιουργίας μπορούν να συνδυαστούν με τη [`structure()`][ref-structure]:

```R
pt2d_2 <- structure(list(x = 2.5, y = 4.2), class = "point2d")
pt2d_2 == pt2d
#> Error in pt2d_2 == pt2d : comparison of these types is not implemented
```

Αν και τα στιγμιότυπα που προκύπτουν είναι εννοιολογικά πανομοιότυπα, δεν έχουμε ακόμη υλοποιήσει τρόπο ώστε η R να το επιβεβαιώσει.

### Γενικές μέθοδοι

Όποιος γνωρίζει τον αντικειμενοστρεφή προγραμματισμό σε άλλες γλώσσες ίσως αναρωτιέται: _"μα δεν υποτίθεται ότι οι κλάσεις μπορούν να ΚΑΝΟΥΝ πράγματα;"_

Μπορούμε να ελέγξουμε τις μεθόδους που είναι διαθέσιμες για στιγμιότυπα `point2d` και να ανακαλύψουμε ότι (σε αντίθεση με την υποκείμενη `list`) προς το παρόν δεν υπάρχει καμία.

```R
methods(class = "point2d")
#> no methods found
methods(class = "list")
#>  [1] %within%      all.equal     as.col_spec   as.data.frame as_mapper     as_tibble     coerce        common_by    
#>  [9] Ops           pattern_alpha relist        scale_type    select        type.convert  within       
#> see '?methods' for accessing help and source code
```

Στις περισσότερες αντικειμενοστρεφείς γλώσσες, οι μέθοδοι ορίζονται μέσα στον ορισμό της κλάσης.
Λίγες γλώσσες (κυρίως η Ruby) σου επιτρέπουν να προσθέτεις και να τροποποιείς μεθόδους κλάσης αργότερα.

Οι κλάσεις S3 είναι πολύ διαφορετικές.
Αντί να προσθέτουμε μεθόδους σε μια κλάση, προσθέτουμε την κλάση σε μια γενική μέθοδο.

Όποιος δουλεύει διαδραστικά στην κονσόλα της R χρησιμοποιεί γενικές μεθόδους συνεχώς, συνήθως χωρίς να σκέφτεται πώς υλοποιούνται.

Ένα πολύ συνηθισμένο παράδειγμα είναι η `print()`, αν και σπάνια πληκτρολογείς το όνομα της συνάρτησης.
Το να εισάγεις μια τιμή `x` από μόνη της στη γραμμή εντολών της κονσόλας είναι απλώς συντακτική ζάχαρη για την `print(x)`.

```R
1:4
#> [1] 1 2 3 4
print(1:4)
#> [1] 1 2 3 4
```

Μπορούμε ήδη να εκτυπώσουμε το `pt2d`.
Αν και η `print()` δεν γνωρίζει τίποτα για την κλάση `point2d`, έχει λογικές προεπιλογές για να χειρίζεται μια μεγάλη ποικιλία αντικειμένων.

```R
pt2d
#> $x
#> [1] 2.5

#> $y
#> [1] 4.2

attr(,"class")
#> [1] "point2d"
```

Αυτό είναι αρκετά φλύαρο και μπορεί να θέλουμε έναν τρόπο για κομψή εκτύπωση του σημείου με συντομία.

Εύκολο: απλώς πρόσθεσε μια συνάρτηση με το όνομα `print.point2d()`.
Το όνομα πρέπει να έχει τη μορφή `methodname.classname`, ώστε ο dispatcher να ξέρει τι να ψάξει.

```R
print.point2d <- function(pt) {
  cat("Cartesian coords (", pt$x, ", ", pt$y, ")\n", sep="")
}

pt2d
#> Cartesian coords (2.5, 4.2)
```

Τώρα ας υποθέσουμε ότι θέλουμε να δημιουργήσουμε μια νέα γενική μέθοδο, για παράδειγμα τη `flipvert()` που αντιστρέφει το πρόσημο της συντεταγμένης `y`.

Και πάλι, εύκολο:

```R
flipvert <- function(x, ...) UseMethod("flipvert")
```

Αυτό δημιουργεί έναν dispatcher, όπου το `x` είναι το αντικείμενό μας με κλάση S3 και το `...` χειρίζεται τυχόν επιπλέον ορίσματα που μπορεί να χρειάζονται οι ορισμοί μεθόδων ("dot args", όπως περιγράφονται στην [έννοια Συναρτήσεις][concept-functions]).

Στη συνέχεια μπορούμε να ορίσουμε τη μέθοδο για το `point2d` και να τη χρησιμοποιήσουμε.

```R
flipvert.point2d <- function(pt) {
  pt$y <- -pt$y
  pt
}

flipvert(pt2d)
#> Cartesian coords (2.5, -4.2)

methods("flipvert")
#> [1] flipvert.point2d
```

Η R ξέρει τώρα πώς να αντιστρέψει το σημείο μας και πώς να εμφανίσει το αποτέλεσμα.

Θα μπορούσαμε να το επεκτείνουμε δημιουργώντας κλάσεις για 3D, για πολικές συντεταγμένες κ.λπ., και στη συνέχεια να ορίσουμε μεθόδους για καθεμία.

Από την οπτική του τελικού χρήστη, υπάρχει μόνο η `flipvert(x, ...)` και μπορούμε να βασιστούμε στη R για να προσδιορίσει την κλάση εισόδου και να χρησιμοποιήσει την κατάλληλη υποκείμενη υλοποίηση.

~~~~exercism/caution
Τα ονόματα συναρτήσεων στη μορφή `verb.class` μοιάζουν με μεθόδους S3, τόσο για τους χρήστες όσο και για τον parser της R.
Απόφυγε να χρησιμοποιείς παρόμοια ονοματολογία σε άλλα πλαίσια.

Ομολογουμένως, η βασική R παραβιάζει μερικές φορές αυτόν τον κανόνα.
Θα πρέπει να το θεωρήσουμε ένα άτυχο ιστορικό ατύχημα (για συναρτήσεις ακόμη παλαιότερες από το S3), το οποίο πρέπει να διατηρηθεί για λόγους συμβατότητας προς τα πίσω.
~~~~

### Κληρονομικότητα

Οι λάτρεις του αντικειμενοστρεφούς προγραμματισμού μπορούν να γράψουν πολλά μακροσκελή κεφάλαια εγχειριδίων για την κληρονομικότητα, τις υποκλάσεις, τα mixins και όλα τα υπόλοιπα.

Η R απλώς σου επιτρέπει να δώσεις πολλαπλά ονόματα στο χαρακτηριστικό `class`: ένα μεγαλύτερο διάνυσμα συμβολοσειρών αντί για μία μόνο συμβολοσειρά.

Με τον κίνδυνο να τραβήξουμε το παράδειγμα στα άκρα, ας υποθέσουμε ότι είχαμε φτιάξει μια γενική κλάση `point` και θέλαμε να δημιουργήσουμε υποκλάσεις `point2d`, `point3d` κ.λπ.

Τότε ο ορισμός του `point2d` χρησιμοποιεί απλώς `class = c("point2d", "point")`: τη συγκεκριμένη κλάση και τη γονική κλάση (ή κλάσεις).

Οι γενικές μέθοδοι όπως η `print()` θα αναζητήσουν τότε διαδοχικά τις `print.point2d()`, `print.point()` και (πιθανώς) `print.default()`, χρησιμοποιώντας την πρώτη υλοποίηση που θα βρει ο dispatcher.

### Ασφάλεια

Πολλές αντικειμενοστρεφείς γλώσσες (Java, C# κ.λπ.) εκμεταλλεύονται την ενθυλάκωση δεδομένων μέσα σε κλάσεις για να κάνουν προσεκτικούς ελέγχους κατά τη μεταγλώττιση και να επιβάλλουν ασφάλεια τύπων.

Να έχεις υπόψη ότι το S3 σου επιτρέπει να κάνεις σχεδόν ό,τι θέλεις, ακόμη και αν δεν βγάζει νόημα (τυχόν μήνυμα σφάλματος έρχεται αργότερα, αν έρθει ποτέ).

Όπως αναφέρει το ["Advanced R"][book-s3] (2e, ενότητα 13.3):

> _Αν έχεις χρησιμοποιήσει άλλες αντικειμενοστρεφείς γλώσσες, αυτό μπορεί να σε κάνει να νιώσεις άβολα, αλλά στην πράξη αυτή η ευελιξία προκαλεί λίγα προβλήματα. Η R δεν σε εμποδίζει να πυροβολήσεις το πόδι σου, αλλά όσο δεν σημαδεύεις το δάχτυλό σου και δεν τραβάς τη σκανδάλη, δεν θα έχεις πρόβλημα._

Λοιπόν, _εντάξει;_
Η R είναι εξαιρετική για διερευνητική ανάλυση δεδομένων και στατιστική, συχνά όταν δουλεύεις διαδραστικά.
Κανείς δεν προτείνει να τη χρησιμοποιήσεις για να γράψεις εξαιρετικά ασφαλή εταιρικά χρηματοοικονομικά συστήματα!
