# Ασκήσεις Εξάσκησης

[Οι ασκήσεις εξάσκησης](/docs/building/product/practice-exercises) είναι ασκήσεις σχεδιασμένες να επιτρέπουν στους μαθητές να λύνουν ένα οποιοδήποτε πρόβλημα, με στόχο να αξιοποιήσουν τις έννοιες που έχουν μάθει μέχρι τώρα.

Θέλεις να προσθέσεις την πρώτη σου άσκηση εξάσκησης σε ένα track; Δες τα [έγγραφα για την προσθήκη άσκησης εξάσκησης](/docs/building/tracks/practice-exercises/add) ή παρακολούθησε το βίντεο με την περιήγησή μας 👇

[video:vimeo/906101866?h=2954ad331e]()

````exercism/note
Μπορείς να δημιουργήσεις γρήγορα τον σκελετό μιας νέας άσκησης εξάσκησης εκτελώντας τις παρακάτω εντολές από τον ριζικό κατάλογο του track:

```shell
bin/fetch-configlet
bin/configlet create --practice-exercise <slug>
```

Για περισσότερες πληροφορίες, δες τα [έγγραφα του `configlet create`](/docs/building/configlet/create)
````

## Μεταδεδομένα

Τα μεταδεδομένα της άσκησης εξάσκησης ορίζονται στο κλειδί `exercises.practice` στο [αρχείο config.json](/docs/building/tracks/config-json). Τα μεταδεδομένα ορίζουν το UUID, το slug και άλλα στοιχεία της άσκησης.

### Παράδειγμα

```json
{
  "exercises": {
    "practice": [
      {
        "uuid": "8ba15933-29a2-49b1-a9ce-70474bad3007",
        "slug": "leap",
        "name": "Leap",
        "practices": ["if-statements", "numbers", "operator-precedence"],
        "prerequisites": ["if-statements", "numbers"],
        "difficulty": 1
      }
    ]
  }
}
```

### `practices`

Το κλειδί `practices` πρέπει να απαριθμεί τα slug των εννοιών που αυτή η άσκηση εξάσκησης επιτρέπει ενεργά σε έναν μαθητή να εξασκήσει.

- Αυτά εμφανίζονται στη διεπαφή χρήστη ως "Κάνε εξάσκηση σε αυτή την έννοια με: TwoFer, Leap, κ.λπ."
- Προσπάθησε να επιλέξεις 3 - 8 ασκήσεις που εξασκούν κάθε έννοια.
- Προσπάθησε να επιλέξεις τουλάχιστον δύο ασκήσεις που επιτρέπουν σε κάποιον να εξασκήσει τα βασικά μιας έννοιας.
- Κάποιες έννοιες είναι πολύ συνηθισμένες (για παράδειγμα `strings`). Σε αυτές τις περιπτώσεις προτείνουμε να επιλέξεις μερικές καλές ασκήσεις που κάνουν τους ανθρώπους να σκέφτονται αυτές τις έννοιες με ενδιαφέροντες τρόπους. Για παράδειγμα, ασκήσεις που απαιτούν UTF-8, συνένωση συμβολοσειρών, απαρίθμηση χαρακτήρων κ.λπ. θα ήταν όλες καλά παραδείγματα.

### `prerequisites`

Το κλειδί `prerequisites` απαριθμεί τις έννοιες που πρέπει να έχει ολοκληρώσει ένας μαθητής για να αποκτήσει πρόσβαση σε αυτή την άσκηση εξάσκησης.

- Αυτά εμφανίζονται στη διεπαφή χρήστη ως "Μάθε τις συμβολοσειρές για να ξεκλειδώσεις το TwoFer"
- Πρέπει να περιλαμβάνει όλες τις έννοιες που χρειάζεται να έχει καλύψει ένας μαθητής για να μπορεί να ολοκληρώσει την άσκηση με τουλάχιστον έναν ιδιωματικό τρόπο. Για παράδειγμα, για την άσκηση TwoFer στη Ruby, τα prerequisites μπορεί να περιλαμβάνουν `strings`, `optional-params`, `implicit-return`.
- Για ασκήσεις που μπορούν να ολοκληρωθούν με εναλλακτικές έννοιες (π.χ. μια άσκηση που λύνεται με `loops` ή `recursion`), ο συντηρητής πρέπει να επιλέξει την προσέγγιση με την οποία θα ήθελε να ξεκλειδώσει την άσκηση, λαμβάνοντας υπόψη την πορεία του μαθητή στο track. Για παράδειγμα, στο παράδειγμα loops/recursion, μπορεί να θεωρήσει ότι αυτή η άσκηση είναι καλή για πρώιμη εξάσκηση στους `loops` ή ότι θα προτιμούσε να την αφήσει για αργότερα ώστε να διδάξει την αναδρομή. Μπορεί επίσης να αξιοποιήσει έναν αναλυτή για να παροτρύνει τον μαθητή να δοκιμάσει μια εναλλακτική προσέγγιση: "Καλή δουλειά που το έλυσες με loops. Μπορεί να θέλεις επίσης να δοκιμάσεις να το λύσεις με αναδρομή."

## Αρχεία

Κάθε άσκηση εξάσκησης έχει τον δικό της κατάλογο μέσα στον κατάλογο `exercises/practice` του track. Το όνομα του καταλόγου της άσκησης εξάσκησης πρέπει να ταιριάζει με την ιδιότητα `slug` της άσκησης εξάσκησης, όπως ορίζεται στο [αρχείο config.json](/docs/building/tracks#concept-exercises).

Μια άσκηση εξάσκησης έχει τέσσερις τύπους αρχείων:

### Αρχεία τεκμηρίωσης

Αυτά τα αρχεία παρουσιάζονται στον μαθητή για να βοηθήσουν στην εξήγηση της άσκησης.

- `.docs/introduction.md`: εισάγει το σκηνικό και το υπόβαθρο της άσκησης (προαιρετικό)
- `.docs/introduction.append.md`: πρόσθετο κείμενο εισαγωγής που προσαρτάται μετά την υπάρχουσα εισαγωγή (προαιρετικό)
- `.docs/instructions.md`: παρέχει οδηγίες για την άσκηση (απαιτείται)
- `.docs/instructions.append.md`: πρόσθετο κείμενο οδηγιών που προσαρτάται μετά τις υπάρχουσες οδηγίες (προαιρετικό)
- `.docs/hints.md`: παρέχει υποδείξεις στον μαθητή για να τον βοηθήσει να ξεκολλήσει στην άσκηση (προαιρετικό)

### Αρχεία μεταδεδομένων

Αυτά τα αρχεία _δεν_ παρουσιάζονται στον μαθητή, αλλά χρησιμοποιούνται για τον ορισμό των μεταδεδομένων της άσκησης.

- `.meta/config.json`: περιέχει μεταπληροφορίες για την άσκηση (απαιτείται)
- `.meta/design.md`: περιγράφει τον σχεδιασμό της άσκησης (προαιρετικό)
- `.meta/tests.toml`: περιέχει πληροφορίες για το ποιες δοκιμές έχουν υλοποιηθεί (προαιρετικό)

### Αρχεία προσεγγίσεων

Αυτά τα αρχεία περιγράφουν προσεγγίσεις για την άσκηση.

- `.approaches/introduction.md`: εισαγωγή στις πιο συνηθισμένες προσεγγίσεις για την άσκηση (προαιρετικό)
- `.approaches/config.json`: μεταδεδομένα για τις προσεγγίσεις (προαιρετικό)
- `.approaches/<approach-slug>/content.md`: περιγραφή της προσέγγισης (προαιρετικό)
- `.approaches/<approach-slug>/snippet.txt`: απόσπασμα που παρουσιάζει την προσέγγιση (προαιρετικό)

### Αρχεία άρθρων

Αυτά τα αρχεία περιγράφουν άρθρα για την άσκηση.

- `.articles/config.json`: μεταδεδομένα για τα άρθρα (προαιρετικό)
- `.articles/<article-slug>/content.md`: περιγραφή του άρθρου (προαιρετικό)
- `.articles/<article-slug>/snippet.md`: απόσπασμα που παρουσιάζει το άρθρο (προαιρετικό)

### Αρχεία άσκησης

Τα αρχεία που αφορούν συγκεκριμένη γλώσσα, όπως τα αρχεία υλοποίησης και δοκιμών. Τα ονόματα αυτών των αρχείων εξαρτώνται από το track.

- Σουίτα δοκιμών: επαληθεύει την ορθότητα μιας λύσης.
- Υλοποίηση-σκελετός: παρέχει ένα σημείο εκκίνησης για τους μαθητές.
- Παράδειγμα υλοποίησης: παρέχει ένα παράδειγμα υλοποίησης που περνά όλες τις δοκιμές.
- Πρόσθετα αρχεία: διασφαλίζουν ότι οι δοκιμές μπορούν να εκτελεστούν.

### Αρχείο: `.docs/introduction.md`

**Σκοπός:** Εισάγει το σκηνικό και το υπόβαθρο της άσκησης στον μαθητή.

**Παρουσία:** Απαιτείται αν η άσκηση υλοποιεί μια Άσκηση Προδιαγραφών Προβλήματος με αρχείο `introduction.md`

Αν η άσκηση υλοποιεί μια [Άσκηση Προδιαγραφών Προβλήματος](https://github.com/exercism/problem-specifications/), το περιεχόμενο αυτού του αρχείου πρέπει να ταιριάζει με το αρχείο `introduction.md` της Άσκησης Προδιαγραφών Προβλήματος. Το configlet έχει λειτουργικότητα για αυτόματο [συγχρονισμό του περιεχομένου](/docs/building/configlet/generating-documents#document-practice-exercises-introductionmd-file) αυτού του αρχείου.

Αν η άσκηση _δεν_ βασίζεται σε μια Άσκηση Προδιαγραφών Προβλήματος, λάβε υπόψη τα εξής:

Δίνουμε μεγάλη αξία στο να κάνουμε το περιεχόμενο του Exercism ασφαλές για όλους και γι' αυτό συχνά είμαστε υπερβολικά προσεκτικοί όταν κρίνουμε αν μια ιστορία είναι κατάλληλη ή όχι. Αν και προσέχουμε τι ενσωματώνουμε, αναγνωρίζουμε ότι είναι δύσκολο να αντιληφθεί κανείς τι μπορεί να θεωρηθεί προβληματικό, οπότε θα υποθέτουμε πάντα ότι ενεργείς καλή τη πίστη και θα κάνουμε το καλύτερο δυνατό για να εντοπίζουμε τυχόν ζητήματα κατά την ανασκόπηση με μη αντιπαραθετικό τρόπο. Αν θέλεις να ελέγξεις μια ιστορία μαζί μας, ανέφερε το @exercism/leadership και θα το δούμε μαζί. Ορίστε μερικά σημεία καθοδήγησης:

- Προσπάθησε να διασφαλίσεις ότι η ιστορία είναι φιλόξενη και κατανοητή από όλους. Αν η ιστορία περιέχει εσωτερικά αστεία ή τοπική αργκό, προσπάθησε να σκεφτείς εναλλακτικές φράσεις.
- Προσπάθησε να γράφεις παραδείγματα που είναι συμπεριληπτικά για όλους. Για παράδειγμα, σκέψου να χρησιμοποιήσεις ονόματα από άλλες κουλτούρες και μικτά φύλα.
- Αναρωτήσου αν γνωρίζεις προσωπικά κάποιον που θα προσβαλλόταν από την ιστορία. Αν ναι, σκέψου να την αλλάξεις για να το αποφύγεις.

#### Παράδειγμα

```markdown
# Introduction

Bob is a lackadaisical teenager. In conversation, his responses are very limited.
```

### Αρχείο: `.docs/introduction.append.md`

**Σκοπός:** Πρόσθετο κείμενο εισαγωγής που προσαρτάται μετά την υπάρχουσα εισαγωγή.

**Παρουσία:** Προαιρετικό

Σε κάποιες (σπάνιες) περιπτώσεις, μπορεί να θέλεις να επεκτείνεις το αρχείο `introduction.md` της άσκησης, για παράδειγμα όταν η άσκηση έχει υλοποιήσει δοκιμές που δεν καλύπτονται από τις υπάρχουσες οδηγίες.

Ένα track που δεν θέλει ο Bob να υποστηρίζει μηνύματα εκτός ASCII, μπορεί να προσθέσει τα εξής:

```markdown
# Introduction append

## Note

As part of his teenage rebellion, Bob has decided to only communicate using ASCII.
```

Τα αρχεία προσάρτησης πρέπει να ξεκινούν με κεφαλίδα H1.
Αυτή η κεφαλίδα δεν εμφανίζεται, αλλά πρέπει παρ' όλα αυτά να υπάρχει.
Την κεφαλίδα H1 ακολουθεί συχνά μια κεφαλίδα H2, η οποία βοηθά στον διαχωρισμό του γενικού περιεχομένου από το περιεχόμενο που αφορά συγκεκριμένο track.

### Αρχείο: `.docs/hints.md`

**Σκοπός:** Παρέχει υποδείξεις σε έναν μαθητή για να τον βοηθήσει να ξεκολλήσει σε μια άσκηση.

**Παρουσία:** Προαιρετικό

- Αν ο μαθητής κολλήσει, του επιτρέπουμε να κάνει κλικ σε ένα κουμπί ζητώντας υπόδειξη, το οποίο θα εμφανίσει το σχετικό μέρος του αρχείου.
- Οι υποδείξεις πρέπει να είναι σε μορφή κουκκίδων κάτω από κεφαλίδες.
- Οι υποδείξεις πρέπει να αρκούν για να ξεμπλοκάρουν σχεδόν οποιονδήποτε μαθητή.
- Οι υποδείξεις δεν πρέπει να δίνουν τη λύση, αλλά να παραπέμπουν σε έναν πόρο που περιγράφει τη λύση (π.χ. σύνδεσμο στην τεκμηρίωση της συνάρτησης που θα χρησιμοποιηθεί).
- Οι υποδείξεις μπορούν να χρησιμοποιούν δείγματα κώδικα για να εξηγήσουν έννοιες, αλλά όχι για να περιγράψουν τη λύση. π.χ. σε μια άσκηση με λίστες μπορεί να δείχνουν ένα απόσπασμα για το πώς λειτουργεί μια συγκεκριμένη συνάρτηση λίστας, αλλά όχι με τρόπο που να μπορεί να αντιγραφεί και να επικολληθεί απευθείας στη λύση.
- Οι υποδείξεις πρέπει να εμφανίζονται ως λίστα Markdown κάτω από μια κεφαλίδα `## General`.
- Αν δεν υπάρχουν υποδείξεις, η κεφαλίδα πρέπει να παραλείπεται.

Η προβολή υποδείξεων δεν θα είναι μια "προτεινόμενη" διαδρομή και θα την αποθαρρύνουμε (απαλά), εκτός αν ο μαθητής δεν μπορεί να προχωρήσει χωρίς αυτήν. Ως εκ τούτου, αξίζει να λάβεις υπόψη ότι ο μαθητής που τη διαβάζει θα είναι λίγο μπερδεμένος/συγκλονισμένος και ίσως απογοητευμένος.

#### Παράδειγμα

```markdown
## General

- There are many [built-in methods][integers] to simplify working with integers.

[integers]: https://ruby-doc.org/core-2.7.0/Integer.html
```

### Αρχείο: .meta/design.md

**Σκοπός:** Περιγράφει τον σχεδιασμό της άσκησης.

**Παρουσία:** Προαιρετικό

Αυτό το αρχείο περιέχει πληροφορίες για τον σχεδιασμό της άσκησης, που περιλαμβάνουν στοιχεία όπως ο στόχος της, οι διδακτικοί της στόχοι, τι δεν πρέπει να διδάσκεται και άλλα.

Υπάρχει για να ενημερώνει τους μελλοντικούς συντηρητές ή συνεισφέροντες σχετικά με το εύρος και τους περιορισμούς μιας άσκησης, ώστε να αποφεύγεται η φυσική τάση να γίνονται οι ασκήσεις πιο πολύπλοκες με τον χρόνο.

#### Παράδειγμα

```markdown
# Design

## Goal

The goal of this exercise is help students practice how to work with strings.

## Notes

This exercise does not contain any error handling tests.
```

### Αρχείο: `.meta/config.json`

**Σκοπός:** Περιέχει μεταπληροφορίες για την άσκηση.

**Παρουσία:** Απαιτείται

Αυτό το αρχείο περιέχει μεταπληροφορίες για την άσκηση:

- `authors`: Το όνομα χρήστη (ή τα ονόματα χρήστη) στο GitHub του συγγραφέα (ή των συγγραφέων) της άσκησης (προαιρετικό)
  - Συμπεριλαμβανομένων των αξιολογητών αν οι αξιολογήσεις τους αλλάζουν ουσιαστικά την άσκηση (σε βαθμό που να νιώθεις ότι "φτάσατε εκεί μαζί")
- `contributors`: Το όνομα χρήστη (ή τα ονόματα χρήστη) στο GitHub του συνεισφέροντα (ή των συνεισφερόντων) της άσκησης (προαιρετικό)
  - Συμπεριλαμβανομένων των αξιολογητών αν οι αξιολογήσεις τους είναι ουσιαστικές/εφαρμόσιμες/έχουν εφαρμοστεί.

- Κάθε track πρέπει να επαληθεύει ότι το παράδειγμα υλοποίησης περνά τις δοκιμές στη ρύθμιση συνεχούς ενσωμάτωσης του.
- Οι μέντορες δεν θα βλέπουν αυτόν τον κώδικα.
- Το αρχείο παραδείγματος _δεν_ εμφανίζεται στον μαθητή όταν προγραμματίζει μέσα στον περιηγητή και _δεν_ κατεβαίνει στο σύστημα αρχείων του μαθητή όταν χρησιμοποιεί τη γραμμή εντολών.
- Οι σχετικές διαδρομές προς το αρχείο (ή τα αρχεία) παραδείγματος υλοποίησης πρέπει να καθορίζονται στο [`"files.example"` κλειδί του αρχείου `.meta/config.json`](./#filemetaconfigjson).

#### Παράδειγμα

```csharp
using System.Linq;

public static class Isogram
{
    public static bool IsIsogram(string word)
    {
        var lowerCaseLetters = word.ToLower().Where(char.IsLetter).ToList();
        return lowerCaseLetters.Distinct().Count() == lowerCaseLetters.Count;
    }
}
```

### Αρχείο: Πρόσθετα αρχεία

**Σκοπός:** Πρόσθετα αρχεία έργου, μεταγλώττισης ή υποστήριξης που απαιτούνται για να μπορούν να εκτελεστούν οι δοκιμές.

**Παρουσία:** Απαιτείται αν τα προεπιλεγμένα αρχεία δεν αρκούν για την εκτέλεση των δοκιμών

Κάποιες γλώσσες απαιτούν πρόσθετα αρχεία για να εκτελεστούν οι δοκιμές. Παραδείγματα αυτών είναι τα αρχεία έργου της C# και τα αρχεία `package.json` της Node, χωρίς τα οποία δεν θα είναι δυνατή η εκτέλεση των δοκιμών.

## Κοινόχρηστα αρχεία

Κάποια αρχεία δεν αφορούν μεμονωμένες ασκήσεις, αλλά ισχύουν για _όλες_ τις ασκήσεις. Δες την [τεκμηρίωση](/docs/building/tracks/shared-files) για περισσότερες πληροφορίες.

## Παρουσίαση

Υπάρχει διαφορά στον τρόπο με τον οποίο παρουσιάζεται η τεκμηρίωση μιας άσκησης στον μαθητή: ο επεξεργαστής μέσα στον περιηγητή εναντίον της γραμμής εντολών. Δες [αυτό το έγγραφο](/docs/building/tracks/presentation) για περισσότερες πληροφορίες.

### Εικονίδιο

Κάθε άσκηση έχει ένα [συνοδευτικό εικονίδιο][exercise-icons].
Από προεπιλογή, το εικονίδιο που εμφανίζεται είναι αυτό του οποίου το όνομα ταιριάζει με το slug της άσκησης.
Μπορείς να το παρακάμψεις αυτό καθορίζοντας την ιδιότητα `icon` στο αρχείο `.meta/config.json` της άσκησης.

Αν υλοποιείς μια άσκηση από τα [μεταδεδομένα problem-specifications][problem-specifications-exercises], πιθανότατα υπάρχει ήδη ένα εικονίδιο για αυτή την άσκηση.
Αν όχι, [άνοιξε ένα issue στο αποθετήριο website-icons][website-icons-issues].
