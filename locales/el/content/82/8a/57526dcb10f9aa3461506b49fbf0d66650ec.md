# Σχετικά

Ο κώδικας assembly που γράφεται στο χέρι είναι γεμάτος επαναλήψεις.
Η ίδια σύντομη ακολουθία εντολών εμφανίζεται ξανά και ξανά, με ελάχιστες παραλλαγές, και οι αφαιρέσεις που μειώνουν τον επαναλαμβανόμενο κώδικα είναι λίγες.
Και όχι μόνο αυτό: ο προγραμματισμός σε assembly απαιτεί τη διαχείριση τιμών χωρίς προφανή σημασιολογία.
Δεν υπάρχουν ονομαστικές παράμετροι και ο προγραμματιστής πρέπει να χειρίζεται χειροκίνητα τις περισσότερες λεπτομέρειες του υποκείμενου μηχανισμού.

Ο NASM, ο assembler που χρησιμοποιεί το track, προσφέρει κάποια εργαλεία που μπορούν να βοηθήσουν τον προγραμματιστή και με τα δύο ζητήματα.
Αυτά τα εργαλεία εκτελούνται σε _χρόνο συμβολομετάφρασης_, προτού φτάσει οποιαδήποτε εντολή στον επεξεργαστή.
Καθοδηγούν τον assembler στο πώς να ξαναγράψει το κείμενο του πηγαίου κώδικα προτού αυτό μεταφραστεί ακόμη και σε κώδικα μηχανής.

Το σημαντικότερο από αυτά τα εργαλεία είναι οι **μακροεντολές**, που μπορούν να ιδωθούν σαν μια συνταγή για τον assembler.
Επεκτείνονται στο σημείο όπου χρησιμοποιούνται, σαν ο κώδικας να είχε γραφτεί εκεί με το χέρι.

[Οι μακροεντολές][macro] μπορούν να πάρουν έναν αριθμό από literal tokens ως παραμέτρους, γεγονός που τις κάνει επαναχρησιμοποιήσιμες σε διαφορετικά περιβάλλοντα.
Ωστόσο, δεν είναι συναρτήσεις: δεν υπάρχει `call`, ούτε `ret`, ούτε μεταβίβαση του ελέγχου σε άλλο σημείο του κώδικα.

## Μακροεντολές μίας γραμμής

Ο απλούστερος ορισμός δίνει ένα όνομα σε μια τιμή ή σε μια σύντομη παράσταση με το `%define`:

```x86asm
%define WIDTH 8
%define BUFFER_SIZE (WIDTH * 16)
```

Κάθε μεταγενέστερη εμφάνιση του `WIDTH` αντικαθίσταται από το `8` πριν από τη συμβολομετάφραση.
Η αντικατάσταση είναι κειμενική, οπότε το όνομα υποκαθίσταται όπου κι αν εμφανίζεται, είτε μέσα σε έναν τελεστέο είτε μέσα σε έναν άλλο ορισμό.

~~~~exercism/note
Για αριθμητικές _σταθερές_, προτίμησε το `equ` αντί για το `%define`.

Μια μακροεντολή μίας γραμμής που δηλώνεται με `%define` επεκτείνεται μόνο όταν χρησιμοποιείται και μπορεί να επαναπροσδιοριστεί ή να καταργηθεί.
Μια σταθερά `equ`, αντίθετα, αξιολογείται στο σημείο του ορισμού και δεν τροποποιείται ποτέ.
~~~~

Ένα `%define` μπορεί επίσης να δεχτεί _ονομαστικές_ παραμέτρους, συμπεριφερόμενο σαν μια μικρή inline συνάρτηση:

```x86asm
%define double(x) ((x) + (x))

    mov eax, double(WIDTH)   ; assembled as mov eax, ((8) + (8))
```

~~~~exercism/caution
Βάλε σε παρενθέσεις και ολόκληρο το σώμα και κάθε παράμετρο.
Με το `%define square(x) x*x`, η κλήση `square(1+1)` επεκτείνεται σε `1+1*1+1`, που είναι `3`.
Γραμμένο ως `%define square(x) ((x)*(x))`, η ίδια κλήση επεκτείνεται σε `((1+1)*(1+1))`, που είναι `4`.
~~~~

Τα ονόματα που ορίζονται με `%define` κάνουν διάκριση πεζών-κεφαλαίων.
Η παραλλαγή `%idefine` κάνει το όνομα να μη διακρίνει πεζά-κεφαλαία, αν αυτό είναι επιθυμητό.

Οι μακροεντολές μίας γραμμής είναι χρήσιμες για να δώσουν νόημα σε διάφορα σημεία του κώδικα.
Αν χρησιμοποιηθούν με προσοχή, βελτιώνουν την αναγνωσιμότητα και μειώνουν την πιθανότητα τυπογραφικών λαθών.
Για παράδειγμα, ένας καταχωρητής που έχει συγκεκριμένο σκοπό μέσα σε μια συνάρτηση μπορεί να οριστεί με βάση τον σκοπό του:

```x86asm
%define COUNTER rcx
    ...
.loop:
    ...
    dec COUNTER
    jnz .loop
    ...
```

## Μακροεντολές πολλών γραμμών

Μια ολόκληρη ακολουθία κώδικα, με οποιονδήποτε αριθμό γραμμών, περικλείεται με το `%macro` και κλείνει με το `%endmacro`.
Ένας αριθμός μετά το όνομα δηλώνει πόσα ορίσματα δέχεται η μακροεντολή, που μπορεί να είναι μηδέν.
Όταν περνούν ορίσματα, χωρίζονται με κόμμα (`,`):

```x86asm
%macro example_macro 0
...
%endmacro
```

Τα ορίσματα στις μακροεντολές πολλών γραμμών δεν έχουν ονόματα.
Αναφέρονται ως `%1`, `%2` και ούτω καθεξής, με τη σειρά που περνούν:

```x86asm
; Multiplies two values, returning the result in the first argument
%macro mult_two 2        ; %1 = accumulator, %2 = value
    imul %1, %2
%endmacro

    mult_two eax, ecx    ; multiplies eax and ecx and returns the result into eax
    mult_two r8, r9      ; multiplies r8 and r9 and returns the result into r8
```

Σημείωσε ότι τα ορίσματα πρέπει να είναι έγκυρη σύνταξη για τις πράξεις που εκτελούνται στο σώμα της μακροεντολής.
Εδώ τα `mult_two eax, ecx` και `mult_two r8, r9` συμβολομεταφράζονται και τα δύο, αλλά το `mult_two eax, cl` όχι, αφού το `imul eax, cl` δεν ορίζεται.

Οι μακροεντολές μπορούν επίσης να δεχτούν οποιονδήποτε αριθμό ορισμάτων.
Αυτό γίνεται με τον συμβολισμό `n-*`, όπου `n` είναι ο ελάχιστος αριθμός ορισμάτων:

```x86asm
%macro multi_args 4-*
    ; this macro may take 4, 5, 6, ... arguments but not just 1 or 2 or 3
%endmacro
```

Σε μια μακροεντολή πολλών γραμμών, το `%0` δηλώνει τον _αριθμό_ των ορισμάτων της μακροεντολής.
Αυτό είναι ιδιαίτερα χρήσιμο σε μακροεντολές που μπορούν να δεχτούν οποιονδήποτε αριθμό ορισμάτων.

### Ετικέτες μέσα σε μια μακροεντολή

Μια μακροεντολή που ορίζει μια συνηθισμένη ετικέτα χαλάει τη στιγμή που θα χρησιμοποιηθεί δύο φορές, γιατί τότε η ετικέτα θα οριστεί κι αυτή δύο φορές.
Για να χρησιμοποιήσεις ετικέτες μέσα σε μια μακροεντολή που μπορεί να κληθεί περισσότερες από μία φορές, πρέπει να βάλεις το πρόθεμα `%%` σε μια τέτοια ετικέτα.
Αυτό δίνει εντολή στον assembler να δώσει στην ετικέτα ένα διαφορετικό, μοναδικό όνομα σε κάθε επέκταση:

```x86asm
; clobbers rcx
%macro clear_n 2         ; %1 = base address, %2 = count of dwords to clear
    xor ecx, ecx
%%loop:
    mov dword [%1 + rcx*4], 0
    inc ecx
    cmp ecx, %2          ; %2 is compared with ecx: it is an immediate or a 32-bit operand
    jb %%loop
%endmacro

    clear_n rdi, 4       ; gets its own %%loop
    clear_n rsi, 8       ; a different %%loop, no clash
```

## Επανάληψη σε χρόνο συμβολομετάφρασης

Μπορείς να επαναλάβεις ένα μπλοκ κώδικα μίας γραμμής χρησιμοποιώντας το [`times`][times].
Αυτό είναι ιδιαίτερα χρήσιμο όταν δηλώνεις επαναλαμβανόμενες τιμές στη μνήμη:

```x86asm
section .data
negative_block: times 16 db -1
; this assembles to 16 db -1 in sequence, i.e., an array of 16 bytes, all equal to -1
```

Για επανάληψη κώδικα πολλών γραμμών, μπορούμε να χρησιμοποιήσουμε το `%rep` αντ' αυτού:

```x86asm
%rep 2          ; number of repetitions: 2
    add rcx, 32
    mov dword [rsi + rcx], 0
%endrep
```

Σημείωσε ότι ο αριθμός των επαναλήψεων δίνεται αμέσως μετά το `%rep` και υπάρχει ένα `%endrep` για να κλείσει το επαναλαμβανόμενο μπλοκ.

Συνηθίζεται να χρησιμοποιείται ένας μετρητής συμβολομετάφρασης μέσα σε ένα μπλοκ `%rep`, όπως ακριβώς ένας βρόχος σε χρόνο εκτέλεσης χρησιμοποιεί έναν μετρητή.
Ενώ μια ακέραια σταθερά συμβολομετάφρασης μπορεί να δηλωθεί με `equ`, όπως έχουμε ήδη δει, για ακέραιες _μεταβλητές_ συμβολομετάφρασης χρησιμοποιούμε αντ' αυτού το `%assign`.
Σε αντίθεση με το `%define`, το `%assign` αξιολογείται αμέσως σε έναν αριθμό και μπορεί να επαναπροσδιοριστεί:

```x86asm
    xor eax, eax
%assign i 0
%rep 4
    add eax, i           ; add 0, then 1, then 2, then 3
%assign i i + 1
%endrep
```

Αφού εκτελεστεί ο προεπεξεργαστής, ο βρόχος έχει εξαφανιστεί και απομένουν τέσσερις εντολές `add`, με τις άμεσες τιμές `0`, `1`, `2` και `3` ενσωματωμένες.
Αυτό είναι ξετύλιγμα βρόχου που το κάνει ο assembler: ούτε καταχωρητής μετρητή ούτε διακλάδωση, μόνο ευθύγραμμος κώδικας.

Μια άλλη συνηθισμένη χρήση του `%rep` είναι ο χειρισμός των ορισμάτων σε μια μακροεντολή που μπορεί να δεχτεί οποιονδήποτε αριθμό τους.
Σε αυτή την περίπτωση, το `%rep` συνδυάζεται συνήθως με το `%rotate`, που περιστρέφει τα ορίσματα μιας μακροεντολής, έτσι ώστε το δεύτερο όρισμα να γίνει πρώτο.
Επανειλημμένες εφαρμογές του `%rotate` κάνουν το τρίτο, μετά το τέταρτο, και ούτω καθεξής όρισμα πρώτο, εξασφαλίζοντας ότι κάθε όρισμα μπορεί να αντιμετωπιστεί με τη σειρά του:

```x86asm
%macro may_args 1-*
    %rep %0 ; repeats for as many times as the number of arguments
        ... ; do something
    %rotate 1
    %endrep
%endmacro
```

## Υπό συνθήκη συμβολομετάφραση

Ο [προεπεξεργαστής][preprocessor] διαθέτει διάφορες συνθήκες.
Επιλέγουν ανάμεσα σε διάφορες διαδρομές, επεκτείνοντας το σώμα τους επί τόπου, αλλά μόνο όταν η συνθήκη τους είναι αληθής.

Τα `%if` ... `%elif` ... `%else` ... `%endif` επιλέγουν έναν κλάδο βάσει αριθμητικού ελέγχου:

```x86asm
%if WIDTH > 4
    mov eax, 2
%elif WIDTH > 2
    mov eax, 1
%else
    mov eax, 0
%endif
```

Τα `%ifdef` και `%ifndef` είναι παρόμοια, αλλά ελέγχουν αν ένα όνομα έχει οριστεί.
Για παράδειγμα, μπορούν να χρησιμοποιηθούν για να διασφαλίσουν ότι τα περιεχόμενα ενός αρχείου συμπεριλαμβάνονται μόνο μία φορά, ακόμη και όταν το αρχείο εισάγεται από περισσότερες από μία πηγές:

```x86asm
%ifndef MY_FILE
%define MY_FILE
... ; whole file here
%endif
```

Μπορεί να πρόσεξες ότι στο τέλος κάθε αρχείου `.asm` σε αυτό το track υπάρχει αυτό το κομμάτι κώδικα:

```x86asm
%ifidn __OUTPUT_FORMAT__,elf64
section .note.GNU-stack noalloc noexec nowrite progbits
%endif
```

Το `%ifidn` συγκρίνει δύο κομμάτια κειμένου για ακριβή αντιστοιχία.
Το ενσωματωμένο `__OUTPUT_FORMAT__` επεκτείνεται στη μορφή εξόδου που ισχύει, οπότε αυτός ο κώδικας ελέγχει αν η μορφή εξόδου είναι `elf64`, δηλαδή η μορφή που χρησιμοποιούν τα συστήματα Linux.
Αν ναι, προστίθεται στο αρχείο αντικειμένου μια σημείωση που δηλώνει τα δικαιώματα που πρέπει να έχει η στοίβα, ένα συνηθισμένο μέτρο ασφαλείας.
Αν όχι, τίποτα δεν αλλάζει.

## Δομές

Για να φτάσεις σε ένα πεδίο μιας καταγραφής στη μνήμη, προσθέτεις τη μετατόπιση byte του πεδίου σε μια διεύθυνση βάσης.
Το να γράφεις αυτές τις μετατοπίσεις ως ακατέργαστους αριθμούς είναι επιρρεπές σε λάθη και κρύβει το νόημά τους.
Τα [`struc`][struc] και `endstruc` δίνουν αντ' αυτού ένα όνομα σε μια διάταξη, μετατρέποντας κάθε πεδίο σε μια συμβολική μετατόπιση που υπολογίζεται σε χρόνο συμβολομετάφρασης.

Μέσα στο μπλοκ, οι οδηγίες δέσμευσης `resb`, `resw`, `resd` και `resq` δεσμεύουν ένα ή περισσότερα byte, λέξεις, διπλές λέξεις ή τετραπλές λέξεις.
Το να βάζεις μια τελεία (`.`) μπροστά από κάθε πεδίο κρατά το όνομά του περιορισμένο στη δομή:

```x86asm
struc thread
    .color:   resd 1     ; offset 0
    .tension: resq 1     ; offset 4 : 0 + 4 (the size of a dword)
    .name:    resb 16    ; offset 12: 4 + 8 (the size of a qword)
endstruc
```

Κάθε όνομα πεδίου πλέον αντιπροσωπεύει τη μετατόπισή του, οπότε το `thread.color` είναι `0`, το `thread.tension` είναι `4` και το `thread.name` είναι `12`.
Ο NASM ορίζει επίσης το `<struc>_size` ως το σύνολο, όπου `<struc>` είναι το όνομα του `struc`.
Για παράδειγμα, εδώ το `thread_size` θα ήταν `4 + 8 + 16 = 28`.

Φτάνεις σε ένα πεδίο προσθέτοντας τη μετατόπισή του σε έναν καταχωρητή βάσης, και το `thread_size` είναι το βήμα από τη μια καταγραφή στην επόμενη:

```x86asm
    mov [rdi + thread.color], eax        ; write the color field
    mov ecx, [rdi + thread.tension]      ; read the tension field
    add rdi, thread_size                 ; advance to the next record
```

Ένα `struc` περιγράφει μόνο μια μορφή, δεν δεσμεύει μνήμη από μόνο του.
Για να δημιουργήσεις ένα αρχικοποιημένο στιγμιότυπο, μπορείς να χρησιμοποιήσεις `istruc ... iend` μετά από κάποια ετικέτα.
Μέσα σε ένα στιγμιότυπο, το `at` τοποθετεί μια τιμή σε ένα επώνυμο πεδίο:

```x86asm
warp_thread:
istruc thread
    at thread.color,   dd 0x00FF00
    at thread.tension, dq 7
    at thread.name,    db "warp", 0
iend
```

Σημείωσε ότι το `thread.name` αρχικοποιείται με `"warp", 0`, που πιάνει μόνο 5 byte.
Τα άλλα 11 byte που του έχουν δεσμευτεί στο `struc` γεμίζουν αυτόματα με μηδενικά από το `iend`, το οποίο συμπληρώνει το στιγμιότυπο μέχρι το `thread_size` με `0`.

Ένα `struc` είναι απλώς συντακτική ζάχαρη για μνήμη που μπορούμε να δηλώσουμε και χειροκίνητα.
Για παράδειγμα, ο παραπάνω κώδικας είναι ισοδύναμος με τον εξής, όπου το `times 11 db 0` εξασφαλίζει ότι δεσμεύονται 16 byte στο τέλος:

```x86asm
warp_thread:
    dd 0x00FF00
    dq 7
    db "warp", 0
    times 11 db 0
```

## Χωρισμός σε αρχεία

Οι μακροεντολές συχνά κρατούνται σε δικό τους αρχείο και εισάγονται σε κάθε πηγαίο αρχείο που τις χρειάζεται με το `%include`:

```x86asm
%include "patterns.mac"
```

Το αρχείο που κατονομάζεται εισάγεται αυτολεξεί σε εκείνο το σημείο, πριν από τη συμβολομετάφραση, ακριβώς σαν να είχαν πληκτρολογηθεί τα περιεχόμενά του εκεί.
Έτσι οι ορισμοί μένουν σε ένα σημείο και πολλά πηγαία αρχεία μπορούν να τους μοιράζονται.

Αν το αρχείο μακροεντολών μπορεί να συμβολομεταφραστεί και μόνο του, θα πρέπει να έχει επέκταση αρχείου `.asm`.
Σημείωσε ότι οι μακροεντολές δεν έχουν σύνδεση.
Ακόμη κι αν το αρχείο μακροεντολών συμβολομεταφραστεί, οι μακροεντολές του είναι ορατές μόνο σε ένα άλλο αρχείο που το εισάγει με `%include`.

Διαφορετικά, ένα αρχείο που προορίζεται μόνο για `%include` μπορεί να έχει οποιαδήποτε επέκταση αρχείου.
Η χρήση είτε του `.asm` είτε του `.mac` είναι μια συνηθισμένη σύμβαση.
