# Σχετικά

Η άσκηση προγραμματισμού παρουσιάζει μια σειρά από ιδιότητες των παραμέτρων:

- Οι παράμετροι που [περνιούνται][passing-parameters] χωρίς τροποποιητή (όπως `out` ή `ref`) περνιούνται κατά τιμή. Δηλαδή, η παράμετρος μπορεί να χρησιμοποιηθεί και να της ανατεθεί τιμή μέσα στην καλούμενη μέθοδο, αλλά οποιαδήποτε αλλαγή δεν θα έχει καμία επίδραση στον καλούντα.
- Όταν μια αναφορά σε έναν πίνακα ή ένα στιγμιότυπο μιας κλάσης είναι παράμετρος, τα στοιχεία/πεδία αυτού του στιγμιότυπου μπορούν να αλλάξουν από την καλούμενη μέθοδο και οι αλλαγές να φανούν στον καλούντα. Αυτό ισχύει ανεξάρτητα από το αν υπάρχει ο τροποποιητής `ref`.
- Μια παράμετρος με τον τροποποιητή [`out`][out-parameter] μεταφέρει μια τιμή πίσω από την καλούμενη μέθοδο στον καλούντα. Η παράμετρος μπορεί να περαστεί στην καλούμενη μέθοδο χωρίς να έχει αρχικοποιηθεί και σε κάθε περίπτωση αντιμετωπίζεται μέσα στην καλούμενη μέθοδο σαν να μην είχε αρχικοποιηθεί κατά την είσοδο. Η κατανόηση της συμπεριφοράς και των κανόνων που αφορούν τους τροποποιητές παραμέτρων αποκτάται ευκολότερα μέσα από παραδείγματα (δείτε παρακάτω) και μηνύματα του μεταγλωττιστή.

```csharp
void Foo(out int val)
{
    val = 42;
}
void Bar(int val)
{
    val = 42;
}

int importantValue = 1729;
Foo(out importantValue);
var result = importantValue == 42;
// => true

importantValue = 1729;
Bar(importantValue);
result = importantValue == 1729;
// => true
```

- Στις παραμέτρους `out` πρέπει να ανατίθεται τιμή μέσα στην καλούμενη μέθοδο.

- Μια παράμετρος με τον τροποποιητή [`ref`][ref-parameter] περνά μια τιμή μέσα στην καλούμενη μέθοδο. Όταν η μέθοδος επιστρέψει, ο καλών θα βρει σε αυτή την παράμετρο οποιεσδήποτε ενημερώσεις έκανε η καλούμενη μέθοδος.

```csharp
void Foo(ref int val)
{
    val *= 7;
}

int importantValue = 6;
Foo(ref importantValue);
return importantValue;
// => 42
```

-`ref` parameters must be variables as the called method will be operating directly on the parameter as seen by the caller.

- Οι τροποποιητές `out` και `ref` απαιτούνται τόσο στην υπογραφή της καλούμενης μεθόδου όσο και στο σημείο κλήσης.
- Οι παράμετροι `out` μπορούν να δηλωθούν ενσωματωμένα στο σημείο κλήσης, δηλαδή: `Foo(out int importantValue);`
- Αν καλέσεις μια μέθοδο που έχει παραμέτρους `out` αλλά δεν σε ενδιαφέρει η τιμή που ανατίθεται σε μία ή περισσότερες από αυτές, τότε μπορείς να χρησιμοποιήσεις την εικονική μεταβλητή [discard][discard] `_`, όπως στο: `Foo(out int _);`

Όλοι οι κανόνες που αφορούν τις παραμέτρους `ref` και `out` επιβάλλονται από τον μεταγλωττιστή.

Υπάρχουν επίσης παράμετροι [`in`][in-parameter], αλλά είναι κυρίως βελτιστοποίηση απόδοσης και συζητούνται στην άσκηση `structs`, όπου είναι πιο σχετικές.

Η τεκμηρίωση που συνδέεται παραπάνω συνοψίζεται στη συνέχεια:

- [passing-parameters][passing-parameters]: εξηγεί πώς μπορούν να περαστούν τιμές ως ορίσματα. Σημείωσε ότι το θέμα των struct + παραμέτρων συζητείται στην άσκηση `structs`.
- [ref-parameter][ref-parameter]: περιγράφει πώς λειτουργούν οι παράμετροι `ref`.
- [out-parameter][out-parameter]: περιγράφει πώς λειτουργούν οι παράμετροι `out`.

Όταν μελετάς την τεκμηρίωση, πρόσεξε ότι χρησιμοποιεί τους εξής όρους:

- παράμετρος / τυπική παράμετρος: αναφέρεται στην παράμετρο όπως τη βλέπει η καλούμενη μέθοδος.
- όρισμα: αναφέρεται στην παράμετρο όπως τη βλέπει ο καλών.

[Θα μπορούσε να υποστηριχθεί][so-tuples-vs-out] ότι μεγάλο μέρος της αξίας των παραμέτρων `out` έχει εξαλειφθεί με την εισαγωγή των `tuples` στην C# 7. Η άσκηση `tuples` δείχνει τα `tuples` να χρησιμοποιούνται για την επιστροφή πολλαπλών τιμών.

Αν και το `ref` είναι εύκολο στη χρήση και δεν έχει επιπτώσεις στην απόδοση, αξίζει να δεις πώς τα προβλήματα που αντιμετωπίζει χειρίζονται σε μια συγκεκριμένη βάση κώδικα πριν το χρησιμοποιήσεις ευρέως. Υπάρχουν εναλλακτικές, όπως το πέρασμα κατά τιμή και η χρήση της τιμής από την εντολή return της καλούμενης μεθόδου. Και πάλι, τα `tuples` μπορούν να παίξουν ρόλο.

Θα δεις από την [τεκμηρίωση][ref-parameter] ότι τα `out` και `ref` δεν μπορούν να χρησιμοποιηθούν σε ορισμένες περιπτώσεις, αλλά μπορείς να τις αγνοήσεις για την ώρα. Ο μεταγλωττιστής θα σου πει πότε προκύπτουν τέτοιες περιπτώσεις.

Σημείωσε ότι τα `optional parameters` και τα `named arguments` συζητούνται στην άσκηση `method-overloading`.

Τα σχετικά θέματα του [`ref local`][ref-local] και του [`ref return`][ref-return] συζητούνται αλλού.

## Δεσμεύσεις στη στοίβα

Οι κανόνες που αφορούν τις παραμέτρους και τους τροποποιητές τους είναι αρκετά απλοί ώστε να τους πάρεις όπως είναι και να τους κατανοήσεις στο επίπεδο αφαίρεσής τους. Ωστόσο, αν σε ενδιαφέρουν οι υποκείμενοι μηχανισμοί και το γιατί αυτές οι λέξεις-κλειδιά μπορεί να κάνουν τη διαφορά στην απόδοση, τουλάχιστον στην περίπτωση των `struct`, τότε θα μπορούσες να ξεκινήσεις από αυτό το [_άρθρο της Wikipedia_][calling-conventions], σημειώνοντας ότι η C# χρησιμοποιεί `stdcall` σε x86/64.

Η ουσία της ιστορίας είναι ότι στην περίπτωση παραμέτρων χωρίς τροποποιητή, η **τιμή** μιας μεταβλητής αντιγράφεται στη στοίβα του προγράμματος για να γίνει διαθέσιμη σε μια καλούμενη ρουτίνα, ενώ για τις παραμέτρους `ref`, `out` και `in` ένας δείκτης (**αναφορά**) στη μνήμη που περιέχει την τιμή τοποθετείται στη στοίβα του προγράμματος και οι τιμές ανατίθενται στη μνήμη στην οποία δείχνει η αναφορά.
