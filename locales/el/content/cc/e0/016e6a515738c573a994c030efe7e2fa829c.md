# Σχετικά

Τα `struct` της C# σχετίζονται στενά με τις `class`.
Έχουν κατάσταση και συμπεριφορά.
Μπορούν να έχουν τα ίδια είδη μελών: κατασκευαστές, μεθόδους, πεδία, ιδιότητες κ.λπ.

Τα πεδία και οι ιδιότητες μπορούν να είναι απλοί τύποι, `struct` ή τύποι αναφοράς.
Τα `struct` ακολουθούν τους ίδιους κανόνες σχετικά με την εμβέλεια, τους κανόνες ανάγνωσης/εγγραφής και τα επίπεδα πρόσβασης όπως οι `class`.

```csharp
enum Unit
{
    Kg,
    Lb
}

struct Weight
{
    private double count;
    private Unit unit;

    public Weight(double count, Unit unit)
    {
        this.count = count;
        this.unit = unit;
    }

    public override string ToString()
    {
        return count.ToString() + unit.ToString();
    }
}

new Weight(77.5, Unit.Kg).ToString();
// => "77.6Kg"
```

Ένα από τα βασικά πράγματα που πρέπει να θυμάσαι είναι ότι όταν ένα struct ανατίθεται σε μια μεταβλητή ή περνάει ως παράμετρος, οι τιμές αντιγράφονται, οπότε οι αλλαγές στην αρχική μεταβλητή δεν επηρεάζουν το αντίγραφο και αντίστροφα.
Συνοψίζοντας, τα `struct` είναι **τύποι τιμών**.

Αυτό το [άρθρο][class-or-struct] συζητά τις διαφορές ανάμεσα στα `struct` και τις `class`.
Θα δεις από το άρθρο ότι τα `struct` τείνουν να είναι ελαφριά και [αμετάβλητα][structs-immutable], αν και αυτή η κατεύθυνση δεν επιβάλλεται (από προεπιλογή) από τον μεταγλωττιστή ή το περιβάλλον εκτέλεσης.

Υπάρχουν μερικά πράγματα που θα συναντήσεις (και για τα οποία ο μεταγλωττιστής θα σου υπενθυμίσει):

1. Τα μέλη ενός `struct` δε μπορούν να αρχικοποιηθούν επιτόπου.
2. Ένα `struct` δε μπορεί να κληρονομηθεί
3. Ένα `struct` έχει πάντα έναν προεπιλεγμένο κατασκευαστή, ακόμη και αν παρέχεται ένας μη προεπιλεγμένος, και δε μπορείς να παρέχεις έναν ρητό κατασκευαστή χωρίς παραμέτρους.

Ως αποτέλεσμα των σημείων 1 και 3 παραπάνω, δεν υπάρχει τρόπος για τον προγραμματιστή ενός `struct` να εμποδίσει τη δημιουργία μη έγκυρων στιγμιοτύπων.

## Συνήθη struct

Θα δεις από την τεκμηρίωση ότι υπάρχει στενή σχέση ανάμεσα στους πρωτογενείς τύπους και τα struct.
Δες το [`Int32/int`][int32] ως παράδειγμα.
Ένα πιο συνηθισμένο παράδειγμα `struct` είναι ο τύπος [`TimeSpan`][time-span].

Τα στιγμιότυπα του `TimeSpan` συμπεριφέρονται σχεδόν σαν αριθμοί, με τελεστές σύγκρισης όπως `>` και `<` και αριθμητικούς τελεστές.
Μπορείς να υλοποιήσεις αυτούς τους τελεστές για τα δικά σου `struct` όταν τους χρειάζεσαι.

Κάτι που αξίζει να σημειώσεις για το `TimeSpan` είναι ότι υλοποιεί έναν αριθμό διεπαφών, π.χ. `IComparable<TimeSpan>`.
Αν και τα `struct` δε μπορούν να κληρονομήσουν άλλα `struct`, μπορούν να υλοποιούν διεπαφές.

## Ισότητα

Ο έλεγχος ισότητας για τα `struct` μπορεί συχνά να είναι πολύ πιο απλός από αυτόν για τις `class`, καθώς από προεπιλογή απλώς συγκρίνει τα πεδία ως προς την ισότητα.
Δε χρειάζεται να παρακάμψεις το `object.Equals()` (ή το `GetHashCode()`).
Να θυμάσαι ότι αν βασίζεσαι στο `Object.GetHashCode()`, πρέπει να διασφαλίζεις ότι τα πεδία που συμμετέχουν στη δημιουργία του κωδικού κατακερματισμού (δηλαδή όλα τα πεδία) δεν αλλάζουν όσο χρησιμοποιείται μια συλλογή κατακερματισμού.
Στην πράξη, αυτό σημαίνει ότι τα struct που χρησιμοποιούνται με αυτόν τον τρόπο θα πρέπει να είναι αμετάβλητα.

Σε αντίθεση με τη μέθοδο `Equals()`, δεν υπάρχει προεπιλεγμένη υλοποίηση των τελεστών ισότητας, `==` και `!=`.
Αν το `struct` σου τους χρειάζεται, τότε θα πρέπει να τους υλοποιήσεις.

Από την άλλη πλευρά, αυτό το [άρθρο][equality] περιγράφει πώς μπορεί να βελτιστοποιηθεί η απόδοση δημιουργώντας τις δικές σου προσαρμοσμένες μεθόδους `Equals()` και `GetHashCode()`, όπως γίνεται συχνά με τις `class`.
Η διαφορά στην περίπτωση αυτής της άσκησης ήταν περίπου 20% σε μια όχι και τόσο αυστηρή σύγκριση, αλλά αυτό μπορεί να είναι προς τα κάτω, επειδή όλα τα πεδία είναι του ίδιου τύπου.
Δες παρακάτω.

Υπάρχουν συζητήσεις στο [διαδίκτυο][equality-performance] σχετικά με βελτιώσεις στην ταχύτητα, όταν δεν παρακάμπτεται η μέθοδος `Equals()`, εφόσον όλα τα πεδία είναι του ίδιου τύπου.
Η διαφορά σε αυτή την άσκηση από τη συμπερίληψη ανόμοιων πεδίων ήταν περίπου 60%.
Αυτό δεν αναφέρεται στην τεκμηρίωση της Microsoft, οπότε το καθιστά μια ατεκμηρίωτη λεπτομέρεια υλοποίησης, και θα πρέπει να αξιοποιείται με σύνεση.

```csharp
public bool Equals(Weight other)
{
    return count.Equals(other.count) && unit.Equals(other.unit);
}

public override bool Equals(object obj)
{
    return obj is Weight other && Equals(other);
}

public override int GetHashCode()
{
    return HashCode.Combine(count, unit);
}
```
