# Εισαγωγή

Η έννοια των συνθηκών εισάγει το `jcc`, την οικογένεια εντολών για διακλάδωση βάσει μιας συνθήκης.
Ένα `jcc` μεταφέρει την εκτέλεση σε άλλο σημείο του προγράμματος μόνο αν ικανοποιείται η συνθήκη του.

Ωστόσο, οι σύγχρονοι επεξεργαστές είναι γρήγοροι και ικανοί να εκτελούν πολλές εντολές παράλληλα.
Θα ήταν πολύ δαπανηρό να ακινητοποιηθεί όλη η εργασία όσο ο επεξεργαστής περιμένει για έναν έλεγχο συνθήκης κατά την εκτέλεση.

Γι' αυτό, εσωτερικά, ο επεξεργαστής δεν περιμένει.
Χρησιμοποιεί έναν **προβλέπτη διακλάδωσης** για να μαντέψει το αποτέλεσμα μιας συνθήκης και αρχίζει να εκτελεί _υποθετικά_ τη διαδρομή που προβλέφθηκε.

Αν η πρόβλεψη είναι σωστή, η εκτέλεση προχωρά σαν να μην υπήρχε διακλάδωση.
Ωστόσο, αν η πρόβλεψη είναι λανθασμένη, ο επεξεργαστής πρέπει να _απορρίψει την εργασία που έγινε_ στη διαδρομή που προβλέφθηκε και να επανεκκινήσει στη σωστή διαδρομή.

Αυτό ονομάζεται **λανθασμένη πρόβλεψη διακλάδωσης** και είναι δαπανηρό, προκαλώντας καθυστέρηση.

Όταν μια διακλάδωση είναι δύσκολο να προβλεφθεί, αυτές οι λανθασμένες προβλέψεις συσσωρεύονται.
Σε αυτές τις περιπτώσεις, είναι μερικές φορές προτιμότερο να αποφεύγεται εντελώς η διακλάδωση, ώστε να εκτελούνται οι ίδιες εντολές ανεξάρτητα από τη συνθήκη.
Κώδικας που επιλέγει μεταξύ τιμών χωρίς `jcc` ονομάζεται **χωρίς διακλαδώσεις**.

Υπάρχουν αρκετοί τρόποι να δομηθεί ο κώδικας ώστε να διακλαδίζεται λιγότερο συχνά, ή ώστε οι διακλαδώσεις που έχει να είναι πιο προβλέψιμες.
Συγκεκριμένα, το x86-64 παρέχει δύο οικογένειες εντολών που χρησιμοποιούνται συνήθως για τη συγγραφή κώδικα χωρίς διακλαδώσεις.

## Υπό Συνθήκη Μετακινήσεις

Η οικογένεια εντολών `cmovcc` αντιγράφει τον τελεστέο πηγής στον προορισμό μόνο αν ικανοποιείται μια συγκεκριμένη συνθήκη.
Διαφορετικά, ο προορισμός παραμένει αμετάβλητος.

Το επίθημα `cc` ακολουθεί την ίδια ονοματολογία όπως στο `jcc`, με την ίδια σημασία:

| εντολή | μετακίνηση αν |
|-------------|--------------------------------------|
| `cmove`     | A == B μετά την `cmp A, B`              |
| `cmovne`    | A != B μετά την `cmp A, B`              |
| `cmovl`     | A < B (με πρόσημο) μετά την `cmp A, B`      |
| `cmovb`     | A < B (χωρίς πρόσημο) μετά την `cmp A, B`    |
| `cmovg`     | A > B (με πρόσημο) μετά την `cmp A, B`      |
| `cmova`     | A > B (χωρίς πρόσημο) μετά την `cmp A, B`    |

Οι κανόνες είναι παρόμοιοι με το `jcc`:

1. Τα `l` και `g` χρησιμοποιούνται για προσημασμένες συγκρίσεις, και τα `b` και `a`, για συγκρίσεις χωρίς πρόσημο.
2. Η προσθήκη `e` σε ένα επίθημα συμπεριλαμβάνει την ισότητα.
3. Η προσθήκη `n` αντιστρέφει τη συνθήκη.
4. Υπάρχουν επίσης παραλλαγές που αναφέρονται στη σημαία που έχει τεθεί.
   Για παράδειγμα, τα `cmovz` και `cmovc`.

Θεώρησε την απόλυτη τιμή ενός προσημασμένου ακέραιου στο `rdi`, που επιστρέφεται στο `rax`.
Γραμμένη με `jcc`, η συνάρτηση επιλέγει ένα από τα δύο μονοπάτια:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Γραμμένη με `cmovcc`, και οι δύο υποψήφιες τιμές υπολογίζονται άνευ όρων και η υπό συνθήκη μετακίνηση επιλέγει μία:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

Η έκδοση χωρίς διακλαδώσεις εκτελεί πάντα τις ίδιες εντολές.
Δεν υπάρχει `jcc` για να μαντέψει ο προβλέπτης.

Ο προορισμός ενός `cmovcc` πρέπει να είναι καταχωρητής.
Η πηγή μπορεί να είναι καταχωρητής ή θέση μνήμης, αλλά όχι άμεση τιμή.

~~~~exercism/note
Στον παραπάνω κώδικα, η εντολή `neg` θέτει αρκετές σημαίες ανάλογα με το αποτέλεσμα, συμπεριλαμβανομένης της σημαίας προσήμου (SF).
Αυτό σημαίνει ότι η `cmp rdi, 0` μπορεί να παραλειφθεί εντελώς:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Για θετικό `rdi`, το `neg` παράγει αρνητικό αποτέλεσμα και SF == 1, οπότε το `cmovs` επαναφέρει το `rdi`.
Για μηδέν ή αρνητικό `rdi`, το `neg` παράγει μη αρνητικό αποτέλεσμα και SF == 0, οπότε το `rax` κρατά την αρνητική τιμή (που είναι η σωστή απόλυτη τιμή).

Αν και η `cmp` είναι ο κύριος τρόπος σύγκρισης τιμών σε κώδικα assembly, πολλές εντολές θέτουν επίσης σημαίες ανάλογα με το αποτέλεσμα τους.
Ο πλήρης κατάλογος των σημαιών που επηρεάζει μια εντολή συνήθως αναφέρεται στην [αναφορά][reference] της.
Για την `neg` συγκεκριμένα, αυτές είναι οι SF, ZF, CF, OF και PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

## Υπό Συνθήκη Θέση

Η οικογένεια εντολών `setcc` θέτει τον τελεστέο προορισμού σε `1` αν ικανοποιείται μια συγκεκριμένη συνθήκη, και σε `0` διαφορετικά.
Ο προορισμός είναι πάντα ένας _τελεστέος 8-bit_.

Το επίθημα `cc` ακολουθεί την ίδια ονοματολογία όπως στα `jcc` και `cmovcc`.
Για παράδειγμα, το `setz` θέτει τον προορισμό σε `1` αν `ZF == 1` και σε `0` διαφορετικά.

Εφόσον ο προορισμός είναι 8-bit, είναι σύνηθες να ακολουθείται το `setcc` από ένα `movzx` όταν χρειάζεται μια μεγαλύτερη τιμή:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Αυτό είναι ένα σύνηθες ιδίωμα για τη μετατροπή ενός αποτελέσματος σύγκρισης σε ακέραιο `0` ή `1`.
