# Εισαγωγή

Ένας *σηματωτής* σε ένα περιπολικό σκάφος ακτοφυλακής τηρεί το ημερολόγιο μηνυμάτων. Οι
ακατέργαστες σημαίες σήματος φτάνουν πλαισιωμένες με χαρακτήρες-δείκτες; οι ενδείξεις πρέπει
να αποδοθούν για μετάδοση; ζεύγη και τριάδες παρατηρήσεων συνοψίζονται επιτόπου. Λίγοι
ιδιωματισμοί από την πρότυπη βιβλιοθήκη της Factor κάνουν την περισσότερη δουλειά.

## `unparse`: από τιμή σε πηγαίο κείμενο

Το [`unparse`][unparse] (στο `prettyprint`) επιστρέφει το κείμενο σε μορφή πηγαίου κώδικα
οποιασδήποτε τιμής:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

Το `unparse` είναι το αντίστροφο του αναλυτή: η αμφίδρομη διαδρομή `dup unparse parse`
ανακατασκευάζει την τιμή. Είναι το σωστό εργαλείο για σειριοποίηση σε μορφή μετάδοσης που ο
παραλήπτης θα αναλύσει ξανά, και το λάθος εργαλείο για έξοδο αναγνώσιμη από ανθρώπους (οι
συμβολοσειρές κρατούν τα εισαγωγικά τους, τα διανύσματα κρατούν το `V{ ... }` τους κ.λπ.).

## Παραλλαγές slice: προβολές, όχι αντίγραφα

Τα `head` και `tail` από το `sequences` *αντιγράφουν* το τμήμα που κρατάς σε μια νέα
ακολουθία. Τα αντίστοιχά τους με κατάληξη `-slice` επιστρέφουν ένα αντικείμενο `slice`, μια
πλειάδα που περιέχει θέση αρχής, θέση τέλους και την υποκείμενη ακολουθία, το οποίο υλοποιεί
το [πρωτόκολλο ακολουθίας][sequence-protocol] χωρίς αντιγραφή:

| λέξη          | αποτέλεσμα                                      |
|---------------|-------------------------------------------------|
| `head`        | `( seq n -- newseq )`: αντιγράφει τα πρώτα n    |
| `head-slice`  | `( seq n -- slice )`: προβολή των πρώτων n      |
| `tail`        | `( seq n -- newseq )`: αντιγράφει από τη θέση n και μετά |
| `tail-slice`  | `( seq n -- slice )`: προβολή από τη θέση n και μετά |
| `head*`       | `( seq n -- newseq )`: αντιγράφει όλα εκτός από τα τελευταία n |
| `head-slice*` | `( seq n -- slice )`: προβολή όλων εκτός από τα τελευταία n |
| `tail*`       | `( seq n -- newseq )`: αντιγράφει τα τελευταία n |
| `tail-slice*` | `( seq n -- slice )`: προβολή των τελευταίων n  |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

Ένα `slice` *είναι* μια ακολουθία, οπότε ό,τι δέχεται μια ακολουθία δέχεται και ένα slice:
τα `length`, `first`, `each` και τα λοιπά λειτουργούν όλα χωρίς αντιγραφή. Οι δοκιμές που
χρειάζεται να συγκρίνουν με μια κυριολεκτική συμβολοσειρά μπορούν να μετατρέψουν με `>string`.

## `?head` και `?tail`: αφαίρεσε έναν δείκτη αν υπάρχει

Οι πλαισιωμένες ενδείξεις φέρουν κείμενο-δείκτη που μπορεί να είναι ή να μην είναι εκεί. Τα
`?head` και `?tail` (στο `splitting`) προσπαθούν να αφαιρέσουν ένα πρόθεμα ή ένα επίθημα,
επιστρέφοντας την (ενδεχομένως συντομευμένη) ακολουθία *και* ένα boolean που δηλώνει αν ο
δείκτης βρέθηκε:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

Το boolean στο τέλος τα κάνει φυσική επιλογή για έναν έλεγχο: συνδύασε το `?head` με `if`
για να διακλαδώσεις ανάλογα με το αν το πλαίσιο ήταν παρόν, ή με `unless` για να απορρίψεις
είσοδο που της λείπει ο αναμενόμενος δείκτης.

## `<repetition>`: N αντίγραφα, εικονικά

Το [`<repetition>`][repetition] (στο `sequences`) είναι άλλη μια εικονική ακολουθία χωρίς
αντιγραφή: το `( len elt -- repetition )` φτιάχνει μια ακολουθία από `len` στοιχεία που είναι
όλα `elt`, χωρίς να δεσμεύει τόσες θέσεις:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

Το `elt` μπορεί να είναι και το ίδιο μια ακολουθία: κάθε αντίγραφο είναι αυτή η ίδια
ακολουθία. Το `concat` στη συνέχεια ενώνει τα αντίγραφα από άκρη σε άκρη:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

Όπως ένα `slice`, το αποτέλεσμα *είναι* μια ακολουθία: τα `length`, `each` και οι φίλοι τους
δουλεύουν απευθείας πάνω της. Χρησιμοποίησέ το για να γεμίσεις έναν κωδικό σήματος σε σταθερό
πλάτος ή για να τοποθετήσεις μια σειρά επαναλαμβανόμενων δεικτών: μετέτρεψε με `>string` (ή
`>array`) μόνο όταν χρειάζεται πραγματικά μια συγκεκριμένη ακολουθία.

## `<clumps>`: επικαλυπτόμενα παράθυρα, εικονικά

Το [`<clumps>`][clumps] (στο `grouping`) είναι μια τρίτη εικονική ακολουθία χωρίς αντιγραφή:
το `( seq n -- clumps )` βλέπει το `seq` ως τη σειρά από *επικαλυπτόμενα* παράθυρα μήκους `n`
πάνω του, με κάθε παράθυρο να είναι ένα slice:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

Μια ακολουθία με `length` ίσο με n δίνει `length - n + 1` παράθυρα. Επειδή κάθε παράθυρο
είναι ένα slice, το ταίριασμα διαδοχικών ενδείξεων δεν κοστίζει αντιγραφή: το `[ first2 ]` σε
κάθε `2`-clump σου δίνει κάθε διαδοχικό ζεύγος για προβολή. (Ο μη επικαλυπτόμενος ξάδελφός
του, το `<groups>`, τεμαχίζει την ακολουθία σε ξεχωριστά μπλοκ αντ' αυτού.)

## Cleave με πολλαπλές εισόδους: `2bi`, `3bi`, `2tri`, `3tri`

Οι απλές λέξεις cleave `bi` και `tri` εφαρμόζουν δύο ή τρεις παραθέσεις σε *μία* είσοδο. Οι
παραλλαγές με πρόθεμα `2` και `3` εφαρμόζουν κάθε παράθεση σε *δύο* ή *τρεις* εισόδους:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

Κάθε παράθεση δέχεται *όλες* τις εισόδους. Χρησιμοποίησέ τα όταν πάνω από μία προβολή
εξαρτάται από το ίδιο ζεύγος (ή την ίδια τριάδα) τιμών, όχι όταν θέλεις να εφαρμοστεί η
*ίδια* πράξη σε κάθε είσοδο ξεχωριστά (αυτό είναι το `bi@` ή το `tri@`).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
