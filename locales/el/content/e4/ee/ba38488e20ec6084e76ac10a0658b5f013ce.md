# Εισαγωγή

## Χαρακτήρες

Μια **κωδικοποίηση χαρακτήρων** είναι μια συγκεκριμένη σύμβαση που χρησιμοποιείται για την αναπαράσταση στοιχείων κειμένου μιας φυσικής γλώσσας ως ακολουθία byte.
Ένα «στοιχείο κειμένου» εδώ μπορεί να είναι οποιαδήποτε μονάδα έχει σημασία σε μια φυσική γλώσσα, για παράδειγμα, γράμματα, κενά, σημεία στίξης, emojis, ιδεογράμματα κ.λπ.

Η NASM (The Netwide Assembler, ο συμβολομεταφραστής που χρησιμοποιείται σε αυτή τη διαδρομή) έχει υποστήριξη για τον ορισμό δεδομένων χρησιμοποιώντας **ASCII**.

Οι σταθερές χαρακτήρων στη NASM μπορούν να έχουν μήκος έως 8 byte και μπορούν να οριστούν χρησιμοποιώντας μονά εισαγωγικά (`'`), διπλά εισαγωγικά (`"`) ή backticks (βαρείες) (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Οι ειδικοί χαρακτήρες πρέπει να ορίζονται σε backticks και να γίνεται escape με `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Σημείωσε ότι δεν υπάρχει ενσωματωμένη υποστήριξη για οποιαδήποτε κωδικοποίηση χαρακτήρων στην x86-64 ως διακριτό τύπο.
Τα δεδομένα στην assembly είναι μια ακολουθία byte και η ερμηνεία αυτών των byte ως χαρακτήρα, αριθμού ή οτιδήποτε άλλου, αφήνεται στον προγραμματιστή.

Για παράδειγμα, ο χαρακτήρας ASCII '0' είναι ένα byte με την τιμή 48.
Έτσι, η αποθήκευση του 48 σε ένα byte είναι ακριβώς το ίδιο με την αποθήκευση του χαρακτήρα ASCII '0':

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Για τον ίδιο λόγο, ο χειρισμός χαρακτήρων γίνεται μετασχηματίζοντας απευθείας τις τιμές σε αυτά τα byte:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## Συμβολοσειρές

Μια **συμβολοσειρά** είναι μια ακολουθία χαρακτήρων.
Στην assembly, συνήθως υλοποιείται ως πίνακας.

Είναι δυνατό να δηλώσεις μια συμβολοσειρά στη NASM με τον ίδιο τρόπο που θα δήλωνες οποιονδήποτε πίνακα:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Μια διαφορά μεταξύ συμβολοσειρών και άλλων πινάκων είναι ότι η NASM υποστηρίζει επίσης τη δήλωση συμβολοσειρών χωρίς κόμμα (`,`) που να χωρίζει τις τιμές.
Είναι επίσης δυνατό να παρεμβάλλονται τιμές με κόμματα:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Σημείωσε ότι, όπως αναφέρθηκε ήδη, οι χαρακτήρες είναι απλώς byte (ή μια ακολουθία byte σε κωδικοποίηση Unicode):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Καθώς κάθε χαρακτήρας ASCII καταλαμβάνει ένα μόνο byte, οποιοδήποτε επόμενο byte σε μεγαλύτερο μέγεθος είναι `0`.
Για παράδειγμα, η δήλωση του `'a'` ως qword (8 byte) σημαίνει ότι το πρώτο byte είναι `'a'` (`97`) και τα άλλα επτά byte είναι όλα `0`.

Για αυτόν τον λόγο, όλα τα παρακάτω είναι ισοδύναμα:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
Στην assembly, οι συμβολοσειρές δεν τερματίζονται αυτόματα από έναν χαρακτήρα ASCII NUL (τιμή `0`).

Όταν συνεργάζεσαι με γλώσσες υψηλότερου επιπέδου, όπως η C, είναι ευθύνη του προγραμματιστή να διασφαλίσει ότι ο σωστός τερματιστής, εάν υπάρχει, προσαρτάται στο τέλος μιας συμβολοσειράς.
~~~~

## Εντολές συμβολοσειρών

Καθώς οι συμβολοσειρές είναι πίνακες, μπορείς να δουλέψεις μαζί τους με τον ίδιο τρόπο όπως με οποιονδήποτε πίνακα, αποαναφέροντας ρητά τη μνήμη:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Επιπλέον, υπάρχουν μερικές εντολές για φόρτωση, μετακίνηση και αποθήκευση τιμών σε ακολουθίες byte στη μνήμη.
Αν και ονομάζονται _εντολές συμβολοσειρών_, μπορούν να χρησιμοποιηθούν με οποιαδήποτε ακολουθία byte στη μνήμη, δηλαδή με οποιονδήποτε πίνακα.

Οι τρεις πιο σημαντικές εντολές συμβολοσειρών είναι οι `lods`, `stos` και `movs`:

| εντολή | τι κάνει |
| --- | --- |
| `lods` | φορτώνει μια τιμή από μια θέση μνήμης που υποδεικνύεται από τον `rsi` στον `rax` |
| `stos` | αποθηκεύει μια τιμή από τον `rax` σε μια θέση μνήμης που υποδεικνύεται από τον `rdi` |
| `movs` | αντιγράφει μια τιμή από μια θέση μνήμης που υποδεικνύεται από τον `rsi` και την αποθηκεύει σε μια θέση μνήμης που υποδεικνύεται από τον `rdi` |

Σημείωσε ότι αυτές οι εντολές _δεν_ δέχονται κανέναν ρητό τελεστέο.
Οι τελεστέοι τους είναι έμμεσοι.

Ως γενικός κανόνας:

1. Όταν ο τελεστέος πηγής τους είναι μια θέση μνήμης, η διεύθυνσή της πρέπει να αποθηκεύεται στον `rsi` (`s` για source).
2. Όταν ο τελεστέος προορισμού τους είναι μια θέση μνήμης, η διεύθυνσή της πρέπει να αποθηκεύεται αντ' αυτού στον `rdi` (`d` για destination).
3. Αν ένας από τους τελεστέους δεν είναι θέση μνήμης, είναι ο καταχωρητής `rax`.

Σημείωσε ότι αυτές οι εντολές κάνουν αυτόματα αποαναφορά των διευθύνσεων μνήμης ανάλογα με τη συγκεκριμένη λειτουργία που εκτελούν.

Όλες μπορούν να λειτουργούν σε διαφορετικά μεγέθη.
Ένα επίθεμα προστίθεται για να δηλώσει αυτό το μέγεθος:

| επίθεμα | σημασία | μέγεθος |
| :----: | ------- | :------ |
| `b` | byte | 1 byte |
| `w` | λέξη | 2 byte |
| `d` | διπλή λέξη | 4 byte |
| `q` | τετραπλή λέξη | 8 byte |

Για παράδειγμα:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

Ενημερώνουν επίσης κάθε διεύθυνση που χρησιμοποιείται κατά το μέγεθος της λειτουργίας.
Αυτή η ενημέρωση γίνεται σύμφωνα με την τιμή της **σημαίας κατεύθυνσης (DF)**:

- Αν η `DF` είναι μηδενισμένη, οι διευθύνσεις _αυξάνονται_ κατά το μέγεθος της λειτουργίας.
- Αν η `DF` είναι ορισμένη, οι διευθύνσεις αντίθετα _μειώνονται_ κατά το ίδιο ποσό.

Το System V ABI ορίζει ότι η σημαία κατεύθυνσης πρέπει να είναι μηδενισμένη κατά την είσοδο στη συνάρτηση.
Έτσι, _η προεπιλεγμένη συμπεριφορά είναι η μνήμη να διαβάζεται/γράφεται σε αύξουσα σειρά διευθύνσεων_.

Η εντολή `cld` μπορεί να χρησιμοποιηθεί για να μηδενίσει τη σημαία κατεύθυνσης, ενώ η εντολή `std`, για να την ορίσει:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
Ο καλών αναμένει η `DF` να έχει μηδενιστεί μετά την επιστροφή οποιασδήποτε καλούμενης συνάρτησης, σύμφωνα με το System V ABI.
Αν ποτέ ορίσεις την `DF`, φρόντισε να τη μηδενίσεις πριν το `ret`.
~~~~

### Rep

Εκτός από αυτές, η εντολή **rep** δεν αλληλεπιδρά άμεσα με τη μνήμη.
Αντ' αυτού, μπορεί να προστεθεί ως πρόθεμα στις άλλες εντολές που αναφέρθηκαν, _επαναλαμβάνοντας_ αυτές τις εντολές.

Όταν έχουν το πρόθεμα `rep`, οι εντολές συμβολοσειρών επαναλαμβάνονται τόσες φορές όσες η τιμή στον `rcx`.
Κάθε φορά, η τιμή στον `rcx` μειώνεται κατά `1`.
Σημείωσε ότι η τιμή στον `rcx` πρέπει να οριστεί πριν χρησιμοποιηθεί η εντολή:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
Σε σύγχρονους επεξεργαστές, οι `rep movs` και `rep stos` είναι συνήθως γρήγορες επιλογές όταν μετακινείς δεδομένα σε μεγάλα μπλοκ.
Οι άλλες εντολές συμβολοσειρών, ακόμη και οι `movs` και `stos` όταν λειτουργούν χωρίς `rep`, ωστόσο, είναι συνήθως πιο αργές από έναν απλό βρόχο.

Μια πιο εμπεριστατωμένη ματιά σε αυτό το θέμα υπάρχει στο [Κεφάλαιο 16.9, "Εντολές συμβολοσειρών", αυτού του βιβλίου αναφοράς][agner-optimization-guide].
