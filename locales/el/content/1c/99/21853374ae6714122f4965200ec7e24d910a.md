# Σχετικά

Τα `interfaces` είναι το κύριο μέσο [αποσύζευξης][wiki-loose-coupling] των χρήσεων μιας κλάσης από την υλοποίησή της. Αυτή η αποσύζευξη παρέχει ευελιξία για τη συντήρηση της υλοποίησης και βοηθά στην υποστήριξη ασφαλούς ως προς τους τύπους γενικής συμπεριφοράς.

Η σύνταξη μιας διεπαφής είναι παρόμοια με αυτή μιας κλάσης ή ενός struct, με τη διαφορά ότι οι μέθοδοι και οι ιδιότητες εμφανίζονται μόνο ως υπογραφή και δεν παρέχεται σώμα.

```csharp
public interface ILanguage
{
    string Speak();
}

public interface IItalianLanguage : ILanguage
{
    string Speak();
    string SpeakItalian();
}

public interface IScriptConverter
{
    string Version { get; set; }
    string ConvertCyrillicToLatin(string cyrillic);
}
```

Η κλάση ή το struct που την υλοποιεί πρέπει να υλοποιεί όλες τις λειτουργίες που ορίζει η διεπαφή.

Οι διεπαφές συνήθως κάνουν ένα ή περισσότερα από τα εξής:

- επιτρέπουν σε πολλές διαφορετικές κλάσεις να αντιμετωπίζονται γενικά από τον κώδικα που τις χρησιμοποιεί. Σε αυτή την περίπτωση οι διεπαφές παίζουν τον ίδιο ρόλο με μια βασική κλάση
- εκθέτουν ένα υποσύνολο λειτουργικότητας για κάποιον συγκεκριμένο σκοπό (όπως η [`IComparable<T>`][icomparable]) ή
- εκθέτουν το δημόσιο API μιας κλάσης, ώστε να μπορούν να συνυπάρχουν πολλαπλές υλοποιήσεις. Ένα παράδειγμα είναι αυτό ενός [test double][wiki-test-double]

```csharp
public class ItalianTraveller : IItalianLanguage
{
    public string Speak()
    {
        return "Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class ItalianTravellerV2 : IItalianLanguage
{
    public string Speak()
    {
        return "migliorata - Ciao mondo";
    }

    public string SpeakItalian()
    {
        return Speak();
    }
}

public class FrenchTraveller : ILanguage
{
    public string Speak()
    {
        return "Ça va?";
    }
}

public class RussianTraveller : ILanguage, IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Speak()
    {
        return "Привет мир";
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}

public class DocumentTranslator : IScriptConverter
{
    public string Version { get; set; } = "1.0";

    public string Translate(string russian)
    {
        throw new NotImplementedException();
    }

    public string ConvertCyrillicToLatin(string cyrillic)
    {
        throw new NotImplementedException();
    }
}
```

Ο κώδικας που χρησιμοποιεί τις παραπάνω διεπαφές και κλάσεις μπορεί:

- να αντιμετωπίζει όλους τους ομιλητές με τον ίδιο τρόπο, ανεξάρτητα από τη γλώσσα.
- να επιτρέπει σε κάποιο υποσύστημα που χειρίζεται τη μετατροπή γραφής να λειτουργεί χωρίς να ενδιαφέρεται για τους συγκεκριμένους τύπους με τους οποίους έχει να κάνει.
- να παραμένει ανεπηρέαστος από τις αλλαγές στον ιταλό ομιλητή, κάτι που είναι βολικό αν ο κώδικας της κλάσης και ο κώδικας του χρήστη συντηρούνται από διαφορετικές ομάδες

Οι διεπαφές χρησιμοποιούνται ευρέως για την υποστήριξη δοκιμών, καθώς επιτρέπουν εύκολο [mocking][so-mocking-interfaces].

Δες αυτό το [άρθρο][dt-interfaces] για λεπτομέρειες σχετικά με το ποιοι τύποι μελών μπορούν να περιλαμβάνονται σε μια διεπαφή.

Οι διεπαφές μπορούν να κληρονομούν από άλλες διεπαφές.

Τα μέλη μιας διεπαφής είναι δημόσια από προεπιλογή.

Οι διεπαφές μπορούν να περιέχουν εμφωλευμένους τύπους, όπως `const` literals, `enums`, `delegates`, `classes` και `structs`. Εδώ, οι διεπαφές λειτουργούν ως [χώροι ονομάτων][wiki-namespaces] με τον ίδιο τρόπο που το κάνουν οι κλάσεις και τα struct, και η συμπεριφορά και η σύνταξη είναι πανομοιότυπες.

Εκ σχεδιασμού, η C# δεν υποστηρίζει πολλαπλή κληρονομικότητα, αλλά διευκολύνει ένα είδος πολλαπλής κληρονομικότητας μέσω των διεπαφών.

Επιπλέον, το ότι ο [πολυμορφισμός μπορεί να υλοποιηθεί μέσω διεπαφών][interface-polymorphism] αποτελεί τη βάση του μηχανισμού των διεπαφών.

## Ρητή υλοποίηση διεπαφών

Μερικές φορές ονόματα μεθόδων και υπογραφές μπορεί να μοιράζονται σε δύο διαφορετικές διεπαφές.
Προκειμένου να παρέχεται μια ξεχωριστή υλοποίηση αυτών των μεθόδων, η C# προσφέρει τη [ρητή υλοποίηση διεπαφών][explicit-implementation]. Σημείωσε ότι για να χρησιμοποιήσεις μια συγκεκριμένη υλοποίηση μιας διεπαφής, πρέπει να μετατρέψεις την παράσταση που αναφέρεται στο αντικείμενο σε αυτή τη διεπαφή. Η ανάθεση, η μετατροπή τύπου ή η πέραση ως παράμετρος το πετυχαίνουν αυτό.

```csharp
public interface IFoo
{
    void X();
}

public interface IBar
{
    void X();
}

public class Census : IFoo, IBar
{
    void IFoo.X()
    {
        Console.Write("This is from Foo");
    }

    void IBar.X()
    {
        Console.Write("This is from Bar");
    }
}

public class User
{
    public void Use()
    {
        IFoo foo = new Census();
        IBar bar = new Census();
        foo.X();
        // => "This is from Foo"
        bar.X();
        // => "This is from Bar"
    }
}
```

Υπάρχουν αρκετές περιπτώσεις χρήσης:

- Σύγκρουση τομέων (όπως φαίνεται παραπάνω) όπου οι μέθοδοι έχουν πανομοιότυπες υπογραφές.
- Μέθοδοι με το ίδιο όνομα αλλά διαφορετικούς τύπους επιστροφής: αν υλοποιήσεις τις δικές σου κλάσεις συλλογών, μπορεί να διαπιστώσεις ότι απαιτείται μια ρητή διεπαφή για το παλιό `IEnumerable.GetEnumerator()`, παράλληλα με το `IEnumerable<T>.GetEnuerator()`. Μπορεί να μη χρησιμοποιήσεις ποτέ αυτή τη διεπαφή, αλλά ο μεταγλωττιστής μπορεί να επιμείνει.
- Μέθοδοι όπου δεν υπάρχει σύγκρουση ονομάτων μεταξύ των διεπαφών, αλλά είναι σκόπιμο η κλάση που υλοποιεί να χρησιμοποιεί το όνομα για κάποιον σχετικό σκοπό: η `IFormattable` έχει μια μέθοδο `ToString()` που δέχεται μια παράμετρο _τύπου μορφοποίησης_ καθώς και μια παράμετρο τύπου `IFormatProvider`. Μια κλάση όπως η `FormattableString` από τη Base Class Library (BCL) έχει τη διεπαφή για να διασφαλίζει ότι μπορεί να χρησιμοποιηθεί από ρουτίνες που δέχονται ένα `IFormattable`, αλλά είναι πιο εκφραστικό για την κύρια έκδοση του `ToString(IFormatProvider)` να παραλείπει την παράμετρο _τύπου μορφοποίησης_, καθώς δεν χρησιμοποιείται στην υλοποίηση και θα μπέρδευε τους χρήστες του API.

## Προεπιλεγμένη υλοποίηση

Η έκδοση 8 της C# αντιμετωπίζει ένα ενοχλητικό πρόβλημα με τα APIs. Αν προσθέσεις μεθόδους σε μια διεπαφή για να επεκτείνεις τη λειτουργικότητα για νέες υλοποιήσεις, τότε είναι απαραίτητο να τροποποιήσεις όλες τις υπάρχουσες υλοποιήσεις της διεπαφής, ώστε να συμμορφώνονται με το συμβόλαιο του API, ακόμα κι αν δεν έχουν κάποια ειδική συμπεριφορά υλοποίησης. Η C# πλέον επιτρέπει να παρέχεται μια _προεπιλεγμένη μέθοδος_ ως μέρος της διεπαφής (οι προγραμματιστές Java θα είναι εξοικειωμένοι). Παλαιότερα, όταν συνέβαινε μια τέτοια αλλαγή, μια _έκδοση 2_ της διεπαφής υπήρχε παράλληλα με την αρχική.

Αυτό το [άρθρο][dt-interfaces] είναι μια εξαιρετική εισαγωγή στις διεπαφές και εστιάζει στην _προεπιλεγμένη υλοποίηση_ και σε άλλες υποστηρικτικές καινοτομίες, όπως τα `static`, `private` και `virtual` μέλη.
