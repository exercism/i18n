# Σχετικά με τη δυνατότητα null

Σε έναν ιδανικό κόσμο, θα μπορούσαμε να βασιστούμε στο ότι τα πάντα είναι καλά ορισμένα, με συγκεκριμένες τιμές και χωρίς κενά.

Αυτό έρχεται σε αντίθεση με την καθημερινή μας εμπειρία, και γι' αυτό πολλές γλώσσες προγραμματισμού έχουν έναν τρόπο να αναπαριστούν την απουσία μιας τιμής: null ή NULL, nil, None, nothing...

Ήταν εύκολο να εισαχθεί (το 1965), αλλά σύντομα προκάλεσε μεταμέλειες.
Ο εφευρέτης του το αποκάλεσε αργότερα ["Σφάλμα του δισεκατομμυρίου δολαρίων"][web-mistake].

Τις τελευταίες δεκαετίες, οι σχεδιαστές γλωσσών έχουν εξερευνήσει πολλούς τρόπους ώστε τα null να είναι διαθέσιμα αλλά (ως επί το πλείστον) ασφαλή.

Η Kotlin έχει μερικές [γενικές αρχές][ref-null-safety], οι οποίες [διαφέρουν σημαντικά από τη Java][ref-java2kotlin].
_Οι διαφορές σημαίνουν ότι η Kotlin έχει ειδική λειτουργικότητα για τη διαλειτουργικότητα με τη Java, αν και οι λεπτομέρειες ξεφεύγουν από το πεδίο αυτής της έννοιας._

- Η Kotlin έχει μια ειδική τιμή `null`.
- Όλοι οι τύποι είναι _εξ ορισμού_ χωρίς δυνατότητα null (δηλαδή δεν μπορούν να είναι `null`).
- Όλοι οι τύποι μπορούν να γίνουν _με δυνατότητα null_, αλλά αυτό πρέπει να γίνει ρητά.
- Οι συναρτήσεις που μπορεί να αποτύχουν με μια εξαίρεση έχουν συνήθως μια παραλλαγή με τιμή επιστροφής που μπορεί να είναι null.
- Ειδική, εξαιρετικά συνοπτική σύνταξη προσπαθεί να κάνει τον έλεγχο και την αντιμετώπιση των null όσο το δυνατόν πιο εύκολη.

## Δημιουργία μεταβλητών με δυνατότητα null

Ένας τύπος μπορεί να αποκτήσει [δυνατότητα null][ref-nullable-type] προσθέτοντας το επίθημα `?` (π.χ. `String?` αντί για `String`).

```kotlin
var a = "Kotlin"  // inferred type is String
a = null          // => Error: Null can not be a value of a non-null type String

var b: String? = "Kotlin"  // nullable type
b = null                   // => b is now null
b == null                  // => true
```

## Χρήσιμοι τελεστές και συναρτήσεις

### Ο [τελεστής ασφαλούς κλήσης][ref-safe-call] `?.`

Για ένα `String` χωρίς δυνατότητα null, μπορούμε να πάρουμε την ιδιότητα `.length`.

Ένα `String?` με δυνατότητα null αποτυγχάνει με την ίδια σύνταξη, αλλά η χρήση του `?.length` επιτρέπει την περίπτωση ενός `null`.
Ο τύπος επιστροφής είναι `Int?`.

```kotlin
var a = "Kotlin"
a.length  // => 6

// b is still null
b.length  // => Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type String?
b?.length // => null
a?.length // => 6
```

Όπως είδαμε στην τελευταία γραμμή παραπάνω, το `?.` λειτουργεί και με τύπους χωρίς δυνατότητα null.

### Ο [τελεστής Elvis][ref-elvis] `?:`

Επεκτείνοντας την ιδέα του τελεστή ασφαλούς κλήσης, ο [τελεστής Elvis][wiki-elvis] μάς επιτρέπει να δώσουμε μια προεπιλεγμένη τιμή που αντικαθιστά το `null`.

```kotlin
// b is still null
b?.length ?: -1  // => -1, in place of null
a?.length ?: -1  // => 6, as before
```

### Ο [τελεστής βεβαίωσης μη-null][ref-not-null] `!!`

Με αυτόν τον τελεστή, ένας τύπος με δυνατότητα null εξαναγκάζεται να αντιμετωπιστεί σαν να μην επιδέχεται null, όταν ο προγραμματιστής είναι σίγουρος γι' αυτό.
Μήπως μερικές φορές καταλαβαίνουμε τη λογική του προγράμματος καλύτερα από έναν υπερβολικά προσεκτικό μεταγλωττιστή;

```kotlin
// b is still a String?
b = "Kotlin?"
b!!.length  // => 7
```

Η ευθύνη είναι πλέον δική μας: αν το `b` είναι ακόμα `null`, παίρνουμε μια `NullPointerException`.

### Η [συνάρτηση `let`][ref-let] `?.let`

Αν περνάμε ένα στοιχείο με δυνατότητα null σε ένα μπλοκ κώδικα, θα μπορούσαμε να κάνουμε συγκεκριμένους ελέγχους null: `if (item != null) { do something }`.

Είναι πιο απλό και πιο ιδιωματικό να χρησιμοποιήσουμε το `item?.let { do something }`.
Το `do something` θα εκτελεστεί μόνο όταν το `item` δεν είναι null.

### Συναρτήσεις του τύπου `somethingOrNone()`

Κάποιες συναρτήσεις μπορεί να αποτύχουν, για παράδειγμα όταν ζητάμε μια άκυρη θέση σε μια συμβολοσειρά ή μια λίστα.

Αντί να πετάξουμε μια εξαίρεση, θα μπορούσαμε να χρησιμοποιήσουμε την [παραλλαγή `...OrNull`][ref-elem-at-or-null] της συνάρτησης, για να πάρουμε (σε αυτή την περίπτωση) μια τιμή επιστροφής `Int?`.

```kotlin
val str = "Kotlin"
str.elementAtOrNull(10)  // => null
str.elementAt(10)  // => StringIndexOutOfBoundsException: String index out of range: 10
```
