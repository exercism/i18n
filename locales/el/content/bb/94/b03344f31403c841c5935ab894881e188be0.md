# Σχετικά


Ήρθε η ώρα να ασχοληθούμε με ένα από τα κεντρικά προγραμματιστικά παραδείγματα της C++: τον αντικειμενοστρεφή προγραμματισμό (OOP).
Ο OOP περιστρέφεται γύρω από τις `classes`, τύπους δεδομένων ορισμένους από τον χρήστη, με το δικό τους σύνολο σχετικών συναρτήσεων.
Θα ξεκινήσουμε από τα βασικά και θα καλύψουμε πιο προχωρημένα θέματα πιο κάτω στο δέντρο της ύλης.

## Μέλη

Οι κλάσεις μπορούν να έχουν **μεταβλητές μέλη** και **συναρτήσεις μέλη**.
Σε αυτά αποκτάς πρόσβαση με τον τελεστή **επιλογής μέλους** `.`.
Όπως ακριβώς οι μεταβλητές έξω από τις `classes`, καλό είναι να αρχικοποιείς τις μεταβλητές μέλη με μια τιμή κατά τη δήλωσή τους.
Αυτή η τιμή θα γίνει τότε η προεπιλογή για τα νέα αντικείμενα που δημιουργούνται από αυτή την κλάση.

## Ενθυλάκωση και απόκρυψη πληροφορίας

Οι κλάσεις δίνουν τη δυνατότητα να περιορίσεις την πρόσβαση στα μέλη τους.
Οι δύο βασικές περιπτώσεις είναι `private` και `public`.
Τα `private` μέλη δεν είναι προσβάσιμα από έξω από την κλάση.
Τα `public` μέλη μπορούν να κληθούν ελεύθερα.
Όλα τα μέλη είναι `private` από προεπιλογή και πρέπει να σημανθούν ρητά για να μπορούν να χρησιμοποιηθούν έξω από την κλάση.

## Βασικό παράδειγμα

Ο ορισμός μιας νέας `class` φαίνεται στο παρακάτω παράδειγμα.
Πρόσεξε το `;` μετά τον ορισμό.

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

Μπορείς να έχεις πρόσβαση σε όλες τις μεταβλητές μέσα από την κλάση.
Ρίξε μια ματιά στη μεταβλητή `damage` μέσα στη συνάρτηση `cast_spell`.
Δεν μπορείς να διαβάσεις ή να αλλάξεις `private` μέλη έξω από την κλάση:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## Κατασκευαστές

Οι κατασκευαστές δίνουν τη δυνατότητα να αναθέτεις τιμές στις μεταβλητές μέλη κατά τη δημιουργία του αντικειμένου.
Έχουν το ίδιο όνομα με την `class` και δεν έχουν τύπο επιστροφής.
Μια κλάση μπορεί να έχει αρκετούς κατασκευαστές.
Αυτό είναι χρήσιμο αν δεν χρειάζεται πάντα να ορίσεις όλες τις μεταβλητές.

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

Οι κατασκευαστές είναι ένα μεγάλο θέμα και έχουν πολλές λεπτομέρειες.
Αν δεν ορίζεις ρητά έναν `constructor` για την `class` σου, τότε (και μόνο τότε) ο μεταγλωττιστής θα κάνει τη δουλειά για σένα.
Αυτό συνέβη στο πρώτο παράδειγμα παραπάνω.
Το αντικείμενο _silverhand_ δημιουργείται καλώντας τον προεπιλεγμένο κατασκευαστή, χωρίς να περαστεί κανένα όρισμα.
Όλες οι μεταβλητές ορίζονται στην τιμή που δηλώθηκε στον ορισμό της κλάσης.
Αν δεν είχες δώσει καμία τιμή σε αυτόν τον ορισμό, οι μεταβλητές μπορεί να έμεναν μη αρχικοποιημένες, κάτι που θα μπορούσε να έχει ανεπιθύμητες συνέπειες.

## Δομές

Οι δομές προέρχονται από τις αρχικές ρίζες της γλώσσας στη C και είναι τόσο παλιές όσο και η ίδια η C++.
Στην πράξη είναι το ίδιο πράγμα με τις `classes`, με μία σημαντική εξαίρεση.
Από προεπιλογή, τα πάντα σε μια `class` είναι `private`.
Οι δομές, αντίθετα, είναι `public` μέχρι να οριστεί κάτι διαφορετικό.
Κατά σύμβαση, η λέξη-κλειδί `struct` χρησιμοποιείται συχνά για **δομές που περιέχουν μόνο δεδομένα**.
Η λέξη-κλειδί `class` προτιμάται για αντικείμενα που πρέπει να διασφαλίζουν ορισμένες ιδιότητες.
Μια τέτοια αναλλοίωτη συνθήκη θα μπορούσε να είναι ότι η `damage` της `class` `Wizzard` σου δεν μπορεί να γίνει αρνητική.
Η μεταβλητή `damage` είναι private και κάθε συνάρτηση που αλλάζει το damage θα διασφάλιζε ότι η αναλλοίωτη διατηρείται.
