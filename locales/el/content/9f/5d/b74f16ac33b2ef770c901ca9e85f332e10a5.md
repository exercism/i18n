# Δομητές συμβολοσειρών

Το `STR` είναι αμετάβλητο, το `FSTR` όχι. Χρησιμοποίησε το `STR` για κείμενο που έχει ολοκληρωθεί και το `FSTR` για κείμενο που ακόμη χτίζεται.

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## Εκχώρησε πάντα το αποτέλεσμα πίσω

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

Το `FSTR` μεγαλώνει με **αποσβεσμένο διπλασιασμό**: όταν του τελειώνει ο χώρος, παίρνει έναν νέο, μεγαλύτερο πίνακα, διπλάσιο σε μέγεθος, και αντιγράφει μέσα σε αυτόν. Έτσι, το αποτέλεσμα είναι συνήθως το ίδιο αντικείμενο και περιστασιακά ένα διαφορετικό. Το να γράφεις `b := b + x` κάθε φορά είναι σωστό και στις δύο περιπτώσεις και είναι ο μόνος τρόπος γραφής που αξίζει να μάθεις.

Ο διπλασιασμός είναι αυτό που κάνει τον συνολικό φόρτο ανάλογο του μήκους και όχι του τετραγώνου του: τα αντίγραφα γίνονται σπανιότερα με τον ίδιο ρυθμό που γίνονται ακριβότερα.

## Γιατί να μην χρησιμοποιείς απλώς το `+` σε `STR`;

Το να ενώσεις έναν σταθερό, μικρό αριθμό κομματιών με `+` είναι σαφές και μια χαρά:

```sather
   return piece + " by " + composer;
```

Το πρόβλημα είναι μόνο ο βρόχος, όπου ο αριθμός των ενώσεων δεν είναι γνωστός όταν γράφεται ο κώδικας. Ένας χονδρικός κανόνας: αν το `+` βρίσκεται μέσα σε ένα `loop`, κατέφυγε στο `FSTR`.

## Χρήσιμες ρουτίνες

| Κλήση | Τι κάνει |
| --- | --- |
| `b + x` | προσθέτει στο τέλος; το `x` μπορεί να είναι `STR`, `CHAR`, `INT`, `BOOL` … |
| `b.size` | πόσους χαρακτήρες έχει μέχρι τώρα |
| `b.str` | ένα ολοκληρωμένο `STR` |
| `b.clear` | το αδειάζει, κρατώντας τον χώρο |

## Ακολουθίες διαφυγής

| Γράφεται | Είναι |
| --- | --- |
| `"\n"` | μια νέα γραμμή |
| `"\t"` | ένα tab |
| `"\""` | ένα διπλό εισαγωγικό |
| `"\\"` | μια ανάστροφη κάθετος |
