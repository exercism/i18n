# Εισαγωγή

Σχεδόν κάθε πρόγραμμα Factor είναι μια ακολουθία λέξεων που καταναλώνουν και παράγουν τιμές στη *στοίβα δεδομένων*. Όταν οι είσοδοι και οι έξοδοι ταιριάζουν καθαρά, ο κώδικας διαβάζεται από αριστερά προς τα δεξιά χωρίς κόπο. Όταν δεν ταιριάζουν, καταφεύγεις στις *λέξεις αναδιάταξης*, και ο κώδικας γίνεται γρήγορα θορυβώδης.

Αυτή η άσκηση σε καθοδηγεί στη βασική λύση του Factor: τους συνδυαστές.

## Λέξεις αναδιάταξης

Οι πιο συνηθισμένες λέξεις αναδιάταξης βρίσκονται στο [`kernel`][kernel]:

```
dup    ( x -- x x )
dupd   ( x y -- x x y )
drop   ( x -- )
swap   ( x y -- y x )
swapd  ( x y z -- y x z )
over   ( x y -- x y x )
pick   ( x y z -- x y z x )
rot    ( x y z -- y z x )
-rot   ( x y z -- z x y )
rotd   ( w x y z -- w y z x )
spin   ( x y z -- z y x )
nip    ( x y -- y )
tuck   ( x y -- y x y )

2dup   ( x y -- x y x y )
3dup   ( x y z -- x y z x y z )
4dup   ( w x y z -- w x y z w x y z )
2drop  ( x y -- )
3drop  ( x y z -- )
4drop  ( w x y z -- )
2nip   ( x y z -- z )
2swap  ( x y z w -- z w x y )
```

Θα έχεις ήδη χρησιμοποιήσει τις `dup` και `swap`. Το `over` δημιουργεί ένα αντίγραφο του *δεύτερου* στοιχείου από την κορυφή, βολικό όταν η ίδια είσοδος πρέπει να τροφοδοτήσει δύο υπολογισμούς:

```factor
! Sum a number with twice itself: x + 2*x
: triple ( x -- 3x ) dup 2 * + ;
```

Αυτό είναι εντάξει για μία χρήση. Αλλά όταν συνδυάζονται σε σειρά, οι ακολουθίες από `dup`, `swap`, `over`, `rot` γίνονται γρήγορα δυσανάγνωστες.

## `keep`: διατήρησε την είσοδο

Το `keep` (στο [`kernel`][kernel]) καλεί μια παράθεση στην κορυφή της στοίβας αλλά αφήνει την αρχική τιμή πάνω από το αποτέλεσμα:

```
keep ( x quot: ( x -- y ) -- y x )
```

```factor
5 [ 2 * ] keep .s
! => 10
! => 5
```

Αυτό αντικαθιστά ένα μοτίβο `dup` και μετά κάτι και μετά αναδιάταξη: όπου θα έγραφες `dup something swap`, μπορείς απλώς να πεις `[ something ] keep`.

## `bi`: δύο συναρτήσεις για μία είσοδο

Το `bi` (στο [`kernel`][kernel]) εφαρμόζει *δύο* παραθέσεις στην ίδια τιμή, αφήνοντας και τα δύο αποτελέσματα στη στοίβα:

```
bi ( x q1 q2 -- r1 r2 )
```

```factor
4 [ sq ] [ neg ] bi .s
! => 16
! => -4
```

Χωρίς το `bi` θα έγραφες `dup sq swap neg`, αρκετά ευανάγνωστο για δύο πράξεις, αλλά ζόρικο για τρεις.

## `tri` και `cleave`: πολλές συναρτήσεις για μία είσοδο

Το `tri` επεκτείνει το `bi` σε τρεις παραθέσεις:

```
tri ( x q1 q2 q3 -- r1 r2 r3 )
```

Το `cleave` (στο [`combinators`][combinators]) είναι η ίδια ιδέα για έναν *πίνακα* με οποιονδήποτε αριθμό παραθέσεων:

```factor
4 { [ ] [ sq ] [ neg ] } cleave .s
! => 4
! => 16
! => -4
```

Η κενή παράθεση `[ ]` λειτουργεί ως ταυτότητα, χρήσιμη όταν μία από τις θέσεις στην κομμένη κάρτα πρέπει να είναι η ίδια η είσοδος.

## `dip` και `2dip`: λειτουργούν από κάτω

Το `dip` (στο [`kernel`][kernel]) καλεί μια παράθεση στις τιμές *κάτω* από την κορυφή της στοίβας, αφήνοντας την κορυφή ανέπαφη. Το `2dip` κάνει το ίδιο αλλά προστατεύει τις *δύο* κορυφαίες τιμές:

```
dip  ( x   quot -- x   )
2dip ( x y quot -- x y )
```

```factor
9 10 11 [ + ] dip .s
! => 19      (9 + 10)
! => 11      (the protected top, restored)

9 10 11 12 [ + ] 2dip .s
! => 19      (9 + 10)
! => 11      (the protected y, originally 11)
! => 12      (the protected x, originally 12)
```

Εδώ το `dip` έκρυψε το `11`, εκτέλεσε το `9 10 +` και έβαλε το `11` πίσω στην κορυφή. Το `2dip` έκρυψε τα `11 12`, εκτέλεσε το `9 10 +` από κάτω και μετά επανέφερε τα `11 12`.

Το `dip` είναι το σωστό εργαλείο όταν η φυσική σειρά ορισμάτων αφήνει την τιμή "διέλευσης" στην κορυφή της στοίβας. Χρησιμοποίησέ το αντί για το σάντουιτς `swap … swap`.

## `bi@`: ίδια πράξη σε δύο τιμές

Το `bi@` (στο [`kernel`][kernel]) εφαρμόζει μία παράθεση σε δύο τιμές της στοίβας:

```
bi@ ( x y quot -- r1 r2 )
```

```factor
3 4 [ sq ] bi@ .s
! => 9
! => 16
```

## `bi*`: διαφορετικές πράξεις σε δύο τιμές

Το `bi*` (στο [`kernel`][kernel]) εφαρμόζει *διαφορετικές* παραθέσεις στις δύο τιμές της στοίβας, την πρώτη παράθεση στη χαμηλότερη τιμή και τη δεύτερη στην κορυφή:

```
bi* ( x y q1 q2 -- r1 r2 )
```

```factor
3 4 [ sq ] [ neg ] bi* .s
! => 9
! => -4
```

Χρησιμοποίησε το `bi@` όταν και οι δύο τιμές δέχονται την ίδια αντιμετώπιση και το `bi*` όταν η καθεμία χρειάζεται τη δική της.

## `tri*`: διαφορετικές πράξεις σε τρεις τιμές

Το `tri*` (στο [`combinators`][combinators]) επεκτείνει το `bi*` σε τρεις τιμές και τρεις παραθέσεις, εφαρμόζοντας κάθε παράθεση σε μία τιμή με τη σειρά:

```
tri* ( x y z q1 q2 q3 -- r1 r2 r3 )
```

```factor
1 2 3 [ sq ] [ neg ] [ 10 * ] tri* .s
! => 1
! => -2
! => 30
```
