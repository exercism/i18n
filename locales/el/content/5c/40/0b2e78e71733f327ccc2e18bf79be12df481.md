# Εισαγωγή

## Σφάλματα

Τα σφάλματα συμβαίνουν. Στην Elixir, ενώ οι άνθρωποι συχνά λένε "άφησέ το να κρασάρει", υπάρχουν στιγμές που χρειάζεται να διασώσουμε την κλήση της συνάρτησης σε μια γνωστή καλή κατάσταση για να εκπληρώσουμε ένα συμβόλαιο λογισμικού. Σε ορισμένες γλώσσες προγραμματισμού, τα σφάλματα χρησιμοποιούνται ως μέθοδος ροής ελέγχου, αλλά στην Elixir αυτό το μοτίβο αποθαρρύνεται. Συχνά μπορούμε να αναγνωρίσουμε συναρτήσεις που μπορεί να πετάξουν ένα σφάλμα μόνο από το όνομά τους: οι συναρτήσεις που πετούν σφάλματα έχουν `!` στο τέλος του ονόματός τους. Αυτό συμβαίνει σε αντιδιαστολή με συναρτήσεις που επιστρέφουν `{:ok, value}` ή `:error`. Δες αυτά τα παραδείγματα από τη βιβλιοθήκη:

```elixir
Map.fetch(%{a: 1}, :b)
# => :error
Map.fetch!(%{a: 1}, :b)
# => raises KeyError
```

## Try/Rescue

Η Elixir παρέχει έναν μηχανισμό για να διασώζεσαι από σφάλματα χρησιμοποιώντας `try .. rescue`

```elixir
try do
  raise RuntimeError, "error"
rescue
  e in RuntimeError -> :error
end
```

Ας εξετάσουμε αυτόν τον μηχανισμό:

- **Γραμμή 1**, το μπλοκ δηλώνεται με `try`.
- **Γραμμή 2**, εδώ τοποθετείται η κλήση της συνάρτησης που μπορεί να πετάξει σφάλμα, στην περίπτωση αυτή καλούμε τη `raise/2`.
- **Γραμμή 4**, στο τμήμα `rescue`, κάνουμε αντιστοίχιση προτύπων στο όνομα του _Module_ του σφάλματος που πετάχτηκε
  - στην αριστερή πλευρά του `->`:
    - το `e` αντιστοιχίζεται στο struct του σφάλματος.
    - το `in` είναι λέξη-κλειδί.
    - το `RuntimeError` είναι το σφάλμα από το οποίο θέλουμε να διασωθούμε.
      - Αν θέλαμε να διασωθούμε από όλα τα σφάλματα, θα μπορούσαμε να χρησιμοποιήσουμε `_` αντί για το όνομα του module ή να παραλείψουμε εντελώς τη λέξη-κλειδί `in`.
  - στη δεξιά πλευρά:
    - οι εντολές που θα εκτελεστούν αν το σφάλμα ταιριάξει.

### Structs σφάλματος

Τα σφάλματα (που μερικές φορές αποκαλούνται και "εξαιρέσεις") από τα οποία διασώζεσαι με αυτόν τον τρόπο είναι structs.
Η διάσωση από σφάλματα στην Elixir γίνεται πολύ σπάνια.
Συνήθως το σφάλμα από το οποίο διασωθήκαμε καταγράφεται ή στέλνεται σε μια εξωτερική υπηρεσία παρακολούθησης και μετά πετιέται ξανά.
Αυτό σημαίνει ότι συνήθως δε μας ενδιαφέρει η εσωτερική δομή του συγκεκριμένου struct σφάλματος.

Στην [έννοια Exceptions][exercism-exceptions] θα μάθεις περισσότερα για τα structs σφάλματος, συμπεριλαμβανομένου του πώς να ορίσεις το δικό σου προσαρμοσμένο σφάλμα.

[exercism-exceptions]: https://exercism.org/tracks/elixir/concepts/exceptions
