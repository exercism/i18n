# Σχετικά

Οι προγραμματιστές συνήθως προσπαθούν να γράψουν τέλειο λογισμικό και συνήθως αποτυγχάνουν.

Τα πράγματα πάνε στραβά, απρόσμενα, και πρέπει να μπορούμε να το αντιμετωπίσουμε.

Κάποιοι σχεδιαστές γλωσσών πιστεύουν ότι προτεραιότητα είναι να εντοπίζεται ένα σφάλμα όσο το δυνατόν γρηγορότερα και μετά να τερματίζεται η εκτέλεση με ένα ενημερωτικό μήνυμα που βοηθά στην αποσφαλμάτωση.

Οι γλώσσες επιστήμης δεδομένων τείνουν να ακολουθούν μια πιο εκλεπτυσμένη προσέγγιση.
Ορισμένα σφάλματα είναι τόσο σοβαρά που ο άμεσος τερματισμός είναι απαραίτητος, αλλά συχνά είναι καλύτερο να επισημαίνεται ένα πρόβλημα ως κάτι που θα αντιμετωπιστεί αργότερα και μετά να συνεχίζεται η εκτέλεση.

Είδαμε στην έννοια [Nothingness][nothingness] ότι η Julia παρέχει διάφορους υποκαταστάτες για προβληματικές τιμές: [`missing`][nothing], [`NaN`][NaN] και `Inf`.
Το αν αυτά αποτελούν καλύτερη προσέγγιση από τον τερματισμό του προγράμματος σε μια συγκεκριμένη περίπτωση είναι θέμα κρίσης του προγραμματιστή.

_Ένα σημείο ονοματολογίας_ πριν μπούμε στις λεπτομέρειες: η τεκμηρίωση της Julia αντιμετωπίζει τις λέξεις "σφάλμα" και "εξαίρεση" ως σε μεγάλο βαθμό εναλλάξιμες.
Το παρακάτω κείμενο μπορεί να είναι εξίσου ασυνεπές.

## Τυπικοί τύποι σφαλμάτων

Σε αυτό το σημείο της ύλης, σίγουρα έχεις δει πολλά μηνύματα σφαλμάτων από τη Julia.
Για παράδειγμα:

```julia-repl
julia> Int(3.14)
ERROR: InexactError: Int64(3.14)
```

Η προσπάθεια μετατροπής ενός float σε ακέραιο συνεπάγεται απώλεια ακρίβειας, οπότε παίρνουμε ένα `InexactError`.

Το `InexactError` είναι ένας τύπος, ένας από αρκετούς ([αυτή τη στιγμή 25][errors]) ενσωματωμένους στη Julia ως τυπικούς.
Όλοι είναι υποτύποι του `Exception`:

```julia-repl
julia> supertype(InexactError)
Exception
```

## `throw()`

Κάποιοι από τους τυπικούς τύπους σφαλμάτων μπορεί να σου φανούν χρήσιμοι για να τους δημιουργήσεις στον δικό σου κώδικα.

Όπως όλοι οι συγκεκριμένοι τύποι, έτσι και τα σφάλματα έχουν κατασκευαστές.
Δέχονται διάφορα ορίσματα, οπότε κοίταξε την [τεκμηρίωση][errors] για αυτόν που θέλεις να χρησιμοποιήσεις.

```julia-repl
julia> DomainError(42, "out of range")
DomainError(42, "out of range")
```

Για να χρησιμοποιήσεις το σφάλμα, τύλιξε τον κατασκευαστή μέσα σε μια συνάρτηση [`throw()`][throw]:

```julia-repl
julia> throw(DomainError(42, "out of range"))
ERROR: DomainError with 42:
out of range
```

## `error()`

Για μια γρήγορη και πρόχειρη λύση, η συνάρτηση [`error()`][error] μπορεί να σου φανεί βολική.
Δέχεται ως όρισμα μια συμβολοσειρά (ή τα μέρη μιας συμβολοσειράς):

```julia-repl
julia> happy = false;
julia> happy || error("😞 something went wrong")
ERROR: 😞 something went wrong
```

## Προσαρμοσμένα σφάλματα

Η δημιουργία νέων τύπων σφαλμάτων είναι καταρχήν πολύ εύκολη.
Απλώς πρόσθεσε έναν ακόμη υποτύπο του `Exception`:

```julia-repl
julia> struct MyError <: Exception end

julia> throw(MyError)
ERROR: MyError
```

Ωστόσο, το παραπάνω παράδειγμα δεν έχει πεδία και ο κατασκευαστής δεν δέχεται ορίσματα, οπότε δεν έχουμε κανέναν έλεγχο πάνω στο μήνυμα του σφάλματος.
Μπορούμε να προσθέσουμε ένα πεδίο μηνύματος:

```julia-repl
julia> struct AnotherError <: Exception
           msg::String
       end

julia> throw(AnotherError("Wrong!"))
ERROR: AnotherError("Wrong!")
```

Το να τυπώσουμε απλώς τον κατασκευαστή δεν είναι ακόμη αρκετά σωστό.
Σύγκρινε με το προηγούμενο παράδειγμα όπου πετάξαμε ένα `DomainError`.

Για να αντιμετωπίζεται ένα προσαρμοσμένο σφάλμα με τον ίδιο τρόπο όπως τα ενσωματωμένα σφάλματα, πρέπει να προσθέσουμε μια μέθοδο [`showerror()`][showerror]:

```julia-repl
julia> Base.showerror(io::IO, e::AnotherError) =
           print(io, "AnotherError: ", e.msg)

julia> throw(AnotherError("Wrong!"))
ERROR: AnotherError: Wrong!
```

Αυτή η μάλλον ελλιπώς τεκμηριωμένη δυνατότητα ουσιαστικά συνδέει τον προσαρμοσμένο τύπο σφάλματός μας με το τυπικό σύστημα χειρισμού σφαλμάτων της Julia.

## Ισχυρισμοί

Η βασική ιδέα ενός ισχυρισμού είναι "αυτή η πρόταση θα έπρεπε να είναι αληθής, οπότε διαμαρτυρήσου έντονα αν είναι ψευδής".
Η αξία του έγκειται κυρίως κατά την αποσφαλμάτωση, καθώς ο κώδικας παραγωγής δεν θα πρέπει ποτέ να αποτυγχάνει σε έναν ισχυρισμό.

Είδαμε στην έννοια [Τύποι][types] ότι μπορούμε να προσθέσουμε ισχυρισμούς τύπων, για παράδειγμα για να ελέγξουμε τον τύπο επιστροφής μιας συνάρτησης.

```julia-repl
julia> 42::Number
42

julia> "two"::Number
ERROR: TypeError: in typeassert, expected Number, got a value of type String
```

Γενικότερα, η μακροεντολή [`@assert`][assert] μας επιτρέπει να ελέγχουμε οποιαδήποτε έκφραση αξιολογείται σε μια τιμή Boolean:

```julia-repl
julia> n = 22;
julia> @assert isodd(n) "n must be odd"
ERROR: AssertionError: n must be odd
```

## `try`...`catch`

Ορισμένα σφάλματα είναι αναγκαστικά θανατηφόρα, αλλά συχνά περιμένουμε το πρόγραμμα να ανακάμψει ομαλά.

Από προεπιλογή, ένα σφάλμα τερματίζει αμέσως την τρέχουσα συνάρτηση και το σφάλμα (μαζί με οποιοδήποτε ενημερωτικό μήνυμα) περνά στη συνάρτηση που την κάλεσε.

Αυτό συνεχίζεται προς τα πάνω στη στοίβα κλήσεων, μέχρι ο κώδικας του ανώτατου επιπέδου να τερματίσει με ένα μήνυμα σφάλματος.

Σε οποιοδήποτε στάδιο, το σφάλμα μπορεί να αναχαιτιστεί με ένα μπλοκ [`try...catch`][try-catch] που επιχειρεί να το χειριστεί.

```julia-repl
julia> n = -1;
julia> try
           log_n = log(n)
       catch problem
           if problem isa DomainError # number out of range
               # See next section for more on @warn and @info
               @warn "you may have supplied a negative real number: $n"
               @info "trying with complex argument"
               log_n = log(Complex(n))  # fallback calculation

           elseif problem isa MethodError # no idea what n is
               @error "please supply a valid argument"
 
           else
              rethrow() # the error could be anything else
           end
      end
┌ Warning: you may have supplied a negative real number: -1
└ @ Main REPL[3]:5
[ Info: trying with complex argument
0.0 + 3.141592653589793im  # success
```

Στο παραπάνω παράδειγμα, το `log(n)` απαιτεί το `n` να είναι είτε μια θετική πραγματική τιμή είτε οποιαδήποτε μιγαδική τιμή.
Το `try ... catch` παγιδεύει προβλήματα με αρνητικές πραγματικές τιμές, επιστρέφοντας τη σωστή μιγαδική απάντηση `iπ` σε μαθηματικό συμβολισμό.

Αν δώσεις, για παράδειγμα, ένα όρισμα συμβολοσειράς, δεν υπάρχει τρόπος ανάκαμψης παρά μόνο να ζητήσεις από τον χρήστη να το διορθώσει.

Ως τελευταία γενική περίπτωση, προσθέσαμε το [`rethrow()`][rethrow] για οτιδήποτε δεν είναι ούτε `DomainError` ούτε `MethodError`.

Υπάρχουν επίσης περισσότερες προαιρετικές ρήτρες:

- [`else`][else], που εκτελείται αν η ρήτρα `try` πετύχει·
- [`finally`][finally], που μπορεί να χρησιμοποιηθεί για τον καθαρισμό εξωτερικών πόρων, ανεξάρτητα από το αν το `try` πετύχει ή αποτύχει: κλείσιμο αρχείων, κλείσιμο συνδέσεων βάσης δεδομένων...

***Σημείωση:*** Μερικές φορές ένα `try...catch` είναι αυτό που χρειάζεσαι, αλλά απόφυγε να το παραχρησιμοποιείς.
Αν μπορεί να χρησιμοποιηθεί αντ' αυτού ένα μπλοκ `if...else`, θα είναι πολύ πιο αποδοτικό από το να πιάνεις εξαιρέσεις.

## Καταγραφή

Σημείωσε ότι η συνάρτηση `error()`, που συζητήθηκε παραπάνω, δεν πρέπει να συγχέεται με τη μακροεντολή [`@error`][error_macro].

Η συνάρτηση δημιουργεί μια εξαίρεση, η οποία θα περάσει προς τα πάνω στη στοίβα κλήσεων αν δεν πιαστεί.

Η μακροεντολή `@error`, μαζί με τις αντίστοιχες [`@debug`][debug_macro], [`@info`][info_macro] και [`@warn`][warn_macro], αποτελεί μέρος της μονάδας [`Logging`][logging] και προορίζεται να δημιουργεί ενημερωτικά μηνύματα χωρίς να μεταβάλλει τη ροή του προγράμματος.

Η έξοδος πηγαίνει στο τερματικό από προεπιλογή (με χρώματα ανάλογα με τη σοβαρότητα), αν και σε μια πραγματική εφαρμογή υπάρχουν πολλές άλλες δυνατότητες.

```julia-repl
julia> @warn "Something looks not quite right"
┌ Warning: Something looks not quite right
└ @ Main REPL[55]:1

julia> @error "Panic!"
┌ Error: Panic!
└ @ Main REPL[56]:1
```

Δες επίσης το προηγούμενο παράδειγμα, στην ενότητα `try...catch`.
