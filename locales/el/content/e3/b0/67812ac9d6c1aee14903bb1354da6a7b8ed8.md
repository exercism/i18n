# Σχετικά

Η μόνη σύμβαση του Factor για τη μεταβίβαση δεδομένων είναι η *στοίβα δεδομένων*: οι λέξεις αφαιρούν από την κορυφή τις εισόδους τους και προσθέτουν εκεί τις εξόδους τους. Κάθε ορισμός λέξης δηλώνει μια *επίδραση στη στοίβα* που τεκμηριώνει αυτό το συμβόλαιο.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

Τα ονόματα μέσα στο `( … -- … )` εξυπηρετούν τον αναγνώστη· αυτό που ελέγχει ο μεταγλωττιστής είναι ο *αριθμός* των εισόδων και των εξόδων. Μια ασυμφωνία είναι σφάλμα κατά τη μεταγλώττιση, το οποίο πιάνει μια κατηγορία από bugs που, σε μια δυναμικά τυποποιημένη γλώσσα χωρίς αυτού του είδους τη δήλωση, θα ήταν σφάλματα κατά τον χρόνο εκτέλεσης.

Επειδή η στοίβα λειτουργεί με βάση τη θέση, χρειάζεται συνεχώς να αναδιατάσσεις την κορυφή της πριν μπορέσει να εκτελεστεί η επόμενη λέξη. Οι **λέξεις αναδιάταξης** του `kernel` κάνουν ακριβώς αυτό:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

Η πλήρης οικογένεια αναδιάταξης τις επεκτείνει με το `-rot` (κυλάει προς την άλλη κατεύθυνση), τα ξαδέρφια με κατάληξη `d` που δρουν ένα στοιχείο πιο βαθιά (`dupd`, `swapd`), τα ξαδέρφια με πρόθεμα `2` που δρουν σε ζεύγη (`2dup`, `2drop`, `2nip`), και άλλα όπως τα `pick` και `tuck`. Παρουσιάζονται όταν τις χρειάζονται οι επόμενες ασκήσεις· το να καταφεύγεις σε πάρα πολλές λέξεις αναδιάταξης μαζί είναι συνήθως σημάδι ότι μια *τοπική μεταβλητή* (τιμή με όνομα) θα ήταν πιο ευανάγνωστη.

Κατά σύμβαση, οι λέξεις χρησιμοποιούν `lowercase-kebab-case`, τα κατηγορήματα τελειώνουν σε `?` και παράγουν ένα boolean (`even?`, `empty?`), τα setter γράφονται `>>name` και τα getter `name>>`, και μια λέξη και η μεταλλακτική παραλλαγή της συχνά έχουν το ίδιο όνομα, που διακρίνονται μόνο από τα συμφραζόμενα.
