# Εισαγωγή

Στη C++, οι δηλώσεις συχνά διαχωρίζονται από τους ορισμούς.
Οι δηλώσεις ομαδοποιούνται σε επονομαζόμενα αρχεία κεφαλίδας, και οι αντίστοιχες υλοποιήσεις τοποθετούνται σε αρχεία πηγαίου κώδικα.
Μπορείς να σκεφτείς τα αρχεία κεφαλίδας ως ένα API.
Το αρχείο κεφαλίδας σου λέει _τι_ έχει να προσφέρει μια βάση κώδικα, χωρίς να μπαίνει στις λεπτομέρειες του _πώς_.

## Κεφαλίδα και πηγαίος κώδικας

Η πιο συνηθισμένη επέκταση αρχείου για αρχεία κεφαλίδας είναι το `.h`.
Κάποια έργα χρησιμοποιούν `.hpp` ή παραλείπουν εντελώς την επέκταση.

Οι ορισμοί βρίσκονται σε ένα ξεχωριστό αρχείο `.cpp`.
Για να ενωθούν ξανά τα μέρη, το αρχείο πηγαίου κώδικα ξεκινά _συμπεριλαμβάνοντας_ το αντίστοιχο αρχείο κεφαλίδας.

Αν θέλεις να γράψεις μια βιβλιοθήκη με το όνομα "quick_math" που προσφέρει μια συνάρτηση "super_root" που θέλεις να χρησιμοποιείς συχνά, τα αρχεία θα έμοιαζαν κάπως έτσι:

```cpp
// A file named quick_math.h
#pragma once

namespace quick_math {

double super_root(double x, int n);

}  // namespace quick_math
```

```cpp
// A file named quick_math.cpp
#include <cmath>

#include "quick_math.h"

double quick_math::super_root(double x, int n) {
    while (n) {
        x = std::sqrt(x), --n;
    }
    return x;
}
```

Αν χρειάζεται να συμπεριλάβεις μια κεφαλίδα που απαιτείται μόνο από την υλοποίηση, η αντίστοιχη γραμμή `#include` χρειάζεται μόνο στο αρχείο πηγαίου κώδικα.
Ό,τι συμπεριλαμβάνεται στην κεφαλίδα είναι επίσης διαθέσιμο στο αρχείο `.cpp`, όπως η βιβλιοθήκη `string` στο παρακάτω παράδειγμα.
**Προσοχή**: το `;` χρειάζεται μετά τη δήλωση στο αρχείο κεφαλίδας, αλλά όχι μετά τον ορισμό στο αρχείο πηγαίου κώδικα.

## Κλάσεις και κεφαλίδες

Οι κλάσεις μπορούν να γίνουν πολύ περίπλοκες και η σχέση τους με τον διαχωρισμό κεφαλίδας / πηγαίου κώδικα μπορεί να μπερδέψει.
Μια πιθανή διάταξη είναι να κρατήσεις όλες τις λεπτομέρειες υλοποίησης στο αρχείο πηγαίου κώδικα και όλες τις δηλώσεις και τις μεταβλητές μέλους στην κεφαλίδα:

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0);
    void give_water();
    std::string get_name();
    int get_size();
    void start_next_day();
};

}  // namespace robots

#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"

robots::Flower::Flower(std::string name, int size) {
    this->name = "Robotica " + name;
    this->size = size;
}

void robots::Flower::start_next_day() {
    if (!needs_water) {
        ++size;
    }
    needs_water = true;
}

std::string robots::Flower::get_name() { return name; }

int robots::Flower::get_size() { return size; }
```

Όταν η κεφαλίδα χρησιμοποιείται ως επισκόπηση του API, εκεί θα κοίταζε κάποιος για πληροφορίες όπως οι προεπιλεγμένες τιμές.
Η προεπιλεγμένη τιμή της παραμέτρου `size` του κατασκευαστή ορίζεται επομένως στην κεφαλίδα και όχι στην υλοποίηση.
Οι ορισμοί στο αρχείο πηγαίου κώδικα έχουν μπροστά τον χώρο ονομάτων `robots` και τον τύπο της κλάσης `Flower`.

Μια άλλη επιλογή διάταξης είναι μια βιβλιοθήκη _μόνο με κεφαλίδα_, που δεν έχει καθόλου αρχείο `.cpp`:

```cpp
// A file named robot_flower.h
#pragma once

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0) {
        this->name = "Robotica " + name;
        this->size = size;
    }
    void give_water() { needs_water = false; }
    std::string get_name() { return name; }
    int get_size() { return size; }
    void start_next_day() {
        if (!needs_water) {
            ++size;
        }
        needs_water = true;
    }
};

}  // namespace robots
```

Τα έργα μπορεί να χρησιμοποιούν συνδυασμούς αυτών των διατάξεων και γίνεται μεγάλη συζήτηση για το ποια ταιριάζει καλύτερα σε κάθε περίπτωση.

## Φρουροί συμπερίληψης

Ίσως πρόσεξες τη γραμμή `#pragma once` στο παραπάνω παράδειγμα αρχείου κεφαλίδας.
Αυτό ονομάζεται φρουρός συμπερίληψης και εξασφαλίζει ότι το περιεχόμενο του αρχείου συμπεριλαμβάνεται μόνο μία φορά κατά τη μεταγλώττιση, ώστε να αποφεύγονται σφάλματα.
Υπάρχει μια άλλη, πιο περίπλοκη παραλλαγή ενός φρουρού συμπερίληψης που ξεκινά με `#ifndef` και τελειώνει με `#endif`.
Εξυπηρετεί τον ίδιο σκοπό και η χρήση του φαίνεται στο παραπάνω παράδειγμα της κλάσης `Flower`.
