# Σχετικά με τα bit

Τα δυαδικά ψηφία αντιστοιχούν τελικά απευθείας στα τρανζίστορ του επεξεργαστή ή της μνήμης σου, και στο αν το καθένα είναι "αναμμένο" ή "σβηστό".

Ο χειρισμός χαμηλού επιπέδου, που ανεπίσημα αποκαλείται "bit-twiddling", είναι ιδιαίτερα σημαντικός στις γλώσσες συστημάτων.

Γλώσσες υψηλότερου επιπέδου, όπως η Kotlin, συνήθως κρύβουν τις περισσότερες από αυτές τις λεπτομέρειες.
Ωστόσο, μια βασική σειρά πράξεων σε επίπεδο bit [είναι διαθέσιμη][ref-bitwise].

~~~~exercism/note
Για να δεις δυαδική έξοδο σε μορφή αναγνώσιμη από τον άνθρωπο, σχεδόν όλα τα παρακάτω παραδείγματα πρέπει να τυλιχτούν σε μια συνάρτηση [`Integer.toBinaryString()`][web-binstring] ή να μετατραπούν με `toString(radix = 2)`.
 
Αυτό αποσπά οπτικά την προσοχή, οπότε οι περισσότερες εμφανίσεις αυτής της συνάρτησης έχουν αφαιρεθεί, και τα αποτελέσματα αναπαρίστανται με συμβολισμό `0b`.

## Πράξεις ολίσθησης bit

Οι τύποι `Int` ή `Long`, τόσο με πρόσημο όσο και χωρίς, μπορούν να αναπαρασταθούν ως συμβολοσειρά από 1 και 0, και να υποστούν χειρισμό ως ακολουθία bit.

Ίσως παραδόξως, οι τύποι `Byte` ή `Short` δεν είναι συμβατοί με τις περισσότερες πράξεις bit στην Kotlin.
Όλα τα παρακάτω παραδείγματα χρησιμοποιούν ακέραιους 32 bit (`Int` ή `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

Οι ολισθήσεις bit μετακινούν τα πάντα προς τα αριστερά ή τα δεξιά κατά έναν καθορισμένο αριθμό θέσεων.
Κάποια bit πέφτουν έξω από το ένα άκρο και το άλλο άκρο γεμίζει με μηδενικά ή άσσους.

- Αριστερή ολίσθηση με `shl`: γέμισμα με μηδενικά.
- Δεξιά ολίσθηση με `shr` ή `ushr`: γέμισμα με μηδενικά για τους θετικούς αριθμούς (δες την επόμενη ενότητα για τους αρνητικούς αριθμούς).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Κάθε αριστερή ολίσθηση διπλασιάζει την τιμή και κάθε δεξιά ολίσθηση τη μειώνει στο μισό (με αποκοπή, όπου χρειάζεται).
Αυτό φαίνεται πιο καθαρά στη δεκαδική αναπαράσταση:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Αυτού του είδους η ολίσθηση bit είναι πολύ ταχύτερη από την "κανονική" αριθμητική, κάτι που κάνει την τεχνική ιδιαίτερα δημοφιλή στον προγραμματισμό χαμηλού επιπέδου.

### Ολίσθηση bit σε αρνητικούς ακέραιους

Με τους _αρνητικούς ακέραιους_, χρειάζεται να είμαστε λίγο πιο προσεκτικοί.

Οι αρνητικές τιμές αποθηκεύονται σε μορφή [συμπληρώματος ως προς δύο][wiki-2complement], που σημαίνει ότι το αριστερότερο bit είναι 1.
Δεν υπάρχει πρόβλημα με την αριστερή ολίσθηση, αλλά όταν κάνουμε δεξιά ολίσθηση, πώς γεμίζουμε τα αριστερότερα bit;

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

Ο τελεστής [`shr`][ref-shr] εκτελεί [αριθμητική ολίσθηση][wiki-arithmetic], διατηρώντας το bit προσήμου.

Ο τελεστής [`ushr`][ref-ushr] εκτελεί [λογική ολίσθηση][wiki-logical], γεμίζοντας με μηδενικά σαν να ήταν ο αριθμός χωρίς πρόσημο.

## Λογικές πράξεις bit

Είδαμε στην [έννοια Booleans][concept-booleans] ότι οι τελεστές `&&` (and), `||` (or) και `!` (not) χρησιμοποιούνται με τιμές Boolean (λογικές).

Υπάρχουν αντίστοιχοι τελεστές `and`, `or`, `xor` ([αποκλειστικό ή][wiki-xor]) για τη σύγκριση των bit δύο ακεραίων, και μια συνάρτηση `inv` (αντιστροφή) για να αντιστρέψεις όλα τα bit.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
