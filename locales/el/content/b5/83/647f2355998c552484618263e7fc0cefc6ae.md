# Οδηγίες

Είναι η βραδιά της πρεμιέρας στο Grand Marquee, και όλο το προσωπικό δουλεύει ταυτόχρονα.
Το πλήθος μπαίνει από κάθε πόρτα, αρκετά ταμεία πουλάνε από το ίδιο ρολό εισιτηρίων, η πρεμιέρα κοντεύει να εξαντληθεί, και πάνω στον θάλαμο προβολής οι μπομπίνες πρέπει να συνεχίζουν να γυρίζουν.

Ό,τι μοιράζεται το προσωπικό βρίσκεται σε μια διεύθυνση μνήμης, και τα tests καλούν τις συναρτήσεις σου από πολλά νήματα ταυτόχρονα.
Μια τιμή που διαβάζεται, αλλάζει και ξαναγράφεται σε ξεχωριστά βήματα θα χάσει ενημερώσεις κάτω από αυτό το φορτίο, οπότε κάθε συνάρτηση πρέπει να κάνει την ενημέρωσή της ατομική.

Όλες οι κοινόχρηστες τιμές σε αυτή την άσκηση είναι προσημασμένοι ακέραιοι 64 bit.

Έχεις πέντε εργασίες.

~~~~exercism/note
Οι ενημερώσεις σε αυτή την άσκηση θα πρέπει να εκτελούνται με _ατομικές_ εντολές.
Τα tests εκτελούν τις συναρτήσεις σου ταυτόχρονα και ελέγχουν ότι καμία ενημέρωση δεν χάνεται, οπότε μια μη ατομική ανάγνωση-τροποποίηση-εγγραφή είναι πολύ πιθανό να αποτύχει σε αυτά.
~~~~

## 1. Μέτρησε τις εισόδους

Οι πόρτες είναι ανοιχτές, και σε κάθε μία ένας ταξιθέτης σκίζει εισιτήρια.
Κάθε ομάδα που περνάει καταμετράται σε μία κοινόχρηστη καταμέτρηση εισόδων, και με κάθε πόρτα να μετράει ταυτόχρονα, η συνολική καταμέτρηση πρέπει να βγαίνει ακόμα σωστή.

Υλοποίησε τη συνάρτηση `admit_group`, η οποία προσθέτει ατομικά το μέγεθος μιας ομάδας στην καταμέτρηση.

Αυτή η συνάρτηση δέχεται ως ορίσματα, με αυτή τη σειρά:

- `admissions`: διεύθυνση μνήμης της κοινόχρηστης καταμέτρησης εισόδων, προσημασμένος ακέραιος 64 bit.
- `group_size`: ο αριθμός των ατόμων στην ομάδα, προσημασμένος ακέραιος 64 bit, πάντα μεγαλύτερος από `0`.

```c
admissions = 120, group_size = 4
// admissions is now 124
```

Τα tests δέχονται ομάδες από πολλές πόρτες ταυτόχρονα.
Η τελική καταμέτρηση πρέπει να ισούται με το άθροισμα κάθε ομάδας που πέρασε.

Αυτή η συνάρτηση δεν έχει τιμή επιστροφής.
Η καταμέτρηση πρέπει να ενημερώνεται επί τόπου.

## 2. Άλλαξε την μπομπίνα

Ο προβολέας φοράει ακριβώς μία μπομπίνα.
Η τοποθέτηση της επόμενης μπομπίνας και η αφαίρεση της τρέχουσας πρέπει να είναι μία μόνο κίνηση: με δύο χειριστές προβολέα στη μηχανή, δύο ξεχωριστά βήματα θα μπορούσαν να δώσουν την ίδια μπομπίνα και στους δύο, ή να ρίξουν μία στο πάτωμα.

Υλοποίησε τη συνάρτηση `change_reel`, η οποία τοποθετεί ατομικά την επόμενη μπομπίνα και επιστρέφει αυτή που ήταν τοποθετημένη.

Αυτή η συνάρτηση δέχεται ως ορίσματα, με αυτή τη σειρά:

- `mounted`: διεύθυνση μνήμης του αναγνωριστικού της τοποθετημένης μπομπίνας, προσημασμένος ακέραιος 64 bit.
- `next_reel`: το αναγνωριστικό της μπομπίνας που θα τοποθετηθεί, προσημασμένος ακέραιος 64 bit.

```c
mounted = 7, next_reel = 9
// => 7, and mounted is now 9
```

Αυτή η συνάρτηση επιστρέφει το αναγνωριστικό της προηγουμένως τοποθετημένης μπομπίνας ως προσημασμένο ακέραιο 64 bit.
Τα tests βάζουν πολλά νήματα να ανταλλάσσουν μπομπίνες μέσω της ίδιας υποδοχής ταυτόχρονα, και ελέγχουν ότι κάθε μπομπίνα που παραδίδεται επιστρέφεται ακριβώς μία φορά.

## 3. Πούλησε ένα εισιτήριο

Κάθε ταμείο πουλάει από έναν κοινόχρηστο μετρητή εισιτηρίων που έχουν πωληθεί.
Η πρόσθεση σε έναν μετρητή, όπως κάνουν οι πόρτες, δεν αρκεί εδώ: κάθε πώληση πρέπει επίσης να μαθαίνει τον αριθμό που της δόθηκε.
Δεν επιτρέπεται δύο πωλήσεις να μοιράζονται τον ίδιο αριθμό, και μετά τον συνωστισμό ο μετρητής πρέπει να ισούται ακριβώς με τον αριθμό των εισιτηρίων που πουλήθηκαν.

Υλοποίησε τη συνάρτηση `sell_ticket`, η οποία προσθέτει ατομικά ένα στον μετρητή και επιστρέφει τον αριθμό του εισιτηρίου που μόλις πουλήθηκε.
Ο αριθμός του εισιτηρίου είναι ο μετρητής _μετά_ από αυτή την πώληση: όταν ο μετρητής ήταν `41`, αυτή η πώληση είναι το εισιτήριο `42`.

Αυτή η συνάρτηση δέχεται ως όρισμα:

- `tickets_sold`: διεύθυνση μνήμης του κοινόχρηστου μετρητή των εισιτηρίων που έχουν πωληθεί, προσημασμένος ακέραιος 64 bit.

```c
tickets_sold = 0
// => 1, and tickets_sold is now 1

tickets_sold = 41
// => 42, and tickets_sold is now 42
```

Αυτή η συνάρτηση επιστρέφει τον αριθμό του εισιτηρίου ως προσημασμένο ακέραιο 64 bit.
Τα tests πουλάνε από πολλά ταμεία ταυτόχρονα: κάθε αριθμός που επιστρέφεται πρέπει να είναι διακριτός, και ο τελικός μετρητής πρέπει να ισούται με τον αριθμό των πωλήσεων.

## 4. Γέμισε την πρεμιέρα

Η πρεμιέρα έχει σταθερό αριθμό θέσεων, και κάθε ταμείο πουλάει γι' αυτήν.
Μια πώληση μπορεί να πραγματοποιηθεί μόνο όσο απομένει μια θέση, και η προβολή δεν πρέπει ποτέ να υπερπουλήσει, ούτε όταν κάθε ταμείο αρπάζει την τελευταία θέση την ίδια στιγμή.
Ο έλεγχος του μετρητή και μετά η πρόσθεση σε αυτόν ως δύο ξεχωριστά βήματα αφήνουν ένα κενό ανάμεσα, οπότε ο έλεγχος και η ενημέρωση πρέπει να πετύχουν ή να αποτύχουν μαζί.

Υλοποίησε τη συνάρτηση `claim_seat`, η οποία διεκδικεί ατομικά την επόμενη θέση όταν υπάρχει ακόμα μια ελεύθερη.
Όταν διεκδικείται μια θέση, η συνάρτηση επιστρέφει τον αριθμό της θέσης, που είναι ο μετρητής των κατειλημμένων θέσεων μετά από αυτή τη διεκδίκηση.
Όταν η προβολή είναι εξαντλημένη, επιστρέφει `0` και αφήνει τον μετρητή αμετάβλητο.

Αυτή η συνάρτηση δέχεται ως ορίσματα, με αυτή τη σειρά:

- `seats_taken`: διεύθυνση μνήμης του μετρητή των θέσεων που έχουν ήδη καταληφθεί, προσημασμένος ακέραιος 64 bit, ποτέ πάνω από `capacity`.
- `capacity`: ο αριθμός των θέσεων στην προβολή, προσημασμένος ακέραιος 64 bit, πάντα μεγαλύτερος από `0`.

```c
seats_taken = 0, capacity = 150
// => 1, and seats_taken is now 1

seats_taken = 82, capacity = 150
// => 83, and seats_taken is now 83

seats_taken = 149, capacity = 150
// => 150, and seats_taken is now 150

seats_taken = 150, capacity = 150
// => 0, and seats_taken stays 150
```

Αυτή η συνάρτηση επιστρέφει τον αριθμό της θέσης, ή `0` όταν η προβολή είναι εξαντλημένη, ως προσημασμένο ακέραιο 64 bit.

## 5. Πρόσεξε τον θάλαμο

Ο θάλαμος προβολής χωράει ένα άτομο.
Μια λέξη στη μνήμη λέει αν είναι κατειλημμένος: `0` για ελεύθερο, `1` για κατειλημμένο.
Το προσωπικό περνάει όλη τη νύχτα, ο καθένας με μια δουλειά να κάνει μέσα: να υπογράψει το βιβλίο καταγραφής, να περάσει το φιλμ στον προβολέα, να αρχειοθετήσει μια μπομπίνα.
Όποια κι αν είναι η δουλειά, ο κανόνας του θαλάμου είναι ο ίδιος, και η επιβολή του είναι δική σου δουλειά: ένα άτομο μέσα κάθε φορά, από την αρχή της δουλειάς του μέχρι το τέλος της.

Υλοποίησε τη συνάρτηση `visit_booth`, η οποία:

1. περιμένει μέχρι ο θάλαμος να είναι ελεύθερος·
2. διεκδικεί τον θάλαμο·
3. εκτελεί τη δουλειά του επισκέπτη·
4. ανοίγει ξανά τον θάλαμο μετά τη δουλειά και πριν επιστρέψει.

Όσο ο θάλαμος κρατείται από κάποιον άλλο, θα πρέπει να περιμένει ευγενικά με `pause`.

Αυτή η συνάρτηση δέχεται ως ορίσματα, με αυτή τη σειρά:

- `booth`: διεύθυνση μνήμης της λέξης κατάληψης, προσημασμένος ακέραιος 64 bit που είναι είτε `0` είτε `1`.
- `task`: η δουλειά του επισκέπτη, μια συνάρτηση που δεν δέχεται παραμέτρους και δεν έχει τιμή επιστροφής.

Σημείωσε ότι τα tests εκτελούν δουλειές που κοιτάζουν τον θάλαμο και ένα κοινόχρηστο βιβλίο καταγραφής.
Αυτό σημαίνει ότι ο θάλαμος πρέπει να είναι κατειλημμένος για όλη τη διάρκεια της δουλειάς, κάθε επίσκεψη πρέπει να εκτελεί τη δουλειά της ακριβώς μία φορά, και με πολλούς επισκέπτες ταυτόχρονα το βιβλίο καταγραφής πρέπει να βγαίνει ακριβές.

~~~~exercism/caution
Η δουλειά του επισκέπτη είναι μια συνηθισμένη συνάρτηση που ακολουθεί τη σύμβαση κλήσης:

- μπορεί να αντικαταστήσει οποιονδήποτε καταχωρητή που σώζεται από τον καλούντα, οπότε πρέπει να κρατάς ό,τι χρειάζεσαι ακόμα μετά τη δουλειά κάπου που η κλήση δεν μπορεί να το αγγίξει·
- επίσης περιμένει η στοίβα να είναι ευθυγραμμισμένη στα 16 byte στο σημείο της κλήσης.

Μια παραβίαση οποιουδήποτε από τους δύο κανόνες μπορεί να εμφανιστεί ως κατάρρευση αντί για αποτυχημένο έλεγχο.
~~~~
