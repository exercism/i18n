# Εισαγωγή

Η Elixir παρέχει μια δομή για τη διάσωση από σφάλματα χρησιμοποιώντας `try .. rescue`

```elixir
try do
  raise RuntimeError, "error"
rescue
  e in RuntimeError -> :error
end
```

Ας εξετάσουμε αυτή τη δομή:

- **Γραμμή 1**, το μπλοκ δηλώνεται με `try`.
- **Γραμμή 2**, εδώ τοποθετείται η κλήση συνάρτησης που μπορεί να προκαλέσει σφάλμα, στην περίπτωση αυτή καλούμε την `raise/2`.
- **Γραμμή 4**, στο τμήμα `rescue`, κάνουμε αντιστοίχιση μοτίβου με το όνομα _Module_ του σφάλματος που πετάχτηκε
  - στην αριστερή πλευρά του `->`:
    - το `e` αντιστοιχίζεται στο struct του σφάλματος.
    - το `in` είναι μια λέξη-κλειδί.
    - το `RuntimeError` είναι το σφάλμα από το οποίο θέλουμε να διασωθούμε.
      - Αν θέλαμε να διασωθούμε από όλα τα σφάλματα, θα μπορούσαμε να χρησιμοποιήσουμε `_` αντί για το όνομα του module ή να παραλείψουμε εντελώς τη λέξη-κλειδί `in`.
  - στη δεξιά πλευρά:
    - οι εντολές που θα εκτελεστούν αν το σφάλμα ταιριάξει.

## Struct σφαλμάτων

Τα σφάλματα (μερικές φορές ονομάζονται και "εξαιρέσεις") που διασώζεις με αυτόν τον τρόπο είναι struct.
Η διάσωση σφαλμάτων στην Elixir γίνεται πολύ σπάνια.
Συνήθως το σφάλμα που διασώθηκε καταγράφεται σε log ή αποστέλλεται σε μια εξωτερική υπηρεσία παρακολούθησης και μετά ξαναπετιέται.
Αυτό σημαίνει ότι συνήθως δεν μας ενδιαφέρει η εσωτερική δομή του συγκεκριμένου struct του σφάλματος.

Στην [έννοια των Εξαιρέσεων][exercism-exceptions] θα μάθεις περισσότερα για τα struct των σφαλμάτων, καθώς και πώς να ορίσεις το δικό σου προσαρμοσμένο σφάλμα.

[exercism-exceptions]: https://exercism.org/tracks/elixir/concepts/exceptions
