# Σχετικά

Η μνήμη συνήθως αντιστοιχίζεται για ένα πρόγραμμα από το Λειτουργικό Σύστημα (OS) σε μια γενική διάταξη:

| διεύθυνση | περιοχή μνήμης          |
| :-----: | :--------------------- |
|  υψηλή   | στοίβα                  |
|         | ...                    |
|         | σωρός                   |
|         | τμήμα ανάγνωσης και εγγραφής |
|         | τμήμα κώδικα/μόνο για ανάγνωση |
|   χαμηλή   | δεσμευμένη               |

Η μνήμη σε τμήματα οργανώνεται σε ενότητες, με διαφορετικά δικαιώματα.

Οι συναρτήσεις που έχουμε ορίσει μέχρι τώρα ήταν όλες στην **section .text**.
Αυτή η ενότητα περιέχει εκτελέσιμα δεδομένα μόνο για ανάγνωση.
Άλλες ενότητες χρησιμοποιούνται για τη δήλωση μεταβλητών δεδομένων, οι οποίες μπορεί να είναι μόνο για ανάγνωση ή ανάγνωσης και εγγραφής, αλλά δεν είναι εκτελέσιμες.

## Ενότητα .data

Τα αρχικοποιημένα δεδομένα δηλώνονται στην **[section .data][data]**.

Στη NASM (The Netwide Assembler, ο assembler που χρησιμοποιεί αυτό το track), μια αρχικοποιημένη μεταβλητή έχει ένα όνομα, μια οδηγία που υποδεικνύει το μέγεθος των δεδομένων και μια λίστα τιμών χωρισμένων με κόμμα.
Καθένα από αυτά χωρίζεται με ένα κενό από το άλλο και η ετικέτα μπορεί προαιρετικά να ακολουθείται από ένα `:`.

Οι κύριες οδηγίες και τα σχετικά μεγέθη δεδομένων τους είναι:

| οδηγία | μέγεθος    |
| :-------: | :------ |
|    db     | 1 byte  |
|    dw     | 2 bytes |
|    dd     | 4 bytes |
|    dq     | 8 bytes |

Για παράδειγμα, αυτό δηλώνει μια μεταβλητή ενός byte με όνομα `space` και τιμή `10`:

```x86asm
section .data
    space db 10
```

Οι μεταβλητές που δηλώνονται στη `section .data` είναι τροποποιήσιμες, δηλαδή είναι ανάγνωσης και εγγραφής.
Έχουν επίσης _στατική_ διάρκεια αποθήκευσης, που σημαίνει ότι υπάρχουν για ολόκληρη τη διάρκεια εκτέλεσης του προγράμματος.

## Ενότητα .rodata

Η **section .rodata** είναι παρόμοια με τη `section .data`.
Και οι δύο ενότητες περιέχουν αρχικοποιημένα δεδομένα, τα οποία δηλώνονται με τον ίδιο τρόπο και έχουν την ίδια διάρκεια αποθήκευσης.

Η κύρια διαφορά μεταξύ τους είναι ότι τα δεδομένα στη `section .rodata` είναι αμετάβλητα, δηλαδή μόνο για ανάγνωση.

~~~~exercism/note
Οι σταθερές που ορίζονται με `equ` είναι διαφορετικές από εκείνες που ορίζονται στη `section .rodata`.

Μια σταθερά που ορίζεται με `equ` δεν καταλαμβάνει χώρο στη μνήμη και αντικαθίσταται άμεσα από την τιμή της από τον assembler.
Στην πραγματικότητα είναι απλώς ένα σύμβολο που στέκεται στη θέση αυτής της τιμής.

Από την άλλη, οι σταθερές που ορίζονται στη `section .rodata` αποθηκεύονται πραγματικά στη μνήμη, έχοντας μια διεύθυνση.
~~~~

## Πρόσβαση στα δεδομένα

### Ετικέτες και έμμεση προσπέλαση

Τα δηλωμένα δεδομένα πρέπει να έχουν ένα όνομα συνδεδεμένο με αυτά.
Αυτό το όνομα λέγεται **ετικέτα**.

Μια ετικέτα είναι ένα σύμβολο που κωδικοποιεί τη συγκεκριμένη διεύθυνση των δεδομένων στη μνήμη.
**Οι διευθύνσεις σε x86-64 είναι τιμές 64 bit**.
Μια τιμή που περιέχει μια τέτοια διεύθυνση, είτε κρατείται σε έναν καταχωρητή είτε είναι αποθηκευμένη στη μνήμη, είναι αυτό που οι γλώσσες υψηλότερου επιπέδου ονομάζουν **[δείκτη][pointer]**.

Στη NASM, αν προσπαθήσεις να προσπελάσεις τα δεδομένα απευθείας με την ετικέτα τους, δεν παίρνεις τη δεσμευμένη μνήμη, αλλά τη διεύθυνσή τους:

```x86asm
section .data
    example dq 27 ; this declares a 8-byte variable initialized with 27

section .text
fn:
    mov rax, example ; this stores the address of the declared variable in rax, not its contents
    ...
```

Για να προσπελάσεις τα περιεχόμενα μιας διεύθυνσης μνήμης, είναι απαραίτητο να κάνεις _αποαναφορά_ σε αυτήν.
Αυτό λέγεται **έμμεση προσπέλαση**.

Στη NASM, αυτό γίνεται με `[]`:

```x86asm
section .data
    example dq -27 ; this declares a 8-byte variable initialized with -27

section .text
fn:
    mov rax, [example] ; this dereferences example and access the value stored in memory (-27)
    ...
```

Ωστόσο, υπάρχουν περιπτώσεις όπου μπορεί να υπάρξει ασάφεια σχετικά με το μέγεθος της μνήμης στην οποία γίνεται αποαναφορά.
Σε αυτές τις περιπτώσεις, πρέπει να χρησιμοποιηθεί ένα πρόθεμα που προσδιορίζει αυτό το μέγεθος.

Αυτά είναι τα πιο σημαντικά προθέματα και τα μεγέθη τους σε ένα τυπικό πρόγραμμα x86-64:

| πρόθεμα | μέγεθος    |
| :----- | :------ |
| byte   | 1 byte  |
| word   | 2 bytes |
| dword  | 4 bytes |
| qword  | 8 bytes |

Η ίδια φόρτωση μπορεί να γραφτεί με το μέγεθος να δηλώνεται ρητά:

```x86asm
    mov rax, qword [example] ; same dereference, size stated explicitly
```

Είναι καλή πρακτική να χρησιμοποιείς πάντα ένα πρόθεμα όταν κάνεις αποαναφορά μνήμης.

### Εγγραφή στη μνήμη

Η εγγραφή στη μνήμη γίνεται με τον ίδιο τρόπο, κάνοντας αποαναφορά μιας διεύθυνσης:

```x86asm
section .data
    example1 db 10            ; example1 is a 1-byte memory location initialized with value 10
    example2 dq -456          ; example2 is a 8-byte memory location initialized with value -456
    example3 dd 54            ; example3 is a 4-byte memory location initialized with value 54

section .text
fn:
    mov byte [example1], 20   ; example1 now has value 20
    mov qword [example2], rdx ; example2 now has value equal to the contents in rdx
    mov dword [example3], eax ; example3 now has value equal to the contents in eax
```

Σημείωσε ότι μπορείς να χρησιμοποιήσεις τελεστέους μνήμης στις περισσότερες εντολές χωρίς πρώτα να φορτώσεις τα περιεχόμενα σε έναν καταχωρητή.
Ωστόσο, συνήθως δεν είναι δυνατό να τους χρησιμοποιήσεις και στον τελεστέο πηγής και στον τελεστέο προορισμού, μόνο σε έναν από τους δύο:

```x86asm
section .data
    example4 dw 4
    example5 dq -8
    example6 dd 15

section .text
fn:
    add word [example4], 5     ; example4 is now a 2-byte memory location with the value 4 + 5 = 9
    imul rax, qword [example5] ; rax = rax * (-8)
    ; this is not possible -> sub dword [example6], dword [example6]
```

### Η εντολή LEA

Αν και μια `mov` μπορεί να χρησιμοποιηθεί για να αποθηκεύσει τη διεύθυνση μιας μεταβλητής σε έναν καταχωρητή, υπάρχει μια εντολή με αυτόν τον συγκεκριμένο σκοπό: **[lea][lea]**.

Αυτή η εντολή χρησιμοποιεί έναν τελεστέο σε μορφή μνήμης, αλλά _δεν_ διαβάζει τη μνήμη.
Αντ' αυτού, υπολογίζει την έκφραση πραγματικής διεύθυνσης και γράφει το αποτέλεσμα στον τελεστέο προορισμού:

```x86asm
lea rax, [example] ; this stores the address of 'example' in rax
```

Είναι πιο ιδιωματικό να χρησιμοποιείς τη `lea` για να υπολογίζεις και να αποθηκεύεις διευθύνσεις μνήμης σε καταχωρητές.

### Σχετική διευθυνσιοδότηση

Κατά την πρόσβαση σε θέσεις μνήμης, η προεπιλεγμένη συμπεριφορά στη NASM είναι να παράγει **απόλυτες διευθύνσεις**, δηλαδή σταθερές διευθύνσεις μνήμης.

Για λόγους ασφάλειας, τα εκτελέσιμα συχνά κατασκευάζονται ως **PIE (Position Independent Executable)**, όπου οι περιοχές μνήμης τοποθετούνται σε τυχαιοποιημένες θέσεις.
Σε ένα `PIE`, η τελική διεύθυνση μιας μεταβλητής δεν είναι γνωστή κατά τον χρόνο σύνδεσης.
Έτσι, ο κώδικας υπολογίζει τις διευθύνσεις ως μετατόπιση από την τιμή ενός ειδικού καταχωρητή που λέγεται `rip`, ο οποίος δείχνει στην επόμενη εντολή που πρόκειται να εκτελεστεί.

Αυτό συνήθως λέγεται **σχετική διευθυνσιοδότηση ως προς το RIP**.

Στη NASM μπορείς να ζητήσεις πρόσβαση σχετική ως προς το RIP με τον **[τελεστή rel][rel]**:

```x86asm
mov rax, qword [rel variable]
```

Η σχετική διευθυνσιοδότηση μπορεί επίσης να γίνει η προεπιλογή για ένα αρχείο πηγαίου κώδικα με το `default rel` στην αρχή.

Όλες οι ασκήσεις σε αυτό το track μεταγλωττίζονται και συνδέονται ως `PIE`, οπότε η `rel` θα πρέπει να χρησιμοποιείται για να παράγει σχετικές διευθύνσεις.

Η τυχαιοποιημένη διάταξη που αναφέρθηκε παραπάνω είναι ένα μέτρο μετριασμού γνωστό ως τυχαιοποίηση διάταξης χώρου διευθύνσεων.
Κάνοντας τη βάση κάθε περιοχής μνήμης απρόβλεπτη, στερεί από έναν επιτιθέμενο τις σταθερές διευθύνσεις στις οποίες βασίζονται πολλές τεχνικές εκμετάλλευσης, και το `PIE` είναι αυτό που επιτρέπει στον φορτωτή να τοποθετήσει αυτές τις περιοχές οπουδήποτε.

Εξαιτίας αυτού, η απόλυτη διευθυνσιοδότηση δεν είναι απλώς ανεπιθύμητη σε αυτό το track, είναι αδύνατο να χρησιμοποιηθεί.
Μια απόλυτη αναφορά όπως η `[abs variable]` ζητά από τον assembler να ενσωματώσει μια σταθερή διεύθυνση 32 bit μέσα στην εντολή.
Στο Linux ο συνδέτης του `PIE` απορρίπτει τη μετεγκατάσταση που παράγεται, και στο macOS η μορφή `macho64` δεν υποστηρίζει καθόλου απόλυτες διευθύνσεις 32 bit, οπότε το αρχείο αποτυγχάνει να μεταφραστεί.

Η σχετική διευθυνσιοδότηση ως προς το RIP αποφεύγει και τα δύο προβλήματα, αφού η εντολή κωδικοποιεί μόνο μια μετατόπιση από το `rip` και ποτέ μια σταθερή διεύθυνση.
Ο ιδιωματικός τρόπος για να τοποθετήσεις μια διεύθυνση σε έναν καταχωρητή υπό `PIE` είναι επομένως η `lea` με έναν τελεστέο `rel`:

```x86asm
default rel

section .data
    variable dq 7

section .text
fn:
    lea rax, [rel variable]       ; materialize the address (PIE-safe)
    mov rcx, qword [rel variable] ; load the value through a RIP-relative access
    ...
```

### Ορατότητα

Οι ετικέτες (συναρτήσεις και δεδομένα) που ορίζονται σε οποιαδήποτε ενότητα (π.χ. `.text`, `.data`, `.rodata`) είναι ορατές μέσα στο ίδιο αρχείο πηγαίου κώδικα.
Αν δηλωθούν ως `global`, είναι ορατές και σε άλλα αρχεία πηγαίου κώδικα.

Αντίστροφα, οι ετικέτες που ορίζονται σε άλλα αρχεία πηγαίου κώδικα είναι ορατές στο τρέχον αρχείο πηγαίου κώδικα αν δηλωθούν ως `extern`.
Σε αυτή την περίπτωση, δεν υπάρχει ένδειξη για το μέγεθος των δεδομένων στη γλώσσα assembly, αυτό πρέπει να είναι γνωστό εκ των προτέρων.

```x86asm
default rel

section .data

global number1 ; 'number1' is a variable visible to other source files
number1 db 200

extern number2 ; 'number2' is a variable visible to the current source file, but defined in another

section .text

extern sum ; sum is a function visible to the current source file, but defined in another

fn:
    mov dil, byte [number1]
    mov sil, byte [number2]
    call sum
    ...
```
