# Σχετικά

Όπως εξετάστηκε στην έννοια [`Nothingness`][concept-nothingness], η R έχει διάφορους τρόπους να αναπαριστά δεδομένα που απουσιάζουν ([`NULL`][ref-null]), είναι άγνωστα ([`NA`][ref-na]) ή μαθηματικά μη έγκυρα ([`NaN`][ref-finite], [`Inf`][ref-finite]).
Γενικά, η R θα προσπαθήσει να χρησιμοποιήσει αυτές τις τιμές για να επισημάνει προβλήματα επί τόπου και να συνεχίσει χωρίς να πετάξει εξαίρεση.

## `stop()`

Κάποια προβλήματα είναι πολύ θεμελιώδη για να αφήσουν το πρόγραμμα να συνεχίσει.
Σε αυτή την περίπτωση, χρησιμοποίησε το [`stop(msg)`][ref-stop] για να σταματήσεις αμέσως το πρόγραμμα με ένα `Error` και να εκτυπώσεις το `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Παρόμοιο με ένα [`assert`][wiki-assert] σε άλλες γλώσσες, το [`stopifnot()`][ref-stopifnot] είναι ένα βολικό περιτύλιγμα για το `stop()`.
Τα ορίσματα είναι ένας αυθαίρετος αριθμός συνθηκών Boolean, χωρισμένων με κόμματα, και το πρόγραμμα θα συνεχίσει μόνο αν όλες είναι `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

Η R έχει πολλούς τρόπους να χειρίζεται τα σφάλματα.
Βασίζονται στη Common Lisp και διαφέρουν σημαντικά από πολλές δημοφιλείς γλώσσες.

Ο απλούστερος είναι να τυλίξεις δυνητικά προβληματικό κώδικα σε [`try()`][ref-try].

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## [`warning()`][ref-warning] και [`message()`][ref-message]

Αυτές είναι αποκρίσεις σε μη μοιραίες συνθήκες, για παράδειγμα:

- Για να προειδοποιήσεις για ένα πρόβλημα από το οποίο το πρόγραμμα θα μπορούσε τουλάχιστον εν μέρει να ανακάμψει.
- Για να ενημερώσεις τον χρήστη για την πρόοδο σε ένα πρόγραμμα που εκτελείται για πολλή ώρα.

Μια διαφορά μεταξύ τους είναι ότι οι προειδοποιήσεις αποθηκεύονται προσωρινά και (από προεπιλογή) εμφανίζονται όταν επιστρέψει η συνάρτηση, ενώ τα μηνύματα εμφανίζονται αμέσως.
Υπάρχουν πολλοί τρόποι να αλλάξεις την προεπιλεγμένη συμπεριφορά, που ξεφεύγουν από τα όρια αυτής της ενότητας.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

Η συνάρτηση [`suppressWarnings()`][ref-warning] μπορεί περιστασιακά να φανεί χρήσιμη μέσα στο Exercism, για να μην μπερδεύεις τον test runner με ανεπιθύμητη έξοδο.

## Χειριστές συνθηκών

Η R έχει έναν εναλλακτικό τρόπο να αντιμετωπίζει καταστάσεις σφάλματος, πιο κοντά στο πνεύμα της προσέγγισης της Java και συγγενών γλωσσών.

Οι λεπτομέρειες ξεφεύγουν από τα όρια αυτής της έννοιας, αλλά όποιος ενδιαφέρεται μπορεί να δει τα [`tryCatch`][ref-conditions] και [`withCallingHandlers`][ref-conditions].

Υπάρχει μια καλή συζήτηση στην [Ενότητα 8.4][book-handling] του Advanced R.
