# Apéndice de las instrucciones

## Sugerencias

Uno de los aspectos principales de la programación funcional es tener funciones sin efectos secundarios y no tener que preguntarte qué objetos ocultos ha modificado una función.

Con la programación reactiva, en lugar de que un componente busque trabajo activamente, ese trabajo se le envía al componente. Esto es similar a los callbacks, pero a un nivel mucho más alto, con abstracciones más potentes. Muy a menudo, la programación reactiva se usa junto con la programación funcional.

En el ejercicio vamos a usar [RxJava](https://github.com/ReactiveX/RxJava), una biblioteca muy conocida de programación reactiva con una API de Java.

El contexto simulado de este ejercicio es una aplicación que recibe dos argumentos:

- las palabras nuevas por adivinar, que provienen de algún motor de juego,
- las letras que elige el jugador.

Esos dos argumentos se implementan con [Observables](http://reactivex.io/documentation/observable.html), usando la clase [io.reactivex.Observable](http://reactivex.io/RxJava/2.x/javadoc/io/reactivex/Observable.html).
Básicamente, puedes suscribirte a un `Observable` para «reaccionar» a los valores que se producen en algún lugar. Por ejemplo, el motor de juego envía palabras nuevas cuando detecta que empezó una partida nueva, o los eventos del teclado generan las letras como argumentos.
Pero muchos frameworks reactivos ofrecen abstracciones potentes, como [`map`](http://reactivex.io/documentation/operators/map.html), que te permite cambiar el argumento recibido, o [`combine`](http://reactivex.io/documentation/operators/combinelatest.html), que te permite combinar uno o más `Observable`s.

La clase `Output` es el resultado esperado del procesamiento del ejercicio, y le permite a un front-end mostrar el estado completo del juego sin que este necesite ninguna forma de almacenamiento, lo que además lo hace funcional.
En este ejercicio tienes que encontrar la manera de usar los dos argumentos para generar esta salida en forma de `Observable`.
