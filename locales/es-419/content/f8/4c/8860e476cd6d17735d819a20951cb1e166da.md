## Boolean en Julia

Los valores verdadero o falso se representan con el tipo `Bool`.
Contiene solo dos valores: `true` y `false`.

```julia-repl
julia> true
true

julia> false
false

julia> typeof(true)
Bool
```

A diferencia de varios otros lenguajes, Julia a propósito no tiene un concepto de «veracidad», y solo las expresiones que evalúan a `true` o `false` se tratan como un `Bool`.

En concreto, los arrays o cadenas vacíos *no* se interpretarán como `false`.
Debe haber una prueba adecuada, como `isempty()`, si quieres un tratamiento especial para los valores vacíos.

## Operadores Boolean

En Julia hay tres [operadores Boolean][boolean-operators].

`&&` es el «y» Boolean.
Evalúa a `true` si las expresiones de *ambos* lados de `&&` son `true`.

```julia-repl
julia> true && true
true

julia> true && false
false
```

`||` es el «o» Boolean.
Evalúa a `true` si una expresión de *cualquiera* de los lados de `||` es `true`.

```julia-repl
julia> true || true
true

julia> false || true
true
```

`!` es el «no» Boolean.
Intercambia (invierte) los valores `true` y `false`.

```julia-repl
julia> !true
false

julia> !false
true
```

Operadores similares les resultarán conceptualmente familiares a quienes usan muchos otros lenguajes, aunque la sintaxis exacta puede variar de un lenguaje a otro.

## Precedencia de operadores

En expresiones más complejas, puede ser útil saber que `&&` tiene una [precedencia][operator-precedence] un poco mayor que `||` *(de la misma manera que `*` se aplica antes que `+` en las expresiones aritméticas)*.

Confiar en esto puede ser confuso y propenso a errores.
Para mayor claridad, usa paréntesis para dejar clara tu intención.

## Evaluación de cortocircuito

¿La expresión `true || x` depende del valor de `x`, o el compilador puede ignorar `x`?

Julia evalúa las expresiones Boolean de izquierda a derecha y se detiene cuando tiene un resultado inequívoco.

Por ejemplo, `true || x` debe ser `true`, sin importar el valor de `x`, así que `x` no se evalúa.
De manera similar, `false && y` es `false`, sin necesidad de evaluar `y`.

A la inversa, `true && x` es `true` *solo si* `x` es `true`, así que `x` debe evaluarse.

De forma similar, si encadenamos varios operadores:

```julia-repl
julia> true && false && something_else
false
```

Como `true && false` debe ser `false`, el `something_else` no es importante y el compilador lo ignora.

En este caso, `something_else` no existía como variable, pero incluirla en este contexto no dio ningún error *(pruébalo en el REPL si lo dudas)*.

Quienes programan en Julia suelen usar este tipo de evaluación de cortocircuito como un atajo para atrapar problemas en tiempo de ejecución y casos límite:

```julia
all_ok || do_something()

is_problem && do_something_else()
```

Por ejemplo, el `do_something` podría ser un `return` anticipado de la función si `all_ok` es `false`, o bien asignar un valor predeterminado a una variable antes de continuar.

Esto es un pequeño abuso de la sintaxis Boolean, pero puede resultar muy cómodo.

## Cómo funcionan los Bool internamente

Si un Bool forma parte de una expresión *aritmética*, `true` se interpreta como `1` y `false` como `0`, lo que refleja cómo se almacenan.

Si vienes de lenguajes de más bajo nivel (C y similares), *por favor* evita usar esto con frecuencia.
Reduce la legibilidad del código y dificulta la depuración.

A veces puedes ver los valores numéricos usados como una forma rápida de contar cuántas cosas son `true`.

```julia-repl
julia> true + false + true
2
```
