# Anexo de instrucciones

## Implementación

Antes de empezar, asegúrate de que entiendes cómo escribir código que pueda pasar los casos de prueba.
Para más contexto, revisa este [tutorial].

La mayoría de los ejercicios de Java incluyen varios casos de prueba.
Estos casos están estructurados para apoyar un proceso muy útil conocido como [desarrollo guiado por pruebas (TDD)][tdd].
El TDD consiste en repetir un ciclo estructurado que ayuda a quien programa a construir funcionalidad compleja poco a poco en lugar de hacerlo todo de una vez.
Ese ciclo se puede describir así:

1. Agrega una prueba que describa una parte de la funcionalidad deseada que tu código todavía no tiene.
2. Ejecuta las pruebas para verificar que esta prueba recién agregada falla.
3. Actualiza tu código actual hasta que:
   - Todas las pruebas anteriores sigan pasando;
   - La nueva prueba también pase.
4. [Limpia][refactoring] tu código, asegurándote de que todas las pruebas sigan pasando.
   Por lo general, esto implica renombrar variables, quitar fragmentos de lógica duplicados, eliminar los mensajes de registro que sobraron, etc.
5. ¡Vuelve al paso 1 hasta que hayas construido toda la funcionalidad deseada!

Los archivos de prueba de este track contienen _todas_ las pruebas que tu solución debe pasar para considerarse válida.
Eso no parece ser compatible de inmediato con el ciclo descrito arriba, en el que las pruebas se escriben una por una.
Sin embargo, la herramienta que usamos para escribir nuestras pruebas, [JUnit][junit],
ofrece una [anotación][java-annotation] [@Disabled][junit-disabled] que sirve para omitir temporalmente una prueba que ya está escrita.
Con esta anotación, nos aseguramos de que los archivos de prueba que te entregamos cumplan las siguientes reglas:

- La primera prueba de cualquier archivo de prueba _no_ se omite de forma predeterminada.
- Todas las pruebas excepto la primera de cualquier archivo de prueba _se omiten_ de forma predeterminada.

Esto te permite simular el ciclo de TDD siguiendo estos pasos ligeramente modificados:

1. Ejecuta las pruebas para verificar que _como máximo una_ prueba falla en este momento.
2. Actualiza tu código actual hasta que pasen todas las pruebas que no están omitidas.
3. Limpia tu código, asegurándote de que todas las pruebas no omitidas sigan pasando.
4. Elimina la anotación `@Disabled` que está más arriba en el archivo de prueba.
5. ¡Vuelve al paso 1 hasta que no quede ninguna prueba omitida y todas pasen!
