# Generador de tests del track de Python de Exercism

El track de Python usa un script generador y plantillas de [Jinja2][Jinja2] para crear archivos de test a partir de los [datos canónicos][canonical data] de Exercism.

## Uso del script

La generación de tests requiere una copia local del repositorio [problem-specifications][problem-specifications].
El script se debe ejecutar desde el directorio raíz `python`, para poder acceder
correctamente a los ejercicios.

Ejecuta `bin/generate_tests.py --help` para ver la información de uso.


## Plantillas de test

Las plantillas de test admiten la sintaxis de [Jinja2] y tienen disponibles las siguientes
variables de contexto de los datos canónicos:
- `exercise`: el nombre del ejercicio con guiones (ej.: `two-fer`)
- `version`: la versión de los datos canónicos (ej.: `1.2.0`)
- `cases`: una lista de objetos de caso o una lista de listas `cases`. Para conocer
la estructura exacta del ejercicio en el que estás trabajando, consulta
`canonical-data.json`
- `has_error_case`: indica si algún caso de test espera que se
lance un error (ej.: `False`)
- `additional_cases`: tiene una estructura similar a `cases`, pero se llena a partir del archivo `.meta/additional_tests.json` del ejercicio si es que existe (para ver un ejemplo, consulta `exercises/word-count/.meta/additional_tests.json`)

Además, se agregan los siguientes filtros de plantilla para mayor comodidad:
- `to_snake`: convierte un string a snake_case (ej.: `{{ "CamelCaseString" | to_snake }}` -> `camel_case_string`)
- `camel_case`: convierte un string a CamelCase (ej.: `{{ "snake_case_string" | camel_case }}` -> `SnakeCaseString` )
- `error_case`: comprueba si un caso de test espera que se lance un error (ej.: `{% for case in cases%}{% if case is error_case}`)
- `regex_replace`: reemplazo de strings con expresiones regulares (ej.: `{{ "abc123" | regex_replace("\\d", "D") }}` -> `abcDDD`)


### Convenciones

- Las macros de uso general para estructuras de plantilla muy repetidas se definen en `config/generator_macros.j2`.
  - Se pueden importar con lo siguiente:
  `{%- import "generator_macros.j2" as macros with context -%}`
- Todas las plantillas de test deben terminar con `{{ macros.footer() }}`.
- Todos los nombres de las clases de Python deben estar en CamelCase (ej.: `TwoFer`).
  - Conviértelo usando `{{ "two-fer" | camel_case }}`
- Todos los nombres de módulos y funciones de Python deben estar en snake_case
(ej.: `high_scores`, `personal_best`).
  - Conviértelo usando `{{ "personalBest" | to_snake }}`
- Los tests específicos del track se definen en el archivo de opciones `.meta/additional_tests.json`. El objeto JSON definido en este archivo debe
tener una sola clave, `cases`, que tiene la misma estructura que `cases` en
`canonical-data.json`.
- Los tests específicos del track se deben colocar después de los tests canónicos en los
archivos de test.
- Los tests específicos del track se deben marcar en el archivo de test con el siguiente comentario:
```
# Additional tests for this track
```


### Estructura

La mayoría de las plantillas se verán más o menos así:

```Jinja2
{%- import "generator_macros.j2" as macros with context -%}
{{ macros.header() }}

class {{ exercise | camel_case }}Test(unittest.TestCase):
    {% for case in cases -%}
    def test_{{ case["description"] | to_snake }}(self):
        value = {{ case["input"]["value"] }}
        expected = {{ case["expected"] }}
        self.assertEqual({{ case["property"] }}(value), expected)

    {% endfor %}

{{ macros.footer() }}
```


### Sobrescribir las importaciones

Los nombres importados en `macros.header()` se pueden sobrescribir agregando
una lista de nombres alternativos para importar (ej.: `clock`):

```Jinja2
{{ macros.header(["Clock"])}}
```


### Ignorar propiedades

En raras ocasiones, puede ser necesario filtrar las propiedades que
no se testean en este track. La macro `header` también acepta un
argumento `ignore` (ej.: `high-scores`):

```Jinja2
{{ macros.header(ignore=["scores"]) }}
```

## Cómo crear una plantilla

1. Crea el archivo `.meta/template.j2` para el ejercicio que estás implementando
  y ábrelo en tu editor.
2. Copia y pega la [estructura de ejemplo](#Layout) en el archivo de plantilla
  y guárdalo.
3. Haz los cambios necesarios en el archivo de plantilla hasta que produzca
  código de test válido, consultando el `canonical-data.json` del ejercicio para
  los nombres de las entradas y la estructura de los casos.
    - Usa las [macros disponibles](../config/generator_macros.j2) para evitar reescribir las secciones estandarizadas.
    - Si estás implementando una plantilla para un ejercicio existente,
    no es obligatorio que coincida exactamente con la estructura del archivo de test actual,
    pero minimizar las diferencias hará que la revisión del PR sea un proceso mucho más fluido para todos los involucrados.
