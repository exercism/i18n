# Introducción

TypeScript es JavaScript con sintaxis para tipos, lo que lo convierte en un lenguaje de programación fuertemente tipado que admite estilos orientados a objetos, imperativos y declarativos (por ejemplo, la programación funcional), y que te ofrece mejores herramientas a cualquier escala.

Como [no puedes aprender TypeScript sin aprender JavaScript][handbook-js-or-ts], parte del contenido de este track se centra en enseñar conceptos de JavaScript, y algunos conceptos se centran únicamente en características específicas de TypeScript.

## (Re)Asignación

Hay varias formas principales de asignar valores a nombres en TypeScript: usando variables o constantes.
En Exercism, las variables siempre se escriben en [camelCase][wiki-camel-case]; las constantes se escriben en [SCREAMING_SNAKE_CASE][wiki-snake-case].
No hay una guía oficial que seguir, y distintas empresas y organizaciones tienen distintas guías de estilo.
_Siéntete libre de escribir las variables como prefieras_.
La ventaja de escribirlas tal como vienen preparadas en los ejercicios es que se resaltarán de forma diferente en la interfaz web y en la mayoría de los IDE.

Las variables en TypeScript se pueden definir con la palabra clave [`const`][mdn-const], [`let`][mdn-let] o [`var`][mdn-var].

Una variable puede referenciar distintos valores a lo largo de su vida cuando usas `let` o `var`.
Por ejemplo, `myFirstVariable` se puede definir y redefinir muchas veces usando el operador de asignación `=`:

```typescript
let myFirstVariable = 1
myFirstVariable = 0
myFirstVariable = 42
```

A diferencia de `let` y `var`, las variables definidas con `const` solo se pueden asignar una vez.
Así se definen las constantes en TypeScript.

```typescript
const MY_FIRST_CONSTANT = 10

// Can not be re-assigned.
MY_FIRST_CONSTANT = 20
// => TypeError: Assignment to constant variable.
```

Como TypeScript puede detectar esto de forma estática, el compilador de TypeScript también producirá un error:

```typescript
// ^? Cannot assign to 'MY_FIRST_CONSTANT' because it is a constant.(2588)
```

Esto significa que no necesitas ejecutar el código para detectar el `TypeError`.

## Inferencia de tipos

Sin entrar demasiado en el tema de la [inferencia de tipos][handbook-type-inference], debes saber que una variable asignada normalmente tiene un tipo inferido, incluso sin una anotación de tipo.

```typescript
const MY_FIRST_CONSTANT = 10
// ^? const MY_FIRST_CONSTANT: number
```

Este tipo se aplica entonces en todo el código.
Esto también significa que, si bien el siguiente código es JavaScript válido:

```javascript
let myFirstVariable = 1
myFirstVariable = 'Some string'
```

Con TypeScript, se queja:

```typescript
let myFirstVariable = 1
myFirstVariable = 'Some string'
// ^? Type 'string' is not assignable to type 'number'.(2322)
```

Esta característica garantiza la seguridad de tipos incluso cuando no se usan anotaciones de tipo.

## Declaraciones de funciones

En TypeScript, las unidades de funcionalidad se encapsulan en _funciones_, que normalmente se agrupan en el mismo archivo si pertenecen juntas.
Estas funciones pueden recibir parámetros (argumentos) y pueden _devolver_ un valor usando la palabra clave `return`.
Las funciones se invocan usando la sintaxis `()`.

```typescript
function add(num1: number, num2: number): number {
  return num1 + num2
}

add(1, 3)
// => 4
```

Los parámetros de una función normalmente se deben anotar con un tipo usando dos puntos (`:`) seguidos del tipo.
El valor de retorno de una función se puede anotar después de cerrar la lista de parámetros usando dos puntos (`:`) seguidos del tipo.

## Anotaciones de tipo

Como se muestra en la declaración de la función `add`, los parámetros tienen una anotación de tipo explícita `: number`.
Las declaraciones de variables, las propiedades de clase, las declaraciones de funciones y más admiten anotaciones de tipo.

Tanto las anotaciones de tipo explícitas como los tipos inferidos son verificados por el comprobador de tipos.

```typescript
add('foo', 3)
// ^? Argument of type 'string' is not assignable to parameter of type 'number'.(2345)
```

## Exponer a otros archivos

Para que una `function`, una constante o una variable estén disponibles en _otros archivos_, hay que [exportarlas][mdn-export] usando la palabra clave `export`.
Otro archivo puede luego [importarlas][mdn-import] usando la palabra clave `import`.
Esto también se conoce como el sistema de módulos.
Un gran ejemplo es cómo funcionan todas las pruebas.
Cada ejercicio tiene al menos un archivo, por ejemplo `lasagna.ts`, que contiene la _implementación_.
Además, hay al menos otro archivo, por ejemplo `lasagna.test.ts`, que contiene las _pruebas_.
Este archivo _importa_ las entidades públicas (es decir, exportadas) para probar la implementación:

```typescript
// file.ts
export const MY_VALUE = 10

export function add(num1, num2) {
  return num1 + num2
}

// file.test.ts
import { MY_VALUE, add } from './file.js'

add(MY_VALUE, 5)
// => 15
```
