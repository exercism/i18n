# Acerca de

La memoria dinámica se implementa mediante funciones de biblioteca que el programador usa para asignar y liberar memoria en tiempo de ejecución.
Como el programador controla la asignación y la liberación de memoria, la memoria dinámica es tan segura como libre de errores humanos sea el programador.
Por esa razón, la memoria dinámica es una de las principales fuentes de bugs de programación y un objetivo principal de los ataques de hackeo.

La memoria dinámica se usa para variables cuyo tamaño solo se conoce en tiempo de ejecución.
Esto suele ser útil para arrays cuyo número de elementos puede variar de una ejecución a otra.
Los arrays de longitud variable (VLA) son otra forma de manejar arrays cuyo tamaño de elemento solo se conoce en tiempo de ejecución.
Un VLA usa almacenamiento automático, lo que significa que su memoria se destruye al salir de su bloque de definición.
(Para obtener más información sobre el almacenamiento, consulta el concepto de [especificadores de clase de almacenamiento](https://github.com/exercism/c/tree/main/concepts/storage-class-specifiers)).
Los VLA se incorporaron al lenguaje C con C99, pero a partir de C11 los VLA son opcionales, así que los compiladores que admiten C11 en adelante no están obligados a admitir VLA.
Un análisis detallado de los arrays de longitud variable queda fuera del alcance de este artículo.

## malloc

`malloc` es una función declarada en `stdlib.h` que se usa para asignar memoria dinámica.
Si la asignación tiene éxito, se devuelve un puntero que apunta a la dirección del primer byte de la memoria asignada.
Si la asignación no tiene éxito, se devuelve `NULL`.
Es prudente verificar si el resultado de `malloc` es `NULL` y manejarlo con cuidado si falla.
El puntero devuelto es de tipo `pointer-to-void`, que a grandes rasgos puede considerarse un puntero «genérico» que se puede convertir al tipo específico que usa la memoria.
`malloc` tiene un parámetro, que es el tamaño en bytes de la memoria deseada.
El tamaño total para asignar un array es el tamaño del tipo de dato de cada elemento multiplicado por el número de elementos.
El operador `sizeof` se usa comúnmente para obtener el tamaño del tipo de dato de cada elemento.
El siguiente ejemplo lo demuestra

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // printed The size of numbers is 8 bytes (can vary by system)
    printf("The size of numbers is %zu bytes\n", sizeof(numbers));
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 2
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 3
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

Es importante recordar que la memoria recién asignada por `malloc` no se inicializa, sino que puede contener valores basura.
Ten en cuenta que el `sizeof` del puntero `numbers` no es el número de elementos del array ni la cantidad total de memoria asignada.
El tamaño del puntero que devuelve `malloc` es el tamaño de cualquier puntero en ese sistema en particular.
El código de ejemplo se ejecutó en un sistema de 64 bits, así que el tamaño del puntero era de 8 bytes (multiplicado por 8 bits por byte = 64 bits).
El tipo de puntero se convirtió implícitamente de pointer-to-void a pointer-to-int.
Que el pointer-to-int apunte a un solo `int` o a un array de `ints` es algo que el programador puede manejar como mejor le parezca.
Por ejemplo

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    // treat numbers as a single value
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    // treat numbers as an array
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    numbers[0] = 2;
    // prints The first element of the array is 2
    printf("The first element of the array is %d\n", numbers[0]);
    // treat numbers as a single value again
    // prints numbers is 2
    printf("numbers is %d\n", *numbers);    
    free(numbers);
    numbers = NULL;    
}
```

Si los valores se van a escribir definitivamente antes de leerlos, usar `malloc` puede ser una forma eficiente de asignar memoria.
Pero si existe la posibilidad de que los valores se lean antes de inicializarlos, usar `malloc` es riesgoso.
Una forma más segura de asignar memoria es usar `calloc`, que inicializa a cero la memoria recién asignada.

Observa que en los ejemplos anteriores se usó `free(numbers)`.

## free

`free` es una función declarada en `stdlib.h` que se usa para liberar memoria que se ha asignado dinámicamente.
La memoria asignada dinámicamente permanece reservada hasta que `free` la libera.
Algunos sistemas operativos pueden liberar automáticamente la memoria asignada dinámicamente cuando el programa termina, pero la buena práctica es no depender de eso.
`free` tiene un parámetro, que es un puntero a la memoria que se asignó dinámicamente.
El uso o la falta de uso de `free` está asociado con varios problemas de memoria.

#### Fuga de memoria

No liberar la memoria asignada dinámicamente después de que la referencia a esa memoria llega al final de su tiempo de vida, o se destruye de alguna otra forma, se conoce como fuga de memoria.
La memoria filtrada es memoria que el sistema tiene reservada pero a la que el programa ya no puede acceder.
Esto puede ser un problema particular si se asigna memoria dentro de un bucle, no se libera al final del bucle y se vuelve a asignar al principio del bucle.
Si se asigna suficiente memoria sin liberarla, la llamada para asignar memoria fallará porque no queda memoria suficiente para asignar.
Es importante recordar que, aunque el sistema mantiene reservada la memoria asignada dinámicamente hasta que se libera, el puntero al que se asigna puede tener solo ámbito de bloque.
Por ejemplo, en los ejemplos de `malloc`, la memoria se asigna en `my_function`.
Esa memoria se filtraría si el puntero a ella no se devolviera y se usara para establecer el puntero `numbers` en `main`.
Por lo tanto, pasar ese puntero `numbers` a `free` libera la memoria asignada en `my_function`.

#### Uso después de liberar (**UAF**)

Si se accede a la memoria después de liberarla, los valores podrían ser cualquier cosa.
En el siguiente ejemplo, la memoria a la que apunta `numbers` se libera y luego se lee en `printf`.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = (int *) malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // could  print anything, e.g.
    // The first element of the array is 18178656
    printf("The first element of the array is %d\n", numbers[0]);
}
```

El puntero `numbers`, una vez liberado, se conoce como puntero colgante.
Un puntero colgante puede referirse a otra memoria distinta de aquella para la que estaba destinado.
Por lo tanto, un puntero colgante puede provocar corrupción de datos y la sustitución y ejecución arbitraria de código.
Un puntero a memoria asignada que no se ha limpiado estableciéndolo en `NULL` se puede usar para hackear el programa.
En el ejemplo anterior, si `numbers` se estableciera en `NULL` así: `numbers = NULL;` después de liberarlo, el siguiente `printf` provocaría la terminación del programa, quizás informando un fallo de segmentación al intentar leer `numbers[0]`.

#### Doble liberación

Si se llama a `free` dos veces sobre un puntero a memoria asignada dinámicamente, se produce un comportamiento indefinido (**UB**).
Esto significa que el compilador puede manejarlo de forma arbitraria como quiera.
El siguiente ejemplo, compilado con dos compiladores diferentes, puede tener dos resultados distintos

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // pointer-to-void from malloc is converted to a pointer-to-int
    int * numbers = malloc(sizeof(int) * count);
    return numbers;
}

int main() {
    int * numbers = my_function(1);
    if (!numbers) return -1;
    *numbers = 1;
    // prints numbers is 1
    printf("numbers is %d\n", *numbers);
    free(numbers);
    // numbers = NULL;
    // first compiler generates runtime error: double free detected in tcache 2
    // second compiler generates no error
    free(numbers);
}
```

El primer y el segundo compilador no generaron ningún error en tiempo de ejecución cuando `numbers` se estableció en `NULL` entre cada llamada a `free`, pero eso no garantizaría que funcione con un tercer compilador.
Una fuente común de doble liberación es tener dos punteros que apuntan a la misma memoria asignada dinámicamente.
Un puntero puede apuntar al inicio de un array en un lugar del programa, y el otro puntero puede usarse para recorrer el array en otro lugar del programa.
En distintos lugares del programa se libera cada puntero, lo que provoca una doble liberación.

## calloc

`calloc` es una función declarada en `stdlib.h` que se usa tanto para asignar memoria dinámica como para inicializar a cero la memoria recién asignada.
Si la asignación tiene éxito, se devuelve un puntero que apunta a la dirección del primer byte de la memoria asignada.
Si la asignación no tiene éxito, se devuelve `NULL`.
Es prudente verificar si el resultado de `calloc` es `NULL` y manejarlo con cuidado si falla.
El puntero devuelto es de tipo `pointer-to-void`, que a grandes rasgos puede considerarse un puntero «genérico» que se puede convertir al tipo específico que usa la memoria.
`calloc` tiene dos parámetros.
El primer parámetro indica cuántos elementos del tipo de dato especificado se van a asignar.
El segundo parámetro indica el tamaño del tipo de dato especificado que se va a asignar.

En el siguiente ejemplo, todas las sentencias `printf` deben mostrar siempre `0`, ya que `calloc` garantiza poner en cero los valores recién asignados.

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    // prints The first element of the array is 0
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The second element of the array is 0
    printf("The second element of the array is %d\n", numbers[1]);
    // prints The third element of the array is 0
    printf("The third element of the array is %d\n", numbers[2]);
    free(numbers);
    numbers = NULL;
}
```

## realloc

`realloc` es una función declarada en `stdlib.h` que se usa para expandir o reducir memoria ya asignada.
Si la reasignación tiene éxito, se devuelve un puntero que apunta a la dirección del primer byte de la memoria reasignada.
Si la reasignación no tiene éxito, se devuelve `NULL`.
Es prudente verificar si el resultado de `realloc` es `NULL` y manejarlo con cuidado si falla.
`realloc` tiene dos parámetros.
El primer parámetro es un puntero a la memoria existente que se va a reasignar.
El segundo parámetro es el tamaño en bytes de la memoria reasignada.
Los valores que se establecieron antes de expandir la memoria se conservan.
Es importante recordar que la memoria que se agrega al expandir no se inicializa a cero y sus valores podrían ser cualquier cosa.
Además, la memoria que se elimina al reducir la memoria tampoco se inicializa y podría conservar los valores.
El siguiente ejemplo muestra cómo expandir y reducir un array

```c
#include <stdio.h>
#include <stdlib.h>

int * my_function(int count) {
    // allocates the amount of bytes in an int, multiplied by count
    int * numbers = calloc(count, sizeof(int));
    return numbers;
}

int * my_function_2 (int * ptr , int count) {
    // reallocates the memory to the size of an int multiplied by count
    int * numbers = realloc(ptr, sizeof(int) * count);
    // if realloc fails, exit the program
    if (!numbers) exit(-1);
    return numbers;
}

int main() {
    int * numbers = my_function(3);
    if (!numbers) return -1;
    numbers[0] = 1;
    numbers[1] = 2;
    numbers[2] = 3;
    // expand the size of the array
    numbers = my_function_2(numbers, 6);
    // prints The first element of the array is 1
    printf("The first element of the array is %d\n", numbers[0]);
    // prints The sixth element of the array is [whatever is there]
    // the additional memory is not initialized, so it could be
    // 0 or it could be 18728 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    numbers[5] = 6;
    // shrink the size of the array
    numbers = my_function_2(numbers, 3);
    // prints The sixth element of the array is [whatever is there]
    // the removed memory is not initialized, so it could be
    // 6 or it could be 43164 or anything else
    printf("The sixth element of the array is %d\n", numbers[5]);
    free(numbers);
}
```

## Cuando el tamaño que se pasa es 0

Si el tamaño que se pasa a `malloc`, `calloc` o `relloac` es `0`, lo que sucede depende de cómo lo implemente el compilador.
Un compilador puede devolver un puntero `NULL` o un puntero no nulo.
Por ejemplo, si se asigna memoria para un puntero a `char`, el compilador puede devolver `NULL` o un puntero no nulo a un string vacío.
Para evitar resultados distintos con compiladores distintos, lo mejor es no asignar con un tamaño de 0.
