# Introducción

Ya *usaste* flujos en `channel-chatter` y te deshiciste de ellos en `boatswains-bilge`. Este ejercicio es tu primer flujo personalizado: una clase que implementa el [protocolo][stream-protocol], para que el mismo código de `with-input-stream` / `read1` / `stream-read1` que funcionaba con un `<string-reader>` funcione también con el tuyo.

## Mixins: la otra mitad de la jerarquía de clases

Ya conoces `TUPLE: child < parent …` de `dragons-descendants`: una jerarquía de un solo padre en la que los slots descienden. Factor tiene una *segunda* forma de extender el grafo de clases: los **mixins abiertos**. Un `MIXIN: m` declara una clase sin slots a la que otras clases se pueden unir más tarde con `INSTANCE: c m`. La pertenencia es de muchos a muchos: una clase puede ser instancia de tantos mixins como quiera.

El protocolo de flujos usa dos mixins para marcar cuál de las dos mitades de la interfaz implementa una clase:

```factor
INSTANCE: my-stream input-stream    ! readable
INSTANCE: my-stream output-stream   ! writable
```

Un flujo puede ser una, la otra, o ambas. Los métodos genéricos de `input-stream` (o `output-stream`) despachan entonces a cualquier clase que se haya unido al mixin: así es como los `read1`, `stream-contents`, `with-input-stream`, etc. del entorno encuentran el camino hacia tu clase.

Los mixins son *abiertos*: puedes agregar un nuevo miembro después de que se declara el mixin, incluso en un vocabulario distinto. Ese es el contraste con `TUPLE: < parent`, donde la relación queda fija al declarar la clase hija.

## Los genéricos del protocolo

Los genéricos del protocolo viven en `io`:

```
stream-read1         ( stream -- elt/f )
stream-read          ( n stream -- seq/f )
stream-read-unsafe   ( n buf stream -- count )
stream-write1        ( elt stream -- )
stream-write         ( seq stream -- )
stream-flush         ( stream -- )
stream-element-type  ( stream -- type )
```

`stream-read1` devuelve el siguiente byte (o `f` al llegar al final del flujo); `stream-write1` escribe uno. `stream-read-unsafe` es la lectura por lotes de más bajo nivel que ofrecen la mayoría de los flujos de entrada; `stream-read` se construye sobre ella y se encarga de la asignación. `stream-element-type` indica si el flujo trabaja con bytes (`+byte+`) o con caracteres (`+character+`); cuando envuelves otro flujo, la implementación más sencilla simplemente delega en el flujo subyacente.

## La limpieza viene de `destructors`

Los flujos se pueden desechar: un flujo personalizado extiende `disposable` e implementa `dispose*`. Ese es el framework de `boatswains-bilge`, aplicado a una clase de flujo:

```factor
TUPLE: my-stream < disposable underlying ;

: <my-stream> ( underlying -- s )
    my-stream new-disposable swap >>underlying ;

M: my-stream dispose* underlying>> dispose ;
```

Una vez que eso está en su lugar, todos los combinadores `with-…` de `channel-chatter` funcionan en tu flujo automáticamente.
