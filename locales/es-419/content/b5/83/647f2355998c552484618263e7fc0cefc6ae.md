# Instrucciones

Es la noche del estreno en el Grand Marquee, y todo el personal trabaja a la vez.
La multitud entra por todas las puertas, varias ventanillas de taquilla venden del mismo rollo de boletos, el estreno está a punto de agotarse y, allá arriba, en la cabina de proyección, los rollos no pueden dejar de girar.

Todo lo que el personal comparte vive en una dirección de memoria, y las pruebas llaman a tus funciones desde varios hilos al mismo tiempo.
Un valor que se lee, se modifica y se vuelve a escribir en pasos separados perderá actualizaciones bajo esa carga, así que cada función debe hacer su actualización de forma atómica.

Todos los valores compartidos en este ejercicio son enteros con signo de 64 bits.

Tienes cinco tareas.

~~~~exercism/note
Las actualizaciones de este ejercicio deben realizarse con instrucciones _atómicas_.
Las pruebas ejecutan tus funciones de forma concurrente y verifican que no se pierda ninguna actualización, así que una lectura-modificación-escritura no atómica tiene muchas probabilidades de fallarlas.
~~~~

## 1. Cuenta las admisiones

Las puertas están abiertas y en cada una hay un acomodador rompiendo boletos.
Cada grupo que pasa se cuenta en un mismo recuento compartido de admisiones, y aunque todas las puertas cuenten a la vez, el total de la sala debe seguir siendo correcto.

Implementa la función `admit_group`, que suma de forma atómica el tamaño de un grupo al recuento.

Esta función recibe como argumentos, en este orden:

- `admissions`: dirección de memoria del recuento compartido de admisiones, un entero con signo de 64 bits.
- `group_size`: el número de personas del grupo, un entero con signo de 64 bits, siempre mayor que `0`.

```c
admissions = 120, group_size = 4
// admissions is now 124
```

Las pruebas admiten grupos por varias puertas a la vez.
El recuento final debe ser igual a la suma de todos los grupos que pasaron.

Esta función no devuelve ningún valor.
El recuento debe actualizarse en el mismo lugar.

## 2. Cambia el rollo

El proyector sostiene exactamente un rollo.
Colocar el siguiente rollo y quitar el actual debe ser un solo movimiento: con dos proyeccionistas en la máquina, dos pasos separados podrían entregarle el mismo rollo a los dos, o dejar caer uno al suelo.

Implementa la función `change_reel`, que coloca de forma atómica el siguiente rollo y devuelve el que estaba colocado.

Esta función recibe como argumentos, en este orden:

- `mounted`: dirección de memoria del identificador del rollo colocado, un entero con signo de 64 bits.
- `next_reel`: el identificador del rollo que se va a colocar, un entero con signo de 64 bits.

```c
mounted = 7, next_reel = 9
// => 7, and mounted is now 9
```

Esta función devuelve el identificador del rollo que estaba colocado antes, como un entero con signo de 64 bits.
Las pruebas hacen que varios hilos intercambien rollos en el mismo soporte a la vez y verifican que cada rollo que entra salga exactamente una vez.

## 3. Vende un boleto

Cada ventanilla vende a partir de un mismo recuento compartido de boletos vendidos.
Aquí no basta con sumar a un recuento, como hacen las puertas: además, cada venta debe conocer el número que le tocó.
Dos ventas no pueden compartir un número y, después de la avalancha, el recuento debe ser exactamente igual al número de boletos vendidos.

Implementa la función `sell_ticket`, que suma de forma atómica uno al recuento y devuelve el número del boleto que se acaba de vender.
El número del boleto es el recuento _después_ de esta venta: cuando el recuento era `41`, esta venta es el boleto `42`.

Esta función recibe como argumento:

- `tickets_sold`: dirección de memoria del recuento compartido de boletos vendidos, un entero con signo de 64 bits.

```c
tickets_sold = 0
// => 1, and tickets_sold is now 1

tickets_sold = 41
// => 42, and tickets_sold is now 42
```

Esta función devuelve el número del boleto como un entero con signo de 64 bits.
Las pruebas venden desde varias ventanillas a la vez: cada número devuelto debe ser distinto y el recuento final debe ser igual al número de ventas.

## 4. Llena el estreno

El estreno tiene un número fijo de asientos y todas las ventanillas están vendiéndolo.
Una venta solo puede concretarse mientras quede un asiento, y la proyección nunca debe sobrevenderse, ni siquiera cuando todas las ventanillas se pelean por el último asiento en el mismo instante.
Revisar el recuento y luego sumarle uno en dos pasos separados deja un hueco entre medio, así que la comprobación y la actualización deben tener éxito o fallar juntas.

Implementa la función `claim_seat`, que reclama de forma atómica el siguiente asiento cuando todavía queda uno libre.
Cuando se reclama un asiento, la función devuelve el número del asiento, que es el recuento de asientos ocupados después de esta reclamación.
Cuando la proyección está agotada, devuelve `0` y deja el recuento sin cambios.

Esta función recibe como argumentos, en este orden:

- `seats_taken`: dirección de memoria del recuento de asientos ya ocupados, un entero con signo de 64 bits, nunca mayor que `capacity`.
- `capacity`: el número de asientos de la proyección, un entero con signo de 64 bits, siempre mayor que `0`.

```c
seats_taken = 0, capacity = 150
// => 1, and seats_taken is now 1

seats_taken = 82, capacity = 150
// => 83, and seats_taken is now 83

seats_taken = 149, capacity = 150
// => 150, and seats_taken is now 150

seats_taken = 150, capacity = 150
// => 0, and seats_taken stays 150
```

Esta función devuelve el número del asiento, o `0` cuando la proyección está agotada, como un entero con signo de 64 bits.

## 5. Cuida la cabina

En la cabina de proyección cabe una sola persona.
Una palabra en memoria indica si está ocupada: `0` si está libre, `1` si está ocupada.
El personal pasa durante toda la noche, cada uno con una tarea que hacer adentro: firmar el libro de registro, enhebrar el proyector, archivar un rollo.
Sea cual sea la tarea, la regla de la cabina es la misma, y hacerla cumplir es tu trabajo: una persona adentro a la vez, desde el comienzo de su tarea hasta el final.

Implementa la función `visit_booth`, que:

1. espera hasta que la cabina esté libre;
2. reclama la cabina;
3. ejecuta la tarea del visitante;
4. vuelve a abrir la cabina después de la tarea y antes de retornar.

Mientras otra persona tiene la cabina, debe esperar con educación usando `pause`.

Esta función recibe como argumentos, en este orden:

- `booth`: dirección de memoria de la palabra de ocupación, un entero con signo de 64 bits que es `0` o `1`.
- `task`: la tarea del visitante, una función que no recibe parámetros y no devuelve ningún valor.

Ten en cuenta que las pruebas ejecutan tareas que observan la cabina y un libro de registro compartido.
Esto significa que la cabina debe estar ocupada durante toda la tarea, que cada visita debe ejecutar su tarea exactamente una vez y que, con varios visitantes a la vez, el libro de registro debe quedar exacto.

~~~~exercism/caution
La tarea del visitante es una función común que sigue la convención de llamada:

- puede sobrescribir cualquier registro que guarda quien llama, así que debes guardar todo lo que sigas necesitando después de la tarea en un lugar que la llamada no pueda tocar;
- también espera que la pila esté alineada a 16 bytes en el punto de la llamada.

Incumplir cualquiera de las dos reglas puede manifestarse como un cierre inesperado en lugar de una comprobación fallida.
~~~~
