# Acerca de

Los [closures][closures] en Swift son bloques de código autocontenidos a los que se les pueden pasar parámetros para que realicen su cómputo y devuelvan valores.
Los closures también capturan valores de su entorno y los usan en sus cálculos.
Como son autocontenidos, se pueden pasar de un lado a otro en un programa como cualquier otro valor, o asignarse a constantes y variables.

Los closures pueden sonar muy parecidos a las funciones de Swift; y en efecto lo son, por una buena razón.
Las funciones en Swift son casos especiales de closures: se les exige tener un nombre y se definen con una sintaxis un poco distinta.

Aunque técnicamente las funciones en Swift son closures, cuando la gente habla de «closures» en Swift se refiere a las [expresiones de closure][closure-expressions].
Las expresiones de closure se escriben como una lista de parámetros seguida por un tipo de retorno y la palabra clave `in`, seguida por el cuerpo del closure, todo dentro de un par de llaves:

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}
```

Esto define una expresión de closure de tipo `(Double, Double) -> Double`, y se puede ejecutar de manera similar a una función de ese tipo, aplicándola a parámetros del tipo adecuado:

```swift
{ (a: Double, b: Double) -> Double in
  return (a + b) / 2.0
}(10.0, 15.0)
// returns 12.5
```

Como no es muy práctico escribir la expresión de closure completa cada vez que se quiere ejecutar, los closures se pueden asignar a nombres, igual que cualquier otro valor en Swift.
Luego se pueden llamar aplicando el nombre a los parámetros:

```swift
let mean = { (a: Double, b: Double) -> Double in
  (a + b) / 2.0
}

mean(13.0, 100.0)
// returns 56.5
```

Como se ve arriba, los closures, igual que las funciones normales, pueden omitir la palabra clave `return` si el cuerpo del closure es una sola expresión.

La mayoría de las veces, los closures se usan con funciones de orden superior, ya sea pasándolos como parámetros o devolviéndolos como resultados:

```swift
[11, 75, 3, 99, 53].contains(where: { (x: Int) -> Bool in x > 100 })
// returns false

["apple", "ball", "carrot"].sorted(by: { (s1: String, s2: String) -> Bool in s1.count < s2.count })
// returns ["ball", "apple", "carrot"]

func makeAdder(base: Int) -> (Int) -> Int {
  { (x: Int) -> Int in base + x }
}
```

## Inferencia de los tipos de closure

Cuando el tipo de retorno o los tipos de los parámetros se pueden [inferir del contexto][inferring-closure-types], se pueden omitir de la expresión de closure.
Además, si se pueden omitir los tipos de los parámetros, también se pueden omitir los paréntesis alrededor de los nombres de los parámetros:

```swift
let mean: (Double, Double) -> Double = { a, b in a + b / 2.0 }

func makeAdder(base: Int) -> (Int) -> Int {
  { x in base + x }
}

["apple", "ball", "carrot"].sorted(by: { s1, s2 in s1.count < s2.count })
```

- En el primer ejemplo, el tipo se puede inferir de la anotación en la constante `mean`.
- En el segundo, el compilador sabe, por la definición de `makeAdder`, que `base` es un `Int` y que la función devuelta debe ser de tipo `(Int) -> Int`. A partir de ahí, puede verificar que si `x` es un `Int`, entonces el closure tendrá tipo `(Int) -> Int`; por lo tanto, podemos omitir la firma de tipo en el closure, ya que `(Int) -> Int` es la única firma válida posible que el closure puede tener.
- El tercer ejemplo es similar, pero el compilador necesita obtener parte de la información de tipo del array con el que se usa el método. Sabe que el método `sorted(by:)` recibe como parámetro un closure con dos parámetros del mismo tipo que los elementos de la colección que se está ordenando, y que devuelve un `Bool`, así que el compilador puede inferir que el tipo de retorno del closure debe ser `Bool`. Y como el método se usa con un array de String, puede determinar que los tipos de los parámetros `s1` y `s2` deben ser ambos `String`.

## Limitaciones de los closures

Como se mencionó antes, las funciones y los closures son muy similares en Swift, pero hay algunas diferencias importantes:

- Los closures no pueden usar etiquetas de argumento externas. No hay forma de definirlas, y tratar de usar el nombre de un parámetro al llamar al closure produce un error:

```swift
let add5 = { x in x + 5 }
add5(x: 10)
// Error: Extraneous argument label 'x:' in call
```

- Los parámetros de los closures no pueden tener un valor por defecto.
- Los parámetros de los closures pueden ser parámetros variádicos, pero deben tener un nombre y una anotación de tipo.
