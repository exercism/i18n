# Introducción

JavaScript tiene un objeto integrado `Date` que almacena la fecha y la hora, y ofrece métodos para gestionarlas.

<!-- prettier-ignore -->
~~~exercism/caution
Estaba basado en la clase `java.util.Date` de Java, que fue reemplazada a principios de la década de 2010, pero por compatibilidad con versiones anteriores, el `Date` de JavaScript sigue existiendo.

Debido a lo difícil que es trabajar con fechas en general y a lo malo o inexistente que es el manejo de las zonas horarias, existen muchas bibliotecas como `moment.js`, `day.js`, `date-fns` y `luxon`.
Ninguna de ellas está disponible en Exercism.

En tus propios proyectos, no uses un paquete obsoleto o sin mantenimiento como `moment.js`, sino que apóyate en alternativas más modernas como `luxon`, o en [Temporal][mdn-temporal], que aún no está ampliamente disponible.
Este ejercicio se centra en `Date`, que seguirá siendo relevante hasta el final de JavaScript.

[mdn-temporal]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal

## Creación

Un objeto `Date` es una instancia de la clase `Date`.
Se puede crear sin pasar ningún argumento a la función constructora.
Esto da como resultado un objeto `Date` que representa la fecha y la hora actuales:

```javascript
const now = new Date();
// => Thu Apr 14 2022 11:46:08 GMT+0530 (India Standard Time)
// Shows current day, date and time (in your time zone).
```

### **Marca de tiempo Unix (número)**

Si se pasa un número, se interpretará como un `timestamp`.
Una marca de tiempo es un número entero que representa la cantidad de **milisegundos** transcurridos desde el **1 de enero de 1970 [UTC][defn-utc]+0**.

```javascript
const epoch = new Date(0);
// Thu Jan 01 1970 01:00:00 GMT+0100 (Central European Standard Time)

const another = new Date(1749508766627);
// Tue Jun 10 2025 00:39:26 GMT+0200 (Central European Summer Time)
```

Se podría esperar que `new Date(0)` genere el objeto de fecha «más temprano», pero JavaScript convertirá la fecha a tu zona horaria local, lo que significa que solo quienes estén en una zona horaria cercana a [GMT / con UTC+0][defn-gmt] obtendrán en realidad el valor de la [época Unix][defn-unix-epoch].

### **Marca de tiempo ISO 8601 (string)**

Puedes pasar un valor de tipo string que represente una fecha al constructor de `Date`.
El **único** formato que es consistente entre implementaciones es la [versión simplificada][mdn-date-string-format] de los llamados [strings de marca de tiempo ISO 8601][defn-iso8601], reconocidos y estandarizados internacionalmente.

Un momento en el tiempo en [UTC][defn-gmt] se ve así:

```text
YYYY-MM-DDTHH:mm:ss.mssZ
YYYYMMDDTHHmmss.mssZ
```

Donde se realizan las siguientes sustituciones:

| Clave | Descripción                                      | Predeterminado |
| ---- | --------------------------------------------- | ------- |
| YYYY | El año calendario, representado con 4 dígitos |         |
| MM   | El mes calendario, representado con 2 dígitos | 01      |
| DD   | El día calendario, representado con 2 dígitos | 01      |
| T    | Una letra T literal, que separa la fecha de la hora |         |
| HH   | Las horas en un reloj de 24 horas, 2 dígitos  | 00      |
| mm   | Los minutos, 2 dígitos                        | 00      |
| ss   | Los segundos, 2 dígitos                       | 00      |
| mss  | Los milisegundos, 3 dígitos                   | 000     |
| Z    | Una letra Z literal, o un desplazamiento `+/-HH:mm` |         |

La letra literal `Z` indica UTC (sin zona horaria, sin horario de verano).

Como la mayoría de los componentes tienen valores predeterminados, es válido omitir partes al final:

```text
YYYY-MM-DD
```

Su valor predeterminado es una hora de 00:00:00.000

Si la marca de tiempo no termina en `Z`, y no termina con `+HH:mm` o `-HH:mm` (lo que indica un desplazamiento de zona horaria), por razones históricas se aplica lo siguiente:

> Cuando el desplazamiento de zona horaria está ausente, los formatos que solo tienen fecha se interpretan como hora UTC y los formatos de fecha y hora se interpretan como hora local.
> La interpretación como hora UTC se debe a un error histórico de la especificación que no era consistente con ISO 8601, pero que no se pudo cambiar debido a la compatibilidad web.
> Consulta [Broken Parser – A Web Reality Issue][ref-broken-parser].

### **Objeto Date**

Un objeto de fecha existente también se puede usar como argumento del constructor.
Esto hace una copia del objeto `Date` existente con la misma fecha y hora.

```javascript
const t1 = new Date();
const t2 = new Date(t1);
// Values of t1 and t2 will be the same.
```

### **Proporcionar valores individuales de los componentes de fecha y hora**

Se puede crear una fecha que represente solo una fecha pasando tres números.
Se puede crear una fecha que represente una fecha y una hora pasando 6 números.

```javascript
const date1 = new Date(95, 11, 17);
// Creates Date for Dec 17 1995 00:00 if your local timezone is equivalent to UTC.

const date2 = new Date(2013, 12, 5, 13, 24, 0);
// Creates Date for Jan 5 2014 13:24 if your local timezone is equivalent to UTC.
```

El segundo valor es el `month`, que empieza en `0` para enero y llega hasta `11` para diciembre.

## `Date.parse()`

Es posible que encuentres menciones o referencias a una función de análisis de fechas llamada `Date.parse`.
Como esta función tiene muy pocas invariantes (verdades) y el resto de su implementación no está especificada (y por lo tanto no es estándar), no conviene usarla.

## Acceder a los componentes de `Date`

Hay varios métodos en los objetos de fecha que devuelven los componentes de la fecha:

```javascript
getFullYear(); // Get the year (4 digits)
getMonth(); // Get the month, from 0 to 11.
getDate(); // Get the day of month, from 1 to 31.
getHours(); // Get the hour in a 24 clock, from 0 to 23
getMinutes(); // Get the minutes, from 0 to 59
getSeconds(); // Get the seconds, from 0 to 59
getMilliseconds(); // Get the milliseconds, from 0 and 999
getDay(); // Get the day of week, from 0 (Sunday) to 6 (Saturday).
```

Cada uno de estos tiene una variante `set` correspondiente (por ejemplo, `setFullYear`) para actualizar el valor.
Cualquier valor que se desborde pasa al siguiente componente:

```javascript
const date = new Date('2025-02-28T12:42:00Z');
// => Fri Feb 28 2025 13:42:00 GMT+0100 (Central European Standard Time)

date.setDate(29);
// there was no February 29th in 2025.

date.getDate();
// => 1

date.toString();
// => Sat Mar 01 2025 13:42:00 GMT+0100 (Central European Standard Time)
```

Existen variantes UTC para todos los métodos, que ignoran la zona horaria local.

## Convertir desde una fecha

Los objetos de fecha tienen un método `getTime()` que devuelve la marca de tiempo UNIX en milisegundos, es decir, la cantidad de milisegundos transcurridos desde la medianoche del 1 de enero de 1970, UTC.
Además, hay disponible un método `toISOString()` para convertir un objeto de fecha a un string de marca de tiempo ISO 8601.

## Comparar fechas

Los operadores mayor que (`>`), mayor o igual que (`>=`), así como menor que (`<`) y menor o igual que (`<=`), se pueden usar directamente entre dos fechas o entre una fecha y un número.
Esto funciona porque JavaScript intentará convertir la fecha a un valor primitivo.

<!-- prettier-ignore -->
~~~exercism/advanced
Cuando se hace una comparación entre dos fechas, o entre una fecha y un número, JavaScript llama a [`[Symbol.toPrimitive]("number")`][mdn-to-primitive], que internamente llama a [`date.valueOf()`][mdn-date-value-of].
Esto último es lo mismo que llamar a [`date.getTime()`][mdn-date-get-time].

Si no quieres depender de este comportamiento, primero convierte a un número usando `getTime()`.

[mdn-to-primitive]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/Symbol.toPrimitive
[mdn-date-value-of]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/valueOf
[mdn-date-get-time]: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/getTime
~~~

Las fechas no se pueden comparar usando igualdad (`==` y `===`), pero el resultado de `.getTime()` sí.
