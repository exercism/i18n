# Introducción

Este ejercicio se apoya en lo que viste en [Observador de aves del patio][backyard-birdwatcher] y te presenta los words de orden superior que reciben una *quotation*, es decir, un fragmento de código entre `[ ]`, para controlar la operación.

## Las quotations como valores

Una quotation es simplemente un fragmento de código literal. Puedes pasarla como dato a otro word:

```factor
{ 1 2 3 4 5 } [ 2 > ] count .   ! => 3
```

Aquí `[ 2 > ]` es una quotation que recibe un número y deja un boolean. `count` la ejecuta sobre cada elemento y cuenta los resultados verdaderos.

## Filtrar y rechazar

```
find      ( seq quot    -- i/f elt/f ) ! first match: index and element, or f f
find-last ( seq quot    -- i/f elt/f ) ! same, but searches from the end
filter    ( seq quot    -- newseq )    ! keep elements where quot is truthy
reject    ( seq quot    -- newseq )    ! drop them instead
without   ( seq exclude -- newseq )    ! drop every element that's in `exclude`
sift      ( seq         -- newseq )    ! drop every `f`, keep the rest
```

```factor
{ 1 2 3 4 5 } [ 3 > ] find .s
! => 3            (index)
! => 4            (element)
{ 1 2 3 4 5 } [ 3 > ] find-last .s
! => 4            (index)
! => 5            (element)
{ 1 2 3 4 5 } [ even? ] filter .    ! => { 2 4 }
{ 1 2 3 4 5 } [ even? ] reject .    ! => { 1 3 5 }
"hello world" " ld" without .       ! => "heowor"
{ 1 f 2 f 3 } sift .                ! => { 1 2 3 }
```

`without` trata su segundo argumento como un conjunto: cualquier elemento de `seq` que sea `=` a *cualquier* elemento de `exclude` se descarta. `sift` es el caso especial sin quotation de `reject`: conserva todos los elementos excepto `f`, lo que resulta práctico para limpiar los huecos que dejó un `map` anterior.

### Conservar el resultado de la prueba

`find` devuelve el *elemento* que coincide. Cuando la prueba ya *calcula* el valor que en realidad quieres, `map-find` te ahorra una segunda pasada: ejecuta la quotation sobre cada elemento y devuelve el primer resultado distinto de `f` **y** el elemento que lo produjo.

```
map-find ( seq quot: ( elt -- result/f ) -- result elt )
```

```factor
USING: kernel math sequences ;

! First multiple of 3, paired with that multiple divided by 3.
{ 11 13 15 17 } [ dup 3 mod 0 = [ 3 /i ] [ drop f ] if ] map-find .s
! => 5            (result: 15/3)
! => 15           (element)
```

La quotation devuelve `f` para los elementos que no cumplen y el resultado que quieres conservar para el que sí cumple. Si ninguno cumple, `map-find` deja `f f`, igual que `find`.

### Filtrar registros por un slot

Cuando los elementos son *tuplas*, el predicado normalmente proyecta un slot mediante su reader autogenerado `slot>>` y prueba sobre él:

```factor
USING: accessors sequences ;

TUPLE: customer name vip? ;

{
    T{ customer { name "Alice" } { vip? t } }
    T{ customer { name "Bob"   } { vip? f } }
    T{ customer { name "Carol" } { vip? t } }
}
[ vip?>> ] filter [ name>> ] map .
! => { "Alice" "Carol" }
```

## Pasar un valor fijo con `with`

A veces el predicado necesita un valor que sea igual en cada llamada: un umbral, un divisor, un string objetivo. `with` (en [`kernel`][kernel]) fija ese valor dentro de la quotation y convierte una quotation de dos argumentos `( value elt -- ? )` en la quotation de un solo argumento que esperan `filter`, `count`, `map` y `each`:

```
with ( value seq quot -- seq curry )
```

Cada llamada por elemento ve `( value elt )` en la pila: primero el valor fijo y después el elemento actual:

```factor
USING: kernel sequences ;

! Count elements greater than 5 — value=5 is threaded in
5 { 2 7 4 9 1 8 } [ < ] with count .   ! => 3
```

## Mapear e iterar

`map` (en [`sequences`][sequences]) aplica una quotation a cada elemento y devuelve el array de resultados. `each` hace el mismo recorrido pero descarta los resultados, lo que es útil cuando la quotation se ejecuta solo por sus efectos secundarios. `2map` recorre *dos* secuencias al mismo tiempo y combina los elementos correspondientes; `2each` y `2reduce` son sus primos de solo efectos secundarios y de plegado; `zip` es la forma abreviada de «emparejarlos sin combinarlos»:

```
map     ( seq       quot           -- newseq )
map-as  ( seq       quot exemplar  -- newseq )
each    ( seq       quot           -- )
2map    ( seq1 seq2 quot           -- newseq )
2each   ( seq1 seq2 quot           -- )
2reduce ( seq1 seq2 identity quot  -- result )
zip     ( seq1 seq2                -- pairs )
```

`2reduce` pasa un acumulador por ambas secuencias a la vez: su quotation recibe `( accumulator elt1 elt2 -- accumulator' )`. Aquí acumula un producto punto: cada par se multiplica y los productos se suman (`1*10 + 2*20 + 3*30`):

```factor
{ 1 2 3 } { 10 20 30 } 0 [ * + ] 2reduce .   ! => 140
```

`map-as` es el primo de `map` que fuerza el tipo de la secuencia de salida: pásale un `{ }` o un `V{ }` vacío como exemplar para anular el tipo por defecto de la entrada (de lo contrario, mapear un string a elementos que no son caracteres da error cuando Factor intenta volver a empaquetar los resultados en un string).

```factor
USING: formatting math sequences ;

{ 1 2 3 } [ sq ] map .                         ! => { 1 4 9 }
{ 1 2 3 } [ . ] each                           ! prints 1, then 2, then 3
{ 1 2 3 } { 10 20 30 } [ + ] 2map .            ! => { 11 22 33 }
{ "x" "y" } { 1 2 } [ "%s%d" sprintf ] 2map .  ! => { "x1" "y2" }
{ 1 2 3 } { 10 20 30 } [ + . ] 2each           ! prints 11, then 22, then 33
{ "a" "b" "c" } { 1 2 3 } zip .                ! => { { "a" 1 } { "b" 2 } { "c" 3 } }
```

Ambas formas de dos secuencias se detienen en la longitud de la entrada más corta. `zip` es lo mismo que `[ 2array ] 2map`: conserva los pares en lugar de colapsarlos.

## Ordenar

`sort` devuelve una copia ordenada en orden natural; `sort-by` (en [`sorting`][sorting]) ordena según una clave extraída de cada elemento:

```
sort    ( seq      -- sortedseq )
sort-by ( seq quot -- sortedseq )
```

```factor
{ 3 1 4 1 5 9 2 6 } sort .
! => { 1 1 2 3 4 5 6 9 }

{ -3 5 -1 4 } [ abs ] sort-by .
! => { -1 -3 4 5 }
```

## Agregar

`map-sum` (en [`sequences`][sequences]) mapea una quotation sobre la secuencia y suma los resultados en una sola pasada:

```
map-sum ( seq quot -- n )
```

```factor
{ 1 2 3 4 } [ sq ] map-sum .   ! => 30
```

## Mínimo y máximo

`minimum` y `maximum` devuelven directamente el elemento más pequeño o más grande de una secuencia. `minimum-by` y `maximum-by` (todas ellas en [`sequences`][sequences]) devuelven el elemento cuya clave extraída es la más pequeña o la más grande:

```
minimum     ( seq      -- elt )
maximum     ( seq      -- elt )
minimum-by  ( seq quot -- elt )
maximum-by  ( seq quot -- elt )
```

```factor
{ 3 1 4 1 5 9 2 6 } minimum .       ! => 1
{ 3 1 4 1 5 9 2 6 } maximum .       ! => 9

{ -3 5 -1 4 } [ abs ] minimum-by .
! => -1
```

## Escribir tu propio word de orden superior

Cuando *tu* word recibe una quotation como argumento en tiempo de ejecución y la pasa a `map`, `filter`, `each`, etc., declara tu word con `; inline`. Eso le indica al compilador que expanda tu word en cada punto de llamada, donde la quotation es un literal conocido; sin eso, el compilador no tiene forma de conocer el efecto de pila de la quotation.

```factor
USING: math sequences ;

: tax-on ( inventory quot -- total )
    map-sum ; inline

{ { "shirt" 20 } { "hat" 15 } } [ second 1/10 * ] tax-on .
! => 3+1/2
```

Los words que se construyen solo con quotations literales no necesitan `inline`; solo lo necesitan los que pasan una quotation *de entrada*.

Si un word `inline` así llega a llamarse a *sí mismo*, es decir, es un combinador recursivo, decláralo `; inline recursive` en su lugar. Sin ese word adicional, el compilador se detiene con *«The inline recursive word ... must be declared recursive»*, que te dice exactamente qué agregar.

## Extraer el segundo elemento

Para un array de 2 elementos, `second` devuelve su segundo elemento. `first` devuelve el primero. Ambos están en [`sequences`][sequences].

## De números a strings

`number>string ( n -- str )` (en [`math.parser`][math.parser]) convierte un número en su forma de string decimal:

```factor
42 number>string .     ! => "42"
3.5 number>string .    ! => "3.5"
```
