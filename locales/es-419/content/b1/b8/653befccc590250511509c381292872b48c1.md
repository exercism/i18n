# Introducción

Una función es **recursiva** cuando se llama a sí misma.

Una diferencia clave entre una llamada a función y un bucle es que llamar a una función empuja a la pila la dirección a la que se debe volver. Esto significa que una función recursiva normalmente necesita más espacio en la pila que un bucle equivalente.

Como consecuencia, una función que no deja de llamarse a sí misma puede terminar agotando todo el espacio de la pila. A esto se le llama **desbordamiento de pila**.

Por eso toda función recursiva debe tener al menos un caso base, que es una situación en la que la función devuelve un valor sin llamarse a sí misma. Cualquier llamada recursiva debe llegar tarde o temprano a un caso base.

Por ejemplo, la función factorial `n! = n * (n - 1) * ... * 1` se puede definir de forma recursiva con `1` como caso base:

```x86asm
factorial:
    ; the argument `n` is passed on `rdi`
    ; the factorial will be returned on `rax`

    cmp rdi, 1
    jle .base_case     ; base case -> if rdi <= 1, return 1

    push rdi           ; save n
    dec rdi            ; rdi = n - 1
    call factorial     ; recursive call, rax = (n - 1)!
    pop rdi            ; restore n
    imul rax, rdi      ; rax = n * (n - 1)! = n!
    ret
.base_case:
    mov rax, 1
    ret
```

Fíjate que `factorial` debe hacer `push rdi` antes de hacer la llamada recursiva y `pop rdi` después. Esto se debe a que todavía necesita `n` una vez que la llamada recursiva devuelve, para poder calcular `n * (n-1)!`.

Fíjate también que usar un registro de los que la función llamada debe preservar no resolvería este problema.

Aunque una función recursiva puede llegar a llamarse a sí misma, también es la función llamada por alguna otra. Eso significa que también debe preservar esos registros antes de usarlos, y restaurar su valor después de usarlos. Esto normalmente se hace con una secuencia de `push`/`pop`, como vimos en un concepto anterior.

Como cada marco de pila de una función recursiva, con la excepción del caso base, también es quien llama y necesita preservar sus propias variables locales, esta secuencia de `push`/`pop` debe repetirse en cada marco de pila. Incluso guardar la variable directamente en la pila, sin usar registros, seguiría costando los mismos `8` bytes por marco de pila.

Esto significa que cada llamada recursiva agrega `8` bytes a la pila por la dirección de retorno que empuja `call`, más `8` bytes por cada variable local que necesita guardar. La función seguirá agregando esos bytes a la pila en cada marco de pila hasta llegar a su caso base. Solo entonces empieza a desenrollarse en orden inverso, y cada llamada recursiva usa tantos `pop` como sea necesario y luego un `ret`.

Por ejemplo, si se llamara a `factorial` con el argumento `10`, se llamaría a sí misma nueve veces antes de llegar al caso base de `1`. En ese punto, se habrían usado `144` bytes para almacenar la `n` (`8` bytes) y la dirección de retorno (`8` bytes) de cada marco de pila anterior.

## Llamada de cola

En algunas situaciones, una función no realiza más trabajo después de llamar a otra y antes de devolver.

Considera, por ejemplo:

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    call times_three
    ret
```

La función `triple_of_square`:

- multiplica el argumento recibido (en `rdi`) por sí mismo, y así obtiene su cuadrado;
- luego llama a `times_three`, que devuelve el argumento recibido multiplicado por tres.

Como resultado, `triple_of_square` devuelve `3*x²`, donde `x` es su argumento, recibido en `rdi`.

Fíjate que en `triple_of_square` no se hace ningún trabajo después de llamar a `times_three`: la función simplemente devuelve. En una situación así, en lugar de usar `call`, una función puede usar `jmp` y transferir la ejecución a la función llamada:

```x86asm
times_three:
    imul rax, rdi, 3
    ret

triple_of_square:
    imul rdi, rdi
    jmp times_three
```

A esto se le llama **llamada de cola**.

La principal ventaja de una llamada de cola es evitar el costo extra de `call`. Un `call` empuja una dirección de retorno a la pila, y para que el control vuelva a ese punto tiene que haber un `ret` que le corresponda.

Una llamada de cola se salta ambos: no hay dirección de retorno que empujar ni un `ret` extra con el que emparejar, solo el `ret` propio de la función llamada.

## Recursión de cola

Una llamada de cola es especialmente útil para funciones recursivas que pueden llamarse a sí mismas muchas veces antes de devolver.

Sin embargo, no toda llamada recursiva se puede convertir directamente en una llamada de cola. Como un `jmp` transfiere el control a la función llamada, quien llama no puede realizar más trabajo después de la llamada de cola.

Por ejemplo, la función `factorial` anterior **no** es recursiva de cola. Después de la llamada recursiva, todavía necesita multiplicar el resultado por la `n` actual, con `imul rax, rdi`.

En situaciones como esta, a veces es posible usar un acumulador que vaya juntando los cálculos parciales y se devuelva al final. Por ejemplo, podemos definir un `factorial_helper` que haga la mayor parte del trabajo y luego `factorial` prepara un acumulador y le transfiere el control a `factorial_helper`:

```x86asm
factorial_helper:
    ; the argument `n` is passed on `rdi`
    ; `rax` is used as an accumulator and will be returned at the end

    cmp rdi, 1
    jle .base_case

    imul rax, rdi        ; we accumulate the partial result on `rax`
    dec rdi              ; rdi = n - 1
    jmp factorial_helper ; tail call to accumulate (n - 1)!
.base_case:
    ret                  ; returns the factorial already accumulated on `rax`

factorial:
    mov rax, 1           ; initial value for the accumulator
    jmp factorial_helper ; tail call
```

Como después de la llamada recursiva no se hace más trabajo, tampoco necesitamos guardar `rdi` ya. No hay ningún `call` ni `push rdi`, así que cada iteración recursiva agrega `0` bytes a la pila: no se usa espacio adicional en la pila. Esta versión puede manejar valores de `n` arbitrariamente grandes sin desbordar la pila. Es más eficiente y también más segura.

En algunos casos, reordenando las funciones, se puede evitar incluso el `jmp` a la función auxiliar. Por ejemplo, `factorial` y `triple_of_square` se pueden reescribir de esta manera:

```x86asm
factorial:
    mov rax, 1
factorial_helper:
    cmp rdi, 1
    jle .base_case

    imul rax, rdi
    dec rdi
    jmp factorial_helper
.base_case:
    ret

triple_of_square:
    imul rdi, rdi
times_three:
    imul rax, rdi, 3
    ret
```

En el fragmento anterior, la ejecución de `factorial` continúa directamente en `factorial_helper`. Lo mismo pasa con `triple_of_square` y `times_three`. En ambos casos, la ejecución sigue de forma secuencial y parece que la función de cola es solo una etiqueta local dentro de la función «principal».

En realidad, no hay ninguna diferencia esencial entre una etiqueta local y una función. El lenguaje ensamblador de x86-64 no les da un tratamiento especial a ninguna de las dos: solo son direcciones en una sección con código ejecutable, como `section .text`.

De esta manera, una función recursiva de cola se puede pensar esencialmente igual que un bucle en el que la llamada recursiva salta de vuelta al inicio, y el caso base es la condición que termina el bucle.
