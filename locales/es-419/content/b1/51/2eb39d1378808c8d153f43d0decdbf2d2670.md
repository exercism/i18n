# Guía de pull requests para contribuidores

¡Gracias por querer contribuir a Exercism!
Antes de crear un pull request, lee la guía [cómo hacer un gran pull request][how-to-make-a-great-pr], que busca ayudarte con la parte no técnica de los pull requests para que tengas una gran experiencia y, al mismo tiempo, ayudes a nuestro equipo de mantenedores.

Este documento contiene algunas pautas adicionales, específicas de Exercism, para distintos tipos de pull requests.

## Pull requests de ejercicios

Crear un pull request para un ejercicio de concepto o un ejercicio de práctica puede ser abrumador por la gran cantidad de reglas que rodean a este tipo de ejercicios.
Por eso, a un mantenedor puede tomarle de dos a tres horas revisarlo, y puede dar lugar a decenas de comentarios.  
Para ayudarte, habrá un revisor principal que comente tu pull request.

No te desanimes por la cantidad de comentarios de revisión; es completamente normal que un ejercicio pase por varias reescrituras antes de llegar a algo que te convenza tanto a ti como al revisor principal.

## Recomendaciones

Aquí tienes algunas recomendaciones para agilizar aún más el proceso.

### Lee la documentación

Antes de crear un pull request para un ejercicio, asegúrate de leer la [documentación de los ejercicios de concepto][concept-exercises] y la [documentación de los ejercicios de práctica][practice-exercises], respectivamente.
Leer la documentación de antemano ayuda muchísimo, ya que las revisiones tendrán menos comentarios y tu pull request se fusionará mucho antes.

### Examina los ejercicios existentes (si los hay)

Si el track ya tiene ejercicios, tómate el tiempo de estudiarlos un poco para descubrir cómo son y cómo están estructurados.

## Pull requests de ejercicios de práctica

### Considera si el cambio realmente corresponde a problems-specifications

Parte del contenido de un ejercicio de práctica (como su introducción) proviene de sus metadatos (compartidos) tal como se definen en el [repo problems-specifications][problem-specifications].
Si tienes la intención de actualizar ese contenido, considera si el cambio también podría beneficiar a otros tracks.
Si es así, abre mejor un pull request a los metadatos del ejercicio en el [repo problems-specifications][problem-specifications].

## Recomendaciones generales

### Abstente de hacer revisiones no solicitadas

Todas las revisiones de pull requests las hacen uno (o más) mantenedores del track, ya que son responsables de aprobar todos los cambios del repositorio.
Que los mantenedores hagan la revisión también ayuda a evitar comentarios contradictorios para quien crea el pull request.

Por supuesto, puedes dejar un comentario para ofrecer ayuda con la revisión (sobre todo en pull requests grandes) o plantear preguntas en caso de que notes algo que parezca un error.
