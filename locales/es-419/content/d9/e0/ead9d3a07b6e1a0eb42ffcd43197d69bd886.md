# Acerca de

Es poco probable que te encuentres con mucho código de producción que no haga uso de espacios de nombres.

Un ejemplo de la sintaxis es:

```csharp
namespace MyNameSpace
{
    public class MyClass {}

    public class OtherClass {}
}
```

Los espacios de nombres son una forma de agrupar código relacionado y evitar conflictos de nombres.

Según la [documentación oficial][namespaces], los espacios de nombres tienen dos roles principales:

- Primero, .NET usa los espacios de nombres para organizar sus muchas clases
- Segundo, declarar tus propios espacios de nombres puede ayudarte a controlar el ámbito de los nombres de clases y métodos en proyectos de programación más grandes.

La biblioteca de clases base (BCL) usa ampliamente los espacios de nombres para organizar su funcionalidad.

## Referencias a tipos con espacios de nombres

Se hace referencia a los tipos incluidos en espacios de nombres desde fuera del espacio de nombres anteponiendo al nombre del tipo la sintaxis de punto. Como alternativa, y lo que es más común, puedes colocar una directiva `using` al principio del archivo (o dentro de un espacio de nombres), y cualquier tipo del espacio de nombres importado se puede usar sin el prefijo. Dentro del mismo espacio de nombres no es necesario calificar los nombres de los tipos.

```csharp
namespace MySpace
{
    public class MyClass {}

    public class Foo
    {
        public void Bar()
        {
            var baz = new MyClass();
        }
    }
}

public class Qux
{
    public void Box()
    {
        var nux = new MySpace.MyClass();
    }
}

namespace OtherSpace
{
    using MySpace;

    public class Tix
    {
        public void Jeg()
        {
            var lor = new MyClass();
        }
    }
}
```

Este [artículo][using] explica claramente las formas en que se puede usar la directiva `using`:

- `using`: evita tener que calificar los tipos con el espacio de nombres
- `using static`: evita tener que calificar los miembros con los tipos (un buen ejemplo es `Math.Max()`).
- `using MyAlias = YourNamespace;`: sustituye el nombre del espacio de nombres por uno más legible.

## Conflicto de espacios de nombres

.NET soluciona el problema de dos espacios de nombres con el mismo nombre en ensamblados diferentes en los que se produciría un conflicto entre nombres de identificador totalmente calificados (quizás un escenario en el que se cargan varias versiones de un ensamblado). Este problema se soluciona con el [calificador de alias de espacio de nombres][namespace-alias-qualifier] y el [alias extern][extern-alias].

Una de las razones para mencionar este tema bastante de nicho es su uso del [operador `::`][dot-dot-operator]. A menudo verás el calificador `global::` antepuesto a espacios de nombres, sobre todo en código generado. La intención aquí es evitar un posible conflicto con algún espacio de nombres anidado o nombre de clase. Al anteponer `global::` a un espacio de nombres, te aseguras de que se seleccione un espacio de nombres de nivel superior.

## Nota para desarrolladores de Java

Al comparar con el `import` de los `packages` de Java, conviene señalar algunas diferencias y similitudes:

- No hay equivalente en C# a importar tipos específicos.
- `using static` e `import static` son equivalentes.
- En Java, los nombres de los paquetes influyen en la accesibilidad entre jars. En C#, los ensamblados son primordiales y pertenecer al mismo espacio de nombres no afecta el nivel de acceso.
- La relación entre las rutas del sistema de archivos y los nombres de clase totalmente calificados en Java no se refleja en los espacios de nombres de C#, aunque es una buena práctica, cuando sea posible, darle a un archivo el mismo nombre que la clase principal que contiene.
