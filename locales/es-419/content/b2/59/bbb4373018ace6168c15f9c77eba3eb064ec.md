# Introducción

## Las aserciones let assert

Cuando hacemos coincidencia de patrones sobre un valor en Gleam, debemos asegurarnos de que los patrones cubran todos los valores posibles del tipo; de lo contrario, el código no compila.

Esta función debería ser rechazada, ya que no contempla el caso en que la lista está vacía:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  case items {
    [item, ..] -> item
  }
}
```

La mayoría de las veces, en los programas de Gleam queremos contemplar todos los casos posibles, pero en algunos programas, como prototipos y scripts rápidos, quizá queramos centrarnos solo en el camino feliz y no escribir código para los demás casos. Aquí es donde entra el `let assert` de Gleam.

Con las aserciones let, un patrón puede cubrir solo algunos de los valores posibles de un tipo, y si el patrón no coincide con un valor, el programa se caerá. Usando `let assert` podemos escribir la función anterior así:

```gleam
pub fn get_first_element_or_crash(items: List(e)) -> e {
  let assert [item, ..] = items
  item
}
```

Las bibliotecas de Gleam nunca deberían usar aserciones let, ya que pueden hacer que el programa se caiga. En su lugar, deberían usar el tipo `Result` y dejar que quien desarrolla la aplicación decida cómo manejar los errores.
