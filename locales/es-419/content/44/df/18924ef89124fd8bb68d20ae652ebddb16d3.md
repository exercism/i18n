# Rutinas vinculadas

```sather
   part : ROUT{STR}:STR := bind(shout(_));
   part.call("who's there");
```

## bind

`bind` toma una llamada en la que cualquier parte puede reemplazarse por `_`. Todo lo que no sea un `_` se evalúa **ahora** y se conserva; cada `_` se convierte en un argumento de la rutina vinculada, en el orden en que se escribe.

```sather
   bind(repeat(2, _))         -- ROUT{STR}:STR
   bind(repeat(_, "Ha"))      -- ROUT{INT}:STR
   bind(repeat(_, _))         -- ROUT{INT,STR}:STR
```

## Los tipos

| Tipo | Recibe | Devuelve |
| --- | --- | --- |
| `ROUT:INT` | nada | `INT` |
| `ROUT{STR}` | un `STR` | nada |
| `ROUT{STR}:STR` | un `STR` | un `STR` |
| `ROUT{INT,INT}:BOOL` | dos `INT` | `BOOL` |

`ITER{...}` es la misma idea para un iterador.

## call

`call` proporciona los argumentos restantes. Una rutina vinculada que no devuelve nada se llama de la misma manera, como una sentencia.

## bind va a la derecha de una asignación

Un `bind` se puede declarar en una variable o pasar como argumento:

```sather
   part ::= bind(shout(_));                -- yes
   part : ROUT{STR}:STR := bind(shout(_)); -- yes
   rehearse("line", bind(shout(_)));       -- yes
```

pero no puede ir directamente en un `return`:

```sather
   return bind(shout(_));                  -- does not parse
```

Guárdalo en una variable y devuelve esa variable. El mensaje de error apunta al `bind` y menciona guiones bajos, lo cual no es obvio a partir de la línea misma.

## Dónde se usan

La biblioteca las recibe dondequiera que haya que proporcionar un comportamiento:

```sather
   names.sort_by(bind(shorter(_, _)));
   scores.count_if(bind(over(10, _)));
   scores.find_if(bind(is_even(_)));
```

El ordenamiento es el caso más claro: `sort_by` sabe cómo ordenar y nada acerca de tu idea del orden, y la rutina vinculada es donde ambas se encuentran.

## Una limitación de este compilador

Sather 1.2 no implementa las rutinas vinculadas **despachadas**, es decir, vincular una rutina a una variable de un tipo abstracto. El compilador lo dice sin rodeos:

```
Dispatched bound routines are not implemented yet
```

Vincula sobre un tipo concreto, o sobre una clase, y todo va bien. Por eso el propio arnés de pruebas del track escribe sus verificaciones de excepciones a mano en lugar de tomar una rutina vinculada.

## ¿Rutinas vinculadas o clases abstractas?

Ambas permiten que quien llama proporcione un comportamiento.

Una rutina vinculada es una sola rutina, no necesita una clase y se escribe donde se usa. Una clase abstracta lleva varias rutinas y algo de estado, y vale la pena la ceremonia cuando lo que se proporciona tiene más de una parte.

Una sola rutina que entregar: vincúlala. Un colaborador con varias: escribe una clase.
