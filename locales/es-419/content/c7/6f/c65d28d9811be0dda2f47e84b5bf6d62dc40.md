# Introducción

[concept:csharp/resource-cleanup]() usa la interfaz `IDispose` para indicar que el recurso de algún objeto u otro estado del programa debía liberarse o restablecerse cuando el objeto ya no fuera necesario (y que confiar en el recolector de basura no lograría esto ni proporcionaría el nivel de control requerido) y que el método `IDisposable.Dispose()` era el lugar natural para ese tipo de operaciones de limpieza.

Existe otra construcción, el bloque `using`, que permite, desde la perspectiva de quien llama, reunir toda la gestión del tiempo de vida de los recursos en una sola sentencia.

```csharp
using (var file = new File("my_secrets"))
{
    file.WriteSecret("xxxxxxx");
}
```

En el ejemplo anterior, los recursos del sistema de archivos asociados con `file` se liberarán y devolverán al sistema operativo cuando se salga del bloque `using`.

Para que el patrón funcione, la variable de la sentencia `using` debe ser un tipo de referencia que implemente la interfaz `IDisposable` y debe liberar recursos o restablecer el estado del programa en su método `Dispose()`.

C# 8 introduce un refinamiento del patrón. Una sentencia `using` se puede colocar al principio de un bloque.

```csharp
using var drawingResource = some_provided_or_new_object;
try
{
    drawingResource.DrawSomething();
}
catch (Exception)
{
    throw;
}
```

Quienes programan en Java quizás reconozcan esto como un análogo del mecanismo de _gestión automática de recursos_ introducido en Java 7.
