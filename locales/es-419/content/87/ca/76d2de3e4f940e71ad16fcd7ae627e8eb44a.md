# Elementos asociados

Los elementos asociados son elementos declarados en traits o definidos en implementaciones.

Estos incluyen:

- **Funciones asociadas** (como los métodos)
- **Tipos asociados**
- **Constantes asociadas**
- **Implementaciones asociadas**

Agrupan funcionalidad relacionada lógicamente con un tipo.

Por ejemplo, el método `is_some` de `Option` está intrínsecamente ligado a `Option`.

## Tipos asociados

Los tipos asociados definen marcadores de posición para tipos en traits, que son especificados por quienes los implementan.

Esto mantiene las definiciones de traits flexibles y concisas.

Ejemplo:

```rust
trait Pack<T> {
    type Result;

    fn pack(self: T, other: T) -> Self::Result;
}

impl PackU32Impl of Pack<u32> {
    type Result = u64;

    fn pack(self: u32, other: u32) -> Self::Result {
        let shift: u64 = 0x100000000; // 2^32
        self.into() * shift + other.into()
    }
}
```

Aquí, `Result` es un tipo asociado que determina cada implementación.

Una función que usa este trait no necesita especificar genéricos adicionales:

```rust
fn combine<T, impl PackImpl: Pack<T>>(a: T, b: T) -> PackImpl::Result {
    a.pack(b)
}
```

## Constantes asociadas

Las constantes asociadas son valores fijos ligados a un tipo y definidos en un trait o en su implementación.

Ejemplo:

```rust
trait Shape<T> {
    const SIDES: u32;
    fn describe() -> ByteArray;
}

struct Triangle {}

impl TriangleShape of Shape<Triangle> {
    const SIDES: u32 = 3;
    fn describe() -> ByteArray {
        "I am a triangle."
    }
}

struct Square {}

impl SquareShape of Shape<Square> {
    const SIDES: u32 = 4;
    fn describe() -> ByteArray {
        "I am a square."
    }
}
```

Esto liga constantes como `SIDES` a `Shape` en lugar de codificarlas directamente en otro lugar.

## Implementaciones asociadas

Las implementaciones asociadas obligan a que se cumplan las relaciones entre tipos y traits.

Por ejemplo:

```rust
// Collection type that contains a simple array
#[derive(Drop)]
pub struct ArrayIter<T> {
    array: Array<T>,
}

// T is the collection type
pub trait Iterator<T> {
    type Item;
    fn next(ref self: T) -> Option<Self::Item>;
}

impl ArrayIterator<T> of Iterator<ArrayIter<T>> {
    type Item = T;
    fn next(ref self: ArrayIter<T>) -> Option<T> {
        self.array.pop_front()
    }
}

/// Turns a collection of values into an iterator
pub trait IntoIterator<T> {
    /// The iterator type that will be created
    type IntoIter;
    impl Iterator: Iterator<Self::IntoIter>;

    fn into_iter(self: T) -> Self::IntoIter;
}

impl ArrayIntoIterator<T> of IntoIterator<Array<T>> {
    type IntoIter = ArrayIter<T>;
    fn into_iter(self: Array<T>) -> Self::IntoIter {
        ArrayIter { array: self }
    }
}
```

Esto garantiza que `Array` siempre se pueda convertir en un iterador (`IntoIter`), lo que asegura consistencia y seguridad de tipos.
