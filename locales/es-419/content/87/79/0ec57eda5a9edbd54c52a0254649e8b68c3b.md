# Anexo de instrucciones

## Pros y contras de `from_quote`
Este ejercicio define una función `from_quote` en el tipo `Time`. Esto hace posible escribir código como este:

```roc
time : Time
time = "00:01:23"
```

Este código llama implícitamente a `Time.from_quote("00:01:23")` en tiempo de compilación. Esto puede acelerar el programa, ya que no necesita encargarse del análisis en tiempo de ejecución, y garantiza que las horas que `from_quote` rechaza se detecten en tiempo de compilación en lugar de en tiempo de ejecución. Además, hace que el código sea bonito y legible. Por ejemplo, aquí está una de las pruebas de este ejercicio:

```roc
## start initiates time tracking for current lap
expect {
	result = Stopwatch.create()
		.start()?
		.advance_time("00:00:05")
		|> expect_current_lap("00:00:05")

	result.is_ok()
}
```

Sin embargo, alguien que lea este código podría suponer que la función `advance_time` recibe un `Str`, cuando en realidad recibe un `Time`. Esto puede causar confusión y errores. Por esta razón, quizá prefieras el formato un poco más largo pero más explícito: `"00:00:05".Time`, que también llama a `from_quote` en tiempo de compilación.

En tus propios programas, quizá prefieras usar `from_str` en su lugar:

```roc
Time := { ... }.{
    from_str : time_str -> Try(Time, [InvalidTime])
    from_str = |time_str| ...
}
```

También puedes llamar a `from_str` (o a cualquier otra función pura) en tiempo de compilación, así:

```roc
Ok(time) = Time.from_str("00:01:23")
```

Nota: si colocas esta definición en el nivel superior, se ejecuta en tiempo de compilación (ya que la función es pura y su argumento se conoce en tiempo de compilación). Dentro de una función, puedes usar `from_str` en tiempo de ejecución.
