# Introducción

Como vimos en el concepto [`Nothingness`][concept-nothingness], R tiene varias formas de representar datos que están ausentes (`NULL`), que son desconocidos (`NA`) o que no son matemáticamente válidos (`NaN`, `Inf`).
En general, R intentará usar estos valores para señalar los problemas en el propio lugar, y continuará sin lanzar una excepción.

## `stop()`

Algunos problemas son demasiado fundamentales como para dejar que el programa continúe.
En este caso, usa `stop(msg)` para detener el programa de inmediato con un `Error` e imprimir `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Similar a un `assert` en otros lenguajes, es una forma cómoda de llamar a `stop()`.
Los argumentos son una cantidad arbitraria de condiciones de tipo Boolean separadas por comas, y el programa solo continuará si todas son `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `try()`

R tiene varias formas de manejar los errores.
Se basan en Common Lisp y difieren bastante de muchos lenguajes populares.

La más sencilla es envolver el código que podría dar problemas en `try()`.

```R
g <- function(val) {
  log10(val)
}

g(3)
#> [1] 0.4771213

g("3")
#> Error in log10(val) : non-numeric argument to mathematical function

# with try() and a default value
h <- function(val) {
  result <- NA
  try(result <- log10(val))
  result
}

h(3) # works as before
#> [1] 0.4771213

h("3") # returns a default value plus the error message
#> Error in log10(val) : non-numeric argument to mathematical function
#> [1] NA
```

## `warning()` y `message()`

Estas son respuestas a condiciones que no son fatales, por ejemplo:

- Advertir sobre un problema del que el programa podría recuperarse al menos en parte.
- Informar al usuario sobre el avance de un programa que tarda mucho en ejecutarse.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

La función `suppressWarnings()` a veces puede ser útil dentro de Exercism, para evitar confundir al ejecutor de pruebas con salida no deseada.
