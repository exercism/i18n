# Acerca de

`<dlist>` (en [`dlists`][dlists]) construye una lista doblemente enlazada nueva. Las operaciones viven en [`deques`][deques] y se despachan según el [protocolo de deque][deque-protocol], así que otros contenedores, principalmente `<dlist>`, pueden implementarlas.

| palabra         | efecto                              |
|-----------------|-------------------------------------|
| `<dlist>`       | `( -- dlist )`: deque nuevo y vacío  |
| `push-front`    | `( elt deque -- )`: agrega al frente |
| `push-back`     | `( elt deque -- )`: agrega al final  |
| `pop-front`     | `( deque -- elt )`: quita del frente |
| `pop-back`      | `( deque -- elt )`: quita del final  |
| `peek-front`    | `( deque -- elt )`: lee el frente sin quitarlo |
| `peek-back`     | `( deque -- elt )`: lee el final sin quitarlo  |
| `deque-empty?`  | `( deque -- ? )`: ¿está vacío el deque? |
| `dlist-length`  | `( dlist -- n )`: cantidad de elementos |

Todas las operaciones de push/pop modifican el deque en el lugar. Pasar un deque a una rutina y después volver a leerlo es el patrón normal.

## Pila vs. cola

Dos patrones de despacho convencionales:

```
LIFO (stack): push-back + pop-back   (or push-front + pop-front)
FIFO (queue): push-back + pop-front  (or push-front + pop-back)
```

Un vector con `push` y `pop` (de `mutation`) es la opción correcta cuando lo único que necesitas es el orden LIFO, ya que `<dlist>` arrastra la sobrecarga de una lista enlazada. Recurre a `<dlist>` cuando necesites O(1) en *ambos* extremos, casi siempre para una cola FIFO.

## Patrón de BFS

Una búsqueda en anchura (BFS) es el uso canónico de FIFO:

```factor
:: reachable ( start graph -- visited )
    HS{ } clone :> visited
    <dlist>    :> frontier
    start visited adjoin
    start frontier push-back
    [ frontier deque-empty? ] [
        frontier pop-front graph at [
            dup visited in? [ drop ] [
                [ visited adjoin ] [ frontier push-back ] bi
            ] if
        ] each
    ] until
    visited ;
```

El deque lleva la frontera de la búsqueda; el conjunto hash se encarga de la deduplicación. Cambia `pop-front` por `pop-back` y la misma estructura se vuelve una búsqueda en profundidad.

## `MEMO:`: caché automática

A veces la consulta por nodo que hace el BFS es costosa. Factor ofrece [`MEMO:`][memo-decl], un reemplazo de `:` que guarda automáticamente en caché el resultado de la palabra, indexado por sus argumentos:

```factor
USING: memoize ;

MEMO: expensive-neighbours ( node -- nodes )
    ! ... slow computation ...
    ;
```

Una palabra `MEMO:` ejecuta su cuerpo la primera vez que ve cada argumento y, a partir de ahí, devuelve el resultado guardado en caché. La caché vive mientras dure la imagen; no hay expulsión por tiempo ni por tamaño. Úsala con funciones puras cuyos argumentos provengan de un conjunto finito y manejable.
