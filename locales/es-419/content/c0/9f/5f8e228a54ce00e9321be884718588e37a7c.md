# Instrucciones

El proyecto del carro de control remoto continúa. El ancho de banda del sistema de telemetría es muy limitado, así que te han pedido implementar un protocolo de mensajes para comunicar los datos de telemetría.

Los datos se transmiten en un búfer (array de bytes). Cuando se envían números enteros, el tamaño del búfer se reduce empleando el protocolo que se describe a continuación.

Cada valor debe representarse con el tipo entero más pequeño posible (los tipos `byte` y `sbyte` no se incluyen, ya que el ahorro sería insignificante):

| De                         | A                         | Tipo     |
| -------------------------- | ------------------------- | -------- |
| 4_294_967_296              | 9_223_372_036_854_775_807 | `long`   |
| 2_147_483_648              | 4_294_967_295             | `uint`   |
| 65_536                     | 2_147_483_647             | `int`    |
| 0                          | 65_535                    | `ushort` |
| -32_768                    | -1                        | `short`  |
| -2_147_483_648             | -32_769                   | `int`    |
| -9_223_372_036_854_775_808 | -2_147_483_649            | `long`   |

El valor debe convertirse a la cantidad de bytes apropiada para el tipo que se le asigne. El búfer completo se compone de un byte que indica la cantidad de bytes adicionales en el búfer (*byte de prefijo*) seguido de los bytes que contienen el número entero (*bytes de carga útil*).

Algunos de los tipos usan una cantidad idéntica de bytes (por ejemplo, los tipos `uint` e `int`). Normalmente tendrían el mismo *byte de prefijo*, pero eso haría que la decodificación fuera problemática. Para contrarrestarlo, el protocolo introduce un pequeño truco: en los tipos con signo, el valor de su *byte de prefijo* es `256` menos la cantidad de bytes adicionales en el búfer.

En la comunicación solo se enviarán el byte de prefijo y la cantidad de bytes siguientes que este indique. De forma interna se usa un búfer de 9 bytes (con ceros al final, según sea necesario), tanto en las rutinas de envío como en las de recepción.

## 1. Codifica un valor entero listo para enviar

Implementa el método estático `TelemetryBuffer.ToBuffer()` para codificar un búfer tomando el parámetro que se le pasa al método.

```csharp
// Type: ushort, bytes: 2, signed: no, prefix byte: 2
TelemetryBuffer.ToBuffer(5)
// => {0x2, 0x5, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0 };

// Type: int, bytes: 4, signed: yes, prefix byte: 256 - 4
TelemetryBuffer.ToBuffer(Int32.MaxValue)
// => {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 };
```

## 2. Decodifica un búfer recibido

Implementa el método estático `TelemetryBuffer.FromBuffer()` para decodificar el búfer recibido y devolver el valor en forma de `long`.

```csharp
TelemetryBuffer.FromBuffer(new byte[] {0xfc, 0xff, 0xff, 0xff, 0x7f, 0x0, 0x0, 0x0, 0x0 })
// => 2147483647
```

Si el byte de prefijo tiene un valor inesperado, se debe devolver `0`.
