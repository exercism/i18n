Los ejercicios de Odin que están dentro del directorio de tu proyecto de Exercism se pueden ejecutar si te cambias al directorio del ejercicio y ejecutas `odin test .`.

```sh
cd "$(exercism workspace)"/odin/leap
odin test .
```

## Habilitar las verificaciones del lenguaje

Mientras ejecutas las pruebas, Odin puede hacer un «vet» de tu código: puede buscar cosas como importaciones y variables sin usar.

Ejecuta tus pruebas con

```sh
odin test . -vet
```

Para obtener aún más verificaciones, agrega la opción `-strict-style`.

## Desarrollo guiado por pruebas (TDD)

`odin test` ejecuta cada procedimiento que tiene el atributo `@(test)`.

En el conjunto de pruebas, notarás que cada procedimiento de prueba tiene este atributo.
Esto significa que cuando lanzas las pruebas, cada procedimiento de prueba se va a ejecutar.

Por lo general, Exercism promueve el [desarrollo guiado por pruebas][tdd], en el que:

- al principio, todas las pruebas excepto la primera están configuradas para omitirse;
- escribes solo el código suficiente para pasar la primera prueba;
- luego habilitas la siguiente prueba y escribes solo el código suficiente para que pase;
- repites hasta que tu código pase todas las pruebas.

Nosotros (quienes mantenemos el track) no encontramos una manera programática elegante de ejecutar solo un subconjunto de las pruebas.
El archivo de pruebas simplemente se volvió demasiado difícil de manejar.
Para desarrollar con TDD, puedes editar el archivo de pruebas y comentar las pruebas que aún no estás listo para ejecutar, y descomentarlas una por una a medida que escribes tu solución.
