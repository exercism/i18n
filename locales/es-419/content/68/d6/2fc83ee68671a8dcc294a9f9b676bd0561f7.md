# Traits

Un trait especifica un conjunto de métodos que un tipo puede implementar.
Los traits son útiles para definir métodos que deberían compartirse entre tipos.
Cuando los traits se usan con tipos genéricos, los métodos definidos se pueden llamar sobre un tipo en particular, pero también es posible llamarlos sobre otro tipo de dato.
De forma abstracta, con el uso de _límites de trait_, podemos especificar que el tipo genérico debe compartir cierto comportamiento.

> **Nota:** Los traits comparten una característica similar a lo que se conoce como interfaces en otros lenguajes de programación, con algunas diferencias.

## Definición de un trait

Definir un trait ayuda a identificar la firma de función que conformaría el conjunto de comportamientos que un tipo puede implementar para lograr un resultado.
Estos métodos forman el comportamiento de un tipo.
Si podemos llamar a los mismos métodos en tipos distintos, esto implica que los tipos involucrados tienen el mismo comportamiento.

```rust
#[derive(Drop)]
pub struct NewsArticle {
    pub headline: ByteArray,
    pub location: ByteArray,
    pub author: ByteArray,
    pub content: ByteArray,
}

// A trait for NewsArticle struct type
pub trait Summary {
    fn summarize(self: @NewsArticle) -> ByteArray;
}
```

Según la definición del trait `Summary` de arriba, el método `summarize` es un comportamiento que solo puede ser llamado por el tipo de struct `NewsArticle`.
Si se invoca en instancias de otro tipo, produce un error de compilación.
Declarar el trait con la palabra clave `pub` expone el trait de este crate a otros crates que también quieran usarlo.
Fíjate también en que usamos un punto y coma después de declarar las firmas de método en los traits.

Un trait se puede definir con un argumento genérico, lo que permite que una función reciba un argumento de cualquier tipo de dato.
Esto aporta flexibilidad a la firma de la función y le permite manejar distintos tipos de dato.
En el caso del trait `Summary` de abajo, este se rediseñó para funcionar con cualquier tipo de dato, de modo que cuando se invoca el método `summarize` en ellos, devuelva un ByteArray.

```rust
// A trait for a generic type
pub trait Summary<T> {
    fn summarize(self: @T) -> ByteArray;
}
```

Un trait puede tener más de un método en su cuerpo; cada firma de método declarada es una línea que termina con un punto y coma.

## Implementación de un trait en un tipo

Después de definir las firmas de función que componen un trait, el compilador exigirá que también se defina una implementación para los tipos que adoptan el trait.
Abajo escribimos un crate de biblioteca `aggregator` para medios que resume algunos datos de instancias de `NewsArticle` y `Tweet`.
Para el struct `NewsArticle`, usaríamos los campos headline, author y location para devolver el valor del método `summarize` del trait `Summary`; mientras que para el struct `Tweet`, usaríamos el username y el content, suponiendo que el contenido del tweet tiene un límite de 280 caracteres.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray;
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {
        fn summarize(self: @NewsArticle) -> ByteArray {
            format!("{} by {} ({})", self.headline, self.author, self.location)
        }
    }

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    let tweet = Tweet {
        username: "EliBenSasson",
        content: "Crypto is full of short-term maximizing projects. \n @Starknet and @StarkWareLtd are about long-term vision maximization.",
        reply: false,
        retweet: false
    };

    println!("New article available! {}", news.summarize());
    println!("New tweet! {}", tweet.summarize());
}
```

## Implementaciones predeterminadas

A veces, un trait se puede definir con una implementación predeterminada para algunos o todos los métodos que lo componen.
Esto evita tener que implementar todos los métodos en cada tipo y mejora la legibilidad del código.
Si algún tipo en particular necesita una implementación especial de un método del trait, puede sobrescribir la implementación predeterminada.

```rust
mod aggregator {
    pub trait Summary<T> {
        fn summarize(self: @T) -> ByteArray {
            "(Read more...)"
        }
    }

    #[derive(Drop)]
    pub struct NewsArticle {
        pub headline: ByteArray,
        pub location: ByteArray,
        pub author: ByteArray,
        pub content: ByteArray,
    }

    impl NewsArticleSummary of Summary<NewsArticle> {}

    #[derive(Drop)]
    pub struct Tweet {
        pub username: ByteArray,
        pub content: ByteArray,
        pub reply: bool,
        pub retweet: bool,
    }

    impl TweetSummary of Summary<Tweet> {
        fn summarize(self: @Tweet) -> ByteArray {
            format!("{}: {}", self.username, self.content)
        }
    }
}

use aggregator::{Summary, NewsArticle, Tweet};

fn main() {
    let news = NewsArticle {
        headline: "Cairo has become the most popular language for developers",
        location: "Worldwide",
        author: "Cairo Digger",
        content: "Cairo is a new programming language for zero-knowledge proofs",
    };

    println!("New article available! {}", news.summarize()); // prints "New article available! (Read more...)"


    let tweet = Tweet {
        username: "Alice",
        content: "Cairo is fun and engaging.",
        reply: true,
        retweet: true,
    };
    println!("New tweet from {}", tweet.summarize()); // prints "New tweet from Alice: Cairo is fun and engaging."
}
```

## Cómo usar y gestionar traits externos

Los traits y las implementaciones se pueden definir en un módulo externo y usarse en otros módulos, siempre que se importen correctamente.
Supongamos que tenemos un trait `ShapeGeometry` con el método `boundary`, que debe implementarse tanto para el struct `Circle` como para el struct `Rectangle`.
Abajo hay un ejemplo de cómo se importa, se gestiona y se usa el trait y su implementación entre módulos.

```rust
// Here T is an alias type which will be provided during implementation
pub trait ShapeGeometry<T> {
    fn boundary(self: T) -> u64;
    fn area(self: T) -> u64;
}

mod rectangle {
    // Importing ShapeGeometry is required to implement this trait for Rectangle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Rectangle {
        pub height: u64,
        pub width: u64,
    }

    // Implementation RectangleGeometry passes in <Rectangle>
    // to implement the trait for that type
    impl RectangleGeometry of ShapeGeometry<Rectangle> {
        fn boundary(self: Rectangle) -> u64 {
            2 * (self.height + self.width)
        }
        fn area(self: Rectangle) -> u64 {
            self.height * self.width
        }
    }
}

mod circle {
    // Importing ShapeGeometry is required to implement this trait for Circle
    use super::ShapeGeometry;

    #[derive(Copy, Drop)]
    pub struct Circle {
        pub radius: u64
    }

    // Implementation CircleGeometry passes in <Circle>
    // to implement the imported trait for that type
    impl CircleGeometry of ShapeGeometry<Circle> {
        fn boundary(self: Circle) -> u64 {
            (2 * 314 * self.radius) / 100
        }
        fn area(self: Circle) -> u64 {
            (314 * self.radius * self.radius) / 100
        }
    }
}

use rectangle::Rectangle;
use circle::Circle;

fn main() {
    let rect = Rectangle { height: 5, width: 7 };
    println!("Rectangle area: {}", ShapeGeometry::area(rect)); //35
    println!("Rectangle boundary: {}", ShapeGeometry::boundary(rect)); //24

    let circ = Circle { radius: 5 };
    println!("Circle area: {}", ShapeGeometry::area(circ)); //78
    println!("Circle boundary: {}", ShapeGeometry::boundary(circ)); //31
}
```

La visibilidad de las implementaciones `CircleGeometry` y `RectangleGeometry` no necesita ser pública, ya que el trait `ShapeGeometry` se hace público y el compilador debería encontrarlo con facilidad.

## Alias de impl

Las implementaciones se pueden crear como alias al importarlas, usando la palabra clave `impl`.
Esto ayuda cuando se instancia una implementación genérica para tipos concretos.
Definamos una implementación trivial del trait `Two` para todos los tipos que implementan el trait `One`, simplemente sumando dos veces el valor de `One` y devolviendo la suma.
Luego podemos exponer la implementación de `Two` que funciona solo para los tipos `u8` y `u128`.

```rust
trait Two<T> {
    fn two() -> T;
}

mod one_based {
    pub impl TwoImpl<
        T, +Copy<T>, +Drop<T>, +Add<T>, impl One: core::num::traits::One<T>
    > of super::Two<T> {
        fn two() -> T {
            One::one() + One::one()
        }
    }
}

pub impl U8Two = one_based::TwoImpl<u8>;
pub impl U128Two = one_based::TwoImpl<u128>;
```

La implementación genérica se puede escribir en un módulo privado y, con el uso de un alias de impl, podemos instanciar la implementación genérica de estos dos tipos concretos.
La ventaja de usar una implementación genérica privada y no expuesta es que evita la duplicación de código entre archivos.
Además, mantiene la API pública simple y limpia.
