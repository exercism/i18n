# Acerca de

En muchos lenguajes orientados a objetos, es común extender comportamientos mediante la [creación de subclases][wiki-subclass] de una clase padre: se heredan métodos de la clase padre y a la vez se agregan otros nuevos.
Así obtenemos una jerarquía de objetos.

Julia _no tiene clases_, así que, por extensión, _no tiene subclases_.
¿Cómo heredamos y extendemos los comportamientos existentes?

En conceptos anteriores vimos cómo crear una jerarquía de tipos y también aprendimos cómo Julia usa el [despacho múltiple][concept-multiple-dispatch] para elegir métodos según los tipos de los argumentos.

Julia también tiene varias [interfaces][ref-interfaces] informales, que permiten que tus tipos personalizados se conecten con comportamientos ya definidos para los tipos estándar.

Esto se ilustra más fácilmente con la interfaz de iteradores.

## [Iteradores][ref-iterators]

Antes, en el temario, hemos visto varias formas en que Julia puede operar sobre cada elemento de una colección.

- [Bucles][concept-loops], como `for item in items...`
- [Broadcasting][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Funciones de orden superior][concept-hof]: `map(√, [1, 4, 9])`
- [Comprensiones][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Generadores][concept-comprehensions]: `(x^2 for x in 1:1e6)`, que se evalúa de forma perezosa.

Está claro que Julia sabe recorrer las colecciones estándar elemento por elemento: vectores y rangos en los ejemplos anteriores, y también Set, Dict, etc.

¿Cómo agregamos esta capacidad a nuestras propias colecciones personalizadas, sobre todo si pueden iterarse de forma perezosa como un generador?

### Requisitos mínimos

Para crear una secuencia que se pueda iterar, necesitamos (al menos) dos cosas:

1. Una forma de obtener el _primer_ elemento.
2. Una forma de obtener el _siguiente_ elemento a partir del estado actual.

Julia logra esto con métodos de la función `Base.iterate()`, mediante los siguientes pasos:

1. Se llama automáticamente a `Base.iterate(iter)` primero.
    - Si no hay nada que iterar, devuelve `nothing`.
    - De lo contrario, devuelve la `Tuple` con el primer elemento devuelto y el primer estado: `(firstitem, firststate)`.
2. Se llama automáticamente a `Base.iterate(iter, state)` si en la iteración anterior se devolvió un elemento, tomando `firststate` como su argumento `state`.
    - Si la iteración termina, devuelve `nothing`.
    - De lo contrario, devuelve la `Tuple` con el siguiente elemento y el siguiente estado: `(nextitem, nextstate)`.
3. Repite el paso 2 hasta que la iteración termine.

Todos estos pasos ocurren «entre bambalinas», lo que significa que el protocolo de iteración gestiona internamente las llamadas a los métodos y el estado (el estado permanece opaco), y solo el elemento queda expuesto a las construcciones de alto nivel, como los bucles.
En otras palabras, lo único que vemos es el `item`, mientras que todo lo demás permanece en una caja negra.

El [despacho múltiple][concept-multiple-dispatch] es clave aquí.
El tipo de `iter` determina qué métodos se llaman, y la cantidad de argumentos determina si se devuelve el primer elemento o el siguiente.

Los métodos para los tipos estándar ya están definidos: `Vector`, `Range`, `Set`, etc. ([actualmente][ref-iterations-collections], 14 tipos en total).

Para que un `MyType` personalizado comparta estos mismos comportamientos, primero tenemos que definir:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Todo esto probablemente suene confuso en abstracto, pero puede ser bastante sencillo.
A modo de ejemplo, imagina que queremos un tipo que genere las potencias de un entero `n` dado, hasta un número máximo de elementos.

Primero, define un tipo personalizado:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Ahora podemos definir los métodos `iterate` para este tipo, pero ¿cuáles son el primer elemento y el primer estado?

Para obtener el primer elemento, algunos iteradores necesitan una preparación complicada, pero en este caso sencillo podemos ver que el primer elemento devuelto es simplemente el número base, así que solo tenemos que comprobar si el valor de `count` es mayor o igual que uno.

Ahora podemos pensar en el primer estado, que lleva la información que se usa en la siguiente iteración.
Tú decides qué información necesitas llevar para lograrlo, y puede ser de cualquier tipo.

En este caso, podríamos simplemente llevar la cuenta del «índice» al que elevar `n`, o podemos encontrar una opción más eficiente usando la potencia más reciente de `n` (es decir, el elemento devuelto) y el siguiente «índice» de la secuencia.
Estos dos números se pueden envolver en una `Tuple` y devolver como el `state`.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

En este ejemplo, el primer elemento (`p.n`) se devuelve al bucle y el primer estado `(p.n, 2)` se pasa al método `iterate(P::Powers, state)`.
Ahí podemos procesar el estado para producir el siguiente elemento multiplicando el elemento actual por el número base, con lo que aumentamos su potencia en `1`.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Si el valor del índice sigue dentro de `count`, se devuelve la `Tuple` con el elemento `next` y el estado incrementado `(next, index + 1)`.
Cuando el valor de `index` supera `count`, se devuelve `nothing` en su lugar, para indicar que la iteración terminó.

Quizá hayas notado que los métodos `iterate(p::Powers)` e `iterate(p::Powers, state)` tienen cuerpos de función bastante parecidos.
De hecho, si somos astutos, esta similitud permite una implementación más compacta usando solo la versión de dos argumentos, con un argumento predeterminado para el estado: `Base.iterate(p::Powers, state=(1, 1))`
Con eso no necesitaríamos el método separado de un solo argumento `iterate(p::Powers)`.
En la práctica esto se hace a menudo cuando es posible.

~~~~exercism/advanced
Cuando presentamos los argumentos opcionales en el concepto de [Funciones][concept-functions], no dijimos nada sobre su implementación.

Desde entonces aprendimos sobre el despacho múltiple, así que ahora tiene más sentido saber que Julia convierte automáticamente una función _con_ argumentos opcionales en varios métodos _sin_ argumentos opcionales.

Definir `Base.iterate(P::Powers, state=(1, 1))` es exactamente equivalente a definir por separado tanto `Base.iterate(P::Powers, state)` como `Base.iterate(P::Powers)`.

[concept-functions]: https://exercism.org/tracks/julia/concepts/functions
~~~~

Hasta ahora ya tenemos algunas funcionalidades útiles: para las primeras 4 potencias de 3, podemos recorrer los resultados con un bucle, comprobar si un número dado está entre los resultados y aplicar funciones de agregación como `sum()`.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Métodos adicionales

A pesar de este buen comienzo, todavía no funciona todo.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers)
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

En efecto, `length(Powers(3, 4))` da exactamente el mismo mensaje de error.

Esto se arregla fácilmente, ya que la longitud forma parte del constructor del tipo: 4 en este caso.
Solo tenemos que definir `Base.length()` para este tipo, y luego podremos usar comprensiones y `collect()` sobre la secuencia.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Por eficiencia, es mejor definir también `Base.eltype()`: el tipo de elemento del resultado.
Esto permite que funciones como `collect()` reserven de antemano espacio para el `Vector{Int}` de salida, en lugar de hacer repetidamente un `push!()` sobre un `Vector{Any}`.

Fíjate en la sintaxis, que puede que no hayas visto antes: este método se define sobre el _tipo_, no sobre una _instancia_ del tipo.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

No es _obligatorio_ que los iteradores tengan una longitud finita.
El uso de secuencias «infinitas» está más limitado, pero recorrerlas con un bucle puede ser útil siempre que haya alguna forma de salir del bucle con `break`.
Por ejemplo, podríamos definir una variante de `Powers` que generara valores menores que cierto límite (quizá `typemax(Int)`, para evitar el desbordamiento de enteros).

## Otras interfaces

### [Indexación][ref-indexing]

La interfaz de iteradores nos permite tomar un tipo personalizado arbitrario y hacer que se comporte como una secuencia, con solo definir unos pocos métodos sencillos.

Supongamos que además queremos poder indexar la secuencia:

```julia-repl
julia> P = Powers(3, 4)
Powers(3, 4)

julia> P[2]
ERROR: MethodError: no method matching getindex(::Powers, ::Int64)
The function `getindex` exists, but no method is defined for this combination of argument types.
```

Podemos agregar este comportamiento, y el [manual][ref-indexing] explica cómo.

Como mínimo, tenemos que definir `getindex()`.

```julia-repl
julia> function Base.getindex(P::Powers, i::Int)
          1 ≤ i ≤ P.count || throw(BoundsError(P, i))
          return p.n ^ i
       end

julia> p = Powers(3, 4)
Powers(3, 4)

julia> p[3]
27
```

También tenemos que definir:

- `firstindex()` y `lastindex()` para admitir `P[begin]` y `P[end]`.
- Variantes de `getindex()` para admitir la indexación con vectores y rangos.
- En teoría, `setindex!()`, aunque es difícil ver qué significaría eso siquiera en este ejemplo.

Sin embargo, a estas alturas estamos haciendo mucho trabajo solo para que nuestro iterador se parezca más a un Vector.

### [AbstractArray][ref-abstractarray]

Puede valer la pena pensar en interfaces alternativas que ofrezcan un mejor punto de partida.

En este caso, podríamos considerar hacer que `Powers` sea un subtipo de [`AbstractArray`][ref-abstractarray], lo que nos da gratis gran parte del comportamiento propio de un array.

Para la secuencia `Powers`, el array correspondiente es de enteros y tiene 1 dimensión.
A veces verás esto escrito como `AbstractArray{Int, 1}`, pero los alias `AbstractVector{Int}` para 1-D y `AbstractMatrix{Int}` para 2-D son más comunes en el código Julia más reciente.

```julia-repl
julia> struct PowersArray <: AbstractVector{Int}
           n::Int
           count::Int
       end
```

En lugar de `length()`, ahora tenemos que definir `size()` con una tupla de longitudes a lo largo de cada dimensión: solo una dimensión en este caso.

```julia-repl
julia> Base.size(PA::PowersArray) = (PA.count,)
```

¿Cómo queremos indexar las entradas?
En el [concepto de arrays multidimensionales][concept-multi-dimensional-arrays] presentamos los dos enfoques principales:

- Un índice por dimensión, es decir, `M[row, col]` para una matriz `M`.
- Un único índice, que corresponde a la disposición de las entradas en la memoria

Estos se llaman `Cartesian` y `Linear`, respectivamente.

En el ejemplo solo tenemos una dimensión, así que la indexación lineal es la adecuada.

```julia-repl
julia> Base.IndexStyle(::Type{PowersArray}) = IndexLinear()

julia> Base.getindex(PA::PowersArray, i::Int) = PA.n ^ i

julia> p = PowersArray(3, 4)
4-element PowersArray:
  3
  9
 27
 81

julia> p[3]
27
```

Fíjate en que en este caso no definimos `iterate()`.
Julia proporciona automáticamente una implementación predeterminada, basada en nuestra definición de `getindex()`.

Definir nuestra propia versión de `iterate()` sigue siendo posible y, en algunos casos, puede ser más eficiente.

Usar la interfaz `AbstractArray` es especialmente valioso si queremos iteración de dimensiones superiores.
A riesgo de llevar el ejemplo sencillo más allá de su límite, esto podría significar las primeras `m` potencias de los números en `1:n`, lo que definirá de forma iterativa un array de tamaño `(m, n)`.

```julia-repl
struct PowersMatrix{Int} <: AbstractMatrix{Int}
    ns::AbstractVector{Int}
    count::Int
end

Base.size(PM::PowersMatrix) = (PM.count, length(PM.ns))
Base.IndexStyle(::Type{PowersMatrix}) = IndexCartesian()
Base.getindex(PM::PowersMatrix, i::Int, j::Int) = PM.ns[j] ^ i

julia> PM = PowersMatrix(2:6, 4)
4×5 PowersMatrix{Int64}:
  2   3    4    5     6
  4   9   16   25    36
  8  27   64  125   216
 16  81  256  625  1296

julia> PM[3, 2]
27

julia> PM[7] # column major linear indexing
27

julia> PM[21]
BoundsError: attempt to access 4×5 PowersMatrix{Int64} at index [21]
[...]
```

### [Redondeo][ref-rounding]

En conceptos anteriores se mencionaron varios tipos de redondeo para los tipos numéricos.

```julia-repl
julia> round(1.7)
2.0

julia> floor(1.7)
1.0

julia> ceil(1.7)
2.0

# specify output type
julia> round(Int, 1.7)
2

julia> round(2.4 + 7.3im)
2.0 + 7.0im
```

La función [`round()`][ref-round] es más flexible que esto: te permite especificar el [`RoundingMode`][ref-roundingmode] (de los 7 que se admiten actualmente), la cantidad de decimales del resultado y la base numérica.

Puede que queramos que las mismas funciones manejen nuestros tipos personalizados.
Normalmente esto se refiere a tipos compuestos como las coordenadas.

```julia-repl
julia> struct Point3D
           x::Float64
           y::Float64
           z::Float64
       end

julia> p = Point3D(7.63, 9.24, 4.50)
Point3D(7.63, 9.24, 4.5)

julia> round(p)
ERROR: MethodError: no method matching round(::Point3D, ::RoundingMode{:Nearest})
The function `round` exists, but no method is defined for this combination of argument types.
```

Como era de esperar, existe una interfaz `Rounding`, que como mínimo requiere que definamos `round()` para nuestro tipo.

```julia-repl
julia> Base.round(P3D::Point3D, r::RoundingMode) = Point3D(round(P3D.x, r), round(P3D.y, r),round(P3D.z, r))

julia> round(p)
Point3D(8.0, 9.0, 4.0)

julia> ceil(p)
Point3D(8.0, 10.0, 5.0)
```

Como incluimos `RoundingMode` en la definición, `floor()` y `ceil()` funcionan automáticamente.

Por supuesto, somos libres de definir formas de redondeo más complicadas.

- Puede que queramos redondear `Point3D` a una distancia entera desde el origen, en la misma dirección.
- Para los ángulos, puede que queramos redondear a las 16 direcciones que usan los meteorólogos (_«viento del SSO a 15 nudos»_), es decir, múltiplos de π/8 radianes.
- Puede que queramos agregar la capacidad de especificar `digits`, `sigdigits` o `base`.
- Hay [opciones especiales][ref-round-periods] para los períodos de tiempo

## Resumen

Las interfaces son bastante confusas de explicar, porque el enfoque de Julia es muy distinto al de la mayoría de los otros lenguajes.
En particular, puede que el nombre de la interfaz nunca se mencione en la implementación: muy distinto de la [creación de subclases][wiki-subclass] o los [mixins][wiki-mixins].

Sin embargo, en la práctica son sorprendentemente sencillas:

1. Define un tipo adecuado, decidiendo si el subtipado resulta útil o no.
2. Averigua qué métodos se requieren (en la [documentación][ref-interfaces]).
3. Implementa esos métodos para tu tipo personalizado; normalmente son solo unos pocos métodos, bastante cortos y sencillos.
4. Deja que el [despacho múltiple][concept-multiple-dispatch] se encargue del resto, automáticamente.
