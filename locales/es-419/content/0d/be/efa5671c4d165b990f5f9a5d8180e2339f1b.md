# Acerca de

Los [tipos personalizados][custom-types] en Elm representan una cantidad fija de casos con nombre. Cada valor corresponde exactamente a uno de esos casos con nombre. En otros lenguajes y contextos se conocen como _tipos suma_, _uniones discriminadas_, _uniones etiquetadas_ y _tipos de datos algebraicos_.

Cada caso de una unión discriminada puede tener datos asociados de forma opcional, y distintos casos pueden tener distintos tipos de datos. Si ninguno de los casos tiene datos asociados, la unión discriminada se parece a lo que en otros lenguajes suele llamarse una _enumeración_ (o _enum_).

Un tipo personalizado se define con la palabra clave `type` y requiere muy poca sintaxis. Es una de las técnicas más importantes de la programación en Elm, y se usa para que los valores posibles en el código coincidan exactamente con los valores válidos en la vida real, lo que no deja espacio para datos inválidos y hace que los [estados imposibles sean imposibles de representar en el código][impossible-states].

```elm
-- Custom Type without associated data
type Season
    = Spring
    | Summer
    | Autumn
    | Winter

-- Custom Type with associated data
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Puedes crear un valor para un caso específico refiriéndote a su nombre (`Spring`), cuando está definido en el mismo módulo o se importa con la sintaxis `import SeasonModule exposing (Season(..))`, o refiriéndote a su nombre totalmente cualificado (`Season.Spring`) cuando se importa con la sintaxis `import SeasonModule exposing (Season)`.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

Los tipos personalizados, junto con todo lo demás en Elm, tienen _igualdad estructural_, lo que significa que dos valores para el mismo caso y con los mismos datos (opcionales) son equivalentes.

La forma preferida de trabajar con tipos personalizados es la [coincidencia de patrones][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
