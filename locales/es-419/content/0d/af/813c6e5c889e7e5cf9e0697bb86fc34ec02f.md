# Excepciones

Algunas rutinas no pueden responder. Cuando se le pide un prop que no está sobre la mesa, `count_of` no tiene ningún número que dar, y cero sería una mentira, porque cero significa «no tenemos ninguno de esos», no «no existe tal cosa».

Una **excepción** es la forma en que una rutina dice que no puede responder.

## Lanzamiento

`raise` abandona la rutina y le entrega un valor a quien la llamó.

```sather
   count_of(props : FMAP{STR,INT}, prop : STR) : INT is
      if ~props.has_ind(prop) then
         raise "Unknown prop: " + prop;
      end;
      return props.get(prop);
   end;
```

Nada de lo que sigue a un `raise` se ejecuta. La rutina no devuelve nada, así que no hay respuesta que revisar ni forma de que quien la llamó continúe como si la hubiera.

El valor que se lanza suele ser un string que dice qué salió mal.

## Captura

`protect` ejecuta un fragmento de código, preparado por si este lanza una excepción.

```sather
   protect
      taken ::= count_of(props, prop);
      #OUT + "There are " + taken;
   when $STR then
      #OUT + "Cannot: " + exception.str;
   end;
```

Si nada lanza una excepción, se ejecuta la parte que sigue a `protect` y se omite la rama `when`. Si algo lanza una excepción, se abandona el resto de la parte `protect` y en su lugar se ejecuta el `when` que corresponda.

`when $STR then` captura un string lanzado. `exception` es el valor que se lanzó, disponible dentro de la rama.

## Propagación

Una rutina que no captura una excepción no tiene que hacer nada al respecto. Esta se propaga hacia afuera, pasando por cada rutina que la llamó, hasta que algo la captura:

```sather
   take_one(props : FMAP{STR,INT}, prop : STR) : INT is
      -- If this raises, take_one raises too. Nothing here says so.
      have ::= count_of(props, prop);
      ...
   end;
```

Esa es la idea de las excepciones. La rutina que nota el problema y la rutina que sabe qué hacer al respecto normalmente no son la misma, y todo lo que hay en medio puede ignorarla.
