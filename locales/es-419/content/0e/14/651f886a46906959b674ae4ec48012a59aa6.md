# Pruebas

Las pruebas de un proyecto de Elm están en el subdirectorio `tests/` de ese proyecto.
Puedes ejecutar las pruebas de cada ejercicio desde el directorio raíz de ese ejercicio.

```bash
$ cd ~/exercism/elm/hello-world
$ elm-test
```

## Vigila los cambios

Vuelve a ejecutar las pruebas automáticamente cada vez que guardes cambios:

```bash
$ elm-test --watch
```

## Flujo de desarrollo guiado por pruebas

En la mayoría de los ejercicios, las pruebas ya están escritas en el archivo `tests/Tests.elm`.
Tu objetivo es hacer que pasen escribiendo el código necesario
en el archivo `src/<exercise>.elm`.
Céntrate en la primera prueba que falle, corrígela,
luego elimina o comenta el siguiente fragmento `skip <|` del archivo de pruebas y repite
hasta que pasen todas las pruebas.

## ¿No sabes cómo seguir?

Tu primer objetivo es lograr que tu código compile, incluso con `Debug.todo` dentro.
Si sientes que no sabes cómo hacer algo,
a menudo es útil extraer esa parte a su propia función sin implementar.

```elm
complexOperationOnMultipleStrings : List String -> List String
complexOperationOnMultipleStrings allStrings =
    List.map complexOperation allStrings


complexOperation : String -> String
complexOperation input =
    Debug.todo "Extracted operation into its own function"
```

Agregar una anotación de tipo a esta función extraída
te ayudará a pensar y también ayudará al compilador a darte mejores mensajes de error.

## Limpia tu código

Considera ejecutar [`elm-format`](https://github.com/avh4/elm-format) en tu código antes de enviarlo
e incluso configurarlo en tu editor de texto para que formatee automáticamente al guardar.
