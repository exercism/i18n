# Introducción

Un *señalizador* a bordo de una embarcación de patrulla costera mantiene el registro de mensajes. Las señales sin procesar llegan enmarcadas con caracteres marcadores; las lecturas hay que prepararlas para la transmisión; los pares y tríos de observaciones se resumen sobre la marcha. Un puñado de modismos de la biblioteca estándar de Factor hacen la mayor parte del trabajo.

## `unparse`: de valor a código fuente

[`unparse`][unparse] (en `prettyprint`) devuelve el texto en forma de código fuente de cualquier valor:

```factor
123 unparse .        ! => "123"
"hi" unparse .       ! => "\"hi\""
{ 1 2 3 } unparse .  ! => "{ 1 2 3 }"
f unparse .          ! => "f"
```

`unparse` es la inversa del analizador: el viaje de ida y vuelta `dup unparse parse` reconstruye el valor. Es la herramienta correcta para serializar a un formato de transmisión que el receptor volverá a analizar, y la herramienta incorrecta para la salida legible por humanos (los strings conservan sus comillas, los vectores conservan su `V{ ... }`, etc.).

## Variantes de slice: vistas, no copias

`head` y `tail` de `sequences` *copian* la parte que conservas en una secuencia nueva. Sus equivalentes con `-slice` devuelven un objeto `slice` (una tupla que contiene el índice inicial, el índice final y la secuencia subyacente) que implementa el [protocolo de secuencia][sequence-protocol] sin copiar:

| palabra       | efecto                                           |
|---------------|--------------------------------------------------|
| `head`        | `( seq n -- newseq )`: copia los primeros n       |
| `head-slice`  | `( seq n -- slice )`: vista de los primeros n     |
| `tail`        | `( seq n -- newseq )`: copia desde el índice n    |
| `tail-slice`  | `( seq n -- slice )`: vista desde el índice n     |
| `head*`       | `( seq n -- newseq )`: copia todo menos los últimos n |
| `head-slice*` | `( seq n -- slice )`: vista de todo menos los últimos n |
| `tail*`       | `( seq n -- newseq )`: copia los últimos n        |
| `tail-slice*` | `( seq n -- slice )`: vista de los últimos n      |

```factor
USING: kernel sequences strings ;

"NS-1024" 2 head-slice  >string .  ! => "NS"
"NS-1024" 2 tail-slice  >string .  ! => "-1024"
"NS-1024" 1 head-slice* >string .  ! => "NS-102"
```

Un `slice` *es* una secuencia, así que cualquier cosa que acepte una secuencia acepta un slice: `length`, `first`, `each` y demás funcionan sin copiar. Las pruebas que necesitan comparar contra un string literal pueden convertir con `>string`.

## `?head` y `?tail`: quitar un marcador si está presente

Las lecturas enmarcadas llevan texto marcador que puede estar o no. `?head` y `?tail` (en `splitting`) intentan quitar un prefijo o un sufijo, y devuelven la secuencia (posiblemente acortada) *y* un valor Boolean que indica si se encontró el marcador:

```
?head ( seq begin -- newseq ? )   ! strip prefix begin if present
?tail ( seq end   -- newseq ? )   ! strip suffix end if present
```

```factor
"NS-1024" "NS-" ?head   ! ( -- "1024" t )      matched, prefix removed
"NS-1024" "XX-" ?head   ! ( -- "NS-1024" f )   no match, sequence unchanged
```

El valor Boolean final los hace ideales para usarlos como guarda: combina `?head` con `if` para ramificar según si el marco estaba presente, o con `unless` para rechazar los datos a los que les falta el marcador esperado.

## `<repetition>`: N copias, de forma virtual

[`<repetition>`][repetition] (en `sequences`) es otra secuencia virtual que no copia: `( len elt -- repetition )` construye una secuencia de `len` elementos que son todos `elt`, sin reservar esa cantidad de ranuras:

```factor
USING: sequences strings ;

5 CHAR: - <repetition> >string . ! => "-----"
3 0 <repetition> >array .        ! => { 0 0 0 }
```

El propio `elt` puede ser una secuencia: cada copia es esa misma secuencia. Después `concat` une las copias una tras otra:

```factor
USING: sequences ;

2 { 1 2 } <repetition> >array . ! => { { 1 2 } { 1 2 } }
3 "ab" <repetition> concat .    ! => "ababab"
4 { "on" "off" } <repetition> concat .
! => { "on" "off" "on" "off" "on" "off" "on" "off" }
```

Al igual que un `slice`, el resultado *es* una secuencia: `length`, `each` y compañía funcionan directamente sobre él. Úsala para rellenar un código de señal hasta un ancho fijo o para colocar una serie de marcadores repetidos; convierte con `>string` (o `>array`) solo cuando de verdad necesites una secuencia concreta.

## `<clumps>`: ventanas superpuestas, de forma virtual

[`<clumps>`][clumps] (en `grouping`) es una tercera secuencia virtual que no copia: `( seq n -- clumps )` ve `seq` como la serie de ventanas *superpuestas* de longitud `n`, cada una un slice:

```factor
USING: grouping math sequences ;

! each window is a slice; map >array to view them concretely
{ 1 2 3 4 } 2 <clumps> [ >array ] map .
! => { { 1 2 } { 2 3 } { 3 4 } }

! the usual move is to project straight from each window
{ 1 2 3 4 } 2 <clumps> [ first2 + ] map .
! => { 3 5 7 }
```

Una secuencia de `length` n produce `length - n + 1` ventanas. Como cada ventana es un slice, emparejar lecturas sucesivas no cuesta ninguna copia: `[ first2 ]` sobre cada clump de `2` te da todos los pares consecutivos a partir de los cuales proyectar. (Su primo sin superposición, `<groups>`, corta la secuencia en bloques disjuntos en su lugar).

## Cleave con varias entradas: `2bi`, `3bi`, `2tri`, `3tri`

Las palabras cleave simples `bi` y `tri` aplican dos o tres quotations a *una* entrada. Las variantes con prefijo `2` y prefijo `3` aplican cada quotation a *dos* o *tres* entradas:

```
bi   ( x       p q   -- )   ! 2 quotations of 1 input
2bi  ( x y     p q   -- )   ! 2 quotations of 2 inputs each
3bi  ( x y z   p q   -- )   ! 2 quotations of 3 inputs each

tri  ( x       p q r -- )   ! 3 quotations of 1 input
2tri ( x y     p q r -- )   ! 3 quotations of 2 inputs each
3tri ( x y z   p q r -- )   ! 3 quotations of 3 inputs each
```

Cada quotation recibe *todas* las entradas. Úsalas cuando más de una proyección dependa del mismo par (o trío) de valores, no cuando quieras aplicar la *misma* operación a cada entrada por separado (eso es `bi@` o `tri@`).

```factor
USING: combinators math ;

3 4 [ + ] [ * ] 2bi . .
! => 12
! => 7

1 2 3 [ + + ] [ * * ] 3bi . .
! => 6
! => 6
```
