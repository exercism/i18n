# Introducción

El lenguaje de programación Java usa _excepciones_ para manejar errores y otros eventos excepcionales.

## ¿Qué es una excepción?

Una excepción es un evento que ocurre durante la ejecución de un programa y que interrumpe el flujo normal de las instrucciones.
En Java, las excepciones se generan de forma explícita, y al acto de generar una excepción se le llama _lanzar una excepción_.
Al acto de manejar una excepción se le llama _capturar una excepción_.

En Java, todas las excepciones son subclases de la clase `Exception`, que a su vez es una subclase de `Throwable`.

Java distingue dos tipos de excepciones:

1. Excepciones comprobadas
2. Excepciones no comprobadas

### Excepciones comprobadas

Las _excepciones comprobadas_ son condiciones excepcionales que una aplicación debería anticipar y de las que debería recuperarse.
Un ejemplo de excepción comprobada es `FileNotFoundException`, que ocurre cuando un método intenta leer un archivo que no existe.

Este tipo de excepción se comprueba en tiempo de compilación: los métodos que lanzan excepciones comprobadas deben indicarlo en su firma, y el código que llama a un método que podría lanzar una excepción comprobada está obligado a manejarla, o el código no compilará.

Todas las excepciones comprobadas son subclases de `Exception` que no extienden `RuntimeException`.

### Excepciones no comprobadas

Las _excepciones no comprobadas_ son condiciones excepcionales que una aplicación por lo general no puede anticipar ni de las que puede recuperarse.
Un ejemplo de excepción no comprobada es `NullPointerException`, que ocurre cuando un método espera un valor distinto de `null` pero recibe `null`.

Este tipo de excepción no se comprueba en tiempo de compilación: los métodos que lanzan excepciones no comprobadas no están obligados a indicarlo en su firma, y el código que llama a un método que podría lanzar una excepción no comprobada no está obligado a manejarla.

Todas las excepciones no comprobadas heredan de `RuntimeException`, que a su vez es una extensión de `Exception`.

## Lanzar excepciones

Un método en Java puede lanzar una excepción usando la sentencia `throw`.

### Lanzar una excepción comprobada

Cuando se lanza una excepción comprobada desde un método, es obligatorio indicarlo en la firma del método usando la palabra clave `throws`, como se muestra en el ejemplo de abajo.
Esto obliga al código que llama a anticipar que se podría lanzar una excepción y a manejarla en consecuencia.

```java
public class InsufficientBalanceException extends Exception {

}

public class BankAccount {
  public void withdraw(double amount) throws InsufficientBalanceException {
    if (balance < amount) {
      throw new InsufficientBalanceException();
    }

    // rest of the method implementation
  }
}
```

### Lanzar una excepción no comprobada

Cuando se lanza una excepción no comprobada desde un método, no es obligatorio indicarlo en la firma del método, aunque es posible hacerlo.

```java
public class BankAccount {
  public void withdraw(double amount) {
    if (amount < 0) {
      throw new IllegalArgumentException("Cannot withdraw a negative amount");
    }

    // rest of the method implementation
  }
}
```

## Manejar excepciones

En Java, el manejo de excepciones se hace con las palabras clave `try`, `catch` y `finally`.

- Las sentencias de código que podrían lanzar una excepción deberían ir dentro de un bloque `try`.
- Al bloque `try` le siguen uno o más bloques `catch` que capturan las excepciones lanzadas en el bloque `try`.
- Después de los bloques `catch` puede venir, de forma opcional, un bloque `finally` que siempre se ejecuta tras el bloque `try`, sin importar si se lanzó una excepción o no.

El siguiente ejemplo muestra cómo funcionan estas palabras clave:

```java
public class ATM {
  public void withdraw(BankAccount bankAccount, double amount) {
    try {
      System.out.println("Withdrawing " + amount);
      bankAccount.withdraw(amount);
      System.out.println("Withdrawal succeeded");
    } catch (InsufficientBalanceException) {
      System.out.println("Withdrawal failed: insufficient balance");
    } catch (RuntimeException e) {
      System.out.println("Withdrawal failed: " + e.getMessage());
    } finally {
      System.out.println("Current balance: " + bankAccount.getBalance());
    }
  }
}
```

En este ejemplo, cuando no se lanza ninguna excepción, se imprime lo siguiente:

```text
Withdrawing 10.0
Withdrawal succeeded
Current balance: 5.0
```

Sin embargo, si la sentencia `bankAccount.withdraw(amount)` lanza una `InsufficientBalanceException`, se imprime lo siguiente:

```text
Withdrawing 10.0
Withdrawal failed: insufficient balance
Current balance: 5.0
```

O bien, si `bankAccount.withdraw(amount)` lanza una excepción no comprobada, se imprime lo siguiente:

```text
Withdrawing -10.0
Withdrawal failed: Cannot withdraw a negative amount
Current balance: 5.0
```

## Errores

Java también tiene una categoría aparte llamada _errores_, que son problemas graves y externos a la aplicación.
Un ejemplo de error es `OutOfMemoryError`, que ocurre cuando una aplicación intenta usar más memoria de la que hay disponible en el sistema.

Al igual que las excepciones no comprobadas, los errores no se comprueban en tiempo de compilación.
La diferencia es que representan problemas a nivel del sistema y, por lo general, los lanza la máquina virtual de Java o el entorno, no la aplicación.
Por lo general, las aplicaciones no deberían intentar capturarlos ni manejarlos.

Todos los errores en Java heredan de la clase `Error`.
