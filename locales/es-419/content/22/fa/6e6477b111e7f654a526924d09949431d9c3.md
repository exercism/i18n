# Acerca de

Un archivo es un flujo con un nombre en disco. El vocabulario [`io.files`][io.files]
ofrece dos formas de trabajar con uno: palabras de conveniencia para archivos completos
que leen o escriben todo en una sola llamada, y abridores de flujos (los combinadores
`with-…`) para leer o escribir de forma incremental. Ambos se apoyan en el mismo
[protocolo de flujos][stream-protocol] que los flujos en memoria del concepto
`io-streams`: un `<file-reader>` y un `<string-reader>` responden a las mismas
palabras.

Cada palabra de archivo recibe una **codificación**, el esquema que asigna bytes a
caracteres y viceversa. Para texto, casi siempre es [`utf8`][utf8] de
`io.encodings.utf8`; el trabajo binario usa `latin1` o una codificación
`<byte-array>`.

## Lectura de archivos completos

```
file-contents   ( path encoding -- str )
file-lines      ( path encoding -- seq )
```

`file-contents` devuelve el archivo completo como un solo string. `file-lines`
devuelve sus líneas como un array, sin los terminadores de línea; es útil cuando
cada línea es un registro.

```factor
USING: io.encodings.utf8 io.files ;

"forecast.txt" utf8 file-contents   ! => "sunny\ncloudy\n"
"forecast.txt" utf8 file-lines      ! => { "sunny" "cloudy" }
```

## Escritura de archivos completos

```
set-file-contents   ( str path encoding -- )
set-file-lines      ( seq path encoding -- )
```

Ambas **reemplazan** el archivo y lo crean si no existe.
`set-file-contents` escribe un string tal cual; `set-file-lines` escribe cada
elemento de una secuencia en su propia línea y agrega los saltos de línea.

```factor
{ "sunny" "cloudy" } "forecast.txt" utf8 set-file-lines
! forecast.txt now holds "sunny\ncloudy\n"
```

## Flujos con ámbito

Cuando quieras agregar contenido a un archivo, o leer y escribir poco a poco,
ábrelo con un combinador `with-…` y usa las palabras de flujo ambientales dentro
de la quotation:

```
with-file-reader     ( path encoding quot -- )
with-file-writer     ( path encoding quot -- )
with-file-appender   ( path encoding quot -- )
```

```factor
USING: io io.encodings.utf8 io.files ;

"log.txt" utf8 [ "another line" print ] with-file-appender
```

`with-file-writer` trunca el archivo primero; `with-file-appender` conserva el
contenido existente y escribe después de él. Cada uno es un ámbito destructor:
el manejador de archivo se cierra cuando termina la quotation, incluso si lanza
una excepción; la misma garantía que ofrecen los combinadores
`boatswains-bilge`, aquí especializada para archivos.

## ¿Archivos completos o con ámbito?

Recurre a `file-contents` / `file-lines` / `set-file-contents` /
`set-file-lines` cuando el archivo sea lo bastante pequeño para mantenerlo en
memoria y quieras todo de una vez. Recurre a los abridores `with-…` cuando
necesites agregar contenido, leer un archivo grande línea por línea con
`readln`, o intercalar lecturas y escrituras; en cualquier caso, mantener el
archivo completo en memoria sería un desperdicio o un error.
