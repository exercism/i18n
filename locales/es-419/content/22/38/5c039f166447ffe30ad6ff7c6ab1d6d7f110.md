# Introducción

[La coincidencia de patrones][pattern-matching] permite escribir código con ramificaciones expresivas y la [desestructuración][destructuring] aporta una forma elegante de vincular valores a variables.
Ambas son sumamente útiles de dominar para quien programa en Elm y, cuando se usan juntas, mejoran muchísimo la legibilidad del código.

## Coincidencia de patrones simple

La coincidencia de patrones designa el código que se ramifica según la forma de los datos que se manipulan.
Por eso encaja de manera natural con el concepto de tipos personalizados, que expresan las múltiples formas que pueden tomar ciertos datos.
Por ejemplo, dado un tipo personalizado `Color` definido como `Blue` o `Red`, podemos escribir una función `toString` que haga coincidencia de patrones sobre el color para devolver el string correcto.

```elm
type Color = Blue | Red

toString : Color -> String
toString color =
    case color of
        Blue -> "blue"
        Red -> "red"
```

La coincidencia de patrones también funciona con tipos personalizados que no son una simple enumeración.
Consideremos una función `hello` que recibe como parámetro un `Maybe String`, el cual contiene el nombre de una persona o nada en absoluto.
Al hacer coincidencia de patrones, podemos dar nombres en minúscula a los datos para vincularlos a esa variable y así poder usarla en el lado derecho de la coincidencia.

```elm
hello : Maybe String -> String
hello maybeName =
    case maybeName of
        Nothing -> "Hello stranger!"
        -- here we bind 'name' to the data inside the 'Just'
        Just name -> "Hello " ++ name ++ "!"
```

La coincidencia de patrones debe ser exhaustiva, de lo contrario el compilador se negará a compilar.
Pero a veces no nos importan ciertos datos ni algunas ramas de una expresión case.
En esos casos, en lugar de tener que buscar un nombre de variable al que vincular y de escribir una rama para cada caso, podemos usar el comodín de guion bajo `_`.

```elm
type Entity = Friend { name: String } | Stranger | Alien

hello : Entity -> String
hello entity =
    case entity of
        -- here we don't care about the data held by 'Friend'
        Friend _ -> "Hi!"
        -- mandatory because pattern matching must be exhaustive,
        -- but for all other cases, we answer the same thing
        _ -> "Hello stranger!"
```

## Coincidencia de patrones avanzada

Además de los tipos personalizados, también podemos hacer coincidencia de patrones sobre tipos que tienen literales, como `Char`, `String`, `Int` y `Floats`.

```elm
howMany : Int -> String
howMany count =
    case count of
        0 -> "none!"
        1 -> "there is one!"
        2 -> "a couple!"
        _ -> "too many to count!"

greekLetter : String -> String
greekLetter letter =
    case letter of
        "a" -> "alpha"
        "b" -> "beta"
        _ -> "I don't remember"
```

Para hacer coincidir más de un valor sin anidar, un truco común en Elm es combinar los valores que quieres comparar en [tuplas _ad hoc_][ad-hoc-tuples], así:

```elm
howManyGreekLetters : Int -> String -> String
howManyGreekLetters count letter =
    case ( count, letter ) of
        ( 0, _ ) -> "none!"
        ( 1, "a" ) -> "there is an alpha!"
        ( 1, "b" ) -> "there is a beta!"
        _ -> "at least two!"
```

Y como los programadores funcionales les tienen mucho cariño a las listas, [también se puede hacer coincidencia de patrones sobre ellas][pattern-match-lists] con la misma sintaxis que se usa para construirlas, mediante el operador `::`.

```elm
head : List a -> Maybe a
head list =
    case list of
        [] -> Nothing
        x :: _ -> Just x
```

Por último, la coincidencia de patrones incluso funciona de forma recursiva, lo que permite adentrarse en tipos complejos y recursivos.

```elm
type Activity = Work | Play Game
type Game = Boardgame String | VideoGame String

pickActivity : Activity -> Bool
pickActivity activity =
    case activity of
        -- The only thing we want is playing Catan
        Play (Boardgame "Catan") -> True
        _ -> False
```

## Desestructuración

La desestructuración se parece mucho a la coincidencia de patrones, en el sentido de que permite vincular variables a los datos que están dentro de los tipos.
La diferencia principal es que llamamos «desestructuración» a ese mecanismo cuando solo hay una forma posible, y coincidencia de patrones cuando hay varias formas.
La desestructuración aparece a menudo en las vinculaciones `let`, en los argumentos de las funciones y, por supuesto, en las expresiones case, mezclada con la coincidencia de patrones.

```elm
pairSum : ( Int, Int ) -> Int
pairSum pair =
    -- Destructuring of a pair in a 'let' binding
    let ( x, y ) = pair
    in x + y

-- Custom type containing a single variant
type Container = Box String

-- Destructuring of the container as function argument
-- to bind its content directly without the need of 'let' or 'case'.
unbox : Container -> String
unbox (Box str) =
    str

-- Destructuring combined with pattern matching
unboxMaybe : Maybe Container -> Maybe String
unboxMaybe maybeContainer =
    case maybeContainer of
        Nothing -> Nothing
        Just (Box "42") -> Just "The answer to the universe!"
        Just (Box str) -> Just str
```

La desestructuración se puede usar con tipos personalizados de una sola variante, con tuplas y también con registros, donde resulta muy cómoda.
Para [desestructurar un registro][records-pattern-matching] se puede usar cualquier cantidad de sus campos: uno, dos, ..., o todos los campos.

```elm
type alias Circle =
    { radius : Float
    , center : ( Float, Float )
    }

perimeter : Circle -> Float
perimeter { radius } =
    2 * pi * radius
```

Lamentablemente, la sintaxis de Elm no permite desestructurar registros de forma recursiva.
En el ejemplo anterior de `Circle`, no hay forma de acceder a las posiciones `x`` and `y del centro del círculo de una sola vez.
Primero debemos acceder al `center` y luego desestructurarlo para obtener sus posiciones `x` e `y`.

```elm
left : Circle -> Float
left { radius, center } =
    let ( x, _ ) = center
    in x - radius
```

¡Y tenemos un último consejo!
A veces queremos acceder fácilmente tanto a algo en su conjunto como a una parte de ello.
Aquí es donde la [palabra clave `as`][as-keyword] puede resultar útil.
Permite dar un nombre de alias a algo en su conjunto y, aun así, poder desestructurar su contenido.

```elm
-- Make the circle smaller if the radius is sufficiently big.
-- Otherwise, return the circle unchanged.
smaller : Float -> Circle -> Circle
smaller reduction ({ radius, center } as circle) =
    if reduction < radius then
        { radius = radius - reduction
        , center = center
        }
    else
        circle
```
