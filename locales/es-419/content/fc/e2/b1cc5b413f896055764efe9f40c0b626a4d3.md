# Mapas y conjuntos

| Tipo | Contiene | Se busca por |
| --- | --- | --- |
| `ARRAY{T}` | valores en orden | posición |
| `FMAP{K,T}` | pares clave-destino | clave |
| `FSET{T}` | valores, sin repeticiones | pertenencia |

## FMAP

```sather
   m ::= #FMAP{STR,INT};
   m := m.insert("emu", 2);
   m.get("emu")          -- 2
   m.has_ind("emu")      -- true
   m.size                -- 1
   m := m.delete("emu");
```

`m["emu"]` **no** es la forma de leer un mapa: `FMAP` no tiene esa rutina y esa línea no compila. Se usa `get`.

### Claves ausentes

`get` sobre una clave que no está devuelve el valor vacío del tipo en lugar de quejarse: `0`, `false` o void. Un `STR` void no falla donde se produce; falla más tarde, donde se termine usando. Usar `has_ind` primero es el hábito que vale la pena formar.

## FSET

```sather
   s ::= #FSET{STR};
   s := s.insert("emu");
   s.has("emu")          -- true
   s.size                -- 1
   s := s.delete("emu");
```

Los conjuntos se combinan:

```sather
   a.union(b)            -- in either
   a.intersect(b)        -- in both
   a.difference(b)       -- in a but not b
   a.is_subset(b)
```

## Asignar de vuelta y copiar

`insert` y `delete` devuelven el contenedor que se debe usar de ahora en adelante. Normalmente ese es el mismo objeto, modificado en el lugar; cuando tiene que crecer, es uno nuevo y más grande. Así:

```sather
   m := m.insert(k, v);     -- always
```

y el nombre de la izquierda es el único en el que se puede confiar después. Otro nombre para el mismo mapa, tomado antes del `insert`, puede quedar obsoleto.

Para conservar una copia independiente, saca una copia primero:

```sather
   n ::= m.copy.insert(k, v);      -- m is unchanged
```

con un detalle: un mapa al que nunca se le ha insertado nada es **void**, y `copy` en un mapa void falla. `insert`, `get`, `has_ind` y `size` funcionan con un mapa void: `#FMAP{K,T}` es void, e insertar en él es cómo un mapa empieza a existir, pero `copy` no.

`HMAP` y `HSET` son las versiones que solo cambian en el lugar. Son más rápidas para construir algo grande, y son la opción predeterminada incorrecta mientras aprendes.

## Recorrer un mapa o un conjunto

| Iterador | Da |
| --- | --- |
| `m.ind!` | cada clave |
| `m.target!` | cada destino |
| `m.pair!` | cada clave y destino juntos |
| `s.elt!` | cada valor de un conjunto |

Ni un mapa ni un conjunto tienen orden. Dos ejecuciones pueden recorrerlos de manera diferente, así que nunca escribas algo que dependa de cuál viene primero.

```sather
   loop
      #OUT + guide.ind! + "\n";
   end;
```
