Nuestro ejecutor de pruebas en línea usa actualmente `pytest 8.4.0` y `pytest-subtests 0.14.2`.
Nuestro analizador en línea usa `pylint 4.0.4`.

## <a name="virtual-environments"></a>Entornos virtuales

Los entornos virtuales de Python ofrecen un aislamiento ligero del entorno de ejecución y de los paquetes.
 Pueden ayudarte a organizar tus proyectos al mantener juntos los paquetes de Python que instalas dentro de un directorio de entorno específico.
Distintos entornos pueden contener diferentes versiones del entorno de ejecución de Python junto con las dependencias de un proyecto o de una biblioteca.
Esto ayuda a evitar bugs e incompatibilidades causados por actualizar una biblioteca para un proyecto que «rompe» una dependencia de otro.

Hoy en día existen muchas herramientas de *entorno virtual* y *similares a entornos virtuales*, y un movimiento creciente que prefiere usar [metadatos de scripts en línea][PEP723], [contenedores de desarrollo][dev containers] o [docker][docker] en lugar de entornos virtuales.
Es importante probar distintas estrategias y encontrar la que se adapte a tu estilo de desarrollo y a las necesidades de tu proyecto.
No asumas que las estrategias de aquí sirven para todos los casos ni que son tus únicas opciones.
Para un repaso más general de herramientas que no se cubren aquí, echa un vistazo a [esta publicación de blog de Bas Nijholt][bas nihholt] y mantén la curiosidad.


Aquí cubriremos tres herramientas principales de *entorno virtual*: la biblioteca estándar de Python [`venv`][venv], el de terceros [`conda env`][condaenv], que usa el gestor de paquetes [`conda`][conda] y (_por lo general_) la distribución Anaconda de Python, y el reemplazo de `pip` + `venv` de terceros, [`uv`][uv].
Las tres son bastante sencillas de usar o de instalar.

Además, [`PyEnv`][pyenv], [`Poetry`][poetry] y [virtualenvwrapper][virtualenvwrapper] son herramientas que pueden ayudarte a gestionar varias versiones de Python y varios entornos de Python en la misma máquina.

### <a name="creating-a-virtual-environment-with-venv"></a>Crear un entorno virtual con `venv`

Para crear un entorno virtual con `venv`, entra con `cd` al directorio donde quieres guardar tus entornos.
Este debe ser un directorio **separado del** código de tu proyecto y que **no** vayas a poner bajo control de versiones.
Luego, ejecuta el comando `venv` con el nombre de una carpeta donde quieras guardar este **entorno** en particular.
Por convención, se suele llamar a esa carpeta `<project-name-here>_venv`:

**Windows**

```powershell
PS C:\Users\foobar> py -m venv {name_of_virtualenv}
```
Para activar el entorno virtual, ejecuta el siguiente comando:

```powershell
PS> .\{name_of_virtual_env}\Scripts\activate.bat
(venv) PS> _
```

<br>

**Linux/MacOS**

```bash
$ python3 -m venv {name_of_virtualenv}
created virtual environment ... in 8568ms
```

Para activar el entorno virtual, ejecuta el siguiente comando:

```bash
$ source {name_of_virtual_env}/bin/activate
(venv) $ _
```

Una vez que un `venv` está activado, puedes ejecutar comandos de `pip` para instalar paquetes «dentro» del entorno.
Los paquetes instalados se asociarán con la versión de Python del `venv` y se ubicarán dentro de `{name_of_virtual_env}/Lib`.

Para _desactivar_ un entorno virtual, puedes llamar al script `deactivate`, que se encuentra en el mismo directorio que `activate`.

### <a name="creating-a-virtual-environment-using-conda"></a>Crear un entorno virtual con `conda`

*La versión más reciente de `conda` se puede instalar a través de [miniconda][miniconda].*
Esta [guía rápida de `conda`][conda-cheatsheet] es muy útil, al igual que la [documentación de `conda`][conda-docs].

Creado originalmente como gestor de paquetes de Python para la popular [`Anaconda distribution`][anaconda] de «Python científico», `conda` se generalizó y amplió más tarde.
Los entornos de conda son similares a los `venv`, con la diferencia clave de que conda puede crear entornos virtuales e instalar paquetes para muchos otros lenguajes de programación además de Python.

Entre los lenguajes que conda admite están `R`, `JavaScript`, `Ruby`, `Fortran`, `C/C++`, `Scala`, `Java` y más.
Para comparar los comandos de conda vs venv, consulta la [referencia de comandos][conda command ref] de conda.

### <a name="uv">UV

Trabajar en proyectos con uv: [uv][uv-docs]

`uv` es una herramienta de gestión de paquetes y proyectos de Python de [Astral][astral], escrita en [Rust][rust programming language].
Fue diseñada para reemplazar a `pip`, `venv`, `poetry` y otras herramientas de gestión de paquetes y dependencias de Python.
A diferencia de `Conda` o `Mamba`, uv está especializada y pensada solo para Python.
 Sin embargo, uv sí admite compilar módulos de extensión de Python escritos en otros lenguajes, como Fortran.
Astral también es el desarrollador del popular linter [Ruff][ruff] y de [TY][ty], un verificador de tipos estático para las anotaciones de tipo de Python, ambos escritos en Rust.


En lugar de entrar en detalles aquí, la [documentación de UV][uv documentation] es tu mejor fuente para la instalación y la configuración.

### <a name="virtual-environment-wrapper">Contenedor de entornos virtuales

Documentación y contexto: [virtualenvwrapper][virtualenvwrapper].

El paquete `virtualenvwrapper` funciona sobre `venv` para gestionar todos tus entornos virtuales en un solo lugar.
 Puedes crear, copiar, eliminar y cambiar entre entornos con comandos similares a los de Linux, como `lsvirtualenv` (_para listar entornos_) y `mkvirtualenv` (_para crear un entorno_).
  También te permite agregar herramientas de gestión adicionales mediante extensiones.
  Incluso puedes crear tus propias extensiones para la herramienta con [este tutorial][venv wrapper tutorial].

<br>

### <a name="pyenv"></a>PyEnv

`pyenv` es la bifurcación para Python de las populares herramientas `rbenv`/`ruby-build`, modificada para Python.
Es esencialmente un conjunto de scripts y shims que permiten establecer versiones de Python tanto de forma global como específica por usuario.
Intenta seguir la tradición de Unix de una herramienta discreta, de propósito único, que hace bien una sola cosa.

`pyenv` y su documentación se pueden encontrar en [GitHub][pyenv on github].

### <a name="visual-studio-code"></a>Visual Studio Code

[Visual Studio Code (VS Code)][vscode] es un editor de código gratuito creado por Microsoft.
Incluye un gran soporte tanto para [entornos virtuales y de conda][virtual environments in vscode] como para [`docker`][docker in vscode] (_mediante el [complemento de docker][vs code docker plugin]_), y se puede ampliar con muchos complementos distintos para [pruebas][python testing in vscode], [linting][linting python in vscode], [formato][formatting python in vscode] y [desarrollo web][python web dev in vscode].

#### <a name="python-for-vs-code"></a>Python para VS Code

_Id de la extensión: ms-python.python_

![Encabezado de la extensión de Python en VS Code](https://raw.githubusercontent.com/exercism/python/main/docs/img/VSCode-EXT-Python-Header.png)

La [extensión de Python de Microsoft][MS Python extension] es la extensión oficial de Python de Microsoft para VS Code, y una instalación muy recomendada.
Tiene una amplia variedad de funcionalidades, como gestión de entornos, gestión de pruebas, linting y depuración.
A partir de la [última versión][vs code python latest release], instalar la extensión de Python de MS también descargará [pylance][vs code pylance] (_un paquete popular para hacer linting y validar código de Python_) y [jupyter][vs code jupyter] (_para trabajar con Jupyter Notebooks_).

- Hay un tutorial de configuración disponible [aquí][python extension setup tutorial] y la [referencia de configuración][vs code python settings reference] es muy útil.
- Puedes encontrar información sobre cómo configurar versiones de Python y trabajar con entornos virtuales [aquí][virtual environments in vscode].
- Puedes encontrar información sobre cómo configurar y trabajar con unittest y pytest en VS Code [aquí][python testing in vscode].

### <a name="spyder-ide">Spyder IDE

[Spyder][spyder-ide] es un IDE de Python gratuito, de código abierto y multiplataforma, pensado para la comunidad científica.
Por lo general, se incluye con la distribución Anaconda de Python, pero se puede [instalar por separado][spyder standalone installers] y usar con cualquier versión de Python.
Recomendamos una instalación independiente para asegurar la máxima flexibilidad y evitar conflictos de paquetes.

Spyder es totalmente compatible con entornos de `venv` y `conda`.
Incluye un terminal interactivo de [IPython][ipython] integrado, un depurador interactivo y un amplio soporte para generar gráficos y explorar datos dentro del editor.
El autocompletado de código y el linting adicionales se ofrecen a través de [kite][kite].
Las integraciones con [Jupyter Notebooks][spyder notebook plugin] y las [herramientas de prueba][spyder unittest plugin] se ofrecen mediante complementos desarrollados por la comunidad.
También puedes escribir [tus propios complementos][writing spyder plugins] usando la API de Spyder.

### <a name="vim"></a>Vim

[Vim][vimdotorg] es una versión gratuita y «mejorada» del editor de texto estándar `vi` de Unix.
Está disponible en una amplia variedad de sistemas operativos y distribuciones de Linux y Unix.
Hay una excelente [guía de instalación y configuración][vim setup at real python] en Real Python, y también hay útiles guías rápidas en [vimsheet][vim cheat sheet], [glump][glump vim cheatsheet] y [rtorr][rtorr vim cheat sheet].


Aunque decidas que editar código de Python en `vim` no es para ti, se recomienda que te familiarices con un conjunto básico de comandos.
`vim` o `vi` suele ser un editor de texto «base» o «predeterminado» en las distribuciones de Linux y Unix, y es el editor predeterminado para los mensajes de commit de `git` (_entre otras cosas_) en esos sistemas.
Es muy probable que termines en un sistema *nix teniendo que editar un archivo de configuración con solo `vi` disponible, así que saber cómo [salir de vim][how do I quit vim] es (_como mínimo_) una buena defensa personal.
