# Introducción

Vimos en Conceptos anteriores que los tipos en Julia forman una jerarquía, con `Any` en la parte superior.

Los tipos abstractos como `Number` tienen subtipos, pero no pueden instanciarse por sí mismos.
Asignarle a una variable un tipo abstracto _restringe_ sus valores a cualquier subtipo de ese tipo abstracto.
Por ejemplo:

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

Esto nos da un tipo de flexibilidad al restringir qué valores son válidos.

Sin embargo, ¿supongamos que queremos que una variable acepte tanto valores enteros como strings?
Estos tipos no están en la misma rama de la jerarquía.

Podríamos asignarle el tipo `Any`, o dejar que ese sea el valor predeterminado, pero entonces perdemos todo control sobre los tipos permitidos.

Para un mejor enfoque, tenemos la sintaxis `Union{ }`, con dos o más tipos listados dentro de las llaves.

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

Otro ejemplo usa la misma unión de tipos en la firma de una función:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

Aquí le dimos un nombre al tipo, lo que puede ofrecer una abreviatura cómoda, pero no es estrictamente necesario.
La función `g(z::Union{Integer, String}) = z^3` se comporta de la misma manera.

Habrá mucho más que decir sobre las firmas de funciones en el Concepto de Despacho Múltiple.

## Uniones con nada

Varios otros lenguajes tienen tipos que pueden contener un valor o no, con nombres como `Option`, `Nullable` o `Maybe`.

Julia no tiene una sintaxis específica para esto, pero las uniones de tipos son una generalización de la misma idea.

Vimos en el Concepto `Nothingness` que Julia tiene varias formas de representar la ausencia de valor, incluyendo `nothing` y `missing`.
Cualquiera de estos puede incluirse en una unión de tipos.

Por ejemplo, al definir algún tipo de lista enlazada, necesitamos una forma de terminar la lista si no hay más nodos.
`Nothing` es el tipo con el valor único `nothing`, y esta definición de Node permite señalar el final de la cadena:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

De manera similar, `missing` puede usarse como marcador de posición para valores ausentes, sobre todo en colecciones como los vectores.
El siguiente ejemplo es muy artificial, pero los valores faltantes son comunes en conjuntos de datos del mundo real.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
