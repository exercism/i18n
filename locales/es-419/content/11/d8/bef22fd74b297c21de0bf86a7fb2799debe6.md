# Instrucciones

Eres el oficial de guardia a bordo de un cúter que cruza el estrecho
de Bering. Tres fuentes anuncian la posición de cada témpano de hielo
y cada promontorio a la vista:

- La **mesa de cartas** habla en direcciones cardinales:
  `north`, `east`, `south`, `west`. Solo una dirección, sin distancia.
- El **navegante** habla en coordenadas *polares* desde la última
  posición del cúter: una magnitud en millas náuticas y una
  demora en grados, en sentido horario desde el norte (así, `0` es el
  norte, `90` es el este, `180` es el sur, `270` es el oeste).
- El **vigía de la cofa** habla en coordenadas *relativas*: una
  distancia hacia adelante, y uno de `ahead`, `starboard`, `behind`,
  `port`. Las demoras relativas se miden con respecto al *rumbo
  actual del barco*: el capitán anuncia ese rumbo en el puente antes
  de cada guardia.

Tu tarea es convertir las tres a un mismo marco cartesiano `(x, y)`
para poder trazar la carta. Las demoras están en grados; `(0, 1)`
es una milla náutica hacia el norte, `(1, 0)` es una milla náutica
hacia el este.

## 1. El modelo de datos, y cartesianas para las cardinales

Primero, define las piezas que comparte todo el ejercicio:

- Define tres tuplas: `cardinal` (un campo, `direction`), `polar`
  (campos `magnitude` y `bearing`) y `relative` (campos
  `distance` y `bearing`).
- Declara los símbolos de dirección con `SYMBOLS:`: `north`, `east`,
  `south`, `west`, `ahead`, `starboard`, `behind`, `port`.
- Declara una variable dinámica `heading` con `SYMBOL:` (la tarea 3
  la usa).
- Declara dos palabras genéricas:
  `GENERIC: >cartesian ( direction -- x y )` y
  `GENERIC: flip ( direction -- direction' )`. Sus métodos los
  agregas en las siguientes tareas.

Luego agrega el método `M: cardinal` de `>cartesian`, que devuelve
el vector unitario de la dirección indicada.

```factor
T{ cardinal { direction north } } >cartesian . .
! => 1
! => 0
! (top of stack is `y`, just below it is `x`)
```

## 2. Cartesianas para las polares

Agrega un método `M: polar` a `>cartesian` que convierta la forma
polar a `(x, y)`:

```
x = magnitude * sin(bearing-in-radians)
y = magnitude * cos(bearing-in-radians)
```

```factor
T{ polar { magnitude 10 } { bearing 90 } } >cartesian . .
! => 0   (close to zero — the cosine of π/2 isn't exactly 0 in floats)
! => 10
```

## 3. Cartesianas para las relativas

Agrega un método `M: relative` a `>cartesian`. El detalle: una demora
relativa se mide con respecto al *rumbo actual* del barco, que no
forma parte de la tupla. Lee la variable `heading` (declarada en la
tarea 1) con `heading get`, suma el desplazamiento de la demora
(`ahead = 0`, `starboard = 90`, `behind = 180`, `port = 270`) y
produce el punto cartesiano. Quien llama establece `heading` dentro
de un bloque `with-variable`.

```factor
0 heading [
    T{ relative { distance 5 } { bearing starboard } } >cartesian
] with-variable . .
! => 0   (heading 0 is north; starboard is east; (5, 0))
! => 5
```

## 4. Flip

Agrega los métodos del genérico `flip` (declarado en la tarea 1)
para que devuelva la dirección opuesta.

- Para `cardinal`: north ↔ south, east ↔ west.
- Para `polar`: suma 180° a la demora (módulo 360).
- Para `relative`: ahead ↔ behind, starboard ↔ port.

```factor
T{ cardinal { direction north } } flip .
! => T{ cardinal { direction south } }

T{ polar { magnitude 10 } { bearing 90 } } flip .
! => T{ polar { magnitude 10 } { bearing 270 } }

T{ relative { distance 5 } { bearing ahead } } flip .
! => T{ relative { distance 5 } { bearing behind } }
```

## 5. Sumar demoras

Define `add-bearings ( a b -- x y )`, que convierte ambas
direcciones a coordenadas cartesianas y devuelve su suma. Funciona
con cualquier combinación de `cardinal`, `polar` y `relative`: esa
es la recompensa de usar un genérico para `>cartesian`.

```factor
T{ cardinal { direction north } } T{ cardinal { direction east } } add-bearings . .
! => 1
! => 1
```
