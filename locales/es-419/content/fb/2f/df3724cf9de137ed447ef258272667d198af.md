# Funciones auxiliares privadas

[comment]: # (requiere 2 parámetros:)
[comment]: # (- expected: la definición de función corregida)
[comment]: # (- actual: la definición de función incorrecta que usó el estudiante)

La interfaz pública de una base de código debe considerarse con cuidado, ya que cada función pública aumenta los costos de mantenimiento a largo plazo y dificulta la refactorización.

En todos los ejercicios de Exercism, la interfaz pública la define el conjunto de pruebas.
Si se está probando una función, esta debe ser pública.
Todas las demás funciones deben ser privadas, incluidas las que tienen el mismo nombre pero distinta aridad.

```elixir
# you defined the following public function

%{actual}

# make it private like this

%{expected}
```
Ten en cuenta que los argumentos por defecto modifican la aridad de una función.

Cuando escribes una biblioteca, a menudo es necesario hacer públicas algunas funciones para usarlas entre módulos.
Para ocultar esas funciones de la documentación, quienes escriben bibliotecas agregan `@doc false` antes de las definiciones de las funciones, o `@moduledoc false` para ocultar todo el módulo.
