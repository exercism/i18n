# Acerca de

Como muchos otros lenguajes, Go tiene punteros.
Si eres nuevo en el tema de los punteros, pueden parecer un poco misteriosos, pero una vez que te acostumbras a ellos son bastante sencillos.
Son una parte crucial de Go, así que tómate tu tiempo para entenderlos bien.

Antes de entrar en los detalles, vale la pena entender para qué sirven los punteros.
Los punteros son una forma de compartir memoria con otras partes de nuestro programa, lo cual es útil por dos razones principales:

1. Cuando tenemos grandes cantidades de datos, hacer copias para pasarlas entre funciones es muy ineficiente.
   Si en su lugar pasamos la ubicación de memoria donde se almacenan los datos, podemos reducir drásticamente la huella de recursos de nuestros programas.
2. Al pasar punteros entre funciones, podemos acceder y modificar directamente la única copia de los datos, lo que significa que cualquier cambio que haga una función es visible de inmediato para otras partes del programa cuando la función termina.

## Variables y memoria

Supongamos que tenemos una variable entera normal `a`:

```go
var a int
```

Cuando declaramos una variable, Go tiene que encontrar un lugar en la memoria para almacenar su valor.
En gran medida esto queda abstraído para nosotros: cuando necesitamos obtener el valor almacenado en esa porción de memoria, basta con referirnos a él por el nombre de la variable.

Por ejemplo, cuando escribimos `a + 2`, en realidad estamos obteniendo el valor almacenado en la memoria asociada a la variable `a` y sumándole 2.

De manera similar, cuando necesitamos cambiar el valor en la porción de memoria de `a`, podemos usar el nombre de la variable para hacer una asignación:

```go
a = 3
```

La porción de memoria asociada a `a` ahora almacenará el valor `3`.

## Punteros

Aunque las variables nos permiten referirnos a valores en la memoria, a veces es útil conocer la **dirección de memoria** a la que apunta la variable.
Los **punteros** contienen las direcciones de memoria de esos valores.
Declaras una variable con un tipo de puntero anteponiendo un asterisco al tipo subyacente:

```go
var p *int // 'p' contains the memory address of an integer
```

Aquí declaramos una variable `p` de tipo «puntero a int» (`*int`).
Esto significa que `p` contendrá la dirección de memoria de un entero.
El valor cero de los punteros es `nil`, porque un puntero `nil` no contiene ninguna dirección de memoria.

### Obtener un puntero a una variable

Para encontrar la dirección de memoria del valor de una variable, podemos usar el operador `&`.
Por ejemplo, si queremos encontrar y almacenar la dirección de memoria de la variable `a` en el puntero `p`, podemos hacer lo siguiente:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'
```

### Acceder al valor mediante un puntero (desreferencia)

Cuando tenemos un puntero, puede que queramos conocer el valor almacenado en la dirección de memoria que representa el puntero.
Podemos hacerlo usando el operador `*`:

```go
var a int
a = 2

var p *int
p = &a // the variable 'p' contains the memory address of 'a'

var b int
b = *p // b == 2
```

La operación `*p` obtiene el valor almacenado en la dirección de memoria que guarda `p`.
A esta operación se la suele llamar «desreferenciar».

También podemos usar el operador de desreferencia para asignar un valor nuevo a la dirección de memoria referenciada por el puntero:

```go
var a int        // declare int variable 'a'
a = 2            // assign 'a' the value of 2

var pa *int
pa = &a          // 'pa' now contains to the memory address of 'a'
*pa = *pa + 2    // increment by 2 the value at memory address 'pa'

fmt.Println(a)   // Output: 4
                 // 'a' will have the new value that was changed via the pointer!
```

Asignar a `*pa` cambiará el valor almacenado en la dirección de memoria que contiene `pa`.
Como `pa` contiene la dirección de memoria de `a`, al asignar a `*pa` en realidad estamos cambiando el valor de `a`.

Sin embargo, una advertencia: verifica siempre que un puntero no sea `nil` antes de desreferenciarlo.
Desreferenciar un puntero `nil` hará que el programa falle en tiempo de ejecución.

```go
var p *int // p is nil initially
fmt.Println(*p)
// panic: runtime error: invalid memory address or nil pointer dereference
```

### Punteros a structs

Hasta ahora solo hemos visto punteros a valores primitivos.
También podemos crear punteros a structs:

```go
type Person struct {
    Name string
    Age  int
}

var peter Person
peter = Person{Name: "Peter", Age: 22}

var p *Person
p = &peter
```

También podríamos haber creado un nuevo `Person` y almacenado de inmediato un puntero a él:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}
```

Cuando tenemos un puntero a un struct, no necesitamos desreferenciar el puntero antes de acceder a uno de los campos:

```go
var p *Person
p = &Person{Name: "Peter", Age: 22}

fmt.Println(p.Name) // Output: "Peter"
                    // Go automatically dereferences 'p' to allow
                    // access to the 'Name' field
```

## Los slices y los maps ya son punteros

Los slices y los maps son tipos especiales porque ya incorporan punteros en su implementación.
Esto significa que, la mayoría de las veces, no necesitamos crear punteros para estos tipos con el fin de compartir la dirección de memoria de sus valores.
Imagina que tenemos una función que incrementa el valor de una clave en un map:

```go
func incrementPeterAge(m map[string]int) {
	m["Peter"] += 1
}
```

Si creamos un map y llamamos a esta función, los cambios que la función hizo al map permanecen después de que la función termina.
Este es un comportamiento similar al que obtenemos si usáramos un puntero, pero fíjate que en este ejemplo no estamos usando ninguna referencia ni desreferencia, ni nada de la sintaxis de punteros:

```go
ages := map[string]int{
  "Peter": 21
}
incrementPeterAge(ages)
fmt.Println(ages)
// Output: map[Peter:22]
// The changes the function 'incrementPeterAge' made to the map are visible after the function ends!
```

Lo mismo ocurre cuando cambiamos un elemento existente en un slice.

Sin embargo, las acciones que devuelven un nuevo slice, como `append`, son un caso especial y **puede que no** modifiquen el slice fuera de la función.
Esto se debe a cómo funcionan los slices internamente, pero no lo cubriremos en detalle, ya que es un tema más avanzado.
Si tienes mucha curiosidad, puedes leer más al respecto en [Go Blog: Mechanics of 'append'][mechanics-of-append]

## Aritmética de punteros

A diferencia de otros lenguajes, Go no admite la aritmética de punteros.
Esto significa que no puedes pasar de la dirección de memoria de un valor a la dirección de otro incrementando el valor del puntero.
Así que fragmentos como el siguiente no son válidos:

```go
var a int
a = 2

var pa *int
pa = &a
pa++ // NOT ALLOWED: incrementing the pointer or any other pointer arithmetic operations are invalid
```
