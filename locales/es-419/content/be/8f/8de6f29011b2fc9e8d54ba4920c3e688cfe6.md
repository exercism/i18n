# Anexo de instrucciones

## Pros y contras de `from_quote`

Este ejercicio define una función `from_quote` en el tipo `Card`. Esto hace posible escribir código como el siguiente:

```roc
card : Card
card = "Q"
```

Este código llama implícitamente a `Card.from_quote("Q")` en tiempo de compilación. Esto puede acelerar el programa, ya que no necesita encargarse del análisis en tiempo de ejecución, y garantiza que las cartas que `from_quote` rechaza se detecten en tiempo de compilación, en lugar de en tiempo de ejecución. Además, hace que el código sea agradable y legible. Por ejemplo, aquí tienes uno de los test de este ejercicio:

```roc
result = simulate_game({
    player_a: ["2", "A"],
    player_b: ["3", "4", "5", "6", "K"],
})
```

Sin embargo, alguien que lea este código podría suponer que la función `simulate_game` recibe un registro que contiene dos `List(Str)`, cuando en realidad es un registro que contiene dos `List(Card)`. Esto puede generar confusión y errores. Por eso, puede que prefieras el formato un poco más largo pero más explícito: `"Q".Card`, que también llama a `from_quote` en tiempo de compilación.

En tus propios programas, puede que prefieras usar `from_str` en su lugar:

```roc
Card := { ... }.{
    from_str : card_str -> Try(Card, [InvalidCard])
    from_str = |card_str| ...
}
```

También puedes llamar a `from_str` (o a cualquier otra función pura) en tiempo de compilación, así:

```roc
Ok(card) = Card.from_str("Q")
```

Nota: si colocas esta definición en el nivel superior, se ejecuta en tiempo de compilación (ya que la función es pura y su argumento se conoce en tiempo de compilación). Dentro de una función, puedes usar `from_str` en tiempo de ejecución.
