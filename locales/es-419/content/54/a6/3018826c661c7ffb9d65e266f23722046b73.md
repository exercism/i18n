# Introducción a la aritmética en el shell de Bash

Bash puede hacer aritmética, pero _solo con enteros_.
Si necesitas hacer cálculos con números de punto flotante, tendrás que llamar a algún programa externo (como [awk][awk] o [bc][bc]).

Los operadores aritméticos están listados (en orden de precedencia) en el manual: [Aritmética del shell][arithmetic].

Además, Bash solo realiza aritmética en ciertos lugares (conocidos como «contextos» aritméticos).

## Expansión aritmética

La expansión aritmética se parece a la [sustitución de comandos][cmd-sub], pero con doble paréntesis.

```bash
$(( expression ))
```

Esta sintaxis se expande al resultado de evaluar la expresión.
Por lo general, se usa para guardar el resultado en una variable:

```bash
x=$(( 3 + 4 ))
```

~~~~exercism/note
La cantidad de espacios en blanco dentro de los paréntesis es cosa tuya.
Es una cuestión de estilo y legibilidad.

```bash
x=$(( 3 + 4 ))
y=$((5+6))
```

Al amable autor de este documento le gusta agregar espacios para que la expresión aritmética se vea mejor dentro de los paréntesis.
~~~~

## Condicional aritmético

El condicional aritmético se realiza dentro de doble paréntesis _sin_ el `$` inicial:

```bash
(( expression ))
```

Esto no se expande al resultado.
Sin embargo, produce un _estado de salida_.

* El estado de salida es 0 (éxito) si el resultado de la expresión es **distinto de cero**.
* El estado de salida es 1 (fallo) si el resultado de la expresión es **cero**.

~~~~exercism/note
Dentro de `((`, Bash usa el mismo sentido de verdadero/falso que el lenguaje C: cero es falso, distinto de cero es verdadero.
**¡Esto es lo contrario de cómo Bash evalúa los estados de salida!**
~~~~

Esta sintaxis se suele usar en dos lugares:

1. como la parte COMANDO de una [sentencia `if`][conditional-if] o un [bucle `while`][looping-while].

   ```bash
   if (( x == y - 1 )); then ...
   while (( y > 0 )); do ...
   ```

1. como un comando independiente para modificar el valor de una variable.

   ```bash
   (( x = x + 1 ))
   echo "new value for x is $x"
   ```

   ~~~~exercism/caution
   Ten cuidado al usar la aritmética de esta forma junto con `set -e`.
   Si la expresión se evalúa como cero, el estado de salida será distinto de cero y Bash terminará.

   ```bash
   x=0
   (( x++ ))
   echo "you will see this"

   set -e
   x=0
   (( x++ ))
   echo "shell exits on the previous line; you won't see this"
   ```

   Para una discusión más detallada sobre el operador `++`, consulta este artículo sobre [Postincrement vs Preincrement][incr]

   [incr]: https://thisvsthat.io/postincrement-vs-preincrement
   ~~~~


## Otros lugares con contexto aritmético

Hay algunos otros lugares que son contextos aritméticos:

* El [bucle `for` aritmético][looping-for].

  ```bash
  for (( i = 0; i < 10; i++ )); do
      echo "$i"
  done
  ```

* La parte del índice de un array indexado numéricamente.

  ```bash
  echo "The next element is ${array[x + 1]}"
  # ................................^^^^^
  ```

  Para saber más sobre los arrays, lee el documento del concepto [Arrays][arrays].

* Las partes de desplazamiento y longitud de la expansión `${var:offset:length}`.
* El [comando integrado `let`][let].
  * Ten en cuenta que se prefiere `(( expression ))` en lugar de `let "expresson"`.
    A diferencia de la construcción del condicional aritmético, la expresión de `let` está sujeta a la expansión de nombres de archivo y a la división de palabras, y requiere comillas.
* La asignación de variables, cuando la variable tiene el «atributo de entero».

  ```bash
  # variable x does not have the integer attribute
  x="3 + 4"
  declare -p x      # => declare -- x="3 + 4"

  # variable y has the integer attribute
  declare -i y
  y="4 + 5"
  declare -p y      # => declare -i y="9"
  ```

  ~~~~exercism/note
  En opinión del autor, `declare -i` tiene un uso limitado.
  Su principal ventaja es permitir aritmética «desnuda» (sin la sintaxis de expresión aritmética).
  Esto puede causar confusión a quienes lean tu código, ya que las expresiones aritméticas se evalúan en lugares inesperados.
  ~~~~

## Uso de variables en expresiones aritméticas

Aquí hay un aspecto de los contextos aritméticos que mejora la legibilidad.

```bash
height=10
width=20
area=$(( height * width ))
```

¿Te fijaste en que faltan los signos de dólar `$` en las variables de la expresión aritmética?
Bash te lo permite.
Hace que las expresiones sean mucho más fáciles de leer.

El manual dice:

> Dentro de una expresión, las variables del shell también se pueden referenciar por su nombre sin usar la sintaxis de expansión de parámetros.

Incluso funciona para los elementos de un array:

```bash
point1=(10 15)  # these are (x, y) coordinates
point2=(20 7)
distance_squared=$(( (point1[0] - point2[0])**2 + (point1[1] - point2[1])**2 ))
```

Pero otras expresiones de parámetros necesitan usar su sintaxis especial.
Por ejemplo, duplicar la longitud de un string:

```bash
s="hello world"
len=$(( ${#s} * 2 ))
```

Y los parámetros posicionales también.
Si los dos primeros parámetros posicionales representan el ancho y la altura:

```bash
area=$(( $1 * $2 ))
```
