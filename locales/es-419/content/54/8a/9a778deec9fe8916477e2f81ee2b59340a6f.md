# Anexo a las instrucciones

El conjunto de pruebas solo genera ~100 nombres de forma predeterminada.
Hay ~700k nombres válidos, así que solo dará una pequeña probabilidad de colisiones.
Considera probar tu solución en busca de colisiones de alguna otra forma, además del conjunto de pruebas.

Este ejercicio continúa nuestra exploración del
[sistema de tipos](https://docs.julialang.org/en/v1/manual/types/) de Julia,
esta vez con tipos mutables,
y nos presenta la
[generación de números aleatorios](https://docs.julialang.org/en/v1/stdlib/Random/).

Imaginemos que restablecer el robot a la configuración de fábrica es como una cirugía: le hace cambios al sujeto, pero no lo reemplaza.
También podríamos haber modelado el problema de forma que restablecer un robot cree un robot nuevo, pero no todos los problemas se pueden modelar solo con estructuras de datos inmutables (¡incluso los lenguajes puramente funcionales lidean con la mutabilidad dentro de sus entornos de ejecución!).

En Julia, las funciones que mutan sus argumentos llevan el sufijo `!` por convención.
Así que nuestro método para hacer esto se llamará `reset!`.

Esto es solo una convención, pero casi todo el código de Julia publicado la sigue, y puede que llegues a estar de acuerdo en que es bastante útil.

## Sugerencias

Vas a tener que definir
un método para generar nombres únicos,
una estructura para describir robots,
un método para restablecer un robot
y un método para obtener el nombre de un robot.

Puede que te resulte útil diseñar primero tu programa para que solo emita un nombre aleatorio para un robot (sin preocuparte por las colisiones) y, más adelante, pensar y diseñar un esquema que evite emitir nombres duplicados.
En tu diseño, piensa con cuidado en cómo cambia el tiempo de ejecución de la generación de nombres a medida que se agotan los nombres. ¿Qué garantías quieres ofrecerle a quien llama?
