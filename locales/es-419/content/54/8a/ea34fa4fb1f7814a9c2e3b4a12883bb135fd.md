# Pruebas

## En Exercism

Cada ejercicio se proporciona como una sola clase ABAP (con uno o más métodos). Por lo general, se dan las definiciones de los métodos con sus parámetros de entrada y salida. Tu tarea es completar la implementación del método según las especificaciones del ejercicio.

Cuando ya tengas código que quieras probar, selecciona «Ejecutar las pruebas». Esto iniciará la ejecución de una clase de pruebas ABAP correspondiente y los resultados aparecerán después de unos segundos. Si hay errores, vuelve a tu código y ajústalo como corresponda. Si todas las pruebas pasan, ¡felicidades! Completaste el ejercicio y ya puedes enviar tu solución.

### Solución de problemas

Detrás de escena, tu código ABAP se compila y se ejecuta usando el llamado [transpilador de abaplint](https://github.com/abaplint/transpiler). Todavía es una solución relativamente nueva. Si tienes algún problema que no puedas resolver, crea un issue en [GitHub](https://github.com/abaplint/transpiler/issues).

### Depuración y registro

No hay ningún depurador disponible cuando ejecutas ejercicios de ABAP en el sitio web de Exercism. Eso puede dificultar saber por qué están fallando tus pruebas. Sin embargo, hay una forma ingeniosa de registrar datos en tu código (Nota: esto no funciona en ningún sistema ABAP).

Aquí tienes un [ejemplo](https://exercism.org/tracks/abap/exercises/affine-cipher/solutions/mbtools). La primera imagen muestra el código del ejercicio con algunas pruebas que fallan. Cada prueba fallida muestra los valores esperados y los reales:

![ejercicio sin registro de datos](https://github.com/exercism/abap/blob/main/docs/logging_01.png?raw=true)

Para facilitar la depuración, agrega una o varias llamadas a `console=>log()` y pásale los datos intermedios que tengas al método. Usar saltos de línea (`\n`) te ayudará a estructurar la salida. Cuando ejecutes las pruebas, verás la salida de la consola en los resultados de las pruebas:

![ejercicio con registro de datos](https://github.com/exercism/abap/blob/main/docs/logging_02.png?raw=true)

Nota: la salida de la consola solo es visible para las pruebas que fallan. Si vas a publicar tu solución, quizá quieras quitar las instrucciones de registro para que tu iteración publicada sea más fácil de leer para los demás miembros de la comunidad.

## En tu propio sistema

### Track completo

La forma más fácil de empezar a practicar en tu propio sistema es clonar [este repositorio](https://github.com/exercism/abap) con [abapGit](https://github.com/abapGit/abapGit). Esto creará los esqueletos y las clases de pruebas de todos los ejercicios disponibles actualmente.

### Ejercicios individuales

Abre tus ABAP Development Tools (o las transacciones `SE24` o `SE80` si tienes un sistema más antiguo) y crea una nueva clase ABAP con el mismo nombre que la clase del ejercicio. Implementa también el esqueleto de la clase y la clase de pruebas copiando y pegando el código del sitio web de Exercism.

### Implementar soluciones

Ahora puedes editar la clase de un ejercicio e implementar una solución. Después ejecuta las pruebas unitarias de ABAP para comprobar si pasa todas las pruebas. Cuando termines y las pruebas pasen, corta y pega tu código en el editor del ejercicio en el sitio web de Exercism. Ejecuta también las pruebas ahí.

### Probar y completar el ejercicio

Cuando escribes código y lo pruebas en tu propio sistema, se usan el compilador y la ejecución estándar de SAP ABAP. Si tus pruebas fallan, probablemente tenga que ver con tu propio código. Vuelve a revisarlo.

Si tu código pasa las pruebas unitarias, corta y pega la implementación de tu clase en el ejercicio del sitio web de Exercism y selecciona «Ejecutar las pruebas». Por supuesto, las pruebas también deberían pasar ahí. Si no es así, consulta la sección de solución de problemas de arriba.
