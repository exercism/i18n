# Tipos de datos genéricos

Los genéricos en Cairo te permiten escribir código reutilizable que funciona con varios tipos, lo que evita la duplicación y mejora la facilidad de mantenimiento.

Puedes usar genéricos con funciones, estructuras, enumeraciones, rasgos y métodos.

## Funciones genéricas

Una función genérica opera con distintos tipos sin necesidad de implementaciones separadas.

Por ejemplo:

```rust
fn largest_list<T>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

Aquí, `T` es un marcador de posición para cualquier tipo.

Sin embargo, Cairo requiere límites de rasgos para asegurar que el tipo genérico cumpla con requisitos específicos.

Si `T` necesita poder dropearse, puedes actualizar la firma:

```rust
fn largest_list<T, impl TDrop: Drop<T>>(l1: Array<T>, l2: Array<T>) -> Array<T> {
    if l1.len() > l2.len() {
        l1
    } else {
        l2
    }
}
```

Los límites de rasgos, como `Drop` o `PartialOrd`, agregan restricciones a los genéricos para operaciones específicas.

## Restricciones anónimas

Si la implementación de un rasgo no se usa directamente en una función, puedes escribir restricciones anónimas con `+`:

```rust
fn smallest_element<T, +PartialOrd<T>, +Drop<T>, +Copy<T>>(list: @Array<T>) -> T {
    let mut smallest = *list[0];
    let mut index = 1;

    while index < list.len() {
        if *list[index] < smallest {
            smallest = *list[index];
        }
        index += 1;
    };

    smallest
}
```

Esto evita nombrar rasgos como `TPartialOrd`, lo que reduce la verbosidad.

## Estructuras con genéricos

Los genéricos en las estructuras permiten que los campos sean flexibles.

Por ejemplo:

```rust
#[derive(Drop)]
struct Wallet<T> {
    balance: T,
}

let w = Wallet { balance: 42 };
```

Si una estructura necesita varios tipos genéricos, solo agrega más marcadores de posición:

```rust
#[derive(Drop)]
struct Wallet<T, U> {
    balance: T,
    address: U,
}

let w = Wallet { balance: 42, address: '0xabc' };
```

## Enumeraciones con genéricos

Las enumeraciones también pueden contener tipos de datos genéricos.

Por ejemplo:

```rust
enum Option<T> {
    Some: T,
    None,
}
```

La enumeración `Option<T>` puede representar un valor opcional de cualquier tipo.

De manera similar, `Result<T, E>` permite definir tipos para el éxito y para el error:

```rust
enum Result<T, E> {
    Ok: T,
    Err: E,
}
```

## Métodos genéricos

Los métodos también pueden usar genéricos.

Por ejemplo:

```rust
#[derive(Copy, Drop)]
struct Wallet<T> {
    balance: T,
}

trait WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T;
}

impl WalletImpl<T, +Copy<T>> of WalletTrait<T> {
    fn balance(self: @Wallet<T>) -> T {
        *self.balance
    }
}

let w = Wallet { balance: 50 };
assert!(w.balance() == 50);
```

También puedes definir métodos para tipos genéricos específicos, como `Wallet<u128>`:

```rust
trait WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128);
}

impl WalletReceiveImpl of WalletReceiveTrait {
    fn receive(ref self: Wallet<u128>, value: u128) {
        self.balance += value;
    }
}

let mut w = Wallet { balance: 50 };
w.receive(100);
assert!(w.balance() == 150);
```

## Mezclar tipos genéricos

Los genéricos pueden manejar combinaciones complejas.

Por ejemplo, al combinar dos instancias de `Wallet` de tipos distintos:

```rust
trait WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2>;
}

impl WalletMixImpl<T1, +Drop<T1>, U1, +Drop<U1>> of WalletMixTrait<T1, U1> {
    fn mixup<T2, +Drop<T2>, U2, +Drop<U2>>(
        self: Wallet<T1, U1>, other: Wallet<T2, U2>,
    ) -> Wallet<T1, U2> {
        Wallet { balance: self.balance, address: other.address }
    }
}

let w1 = Wallet { balance: true, address: 10 };
let w2 = Wallet { balance: 32, address: 100 };
let w3 = w1.mixup(w2);

assert!(w3.balance);
assert!(w3.address == 100);
```

Al agregar restricciones `+Drop`, el compilador asegura un manejo adecuado de los recursos.

Los genéricos son potentes, pero requieren un manejo cuidadoso de las restricciones.

Úsalos para escribir código reutilizable, independiente del tipo y conciso.
