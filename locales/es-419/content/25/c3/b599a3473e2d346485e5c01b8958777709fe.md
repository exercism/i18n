# Introducción al entrecomillado

Un consejo que los nuevos programadores de bash escucharán una y otra vez:

> ¡Entrecomilla tus variables!

¿Por qué?

Cuando expandes una variable (como `$name`), casi siempre quieres usar el _valor_ de la variable como un solo string (o número).
No quieres que el valor se trate inesperadamente como dos o más strings separados.

## Entrecomillado

El entrecomillado es el mecanismo principal para asegurar que un fragmento de texto se trate como una sola palabra.
Hay dos tipos principales de comillas.

### Comillas dobles

Las comillas dobles permiten la expansión de parámetros, la expansión aritmética y la sustitución de comandos dentro de ellas.

```bash
echo "This is bash version $BASH_VERSION"
```

Puedes incluir una comilla doble literal dentro de un string entre comillas dobles si la precedes con una barra invertida.

```bash
echo "She said \"Let me teach you about bash.\""
```

### Comillas simples

Las comillas simples _no permiten_ ninguna expansión dentro de ellas.

```bash
echo 'This is bash version $BASH_VERSION'
# ...^..................................^
# prints exactly: This is bash version $BASH_VERSION
```

_No es posible_ incrustar una comilla simple dentro de un string entre comillas simples.

## Importancia del entrecomillado

¿Qué tiene de malo `echo $name`, exactamente?

Cuando el shell analiza una línea de código, realiza [varios tipos de expansiones][expansions], en orden.
Dos de las últimas expansiones son la _división de palabras_ y la _expansión de nombres de archivo_.

### División de palabras

Cualquier resultado de expansión de parámetros, sustitución de comandos o expansión aritmética _que no ocurrió dentro de comillas dobles_ es candidato a la «división de palabras».
El shell toma el resultado expandido y lo divide en cualquier secuencia de caracteres presente en el valor de `$IFS`.
De forma predeterminada, son el espacio, el tabulador y el salto de línea.

Podemos ver esto en acción usando un bucle de shell:

```bash
sentence="The quick brown fox jumps."
i=0
for word in "$sentence"; do echo "$((++i)) $word"; done
# ..........^.........^
```
produce:
```none
1 The quick brown fox jumps.
```

Pero sin comillas:

```bash
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
produce:
```none
1 The
2 quick
3 brown
4 fox
5 jumps.
```

Veámoslo con un valor diferente de `$IFS`:

```bash
csv="first,second,third"
IFS=","
for word in $csv; do echo "$word"; done
```
produce:
```none
first
second
third
```

#### Desactivar la división de palabras

Una técnica para desactivar la división de palabras es establecer `$IFS` en un string vacío

```bash
sentence="The quick brown fox jumps."
IFS=    # or explicitly, IFS=""
i=0
for word in $sentence; do echo "$((++i)) $word"; done
# .........^.........^
```
produce:
```none
1 The quick brown fox jumps.
```

Sin embargo, no se recomienda dejar las variables sin comillas a menos que también desactives la expansión de nombres de archivo.
Veremos cómo hacerlo más abajo.

### Expansión de nombres de archivo

Los patrones «glob» se usan para expresar un patrón conciso que coincida con un conjunto de archivos.
Por ejemplo, podrías hacer coincidir todos los archivos Markdown de un directorio con `*.md`.
Los [patrones glob][glob] existen desde la invención de Unix.

Los caracteres comodín de glob son:

* `*` coincide con cero o más de cualquier carácter,
* `?` coincide con exactamente uno de cualquier carácter,
* `[...]` coincide con exactamente un carácter del conjunto de caracteres listados dentro de los corchetes.

   ~~~~exercism/advanced
   <details><summary>
   Hay muchos detalles sobre los conjuntos de caracteres.
   Haz clic aquí para mostrarlos.
   </summary>

    * `[abc]` coincide con exactamente un carácter que sea una `a`, una `b` o una `c`.
        * para incluir un corchete de cierre literal en la expresión, haz que sea el primer carácter después del corchete de apertura (después de un `^` opcional)
            * `[][]` es un conjunto de caracteres que coincidirá con un corchete de cierre o de apertura.
            * o escápalo con una barra invertida: `[[\]]`
    * `[x-y]` coincide con exactamente un carácter que esté en el _rango_ de `x` a `y`
        * para incluir un carácter guion literal en un conjunto de caracteres, debe ser el primer carácter después del corchete de apertura (después de un `^` opcional) o el último carácter antes del corchete de cierre.
            * `[-xy]` o `[xy-]` coinciden cada uno con exactamente un carácter que sea un `-`, una `x` o una `y`
            * o escápalo con una barra invertida: `[x\-y]`
        * se pueden especificar varios rangos, por ejemplo `[0-9A-Fa-f]` coincide con un dígito hexadecimal
    * `[^abc]` coincide con exactamente un carácter que **NO** sea una `a`, una `b` o una `c`,
    * `[^x-y]` coincide con exactamente un carácter que **NO** esté en el rango de `x` a `y`
    * `[[:character_class:]]` coincide con un carácter que esté en la clase de caracteres denominada «character_class»
        * las clases de caracteres disponibles son: 
            * `lower` -- letras minúsculas
            * `upper` -- letras mayúsculas
            * `alpha` -- letras
            * `digit` -- dígitos
            * `alnum` -- letras y dígitos
            * `space` -- espacios en blanco
            * `blank` -- espacios en blanco horizontales (espacio y tabulador)
            * `xdigit` -- dígitos hexadecimales
            * `word` -- caracteres permitidos en un identificador (letras, números, guion bajo)
            * `punct` -- puntuación
            * `cntrl` -- caracteres de control
            * `graph` -- caracteres «visibles»
            * `print` -- caracteres visibles más espacio
        * se pueden combinar:
            * la clase `[[:alpha:]]` consiste en `[[:lower:][:upper:]]`
            * la clase `[[:alnum:]]` consiste en `[[:alpha:][:digit:]]`
            * la clase `[[:word:]]` consiste en `[[:alnum:]_]`
            * el guion bajo (octal 137) es tanto `[[:word:]]` como `[[:punct:]]`
            * la clase `[[:graph:]]` consiste en `[[:alnum:][:punct:]]`
            * la clase `[[:print:]]` consiste en `[[:graph:] ]` -- solo espacio (octal 040), no ningún otro espacio en blanco.

#### Iterar sobre una lista de archivos

Puedes iterar sobre una lista de archivos con un bucle `for`

```bash
for file in *.csv; do
    do_something_with "$file"
done
```

Fíjate que la variable `"$file"` está entre comillas.
El patrón glob puede devolver archivos que contienen espacios en el nombre.
Necesitamos entrecomillar la variable para que el comando `do_something_with` reciba exactamente un argumento, el nombre del archivo.

#### Los patrones glob no son expresiones regulares

Los patrones glob **no son** expresiones regulares.

* coinciden con exactamente un carácter
   * regex `.`
   * glob `?`
* coinciden con cero o más caracteres
   * regex `.*`
   * glob `*`
        * el patrón glob `.*` significa «coincide con un nombre de archivo donde el primer carácter es un punto literal seguido de cero o más de cualquier carácter».
* coinciden con uno o más caracteres
   * regex `.+`
   * glob `?*`
* los conjuntos de caracteres de regex y los conjuntos de caracteres de glob actúan de la misma manera.

#### Entrecomillado y expansión de nombres de archivo

Hay ocasiones en las que quieres suprimir la expansión de nombres de archivo.
Manejar la entrada del usuario es una de esas ocasiones.
Considera este fragmento de código

```bash
read -p "Enter something: " user_input
echo $user_input
```

Si el usuario ingresa un asterisco (`*`), ¿qué se imprimirá?
La lista de archivos del directorio actual.
Probablemente eso no sea lo que quieres hacer.

Otro ejemplo es pasar patrones como argumentos a programas que esperan patrones.
El programa `tr` se usa a menudo para manipular texto. Para convertir a minúsculas el valor de una variable, puedes hacer esto

```bash
var="My Puppet"
echo "$var" | tr '[:upper:]' '[:lower:]'
```
produce:
```none
my puppet
```

Un error común es olvidar entrecomillar los argumentos de `tr`: `tr [:upper:] [:lower:]`

~~~~exercism/caution
¿Por qué es un problema? 
Los patrones glob sin comillas se expandirán a la lista de archivos que coincidan.
Supón que la persona que usa tu script tiene archivos llamados `p`, `u` y `w` en el directorio actual:

```bash
touch p u w
var="My Puppet"
echo "$var" | tr [:upper:] [:lower:]
```

¡Esto produce un error!

El patrón `[:upper:]` sin comillas coincide con cualquiera de `:`, `u`, `p`, `e` o `r`.
El patrón `[:lower:]` sin comillas coincide con cualquiera de `:`, `l`, `o`, `w`, `e` o `r`.
Bash hace coincidir los archivos `p` y `u` para el primer patrón, y el archivo `w` para el segundo patrón, y se invoca `tr` así

```bash
echo "$var" | tr p u w
```

Y ese es el número incorrecto de argumentos para `tr`.
~~~~

#### Desactivar la expansión de nombres de archivo

Puedes usar el comando [`set`][set] para desactivar la expansión de nombres de archivo.

```bash
echo *      # prints a list of files
set -f      # disable filename expansion
echo *      # prints a literal asterisk
set +f      # enable filename expansion
```

#### Controlar la expansión de nombres de archivo

Hay varias opciones de configuración para el comando integrado [`shopt`][shopt] que controlan cómo funciona la expansión de nombres de archivo.
Un par de opciones interesantes son:

* `shopt -s nocaseglob` -- realiza coincidencias sin distinguir mayúsculas y minúsculas
* `shopt -s extglob` -- habilita patrones extendidos
* `shopt -s nullglob` -- si ningún archivo coincide, reemplaza el patrón por nada.
   El comportamiento predeterminado es dejar el patrón en su lugar como un string literal.
