# Introducción

En muchos lenguajes orientados a objetos, es común extender comportamientos [creando subclases][wiki-subclass] de una clase padre, heredando métodos de ella y agregando otros nuevos al mismo tiempo.
Así obtenemos una jerarquía de objetos.

Julia _no tiene clases_, así que, por extensión, _tampoco tiene subclases_.
¿Cómo heredamos y extendemos los comportamientos existentes?

En conceptos anteriores vimos cómo crear una jerarquía de tipos, y también aprendimos cómo Julia usa el [despacho múltiple][concept-multiple-dispatch] para elegir métodos según los tipos de los argumentos.

Julia también tiene varias interfaces informales, que permiten que tus tipos personalizados se enganchen a comportamientos ya definidos para los tipos estándar.

Esto se ilustra más fácilmente con la interfaz de iteradores.

## Iteradores

Antes, en el temario, vimos varias formas en que Julia puede operar sobre cada elemento de una colección.

- [Bucles][concept-loops], como `for item in items...`
- [Operaciones con vectores][concept-vector-operations]: `[1, 2, 3] .- 0.5`
- [Funciones de orden superior][concept-hof]: `map(√, [1, 4, 9])`
- [Comprensiones][concept-comprehensions]: `[x * y for x in 1:3 for y in 4:6 if isodd(x * y)]`
- [Generadores][concept-comprehensions]: `(x^2 for x in 1:1e6)`, que se evalúa de forma perezosa.

Está claro que Julia sabe cómo recorrer las colecciones estándar elemento por elemento: vectores y rangos en los ejemplos anteriores, y también Sets, Dicts, etc.

¿Cómo agregamos esta capacidad a nuestras propias colecciones personalizadas, sobre todo si se pueden iterar de forma perezosa como un generador?

### Requisitos mínimos

Para crear una secuencia que se pueda iterar, necesitamos (al menos) dos cosas:

1. Una forma de obtener el _primer_ elemento.
2. Una forma de obtener el elemento _siguiente_ a partir del estado actual.

Julia logra estas tareas con métodos de la función `Base.iterate()` mediante los siguientes pasos:

1. Primero se llama automáticamente a `Base.iterate(iter)`.
    - Si no hay nada que iterar, devuelve `nothing`.
    - Si no, devuelve la `Tuple` del primer elemento devuelto y el primer estado: `(firstitem, firststate)`.
2. Si la iteración anterior devolvió un elemento, se llama automáticamente a `Base.iterate(iter, state)`, tomando `firststate` como su argumento `state`.
    - Si la iteración termina, devuelve `nothing`.
    - Si no, devuelve la `Tuple` del elemento siguiente y el estado siguiente: `(nextitem, nextstate)`.
3. Repite el paso 2 hasta que la iteración termine.

Todos estos pasos ocurren «bajo el capó», lo que significa que el protocolo de iteración gestiona internamente las llamadas a métodos y el estado (que permanece opaco), y lo único que se expone a las construcciones de alto nivel, como los bucles, es el elemento.
En otras palabras, lo único que vemos es el `item`, mientras que todo lo demás queda dentro de una caja negra.

El [despacho múltiple][concept-multiple-dispatch] es fundamental para esto.
El tipo de `iter` determina qué métodos se llaman, y el número de argumentos determina si se devuelve el primer elemento o el siguiente.

Los métodos para los tipos estándar ya están definidos: `Vector`, `Range`, `Set`, etc. ([actualmente][ref-iterations-collections] 14 tipos en total).

Para que un `MyType` personalizado comparta los mismos comportamientos, primero tenemos que definir:
- `Base.iterate(iter::MyType)`
- `Base.iterate(iter::MyType, state)`

Todo esto probablemente suene confuso en abstracto, pero puede ser bastante simple.
Para ilustrarlo, imagina que queremos un tipo que dé las potencias de un entero `n` dado, hasta una cantidad máxima.

Primero, define un tipo personalizado:

```julia
struct Powers
    n::Int      # base number to raise to a power
    count::Int  # maximum length of the sequence
end
```

Ya podemos definir los métodos `iterate` para este tipo, pero ¿cuáles son el primer elemento y el primer estado?

Para obtener el primer elemento, algunos iteradores necesitan una configuración complicada, pero en este caso sencillo podemos notar que el primer elemento devuelto es simplemente el número base, así que solo tenemos que comprobar si el valor de `count` es mayor o igual que uno.

Ahora podemos considerar el primer estado, que lleva información que se usa en la siguiente iteración.
Depende de ti decidir qué información necesitas ir registrando para lograrlo, y puede ser de cualquier tipo.

En este caso, podríamos simplemente llevar un registro del «índice» al que elevar `n`, o podemos encontrar una opción más eficiente usando la potencia más reciente de `n` (es decir, el elemento devuelto) y el siguiente «índice» de la secuencia.
Estos dos números se pueden envolver en una `Tuple` y devolver como el `state`.

```julia
function Base.iterate(p::Powers)
    # if iteration should continue
    if 1 ≤ p.count
        # return (firstitem, firststate)
        return (p.n, (p.n, 2)) 
    end
    # else terminate iteration
    return nothing
end
```

En este ejemplo, el primer elemento (`p.n`) se devuelve al bucle y el primer estado `(p.n, 2)` se pasa al método `iterate(P::Powers, state)`.
Ahí podemos procesar el estado para producir el siguiente elemento multiplicando el elemento actual por el número base, y así aumentar su potencia en `1`.

```julia
function Base.iterate(p::Powers, state)
    # unpack the state
    curr, index = state

    # create next item                 
    next = curr * p.n

    # if iteration should continue
    if index ≤ p.count
        # return (nextitem, nextstate)
        return (next, (next, index + 1))
    end
    # else terminate iteration
    return nothing
end
```

Si el valor del índice todavía está dentro de `count`, se devuelve la `Tuple` con el elemento `next` y la `Tuple` del estado incrementado.
Cuando el valor de `index` supera `count`, se devuelve `nothing` en su lugar, para indicar que la iteración ha terminado.

Quizá hayas notado que los métodos `iterate(p::Powers)` e `iterate(p::Powers, state)` tienen cuerpos de función bastante parecidos.
De hecho, si somos astutos, esta similitud permite una implementación más sencilla usando solo la versión de dos argumentos con un argumento predeterminado para el estado: `Base.iterate(p::Powers, state=(1, 1))`
Con eso, no necesitaríamos el método aparte de un solo argumento `iterate(p::Powers)`.
Esto se hace con frecuencia en la práctica cuando es posible.

Hasta ahora ya tenemos algunas funcionalidades útiles: para las primeras 4 potencias de 3, podemos recorrer los resultados con un bucle, comprobar si un número dado está entre los resultados y aplicar funciones de agregación como `sum()`.

```julia-repl
julia> for p in Powers(3, 4)
            println(p)
       end
3
9
27
81

julia> 9 ∈ Powers(3, 4) # ∈ is a synonym for in
true

julia> sum(Powers(3, 4))
120
```

### Métodos adicionales

A pesar de este buen comienzo, todavía no funciona todo.

```julia-repl
julia> [p for p in Powers(3, 4)]
ERROR: MethodError: no method matching length(::Powers) (from the documentation][ref-interfaces])
The function `length` exists, but no method is defined for this combination of argument types.
You may need to implement the `length` method or define `IteratorSize` for this type to be `SizeUnknown`.
```

Efectivamente, `length(Powers(3, 4))` da exactamente el mismo mensaje de error.

Esto se arregla fácilmente, ya que la longitud es parte del constructor del tipo: 4 en este caso.
Solo tenemos que definir `Base.length()` para este tipo, y entonces podremos usar comprensiones y `collect()` sobre la secuencia.

```julia-repl
julia> Base.length(P::Powers) = P.count

julia> length(Powers(3, 4))
4

julia> [p for p in Powers(3, 4)]
4-element Vector{Int64}:
  3
  9
 27
 81

julia> collect(Powers(3, 4))
4-element Vector{Any}:
  3
  9
 27
 81

julia> Set(Powers(3, 4))
Set{Int64} with 4 elements:
  81
  27
  9
  3
```

Por eficiencia, lo mejor es definir también `Base.eltype()`: el tipo de elemento del resultado.
Esto permite que funciones como `collect()` reserven espacio de antemano para el `Vector{Int}` de salida, en lugar de hacer repetidamente un `push!()` a un `Vector{Any}`.

Fíjate en la sintaxis, que quizá no hayas visto antes: este método se define sobre el _tipo_, no sobre una _instancia_ del tipo.

```julia-repl
julia> Base.eltype(::Type{Powers}) = Int
```

Los iteradores no están _obligados_ a tener longitud finita.
El uso de secuencias «infinitas» es más limitado, pero recorrerlas con un bucle puede ser útil siempre que haya alguna forma de `break` para salir del bucle.
Por ejemplo, podríamos definir una variante de `Powers` que genere valores menores que cierto límite (quizá `typemax(Int)`, para evitar el desbordamiento de enteros).

## Resumen

Las interfaces son bastante confusas de explicar, porque el enfoque de Julia es muy distinto al de la mayoría de los demás lenguajes.
En particular, puede que el nombre de la interfaz nunca se mencione en la implementación, a diferencia de [crear subclases][wiki-subclass] o de los [mixins][wiki-mixins].

Sin embargo, en la práctica son sorprendentemente simples:

1. Define un tipo adecuado.
2. Averigua qué métodos se requieren.
3. Implementa esos métodos para tu tipo personalizado; normalmente son solo unos pocos métodos, bastante cortos y simples.
4. Deja que el [despacho múltiple][concept-multiple-dispatch] se encargue del resto, automáticamente.
