# Acerca de

Cuando una función acepta otra función (o un closure) como parámetro, ese closure que se pasa se denomina *no escapante* por defecto.
Se dice que un closure *escapa* de una función cuando se lo llama después de que la función ya devolvió.

Esta situación suele darse cuando:

- Un closure se guarda en una variable o propiedad externa.
- Un closure se ejecuta de forma asíncrona después de que finaliza una operación.
- Un closure se devuelve desde la función para llamarlo más tarde.

Considera el siguiente ejemplo:

```swift
func emptyKitchen(_ order: String) -> String {
    "Sorry, we're all out of \(order)."
}

func prepare(order: String, kitchen: (String) -> String) -> (String) -> String {
    func newKitchen(_ newOrder: String) -> String {
        if newOrder == order {
            return "One \(order) coming up!"
        } else {
            return kitchen(newOrder)
        }
    }
    return newKitchen
}
```

En este código, `prepare` acepta una función llamada `kitchen`, construye una nueva función `newKitchen` que llama a `kitchen` y devuelve `newKitchen`.
Intentar compilar este código produce un error: `Escaping local function captures non-escaping parameter 'kitchen'`.

Como `newKitchen` sobrevive a `prepare`, el closure `kitchen` escapa.
Para permitirlo, marca el tipo del parámetro con el atributo `@escaping`.

```swift
func prepare(order: String, kitchen: @escaping (String) -> String) -> (String) -> String {
    func newKitchen(_ newOrder: String) -> String {
        if newOrder == order {
            return "One \(order) coming up!"
        } else {
            return kitchen(newOrder)
        }
    }
    return newKitchen
}

let restaurant = prepare(
    order: "sandwich",
    kitchen: prepare(
        order: "chicken",
        kitchen: prepare(order: "steak", kitchen: emptyKitchen)
    )
)

print(restaurant("pork chop"))
// Prints "Sorry, we're all out of pork chop."

print(restaurant("chicken"))
// Prints "One chicken coming up!"
```

El atributo `@escaping` le indica al compilador de Swift que el closure sobrevivirá a la llamada inmediata a la función, lo que permite que Swift gestione correctamente la memoria y las referencias capturadas.
