# Instrucciones

Vuelves a trabajar en el sistema ORM (mapeo objeto-relacional) que se presentó en [exercise:csharp/object-relational-mapping]().

Nuestro análisis del uso del ORM muestra que el 95% de las transacciones se ejecutan desde un único método que hace la llamada, y se ha decidido que sería más apropiado tener un solo método del ORM que abriera, escribiera y confirmara una transacción.

La base de datos tiene los siguientes métodos de instancia:

- `Database.BeginTransaction()` inicia una transacción en la base de datos.
- `Database.Write(string data)` escribe datos en la base de datos dentro de la transacción. Si recibe datos incorrectos, se lanzará una excepción. Un intento de llamar a este método sin que se haya llamado antes a `BeginTransaction()` provocará que se lance una excepción. Si tiene éxito, el estado interno de la base de datos cambiará a `DataWritten`.
- `Database.EndTransaction()` confirma la transacción en la base de datos. Puede lanzar una excepción si no puede cerrar la transacción o si no se ha llamado a `Database.BeginTransaction()`.
- Una llamada a `Database.Dispose()` limpiará la base de datos si se lanza una excepción durante una transacción. Esto cambiará el estado de la base de datos a `Closed`.

## 1. Escribir en la base de datos

Implementa el método `Orm.Write()` para iniciar una transacción de base de datos, escribir los datos que se pasan y confirmar la transacción. Todas las excepciones, incluida `InvalidOperationException`, deben poder propagarse a quien hizo la llamada, sin registrarlas ni intervenir de ninguna otra forma.

```csharp
Database db = new Database();
Orm orm = new Orm(db);
orm.Write("good write");
// => database has an internal state of State.Closed
orm.Write("bad write");
// => an exception is thrown but database is left with an internal state of State.Closed
orm.Write("bad commit");
// => an exception is thrown but database is left with an internal state of State.Closed
```

## 2. Escribir en la base de datos y devolver a quien hizo la llamada una indicación de si la escritura fue exitosa

Han pasado unos meses desde que se introdujo `Orm.Write()` y hay división en el equipo. A muchos desarrolladores les gustaría que el _ORM_ gestionara los errores cuando se lanzan excepciones y que simplemente devolviera a quien hizo la llamada una indicación de éxito.

Implementa el método `Orm.WriteSafely()` para iniciar una transacción de base de datos, escribir los datos que se pasan y confirmar la transacción (igual que antes). Debe devolver `true` si la _escritura_ fue exitosa; de lo contrario, `false`. No intentes registrar la excepción en el log.

```csharp
Database db = new Database();
Orm orm = new Orm(db);
orm.WriteSafely("good write");
// => true
orm.WriteSafely("bad write");
// => false
orm.WriteSafely("bad commit");
// => false
```
