# Introducción

En Go, los strings son inmutables.
Concatenar strings con `+` dentro de un bucle provoca asignaciones frecuentes y copia los datos varias veces.
El [paquete `strings`](https://pkg.go.dev/strings) ofrece [`Builder`](https://pkg.go.dev/strings#Builder) para minimizar el consumo de memoria al ensamblar strings de forma eficiente.

## Construir strings

El valor cero de un `strings.Builder` está listo para usarse de inmediato, sin necesidad de inicialización ni de asignación de memoria explícitas.
Puedes agregar datos nuevos al builder con métodos de escritura específicos.
Cada método de escritura devuelve un valor de error para cumplir con las interfaces estándar de Go, pero está garantizado que siempre es `nil`, así que en el código del día a día se suele ignorar.

Los métodos que más se usan son:

- `WriteString(s string) (int, error)`: agrega un string al búfer.
- `WriteRune(r rune) (int, error)`: agrega la codificación UTF-8 de un rune.
- `WriteByte(c byte) error`: agrega un solo byte.

```go
var sb strings.Builder

sb.WriteString("Hello")
var r rune = ' '
sb.WriteRune(r)
var b byte = '.'
sb.WriteByte(b)
```

## Obtener el resultado y reiniciar

Cuando termines de armar tu texto, puedes obtener el contenido acumulado como un string estándar de Go llamando al método `String()`.
Llamar a `String()` es una operación muy económica, porque devuelve directamente el slice de bytes subyacente como un string, sin copiar los datos acumulados.

Si necesitas reutilizar la misma instancia del builder para armar otro string (por ejemplo, dentro de un bucle), puedes llamar al método `Reset()`.
Esto vacía el búfer interno, lo que te permite empezar de cero y construir el siguiente string conservando, por debajo, la capacidad de memoria que ya estaba reservada.

```go
var sb strings.Builder

sb.WriteString("Task One")
fmt.Println(sb.String()) // Output: Task One

// Clear the buffer for resource reuse
sb.Reset()

sb.WriteString("Task Two")
fmt.Println(sb.String()) // Output: Task Two
```
