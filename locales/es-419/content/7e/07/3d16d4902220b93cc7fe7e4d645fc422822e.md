# Acerca de

_«Las fechas y las horas son algo que les enseñamos a los niños pequeños. ¿Qué tan difícil puede ser?»_

Muchos programadores han cometido ese error, y la experiencia posterior suele tener un efecto negativo en su salud y su felicidad.

Cualquiera que haga programación no trivial con fechas y horas debería al menos estar en condiciones de entender y mitigar los posibles problemas.

Este documento intentará dar una visión general de cómo Julia maneja las fechas y las horas, pero para más detalles será necesario consultar el [manual][Dates].
También hay un [Wikibook][Wikibook] cuyas explicaciones a algunos lectores les pueden resultar más claras, e incluye un útil [diagrama][type-hierarchy] de la jerarquía de tipos.

## El módulo `Dates`

La mayor parte de la funcionalidad básica está en `Dates`, un módulo que se incluye en una instalación predeterminada pero que no forma parte de la biblioteca estándar.

Para usar el módulo, hay dos opciones:

1. Agrega `import Dates` y luego antepón `Dates.` a todas las llamadas a funciones.
2. Agrega `using Dates`, que trae todo el módulo al espacio de nombres actual (_excepto por algunos nombres problemáticos_).

```julia-repl
# option 1
julia> import Dates

julia> Dates.now()
2025-06-21T16:02:39.080

julia> now()  # wrong: need to include `Dates.` after an import
ERROR: UndefVarError: `now` not defined in `Main`


# option 2
julia> using Dates

julia> now()  # functions are now in the namespace
2025-06-21T16:03:04.161
```

El módulo `Dates` es grande y complicado, pero ofrece cuatro áreas principales de funcionalidad:

- `Dates.Date`, que incluye día, mes y año, pero no la hora del día.
- `Dates.Time`, que incluye la hora del día, con resolución de nanosegundos, pero no la fecha.
- `Dates.DateTime`, que combina fecha y hora con resolución de milisegundos.
- `Dates.Period`, que maneja intervalos de tiempo y de fecha.

Ten en cuenta que un `DateTime` generalmente _no_ incluye información de zona horaria (en Python esto se llama una fecha y hora «naive»).
Una excepción es `now()`, que obtiene la hora local del reloj de tu sistema y puede convertirla a UTC si es necesario.

Otros cálculos de zona horaria necesitan el paquete `TimeZones.jl`, que no forma parte de una instalación predeterminada.
A partir de junio de 2025, esto no está disponible en Exercism, pero podría agregarse en el futuro.

Quizás las necesidades más frecuentes son:

- Parsear algún formato de entrada apropiado para construir un tipo de `Dates`.
- Obtener el formato numérico o de string requerido a partir de un tipo de `Dates`.
- Aplicar un desplazamiento a un valor `Date`, `Time` o `DateTime`.
- Calcular el intervalo entre dos de esos valores.
- Obtener la fecha actual (con `today()`) o la hora actual (con `now()`), o ambas.

~~~~exercism/note
Para reducir las distracciones visuales, la mayor parte del código de ejemplo en el resto de este documento asume `using Dates` y evita incluir el nombre del módulo `Dates.` en las llamadas a funciones.
~~~~

### Formatos de fecha y hora

Hay muchas maneras de escribir fechas y horas, y suelen depender de la cultura.
Las fechas solo con números, como «7/6/23», son ambiguas, confusas y han provocado muchos errores costosos en organizaciones multinacionales (_el autor lo dice por amarga experiencia personal_).

El estándar internacional se define en [`ISO 8601`][ISO8601], y tiene dos ventajas principales:

- El parseo es rápido e inequívoco.
- Ordenar es fácil, ya que la fecha y hora se puede tratar como texto normal y ordenar alfabéticamente.

En un ejemplo anterior vimos que `Date.now()` devolvía `2025-06-21T16:03:04.161`.

Se compone de varias partes:

- `YYYY-MM-DD` para la parte de la fecha.
- `hh:mm:ss` para la parte de la hora.
- Opcionalmente, milisegundos (o una unidad aún más pequeña) después del punto decimal.

Otros formatos de string se tratarán en una sección posterior.

## Dates

`Dates.Date` es un tipo relativamente simple que solo representa fechas, sin ningún conocimiento de horas ni de zonas horarias.

```julia-repl
# constructor with year, month, day arguments
julia> date1 = Date(2025, 06, 23)
2025-06-23

# constructor with ISO 8601 string
julia> date2 = Date("2025-06-23")
2025-06-23

julia> date1 == date2
true

julia> typeof(date1)
Date
```

Hay funciones de acceso para cada parte individual de la fecha, y vienen en pares que se distinguen por el uso de mayúsculas o minúsculas.

```julia-repl
# lowercase returns an integer
julia> month(date1)
6

julia> typeof(month(date1))
Int64

# Propercase returns a Period type
julia> Month(date1)
6 months

julia> typeof(Month(date1))
Month

# various compound methods are also available, returning a tuple
julia> monthday(date1)
(6, 23)
```

### Funciones de consulta

Hay una variedad de [funciones de consulta][query-func] que entienden algo del calendario.
El siguiente ejemplo muestra solo algunas.

```julia-repl
julia> date1
2025-06-23

julia> dayofweek(date1) # 1 = Monday, 7 = Sunday
1

julia> dayname(date1)
"Monday"

julia> daysinmonth(date1)
30

julia> isleapyear(date1)
false

julia> lastdayofmonth(date1)
2025-06-30
```

## Times

`Dates.Time` es el tipo básico que solo representa horas.
No tiene noción de las fechas: las horas vuelven automáticamente a `Time(0, 0, 0)` a la medianoche.

El formato completo del constructor es `Time(hour, min, sec, millisec, microsec)` o el equivalente en ISO 8601.

Todos los parámetros son opcionales y tienen `0` como valor predeterminado.

```julia-repl
julia> Time(14, 57, 25, 142)
14:57:25.142

julia> Time(14, 57, 25, 142, 32)`
14:57:25.142032

julia> Time("14:57:25.142")
14:57:25.142
```

Al igual que con `Date`, las partes individuales están disponibles mediante funciones de acceso:

```julia-repl
julia> minute(t) # => integer
57

julia> Minute(t) # => Period
57 minutes
```

## DateTimes

`Dates.DateTime` combina la mayoría de las características de los tipos `Date` y `Time`.

Es la más versátil de estas tres clases, aunque la resolución de tiempo se limita a milisegundos (`Time` puede llegar a los nanosegundos).

```julia-repl
julia> dt1 = DateTime(2025, 6, 23, 14, 57, 25, 142)
2025-06-23T14:57:25.142

# date1 and t were defined in previous examples
julia> dt2 = DateTime(date1, t)
2025-06-23T14:57:25.142
```

Los parámetros de año, mes y día tienen `1` como valor predeterminado, y todos los parámetros de hora tienen `0`.

Mantener el orden correcto de todos estos parámetros puede ser todo un desafío, así que quizás sea preferible el formato ISO.

Como alternativa, un `DateTime` se puede construir a partir de un `Date` y un `Time`, como en el ejemplo anterior.

## Periods

Cada uno de los componentes de fecha y hora tiene su propio tipo [`Period`][period], desde `Year` hasta `Nanosecond`, que representa un intervalo de tiempo.
Resultan especialmente útiles para la aritmética.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Year(21)
21 years

julia> Second(61)
61 seconds

julia> dt1 + Year(21) - Second(61)
2046-06-23T14:56:24.142

julia> Date(2025, 07, 03) - Date(2025, 04, 25)
69 days
```

También existe un tipo [`CompoundPeriod`][compound-period], que puede combinar varios tipos `Period`.
Curiosamente, por ahora necesita el nombre del módulo para evitar un error de espacio de nombres (_lo que parece un bug_).

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> offset = Dates.CompoundPeriod(Year(21), Second(-61))
21 years, -61 seconds

julia> dt1 + offset
2046-06-23T14:56:24.142
```

Al restar fechas u horas, el período se expresa en días (para las fechas) o en nanosegundos (para las horas).
Puede resultar útil usar [`canonicalize`][canonicalize] para convertirlos en un `CompoundPeriod`.

```julia-repl
julia> diff = Time(23, 14, 00) - Time(1, 23, 52)
78608000000000 nanoseconds

julia> canonicalize(diff)
21 hours, 50 minutes, 8 seconds

julia> typeof(canonicalize(diff))
Dates.CompoundPeriod
```

Cuando se trabaja con tipos `Period`, Julia intenta ser inteligente con las irregularidades del calendario, como la duración de los meses, y redondea según sea necesario.

```julia-repl
# February has fewer days than January
julia> Date(2025, 1, 31) + Month(1) 
2025-02-28
```

## [Redondeo][rounding]

Las funciones `floor`, `ceil` y `round` te resultarán familiares de los números enteros y de punto flotante, pero también funcionan con fechas y horas.
Especifica el `Period` al que quieres redondear como segundo argumento.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> floor(dt1, Minute(15))
2025-06-23T14:45:00

julia> ceil(dt1, Minute(30))
2025-06-23T15:00:00

julia> ceil(dt1, Month(1))
2025-07-01T00:00:00
```

## Representaciones en string

Mencionamos antes el estándar ISO 8601, que es la representación predeterminada de fecha y hora en Julia al formatear o parsear strings.

Es obvio que se usan con frecuencia muchos otros formatos, a menudo ligados a una cultura.
Para manejarlos, Julia tiene el tipo `DateFormat`, que se puede construir a partir de un string de formato de complejidad arbitraria.

```julia-repl
# dateformat"" string syntax
julia> dtfmt = dateformat"d/m/y"
dateformat"d/m/y"

julia> typeof(dtfmt)
DateFormat{Symbol("d/m/y"), Tuple{Dates.DatePart{'d'}, Dates.Delim{Char, 1}, Dates.DatePart{'m'}, Dates.Delim{Char, 1}, Dates.DatePart{'y'}}}

# DateFormat constructor
julia> DateFormat("d/m/y")
dateformat"d/m/y"
```

El ejemplo anterior es muy simple: solo una fecha en el formato día/mes/año común en Europa.
Se muestran dos variantes de la sintaxis, pero el resultado es idéntico.

Luego, un `DateFormat` se puede usar para parsear cualquier string adecuado:

```julia-repl
julia> DateTime("14/7/2023", dtfmt)
2023-07-14T00:00:00
```

Crear un `DateFormat` implica un costo considerable, así que hacer este paso una sola vez (como aquí con `dtfmt`) ayuda al rendimiento cuando se itera sobre muchos strings de fecha y hora.

Los formatos pueden ser mucho más complejos que esto, así que consulta el [manual][dateformat] para más detalles.

Quien esté familiarizado con otros lenguajes quizás note un parecido con las funciones `strptime` y `strftime`, que existen desde hace décadas.
La versión de Julia toma prestado de ese legado, pero busca ser más concisa y flexible.

El mismo `DateFormat` también se puede usar para producir una fecha y hora con el formato de string que quieras, mediante la función [`Dates.format()`][format].

Lamentablemente, parece haber un conflicto de espacio de nombres con `format` (al menos en Julia 1.11.5), así que lo mejor es incluir el prefijo `Dates.` incluso después de `using Dates`.

```julia-repl
julia> dt1
2025-06-23T14:57:25.142

julia> Dates.format(dt1, dateformat"e, u d")
"Mon, Jun 23"
```

Como se [documenta][wiki-format], `"e, u d"` da la representación de texto abreviada del día de la semana y del mes.

La representación de texto es en inglés de forma predeterminada.
Se pueden agregar otros idiomas, aunque por ahora el soporte para esto no es óptimo.
