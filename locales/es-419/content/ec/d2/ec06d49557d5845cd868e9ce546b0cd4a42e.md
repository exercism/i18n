# Acerca de

La E/S de Factor se basa en un único [protocolo][stream-protocol] que cualquier fuente o destino de datos puede implementar. Los streams incluidos (`<file-reader>`, `<file-writer>`, `<string-reader>`, `<string-writer>`, sockets de red, arrays de bytes, ttys) son todos clases que implementan el mismo puñado de genéricos de [`io`][io] y extienden `disposable` de [`destructors`][destructors].

```factor
USING: io ;

GENERIC: stream-read1        ( stream -- elt/f )
GENERIC: stream-read-unsafe  ( n buf stream -- count )
GENERIC: stream-write1       ( elt stream -- )
GENERIC: stream-write        ( seq stream -- )
GENERIC: stream-flush        ( stream -- )
GENERIC: stream-element-type ( stream -- type )
```

`stream-read-unsafe` es la lectura por lotes de bajo nivel: llena un búfer que proporciona quien llama y devuelve cuántos elementos se escribieron. Los públicos `stream-read` y `stream-read-partial` se construyen sobre él y se encargan de la asignación de memoria. La mayoría de los streams definidos por el usuario implementan `stream-read1` (cuando las lecturas ocurren de a un elemento a la vez) o `stream-read-unsafe` (cuando las lecturas se pueden agrupar por lotes).

`stream-element-type` devuelve uno de dos tokens singleton: `+byte+` para streams de bytes (lectores de archivos, sockets) y `+character+` para streams de caracteres (lectores de string, ttys). Un stream envoltorio normalmente solo delega en el stream subyacente.

## Unirse a los mixins

```factor
INSTANCE: my-stream input-stream
INSTANCE: my-stream output-stream
```

Una clase puede ser uno, el otro, o ambos. Unirse al mixin hace que los métodos predeterminados de `input-stream` / `output-stream` se despachen a tu clase: el mismo patrón de mixin abierto que `set` del vocabulario `sets`.

## El framework disposable

`new-disposable ( class -- disposable )` registra una instancia nueva en el ámbito de destructores actual para que una excepción en medio de la preparación de recursos se desmonte de forma limpia:

```factor
USING: destructors ;

[
    "log.txt" utf8 <file-writer>   ! registered automatically
    "log.txt" utf8 <file-reader>   ! and so is this one
    ! ... use them ...
] with-destructors
! both files closed even if an error is thrown above
```

`dispose` es la palabra pública; `dispose*` es el genérico que implementa la clase. Una sobrescritura de `dispose*` en una subclase debe limpiar su propio estado y después liberar los recursos que posee:

```factor
M: my-stream dispose* underlying>> dispose ;
```

El framework garantiza que `dispose*` se ejecuta como máximo una vez por objeto: las llamadas repetidas a `dispose` no hacen nada.

## Accesores con ámbito

Tres combinadores configuran el «stream de entrada/salida actual» global que usan `print`, `read1`, etc.:

```
with-input-stream   ( stream quot -- )    ! reads in quot use stream
with-output-stream  ( stream quot -- )    ! writes in quot use stream
with-disposal       ( disposable quot -- )! generic — any disposable
```

Cada uno libera el recurso al salir, incluso si la cita lanza una excepción. Así es como la mayoría del código usa un stream personalizado, en lugar de pasarlo por todas las llamadas.
