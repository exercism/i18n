# Acerca de

En Elixir, todo el código se ejecuta dentro de procesos. Los procesos de Elixir:

- No deben confundirse con los procesos del sistema.
- Son ligeros.
- Tienen casos de uso específicos. Pueden:
  - [Mantener estado global][getting-started-processes-state].
  - [Contener fallos][getting-started-processes-links].
  - Permitir código concurrente y asíncrono.
- Es normal tener una aplicación de Elixir que ejecuta _cientos_ de procesos, pero también una que no crea procesos nuevos de forma explícita, sobre todo si es una biblioteca.

## Crear procesos

De forma predeterminada, una función se ejecuta en el mismo proceso desde el cual fue llamada. Cuando necesitas ejecutar explícitamente una función determinada en un proceso nuevo, usa `spawn`:

- [`spawn/1`][kernel-spawn-1] acepta una función que ejecutará directamente.

  ```elixir
  spawn(fn -> 2 + 2 end)
  # => #PID<0.125.0>
  ```

- [`spawn/3`][kernel-spawn-3] acepta una función que ejecutará por el nombre del módulo, el nombre de la función (como átomo) y una lista de argumentos que se pasan a esa función.

  ```elixir
  spawn(String, :split, ["hello there", " "])
  # => #PID<0.113.0>
  ```

  - A este trío de datos se le suele llamar _MFA_: _Module, Function, Arguments_.

- Un proceso termina en cuanto su función ha terminado de ejecutarse.

- Puedes comprobar si un proceso sigue _vivo_ (ejecutándose) con [`Process.alive?/1`][process-alive]:

  ```elixir
  pid = spawn(fn -> 2 + 2 end)
  Process.alive?(pid)
  # => false
  ```

## Mensajes

Los procesos no comparten información directamente entre sí. Los procesos _envían mensajes_ para compartir datos. Este patrón de concurrencia se llama el [modelo de actores][wiki-actor-model].

- Envía mensajes a un proceso con [`send/2`][kernel-send].

  ```elixir
  send(pid, :hello)
  ```

  - El mensaje termina en el _buzón_ del destinatario en el orden en que se envían.
  - `send` no comprueba si el mensaje fue recibido ni si el destinatario sigue vivo.

- Un mensaje puede ser de cualquier tipo.
- Puedes recibir un mensaje enviado al proceso actual con [`receive/1`][kernel-receive].

  - Necesitas hacer coincidencia de patrones con los mensajes.
  - `receive` espera hasta que un mensaje que coincida con alguno de los patrones dados esté en el buzón del proceso.
    - De forma predeterminada, espera indefinidamente, pero se le puede dar un tiempo límite con un bloque `after`.
  - Los mensajes leídos se eliminan del buzón del proceso. Los mensajes no leídos se quedan ahí indefinidamente.
    - Escribe siempre una cláusula `_` que capture todo en `receive/1` para evitar quedarte sin memoria por la acumulación de mensajes no leídos.

  ```elixir
  receive do
    {:ping, sender_pid} -> send(sender_pid, :pong)
    _ -> nil
  after
    5000 ->
      {:error, "No message in 5 seconds"}
  end
  ```

## Bucle de recepción

Si quieres recibir más de un mensaje, necesitas llamar a `receive/1` de forma recursiva. Es un patrón común implementar una función recursiva, por ejemplo llamada `loop`, que llama a `receive/1`, hace algo con el mensaje y luego se llama a sí misma para esperar más mensajes. Si necesitas llevar algún estado de una llamada a `receive/1` a otra, puedes hacerlo pasando un argumento a esa función `loop`.

```elixir
def loop(state) do
  receive do
    :increment_by_one ->
      loop(state + 1)

    {:report_state, sender_pid} ->
      send(sender_pid, state)
      loop(state)

    :stop ->
      nil

    _ ->
      loop(state)
  end
end
```

En la práctica, este enfoque rara vez se usa directamente. Elixir ofrece abstracciones de concurrencia, como el [módulo `Agent`][agent] o el [comportamiento `GenServer`][genserver], que se construyen sobre el bucle de recepción. Sin embargo, es fundamental entender esas bases para poder usar las abstracciones de forma eficiente.
