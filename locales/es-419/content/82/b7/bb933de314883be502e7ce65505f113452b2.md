# Instrucciones

En este ejercicio, procesarás mensajes de registro con seis niveles de gravedad.

Cada línea de registro es un string con el siguiente formato: `"[<LVL>]: <MESSAGE>"`.

Estos son los distintos niveles de registro:

| NIVEL     | LVL   |
| --------- | ----- |
| `Trace`   | `TRC` |
| `Debug`   | `DBG` |
| `Info`    | `INF` |
| `Warning` | `WRN` |
| `Error`   | `ERR` |
| `Fatal`   | `FTL` |

## 1. Analiza el nivel de registro

Define un enum `LogLevel` que tenga seis elementos correspondientes a los niveles de registro definidos arriba.
Luego, define la función `parse_log_level`, que recibe el mensaje de registro como parámetro y devuelve el miembro del enum correspondiente a su nivel.

```python
parse_log_level("[INF]: File deleted")
#=> LogLevel.Info
```

## 2. Admite niveles de registro desconocidos

Lamentablemente, de vez en cuando aparecen mensajes de registro con una gravedad _desconocida_. Para manejar con elegancia estos mensajes de registro «misteriosos» en la función `parse_log_level`, agrega un miembro `Unknown` al enum `LogLevel`, que se devolverá cuando se analice un nivel de registro desconocido:

```python
parse_log_level("[XYZ]: Overly specific, out of context message")
#=> LogLevel.Unknown
```

## 3. Convierte un mensaje de registro al formato corto

El nivel de registro de una línea de registro es bastante verboso. Para reducir el espacio en disco necesario para almacenar los mensajes de registro, se define un formato corto: `"[<CODE_LEVEL>]:<MESSAGE>"`.

Los códigos de nivel de registro siguen una correspondencia directa:

| NIVEL     | CÓDIGO |
| --------- | ---- |
| `Trace`   | `0`  |
| `Debug`   | `1`  |
| `Info`    | `4`  |
| `Warning` | `5`  |
| `Error`   | `6`  |
| `Fatal`   | `7`  |
| `Unknown` | `42` |

Define la función `convert_to_short_log()`, que recibe dos parámetros:

1. Nivel de registro: el nivel de registro del mensaje enviado. Ej.: `LogLevel.Error`.
2. Mensaje de registro: el mensaje de tipo `str`.

```python
convert_to_short_log(LogLevel.Error, "Stack overflow")
# => "6:Stack overflow"
```

## 4. Crea un alias

Parece que el usuario creó logs para `LogLevel.Warn` en lugar de `LogLevel.Warning`. Crea un `alias` para `LogLevel.Warning` y devuelve el nuevo miembro alias en la función `get_warn_alias`.

Esto se puede hacer en la misma clase enum `LogLevel` que ya está definida al inicio del archivo. Ambos miembros de LogLevel deben apuntar al mismo valor: `"WRN"`.

```python
get_warn_alias()
#=> LogLevel.Warn

get_warn_alias() == LogLevel.Warning
#=> True
```

## 5. Todos los nombres y valores de los miembros

Define la función `get_members()`.

Esta función debe devolver una lista de tuplas `(name, value)` que contenga todos los miembros del enum `LogLevel`.

```python
get_members()
```
