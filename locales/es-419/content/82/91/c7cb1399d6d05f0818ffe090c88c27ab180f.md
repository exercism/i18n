# Acerca de

Las [comprensiones][for] ofrecen un mecanismo para transformar _enumerables_ de forma fácil y declarativa. Son _azúcar sintáctico_ para iterar a través de enumerables en Elixir.

[//]: # (elixir-formatter-disable-next-block)

```elixir
for s <- ["a", "b", "hello", "c"], # 1. generator
  String.length(s) == 1,           # 2. filter
  into: "",                        # 3. collectable
  do: String.upcase(s)

# => "ABC"
```

Una comprensión tiene tres partes:

1. _generadores_:
   - Valores enumerados a partir de estructuras que implementan el protocolo [_Enumerable_][enumerable].
   - Expresiones de coincidencia de patrones para desestructurar los valores enumerados.
2. _filtros_: condiciones booleanas, que se usan para seleccionar qué valores enumerados usar al crear los nuevos valores.
3. _coleccionables_: una estructura que implementa el protocolo [_Collectable_][collectable], que se usa para recolectar los nuevos valores.

Hay comprensiones de una sola línea y de varias líneas. Cuando se usa más de un generador, se enumera un [producto cartesiano][cartesian-product] de los valores generados. Eso significa que cada valor generado por el primer generador se emparejará una vez con cada valor generado por el segundo generador.

```elixir
for n <- [0, 1, 2, 3], do: n + 1
# => [1, 2, 3, 4]

for x <- [0, 1],
    y <- [0, 1] do
  {x, y}
end

# => [{0, 0}, {0, 1}, {1, 0}, {1, 1}]
```

El valor del bloque do se inserta en el _coleccionable_ **por cada valor generado** a partir del _enumerable_.

```elixir
for _ <- [1, 2, 3], do: :a
# => [:a, :a, :a]
```

La coincidencia de patrones puede ocurrir en la comprensión, ya sea en el lado izquierdo de `<-` o en su propia línea.

```elixir
for {atom, str} <- [a: "string"], do: str
# => ["string"]

for pair <- [a: "string"],
    {atom, str} = pair do
  str
end

# => ["string"]
```
