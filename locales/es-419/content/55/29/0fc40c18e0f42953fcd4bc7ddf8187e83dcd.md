# Acerca de

## Representación, caracteres y enteros

Al igual que otros tipos simples (`int`s, `bool`s, etc.), el `char` tiene un tipo acompañante o un alias, en este caso, `System.Char`.

De hecho, es un `struct` con un campo de 16 bits y es inmutable por defecto.

`char` tiene algunos métodos de instancia como `Equals`, `ToString` y [`CompareTo`][compare-to].

`char` tiene el mismo ancho que un [`ushort`][uint16], pero por lo general no se usan de forma intercambiable como ocurre en algunos lenguajes. `ushort` tiene que convertirse explícitamente a `char`.

Por si acaso, los `char` pueden ser objeto de operaciones aritméticas. El resultado de estas operaciones es un entero.

Obviamente, no hay equivalencia entre un `byte` de 8 bits y el `char` de 16 bits.

## Uso

Los `char` son, por lo general, fáciles de usar.

Se pueden definir como literales con comillas simples:

```fsharp
let ch = 'A'
// => val ch: char = 'A'
```

Un `char` individual se puede obtener de un string con indexación (base cero):

```fsharp
let str = "Exercism" 
// => val str: string = "Exercism"

str[4]
// => val it: char = 'c'
```

Iterar sobre un string devuelve un `char` en cada paso:

```fsharp
[| for c in "F#" -> c, int c |]
// => val it: (char * int) array = [|('F', 70); ('#', 35)|]
```

Como se muestra arriba, un `char` se puede convertir a su valor `int`.
Esto también funciona (*al menos algunas veces*) para otros sistemas de escritura:

```fsharp
[| for c in "東京" -> c, int c |] // Tokyo, if Wikipedia is to be believed
// => val it: (char * int) array = [|('東', 26481); ('京', 20140)|]
```

El Int16 subyacente se usa al comparar caracteres:

```fsharp
'A' < 'D'
// => val it: bool = true
```

Además, un `int` se puede convertir a `char`:

```fsharp
char 77
// => val it: char = 'M'
```

La biblioteca `System.Char` contiene el conjunto completo de [métodos][Char-methods] que se esperan de un lenguaje .NET, como las conversiones a mayúsculas o minúsculas (pero revisa las advertencias de la siguiente sección):

```fsharp
'a' |> System.Char.ToUpper
// => val it: char = 'A'

'Q' |> System.Char.ToLower
// => val it: char = 'q'
```

Las bibliotecas de .NET ayudan a extraer `char` de los strings, en este caso con métodos de `Seq`:

```fsharp
"Exercism" |> Seq.toList
// => val it: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

"Zürich" |> Seq.toArray
// => val it: char array = [|'Z'; 'ü'; 'r'; 'i'; 'c'; 'h'|]
```

Hay varias formas de convertir una lista (o un array) de caracteres a un string, entre ellas estas:

```fsharp
let s = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']
// => val s: char list = ['E'; 'x'; 'e'; 'r'; 'c'; 'i'; 's'; 'm']

// with a .NET method
System.String.Concat s
// => val it: string = "Exercism"

// with String.concat
String.concat "" <| List.map string s
// => val it: string = "Exercism"

// with a string constructor
new string [|for c in s -> c|]
// => val it: string = "Exercism"

// with StringBuilder
open System.Text
string (List.fold (fun (sb:StringBuilder) (c:char) -> sb.Append(c)) 
                      (new StringBuilder())
                       s)
// => val it: string = "Exercism"
```

Aquí puedes encontrar información general sobre los `char`:

- [Documentación de Chars][chars-docs]: documentación de referencia para `char`.

Sin embargo, los `char` tienen varias asperezas, como se detalla a continuación. Estas asperezas tienen que ver, sobre todo, con la oposición entre el estándar unicode completo, por un lado, y las representaciones históricas del texto, así como el rendimiento y el uso de memoria, por el otro.

## Problemas con Unicode

Cuando trabajes con strings, si hay métodos de la biblioteca [`System.String`][System-string] disponibles, búscalos y úsalos en lugar de descomponer el string en caracteres.

Algunos «caracteres» textuales constan de más de un `char` porque el estándar unicode tiene más de 65536 puntos de código. Por ejemplo, los emojis que aparecen en algunas de las pruebas tienen 2 `char`, ya que están formados por caracteres [subrogados][surrogates].

Además, existen secuencias de combinación, por ejemplo, cuando en algunos casos un carácter acentuado puede constar de un `char` para el carácter simple y otro `char` para el acento.

Si tienes que trabajar con caracteres individuales, intenta usar métodos de biblioteca como [`System.Char.IsControl`][is-control], [`System.Char.IsDigit`][is-digit] en lugar de hacer comparaciones ingenuas, como comprobar que un carácter está entre '0' y '9'.

Por ejemplo, fíjate que '٢' es el dígito árabe 2. `IsDigit` devolverá true para la versión árabe, así que, por ejemplo, al validar necesitas tener claro qué rango de argumentos es aceptable.

Incluso los métodos de la biblioteca `System.Char` pueden no comportarse como esperarías cuando trabajas con idiomas menos conocidos.

Una forma segura de dividir un string en «caracteres» de visualización es usar [`StringInfo`][string-info] y métodos como [`GetNexttextElement`][get-next-text-element].
Esto puede ser necesario si trabajas con globalización o localización.

Otra opción en la que importan los valores escalares de los caracteres unicode (por ejemplo, si estás creando tu propio sistema de codificación) es usar [runes][runes]. Sin embargo, si sabes que el rango de caracteres con el que trabajas no incluye subrogados ni secuencias de caracteres combinados (por ejemplo, ASCII latino) y tus argumentos están bien validados, puedes evitarlo.

De nuevo, la mejor situación es aquella en la que puedes usar los métodos de biblioteca de `String`.

Si terminas en la poco envidiable posición de tener que lidiar con las minucias de unicode, [esto][char-encoding-net] es un buen punto de partida.

## Globalización

Si trabajas en un entorno en el que tratas con varias culturas, o la cultura es importante en algunas partes del código pero no en otras, ten en cuenta las sobrecargas de [`ToUpper`][to-upper] y [`ToLower`][to-lower] que reciben una cultura, y [`ToUpperInvariant`][to-upper-invariant] y [`ToLowerInvariant`][to-lower-invariant], que proporcionarán un resultado consistente independientemente de la [cultura][culture-info] actual.
