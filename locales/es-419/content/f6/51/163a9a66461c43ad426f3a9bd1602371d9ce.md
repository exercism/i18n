# Conceptos básicos de Unison

## Términos y funciones

Los términos y las funciones son las unidades básicas para escribir un programa en Unison.

Un «término» es lo que llamamos un valor estático. Se define con `name = expression`, opcionalmente precedido por una firma de tipo con la forma `name : MyType`. Unison admite la inferencia de tipos, así que es posible que veas la firma de tipo omitida en definiciones simples.

```
myTerm = 42

helloThere : Text
helloThere = "Hello, World!"
```

Las funciones de Unison tienen la forma `myFunctionName argument1 argument2 = myImplementation`; empiezan con el nombre de la función seguido de argumentos separados por espacios.

```
getMax a b = Nat.max a b
```

Las funciones pueden incluir opcionalmente una firma de tipo. El último tipo a la derecha es siempre el tipo de retorno final de la función, y cada argumento se separa con la flecha de función `->`.

```
{{getMax accepts two arguments of type Nat and its return type is a Nat}}
getMax : Nat -> Nat -> Nat
getMax a b = Nat.max a b
```

Para llamar a una función, usa su nombre seguido de sus argumentos separados solo por espacios.

```
maximum = getMax 1 10

> maximum
  ⧩
  10
```

Cuando llamas a una función, Unison intentará tratar lo que esté inmediatamente a la derecha como su argumento, lo que no siempre produce el orden de evaluación de funciones que deseas.

Supongamos que queremos obtener el valor `1` de la siguiente expresión

```
shouldBe1 = getMax 1 10 - 10

> shouldBe1
  ⧩
  0
```

Tal como está escrita, `shouldBe1` se evalúa como `0` porque el orden implícito de aplicación de funciones es `getMax 1 10`, que da `10`, y luego `10 - 10`, que da `0`.

Puedes usar paréntesis para reagrupar la expresión en el orden de operaciones que desees.

```
shouldBe1 = getMax 1 (10 - 10)

shouldBe1
  ⧩
  1
```

## Expresiones de observación

Unison ofrece una forma de evaluar código rápidamente llamada «expresión de observación». Una expresión de observación empieza con el símbolo `>` y va seguida de la expresión que se va a evaluar. Las expresiones de observación se pueden escribir en cualquier archivo con la extensión `.u`. Al guardar el archivo, verás el resultado de la expresión en la consola del Unison Codebase Manager (UCM). Siempre que sea posible en esta documentación, mostraremos una expresión junto con el resultado esperado después de evaluarla en una expresión de observación.

```
> helloThere
  ⧩
  "Hello, World!"
```

## Funciones de varias líneas

Las funciones de varias líneas en Unison usan la indentación o bloques `let` para especificar los límites del código, también conocido como «ámbito léxico».

```
swapOrder : Text -> Text -> Text -> Text
swapOrder beg middle end =
  newBeginning = end ++ middle
  newBeginning ++ beg
```

Todo lo que está en el mismo nivel de indentación comparte el mismo ámbito, y por eso podemos hacer referencia a la variable `newBeginning` en la última línea.

## Espacios de nombres y sentencias `use`

Los espacios de nombres son la forma en que agrupamos y organizamos las funciones de Unison. Puedes pensar en ellos como algo análogo a los «directorios». Aportan estructura y agrupación lógica.

Puedes traer las funciones de un espacio de nombres al ámbito con una sentencia `use`.

Supongamos que estás escribiendo una función que usa valores `List` de Unison. Sabes que vas a necesitar funciones como `List.map` y `List.flatMap`, donde `List` es el espacio de nombres y `map` y `flatMap` son funciones. Para no repetirte, puedes optar por traer todo del espacio de nombres `List` al ámbito léxico de tu función así:

```
listProcessing: [Nat] -> [Text]
listProcessing nats =
  use List
  map Nat.toText nats |>
  flatMap (fill 2)
```

La línea `use List` desambigua las referencias a `map` y `flatMap`. Puedes leer más sobre las [sentencias `use` aquí][use-statements].

## La biblioteca estándar de Unison

La biblioteca estándar de Unison se llama `base`. Si seguiste la guía de inicio rápido y tienes una base de código creada localmente, la biblioteca estándar debería haberse descargado automáticamente. Puedes explorar la documentación de la biblioteca estándar en línea en [Unison Share][unison-share-base].

## Comentarios y literales de documentación

Los comentarios en Unison son una característica un poco inusual. Cuando escribes código en Unison, puedes crear texto en tu archivo con la extensión `.u` que no se interpreta, con la siguiente sintaxis:

```
-- a single line comment
-- another single line comment

{-
  a multiline comment
  spanning multiple lines
-}
```

_Sin embargo_, como el código de Unison se guarda como un hash de su árbol de sintaxis abstracta y no como archivos de texto en el sistema de archivos, los comentarios que son «decoraciones» de texto de una función o un término de Unison en el archivo no se pueden guardar ni volver a mostrar realmente para compartirlos. Si quieres agregar información a tu término de Unison de una forma que se guarde para que otras personas la lean y la entiendan, puedes usar un literal de documentación.

La documentación es un valor de primera clase en el lenguaje de programación Unison. Eso significa que un elemento `Doc` se puede asignar a un valor, pasar como valor a una función o devolver como valor de una función. Los elementos de literal de documentación se abren y cierran con llaves dobles. Así es como podríamos usar el elemento `Doc` como comentario.

```
myFunction: Nat -> Boolean
myFunction n =

  {{ when n is `4` we have a special important business logic exception}}

  if n === 4 then true
  else
    if isEven n then false
    else true
```
