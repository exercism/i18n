# Acerca de

Factor divide la E/S de flujos en dos capas. La capa inferior es la
API de *flujo explícito*: cada palabra recibe el flujo como
argumento. La capa superior es la API de *flujo ambiente*: palabras
cortas, de una sola línea, que actúan sobre el flujo que esté vinculado
en ese momento. Ambas capas se apoyan en el mismo [protocolo][stream-protocol]; las palabras de la capa superior
solo buscan el flujo ambiente y reenvían la llamada.

## Palabras de flujo explícito

```
stream-read       ( n stream -- seq/f )
stream-read1      ( stream -- elt/f )
stream-readln     ( stream -- str/f )
stream-write      ( seq stream -- )
stream-write1     ( elt stream -- )
stream-print      ( str stream -- )
stream-flush      ( stream -- )
stream-contents   ( stream -- seq )
stream-lines      ( stream -- seq )
```

`stream-contents` consume todo; `stream-lines` consume y
divide en los límites de línea; `stream-readln` devuelve una línea a
la vez (o `f` al llegar al final del flujo).

## Palabras de flujo ambiente

```
read1   ( -- elt/f )
read    ( n -- seq/f )
readln  ( -- str/f )
write   ( seq -- )
write1  ( elt -- )
print   ( str -- )
flush   ( -- )
```

Estas son las palabras de E/S del día a día. Buscan el flujo de
entrada o de salida actual en las variables dinámicas
`input-stream` / `output-stream` y reenvían. Por eso,
redirigir `print` a un string es solo cuestión de vincular
`output-stream` mientras dura una quotation.

## Constructores de flujos incluidos

| palabra           | vocabulario         | qué construye                   |
|-------------------|----------------------|---------------------------------|
| `<string-reader>` | [`io.streams.string`][io.streams.string]  | lee un string literal           |
| `<string-writer>` | [`io.streams.string`][io.streams.string]  | recoge lo escrito en un string  |
| `<file-reader>`   | [`io.files`][io.files]           | lee un archivo con una codificación   |
| `<file-writer>`   | [`io.files`][io.files]           | escribe un archivo con una codificación  |

Los cuatro producen objetos desechables: extienden `disposable` de
`destructors`, así que los combinadores `with-…` de abajo los liberan
al salir.

## Vinculación de alcance

```
with-input-stream   ( stream quot -- )
with-output-stream  ( stream quot -- )
with-string-reader  ( str quot -- )
with-string-writer  ( quot -- str )
with-file-reader    ( path encoding quot -- )
with-file-writer    ( path encoding quot -- )
```

Cada una abre un flujo, lo vincula como la entrada o la salida
ambiente para la quotation interna y lo libera al salir, incluso
si la quotation lanza una excepción. Son los combinadores de
destructores de `boatswains-bilge`, especializados para flujos.

`with-string-writer` es una variante especialmente limpia:
construye automáticamente un `<string-writer>` nuevo, ejecuta la
quotation con ese writer como la salida ambiente y devuelve
el string acumulado. Todo el patrón de «capturar la salida de una
quotation» es una sola palabra.

```factor
USING: io io.streams.string ;

[ "alpha" print "bravo" print ] with-string-writer .
! => "alpha\nbravo\n"
```

## ¿Y por qué usar flujos ambiente?

La vinculación de variables dinámicas es la razón por la que `print`
funciona en un programa que no sabe si se está ejecutando de forma
interactiva, hacia un archivo de log o hacia un búfer de prueba
capturado. Cambia la vinculación una vez y cada palabra que llama a
`print` hará lo correcto, sin necesidad de recablear nada. Esa es la
inversión que te ofrece la capa superior.

Para *implementar* un flujo, es decir, definir tu propia clase que se
acopla al protocolo, consulta el concepto `streams` (que se enseña en
`telegraphers-tape`).
