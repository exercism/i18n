# Introducción a los fundamentos del shell

## Shells

Un _shell_ es un programa que te permite ingresar comandos para interactuar con el sistema operativo.
Los shells pueden ser gráficos; el entorno de escritorio que usas con el mouse o el trackpad es un shell.
Nos enfocaremos en las interfaces de línea de comandos, donde escribes comandos y los resultados se imprimen (por lo general) en tu terminal.

Existen muchos shells de línea de comandos diferentes.
Windows ofrece **cmd** y **powershell**.
Mac y Linux ofrecen «shells de Unix», de los cuales hay muchos.
El shell predeterminado de Mac es **zsh**.
**csh** es un shell heredado con sintaxis similar a C.
**bash** es uno de los shells más populares, sobre todo en Linux.

Uno de los primeros shells que existió es el Bourne shell, **sh**.
Con el tiempo, este shell se [estandarizó][posix] para estar disponible en todo sistema tipo Unix.
Muchos shells están basados en el Bourne shell y a menudo ofrecen funcionalidad interactiva o de programación adicional.

**Bash** está basado en el Bourne shell.
Por eso se llama «**B**ourne-**a**gain **sh**ell».
Es el shell predeterminado en muchos sistemas Linux.
Bash ofrece muchas facilidades que lo convierten en un shell interactivo agradable, entre ellas:

* un prompt totalmente personalizable,
* la capacidad de recuperar y modificar comandos del historial,
* la capacidad de manipular procesos en ejecución,
* alias que reducen lo que escribes,
* y más.

Este track no trata sobre cómo usar bash como shell interactivo.
Trata sobre aprender a escribir programas usando bash.
El énfasis estará en usar _solo_ bash para resolver problemas, aunque no hay restricciones para llamar a herramientas externas.

## Fundamentos de Bash: comandos y argumentos

Bash lee comandos de su entrada (que por lo general es una terminal o un archivo).
Cada línea de entrada que lee se trata como un _comando_: una instrucción que se debe llevar a cabo.
(Hay algunos casos avanzados, como los comandos que abarcan varias líneas, que veremos más adelante.)

Bash divide cada línea en **palabras** delimitadas por un carácter de espacio en blanco (espacios y tabulaciones).
La primera palabra de la línea es el nombre del _comando_ que se debe ejecutar.
Todas las palabras restantes se convierten en _argumentos_ de ese comando (opciones, nombres de archivo, etc.).

~~~~exercism/note
En los ejemplos a continuación, te mostraremos algunos comandos interactivos que puedes ejecutar.

* El carácter `#` inicia un _comentario_.
  Cualquier palabra que siga al comentario es ignorada por el shell; el comentario está pensado solo para leerse.
* El carácter `$` indica el prompt del shell. 
  Si vas a copiar el comando, no incluyas el prompt.
~~~~

```bash
# Note: It is always a good idea to run `ls` before `rm`
# to make sure you know what you are deleting.

$ rm *            # Remove all files in the current directory.
                  # Make sure you run this in a temp directory or you can lose files!
$ ls              # List files in the current directory (no output, no files).
$ touch a   b c   # Create files 'a', 'b' and 'c'.
$ ls              # List files again; this time the outputs: 'a', 'b' and 'c'.
a  b  c
```

`rm` es una aplicación que elimina los archivos que se le pasan.
`*` es un carácter [glob][glob], un patrón «comodín» que coincide con todos los archivos del directorio actual.
Hablaremos más sobre los globs más adelante.

¿Notaste que hay varios espacios entre `a` y `b`, y solo uno entre `b` y `c`?
¡La cantidad de espacios en blanco entre argumentos no importa!
Por ejemplo:

```bash
$ echo This is a test.
This is a test.
$ echo This    is    a    test.
This is a test.
```

`echo` es un comando que imprime sus argumentos en la salida estándar (que en nuestro caso es la terminal).
Bash divide el comando en cinco palabras e invoca el comando `echo` con cuatro argumentos.
Los espacios adicionales del segundo ejemplo no marcan ninguna diferencia.
`echo` no sabe cómo estaban distribuidos originalmente los espacios entre las palabras.

Si queremos conservar los espacios en blanco adicionales, debemos pasar la oración como un solo argumento.
Podemos lograrlo usando [comillas][Quotes]:

```bash
$ echo "This    is    a    test."
This    is    a    test.
```

Las comillas agrupan todo lo que está dentro de ellas en un _único argumento_.
El argumento es `This    is    a    test.`, incluidos esos caracteres de espacio específicos.
Ten en cuenta que las comillas no forman parte del argumento: bash las elimina antes de entregarle ese único argumento a `echo`.

Los argumentos se separan del nombre del comando y entre sí por un espacio en blanco.
Es importante recordarlo.
Por ejemplo, lo siguiente es incorrecto:

```bash
$ [-f file]
bash: [-f: command not found
```

Esto pretende comprobar la existencia de un archivo llamado `file`.
Es razonable suponer que los espacios en blanco alrededor de `[` y `]` no importan, pero `[` en realidad es un comando, y requiere que su último argumento sea `]`.
(Cubriremos el comando `[` con más detalle más adelante.)
Por lo tanto, debemos separar `[` de `-f` y `]` de `file`.
De lo contrario, bash pensará que estamos tratando de ejecutar un comando llamado `[-f` con un solo argumento `file]`.
El comando correcto separa todos los argumentos con espacios en blanco:

```bash
$ [ -f file ]
```

(Vemos a mucha gente que se confunde con este comportamiento; creen que `[...]` es «solo sintaxis» y que pueden omitir los espacios; `[` es un comando y los espacios en blanco son obligatorios.)

Si el nombre de nuestro archivo contiene espacios en blanco u otros caracteres especiales, también se debe entrecomillar:

```bash
$ [ -f "my file" ]
```

## Tipos de comandos

Bash entiende varios tipos diferentes de comandos: alias, funciones, comandos internos, palabras clave y ejecutables.
Todos son _comandos_ y todos actúan de manera muy similar.

De manera predeterminada, los alias solo están habilitados en shells interactivos, no en scripts de shell.
No los cubriremos aquí.

### Funciones

Una función contiene comandos de shell y se comporta de manera muy parecida a un pequeño script; incluso puede recibir argumentos y crear variables locales.
Cuando se llama a una función, se ejecutan los comandos que contiene.
Cubriremos las funciones en profundidad más adelante.

### Comandos internos

Bash tiene algunos comandos básicos incorporados, como: `cd` (cambiar de directorio), `echo` (escribir salida), etc.
Se pueden considerar como funciones que ya vienen incluidas.

### Palabras clave

Las palabras clave son como los comandos internos, con la diferencia principal de que las palabras clave en realidad son sintaxis de bash y pueden analizarse con reglas especiales.
Por ejemplo, `[` es un comando interno de bash, mientras que `[[` es una palabra clave de bash; ambos se usan para comprobar diversas condiciones.
Pero la palabra clave `[[` tiene algo de funcionalidad adicional.
Por ejemplo, proporciona el operador `=~`, que hace comprobaciones con expresiones regulares.

```bash
$ [[ "hello world" =~ e.*o ]]   # returns a "success" status
$ [ "hello world" =~ e.*o ]
bash: [: =~: binary operator expected
```

Los operadores de comparación de cadenas `<` y `>` son otro ejemplo de cómo las palabras clave analizan el código de manera diferente.
Dentro de `[[...]]`, estos operadores no necesitan ningún cuidado especial.

```bash
$ if [[ "$USER" < "n" ]]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```

Pero dentro de `[...]` debes entrecomillarlos o escaparlos para evitar que el shell los analice como operadores de redirección.

```bash
$ if [ "$USER" < "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => bash: n: No such file or directory

$ if [ "$USER" \< "n" ]; then
    echo "$USER is in the first half of the alphabet"
fi
# => glennj is in the first half of the alphabet
```


### Ejecutables

El último tipo de comando que bash puede ejecutar es un _ejecutable_.
Son archivos ejecutables (programas) en el sistema de archivos de tu computadora que puedes ejecutar.
(A los ejecutables también se les puede llamar _comandos externos_ o _aplicaciones_.)
Por lo general, los ejecutables se invocan escribiendo solo su nombre; normalmente no se necesita la ruta completa del archivo.
Esto es posible porque bash usa una variable predefinida que lo ayuda a encontrar la ubicación de los archivos ejecutables comunes.
Esta variable se llama `PATH`.
Es un conjunto de nombres de directorio separados por dos puntos (por ejemplo, `/usr/bin:/bin`). 
Cuando se especifica un comando (por ejemplo, `myprogram` o `ls`) sin una ruta de archivo (y no es un alias, una función, un comando interno ni una palabra clave), bash busca en los directorios de `PATH`.
Los directorios se buscan en orden, de izquierda a derecha, para ver si contienen un ejecutable con el nombre dado.

Si el ejecutable está fuera de una ruta conocida, será necesario especificar la ruta del archivo del ejecutable.
Para el ejecutable `myprogram` en el directorio actual, usa `./myprogram`; si está en el directorio `/opt/somedirectory`, usa `/opt/somedirectory/myprogram`.

Consejo: el comando `type` se puede usar para obtener detalles sobre el comando:

```bash
$ type rm
rm is hashed (/bin/rm)
# or it might return: `rm is /bin/rm`

$ type cd
cd is a shell builtin
```

## Scripts

Un _script_ es una secuencia de comandos guardada en un archivo.
Bash lee el archivo y procesa los comandos en orden.
Pasa al siguiente comando solo cuando el actual ha terminado.
La excepción es si un comando se ha especificado para ejecutarse de forma asíncrona (en segundo plano).
No te preocupes demasiado por este caso todavía; aprenderemos cómo funciona más adelante.

Cualquier ejemplo de línea de comandos de esta guía también se puede usar en un script.

Crear un script es fácil.
Empieza creando un archivo nuevo y coloca esto en la primera línea:

```bash
#!/bin/bash
```

Esta línea se llama _directiva de intérprete_ (también se le llama _hashbang_ o **_shebang_**).
Especifica que se debe usar `/bin/bash` como intérprete cuando el archivo se usa como ejecutable en un comando.
Cuando el kernel del sistema operativo ejecuta un _archivo no binario_, lee la primera línea del archivo.
Si la línea comienza con `#!`, el kernel usa la línea para determinar a qué intérprete enviar el archivo.
(También hay otras formas válidas de hacer esto; consulta más abajo.)
El `#!` debe estar al principio absoluto del archivo, sin espacios ni líneas en blanco antes.
Los comandos de nuestro script aparecerán en líneas separadas debajo de esta.

Consejo: en lugar de `#!/bin/bash`, puedes usar

```bash
#!/usr/bin/env bash
```

`env` busca en `$PATH` el ejecutable nombrado por su primer argumento (en este caso, «bash»).
Para una explicación más detallada de esta técnica y de en qué se diferencia del simple `#!/bin/bash`, consulta [esta pregunta en StackOverflow][env bash].

Por favor, no te dejes engañar por scripts o ejemplos de internet que usan `/bin/sh` como intérprete.
**¡`sh` no es `bash`!**
Bash en sí es un shell «compatible con sh», lo que significa que puede ejecutar la mayoría de los scripts de `sh` y comparte gran parte de la misma sintaxis.
Sin embargo, lo contrario no es cierto; algunas funcionalidades de bash se romperán o provocarán un comportamiento inesperado en `sh`.
De hecho, no existe un único shell `sh`.
Hay muchas implementaciones de shell que admiten la sintaxis de POSIX-sh.
Según tu sistema operativo, cuando ejecutas `sh` podrías estar ejecutando en realidad bash, ash, dash o algún otro shell.

Una vez creado el archivo del script, se puede ejecutar así:

```bash
$ bash myscript
```

En este ejemplo, ejecutamos el _comando_ `bash` y le decimos que lea el script que le pasamos como _argumento_.
Cuando lo hacemos así, la línea `#!` es solo un _comentario_.

Como alternativa, podemos dar a nuestros scripts permisos de ejecución.
Con este método podemos ejecutar el script como cualquier otro ejecutable en lugar de llamar a bash manualmente:

```bash
$ chmod +x myscript  # Mark the file as executable.
$ ./myscript         # Now, myscript can be executed directly
                     # instead of having to specify bash.
```

Cuando ejecutamos el comando de esta manera, el sistema operativo (SO) usa la línea `#!` para determinar qué intérprete usar para ejecutar tu script.
