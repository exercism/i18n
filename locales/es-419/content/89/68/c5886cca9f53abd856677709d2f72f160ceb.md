# Introducción

Como se explora en el concepto [`Nothingness`][concept-nothingness], R tiene varias formas de representar datos que están ausentes (`NULL`), que son desconocidos (`NA`) o que son matemáticamente inválidos (`NaN`, `Inf`).
En general, R intentará usarlas para señalar los problemas ahí mismo y continuar sin lanzar una excepción.

## `stop()`

Algunos problemas son demasiado fundamentales como para dejar que el programa continúe.
En este caso, usa `stop(msg)` para detener el programa de inmediato con un `Error` e imprimir `msg`.

```R
f <- function() {
    stop("I have a problem")
}
f()
#> Error in f() : I have a problem
```

## `stopifnot()`

Similar a un `assert` en otros lenguajes, esta es una envoltura conveniente para `stop()`.
Sus parámetros son una cantidad arbitraria de condiciones booleanas separadas por comas, y el programa solo continuará si todas son `TRUE`.

```R
stopifnot(1 < 2) # continues OK
stopifnot(1 < 2, 1 == 2)
#> Error: 1 == 2 is not TRUE
```

## `warning()` y `message()`

Estas son respuestas a condiciones no fatales, por ejemplo:

- Advertir de un problema del que el programa podría recuperarse al menos en parte.
- Informar al usuario del progreso en un programa de larga duración.

```R
w <- function() {
  warning("something strange happened")
  -1
}

w()
#> [1] -1
#> Warning message:
#> In w() : something strange happened

# if warnings are not wanted
suppressWarnings(w())
#> [1] -1
```

La función `suppressWarnings()` puede ser útil en ocasiones dentro de Exercism, para evitar confundir al ejecutor de pruebas con salida no deseada.
