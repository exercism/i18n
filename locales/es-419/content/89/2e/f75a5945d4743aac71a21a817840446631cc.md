# Acerca de

En C#, una tupla es una estructura de datos que organiza datos y que contiene dos o más campos de cualquier tipo.

Por lo general, una tupla se crea colocando 2 o más expresiones separadas por comas dentro de un par de paréntesis.

```csharp
string boast = "All you need to know";
bool success = !string.IsNullOrWhiteSpace(boast);
(bool, int, string) tripple = (success, 42, boast);
```

Como cualquier otra expresión, una tupla se puede usar de muchas maneras: en [asignaciones][tuple-assignment], para inicializar un campo o una variable, como [valor de retorno][tuple-return-values] de un método o pasada como parámetro. Se puede comprobar su [igualdad][tuple-equality]. La igualdad de las tuplas se ilustra por completo en el ejercicio `pattern-matching-tuples`, pero a continuación se incluye un ejemplo en el código para que la explicación quede completa.

Los campos se extraen con la sintaxis de punto. De forma predeterminada, el primer campo es `Item1`, el segundo `Item2`, etc. Los nombres que no son los predeterminados se explican más abajo, en _Nombres_.

Una tupla se puede usar como parámetro genérico, por ejemplo, `IList<(bool, string)>`

Además, las tuplas admiten la «deconstrucción», que se explica más abajo, y se pueden usar en la coincidencia de patrones, que se cubre en un ejercicio posterior.

```csharp
// initialization
(int, int, int) vertices = (90, 45, 45);

// assignment
vertices = (60, 60, 60);

//  return value
(bool, int) GetSameOrBigger(int num1, int num2)
{
    return (num1 == num2, num1 > num2 ? num1 : num2);
}

// method argument
int Add((int, int) operands)
{
    return operands.Item1 + operands.Item2;
}

// equality testing
var estimateA = (42, 1729);
var estimateB = (2*3*7, 7*13*19);
bool result = estimateA == estimateB;
// => result == true
```

Esta [introducción][tuples] muestra cómo definir y usar tuplas.

## Nombres

Los nombres de campo `Item1`, etc. no hacen que el código sea legible. Hay 3 maneras de dar nombres a los campos: a) en la declaración del tipo, b) en la expresión que lo crea, c) mediante los [inicializadores de proyección de tuplas][tuple-projection-initializers] (no se ilustra aquí).

```csharp
// name items in declaration
(bool success, string message) results = (true, "well done!");
bool mySuccess = results.success;
string myMessaage = results.message;

// name items in creating expression
var results2 = (success: true, message: "well done!");
bool mySuccess2 = results2.success;
string myMessaage2 = results2.message;
```

No intentes ser demasiado ingenioso con el mecanismo de nombres. En realidad, no es más que azúcar sintáctico. Por ejemplo, no puedes cambiar los nombres de una tupla cuando le asignas el valor de otra tupla.

## Deconstrucción

A veces resulta conveniente tomar una tupla y asignar sus campos a varias variables, inicializándolas si hace falta. Este mecanismo se llama [deconstrucción][tuple-deconstruction]. (También se puede aplicar a tus propios objetos. Consulta [aquí][udt-deconstruction]).

```csharp
var goodNumbers = (42, 3.142, 1729);
(int ultimateQuestion, var π, var ramanujan) = goodNumbers;
return ultimateQuestion;
// => 42
```

## Asignación de campos

A los campos de las tuplas se les puede asignar valores de forma individual. Sin embargo, dada la tendencia de C# hacia la inmutabilidad, este tipo de uso no está muy extendido. A menudo se usan las tuplas como si fueran inmutables, lo cual, por supuesto, no es el caso.

```csharp
(int, string) tpl;
tpl.Item1 = 1;
tpl.Item2 = "bad";
tpl.Item2 = "even worse";
// => (1, "even worse";
```

## Antecedentes

Las tuplas de las que hablamos no deben confundirse con [`System.Tuple`][system-tuple], que probablemente solo se encuentre en bases de código heredadas.

La situación es un poco más confusa cuando se trata de `System.ValueTuple`. La [documentación][system-value-tuple] de la última sobrecarga de [`System.ValueTuple`][system-value-tuple] afirma que «los tipos de tupla de valor proporcionan la implementación en tiempo de ejecución que da soporte a las tuplas en C#». Con «tipos de tupla de valor» aquí se refieren a las sobrecargas genéricas de `System.ValueTuple`. Con «tuplas» se refieren a lo que nos ha ocupado en este ejercicio. En esencia, están diciendo que `System.ValueTuple` es un detalle de implementación de las tuplas. Es poco probable que esto le interese mucho a la mayoría de la gente la mayor parte del tiempo. Por desgracia, gran parte de la documentación sobre «tuplas», incluida la de Microsoft, está salpicada de referencias a `System.ValueTuple`. Probablemente no pasa nada por pasarlas por alto.

## Otros usos y limitaciones

La coincidencia de patrones es un uso especialmente productivo de las tuplas. Se cubre en un ejercicio posterior.

Las tuplas permiten algunos otros pequeños toques estilísticos:

- Asignación múltiple (sobre todo en constructores), por ejemplo, `(this.field1, this.field2) = (arg1, arg2);`
- Intercambiar o reciclar valores, por ejemplo, `(a, b) = (b, a);`
- Usarlas en lugar de un `struct` en una lista
- Usarlas como clave de un diccionario o como el contenido de un conjunto.
- Usarlas en LINQ. (LINQ se cubre en ejercicios posteriores).

La documentación describe las tuplas como un mecanismo ligero, y esa es la clave para usarlas con éxito. Usar una tupla en lugar de una clase o un struct puede llevar a una tediosa repetición de los tipos de sus campos y, quizá, de sus nombres. Esto se aplica sobre todo cuando se usa como argumento de un método o como argumento genérico en colecciones.

Lo mejor es usar con criterio trucos como la asignación múltiple y el intercambio de valores.

No se admiten operaciones relacionales distintas de la igualdad y la desigualdad.

Ten en cuenta que las tuplas se introdujeron en el lenguaje hace relativamente poco (C# 7), así que si quieres usarlas, asegúrate de que tu base de código use la [versión][language-version] 7 o posterior del lenguaje.
