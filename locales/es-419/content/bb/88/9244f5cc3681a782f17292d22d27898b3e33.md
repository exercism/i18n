# Introducción

## Structs

Las structs son tipos de datos personalizados que te permiten nombrar y agrupar varios valores relacionados.

Para definir una struct, usa la palabra clave `struct` seguida de un nombre y llaves que contienen los campos con sus nombres y tipos:

```rust
#[derive(Drop)]
struct User {
    active: bool,
    username: ByteArray,
    email: ByteArray,
    sign_in_count: u64,
}
```

Para crear una instancia de una `struct`, especifica el nombre de la `struct` y usa llaves con pares clave-valor para los campos.

```rust
let user = User {
   active: true, username: "someusername123", email: "someone@example.com", sign_in_count: 1
};
```

Usa la notación de punto para acceder a los campos de una instancia mutable de `struct` o para modificarlos.

```rust
let mut user = User {
    active: true, username: "someusername123", email: "someone@example.com", sign_in_count: 1
};
user.email = "anotheremail@example.com";
```

## Propiedad

Los valores en Cairo son inmutables, y esta inmutabilidad garantiza que, incluso si muchas variables se refieren al mismo valor, el valor en sí permanece constante y sin alteraciones.
El _propietario_ de una variable es el código que puede leer esa variable (y escribirla si es mutable).

Reglas de propiedad en Cairo:

1. Cada variable en Cairo tiene un propietario.
2. Solo puede haber un propietario a la vez.
3. Cuando el propietario sale del ámbito, la variable se destruye.

Un ámbito es el rango dentro de un programa en el que una variable es válida.

```rust
fn main() {
                      // `x` is not valid here, it has not been declared yet
    let x: u32 = 3;   // `x` is declared, it is valid from this point forward
                      // do stuff with `x`

} // this scope ended here, `x` goes out of scope and is no longer valid
```

Cuando una variable sale del ámbito, se destruye, lo que garantiza que el recurso asociado se libere correctamente.
Esto se logra implementando o derivando el trait `Drop`, que le indica al compilador que el tipo se puede destruir de forma segura una vez que ya no es útil.

```rust
#[derive(Drop)]
struct A {}

fn main() {
    A {}; // this value can be destroyed after going out of scope
}
```

Por el momento, la implementación de `Drop` se puede derivar para todos los tipos, excepto para los diccionarios (`Felt252Dict`) y los tipos que contienen diccionarios.

Un valor también se puede _mover_, lo cual ocurre cuando un valor se pasa a otra función: se destruye la variable original que se refería al valor (lo que hace que la variable quede inservible) y se crea una nueva variable para contener el mismo valor.

```rust
fn foo(num: u32) { 
    // do something with p
}

fn main() {
    let num: u32 = 10;
    foo(num);
    // ownership of `num` was moved into `foo` and is thus no longer valid in this scope
}
```

Devolver valores equivale a moverlos.

El ejemplo de abajo muestra una función que devuelve algún valor:

```rust
#[derive(Drop)]
struct A {}

fn main() {
    // main now owns a1
    let a1 = gives_ownership();

    // a2 comes into scope
    let a2 = A {};

    // a2 is moved into takes_and_gives_back, which also moves its return value into a3
    let a3 = takes_and_gives_back(a2);
} // Here, a3 and a1 go out of scope and are dropped. a2 was moved, so nothing happens.

// Moves its return value into the function that calls it
fn gives_ownership() -> A {
    let some_a = A {};
    some_a
}

// This function takes an instance some_a of A and returns it
fn takes_and_gives_back(some_a: A) -> A {
    some_a
}
```

Como una variable se destruye después de moverse, el compilador nos prohíbe reutilizarla después.

```rust
#[derive(Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(p: Point) { 
    // do something with p
}

fn main() {
    let p = Point { x: 5, y: 10 };
    foo(p);
    foo(p); // compiler error: Variable was previously moved.
}
```

En este caso, intentamos pasar el mismo valor (la struct `Point` de la variable `p`) a ambas llamadas a la función.
Una vez que pasamos la variable a la función `foo` la primera vez, la variable ya no se puede usar.

Una forma de resolverlo es derivar el trait `Copy` en nuestra struct, lo que cambiaría lo que pasa cuando pasamos una variable `Copy` a una función: ya no movería el valor, sino que crearía una nueva variable que se refiere al mismo valor.
Esta es una operación gratuita porque las variables son una abstracción de Cairo y los valores siempre son inmutables.

Para implementar el trait `Copy` en tu tipo, agrega la anotación `#[derive(Copy)]` a la definición del tipo.

```rust
#[derive(Copy, Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(p: Point) { 
    // do something with p
}

fn main() {
    let p = Point { x: 5, y: 10 };
    foo(p);
    foo(p); // this now works
}
```

## Referencias e instantáneas

Cairo tiene dos funcionalidades para pasar un valor sin destruirlo ni moverlo, llamadas `references` y `snapshots`.

Las instantáneas proporcionan una «vista» inmutable de un valor en un momento determinado, lo que te permite conservar la propiedad de una variable mientras accedes a su estado.
Cualquier modificación de la variable crea una nueva celda de memoria, y deja sin cambios la vista de la instantánea.

Para crear una instantánea, simplemente coloca el prefijo `@` delante de la instancia de la variable.

```rust
// this function takes in a snapshot using `@` with the data-type
fn get_len(arr: @Array<u128>) -> u32 { // 
    arr.len()
}

fn foo(arr: Array<u128>) {
    arr.pop_front();
}

fn main() {
    let mut new_arr: Array<u128> = array![1, 2, 3, 4, 5, 6, 7, 8];
    let snapshot = @new_arr; // using `@` to create a snapshot of a variable
    let len = get_len(snapshot); // pass the snapshot as argument, retaining ownership
    foo(new_arr); // `new_arr` is still valid up until here and no further
}
```

Para convertir una instantánea de nuevo en una variable normal, puedes usar el operador desnap `*`, que es lo opuesto al operador `@`.
Solo se les puede aplicar desnap a los tipos que implementan el trait `Copy`.

```rust
fn square(n: @u32) -> u32 {
    let n = *n; // we desnap the value
    n * n
}

fn main() {
    let num: u32 = 10;
    let squared = square(@num); // we use `@` to create a snapshot
    println!("{} squared = {}", num, squared);
}
```

Las referencias te permiten pasar valores mutables a funciones y que se devuelvan de forma implícita, manteniendo la propiedad en el contexto de la llamada.
Esto se logra usando el modificador `ref`, siempre que la variable se declare como mutable con la palabra clave `mut`.

Podemos actualizar el ejemplo anterior de `Point` para usar referencias mutables en lugar de depender del trait `Copy`, y seguiría funcionando.

```rust
#[derive(Drop)]
struct Point {
    x: u128,
    y: u128,
}

fn foo(ref p: Point) { 
    // we can now update the passed values and the changes
    // will be visible in the calling context
    p.x += 1;
}

fn main() {
    let mut p = Point { x: 5, y: 10 };
    foo(ref p);
    foo(ref p); // this now works even without the Copy trait
    println!("p.x = {}", p.x); // p.x = 7 
}
```
