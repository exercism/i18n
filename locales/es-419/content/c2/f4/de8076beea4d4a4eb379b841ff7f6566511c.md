# Reputación

La reputación es el sistema que permite a las personas adquirir «confianza» dentro del ecosistema de Exercism.

La reputación mide cuánto ha contribuido una persona a Exercism, tanto mediante su contribución a la plataforma (por ejemplo, creando software, ejercicios y documentación) como mediante su contribución a la comunidad (por ejemplo, mentoría).

La reputación no se puede «gastar» ni «usar». Sin embargo, alcanzar ciertos umbrales de reputación da acceso a nuevos privilegios y formas de contribuir. En pocas palabras, cuanta más reputación tiene alguien, más confiamos en esa persona y, por lo tanto, más poder recibe. La reputación también es una medida visible públicamente de cuánto le has dado a Exercism.

## Propósito

El propósito del sistema de reputación es:

1. Maximizar las interacciones centradas en el crecimiento entre estudiantes y mentores
2. Maximizar las ganas de los mentores de contribuir

## Cómo se adquiere la reputación

La reputación se puede adquirir de diversas formas:

| Acción                            | Reputación |
| --------------------------------- | ---------- |
| Mentorizar una solución con éxito | 5          |
| Publicar una solución             | 1-3        |
| Escribir un ejercicio             | 20         |
| Actualizar un ejercicio           | 10         |
| Escribir un concepto              | 10         |
| Actualizar un concepto            | 5          |
| Crear un pull request             | 3-100      |
| Revisar un pull request           | 1-20       |
| Fusionar un pull request          | 1-5        |

### Mentorizar una solución con éxito

Por cada solución mentorizada con éxito (cuando la discusión se dio por terminada), se otorgan `5` puntos de reputación.

### Publicar una solución

Por cada solución publicada, se otorga reputación según la dificultad del ejercicio:

| Etiqueta | Reputación |
| -------- | ---------- |
| `easy`   | 1          |
| `medium` | 2          |
| `hard`   | 3          |

### Escribir un ejercicio

Por cada ejercicio en el que el usuario aparezca como autor, se otorgan `20` puntos de reputación.

### Actualizar un ejercicio

Por cada ejercicio en el que el usuario aparezca como contribuidor, se otorgan `10` puntos de reputación.

### Escribir un concepto

Por cada concepto en el que el usuario aparezca como autor, se otorgan `10` puntos de reputación.

### Actualizar un concepto

Por cada concepto en el que el usuario aparezca como contribuidor, se otorgan `5` puntos de reputación.

### Crear un pull request

Por defecto, se otorgan `12` puntos de reputación cuando se fusiona un pull request que abrió el usuario.

Según el contenido del pull request, un mantenedor puede otorgar más (o menos) reputación agregando una de las siguientes etiquetas al pull request:

| Etiqueta        | Reputación | Ejemplos                                                                                                                                                                                                                                                                                                                                                            |
| --------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x:rep/tiny`    | 3          | <ul><li>Corregir un solo error tipográfico o enlace</li><li>Eliminar una línea en blanco o agregar un salto de línea</li><li>Cambiar o agregar un solo comentario de código</li></ul>                                                                                                                                                                               |
| `x:rep/small`   | 5          | <ul><li>Corregir un solo caso de prueba, tarea o ejemplo</li><li>Corregir varios errores tipográficos o enlaces en un solo archivo</li><li>Aclarar el contenido agregando unas cuantas líneas a un archivo</li></ul>                                                                                                                                                |
| `x:rep/medium`  | 12         | <ul><li>Sincronizar un ejercicio con problem-specifications (incluidas las ediciones)</li><li>Agregar uno o más casos de prueba desde cero</li><li>Mejorar varios archivos de un ejercicio</li><li>Agregar notas del mentor para un ejercicio desde cero</li><li>Corregir un error pequeño en un test runner/analyzer/representer</li><li>Agregar comentarios del analyzer para un solo ejercicio</li></ul> |
| `x:rep/large`   | 30         | <ul><li>Agregar un nuevo ejercicio de concepto o de práctica</li><li>Agregar documentación nueva de un concepto</li><li>Reescritura sustancial de un concepto o ejercicio existente</li><li>Agregar nuevos scripts de CI u otra automatización</li></ul>                                                                                                             |
| `x:rep/massive` | 100        | <ul><li>Crear un test runner, analyzer, representer o generator desde cero</li><li>Refactorizaciones importantes de esas herramientas</li><li>Crear documentación importante desde cero (por ejemplo, guías de contribución o de pruebas)</li></ul>                                                                                                                  |

Los ejemplos anteriores pueden servir como orientación aproximada sobre cuándo aplicar cada etiqueta, pero los mantenedores son libres de usar su propio criterio.

- La cantidad estimada de tiempo dedicado debe interpretarse como el tiempo promedio que un _mantenedor_ dedicaría a hacer el PR.
- Si se especifica más de una etiqueta, la etiqueta con el valor de reputación más alto determina la reputación otorgada.
- Si un pull request sigue abierto, todavía no se otorga reputación.
- Si un pull request se cierra _sin_ fusionarlo, no se otorga reputación.

_Por compatibilidad con versiones anteriores, también admitimos usar las etiquetas `x:size` para determinar la reputación otorgada._

### Revisar un pull request

Por cada pull request fusionado o cerrado que el usuario haya revisado, se otorgan `5` puntos de reputación.

- Si un pull request sigue abierto, todavía no se otorga reputación.
- La reputación por revisión solo se otorga una vez por usuario y por pull request.
- El usuario que abrió el pull request _no_ recibe reputación por revisar su propio pull request.

- La reputación que se otorga por revisar un pull request cambia si se agrega una de las siguientes etiquetas al pull request:

  | Etiqueta        | Reputación |
  | --------------- | ---------- |
  | `x:rep/tiny`    | 1          |
  | `x:rep/small`   | 2          |
  | `x:rep/medium`  | 5          |
  | `x:rep/large`   | 10         |
  | `x:rep/massive` | 20         |

  _No_ es posible usar distintos «tamaños» de reputación para quien abre un pull request y para quien lo revisa.
  Ambos se basan en la misma etiqueta `x:rep`.

  Si se especifica más de una etiqueta, la etiqueta con el valor de reputación más alto determina la reputación otorgada.

  _Por compatibilidad con versiones anteriores, también admitimos usar las etiquetas `x:size` para determinar la reputación otorgada._

### Fusionar un pull request

Por cada pull request que el usuario haya fusionado, se otorga `1` punto de reputación.

- Si un pull request sigue abierto, todavía no se otorga reputación.
- Si un pull request se cierra _sin_ fusionarlo, no se otorga reputación.
- El usuario que abrió el pull request _no_ recibe reputación por fusionar su propio pull request.
- Si el pull request no tiene ninguna revisión, en su lugar se otorgan `5` puntos de reputación.

### Abrir un issue

Al igual que con los pull requests, por defecto **no se otorga reputación** cuando se abre un issue.
A diferencia de los pull requests, solo se otorga reputación por issues grandes o masivos.

Según el contenido del issue, un mantenedor puede decidir otorgar reputación agregando una de las siguientes etiquetas al issue:

| Etiqueta        | Reputación | Ejemplos                                             |
| --------------- | ---------- | ---------------------------------------------------- |
| `x:rep/large`   | 30         | <ul><li>Ejercicio de concepto completamente desarrollado</li></ul> |
| `x:rep/massive` | 100        | <ul><li>Diseñar el plan de estudios de un track</li></ul>       |

Los ejemplos anteriores pueden servir como orientación aproximada sobre cuándo aplicar cada etiqueta, pero los mantenedores son libres de usar su propio criterio.

- La reputación debe reflejar la cantidad de esfuerzo que ese _mantenedor_ dedicaría a crear el issue.

- Si se especifica más de una etiqueta, la etiqueta con el valor de reputación más alto determina la reputación otorgada.
