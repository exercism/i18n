# Introducción

En C++, las declaraciones a menudo se separan de las definiciones.
Las declaraciones se agrupan en los llamados archivos de cabecera, y las implementaciones respectivas se colocan en archivos fuente.
Puedes pensar en los archivos de cabecera como una API.
El archivo de cabecera te dice _qué_ ofrece una base de código, sin entrar en los detalles de _cómo_.

## Cabeceras y archivos fuente

La extensión de archivo más común para los archivos de cabecera es `.h`.
Algunos proyectos usan `.hpp` o prescinden por completo de la extensión.

Las definiciones están en un archivo `.cpp` aparte.
Para reunir las partes, el archivo fuente empieza por _incluir_ el archivo de cabecera correspondiente.

Si quieres escribir una biblioteca llamada «quick_math» que ofrece una función «super_root» que quieres usar a menudo, los archivos se verían así:

```cpp
// A file named quick_math.h
#pragma once
namespace quick_math {
    double super_root(double x, int n);
}
```

```cpp
// A file named quick_math.cpp
#include "quick_math.h"
#include <cmath>
double quick_math::super_root(double x, int n) {
    while(n) { x = std::sqrt(x), --n;}
    return x;
}
```

Si necesitas incluir una cabecera que solo requiere la implementación, la línea `#include` correspondiente solo es necesaria en el archivo fuente.
Todo lo que se incluye en la cabecera también está disponible en el archivo `.cpp`, como la biblioteca `string` del ejemplo de abajo.
**Atención**: el `;` es necesario después de la declaración en el archivo de cabecera, pero no después de la definición en el archivo fuente.

## Clases y cabeceras

Las clases pueden volverse muy complejas y su relación con la división entre cabecera y fuente puede resultar confusa.
Una organización posible es mantener todos los detalles de la implementación en el archivo fuente y todas las declaraciones y variables miembro en la cabecera:

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H
#include <string>
namespace robots {
    class Flower {
        private:
            bool needs_water{};
            int size{};
            std::string name{};
        public:
            Flower(std::string name, int size = 0);
            void give_water();
            std::string get_name();
            int get_size();
            void start_next_day();
    };
}
#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"
robots::Flower::Flower(std::string name, int size) {this->name = "Robotica " + name; this->size = size;}
void robots::Flower::start_next_day() {if (!needs_water) ++size; needs_water = true;}
std::string robots::Flower::get_name() {return name;}
int robots::Flower::get_size() {return size;}
```

Cuando la cabecera se usa como resumen de la API, es ahí donde uno buscaría información como los valores predeterminados.
Por eso, el valor predeterminado del parámetro `size` del constructor se define en la cabecera y no en la implementación.
Las definiciones en el archivo fuente llevan como prefijo el espacio de nombres `robots` y el tipo de clase `Flower`.

Otra opción de organización es una biblioteca _header only_, que no tiene ningún archivo `.cpp`:

```cpp
// A file named robot_flower.h
#pragma once
#include <string>
namespace robots {
    class Flower {
        private:
            bool needs_water{};
            int size{};
            std::string name{};
        public:
            Flower(std::string name, int size = 0) {this->name = "Robotica " + name; this->size = size;}
            void give_water() {needs_water = false;}
            std::string get_name() {return name;}
            int get_size() {return size;}
            void start_next_day() {if (!needs_water) ++size; needs_water = true;}
    };
}
```

Los proyectos pueden usar combinaciones de estas organizaciones y hay mucho debate sobre cuál podría ser la mejor opción para cada caso de uso.

## Guardas de inclusión

Es posible que hayas notado la línea `#pragma once` en el archivo de cabecera de ejemplo de arriba.
Esto se llama guarda de inclusión y garantiza que el contenido del archivo se incluya una sola vez durante la compilación para evitar errores.
Existe otra variación más compleja de una guarda de inclusión que empieza con `#ifndef` y termina con `#endif`.
Cumple la misma función y su uso se muestra en el ejemplo de la clase `Flower` de arriba.
