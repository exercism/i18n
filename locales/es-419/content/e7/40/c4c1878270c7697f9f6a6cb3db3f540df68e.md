# Funciones en `jq`

Puedes definir tus propias **funciones personalizadas** en `jq` para encapsular la lógica que necesites.
Las _funciones_ se comportan igual que las integradas: reciben una entrada y emiten cero, una o más salidas.

## Definir una función

Puedes definir una _función_ de `jq` con la siguiente sintaxis:

```jq
# no arguments
def funcname: expression;

# or with arguments
def funcname(args): expression;
```

- empieza con la palabra clave `def`,
- lleva dos puntos antes del cuerpo de la función,
- el cuerpo consta de una sola expresión,
- termina con un punto y coma,
- como en el resto de la sintaxis de `jq`, puedes usar espacios en blanco libremente para que sea más legible.

## Dónde colocar las funciones

Las _funciones_ deben definirse antes de usarlas: esto es un error:

```jq
def A: B(10);
def B(n): n + 1;
A
# => error: B/1 is not defined
```

Esto implica que debes colocar las _funciones_ al inicio de tu código `jq`, antes de la expresión «principal».

### Funciones anidadas

Las _funciones_ se pueden anidar:

```jq
def A:
    def B(n): n + 1;
    B(10)
    ;
A
# => 11
```

Aquí, la _función_ `B` solo es visible en el cuerpo de `A`.

## Ámbito

Una _función_ introduce un nuevo **ámbito** para las variables y las funciones anidadas.

## Argumentos

Los **argumentos** de una _función_ se separan con _puntos y coma_, no con comas.
Por ejemplo, una _función_ que recibe un número, y luego suma un número y multiplica por un número:

```jq
def add_mul(adder; multiplier): (. + adder) * multiplier;

10 | add_mul(5; 4)    # => 60
```

<!-- prettier-ignore -->
~~~~exercism/note
Se necesitan puntos y coma porque la coma ya tiene un propósito en `jq`: es un operador que une flujos.

Usar una coma en lugar de un punto y coma intentará hacer dos llamadas a una función `add_mul` de _1 argumento_, que no existe y por lo tanto fallará en la primera llamada:

```jq
10 | add_mul(5, 4)
# error: add_mul/1 is not defined
```

La coma en `5, 4` concatena los números 5 y 4 en un flujo.
Cuando llamamos a una función con un flujo como argumento, `jq` llamará a esa función varias veces, una por cada valor del flujo.
Este es un ejemplo de la «iteración implícita» inherente a los flujos de `jq`.
`10 | add_mul(5, 4)` es equivalente a lo siguiente.

```jq
(10 | add_mul(5)), (10 | add_mul(4))
```
Ahora podemos ver cómo aparece el error `add_mul/1 is not defined`.
~~~~

<!-- prettier-ignore-end -->

### Los argumentos son _expresiones_

Los _argumentos_ de una función son filtros, no valores.
En este sentido, se comportan como lo que otros lenguajes describen como callbacks:

Usando la función `add_mul` como ejemplo:

```jq
10 | add_mul(. + 5; . - 2)    # => 200
```

¿Qué está pasando aquí?

- el argumento `adder` recibe la _expresión_ `. + 5`
  - cuando la función hace `. + adder`, eso se convierte en `. + . + 5`
  - eso da como resultado 25, ya que `. == 10`
- de forma similar, el argumento `multiplier` es la expresión `. - 2`
  - eso da como resultado 8
  - entonces el resultado es `25 * 8 == 200`

### Argumentos como valores

A veces vas a querer «materializar» un _argumento_ en una variable:

```jq
def my_func(arg):
    arg as $arg
    | other stuff ...
;
```

Hay una forma abreviada de hacer esto:

```jq
def my_func($arg):
    other stuff ...
;
```

Ten en cuenta que esto es solo «azúcar sintáctico»: el nombre `arg` sin `$` sigue estando en el ámbito de la _función_.

<!-- prettier-ignore -->
~~~~exercism/caution
Por ejemplo, escribí algo así para resolver un ejercicio:

```jq
# function that encodes the input value
def code:
    # expression here
    ;

def equals($code):
    (. | code) as $this_code
    | $code == $this_code
    ;

("some key value" | code) as $key
| ["array", "of", "values"]
| map(select(equals($key)))
```

y me sorprendió que todos los valores del array fueran iguales a la clave.

Esto pasó porque jq veía la función `equals` así:

```jq
def equals(code):
    code as $code
    | (. | code) as $this_code
    | $code == $this_code
    ;
```

El **argumento** `code` _sobrescribió_ la **función** `code` definida previamente.
Eso significaba que `(. | code)` simplemente emite el **argumento** en lugar de calcular un nuevo código a partir del valor de entrada.
Por eso `$this_code` y `$code` eran siempre iguales.
~~~~

## Aridad

Las _funciones_ tienen una **aridad**, es decir, la cantidad de _argumentos_ que reciben.

Las _funciones_ pueden usar el mismo nombre con distintas _aridades_.
La función integrada [`range`][man-range] lo demuestra: `range/1`, `range/2` y `range/3` coexisten.

Esto puede ser útil para definir funciones recursivas que llevan su estado a través de los argumentos.
Por ejemplo, `map` _podría_ implementarse así:

```jq
def my_map($accumulator; func):
    if length == 0
        then $accumulator
        else first as $elem | .[1:] | my_map($accumulator + [$elem | func]; func)
    end
    ;

def my_map(func):
    my_map([]; func)
    ;

[1, 2, 3, 4] | my_map(. * 10)   # => [10, 20, 30, 40]
```

## Recursión

`jq` realiza optimización de llamadas de cola, pero solo en funciones de aridad 0.

## Módulos

Un módulo de `jq` es un archivo que contiene solo funciones.
Los módulos se incluyen en un programa de jq con los comandos [`include`][man-include] o [`import`][man-import].
