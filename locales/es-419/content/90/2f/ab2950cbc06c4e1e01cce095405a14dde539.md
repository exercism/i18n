# Contratos

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0 and load <= limit
      post result >= 0
   is
      return limit - load;
   end;
```

| Cláusula | Dice | De quién es la culpa si se incumple |
| --- | --- | --- |
| `pre` | lo que debe cumplirse al entrar | de quien llama |
| `post` | lo que se cumple al salir | de la rutina |

Ambos reciben un `BOOL`, y ambos pueden usar los argumentos de la rutina y los
atributos del objeto. `post` también puede usar `result`, el valor que se
devuelve.

## assert

Dentro del cuerpo de una rutina, `assert` declara algo que debe ser verdadero en
ese punto:

```sather
      assert load <= limit;
```

Se verifica con la misma opción que los demás.

## Invariantes de clase

Una clase puede declarar algo que es verdadero para cada uno de sus objetos
entre llamadas:

```sather
   invariant : BOOL is
      return checks >= 0 and limit > 0;
   end;
```

Se verifica al entrar y al salir de cada rutina pública, cuando la verificación
está activada.

## Cómo activarlo

| Opción | Verifica |
| --- | --- |
| `-chk` | todo: pre, post, assert, invariant, límites, aritmética |
| `-chk_no` | nada |

Ten en cuenta que `-chk_pre` por sí solo *no* activa la verificación de
precondiciones en este compilador; lo que funciona es `-chk`. Una violación
imprime la rutina y la línea de código fuente, y detiene el programa. No es una
excepción, y `protect` no la capturará.

Lo habitual es desarrollar y probar con `-chk` y distribuir sin él, para que las
verificaciones no cuesten nada en el programa distribuido. Eso solo vale la pena
si las pruebas ejercitan de verdad esas rutas.

## Qué hace que un contrato sea bueno

Di lo que la rutina necesita, no cómo funciona:

```sather
   pre load >= 0 and load <= limit        -- yes
   pre load /= 47                         -- what?
```

Un `post` que repite el cuerpo no le enseña nada a nadie:

```sather
   post result = limit - load             -- says the body twice
   post result >= 0                       -- says something worth knowing
```

## Herencia

Un subtipo puede debilitar un `pre` y reforzar un `post` (aceptar más, prometer
más), pero nunca lo contrario, o el código escrito contra el supertipo se
rompería. Esa es la regla que los contratos existen para hacer verificable.
