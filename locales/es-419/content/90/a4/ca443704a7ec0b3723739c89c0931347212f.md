# Sección sobre los comentarios

Go tiene [excelentes guías](https://golang.org/doc/effective_go.html) sobre cómo escribir comentarios. Existe un formato estándar que puedes usar para los comentarios de documentación, y que la herramienta `godoc` puede convertir automáticamente en una documentación muy bonita.

El comentario del paquete debe empezar con la palabra `Package`, seguida del nombre del paquete, así:

```go
// Package cook provides handy conversion methods for units typically used in recipes.
package cook
```

En el caso de las funciones, los métodos, las constantes y las variables de paquete exportadas, el comentario debe empezar con el nombre y continuar con una frase verbal:

```go
// TbsToMl converts tablespoons to milliliters.
func TbsToMl(tbs int) int {
	// ...
}
```

La wiki de [CodeReviewComments](https://github.com/golang/go/wiki/CodeReviewComments#comment-sentences) especifica además que los comentarios de documentación deben ser oraciones completas, que terminen con un punto.

Además de optimizar la legibilidad, seguir estas recomendaciones mejora cómo se ve tu código en las [herramientas de documentación de Go](http://whipperstacker.com/2015/09/30/go-documentation-godoc-godoc-godoc-org-and-go-doc/) como [godoc.org](http://godoc.org), `godoc` y `go doc`.

Tómate un momento para leer la sección sobre comentarios de documentación en la guía de estilo oficial, [Effective Go](https://golang.org/doc/effective_go.html), y así ver el razonamiento que hay detrás de estas decisiones.
