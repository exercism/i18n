# Acerca de

La única convención de Factor para pasar datos es la *pila de datos*: las palabras sacan sus argumentos de la pila y dejan sus resultados en ella. Cada definición de palabra declara un *efecto de pila* que documenta ese contrato.

```factor
: restow ( a b -- b a ) swap ;
: discard-top ( a b -- a ) drop ;
```

Los nombres que aparecen dentro de `( … -- … )` están ahí para beneficio de quien lee el código; lo que el compilador verifica es el *número* de argumentos y resultados. Una discrepancia es un error en tiempo de compilación, lo que atrapa toda una clase de bugs que serían errores en tiempo de ejecución en un lenguaje de tipado dinámico sin este tipo de declaración.

Como la pila es posicional, necesitas reordenar constantemente su parte superior antes de que pueda ejecutarse la siguiente palabra. Las **palabras de reordenamiento** del `kernel` hacen exactamente eso:

```
dup   ( x   -- x x   )    ! duplicate the top
drop  ( x   --       )    ! discard the top
swap  ( x y -- y x   )    ! flip the top two
over  ( x y -- x y x )    ! copy the second item onto the top
nip   ( x y -- y     )    ! discard the second item
rot   ( x y z -- y z x )  ! roll the third item up to the top
```

La familia completa de reordenamiento las amplía con `-rot` (que rota hacia el otro lado), los primos con sufijo `d` que actúan un elemento más adentro (`dupd`, `swapd`), los primos con el prefijo `2` que actúan sobre pares (`2dup`, `2drop`, `2nip`) y otros como `pick` y `tuck`. Se van presentando a medida que los ejercicios posteriores los necesitan; echar mano de demasiadas palabras de reordenamiento a la vez suele ser señal de que un *local* (un valor con nombre) se leería mejor.

Por convención, las palabras se escriben en `lowercase-kebab-case`, los predicados terminan en `?` y producen un Boolean (`even?`, `empty?`), los setters se escriben `>>name` y los getters `name>>`, y una palabra y su variante mutadora a menudo comparten nombre y solo se distinguen por el contexto.
