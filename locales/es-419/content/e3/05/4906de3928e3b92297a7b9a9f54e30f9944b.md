# Pistas
Un uso común de `Either` es indicar un cálculo que posiblemente resulte en un error
(si el error en sí no te interesa, quizás el tipo `Option`, más simple, sea una mejor opción).
Cuando no hay error, el resultado suele ser un `Right` (regla mnemotécnica: el valor correcto),
mientras que un error es un `Left`, por ejemplo un `Left[String]` que contiene un mensaje de error.
Ten en cuenta que en Scala 2.12 `Either` está sesgado hacia la derecha por defecto, así que funciona como esperas en operaciones como `filter`, `map`, `flatMap` o en una comprensión `for`.
Si no conoces `Either`, puedes leer [este tutorial](http://danielwestheide.com/blog/2013/01/02/the-neophytes-guide-to-scala-part-7-the-either-type.html). Pero ten en cuenta que este tutorial trata sobre versiones de Scala anteriores a la 2.12. Para Scala 2.12 puedes ignorar sin problema `RightProjection` y omitir `.right`.
`Either` es una llamada [mónada](https://en.wikipedia.org/wiki/Monad_(functional_programming)) que cubre un «aspecto computacional»,
en este caso el manejo de errores.
El uso correcto de las mónadas puede dar como resultado un código muy conciso, pero elegante
y legible. El uso incorrecto puede llevar fácilmente a lo contrario.
Mira [este video](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) para aprender más.
## Trampas comunes que debes evitar
Hay algunas reglas generales para `Either`:
1. Si no lo necesitas, no lo uses. En lugar de
```scala
def add1(x: Int): Either[String, Int] = Right(x + 1)
```
es mejor tener
```scala
def add1(x: Int): Int = x + 1
```
(existe `Either.map` para aplicar funciones así de simples,
así que no tienes que llenarlas de `Either`).
2. No hagas «unwrap» si en realidad no lo necesitas.
A menudo hay funciones integradas para lo que buscas. Señales de un unwrap
prematuro son `isLeft/isRight` o la coincidencia de patrones. Por ejemplo, en lugar de
```scala
val x: Either[String, Int] = ...

if (x.isRight) x.right.get + 1 else x.left.get
// or
x match {
  case Right(n) => n + 1
  case Left(s) => s
}
```
es mejor tener
```scala
x fold (identity, _ + 1)
```
3. Puedes usar mónadas dentro de una comprensión `for`, ¡y son una maravilla!
Esto es recomendable cuando quieres «componer» varias instancias de `Either`. En lugar de
```scala
val xo: Either[String, Int] = ...
val yo: Either[String, Int] = ...
val zo: Either[String, Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	    x + y + z)))
```
es mejor tener
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
