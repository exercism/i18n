# Iteradores personalizados

```sather
   markers!(once spacing : INT, once count : INT) : INT is
      loop
         yield spacing * 1.upto!(count);
      end;
   end;
```

| | rutina | iterador |
| --- | --- | --- |
| nombre | `foo` | `foo!` |
| entrega un valor | `return` | `yield` |
| termina | `return`, o el final | `quit`, o quedarse sin valores |
| se puede llamar | en cualquier lugar | solo dentro de un `loop` |
| conserva su lugar | no | sí |

## yield

`yield` entrega un valor y suspende la ejecución. Todo se restaura en el siguiente
turno: las variables locales, la posición en los bucles propios del iterador y
las posiciones de cualquier iterador que esté llamando a su vez.

Un `yield` dentro de bucles anidados se reanuda en el más interno, y eso es lo que
hace que escribir un recorrido sobre algo anidado sea sencillo:

```sather
   all_cells!(grid : ARRAY{ARRAY{INT}}) : INT is
      loop
         row ::= grid.elt!;
         loop
            yield row.elt!;
         end;
      end;
   end;
```

## quit

Termina el iterador y, con él, el bucle que lo llama. No lleva ningún valor: un
`quit` no es un último resultado, es el anuncio de que no hay ninguno.

Un iterador con un tipo de retorno debe entregar un valor mediante `yield` cada
vez que cede el control; `quit` es la forma en que declina hacerlo.

## once

```sather
   markers!(once count : INT) : INT is
```

Un argumento `once` se evalúa cuando se entra al bucle y se conserva. Un
argumento normal se vuelve a evaluar en cada turno, lo cual importa cuando la
expresión que se pasa contiene otra llamada a un iterador:

```sather
   loop
      #OUT + TRAIL::markers!(sizes.elt!);     -- a new count every turn
   end;
```

Marca los argumentos como `once` a menos que quieras eso específicamente. Toda
la biblioteca lo hace.

## self y los iteradores

Se puede llamar a un iterador sobre un objeto, y entonces `self` es ese objeto. Su
estado en pausa pertenece al lugar de la llamada, no al objeto, así que dos bucles
que recorren el mismo objeto no se interfieren.

## Cuándo escribir uno

Escribe un iterador cuando la respuesta es una secuencia y quien llama debe decidir
cuánto de ella tomar. Detenerse antes de tiempo no cuesta nada y no se construye
nada que no se use, a diferencia de una rutina que devuelve un `ARRAY`, que tiene
que construirlo todo primero.
