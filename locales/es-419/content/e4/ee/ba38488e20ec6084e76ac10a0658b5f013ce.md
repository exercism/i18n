# Introducción

## Caracteres

Una **codificación de caracteres** es una convención específica que se usa para representar elementos de texto de un idioma natural como una secuencia de bytes.
Un «elemento de texto» aquí puede ser cualquier unidad que tenga significado en un idioma natural, por ejemplo, letras, espacios, signos de puntuación, emojis, ideogramas, etc.

NASM (The Netwide Assembler, el ensamblador que usa esta pista) admite la definición de datos usando **ASCII**.

Las constantes de carácter en NASM pueden tener hasta 8 bytes de longitud y se pueden definir con comillas simples (`'`), comillas dobles (`"`) o acentos graves (`` ` ``):

```x86asm
mov rax, '0' ; this copies the ASCII character '0' (decimal value 48)
mov rcx, "z" ; this copies the ASCII character 'z' (decimal value 122)
mov rdx, ` ` ; this copies the ASCII character ' ' (decimal value 32)
```

Los caracteres especiales se deben definir entre acentos graves y escapar con `\`:

```x86asm
mov rax, `\n` ; this copies the ASCII character newline (decimal value 10)
mov rcx, `\t` ; this copies the ASCII character tab (decimal value 9)
```

Ten en cuenta que x86-64 no tiene soporte integrado para ninguna codificación de caracteres como un tipo distinto.
Los datos en ensamblador son una secuencia de bytes, y la interpretación de esos bytes como un carácter, un número o cualquier otra cosa queda a criterio del programador.

Por ejemplo, el carácter ASCII '0' es un solo byte con el valor 48.
Entonces, almacenar 48 en un byte es exactamente lo mismo que almacenar el carácter ASCII '0':

```x86asm
mov al, '0' ; al has the value 48
mov cl, 48  ; cl has the value '0'
; al and cl now have the same value
```

Por esta misma razón, la manipulación de caracteres se hace transformando directamente los valores de esos bytes:

```x86asm
mov al, 'A' ; al now has the value 'A', which is 65 in ASCII
add al, 32 ; al now has the value 97, which is 'a' in ASCII
; so, summing 32 to an uppercase ASCII letter makes it lowercase

mov al, 5 ; al now has the value 5
add al, 48 ; al now has the value 53, which is '5' in ASCII
; so, summing 48 (equivalently, '0') transforms a number between 0 and 9 into an ASCII digit
```

## Strings

Un **string** (_cadena_) es una secuencia de caracteres.
En ensamblador, por lo general se implementa como un array.

Es posible declarar un string en NASM de la misma manera en que se declararía cualquier array:

```x86asm
section .data
    string1 db "h", "e", "l", "l", "o"
```

Una diferencia entre los strings y los demás arrays es que NASM también admite declarar strings sin una coma (`,`) que separe los valores.
También es posible intercalar valores con comas:

```x86asm
section .data
    string2 db "hello"
    string3 db "h", "ello"
```

Ten en cuenta que, como ya se mencionó, los caracteres son solo bytes (o una secuencia de bytes en una codificación Unicode):

```x86asm
section .data
    string1 db "hi"
    string2 db "h", "i"
    string3 db 104, 105
; string1, string2 and string3 are all equivalent
```

Como cada carácter ASCII ocupa un solo byte, cualquier byte posterior en un tamaño mayor es `0`.
Por ejemplo, declarar `'a'` como un qword (8 bytes) significa que el primer byte es `'a'` (`97`) y los otros siete bytes son todos `0`.

Por esta razón, todos estos son equivalentes:

```x86asm
section .data
    ; in all of the following, "hello" takes 5 bytes
    string1 dw 'hello'         ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string2 dw 'he', "ll", `o` ; 3 words (2-byte) - 5 bytes for "hello" + 0
    string3 db `hello`, 0      ; 6 bytes - 5 bytes for "hello" + 0
```

~~~~exercism/caution
En ensamblador, los strings no terminan automáticamente con un carácter NUL de ASCII (valor `0`).

Cuando se interactúa con lenguajes de nivel superior, como C, es responsabilidad del programador asegurarse de que el terminador correcto, si lo hay, se agregue al final de un string.
~~~~

## Instrucciones de string

Como los strings son arrays, puedes trabajar con ellos de la misma manera que con cualquier array, desreferenciando la memoria de forma explícita:

```x86asm
section .data
    hello_msg db "hello", 0

section .text
fn:
    lea rdi, [rel hello_msg]
    mov al, byte [rdi]       ; al == 'h'
    mov cl, byte [rdi + 4]   ; cl == 'o'
    ret
```

Además de eso, hay algunas instrucciones para cargar, mover y almacenar valores en secuencias de bytes en memoria.
Aunque se llaman _instrucciones de string_, se pueden usar con cualquier secuencia de bytes en memoria, es decir, con cualquier array.

Las tres instrucciones de string más importantes son `lods`, `stos` y `movs`:

| instrucción | qué hace                                                                                                          |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `lods`      | carga un valor desde una ubicación de memoria indicada por `rsi` hacia `rax`                                       |
| `stos`      | almacena un valor de `rax` en una ubicación de memoria indicada por `rdi`                                          |
| `movs`      | copia un valor desde una ubicación de memoria indicada por `rsi` y lo almacena en una ubicación de memoria indicada por `rdi` |

Ten en cuenta que esas instrucciones _no_ llevan ningún operando explícito.
Sus operandos son implícitos.

Como regla general:

1. Cuando su operando fuente es una ubicación de memoria, su dirección se debe almacenar en `rsi` (`s` de source).
2. Cuando su operando destino es una ubicación de memoria, su dirección se debe almacenar en `rdi` (`d` de destination).
3. Si uno de los operandos no es una ubicación de memoria, es el registro `rax`.

Ten en cuenta que esas instrucciones desreferencian automáticamente las direcciones de memoria de acuerdo con la operación específica que realizan.

Todas ellas pueden operar en diferentes tamaños.
Se agrega un sufijo para indicar ese tamaño:

| sufijo | significado | tamaño  |
| :----: | ----------- | :------ |
|  `b`   | byte        | 1 byte  |
|  `w`   | word        | 2 bytes |
|  `d`   | dword       | 4 bytes |
|  `q`   | qword       | 8 bytes |

Por ejemplo:

```x86asm
movsb ; copies one byte from the memory location whose address is in `rsi` and stores it into the memory location whose address is in `rdi`
lodsq ; copies one qword (8 bytes) from the memory location whose address is in `rsi` and stores it in `rax`
stosw ; stores one word (2 bytes) from `ax` into the memory location whose address is in `rdi`
```

También actualizan cualquier dirección usada según el tamaño de la operación.
Esta actualización se hace de acuerdo con el valor de la **bandera de dirección (DF)**:

- Si la `DF` está borrada, las direcciones _aumentan_ según el tamaño de la operación.
- Si la `DF` está establecida, las direcciones _disminuyen_ en esa misma cantidad.

El ABI de System V establece que la bandera de dirección se debe borrar al entrar a una función.
Por lo tanto, _el comportamiento predeterminado es que la memoria se lea y se escriba en orden ascendente de direcciones_.

La instrucción `cld` se puede usar para borrar la bandera de dirección, mientras que la instrucción `std` la establece:

```x86asm
lea r8, [rdi]
lea r9, [rsi]

movsq ; both rdi and rsi increase (because `DF` is cleared by default) by 8 (`q` for qword)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8

std ; sets `DF`
lodsw ; rsi decreases (because `DF` is set) by 2 (`w` for word)
; so now:
; rdi == r8 + 8
; rsi == r9 + 8 - 2 == r9 + 6

cld ; clears `DF`
stosd ; rdi increases (because `DF` is cleared) by 4 (`d` for dword)
; so now:
; rdi == r8 + 8 + 4 == r8 + 12
; rsi == r9 + 6
```

~~~~exercism/caution
El llamador espera que la `DF` esté borrada después de que retorne cualquier función llamada, según el ABI de System V.
Si alguna vez estableces la `DF`, asegúrate de borrarla antes de `ret`.
~~~~

### Rep

Aparte de esas, la instrucción **rep** no interactúa directamente con la memoria.
En cambio, se puede agregar como prefijo a las otras instrucciones mencionadas, _repitiendo_ esas instrucciones.

Cuando se le antepone `rep`, las instrucciones de string se repiten una cantidad de veces igual al valor de `rcx`.
Cada vez, el valor de `rcx` se reduce en `1`.
Ten en cuenta que el valor de `rcx` se debe establecer antes de usar la instrucción:

```x86asm
mov rcx, 4
rep movsq ; this repeats `movsq` 4 times
          ; it copies 4 * 8 == 32 bytes from a memory location indicated by `rsi` to a memory location indicated by `rdi`
```

~~~~exercism/advanced
En las CPU modernas, `rep movs` y `rep stos` suelen ser opciones rápidas cuando se mueven datos en bloques grandes.
Sin embargo, otras instrucciones de string, e incluso `movs` y `stos` cuando operan sin `rep`, suelen ser más lentas que un bucle simple.

Puedes encontrar una visión más detallada de este tema en [el capítulo 16.9, «String instructions», de este libro de referencia][agner-optimization-guide].
