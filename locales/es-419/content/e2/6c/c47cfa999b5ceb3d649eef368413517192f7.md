# Acerca de los bits

Los dígitos binarios, en última instancia, se corresponden directamente con los transistores de tu CPU o tu RAM, y con si cada uno está «encendido» o «apagado».

La manipulación de bajo nivel, llamada informalmente «bit-twiddling», es especialmente importante en los lenguajes de sistemas.

Los lenguajes de más alto nivel, como Kotlin, suelen abstraer la mayor parte de estos detalles. Sin embargo, un conjunto básico de operaciones a nivel de bits [está disponible][ref-bitwise].

~~~~exercism/note
Para ver una salida binaria legible para humanos, casi todos los ejemplos de abajo deben envolverse en una función [`Integer.toBinaryString()`][web-binstring], o convertirse con `toString(radix = 2)`.
 
Esto distrae visualmente, así que se han quitado la mayoría de las apariciones de esta función, y los resultados se representan con la notación `0b`.

## Operaciones de desplazamiento de bits

Los tipos `Int` o `Long`, tanto con signo como sin signo, se pueden representar como un String de unos y ceros y manipular como una secuencia de bits.

Aunque parezca sorprendente, los tipos `Byte` o `Short` no son compatibles con la mayoría de las operaciones a nivel de bits en Kotlin.
Todos los ejemplos de abajo usan enteros de 32 bits (`Int` o `UInt`).

```kotlin
val ns = 0b111  // 7 decimal
Integer.toBinaryString(ns)  // => "111"
```

Los desplazamientos de bits mueven todo hacia la izquierda o hacia la derecha una cantidad de posiciones determinada.
Algunos bits se caen por un extremo y el otro extremo se rellena con ceros o unos.

- Desplazamiento a la izquierda con `shl`: relleno con ceros.
- Desplazamiento a la derecha con `shr` o `ushr`: relleno con ceros para los números positivos (para los números negativos, consulta la sección más adelante).

```kotlin
val ns = 0b111  // 7 decimal
ns shl 1  // => 0b1110, decimal 14
ns shr 1  // => 0b11, decimal 3
ns ushr 1  // => 0b11

val nu: UInt = 0b111u  // 7 unsigned
nu shr 1  //  => 0b11
```

Cada desplazamiento a la izquierda duplica el valor, y cada desplazamiento a la derecha lo reduce a la mitad (con truncamiento).
Esto se ve más claro en la representación decimal:

```kotlin
3 shl 2  // => 12
24 shr 3 // => 3
```

Este tipo de desplazamiento de bits es mucho más rápido que la aritmética «normal», lo que hace que la técnica sea muy popular en la programación de bajo nivel.

### Desplazamiento de bits con enteros negativos

Con los _enteros negativos_ hay que tener un poco más de cuidado.

Los valores negativos se almacenan en forma de [complemento a dos][wiki-2complement], lo que significa que el bit más a la izquierda es 1.
No hay problema para un desplazamiento a la izquierda, pero al desplazar a la derecha, ¿cómo rellenamos los bits más a la izquierda?

```kotlin
val ns = -0b111  // => 0b11111111111111111111111111111001

// shift left: simple
ns shl 1  // => 0b11111111111111111111111111110010, decimal -14

// shift right: preserves sign bit
ns shr 1  // => 0b11111111111111111111111111111100, decimal -4

// unsigned shift right: left-pads with zeros
ns ushr 1 // => 0b01111111111111111111111111111100, decimal 2147483644
```

El operador [`shr`][ref-shr] realiza un [desplazamiento aritmético][wiki-arithmetic], que conserva el bit de signo.

El operador [`ushr`][ref-ushr] realiza un [desplazamiento lógico][wiki-logical], rellenando con ceros como si el número no tuviera signo.

## Lógica a nivel de bits

Vimos en el [concepto de Booleanos][concept-booleans] que los operadores `&&` (and), `||` (or) y `!` (not) se usan con valores booleanos.

Hay operadores equivalentes `and`, `or`, `xor` ([or exclusivo][wiki-xor]) para comparar los bits de dos enteros, y una función `inv` (inversión) para invertir todos los bits.

```kotlin
0b1011 and 0b0010 //  bit is 1 in both numbers
// => 0b0010

0b1011 or 0b0010 // bit is 1 in at least one number
// => 0b1011

0b1011 xor 0b0010 // bit is 1 in exactly one number, not both
// => 0b1001

0b1011.inv() // flip all bits (in a 32-bit signed Int)
// => 0b11111111111111111111111111110100
```
