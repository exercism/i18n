# Introducción

Gleam no usa excepciones para el manejo de errores; en su lugar, las funciones que pueden tener éxito o fallar devuelven el tipo genérico `Result`.

El tipo `Result` viene integrado en el lenguaje, así que no necesitas definirlo ni importarlo, pero si lo definieras tú mismo se vería así:

```gleam
pub type Result(value, error) {
  Ok(value)
  Error(error)
}
```

La variante `Ok` se devuelve cuando una función tiene éxito, y la variante `Error` se devuelve cuando una función falla.

Los resultados son muy comunes en Gleam, y quienes programan en Gleam suelen usar el [módulo `gleam/result`](https://hexdocs.pm/gleam_stdlib/gleam/result.html) para que trabajar con ellos sea más fácil.

La función `result.map` se puede usar para llamar a una función sobre el valor que está dentro de un resultado si es un `Ok`, o para dejar pasar un `Error` sin cambios.

```gleam
Ok(1)
|> result.map(fn(x) { x + 1 })
// -> Ok(2)

Error("Oh no!")
|> result.map(fn(x) { x + 1 })
// -> Error("Oh no!")
```

La función `result.try` es similar, pero se espera que la función de callback devuelva un resultado. Esto es útil para encadenar varias funciones que devuelven resultados.

```gleam
Ok(1)
|> result.try(fn(x) { Ok(x + 1) })
// -> Ok(2)

Ok(1)
|> result.try(fn(x) { Error("Nope!") })
// -> Error("Nope!")
```
