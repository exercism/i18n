# Bibliotecas

Exercism pretende enseñar [fluidez](/docs/using/product/fluency) en la sintaxis, los modismos y la biblioteca estándar del lenguaje.
Esto explícitamente _no_ menciona las bibliotecas externas (no integradas), ya que eso entra dentro del _dominio_.
Por lo tanto, los ejercicios deben, con pocas excepciones, poder resolverse sin usar bibliotecas.

## Razones para soportar bibliotecas

Hay un par de razones por las que un track todavía podría querer soportar bibliotecas:

1. El lenguaje tiene una biblioteca estándar (muy) mínima.
   Un ejemplo de ese lenguaje es Rust.
2. La biblioteca agrega funcionalidad de pruebas.
   Un ejemplo es una biblioteca que agrega soporte para pruebas basadas en propiedades.
3. El ejercicio solo se puede resolver usando una biblioteca.
   Un ejemplo de ese ejercicio es el [ejercicio lens-person](https://exercism.org/exercises/lens-person), que en la mayoría de los lenguajes solo se puede resolver usando una biblioteca.

## Soportar bibliotecas en el test runner

Como el test runner no tiene acceso a internet mientras se ejecuta, no es posible descargar bibliotecas en tiempo de ejecución.
La **única** solución a este problema es instalar/descargar las bibliotecas en tiempo de compilación, donde _sí_ tienes acceso a internet.
En la práctica, esto significa que tendrás que instalar/descargar las bibliotecas dentro del Dockerfile.

Como ejemplo, el [Dockerfile del test runner de Prolog](https://github.com/exercism/prolog-test-runner/blob/ed7447a7518ede6ee3405e649f50aaec828e318b/Dockerfile) instala la biblioteca `date_time`:

```dockerfile
RUN swipl pack install date_time -y
```

## Documentación

Si tu track soporta bibliotecas, esto debería documentarse en un [documento del track](/docs/building/tracks/docs).
Además, enlaza a este documento (usando su URL completa) desde el [documento `exercises/shared/.docs/help.md`](/docs/building/tracks/shared-files#file-help-md).
