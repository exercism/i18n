# Instrucciones

Cuanto más aprendes sobre programación, más empiezas a pensar que esto podría ser más que una simple moda.
Incluso podría haber algunas oportunidades de negocio: la gente escribe código, quiere guardarlo, compartirlo, colaborar y quizá hasta recibir algo de retroalimentación.

Muy bien, hagámoslo, construyamos un servicio para animar a la gente a programar: ¡hup, hup, gente, empiecen a usar git!
Lo llamaremos... GitHup.

Te pones a construir una API REST de JSON: usuarios, pull requests, comentarios, y el backend queda listo en un santiamén.
Este es un ejemplo del payload que se devuelve cuando le pides al servidor la lista de comentarios de un pull request:

```json

    "body": "Great stuff!",
    "side": "RIGHT",
    "_links": {
      "self": {
        "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1"
```

Por supuesto, el frontend se hará en Elm, pero primero necesitas entender de qué se tratan esos famosos decodificadores y codificadores.

```exercism/note
Aparte de la historia humorística, los requisitos del ejercicio están tomados directamente de los endpoints de la API REST de GitHub para los comentarios de revisión de pull requests.
Se eliminaron algunos campos de los esquemas JSON por simplicidad, pero esto es lo más cerca que se puede estar de una aplicación del mundo real.
```

## 1. ¡El ID, por favor!

Tu ojo de águila notó que tanto los comentarios como los usuarios tienen un campo `id`, un lugar perfecto para empezar.

Define `decodeId` para que pueda decodificar un objeto JSON con un `id` entero.

```elm
Decode.decodeString decodeId """{id: 10}"""
    --> Ok 10
```

## 2. ¿Cómo me llamo, ya se me olvidó?

Te das cuenta, en el ejemplo de arriba, de que no todos los usuarios tienen un nombre.

Define `decodeName` para que pueda decodificar un string en el campo `name` si es que hay uno.
¿No hay nombre? No hay problema, simplemente devuelve `Nothing`.
Este decodificador nunca debe fallar.

```elm
Decode.decodeString decodeName """{"id": 10, "name": "Otto"}"""
    --> Ok (Just Otto)

Decode.decodeString decodeName """null"""
    --> Ok Nothing
```

## 3. ¿User? ¡Apenas lo conozco!

Ya vamos más o menos a la mitad de la decodificación de usuarios, terminemos esto.

Define `decodeUser` para que pueda decodificar un objeto de usuario JSON.
Asegúrate de usar `decodeId` y `decodeName` en `decodeUser`.

```elm
Decode.decodeString decodeUser
    """
    {
      "id": 101,
      "login": "octodog",
      "avatar_url": "https://githup.com/images/error/octodog_happy.gif",
      "site_admin": false
    }
    """
    --> Ok
    -->   { id = 101
    -->   , name = Nothing
    -->   , login = "octodog"
    -->   , avatarUrl = "https://githup.com/images/error/octodog_happy.gif
    -->   , siteAdmin = False
    -->   }
```

## 4. Soy un comentario fuerte e independiente

Algunos comentarios en una revisión de pull request son independientes y, por lo tanto, no tienen un `pull_request_review_id`.
Sin embargo, la especificación menciona que, en tal caso, igual debe haber un campo `pull_request_review_id`, pero el valor debe ser `null`, el `Nothing` de los pobres.

Define `decodePullRequestReviewId` para que pueda decodificar un entero en el campo `pull_request_review_id` si es que hay uno.
Si no hay un entero, debe haber un `null`; si no hay un `null`, el decodificador debe fallar.

```elm
Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": 3}"""
    --> Ok (Just 3)

Decode.decodeString decodePullRequestReviewId """{"pull_request_review_id": null}"""
    --> Ok Nothing

Decode.decodeString decodePullRequestReviewId """{"id": 3}"""
    --> Err ...
```

## 5. Trabajo por el lado

Ahora sigue este interesante campo `side`.
En una revisión de pull request, puedes comentar sobre el código que se eliminó (en el lado `Left` de la pantalla) o sobre el código que se agregó (en el lado `Right` de la pantalla).

Define `decodeSide` para que pueda decodificar ya sea `"LEFT"` o `"RIGHT"` en el campo `side` y hacerlo coincidir con su variante de tipo correspondiente.

```elm
Decode.decodeString decodeSide """{"side": "LEFT"}"""
    --> Ok Left

Decode.decodeString decodeSide """{"side": "middle?"}"""
    --> Err ...
```

## 6. El despertar de Link

Cada comentario tiene un conjunto de enlaces, que no parece ser consistente entre comentarios.

Define `decodeLinks` para que pueda decodificar una colección de URLs en el campo `_links`.
Los nombres y la cantidad de enlaces pueden variar, asegúrate de poder contemplar eso.
Los enlaces en sí son objetos JSON que siempre deben tener un campo `href`.

```elm
Decode.decodeString decodeLinks """
    {
      "_links": {
        "self": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" },
        "html": { "href": "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" },
        "pull_request": { "href": "https://api.githup.com/repos/octodog/Hello-World/pulls/1" }
      }
    }
    """
    --> Ok
    -->   (Dict.fromList
    -->       [ ( "self", "https://api.githup.com/repos/octodog/Hello-World/pulls/comments/1" )
    -->       , ( "html", "https://githup.com/octodog/Hello-World/pull/1#discussion-diff-1" )
    -->       , ( "pull_request", "https://api.githup.com/repos/octodog/Hello-World/pulls/1" )
    -->       ]
    -->   )
```

## 7. Sí, comentarios

Ya casi llegamos, terminemos esto.

Define `decodeComment` y `decodeComments` para que puedan decodificar un único objeto de comentario JSON o una lista de comentarios, respectivamente.
Asegúrate de usar todas las funciones definidas hasta ahora en `decodeComment`, con la excepción de `decodeName`.
Por supuesto, `decodeComments` también debe usar `decodeComment`.

## 8. Y todo encaja

Todavía falta una funcionalidad más en todo esto: poder enviar un comentario nuevo al servidor.
Para esto, necesitas lograr lo opuesto a un decodificador: poder transformar un `Comment` de Elm en un `Value` de JSON.

Define `encodeComment` para que pueda codificar cualquier `Comment` válido.
El orden de los campos no importa, siempre que el codificador pueda producir un valor que `decodeComment` pueda decodificar.
