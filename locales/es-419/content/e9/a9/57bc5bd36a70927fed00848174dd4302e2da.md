# Introducción

Es hora de abordar uno de los paradigmas fundamentales de C++: la programación orientada a objetos (POO).
La POO gira en torno a `classes`, tipos de datos definidos por el usuario con su propio conjunto de funciones relacionadas.
Empezaremos con lo básico y cubriremos temas más avanzados más adelante en el árbol del temario.

## Miembros

Las clases pueden tener **variables miembro** y **funciones miembro**.
Se accede a ellas mediante el operador de **selección de miembros** `.`.
Igual que con las variables fuera de `classes`, es recomendable inicializar las variables miembro con un valor al declararlas.
Ese valor será entonces el predeterminado para los objetos que se creen a partir de esta clase.

## Encapsulamiento y ocultamiento de la información

Las clases ofrecen la opción de restringir el acceso a sus miembros.
Los dos casos básicos son `private` y `public`.
No se puede acceder a los miembros `private` desde fuera de la clase.
Se puede llamar libremente a los miembros `public`.
Todos los miembros son `private` de forma predeterminada y hay que marcarlos explícitamente para que se puedan usar fuera de la clase.

## Ejemplo básico

La definición de una nueva `class` se puede ver en el siguiente ejemplo.
Fíjate en el `;` después de la definición.

```cpp
class Wizzard {
  public:               // from here on all members are accessible publicly
    int cast_spell() {  // defines the public member function cast_spell
      return damage;
    }
    std::string name{}; // defines the public member variable `name`
  private:              // from here on all members are private
    int damage{5};      // defines the private member variable `damage`
};

```

Puedes acceder a todas las variables desde dentro de la clase.
Observa `damage` dentro de la función `cast_spell`.
No puedes leer ni cambiar los miembros `private` desde fuera de la clase:

```cpp
Wizzard silverhand{};
// calling the `cast_spell` function is okay, it is public:
silverhand.cast_spell();
// => 5

// name is public and can be changed:
silverhand.name = "Laeral";

// damage is private:
silverhand.damage = 500;
 // => Compilation error
```

## Constructores

Los constructores ofrecen la posibilidad de asignar valores a las variables miembro al crear un objeto.
Tienen el mismo nombre que la `class` y no tienen tipo de retorno.
Una clase puede tener varios constructores.
Esto es útil si no siempre necesitas asignar todas las variables.

```cpp
class Wizzard {
  public:
    Wizzard(std::string new_name) {
      name = new_name;
    }
    Wizzard(std::string new_name, int new_damage) {
      name = new_name;
      damage = new_damage;
    }
    int cast_spell() {
      return damage;
    }
    std::string name{};
  private:
    int damage{5};
};

Wizzard el{"Eleven"};       // deals  5 damage
Wizzard vecna{"Vecna", 50}; // deals 50 damage
```

Los constructores son un tema amplio y tienen muchos matices.
Si no defines explícitamente un `constructor` para tu `class`, entonces, y solo entonces, el compilador hará el trabajo por ti.
Eso es lo que pasó en el primer ejemplo de arriba.
El objeto _silverhand_ se crea llamando al constructor predeterminado, sin pasar ningún argumento.
Todas las variables se establecen en el valor que se indicó en la definición de la clase.
Si no hubieras dado ningún valor en esa definición, las variables podrían quedar sin inicializar, lo que podría tener consecuencias no deseadas.

## Estructuras

Las estructuras vienen de las raíces originales del lenguaje en C y son tan antiguas como el propio C++.
En efecto, son lo mismo que las `classes`, con una excepción importante.
De forma predeterminada, todo en una `class` es `private`.
Las estructuras, en cambio, son `public` hasta que se defina lo contrario.
Por convención, la palabra clave `struct` se usa a menudo para **estructuras de solo datos**.
Se prefiere la palabra clave `class` para objetos que necesitan garantizar ciertas propiedades.
Un invariante de ese tipo podría ser que el `damage` de tu `class` `Wizzard` no pueda volverse negativo.
La variable `damage` es privada y cualquier función que cambie el damage garantizaría que se preserve el invariante.
