# Introducción

Algunos bucles no se pueden escribir como «haz esto para cada elemento de una secuencia»: tienes que seguir hasta que alguna condición cambie. El combinador `while` de Factor es la herramienta para eso: una quotation de predicado dice «¿sigo?», una quotation de cuerpo hace el trabajo de un paso, y `while` repite hasta que el predicado dé `f`.

## `while` y `until`

```
while ( pred body -- )
until ( pred body -- )
```

`pred` y `body` son ambas quotations que operan sobre la pila de datos. `while` sigue iterando mientras `pred` deje un valor verdadero; `until` es lo contrario: sigue iterando *hasta* que `pred` se vuelva verdadero (es decir, mientras `pred` deje `f`).

Un solo dato de estado puede fluir en la pila entre el predicado y el cuerpo:

```factor
USING: kernel math ;

5 [ dup 0 > ] [ dup . 1 - ] while drop
! prints 5 4 3 2 1
```

Traza: el predicado `dup 0 >` mira el contador en curso; el cuerpo `dup . 1 -` lo imprime y lo decrementa; el bucle se detiene cuando el contador llega a `0`. El `drop` del final descarta ese `0` final de la pila.

## `while*`: conserva el valor del predicado

```
while* ( pred body -- )
```

A `while` solo le importa si su predicado dejó un valor verdadero: descarta ese valor antes de ejecutar el cuerpo. `while*`, en cambio, *le entrega ese valor al cuerpo*. Recurre a él siempre que la prueba y el cuerpo quieran lo mismo recién calculado: una búsqueda, una coincidencia, un token analizado.

En este ejemplo, cada nombre apunta al siguiente en una cadena. El predicado busca el nombre actual; mientras exista un nombre siguiente, `while*` se lo pasa al cuerpo, que lo imprime y continúa desde ahí:

```factor
USING: assocs kernel locals prettyprint ;

:: print-chain ( start links -- )
    start [ links at ] [ dup . ] while* ;

"a" H{ { "a" "b" } { "b" "c" } } print-chain
! prints "b" then "c"
```

`links at` devuelve el nombre siguiente, o `f` cuando un nombre no tiene entrada. Mientras devuelva un nombre, `while*` le da ese nombre a `dup .`, que lo imprime y lo deja como clave para la siguiente búsqueda. El primer `f` detiene el bucle, y `while*` lo descarta, así que no sobra nada.

## Varios valores de estado con variables locales

Cuando el bucle carga más de un valor (por ejemplo, un array restante y un total acumulado), hacer malabares con la pila se vuelve ruidoso. El patrón más limpio es declarar *variables locales* con `::`:

```
:: word ( inputs -- outputs ) ... ;
```

Dentro del cuerpo, `:> name!` agrega una variable local mutable; las lecturas usan `name` y las escrituras usan `name!` (que consume el valor nuevo de la pila y lo asigna).

```factor
USING: kernel locals math sequences ;

! Walk a sequence from the front, summing as we go
:: sum-by-hand ( seq -- total )
    seq :> rest!
    0   :> running!
    [ rest empty? ] [
        rest unclip [ rest! ] dip
        running + running!
    ] until
    running ;
```

Aquí, dos variables locales (`rest` y `running`) cubren todo el estado del bucle: el predicado las inspecciona, el cuerpo las actualiza y el valor final se devuelve al terminar.

`unclip ( seq -- rest first )` despega el primer elemento de una secuencia, lo que resulta útil cuando el bucle quiere consumir un array de a un elemento por iteración. La forma `[ rest! ] dip` actualiza `rest` a la cola restante y deja el elemento recién extraído en la pila para que el cuerpo lo use.
