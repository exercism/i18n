# Introducción

## Enumeraciones

Hasta ahora hemos manejado principalmente números y strings.
Para modelar el mundo real, podríamos querer una cantidad limitada de valores que una variable pueda tomar.
Quizás quieras un tipo dedicado con unos pocos valores distintos y con nombres distintos.
Por ejemplo, en una fábrica de patinetas, que el material de la tabla sea una elección de solo maple, bamboo o plastic.

Podrías usar enteros para codificar esos valores, pero tendrías que usar código extra para verificar si llega un valor inválido del sistema para el material.
El significado de esos [números mágicos][magic numbers] es difícil de rastrear en el código fuente y son propensos a confusiones.
Se pueden usar `enumerations` para fomentar código expresivo y para restringir errores de comparación no intencionales.

## Ejemplo de uso

El término específico para este tipo de enumeración es `scoped enumeration`.
El siguiente fragmento muestra cómo escribir una `enumeration` `DeckMaterial`.
Fíjate en la palabra clave `enum class` y el `;` al final de la definición:

```cpp
enum class DeckMaterial {
    maple,
    bamboo,
    plastic
};
```
Ahora, mira una función de precios en la tienda de patinetas y fíjate en el operador de resolución de ámbito (`::`) que especifica un `enumerator` de la `enumeration`:

```cpp
double deck_price(double base_price, DeckMaterial material) {
    if(material == DeckMaterial::plastic) {
        return base_price * 0.9;
    }
    return base_price * 1.3;
}
```

## Ámbito

Imagina que tienes una segunda `enumeration` para el material de las ruedas:

```cpp
enum class WheelMaterial {
    steel,
    clay,
    plastic
};
```
Aunque tanto las ruedas como la tabla pueden estar hechas de _plastic_, las dos no se pueden confundir.
Son _tipos_ diferentes: `DeckMaterial` plastic y `WheelMaterial` plastic.
Cada `enumeration` tendrá sus `enumerators` en su propio ámbito: su propio `namespace`.
Esta es la razón por la que se llaman `scoped enumerations`.

## Enumeraciones sin ámbito
Quizás estés pensando que, con el nombre `scoped`, también habría enumeraciones `unscoped`, y estarías en lo correcto.
`Unscoped enumerations` son cada vez menos populares porque todas comparten el mismo namespace global.
Debido a que se comparten, no podrías tener dos `unscoped enumerations` con los mismos `enumerators`, como _plastic_ en el ejemplo de arriba.

Además, `unscoped enumerations` se convierten implícitamente a enteros.
Mira el ejemplo de abajo para ver un resultado sorprendente:

```cpp
enum CitrusFruits {
    lemons,  // 0
    oranges, //1
};

enum IceCream {
    walnut,  // 0
    apples,  // 1
};

bool comparison{apples == oranges};
// => true

// Example from above:
bool comparison{DeckMaterial::plastic == WheelMaterial::plastic};
// => Does not compile!
```

Si quieres convertir `scoped enumerations` a enteros, puedes usar `static_cast<int>`.
