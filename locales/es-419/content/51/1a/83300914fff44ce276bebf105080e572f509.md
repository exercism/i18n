# Fundamentos de match

La expresión `match` permite comparar un valor fácilmente con una serie de patrones y luego ejecutar el código según el patrón que coincida.
Un patrón está formado por valores literales, nombres de variables, comodines y muchas otras cosas.

```rust
#[derive(Drop)]
enum Color {
    Red,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red => println!("The color is Red"),
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Yellow;
    print_color_type(color); // prints "The color is Yellow"
}
```

Para manejar varias líneas de código, el brazo de código del `match` debe ir entre llaves `{}`:

```rust
fn specified_color(color: Color) -> felt252 {
    let mut response: felt252 = '';

    match color {
        Color::Red => {
            response = 'You passed in Red';
        },
        Color::Yellow => {
            response = 'You passed in Yellow';
        },
        Color::Green => {
            response = 'You passed in Green';
        },
    }

    response
}
```

La expresión `match` también tiene la funcionalidad de vincularse a los valores que coinciden con el patrón.
Esto permite extraer el valor asociado de una variante de un enum.

```rust
#[derive(Drop, Debug)]
enum ColorType {
    Light,
    Dark,
}

#[derive(Drop)]
enum Color {
    Red: ColorType,
    Yellow,
    Green,
}

fn print_color_type(color: Color) {
    match color {
        Color::Red(state) => {
            println!("The color is Red");
            println!("The Color Type is {:?}", state);
        },
        Color::Yellow => println!("The color is Yellow"),
        Color::Green => println!("The color is Green"),
    }
}

fn main() {
    let color = Color::Red(ColorType::Dark);
    print_color_type(color);
}
```

Aquí extendemos la variante `Red` del enum `Color` para que tenga un enum asociado.
Con ayuda de la expresión `match`, podemos extraer el valor asociado: `state`.
Es simplemente un nombre de variable que se puede usar después en el brazo del código.

## Cómo hacer match con el tipo de enum `Option`

El enum `Option` integrado también se puede manejar con la expresión `match`.

Diseñemos una función que reciba un parámetro `Option<u8>`.
Si el parámetro recibido trae un valor, se le suma uno a ese valor; de lo contrario, la función debe devolver el valor `None` sin hacer ninguna operación.

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
        Option::None => Option::None,
    }
}

fn main() {
    let three: Option<u8> = Option::Some(3);
    let four: Option<u8> = add_one(three);
    let none = add_one(Option::None);

    println!("{three:?}"); // prints "Option::Some(3)"
    println!("{four:?}"); // prints "Option::Some(4)"
    println!("{none:?}"); // prints "Option::None(())"
}
```

> Nota: `{:?}` es una sintaxis de formato especial que permite imprimir una forma de depuración del parámetro que se pasa a la macro `println!`.
> Puedes encontrar más información al respecto en [The Cairo Book][debugging].

Una ventaja de usar el flujo de control `match` es su naturaleza exhaustiva: los patrones de los brazos deben cubrir _todas_ las posibilidades.
Considera la versión del ejemplo anterior que no maneja el caso `None`:

```rust
fn add_one(x: Option<u8>) -> Option<u8> {
    match x {
        Option::Some(val) => Option::Some(val + 1),
    }
     // this code does not compile, as we forgot to handle the `None` case
}
```

## Patrón que captura todo con el comodín `_`

Con los enums también podemos realizar acciones especiales para algunos valores concretos, pero para todos los demás valores realizar una acción predeterminada agregando un nuevo brazo con `_` como patrón en el último brazo de la expresión `match`.
El patrón `_` es un patrón especial que coincide con cualquier valor y no se vincula a ese valor.

La función `is_red` recibe un parámetro y devuelve `true` si el color es `Red` y `false` para cualquier otro color:

```rust
fn is_red(color: Color) -> bool {
    match color {
        Color::Red => true,
        _ => false,
    }
}
```

## Coincidencia de patrones con el operador `|`

La construcción de flujo de control `match` de Cairo permite comparar un valor con varios patrones usando el operador `|` (_or_).
Esto ayuda a simplificar el código.

Por ejemplo, usando el enum `Color`, queremos escribir una función que devuelva `true` para los colores `Red` o `Green` y `false` para los demás colores:

```rust
fn is_red_or_green(color: Color) -> bool {
    match color {
        Color::Red | Color::Green => true,
        _ => false,
    }
}
```

## Coincidencia de patrones con `felt252` y variables enteras

Es posible comparar variables `felt252` y enteras con un conjunto de valores.
Sin embargo, hay algunas restricciones:

- Solo se admiten enteros que quepan en un único `felt252` (es decir, `u256` no es compatible).
- El 0 debe ser el primer brazo.
- Cada brazo debe seguir un segmento secuencial, contiguo con los otros brazos.

Implementemos un juego de lanzar un dado de seis caras.
Al lanzar el dado, obtenemos un número entre 0 y 5.
Si el lanzamiento da 0, 1 o 2, ganas.
Si obtienes 3, tiras otra vez.
Con cualquier otro valor, pierdes:

```rust
fn toss(value: u8) {
    match value {
        0 | 1 | 2 => println!("you won!"),
        3 => println!("you can roll again!"),
        _ => println!("you lost...")
    }
}

fn main() {
    toss(2); // prints "you won!".
    toss(3); // prints "you can roll again!".
    toss(5); // prints "you lost...".
}
```

## Coincidencia con tuplas

Las tuplas también se pueden comparar con un conjunto de patrones.
Estos patrones se diseñan de forma similar a una tupla.

```rust
#[derive(Drop)]
enum DayType {
    Week,
    Weekend,
    Holiday
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn vending_machine_accept(c: (DayType, Coin)) -> bool {
    match c {
        (DayType::Week, _) => true, // accepts all coins during week day
        (_, Coin::Dime) | (_, Coin::Quarter) => true, // accepts only Dime or Quarter coin for all specified days
        (_, _) => false, // returns false for other instances
    }
}
```

En el último brazo del match, no importa si usamos `(_, _)` o solo el comodín `_` para coincidir con cualquier combinación de día y color, porque funcionalmente son lo mismo.
