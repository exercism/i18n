# Introducción a los here documents

En los scripts de Bash, un «here document» (o «heredoc») redirige varias líneas de entrada a un comando o programa, como si las escribieras directamente en la terminal.
Es una herramienta potente para incluir texto de varias líneas dentro de tus scripts sin necesidad de archivos externos ni de una manipulación compleja de strings.

## Características y sintaxis principales

1. Delimitador: un heredoc comienza con el operador `<<` seguido de una palabra delimitadora (a la que a menudo se le llama «marcador» o «terminador»).
   Este delimitador puede ser cualquier palabra que elijas, pero es común usar algo como `EOF`, `END` o `TEXT` para mayor claridad.
   Para que el código sea más legible, puedes usar algo descriptivo como delimitador, por ejemplo `END_INSTALLATION_INSTRUCTIONS`.

1. Contenido: después del `<< DELIMITER` inicial, escribes el contenido que quieres redirigir.
   Puede ser varias líneas de texto, código o cualquier otra cosa.

1. Terminación: el heredoc termina cuando la palabra delimitadora vuelve a aparecer en una línea por sí sola, sin espacios en blanco delante ni detrás.

## Sintaxis básica

```bash
command << DELIMITER
  Content line 1
  Content line 2
  ...
  Content line N
DELIMITER
```

## Cómo funciona

* Bash lee todas las líneas entre el `<< DELIMITER` inicial y el `DELIMITER` final.
* Bash conecta este contenido a la entrada estándar del comando.
* El comando procesa esta entrada como si viniera del teclado.

### Ejemplo 1: salida de texto simple

```bash
cat << EOF
This is the first line.
This is the second line.
This is the third line.
EOF
```

Salida:

```plaintext
This is the first line.
This is the second line.
This is the third line.
```

En este ejemplo:

* `cat` es el comando.
* `<< EOF` inicia el heredoc con `EOF` como delimitador.
* Las tres líneas de texto son el contenido.
* `EOF` por sí solo en una línea termina el heredoc.
* `cat` luego muestra el contenido que recibió.

### Ejemplo 2: uso con wc (conteo de palabras)

```bash
wc -l << END
Line 1
Line 2
Line 3
END
```

Salida:

```plaintext
3
```

Aquí, `wc -l` cuenta el número de líneas.
El heredoc proporciona las tres líneas como entrada.

### Ejemplo 3: pasar datos a un script

El script:

```bash
#!/usr/bin/env bash

# Script to process input
while IFS= read -r line; do
  echo "Processing: $line"
done
```

Llama al script desde un prompt interactivo de bash con un heredoc:

```bash
./your_script << MY_DATA
Item 1
Item 2
Item 3
MY_DATA
```

Salida:

```plaintext
Processing: Item 1
Processing: Item 2
Processing: Item 3
```

## Variaciones y características avanzadas

### Contenido literal

Bash realiza expansión de variables, sustitución de comandos y expansión aritmética dentro de un heredoc.
En este sentido, los heredocs se comportan como strings entre comillas dobles.

```bash
cat << EOF
The value of HOME is $HOME
The current date is $(date)
Two plus two is $((2 + 2))
EOF
```

Salida:

```plaintext
The value of HOME is /home/glennj
The current date is Thu Apr 24 13:47:32 EDT 2025
Two plus two is 4
```

Cuando el delimitador va entre comillas (simples o dobles), estas expansiones no ocurren.
El contenido se toma de forma literal.
Esto es como los strings entre comillas simples.

```bash
cat << 'EOF'
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
EOF
```

Salida:

```plaintext
The value of $HOME is not expanded here.
The result of $(date) is not executed.
Two plus two is calculated by $((2 + 2))
```

### Eliminar tabulaciones iniciales

Si usas `<<-` (con un guion al final) en lugar de `<<`, Bash eliminará los _caracteres de tabulación_ iniciales de cada línea del heredoc.
Esto es útil para indentar el contenido del heredoc dentro de tu script sin afectar la salida.

```bash
# Note, the leading whitespace is tab characters only, not spaces!
# The ending delimiter can have leading tabs as well.
cat <<- END
	This line has 1 leading tab.
	  This line has a leading tab and some spaces.
		This line 2 leading tabs.
	END
```

La salida se imprime con todas las tabulaciones iniciales eliminadas:

```plaintext
This line has 1 leading tab.
    This line has a leading tab and some spaces.
This line 2 leading tabs.
```

~~~~exercism/caution
El autor no recomienda este uso.
Si bien puede mejorar la legibilidad del script,

1. es fácil reemplazar accidentalmente los caracteres de tabulación por espacios (tu editor puede hacerlo automáticamente), y
1. es difícil notar la diferencia entre espacios y tabulaciones.
~~~~

## Cuándo usar here documents

* Entrada de varias líneas: cuando necesitas proporcionar varias líneas de texto a un comando.
* Archivos de configuración: incluir pequeños fragmentos de configuración dentro de un script.
* Generación de código: crear código sobre la marcha dentro de un script.
* Interacciones con scripts: simular la entrada del usuario para programas interactivos.
* Evitar archivos externos: cuando quieres evitar crear archivos temporales.

Un uso típico podría ser proporcionar un texto de ayuda:

```bash
#!/usr/bin/env bash

usage() {
    cat << END_USAGE
Refresh database tables.

usage: ${0##*/} [-h|--help] [-A|--no-archive]

where: --no-archive flag will _skip_ the archive jobs
END_USAGE
}

# ... parsing command line options here ...

if [[ $flag_help == "true" ]]; then
  usage
  exit 0
fi
```

## Posibles desventajas

* Los documentos incrustados grandes pueden hacer que tu código sea más difícil de leer.
  Puede ser mejor distribuir tu script con la documentación en archivos separados.
* Los here documents pueden romper el flujo del código.
  Puede que estés en una sección de código muy anidada cuando quieras pasar algo de texto a un programa.
  La indentación del heredoc puede verse chocante en comparación con el código que la rodea.

## Here strings

Al igual que los here documents, los _here strings_ (o «herestrings») proporcionan entrada a un comando.
Sin embargo, mientras que los heredocs se dan como un bloque de texto, los herestrings se dan como un solo string de texto.
Los here strings usan la sintaxis `<<< "text"`.

```bash
tr 'a-z' 'A-Z' <<< "upper case this string"
```

Salida:

```plaintext
UPPER CASE THIS STRING
```

A diferencia de los heredocs, no se requiere un delimitador final.

### ¿Por qué usar here strings?

Se puede usar una tubería en lugar de un here string:

```bash
echo "upper case this string" | tr 'a-z' 'A-Z'
```

Entonces, ¿por qué usar un here string?

Considera el caso en el que obtienes el string como salida de un cálculo que tarda mucho, y quieres pasar el resultado a dos comandos distintos.
Si usas tuberías, tienes que ejecutar el cálculo dos veces:

```bash
some_long_running_calculation | first_command
some_long_running_calculation | second_command
```

Un enfoque más eficiente es capturar la salida del cálculo (usando sustitución de comandos) y usar here strings para proporcionar entrada a los dos comandos siguientes:

```bash
result=$( some_long_running_calculation )
first_command <<< "$result"
second_command <<< "$result"
```

Aquí tienes una aplicación real de ese ejemplo:

* captura la respuesta JSON a una consulta a una API REST (que está paginada),
* proporciona los datos JSON a un programa jq para analizar los resultados y escribir eso en un archivo, y luego
* proporciona los datos JSON a otro programa jq para determinar la URL de la siguiente consulta.

```bash
# initialize the output CSV file
echo "ID,VALUE" > data.csv

url='https//example.com/api/query?page=1'

while true; do
  json=$( curl "$url" )

  # convert the results part of the response into CSV
  jq -r '.results[] | [.id, .value] | @csv' <<< "$json"

  # get the URL for the next page
  url=$( jq -r '.next_url // ""' <<< "$json" )
  if [[ "$url" == "" ]]; then
    break
  fi
done >> data.csv
```

Fíjate en la posición de la redirección de salida.
Toda la salida del bucle while se agregará al archivo `data.csv`.

## Heredocs y herestrings como redirección

Como no son más que formas de redirección, se pueden combinar con otras operaciones de redirección:

```bash
cat <<< END_OF_TEXT > output.txt
This is my important text.
END_OF_TEXT

awk '...' <<< "$my_var" >> result.csv
```

## En resumen

Los here documents (o «heredocs») son una forma flexible y cómoda de manejar la entrada de varias líneas en los scripts de Bash.
Simplifican el proceso de incluir texto y datos directamente dentro de tus scripts, lo que los hace más autónomos y más fáciles de leer.

Los here strings (o «herestrings») son como los here documents, pero ofrecen una sintaxis más simple y más dinámica.
