# Pruebas

Puedes ejecutar las pruebas con el siguiente comando en el directorio del ejercicio:

```bash
dub test
```

## Aprobar las pruebas

Haz que la primera prueba compile, se enlace y pase siguiendo las [tres reglas del desarrollo guiado por pruebas](http://butunclebob.com/ArticleS.UncleBob.TheThreeRulesOfTdd). Crea la estructura mínima necesaria declarando espacios de nombres, funciones, clases, etc., para resolver los errores del compilador y hacer que la prueba falle. Luego escribe el código mínimo necesario para que la prueba pase. Cuando lo hayas hecho, descomenta la siguiente prueba moviendo la línea que aparece a continuación hasta después de la prueba siguiente.

```D
static if (all_tests_enabled)
```

Esto puede provocar errores de compilación, ya que puede que se usen construcciones nuevas que todavía no has declarado ni definido. De nuevo, corrige los errores de compilación de forma mínima para obtener una prueba que falle; luego cambia el código de forma mínima para que la prueba pase, refactoriza tu implementación para que sea más legible y expresiva, y después pasa a la siguiente prueba.

Intenta usar las herramientas estándar de D en lugar de escribir a mano tus propios algoritmos o herramientas de bajo nivel.
