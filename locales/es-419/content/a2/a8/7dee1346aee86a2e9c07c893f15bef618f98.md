# Acerca de

## const

El modificador [`const`][constants] se puede aplicar (y, por lo general, se debería aplicar) a cualquier campo cuyo valor se conozca en tiempo de compilación y no cambie durante la vida del programa.

```csharp
private const int num = 1729;
public const string title = "Grand" + " Master";
```

El compilador te guiará sobre qué expresiones se pueden evaluar en tiempo de compilación. Se permiten las operaciones aritméticas sencillas, igual que la concatenación de strings. Esto excluye cualquier evaluación que requiera usar el montón o la pila, así que no tienes disponibles las llamadas a métodos ni las referencias a tipos no primitivos.

En la web hay cierto debate sobre las ventajas de rendimiento de `const` frente a las variables. Si se compara con campos de instancia que no son `const`, puede haber un ahorro de memoria apreciable, pero comparado con las variables estáticas es decididamente trivial. Es probable que tus colegas vean cualquier consideración sobre el rendimiento de la CPU como una [optimización prematura][premature-optimization].

Una razón más convincente para usar `const` es que mejora la capacidad de quien mantiene el código para razonar sobre él. Con solo ver que un campo está marcado como `const` o `readonly`, o que una propiedad no tiene setter, quien mantiene el código puede descartarlo en gran medida de su análisis. Es poco probable que sea el origen de bugs. Es poco probable que plantee dificultades en una refactorización. Este [comentario de Stack Overflow][so-consts] habla de esto.

El modificador `const` también se puede aplicar a valores dentro de los métodos:

```csharp
public double Area(double r)
{
    const double π = 3.142;
    return System.Math.Pow((π * r), 2);
}
```

Identificar un valor con `const` de esta manera puede ser útil si se usa varias veces en el método o si quieres llamar la atención sobre su significado. No hay ninguna mejora de rendimiento frente a usar los literales directamente en el código.

## readonly

El modificador [`readonly`][readonly-fields] se puede aplicar (y, por lo general, se debería aplicar) a cualquier campo que no se pueda convertir en `const`, cuyo valor no cambie durante la vida del programa y que se establezca con un inicializador en línea o durante la instanciación (por el constructor o por un método llamado por el constructor).

```csharp
private readonly int num;
private readonly System.Random rand = new System.Random();

public MyClass(int num)
{
    this.num = num;
}
```

Se recomienda usar el modificador `readonly` por las mismas razones que se aplican a `const`. La práctica de restringir los campos de esta manera ayuda a quienes mantienen el código a razonar sobre él.

Ten en cuenta que agregar el modificador `readonly` a un campo solo impide que se cambie el valor de ese campo. En el caso de los tipos agregados, no protege los campos ni las propiedades de ese tipo. En particular, no protege el contenido de los arrays.

```csharp
private readonly IList list = new List();

public void Foo()
{
    list = new List();  // does not compile

    list.Add("new stuff");  // succeeds at runtime
}
```

Para asegurarte de que todos los miembros de un tipo de referencia estén protegidos, puedes declarar los campos como `readonly` y definir propiedades automáticas sin un descriptor de acceso `set`.

Deberías echar un vistazo a las [colecciones de solo lectura][readonly-collections] de la biblioteca de clases base.

Para los arrays, lo más parecido a una versión de solo lectura que puedes conseguir es el método [`Array.AsReadOnly<T>()`][as-read-only].
