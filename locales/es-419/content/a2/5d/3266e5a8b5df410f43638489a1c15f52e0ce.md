# Tests

Cada ejercicio contiene un archivo de tests.
Ejecuta los tests con el programa `bats`.
```bash
bats test-hello-world.bats
```

Tendrás que instalar `bats`.
Consulta la página [Cómo ejecutar los tests en el track de Bash][bash] para ver las instrucciones de instalación de `bats` para tu sistema.

### bats está implementado en bash

El archivo de bats es un script de bash, con algunas funciones especiales que reconoce el comando `bats`.
Verás algunos tests que se ven así:
```sh
gawk -f some-exercise.awk <<< "some,input,here"
```
Esa sintaxis `<<<` es un [Here String][here-string] de bash.
Envía el string del lado derecho a la entrada estándar del programa del lado izquierdo.
Es ([aproximadamente][so]) lo mismo que
```sh
echo "some,input,here" | gawk -f some-exercise.awk
```

## Ayuda para las funciones assert

Los tests usan funciones de la librería [bats-assert][bats-assert].
Ahí encontrarás ayuda para las distintas funciones `assert*`.

## Tests omitidos

Resolver un ejercicio significa hacer que todos sus tests pasen.
Por defecto, solo se ejecuta un test (el primero) cuando ejecutas los tests.
Esto es intencional, ya que te permite enfocarte en hacer que solo ese test pase.
Una vez que pase, puedes habilitar el siguiente test si comentas o eliminas las

    [[ $BATS_RUN_SKIPPED == true ]] || skip

anotaciones que preceden a los otros tests.

## Anular las omisiones

Para ejecutar todos los tests, incluidos los que tienen anotaciones `skip`, puedes ejecutar:
```bash
BATS_RUN_SKIPPED=true bats test-some-exercise.bats
```

Puede ser conveniente usar una función envoltorio para ahorrar escritura: en `bash` puedes hacer lo siguiente:
```bash
bats() {
    BATS_RUN_SKIPPED=true command bats *.bats
}
```
Luego ejecuta los tests simplemente con:
```bash
bats
```

## Salida de depuración

```exercism/caution
Esto funciona localmente con `bats`, pero **no** en el editor en línea de Exercism.
```

Cuando ejecutas los tests, `bats` captura tanto stdout como stderr para compararlos con la salida esperada.
Si imprimes mensajes de depuración en stdout o stderr, se incluirán en la salida capturada y podrían hacer que el test falle.

Para imprimir información de depuración sin afectar los resultados de los tests, `bats` proporciona el descriptor de archivo **3** para este propósito.
Todo lo que se imprima en el archivo `/dev/fd/3` se mostrará durante la ejecución del test, pero no se incluirá en la salida capturada que se usa para las aserciones.

Ejemplo:

```awk
BEGIN {
    # This debug message will not interfere with test output comparison
    print "a debug message" > "/dev/fd/3"

    # Normal program output (this is what your tests will see and compare)
    print "Hello, World!"
}
```

Ejemplo de ejecución:

```none
$ bats test-hello-world.bats
test-hello-world.bats
 ✓ Say Hi!
a debug message

1 test, 0 failures
```

Esto te permite ver una salida de depuración útil sin afectar los tests.

Ocultar los detalles en una función puede mejorar la legibilidad si la usas en varios lugares de tu código:

```awk
BEGIN {
    debug("starting ...")
}

# do stuff here ...

END {
    debug("... finished")
}

function debug(msg) {print msg > "/dev/fd/3"}
```
