## Errores en `jq`

`jq` reporta dos grandes categorías de errores:

1. **Errores en tiempo de compilación**: el programa mismo no es válido, por ejemplo por errores de sintaxis o por referencias a funciones o variables no definidas.
   `jq` se niega a ejecutar el programa por completo.

   ```sh
   $ jq -n '1 + $foo + 2'
   jq: error: $foo is not defined at <top-level>, line 1, column 5:
       1 + $foo + 2
           ^^^^
   jq: 1 compile error
   ```

2. **Errores en tiempo de ejecución**: el programa es válido, pero algo sale mal mientras se procesa un valor; por ejemplo, indexar un número con un string, analizar texto JSON no válido con `fromjson` o llamar a una función con argumentos de un tipo incorrecto.

   ```sh
   $ echo '42' | jq '.foo'
   jq: error (at <stdin>:1): Cannot index number with "foo"
   ```

Este concepto trata de los **errores en tiempo de ejecución**: cómo lanzarlos, cómo capturarlos y cómo detenerlos.

Un error en tiempo de ejecución que no se captura hace que `jq` imprima un mensaje en la _salida de error estándar_ y termine con el estado `5`.

## Lanzar errores: `error` y `error(message)`

El filtro [`error`][man-error] lanza un error.

- `error` lanza un error cuyo valor es el valor de **entrada**.
- `error(message)` lanza un error cuyo valor es el resultado de `message`.

```jq
"bad input" | try error catch .
# => "bad input"

42 | try error("invalid value: \(.)") catch .
# => "invalid value: 42"
```

~~~~exercism/note
El valor del error puede ser _cualquier_ valor JSON, no solo un string.
Lanzar errores estructurados permite que un manejador de `catch` tome decisiones a partir del contenido del error.

```jq
try error({kind: "range", msg: "age must be non-negative"})
catch (if type == "object" then "\(.kind) error: \(.msg)" else "unexpected: \(.)" end)
# => "range error: age must be non-negative"
```
~~~~

Si un valor de error que no es un string no se captura, `jq` lo imprime como JSON, marcado con `(not a string)`.

```sh
$ jq -n 'error({code: 42, msg: "boom"})'
jq: error (at <unknown>) (not a string): {"code":42,"msg":"boom"}
```

## Capturar errores: `try` y `catch`

Los errores se pueden capturar con [`try EXP catch HANDLER`][man-try-catch].
Se ejecuta la primera expresión; si lanza un error, se ejecuta la expresión `HANDLER` **con el valor del error como su entrada**.
La salida del manejador se emite como si hubiera sido la salida de la expresión probada.

```jq
true | try .a catch "cannot index a \(type)"
# => "cannot index a boolean"

[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]

true | try error("some exception") catch .
# => "some exception"
```

La forma más corta `try EXP` equivale a `try EXP catch empty`: el error se descarta y no se produce ninguna salida.

```jq
[{}, true, {"a": 1}] | [.[] | try .a]
# => [null, 1]
```

~~~~exercism/note
Un error **interrumpe el resto del flujo** dentro del `try`.
Los valores que ya se produjeron se conservan, pero nada de lo que viene después del error se evalúa.

```jq
jq -n 'try (1, error("x"), 3) catch "caught: \(.)"'
# outputs:
# 1
# "caught: x"
# (3 is never produced)
```
~~~~

Un manejador puede lanzar un error nuevo, o volver a lanzar el original con un `error` simple; como el valor del error es la entrada del manejador, esto lo propaga sin cambios.

```jq
try repeat(f) catch
  if . == "break" then empty else error end
```

## Suprimir errores: el operador `?`

El [operador `?`][man-question-mark], usado como `EXP?`, es una forma abreviada de `try EXP`.
Convierte una expresión que falla en una que simplemente no produce ninguna salida.

```jq
["1", "invalid", "3", 4] | [.[] | tonumber?]
# => [1, 3, 4]

true | [.a?]
# => []
```

A menudo se ve junto a los operadores de indexación:

- `.foo?` es `.["foo"]?`
- `.[]?` itera solo si la entrada es un array o un objeto, y no produce nada en caso contrario

~~~~exercism/caution
`?` suprime **todos** los errores, incluidos los que no anticipaste.
`user.name?` no produce nada de forma silenciosa cuando `user` no es un objeto, lo que puede ocultar problemas en los datos o errores de escritura en tu programa.
Prefiere `try ... catch` cuando necesites saber _que_ algo falló, o valida la entrada de forma explícita.
~~~~

## El operador alternativo `//`

A veces los programadores esperan que `a // b` produzca `b` cuando `a` falla.
Eso era cierto en versiones antiguas de `jq`, pero no desde `jq` 1.6.
El operador `//` no suprime errores.
Solo sustituye por `b` cuando `a` no produce ningún valor, o produce `false` o `null`; los errores en `a` se siguen propagando.

```sh
$ jq -n '(error("x")) // 42'
jq: error (at <unknown>): x
```

Usa `try a catch b` si quieres una alternativa para los errores.

## El operador alternativo de desestructuración `?//`

El [operador `?//`][man-question-mark-slash-slash] combina la desestructuración con el manejo de errores.
Prueba cada patrón de enlace en orden hasta que uno funcione, y las variables enlazadas por las alternativas que fallan quedan en `null`.

```jq
# input:
#   [
#     {"a": 1, "b": 2, "c": {"d": 3, "e": 4}},
#     {"a": 5, "b": 6, "c": [{"d": 7, "e": 8}]}
#   ]

.[] as {$a, $b, c: {$d, $e}} ?// {$a, $b, c: [{$d, $e}]}
| {$a, $b, $d, $e}

# outputs:
# {"a": 1, "b": 2, "d": 3, "e": 4}    # first element: c is an object, first pattern matched
# {"a": 5, "b": 6, "d": 7, "e": 8}    # second element: c is an array, second pattern matched
```

Aquí el primer patrón espera que `c` sea un _objeto_ con las claves `d` y `e`, mientras que el segundo espera que `c` sea un _array_ que contenga un objeto así.
El primer elemento de entrada se enlaza con el primer patrón; el segundo elemento falla con ese patrón, así que se prueba el segundo en su lugar.

Esto permite que un solo programa desestructure entradas que pueden tomar una de varias formas, sin escribir cadenas explícitas de `if type == ...`.

## Detener el programa: `halt` y `halt_error`

A veces la respuesta correcta ante un error es dejar de procesar por completo.

- [`halt`][man-halt] detiene el programa `jq` de inmediato y sin más salida; el estado de salida es `0`.
- [`halt_error`][man-halt-error] detiene el programa, imprime su **entrada** en la _salida de error estándar_ como texto sin formato (sin adornos, ni siquiera un salto de línea) y termina con el estado indicado, que por defecto es `5`.

```sh
$ echo '"Error: something went wrong"' | jq 'halt_error(1)'
Error: something went wrong    # printed on stderr, exit status 1
```

Fíjate que estos filtros detienen el programa de inmediato, incluso si quedan más entradas por leer.

### Estados de salida

Como referencia, `jq` usa estos estados de salida:

| Estado | Significado                                      |
| :----: | ------------------------------------------------ |
| `0`    | éxito                                            |
| `2`    | error de uso (opciones de línea de comandos incorrectas) |
| `3`    | error de compilación                             |
| `5`    | error en tiempo de ejecución (o `halt_error` sin argumento) |

Con la opción `--exit-status` / `-e`, el estado refleja en cambio el último valor de salida: `0` para `true` o números, `1` para `false` o `null`, `4` cuando no hay salida.

## Ayudas para depurar

Cuando estés rastreando de dónde viene un error, estos filtros te ayudan:

- [`debug`][man-debug] deja pasar su entrada sin cambios, pero imprime `["DEBUG:", <input>]` en la salida de error estándar.
  `debug(msgs)` también imprime `msgs` como mensajes de depuración.
- [`stderr`][man-stderr] imprime su entrada, sin formato y compacta, en la salida de error estándar.
- [`input_line_number`][man-input-line-number] genera el número de línea de la entrada que se está filtrando en ese momento; resulta muy útil cuando un archivo contiene muchos textos JSON y uno de ellos está mal.
- [`$__loc__`][man-loc] genera un objeto con las claves `file` y `line` que describen dónde aparece en el programa, y que se puede incluir en los mensajes de error.

```jq
def checked_div($d):
  if $d == 0
  then error("\($__loc__): division by zero")
  else . / $d end;

try (10 | checked_div(0)) catch .
# => "{\"file\":\"<top-level>\",\"line\":3}: division by zero"
```
