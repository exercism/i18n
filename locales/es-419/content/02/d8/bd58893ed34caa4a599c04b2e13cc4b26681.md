# Acerca de

Para lo básico sobre los argumentos de función, consulta el [concepto de función][function concept].

## Nombres de parámetros

Los nombres de los parámetros, igual que los nombres de las variables, deben empezar con una letra o un guion bajo y pueden contener letras, guiones bajos o números.
Los nombres de los parámetros no deben contener espacios ni signos de puntuación.

## Argumentos posicionales

Los argumentos posicionales son valores que se pasan a una función en el mismo orden que los parámetros a los que se vinculan.
De manera opcional, los argumentos posicionales se pueden pasar usando el nombre de su parámetro:


```python
def concat(greeting, name):
    return f"{greeting}{name}"

# Passing data to the function by position.
print(concat("Hello, ", "Lilly"))
#->  Hello, Lilly

# Passing data to the function using the parameter name.
print(concat(name="Glenn", greeting="Hello, "))
#-> Hello, Glenn
```

La primera llamada a `concat` pasa los argumentos por posición.
La segunda llamada a `concat` pasa los argumentos por nombre, lo que permite cambiar sus posiciones.

Ten en cuenta que los argumentos posicionales no pueden ir después de los argumentos pasados por nombre (_también llamados [argumentos por palabra clave][keyword-arguments]. **No** se deben confundir con los parámetros var-positional ni con [**kwargs][kwargs]**).

Este conjunto de argumentos:

```python
print(concat(greeting="Hello, ", "Gregor"))
```

Produce este error:

```
SyntaxError: positional argument follows keyword argument
```

Para exigir que los argumentos sean solo posicionales en las llamadas a la función, puedes usar el operador `/` en la lista de parámetros:

```python
# Parameters showing a position-only operator. 
def concat(greeting, name, /):
    return f"{greeting}{name}"

print(concat("Hello, ", "Ginnie"))
#-> Hello, Ginnie

# Call to the function using keyword arguments.
print(concat(name="Franklin", greeting="Hello, "))
Traceback (most recent call last):
    print(concat(name="Franklin", greeting="Hello, "))
TypeError: concat() got some positional-only arguments passed as keyword arguments: 'greeting, name'
```

## Argumentos por palabra clave

Los argumentos por palabra clave usan el nombre del parámetro al llamar a una función.
De manera opcional, se pueden indicar por su posición:

```python
def concat(greeting, name):
    return f"{greeting}{name}"

# Function call using parameter names as argument keywords.
print(concat(name="Eliza", greeting="Hello, "))
#-> Hello, Eliza

# Function call with positional data as arguments.
print(concat("Hello, ", "Tim"))
#-> Hello, Tim
```

Para exigir que los argumentos sean solo por palabra clave en las llamadas a la función, puedes usar el operador `*` en la lista de parámetros:

```python
# Function definition requiring keyword-only arguments.
def concat(*, greeting, name):
    return f"{greeting}{name}"

# Keyword arguments can be in an arbitrary order.
print(concat(name="Kimmie", greeting="Hello, "))
#-> Hello, Kimmie

# Calling the function with positional data raises an error.
print(concat("Hello, ", "Coleen"))
Traceback (most recent call last):
    print(concat("Hello, ", "Coleen"))
TypeError: concat() takes 0 positional arguments but 2 were given
```

## Valores predeterminados de los argumentos

Puedes proporcionar valores predeterminados para uno o más argumentos en la lista de parámetros.
Esto permite llamar a la función con _menos_ argumentos si es necesario.
Los valores predeterminados se pueden sobrescribir llamando a la función con un nuevo valor de argumento, reemplazando así el valor predeterminado:

```python
# Function with default argument values.
def concat(greeting, name="you", punctuation="!"):
    return f"{greeting}, {name}{punctuation}"

print(concat("Hello"))
#-> Hello, you!

# Overriding the default values
print(concat("Hello", name="Polly", punctuation="."))
#-> Hello, Polly.
```


## Argumentos posicionales o por palabra clave

Los argumentos pueden ser posicionales o por palabra clave si no se usan los operadores `/` ni `*` en las definiciones de los parámetros.
Como alternativa, los argumentos posicionales o por palabra clave se pueden colocar entre los parámetros solo posicionales de la izquierda y los parámetros solo por palabra clave de la derecha:

```python
# Position-only argument followed by position-or-keyword, followed by keyword-only.
def concat(greeting, /, name, *, ending):
    return f"{greeting}{name}{ending}"

print(concat("Hello, ", "Mark", ending="!"))
#-> Hello, Mark!

print(concat("Hello, ", name="Rachel", ending="!"))
#-> Hello, Rachel!

print(concat(greeting="Hello, ", name="JoJo", ending="!"))
Traceback (most recent call last):
    print(concat(greeting="Hello, ", name="JoJo", ending="!"))
TypeError: concat() got some positional-only arguments passed as keyword arguments: 'greeting'
```


## `*args`

Los ejemplos de código suelen usar una definición de función parecida a la siguiente:

```python
def my_function(*args, **kwargs):
    # code snipped
```

`*args` es un nombre de dos partes que representa una `tuple` con un número indefinido de argumentos posicionales separados, también conocidos como [`variadic argument`][variadic argument].
`args` es el nombre que se le da a la `tuple` de argumentos, pero podría ser cualquier otro nombre válido en Python, como `my_args`, `arguments`, etc.
El `*` es el operador que transforma el grupo de argumentos separados en una [`tuple`][tuple].

~~~~exercism/note
Si alguna vez has [desempaquetado una tupla][unpack-a-tuple], puede que el `*` de `*args` te resulte confuso.
El `*` en la definición de un _parámetro_, en lugar de desempaquetar una tupla, convierte uno o más argumentos posicionales _en_ una tupla.

Decimos que el operador `*` está [_sobrecargado_][overloading], ya que se comporta de manera distinta según el contexto.
Por ejemplo, `*` se usa para la multiplicación, se usa para desempaquetar y se usa para definir un número arbitrario de parámetros posicionales.

[overloading]: https://therenegadecoder.com/code/abusing-pythons-operator-overloading-feature/
[unpack-a-tuple]: https://www.geeksforgeeks.org/unpacking-a-tuple-in-python/
~~~~
    
Como se puede iterar sobre una `tuple`, `args` se puede pasar a cualquier otra función que acepte un iterable.
Aunque `*args` suele aparecer junto a `**kwargs`, no tiene por qué ser así:


```python
def add(*args):
    # args is passed to the sum function, which iterates over it.
    return sum(args)

print(add(1, 2, 3))
#-> 6
```

Si `*args` va después de uno o más argumentos posicionales, entonces `*args` será lo que quede después de los argumentos posicionales:


```python
def add(first, *args):
    # first will be 1, leaving the values 2 and 3 in *args
    return first + sum(args)

print(add(1, 2, 3))
#-> 6
```

Si se definen uno o más [argumentos predeterminados][default arguments] después de `*args`, son independientes de los valores de `*args`:


```python

def add(first, *args, last=0):
    return first + sum(args) + last
 
print(add(1, 2, 3))
#-> 6

print(add(1, 2, 3, last=4))
#-> 10

# This uses the unpacking operator * to separate the list elements into positional arguments.
# It does not have the same behavior as the * (packing) in *args.
print(add(*[1, 2, 3]))
#-> 6
```

Ten en cuenta que cuando un argumento ya está dentro de un `iterable` (_como una `tuple` o una `list`_), hay que [_desempaquetarlo_][unpacking-and-multiple-assignment] antes de pasarlo a una función que acepta un número arbitrario de argumentos separados.
Esto se logra usando `*`, que es el [operador de desempaquetado][unpacking operator].

En este contexto, `*` _desempaqueta_ el contenedor en sus elementos separados, que luego `*args` transforma en una `tuple`.
Cuando solo hay argumentos posicionales, la acción de desempaquetado debe dar como resultado la misma cantidad de argumentos que de parámetros formales definidos.

Si no se desempaqueta la lista que se pasa a `add`, el programa daría un error:

```python
def add(first, *args, last=0):
    return first + sum(args) + last

print(add([1, 2, 3]))
Traceback (most recent call last):
    print(add([1, 2, 3]))
    return first + sum(args) + last
TypeError: can only concatenate list (not "int") to list
```


## `**kwargs`

`**kwargs` es un nombre de dos partes que representa un número indefinido de argumentos [clave-valor][key-value] separados.
`kwargs` es el nombre del grupo de argumentos y podría ser cualquier otro nombre, como `my_args`, `arguments`, etc.
El `**` transforma el grupo de argumentos con nombre en un [`dictionary`][dictionary] de pares `{argument name: argument value}`.

Como se puede iterar sobre un diccionario, `kwargs` se puede pasar a cualquier otra función que acepte un iterable.
Aunque `**kwargs` suele aparecer junto a `*args`, no tiene por qué ser así:


```python
def add(**kwargs):
    return sum(kwargs.values())

print(add(one=1, two=2, three=3))
#-> 6
```

Ten en cuenta que se llama al método `dict.values()` para iterar por los `values` del diccionario `kwargs`.
Cuando se itera sobre un diccionario, lo predeterminado es iterar por las _`keys`_, así que hay que especificar `dict.values()` de forma explícita:

```python
def concat(**kwargs):
    # Join concatenates the tuples from `kwargs.items()`
    return " ".join((str(item) for item in kwargs.items()))

print(concat(one=1, two=2, three=3))
#-> ('one', 1) ('two', 2) ('three', 3)
```
