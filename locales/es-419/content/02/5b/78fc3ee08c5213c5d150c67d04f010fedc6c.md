# Sugerencias

`Option` se usa para indicar un cálculo que posiblemente no tenga un resultado útil
(por ejemplo, debido a un error o a una entrada no válida).
Si `Option` no te resulta familiar, puedes leer [este tutorial](http://danielwestheide.com/blog/2012/12/19/the-neophytes-guide-to-scala-part-5-the-option-type.html).
`Option` es lo que se llama una [mónada](https://en.wikipedia.org/wiki/Monad_(functional_programming)), que abarca un «aspecto computacional», en este caso la posible ausencia de un valor.
El uso correcto de las mónadas puede dar como resultado un código muy conciso pero elegante
y legible. El uso incorrecto puede dar fácilmente lo contrario.
Mira [este video](https://www.youtube.com/watch?v=Mw_Jnn_Y5iA) para aprender más.
## Trampas comunes que debes evitar
Hay algunas reglas generales para `Option`:
1. Si no lo necesitas, no lo uses. En lugar de
```scala
def add1(x: Int): Option[Int] = Some(x + 1)
```
es mejor tener
```scala
def add1(x: Int): Int = x + 1
```
(existe `Option.map` para aplicar ese tipo de funciones simples,
así que no tienes que llenarlas con `Option`).
2. No «desenvuelvas» si en realidad no lo necesitas.
A menudo existen funciones integradas para lo que necesitas. Señales de un
desenvolvimiento prematuro son `isDefined/isEmpty` o la coincidencia de patrones. En lugar de
```scala
val x: Option[Int] = ...

if (x.isDefined) x.get + 1 else 0
// or
x match {
  case Some(n) => n + 1
  case None => 0
}
```
es mejor tener
```scala
x map (_ + 1) getOrElse 0
```
3. Las mónadas se pueden usar dentro de una for-comprehension, ¡es lo mejor!
Esto es recomendable cuando quieres «componer» varias instancias de `Option`. En lugar de
```scala
val xo: Option[Int] = ...
val yo: Option[Int] = ...
val zo: Option[Int] = ...

xo.flatMap(x =>
  yo.flatMap(y =>
    zo.map(z =>
	  x + y + z)))
```
es mejor tener
```scala
for {
  x <- xo
  y <- yo
  z <- zo
} yield x + y + z
```
