# Acerca de

Las funciones recursivas son funciones que se llaman a sí mismas.

Una función recursiva necesita tener al menos un _caso base_ y al menos un _caso recursivo_.

Un _caso base_ devuelve un valor sin volver a llamar a la función.
Un _caso recursivo_ vuelve a llamar a la función, modificando el argumento para que en algún momento coincida con el caso base.

En Elm, las funciones recursivas se definen normalmente usando coincidencia de patrones con expresiones `case`.

```elm
count : List a -> Int
count list =
    case list of
        [] ->
            0  -- base case

        _ :: tail ->
            1 + count tail  -- recursive case
```

Una función recursiva puede tener muchos casos base y/o muchos casos recursivos.
Por ejemplo, [la sucesión de Fibonacci][fibonacci] es una sucesión recursiva con dos casos base:

```elm
fibonacci : Int -> Int
fibonacci n =
    case n of
        0 ->
            0

        1 ->
            1

        _ ->
            fibonacci (n - 1) + fibonacci (n - 2)
```

Ten en cuenta que esta implementación en particular es exponencialmente lenta, ya que los números de Fibonacci relacionados se calculan desde cero en dos llamadas recursivas independientes.

Contar cuántas veces aparece un valor dado `x` en una lista tiene dos casos recursivos:

```elm
countOccurrences : List a -> a -> Int
countOccurrences list x =
    case list of
        [] ->
            0

        head :: tail ->
            if head == x then
                1 + countOccurrences tail x
            else
                countOccurrences tail x
```

## Bucles mediante recursión

Debido a la inmutabilidad, los bucles en Elm se escriben de forma distinta a como se escriben en los lenguajes imperativos.
Por ejemplo, los bucles suelen verse así:

```c
for(i = 0; i < array.length; i++) {
  // do something with array[i]
}
```

En un lenguaje funcional como Elm, no es posible mutar variables.
Por eso, los bucles tienen que implementarse con recursión.

El equivalente de un bucle `for` en Elm se vería así:

```elm
loop : List a -> (a -> b) -> List b
loop list f =
    case list of
        [] ->
            []

        head :: tail ->
            f head :: loop tail f
```

En la práctica, para recorrer listas y otras estructuras de datos en Elm lo más habitual es usar funciones del módulo [`List`][module-list], como `List.map`, `List.filter` y `List.foldl`.
Por dentro, estas funciones están implementadas con recursión.

## Ejecución infinita

Las funciones recursivas, si se implementan mal o si el número de llamadas recursivas es demasiado grande, podrían no devolver nunca su resultado.
Esto puede ser problemático porque cada vez que se llama a una función, se guarda en memoria una referencia del lugar al que el entorno de ejecución debe devolver el resultado (en la [pila de llamadas][wiki-call-stack]).
Si una función recursiva se llama a sí misma demasiadas veces o incluso de forma infinita, es posible quedarse sin memoria y provocar que el entorno de ejecución falle (un [error de desbordamiento de pila][wiki-stack-overflow]).
El entorno de ejecución de Elm está optimizado para la recursión y la fiabilidad, pero la recursión infinita aún puede causar problemas.

Este problema de ejecución infinita puede deberse a:

- Olvidar implementar un caso base.
- No manejar todos los casos posibles en la coincidencia de patrones.
- No modificar bien el argumento al hacer la llamada recursiva, y por lo tanto no llegar nunca al caso base.
