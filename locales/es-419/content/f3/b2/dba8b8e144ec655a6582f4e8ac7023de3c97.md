# Instrucciones

Estás escribiendo el firmware para el sistema de puntuación de una consola portátil retro.
El CPU de la máquina es modesto, y la pantalla del marcador se actualiza a una tasa fija.
Para que la imagen se mantenga fluida, las rutinas de puntuación deben ejecutarse en un número predecible de ciclos, sin importar lo que esté haciendo el jugador.

Tienes cuatro tareas.

~~~~exercism/note
El código de las tareas debe ser sin ramas.
Usa `cmovcc`, `setcc` y aritmética en lugar de saltos condicionales.
~~~~

## 1. Agrega un bonus sin desbordar la pantalla

La región de puntuación de la LCD de la consola portátil tiene espacio para seis dígitos decimales.
No puede mostrar ningún número mayor que `999999`.
Cuando un bonus llevaría el total acumulado más allá de ese límite, el total mostrado se mantiene en el máximo en lugar de reiniciarse.

Define una función `add_bonus` que, dado un total actual y un bonus que se debe agregar, devuelve el nuevo total acotado a `999999`.
Los argumentos, en orden, son:

1. `total`: el total de puntuación actual (siempre entre `0` y `999999`)
2. `bonus`: el bonus que se debe agregar (siempre no negativo)

El valor devuelto es `total + bonus` si esa suma es menor o igual que `999999`, y `999999` en caso contrario:

```c
add_bonus(500, 100);
// => 600
add_bonus(999990, 50);
// => 999999
add_bonus(999999, 0);
// => 999999
```

Tanto los argumentos como el valor devuelto son enteros con signo de 64 bits.

~~~~exercism/note
Puedes suponer que `total + bonus` no desborda un entero con signo de 64 bits.
~~~~

## 2. Compara dos puntuaciones

La consola portátil guarda una pequeña tabla de clasificación con las mejores puntuaciones recientes del jugador en su archivo de guardado.
Después de cada partida, la nueva puntuación se inserta en la tabla de clasificación en la posición correcta.
La rutina de ordenamiento pregunta cuál de dos puntuaciones va primero y espera la respuesta como un entero pequeño.

Define una función `compare_scores` que, dadas dos puntuaciones, devuelve:

- `+1` si la primera puntuación es _mayor_
- `-1` si la primera puntuación es _menor_
- `0` si las dos puntuaciones son _iguales_

Ejemplo:

```c
compare_scores(500, 300);
// => 1
compare_scores(300, 500);
// => -1
compare_scores(500, 500);
// => 0
```

Tanto los argumentos como el valor devuelto son enteros con signo de 64 bits.

## 3. Valida una puntuación sin procesar

La consola portátil puede conectarse a otra unidad a través de su cable de enlace para compartir puntuaciones después de una partida multijugador.
El cable tiene ruido eléctrico y los bytes entrantes se corrompen ocasionalmente, produciendo valores muy por debajo del mínimo legal o muy por encima del máximo legal.
El validador acota cada puntuación entrante al rango legal antes de que el resto del sistema la vea.

Define una función `validate_score` que, dada una puntuación sin procesar y los límites legales, devuelve la puntuación acotada a `[min, max]`.
Los argumentos, en orden, son:

1. `score`: la puntuación sin procesar recibida por el cable de enlace
2. `min`: la puntuación más pequeña permitida
3. `max`: la puntuación más grande permitida

El valor devuelto es `min` si `score < min`, `max` si `score > max`, y `score` en caso contrario.
Puedes suponer que `min <= max`.

Ejemplo:

```c
validate_score(450, 0, 500);
// => 450
validate_score(-50, 0, 1530);
// => 0
validate_score(1234567, 0, 2999);
// => 2999
```

Todos los argumentos y el valor devuelto son enteros con signo de 64 bits.

## 4. Rastrea las dos puntuaciones más altas

Al final de cada sesión de juego, la consola portátil recorre el registro de partidas recientes en su archivo de guardado para encontrar las dos puntuaciones más altas jamás registradas.
El registro es un array simple de enteros con signo de 64 bits en memoria.
El recorrido pasa por el array una sola vez y mantiene dos máximos en curso: el más alto visto hasta el momento y el segundo más alto.

Ten en cuenta que ambos números deben ser al menos `0`.
Cualquier número negativo se descarta.

Una primera versión de la función se escribió con saltos condicionales en cascada.
Para cada candidato, el código pregunta dónde encaja (por encima del primero, entre el primero y el segundo, o en ningún lugar) y desplaza los máximos en curso en consecuencia, descartando cualquier resultado negativo.

Esto funciona.
Sin embargo, como los valores de entrada son aleatorios, cada salto condicional provoca muchos fallos en la predicción de ramas.
Por eso has decidido refactorizar el bucle principal para que no tenga ramas.

A continuación se muestra la función con la sección con ramas comentada:

```x86asm
; rdi = output buffer for two elements, rsi = input array address, rdx = number of elements in array
top_two:
    xor r8d, r8d                   ; first  = 0
    xor r9d, r9d                   ; second = 0
    xor ecx, ecx                   ; index = 0
    test rdx, rdx
    jz .done

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;                       BRANCHY CODE TO REFACTOR
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;.loop:
;    mov rax, qword [rsi + 8*rcx]   ; candidate
;    inc rcx
;    cmp rax, r8
;    jle .check_second              ; candidate <= first, try second
;    mov r9, r8                     ; second = first
;    mov r8, rax                    ; first  = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;    jmp .done                      ; otherwise, we are done
;.check_second:
;    cmp rax, r9
;    jle .loop                      ; candidate <= second, go to next iteration
;    mov r9, rax                    ; second = candidate
;    cmp rcx, rdx
;    jb .loop                       ; go to next iteration
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

.done:
    mov qword [rdi], r8            ; save first
    mov qword [rdi + 8], r9        ; save second
    ret
```

Reemplaza la sección comentada con una implementación sin ramas.
El único salto permitido en el nuevo código es el que vuelve al inicio del bucle para comprobar un nuevo elemento del array.

La función no tiene valor devuelto y toma los mismos argumentos que la versión con ramas:

1. `out`: búfer de salida donde la función escribirá las dos puntuaciones no negativas más altas en orden descendente, como enteros con signo de 64 bits
2. `array`: array de entrada de enteros con signo de 64 bits
3. `length`: el número de elementos del array, como un entero sin signo de 64 bits

~~~~exercism/note
Si el array contiene valores duplicados, los duplicados pueden aparecer en ambas posiciones de salida si son las dos puntuaciones más altas.
~~~~
