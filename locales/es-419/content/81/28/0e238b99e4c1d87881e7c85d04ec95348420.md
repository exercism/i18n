# Acerca de

En Rust, los métodos son funciones definidas para una struct (o un `enum` o un objeto `trait`).
Esto cambia la forma de llamarlos: en lugar de `frobnicate(foo)`, un método se llama como `foo.frobnicate()`.

Los métodos son similares a las funciones: se declaran con la palabra clave `fn`,
tienen un nombre, y pueden tener parámetros y devolver valores.

A diferencia de las funciones, el primer parámetro de un método siempre es `self` (o una variante),
que representa la instancia de la struct sobre la que se llama al método (más detalles a continuación).

Vamos a crear un `enum` para las casas de Hogwarts y una `struct` que describa la `age` y la `house` de un mago:

```rust
#[derive(Debug)]
enum House {
    Gryffindor,
    Hufflepuff,
    Ravenclaw,
    Slytherin,
}

struct Wizard {
    age: u32,
    house: House,
}
```

## Definir métodos

Para definir métodos para la struct `Wizard`, iniciamos un bloque `impl` (abreviatura de implementación) para `Wizard`.

```rust
impl Wizard { }
```

Todo lo que esté dentro de este bloque `impl` quedará asociado con el tipo `Wizard`.
Fíjate que una struct puede tener varios bloques `impl`.

### Usar `self`

Un método debe tener como primer parámetro un parámetro llamado `self` de tipo `Self`.
El tipo `Self` es un alias del tipo para el que sirve el bloque `impl`.
En nuestro ejemplo, `Self` representa a `Wizard`.

Rust nos permite abreviar esto escribiendo solo el nombre `self` en el lugar del primer parámetro, por comodidad.
Los tipos de `self` más comunes en los métodos son:

- `self`: Abrevia `self: Self`. La firma con el `self` a secas consume la instancia.
- `&self`: Abrevia `self: &Self`. Toma prestada la instancia de forma inmutable.
- `&mut self`: Abrevia `self: &mut Self`. Toma prestada la instancia de forma mutable.

En código más avanzado también podrías ver firmas como `self: Pin<&self>`, `self: Rc<Self>`, etc.
Sin embargo, esto está fuera del alcance de este tutorial.

### Definir un método con `&self`

Si queremos implementar un método `info` para mostrar la información básica del mago,
podríamos definir este método dentro de un bloque `impl` para `Wizard`:

```rust
impl Wizard {
    fn info(&self) {
        println!(
            "A wizard of age {} who studies in House {:?} at Hogwarts",
            self.age,
            self.house,
        );
    }
}
```

Fíjate que en la firma de `info` tomamos prestada la instancia de forma inmutable con `&self`.
De esta manera, podríamos leer los campos `age` y `house` de una instancia de `Wizard` sin modificarlos.
Si hubiéramos usado un `self` que consume en lugar de tomar prestado, la instancia quedaría inaccesible después de llamar al método.

Con el método `info` implementado, podríamos imprimir la información básica de un mago:

```rust
let harry = Wizard { age: 11, house: House::Gryffindor };
harry.info();
// => A wizard of age 11 who studies in House Gryffindor at Hogwarts
```

### Definir un método con `&mut self`

Si queremos implementar un método que modifica los campos de una instancia de una struct,
tomamos prestada la instancia de forma mutable con `&mut self` en la firma del método.

Supongamos que queremos establecer una nueva regla en Hogwarts para permitir que los estudiantes cambien de casa.
Podríamos implementar un método `switch_house` de la siguiente manera:

```rust
impl Wizard {
    fn switch_house(&mut self, new_house: House) {
        self.house = new_house;
    }
}
```

Ahora podemos cambiar de casa a un mago que estudia en Hogwarts:

```rust
// Note that the variable must be mutable
let mut cedric = Wizard {age: 14, house: House::Hufflepuff};
cedric.info();
// => A wizard of age 14 who studies in House Hufflepuff at Hogwarts
cedric.switch_house(House::Slytherin);
cedric.info()
// => A wizard of age 14 who studies in House Slytherin at Hogwarts
```

## Varios bloques «impl»

En Rust, cada elemento puede tener varios bloques `impl`.
Así que podemos agrupar todos los métodos en el mismo bloque `impl` o tener varios bloques `impl` para distintos grupos de métodos.
Ambos enfoques son sintaxis válida, pero la organización típica de un proyecto usa un solo bloque `impl` por cada conjunto único de restricciones `where` a nivel de `impl`.

## Funciones asociadas

Es posible definir funciones dentro de un bloque `impl` que no contengan un parámetro `self`.
Como no tienen el parámetro `self`, no son métodos.
Sin embargo, siguen estando asociadas con el tipo implementado, y se llaman nombrando ese tipo.
Por eso se llaman funciones asociadas (o funciones asociadas a un tipo).

Ya has visto algunas funciones asociadas, como `String::from()`:

```rust
let some_string = String::from("This is an associated function but not a method");
```

Los constructores suelen implementarse como funciones asociadas.
Vamos a crear una función `new` asociada con el tipo `Wizard`:

```rust
impl Wizard {
    fn new(age: u32, house: House) -> Self {
        Self {
            age,
            house,
        }
    }
}
```

Fíjate que podemos usar `Self` en lugar de `Wizard` para indicar el tipo que devolverá la función.
No es obligatorio usar el alias de tipo `Self` de esta forma, pero puede simplificar la implementación para tipos con nombres complicados o largos.
Ahora podemos ejecutar lo siguiente:

```rust
let myrtle = Wizard::new(14, House::Ravenclaw);

myrtle.info();
// => A wizard of age 14 who studies in House Ravenclaw at Hogwarts
```
