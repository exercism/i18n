# Instrucciones

Después de una revisión de seguridad reciente, te han pedido que limpies los archivos de log archivados de la organización.

## 1. Identifica las líneas de log corruptas

Necesitas hacerte una idea de cuántas líneas de log de tu archivo no cumplen con los estándares actuales.
Crees que una prueba sencilla revela si una línea de log es válida.
Para que se considere válida, una línea debe comenzar con uno de los siguientes strings:

- [DEBUG]
- [INFO]
- [WARNING]
- [ERROR]

Implementa la función `valid_line?/1` para que devuelva `true` si la línea de log es válida.

```elixir
LogParser.valid_line?("[ERROR] Network Failure")
# => true

LogParser.valid_line?("Network Failure")
# => false
```

## 2. Divide la línea de log

Poco después de empezar el proyecto de análisis de logs, te das cuenta de que los logs de una aplicación no están divididos en líneas como los de las demás. En este proyecto, lo que debería haber sido varias líneas separadas aparece en una sola línea, unido por flechas llamativas como `<--->` o `<*~*~>`.

De hecho, cualquier string que tenga como primer carácter `<`, como último carácter `>`, y cualquier combinación de los siguientes caracteres `~`, `*`, `=` y `-` en medio, puede usarse como separador en los logs de este proyecto.

Implementa la función `split_line/1` que toma una línea y devuelve una lista de strings.

```elixir
LogParser.split_line("[INFO] Start.<*>[INFO] Processing...<~~~>[INFO] Success.")
# => ["[INFO] Start.", "[INFO] Processing...", "[INFO] Success."]
```

## 3. Elimina los artefactos del log

Has descubierto que un procesamiento previo de los logs ha estado esparciendo por todos los logs el texto «end-of-line» seguido de un número de línea (sin un espacio intermedio).

Implementa la función `remove_artifacts/1` que toma un string y elimina todas las apariciones del texto «end-of-line» (sin distinguir mayúsculas y minúsculas) y devuelve una línea de log limpia.

Las líneas que no contengan el texto «end-of-line» deben devolverse sin modificar.

Solo elimina el texto «end-of-line»; no es necesario ajustar los espacios en blanco.

```elixir
LogParser.remove_artifacts("[WARNING] end-of-line23033 Network Failure end-of-line27")
# => "[WARNING]  Network Failure "
```

## 4. Etiqueta las líneas con nombres de usuario

Te has dado cuenta de que algunas de las líneas de log incluyen oraciones que se refieren a usuarios.
Estas oraciones siempre contienen el string `"User"`, seguido de uno o más caracteres de espacio en blanco y, después, un nombre de usuario.
Decides etiquetar esas líneas.

Implementa una función `tag_with_user_name/1` que procesa las líneas de log:

- Las líneas que no contienen el string `"User"` permanecen sin cambios.
- Para las líneas que contienen el string `"User"`, añade al principio de la línea `[USER]` seguido del nombre de usuario.

```elixir
LogParser.tag_with_user_name("[INFO] User Alice created a new project")
# => "[USER] Alice [INFO] User Alice created a new project"
```

Puedes asumir que:

- Cada aparición del string `"User"` va seguida de uno o más caracteres de espacio en blanco y del nombre de usuario.
- Hay como máximo una aparición del string `"User"` en cada línea.
- Los nombres de usuario son strings no vacíos que no contienen espacios en blanco.
