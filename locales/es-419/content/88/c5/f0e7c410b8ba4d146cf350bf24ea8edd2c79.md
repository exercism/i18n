# Introducción

## Código sin ramificaciones

El concepto de condicionales presenta `jcc`, la familia de instrucciones para ramificar según una condición.
Un `jcc` transfiere la ejecución a otro punto del programa solo si se cumple su condición.

Sin embargo, las CPU modernas son rápidas y capaces de ejecutar muchas instrucciones en paralelo.
Sería demasiado costoso detener todo el trabajo mientras la CPU espera una comprobación de una condición en tiempo de ejecución.

Por eso, internamente, la CPU no espera.
Usa un **predictor de ramificaciones** para adivinar el resultado de una condición y empieza a ejecutar _especulativamente_ la ruta predicha.

Si la predicción es correcta, la ejecución continúa como si no hubiera ramificación.
Sin embargo, si la predicción es errónea, la CPU debe _descartar el trabajo hecho_ en la ruta predicha y reiniciar en la correcta.

Esto se llama **predicción errónea de ramificación** y es costoso, ya que implica un retraso.

Cuando una ramificación es difícil de predecir, esas predicciones erróneas se acumulan.
En esos casos, a veces es preferible evitar la ramificación por completo, de modo que se ejecuten las mismas instrucciones independientemente de la condición.
El código que selecciona entre valores sin un `jcc` se conoce como **código sin ramificaciones**.

Hay varias formas de estructurar el código para que ramifique menos, o para que las ramificaciones que tenga sean más predecibles.
En particular, x86-64 ofrece dos familias de instrucciones que se usan habitualmente para escribir código sin ramificaciones.

### Movimientos condicionales

La familia de instrucciones `cmovcc` copia el operando fuente en el destino solo si se cumple una condición específica.
De lo contrario, el destino queda sin cambios.

El sufijo `cc` sigue la misma nomenclatura que en `jcc`, con el mismo significado:

| instrucción | mueve si                                |
|-------------|-----------------------------------------|
| `cmove`     | A == B después de `cmp A, B`            |
| `cmovne`    | A != B después de `cmp A, B`            |
| `cmovl`     | A < B (con signo) después de `cmp A, B` |
| `cmovb`     | A < B (sin signo) después de `cmp A, B` |
| `cmovg`     | A > B (con signo) después de `cmp A, B` |
| `cmova`     | A > B (sin signo) después de `cmp A, B` |

Las reglas son similares a las de `jcc`:

1. `l` y `g` se usan para comparaciones con signo, y `b` y `a`, para comparaciones sin signo.
2. Agregar `e` a un sufijo incluye la igualdad.
3. Agregar `n` niega la condición.
4. También hay variantes que se refieren a que la bandera está establecida.
   Por ejemplo, `cmovz` y `cmovc`.

Considera el valor absoluto de un entero con signo en `rdi`, devuelto en `rax`.
Escrito con `jcc`, la función selecciona una de dos rutas:

```x86asm
abs_branch:
    mov rax, rdi
    cmp rax, 0
    jge .done
    neg rax
.done:
    ret
```

Escrito con `cmovcc`, ambos valores candidatos se calculan de forma incondicional y el movimiento condicional elige uno:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi
    cmp rdi, 0
    cmovge rax, rdi    ; the value in `rdi` is moved to `rax` if rdi >= 0
                       ; otherwise, it stays the same, i.e., -rdi
    ; now rax = abs(rdi)
    ret
```

La versión sin ramificaciones siempre ejecuta las mismas instrucciones.
No hay ningún `jcc` que el predictor pueda adivinar.

El destino de un `cmovcc` debe ser un registro.
La fuente puede ser un registro o una ubicación de memoria, pero no un valor inmediato.

~~~~exercism/note
En el código anterior, la instrucción `neg` establece varias banderas según el resultado, incluida la bandera de signo (SF).
Esto significa que se puede omitir por completo el `cmp rdi, 0`:

```x86asm
abs_branchless:
    mov rax, rdi
    neg rax            ; rax = -rdi. `neg` sets SF = 1 if the result is negative
    cmovs rax, rdi     ; if SF == 1 (i.e., rax < 0), replace rax with rdi
                       ; otherwise rax stays = -rdi, which is non-negative
    ; now rax = abs(rdi)
    ret
```

Para `rdi` positivo, `neg` produce un resultado negativo y SF == 1, así que `cmovs` restaura `rdi`.
Para `rdi` cero o negativo, `neg` produce un resultado no negativo y SF == 0, así que `rax` conserva el valor negado (que es el valor absoluto correcto).

Aunque `cmp` es la forma principal de comparar valores en código ensamblador, muchas instrucciones también establecen banderas según su resultado.
La lista completa de banderas que afecta una instrucción suele aparecer en su [referencia][reference].
En el caso concreto de `neg`, esas son SF, ZF, CF, OF y PF.

[reference]: https://www.felixcloutier.com/x86/
~~~~

### Establecimiento condicional

La familia de instrucciones `setcc` establece el operando de destino en `1` si se cumple una condición específica, y en `0` en caso contrario.
El destino siempre es un _operando de 8 bits_.

El sufijo `cc` sigue la misma nomenclatura que en `jcc` y `cmovcc`.
Por ejemplo, `setz` establece el destino en `1` si `ZF == 1` y en `0` en caso contrario.

Como el destino es de 8 bits, es común seguir `setcc` con un `movzx` cuando se necesita un valor más ancho:

```x86asm
cmp rdi, rsi
setg al             ; al = 1 if rdi > rsi (signed), 0 otherwise
movzx eax, al       ; eax (and rax) = 1 or 0, with the upper bits cleared
```

Este es un recurso habitual para convertir el resultado de una comparación en un entero `0` o `1`.
