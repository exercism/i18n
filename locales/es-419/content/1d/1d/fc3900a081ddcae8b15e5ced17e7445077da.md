# Acerca de

Preparar un valor para transmitirlo implica tres cosas a la vez: serializarlo, elegir la parte correcta de él y no copiar cuando no hace falta. Tres modismos de Factor cubren ese terreno.

## `unparse`: de un valor al código fuente

[`unparse`][unparse] (en `prettyprint`) devuelve el texto en forma de código fuente de cualquier valor. Es la inversa del analizador sintáctico: el ciclo de ida y vuelta `dup unparse parse` reconstruye el valor.

```factor
USING: prettyprint ;

{ 1 2 3 } unparse .   ! => "{ 1 2 3 }"
"hi" unparse .        ! => "\"hi\""
123 unparse .         ! => "123"
```

Compáralo con `>string` (que solo funciona con secuencias de caracteres) y `number>string` (solo números). `unparse` es la opción universal, a costa de producir sintaxis de Factor (los strings entre comillas conservan sus comillas), así que es la herramienta correcta cuando quien recibe el texto lo va a analizar de nuevo, y la herramienta equivocada para una salida legible para humanos.

## Slices: vistas, no copias

| palabra       | efecto                                         |
|---------------|------------------------------------------------|
| `head`        | `( seq n -- newseq )`: copia los primeros n     |
| `head-slice`  | `( seq n -- slice )`: vista de los primeros n   |
| `tail`        | `( seq n -- newseq )`: copia desde el índice n en adelante |
| `tail-slice`  | `( seq n -- slice )`: vista desde el índice n en adelante |
| `head*`       | `( seq n -- newseq )`: copia todo menos los últimos n |
| `head-slice*` | `( seq n -- slice )`: vista de todo menos los últimos n |
| `tail*`       | `( seq n -- newseq )`: copia los últimos n      |
| `tail-slice*` | `( seq n -- slice )`: vista de los últimos n    |

Un `slice` es una tupla que contiene un índice inicial, un índice final y la secuencia subyacente. Implementa el [protocolo de secuencia][sequence-protocol], así que cualquier operación de secuencia funciona sobre él. Usa las variantes slice cuando, de otro modo, tuvieras que reservar memoria solo para leer; usa las que copian cuando necesites conservar los datos después de que la secuencia subyacente cambie.

## Cleave con varias entradas: `2bi`, `3bi`, `2tri`, `3tri`

Las palabras cleave simples `bi` y `tri` aplican dos o tres quotations a *un* argumento de la pila. Las variantes con prefijo `2` y con prefijo `3` aplican cada quotation a *dos* o *tres* argumentos:

```
bi   ( x       p q   -- )
2bi  ( x y     p q   -- )
3bi  ( x y z   p q   -- )

tri  ( x       p q r -- )
2tri ( x y     p q r -- )
3tri ( x y z   p q r -- )
```

Cada quotation recibe *todos* los argumentos, así que usa `2bi` cuando ambas proyecciones dependan del par, no cuando quieras aplicar la misma proyección a cada argumento por separado (eso es `bi@`).

```factor
1 2 [ + ] [ * ] 2bi . .       ! => 2  3   (both use 1 and 2)
1 2 3 [ + + ] [ * * ] 3bi . . ! => 6  6
```

Para aplicar *una* quotation a cada argumento por separado, usa mejor `bi@` (dos argumentos) o `tri@` (tres argumentos): la misma familia, distinta forma.
