# Combinación de iteradores

Un bucle puede llamar a más de un iterador. A cada uno se le pide su siguiente valor una vez por turno, y avanzan juntos.

```sather
   loop
      first ::= violin_one.elt!;
      second ::= violin_two.elt!;
      #OUT + first + " against " + second + "\n";
   end;
```

Eso recorre ambos arrays en paralelo: el primer elemento con el primer elemento, el segundo con el segundo.

## La regla que sorprende a todos

**El bucle termina tan pronto como se agota el *primero* de sus iteradores.**

No cuando se agota el último. No cuando se agotan todos. El primero.

Así que si `violin_one` tiene cuatro compases y `violin_two` tiene dos, el bucle de arriba se ejecuta **dos veces**. Los compases tercero y cuarto de la primera parte nunca se miran, porque para entonces la segunda parte ya no tiene nada que ofrecer.

Por lo general, eso es exactamente lo que se busca (emparejar cosas solo tiene sentido mientras hay pares), pero conviene saberlo de antemano en lugar de descubrirlo.

## Contar en paralelo

Un iterador que nunca se agota es útil precisamente por esa regla. `up!` cuenta para siempre:

```sather
1.up!        -- 1, 2, 3, 4, ... and never ends
```

Por sí solo, se repetiría para siempre. Emparejado con uno que sí termina, numera los valores sin tener que decidir nunca hasta dónde contar:

```sather
   loop
      number ::= 1.up!;
      bar ::= part.elt!;
      #OUT + "Bar " + number + ": " + bar + "\n";
   end;
```

`part.elt!` termina el bucle; `1.up!` aporta la numeración. Ninguno tiene que saber cuánto dura la parte.

## El orden no importa

A todos los iteradores se les pide una vez por turno, así que no importa cuál se escriba primero. Lo que importa es que a cada uno se le pida exactamente una vez: escribir `part.elt!` dos veces en un mismo turno toma dos valores en lugar de uno.
