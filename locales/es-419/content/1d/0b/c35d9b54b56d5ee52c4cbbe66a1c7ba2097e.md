# Acerca de

En C#, se puede definir una jerarquía de _clases_ usando la _herencia_, que permite que una clase derivada (`Car`) herede el comportamiento y los datos de su clase padre (`Vehicle`). Si no se especifica una clase padre, la clase hereda de la clase `object`.

Las clases padre pueden proporcionar funcionalidad a las clases derivadas de tres maneras:

- Definir un método normal.
- Definir un método [`virtual`][virtual-keyword], que es como un método normal, pero que las clases derivadas _pueden_ cambiar.
- Definir un método [`abstract`][abstract-keyword], que es un método sin implementación que las clases derivadas _deben_ implementar. Una clase con métodos `abstract` también debe marcarse como [`abstract`][abstract-classes]. Las clases abstractas no se pueden instanciar.

El [modificador de acceso `protected`][protected-keyword] permite acceder a un miembro de la clase padre desde una clase derivada, pero bloquea el acceso desde otras clases. Así, las clases derivadas pueden acceder a los miembros `public` y `protected` de la clase padre, pero no a los miembros `private`.

Las clases derivadas pueden acceder a los miembros de la clase padre mediante la [palabra clave `base`][base-keyword].

```csharp
// Inherits from the 'object' class
abstract class Vehicle
{
    // Can be overridden
    public virtual void Drive()
    {
    }

    // Must be overridden
    protected abstract int Speed();
}

// Cannot be inherited from
sealed class Car : Vehicle
{
    public override void Drive()
    {
        // Override virtual method

        // Call parent implementation
        base.Drive();
    }

    protected override int Speed()
    {
        // Implement abstract method
    }
}
```

El constructor de una clase derivada [llamará automáticamente al constructor de su clase padre][constructors] _antes_ de ejecutar la lógica de su propio constructor. Se pueden pasar argumentos al constructor de una clase padre usando la [palabra clave `base`][base-keyword-constructor]. Como las clases abstractas no se pueden instanciar, sus constructores se pueden marcar como `protected`.

```csharp
abstract class Vehicle
{
    protected Vehicle(int wheels)
    {
        Console.WriteLine("Called first");
    }
}

class Car : Vehicle
{
    public Car() : base(4)
    {
        Console.WriteLine("Called second");
    }
}
```

Cuando más de una clase deriva de una clase base, las dos (o más) subclases suelen implementar versiones diferentes de un método de la clase base. Este es un principio muy importante llamado [polimorfismo][polymorphism]. Por ejemplo, en una variación del ejemplo anterior mostramos cómo el código que usa `Vehicle` puede cambiar su comportamiento según el tipo de vehículo que se haya instanciado.

```csharp
abstract class Vehicle
{
   public abstract string GetDescription();
}

class Car : Vehicle
{
   public Car()
   {
   }

   public override string GetDescription()
   {
      return "Runabout";
   }
}

class Rig : Vehicle
{
   public Rig()
   {
   }

   public override string GetDescription()
   {
      return "Big Rig";
   }
}

Vehicle v1 = new Car();
Vehicle v2 = new Rig();

v1.GetDescription();
// => Runabout
v2.GetDescription();
// => Big Rig
```

Para evitar que se herede de una clase, agrega el [modificador `sealed`][sealed-classes].
Algunos desarrolladores tratan de evitar heredar de clases concretas (como se analiza en [esta pregunta de SO][pro-sealed]) y el modificador _sealed_ respalda este enfoque. Por otro lado, muchos desarrolladores de C# los consideran un obstáculo para el mantenimiento, como se analiza en algunos de los comentarios de [esta pregunta][anti-sealed]. El consejo es usar el modificador sealed con moderación hasta que hayas adquirido confianza en su uso para tus necesidades.

El siguiente [artículo][new-vs-override] describe `new` como una alternativa al modificador `override`. Esto es útil en ocasiones, tal vez con jerarquías de clases enrevesadas o con algún tipo de conflicto entre bibliotecas.
