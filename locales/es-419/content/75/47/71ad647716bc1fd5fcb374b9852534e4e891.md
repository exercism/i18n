# Tests

Cada ejercicio incluye los tests unitarios.
Tú aportas la implementación.
Cada archivo genera un ejecutable de consola que ejecuta los tests.
Ejecutar el ejecutable de tests imprime mensajes por cada test que falla y reporta un estado de salida distinto de cero cuando los tests fallan.

*Nota* Tu código se prueba con el conjunto de tests cada vez que compilas tu proyecto.
Si tu código no pasa uno o más tests pero es código D válido, igual se compila.

Trabajar en cada ejercicio es un proceso que consiste en:

* Ejecutar los tests con `dub test`
  * Si decidiste no instalar DUB, en su lugar usarías `dmd source/*.d -de -w -main -unittest` y luego ejecutarías el binario resultante.
* Para cada test unitario:
  * Resuelve los errores de compilación para que el test falle.
  * Implementa solo lo necesario para que el test pase.
  * Refactoriza tu implementación para mejorar la legibilidad, reducir la duplicación, etc.
  * Habilita el siguiente test

*Nota:* D tiene soporte para tests unitarios directamente en el lenguaje, así que los tests unitarios suelen estar en el mismo archivo que la implementación.
Los tests unitarios se ejecutan antes del cuerpo de main y se habilitan en el ejecutable final usando la opción de compilador **-unittest**.

## Cómo interpretar la salida de los tests unitarios

Si todos los tests pasan, la salida de los tests podría verse así

```none
$ dub test
             Generating test runner configuration 'dnd-character-test-library' for 'library' (library).
    Starting Performing "unittest" build using dmd for x86_64.
    Building dnd-character ~master: building configuration [dnd-character-test-library]
     Linking dnd-character-test-library
     Running dnd-character-test-library
1 modules passed unittests
```
