# Introducción

La igualdad de los tipos simples (strings y primitivos) normalmente se comprueba con `==` y `!=`.

Los tipos de referencia (instancias de clases) se comparan usando el método `Equals()` heredado de `Object`. Si tu objetivo con la prueba de igualdad es asegurarte de que dos objetos son exactamente la misma instancia, basta con confiar en la implementación de `Object`. Si no, necesitas sobrescribir `object.Equals()`.

Si sabes que todas las instancias de tu clase se crean en un solo lugar, por ejemplo los personajes de algún juego o simulación, la igualdad de referencias es suficiente. Sin embargo, es probable que se creen varias instancias de la misma entidad del mundo real (desde una base de datos, por entrada del usuario, mediante una solicitud web). En este caso, hay que comprobar la igualdad de los valores que identifican de forma única a la entidad. Por lo tanto, hay que sobrescribir `Equals()` y comprobar la igualdad de los miembros de datos adecuados de tu clase.

Un método `Equals()` sobrescrito contendrá pruebas de igualdad sobre miembros de tipos simples usando `==`, y sobre tipos de referencia con llamadas recursivas a `Equals()`.

La clase `Object` proporciona los métodos adecuados para comparar dos objetos y detectar si son una misma instancia.

## `Object.GetHashCode()`

El método `Object.GetHashCode()` devuelve un código hash en forma de entero de 32 bits. Las clases _diccionario_ y _conjunto_, como `Dictionary<T>` y `HashSet<T>`, usan el código hash para almacenar y recuperar objetos de manera eficiente.

La relación entre el código hash y la igualdad es que, si dos objetos son iguales (`Equal()` devuelve true), entonces `GetHashCode()` debe devolver el mismo valor para ambos objetos. Esto no aplica en la dirección inversa. No es simétrico. Que dos objetos tengan el mismo código hash no significa que tengan que ser iguales. Imagina una función de búsqueda que primero va a un «depósito» según el código hash y luego selecciona el elemento concreto mediante la prueba de igualdad.

La documentación de la API de la librería HashCode explica cuál es la mejor manera de generar un código hash.

Los valores que se usan en la prueba de igualdad deben ser estables mientras se usa la colección con hash. Si agregas un objeto a la colección con un conjunto de valores y luego cambias esos valores, el código hash ya no apuntará al «depósito» correcto. En la práctica, esto significa que el objeto debería ser inmutable. Otras opciones corren el riesgo de crear trampas para quienes mantienen el código.
