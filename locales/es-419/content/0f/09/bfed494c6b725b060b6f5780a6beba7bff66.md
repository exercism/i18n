# Introducción a las tuberías y las listas de comandos

Hemos visto cómo escribir comandos simples, donde a un comando le siguen argumentos.
Ahora veremos cómo crear comandos más complejos componiendo comandos simples.

## Entrada y salida

Antes de empezar, una breve introducción a la entrada y la salida.

Los procesos tienen canales estándar de entrada y salida.

* Un proceso puede consumir _entrada_ en «stdin».
* Un proceso puede emitir _salida_ en «stdout».
* Un proceso puede emitir _salida de error_ en «stderr».

El comando `tr` es un ejemplo muy puro de esto.
Lo único que hace es leer texto de su entrada, realizar transliteraciones de caracteres e imprimir el texto resultante en su salida.

Veremos más sobre cómo manipular los canales «stdio» más adelante en el temario.

## Tuberías

Esta es una de las características estrella de la programación de shell.
Las tuberías te permiten crear transformaciones sofisticadas en un flujo de texto.

Para producir una lista ordenada de usuarios:

```bash
cat /etc/passwd | cut -d : -f 1 | sort
```

El símbolo de tubería (`|`) conecta la salida de un comando con la entrada de otro.
`cut` lee la salida de `cat`, y `sort` lee la salida de `cut`.

~~~~exercism/advanced
* De forma predeterminada, cada comando de una tubería se ejecuta en una subshell separada.
  (Una subshell es un proceso hijo que es una copia del shell en ejecución actual.)

* Ejecutar tuberías tiene un costo de rendimiento.
  Si te encuentras con tuberías largas de comandos similares, considera combinarlas en un solo comando.
  Por ejemplo, las tuberías que usan varias instancias de `grep`, `cut`, `sed`, `awk` y `tr` generalmente se pueden combinar en un solo comando `awk` para mayor eficiencia.

* El estado de salida de una tubería es el estado de salida del último comando de la tubería.
  Eso significa que si algún comando anterior falló pero el último comando tuvo éxito, el estado de salida de toda la tubería es cero.

  Hay una configuración de shell que puede cambiar esto;
  si la opción «pipefail» está habilitada (con `set -o pipefail`), el estado de salida de la tubería será:
  * cero si todos los comandos tienen éxito; de lo contrario,
  * el _**último** estado de salida distinto de cero_ de los comandos de la tubería.
~~~~

## Listas de comandos

Una lista de comandos es una secuencia de tuberías separadas por `;` (o un salto de línea), `&&` o `||`.

* `A; B` es una lista de comandos donde `B` se ejecuta después de que `A` haya terminado.
* `A && B`, donde `B` se ejecuta solo si `A` tiene éxito (sale con estado cero).
* `A || B`, donde `B` se ejecuta solo si `A` falla (sale con estado distinto de cero).

El estado de salida de una lista de comandos es el estado de salida del último comando que se ejecutó.

Los operadores `&&` y `||` se pueden encadenar para que el siguiente comando se ejecute de forma condicional según el estado de los comandos anteriores.
Por ejemplo

```bash
A && B && C && D || E
```

* B se ejecuta si A tiene éxito,
* C se ejecuta si A y B tienen éxito,
* D se ejecuta si A, B y C tienen éxito,
* E se ejecuta si **alguno** de A, B, C o D falla.

~~~~exercism/caution
Usa estos operadores lógicos con moderación.
Pueden llevar rápidamente a código ilegible o a lógica difícil de comprender.

Por ejemplo, puedes pensar que estos son iguales:

```bash
if A; then B; else C; fi
```

```bash
A && B || C
```

La diferencia es: ¿cuándo se ejecuta C?

* En el primer fragmento (la sentencia condicional), C se ejecutará solo si A falla.
* En el segundo fragmento, ¡C se ejecutará si A falla _o si A tiene éxito pero B falla_!
~~~~

### Usos de las listas de comandos

Aquí hay un par de ejemplos donde las listas de comandos pueden simplificar el código.

#### Leer bloques de líneas de un archivo

Supón que tienes un archivo de datos que contiene datos sobre triángulos,
y un triángulo se representa con tres líneas separadas que contienen los lados del triángulo.

```bash
$ cat triangle.dat
3
4
5
9
12
14
```

Puedes usar un bucle while donde la condición son tres comandos read separados:

```bash
while read a && read b && read c; do
    if is_pythagorean "$a" "$b" "$c"; then
        echo "$a:$b:$c is pythagorean"
    else
        echo "$a:$b:$c is not pythagorean"
    fi
done < triangle.dat
```

Suponiendo que `is_pythagorean` es un comando que determina si los tres lados satisfacen la ecuación de Pitágoras, la salida sería:

```none
3:4:5 is pythagorean
9:12:14 is not pythagorean
```

#### Aserciones

Muchos lenguajes de programación tienen una forma de aserción donde se lanza una excepción si alguna condición falla

```
assert(user == "Administrator", "wrong user");
```

Podemos usar un operador OR en Bash para simular esa función:

```bash
die () { # a little convenience function
    echo "$*" >&2
    exit 1
}

[[ $user == "Administrator" ]] || die "wrong user"
[[ $password == "secret!" ]]   || die "incorrect password"
```

## Consideraciones de estilo

Las listas de comandos largas se vuelven difíciles de leer bastante rápido.
El uso generoso de saltos de línea puede ayudar mucho.

Considera este ejemplo donde se agrega una palabra a un array si se cumplen dos condiciones.

```bash
[[ "$word" != "$topic" ]] && [[ "$key" == "$(sorted "$topic")" ]] && anagrams+=("$candidate")
```

Bash te permite agregar un salto de línea después de una tubería o un operador lógico.

```bash
[[ "$word" != "$topic" ]] &&
[[ "$key" == "$(sorted "$topic")" ]] &&
anagrams+=("$candidate")
```

Sin embargo, el operador puede pasar desapercibido fácilmente al final de la línea.
Usar una _continuación de línea_ significa que puedes poner el operador primero, lo que deja más claro que la lista continúa:

```bash
[[ "$word" != "$topic" ]] \
&& [[ "$key" == "$(sorted "$topic")" ]] \
&& anagrams+=("$candidate")
```

~~~~exercism/note
Una _continuación de línea_ es la secuencia de dos caracteres «barra invertida» y «salto de línea» (`\` + `\n`).
Cuando Bash ve esa secuencia, simplemente la elimina del código, y así _continúa_ la línea actual con la línea siguiente.
Ten cuidado de no dejar ningún espacio entre la barra invertida y el salto de línea.
~~~~

Aquí tienes otro ejemplo

```bash
printf "%s\n" "${numbers[@]}" | bc --mathlib | sort --general-numeric-sort
```

o 

```bash
printf "%s\n" "${numbers[@]}" \
| bc --mathlib \
| sort --general-numeric-sort
```
