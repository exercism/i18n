# Acerca de

Las excepciones son una forma de manejo de errores.
Se llaman excepciones porque normalmente aparecen cuando te enfrentas a algún evento inesperado.

En cualquier punto de nuestro código, podemos «lanzar» una excepción.
Lo hacemos con el método `raise`, al que le pasamos un objeto, normalmente un objeto `Exception`, aunque también podemos usar strings básicos.
Por ejemplo, verás en los esqueletos de los ejercicios que usamos el `RuntimeError` integrado para indicarle a Ruby que un método no se ha implementado.
También puedes usar la sintaxis abreviada de `raise(ExceptionObject, params)`.
Si se omite la clase de la excepción, se usa `RuntimeError` de forma predeterminada.

Por ejemplo:

```ruby
# These are equivalent
raise RuntimeError.new("Please implement this method")
raise RuntimeError, "Please implement this method"
raise "Please implement this method"
```

Cuando Ruby ve esto, hace subir el error hasta la parte superior del programa y luego sale.

Por ejemplo, si intentas dividir algo entre cero, verás algo así:

```ruby
5/0

#=> Traceback (most recent call last):
#=> ...
#=> ZeroDivisionError (divided by 0)
```

Es importante tener en cuenta que las excepciones se deben usar en los casos en que ocurre algo excepcional, un error que necesita un manejo especial.
No se deben usar excepciones para el flujo de control de un programa, ya que eso se considera un mal diseño, que a menudo conduce a un rendimiento y una mantenibilidad deficientes.

## Jerarquía de clases

En Ruby, las excepciones siguen una jerarquía de clases en la que `Exception` es la clase base.
Estas son las excepciones integradas más comunes de Ruby:

```
Exception
  NoMemoryError
  ScriptError
    LoadError
    NotImplementedError
    SyntaxError
  SignalException
    Interrupt
  StandardError
    ArgumentError
    IOError
    EOFError
    IndexError
    LocalJumpError
    NameError
      NoMethodError
    RangeError
      FloatDomainError
    RegexpError
    RuntimeError
    SecurityError
    SystemCallError
    SystemStackError
    ThreadError
    TypeError
    ZeroDivisionError
  SystemExit
```

Rescatar errores de una clase específica también rescata los errores de sus clases hijas.
Por eso, rescatar desde `Exception` puede ser peligroso.
Ruby también usa las excepciones para manejar mensajes del sistema operativo, las «señales», por ejemplo `ctrl-c`.
Esto significa que rescatar desde `Exception` también capturará estas «señales» del sistema.
Así que, para evitar comportamientos inesperados, la práctica común para capturar «todos los errores» es rescatar desde `StandardError`.

## Sintaxis de rescate
Ruby también ofrece cláusulas de rescate extendidas para situaciones que requieren un tratamiento especial:

```ruby
begin
  # ...
rescue CustomError => error
  # This block is run if a CustomError occurs
rescue AnotherCustomError => error
  # This block is run if a AnotherCustomError occurs
else
  # This block is run if no exception occurred at all
ensure
  # This block always run, regardless of whether an exception occurred
end
```

Esto puede ser útil, por ejemplo, cuando trabajas con E/S de red, donde siempre debes acordarte de cerrar una conexión.

Los bloques `rescue` de Ruby también pueden usar la palabra clave `retry`, que vuelve a ejecutar todo lo que está entre begin y rescue:

```ruby
counter = 0
begin
  counter += 1
  api_request
rescue
  retry if counter <= 3
end
```
