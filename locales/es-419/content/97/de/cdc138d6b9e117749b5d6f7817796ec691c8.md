# Introducción

Más allá de las clases de caracteres y los cuantificadores, las expresiones regulares pueden describir *estructura* y *contexto*. Estas funcionalidades viven en el mismo vocabulario [`regexp`][regexp] y en el mismo literal `R/ /`.

Los paréntesis `( )` agrupan parte de un patrón para que un cuantificador o un `|` («esto o aquello») se aplique a todo el grupo; un `?` después de un grupo lo hace opcional:

```factor
USING: regexp ;

"abab"    R/ (ab)+/ matches? .             ! => t
"$100"    R/ \$\d+(\.\d{2})?/ matches? .   ! => t   (optional group)
```

Las anclas fijan un patrón a una posición: `^` (inicio), `$` (final) y `\b` (un límite de palabra).

Una *búsqueda alrededor* coincide por lo que rodea a un punto sin consumirlo:

```
(?=...)    ! lookahead — ... must follow
(?!...)    ! negative lookahead — ... must not follow
(?<=...)   ! lookbehind — ... must come before
```

```factor
USING: regexp ;

"spent $100 and $25" R/ (?<=\$)\d+/ all-matching-subseqs .
! => { "100" "25" }

"up 5% then 12%" R/ \d+(?=%)/ all-matching-subseqs .
! => { "5" "12" }
```

Una letra de opción después del `/` de cierre cambia todo el patrón; `i` lo hace insensible a mayúsculas y minúsculas:

```factor
USING: regexp ;

"REFUND" R/ refund/i matches? .   ! => t
```

Factor usa búsquedas alrededor en lugar de grupos de captura: no tiene extracción de grupos de captura, retrorreferencias ni cuantificadores perezosos.
