# Introducción

En C++, las declaraciones a menudo se separan de las definiciones.
Las declaraciones se agrupan en los llamados archivos de encabezado, y las implementaciones correspondientes se colocan en archivos fuente.
Puedes pensar en los archivos de encabezado como una API.
El archivo de encabezado te dirá _qué_ ofrece una base de código sin entrar en los detalles de _cómo_.

## Encabezado y fuente

La extensión de archivo más común para los archivos de encabezado es `.h`.
Algunos proyectos usan `.hpp` o prescinden por completo de la extensión.

Las definiciones se encuentran en un archivo `.cpp` aparte.
Para reunir las partes, el archivo fuente empieza por _incluir_ el archivo de encabezado correspondiente.

Si quieres escribir una biblioteca llamada «quick_math» que ofrece una función «super_root» que quieres usar a menudo, los archivos se verían así:

```cpp
// A file named quick_math.h
#pragma once

namespace quick_math {

double super_root(double x, int n);

}  // namespace quick_math
```

```cpp
// A file named quick_math.cpp
#include <cmath>

#include "quick_math.h"

double quick_math::super_root(double x, int n) {
    while (n) {
        x = std::sqrt(x), --n;
    }
    return x;
}
```

Si necesitas incluir un encabezado que solo se requiere en la implementación, la línea `#include` correspondiente solo es necesaria en el archivo fuente.
Todo lo que se incluye en el encabezado también está disponible en el archivo `.cpp`, como la biblioteca `string` del ejemplo de abajo.
**Atención**: el `;` es necesario después de la declaración en el archivo de encabezado, pero no después de la definición en el archivo fuente.

## Clases y encabezados

Las clases pueden volverse muy complejas y su relación con la división entre encabezado y fuente puede resultar confusa.
Una posible organización es mantener todos los detalles de implementación en el archivo fuente y todas las declaraciones y variables miembro en el encabezado:

```cpp
// A file named robot_flower.h
#if !defined(ROBOT_FLOWER_H)
#define ROBOT_FLOWER_H

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0);
    void give_water();
    std::string get_name();
    int get_size();
    void start_next_day();
};

}  // namespace robots

#endif
```

```cpp
// A file named robot_flower.cpp
#include "robot_flower.h"

robots::Flower::Flower(std::string name, int size) {
    this->name = "Robotica " + name;
    this->size = size;
}

void robots::Flower::start_next_day() {
    if (!needs_water) {
        ++size;
    }
    needs_water = true;
}

std::string robots::Flower::get_name() { return name; }

int robots::Flower::get_size() { return size; }
```

Cuando el encabezado se usa como una vista general de la API, ahí es donde alguien buscaría información como los valores predeterminados.
Por eso, el valor predeterminado del parámetro `size` del constructor se maneja en el encabezado y no en la implementación.
Las definiciones en el archivo fuente llevan como prefijo el espacio de nombres `robots` y el tipo de clase `Flower`.

Otra opción de organización es una biblioteca _solo de encabezado_, que no tiene ningún archivo `.cpp`:

```cpp
// A file named robot_flower.h
#pragma once

#include <string>

namespace robots {

class Flower {
   private:
    bool needs_water{};
    int size{};
    std::string name{};

   public:
    Flower(std::string name, int size = 0) {
        this->name = "Robotica " + name;
        this->size = size;
    }
    void give_water() { needs_water = false; }
    std::string get_name() { return name; }
    int get_size() { return size; }
    void start_next_day() {
        if (!needs_water) {
            ++size;
        }
        needs_water = true;
    }
};

}  // namespace robots
```

Los proyectos pueden usar combinaciones de estas organizaciones y hay mucho debate sobre cuál puede ser la mejor opción para cada caso de uso.

## Guardas de inclusión

Es posible que hayas notado la línea `#pragma once` en el archivo de encabezado de ejemplo de arriba.
Esto se llama guarda de inclusión y garantiza que el contenido del archivo se incluya solo una vez durante la compilación para evitar errores.
Existe otra variación más compleja de una guarda de inclusión que empieza con `#ifndef` y termina con `#endif`.
Cumple el mismo propósito y su uso se muestra en el ejemplo de la clase `Flower` de arriba.
