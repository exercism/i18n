# Acerca de

El código escalar se apoya en banderas que distintas instrucciones activan para bifurcar en respuesta a cierta condición.
Los valores empaquetados, en cambio, no representan un solo valor sino muchos en paralelo.
Una misma condición puede fallar en un carril y cumplirse en otro.

Por eso el código SIMD es [sin bifurcaciones][branchless-code] de forma predeterminada.

En lugar de apoyarse en banderas, las comparaciones empaquetadas suelen producir una **máscara** en el operando destino.
Para cada carril, la comparación llena todo el carril con unos cuando se cumple y con ceros cuando no se cumple.
Leído como entero con signo, un carril verdadero es `-1` y un carril falso es `0`.

Esta máscara se puede combinar después con [operaciones bit a bit][simd-bitwise] para filtrar carriles específicos.

## Comparaciones empaquetadas

Una `cmp` escalar es genérica en el sentido de que se usa para activar varias banderas a la vez.
Otra instrucción puede entonces consumir esas banderas para bifurcar o para hacer cálculos.

Sin embargo, como una comparación empaquetada no solo comprueba una condición sino que además calcula una máscara, no es genérica.
Hay que darle a la comparación la condición exacta que se prueba.

Hay dos maneras de hacerlo:

- A las comparaciones de enteros se les da la condición como sufijo: `eq` para igualdad y `gt` para mayor que.
  Las demás variantes se construyen combinando el resultado de una de estas.
- A las comparaciones de punto flotante se les da la condición codificada en un inmediato.
  Distintos valores de ese inmediato corresponden a distintas condiciones que se prueban.

Aparte de usar un sufijo condicional específico en las comparaciones de enteros, la sintaxis sigue la misma estructura que ya vimos:

- Para enteros, `p` + `cmp` + condición + tamaño (`b`, `w`, `d` o `q`).
- Para flotantes, `cmp` + `p` + tamaño (`s` o `d`).
  La condición se pasa en un inmediato como operando adicional.

### Comparaciones de enteros

Como ya se mencionó, solo hay comparaciones de enteros para igualdad y mayor que:

| instrucción                                | descripción                      |
|--------------------------------------------|----------------------------------|
| `pcmpeqb`, `pcmpeqw`, `pcmpeqd`, `pcmpeqq` | igualdad por carril              |
| `pcmpgtb`, `pcmpgtw`, `pcmpgtd`, `pcmpgtq` | mayor que **con signo** por carril |

```x86asm
movdqa  xmm0, [rel scores]
pcmpgtd xmm0, [rel threshold] ; lane i = 0xFFFFFFFF (-1) if scores[i] > threshold[i], else 0
```

Para crear una comparación de menor que, usa `gt` con los operandos intercambiados: `a < b` == `b > a`.

Ten en cuenta que la comparación es **con signo**.
Para hacer una comparación sin signo, invierte el bit superior de ambos operandos.
Esto se puede hacer con un XOR con una máscara en la que solo esté activo el bit superior.

~~~~exercism/note
Dos expresiones muy útiles son:

1. Hacer XOR de un registro consigo mismo para producir todo ceros.
2. Comparar un registro consigo mismo para producir todo unos.

Por ejemplo:

```x86asm
pxor    xmm4, xmm4 ; xmm4 = all zeros
pcmpeqd xmm7, xmm7 ; xmm7 = all ones
```

Las máscaras de todo ceros y de todo unos son comunes para codificar «falso en todas partes» y «verdadero en todas partes», respectivamente.
También sirven para representar `0` empaquetado o `-1` empaquetado, que son valores centinela habituales.
Por ejemplo, el NUL que marca el final de una cadena es un `0`.
~~~~

### Comparaciones de punto flotante

Los carriles de punto flotante usan otra forma: una sola instrucción, `cmpps` (y `cmppd` para carriles de 64 bits), con la condición como inmediato:

```x86asm
movaps xmm0, [rel readings]
cmpps  xmm0, [rel limits], 1 ; condition 1 is "less than": lane i = all ones if readings[i] < limits[i]
```

NASM también tiene pseudooperaciones que se traducen al inmediato correcto y son más fáciles de recordar.
En todas las siguientes, la `x` de `px` puede ser `s` (flotantes de 32 bits) o `d` (flotantes de 64 bits):

| pseudooperación | inmediato | comparación            |
|--------------|-----------|------------------------|
| `cmpeqpx`    | 0         | a == b                 |
| `cmpltpx`    | 1         | a <  b                 |
| `cmplepx`    | 2         | a <= b                 |
| `cmpunordpx` | 3         | a is NaN or b is NaN   |
| `cmpneqpx`   | 4         | a != b                 |
| `cmpnltpx`   | 5         | a >= b                 |
| `cmpnlepx`   | 6         | a >  b                 |
| `cmpordpx`   | 7         | neither a nor b is NaN |

~~~~exercism/caution
NaN se compara como no ordenado: no es menor, ni igual, ni mayor que nada, ni siquiera que sí mismo.
Los predicados ordenados, como `cmpltps`, dan falso cuando cualquiera de los operandos es NaN, mientras que los predicados no ordenados dan verdadero.
Por eso existen `cmpordps` y `cmpunordps`: para probar si hay NaN de forma explícita.
~~~~

## Seleccionar con una máscara

Una máscara codifica el resultado de una condición.
Luego se puede usar para elegir, carril por carril, entre dos conjuntos de valores según esa condición.
Tomamos el carril de un valor donde la máscara es verdadera y de otro donde es falsa:

```x86asm
; result = (a AND mask) OR (b AND NOT mask)
movdqa xmm2, xmm0  ; xmm0 holds the mask, keep a copy
pand   xmm2, xmm3  ; xmm2 = a AND mask: lanes of a where mask is true
pandn  xmm0, xmm4  ; xmm0 = NOT mask AND b: lanes of b where mask is false
por    xmm2, xmm0  ; combine the two halves
```

Este patrón es la forma empaquetada de la selección sin bifurcaciones.
Se calcula cada carril, y solo la máscara decide qué valor sobrevive, sin ningún `jcc` en ninguna parte.

## Blends dedicados

Hay instrucciones que hacen esa misma selección directamente, leyendo un bit por elemento desde un registro de máscara.
Se llaman instrucciones **blend**:

| instrucción | elemento     | origen de la máscara |
|-------------|-------------|-----------------|
| `pblendvb`  | byte        | `xmm0` implícito |
| `blendvps`  | carril de 32 bits | `xmm0` implícito |
| `blendvpd`  | carril de 64 bits | `xmm0` implícito |

Fíjate que la primera instrucción sigue la sintaxis de enteros, mientras que las otras dos siguen la sintaxis de flotantes.
Sin embargo, como estas instrucciones solo seleccionan bytes en bruto, cualquiera de ellas sirve tanto para enteros como para flotantes.

Para cada elemento, el blend conserva el destino cuando el bit superior del elemento correspondiente de la máscara está en cero, y toma el origen cuando está en uno.
Solo se consulta ese **bit superior**, requisito que una máscara de comparación cumple, ya que sus carriles son todo unos o todo ceros.
El registro de máscara siempre es `xmm0`, que es implícito:

```x86asm
movaps   xmm0, [rel mask]  ; the selecting mask must be in xmm0
movaps   xmm1, [rel b]     ; destination: kept where the mask bit is clear
blendvps xmm1, [rel a]     ; source: taken where the mask bit is set
```

También es posible usar `pblendvb` para seleccionar carriles a partir de una máscara de comparación para cualquier otro tamaño.
Como todos los bytes de un carril verdadero son todo unos, `pblendvb` los selecciona todos.

~~~~exercism/note
Todas estas instrucciones agregan una `v` después de la operación que realizan (`blend`).
Esa `v` viene de _variable_, porque la selección no es estática: depende de un registro.

También hay variantes sin `v`, que seleccionan según un inmediato.
Siguen el mismo patrón: seleccionan el carril `i` si el bit `i` del inmediato está activo.
~~~~

## De una máscara de vuelta a lo escalar

Aunque es potente, el código SIMD carece de buena parte de la flexibilidad del código escalar.
En muchas situaciones hace falta pasar de un registro empaquetado de vuelta al mundo de las instrucciones escalares.

La familia de instrucciones `movmsk` sirve de puente entre los dos mundos.
Estas instrucciones extraen el **bit superior** de cada carril hacia un registro de propósito general:

| instrucción | recoge                     | ancho del resultado |
|-------------|-----------------------------|--------------|
| `pmovmskb`  | el bit superior de cada uno de los 16 bytes | 16 bits      |
| `movmskps`  | el bit superior de cada uno de los 4 dwords | 4 bits       |
| `movmskpd`  | el bit superior de cada uno de los 2 qwords | 2 bits       |

Si se usan después de una comparación, cada bit en uno representa un carril «verdadero» y cada bit en cero, un carril «falso».
Ese resultado se puede manipular después como de costumbre con instrucciones escalares.
Por ejemplo, un `popcnt` cuenta cuántas coincidencias hay, y `tzcnt` encuentra la primera.

El registro de propósito general puede ser de 32 o de 64 bits de ancho.

## Probar un vector completo

También hay una variante empaquetada de la instrucción escalar `test`: `ptest`.

Se parece a su equivalente escalar en que hace una operación AND entre dos operandos, sin modificarlos.
A diferencia de `test`, `ptest` también hace una operación ANDN, que niega el primer operando.

Así, se puede pensar en `ptest` como una versión no destructiva de `pand` y `pandn` que activa banderas según el resultado.
Al igual que esas dos instrucciones, `ptest` trata todo el registro SIMD como un solo carril, así que no lleva prefijo de tamaño.

Si el resultado de la operación AND es `0`, se activa `ZF`, y si la operación ANDN da `0`, se activa `CF`.
Esto significa que `ptest` sirve para comprobar tanto una máscara de todo unos como una de todo ceros:

1. Usar `ptest` con un registro y sí mismo activa `ZF` solo si el registro es todo ceros.
   Esto imita la expresión escalar común de usar `test` con un registro y sí mismo para comprobar si es `0`.
2. Usar `ptest` con un registro y una máscara de todo unos activa `CF` solo si el registro es todo unos.
   Además, activa `ZF` solo si el registro es todo ceros, lo que permite comprobar ambas máscaras a la vez.

```x86asm
pxor  xmm0, xmm0   ; xmm0 = all zeros
ptest xmm0, xmm0   ; xmm0 AND xmm0 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm0 == 0 => CF is set

; Using ptest on a register with itself makes ZF set only if the register is all zeros

pcmpeqb xmm1, xmm1 ; xmm1 = all ones
ptest   xmm0, xmm1 ; xmm0 AND xmm1 == 0 => ZF is set
                   ; (NOT xmm0) AND xmm1 != 0 => CF is cleared

pcmpeqb xmm3, xmm3 ; xmm3 = all ones
ptest   xmm3, xmm1 ; xmm3 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm3) AND xmm1 == 0 => CF is set

mov eax, -1
movd  xmm2, eax    ; xmm2 = {-1, 0, 0, 0}
ptest xmm2, xmm1   ; xmm2 AND xmm1 != 0 => ZF is cleared
                   ; (NOT xmm2) AND xmm1 != 0 => CF is cleared

; After using ptest on a register with an all-ones mask, ZF is only set if the register is all zeros.
; CF may be:
; 1. cleared, if the register is all zeros or is partially set
; 2. set, if the register is all ones
```

El resultado de un `ptest` se puede usar para bifurcar o en instrucciones sin bifurcaciones como `setcc` o `cmovcc`, como de costumbre.

## AVX y más allá

AVX les da a las comparaciones, los blends y `ptest` una forma con prefijo `v` sobre registros más anchos.

El blend variable cambia de forma.
La máscara ya no es el `xmm0` implícito, sino un cuarto operando explícito:

```x86asm
vpcmpgtd  ymm0, ymm1, ymm2       ; eight 32-bit lanes compared at once
vblendvps ymm0, ymm1, ymm2, ymm3 ; ymm3 is the mask, named explicitly
vptest    ymm0, ymm0
```

Las extensiones AVX-512 cambian el modelo más a fondo.

Primero, agregan una nueva clase de registros SIMD de 64 bytes, llamados `zmm`.
Expanden los registros `ymm` correspondientes, del mismo modo que los registros `ymm` expanden los registros `xmm`.

Segundo, esas extensiones también crean toda una nueva clase de **registros opmask**, de `k0` a `k7`, cuyo propósito principal es servir como máscaras para las instrucciones SIMD.
Las comparaciones ya no escriben en vectores, sino en uno de estos nuevos registros.
También se pueden usar directamente en muchas instrucciones como predicados con una máscara de escritura `{k}`, seleccionando carriles _directamente_:

```x86asm
vpcmpgtd  k1, zmm0, zmm1         ; k1 gets one bit per lane
vmovdqa32 zmm2{k1}, zmm3         ; copy only the lanes whose bits are set in k1
```

Por último, hay nuevas instrucciones para operar sobre esos nuevos registros, incluida la de copiarlos a registros de propósito general.
Esto hace innecesarias las instrucciones `movmsk`, y no hay soporte para instrucciones `movmsk` sobre registros `zmm`.

Estas extensiones se mencionan para ser completos.
Los ejercicios de este track usan las formas SSE.
