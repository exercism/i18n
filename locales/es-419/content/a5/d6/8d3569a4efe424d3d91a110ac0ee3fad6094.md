# Introducción

La mayoría de las palabras de secuencia que has visto devuelven secuencias *nuevas*
sin tocar la que reciben: `suffix`, `reverse`, `map`, y así por el estilo.
Pero los arrays y los vectores también admiten **mutación en el lugar**, y
ambos aparecen cuando quieres registrar un estado que cambia con el tiempo.

## Dos variantes de secuencia mutable

- **Los arrays** (`{ … }`) tienen una longitud fija. `<array> ( n elt -- array )`
  (en [`arrays`][arrays]) crea un array nuevo de longitud `n` lleno de copias de `elt`.
- **Los vectores** (`V{ … }`) crecen y se encogen. Usa `V{ } clone` para obtener
  uno nuevo vacío; `<vector> ( n -- vector )` (en
  [`vectors`][vectors]) preasigna capacidad para `n` elementos.

```factor
USING: arrays kernel prettyprint vectors ;

5 0 <array> .   ! => { 0 0 0 0 0 }
V{ } clone .    ! => V{ }
```

## Cambiar una posición

Estas dos funcionan con cualquiera de los dos tipos de secuencia. Ambas
esperan la secuencia después del índice:

```
set-nth    ( elt n seq -- )
change-nth ( n seq quot -- )
```

`set-nth` asigna; `change-nth` aplica una quotation al elemento en la posición `n`.
Ninguna de estas dos palabras de [`sequences`][sequences] devuelve nada en la pila: el efecto es la mutación.

```factor
USING: arrays kernel math prettyprint sequences ;

5 0 <array>                 ! { 0 0 0 0 0 }
7 2 pick set-nth            ! mutates: position 2 becomes 7
0 over [ 1 + ] change-nth   ! mutates: position 0 += 1
.                           ! => { 1 0 7 0 0 }
```

## Crecer y encoger

Estas tres solo tienen sentido en los vectores, ya que los arrays no pueden
cambiar de longitud:

```
push  ( elt seq -- )    ! append to the end
pop   ( seq -- elt )    ! remove and return the last
pop*  ( seq -- )        ! remove the last, discard
```

```factor
USING: kernel sequences vectors ;

V{ } clone              ! a fresh empty vector
"alice" over push       ! V{ "alice" }
"bob"   over push       ! V{ "alice" "bob" }
dup pop .               ! prints "bob"
.                       ! prints V{ "alice" }
```

## Vector → array

Cuando has construido un vector y quieres devolver un array de longitud
fija, `>array ( seq -- array )` (en [`arrays`][arrays]) devuelve un
array nuevo con los mismos elementos:

```factor
USING: arrays kernel prettyprint sequences vectors ;

V{ "alice" "bob" "carol" } >array .
! => { "alice" "bob" "carol" }
```

## `clone`: conserva una instantánea

La mutación modifica la secuencia en el lugar. Si quien llama te pasa una
secuencia y estás a punto de cambiarla, `clone` (en
[`kernel`][kernel]) te da una copia nueva e independiente para que lo que
ve quien llama no se modifique por debajo:

```factor
USING: kernel prettyprint ;

V{ "a" "b" "c" } clone .    ! => V{ "a" "b" "c" }   (a fresh copy)
```

La misma precaución aplica a `V{ }` y a otros literales vacíos. En algunos
lenguajes, `[]` o `vec![]` reserva un contenedor nuevo cada vez que se
evalúa la expresión. En Factor, el literal `V{ }` escrito en tu código
fuente es *un solo* objeto, compartido por cada sitio de llamada que lo
menciona. Si haces `push` directamente sobre `V{ }`, la siguiente llamada
ve los restos. `V{ } clone` crea la copia nueva que casi siempre quieres.
