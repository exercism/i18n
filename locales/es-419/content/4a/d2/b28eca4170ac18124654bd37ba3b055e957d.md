# Introducción

## Igualdad

Por lo general, la igualdad de los tipos simples (strings y primitivos) se prueba con `==` y `!=`.

Los tipos de referencia (instancias de clases) se comparan con el método `Equals()` heredado de `Object`. Si tu objetivo con la prueba de igualdad es asegurarte de que dos objetos sean exactamente la misma instancia, basta con confiar en la implementación de `Object`. Si no es así, necesitas sobrescribir `object.Equals()`.

Si sabes que todas las instancias de tu clase se crean en un solo lugar, por ejemplo, personajes de algún juego o simulación, la igualdad de referencia es suficiente. Sin embargo, es probable que se creen varias instancias de la misma entidad del mundo real (desde una base de datos, por entrada del usuario, mediante una petición web). En ese caso, hay que probar la igualdad de los valores que identifican de forma única a la entidad. Por lo tanto, se debe sobrescribir `Equals()` y probar la igualdad de los miembros de datos apropiados de tu clase.

Un método `Equals()` sobrescrito contendrá pruebas de igualdad sobre miembros de tipos simples usando `==`, y sobre tipos de referencia con llamadas recursivas a `Equals()`.

La clase `Object` proporciona los métodos adecuados para comparar dos objetos y detectar si son una y la misma instancia.

### `Object.GetHashCode()`

El método `Object.GetHashCode()` devuelve un código hash en forma de entero de 32 bits. Las clases _diccionario_ y _conjunto_, como `Dictionary<T>` y `HashSet<T>`, usan el código hash para almacenar y recuperar objetos de manera eficiente.

La relación entre el código hash y la igualdad es que, si dos objetos son iguales (`Equal()` devuelve true), entonces `GetHashCode()` debe devolver el mismo valor para ambos. Esto no aplica en la dirección inversa. No es simétrico. Que dos objetos tengan el mismo código hash no significa que tengan que ser iguales. Imagina una función de búsqueda que primero va a un «cubo» según el código hash y luego elige el elemento concreto usando la prueba de igualdad.

La documentación de la API de la biblioteca HashCode explica cuál es la mejor manera de generar un código hash.

Los valores que se usan en la prueba de igualdad deben ser estables mientras se está usando la colección con hash. Si agregas un objeto a la colección con un conjunto de valores y luego cambias esos valores, el código hash ya no apuntará al «cubo» correcto. En la práctica, esto significa que el objeto debe ser inmutable. Otras estrategias corren el riesgo de crear trampas para quienes mantienen el código.

## Conjuntos

Un conjunto es una colección de valores únicos. La implementación predeterminada de un conjunto en .NET es la clase `HashSet<T>`, que es una colección que solo contiene valores únicos.
