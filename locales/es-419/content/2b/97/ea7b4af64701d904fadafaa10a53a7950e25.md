# Acerca de

Los hash-sets implementan el [protocolo][set-protocol] [`sets`][sets] con hashing
por debajo, lo que da inserciones, búsquedas y eliminaciones de O(1) en promedio.
Se modifican en el lugar, y eso los hace ideales para el patrón del
*conjunto de visitados* en recorridos de grafos.

```factor
USING: hash-sets kernel sets ;

HS{ } clone                   ! fresh empty mutable set
"NS-1024" over adjoin         ! insert (no-op if already present)
"NS-1024" over in? .          ! => t  (membership test)
"WB-203" over adjoin
over cardinality .            ! => 2
"NS-1024" over delete         ! remove
over cardinality .            ! => 1
```

| palabra       | efecto                                    |
|---------------|-------------------------------------------|
| `HS{ }`       | literal de hash-set vacío (es compartido: ¡hazle `clone`!) |
| `>hash-set`   | `( seq -- set )`: construye un conjunto nuevo a partir de una secuencia (elimina duplicados) |
| `adjoin`      | `( elt set -- )`: inserción destructiva   |
| `in?`         | `( elt set -- ? )`: pertenencia           |
| `delete`      | `( elt set -- )`: eliminación destructiva |
| `cardinality` | `( set -- n )`: número de elementos       |
| `null?`       | `( set -- ? )`: verdadero cuando el conjunto está vacío |
| `members`     | `( set -- seq )`: enumera como secuencia  |
| `union`       | `( set1 set2 -- set )`                    |
| `intersect`   | `( set1 set2 -- set )`                    |
| `diff`        | `( set1 set2 -- set )`                    |
| `set-like`    | `( set exemplar -- set' )`: convierte `set` a la clase de `exemplar` |

Para construir un conjunto a partir de datos que ya tienes, `>hash-set` convierte
cualquier secuencia en un solo paso y descarta los duplicados: `{ 2 3 2 5 } >hash-set`
da `HS{ 2 3 5 }`. Es la contraparte en bloque de ir haciendo crecer un conjunto
con `adjoin` repetido.

Un detalle sutil sobre `in?` frente a `member?` (de
`sequences`): ambos comprueban pertenencia, pero `member?` hace un
recorrido lineal por una secuencia, mientras que `in?` despacha al método de
protocolo que tenga el tipo del conjunto: para `HS{ }`, eso es una
búsqueda en la tabla hash. Usa `in?` cuando tu contenedor de
«visitados» tenga más que un puñado de elementos.

`null?` responde a «¿este conjunto está vacío?» sin calcular por completo la
`cardinality`: es la guarda natural para «¿nos queda algo por procesar?».
Para una lista de trabajo guardada como conjunto, `[ set null? ] [ … ] until`
la consume hasta dejarla vacía.

## Combina de maravilla con las tablas hash

`HS{ }` para «¿ya visité X?» combina de forma natural con `H{ }` para
«¿quiénes son los vecinos de X?». Un recorrido en profundidad (DFS) de manual es
simplemente esto:

```factor
visited adjoin
stack push
[ stack empty? ] [
    stack pop dup neighbours-quot call [
        dup visited in? [ drop ] [
            [ visited adjoin ] [ stack push ] bi
        ] if
    ] each
] until
```

El conjunto de visitados elimina el trabajo duplicado; la pila encadena los
nodos de la frontera (LIFO mediante `push`/`pop`); el mapa de vecinos (una
tabla hash) aporta el grafo. El orden de visita no importa para una
pregunta de alcanzabilidad, y por eso basta con un vector usado como pila:
una búsqueda en anchura (BFS) real sobre la misma estructura cambia el vector
por una [`<dlist>`][dlist] y saca los elementos por el frente, en lugar del final.
