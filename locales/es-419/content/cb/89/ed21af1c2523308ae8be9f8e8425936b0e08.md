# Introducción

## JSON

### JSON

JSON (JavaScript Object Notation) es un formato de datos y de archivo legible por humanos que se usa comúnmente para intercambiar datos, en particular en aplicaciones web.
Como tal, no sorprende que ocupe un lugar especial en el lenguaje Elm.

Elm proporciona los módulos principales `Json.Decode` y `Json.Encode` para analizar y escribir datos JSON.
Los decodificadores JSON son una forma de _declarar_ qué tipo de datos se espera y a qué estructura de datos se deben mapear los datos.

Importemos algunos alias y tipos de los módulos:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

Usar `Decode.decodeString : Decoder a -> String -> Result Error a` con un decodificador y un string JSON tendrá éxito si el string cumple con las especificaciones del decodificador, o fallará en caso contrario.
No hay forma de inspeccionar los datos JSON sin procesar al definir el decodificador, lo cual puede resultar inusual si vienes de lenguajes imperativos.

### Decodificadores de tipos de datos básicos

JSON tiene una pequeña cantidad de tipos de datos básicos:

- String: se codifica con comillas dobles `"hello world"`
- Boolean: ya sea `true` o `false`
- Number: como `34` o `0.12`
- Null: la ausencia de datos `null`

Cada uno de estos está asociado con una función de `Decode`:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

Fíjate que `Decode.null` te permite decidir cómo modelar un `null` en tu programa al requerir un valor arbitrario como argumento (quizás `()`, `Nothing`, o cualquier cosa apropiada para tu programa).

### Combinar decodificadores

JSON también define dos estructuras de datos para agrupar tipos de datos básicos:

- Array: una colección de otros tipos de datos `[0, null, "none", []]`
- Object: una colección de pares clave-valor `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode` también ofrece funciones para decodificar estos:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

Estas funciones `Decode.list : Decoder a -> Decoder (List a)` y `Decode.dict : Decoder a -> Decoder (Dict String a)` esperan cada una un decodificador como argumento, que debe decodificar cada uno de los elementos de la estructura de datos.
Si el decodificador del argumento no logra decodificar algún elemento de un valor de tipo array u object, el decodificador completo falla, lo cual es un patrón común.

Combinar decodificadores simples en otros más complejos es la idea central de la técnica.
Presentaremos varias funciones más que se pueden usar para construir decodificadores de datos del mundo real arbitrariamente complejos mediante un ejemplo.

### GeoJSON

Para practicar la combinación de decodificadores básicos para analizar datos JSON complejos, construyamos decodificadores para analizar (un subconjunto de) datos GeoJSON.
GeoJSON es un formato de datos especializado basado en JSON que se usa para representar características geográficas, como ubicaciones, rutas o regiones, especificadas con coordenadas geográficas 2D o 3D, junto con otras propiedades.

#### Objeto geométrico

Un objeto geométrico de GeoJSON es un objeto que contiene un campo `type` con un valor de tipo string (hay 7 valores posibles para `type`) y un campo `coordinates` con coordenadas geográficas (recolectadas en una estructura que depende del tipo).
Por ejemplo,

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

o

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

Un objeto geométrico se podría representar en Elm con el siguiente tipo

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

Para inspeccionar el valor de un campo determinado, podemos usar `Decode.field : String -> Decoder a -> Decoder a`, que decodifica el valor de una clave específica de un objeto.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

Para transformar el valor que un decodificador analizó correctamente, podemos usar `Decode.map : (a -> value) -> Decoder a -> Decoder value`, o cualquiera de sus variantes, desde `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` hasta `Decode.map8`.

En este caso, queremos decidir qué decodificador de coordenadas usar según el valor del campo `type`, lo cual es un trabajo perfecto para `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` y sus compañeros `Decode.succeed : a -> Decoder a` y `Decode.fail : String -> Decoder a`.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

Fíjate en este punto que podríamos usar `Decode.andThen` para validar las coordenadas (verificando que las coordenadas vengan en pares o tríos y que los valores de las coordenadas tengan sentido geográfico).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

#### Objeto Feature

Un objeto Feature de GeoJSON representa algo delimitado espacialmente: tiene un campo `type` con el valor `"Feature"`, un campo `geometry` con un objeto geométrico o un `null`, un campo `properties` con un objeto JSON arbitrario o un `null`, y un campo `id` opcional con un valor de tipo string o number de JSON.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

o

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

Abordemos primero el campo `id`.
Si existe, debe admitir strings o números, así que podríamos introducir un tipo personalizado para el valor o guardarlo siempre como string.

Para elegir entre dos decodificadores posibles, podemos usar `Decode.oneOf : List (Decoder a) -> Decoder a`.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

Para expresar que el campo es opcional, podríamos usar la misma técnica

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

Pero en su lugar podríamos usar `Decode.maybe : Decoder a -> Decoder (Maybe a)`

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

Fíjate que `decodeMaybeFeatureId` (o cualquier decodificador envuelto con `Decode.maybe`) siempre tendrá éxito, ya que siempre puede recurrir a `Ok Nothing`, aunque un decodificador que lo use todavía podría fallar

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

A continuación, enfoquémonos en el campo `geometry`, que puede ser un objeto geométrico o `null`.
Podríamos usar `Decode.oneOf` una vez más, pero hay una mejor opción: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` y `Decode.nullable` tienen la misma firma, pero su comportamiento es diferente, ya que el resultado `OK Nothing` de un `Decode.nullable` solo provendrá del valor JSON específico `null`.

Finalmente, el campo `properties` puede contener un objeto JSON arbitrario o un `null`, lo cual es trabajo para `Decode.value : Decoder Value`.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

Fíjate que `Value` es un tipo opaco, lo que significa que no puedes inspeccionar su contenido fácilmente.
Para usarlo, puedes escribir un decodificador para él y ejecutarlo con `Decode.decodeValue : Decoder a -> Value -> Result Error a`, o enviarlo a JavaScript directamente a través de un puerto.

Estamos listos para analizar objetos Feature:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

### Codificadores JSON

Los codificadores permiten escribir JSON válido a partir de valores de Elm usando la función `Encode.encode : Int -> Value -> String`.
El primer argumento especifica la cantidad de indentación en el resultado final, y el segundo argumento es el valor JSON que se va a escribir.

Un `Value` se puede obtener de `Decode.value` o producirse con uno de los codificadores:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

así como con `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

Definamos codificadores para los decodificadores de GeoJSON definidos anteriormente

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

En general, una buena prueba para tus pares decodificador-codificador es verificar que `elmValue |> encoder |> decoder == elmValue`.
