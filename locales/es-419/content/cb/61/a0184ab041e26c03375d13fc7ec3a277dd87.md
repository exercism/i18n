# Introducción

Python es un lenguaje de programación [dinámico y de tipado fuerte][dynamic typing in python].
Emplea tanto el [duck typing][duck typing] como el [tipado gradual][gradual typing], mediante [anotaciones de tipo][type hints].
Python pone mucho énfasis en la legibilidad del código y (_de forma similar a Haskell_) usa la [indentación significativa][significant indentation] para denotar definiciones de funciones, métodos y clases.

Python fue creado por Guido van Rossum y se publicó por primera vez en 1991.

Se admiten los _estilos_ de programación imperativo, declarativo (por ejemplo, funcional) y orientado a objetos, pero internamente **[todo en Python es un objeto][everythings an object]**.

Profundizaremos más en lo que significa todo esto a medida que avancemos por los conceptos de la ruta de Python.

Este primer concepto (`basics`) presenta 4 características principales del lenguaje Python:
1.  Asignación de nombres (_variables y constantes_),
2.  Funciones (_la palabra clave `def` y la palabra clave `return`_),
3.  Comentarios, y
4.  Docstrings.

<br>

## Asignación de nombres (variables y constantes)

Quienes programan pueden vincular [_nombres_][facts-and-myths-about-python-names] (también llamados _variables_) a cualquier tipo de objeto usando el operador de asignación `=`: `<name> = <value>`.
Un nombre se puede reasignar (o revincular) a valores distintos (tipos de objeto distintos) a lo largo de su vida:


```python
>>> my_first_variable = 1  # <--my_first_variable bound to an integer object of value one.
>>> my_first_variable = 2  # <--my_first_variable re-assigned to integer value 2.

>>> print(type(my_first_variable))
<class 'int'>

>>> print(my_first_variable)
2

>>> my_first_variable = "Now, I'm a string." # <--You may re-bind a name to a different object type and value.
>>> print(type(my_first_variable))
<class 'str'>

>>> my_first_variable = 'You can call me "str".' # <--Strings can be declared using single or double quote marks.
>>> print(my_first_variable)
You can call me "str".
```


### Constantes

Las constantes son nombres que están pensados para asignarse solo una vez en un programa, aunque Python no impedirá la reasignación.
Usar `SCREAMING_SNAKE_CASE` le indica a cualquiera que lea el código que el nombre **no** se debe reasignar ni se debe modificar su valor.
Las constantes se deben definir a nivel de [módulo][module] (archivo) y, por lo general, son visibles para todas las funciones y clases de un programa.



## Funciones

La palabra clave `def` da inicio a una [definición de función][function definition].
Cada función puede tener cero o más [parámetros][parameters] formales entre paréntesis `()`, seguidos de dos puntos `:`.
Las sentencias del _cuerpo_ de la función comienzan en la línea que sigue a `def` y deben estar _indentadas en un bloque_.


```python
# The body of this function is indented by 2 spaces & prints the sum of the numbers.
def add_two_numbers(number_one, number_two):
  total = number_one + number_two
  print(total)  

>>> add_two_numbers(3, 4)
7


# Inconsistent indentation in your code blocks will raise an error.
>>> def add_three_numbers_misformatted(number_one, number_two, number_three):
...     result = number_one + number_two + number_three   # This was indented by 4 spaces.
...    print(result)     # <--This was only indented by 3 spaces.
...
...
  File "<stdin>", line 3
    print(result)
    ^
IndentationError: unindent does not match any outer indentation level
```


Las funciones devuelven _explícitamente_ un valor u objeto mediante la palabra clave [`return`][return]:


```python
# Function definition on first line, explicit return used on final line.
def add_two_numbers(number_one, number_two):
  return number_one + number_two   


# Calling the function in the Python shell returns the sum of the numbers.
>>> add_two_numbers(3, 4)
7

# Assigning the function call to a variable and printing 
# the variable will also return the value.
>>> sum_with_return = add_two_numbers(5, 6)
>>> print(sum_with_return)
11
```


Las funciones que no tienen una expresión _explícita_ después de un `return` devolverán _implícitamente_ el objeto [`None`][none].
Los detalles de `None` se cubrirán en un concepto posterior.
Para los fines de este ejercicio y de esta explicación, `None` es un marcador de posición que representa nada, o null:


```python
# This function will return `None`
def square_a_number(number):
    square = number * number
    return # <-- note that this return is not followed by an expression

# Calling the function in the Python shell appears 
# to not return anything at all.
>>> square_a_number(2)
>>>


# Using print() with the function call shows that 
# the function is actually returning the **None** object.
>>> print(square_a_number(2))
None
```

Las funciones que omiten `return` también devolverán _implícitamente_ el objeto [`None`][none].
Esto significa que si no usas `return` en una función, Python devolverá el objeto `None` por ti.

```python
# This function omits a return keyword altogether.
def add_two_numbers(number_one, number_two):
  result = number_one + number_two

>>> add_two_numbers(5, 7)
>>> print(add_two_numbers(5, 7))
None

# Assigning the function call to a variable and printing 
# the variable will also show None.
>>> sum_without_return = add_two_numbers(5, 6)
>>> print(sum_without_return)
None
```


## Comentarios

Los [comentarios][comments] en Python comienzan con un `#` que no forma parte de un string y terminan al final de la línea.
A diferencia de muchos otros lenguajes de programación, Python **no admite** marcas de comentario multilínea.
Cada línea de un bloque de comentarios debe comenzar con el carácter `#`.


## Docstrings

La primera sentencia del cuerpo de una función puede ser, de forma opcional, un [_docstring_][docstring], que resume de manera concisa el propósito de la función o del objeto.
Los docstrings los leen herramientas de documentación automatizadas como [Sphinx][sphinx] y se obtienen llamando al atributo especial `.__doc__` en el nombre de la función, el método o la clase.
Las convenciones generales de los docstrings se describen en [PEP257][pep257], pero los formatos exactos varían según el proyecto y el equipo.
Los docstrings se declaran usando triples comillas dobles (""") indentadas al mismo nivel que el bloque de código:


