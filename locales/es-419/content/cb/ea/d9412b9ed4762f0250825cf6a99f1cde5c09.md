# Contratos

Los argumentos y el tipo de retorno de una rutina dicen qué *tipo* de cosa entra
y sale. No pueden decir que un peso deba ser positivo, ni que un arnés nunca
reporte más capacidad libre de la que tiene.

Un **contrato** dice esas cosas, en el propio encabezado de la rutina, donde
cualquiera que la lea las verá.

## pre

`pre` establece lo que debe ser verdadero cuando se llama a la rutina. Va entre
el tipo de retorno y el `is`.

```sather
   spare_capacity(load : INT) : INT
      pre load >= 0
   is
      return limit - load;
   end;
```

Eso es una exigencia para **quien llama**: no llames a esta rutina con una carga
negativa.

## post

`post` establece lo que será verdadero cuando la rutina responda. Dentro de él,
`result` es el valor que se devuelve.

```sather
   percent_used(load : INT) : INT
      pre load >= 0
      post result >= 0
   is
      return load * 100 / limit;
   end;
```

Eso es una promesa para quien llama. Una rutina que tiene ambas cosas es un
trato: dame esto y yo te doy aquello.

Varias condiciones se unen con `and`, como lo hace cualquier Boolean:

```sather
      pre load >= 0 and load <= limit
```

## Los contratos no son excepciones

Una excepción lanzada es para algo que puede pasar. Un contrato roto significa
un **bug**: alguien llamó mal a la rutina, o la rutina no hizo lo que decía.

Así que un contrato roto no lanza algo que se pueda capturar. Cuando la
verificación de contratos está activada, el programa se detiene e imprime qué
rutina y qué condición. Cuando está desactivada, la condición ni siquiera se
evalúa, y el programa sigue ejecutándose hacia cualquier disparate que venga
después.

Por eso un contrato es una afirmación sobre la corrección y no una forma de
manejar argumentos incorrectos. Si esperas un argumento incorrecto, verifícalo y
lanza `raise`. Si un argumento incorrecto significa que quien llama está mal,
dilo con `pre`.

## Cómo activar la verificación

Este Sather verifica los contratos cuando se le pasa `-chk` al compilador:

```
sacomp -chk mine.sa -main MAIN -o mine
```

Sin esa opción, `pre` y `post` son documentación que el compilador leyó y aceptó
como bien formada, y nada más. Las pruebas de este ejercicio se compilan sin
`-chk`, así que no pueden detectar por ti un contrato roto; verifican que las
rutinas hagan lo correcto cuando se usan bien.
