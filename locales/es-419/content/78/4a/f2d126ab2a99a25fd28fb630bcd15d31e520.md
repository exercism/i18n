# Instrucciones

Has estado trabajando en la oficina municipal durante un tiempo y has desarrollado un conjunto de herramientas que agilizan tu trabajo del día a día, por ejemplo, a la hora de llenar formularios.

Ahora se te une un nuevo colega y te diste cuenta de que puede que tus herramientas no se expliquen por sí solas. En tu oficina hay muchas convenciones extrañas, como llenar siempre los formularios con letras mayúsculas y evitar dejar campos vacíos.

Decides escribir algo de documentación para que tu nuevo colega pueda ponerse manos a la obra y empezar a usar tus herramientas enseguida.

## 1. Documenta el propósito de las herramientas de formularios

Agrega documentación al módulo `Form` que describa su propósito. Debe decir:

```
A collection of loosely related functions helpful for filling out various forms at the city office.
```

## 2. Documenta el llenado de campos con valores en blanco

Agrega documentación y un typespec a la función `Form.blanks/1`. La documentación debe decir:

```
Generates a string of a given length.

This string can be used to fill out a form field that is supposed to have no value.
Such fields cannot be left empty because a malicious third party could fill them out with false data.
```

El typespec debe explicar que la función acepta un solo argumento, un entero no negativo, y devuelve un string.

## 3. Documenta la división de valores en listas de letras mayúsculas

Agrega documentación y un typespec a la función `Form.letters/1`. La documentación debe decir:

```
Splits the string into a list of uppercase letters.

This is needed for form fields that don't offer a single input for the whole string,
but instead require splitting the string into a predefined number of single-letter inputs.
```

El typespec debe explicar que la función acepta un solo argumento, un string, y devuelve una lista de strings.

## 4. Documenta la comprobación de si un valor cabe en un campo con una longitud máxima

Agrega documentación y un typespec a la función `Form.check_length/2`. La documentación debe decir:

```
Checks if the value has no more than the maximum allowed number of letters.

This is needed to check that the values of fields do not exceed the maximum allowed length.
It also tells you by how much the value exceeds the maximum.
```

El typespec debe explicar que la función acepta dos argumentos, un string y un entero no negativo, y devuelve uno de dos valores posibles. Devuelve el átomo `:ok` o una tupla de 2 elementos cuyo primer elemento es el átomo `:error` y el segundo, un entero positivo.

## 5. Documenta los distintos formatos de dirección

Por alguna razón que desconoces, el sistema interno de la oficina municipal usa dos formas distintas de representar las direcciones: como un mapa o como una tupla.

Documenta este hecho definiendo tres tipos públicos personalizados:
- `address_map`: un mapa con las claves `:street`, `:postal_code` y `:city`. Cada clave contiene un valor de tipo string.
- `address_tuple`: una tupla con tres valores: `street`, `postal_code` y `city`. Cada valor es de tipo string. Diferencia los valores dándoles nombres en el typespec.
- `address`: puede ser un `address_map` o un `address_tuple`.

## 6. Documenta cómo formatear la dirección

Agrega documentación y un typespec a la función `Form.format_address/1`. La documentación debe decir:

```
Formats the address as an uppercase multiline string.
```

El typespec debe explicar que la función acepta un argumento, una dirección, y devuelve un string.
