# Introducción

El sistema de errores de Factor tiene tres partes: `throw` para lanzar un error, `recover` para manejar uno, y `ERROR:` para definir tu propio tipo de error.

## `throw`

`throw` (en [`kernel`][kernel]) lanza un error. El argumento puede ser *cualquier* valor (un string, un número o una tupla), y se convierte en el error que puedes inspeccionar después:

```factor
! DOCTEST: SKIP
"file not found" throw
```

`throw` no devuelve; el resto de la palabra actual se omite.

## `recover`

`recover` (en [`continuations`][continuations]) es el try/catch de Factor. Recibe una cita *try* y una cita *recovery*:

```
recover ( try recovery -- )
```

Si `try` termina sin lanzar un error, `recovery` se ignora. Si `try` lanza un error, el error se coloca en la pila y se ejecuta `recovery`:

```factor
[ "boom" throw ] [ drop "caught" ] recover .
! => "caught"

[ "ok" ] [ drop "never runs" ] recover .
! => "ok"
```

`when` de [`kernel`][kernel] es el compañero natural: ejecuta una cita solo cuando la parte superior de la pila es verdadera:

```factor
: check-positive ( n -- )
    0 < [ "negative!" throw ] when ;
```

## `ERROR:`

`ERROR:` define una clase de tupla *y* una palabra que construye una instancia nueva y la lanza:

```factor
! DOCTEST: SKIP
ERROR: not-found path ;

"/missing" not-found
! throws T{ not-found { path "/missing" } }
```

Un error sin slots es simplemente `ERROR: name ;`: llamar a `name` lanza una instancia vacía. Las tuplas definidas con `ERROR:` llevan un predicado de clase `name?` que puedes usar para comprobar si un error capturado era de ese tipo.

## Recuperar los slots

Un error capturado es simplemente una tupla, así que cada slot de `ERROR:` viene con el mismo lector `slot>>` autogenerado que cualquier otra tupla.

```factor
! DOCTEST: SKIP
{
    T{ not-found { path "/a" } }
    T{ not-found { path "/b" } }
}
[ path>> ] map .   ! => { "/a" "/b" }
```
