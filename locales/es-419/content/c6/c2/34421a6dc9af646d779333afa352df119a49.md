# Tipos de string

Cairo no tiene un tipo de dato nativo para los string.
Sin embargo, hay dos formas de representar un tipo string: los string cortos usando un solo `felt252` y los string de longitud arbitraria usando `ByteArray`.

## String cortos

Un string corto se forma con comillas simples, donde cada carácter que compone el string se codifica en un byte siguiendo el [estándar ASCII][ascii-table].

Como string ASCII, por ejemplo, `'abc'` será:

- `'a'` es equivalente a `0x61`
- `'b'` es equivalente a `0x62`
- `'c'` es equivalente a `0x63`
- `'abc'` es equivalente a `0x616263`

El tipo de dato `felt252` almacena los string cortos en Cairo.
Como `felt252` contiene 251 bits, un string corto está limitado a 31 caracteres (31 \* 8 = 248 bits, que es el máximo múltiplo de 8 que cabe en 251 bits).

Ejemplos de declaraciones de string cortos:

```rust
    let my_first_char = 'D';
    let my_first_char_in_hex = 0x44;

    let my_first_string = 'Hello world';
    let my_first_string_in_hex = 0x48656C6C6F20776F726C64;
```

### ByteArray

La estructura ByteArray se introdujo en Cairo 2.4.0.
Los string de tipo ByteArray se escriben con comillas dobles de la siguiente manera:

```rust
    let long_string: ByteArray = "this is a string which has more than 31 characters";
```

Técnicamente, la actualización también introdujo el tipo `bytes31`, que almacena 31 bytes y que cabe en un felt.
La estructura `ByteArray` básicamente representa un string largo usando un array de `bytes31` que contienen las «palabras completas» (es decir, palabras que llenan todo el felt) y un único campo felt que contiene una «palabra incompleta» (el número de bytes que hay dentro se especifica en un campo de longitud aparte).

```rust
#[derive(Drop, Clone, PartialEq, Serde, Default)]
struct ByteArray {
    data: Array<bytes31>,
    pending_word: felt252,
    pending_word_len: usize,
}
```
