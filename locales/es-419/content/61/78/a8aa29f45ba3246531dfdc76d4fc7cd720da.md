# Booleanos

`BOOL` contiene uno de dos valores: `true` y `false`.

```sather
   ready : BOOL is
      return true;
   end;
```

## Comparación

| Operador | Pregunta | Ejemplo |
| --- | --- | --- |
| `=` | ¿son iguales? | `age = 13` |
| `/=` | ¿son diferentes? | `age /= 13` |
| `<` | menor que | `age < 13` |
| `<=` | menor o igual que | `age <= 13` |
| `>` | mayor que | `age > 13` |
| `>=` | mayor o igual que | `age >= 13` |

Estos funcionan con números, y `=` y `/=` también funcionan con strings.

## Los tres operadores

| Operador | Se escribe | Verdadero cuando |
| --- | --- | --- |
| and | `a and b` | ambos son verdaderos |
| or | `a or b` | al menos uno es verdadero |
| not | `~a` | `a` es falso |

`and` y `or` tienen **evaluación de cortocircuito**: `a and b` no se molesta en
mirar `b` cuando `a` resulta ser falso, porque la respuesta ya está decidida.
De igual manera, `a or b` se detiene si `a` es verdadero. Eso importa cuando el
lado derecho es costoso o daría error si se ejecutara.

## Devolver una comparación directamente

Una rutina cuyo único trabajo es hacer una pregunta debería devolver la
pregunta, no elegir una respuesta con un condicional:

```sather
   -- say this
   old_enough(age : INT) : BOOL is
      return age >= 13;
   end;
```

Escribir `if age >= 13 then return true else return false end` usa tres líneas
para decir lo que la comparación ya decía, y cualquier lector con experiencia
se va a dar cuenta.

## Precedencia

`~` tiene la precedencia más alta, después va `and` y luego `or`. Entonces

```sather
~a and b or c
```

significa `((~a) and b) or c`. Los paréntesis no cuestan nada de escribir, y
valen la pena siempre que un lector tuviera que recordar ese orden para poder
seguir la línea.
