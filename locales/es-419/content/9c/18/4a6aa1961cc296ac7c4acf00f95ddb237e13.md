# Inclusión de código

`circus-acts` usaba `<` para decir que una clase *puede hacer* lo que describe una clase abstracta. No decía nada sobre cómo.

`include` es la otra mitad: toma el código real de otra clase y pone una copia de él en esta.

```sather
class WARM_UP is

   count : INT is return 8; end;

   describe : STR is return count + " counts"; end;

end; -- class WARM_UP

class JAZZ_ROUTINE is

   include WARM_UP;

   -- count and describe are now here too, as though written out.

end; -- class JAZZ_ROUTINE
```

`JAZZ_ROUTINE::count` es 8, sin que `JAZZ_ROUTINE` lo mencione.

## Estas son dos decisiones separadas

La mayoría de los lenguajes las unen: un solo `extends` hereda el código y hace que la subclase se pueda usar dondequiera que se use la superclase. Sather las mantiene separadas.

| Escrito | Dice |
| --- | --- |
| `class A < $B` | un `A` se puede usar dondequiera que se quiera un `$B` |
| `class A is include B` | `A` empieza con una copia del código de `B` |

Cualquiera de las dos sin la otra, o ambas. Incluir una clase **no** la convierte en un subtipo: después de `include WARM_UP`, un `JAZZ_ROUTINE` todavía no se puede usar donde se quiere un `WARM_UP`, y nada pretende lo contrario.

## Cambio de nombre

A una rutina incluida se le puede dar otro nombre:

```sather
   include WARM_UP count -> warm_up_count;
```

Varias se separan con comas:

```sather
   include WARM_UP count -> warm_up_count, describe -> warm_up_describe;
```

## Dejar una fuera

Renombrar a *nada* la deja fuera, y así es como se reemplaza:

```sather
class TAP_ROUTINE is

   include WARM_UP describe -> ;

   describe : STR is return "Tap: " + count + " counts"; end;

end; -- class TAP_ROUTINE
```

`count` entra como siempre; `describe` no, así que escribir uno aquí no genera un choque. Sin el `describe -> ;` el compilador se negaría: dos rutinas con el mismo nombre y los mismos argumentos en una misma clase son un error, y Sather no va a adivinar cuál querías.

Esa es la diferencia con una sobrescritura en la mayoría de los lenguajes: el reemplazo se anuncia en lugar de darse por implícito.
