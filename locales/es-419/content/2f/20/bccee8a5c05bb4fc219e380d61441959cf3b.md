# Guías para contribuir

Si quieres participar en el desarrollo del track de Pharo, sigue las instrucciones que aparecen a continuación; te ayudarán a empezar.

¡Tenemos muchas ganas de mejorar este track y de mostrarles a los desarrolladores otra forma de pensar la programación! :tada:

Lee cómo [involucrarte en un track de Exercism](https://github.com/exercism/docs/tree/master/contributing-to-language-tracks) y asegúrate también de leer el [Código de conducta de Exercism](https://exercism.io/code-of-conduct).

Aceptamos pull requests de todo tipo. Ninguna contribución es demasiado pequeña, sobre todo las que corrigen y mejoran ejercicios existentes. Ten en cuenta que los ejercicios de este track deben cumplir con los [estándares de Exercism](https://github.com/exercism/docs/tree/master/language-tracks/exercises), pero si tienes dudas sobre cómo hacer un cambio, abre un issue en GitHub y lo comentamos.

>__Nota__: La organización de Exercism decidió [pausar las contribuciones de la comunidad en general](https://exercism.org/blog/freeing-our-maintainers). El track de Pharo quedó excluido de esta política, porque nuestra comunidad es bastante pequeña (en otras palabras: cualquier persona que contribuya al track de Pharo todavía puede crear issues y enviar PRs).

## Conocimientos previos

Se espera que ya tengas [familiaridad](./docs/RESOURCES.md) con el desarrollo en Pharo y con su uso de [Iceberg Git](https://github.com/pharo-vcs/iceberg).

## Configuración del entorno de desarrollo

Para empezar, asegúrate de tener un entorno de desarrollo completo de Exercism y de tener instalados los siguientes artefactos:

### __Imagen de Pharo e IDE__

Necesitas tener un entorno de desarrollo de Pharo (una imagen de Pharo en ejecución, es decir, el IDE) para crear los ejemplos de código reales.

1. Usa [PharoLauncher](https://pharo.org/download) para crear una imagen de desarrollo estable y nueva a partir de la categoría `Official distributions` (al 05/24, la imagen estable es: Pharo 12.0 - 64bit (stable)) y lánzala (también puedes usar [zerconf](https://get.pharo.org/) si ya lo conoces).
2. Lanza tu imagen para comprobar que todo funcione bien.

> __Nota__: Si tienes algún problema de TIMEOUT, consulta las [instrucciones de instalación para usuarios](./docs/INSTALLATION.md).

### __Configuración de los repositorios de git__

1. Si no lo has hecho antes, haz un fork de `https://exercism/pharo-smalltalk` en GitHub.
2. Para clonar tu fork, evalúa el siguiente comando en el Playground de la imagen de Pharo en ejecución:
```
Metacello new
 baseline: 'Exercism';
 repository: 'github://exercism/pharo-smalltalk:main/releases/latest';
 load: 'dev'
```
Esto clonará el repositorio git del track de Pharo y cargará el código fuente del track en la imagen de Pharo, es decir, su línea base de desarrollo. La carpeta local con el repositorio clonado se ubicará en (según tus preferencias de Iceberg): `<path-to-Pharo-image>/pharo-local/iceberg/<your-id/pharo-smalltalk`.
> __Nota__: Las fuentes de la imagen de Pharo se sincronizan y se serializan en archivos `*.st` ubicados en la subcarpeta `src` del directorio mencionado.

2. Otra forma de hacer lo mismo es clonar tu fork por medio de la CLI: `git clone https://github.com/<your id>/pharo-smalltalk` como proyecto de GitHub y especificar `<your id>` como nombre del propietario y `pharo-smalltalk` como nombre del proyecto.
Luego instala la línea base `dev` de Metacello (no la predeterminada) en Iceberg usando el menú contextual de Metacello de la imagen de Pharo en ejecución (por ejemplo, haz clic derecho en el proyecto «pharo-smalltalk» que acabas de clonar, selecciona la segunda opción del menú de Metacello y escribe `dev`).

3. Después de cargar el proyecto en la imagen de Pharo, no olvides __guardar la imagen__ para conservar los cambios (elemento de menú Pharo -> Save).

__Repositorios opcionales__
1. Como alternativa, puedes usar `git clone https://github.com/exercism/pharo-smalltalk` como repositorio de staging en el que generarás ejercicios y recursos para registrar (por separado de la programación en Pharo). Ten en cuenta que los cambios que genere la herramienta Configlet en este repositorio deberán copiarse a tu repositorio fork local. Se sugiere usar algo como `~/development/exercism/pharo-staging` para evitar confusiones (nota: puede estar en cualquier lugar). Este repositorio no es necesario; aún puedes generar los cambios de Configlet directamente en tu repositorio fork (el cual está sincronizado con tu imagen de Pharo), si tienes claro qué cambios incluir en el commit.
2. También puedes clonar las [especificaciones de problemas](https://github.com/exercism/problem-specifications) de Exercism, en caso de que quieras trabajar en ejercicios de práctica desde cero. Ubícalo también en un subdirectorio del espacio de trabajo de exercism que configures más abajo (este repositorio se usa para generar los archivos readme.md de los ejercicios y sirve de referencia para las pruebas sugeridas).

### __Nota sobre las ramas usadas del repositorio__

La rama `main` es la rama principal de desarrollo, en la que se integra todo. Si trabajas en algún cambio de código, crea una rama de trabajo a partir de `main` y haz allí tus commits. Cuando termines, abre un PR en GitHub para que se integre en `main` del repositorio base (Exercism/pharo-smalltalk). Esta rama antes se llamaba `master`, y __hoy está obsoleta__.

### __Configuración de las herramientas CLI de Exercism__

Estas herramientas son necesarias para interactuar con el proyecto Exercism:
1. La [interfaz de línea de comandos de exercism](https://exercism.io/cli-walkthrough), configurada apuntando al directorio de desarrollo de ejercicios de Exercism llamado espacio de trabajo (por ejemplo, `exercism configure -w ~/development/exercism`). Puede ser la ruta a tu repositorio fork local o, de forma opcional, al repositorio de staging.
2. El [configlet](https://github.com/exercism/configlet#usage) de Exercism, linter y generador para crear los metadatos de los ejercicios y ejecutar las validaciones. Para instalar Configlet, sigue las instrucciones del apartado [Cómo usarlo en tu track](https://github.com/exercism/configlet#use-in-your-track) (consulta bin/fetch-configlet).

## Trabajar en los ejercicios de Exercism

La organización de Exercism distingue entre ejercicios de concepto (que explican teoría de lenguajes de programación) y ejercicios de práctica. Por ahora, los párrafos siguientes se centran solo en contribuir con ejercicios de práctica.

### __Resumen__

Pasos para completar un ejercicio:
1a. Crear un ejercicio de práctica desde cero (a partir de las especificaciones de problemas).
1b. Trabajar en la solución de un ejercicio de práctica existente.
2a. Generar los archivos fuente serializados de la solución del ejercicio en un directorio y generar los metadatos del ejercicio.
2b. Ajustar la línea base del proyecto para incluir el ejercicio recién completado como parte del proyecto.
3. Hacer commit de los cambios en tu repositorio fork y publicarlos abriendo un PR.

#### TLDR: guía rápida para generar y exportar un ejercicio de práctica
En resumen: lo único que necesitas es generar y exportar el ejercicio desde Pharo. En el Playground, ejecuta:
```Smalltalk
"Obtain exercise from problem specification"
ExercismExerciseGenerator new generateExerciseFrom: 'path-to-problem-specifications/exercises/slug-name' asFileReference.

"Update exercise version within Pharo image  (with updated test cases) to output exercise directory (once you have solution class defined)"
ExercismGenerator new 
	exercisesDirReference: 'path-to-local-repository/exercises/practice' asFileReference;
	generateForExercise: 'slug-name'.
```
  > __Nota__: Encontrarás más detalles en los pasos de abajo. 

![Flujo de trabajo para completar un ejercicio de práctica](/docs/images/overview-exercism-pharo-contribution.svg)

### __1. Crear un nuevo ejercicio de práctica__
*TLDR: Todos los detalles y la descripción de la API relacionados con la generación de ejercicios están en el comentario de clase de la clase `ExercismExerciseGenerator`.*  

__Ejercicios nuevos a partir del repositorio de problemas__
- Si quieres empezar un ejercicio de práctica completamente nuevo (paso 1a.), puedes usar el repositorio de especificaciones de problemas y generar la clase de pruebas del ejercicio con: 
`ExercismExerciseGenerator generateFrom: <path-to-problem-specifications/exercises>`. Esto generará las clases de pruebas de todos los ejercicios del repositorio de especificaciones de problemas en el paquete `ExerciseWIP`.  

  > __Nota__: Puedes lograr lo mismo con un elemento de menú de la imagen de Pharo (World menu -> Exercism -> Generate test cases).
- De forma más específica, puedes generar la clase de pruebas de un ejercicio en particular con: `ExercismExerciseGenerator generateExerciseFrom: '<path-to-problem-specifications/exercises/slug-name>' asFileReference`.

El resultado de la sentencia anterior será una nueva clase de pruebas `<SlugNameTest>` (una subclase de ExercismTest) con los métodos de prueba generados en el paquete `ExerciseWIP`.

__Regenerar un ejercicio existente a partir del repositorio de problemas__
Si quieres regenerar los métodos de prueba de un ejercicio existente (ya definido en el paquete de la solución, por ejemplo `Exercise@TwoFer`), puedes usar el siguiente código. Ten en cuenta que los demás métodos no se tocarán (por ejemplo, uuid, version, etc.). 

 `ExercismExerciseGenerator new regenerateExerciseFrom: 'path-to-problem-specifications/exercises/exercise-slug' asFileReference`

__Desde cero__  
Si tienes una idea interesante, consulta la documentación sobre cómo agregar nuevos ejercicios.

En el proyecto hay un ejemplo de un ejercicio definido por el usuario: `DieTest`. Si sobrescribes el método customData, el generador creará por ti los archivos correspondientes.

Ten en cuenta que:
- Cada ejercicio debe ser independiente. No hagas referencia a archivos fuera del directorio del ejercicio, ya que no se incluirán cuando el usuario descargue el ejercicio.
- Los ejercicios deben cumplir con los [estándares de Exercism](https://exercism.org/docs/building/tracks/practice-exercises).
- Los ejercicios deben usar solo las bibliotecas del núcleo de Pharo.
- Cada ejercicio debe:
  - estar almacenado en un proyecto de nivel superior llamado `Exercism@<ExerciseName>`
  - tener un TestCase llamado `<ExerciseName>Test` (en CamelCase) y una solución de ejemplo llamada `<ExerciseName>`
  - el TestCase debe tener un comentario de clase en formato markdown que describa el ejercicio. Este texto también se usa para generar un archivo README.md.
- No hagas commit de archivos de configuración ni de directorios dentro del ejercicio (esto puede revisarse para ejercicios futuros; avísanos si se convierte en un problema).
- Asegúrate de generar un UUID nuevo para el ejercicio con `UUIDGenerator next` y colocar ese valor en el método `uuid` de la prueba.

> __Nota__: Lamentablemente, el generador de UUID actual de Pharo no cumple con el RFC 4122, versión 4. Por eso, debes usar el UUID que genera configlet, evaluando: `/bin/configlet uuid`

### __2. Trabajar en un ejercicio existente__

Aunque hay muchas formas de ayudar, la contribución más fácil y útil con diferencia es completar una solución para cualquiera de los ejercicios que están «abiertos» en este momento.

  * Asegúrate de que tu imagen esté al día con la rama main de exercism/pharo-smalltalk (y sube cualquier cambio de vuelta a tu fork)

  * Los ejercicios son todos TestCases generados automáticamente a partir del repositorio problem-specifications mencionado antes. Los encontrarás como subclases de ExercismTest en el paquete ExercismWIP. Ten en cuenta que el ExercismTest regenerado puede estar ya en el paquete del ejercicio correspondiente, si la solución ya estaba lista. El paquete ExercismWIP se usa para los ejercicios nuevos o en desarrollo que todavía no se han publicado junto con su clase de solución.

  * Cuando hayas elegido el ejercicio en el que quieres trabajar, crea un issue en GitHub con el título «Convert Exercise <name>». Así otras personas sabrán que estás trabajando en él y también te servirá como base para tu pull request posterior.

  * Cada ejercicio WIP ya tiene la descripción del problema en su comentario de clase. Ejecuta sus pruebas y desarrolla una solución con TDD (en el depurador si ejecutas la primera prueba por sí sola).

  * Es posible que tengas que __ajustar la prueba si no es Smalltalk idiomático__ (nuestro generador es bastante básico; dicho esto, algunas correcciones podrían ser apropiadas como PR hacia el texto original de [problem-specifications](https://github.com/exercism/problem-specifications)).

  * Actualiza los metadatos del ejercicio en el lado de clase del ejercicio sobrescribiendo el método #exercise y completando la dificultad, los temas, etc. También deberías completar el texto de pistas en la pestaña del comentario de prueba (en la parte inferior, reemplazando el texto TBD).

  * Actualiza el paquete del ejemplo elegido a `Exercise@<ExerciseName>` (es decir, sácalo del paquete WIP): paso 1b.
  * Crea una rama nueva en Iceberg con el nombre del ejercicio que elegiste (puedes usar la herramienta Iceberg para esto e ingresar el número del issue que creaste antes).
  * Antes de enviar tu pull request, ejecuta todas las pruebas de los ejercicios de Pharo y asegúrate de que __todas pasen__.

### Pruebas

En el nivel más básico, Exercism se trata de las pruebas y de probar con [conjuntos de pruebas](https://github.com/exercism/docs/blob/master/language-tracks/exercises/anatomy/test-suites.md).

Los ejercicios de Exercism de Pharo están organizados en subpaquetes, y cada uno contiene un TestCase que debe ser compatible con [SUunit](https://en.wikipedia.org/wiki/SUnit). Esta es la biblioteca xUnit original y no se necesitan frameworks adicionales de terceros para los ejercicios.

Para probar un ejercicio, ejecútalo desde el ejecutor de pruebas integrado haciendo clic en el orbe de pruebas. El orbe se pondrá verde si las pruebas pasan, o naranja o rojo si hay fallos o errores, respectivamente. Como alternativa, puedes ejecutar las pruebas manualmente en el Playground evaluando:

```smalltalk
<ExerciseName>Test suite run. "single exercise"

AllExercismTests suite run. "all exercises"
```
> __Nota:__ Si quieres definir tu propio caso de prueba (no generado), puedes ponerlo en el protocolo `extra` de la clase de prueba.
Por consistencia, usamos el orden de parámetros en las pruebas `self assert: actual equals: expected` en el método de prueba.

Para probar en una imagen que no sea de desarrollo, sigue los [pasos de instalación para usuarios](./docs/INSTALLATION.md). Si usas esa imagen para probar líneas base de desarrollo posteriores, es posible que tengas que eliminar los siguientes directorios de desarrollo para asegurarte de obtener el código más reciente:
`./pharo/pharo-local/iceberg, ./pharo/pharo-local/package-cache`

### __3. Publicar un ejercicio terminado__

Ahora que terminaste la solución y los commits en tu rama local, debes completar estos pasos:  
#### Generar el código fuente del ejercicio
Esto corresponde al paso 2a: __generar los archivos de código fuente__ de la solución y de la clase o clases de prueba.

__Generar los archivos de salida para todos los ejercicios__ 
- `ExercismGenerator generate` -> esto generará todos los archivos fuente de todos los ejercicios. Ejecutará el comando `generate` de configlet y también regenerará `config.json`, que lista todos los ejercicios válidos. (O, en el World menu, elige: «Exercism» -> «Regenerate meta data»)

#### Generar los archivos de salida para un ejercicio específico
- Para usar el directorio predeterminado (`repository-root/exercises/practice`)
```
ExercismGenerator new generateForExercise: 'slug-name'
```

Cuando necesites exportar a un directorio de ejercicios específico:
```
ExercismGenerator new 
	exercisesDirReference: 'path-to-exercises/practice' asFileReference;
	generateForExercise: 'slug-name'
```

> __Notas__: 
  - ExercismGenerator actualizará el config.json principal automáticamente (lo creará si no existe).
  - sincronizará todos los documentos, metadatos y rutas de archivo del o los ejercicios especificados usando el comando de configlet. Ver detalles: [Cómo usar sync al agregar un ejercicio nuevo](https://github.com/exercism/configlet#using-sync-when-adding-a-new-exercise-to-a-track)

#### Actualizar la línea base del proyecto Pharo-smalltalk
Paso 2b: actualiza la línea base del proyecto Pharo-smalltalk agregando el nombre del ejercicio a la lista del método `BaselineOfExercism>>exercisePackageNames`. Esto garantizará que tu ejercicio se cargue cuando el proyecto se cargue, incluido el ejercicio nuevo, mediante el comando de Metacello.
  
#### Enviar un pull request
Paso 3: antes de crear el PR, comprueba que los artefactos de Exercism sean correctos ejecutando el comando de CLI:
`bin/configlet lint` (de todos modos, la automatización de CI ejecutará el linting cuando se envíe el PR).  
Si todo está bien, puedes crear el PR:
- sube tu rama a tu fork y luego crea un pull request en `exercism/pharo-Smalltalk` 

> __Detalles finales__: 

- Es importante [habilitar las ediciones de los mantenedores](https://help.github.com/en/articles/allowing-changes-to-a-pull-request-branch-created-from-a-fork) para que podamos colaborar contigo en tu rama.
-  Los pull requests deben centrarse en un solo ejercicio, issue o cambio conceptualmente coherente. Consulta las [guías para pull requests](https://github.com/exercism/docs/tree/main/building/github#guides) de Exercism para más detalles.
- Sigue tu PR y responde cualquier pregunta que surja.
- Por último, envía los ajustes que hagan falta y un mantenedor integrará tu pull request para que tu solución final aparezca en el sitio.

## Información adicional para mantenedores

### Estilo de código

El código de este repositorio debe seguir las convenciones de [Pharo with style](https://github.com/SquareBracketAssociates/Booklet-PharoWithStyle) siempre que sea posible. También puedes consultar el más genérico [Smalltalk with style](http://sdmeta.gforge.inria.fr/FreeBooks/WithStyle/SmalltalkWithStyle.pdf).

También deberías usar el formateador de código integrado (meta-t FO en el editor) al crear ejercicios, así como las críticas de código.

### Cambios importantes

Si planeas hacer cambios importantes o que rompan la compatibilidad, abre un issue para que podamos comentarlo antes de integrarlo. Si el tema va más allá del track de Pharo, abre también un issue en [exercism/discussions](https://github.com/exercism/discussions/issues).
