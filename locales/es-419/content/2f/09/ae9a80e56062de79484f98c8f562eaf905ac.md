# Acerca de

El principal constructo orientado a objetos en C# es la _clase_, que es una combinación de datos ([_campos_][fields]) y comportamiento ([_métodos_][methods]). Los campos y los métodos de una clase se conocen como sus _miembros_.

El acceso a los miembros se puede restringir mediante modificadores de acceso, de los cuales los dos más comunes son:

- [`public`][public]: cualquier código puede acceder al miembro (sin restricciones).
- [`private`][private]: solo el código de la misma clase puede acceder al miembro.

Es costumbre especificar un modificador de acceso para todos los miembros. Si no se especifica ningún modificador de acceso, se usará `private` de forma predeterminada.

Esta agrupación de datos y comportamiento relacionados, junto con la restricción del acceso a los miembros, se conoce como [encapsulación][encapsulation], que es uno de los conceptos fundamentales de la orientación a objetos.

La combinación de los valores de los campos de un objeto en un momento dado se conoce como el [estado][object-state] del objeto.

Puedes pensar en una clase como una plantilla para crear instancias de esa clase. Para [crear una instancia de una clase][creating-objects] (también conocida como _objeto_), se usa la [palabra clave `new`][new]:

```csharp
class Car
{
}

// Create two car instances
var myCar = new Car();
var yourCar = new Car();
```

Los [campos][fields] tienen un tipo y se pueden definir en cualquier parte de una clase.
Los campos públicos se definen en [PascalCase][pascal-case] y los campos privados se definen en [camelCase][camel-case] y llevan el prefijo de un guion bajo `_`:

```csharp
class Car
{
    // Accessible by anyone
    public int Weight;

    // Only accessible by code in this class
    private string _color;
}
```

De manera opcional, se puede asignar un valor inicial a un campo. Si un campo _no_ especifica un valor inicial, se le asignará el [valor predeterminado][default-values] de su tipo. Los valores de los campos de una instancia se pueden consultar y actualizar usando la notación de punto.

```csharp
class Car
{
    // Will be set to specified value
    public int Weight = 2500;

    // Will be set to default value (0)
    public int Year;
}

var newCar = new Car();
newCar.Weight; // => 2500
newCar.Year;   // => 0

// Update value of the field
newCar.Year = 2018;
```

Por lo general, los campos privados se actualizan como efecto secundario de llamar a un método. Esos métodos suelen no devolver ningún valor, en cuyo caso el tipo de retorno debe ser [`void`][void]:

```csharp
class CarImporter
{
    private int _carsImported;

    public void ImportCars(int numberOfCars)
    {
        // Update private field
        _carsImported = _carsImported + numberOfCars;
    }
}
```

Ten en cuenta que no es costumbre usar campos públicos en las clases de C#. O bien se usan campos privados, o bien otros tipos de miembros que se tratarán en ejercicios posteriores.

Dentro de una clase, la [palabra clave `this`][this] hará referencia a la clase actual. Esto es especialmente útil si un parámetro tiene el mismo nombre que un campo:

```csharp
class CarImporter
{
    private int carsImported;

    public void SetImportedCars(int carsImported)
    {
        // Update private field from public method
        this.carsImported = carsImported;
    }
}
```

La estructura de clases y métodos ofrece una manera natural de limitar la visibilidad de elementos del programa, como los campos y los métodos, y de evitar el conocido [problema del estado global][so-global-state-problem]. Para que el código externo a la clase pueda verlos, los campos, métodos y otros miembros públicos se deben calificar con el nombre del objeto, `object.field` o `object.method()` (o el nombre de la clase en el caso de los estáticos). Las variables y los parámetros declarados dentro de un método solo son visibles dentro de ese método.

Algo de lo que debes tener cuidado con este enfoque es que, si el nombre de un campo y el nombre de una variable o parámetro dentro de un método son iguales, el código dentro del método ignorará el nombre del campo, lo cual quizá no sea lo que quieres. En general, conviene evitar esto siempre que sea posible, aunque es un patrón común en los constructores. Si es apropiado que el nombre del campo y el de la variable sean iguales, califica el nombre del campo con la palabra clave `this` dentro del método.

Estos [modificadores de acceso][access-modifiers] se pueden usar para limitar aún más la visibilidad.
