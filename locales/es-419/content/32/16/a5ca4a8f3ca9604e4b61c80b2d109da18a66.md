# Pistas

## General

- Un contrato va después del tipo de retorno y antes del `is`:

  ```sather
     spare_capacity(load : INT) : INT
        pre load >= 0
     is
        ...
     end;
  ```

- Dentro de un contrato puedes usar los argumentos y los atributos del objeto,
  así que `limit` está disponible.
- Las pruebas se construyen sin `-chk`, así que un contrato equivocado no las
  hará fallar. Escríbelos pensando en quien los lee.

## 1. Arma un arnés

- `pre kg > 0`, en `create`.
- El cuerpo es el `new` de siempre: asigna el atributo y devuélvelo.

## 2. ¿Cuánto sobra?

- Dos condiciones unidas con `and`: `pre load >= 0 and load <= limit`.
- `post result >= 0`. Eso se deduce del `pre`, y por eso vale la pena decirlo:
  deja registrado por qué se puede confiar en la respuesta.

## 3. ¿Qué tan lleno está?

- `pre load >= 0` y `post result >= 0`.
- `load * 100 / limit`, en ese orden. Dividir primero lo echaría todo a perder,
  como pasaría en `tuning-the-strings`.

## 4. ¿Es seguro?

- Ningún `pre`: la idea es precisamente que se puede preguntar por cualquier
  carga.
- El `post` reformula la pregunta: `post result = (load <= limit)`.
  Con paréntesis, porque `=` se usa dos veces para cosas distintas.
