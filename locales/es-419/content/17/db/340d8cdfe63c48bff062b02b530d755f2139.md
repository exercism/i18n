# Acerca de

Common Lisp le ofrece al programador varios condicionales diferentes que se pueden clasificar según el número de «ramas» que admiten.

Además, a diferencia de muchos otros lenguajes de programación, todos los condicionales de Common Lisp son _expresiones_, no sentencias.
Esto significa que todos los condicionales de Lisp se evalúan a algún valor y pueden usarse en lugar de parámetros concretos.

Por ejemplo:

```lisp
;; Doubles x when it's even
(* x (if (evenp x) 2 1))
```

## Condicionales de una sola rama

Los condicionales `when` y `unless` evalúan cierto código solo cuando la prueba proporcionada es verdadera o falsa, respectivamente, y en caso contrario se evalúan a `nil`.

La sección que va después de la expresión de prueba puede contener más de una expresión.

```lisp
(when (= 2 2) "All is well")      ; => "All is well"
(unless (= 2 2) "Time to panic!") ; => NIL
```

## El condicional de dos ramas

El condicional `if` evalúa la primera expresión del cuerpo cuando la prueba es verdadera y la segunda en caso contrario.

```lisp
(if (= 2 2) 'how-honest 'you-liar) ; => HOW-HONEST
```

Ten en cuenta que tanto la cláusula *then* como la cláusula *else* solo pueden ser una única expresión.

## Condicionales de múltiples ramas

El «supercondicional» de Lisp es `cond`, que puede tener un número infinito de ramas.
Cada rama tiene una condición de prueba y una expresión de cuerpo que van encerradas entre un par adicional de paréntesis.
Si todas las pruebas se evalúan como falsas, se devuelve `nil`.

```lisp
(cond ((= 0 2) 'nope)
      ((= 1 2) 'try-again)
      ((= 2 2) 'quite-true)
      ((= 3 2) 'too-far)
      (t 'something-else))
; => QUITE-TRUE
```

Ten en cuenta que no hay límite para el número de expresiones que van después de la expresión de prueba. 


Si solo quieres probar un valor contra varias ramas, puedes usar la expresión `case`, que es más limpia.
Si no coincide ninguno de los casos, se devuelve `nil`.
Tanto `t` como `otherwise` se pueden usar como casos generales:

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark")
  (otherwise "???"))
; => "???"
```

Ten en cuenta que, al igual que con `cond`, no hay límite para el número de expresiones que van después de la expresión de prueba.

## Los condicionales sigilosos

Las operaciones booleanas `and` y `or` de Common Lisp son macros de cortocircuito que se pueden usar para reducir la duplicación de ciertas expresiones condicionales.

La macro `and` devuelve `nil` de inmediato si encuentra un solo valor falso, pero en caso contrario devuelve el último valor verdadero del `and`:

```lisp
(and 42 "Magic" :cool) ; => :COOL
(and () "Magic" :cool) ; => NIL
```

La macro `or` devuelve el primer valor verdadero que encuentra, o `nil` si no hubo ningún valor verdadero:

```lisp
(or () 42 nil)  ; => 42
(or () NIL nil) ; => NIL
```

## Estoy exhausto...

Como se mencionó antes, cuando no coincide ninguna de las ramas de una sentencia `case` y no hay una cláusula `otherwise`, se devuelve `nil`.
Sin embargo, en ocasiones, que no coincida ninguna rama debería tratarse como un error, y aquí es donde entra `ecase` (para la coincidencia **exhaustiva**).

Se usa exactamente igual que `case`, pero señala un error en lugar de devolver `nil` cuando no hay coincidencia.

```lisp
(case 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => NIL

(ecase 'elder-beast
  (cat "Meow")
  (bird "Chirp")
  (dog "Bark"))
; => ERROR: ELDER-BEAST fell through ECASE expression. Wanted one of (CAT BIRD DOG).
```
