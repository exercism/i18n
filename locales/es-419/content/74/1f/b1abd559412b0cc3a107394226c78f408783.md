# Acerca de

El análisis es el proceso de transformar texto en datos significativos. Las funciones del paquete `String` son limitadas en ese sentido y las expresiones regulares son difíciles de usar, así que la forma idiomática de analizar en Elm es con el paquete `elm/parser`.

Veamos un ejemplo de cómo escribir un analizador para (un subconjunto de) el lenguaje de programación [LOLCODE][lolcode]. Considera el siguiente programa comentado:

```
HAI 1                 # program version 1
CAN HAS STDIO?        # import stdio
VISIBLE "HAI WORLD!"  # print "HAI WORLD!"
KTHXBYE               # end of program
```

Primero, escribamos un tipo de Elm para representar los posibles comandos:

```elm
type Command
    = Version Int
    | Import String
    | Print String
```

Nuestro programa de LOLCODE se puede modelar entonces como una `List Command`. Empecemos con un analizador para la línea `HAI 1`:

```elm
versionP : Parser Command
versionP =
    Parser.succeed Version
        |. Parser.keyword "HAI"
        |. Parser.spaces
        |= Parser.int
```

`versionP` se construye usando una _secuencia de analizadores_. El operador `(|.)` significa «analizar el string pero descartar el resultado» y `(|=)` significa «analizar el string y conservar el resultado». En este ejemplo, `Parser.keyword "HAI"` consumirá un «HAI», pero ese resultado se ignora. `Parser.spaces` consumirá cualquier cantidad de caracteres ' ', '\n' y '\r', pero eso también se ignorará. `Parser.int` analizará un número entero, y el valor de ese entero (digamos 1) se pasará al `Parser.succeed Version` que está más arriba y el analizador logrará devolver el valor `Version 1`.

Si uno cualquiera de los analizadores de la secuencia falla, devolverá un `Parser.DeadEnd` y todo el analizador fallará. Un analizador se puede ejecutar con `Parser.run`:

```elm
Parser.run versionP "HAI 1"
    --> Ok (Version 1)
Parser.run versionP "HAI 2"
    --> Ok (Version 2)
Parser.run versionP "BYE 2"
    --> Err [{ problem = ExpectingKeyword "HAI", col = 1, row = 1 }]
Parser.run versionP "HAI MOM"
    --> Err [{ problem = ExpectingInt, col = 5, row = 1 }]
```

Ataquemos la línea «CAN HAS STDIO?» con

```elm
importP : Parser Command
importP =
    Parser.succeed Import
        |. Parser.keyword "CAN HAS"
        |. Parser.spaces
        |= packageP
        |. Parser.symbol "?"
```

`importP` también es una secuencia de analizadores, pero esta vez termina con `Parser.symbol`, que sirve para analizar símbolos como «?». El valor que queremos conservar (el nombre del paquete que se va a importar) lo analiza

```elm
packageP : Parser String
packageP =
    Parser.chompWhile Char.isAlphaNum
        |> Parser.getChompedString
        |> Parser.map String.toLower
```

Como no sabemos cuál será el nombre del paquete, no podemos usar `Parser.keyword`, así que en su lugar usamos `Parser.chompWhile`, que consumirá caracteres uno por uno siempre que cumplan una condición (aquí, ser un carácter alfanumérico). Luego, `Parser.getChompedString` recoge esos caracteres consumidos y devuelve un `Parser String`. En este caso, queremos normalizar los nombres de los paquetes, así que usamos `Parser.map` para modificar el string que contiene el analizador y convertirlo a minúsculas.

```elm
Parser.run importP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS StDiO?"
    --> Ok (Import "stdio")
Parser.run importP "CAN HAS STDIO"
    -->  Err [{ problem = ExpectingSymbol "?", col = 14, row = 1 }]
```

A continuación, `VISIBLE "HAI WORLD!"` lo analiza

```elm
printP : Parser Command
printP =
    Parser.succeed Print
        |. Parser.keyword "VISIBLE"
        |. Parser.spaces
        |. Parser.symbol "\""
        |= stringP
        |. Parser.symbol "\""

stringP : Parser String
stringP =
    Parser.chompWhile (\c -> c /= '"')
        |> Parser.getChompedString

Parser.run printP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
```

Ya tenemos un analizador para cada comando. Claro que, en un programa general, no se puede predecir el orden de estos comandos, así que construimos un analizador de comandos genérico

```elm
commandP : Parser Command
commandP =
    Parser.oneOf
        [ versionP
        , importP
        , printP
        ]
```

`Parser.oneOf` probará un analizador, en el orden dado. Si un analizador falla, se prueba el siguiente, pero si tiene éxito, se devuelve su resultado sin probar los analizadores restantes. Si todos los analizadores fallan, `Parser.oneOf` falla.

```elm
Parser.run commandP "HAI 2"
    --> Ok (Version 2)
Parser.run commandP "CAN HAS STDIO?"
    --> Ok (Import "stdio")
Parser.run commandP "VISIBLE \"HAI WORLD!\""
    --> Ok (Print "HAI WORLD!")
Parser.run commandP "O NOES"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 1 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 1 }
    --      ]
```

Fíjate que cada intento fallido produce un `Parser.DeadEnd` que `Parser.oneOf` recoge.

Para analizar un programa completo, necesitamos analizar varios comandos de forma secuencial con

```elm
programP : Parser (List Command)
programP =
    Parser.sequence
        { start = ""
        , separator = "\n"
        , end = "KTHXBYE"
        , spaces = Parser.succeed ()
        , item = commandP
        , trailing = Parser.Optional
        }
```

`Parser.sequence` es un analizador muy personalizable con varias opciones. `start`, `separator` y `end` toman strings que separan los elementos de la secuencia; para analizar una lista de Elm usaríamos "[", "," y "]". `spaces` aporta flexibilidad porque toma un analizador que se encargará de los posibles espacios entre los elementos y los separadores; para analizar una lista de Elm usaríamos `Parser.spaces`, pero en este caso no aceptamos ningún espacio, así que usamos `Parser.succeed ()`, que tiene éxito de inmediato sin consumir nada en realidad. `item` toma el analizador de elementos y, por último, `trailing` nos deja decidir si los separadores finales son `Parser.Forbidden`, `Parser.Mandatory` o `Parser.Optional`.

```elm
Parser.run programP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run programP "KTHXBYE"
    --> Ok []
Parser.run programP "HAI 2\nCAN HAS STDIO?\n"
    --> Err [ { problem = ExpectingKeyword "HAI", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "CAN HAS", col = 1, row = 3 }
    --      , { problem = ExpectingKeyword "VISIBLE", col = 1, row = 3 }
    --      , { problem = Expecting "KTHXBYE", col = 1, row = 3 }
    --      ]
```

Cuando los analizadores tienen éxito, dejan de consumir el string

```elm
Parser.run Parser.int "1"
    --> Ok 1
Parser.run Parser.int "1 BTW VISIBLE \"U SEE NOTHING\""
    --> Ok 1
```

Así que si necesitamos asegurarnos de que analizamos todo el string, podemos usar `Parser.end`

```elm
fullProgramP : Parser (List Command)
fullProgramP =
    programP
        |. Parser.spaces
        |. Parser.end

Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run fullProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE\nBTW VISIBLE \"U SEE NOTHING\""
    --> Err [{ problem = ExpectingEnd, col = 1, row = 4 }]
```

Por último, a veces necesitamos decidir que un analizador falle según su contenido analizado. Por ejemplo, si necesitáramos un analizador que fallara con los programas que empiezan con dos comandos «HAI» seguidos, podríamos usar

```elm
singleVersionProgramP : Parser (List Command)
singleVersionProgramP =
    fullProgramP
        |> Parser.andThen
            (\commands ->
                case commands of
                    (Version _) :: (Version _) :: _ ->
                        Parser.problem "Multiple versions defined"

                    _ ->
                        Parser.succeed commands
            )
```

`Parser.andThen` puede inspeccionar el contenido de un analizador y devuelve un analizador nuevo según su valor. Aquí, hicimos fallar el analizador con un mensaje personalizado usando `Parser.problem` en un caso, y devolvimos el valor original en el otro.

```elm
Parser.run singleVersionProgramP "HAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Ok [Version 2, Import "stdio"]
Parser.run singleVersionProgramP "HAI 1\nHAI 2\nCAN HAS STDIO?\nKTHXBYE"
    --> Err [{ problem = Problem "Multiple versions defined", col = 8, row = 4 }]
```
