# Introducción

## Registros

Los [registros][records] son estructuras de datos que agrupan información relacionada con etiquetas.
Son similares a los objetos de JavaScript o Java, o a las structs de C o Rust, pero con algunas diferencias clave.

### Crear registros

Los registros se [crean][create] con llaves y sus elementos se separan con comas.

```elm
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

El tipo de un registro también se define con una sintaxis similar, excepto que los signos de igual `=` se reemplazan por dos puntos `:`.

```elm
firefly : { name : String, creator : String, episodes : Int }
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

Repetir estas definiciones de tipo es engorroso, así que usar un [type alias][record-types] para compartir la definición es algo habitual.

```elm
type alias TvSeries =
    { name : String
    , creator : String
    , episodes : Int
    }

firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }
```

El type alias también proporciona automáticamente una función constructora para el registro.
Esto a veces sorprende, ya que las funciones en Elm deben empezar con un carácter minúsculo, pero los constructores de tipo son una excepción.

```elm
firefly : TvSeries
firefly = TvSeries "Firefly" "Joss Whedon" 14
```

### Acceder a los campos de un registro

La forma principal de [acceder al valor de un campo de una instancia de registro][access] es usar la notación de punto, como `firefly.creator`.
El compilador de Elm también admite funciones de acceso especiales que empiezan con un punto `.`, como `.creator`, que funcionan en cualquier registro que tenga un campo con ese nombre.
Esa es la segunda excepción a la regla de que las funciones deben empezar con un carácter minúsculo.
De hecho, las funciones definidas por el usuario deben empezar con un carácter minúsculo, pero los dos ejemplos que acabamos de ver los genera el compilador, no quien programa.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

firefly.name
    --> "Firefly"

.creator firefly
    --> "Joss Whedon"
```

Los registros también se pueden _desestructurar_ al vincular valores usando la [coincidencia de patrones de registros][pattern-matching].
La desestructuración funciona con cualquier registro que tenga campos con los nombres relevantes.

```elm
episodesCount : TvSeries -> Int
episodesCount { episodes } =
    episodes

complicatedCopy : TvSeries -> TvSeries
complicatedCopy show =
    let
        { name, creator } = show
    in
    { name = name
    , creator = creator
    , episodes = episodesCount show
    }
```

### Actualizar registros

Los registros son inmutables, como todo en Elm, así que una vez que se define un registro, los valores de sus campos nunca pueden cambiar.
Existe una [sintaxis especial para crear una copia de un registro existente, pero cambiando uno o más campos][update].
Esta sintaxis usa el símbolo de barra vertical `|` para distinguir el registro original y los campos que cambiarán, como `{ oldRecord | field1 = newValue }`.

```elm
firefly : TvSeries
firefly =
    { name = "Firefly"
    , creator = "Joss Whedon"
    , episodes = 14
    }

updatedFirefly : TvSeries
updatedFirefly =
    { firefly | creator = "J Whedon", episodes = 15 }
```

### Comparar registros

Elm usa la [igualdad estructural][equality], lo que significa que dos instancias del mismo registro con valores idénticos son iguales.

```elm
firefly1 = TvSeries "Firefly" "Joss Whedon" 14
firefly2 = TvSeries "Firefly" "Joss Whedon" 14

firefly1 == firefly2
    --> True
```

### Registros extensibles

Elm también admite el [tipado estructural][structural-typing], lo que significa que si una función requiere un registro con un campo x y un campo y, funcionará con cualquier registro que tenga esos campos, como puntos en 2D, puntos en 3D, naves espaciales, etc.
Esos tipos de registro tienen una barra vertical `|` en su definición, como `{ a | x : Float, y : Float }`, y se llaman «registros extensibles» en la terminología de Elm.
Ten cuidado con la diferencia entre una barra vertical `|` en una definición de tipo, que es una definición de registro extensible (`{ a | x : Int }`), y una barra vertical `|` en una instancia de registro real, que significa que estamos actualizando algunos campos de ese registro.

```elm
point2d = { x = 1, y = 2 }
point3d = { x = 3, y = 4, z = 7 }

.x point2d --> 1
.x point3d --> 3

length : { a | x : Float, y : Float } -> Float
length vector =
    sqrt (vector.x * vector.x + vector.y * vector.y)

length point2d --> 2.236068
length point3d --> 5

translateX : { a | x : Float } -> { a | x : Float }
translateX vector =
    { vector | x = vector.x + 1 }

translateX point2d --> { x = 2, y = 2 }
translateX point3d --> { x = 4, y = 4, z = 7 }
```
