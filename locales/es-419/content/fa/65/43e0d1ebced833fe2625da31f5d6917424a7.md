# Para quienes mantienen

## Script auxiliar para crear pruebas de Fortran: create_fortran_test.py

Una forma sencilla de crear la prueba de un ejercicio es usar el script
`bin/create\_fortran\_test.py`

Usa este script para crear un archivo inicial <exercise>\_test.f90 que puedes usar como plantilla para tu prueba.
Por lo general, tendrás que reemplazar la función «response» del archivo generado por la llamada correcta a la función.

Ten en cuenta también que Fortran tiene problemas con caracteres especiales como `\n` y `\t`, así que presta especial atención al manejarlos.

### Requisitos previos

- CMake y un compilador de Fortran que funcionen
- Python3.x (puede que funcione con Python2, pero no me tomé el trabajo de hacerlo compatible con versiones anteriores)
- la última versión de https://github.com/exercism/problem-specifications.git
- git

### Flujo de trabajo para crear una nueva prueba

- trae los últimos cambios de `exercism/problem-specifications`, por ejemplo git clone git@github.com:exercism/problem-specifications.git
- Crea una rama nueva para crear un ejercicio nuevo, por ejemplo git checkout -b exercise-bob
- ejecuta este script para el ejemplo que quieras crear
- copia `config/CMakeLists.txt` al directorio del ejercicio (puedes usar `bin/update-cmake-files` para esto)
- implementa el ejercicio de forma que funcione
- corrige las pruebas problemáticas que encuentres (ver, por ejemplo, exercise/bob «Test 20» y «Test 24»)
- asegúrate de que el comando `ctest` valide sin errores
- copia tu solución a .meta/example.f90 y quita la implementación real del archivo del ejercicio, por ejemplo, bob.f90
- actualiza los directorios .docs y .meta
  - cp ../problem-specifications/exercises/bob/description.md exercises/practice/bob/.docs/instructions.md
    - reemplaza «# Description» por «# Instructions»
  - llena .meta/tests.toml manualmente (hasta que exista una forma automatizada)
  - llena .meta/config.json manualmente (hasta que exista una forma automatizada)
    - Usa ../problem-specifications/exercises/bob/metadata.yml
- abre un pull request con tus cambios

Para el ejemplo de bob:

```bash
$ python bin/create_fortran_test.py -j ../problem-specifications/main/exercises/bob/canonical-data.json -t exercises/practice/bob/bob_test.f90
Namespace(json='../problem-specifications/main/exercises/bob/canonical-data.json', target='exercises/practice/bob/bob_test.f90')
Wrote : exercises/practice/bob/bob_test.f90
$ cp config/CMakeLists.txt exercises/practice/bob/.
$ cd exercises/practice/bob
$ touch bob.f90
$ mkdir build
$ cd build
$ cmake ..
$ make
$ ctest -V
```

### Cómo cambiar `CMakeLists.txt`

Cuando cambies el archivo de cmake, actualiza la copia maestra en `config/` y usa `bin/update-cmake-files` para copiarla a todos los directorios de ejercicios.

## Solución

Cuando tengas una solución, copia esa solución al directorio «.meta» como «example.f90».

Quizá quieras dejar una implementación esqueleto de la función o la subrutina que ayude al estudiante, y dejar en el directorio del ejercicio el archivo con el nombre del ejercicio.
