# Pistas

## General

El lenguaje SGF tiene una definición recursiva:

```none
GameTree = "(" Sequence { GameTree } ")"
```

Es decir, un GameTree es un fragmento de texto que empieza con un `(`, seguido de un texto llamado «Sequence» (una lista de nodos de juego), _seguido de **cero o más** GameTree hijos_, y termina con un `)`.

Quizá quieras usar expresiones regulares para analizar un texto SGF.
Sin embargo, como los árboles de juego pueden anidarse dentro de otros árboles de juego a cualquier profundidad, las expresiones regulares estándar no son lo bastante potentes para llevar la cuenta de los niveles de anidamiento.

Hay un par de enfoques para resolver este ejercicio:

### Máquina de estados

Podrías recorrer la cadena que vas a analizar carácter por carácter, manteniendo una variable con tu posición actual.
Puedes llevar la cuenta del estado actual del texto analizado a partir del carácter que esté en la posición actual.
El «estado actual» podría ser algo como «leyendo el nombre de una propiedad» o «dentro del valor de una propiedad».
Con este enfoque hay muchos valores de los que tienes que llevar la cuenta.

### Analizador

Un [analizador basado en PEG][PEG-parser] es una muy buena manera de analizar un lenguaje que tiene una gramática definida.
[LPeg][LPeg] es un analizador PEG y es una de las dependencias requeridas de MoonScript, así que ya tienes acceso a él.
Un analizador te permite escribir reglas sobre cómo debe verse el texto.
Por ejemplo, «el nombre de una propiedad son todo letras mayúsculas» o «el valor de una propiedad va encerrado entre corchetes».
Después, el analizador hace el trabajo pesado de hacer coincidir el texto que analizas con tus reglas.
