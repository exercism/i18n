# Acerca de

Para entender [`Box`][box], es útil entender qué son la [pila y el montón][stack and heap].

La pila es un área de memoria que funciona como un búfer en el que el último en entrar es el primero en salir (LIFO). Es muy rápido apilar datos en la pila y también es rápido sacarlos.
Los datos pueden incluir variables o direcciones de funciones, pero deben tener un tamaño fijo conocido en tiempo de compilación.

Si los datos tienen un tamaño desconocido en tiempo de compilación o un tamaño que puede cambiar, entonces hay que asignarlos en el montón. El proceso de asignación debe encontrar
espacio en el montón lo bastante grande para almacenar los datos, escribir los datos en el montón y apilar la dirección de memoria de esos datos en la pila, todo lo cual lleva
bastante más tiempo que simplemente poner los datos en la pila. Recuperar datos del montón es un poco más lento porque hay que pasar por la dirección que está en la
pila y seguirla hasta la ubicación de los datos en el montón.

`Box` es un puntero inteligente que asigna datos en el montón. La dirección está en la pila y apunta a los datos en el montón. Una [razón][reasons] para usar `Box`
es poner datos en el montón cuando tienes un tipo cuyo tamaño no se puede conocer en tiempo de compilación y quieres usar un valor de ese tipo en un contexto que requiere
un tamaño exacto. Un uso práctico de eso es cuando tienes varias structs que quieres manejar de la misma manera mediante un trait que todas implementan, como
en el ejemplo de abajo.

Supongamos que tenemos dos structs. Cada struct es de algo que puede ser molesto. Podemos hacer que cada struct implemente un trait Annoyance así:

```rust
struct WerewolfOfLondon;
struct Rooster;

trait Annoyance {
    fn annoy(&self) -> &'static str;
}

impl Annoyance for WerewolfOfLondon {
    fn annoy(&self) -> &'static str {
        "ahhh-OOOOOOO!"
    }
}

impl Annoyance for Rooster {
    fn annoy(&self) -> &'static str {
        "errr-errr-errr-errr-ERRRRRRRRR!"
    }
}
```

Ahora supongamos que queremos una función que nos dé un Annoyance según la hora del día que se le pase. Primero podemos intentar esto, y descubrimos que no compila:

```rust
enum TimeOfDay {
    Midnight,
    Morning,
}

//return something that implements Annoyance
fn annoy_me(time_of_day: TimeOfDay) -> impl Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// `match` arms have incompatible types
// expected struct `WerewolfOfLondon`, found struct `Rooster`
// this is found to be of type `WerewolfOfLondon`
// `match` arms have incompatible types
// you could change the return type to be a boxed trait object
// if you change the return type to expect trait objects, box the returned expressions

```

El compilador, en toda su amabilidad, nos dice exactamente qué hacer: devolver un objeto trait dentro de un `Box`. Si no sabes qué es un objeto trait,
una forma sencilla de describirlo es como una manera de devolver un objeto específico mediante [despacho dinámico][dynamic dispatch] desde una función que podría devolver cualquier objeto
que implemente un trait determinado. Como necesitamos despacho dinámico, podemos intentar simplemente poner un `dyn` delante del nombre del trait y ver si nos funciona.

```rust
fn annoy_me(time_of_day: TimeOfDay) -> dyn Annoyance {
    match time_of_day {
        TimeOfDay::Midnight => WerewolfOfLondon,
        TimeOfDay::Morning => Rooster,
    }
}

// the size for values of type `dyn Annoyance` cannot be known at compilation time
// the trait `Sized` is not implemented for `dyn Annoyance`
// all local variables must have a statically known size
// unsized locals are gated as an unstable feature
```

Uno de los errores es que el tamaño de `dyn Annoyance` no se puede conocer en tiempo de compilación. Esto se debe a que `annoy_me` no sabe qué objeto trait específico
va a devolver antes de que se la llame. Las structs que implementan Annoyance podrían tener campos distintos y ser de tamaños distintos. Y nos recuerdan que
uno de los usos de `Box` es para un tipo cuyo tamaño no se puede conocer en tiempo de compilación. Así que ahora probamos con un valor de retorno envuelto en un `Box`, y ponemos en un `Box` los valores devueltos
por la expresión `match`, así:

```rust
fn annoy_me(time_of_day: TimeOfDay) -> Box<dyn Annoyance> {
    match time_of_day {
        TimeOfDay::Midnight => Box::new(WerewolfOfLondon),
        TimeOfDay::Morning => Box::new(Rooster),
    }
}
```

La signatura de `Box` es `Box<T>`, donde `T` representa el tipo específico que se va a poner en el `Box`, el cual se coloca entre los paréntesis angulares, como en `Box<dyn Annoyance>` de arriba.

Podemos consumir el objeto trait dentro del `Box` así:

```rust
fn be_annoying(annoying_one: &dyn Annoyance) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(&*my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(&*my_annoyance);
}
```

lo cual imprime

```rust
"ahhh-OOOOOOO!"
"errr-errr-errr-errr-ERRRRRRRRR!"
```

Como `my_annoyance` es de tipo `Box<dyn Annoyance>`, hay que desreferenciarlo desde el `Box` usando el operador de desreferencia `*`. Luego se referencia como un
`dyn Annoyance` para que la función `be_annoying` lo tome prestado.

Otra forma de implementarlo sería quitar el requisito de que el parámetro tenga un tamaño definido. En ese caso, la compilación crearía una función distinta
para cada variante de Annoyance, para poder despacharla de forma estática (un proceso llamado [monomorfización][monomorphization]), así:

```rust
fn be_annoying<A: Annoyance + ?Sized>(annoying_one: &A) {
    println!("{:?}", annoying_one.annoy());
}
```

Aún otra forma de implementarlo sería que la función `be_annoying` aceptara un `Box<dyn Annoyance>` y usara la [coerción de deref][deref coercion] para no tener que
desreferenciar el `Box` manualmente. Esto transferiría la propiedad del objeto trait Annoyance a la función `be_annoying`. Quedaría fuera de
ámbito al final de la función y ya no estaría disponible.

```rust
fn be_annoying(annoying_one: Box<dyn Annoyance>) {
    println!("{:?}", annoying_one.annoy());
}

pub fn main() {
    let my_annoyance = annoy_me(TimeOfDay::Midnight);
    be_annoying(my_annoyance);
    let my_annoyance = annoy_me(TimeOfDay::Morning);
    be_annoying(my_annoyance);
}
```
