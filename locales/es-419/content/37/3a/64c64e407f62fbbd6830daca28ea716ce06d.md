## Closures finales

Swift ofrece una variación adicional de su sintaxis cuando se trabaja con closures, conocida como [closures finales][trailing-closures]. Los closures finales surgen cuando el último parámetro en la lista de parámetros de una función tiene tipo función. En ese caso, si se pasa un closure, el closure se puede escribir _después_ del paréntesis de cierre y se omite la etiqueta del argumento. Fíjate que si la función tiene un solo parámetro, los paréntesis se pueden omitir por completo.

```swift
func fetchURL(_ urlString: String,
              uponReceipt handleResult: (String) -> ()
             )  -> () {
  if let url = URL(string: urlString), let htmlString = fetch(url) {
    handleResult(htmlString)
  }
}

fetchURL("https://www.swift.org") { print($0) }
// prints the fetched html string

["apple", "ball", "carrot"].sorted { $0.count < $1.count }
```

## Varios closures finales

Aunque las versiones anteriores de Swift solo admitían el uso de un único closure final, a partir de la versión 5.2.4 Swift admite varios closures finales.

Si una función tiene más de un closure al final de su lista de parámetros, la sintaxis de closures finales se puede usar para sacarlos a todos fuera de los paréntesis. Sin embargo, solo se omite la etiqueta del primer argumento; las demás deben llevar etiqueta:

```swift
func fetchURL(_ urlString: String,
              uponReceipt handleResult: (String) -> (),
              onFailure handleFailure: () -> ()
             )  -> () {
  if let url = URL(string: urlString), let htmlString = fetch(url) {
    handleResult(htmlString)
  } else {
    handleFailure()
  }
}

fetchURL("https://www.swift.org") {
  print($0)
} onFailure: {
  print("Error: https://www.swift.org could not be fetched")
}
// prints the fetched html string on successful fetch or prints error message on failure
```
