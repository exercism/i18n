# Introducción

## Recursión de cola

Cuando [se recursa][exercism-recursion] a través de enumerables (arrays, bitstrings, strings), a menudo surgen dos preocupaciones:

- cuánta memoria se requiere para almacenar la secuencia de llamadas recursivas a funciones
- cómo construir la solución de manera eficiente

Para abordar estas preocupaciones se puede usar un _acumulador_.

Un acumulador es una variable que se pasa junto con los datos. Se usa para pasar el estado actual de la ejecución de la función, de llamada en llamada, hasta llegar al _caso base_. En el caso base, el acumulador se usa para devolver el valor final de la llamada recursiva a la función.

Quien escribe la función debe inicializar los acumuladores, no quien la usa. Para lograr esto, declara dos funciones: una función pública que recibe solo los datos necesarios como argumentos y que inicializa el acumulador, y una función privada que también recibe un acumulador. En Elixir, es un patrón común anteponer `do_` al nombre de la función privada.

```elixir
# Count the length of a list without an accumulator
def count([]), do: 0
def count([_head | tail]), do: 1 + count(tail)

# Count the length of a list with an accumulator
def count(list), do: do_count(list, 0)

defp do_count([], count), do: count
defp do_count([_head | tail], count), do: do_count(tail, count + 1)
```

El uso de un acumulador nos permite convertir funciones recursivas en funciones _recursivas de cola_. Una función es recursiva de cola si lo _último_ que se ejecuta en ella es una llamada a sí misma.
