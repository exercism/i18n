# Nil

Crystal tiene un tipo llamado [`Nil`][nil], que solo puede tener un valor: `nil`.
Se usa para representar la ausencia de un valor y es similar a `null` o `None` en otros lenguajes.

Los valores nil pueden ser devueltos por varios métodos, por ejemplo [`String#[]?`][string-index], que devuelve `nil` si el índice está fuera de los límites.

```crystal
"foo"[10]? # => nil
```

Crystal tiene lo que se conoce como **COMPROBACIONES DE REFERENCIAS NULAS**, lo que significa que todos los tipos son no nulables por defecto.
Esto significa que no puedes asignar `nil` a una variable a menos que la declares explícitamente como un tipo `Nil`.
A su vez, esto significa que el compilador verificará automáticamente las referencias nulas.

## Valor falsey

Existen ciertos enfoques para manejar los valores `nil`.
`nil` es un valor [falsey][truthy-falsey], al igual que `false`.
Esto significa que en las sentencias y en otros lugares donde se espera un valor falsey o truthy, se tratará igual que `false`.

```crystal
if nil
  puts "nil is truthy"
else
  puts "nil is falsey"
end

# => nil is falsey
```

Esto significa que no se tomará la rama truthy si una variable nulable tiene un valor `nil`.

```crystal
foo = "boo"[2]? # It is possible that foo is nil
if foo
  p foo.class # => Char
end
```

## Comprobar si es nil

Crystal tiene un método que se puede usar para comprobar si un valor es `nil`.
Se llama [`nil?`][nil?] y está disponible en todos los objetos.

```crystal
foo = "boo"[2]?
if foo.nil?
  puts "foo is nil"
else
  puts "foo is not nil"
end
```

Esto es un poco diferente cuando solo usas el valor en un condicional, ya que en los ejemplos anteriores tanto `false` como `nil` se trataban como falsos.
Aquí solo `nil` se trata como falsey, ya que si fuera `false` no habría sido nil y, por lo tanto, habría sido truthy.

## El operador or

La forma más fácil de manejar los valores `nil` es asegurarte de que nunca lleguen a ser `nil` en primer lugar.
El operador or ([`||`][or]) se usa a menudo cuando trabajas con `Bools`, pero si se entiende bien, también se puede usar para manejar valores `nil`.
El operador or comprueba si el primer valor es truthy; si no lo es, se usa el segundo valor.
Esto se puede usar para lograr que, si el valor es `nil`, sea falsey y, por lo tanto, se use el segundo valor.

```crystal
"foo"[10]? || "bar" # => "bar"
```

## not_nil!

~~~~exercism/caution 
Este enfoque debe verse como un último recurso y solo debe usarse si tienes la **certeza** de que el valor no es nil.
Si es posible, usa los otros enfoques en su lugar.
~~~~

[`not_nil!`][not_nil] es un método que te permite decirle al compilador que un valor no es nil y, por lo tanto, hace que el tipo que contiene no pueda ser nil.
Lo hace lanzando una excepción si el valor es nil.

```crystal
foo = "foo"[4]?
foo.not_nil!
# => Error: Nil assertion failed (NilAssertionError)
```
