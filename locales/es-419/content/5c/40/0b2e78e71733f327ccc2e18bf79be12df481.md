# Introducción

## Errores

Los errores ocurren. En Elixir, aunque se suele decir «let it crash», hay ocasiones en las que necesitamos rescatar la llamada a la función hasta un estado válido conocido para cumplir con un contrato de software. En algunos lenguajes, los errores se usan como método de control de flujo, pero en Elixir este patrón no se recomienda. A menudo podemos reconocer las funciones que pueden lanzar un error solo por su nombre: las funciones que lanzan errores llevan `!` al final de su nombre. Esto es en comparación con las funciones que devuelven `{:ok, value}` o `:error`. Mira estos ejemplos de la biblioteca:

```elixir
Map.fetch(%{a: 1}, :b)
# => :error
Map.fetch!(%{a: 1}, :b)
# => raises KeyError
```

## Try/Rescue

Elixir proporciona una construcción para rescatar errores usando `try .. rescue`

```elixir
try do
  raise RuntimeError, "error"
rescue
  e in RuntimeError -> :error
end
```

Veamos esta construcción:

- **Línea 1**, el bloque se declara con `try`.
- **Línea 2**, la llamada a la función que puede dar error se coloca aquí; en este caso estamos llamando a `raise/2`.
- **Línea 4**, en la sección `rescue`, hacemos coincidencia de patrones con el nombre del _módulo_ del error lanzado
  - del lado izquierdo de `->`:
    - `e` coincide con el struct del error.
    - `in` es una palabra clave.
    - `RuntimeError` es el error del que queremos rescatar.
      - Si quisiéramos rescatar de todos los errores, podríamos usar `_` en lugar del nombre del módulo u omitir por completo la palabra clave `in`.
  - del lado derecho:
    - las instrucciones que se ejecutarán si el error coincide.

### Structs de error

Los errores (a veces también llamados «excepciones») que rescatas de esta forma son structs.
En Elixir, rara vez se rescatan errores.
Por lo general, el error rescatado se registra o se envía a un servicio externo de monitoreo, y luego se vuelve a lanzar.
Esto significa que normalmente no nos importa la estructura interna del struct de error específico.

En el [concepto Excepciones][exercism-exceptions] aprenderás más sobre los structs de error, incluido cómo definir tu propio error personalizado.
