# Ejecutar las pruebas

Desde la terminal, cámbiate al directorio base del ejercicio y luego ejecuta las pruebas con:

```bash
$ mix test
```

Esto ejecutará el archivo de prueba que se encuentra en la subcarpeta `test`, un archivo que termina en `_test.exs`.

Documentación:

* [`mix test` - la herramienta de ejecución de pruebas de Elixir](https://hexdocs.pm/mix/Mix.Tasks.Test.html)
* [`ExUnit` - la biblioteca de pruebas unitarias de Elixir](https://hexdocs.pm/ex_unit/ExUnit.html)

## Pruebas pendientes

En las suites de pruebas de los ejercicios de práctica, todas las pruebas excepto la primera están etiquetadas para omitirse.

Cuando logres que una prueba pase, puedes hacer que se ejecute la siguiente comentando el `@tag :pending` correspondiente con el símbolo `#`.

Por ejemplo:

```elixir
# @tag :pending
test "shouting" do
  assert Bob.hey("WATCH OUT!") == "Whoa, chill out!"
end
```

Si quieres ejecutar todas las pruebas a la vez, puedes incluir todas las pruebas omitidas usando el flag `--include` en el comando `mix test`:

```bash
$ mix test --include pending
```

O puedes habilitar todas las pruebas comentando la línea de `ExUnit.configure` en el archivo `test/test_helper.exs`.

```elixir
# ExUnit.configure(exclude: :pending, trace: true)
```

## Opciones útiles de `mix test`

* `test/<FILE>.exs:LINENUM` - ejecuta solo una prueba, la prueba de `<FILE>.exs` cuya definición está en la línea `LINENUM`
* `--failed` - ejecuta solo las pruebas que fallaron la última vez que se ejecutaron
* `--max-failures` - la suite deja de evaluar pruebas cuando se alcanza este número de pruebas fallidas
* `--seed 0` - desactiva la aleatorización, así las pruebas en un solo archivo siempre se ejecutarán en el mismo orden en que se definieron
