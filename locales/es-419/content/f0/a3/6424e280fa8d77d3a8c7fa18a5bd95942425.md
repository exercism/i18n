## Opcionales

Swift usa los [_opcionales_][optionals] para permitir que quien programa represente la posible ausencia de un valor.
Un opcional es un tipo que puede contener un valor o ser [`nil`][nil], que representa la ausencia de un valor.
Usar un opcional requiere que el programa verifique si el valor existe y lo desenvuelva antes de usarlo.

Cualquier tipo se puede convertir en un opcional agregando un `?` al final del nombre del tipo.
Así, un entero opcional tendría el tipo `Int?` y un string opcional tendría el tipo `String?`.
Definir constantes o variables de tipo opcional y asignarles valores se hace igual que con los valores de tipos no opcionales.

```swift
let x: Int? = 42
var y: String? = "Hello"
y = "Goodbye"
```

Puedes asignar la ausencia de un valor a una variable de tipo opcional asignándole el valor especial `nil`.
`nil` se puede usar con todos los tipos opcionales, pero los `nil` asignados a dos tipos opcionales diferentes no tienen el mismo tipo y no se pueden intercambiar ni siquiera comparar.

```swift
let intOpt: Int? = nil
let stringOpt: String? = nil

intOpt = stringOpt
// Compiler error: Cannot assign value of type 'String?' to type 'Int?'

intOpt == stringOpt
// Compiler error: Binary operator '==' cannot be applied to operands of type 'Int?' and 'String?'
```

Ten en cuenta también que, aunque `nil` se puede asignar a cualquier tipo opcional, no se puede asignar a un tipo no opcional (incluso si en realidad no contiene `nil`).
Y a los métodos que esperan un tipo no opcional no se les puede pasar un tipo opcional sin desenvolverlo primero.

```swift
var x: Int = 42
var y: Int? = 42

y = x
// Works fine
x = y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
x + y
// error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

## Cómo usar los opcionales

Como los tipos opcionales no son los mismos tipos que sus tipos base, los dos tipos no se pueden usar de las mismas maneras.
Por ejemplo: `Int("123") + 1` da como resultado un error del compilador: «Value of optional type 'Int?' must be unwrapped to a value of type 'Int'».
Esto se debe a que `Int("123")` devuelve un tipo opcional `Int?`, no un tipo `Int`, ya que si el string no se puede convertir a un entero, el resultado será `nil`.
Para acceder al `Int` que resulta de la conversión, primero hay que «desenvolverlo».

En Swift, esto se hace casi siempre con las construcciones `if-let` y `guard-let` para la [_vinculación opcional_][optional-binding], que verifican si hay `nil` y, si el valor existe, toman un camino de código en el que el valor desenvuelto se vincula a un nombre que se proporciona, o bien toman otro camino de código si se encontró `nil`.

```swift
if let safeNum = Int("123") {
	let sum = safeNum + 1
	…
} else {
  // code for the case where nil was found -- may be left out
}
```

Vale la pena notar que la variable `safeNum` tiene el tipo `Int` y no `Int?`.
En el ejemplo de abajo, `num` es de tipo `Int?` y `safeNum` es de tipo `Int`.

```swift
let num = Int("123")
if let safeNum = num {
  // num is of type Int
}
```

Esta _vinculación opcional_ es importante porque desenvuelve (o «quita») el tipo opcional del valor, lo que permite usarlo como un valor no opcional.
Si solo hicieras una verificación condicional para saber si el valor es `nil`, el valor seguiría siendo de tipo opcional:

```swift
let num = Int("123")
if num != nil {
  // num is of type Int?
}
```

La opción `guard-let` también se puede usar en los casos en los que se quiere un retorno anticipado:

```swift
guard let num = Int("123") else { return nil }
let sum = num + 1
…
```

## Comparar opcionales

Ten en cuenta que, aunque el tipo base de un par de opcionales se pueda comparar con los operadores de comparación estándar, los opcionales en sí no se pueden comparar.
Solo se puede verificar su igualdad.
Dos opcionales son iguales si ambos son `nil` o si los valores que contienen son iguales dentro de sus tipos base.

Sin embargo, se puede escribir código para hacer una comparación personalizada de dos valores opcionales.
Abajo hay un ejemplo de una sentencia `switch` que devolverá `true` solo si ambos valores opcionales no son nil y el primer valor es menor que el segundo.
Para hacerlo, usa el _patrón opcional_ `varName?`, que solo coincide con opcionales que no son nil y vincula el valor dentro del opcional al nombre `varName`.

```swift
switch (optionalA, optionalB) {
case let (valA?, valB?): return valA < valB
default: return false
}
```

## Coalescencia de nil

Existe otra opción para desenvolver en la que se puede usar un [valor de respaldo][fallback] si hay `nil`.
Esto se puede hacer con el _operador de coalescencia de nil_, `??`. Suponiendo que `x` es un `Int?`, si escribes `let y = x ?? 0`, Swift verificará si x es `nil`.
Si no lo es, desenvolverá `x` y asignará el valor desenvuelto a `y`; y si `x` _es_ `nil`, asignará 0 a `y`.

Como `x ?? y` no es más que una forma abreviada de `x != nil ? x! : y`, si `x` no es nil, la expresión `y` no se evalúa en absoluto.

Por último, conviene señalar que el operador de coalescencia de nil es asociativo por la derecha, lo que puede dar resultados sorprendentes para quien no lo sabe.

```swift
let k = 42 ?? 0 + 1    // returns 42
let j = nil ?? 0 + 1   // returns 1
```

Puedes leer más sobre el operador de coalescencia de nil en [A Tour of Swift: Nil-Coalescing Operator][nil-coalescing].
