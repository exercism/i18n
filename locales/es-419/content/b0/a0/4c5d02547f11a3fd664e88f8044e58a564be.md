# Acerca de

## JSON

[JSON][json] (JavaScript Object Notation) es un formato de datos y de archivos legible por humanos que se usa comúnmente para intercambiar datos, en particular en aplicaciones web.
Por eso no sorprende que ocupe un lugar especial en el lenguaje Elm.

Elm incluye los módulos centrales [`Json.Decode`][decode] y [`Json.Encode`][encode] para analizar y escribir datos JSON.
Los decodificadores de JSON son una forma de _declarar_ qué tipo de datos se espera y a qué estructura de datos deben corresponder esos datos.

Si vienes de lenguajes con tipado dinámico, los decodificadores a menudo parecen engorrosos, o demasiado rígidos a primera vista.
Si bien son ciertamente verbosos, al menos en Elm, son una herramienta valiosa para describir de forma explícita lo que los programas esperan de los datos que reciben, y [no son menos expresivos que los tipos dinámicos][dynamic-types-not-more-open].

Importemos algunos alias y tipos de los módulos:

```elm
import Json.Decode as Decode exposing (Decoder, Error)
import Json.Encode as Encode exposing (Value)
```

Usar `Decode.decodeString : Decoder a -> String -> Result Error a` con un decodificador y un string de JSON tendrá éxito si el string cumple con las especificaciones del decodificador, o fallará en caso contrario.
No hay forma de inspeccionar los datos JSON sin procesar al definir el decodificador, lo que puede resultar inusual si vienes de lenguajes imperativos.

## Decodificadores de tipos de datos básicos

JSON tiene un número reducido de tipos de datos fundamentales:

- String: se escribe entre comillas dobles `"hello world"`
- Boolean: ya sea `true` o `false`
- Number: como `34` o `0.12`
- Null: la ausencia de datos, `null`

Cada uno de ellos está asociado a una función de `Decode`:

```elm
Decode.decodeString Decode.string """\"hello\""""
    --> Ok "hello"

Decode.decodeString Decode.string """null"""
    --> Err ...

Decode.decodeString Decode.bool """true"""
    --> Ok True

Decode.decodeString Decode.bool """0"""
    --> Err ...

Decode.decodeString Decode.int """12"""
    --> Ok 12

Decode.decodeString Decode.float """3.14"""
    --> Ok 3.14

Decode.decodeString (Decode.null AnyValue) """null"""
    --> Ok AnyValue

Decode.decodeString (Decode.null AnyValue) """true"""
    --> Err ...
```

Fíjate que `Decode.null` te deja decidir cómo modelar un `null` en tu programa, ya que requiere un valor arbitrario como argumento (tal vez `()`, `Nothing` o cualquier cosa que sea apropiada para tu programa).

## Combinar decodificadores

JSON también define dos estructuras de datos para agrupar tipos de datos fundamentales:

- Array: una colección de otros tipos de datos `[0, null, "none", []]`
- Object: una colección de pares clave-valor `{"id": 1, "is_admin": false, "more_info": {}}`

`Decode` también ofrece funciones para decodificarlos:

```elm
Decode.decodeString (Decode.list Decode.int) """[1, 2, 3]"""
    --> Ok [1, 2, 3]

Decode.decodeString (Decode.list Decode.int) """[1, 2, 3, "not an int"]"""
    --> Err ...

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": 71 }"""
    --> Ok (Dict.fromList [("key1", 17), ("key2", 71)])

Decode.decodeString (Decode.dict Decode.int) """{ "key1": 17, "key2": "seventy-one" }"""
    --> Err ...
```

Estas funciones, `Decode.list : Decoder a -> Decoder (List a)` y `Decode.dict : Decoder a -> Decoder (Dict String a)`, esperan cada una un decodificador como argumento, el cual debe decodificar cada uno de los elementos de la estructura de datos.
Si el decodificador que pasas como argumento no logra decodificar algún elemento de un array o de un objeto, falla el decodificador completo, y este es un patrón común.

Combinar decodificadores simples en otros más complejos es la idea central de esta técnica.
Vamos a presentar varias funciones más que puedes usar para construir decodificadores de datos del mundo real, tan complejos como quieras, mediante un ejemplo.

## GeoJSON

Para practicar cómo combinar decodificadores básicos y analizar datos JSON complejos, construyamos decodificadores que analicen (un subconjunto de) datos GeoJSON.
[GeoJSON][geojson] es un formato de datos especializado basado en JSON que se usa para representar elementos geográficos, como ubicaciones, rutas o regiones, especificados con coordenadas geográficas 2D o 3D, junto con otras propiedades.

### Objeto de geometría

Un objeto de geometría de GeoJSON es un objeto que contiene un campo `type` con un valor de tipo string (hay 7 valores posibles para `type`) y un campo `coordinates` con coordenadas geográficas (agrupadas en una estructura que depende del tipo).
Por ejemplo,

```json
{
  "type": "Point",
  "coordinates": [127.831, 26.461]
}
```

o

```json
{
  "type": "LineString",
  "coordinates": [
    [127.831, 26.461],
    [127.829, 26.465],
    [127.829, 26.469],
    [127.83, 26.47]
  ]
}
```

Un objeto de geometría se podría representar en Elm con el siguiente tipo

```elm
type Geometry
  = Point (List Float)
  | LineString (List (List Float))
  | ...
```

Para consultar el valor de un campo determinado, podemos usar `Decode.field : String -> Decoder a -> Decoder a`, que decodifica el valor de una clave específica de un objeto.

```elm
decodePointCoordinates : Decoder (List Float)
decodePointCoordinates =
    Decode.field "coordinates" (Decode.list Decode.float)

decodeLineStringCoordinates : Decoder (List (List Float))
decodeLineStringCoordinates =
    Decode.field "coordinates" (Decode.list (Decode.list Decode.float))
```

Para transformar el valor que un decodificador analizó con éxito, podemos usar `Decode.map : (a -> value) -> Decoder a -> Decoder value`, o cualquiera de sus hermanas, desde `Decode.map2  (a -> b -> value) -> Decoder a -> Decoder b -> Decoder value` hasta `Decode.map8`.

En este caso, queremos decidir qué decodificador de coordenadas usar según el valor del campo `type`, y para eso `Decode.andThen : (a -> Decoder b) -> Decoder a -> Decoder b` es perfecto, junto con sus amigas `Decode.succeed : a -> Decoder a` y `Decode.fail : String -> Decoder a`.

```elm
decodeGeometry : Decoder Geometry
decodeGeometry =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                case value of
                    "Point" ->
                        decodePointCoordinates |> Decode.map Point

                    "LineString" ->
                        decodeLineStringCoordinates |> Decode.map LineString

                    _ ->
                        Decode.fail "Geometry not implemented yet, or invalid type value"
            )
```

Fíjate que en este punto podríamos usar `Decode.andThen` para validar las coordenadas (comprobar que vengan en pares o tríos y que los valores de las coordenadas tengan sentido geográfico).

```elm
Decode.decodeString decodeGeometry """{"type": "Point", "coordinates": [127.831, 26.461]}"""
    --> Ok (Point [127.831, 26.461])

Decode.decodeString decodeGeometry """{"type": "LineString", "coordinates": [127.831, 26.461]}"""
    --> Err ...
```

### Objeto de tipo Feature

Un objeto de tipo Feature de GeoJSON representa algo delimitado espacialmente: tiene un campo `type` con el valor `"Feature"`, un campo `geometry` con un objeto de geometría o `null`, un campo `properties` con un objeto JSON arbitrario o `null`, y un campo opcional `id` con un valor de tipo string o número de JSON.

```json
{
  "type": "Feature",
  "geometry": null,
  "properties": null
}
```

o

```json
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
```

Abordemos primero el campo `id`.
Si existe, debe admitir strings o números, así que podríamos introducir un tipo personalizado para el valor, o guardarlo siempre como string.

Para elegir entre dos decodificadores posibles, podemos usar `Decode.oneOf : List (Decoder a) -> Decoder a`.

```elm
decodeFeatureId : Decoder String
decodeFeatureId =
    Decode.oneOf
        [ Decode.string
        , Decode.int |> Decode.map String.fromInt
        , Decode.float |> Decode.map String.fromFloat
        ]
        |> Decode.field "id"

Decode.decodeString decodeFeatureId """{"id": "seventeen"}"""
    --> Ok "seventeen"

Decode.decodeString decodeFeatureId """{"id": 17}"""
    --> Ok "17"

Decode.decodeString decodeFeatureId """{"type": "Point"}"""
    --> Er ...
```

Para expresar que el campo es opcional, podríamos usar la misma técnica

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.oneOf
        [ decodeFeatureId |> Decode.map Just
        , Decode.succeed Nothing
        ]
```

Pero en lugar de eso podríamos usar `Decode.maybe : Decoder a -> Decoder (Maybe a)`

```elm
decodeMaybeFeatureId : Decoder (Maybe String)
decodeMaybeFeatureId =
    Decode.maybe decodeFeatureId

Decode.decodeString decodeMaybeFeatureId """{"id": 17}"""
    --> Ok (Just "17")

Decode.decodeString decodeMaybeFeatureId """{"type": "Point"}"""
    --> Ok Nothing
```

Fíjate que `decodeMaybeFeatureId` (o cualquier decodificador envuelto con `Decode.maybe`) siempre tendrá éxito, ya que siempre puede recurrir a `Ok Nothing`, aunque un decodificador que lo use todavía podría fallar

```elm
Decode.decodeString (Decode.list decodeMaybeFeatureId) """{"id": 17}"""
    --> Err ...
```

Ahora enfoquémonos en el campo `geometry`, que puede ser un objeto de geometría o `null`.
Podríamos usar `Decode.oneOf` otra vez, pero hay una opción mejor: `Decode.nullable : Decoder a -> Decoder (Maybe a)`.

```elm
decodeFeatureGeometry : Decoder (Maybe Geometry)
decodeFeatureGeometry =
    Decode.nullable decodeGeometry
        |> Decode.field "geometry"

Decode.decodeString decodeFeatureGeometry """{"geometry": {"type": "Point", "coordinates": [127.831, 26.461]}}"""
    --> Ok (Just (Point [127.831, 26.461]))

Decode.decodeString decodeFeatureGeometry """{"geometry": null}"""
    --> Ok Nothing

Decode.decodeString decodeFeatureGeometry """{"geometry": {}}"""
    --> Err ...
```

`Decode.maybe` y `Decode.nullable` tienen la misma firma, pero su comportamiento es distinto, ya que el resultado `OK Nothing` de un `Decode.nullable` solo provendrá del valor JSON específico `null`.

Por último, el campo `properties` puede contener un objeto JSON arbitrario o `null`, y para eso está `Decode.value : Decoder Value`.

```elm
decodeProperties : Decoder (Maybe (Dict String Value))
decodeProperties =
    Decode.nullable (Decode.dict Decode.value)
        |> Decode.field "properties"


Decode.decodeString decodeProperties """{"properties": null}"""
    --> Ok Nothing

Decode.decodeString decodeProperties """{"properties": {"country": "Japan"}}"""
    --> Ok (Just (Dict.fromList [("country", <internals>)]))

Decode.decodeString decodeProperties """{"properties": 17}"""
    --> Err ...
```

Fíjate que `Value` es un tipo opaco, lo que significa que no puedes consultar su contenido con facilidad.
Para usarlo, puedes escribir un decodificador para él y ejecutarlo con `Decode.decodeValue : Decoder a -> Value -> Result Error a`, o enviarlo directamente a JavaScript mediante un puerto.

Ya estamos listos para analizar objetos de tipo Feature:

```elm
type alias Feature =
    { id : Maybe String
    , geometry : Maybe Geometry
    , properties : Maybe (Dict String Value)
    }

decodeFeature : Decoder Feature
decodeFeature =
    Decode.field "type" Decode.string
        |> Decode.andThen
            (\value ->
                if value /= "Feature" then
                    Decode.fail "not a Feature"

                else
                    Decode.map3 Feature
                        decodeMaybeFeatureId
                        decodeFeatureGeometry
                        decodeProperties
            )

Decode.decodeString decodeFeature """{"type": "Feature", "geometry": null, "properties": null}"""
    --> Ok { geometry = Nothing, id = Nothing, properties = Nothing }

"""
{
  "type": "Feature",
  "id": "0157",
  "geometry": {
    "type": "Point",
    "coordinates": [127.831, 26.461]
  },
  "properties": {
    "country": "Japan"
  }
}
"""
  |> Decode.decodeString decodeFeature
    --> Ok { geometry = Just (Point [127.831,26.461]), id = Just "0157", properties = Just (Dict.fromList [("country",<internals>)]) }
```

## Codificadores de JSON

Los codificadores permiten escribir JSON válido a partir de valores de Elm con la función `Encode.encode : Int -> Value -> String`.
El primer argumento especifica la cantidad de sangría en el resultado final, y el segundo es el valor JSON que se va a escribir.

Un `Value` se puede obtener de `Decode.value` o se puede producir con uno de los codificadores:

```elm
Encode.encode 0 (Encode.string "hello")
    --> "hello"

Encode.encode 0 (Encode.bool True)
    --> "true"

Encode.encode 0 (Encode.int 12)
    --> "12"

Encode.encode 0 (Encode.float 3.14)
    --> "3.14"

Encode.encode 0 Encode.null
    --> "null"

Encode.encode 0 (Encode.list Encode.int [1, 2, 3])
    --> "[1,2,3]"

Encode.encode 4 (Encode.list Encode.int [1, 2, 3])
    --> "[\n    1,\n    2,\n    3\n]"

Encode.encode 0 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\"key1\":17,\"key2\":71}"

Encode.encode 4 (Encode.dict String.toLower Encode.int (Dict.fromList [("KEY1", 17), ("KEY2", 71)]))
    --> "{\n    \"key1\": 17,\n    \"key2\": 71\n}"
```

así como con `Encode.object : List ( String, Value ) -> Value`

```elm
Encode.object
    [ ( "key1", Encode.int 17 )
    , ( "key2", Encode.int 71 )
    ]
    |> Encode.encode 0
    --> "{\"key1\":17,\"key2\":71}"
```

Definamos codificadores para los decodificadores de GeoJSON que definimos antes

```elm
encodeGeometry : Geometry -> Value
encodeGeometry geometry =
    case geometry of
        Point coord ->
            Encode.object
                [ ( "type", Encode.string "Point" )
                , ( "coordinates", Encode.list Encode.float coord )
                ]

        LineString coord ->
            Encode.object
                [ ( "type", Encode.string "LineString" )
                , ( "coordinates", Encode.list (Encode.list Encode.float) coord )
                ]

encodeFeature : Feature -> Value
encodeFeature feature =
    let
        maybeId =
            case feature.id of
                Nothing ->
                    []

                Just id ->
                    [ ( "id", Encode.string id ) ]
    in
    Encode.object
        (maybeId
            ++ [ ( "type", Encode.string "Feature" )
               , ( "geometry"
                 , case feature.geometry of
                    Nothing ->
                        Encode.null

                    Just geometry ->
                        encodeGeometry geometry
                 )
               , ( "properties"
                 , case feature.properties of
                    Nothing ->
                        Encode.null

                    Just dict ->
                        Encode.dict identity identity dict
                 )
               ]
        )
```

En general, una buena prueba para tus pares decodificador-codificador es comprobar que `elmValue |> encoder |> decoder == elmValue`.

## ¿Qué más?

No cubrimos todas y cada una de las funciones de los módulos `Json`.
Algunas de las cosas que no mencionamos son: decodificadores para convertir arrays en `Array` u objetos en `List (String, a)`, decodificadores para arrays con uno o más elementos, decodificadores para campos específicos en objetos JSON anidados o elementos específicos en arrays, cómo decodificar estructuras recursivas, y también las distintas variantes de `Error` y cómo mostrarlas.

Otros paquetes que se usan con frecuencia son [`Json.Decode.Pipeline`][pipeline], que introduce un flujo cómodo para estructuras JSON complejas, y [`Json.Decode.Extra`][extra], que ofrece más decodificadores, codificadores y utilidades.
