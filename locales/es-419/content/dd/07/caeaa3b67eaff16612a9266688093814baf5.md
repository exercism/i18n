# Acerca de

## Introducción

Los genéricos son una característica del lenguaje que permiten reutilizar código.
Por ejemplo, no debería importar qué tipo contiene una lista para calcular su longitud.
Por eso la función `length` usa un parámetro de tipo genérico `a` en su firma de tipo.

```elm
length : List a -> Int
```

## Parámetros en los tipos

Cuando un tipo es genérico sobre otro tipo, usamos un nombre en minúscula para ese otro tipo y lo llamamos parámetro de tipo.
Ejemplos comunes son los tipos personalizados `List`, `Maybe` y `Result`.

```elm
-- Maybe is generic over the type a
type Maybe a
    = Nothing
    | Just a

someString : Maybe String
someString = Just "hello"

someInt : Maybe Int
someInt = Just 42
```

Una observación importante sobre los nombres de los parámetros de tipo es que pueden tener más de un carácter.
La única restricción es que deben ser nombres en minúscula.
Por eso, cuando es útil, tendemos a darles nombres descriptivos.

Un tipo puede ser genérico sobre varios tipos, y por lo tanto tener varios parámetros de tipo.
En ese caso, cada tipo independiente recibe un nombre en minúscula diferente.
El ser independientes no impide que puedan ser el mismo tipo; simplemente permite que sean diferentes.

```elm
-- Result is generic over the types error and value
type Result error value
    = Ok value
    | Err error
```

Los alias de tipo de registro también pueden tener parámetros de tipo, aunque es menos común.

```elm
-- Event is generic over the type a
type alias Event a =
    { at : Time
    , data : a 
    }
```

> Por eso el paquete `Html` define el tipo `Html msg`, con un parámetro de tipo llamado `msg`.
> La arquitectura de Elm te guía hacia la creación de un tipo personalizado `Msg` que describe todos los mensajes que tu página web puede desencadenar.
> Como resultado, tu código construirá vistas del tipo `Html Msg`, donde `Msg` es el tipo concreto que definiste.
> A veces, quienes empiezan se confunden entre errores que mencionan `Html msg` (en minúscula) y errores con `Html Msg`.
> ¡Ahora ya lo sabes!
> La diferencia es que el primero es genérico sobre cualquier tipo `msg`, mientras que el segundo es específico para tu tipo `Msg`.

## Parámetros de tipo en funciones

Dado que los tipos pueden ser genéricos, las funciones también.
Se pueden escribir funciones que manejen tipos genéricos, como `Maybe.withDefault`.

```elm
withDefault : a -> Maybe a -> a
withDefault default maybe =
    case maybe of
      Just value -> value
      Nothing -> default
```

Las funciones que toman otras funciones como parámetros se llaman funciones de orden superior, y estas también pueden ser genéricas.

```elm
map : (a -> b) -> Maybe a -> Maybe b
map function maybe =
  case maybe of
    Just value ->
      Just (function value)

    Nothing ->
      Nothing
```

Los parámetros de tipo pueden aparecer tanto en las entradas como en la salida de una función, y la genericidad que habilitan los parámetros de tipo se suele llamar **polimorfismo paramétrico**.
Esto contrasta con el polimorfismo ad hoc, también conocido como sobrecarga de funciones, donde el mismo nombre de función se puede usar en múltiples implementaciones donde los tipos difieren.
Esto también contrasta con el polimorfismo de subtipos, donde los tipos se pueden definir en una jerarquía, y las funciones definidas en un tipo también se pueden llamar con argumentos de sus subtipos.
En Elm, el único mecanismo disponible para la genericidad es el polimorfismo paramétrico.
