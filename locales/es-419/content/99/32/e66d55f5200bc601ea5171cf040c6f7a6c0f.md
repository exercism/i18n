# Introducción

Antes de que se introdujera la clase `Promise`, solo había una forma de manejar el código asíncrono: el _patrón de callback_.

Un callback es una función que se pasa como argumento a otra función y que se llamará una vez que haya terminado alguna acción en esa otra función. Un patrón común para esas funciones de callback es que aceptan un «error» como primer parámetro (ver el ejemplo a continuación).

```javascript
function callback(error, arg2, arg3) {}
```

¿Cómo se relaciona esto con el código asíncrono?

Históricamente, los callbacks se han usado para poder hacer algo de trabajo después de que se completara una tarea asíncrona y sin bloquear todo el programa.

```javascript
fetchProduct(productId, function (error, data) {
  if (error) {
    // Handle the error
  } else {
    // Do some work
  }
});
```

En el ejemplo anterior, la función `fetchProduct` (que es asíncrona) recibe un callback como segundo argumento que decide qué hacer cuando se han obtenido los datos del producto.
