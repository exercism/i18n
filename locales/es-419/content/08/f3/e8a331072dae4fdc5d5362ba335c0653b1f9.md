# Pruebas

Ejecuta las pruebas con:

```bash
$ wrenc exercise-name.spec.wren
```

Por ejemplo, para `hello-world`:

```bash
$ wrenc hello-world.spec.wren
```


## Entender las pruebas omitidas

El método `skip` le indica al conjunto de pruebas que no ejecute una prueba en particular.

- ¿Por qué se omiten?

Para que puedas concentrarte en una prueba a la vez e ir habilitándolas una por una a medida que avanzas en la solución.

- ¿Cómo habilitarlas?

Una prueba omitida:

```js
// this test will be skipped and not run
skip.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

Solo cambia `skip.test` por `do.test`.

```js
// now the test will be run normally
do.test("title cased phrases") {
    Expect.value(Acronyms.parse("Portable Network Graphics")).toEqual("PNG")
}
```

## Cómo crear tu primer módulo de Wren

Las pruebas de este track cargan tu implementación importándola como un módulo de Wren:
`import "./bob" for Bob`. No hay ninguna sintaxis especial para exportar tu
implementación. Solo nombra tu clase `Bob` para que coincida con las instrucciones de
importación `for
Bob` y todo debería funcionar sin más.

```javascript
class Bob {
  static hey(message) {
    // Your solution to the exercise goes here
  }
}
```

Puedes encontrar más información sobre los módulos en la
[documentación de modularidad de Wren][modularity].
Para que sea más fácil empezar, hay un archivo Wren _esqueleto_ en el
directorio de cada ejercicio.

[modularity]: https://wren.io/modularity.html
