# Acerca de

Los recursos que mantienen estado del sistema operativo (manejadores de archivos, sockets, bloqueos) necesitan una limpieza *garantizada*, incluso cuando una excepción desenrolla la pila. El vocabulario [`destructors`][destructors] de Factor proporciona un pequeño framework para eso, y la mayoría de los recursos integrados (`<file-reader>`, `<file-writer>`, sockets, …) ya se conectan a él.

## La clase y el genérico

Una clase se une extendiendo `disposable` e implementando `dispose*`:

```factor
TUPLE: my-handle < disposable underlying ;

: <my-handle> ( underlying -- handle )
    my-handle new-disposable swap >>underlying ;

M: my-handle dispose* underlying>> dispose ;
```

`new-disposable ( class -- obj )` reserva la tupla *y* la registra en el ámbito del destructor actual, así que una excepción entre la asignación y el siguiente punto seguro no puede filtrar el recurso. El framework garantiza que `dispose*` se ejecuta **como máximo una vez** por objeto; las llamadas repetidas a `dispose` no tienen efecto.

## Quienes llaman desde fuera usan `dispose`

| palabra           | efecto                                        |
|-------------------|-----------------------------------------------|
| `dispose`         | `( obj -- )`: libera; seguro llamarla dos veces    |
| `with-disposal`   | `( disposable quot -- )`: abre un ámbito para un recurso |
| `with-destructors`| `( quot -- )`: abre un ámbito de registro         |
| `&dispose`        | `( obj -- obj )`: libera al salir normalmente *o* por error |
| `|dispose`        | `( obj -- obj )`: libera solo si el ámbito se desenrolla |

`with-disposal` es la forma para un solo recurso. Para más de un recurso, abre un ámbito `with-destructors` y registra cada adquisición con `&dispose` (siempre quieres liberarlo) o `|dispose` (libera solo en caso de fallo; la ruta de éxito lo conserva).

```factor
[
    "in.txt"  utf8 <file-reader> &dispose
    "out.txt" utf8 <file-writer> &dispose
    [ read1 ] [ write1 ] bi
] with-destructors
```

## `cleanup` es la primitiva básica

Para un try/finally puntual sin un registro, [`cleanup`][cleanup] (de `continuations`) es la palabra de más bajo nivel:

```
cleanup ( try cleanup-always cleanup-error -- )
```

`with-destructors` es estrictamente más potente (el registro puede crecer en tiempo de ejecución), pero `cleanup` es la opción natural cuando el emparejamiento de adquisición/liberación es fijo y local.
