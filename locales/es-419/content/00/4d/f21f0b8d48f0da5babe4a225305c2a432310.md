# Acerca de

[8th](https://8th-dev.com) es un lenguaje de tipado fuerte, derivado de FORTH y basado en la pila, con sintaxis RPN.

8th es compatible con las plataformas android, ios32, lin64, mac64, rpi32 y win64. 8th te permite usar la plataforma que prefieras para escribir y probar tu código. ¡Con un solo clic generas los ejecutables *para* cualquier plataforma que 8th admita, *desde* cualquier plataforma que admita!

8th incluye todo lo que necesitas: compatibilidad con GUI multiplataforma, cifrado fuerte, compatibilidad con bases de datos SQLite, FFI, acceso REST, localización sencilla, acceso al hardware, compatibilidad con JSON, un REPL y mucho más.

La seguridad no es algo secundario en 8th. Se diseñó desde el principio para evitar los problemas de seguridad de software más comunes. Trabajamos continuamente para hacerlo aún más seguro.

8th tiene un [foro](https://8th-dev.com/forum/), además de una extensa documentación que incluye un [manual](https://8th-dev.com/manual.html) y un diccionario con hipervínculos de [palabras](https://8th-dev.com/words.html) integradas y de biblioteca. ¡[Compara](https://8th-dev.com/compare.html) 8th con otros lenguajes!

## Introducción rápida para usuarios de lenguajes «mainstream»

Si vienes de C, de Java o de la mayoría de los lenguajes más comunes, puede que 8th te resulte un poco desconcertante. Para ayudarte a empezar por buen camino, aquí tienes algunas de las principales diferencias entre 8th y «lo mainstream», además de algunos consejos útiles:

* Como consecuencia de la forma en que el intérprete busca los elementos, debes declarar un var o una palabra antes de usarlos por primera vez. Si no lo haces, obtendrás la excepción can't find ...

* Un var es un contenedor con nombre para otros elementos. ¡No es el nombre del elemento al que se refiere! Así, var x puede contener un array, pero es un error intentar acceder a x como si x mismo fuera un array, y si lo haces se lanzará una excepción.

* No puedes declarar un var dentro de (por ejemplo, como local de) una palabra, ¡no lo intentes! Sin embargo, puedes usar w:@ y w:! para acceder a variables locales de la palabra.

* Intenta escribir tus propias palabras de modo que se puedan encadenar con otras palabras. Por ejemplo: las «palabras de archivo» hacen alguna operación sobre un archivo y dejan el elemento del archivo en la pila (y quizá otra información) para que la siguiente palabra trabaje con él.

* Mantén tus palabras cortas. Coméntalas. Asegúrate, sobre todo, de comentar el efecto sobre la pila, y…

* … prueba cada palabra que escribas (preferiblemente mientras la escribes o poco después), asegurándote de que cumpla con su SED (Stack-Effect Diagram) documentado. Esto te ayudará a escribir código sin bugs. Vuelve a probar si cambias el SED o el código.

* Consulta las palabras help y apropos para ver los detalles de la acción del SED y de los efectos secundarios de cualquier palabra de la que no tengas certeza.

* En 8th, una excepción es un error fatal y hará que la aplicación se cierre (este es el comportamiento predeterminado). No esperes poder «atrapar» una y manejarla de forma efectiva.

* No hay ciclo de compilación/enlazado. En cambio, 8th es un motor que primero interpreta tu código y, si es necesario, lo compila en tiempo de ejecución. Cuando se ejecuta en un dispositivo, tu código es código nativo de la plataforma, no bytecode que corre dentro de una VM.
