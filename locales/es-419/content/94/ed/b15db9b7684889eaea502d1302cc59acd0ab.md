# Introducción

Elixir ofrece una construcción para rescatar de errores usando `try .. rescue`

```elixir
try do
  raise RuntimeError, "error"
rescue
  e in RuntimeError -> :error
end
```

Veamos esta construcción:

- **Línea 1**, el bloque se declara con `try`.
- **Línea 2**, la llamada a la función que puede dar error se coloca aquí; en este caso llamamos a `raise/2`.
- **Línea 4**, en la sección `rescue`, hacemos coincidencia de patrones sobre el nombre del _módulo_ del error lanzado.
  - en el lado izquierdo de `->`:
    - `e` coincide con el struct del error.
    - `in` es una palabra clave.
    - `RuntimeError` es el error del que queremos rescatar.
      - Si quisiéramos rescatar de todos los errores, podríamos usar `_` en lugar del nombre del módulo u omitir por completo la palabra clave `in`.
  - en el lado derecho:
    - las instrucciones que se ejecutan si el error coincide.

## Structs de error

Los errores (a veces también llamados «excepciones») que rescatas de esta manera son structs.
Rescatar errores en Elixir es algo que se hace muy rara vez.
Por lo general, el error rescatado se registra o se envía a un servicio externo de monitoreo, y luego se vuelve a lanzar.
Esto significa que por lo general no nos importa la estructura interna del struct de error específico.

En el [concepto de Excepciones][exercism-exceptions] aprenderás más sobre los structs de error, incluido cómo definir tu propio error personalizado.
