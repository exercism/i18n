# Construir un test runner

El test runner es una pieza esencial de las herramientas, ya que permite:

- Que el sitio web verifique automáticamente si una iteración pasa todas las pruebas.
- Que los estudiantes resuelvan ejercicios usando el [editor en el navegador](/docs/using/solving-exercises/using-the-online-editor) ([sin necesidad de la CLI](/docs/using/solving-exercises/working-locally)).

Para empezar a construir un test runner, revisa el documento [Crear un test runner desde cero](/docs/building/tooling/test-runners/creating-from-scratch).

## Implementación

Las herramientas de un track normalmente (en su mayoría) están escritas en el lenguaje del track.

```exercism/caution
Si bien eres libre de usar otros lenguajes, cada lenguaje adicional hará más difícil mantener o contribuir al track.
Por eso, te recomendamos usar el lenguaje del track cuando sea posible, porque hace más fácil mantenerlo o contribuir a él.
```

## Despliegue

El test runner se empaqueta y se ejecuta como un [contenedor de Docker](/docs/building/tooling/docker).
Las imágenes de Docker del test runner se despliegan automáticamente usando un [flujo de trabajo de GitHub Actions](https://github.com/exercism/generic-test-runner/blob/main/.github/workflows/docker.yml).

## Pruebas

Una vez que hayas construido un test runner, puedes usar su imagen de Docker en la configuración de CI de tu track para verificar los ejercicios del track.
El principal beneficio de este enfoque es que imita mejor la configuración de producción; en otras palabras, puedes tener más confianza de que las cosas también funcionan en producción.
Una posible desventaja es que podría ralentizar el flujo de trabajo de CI.
Depende de ti, que mantienes el track, decidir cuál enfoque funciona mejor para tu track.
