# Pruebas

Cada ejercicio viene con un conjunto de pruebas unitarias y todo lo necesario para compilarlas y ejecutarlas.
La implementación la aportas tú.

## Ejecutar las pruebas

Abre una terminal en la carpeta del ejercicio y ejecuta:

```
make
```

Esto compila tu solución y las pruebas, y después las ejecuta.
Ejecútalo de nuevo cada vez que cambies tu solución.

Si tienes la [CLI de Exercism](https://exercism.org/docs/using/solving-exercises/working-locally), puedes usar este comando en su lugar, que también ejecuta `make`:

```
exercism test
```

Para eliminar los archivos que crea la compilación, ejecuta `make clean`.

### Sin make

Si no tienes `make` (en Windows, por ejemplo), puedes compilar y ejecutar las pruebas directamente.
Para el ejercicio «Bob»:

```
gfortran TesterMain.f90 bob.f90 bob_test.f90 -o run_tests
```

Después, ejecuta las pruebas en Linux o macOS:

```
./run_tests
```

O en Windows:

```
.\run_tests
```

## Avanzar por un ejercicio

Los archivos de cada ejercicio llevan su nombre.
Para el ejercicio «Bob»:

| Archivo          | Contenido                                                          |
| ---------------- | ------------------------------------------------------------------ |
| `bob.f90`        | una plantilla de la solución, lista para que la completes          |
| `bob_test.f90`   | las pruebas                                                        |
| `TesterMain.f90` | la biblioteca de pruebas                                           |
| `Makefile`       | instrucciones para `make`                                          |
| `CMakeLists.txt` | instrucciones para [CMake](#using-cmake-instead), que es opcional  |

Solo necesitas editar el archivo de la solución.

Avanzar por cada ejercicio es un proceso que consiste en repetir estos pasos hasta que todas las pruebas pasen:

- Corregir los errores de compilación y después ejecutar las pruebas para ver cuáles fallan.
- Implementar lo justo y necesario para que pase la siguiente prueba que falla.
- Refactorizar tu implementación para mejorar la legibilidad, reducir la duplicación, etc.
- Ejecutar las pruebas de nuevo y pasar a la siguiente prueba que falla.

Se imprime un mensaje por cada prueba que falla, seguido de un resumen.
Si alguna prueba falla, `make` termina con un error.

Cada prueba tiene un comentario que describe la prueba y después la prueba en sí, que empieza con `call assert_equal`, por ejemplo.

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Para desactivar una prueba, basta con comentarla con un `'!'`, por ejemplo.

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

## Usar CMake en su lugar

No necesitas CMake, pero puede serte útil si trabajas en un IDE como Visual Studio o Xcode, o si usas un compilador distinto de GFortran.

La carpeta del ejercicio debe conservar su nombre original, porque CMake lo usa para encontrar los archivos fuente.
Empieza en la carpeta del ejercicio:

```
mkdir build
cd build
cmake ..
cmake --build .
ctest -V
```

Después de cambiar tu solución, solo hacen falta los dos últimos comandos.

**Nota:** ejecuta siempre `cmake` desde una carpeta aparte, como `build`.
Ejecutar `cmake .` en la carpeta del ejercicio reemplaza el `Makefile` que viene con el ejercicio.

CMake elige un generador adecuado para tu sistema.
Para elegir otro, usa la opción `-G`, por ejemplo `cmake -G Xcode ..`.
Ejecuta `cmake --help` para ver la lista de generadores que puedes usar.
Con Visual Studio o Xcode, ejecuta las pruebas con `ctest -V -C Debug`.

Si tu carpeta del ejercicio no contiene un `Makefile`, es que se descargó antes de que estos archivos se añadieran a los ejercicios.
Aún puedes usar CMake.
