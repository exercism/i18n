# Instrucciones

Mantienes la estación de procesamiento de un array de sismógrafos, una red de sensores que registran cómo se mueve el suelo.

Las lecturas llegan como bloques de valores.
Algunas son desplazamientos del suelo almacenados como números de punto flotante de 32 bits; otras son conteos crudos y palabras de estado almacenados como enteros de 32 bits.
La estación procesa un bloque completo a la vez, aplicando la misma operación a cada valor.

Tienes seis tareas, y cada una opera sobre un bloque de valores que está en memoria.
Recibes los operandos a través de direcciones de memoria y escribes tu respuesta a través de una dirección de resultado.
Todas las direcciones de memoria de este ejercicio están alineadas a 16 bytes.

~~~~exercism/note
Los cálculos de este ejercicio deben realizarse usando operaciones bit a bit de SIMD y desplazamientos, no operaciones escalares.
~~~~

## 1. Rectifica la traza

Para el análisis de magnitud, solo importa el tamaño de cada desplazamiento del suelo, no su dirección.
El primer paso de procesamiento convierte cada lectura en un valor no negativo.

Implementa la función `rectify_trace`, que calcula el valor absoluto de cada lectura.
Un bloque contiene 4 lecturas, cada una un número de punto flotante de 32 bits.

Esta función recibe como argumentos, en este orden:

- `result`: dirección de memoria de un búfer donde se escriben las 4 lecturas rectificadas.
- `trace`: dirección de memoria de las lecturas registradas, con 4 valores, cada uno un número de punto flotante de 32 bits.

```c
trace  = {1.5, -2.25, 0.0, -135.75}
result = {1.5,  2.25, 0.0,  135.75}
```

Esta función no devuelve ningún valor.

## 2. Lee la escala de un temblor

Los analistas clasifican los temblores por su potencia de dos: una lectura cercana a `8.0` está en la escala `3`, y una lectura cercana a `0.25` está en la escala `-2`.
Esa escala ya está almacenada dentro de cada número de punto flotante, como su campo de exponente.

Un número de punto flotante de 32 bits se distribuye así: un bit de signo en el bit 31, un exponente de 8 bits en los bits 30 a 23, y una fracción de 23 bits en los bits 22 a 0.
El exponente almacenado tiene un sesgo de 127, por lo que el valor del número es `(-1)^sign * 1.fraction * 2^(exponent - 127)`.

Implementa la función `reading_scale`, que extrae el exponente sin sesgo de cada lectura como un entero de 32 bits con signo.

Esta función recibe como argumentos, en este orden:

- `result`: dirección de memoria de un búfer donde se escriben las 4 escalas, cada una un entero de 32 bits con signo.
- `trace`: dirección de memoria de las lecturas rectificadas, con 4 valores, cada uno un número de punto flotante de 32 bits.

```c
trace  = {8.0, 0.25, 1.0, 13.5}
result = {  3,   -2,   0,   3}
```

Esta función no devuelve ningún valor.
Todas las lecturas son números de punto flotante normales y distintos de cero.

## 3. Reduce la resolución

Para el almacenamiento a largo plazo, los conteos crudos de desplazamiento se guardan con una resolución más gruesa: cada conteo se divide por una potencia de dos.

Los conteos de desplazamiento tienen signo: el suelo puede moverse en ambos sentidos.
Dividirlos correctamente requiere el desplazamiento que conserva el signo.

Implementa la función `coarsen_displacements`, que divide cada conteo con signo entre `2^shift`, redondeando hacia menos infinito.

Esta función recibe como argumentos, en este orden:

- `result`: dirección de memoria de un búfer donde se escriben los 4 conteos reducidos, cada uno un entero de 32 bits con signo.
- `counts`: dirección de memoria de los conteos crudos, con 4 enteros de 32 bits con signo.
- `shift`: la potencia de dos entre la que se divide, como un entero de 64 bits sin signo entre `0` y `31`.

```c
counts = {1024, -1024, 25, -25}
shift  = 3
result = { 128,  -128,  3,  -4}
```

~~~~exercism/note
La instrucción `movq` puede usarse para copiar un entero de 64 bits desde un registro de propósito general a un registro `xmm` sin cambiar la representación de bits subyacente.
~~~~

Esta función no devuelve ningún valor.

## 4. Aplica compuertas a los canales

Cada estación combina dos campañas de registro y luego silencia los canales que su informe de hardware marca como defectuosos.
Cada bloque contiene 4 máscaras de canales, cada una un entero de 32 bits sin signo, donde cada bit representa un canal: `1` habilitado, `0` deshabilitado.

Implementa la función `gate_channels`, que combina los canales habilitados en cualquiera de las dos campañas y luego limpia todos los canales marcados como defectuosos.

Esta función recibe como argumentos, en este orden:

- `result`: dirección de memoria de un búfer donde se escriben las 4 máscaras resultantes, cada una un entero de 32 bits sin signo.
- `enable_a`: dirección de memoria de las máscaras de habilitación de la primera campaña, con 4 enteros de 32 bits sin signo.
- `enable_b`: dirección de memoria de las máscaras de habilitación de la segunda campaña, con 4 enteros de 32 bits sin signo.
- `faulty`: dirección de memoria de las máscaras de canales defectuosos, con 4 enteros de 32 bits sin signo.

```c
enable_a = {0b1100, 0b0001, 0b1111, 0b0000}
enable_b = {0b0110, 0b0001, 0b0000, 0b0000}
faulty   = {0b0100, 0b0011, 0b1001, 0b1111}
result   = {0b1010, 0b0000, 0b0110, 0b0000}
```

Esta función no devuelve ningún valor.

## 5. Alterna los bits de calibración

Una vez al día, la estación ejecuta una pasada de calibración que invierte un conjunto elegido de bits de configuración en cada palabra de estado y deja intactos todos los demás bits.
Pero el hardware bloquea algunos bits y estos nunca deben cambiar, sin importar lo que solicite la pasada.
Ejecutar la misma pasada dos veces restaura la configuración original.

Implementa la función `toggle_calibration`, que invierte, en cada palabra de estado, exactamente los bits que están activados en la máscara de alternancia correspondiente y no están activados en la máscara de bloqueo correspondiente.

Esta función recibe como argumentos, en este orden:

- `result`: dirección de memoria de un búfer donde se escriben las 4 palabras de estado actualizadas, cada una un entero de 32 bits sin signo.
- `status`: dirección de memoria de las palabras de estado actuales, con 4 enteros de 32 bits sin signo.
- `toggle`: dirección de memoria de las máscaras de alternancia, con 4 enteros de 32 bits sin signo.
- `locked`: dirección de memoria de las máscaras de bloqueo, con 4 enteros de 32 bits sin signo.

```c
status = {0b1100, 0b0001, 0b1111, 0b1010}
toggle = {0b0110, 0b0011, 0b1111, 0b1010}
locked = {0b0010, 0b0001, 0b1100, 0b0000}
result = {0b1000, 0b0011, 0b1100, 0b0000}
```

Esta función no devuelve ningún valor.

## 6. Amplifica la traza

Cada canal del array tiene su propio ajuste de ganancia, expresado como una potencia de dos: una ganancia de `3` multiplica la lectura del canal por `8`, y una ganancia de `-5` la divide entre `32`.

La estación aplica estas ganancias sin una sola multiplicación, manipulando el campo de exponente de cada número de punto flotante.

Implementa la función `amplify_trace`, que multiplica cada lectura por `2` elevado a la ganancia de su canal, operando solo sobre los bits crudos.

Esta función recibe como argumentos, en este orden:

- `result`: dirección de memoria de un búfer donde se escriben las 4 lecturas amplificadas.
- `trace`: dirección de memoria de las lecturas, con 4 valores, cada uno un número de punto flotante de 32 bits.
- `gains`: dirección de memoria de las ganancias por canal, con 4 enteros de 32 bits con signo.

```c
trace  = {1.5, -2.0, 0.25, 96.0}
gains  = {  2,    1,    3,   -5}
result = {6.0, -4.0,  2.0,  3.0}
```

Esta función no devuelve ningún valor.
Todas las lecturas son números de punto flotante normales y distintos de cero, y cada resultado amplificado también es normal.
