## Aplicación parcial

Todas las funciones en Elm están [currificadas][currying], lo que significa que si llamas a una función sin pasar todos los argumentos, devuelve una nueva función.

El resultado de hacer esto se llama [aplicación parcial][partial-application] (no estás pasando todos los argumentos a la función, sino que estás aplicando algunos de ellos parcialmente).

```elm
add: Int -> Int -> Int
add a b = a + b

add2: Int -> Int
add2 = add 2

eight: Int
eight = add2 6
--> 8
```

La aplicación parcial siempre aplica los argumentos en orden.

```elm
contains: String -> String -> Bool
contains first second =
--> This function is in the standard library, and returns True if the second string contains the first one

containsCedd: String -> Bool
containsCedd = contains "Cedd"
--> (partial application always applies the arguments in order, so "Cedd" becomes the first argument to contains
--> This is a function that takes a string, and returns True if that string contains Cedd)

ceddBurgeContainsCedd: Bool
ceddBurgeContainsCedd = containsCedd "Cedd Burge"
--> True
--> ("Cedd Burge" ends up being the second argument to contains, and it does include "Cedd", the first argument)
```

## Operador pipe (`|>`)

Decir `x |> f` es exactamente lo mismo que `f x`. Un ejemplo concreto es que `"5" |> String.toInt` es lo mismo que `String.toInt "5"`.

Esto no parece muy útil al principio, pero se llama [operador pipe][pipe-operator] porque te permite escribir código «encadenado».

Por ejemplo, supongamos que tenemos una función sanitize para convertir la entrada del usuario en números enteros:

```elm
sanitize : String -> Maybe Int
sanitize input =
    String.toInt (String.trim input)
```

Podemos reescribirla así:

```elm
sanitize : String -> Maybe Int
sanitize input =
    input
    |> String.trim
    |> String.toInt
```

Esto evita el uso de paréntesis y muestra las funciones en el orden en que se aplican (primero `String.trim`, luego `String.toInt`), lo que ayuda a la legibilidad.

También existe un [operador pipe inverso `(<|)`][reverse-pipe-operator]. Decir `x <| f` es exactamente lo mismo que `f x`. Esto tampoco parece muy útil a primera vista, y definitivamente no se usa tanto como el operador pipe, pero ayuda a evitar paréntesis en algunas situaciones.

## Composición de funciones / estilo point free

El operador [`(>>)`][forward-composition] tiene el tipo `(a -> b) -> (b -> c) -> (a -> c)` y crea una función de tipo `a -> c` al componer dos funciones compatibles de tipo `a -> b ` y `b -> c`. Lo hace tomando la salida (de tipo `b`) de la primera función y usándola como el primer argumento de la segunda función (que debe ser del mismo tipo `b`). La función creada recibirá el mismo argumento (de tipo `a`) que la primera función, y devolverá lo que sea `c` que devuelva la segunda función.

Un ejemplo concreto es `String.trim >> String.toInt`. `String.trim` toma un string como su único parámetro, así que esto es lo que toma la función creada. `String.toInt` devuelve un `Maybe Int`, así que esto es lo que devuelve la función creada. `String.trim` devuelve un `String`, que `String.toInt` acepta como parámetro, así que el ejemplo compila.

Ahora podemos reescribir nuestra función `sanitize` de la siguiente manera:

```elm
sanitize : String -> Maybe Int
sanitize =
    String.trim >> String.toInt
```

Fíjate que ya no usamos el parámetro `input` que se ve en el ejemplo original, aunque la funcionalidad es idéntica. Esta forma de crear funciones que no hacen referencia a sus parámetros se llama «estilo point free». La ventaja de este estilo es que el código es más conciso; la desventaja es que puede ser más difícil de entender, sobre todo para principiantes.

Vale la pena recordar que todas las funciones están currificadas en Elm, así que `String.length >> max` compila, y da como resultado lo siguiente:

- Una función (1) que tiene un parámetro de tipo string (el argumento de `String.length`)
- `max` es una función que tiene dos parámetros `Int`, pero la función 1 le pasa un solo `Int` (lo que devuelve `String.length`), así que `max` queda parcialmente aplicada.
- El valor que devuelve la función `max` parcialmente aplicada es otra función (2) que recibe un `Int` y devuelve el mayor entre este `Int` y el `Int` parcialmente aplicado que viene de `String.length`.
- Por lo tanto, la función 1 (`String -> Int`) devuelve la función 2 (`Int -> Int`).
- Así que `((String.length >> max) "123") 2` devuelve `3`, porque `"123"` tiene una longitud de 3, que es mayor que el 2 del argumento `Int`.

## Diseño de funciones

Para que sea fácil escribir código elegante en Elm, conviene hacer que la estructura de datos principal sea el último parámetro de las funciones. Todas las funciones comunes de la biblioteca estándar lo hacen, como `List.map` (con su firma de tipo a continuación).

```elm
map : (a -> b) -> List a -> List b
```

Aquí podemos ver que el último parámetro de la función `map` es `List a` y que devuelve `List b`, así que la estructura de datos principal (`List`) es el último parámetro.

Esto permite escribir código encadenado elegante, como el siguiente.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase names =
    names
    |> List.map String.trim
    |> List.map String.toUpper
```

También hace conveniente usar la composición de funciones y el estilo point free, como alternativa al encadenamiento.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map String.trim
    >> List.map String.toUpper
```

La composición de funciones también te permite reducir este ejemplo a una sola llamada a `List.map`.

```elm
trimAndUpperCase : List String -> List String
trimAndUpperCase =
    List.map (String.trim >> String.toUpper)
```
