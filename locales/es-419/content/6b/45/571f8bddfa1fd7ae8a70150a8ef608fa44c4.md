# Introducción

Los especificadores de clase de almacenamiento tienen que ver con cómo se guardan las variables en la memoria.
Están estrechamente relacionados con la duración de almacenamiento (también conocida como el tiempo de vida) de un valor.

## auto: la clase de almacenamiento predeterminada para las variables con ámbito de función o de bloque

Como las variables definidas dentro de un bloque o una función son `auto` de forma predeterminada, no es común usar el término de manera explícita.
El tiempo de vida de una variable `auto` comienza cuando se entra al bloque y termina cuando se sale de él.
Cuando se entra al bloque, se reserva memoria para una variable `auto`, _pero sin ningún valor predeterminado_.

## static: el especificador de almacenamiento que no se debe confundir con el tipo de enlazado static

Si una variable se define fuera de un bloque o una función y se marca con `static`, ese `static` se refiere a su enlazado, lo que significa que solo se puede acceder a ella dentro del archivo.
Si una variable se define dentro de una función o en un bloque dentro de una función y se marca con `static`, tiene duración de almacenamiento `static`.
El valor de la variable `static` persiste entre llamadas a la función o al bloque.

## extern: cómo acceder a una variable en otra unidad de traducción

Una unidad de traducción consta de un archivo fuente y cualquier otro archivo que incluya mediante `#include`.
Aunque una variable con ámbito de archivo se puede declarar e inicializar como `extern`, la palabra clave `extern` normalmente se usa para hacer referencia a una variable existente, no para definir una nueva.
La variable a la que se hace referencia con `extern` debe tener ámbito de archivo.
Una variable con ámbito de archivo siempre tiene almacenamiento `static`.
Una variable en un archivo incluido debe tener enlazado externo para que el archivo que la incluye pueda acceder a ella.

## register: cómo posiblemente acelerar el acceso a una variable

Una variable marcada como `register` expresa el deseo del programador de que el valor se coloque en un registro para acceder a él rápidamente.
Una variable `register` es como una variable `auto` en el sentido de que debe estar en el ámbito de una función o de un bloque.
Como se pretende que el valor se coloque en un registro en lugar de en la memoria, el compilador debería impedir el acceso a la dirección de la variable, ya que no se puede obtener la dirección de un registro.
Sin embargo, una dirección de memoria en sí misma sí se puede colocar en un registro.
`register` es esencialmente una sugerencia, ya que puede que el valor se coloque realmente en un registro o puede que no.

## typedef: el especificador de clase de almacenamiento que en realidad no lo es

`typedef` se describe como un especificador de clase de almacenamiento solo por razones sintácticas.
Esto se debe a que un especificador de clase de almacenamiento no se puede usar junto con otro especificador de clase de almacenamiento.
Por lo tanto, `typedef auto int i = 42;` es tan ilegal como `static auto int i = 42;`.
