# Acerca de

Aunque Swift tiene muchos tipos diferentes, cada uno de ellos pertenece a una de dos clasificaciones distintas: los _tipos de valor_ y los _tipos de referencia_. En Swift, [las estructuras son tipos de valor][structs-are-value-types], mientras que [las clases son tipos de referencia][classes-are-reference-types].

La diferencia principal entre los tipos de valor y los tipos de referencia es que, cuando se asigna un tipo de valor a una variable o a una constante, o cuando se pasa a una función, lo que se asigna o se pasa es en realidad una copia del valor, no ese valor en particular. Modificar una copia de una estructura no afecta a las demás copias. Con los tipos de referencia, lo que se asigna o se pasa es una referencia a ese valor, así que dos nombres distintos pueden referirse a la misma instancia de una clase. Esto puede provocar que se modifique la instancia original cuando se accede a ella con otro nombre.

Entonces, dadas la estructura y la clase que definen a un personaje de un juego y sus estadísticas de juego, podemos ver qué pasa cuando estos elementos se copian y se modifican.

```swift
struct CharacterStats {
  var health = 0.0
  var speed = 0
  var strength = 0

  mutating func takeHit(_ damage: Double) {
    health = max(0.0, health - damage)
  }
  func canLift(_ weight: Int) -> Bool {
    weight < strength * 100
  }
}

class GameCharacter {
  var stats = CharacterStats()
  var characterClass: String?
  var name: String?
  var active = false
  let id: String = makeRandomID()

  func takesDamage(_ damage: Double) {
    stats.takeHit(damage)
    if stats.health <= 0 {
      active = false
    }
  }
  func sayName() -> String {
    return "My name is \(name ?? "no one"), my class is \(characterClass ?? "undetermined")"
  }
  func lift(_ weight: Int) -> String {
    if stats.canLift(weight) {
      return "No problem!"
    } else {
      return "Ooof! No way."
    }
  }
}

var statsA = CharacterStats(health: 100.0, speed: 15, strength: 12)
var statsB = statsA
statsA.speed = 17
statsB.takeHit(50)
statsA.health
// => 100
statsB.health
// => 50
statsA.speed
// => 17
statsB.speed
// 15

var charA = GameCharacter()
charA.name = "Hagor the Brave"
charA.characterClass = "Warrior"
charA.stats = statsA
charA.sayName()
// => "My name is Hagor the Brave, my class is Warrior"
charA.lift(1000)
// => true

var charB = charA
charB.name = "Bunny Wigglesworth"
charB.characterClass = "Couch Potato"
charB.stats.strength = 3

charA.sayName()
// => "My name is Bunny Wigglesworth, my class is Couch Potato"
charA.lift(1000)
// => false
```

Fíjate en cómo cambiar las propiedades de `charB` afectó a las de `charA`, ya que ambos nombres se refieren a la misma instancia. Fíjate también en que, con las estadísticas de los dos personajes, los tipos de valor dentro de un tipo de referencia cambiarán dentro de los tipos de referencia. Sin embargo, esto no es una violación del comportamiento de los tipos de valor, porque `charA.stats` es la misma instancia de `CharacterStats` que `charB.stats`, ya que `charA` y `charB` se refieren a la misma instancia de la clase `GameCharacter`. Como podemos ver, las copias de esos tipos de valor no se afectan entre sí, por ejemplo.

```swift
var aStats = charA.stats
aStats.speed = 1
charA.takesDamage(30)

aStats.speed
// => 1
charA.stats.speed
// => 17
aStats.health
// => 100
charA.stats.health
// => 70
```

Por esto las estructuras requieren la palabra clave `mutating` delante de los métodos que alteran el estado de las propiedades de la estructura. Cambiar la propiedad de una estructura en realidad crea una nueva copia de la estructura con el nuevo valor establecido para esa propiedad, y la nueva copia reemplaza a la antigua. Es un indicador visual de que esta copia y este reemplazo pueden ocurrir con los valores de ese tipo.

Esto tiene como efecto secundario que cualquier instancia de una estructura cuyas propiedades variables cambien, ya sea llamando a funciones mutating o mediante asignación directa, _debe_ asignarse a variables, no a constantes. De lo contrario, se generará un error del compilador:

```swift
let constantStats = CharacterStats(health: 30, speed: 20, strength: 10)
constantStats.health
// => 30
constantStats.speed
// => 20
constantStats.takeHit(10)
// => Cannot use mutating member on immutable value: 'constantStats' is a 'let' constant
constantStats.speed -= 2
// => Left side of mutating operator isn't mutable: 'constantStats' is a 'let' constant
constantStats.strength = 15
// => Cannot assign to property: 'constantStats' is a 'let' constant
```

Los valores iniciales todavía se pueden crear y consultar, pero no se permite cambiarlos. Esta restricción no se aplica a las clases. Si se asigna una instancia de una clase a un nombre con `let`, lo que la constante guarda es la referencia a la instancia, así que lo que no puede cambiar es esa referencia, no la instancia en sí. Por lo tanto, la instancia en sí puede cambiar, pero la referencia no puede modificarse para apuntar a otra instancia.

Un resumen de lo que se puede cambiar en las estructuras y las clases definidas con `let` o `var` es el siguiente:

|         | **estructura**                                                                                     | **clase**                                                                                       |
| ------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **let** | _No_ se puede asignar una nueva estructura al nombre.</br>_No_ se puede modificar ninguna propiedad de la estructura. | _No_ se puede asignar una nueva clase al nombre.</br>_Sí_ se pueden modificar las propiedades mutables de la clase. |
| **var** | _Sí_ se puede asignar una nueva estructura al nombre.</br>_Sí_ se pueden modificar las propiedades mutables de la estructura.   | _Sí_ se puede asignar una nueva clase al nombre.</br>_Sí_ se pueden modificar las propiedades mutables de la clase.    |

## Identidad

Como dos nombres distintos pueden contener una referencia a la misma instancia de una clase, a veces es útil comprobar si ese es el caso. Swift usa el operador _idéntico_ `===` para comprobarlo (junto con su negación, `!==`).

```swift
let char1 = GameCharacter()
let char2 = char1
let char3 = GameCharacter()

char1 === char2
// => true
char1 === char3
// => false
char2 === char3
// => false
char2 !== char3
// => true
```

Como dos nombres no pueden referirse a la misma instancia de una estructura, estos operadores de identidad no están definidos para las estructuras.

```struct
someStats === differentStats
// Error: Cannot convert value of type 'CharacterStats' to expected argument type 'AnyObject?'
```

Fíjate en que identidad no es lo mismo que igualdad. Según muchas definiciones, `char1` y `char3` se considerarían iguales, ya que todas sus propiedades tienen los mismos valores, pero no comparten la misma identidad. La identidad está disponible automáticamente para todas las clases en Swift, pero normalmente los desarrolladores tienen que escribir sus propios operadores de igualdad para determinar si dos instancias de una estructura o clase son _iguales_. Hacer esto queda fuera del alcance de este ejercicio.
