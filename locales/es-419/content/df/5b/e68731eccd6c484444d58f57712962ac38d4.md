# Prepárate para el lanzamiento

Antes de estar listo para lanzar tu track, asegúrate de que se hayan completado las siguientes tareas.

## Solicita el ícono del track

Para diseñar un ícono para el sitio, abre un nuevo issue en el repositorio [exercism/website-icons](https://github.com/exercism/website-icons/issues), respondiendo las siguientes preguntas:

- ¿El lenguaje tiene un logo oficial? Si es así,
  - incluye un enlace a un ejemplo
  - enumera los requisitos de atribución y los derechos otorgados para el uso de ese logo
- ¿El lenguaje tiene un logo no oficial? Si es así,
  - explica las formas en que las personas usan el logo no oficial
  - incluye un enlace a un ejemplo
  - enumera los requisitos de atribución de ese logo

## Agrega la documentación del track

Agrega los siguientes documentos del track:

- `docs/ABOUT.md`: una breve introducción al lenguaje.
- `docs/INSTALLATION.md`: describe lo que el estudiante necesita instalar para poder trabajar en el track en su sistema local usando la CLI.
- `docs/LEARNING.md`: enlaces a recursos de aprendizaje.
- `docs/RESOURCES.md`: enlaces a recursos útiles.
- `docs/TESTS.md`: describe todo lo relacionado con ejecutar los tests en el track.

Estos documentos ayudarán al estudiante a comenzar con el track, además de aprender sobre el track y su lenguaje.
Consulta la [documentación de docs](/docs/building/tracks/docs) para obtener más información.

## Agrega la documentación de los ejercicios

Agrega los siguientes documentos de ejercicios:

- `exercises/shared/.docs/help.md`: contiene instrucciones específicas del track sobre cómo obtener ayuda
- `exercises/shared/.docs/tests.md`: contiene instrucciones específicas del track sobre cómo ejecutar los tests

## Agrega un fragmento de código

Agrega un fragmento de código al archivo `docs/SNIPPET.txt`.
Este fragmento da una idea visual de cómo se ve la sintaxis del lenguaje.
Consulta la [documentación de docs](/docs/building/tracks/docs) para obtener más información.

## Actualiza los metadatos

Los metadatos del track se definen en el [archivo config.json](/docs/building/tracks/config-json).
Se deben actualizar las siguientes propiedades:

- `language`: el lenguaje del track (por ejemplo, `"C#"`). Su longitud debe ser <= 255
- `slug`: el lenguaje del track como un string en minúsculas y con formato kebab-case (por ejemplo, `"csharp"`). Su longitud debe ser <= 255
- `blurb`: una descripción breve del lenguaje. Su longitud debe ser <= 400
- `online_editor`: un objeto que describe la configuración que se usa para el editor en línea:
  - `indent_style`: ya sea `"space"` o `"tab"`
  - `indent_size`: el tamaño de la indentación como un entero (por ejemplo, `4`)
  - `highlightjs_language`: el identificador de lenguaje para Highlight.js (consulta la [lista completa de identificadores](https://github.com/highlightjs/highlight.js/blob/main/SUPPORTED_LANGUAGES.md)). Si no hay soporte de Highlight.js, este campo se puede omitir.
- `key_features`: las características clave del lenguaje, que resumen de forma concisa sus rasgos más importantes. Para obtener más información, consulta la [documentación de key features](/docs/building/tracks/config-json#h-key-features).
- `tags`: define las etiquetas que aplican a este track, lo que permite que se pueda buscar en el sitio web. Para obtener más información y ver la lista de etiquetas admitidas, consulta la [documentación de tags](/docs/building/tracks/config-json#h-tags).
