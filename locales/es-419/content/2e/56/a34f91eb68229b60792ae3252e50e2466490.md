# Excepciones

```sather
   raise "Unknown prop: " + prop;
```

```sather
   protect
      ...
   when $STR then
      #OUT + exception.str;
   end;
```

## raise

`raise` acepta cualquier objeto. Lanzar un `STR` es el caso simple y es lo que usa este ejercicio. Una clase propia puede llevar más información (cuál prop, cuántas se esperaban), a costa de tener que definirla en algún lugar.

Una excepción viaja hacia afuera a través de quienes llaman, hasta que un `protect` la captura. Si ninguno lo hace, el programa se detiene y la imprime.

Sather no registra qué excepciones puede lanzar una rutina, ni obliga a quienes llaman a manejarlas. Nada en el tipo de una rutina indica que pueda fallar.

## protect

```sather
   protect
      body
   when $STR then
      ...
   when SOME_CLASS then
      ...
   end;
```

Las ramas se prueban en orden, y se ejecuta la primera cuyo tipo coincide con el valor lanzado. `exception` es ese valor y solo está en el ámbito dentro de una rama.

Un `protect` sin una rama que coincida no captura: la excepción sigue hacia afuera como si el `protect` no estuviera allí.

## Dónde capturar

Captura donde de verdad se pueda hacer algo. Un `protect` que se traga una excepción y continúa con un valor inventado convierte un fallo que salta a la vista en una respuesta incorrecta y silenciosa, que es peor.

```sather
   -- almost always wrong
   protect
      return risky;
   when $STR then
      return 0;
   end;
```

## ¿Excepciones o contratos?

Ambos tienen que ver con cosas que salen mal, pero son para casos opuestos.

Una **excepción** es para algo que de verdad puede pasar y que quien llama razonablemente no habría podido evitar: un prop que falta en la tabla, un archivo que no está.

Un **contrato**, que es el siguiente ejercicio, es para algo que nunca debe pasar (quien llama pasa un peso negativo) y es una afirmación de que quien llama tiene un bug. Los contratos se verifican solo cuando se piden, y un contrato violado detiene el programa en lugar de lanzar algo que se pueda capturar.

En pocas palabras: si puede ocurrir incluso con quien llama con cuidado, lánzalo. Si ocurre porque quien llama se equivocó, ponlo en un contrato.
