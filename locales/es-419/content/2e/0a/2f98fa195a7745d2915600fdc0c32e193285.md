# Acerca de

En Rust, un iterador es cualquier valor que implemente el trait [`Iterator`](https://doc.rust-lang.org/stable/std/iter/trait.Iterator.html).
Los valores de un iterador se pueden avanzar manualmente llamando al método `next` del iterador.

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // many built-in methods implemented
}
```

Muchas de las [`collections`](https://doc.rust-lang.org/std/collections/index.html) de Rust implementan
[`IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html),
que puede producir un `Iterator` a partir de los valores de la colección.

```rust
trait IntoIterator where Self::IntoIter: Iterator<Item=Self::Item> {
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}
```

Fíjate que, aunque `IntoIterator::into_iter` consume su tipo `self`, ese tipo no tiene que ser necesariamente un valor propio.
Por eso existen implementaciones de `IntoIterator` para [`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-2),
para [`&'a Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator)
y para [`&'a mut Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html#impl-IntoIterator-1).
Estas implementaciones para distintos grados de propiedad ofrecen una flexibilidad muy útil.

Entender los `traits` no es necesario para este concepto y tendremos un ejercicio completo para que los domines.
Por ahora, solo recuerda que:

- Cualquier tipo que implemente `IntoIterator` se llama _iterable_ porque se puede convertir en un iterador.
- Cualquier tipo que implemente `Iterator` es un iterador, que _produce_ valores y se puede _recorrer_.
- Puedes obtener un iterador de cualquier tipo que implemente `IntoIterator` llamando a su método `into_iter`.
- Todo iterador [implementa `IntoIterator`](https://doc.rust-lang.org/std/iter/trait.IntoIterator.html#impl-IntoIterator-25) y se produce a sí mismo.
- Los bucles `for` siempre operan sobre iteradores y llaman a `IntoIterator` de forma implícita sobre su argumento de rango.

## `into_iter` y los bucles `for`

Probablemente ya conoces los bucles `for` sobre un vector:

```rust
// lor is a `Vec`, which implements `IntoIterator`
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
for people in &lor {
    println!("{people}");
}
```

En esencia, un bucle `for` no es más que una forma abreviada de llamar al método `into_iter` de su argumento
y luego llamar a `next()` hasta que deje de producir elementos. En otras palabras, el bucle anterior equivale a:

```rust
{
    let mut iterator = (&lor).into_iter();
    while let Some(people) = iterator.next() {
        println!("{people}");
    }
}
```

## Los métodos `iter` e `iter_mut`

La mayoría de los tipos de colección de Rust proporcionan los métodos `iter` e `iter_mut`.
Para una colección de tipo `T`, estos dos métodos hacen lo siguiente por convención:

- El iterador que devuelve `iter` producirá `&T` prestado de forma inmutable.
- El iterador que devuelve `iter_mut` producirá `&mut T` prestado de forma mutable.

```rust
let mut v = vec![1, 2, 3];

// Using `iter` method
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&1));
assert_eq!(iterator.next(), Some(&2));
assert_eq!(iterator.next(), Some(&3));
assert_eq!(iterator.next(), None);

// Using `iter_mut` method
for value in v.iter_mut() {
     *value *= *value;
}
println!("{v:?}");
// => [1, 4, 9]
```

## Diferencias entre `iter`, `iter_mut` e `into_iter`

Si `iter`, `iter_mut` e `into_iter` producen iteradores, ¿cuáles son las diferencias?

- El iterador que devuelve `iter` producirá, por convención, `&T` prestado de forma inmutable.
- El iterador que devuelve `iter_mut` producirá, por convención, `&mut T` prestado de forma mutable.
- El iterador que devuelve `into_iter` puede producir `T`, `&T` o `&mut T`, según su contexto.

¿Cuál es el contexto de una llamada a `into_iter`?
Su tipo `self`.
Recuerda que existen implementaciones de `IntoIterator` para `Vec`, `&'a Vec` y `&'a mut Vec`.
Por lo tanto:

- `(&v).into_iter()` es igual a `v.iter()` => devuelve `&T`
- `(&mut v).into_iter()` es igual a `v.iter_mut()` => devuelve `&mut T`
- `v.into_iter()` => devuelve `T` y mueve los valores

Esto se ve más claro en los bucles `for`:

- `for num in &v {...}` => vincula `&T`
- `for num in &mut v {...}` => vincula `&mut T`
- `for num in v {...}` => vincula `T` y mueve los valores

A menudo es más claro escribir `v.iter()` en lugar de `(&v).into_iter()`.
Por eso hay razones de ergonomía para preferir `iter` e `iter_mut` sobre `into_iter`.

## Cómo usar los métodos integrados de los iteradores

Los iteradores ofrecen numerosos métodos integrados, como `map`, `filter` y `collect`.
Estos métodos a veces se usan con closures.

`map` usa un closure para transformar los valores de un iterador.
`take` trunca un iterador (posiblemente infinito) en uno que termina después de, como máximo, el número de elementos especificado.

```rust
for even_number in (0..).into_iter().map(|x| x * 2).take(4) {
    let odd_number = even_number + 1;
    println!("{even_number} => {odd_number}");
}
// 0 => 1
// 2 => 3
// 4 => 5
// 6 => 7
```

`filter` transforma el iterador en uno que solo devuelve aquellos valores para los que el closure se evalúa como `true`.
`count` consume el iterador y devuelve el número de elementos producidos.

```rust
let lor = vec!["Ainur", "Elves", "Men", "Dwarves", "Hobbits", "Orcs", "Dragons"];
let short_people = ["Dwarves", "Hobbits"];
let num_tall_people = lor.iter().filter(|people| !short_people.contains(people)).count();
assert_eq!(num_tall_people, 5);
```

`flat_map` transforma un iterador transformando cada elemento en un nuevo iterador mediante el closure proporcionado,
y luego aplana todos los iteradores nuevos producidos encadenándolos entre sí.
`collect` produce una nueva colección,
siempre que el tipo de la colección implemente [`FromIterator`](https://doc.rust-lang.org/std/iter/trait.FromIterator.html).

```rust
let words = ["alpha", "beta", "gamma"];
// chars() returns an iterator
let merged: String = words.iter()
                          .flat_map(|s| s.chars())
                          .collect();
assert_eq!(merged, "alphabetagamma");
```

El [trait `Iterator`](https://doc.rust-lang.org/std/iter/trait.Iterator.html) ofrece _muchas_ transformaciones de iterador útiles como estas;
vale la pena leer la documentación y familiarizarte con ellas.

## Pereza

Es importante saber que los iteradores de Rust son perezosos:
no producen ningún valor hasta que consumimos el iterador.
Si escribes y ejecutas el siguiente código:

```rust
(0..5).map(|x| x * x);
```

Obtendrás el siguiente error del compilador:

```rust
 --> src/main.rs:2:5
  |
2 |     (0..5).map(|x| x * x);
  |     ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

Esto se debe a que `map` es un método adaptador que devuelve otro iterador.

Para consumir un iterador, usa un bucle `for` o un método de iterador que produzca algún valor que no sea a su vez un iterador.

Por ejemplo, `collect` es un método consumidor (su firma de función no devuelve un iterador, sino un tipo genérico):

```rust
//         Iterator   Adaptor        Consumer
//                |      |               |
let v: Vec<_> = (0..5).map(|x| x * x).collect();
```
