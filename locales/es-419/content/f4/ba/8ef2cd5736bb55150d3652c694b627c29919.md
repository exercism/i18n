# Clases abstractas

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class JUGGLING < $ACT is
   name : STR is return "Juggling"; end;
   minutes : INT is return 5; end;
   create : SAME is return new; end;
end;
```

## El $ es parte del nombre

Cada clase abstracta se nombra con un `$` al principio, y solo las clases abstractas lo llevan. Así que un tipo que empieza con `$` es uno del que no puedes crear un objeto, y eso se ve en todos los lugares donde aparece el nombre.

## Qué puede ir en una

Firmas de rutinas e iteradores, que terminan en el punto y coma. Sin cuerpos, sin atributos, sin `create`. Una clase abstracta describe lo que se le puede *pedir* a algo, nunca lo que contiene.

## Conformidad

```sather
class TRAPEZE < $ACT is
```

La clase debe definir cada rutina listada, con tipos de argumento y tipo de retorno que coincidan. Se verifica al compilar.

Una clase puede conformar a varias:

```sather
class TRAPEZE < $ACT, $RISKY is
```

y las clases abstractas pueden extender una a otra:

```sather
abstract class $TIMED_ACT < $ACT is
   overrun : INT;
end;
```

## Dónde ocurre el despacho

Una variable de un tipo abstracto contiene una referencia a algún objeto que conforma. Llamar a una rutina sobre ella elige la versión que pertenece a la clase real del objeto, en tiempo de ejecución.

Ese es el único lugar donde Sather decide algo en tiempo de ejecución. Una llamada sobre una variable de un tipo concreto queda resuelta al compilar.

## typecase

A veces el tipo sí importa. `typecase` pregunta:

```sather
   typecase act
   when TRAPEZE then #OUT + "rig the net";
   else            #OUT + "nothing to rig";
   end;
```

Dentro de una rama, la variable tiene el tipo más restringido. Recurre a él rara vez: un `typecase` sobre cada tipo de acto suele ser una rutina que en realidad pertenecía a la clase abstracta desde el principio.

## $OB

`$OB` es la clase abstracta a la que conforman todos los objetos. A veces resulta útil, y la mayoría de las veces es señal de que se perdió un tipo por el camino.

## ¿Por qué no la herencia?

Sather separa dos cosas que la mayoría de los lenguajes une. `<` solo dice lo que una clase puede *hacer*. Obtener una implementación de otro lugar es `include`, que es el ejercicio que viene dos más adelante, y es una decisión aparte.
