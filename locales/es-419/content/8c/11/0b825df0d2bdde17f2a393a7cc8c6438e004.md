# Introducción a comandos y argumentos

Este track no trata sobre cómo usar bash como shell interactivo.
Trata sobre aprender a escribir programas usando bash, el lenguaje de programación.

Un programa de bash, o _script_, es una secuencia de comandos guardada en un archivo.
bash (el ejecutable) lee el archivo y ejecuta los comandos en orden.

## El shebang

La primera línea de un script suele ser una _directiva de intérprete_, también conocida como _hashbang_ o _shebang_:

```bash
#!/usr/bin/env bash
```

Cuando el sistema operativo ejecuta un archivo no binario, lee la primera línea.
Si la línea comienza con `#!`, el kernel la usa para determinar qué intérprete debe ejecutar el archivo.
El `#!` debe estar al principio absoluto del archivo, sin espacios ni líneas en blanco antes.

Aquí, `env` busca en `PATH` el ejecutable `bash`.
También puedes ver el más simple `#!/bin/bash`, que fija la ubicación del intérprete de forma rígida; la forma con `env` es más portable.

~~~~exercism/note
No te dejes engañar por scripts o ejemplos de internet que usan `/bin/sh` como intérprete.
**¡`sh` no es `bash`!**
Bash es «compatible con sh» y puede ejecutar la mayoría de los scripts de `sh`, pero algunas funcionalidades de bash se romperán o se comportarán de forma inesperada en `sh`.
~~~~

## Comentarios

Una línea que comienza con `#` es un _comentario_, y bash la ignora.
Un comentario también puede ir después de un comando en la misma línea: todo lo que va desde el `#` hasta el final de la línea se ignora.
Los comentarios existen para que las personas lean el script.

## Palabras y argumentos

Bash lee comandos de su entrada (que por lo general es una terminal o un archivo).
Cada línea de entrada que lee se trata como un _comando_: una instrucción que se debe llevar a cabo.
(Hay algunos casos avanzados, como los comandos que abarcan varias líneas, que veremos más adelante.)

Bash divide cada comando en **palabras** delimitadas por caracteres de espacio en blanco (espacios y tabulaciones).
La primera palabra es el nombre del _comando_ que se debe ejecutar.
Todas las palabras restantes se convierten en _argumentos_ de ese comando (opciones, nombres de archivo, etc.).

Un comando puede ser un _comando interno_ de bash, como `echo`, o un programa _ejecutable_, como `head`, `awk` o `sed`.

## El comando `echo`

`echo` imprime sus argumentos, separados por un solo espacio, y termina con un salto de línea:

```bash
echo flour sugar eggs
```

produce:

```text
flour sugar eggs
```

La cantidad de espacios en blanco entre argumentos no importa:

```bash
echo flour       sugar        eggs
```

```text
flour sugar eggs
```

Llamar a `echo` sin argumentos imprime una línea en blanco.

## Las opciones son solo argumentos

Muchos comandos aceptan _opciones_ que cambian cómo se comportan.
Para bash, una opción no tiene nada de especial: es una palabra como cualquier otra, separada de las que la rodean por espacios en blanco.
El propio comando decide cómo interpretar sus argumentos.
Por convención, las opciones comienzan con un `-`.

El comando `head` imprime las primeras líneas de un archivo.
Dado el archivo `list.txt`:

```bash
head -n 2 list.txt
```

Bash divide esta línea en cuatro palabras:

| Palabra    | Rol                                                 |
| ---------- | --------------------------------------------------- |
| `head`     | el comando que se debe ejecutar                     |
| `-n`       | una opción que le dice a `head` que cuente _líneas_ |
| `2`        | el valor de la opción `-n`                          |
| `list.txt` | el archivo que se debe leer                         |

Bash le pasa las últimas tres palabras a `head` sin cambios.
Es `head` el que entiende que `-n` va seguido de un número, y que la palabra restante es un archivo.

Como el espacio en blanco es lo que separa las palabras, importa dónde lo pones.
`head -n 2` le da a `head` dos argumentos (`-n` y `2`), mientras que `head -n2` le da uno (`-n2`).
Muchos comandos aceptan ambas formas, pero eso depende del comando.
A bash no le importa; solo divide la línea en palabras.

## Entrecomillar argumentos

[Las comillas][Quotes] agrupan palabras en un _único argumento_.
Los espacios en blanco dentro de las comillas se conservan, y los caracteres de comillas en sí no forman parte del argumento:

```bash
echo "flour       sugar        eggs"
```

```text
flour       sugar        eggs
```

Si un argumento, como un nombre de archivo, contiene espacios en blanco, entrecomíllalo:

```bash
head -n 1 my shopping list.txt     # three files: "my", "shopping", "list.txt"
head -n 1 "my shopping list.txt"   # one file
```

## Ejecutar un script

Para ejecutar un script, pásalo como argumento al comando `bash`:

```bash
bash myscript
```

Usada de esta manera, la línea `#!` es solo un comentario.
Le estás diciendo al sistema operativo cómo ejecutar el archivo.

Como alternativa, marca el archivo del script como ejecutable y ejecútalo como cualquier otro programa:

```bash
chmod +x myscript
./myscript
```

Ahora el sistema operativo usa la línea `#!` para determinar qué intérprete debe usar.
