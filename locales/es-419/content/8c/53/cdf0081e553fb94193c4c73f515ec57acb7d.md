# Contribuir con un concepto y un ejercicio de concepto

Un [ejercicio de concepto][product-concept] busca enseñar un solo concepto en un lenguaje determinado.
Debe tener un objetivo de aprendizaje claro y proporcionar suficiente código base para que el estudiante no tenga que aprender código innecesario.
El concepto asociado tiene su propia documentación, independiente del ejercicio de concepto.
Los conceptos pueden tener otros conceptos como prerrequisitos y permanecer bloqueados hasta que se completen los ejercicios de concepto de los conceptos prerrequisito.
La dificultad de los ejercicios de concepto no debería aumentar a medida que avanza el track.
Cualquier desarrollador que esté familiarizado con los conceptos prerrequisito debería poder resolver un ejercicio de concepto en 5 a 10 minutos.

Ahora que sabemos qué es un ejercicio de concepto, veamos en detalle cómo implementar uno y su concepto asociado.
Como referencia, la [especificación detallada de un ejercicio de concepto][concept-exercise-spec] y la de un [concepto][concept-spec] están disponibles en el [repositorio de documentación][docs-repo] de exercism.
Este documento reúne información de muchas fuentes para servir como una guía paso a paso cómoda sobre cómo contribuir con un ejercicio de concepto.

También están representados como un grafo de dependencias en el [sitio web de exercism][concepts-graph-exercism].

## 2. Define los objetivos de aprendizaje

Es importante saber qué busca enseñar un ejercicio de concepto y qué queda fuera de su alcance, así que creemos nuestro primer archivo: `exercises/concept/<story-name>/.meta/design.md`.
Como los ejercicios de concepto llevan el nombre de la historia que usan y todavía no la conocemos, por ahora dejaremos `story-name` y lo reemplazaremos más adelante.
La [especificación de `design.md`][design-spec] indica que este documento debe definir el objetivo general del ejercicio, sus múltiples objetivos de aprendizaje, las cosas que quedan fuera de alcance, el concepto asociado que desbloquea y los conceptos prerrequisito para poder completar el ejercicio.
Puedes usar el [`design.md` del ejercicio de concepto de Boolean][design-bool] como plantilla de partida.

## 3. Escribe una introducción al concepto para el ejercicio

Una vez que los objetivos de aprendizaje estén claros, es momento de escribir una introducción que explique lo suficiente del concepto para que el estudiante pueda luego resolver el ejercicio.
Crea un archivo `exercises/concept/<story-name>/.docs/introduction.md`.
El contenido detallado de este archivo se explica en [su especificación][exercise-intro-spec].
Puedes usar el [`introduction.md` del ejercicio de concepto de Boolean][intro-bool] como plantilla de partida.

La información que proporciones debe introducir el concepto justo lo suficiente para que el estudiante descubra por su cuenta la solución del ejercicio.
Usa términos técnicos adecuados para que al estudiante le resulte más fácil buscarlos en línea.
Trata de evitar los enlaces y, en su lugar, explica las cosas de forma concisa dentro del texto.
Presenta la sintaxis del código con bloques de código.

## 4. Encuentra una historia para el ejercicio

Cada ejercicio de concepto debe estar basado en una historia o un tema.
Tratamos de que sean lo más inclusivos posible, sabiendo que Exercism se usa en todo el mundo.
La primera opción es reutilizar una historia que ya exista dentro de la [lista de historias registradas en la documentación][stories].
Si quieres crear una historia nueva, no dudes en avisar a @exercism/leadership en tu PR.
Ahora puedes cambiar el nombre del directorio `exercises/concept/<story-name>/` para que coincida con tu historia.

## 5. Escribe las instrucciones del ejercicio

Una vez que tengas la historia, debemos escribir instrucciones precisas que enumeren las tareas que el estudiante tendrá que realizar.
Tanto la historia como las instrucciones se escriben en el documento `exercises/concept/<story-name>/.docs/instructions.md`.
Como se explica en [la especificación de ese documento][instructions-spec], cada tarea tiene su propio título de nivel 2 en markdown (`## 1. Do X`), seguido de una descripción y un ejemplo de uso del código.
Puedes usar el [`instructions.md` del ejercicio de concepto de Boolean][instructions-bool] como plantilla de partida.

Además de `instructions.md`, también necesitamos un archivo `hints.md`.
Debe contener los mismos títulos de nivel 2 (`## 1. Do X`) que el archivo de instrucciones, para que se muestren las pistas correctas según la tarea en la que se esté trabajando.
También puede haber una sección `## General` con pistas que apliquen a todas las tareas.
Las pistas no deben revelar la solución directamente.
Además, ten en cuenta que quien hace clic en las pistas puede que ya esté confundido, abrumado o frustrado con el ejercicio.
Hay más información sobre este documento en [su especificación][hints-spec], y puedes usar el [`hints.md` del ejercicio de concepto de Boolean][hints-bool] como plantilla de partida.

## 6. Abre un pull request en borrador para validar el diseño

¡Ahora es un buen momento para abrir un pull request en borrador de tu ejercicio de concepto!
Ya tenemos suficiente material para evaluar el ejercicio y remodelarlo si hace falta antes de comprometernos con su estado actual para el resto de los archivos requeridos.
No te preocupes si las comprobaciones automáticas de la CI fallan por documentos faltantes, ¡los crearemos más adelante!

## 7. Escribe el código

Vamos a escribir el código como si estuviéramos resolviendo el ejercicio, y más tarde moveremos archivos para cumplir con las especificaciones.
Empecemos copiando el contenido del directorio [`template/`][template] dentro de nuestro directorio `exercises/concept/<story-name>/`.
Esto significa que tenemos los siguientes archivos:

```txt
elm.json           # elm project configuration file
src/Exercise.elm   # code for the exercise
tests/Tests.elm    # tests for the exercise
```

Luego renombra `Exercise.elm` para usar el PascalCase del nombre de la historia.
Por ejemplo, `annalyns-infiltration` pasa a ser `AnnalynsInfiltration.elm`.
Dentro de ese archivo fuente, ahora puedes escribir todas las funciones descritas en el `instructions.md` que acabamos de escribir.

Una vez que el ejercicio esté implementado, actualiza el contenido del archivo `tests/Tests.elm` para incluir los tests relevantes que sigan de forma natural el orden de las tareas de `instructions.md`.
**Evita usar `Fuzz`** en los tests de los ejercicios de concepto, ya que no se lleva bien con la posibilidad de depurar el código con `Debug.log`.
En su lugar, incluye algunos tests unitarios de casos límite y de casos generales.
**Evita usar expresiones `let` directamente bajo llamadas a las funciones `test` o `describe`** en los tests de los ejercicios de concepto, ya que [el test runner de elm todavía no lo admite](https://github.com/exercism/elm-test-runner/issues/30).

Cuando el ejercicio y los tests estén listos y funcionen bien, haz lo siguiente:

- Copia `src/<ExerciseSlug>.elm` a `.meta/Exemplar.elm`. Tu implementación sirve como referencia, una implementación «ejemplar» del ejercicio, que se usa al ejecutar los tests del track.
- Elimina todas las implementaciones dentro de `src/<ExerciseSlug>.elm` para quedarte con un archivo inicial listo para que el estudiante empiece el ejercicio.

## 8. Escribe la documentación del concepto

Crea un directorio `concepts/<concept>/` para el concepto asociado con nuestro ejercicio `exercises/concept/<story-name>`.
Dentro de esa nueva carpeta, creamos dos documentos markdown, [`introduction.md`][concept-intro-spec] y [`about.md`][concept-about-spec], y un archivo [`links.json`][concept-links-spec] (los enlaces llevan a sus especificaciones).

El archivo de concepto `introduction.md` contiene la presentación que los estudiantes verán en la página del concepto mientras no hayan completado el ejercicio de concepto asociado.
Debe darles una buena visión general de lo que aprenderán si empiezan el ejercicio asociado.
En cambio, el archivo de concepto `about.md` contiene el resumen del concepto que un estudiante verá en la página del concepto solo después de haber completado el ejercicio de concepto asociado.
Por eso su contenido es similar al del archivo `exercises/concept/<story-name>/.docs/introduction.md` que ya escribimos, pero no es el mismo.
Sugiero empezar por el documento de introducción del ejercicio y simplificarlo hasta su esencia para el archivo de concepto `introduction.md`.
Y para el documento `about.md`, empieza por la introducción del ejercicio y complétala de modo que toda la información relevante sobre el concepto esté presente en esa página.
`links.json` proporciona enlaces útiles con información adicional sobre un concepto.
Pueden ser documentación oficial, un buen tutorial, etc.
Estos enlaces no reemplazan los enlaces más contextuales dentro del archivo about.md de un concepto, sino que ofrecen un conjunto rápido de puntos de referencia generales para el estudiante.
Los enlaces también pueden tener un campo opcional icon_url, que sirve para personalizar el icono que se muestra con el enlace. Si no se especifica, el icono predeterminado es el favicon.
Puedes encontrar los iconos disponibles en [github.com/exercism/website-icons/tree/main/exercises][icons].

## 9. Completa los distintos archivos de configuración

Ahora que el código y la documentación están listos, solo quedan unos pocos archivos de configuración para completar este PR:

- [`concepts/<concept>/.meta/config.json`][concept-config-json]: hazte autor, agrega a posibles revisores como colaboradores y añade una «blurb» (descripción corta).
- [`exercises/concept/<story-name>/.meta/config.json`][exercise-config-json]: contiene los autores (tú), los colaboradores, la blurb y otras cosas. Consulta la especificación enlazada.
- `config.json`: agrega una [entrada de concepto][track-config-json-concept] y una [entrada de ejercicio de concepto][track-config-json-concept-exercise] en el archivo `config.json` del track. Usa «wip» o «beta» para la clave status del ejercicio de concepto. Los UUID se pueden generar con el [ejecutable configlet][configlet] que proporciona exercism.
