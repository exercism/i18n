# Acerca de

Ruby es un lenguaje dinámico y fuertemente tipado.
En los lenguajes dinámicos, el tipo de una variable o de un objeto se resuelve en tiempo de ejecución, lo que significa que su valor o su tipo pueden cambiar hasta el último momento (cuando el intérprete lo analiza).
¿Y qué queremos decir con fuertemente tipado?
Una vez que conocemos el tipo de una variable o de un objeto, Ruby es estricto con lo que puedes hacer con él, por ejemplo:

```ruby
x = '2'
y = x + 'n'
# => '2n'
```

**Pero**

```ruby
x = '2'
y = x + 2
# => TypeError (no implicit conversion of Integer into String)
```

Recuerda que en Ruby todo es un objeto.
Incluso las clases son instancias de la clase `Class`.

Por ejemplo:

```ruby
1.class
# => Integer

Integer.is_a?(Object)
# => true

Class.is_a?(Object)
# => true
```

Esto significa que también podemos definir clases así:

```ruby
Car = Class.new do
  def run
    'running'
  end
end

Car.new.run
# => 'running'
```

Por último, ten en cuenta que el objeto `Integer` contiene valores que pueden estar definidos por uno o más dígitos (consecutivos) y que sus métodos admiten muchos de los [operadores matemáticos][integers-docs].

[integers-docs]: https://docs.ruby-lang.org/en/master/Integer.html

~~~~exercism/note
En la documentación, es común que se haga referencia a los métodos de instancia con una sintaxis como `Class#method_name`, mientras que a los métodos de clase o de módulo se los referencia como `Class::method_name`.
El `::` se llama _Scope Resolution Operator_, y hace referencia a la constante o al método a nivel de clase o de módulo.
Te encontrarás con esto en la documentación de Ruby, y en listas de correo y otros espacios de ayuda.
En cambio, verás que en nuestros textos nos referimos a los métodos de clase y de módulo como `ClassName.method_name` o `ModuleName.method_name`.
~~~~
