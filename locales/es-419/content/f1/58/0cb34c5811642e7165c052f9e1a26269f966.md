### Introducción

¡Te damos la bienvenida al primer ejercicio del track de Java!

Este documento es una guía paso a paso para resolver este ejercicio.
Las instrucciones deberían funcionar igual de bien en Windows, macOS y Linux.

Aunque ya conozcas los conceptos básicos de Java, seguir esta guía puede serte útil: te ayudará a entender la salida de la herramienta Gradle, que usamos para compilar y probar nuestro código, y además te presentará algunos de los patrones comunes a todos los ejercicios de este track.

### Estructura del ejercicio

Cuando descargas un nuevo ejercicio de Java, recibes:

- __uno o más archivos de prueba__ (siempre).
Están en el directorio `src/test/java` y definen un conjunto de pruebas que nuestra solución debe cumplir antes de poder declarar con seguridad que funciona.
- __uno o más archivos de inicio__ (al principio).
Si se incluyen, están en el directorio `src/main/java` y definen esqueletos de las clases que necesitarás para resolver el problema actual.

### Resolviendo «Hello, World!»

Puedes usar nuestro editor en línea para trabajar en tu solución y ejecutar las pruebas, pero si quieres resolver el problema y ejecutar las pruebas de forma local, revisa estos enlaces:

- [Installing Java]
- [Working Locally]

### Paso 1: Corregir la solución

Ya sea que trabajes de forma local o uses el editor en línea, deberías encontrar el siguiente código:

```java
String getGreeting() {
    return "Goodbye, Mars!";
}
```

El objetivo es modificar el código que te damos para que produzca el texto `"Hello, World!"` en lugar de `"Goodbye, Mars!"`.

### Paso 2: Ejecutar las pruebas

Después de hacer las correcciones e implementar tu solución, ejecuta las pruebas de nuevo.
Puedes ejecutar las pruebas con el editor en línea o de forma local en tu computadora:

- Para ejecutar las pruebas en el editor en línea, haz clic en el botón «Run Tests».
- Para ejecutar las pruebas de forma local, consulta [Pruebas en el track de Java][Testing locally on the java track]. Si las pruebas fallan, ¡no pasa nada! Fíjate en lo que te dice el mensaje de error, cambia tu código y vuelve a probar; cuando tus pruebas pasen, continúa con el siguiente paso.

### Paso 3: Enviar tu primera iteración

Con una solución que funcione y que hayas revisado, ya puedes enviarla a exercism.org.
Puedes enviar la solución con el editor en línea o de forma local usando la [CLI de Exercism][Working Locally]:

- Para enviar el ejercicio de forma local, primero [instala la CLI de Exercism][Working Locally] si aún no lo has hecho y luego envía los archivos de tu solución, por ejemplo:

  ```sh
  exercism submit <file location>
  ```

- Reemplaza `<file location>` con la ubicación relativa de tu archivo `Greeter.java`; entonces, si trabajas en `C:\exercism\java\hello-world`, el comando sería

  ```sh
  exercism submit .\src\main\java\Greeter.java
  ```

- Si quieres usar el editor en línea para enviar tu solución, ¡solo haz clic en el botón «Submit»!

Para ver con más detalle cómo enviar una solución de forma local:

- [Enviar de forma local][Working Locally]

### Conviértete en mentor

El corazón de Exercism son las conversaciones sobre prácticas de programación.
Practicar es sin duda divertido, pero relacionarte con otras personas, tanto en sus intentos como en los tuyos, es la forma de recibir retroalimentación.
Esa retroalimentación puede ayudarte a ver qué estás haciendo bien y en qué podrías necesitar mejorar.

Algunas soluciones enviadas serán casi idénticas a la tuya y otras serán completamente diferentes.
Ver ambos tipos puede resultar instructivo e interesante.

Los mentores revisan las soluciones enviadas del track que eligieron mentorear para ayudar a las personas a aprender lo más posible.

Para leer más sobre la mentoría, ve a la [documentación de Exercism][Mentoring].
