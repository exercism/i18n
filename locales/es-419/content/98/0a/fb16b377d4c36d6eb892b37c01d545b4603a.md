# Pistas

## General

- Échale un vistazo a la [guía de Elm][elm-guide], que tiene un buen ejemplo resuelto muy similar.

## 1. Define los tipos Model y Msg de la aplicación, y escribe la función init

- El `Model` contiene el estado de la aplicación: todos los datos que la aplicación necesita.
- Debe ser un [registro][record].
- Esta aplicación solo necesita un `String` para guardar el texto del cuadro de texto (las pruebas requieren que se llame `content`).

- El tipo `Msg` define los mensajes que se pasan a la función update, para provocar cambios específicos en el modelo.
- Debe ser un [tipo personalizado][custom-type].
- Esta aplicación solo necesita un cambio en el modelo: actualizar el modelo cuando cambia el texto del cuadro de texto.

- La función `init` simplemente debe devolver un `Model` con un valor predeterminado razonable (las pruebas requieren un string vacío).

## 2. Escribe la función update

- En cualquier aplicación útil, la función update usa una sentencia `case` para hacer coincidencia de patrones sobre el parámetro `Msg`.
- En cada rama de la sentencia `case`, extrae del parámetro `Msg` la información que necesita y devuelve un `Model` actualizado.
- El `Model` debe ser un registro, y normalmente se usa la [sintaxis de actualización de registros][record-update-syntax].

## 3. Escribe la función view

- La función `view` debe devolver un `div` para el elemento raíz.
- El primer hijo debe ser un `input`, con un atributo `value` para el texto actual, y un atributo o evento `onInput` con la variante correspondiente de `Msg`.
- El segundo hijo debe ser otro `div` con un hijo `text` que indique si el texto es un palíndromo o no.

## 4. Escribe la función main

- La función main solo debe llamar a [`Browser.sandbox`][browser-sandbox].
- `Browser.sandbox` requiere un argumento de tipo [registro][record] con las funciones `init`, `update` y `view`.
