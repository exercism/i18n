# Introducción

Todos los errores en Elixir implementan el _Exception Behaviour_. Al igual que el _Access Behaviour_, el _Exception Behaviour_ define funciones de callback que un módulo debe implementar para cumplir con el contrato de software del comportamiento. Una vez que se define un error, tiene las siguientes propiedades:

- El nombre del módulo define el nombre del error.
- El módulo define un struct de error.
- El struct tendrá un campo `:message`.
- El módulo se puede usar con `raise/1` y `raise/2` para lanzar el error deseado.

El _Exception Behaviour_ también especifica dos callbacks: `message/1` y `exception/1`. Si no se implementan, se usarán las implementaciones predeterminadas. `message/1` transforma el struct de error en un mensaje legible cuando se llama con `raise`. `exception/1` permite agregar contexto adicional al mensaje cuando se llama con `raise/2`.

## Definir una excepción

Para definir una excepción a partir de un módulo de error, usamos la macro `defexception`:

```elixir
# Defines a minimal error, with the name `MyError`
defmodule MyError do
  defexception message: "error"
end

# Defines an error with a customized exception/1 function
defmodule MyCustomizedError do
  defexception message: "custom error"

  @impl true
  def exception(value) do
    case value do
      [] ->
        %MyCustomizedError{}

      _ ->
        %MyCustomizedError{message: "Alert: " <> value}
    end
  end
end
```

## Usar excepciones

Los errores definidos se pueden usar como un error integrado usando `raise/1` o `raise/2`.

- `raise/1` lanza un error específico por el nombre de su módulo o, si el argumento es un string, lanza un `RuntimeError` con el string como mensaje.
- `raise/2` lanza un error específico por el nombre de su módulo y acepta un argumento de atributos que se usa para obtener el error con el mensaje adecuado.
