# Constructores de string

`STR` es inmutable; `FSTR` no lo es. Usa `STR` para el texto que ya está terminado y `FSTR` para el texto que todavía se está construyendo.

```sather
   b ::= #FSTR;              -- empty
   b ::= #FSTR(256);         -- empty, with room for 256 characters
   b ::= #FSTR("Act I: ");   -- starting from a string
   b := b + "Enter";
   s ::= b.str;              -- a STR again
```

## Asigna siempre el resultado a la variable

```sather
   b := b + "Enter";         -- yes
   b + "Enter";              -- no: the answer is thrown away
```

`FSTR` crece por **duplicación amortizada**: cuando se queda sin espacio, toma un array nuevo y más grande, del doble de tamaño, y copia ahí. Así que el resultado suele ser el mismo objeto y, de vez en cuando, uno distinto. Escribir `b := b + x` cada vez es correcto en ambos casos, y es la única forma que vale la pena aprender.

La duplicación es lo que hace que el trabajo total sea proporcional a la longitud y no a su cuadrado: las copias se vuelven más raras a la misma velocidad con la que se vuelven más costosas.

## ¿Por qué no usar simplemente `+` con STR?

Unir una cantidad fija y pequeña de piezas con `+` es claro y está bien:

```sather
   return piece + " by " + composer;
```

El problema aparece solo en un bucle, donde la cantidad de uniones no se conoce cuando se escribe el código. Una guía aproximada: si el `+` está dentro de un `loop`, recurre a `FSTR`.

## Rutinas útiles

| Llamada | Qué hace |
| --- | --- |
| `b + x` | agrega; `x` puede ser `STR`, `CHAR`, `INT`, `BOOL` … |
| `b.size` | cuántos caracteres lleva hasta ahora |
| `b.str` | un `STR` ya terminado |
| `b.clear` | lo vacía y conserva el espacio |

## Secuencias de escape

| Se escribe | Es |
| --- | --- |
| `"\n"` | una línea nueva |
| `"\t"` | una tabulación |
| `"\""` | una comilla doble |
| `"\\"` | una barra invertida |
