# Iteradores personalizados

Has estado usando iteradores desde `bird-survey`. Ahora vas a escribir uno.

## yield

Un iterador se parece a una rutina con dos diferencias: su nombre termina en `!`, y entrega valores con `yield` en lugar de `return`.

```sather
   markers!(count : INT) : INT is
      loop
         yield 100 * 1.upto!(count);
      end;
   end;
```

`yield` le entrega un valor al bucle que llamó al iterador y después **espera**. Cuando ese bucle vuelve a dar la vuelta, el iterador continúa justo después del `yield`, con todo exactamente como lo dejó: sus variables, su propio bucle, su posición.

Eso es un iterador: una rutina que puede hacer una pausa a la mitad y reanudarse después.

```sather
   loop
      #OUT + TRAIL::markers!(3) + " ";      -- 100 200 300
   end;
```

## Cómo termina

Un iterador termina de una de dos maneras.

**Se agota.** Cuando el propio bucle del iterador termina, o la rutina llega a su final, se acabó, y el bucle que lo llamó termina de inmediato.

**quit.** `quit` lo termina ahí mismo, sin entregar nada.

```sather
   named!(names : ARRAY{STR}) : STR is
      loop
         name ::= names.elt!;
         if name = "" then quit; end;
         yield name;
      end;
   end;
```

Eso entrega nombres hasta que se topa con uno vacío y se detiene. `quit` es para un iterador lo que `return` es para una rutina, salvo que no lleva ningún valor: ya no queda nada que entregar.

## once

Un argumento marcado con `once` se calcula una sola vez, cuando el bucle comienza, en lugar de en cada vuelta:

```sather
   markers!(once count : INT) : INT is
```

Úsalo para todo lo que no cambia entre vueltas, que es la mayoría de los argumentos. Los propios iteradores de la biblioteca lo hacen: `upto!(once i : SAME)`.

## Iteradores sin valor

Un iterador no necesita entregar nada. `times!` es uno:

```sather
   steps!(once count : INT) is
      loop
         ignored ::= 1.upto!(count);
         yield;
      end;
   end;
```

Un `yield` a secas no entrega nada y simplemente deja que el bucle dé una vuelta.

## Dónde se guarda la posición

Cada *lugar del programa* que llama a un iterador conserva su propia posición, y por eso llamar dos veces al mismo iterador dentro del cuerpo de un bucle lo recorre dos veces. Ahora ya ves por qué: las dos llamadas son dos rutinas pausadas distintas.
