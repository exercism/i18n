# Acerca de los chars

¡Este puede ser un tema _enorme_!
Es posible escribir un libro largo sobre él, y varias personas ya lo han hecho (busca «unicode book» en Amazon para ver algunos ejemplos).

## Una historia muy breve

Manejar caracteres en las computadoras era mucho más sencillo en décadas anteriores, cuando quienes programaban asumían que el inglés era el único idioma importante.
Así que: 26 letras, mayúsculas y minúsculas, 10 dígitos, varios signos de puntuación, más un código (0x07) para hacer sonar una campana, y todo cabía en 7 bits: el conjunto de caracteres [ASCII][wiki-ascii].

Naturalmente, la gente empezó a preguntar qué pasaba con à, ä y Ł, luego otras personas empezaron a preguntar por ऄ, ஹ y ญ, y los jóvenes querían emojis 😱.
¿Qué hacer?

Para resumir una larga historia, muchas personas inteligentes y pacientes tuvieron que formar parte de comités durante años, definiendo los detalles del conjunto de caracteres [Unicode][web-unicode] y de codificaciones como [UTF-8][wiki-utf-8], y muchísimo software necesitó una reescritura _muy_ complicada.
Además, se introdujeron un montón de bugs nuevos.

Para evitar que _todo_ se rompiera, el diseño de Unicode/UTF-8 garantiza que los primeros 127 códigos sean idénticos a ASCII _(incluso la campana)_.

## Los caracteres en Kotlin

Los lenguajes diseñados después de 2005 aproximadamente tienen la enorme ventaja de que ya existía un estándar Unicode razonablemente estable.

Kotlin (publicado por primera vez en 2011) pudo asumir que sus usuarios usarían una variedad de idiomas (humanos) y que necesitarían Unicode para expresarlos.

~~~~exercism/advanced
Los [caracteres][ref-char] en Kotlin son [`codepoints`][wiki-codepoint] de 16 bits (UTF-16), igual que un `char` de la JVM.
Esto alcanza para expresar la mayoría de los alfabetos escritos, pero no toda la gama de emojis.

El estándar Unicode completo usa hasta seis bytes (48 bits) por carácter (a lo que se llama [`grapheme`][wiki-grapheme]).

Los `Strings` de Kotlin admiten este estándar completo usando varios codepoints por carácter, cuando es necesario.
Por ejemplo, 😱 serían `\uD83D` y `\uDE31`.

Lamentablemente, Java no tiene soporte de graphemes incorporado y, por compatibilidad, Kotlin tampoco.

[wiki-codepoint]: https://en.wikipedia.org/wiki/Code_point
[wiki-grapheme]: https://en.wikipedia.org/wiki/Grapheme
[ref-char]: https://kotlinlang.org/docs/characters.html
~~~~


Los literales de carácter se escriben entre comillas simples y son distintos de los strings escritos entre comillas dobles.
Esto probablemente sea obvio para quienes vienen del mundo de C/C++, pero puede confundir a quienes programan en Python y JavaScript.

```kotlin
val a = 'a'
a::class.qualifiedName  // => kotlin.Char
a.code  // => 97

val jha = 'झ'  // Devanagari alphabet
jha.code  // => 2333

val heart = '❤'  // heart emoji
heart.code  // => 10084

Char.MAX_VALUE.code // => 65535 (64k, the largest code point allowed)

val not_char = 'abc' // => Too many characters in a character literal.
```

Convertir entre `Char` e `Int` es sencillo:

```kotlin
a.code  // => 97
Char(97) // => 'a'
```

El compilador permite _algunas_ formas de aritmética de enteros con `Char`:

```kotlin
'a' + 5     // => 'f'
'c' - 'a'   // => 2
'c' + 'a'   // => error!

'f' + ('A' - 'a')  // => 'F' (same as 'f'.uppercase()

'f'.dec() // => 'e' (decrement)
'f'.inc() // => 'g' (increment)
```

## Algunas funciones para `Char`

Como siempre, hay [demasiadas funciones][ref-char-lib] para analizarlas aquí, así que esta es solo una selección.

- Para los alfabetos adecuados, cambia las mayúsculas y minúsculas con [`uppercase()`][ref-uppercase] y [`lowercase()`][ref-lowercase].
- Comprueba el uso de mayúsculas o minúsculas con [`isUpperCase()`][ref-isuppercase] y [`isLowerCase()`][ref-islowercase].
- Comprueba el tipo de carácter con:
  - [`isLetter()`][ref-isletter], abarca muchos alfabetos (las categorías Lu, Ll, Lt, Lm y Lo de Unicode)
  - [`isDigit()`][ref-isdigit], en el rango 0..9 (la categoría Nd de Unicode)
  - `isLetterOrDigit()`, combina las dos anteriores
  - [`isWhitespace()`][ref-iswhitespace], cualquier carácter de espacio en blanco (las categorías Cc, Zp, Zl y Zs de Unicode)

```kotlin
'झ'.isLetter()      // => true
'A'.isLowerCase()   // => false
'4'.isDigit()       // => true
'\t'.isWhitespace() // => true  (tab character)
```

Además, las [expresiones regulares][ref-regex] (que serán el tema de un concepto posterior) permiten búsquedas y manipulaciones potentes.

## Conversiones entre listas de `Char` y `String`

Para convertir un `String` en una `List` de `Char`, podemos usar `toList()`.

Para convertir una `List` de `Char` en un `String`, existe la función [`joinToString()`][ref-jointostring], que recibe un separador (a menudo el string vacío) como argumento.

```kotlin
val kt = "kotlin".toList()  // => [k, o, t, l, i, n]
kt.joinToString("")   // => "kotlin"
kt.joinToString("_")  // => "k_o_t_l_i_n"
```

Ten en cuenta que `joinToString()` opera sobre una List o un Array.
Para _convertir_ un solo `Char` en un string de un carácter, usa `toString()`.

```kotlin
'a'.toString() // => "a"
```

Para comprobar si un carácter está presente en un `String`, o en una lista o array de `Char`, tenemos `in`, que se corresponde con la función [`contains()`][ref-contains].

```kotlin
val clist = "kotlin".toList()  // => [k, o, t, l, i, n]
't' in clist     // => true
't' in "kotlin"  // => true
```
