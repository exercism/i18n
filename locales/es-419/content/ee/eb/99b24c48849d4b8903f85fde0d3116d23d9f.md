# Acerca de

En un concepto anterior, se mencionó que tanto las etiquetas locales como las funciones son solo direcciones en una sección con código ejecutable, como `section .text`.

De hecho, las funciones se pueden manipular de la misma manera que cualquier dirección de memoria, es decir, se pueden cargar en registros, pasar de un lugar a otro y almacenar en memoria.
También es posible usar `call` o `jmp` para transferir la ejecución a una función almacenada en un registro o en memoria:

```x86asm
section .text
sum_op:
    lea rax, [rdi + rsi] ; loads the sum rdi + rsi into rax
    ret

apply_sum:
    lea rax, [rel sum_op]
    jmp rax              ; tail call
```

Una dirección de función que se pasa como un valor se llama [thunk][thunk].
Los thunks son un bloque de construcción de la [programación de orden superior][higher-order] en lenguaje ensamblador: código que opera sobre otro código.

## Código como datos

Las direcciones de funciones también se pueden almacenar en memoria y recuperar más tarde:

```x86asm
section .bss
    cached_fn resq 1

section .text
save_op:
    mov qword [rel cached_fn], rdi
    ret

apply_op:
    ; arguments are already set up according to the ABI
    jmp qword [rel cached_fn] ; tail call
```

`save_op` escribe la dirección de la función que recibe en `cached_fn`.
El valor persiste después de que `save_op` devuelve, así que cualquier llamada posterior a `apply_op` hace un salto de cola a la dirección que se haya almacenado por última vez.
Esto hace posible cambiar a qué función llama `apply_op` en tiempo de ejecución.

## Tablas de despacho

Almacenar direcciones de funciones en un array hace posible seleccionar diferentes funciones según algún índice, que posiblemente dependa de una condición en tiempo de ejecución.
Esto se llama [tabla de despacho][dispatch-table]:

```x86asm
section .data
    dispatch_table dq add_op, sub_op, mul_op

section .text
dispatch:
    ; this function takes two arguments in rdi and rsi, and an index in rdx
    ; it then applies the function corresponding to the index in rdx to the arguments
    lea rax, [rel dispatch_table]
    jmp qword [rax + 8*rdx]  ; tail-call the function address for the index
```

## Thunks con estado

Un thunk que lee o actualiza alguna memoria persistente entre llamadas puede comportarse de manera diferente según lo que haya ocurrido antes.
Su resultado puede depender de más que solo sus argumentos.

Por ejemplo, un _contador_ que toma una función y la llama con la cuenta actual, incrementando la cuenta cada vez:

```x86asm
section .data
    count dq 0

section .text
tick:
    mov rax, rdi               ; saves the function address
    mov rdi, [rel count]       ; loads the current count as the function's argument
    inc qword [rel count]      ; advances the count
    jmp rax                    ; tail-calls the function
```

`tick` llama a la función dada con la cuenta actual como su argumento, luego incrementa la cuenta.
Así, una primera llamada `tick(square)` llama a `square(0)`, la siguiente llamada `tick(square)` llama a `square(1)`, la siguiente `square(2)`, y así sucesivamente.

Otro ejemplo sería una _computación retrasada_:

```x86asm
section .bss
    captured_fn resq 1
    argument resq 1

section .text
delay:
    mov qword [rel captured_fn], rdi ; saves the function
    mov qword [rel argument], rsi    ; saves the argument
    lea rax, [rel invoke]            ; returns the `invoke` function
    ret

invoke:
    mov rdi, qword [rel argument]    ; loads the saved argument into `rdi`
    jmp qword [rel captured_fn]      ; tail-calls the saved function
```

`delay` toma una función y un valor, los almacena, y devuelve `invoke`.
Cuando se llama a `invoke`, ejecuta la función capturada con el argumento guardado.

Muchos de los patrones comunes en lenguajes de alto nivel, como callbacks, métodos virtuales, generadores, currificación, composición de funciones y muchos otros, se basan en thunks combinados con estado persistente.
