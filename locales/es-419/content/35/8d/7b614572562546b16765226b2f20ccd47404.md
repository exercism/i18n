# Usa especificaciones de tipo

[comment]: # (This warning is raised when the solution doesn't have a type specification)

Incluye [especificaciones de tipo](https://elixir-lang.org/getting-started/typespecs-and-behaviours.html#types-and-specs) (`@spec`) para comunicar el contrato que hay entre los argumentos de una función y el valor que devuelve.

- Elixir es un lenguaje con tipado dinámico, lo que significa que las comprobaciones de tipos solo ocurren en tiempo de ejecución. El uso de especificaciones de tipo permite que los linters y el análisis estático como [`Dialyxir`](https://hexdocs.pm/dialyxir/readme.html) (basado en [`Dialyzer`](http://erlang.org/doc/man/dialyzer.html) de Erlang) evalúen el código en busca de comportamientos no deseados.
- Puedes encontrar una [lista completa](https://hexdocs.pm/elixir/typespecs.html#basic-types) de todos los tipos integrados en la [documentación del lenguaje](https://hexdocs.pm/elixir/typespecs.html#content)
- los tipos se pueden especificar con o sin paréntesis: `atom()` frente a `atom`
  - el estilo de Exercism para Elixir es especificar sin paréntesis.

```elixir
# Example 1
@spec add_one(int) :: int
def add_one(n) when is_integer(n) do
  n + 1
end

# Example 2
@spec hello(String.t) :: String.t
def hello(what \\ "world") when is_binary(what) do
  "Hello, #{what}"
end
```
