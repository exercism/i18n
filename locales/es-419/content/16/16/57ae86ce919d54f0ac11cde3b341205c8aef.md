# Anexo de instrucciones

## Proceso de Node

A diferencia de otros ejercicios, `grep.js` _no_ se importa dentro del archivo de pruebas `grep.spec.js`. En su lugar, se usará como si fuera un ejecutable. Para facilitarlo, el archivo `grep.js` se ha configurado con un shebang y un comentario que explica qué hace esto:

```javascript
#!/usr/bin/env node

// The above line is a shebang. On Unix-like operating systems, or environments,
// this will allow the script to be run by node, and thus turn this JavaScript
// file into an executable. In other words, to execute this file, you may run
// the following from your terminal:
//
// ./grep.js args
//
// If you do not have a Unix-like operating system or environment, for example
// Windows without WSL, you can use the following inside a window terminal,
// such as cmd.exe:
//
// node grep.js args
//
// Read more about shebangs here: https://en.wikipedia.org/wiki/Shebang_(Unix)
```

Las pruebas iniciarán un nuevo _proceso_ de node que ejecuta `grep.js`.

## Leer los argumentos

Para obtener los argumentos con los que se inició el _proceso_, usa `process.argv`.

## Leer archivos

La función `readLines` ya está incluida. No necesitas transformar la ruta del archivo para usarla. La función `readlines` _resolverá_ la ruta desde el directorio de trabajo actual, que, para los procesos de `grep.js`, está establecido en el directorio del ejercicio.

## Escribir la salida

Para escribir la salida, usa

- `console.log` para escribir en el flujo de salida estándar;
- `console.error` para escribir en el flujo de error estándar.

Las pruebas consideran que la ejecución fue exitosa (resuelta) si no se escribe nada en el flujo de error estándar, y no exitosa (rechazada) si se escribe algo en el flujo de error estándar.
