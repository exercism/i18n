# Acerca de

El tipo `Result` es la solución que ofrece el lenguaje Elm para reportar y recuperar errores. Se parece un poco al tipo `Maybe`, pero mientras que el `Nothing` de `Maybe` codifica algún tipo de fallo, no te dice nada sobre _por qué_ falló. `Result` incluye un contexto sobre por qué falló algo.

## Definición y variable de tipo

El tipo `Result` se define de la siguiente manera:

```elm
type Result error value
  = Ok value
  | Err error
```

En pocas palabras, este tipo codifica el resultado de una operación que puede tener éxito y devolver un `value`, o fallar y devolver una explicación del fallo (`error`).

En la terminología de Elm, esto se conoce como una definición de «tipo personalizado». Los tipos personalizados se presentan con más detalle en otro concepto de este track, pero no los necesitamos para entender específicamente `Result`. El `error` y el `value` en `OK value` y `Error error` representan una variable de tipo, lo que significa que pueden ser de cualquier tipo, como `Int`, `Bool` o `String`. Así, un `Result String Int` es una variable que se espera que contenga un `Int` y, si hay un error, este se representará como un `String`.

```elm
ageFromString : String -> Result String Int
ageFromString input =
  case String.toInt input of
    Nothing ->
      Err "That is not a number!"

    Just age ->
      if age < 0 then
        Err "Please try again after you are born."

      else if age > 135 then
        Err "Are you some kind of turtle?"

      else
        Ok age
```

## Leer el contenido de un valor Result

Leer el contenido de un valor `Result` se hace mediante «pattern matching». El pattern matching también se presenta con más detalle en otro concepto, así que nos centramos solo en cómo funciona el pattern matching de un `Result`.

```elm
formatAge : Int -> String
formatAge age =
    "You are " ++ toString(age)

howOldAmI : String -> String
howOldAmI age =
    case ageFromString age of
        Err message -> message
        Ok age -> formatAge age

howOldAmI "Bananas"
    --> "That is not a number!"

howOldAmI "32"
    --> "You are 32"
```

Cada vez que usas un valor `Result`, el compilador de Elm verifica que tu código maneje todas las posibilidades, así que nunca puedes hacer pattern matching de un `Result` y manejar solo el caso en el que hay un `Ok value`. Esto puede parecer molesto al principio, pero es una de las mayores fortalezas del lenguaje Elm. Esto evita cientos de bugs y hace que la refactorización guiada por el compilador sea una experiencia sin miedo y gratificante.

## Manipular el contenido de un valor Result

Existen varias funciones para trabajar con tipos `Result`, que normalmente son preferibles al pattern matching. `Result.map` se puede usar para mapear el valor, y `Result.andThen` se puede usar para encadenar funciones que pueden fallar.

Result.map se usa para cambiar el valor Ok y es útil para encadenar funciones sin tener que preocuparte por si el Result contiene un error o no. Si el valor es Ok, Result.map llama a la función encadenada (`formatAge` a continuación), pero si hay un error, Result.map no hace nada y simplemente devuelve el error.

```elm
howOldAmI : String -> Result String String
howOldAmI age =
    Result.map formatAge (ageFromString age)

howOldAmI "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.map just returns the Err)

howOldAmI "32"
    --> Ok "You are 32" (ageFromString returns Ok 32, Result.map passses this to formatAge)
```

Result.andThen se usa para cambiar el valor Ok y es útil para encadenar funciones sin tener que preocuparte por si el Result contiene un error o no. Es similar a Result.map, pero Result.andThen trabaja con una función encadenada (`formatSpecialBirthday` a continuación) que también devuelve un Result. `Result.map` también puede hacerlo, pero termina con una capa extra de anidamiento, que `andThen` evita con ingenio.

```elm
formatSpecialBirthday : Int -> Result String String
formatSpecialBirthday age =
    if age == 18 then
        Ok "Welcome to adulthood!"

    else if age == 65 then
        Ok "Welcome to retirement!"

    else
        Err "Not a special birthday"

specialBirthdayMessage : String -> Result String String
specialBirthdayMessage age =
    Result.andThen formatSpecialBirthday (ageFromString age)

specialBirthdayMessage "Bananas"
    --> Err "That is not a number!" (ageFromString returns Err, so Result.andThen just returns the Err)

specialBirthdayMessage "32"
    --> Err "Not a special birthday" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Err)

specialBirthdayMessage "18"
    --> Ok "Welcome to adulthood" (ageFromString returns Ok 32, Result.map passses this to formatSpecialBirthday, which returns Ok)
    --> If we used Result.map, it would be OK (Ok "Welcome to audulthood"), which is annoying
```
