# Acerca de

En C#, el [literal `null`][null-keyword] se usa para denotar la ausencia de un valor. Un _tipo anulable_ es un tipo que admite valores `null`.

Antes de C# 8.0, los tipos de referencia siempre eran anulables y los tipos de valor no. Sin embargo, un [tipo de valor se puede volver anulable][nullable-value-types] agregándole un signo de interrogación (`?`).

```csharp
string nullableReferenceType = "hello";
nullableReferenceType = null; // Valid as type is nullable

int nonNullableValueType = 5;
nonNullableValueType = null; // Compile error as type is not nullable

int? nullableValueType = 5; // Define nullable value type
nullableValueType = null;   // Valid as type is nullable
```

Acceder a un miembro de una variable cuyo valor es `null` compila sin problema, pero hace que se lance una `NullReferenceException` en tiempo de ejecución:

```csharp
string sentence = "What a nice day!";

// Throws NullReferenceException at runtime
sentence.Length;
```

Para contrarrestar este tipo de error tan común, C# 8 permite [activar una característica][nullable-csharp-8] que hace que los [tipos de referencia no sean anulables de forma predeterminada][nullable-reference-types]:

```csharp
string nonNullableReferenceType = "book";
nonNullableReferenceType = null; // Compile warning (no error!)

string? nullableReferenceType = "movie";
nullableReferenceType = null; // Valid as type is nullable
```

Para [trabajar de forma segura con valores anulables][nullable-types-tutorial], conviene verificar si son `null` antes de trabajar con ellos:

```csharp
string NormalizedName(string? name)
{
    if (name == null)
    {
        return "UNKNOWN";
    }
    else
    {
        // Value is not null at this point, so no compile warning
        // and no runtime NullReferenceException being thrown
        return name.ToUpper();
    }
}

NormalizedName(null); // => "UNKNOWN"
NormalizedName("Elisabeth"); // => "ELISABETH"
```

El [operador `??`][null-coalescing-operator] permite devolver un valor predeterminado cuando el valor es `null`:

```csharp
string? name1 = "John";
name1 ?? "Paul"; // => "John"

string? name2 = null;
name2 ?? "George"; // => "George"
```

El [operador `?.`][null-conditional-operator] permite llamar a miembros de forma segura en un valor que posiblemente sea `null`:

```csharp
string? fruit = "apple";
fruit?.Length; // => 5

string? vegetable = null;
vegetable?.Length; // => null
```

Si el compilador cree que un valor podría ser `null` pero tú sabes que no lo será, puedes usar el [operador `!.`][null-forgiving-operator] para suprimir la advertencia. Sin embargo, usa este operador solo como último recurso.

```csharp
void PrintName(string? name)
{
    // Assume that the IsValid() method only return true
    // when its argument is not null
    if (IsValid(name))
    {
        // No compile warning
        Console.WriteLine(name!.Length);
    }
}
```
