# Estructuras

Las estructuras reúnen un conjunto fijo y heterogéneo de datos en una sola unidad. Las estructuras en Rust tienen estas propiedades:

- Cada tipo de estructura tiene un nombre particular.
- Cada miembro de una estructura se llama **campo**.
- Cada campo de una estructura tiene un nombre particular.
- La visibilidad se controla a nivel de campo: cada campo puede ser público, privado u otro, de forma independiente[^1].

# Panorama de las estructuras

Las estructuras se definen con la palabra clave `struct`, seguida del nombre del tipo que describe la estructura.
Después del nombre pueden venir llaves (para una estructura estándar), paréntesis (para una estructura de tupla) o un punto y coma (para una estructura unitaria).

```rust
struct Item {}
```

Luego se incorporan tipos adicionales al cuerpo de la estructura como _campos_ de la estructura, cada uno con su propio tipo:

```rust
struct Item {
    name: String,
    weight: f32,
    worth: u32,
}
```

Por último, se pueden definir métodos en las estructuras dentro de un bloque `impl`:

```rust
impl Item {
    // initializes and returns a new instance of our Item struct
    fn new() -> Self {
        todo!()
    }
}
```

# Variedades de estructuras

Las estructuras vienen en tres variantes: estructuras con campos con nombre (estructuras estándar), estructuras de tupla y estructuras unitarias.

Las estructuras se parecen mucho a las **tuplas**. De hecho, la única diferencia entre estructuras y tuplas tiene que ver con qué es anónimo. La forma general es así:

- Las estructuras tienen nombre y tienen campos con nombre:

  ```rust
  struct Foo {
      bar: Bar,
      bat: Bat,
  }
  ```

  Se accede a los campos por su nombre:

  ```rust
  let bar = foo.bar;
  ```

- Las estructuras de tupla tienen nombre y tienen campos anónimos:

  ```rust
  Foo(Bar, Bat)
  ```

  Se accede a los campos mediante desempaquetado o por índice numérico:

  ```rust
  // unpacking
  let (bar, bat) = foo;
  ```

  ```rust
  // numeric index
  let bar = foo.0;
  let bat = foo.1;
  ```

- Las tuplas son anónimas y tienen campos anónimos:

  ```rust
  (Bar, Bat)
  ```

  Al igual que en las estructuras de tupla, se accede a los campos mediante desempaquetado o por índice numérico.

- Las estructuras anónimas son, como su nombre lo indica, anónimas, pero con campos con nombre. Puede que las conozcas de otros lenguajes, como Go o Java. No existen en Rust; se considera idiomático usar una tupla en su lugar.

# Tipos de tamaño cero

Las estructuras pueden tener tantos campos como se requiera, o tan pocos. Esto implica que es válido que una estructura tenga cero campos. Una estructura con cero campos se llama **tipo de tamaño cero** y el compilador la trata de forma especial: los tipos de tamaño cero (a menudo abreviados como **ZST**) nunca consumen espacio en la pila ni en el heap, incluso cuando podrías esperar que lo hicieran. Por ejemplo, `Box<T>` no reserva memoria en el heap si `T` es un ZST.

Puedes usar la sintaxis de estructura estándar o de estructura de tupla cuando escribas un ZST:

```rust
// declaration
struct Foo {}
// instantiation
let foo = Foo {}
```

```rust
// declaration
struct Foo();
// instantiation
let foo = Foo();
```

También hay una forma abreviada para los ZST:

```rust
// declaration
struct Foo;
// instantiation
let foo = Foo;
```

Por lo general, cuando escribes un ZST, se prefiere la forma abreviada, ya que no puedes mezclarlas: el estilo que hayas usado para declarar un ZST[^2] es el mismo estilo que se requiere para instanciarlo.

Después de toda esta explicación sobre la sintaxis de los ZST, hablemos de por qué querrías algo así. Un ZST no puede almacenar datos, pero es excelente para implementar traits.

---

[^1]: [Estos documentos](https://doc.rust-lang.org/reference/visibility-and-privacy.html) explican algunas opciones de visibilidad menos usadas.
[^2]: Este es un caso particular de una regla general: el estilo que se use para declarar cualquier tipo de estructura es el mismo estilo que se requiere para instanciarla.
