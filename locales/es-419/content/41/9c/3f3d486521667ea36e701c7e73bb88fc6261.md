# Introducción

Los `Complex numbers` no son complicados.
Solo necesitan un nombre menos alarmante.


Son tan útiles, sobre todo en la ingeniería y la ciencia, que Python incluye [`complex`][complex] como un tipo numérico estándar, junto con los enteros ([`int`s][ints]) y los números de punto flotante ([`float`s][floats]).


Un valor `complex` en Python es esencialmente un par de números de punto flotante:

```python
>>> my_complex = 5.443+6.77j
(5.443+6.77j)
```

A estas se las llama la parte «real» y la «imaginaria».
Puede que hayas oído que «`i` (o `j`) es la raíz cuadrada de -1».
Por ahora, todo esto significa que la parte imaginaria _por definición_ cumple la igualdad `1j * 1j == -1`.
Es una idea simple, pero lleva a consecuencias matemáticas interesantes.

En Python, la parte «imaginaria» se designa con `j` (_no `i` como verías en los libros de matemáticas_), y
la `j` debe ir inmediatamente después de un número, para evitar que Python la interprete como el nombre de una variable:


```python
>>> j
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
NameError: name 'j' is not defined

>>> 1j
1j

>>> type(1j)
<class 'complex'>
```


Hay dos maneras comunes de crear números complejos.

1) El constructor [`complex(real, imag)`][complex] toma dos parámetros `float`:

    ```python
    >>> z1 = complex(1.5, 2.0)
    >>> z1
    (1.5+2j)
    ```

    El constructor también puede analizar una entrada de tipo string.
    Tiene la curiosa limitación de que falla si el string contiene espacios.

    ```python
    >>> complex('4+2j')
    (4+2j)
    
    >>> complex('4 + 2j')
    Traceback (most recent call last):
      File "<stdin>", line 1, in <module>
    ValueError: complex() arg is a malformed string
    ```


2) El número complejo se puede especificar como el literal `<real part> + <complex part>j`, o solo `<complex part>j` si la parte real es cero:


    ```python
    >>> z2 = 2.0 + 1.5j
    >>> z2
    (2+1.5j)
    ```
    El resultado final es idéntico al de usar el constructor `complex()`.


## Aritmética

La mayoría de los [`operators`][operators] que se usan con números de punto flotante y enteros también funcionan con números complejos.

La división entera _**no**_ es posible con números complejos, así que los operadores `//` y `%` y la función `divmod()` fallarán con el tipo de número complejo.

Explicar las reglas para la multiplicación y la división de números complejos está fuera del alcance de este concepto (_y es poco probable que tengas que hacer esas operaciones «a mano» muy seguido_).

Cualquier introducción [matemática][math-complex] o de [ingeniería eléctrica][engineering-complex] a los números complejos cubrirá estos escenarios, si quieres profundizar en el tema.

La biblioteca estándar de Python tiene un módulo [`math`][math-module] lleno de funcionalidad útil para trabajar con números reales, y el módulo [`cmath`][cmath] es su equivalente para trabajar con números complejos.
