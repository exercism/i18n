# Pruebas

Cada ejercicio incluye las pruebas unitarias y una receta de compilación de CMake. La implementación la aportas tú.
Cada archivo de pruebas está pensado para enlazarse con tu implementación y producir así un ejecutable de consola que ejecuta las pruebas. Al ejecutar el ejecutable de pruebas, se imprimen mensajes por cada prueba que falla y se informa un estado de salida distinto de cero cuando las pruebas fallan.

El archivo de pruebas tendrá el nombre `<exercise>_test.f90`, así que para el ejercicio «Bob» el archivo que contiene las pruebas es `bob_test.f90`. Cada prueba tendrá un comentario que describe la prueba y después la prueba en sí, que empieza con `call assert_equal`, por ejemplo.

```
  ! Test 16: non-letters with question
  call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Para desactivar una prueba, basta con comentarla con un `'!'`, por ejemplo.

```
  ! Test 16: non-letters with question
  ! call assert_equal("Sure.", hey(":) ?"), "non-letters with question")
```

Avanzar por cada ejercicio es un proceso que consiste en:

- Crear la compilación inicial con CMake
- Repetir estos pasos hasta que todas las pruebas pasen:
  - Corregir los errores de compilación y después ejecutar las pruebas para ver cuáles fallan.
  - Implementar lo justo y necesario para que pase la siguiente prueba que falla.
  - Refactorizar tu implementación para mejorar la legibilidad, reducir la duplicación, etc.
  - Ejecutar las pruebas de nuevo y pasar a la siguiente prueba que falla.

## Crear la compilación inicial con CMake

Cada ejercicio trae un archivo `CMakeLists.txt` junto con las pruebas unitarias. Contiene la receta predefinida de CMake que se encarga de la compilación por ti. No deberías necesitar editar este archivo. La receta incluida da por sentado que tu implementación existe en un archivo fuente con el nombre del ejercicio.

Por ejemplo, el ejercicio «Bob» espera una implementación en el archivo `bob.f90`.

Se incluye una plantilla de este archivo con el ejercicio, lista para que la completes.

Con esta receta, CMake puede generar un proyecto adecuado para tu entorno si ejecutas `cmake -G` con un generador adecuado y la ubicación del directorio del ejercicio. CMake generará un script de compilación apropiado para tu sistema operativo. Para mantener esos archivos generados separados del código fuente del ejercicio, es común crear un directorio llamado `build` que contenga tanto esos archivos de compilación generados como el código compilado.

Así mantendrás la carpeta del ejercicio ordenada y limpia.

**Nota:** la primera vez que se llama a `cmake`, el [testlib](#testlib) se descargará automáticamente. El `testlib` es necesario para que funcionen las pruebas unitarias.

Como vas a ejecutar CMake para crear las instrucciones de compilación de cada ejercicio, quizás quieras crear un script de bash (Linux/MacOS) o un archivo por lotes (Windows) para este comando.

Una vez que CMake haya creado el entorno de compilación, puedes compilar tu código con el comando adecuado para tu entorno:

- Linux con make: `make`
- Windows con Visual Studio: selecciona Build / Build Solution en el menú.
- Windows con MingW: `mingw32-make.exe`
- Windows con nMake: `nmake.exe`
- MacOS con Xcode: selecciona Build en la barra de herramientas.

A continuación se muestran ejemplos de cómo ejecutar CMake en distintos entornos.

### Linux\MacOS con Make

El nombre del generador para CMake es `Unix Makefiles`.
Suponiendo que el ejercicio actual es `bob` y que estás en la carpeta del ejercicio:

```
$ mkdir build
$ cd build
$ cmake -G "Unix Makefiles" ..
$ make
```

Ejecuta `make` en el directorio build para compilar tu solución y las pruebas.
Si hay errores de compilación, corrígelos y ejecuta `make` de nuevo.
Cuando la compilación se complete correctamente, ejecuta las pruebas:

```
$ ctest -V
```

### Windows con Visual Studio 2017

El nombre del generador para CMake es `Visual Studio 15`. El mismo generador admite todas las ediciones del IDE de Visual Studio 2017: Community, Professional y Enterprise. Suponiendo que el ejercicio actual es `bob` y que estás en la carpeta del ejercicio:

```
> mkdir build
> cd build
> cmake -G "Visual Studio 15" ..
```

### Windows con MingW

El nombre del generador para CMake es `MinGW Makefiles`. Suponiendo que el ejercicio actual es `bob` y que estás en la carpeta del ejercicio:

```
> mkdir build
> cd build
> cmake -G "MinGW Makefiles" ..
```

Ejecuta `mingw32-make` en el directorio build para compilar tu solución y las pruebas.
Si hay errores de compilación, corrígelos y ejecuta `mingw32-make` de nuevo.
Cuando la compilación se complete correctamente, ejecuta las pruebas:
```
> ctest -V
```

### MacOS con Xcode

El nombre del generador para CMake es `Xcode`.
Suponiendo que el ejercicio actual es `bob` y que estás en la carpeta del ejercicio:

```
$ mkdir build
$ cd build
$ cmake -G Xcode ..
```

Ejecuta `cmake --build .` en el directorio build para compilar tu solución y las pruebas.
Si hay errores de compilación, corrígelos y ejecuta `cmake --build .` de nuevo.
Cuando la compilación se complete correctamente, ejecuta las pruebas:

```
$ ctest -V
```

### Testlib

Las pruebas dependen de una pequeña biblioteca llamada `testlib`, que se descarga de GitHub la primera vez que se configura la compilación con cmake.

Si la descarga falla, elimina la carpeta `testlib` si existe (puede contener archivos vacíos) y descarga los archivos manualmente, por ejemplo.

```
mkdir testlib
cd testlib
wget https://raw.githubusercontent.com/exercism/fortran/main/testlib/CMakeLists.txt
wget https://raw.githubusercontent.com/exercism/fortran/main/testlib/TesterMain.f90
```
