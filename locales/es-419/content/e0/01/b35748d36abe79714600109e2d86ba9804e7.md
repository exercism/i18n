# Acerca de

El tipo `Result` permite que una función devuelva un único valor que indique todas estas cosas:
- Si la operación tuvo éxito o falló
- Si tuvo éxito, el valor resultante de la operación
- Si falló, el motivo del fallo

En otros lenguajes de programación que no admiten algo como un tipo `Result`, es común encontrar los siguientes patrones para lograr los objetivos mencionados:
- Una función que devuelve un código numérico que indica el éxito o el motivo del fallo y que requiere un parámetro de salida para recibir el valor cuando la operación tiene éxito.
- Una función que devuelve el valor cuando tiene éxito o NULL cuando hay un error, y luego otra función para obtener el código de error que indica el motivo del fallo.

Otro mecanismo común para manejar errores es la excepción, que sale de forma abrupta de la función actual y
transfiere el control al primer manejador de la pila de llamadas cuando ocurre un fallo.  
Si ningún manejador «atrapa» la excepción, el programa se cancela.

## Beneficios de usar el tipo `Result`

* __Seguridad en tiempo de compilación__: al hacer explícito en el sistema de tipos el éxito o el fallo de una llamada a una función, el compilador puede asegurarse de que el código que llama maneje todos los casos de fallo, lo que evita una gran categoría de errores que podrían ocurrir con valores nulos.

* __Seguridad en tiempo de ejecución__: en lugar de usar `null`, el tipo `Result` usa `Error` para representar un fallo, lo que hace imposible que ocurra una `NullReferenceException`.

* __Manejo explícito de errores__: el código que llama a una función que devuelve un `Result` debe reconocer que la
llamada puede fallar; el código que llama debe manejar esos fallos de forma intencional.  No hay fallos silenciosos ni excepciones sorpresa.

* __Flujo de control predecible__: un `Result` se devuelve como cualquier otro valor; no salta fuera de la pila de llamadas como una excepción.  Siempre sabes de dónde vienen los errores y cómo se propagan.

* __Mejor legibilidad y mantenibilidad__: al devolver un `Result`, la firma de una función indica claramente el comportamiento esperado en caso de éxito y de fallo.

## Uso

El tipo `Result` es un tipo genérico que contiene dos tipos subyacentes:
- El tipo del valor resultante en una operación exitosa
- El tipo que representa el motivo del fallo cuando este ocurre

El tipo `Result` también es una [unión discriminada][discriminated-union] con los siguientes casos posibles:
* `Ok <value>` que representa un resultado exitoso
* `Error <reason>` que representa un fallo

La siguiente función muestra cómo crear un valor `Result`:

```fsharp
let validateName (name: string) : Result<string, string> = 
    match name with
    | null -> Error "Name not found."
    | "" -> Error "Name is empty."
    | _ -> Ok name
```

En este ejemplo, el valor `Ok` es un string (el nombre dado), y el valor `Error` también es un string (la causa del error, en formato legible para humanos).

## Leer el contenido de un valor `Result`

Considera la siguiente definición de tipo y firma de función:

```
type FileOpenError = 
| NotFound
| AccessDenied
| FileLocked

let openFile (filename: string) : Result<int, FileOpenError> =
```

El código que llama a la función `openFile` puede usar la coincidencia de patrones para manejar los casos de éxito y de fallo, como en el siguiente ejemplo:

```fsharp
match openFile(filename) with
| Ok handle -> doSomethingWithFile(handle)
| Error NotFound -> printfn $"Error: file {filename} was not found."
| Error AccessDenied -> printfn $"Error: you do not have permission to open the file {filename}."
| Error FileLocked -> printfn $"Error: file {filename} is already in use."
```
