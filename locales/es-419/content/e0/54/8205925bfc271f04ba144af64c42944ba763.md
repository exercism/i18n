# Notas sobre los signos de agrupación

Tcl es un [lenguaje muy sencillo](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm), pero la forma en que el intérprete analiza el código tiene un par de casos límite bastante complicados.

## Llaves

Las llaves en Tcl son simplemente una manera de citar un bloque de texto: ese texto puede interpretarse como código o como datos. Dentro de las llaves pueden aparecer llaves anidadas, pero las llaves anidadas deben estar balanceadas. La página de manual de Tcl dice lo siguiente:

> Las llaves se anidan dentro de la palabra: por cada llave de apertura adicional debe haber una llave de cierre adicional (sin embargo, si una llave de apertura o de cierre dentro de la palabra _está escapada con una barra invertida_, entonces no se cuenta al ubicar la llave de cierre correspondiente).

La redacción ahí es bastante específica: si quieres tener un carácter de llave de apertura o de cierre sin pareja, este debe estar escapado con una barra invertida. Así que no hagas esto:
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "{"}]
    # ......................^ will not work
}
```
Debes hacer esto
```tcl
proc isOpenBrace {char} {
    return [expr {$char eq "\{"}]
    # ......................^^ will work
}
```

Esto puede dar problemas por la forma en que Tcl analiza los comentarios, que es distinta de la de la mayoría de los lenguajes. Hay más discusión al respecto en la [wiki de Tcl](https://wiki.tcl-lang.org/page/Why+can+I+not+place+unmatched+braces+in+Tcl+comments).

## Corchetes

De manera similar, dado que Tcl usa los corchetes para la [sustitución de comandos.](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M11), incluso dentro de strings entre comillas dobles, debes tener cuidado al escapar los corchetes de apertura.

## Paréntesis

Con la excepción de las [variables de array asociativo](https://tcl.tk/man/tcl8.6/TclCmd/Tcl.htm#M12), los paréntesis son simplemente caracteres comunes.
