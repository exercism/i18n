# Introducción

Las tuplas pueden extender otras tuplas. `TUPLE: child < parent slots ;`
declara una clase cuyas instancias también son instancias de `parent`:
heredan los slots del padre además de los suyos propios, y los accesores
del padre también funcionan en ellas, como si se hubieran definido en la
clase hija.

```factor
USING: accessors ;

TUPLE: animal name age ;
TUPLE: dog < animal breed ;

"Rex" 4 "labrador" dog boa .
! => T{ dog { name "Rex" } { age 4 } { breed "labrador" } }

"Rex" 4 "labrador" dog boa name>> .   ! => "Rex"   (inherited accessor)
```

## Orden de los slots en `boa`

El constructor `boa` recibe los slots en *orden de declaración, primero
los padres*. Para el `dog` de arriba:

```
dog boa ( name age breed -- dog )
```

Un nieto `puppy < dog ` que añada `weeks` sería:

```
puppy boa ( name age breed weeks -- puppy )
```

## Jerarquía de predicados

Cada declaración `TUPLE:` genera un predicado (`name?`).
Con la herencia, los predicados se anidan; todo descendiente
cumple los predicados de sus ancestros:

```factor
"Rex" 4 "labrador" dog boa
dup dog? .        ! => t
dup animal? .     ! => t
```

Lo contrario no se cumple: un `animal` que no es un `dog` no pasa
`dog?`.

## Nota para más adelante

Los métodos genéricos (`M:`, que se enseñan en [`generics`][generics])
también se despachan hacia arriba por la jerarquía: un método definido en
`animal` se ejecuta para todos sus descendientes, a menos que una
sobrescritura más específica tenga prioridad. Lo verás en
`boatswains-bilge` justo después de este ejercicio.

[generics]: https://docs.factorcode.org/content/article-generic.html
