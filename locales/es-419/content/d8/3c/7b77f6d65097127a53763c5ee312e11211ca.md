# Introducción

## Comentarios

Common Lisp le permite a quien programa escribir «comentarios» que la computadora ignora.
Los comentarios de una sola línea comienzan con uno o más puntos y coma (`;`) y, de vez en cuando, puedes ver lo siguiente:

```lisp
(code...) ; => value
```

Donde el comentario se usa para indicar qué valor devuelve Common Lisp después de ejecutar el código de esa línea.

Es idiomático usar un solo punto y coma para un comentario corto al final de una línea, dos para un comentario más largo encima de una sección de código, tres para un comentario largo que describe algo como una función y cuatro para un comentario como un encabezado en la parte superior de un archivo fuente.

## Cons

Todos los objetos de Common Lisp son «átomos» (valores únicos e indivisibles) o «conses» (construidos por la función constructora «cons»).
Un cons se compone de dos partes: el primer elemento y el resto de los elementos.
Por razones históricas, estas dos partes se llaman el `car` y el `cdr`.
Cuando estos conses se evalúan como código, el primer elemento (`car`) representa la función que se llama, mientras que el resto de los elementos
(`cdr`) representan los argumentos de esa función:

```lisp
(<function> <arg1> <arg2> ... <argN>)
; ^ car ^  |        ^ cdr ^
```

## Expresiones

Todo el código de Common Lisp está hecho de S-Expressions (expresiones simbólicas). Para abreviar, se llaman sexprs. Cada sexpr es un átomo o un cons. Cuando se evalúan las S-Expressions, automáticamente devuelven un valor que ocupa el lugar de la expresión. Cuando escribes tus propias funciones (usando `defun`), el último valor dentro del cuerpo del `defun` se devuelve automáticamente:

```lisp
;; Defining a new function
(defun gimme-foo () 'foo)
;; Calling the function as an S-Expression
(gimme-foo) ; => FOO
```

## Símbolos

Los símbolos en Common Lisp son valores especiales que pueden apuntar a otros valores o, en el caso de las _palabras clave_, a sí mismos.
Cuando Lisp evalúa los símbolos, estos se reemplazan con los valores a los que apuntan:

```lisp
foo  ; => <whatever-foo-points-to>
:foo ; => :FOO
```

Ten en cuenta que las palabras clave se denotan con dos puntos (`:`) al principio.

La cita, es decir, agregar `'` antes de una S-Expression, le indica a Lisp que no evalúe esa expresión.
Al citar `'foo` en nuestro ejemplo de `defun`, evitamos que Lisp intentara buscar (y no encontrara) aquello a lo que se supone que apunta `FOO`; en lugar de eso, devuelve el valor `FOO` en sí mismo.
Si `FOO` no se ha definido en ninguna parte de nuestro programa:

```lisp
foo  ; => <ERROR! Lisp doesn't know what foo points to!>
'foo ; => FOO
```

Por ahora, puedes considerar esto simplemente como una forma de devolver símbolos desde una función, pero volveremos a tratar la cita y exploraremos más a fondo sus implicaciones en futuros ejercicios de concepto.
