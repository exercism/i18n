# Acerca de

[Elixir](https://elixir-lang.org/), publicado por primera vez en 2012, amplía las ya robustas características de Erlang y, además, es más fácil de acceder, leer, probar y escribir para quienes recién empiezan.

José Valim, el creador de Elixir, explica [en su charla de 2012](https://vimeo.com/53221562) cómo construyó el lenguaje para que las aplicaciones fueran:

  1. Distribuidas
  2. Tolerantes a fallos
  3. Casi en tiempo real
  4. Con cambio de código en caliente (puede introducir código nuevo sin detener el servidor)

En realidad, Elixir se compila a [bytecode](https://en.wikipedia.org/wiki/Bytecode) y luego se ejecuta en la [máquina virtual Erlang BEAM](https://codesync.global/media/robert-virding-co-creator-of-erlang-explains-the-beam/).

No hay un «costo de conversión» por llamar a Erlang, lo que significa que puedes ejecutar código Erlang justo al lado de código Elixir.

Como es un lenguaje funcional, todo en Elixir es una expresión.

Elixir cuenta con «documentación de primera clase», lo que significa que los comentarios se pueden adjuntar a una función, lo que hace que sea más fácil de recuperar.

Las expresiones regulares también reciben un tratamiento de primera clase, lo que elimina el engorroso escapado dentro de los strings.

La implementación de comunicación asíncrona de Elixir permite que el código sea ligero y, aun así, incorpore una concurrencia de gran volumen.

Quienes programan usan Elixir para manejar miles de solicitudes y respuestas *de forma concurrente* en un solo nodo de servidor.

Se ha usado con éxito en microservicios que necesitan consumir y servir una multitud de APIs rápidamente.

El [framework Phoenix](https://www.phoenixframework.org/) ayuda a estructurar aplicaciones Elixir para la web.
