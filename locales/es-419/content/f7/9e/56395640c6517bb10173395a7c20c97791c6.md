# Flujos de trabajo

GitHub Actions usa el concepto de _flujos de trabajo_, que son scripts que se ejecutan automáticamente cada vez que ocurre un evento específico (por ejemplo, al hacer push de un commit).

Cada flujo de trabajo de GitHub Actions se define en un archivo `.yml` dentro del directorio `.github/workflows`.
Para obtener más información sobre los flujos de trabajo, consulta la siguiente documentación:

- [Sintaxis de los flujos de trabajo](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions)
- [Elegir cuándo se ejecuta tu flujo de trabajo](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/triggering-a-workflow)
- [Elegir dónde se ejecuta tu flujo de trabajo](https://docs.github.com/en/actions/writing-workflows/choosing-where-your-workflow-runs)
- [Elegir qué hace tu flujo de trabajo](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does)
- [Escribir flujos de trabajo](https://docs.github.com/en/actions/writing-workflows)
- [Buenas prácticas](/docs/building/github/gha-best-practices)

## Flujos de trabajo compartidos

Algunos flujos de trabajo se comparten entre repositorios.

```exercism/caution
Los flujos de trabajo compartidos se sincronizan automáticamente (desde el [repositorio org-wide-files](https://github.com/exercism/org-wide-files/)).
Por lo tanto, no deberías cambiar su contenido manualmente.
```

### Flujos de trabajo generales

- [Sincronizar etiquetas](/docs/building/tracks/ci/workflows/sync-labels): sincroniza las etiquetas del repositorio a partir de un archivo

### Flujos de trabajo específicos del track

- [configlet](/docs/building/tracks/ci/workflows/configlet): comprueba si los archivos (de configuración) del track están bien estructurados, tanto sintáctica como semánticamente
- [Ningún archivo importante ha cambiado](/docs/building/tracks/ci/workflows/no-important-files-changed): comenta en los pull requests que provocarían que se vuelvan a probar las soluciones existentes
- [Prueba](/docs/building/tracks/new/setup-continuous-integration#h-test-workflow): verifica los ejercicios del track

### Flujos de trabajo específicos de las herramientas

- [Despliegue](/docs/building/tracks/ci/workflows/deploy): despliega la imagen Docker de las herramientas del track en Docker Hub y ECR

### Flujos de trabajo opcionales

También hay algunos flujos de trabajo que los tracks pueden activar de forma opcional:

- [Pausar las contribuciones de la comunidad](/docs/building/tracks/ci/workflows/pause-community-contributions): comenta automáticamente en los issues y PRs nuevos creados por usuarios que no son miembros de la organización de Exercism en GitHub

## Flujos de trabajo personalizados

Los mantenedores pueden agregar flujos de trabajo personalizados a sus repositorios sin problema.
Algunos ejemplos de estos flujos de trabajo podrían ser:

- Etc.
