# Introducción

## Tipos personalizados

Los [tipos personalizados][custom-types] en Elm representan un número fijo de casos con nombre. Cada valor corresponde exactamente a uno de los casos nombrados.

Un tipo personalizado se define con la palabra clave `type` y requiere muy poca sintaxis. Son una de las técnicas más importantes en la programación con Elm, y se usan para hacer que los valores posibles en el código coincidan exactamente con los valores válidos en la vida real, lo que no deja lugar a datos inválidos y hace que [los estados imposibles sean imposibles de representar en el código][impossible-states].

```elm
type Season
    = Spring
    | Summer
    | Autumn
    | Winter
```

Cada caso de un tipo personalizado puede tener datos asociados de forma opcional, y diferentes casos pueden tener diferentes tipos de datos. Si ninguno de los casos tiene datos asociados, la unión discriminada es similar a lo que en otros lenguajes suele llamarse una _enumeración_ (o _enum_).

```elm
type FlexibleNumber
    = Integer Int
    | Float Float
    | Invalid
```

Puedes crear un valor para un caso específico refiriéndote a su nombre (`Spring`), cuando está definido en el mismo módulo, o se importa con la sintaxis `import SeasonModule exposing (Season(..))`, o refiriéndote a su nombre totalmente cualificado (`Season.Spring`) cuando se importa con la sintaxis `import SeasonModule exposing (Season)`.

```elm
integerTwo = Integer 2
invalid = FlexibleNumber.Invalid
```

Los tipos personalizados, al igual que todo en Elm, tienen _igualdad estructural_, lo que significa que dos valores para el mismo caso y con los mismos datos (opcionales) son equivalentes.

La forma preferida de trabajar con tipos personalizados es con la [coincidencia de patrones][pattern-matching]:

```elm
let describe flexibleNumber =
    case flexibleNumber of
        Integer i ->
            "Integer: " ++ fromInt(i)

        Float f ->
            "Float: " ++ fromFloat(f)

        Invalid   ->
            "Invalid"
```
