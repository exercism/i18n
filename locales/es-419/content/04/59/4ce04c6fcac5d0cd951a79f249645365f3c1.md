# Guía para analizadores

Este documento ofrece orientación para cuando implementes un analizador.

## General

- Analiza _todos_ los archivos enviados, excepto los archivos de tests, invalidator, editor, example y exemplar.
- No busques una corrección del 100 %, porque sería casi imposible de lograr.
  Está bien si el analizador no encuentra todos los problemas o no logra inferir ciertas etiquetas.

## Compilación

Si tu lenguaje requiere un paso de compilación, ten en cuenta estos puntos:

- Compilar la solución normalmente permite una mayor fidelidad.
  Por ejemplo, el tipo definitivo de cualquier valor solo se conoce _después_ de compilar.
  Eso sí, ten presentes las contrapartidas (por ejemplo, se ejecuta más lento y consume más memoria).
- Considera la compilación en memoria (si es posible) para mejorar el rendimiento.

## Pruebas

- Ten un conjunto de pruebas amplio.
- Usa pruebas golden para verificar el comportamiento del analizador.
  Estas pruebas deberían usar la imagen de Docker que se desplegará para verificar el analizador.
- Considera tener pruebas para cada enfoque.
  Quieres que el analizador funcione bien con estas soluciones, y además te ayudará a asignar etiquetas a los enfoques más adelante.
