# Mutabilidad

La mutabilidad es una propiedad de un enlace particular en Rust. Un enlace es inmutable o mutable. El valor de un enlace inmutable no se puede cambiar; el valor de un enlace mutable sí se puede cambiar. Todos los enlaces son inmutables por defecto.

## Enlaces

Un enlace es la asociación entre un nombre de variable particular tal como aparece en el código fuente y una región de memoria particular tal como aparece durante la ejecución. En sentido estricto, los enlaces solo existen durante la compilación: antes de la compilación no hay memoria realmente asignada, y después de la compilación, el código máquina trata exclusivamente con direcciones de memoria en lugar de variables con nombre.

Los enlaces se suelen crear con la palabra clave `let`. Además, los enlaces se crean a partir de parámetros de función y en ciertas otras circunstancias.

Los enlaces pueden tener varias propiedades, de las cuales la más importante es la mutabilidad. Un enlace mutable es aquel para el que es legal cambiar el valor de la memoria enlazada. Rust rastrea y aplica estrictamente la mutabilidad de cada enlace para ayudar a garantizar que los programas sean correctos, rechazando los programas que intentan incorrectamente modificar un enlace que debería ser inmutable.

## Mutabilidad

En la práctica, la mutabilidad a menudo es simple. Al usar la palabra clave `mut` en la definición del enlace, obtienes la capacidad de cambiar el valor.

```rust,ignore
let x = 1;
// this does not compile because `x` is immutable
x = 2;
```

```rust
let mut x = 1;
x = 2;
// 🎉🎆🎉🎆🎉
```

### Degradar de mutable a inmutable

Un enlace siempre se puede degradar de mutable a inmutable. Esta operación es transparente.

```rust
fn debug(n: i32) {
    dbg!(n);
}

fn main() {
    let mut x = 1;
    x += 2;
    debug(x);                // emits "n = 3"
}
```

### Promover de inmutable a mutable

En general, es posible promover un valor de inmutable a mutable cada vez que se transfiere la propiedad.

```rust
let x = "hello".to_string();
let mut y = x;               // (1)
y += ", world";
dbg!(y);
```

En `(1)`, la propiedad del string se transfiere de `x` a `y`, lo que nos permite promover el valor a mutable.

### Mutabilidad en parámetros de función

Hay dos formas diferentes de que los parámetros de función sean mutables. El primer método, más común, se parece al paso por referencia en C:

```rust
fn increment(n: &mut i32) {  // (1)
    *n += 1;
}

fn main() {
    let mut x = 1;           // (2)
    increment(&mut x);       // (3)
    dbg!(x);                 // emits "x = 2"
}
```

En este ejemplo, la mutabilidad se anotó explícitamente en tres lugares. Las tres declaraciones de mutabilidad son necesarias para que funcionen las referencias mutables.
En `(2)`, el enlace `x` se declara como mutable. Este enlace es el propietario de nivel superior del valor.
En `(3)`, ese valor se toma prestado de forma mutable, para pasarlo a la función `increment`.
En `(1)`, se crea un nuevo enlace mutable `n` a la referencia adecuada.

Hay otro estilo de mutabilidad de parámetros, que es menos común pero a veces sigue siendo útil. En este estilo, el valor se posee, pero el enlace es mutable.

```rust
fn increment_internally(mut n: i32) {   // (1)
    n += 1;
    dbg!(n);                            // emits "n = 2"
}

fn main() {
    let x = 1;                          // (2)
    increment_internally(x);            // (3)
    dbg!(x);                            // emits "x = 1"
}
```

Este ejemplo requiere menos anotaciones explícitas porque en realidad es una transferencia de propiedad con promoción de mutabilidad incorporada. Funciona porque `i32` es un tipo `Copy` que copia datos de forma transparente.
En `(1)` declaramos que `increment_internally` acepta un `i32` mutable poseído llamado `n` como su parámetro.
En `(2)` declaramos que `x` es un enlace inmutable al valor `1`.
En `(3)` `x` se copia a una nueva ubicación en memoria. `x` permanece inmutable. `n` es mutable.

Por supuesto, es posible combinar las formas, dando un enlace mutable a una referencia mutable (`mut n: &mut i32`, etc.), pero rara vez es lo que realmente se desea.

### Mutabilidad sin `let`

Varias construcciones en Rust (`if let`, `match`, etc.) también pueden crear enlaces. Estos enlaces también pueden ser mutables.

```rust
fn maybe_increment(n: &mut Option<i32>) {
    if let Some(ref mut n) = n {
        *n += 1;
    }
}

fn main() {
    for mut v in [Some(1), None] {
        maybe_increment(&mut v);
        dbg!(v);
    }
}
```

Este ejemplo produce primero `v = Some(2)`, luego `v = None`.

## Shadowing

Es posible, y a menudo idiomático, reutilizar el nombre de una variable a medida que un valor particular se transforma, redeclarándola con múltiples invocaciones de `let`. Esto se conoce como shadowing.

```rust
let s = "my string";
let s = s.to_uppercase();
dbg!(s);                               // emits "s = MY STRING"
let s = s.split_whitespace().count();
dbg!(s);                               // emits "s = 2"
```

Sin embargo, este no es un caso de mutabilidad; los valores originales en principio siguen presentes. Dados tipos que no son `Drop`, el compilador puede optar por mutar una ubicación de memoria en lugar de asignar una nueva. Sin embargo, nunca hará esto con un tipo `Drop` o si el enlace antiguo se vuelve a usar.

```rust
let x = 1;

// creating a scope like this forces bindings created internally to drop
// when the scope is exited
{
    let x = 10;
    dbg!(x);                   // emits "x = 10"
}

dbg!(x);                       // emits "x = 1"
```
