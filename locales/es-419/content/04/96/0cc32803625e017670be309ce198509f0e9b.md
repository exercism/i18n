# Generadores de tests

El track de C# usa un [generador de tests](https://exercism.org/docs/building/tooling/test-generators) para generar automáticamente los tests de los ejercicios de práctica.
Aprovecha que la mayoría de los ejercicios definidos en el [repositorio problem-specifications](https://github.com/exercism/problem-specifications/) también tienen un archivo `canonical-data.json`, que contiene entradas y salidas de prueba estandarizadas que se pueden usar para implementar el ejercicio.

## Pasos

Para generar los tests de un ejercicio de práctica, el generador de tests:

1. Lee los casos de prueba del ejercicio desde su archivo `canonical-data.json`
2. Usa el archivo `tests.toml` para omitir y excluir casos de prueba
3. Renderiza los casos de prueba usando la plantilla del generador del ejercicio
4. Formatea la plantilla renderizada usando Roslyn
5. Escribe la plantilla formateada en el archivo de tests del ejercicio

### Paso 1: leer el archivo `canonical-data.json`

El generador de tests parsea los casos de prueba del `canonical-data.json` del ejercicio usando el [espacio de nombres System.Text.Json](https://learn.microsoft.com/en-us/dotnet/api/system.text.json).

Como algunos datos canónicos usan anidamiento, el caso de prueba parseado incluye un campo `path` adicional que contiene las propiedades `description` de cualquier elemento padre, además de la propiedad `description` del propio caso de prueba.

### Paso 2: omitir los tests excluidos del archivo `tests.toml`

Cada ejercicio tiene un archivo `tests.toml`, en el que se pueden excluir o deshabilitar tests individuales.
El generador de tests eliminará cualquier caso de prueba marcado como excluido (`include = false`).

### Paso 3: renderizar los casos de prueba

Los casos de prueba (potencialmente transformados) se pasan luego al archivo `.meta/Generator.tpl`, que define cómo deben renderizarse los tests a partir de esos casos de prueba.

### Paso 4: formatear la plantilla renderizada usando Roslyn

La plantilla renderizada se formatea luego con [Roslyn](https://github.com/dotnet/roslyn).
Esto tiene las siguientes ventajas:

- Los ejercicios se formatean de manera consistente
- No necesitas preocuparte mucho por los espacios en blanco y la alineación al escribir plantillas

### Paso 5: escribir la plantilla renderizada en el archivo de tests del ejercicio

Por último, la salida de la plantilla renderizada se escribe en el archivo de tests del ejercicio.

## Plantillas

Las plantillas se renderizan con la [biblioteca Scriban](https://github.com/scriban/scriban/).

## Interfaz de línea de comandos

Hay dos formas de ejecutar el generador de tests:

1. `bin/update-tests.ps1`: actualiza los tests de todos los ejercicios que tengan una plantilla de generador
2. `bin/update-tests.ps1 -e <slug>`: actualiza los tests del ejercicio especificado, si tiene una plantilla de generador
