# Introducción

Un **bucle** es una secuencia de instrucciones que se ejecuta potencialmente más de una vez, hasta que se cumple una condición de finalización.

En x86-64, un bucle normalmente se crea con un salto a una etiqueta anterior:

```x86asm
example_loop:
    ...
    jmp example_loop
```

Ten en cuenta que un salto incondicional a una etiqueta anterior siempre transferirá la ejecución a esa etiqueta.
Esto significa que el bucle seguirá repitiéndose para siempre, a menos que haya otro salto hacia fuera de la secuencia repetida.

Por ejemplo, este bucle no termina:

```x86asm
infinite_loop:
    inc rax
    jmp infinite_loop ; always jumps to 'infinite_loop', repeating 'inc rax' forever
```

Y este bucle puede terminar, dependiendo de si se cumple la condición:

```x86asm
maybe_finite_loop:
    cmp rax, 1
    je out_of_loop ; jumps to 'out_of_loop' if rax == 1, breaking the loop

    inc rax
    jmp maybe_finite_loop ; always jumps to 'maybe_finite_loop'
out_of_loop:
    ...
```

## Bucles con contador

Un bucle con contador casi siempre termina de la misma manera: una instrucción que actualiza un contador o compara dos valores, seguida inmediatamente por un salto condicional que decide si dar otra vuelta.

```x86asm
sum_array:
    ; rdi is the memory address of an array
    ; rsi is the number of elements in the array

    mov eax, 0           ; running total
.loop:
    add rax, qword [rdi] ; add the current element
    add rdi, 8           ; advance to the next element
    sub rsi, 1           ; one fewer element to process, setting ZF at zero
    jnz .loop            ; repeat while the counter is not yet zero
    ret
```

~~~~exercism/note
`cmp rsi, 0` no es necesario en el código anterior porque `sub rsi, 1` ya establece el `zero flag (ZF)` cuando el resultado es `0`.

Aunque `cmp` es la principal forma de comprobar condiciones en ensamblador, muchas instrucciones actualizan las banderas.
Por ejemplo, muchas instrucciones aritméticas con enteros o de manipulación de bits actualizan `ZF` cuando el resultado es `0`, y `SF` cuando el resultado es negativo (es decir, el bit más alto está establecido).

Puedes consultar una [referencia][reference] para ver qué banderas se ven afectadas por cada instrucción.

[reference]: https://www.felixcloutier.com/x86/
~~~~

Ten en cuenta que en el ejemplo anterior se supone que `rsi` es mayor que `0`.
Si fuera `0`, entonces `sub rsi, 1` reduciría `rsi` a `-1`, que es un número sin signo muy grande.
Harían falta `18,446,744,073,709,551,615` iteraciones más antes de que el bucle finalmente terminara.
Además, como la longitud del array es `0`, cualquier acceso a memoria quedaría fuera de los límites.

Si no hay garantías sobre la longitud de un array, hay dos enfoques comunes.

El primero consiste en mover la condición de finalización al comienzo del bucle y luego tener un salto incondicional al final:

```x86asm
sum_array:
    mov eax, 0
.loop:
    cmp rsi, 0
    je .done
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jmp .loop
.done:
    ret
```

El segundo consiste en comprobar una vez si el array tiene longitud cero antes del comienzo del bucle:

```x86asm
sum_array:
    mov eax, 0

    cmp rsi, 0
    je .done
.loop:
    add rax, qword [rdi]
    add rdi, 8
    sub rsi, 1
    jnz .loop
.done:
    ret
```

Este segundo enfoque suele ser más eficiente que el primero, porque hay menos ramificaciones en el cuerpo del bucle.
Aprenderás más sobre esto en un concepto futuro.

~~~~exercism/advanced
En algunas situaciones, los procesadores modernos pueden fusionar dos instrucciones diferentes en una sola operación.
Esta optimización se llama **macrofusion**.

Muchas instrucciones aritméticas como `sub` y `add`, así como `cmp` y `test`, comúnmente se fusionan con un salto condicional que sigue justo después.
Esto significa que una instrucción como `cmp rax, rdx`, seguida inmediatamente por un salto condicional, normalmente puede ser tratada por la CPU como una sola operación.

La macrofusion depende de la CPU y hay cierta variación en qué instrucciones se fusionan con qué salto condicional.

Una referencia útil es [The microarchitecture of Intel, AMD, and VIA CPUs, by Agner Fog][agner-uarch].
La sección 3.4.2.2 (Optimizing for Macrofusion) del [Intel optimization reference manual][intel-opt] también enumera pares fusibles para las CPU Intel.

[agner-uarch]: https://www.agner.org/optimize/microarchitecture.pdf
[intel-opt]: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf
~~~~
