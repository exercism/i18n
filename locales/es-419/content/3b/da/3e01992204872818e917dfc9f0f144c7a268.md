# Inclusión de código

```sather
   include WARM_UP;
   include WARM_UP count -> warm_up_count;
   include WARM_UP describe -> ;
   include WARM_UP count -> beats, describe -> ;
```

Un `include` copia el código de otra clase dentro de esta. Es una
operación en tiempo de compilación sin costo en tiempo de ejecución y sin
relación en tiempo de ejecución: las dos clases no quedan conectadas
después.

## La cláusula

```
   include CLASS  old_name -> new_name , old_name -> ;
```

Cada entrada renombra una característica. `-> ;` sin un nombre nuevo la deja fuera.
Todo lo que no se menciona entra sin cambios.

El renombrado se aplica a lo que ve el exterior. Las llamadas entre las
rutinas incluidas siguen funcionando: si `describe` llama a `count` y `count`
se renombra a `beats`, `describe` llama a `beats`.

## Incluir varias

```sather
   include WARM_UP;
   include COOL_DOWN;
```

está permitido, y así es como Sather obtiene lo que otros lenguajes llaman
herencia múltiple, sin los problemas habituales, porque un conflicto es un
error de compilación y la solución es renombrar o dejar una fuera. Nada se
resuelve mediante un orden de precedencia que tengas que memorizar.

## private include

```sather
   private include WARM_UP;
```

incorpora el código para uso propio de esta clase sin exponerlo. Útil cuando
quieres la implementación y no la interfaz.

## Los dos juntos

La forma habitual para una familia de clases:

```sather
abstract class $ACT is
   name : STR;
   minutes : INT;
end;

class ACT_BASICS is
   minutes : INT is return 5; end;
end;

class JUGGLING < $ACT is
   include ACT_BASICS;
   name : STR is return "Juggling"; end;
end;
```

`< $ACT` dice qué puede hacer; `include ACT_BASICS` aporta parte del cómo.
Si cambias de opinión sobre el cómo, el `<` no se mueve.

## Por qué se hace así

Una clase abstracta no tiene código, así que no se puede heredar de ella por
accidente, y no existe algo como una superclase cuyo comportamiento cambie
bajo tus pies. La reutilización es una copia tomada en tiempo de compilación,
de una clase que nombraste, con cada renombrado escrito.

El costo es que la reutilización debe pedirse explícitamente en cada clase.
Ese es el intercambio: más que escribir, nada implícito.
