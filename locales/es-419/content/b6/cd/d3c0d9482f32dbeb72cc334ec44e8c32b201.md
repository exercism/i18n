# Instalar Factor

El track de Factor usa **Factor 0.101**. Las versiones anteriores no son compatibles.

Puedes instalar una compilación [estable](#stable) o [nightly](#nightly), o [compilar desde el código fuente](#build-from-source).

Verifica tu instalación ejecutando `factor -e='vm-version print'`: debería imprimir `0.101` o una versión superior.

---
### Estable

<https://factorcode.org#stable-release> ofrece compilaciones estables en la sección «Stable release».

---
### Nightly

<https://factorcode.org#development-release> ofrece compilaciones nightly en la sección «Development release». Estas compilaciones se generan a partir de git, pero solo se muestran las que pasan.

---
### Compilar desde el código fuente

Si quieres lo más reciente y hasta nightly es demasiado antiguo para ti, vas a necesitar un compilador de C++ moderno (GCC >=4.8 o Clang >=3.5), `make` y `curl`.

Con esos sencillos requisitos cumplidos, puedes:

1. Descarga el script de shell `build`: [**aquí** para sistemas tipo Unix / shells POSIX](https://raw.githubusercontent.com/factor/factor/master/build.sh) o [**aquí** para Windows](https://raw.githubusercontent.com/factor/factor/master/build.cmd). Ponlo en el directorio donde se debe instalar Factor. Se creará un directorio llamado `factor` que contendrá el código fuente.

2. Ejecútalo como `./build.sh install`, o `.\build.cmd install` en Windows. <sub>Esto clonará el repositorio `git` de Factor, lo compilará y descargará una imagen de la VM de Factor desde <https://factorcode.org>. Este proceso puede tardar entre 2 y 20 minutos, según tu conexión y la velocidad de tu procesador.</sub>

3. Ya puedes ejecutar el binario `factor` o `factor.exe` generado dentro del subdirectorio `factor`. Prueba `factor --help` para obtener ayuda. También puedes consultar la documentación desde la línea de comandos, o presionando <kbd>F1</kbd> en el GUI Listener, lo que abrirá el navegador de ayuda.

4. En el futuro, usa `build.sh` o (`build.cmd` en Windows) dentro del subdirectorio `factor` para traer los cambios desde git y recompilar en el mismo lugar, y descargar una nueva imagen de la VM si es necesario.

La estructura de archivos ahora puede verse así:

```
.
├── build.sh                   <- delete if you like
└── factor
    ├── basis
    ├── boot.unix-x86.64.image
    ├── build.cmd              <- use these from now on
    ├── build.sh               <-
    ├── core
    ├── extra
    ├── factor
    ├── Factor.app
    ├── factor.image
    ├── GNUmakefile
    ├── libfactor.a
    ├── libfactor-ffi-test.so
    ├── LICENSE.txt
    ├── misc
    ├── Nmakefile
    ├── README.md
    ├── unmaintained
    ├── vm
    └── work
```

Ya no necesitas el script `build` de nivel superior, porque en el futuro deberías usar el que descargaste.

---

### Compilar manualmente desde el código fuente (no recomendado)

Clona el [repositorio](https://github.com/factor/factor) y usa `make` en esa carpeta.

Si `make` falla con un error sobre un objetivo que no existe, prueba `make factor` o, si sabes leer un Makefile, busca el objetivo de make para tu plataforma en `GNUmakefile`.

Si *eso* también falla, abre un issue en [factor/factor](https://github.com/factor/factor) con el error: los amables desarrolladores estarán encantados de ayudarte.
