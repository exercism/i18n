# Introducción a la redirección

En el mundo de la interfaz de línea de comandos, los programas suelen interactuar con tres flujos de datos estándar:

1. **Entrada estándar** (`stdin`): donde un programa recibe su entrada (normalmente desde el teclado).
1. **Salida estándar** (`stdout`): donde un programa envía su salida normal (normalmente a la pantalla de la terminal).
1. **Error estándar** (`stderr`): donde un programa envía los mensajes de error (normalmente a la pantalla de la terminal).

Recuerda que los presentamos en el capítulo de [Tuberías y listas de comandos][pipelines].

~~~~exercism/note
Las tuberías se pueden considerar una forma de redirección: la salida estándar de un programa se envía directamente a la entrada estándar de otro.
Ya cubrimos las tuberías.
Este concepto tratará la redirección desde y hacia archivos.
~~~~

La redirección del shell es un mecanismo potente que te permite cambiar el destino de estos flujos.
En lugar de que un programa lea desde el teclado o escriba en la pantalla, puedes redirigir la entrada desde un archivo o enviar la salida a un archivo.
Esto te da bastante flexibilidad y control sobre cómo interactúan los programas con los datos.

## Operadores de redirección principales

Aquí están los operadores de redirección más comunes y lo que hacen:

### `>` (redirección de salida)

* Propósito: redirigir la salida estándar (`stdout`) de un comando a un archivo.
* Comportamiento:
  * Si el archivo no existe, se crea.
  * Si el archivo existe, su contenido se sobrescribe.
* Ejemplo:

  ```bash
  # Sends the output of 'ls -l' to 'file_listing.txt'
  ls -l > file_listing.txt
  ```

~~~~exercism/caution
La redirección se realiza **antes** de que se ejecute el comando.
Esto significa que no puedes redirigir a un mismo archivo del que necesitas leer.

```bash
date > date.txt         # populate the file with the current date
cat date.txt > date.txt # 'date.txt' is now empty!
```

En el segundo comando del ejemplo anterior,

1. Primero, Bash trunca el archivo indicado en la redirección.
   Esto destruye el contenido anterior y deja un archivo vacío.
2. Luego, Bash lee el archivo recién vaciado.
3. Después, Bash escribe el contenido (es decir, nada) de vuelta en el archivo.
~~~~

### `>>` (redirección de salida para agregar)

* Propósito: agregar la salida estándar (`stdout`) de un comando al final de un archivo.
* Comportamiento:
  * Si el archivo no existe, se crea.
  * Si el archivo existe, la salida se agrega al final del archivo.
* Ejemplo:

  ```bash
  # Adds "Another line" to the end of the file
  echo "Another line" >> file_listing.txt
  ```

### `<` (redirección de entrada)

* Propósito: redirigir la entrada estándar (`stdin`) de un comando desde un archivo.
* Comportamiento: el comando lee su entrada desde el archivo indicado en lugar del teclado.
* Ejemplo:

  ```bash
  # 'tr' reads from 'lowercase.txt' and
  # output is redirected to 'uppercase.txt'
  tr 'a-z' 'A-Z' < lowercase.txt > uppercase.txt
  ```

### `2>` (redirección de errores):

* Propósito: redirigir el error estándar (`stderr`) de un comando a un archivo.
* Comportamiento: los mensajes de error se envían al archivo indicado en lugar de a la terminal.
* Ejemplo:
  ```bash
  # Error message from 'rm' is sent to 'error_log.txt'
  rm non_existent_file 2> error_log.txt
  ```

Puedes _agregar_ el error estándar al final de un archivo con `2>>`.

### Redirecciones adicionales

También hay redirecciones que pueden combinar tanto `stdin` como `stderr`.
Consulta el [manual][manual] para más detalles.

## `/dev/null`

`/dev/null` es un archivo especial que

* está vacío cuando lo lees, y
* descarta todos los datos que se escriben en él.

A veces se le llama «el bitbucket».
Es útil para suprimir la salida o los errores.

```bash
some_command > /dev/null  # Discards stdout
some_command 2> /dev/null # Discards stderr

# Using /dev/null as input will prevent the command
# from reading data from the keyboard
some_command < /dev/null
```

## Cómo combinar redirecciones

Puedes indicar varias redirecciones a la vez.

```bash
some_command < input.txt > output.txt 2> error.txt
```

Una redirección se puede copiar.

```bash
# send stderr to the same destination as stdout
some_command > output.txt 2>&1
```

Cuando veas `2>&1`, léelo como «redirige el error estándar a _lo que sea que la salida estándar esté apuntando **en ese momento**_».
Bash procesa las instrucciones de redirección estrictamente de izquierda a derecha, lo que significa que puedes hacer:

```bash
# redirect stdout to 'output1.txt'
# redirect stderr to the same place
# then change stdout to 'output2.txt'
some_command > output1.txt 2>&1 > output2.txt
```

## Descriptores de archivo

En el contexto de la programación del shell y de sistemas operativos como Linux/Unix, un descriptor de archivo (FD) es un número entero no negativo que sirve como identificador o referencia de un archivo abierto o de un recurso de E/S (entrada/salida).
Piénsalo como una etiqueta o un número de referencia que el sistema operativo usa para llevar la cuenta de los archivos abiertos y los flujos de datos.

Los números que ves a la izquierda de las redirecciones son descriptores de archivo.

A los flujos de E/S estándar se les asignan los primeros 3 descriptores de archivo:

* la entrada estándar es el FD 0
* la salida estándar es el FD 1
* el error estándar es el FD 2

Se pueden establecer o crear nuevos descriptores de archivo con el comando `exec` y los operadores de redirección.

```bash
# create FD 3 as a copy of stdout
exec 3>&1
# send stdout to a log file
exec > log.txt

# then redirect both stdout and file descriptor 3
echo "some debug message" >&3  # displayed in the terminal
some_command  2>&1 # stdout and stderr send to 'log.txt'
```

Esta técnica parece bastante enrevesada, pero puede ser muy útil cuando algún otro programa ejecuta tu script y ese programa captura automáticamente la salida estándar.
El comando `bats`, que se usa para ejecutar las pruebas unitarias de esta pista, funciona así: `bats` captura la salida estándar y el error estándar de una prueba, pero los mensajes de depuración enviados al FD 3 se muestran en la terminal.
~~~~

## En resumen

¿Por qué es útil la redirección?

* Guardar la salida: almacena los resultados de un comando para revisarlos o procesarlos más tarde.
* Registro: captura los mensajes de error para depurar.
* Automatización: encadena comandos, usando la salida de uno como la entrada de otro.
* Filtrado: descarta la salida que no quieres.
* Procesamiento por lotes: procesa datos desde archivos en lugar de escribirlos a mano.
* Programación de scripts: las redirecciones son esenciales para escribir scripts de shell robustos.

Las redirecciones del shell te dan un control detallado sobre cómo interactúan los programas con los datos, lo que te permite construir flujos de trabajo complejos y gestionar la información de forma eficaz.
