# Pruebas

Una forma de resolver los ejercicios de Exercism es entrar al sitio web y usar el editor del navegador, donde puedes editar y probar tu solución.

Como alternativa, puedes descargar los ejercicios a tu computadora y usar tu propio editor y un conjunto de herramientas para crear, probar y, finalmente, enviar tu solución.

Esto implica usar la interfaz de línea de comandos de Exercism, o CLI, una aplicación que se ejecuta dentro de una terminal o una ventana de línea de comandos. Aquí puedes encontrar las instrucciones de instalación: [Documentación de la CLI de Exercism](https://exercism.org/docs/using/solving-exercises/working-locally).

## Enfoque de las pruebas

Exercism supone que tienes algo de experiencia con el desarrollo guiado por pruebas. Cada ejercicio consta de un _`stub file`_, un _`test file`_ que contiene una serie de pruebas ya escritas y un _`test script`_ que se usa para ejecutar las pruebas.

Resolver un ejercicio requiere desarrollar el _`stub file`_ de forma incremental hasta que contenga el código que, con el tiempo, pase todas las pruebas.

En la práctica, esto significa que vas a editar activamente tanto el _`stub file`_ como el _`test file`_. Ten en cuenta que el _`test file`_ se edita no para cambiar el código de las pruebas, sino para comentar las pruebas que fallan.

Al principio, todas las pruebas menos una estarán comentadas; luego, a medida que el _`stub file`_ avanza hacia una solución que funcione, vas descomentando más pruebas hasta que todas se ejecuten correctamente.

## Infraestructura de pruebas

No hace falta instalar ningún software adicional, ya que los componentes del framework de pruebas vienen incluidos en la descarga del ejercicio.

El framework de pruebas está formado por tres archivos Rexx. Al momento de probar, estos se combinan con la solución del ejercicio para formar la unidad de código de prueba; el _`test script`_ la ejecuta y los resultados de las pruebas se imprimen en la terminal.

Por favor, no edites ni borres el _`test script`_ ni ningún otro archivo del framework de pruebas. Si algún gremlin hace que esto pase, simplemente vuelve a descargar el ejercicio con la CLI de Exercism, y ten cuidado de guardar tu código de solución.

## Cómo ejecutar las pruebas

Para resolver un ejercicio, sigue estos pasos:

1. Abre una terminal
2. Descarga el ejercicio que elijas
3. Entra al directorio del ejercicio
4. Carga el archivo stub y el archivo de pruebas en tu editor
5. De forma iterativa,

    1. Ejecuta el script de pruebas
    2. Escribe código en tu archivo stub (convirtiéndolo poco a poco en un archivo de solución) y comenta o descomenta pruebas en tu archivo de pruebas

6. Cuando todas las pruebas pasen, envía la solución a Exercism
7. Cierra la terminal
8. Celebra tu éxito

Un ejemplo concreto dentro de una terminal Linux usando el ejercicio `acronym` (supón que el espacio de trabajo de Exercism es `/home/exercism`)

Descarga el ejercicio:

`exercism download --track=rexx --exercise=acronym`

Entra al directorio del ejercicio:

`cd /home/exercism/rexx/acronym`

Desde otra ventana, quizá con interfaz gráfica, carga en tu editor `acronym.rexx` y `acronym-check.rexx`, el archivo stub y el archivo de pruebas, respectivamente.

Ejecuta el script de pruebas: `./test-acronym`

y todas las pruebas deberían fallar:

```bash
1..9
not ok 1 - basic Abbreviate("Portable Network Graphics")
not ok 2 - lowercase words Abbreviate("Ruby on Rails")
not ok 3 - punctuation Abbreviate("First In, First Out")
not ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
not ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
not ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
not ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
not ok 8 - apostrophes Abbreviate("Halley's Comet")
not ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Comenta todas las pruebas menos la primera en el archivo `acronym-check.rexx` y vuelve a ejecutar el script de pruebas; deberías obtener el siguiente resultado:

```bash
1..1
not ok 1 - basic Abbreviate("Portable Network Graphics")
```

Modifica `acronym.rexx` hasta que contenga código que funcione, y el resultado de ejecutar el script de pruebas debería llegar a ser:

```bash
1..1
ok 1 - basic Abbreviate("Portable Network Graphics")
```

Continúa descomentando las demás pruebas, vuelve a ejecutar el script de pruebas y, al final, el resultado debería ser:

```bash
1..9
ok 1 - basic Abbreviate("Portable Network Graphics")
ok 2 - lowercase words Abbreviate("Ruby on Rails")
ok 3 - punctuation Abbreviate("First In, First Out")
ok 4 - all caps word Abbreviate("GNU Image Manipulation Program")
ok 5 - punctuation without whitespace Abbreviate("Complementary metal-oxide semiconductor")
ok 6 - very long abbreviation Abbreviate("Rolling On The Floor Laughing So Hard That My Dogs Came Over And Licked Me")
ok 7 - consecutive delimiters Abbreviate("Something - I made up from thin air")
ok 8 - apostrophes Abbreviate("Halley's Comet")
ok 9 - underscore emphasis Abbreviate("The Road __Not__ Taken")
```

Ya puedes enviar la solución de tu ejercicio:

`exercism submit acronym.rexx`

y obtener otro punto de reputación. Cierra la terminal cuando termines.

El proceso para alguien que usa MacOS sería muy similar, ya que es un sistema operativo derivado de UNIX.

El proceso para quienes usan Windows es, en líneas generales, similar, aunque tiene algunas diferencias menores:

- La ventana de _Command Prompt_ es la terminal
- Las barras invertidas reemplazan a las barras inclinadas en las rutas, así que el directorio de trabajo podría ser:

  `cd C:\Users\MyName\exercism\rexx\acronym`

- El script de pruebas se ejecuta con:

  `test-acronym`  o  `test-acronym.bat`

El resultado de las pruebas será idéntico.
