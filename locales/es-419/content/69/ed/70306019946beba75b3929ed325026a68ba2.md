# Instrucciones

Estás escribiendo código para el sistema de datos del piso de una fábrica de autopartes automotrices.
Los componentes del motor y del chasis pasan por una serie de estaciones de mecanizado.
Cada estación produce mediciones que hay que combinar, comparar, calibrar o normalizar antes de que se ejecute la siguiente etapa.
Las funciones que implementas aquí son una por cada estación.

~~~~exercism/note
Los cálculos de este ejercicio deben realizarse usando instrucciones SIMD, no operaciones escalares.
~~~~

## 1. Combina los rendimientos de dos líneas

El piso de la fábrica tiene dos líneas de ensamblaje en paralelo.
Al final de cada turno, ambas líneas reportan su rendimiento para 4 contenedores de piezas como números de precisión simple.
El tablero del supervisor muestra el rendimiento combinado por contenedor, así que los dos informes se suman contenedor por contenedor.
El sistema de informes administra los tres búferes, y estos siempre están alineados a 16 bytes.

Define una función `sum_yields` que, dados los rendimientos por contenedor de `line_a` y `line_b`, escriba la suma por contenedor en `result`.
Los argumentos, en orden, son:

1. `line_a`: dirección de memoria alineada a 16 bytes que contiene 4 números de punto flotante de 32 bits
2. `line_b`: dirección de memoria alineada a 16 bytes que contiene 4 números de punto flotante de 32 bits
3. `result`: dirección de memoria alineada a 16 bytes donde la función escribirá 4 números de punto flotante de 32 bits

Esta función no devuelve ningún valor; en su lugar, el resultado se almacena en el búfer que se pasa (`result`):

```c
line_a = {10.0, 20.0, 30.0, 40.0};
line_b = { 5.0, 15.0, 25.0, 35.0};
sum_yields(line_a, line_b, result);
// => result == {15.0, 35.0, 55.0, 75.0};
```

## 2. Calcula la desviación escalada

Entre operaciones, una estación de muestreo mide las piezas mecanizadas y las compara con las dimensiones objetivo.
Los valores medidos llegan desde un medidor de precisión a un búfer que siempre está alineado a 16 bytes.
Los valores objetivo provienen del paquete de la orden de trabajo, que no tiene garantía de alineación.
La desviación se multiplica por un factor de sensibilidad por eje antes de pasarla al verificador de tolerancias posterior.
En esta etapa, el verificador posterior lee la desviación directamente de un registro SIMD en lugar de leerla desde la memoria.

Define una función `scaled_deviation` que, dados `measured` y `target` y una `sensitivity`, escriba la desviación escalada en `result`.
Los argumentos, en orden, son:

1. `measured`: dirección de memoria alineada a 16 bytes que contiene 2 números de punto flotante de 64 bits
2. `target`: dirección de memoria que contiene 2 números de punto flotante de 64 bits (sin garantía de alineación)
3. `sensitivity`: dirección de memoria que contiene 2 números de punto flotante de 64 bits (sin garantía de alineación)
4. `result`: dirección de memoria de un búfer donde la función escribirá 2 números de punto flotante de 64 bits (sin garantía de alineación)

La desviación escalada es `(measured - target) * sensitivity`, carril por carril.

Esta función no devuelve ningún valor; en su lugar, el resultado se almacena en el búfer que se pasa (`result`) como un par de números de punto flotante de 64 bits.

```c
measured    = {10.5, 20.5};
target      = {10.0, 20.0};
sensitivity = { 2.0,  4.0};
scaled_deviation(measured, target, sensitivity, result);
// => result == {1.0, 2.0};
```

## 3. Calibra un lote

Antes de que las piezas entren a la bahía de inspección final, las lecturas dimensionales de un lote de 4 piezas se reescalan a doble precisión y se corrigen según una deriva de temperatura conocida.

Las 4 lecturas sin procesar llegan como números de precisión simple.
Para cada fila de 2 lecturas, la calibración calcula `reference / (raw - offset)` y luego multiplica ese resultado por un factor de conversión constante de `0.5`.

Ten en cuenta que la `reference` y el `offset` son los mismos para ambas filas del lote.
El factor de conversión es el mismo en cada calibración, así que en lugar de recibirlo como argumento, debes declararlo como una constante empaquetada de 16 bytes en memoria.

Define una función `calibrate_batch` que, dado un lote `raw`, una `reference`, un `offset` y un búfer `result`, escriba los valores calibrados en `result`.
Los argumentos, en orden, son:

1. `raw`: dirección de memoria que contiene 4 números de punto flotante de 32 bits (sin garantía de alineación)
2. `reference`: dirección de memoria alineada a 16 bytes que contiene 2 números de punto flotante de 64 bits
3. `offset`: dirección de memoria alineada a 16 bytes que contiene 2 números de punto flotante de 64 bits
4. `result`: dirección de memoria alineada a 16 bytes donde la función escribirá 4 números de punto flotante de 64 bits (32 bytes en total)

La función debe, para cada una de las dos filas del lote:

1. Convertir los 2 valores sin procesar de precisión simple de la fila a doble precisión.
2. Restar el `offset` del par convertido.
3. Dividir la `reference` entre el resultado.
4. Multiplicar carril por carril cada número de punto flotante de 64 bits por el factor de conversión fijo de `0.5`.
5. Almacenar los 2 números de punto flotante de 64 bits en los 16 bytes correspondientes de `result`.

Esta función no devuelve ningún valor; en su lugar, el resultado se almacena en el búfer que se pasa (`result`):

```c
raw       = {10.0, 20.0, 25.0, 50.0};
reference = {100.0, 100.0};
offset    = {  5.0,  10.0};
calibrate_batch(raw, reference, offset, result);
// => result == {10.0, 5.0, 2.5, 1.25};
```

## 4. Normaliza las puntuaciones a lo largo de una línea

Al final de la línea, cada pieza tiene una puntuación de calidad que debe normalizarse antes de reportarse.
Cada puntuación se multiplica por su propia ganancia por pieza y luego se divide por una escala de producción por eje.
El búfer de ganancias contiene una ganancia por pieza.

La escala de producción es la misma para toda la corrida y se pasa en una dirección de memoria que contiene dos números de punto flotante de 64 bits.
Las puntuaciones se actualizan **in situ**: el mismo búfer que contenía las puntuaciones sin procesar ahora contiene las puntuaciones normalizadas.

Define una función `normalize_scores` que, dado un array `scores`, un array `gains`, una `scale` y una cantidad `n`, normalice las puntuaciones in situ.
Los argumentos, en orden, son:

1. `scores`: dirección de memoria alineada a 16 bytes que contiene `n` números de punto flotante de 64 bits (se modifica in situ)
2. `gains`: dirección de memoria alineada a 16 bytes que contiene `n` números de punto flotante de 64 bits
3. `scale`: dirección de memoria alineada a 16 bytes que contiene 2 números de punto flotante de 64 bits
4. `n`: un entero positivo par de 64 bits (mínimo `2`), la cantidad de puntuaciones que hay que normalizar

Los dos carriles de la escala se aplican a los dos elementos de cada par.
El primer carril escala el primer elemento de cada par (carriles en posiciones pares), el segundo carril escala el segundo (carriles en posiciones impares).
Cada puntuación se multiplica por su ganancia correspondiente y luego se divide por el carril de escala adecuado: `score * gain / scale_lane`.

Esta función no devuelve ningún valor; en su lugar, el resultado se almacena en el búfer de entrada (`scores`), en la misma posición de la `score` correspondiente que se normalizó:

```c
n      = 4
scores = {10.0, 20.0, 30.0, 40.0};
gains  = { 2.0,  1.5,  1.0,  0.5};
scale  = { 2.0,  4.0};
normalize_scores(scores, gains, scale, n);
// => scores == {10.0, 7.5, 15.0, 5.0};
```
