# Acerca de

En conceptos anteriores vimos que los tipos en Julia forman una jerarquía, con `Any` en la parte superior.

Los tipos abstractos como `Number` tienen subtipos, pero no se pueden instanciar por sí mismos. Asignarle un tipo abstracto a una variable _restringe_ los valores de esa variable a cualquier subtipo del tipo abstracto. Por ejemplo:

```julia-repl
julia> x::Number = 3
3

julia> typeof(x)  # one subtype of Number
Int64

julia> x = 4.2
4.2

julia> typeof(x) # another subtype of Number
Float64

julia> x = "fail" # not a number type!
ERROR: MethodError: Cannot `convert` an object of type String to an object of type Number
```

Esto nos da una forma de flexibilidad al restringir qué valores son válidos.

Sin embargo, ¿qué pasa si queremos que una variable acepte tanto valores enteros como valores de tipo string?
Estos tipos no están en la misma rama de la jerarquía.

Podríamos asignarle a la variable el tipo [`Any`][any], o dejar que use ese tipo por defecto, pero entonces perderíamos todo el control sobre los tipos permitidos.

Para una mejor estrategia, contamos con la sintaxis [`Union{ }`][union], con dos o más tipos dentro de las llaves.

```julia-repl
julia> y::Union{Integer, String} = 4
4

julia> typeof(y)
Int64

julia> y = "works"
"works"

julia> typeof(y)
String

julia> y = 5.3
ERROR: MethodError: Cannot `convert` an object of type 
  Float64 to an object of type 
  Union{Integer, String}
```

Otro ejemplo usa la misma unión de tipos en la firma de una función:

```julia-repl
julia> IntOrString = Union{Integer, String}
Union{Integer, String}

julia> f(z::IntOrString) = z^3
f (generic function with 1 method)

julia> f(2) # integers are cubed
8

julia> f("ab") # strings are repeated 3 times
"ababab"
```

Aquí le dimos un nombre al tipo, lo cual puede servir como una forma abreviada práctica, pero no es estrictamente necesario.
La función `g(z::Union{Integer, String}) = z^3` se comporta de la misma manera.

Habrá mucho más que decir sobre las firmas de funciones en el concepto Multiple Dispatch.

## Uniones con nothing

Varios otros lenguajes tienen tipos que pueden contener o no un valor, con nombres como `Option`, `Nullable` o `Maybe`.

Julia no tiene una sintaxis específica para esto, pero las uniones de tipos son una generalización de la misma idea.

Vimos en el concepto [`Nothingness`][nothingness] que Julia tiene varias formas de representar no-valores, incluyendo [`nothing`][nothing] y [`missing`][missing].
Cualquiera de estos se puede incluir en una unión de tipos.

Por ejemplo, al definir algún tipo de [lista enlazada][linked], necesitamos una forma de terminar la lista si no hay más nodos.
`Nothing` es el tipo con el valor singleton `nothing`, y esta definición de Node permite señalar el final de la cadena:

```julia-repl
julia> struct Node
           value::Any
           next::Union{Node, Nothing}
       end
```

De manera similar, `missing` se puede usar como un marcador de posición para valores ausentes, especialmente en colecciones como los vectores.
El ejemplo de abajo es muy forzado, pero los valores ausentes son comunes en conjuntos de datos del mundo real.

```julia-repl
julia> q(x::Real) = x >= 0 ? sqrt(x) : missing  # skip negative values
q (generic function with 1 method)

julia> vals::Vector{Union{Real, Missing}} = q.([4, 3.1, -1, 0])
4-element Vector{Union{Missing, Float64}}:
 2.0
 1.760681686165901
  missing
 0.0
```
