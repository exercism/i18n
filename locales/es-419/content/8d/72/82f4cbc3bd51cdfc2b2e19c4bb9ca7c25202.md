# Instrucciones

Estás trabajando en un sistema para simplificar el proceso de inicio de sesión en la red de tu organización. Las tareas se refieren a la parte de autenticación. El sistema usa el reconocimiento facial para comprobar la identidad.

En todos los casos, se garantiza que el parámetro del color de ojos no es nulo.

## 1. Asegúrate de que los rasgos faciales coincidan

Implementa `Authenticator.AreSameFace()` para comprobar que dos rostros coinciden.

Agrega rutinas de igualdad para la clase `FacialFeatures`.

```csharp
Authenticator.AreSameFace(new FacialFeatures("green", 0.9m), new FacialFeatures("green", 0.9m);
// => true
Authenticator.AreSameFace(new FacialFeatures("blue", 0.9m), new FacialFeatures("green", 0.9m);
// => false
```

## 2. Autentica al administrador del sistema

A pesar de tus protestas, el administrador del sistema insiste en tener una identidad integrada durante las pruebas de aceptación para poder autenticarse siempre.

El correo del administrador es admin@exerc.ism. Tiene los ojos verdes y un filtrum con un ancho de 0.9.

Agrega rutinas de igualdad para la clase `Identity`.

Implementa el método `Authenticator.IsAdmin()` para comprobar que la identidad que se pasa coincide con la del administrador.

```csharp
var authenticator = new Authenticator();
authenticator.IsAdmin(new Identity("admin@exerc.ism", new FacialFeatures("green", 0.9m)));
// => true
authenticator.IsAdmin(new Identity("admin@thecompetition.com", new FacialFeatures("green", 0.9m)));
// => false
```

## 3. Registra nuevas identidades

Implementa el método `Authenticator.Register()`, que almacena una identidad en el propio autenticador, de modo que las llamadas a `IsRegistered()` devuelvan `true` para esa identidad; de lo contrario, `IsRegistered()` devuelve `false`.

Para detectar intentos duplicados de registrar una identidad, si la identidad ya se ha registrado, `Authenticator.Register()` devuelve `false`; de lo contrario, `true`.

```csharp
var authenticator = new Authenticator();
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.IsRegistered(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => true
authenticator.Register(new Identity("tunde@thecompetition.com", new FacialFeatures("blue", 0.9m)));
// => false
```

## 4. Evita que se autentiquen identidades no válidas

Implementa el método `Authenticator.IsRegistered()` y asegúrate de que devuelva false cuando no se haya registrado ninguna identidad.

```csharp
var authenticator = new Authenticator();
authenticator.IsRegistered(new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.8m)));
// => false
```

## 5. Agrega diagnósticos para detectar múltiples intentos de autenticación

Se ha reportado un error según el cual el método `Authenticator.IsRegistered()` se llama varias veces seguidas para la misma identidad. Crees que hay algún tipo de problema de «rebote» en el que se envía el mismo registro exacto varias veces. Tu tarea es agregar una rutina de diagnóstico, `Authenticator.AreSameObject()`, para respaldar cualquier prueba que se realice. La rutina compara dos objetos y devuelve `true` si son exactamente la misma instancia; de lo contrario, `false`.

```csharp
var identityA = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityB = identityA;
Authenticator.AreSameObject(identityA, identityB);
// => true

var identityC = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
var identityD = new Identity("alice@thecompetition.com", new FacialFeatures("blue", 0.9m));
Authenticator.AreSameObject(identityC, identityD);
// => false
```
