# Acerca de

Elm es un lenguaje encantador para crear aplicaciones web confiables.
Tiene mensajes de error amigables, un gran rendimiento, recursos pequeños y ninguna excepción en tiempo de ejecución.

Probablemente la parte más famosa y más copiada de Elm es La Arquitectura Elm, un patrón simple para estructurar aplicaciones web, y es como están escritas todas las aplicaciones web de Elm.

La idea central es que tu código se construye alrededor de un `Model` del estado de tu aplicación, una forma de `update` tu modelo y una forma de `view` tu modelo.

El `Model` contiene el estado de la aplicación: todos los datos que esta necesita.
Puede ser de cualquier tipo, pero en cualquier aplicación útil normalmente es un [registro][record].
Si imaginas una aplicación simple con un cuadro de texto y un texto que muestre ese texto al revés, el modelo se vería como el siguiente.
También puedes ver este ejemplo en la [Guía de Elm][elm-guide-text-fields].

```elm
type alias Model =
  { text : String
  }
```

`update` es una función a la que se llama con un `Msg` cuando hay un cambio (como que el usuario haga clic en un botón).
Recibe el `Msg` y el `Model` actual, y devuelve un nuevo `Model`.
El `Msg` puede ser de cualquier tipo, pero normalmente es un [tipo personalizado][custom-type].

```elm
type Msg
  = TextChanged String

update : Msg -> Model -> Model
update msg model =
  case msg of
    TextChanged newText ->
      { model | text = newText }
```

Como con todos los tipos personalizados, las variantes del `Msg` pueden incluir toda la información arbitraria que necesiten.
En el ejemplo anterior, la variante `TextChanged` incluye un `String`.

`view` es una función que devuelve HTML para mostrarlo al usuario en el navegador.
Recibe el `Model` actual y devuelve un `Html Msg` (el tipo que Elm usa para representar HTML).
Cada elemento HTML (por ejemplo `<div>`) tiene una función de Elm correspondiente (`Html.div`), en el paquete `Html`.
Cada una de estas funciones recibe dos parámetros: el primero es una lista de atributos (de los paquetes `Html.Attributes` y `Html.Events`), y el segundo es una lista de elementos hijos (funciones del paquete `Html`).
También hay una función `text` que representa contenido de texto HTML, que solo recibe un parámetro de tipo string, pero por lo demás se usa igual que todas las demás funciones y elementos del paquete `Html`.

La función `view` puede especificar que ciertos eventos, como hacer clic en un botón o editar el texto de un cuadro de texto, den como resultado la creación de un `Msg`, que el Runtime de Elm usará para llamar a la función `update`, modificar el `Model` y generar HTML actualizado.
En el código de abajo esto ocurre con `Html.Events.onInput TextChanged`.

```elm
view : Model -> Html Msg
view model =
  Html.div []
    [ Html.input
      [ Html.Attributes.placeholder "Text to reverse"
      , Html.Attributes.value model.text
      , Html.Events.onInput TextChanged
      ]
      []
    , Html.div [] [ Html.text (String.reverse model.text) ]
    ]
```

`Html.Events.onInput` espera que se le pase una función (`String -> Msg`) que usará para crear el `Msg`.
Los distintos eventos esperan funciones distintas según la información que puedan proporcionar; por ejemplo, `Html.Events.onCheck` (para casillas de verificación) espera `Bool -> Msg`, y `Html.Events.onClick` simplemente espera un `Msg`.

El lenguaje Elm es puro y funcional y no es posible la mutación, así que el Runtime de Elm se encarga de todas las cosas que cambian.
Puedes ver todos los distintos [elementos HTML][html-elements], [atributos de elementos][element-attributes] y [eventos HTML][html-events] en el registro de paquetes de Elm.

Hay 4 «niveles» de aplicación web que puedes escribir en Elm, que son cada vez más potentes y más complicados (aunque Elm sigue siendo un lenguaje y un ecosistema encantadoramente simples).
Todos están definidos en el [paquete Browser][browser-package]:

- [sandbox][browser-sandbox]: reaccionar a la entrada del usuario, como botones y casillas de verificación
- [element][browser-element]: comunicarse con el mundo exterior, usando HTTP y la interoperabilidad con JavaScript
- [document][browser-document]: controlar el `<title>` y el `<body>` de una página web
- [application][browser-application]: crear aplicaciones completas de una sola página que manejen el enrutamiento y los cambios de URL

Este concepto usa [sandbox][browser-sandbox], ya que es el más simple (y, como es un sandbox, es relativamente fácil trabajar con el editor en línea de Exercism).
El módulo de entrada de un programa Elm debe llamarse `Main`, y la función que crea la aplicación debe llamarse `main`, como se muestra a continuación.

```elm
import Browser
import Html exposing (Html, Attribute, div, input, text)
import Html.Attributes exposing (placeholder, value)
import Html.Events exposing (onInput)

main =
  Browser.sandbox { init = init, update = update, view = view }

init : Model
init =
  { text = "" }

-- Add Model, Msg, update and view here
```

Ya vimos las funciones `update` y `view`, y [sandbox][browser-sandbox] además requiere una función `init`, que devuelve el estado inicial del `Model`.
