# Instrucciones

Este problema está inspirado en la planificación estática no apropiativa de los sistemas operativos de tiempo real (RTOS), pero también se parece al Job-Shop Scheduling Problem (JSP) con un solo recurso. Este problema supone que todas las tareas se conocen de forma estática. En otras palabras, los tiempos de liberación de todas las tareas de este problema se conocen al inicio del programa. En la práctica, el tiempo de liberación de las tareas no se conoce al inicio de un programa y puede generarse en cualquier momento mediante E/S, interrupciones, etc.

Dada una lista de tareas con sus parámetros, determina una planificación en la que las tareas puedan ejecutarse de forma secuencial y sin superponerse. Como el problema está inspirado en la planificación de procesos de un RTOS, supondremos que se requiere un tiempo distinto de cero entre tareas, también conocido como la sobrecarga del cambio de contexto. Hay dos tipos de tareas: periódicas y dinámicas. Ambos tipos tienen un parámetro de ID de tarea, que es un string que sirve para diferenciar entre las distintas tareas de la lista de tareas.

Una **tarea periódica** se define como una tarea que se ejecuta de forma periódica. En otras palabras, la tarea se ejecutará una vez cada T segundos, donde T se define como el periodo.
Una tarea periódica se define mediante los siguientes parámetros:
* Tiempo de inicio: momento en que comienza la primera repetición, o instancia, de la tarea
* Periodo: tiempo entre el inicio de las repeticiones de la tarea
* Tiempo de ejecución: tiempo que dura cada repetición
* Tiempo de fin: momento en que la tarea entera deja de planificarse

Una **tarea dinámica** se define como una tarea que se ejecuta solo una vez.
Una tarea dinámica se define mediante los siguientes parámetros:
* Tiempo de liberación: primera vez que la tarea PUEDE planificarse (NO es lo mismo que el tiempo de inicio)
* Tiempo de ejecución: tiempo que se ejecuta la tarea
* Fecha límite: momento en que la tarea debe terminar su ejecución

La función que debes implementar recibe dos entradas. La primera es una lista de instancias de `RealTimeTask`. Las instancias de `RealTimeTask` se recibirán como una instancia de `PeriodicRealTimeTask` o de `DynamicRealTimeTask`, con todos los parámetros de la tarea como números enteros. Puedes usar la función integrada `isinstance()` de Python para diferenciar entre los dos tipos de tareas de la lista. El orden de la lista es irrelevante; fíjate solo en los parámetros de las tareas. La segunda entrada es un número entero que especifica la sobrecarga del cambio de contexto. La sobrecarga del cambio de contexto siempre será un número entero no negativo.

La salida debe ser un diccionario cuyas claves sean el ID de tarea de las instancias de RealTimeTask y cuyos valores sean una lista de tuplas de dos elementos. El formato de las tuplas de dos elementos es (tiempo de inicio, tiempo de fin). Las tareas dinámicas deben contener solo una tupla de dos elementos en la lista, mientras que las tareas periódicas pueden contener más de una. El orden de las tuplas de dos elementos en la lista no importa. Si no se puede crear una planificación válida a partir de la lista de tareas con la sobrecarga de cambio de contexto dada, lanza una excepción `NoRtosStaticScheduleProducible`. Ten en cuenta que los resultados del modelo Z3 para las variables deberán convertirse a enteros antes de mostrarse. Si el resultado del modelo Z3 es de tipo `IntNumRef`, puedes usar el método de clase `as_long()` para convertirlo a un número entero.

Se proporciona una función adicional para que puedas visualizar el orden secuencial de las tareas. Esta función también se puede habilitar para casos de prueba individuales si estableces el argumento de palabra clave `plot` en `True` dentro de la función `check()`. Se usa un gráfico de barras horizontales discontinuas para graficar y etiquetar cada tarea. Para usar esta función, debes instalar la biblioteca de Python *matplotlib*. Encontrarás los detalles de instalación de *matplotlib* [aquí](https://matplotlib.org/stable/users/installing.html).
